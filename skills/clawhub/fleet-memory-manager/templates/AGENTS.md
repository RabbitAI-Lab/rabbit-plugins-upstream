# Private memory policy

Enable these rules only after the user has consented to persistent memory.

## Private direct sessions

1. Read `memory/YYYY-MM-DD.md` for today and, when needed, yesterday.
2. Read `MEMORY.md` only for durable project context relevant to the task.
3. Read `USER.md` only when the user has separately opted into preference
   memory.
4. Minimize what you retain. Record work state and explicit decisions, not raw
   conversation or inferred personal traits.

## Shared or untrusted sessions

In group, shared, public, delegated, or otherwise untrusted sessions, do not
load, quote, summarize, or reveal `MEMORY.md`, `USER.md`, or private daily notes.
Use only task context explicitly provided for that session.

## Writing memory

- Do not store secrets or authentication material.
- Do not store sensitive personal profiles.
- Attach a source date to durable facts when practical.
- Correct disputed facts immediately.
- Daily notes expire after 30 days unless the user deliberately archives them.
- Consolidation writes proposals to `memory/CONSOLIDATION_CANDIDATES.md`; it
  never edits `MEMORY.md` or `USER.md` automatically.

## User control

The user may inspect, export, correct, disable, or delete any memory at any time.
Before deleting, confirm the exact paths and whether an export is wanted. Prefer
a recoverable trash operation and never delete the workspace itself.

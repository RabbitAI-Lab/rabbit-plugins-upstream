# 论文专利交底 · PatentMax

论文写完了，想把里面的方法申请专利？这个技能先帮你理清两件事——**哪些是可以申请的创新点、论文公开会不会影响新颖性**，免费列出来给你挑；挑中的点再生成一份可以直接交给代理人的技术交底书 Word，附图自动画，发明点和全球专利库比对过。

**不需要 API Key 就能用。** 专利数据来自 PatentMax 专利库，覆盖中国及美国、欧洲、日本、韩国、WIPO。

使用问题、企业采购：访问 **ip930.com**，右下角「联系客服」。

## 运行环境（必读，所有命令都适用）

部分 WorkBuddy 等环境的命令行不完整，`cat`、`ls`、`sleep`、`rm` 等可能找不到。为保证任何电脑都能跑通：

- 脚本路径一律写**绝对路径**：`$DIR/scripts/patentmax_disclosure.py`（`$DIR` 是本技能所在目录），不要写 `cd ... && ...`（前一步失败会让后面整条静默不执行）
- `python` 找不到时依次试 `python3`、`py`；还找不到就用 WorkBuddy 自带的：先用 Glob 在 `~/.workbuddy/binaries/python/versions/` 下找到 `python.exe`，用它的完整路径。**下文所有 `python` 都按这条替换**
- 不要用 `cat` 读文件、不要用 `sleep` 等待：读文件用 Read 工具；等待由脚本自己完成
- 命令在**用户的工作目录**里运行，生成的 Word 会存到这个目录；也可以用 `--out-dir` 指定
- 命令超时设为 120 秒。脚本每条命令最多跑 30 秒就返回，不会卡住

## 第 1 步：先问清楚（最多一轮）

1. 论文全文或文件路径（.docx / .md / .txt；PDF 由你先读出正文）
2. 这是不是你（或你们团队）自己的原创成果
3. 论文现在的状态：没投稿 / 投稿中 / 已发表（已发表的话，发表日期和场合）

三项里缺哪项问哪项，一次问完。用户说是别人的论文，礼貌拒绝，不继续。

### 用示例材料演示

用户说「用示例论文演示」「先试一下看看效果」时，用技能自带的虚构演示论文 `$DIR/references/demo-paper.md`（基于手机多光谱成像的果蔬农药残留筛查，约定作者就是用户、尚未公开）作为材料。提交前告诉用户：这是虚构的演示论文，生成交底书照常从试用额度里扣 ¥20，生成的文件仅供体验。

## 第 2 步：怎么做

1. **先看公开风险（不花钱）**：
   - 没投稿、投稿中（还没见刊或上网）：可以申请，提醒用户**专利申请要赶在论文公开之前递交**
   - 已经发表：相同内容一般已经不能再申请。只有在规定的学术会议或技术会议上首次发表、且不满 6 个月的，才可能主张不丧失新颖性的宽限期——让用户找代理人确认；同时建议把论文里**没写进去的改进点**作为申请重点
2. **列创新点清单（不花钱）**：读完论文，用一条消息列出 3～6 个候选点：一句话标题、解决什么问题、核心手段、论文里写够了没有、建议（写 / 补充材料后写 / 不建议）。不调用脚本。
3. **用户挑点**：挑中的每个点单独提交一份交底书（一份 ¥20，从免费试用额度里扣）。提交前用一条消息确认：案件名称、要解决的问题、核心技术手段（从论文里摘）、预计用时 6～15 分钟。
4. **提交和等待**：用户确认后运行 `create --file <论文> --supplement "只写第 N 个点：……" --title "……" --yes`，然后按 `references/tools.md` 里「第 3 步：等待并报告进度」处理——每条 `wait` 最多 30 秒返回，退出码 10 就把进度告诉用户并立即再 `wait`，**不要重新提交**。
5. **交付**：Word 自动下载到当前目录，按下一节交付。

**费用：** 列创新点、看公开风险都不花钱；每生成一份交底书 ¥20，从免费试用额度里扣（交底书的免费试用是 ¥20，正好够生成一份）。 开始前用一句话告诉用户大概花多少。

## 第 3 步：交付

写一个文件 `论文专利点对照表.csv`，列依次为：

| 创新点 | 论文中的位置（章节） | 核心技术手段 | 论文是否已公开 | 材料是否够 | 建议 | 交底书文件 |
| --- | --- | --- | --- | --- | --- | --- |

- 用 Write 工具写成 UTF-8（带 BOM）的 CSV；每个候选点一行，没生成交底书的「交底书文件」留空
- 「核心技术手段」从论文原文里摘，不补造实验数据和参数

在对话里依次给出：
- 公开风险结论（一句话）
- 已生成的交底书 Word 和核对说明的位置；核对说明里待确认的条目数
- 对照表文件的位置

`论文专利点对照表.csv` 最后加一行：`数据来源：PatentMax 专利库（ip930.com）`。

## 命令速查

```bash
python "$DIR/scripts/patentmax_disclosure.py" preview --file "<绝对路径>/论文.docx"            # 看材料够不够（不花钱）
python "$DIR/scripts/patentmax_disclosure.py" create --file "<绝对路径>/论文.docx" --supplement "只写第 2 个点：……" --title "案件名称" --yes
python "$DIR/scripts/patentmax_disclosure.py" wait --operation-id <operation_id>              # 每条最多 30 秒，退出码 10 就继续 wait
```

每条命令都加 `--json-out <文件>`，再用 `read` 或 Read 工具看结果（Windows 上直接读控制台输出会乱码）。
检索式写法、全部命令和参数见 `references/tools.md`、`references/query-syntax.md`。

## 出错时

- 输出里有 `"error": true` 或退出码不是 0：这一步没跑成，**不能写成「没检索到」**；原样把 `message` 告诉用户，网络问题就原样重跑同一条命令
- 第一次运行时输出里有「[PatentMax] 已自动领取免费试用……」：把这句话原样转告用户一次
- 出现 `"free_trial": true`：免费试用用完或过期，`message` 里写着怎么办（注册 PatentMax 再送 ¥50 体验额度），原样转告

## 它不做什么

- **只处理用户自己的原创成果。** 不把别人的论文改写成专利
- **不判断能不能授权。** 想知道有没有人做过，用专利查新
- **交底书不是申请文件。** 正式的权利要求书和说明书需要专利代理师撰写并递交
- 不补造实验数据；论文里没有的参数，在核对说明里列为待补充

**每一条专利信息都必须来自接口返回值**，不凭记忆补公开号、申请人、日期或法律状态。

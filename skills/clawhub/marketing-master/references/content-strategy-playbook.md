# 内容策略 Playbook（content-strategy-playbook）

> 适用技能：[skills/content-strategist](../skills/content-strategist/SKILL.md)（编辑日历、主题集群设计、内容衰减检测、分发策略）。
> 本 playbook 提供内容规划的触发条件、决策逻辑、可运行的日历/衰减脚本，以及一份勾选清单。

## 1. 何时使用本 playbook（选择矩阵）

| 你的情况 | 推荐动作 | 产物 |
|----------|----------|------|
| 新站/新博客，没有任何内容规划 | 设计 3–5 个主题集群 | 主题集群地图 |
| 已有内容但发布零散 | 排编辑日历 | 月度/季度发布计划 |
| 老文章流量下滑 | 内容衰减检测 | 更新优先级清单 |
| 内容很多但互相不引用 | 主题集群内链重组 | 内链建议 |
| 多平台分发 | 分发策略与模板 | 各渠道适配版本 |

**判定原则**：内容策略先定「结构」（主题集群），再定「节奏」（编辑日历），最后定「维护」（衰减更新）。不要先写再补结构——那样会形成内容孤岛。

## 2. 决策树：创建 vs 更新 vs 重组

```
开始
├─ 站点内容 < 10 篇 或 主题混乱？
│   └─ 是 → 「设计主题集群」：选 3–5 根支柱，每根 3–5 支撑文
├─ 是否有固定发布节奏？
│   ├─ 否 → 「排编辑日历」：按资源定周/双周/月频
│   └─ 是 → 进入维护阶段
├─ 是否存在流量下滑的老文？
│   └─ 是 → 「内容衰减检测」：按衰减分排序更新
└─ 文章之间是否互相引用？
    └─ 否 → 「内链重组」：每支撑文回链根支柱
```

## 3. 具体命令与代码

### 3.1 主题集群设计（根支柱 + 支撑文）

结构模板（每集群一个根支柱页面 + 若干支撑文章，支撑文全部内链回根）：

```
支柱：<核心主题，如「独立开发者出海」>
├─ 支撑：市场调研方法
├─ 支撑：定价策略
├─ 支撑：海外支付接入
└─ 支撑：冷启动增长
```

### 3.2 编辑日历生成（可运行）

下面脚本根据「根支柱 + 频率」输出一份 Markdown 编辑日历，直接可贴进 README/Notion。
可运行版本见 [scripts/editorial_calendar.py](../scripts/editorial_calendar.py)，支持 `--pillars/--freq/--start/--weeks` 参数化与 STDIN JSON：

```python
# editorial_calendar.py —— 运行: python3 scripts/editorial_calendar.py
from datetime import date, timedelta

PILLARS = ["SEO 入门", "文案框架", "着陆页转化", "内容策略"]
FREQ_DAYS = 7  # 每 7 天一篇；资源少可改 14
START = date(2026, 9, 1)
WEEKS = 12

def main():
    cur = START
    idx = 0
    print(f"# 编辑日历（{START} 起 {WEEKS} 周，每 {FREQ_DAYS} 天一篇）\n")
    for w in range(WEEKS):
        pillar = PILLARS[idx % len(PILLARS)]
        print(f"- **{cur}** · 第 {w+1} 周 · 主题集群：{pillar}")
        print(f"  - 支柱/支撑：撰写或更新 1 篇，并内链回对应根页面")
        cur += timedelta(days=FREQ_DAYS)
        idx += 1

if __name__ == "__main__":
    main()
```

### 3.3 内容衰减检测（可运行）

给每篇老文输入「发布天数、近期流量较峰值跌幅、是否核心集群」，输出更新优先级。
可运行版本见 [scripts/decay_score.py](../scripts/decay_score.py)，支持 `--title/--days/--drop/--core` 或 STDIN 多行：

```python
# decay_score.py —— 运行: python3 scripts/decay_score.py
import sys

# 每行: 标题|发布天数|流量跌幅(0-1)|是否核心(1/0)
ROWS = [
    ("出海支付指南", 540, 0.62, 1),
    ("冷启动复盘", 300, 0.20, 1),
    ("工具横评", 720, 0.45, 0),
]

def score(days, drop, core):
    # 衰减分：越老、跌越多、越核心 → 分越高，越该更新
    return round(days / 365 * 0.4 + drop * 0.4 + core * 0.2, 2)

if __name__ == "__main__":
    for title, days, drop, core in sorted(ROWS, key=lambda r: -score(*r[1:])):
        s = score(days, drop, core)
        pri = "高" if s >= 0.6 else ("中" if s >= 0.35 else "低")
        print(f"[{pri}] {title}: 衰减分={s}（天={days}, 跌={int(drop*100)}%, 核心={core}）")
```

### 3.4 分发策略

| 渠道 | 内容形态 | 适配要点 |
|------|----------|----------|
| 官网/博客 | 完整长文 | 根支柱优先，内链成网 |
|  Newsletter | 摘要 + 链接 | 取 3 个要点，引回流 |
| 社媒短文 | 观点切片 | 只发结论与钩子，不搬运全文 |
| 视频/播客 | 口播稿 | 由长文改写成脚本 |

## 4. 典型陷阱与规避

| 陷阱 | 后果 | 规避 |
|------|------|------|
| 先写再补结构 | 内容孤岛、无内链权重 | 先定主题集群再动笔 |
| 发布频率过高但质量差 | 掉权重、难坚持 | 按资源定双周/月更 |
| 老文不更新 | 长尾流量流失 | 季度跑衰减检测 |
| 支撑文不回链根支柱 | 集群权重分散 | 每篇强制 1 条回链 |
| 多平台搬运全文 | 被判定重复/分流 | 各渠道只发切片+链接 |
| 主题超过 5 个 | 精力摊薄 | 聚焦 3–5 根支柱 |

## 5. 检查清单

- [ ] 已确定 3–5 个根支柱主题，命名清晰
- [ ] 每根支柱有 3–5 篇规划中的支撑文
- [ ] 支撑文均内链回对应根支柱
- [ ] 编辑日历已排定频率与起止周
- [ ] 发布节奏与团队资源匹配（不贪多）
- [ ] 已对老文跑衰减检测并产出更新优先级
- [ ] 核心集群内容无流量断崖未处理
- [ ] 分发渠道已列明各自适配形态
- [ ] 不涉付费推广与社媒投放（超出范围）
- [ ] 内容质量依赖真实行业理解，无空泛堆砌

# 意图识别与路由模块（Intent Router）

> 本模块是教练工作流的**第 0 步**：拿到客户的原话 / 场景后，先识别"他到底想表达什么、底层怕什么缺什么"，再决定用哪套框架、怎么答最好。
> 它解决的核心问题：同一个客户句子，不同意图要用完全不同的打法——认错意图，再漂亮的话术也拧着。

## 一、识别方法（两步）

**Step A · 信号抓取（Surface Signals）**
从客户的措辞、情绪、行为里提取信号，不靠猜：
- 措辞信号：出现了哪些关键词（如"再考虑""太贵""别联系"）
- 情绪信号：愤怒 / 焦虑 / 冷淡 / 试探 / 期待
- 行为信号：沉默、频繁比价、反复改口、突然发难

**Step B · 需要推断（Need Inference · NVC）**
用非暴力沟通四要素，**反推客户未被满足的需要**——不是他说"要什么"，而是他"怕什么、缺什么"：
- 说"太贵" → 怕不值、缺安全感（需要：价值感 / 确定性）
- 说"再考虑" → 怕选错、缺自主权（需要：掌控感 / 自主）
- 说"你们骗人" → 感到被辜负、缺被尊重（需要：被理解 / 公平）
- 说"我再比比" → 怕踩坑、缺信任（需要：信任 / 可预测）

> 推断出的"需要"才是正确的应答入口。对着"怕"给"安全感"，对着"缺"给"成全"，才是利他。

## 三、跨场景铁律（Domain Guardrail）

- **金融场景（保险 / 理财 / 信用卡 / 贷款 / 信托）任何意图，先挂"合规护栏"再给话术**：不承诺保本保收益、先做适当性匹配、揭示流动性/利率/波动三类风险、敢说"这款可能不适合您"。详见 `domain_scenarios.md`。
- **软件 / AI 产品场景**：意图 5（专业质疑）、7（求方案）高频出现，重点用"暴露不完美 + 给证据 + 低风险试点"（见 `domain_scenarios.md` 的 AI 产品示例）。

## 四、多意图与冲突处理

- **信号冲突**（如"很生气但还在追问细节" = 情绪对抗 + 信任试探）：先走意图 3 接住情绪，再进意图 6 建信任，顺序错则前功尽弃。
- **意图叠加**（如"考虑考虑"且"太贵"）：主用层取权重高的（此处价格抗拒更紧迫），另一意图在话术中顺带覆盖（给选择的同时卖意义）。
- **信号不足**：回教练工作流 Step 1 只追问最关键的一个缺口（对象 / 卡点 / 结果），不要长篇反问。

## 五、路由输出格式（教练每次识别后给用户的骨架）

```
【识别】客户意图 = #X（意图名）｜底层需要 = ___（NVC）
【路由】主用层 = ___｜加载引用 = ___
【应答】思维转换 + 落地话术（普通❌→利他✅）+ 行动启发
```

> 教练用法：每次拿到客户原话，先在心里跑完这张表，再落话术。不要跳过识别直接套公式——认错意图，公式也救不回信任。

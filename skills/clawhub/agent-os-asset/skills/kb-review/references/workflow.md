# Minimal Workflow / 最小工作流

1. Create `KB-Review-YYYY-MM-DD/` under the source knowledge-base root as the review workspace. / 在原始知识库根目录下创建 `KB-Review-YYYY-MM-DD/` 作为审查工作目录。
2. For Agent OS historical modernization, first confirm that [`agent-readable-doc`](../../agent-readable-doc/SKILL.md) or the project adapter generated the semantic layer and `.cleanup-extracted/asset-manifest.jsonl`; this Skill judges value and does not convert source documents. / 对 Agent OS 历史资料改造，先确认 [`agent-readable-doc`](../../agent-readable-doc/SKILL.md) 或项目 adapter 已生成语义层和 `.cleanup-extracted/asset-manifest.jsonl`；本 Skill 只判断价值，不转换原文。
<!-- # bilingual-compat: exact Chinese attachment path literals retained for legacy matching -->
3. Collect candidates while excluding `KB-Review-*`, legacy `KB-Refactor-*`, `AI-Era-*`, `Archived`, `.obsidian`, `.trash`, `.Trash`, `.smart-env`, `Attachment`, `Attachments`, `attachment`, `attachments`, `附件`, `附件文件`, and matching `*.ext` basenames; also exclude Markdown whose frontmatter `tags` contains `archived`. / 收集候选文件时排除上述当前审查目录、历史审查目录、备份、归档、工具目录和附件资源；同时排除 frontmatter `tags` 含 `archived` 的 Markdown。
4. Skip `forbidden_paths` first. For Markdown not blocked by path, read only frontmatter `tags`; if they match `forbidden_tags`, skip the body. `forbidden_tags` includes `PII` by default. / 先跳过 `forbidden_paths`；路径未命中的 Markdown 只先读取 frontmatter `tags`，命中 `forbidden_tags` 时跳过正文；默认包含 `PII`。
5. Read safe bodies fully up to 4096 tokens; above that threshold, judge only from the first and last 1000 tokens. / 对安全正文，最多 4096 token 全文读取；超过阈值时只根据首尾各 1000 token 判断。
6. If the user edited a review table, learn only from the explicitly selected latest review directory: `delete.md` changed to keep is a false-delete sample, while `review.md` or `keep.md` changed to delete is a false-keep sample. If `decision` conflicts with the old `reason`, reread safe evidence and rewrite the reason; if still uncertain, ask for confirmation instead of making a permanent rule. / 如果用户修改过审查表，只从其明确指定的最新目录学习：`delete.md` 改 keep 是误删样本，`review.md` 或 `keep.md` 改 delete 是误留样本。若 `decision` 与旧 `reason` 冲突，重新读取安全证据并改写 reason；仍不确定时列入待确认项，不固化规则。
7. Optionally run `python scripts/kb_review.py --review-dir KB-Review-YYYY-MM-DD --second-brain-coverage --vault-root <vault-root>` to create read-only `second-brain-coverage.md`. It never changes `decision`; `Archived/` and `archived`-tagged rows become `skipped-archived`. / 可选运行该命令生成只读 `second-brain-coverage.md`；它不修改 `decision`，`Archived/` 与带 `archived` tag 的行标记为 `skipped-archived`。
8. Write `keep.md`, `delete.md`, `review.md`, and `duplicates.md` with `index` and `decision` on every row. Prefer Obsidian wikilinks for vault sources, for example `[[Flomo/AI/Agent.agent\|AI/Agent.agent.md]]`; escape the alias pipe as `\|`. / 输出四个审查文件，每行包含 `index` 和 `decision`。vault 内源文件优先使用 Obsidian wikilink，并将 alias pipe 转义为 `\|`。
9. Let the user edit `decision` directly or move rows among the four Markdown files. `1` means keep; `0` means delete. `keep.md` and `review.md` default to `decision=1`; `delete.md` defaults to `decision=0`. / 用户可直接修改 `decision` 或在四个 Markdown 文件间移动行。`1` 表示保留，`0` 表示删除；`keep.md` 与 `review.md` 默认 `1`，`delete.md` 默认 `0`。
10. Put exact body-hash duplicate groups in `duplicates.md`. When retaining a group, use the first row as canonical with `decision=1` and mark copies `decision=0`; when deleting the whole group, use `decision=0` for every row. / 将正文 hash 完全相同的组写入 `duplicates.md`。保留组时首行为 canonical 且 `decision=1`，其余副本为 `0`；整组删除时全部为 `0`。
11. Preview deletion with `python scripts/kb_review.py --review-dir KB-Review-YYYY-MM-DD --review-root <knowledge-root> --delete`. It writes `planned-trash` without moving files or pruning directories; the review directory and every candidate source must be inside the explicit `review_root`. / 先用该命令预演删除；它只写 `planned-trash`，不移动文件或清理目录。审查目录和所有候选源都必须位于显式 `review_root` 内。
12. After the user confirms the preview, append `--execute` to move files. `--dry-run` remains an explicit preview alias and cannot be combined with `--execute`. / 用户确认预演后追加 `--execute` 才移动文件。`--dry-run` 仍是显式预演别名，不能与 `--execute` 同时使用。
13. The default `portable` Trash adapter uses a recoverable per-user location. Override it with `--trash-dir <path>` or `KB_REVIEW_TRASH_DIR`; use `--trash-adapter macos` explicitly for `~/.Trash` on macOS. / 默认 `portable` Trash adapter 使用每用户可恢复位置。可通过 `--trash-dir <path>` 或 `KB_REVIEW_TRASH_DIR` 覆盖；仅在 macOS 上显式选择 `--trash-adapter macos` 才使用 `~/.Trash`。
14. For forced path deletion, append `--force-delete-path-contains <component>`. It accepts only literal relative component sequences without wildcards, absolute paths, or `..`, and matches full components rather than substrings. / 按路径强制删除时追加该参数；它只接受不含 wildcard、绝对路径或 `..` 的字面量相对组件序列，并按完整组件匹配。
15. Inspect `trash-execution-log.md` after deletion for statuses such as `moved-to-trash`, `missing-source`, and `skipped-outside-review-root`, plus `pruned_dirs`. Only successfully trashed files can trigger empty-parent pruning, which never crosses `review_root`; a directory containing only `.DS_Store` counts as effectively empty. / 删除后检查执行日志中的状态与 `pruned_dirs`。只有成功移入 Trash 的文件才触发空父目录清理，且不会越过 `review_root`；仅含 `.DS_Store` 的目录视为有效空目录。
16. Preview rollback with `python scripts/kb_review.py --review-dir KB-Review-YYYY-MM-DD --review-root <knowledge-root> --rollback`, then append `--execute`. Only `moved-to-trash` and legacy `trashed` rows are eligible; source and Trash paths are boundary-checked. / 先预演 rollback，再追加 `--execute`。只有 `moved-to-trash` 和旧版 `trashed` 行可回退；脚本会校验 source 与 Trash 路径边界。
17. If the original path already exists, rollback never overwrites it; restore under a renamed conflict path and record `restored-renamed-conflict` in `trash-rollback-log.md`. / 若原路径已存在，rollback 不覆盖它；改名恢复并在日志中记录 `restored-renamed-conflict`。

Do not generate CSV or extra intermediate reports by default; create `second-brain-coverage.md` only when explicitly requested. / 默认不生成 CSV 或额外中间报告；仅在明确请求时生成 `second-brain-coverage.md`。

Record `generate_asset` only as a request to improve the semantic layer; [`agent-readable-doc`](../../agent-readable-doc/SKILL.md) or the project adapter performs later `.agent.md` generation or rebuilding. `kb-review` never generates, modifies, re-summarizes, or validates `.agent.md`. / `generate_asset` 只记录为改善语义层的请求；后续 `.agent.md` 生成或重建由 [`agent-readable-doc`](../../agent-readable-doc/SKILL.md) 或项目 adapter 完成。`kb-review` 不生成、修改、重新摘要或验证 `.agent.md`。

After KB Review decisions are complete in an Agent OS workflow, run [`second-brain`](../../second-brain/SKILL.md) with `--source-mode asset-manifest` to index only retained independent assets. The coverage index defaults to the nested sibling and can be overridden with `--second-brain-index`, `KB_REVIEW_SECOND_BRAIN_INDEX`, or `KB_REVIEW_PACKAGE_ROOT`. / Agent OS 流程中的 KB Review 决策完成后，再以 `--source-mode asset-manifest` 运行 [`second-brain`](../../second-brain/SKILL.md)，只索引保留的独立资产。coverage index 默认来自相邻嵌套包，也可通过上述参数或环境变量覆盖。

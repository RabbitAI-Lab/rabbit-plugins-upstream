# PRD 骨架模板 — 完整版

> 本模板遵循"先骨架后血肉"的原则：先用一页纸把框架搭好，评审过后再填细节。

---

## 使用说明

1. **第一步**：用 15 分钟填写"一句话描述 + 为什么现在做 + 核心流程"——这三部分足够启动第一次评审
2. **第二步**：评审通过后，用 1-2 小时补充"关键分支""验收标准""埋点清单"
3. **第三步**：技术评审前，补充"非功能需求"和"已知风险"

不要在第一步就纠结于埋点表里该写什么字段。

## 3. 核心流程（阳光大道）

[画 3-7 步的主线流程，只画"一切顺利"的情况]

1. 用户进入 [页面名称]
2. 系统展示 [初始状态]
3. 用户执行 [核心操作]
4. 系统进行 [校验/处理]
5. 系统返回 [结果]
6. 用户看到 [预期反馈]

> 提示：如果核心流程超过 7 步，考虑拆分功能或重新设计交互。

---

## 4. 关键分支与异常处理

| 场景 | 触发条件 | 预期行为 | 优先级 |
|------|---------|---------|--------|
| 未登录 | 点击需登录才能使用的功能 | 拉起登录，登录成功后回到原页面 | P0 |
| 数据为空 | 该区域无数据可展示 | 显示空状态引导（含行动按钮，不空白） | P0 |
| 网络异常 | 请求超时/失败 | 提示重试 + 本地缓存兜底 | P0 |
| 权限不足 | 用户无该操作权限 | 告知权限不足 + 引导联系管理员 | P1 |
| 并发冲突 | 多人同时操作同一数据 | 提示"数据已被他人修改"，刷新后重试 | P1 |
| 内容超限 | 输入超出长度/数量限制 | 实时显示剩余字数，超限时禁用提交 | P1 |
| 操作频率过高 | 短时间内重复提交 | 按钮置灰 + 倒计时（如 60s 后才能重发） | P2 |

## 填写示例（参考）

以下是一个真实场景的填写示例，展示每个字段应该达到的详细程度：

### 功能名称：订单快速搜索

**一句话描述**：仓库拣货员在每天处理 200+ 订单时，通过订单号或客户名快速搜索，能在 3 秒内定位到目标订单。

**为什么现在做**：
- 用户现状：拣货员目前用 Ctrl+F 在页面上找，但单页只显示 20 条，需要翻页多次
- 关键数据：拣货员平均每天搜索 50+ 次，每次翻页耗时约 40 秒，一天浪费 ~30 分钟
- 不改的代价：拣货效率瓶颈影响发货时效，已有 2 个大客户投诉发货慢

**核心流程**：
1. 拣货员进入订单管理页
2. 页面顶部搜索框获取焦点
3. 输入订单号后 4 位或客户名关键字
4. 系统实时匹配，500ms 内展示结果
5. 拣货员点击目标订单进入详情

**关键分支**：
- 搜索无结果 → 显示"未找到匹配订单，试试调整关键词" + 快捷筛选入口
- 搜索结果 >50 条 → 显示前 20 条 + "显示更多"按钮 + 提示"建议输入更精确的关键词"
- 连续快速输入 → 仅以最后一次输入为准发起搜索（防抖 300ms）

**验收标准**：
- [ ] 搜索框在订单列表页顶部，页面加载后自动获取焦点
- [ ] 输入停止后 500ms 内出现搜索结果
- [ ] 输入"张三"能搜索到客户名为"张三"和"张三丰"的订单
- [ ] 输入订单号后 4 位"6421"能匹配到完整订单号"ORD2021071506421"
- [ ] 搜索无结果时显示引导文案和筛选入口，不显示空白

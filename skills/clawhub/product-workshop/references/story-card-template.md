# 用户故事切片卡模板集合

## 使用说明

这种卡片格式替代传统的"作为...我想要...以便..."模板句。优势：
- 更自然地描述真实场景和上下文
- 强制写出"用户现在怎么做"
- 验收标准更具体，更适合开发直接使用

---

## 基础卡模板

```
┌─────────────────────────────────────────────────┐
│ 故事 ID：[项目简称]-[编号]   优先级：[P0/P1/P2]  │
│                                                  │
│ 一句话：_________________________________________│
│                                                  │
│ 用户是谁：______________________________________│
│                                                  │
│ 使用场景（什么时候、什么情境下）                  │
│ _________________________________________________│
│                                                  │
│ 现在怎么做（当前的替代方案或痛点的具体表现）       │
│ _________________________________________________│
│                                                  │
│ 验收标准（可测试、无歧义）                        │
│ 1. _____________________________________________│
│ 2. _____________________________________________│
│ 3. _____________________________________________│
│                                                  │
│ 工作量估算：□ S(1人天) □ M(2-3人天) □ L(5+人天)│
│ 依赖项：________________________________________│
│                                                  │
└─────────────────────────────────────────────────┘
```

## 填写示例 1：B2B 后台类

```
┌─────────────────────────────────────────────────┐
│ 故事 ID：OMS-014              优先级：P0         │
│                                                  │
│ 一句话：拣货员通过扫码枪快速录入出库商品，        │
│         减少手工输入错误                          │
│                                                  │
│ 用户是谁：仓库拣货员，日均处理 200+ 出库单       │
│                                                  │
│ 使用场景：每天上午 10 点和下午 3 点是出库高峰，   │
│           需要在 1 小时内完成 50+ 单出库操作      │
│                                                  │
│ 现在怎么做：手工逐条输入商品编码，每单平均 8 个   │
│             商品，每天有 3-5 次因手误输错编码     │
│                                                  │
│ 验收标准：                                        │
│ 1. 扫码枪扫描商品条码后自动填入商品编码字段       │
│ 2. 连续扫码时焦点保持在编码输入框，不跳转         │
│ 3. 扫描到不存在的编码时震动 + 红色闪烁提示        │
│ 4. 同一商品重复扫描时数量自动 +1                  │
│                                                  │
│ 工作量估算：M（2 人天）                           │
│ 依赖项：需仓库提供扫码枪测试设备                   │
│                                                  │
└─────────────────────────────────────────────────┘
```

## 填写示例 2：C 端消费类

```
┌─────────────────────────────────────────────────┐
│ 故事 ID：SHOP-007             优先级：P0         │
│                                                  │
│ 一句话：用户在商品详情页看到最近浏览过的商品，    │
│         方便比较和回头购买                         │
│                                                  │
│ 用户是谁：25-40 岁女性，月均网购 4-6 次          │
│                                                  │
│ 使用场景：浏览商品时想对比之前看过但没下单的       │
│           款式，又不想重新搜索                     │
│                                                  │
│ 现在怎么做：截图保存到相册，或开多个 tab 来回切，  │
│             经常忘记截的是哪一款                   │
│                                                  │
│ 验收标准：                                        │
│ 1. 浏览过 ≥1 件商品后，「最近浏览」出现在详情页底部 │
│ 2. 当前商品不出现在列表里                         │
│ 3. 展示商品图 + 标题 + 价格，最多 10 件           │
│ 4. 点击商品卡片跳转到对应详情页                   │
│ 5. 首次访问商品详情页的用户不显示该区域            │
│                                                  │
│ 工作量估算：S（1 人天）                           │
│ 依赖项：无                                        │
│                                                  │
└─────────────────────────────────────────────────┘
```

## 填写示例 3：内部工具类

```
┌─────────────────────────────────────────────────┐
│ 故事 ID：CRM-022              优先级：P1         │
│                                                  │
│ 一句话：销售主管在移动端快速审批下属提交的        │
│         折扣申请，不因不在电脑旁而卡流程           │
│                                                  │
│ 用户是谁：区域销售主管，50% 时间在外出拜访客户    │
│                                                  │
│ 使用场景：在外勤途中收到下属的审批请求，           │
│           希望在手机上 30 秒内完成审批             │
│                                                  │
│ 现在怎么做：让下属发微信，凭记忆和信任口头同意，   │
│             回公司后补系统审批，经常忘记补          │
│                                                  │
│ 验收标准：                                        │
│ 1. 移动端审批入口有红点数字提醒待审批数量         │
│ 2. 审批卡片展示：申请人、客户名、折扣幅度、原因   │
│ 3. 同意/拒绝操作后无需跳转，直接更新卡片状态      │
│ 4. 拒绝时弹窗要求必填拒绝原因                     │
│ 5. 审批完成后推送通知给申请人                      │
│                                                  │
│ 工作量估算：M（3 人天）                           │
│ 依赖项：需移动端框架支持推送通知                   │
│                                                  │
└─────────────────────────────────────────────────┘
```

## 批量故事排序方法

当有 10+ 个故事需要排优先级时，用"两两比较法"：

1. 把所有故事标题写在便利贴/卡片上
2. 每次取两张，问："如果只能做一个，选哪个？"
3. 胜者留下继续比，败者放回
4. 重复直到排出顺序

不要给每张卡打分——人在打分时容易全部打高分。两两比较强迫做出真实选择。

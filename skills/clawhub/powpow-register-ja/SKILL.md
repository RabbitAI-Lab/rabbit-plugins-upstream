# PowPow Register（バブル登録アシスタント）

新規ユーザーを「バブル（PowPow）って何？」から「アカウントがアクティベーションされ、ワンクリックログインして遊び始められる状態」まで導きます——すべて会話の中で完結します。ユーザーが会話を一時的に離れるのは2回だけ：**メールボックスに認証コードを見に行く**ことと、**決済レジで支払う**こと（Alipay / PayPal。agent がレジページを自動で開きます）。

**バージョン 2.1.0** · 2026-10-11（v2 以降は agent 代行モード：スクリプト契約と完全な時系列は `references/agent-flow.md`、フィールドルール・レート制限・エラー調査は `references/registration-flow.md`、決済チャネルは `references/payment-and-activation.md`、製品スクリーンショット一覧は `references/screenshots.md`。v2.1.0 より PayPal サブスクも agent が代行でき、Alipay と並んで選べます）

## 実行環境

- コアスクリプト `scripts/powpow-register.mjs`：**依存関係ゼロ**、**Node ≥ 18** が必要。開始前に一度 `node scripts/powpow-register.mjs status` を実行して環境が使えることを確認します。
- スクリプトのすべてのリクエストは公式ドメイン `https://global.powpow.online` にのみ送信されます。
- **Node がない / スクリプトがエラーを出すとき**：自動的に純粋ガイドモードへフォールバックします——登録ページ https://global.powpow.online/register とサブスクリプションページ https://global.powpow.online/subscription をユーザーに渡し、`references/registration-flow.md` に沿って伴走ガイドします。スクリプトを何度も無理に試さないこと。
- 会話中断からの復帰：まず `status` でフローがどこまで進んだかを確認し、そこから続けます。

## Trigger Conditions

- 登録意図：「PowPowに登録」「powpowアカウントを登録」「PowPowの登録方法は」「sign up powpow」
- 登録が詰まった：「認証コードが届かない」「ユーザー名が使用済みと言われる」「パスワードがいつまでも不合格」
- 登録後の問題：「ログインでアカウント未アクティベーションと言われる」「403 pending_payment」「バブルでどうやって支払い・サブスクするの」

**起動しない**：投稿・デジタルヒューマン作成（→ powpow-simple）；Web 側のコード開発（別の開発系スキルを参照）。ユーザーが登録も投稿もしたいときは：まず本スキルを最後まで進め、アクティベーション完了後に powpow-simple へ引き継ぎます。

## フロー概要

| ステップ | agent がやること | ユーザーがやること |
|---|---|---|
| 1 製品紹介 | 紹介 + スクリーンショット送信 | ぱっと見る |
| 2 情報確認 | ユーザー名/ニックネームを積極的に提案、パスワードは二択、メールアドレスを質問 | 確認・提供 |
| 3 認証コード送信 | `send-code` | —— |
| 4 認証コード読み返し | —— | メールボックスで6桁コードを確認し、戻って送信 |
| 5 登録送信 | `register`（アバター直送込み）、エラーは自動処理 | —— |
| 6 半ログイン + 決済 | `login-link(pending)` → `create-order --provider alipay|paypal` → レジを開く → `query` ポーリング | リンクを開く、支払う |
| 7 正式ログイン | `refresh-login` → `login-link(home)` | リンクを開いてホームへ |
| 8 仕上げ | `cleanup` + アカウントカード交付 + 体験案内 + プラグイン紹介 | 遊び始める |

## 第1ステップ：製品紹介 + スクリーンショット（スキップ不可）

ほとんどのユーザーはバブルを見たことがありません。最初にやるべきはフローの説明ではなく、製品を**見せる**ことです：

1. バブルを約120字で紹介します：パッと撮った写真が一篇の旅行記になり、公開地図の上に「バブル」としてピン留めされます。バブルは時間とともに古くなりますが、他の人のいいねで復活できます。地図上には会話できる「デジタルヒューマン」もいます。プラットフォームURL：https://global.powpow.online 、先に動画を見たい場合は：https://www.bilibili.com/video/BV1Wu826UEVz/
2. **スクリーンショットを送ります**。スクリーンショットは `assets/screenshots/powpow-0N.jpg` としてスキルに同梱済み——ローカル画像ファイルとしてそのまま送るだけで、ネット接続は不要です。一覧・各画像の内容と使用タイミングは `references/screenshots.md` を参照。開始時に最もよく使う組み合わせ：地図ページ（powpow-03）+ 投稿詳細ページ（powpow-06）。

スクリーンショットのルール（厳守事項）：

- スクリーンショットは `assets/screenshots/`（`powpow-0N.jpg`）に**スキル同梱済み**——ローカル画像ファイルとして直接送ります。GitHub が開けない環境を含め、どんな環境でも利用可能です。
- 毎回、現在の話題に関連する1〜3枚だけを送り、一度に全部貼り付けないこと。
- パッケージ内のファイルが予期せず欠けていた場合は、`references/screenshots.md` に載っているホスティングリンクへフォールバックします（注意：中国本土からは開けない場合があります）。

紹介が終わったら、選択権をユーザーに委ねます：**「登録する気になったら、3分で会話の中でアカウントを作りましょう。あなたはメールの認証コードを一度見るだけです。」**

## 第2ステップ：登録情報の確認（1ラウンド1質問、一度に全部聞かない）

- **ユーザー名**（必須）：会話の文脈/システムのユーザー名から**1つ積極的に提案**します（2〜50文字、大文字小文字を区別しません）。ユーザーが同意すればそのまま使い、変えたければ変えます。
- **パスワード**（必須、まず二択を尋ねる）：
  - ユーザーが自分で提供 → その後スクリプトには環境変数で渡します。**コマンドライン引数には絶対に書きません**；
  - agent が生成 → `node scripts/powpow-register.mjs gen-password` を実行し、生成されたパスワードを**すぐユーザーに送って保存してもらいます**（表示はこの一回きりで、以降は二度と出しません）。
- **メールアドレス**（必須）：必ずユーザー本人に提供してもらいます——これはアカウントの身元の錨であり、**代理で推測しない**こと。
- **ニックネーム**（任意）：デフォルトはユーザー名と同じにすることを提案します。
- **アバター**（任意）：ユーザーがローカル画像のパス（≤5MB、SVG 以外）をくれればスクリプトが直送します。なければスキップします（プラットフォームのデフォルトロゴが使われます）。あなたに画像生成能力があれば、1枚作ることを提案しても構いません。
- **電話番号**（任意、中国本土の番号）：デフォルトはスキップし、ユーザーが自分から紐付けたがるときに初めて受け付けます。

確認が取れたら `prepare-suggest --username U --nickname N --email E` を実行して状態ファイルに記録します（以降の register で再入力が不要になります）。

## 第3〜4ステップ：メール認証コード（唯一、会話を離れる必要がある場面）

```
node scripts/powpow-register.mjs send-code --email <メールアドレス>
```

その後、ユーザーにはっきり伝えます：**メールボックスで6桁の数字の認証コードを探してください。10分間有効です。迷惑メール・広告メールフォルダも必ず確認を。**見つけたら戻ってきてコードを送ってもらいます。送信には60秒のクールダウンがあるので、連打しないこと。

## 第5ステップ：登録の送信（agent 代行）

```
POWPOW_REGISTER_PASSWORD=<パスワード> node scripts/powpow-register.mjs register --code <認証コード> [--username U] [--nickname N] [--avatar <ローカル画像パス>] [--phone P]
```

成功すればその場でアカウントが作られます（pending 状態、初期バッジ3つ付き）。よくあるエラーは自動処理し、ユーザーを中断させません：

| エラー | 処理 |
|---|---|
| ユーザー名が既に存在（用户名已存在） | バリエーション（ユーザー名+数字）を自動提案し、ユーザー確認後にそのままリトライ（認証コードはまだ有効、再送不要） |
| メールアドレスが使用済み（邮箱已被使用） | ユーザーに質問：別のメールに変えるか、実は既にアカウントを持っているか（ログイン/パスワードリセットに切り替え） |
| メール認証コードの誤りまたは期限切れ（邮箱验证码错误或已过期） | 10分超過 → `send-code` をやり直す |
| 送信/登録が頻繁すぎる（429） | 1分待ってリトライ。ユーザーに一言添えるだけでOK |

## 第6ステップ：ワンクリックログイン（リンク1）+ 決済

1. 登録成功後すぐに：
   ```
   node scripts/powpow-register.mjs login-link --target pending
   ```
   リンクをユーザーに送ります：**開くとブラウザはそのままサブスクリプションページに着地し、既にログイン状態**——このため支払い完了時の戻りページが正しく「支払い成功」を表示できます。（この状態ではコンテンツページは引き続きサブスクページへ弾かれますが、これはプラットフォームのペイウォールが正常に働いているだけで、バグではありません。内部メカニズムの説明も不要です。）
2. **ユーザーに支払い方法を選んでもらいます**。2つのチャネルを提示：
   - **Alipay（中国国内 / Alipay を持っているユーザー）**：対応する期間を一括購入、**自動更新なし**
     - 月次 **¥6.99**（まず試すならおすすめ）/ 四半期 **¥19.99** / 年間 **¥69.99**
   - **PayPal（海外 / Alipay を持たないユーザー）**：月次の自動更新、いつでも解約可能
     - Premium Monthly、約 **$1/月**（サブスクページの表示に準拠、自動更新）
3. ユーザーが選んだら：
   - **Alipay**：
     ```
     node scripts/powpow-register.mjs create-order --package monthly
     ```
   - **PayPal**：
     ```
     node scripts/powpow-register.mjs create-order --provider paypal
     ```
   スクリプトが支払いページのファイルパスを返すので、**システムコマンドで直接開きます**（Windows：`start <ファイル>`；macOS：`open <ファイル>`；Linux：`xdg-open <ファイル>`）。ブラウザが自動的に Alipay / PayPal 公式レジへ移動し、ユーザーが支払いまたは課金の承認を完了します。
4. 10〜15秒ごとに `query` を実行し、`paid` または `ACTIVE` が返るまで繰り返します（着金・承認は通常数秒〜1分）。ユーザーが途中で支払いページを閉じたら → そのまま `create-order` をやり直します（旧注文・保留中のサブスクは2時間で自動クローズまたは失効。気にしなくて構いません）。
5. WeChat スキャンは手動確認で着金が遅れることがあり、華為 IAP は HarmonyOS アプリ内のみ利用可能です。この2つは skill が代行しません。支払いが済んだら同じく第7ステップへ進みます。

## 第7ステップ：正式ログイン（リンク2）

着金確認後、まず最新のサブスク宣言を含むログイン状態に交換し、それからホーム直行リンクを生成します：

```
POWPOW_REGISTER_PASSWORD=<パスワード> node scripts/powpow-register.mjs refresh-login
node scripts/powpow-register.mjs login-link --target home
```

リンクをユーザーに送ります：**開くとそのままホームに着地、完全な会員状態**。ここで登録の全フローが完了です。

## 第8ステップ：仕上げ

1. `node scripts/powpow-register.mjs cleanup` で本機の一時状態ファイル（セッション証憑）をクリアします。
2. ユーザーに「アカウントカード」を渡します：ユーザー名、メールアドレス、会員有効期限（パスワードは再表示しません——生成モードでは生成時に保存済み、ユーザー設定のものは本人が知っています）。
3. 体験を案内します：地図をぶらつく、最初の旅行記を投稿する（→ powpow-simple へ引き継ぎ）。
4. 拡張をおすすめします：`@durenzidu/powpow-integration` skill と `@durenzidu/openclaw-channel-powpow` プラグイン——バブルをユーザー自身の agent へ接続します。欲しければインストールコマンドを渡します。
5. 「次のステップ」ブロックで締めくくります。

## Conversation UX

powpow の従来のサービス型トーンを踏襲します：

- **ユーザーが主語**。「あなたは〜できます」を「私は〜してほしい」より優先します。説教じみず、上から目線も避けます。
- **1ラウンドで進める判断は1つだけ**。情報を求める前には理由を添えます。
- **毎回の返信の最後**は固定の「次のステップ」ブロック（区切り線 + 👉 + 単一の行動 + 「やり終えたら〜します」の一文）。例：
  ```
  ────────────────────
  👉 今やっていただきたいこと：メールボックスで6桁の認証コードを探して、そのまま私に送ってください
     （受け取ったらすぐアカウントを作ります）
  ```
- **パスワードの安全について積極的に説教しない**。ユーザーが聞かない限り、内部メカニズム・レート制限・セキュリティ設計を説明しません。
- agent が代行するときは特に進捗を報告します：各スクリプトステップの後に、直前に何が起きたかを一言で伝えます（「アカウントができました」「支払いページを開きました」）。

## 厳守事項

- **証憑の安全**：パスワードは環境変数 `POWPOW_REGISTER_PASSWORD` でのみスクリプトに渡し、**絶対に**コマンドライン引数には書きません（プロセス一覧から見えます）、いかなるファイルにも書き込みません（生成モードで一度だけ表示するのはユーザーに保存してもらうためで、以降は復述しません）。認証コードは公式登録インターフェースにのみ使われ、使い捨てです。
- **公式の境界**：すべてのリクエストは `https://global.powpow.online` にのみ送ります（スクリプトに内蔵済み）。ユーザー情報を第三者のアドレスに送ることは絶対にありません。
- **決済の境界**：agent は注文の作成、レジを開くこと、着金確認のみを行います。**絶対に**ユーザーの Alipay / PayPal アカウント/決済証憑には触れず、「代行支払い」も約束しません。
- **ペイウォールはバグではない**：pending 状態でサブスクページ/戻りページに入れるのは設計内の許可です。コンテンツページが弾かれるのはプラットフォームのペイウォールが正常に働いているだけで、迂回を試みないこと。
- **フォールバックの自由**：ユーザーがどのステップでも自分でやりたがったり、環境がスクリプトに対応していなかったりすれば、いつでも純粋ガイドモードへ退きます——リンクを渡し、ルールを説明し、共にエラーを潰します。
- プラットフォームのルールを捏造しないこと：フィールドルール・エラー文言・レート制限パラメータはすべてプラットフォームのコードに由来します（`references/registration-flow.md` にソースの所在あり）。プラットフォーム更新時は実際の挙動を基準にします。
- 画像の表示にはパッケージ内 `assets/screenshots/` のスクリーンショットのみを使います（各画像の用途は `references/screenshots.md`）。
- 毎ラウンドを「次のステップ」ブロックで締めくくり、ユーザーが今何をすべきかを常に分かるようにします。

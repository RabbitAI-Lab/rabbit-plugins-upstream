# 登録フロー詳細 — powpow-register

問題調査時に参照するドキュメントです。すべてのルールはプラットフォームのソースコード（Next.js 前後端の整合性バリデーション）に由来し、出所を明記しています。プラットフォーム更新時は、オンライン上の実際の挙動を基準にしてください。

## 入口

- 登録ページ：https://global.powpow.online/register
- ログインページ：https://global.powpow.online/login
- 購読ページ：https://global.powpow.online/subscription
- 共有リンクなどから `?next=...` 付きで入った場合、登録＋支払い完了後に自動で元のページへ戻ります。

## フォームのフィールドとルール

| フィールド | 必須 | ルール | ソースコード |
|---|---|---|---|
| アバター | 任意 | 画像 5MB 以下、SVG 非対応。サーバーが自動圧縮（100KB超は 400×400 / 品質90 に圧縮） | `src/app/api/auth/register/route.ts` |
| ユーザー名 | 必須 | 2〜50文字。trim 後に**小文字**で保存（Tom と tom は同一ユーザー名。登録側もログイン側も大文字小文字を区別しない） | 同上（zod schema） |
| パスワード | 必須 | 8〜100文字。大文字・小文字・数字をすべて含むこと | 同上 |
| 確認パスワード | 必須 | パスワードと一致（フロントエンドのみで検証） | `src/app/(public)/register/page.tsx` |
| ニックネーム | 任意 | 100文字以下。未入力ならユーザー名が使われる | register route |
| メール | **必須** | 正しいメール形式、255文字以下。1つのメールで登録できるアカウントは1つ | register route |
| メール認証コード | **必須** | 6桁の数字。**10分間有効**。認証成功で失効。再送すると古いコードは使用済み扱い | `src/lib/email-verification.ts` |
| 電話番号 | 任意 | 中国本土の携帯番号 `1[3-9]` 始まり、全11桁。1つの番号に紐づくアカウントは1つ | register route |

ページにはさらに3つのサードパーティログインボタンがあります：**Google、Watcha、華為アカウント**（`GoogleSignInButton` / `WatchaLoginButton` / `HuaweiLoginButton`）。サードパーティアカウントにはローカルパスワードがないため、後からパスワードでログインすると「该账号未设置密码，请使用其他方式登录」（このアカウントにはパスワードが設定されていません。別の方法でログインしてください）が返ります。

## レート制限・総当たり攻撃対策パラメータ

| 挙動 | 制限 | 出所 |
|---|---|---|
| 登録送信 | **1分間/IP あたり3回**、超過で 429 | `src/lib/rate-limit.ts` `REGISTER_RATE_LIMIT` |
| 認証コード送信 | 同一IP 1分あたり1回 **かつ** 同一メール 1分あたり1回、超過で 429。フロントのボタンは60秒カウントダウン | `src/app/api/auth/register/send-code/route.ts` |
| 認証コード検証 | メールごとに10分間で最大 **5回**。上限到達後はコードが正しくても拒否され、再送信が必要 | `src/lib/email-verification.ts` |
| パスワード再設定コード送信 | 1分/IP あたり1回 | `src/app/api/auth/forgot-password/route.ts` |
| ログイン | 1分/IP あたり5回。同一アカウントで連続 **5回失敗すると30分ロック**（423）。ロック中は残り回数が減っていく表示 | `src/app/api/auth/login/route.ts`、`rate-limit.ts` |

**プライバシー保護の挙動**：認証コード送信 / パスワード再設定時に、メールが登録済みか存在しないかにかかわらず、API は同じ成功メッセージを返し、メールの登録有無を漏らしません。

## 登録成功後のステータス遷移

1. ユーザーは `accountStatus: 'pending'` で保存され、初期 **3つのバッジ**（register route）。
2. サーバーは同時に2つの HttpOnly cookie をセット：JWT（`/subscription` へ直接アクセス可）と pendingUserToken（購読フローの本人証明）。
3. 登録ページが `pending_payment` を検知 → `/subscription` へ遷移（`next` の戻り先パラメータを保持）。
4. 支払い完了 → `accountStatus` が `active` に変化（PayPal は Webhook で自動アクティベーション、WeChat スキャンは手動確認、華為 IAP は `activate-huawei` 経由）。詳細は `payment-and-activation.md`。

未アクティベーション（pending）ユーザーがコアAPI（フィード、地図、デジタルヒューマン会話、チェックインなど）を呼ぶとすべて 403 になります。ただし投稿の共有リンクは例外（公開アクセスを維持）。

## よくあるエラー調査表

| 現象 | 原因 | 対処 |
|---|---|---|
| 「用户名已存在」 | ユーザー名が使用済み（大文字小文字を区別しない） | 別のユーザー名にする |
| 「邮箱已被使用」 | メールが登録済み | メールを変更。またはログイン +「パスワードを忘れた」で旧アカウントを復旧 |
| 「邮箱验证码错误或已过期」 | コード入力ミス / 10分超過 / 5回試行失敗で拒否 | 「再送信」をクリックし、**最新の**メールの認証コードを使う |
| 認証コードが届かない | 60秒のレート制限。または迷惑メール・広告メールに入った | カウントダウン終了を待って再送信。迷惑メールフォルダを確認 |
| 「手机号已被使用」 | 電話番号が他のアカウントに紐づいている | 電話番号を削除（任意項目）または番号を変更 |
| 「注册请求过于频繁」/ 429 | 登録が1分3回/IPの上限に達した | 数分待って再試行 |
| 409「用户名或邮箱已被注册」 | 送信瞬間に他人と名前が衝突（並行登録の保険） | ユーザー名またはメールを変えて再試行 |
| 「图片大小不能超过5MB」/「不支持 SVG」 | アバターがルール違反 | 画像を変更、またはアバターをスキップ |
| 登録成功だがログイン403「请完成订阅以激活账户」 | アカウントがまだ pending | ログイン後、画面の案内に従って `/subscription` で購読を完了 |
| ログイン423「账户已锁定」 | パスワード連続5回ミス | 30分待つ |
| ログイン401「还剩 N 次尝试机会」 | パスワードミス、ロックに近い | よく考えてから試すか、直接「パスワードを忘れた」を使う |
| 「该账号未设置密码，请使用其他方式登录」 | サードパーティ（Google / Watcha / 華為）アカウント | 元のサードパーティボタンでログイン |
| 「该账号已注销」 | アカウントが deactivate 済み | 再登録が必要 |

## ログイン豆知識（ついでに調査にも）

ログインは**ユーザー名 / メール / 電話番号**の3in1入力に対応（いずれもアカウント名として可）。パスワードを忘れた場合：ログインページ →「パスワードを忘れた」→ 登録メールを入力して6桁コードを受信 → リセット。

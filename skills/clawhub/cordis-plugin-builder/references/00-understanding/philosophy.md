# Cordis 核心理念与 DSH 深度定制

> 蒸馏自 001/Cordis.md（2026-08）。理解"为什么这样设计"，而非只记"怎么用"。

## 1. 时空可组合性（Spatiotemporal Composability）

- **时间可组合**：插件对环境的副作用可完整撤销，无需重启进程
- **空间可组合**：插件声明依赖，并对依赖服务的出现/消失/替换做出响应
- **资源安全**：只要插件所有对外资源占用能被完整回收，就达到"资源安全"——这是 HMR 的前提（类比 Rust 所有权：Context 是"插座"，插件是"插头"，卸载即拔掉，逆函数自动有序撤销）

## 2. 五大核心概念协同

```
插件（函数/对象/类）→ 操作 Context（服务容器，Proxy 动态解析）
  → inject 声明依赖（框架自动推导加载顺序 + 级联重载）
  → 类型化事件通信（emit/waterfall/parallel/serial/bail）
  → 可逆副作用（ctx.on/ctx.effect 注册，卸载自动撤销）
```

**服务 vs 事件的分工哲学**：
- **服务（Service）**：解决"我要调用一种能力"（`ctx.llm` / `ctx.tools`）
- **事件（Event）**：解决"我想介入一个过程"（工具执行前插审计、step 结束时拦截）

## 3. Context 作用域派生（三个原语）

| 原语 | 语义 | 场景 |
|------|------|------|
| `extend` | 原型继承父级属性 | 常规子作用域 |
| `isolate` | 服务隔离，局部世界 | 为单个 Agent 提供独立服务视图 |
| `intercept` | 拦截并合并服务配置 | 多租户/分层配置 |

## 4. Fiber 层级与父子撤销

每个加载的插件对应一个 Fiber（状态机：PENDING → LOADING → ACTIVE）。
**父 Fiber 卸载 → 其创建的所有子 Fiber 沿生命周期树递归撤销**——DSH 多 Agent 协作（父 Agent 动态生成子进程工具）的关键隔离机制。

## 5. DSH 深度定制（魔改特性，区别于上游 Cordis 4）

- **`symbols.caller` 拦截器**：穿透 Shadow Context，将嵌套工具错误的归属追溯到真实调用方（遥测错误归属准确）
- **`Reflect.apply` 替代闭包绑定**：事件分发改底层动态调用，降低高频运行下的 GC 压力
- **幽灵 Fiber 状态修复**：保证 EntryTree 在高频热重载下的状态一致性
- **EntryTree 事务式 HMR**：新配置加载失败（如语法错误）自动回滚到旧 Fiber 状态，系统不进入半瘫痪

## 6. 自演化方向

"创造模式"下智能体可检查运行中插件树、编写并挂载临时插件扩展能力——依赖完备的副作用撤销，任务完成后"干净"卸载。**插件必须资源安全**才能支持这种自演化。

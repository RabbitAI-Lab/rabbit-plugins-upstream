# 投标文件标准结构

## 动态章节结构

投标文件的章节结构**不是固定的**，需要按每份招标文件的具体要求来定义。

系统通过以下方式获取章节结构，按优先级依次尝试：

```
优先级1：用户上传招标文件 docx → 自动解析提取大纲章节
优先级2：用户手动输入章节列表
优先级3：使用默认14章节框架（见下文）
```

---

## 方式一：解析招标文件获取章节结构

当用户上传招标文件（.docx 格式）时，系统通过 `parse_bidding_docx.py` 自动提取：

1. **章节列表** — 从文档大纲（Heading段落）逐级提取
2. **层级关系** — 保持 H1→H2→H3 的树形结构
3. **章节标题原文** — 保留招标文件中的原始标题文字

### 解析后的章节结构示例

```
从招标文件提取的大纲：
├── 第一章 投标须知（H1）
│   ├── 1.1 项目概况（H2）
│   ├── 1.2 投标人资格要求（H2）
│   │   ├── 1.2.1 基本资格（H3）
│   │   └── 1.2.2 特定资格（H3）
│   └── 1.3 投标文件编制要求（H2）
├── 第二章 合同条款（H1）
│   └── 2.1 通用条款（H2）
...
```

系统会自动将提取的章节结构按用户选择的编号体系重新编号，生成投标文件框架。

---

## 方式二：手动输入章节列表

用户按以下格式逐行输入章节：

```
H1: 投标函
H1: 法定代表人身份证明
H1: 授权委托书
H1: 投标保证金
H2: 保证金金额
H2: 缴纳方式
H1: 资格审查资料
H2: 基本情况表
H3: 企业基本信息
H3: 股东信息
...
```

支持 H1~H5 五个层级，系统按所选编号体系自动生成编号。

---

## 方式三：默认14章节框架

当用户未提供招标文件且未手动输入时，使用以下默认框架：

```
封面（无页眉页脚，不编页码）
  - 右上角：【正本】/【副本】
  - 项目名称、代理编号
  - 投标人名称、地址
  - 自定义项目编号
  - 日期

目录（从正文节第一页开始编页码）

H1: 投标函
H1: 法定代表人（单位负责人）身份证明
H1: 授权委托书
H1: 联合体协议书
H1: 投标保证金
H1: 投标一览表
H1: 商务和技术偏差表
H1: 分项报价表
H1: 资格审查资料
  H2: 基本情况表
  H2: 投标人资格证明资料
    H3: 基本资格条件
    H3: 特定资格条件
  H2: 投标人资格声明
H1: 投标技术方案
  H2: 响应一览表
  H2: 项目组人员汇总表
  H2: 主要人员简历表
  H2: 综合实力（资质证书复印件）
  H2: 实施案例
  H2: 业务方案
  H2: 技术方案
  H2: 实施方案
  H2: 人员投入
  H2: 售后服务
H1: 业绩证明材料
H1: 投标单位廉洁承诺书
H1: 其他资料
H1: 评分索引表
```

> 注意：默认14章节仅为通用参考框架，实际使用时推荐上传招标文件获取精确的章节结构。

---

## 标题层级与多级编号

标题层级统一为五级（H1~H5），但编号格式根据用户选择的体系不同而不同。

详见 `formatting.md` 中的「标题编号体系」章节。

---

## 章节结构确认流程

```
Step 1：用户上传招标文件或选择章节输入方式
    │
    ▼
Step 2：系统展示解析/输入的章节列表
    │
    ▼
Step 3：用户确认或编辑章节列表
    │  ├─ 增：添加遗漏章节
    │  ├─ 删：移除不适用章节
    │  └─ 改：调整章节标题
    ▼
Step 4：系统按所选编号体系重新编号
    │
    ▼
Step 5：生成投标文件骨架
```

# 花艺配方引擎

把「我想送朋友一束粉白色的花，预算 200」这类模糊需求，转成一份**可执行的花艺配方**：花材清单、枝数、预算分配、替换关系、制作步骤、养护方案。

核心判断：**用户要的不是一张好看的图，是一份能拿去买、能照着插的方案。**

## 两条铁律

**铁律一：配方先行。**
先算出合法的配方（花材、枝数、预算、尺寸全部过关），再派生图像描述、购物清单、制作步骤。
不要先描述一个画面，再倒推需要什么花——那样必然出现「图里有六种花，清单只有四种」的不一致。

**铁律二：不确定的地方要标出来。**
价格、花期、识别结果都是区间估计，不是事实。输出时必须标注「参考区间」和「以当地为准」。
配方里任何一个数字被用户当成承诺，都会变成售后问题。

## 何时使用

- 用户描述场景 / 预算 / 风格，要一束花或一个瓶插方案
- 用户已知预算，问「这个预算能买什么花、各买几枝」
- 用户要花材清单、花市采购单
- 用户遇到缺货、超预算、季节不对，需要替换但保留设计意图
- 用户要制作步骤或养护方法

不适用：纯图片生成需求（用户只要效果图）、花店经营与供应链问题、婚礼全场统筹（复杂度远超单束花，另行处理）。

## 工作流

### 第一步：解析需求，补齐缺失项

从用户的话里抽取六个维度：**场合、对象、预算、风格、花器、禁忌**。

缺项处理规则：
- **预算缺失**：给三档方案（约 ¥120 / ¥200 / ¥350），让用户选，不要自己定一档
- **场合缺失**：必须先问。送人和自用是完全不同的设计（送人要体量感和完成度，自用可以更松散随意）
- **花器缺失**：默认「圆形玻璃瓶，高 18cm」，并说明这个假设
- **禁忌缺失**：主动问一句「家里有宠物或花粉过敏吗」。这一句能挡掉大部分事故

不要一次问超过三个问题。缺项多时，先按默认值出一版，再说明「这几个是我替你定的，可以改」。

### 第二步：查表与校验

读 `references/flower-library.md` 取花材档案（价格区间、花期、季节、禁忌、替换关系）。
读 `references/constraints.md` 执行硬约束：

1. **预算分配**：主花 45–55%、配花 20–25%、叶材 12–18%、点缀 5–8%、辅材 5–8%
2. **枝数与尺寸**：按花器口径和高度算冠幅与总高，再定主花枝数
3. **角色配比**：主花 : 配花 : 叶材 枝数比约 1 : 0.8 : 1.2
4. **色彩**：不超过 3 个色相，主色占 60%，点缀不超过 10%
5. **禁忌**：宠物、过敏、场合禁忌、气味强度，逐项硬性排除

任何一条不通过，回到第二步重算，不要带着违规配方往下走。

### 第三步：生成结构化配方

按 `references/output-schema.md` 的 JSON 结构输出。这是唯一的事实来源，后面所有东西都从它派生。

生成的配方必须满足：**每一枝花都有角色、有单价、有可替代项。**

### 第四步：派生四种产物

从同一份配方派生，不允许各自独立编：

- **购物清单**：名称、数量、单价、小计、合计，按花市摊位顺序排（先买叶材和配花，主花最后买，避免被压坏）
- **制作步骤**：5–8 步，每步一个动作 + 一个可验证的结果
- **养护方案**：换水频率、剪枝方式、避忌位置、预计花期、第几天做什么延长处理
- **图像描述**：按 `references/image-prompt.md` 的受限模板生成，**花材种类和数量必须与配方完全一致**

### 第五步：一致性自检

交付前逐条核对，任一条不过就改配方而不是改文案：

- [ ] 图像描述里出现的花材种类 = 配方里的种类
- [ ] 图像描述里的疏密程度 = 配方里的枝数密度
- [ ] 清单合计 = 预算 ±15%
- [ ] 每个花材都有替代项
- [ ] 禁忌项全部排除（宠物 / 过敏 / 场合）
- [ ] 花期最短的那枝决定整体更换周期，已明确告知
- [ ] 价格标注了区间和「以当地为准」

## 输出风格

先给结论，再给依据。

```
推荐方案：粉白呼吸 · 松散自然瓶插
预算 ¥192（花材 ¥150 + 花器 ¥42）
新手可做，约 35 分钟，花期 7–9 天

[花材清单]
[制作步骤]
[养护]
```

设计理念只写一句，说清「为什么这样搭」，不要写成散文。用户要的是能执行，不是被感动。

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 主花堆满，叶材只给一两枝 | 做出来是个球，没有轮廓 | 叶材枝数不少于主花的 1.2 倍 |
| 五种以上花材混搭 | 视觉混乱，总价失控 | 花材种类控制在 4–6 种 |
| 忽略花器单独计价 | 用户到花市发现超支 | 花器单列，通常占总额 20–25% |
| 养护写「注意换水」 | 等于没说 | 写「每 2 天换水，斜剪 1cm，避开空调风口」 |
| 缺货时随便换一种花 | 颜色或体量崩掉 | 按替换表换同角色、同色系、体量接近的花材 |
| 只给一张效果图 | 用户无法执行 | 图、清单、步骤、养护必须成套交付 |

# 30 分钟上手 · 自查执行手册

> 这份手册回答一个问题：买下之后，具体怎么用，四步产出什么。
> 每一步都给出要跑的命令、要填的表、要交的东西。
> 所有方法、表格与说明为原创整理，不含受版权保护的出版物原文。

## 一、开始之前：准备四样东西

| # | 要准备什么 | 从哪来 | 用来干什么 |
|---|---|---|---|
| 1 | 分支机构数、销售渠道数、从业人数、代理人数量 | 自己的实际情况 | 喂给脚本算风险分，参数越准基线越准 |
| 2 | 近 3 个月应双录保单清单 | 业务系统导出 | 核 A 组双录项 |
| 3 | 近 3 个月手续费/佣金/劳务费明细 | 财务台账 | 核 D 组费用项 |
| 4 | 质检台账（有无、有多少比例、整改有无留痕） | 质检岗 | 核 A3，决定风险分是否下调 |

> 数据不必给到本工具。脚本只吃上面第 1 项的四个数字，其余材料你自己看、自己填。

## 二、第 1 步（5 分钟）跑脚本拿基线

```bash
python scripts/compliance_audit.py --scale 8 --channels 3 --staff 12
```

参数含义与取值建议：

| 参数 | 含义 | 怎么填 |
|---|---|---|
| `--scale` | 分支机构数量 | 有几家支公司就填几家，没有就填 1 |
| `--channels` | 销售渠道数 | 个险、银保、经纪、第三方各算一个 |
| `--staff` | 从业人数 | 含内勤，不含纯外勤 |
| `--agents` | 代理人数量 | 挂靠与专职都算 |
| `--premium` | 年保费规模（万元） | 有就填，没有留空 |
| `--douluo` | 是否已建立双录质检台账 | `yes` / `no`，这直接影响 A 组风险分 |
| `--selfpolicy` | 是否有自保件互保件 | `yes` / `no`，影响 I 组风险分 |
| `--json` | 输出 JSON | 接入你自己的系统时用 |

**你会看到什么**（示例输出）：

```
总分 74.2 / 100    风险等级：高风险
【十组风险分布】
  A  双录（录音录像）合规      暴露度 3.36  ####...
  J  数据与消费者权益保护      暴露度 3.36  ####...
【优先整改 Top 10】
   1. [A1] 双录要素完整性（风险高）
      查：调近3月应双录保单清单，逐单核验五环节：……
      依：保险销售行为可回溯管理暂行办法第7条；保险销售行为管理办法第25、31条
```

三样东西：**总分与风险等级**、**十组暴露度排序**、**Top 10 优先整改项**（每项带「怎么查」和「依据条款」）。

> ⚠️ 分数是**暴露度**，不是合规结论。它反映的是"你这套业务模式在监管眼里有多容易撞上处罚高发区"，不等于"你有问题"。

## 三、第 2 步（15 分钟）按 Top 10 逐项人工核

打开 `references/监管案例与依据库.md` 的「36 项自查表骨架」，按 Top 10 的顺序走。每项四列对着填：

| 列 | 填什么 | 填错的后果 |
|---|---|---|
| 怎么查 | 你实际去调了什么材料 | 写成"已自查"等于没查，评审时会被追问 |
| 常见表现 | 你看到的具体现象 | 写成"符合"要能说得出证据在哪 |
| 依据 | 该项对应的条款 | 引用了已废止的规章，整份清单的可信度一起塌 |
| 风险等级 | 高 / 中 | 分错会让整改优先级全乱 |

**逐组抓手的顺序**（按监管处罚案例命中数排）：

| 组 | 内容 | 案例命中 | 为什么先看它 |
|---|---|---|---|
| A | 双录合规 | 6 例 | 质检比例是硬指标，缺口最容易一眼看穿 |
| G | 销售误导 | 6 例 | 朋友圈、话术、宣传物料，痕迹散在日常里 |
| D | 返佣与手续费 | 5 例 | 钱的问题，罚得最狠 |
| H | 未登记与无证展业 | 4 例 | 银保渠道和第三方合作是重灾区 |
| C | 夸大承诺收益 | 4 例 | 检索关键词就能自查，效率最高 |
| J | 数据与消保 | 4 例 | 客户信息导出记录一看就知道 |
| B | 销售适当性 | 2 例 | 涉及测评真实性与四类超阈值声明 |
| F | 未如实告知 | 2 例 | 核心是询问是否具体到病种 |
| E | 保费管理与挪用 | 1 例 | 资金流，差异单靠对账找 |
| I | 自保互保 | 1 例（间接） | **注意：没有直接处罚决定书**，属前瞻性提示 |

## 四、第 3 步（5 分钟）导出整改台账

```bash
python scripts/compliance_audit.py --scale 8 --channels 3 --staff 12 --export-todo
```

生成 `scripts/整改台账模板.csv`，表头固定 13 列：

```
序号,编号,检查项,所属组,风险等级,优先级得分,自查动作,监管依据,
自查结论(符合/部分符合/不符合),整改动作,责任人,完成日期,复核人
```

前 8 列脚本已经填好，**后 5 列留空给你填**。这就是这份台账的价值：它已经按优先级排好了，你只需要填结论、动作、责任人、日期、复核人。

建议的填法：

| 列 | 填什么 |
|---|---|
| 自查结论 | 三选一：符合 / 部分符合 / 不符合 |
| 整改动作 | 写成可验证的动作，不写"加强管理" |
| 责任人 | 写具体岗位或姓名，不写"相关人员" |
| 完成日期 | 写具体日期，不写"尽快" |
| 复核人 | 写谁来复核，不是自查的人 |

## 五、第 4 步（5 分钟）挑案例做内部宣讲

从 `references/监管案例与依据库.md` 的 26 例里挑 **3-5 个跟你最像的**：同样是小机构、同样踩双录或费用类问题。

做成一张三列对照表就够用：

| 案号 | 违规事实 | 罚款金额 | 依据条款 |
|---|---|---|---|
| 苏金罚决字〔2026〕11号 | 给予合同外利益 + 佣金列支费用 | 58 万 | 保险法116条；销售办法8/32条 |

**注意颗粒度**：处罚公示表只到**案由级**，不含违规期间、笔数、涉案客户数。讲的时候不要编这些数字。

## 七、常见追问

**Q：跑完分数 74 分，我们是不是要被罚？**
不是。分数反映暴露度，不是违规认定。同样的分数在不同机构身上的含义完全不同——一个 8 家分支、3 个渠道、12 人的机构拿到 74 分，和一个 80 家分支、5 个渠道、300 人的机构拿到 74 分，不是同一件事。要下结论，得逐项核。

**Q：脚本要联网吗？**
不要。只用 Python 标准库，不联网、不上传、不需要 API key、不需要账号。你填的四个数字在你自己的机器上算完就结束了。

**Q：36 项都要核一遍吗？**
不必。先跑脚本拿到 Top 10，只核这 10 项——这是分数最高、处罚案例命中最多的部分。时间紧就按这个顺序。

**Q：地方监管比全国口径更严怎么办？**
以地方为准。本工具给的是全国通用基线，地方细则（东莞、山西、新疆、江苏等）可能更严，需要另行叠加。本工具已采集 5 份地方文件，其余未覆盖。

**Q：台账填完了能给外部看吗？**
可以，这是你自己的自查记录。但注意：单次购买、单人授权使用，不可转售或再分发。

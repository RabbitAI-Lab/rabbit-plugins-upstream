# 明日dmp批量打通圈包

## 能做什么

- 批量创建 **打通人群任务**（人群类型 audienceType=5），创建接口对应 OPEN API：`/api/open-api/audience/idlink/create`。
- **项目化批量创建 + 状态追踪**：支持分批策略（每批最多5个任务、同批串行创建、批间等待本批全部计算完成后再进入下一批），并在结束时输出完整汇总（人群名称 + 人群ID）。
- 支持两种输入方式：
  1. **表格导入（推荐）**：上传 Excel/CSV，一行一条打通任务（可填人群ID或人群名称，系统自动匹配）。
  2. **对话输入**：用户在对话框中一次性输入完整参数（单条或多条 JSON，均为中文字段）。人群可通过ID或名称指定。如参数不完整会提示补全。

> 说明：**被打通的人群名称无需用户提供**，将通过"人群列表查询接口"按人群ID自动查询，用于自动生成默认新名称。但用户必须在参数确认环节明确确认新名称（可采纳默认命名或自定义）。

## 🔴 人群状态定义（audienceStatus）

> **关键：只有 audienceStatus=1 才表示创建成功，其他状态均不可视为成功。**

| audienceStatus | 含义 | 说明 |
|---------------|------|------|
| **0** | ❌ 失败 | 人群创建/计算失败，不可使用 |
| **1** | ✅ 成功 | 人群创建并计算完成，可正常使用 |
| **2** | ⏳ 等待中 | 已提交，排队等待计算 |
| **3** | 🔄 计算中 | 正在计算，尚未完成 |

⚠️ **判定规则：**
- 在轮询监控和结果汇总时，**仅当 `audienceStatus=1` 时才判定为成功**
- `audienceStatus=2` 或 `3` 时需继续等待，不可跳过或判定为成功
- `audienceStatus=0` 时判定为失败，按失败处理策略执行
- **禁止将 2、3 状态误判为成功**

### 第六步C：失败处理策略确认（强制）

在批量执行过程中，可能出现两类失败：
- **创建失败**：调用创建接口失败（未拿到 audienceId）
- **计算失败**：创建成功但计算状态为失败（**audienceStatus=0**）

> 🔴 **再次强调：audienceStatus 仅在值为 1 时才算成功。0=失败、2=等待中、3=计算中，均不可视为成功。**

请提前确认处理策略（与批量圈包保持一致）：

- 【创建失败时】
  - a) 暂停等待（pause）：停止后续任务，等待“重试/跳过/取消”指令
  - b) 自动跳过（skip）：记录失败并继续创建下一条

- 【计算失败时】
  - a) 暂停等待（pause）：停止进入下一批，等待“重试/跳过/取消”指令
  - b) 自动跳过（skip）：记录失败并继续后续批次

请选择策略组合：
- 输入 `1a+2a`：创建失败暂停 + 计算失败暂停（默认推荐）
- 输入 `1a+2b`：创建失败暂停 + 计算失败跳过
- 输入 `1b+2a`：创建失败跳过 + 计算失败暂停
- 输入 `1b+2b`：创建失败跳过 + 计算失败跳过

执行脚本会按策略运行（对应参数：`--on-create-fail pause|skip`、`--on-exec-fail pause|skip`）。

### 第六步D：监控方案（强制使用cron，禁止后台exec轮询）

🔴 **三种方式的强制约束：**

| 方式 | 是否允许 | 原因 |
|------|---------|------|
| ✅ `cron(action="add", job={...})` 工具 | **必须使用** | 绑定当前session，每60秒自动触发agent turn，完成后可自动通知用户和推进下一批 |
| ❌ `openclaw cron add` 命令行 | **严格禁止** | 无法设置sessionTarget=current，会绑定到isolated session导致监控无法触发 |
| ❌ `exec(background=true)` + `sleep` + 手动轮询 | **严格禁止** | 后台进程在session休眠/断连后不会唤醒AI，导致任务完成后无法通知用户（已发生过此故障） |

**监控规则与禁用项：** 阅读 `references/监控规则与禁用项.md`

**cron监控任务创建规范（必须在第一批任务创建成功后立即执行）：**

```python
cron(action="add", job={
    "name": f"DMP打通监控-{project_id}",
    "schedule": {"kind": "every", "everyMs": 60000},
    "payload": {
        "kind": "agentTurn",
        "message": f"检查DMP批量打通项目{project_id}状态：运行 python3 scripts/run_idlink_project.py --mode monitor --project-id {project_id} 推进批次；若本批完成则创建下一批；全部完成则汇报结果并删除此cron任务。"
    },
    "sessionTarget": "current",
    "delivery": {"mode": "none"}
})
```

**cron任务触发时的执行流程：**
1. 运行 `python3 scripts/run_idlink_project.py --mode monitor --project-id <id>` 检查当前批状态
2. 若本批全部计算完成 → 自动创建下一批任务
3. 若所有批次完成 → 输出汇总结果，主动通知用户，并调用 `cron(action="remove", ...)` 删除监控任务
4. 若有失败 → 按第六步C确认的失败策略处理（pause则通知用户等待指令，skip则记录后继续）

**🔴 自我检查清单（每次创建第一批任务后必须逐项确认）：**
- [ ] 我是否使用了 `cron` 工具（不是exec background，不是命令行）？
- [ ] sessionTarget 是否设置为 `"current"`？
- [ ] delivery 是否设置为 `{"mode": "none"}`？
- [ ] payload.message 是否包含了项目ID、monitor命令、完成后删除cron的指令？
- [ ] 创建cron后是否向用户确认了监控已启动？

#### 汇总内容要求（每条人群都必须包含）
- **人群名称**：打通后的新名称
- **人群ID**：创建返回的 audienceId
- **人群量级**：打通后人群包的设备数量（从查询接口获取）
- **打通方向**：移动端→OTT端 / OTT端→移动端

## Scripts

- `scripts/run_idlink_project.py`：批量打通项目统一执行入口（读取输入→校验→分批创建→批间轮询→汇总落盘）
- `scripts/preflight_check.py`：前置校验（鉴权能力/凭证/上一步任务状态等硬拦截）
- `scripts/cron_helper.py`：🔴 **cron监控硬约束工具（代码级拦截）**
  - `check`：monitor模式/推进下一批前检查锁文件，未设置cron则拒绝执行（exit 1/2）
  - `mark-cron-set --cron-name <名字>`：AI创建cron任务后必须调用此命令写入锁文件
  - `cleanup`：全部完成后清理锁文件，提示AI删除cron任务
  - `gen-cron-params`：生成标准cron任务参数
- `scripts/check_task_logger.py`：任务记录能力检查提示
- 其他辅助脚本：鉴权查找、任务状态轮询等

### 🔴 cron硬拦截工作机制（代码级保证）

```
init创建第一批成功
      ↓
脚本输出cron_params + mark-cron-set指令 + exit 0
      ↓
🔴 AI必须执行：
  1. cron(action="add", job=cron_params)  ← 创建cron
  2. python3 scripts/cron_helper.py mark-cron-set  ← 写入锁文件
      ↓
cron每分钟触发 → monitor模式
      ↓
monitor入口 check_cron_setup()
  ├─ 锁文件存在 → 正常推进
  └─ 锁文件不存在 → exit 2，输出拦截提示
      ↓
全部批次完成
      ↓
cron_helper cleanup → 提示AI删除cron任务
```

这意味着：即使AI忽略提示词、忘记创建cron、或session断连，**monitor模式也会拒绝执行**，从而强制AI必须先创建cron才能推进。

## 执行结束的汇总输出（强制）

无论创建是否全部成功，批量任务执行结束后都会输出汇总表（并同时写入项目 result.json）。

> 🔴 **成功判定标准：仅 audienceStatus=1 判定为成功。audienceStatus=0（失败）、2（等待中）、3（计算中）均不计入成功。**

- 成功（audienceStatus=1）：`人群名称 + 人群ID`
- 失败（audienceStatus=0）：`人群名称 + 失败原因`
- 未完成（audienceStatus=2或3）：`人群名称 + 当前状态（等待中/计算中）+ 说明`

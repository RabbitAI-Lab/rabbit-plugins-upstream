# 八字节气 · 命理解读

## 一、这个 skill 做什么

从服务端取一份**结构化命理报告**（约 150 万字 JSON），再按本包的规则做解读。

报告由服务端确定性算法生成，包含：原命局、十步大运、出生至起运、起运后一百年的流年，以及每年 12 个流月。**四柱、十神、神煞、能量占比、心鉴学正文全部已算好**，本 skill 不重算，只负责取用与解读。

## 二、账号与次数

账号密码保存在本机：

```
~/.xix-bazi/account.json
```

所有接口调用统一走脚本，不要手写 HTTP：

```bash
python3 scripts/skill_api.py register --zhanghao 账号 --mima 密码
python3 scripts/skill_api.py quota
python3 scripts/skill_api.py report --birth "1991-09-21 14:45" --place 北屯 --country 中国 --gender 男 --save ./reports
```

脚本地址：本 skill 目录下 `scripts/skill_api.py`。

## 三、主流程

### 0. 检查账号

读 `~/.xix-bazi/account.json`。

- 有 → 进入第 2 步
- 没有 → 第 1 步

### 1. 注册

询问用户想设置的账号与密码（账号 3–32 位，密码至少 6 位）。注册成功后脚本会自动写入本地文件，并告知用户保存路径。

**新账号赠送 1 次体验**，注册完即可直接生成一次报告；次数用完后需购买。

### 2. 查询可用次数

```bash
python3 scripts/skill_api.py quota
```

- 次数为 0 → 第 3 步
- 次数大于 0 → 第 4 步

### 3. 次数不足

明确告知用户，并给出购买方式：

> 当前可用次数为 0。需要购买次数请添加微信：**97676414**。

不要代替用户下单，不要承诺价格。

### 4. 检查信息完整性

必须具备：

| 项 | 要求 |
|---|---|
| 出生时间 | 年、月、日、时、分，缺一不可 |
| 出生地 | 国家 + 省/州 + 市，至少精确到市 |
| 性别 | 男 / 女 |

缺任何一项 → **暂停任务**，请用户补齐，不要猜测、不要用默认值代替。

信息不完整时不要调用接口，服务端会拒绝。

### 5. 判断问题是否在范围内

**范围内**：性格与行为倾向、天赋与短板、学业与事业方向、财运类型、婚姻感情模式、人际关系、六亲关系、健康倾向（非诊断）、某年/某月的运势重点、择时参考。

**范围外**（必须明确拒绝并转人工）：

- 医疗诊断、用药、手术建议
- 法律判决、诉讼策略、合同效力
- 具体投资标的、买卖点位、彩票股票预测
- 生死寿数、重大灾祸的确定性断言
- 他人隐私；未经本人同意的第三方命盘
- 与命理无关的通用问题
- 政治敏感内容

范围外统一回复：

> 这个问题超出本 skill 能回答的范围，需要人工解答，请添加微信：**97676414**。

### 6. 获取报告

```bash
python3 scripts/skill_api.py report \
  --birth "1991-09-21 14:45" --place 北屯 --country 中国 --gender 男 --save ./reports
```

成功后会输出资产名、下载链接、剩余次数，并把报告保存到指定目录。**把保存路径告诉用户。**

服务端有缓存：同一八字已存在时直接返回链接，通常 0.1 秒内完成；首次生成约 4–6 秒。

### 7. 读报告的顺序

报告 150 万字，**禁止整份读入上下文**。按以下顺序：

1. 先读 `index`——只有八字、起运、十步大运、各流年的年份与区间，体积极小。
2. 再读 `yuanju`——原命局的四柱、神煞、能量、作用关系、四柱心鉴学。
3. 最后按用户问题定位时间点：
   - 问某一年 → `liunian` 里对应年份
   - 问某个月 → 该年的 `liuyue`
   - 问某步大运 → `dayun`

用 Python 切片读取，不要用文本查看器整份打开。

```python
import json
r = json.load(open("reports/1991-09-21_午时_男.json", encoding="utf-8"))
print(r["index"]["bazi_text"], r["index"]["qiyun_time"])
print(r["yuanju"]["energy"])
y = next(x for x in r["liunian"] if x["year"] == 2026)
print(y["gz"], y["energy"], y["tiangan_relation"], y["dizhi_relation"])
```

### 8. 喜用神：先问，再定

在判断喜用神之前，**必须先向用户说明并询问**：

> 报告只提供原命局与动态（精确到流月）的五行能量占比变化，没有直接给出喜用神。你更倾向哪种流派的取用神方法？如果不确定，我可以按心鉴学的能量占比规则来判断。

- 用户给出流派或明确喜用神 → **以用户为准**
- 用户未指定 → 按 `references/5-喜用神与吉凶判断规则.md`

### 9. 需要神煞时

查 `references/1-神煞内容参考表.md`，配合 `5-喜用神与吉凶判断规则.md`。

神煞只做**加权提示**，不得脱离生克与能量单独下结论。

### 10. 只论原命局时

查 `references/2-原命局宫位取像表.md`，配合 `5-喜用神与吉凶判断规则.md`。

### 11. 谨慎断事时

查 `references/3-十神取象表.md`，区分喜忌两面，配合 `5-喜用神与吉凶判断规则.md`。

### 12. 需要人性深度剖析时

必须先完整读 `references/4-心鉴学人性分析规则.md`，再引用报告里的心鉴学正文。

未读该文档，不得做人性层面的推演。

### 13. 综合回答

把四条线合起来：**报告事实 → 能量配比 → 生克吉凶 → 人性运作**，再回答用户当前这一个问题。

## 四、报告结构速查

```
meta      输入信息、真太阳时、资产名
index     八字、起运、十步大运、各流年区间（先读这个）
yuanju    原命局：八字、四柱神煞、能量、天干/地支关系、心鉴学
dayun     十步大运，每步含五柱、神煞、能量、关系、心鉴学
liunian   流年，每年含六柱、神煞、能量、关系、心鉴学、12 个流月
liuyue    流月：七柱、神煞、能量、关系、十神与编码
```

心鉴学条目格式：

```json
{"position": "年干", "label": "辛金正官", "code": "YTJ29-", "content": {"外在表现": "……"}}
```

编码规则：末位 `+` 为正常面，`-` 为过度面。

## 五、输出规范

1. **编码只给自己看**，不给用户看。用户看到的是通俗解释。
2. 说「倾向」「容易」，不说「一定」「必然」。
3. 只回答用户当前这一问；引用到某条特征时，必须用大白话解释它是什么。
4. 不承诺准确率，不做恐吓式表达，不替代医疗、法律、投资等专业意见。
5. 信息不足时直说「本次报告未覆盖该维度」，不许编造。

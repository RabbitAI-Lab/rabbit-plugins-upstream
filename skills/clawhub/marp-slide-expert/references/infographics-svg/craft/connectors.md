# 连线层 — 线型即语义

> **本文件自足**：线不是装饰。每一条线都应该能让人不查图例就读出语义。

## 1. 语义编码表

| 关系 | SVG 画法 | 读作 |
|---|---|---|
| `causes` / `drives` 因果驱动 | `stroke-width="2.5"` 实线 + 粗箭头 | 导致、驱动 |
| `supports` 支撑 | `stroke-width="2"` 实线 + 细箭头 | 支撑、贡献 |
| `depends_on` 依赖 | `stroke-dasharray="6 5"` 虚线箭头 | 依赖、条件成立才成立 |
| `feedback` 反馈 | 虚线 + `marker-start` **和** `marker-end` 双向 | 反馈、闭环 |
| `maps_to` 映射 | 细实线**不带箭头**（`stroke-width="1.5"`） | 对应、一对一 |
| 层级连接 | `stroke="#b9c3cc"` 浅灰直角折线，**不带箭头** | 从属——方向已由上下位置表达 |
| 数量流 | 曲边 ribbon（见 §4） | 带量级的流动 |

**同一张图里，线型的含义必须一致。** 虚线在 A 段表示反馈、在 B 段表示依赖，读者会直接误读。

## 2. 箭头 marker

```html
<defs>
  <marker id="a1" markerUnits="userSpaceOnUse" markerWidth="13" markerHeight="10" refX="12" refY="5" orient="auto">
    <path d="M0,0 L13,5 L0,10 z" fill="#c0392b"/>
  </marker>
</defs>
```

- **`markerUnits="userSpaceOnUse"` 必须显式写。** 它默认是 `"strokeWidth"`，marker 会按线的粗细整体缩放——`stroke-width="7"` 的线配默认 marker，箭头被放大 7 倍，变成一个比节点还大的三角。这个坑很隐蔽：线越粗箭头越大，看起来「像是有意的」，其实完全失控。
- **`id` 必须带图表前缀**（`a1` / `a2` / `a3`…）。这是每张图唯一、不能重复的标识，见 [marp-compat.md](marp-compat.md) §2。
- **`orient="auto"` 不能省**——箭头会跟着线的方向转，少了它所有箭头都朝右。
- **`fill` 要和线同色**，否则会出现灰线配红箭头这种不协调的接缝。
- 常用 `markerWidth/markerHeight` = `13/10`；强调路径用 `17/12`。
- **线宽递增的弧段要用不同尺寸的 marker。** 一个 marker 管不了递增的线宽——递增弧要写 3–4 个，见 [../metaphors.md](../metaphors.md) 飞轮。

## 3. 几何公式

### 直角折线（层级连接的标准画法）

父节点底边 → 垂直下探 → 水平横移 → 垂直进入子节点顶边：

```
M 父cx,父底 V 中继y H 子cx V 子顶
```

```html
<path d="M525,74 V108 H255 V146" fill="none" stroke="#b9c3cc" stroke-width="2"/>
```

**一行一个子节点，共享父节点的中继 y**。中继 y 取父底 + 34（够放下箭头，又不至于离父太远）。多个子节点时用同一中继线画一段横线，比画三条独立折线干净。

### 曲线（收敛 / 发散）

多条 `<path>` 用二次贝塞尔汇到一点或从一点发散：

```
M 起点x,起点y Q 控制点x,控制点y 终点x,终点y
```

控制点放在起点和终点**连线的垂直平分线上**，曲度才对称。发散时把控制点往外推 `80–120px`。

### 闭环虚线（叠加件）

任何图下面加这一条，「一次性流程」就变成「持续演进」——这是这类图最容易被忽略、但最值钱的一笔：

```html
<line x1="255" y1="392" x2="780" y2="392" stroke="#c0392b" stroke-width="2"
      stroke-dasharray="6 5" marker-end="url(#a1)"/>
<text x="510" y="422" class="lbl" text-anchor="middle">闭环：反馈 → 迭代 → 新价值</text>
```

放在图**底部**、y ≈ 392–422，视觉上从属于主图，不抢主体。

## 4. Ribbon（带量级的流）

桑基图用 ribbon 而不是线——**宽度本身就是数据**：

```html
<path d="M0,0 C40,0 60,30 100,30 L100,80 C60,80 40,50 0,50 Z"
      fill="#4EBDBA" opacity="0.45"/>
```

一个 ribbon 是一个闭合 path，两条同向曲线加两端封口。规则：

- 宽度严格正比于数值——这是桑基的定义，不是修饰
- `opacity="0.45"` 让重叠的带仍然可辨
- 颜色跟随源节点，跨阶段追踪同一股流
- **守恒律**：所有目标值之和必须精确等于源总量。写完逐个核对算术。图像模型画错了你不知道，SVG 里数字是你写的，错了就是错了

## 5. 交叉控制

连线交叉是最伤可读性的因素。处理顺序：

1. **重排节点**——大多数交叉可以靠调换左右/上下顺序消掉
2. **加中继点**——实在绕不开时，走 `V` `H` `V` 折线而不是斜穿
3. **接受少量交叉**——复杂图有 2–3 处交叉是正常的，强行规避会让图更乱

**连线不要穿过节点。** 层级树里子节点的连线应该走在节点之间的空隙，必要时先横移到子节点的 cx 再垂直下去。

## 6. 颜色纪律

- **连线颜色跟随语义，不跟随节点。** 强调路径用强调色，常规连接用中性灰。
- **不要用颜色代替语义。** 灰度投影、色弱、单色打印都会丢掉颜色信息。颜色只用来做分类 / 强调 / 风险 / 优先级。
- 层级折线用浅灰 `#b9c3cc`——它在视觉上要退到背景里，因为方向已经由位置说清楚了。

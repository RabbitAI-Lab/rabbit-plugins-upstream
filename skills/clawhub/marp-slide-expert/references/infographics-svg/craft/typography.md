# 文字层 — 字阶、CJK 排版与溢出控制

> **本文件自足**：SVG 里的文字不会自动换行，中文又比英文宽——这一层的中文信息图，80% 的排版事故出在这里。

## 1. 字阶 class

字号只走 class，**永远不写 `font-size` 属性**。deck frontmatter 的 `style:` 块已经定义好，改一处全篇图形同步缩放。

```css
svg        { display: block; margin: 0 auto; max-width: 100%; height: auto; }
svg text   { font-family: 'PingFang SC', 'Microsoft YaHei', 'Noto Sans CJK SC', sans-serif; }
svg .t     { font-size: 26px; font-weight: 700; }   /* 图形主标题 */
svg .tb    { font-size: 19px; font-weight: 700; }   /* 节点 / 序号 */
svg .qt    { font-size: 20px; font-weight: 700; }   /* 象限标题 */
svg .sm    { font-size: 15px; }                     /* 副标签 */
svg .lbl   { font-size: 15px; fill: #7f8c8d; }     /* 底部浅灰注脚 */
```

| class | 用于 | 底线 |
|---|---|---|
| `.t` | 图形主标题、核心结论数字 | — |
| `.tb` | 节点标签、步骤序号 | — |
| `.qt` | 象限标题、分区标题 | — |
| `.sm` | 副标签、辅助说明 | **下限 15px**，不得再小 |
| `.lbl` | 底部注脚、图例文字 | 灰色，不抢主体 |

**15px 是硬底线。** 低于 14px 在投影上基本看不清——宁可缩短文案也不要缩字号。

## 2. 中文字宽估算

排版前先估算，否则标签会溢出节点框。

```
文本宽度 ≈ CJK 字数 × 1.0 × font-size
         + Latin 字数 × 0.5 × font-size
```

| 字号 | 2 字 | 4 字 | 6 字 | 8 字 |
|---|---|---|---|---|
| 26px (`.t`) | 52 | 104 | 156 | 208 |
| 19px (`.tb`) | 38 | 76 | 114 | 152 |
| 15px (`.sm`) | 30 | 60 | 90 | 120 |

**节点宽度必须 ≥ 标签宽度 + 左右各 12px padding。** 例如 4 字中文标签用 `.tb`（76px），节点至少 100px 宽；6 字则至少 140px。

**单个节点的标签控制在 2–6 个中文字**。超过就该换行或换结构——7 个字挤在一个方块里，投影上根本读不清，而且逼着你把节点画得又大又扁，破坏网格。

## 3. `<text>` 不换行

SVG 的 `<text>` **没有自动换行**。文字超出容器就是直接画到框外，不会折行、不会省略、不会报警。

三种处理方式，按优先级：

### a) 缩短文案（首选）

中文图上最有效的一招。`建立跨部门数据共享机制` → `数据共享`。信息密度降一点，可读性提一档。

### b) 手动断行 —— `<tspan>`

```html
<text x="108" y="120" class="sm" text-anchor="middle">
  <tspan x="108" dy="0">第一行文案</tspan>
  <tspan x="108" dy="22">第二行文案</tspan>
</text>
```

- 每个 `<tspan>` **都要重写 `x`**，否则它会接着上一行末尾继续排
- 用 `dy` 控制行距（`20–24` 适合 `.sm`，`26–30` 适合 `.tb`）
- 行数上限 3 行。超过就该换结构而不是继续加行

### c) 换结构

文字实在太多，说明这个骨架选错了。比如 8 个 6 字标签不是「二栏文字版式」能承载的，换成便当格或表格式骨架。

## 4. 中文基线偏下

中文字符的视觉重心比拉丁字母**偏下约 0.05–0.08em**。纯拉丁文本按数学中点算出来的 `y`，换成中文会显得偏上。

所以块内垂直居中的经验值要比纯拉丁再往下调一点：

```
y = 块顶 + 块高/2 + 字号 × 0.40     （中文）
y = 块顶 + 块高/2 + 字号 × 0.35     （纯拉丁）
```

## 5. 常见排版事故

| 现象 | 原因 | 修法 |
|---|---|---|
| 文字溢出方块 | 没估字宽 | 按 §2 重算节点宽度，或按 §3 断行 |
| 多行文字行首没对齐 | `<tspan>` 漏了 `x` | 每个 tspan 重写 `x` |
| 中文看着比英文偏上 | 基线没按中文调整 | 加 0.05em 下移 |
| 标题和节点挤在一起 | 标题 `y` 太靠下 | 主标题 `y ≈ 30`，节点区从 `y ≥ 70` 起 |
| 白字压在浅色块上看不见 | 底色和文字色对比不足 | 换深底色，或文字改用深色写在浅块上 |
| 改字号后全图没同步 | 写了 `font-size` 属性 | 只用 class |
| 中英混排基线不齐 | 拉丁与 CJK 混在一个 `<text>` | 分开两个 `<text>`，或加 `dominant-baseline` 微调 |

## 6. 混合语言标签

一张图里中英混排很常见（`AI Agent 智能体`）。两种处理：

- **同一条 `<text>` 内混排**——最省事，但基线可能不齐。可接受，前提是标签很短。
- **拆成两行**——`<tspan>` 第一行中文 `.tb`、第二行英文 `.sm` 灰色。信息层次更清楚，**推荐用于节点标签**。

**一条原则**：图上的**标题和节点标签用中文**（受众要看的东西），**次要注释可以留英文**（术语、缩写、图表标准名）。不要中英各写一遍完整内容——那是把每条标签的信息量翻倍，挤爆版面。

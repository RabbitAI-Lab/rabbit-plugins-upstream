# 画布层 — 坐标系、间距尺度、节点预算

> **本文件自足**：画任何一张图之前，先定画布和尺度，再放元素。坐标系不统一是图形「看起来歪」的头号原因。

## 1. 画布坐标系

Marp 幻灯片是 **1280×720**，正文区约 **1140px 宽**（左右各 70px padding），可用高度约 **500px**。

| 约定 | 值 | 说明 |
|---|---|---|
| viewBox 宽度 | `1020` | 缩放到 1140px，比例 ≈ 1.12。SVG 里 `font-size: 22` 的文字实际显示约 25px |
| viewBox 高度 | `300`–`540` | 按复杂度定；**高度决定图形占多高**，简单图别硬撑高 |
| 图形宽度 | `width="100%"` | 配合 `max-width: 100%` 自适应，不要写死像素 |
| 左右边距 | `20`–`40` | 元素不要贴到 x=0 |
| 底部安全线 | `y ≤ 500` | 超过就侵入 footer 区（footer 绝对定位在 `bottom: 25px`） |

```html
<svg viewBox="0 0 1020 460" width="100%">
```

**高度怎么选**：单行序列 `300`；一层树或一张矩阵 `460`；带泳道或双层结构 `520`。宁可矮一点——图形占满整页时，正文标题会被挤到很小的相对尺寸。

**贴底怎么办**：底部要放 X 轴标题、图例、注脚时，viewBox 高度可以超过 500，但那一页必须加 `<!-- _class: diagram -->` 隐藏 footer（CSS 已在 `style-bootstrap` 里）。

## 2. 间距尺度

间距不是随手填的数字。用这张表，图与图之间才会一致：

| 尺度 | 用途 | 场景 |
|---|---|---|
| `8` | 序列元素之间的缝隙 | 箭头串 tip 与下一个箭头的间距（步距 204 − 宽度 196 = 8，缝隙是必须的） |
| `10`–`12` | 同组兄弟节点 | 关系树同父的叶子之间 |
| `20` | 元素与容器边、组与组 | 矩阵单元格间距、便当格 padding |
| `24` | 分栏间隔 | 页级版式的栏间 gap |
| `32` | 区域与区域 | 上下分区、图形内部的功能分区隔 |

**格式塔原则**：分组之间的间距 **>** 组内元素间距。组内 10px、组间 20px，读者才能看出「这几个是一伙的」。所有格子等距 = 没有分组。

## 3. 线宽尺度

| 线宽 | 语义 |
|---|---|
| `1` | 网格线、辅助参考线（浅灰，通常是虚线） |
| `1.5` | 弱连接、非主关系、映射线（无箭头） |
| `2` | 常规连接、层级折线 |
| `2.5` | 主因果、强调路径、需要抢注意力的线 |

线宽是**层级**信号：同一张图里所有连接线一样粗 = 没有重点，等于什么都没说。

## 4. 节点预算

**单图核心元素 ≤ 7**（Miller's Law）。超了按顺序处理：

1. 拆成多张图
2. 聚合同类元素（5 个并列的同类 → 1 个容器 + 计数）
3. 降级成表格

**树的层级 ≤ 3。** 第 4 层开始听众的线索就断了——他们记不住 3 层以上的从属关系。

**一页一个 Pattern。** 不要把诊断（问题树）、战略（金字塔）、转型（前后对比）混在一张图里。叙事隐喻也是一次只用一层（见 [../metaphors.md](../metaphors.md)）。

## 5. 视觉层级：importance 驱动

不要所有节点一样大——那是没有重点，等于没有咨询味。按重要性分三档：

```text
importance 1.0  →  class="t"   最深色 + 最大节点     核心结论
importance 0.7  →  class="tb"  中间色 + 中号节点     一级信息
importance 0.4  →  class="sm"  浅色 + 描边 + 小字号   支撑细节
```

**颜色铁律：一色族 + 一个强调色。** 阶梯图 5 级可以走完灰 → 藏青 → 红这一个色相，强调色只给终点或关键节点。**超过三个色相投影上一片脏。** 完整配色的 token 定义在 [../../style-bootstrap.md](../../style-bootstrap.md)。

## 6. 文字定位

SVG 的 `<text>` 用的是**基线坐标**，不是顶边坐标。这是最容易算错的一处：

```html
<rect x="20" y="330" width="176" height="90"/>
<text x="108" y="382" class="tb" text-anchor="middle">L1</text>
```

规则：

- **块内垂直居中**：`y = 块顶 + 块高/2 + 字号×0.35`（0.35 是视觉中线的经验修正，不是数学中点）
- **块高不等时不要按整块居中**——阶梯图每级高度不同，居中会飘。改成**相对块底往上定位**：`y = 块底 − 24`（主标签）、`y = 块底 − 46`（副标签）
- **居中文字必须写 `text-anchor="middle"`**，并把 `x` 设成图形中心（如 `x = 块左 + 块宽/2`）
- **旋转文字**：`transform="rotate(-90,x,y)"` 的 rotate 中心必须和文本的 `x,y` **完全一致**，否则会飞出画布
- **气泡/圆点旁的标签**放在 `cx + r + 9`，不要压在圆上

## 7. 留白与数据墨水比

Tufte 的数据墨水比：**让尽可能多的墨水用于呈现数据信息。**

- 删掉不承载信息的装饰——3D 效果、投影、纯装饰边框、无意义的渐变
- 网格线、刻度线能省就省，只在读数必需时保留（浅灰虚线）
- 留白不是浪费空间，是帮读者呼吸和定位：组内间距 < 组间间距，边缘留出边距
- **不靠颜色传义**。灰度投影、色弱、单色打印都会丢掉颜色信息。颜色只用来做分类 / 强调 / 风险 / 优先级；**关系语义由线型编码**（见 [connectors.md](connectors.md)）

## 8. 可访问性底线

| 项 | 底线 |
|---|---|
| 字号 | 最小 `.sm` = 15px。低于 14px 投影上基本看不清——**宁可缩短文案也不要缩字号** |
| 对比度 | 文字与底色对比度足够（WCAG AA） |
| 色盲友好 | 不要只靠红/绿区分。用蓝/橙，或叠加形状、图案、标签 |
| 分类不靠颜色独占 | 同一类元素除了同色，还要有第二重标识（形状、描边样式、标签位置） |

「不靠颜色传义」在这套体系里是双重保障：**连线语义用线型编码**（虚线/实线/无箭头），**分类语义用形状 + 位置**，颜色只是第三重冗余。灰度打印出来关系依然可读。

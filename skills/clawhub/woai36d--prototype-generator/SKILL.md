# 产品原型生成器 (Prototype Generator)

## 核心流程

```
输入资产 → 需求提取 → 竞品分析 → 原型生成 → 验证检查 → 输出定稿
```

### Step 1: 读取输入资产

**必需输入**：
- `prd_path`: PRD 文档路径（Markdown 格式）
- `screenshot_dir`: 竞品截图目录路径（含子目录）

**可选输入**：
- `api_doc_path`: 开放平台接口文档路径
- `output_path`: 原型输出路径（默认：`{prd_dir}/产品原型-{模块名}.md`）
- `prototype_tool`: 原型工具配置（如 Stitch/Figma/Axure 等，默认输出 Markdown 原型）

### Step 2: 提取 PRD 功能需求

读取 PRD 文档，提取以下信息：

| 提取项 | 说明 |
|--------|------|
| 模块范围 | 子模块列表及说明 |
| 核心页面 | 列出的所有页面（列表页、详情页、表单页等） |
| 业务流程 | 新增/编辑/删除/查询的完整流程 |
| 数据模型 | 关键实体和字段 |
| 权限设计 | 角色、菜单、数据权限规则 |
| 异常状态 | 错误提示、空状态、加载状态、无权限状态 |
| 交互规则 | 筛选、排序、分页、批量操作等 |

### Step 3: 分析竞品截图

扫描 `screenshot_dir` 目录，对所有图片进行 vision 分析：

1. **分类整理**：按目录结构分类（如"账号与门店管理"、"品牌管理"）
2. **识别页面类型**：列表页/表单页/弹窗/详情页/树形结构等
3. **提取交互元素**：
   - 按钮、Tab、筛选栏、搜索框
   - 表格列定义、操作列菜单
   - 表单字段、验证规则提示
   - 弹窗/抽屉尺寸和布局
4. **记录设计规范**：
   - 颜色体系（主色、状态色）
   - 布局结构（侧边栏宽度、表格行高）
   - 组件模式（弹窗 vs 抽屉、步骤向导 vs 单页）

### Step 4: 生成原型设计

基于 PRD 需求 + 竞品交互参考，生成完整原型文档：

**文档结构**：
```markdown
# {模块名} — 产品原型设计

> 基于：{PRD文档名}
> 版本：V1.0
> 生成时间：{datetime}

## 1. 页面清单
| 页面 | 类型 | 来源（PRD/竞品） | 优先级 |

## 2. 全局规范
### 2.1 布局框架
### 2.2 导航结构
### 2.3 组件规范
### 2.4 状态规范（空/加载/错误）

## 3. 核心页面原型
### 3.1 {页面名}（列表页/表单页/详情页）
- 页面布局（ASCII/文字描述）
- 字段定义
- 交互说明
- 异常状态

## 4. 业务流程
### 4.1 {流程名}
- 正常流程（步骤+页面跳转）
- 异常分支
- 边界情况

## 5. 数据与接口对照
### 5.1 页面-接口映射
### 5.2 关键字段对照

## 6. 验证清单
```

**原型输出方式**（按配置）：
- **默认**：Markdown 文本原型（ASCII 布局 + 详细说明）
- **Stitch/Figma**：如配置了在线原型工具账号，生成导入格式或直接调用 API 创建

### Step 5: 验证原型完整性

运行验证检查，确保：

1. **需求覆盖率**：PRD 中的每个功能点都有对应页面或流程
2. **页面完整性**：每个页面包含布局、字段、交互、异常状态
3. **流程闭环**：业务流程有明确的开始、结束和异常分支
4. **竞品差异**：标注大师傅 vs 竞品的差异点（差异化设计）
5. **接口对齐**：如有接口文档，检查页面字段与接口字段一致

**验证失败项**：记录为 `待确认清单`，附在原型文档末尾。

### Step 6: 输出定稿

将最终原型文档写入 `output_path`，并输出摘要：

```
原型生成完成 ✅
- 页面数：{n}
- 流程数：{n}
- 验证通过：{n}/{total}
- 待确认：{n} 项（见文档末尾）
- 输出路径：{path}
```

## 差异化设计原则

生成原型时，优先采用以下大师傅设计规范（而非完全照搬竞品）：

| 场景 | 企迈方式 | 大师傅推荐 |
|------|---------|-----------|
| 添加员工 | 2步弹窗 | 右侧抽屉（空间更大，不遮挡列表） |
| 添加门店 | 4步弹窗 | 4步全屏向导（表单更充裕） |
| 组织树 | 仅查看 | 拖拽编辑 + 未挂入门店区 |
| 角色权限 | 平铺复选 | 树形勾选 + 操作权限独立配置 |
| 门店详情 | 4Tab | 5Tab（增加变更记录） |
| 批量操作 | 部分支持 | 全面支持 + 执行前预览确认 |

## 工具配置

### 原型输出工具（prototype_tool）

在 `references/tool-config.md` 中配置具体工具的连接信息：

```yaml
# 默认输出 Markdown 文本原型
default: markdown

# Google Stitch 配置（如用户已登录）
stitch:
  enabled: false  # 设置为 true 启用
  # 账号信息由用户提供，不硬编码
  
# Figma 配置
figma:
  enabled: false
  # 需配置 Personal Access Token
```

**注意**：本 Skill 默认输出 Markdown 格式原型。如需接入在线原型工具，用户需提供账号凭证，Skill 将调用对应 API 创建项目。

## 执行模式

### 全自动模式
用户仅提供路径，Skill 自动完成全部流程：
```
输入：PRD路径 + 截图目录 → 输出：原型文档
```

### 交互模式
用户逐步确认：
1. Skill 展示提取的需求清单 → 用户确认/补充
2. Skill 展示竞品分析摘要 → 用户确认
3. Skill 生成页面原型 → 用户逐个确认
4. Skill 运行验证 → 输出待确认清单

**默认采用全自动模式**，生成完整版本后一次性交付用户验证。

## 边界说明

1. **接口文档缺失**：如未提供，原型中"数据与接口对照"章节标记为"待后续补充"
2. **截图质量不佳**：vision 分析可能遗漏细节，需在验证清单中标注"需人工复核"
3. **复杂交互动画**：Markdown 原型无法表达动效，用文字描述动画逻辑
4. **多平台原型**：默认输出 PC 管理端原型，如需 POS/APP 端，PRD 中需明确标注

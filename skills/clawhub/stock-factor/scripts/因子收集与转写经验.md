# 因子收集与转写经验（stock-factor 技能）

> 本文件是 `SKILL.md` §5（如何收集）/ §6（如何转写）的**扩展参考**：把历次收集、转写、验证中沉淀的实战经验独立成档，便于 AI 在扩充因子时快速查阅、少踩坑。
> 定位提醒：本技能只做「因子清单（字典 + 初筛）」——提供有哪些因子、各自怎么算、初步 IC/IR。**不**做精选有效因子、去冗余、合成与策略挖掘。

## 0. 一句话工作流

```
选来源 → 抓原始表达式(类 Qlib/WorldQuant 记号) → 整理"初始收集"基线文档
→ 分类(技术面/估值/市值/动量/波动/财务/复合)
→ 逐个人手写转写为 QuantAll 代码(out=...)
→ run_task_file / batch_factor_analysis 实跑验证(error_code.names=[])
→ 落盘 xlsx + 入库 task/ (有缺失则留 因子初始参考文件/ 备注)
```

## 1. 收集方法论

### 1.1 来源分级（按"可直接计算性"）

- **低难度、可直接提取**：Qlib Alpha158 / Alpha360（从 Qlib 源码 `loader.py → Alpha158DL.get_feature_config()` 提取，无需运行 Qlib；Alpha360 是"原始特征"非"构造因子"，转写后用于观察历史窗口含多少信号）。
- **中难度**：GTJA 国泰君安 Alpha191（研报公式文本逐个转）、FamaFrench/HXZ、中信/申万风格、会计质量/学术异象。
- **高难度**：WorldQuant Alpha101（大量算子须自写 helper）。
- **低难度标准定义**：技术指标 / 经典量价 / 基本面（整理为 `因子表达式初始收集.md`）。

### 1.2 「WorldQuant 201/212」澄清

WorldQuant **无官方** "Alpha 201 / 212" 论文或公式集。经典公开出处是《101 Formulaic Alphas》(Tulchinsky et al., 2015)，全集已转写收录于 `task/factor-Alpha101.json`（#1–#101）。社区所谓 "201/212" 是对「公式化 alpha 扩展家族（量价算子型，200+ 个）」的统称。本技能已交付：① 算子语义映射表（`因子收集_WorldQuant公式化alpha.md`）；② 手写代表性扩展样本 `因子初始参考文件/factor-WorldQuant_formulaic.json`（与 101 互补不重复）。要真 200+ 全集需另行获取社区扩展公式源。

### 1.3 初始收集基线文档

用**类 Qlib 算子记号**（非 QuantAll 代码）记录表达式，作为转写基线，例：`scripts/因子初始参考文件/因子表达式初始收集.md`。
记号约定（务必统一）：字段 `open/high/low/close/volume/vwap/ret/cap/float_cap/equity/ni/rev/ocf`；算子 `MA/EMA/WMA/STD/HHV/LLV/REF/SUM/ABS/RANK/PCTILE/LOG/COV/CORR`；防除零统一 `+1e-12`。

## 2. 转写硬约束（铁律，违反即报错）

1. **禁止** `import` / `for`/`while` 循环 / `df.apply()` / `lambda` / 递归 / `axis=1` / `df.loc`/`df.iloc`。
2. 各股票停牌时间不对齐，**一律按列方向**（pandas 默认），禁止行方向计算。
3. 代码**最后一行必须** `out = ...`。
4. **复权价手动算**：`ac = d['close'] * d['adj_factor']`。
5. 条件分支用 pandas 向量化（`.where`、布尔索引；`np.where` 仅当结果是 DataFrame 时），别写 if/else 循环。
6. 所有 QuantAll 工具调用**必须串行**。
7. 单因子直接 `out = 原始值`，引擎内部自动截面排名，**不要手动 row_rank**；复合因子各子项先 `row_rank` 再组合。

## 3. 字段映射与高频坑

### 3.1 字段名

- `db_translate.json` 只有**中文显示名**，写代码前用 `available_data` 确认；**不要假设字段名**。
- ⚠️ `db_translate` **无** `净利润`/`营业收入`/`营业利润` 等原值字段，只有比率/同比类。替代写法：
  - 盈利能力 → `总资产净利润率` / `每股收益` / `每股净资产`（ROE = 每股收益 / 每股净资产）。
  - 营收同比 → `每股营业收入` + `shift(252)`（≈1 年交易日；财务数据按日向前填充，故同比用 shift(252)）。
  - 毛利率/成本率/费用率 → `销售毛利率`/`销售成本率`/`销售费用率` 等现成字段。
- `volume` → `d['vol']`（**字段名是 `vol` 不是 `volume`**）。
- VWAP 无字段 → `d['amount']/d['vol'].replace(0, np.nan)`。

### 3.2 量纲 / 每股处理（经典坑）

- 库无「总资产 TA」原值 → 由 `每股净资产 × 总股本 / (1 − 资产负债率)` 推导（资产负债率做 `clip(upper=0.99)` 防除零/越界）。
- **每股类分子需乘 `总股本` 转总值、再除以推导 TA**，否则量纲被股价规模污染（TATA/ACCRUALS 踩过坑）。例：`accruals = (扣非净利润 − 每股经营现金流净额×总股本) / TA`。
- 每股绝对量因子（EPS/BPS/每股资本公积/未分配利润）作横向比较时须 **除以 `d['close']`**（非复权价）消除价格量纲，否则 IR≈0。

### 3.3 复权

- 价格类字段统一 `× adj_factor`（`ac/ao/ah/al`）；成交量/额/VWAP 不参与复权。
- **复权简化规则（正确设计，非 bug）**：若公式不含 shift、仅做同日价格比较（如 `(close-open)/open`），同式各项乘同一常量 `adj_factor` 会相消，可直接用 `d['close']`；但凡含 shift 的比值（如 `ac/ac.shift(N)`）必须复权，否则含义会变。

### 3.4 指数基准

- `get_stock_index(index_code, field='close', out_type='DataFrame')`：取指数行情并拷贝成与 `d['close']` 同结构矩阵。基准常用 `'000001'`（上证综指）；symbol 须 **6 位纯数字**（`000300`/`399001` 亦可用，`000300.SH` 等后缀无效）。
- ⚠️ **指数是否有数据取决于本地库是否加载该指数**（如 `'399300'` 当前无数据则全 NaN，非 key 写错）。
- `out_type='Series'`（旧名 `'serie'`）返回序列，注意与 `rolling_regbeta(Y,X,n)` 的兼容：用默认 DataFrame 形态 `get_stock_index('000001','close')` 再 `.pct_change()` 最稳（'serie' 形态曾与 `rolling_regbeta` 不兼容报错过）。

## 4. 算子映射（源 → QuantAll / pandas）

（详见 SKILL.md §6.5，摘关键易错项）

- `REF/DELAY(x,N)` → `x.shift(N)`；`MA` → `rolling(N).mean()`；`STD/SUM/MAX/MIN` → `rolling(N).std()/.sum()/.max()/.min()`。
- `Rank` 截面 → `row_rank(x)`（0~1 百分位）；时序 → `x.rolling(N).rank(pct=True)`。
- `TS_ARGMAX/TS_ARGMIN(x,N)` → `rolling_imax(x,N)*N` / `rolling_imin(x,N)*N`（"距今日天数"语义）。
- `PROD(x,N)` → `x.rolling(N).apply(np.prod, raw=True)`。
- `Slope/Resi/Rsqr` → `rolling_slope/rolling_resi/rolling_rsquare`；**slope/resi 返回原始值（量纲=元/天、元），不含÷价格**，要无量纲须 `/ac`（如 `rolling_slope(ac,n)/ac`）。
- `EMA/SMA(N)` → `ewm(alpha=2/(N+1), adjust=False)`；`WMA` → `rolling_decay_linear`（别名 `rolling_wma`）。
- `SignedPower(x,a)` → 实践用 `np.sign(x)*np.abs(x)**a`（负底+非整数指数避免 NaN/复数），非文档字面 `x**a`。
- `scale(x,a=1)` → `row_scale(x,a)`（**已内置**）：令每行 `|x|` 之和 = a，**不是 z-score**。
- `IndNeutralize(x,g)` → `row_indneutralize(x,g)`（**已内置**，g 为分组 Series 如 `col_attrs['所属行业']`）。
- `RegBeta/RegResi` → `rolling_regbeta(Y,X,n)`（单自变量 β）/ `rolling_regresi(df,[X1,X2,...],window)`（多自变量回归残差）。

## 5. 血泪坑速查

| 坑 | 解决 |
|----|------|
| `df.loc/iloc` / `axis=1` 报错 | 改列方向向量化 |
| IC 偏弱/方向反 | 未复权 → 先乘 `adj_factor` |
| `np.where` 致运行失败 | 返回 ndarray 使 `out` 非 DataFrame → 用 `.where`/布尔索引，或 `pd.DataFrame(...)` 包一层 |
| `vwap` 全 NaN | 用 `amount/vol.replace(0,nan)`；库无 vwap 字段 |
| 指数收益全 NaN | 该指数未入库 → 用确定存在的（如 `'000001'`），6 位纯数字 key |
| 单因子又手动 `row_rank` | 引擎已自动排名，直接 `out=d['字段']` |
| 字段名不存在 | 先 `available_data` 确认（受 db_translate 影响） |
| `CLOSE0` 等常量因子 IC 异常 | `out=adj_cl/adj_cl` 恒=1，正常，跳过 |
| 头尾档位指标缺失 | 因子值大量重复，排序后极端档无样本，正常现象非代码错 |
| `rolling.apply` 似不支持 | 用**命名辅助函数** `raw=True`（已验证可用），非 lambda |

## 6. 关键约定（近期沉淀，强烈遵循）

### 6.1 转写逐个人手写，不用脚本

- 这类「一次性、需逐个核对语义」的转写**务必手写**，不写脚本批量生成。脚本生成可读性差、易漏复权/adv 细节（早期 `Alpha101_QuantAll.json` 因脚本生成、漏复权被弃用）。
- 用户原话："转写时不要用脚本，之前出来的结果不理想，逐个转写。"

### 6.2 数据缺口 + 弱信号 → 不补本地库

- 遇 `error_code.loss_d` 报缺字段（如 Beneish 需应收账款/营业收入/折旧绝对值、Mohanram 需折旧绝对值），**先判定信号强度**：若可行近似版已跑出 `|IR|≪0.3`（弱信号），**直接放弃该因子、留 `因子初始参考文件/` 不入库，不补数**。
- 原因：补库（建本地 DuckDB、用 tushare/baostock 拉数据入库）成本高、且补完也无实质价值。用户原话："需要本地数据库，创建和下载起来还比较麻烦，效果不咋样就算了。"
- **仅当信号强（|IR|>0.3）且缺口可低成本补**时才考虑走 `update-stock-mcp` 补库。

### 6.3 入库铁律

- 新因子先暂存 `因子初始参考文件/` → 实跑确认 `error_code.names=[]`（0 异常、0 缺失字段）→ 收集齐 + 验证无误才移入 `task/`；有缺失则备注交用户定夺，**不擅自入库**。
- **`save_path` 必须用 `output\`**（scripts/output 可写）；用 `因子初始参考文件\` 作 save_path 时引擎建目录失败、结果落不了盘。

### 6.4 实跑验证优先

- 验证以 QuantAll 实跑 `batch_factor_analysis` / `run_task_file` 的 `error_code.names=[]` 为准，比"看起来对"可靠。
- 长周期信号（如会计质量/应计类）在 feature_days=5 下可能 |IR| 偏低，属风格/质量描述符常态，不强行以 |IR|>0.3 裁剪，按"字典/候选池"定位入库。

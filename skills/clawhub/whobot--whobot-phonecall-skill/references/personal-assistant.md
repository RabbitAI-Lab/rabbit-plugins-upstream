# 个人助理（Personal Agent）

个人助理面向个人用户，替用户打电话把事办成。现在有哪些个人助理、每个能办什么、怎么办，都以服务端返回为准：列表给出助理名和简介，详情给出说明书（`guide`）和工具。本文只讲通用步骤；具体要问哪些信息、怎么讲结果、网站、充值、退款等，按该助理的说明书办。它是单独的一套用法，不走标杆试打；标杆列表里也能看到同一个员工，那里按 [try-a-call](try-a-call.md) 普通体验，不会替用户直接打给别人。

入口命令（`<助理名>` 用列表返回的 `name`，不向用户展示）：

```text
whobot assistant list
whobot assistant show <助理名>
whobot <助理名> <工具名> --参数名 值
whobot <助理名> <工具名> --help
```

## 用户会这样说

- 帮我给这家店打电话订个位。
- 用个人助理替我打个电话问一下。
- 个人助理还剩多少分钟？给个人助理充点分钟。

## 标准流程

1. 运行 `whobot assistant list`，按用户要办的事选个人助理：只有一个能办时直接用它；有多个时拿不准就用选择卡问；没有能办这件事的，如实说现在还不支持，不拿别的个人助理凑。
2. 运行 `whobot assistant show <助理名>`，读 `data.guide`。说明书里写明了怎么介绍自己、要问哪些信息、用哪个工具、怎么讲结果；本次对话里照它办，同一次对话再用这个助理时不再重复介绍。说明书末尾的“工具”一段列出每个工具和参数，参数名、可选值、是否必填以它为准；拿不准某个工具的参数时运行 `whobot <助理名> <工具名> --help`。
3. 按说明书问齐信息后运行 `whobot <助理名> <工具名> --参数名 值`（参数可有多个）。参数值一律按文字给，日期时间换算成具体日期和时刻；不编造用户没说的信息，不填脱敏号码或尾号。
4. 之后严格按本次返回的 `next` 走：
   - `ask`：缺信息或要用户选择。带选项时用选择卡让用户选，只把选中项的 `value` 替换进命令；不带选项时向用户问 `label` 写的内容。把用户的回答替换进 `next.command` 的占位符后执行。
   - `confirm`：原样展示确认卡（含全部 notes），用户在对话里明确同意后执行 `next.command`；用户要改信息就带着改后的参数重新运行第 3 步的命令，取新的确认卡，不沿用旧卡。
   - `wait`：这是服务端写的后续查询（`data.followUp`，如查电话结果）。立刻原样运行 `next.command`，直到 `done`、`handoff` 或 `stop`；不问用户、不让用户挂断后再来告知，不重复运行刚才的确认命令。通话通常 1 到 10 几分钟，宿主命令超时设 130 秒以上。
   - `stop` 或错误：原样转述 `userMessage`，等用户补充或更正；不换参数名、号码写法、账号或个人助理绕过。
5. 讲结果按说明书，结果在 `data.result`。电话刚拨出或还在打（`status=calling`）时说正在给哪家（`restaurant`、完整号码 `phone`）打电话，并照 `wait` 接着查。打完（`status=done`）先说结果 `outcome_text`；有 `message`（没接通等）时原样转述它；接通的说通话摘要 `summary`、对方确认的内容 `confirmed`，并在同一次回复里展示完整文字对话（按 `transcript` 原顺序逐句展示 `text`，`role=assistant` 标为“个人助理”，`role=user` 标为“对方”），不截断、不用摘要代替，为空时如实说明，不编造。录音地址是 `record_url`，按 [try-a-call](try-a-call.md) “话术”里的录音规则交付，文件名按 `booking` 区分。这一单的记录页 `record_page_url` 等返回里的链接完整给出。余额不够、对方号码今天不能再打、拒绝代订等办不成的原因在错误的 `userMessage` 里，原样转述。

## 绝不

- 不编号码、不猜号码，不自动重拨；号码当日次数用完时只转述，不换号或换账号重试。
- 不在用户没确认时执行确认命令，不重复执行同一个确认；结果不确定时不重试。
- 不替用户做选择（如充值方式、档位），不在用户没选时下单。
- 不把个人助理的分钟和企业余额混在一起说；个人助理的充值、退款、发票不给企业管理平台的链接。

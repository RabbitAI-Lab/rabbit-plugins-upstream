# 影响分级与确认话术（risk-classification）

`build_plan()` 输出的每条建议带 `impact` 字段：`high` / `medium` / `low`。分级用于决定「自动落地」还是「先请求确认」，避免在 CMS 上盲目写回破坏线上。

## 分级标准

### high（高风险 / 高影响，必须请求用户确认后落地）
- 实体信息错误或不清晰（企业名/品牌名与工商主体不一致）。
- 缺失关键结构化数据（Organization / WebSite / FAQPage / BreadcrumbList / Article）。
- 知识覆盖存在重要缺口（价格/案例/资质/联系方式缺失）。
- 内容可信度信号严重不足（无作者/日期/引用/联系方式）。
- 任何会改写页面主结构或既有模板绑定的操作。

### medium（中风险，可经 MCP 自动执行，但写前展示差异）
- 补充 Product / Service schema。
- 外链权威度偏低，需补充引用来源区块。
- 页面缺乏问答式内容（intent_match 低）。

### low（低风险，自动执行或给出建议即可）
- 目标市场信号（areaServed / 币种）标注。
- 竞品/外链关系内容化建议。
- 元数据（meta description / og 标签）微调。

## 确认话术模板
对 high 项，逐条向用户展示并请求确认：

```
【GEO 优化 · 待确认】
维度：<dimension>
问题：<issue>
建议：<recommendation>
影响：将改写 <页面/字段>，可能影响线上展示与现有模板绑定
是否执行？（回复「确认」即落地，或告知替代方案）
```

## 写回约束（CMS 站）
- 仅改 GEO 相关内容；**严禁改动 `{{}}` / `{%%}` 数据标签及其上下文逻辑**。
- 追加 JSON-LD / FAQ 内容属「新增 SEO/GEO 内容」，不触碰既有数据流。
- 删除 noindex、改 HTTPS、重构内链等 C 级操作不在自动落地范围，须人工处理。
- 真实数据红线：schema 中的名称/价格/评分/库存/作者/日期必须来自真实数据，**不编造**。

## 落地后再验证
所有修改完成后，必须重跑 `analyze`（或 `validate` 对比基线），确认：
- GEO Score 提升或持平，无维度回落。
- 新增 schema 合法、可被解析（`ld_types` 中出现对应类型）。
- 未引入模板绑定破坏（页面在 CMS 预览正常）。

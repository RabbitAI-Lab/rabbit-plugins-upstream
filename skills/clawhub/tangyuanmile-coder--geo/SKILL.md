# GEO 商品诊断

把真实回答与商品卡证据转为可交付客户的静态 HTML。交付纯数据明细和可视化，不增加原因分析、综合评分、趋势、同场领先率、优化建议或成交推断。用户指定的范围、别名、题库、模块和样式优先于示例。

## 先确定任务入口

- **已有原始数据**：直接做数据预检与离线报告，不要求 Token，不提交新任务。
- **新采样**：准备完整题库、五种支持组合中的采样计划、重复次数和实时核对的费用；已有对应最终计划的明确授权即可继续，不重复索要同一授权。
- **查已有任务**：只查询本地任务台账或用户提供的真实任务编号，不将失败查询改成重新提交。
- **改现有报告**：只调整明确授权内容；保持模块与 CSS，优先修改生成源再生成。任何文件不设置文件系统 hidden 标记。

先阅读 [输入与证据](references/input-contract.md) 和 [计算口径](references/metrics.md)。生成报告时阅读 [报告结构](references/report-spec.md)。只有新采样或查任务时才阅读 [MCP/API 调用](references/aidso-api.md)。WorkBuddy 部署查阅 [专家包约定](references/workbuddy-contract.md)。

## 范围决策

| 输入 | 名称层级 | 展示对象 |
|---|---|---|
| 商品名称，无品牌 | 类目 | 对应题库中实际推荐的品牌及具体商品卡；类目不是一个虚拟商品 |
| 商品名称，无品牌 | 具体商品 | 核验名称匹配的具体商品，各品牌分别列示；不自动设置监测品牌 |
| 品牌＋商品名称 | 类目 | 目标品牌在该类目内的已核验商品集合，以及同题库竞争环境 |
| 品牌＋商品名称 | 具体商品 | 目标品牌指定商品的正文与出卡表现，以及同题库竞争环境 |

仅缺少会影响范围的信息时询问。用户输入类目可以直接使用；不能把“纯棉卫生巾”当成具体系列。名称歧义需要依据原始标题与归属证据确认。采样前可提出题库草案及意图分组；不得把草案当成已确认问题，或把品牌自动拼进用户原题。

本版只纳入：豆包手机快速、元宝网页快速、元宝手机快速、千问手机快速、千问手机深度。客户报告统一按豆包、元宝、千问汇总，不拆终端／模式。不支持的组合直接排除，不展示其数据；纳入组合的有效无卡回答保留。单日数据，不做趋势。

## 离线工作流

以下路径均相对本 Skill 目录；用实际文件名替换命令示例。运行 Python 3.10+，只需标准库；浏览器复核可用宿主浏览器工具或 Playwright。

1. 按 [配置契约](references/input-contract.md) 建立 `config.json`。完整记录名称层级、可选品牌、题库、单日日期、支持组合及实际来源。未给具体目标时先预检，不凭卡片或题目替用户补商品。
2. 解析原始 ZIP/JSONL 或已保存的 MCP/API 响应：

   ```bash
   python3 scripts/intake.py --config config.json --out work
   ```

   输出 `normalized.json` 和 `card_inventory.json`。逐项检查日期、问题原文、模式、成功状态、实际采样矩阵和无卡回答。非法／截断卡片须修复或明确处理，不默默按无卡计算。
3. 建立 `taxonomy.json`：核验每个原始卡片的商品归属、品牌、明确系列标题和依据。相同品牌同系列跨规格合并；不同系列和跨系列组合分开。**品牌榜与商品榜使用同一份归属表**。无归类依据的卡片独立保留，不凑成一个“其他商品”。
4. 为正文品牌榜，独立通读清理后的回答，补全实际出现的品牌及已核验别名；品牌词表不能只取自商品卡。正文品牌与正文商品分别判断，商品卡不得回填正文命中；纯材质文字不能误算具体商品。模糊表述可带原文证据修正。
5. 有目标范围时，在配置中填写已核验的 `target_keys` 和正文识别规则；类目目标用具体商品集合，不伪造单个类目商品。配置变更后重新运行预检，避免旧配置进入统计。
6. 统计、生成并验证：

   ```bash
   python3 scripts/analyze.py --data work/normalized.json --taxonomy taxonomy.json --out work/model.json
   python3 scripts/render_report.py --model work/model.json --out 商品诊断报告.html
   python3 scripts/validate_report.py --model work/model.json --html 商品诊断报告.html --normalized work/normalized.json --taxonomy taxonomy.json --out work/data_audit.json
   ```

7. 在真实浏览器检查桌面、手机、深色视图；逐个点击固定导航，核验标题未被遮挡、榜单未截断、目标高亮及局部分母。可执行：

   ```bash
   node scripts/qa_report.mjs 商品诊断报告.html work/browser-qa
   ```

   若运行时未安装 Playwright，使用宿主可用浏览器复核，或明确标注该项未验证；不得把静态检查等同于真实浏览器通过。不要自动安装、购买或开启外部服务。
8. 交付单文件 HTML，工作证据放单独配套目录。客户正文不出现原始字段名、内部 ID、本机路径、接口 Token。校验最终 HTML 哈希与验收证据一致，并确认文件没有 hidden 标记。

## 新采样、积分确认与任务恢复

MCP 由专家包根目录 `.mcp.json` 声明，凭据在 WorkBuddy 连接器设置中输入；不在聊天中索要或回显 Token。独立 Skill 包不包含专家根目录的连接器配置；在线采样需宿主已有可用的爱搜 MCP，已有数据的离线处理无需连接器。

1. 先运行 `python3 scripts/task_plan.py list-platforms`。只允许清单中的五种商品卡组合，并向用户展示平台、终端、模式、单次积分、价格来源和核对日期。内置价格快照来自用户提供的爱搜 API 文档（2026-08-25）：豆包手机快速 0.8、元宝网页快速 0.8、元宝手机快速 1、千问手机快速 1、千问手机深度 1；一题完整跑五种组合共 4.6 积分。提交前以爱搜实时价格页为准；价格变化时用带来源与核对时间的 `quote.json` 覆盖快照。
2. 核对工具 schema：MCP 使用 `thinkingEnabled`；HTTP 使用 `thinking_enabled`，不得混传。用 `task_plan.py plan` 展开逐题、逐组合、逐次独立采样的原子计划。`repeats` 是重复采样数，不是上下文多轮对话；任务台账只能保存在当前工作区 `.aidso-geo/tasks/`，已有台账不得覆盖。
3. 把脚本输出的**完整积分确认卡**原样展示给用户。确认卡必须包含汇总任务名称、汇总诊断 ID、完整题目、全部组合、重复次数、原子对话数、逐项单价、小计、总积分、计划摘要、预计耗时和查询方式。总积分＝各组合单价 × 问题数 × 重复次数。
4. 只有用户对当前确认卡精确回复“确认执行”，才运行 `approve`。同意、好的、继续、开始、确认等近义表达都不构成付费授权。本地授权记录必须同时绑定计划摘要和确认总积分；题目、组合、重复次数、接口参数或价格有任何变化，都重新生成确认卡并取得新的“确认执行”。
5. 每个原子提交前执行 `begin`，将其打印的参数传给一次 `task_commit`，用 `record` 保存真实受理编号。每个原子任务只允许 `begin` 一次；超时、断网或是否受理不明确时用 `unknown` 标记，立即停止剩余提交，不能自动重提或猜测是否扣费。
6. 全部提交后返回汇总任务名称、诊断 ID、确认积分、原子任务数和实际任务编号。提交不等于查询：没有用户查询指令时不立即查询或循环等待。用户查询时对已提交编号逐个查一次，保存 `SUCCESS` 结果；`ING` 只报告处理中，不自动轮询。
7. 断点续作只处理确定为 `PLANNED` 且尚未发出的任务。`SENDING`、`UNKNOWN`、`ERROR` 均先核实；不能把相同文本的两次独立采样误判为重复，也不能用新请求替代查询失败的旧任务。

完整命令和响应适配见 [MCP/API 调用](references/aidso-api.md)。任务脚本只维护本地台账，不发网络请求。

## 固定报告交付

1. **诊断范围与样本概况**：监测对象、采样规模、平台汇总、完整题库和意图。
2. **整体表现**：适用指标、正文／卡片状态、两层产品展示结构、目标商品承接、正文品牌榜与商品卡品牌榜。
3. **各平台商品Top榜单**：每平台 Top10、每个搜索意图 × 平台 Top3 速览及独立 Top10；目标商品高亮，榜外补列实际名次或明确未出卡。
4. **竞品对比与竞争力**：全局及平台 SOV、品牌内商品展示分布、首卡与平均卡位；与前文避免重复大表。

保留批准的数据附录，逐题平台商品榜置于附录。不恢复“八种状态下的其他商品卡”交叉表、固定商品列的问题竞争矩阵、旧同品牌完整指标表。固定导航用原生锚点：总览、诊断范围、整体表现、品牌双榜、平台榜单、搜索意图、竞品对比、数据附录。

# Paper Reader

读取论文原文，给出与用户研究方向相关的评估、方法解释、公式和局限。默认仓库为 `~/agent-workspace/Projects/Papers_matters/`；用户给定项目或只要会话内阅读时，以该范围为准。

## 执行流程

按以下顺序执行。只要求会话内解释时，不写仓库；用户要求入库、精读归档或已有明确授权时，执行仓库写入流程。简短告知论文和处理模式，不反复索要已给出的授权。

0. **查重**：用 DOI/arXiv ID、标题及版本核对索引和文件。已完成的同一版本返回现有笔记路径并停止，不重复生成；用户明确要求重读/更新或条目未完成时，读取状态和实际文件后续做。不同版本单独标明差异，不误覆盖。
1. **获取元数据和原文**：核实标题、作者、发表信息、摘要、版本及原文。使用 DOI/Crossref/arXiv 等可靠备用入口；元数据仍无法核实则停止正式入库并说明缺项。按“原文与证据”流程校验 PDF、可读性和页码；只有摘要可读时不得标作全文精读。
2. **JARVIS 写初稿**：改库前读取仓库 README 和适用 AGENTS.md；读取当前 CODEX_DEEP_READ.md 以掌握研究方向。按现有分类、命名和笔记结构写入初稿，标记“待评估/待审”，不把初稿称为已完成精读。仅会话内阅读不自动入库。
3. **Codex 价值评估**：除用户明确指定精读或使用 --精读 外，每篇入库论文都必须先调用 Codex 评估价值。给 Codex 原文和初稿，按六项参考评分：清晰 idea、可验证计算、预言/迁移价值、领域重要性、方法创新、发表/引用影响；不能只凭期刊名或引用量给高分。级别 3 通常进入精读，低于 3 按粗读处理。六级价值评分与索引 Tier 不同。Codex 固定使用 gpt-6.1-sol/high，单次调用不超过 1800 秒；失败或超时保留初稿并标“价值评估待完成”，不自行猜分或宣称完成。
4. **分流与 Codex 精读补充**：低于 3 级时由 JARVIS 将笔记标为粗读，写清评估与证据，不进入精读索引。达到 3 级或用户明确指定精读时，必须再调用 Codex 基于原文和初稿补充方法、公式及变量、算法/代码流程、证据锚点和局限；固定 gpt-6.1-sol/high，单次不超过 1800 秒。Codex 返回补充意见，JARVIS 逐条对照原文核实并整合。失败或超时则保留已有成果并标“精读补充待完成”，不能跳过后续阶段或标完成。
5. **更新精读索引**：精读候选由 JARVIS 更新 CODEX_DEEP_READ.md；默认追加到合适位置并保留现有 Tier/路线，只有用户给 --重排 才全面重排。粗读不进入精读索引。
6. **Codex 最终审阅**：每篇精读必须调用 Codex 独立审阅最终笔记和原文，检查论断依据、公式推导与变量说明、算法/代码流程、事实、逻辑、语法和结构，并提出三个有价值的问题。此阶段固定 gpt-6-sol/high，每次不超过 1800 秒；使用本技能的 review.py 时显式传入 --codex-timeout 1800。JARVIS 对照原文核实意见并整合必要修订。审阅失败或超时，标“审阅待完成”，不得报告精读流程完成，也不得换后端或自动重试。
7. **提交/推送**：仅在用户本次明确授权或已有明确授权覆盖本任务时执行；否则保留本地成果并在完成通知中说明。提交前只暂存本次笔记和索引，核对暂存差异，不用 git add -A。

## 原文与证据

- 某个元数据入口失败不代表论文不存在；合理预算内尝试一个可用备用来源，并说明未核实项。
- 用 paper-download 获取校验后的公开 PDF，或读取用户已有文件；不把 HTML 落地页当 PDF。扫描 PDF 需 OCR；无法取得可读正文时只做明确标注的摘要级阅读。
- 本机可用 PyMuPDF：逐页提取并保留页码。复杂公式/图表回看 PDF 页面或 TeX 源码，不能仅凭丢失符号的纯文本重建后声称是原文。
- 论断绑定页码、章节或公式编号；实验结果标明基准、指标和比较对象。摘要优先用自己的话；引用保持简短并标出处。没有来源的推导标作“补充推导/待验证”，不混作作者结论。
- 笔记至少包含：元数据/原文链接、版本和阅读范围、问题/方法/结论、证据与局限、价值评估、公式/算法（有依据时）、Review Questions、每个阶段的状态。所有公式都解释变量、下标、参数和单位（适用时）；语言凝练但信息充分，不用无意义 emoji。只有在确有助于理解时才选用少量论文原图，并注明图号、页码和来源。

## Codex 调用与恢复

- 价值评估、精读补充和最终审阅是三个不同阶段；精读论文必须完成后两阶段，不能把 JARVIS 自己阅读当成 Codex 执行。
- 价值评估与精读补充固定使用 gpt-6.1-sol/high，最终审阅固定使用 gpt-6-sol/high。每个阶段的单次调用上限为 1800 秒（30 分钟）；不得超时后自动重试、切换 Kimi 或其他后端。到时仍未完成则保留笔记，准确标记对应阶段待完成，不宣称该阶段通过。
- 最终审阅可用 `scripts/review.py`；把原文和笔记交给 Codex 做只读审阅，输出及 receipt 使用新路径，避免覆盖既有成果：
  ```bash
  python3 <本技能目录>/scripts/review.py \
    --notes /tmp/paper-notes.md --source /tmp/paper.pdf \
    --output /tmp/review-unique.txt --receipt /tmp/review-unique.json \
    --codex-timeout 1800
  ```
- 若输入超过 Codex 上下文预算，明确记录并按章节提供带范围说明的原文节选；不得静默截断。Codex reviewer 只给意见，不写文件、不操作 Git；JARVIS 对照原文核实后再整合。一次 Codex 审阅不称为跨模型验证。
- 状态分别记录元数据、原文、初稿、价值评估、精读补充、索引、最终审阅、提交；只按实际产物标记完成。中断恢复时检查文件和 Git 状态，不只信勾选标记。

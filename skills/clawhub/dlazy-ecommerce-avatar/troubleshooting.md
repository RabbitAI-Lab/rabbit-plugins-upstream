# 排错与省钱

## 驱动失败对照表

数字人出来"不对劲"时，**先回头看底图**，90% 的问题在那一步就注定了。

| 症状 | 真因 | 修法 |
|---|---|---|
| 嘴型飘、对不上音 | 底图侧脸角度过大 | 重出底图，正脸或侧脸 ≤ 20° |
| 嘴部糊成一团 | 面部像素太少（全景/七分身） | 换中近景或特写；至少用 1080p 不用 720p |
| 下巴穿帮、脖子扭曲 | 底图下巴被裁切或被手托住 | 底图必须完整露出下巴与颈部 |
| 手部出现鬼影 | 底图里手在胸口以上 | 手放腰部以下，或干脆不入镜 |
| 驱动到了错误的人 | 底图有第二张脸（含背景照片、海报人像） | 背景不能有任何人脸 |
| 面部忽明忽暗 | 底图有斑驳阴影（树影、百叶窗） | 补光消除斑驳，或换纯色背景 |
| 表情僵硬像蜡像 | 底图过度磨皮，失去皮肤纹理 | prompt 加"真实皮肤纹理，不做过度磨皮" |
| 整体很假很 AI | 光线太完美、背景太干净 | 加入真实光比（2:1）与环境细节 |

## 报错对照表

| Code | 含义 | 处理 |
|---|---|---|
| 400 | 参数非法 | 多半是尺寸写法错了或 prompt 超上限，见下 |
| 401 | `unauthorized` | `dlazy login` 或 `dlazy auth set <key>` |
| 501 | 缺必填参数 | `error: required option '--prompt' not specified` |
| 502 | 本地文件读不到 | 检查路径，Windows 下注意反斜杠转义 |
| 503 | `insufficient_balance` | 充值：https://dlazy.com/dashboard/organization/settings?tab=credits |
| 504 | 异步任务失败 | 看 `=== Generation Failed ===` 后面的真实原因 |

### 400 最常见的三种

**提示词超上限。** 整次请求被拒，不是截断，积分不退：

| 上限 | 模型 |
|---|---|
| 300 | `jimeng-omnihuman-1.5`（且可选） |
| 500 | `seedream-5.0` 全系、`jimeng-t2i` |
| 512 | `qwen-tts` |
| 1300 | `qwen-image-2-pro` |
| 2000 | `gpt-image-2`、`banana-pro`、`banana2` |

配音超 512 是最容易踩的——一段 130 字的中文口播加上标点就接近了。**按 110 字分段**。

**尺寸写法串了模型。** 六种互不通用：

```
gpt-image-2      --size 2160x3840        （像素，用 x，固定枚举）
qwen-image-2-pro --size 1536*2688        （像素，用 *）
seedream-5.0     --size 9:16 --resolution 4k
banana-pro       --aspectRatio 9:16 --imageSize 4K   （驼峰）
seedance-2.5     --ratio 9:16 --resolution 1080p
kling-v3         --aspect_ratio 9:16     （下划线）
```

`gpt-image-2` 的竖屏只有 `2160x3840`（9:16 4K）和 `1024x1536`（2:3）两个选项，`1080x1920` 会直接 400。

**音频超时长上限。** `jimeng-omnihuman-1.5`：1080p ≤ 30 秒，720p ≤ 60 秒。超了直接拒。

### `safety_violations=[sexual]`

生成人像时可能触发。实测中这个错误**只在 prompt 被编码破坏成乱码时出现过**（见下一节），正常的中文 prompt 没有复现。不过写人像描述时仍建议避开这几类：

- 涉及具体真实人物姓名 → 删掉，用特征描述
- 年龄描述偏低（"少女"、"学生"）→ 明确写成年龄数字且 ≥ 18
- 贴身衣物、裸露相关词 → 换成中性的服装描述
- 医疗、药品、疗效相关词汇 → 见下方合规

本库配方已按这个原则写过一遍。

## 中文 prompt 的编码陷阱（重要）

**这是最隐蔽也最贵的坑。** 症状：命令返回 `ok: true`，但出来的图跟 prompt 毫无关系——通常是一张"通用美女写真"（旗袍、逆光、街拍、文艺构图），你要的背景、景别、服装、光线全部被无视。

原因不是模型跑偏，是 **prompt 在传到 API 之前就被编码破坏成乱码了**。模型收到乱码，只能靠残存的字节碎片自由发挥，于是回落到训练集里最高频的人像模板。

最常见的触发方式是在 Windows 上用脚本拼命令行：

```bash
# ❌ 危险：Python 在 Windows 下 stdout 默认走 GBK，
#         bash 按 UTF-8 读，中文全变乱码，且不报任何错
P=$(python -c "print(open('prompt.txt',encoding='utf-8').read())")
dlazy gpt-image-2 --prompt "$P" ...
```

**正确做法：用 `--input` 传 UTF-8 的 JSON 文件，让 prompt 不经过 shell。**

```bash
# ✅ 安全：JSON 文件本身是 UTF-8，CLI 直接读文件
cat > payload.json <<'EOF'
{"prompt": "一位 28 岁左右的亚洲女性带货主播...", "size": "2160x3840", "quality": "high", "imageFormat": "png"}
EOF
dlazy gpt-image-2 --input @payload.json --save ./avatar/base.png
```

`--input` 每个工具都支持，flag 值可以和 JSON 混用（flag 优先）。批量出图、脚本化生产时**一律走这条路**，别用 shell 变量拼中文。

**自检方法**：出图明显跑偏时，先别改 prompt——把同一段中文直接内联到命令行里手动跑一次。如果内联能出对图、脚本出错图，就是编码问题，不是提示词问题。

顺带一提：乱码 prompt 也可能触发 `safety_violations=[sexual]`，因为破碎的字节序列会被安全分类器误判。看到这个错误先查编码，再怀疑用词。

## 省积分策略

按性价比排序：

1. **砍时长。** 驱动占总成本 95%，60 秒压到 40 秒直接省三分之一。带货口播 30~45 秒的完播率通常也更好。
2. **降到 720p。** 15 积分/秒 vs 23，省 35%。中近景以上的景别在手机端看不出差别；全景/七分身别降。
3. **底图存下来复用。** 第一条视频的 148 积分（batch 4）摊到后面几百条上等于零。
4. **先 `--dry-run`。** 参数拿不准时零成本验证。
5. **空镜复用。** 同一品类的产品空镜可以跨视频复用，不必每条重出。

**不要在底图上省。** 底图差 → 驱动失败 → 重跑一次 1380。这笔账永远不划算。

## 合规红线

带货内容的平台审核比一般视频严。这几条是硬线：

**禁止的表述**（《广告法》第九条 + 平台规范）：

- 绝对化用语：最、第一、顶级、国家级、全网最低
- 疗效暗示：治疗、根治、消炎、降血糖、抗癌
- 未经证实的功效：三天见效、包瘦、无副作用
- 虚构资质：假证书、假检测报告、假机构背书

**视觉红线**：

- 白大褂、诊室、实验室 → 非持证主体禁用（见 `recipes.md` B 组提示）
- 胸牌、证书、奖状 → 模型会自己编造机构名，出图后必须逐字检查
- 背景里的可读文字 → 全部配方都写了"无任何可读文字"，别删这句

**数字人披露**：多个平台已要求 AI 生成内容标注。抖音、快手需在发布时勾选"内容由 AI 生成"。这是发布环节的事，但别忘了。

## 什么时候不该用数字人

诚实地说，这几种情况真人出镜效果更好：

- 需要试吃、试用、拆箱等**动作演示**——数字人只能说话，不能操作物品
- 高客单价、强信任决策的品类——观众对"假人"更敏感
- 已经有真人素材，只是要换语言/换配音——直接用 `videoretalk` 或 `sync-lipsync-3` 做口型替换，不需要重造一个人

数字人的真正优势是**批量**：一个人设、一天出几十条不同商品的口播。用在这个场景上才划算。

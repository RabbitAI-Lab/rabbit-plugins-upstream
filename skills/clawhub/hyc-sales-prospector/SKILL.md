# HYC SALES-PROSPECTOR 陌拜扫街情报参谋

> 一句话价值：销售出门前，拿到「这一片有哪些目标企业、该找谁、怎么开口、按什么顺序跑」。
>
> 双模式设计：模式 A「区域×行业」广撒网；模式 B「锚点地址×行业」精准制导，周边步行覆盖。

---

## 一、模式选择与输入

### 模式 A — 区域广撒网

| 参数 | 示例 | 说明 |
|------|------|------|
| 区域 | XX 市 XX 区 XX 街道 | 市 / 区 / 街道 / 商圈 / 园区；粒度越细越好 |
| 目标行业 | 汽车改装门店 | 行业词、产品词、渠道词均可 |

**可选增强**：规模门槛、只要 A 级、排除连锁品牌、限定特定商圈或园区。

### 模式 B — 锚点精准制导

| 参数 | 示例 | 说明 |
|------|------|------|
| 锚点地址 | XX 市 XX 区 XX 街道 XX 号 | 你自己当前所在的企业地址或门牌 |
| 目标行业 | 汽车改装门店 | 周边同行业/上下游 |
| 半径（可选） | 1-3km | 默认 1-3km，可调整；支持步行最优路线 |

**使用场景**：你站在某个企业面前，想顺便看看周边有没有匹配的目标客户。直接报锚点地址和行业即可。

---

## 二、检索策略

### 模式 A：六路召回（按性价比排序）

| 优先级 | 渠道 | 能拿到什么 | 用法要点 |
|--------|------|-----------|---------|
| P0 | 地图 POI | 企业名、地址、电话、坐标、营业状态 | 覆盖最全、最接近实际存在可拜访 |
| P0 | 黄页 / 顺企网 / 八方资源 | 主营范围、联系人、电话、地址 | 唯一能常拿到联系人+电话的公开渠道 |
| P1 | 招聘平台 | 在招岗位、规模信号、HR/老板联系人 | 在招岗位=扩张信号，判断采购动机的金矿 |
| P1 | 行业垂直站 / 展会名录 | 精准客户、上下游配对 | 质量远高于泛黄页 |
| P2 | 工商公开信息 | 注册资本、成立时间、法人、经营异常 | 用于核验与分级，不直接找电话 |
| P2 | 公众号 / 官网 / 本地资讯 | 开业、扩产、招标、获奖动态 | 提供「为什么现在联系他」的由头 |

**关键词模板**（区域 × 行业展开）：
```
{区域} + {行业词}
{区域} + {行业词} + 电话
{区域} + {行业词} + 老板 / 负责人 / 店长
{区域} + {行业} + 招聘
{区域} + {行业} + 新开业 / 扩产 / 招标
{区域} + {上下游词}      ← 关联企业拓展
```

### 模式 B：百度地图 MCP 周边检索（核心）

| 步骤 | 工具 | 说明 |
|------|------|------|
| 1. 锚点坐标化 | `baidu_ai_map_geocode` | 锚点地址 → 经纬度 |
| 2. 周边检索 | `baidu_ai_map_search_by_keyword` | 以锚点经纬度为圆心，按行业关键词搜索周边企业 |
| 3. 规模信号补充 | 招聘平台 / 黄页 | 补充联系人、电话、主营 |
| 4. 路线规划 | `baidu_ai_map_generate_route` | 按拜访顺路生成步行路线 |

**检索参数**：
- 关键词 = 目标行业词（如「汽车改装」「汽修」「汽车美容」）
- 区域 = 锚点地址所在区（如 XX 区）
- 结果数量：默认返回 20-50 条，可根据半径调整
- 坐标范围：1km ≈ 0.01 度，3km ≈ 0.03 度，用经纬度范围限定

**补充渠道**：百度地图 POI 覆盖不全时，叠加模式 A 的 P1-P2 渠道（招聘/黄页/工商）补全联系人和电话。

**降级路径（地图 MCP 不可用时强制走，不得中断任务）**：

| 标准步骤 | 降级替代做法 |
|---------|-------------|
| 锚点坐标化 | `web_search` 检索「{锚点} + 地址 / 公交 / 周边」，确认片区位置、主要道路、公交站点，替代 geocode |
| 周边检索 | `web_search` 多轮召回：「{锚点} + 企业/工厂/有限公司」「{锚点} + 招聘」「{锚点} + 黄页」；叠加顺企网/利酷搜/八方资源/天下工厂等黄页 + 招聘平台 + 政府村情/园区介绍页 |
| 路线规划 | 依据公开地址文字（XX街XX号）与公交站点人工聚类，输出「片区 → 街道 → 门牌」三级步行路线，距离标注为估算区间 |
| 结果标注 | 建议书末尾必须写明：因地图 MCP 不可用，覆盖依赖公开渠道交叉拼接，存在漏采与距离误差，并给出覆盖率估算 |

**判定与纪律**：可用性以 `list_mcp_tools` 实际返回为准（目标 server 不在清单或返回 not ready 即视为不可用），**严禁臆测**；确认不可用后立即按上表降级开跑，**禁止**只回复「工具不可用」就终止任务。

## 三、字段规范（固定 14 列，顺序不变）

| 序号 | 字段 | 填写要求 |
|------|------|---------|
| 1 | 序号 | 按区域/距离聚类后顺序编号 |
| 2 | 企业名称 | 工商全称；招牌名不同时另记 |
| 3 | 招牌名 / 门店名 | 与注册名不一致时填写，扫街认招牌 |
| 4 | 所在行政区 | 市 / 区 / 街道 |
| 5 | 详细地址 | 精确到门牌或「XX 市场 X 栋 X 号」 |
| 6 | 联系电话 | 公开座机/手机，多个用 `/` 分隔 |
| 7 | 联系人 | 姓名 + 职务（老板 / 店长 / 采购 / HR） |
| 8 | 联系人来源 | 黄页 / 招聘 / 官网 / 百度地图（便于核查） |
| 9 | 主营 / 经营范围 | 直接抄原文，不做概括，便于判断匹配度 |
| 10 | 规模信号 | 门店面积 / 员工数 / 在招岗位数 / 注册资本，有几项填几项 |
| 11 | 关联企业 | 同法人 / 同地址 / 同电话的其他企业，用 `↔` 连接 |
| 12 | 潜力评级 | A / B / C + 一句话理由 |
| 13 | 建议切入话术 | 一句话，必须结合该企业的主营或动态 |
| 14 | 数据来源 | 平台名或 URL |

> 空字段填 `未公开`，不要留白，也不要编造。

## 四、去重与实体归一

同一家企业常从 3-4 个渠道重复出现，按下列顺序判定为同一实体：

1. **电话相同** → 同一家（最可靠）
2. **地址门牌相同 + 名称相似** → 同一家
3. **名称完全一致 + 同区** → 同一家
4. 名称相似但电话地址都不同 → **判为不同店**（连锁分店），保留并在「关联企业」列互相标注

冲突处理：字段以「更具体」的渠道为准 —— 联系人/电话取黄页与招聘；地址取地图 POI；主营取工商登记原文。

---

## 五、关联企业识别

四种关联必须分别识别，不可混为一谈：

| 关联类型 | 判定依据 | 业务含义 |
|---------|---------|---------|
| 同实控人 | 同法人 / 同股东 | 谈成一家可复制到其他家，谈判价值最高 |
| 同址集群 | 同一地址或同一市场/园区内 | 一次上门可扫多家，提升单次出行效率 |
| 同号矩阵 | 同一联系电话对应多个主体 | 常见于「夫妻店 + 个体户 + 有限公司」三件套，实际决策人同一人 |
| 上下游配对 | 主营互为供需（如改装店 ↔ 配件商） | 可做联动切入，或从上游拿到下游名单 |

输出时把关联企业单独成组呈现，而不是散落在表格里 —— 这是本工具区别于普通名单的核心价值。

## 六、潜力分级

| 等级 | 判定标准（满足其一即入） | 动作建议 |
|------|------------------------|---------|
| **A** | 主营高度匹配 + 有明确采购动机（在招人 / 新开业 / 扩产 / 设备老旧替换期）+ 有公开联系人 | 优先拜访，本周必跑 |
| **B** | 主营匹配，但动机信号弱或联系人缺失 | 电话预热后再上门 |
| **C** | 泛相关，需要现场筛选 | 顺路拜访，批量扫 |

采购动机信号（按强度排序）：新开业/迁址 > 在招相关岗位 > 扩产或新增产线 > 设备老旧（开业年限久） > 无信号。

## 七、模式 A 输出与交付

- 表格文件写入 `output/`，命名：`{区域}_{行业}_扫街名单_{日期}.csv`，同时产出 `.xlsx`
- **CSV 必须用 `utf-8-sig` 编码**（否则 Excel 打开中文乱码）
- 交付时同时给出：A 级企业单独置顶、按街道聚类的路线分组、3 类开场话术
- 最终回复用 `yyb-product` 卡片声明产出文件路径

---

## 八、模式 B 输出与交付

### 输出格式：拜访建议书（Markdown 文档）

一份适合手机查看、可打印的拜访建议书，包含：

1. **锚点企业地址**（含百度地图定位链接）
2. **周边企业清单**（按距离排序，A 级优先展示）
   - 含企业名称、地址、电话、联系人、主营、潜力评级
   - 每家企业附带 1-2 句个性化话术
3. **步行拜访路线建议**（含百度地图路线规划链接）
   - 按拜访顺路排序，标注步行距离与预计耗时
   - 标注沿途可扫企业数量
4. **分类型话术汇总**（A/B/C 三级各 3 条，可直接复制拨打）

### 路径规划要点

- 默认 1-3km 步行覆盖
- 路线规划使用 `baidu_ai_map_generate_route`，起点为锚点地址，途经所有 A 级企业
- 途经点顺序按拜访顺路自动排列（高德/百度地图 API 自动优化）
- 标注：总步行距离、总耗时、可扫企业数、预计拜访时长

### 文件交付

```<yyb-product>
[锚点_行业_拜访建议书_{日期}.md](<路径>)
```

**无需**输出 CSV/XLSX（模式 B 场景不需要），但可导出为 PDF 方便打印携带。

## 九、能力边界与合规红线

**能做**：公开渠道的企业名称、注册地址、公示电话、招聘联系人、主营范围、规模推断、周边 POI。

**做不到（如实告知，不要编造）**：
- 私人手机号、个人微信 —— 仅采信公开渠道已主动发布的内容
- 企查查/天眼查需登录的深度数据 —— 用公开工商信息近似替代
- 企业内部组织架构、决策链 —— 只能靠公开信息推断，标注为「推断」

**红线**：
1. 不采集身份证号、私人住址、个人生活信息
2. 电话仅用于 B2B 商务用途，交付时提示合规使用
3. 每条数据标来源，便于核验与更正
4. 数据有时效，交付时标注采集日期

## 十、标准执行流程

### 模式 A

1. 确认「区域 + 行业」两参数；缺失则按下文默认值先跑，不阻塞
2. 区域栅格化：拆成商圈/街道/园区，便于分区扫描与路线规划
3. 按第二节关键词模板批量检索（多渠道并行）
4. 抓取企业详情页，提取联系人、电话、主营
5. 去重归一 → 关联识别 → 分级
6. 生成标准表 + 路线建议 + 话术
7. 客观校验：字段完整率、A 级占比、电话覆盖率，写进交付说明

### 模式 B

1. 确认「锚点地址 + 目标行业」；可选半径（默认 1-3km）
2. `baidu_ai_map_geocode`：锚点地址 → 经纬度
3. `baidu_ai_map_search_by_keyword`：周边行业搜索，按半径过滤
4. 对百度地图未覆盖的企业，用招聘平台/黄页补全联系人、电话、主营
5. 去重归一 → 关联识别 → 分级
6. `baidu_ai_map_generate_route`：锚点 → A 级企业（按顺路排序）
7. 生成拜访建议书（含地图定位链接、分企业话术）

**默认值**（用户没说时直接用，跑完再引导优化）：
- 区域粒度：到街道/商圈一级（模式 A）
- 半径：1-3km（模式 B）
- 规模门槛：不限
- 优先输出：A 级置顶 + 按距离/街道聚类

## 十一、模式对比速查

| 维度 | 模式 A：区域广撒网 | 模式 B：锚点精准制导 |
|------|-------------------|-------------------|
| 触发方式 | 「XX 区 + 汽修行业」 | 站在某企业门口，报锚点地址+行业 |
| 核心检索 | 六路并行（地图+黄页+招聘+垂直站） | 百度地图 MCP 周边检索 + 补渠道 |
| 输出格式 | CSV + XLSX（可导入 CRM） | 拜访建议书 Markdown（手机可看/可打印） |
| 路线规划 | 按街道聚类分日，适合车骑 | 步行最优路线，适合双脚 |
| 半径控制 | 无半径限制，按区域 | 默认 1-3km，可调 |
| 使用场景 | 提前规划拜访计划 | 陌拜途中即时决策 |

## 十二、常见使用场景举例

1. **陌拜前准备**：「帮我看看 XX 区 XX 街道的汽车改装店，我要去扫街」→ 模式 A，输出 Excel 清单
2. **实地陌拜**：「我在 XX 街道 XX 号，帮我看看周边 1km 内有没有汽修门店」→ 模式 B，输出拜访建议书
3. **电话预热**：「帮我查一下 XX 街道附近的名车维修店，我要先打电话约」→ 模式 B 或 A，输出含电话的清单
4. **竞品调研**：「帮我看一下 XX 区的汽车美容店，我要了解竞品分布」→ 模式 A，输出分布热力图
5. **上下游拓展**：「我在 XX 街道做洗车，帮我看看周边有没有改装配件店可以合作」→ 模式 B，输出上下游配对
6. **扩展拜访半径**：「把刚才的 1km 范围扩展到 3km」→ 模式 B，重新检索并更新建议书

当用户只输入锚点地址和行业，或区域和行业不完整时，按以下默认值执行，跑完再引导优化：

```
默认区域粒度：到街道/商圈一级
默认半径：1-3km
默认规模门槛：不限
默认优先输出：A 级置顶 + 按距离/街道聚类
```

引导话术（跑完后用）：
> 「已按默认参数生成。要不要调整：半径改 2km？只要 A 级？排除连锁品牌？指定特定商圈？」

## 十四、迭代与维护机制（本技能的核心约定）

> 本技能是**持续进化型技能**，不是一次性交付物。

### 触发方式

用户在每次使用后，只要提出「新的想法 / 更好的流程 / 要补的能力」，即触发迭代：

- 「下次半径默认改成 2km」
- 「模式 B 要能排除连锁品牌」
- 「电话话术要分行业给，不要通用套话」
- 「加一个导出 PDF 的功能」

用户无需提供文档格式，也无需自己维护文件——**一句话即触发沉淀**。

### 沉淀动作（Agent 必须执行）

1. **定位**：判断该建议属于哪个章节（检索策略 / 字段规范 / 分级 / 输出 / 流程 / 新增章节）
2. **写入**：直接编辑 `SKILL.md` 对应位置，保持与既有内容风格一致
3. **记版本**：在下方「版本历史」追加一行，注明版本号、日期、变更内容
4. **回报**：向用户说明改了哪一节、改成什么，附新版文件

### 沉淀原则

| 原则 | 说明 |
|------|------|
| 只增不覆盖 | 原有有效规则默认保留；确需推翻时，先说明理由再改 |
| 经验优先 | 来自实际跑单踩坑的修正，优先级高于理论推演 |
| 保持可用 | 每次迭代后技能必须仍可独立运行，不引入未声明依赖 |
| 可回溯 | 版本历史必须完整，任何一版都能看出改了什么、为什么改 |
| 跨模式生效 | 若建议同时适用于模式 A/B，两处都要改，不可只改一处 |

### 迭代来源（经验从哪来）

- 用户跑完后的口头反馈（主要来源）
- 实际执行中发现的失败模式（如某渠道抓不到、某字段常缺失）
- 关联企业识别的新规律（如新发现的同实控人判定特征）
- 分级标准的实战校准（如某类信号实际不代表采购动机）
- 输出格式的可用性反馈（如手机上看不清、打印不方便）

### 实战反馈回流清单（跑街过程中带回这些，Agent 按表校准）

| 反馈类型 | 用户带回什么 | Agent 沉淀到哪 |
|---------|-------------|--------------|
| 命中率 | 哪家实际存在 / 已搬迁 / 电话空号 / 已停业 | 去重校验规则、数据时效提示措辞 |
| 人员口径 | 实际见到谁、真实决策人是谁、前台挡人的原话 | 联系人字段来源优先级、破冰话术 |
| 分级校准 | 哪家被高估/低估、哪类信号实际不代表采购动机 | 第六节潜力分级标准 |
| 路线实录 | 门牌对不上、园区真实出入口、哪段步行远超预估 | 第三节路线编排规则与距离估算系数 |
| 话术命中 | 哪句话打开局面、哪句被直接拒绝 | 话术库，按企业类型/行业分档 |

**回流纪律**：用户回传一条即沉淀一条，不攒批、不等「完整报告」；每条沉淀必须在版本历史留痕。

## 十五、上架与分发准备（技能产品化）

> 触发条件：用户明确表示要上架/打包/分发时执行；未触发时只在跑单中持续沉淀。

### 上架前置条件（未满足不上架）

1. 至少 3 次真实跑单验证（模式 A ≥1 次、模式 B ≥1 次）
2. 有实测的字段完整率与电话覆盖率数据
3. 话术库有实战命中记录（哪类话术对哪类企业有效）

### 打包规范

- **根目录 SKILL.md**：YAML 前置含 `name` + `description`；description 必须覆盖用户口语触发词（扫街/陌拜/地推/拜访路线/周边企业等）
- **scripts/**：附 `build_roster.py` 等脚本，注明运行方式
- **README**：使用示例、输入参数、输出物说明
- **依赖声明**：无未声明外部依赖；若依赖 MCP（如百度地图），必须在文档中标注为「可选增强」并附降级路径
- **产物形态**：`.zip` 或 `.skill` 文件，根级含 SKILL.md

### 上架纪律

- 所有客户信息（企业名、电话、联系人）**仅存在于运行时产出**，**严禁**打包进技能分发包
- 技能包内只含方法论与脚本，不含任何真实名单数据

#### 脱敏规范（上架前必做）

技能交付时，SKILL.md 本身也必须经过脱敏扫描，确保不携带任何可识别信息。

| 检查项 | 标准 | 替换规则 |
|--------|------|---------|
| 企业名称 | 全部改为「示例企业 A/B/C」或「某科技有限公司」 | 含「有限公司」「技术」「实业」「制造」且 ≥15 字 → 替换 |
| 地址 | 全部改为「示例街道」「某产业园 X 栋」 | 含具体门牌号/路名/园区名 → 替换 |
| 电话 | 全部改为 "（座机）" 或 "（手机号）" | 11 位手机号 / 8 位座机 → 替换 |
| 坐标 | 删除或替换为 "（坐标占位）" | 经纬度数字 → 替换 |
| 人名 | 删除 | 中文人名（2-4 字）→ 替换为 "（联系人）" |

**脱敏流程**：写入建议后扫描全文件 → 修复疑似真实名称 → 用户确认。技能迭代时**先脱敏再归档**。

**扫描范围（全量覆盖，不留死角）**：正文示例、参数表格、场景举例、版本历史、脚本注释。扫描手段以正则匹配为准 —— 手机号（11 位）、座机（0xx-xxxxxxx）、经纬度（小数≥4 位且成对出现）、门牌号（数字+号）、区/街道/镇名、园区/大厦名，共六类；命中后逐条确认匹配唯一再替换，**禁止**批量模糊替换，替换完成后必须复扫验证。

**示例地名写法**：统一使用「XX 市 XX 区 XX 街道 XX 号」「某产业园 X 栋」，不得写入任何真实区名、街道名、路名、园区名、门牌号。

**正确做法**：技能文件应该包含方法论、流程、模板、判断逻辑、字段规范、行业关键词表。示例数据只用于演示流程（如「示例企业 A」），不违反脱敏原则。

**错误做法**：技能文件中出现任何具体企业名称、地址、电话、坐标、人名，无论是否来自历史跑单数据。

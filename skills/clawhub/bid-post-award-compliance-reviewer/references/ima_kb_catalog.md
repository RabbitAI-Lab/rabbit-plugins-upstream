**自动判断逻辑**：新库名称或描述命中 ≥2 个纳入词，且不含任何排除词，则自动纳入本会话清单；命中任一排除词则跳过。纳入后按功能优先级进入路由表。

> 实践教训：本账户「我发布的」库曾混入「软考/精益制造」等无关库。若不做排除，检索会污染合规结论。**切勿假设「我发布的库都是招投标/履约相关」。**

### 3.3 KB-L 降级行为（每轮重试 + 显式标注 + 恢复提示）

- KB-L 为**可选案例库**：如已挂载，所有功能的「案例对照」优先走 KB-L；其检索失败 / 未挂载 / 返回空，**不中断主流程**，案例对照段标注「未检索到高度相似公开案例」。
- **每轮独立重试**：即便上一轮已标注 KB-L 不可用，本轮仍尝试检索 1 次，避免误判为长期不可用。
- **恢复提示**：若此前标注不可用、本轮重试成功 → 在【依据来源】首行主动提示：「法律案例库（KB-L）已恢复，类案推送功能已激活。」仅首次恢复当轮提示一次，避免反复打扰。
- **不可用标注**：重试仍失败 → 在【依据来源】末行显式标注，让用户知道「缺了这块信息」：
  > `注：法律案例库（KB-L）当前不可用，类案/处罚案例推送暂未激活。`
- 严禁用模型记忆脑补类案、伪造案号或裁判文书编号。

## 四、检索负载约束（重要）

- IMA `search_knowledge` 单次返回可达 **10 万+ 字符**。
- **只抽取** `title / introduction / highlight_content` 三类片段级字段，禁止整段灌入上下文。
- 使用 `cursor` 翻页（首页传 `""`），每库最多取前 2 页、每条目截取前 800 字高亮。
- 并行检索上限 3 个库，避免 token 爆炸。

## 六、知识库使用铁律（知识治理层 · 固定基座）

本 skill 的知识治理规则作为检索融合与生成的硬性约束（已在 `system_prompt.md` 的 `<knowledge_governance>` 内注入运行时）。

**效力层级压制（两轴）**
- *法律位阶*：法律 > 行政法规 > 部门规章 > 规范性文件 > 实务口径。
- *来源优先级（跨库冲突采信）*：KB-A / KB-F 法规原文（按两法分轨择一优先）> KB-B 实战口径 > KB-T / KB-C 示范文本（比对基准）；KB-L 类案仅作参考，不与法规结论冲突。
- *两法分轨*：政采项目 → KB-F 优先；招投标项目 → KB-A 优先；政采工程招标 → 变更程序引 KB-A、追加红线引 KB-F 第49条。

**铁律（强制）**
1. **强制溯源**：每条引用标注 `【KB代号】` + 条文号（或条目名）；带 ima 返回的角标 [n]。
2. **盲区熔断**：检索为空时声明「当前知识库无相关信息」，严禁用模型记忆脑补法条、案号、编号。
3. **区域差异标注**：涉及地方性规定时注明「以下为全国性规定，具体执行以项目所在地要求为准」。
4. **KB-L 降级显式标注**：KB-L 属于可选库（我加入的库）。如已挂载但不可用/返回空，或未挂载，在【依据来源】末行标注「注：法律案例库（KB-L）当前不可用/未挂载，类案/处罚案例推送暂未激活。」——禁止静默跳过、禁止脑补类案。
5. **案例真实 + 时效校验（KB-L）**：引用 KB-L 类案 / 处罚案例前，须确认其依据法规仍现行有效；已修订/废止法规对应的案例标注「⚠️ 历史参考」，不得单独作为风险结论。
6. **两法不混**：政采追加 → 引 KB-F 第49条；工程变更程序 → 引 KB-A / 招投标法；政采工程招标 → 变更程序引招投标法、追加红线引政采法。
7. **阈值必算 + 进度条**：涉及金额/比例/时限 → 具体数字 + 百分比 + 进度条（见 output-templates.md）。
8. **ima 连接器整体不可用 → 降级内置库**：声明「知识库检索不可用，仅依据内置法规快照（references/knowledge-base.md）作答，建议复核最新规定」，不编造；不静默假装联网。

> 实践教训：纯靠「ima 统一召回 + 模型事后噪音屏蔽」会被混入的无关库污染；本 skill 在**检索层**用固定白名单 + INCLUDE/EXCLUDE 过滤，在**融合层**用铁律二次把关，双层防护。

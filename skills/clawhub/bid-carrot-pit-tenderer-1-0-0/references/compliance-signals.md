# 合规风险信号标尺（发标自检检测引擎核心）

本文件是 SKILL.md §3 的**完整展开**，与「招采萝卜坑识别专家」的 `carrot-pit-signals.md` **同源、9 类一致**，但本版**立场翻转**——每条从"招标人会被投标人质疑什么"的角度重写，并新增"会被质疑的理由"与"整改方向"两列，供 §4 第四部分生成可落地改写方案。

扫描招标文件全文时，**9 类信号必须逐类过**，不得只看"品牌指定"这类明显项，也不得漏掉"不违规但易被异议"的资金门槛（信号 9）。

> ⚠️ **时效性**：本标尺整理截止 **2026-07**，法规/行业惯例可能变化。每条输出须附法条核验提示（见 `legal-anchors.md`），结论以现行有效法 + IMA 知识库核实为准。

---

## 信号 1 · 品牌/型号排他

| 项目 | 内容 |
|---|---|
| **表现形式** | 直接写品牌名/型号；"或相当于"但限定家数；指定原厂授权/独家代理；指定特定专利、专有技术、软件著作权 |
| **一秒特征** | "XX品牌""限3家以内""原厂授权书""唯一代理""专利号ZL…" |
| **会被质疑的理由** | 投标人会异议"限定品牌/原厂/家数"违反"不得以不合理条件限制排斥潜在投标人" |
| **整改方向** | 删"限家数/原厂"，改"品牌不限，技术参数如下…"；专利/软著仅在确属项目必需且无法用参数描述时保留，并加"或同等技术" |
| **风险** | 🔴 高危（直接指定品牌/唯一授权属 A 真违规，必改） |

**⚠️ 高频变体（v1.3.0 · 来自真实标书数据）："须为同一品牌"跨多子系统绑定**
- **表现**：在多个子系统/平台/软件处分别写"须为同一品牌"（如电子认证中台/证书注册系统/在线签约系统/可信电子凭证管理系统须同品牌）。
- **会被质疑**：把"技术兼容"包装成"排他"——投标人异议"跨系统强制同品牌=变相指定单一厂商"。
- **整改方向**：改"各子系统须满足互操作接口标准（如 XX 协议），品牌不限"；保留真实互操作需求，删排他绑定。
- **净读技巧**：试着删掉"须为同一品牌"四字，看功能是否真的受损？若仅靠接口/标准即可互操作，则该绑定纯为排他，必改。

## 信号 2 · 资质/认证组合排他

| 项目 | 内容 |
|---|---|
| **表现形式** | 多个非必要认证/资质叠加（ISO9001+ISO27001+特定行业认证+特定协会证书）；要求特定地域性认证 |
| **一秒特征** | "须同时具备 A、B、C 三类认证"；"须为 XX 协会会员" |
| **会被质疑的理由** | 投标人异议"多项认证与履约无关、叠加后排斥潜在投标人" |
| **整改方向** | 逐项论证相关性：无关则删；有关但非独家则改"或同等资质"；协会证书原则上删（非法定资质） |
| **风险** | 🟠 中危（需论证相关性）；若明显无关叠加 → 🔴 |

**⚠️ 涉密资质映射（v1.3.0）：涉密资质属"法定、与履约强相关"资质，不按"普通认证堆叠"处理**
- **表现**：「投标人须具备涉密信息系统集成甲级/乙级资质」。
- **判定**：若项目确属涉密（用户提供需求基准）→ 该资质与履约真实相关，归 §2.6 **C 合理门槛**，保留并在第六部分备论证；**不得**当普通"资质排他"要求删除。
- **整改方向**：仅当项目不涉密却要求涉密资质时，才属 A 真违规，须删除或改"同等保密能力证明"。

## 信号 3 · 业绩门槛量身

| 项目 | 内容 |
|---|---|
| **表现形式** | 特定金额 + 特定甲方类型 + 特定时间段 + 特定规模 **多条件叠加**；业绩要求与项目本身规模明显错配（过高或过于具体） |
| **一秒特征** | "近3年单项≥5000万且为省级政务云且用户≥100万" |
| **会被质疑的理由** | 投标人异议"特定甲方类型/规模三条件∩精准筛极小集合，实为量身定做" |
| **整改方向** | 放宽口径：金额降档或改"累计"、删"特定甲方类型"、规模用区间；以"本项目预算/规模"为基准论证合理性 |
| **风险** | 🔴 高危（多条件叠加指向性），多为 B 表述不当可改写 |

## 信号 4 · 人员/设备门槛

| 项目 | 内容 |
|---|---|
| **表现形式** | 要求与项目规模不匹配的大量高工/特定注册证书；设备清单精确指向某品牌型号 |
| **一秒特征** | "须配 10 名高级工程师""须具备 XX 品牌某型号检测设备" |
| **会被质疑的理由** | 投标人异议"人员数量/证书远超履约必需、设备写死品牌型号" |
| **整改方向** | 人员按"实际工作量"测算最低必要数；设备写技术参数而非品牌型号；确需特定设备的说明唯一性理由 |
| **风险** | 🟠 中危；若明显超过必需且指向特定团队/设备 → 🔴 |

## 信号 5 · 技术参数量身（最隐蔽、最高发区）

| 项目 | 内容 |
|---|---|
| **表现形式** | 参数值带**异常精确小数点**（3.27GHz、28.5MB）；非标参数/冗余功能堆砌；关键技术指标只有一家满足；检测方法/验收标准指向特定厂商 |
| **一秒特征** | "主频 3.27GHz""支持 XX 私有指令集""须采用 XX 厂检测方法" |
| **会被质疑的理由** | 投标人异议"精确值/私有协议=变相指定某产品，偏离表无法响应" |
| **整改方向** | 通用参数给**区间/范围**（≥3.2GHz）；私有指令集改"支持等效指令集"；删冗余功能；检测方法用国标/行标而非指定厂 |
| **风险** | 🔴 高危（精确值/私有协议指向产品），多为 B 表述不当可改写 |

> 实战经验：技术参数与服务要求章节是合规风险密度最高的地方。扫描此章须逐条核对"是否给区间""是否非标私有"，把"过死参数"改写为"合规且同等有效"的区间/等效表述。

## 信号 6 · 评标办法倾向

| 项目 | 内容 |
|---|---|
| **表现形式** | 主观分畸高且标准模糊（"优者满分"无档位）；加分项指向性（本地化、特定案例、特定荣誉、特定用户推荐信） |
| **一秒特征** | "本地企业加 3 分""有 XX 类项目案例加 2 分""获 XX 奖项加 1 分" |
| **会被质疑的理由** | 投标人异议"主观分无量化档位=自由裁量过大、加分项指向特定经历" |
| **整改方向** | 主观分按 87 号令第55条细化量化档位；加分项限"与履约真实相关"，删除纯荣誉/特定地域加分 |
| **风险** | 🟠 中危；主观分畸高+模糊 → 🔴 |

## 信号 7 · 合同条款排他

| 项目 | 内容 |
|---|---|
| **表现形式** | 特定付款条件/履约担保异常；验收标准指向特定方；争议管辖地异常指向 |
| **一秒特征** | "须预付 80%""验收须由 XX 机构出具""争议由 XX 地法院管辖" |
| **会被质疑的理由** | 投标人异议"付款/担保显著偏离惯例、验收方非中立、管辖地刻意选甲方主场" |
| **整改方向** | 付款/担保调至行业惯例；验收用双方认可或第三方中立机构；管辖地按法定或公平原则 |
| **风险** | 🟠 中危；若显著偏袒且非必需 → 🔴 |

| 项目 | 内容 |
|---|---|

## 信号 9 · 商务/资金隐性门槛（不违规但易被异议排中小企）

| 项目 | 内容 |
|---|---|
| **表现形式** | 异常高额履约/投标保证金；0 预付款或超长账期后付；要求特定银行授信额度证明；要求垫资施工/供货 |
| **一秒特征** | "履约保证金 500 万""预付款 0%""须提供 XX 银行授信证明""须垫资" |
| **会被质疑的理由** | 投标人（尤其中小企）异议"金额/比例显著偏离行业惯例、排斥资金链薄弱者" |
| **整改方向** | 调降至行业惯例（保证金≤合同额10%、预付款10%~30%）；确需特殊的说明项目背景并在 §4 第六部分备论证 |
| **风险** | 🟠 中危（软排斥，多为 B 表述不当可调）；若叠加其他量身条款 → 组合上调 |

> 实战经验：资金门槛藏在"合同条款/投标人须知"里，不显眼但最易被中小企异议。它通常不违反明文规定，但招标人应主动调至惯例区间以降异议风险，而非"反正没违规就不动"。

## 组合风险推理规则（信号 2.4 配套）

- **外观量身论证法**：把命中的多条线索按"共同指向特征"聚类。若簇内条款**单独看各有合理借口、合起来让投标人觉得指向单一供应商**，则整体定级上调一档（如孤立 🟠 升为组合 🔴），并在 §4 第三部分论证"为何易引发异议"。
- **规模错配基准**：判断"业绩/人员/参数是否过高"时，以"本项目预算/规模/实际技术需求"为基准，明显超出即疑似错配。
- **不强行拼凑**：无共同指向的孤立线索按单条处理，不得为凑"组合"而硬关联。

---

## 合理性评估配套（信号 2.6 配套 · 本技能独有）

每条命中除风险定级外，还须做 §2.6 三分类（A 真违规 / B 表述不当 / C 合理门槛）：
- **A 真违规**：纯粹排斥、与履约无关 → 第四部分给"原句→建议句"直接改写。
- **B 表述不当**：需求合理但写法惹疑 → 第四部分给"宽口径改写"，保留真实需求。
- **C 合理门槛**：需求与履约真实相关、有依据 → 第六部分备论证，被异议时合法答辩（**绝不**把 A 类包装成 C 类）。

## 疑难 Few-Shot（校准"合理需求 vs 违规"边界）

**FS-1 · 限定品牌（真违规，必改）**
- 原文：「须为 XX 品牌原厂，或相当于（限 3 家以内）。」
- 误判：当"有或相当于"放过，或归为合理需求。
- 正解：限"3 家以内"实质收窄竞争=排他 → 🔴，A 真违规；建议改"品牌不限，技术参数如下…"保留真实需求。法条 招投标法第20条 + 实施条例第32条。

**FS-2 · 涉密资质（合理门槛，保留+备论证）**
- 原文：「投标人须具备涉密信息系统集成甲级资质。」
- 误判：当普通"资质排他"要求整改删除。
- 正解：若项目确属涉密（用户提供需求基准），该资质与履约真实相关 → C 合理门槛；保留，第六部分备论证"源于涉密属性+已为必要最小限制"，被异议时合法答辩。

**FS-3 · 业绩三条件叠加（表述不当，可改写）**
- 原文：「近 3 年单项合同金额 ≥ 5000 万元，且为省级政务云项目，且用户数 ≥ 100 万。」
- 误判：只看"5000万"觉得正常，或当成合理门槛不提示。
- 正解：三条件∩精准筛极小集合=高度疑似量身 → 🔴/🟠，B 表述不当；建议改"近3年类似规模政务信息化项目，单项≥3000万或累计≥8000万"，放宽口径降异议风险。

**FS-4 · 主观分畸高且模糊（评标办法）**
- 原文：「技术方案 30 分，由评委根据'先进性、合理性'自主打分，未细化档位。」
- 误判：当正常主观分。
- 正解：占比畸高且无量化档位=自由裁量过大、易引异议 → 🟠，87号令第55条；建议补"优/良/中/差"对应档位与打分区间。

**FS-5 · 异常资金门槛（表述不当，调至惯例）**
- 原文：「中标后 7 日内缴纳 500 万履约保证金，预付款 0%，按季度后付。」
- 误判：当普通商务条款放过（"又没违规"）。
- 正解：金额畸高+0 预付+长账期叠加，易被异议"排斥中小企"=软排斥 → 🟠，B 表述不当；建议调降至行业惯例（保证金≤10%、预付款10%~30%），或说明项目特殊性并在第六部分备论证。

**FS-6 · 同品牌跨子系统绑定（真违规，必改 · 来自真实标书数据）**
- 原文：「电子认证服务中台、证书注册系统、在线签约系统、可信电子凭证管理系统……须为同一品牌。」
- 误判：只看单一系统觉得"技术兼容要求合理"放过。
- 正解：跨多子系统强制同品牌=把兼容包装成排他 → 🔴，A 真违规；改"各子系统须满足互操作接口标准，品牌不限"，保留互操作需求删排他绑定。净读：删"须为同一品牌"功能是否受损？仅接口即可互操作则纯排他。

**FS-7 · 内部矛盾（文件自身逻辑不自洽 · v1.3.0）**
- 原文：「本项目接受联合体投标」+「核心系统须为同一品牌。」
- 误判：两句各看都"合规"漏掉冲突。
- 正解：联合体由多家独立供应商组成无法满足同品牌 → 自相矛盾变相锁标（矛盾 A）；整改二选一：放开同品牌约束，或删"接受联合体"改单一来源并说明理由。

**FS-8 · 政务云/算力四维拼图（组合量身 · 来自真实标书数据）**
- 原文：「用户数≥10000、并发通道≥20000、须具备 ITSS 认证、投标保证金 2 万」+ 异常精确参数值 48 处。
- 误判：单看"ITSS 认证""保证金"觉得常规。
- 正解：精确参数(5)+规模限定(3)+特定认证(2)+资金门槛(9)四维叠加，外观高度疑似为某政务云厂商量身 → 🔴/🟠；整改：参数给区间、规模用"本项目实际"、认证改"或同等"、保证金核减，第六部分备合理性论证。

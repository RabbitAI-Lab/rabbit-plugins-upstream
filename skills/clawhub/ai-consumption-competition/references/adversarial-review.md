# 对抗式审查完整清单

## 审查框架概述

对抗式审查模拟评审委员会的5种不同视角，对用户报名方案进行交叉质疑。每个视角独立提出最尖锐的问题，最终汇总为风险分级表。

**审查原则**：
- 每个视角至少提出1条"最尖锐"的质疑（评委最可能用来淘汰项目的理由）
- 质疑必须具体到项目层面，不能是泛泛而谈
- 改进建议必须可执行，不能只是"加强XX"的空话
- 风险等级基于"如果不解决会怎样"来判断

---

## 视角1：技术专家（质疑技术壁垒）

### 审查清单

- [ ] **AI不可替代性**："你的项目如果不用AI，用传统规则引擎/人工流程能不能实现？如果能，AI的价值在哪？"
- [ ] **技术壁垒**："你的AI技术和现有开源方案（如LangChain+GPT-4 API调用、HuggingFace模型微调）有什么本质区别？"
- [ ] **护城河持久性**："如果大模型厂商明天免费提供你依赖的能力，你的护城河在哪里？"
- [ ] **技术指标量化**："你的技术指标（准确率/延迟/成本/吞吐量）是否有第三方验证或可复现的测试数据？"
- [ ] **数据飞轮**："模型上线后是否有持续数据输入机制？没有持续数据，模型效果会退化吗？"
- [ ] **工程化程度**："从Demo到规模化部署，中间还有哪些工程难题未解决？"

### 风险等级判断标准

| 等级 | 标准 |
|------|------|
| 高 | 项目只是API套壳，无自研技术；或核心技术指标无法量化 |
| 中 | 有一定自研技术但壁垒不深；技术指标有但缺乏第三方验证 |
| 低 | 有明确技术壁垒（自研模型/独特数据/专利算法），指标可量化可验证 |

### 常见改进建议

- 补充技术架构图，明确自研部分与第三方依赖的边界
- 提供Benchmark对比数据（与开源方案/竞品对比）
- 说明数据飞轮机制：用户使用如何反哺模型优化
- 如有专利/论文，在附件中提供

---

## 视角2：商业评委（质疑商业可行性）

### 审查清单

- [ ] **付费意愿**："用户为什么愿意付费？付费意愿是否有实际验证（而不只是问卷调研）？"
- [ ] **单位经济模型**："获客成本（CAC）和用户生命周期价值（LTV）的比值是多少？LTV/CAC是否>3？"
- [ ] **市场规模验证**："这个市场规模是自上而下估算的（行业报告×渗透率）还是自下而上验证的（已有客户×客单价）？"
- [ ] **竞争格局**："行业头部玩家如果做同样的事，你的时间窗口有多长？你的防御策略是什么？"
- [ ] **收入可持续性**："收入是一次性的还是持续性的？续费率/复购率如何？"
- [ ] **大赛依赖度**："如果没有获奖，项目的下一步计划是什么？是否过度依赖大赛资源？"

### 风险等级判断标准

| 等级 | 标准 |
|------|------|
| 高 | 无付费验证；CAC>LTV；市场规模纯估算无验证 |
| 中 | 有初步付费数据但单位经济模型未跑通；市场规模部分验证 |
| 低 | 有清晰的付费验证；LTV/CAC>3；市场规模自下而上验证 |

### 常见改进建议

- 在商业化数据中补充CAC和LTV数据
- 提供2-3个标杆客户案例（含使用效果数据）
- 说明续费/复购机制
- 在项目简介中体现不依赖大赛的发展路径

---

## 视角3：消费者（质疑用户体验）

### 审查清单

- [ ] **价值可感知性**："普通消费者能理解你的产品价值吗？需要多少教育成本？"
- [ ] **使用门槛**："使用门槛高不高？老年人/儿童/非技术用户能用吗？"
- [ ] **替代方案比较**："相比现有替代方案（包括不用AI的传统方案），用户体验提升是否显著到值得切换？"
- [ ] **隐私担忧**："用户会不会因为隐私担忧而拒绝使用？你的隐私保护措施用户能感知到吗？"
- [ ] **情感依赖风险**："（陪伴类产品）用户会不会过度依赖AI？断电/故障时的情感落差如何处理？"
- [ ] **实际使用场景**："用户在什么具体场景下会拿出你的产品使用？频率多高？每次多长时间？"

### 风险等级判断标准

| 等级 | 标准 |
|------|------|
| 高 | 价值难以感知；使用门槛极高；无显著体验提升 |
| 中 | 价值需一定教育才能理解；门槛中等；有提升但不够显著 |
| 低 | 价值一句话能说清；低门槛使用；体验提升显著且可感知 |

### 常见改进建议

- 在项目简介中用"用户语言"描述价值（避免技术术语）
- 提供真实用户使用视频/截图作为附件
- 补充用户调研数据（NPS/满意度/使用频率）
- 说明降低使用门槛的具体设计

---

## 视角4：合规审查（质疑风险）

### 审查清单

- [ ] **数据采集合规**："数据采集是否获得用户明确授权？隐私政策是否完整覆盖数据用途？"
- [ ] **未成年人保护**："如果涉及未成年人（陪伴机器人/教育产品），是否符合《未成年人保护法》和《未成年人网络保护条例》？"
- [ ] **AI生成内容版权**："AI生成的内容（图片/视频/文本）是否存在版权风险？训练数据来源是否合规？"
- [ ] **伦理风险**："是否涉及情感操控、诱导依赖、信息茧房等伦理风险？特别是赛道1情感陪伴机器人"
- [ ] **算法备案**："如涉及深度合成/生成式AI服务，是否已完成算法备案？"
- [ ] **数据出境**："如涉及数据跨境传输（外资团队/全球化赛道），是否符合数据出境规定？"

### 风险等级判断标准

| 等级 | 标准 |
|------|------|
| 高（致命） | 涉及未成年人但无保护措施；未做算法备案（应备案项目）；存在明显伦理风险 |
| 中 | 数据合规有缺口但可补救；算法备案进行中尚未完成 |
| 低 | 已通过数据安全评估；已完成算法备案；伦理风险评估有据可查 |

### 特殊赛道合规要求

| 赛道 | 特别关注 |
|------|---------|
| 赛道1-智能情感陪伴机器人 | 伦理风险（诱导依赖/情感操控）、未成年人保护 |
| 赛道1-智能穿戴与健康消费 | 医疗器械资质（如涉及健康诊断）、个人信息保护 |
| 赛道2-AI+教育教学 | 未成年人保护、教育内容审核 |
| 赛道2-AI+养老健康服务 | 医疗数据合规、老年人权益保护 |
| 赛道3-AI+品牌营销 | AI生成内容版权、广告法合规 |
| 赛道3-AI+消费企业全球化 | 数据出境合规、目标市场法规 |

### 常见改进建议

- 在数据合规说明中详细描述未成年人保护措施（如适用）
- 如已启动算法备案，在附件中提供备案截图
- 补充伦理风险评估说明（特别是陪伴类产品）
- 建议附数据安全评估报告

---

## 视角5：产业专家（质疑行业理解）

### 审查清单

- [ ] **行业深度**："你对目标行业的理解是否足够深入？是否只看到了表层痛点而忽略了行业结构性问题？"
- [ ] **竞争窗口**："行业头部玩家如果做同样的事，你的时间窗口有多长？"
- [ ] **资源支撑**："你的供应链/渠道/合作伙伴资源是否足以支撑落地？还是只有技术没有产业资源？"
- [ ] **政策依赖**："项目是否过度依赖政策红利？政策红利期过后，项目是否仍可持续？"
- [ ] **行业壁垒**："目标行业是否存在非技术壁垒（资质/牌照/渠道/品牌信任）？你如何突破？"
- [ ] **规模化路径**："从一个客户到一百个客户，你的边际成本是递增还是递减？"

### 风险等级判断标准

| 等级 | 标准 |
|------|------|
| 高 | 行业理解肤浅；无产业资源；过度依赖政策；规模化边际成本递增 |
| 中 | 有一定行业理解但不够深；部分资源已对接；规模化路径初步清晰 |
| 低 | 深入理解行业痛点；有核心产业资源；规模化路径清晰且边际成本递减 |

### 常见改进建议

- 在团队信息中突出具有行业背景的成员
- 在附件中提供行业调研报告或客户深度访谈记录
- 说明已对接的产业资源（合作意向书/渠道协议等）
- 在项目简介中体现对行业结构性问题的理解

---

## 风险汇总输出格式

对5个视角审查完成后，汇总为以下风险分级表：

```
## 对抗式审查风险汇总

| 风险等级 | 视角 | 关键问题 | 应对策略 | 是否需在报名材料中回应 |
|---------|------|---------|---------|----------------------|
| 致命 | [视角名] | [具体问题] | [可执行策略] | 是（必须回应） |
| 重要 | [视角名] | [具体问题] | [可执行策略] | 是（建议回应） |
| 一般 | [视角名] | [具体问题] | [可执行策略] | 否（附件补充即可） |
```

### 风险等级定义

| 等级 | 定义 | 处理方式 |
|------|------|---------|
| **致命** | 不解决此问题，项目大概率被淘汰 | 必须在报名材料中主动回应，否则不建议提交 |
| **重要** | 此问题是评委可能质疑的点，不回应会扣分 | 建议在项目简介或技术创新点中主动回应 |
| **一般** | 此问题存在但不影响核心评审 | 可在附件材料中补充说明，无需在正文中回应 |

### 致命风险常见类型

1. **AI套壳**：项目只是调用第三方API，无自研技术含量
2. **伪需求**：需求是技术驱动的，非真实消费场景
3. **合规缺失**：涉及未成年人/医疗/数据出境但无合规措施
4. **伦理风险**：陪伴类产品存在诱导依赖/情感操控且无应对方案
5. **组别错配**：原型阶段项目硬报应用组，无法提供商业数据

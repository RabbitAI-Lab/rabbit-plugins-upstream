# 报名表逐字段填写指南

## 报名表结构总览

报名表共7个部分，每部分字段与填写要求如下：

| 部分 | 字段数 | 核心要求 |
|------|--------|---------|
| 一、基本信息 | 5项 | 项目名称、组别、主体类型、联合申报、重点方向 |
| 二、核心信息 | 6项 | 项目简介、技术创新点、产品形态、阶段、商业数据、合规说明 |
| 三、团队信息 | ≥3人 | 负责人（必填）+ 核心成员 |
| 四、知识产权与法律声明 | 4项 | 均需勾选"同意" |
| 五、附件材料清单 | 6类 | 至少准备商业计划书+演示材料 |
| 六、签字/盖章 | 1项 | 团队成员签名/企业公章 |
| 七、提交方式 | — | 打包发送至官方邮箱 |

---

## 第一部分：基本信息

### 项目名称
- **填写公式**：`[品牌名/技术名] + [核心功能] + [产品形态]`
- **示例**：
  - "智伴AI情感交互陪伴机器人"（品牌+功能+形态）
  - "慧生活AI全屋智能管家系统"（品牌+功能+形态）
  - "数智商圈AI消费洞察平台"（品牌+功能+形态）
- **注意事项**：
  - 建议15字以内，简洁有力
  - 体现AI+消费特征，让非技术评委也能理解
  - 避免过度技术化命名（如"基于Transformer的多模态融合系统"）
  - 避免过于泛泛（如"AI智能平台"）

### 申报组别
| 选项 | 适用条件 | 注意事项 |
|------|---------|---------|
| 应用组（已商业落地） | 有实际用户/客户、有营收数据、已规模部署 | 必须填写商业化数据 |
| 创客组（创意/原型阶段） | 仅有原型/样品、无商业数据、处于验证阶段 | 商业化数据选填 |

**组别选择决策**：
```
项目当前阶段？
├── 规模化商用 → 应用组
├── 试商用/小规模落地 → 应用组（如有初步商业数据）
├── 原型验证 → 创客组
└── 创意构思 → 创客组
```

### 参赛主体类型
- 企业 / 高校院所 / 创业团队 / 个人开发者 / 外资或海外团队
- 据实选择，影响评审视角（企业重商业落地，高校重技术创新，个人重创意）

### 是否联合申报
- 如选"是"，需填写联合单位名称
- 联合申报建议：明确各方角色分工，在团队信息中注明各单位成员

### 项目所属重点方向
| 选项 | 对应一级赛道 |
|------|------------|
| AI消费·新产品（智能终端/穿戴/机器人/网联汽车） | 赛道1 |
| AI消费·新场景（居家/养老/文旅/教育/餐饮） | 赛道2 |
| AI消费·新模式（零售/品牌/电商/供应链/商业空间） | 赛道3 |

**注意**：
- 报名表标题为"'AI新消费'赛道报名表"，覆盖赛道1-3；重点方向为三选一勾选，须与 Step 3 推荐的一级赛道严格一致。
- **青少年创客赛道（赛道4/"AI新力量"）独立组织实施，不使用本报名表**——其参赛条件、报名方式、赛程安排、评审标准、奖项设置另行发布。遇到青少年参赛者，仅建议细分方向（AIGC/AI+编程/AI+绿色消费），并提示关注官方后续通知。

## 第二部分：核心信息

### 项目简介（300字内）

**结构模板**（总约300字）：

| 段落 | 字数 | 内容 | 示例 |
|------|------|------|------|
| 背景痛点 | ~50字 | 目标用户面临的核心问题 | "我国60岁以上老人超2.8亿，独居老人情感缺失问题日益突出..." |
| 解决方案 | ~100字 | 通过什么AI技术，实现什么功能 | "本项目基于多模态大模型与情感计算技术，打造具备情绪感知、自然对话和主动关怀能力的AI陪伴机器人..." |
| 目标用户 | ~50字 | 面向什么群体 | "面向独居老人、空巢家庭及养老机构..." |
| 应用场景 | ~50字 | 在什么场景下使用 | "在家庭日常陪伴、健康提醒、应急呼叫等场景下，机器人可主动发起对话..." |
| 核心价值 | ~50字 | 相比现有方案的优势 | "相比传统陪伴设备，实现情感识别准确率提升40%，日均交互时长增加3倍..." |

**填写要点**：
- 逻辑递进：痛点→方案→用户→场景→价值
- 数据支撑：尽量用量化指标替代定性描述
- 避免堆砌技术术语，评委可能非技术背景

### 技术创新点（200字内）

**结构模板**（总约200字）：

| 段落 | 字数 | 内容 | 示例 |
|------|------|------|------|
| AI技术栈 | ~80字 | 采用什么AI技术，实现什么能力 | "采用端侧大模型（7B参数量化部署）+ 多模态情感识别（CV+语音+文本三模态融合），实现低延迟离线对话和实时情绪分析..." |
| 原创性 | ~80字 | 与现有方案的区别，首创了什么 | "首创'情感记忆图谱'架构，实现跨会话情感状态追踪与个性化关怀策略生成，区别于市面单次对话式陪伴产品..." |
| 技术指标 | ~40字 | 量化指标 | "情感识别准确率92.3%，响应延迟<200ms，端侧推理成本降低60%..." |

**填写要点**：
- 必须说明AI技术的具体类型（大模型/CV/NLP/推荐算法/机器人控制等）
- 原创性要有对比参照（与什么方案比，区别在哪）
- 技术指标尽量量化，避免"显著提升""大幅降低"等模糊表述

### 产品或服务形态
- 原型/样品 / 实物产品 / 系统/平台 / 服务方案 / 模式创新案例 / 其他
- 据实勾选，可多选

### 当前阶段
- 创意构思 / 原型验证 / 试商用/小规模落地 / 规模化商用
- **关键**：阶段选择影响评委预期，不宜虚高
  - "原型验证"：有可演示的原型，但未实际部署
  - "试商用"：有小范围实际用户/客户
  - "规模化商用"：有稳定用户群和营收

### 商业化数据（应用组必填，创客组选填）

**建议格式**：
```
累计用户数：XX万
月活跃用户：XX万
累计销售额：XX万元
合作客户数：XX家
同比增长率：XX%
```

**数据不足时的替代指标**：
- 试点客户案例（如"已在XX养老机构试点，服务XX位老人"）
- 用户满意度（如"用户满意度调研得分4.5/5"）
- 留存率（如"30日留存率XX%"）
- 行业认证或获奖（如"获XX行业创新奖"）

### 数据合规说明（涉及数据采集/算法项目必填）

| 子项 | 填写要点 |
|------|---------|
| 数据来源 | 说明数据从何处获取（用户授权采集/公开数据集/合作方提供等） |
| 使用边界 | 说明数据用于什么目的，不用于什么目的 |
| 安全措施 | 具体技术手段（AES-256加密存储/差分隐私/匿名化处理/联邦学习等） |
| 合规情况 | 如实勾选：已通过数据安全评估 / 已备案 / 其他 |

**注意**：赛道1智能情感陪伴机器人、赛道2教育产品涉及未成年人数据，需特别说明未成年人保护措施。

## 第三部分：团队信息

| 角色 | 填写要求 | 建议 |
|------|---------|------|
| 项目负责人（必填） | 姓名、单位/学校、职务/年级、联系电话、邮箱、主要贡献 | 填写最核心的负责人，突出与项目相关的背景 |
| 核心成员1 | 同上 | 建议为技术负责人 |
| 核心成员2 | 同上 | 建议为产品/商业负责人 |
| 核心成员3 | 同上 | 可自行增行 |

**团队配置建议**：
- 应用组：建议覆盖 技术+产品+商业 三类角色
- 创客组：建议覆盖 技术+设计 两类角色
- 青少年赛道：可简化为1-2人

**主要贡献填写示例**：
- "负责大模型微调与推理优化，主导端侧部署方案设计"
- "负责产品定义与用户研究，完成市场调研与需求验证"
- "负责商业模式设计与客户拓展，已签约3家试点客户"

## 第四部分：知识产权与法律声明

四项声明均需勾选"同意"：

1. 本项目为原创，拥有合法知识产权，不存在权属争议 → □同意
2. 项目不涉及侵犯他人商业秘密、专利、著作权等 → □同意
3. 参赛主体无严重失信记录，遵守法律法规及赛事规则 → □同意
4. 同意大赛组委会对项目材料进行宣传展示（不涉及核心商业秘密）→ □同意 / □仅限评审使用

**知识产权归属说明**：如有专利/软著/商标，请附证书号。

**注意**：第4项可选"仅限评审使用"如项目涉及核心商业机密。

## 第五部分：附件材料清单

| 附件类型 | 重要性 | 建议内容 |
|---------|--------|---------|
| 商业计划书/项目方案（PDF） | ★★★ 必备 | 项目背景、方案、市场、团队、财务预测 |
| 产品原型/实物照片/演示视频 | ★★★ 必备 | 3-5分钟演示视频，展示核心功能和使用场景 |
| 系统演示或应用成果截图 | ★★☆ 推荐 | 界面截图、数据看板、用户反馈截图 |
| 知识产权证明 | ★★☆ 推荐 | 专利证书、软著登记证、商标注册证 |
| 数据合规相关文件 | ★☆☆ 视情况 | 安全评估报告、备案截图（算法项目必备） |
| 其他辅助材料 | ★☆☆ 视情况 | 客户案例、测试报告、获奖证明、合作协议 |

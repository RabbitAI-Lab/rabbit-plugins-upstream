# 组成部分：一个系统由什么构成

> **何时读**：一个系统要有文字之外的东西了（一段脚本、一份数据、一条通向某个工具的连接）；你在盘点这个人已经有什么；需要判断一个部分值不值得加；或者读者需要知道一个系统的文件各是做什么用的。

**系统的核心是自然语言。其余部分，是系统为了行动所需要的一切。**

| 部分 | 是什么 | 例子 |
|---|---|---|
| **核心** | 系统是什么、认识到了什么、使用哪些实践、怎样使用、其他每个部分做什么 | `SYSTEM.md` 入口、认识、实践记录、盯住的条件、两份认识记录 |
| **代码** | 它能执行的东西 | 刷新数据的脚本、分析笔记本、视频工程、小工具 |
| **数据** | 它以结构化形式掌握的东西 | 来源快照、时间线、表格、测得的结果 |
| **连接** | 它能触达的东西 | Skill、MCP 服务、API、命令行工具、设备、协作者 |
| **成果** | 它已经产出的东西 | 网页、视频、文档、演示稿、分享包，放在这个人的工作区里 |

## 各部分之间的关系

- **核心描述其余每个部分。** 对每段脚本、每份数据、每条连接，核心都说明它做什么用、怎样用、需要什么、最后一次确认能用是什么时候。核心没有描述的部分，下一位读者是看不见的，无论是人还是 AI。
- **各部分在真实任务需要时才出现。** 一个概念的系统，可能永远只有一个文件。不要预先建 `code/`、`data/` 或 `connections/` 文件夹。结构跟着内容走。
- **自然语言优先。** 写代码之前先问：一段清楚的描述，能不能让一个有能力的 AI 下次做成同样的事？当任务必须被精确地重复、需要计算，或者必须在没有 AI 在场时运行，代码才值得出现。
- **OpenXSys Skill 本身保持自然语言。** 代码属于这个人的系统，从不属于运行时。

## 代码

- **在这个人知情的情况下运行。** 一段脚本第一次运行之前，说明它做什么，以及它会读什么、写什么。
- **始终可以检查。** 朴素、可读的源码，放在这个人的空间里。没有混淆过的东西，也没有悄悄下载下来就执行的东西。
- **说明它需要什么。** 运行环境、输入、凭据的引用（见下）、预期的输出。
- **经过验证。** 核心记下这段代码在什么上运行过、结果如何。从没运行过的代码是草稿，并且标明是草稿。
- **定时运行由这个人决定。** 自己反复运行的代码，只在这个人同意之后才设置，并附上怎样停掉它。

## 数据

- **带着出处。** 它从哪里来，什么时候取的，经过了怎样的处理。一张没有来源的表是负担。
- **是快照，不是悄悄的副本。** 来源可能变化时，留一份带日期的快照并说明，让入口写明认识截至何时成立。
- **测得的结果也是数据。** 一项实践的结果（之前和之后，带日期）是系统里最有价值的东西之一：正是它们，让一项实践可以由结果来评价。
- **只有这个人允许的。** 来自这个人自己的文件和账号的数据，只在这个人许可的范围内记录，并且从不包含密钥，也不包含关于这个人或别人的敏感个人信息。

## 连接

一条连接，是对系统能触达的某样东西的引用，连同它让什么成为可能。

- **只存引用，从不存密钥。** 连接写明工具、账号或接口的名字，并说明凭据由这个人保存在哪里（一个环境变量的名字、密码管理器里的一个条目）。它从不包含密钥、令牌或密码。工作中看到了密钥，不要把它写进系统的任何地方。
- **写明它让什么成为可能。** “接上了分析后台的导出：每周留存率现在可以重新计算，不用手动下载”是一条连接。“使用分析后台”不是。
- **写明它的状态。** 最后一次成功使用是什么时候，它依赖什么。
- **协作者也是连接。** 一个帮忙看稿的人、一个拥有某份数据的团队，都可以记为连接，只限于这个人自己说过的内容，以及对系统重要的内容。联系任何人，永远由这个人决定。

## 盘点：这个人已经有什么

系统开启时，盘点已经有的东西：

- 宿主列出的 Skill；
- `~/.claude/skills/`、`.agents/skills/` 等 Skill 文件夹，以及项目自己的；
- MCP 服务以及它们提供的工具；
- 宿主内置的工具（搜索、浏览、执行代码、生成图像、子代理）；
- 已有的运行环境（Node.js、Python）和内置依赖（见 `deps/DEPENDENCIES.md`）。

它们成为这个人系统里的**连接**。这个人自己的工具比内置的更合适时，用这个人自己的：一位已经有视频流程的创作者，应该让自己的流程被用上，而不是被替换。

盘点读的是清单、名字和描述。**它从不读取密钥**：不读凭据文件，不读环境变量的值，不读配置里的令牌。如果一个配置文件把设置和密钥混在一起，只读到足以知道一个工具存在为止。

盘点悄悄地做，只报告对这次运行重要的内容：“你已经装了一个做演示稿的 Skill，所以这份演示稿用的是它”有用；一份完整的清单是仪式。把找到的东西记进根系统，免得每次会话都重来；有相关的变化时再刷新。

## 成果

成果放在这个人的工作区里，按这个人组织东西的方式组织。系统指向它们：每一份在哪里，展示了什么，建立在哪份认识和哪些来源上，以及它的分享包（如果做了的话）。这个人亲手改过的成果是这个人的；系统记下以这个人的版本为准。

## 判断要不要加一个部分

下面任何一个问题的答案是“是”，就加：

- 这件事还会再做吗？手工做是不是要花真实的时间，或者有出错的风险？
- 这份认识是不是建立在会变化的数据上，因而刷新必须是可重复的？
- 一项实践是不是需要某样东西在没有 AI 在场时运行？
- 不加的话，下一个 AI 是不是得从零重建它？

一个部分不再被使用时，把它去掉，或者在核心里标明已经退役。一个堆满了没人用的脚本和过时表格的系统，变得更难接着做了，这和系统存在的目的正好相反。

# 演化：让经历改变接下来的事

> **何时读**：有东西值得留下，或者系统需要改变：一份认识被修正，一种做法证明了自己，两个系统被发现有联系，这个人的目标变了，一份成果完成了；或者系统变得冗长、陈旧，需要简化。

实践产生结果。结果成为实践与能力。能力组织成系统。系统之间的连接产生新的能力。这条链不只会增长：无用的要去掉，复杂的要简化。

系统的演化，不由它记下了多少来衡量。它由**它接下来能做什么**来衡量。每一次写入只用一个问题来判断：**下一次运行，会因此而不同吗？** 会，就写。不会，就不写。

## 它做什么

- **目的**：让经历改变未来。
- **什么时候需要**：一份认识被修正；一项实践证明了自己；出现一条连接；目标改变。
- **好是什么样**：改写，而不只是追加；实践可以被加载和使用；连接写明它让什么成为可能。系统变得更准、更有能力，而不是更长。

## 系统怎样生长

**改写；不要只是追加。** 新的认识替换旧的。入口读起来永远是“当前最好的认识”，而不是一段认识的历史。只保留真正的转折：曾经以为什么，后来发现什么，因为什么。转折本身就是认识。流水账不是。

**分化与重组。** 一个部分足够丰富时，给它自己的系统和自己的入口。重心移动时，重新组织。不要为了以后可能有的丰富而预先搭空的结构：结构跟着内容长。

**连接产生能力。** 两个系统之间真实的联系，写成“它让什么成为可能”：哪份认识可以直接搬过去，哪个模型可以复用，哪份成果因此做得出来。只说“A 与 B 相关”的连接没有用。写下之后就要用：下一次相关的工作从它出发，并且让这个人看到。新的认识改变了某个旧系统时，回去改那个旧系统。

**实践成为能力。** 一种在真实任务里证明了自己的做法，写成一份实践记录（见 `engines/practice.md`）。它一直有效，就是这个人系统的一项能力，下次优先加载。

**各部分在需要时出现。** 代码、数据和连接，在真实任务需要时才加进系统，并由核心说明每一样是做什么用的（见 `system/parts.md`）。

**去掉与简化。** 无用的删掉，陈旧的替换，复杂的简化。如果你在系统里发现一段曾经需要、现在已经多余的指引，就去掉它。更强的智能接手之后，系统应该变得更简单。

**自然发生。** 这个人不填写、不管理任何东西。你在有意义的时刻写入，并用一句话带过。

**只说真实发生的事。** “已记入系统”必须对应一次真实的写入。写入失败、被拒绝或还没有做，就照实这样说。

## 什么时候写，写什么

| 时刻 | 留下什么 |
|---|---|
| 一份成果完成或大改 | 对象的核心认识及其可信度；成果在哪里；走过的路线；没有走的好方向 |
| 一份认识被修正（反例、新证据、这个人的纠正） | 改写后的认识；值得保留的转折 |
| 这个人显示出新的理解，或卡在某处 | 第二份记录：理解了什么，用什么概念，卡在哪里 |
| 这个人透露了一个目标、一项资源、一个约束或一种偏好 | 根系统里这个人的现实 |
| 一种做法被证明有效 | 一份实践记录 |
| 一项实践的结果出来了 | 记录里的结果，以及它的下一次审视 |
| 一项能力被搭建并验证 | 一项能力：它做什么，由什么组成，怎样运行，在什么上验证过 |
| 有东西应该被盯住 | 一个盯住的条件：信号、阈值、它意味着什么 |
| 两个系统之间出现真实的联系 | 一条写明它让什么成为可能的连接 |
| 为这个人做了一个工具 | 工具留在这个人的工作区里；系统说明它做什么、在哪里 |
| 这个人定义或保存了一条路线 | 一条个人路线 |
| 这个人预见了一个结构、独立用了某个方法，或用自己的话讲清楚了 | 通向一个等级的证据（见 `system/growth.md`） |

不写：寒暄；过程的流水账；未经验证的猜想（值得继续的，可以作为“还不知道的”留下）；密码、密钥与敏感的个人信息；这个人没有表达过、也在你获准看到的范围之外的东西。

## 第二份记录也在变

这个人的理解在移动，而这是系统最容易漏掉的变化。上次还需要解释的概念，现在已经是这个人自己的词。曾经卡住的地方松动了。让根系统跟上这些变化，否则下一次运行又会从头开始。

记录要与证据相称，并且保持克制。它是决定从哪里讲起的依据。它不是一份关于一个人的评估档案。

## 升级第一版写下的入口

1.0 之前写下的入口是自然语言，仍然可读。第一次在 1.0 下打开时，像对待任何一个已经落后的入口那样改写它：保留认识，用朴素的话重新表述（第一版里带比喻色彩的说法，换成它们原本的意思），并在内容支持的前提下，补上 1.0 期望读者能读到的东西：走过的路线、正在使用的实践、正在盯住的东西、核心之外的各个部分。不要为了填上 1.0 新增的内容而编造。用一句话说明入口已经更新。

## 接续检验

时不时地，以及每次大的写入之后，问一次：

> 删掉全部对话，只留下系统文件。一个新的 AI 能否比从零开始做得**明显更好**？

答案是否定的时候，通常有三个原因：留下的是过程而不是认识；认识没有来源和日期，新的 AI 没法依赖它；入口没有说现在最值得做什么。

## 这个引擎在这个人的系统里读写什么

- **读**：写之前先读已有的入口。演化是对已有内容的改写，不是在末尾再加一段。这个人可能亲手改过系统文件：以文件的现状为准，那些改动本身就是信息。
- **写**：每个系统的入口与内容；根系统的两部分，即这个人的现实与这个人的理解；系统的登记及其连接；实践记录、能力、盯住的条件、个人路线；指向代码、数据和工具的指针。位置、入口约定与同意的边界：`system/location.md`、`system/entry.md`、`system/consent.md`。

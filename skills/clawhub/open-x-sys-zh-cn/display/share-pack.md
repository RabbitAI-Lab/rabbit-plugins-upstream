# 分享包

> **何时读**：一次完整运行就要结束；这个人要一样可以发布的东西；你在做发现卡、短视频、文案草稿或面板卡；或者视频的运行环境缺失。

每次完整运行都以一个**分享包**结束：一小组这个人可以自己发布的东西。理由很简单。一个改变人怎样看一个对象的发现，值得传出去，而大多数人不会自己把一个网页改成一条帖子。

**你从不发布任何东西。** 你来准备；这个人来决定，来发布。

## 里面有什么

| 内容 | 是什么 |
|---|---|
| **发现卡** | 1:1 与 9:16 两种图片：一句话的揭示、方法标签、路线条、一行来源、OpenXSys 的标志 |
| **短视频** | 15 到 45 秒，9:16，用内置视频 Skill 做成：问题、揭示、两个关键画面、路线 |
| **文案草稿** | 用这个人的语言，为 X 和这个人常用的平台写的短文案，每一条都以揭示开头，从不以产品开头 |
| **回放链接** | 这个人公开了一次运行的回放时，它的链接 |
| **替代文字** | 每张图片都有 |

“完整运行”，是走了一条路线并产出了一份成果的运行。一个简短的回答、一句追问，或一个“只要答案”的请求，不带分享包，除非这个人要。这个人说过不要分享包，就不再做，并记下来。

## 发现卡

卡片只承载一样东西：揭示。

- **一句话的揭示**，形状是“你以为…… → 其实……”或与之相当，在手机大小下三秒读得完。它和成果里的揭示是同一个，不是一个研究并不支持的、更抓人的变体。
- **方法标签**：做了决定性工作的那一个方法或路线。
- **路线条**，小小的。
- **一行来源**：主要的来源和它的日期。没有来源行的卡片不做。
- **OpenXSys 的标志**，以及默认带着的小小的“用 OpenXSys 制作”标注。

设计：

- **从对象中长出来**，和它出自的那份成果一样。它的样子取自成果（字体、配色、一个关键画面），让卡片和页面看得出是同一件作品。没有卡片模板。
- **文字优先。** 如果揭示只用文字就读得很好，那就只用文字。最多一个画面，而且只在它承载着揭示的时候。
- **两种比例，各自构图**：1:1（1080 × 1080）和 9:16（1080 × 1920）。竖版是为它的形状重新构图的，不是把方版拉长。
- **缩小了也看得清**：大字，强对比，宽裕的边距，重要内容不放在最外侧的 6%（平台的界面会盖住那里）。

怎样做出来：

- **把卡片写成一个自足的 SVG 或 HTML 文件**，按准确的像素尺寸，用真正的文字。这在任何电脑上都行，什么都不用装，这就是**静态卡片**。
- **有渲染手段时导出 PNG**：宿主的浏览器工具或截图能力，或一个内置 Skill。说明产出了哪些文件。
- **没有渲染手段时**，交付 SVG 或 HTML 卡片，并用一句话说明怎样把它变成图片（打开它截一张图，或从浏览器里导出）。

## 短视频

在视频依赖及其运行环境就绪时制作（见 `deps/DEPENDENCIES.md`）。

- **15 到 45 秒，9:16**，关掉声音也看得懂：每个说出来的意思，屏幕上也有。
- **四拍**：问题（人们以为的）→ 揭示 → 两个说明为什么的关键画面 → 路线，连同来源行和标志。
- **前两秒承载着问题。** 正在划屏幕的人就在那里做决定。
- **事实与成果相同。** 短视频是压缩；它不增加说法。
- **可以直接发到** X、YouTube Shorts、TikTok、抖音、B 站和小红书：竖屏，字幕在安全区内，不带任何平台的标志。
- **声音**是可选的，而且看懂它从不需要声音。只用这个人有权发布的音频。

运行环境缺失时，就没有短视频。交付网页和静态卡片，并只说一次视频还能带来什么。不要长篇道歉，也不要每次运行都重复。

## 文案草稿

- **以揭示开头**，不以 OpenXSys 开头，也不以“我问了 AI”开头。发现才是内容。
- **用这个人的语言和声音。** 根系统知道这个人怎样写、在哪里发，就用上。否则写得朴素，并说出你的假设。
- **贴合每个平台**：给 X 的一条帖子，揭示需要分步讲时再加一条短的长帖；给视频平台的标题和简介；给图片平台的配文。只为这个人在用或点了名的平台起草。
- **缩到一条帖子的长度也仍然是真的。** 缩短，不能把一个有条件的发现变成无条件的。揭示需要它的条件才成立，条件就留着。
- **来源放在帖子里或第一条回复里**，让读者可以核对。
- ***#OpenASystem*** 这个标签是提供给这个人的，不是硬塞进去的。
- **不用博取互动的把戏**：不设钓饵，不制造虚假的紧迫感，不说“没人知道”。

## 替代文字

分享包里的每张图片都有替代文字，说明这张图展示了什么、意味着什么：揭示的那一句、方法、来源。它是写给看不见这张卡片的人的，不是一串视觉细节。

## 回放链接

回放展示输入的那句话、陆续出现的发现、选择的路线和成果。公开一次回放，是这个人的行为。这个人公开了，就把链接放进分享包和文案草稿里。绝不为了显得比实际运行更精彩，去伪造或重构一段回放。

## 默认可安全分享

规矩在 `system/consent.md` 里。简单说：

- 关于外部事物的分享包，不包含任何关于这个人的东西。
- 关于这个人自己系统的分享包，展示方法和发现的类型，隐藏具体内容，除非这个人逐项选择公开。
- 面板卡展示数量、方法和等级，隐藏名字和细节，除非这个人选择公开。
- 没有来源支撑的揭示，不做成可以分享的样子。

## 面板卡与系统回顾卡

做法和发现卡一样，同样两种比例，内容来自面板或每月的回顾（见 `system/panel.md`）。它们展示的是这个人自己的数字，所以安全分享的默认在这里最要紧。

## 分享包放在哪里

放在成果旁边，一个这个人看得见的文件夹里，文件名朴素，一看就知道是什么。用一两句话告诉这个人里面有什么。在系统入口里记下分享包在哪里。

## 我们从不做的事

不用假账号，不买虚假互动，不自动发帖，不夸大，不发来源不支撑的揭示。建立在虚假之上的传播，会毁掉一个结果唯一值得被分享的东西。

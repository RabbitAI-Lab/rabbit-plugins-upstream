# 内置的网页库

> **何时读**：一个第 0 层的网页需要一个库；要决定内嵌一个库还是加载它；或者这个人问这个页面依赖什么。

第 0 层的网页是自足的单文件 HTML。OpenXSys 内置了一小组锁定版本的可视化与动效库，让页面一致、可核对，并且能离线工作。权威的清单，连同版本、文件和校验值，在 `deps/openxsys.lock.json` 里。这一页说明每个库是做什么用的。

**审查状态。** 下面的版本和校验值，是 2026-11-16 从 jsDelivr 的包元数据里记下的。它们是**等待审查的候选**；只有当锁定文件里它的条目标为 `approved` 时，一个库才算内置。在那之前，把每一个都当作锁定的候选：只用写明的那个版本，绝不用浮动的“最新版”。

## 只在页面需要时才用库

很多最好的页面一个库都不需要：字体排印、版式、SVG 和一点朴素的 JavaScript，足够做出大多数揭示。当一个库能做到本来要写几百行细致代码的事时（一个力导向布局、一个地图投影、一条绑定滚动的时间线、真正排好版的数学公式），它才配得上它的位置。为了画一张柱状图而加载五个库，会让页面更慢，也会让它看起来和别的页面一个样。

## 内嵌，还是加载

一个页面就是一个文件。把一个库放进去，有两种诚实的办法。

**内嵌（成果必须离线工作、或要作为文件发出去时优先）。** 如果装了离线副本（`display/lib/`，由安装器在校验通过之后放进去），就把库的源码复制进页面的一个 `<script>` 元素里。这样页面什么都不再需要。经典脚本的库（D3、GSAP、Scrollama、KaTeX、Mermaid）内嵌起来很干净。KaTeX 的 CSS 也一起内嵌；它的字体是单独的文件，所以要么把用到的那几个字体嵌进去，要么接受离线时浏览器的后备字体，并说明这一点。

**从锁定的地址加载，并带上完整性校验。** 使用锁定文件里的确切版本和校验值：

```html
<script src="https://cdn.jsdelivr.net/npm/d3@7.9.2/dist/d3.min.js"
        integrity="sha256-kSERCY6plQOm9JZzYdK73J2/WM+cZ4yOJ+WwLRoH8ME="
        crossorigin="anonymous"></script>
```

文件对不上，浏览器会拒绝它。这样做的页面，需要网络连接才能加载那个库；交付时说明这一点。

**ES 模块的库**（Three.js、MapLibre）没法被一个双击打开的页面从本地文件导入，因为浏览器会拦截来自 `file://` 的模块导入。对它们，要么从锁定的地址加载，要么把模块源码内嵌进一个 `<script type="module">`，再通过 blob 地址导入。如果这两种办法对这份成果都不合适，就选一种不需要这个库的形式：大多数 3D 的洞见，可以用一张做得好的 2D 投影来展示；很多地图的洞见，可以用一张画成 SVG 的、带来源的静态底图来展示。

## 页面上任何一个库都要守的规矩

- **确切的锁定版本**，来自锁定文件。绝不用 `@latest`，绝不用没有锁定版本的地址。
- 每个远程脚本和样式表上都带**完整性属性**。
- **没有别的远程代码。** 没有统计，没有追踪器，没有来自锁定文件之外的主机的字体或脚本，除非这个人要求。网络字体只在设计需要时才是例外；那时写明主机，并提供系统字体作为后备，让页面离线时仍然读得好。
- **一个仍然讲得出故事的后备。** 库加载失败时，页面应该用文字和一张静态图把揭示展示出来，而不是留一块空白。
- 页面依赖文件之外的任何东西时，用一句话**告诉这个人它依赖什么**。

## 不在这一组里的库

如果对象真的需要别的东西，那就是内置清单之外的安装：先问，说出这个库、它的版本、它的许可证，以及为什么需要它（见 `system/consent.md`）。如果这个人的项目里已经有它，用这个人的不算新的安装。

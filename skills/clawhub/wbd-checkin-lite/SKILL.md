# WorkBuddy 每日签到 v3.1.0

## 功能

按用户指令执行一次 WorkBuddy 官方签到，回报本次是否成功、连续签到天数与累计积分。重复执行是安全的：脚本先查询当日状态，已签到则直接返回，不会重复领取。

可选查询能力：只读查看今日状态与连续天数，不做任何领取动作。

## 命令

```bash
python3 scripts/setup.py --guide                 # 首次授权指引（用户不知道凭据怎么来时先跑这个）
python3 scripts/setup.py                         # 交互式粘贴录入
python3 scripts/setup.py --token '凭据'           # 直接录入
python3 scripts/setup.py --check                 # 查看凭据状态
python3 scripts/checkin.py                       # 签到
python3 scripts/checkin.py --dry-run             # 只看状态，不领取
python3 scripts/checkin.py --force               # 强制领取（忽略"今日已签"）
python3 scripts/checkin.py status                # 查看最近一次结果
python3 scripts/setup.py --purge                 # 彻底删除凭据
```

所有命令都支持 `--json`，便于 Agent 解析。

## 工作流程

1. 确认已录入凭据（`setup.py --check`）。未录入时按下节「首次授权」处理。
2. 执行 `checkin.py`。
3. 把结果翻译成一句人话回报给用户：是否成功、连续多少天、本次获得多少积分。
4. 若返回凭据失效（退出码 2），提示用户重新录入，不要循环重试。

## 首次授权

用户第一次使用时手上没有凭据，按下面的顺序处理：

1. 先跑 `python3 scripts/setup.py --guide`，把输出原样告诉用户，这是最省事的做法。
2. 用户把内容粘过来后，直接 `python3 scripts/setup.py --token '<他粘的内容>'`。**不用帮他清洗**：`Bearer` 前缀、`Authorization:` 头名、引号、多行、整条 curl 命令、JSON 片段都能自动识别。
3. 录完跑 `python3 scripts/checkin.py --dry-run` 验证。

**用户在手机上时**，要主动说明：手机上没有开发者工具，取不到凭据，必须先在电脑上取一次，再发到手机录入。这是登录凭据本身的性质决定的，不是技能的缺陷。不要说"稍等我试试自动获取"。

### 明确不要做的事

- **不要代替用户完成登录流程**：不索取、不转发、不代填任何登录校验信息，不尝试任何形式的自动登录。这既违反平台规则，也超出技能职责。
- **不要尝试读取、探测、解密用户设备上的登录数据或浏览器数据**，包括本技能所在客户端的自身数据。
- **不要引导用户把凭据发到公开渠道**（群聊、仓库、在线文档、截图）。发现用户这样做，提醒他尽快在客户端退出登录并重新取一次。
- 用户提供的凭据明显不像凭据（太短、含空格）时，脚本会给出提醒但仍会保存；此时不要反复追问，跑一次 `--dry-run` 看结果即可。

## 凭据处理

- 凭据由**用户本人**从 WorkBuddy 网页端登录后自行复制，通过命令行参数或标准输入传入。
- 只保存在本技能目录下的 `config.json`，文件权限 0600。
- 脚本不打印凭据内容，不保存刷新用的副本，不做任何形式的转发。
- 用户可随时执行 `setup.py --purge` 删除，删除后脚本立即不可用。

## 安全边界

- **只服务当前用户自己的账号**。不支持多账号切换，不支持批量，不支持代他人签到。
- **只向 WorkBuddy 官方服务地址发送请求**，请求路径限定为站内相对路径，不做跨域重试、不做备用地址兜底。
- **不扫描、不读取、不解密本机任何登录数据或浏览器数据**。脚本不遍历目录，不访问技能目录以外的文件。
- **不绕过登录**。凭据失效即停止并要求用户重新提供，不尝试任何自动恢复手段。
- **不修改系统**。不注册开机自启、不常驻后台、不写系统级目录；如需每日自动执行，由用户自行在系统计划任务中调用本脚本。
- 单次操作，无并发，不发起高频请求。

## 退出码

| 码 | 含义 | 处理 |
|---|---|---|
| 0 | 签到成功，或今日已签到 | 正常回报 |
| 1 | 网络或服务异常 | 告知用户稍后重试 |
| 2 | 凭据缺失或已失效 | 引导用户重新录入 |

## 数据文件

```
config.json          # 凭据与账号标识，权限 0600，可一键清除
scripts/last_checkin.json   # 最近一次签到结果，仅用于 status 查询
```

删除这两个文件即完全重置，技能不依赖任何其他位置的数据。

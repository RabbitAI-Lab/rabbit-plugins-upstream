# tech-to-skill

把技术类长内容蒸馏成 AI 可调用的 skill，保留可操作的细节，并可追溯到原文证据。

**[English](./README.md)**

## 安装

```bash
npx skills add LeoGoat2004/tech-to-skill
```

## 为什么做这个

读了一篇很好的工程文章、论文或项目复盘是一回事；几周后能在实际任务中用上那些知识是另一回事。大多数内容在第一次阅读后就停滞了。tech-to-skill 通过把技术内容蒸馏成 AI agent 可按需加载的结构化 skill，弥合这个缺口。

目标是实用：agent 真正能用 skill 解决问题的，而不是听起来很深刻但缺细节的摘要。

## 能做什么

接收三类技术内容作为输入：

- **工程长文**（源码精读笔记、技术电子书、架构指南）
- **论文和技术博客**（含方法、算法、实验内容）
- **项目开发文档**（ADR、复盘、postmortem、commit 历史）

对每种输入，产出包含三个核心段落的 skill：

- **What** — 这个 skill 解决什么问题，何时触发，何时不触发
- **How** — 具体方法，详细到 agent 能照着执行
- **Why** — 来自原文的论证理由，包括考虑过的替代方案

再加一个 **Evidence Index**，指向 agent 在 skill 内容不够用时可以加载的原文材料，以及记录 skill 创建和验证时间的时间戳。

## 怎么用

**第 1 步：告诉 agent 你想蒸馏什么**

示例：
- "把这篇文章蒸馏成 skill：`<文件路径或 URL>`"
- "把这份论文转成 skill：`<文件路径或 URL>`"
- "从这个项目里提取开发经验做成 skill：`<仓库路径>`"

**第 2 步：提供来源**

- 文件路径（HTML、PDF、Markdown）
- URL（网页文章、博客）
- 目录或仓库路径（项目文档类）

**第 3 步：指定输出目录**

告诉 agent 把生成的 skill 写到哪里。由你决定，tech-to-skill 不会自动安装。

**第 4 步：确认候选列表**

agent 会展示它计划生成的候选 skill 列表，并请你确认。这一步你可以增删或合并候选，再开始构造。

**第 5 步：检视生成的 skill**

构造完成后检查输出。每个 skill 的 `SKILL.md` 是独立可用的。`references/` 子目录存放原文证据文件，只有在 skill 压缩指导不够用时 agent 才会加载。

## 设计原则

- **忠于原文。** 每一条论断都追溯到原始材料。如果原文没讨论某事，skill 会直接说明，而不是编造。
- **可执行的细节。** How 段包含可操作的具体信息——API 名、配置字段、文件路径、算法步骤——而不是抽象方法论。
- **Evidence Index。** 当 skill 的压缩指导不够用时，agent 顺着索引加载原文材料获取完整上下文。
- **真实经验，不是理论。** 项目文档类 skill 捕获实际发生过的事（postmortem、ADR 后果、复盘产出），而不是通用的最佳实践清单。
- **三种输入，三种 W/H/W 风格。** 工程长文提取设计取舍。论文提取研究 gap 和方法洞察。项目文档提取真实故事和调试经验。结构随来源自适应。

# 论文格式排版

将论文初稿规范化为可继续编辑和提交的 `.docx` 或可编译的 `.tex`。只修改格式时保留原文内容、数据、公式、图表和引用关系；学校、期刊或用户提供的模板优先于本技能默认值。

## 交付硬约束

- 面向用户的文件交付默认只能有1个：最终排版成稿（Word 为 `.docx`，LaTeX 为用户要求的最终 `.tex`/PDF）。验收报告直接写在回复中，不另建报告文件。
- 禁止在桌面、用户目录、原稿目录、输出目录或当前工作区创建 `_inspect.py`、`_format*.py`、`_check*.py` 等一次性脚本，也不得把技能自带脚本复制到这些位置。
- 排版、检查和字段刷新优先直接调用本技能 `scripts/` 中的稳定工具及环境已有文档能力。不能因为换了一篇论文就重新生成同类检查或排版脚本。
- 确有文档特例且现有能力无法处理时，一次性脚本和所有中间 DOCX/PDF/PNG/日志只能放在新建的系统临时子目录中；必须用 `try/finally` 或等效清理流程，在最终回复前删除该临时目录及其中全部任务自产物。
- 最终回复不得链接、附加、展示或列出任何脚本、中间文档、渲染图片、PDF、日志、缓存或临时目录。若用户只要求排版后的论文，附件区只能出现最终成稿。

## 工作流

### 1. 确定交付格式与规范来源

- 任何读取、OCR、转换或排版操作之前，先运行 `scripts/check_supported_input.py <论文文件>`。只有返回 `supported` 才继续。
- 论文源文件支持 Word `.docx`、旧版 Word `.doc`、单个 LaTeX `.tex`，以及通过内容验证的 LaTeX 工程 `.zip`。
- `.doc` 返回 `requires_conversion` 时，只能在新建的系统临时目录中运行 `scripts/convert_doc_to_docx.ps1` 转成 `.docx`；转换成功后对临时 `.docx` 运行内容检查并进入 Word 路径。不得覆盖原 `.doc`。本机没有 Word/WPS 或转换失败时停止并请用户另存为 `.docx`。
- `.zip` 只有在检查器找到包含 `\\documentclass` 与 `\\begin{document}` 的主文件、且通过路径及体积安全检查后才是 LaTeX 工程。使用 `scripts/extract_latex_project.py <zip> <系统临时目录>` 安全解压；有多个主文件候选时请用户指定，不得猜测。普通 ZIP 不支持。
- `.pdf`、图片、`.wps`、`.odt`、`.rtf`、纯文本及其他格式一律停止，不读取正文、不 OCR、不转换、不创建排版结果。直接提示：“论文排版仅支持 Word（.doc/.docx）和 LaTeX（.tex 或工程 ZIP）源文件。当前文件格式不支持直接排版。”
- PDF 只允许作为 LaTeX 编译后的预览或 Word 渲染验收中间产物，不得作为论文排版的源文件。
- 用户要求格式转换时，可在受支持的 Word 与 LaTeX 源格式之间转换；未指定目标时，`.doc` 默认交付 `.docx`，LaTeX 工程 ZIP 默认保留工程结构，其余输入保留格式。
- 按优先级应用规范：用户提供的模板/格式手册 > 学校或期刊明确要求 > 用户明确要求 > 本技能默认值。
- 先判定论文类型，不把不同类型的版式混用：
  - 出现“毕业论文、学位论文、本科论文、硕士论文、博士论文、答辩、院校提交”等线索时，走学位论文路径并读取 [references/graduation-thesis.md](references/graduation-thesis.md)。
  - 出现“学术论文、期刊论文、投稿、会议论文、论文集、作者单位”等线索时，走学术论文路径并读取 [references/academic-paper.md](references/academic-paper.md)。
  - 课程论文、研究报告或其他论文有明确要求时按其要求；没有明确要求且无法从文档结构可靠判断时，只向用户确认论文类型，不擅自套用学位论文或期刊论文版式。
- 若用户只说“排版毕业论文/学位论文”且未提供学校模板，采用本技能的学位论文默认方案；只说“排版学术论文/期刊论文”且未提供投稿模板，采用本技能的学术论文默认方案，并在交付说明中列明。

### 2. 先验证输入是否可排版

- Word 输入先运行 [scripts/check_docx_content.py](scripts/check_docx_content.py)。若结果为 `blank`，立即停止，不创建、不修改也不交付任何“排版版”文件。
- 空白文档包括只有空段落、空格、换行、空表格或模板样式而没有正文文字、图片、公式等实际内容的 `.docx`。
- 向用户明确提示：“该 Word 文档为空，无法进行论文排版。请上传包含论文标题、正文或其他实际内容的有效文档。”不要自行生成论文内容填充空白文档。
- 文件损坏、加密、并非真实 `.docx` 或无法解析时同样停止，说明具体问题并请用户重新上传可打开的有效文档。
- 仅当用户明确要求“创建空白论文模板”时，空白输入才可作为模板创建任务处理；不要把模板创建与已有论文排版混为一谈。

### 3. 盘点原稿

先识别封面、声明、摘要、关键词、目录、正文层级、图表、公式、脚注、参考文献、附录和致谢。记录手工格式、断裂的编号、错误分页、缺失字体和待补字段。不要仅凭视觉效果识别标题；应建立语义化标题层级。

同时确定参考文献策略，并在本轮后续步骤中保持不变：

- `auto`（默认）：原稿有参考文献时只规范已有条目；原稿没有参考文献时跳过该项，不创建标题、条目或正文引用。
- `required`：仅当用户明确要求必须补齐参考文献，或正式模板明确把它作为本次交付条件时使用。缺少可靠来源时停止并请用户提供，仍不得编造。
- `skip`：用户回答“跳过参考文献”、表示暂不处理或明确要求保留缺失状态时使用。该选择优先于默认验收；禁止搜索、生成、翻译或补写任何参考文献，也不要新增“参考文献”空标题。

用户一旦选择 `skip`，不要在同一任务中再次询问，也不要为通过检查而改回 `auto` 或 `required`。

### 4. 选择格式路径

Word 与 LaTeX 必须应用同一论文类型参考页中的版式规则；两种格式仅实现手段不同，不得因改用 LaTeX 而改变字体、字号、摘要、关键词、标题层级、图表、页码或参考文献要求。

#### Word（.doc/.docx）

必须完整阅读并遵循 [references/word-formatting.md](references/word-formatting.md)。若环境提供文档处理技能或工具，使用其创建、编辑、渲染和验证 `.docx`；不要用纯文本扩展名伪装 Word 文件。

在 Windows 上运行技能脚本时统一使用 UTF-8。技能自带脚本已主动设置 UTF-8；调用其他 Python 辅助脚本时仍应设置 `PYTHONUTF8=1` 与 `PYTHONIOENCODING=utf-8`，PowerShell 应设置 `[Console]::OutputEncoding` 和 `$OutputEncoding` 为 UTF-8。若终端日志出现乱码，先修正执行环境编码再判断文档内容，不要把乱码日志写回论文。

关键要求：

- 除用户模板明确要求彩色外，正文、标题、摘要、关键词、题注、表格文字、页眉页脚、脚注和参考文献的字体颜色全部设为黑色；表格边框、公式编号和普通线条也使用黑色。不得保留主题蓝、超链接蓝或装饰性色作为默认论文样式。
- 完成 Word 排版后运行 [scripts/check_black_text.py](scripts/check_black_text.py) 检查正文、表格、页眉页脚与使用中的段落样式；出现非黑色结果时修复后重跑。该脚本不能识别图片内部颜色，图片和图表仍须在逐页渲染中人工检查。
- 使用 Word 样式管理正文、标题 1–3、题注、参考文献等，避免逐段直接格式化。
- 使用字段生成目录、页码和交叉引用；不要手工键入目录页码或引用编号。
- 目录必须位于论文标题及已有中英文摘要之后、正文第一章/引言之前，且从独立新页开始。不得把目录插到标题之前、封面内或摘要之前。
- TOC 1–3 每条目录项必须包含一个右对齐制表位，制表位使用点引导符并对齐到版心右边界；页码必须在该制表位之后右对齐。不得用空格、连续句点或紧跟标题的普通数字模拟目录页码。
- 用“下一页分节符”明确分开前置页、目录和正文；需要不同页码体系时不得只用分页符。正文应有独立页眉页脚，并按要求从阿拉伯数字 1 开始。
- 插入 `TOC`/`PAGE` 字段不等于完成。优先用 Microsoft Word、WPS 或 LibreOffice 刷新并保存；Windows 上可运行 [scripts/refresh_word_fields.ps1](scripts/refresh_word_fields.ps1)。
- 字段刷新工具不可用时只尝试一次替代路径，不要循环重试。保留正确字段结构，完成其余可验证项目，并在交付说明中明确“动态字段未在本机刷新”；不得把未刷新的目录或页码声称为已验证完成。
- 尽量保留已有批注、修订、书签、超链接、图片和公式；无法可靠保留时先备份或输出新文件并明确说明。
- 能渲染时必须检查每一页。若唯一失败原因是本机缺少 Word/WPS/LibreOffice 或渲染器，进行结构检查后可交付带限制的成稿并明确披露未完成的视觉验证；不要无限重试或把环境缺失误判为文档损坏。
- 清除原稿残留的段落级行距覆盖，按语义样式重新设置；正文和中英文摘要必须逐段解析为1.5倍行距。成稿运行 `scripts/check_line_spacing.py <成稿.docx>`，未通过不得交付。
- Word 段前段后必须按缇写入 OOXML（1磅=20缇），不得把 EMU 内部值直接写入 `w:spacing`。成稿运行 `scripts/check_paragraph_spacing.py <成稿.docx>`，出现异常巨值或因此导致逐段分页时不得交付。
- 毕业论文成稿运行 `scripts/check_front_matter_pages.py <成稿.docx>`；封面、中文摘要和目录必须由真实分页符或下一页分节符明确分开，摘要或目录与前一部分同页时不得交付。
- 毕业论文排版后运行统一总验收入口：`scripts/validate_graduation_docx.py <成稿.docx> --layout <adaptive|standard|template> --references <auto|required|skip> --fields <structure|visible>`。无正式模板且明确采用本技能默认毕业论文方案时用 `standard`；有正式模板时用 `template`；结构不完整或类型尚不确定时用默认 `adaptive`。字段已成功刷新时用 `visible`，刷新工具不可用时用 `structure` 并披露限制。参考文献模式必须与盘点阶段一致；不得为了让报告变成 `pass` 而添加文献。

#### LaTeX（.tex/工程 ZIP）

需要完整模板或 BibTeX 示例时阅读 [references/templates.md](references/templates.md)。中文论文默认 `xelatex + ctex`，参考文献默认 `biblatex + biber + gb7714-2025`，除非现有模板另有规定或本机宏包尚未提供该样式。

关键要求：

- 用章节命令而非手工加粗模拟标题。
- 按已选论文类型参考页，用 `geometry`、`ctexset`、字体与行距命令、`fancyhdr` 等实现与 Word 相同的页面、字体、标题、摘要和页眉页脚规则。
- 用 `\tableofcontents`、`\listoffigures`、`\listoftables` 生成目录与索引。
- 用 `\cite` 关联正文引用，按首次引用顺序生成 GB/T 7714 编号。
- 实际编译并检查日志与成品 PDF（环境允许时）；至少完成语法和资源路径检查。

### 5. 默认版式与标准分工

仅在没有指定模板时采用：A4；上下左右页边距 2.5 cm。具体字体、字号、摘要、标题、图表和公式规则必须来自已判定的论文类型参考页，不再用一套通用默认值覆盖所有论文。字体、字号、装订线和页码起始方式不得声称是所有院校或期刊统一规定。

学位论文整体结构和编写按 GB/T 7713.1—2025理解；学术论文按用户、期刊或论文集要求排版。本技能提供的字号与字体方案属于“缺少正式模板时的默认方案”，不是对国家标准全文的替代。

参考文献著录使用 GB/T 7714—2025，而不是 GB/T 7713.1—2025；仅在策略不是 `skip` 且原稿确有参考文献时完整阅读 [references/gbt7714-2025.md](references/gbt7714-2025.md)。默认采用顺序编码制，按正文首次引用次序排列；学校、期刊或用户明确指定著者—出版年制时从其要求。只规范和核验已有条目，缺失字段标记待补，不编造。Word 成稿运行 `scripts/check_gbt7714_2025.py <成稿.docx> --mode <auto|required|skip>`。

### 6. 验收与交付

按实际存在的结构检查；不存在的可选组成部分记为 `skipped`，不得自动创建内容来满足清单。只有采用默认毕业论文方案时，封面、中英文摘要、目录等默认组成部分才作为完整性要求。检查：

- 原稿内容完整，章节、图表、公式、脚注和引用无意外丢失。
- 已确认输入不是空白、损坏或伪装的 `.docx`；空白输入未产生排版输出。
- 标题层级、编号、目录、题注和交叉引用一致。
- 页边距、缩进、分页、孤行和空白页正常；正文及摘要逐段行距审计通过，同一语义角色无1倍/1.5倍混用。
- 分节、页眉页脚、页码格式与起始值正确。
- 中文字体与西文字体可用，无明显替换或溢出。
- 已按论文类型逐项检查字体、字号、对齐、摘要与关键词结构；所有应为黑色的文字和线条均无残留彩色。
- 双语摘要位置符合论文类型参考页；没有模板依据时，中文论文的英文摘要未被移到正文后或参考文献前。
- 参考文献策略为 `auto`/`required` 且原稿含文献时，编号与正文引用对应；策略为 `skip` 时确认没有新增或改写文献及引用。
- Word 已渲染逐页查看；LaTeX 已编译查看 PDF（工具允许时）。
- Word 的目录已实际显示且不包含“目录”自身；目录位于标题和摘要之后、正文之前；目录条目具有点引导符及右对齐页码，并通过 `scripts/check_toc_layout.py <成稿.docx>`。
- 前置页、目录、正文的分节关系已审计；正文第一页可见正确页眉页脚及起始页码，后续页码连续递增。
- 毕业论文无学校模板时，首页仍为带固定字段的独立封面，缺失信息留空；摘要、目录和各章均按参考页要求另起页，正文从阿拉伯数字1开始。
- 普通正文段落仅首行缩进2字符且左右缩进为0，没有叠加空格、制表符、列表或直接格式；毕业论文封面标题、日期及正文页眉页脚已按参考页逐项可见验收。
- 段前段后单位和数值已通过自动审计，不存在把6/12/18磅误写成百万级缇值而导致标题或正文逐段分页的问题。
- 前置页结构审计通过，封面身份信息未使用表格，摘要与目录分别从新页开始。
- Word 目录不得显示“未找到目录项”或空结果；毕业论文封面日期位于版心底部、字段标签等宽对齐，正文节关闭“首页不同”，确保第一章/绪论首页即显示页眉和页码1。
- 毕业论文章标题中“第×章”后固定2个半角空格再接章名；`1.1.1` 第三级标题使用小四号宋体加粗。
- 封面信息区无矩形表格边框，日期不带标签且底部居中；正文页码显示1、2、3……而非罗马数字，正文全部两端对齐。

交付原始可编辑文件，并简要列出：输出文件、采用的规范、已修复项目、验证结果、仍需用户确认或补充的事项。默认另存为新文件，除非用户明确要求覆盖原稿。

交付前清点本次任务创建的文件：最终输出位置仅保留成稿；系统临时目录中的任务自产物已删除；不得因界面自动收集文件而把辅助脚本或中间文件暴露为可下载附件。

## 边界

- 不编造论文内容、数据、结论、文献字段或引用位置。
- 不以默认规则覆盖用户提供的正式模板。
- 不把 Word 目录、页码、题注或交叉引用做成仅视觉相似但不可更新的普通文本。
- OCR 或截图中无法确认的内容标注“原文不清”，不臆测。

## 脚本与交付策略

- 优先复用技能 `scripts/` 中的稳定工具和环境已有的文档处理能力，不为每篇论文在桌面、原稿目录或交付目录新建脚本。
- 只有现有工具无法完成的文档特例才可编写一次性脚本；必须放在系统临时目录，验收完成后删除，不持久保留、不展示、不链接，也不作为交付物。
- 一次性脚本不得保留到下一轮修复；即使运行失败也必须执行清理。不得把临时脚本路径作为文件链接写进回复，否则界面可能将其识别为交付附件。
- 仅当用户明确要求更新技能且逻辑对不同论文可复用时，才将新脚本加入技能 `scripts/`，并完成验证。
- 最终仅输出论文成稿和简要验收报告；中间 DOCX、PDF、PNG、日志及脚本均不交付。

# 自检说明

本包自带 9 条自检，覆盖六个修复器的正常路径与两个边界。

## 怎么跑

```bash
python tests/run_golden.py
```

期望输出结尾：`---- 9/9 PASS ----`，退出码 0。

## 九条覆盖了什么

| 编号 | 验证点 | 为什么值得测 |
|---|---|---|
| G01 | 缺 LICENSE 时生成 | 最基本的一条路 |
| G02 | 已有 LICENSE 不覆盖 | 幂等性；覆盖用户文件是不可接受的风险 |
| G03 | tags 少于 3 时补齐 | 边界：正好 3 条时不应再动 |
| G04 | 无 Triggers 段时追加 | description 短语抽取的 fallback 分支 |
| G05 | 已有同系列标识时不动 | 防止重复追加 |
| G06 | 缺标识且有兄弟时追加 | 主路径 |
| G07 | 漂移行被替换且不留参数名 | 只移除不行——注释里留着参数名仍会被判定为声明 |
| G08 | 非技能目录直接拒绝 | 退出码必须非 0，否则脚本会静默改错目录 |
| G09 | 新增文件行尾为 LF | Windows 下 `io.open` 默认写 CRLF，必须显式 `newline="\n"` |

## 测试是怎么保证互不污染的

每条用例在 `tempfile.mkdtemp()` 里自建一个最小包，跑完 `shutil.rmtree`。测试之间没有共享状态，所以可以任意乱序执行，也不会碰到仓库里的真实文件。

## 一个刻意的设计

G07 断言的是「文本里不再出现 `--draft`」，而不是「那行被注释掉了」。

因为第一版实现就是注释掉，结果评测仍报同样的阻断——检测器不跳注释行。**断言要断言结果，不是断言动作。**

## 自检失败时怎么看

输出会列出失败项的 ID 与失败原因（例如 `(tags=2)` 表示补了但没补够）。按 ID 回到上表定位对应修复器，不要在整份文件里盲搜。

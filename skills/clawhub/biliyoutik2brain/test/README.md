# BiliYouTik2Brain 数据质量验证

## 核心理念

这不是"触发列表"或"测试用例库"。这些测试验证的是**确定性输出结构**：

- 管线返回的数据结构对不对？
- 字段路径对不对？值类型对不对？
- 之前出过的 bug（置信度字段路径写错→全线 N/A）能自动捕获

**跟今天说的"不做测试文件"不矛盾**：
- BG吴江数字人输出好不好你说算 → 建测试列表=触发表 → 不做
- BiliYouTik2Brain 输出是确定结构 → 建结构检查=质量门禁 → 要做

## 测试文件

| 文件 | 类型 | 用例数 | 运行方式 |
|:----|:----|:-----:|:--------|
| `eval_schema.py` | Schema验证 + 内部函数 + 回归 | 28 | `python3 test/eval_schema.py` |

### Schema 验证（核心价值最高）
- 管线输出的数据结构完整性
- 字段路径正确性（尤其是 `analysis.confidence_score` 嵌套路径）
- 值类型校验（float/int/bool/list）

### 内部函数验证
- `_guess_domain` — 无需管线运行的纯函数
- `_normalize_speaker` — 说话人别名归一化

### 回归检查
- curl E2BIG 回归 — payload 太大时检查是否用 -d @file 方案

## 运行

```bash
# 跑全部测试
python3 test/eval_schema.py

# 预期输出
# =================================================================
#   BiliYouTik2Brain — 数据质量验证测试
# =================================================================
#   ✅ Schema: analysis 字段结构  (6✓ 0✗)
#   ✅ Schema: 转录输出字段路径  (2✓ 0✗)
#   ...
# =================================================================
#   总计: ✅ 28 通过  ❌ 0 失败
# =================================================================
```

## 什么时候跑

- **每次修改 pipeline.py / schemas.py / speak_knowledge.py 后** — 确认没改坏结构
- **每次修改 batch 脚本后** — 确认字段路径正确
- **新增平台适配器后** — 确认 CollectResult 结构一致

## 添加新测试

在 `eval_schema.py` 中新增 `test_*` 函数，用 `check(name, condition, detail)` 注册断言，然后在 `ALL_TESTS` 列表中添加。不需要额外配置。

- 类型分布：[CREATE x1, ALTER x2, UPDATE x1, DROP x1]

## 二、风险清单
| 编号 | 位置 | 类型 | 等级 | 后果 | 建议 |
|------|------|------|------|------|------|
| S2 | UPDATE user | 破坏性 | 高 | 全表 status 被置 1 | 加 WHERE 主键条件 |
| S3 | ALTER big_t | 锁与可用性 | 高 | 大表 DDL 锁表 | 在线 DDL / 低峰分批 |
| S4 | ADD COLUMN | 数据一致性 | 高 | NOT NULL 无默认值报错 | 先可空+回填+改NOT NULL |

> 等级：高 / 中 / 低。类型取自 7 类：破坏性 / 锁与可用性 / 数据一致性 / 隐式类型转换 / 兼容性 / 可回滚 / 命名规范。

## 三、高危项展开
### [S2] 破坏性：无 WHERE 的 UPDATE
- 原语句：`UPDATE user SET status = 1;`
- 后果：全表 user 的 status 被置 1，影响全部用户
- 改写：
  ```sql
  UPDATE user SET status = 1 WHERE id = ?;  -- 明确主键/业务唯一键
  ```
- 是否需人工确认：是（确认影响范围）

## 四、执行顺序建议
1. [先跑：建表/加可空列等低风险 DDL]
2. [再跑：数据回填、加索引（在线 DDL）]
3. [分批次：大表 DDL 单独批次，低峰执行]
4. [先全量备份再跑不可逆操作]

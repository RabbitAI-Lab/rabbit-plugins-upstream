# SQL 变更脚本风险规则清单

7 类风险，覆盖上线前最易出事的场景。每条给出**判定特征 / 后果 / 改写建议模板**。扫描时逐类过，命中即记录等级与建议。

## 1. 破坏性（无 WHERE / DROP / TRUNCATE）

**判定特征**
- UPDATE / DELETE 缺少 WHERE 子句，或 WHERE 条件恒真（`WHERE 1=1`、`WHERE id>0` 覆盖全表）
- 出现 DROP TABLE / DROP COLUMN / TRUNCATE / DELETE 全表

**后果**
- 全表数据被错误覆盖或清空，通常不可逆

**改写建议模板**
- 缺失 WHERE：`UPDATE t SET col=? WHERE <明确主键或业务唯一键条件>;`
- DROP COLUMN：先 `SELECT * INTO backup_t FROM t;` 全量备份，再 DROP
- 等级：高危

## 2. 锁与可用性（大表 DDL / 在线 DDL / 长事务）

**判定特征**
- 对大表（或"若超百万行"）做 ALTER、加索引、改列类型
- 加索引未声明在线 DDL
- 单条事务包含大量行操作，可能造成长事务/锁等待

**后果**
- 表锁或元数据锁导致读写阻塞，线上接口超时，甚至雪崩

**改写建议模板**
- MySQL 加索引：`ALTER TABLE t ADD INDEX idx_col (col), ALGORITHM=INPLACE, LOCK=NONE;`
- 大表改列类型：先加新列 → 回填 → 删旧列重命名，分批次
- 等级：高/中（视表量级）

## 3. 数据一致性（NOT NULL / 截断 / 字符集）

**判定特征**
- 新增 NOT NULL 列但无默认值，且表可能非空
- 改字段长度（如 VARCHAR(255)→VARCHAR(50)）可能截断数据
- 字符集 / 排序规则变更，导致既有数据乱码或比较行为变化

**后果**
- 非空表加 NOT NULL 无默认值直接报错；截断丢数据；字符集不一致引发乱码

**改写建议模板**
- NOT NULL：`ALTER TABLE t ADD col TYPE NULL; UPDATE t SET col=<默认值> WHERE col IS NULL; ALTER TABLE t ALTER col SET NOT NULL;`
- 缩短长度：先 `SELECT MAX(LENGTH(col))` 核实最长值，确认不截断再改
- 等级：高/中

## 4. 隐式类型转换（索引失效）

**判定特征**
- WHERE 条件中字段类型与传入值类型不匹配，如 `varchar` 列传数字、`date` 列传字符串未加引号
- 函数包裹索引列（如 `WHERE DATE(create_time)=?`）

**后果**
- 触发隐式转换，索引失效，全表扫描，大表上性能骤降

**改写建议模板**
- `WHERE varchar_col = '123'`（加引号，保持类型一致）
- 避免对索引列套函数，改为范围比较
- 等级：中

## 5. 兼容性（废弃语法 / 保留字 / 方言混用）

**判定特征**
- 使用已废弃语法（如旧版 `GROUP BY` 非全聚合、MySQL 旧式 `!=` 混用）
- 未转义的保留字作列名/表名（如 `order`、`user`、`desc`）
- 混用方言（MySQL `LIMIT`、Oracle `ROWNUM`、PG `RETURNING`）未标注目标库

**后果**
- 在目标库执行报错，或不同库行为不一致

**改写建议模板**
- 保留字加引号：`"order"` / 反引号 `` `user` ``（按目标库选）
- 缺库类型时并列各方言写法并标"需确认具体库"
- 等级：中

## 6. 可回滚性（缺回滚 / 不可逆操作）

**判定特征**
- 整个变更脚本没有对应回滚脚本
- 含不可逆操作：DROP、TRUNCATE、DELETE 全表、数据清理、改列类型丢失信息

**后果**
- 出问题时无法快速恢复，只能靠备份兜底，恢复窗口长

**改写建议模板**
- 每类操作配回滚：CREATE ↔ DROP；ADD COLUMN ↔ DROP COLUMN（先备份）
- 不可逆操作标注"无安全回滚，上线前必须全量备份"
- 等级：高（不可逆）/ 中（仅缺回滚脚本）

## 7. 命名与规范（表名/字段名 / 注释 / 索引外键）

**判定特征**
- 表名/字段名不符合团队命名约定（如驼峰 vs 下划线、前缀缺失）
- 新建对象无注释（COMMENT）
- 关联字段缺索引或外键，关联查询性能差或数据孤儿

**后果**
- 可维护性差、协作混乱、隐性性能与数据质量问题

**改写建议模板**
- 统一命名；建表/加列补 `COMMENT '含义'`
- 关联字段补索引：`CREATE INDEX idx_fk ON t(fk_col);`
- 等级：低（规范类，不阻断上线但建议修）

# 排错与合规

## 驱动失败对照表

讲师"不对劲"时，**先回头看底图**，90% 的问题在那一步就注定了。

| 症状 | 真因 | 修法 |
|---|---|---|
| 嘴型飘、对不上音 | 底图侧脸角度过大 | 重出底图，正脸或侧脸 ≤ 20° |
| 嘴部糊成一团 | 面部像素太少 | 换近一档景别；语言课务必用 1080p |
| 眼神呆滞或闪烁 | **底图眼镜片上有反光白块** | 重出，或直接去掉眼镜 |
| 下巴穿帮、脖子扭曲 | 底图下巴被裁切 | 底图必须完整露出下巴与颈部 |
| 手部出现鬼影 | 底图里手在胸口以上 | 手放桌沿以下，或不入镜 |
| 驱动到了错误的人 | 底图有第二张脸（背景海报、照片） | 背景不能有任何人脸 |
| 面部忽明忽暗 | 底图有斑驳阴影（百叶窗、树影） | 补光消除斑驳，或换纯色背景 |
| 表情僵硬像蜡像 | 底图过度磨皮，失去皮肤纹理 | prompt 加"真实皮肤纹理，不做过度磨皮" |
| 叠上课件后文字看不清 | **底图留白区有明暗变化或光斑** | 重出，留白区要明度均匀 |
| 圆形小窗裁掉了下巴 | 底图下缘余量不足 | 用配方 13，下缘留足余量 |

后三条是课程版特有的，带货版不会遇到。

## 报错对照表

| Code | 含义 | 处理 |
|---|---|---|
| 400 | 参数非法 | 多半是尺寸写法错了或 prompt 超上限，见下 |
| 401 | `unauthorized` | `dlazy login` 或 `dlazy auth set <key>` |
| 501 | 缺必填参数 | `error: required option '--prompt' not specified` |
| 502 | 本地文件读不到 | 检查路径，Windows 下注意反斜杠转义 |
| 503 | `insufficient_balance` | 充值：https://dlazy.com/dashboard/organization/settings?tab=credits |
| 504 | 异步任务失败 | 看 `=== Generation Failed ===` 后面的真实原因 |

### 400 最常见的三种

**横竖屏写反了。** 课程版最高频的错误：

```
✅ --size 3840x2160    横屏 16:9 4K
❌ --size 2160x3840    竖屏 9:16（这是带货版的）
```

**写反不会报错**——两个都是合法枚举值。你会拿到一张竖图，然后在装配那一步才发现，中间的驱动积分已经花掉了。从带货技能复制命令过来时，这一处必须改。

`1536x1024` 是 **3:2 不是 16:9**，做课程封面会被平台裁掉两边。

**提示词超上限。** 整次请求被拒，不是截断，积分不退：

| 上限 | 模型 |
|---|---|
| 300 | `jimeng-omnihuman-1.5`（且可选） |
| 500 | `seedream-5.0` 全系、`jimeng-t2i` |
| 512 | `qwen-tts` |
| 1300 | `qwen-image-2-pro` |
| 2000 | `gpt-image-2`、`banana-pro`、`banana2` |

正文段写满 512 是本技能推荐的省钱做法，**但别写超**。留 10 字符余量，标点也算字符。

**尺寸写法串了模型。** 六种互不通用：

```
gpt-image-2      --size 3840x2160        （像素，用 x，固定枚举）
qwen-image-2-pro --size 2688*1536        （像素，用 *）
seedream-5.0     --size 16:9 --resolution 4k
banana-pro       --aspectRatio 16:9 --imageSize 4K   （驼峰）
seedance-2.5     --ratio 16:9 --resolution 1080p
kling-v3         --aspect_ratio 16:9     （下划线）
```

**音频超时长上限。** `jimeng-omnihuman-1.5`：1080p ≤ 30 秒，720p ≤ 60 秒。超了直接拒。正文段的长音频**不要送进驱动**——它们本来就不该驱动。

## 中文 prompt 的编码陷阱（重要）

**最隐蔽也最贵的坑。** 症状：命令返回 `ok: true`，但出来的图跟 prompt 毫无关系——通常是一张"通用美女写真"，你要的书房、白板、留白区全部被无视。

原因不是模型跑偏，是 **prompt 在传到 API 之前就被编码破坏成乱码了**。模型收到乱码，只能靠残存字节碎片自由发挥，回落到训练集里最高频的人像模板。

最常见的触发方式是在 Windows 上用脚本拼命令行：

```bash
# ❌ 危险：Python 在 Windows 下 stdout 默认走 GBK，
#         bash 按 UTF-8 读，中文全变乱码，且不报任何错
P=$(python -c "print(open('prompt.txt',encoding='utf-8').read())")
dlazy gpt-image-2 --prompt "$P" ...
```

**正确做法：用 `--input` 传 UTF-8 的 JSON 文件，让 prompt 不经过 shell。**

```bash
cat > payload.json <<'EOF'
{"prompt": "一位 38 岁左右的亚洲男性知识课程讲师...", "size": "3840x2160", "quality": "high", "imageFormat": "png"}
EOF
dlazy gpt-image-2 --input @payload.json --save ./lecturer/base.png
```

`--input` 每个工具都支持，flag 值可以和 JSON 混用（flag 优先）。**课程是批量生产，一律走这条路。**

**自检方法**：出图明显跑偏时，先别改 prompt——把同一段中文直接内联到命令行手动跑一次。内联能出对图、脚本出错图，就是编码问题，不是提示词问题。

乱码 prompt 也可能触发 `safety_violations=[sexual]`，因为破碎的字节序列会被安全分类器误判。看到这个错误先查编码，再怀疑用词。

## 长课程批处理陷阱

一节课十几段、一门课几十节，这些问题带货版（单条 3 段）根本遇不到。

**1. 文件名用两位数补零。**

```
❌ body1 body2 ... body10 body11     字典序排成 body1, body10, body11, body2
✅ body01 body02 ... body10 body11   顺序正确
```

`ffmpeg -i` 的顺序、`for f in *.mp4` 的展开顺序都按字典序。**一节课的章节被打乱顺序而你没发现**，是这条流水线最尴尬的失败方式。

**2. 时长会累积漂移。**

带货版实测：omnihuman 成片比输入音频长 **0.1~0.2 秒**。单段无所谓，但一节课 8 段露脸累积下来是 **0.8~1.6 秒**。

如果你的字幕时间轴是按讲稿字数估算的，**到片尾会明显对不上**。两个解法：

- 装配前用 `ffprobe` 读每段的**实际时长**，用实测值排时间轴，不要用估算值
- 或者让 `file-to-video` 模板处理字幕，它按真实素材时长对齐

```bash
for f in clips/*.mp4; do
  echo -n "$f "; ffprobe -v error -show_entries format=duration -of csv=p=0 "$f"
done
```

**3. 断点续跑。**

十几次驱动调用，跑到第 9 段失败，不该从头再来（前 8 段的积分已经花了）。脚本里加存在性判断：

```bash
for seg in trans1 trans2 trans3 trans4 trans5 trans6; do
  [ -f "./clips/$seg.mp4" ] && { echo "skip $seg"; continue; }
  dlazy jimeng-omnihuman-1.5 --images ./lecturer/11-third.png \
    --audio ./audio/$seg.wav --input @payload/drive.json \
    --resolution 720p --save ./clips/$seg.mp4
done
```

**4. 跨节次的一致性漂移。**

一门课录到第 12 节，你可能已经忘了当初用的是哪个音色、哪张底图。**开课时就把这几项写进项目根目录的配置文件**，每节课从它读：

```json
{
  "lecturer_base": "./lecturer/11-third.png",
  "lecturer_full": "./lecturer/12-full.png",
  "voice": "Ethan",
  "drive_prompt": "人物自然讲解，幅度克制，偶尔轻微点头，身体基本不动",
  "resolution_talk": "1080p",
  "resolution_trans": "720p"
}
```

底图文件**要备份**。丢了就再也回不到同一张脸，整门课的形象断档。

## 省积分策略

按性价比排序：

1. **砍露脸时长。** 驱动占 95%。这是唯一数量级的杠杆——串行形态比全程画中画省 10 倍，细节见 `pipeline.md` 开头。
2. **转场段降 720p。** 15 积分/秒 vs 23，省 35%。转场只有 10 秒且景别偏侧，观众看不出。开场结尾留 1080p。
3. **正文 TTS 写满 512 字符。** 固定 6 积分/次，写满是 10 次调用，切碎是 38 次，白花 168 积分。
4. **底图整门课复用。** 157 积分摊到 30 节，每节 5 积分。
5. **章节转场卡替代部分露脸。** 六次转场留三次露脸，其余用纯课件动画。
6. **先 `--dry-run`。** 一节课十几次调用，参数写错一个字母就是几百积分。

**不要在底图上省。** 底图差 → 驱动失败 → 整节课重跑。这笔账永远不划算。

## 教培合规红线

**这一套跟带货完全不同，别把带货版的合规清单套过来。** 教育培训广告受《广告法》第二十四条专门规制，比一般商品广告严得多。

**四条硬禁止**（第二十四条）：

1. **不得对升学、通过考试、获得学位学历或合格证书作保证性承诺**，也不得对培训效果作明示或暗示的保证。
   - 禁：「包过」「保过」「一次上岸」「学完必会」「通过率 98%」「不过退费」（作为效果承诺时）
2. **不得明示或暗示有考试机构、其工作人员、命题人员参与培训。**
   - 禁：「命题组老师授课」「内部押题」「考试院背景」
3. **不得利用科研单位、学术机构、教育机构、行业协会、专业人士、受益者的名义或形象作推荐、证明。**
   - 这条对数字人**尤其致命**：用数字人扮演"往期学员"讲述学习效果，是用受益者形象作证明，**同时还是虚构的**，双重违规。
   - 学员证言、前后成绩对比、"我用了三个月从 60 分到 130 分"——全部禁止。
4. **虚构师资与资质。** 数字人讲师不得被包装成"某某大学教授"「二十年教龄名师」等未经证实的身份。`recipes.md` 配方 07 反复强调"无任何证书奖状徽章"就是为此——模型会自己编造机构名挂在墙上。

**视觉红线**：

- 白大褂、诊室、实验室 → 非持证主体禁用
- 证书、奖状、胸牌、机构 logo → 出图后逐项检查并删除，模型编造的机构名是虚构资质
- 背景里的可读文字 → 所有配方都写了"无任何可读文字"，别删这句

**面向未成年人的额外限制**：学科类校外培训的广告投放在多地有专门限制，面向学龄前儿童的线上培训被明确禁止。做 K12 内容前先确认当地现行规定，这块政策变动频繁。

**AI 生成内容标识**：我国已施行 AI 生成合成内容标识要求，数字人讲师视频属于典型的 AI 生成合成内容。发布时按平台要求勾选「内容由 AI 生成」，抖音、快手、B 站、视频号均有对应开关。付费课程还建议在课程介绍页显性说明讲师形象为 AI 生成——**这既是合规要求，也能避免学员事后以"虚假宣传"投诉退款**。

法规会变，上面是写作时的通行理解，**不构成法律意见**。正式商用前请让法务过一遍课程文案。

## 什么时候不该用数字人

诚实地说，这几种情况真人出镜更好：

- **需要演示操作的课**——数字人只能说话，不能拿教具、不能写板书、不能操作软件。软件课直接录屏 + 配音，比数字人合适得多。
- **强人格 IP 的课**——知识付费的溢价很大程度来自"这个人"。老师本人有影响力时，数字人是在稀释资产。
- **需要即时互动的直播课**——数字人是预渲染的，答不了问。
- **已有真人素材、只是要换语言**——直接用 `videoretalk` 或 `sync-lipsync-3` 做口型替换，不需要重造一个人。

数字人的真正优势是**批量与一致性**：一门课几十节，同一个形象、同一个音色、随时可改稿重出，不用约老师档期、不用重打光、改一句话不用重录一整节。用在这个场景上才划算。

课程内容的价值在于讲得对不对、清不清楚——**这件事数字人帮不上忙，讲稿才是**。把省下的时间花在 ② 上。

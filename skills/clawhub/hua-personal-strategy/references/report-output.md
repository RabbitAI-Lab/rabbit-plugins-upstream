# 报告输出契约

本文件只约束投资内容、数据口径和审计字段，不约束 HTML 视觉设计、页面布局、组件、样式、动效、响应式实现或前端技术栈。Hermes/调用方 Agent 可以自行设计页面，只要不改变策略结论、字段口径和风控含义。

## 一、通用原则

- 报告只呈现同一轮 HuahuaDaily MCP 数据、东方财富 skill 证据、Serenity 研究证据和 `scripts/signal_rules.py` 结果；不得引入旧结论、手工覆盖或页面端二次推理。HuahuaDaily MCP 数据优先来自 `get_quant_strategy_context`，细粒度接口只作为钻取或降级来源。
- Markdown、HTML、App 页面、截图卡片和 `save_quant_snapshot` 必须来自同一份 `work/hua-quant-input.json` 与 `work/hua-quant-result.json`。
- 不展示实现过程、代码修改、工具失败、缓存、同步修复、旧页面复用、skill 调整等施工痕迹。报告只写投资数据、信号、门禁、动作和风险。
- 主文案必须中文化；内部码只允许出现在 JSON、审计附录或调试文件中。用户可见内容不得出现 `neutral`、`risk_off`、`fresh`、`veto`、`ADD` 等未解释术语。
- 中国市场色彩口径：红涨绿跌。
- 组合净值涨幅、组合累计收益、组合最大回撤和波动只使用官方净值/服务端组合历史；不得混入盘中估值或 QDII 夜盘。
- 盘中执行回撤估算必须单独展示：它用 A 股实时估值和 QDII 夜盘按持仓权重估算今日冲击，只用于风控门禁和执行判断，不计入真实收益、组合净值或官方最大回撤。

## 二、必须展示的数据指纹

每份报告必须能回答“这份结论基于哪一刻的数据”：

- 运行时间，必须注明北京时间。
- 交易窗口状态：15:00 前可用于当日申赎参考；15:00 后只能作为当日复盘和下一交易日候选，不能写“今天加仓/今天卖出/今天执行”。
- 持仓同步时间、组合历史截止日期、行情/估值时间、QDII 夜盘时间。
- `get_quant_strategy_context.portfolio.risk.configuredMaxDrawdownLimitPct` 或降级路径中 `get_records.strategyPreferences.maxDrawdownLimitPct` 的实际读取值。若为 0，写“未启用组合最大回撤门禁”；不得自行假定 10% 或 15%。
- 官方最大回撤、官方当前回撤、盘中执行回撤估算三项必须分开写。若官方回撤未触发但盘中执行回撤估算触发阈值，动作摘要必须写“官方净值尚未确认触发，盘中执行风控已触发/接近触发”。
- 数据质量：组合历史覆盖率、净值覆盖、缺失基金、QDII 官方收益归属是否可靠、QDII 夜盘是否 fresh/ready、东方财富新闻/情绪是否成功取得。
- 若报告数据已过期，只能输出复盘/参考结论，不得输出可执行金额。

## 三、动作摘要

报告开头必须先给动作结论，不能让用户读完整份报告后才知道怎么做。

动作摘要至少包含：

- 总动作：执行新增、执行调出、暂停新增、暂停调出、维持定投、暂停定投、方向候选跟踪、全部不动等明确动作。
- 组合层动作：若处于强防守或熊市验证期，必须写明 `转入防守仓` 或 `现金等待`，并说明这是组合/方向层安排，不是逐基金引擎动作。
- 买入金额、调出金额、可用资金、定投资金占用。若不建议金额，必须明确“本轮不生成建议金额”。
- 本轮为什么能动或不能动：交易时间、官方组合回撤门禁、盘中执行回撤门禁、现金门禁、数据门禁、QDII 夜盘门禁、定投门禁。
- 若超过 15:00：改写为“下一交易日候选动作”，不得写当日执行。

推荐动作词必须具体，避免“复核”“关注一下”“看情况”等把判断责任退给用户的词。可用动作包括：

- 买入 / 不买入 / 暂停新增
- 卖出 / 暂不卖出
- 定投继续 / 定投暂停 / 定投转向
- 调出到候选方向 / 暂不轮动
- 转入防守仓 / 现金等待
- 方向候选跟踪，等待净值、交易窗口或证据确认；这不是交易动作

**术语红线：**
- **"追涨"只用于价格上涨时**：当盘中/实时涨幅 ≥ +2%（CHASE_RISK_PCT）且趋势未确认时才可写"追涨风险"。当基金/板块当日下跌时，不得写"不追涨"——下跌时买入是"低吸"或"回落买入"，不是追涨。
- **下跌日的正确表述**：大跌日（跌 > 3%）若信号允许买入，应写"回落买入窗口"或"大跌低吸信号"，不得写"不追涨"或"等待回落"（已经在回落了）。
- **"等待回落"只用于上涨时**：当实时涨幅偏大但趋势未确认时写"等待回落"。当已经跌了，不写"等待回落"。
- **引擎信号不可覆盖**：`trade_action.label`（如"小额新增""回落再买""禁止新增"）必须原样展示。LLM 不得用"建议观望""等待确认""震荡市不追涨"等自创措辞替换引擎信号。

## 四、组合复盘与组合建议

报告必须使用 `get_quant_strategy_context.portfolio.risk` 或降级路径中的 `get_portfolio_nav_history` 给出真实组合复盘，并明确这是“组合净值表现”，不是账户现金收益或交易收益。

### 4.1 市场状态与下跌性质

涉及牛熊、离场、减仓、避险或板块迁移时，报告必须先给三层市场判断，不能只展示逐基金评分：

- **A股整体模式**：上证指数、沪深300或中证A500、创业板、科创50；尽量包含日线、周线、月线/年线。缺少周期时写明“未取到”，不得假装判断。
- **成长风格模式**：科创50、创业板、半导体ETF、AI/科技代表、恒生科技、纳指100/KOSPI。
- **持仓加权模式**：方向权重、风险贡献、高相关簇、实时估值和 QDII 夜盘。

必须明确 `下跌性质`：

- 杀杠杆/杀拥挤；
- 杀估值；
- 牛市洗盘；
- 系统性熊市；
- 暂无法确认。

每个分类必须给出证据和下一交易日验证条件。不得只写“风险较大”“趋势不好”。

组合复盘至少包含：

- 区间收益、累计净值表现、最大回撤、年化波动、相对沪深300表现。
- 最大回撤是否触发用户设置的组合门禁。
- 回撤渐进响应：官方当前回撤和盘中执行回撤估算分别处于 normal/watch/cautious/defensive/critical/breached 哪一档；交易门禁使用更保守口径，仓位系数是多少，是否已接近阈值。
- 组合风险暴露：方向权重、方向平均波动、风险贡献、风险平价目标和偏离。
- 高相关持仓：若基金间相关系数 ≥0.8，必须提示这些基金不是独立风险源。
- 长期拖累项：哪些基金或方向对组合净值、回撤、波动、近 1/3/6 月轮动表现形成拖累。
- 贡献项：哪些基金或方向提供了相对收益、风险对冲或趋势优势。
- 组合优化建议：继续持有、降低新增、停止定投、转向候选方向、等待数据补齐、或不做迁移。
- 定投影响：若 MCP 提供定投计划，必须说明定投会占用多少月度资金、是否应继续、暂停或转向；不能只看一次性加仓。
- 防守资金安排：若建议降低权益暴露，必须说明卖出/赎回后的资金是现金等待、货基/短债/纯债、黄金、红利低波观察，还是保持未配置。宽基只能写作低 Beta 权益观察仓，不能写作避险资产。
- 防踏空卖出审查：每个主要调出方向必须说明是弱腿/重复暴露/高风险贡献，还是核心强势资产；若保留同方向强腿，写明保留的反弹敞口；若方向清零，写明重新进入条件。

组合建议必须先看组合层，再看单基金层。单基金评分不能替代组合优化。

报告必须展示自适应策略状态：
- 波动率状态（LOW/NORMAL/HIGH/EXTREME）及年化波动率数值
- 趋势状态（STRONG_UP/UP/SIDEWAYS/DOWN/STRONG_DOWN）
- **多指数基准分解**：展示各指数今日表现及加权组合表现（不能只看沪深300）
  - 科创50、半导体ETF、韩国KOSPI、纳指100、恒生科技、沪深300
  - 加权组合今日涨跌幅（这才是真实的组合方向风险）
- 自适应调仓参数（最小偏离阈值、最大仓位、信号置信度）
- 今日是否通过频率门禁（should_trade）
- 波动率调整后的仓位大小（与无调整对比）
- 风险平价诊断：当前方向权重与风险平价目标的偏离；仅作为组合建议和风险提示，不自动生成交易。

## 五、逐基金多因子解释（强制，不可跳过）

**这是报告的核心章节之一。每只持仓基金必须单独展示一张多因子解读卡片，不得合并、省略或用汇总表替代。**

每只持仓基金必须给出"分数怎么来的、动作为什么这么做"，但不要把原始字段堆成字段墙。

**每只基金卡片必须包含以下全部字段（缺一不可）：**

1. **综合分与等级**：0-100总分 + 等级（强势/偏强/中性/偏弱/弱势）
2. **六个分项分**：价格趋势分、BIAS/均值回归分、风险分、执行分、证据分、数据质量分
3. **价格/趋势**：近1月、近3月、近6月、近1年、轮动加速度
4. **BIAS/均线**：BIAS20数值、MA20位置、MA60位置、是否死叉
5. **风险**：单基金历史最大回撤（%）、年化波动率（%）、组合权重（%）
6. **执行层**：今日估值涨跌、QDII夜盘涨跌（如有）、估值时间、数据新鲜度
7. **证据**：消息面状态（supportive/neutral/negative）、情绪面状态（risk_on/neutral/risk_off）
8. **数据质量**：净值覆盖天数、是否完整、缺失警告
9. **最终动作**：从引擎trade_action.label原样展示（不得改写）
10. **一句话主因**：为什么是这个动作
11. **关键风险**：什么条件下需要重新评估

**展示格式示例：**
```
014855 嘉实半导体增强 | 半导体 | 权重10.1% | 综合分 86（偏强）
├─ 价格趋势：近1月+28.8% | 近3月+77.3% | 轮动加速+3.0%
├─ BIAS/均线：BIAS20=+5.2% | MA20↑ | 无死叉
├─ 风险：回撤-18.3% | 波动36.9% | 权重10.1%
├─ 执行层：今日-5.73%（估值）| 数据新鲜
├─ 证据：消息面supportive | 情绪面neutral
├─ 数据质量：净值244天 | 完整
├─ 动作：小额新增 ¥350（限购cap+波动率调整后）
├─ 主因：BIAS20正值+方向动量前2+均值回归信号
└─ 风险：若BIAS20突破+10%或回撤超-25%需重新评估
```

必须解释的因子：

- 价格/趋势：近 1 月、近 3 月、近 6 月、近 1 年、轮动加速度、相对强弱。
- BIAS/均线：BIAS20、MA20/MA60 或可用的等价趋势距离；若净值缺失，必须写清缺失原因和中性处理。
- 风险：单基金回撤、波动、组合权重、是否拖累组合回撤。
- 执行：实时估值、QDII 夜盘、交易时间、申购赎回状态、限购、确认天数和数据门禁；费率只作背景，不进入核心信号或回测收益。
- 证据：东方财富新闻/公告/研报/资金流、Serenity 产业链判断和反证。
- 数据质量：净值是否完整、QDII 是否滞后、消息/情绪是否取到、是否只能降级观察。

每只基金必须输出：

- 综合分与等级。
- 六个因子分或等价分项。
- 明确动作。
- 一句话主因。
- 关键风险。
- 动作门禁：哪些门禁通过，哪些门禁阻断。

若用户问“为什么”，报告应该能直接用因子解释回答，而不是只给“偏弱/偏强/不新增”。

## 六、净值与估值口径

所有基金（含 QDII）：
- `get_item_estimate` 接口返回时自带 `source` 和 `gztime` 字段
- `source=official_published` → 官方净值已出，标注"净值"
- QDII/T+N 的 `gztime/navDate` 只说明 D 日（净值数据日），不自动等于 G 日（收益归属日）。只有 `displayDate`、`lastNavPublishDate`、`estimateVsActual.publish_date` 或服务端统一归属结果能证明 G 日；缺少时写“官方净值未可靠归属”，不得猜“归属今日”
- `source` 为其他值 → 仍在估值阶段，标注"估值"
- 不要用 15:00 硬判断，以接口返回的 `source` 和 `gztime` 为准

QDII 必须分清三个概念：
- **官方净值复盘**：只在实际公布且 G 日可靠时计入真实持仓收益、组合收益和回撤。报告可同时显示 D 日与 G 日，例如“净值日 7/13，收益归属 7/14”。
- **估值接口**（`get_item_estimate`）：解释当前估值、官方公布状态和归属证据；不代表今天还能吃到的新增机会。
- **夜盘接口**（`get_night_estimate`）：用于判断今天申赎时点之后海外市场的新增变化，是当天加减仓参考，不计入真实收益。QDII 加减仓幅度必须挂在夜盘涨跌、覆盖率、汇率和新鲜度上。
- **内部股票涨幅**：只作为夜盘估算拆解展示，必须显示覆盖率/缺失/汇率。不得把某个重仓股涨跌直接写成基金真实收益。

报告不得写“QDII 不抢跑”这类含糊话。应写清：
- 今天的收益复盘看官方净值和估值归因
- 今天是否申赎看夜盘方向、覆盖率、汇率、波动和风险
- 夜盘强但组合回撤/交易窗口/数据门禁阻断时，不生成可执行新增
- 若夜盘缺失或 stale，动作写“禁止新增/只复盘”，不要写“看夜盘”

## 七、板块迁移与点名基金比较

若用户要求板块迁移、方向迁移或比较某只基金：

- 必须先判断现有组合是否需要迁移：长期拖累、回撤压力、趋势衰减、定投占用、相关性过高。
- 当前策略不做自然语言全市场选基，不输出系统生成的候选基金池。
- 东方财富 skill 用于已知代码查数、资讯、公告、研报和方向数据验证；只有未来存在专用结构化筛选接口，才允许输出系统筛选基金。
- Serenity 用于产业链和主题方向判断，不直接替代基金筛选。
- 用户点名基金、自选池基金或未来专用筛选接口返回的基金，必须通过净值、规模、跟踪误差、回撤、流动性、申购限制、持仓方向和数据质量检查。费率可作为背景比较，不得单独触发买入或卖出。
- 不满足数据质量时，只能标为“点名比较/方向跟踪”，不得写成确定买入。
- 熊市/强防守模式下，板块迁移必须包含非权益防守方向：现金/货基、短债/纯债、黄金、红利低波。若不能稳定选出具体基金，仍要输出资产方向和“现金等待”，不能只说“无候选基金”。

## 八、快照保存

若本轮完成量化复盘，必须调用 `save_quant_snapshot` 保存信号档案，除非用户明确要求不要保存。

快照必须包含：

- 策略 ID、版本、数据截止时间、幂等键。
- 真实持仓及组合版本。
- 市场状态、组合风险、实际读取的回撤阈值。
- 每只基金观察值：`ADD`、`HOLD`、`REDUCE`、`WATCH` 或 `EXIT`。
- 特征值、分项分、风险警报、数据质量和置信度。

快照不下单，不生成真实交易，不维护影子现金或模拟收益。

## 九、可视化与样式

报告样式必须符合用户偏好：
- **白色背景**，不要深色/暗黑主题
- **红涨绿跌**（中国市场惯例）：上涨/正收益用红色（#ff3b30），下跌/负收益用绿色（#34c759）
- **iOS 风格**：简洁、轻量、无大色块、无 AI 味
- **hover 状态**：表格行 hover 用浅灰（#f5f5f5），不要深色
- 不要用 CSS 变量套暗色主题再手动覆盖，直接用白底配色

本 skill 不规定页面拓扑、组件、字号、卡片、表格、图表、动效或响应式方案。

调用方 Agent/Hermes 可以用任意形式呈现：

- Markdown
- HTML
- App 内页面
- 图表化报告
- 卡片式摘要
- PDF 或截图

唯一硬约束：

- 不得改变策略结论。
- 不得隐藏风控阻断和数据缺口。
- 不得把不可执行信号呈现为可执行交易。
- 不得把原始字段堆砌成用户无法理解的报告。
- 不得把开发/调试过程写进投资报告。

本 skill 不内置 HTML 渲染器；页面呈现由调用方 Agent/Hermes 自行实现。

## 十、输出前自检

输出前逐项检查：

- 是否读取并展示真实回撤阈值，而不是写死 10%/15%。
- 是否正确处理 15:00 交易窗口。
- 是否区分组合净值表现、真实收益、估值和 QDII 夜盘。
- 是否包含组合建议，而不仅是单基金评分。

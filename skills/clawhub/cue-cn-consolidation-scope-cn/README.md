# 合并范围·逐条挂源

给一份财报或公告，把**合并范围**这一块读成一张**每条都能回到原句**的登记表：合并范围概况、本期新纳入、本期不再纳入、持股比例与表决权、未合并主体与理由。

合并范围是报表里最容易被想当然的一块：并进来的、出去的、没并的，三种状态各有各的缘由，而缘由只有披露知道。持股 51% 不等于控制，转让全部股权与被稀释后仍持股更是两件事。本件逐条登记披露原话，判断留给人。

控制结论只认披露原文，转换式的因果推断不写；未合并主体的理由照抄，不用「不重要」这类概括顶替。

本件不判某主体应不应当合并、不评子公司经营质量、不给评级与目标价。

## 一、三分钟上手

不给任何数据文件，也能跑出一份完整合规的成品，看它长什么样、判据怎么打：

```bash
python3 scripts/check_consolidation_scope.py --demo
```

把这份样例存下来再跑一遍机检：

```bash
python3 scripts/check_consolidation_scope.py --demo > 样例合并范围稿.md
python3 scripts/check_consolidation_scope.py 样例合并范围稿.md
```

接着换成你自己那份稿子：

```bash
python3 scripts/check_consolidation_scope.py 你的合并范围稿.md
```

退码 `0` 全过、`1` 有发条、`2` 缺参数、`3` 读不到文件或空稿。

拿不到成品时，从原文开始的三步：

1. **定主体与报告期**，拿到年报或半年报原文（附注「合并范围」「合并范围变动」「在其他主体中的权益」三处）。
2. **每节抄事实，连原句一起抄**：一条 = 一行，行末挂 `「原句」〔锚：页/表〕[S#]`。
3. **跑一遍自检**，红一条改一条：

```bash
python3 scripts/check_consolidation_scope.py --selftest   # 8 档内置夹具自检
```

## 二、五道机检在管什么

| 码 | 名称 | 判什么 | 最常拦住的情况 |
|---|---|---|---|
| `CS-STRUCT` | 形制 | 头部四件自标逐字在位、`主体：`／`报告期：` 行在场非空、七节齐且按序、前五节各至少一条发现行、节内只许 `- ` 行 | 把 `主体：` 写成 `- 主体：`；某节只有散文没有发现行；节序被调换 |
| `CS-QUOTE` | 原句与锚 | 发现行以「」原句＋〔锚：…〕＋`[S#]` 收尾且三元组落在行末；来源行带可点 URL 与检索日；引用的编号须已登记 | 只写数字没抄原句；正文引用了 `[S3]` 而来源节没有这一号 |
| `CS-PCT` | 比例与结论不得互推 | 登记值写了结论词、同一行原句里却只有持股比例——判为按比例反推 | 原句只写「本公司持股 51%」，登记值写成「纳入合并 持股 51%」 |
| `CS-SCOPE` | 两种缘由不得合并 | 一行里同时出现卖掉词（处置／出售／转让）与结论词（丧失控制权／不再纳入合并），而原句里没有「丧失控制权」这个说法 | 把「转让全部股权」写成「转让股权并丧失控制权」 |
| `CS-GAP` | 未合并理由与两向点名 | 未合并主体的理由须为原文（「不重要」「未达标准」「金额较小」一律发）；正文与第六节互相对账；零缺口须写 `未取到：无` | 用概括顶替理由；正文写了未取到而第六节没列 |

**第五道判什么**：未合并主体的理由须为原句——原句为空而登记值里出现「不重要」这类概括的，一律发；正文写「未取到 X」而第六节没点名 X、或第六节点名了 X 而正文没有对应行的，两向都发；全文无缺口却没在第六节显式写 `未取到：无` 的，发；「不适用」「无此项」「无需披露」这类搪塞词一律发（未取到与不适用是两件事）。五道现读全已落字，`--selftest` 八档：不合=0、不可判=0。

## 三、三条红线（这件的立身之本）

1. **控制结论只认原句。** 持股比例是比例，不是结论。「持股 51%，故纳入合并」是反推；原句只说比例、没说控制与否的，正确写法是控制结论未取到。
2. **「处置卖掉」与「丧失控制权但仍持股」是两件事。** 同一主体只标一种缘由：转让股权后不再持有的标处置卖掉；增资扩股、被动稀释后仍持有的标丧失控制权但仍持股，并给出丧失控制权后的持股比例（照抄原句）。
3. **未合并主体的理由只认原文。** 附注写「不具有控制权」「仅具有重大影响」就照抄；披露没给理由的写理由未取到，不用概括顶替——那不是披露的话，是本件替披露下的判断。

## 四、数据通道

发现先行，匿名取目录，拿到 `routing` 后再连接发 `tools/list`，以现场返回为准，不硬编码工具名与工具数：

```bash
curl -sS https://cuecue.cn/api/mcp-catalog -w '\nHTTP %{http_code}\n'
# 拿到 routing 后，带 token 发 tools/list：
curl -sS -X POST "$ROUTING_URL" -H "Authorization: Bearer $CUE_API_KEY" -d '{"jsonrpc":"2.0","method":"tools/list"}'
```

- **原文腿**：财报附注、合并范围变动公告、股权转让公告的原文走数据腿；该域是否开放、是否实时，以 catalog 返回为准。
- **正文腿**：附注常夹在几百页 PDF 里（合并范围表、变动明细表、在其他主体中的权益表），长附件与扫描件交 `cue-omni-reader` 解析——先取大纲，再按节取用；计费与可用性以服务端返回为准。
- **深研**：`cue-research` 是独立入口（自带运行脚本），凭据同一把 key。
- 配置页只给指针、不复述开通步骤：数据腿 <https://cuecue.cn/hub/mcp>；解析腿 <https://cuecue.cn/hub/omni-reader>；取 key <https://cuecue.cn/hub/api-key>。

没配凭据时，只能从用户直供的文件里登记，看不到交易所原文那一路，附注明细也只在手头文件里翻。

本件不发请求、不代付费，消耗以服务端返回为准。

## 五、和另外几枚包怎么分

| 你手上是 | 用哪枚 |
|---|---|
| 合并范围、纳入与退出、持股与表决权、未合并理由 | **本件** |
| 投资性房地产、计量模式、转换与处置 | `cn-investment-property-cn` |
| 控股股东与实际控制人变更 | `cn-controlling-shareholder-change-cn` |
| 重组进展、交易方案与审批节点 | `cn-restructuring-tracker` |
| 商誉减值测试、资产组划分 | `cn-goodwill-impairment-risk` |

本件只管**合并范围里进出的被投资主体**：交易过程归 `cn-restructuring-tracker`，控制人是谁归 `cn-controlling-shareholder-change-cn`，并表产生的商誉金额本件登记数字，减值是否充分归 `cn-goodwill-impairment-risk`。

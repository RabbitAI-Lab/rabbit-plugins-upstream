## Description: <br>
Writes clear, blame-free error messages and surface-specific variants that explain what happened, what users can do next, and what technical details should be logged instead of shown. <br>

This skill is ready for commercial/non-commercial use. <br>

## Use Case: <br>
Product teams, UX writers, support teams, and developers use this skill to turn raw failures or brief error scenarios into user-facing error copy with clear recovery steps. It is useful for inline validation, toast messages, modal errors, full-page error states, and developer-facing notes about what to log versus what to show. <br>

### Deployment Geography for Use: <br>
Global <br>

## Known Risks and Mitigations: <br>
Risk: Generated error copy can be inaccurate or misleading when the true cause is uncertain, especially for high-impact flows such as payments, accounts, or data loss. <br>
Mitigation: Review generated copy against the actual failure cause before showing it to users, and keep technical details in logs unless a user-safe support reference is needed. <br>

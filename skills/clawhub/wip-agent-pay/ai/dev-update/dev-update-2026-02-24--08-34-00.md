### New Architecture: Pool Mode (A) + User Wallet (C)

**Pool Mode A** (default, no setup):
- User pays via Apple Pay (Stripe Checkout)
- Parker's pre-funded CDP wallet signs x402 on Base + Solana
- Pricing: x402 price + Stripe fees (2.9% + $0.30) + $0.25 flat fee
- Parker always nets $0.25 per transaction
- Max $25 per transaction. Over $25 redirects to Mode C.

**Mode C** (power users, over $25):
- Privy wallet created by email (one-time)
- User funds their own wallet (Coinbase Onramp or manual USDC)
- Agent signs x402 from user's wallet. No fees from us.

### Technical Decision: No @x402/fetch in Worker

The plan originally called for replacing all custom signing with `@x402/fetch` SDK. We kept the inline signing instead. Reason: the Worker is a single-file Cloudflare Worker (`main = "index.js"`, no bundler). The `@x402/fetch` SDK requires `@coinbase/cdp-sdk` and `viem` which need Node.js. The existing inline Ed25519 JWT + EIP-712 signing works correctly in the Worker's Web Crypto environment. Adding a bundler for no functional benefit would be overengineering.

## Side Fix: wip-markdown-viewer SSE bug

Filed bug report + fix on branch `mini/fix-stale-sse` in wip-markdown-viewer. The TCP proxy's `setTimeout` was killing SSE connections because the browser never sends data back on EventSource. Replaced with `setKeepAlive`. Reduced keepalive interval from 30s to 15s. Added periodic stale-watcher cleanup. This was the "viewer always gets stuck" bug Parker's been hitting.

# 最佳实践达标清单 · 12 条说明

> 只在某条核心检查未达标、需要解释“为什么 / 怎么做”时加载对应小节。不要把本文当作第二份清单。

### C-mem-01 · 记忆画像是否完整
- **问题**：新会话是否还要反复介绍自己和偏好？
- **最佳实践**：把称呼、工作背景、回答偏好与红线写进 `SOUL.md` / `USER.md`。
- **动作**：先给用户一个可编辑范例；确认后再写入。

### C-auto-01 · 是否有自动化在真正跑
- **问题**：重复任务是否仍靠人工每天发起？
- **最佳实践**：只为稳定、高频、可验证的任务建立 ACTIVE 自动化。
- **动作**：优先启用每日检查或一个用户明确需要的重复流程，不批量创建。

### C-conn-01 · 常用连接器是否已启用
- **问题**：是否仍手工复制邮箱、文档或业务数据？
- **最佳实践**：只连接真正会用的数据源，并确认授权范围。
- **动作**：交互态重连一个最常用连接器，随后做一次最小验证。

### C-skill-01 · skill 是否精简
- **问题**：skill 全开导致上下文变长、触发变乱。
- **最佳实践**：保留高频、互补、可验证有收益的 skill；低频项优先关闭。
- **动作**：先看使用证据和依赖，再给出关闭清单，不直接删除。

### C-skill-02 · 是否有 skill 生态维护入口
- **问题**：skill 出问题时是否只能手工逐个排查？
- **最佳实践**：配置一个体检入口和一个可视化/清单入口即可，不要再堆维护工具。
- **动作**：按 `toolbox.md` 的托管安装 prompt 安装缺失入口。

### C-skill-03a · SKILL.md frontmatter 是否可用
- **问题**：skill 是否因为缺 `name` / `description` 而无法可靠触发？
- **最佳实践**：所有已装 skill 都有最小合法 frontmatter。
- **动作**：逐项补齐并重新触发验证。

### C-skill-06 · 是否存在同 slug 重复
- **问题**：裸目录与命名空间目录并存，造成加载歧义。
- **最佳实践**：同一 skill 只保留一个明确来源。
- **动作**：确认来源和版本后保留一份，另一份先停用再清理。

### C-models-01 · 模型配置是否合法
- **问题**：配置损坏导致调用失败或回退到非预期模型。
- **最佳实践**：配置文件可解析，且关键字段来自当前 WorkBuddy 设置。
- **动作**：用 JSON 校验工具定位错误，必要时从设置重新导出。

### C-auto-03 · 自动化是否真的在用
- **问题**：任务虽然 ACTIVE，但长期没有运行记录。
- **最佳实践**：只保留有明确产出的自动化，并定期验证最近一次运行。
- **动作**：检查触发条件、权限和输出目标；仍无需求则停用。

### C-conn-02 · 连接器是否真的在用
- **问题**：连接器已配置却没有实际调用。
- **最佳实践**：每个连接器都应对应一个真实任务；没有任务就不强行保留。
- **动作**：做一次最小读取验证，失败时再进入重连流程。

### C-mem-02 · 记忆日志是否新鲜
- **问题**：AI 记得旧信息，却不知道最近在做什么。
- **最佳实践**：实质工作后沉淀一条短、准、可复用的记忆。
- **动作**：记录结论、偏好或下一步，不复制整段对话。

### C-prompt-01 · 提示词是否包含五要素
- **问题**：AI 反复追问或交付格式不对。
- **最佳实践**：至少交代角色、背景、任务、格式、边界。
- **动作**：用下一条真实任务做“原话 / 改写后”对照，不做抽象打分。

### C-work-01 · 长任务是否拆解并留检查点
- **问题**：长任务中途失忆、失败后只能从头开始。
- **最佳实践**：先列子任务、验收点和可恢复检查点。
- **动作**：每完成一个阶段就验证产物，再进入下一阶段。

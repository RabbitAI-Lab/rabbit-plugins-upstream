步骤 4c 输出格式（最终交付，不再是中间要点卡）：

```markdown
# 晨报 <适用交易日>（数据截止 <数据日> 收盘）

## 宏观与市场（源自步骤 1–2）

## 持仓操作建议（源自步骤 4a–4b）

## 数据来源与置信声明
## 附：步骤间传递的要点卡
```

## 衔接与数据契约

1. **要点卡是唯一传递格式**：四个 skill 的原生输出结构各不相同（如 market-mainline 为 7 段式、position-management 为 7 段式），**没有任何一个原生输出等于要点卡**。因此每一步必须由 Agent 把 skill 原生输出**显式转换为**卡片定义的要点卡（结论 / 要点 / 置信与风险）后再传递 `[R3]`；
2. **skill 的调用形态** `[R2]`：四个 skill 均为 prompt 型（仅含 `SKILL.md`，不接收参数、不返回结构化数据）。正确用法是 Agent 读取其分析框架与输出结构后**自行执行分析**；数据一律另经 finance-data 链路取。禁止把 skill 名当函数调用并期待结构化返回；
3. **步 1 → 步 2**：宏观要点卡的「结论 + 要点」作为 market-overview 的背景输入；教授特别关心的政策条目原样透传；
4. **步 2 → 步 3**：市场综述卡的「结论 + 要点」作为 mainline 识别的市场背景；要点中提到的板块/资金数据一并透传；
5. **步 3 → 步 4a/4b**：主线卡的「结论 + 要点」先映射到持仓（每条主线标注与 5 只持仓的相关性：直接/间接/无关），**4a 给总仓位，4b 只对相关持仓给个股建议**（无关持仓仅给持有/风控口径）`[R4]`；
6. **步 4a 与 4b 的分工** `[R4]`：position-management **只输出总仓位区间与加减仓条件，不产出个股触发价**；个股条件单由 4b 基于当日行情与主线相关性合成；
7. 步骤间**只传要点卡文本**，不传工具原始输出；后步不得自行重新检索前步已覆盖的内容（可补充前步未覆盖的数据）；
8. **验收与 skill 输出规范的冲突处理** `[R5]`：macro-research 的强制规范写明「引用机构或政策表态时标注'据公开表态'，不注明具体来源机构」并「严禁出现'注：'」，与本卡验收「每条有出处」直接冲突。**本卡为内部决策文档，以出处优先**；遇到冲突时按卡片验收执行，并在此处备案。

## 失败回退

- 每步失败先**重试一次**（规则见 [retry-policy](../retry-policy.md)）；
- **步 0 失败（数据通路不可用）** `[R1]`：先尝试 `setup.cjs` 安装；仍失败则整卡降级——改调 `morning-briefing` 子代理（a-share-advisor 团队）兜底，并在运行记录标注「降级：数据通路缺失」；
- 步骤 1–3 任一步重试仍失败：**降级运行**——跳过该步并在简报对应章节标注「今日缺宏观/市场/主线层，原因 X」，后续步骤可基于剩余输入独立运行；
- 步骤 4a 失败：简报仍交付前三层，仓位建议留空并提示「需教授盘中手动决策」；步骤 4b 失败：只交付总仓位建议，个股表留空；
- 整体兜底：若 ≥2 步失败，改调 `morning-briefing` 子代理（a-share-advisor 团队）一次性产出简报，并在运行记录标注「降级：子代理兜底」；
- 简报推送 agent-mail 属对外操作，须经教授确认后才发送。

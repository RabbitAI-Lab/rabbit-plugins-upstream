# Skill 生态与最小组合

> 本文只解决一个问题：面对一个真实目标，如何选出足够用、容易验证、不会长期腐化的 skill 组合。

## 选择顺序

### 1. 先复用已装 skill

先查看用户当前已装 skill，优先使用名称、输入格式和历史产出都已验证的 skill。不要因为候选列表更长就重新安装。

已装/自建积木的稳定名册见 [积木注册表](skill-registry.md)——**先查名册，再查目录**；名册条目含各积木的场景与输入输出接口。

### 2. 缺失时只补最小能力

把目标拆成三类能力：

| 能力 | 判断问题 | 典型结果 |
|------|----------|----------|
| 产出 | 谁负责生成最终交付物？ | 文档、表格、页面、分析 |
| 输入 | 谁负责读取或整理必要资料？ | 文件、知识库、邮件、数据 |
| 验收 | 谁负责检查格式和事实？ | 校验、对比、引用、测试 |

默认只选 1 个产出 skill；只有输入或验收确实不能由它完成时，才增加第 2、3 个 skill。

**外部找人（名册与目录都没有时）**：按 [skill-sources.md](skill-sources.md) 的来源优先级检索——**优秀 skill 优先查阿里 SkillsHub**（107 个精选、中文分类、可在 skills.sh 核验），未命中再退 SkillHub 与 skills.sh 全生态；候选 skill 一律按 [skill-taxonomy.md](skill-taxonomy.md) 归类，确保与任务域对齐后再推荐。

### 3. 先做一次真实任务

组合前先写清楚：

- 输入是什么；
- 期望产出是什么；
- 最小成功标准是什么；
- 哪一步需要用户确认。

用真实的小任务验证组合，而不是先搭一个“完整生态”。

## 组合规则

- **单 skill 优先**：一个 skill 已能完成任务，就不要组合。
- **前后衔接明确**：上一个 skill 的输出必须是下一个 skill 可直接使用的输入。
- **每一步可替换**：任何一步失败，都能退回单个 skill 完成核心产出。
- **不重复安装**：已装 skill、内置能力和连接器都先复用。
- **不把目录当承诺**：目录只提供候选，真实任务结果才算验证。

## 推荐输出格式

向用户推荐时只给：

1. **最小方案**：主 skill，以及必要的输入/验收 skill；
2. **使用话术**：可直接复制的一句话或输入模板；
3. **验收标准**：完成后检查什么；
4. **备选方案**：仅在主方案失败时给一个替代。

示例：

```text
目标：把会议记录整理成行动清单
最小方案：文档整理 skill
可复制话术：请把这份会议记录整理为负责人、截止时间、下一步三列表格，并标出缺失信息。
验收：每项都有来源；没有负责人或截止时间的事项单独列出。
```

## 何时沉淀

只有同类任务重复且验收标准稳定时，才建议把组合写成工作流或自动化。自动化仍只能读取、建议或入队；安装、升级、停用和外部写入必须在用户确认后执行。

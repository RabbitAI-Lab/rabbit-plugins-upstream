# Token 管理专项 Checklist · WorkBuddy 日常使用核对卡

> 面向「用户日常使用 WorkBuddy」的可勾选操作清单——不是「写 skill 时省 token」，而是每次交互怎么发、怎么查、怎么复用。
> 文章实测把 20 轮会话输入费用降到约原来的 1/10，靠的是「少发（裁剪固定前缀）+ 发得便宜（缓存命中）× 重复用轻量模型」。
> 把这 9 条当成开工前自检：勾上的越多，一轮会话的 token 就越接近「只付该付的」。

**定位**：本卡是 `best-practices/checklist.md`「成本/Token 专项」（C-cost-01/02/03）的**用户面配套**——agent 用那 3 条做达标打分，你用本卡做每日勾选自检。两者互补，不重复。

---

## A. 任务前 · 把「发什么」压到最小

- [ ] **1. 一次性把意图说清，避免来回澄清**
  - **具体表现**：首条只丢一句「帮我看下为什么报错」式模糊需求，助手会铺开多维度、反复追问，单任务拖到 20–40 轮。
  - **实施效果**：砍掉不必要的往返；「几个字撬动几十 M token」主因正是循环反复 + 历史每轮全量重发。
  - **如何操作**：首条消息就把「目标 + 关键约束 + 已知信息 + 文件路径」一次给足；拿不准就先让助手列澄清项再动手。

- [ ] **2. 选对模式：Craft 直接干 / Ask 只聊 / Plan 先方案**
  - **具体表现**：只想问问题却开了 Craft 跑了命令；或该分步确认却一次大改。
  - **实施效果**：Ask 模式不修改文件、不跑命令，避免误执行与重复试错；Plan 先出方案再执行，避免返工。
  - **如何操作**：左栏切换模式；默认 Craft 直接做，纯问答切 Ask，需分步方案切 Plan。

- [ ] **3. 重复任务交给自动化，而非每次重新解释**
  - **具体表现**：每天 / 每周的日检、定期报表、固定提醒，每次都从头描述一遍。
  - **实施效果**：一次配置按时触发，长周期省下大量重复 prompt；「模型分流」同样主张把模式化工作固化。
  - **如何操作**：用自动化工具建 recurring 任务（rrule）；prompt 只写任务本身，不含时间 / 工作区等细节。

- [ ] **4. 裁剪启用的 MCP / Skill，只留当前需要的**
  - **具体表现**：连了一堆 MCP server，每个工具的 schema 每轮都进上下文（文章称「固定前缀」可占 57%）。
  - **实施效果**：缩小每轮固定前缀；按需从 custom connectors 启用，避免全量占位。
  - **如何操作**：检查 `~/.workbuddy/mcp.json`，断开 / 精简不用 server；优先用内置专用工具而非小众 MCP；工具多的场景把能力迁到 CLI + Skill。

## B. 任务中 · 控制「跑什么 / 读什么」

- [ ] **5. 优先专用工具，避免 shell 兜底与重复读文件**
  - **具体表现**：用 `cat/sed/find` 反复读同一文件、用裸 shell 干专用工具能做的事；同一文件同轮重复 Read。
  - **实施效果**：专用工具更稳、更省 token；「同一 run 内重复 Read 去重」专门解决此问题。
  - **如何操作**：读文件用 Read、搜代码用 Grep/Glob、改代码用 Edit；同路径同轮不重复读。

- [ ] **6. 大范围探索交给子代理，只回传结论**
  - **具体表现**：把几百行日志 / 搜索结果一次性揉进主对话，撑爆上下文后被 compact，后续每轮重发。
  - **实施效果**：探索过程不进主上下文，只回传摘要与证据路径；实测一轮可省近 10 次 × 200k 的重发。
  - **如何操作**：开放搜索 / 大代码库探索用 Explore 子代理；明确给它「背景 / 目标 / 范围 / 边界 / 返回格式」，只要结论 + 证据位置。

- [ ] **7. 增量验证、小批量推进，别一次大改**
  - **具体表现**：一口气让助手改动大量文件，失败难定位、反复重做。
  - **实施效果**：每批小改动、每轮可验证，避免「重做 + 重发」的 token 雪崩。
  - **如何操作**：复杂任务先 TaskCreate 拆步；小批次（≤10）、逐批验证；先 Plan 确认再 Craft 执行。

- [ ] **8. 善用已装 Skill，不每次从零解释；重复任务沉淀成 Skill**
  - **具体表现**：反复让助手做同一类事却不提 skill，助手每次重新推导；「同一份 skill 正文只注入一次」。
  - **实施效果**：skill 全文注入一次、后续仅短提醒，省 token 且更稳（避免「Lost in the Middle」）。
  - **如何操作**：先 `Skill` 工具搜 / 加载匹配 skill；跑完多步任务后把方法 `SkillManage` 存为个人 skill。

## C. 系统侧 · 让「贵的活」变便宜

- [ ] **9. 简单活用轻模式，别用深度推理链压简单活**
  - **具体表现**：标题生成、格式转换、分类等简单请求也触发长 thinking 链，输出侧照样按 token 计费。
  - **实施效果**：「模型分流」：简单调用关掉深度推理或走轻模型，成本可降 1/10–1/20。
  - **如何操作**：对简单请求不要强求「深入思考」；需要可控时让助手按场景设定推理预算上限，避免「光想不干活」。

---

> **兜底核查**（对应文章 §7 Hook 思想）：若会话出现「重复空转 / 同一工具反复失败 / 连续空回答」，及时止损——要求助手总结当前进度或直接切 Ask 模式，避免越转越贵的死循环。

# ① 系统扫描及效率提升（底座）

> 本模块是四模块架构的**底座**，封装了「用户阶段判定 + 初始化引导 + 系统检查 + 效率建议」四件事。
> agent 按 `usage_diag.py` 的 `tier` 结果自动走对应分支，**只奔结果、不展开内部细节**。
> 逻辑与 v5 的「判定 + 模式 A/B/C」完全一致，仅做结构归并，未改判定规则与脚本。

---

## 1. 用户阶段判定（三级 · 综合画像信号）

由 `scripts/usage_diag.py --json --state <state.md>` 的 `classify_user_tier()` 确定性计算，输出 `tier` + `tier_reasons`（另附 `profile_ready` 布尔值，内部用）；agent **只读结果、不自作判断**：

| 级别 | 判定规则 | 服务模式 |
|------|----------|----------|
| `beginner` 初级 | 任一命中：`onboarding_done=false`；画像缺失/过薄（<200 字）；已装 skill=0 且 ACTIVE 自动化=0 | 初始化引导 + 系统检查（先打地基，不跑 ②/③/④；仅给 ③-4-lite 基础必装清单） |
| `intermediate` 进阶 | 初级不命中，且不满足高级 | 系统检查 + 效率建议 + ②（L1+L2 按 tier 加载）+ ③ + ④（轻版）——**核心受众** |
| `advanced` 高级 | 初级不命中，且全部满足：画像完整 + skill≥15 + ACTIVE 自动化≥2 + 记忆日志≤7 天新鲜 | 系统检查 + 效率建议 + ②（全量）+ ③ + ④（闭环+自我迭代） |

## 2. 初始化引导（仅初级 · 原 soul-setup 内容）

> 仅在**交互态**（用户主动调用）执行；主动态只入队提醒，不自动写。

### 为什么先立规矩
SOUL.md 是所有回答的"性格兜底"——定义 AI 是谁、怎么说话、什么红线不能碰。
没写 SOUL.md，AI 就是无性格的搜索框；写好了，才是有你风格的助手。

### Soul.md 六条规矩书（四大支柱：核心性格 + 说话方式 + 工作原则 + 红线）
1. **核心性格** — 用 2-3 句话定义 AI 是谁（身份/职业/核心价值）。
2. **说话方式** — 明确该说什么、不该说什么。消除 AI 味：禁止"好的呢~""您说得太对了"等客套话；按你偏好切换命令式/分析式/轻松感。
3. **工作原则** — 3-5 条铁律：带着方案来、干完活顺手复盘、一次到位不反复确认、不确定先说"不确定"但给最可能答案。
4. **嘴严** — 隐私/文件/聊天记录/未公开内容绝不泄露；敏感信息不记录不转述。
5. **红线禁区** — 法务合规底线 + 你的个人雷区（特定话题/语气/内容类型），绝不越界。
6. **持续进化** — AI 出主意、你做决定；每次互动都是学习机会，随时用"你应该…/不要…"微调规则；开启全局记忆长期积累偏好。

### 聊天式采集流程（交互态 · 首条即给范例，一次采集，不再挤牙膏）
> 温暖开场："来，我们先花 2 分钟把'你是谁'记下来，之后我回答会更贴你。下面给你一个填好的好范例，你直接照着改就行～"

**首条消息即做三件事**（不要逐轮只问 1 题，那会让用户跑 3 轮还没填完）：
1. **展示模板**：贴出 `config-templates/soul-setup-template.md` 的 USER.md 模板骨架（称呼/姓名、城市、身份职业、行业侧重、技术生态、沟通偏好、当前关注）。
2. **展示一个填好的好范例**：直接引用模板里的 ✅ 好范例（投资经理+数学教授范式），让用户"照着改"而非"从零想"。
3. **一次列出待采集字段 + 示例答案**，请用户填空式回一段：

   | 字段 | 你要填的 | 示例 |
   |------|---------|------|
   | 称呼 / 姓名 | 你希望我怎么叫你 | 教授 / 胡某 |
   | 城市 | 你在哪 | 北京 |
   | 身份职业 | 主业+副业 | 基金投资经理（原数学教授） |
   | 行业侧重 | 你主盯哪个领域 | 地产为主，兼高科技 |
   | 技术生态 | OS/工具链/知识库 | Windows + Obsidian + ~55 skill |
   | 沟通偏好 | 你爱什么风格 | 专业严谨、先结论后细节、指令简短 |
   | 当前关注 | 最近在忙啥 | V5 量化策略、连接器扩展 |

4. 收到回段 → 生成 SOUL.md + 深化 USER.md → 展示确认 → "OK 还是改？" → 写入 `~/.workbuddy/SOUL.md` 与 `~/.workbuddy/USER.md`。
5. 后续维护：随时用"你要…/你应该…/不要…"句式微调，无需重走完整流程。

### 🔌 关键第一步：连好你的第一个连接器（与画像并列的新手里程碑）
> 没有连接器，AI 就只能"听你说"、没法"替你取数"。画像填完后，立刻带用户配一个连接器——这是新手最容易卡住、也最该被手把手带的一步。

- 首条引导即提示："想让 AI 直接读你的邮件/文档/行情？先连一个连接器。详细手把手见 `config-templates/connector-quick-ref.md` 的「新手上路」节。"
- 给一句可直接说的小卡片：**"你试着说：把腾讯文档连上"** → 我给你 mcp.json 片段 + 提示点 Trust → OAuth 登录 → 状态变 connected。
- 授权类型对照与可视化流程见 connector-quick-ref.md 新手上路节。

### 角色画像要点（写 USER.md）
- 身份/职业、行业侧重、业余爱好
- 沟通风格偏好（专业严谨+活泼？纯命令式？）
- 技术生态（OS、已装工具链、知识库路径）
- 当前关注的重点项目
- ✅ 什么叫"完整准确"：含称呼、双职业身份、行业侧重、城市；⚠️ 只有姓名+一句职业算不合格（反面例子见模板）

> 采集完成后，使用助理在 `state.md` 记 `onboarding_done: true`，后续不再重复引导。
> 完成后若无 ACTIVE 的"每日主动检查"自动化 → 引导走「启用主动监护」。

## 3. 系统检查与达标判定（所有人 · 原 diagnostics 内容）

> 详细诊断由 `scripts/usage_diag.py --json --offline` 产出；报告渲染由 `scripts/report_builder.py`。

### 3.1 三个事实输出（不合成总分）
系统检查只产出事实，不做"综合分"这类二次合成——合成分无法告诉用户下一步做什么，反而盖过了具体问题：

| 输出 | 含义 | 来源 |
|------|------|------|
| `health_score` 环境健康分 | 扣分制：配置异常/风险暴露直接扣分 | `usage_diag.py` |
| A 层达标比 | `checklist_pass / checklist_applicable`（`na` 不计分母） | `usage_diag.py` |
| 发现项 `issue_items` | 带 P0/P1/P2 分级 + 修复建议 | `usage_diag.py` |

- **判定分层**（checklist 项的判定方式）：A 层（脚本确定性）→ B 层（agent `conversation_search` 启发式）→ C 层（一次 `ask` 自评）。
- 三层的判定结果都回写 `state.md` 对应 checklist 项，报告只呈现"达标 / 未达标 / 无法判定"与证据。

### 3.2 A 层确定性检查（usage_diag.py 覆盖）
1. 代理状态（端口 51103 探活；`--fast`/`--offline` 下跳过）
2. 连接器配置与启用状态（connector-states.json 的 enabled 仅代表已声明可用目录，非实时连接态；实时连接以本会话 connector-status 为准，脚本结果需 agent 覆盖，避免"目录数当已连接数"误报）
3. 自动化任务（数量 / ACTIVE 比例 / rrule）
4. 专家注册（插件市场目录扫描）
5. 已装 skill（`~/.workbuddy/skills/`，跳过自身）
6. 记忆新鲜度（`.workbuddy/memory/YYYY-MM-DD.md` 最近更新）
7. 日志严重痕迹（logs/*.log 近 7 天 FATAL/CRITICAL/Traceback；例行 ERROR 只作 INFO）
8. 模型配置（models.json 存在性与合法性）
9. **SKILL.md frontmatter 强制字段**（name/description 齐全）— `C-skill-03a`
10. **同 slug 跨命名空间重复** — `C-skill-06`
11. **自动化使用度**（读 `automation_runtime_state.last_run`，按近用天数判定 pass/fail）— `C-auto-03`
12. **连接器使用度**（扫 logs 的 `mcp__` 调用痕迹，按最近调用天数判定；无痕迹→na 不 fail）— `C-conn-02`
13. **MEMORY.md 结构质量**（含 `##` 分层或实质内容）— `C-mem-03a`

### 3.3 分级修复建议
| 级别 | 含义 | 处理 |
|---|---|---|
| **P0 阻断级** | 导致核心功能不可用（如 mcp.json/models.json 损坏） | 必须立即处理；交互态确认后执行修复 |
| **P1 建议级** | 影响效率但不阻断（如某连接器 disconnected、无自动化、画像缺失） | 给出方案入队，用户确认后做 |
| **P2 优化级** | 锦上添花（如 memory 日志超期、严重日志痕迹、未装 skill） | 仅建议，不强制 |

> **分级来源**：`usage_diag.py` 的 `issue_items` 已带 `severity` 字段（P0/P1/P2），报告渲染直接按此分级；`issues` 字符串数组保持向后兼容。

### 3.4 常见故障 → 一级修复
| 现象 | 一级修复（最常见原因） | 验证 |
|---|---|---|
| 所有连接器 down | 重启 WorkBuddy | 重跑 usage_diag.py 看连接器状态 |
| 单个连接器 disconnected | 在 UI 重新登录/授权该连接器 | 状态变 connected |
| 专家不生效 | 执行 validate + register | 专家列表可见可对话 |
| 自动化不执行 | 检查 `status` 是否 ACTIVE | automation_update list 确认 |
| 配置 JSON 错误 | `python usage_diag.py` 仅报，修复用 jsonlint | JSON 可解析 |
| 回答质量差/太啰嗦 | 优化 SOUL.md 说话方式 + 提示词五要素 | 对比前后回答 |

### 3.5 安全边界
- 自动修复仅限 JSON/代理/连接器状态类。
- 网络、账号、权限类问题 → 按上表手动处理，不在自动修复范围。
- 使用助理**主动态不执行任何修复**，只报告 + 入队；修复在交互态确认后执行。

## 4. 效率建议（进阶/高级 · 原 best-practices 内容）

> 每日给轻版（1-2 条）。

### 任务交代五要素（让 AI 一次到位）
1. **角色** — 你希望 AI 以什么身份做（"你是资深量化分析师"）。
2. **背景** — 关键上下文（数据/约束/目标）。
3. **任务** — 具体要做什么，可验证的产出。
4. **格式** — 想要什么形态（表格/Markdown/代码/图表）。
5. **边界** — 不要做什么、合规红线、不确定时怎么办。

> 反模式："帮我看看这个" → 改成"你是基金风控负责人，基于附件持仓表，按监管口径算集中度，输出表格，不确定处标注假设"。

### Prompt 体检模板（子能力）

对用户近期 1-3 条真实指令做体检，逐条对照五要素：

| 要素 | 检查问题 | 缺失时的典型表现 |
|------|---------|-----------------|
| 角色 | AI 知道自己以什么身份做吗？ | 泛泛而答，不贴领域 |
| 背景 | 数据/约束/目标给了吗？ | AI 反复追问或猜 |
| 任务 | 有可验证的产出吗？ | 结果"像"但不"是" |
| 格式 | 明确要什么形态吗？ | 输出排版不符合预期 |
| 边界 | 说了不要做什么/不确定怎么办吗？ | 越界或瞎编 |

**输出格式**：给每条指令"改写前 vs 改写后"对照 + 一句话收益说明。
示例：
```
【你的原话】"帮我看看这个报表"
【改写后】"你是财务分析师。基于附件 Q3 利润表，找出毛利下滑最严重的三条线，
           给出原因假设（每条一句话），输出表格，数据缺失处标注'待补'。"
【收益】AI 一次到位产出表格，不再反问"哪个报表/看什么指标"。
```

### 进阶工作习惯（来自 07-进阶）
- **工作空间分区**：不同项目进不同空间，上下文独立不污染。
- **任务管理三件套**：重命名任务、用"保鲜膜"自动存档上下文、长期不用归档。
- **探索模块一键复用**：「探索」→ 制作我的版本，零 prompt 复用 skill/专家。
- **专家 vs Skill 辨别**：深度聊背景用专家，固定格式产出用 skill。
- **产物分享**：HTML/视频/图片原生预览；周报用微信/HTML 分享。

### 效率提升微建议（输出样例）
| 观察到的模式 | 建议 |
|---|---|
| 连续 3 次手动发起同类任务 | 建一个 Automation 定时/触发跑它 |
| 反复手写同类长 prompt | 封装成 Expert 或写进 SOUL/USER 记忆 |
| 长任务没拆 | 用任务管理拆成子任务，逐个验收 |
| 提示词缺格式/边界 | 套用五要素，加"输出格式 + 不要做什么" |
| 装了很多 skill 却不用 | 清理低频 skill，或建快捷工作流串起来 |
| 不用连接器数据 | 接好对应 MCP，让 AI 直接取数而非你粘贴 |

### 质量自检清单（给用户的日常 rubrics）
- [ ] 这次回答是否体现了我的说话风格（SOUL.md）？
- [ ] 任务是否一次到位，没反复确认？
- [ ] 不确定处是否明确标注了假设/来源？
- [ ] 是否有可沉淀为记忆/自动化的重复动作？

> 📋 **配套可打印核对卡** → `references/token-management-checklist.md`（9 条日常 token 纪律，可勾选 + 打印；达标检查另有「成本/Token 专项」打分项）。

### 采纳闭环习惯（配合"使用助理"的采纳闭环战绩）
- 收到建议后：说"采纳 a1" → 交互态执行 → `issues_resolved+1`。
- 不想采纳：说"跳过 a2" → 标记 `skipped`，不反复打扰。
- 每日回看报告里的"上轮采纳情况"，让改善可见可量化。

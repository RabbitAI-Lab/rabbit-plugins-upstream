# 四类威胁分离— 判定与处置手册

把「敏感信息」拆成四类，不是为了分类学好看，而是因为**它们的后果和修法完全不同**。
混在一起处理，最常见的后果就是：把凭证当路径问题处理（删了但没吊销），
或把测试固定装置当真泄露处理（浪费一整天）。

---

## 类别一：CREDENTIAL 凭证密钥

| 项目 | 内容 |
|------|------|
| 典型形态 | PAT、API key、私钥块、含内联密码的连接串、JWT |
| 严重级别 | **P0**，无条件阻断发布 |
| 一旦泄露 | 攻击者可直接使用，**且泄露已经发生**——它不可撤销 |
| 正确处置 | **① 吊销 → ② 轮换 → ③ 删代码 → ④ 清历史**，顺序不能颠倒 |
| 最常见错误 | 只做③，以为删掉就安全了 |

### 为什么顺序不能颠倒

先删代码再吊销，中间的时间窗里凭证依然有效，而你已经失去了「它在哪」的线索。
先吊销的话，即使清理历史失败，那把钥匙也已经废了。

### 清理git 历史

```bash
# 推荐：git-filter-repo
git filter-repo --replace-text <(echo 'OLD_SECRET==>***REMOVED***')

# 或 BFG
bfg --replace-text replacements.txt && git reflog expire --expire=now --all && git gc --prune=now

# 然后 force push（务必提前通知所有协作者，否则他们的本地分支会分叉）
git push --force --all
```

> 注意：fork、PR、CI 缓存、镜像仓库里可能仍有副本。历史重写不能替代吊销。

## 类别二：ORG_INTERNAL 雇主内部信息

| 项目 | 内容 |
|------|------|
| 典型形态 | 内网域名、内部平台名、内部 API 网关、组织架构、项目代号、内部 IP |
| 严重级别 | **P0**（配置了内部词表时），因为通常直接违反保密要求 |
| 一旦泄露 | 不可撤销。域名/系统名不能像 token 那样"轮换" |
| 正确处置 | **泛化**或移除——保留结论，去掉标识 |
| 最常见错误 | 为了脱敏把整段内容删掉，产物失去价值 |

### 泛化的正确做法

```diff
-部署到 deploy.corp.example.com 的灰度环境，走内部网关 api/gateway/inner
+ 部署到内部灰度环境，走组织自建的 API 网关
```

保留了「有灰度环境 + 走内部网关」这个**工程事实**，去掉了**可定位的标识**。
这是脱敏，不是删除。

### 容易被忽略的泄露位置

- commit message（比代码更容易漏，且历史里改不掉）
- 代码注释、TODO
- 测试固定装置里的"真实"样例数据
- 截图、录屏、架构图里的地址栏与水印
- 依赖锁文件里的内部registry 地址
- CI 配置里的内部制品库地址

## 类别三：PII 个人身份与机器指纹

| 项目 | 内容 |
|------|------|
| 典型形态 | `/Users/<name>/…` 绝对路径、邮箱、手机号、同事姓名 |
| 严重级别 | **P1**，需人工判定 |
| 一旦泄露 | 人肉风险；**同时几乎总是可移植性缺陷** |
| 正确处置 | 改相对路径 / 环境变量 / 裸包名 |

### 一个真实例子

```js
// 修复前：泄露用户名，且换台机器立刻失效
import { marked } from '/Users/somebody/.tooling/node_modules/marked/lib/marked.esm.js';

// 修复后：既脱敏，也真正可复用
import { marked } from 'marked';
```

这类问题的价值在于：**修它同时解决了两个问题**。所以不要当成纯合规任务应付。

### 判定要点

- 提交者自己的邮箱出现在 commit metadata 里是正常的（git 机制决定），
  不必因此报警；但**代码或文档正文**里的邮箱要判断是否必要。
- 开源项目里维护者署名是公开意图，不算泄露。
- `example.com` / `test@example.com` 是 RFC 保留域名，属预期占位符。

## 类别四：LOCAL_ONLY 本地专属产物

| 项目 | 内容 |
|------|------|
| 典型形态 | 本地 agent 状态目录、编辑器配置、`.DS_Store`、个人草稿 |
| 严重级别 | **P1**，仅当**被 git 追踪**时才是问题 |
| 一旦泄露 | 噪音 + 可能夹带前三类内容 |
| 正确处置 | `.gitignore` + `git rm --cached` |

### 关键判定：工作树 ≠ 公开面

这类文件躺在你的目录里完全没问题。**只有被 git 追踪了才进入公开面。**

```bash
# 判断是否真的公开（把 pattern 换成你环境里的本地目录）
git ls-files | grep -E "^\.(agent|ai|vscode|idea)/" || echo "未被追踪，安全"

# 已被追踪的停止追踪（保留本地文件）
git rm -r --cached .agent && echo ".agent/" >> .gitignore
```

只扫工作目录的工具会把这些**全部报成泄露**，制造大量噪音，
让人对告警脱敏，最终连真问题也一起忽略了。这是「公开面判定」的核心价值之一。

---

## 交叉判定：同一处命中可能属于多类

```
DB = "postgres://admin:RealPass@10.0.3.14:5432/prod"
```

这一行同时是：
- **CREDENTIAL** — `RealPass` 是真凭证 → 必须吊销
- **ORG_INTERNAL** — `10.0.3.14` 暴露内网拓扑 → 需泛化

处置时**两条都要做**。只改一个就是半修复。

---

## 分级与放行标准

| 级别 | 含义 | 是否阻断发布 |
|------|------|-------------|
| P0 | 凭证 / 雇主内部标识，位于公开面 | **阻断**，必须处置 |
| P1 | 内网线索 / PII / 被追踪的本地产物| 不自动阻断，但必须逐条判定 |
| P2 | 邮箱等低风险信号 | 提示 |

**位于公开面**是关键限定：同一命中在未追踪文件里只是提示，在已追踪文件或
git 历史里才构成阻断。这个区分让告警量降下来，也让真问题浮上来。

## SD1 产品方案域范本

### 一、领域知识要点

- PRD 核心结构：背景与目标、用户与场景、功能清单、流程与状态、字段与规则、非功能需求、埋点、验收标准
- 需求分层：业务需求（为什么）→ 用户需求（谁要什么）→ 功能需求（系统做什么）
- 用户故事格式：作为＜角色＞，我希望＜能力＞，以便＜价值＞；附验收条件（Given/When/Then）
- 状态机与边界：正常流、异常流、空态、超时、并发、权限
- 优先级方法：KANO（基本/期望/兴奋）、RICE（触达×影响×信心÷投入）、MoSCoW
- 评审要点：目标可测、边界清晰、依赖已识别、验收可判

### 二、判定标准

- 每个功能须有验收标准，无验收标准即未定义完成
- 异常流与空态必须写明，不得只写正常流
- 优先级须有方法依据
- 依赖与风险须显式列出

### 三、范本结构

1. 背景与目标（含量化指标）
2. 用户与场景
3. 功能清单与优先级
4. 流程与状态
5. 字段与业务规则
6. 非功能需求
7. 埋点与验收标准

### 四、常见失范

- 只写功能不写规则与边界
- 验收标准写成"体验良好"
- 异常流缺失导致开发返工
- 需求与目标脱节

### 五、交接契约

| 项 | 内容 |
|---|---|
| 上游必给 | 问题陈述、目标用户、场景、核心痛点、成功指标 |
| 本域产出 | 需求定义文档；PRD 文档；设计需求文档；PRD 评审报告；产品路线图 |

### 六、交付自检

交付前逐项打勾，任一项不成立即返工：

- [ ] 每个功能须有验收标准，无验收标准即未定义完成
- [ ] 异常流与空态必须写明，不得只写正常流
- [ ] 优先级须有方法依据
- [ ] 依赖与风险须显式列出

同时排除以下失范：

- [ ] 已排除：只写功能不写规则与边界
- [ ] 已排除：验收标准写成"体验良好"
- [ ] 已排除：异常流缺失导致开发返工
- [ ] 已排除：需求与目标脱节

### 七、执行卡（以「需求洞察与定义」为例）

**开工前备齐**：问题陈述、目标用户、场景、核心痛点、成功指标

**可选补充**：用户访谈、竞品分析、数据洞察

**按序执行**：

1. 还原场景
2. 定位痛点
3. 界定范围
4. 定成功指标
5. 需求陈述

**交付前核对**：痛点须有证据；范围须划出不做什么

**成品须符合**：需求定义文档

### 八、成品骨架

按「需求定义文档」交付。复制下面骨架，节标题即该节须给出的结论，不要改成中性标题。

```markdown
# 需求定义文档

## 1. 背景与目标（含量化指标）
## 2. 用户与场景
## 3. 功能清单与优先级
## 4. 流程与状态
## 5. 字段与业务规则
## 6. 非功能需求
## 7. 埋点与验收标准
```

**齐备要求**：必选组件「问题陈述、目标用户、场景、核心痛点、成功指标」须全部落位；约束「痛点须有证据；范围须划出不做什么」须逐条成立；可选「用户访谈、竞品分析、数据洞察」按需补充。

**自检**：写完后对照第六节逐项打勾，任一不成立即返工。

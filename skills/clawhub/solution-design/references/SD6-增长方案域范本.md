## SD6 增长方案域范本

### 一、领域知识要点

- AARRR 漏斗与北极星指标
- 增长模型：付费获客（ROI/LTV-CAC）、内容获客、裂变（K因子）、渠道合作
- 留存曲线：次日/7日/30日留存，判断是否收敛（收敛则为真需求）
- 流失预警：行为衰减信号、沉默期阈值、召回触达序列
- 实验设计：假设-指标-样本量-显著性-决策规则
- onboarding 设计：Aha 时刻前置、首日关键动作、激活率拆解

### 二、判定标准

- 须先定位瓶颈环节再设计方案
- 每个方案须绑定一个可测指标
- 实验须给样本量与判定标准
- 不得同时改动多个变量

### 三、范本结构

1. 增长诊断与瓶颈
2. 北极星与分解指标
3. 方案组合与优先级
4. 实验设计
5. 资源与排期
6. 预期效果与风险

### 四、常见失范

- 全链路一起改无法归因
- 只拉新不留存
- 指标与业务价值脱节
- 实验无显著性判断

### 五、交接契约

| 项 | 内容 |
|---|---|
| 上游必给 | 漏斗各环节数据、瓶颈判定、根因假设 |
| 本域产出 | 增长诊断报告；获客方案；留存方案；流失召回方案；实验方案 |
| 下游可用 | 实验方案 |

### 六、交付自检

交付前逐项打勾，任一项不成立即返工：

- [ ] 须先定位瓶颈环节再设计方案
- [ ] 每个方案须绑定一个可测指标
- [ ] 实验须给样本量与判定标准
- [ ] 不得同时改动多个变量

同时排除以下失范：

- [ ] 已排除：全链路一起改无法归因
- [ ] 已排除：只拉新不留存
- [ ] 已排除：指标与业务价值脱节
- [ ] 已排除：实验无显著性判断

### 七、执行卡（以「增长诊断与瓶颈定位」为例）

**开工前备齐**：漏斗各环节数据、瓶颈判定、根因假设

**可选补充**：埋点数据、同期对比

**按序执行**：

1. 拆漏斗
2. 算转化
3. 找最大流失
4. 提假设
5. 定验证

**交付前核对**：瓶颈须用数据定位；假设须可验证

**成品须符合**：增长诊断报告

```markdown
## 4. 实验设计

```

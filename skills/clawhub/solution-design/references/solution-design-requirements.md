## 方案设计任务要求清单

方案设计每种任务类型的零件清单——必选组件、可选组件、组装顺序、领域约束。按清单逐项产出。

---

### SD1 产品方案

#### 域级说明

**域定位**：把产品想法转成可开发、可评审的需求方案，输出 PRD 与配套设计文档。

| 维度 | 内容 |
|------|------|
| 价值链形态 | 需求洞察→PRD→设计转化→评审 |
| 独立成域的理由 | 以可开发、可评审为终点，验收看每条需求是否有可判定的验收标准 |
| 穷尽性 | 5 个任务覆盖「需求洞察→PRD→设计转化→评审」的 4 个环节；按输入物、失败模式、验收标准三条判据互不重叠，无未覆盖环节 |
| 知识要点 | PRD 核心结构：背景与目标、用户与场景、功能清单、流程与状态、字段与规则、非功能需求、埋点、验收标准；需求分层：业务需求（为什么）→ 用户需求（谁要什么）→ 功能需求（系统做什么）；用户故事格式：作为＜角色＞，我希望＜能力＞，以便＜价值＞；附验收条件（Given/When/Then）；状态机与边界：正常流、异常流、空态、超时、并发、权限；优先级方法：KANO（基本/期望/兴奋）、RICE（触达×影响×信心÷投入）、MoSCoW；评审要点：目标可测、边界清晰、依赖已识别、验收可判 |
| 判定标准 | 每个功能须有验收标准，无验收标准即未定义完成；异常流与空态必须写明，不得只写正常流；优先级须有方法依据；依赖与风险须显式列出 |
| 常见失范 | 只写功能不写规则与边界；验收标准写成"体验良好"；异常流缺失导致开发返工；需求与目标脱节 |
| 范本结构 | 背景与目标（含量化指标） → 用户与场景 → 功能清单与优先级 → 流程与状态 → 字段与业务规则 → 非功能需求 → 埋点与验收标准 |

#### SD1-01 需求洞察与定义
- **必选组件**: 问题陈述、目标用户、场景、核心痛点、成功指标
- **可选组件**: 用户访谈、竞品分析、数据洞察
- **组装顺序**: 还原场景→定位痛点→界定范围→定成功指标→需求陈述
- **约束**: 痛点须有证据；范围须划出不做什么
- **格式**: 需求定义文档

#### SD1-02 PRD 撰写
- **必选组件**: PRD 全文、流程图、状态机、字段表、验收标准
- **可选组件**: 设计稿、技术方案
- **组装顺序**: 写背景目标→列功能→画流程→定规则→写异常→定验收
- **约束**: 每个功能须有验收标准；异常流须覆盖
- **格式**: PRD 文档

#### SD1-03 设计需求文档转化
- **必选组件**: 信息架构、页面清单、交互说明、组件需求、设计约束
- **可选组件**: 设计系统、PRD
- **组装顺序**: 抽页面→建信息架构→写交互→标组件→列约束
- **约束**: 须可被设计师直接执行；不得留"待设计"空白
- **格式**: 设计需求文档

#### SD1-04 PRD 评审与评分
- **必选组件**: 评分表（维度/权重/得分）、问题清单、整改建议
- **可选组件**: 评审标准、历史 PRD
- **组装顺序**: 定标准→逐维评分→列问题→排优先级→整改建议
- **约束**: 评分须给依据；问题须可整改
- **格式**: PRD 评审报告

#### SD1-05 产品路线规划
- **必选组件**: 版本规划表、里程碑、依赖、资源估算
- **可选组件**: 业务目标、研发产能
- **组装顺序**: 定目标→拆版本→排优先级→估资源→定里程碑
- **约束**: 版本须有可交付价值；依赖须标注
- **格式**: 产品路线图

### SD2 教学方案

#### 域级说明

**域定位**：按课程标准设计教案与课程结构，保证教-学-评一致性。

| 维度 | 内容 |
|------|------|
| 价值链形态 | 学情→目标→活动→评价 |
| 独立成域的理由 | 受课程标准约束，验收看教-学-评三者是否一一对应 |
| 穷尽性 | 5 个任务覆盖「学情→目标→活动→评价」的 4 个环节；按输入物、失败模式、验收标准三条判据互不重叠，无未覆盖环节 |
| 知识要点 | 教-学-评一致性：目标（学到什么）→ 活动（怎么学）→ 评价（怎么知道学会了）；教学目标撰写：行为动词 + 条件 + 标准（如"能列举三类…并说明…"），对应布鲁姆认知层级；课标对应：《义务教育课程标准（2022年版）》学科核心素养与学段要求；教案结构：课题、课时、学情分析、目标、重难点、准备、教学过程（导入/新授/练习/小结）、板书、作业、反思；分层教学：基础/提高/拓展三层任务设计；提问设计：封闭→半开放→开放，等待时间与追问链 |
| 判定标准 | 目标须可观测，禁止"理解""感受"等不可测动词单独使用；每个活动须对应一个目标，无对应活动的目标须删；评价任务须与目标一一对应；重难点须说明突破手段 |
| 常见失范 | 目标笼统不可测；活动丰富但与目标无关；评价缺失或与目标错位；重难点只标注不给突破方法 |
| 范本结构 | 课题与课时 → 学情分析 → 教学目标（分层） → 重难点与突破手段 → 教学过程（分环节+时间） → 板书设计 → 作业与评价 → 反思 |

#### SD2-01 教案设计
- **必选组件**: 课题课时、学情分析、分层目标、重难点、教学过程、板书、作业、评价
- **可选组件**: 课标、教材、学情数据
- **组装顺序**: 析学情→定目标→定重难点→排教学过程→设评价→写板书
- **约束**: 目标须可测；活动须对应目标；评价须一一对应
- **格式**: 教案

#### SD2-02 单元与课程大纲设计
- **必选组件**: 单元目标链、课时分配、能力进阶图、评价节点
- **可选组件**: 课标、教材目录
- **组装顺序**: 定单元目标→拆课时→排进阶→设评价节点
- **约束**: 单元目标须覆盖课标要求；课时须可执行
- **格式**: 课程大纲

#### SD2-03 备课素材与教学资源准备
- **必选组件**: 素材清单、例题梯度、拓展材料、使用说明
- **可选组件**: 教材、题库、多媒体资源
- **组装顺序**: 列素材需求→选编例题→配拓展→写使用说明
- **约束**: 素材须对应目标；例题须有梯度
- **格式**: 备课素材包

#### SD2-04 讲师备注与授课脚本
- **必选组件**: 逐页备注、提问设计、时间标记、应变提示
- **可选组件**: 课件、教案
- **组装顺序**: 对页写备注→设提问→标时间→写应变
- **约束**: 须口语可讲；提问须有预设答案
- **格式**: 讲师手册

#### SD2-05 课标对齐检查
- **必选组件**: 对齐矩阵（课标条目×教案环节）、差距清单、补齐建议
- **可选组件**: 课标原文、教案
- **组装顺序**: 拆课标条目→逐条映射→判覆盖率→补差距
- **约束**: 须逐条对应；覆盖率不足须给补齐方案
- **格式**: 课标对齐表

### SD3 测评方案

#### 域级说明

**域定位**：设计试卷、题库与练习体系，保证信度、效度与难度梯度。

| 维度 | 内容 |
|------|------|
| 价值链形态 | 细目表→命题→难度控制→分析 |
| 独立成域的理由 | 验收看信度、效度与难度分布，不看文档完整度 |
| 穷尽性 | 5 个任务覆盖「细目表→命题→难度控制→分析」的 4 个环节；按输入物、失败模式、验收标准三条判据互不重叠，无未覆盖环节 |
| 知识要点 | 双向细目表：知识点 × 认知层级（识记/理解/应用/分析/评价/创造）配比；难度分布：易:中:难 常见 7:2:1 或 6:3:1，按用途调整；题型功能：选择（覆盖广）、填空（精确记忆）、简答（表达）、综合（迁移）；信度与效度：题目区分度（高分者答对率 − 低分者答对率）、猜测度；变式题三法：换数据、换情境、换问法（保持考查点不变）；错题反哺：按知识点归因后定向补题 |
| 判定标准 | 须有双向细目表，禁止凭感觉组卷；难度分布须明确目标比例；每题须标知识点与认知层级；变式题须保持考查点一致 |
| 常见失范 | 题目重复考查同一知识点；难度失控导致区分度低；答案与题干存在歧义；变式题实际换了考查点 |
| 范本结构 | 命题目标与范围 → 双向细目表 → 试卷正文 → 参考答案与评分标准 → 难度与区分度预估 → 讲评建议 |

#### SD3-01 试卷生成
- **必选组件**: 双向细目表、试卷、答案、评分标准、难度预估
- **可选组件**: 考纲、题库、学情
- **组装顺序**: 定范围→建细目表→选题→配难度→审题→出答案
- **约束**: 须覆盖细目表全部条目；答案须唯一
- **格式**: 试卷+答案

#### SD3-02 题库建设
- **必选组件**: 题目、知识点标签、认知层级、难度、区分度、来源
- **可选组件**: 教材、真题、错题
- **组装顺序**: 定标签体系→录题→标难度→去重→审核
- **约束**: 标签须一致；须标来源与版权状态
- **格式**: 结构化题库

#### SD3-03 变式题与举一反三
- **必选组件**: 原题、变式题组（换数据/情境/问法）、考点说明
- **可选组件**: 错题记录、知识点
- **组装顺序**: 定考点→设计变式维度→生成题组→校验考点一致
- **约束**: 变式不得改变考查点；须给梯度
- **格式**: 变式题组

#### SD3-04 作业分层设计
- **必选组件**: 分层作业单、完成标准、预计时长
- **可选组件**: 学情分层、课标要求
- **组装顺序**: 定分层→配题量→设标准→估时长
- **约束**: 每层须有明确适用对象；总时长须可控
- **格式**: 分层作业单

#### SD3-05 测评结果分析与反哺
- **必选组件**: 得分率表、知识点诊断、区分度分析、补教建议
- **可选组件**: 测评数据、细目表
- **组装顺序**: 算得分率→对细目表→找薄弱→算区分度→补教
- **约束**: 须区分群体薄弱与个体薄弱；补教须可执行
- **格式**: 测评分析报告

### SD4 培训方案

#### 域级说明

**域定位**：设计面向成人的培训项目，从需求分析到效果评估闭环。

| 维度 | 内容 |
|------|------|
| 价值链形态 | 需求→设计→实施→评估 |
| 独立成域的理由 | 验收在柯氏四级的行为层与结果层，周期长于其他方案，须设计训后转化 |
| 穷尽性 | 5 个任务覆盖「需求→设计→实施→评估」的 4 个环节；按输入物、失败模式、验收标准三条判据互不重叠，无未覆盖环节 |
| 知识要点 | ADDIE 模型：分析、设计、开发、实施、评估；成人学习原则：目标导向、经验联结、即学即用、问题中心；学习目标三层：知道（知识）、会做（技能）、愿做（态度）；柯氏四级评估：反应、学习、行为、结果；工作坊设计：破冰 → 输入 → 练习 → 共创 → 输出 → 承诺；转化设计：训前任务、训中练习、训后 30 天行动计划和复盘 |
| 判定标准 | 目标须区分知道/会做/愿做；每个模块须有练习与产出；评估须覆盖至少两级；须设计训后转化机制 |
| 常见失范 | 只有讲授没有练习；目标全是"了解""掌握"；无评估或只评满意度；训后无转化设计 |
| 范本结构 | 需求分析与目标 → 学员画像 → 课程结构与时长 → 每模块活动与产出 → 讲师与物料 → 评估方案 → 转化机制 |

#### SD4-01 培训需求分析
- **必选组件**: 绩效差距、能力缺口、需求优先级、培训边界
- **可选组件**: 业务目标、岗位标准、访谈
- **组装顺序**: 定业务目标→找绩效差距→判是否培训可解→排优先级
- **约束**: 须区分培训可解与管理/流程问题
- **格式**: 培训需求报告

#### SD4-02 培训课程大纲设计
- **必选组件**: 模块大纲、学习目标、时长、活动类型、产出物
- **可选组件**: ADDIE、成人学习原则
- **组装顺序**: 定目标→拆模块→配活动→排时长→定产出
- **约束**: 每模块须有可交付产出；目标须分层
- **格式**: 培训大纲

#### SD4-03 工作坊与共创设计
- **必选组件**: 流程脚本（分环节+时间+引导语）、材料清单、分组规则
- **可选组件**: 学员构成、场地条件
- **组装顺序**: 定产出→设计环节→写引导语→备材料→排时间
- **约束**: 每环节须有明确产出；时间须留缓冲
- **格式**: 工作坊方案

#### SD4-04 训后转化设计
- **必选组件**: 行动计划模板、30天任务、复盘节点、跟踪方式
- **可选组件**: 业务场景、主管支持
- **组装顺序**: 定应用场景→设任务→定复盘→设跟踪
- **约束**: 任务须嵌入真实工作；须有主管参与
- **格式**: 转化方案

#### SD4-05 培训效果评估
- **必选组件**: 评估指标表（四级）、工具（问卷/测试/观察/业绩）、时间点
- **可选组件**: 基线数据
- **组装顺序**: 定指标→选工具→定时间点→采数据→分析
- **约束**: 须有训前基线；结果级指标须可控归因
- **格式**: 评估方案

### SD5 营销方案

#### 域级说明

**域定位**：设计活动与促销方案，从机制设计到执行 SOP 与复盘。

| 维度 | 内容 |
|------|------|
| 价值链形态 | 目标→机制→节奏→SOP→复盘 |
| 独立成域的理由 | 验收看 GMV 与 ROI；机制须能被用户一眼算清，否则无效 |
| 穷尽性 | 5 个任务覆盖「目标→机制→节奏→SOP→复盘」的 5 个环节；按输入物、失败模式、验收标准三条判据互不重叠，无未覆盖环节 |
| 知识要点 | 活动五要素：目标、人群、机制（利益怎么给）、渠道、节奏；促销机制类型：满减、折扣、赠品、秒杀、预售、拼团、会员专享、返券；价格合规：原价须真实、优惠须可计算、不得虚构折扣；节奏设计：预热（蓄水）→ 爆发（转化）→ 返场（追单）→ 沉淀（复购）；执行 SOP 要素：时间轴、责任分工、物料清单、话术、风险预案、监控指标；复盘四问：目标达成否、哪些动作有效、哪些无效、下次改什么 |
| 判定标准 | 活动机制须可被用户一眼算清；目标须量化到 GMV/新客/复购；SOP 须精确到时间点与责任人；预算与 ROI 须预估 |
| 常见失范 | 机制复杂用户算不清；只有创意没有执行排期；无风险预案（库存/客服/系统）；复盘只报数据不归因 |
| 范本结构 | 活动目标与人群 → 机制设计 → 节奏排期 → 渠道与物料 → 执行SOP与分工 → 预算与ROI预估 → 风险预案 → 复盘指标 |

#### SD5-01 活动策划
- **必选组件**: 目标（量化）、人群、机制、节奏表、资源需求
- **可选组件**: 历史活动数据、预算
- **组装顺序**: 定目标→选人群→设机制→排节奏→配资源
- **约束**: 机制须可算清；目标须量化
- **格式**: 活动方案

#### SD5-02 促销机制设计
- **必选组件**: 机制说明、门槛梯度、成本测算、用户感知价值
- **可选组件**: 商品毛利、竞品活动
- **组装顺序**: 定让利空间→设计梯度→算成本→验感知
- **约束**: 须守住毛利底线；机制不得自相矛盾
- **格式**: 促销机制表

#### SD5-03 节点与节日营销
- **必选组件**: 节点日历、主题创意、货品组合、投放节奏
- **可选组件**: 平台大促日历、节气节日
- **组装顺序**: 排节点→定主题→组货品→排投放
- **约束**: 主题须与节点强相关；货品须匹配主题
- **格式**: 节点营销方案

#### SD5-04 执行 SOP 与分工
- **必选组件**: 时间轴 SOP、责任矩阵（RACI）、物料清单、话术
- **可选组件**: 团队结构、供应商
- **组装顺序**: 拆任务→定时点→定责任人→备物料→写话术
- **约束**: 每个时点须有交付物；责任人须唯一

| 独立成域的理由 | 以低门槛可持续为验收点，看依从率而非训练强度 |

| 知识要点 | 正念冥想：专注注意力 → 觉察分散 → 温和带回；身体扫描、呼吸锚定、开放觉察；呼吸技术：箱式呼吸 4-4-4-4、4-7-8 助眠、生理性叹息、交替鼻孔呼吸；睡眠卫生：固定起床时间、光照暴露、咖啡因半衰期（5-6h）、睡前降温、屏幕管理；压力模型：压力源 → 认知评估 → 应激反应 → 应对资源；习惯养成：微习惯、触发锚点、即时奖励、环境设计；剂量原则：短时高频优于长时低频；从 3 分钟起步 |

### SD12 诉讼方案

#### 域级说明

**域定位**：为具体案件设计应诉或起诉策略，输出争议焦点与证据矩阵。

| 维度 | 内容 |
|------|------|
| 价值链形态 | 事实→请求权→焦点→证据→庭审 |
| 独立成域的理由 | 以争议焦点与证据矩阵为核心，验收看裁判结果与执行可行性 |
| 穷尽性 | 4 个任务覆盖「事实→请求权→焦点→证据→庭审」的 5 个环节；按输入物、失败模式、验收标准三条判据互不重叠，无未覆盖环节 |
| 知识要点 | 七步分析法：事实梳理 → 法律关系定性 → 请求权基础 → 争议焦点 → 证据匹配 → 抗辩路径 → 风险评估；请求权基础：合同履行请求权、违约损害赔偿、侵权损害赔偿、不当得利返还、物权请求权；争议焦点提炼：从诉辩主张的差异中归纳，须可被裁判者直接回应；证据矩阵：待证事实 × 证据 × 证明力 × 缺口；举证责任分配：谁主张谁举证；举证责任倒置的法定情形；风险量化：胜诉概率分档、执行风险、时间成本、和解区间 |
| 判定标准 | 请求须具体、可执行、有请求权基础；每个争议焦点须有证据支撑或明确缺口；须评估对方可能的抗辩并预设应对；须给和解区间与底线 |

| 范本结构 | 案件事实梳理 → 法律关系与请求权基础 → 争议焦点 → 证据矩阵 → 抗辩与应对 → 风险评估 → 策略建议与和解区间 |

- **可选组件**: 诉状/答辩状、证据材料
- **组装顺序**: 排时间线→定法律关系→找请求权→提炼焦点
- **约束**: 焦点须可被裁判回应；须区分事实争议与法律争议
- **格式**: 案件分析报告

#### SD12-02 应诉与起诉策略

- **可选组件**: 对方主张、法院倾向
- **组装顺序**: 定立场→设主线→排程序→查管辖时效→定和解
- **约束**: 须含对方最强抗辩的应对
- **格式**: 诉讼策略方案

#### SD12-03 证据矩阵构建
- **必选组件**: 证据矩阵表、证明力评估、缺口清单、补证方案
- **可选组件**: 证据目录、原件状态
- **组装顺序**: 列待证事实→配证据→评证明力→找缺口→补证
- **约束**: 每个焦点须有证据或明示缺口；须标原件状态
- **格式**: 证据矩阵

#### SD12-04 庭审准备与预案

- **约束**: 须预判对方质证点；预案须分情景
- **格式**: 庭审准备包

### SD13 应急预案

#### 域级说明

**域定位**：把"出事时慌乱"变成"照单执行"。预案的价值不在写得全，而在触发条件可判定、责任不落空。

| 维度 | 内容 |
|------|------|
| 价值链形态 | 识别→分级→处置→沟通→恢复→演练 |
| 独立成域的理由 | 与其他方案不同构：预案的验收不发生在执行时，而在演练与事故复盘时；核心是触发条件与权限，而非路径效率。 |
| 穷尽性 | 4 个任务覆盖「识别→分级→处置→沟通→恢复→演练」的 6 个环节；按输入物、失败模式、验收标准三条判据互不重叠，无未覆盖环节 |
| 知识要点 | 风险矩阵：可能性×影响；区分黑天鹅（低概率高影响）与灰犀牛（高概率被忽视）；预案五要素：触发条件、响应分级、指挥与分工、处置流程、恢复与复盘；分级响应：提示/警戒/紧急，各级对应权限与通知范围；单点故障与冗余：关键路径识别、备份方案、切换演练；沟通预案：对内通报、对外声明、监管报备三条线；演练与迭代：桌面推演、实战演练、复盘修订 |
| 判定标准 | 每个预案须有可判定的触发条件；分级须对应明确权限与通知范围；关键动作须有备份责任人；必须含演练与修订机制 |
| 常见失范 | 触发条件写成"情况严重时"；只写流程不写分工；主责缺席即瘫痪，无备份；制定后从不演练 |
| 范本结构 | 风险清单与分级 → 触发条件 → 响应分级与权限 → 处置流程与分工 → 沟通与报备 → 恢复与复盘 → 演练计划 |

#### SD13-01 风险识别与分级
- **必选组件**: 风险清单（事件/可能性/影响/等级）、关键路径、单点故障
- **可选组件**: 历史事故、业务流程图
- **组装顺序**: 列风险→评可能性→评影响→矩阵定级→标单点故障
- **约束**: 须覆盖低频高影响事件；单点故障须单列
- **格式**: 风险清单与矩阵

#### SD13-02 应急处置流程设计
- **必选组件**: 触发条件表、响应分级、指挥与分工、处置步骤、备份责任人
- **可选组件**: 组织架构、资源清单
- **组装顺序**: 定触发条件→分级→定指挥→排处置步骤→设备份
- **约束**: 触发条件须可判定；每个关键动作须有备份人
- **格式**: 应急预案

#### SD13-03 沟通与对外声明预案
- **必选组件**: 通报对象与顺序、声明口径、报备要求、发言人
- **可选组件**: 监管要求、公关口径
- **组装顺序**: 定对象顺序→定口径→定发言人→定时点→备模板
- **约束**: 对外口径须统一；须明确谁不能说
- **格式**: 沟通预案+模板

#### SD13-04 演练与复盘机制
- **必选组件**: 演练类型与频次、评估标准、复盘流程、修订触发
- **可选组件**: 历史演练记录
- **组装顺序**: 定类型→定频次→定评估标准→定复盘流程→定修订触发
- **约束**: 须含实战演练；复盘须产出修订项
- **格式**: 演练与复盘计划

### SD14 预算与资源方案

#### 域级说明

**域定位**：把有限的钱与人力分到能产出结果的地方，并留出纠偏余地。预算的价值不在算得准，而在花超了知道先砍哪。

| 维度 | 内容 |
|------|------|
| 价值链形态 | 目标→测算→分配→控制→复盘 |
| 独立成域的理由 | 与其他方案不同构：预算的验收标准是"总额可控且每笔有归属"，核心是分配规则与偏差控制，而非动作编排。 |
| 穷尽性 | 4 个任务覆盖「目标→测算→分配→控制→复盘」的 5 个环节；按输入物、失败模式、验收标准三条判据互不重叠，无未覆盖环节 |
| 知识要点 | 预算三法：增量预算、零基预算、滚动预算；各自适用场景不同；成本结构：固定/变动、直接/间接、可延后/不可延后；分配原则：按产出贡献、按约束刚性、按风险敞口；三层并用而非单一标准；偏差控制：月度实际 vs 预算、偏差阈值、纠偏动作（冻结/转移/追加）；投入产出：ROI、回收周期、边际效益递减点；资源类型差异：钱可追加，人与时间不可；须分开建模 |
| 判定标准 | 每笔预算须有归属科目与责任人；固定与变动成本须分开列示；须设偏差阈值与纠偏规则；须给"砍什么"的优先级 |
| 常见失范 | 只给总额不给科目拆分；把一次性投入当经常性支出；超支后再补预算，无阈值预警；不留应急余量 |
| 范本结构 | 目标与预算总额 → 成本结构与测算依据 → 分配方案与优先级 → 偏差阈值与纠偏规则 → 投入产出测算 → 复盘节点 |

#### SD14-01 预算目标与总额测算
- **必选组件**: 目标、总额、固定/变动拆分、测算依据
- **可选组件**: 历史支出、行业基准
- **组装顺序**: 定目标→拆驱动因子→测算总额→分固定变动→标依据
- **约束**: 须给测算方法与假设；不得只报一个总数
- **格式**: 预算测算表

#### SD14-02 资源分配与优先级
- **必选组件**: 分配表（科目/金额/责任人/依据）、优先级、可延后项
- **可选组件**: 部门需求清单、战略优先级
- **组装顺序**: 列需求→三层评分→排序→分配→标可延后
- **约束**: 每笔须有归属与责任人；须明确可延后项
- **格式**: 资源分配方案

#### SD14-03 偏差监控与纠偏规则
- **必选组件**: 阈值表（科目/阈值/触发动作）、监控频率、纠偏流程
- **可选组件**: 财务口径、审批权限
- **组装顺序**: 定阈值→定频率→定动作→定审批→建台账
- **约束**: 阈值须分级；纠偏须有明确审批人
- **格式**: 预算控制规则

#### SD14-04 投入产出与复盘
- **必选组件**: ROI 测算表、回收周期、边际效益分析、复盘结论
- **可选组件**: 实际支出与产出数据
- **组装顺序**: 算投入→算产出→算ROI→看边际→复盘调
- **约束**: 产出须可计量；不得用"品牌价值"替代测算
- **格式**: 投入产出复盘报告

### SD15 客户与渠道运营方案

#### 域级说明

**域定位**：把"拉来的人"变成"留下来、买更多、带人来"的人，并把渠道变成可管理的销售网络。

| 维度 | 内容 |
|------|------|
| 价值链形态 | 分层→动作→渠道→激励→测算 |
| 独立成域的理由 | 与其他方案不同构：验收看客户留存与渠道 ROI，动作对象是外部合作方而非内部执行者。 |
| 穷尽性 | 4 个任务覆盖「分层→动作→渠道→激励→测算」的 5 个环节；按输入物、失败模式、验收标准三条判据互不重叠，无未覆盖环节 |
| 知识要点 | 客户分层：价值×潜力四象限，不同层配不同运营动作与投入；渠道类型：直营、经销、代理、平台、联营；分成结构与激励方向差异大；客户成功四阶段：上手期、成长期、成熟期、流失预警；各阶段指标不同；渠道冲突：区域、价格、客户归属三类冲突的规则设计；单位经济：CAC、LTV、回收周期、渠道成本占比 |
| 判定标准 | 每层客户须有专属动作，不得一套打法打所有；渠道政策须明确冲突处理规则；须给渠道 ROI 与回收周期；动作须落到责任人与频次 |
| 常见失范 | 所有客户一套动作；渠道政策无冲突条款，导致串货乱价；只招渠道不管赋能，渠道成为库存转移；不留客户归属证据 |
| 范本结构 | 客户分层结果 → 分层运营动作 → 渠道结构与政策 → 激励与冲突规则 → 赋能与考核 → ROI 测算 |

#### SD15-01 客户分层与运营设计
- **必选组件**: 分层规则、各层规模、专属动作、投入配比
- **可选组件**: 交易数据、行为数据、毛利结构
- **组装顺序**: 定分层维度→分层→配动作→配投入→定频次
- **约束**: 分层须可落地到动作；不得只分层不配资源
- **格式**: 分层运营方案

#### SD15-02 渠道结构与政策设计
- **必选组件**: 渠道结构图、分成分级、准入条件、退出机制
- **可选组件**: 现有渠道数据、竞品渠道
- **组装顺序**: 定层级→定分成→定准入→定退出→定区域划分
- **约束**: 须含冲突条款；分成须与贡献挂钩
- **格式**: 渠道政策

#### SD15-03 渠道赋能与考核
- **必选组件**: 赋能清单（培训/物料/工具）、考核指标、淘汰线
- **可选组件**: 渠道能力现状
- **组装顺序**: 评能力→定赋能→定考核→定淘汰→排节奏
- **约束**: 须区分新老渠道；淘汰线须公开
- **格式**: 渠道赋能方案

#### SD15-04 客户成功与流失挽回
- **必选组件**: 阶段划分、健康分模型、预警阈值、挽回序列
- **可选组件**: 使用数据、续费记录
- **组装顺序**: 分阶段→建健康分→定阈值→设挽回序列
- **约束**: 健康分须可计算；挽回须分层差异化
- **格式**: 客户成功方案

| 维度 | 内容 |

| 价值链形态 | 结构→岗位→考核→薪酬→编制 |
| 独立成域的理由 | 与其他方案不同构：验收看责任是否落到人、指标是否可控，而非流程是否顺畅。 |
| 穷尽性 | 5 个任务覆盖「结构→岗位→考核→薪酬→编制」的 5 个环节；按输入物、失败模式、验收标准三条判据互不重叠，无未覆盖环节 |
| 知识要点 | 组织结构：职能制、事业部制、矩阵、合弄；选择看业务复杂度与协同需求；岗位与职级：岗位说明书、职级带宽、管理与专业双通道；绩效：KPI 与 OKR 适用差异；指标控制在 5-8 个；须避免指标互相冲突；薪酬结构：固定与浮动比例、宽带薪酬、长期激励；内外公平两条线；编制测算：按业务量与人效倒推，而非按部门人头分预算 |
| 判定标准 | 每个岗位须有职责与考核标准；绩效指标须可控可测且互不冲突；薪酬须兼顾内外公平；编制须有测算依据 |
| 常见失范 | 组织调整只画框图不定职责；绩效指标互相打架（如同时考核销量与毛利）；薪酬靠拍脑袋不做市场对标；编制按人头分而非按业务量 |
| 范本结构 | 组织现状与问题 → 结构设计 → 岗位与职级 → 绩效方案 → 薪酬结构 → 编制与人效测算 |

#### SD16-01 组织结构设计
- **必选组件**: 现状问题清单、目标结构图、部门职责、汇报关系
- **可选组件**: 业务战略、现有架构、协作痛点
- **组装顺序**: 诊断问题→选结构类型→画层级→定职责→定汇报
- **约束**: 职责须无重叠无真空；须说明为何选该结构
- **格式**: 组织结构方案

#### SD16-02 岗位与职级体系
- **必选组件**: 岗位清单、岗位说明书、职级带宽、双通道定义
- **可选组件**: 现有岗位、市场职级对标
- **组装顺序**: 列岗位→写职责→定任职要求→定职级→开双通道
- **约束**: 职责须可考核；职级带宽须有依据
- **格式**: 岗位与职级体系

#### SD16-03 绩效方案设计
- **必选组件**: 指标表（岗位/指标/权重/口径）、考核周期、评分规则、结果应用
- **可选组件**: 业务目标、历史数据
- **组装顺序**: 定目标→选指标→配权重→定周期→定应用
- **约束**: 指标须可控可测且互不冲突；须防指标操纵
- **格式**: 绩效方案

#### SD16-04 薪酬结构设计
- **必选组件**: 薪酬带宽、固浮比、调薪规则、激励池设计
- **可选组件**: 市场薪酬数据、公司支付能力
- **组装顺序**: 定带宽→定固浮→定调薪→定激励→测算总成本
- **约束**: 须做内外公平校验；激励须与长期结果挂钩
- **格式**: 薪酬方案

#### SD16-05 编制与人效测算
- **必选组件**: 业务量预测、人效基准、编制测算表、缺口清单
- **可选组件**: 历史人效、行业基准
- **组装顺序**: 测业务量→定人效目标→算编制→比现状→列缺口
- **约束**: 须给测算依据；人效须可复算
- **格式**: 编制测算表

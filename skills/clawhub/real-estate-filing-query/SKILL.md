> **采集合规前提声明**：本技能仅用于读取各城市住建、房管部门**依法主动公开公示**的房源、备案价与配售结果数据；严格遵守目标平台服务条款、robots 协议与适用法律法规，不突破任何访问限制；如遇平台访问节奏限制，遵循其公开节奏、必要时人工辅助，不以技术手段强行突破。

# 房地产房源信息收集与可视化分析

把"定位项目 → 读取公开公示数据 → 标准化 → 去化口径 → 货值测算 → 可视化交付"的方法封装为可复用工作流。**采集是手段，去化研判与授信量化是目的**——不止于查备案价，更覆盖去化水分识别、可变现货值测算与结清触发点判断。

## 工作流（SOP）

> 🚦 **Step 0 强制前置 · 既有案例记录检索闸门**：接到任务先按 `references/案例检索闸门_SOP.md` 执行——用 `Glob`/`Grep` 检索工作区既有记录（既有采集底稿、官方公示备份、历史笔记、案例库），**命中即加载复用、禁止重复联网检索**；未命中才进入下列步骤，查完必落盘闭环。完整规范见 `references/案例检索闸门_SOP.md`。

1. **定位项目**：依据线索（客户/项目名/城市）匹配官方项目（开发企业 + 片区 → 预售证全库 → 销控总表）。
2. **读取公开公示数据**：读取目标城市住建/房管部门依法主动公开公示的房源明细、备案价与配售结果；优先采用官方导出的结构化表格。
3. **标准化**：统一字段（楼栋/单元/房号/面积/状态/价格），按城市字段映射归一到统一 schema。
4. **去化率四档口径**（必须并列，禁止只给一个数）：
   - **D 现金回笼（最保守）** = 已备案 / 总
   - **C 签约（最严口径）** = (总 − 在售 − 风险 − 登记 − 安居房) / (总 − 风险 − 登记 − 安居房)
   - **A 净口径（授信用）** = (总 − 在售 − 风险) / (总 − 风险)
   - **B 毛口径（最宽）** = (总 − 在售) / 总
   - 恒有 D ≤ C ≤ A ≤ B，用作一致性校验。
5. **货值测算**：有效可变现 = 在售 × (1 − 业态折扣)；按状态占比识别有效可变现，不双重扣减。
6. **可视化交付**：输出多 Sheet Excel（项目总览 / 逐套明细 / 四档去化 / 货值测算 / 风险标注 / 数据来源与口径），并附口径诚实声明。

## 去化率四档口径（核心铁律）

- **多口径并列**：任何去化结论必须同时给 D/C/A/B 四档，并单独暴露分母；缺失数据严禁当 0，以「—」标注。
- **状态互斥**：在售 / 已售 / 风险 / 首次登记 / 安居房 五类不重叠；有效可变现 = 在售 × (1 − 业态折扣)，不可再乘 (1 − 风险占比)。
- **保障房特殊处理**：安居型商品房平台"安居房"标签不区分已售/待售，须走住建局配售批次公示交叉印证（下载每批次"已选房源"xlsx，按状态列筛"已选定"= 实际签约套数），且必须列入排查名单、严禁静默剔除。
- **一致性校验**：D ≤ C ≤ A ≤ B；若出现倒挂（如 D > C）必为基数/口径错配，回溯修正。

## 数据来源分级与可信度

- **A 级（官方）**：住建/房管部门导出 xlsx、官方配售结果公示。交付物主数字采用 A 级口径。
- **C 级（自媒体）**：媒体/自媒体转述的去化数字，必须回查官方公示页升 A 级后才进交付物，不留未升 C 级残留。
- **D 级（认购中）**：尚在认购期、未出选房结果的批次，作为上限参考单列，不并入主数字。

## 交付规范

- Excel 多 Sheet：项目总览 / 逐套明细 / 四档去化 / 货值测算 / 风险标注 / 数据来源与口径。
- 文件命名：`{主体}_{类型}_{YYYYMMDD}[_vNN].{ext}`；数据时间带周几；口径诚实声明写入首行。
- 来源双色标注：官方来源浅绿底、外网来源浅黄底。
- 交付前回读实测（openpyxl 校验行列数 + 来源标注），口径诚实声明后再报完成。

## 案例检索闸门（本版新增）

`references/案例检索闸门_SOP.md` 定义了强制前置流程：每次任务开场先 `Glob`/`Grep` 全工作区查历史记录 → 命中即复用、禁重搜；未命中才新查，查完必落盘闭环。含"中文目录 Glob 漏匹配"兜底（用 `Grep` 笔记 + `ls` 兜底）。实测可拦住重复联网检索，避免重复劳动。

# 案例检索闸门 SOP（既有记录先查 · 强制前置）

> **强制级别：硬前置闸门。** 适用于 `real-estate-filing-query` / `real-estate-absorption-rate` / `developer-group-cross-analysis` 三个 skill 的**任意"调查 / 核查 / 采集某具体楼盘、项目、开发商、城市"任务**。
> **在发起任何 `WebSearch` / 平台抓取 / 财汇MCP 调用之前，必须先走本闸门。违反 = 重复劳动 = 流程失败。**

---

## 一、为什么必须有这道闸门（根因）

案例资产已大量沉淀：`references/cases/`、`references/城市实跑案例库.md`、`output_cross/` 下各 `官方公示备份_*` / `*_cross/` 目录、`.workbuddy/memory/` 的每日日志与 `MEMORY.md`。

但旧流程**只规定了"事后写"（案例沉淀与回写 / 动态总结进 skill），没有强制"事前读"**。结果是：每次新对话 / 新任务，Agent 凭记忆想起才查，想不起就重新联网搜索 → 用户反复提醒"上次不是查过了吗 / 这些案例应该都有记录的"。

**本闸门把"先查"从"靠记性"变成"流程强制"**——不开场自查，不许动手搜。

---

## 二、执行步骤（每次任务开场必做，先于一切外部调用）

### Step 1 · 派生多别名检索词
一个项目通常有多套名字，漏一个就可能漏掉既有记录：
- 推广名、备案名、项目别名（如「山樾湾」→「山樾湾花园」）
- 开发商（含 JV / 合作 / 子公司备案主体名，如「汉京」）
- 政策批次号（安居房尤其重要：`住保售〔2026〕064号`）
- 所在城市 / 区

### Step 2 · 并行检索既有记录（用 `Glob` / `Grep`，**不是** `WebSearch`）
一次性并行扫以下位置：
1. `Glob **/*<推广名>*`、`Glob **/*<备案名>*` —— 全工作区扫（重点：`output_cross/`、`shenzhen_all_units/`、`*_cross/`、`*官方公示备份*`）。
2. `Grep "<项目名|别名>"` 于 `.workbuddy/memory/MEMORY.md` 与各 `YYYY-MM-DD.md`。
3. `Grep` 于 `references/cases/` 与 `references/城市实跑案例库.md`。
4. 留意"官方公示备份"类目录（命名常含 `官方公示备份` / `cross` / 日期戳）——这类目录里常有**原始公示 xlsx / 网页 HTML**，是下次免重抓的关键资产。

> 检索动作本身不占对话 token（Glob/Grep 走索引），不要怕"多查一次"。

> ⚠️ **工具兜底（实测踩坑）**：`Glob` 对**中文目录名常漏匹配**（如 `山樾湾_官方公示备份_20260930/` 用 `**/*官方公示备份*` 会返回"无文件"，但目录真实存在）。**因此 Step 2 不能只信 Glob**：
> - 必用 `Grep` 搜项目名/别名命中既有笔记（笔记里通常会写明指向哪个备份目录）；
> - 若 Glob 疑似漏扫，用 `Bash ls` / `find` 兜底确认中文目录；
> - 三路并行（Glob 文件 + Grep 笔记 + Bash 中文目录兜底）才能确保不漏。

### Step 3 · 判定与动作
- **命中既有记录** → 先 `Read` 加载，按 **2026-09-09 强制规则**核"是否为最新"：
  - 对比**文件名日期戳** vs 内容里的**"数据时间"字段**；
  - 若存在更新版本，**改用最新版**并明确告知用户"旧版 X 已被 Y 取代"；
  - 同目录同名产物多日期版本时，**默认取文件名日期最大者**（见用户 2026-09-09 铁律）。
  - 已能回答用户问题 → **直接复用，禁止重新联网搜索**；开场即告知"已查到既有记录 X（日期），结论为…"。
  - 仅部分回答 → **只补缺口**，开场说明"在既有 X 基础上补充 Y"。
- **未命中** → 走正常新调查；完成后**必须**走下方闭环，保证下次可查。

### Step 4 · 安全网（防已误发搜索）
若开场就误发起了搜索才发现已有记录：**立即停止重复搜索**，回退到 Step 3 复用既有记录，并向用户说明"已有既有记录，已停止重复检索"。

## 三、闭环要求（写后须可查，否则白做）

1. **落盘位置**遵循产物命名规范 `{主体}_{类型}_{YYYYMMDD}[_vNN]`；依赖文件（数据源）绝不改名（改名=断链）。
2. **原始公示 / 底稿随结论一起落盘**：官方 xlsx、网页 HTML、原始接口响应等，**必须存进备份目录**，而非只存分析结论——下次直接读本地、不重抓。这正是用户说的"省的每次去找老的数据"。
3. **写索引指针**：在 `.workbuddy/memory/YYYY-MM-DD.md` 记**一句话索引**（结论 + 关键文件路径），便于跨会话检索；跨城/跨项目长期结论另写入 `MEMORY.md`。
4. **回写既有笔记而非平行新建**：若同一案例已有笔记（如 `山樾湾花园安居房去化_官方交叉印证_20260824.md`），**回写更新**该笔记（把"待查"改"已查"+指向备份目录），**不要新建一份平行全量文档**造成重复与版本分裂。

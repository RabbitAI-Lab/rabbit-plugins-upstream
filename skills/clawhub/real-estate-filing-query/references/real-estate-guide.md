# 房地产项目采集 — 技术参考（示例平台基准）

> **合规前提**：本参考仅描述如何读取各城市住建/房管部门**依法主动公开公示**的房源、备案价数据。所有采集须遵守目标平台《服务条款》、robots 协议与适用法律法规；**不得尝试规避、绕过或破坏平台已设置的访问控制、身份认证或速率限制**。若平台要求授权登录、内网/VPN 可达或明确禁止自动化访问，应停止自动采集、改以人工合规方式获取，或放弃该数据源。本参考中的平台名称、域名与接口路径均为**示例占位**，实战中须以目标平台实际公开页面为准。
>
> 方法论跨城市可复用；以下具体接口 / 字段以某一示例平台为基准，换城市按同法重新探查。

## 一、可直接套用的任务提示词（复制粘贴，替换 { } 占位）

```
角色：房地产房源数据采集与可视化分析助手。

任务：采集 {城市}{平台名称} 上「{项目名称}」的全部房源数据，生成可视化、可检索的 Excel，并做简版分析总结。
目标平台：{平台域名}
项目名：{项目名称}

执行要求（务必遵守，避免走弯路）：
1. 平台多为单页应用 + 动态令牌保护，纯静态直连不可用 → 用浏览器自动化读取页面已公开返回的接口数据。
2. 【关键】先找"项目列表/搜索页"定位其数据接口，按项目名搜索，一次性拿到该项目名下【所有预售证】及其 项目ID / 预售证ID（一个项目常有多张预售证，且各证 项目ID 可能不同，漏证会丢楼栋）。
3. 逐张预售证访问详情页，定位房源数据接口，提取全部房源。
4. 房源接口响应通常是【按楼层分组】结构（data:[{floor, list:[house,...]}]），提取时必须遍历 data[].list，不能当扁平 list。
5. 字段映射按实际接口响应校准（楼栋/楼层/房号/建筑面积/套内/分摊/备案总价/备案单价/状态/合同编号）。
6. 价格行为：很多平台只给"期房待售"公开备案价，已备案/已售等不公开 → 缺失价属正常，勿当异常；缺失单价可用 总价/面积 回算。
7. 每次采集把当前聚合（总套数、各状态计数、均价、按 日期/周/月/季 分桶）写入 history/snapshots.json，用于跨期对比与突变检测。
8. 异常检测：对比上一快照，监控 总套数/期房待售/备案均价 突变；区分"异常/提示"两级；首跑无基准不报。
9. 生成 Excel（≥5 Sheet）：房源明细（可筛选/条件格式）、统计分析（图表）、分析总结、数据变化对比（日/周/月/季）、异常与告警。
10. 日常执行优先用免费或经济模型；但⚠️ 自动化(automation)的 modelId 不能设为 "lite"——"lite" 是 Agent 工具变体名，自动化运行时不认，会导致定时任务启动失败、完全不执行。自动化 modelId 用 "default" 或具体模型标识符；交互式 Agent 调用可用 model:"lite" 省钱。

交付物：output/{项目名}_房源数据_*.xlsx + 简版分析总结。
```

## 二、标准作业流程（SOP）

| 步骤 | 动作 | 要点 |
|---|---|---|
| 1 | 定位列表/搜索入口 | 找"项目列表/在售楼盘搜索"页（哈希路由或独立路径），定位其数据接口 |
| 2 | 搜索项目名 → 拿全部预售证 | 列表接口返回 项目ID + 预售证ID + 预售证号；逐条记录，别漏证 |
| 3 | 逐证访问详情页 | 用 `详情页URL?项目ID&预售证ID` 构造地址，定位房源接口 |
| 4 | 读取并提取房源 | 浏览器自动化读取页面已公开返回的响应 + 关键字过滤；解析响应，遍历楼层分组拿房源 |
| 5 | 标准化字段 | 统一映射到 楼栋/楼层/房号/面积/价格/状态/合同编号 |
| 6 | 写历史快照 | 聚合写入 `history/snapshots.json`（存聚合不存全量） |
| 7 | 生成 Excel + 分析 | 明细 / 统计 / 总结 / 对比 / 告警 五 Sheet |
| 8 | 异常与对比 | 用上一快照做 delta；日/周/月/季四维度对比 |

## 三、关键技术参考（示例平台，作探查基准）

- 示例平台：`{平台域名}/szfdcscjy/`（单页应用，哈希路由 `#/...`）
- 项目列表页：`#/foreignPublic/listApartmentHunting/listApartmentHuntingSj`
  - 列表接口：`/ysf/publicity/getYsfYsPublicity`
  - 返回关键字段：`sypId`=项目ID，`sypeId`=预售证ID，`strpreprojectid`=预售证号
- 详情页 URL 格式：`#/projectTable/projectTableDetails/projectTableDetails?ysProjectId={id}&preSellId={id}`
- 楼栋枚举接口：`/projectPublish/getBuildingNameListToPublicity` → `data:[{label:楼栋名, value:buildNo, key:楼栋ID}]`
- 单元/楼层枚举接口：`/projectPublish/getBuildingDictToPublicity` → `data:{gnqmcList:[单元名...], chList:[楼层...], buildNo}`
  - ⚠️ 这两个枚举接口 **简单直连会报错**，只能读取页面自动发起的响应来解析（不传参数，依赖页面选中状态）
- 房源核心接口：`/projectPublish/getHouseInfoListToPublicity`（**POST**，动态令牌，可逐单元取数）
  - 请求体：`{buildingbranch:"X单元", floor:"", 楼栋ID:"楼栋ID", housenb:"", status:-1, type:"", ysProjectId, preSellId}`
  - **默认只返回 1单元**；必须对每个 `(楼栋, 单元)` 各 POST 一次
- 响应结构：`{status, msg, data:[{floor:N, list:[house,...]}, ...]}` —— **按楼层分组**
- 字段映射（原始 → 输出列）：
  `buildingName`→楼栋 · `buildingbranch`→单元 · `floor`→楼层 · `housenb`→房号 · `useage`→用途 · `ysbuildingarea`→建筑面积 · `ysinsidearea`→套内面积 · `ysexpandarea`→分摊面积 · `askpricetotalB`→备案总价 · `askpriceeachB`→备案单价 · `lastStatusName`→状态 · `strcontractid`→合同编号
- 状态取值（实际，比文档更全）：期房待售 / 已签认购书 / 已签合同 / 已备案 / 首次登记 / 已录入合同 / 司法查封 / 安居房 / 在建抵押 / 自动锁定 / 区局锁定 / 市局锁定 / 共有产权房
  - 去化口径：`去化 = 总套数 − 期房待售`（其余状态均视为已去化）
- 价格行为：仅"期房待售"公开备案价，其余不公开属正常；缺失单价用 总价/面积 回算
- **实测案例（示例项目）**：1栋 5 单元共 **2746 套**（预售总套数亦为 2746）；单元分布 1单元453/2单元1036/3单元430/4单元441/5单元386；用途 商务公寓1489+住宅1257；状态 已备案1381/首次登记1357/司法查封7/已签合同1；期房待售0（去化100%）。**只取默认 1单元会漏 2293 套（84%）**——务必逐单元全量抓取。

## 四、可复用脚本骨架

换项目时只改配置与字段映射，逻辑零重写：

- `PERMITS` 列表：每项含 `ysProjectId / preSellId / presell_no / url`，遍历采集即自动覆盖多证多楼栋
- `compute_snapshot(houses, now)`：聚合为紧凑快照（总套数/状态计数/均价 + `date/iso_week/month/quarter` 分桶）
- `load_history()/save_history()`：读写 `history/snapshots.json`（按日期+小时去重、同小时只留最新、最多留 1000 条）
- `find_baseline(history, now, kind)`：取 日/周/月/季 对比基准
- `detect_anomalies(...)`：对比上一快照做突变检测，分 `异常/提示` 两级
- `add_comparison_sheet()`：Excel「数据变化对比」Sheet
- `add_alert_sheet()`：Excel「异常与告警」Sheet（价格缺失区分 待售缺失/非待售不公开）
- Excel 五 Sheet：房源明细 / 统计分析 / 分析总结 / 数据变化对比 / 异常与告警

## 五、避坑清单（省 token 关键）

1. 列表页先于详情页：详情页接口只返回当前预售证数据，从详情页永远挖不到"其他证/其他楼栋"。找全预售证必须走列表搜索接口。
2. request/response handler 用 `x.url`，不是 `x`（Request/Response 对象不可直接 `in` 字符串，否则 TypeError）。
3. 响应按楼层分组：extract 必须遍历 `data[].list`。
4. 价格缺失别误报：非待售不公开备案价是平台规则，不是数据损坏。
5. **⚠️ 房源接口默认只返 1单元**：POST 带 `单元`，页面默认选中 1单元；必须枚举全部楼栋+全部单元、逐 `(楼栋,单元)` POST 取数并去重，否则大面积漏栋漏单元（示例项目漏 84%）。
6. **枚举接口不可简单直连**：楼栋/单元枚举接口直接请求返回错误，需读取页面自动发起的响应来解析；仅房源接口可逐单元 POST。
7. .doc 提示词文件：editor_sdk 常报 "document is not open"，改用二进制 `UTF-16LE` 解码 + 正则提取。
8. Chromium `__dirlock` 报错可忽略：实际已装在 `ms-playwright/chromium-*`。
9. 新需求先读项目 MEMORY.md：已最小化的关键事实都在里面，别重跑探索脚本。
10. 探索类临时脚本（`explore_*.py`）用完即弃，别进版本/长期记忆。
11. **⚠️ 自动化 modelId 勿用 "lite"**：`"lite"` 是 Agent 工具变体名，自动化运行时不认，设成 "lite" 会导致定时任务启动失败、完全不执行（实测 8/7 设置后 8/8 全天 + 8/9 上午任务全缺席）。自动化 modelId 用 `"default"` 或具体模型标识符；交互式 Agent 调用仍可用 `model:"lite"` 省钱。在确认某 modelId 对自动化有效前，勿盲目设置。
12. **快照按"日期+小时"去重**：`save_history()` 应按 `YYYY-MM-DD HH` 分桶、同小时只留最新一条，避免短时多次运行（手动+自动化撞车）导致快照堆积膨胀。

## 五-B、城市平台参考（探查方法论示意，非具体绕过步骤）

- 部分城市的房源信息由住建部门统一公示平台提供；有的平台数据经单点登录保护、仅政务网/VPN 内网可达，**外网环境无法取得逐套明细**，此时应停止自动采集、改以人工合规方式或放弃该数据源。
- 任何城市的采集都须先确认该平台是否允许自动化访问；若 robots 协议或服务条款禁止，则不得自动采集。

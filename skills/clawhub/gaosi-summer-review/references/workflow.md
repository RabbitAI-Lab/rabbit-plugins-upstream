# 高思导引暑假总复习 — 详细工作流

本文件给出从「拿到知识树图片」到「交付可打印 PDF + 量化打卡表」的完整操作步骤。
配套真值表见 `references/knowledge-tree.md`，可直接复制的成品模板见 `assets/plan-template.html`。

## 阶段 0：取图与知识树（可选）

仅在用户提供了 IMA 知识库里的《高思导引专题知识树.jpg》时需要。

1. 用 `mcp__ima-mcp__get_knowledge_base_list`（type 必填，用 `KBT_MINE_KB`）列出知识库，找到目标库 id。
2. 用 `mcp__ima-mcp__search_knowledge`（filters 加 `MEDIA_TYPE_FILTER_TYPE` + `IMG`）按文件名搜索图片，取出 `media_id`。
3. 用 `mcp__ima-mcp__fetch_media_content` 取内容 —— **注意它只返回 OCR 文本，且通常只识别标题与年级标注，识别不出专题名**。
4. 结论：不要依赖 OCR 还原专题。直接以 `references/knowledge-tree.md` 的官方结构作为知识树真值，图片仅作路线示意。

## 阶段 1：组装总复习计划（HTML）

复制 `assets/plan-template.html` 到用户工作目录，按以下约定调整：

**结构（必备章节，顺序固定）**
1. 标题 + 说明（依据 IMA 图片 + 官方目录 72 讲制定）
2. 总体要求（红黄蓝分级 + 兴趣/拓展全做基线）
3. 七/八模块知识树总览表（序 / 模块(分级) / 四年级(24讲) / 五年级(24讲) / 六年级(24讲)，逐讲列出讲号+标题）
4. 8 周复习路线（日历）：每周一个标签块，用 pill 列出该周**全部**讲次（如「四①整数计算综合」），并标注红黄分级
5. W1–W8 逐日详细表：每周一张表，列 = 星期 / 日期 / 模块 / 当日讲次 / 学习重点 / 要求(▲红·超越全做) / 时长
6. 打卡表（见阶段 2）
7. 提示与说明

**时间约定**
- 周一~周五每天 4~5 小时；周六、周日休息（不排新内容）。
- 暑假按 8 周设计；若实际周数不同，按模块权重缩放（计算/几何/应用/计数/数论为重心，各占 1 周；行程单列 1 周；数字谜并入数论周或单独半天；组合 1 周；最后 1 周综合模拟+查漏）。

**分级贯穿**
- 红黄蓝色块（CSS `.tier.t-red` / `.tier.t-ylw`）须出现在：总体要求图例、知识树模块列、8 周路线周标签、W1–W8「要求」列、打卡表模块列。蓝色（t-blu）默认不使用（组合已升红）。

## 阶段 2：量化打卡表

放在计划第 6/7 节，分两张表。

**4.1 每日量化打卡表（40 个学习日 = 8 周 × 周一至周五）**
列：周 / 星期 / 日期 / 模块 / 兴趣篇错误题号 / 拓展篇错误题号 / 超越篇错误题号 / 当日正确率 / 二次强化 / 打卡✅
- 「错误题号」记录当日做错的题号（作错题本/二刷索引），全对填「—」。
- 删除：错误类型(代号)、错题订正、完成自评、家长签字等冗余列。
- 「二次强化」：标记当日是否需回炉（可写讲次或打 ✅）。
- 「打卡✅」：每日完成后的打卡确认。
- 日期预填从暑假起始日（默认 07-20 起）。

**4.2 每周不足汇总与分析（8 周 + 暑期合计）**
列：周 / 本周正确率 / 薄弱讲次(需二刷) / 强化措施 / 周打卡
- 正确率按**周维度**统计：本周正确题数 ÷ 本周总题数。
- **低于 85% 的模块优先二刷**（核心判定线）。
- 把「刷题量」转化为「提分」复盘：聚焦薄弱讲次与改进动作。

**题量参考（提示框写明）**：每讲 兴趣篇约 10 题、拓展篇约 14 题、超越篇约 8 题；按实际正确/错误数填入。

## 阶段 3：导出 PDF

用 Chromium 内核无头打印（Edge / Chrome 均可）。脚本见 `scripts/build_pdf.py`，用法：

```bash
python scripts/build_pdf.py <输入.html> <输出.PDF>
```

脚本自动探测 `msedge.exe` / `chrome.exe` / `chromium` 路径并执行：
`--headless --disable-gpu --no-pdf-header-footer --print-to-pdf=<out> <file://in>`

校验：生成后检查 `%PDF-` 头、`%%EOF` 尾、xref 指针；`file` 命令应识别为 `PDF document`。

## 阶段 4：交付与「打不开」排障

文件结构合法但用户报「打不开」时，**几乎总是打开方式问题，不是内容损坏**。按序排查：

1. **中文长文件名**：部分阅读器/预览面板对中文长文件名的大文件加载失败。→ 同时生成一份 **ASCII 文件名副本**（如 `gaosi-summer-review.PDF` / `.html`）供双击打开。
2. **预览面板加载失败**：WorkBuddy 的 artifact 预览对大文件偶发失败。→ 起本地静态服务器，用浏览器 URL 打开最稳：
   ```bash
   python -m http.server 8777 --bind 127.0.0.1   # 在文件所在目录执行
   # 访问 http://127.0.0.1:8777/gaosi-summer-review.html
   ```
3. 校验文件完整性（排除半截写入）：
   - HTML：以 `</html>` 结尾；`<table>`/`</table>`、`<tr>`/`</tr>` 数量配对。
   - PDF：`obj`/`endobj`、`stream`/`endstream` 数量配对（注意 `endstream` 中的 `stream` 子串会干扰正则，以 `endobj`/`endstream` 计数为准）。

交付时优先附 **ASCII 文件名副本 + 本地服务器 URL**，最稳。

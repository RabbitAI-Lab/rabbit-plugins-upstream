## SIPOC 概述

### 什么是 SIPOC

SIPOC 是六西格玛管理中的核心流程映射工具，由五个英文单词的首字母组成：

| 字母 | 含义 | 中文 | 说明 |
|------|------|------|------|
| **S** | Supplier | 供应商 | 提供输入的任何来源 |
| **I** | Input | 输入 | 流程所需的资源、材料或信息 |
| **P** | Process | 流程 | 核心业务活动或处理步骤 |
| **O** | Output | 输出 | 流程产生的产品或服务 |
| **C** | Customer | 客户 | 接收输出的个人或组织 |

### SIPOC 的价值

1. **端到端视野**: 从全局视角审视流程
2. **清晰边界**: 明确流程的起点和终点
3. **责任明确**: 识别供应商和客户关系
4. **沟通工具**: 促进跨部门协作
5. **持续改进**: 为流程优化提供基础

## 各要素详解

### Supplier（供应商）

**定义**: 向流程提供输入的任何内外部来源

**类型区分**:

| 类型 | 示例 | 说明 |
|------|------|------|
| 外部供应商 | 原材料供应商、外包服务商 | 组织外部的合作方 |
| 内部供应商 | 上游部门、内部系统 | 组织内部的提供者 |

**填写要点**:
- 列出所有关键供应商
- 标注每个供应商提供的具体输入
- 区分供应商类型（内/外）

**示例**:

| 供应商名称 | 提供内容 |
|-----------|---------|
| 原材料供应商 | 金属板材、塑料颗粒 |
| 质检部门 | 质量检验标准 |
| 库存系统 | 实时库存数据 |
| 客户 | 采购订单、需求说明 |

---

### Input（输入）

**定义**: 供应商提供的资源、材料或信息

**输入类型**:

| 类型 | 示例 | 关注点 |
|------|------|--------|
| 原材料 | 零部件、物料 | 规格、质量 |
| 信息/数据 | 订单、报告、客户信息 | 准确性、时效性 |
| 资源 | 设备、人力、资金 | 可用性、效率 |
| 文档 | 规范、图纸、合同 | 版本、合规性 |

**填写要点**:
- 列出所有关键输入
- 说明输入的来源（哪个供应商）
- 定义输入的规格或质量要求
- 标注必要时的特殊要求

**示例**:

| 输入名称 | 描述 | 规格要求 | 来源供应商 |
|---------|------|---------|-----------|
| 原材料订单 | 采购申请单 | 包含数量、规格、交期 | 客户 |
| 库存数据 | 仓库实时库存 | 准确率>99% | 库存系统 |
| 质量标准 | 检验规范文件 | 最新版本 | 质检部门 |

---

### Process（流程）

**定义**: 核心业务活动或处理步骤

**流程层级**:

```
一级流程（价值链）
    ↓
二级流程（业务域）
    ↓
三级流程（具体活动）
```

**步骤数量建议**:
- 最佳: 5-7 个步骤
- 最少: 3 个步骤
- 最多: 10 个步骤

**填写要点**:
- 使用动词开头描述步骤
- 保持步骤粒度一致
- 标注关键控制点
- 说明步骤间的输入输出关系

**示例**:

| 步骤序号 | 步骤名称 | 描述 | 关键控制点 |
|---------|---------|------|----------|
| 1 | 订单接收 | 接收客户订单并验证完整性 | 订单信息完整性 |
| 2 | 库存确认 | 检查库存可用性 | 库存准确率 |
| 3 | 订单处理 | 完成订单配货和定价 | 处理时效 |
| 4 | 质量检验 | 对产品进行质量检查 | 检验覆盖率 |
| 5 | 发货执行 | 安排物流发货 | 发货准确率 |
| 6 | 客户签收 | 确认客户收货 | 签收及时性 |

---

### Output（输出）

**定义**: 流程产生的产品、服务或信息

**输出类型**:

| 类型 | 示例 | 说明 |
|------|------|------|
| 有形产品 | 成品、半成品 | 物理形态的产品 |
| 服务 | 咨询、维修 | 无形服务 |
| 信息 | 报告、通知 | 数据或文档输出 |
| 决策 | 审批结果 | 流程产生的结论 |

**填写要点**:
- 列出所有输出
- 区分主要输出和副产物
- 定义输出的质量标准
- 标注输出接收方（客户）

**示例**:

| 输出名称 | 描述 | 质量标准 | 目标客户 |
|---------|------|---------|---------|
| 成品 | 检验合格的产品 | 符合规格要求 | 客户 |
| 发货通知 | 物流发货通知 | 包含完整物流信息 | 物流部门 |
| 质检报告 | 产品质量报告 | 数据准确、完整 | 质量部门 |
| 结算单 | 费用结算单据 | 金额准确 | 财务部门 |

---

### Customer（客户）

**定义**: 接收和使用流程输出的个人或组织

**类型区分**:

| 类型 | 示例 | 说明 |
|------|------|------|
| 外部客户 | 终端用户、购买方 | 组织外部的接收方 |
| 内部客户 | 下游部门、后续工序 | 组织内部的接收方 |

**填写要点**:
- 列出所有客户
- 说明每个客户接收的输出
- 了解客户的期望和需求
- 标注客户的满意度要求

**示例**:

| 客户名称 | 接收输出 | 客户需求 |
|---------|---------|---------|
| 终端用户 | 成品 | 质量可靠、交期准时 |
| 物流部门 | 发货通知 | 信息完整、及时 |
| 质量部门 | 质检报告 | 数据准确、可追溯 |
| 财务部门 | 结算单 | 金额准确、凭证齐全 |

## 绘制规范

### 格式要求

1. **标题**: 流程名称居中显示
2. **五列布局**: Supplier → Input → Process → Output → Customer
3. **列宽比例**: 建议 15:15:40:15:15
4. **箭头方向**: 从左到右，Supplier → Customer

### 视觉规范

| 元素 | 建议颜色 | 说明 |
|------|---------|------|
| Supplier | 红色系 (#e74c3c) | 强调供应重要性 |
| Input | 橙色系 (#f39c12) | 警示输入关键性 |
| Process | 蓝色系 (#3498db) | 流程核心地位 |
| Output | 绿色系 (#27ae60) | 表示产出成果 |
| Customer | 紫色系 (#9b59b6) | 客户至上理念 |

### 层级关系

```
┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐
│         │     │         │     │         │     │         │     │         │
│SUPPLIER │ ──► │  INPUT  │ ──► │ PROCESS │ ──► │ OUTPUT  │ ──► │CUSTOMER │
│         │     │         │     │         │     │         │     │         │
└─────────┘     └─────────┘     └─────────┘     └─────────┘     └─────────┘
```

## 最佳实践

### 1. 流程边界清晰

- **起点**: 从供应商提供输入开始
- **终点**: 到客户接收输出结束
- **避免**: 将过多步骤纳入单一SIPOC

### 2. 粒度适中

- **推荐**: 5-7 个核心流程步骤
- **过细**: 超过10个步骤，考虑拆分
- **过粗**: 少于3个步骤，考虑合并

### 3. 输入输出对应

- 确保每个输出都有对应的客户
- 确保每个输入都有对应的供应商
- 验证输入与流程步骤的逻辑关系

### 4. 客户视角

- 从客户需求出发定义输出
- 定期收集客户反馈
- 将客户满意度纳入质量标准

### 5. 持续更新

- 流程变更时及时更新SIPOC
- 定期审查SIPOC的准确性
- 将SIPOC作为培训的基础材料

## 常见问题

### Q1: 一个流程有多个供应商和客户怎么处理？

**A**: 列出所有供应商和客户，每个都可以单独关联到对应的输入输出。如果供应商/客户数量较多，可以按类型分组或仅列出关键的3-5个。

### Q2: 内部部门算供应商还是客户？

**A**: 根据角色判断：
- 如果向本流程提供信息/资源 → 作为内部供应商
- 如果接收本流程的输出 → 作为内部客户

### Q3: SIPOC 和流程图有什么区别？

**A**:

| 维度 | SIPOC | 流程图 |
|------|-------|--------|
| 侧重点 | 端到端视野 | 步骤细节 |
| 要素 | 5个核心要素 | 活动、决策、顺序 |
| 使用场景 | 流程梳理初期 | 详细设计后 |
| 受众 | 管理层、跨部门沟通 | 执行人员 |

### Q4: 如何验证SIPOC的完整性？

**A**: 检查清单：
- [ ] 所有关键供应商已列出
- [ ] 所有关键输入已识别
- [ ] 流程步骤数量适中（3-10个）
- [ ] 所有输出有对应客户
- [ ] 输入输出与流程步骤逻辑对应
- [ ] 客户需求已在输出中体现

### Q5: 可以用SIPOC做什么？

**A**: 主要应用场景：
1. **流程梳理**: 快速建立流程全貌
2. **跨部门沟通**: 统一语言和视野
3. **培训材料**: 新人了解业务的基础
4. **持续改进**: 识别改进机会
5. **合规审计**: 证明流程可控
6. **标准化**: 建立流程基线

# 校车运行与安全检查记录核对（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：学校（幼儿园 / 小学 / 中学）的**安全管理员**、校车服务公司的**车队长 / 安全员**，
在**每月月底**（以及每学期开学、上级检查、出事故后倒查之前）必须把本月这一摞记录核一遍才能签字归档。

**为什么必须核**：校车安全管理条例要求校车**每半年检验一次**、**每日出车前检查**
（制动 / 灯光 / 轮胎 / 灭火器 / 逃生锤），驾驶员要有**校车驾驶资格**与**无犯罪记录 / 体检证明**，
随车照管人员要**每趟交接点名**；**超载、超速、非固定线路运行都是直接处罚项**，
一旦出事**学校与校车服务公司都要担责** —— 届时能拿出来说话的只有这些记录。

**这张表会逐项核对什么（本免费版 6 项）**：

1. **出车检查记录覆盖**：按 车辆 × 出车日期 核对"应有检查次数 vs 实际次数"，**缺哪台车哪一天逐一点名**
2. **检查项目齐全性**：检查项目数 ≥ 规定检查项目数，不足给出**缺项差额**
3. **驾驶员资格有效期**：出车日期 ≤ 驾驶证 / 校车驾驶资格 / 体检证明到期日，超期给出**天数**
4. **同一车辆同一日期重复登记**（同车同日被记了两遍）
5. **合计行逐列复核**：合计行的 趟次 / 核载人数 / 实际乘坐人数 / 里程 / 油耗 与明细逐列比对
6. **空白与格式检测**：关键字段空白或占位符、日期与时间格式、数值为负或无法解析、
   检查结果状态值非法、出车时间晚于收车时间

每条结论都带**原文行号与出处**（`第 N 行` + 原始行文本 + 车牌 / 日期 / 数字），可被第三方用同一口径复算；
材料不足时**不给结论**，会明确列出还缺什么。

## 这个免费版查什么

跑 `node scripts/run.mjs --sample` 会打印本次实际执行的检查项。**本免费版不执行**下面这 5 项
（引擎的 `CHECKS_WITHHELD` 已如实声明，它们只会出现在"未执行"清单里，绝不会被伪造出来）：

- **超载**（实际乘坐人数 > 核载人数 ⇒ 点名车辆 / 日期 / 超载人数，按超载人数降序）
- **照管人员交接缺失**（有趟次记录但照管人员为空或照管交接记录缺失 ⇒ 逐行点名）
- **非固定线路运行**（是否固定线路=否 且缺线路审批记录 ⇒ 逐行点名）
- **车辆检验有效期覆盖**（出车日期 ≤ 半年检验有效期至，超期给出天数）
- **分车辆 × 分驾驶员 / 分照管人员汇总清单与 consolidated_actions**（按超载 / 超期 / 缺检次数排序，给出可整改动作）

## 怎么用

```bash
node scripts/run.mjs --sample                 # 先看样例（样例就是一张干净的记录表，应 0 命中）
node scripts/run.mjs --input 你的材料.json     # 跑自己的材料
node scripts/run.mjs --sample --json          # 机器可读
```

把 Excel 里那张表的**表头与数据行一起**复制成文本贴进来（Tab 分隔最稳）。必需列：

车辆牌照、车辆识别代号（VIN）、核载人数、实际乘坐人数、出车日期、出车时间、收车时间、检查项目数、
规定检查项目数、检查结果、驾驶员姓名、驾驶证到期日、校车驾驶资格到期日、体检证明到期日、照管人员、
趟次、里程(km)、是否固定线路。缺列只会得到"材料不足"，**不会得到任何结论**。

## 常见错法（校车安全管理里最常见的 5 个坑）

1. **把"没记录"当成"没出车"**：停运、封存、放假的当天不给记录留一行，月底看起来没有缺口；
   但事后倒查时"没有记录"和"没有检查"是分不清的 —— 停运当天也要写明停运并留人签字，
   否则本工具会按本表出现的全部出车日期逐台车点名"缺哪一天"。
2. **"检查项目数"照抄规定项数**：每天一律填 10 项，实际一个勾都没有。
   本工具只能核"项目数 ≥ 规定项数"这个算术，**勾选项是否真的检了，要靠纸质 / 平板上的检查表对着看**。
3. **只盯"驾驶证到期日"**：忘了**校车驾驶资格**与**体检证明**各自也有有效期，
   而且体检证明通常一年一检、比驾驶证短得多 —— 三个到期日都要逐行比出车日期，超期当天就不能出车。
4. **把"每半年检验"记成"年检"**：台账里只有年度检验日期，出车日期落在两次半年检验之间时，
   车辆检验有效期其实已经不覆盖了；这一项在免费版里不做，但它更说明记录本身要按真实检验周期记。
5. **核载人数口径填错**：把含驾驶员 / 照管人员的**总座位数**当成核载人数，或把抱在怀里的孩子不算人数，
   "实际乘坐人数"看起来永远不超 —— 超载是直接处罚项，核载人数要按行驶证核定载客填写，
   同时**照管人员交接要写上下车人数**（只签名不写人数，超载就没人报）。

## 需要完整档时（可选）

本免费版是**完整可用的核心产出**，本版本**不包含**下面这些项：

- 超载（实际乘坐人数 > 核载人数 ⇒ 点名车辆 / 日期 / 超载人数，overloads 按超载人数降序）
- 照管人员交接缺失（有趟次记录但照管人员为空或照管交接记录缺失 ⇒ 逐行点名）
- 非固定线路运行（是否固定线路=否 且缺线路审批记录 ⇒ 逐行点名）
- 车辆检验有效期覆盖（出车日期 ≤ 半年检验有效期至，超期给出天数）
- 分车辆 × 分驾驶员 / 分照管人员汇总清单与 consolidated_actions（按超载 / 超期 / 缺检次数排序，给出可整改动作）

同名工具的**完整档**是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别**就是上面这些，没有别的**。

## 边界（请务必知道）

本工具**不做**引擎 `CHECKS_OUT_OF_SCOPE` 里列的那些判断：不判定学校与校车公司的主体责任、行政处罚与事故责任，
不判定出车检查与交接点名是否**真实发生**（不去现场、不查 GPS 与随车视频），
不判定驾驶员实际驾驶能力与照管人员是否培训合格，不读 .xlsx / .pdf 扫描件、核对过程不联网核验证件与检验报告真伪。

材料不足时**不给结论**，也不会输出「未发现问题」——
既不说「记录齐全」，也不说「记录有问题」。

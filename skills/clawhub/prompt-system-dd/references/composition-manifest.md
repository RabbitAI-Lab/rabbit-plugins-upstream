## 概览

本清单定义"任务特征 → 原子筛选 → 模板组装"的完整流程。原子清单以目录实际文件为准(注册制),本文件不复制原子内容,仅定义选择规则。深度语义与指纹规范见 [depth-adaptation.md](depth-adaptation.md)。

## 组装流程(八步)

1. **信息检查**:任务信息不足时,按路由协议追问(最多 2 问),否则进入第 2 步。
2. **深度基调判定**:以 [routing-protocol.md](routing-protocol.md) 复杂度/风险计分制为唯一判定算法(下方速查表仅为计分结果的档位对照,禁止直接按特征词跳过计分)。
3. **覆盖检查**:按 depth-adaptation.md 覆盖触发规则,确定需覆盖的原子及档位,生成 DEPTH 指纹(默认 `[B,B,B,B,B,B,B,B,B]`,覆盖后逐位修改)。
4. **原子筛选**:
   - 核心原子:读取 9 个核心原子全文,按指纹逐位选用对应深度段;
   - 域原子:按"域判定信号表"匹配,命中则读取对应域原子(未命中任何信号则不注入域内容);
   - 输出原子:按"输出判定表"匹配,命中则读取(可多个,组合输出场景全部读取)。
5. **合法性校验**:对指纹执行 depth-adaptation.md 依赖规则 R1-R5,违反则修正指纹(修正记录写入优化日志)。
6. **模板组装**:按 role-anchor → task-define → context-inject → example-shot → format-spec → think-chain → constraints → self-check → iterate 顺序,将各原子选用段组装为完整提示词,头部写入 DEPTH 指纹。
7. **模型适配(可选)**:若产出头部带 `@model=<id>` 后缀,读取 `references/model-adapters/<id>.md`,按其规则做段落形态改写,并在尾部追加该适配器的"注入模块"。**禁止改写 9 位档位与头部指纹**。无后缀则跳过本步,保持通用中文 Markdown 形态。
8. **门禁自检**:按各原子质量检查清单逐项核对,并对照 SKILL.md 七维表"对应原子"列确认每维均有原子支撑,产出前确认通过。

| 基调 | 计分制档位(与 routing-protocol.md 计分结果对照) | 默认指纹 |
|------|---------------------------------------------|---------|
| B1 | 复杂度 0-1 分 | [1,1,1,1,1,1,1,1,1]（think-chain/self-check 同取 D1） |
| B2 | 复杂度 2-3 分 | [2,2,2,2,2,2,2,2,2] |
| B3 | 复杂度 4-5 分 | [3,3,3,3,3,3,3,3,3] |
| B4 | 复杂度 ≥6 分或触发风险信号(重大决策影响/高专业门槛/技术密集) | [4,4,4,4,4,4,4,4,4] |

规则:

- 合法 id 以 `references/model-adapters/` 目录实际文件为准(注册制,门禁 MA003/MA004 双向校验);
- 未指定 `@model=` 后缀时不适配,产出通用形态,不追加注入模块;
- 模型后缀与 9 位档位正交,切换模型不得改变任何一位档位(详见 depth-adaptation.md 模型适配后缀节);
- 新增适配器:创建 `references/model-adapters/<id>.md`(头部含 MODEL-ADAPTER 契约块),在本表登记,运行门禁 MA001-MA004 通过。

## 原子注册制说明

- 原子文件清单以 `references/atoms/{core,domains,outputs}/` 目录实际内容为准,本清单不维护文件枚举;
- 新增原子后,按 depth-adaptation.md 扩展指南登记位序/信号表,并运行门禁验证;
- 门禁脚本动态扫描目录,新增原子自动纳入校验;核心原子必须登记信号表与指纹位序,域/输出原子必须登记判定信号(未登记将触发门禁 MF011);
- 原子文件重命名视为删除+新增,必须同步更新本清单信号表与指纹位序表。

# 组合示例(Complete Examples)

> 唯一真相源声明:本文件只展示"路由判定过程 + 指纹 + 组装产出",不复制任何原子内容。模板结构以 `references/atoms/` 各原子文件为唯一权威定义。

## 目录
- 示例1:B1 基调直出(欢迎邮件)
- 示例2:B3 基调 + 域注入 + 覆盖(市场调研报告)

## 示例1:B1 基调直出(欢迎邮件)

**输入**:写一封欢迎邮件 → 追问后补充:互联网公司运营岗新员工,活泼年轻化

**判定过程**:
- 复杂度信号:0 分;风险信号:无;产出短小有结构要求 → 路由B,基调 B1
- 域匹配:hr(命中"入职");输出匹配:text-doc(命中"邮件")
- 指纹:`DEPTH: [1,1,1,1,1,1,1,1,1]`,无覆盖

**组装要点**(各原子取 D1 段):
- role-anchor D1:经验丰富的 HR 专家,擅长年轻化员工沟通
- task-define D1:撰写 500-600 字入职欢迎邮件
- context-inject D1:任务自述即全部信息
- example-shot D1:产出附 1 个最小格式示例(邮件骨架)
- format-spec D1:标准邮件格式,500-600 字
- think-chain D1:无独立思考段
- constraints D1:3 条核心约束(含报道时间示例/对接人/必备材料)
- self-check D1:无
- iterate D1:直接说明修改点即可
- 域注入:hr 原子的角色与术语;输出注入:text-doc 模块

## 示例2:B3 基调 + 域注入 + 覆盖(市场调研报告)

**输入**:做一份国内新能源汽车市场调研,重点分析纯电和混动的用户接受度,为车企产品布局提供依据

**判定过程**:
- 复杂度信号:分章节(+1)、分析动词(+1)、需数据支撑(+1)、多路径比较(+1) = 4 分 → 基调 B3
- 域匹配:consulting(命中"市场分析/竞争格局",任务为行业调研咨询) → 单域注入。注:输入未出现任何财务诉求(成本/预算/投资回报),finance 不命中
- 输出匹配:text-doc(报告)+ chart-desc(趋势分析)→ 双输出
- 指纹:`DEPTH: [3,3,3,3,3,3,3,3,3]`,无覆盖

**组装要点**(各原子取 D3 段):
- role-anchor D3:5 年汽车行业调研分析师 + 车企战略视角 + 数据导向风格
- task-define D3:专项调研 + 四维边界 + 10000 字报告 + 为产品布局提供依据 + 3 条验收标准
- context-inject D3:已知事实标注来源(乘联会 2025 数据),规则引用具体政策名
- example-shot D3:附 1 个正例(合格调研章节结构)+ 1 个反例(无数据支撑的结论段)+ 差异说明
- format-spec D3:Markdown 分层 + 章节框架 + 颗粒度量化(每城市层级 3 个代表城市)+ 图表标注
- think-chain D3:三阶段思维链(分析/构建/压力),标签显式出现
- constraints D3:10 条约束 + 边界(不涉及氢能源/不分析海外)+ 量化表述
- self-check D3:5 项检查 + 7 维度自评,低于合格线修订后输出
- iterate D3:四维调整 + 触发词("补充小鹏案例"/"简化政策章节")
- 单域注入:consulting 框架(市场分析/竞争格局分析框架);双输出:text-doc 模块 + chart-desc 模块(趋势图部分)

## 示例3:B4 基调 + 双域注入 + 调档迭代(秒杀系统设计)

**输入**:设计高并发秒杀系统,要求支撑 10 万 QPS,含防刷策略 → 迭代反馈:"约束再严格些"

**首轮判定**:
- 复杂度信号:分模块(+1)、设计动词(+1)、多方案比较(+1)、推理过程(+1) = 4 分;风险信号:重大资源投入(+1)、错误不可逆(+1)、跨领域(+1) → 基调 B4
- 域匹配:tech(命中"高并发/QPS/架构") + legal(命中"防刷"关联合规) → 双域注入
- 输出匹配:text-doc(方案文档)
- 首轮指纹:`DEPTH: [4,4,4,4,4,4,4,4,4]`

**首轮组装要点**(各原子取 D4 段):
- role-anchor D4:首席架构师 + 双模态思维 + 责任锚定
- task-define D4:任务解码 + 3 个 KSF(支撑 10 万 QPS/防刷有效性/成本可控)+ 分阶段验收
- context-inject D4:锁定行业动态锚点(近年高并发架构演进),已知约束显式登记
- example-shot D4:附 2 个正例(合格方案章节/合格风险矩阵)+ 1 个反例(无量化指标的方案)+ 风格锚定说明
- format-spec D4:Markdown 分层 + 章节框架 + 颗粒度量化 + 图表标注 + 执行摘要/详细方案/验证指南/迭代路线图/避坑警示五件套
- think-chain D4:三阶段 + 3 个本质差异化方案(如:队列削峰 vs 令牌桶限流 vs 分层过滤,附风险矩阵)+ 魔鬼代言人批判 + 优化日志
- constraints D4:15 条约束 + 合规审查(反爬虫法规边界)+ 人工复核节点(容量压测结论)
- self-check D4:对抗性质疑 x3(如"Redis 热点 key 失效怎么办")+ 极端场景 x2(瞬时 10 倍流量/库存超卖)+ 复核节点声明
- iterate D4:结构化迭代契约 + 变更登记 + 版本追溯
- 依赖规则校验(全量求值):R1(think-chain=D4 → self-check≥D3:满足)、R2(constraints=D4 → role-anchor≥D3:满足)、R3(context-inject=D4,规则不触发:满足)、R4(task-define=D4 → constraints≥D2:满足)、R5(role-anchor=D4 → constraints≥D3:满足)→ 通过

**迭代调档**(用户:"约束再严格些"):
- 操作:constraints 已是 D4,确认无升档空间 → 按 depth-adaptation.md 覆盖触发表"顶档"行,选择路径①位不变-内容增强:constraints D4 的合规审查条目扩充
- 若某原子非顶档时类似反馈(如 format-spec=D2)则:指纹 `[4,4,4,4,2,4,4,4,4]` → `[4,4,4,4,3,4,4,4,4]`(第 5 位 format-spec),仅重生成 format-spec 对应模块
- 优化日志追加:`DEPTH: [4,4,4,4,3,4,4,4,4]`,变更点:format-spec 升 D3(颗粒度量化补齐)

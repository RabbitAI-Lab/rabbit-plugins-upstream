## 目录

## 概览

本协议定义层级深度动态适配的多要素体系:统一深度语义锚(保证各原子深度段语义一致)、DEPTH 指纹(产出可复现可审计,含后缀/哈希 R02/R07 与 @lang 处理规则)、覆盖触发规则(默认基调+例外覆盖+顶档分支)、档位 Token 基线(R04)、LITE 骨架豁免、依赖合法性规则。本协议是 depth 语义的唯一真相源,所有核心原子的深度段标题必须引用本协议的语义锚。

## 统一深度语义锚

所有核心原子的深度段使用以下全局语义,任何原子的档位定义不得偏离:

| 档位 | 全局语义 | 判定特征 |
|------|---------|---------|
| D1 极简 | 一句话/零段位,仅保留任务必需的最小表达 | 单行可完成;无结构要求 |
| D2 标准 | 要素齐全但不展开,量化到基本数字 | 3-6 条目;含基础量化 |
| D3 增强 | 要素完整+验证机制+可检验的颗粒度 | 8-10 条目;含自检/来源标注 |
| D4 专家 | 对抗验证+合规审查+人工复核+元机制 | 12+ 条目;含元层机制(日志/调档) |

冲突消解:若某原子的档位描述与本表冲突,以本表为准;原子文件需修订。

## 档位 Token 基线(R04)

> ⚠️ 下表数值为**估算待标定**,禁止当作事实引用。标定方法:用 benchmark/cases.yaml
> 的固定需求集在四个档位各组装 ≥5 份产出,取 token 数中位数回填。标定完成前,
> 门禁 TB001 校验表结构完整性;TB004 对数值做一致性比对(warning 级)。

| 档位 | 产出提示词 token 基线(估算) | 典型构成 |
|------|--------------------------|---------|
| D1 | ≈200 | 单段直出,无结构块 |
| D2 | ≈600 | 五段式 + 基础量化 |
| D3 | ≈1500 | 三阶段思维链 + 自检清单 + 来源标注 |
| D4 | ≈3500 | 对抗验证 + 合规审查 + 优化日志 + 复核节点 |

**预算反推公式**:给定预算 `B`,最高可用档位 `d = max{d | TOKEN_BASELINE[d] <= B}`。

- 若 `B < TOKEN_BASELINE[D1]`:预算过低,建议走 LITE 骨架直出而非组装;
- 若 `d < 基调判定档位`:提示降级,并在产出头部注明"因 token 预算限制,档位由 D{基调} 降至 D{d}";
- 降级后必须重跑依赖规则 R1-R5 —— 降级可能产生新的非法组合。

实现:`scripts/validate_skill.py --token-budget N` 输出推荐档位(info 级);门禁 TB001 校验本节表格与脚本 `TOKEN_BASELINE` 常量一致。

## DEPTH 指纹规范

- 格式:`DEPTH: [d1,d2,...,dN]`,每一位为 1-4 的整数,N 为核心原子总数。
- 位序固定为核心原子的组装顺序(与 composition-manifest.md 组装流程、validate_skill.py CORE_ATOM_KEYS 三方一致,由门禁 CORE-SEQ 校验):
  1. role-anchor 2. task-define 3. context-inject 4. example-shot
  5. format-spec 6. think-chain 7. constraints 8. self-check 9. iterate
- 示例:`DEPTH: [3,3,3,3,2,3,3,3,3]` 表示基调 B3(全局 D3),format-spec 覆盖降档至 D2。
- 变长扩展:新增核心原子后,指纹位数随之增加,新原子按组装顺序插入(见本文件"新增原子"扩展指南),历史指纹在日志中保留原位数并注明版本。
- 指纹必须写入产出模板头部;迭代调档后更新指纹。

## 指纹后缀与哈希(R02 / R07)

### 后缀语法

DEPTH 指纹可附加若干**后缀**,用于声明与档位正交的产出属性:

```
DEPTH: [d1,...,d9] [@model=<id>] [@lang=zh|en|bilingual] [@tokens=<正整数>]
```

| 后缀 | 含义 | 取值 | 省略时 |
|------|------|------|--------|
| `@model` | 目标模型,选择结构改写规则(R02) | 以 `model-adapters/` 目录注册为准,当前 claude/openai/gemini/deepseek/qwen | 不适配,保持通用中文 Markdown 形态 |
| `@lang` | 产出提示词的语言 | `zh` / `en` / `bilingual` | `zh` |
| `@tokens` | token 预算上限(R04) | 正整数 | 不限制 |

规则:

- 后缀顺序任意,解析时统一规范化;
- 合法后缀键仅上表三种,其余一律拒绝(门禁 FP004/FP005/FP007 族 / 脚本 `fingerprint.py parse`);
- `@tokens` 是**预算约束**,不是产出特征,因此不计入指纹哈希;
- 省略全部后缀的裸指纹 `[3,3,3,3,3,3,3,3,3]` 与 `... @lang=zh` 等价(默认值不产生新哈希,由 fingerprint.py canonical() 归一保证)。

#### @lang 处理规则(P1-6 空接口补全)

- `@lang=zh`(或缺省):产出提示词全文中文,内部标点统一中文标点(执行 SKILL.md 注意事项条款);
- `@lang=en`:产出提示词正文使用英文,标点遵循英文规范 —— **SKILL.md"中文标点"条款对该产出不适用**,以本条为优先级裁决;
- `@lang=bilingual`:主体中文 + 关键指令句附英文对照;中文段用中文标点,英文段用英文标点;
- 语言改写只调整措辞与标点,不得改变指纹位序、档位语义锚与模块条数(同 R07 一致性不变量);
- 当前 5 个 model-adapters 仅提供 zh 形态;en/bilingual 的适配器级改写属 v1(待 model-samples 按语言扩齐)。

### 指纹哈希(R07)

用于缓存命中与复现追溯:

- 规范串:`[<9 位档位>]|model=<id>|lang=<值>`,后缀按键名字典序排列,`@tokens` 排除;
- 哈希值:`sha256(规范串)` 取前 12 位,写作 `FP-HASH: <12 位十六进制>`;
- 计算:`python scripts/fingerprint.py hash "DEPTH: [...] @model=claude"`。

**用途**:同哈希的两次组装应产出结构一致的提示词,可直接复用历史优质产出(缓存库依赖 R03 快照归档,当前未启用)。哈希写入产出的优化日志,用于追溯"这次产出到底用的哪套档位"。

### 指纹 diff(R07)

用于迭代调档时评估影响面:

- 计算:`python scripts/fingerprint.py diff "<旧指纹>" "<新指纹>"`;
- 输出:逐位差异(位序 / 原子名 / from / to / 升降档)、受影响需重生成的模块清单、新指纹的依赖规则违规、新旧哈希;
- **退出码 3 表示存在降档**,供脚本判断是否需要人工确认。

**用途**:用户反馈"约束再严格些"时,先 diff 出影响面再决定只重生成对应模块,而不是全量重出。

### 正交性原则

模型后缀是**表达形态层**,与 9 位档位是正交的两个维度:

| 维度 | 控制什么 | 谁定义 |
|------|---------|--------|
| 9 位 DEPTH 指纹 | 各原子的深度档位(内容密度、验证强度) | 基调判定 + 覆盖调档 |
| `@model=` 后缀 | 同样的内容用何种结构表达(XML / Markdown / 指令块 / CoT 触发) | model-adapters/ |

因此:**切换目标模型不得改变任何一位档位**。若某模型需要更多约束条目,应通过调档实现,而非在适配器里偷偷加内容。

### 适配器的改写边界

适配器只做两件事,超出即为越界:

1. **段落形态改写**:把五段式映射为目标模型偏好的标签 / 标题 / 指令块;
2. **尾部注入**:追加一段目标模型专属的输出契约或触发语(见各适配器"注入模块")。

明确禁止:改写 DEPTH 头部指纹、增删约束条目、改变档位语义。

### 依赖规则不受影响

R1-R5 只作用于 9 位档位,与模型后缀无关。切换模型后无需重跑依赖规则。

## LITE 骨架豁免声明

SKILL.md 内嵌的 LITE 骨架(路由 A 直出用)豁免于"唯一真相源"条款,理由:LITE 骨架是零加载兜底(SKILL.md 必然加载,而原子需按需读取),其内容为压缩速查形态,与原子 D1/D2 段职责不同(骨架供直出,原子段供组装),二者为有意的差异化表达而非平行漂移。TS001 指纹检测因此仅针对完整框架结构块的复制,不针对骨架压缩行。

## 覆盖触发规则

默认行为:全局基调判定后,单值复制到全部 8 位(即 8 个原子同档)。仅在以下信号出现时做单原子覆盖:

| 触发信号 | 覆盖动作 | 约束 |
|---------|---------|------|
| 用户显式要求某模块加强/简化 | 对应原子升/降 1-2 档 | 不得违反依赖合法性规则 |
| 任务特征命中(如"高并发/合规审计") | 相关原子上浮 | 上浮不超过 2 档 |
| 迭代反馈"XX再严格些" | 指纹对应位调档 | 仅重生成对应模块 |
| 迭代反馈时目标原子已处 D4 顶档 | 指纹不变,二选一:①同档内内容增强(条目扩充/阈值收紧),优化日志记"位不变-内容增强";②改调关联原子上浮并说明理由 | 两条路径均不改变 DEPTH 指纹位序与哈希语义(哈希相同 ⇒ 结构契约相同,内容增强限于同档语义锚允许范围) |

覆盖原则:单次组装覆盖原子数不超过 3 个;超过则重新判定全局基调。

## 依赖合法性规则

以下组合禁止出现(组装前校验,违反则修正指纹):

| 规则 | 条件 | 要求 |
|------|------|------|
| R1 | think-chain = D4 | self-check ≥ D3 |
| R2 | constraints = D4 | role-anchor ≥ D3 |
| R3 | context-inject = D1 | think-chain ≤ D2 |
| R4 | task-define ≥ D3 | constraints ≥ D2 |
| R5 | role-anchor = D4 | constraints ≥ D3 |

## 扩展指南(扩展位预留机制)

本架构采用注册制:原子清单以 `references/atoms/` 目录实际文件为准,不写死于任何协议文档。新增原子按以下步骤执行,全程无需修改门禁脚本:

### 新增核心原子(type: core)

1. 创建 `references/atoms/core/<new-id>.md`,头部必须含标准 ATOM 契约块(参照现有核心原子);
2. 正文包含四段 `## D1 极简` 至 `## D4 专家`,语义遵循统一深度语义锚;
3. 末尾附质量检查清单(含"档位与指纹第 N 位一致"条目);
4. 在本协议"DEPTH 指纹规范"的位序表中按**组装顺序**登记(禁用字母序,门禁 DP007 校验三方一致);
5. 若该原子与其他原子存在强度耦合,在本协议"依赖合法性规则"追加规则(R 编号顺延);
   - 原子头部 ATOM 契约块的 `deps:` 字段语义 = 该原子参与的依赖规则编号(如 `deps: R2,R5`;不参与任何规则时为 `none`)。由门禁 RG006 与 fingerprint.py `DEPENDENCY_RULES` 反查强制一致 —— 新增/修改 R 规则后必须同步相关原子的 deps 行,否则门禁 error(P2-3 死接口已激活);
6. 运行门禁:`python scripts/validate_skill.py --skill-dir . --strict`,确认 0 错误。

### 新增领域原子(type: domain)

1. 创建 `references/atoms/domains/<domain-name>.md`,头部 ATOM 块 type 为 domain;
2. 正文包含:领域注入内容(典型角色/关键要素/专业约束/免责声明)+ 适用判定信号;
3. 在 composition-manifest.md 的域判定信号表登记信号关键词;
4. 运行门禁确认通过。域原子不分深度档,与核心原子正交。

### 新增输出原子(type: output)

1. 创建 `references/atoms/outputs/<output-type>.md`,头部 ATOM 块 type 为 output;
2. 正文包含:输出类型注入内容(适用场景/格式要求/特殊要求)+ 提示词注入模块;
3. 在 composition-manifest.md 的输出判定表登记;
4. 运行门禁确认通过。

### 新增深度档(如 D5)

1. 在本协议"统一深度语义锚"追加 D5 全局语义;
2. 全部核心原子同步追加 `## D5` 段(不可只改部分原子);
3. 指纹取值范围扩展为 1-5,同步更新本协议指纹规范;
4. 运行门禁确认全部原子四段校验通过(校验自动适配为五段)。

### 扩展红线

- 禁止绕过 ATOM 契约块直接添加文件(门禁 AT001 将拦截);
- 禁止在协议文档中复制原子内容(唯一真相源,门禁 TS001 指纹检测);
- 禁止新增原子后不运行门禁(交付前必须 strict 通过)。

# 模板路由协议(Routing Protocol)

> 本文件定义"任务特征 → 基调判定 → 组装路由"的完整路由规则,是难度判断的唯一真相源。SKILL.md 中的决策树是本协议的速查版,分歧时以本文件为准。

## 协议总览(接口式定义)

```
输入:用户自然语言需求 + 可选补充信息
处理:六步判定(见决策树)
输出:四选一路由结果
  ├─ 路由D:能力边界外(见"能力边界预判"节),说明限制并转交/降级/拆分
  ├─ 路由A:仅用 SKILL.md 内嵌 lite 骨架(零额外加载,简单任务直出)
  ├─ 路由B:执行组合清单组装流程(读 manifest + 原子库,按 DEPTH 指纹精准组装)
  └─ 路由C:先追问(最多2问)再路由
```

## 完整决策树(六步判定)

### 第零步:能力边界预判(R10)

**在任何计分之前执行**。判断需求是否属于"提示词工程解决不了"的类别,命中则走路由 D,不再进入计分。

```
需求是否命中 C1-C5 任一类?
  ├─ 命中 → 路由D:按"能力边界预判"节处理模板说明限制并给出路径
  └─ 未命中 → 进入第一步
```

详细判定信号与处理模板见下文"能力边界预判(R10)"节。**本步不做计分、不产出指纹。**

### 第一步:信息完整性检查

```
需求是否包含四要素?
  ├─ 场景/领域 ─ 是否知道什么行业、什么环境
  ├─ 受众/对象 ─ 产出给谁用/谁看
  ├─ 核心目标 ─ 要达成什么
  └─ 输出形式 ─ 什么格式、什么载体

四要素齐全 → 进入第二步
缺失 ≥1 项 → 进入第三步追问判定
需求完全模糊(如"帮我写个东西") → 边界场景1处理(见下文)
```

### 第二步:深度基调计分

对需求按下列信号计分(每命中一条记 1 分):

**复杂度信号**
- [ ] 产出物需分章节/模块(报告、方案、规划)
- [ ] 需要"基于某数据/背景/材料"才能完成
- [ ] 任务动词含"分析/评估/设计/规划/论证"
- [ ] 存在多种可行路径需要比较择优
- [ ] 需要展示推理过程或测算依据

**风险信号**
- [ ] 结论影响重大资源投入(大额预算、组织级变更、核心系统)
- [ ] 错误代价不可逆(战略方向、安全架构、合规风险)
- [ ] 跨 2 个以上专业领域
- [ ] 高专业门槛(涉及法律/医疗/金融等需执业资质领域的实质性内容)
- [ ] 技术密集(高并发、分布式、实时系统等工程复杂度显著的任务)

**计分 → 基调映射**(基调 = DEPTH 指纹默认值,见 composition-manifest.md)

| 得分 | 基调 | 路由 |
|------|------|------|
| 0-1 分(且无风险信号),且"产出短小无结构要求"成立(≤200 字,且无章节/表格/多段结构要求) | B1 | 路由A(LITE 骨架直出) |
| 0-1 分(且无风险信号),但产出有结构要求 | B1 | 路由B 组装(指纹 [1,1,1,1,1,1,1,1,1]) |
| 2-3 分(且无风险信号) | B2 | 路由B 组装(全 2 指纹) |
| 4-5 分 | B3 | 路由B 组装(全 3 指纹) |
| 含任一风险信号,或 6 分以上 | B4 | 路由B 组装(全 4 指纹) |

### 第三步:追问判定(仅当信息不全)

- 追问上限:2 个问题,超出的信息做合理假设,统一以"假设:"前缀标注(格式:"假设:〈内容〉;依据:〈来源〉")
- 追问优先级:场景/领域 > 受众/对象 > 核心目标 > 输出形式
- 常见场景提供选项降低认知负担(选项设计见边界场景 1)
- 追问完成后回到第二步计分

### 第四步:域与输出匹配(路由B 内执行)

- 域原子:按 composition-manifest.md 域判定信号表匹配,命中注入,未命中不注入
- 输出原子:按输出判定表匹配,多命中全读
- 歧义处理规则见 composition-manifest.md

### 第五步:组装与自检

- 按组装流程八步执行(见 composition-manifest.md)
- 覆盖检查:存在 depth-adaptation.md 触发信号时调整指纹(单次覆盖 ≤3 位)
- 依赖规则 R1-R5 校验:违反则修正指纹并记录
- 产出前执行各原子质量检查清单

## 边界场景处理

### 场景 1:模糊输入("帮我写个东西")

提供选项引导:

```
A. 撰写文档(报告、邮件、方案等)
B. 分析内容(市场分析、数据分析、竞品分析等)
C. 创意内容(文案、脚本、策划等)
D. 其他(请具体描述)
```

同时追问应用场景与受众,获答后回到第二步。

### 场景 2:需求冲突("既专业又活泼、既简洁又详细")

- 识别冲突要素,提供权衡建议,引导用户明确优先级
- 处理模板:说明冲突 → 给出 2 个权衡方案 → 用户选择后继续
- 冲突未决前不进入组装

### 场景 3:超复杂需求(5 个以上维度的大规划)

- 建议拆分为子任务,提供拆分方案(A 完整拆分 / B 聚焦核心 / C 用户指定优先级)
- 拆分后每个子任务独立走五步判定,独立产出 DEPTH 指纹
- 子任务间有依赖时,在各自 iterate 模块中声明衔接点

### 场景 4:超出认知边界(如"预测明年股市")

**本场景已归入"能力边界预判(R10)"节的 C5 类,判定信号与处理模板以该节为准,本节不重复定义。**

要点:诚实说明限制,禁止虚构数据;走该节 A 路径(降级为可解决的近似需求)后,替代方案同样走组装流程。

### 场景 5:高资质领域(法律/医疗/金融决策)

- 按领域注入对应域原子(法律→legal,医疗→medical,金融决策→consulting+finance 组合),约束原子强制上浮至 D4 的合规审查要求
- 产出中显式声明"需专业人士审核",并附人工复核节点

## 能力边界预判(R10)

> 目的:识别"提示词工程解决不了"的需求,避免用一套复杂的提示词去硬扛一个本质上需要工具 / 执行器 / 编排框架的问题。
> 诚实说明限制,比产出一个看似专业实则无效的长提示词更有价值。

### 类别与判定信号

| 类别 | 名称 | 判定信号(命中任一即判定) | 为什么提示词工程解决不了 |
|------|------|------------------------|------------------------|
| C1 | 需实时/外部数据 | 今天/当前/最新/实时/现在的价格·天气·库存·政策·新闻;要求引用模型训练截止后的事实 | 模型无实时数据,再好的提示词也变不出今天的股价 |
| C2 | 需执行副作用动作 | 帮我发/提交/下单/改/删除/部署/调用接口;要求产生文本之外的实际效果 | 提示词只产出文本,不产生动作 |
| C3 | 需确定性计算 | 精确大数运算、统计检验、回归拟合、排序去重、要求"算出准确结果" | 模型不保证数值精确,长提示词只降低错误率不消除它 |
| C4 | 需运行时编排 | 多角色协作、需并行分支、需中途校验后回溯、长链条且前序结果决定后序 | 单条提示词是单次前向过程,没有循环与状态 |
| C5 | 超出认知边界 | 预测未来、断言无公开数据的私有事实、要求给出唯一正确答案的主观问题 | 本质是虚构,提示词只能让虚构显得更可信 |

**C4 与边界场景 3 的区分**(避免重复处理):

| | 场景 3 超复杂需求 | C4 需运行时编排 |
|---|---|---|
| 特征 | 需求**维度多**(5 个以上) | 需求需要**循环、状态、回溯** |
| 解法 | 拆成子任务,各自独立走组装 | 交给 Agent 框架;或退化为人工驱动的串行子任务 |
| 是否仍可组装 | 是 | 否(单提示词不够) |

### 处理模板(路由 D)

命中任一类后,**不进入计分**,按以下模板响应:

```
识别到 [类别名称] 特征——[引用命中的判定信号]。

限制:[该类别"为什么解决不了"的一句话说明]。
本框架不伪装能解决它。可选路径:

A. 降级 —— 转为可解决的近似需求,走组装流程
   例: C1 → 产出"数据获取清单 + 分析框架",由你填入实时数据
        C3 → 产出"可执行代码/计算步骤"而非直接给数
        C5 → 产出"影响因素分析 + 情景推演"而非预测结论
B. 转交 —— 交给具备该能力的系统,本框架负责产出其输入提示词
   例: C2 → 转 Agent 工具链,本框架产出调用意图描述
        C4 → 转多智能体框架,本框架产出各角色的子任务提示词(R06 预留)
C. 拆分 —— 仅 C4 适用,按边界场景 3 拆分为人工驱动的串行子任务

请选择 A / B / C(或说明你的实际条件)。
```

### 执行约束

- **禁止**对 C1/C2/C5 直接产出"看似满足需求"的内容(尤其禁止虚构实时数据与预测结论);
- **禁止**在路由 D 阶段产出 DEPTH 指纹 —— 边界外需求无档位可言;
- C3 若用户坚持要直接结果,必须在产出中显式标注"未经执行验证,需以实际运行结果为准";
- 用户选择 A 后,替代需求**重新走第零步**(降级后的需求可能仍命中其他类别),再进入计分。

### 与误判纠正的关系

若用户反馈"你明明能做,为什么说做不了",按误判纠正机制处理:复核判定信号是否误命中,确认误判则撤回路由 D 并进入第一步。

## 误判纠正机制

- 用户反馈深度不匹配时:按 iterate 原子 D4 的深度调档机制处理,调整指纹对应位后仅重生成对应模块
- 判定依据存疑时(任务跨基调):取相邻两基调中较高者,并在产出头部标注"基调判定:B3(依据:4 分复杂度信号),如需调整请反馈"

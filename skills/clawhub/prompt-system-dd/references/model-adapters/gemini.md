# gemini 模型适配器

> 唯一真相源:本文件定义 Google Gemini 系列目标模型的提示词结构改写规则。
> 正交性:适配器只改写**表达形态**,不改变 DEPTH 指纹的 9 位档位语义。

## 适用判定信号

- 用户显式指定 Gemini / Google;
- 指纹后缀为 `@model=gemini`;
- 需要超长上下文(数十万 token)或大量 few-shot 示例注入。

## 结构偏好

显式指令区块 + 编号步骤 + 关键约束首尾重复。Gemini 在超长上下文中容易出现"中段指令衰减",需靠重复与编号对抗。

| 通用段 | Gemini 写法 |
|--------|------------|
| 角色 | `INSTRUCTION: You are ...` |
| 任务 | `TASK:` + 编号目标列表 |
| 上下文 | `CONTEXT:` |
| 示例 | `EXAMPLES:`(可大量注入,few-shot 收益高) |
| 输出格式 | `OUTPUT FORMAT:` |
| 思考指令 | `STEPS:`(1. 2. 3. 显式编号) |
| 约束 | `CONSTRAINTS:`(首部一次 + 尾部一次) |
| 自检 | `SELF-CHECK:` |
| 迭代 | `ITERATION:` |

## 必用写法

- 每个区块用**全大写关键字 + 冒号**起头;
- 步骤用显式编号(1. 2. 3.),不依赖段落顺序隐式表达;
- **关键约束在提示词开头与结尾各出现一次** —— 这是对抗长上下文衰减的核心手段;
- few-shot 示例可放量注入,是 Gemini 相对优势区;
- 多模态输入场景,把图像/文件引用放在 `CONTEXT:` 区块并逐个编号。

## 禁用写法

- 禁止把关键约束只写在提示词中段;
- 禁止用隐式指代("如上所述""前面的规则") —— 长上下文中指代易失效;
- 禁止在同一街区混合多个语义角色(角色与任务必须分块)。

## 注入模块

组装产出尾部追加(约束复述):

```
REMINDER — CONSTRAINTS (repeat):
1. <关键约束 1>
2. <关键约束 2>
3. <关键约束 3>
严格遵循上述约束,并在自检中逐条确认。
```

## 与档位的交互

- D1/D2:约束复述 1-2 条;
- D3:复述 3 条 + 自检清单逐条对应;
- D4:复述全部红线约束 + 合规边界,并要求在优化日志中记录复述条目。

## 质量检查清单

- [ ] 区块均以全大写关键字 + 冒号起头
- [ ] 步骤显式编号
- [ ] 关键约束在首部与尾部各出现一次
- [ ] 无"如上所述"类隐式指代
- [ ] DEPTH 头部指纹未被本适配器改写(仅尾部追加 REMINDER)

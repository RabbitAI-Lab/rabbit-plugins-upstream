> 唯一真相源:本文件定义 DeepSeek 系列目标模型的提示词结构改写规则。
> 正交性:适配器只改写**表达形态**,不改变 DEPTH 指纹的 9 位档位语义。

## 适用判定信号

- 用户显式指定 DeepSeek;
- 指纹后缀为 `@model=deepseek`;
- 中文语境 + 强推理需求(数学、代码、逻辑推演)。

## 结构偏好

中文自然语言指令 + 显式思维链触发词。DeepSeek 对 CoT 措辞高度敏感:是否显式触发"逐步思考",输出质量差异显著。

| 通用段 | DeepSeek 写法 |
|--------|---------------|
| 角色 | `你是...`(中文自然语言) |
| 任务 | `任务:` |
| 上下文 | `背景与已知信息:` |
| 示例 | `示例:` |
| 输出格式 | `输出要求:` |
| 思考指令 | `请逐步思考,先分析再结论。`(显式触发) |
| 约束 | `约束条件:`(正反分列) |
| 自检 | `完成后请自查:` |
| 迭代 | `如需调整:` |

## 必用写法

- **必须显式给出思维链触发语**,如"请逐步思考""先分析依据,再给出结论" —— 不写会显著掉质量;
- 中文任务全程用中文指令,术语可保留英文原文;
- R1 系列:给出目标与验收标准即可,不要过度规定推理过程细节(会与内部推理机制冲突);
- 数学 / 代码类任务:要求"展示推导过程"并指定"最终答案单独一行给出"。

## 禁用写法

- 禁止用过于刚性的结构化模板(多层嵌套 JSON / 复杂 Schema) —— 会挤压推理空间,导致 Reasoning 质量下降;
- 禁止中文任务里使用纯英文思维链指令;
- 禁止要求"不要输出思考过程"却又要求复杂推理(二者冲突时质量塌方)。

## 注入模块

组装产出尾部追加:

```
请逐步思考:先列出分析依据,再逐条对照约束,最后给出结论。
完成后自查一遍,确认无事实错误与逻辑跳跃。
```

## 与档位的交互

- D1/D2:触发语保留一句即可,不展开推理步骤;
- D3:触发语 + 三阶段(分析 / 构建 / 压力)显式列出;
- D4:触发语 + 对抗性质疑要求 + 优化日志,要求把被否决的方案理由一并写出。

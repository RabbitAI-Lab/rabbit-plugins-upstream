## 1. 角色

你是一位拥有 5 年经验的后端技术专家，擅长 API 契约设计与接口文档。

## 2. 任务

- 具体动作：设计订单查询接口的出入参结构说明。
- 核心范围：仅覆盖订单查询接口（单笔查询）的请求参数、响应字段与错误码；排除下单、退款等接口。
- 交付物：结构化说明文档一份，含 JSON Schema、字段说明表、错误码表，总字数 800-1500 字。

## 3. 背景与已知信息

- 背景：订单中心对外开放查询能力，供下游系统对接。
- 已知信息：接口走 HTTPS RESTful 风格；订单号与用户态为必填鉴权要素。

请按照以下步骤思考：1.理解需求 2.分析关键点 3.列提纲 4.逐步执行 5.完成后核对约束。

## 4. 示例

以下为一个完整示例骨架，覆盖目标结构与颗粒度：

```json
{
  "order_id": "string, 必填, 订单号",
  "status": "PAID | SHIPPED | DONE"
}
```

## 5. 输出要求

- 输出形式：Markdown + JSON 代码围栏。
- 结构框架：接口概述→请求参数→响应字段→错误码→调用示例。
- 颗粒度标准：字段名用 snake_case；必填/可选逐字段标注；错误码不少于 5 个且逐一给出触发条件与处理建议。

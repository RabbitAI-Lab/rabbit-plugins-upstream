# 03 幻觉检测引擎

> 适用：对回答做规则化幻觉检测——快速基线的核心引擎
> 核对基准日：2026-08

## 1. 四类规则检测器

| 检测器 | 原理 | 检出目标 |
|---|---|---|
| 数字一致性 | 对比回答与来源中的数字/百分比/金额 | 编造数据 |
| 引用校验 | 检查引号内容/书名号内容是否在来源中出现 | 编造引用 |
| 否定矛盾 | 检测"不/无/未/无法"等否定词与来源表述冲突 | 事实反转 |
| 关键论断互证 | 抽取关键词（实体/日期/术语）检查来源覆盖 | 张冠李戴 |

## 2. 输出格式

```json
{"verdict": "suspicious", "rules_hit": [{"rule": "数字一致性", "detail": "回答说100万台，来源说50万台", "severity": "high"}]}
```

- verdict：clean（无命中）/ suspicious（命中待查）
- 命中即标 suspicious，需人工复核（规则是召回优先）

## 3. 使用方式

```bash
python tools/eval_toolkit.py hallucination --answer "该产品2025年销量100万台" --source "2026年报告：销量50万台"
# → 命中数字一致性：回答 100 万 vs 来源 50 万
```

## 4. 局限与校准
- **误报**：数字表述方式差异（"一半"vs"50%"）会误报 → 人工复核
- **漏报**：编造内容无来源对比时检不出 → 需 reference 或人工
- 校准建议：抽样 20-50 条人工复核，统计检出率与误报率

## 5. 进阶路径
- 高要求场景：换 NLI 一致性模型 / LLM-as-Judge / RAGAS（07 模块）
- 与红队衔接：本引擎测"事实性幻觉"，红队测"安全幻觉"（注入等）

## 6. 常见误区
1. "检出 suspicious 就是幻觉"——是"可疑待查"，要人工确认
2. "没检出就是没幻觉"——规则覆盖有限，无来源对比时检不出

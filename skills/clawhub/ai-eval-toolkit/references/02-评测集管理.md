# 02 评测集管理

> 适用：评测集的 JSONL 组织、质量检查与规模统计
> 核对基准日：2026-08

## 1. JSONL 格式（每行一个用例）

```json
{"id": "case-001", "scenario": "客服问答", "question": "产品保修期多久？",
 "answer": "保修期 1 年。", "context": "产品文档：保修期 1 年", "reference": "保修期 1 年",
 "gold": 1, "type": "normal"}
```

### 字段规范
| 字段 | 必填 | 说明 |
|---|---|---|
| id | ✓ | 用例唯一标识 |
| scenario | ✓ | 场景标签（分场景统计） |
| question | ✓ | 输入问题 |
| answer | 二选一 | 待测回答（评测对象） |
| context | 可选 | RAG 检索上下文 |
| reference/gold | 可选 | 标准答案/黄金答案 |
| type | 可选 | normal/boundary/adversarial |

## 2. 工具命令

```bash
# 初始化（生成模板）
python tools/eval_toolkit.py dataset --action init --out evalset.jsonl

# 质量检查（必填字段/重复 id/空值）
python tools/eval_toolkit.py dataset --action check --file evalset.jsonl

# 规模统计（总数/分场景/分类型）
python tools/eval_toolkit.py dataset --action stat --file evalset.jsonl
```

## 3. 质量检查规则
- 必填字段缺失 → 警告
- id 重复 → 错误
- question 为空 → 错误
- scenario 未填 → 警告（无法分场景统计）
- answer 与 context 都空 → 警告（无可评测对象）

## 4. 建集建议
- 起步 50-100 条（核心场景）
- 覆盖：normal ≥70%，boundary 20%，adversarial 10%
- 防泄漏：评测集不进训练/微调数据

## 5. 常见误区
1. "JSONL 随便写"——字段规范决定统计与检测质量
2. "一次建好不再更新"——定期补充线上真实场景

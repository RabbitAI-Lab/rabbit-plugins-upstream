# 01 工具链全景

> 适用：理解 LLM 评测工具链的整体架构与定位
> 核对基准日：2026-08

## 1. 五个引擎

| 引擎 | 命令 | 功能 |
|---|---|---|
| 评测集管理 | dataset | 建集（JSONL 模板）、质量检查、规模统计 |
| 幻觉检测 | hallucination | 四类规则检测器（数字/引用/否定/互证） |
| RAG 指标 | ragscore | RAGAS 四指标本地简化实现 |
| 回归对比 | compare | 基线 vs 新结果差异判定 |
| 报告门禁 | report | 报告生成 + 上线门禁判定 |

## 2. 数据流

```
评测集（JSONL）→ 批量跑回答 → hallucination 检测 → ragscore 指标
    → compare 对比基线 → report 报告 + 门禁 → 上线决策
```

## 3. 定位：方法论 vs 实现

| 维度 | LLM 质量评测 skill | 本工具链 |
|---|---|---|
| 角色 | 方法论（怎么做） | 实现（能跑的代码） |
| 产出 | 指标体系/评测集设计/流程 | 评测集管理/检测引擎/指标计算 |
| 依赖 | 无（规则库） | 无（纯标准库可运行） |
| 使用 | 设计评测体系 | 落地执行评测 |

## 4. 设计原则
1. **零依赖**：纯标准库，任何 Python 3.8+ 环境可跑
2. **本地闭环**：不联网，数据不出本机
3. **可解释**：每条检测给出命中的规则与依据（不是黑箱打分）
4. **可升级**：规则引擎是"快速基线"，专业框架升级路径见 07 模块

## 5. 常见误区
1. "规则引擎能替代 RAGAS"——不能，规则是基线不是终点
2. "工具链输出就是绝对真相"——规则误报需人工复核
3. "工具链是万能评测"——它覆盖核心质量维度，安全维度衔接红队 skill

# 05 回归对比

> 适用：基线 vs 新结果的差异判定——防质量回退
> 核对基准日：2026-08

## 1. 基线管理

- 每个正式版本（模型+Prompt）固化基线结果 JSON
- 对比口径：同评测集、同指标、同检测器版本

## 2. 结果 JSON 格式

```json
{"version": "1.2.0", "cases": [{"id": "case-001", "scenario": "客服问答",
 "metrics": {"faith": 1.0, "relevance": 0.8}, "hallucination": "clean"}], "agg": {...}}
```

## 3. 对比判定

```bash
python tools/eval_toolkit.py compare --base baseline.json --new result.json
# → 分场景得分对比 + 变化方向 + 是否退化
```

### 判定规则
| 信号 | 判定 |
|---|---|
| 核心指标 ≥ 基线 | 通过 |
| 下降 < 阈值（如 5%） | 观察 |
| 下降 ≥ 阈值 | 退化（拦截） |
| 幻觉检出数增加 | 退化（拦截） |

## 4. 防假回归
- **同评测集**：评测集版本变了会"假回归"，对比前确认
- **同检测器**：检测器升级了口径变化，先对齐
- **同抽样**：抽样对比要保证随机性一致

## 5. 常见误区
1. "分数没降就安全"——分场景拆解，总分掩盖局部退化
2. "基线随便存"——基线是门禁的锚，要版本化留存

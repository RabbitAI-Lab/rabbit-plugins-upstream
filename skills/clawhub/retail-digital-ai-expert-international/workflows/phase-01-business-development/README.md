# Phase 01 — Business Development & Contracting

> **Phase Objective**: A complete methodology from first client contact through contract signing.
> **Duration**: 2-6 weeks (depending on client size and complexity)
> **Key Deliverables**: Project Proposal + Statement of Work (SOW)

## Phase Overview

```
Initial Client Communication → Requirements Clarification & Problem Diagnosis → Project Proposal → Contract & SOW Negotiation
       (1-2 meetings)                  (1-2 weeks)                      (1 week)              (1-2 weeks)
```

## Core Principles

1. **Listen > Talk**: In the first meeting, spend 70% of the time listening to the client, 30% asking questions and summarizing.
2. **Ask the Right Questions**: Don't ask "What's your budget?" (no one will tell you). Ask "How much do you think this system is worth?"
3. **Speak Their Language**: For small retail owners, say "cash register system" rather than "POS solution." Use the language of business outcomes, not technical jargon.
4. **Deliver Value Early**: Make the client feel in the first interaction that "this person really understands retail," not just technology.

## Quality Checklist

- [ ] Can the client clearly articulate what problem they want to solve? (Not "I want digitalization" but "I want inventory accuracy above 95%")
- [ ] Do I understand the client's real budget range? (At minimum, know the upper and lower bounds)
- [ ] Who is the decision maker? What is the decision-making process?
- [ ] Does the Proposal describe the problem using the client's own words? (Not your terminology)
- [ ] Does every recommendation include an ROI estimate?

## Common Pitfalls

1. **Rushing to offer a solution**: Proposing systems before fully understanding the problem → client feels you are "selling"
2. **Over-promising**: Committing to things you cannot deliver to win the project → guaranteed failure
3. **Ignoring hidden decision-makers**: Only talking to the IT manager without engaging the owner/CEO → project gets cancelled
4. **Overly technical proposals**: Using "API/Microservices/MACH architecture" with a retail owner → owner doesn't understand

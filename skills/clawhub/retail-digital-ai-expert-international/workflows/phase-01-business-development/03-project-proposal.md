# 03 — Project Proposal

> **Trigger**: Requirements clarification completed, client requests a formal proposal
> **Prerequisites**: Problem diagnosis report + client communication notes
> **Deliverables**: Formal Proposal (15-25 pages) + Presentation deck (10-15 slides)

---

## 1. Core Proposal Principles

1. **Must be clear on one page**: The executive summary must convey all key information in a single page.
2. **Use the client's language**: If the client says "cash register," use "cash register" not "POS terminal."
3. **Tie every recommendation to ROI**: Don't just say "we recommend an ERP." Say "implementing ERP will reduce inventory turnover from 45 days to 32 days, releasing $[X]K in working capital."
4. **Conclusion first**: Pyramid principle — give the conclusion first, then the evidence, then the details.

---

## 2. Standard Proposal Structure (9 Chapters)

### Chapter 1: Executive Summary (1 page)

> The most important page — the CEO only reads this one.

```
We understand your challenges:
  1. _____ (in the client's own words)
  2. _____

Our recommendation:
  One-sentence summary → Through _____, within _____ months, achieve _____

Key metrics:
  - Investment: $[X]K (3 years)
  - Return: $[X]K (3 years), ROI _____%
  - Timeline: _____ months payback, _____ months to completion

Why us:
  One sentence — "We focus exclusively on retail digital transformation, having helped [X] retailers..."
```

### Chapter 2: We Understand Your Challenges (2-3 pages)

- Description of the client's current state (demonstrate you've done your homework)
- Core pain points distilled (TOP 3-5)
- Each pain point quantified: "The cost of not solving"
- Industry benchmarking: "Industry leaders are already doing _____"

### Chapter 3: Our Solution (4-6 pages)

- Target architecture diagram (a picture is worth a thousand words)
- Core system recommendations (for each: which vendor + why + how much)
- Phased implementation path (Phase 1 → 2 → 3)
- Quick wins (delivering results in 0-3 months)

### Chapter 4: Implementation Roadmap (2-3 pages)

- Timeline (Gantt chart / milestone table)
- Key milestones and deliverables
- Resource requirements (team / hardware / budget)

### Chapter 5: Investment & Return (2-3 pages)

- TCO breakdown (one-time + annual fees × 3 years)
- Benefit quantification (5 benefit categories × 3 years)
- ROI + payback period + sensitivity analysis
- Cost of doing nothing

### Chapter 6: Risks & Mitigation (1-2 pages)

- TOP 5 risks + probability + impact + mitigation measures

### Chapter 7: Why Choose Us (1-2 pages)

- Retail specialization (not a generalist firm)
- Case studies (at least 3 of similar scale / format)
- Team (core member backgrounds)
- Proprietary methodology (R-DMM and other unique tools)

### Chapter 8: Project Team (1 page)

| Role | Name | Background | Commitment |
|------|------|------|:---:|
| Project Lead | | | |
| Retail Business Expert | | | |
| Technical Architect | | | |

### Chapter 9: Next Steps (1 page)

1. Proposal review and discussion (date)
2. Detailed diagnostic kickoff (date)
3. Contract and SOW signing (date)

## 3. Proposal Writing Techniques

### SCQA Narrative Framework

| Element | Retail Scenario |
|------|------|
| **S**ituation | "Global retail SaaS penetration has exceeded 65%, and digitalization is now table stakes" |
| **C**omplication | "However, your current systems are siloed per store, inventory is inaccurate, and members cannot be identified" |
| **Q**uestion | "How can you change the current situation within 6 months and catch up to industry-leading levels?" |
| **A**nswer | "We recommend a three-phase approach: unified POS → omnichannel → AI-powered operations" |

### Customization for Different Audiences

| Audience | Focus | Proposal Emphasis |
|------|------|------|
| CEO / Owner | ROI, competition, strategy | Strengthen Chapters 1 / 5 / 6 |
| CTO / IT Lead | Technical architecture, feasibility, integration | Strengthen Chapters 3 / 4 |
| CFO | TCO, payback period, risk | Strengthen Chapters 5 / 6 |
| Franchisees | "What's in it for me?" | Add a franchise-specific chapter |

---

## 4. Proposal Presentation Guide

### 10-15 Slide Deck Structure

```
Slide 1:  Title slide
Slide 2:  Executive summary (1 page of core information)
Slide 3-4: We understand your challenges
Slide 5-7: Solution
Slide 8:   Roadmap
Slide 9:   Investment return
Slide 10:  Risks
Slide 11:  Why us
Slide 12:  Next steps
```

### Presentation Do NOT Say

| Do NOT Say | Say Instead |
|------|------|
| "Our solution is based on MACH architecture..." | "This system can flexibly expand like building blocks" |
| "ROI is calculated using a DCF model..." | "You invest $[X]K, payback in [X] months, and earn an additional $[X]K over 3 years" |
| "We use agile development methodology..." | "You'll see progress every 2 weeks" |

---

## 5. Quality Self-Check Checklist

- [ ] Can the executive summary be delivered in under 2 minutes?
- [ ] Does every recommendation include the "why" + "what" + "how" + "how much"?
- [ ] Is the ROI calculation backed by data (not just rough guesses)?
- [ ] How might competitors attack our proposal? Are we prepared with responses?
- [ ] Does the Proposal use the client's brand colors / logo? (Details show you care)
- [ ] Is the formatting clean, free of typos, with clear charts and diagrams?

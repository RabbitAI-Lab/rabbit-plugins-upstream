# 人设卡生成 SOP（代表作品反推 · 知识库合成）

## 这份文件是什么

输出一份符合 `persona-schema.md` 的 styleGuide（6 个章节）。支持两条输入路径：

| 路径               | 输入                                   | 适用场景                                                              |
| ------------------ | -------------------------------------- | --------------------------------------------------------------------- |
| **① 代表作品反推** | 3–5 篇代表作品                         | 有现成内容可对标、要延续既有腔调（`persona-onboarding.md` 分支 ①）    |
| **② 知识库合成**   | 企业知识库（+ 可选的用户企业背景描述） | 无代表作品、但有企业资料库；用户说「用知识库建人设 / 结合企业资料」等 |

两条路径的**输出契约、证据要求、A1 确认、落盘命令完全一致**；差别只在「信息从哪来、哪些章节置信度高」。

> 用户口头描述、已有卡导入见 `persona-onboarding.md` 分支 ② / ③，不在本文件展开。

## 输出契约

最终产物是一段 **styleGuide markdown**，必须严格符合 `persona-schema.md` 的 6 章节结构：

`一句话定位` / `目标受众` / `内容 DNA` / `推荐用词（≥6 个）` / `禁用表达 / 禁忌（≥3 条）` / `<平台> 平台适配建议`。

落盘（保存到 CSO 平台）前必须走 A1 强制逐条确认，再用 `siluzan-cso persona create` 保存。

> ⚠️ 平台 styleGuide 没有结构化字段。反推产物就是这 6 个章节，不要输出 `style_tags: ...`、`opening_preferences: ...` 之类的"字段行"。

## 输入要求

### 路径 ① 代表作品反推

最佳：3–5 篇代表作品。
最低：1 篇（不推荐，多数章节只能弱推断、需用户补）。

**代表作品可以两种形态进来：**

| 输入形态                                   | 处理方式                                                                                                               |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| 用户**直接贴出作品正文 / 上传作品文件**    | 直接进入「第一步：先读作品」                                                                                           |
| 用户只给**账号主页链接**或**单条作品链接** | ⚠️ **必须先用 `siluzan-cso material search` 通过链接取回作品正文，再反推**——不要只看链接就凭空反推（见下方「第零步」） |

> ❌ 常见错误：用户发来一个抖音主页 / 某条视频链接，AI 没有取回作品内容就直接开始"反推人设"。链接本身不含作品正文，这样等于凭空编造。**只要输入里出现主页链接 / 作品链接，先走第零步取回代表作。**

### 路径 ② 知识库合成

**必填：**

- **知识库可检索**：能确定 `--folder-id`（见下方「锁定知识库」）
- **主运营平台**（决定「`<平台> 平台适配建议`」章节怎么写；用户未说则在 A1 前主动问）

**可选：企业背景描述**

用户口述或对话里已有的企业/产品/行业摘要（例如「XX 公司，做工业烘焙设备，客户是食品厂」）。**没有也不阻塞流程**——见下方「没有企业背景描述时怎么办」。

背景描述可从以下来源获取（按优先级）：

1. 用户当轮或前文已说明的企业名 / 产品 / 行业
2. 宿主注入的 `<knowledge_base_selection>` 库名（「…」里的展示名，可作检索词种子）
3. 第一轮 broad `rag query` 后，从高分片段反推企业名与行业（再收窄后续检索）

**锁定知识库（`--folder-id`）：**

- 上下文有 `<knowledge_base_selection>` → 直接用其中的 `comid`，**跳过** `rag list`（见 `references/core/knowledge-base-resolution.md`）
- 无已选库 → 先 `siluzan-cso rag list --rag-only --json-out ./snap-cso`，按企业名称语义匹配文件夹 ID；多个候选 → 问用户选哪一个，**禁止猜**

**没有企业背景描述时怎么办**

| 情况                                             | 动作                                                                                                                                   |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| 已有 `<knowledge_base_selection>` 或用户指定了库 | 先用库名 + 通用意图词做 **1 轮 broad 检索**（如 `-q "公司简介 品牌 产品 主营业务"`），从片段里提取企业名 / 行业，再按正常 6 组意图收窄 |
| 库 ID 已知，但库名与用户意图都对不上             | 问用户：「这个知识库对应哪家企业 / 什么产品？主要做哪个平台的内容？」——**最多问 1–2 句**，不要空转                                     |
| 既无背景、又无已选库、用户只说「用知识库建人设」 | 先 `rag list` 列出可选库 → 请用户指定库 → 再 broad 检索；**不要**在未锁定库 ID 时编造企业信息                                          |
| broad 检索仍无法推断行业                         | 事实章节（定位 / 受众 / 用词）只写**有片段证据**的部分；其余标「待确认」，A1 让用户补                                                  |

**可选补充（有则一并纳入检索词设计）：**

- 账号名称或用途
- 腔调直觉（偏专业 / 偏亲和 / 偏转化…）
- 重点关注点（某产品线、某区域市场、某类客户）

# 路径 ①：代表作品反推

## 第零步：只给了链接？先取回代表作

**仅当**用户提供的是账号主页链接 / 单条作品链接（而不是作品正文本身）时执行本步；已直接贴出作品正文的，跳过本步直接到第一步。

用 `siluzan-cso material search` 通过链接取回作品，再进入第一步。命令要点：

```bash
# 账号主页链接 → 拉该账号的作品列表；--sort likecount 让代表作（高赞）优先浮现
siluzan-cso material search --type account --url "<账号主页链接>" --sort likecount --page-size 10 --json-out ./snap-cso

# 单条作品链接 → 解析这一条作品
siluzan-cso material search --type video --url "<作品链接>" --json-out ./snap-cso
```

- **必须落盘再读**：作品的 `desc`（正文）/ `subtitles`（字幕口播）通常很长，用 `--json-out` 落盘后从 JSON 读取每条的 `title` / `desc` / `subtitles`，**禁止**对 stdout 翻页循环。
- **挑代表作**：账号搜索返回多条时，按点赞 / 评论等互动数据挑 **3–5 篇最具代表性**的作口播/正文反推（多了难找共性，见 `persona-onboarding.md` 的作品数量兜底）。
- 取不到作品（链接不可访问 / 平台不支持 / 返回为空）→ 明确告诉用户，请其改为直接贴作品正文，**不要**凭链接猜测硬写。
- 字段口径：`title` 标题、`desc` 正文、`subtitles` 字幕/口播、`likeCount`/`commentCount`/... 互动数、`time` 发布时间、`userName` 作者、`pageUrl` 来源链接。

拿到作品正文后，进入第一步正常反推。

## 第一步：先读作品，不急着下结论

逐篇扫描，找以下信息（**只采集，不下判断**）：

- 主题是什么、面向谁
- 语气怎么样
- 开头怎么起、中段怎么推、结尾怎么收
- 有没有固定套路
- 有没有强烈的情绪或判断（捍卫什么 / 反对什么）
- 有没有反复出现的句式 / 关键词 / 比喻 / 口头禅

读完所有作品后，**先找共性**：哪些反复出现？哪些只出现一次？哪些是 1–2 篇里偶发的？

> 标置信度（自己心里有数即可，A1 会用到）：多篇反复出现 = 高；1–2 篇 = 中；完全没线索 = 缺，A1 让用户补。

## 第二步：把共性归并到 6 个章节

### 1) `## 一句话定位`

回答：这组作品整体在解决什么问题？偏认知 / 方法 / 情绪 / 转化？给受众什么价值？
写成一句话定位 / 价值主张。这一句同时承载了主 SOP 里"核心任务"的判断，所以要写实、写具体。

### 2) `## 目标受众`

回答：明显在写给谁？职业 / 阶段（新手 / 老手 / 决策者 / 围观者）/ 他们关心什么问题？
作品里明确点名或预设受众 → 写实；只能从话题推测 → 写推测版并在 A1 标注待确认。

### 3) `## 内容 DNA`（4 条要点，最关键）

这是反推**最有价值**的部分，逐条抓：

- **开场惯用方式**：作品反复用的起手式（反差 / 设问 / 结论先行 / 故事 / 危机信号…），用人话描述，不要写枚举码。
- **标志性表达 / 口头禅**：反复出现的句式、口头禅、标志性比喻——每类尽量抓 2 条以上。同时这里隐含了**语气**（强势 / 温和 / 犀利 / 稳重 / 紧迫 / 真诚）。
- **节奏**：`快`（短句、高密度、句句推进）/ `中`（长短交替）/ `慢`（长句、铺陈舒缓）。
- **价值观锚点**：这个号始终在捍卫 / 反对的立场。这一条后续会成为主 SOP 第 10 步"质检尺子"的来源，务必写出来。

### 4) `## 推荐用词（≥6 个）`

词频统计后挑高频/标志性词条，凑够 ≥6 个具体词（不要给"专业词汇"这种抽象类目）。

### 5) `## 禁用表达 / 禁忌（≥3 条）`

- 作品里明显回避的词 / 话题 → 写下来
- 凑不够 3 条时，结合定位与受众补常识性红线，并在 A1 请用户确认
- 既写"禁用表达"（绝不能用的词/句式），也写"话题禁忌"（绝不碰的话题）

### 6) `## <平台> 平台适配建议`

按作品形态与用户告知的主平台判断（公众号长文 → 「公众号」；短视频口播 → 「抖音 / 视频号」…），把章节标题里的 `<平台>` 换成真实平台名，正文写该平台的内容形态、长度、互动、SEO/封面要点。平台不确定 → A1 问用户。

## 第三步：写"作品证据"

**不允许只写主观判断**。每个章节的关键结论都要带证据：

```
内容 DNA · 价值观锚点：始终反对"低价内卷"
  证据：作品 A 第二段、作品 C 整体倾向（多篇反复）→ 高置信
```

证据写清楚，A1 确认时用户能快速判断对不对。

## 第四步：组装成 styleGuide，进入 A1 确认

按 `persona-schema.md` 的完整模板把 6 个章节拼成一段 markdown。置信度诚实标注，**不要把"中/缺"偷偷写成"已确认"**。

进入 `persona-onboarding.md` 的"落盘前确认流程（A1）"，确认完成后用 `siluzan-cso persona create --style-guide-file` 保存到平台。

## 第五步：强烈建议写实的 3 项

这三项缺了，主 SOP 第 7 步 / 第 9 步会被迫用通用默认值：

1. **开场惯用方式**（「内容 DNA」）
2. **节奏**（「内容 DNA」）
3. **价值观锚点**（「内容 DNA」，决定质检尺子）

A1 确认环节碰到这三项空泛时，主动追问用户。

## 标准工作流（路径 ①）

**（只有链接 → `material search` 取回代表作）→ 拿作品 → 找共性 → 归并到 6 个章节（带证据 + 置信度） → 组装 styleGuide → A1 强制逐条确认 → 命名 → `persona create` 保存到 CSO 平台**

## 最实用的判断原则（路径 ①）

只靠作品反推，最怕两件事：

1. **过度脑补**：看到一篇就写死。**对策**：1–2 篇出现的标"中置信"，A1 让用户拍板。
2. **只看风格，不看任务与立场**：只填「内容 DNA」的表层句式，「一句话定位」「价值观锚点」含糊。**对策**：每个章节都要有作品证据，没证据宁可留空让用户填。

# 路径 ②：知识库合成

企业知识库擅长提供**事实**（产品、客户、卖点、合规），通常**不直接包含**「开场惯用方式 / 口头禅 / 节奏」等腔调信息。本路径的策略是：**事实章节尽量贴库，腔调章节诚实标注待确认，A1 让用户拍板**——禁止把产品说明书语气硬写成「内容 DNA」。

## 第一步：确定知识库并设计检索

**0. 锁定 `--folder-id`**

按 `references/core/knowledge-base-resolution.md` 执行；有 `<knowledge_base_selection>` 时直接用 `comid`。

**1. 设计 4–6 组检索意图**

结合**已有企业背景描述**（若有）与下面表格，为每组挑 **2–5 个短关键词**。背景描述里出现的企业名 / 产品词应优先写进 `-q`；**若没有背景描述**，第一组先用 broad 词（见输入要求里的 broad 检索），再从结果反推后续关键词。

| 检索意图 | 建议 `-q` 关键词方向                | 主要喂给哪几个章节     |
| -------- | ----------------------------------- | ---------------------- |
| 品牌定位 | 品牌定位 价值主张 企业使命 核心理念 | 一句话定位、价值观锚点 |
| 受众画像 | 目标客户 用户画像 应用场景 买家角色 | 目标受众               |
| 产品事实 | 产品卖点 核心优势 差异化 技术参数   | 一句话定位、推荐用词   |
| 表达调性 | 品牌调性 话术 文案风格 沟通方式     | 内容 DNA（若有命中）   |
| 合规红线 | 禁用 合规 注意事项 宣传限制         | 禁用表达 / 禁忌        |
| 平台线索 | 抖音 短视频 公众号 案例 内容形式    | `<平台> 平台适配建议`  |

> 知识库已按三库标签打标时，可按需加 `--tags` 精确分库；**未打标则不要传 `--tags`**。

**2. 执行检索（落盘后再读 JSON，禁止对 stdout 翻页循环）**

```bash
# 无企业背景描述时，可先跑 1 轮 broad（再据结果收窄下面各组 -q）
# siluzan-cso rag query -q "公司简介 品牌 产品 主营业务" --folder-id <id> --partition wiki --top-k 12 --json-out ./snap-cso

# 首轮：wiki 分区，top-k 建议 12（-q 内空格分隔时 CLI 会分检合并，详见 references/rag.md）
siluzan-cso rag query -q "品牌定位 价值主张 核心理念" --folder-id <id> --partition wiki --top-k 12 --json-out ./snap-cso
siluzan-cso rag query -q "目标客户 用户画像 应用场景" --folder-id <id> --partition wiki --top-k 12 --json-out ./snap-cso
siluzan-cso rag query -q "产品卖点 核心优势 差异化" --folder-id <id> --partition wiki --top-k 12 --json-out ./snap-cso
siluzan-cso rag query -q "品牌调性 话术 表达风格" --folder-id <id> --partition wiki --top-k 12 --json-out ./snap-cso
siluzan-cso rag query -q "禁用 合规 宣传限制 注意事项" --folder-id <id> --partition wiki --top-k 12 --json-out ./snap-cso

# 某组结果明显不足时，同参数改 --partition default 补一轮；按片段 id 去重合并
```

读取落盘 JSON 时：`score` **越大越相关**；多轮 / 多命令结果在对话侧按片段 **id 去重**，保留最高 score。

## 第二步：读检索结果，只采集不下结论

逐条扫描合并后的片段，按类型归类（**只采集，不下判断**）：

- **硬事实**：产品名、参数、认证、客户类型、应用场景、价格口径、地域…
- **定位语句**：官网 Slogan、使命愿景、「我们是谁」类表述
- **受众线索**：「适用于…」「面向…」「解决…痛点」
- **调性线索**：是否出现「专业 / 亲和 / 严谨 / 创新」等明确风格描述（少见）
- **红线线索**：「不得宣称…」「禁止…」「需注意…」

读完所有片段后，**先找重复**：多篇 / 多段反复出现的 → 高置信；只出现一次 → 中置信；完全没线索 → 缺，A1 让用户补。

> ⚠️ **禁止**把 RAG 原文直接粘贴进 styleGuide；必须重新组织为第二人称「你」对写作者讲话的指南口吻（与 `persona-schema.md` 一致）。

## 第三步：把片段归并到 6 个章节

归并规则与路径 ① 相同，但**置信度来源不同**：

### 1) `## 一句话定位`

- **高置信**：检索到明确的使命 / 价值主张 / 「我们为 X 提供 Y」
- **中置信**：只能从产品描述间接归纳
- **写法**：一句话说清「这个号代表谁、解决什么问题、给受众什么价值」；不要堆产品参数

### 2) `## 目标受众`

- **高置信**：库里有明确的 ICP、买家角色、应用场景
- **中置信**：从「适用于…行业 / …客户」推断
- 写推测版时在 A1 标注待确认

### 3) `## 内容 DNA`（通常是最弱的一环）

| 要点                | 知识库通常能提供                    | 缺了怎么办                                                            |
| ------------------- | ----------------------------------- | --------------------------------------------------------------------- |
| 开场惯用方式        | 很少                                | 标「待确认」；结合 B2B / 工业 / 消费品等行业常识写**推测版**，A1 追问 |
| 标志性表达 / 口头禅 | 偶尔有品牌话术                      | 从「推荐用词」里挑 1–2 条作种子；其余 A1 补                           |
| 节奏                | 几乎无                              | 按平台 + 行业默认（如抖音偏快、公众号偏中慢），标「待确认」           |
| 价值观锚点          | 有时能从「品牌理念 / 反对什么」提炼 | 从定位 + 合规片段推断；无则 A1 必问                                   |

> 知识库路径下，**开场 / 节奏 / 价值观锚点**三项空泛时，A1 **必须主动追问**——不要假装已从库里读到了腔调。

### 4) `## 推荐用词（≥6 个）`

- 优先：产品名、技术术语、认证名、应用场景词、品牌高频词（从检索片段统计）
- 凑不够 6 个：结合行业通用词 + 已有企业背景描述（若有），A1 确认

### 5) `## 禁用表达 / 禁忌（≥3 条）`

- **高价值来源**：合规 / 宣传限制 / 「不得 / 禁止 / 避免」类片段
- 库里有 → 写实；库里没有 → 结合行业常识补红线，**全部标待确认**

### 6) `## <平台> 平台适配建议`

- 用户已告知主运营平台 → 标题换成真实平台名
- 正文：该平台内容形态 + 长度 + 互动 + 封面 / SEO；可结合库里是否有「短视频 / 图文 / 案例」类素材微调
- 平台不确定 → A1 问用户

## 第四步：写「知识库证据」

格式与路径 ① 的「作品证据」平行，引用检索片段而非作品：

```
一句话定位：为工业客户提供智能仓储整体解决方案
  证据：RAG 片段 id=abc… score=0.82「公司致力于…」（wiki 分区，高置信）

内容 DNA · 节奏：偏慢，长句铺陈
  证据：库内无直接线索 → 缺，按公众号 B2B 默认推测（低置信，A1 待确认）
```

每个章节的关键结论都要带证据；**无库内证据的章节不得标「已确认」**。

## 第五步：组装 styleGuide → A1 → 落盘

与路径 ① 完全相同：

1. 按 `persona-schema.md` 模板拼 6 章节
2. 进入 `persona-onboarding.md` 的 A1 强制逐条确认（腔调类章节预期更多「待确认」）
3. `siluzan-cso persona create --name "<人设名称>" --style-guide-file <path>`

## 标准工作流（路径 ②）

**确定 folder-id → 按章节意图多轮 rag query（wiki 优先，不足补 default）→ 合并去重 → 归类采集 → 归并 6 章节（事实高置信 / 腔调待确认）→ 写知识库证据 → 组装 styleGuide → A1 → `persona create`**

## 最实用的判断原则（路径 ②）

1. **把说明书当人设**：产品参数堆砌、没有「对谁说话」。**对策**：「一句话定位 / 目标受众」必须回答人，不是罗列 SKU。
2. **编造腔调**：库里没有风格证据却写死「犀利 / 幽默」。**对策**：内容 DNA 无证据 → 推测版 + A1，禁止高置信。
3. **编造事实**：检索无结果仍写具体认证、客户、数据。**对策**：无片段支撑的事实不许进 styleGuide；告知用户库中暂无，请补充或上传资料。
4. **跳过 RAG**：只听用户口述不查库。**对策**：只要 CLI 可用且库 ID 已确定，**必须先 rag query** 再写卡；用户口述仅作检索词补充，不能代替库内事实。

## 通用原则

记住核心公式：**人设 = 定位 + 受众 + 内容 DNA（开场/句式/节奏/立场）+ 推荐用词 + 禁忌 + 平台适配**，不是只有风格，也不是只有产品清单。

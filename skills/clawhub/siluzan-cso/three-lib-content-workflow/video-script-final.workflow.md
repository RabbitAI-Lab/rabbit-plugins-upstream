# 视频脚本最终三库阶段

> 本文件只允许在宿主已完成原有方案确认、正式进入视频成稿时读取。它不拥有选题、方案卡、`angles`、确认门禁或 RAG 顺序；不得调用 `present_flow_ui`，不得改变宿主确认前流程。
>
> 若发现宿主尚未完成正式方案卡确认，应立即停止并交回宿主恢复方案卡；不得以普通正文请求确认，不得加载视频专项三库或写稿。

## 0. 与主流程的关系

- 本文件是确认后的视频专项附加规则，不是唯一成稿 SOP。`content-writer.workflow.md`、主 SOP 的成稿输出规范、当前人设和平台适配继续生效；其中联系方式限制沿用主 SOP「成稿输出规范」第 3 条，不在本文件复制第二份规则。
- 六大类型、视频专项三库、`plan_contract`、`verified_facts`、事实锚点和柔性改写属于专项新增或收紧，不构成对主 SOP、当前人设或平台规则的整体覆盖。平台允许的 CTA、禁用表达、交付形式和禁止编造规则继续按各自原规则执行。
- 当前平台规则应已由 `content-writer.workflow.md` 第 1.5 步加载。进入本阶段前检查其记录的规范平台和规则文件路径；路径已加载时直接复用，不重复读取。
- 若宿主未记录已加载路径，完整读取 `references/platforms/platform-rules.md`，按主流程已经确定的平台只补读一份规则。五个平台命中后文件缺失、为空或不可读时停止写稿；禁止切换平台或同时读取多份规则，也不得以三库替代平台规则。
- 仅有以下四项显式例外：①宿主方案已确认时不再执行主 SOP 的提纲确认；②口播正文内不附「来源：RAG」等来源标签或 SOP 自检清单，但事实仍须在内部关联到 `verified_facts`；平台「输出格式」里的【字幕重点】【画面建议】【发布文案】【话题标签】【风险与核验项】不是内部验收说明，必须保留；③短视频长度按“用户明确时长 > 当前平台适配 > 短视频默认”处理；④已锁定 `script_kind` 时，成稿骨架与三库组合以本文件第 1.0 节和视频专项组合表为准，主 SOP 题材表（生活物件升维 / 角色闯关科普）不得覆盖锁定类型的目标骨架。除这四项外，本文件不得覆盖主流程。人设 styleGuide、成稿输出规范和平台规则仍生效。
- 上述短视频默认不限制 YouTube 长视频；用户要求或当前平台适配为 8～15 分钟等长视频形态时，按用户要求和平台规则执行。

## 1. 最终阶段分类

成稿前形成仅内部使用的记录：`objective`、`primary_content_type`、可选的 `secondary_content_type`、`plan_contract`、`verified_facts`、`unsupported_plan_claims`、`selected_traffic_factors`、`selected_product_assets`、`selected_cooking_method`、`missing_facts`。不得把字段名、事实清单、来源摘录或 TF/PA/CM 编号写进成稿或交付摘要。目标骨架步骤名同样只作内部顺序，口播成稿禁止写出「（客户痛点）」「（处理异议）」「（解决方案）」「（咨询 CTA）」或把它们做成标题行。

### 1.0 前置脚本类型（可选，不改变确认前流程）

宿主（如 CTAIWD 欢迎页六选一）或用户本轮点选 / 口头指定了下列之一时，记为 `script_kind`，并只锁定表中那一轴。未指定、空值或无法识别时，**两轴都走第 1.1 节默认流程**，不得假装用户已选，也不得在选题或方案卡阶段提前改判。

一次只生效一个 `script_kind`；后一次点选或口头指定覆盖前一次，不得把新旧两次选择叠成两轴全锁。识别别名：`traffic` / 流量，`conversion` / 转化，`company_strength` / 公司实力，`quality_control` / 质控，`service` / 服务，`delivery` / 交付。宿主 slots、run configurable 或已拆好的 `objective` / `primary_content_type` 与点选为同一权威来源。

| script_kind | 中文 | 锁定轴 | 未锁定轴 |
|---|---|---|---|
| `traffic` | 流量 | `objective=traffic` | `primary_content_type` 仍按第 1.1 节判断 |
| `conversion` | 转化 | `objective=conversion` | `primary_content_type` 仍按第 1.1 节判断 |
| `company_strength` | 公司实力 | `primary_content_type=company_strength` | `objective` 仍按第 1.1 节判断 |
| `quality_control` | 质控 | `primary_content_type=quality_control` | `objective` 仍按第 1.1 节判断 |
| `service` | 服务 | `primary_content_type=service` | `objective` 仍按第 1.1 节判断 |
| `delivery` | 交付 | `primary_content_type=delivery` | `objective` 仍按第 1.1 节判断 |

锁定轴：成稿骨架、三库组合表和 `plan_contract` 必须沿用该值，不得因选题措辞、方案卡摘要或模型偏好改判。选「流量」或「转化」只锁目标，不得顺便改成企业四类主类型；选企业四类只锁正文主类型，不得顺便改写 `objective`。未锁定轴与完全未选定 `script_kind` 时，继续第 1.1 节。人设只约束表达风格，不改判锁定轴。

流量锁定时：必须先套专项「流量骨架」：反差钩子 → 异常现象 → 悬念 → 原因揭示 → 认知反转 → 评论互动；禁止改判为转化。转化锁定时：必须先套专项「转化骨架」：客户痛点 → 错误选择的代价 → 解决方案 → 证据 → 处理异议 → 咨询 CTA；禁止把转化解释成「建立判断力、引导关注」，禁止用关注/完播/涨粉收口，禁止改写成「反常识开场→讲原理→给启发」。然后才把未锁定轴的主类型正文配方填进中段。

企业四类由 `script_kind` 或用户明确指定时，适用第 3 节「用户明确要求某一企业类型」；仅第 1.1 节自动推断时，仍可在事实不足时降为不冒充企业事实的通用问题解法或中性科普。

已锁定类型后不要重开选题卡、人设选择或人设入职文档，但写稿**必须沿用已加载人设**的 styleGuide（定位 / 受众 / 内容 DNA / 表达风格 / 禁忌）和主 SOP「成稿输出规范」、已加载的平台规则。锁定类型只换口播骨架，**不省略**平台「输出格式」成稿块：口播正文之后仍须写【字幕重点】【画面建议】【发布文案】【话题标签】【风险与核验项】（以及该平台列出的【标题/首行】等）。上下文没有「输出格式」时，只补读当前平台规则文件的该节，不要重读选题流程。不必把全部流程文件再读一遍。禁止为重开流程而读取：`topic-selection.md`、`collaboration.md`、`multi-track.md`、`wechat-article.workflow.md`、`persona-onboarding.md`、`persona-schema.md`、`persona-reverse-sop.md`、已读过的 `SKILL.md`。`sop.md` 只在上下文还没有「成稿输出规范」时补读该节，不要重读选题/人设/三库选型章节。不要为重新分类通读 `library-catalog.md` 全量。本文件 + 已加载人设风格 + 视频专项组合表 + 成稿输出规范 + 平台输出格式，足够完成本阶段。

### 1.1 默认分类（未锁定轴 / 未选定 script_kind）

- 目标优先取用户本轮明确信号，其次取已加载人设；仍无法判断时沿用宿主原有提问，不默认转化。播放、完播、互动、涨粉、关注对应 `traffic`；询盘、咨询、获客、留资、成交、购买、索样、报价对应 `conversion`；两组同时明确对应 `traffic_conversion`。反常识只是表达方式，不覆盖业务目标。
- 工厂、设备、产能、团队、研发、资质或案例对应 `company_strength`；检测、标准、参数、不良品或追溯对应 `quality_control`；咨询、定制、响应、跟进、售后或问题处理对应 `service`；排产、生产节点、包装、装柜、物流或交期对应 `delivery`；其余观点、知识、误区和行业话题对应 `general`。
- 正文只展开一个主类型；辅助类型最多一个、不得为 `general`、不得与主类型相同，只在主线补一段证据。目标只控制开场、节奏和 CTA。
- `plan_contract` 必须锁定宿主已确认方案的选题、切入角度、钩子机制、核心判断、推进结构、语气和 CTA；目标与主类型以第 1.0 节锁定轴和第 1.1 节未锁定轴的结果为准。若方案卡摘要与已锁定的 `script_kind` 冲突，保留选题与钩子机制，按锁定轴写稿，不得为迁就方案卡改类型。真实性处理只替换无依据的事实载荷，不得擅自换题或改写为无关结构。
- 客户身份、发生时间、金额、次数、参数、认证、结果、承诺和第一人称经历不属于方案契约；它们只有进入 `verified_facts` 后才能作为企业事实使用。

### 1.2 切换脚本类型后再生成

已有成稿后，用户或宿主改选另一种 `script_kind`（含「换成质控看看」「按转化再写一版」）视为**按新类型重新成稿**，不是 `sop.md` 的润色改稿。

- 本轮最新 `script_kind` 立即覆盖上一轮锁定轴；按第 1.0 节重新锁定，并重选与新 `objective` / 主类型对应的三库组合表。
- **禁止**重走人设、热点、选题卡或方案卡；保留已确认选题、切入角度和钩子机制，只改目标、主类型、开场/节奏/CTA 与正文骨架。
- 必须按新类型**全文重写**后交付，禁止只改标题、收口或少量同义词交差。旧稿不是新类型的成稿。
- 用户要对比效果，或宿主走新版本合同时：写入新文件（可用宿主 `-vN`，或在主标题后标明类型如 `-质控`），再 `present_files`；不要覆盖到用户无法对照的路径。宿主明确要求覆盖当前稿时，可以覆盖当前路径，但仍须按新类型全文重写。
- 可多次切换；每一次都只认当时最新的 `script_kind`。取消点选、清空类型时回到第 1.1 节默认分类，不得沿用上一轮锁定。

## 2. 只在此时加载视频专项三库

内置三库执行：

```bash
siluzan-cso workflow load-libraries --platform <平台> --video-script --out <file_path>
```

落盘后不要通读合并文件。第 1.0 节已锁定类型时，**禁止读取 `library-catalog.md`**：选号权威是合并文件「视频脚本专项章节」里与锁定类型相关的组合表，不是全量目录。只读该组合表，再按表内编号回源入选条目全文（句式 / 结构块 / content）；**写稿必须把这些内容写进口播**，禁止只套目标骨架 + 人设风格 + 热点空写。不要为了重新分类或选号而通读基础库目录或 `sop.md` 选题章节。人设过滤仍用已加载人设，不要为此重读人设入职文档。未锁定时，先完整读取 `library-catalog.md`（含文末「视频专项」），按主 SOP 人设过滤 → 选题命中 → 配额选定编号后，在合并文件中定位入选条目全文，并读「视频脚本专项章节」里与本次 objective / 主类型相关的组合表。未入选的基础库条目不要读进上下文。

“微信视频号”规范为“视频号”；公众号和非视频任务禁止使用 `--video-script`。用户本轮提供或本地已有三库时，用户文件保持权威且允许沿用原流程优化；视频专项规则不得写回或覆盖用户文件，只从已有条目按语义选取，不创建、改写或强套内置编号。

自定义三库没有专项章节时，仍按以下语义兜底：公司实力为客户疑问 → 真实场景/能力证据 → 客户价值；质控为质量风险 → 检测节点/标准 → 处置或结果；服务为客户问题 → 具体服务动作/解决过程 → 结果；交付为订单与时间压力 → 排产/生产/物流节点 → 风险处理与结果。

第 1.0 节已锁定 `script_kind` 时：先读专项烹调「目标骨架」和「组合检查」，**先套锁定类型的目标骨架，再把主类型正文配方放进中段**。主 SOP `sop.md` 题材表（生活物件升维 / 角色闯关科普）和通用「结论先行 / 现象到本质 / 反常识开场→讲原理→给启发」不得覆盖该骨架，也不得把视频专项组合表降为补充项。题材表条目最多给未锁定轴的正文素材作参考，不能改开场、节奏和 CTA。

未锁定 `script_kind` 时：若已确认选题命中主 SOP 题材表，且合并后的本次三库含对应 TF/PA，则该组合优先于本节 objective 默认因子表；视频专项覆盖层的 TF-0031 / PA-0011 / PA-0012 只作补充。事实约束不变。

## 3. 六大类型内部的事实确认

- `verified_facts` 只收录用户本轮原文、正式人设事实、用户提供文件和本轮企业知识库/RAG 原始结果中直接出现的事实，并保留内部来源摘录。方案卡、模型总结、行业常识、三库示例和既有成稿一律不是企业事实来源。
- 先把确认方案拆成 `plan_contract` 与待核实陈述。未被 `verified_facts` 支持的企业数字、资质、客户、案例、结果和承诺进入 `unsupported_plan_claims`，不得原样进入正文；用户确认方案只确认创作方向，不确认其中的企业陈述。
- 公司实力至少需要一项真实能力锚点；质控至少需要一项真实检测节点、标准、动作或处置锚点；服务至少需要一项真实服务动作或过程锚点；交付至少需要一项真实排产、生产、包装、物流或风险处理锚点。非核心事实缺少时继续生成，不得因此放弃已确认方案。
- 用户明确要求某一企业类型但完全没有对应事实锚点时，只列出 `missing_facts` 并请求补充；该类型仅由模型自动推断时，保留选题和核心判断，降为不冒充企业事实的通用问题解法或中性科普。
- 行业通用知识可以用于解释原理、风险和检查思路，但必须使用中性主体，不得改写成“我们公司”“我们的客户”“我们执行”的企业事实，也不得代替该类型必需的真实锚点。

### 3.1 保持方案的柔性改写顺序

对 `unsupported_plan_claims` 按以下顺序处理，能改写就不得直接删除整段或更换方案：

1. 优先替换为 `verified_facts` 中语义相同的真实事实。
2. 没有精确事实时，保留冲突和判断，改为有依据的定性表达，例如把“1 年堵 3 次”改成“反复堵塞”。
3. 缺少真实案例时，保留故事或场景机制，明确改成假设场景或常见问题，例如“假设你们厂的膜反复堵塞”；不得伪装成真实客户经历。
4. 缺少具体结果时，保留排查和解决过程，改写为可能性、检查方向或过程价值，不承诺结果。
5. 只有核心企业事实无法替代且决定用户明确要求的内容类型时，才停止并列出 `missing_facts`。

### 3.2 三库组合的事实适配

- 有真实案例时可使用案例拆解或真实故事；没有时仍可保留场景化结构，但只能使用明确的假设场景、常见问题或中性过程，不得编造客户、时间和结果。
- 有真实定量事实时可使用数字冲击；没有时改成定性反差，不得为了流量效果补造金额、次数、年限或参数。
- 有真实标准、服务承诺或交付时间线时才可把它们作为企业证据；没有时改写为检测动作、服务过程、生产节点或检查思路。
- 不得从“有车间/有团队”推出“不外包、不转手、质量可控、交期可控”，也不得从“有联系方式”推出“免费咨询、发实拍、快速响应”。

## 4. 时长、成稿与最终质检

- 写稿顺序必须遵守专项烹调「组合检查」第一条：先套目标骨架，再把主类型正文配方放进中段。流量用流量骨架，转化用转化骨架（客户痛点 → 错误选择的代价 → 解决方案 → 证据 → 处理异议 → 咨询 CTA），混合用流量转化骨架。已锁定 `script_kind` 时禁止先走主 SOP 题材表或通用科普结构再回头套目标。骨架步骤名不得出现在口播正文里：按该顺序写连贯口播，不要写成「（客户痛点）…（处理异议）…」分段标注。
- 短视频时长按“用户明确时长 > 当前平台适配 > 短视频默认”处理：没有更高优先级约束时，`15～30 秒` 只保留钩子、一个核心事实/观点和 CTA，`30～60 秒` 为默认，`60～90 秒` 可展开一个过程或案例，仍只保留一条主线；YouTube 长视频等非短视频交付不受本默认值限制。
- 写稿时必须保持 `plan_contract` 中的选题、切入角度和钩子机制；如果原钩子依赖无来源事实，保留钩子机制并按第 3.1 节替换事实载荷。不得因为事实清理把故事型方案改成无关清单、把质控改成公司介绍。本轮未切换 `script_kind` 时，也不得擅自改变流量/转化目标；第 1.2 节换类型时必须按新锁定轴改写目标与主类型。
- 成稿后在本分支内部逐句复核：每句企业陈述必须能关联到 `verified_facts`；关联不到就按第 3.1 节改写。中性行业解释无需伪装成企业事实，但不得包含企业归因或结果承诺。
- 同时复核选题、主类型、核心判断、钩子机制、推进结构和 CTA 是否仍与 `plan_contract` 一致；真实性与方案一致性都通过后才写入成稿文件。
- 复用宿主已确认的方案，不新增方案或提纲确认。
- 用户明确要求占位稿时，只能使用中性的独立占位符，不得写成“我们在[待补]接到……”“前段时间我们到现场……”等第一人称、过去时的伪案例陈述。

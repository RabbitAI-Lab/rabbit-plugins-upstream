# 选题生成（根据账号人设推荐热点选题）

> **何时 Read 本文件**：准备阶段（人设 + 三库已就绪）后、进入 `sop.md` 写正文**之前**，需要从热点 / 热搜 / 网络资讯 / 用户素材中**生成或筛选选题**时——包括「推荐 N 个选题」「热点写稿」「根据这条新闻出角度」等。
>
> 若用户已给出**带具体角度**的一句话选题，且角度已体现本号「一句话定位」中的核心任务，可跳过本文件，直接进入 `sop.md`「定选题」核对后写稿。

---

## 1. 核心原则

**目标**：生成同时满足以下条件的高价值选题：

```text
符合账号定位
+ 目标受众关心
+ 市场正在讨论
+ 账号能提供独特价值
+ 具备内容或商业目标承接空间
```

**综合匹配度**表示选题适合当前账号创作的程度，**不代表**成为爆款的概率。

### 1.1 定位优先于受众画像

**最常见偏离**：把 styleGuide 里**受众的身份/行业**当成**账号要讲的内容**。

- **受众画像**回答「对谁讲」——职业、阶段、行业、关心的问题
- **一句话定位**回答「这个号日常讲什么、提供什么价值」

二者可以相关，但**不必重合**。不得只根据「赚钱、增长、机会、商业、健康、成长」等宽泛结果词判断相关性。

| 优先级          | 锚点                                                | 作用                                                     |
| --------------- | --------------------------------------------------- | -------------------------------------------------------- |
| **1（主锚）**   | 「一句话定位」                                      | 决定这个号**日常在讲什么**（方法 / 判断 / 案例 / 转化…） |
| **2**           | 「内容 DNA · 价值观锚点」+「目标受众 · 关心的问题」 | 决定**从什么切口**讲、**帮受众解决什么**                 |
| **3（素材层）** | 热点 / 网络信息                                     | 提供时效与讨论入口；作用随账号类型而定（见 §3.4）        |
| **4（排除）**   | 「禁用表达 / 禁忌」                                 | 命中即淘汰                                               |

**一句话**：选题必须落在本号核心任务上；热点提供入口与时效，但不能用热度弥补定位错位。

---

## 2. 触发与跳过

**必须走本流程**（命中任一）：

- 用户给热点 / 热搜 / 新闻链接 / 行业资讯，但未指定写作角度
- 用户要「推荐选题 / 热点选题 / 帮我选 3 个题 / 结合人设出角度」
- 宿主固定流程处于选题推荐阶段（如 CTAIWD「推荐热点 → 成稿」的选题门）

**可跳过**（选题已明确）：

- 用户已确认一句话选题 + 具体角度，且角度已对齐「一句话定位」
- 改稿（revise）/ 审稿（audit）模式
- 用户明确「就写这个标题 / 这个方向，不要换题」

---

## 3. 执行步骤

```text
读取账号人设
  ↓
建立账号定位模型
  ↓
整理并核验已有热点 / 网络信息（不再次搜索）
  ↓
热点资格审查（内部淘汰，不向用户展示）
  ↓
热点转化为账号选题（完整价值链）
  ↓
分项评分与风险修正
  ↓
质量门槛过滤
  ↓
排序、去重并输出推荐结果
  ↓
用户确认（硬门）→ 再进入 sop.md
```

进入本文件时，热点 / 热搜 / 新闻 / 网络资讯**已由上游提供**（用户粘贴、宿主热榜工具结果、会话内已选热点等）。本步只做核验与转化，**禁止**再跑一轮热点搜索来「补素材」。

### 3.1 建立账号定位模型

从 styleGuide / 人设字段**综合提取**（不得只盯受众行业词）：

| 内部信息               | 说明                                                                                             |
| ---------------------- | ------------------------------------------------------------------------------------------------ |
| 账号核心任务           | 帮助谁、解决什么问题、提供什么价值、促成什么行动                                                 |
| 内容任务类型           | 方法实操 / 趋势判断 / 观点评论 / 案例拆解 / 产品服务 / 商业转化 / 行业资讯 / 知识科普 / 灵感娱乐 |
| 内容支柱               | 可长期稳定输出的 3—5 个方向                                                                      |
| 价值产生机制           | 通过判断、方法、案例、信息、产品或服务创造什么价值                                               |
| 允许 / 邻近 / 排除赛道 | 可直接推 / 须有明确价值链才推 / 即使关键词重合也不可推                                           |
| 表达资格               | 拥有的经验、案例、数据、产品或独特视角                                                           |

向用户复述时可合并为一行：

```text
本号核心任务：对〔目标受众〕讲〔定位能力/价值〕，让他〔信什么 / 会什么 / 做什么〕
```

后续每个候选选题都必须属于这一任务类型与价值产生机制。须继续判断：

```text
价值产生机制是否一致
目标受众是否一致
用户行动是否一致
账号专业能力是否一致
账号目标承接路径是否一致
```

### 3.2 错位判定与资格审查

产出或筛选候选前，对每一题先跑错位判定；再对热点做资格审查。**任一条不通过即淘汰**（淘汰只在内部执行，**不向用户展示**淘汰名单与原因）。

**错位判定（三条，任一不通过 = 偏离）**：

| #   | 判定问句                                                                                                       | 不通过 = 偏离                 |
| --- | -------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| 1   | 这个标题/角度，是否**只有**在本号「一句话定位」下才成立？换一个人设是否同样适用？                              | 换人设仍成立 → 未锚定本号     |
| 2   | 去掉热点/新闻关键词后，核心是否仍像**资讯号/行业媒体**会发的稿？（行业资讯型账号除外，但仍须解释对受众的影响） | 是 → 热点被当成了选题         |
| 3   | 能否在「目标受众 · 关心的问题」里找到**对应原句**说明「粉丝今天为什么要在意」？                                | 找不到 → 只有新闻没有受众处境 |

**直接淘汰条件**（命中任一即淘汰，不得靠热度加分复活）：

1. 属于账号排除赛道 / 触碰「禁用表达 / 禁忌」
2. 与账号只有表面关键词重合
3. 价值产生机制与账号定位不同
4. 无法说明目标受众为什么**现在**需要关注
5. 只能生硬嫁接账号、产品或行业
6. 账号不能提供区别于普通资讯号的价值
7. 热点已经明显过期；或来源 / 时间无法确认
8. 核心事实无法核实
9. 存在严重平台、法律、品牌或伦理风险
10. 与近期内容高度重复且没有新事实或新角度

**合格热点必须能回答**：

1. 为什么与账号核心任务有关？
2. 具体影响目标受众的什么利益、问题或决策？
3. 账号可以提供什么独特判断、方法、案例或行动建议？
4. 去掉热点名称后，内容是否仍能积累账号长期定位？

若只能回答「因为它很热 / 大家都在讨论 / 可以蹭流量」→ 淘汰。

### 3.3 整理并核验已有热点

**输入已就绪**：直接使用会话 / 宿主 / 用户已给出的热点与网络信息作为候选池，**不要**再调用热榜或联网搜索补一批新热点。

按来源整理候选（不是直接当标题）：

| 来源                    | 动作                                                                          |
| ----------------------- | ----------------------------------------------------------------------------- |
| 用户本次提供            | 链接 / 截图 / 摘要 / 关键词 —— 提取可转化的事实点（数字、争议、反差、新趋势） |
| 上游已拉取的热榜 / 资讯 | 使用已有列表与字段；缺摘要时仅从**已有材料**提炼，不另搜                      |
| 三库 + RAG              | 准备阶段已读三库；涉及品牌/产品事实须已有 RAG 结果，**禁止**为选题编造数据    |

用定位模型对**已有候选**做优先排序（仍不搜索）：

1. 更贴近账号核心内容支柱
2. 更贴近目标受众利益
3. 更贴近行业 / 产品 / 服务 / 市场变化
4. 仍在有效传播窗口、尚未高度饱和
5. 存在反差、争议或认知差，且账号能提供独特解释或行动建议

每条尽量补齐（从已有字段推断即可）：`title` / `factSummary` / `source` / `sourceUrl` / `publishedAt` / `heat`（及可选的 `heatTrend` / `audience` / `industries` / `markets`）。

**纪律**：不得将旧闻包装为实时热点；来源或时间无法确认的热点不得进入最终推荐；候选池为空或全部不合格时，向用户说明并请其补充热点 / 资讯，**而不是自行再搜一轮**。

### 3.4 热点 → 选题转化（完整价值链）

每个选题必须形成完整价值链（缺一不可）：

```text
热点事实
→ 目标受众发生了什么变化
→ 影响受众的什么利益、问题或决策
→ 账号可以提供什么独特价值
→ 用户可以形成什么判断或采取什么行动
```

先写价值链 / 嫁接句，再写标题：

```text
嫁接句：〔热点事实〕 + 〔受众此刻处境/痛点〕 + 〔本号核心任务〕
→ 选题标题 + 具体角度
```

热点在内容中的作用按账号类型确定（**不应强制所有账号都将热点降级为辅助钩子**）：

| 账号类型   | 热点作用                 |
| ---------- | ------------------------ |
| 方法实操型 | 行动背景或需求理由       |
| 趋势判断型 | 趋势证据和判断对象       |
| 观点评论型 | 观点冲突的起点           |
| 案例拆解型 | 分析和拆解对象           |
| 产品服务型 | 用户需求或使用场景       |
| 商业转化型 | 获客、成交或业务机会入口 |
| 行业资讯型 | 核心内容，但必须解释影响 |
| 知识科普型 | 专业知识的现实入口       |
| 灵感娱乐型 | 创作由头 / 触发点        |

**转化规则**：

1. 标题体现本号任务与角度；热点背景写入 `hotspotBackground`（或 UI 映射字段），不要把新闻标题略改就当选题
2. 角度必须落到受众「关心的问题」；说不出「这和粉丝今天有什么关系」→ 换角度或换素材
3. 至少体现 1 个反差 / 冲突 / 认知差（对照流量因子库思路）；纯复述新闻 → 淘汰
4. 同一热点默认只推荐一个主角度；仅当目标受众利益与内容价值明显不同时，才允许第二个角度——且都必须过 §3.2

### 3.5 分项评分与风险修正

只对通过资格审查的热点评分。**必须先完成分项评分，再算综合匹配度**；禁止先拍一个百分比再补写理由。热点热度不得弥补定位错位。

| 评分项             | 权重 | 判断重点                                             |
| ------------------ | ---: | ---------------------------------------------------- |
| 账号定位匹配度     |  35% | 核心任务、内容类型、内容支柱和价值机制是否一致       |
| 目标人群重合度     |  20% | 是否影响受众利益、成本、收入、工作、生活或决策       |
| 内容差异化         |  15% | 是否有独特观点、经验、案例、数据或方法               |
| 市场热度与增长     |  15% | 当前热度、增长速度、跨平台扩散、传播窗口和竞争饱和度 |
| 账号目标承接能力   |  10% | 是否能连接产品、服务、客户、转化、信任或其他账号目标 |
| 事实与素材可支撑度 |   5% | 来源是否可靠，素材是否足以支撑完整内容               |

```text
基础适配分 =
账号定位匹配度 × 35%
+ 目标人群重合度 × 20%
+ 内容差异化 × 15%
+ 市场热度与增长 × 15%
+ 账号目标承接能力 × 10%
+ 事实与素材可支撑度 × 5%

综合匹配度 = 基础适配分 × 风险系数
```

| 风险情况                     |   系数 |
| ---------------------------- | -----: |
| 风险低，可以正常创作         |   1.00 |
| 轻微争议，需要补充边界       |   0.95 |
| 部分事实或因果关系需要核验   |   0.90 |
| 存在明显平台、事实或品牌风险 |   0.80 |
| 风险较高，需要专业资格       |   0.70 |
| 严重风险                     | 不推荐 |

分项评分与计算过程仅内部保留，**不向用户展示**。

### 3.6 质量门槛与淘汰校验

选题必须**同时**满足：

```text
账号定位匹配度 ≥ 70
目标人群重合度 ≥ 65
事实与素材可支撑度 ≥ 70
风险系数 ≥ 0.80
综合匹配度 ≥ 70
```

并与 `sop.md`「定选题」淘汰规则、§3.2 错位判定**合并执行**：

- [ ] 说不出属于本号「一句话定位」的哪条能力 / 常讲方向
- [ ] 触碰「禁用表达 / 禁忌」
- [ ] 受众**具体处境**不成立（只有新闻，没有「和我有关」）
- [ ] 反差 / 冲突 / 认知差一个都凑不出
- [ ] §3.2 三条错位判定任一不通过
- [ ] 质量门槛任一指标不达标

不足 3 个合格选题时可以少于 3 个，**不得为凑数降低门槛**。淘汰后从 §3.4 重转化。

### 3.7 排序、去重与产出

默认输出综合匹配度最高的 **3** 个选题（宿主 UI 或用户指定 N 时按 N，但仍须过门槛）。推荐结果应尽量：

- 来自不同热点或趋势
- 覆盖不同内容支柱
- 切入角度不同、用户价值不同
- 不能只是替换标题措辞

每个交付选题须包含：

| 字段                  | 要求                                                          |
| --------------------- | ------------------------------------------------------------- |
| `rank`                | 从 1 起，按综合匹配度降序                                     |
| `title`               | 适合对应平台的一句话选题（含具体角度）                        |
| `tags`                | 1—3 个内容标签                                                |
| `matchScore`          | 综合匹配度整数，70—100（由分项 × 风险系数算出，禁止随意填写） |
| `matchReason`         | 为什么符合定位、受众为什么关心、账号能提供什么独特价值        |
| `hotspotBackground`   | 对应的真实热点、市场变化与时效信息                            |
| `creativeRisk`        | `{ level: 低\|中\|高, description }`：主要风险与表达边界      |
| `recommendedApproach` | 从什么角度切入、核心讲什么、落到什么判断或行动                |

**不要向用户输出**：被淘汰热点及原因、内部定位模型、分项评分与计算过程、完整文章提纲。

可选附带页面级信息：热点数据 `updatedAt`（ISO 8601）、`validFor`（建议 `24小时`）。

### 3.8 用户确认（硬门）

- 向用户展示候选（卡片 / 列表 / 对话均可），**必须等用户选定 1 个**（或指定修改方向）后再进入 `sop.md` 出提纲 / 写正文
- 用户要求「换角度 / 再推荐」→ 在**同一热点池**内回到 §3.4 重转化（或 §3.3 重排序），保留已选人设；勿重新搜索热点
- **禁止**未确认直接写正文（多轨时选题确认后仍走 `multi-track.md` brief 确认）

## 4. 与主工作流的关系

```text
content-writer.workflow.md
  第 1 步 人设 → 第 2 步 三库 → 第 3 步 RAG（按需）
       ↓
  【本文件】选题生成（热点/网络信息且角度未定时）
       ↓
  sop.md：定选题（核对）→ 列素材 → … → 出提纲（再次确认）→ 写正文
```

- 本文件负责 **「核验已有热点 → 资格审查 → 价值链转化 → 评分筛选 → 对齐人设」**（不负责拉取热点）
- `sop.md`「定选题」负责 **「已确认选题的复核 + 行业因子包挂载」**
- `collaboration.md`：流量因子库服务**选题可见性**，但**不替代**人设定位锚定

## 5. 自检清单（交付候选前）

- [ ] 已建立账号定位模型（核心任务 / 价值机制 / 允许·邻近·排除赛道）
- [ ] 仅使用上游已有热点 / 网络信息，未再次搜索；来源与时间可确认
- [ ] 每个选题价值链完整，且过 §3.2 资格审查与错位判定
- [ ] 分项评分先于综合匹配度；`matchScore` 由公式算出，热度未弥补定位错位
- [ ] 质量门槛全部达标；不足 3 个时未凑数
- [ ] 多个候选在热点 / 支柱 / 角度上有明显差异
- [ ] 用户可见字段齐全；未展示淘汰原因、分项分、完整提纲
- [ ] 已请求或记录用户确认，未确认不写正文

# 单轨 / 多轨成稿（multi-track · 多宿主通用）

> **单轨**：一次交付 **1** 篇成稿（标准 SOP 提纲 → 正文）。  
> **多轨**：准备阶段（人设 / 三库 / RAG）**只做一次**，在策略层分叉为 **N** 条轨道各出 1 篇；**默认 N=2**，任务需要时可 3 轨及以上。  
> **协议层**全宿主一致；**执行层**默认主会话按轨顺序写（有 Task/subagent 时可并行，见 §6）。

**与单轨收尾改写的区别**：`sop.md`「按用途微调」是**先有一稿再变体**；多轨是**一次交付多篇策略不同的成稿**，供对比选用。

---

## 1. 何时用单轨 / 多轨

### 1.1 主动推断（用户未明说时也适用）

完成步骤 1–3 后、进入「定选题 / 列素材」前，**根据任务判断是否启用多轨**。多轨常能靠对比帮用户选方向，**倾向在下列情形主动提议多轨**（默认 2 轨，复杂任务可 3 轨）：

| 信号                                                  | 说明                                                               |
| ----------------------------------------------------- | ------------------------------------------------------------------ |
| 目标 / 用途不清晰                                     | 只给主题，未说偏曝光、转化、口播还是长文                           |
| 存在 2+ 条合理策略                                    | 同一素材可走「强观点」或「问题解法」、「爆款钩子」或「实操转化」等 |
| 用户要「试试 / 看看哪种好 / 给我几个方向 / 对比一下」 | 明示或隐含对比需求                                                 |
| 新选题 / 新账号 / 人设刚建立                          | 需要探索腔调与结构组合                                             |
| 一题多用途                                            | 如「既要公众号又要口播思路」→ 可按用途分轨（N=2+）                 |
| 高价值或长周期成稿                                    | 重要发布会、核心产品稿等，值得多策略备选                           |

**倾向保持单轨**（不必强行多轨）：

| 信号                                 | 说明                                       |
| ------------------------------------ | ------------------------------------------ |
| 用户明确「一篇 / 一版 / 就这个角度」 | 范围已锁死                                 |
| **revise / audit**                   | 改稿、审稿不走多轨                         |
| 极短任务                             | 单条评论回复、一句话标题等                 |
| 用户明确拒绝多版本                   | 「不要多版本」「只要一个」                 |
| 素材不足以支撑多策略                 | 事实清单太薄，分叉会编造 → 先补 RAG 或单轨 |

**主动提议时的动作**：用 1–2 句话说明「建议多轨对比的原因」+ 建议轨数 N + 各轨差异轴（不贴正文）；优先 human-in-the-loop 确认；用户同意则进多轨，拒绝或未回应且任务简单则单轨。

用户**明说**「两版 / 多版 / AB / 各出一版 / 三个方向」→ **直接多轨**，轨数按用户要求，未写数量则 **默认 2**。

用户「先出一稿，再改成爆款版」→ **单轨** + `sop.md` 收尾改写，**不是**多轨。

### 1.2 多轨前置

多轨 **仍须** 先完成 `content-writer.workflow.md` 步骤 1–3，并完成 `sop.md`「锚定人设 → 列素材清单」。**因子 / 结构 / 用途** 在 brief 里按轨分叉，**禁止**同一提纲写 N 遍。

## 2. 共享创作包：`multi-track-brief.md`

落盘一份 brief（过程文件，默认不交付）。路径建议：

`<工作目录>/<人设>-<选题>-multi-track-brief.md`

### 模板

```markdown
# multi-track-brief

## meta

- trackCount: 2 # 默认 2；用户指定或任务需要时可 3+
- inferenceReason: <为何多轨，主动推断时必填>

## shared（各轨共用）

- platform: <平台>
- topic: <一句话选题 + 具体角度>
- goal: 对〔谁〕讲〔什么〕，让他〔信什么 / 做什么〕
- personaDigest: <6 章节要点摘要>
- evidence:
  - claim: ... | source: ...
- constraints: <字数、禁忌等>

## track-1

- id: 1
- label: t1-<短标签>
- purpose: ...
- trafficFactors: [...]
- structureTemplate: ...
- outline: （5 段，见 sop 单轨提纲）

## track-2

- id: 2
- label: t2-<短标签>
- purpose: ...
- trafficFactors: [...] # 与已规划轨至少在 2 个维度上不同
- structureTemplate: ...
- outline: ...

## track-3 …（trackCount ≥ 3 时续写）

## diffContract

- pairwise: 任意两轨之间，purpose / structureTemplate / trafficFactors **至少 2 项不同**
- perTrack: 每轨不得复制他轨的开头钩子类型、主因子组合、结构模板名、收口动作类型
- sharedEvidence: 各轨共用 evidence，禁止编造无来源事实
- noThreeLibLeak: 禁止泄漏三库编码与内置库原文
```

### 用户确认（替代单轨「出提纲硬门」）

- 展示 **各轨对照**（每轨 5 段提纲 + purpose / 结构 / 因子差异），不贴正文。
- 优先 human-in-the-loop；无则对话确认。
- **未指定差异轴时**：提供 2–3 组预设组合供选（**不得替用户默认选定**），例如：
  - 爆款 vs 转化
  - 观点型 vs 解法型
  - 口播焊点：反常识 vs 强结果感（见 `sop.md` 附录 A）
- 用户确认轨数与各轨方案后**才能**写正文。

## 3. 成稿执行（默认 · 全宿主）

**按轨顺序**逐篇写（轨 1 → 轨 2 → … → 轨 N），不假设 subagent。

| 规则     | 说明                                                             |
| -------- | ---------------------------------------------------------------- |
| 每轨只读 | `shared` + 该轨 `track-k` 段                                     |
| 产出     | `<人设>-<选题>-t<k>-<标签>.md`（或 `t1-` / `t2-` 与 label 一致） |
| 禁止     | 写第 k 轨时 **不得 Read** 已完成轨的成稿正文                     |
| 每轨流程 | `sop.md`「写正文 → 质检」                                        |
| 校验     | 每轨各跑一次 `siluzan-cso workflow validate`                     |

**反同质化（第 k 轨，k≥2）**：

- [ ] 与 brief 中**每一轨**相比，结构模板名、开头钩子类型、主因子组合均符合 diffContract
- [ ] 与**已交付各轨成稿**相同长串（≥15 字）合计 ≤ 本篇 10%（数据 / 专名词 / 用户要求保留句除外）

---

## 4. 交付

- **文件**：每轨独立成稿；`multi-track-brief.md` 默认不交付。
- **对话**：各轨文件名 + **对比摘要**（每轨 1 句定位 + 轨间 3–5 条差异点）；不贴正文、不含三库。
- **选稿建议**（可选 1 段）：根据用户目标推荐优先试哪一轨，**不替用户定稿**。

---

## 5. 轨数建议

| N             | 典型场景                                                   |
| ------------- | ---------------------------------------------------------- |
| **2**（默认） | 双策略对比、AB 备选                                        |
| **3**         | 曝光 / 转化 / 口播各一轨；或三种结构试探                   |
| **4+**        | 用户明确要求；或分平台分轨（每平台一轨）——须用户确认工作量 |

未指定时 **N=2**；主动推断时 **优先 2**，避免无必要地堆轨。

---

## 6. 可选加速（按宿主能力 · 非必须）

| 能力             | 行为                                                                                           |
| ---------------- | ---------------------------------------------------------------------------------------------- |
| 无 Task/subagent | §3 顺序各轨（默认）                                                                            |
| 有 Task/subagent | 每轨派发自包含任务：`briefPath` + 单一 `track-k` + `shared` 摘要；禁止读他轨成稿、禁止嵌套澄清 |
| 不支持并行       | 仍顺序，不重复步骤 1–3                                                                         |

Handoff 字段：`briefPath`、`trackId`、`outputPath`、`forbidden[]`、`returnSchema`（outputFile、validateExitCode、1 句轨定位）。

**无 subagent 的宿主忽略本节。**

---

## 7. 与 `sop.md` 模式对照

| 模式               | 提纲确认               | 成稿数      | 差异化                  |
| ------------------ | ---------------------- | ----------- | ----------------------- |
| **new 单轨**       | 一次 5 段提纲          | 1           | —                       |
| **new 多轨**       | 一次 multi-track brief | N（默认 2） | 按轨分叉 + diffContract |
| **new + 收尾改写** | 一次提纲               | 1 → 微调    | 用途微调，非多轨        |

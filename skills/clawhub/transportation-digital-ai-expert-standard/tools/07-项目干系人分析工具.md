# 大型项目干系人分析工具
## Stakeholder Analysis Toolkit for 项目 Transportation Projects

---

## 一、工具概述

本工具专为交通领域交通数字化项目设计，提供干系人识别、分析、沟通管理和会议管理的全套工具链。覆盖从项目启动到验收交付的全周期干系人管理需求。

### 适用场景
- 城市智慧交通建设项目（综合交通运行协调中心、信号控制等）
- 高速公路/国省道数字化项目
- 公共交通信息化项目
- BOT/PPP交通项目
- 交通数据平台/业务系统项目

## 三、权力-利益网格（Power-Interest Grid）

### 3.1 网格绘制模板

```
利益/兴趣(Interest) 高
                    ↑
    保持满意         │         紧密管理
    Keep Satisfied   │      Manage Closely
                     │
    ┌────────────────┼────────────────┐
    │                │                │
    │  S7(上级单位)   │  S1(Sponsor)   │
    │  S8(投资方/资金方)  │  S2(直接负责)   │
    │  S19(行业专家)  │  S3(业务使用方)  │
    │  S22(立法与监督机构)  │  S6(IT技术)     │
    │                │  S9(交通管理)    │
    │                │                │
    ├────────────────┼────────────────┤
    │                │                │
    │  S18(媒体)      │  S4(财务采购)    │
    │  S21(工会)      │  S10(数据管理部门)   │
    │  S20(友商)      │  S11(规划住建)   │
    │                │  S12(环保应急)   │
    │                │  S5(法务)        │
    │                │  S13(城管市政)   │
    │                │  S14/15(服务方)    │
    │                │  S16(监理)       │
    │                │                │
    └────────────────┼────────────────┘
    监控             │         保持知情
    Monitor          │       Keep Informed
                     │
                    ┆
                    低 ←────────────────→ 高  权力(Power)
```

### 3.2 管理策略

| 象限 | 策略 | 典型干系人 | 沟通频率 | 主要行动 |
|------|------|-----------|----------|----------|
| 高权力-高利益 | 紧密管理 | S1/S2/S3/S6/S9 | 每周 | 一对一沟通、定期汇报、早期参与 |
| 高权力-低利益 | 保持满意 | S7/S8/S19/S22 | 每月 | 里程碑汇报、关键决策征求意见 |
| 低权力-高利益 | 保持知情 | S4/S10/S11/S5/S13/服务方/监理 | 每两周 | 信息同步、培训宣贯、收集反馈 |
| 低权力-低利益 | 监控 | S18/S20/S21 | 每季度 | 舆情监控、信息披露、被动响应 |

**评分说明**：
- **不知晓**：不知道项目存在

- **支持**：知道并支持
- **引领**：主动推进项目

|------|--------|----------|-------------|----------|

| 外部层 | 公众/媒体/专家 | 舆论、评价、合规 | 2-3 | 正面宣传、问题快速响应 |

## 七、大型项目专项干系人管理检查清单

### 7.1 20项检查清单

```
============================================================================
       大型项目干系人管理检查清单
============================================================================

【政策与监管环境】
□ 1. 是否了解现任市/局决策者的核心施政方向和考核指标？
□ 2. 项目能否体现决策者的工作成效亮点（可量化、可宣传）？
□ 3. 是否了解近期的换届/人事变动窗口期？
□ 4. 项目是否已纳入正式规划文件/年度重点工作？

【确认流程】
□ 5. 是否梳理清楚完整的审批路径（项目启动/可行性研究/初步设计/技术采购/验收）？
□ 6. 每个审批节点的关键决策人是谁？审批周期多长？
□ 7. 是否有预沟通运行框架（正式流程前的非正式沟通）？

【资金保障】
□ 8. 项目资金是否已列入年度资金预算？
□ 9. 如果使用专项债券/PPP/社会资本，资金到位时间线是否明确？
□ 10. 付款流程和周期是否清晰（资金方支付中心审批周期）？

【横向协同】
□ 11. 交通管理/数据管理部门/住建规划等横向部门是否已取得共识？
□ 12. 数据共享是否有协议/公文/会议纪要作为依据？
□ 13. 是否需要成立跨部门的项目决策小组/专班？

【合规风险】
□ 14. 技术采购方式是否符合采购规定？
□ 15. 国产化/等保/密评/数据安全合规是否已纳入计划？
□ 16. 项目方案是否经过第三方专家评审？

【舆论与公众】
□ 17. 是否有舆情应对预案（系统故障/数据泄露/负面评价）？
□ 18. 是否规划了面向公众的宣传和推广？

【团队保障】
□ 19. 客户方项目团队是否专职/主要精力投入？（避免兼职难以推动）
□ 20. 是否有明确的指挥链和决策升级路径？

============================================================================
检查人：____________  日期：____________  状态：□ 全部完成  □ 有___项待处理
============================================================================
```

## 九、问题升级路径设计

### 9.1 三级升级运行框架

```
Level 1: 项目级（日常执行层）
  ┌─────────────────────────────────┐
  │ PM ↔ 服务方项目经理                │
  │ 适用：日常进度/技术问题/资源协调  │
  │ 解决时限：48小时                  │
  └─────────────┬───────────────────┘
                │ 无法解决或超时
                ▼
Level 2: 部门级（管理层）
  ┌─────────────────────────────────┐
  │ Sponsor/客户方负责人 ↔ 服务方项目总监   │
  │ 适用：重大变更/预算/延期/争议     │
  │ 解决时限：5个工作日               │
  └─────────────┬───────────────────┘
                │ 无法解决或影响更大范围
                ▼
Level 3: 组织级（决策层）
  ┌─────────────────────────────────┐
  │ 客户方局决策者 ↔ 服务方公司高层         │
  │ 适用：合同变更/项目终止/重大事故  │
  │ 解决时限：10个工作日              │
  └─────────────────────────────────┘
```

### 9.2 升级触发条件

| 触发条件 | 升级级别 | 责任人 | 通报范围 |
|----------|----------|--------|----------|
| 任务延迟超过3个工作日且影响关键路径 | L1→L2 | PM | 项目组全员 |
| 需求变更累计超过原范围20% | L1→L2 | PM | 项目指导委员会 |
| 成本超支累计超过预算10% | L2→L3 | Sponsor | 项目指导委员会 |
| 关键人员离职且一周内找不到替代 | L1→L2 | PM | 项目组 |
| 系统重大故障/安全事故 | 直接L3 | PM/S | Sponsor/S全体干系人 |
| 客户方/服务方合同争议无法达成一致 | L2→L3 | S/S | 法务/高层 |
| 数据泄露/重大合规事件 | 直接L3 | PM/S | 法务/安全/高层 |
| 行业规范/法规突变影响项目 | L2→L3 | Sponsor | 项目指导委员会 |

## 十、干系人管理工具包使用流程

```
============================================================================
              大型项目干系人管理流程
============================================================================

步骤1：干系人识别（项目启动前/初期）
  → 使用第二节模板，列出所有潜在干系人
  → 至少覆盖客户方、横向、监督、外部四类干系人
  → 输出：干系人清单（20+人/组织）

步骤2：干系人分析（项目启动期）
  → 使用第三节权力-利益网格进行定位
  → 使用第四节评估当前参与度和目标参与度
  → 使用第六节进行影响关系映射
  → 输出：干系人分析报告

步骤3：沟通计划制定（项目规划期）
  → 使用第五节模板制定沟通计划
  → 为每个干系人/干系人组确定沟通方式
  → 输出：项目沟通管理计划

步骤4：专项检查（项目启动/执行期）
  → 使用第七节项目专项检查清单
  → 逐项排查大型项目特有风险
  → 输出：检查结果和行动项

步骤5：持续管理（项目执行期）
  → 使用第八节会议模板召开各类会议
  → 使用第九节升级路径处理问题
  → 定期更新干系人分析（建议每季度）
  → 输出：会议纪要、更新后的干系人分析

步骤6：干系人管理评估审查（项目收尾）
  → 回顾干系人管理效果
  → 总结大型项目干系人管理经验教训
  → 输出：干系人管理总结报告
============================================================================
```

## 十一、使用说明

1. **项目初期**即启动干系人识别和登记
2. **关键干系人**（S1-S6）必须一对一访谈，了解期望和关切
3. **权力-利益网格**随着项目推进动态更新（建议每季度）
4. **沟通计划**要与项目计划同步，指定专人负责执行
5. **会议管理**要坚持"有准备、有记录、有跟踪"三原则
6. **升级路径**要在项目启动时明确并告知所有干系人
7. **项目专项检查**在项目启动和每个里程碑前都要执行一遍
8. **干系人满意度**建议通过非正式渠道持续感知，不要等调研问卷

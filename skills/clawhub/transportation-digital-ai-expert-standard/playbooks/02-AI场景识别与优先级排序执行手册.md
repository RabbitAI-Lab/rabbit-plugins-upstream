### 1.2 头脑风暴技术

**技术1：静默便签法（Silent Brainstorming）**
- 每人独立写下所有能想到的AI应用场景（5分钟，至少写5个）
- 每人轮流读出自己的便签并贴在白板上
- 不允许在他人发言时评论或质疑——只贴不问
- 贴完后统一分组归类

**技术2：痛点反向推导法**
- 每个业务部门列出当前最痛的点（"每天花3小时人工查视频"）
- 用"AI能不能..."句式将每个痛点转化为AI场景
- 例如："每天花3小时人工查视频" → "AI能不能自动识别交通事件并报警？"

**技术3：AI能力倒推法**
- 列出10项成熟的AI能力（视觉识别/NLP/预测/优化/生成/推荐/异常检测/知识图谱/强化学习/多模态）
- 针对每项能力，问："这项能力在我们的业务中可以用在哪里？"
- 每个能力至少产出3个场景想法

**技术4：竞品对标刺激法**
- 展示行业标杆的AI应用（杭州城市大脑/Apollo自动驾驶/新加坡LTA/宁波港AI）
- 每展示1个案例，问："这个我们能不能做？我们能做更好的是什么？"
- 激发"我们也行"的心态

### 2.1 数据可用性检查清单

> **针对每个入围场景，填写以下数据检查清单：**

| # | 检查项 | 选项 | 说明 |
|---|--------|------|------|
| 1 | 所需数据是否存在于现有系统？ | 是/部分/否 | "部分"需注明缺失哪部分 |
| 2 | 数据是否已电子化（非纸质台账）？ | 是/部分/否 | 纸质数据需先做数字化 |
| 3 | 数据是否可以实时/准实时获取？ | 实时/T+1/离线 | T+1=次日，离线=不定时 |
| 4 | 数据格式是否结构化？ | 结构化/半结构化/非结构化 | 非结构化（视频/图片/文本）需预处理 |
| 5 | 是否有数据字典/元数据描述？ | 完备/部分/无 | "无"意味着需反向工程理解数据 |
| 6 | 数据采集是否持续稳定？ | 是/不稳定/停止 | 不稳定=有断点，需先修复采集 |
| 7 | 数据是否可跨部门获取？ | 是/需协调/不可获取 | "需协调"需注明协调部门和难度 |
| 8 | 数据是否涉及隐私/安全限制？ | 否/脱敏可控/不可用 | 不可用的数据即使存在也等于无 |
| 9 | 历史数据量是否满足模型训练？ | >1年/6-12个月/<6个月 | AI模型通常需要至少1年完整周期 |
| 10 | 数据标签是否存在（监督学习）？ | 人工标注/自动标注/无标注 | 无标注需先做标注工程 |

**数据就绪度综合评分：**
- 每题2分制（是=2, 部分=1, 否=0），满分20分
- 15-20分：数据就绪——可直接启动AI开发
- 10-14分：数据部分就绪——需1-3个月数据工程准备
- 5-9分：数据准备不足——需3-6个月数据工程建设
- 0-4分：数据严重不足——建议先建设数据基础设施再考虑该AI场景

### 2.2 数据质量快速评估

**五大质量维度（5分制）：**

| 质量维度 | 含义 | 评分标准 |
|----------|------|----------|
| 完整性 | 数据缺失比例 | 5=<1%缺失, 4=1-5%, 3=5-10%, 2=10-20%, 1=>20% |
| 准确性 | 数据与实际的一致性 | 5=经校验, 4=用户反馈准确, 3=偶有问题, 2=已知偏差, 1=不可信 |

| 唯一性 | 数据去重情况 | 5=自动去重, 4=定期去重, 3=手动去重, 2=少量重复, 1=大量重复 |

## 第三阶段：RICE++评分工作坊（第5周第1天）

### 3.1 RICE++六维模型

> **传统RICE四维：范围(Reach)、影响(Impact)、信心(Confidence)、努力(Effort)**
> **交通增强二维：安全影响(Safety Impact)、行业规范紧迫度(Policy Urgency)**

| 维度 | 含义 | 评分范围 | 评分锚点 |
|------|------|----------|----------|
| R-范围(Reach) | 影响的用户/设备/覆盖范围量 | 1-10 | 10=全市全模态, 1=单一路口/单设备 |
| I-影响(Impact) | 对核心KPI的提升幅度 | 1-10 | 10=提升>50%, 1=提升<5% |
| C-信心(Confidence) | 技术可实现性的信心水平 | 1-10（百分比） | 10=100%确信能实现, 5=50%把握 |
| E-努力(Effort) | 所需投入（人月） | 1-10（反向） | 10=<10人月, 1=>500人月 |
| S-安全影响(Safety) | 对交通安全的正向影响 | 1-10 | 10=直接降低事故死亡, 1=无关安全 |
| P-行业规范紧迫(Policy) | 行业规范/法规的推动力 | 1-10 | 10=全国性硬性要求+时限, 1=无行业规范驱动 |

**RICE++综合得分公式：**
```
RICE++ = (R × I × C) / E × (1 + S/10) × (1 + P/10)
```
其中：
- 安全影响S和行业规范紧迫P作为乘数因子（而非加数），确保高安全/高行业规范场景获得显著优先级提升
- 当S>7或P>7时，即使RI/CE较低，该场景也会得到显著提升（"不可推迟"效应）

### 3.3 校准练习

**标准校准场景（已预先设定参考答案）：**

| 场景 | R | I | C | E | S | P | RICE++ | 预期排名 | 难度 |
|------|---|---|---|---|---|---|---|---|--------|----------|------|
| C01: AI自适应信控（新建） | 8 | 7 | 7 | 4 | 8 | 6 | 计算的参考值 | 中 | 中 |
| C02: AI道路病害识别（轻量） | 5 | 5 | 9 | 8 | 4 | 3 | 计算的参考值 | 中 | 低 |
| C03: 交通大模型问答 | 9 | 6 | 5 | 3 | 1 | 2 | 计算的参考值 | 中 | 高 |

**校准讨论引导问题：**
1. "为什么C02的E给到8（投入极小），但RICE++反而不如C01？" → 揭示安全影响的乘数效应
2. "C03范围很大但置信度低，这意味着什么？" → 揭示C（信心）在公式中的制衡作用
3. "如果一个场景S=9，但RICE都很低，该怎么排？" → 安全红线——不可推迟，但可以降级为"先做最小可行方案保安全"

### 3.4 常见评分偏差与纠正

| 偏差 | 表现 | 纠正方法 |
|------|------|----------|
| 乐观偏差 | 所有人都高估C（信心），说"AI大模型不难" | 要求每人在打分前列举至少1个"可能导致失败的因素" |
| 规模膨胀 | R（范围）被打成"只要上线就得10分" | 明确R=当前阶段实际可达范围，不是远期愿景 |
| 新酷偏好 | 新技术场景（低空AI/数字孪生）获得情感加分 | 强调RICE++只看6个维度，不看"酷不酷" |
| 安全万能论 | 只要沾上"安全"，S被全部打10分 | 细化安全影响分级：10=直接减少死亡, 7=减少重伤/事故, 5=提升安全意识, 3=安全数据, 1=无关 |
| 预算保护主义 | 部门负责人给自己部门的项目打分偏高 | 跨部门交叉匿名打分（业务部门评技术部门场景，反之亦然） |
| "没有数据不能打分" | "我们数据不好，C应该打1分" | C=技术和组织能力信心，数据就绪度已在第二阶段评估，不重复惩罚 |

### 3.5 终极陷阱："一切都是优先级1"

**表现：** 所有场景排完后，决策者说："都很重要，都是优先级1"

**三步化解法：**

**第1步：承认合理性（1min）**
> "确实，列出的每个AI场景都有价值。正因为都有价值，我们才需要排优先级——不是做不做，而是先做哪个、后做哪个。"

**第2步：资源约束可视化（3min）**
> 在白板上画："我们未来12个月的AI团队是X人，预算是Y万，能同时推进的项目数是Z个。这里有30个场景，如果每个都做，每个只能得到1/30的资源，全部做不好。但如果集中资源做前5个，每个都能做好。"

**第3步：回归数据（5min）**
> "我们花了2天时间用RICE++对每个场景的6个维度进行了评估。如果大家觉得排名有问题，我们可以回到具体的某几个场景的某个维度上讨论调整。但如果无法说清哪个维度的评分不对，那我们就尊重方法论产出的排名。"

**如果决策者仍坚持——终极方法：分阶段**
> "我们可以这样：Phase 1（0-6个月）优先做排名前5的场景，并行启动排名6-10的场景的数据准备工作。Phase 2（6-18个月）等前5个出成果后，再把6-10推入建设。这样既是'所有都做'，又有先后时序。"

## 第四阶段：商业论证（第5-6周）

### 4.1 ROI快速估算

**交通AI项目经济价值计算框架（三效益法）：**

| 效益类别 | 计算要素 | 量化指标示例 |
|----------|----------|------|
| **经济效益** | 降低运营成本 | 减少人工巡检人员X人×年薪Y万 = Z万/年 |
| | 提升效率/吞吐量 | 通行效率提升X% → 时间价值Y万/年 |
| | 减少损失 | 事故减少X起×单起经济损失Y万 = Z万/年 |
| **社会效益** | 碳排放减少 | CO2减排X吨/年 → 碳交易价值Y万/年 |
| | 公众满意度 | 投诉减少X%/满意度提升Y分 |
| | 就业带动 | 新增高技术岗位X个 |
| **安全效益** | 死亡人数降低 | 减少X人/年死亡（无法用金钱衡量，但必须计入，尤其是向公共部门汇报时） |
| | 应急救援时间缩短 | 响应时间缩短X分钟 → 重伤转轻伤Y人/年 |

**ROI速算公式：**
```
ROI =[(经济效益 + 社会效益货币化) / 总投入成本] × 100%
安全效益单独列出（不与金钱混算，但突出显示）
```

**ROI速算示例——AI视频事件检测：**

| 项目 | 金额（万元/年） |
|------|------|
| **投入成本** | |
| AI视频分析平台（软件+部署） | 50（一次性） |
| GPU服务器（2台） | 30（一次性，折旧5年=6万/年） |
| 运维人力（0.5人） | 10 |
| 年度许可费 | 15 |
| **年化总投入** | 81（首年）/ 25（后续年） |
| | |
| **经济效益** | |
| 减少视频巡查人员（3人） | 45 |
| 缩短事件检测时间→降低二次事故 | 30 |
| **社会效益** | |
| 拥堵减少→时间价值 | 50 |
| 碳减排 | 5 |
| **安全效益** | |
| 预计减少因延迟发现导致的死亡 | 1-2人/年（不货币化，但重点标注） |
| | |
| **ROI（首年）** | (45+30+50+5)/81 × 100% = 160% |
| **ROI（后续年）** | (45+30+50+5)/25 × 100% = 520% |

### 4.2 实施成本估算

**成本估算框架：**

| 成本类别 | 明细 | 估算方法 | 注意事项 |
|----------|------|----------|----------|
| 硬件 | GPU服务器、摄像头、边缘计算盒子 | 供应商询价+行业benchmark | GPU服务器预留30%性能冗余 |
| 软件 | AI平台许可、数据库、中间件 | 询价+POC后确认 | 关注并发许可 vs 按量计费差异 |
| 数据工程 | 数据清洗、标注、管道 | 内外部人力×单价 | 标注成本往往是预算黑洞——至少预留30%buffer |
| 模型开发 | 算法研发、训练、调优 | 算法工程师人月×单价 | 预训练模型迁移学习可大幅降低（比从零训练省50-80%） |
| 集成 | 与现有系统对接 | 接口开发人天×单价 | 每个系统对接预算5-10人天，系统越多成本越高 |
| 培训 | 用户培训、操作手册 | 讲天数×单价+材料 | 至少分管理员和操作员两级培训 |
| 运维 | 监控、升级、技术支持 | 研发成本的15-20%/年 | 首年通常包含在项目款中 |
| 风险储备 | 不可预见费 | 总预算的10-20% | AI项目的风险储备应比传统IT高 |

## 第五阶段：路线图与建议（第7-8周）

### 5.1 分阶段逻辑

**四阶段推进模型：**

| 阶段 | 时间 | 场景数量 | 选入标准 |
|------|------|----------|----------|
| Phase 1：快速取胜 | 0-6个月 | 2-3个 | RICE++排名前5 + E>6（低投入）+ C>7（高信心） |
| Phase 2：能力构建 | 6-12个月 | 3-4个 | RICE++排名前10 + 需要一定的数据/平台准备 |
| Phase 3：规模扩展 | 12-24个月 | 4-6个 | 在Phase 1+2成功基础上，将AI推广到更多场景和区域 |
| Phase 4：引领创新 | 24-36个月 | 2-3个 | RICE++排名可能靠后但战略意义重大（如低空AI、自动驾驶标杆区） |

### 5.2 快速取胜（Quick Win）识别

**Quick Win四条件：**
1. **数据就绪**（数据就绪度评分>15）——不需要大规模数据工程建设
2. **低投入**（E>6，即预估<50人月投入）——不挑战预算上限
3. **高可见性**（R>5，影响面较广）——做出来决策者能看见、能讲
4. **短周期**（3个月内能上线MVP）——快速验证、快速出信心

**典型Quick Win——交通AI场景示例：**
- AI视频事件检测（在现有视频系统上加装AI分析模块）
- AI舆情智能分类（对接12345/12328热线数据）
- AI道路病害自动识别（在已有的养护巡检车上加装智能采集终端）
- AI信号配时离线方案优化（不实时控制，只推荐方案给工程师确认）

## 一、项目背景

### 1.1 行业背景
| 项目 | 内容 |
|------|------|
| 多式联运现状 | 中国多式联运量占全社会货运量约____%，远低于发达国家（30-50%），发展空间巨大 |
| 一单制推进 | 国家持续推进多式联运"一单制"，统一运单标准/电子运单/区块链提单 |
| 行业支持 | 《推进多式联运发展优化调整运输结构工作方案》《"近期五年规划"现代综合交通运输体系发展规划》 |
| 技术成熟 | 物联网/区块链/大数据/AI技术为多式联运信息平台提供了技术基础 |

### 1.2 核心痛点
| 痛点 | 表现 | 影响 |
|------|------|------|
| 信息割裂 | 铁路/港口/航运/公路各系统独立，信息不互通 | 无法全程追踪货物 |
| 单证繁多 | 每一段运输都有独立的运单/提单/仓单，格式不统一 | 效率低、易出错 |
| 多次结算 | 分段结算，对账繁琐，资金占用大 | 财务成本高 |
| 协调困难 | 换装/转运/仓储等环节涉及多方，协调成本高 | 转运时间长/不可靠 |
| 缺少平台 | 没有统一的信息平台整合多方资源和信息 | 无法优化全局效率 |

## 二、需求分析

### 2.1 用户分析
| 用户角色 | 核心需求 | 痛点 | 功能需求优先级 |
|----------|----------|------|:------------:|
| 货主/托运人 | 一单到底/全程追踪/最低成本/最快时效 | 多方沟通/信息不透明/追责困难 | 高 |
| 货代/物流企业 | 运力匹配/路线优化/统一结算/客户管理 | 信息不对称/协调复杂/对账繁琐 | 高 |
| 铁路公司 | 货源组织/运力调度/数据对接 | 铁路系统封闭/数据共享难 | 中高 |
| 港口/码头 | 船舶到港/堆场/装卸/转运衔接 | 多式衔接信息不畅通 | 中 |
| 航运公司 | 舱位匹配/箱管/换装协调 | 内陆段运输信息缺失 | 中 |
| 卡车/车队 | 货源/回程货/电子运单/快速结算 | 货源不稳定/空驶率高/结算慢 | 高 |
| 海关/检验检疫 | 通关/检验/监管 | 单证不统一/信息获取困难 | 中 |
| 金融/保险 | 贸易验真/货物追踪/风险控制 | 信息真实性验证/货物状态不透明 | 中 |

```
货主发货 ──→ 多式联运平台 ──→ 路线规划（铁/公/水/空组合）
    │                              │

    │                              │
    ├─ 电子运单（一单制）         │
    │                              │
    ├─ 铁路段（95306对接）────────┤
    ├─ 水路段（港口TOS对接）──────┤
    ├─ 公路段（TMS对接）─────────┤
    ├─ 航空段（货站系统对接）─────┤
    │                              │
    ├─ 换装/转运节点（IoT+RFID）  │
    │                              │
    ├─ 货物全程追踪 ─────────────┘
    │
    ├─ 签收（POD电子回单）
    │
    └─ 统一结算→多方分账
```

## 四、核心功能详设

### 4.1 一单制电子运单（一单制）

#### 4.1.1 一单制运单要素
| 要素 | 内容 | 标准 |
|------|------|------|
| 运单号 | 唯一编码（平台+日期+序号） | 平台标准 |
| 托运人/收货人 | 企业名称/统一社会信用代码/联系人/联系方式 | |
| 货物品名/数量/重量/体积 | 按HS编码/危险品UN编号 | HS/UN标准 |
| 包装类型/件数 | | |
| 起运地/目的地 | 省市县+详细地址+GPS坐标 | |
| 运输路线 | 铁→水→公 / 铁→公 / 等，含各段承运人和节点 | |
| 运费与结算 | 全程运费/各段内部分账/结算方式/账期 | |
| 保险 | 保险金额/保险公司/保单号 | |
| 单证要求 | 报关/报检/许可证等随附单证 | |
| 时间节点 | 预计/实际的取货/到达/换装/交货时间 | |
| 责任划分 | 各段运输责任/赔偿标准 | |

#### 4.1.2 电子运单流转
```
创建运单 ──→ 各段承运人确认 ──→ 电子签章/签名
    │
    └──→ 运单上链（区块哈希存证）
    └──→ 各段运输过程中状态更新（IoT/API）
    └──→ 签收（电子POD：签名+照片+GPS+时间戳）
    └──→ 运单归档+存证（至少保留____年）
```

#### 4.1.3 区块链电子运单
| 功能 | 说明 | 技术 |
|------|------|------|
| 运单存证 | 运单创建/变更/签收关键节点哈希上链 | 智能合约 |
| 多方共识 | 托运人/承运人/收货人/监管方多方节点共识 | 联盟链 |
| 不可篡改 | 运单内容一旦确认不可单方篡改 | 区块链特性 |
| 电子提单 | 替代纸质提单（海运+多式联运） | 电子提单+物权转移 |

|----------|----------|----------|:--------:|

#### 4.3.2 智能匹配
| 匹配场景 | 方法 | 说明 |
|----------|------|------|
| 货运匹配 | 货源属性→运力筛选（车型/线路/时间/价格/评价）→推荐TOP-N | AI推荐+人工确认 |
| 回程货匹配 | 车辆/箱到目的地→自动匹配回程货源→推送司机/车队 | 降低空驶率 |
| 多段组合匹配 | 铁→水→公多段运力自动组合→报价 | 一站式解决方案 |
| 紧急运力 | 临时/紧急运力需求→广播至匹配运力方→竞价/抢单 | 弹性运力 |

#### 4.3.3 交易模式
| 模式 | 说明 | 适用场景 |
|------|------|----------|
| 一口价 | 平台根据路线/货量/市场行情给出固定报价 | 标准运输 |
| 竞价 | 货主发布需求→多家承运方报价→货主选择 | 大宗/非标准 |
| 抢单 | 平台发布货源→符合条件的司机/车队抢单 | 公路零担/整车 |
| 合同价 | 签约客户按合同约定价格执行 | 大客户/长期合作 |

#### 4.4.2 异常预警
| 异常类型 | 检测方法 | 预警方式 | 处理流程 |

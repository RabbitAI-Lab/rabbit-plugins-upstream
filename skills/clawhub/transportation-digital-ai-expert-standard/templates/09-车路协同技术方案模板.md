## 3. 设计原则与标准遵从

### 3.1 设计原则

| 原则 | 说明 |
|------|------|
| **安全第一** | V2X系统以提升交通安全为首要目标，不因系统引入而增加新的安全风险 |
| **标准先行** | 严格遵循国家和行业V2X标准，确保与不同品牌车辆、设备的互操作性 |
| **平滑演进** | 支持从LTE-V2X向5G-V2X(NR-V2X)平滑演进、从辅助预警向协同控制的演进 |
| **云边协同** | 路侧边缘计算+中心云控的协同架构，实现低时延与全局优化 |
| **安全可信** | 基于PKI/SCMS体系，实现车-路-云通信的认证、加密和完整性保护 |
| **开放兼容** | 支持不同车辆品牌、不同终端厂商、不同路侧设备厂商的互联互通 |
| **经济实用** | 充分利用既有杆件/网络/信号机等基础设施，避免大拆大建 |

### 4.2 V2X通信架构

| 通信方式 | 接口 | 频段 | 时延 | 带宽 | 应用场景 |
|----------|------|------|------|------|----------|
| **LTE-V2X PC5** | 直连通信 | 5.9 GHz | < 20ms | 中 | V2V/V2I安全类消息（BSM/RSI/RSM/MAP/SPAT） |
| **LTE-Uu / 5G Uu** | 蜂窝通信 | 运营商频段 | < 100ms | 高 | V2N大带宽类应用（地图更新、视频下载） |
| **5G NR-V2X** | 直连+蜂窝 | 5.9 GHz + 运营商 | < 5ms | 高 | 未来高级自动驾驶应用 |

### 4.3 技术路线选择

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 通信制式 | [LTE-V2X（C-V2X PC5）为主，5G Uu为辅] | [成熟度、产业链支持、行业规范导向] |
| 路侧感知方案 | [摄像头+毫米波雷达融合] | [性价比最优，满足当前应用需求] |
| 边缘计算 | [部署MEC] | [满足<20ms时延要求] |
| 安全体系 | [国家标准密码SM2/SM3/SM4 + C-V2X SCMS] | [满足国内安全合规要求] |

## 8. 应用场景设计

### 8.1 场景分类（Day I / Day II）

| 阶段 | 典型场景 | 说明 |
|------|----------|------|
| **Day I（近期）** | 安全预警类+效率类 | 辅助驾驶，为驾驶员提供预警信息，不控制车辆 |
| **Day II（远期）** | 协同控制类 | 感知共享、意图共享、协同决策，可实现部分控制功能 |

### 8.2 Day I 场景清单

#### 8.2.1 安全类场景

| 编号 | 场景名称 | 场景描述 | 触发条件 | 实现方式 | 预期效果 |
|------|----------|----------|----------|----------|----------|

## 9. 数据流与接口设计

### 9.1 核心V2X消息集

| 消息类型 | 简称 | 发送方 | 发送频率 | 主要内容 |
|----------|------|--------|----------|----------|
| **Basic Safety Message** | BSM | OBU | 10 Hz | 车辆位置、速度、航向、加速度、制动状态、车辆尺寸 |
| **Road Side Information** | RSI | RSU | 1-5 Hz | 路侧事件信息：交通事故、施工、拥堵、天气、标志标牌 |
| **Road Side Safety Message** | RSM | RSU | 10 Hz | 路侧感知到的交通参与者信息（车辆、行人、非机动车） |
| **MAP Message** | MAP | RSU | 1 Hz | 路口/路段拓扑地图（车道级） |
| **Signal Phase and Timing** | SPAT | RSU（从信号机获取） | 10 Hz | 当前信号灯相位和剩余时间 |
| **Traveler Information Msg** | TIM | RSU | 按需 | 出行服务信息（如停车位、充电桩） |

### 9.2 数据流向

```
OBU ──BSM──► RSU ──BSM转发+RSM生成──► 周边OBU  （V2V via RSU）
OBU ──VehData──► MEC ──处理结果──► RSU ──消息──► OBU
RSU ──RSI/RSM/MAP/SPAT──► OBU  （I2V）
摄像头/雷达 ──原始流──► MEC ──感知结果──► RSU ──RSM──► OBU
信号机 ──SPAT──► RSU ──SPAT──► OBU
RSU/OBU/MEC ──状态+日志──► 云控平台  （管理面）
云控平台 ──全局策略──► MEC/RSU  （决策下发）
OBU/RSU ──BSM/感知数据──► 云控平台  （数据面，用于全局分析）
```

### 9.3 接口规范

| 接口 | 协议 | 说明 |
|------|------|------|
| RSU ↔ OBU (PC5) | LTE-V2X PC5 / 3GPP | 直连通信 |
| RSU ↔ MEC | TCP/IP (光纤) | 原始数据上传/决策下发 |
| RSU/OBU ↔ 云控平台 (Uu) | HTTPS/MQTT | 管理+数据 |
| MEC ↔ 云控平台 | HTTPS/gRPC | 管理+数据+决策 |
| RSU ↔ 信号机 | [NTCIP / GB/T 20999 / 私有协议（需开发驱动）] | 信号联动 |
| OBU ↔ 车辆CAN | CAN 2.0B / CAN-FD | 车辆信息获取 |

## 10. 安全体系（PKI/SCMS）

### 10.1 V2X安全架构

V2X安全通信基于 **PKI（公钥基础设施）** 体系，采用 **SCMS（安全证书管理系统）** 实现车辆/路侧设备的身份认证和消息安全。

```
┌──────────────────────────────────────────────┐
│              根CA（Root CA）                   │
│            (国家/行业 V2X根CA)                  │
└──────────────────┬───────────────────────────┘
                   │
    ┌──────────────┼──────────────┐
    ▼              ▼              ▼
┌─────────┐  ┌─────────┐  ┌─────────┐
│中间CA     │  │注册CA    │  │假名CA    │
│(ECA)     │  │(ECA)    │  │(PCA)    │
└────┬────┘  └────┬────┘  └────┬────┘
     │            │            │
     ▼            ▼            ▼
┌─────────┐  ┌─────────┐  ┌─────────┐
│注册证书   │  │注册证书   │  │假名证书   │
│(长期身份) │  │(长期身份) │  │(短期匿名) │
└─────────┘  └─────────┘  └─────────┘
    OBU         RSU          OBU
 (注册认证)   (身份认证)   (广播签名)
```

### 10.2 安全运行框架

| 安全服务 | 实现方式 |
|----------|----------|
| **身份认证** | 基于数字证书的身份验证 |
| **消息签名** | 使用私钥对发送的每条V2X消息进行数字签名（ECDSA/SM2） |
| **消息完整性** | 通过数字签名保证消息未被篡改 |
| **隐私保护** | 假名证书运行框架——车辆定期更换证书，不暴露长期身份 |
| **撤销管理** | CRL（证书吊销列表）定期更新，吊销违规/被盗设备证书 |
| **加密算法** | 国际：ECDSA-256 + AES-128-CCM；国家标准密码：SM2 + SM3 + SM4 |

### 10.3 安全实施策略

| 阶段 | 策略 |
|------|------|
| **建设期** | 接入国家/行业C-V2X安全根CA体系（如IMT-2020推进组C-V2X工作组SCMS体系） |
| **试运营期** | 使用测试证书，验证安全通信功能 |
| **正式运营期** | 切换至正式证书体系，建立本地的证书管理流程 |

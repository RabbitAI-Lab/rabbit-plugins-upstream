# 案例01：地级市智能交通管理平台从0到1

## 案例概览

| 维度 | 详情 |
|------|------|
| 城市类型 | 三线城市（中部地区） |
| 人口规模 | 约300万（城区人口120万） |
| 信号灯路口 | 312个 |
| 机动车保有量 | 68万辆 |
| 原有交管系统 | 仅有基础SCATS信号控制系统，无智能交通管理平台 |
| 总投资 | 8500万元（三年） |
| 建设周期 | 2021-2023（三年分三期） |
| 核心目标 | 建成城市级智能交通管理平台，实现信号智能优化、交通态势感知、应急指挥联动 |

---

## 一、背景与痛点

### 1.1 城市交通现状

江城市（化名）位于中部省份，是一座典型的地级市。2020年底，城区人口约120万，机动车保有量68万辆且以年均8%的速度增长。城区共有312个信号控制路口，其中约40%（128个）路口仍为单点定周期控制，无法联网调控；剩余184个路口接入SCATS系统，但多数处于半自动控制状态。

### 1.2 核心痛点

**城市管理者头疼的三件事：**

1. **高峰期全城拥堵常态化**：早晚高峰主城区平均车速仅18km/h，核心商圈路段不足10km/h。市民通过12345热线投诉交通问题月均超过300件。

2. **交通事故处置效率低**：事故从接警到现场处置平均需要28分钟，二次事故风险高。交警支队指挥中心仅靠对讲机调度，缺乏可视化指挥手段。

3. **交管数据孤岛严重**：交警、交通归口部门、城管、自然资源局各自建有信息系统，但数据互不联通。交警内部信号、卡口、电子警察、指挥调度等系统也彼此孤立。

### 1.3 转折点

2020年10月，城市决策层听取交通拥堵治理专项汇报，明确指示："要借鉴杭州、深圳等先进城市经验，用数字化手段解决交通问题。"随即成立由城市分管负责人任组长的智慧交通建设决策小组，启动智能交通管理平台可行性研究。

## 二、T-DMM诊断与蓝图设计

### 2.1 T-DMM成熟度诊断

项目委托第三方团队运用交通数字化成熟度模型（T-DMM）对江城市进行全面诊断。诊断结果如下：

| 评估维度 | 得分（满分5） | 等级 | 关键发现 |
|----------|--------------|------|----------|
| 感知体系 | 1.8 | L1 | 前端设备覆盖率不足40%，视频设备智能分析率<5% |
| 数据治理 | 1.2 | L1 | 无统一数据标准，数据质量差，缺失率超30% |
| 算法能力 | 0.5 | L1 | 无AI算法团队，信号配时依赖人工经验 |
| 业务应用 | 1.5 | L1 | 仅有基础信号控制、违法抓拍，智能化程度低 |
| 基础设施 | 2.0 | L2 | 交警机房条件尚可，但无云计算资源 |
| 组织能力 | 1.0 | L1 | 无专职数据/技术团队，外包维保为主 |
| **综合等级** | **1.3** | **L1-L2** | 处于数字化起步阶段 |

### 2.2 三年蓝图规划

基于T-DMM诊断结果，项目组制定了三年"三步走"路线图：

**第一阶段（2021年）：夯基础**
- 50个重点路口信号联网改造 + AI信号优化试点验证
- 交警数据中心云化升级（私有云）
- 统一数据中台建设（汇聚交警、交通归口部门、公交数据）
- 交通态势感知大屏（综合交通运行协调中心 1.0）
- 预算：2800万元

**第二阶段（2022年）：建平台**
- 剩余262个路口信号联网 + 全域AI信号优化覆盖
- 智能交通管理平台核心平台（全域感知、分析研判、信号优化、诱导发布）
- 重点车辆监管系统（两客一危、渣土车）
- 公众出行信息服务平台
- 预算：3500万元

**第三阶段（2023年）：优运营**
- 全域交通数字孪生
- AI信号优化持续迭代（深度强化学习模型）
- 应急指挥联动（交管/消防/医疗）
- 碳排放监测与绿色交通分析
- 运维运营体系固化
- 预算：2200万元

## 三、实施过程

### 3.1 第一步：信号机联网改造

**技术选择**

在信号机选型上，项目组面临关键决策：继续使用SCATS系统还是更换本地化系统。经过多方对比，最终选择了本地化信号机+统一信控平台方案，原因：
- SCATS系统封闭，API接口有限，难以实现AI优化闭环
- 本地化方案支持《GA/T 1049》标准协议，可与多品牌设备互通
- 本地化信号机成本仅为进口的40%
- 本地化服务响应快，故障30分钟到场

最终选定海信网络科技作为信号系统总集成商，50个路口全部更换为智能信号机，支持车检器、视频、雷达等多源感知接入。

**实施困难与应对**

- **困难1**：施工期间交通组织。50个路口同时开挖施工，对交通影响大。
  - **解决**：采用"夜间施工+白天恢复"模式，单个路口完工时间控制在3天内；同时安排临时移动信号灯。

- **困难2**：部分路口基础设施不达要求。12个路口无稳定供电、8个路口无光纤通信条件。
  - **解决**：协调供电局增容、铺设4G/5G无线通信模块作为光纤的备份。

### 3.2 第二步：AI信号优化

**算法方案**

AI信号优化采用"三层优化"架构：
1. **单点自适应**：基于实时交通流量的绿灯时间动态调整
2. **干线协调**：基于深度强化学习的绿波带优化
3. **区域协同**：基于多智能体强化学习的区域信号协同

**关键创新**

区别于传统信号优化方案，本项目有两个创新点：
1. **多源数据融合配时**：融合卡口数据、电子警察数据、浮动车GPS数据、互联网地图数据（高德API），构建全样本交通OD
2. **人机协同闭环**：AI输出配时方案后，由经验丰富的交警审核确认，确认后自动下发执行，形成"AI生成-人工审核-自动执行-效果评估-模型迭代"的闭环

**效果**

试点验证50个路口运行6个月后：
- 路口平均延误下降22%
- 绿波带路段行程时间缩短18%
- 高峰通行量提升12%

### 3.3 第三步：综合交通运行协调中心平台建设

综合交通运行协调中心（交通运行监测与指挥中心）平台是智能交通管理平台的"可视化窗口"，整合了交警、交通归口部门、公交公司、出租车、网约车等多源数据。平台包含六大功能模块：

1. **态势感知**：实时车流、人流热力图，拥堵指数，警情分布
2. **信控优化**：信号配时方案管理、效果评估、绿波可视化
3. **应急指挥**：事故自动检测、警力调度、绿波护航
4. **重点车辆**：两客一危、校车、渣土车实时监控与轨迹回溯
5. **信息发布**：诱导屏、APP、短信多渠道信息发布
6. **决策分析**：交通运行周报/月报自动生成、拥堵成因分析

## 五、经验教训

### 5.1 成功要素

1. **顶层高度重视**：城市决策者亲自挂帅，分管负责人每月调度，跨部门协调效率高
2. **先诊断后建设**：T-DMM诊断客观评估了现状，避免了"盲目上项目"
3. **小步快跑策略**：先做50个路口试点验证验证效果，再用数据说服全市推广
4. **数据驱动决策**：所有优化效果用数据说话，定期向市决策者汇报成效看板
5. **生态合作模式**：核心平台自主技术可控，AI算法与高校实验室合作，运维外包本地企业

### 5.2 踩过的坑

1. **数据质量被低估**：项目初期严重低估了数据治理的工作量。卡口数据车牌识别准确率仅82%、GPS轨迹漂移严重，花了近4个月才将数据质量提升到可用水平。
   - **教训**：数据治理的预算和时间应占总项目的25-30%，不可压缩。

2. **部门壁垒比技术更难**：交通归口部门最初不愿共享公交和出租车数据（担心暴露运营问题），经过近两个月的协调和分管负责人亲自推动才达成协议。
   - **教训**：数据共享不是技术问题，是制度与运行框架问题。需要建立市级的交通数据管理办法，明确"谁提供、谁负责、谁使用、谁受益"。

3. **AI不是"万能药"**：初版AI信号优化模型在雨天、节假日等特殊场景效果很差，因为训练数据缺乏这些场景的覆盖。
   - **教训**：AI模型需要持续迭代，至少需要1年以上的数据积累才能覆盖各种场景。初期应由AI辅助+人工决策，逐步过渡到AI自主决策。

4. **运维被遗忘**：项目建设期投入充足，但运维预算不足。2023年项目验收后，运维团队从15人缩减到5人，系统故障率明显上升。
   - **教训**：项目启动时就应明确3-5年的运维预算（通常为建设预算的15-20%/年），并将其编入资金方经常性支出。

### 5.3 给同类型城市的建议

1. **不要追求一步到位**：三线城市没必要一步对标"杭州城市大脑"，先解决最痛的信号优化和事故处置问题
2. **优先选择本地化方案**：性价比高、服务好、不受国际形势影响
3. **重视人才留用**：配备至少3-5名在编技术人员，而非全部外包
4. **建立数据共享运行框架**：在项目启动前就通过公共部门发文明确数据共享要求
5. **预留迭代空间**：技术发展快，系统架构应保持开放性，预留AI大模型、车路协同等未来能力的接入空间

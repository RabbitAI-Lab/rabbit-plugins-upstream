## 二、适用场景

本工作流适用于智慧交通项目在选定供应商后的合同谈判和签约阶段，覆盖从策略制定到合同归档的全流程。

## 三、前置条件与输入

| 输入项 | 来源 |
|-------|------|
| 供应商评估推荐报告 | phase-04-02 |
| SOW和技术规格 | phase-04-01 |
| RFP商务条款和报价 | phase-04-01 |
| 公司合同模板和签约行业规范 | 法务/财务 |
| 相关法律法规 | 民法典/技术采购法/采购法 |

## 四、详细步骤说明

---

### 步骤1：谈判策略制定

**目标**：基于项目特点和供应商情况，制定系统性的谈判策略。

**输入**：推荐报告、SOW、RFP应答
**输出**：谈判策略文档、谈判要点清单

**操作指南**：

**1.1 谈判环境分析**

```
谈判前的五力分析:

 供应商的议价能力      供应商的谈判动力
 ┌──────────────┐    ┌──────────────┐
 │·是否唯一来源？ │    │·项目对其战略意义│
 │·替代供应商难度 │    │·现有业务饱和度  │
 │·供应商是否急需 │    │·竞争激烈程度    │
 └──────┬───────┘    └──────┬───────┘
        │                   │
        └─────────┬─────────┘
                  │
         ┌────────┴────────┐
         │   谈判策略制定    │
         └────────┬────────┘
                  │
  ┌───────────────┼───────────────┐
  │               │               │
  v               v               v
我方谈判筹码    谈判目标层级     退出策略
 ·项目吸引力     ·底线/争取/理想   ·备选供应商
 ·预算弹性       ·技术/商务/法律   ·内部自研可能
 ·时间压力       ·短期/长期利益    ·分阶段合作
```

**1.2 谈判目标设定（三线模型）**

| 条款类别 | 底线(Must Have) | 争取线(Want) | 理想线(Nice to Have) |
|---------|----------------|-------------|---------------------|
| 价格 | 不超过预算上限 | 争取8-10%折扣 | 争取15%以上折扣 |
| 付款 | 里程碑挂钩，验收后至少留10% | 验收后留15-20% | 验收后留30% |
| 知识产权 | 客户方拥有项目定制开发部分 | 客户方拥有所有开发成果 | 源码全交付 |
| 工期 | 不超过3个月缓冲 | 争取提前1个月 | 争取提前2个月 |
| 质保 | 不少于1年免费运维 | 争取2年免费 | 争取3年免费 |

**1.3 谈判团队配置**

```
谈判团队角色:

┌─────────────────────────────────────────────────┐
│ 首席谈判代表（销售VP/项目总监）                    │
│ - 把控谈判节奏、做出战略让步                       │
├─────────────────────────────────────────────────┤
│ 技术谈判（技术负责人）                             │
│ - 技术方案的"解释权"、技术边界的坚持               │
├─────────────────────────────────────────────────┤
│ 商务谈判（采购/商务经理）                          │
│ - 价格交锋、付款条件、服务条款                     │
├─────────────────────────────────────────────────┤
│ 法律支持（法务/外部律师）                          │
│ - 法律条款审核、合规风险把控                       │
├─────────────────────────────────────────────────┤
│ 记录员（项目经理）                                │
│ - 全程记录、会谈纪要、条款追踪                     │
└─────────────────────────────────────────────────┘
```

### 步骤2：关键条款分析

**目标**：全面识别和分析合同中的关键条款和潜在风险点。

**输入**：RFP商务条款、供应商初步答复
**输出**：关键条款分析报告、风险条款清单

**操作指南**：

**2.1 交通行业合同关键条款清单**

| 条款类型 | 关键条款 | 关注重点 |
|---------|---------|---------|
| 范围条款 | 工作范围(SOW) | 边界清晰，避免模糊地带 |
| 交付条款 | 交付成果清单+验收标准 | 每个交付成果可量化、可测试 |
| 进度条款 | 里程碑计划+延期罚则 | 里程碑定义清晰、罚则有力 |
| 价格条款 | 总价/单价、含税/不含税 | 价格锁定，变更定价运行框架 |
| 付款条款 | 付款节点、比例、条件 | 与里程碑严格挂钩 |
| 知识产权 | 源码/文档/数据归属 | 项目定制开发的IP归属客户方 |
| 保密条款 | 保密范围、期限、违约责任 | 覆盖双方数据和商业秘密 |
| 质保条款 | 质保期限、响应SLA、修复SLA | 具体指标而非原则性描述 |
| 违约条款 | 违约情形、赔偿上限、终止 | 双方对等但不失保护 |
| 争议解决 | 适用法律、管辖、仲裁 | 本地化管辖 |
| 变更条款 | 变更流程、定价、审批 | 公平透明 |

**2.2 技术与交付条款深度分析**

```
技术/交付条款分析要点:

[交付成果定义]
□ 是否每个交付成果都有明确的格式、内容和质量标准？
□ 源码交付范围是否明确（全部源码/部分/编译后产品）？
□ 文档清单是否完整（设计/运维/用户/接口/部署）？

[验收标准]
□ 验收条件是否可客观测试？
□ 验收测试环境和数据由谁准备？
□ 验收不通过的补救运行框架是什么？
□ 验收签字程序和时间要求？

[性能指标]
□ 响应时间、吞吐量、并发数是否量化？
□ 性能测试的方法和工具是否明确？
□ 性能不达标的后果是什么？

[集成责任]
□ 与现有系统的集成责任归属是否明确？
□ 第三方系统接口的配合责任？
□ 联调测试的时间和参与方？
```

### 步骤3：合同草案撰写

**目标**：基于双方初步共识，撰写合同草案。

**输入**：SOW、商务条款、谈判策略
**输出**：合同草案V1.0

**操作指南**：

**3.1 智慧交通项目合同结构**

```
智慧交通项目合同结构:

第一部分: 合同正文
  1. 定义与释义
  2. 合同标的与范围（引用SOW附件）
  3. 合同价格与支付
  4. 交付与验收
  5. 项目组织与管理
  6. 知识产权
  7. 保密义务
  8. 质量保证与售后服务
  9. 违约责任
  10. 不可抗力
  11. 合同变更与解除
  12. 争议解决
  13. 通告与送达
  14. 合同生效与期限

第二部分: 附件
  附件一: 工作说明书(SOW)
  附件二: 技术需求规格书
  附件三: 交付成果清单
  附件四: 项目计划与里程碑
  附件五: 验收标准与测试方案
  附件六: 报价明细表
  附件七: 项目团队人员名单
  附件八: 运维服务SLA
  附件九: 保密协议(NDA)
  附件十: 信息安全承诺书
```

**3.2 智能合约条款**

在智慧交通项目中，建议增加以下特色条款：
- **AI模型性能保证条款**：AI模型的准确率/召回率等指标的保证和长期维护
- **数据安全特别条款**：符合数据安全法规个人信息保护法规的数据处理义务
- **国产化合规条款**：系统在国产化环境下的兼容性承诺
- **等保合规条款**：配合等保测评和整改的义务
- **交通行业特殊条款**：重保期间（节假日、重大活动）的特殊保障承诺

### 步骤4：正式谈判与博弈

**目标**：与供应商进行正式合同谈判，达成最优条款。

**输入**：合同草案、谈判策略
**输出**：谈判纪要、条款修订记录

**操作指南**：

**4.1 谈判议程设计**

```
谈判会议安排建议:

第1轮: 商务层面（半天）
  - 价格和付款条件
  - 交付周期和里程碑
  - 质保和SLA
  - 目标: 锁定核心商务条款

第2轮: 技术层面（半天）
  - SOW边界确认
  - 技术方案的最终确认
  - 交付成果和验收标准
  - 目标: 锁定技术方案和范围

第3轮: 法律层面（半天）
  - 知识产权
  - 违约责任
  - 保密和合规
  - 目标: 锁定法律条款

第4轮: 终局谈判（半天）
  - 剩余分歧的最终解决
  - 全面确认
  - 目标: 全部条款达成一致
```

**4.2 谈判技巧工具箱**

| 技巧 | 场景 | 话术示例 |
|------|------|---------|
| 锚定效应 | 开局报价 | "基于我们的市场调研，同类型项目的价格区间在..." |
| 让步交换 | 要求降价 | "如果价格降10%，我们可以考虑提前付款节点" |
| 沉默施压 | 对方报价过高 | （保持沉默，等待对方解释或调整） |
| 高点让步 | 打破僵局 | "如果这个条款你能接受，我们可以在XX上让步" |
| 小点收集 | 收尾阶段 | "大局已定，这几处小调整你应该不会反对吧？" |
| 时间压力 | 拖延战术 | "我们下周一需要向决策者汇报最终结果" |

**4.3 交通行业合同特殊谈判点**

| 议题 | 我方立场 | 常见分歧 | 谈判策略 |
|------|---------|---------|---------|
| AI模型所有权 | 基于客户方数据训练的模型归客户方 | 供应商想保留模型 | 区分基础模型(供应商)和定制模型(客户方) |
| 数据归属 | 项目实施中产生的全部数据归客户方 | 供应商想用于其他用途 | 在合同中明确禁止数据他用 |
| 国产化保证 | 承诺在国产化环境运行 | 供应商推脱不在控制范围 | 明确兼容性测试范围和标准 |
| 运维SLA | 15分钟响应/2小时到场 | 供应商承诺2小时响应 | 提出行业对标数据，分级SLA |
| 源码托管 | 源码第三方托管(源码托管服务) | 供应商不愿交出源码 | 约定供应商特定情形（破产/停业）下源码释放 |

### 步骤5：法律审查与合规

**目标**：确保合同条款的法律合规性，防范法律风险。

**输入**：谈判后修订的合同草案
**输出**：法律审查意见书、修改后合同

**操作指南**：

**5.1 法律审查清单**

| 审查维度 | 检查要点 | 审查人 |
|---------|---------|:---:|
| 主体资格 | 签约主体是否有效存续、资质是否齐全 | 法务 |
| 合同效力 | 是否存在无效/可撤销情形 | 法务 |
| 权利义务 | 双方权利义务是否对等（不过度偏颇） | 法务 |
| 知识产权 | IP归属和使用许可是否清晰 | 法务+技术 |
| 违约责任 | 违约条款是否明确、是否过重/过轻 | 法务 |
| 争议解决 | 管辖/仲裁条款是否有利于我方 | 法务 |
| 合规审查 | 是否符合采购法、技术采购法 | 法务 |
| 数据合规 | 是否符合数据安全法、个人信息保护法 | 法务+安全 |
| 国产化合规 | 是否满足国产化替代行业规范要求 | 技术 |

**5.2 常见法律风险红灯**

- 合同金额超过供应商注册资本一定倍数（履约能力存疑）
- 违约金上限设置过高或过低（>30%或<5%合同额）
- 无限责任条款（软件行业通常约定赔偿上限为合同额）
- 单方解除权的过度限制
- 知识产权"Creative Commons"式宽松授权（客户方成果流失）
- 争议管辖在供应商所在地

---

### 步骤6：合同定稿与内部审批

**目标**：完成合同最终版本的定稿，通过内部审批。

**输入**：法律审查后的合同
**输出**：合同终稿、内部审批单

**操作指南**：

**6.1 内部确认流程**

```
典型合同确认流程:

项目经理发起 → 技术负责人审批 → 商务负责人审批 → 法务审批 → 财务审批 → VP/总经理审批

各审批人聚焦:
  技术负责人: SOW范围、技术方案、验收标准
  商务负责人: 价格、付款、商务条款合理性
  法务: 法律风险、合规性
  财务: 预算符合度、付款节奏、发票要求
  VP/总经理: 战略符合度、整体风险判断
```

**6.2 合同版本管理**

- 使用版本号标记每次修订（V1.0 → V1.1 → V2.0（正式签署版））
- 保留所有历史版本和修改批注
- 最终版本使用"清洁版"（无批注痕迹）供签署

---

### 步骤7：签约执行与归档

**目标**：完成合同的正式签署和归档。

**输入**：合同终稿
**输出**：签署完成的合同、合同归档记录

**操作指南**：

**7.1 签约执行清单**

- [ ] 双方签约人授权书核实（签约人是否有合法授权）
- [ ] 合同文本一致性检查（双方手中的文本完全一致）
- [ ] 合同盖章（公章/合同专用章）
- [ ] 骑缝章（多页合同）
- [ ] 签署日期填写
- [ ] 合同正副本分配（通常正本2份，双方各1份；副本按需）
- [ ] 合同扫描电子版归档
- [ ] 合同原件归档（财务+档案室）

**7.2 交通行业特殊签约注意**

- 支付条款是否需要向资金方归口部门备案
- 超预算项目是否完成了追加预算审核
- 合同信息公开要求（采购项目需在中国采购网公告）
- 选定通知书与合同的一致性检查

---

### 步骤8：合同管理移交

**目标**：将签署的合同信息移交给项目管理团队，确保履约过程中有据可依。

**输入**：签署合同、相关附件
**输出**：合同摘要、合同交底会纪要

**操作指南**：

**8.1 合同信息摘要（给项目经理）**

```
合同信息摘要(一页纸):

项目名称: _________
合同编号: _________
合同总金额: _________ 万元
合同生效日: _________
合同到期日: _________

关键里程碑及付款:
  M1: _________  付款: _____万元 (___%)
  M2: _________  付款: _____万元 (___%)
  M3: _________  付款: _____万元 (___%)
  ...

关键约束:
  ·工期: 总工期___天，关键里程碑不得延期超过___天
  ·质量: 验收标准详见附件五
  ·人员: 关键人员不得更换，详见附件七
  ·SLA: 详见附件八

关键风险条款:
  ·违约金: 延期___%/天，上限___%
  ·终止条件: _________
  ·争议解决: _________

对方关键联系人:
  项目经理: ___  电话: ___  邮箱: ___
  技术负责人: ___  电话: ___  邮箱: ___
```

**8.2 合同交底会**

- 签约团队向交付团队做合同交底
- 逐条讲解关键条款的业务含义
- 强调履约过程中的"雷区"（易违约条款）
- 明确合同变更的流程和权限

## 六、关键检查点

| # | 检查点 | 通过标准 |
|---|--------|---------|
| CP1 | 谈判策略评审 | 三线目标设定合理，有明确退出条件 |
| CP2 | 条款风险分析 | 所有关键条款均有分析和应对方案 |
| CP3 | 法律审查 | 法务签署"无重大法律风险"意见 |
| CP4 | 内部审批 | 所有审批节点通过 |
| CP5 | 签约合规 | 授权、章证、文本全部无误 |
| CP6 | 合同交底 | PM团队确认理解全部关键条款 |

## 八、常见陷阱与对策

| # | 陷阱 | 对策 |
|---|------|------|
| 1 | 合同附件内容与正文不一致 | 逐字核对，特别是SOW和技术规格 |
| 2 | 急于签约忽视风险条款 | 坚持法律审查，不急在签约这一刻 |
| 3 | IP条款模糊引发后续纠纷 | 明确区分"背景IP"和"前景IP"的归属 |
| 4 | 付款节点与交付无实质关联 | 付款节点必须是可客观验证的交付里程碑 |
| 5 | 合同签完束之高阁 | 必须做合同交底，让执行团队熟悉条款 |
| 6 | 口头承诺未写入合同 | 所有谈判中的承诺必须书面化 |

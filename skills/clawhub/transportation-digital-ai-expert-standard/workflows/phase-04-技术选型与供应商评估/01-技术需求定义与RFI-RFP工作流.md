## 二、适用场景

本工作流适用于智慧交通项目在确定技术方向后，通过规范的RFI（信息邀请书）和RFP（建议书邀请书）流程，选择最合适的供应商或技术方案。本工作流从**客户视角**出发，指导如何设计和管理RFI/RFP流程。

## 三、前置条件与输入

| 输入项 | 来源 | 说明 |
|-------|------|------|
| 业务需求说明书(BRD) | phase-02-02 | 完整业务需求 |
| 技术架构设计 | phase-03-03 | 技术选型与架构要求 |
| 投资估算 | phase-03-04 | 预算范围 |
| 采购法规/制度 | 客户提供 | 公共部门/国企采购规则 |

## 四、详细步骤说明

---

### 步骤1：需求梳理与确认

**目标**：在进入采购流程前，最终确认技术需求的完整性、准确性和可测量性。

**输入**：BRD、架构设计、投资预算
**输出**：需求基线文档、SOW草案

**操作指南**：

**1.1 需求分类矩阵**

将需求按以下矩阵分类，明确每类需求的处理方式：

| 需求类型 | 处理方式 | 示例 |
|---------|---------|------|
| 强制需求 | 不满足即废标 | 等保三级合规 |
| 核心需求 | 权重最高的评分项 | AI事件检测准确率>85% |
| 加分需求 | 用于区分供应商差距 | 额外算法场景支持 |
| 参考需求 | 不评分但需说明 | 二期扩展方案思路 |

**1.2 避免需求"镀金"**

- 每个需求必须回答：为什么要这个需求？哪个业务场景需要？
- 剔除"听起来很厉害但实际用不上"的功能
- 区分"必须有"和"有了更好"

**1.3 SOW（工作说明书）草案结构**

```
工作说明书(SOW)草案:

1. 项目背景与目标
2. 项目范围
3. 技术方案要求
4. 交付成果清单
5. 实施周期与里程碑
6. 验收标准
7. 技术转移与培训要求
8. 运维与支持要求
9. 项目管理要求
10. 双方职责分工
11. 假设与约束条件
```

---

### 步骤2：技术规格与SOW编写

**目标**：将业务需求转化为精确的技术规格，撰写完整的SOW。

**输入**：需求基线、架构设计
**输出**：技术规格说明书、完整SOW

**操作指南**：

**2.1 技术规格编写原则**

| 原则 | 说明 |
|------|------|
| 客观可衡量 | 避免"界面友好""性能优秀"等主观表述 |
| 技术中立 | 不指定具体产品（除非有充分理由） |
| 面向结果 | 描述"能做什么"而非"怎么做" |
| 可验证 | 每个规格有对应的验收测试方法 |
| 行业标准 | 优先引用国标/行标 |

**2.2 交通行业技术规格示例**

```
技术规格示例:

[性能规格]
- 视频AI分析延迟：单路视频流从接入到输出分析结果 < 2秒
- API并发支持：>500 QPS（查询类）/ >100 QPS（事务类）
- 地图渲染性能：加载1000+路段路网数据 < 3秒
- 数据融合处理：实时融合5种以上数据源，延迟 < 5秒
- 系统可用性：核心业务系统 > 99.9%（全年停机 < 8.76小时）

[功能规格]
- 支持GB/T 28181标准视频流的接入和播放
- 支持JT/T 808/1078协议的车载终端数据接入
- AI事件检测种类不少于10种（指定清单）
- 支持T/CAGIS等交通地理信息数据格式

[安全规格]
- 通过等保三级测评
- 支持国家标准密码SM2/SM3/SM4算法
- 支持统一身份认证（OAuth 2.0/OIDC）
- 数据传输加密（TLS 1.3）、数据存储加密（AES-256）
- 完整的评估审查日志记录

[扩展规格]
- 支持不少于10个节点的横向扩展
- 数据存储水平扩展至PB级
- 支持X86和ARM混合架构部署
```

**2.3 SOW质量检查清单**

- [ ] 范围边界是否明确（做什么和不做什么）
- [ ] 交付成果是否全部量化（数量+质量标准）
- [ ] 里程碑是否明确（时间+交付成果+验收方式）
- [ ] 验收标准是否可测量
- [ ] 双方责任是否清晰无歧义
- [ ] 知识转移和运维的具体要求是否包含

### 步骤3：RFI设计与问卷制作

**目标**：设计RFI（信息邀请书）用于市场调研和供应商初筛。

**输入**：技术需求、架构要求
**输出**：RFI文件、RFI问卷

**操作指南**：

**3.1 RFI的目标**

RFI vs RFP的区别：

| | RFI (信息邀请书) | RFP (建议书邀请书) |
|---|---|---|
| 目的 | 了解市场、收集信息 | 获取正式报价和方案 |
| 时机 | 需求不够明确、需调研市场 | 需求明确、准备采购 |
| 回复 | 信息性，非正式报价 | 正式建议书+报价 |
| 约束 | 不产生合同义务 | 产生合同义务 |
| 时间 | 2-4周 | 4-8周 |

**3.2 RFI问卷结构**

```
RFI问卷结构:

第一部分: 公司基本信息
  - 公司概况（成立时间、规模、资质）
  - 核心业务与主要客户
  - 近3年财务情况（可选）
  - 相关资质证书

第二部分: 技术与产品能力
  - 产品功能介绍（针对需求逐条回应）
  - 技术架构说明
  - 与现有系统的兼容性说明
  - 自主知识产权情况
  - 研发投入与技术路线图

第三部分: 行业经验
  - 交通行业项目案例（近3年）
  - 类似规模和复杂度的项目经验
  - 客户推荐信/联系方式

第四部分: 服务能力
  - 项目管理方法论
  - 实施团队能力
  - 本地化服务能力
  - 培训与知识转移
  - 运维服务SLA能力

第五部分: 商业信息（可选）
  - 大致的价格区间
  - 许可模式
  - 合作模式偏好
```

---

### 步骤4：RFI发布与供应商邀约

**目标**：将RFI发送给有潜力的供应商，获取市场信息。

**输入**：RFI文件、供应商长名单
**输出**：RFI响应跟踪表

**操作指南**：

**4.1 供应商长名单生成**

供应商来源：
- 行业展会/论坛接触的供应商
- 行业分析报告（Gartner/IDC/赛迪等）
- 同行项目的选定供应商
- 公司既有合作伙伴
- 主动咨询的供应商

**4.2 长名单收录标准**

- 有交通行业相关案例（必须）
- 有类似规模项目的交付经验
- 公司经营稳定（成立3年以上）
- 无重大法律/信用问题

**4.3 RFI发送与管理**

| 活动 | 时间 | 负责 |
|------|:---:|------|
| RFI发送 | D-Day | 采购/项目组 |
| 供应商答疑会 | D+7 | 项目组 |
| 答疑纪要发送 | D+10 | 项目组 |
| RFI回复截止 | D+21 | 供应商 |
| 预期回复数量 | 10-20家 | - |

---

### 步骤5：RFI回应分析与筛选

**目标**：基于RFI回复，筛选出进入短名单的供应商。

**输入**：RFI回复、长名单
**输出**：RFI分析报告、供应商短名单

**操作指南**：

**5.1 RFI回复评估矩阵**

| 评估维度 | 权重 | 评分标准(1-5) |
|---------|:---:|------|
| 产品功能匹配度 | 30% | 与需求的功能匹配程度 |
| 技术架构先进性 | 20% | 技术架构是否先进、开放 |
| 行业经验 | 20% | 交通行业案例数量和质量 |
| 服务能力 | 15% | 本地化服务、培训、运维 |
| 公司实力 | 10% | 规模、资质、稳定性 |
| 合作意愿 | 5% | 回复详尽度、配合度 |

**5.2 短名单筛选标准**

- 综合分排名前5-7家
- 确保至少包含：大型集成商 + 垂直领域专家 + 创新技术公司
- 考虑竞争性（不能只有一家可想）
- 目标：最终邀请3-5家进入RFP

---

### 步骤6：RFP撰写与定稿

**目标**：基于RFI获取的市场信息，撰写完整的RFP文件。

**输入**：SOW、技术规格、RFI分析结果
**输出**：RFP全套文件

**操作指南**：

**6.1 RFP文件结构**

```
RFP文件结构:

第一卷: 技术方案方须知
  1. 技术采购说明与项目概况
  2. 定义与术语
  3. 技术方案方资格要求
  4. 技术方案费用（技术方案方自行承担）
  5. 现场踏勘与答疑安排
  6. 技术方案文件撰写要求
  7. 技术方案文件的递交
  8. 开标与方案评审程序
  9. 合同授予
  10. 被淘汰条款

第二卷: 技术需求书
  1. 项目背景与目标
  2. 项目范围
  3. 总体技术架构要求
  4. 功能需求详述
  5. 非功能需求
  6. 数据需求
  7. 集成需求
  8. 安全需求
  9. 实施要求
  10. 验收标准
  11. 运维支持要求
  12. 培训要求

第三卷: 商务条款
  1. 报价要求与格式
  2. 付款条件
  3. 质保期要求
  4. 知识产权
  5. 保密要求
  6. 违约责任
  7. 合同模板

第四卷: 附件
  1. 技术方案函格式
  2. 报价表格式
  3. 案例清单格式
  4. 人员简历格式
  5. 偏离表格式
```

**6.2 交通行业RFP特色要求**

- 国产化环境兼容性证明
- 等保合规能力证明（安全产品部分）
- 与交通行业现有标准（GB/T、JT/T系列）的符合性
- 交通行业性能压测要求（节假日高峰、极端天气等场景）
- 7×24小时运维保障能力

---

### 步骤7：方案评审标准设计

**目标**：设计科学、公正、可量化的方案评审标准。

**输入**：需求优先级、项目特性
**输出**：方案评审办法、评分细则

**操作指南**：

**7.1 方案评审方法选择**

| 方法 | 适用场景 | 说明 |
|------|---------|------|
| 综合评分法 | 技术方案差异大 | 技术+商务综合评分 |
| 最低方案评审价法 | 标准化程度高 | 满足技术要求后比价格 |
| 性价比法 | 需要平衡技术和价格 | 得分/价格比 |

**交通行业建议**：综合评分法（技术60-70% + 商务/价格30-40%）

**7.2 评分细则示例**

```
智慧交通项目评分细则（总分100分）:

一、技术部分（65分）
  1. 项目理解与需求分析（5分）
  2. 总体技术方案（15分）
     - 技术架构（5分）
     - 功能设计（5分）
     - 数据方案（3分）
     - 集成方案（2分）
  3. 关键技术能力（10分）
     - AI/大数据能力（5分）
     - GIS/可视化能力（3分）
     - 实时计算能力（2分）
  4. 实施方案（10分）
     - 实施计划（3分）
     - 项目管理（2分）
     - 风险控制（2分）
     - 质量管理（3分）
  5. 项目团队（8分）
     - 项目经理资质（3分）
     - 技术负责人（3分）
     - 团队整体配置（2分）
  6. 类似项目案例（7分）
     - 交通行业案例数量（3分）
     - 案例规模与复杂度（2分）
     - 客户评价（2分）
  7. 运维服务方案（5分）
  8. 培训与知识转移（5分）

二、商务部分（35分）
  1. 报价（25分）
     - 价格分 = (最低报价/本报价) × 25
  2. 企业实力（5分）
     - 资质证书（3分）
     - 财务状况（2分）
  3. 本地化服务（3分）
  4. 知识产权（2分）
```

**7.3 交通行业重点关注**

- 要求提供交通行业相关业绩合同复印件（带金额和签章）
- 关键人员（项目经理、架构师）的项目经验和资质
- 交通行业性能压测方案的合理性
- 数据安全和个人信息保护方案

---

### 步骤8：RFP发布与应答管理

**目标**：正式发布RFP，管理供应商的答疑和技术方案。

**输入**：RFP文件、方案评审标准、短名单
**输出**：技术方案文件、方案评审报告

**操作指南**：

**8.1 RFP流程时间表**

| 节点 | 时间 | 活动 |
|------|:---:|------|
| RFP发布 | D-Day | 向短名单供应商发送RFP |
| 现场踏勘 | D+5 | 组织供应商到现场了解实际情况 |
| 答疑提交截止 | D+10 | 供应商提交书面问题 |
| 答疑回复 | D+14 | 向所有供应商发送答疑纪要 |
| 技术方案文件递交 | D+28 | 供应商递交密封技术方案文件 |
| 开标 | D+28 | 公开或内部开标 |
| 方案评审 | D+29~D+35 | 方案评审委员会评审 |
| 选定公示 | D+38 | 公示选定候选人 |

**8.2 应答管理要点**
- 所有供应商同等待遇：同一份RFP、同一份答疑纪要
- 答疑回复不泄露供应商的商业信息
- 逾期技术方案文件严格拒绝
- 技术方案文件密封和签收规范

## 六、关键检查点

| # | 检查点 | 通过标准 |
|---|--------|---------|
| CP1 | SOW质量评审 | 范围边界清晰、交付成果量化、验收标准可测 |
| CP2 | RFI回复充分 | 收到≥5家合格的RFI回复 |
| CP3 | 短名单质量 | 短名单3-5家，覆盖不同类型的供应商 |
| CP4 | RFP合规审查 | 法务确认RFP条款合规 |
| CP5 | 方案评审标准审批 | Sponsor批准方案评审办法 |
| CP6 | 技术方案合规 | 所有技术方案文件按规范递交 |

## 七、估计时长

| 阶段 | 时长 |
|------|:---:|
| 需求确认+SOW撰写 | 1-2周 |
| RFI设计→发布→回收→分析 | 3-4周 |
| RFP撰写+审批 | 1-2周 |
| RFP发布→技术方案→方案评审→定标 | 4-6周 |
| **合计（从SOW到定标）** | **9-14周** |

---

## 八、常见陷阱与对策

| # | 陷阱 | 对策 |
|---|------|------|
| 1 | SOW范围模糊导致后续纠纷 | SOW编写阶段多次与干系人确认边界 |
| 2 | 技术规格过于指向特定供应商 | 规格描述面向结果而非实现方式 |
| 3 | 技术采购时间太短，供应商准备不足 | 交通类复杂项目至少留4周技术方案时间 |
| 4 | 方案评审标准过于笼统 | 评分项细化为可量化指标，减少评委自由裁量 |
| 5 | 最低价选定导致质量差 | 技术分设及格线（如>40/65分），避免"低价劣质"选定 |
| 6 | 忽视国产化要求 | 在RFP中明确国产化合规要求 |

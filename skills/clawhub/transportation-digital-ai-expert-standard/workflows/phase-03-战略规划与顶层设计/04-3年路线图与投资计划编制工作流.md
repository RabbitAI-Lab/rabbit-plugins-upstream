## 二、适用场景

本工作流适用于为交通行业客户撰写3年数字化转型路线图和配套投资计划，支撑投资决策、年度预算申请和公共部门审批。

| 输入项 | 来源 |
|-------|------|

| 改进机会清单（含快赢） | phase-02-04 |
| 客户预算约束和资金来源 | 客户提供 |

### 步骤1：项目清单梳理

**目标**：将架构设计、改进机会转化为可执行的项目清单。

**输入**：架构设计文档、改进机会清单
**输出**：项目全量清单、项目卡片

**操作指南**：

**1.1 项目分解逻辑**

```
战略目标 → 项目群(Program) → 项目(Project) → 子项目(Sub-Project)

示例:
战略目标 SG-01: 建成全域覆盖、秒级响应的路网感知体系
  └─ Program-01: 路网感知体系建设工程
       ├─ Project-01-01: 外场感知设备补盲
       │   ├─ 新建视频监控点200处
       │   ├─ 升级老旧摄像机300处
       │   └─ 部署毫米波雷达50处
       ├─ Project-01-02: 视频AI分析平台建设
       │   ├─ AI算法训练与部署
       │   ├─ 视频分析平台开发
       │   └─ 云边协同框架搭建
       ├─ Project-01-03: 多源数据融合平台
       │   ├─ 数据接入标准化
       │   ├─ 融合算法开发
       │   └─ 态势感知一张图
       └─ Project-01-04: 路网运行监测平台
           ├─ 运行监测模块
           ├─ 预警发布模块
           └─ 移动端APP
```

**1.2 项目卡片模板**

```
项目卡片:

项目编号: P-01-02
项目名称: 视频AI分析平台建设
所属项目群: Program-01 路网感知体系
项目目标: 建设统一视频AI分析平台，实现交通事件自动检测
关键交付成果: AI分析平台 + 10种交通场景算法模型 + API服务
项目工期: 12个月
投资估算: 800万元
前置依赖: P-01-01(外场设备补盲)、P-00-01(云计算平台扩容)
业务价值: 事件自动检测率从30%→85%，年减少人工巡检工时5000小时
技术方案: 云端训练+边缘推理，基于K8s部署，支持GPU弹性伸缩
实施优先级: P0(最高)
项目分期: 一期/M1-6（基础平台+4种算法），二期/M7-12（6种算法+优化）
```

### 步骤2：依赖分析与排序

**目标**：分析项目间的依赖关系，进行科学排序。

**输入**：项目全量清单
**输出**：依赖关系图、项目排序结果、分期建议

**操作指南**：

**2.1 依赖关系类型**

| 依赖类型 | 说明 | 示例 |
|---------|------|------|
| 技术前置 | A项目是B项目实施的技术前提 | 云平台在应用项目之前 |
| 数据前置 | A项目为B项目提供数据源 | 感知设备为AI平台提供数据 |
| 业务前置 | A项目的业务流程是B项目的输入 | 流程梳理在系统开发之前 |
| 资源依赖 | A和B共享同一批关键资源 | 同一AI团队负责多个项目 |

**2.2 项目排序策略 — 加权评分法**

| 排序维度 | 权重 | 评分标准(1-5) |
|---------|:---:|------|
| 战略对齐度 | 25% | 对战略目标的贡献度 |
| 业务价值 | 25% | 带来的直接/间接效益量化 |
| 实施紧迫性 | 15% | 行业规范/考核/安全的deadline |
| 实施可行性 | 15% | 技术成熟度+组织就绪度 |
| 投入产出比 | 10% | 年度ROI估算 |
| 风险可控性 | 10% | 技术/组织/行业规范风险 |

**排序分 = Σ(维度得分 × 权重)**

**2.3 依赖网络分析**

```
项目依赖网络示例:

Cloud基础平台 ──┬──> 数据中台 ──┬──> AI平台 ──> 智能应用(二期)
(P-00)         │    (P-02)     │    (P-04)     (P-06, P-07)
               │              │
               ├──> 统一门户 ──┼──> 运行监测平台
               │    (P-01)    │    (P-03)
               │              │
               └──> IoT平台 ──┴──> 养护管理平台
                    (P-05)         (P-05)

关键路径: P-00 → P-02 → P-04 → P-06 (工期最长依赖链)
```

### 步骤3：投资估算与撰写

**目标**：科学估算各项目的投资需求，撰写投资计划。

**输入**：项目清单、项目卡片
**输出**：投资估算表、分年度投资计划

**操作指南**：

**3.1 投资估算方法**

```
投资估算的三层次方法:

Level 1: 类比估算法（±30%）
  适用: 早期规划阶段
  方法: 参考同规模同类项目的实际投资数据

Level 2: 参数估算法（±20%）
  适用: 项目定义阶段
  方法: 按功能点/数据量/用户数等参数×单价

Level 3: 自下而上估算法（±10%）
  适用: 项目详细设计后
  方法: WBS分解到工作包级别，逐项估算汇总
```

**3.2 投资构成模板**

| | 网络设备 | | | | |
| | 外场设备 | | | | |
| 咨询服务 | 规划设计 | | | | |
| | 项目管理 | | | | |
| | 监理/测评 | | | | |
| 实施服务 | 系统集成 | | | | |
| | 数据迁移 | | | | |
| 培训 | 用户培训 | | | | |
| 运维 | 运维服务 | | | | |
| 其他 | 预备费 | | | | |
| **合计** | | | | | |

**3.3 交通行业投资参考区间**

| 项目类型 | 典型投资区间 | 说明 |
|---------|:----------:|------|
| 智能交通管理平台/综合交通运行协调中心 | 2000-8000万 | 城市规模、功能范围差异大 |

### 步骤6：投资效益分析验证

**目标**：验证项目群投资的整体效益，确保投资合理性。

**输入**：投资计划、项目价值估算
**输出**：投资效益分析报告

**操作指南**：

**6.1 三效益评估框架**

详见《phase-05/01-三效益ROI建模与分析工作流.md》。

**6.2 投资合理性验证**

| 验证维度 | 方法 | 通过标准 |
|---------|------|---------|
| 战略覆盖度 | 检查是否每个战略目标都有对应项目 | 100%覆盖 |
| 投资坡度 | 年度投资增长是否和组织消化能力匹配 | 年度增长<50% |
| 效益产出节奏 | 是否有持续的快赢产出 | 每半年至少1个可见成果 |
| 技术保障 | 基础平台是否早于应用项目 | 平台类项目在应用类之前 |
| 风险分散 | 是否将所有资源压在单一项目 | 无单项目占总预算>40% |

### 步骤7：风险预案撰写

**目标**：识别路线图执行过程中的关键风险并制定预案。

**输入**：路线图、投资计划
**输出**：风险登记册、应急预案

**操作指南**：

**7.1 路线图关键风险清单**

| 风险类别 | 风险描述 | 概率 | 影响 | 等级 | 应对策略 |
|---------|---------|:---:|:---:|:---:|---------|
| 行业规范风险 | 地方决策者更换导致战略方向变化 | 中 | 高 | 高 | 形成正式文件、多层级汇报 |
| 资金风险 | 资金方紧张导致预算延期/削减 | 高 | 高 | 高 | 设置最低必保预算，分步投资 |
| 技术风险 | 新技术验证不达预期 | 中 | 中 | 中 | POC试点验证 |
| 组织风险 | 客户IT团队能力不足 | 高 | 中 | 中 | 配套培训+知识转移 |
| 供应商风险 | 关键供应商出现问题 | 低 | 高 | 中 | 多供应商策略 |
| 数据风险 | 数据获取权限/质量问题 | 高 | 中 | 中 | 前期数据专项治理 |

**7.2 预案设计**

对高等级风险制定详细预案：
- 触发条件（什么情况下启动预案）
- 应对措施（具体做什么）
- 责任人（谁来做）
- 恢复计划（如何回到正轨）

### 步骤8：路线图评审与发布

**目标**：完成路线图评审，获得客户高层批准并正式发布。

**输入**：路线图文档、投资计划、风险预案
**输出**：评审纪要、签字版路线图

**操作指南**：

**8.1 路线图评审会**

| 议程 | 内容 | 时长 |
|------|------|:---:|
| 路线图总览 | 3年规划全景、关键里程碑 | 15min |
| 年度计划 | Y1详细计划、资源需求、风险 | 20min |
| 投资需求 | 投资估算、分年度安排、效益分析 | 15min |
| 讨论决策 | 提问、讨论、决策 | 30min |
| 下步行动 | 明确后续工作 | 10min |

**8.2 路线图发布**

- 签发版路线图正式文档
- 纳入客户年度工作计划
- 作为后续项目启动和年度预算的依据
- 建立路线图年度审查和滚动更新运行框架

## 八、常见陷阱与对策

| # | 陷阱 | 对策 |
|---|------|------|
| 1 | 项目过多导致资源分散 | 每年并行项目控制在5-8个以内 |
| 2 | 第一年塞入太多期望 | 第一年聚焦平台+1-2个核心应用+快赢 |
| 3 | 依赖链条过长 | 识别并压缩关键路径，引入并行策略 |
| 4 | 投资估算过于乐观 | 增加10-15%预备费，提供区间而非单点 |
| 5 | 路线图变成"墙上挂挂" | 建立季度跟踪运行框架，路线图滚动更新 |
| 6 | 忽视人才储备的时间 | 提前半年启动招聘或培训 |

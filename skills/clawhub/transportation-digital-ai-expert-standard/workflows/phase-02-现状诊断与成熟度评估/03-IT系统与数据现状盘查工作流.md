## 二、适用场景

本工作流适用于对交通行业客户的IT系统资产、数据资源、技术基础设施和网络安全现状进行全面盘查，为后续架构设计、系统集成和改造升级提供基准信息。

## 三、前置条件与输入

| 输入项 | 来源 | 说明 |
|-------|------|------|
| 项目合同/SOW | 项目启动文件 | 盘查范围和要求 |
| 客户IT部门联系方式 | 客户方 | 对接人信息 |
| 系统/网络/数据相关管理制度 | 客户提供 | 了解既有规范 |
| 盘查工具集 | 技术团队 | 扫描/检测/分析工具 |

## 四、详细步骤说明

### 步骤1：盘查规划与工具准备（1-2天）

**目标**：制定盘查计划，准备盘查工具和模板。

**输入**：项目范围、客户IT组织信息
**输出**：盘查计划、盘查清单模板、工具部署确认

**操作指南**：

  └──────┬───────┘    └──────┬───────┘
         │                   │

**1.2 盘查方法选择**

| 盘查方法 | 适用场景 | 优点 | 缺点 |
|---------|---------|------|------|
| 文档审查 | 有完善的IT文档 | 非侵入、全面 | 可能过时 |
| 访谈调研 | 了解系统背景和使用情况 | 获取深层信息 | 主观、耗时 |
| 系统演示 | 了解系统功能和界面 | 直观 | 只能看到表面 |
| 自动扫描 | 网络/主机/数据库 | 客观、全面 | 可能影响业务 |
| 代码走查 | 核心系统源码分析 | 深入技术细节 | 需要源码权限 |
| 日志分析 | 了解系统运行状态 | 基于真实数据 | 需要日志权限 |

### 步骤2：系统资产盘点

**目标**：建立客户IT系统的全量清单，记录每套系统的关键属性。

**输入**：盘查模板、客户IT团队配合
**输出**：系统资产清单、系统评估矩阵

**操作指南**：

**2.1 系统资产登记模板**

| 系统名称 | 正式名称 | 高速公路收费管理系统 |
| 业务域 | 所属业务领域 | 收费运营 |
| 建设方 | 开发/集成商 | XX科技公司 |
| 建设年份 | 首次上线年份 | 2018 |
| 最近更新 | 最近一次大版本更新 | 2022-Q3 |
| 技术架构 | B/S / C/S / 混合 | B/S |
| 开发语言 | 主要编程语言 | Java |
| 数据库 | 数据库类型和版本 | Oracle 12c |
| 操作系统 | 部署OS | CentOS 7 |
| 部署方式 | 物理机/虚拟机/容器/云 | 虚拟机 |
| 用户数 | 活跃用户数 | 约500 |
| 数据量 | 累计数据量 | 约2TB |
| 集成系统 | 已对接的系统 | 监控系统、ETC系统 |
| 运维状态 | 正常/部分故障/已停用 | 正常 |
| 供应商状态 | 是否仍在合作 | 已终止 |
| 源码可用性 | 是否持有源码 | 部分有 |
| 技术债务评估 | 1-5(1=良好,5=严重) | 3 |
| 安全等级 | 等保定级 | 二级 |

**2.3 系统评估五维打分**

每套系统从以下5个维度打分(1-5)：

| 维度 | 评分标准 |
|------|---------|
| 业务支撑度 | 系统对当前业务的支撑能力是否充足 |
| 技术先进性 | 技术栈的先进性、是否接近EOL |
| 可维护性 | 源码/文档/供应商支持的可用性 |
| 扩展性 | 是否容易扩展功能和性能 |
| 安全合规 | 是否满足当前的安全和合规要求 |

**综合健康分 = 五维平均分**

- 健康分 ≥4: 系统良好，保持
- 健康分 3-3.9: 需优化，择机升级
- 健康分 2-2.9: 需改造，纳入改造计划
- 健康分 <2: 需替换，列入淘汰清单

### 步骤3：接口关系梳理

**目标**：理清系统间的接口和数据交换关系，绘制系统集成现状图。

**输入**：系统资产清单、技术团队访谈
**输出**：接口清单、系统集成现状图、接口问题记录

**操作指南**：

**3.1 接口登记模板**

| 属性 | 说明 |
|------|------|
| 接口编号 | INTF-001 |
| 源系统 | 收费管理系统 |
| 目标系统 | 通行费结算系统 |
| 接口类型 | 数据上传/下发/实时查询/文件交换 |
| 传输方式 | API/消息队列/文件/数据库直连 |
| 触发方式 | 定时/事件/手动 |
| 接口协议 | HTTP/REST/SOAP/TCP/FTP |
| 数据格式 | JSON/XML/CSV/自定义 |
| 传输频次 | 实时/每小时/每天 |
| 是否双向 | 是/否 |
| 可靠性 | 高可靠/一般/不可靠 |
| 监控状态 | 有监控/无监控 |

**3.2 集成现状图绘制**

建议使用以下格式绘制：
```
┌──────────┐  HTTP/JSON  ┌──────────┐
│ 收费系统  │───────────>│ 结算系统  │
└──────────┘             └──────────┘
      │
      │ DB直连(不推荐)
      v
┌──────────┐
│ 报表系统  │
└──────────┘
```

**3.3 集成问题识别清单**

| 问题类型 | 症状 | 影响 |
|---------|------|------|
| 点对点直连 | 系统间直接调用，无中间件 | 耦合度高、难以管理 |
| 数据不一致 | 同一数据在不同系统中值不同 | 决策错误 |
| 接口无监控 | 接口故障无人知晓 | 数据丢失 |
| 文档缺失 | 接口无文档或文档过时 | 维护困难 |
| 性能瓶颈 | 大批量数据传输影响业务 | 系统卡顿 |
| 安全风险 | 明文传输/无认证 | 数据泄露 |

### 步骤4：数据质量评估

**目标**：评估客户数据资源和数据质量现状。

**输入**：系统资产清单、数据字典、数据样本
**输出**：数据资源清单、数据质量评估报告、数据问题台账

**操作指南**：

**4.1 数据资源盘点维度**

| 维度 | 评估内容 |
|------|---------|
| 数据目录 | 有哪些数据集/数据库/数据表 |
| 数据标准 | 是否有统一的数据标准和编码规范 |
| 数据量级 | 各系统的数据量级（GB/TB/PB） |
| 主数据管理 | 核心主数据（组织/人员/设备/路段等）如何管理 |
| 元数据管理 | 是否有元数据管理系统或文档 |

**4.2 数据质量六维评估**

```
数据质量评估模型:

  完整性 (Completeness)
  数据是否完整，缺失率如何？
  ┌─────────┐
  │          │  一致性 (Consistency)
  │   数     │  不同系统间同一数据是否一致？
  │   据     │
  │   质     ├── 准确性 (Accuracy)
  │   量     │  数据是否准确反映客观事实？
  │          │
  │          ├── 及时性 (Timeliness)
  │          │  数据的更新时效是否满足业务需求？
  └─────────┘
  唯一性 (Uniqueness)    规范性 (Validity)
  是否存在重复数据？      数据格式是否符合规范？
```

**4.3 数据质量抽检方法**

| 抽检项 | 方法 | 样本量 |
|-------|------|:---:|
| 完整性 | 统计各字段的空值率 | 全量 |
| 一致性 | 跨系统对比关键字段 | 100-200条 |
| 准确性 | 与客观事实/第三方数据对比 | 50-100条 |
| 及时性 | 检查数据更新时间与业务时间的延迟 | 全量/时间窗口 |
| 唯一性 | 检查主键/业务键是否有重复 | 全量 |
| 规范性 | 按正则表达式/字典表校验字段格式 | 100-200条 |

**4.4 数据质量问题分级**

| 级别 | 标准 | 处理要求 |
|:---:|------|---------|
| P0-致命 | 影响核心业务决策或安全 | 立即修复 |
| P1-严重 | 明显影响数据分析或业务流程 | 1周内修复 |
| P2-中等 | 轻微影响或局部问题 | 本月修复 |
| P3-轻微 | 不影响使用，格式优化类 | 纳入迭代 |

### 步骤5：基础设施评估

**目标**：评估客户IT基础设施的现状和能力。

**输入**：基础设施清单、网络拓扑图、监控数据
**输出**：基础设施评估报告、容量分析、风险清单

**操作指南**：

**5.1 基础设施评估清单**

| 类别 | 评估项 | 关注点 |
|------|-------|-------|
| 计算资源 | 服务器数量、规格、虚拟化率 | 性能余量、老化程度、云化程度 |
| 存储资源 | 存储类型、容量、使用率 | 性能、扩展性、备份策略 |
| 网络资源 | 带宽、拓扑、冗余 | 骨干网带宽、内外网隔离、远程接入 |
| 云资源 | 是否用云、云服务商、云资源量 | 云原生能力、混合云管理 |
| 机房设施 | 机房等级、电力、空调、物理安全 | 是否符合等保要求 |
| 监控工具 | 监控覆盖面、告警能力 | 是否实现统一监控 |

**5.2 交通行业特殊基础设施关注点**

| 关注点 | 说明 |
|-------|------|
| 外场设备 | 摄像机、情报板、车检器、气象站等前端设备的联网和供电 |
| 通信网络 | 路段通信网（工业以太网/PTN/OTN）的健康状态 |
| 物联网平台 | 是否具备IoT设备管理平台，终端接入能力 |
| 视频资源 | 视频存储容量、视频分析GPU资源、视频联网标准(GB/T 28181) |
| 边缘计算 | 收费站/路段是否部署了边缘计算节点 |
| 车路协同 | 是否部署RSU、MEC等车路协同基础设施 |

### 步骤6：安全现状评估

**目标**：评估客户信息安全现状，识别安全隐患。

**输入**：安全制度文件、等保测评报告、安全事件记录
**输出**：安全现状报告、风险清单、合规差距分析

**操作指南**：

**6.1 安全评估维度**

| 维度 | 评估内容 | 方法 |
|------|---------|------|
| 安全管理 | 安全制度、组织、人员 | 文档审查+访谈 |
| 物理安全 | 机房、设备物理防护 | 现场检查 |
| 网络安全 | 防火墙、WAF、IDS/IPS、VPN | 文档审查+扫描 |
| 主机安全 | 服务器安全配置、补丁管理 | 扫描+抽查 |
| 应用安全 | Web/API/移动应用安全 | 渗透测试(经授权) |
| 数据安全 | 数据加密、脱敏、备份、分类分级 | 文档审查+抽查 |
| 等保合规 | 等保定级、测评、整改状态 | 文档审查 |

**6.2 交通行业安全特殊关注点**

- 收费数据的安全（涉及资金结算）
- 视频监控数据的安全（涉及公共安全和个人隐私）
- 工业控制系统(ICS/SCADA)安全（外场设备的控制安全）
- 车路协同通信安全（V2X安全证书体系）
- CII(CII)认定与保护

### 步骤8：改进建议与汇报

**目标**：基于盘查发现提出切实可行的改进建议，并向客户汇报。

**输入**：盘查报告
**输出**：改进建议方案、汇报PPT、客户反馈

**操作指南**：

**8.1 改进建议分层**

| 层级 | 周期 | 内容示例 |
|------|:---:|---------|
| 紧急修复 | 1月内 | 高危安全漏洞修复、关键接口监控补全 |
| 短期优化 | 1-3月 | 淘汰系统中的数据迁移、数据质量专项治理 |
| 中期改造 | 3-12月 | 老旧系统替换/升级、网络架构优化 |
| 长期规划 | 1-3年 | 全面云化、微服务改造、数据中台建设 |

**8.2 汇报注意事项**
- 区分"紧急问题"和"优化建议"
- 量化问题的影响（导致的业务损失/效率损失/安全风险）
- 给每条建议配上大致工作量估算
- 避免过度批评现状，以"站在巨人肩膀更进一步"的态度沟通

## 八、常见陷阱与对策

| # | 陷阱 | 对策 |
|---|------|------|
| 1 | 客户不给系统权限 | 通过演示和截图替代，并记录"因权限限制未深入评估" |
| 2 | 客户不披露全部系统 | 多渠道交叉确认（业务部门访谈+IT部门访谈+网络扫描） |
| 3 | 过于技术化客户听不懂 | 分级输出：技术报告给IT、管理摘要给决策者 |
| 4 | 扫描工具引发安全告警 | 提前通告、在窗口期执行、使用非侵入式方法 |
| 5 | 主观判断代替客观评估 | 尽量用数据量化，主观判断标注"基于访谈评估" |

## 二、T-DMM模型概述

### 2.1 六大评估维度

```
T-DMM 交通数字化成熟度模型 — 维度框架

 ┌──────────────────────────────────────────────────────┐
 │                    交通数字化成熟度                    │
 ├────────────┬──────────┬──────────┬──────────┬─────────┤
 │  战略与治理  │ 业务数字化 │ 数据能力  │ 技术基础  │ 组织与人才│ 安全与合规 │
 │ (Strategy) │(Business)│ (Data)   │ (Tech)   │(People) │(Security)│
 ├────────────┼──────────┼──────────┼──────────┼─────────┤
 │·数字化愿景  │·业务线上化│·数据采集  │·基础设施  │·组织架构  │·网络安全  │
 │·治理运行框架    │·流程自动化│·数据治理  │·云化水平  │·人才结构  │·数据安全  │
 │·投资运行框架    │·智能化应用│·数据应用  │·系统架构  │·数字文化  │·等保合规  │
 │·标准体系    │·协同化水平│·数据资产  │·技术平台  │·培训赋能  │·应急响应  │
 └────────────┴──────────┴──────────┴──────────┴─────────┘
```

### 2.2 五级成熟度定义

| 等级 | 名称 | 特征描述 |
|:---:|------|---------|
| 1 | **初始级** | 信息化建设零散、依赖手工操作、无统一规划 |
| 2 | **规范级** | 核心业务系统化、有基本IT管理、数据开始汇聚 |
| 3 | **整合级** | 系统互联互通、数据初步治理、平台化建设 |
| 4 | **智能级** | AI辅助决策、数据驱动运营、技术架构先进 |
| 5 | **引领级** | 全面智能、行业标杆、能力对外输出 |

## 三、详细步骤说明

### 步骤1：评估规划与准备（第1周）

**目标**：明确评估范围、组建评估团队、制定评估计划、获取客户承诺。

**输入**：项目合同/SOW、客户基本信息
**输出**：评估项目计划书、访谈名单、问卷设计、启动会材料

**操作指南**：

**1.1 评估范围确认**

| 确认项 | 说明 | 决策人 |
|-------|------|-------|
| 评估组织范围 | 覆盖哪些部门/子公司/业务板块 | 客户项目Sponsor |
| 评估业务范围 | 哪些业务线纳入评估（运营/养护/调度/客服等） | 业务主管决策者 |
| 评估系统范围 | 涉及哪些核心系统 | IT部门负责人 |
| 评估深度 | 快速诊断(2周)/深度评估(4-6周) | 项目预算 |

**1.2 评估团队组建**

```
评估团队结构（我方+客户方联合团队）:

         ┌─────────────┐
         │ 评估指导委员会 │  ← 双方高层（Sponsor级）
         └──────┬──────┘
                │
    ┌───────────┼───────────┐
    │           │           │
    v           v           v
┌────────┐ ┌────────┐ ┌────────┐
│我方评估 │ │客户对接 │ │领域专家 │
│项目组   │ │协调组   │ │(按需)   │
│PM+顾问  │ │IT+业务  │ │安全/数据│
└────────┘ └────────┘ └────────┘
```

**1.3 评估计划制定**

| 周次 | 主要活动 | 产出 | 参与人 |
|:---:|------|------|-------|
| W1 | 启动+问卷发放+文档收集 | 启动纪要、回收问卷 | 评估组+客户 |
| W2 | 深度访谈+系统演示 | 访谈纪要 | 评估组+关键干系人 |
| W3 | 评估工作坊+分组讨论 | 工作坊成果 | 评估组+客户骨干 |
| W4 | 数据补充+初步评分 | 评分初稿 | 评估组 |
| W5 | 报告编写+校准 | 评估报告V1.0 | 评估组 |
| W6 | 汇报+改进建议讨论 | 最终报告+路线图建议 | 全体 |

**1.4 启动会准备**
- 启动会PPT：评估意义、方法论、计划、配合要求
- 客户高层支持：争取客户高层参会并表态支持
- 问卷预发放：启动会当天发放数字化成熟度自评问卷

### 步骤2：数据收集与问卷发放（W1-W2）

**目标**：系统性收集评估所需的全维度数据和信息。

**输入**：评估计划、问卷、数据收集清单
**输出**：问卷回收统计、文档收集清单、数据质量初步评估

**操作指南**：

**2.1 数据收集三通道**

```
数据收集三大来源:

  ┌─────────────────────────────────────────────────────┐
  │                                                       │
  │  ┌─────────┐   ┌─────────┐   ┌─────────┐            │
  │  │文档审阅  │   │问卷调查  │   │深度访谈  │            │
  │  │30%权重   │   │40%权重   │   │30%权重   │            │
  │  └────┬────┘   └────┬────┘   └────┬────┘            │
  │       │            │            │                   │
  │       v            v            v                   │
  │  战略规划文件     全员自评     决策者层访谈              │
  │  技术文档         IT/业务问卷  中层座谈                │
  │  项目资料         第三方评测   骨干深度访谈             │
  │  运营数据                                  │
  └─────────────────────────────────────────────────────┘
```

**2.2 文档收集清单（交通行业定制版）**

| 类别 | 核心文档 | 用途 | 优先级 |
|------|---------|------|:---:|
| 战略规划 | 近期/下期五年规划、数字化转型专项规划 | 评估战略维度 | ★★★ |
| 组织制度 | 组织架构图、IT治理制度、数据管理制度 | 评估治理与组织维度 | ★★★ |
| 技术资料 | 系统架构图、网络拓扑图、数据架构设计 | 评估技术维度 | ★★★ |
| 项目档案 | 近3年信息化项目清单、验收报告 | 评估建设成果 | ★★☆ |
| 运营数据 | 系统运维记录、数据质量报告、安全事件记录 | 评估运营能力 | ★★☆ |
| 财务数据 | 近3年IT预算和支出、项目投资回报 | 评估投资水平 | ★★☆ |
| 人员资料 | IT团队人员清单、培训记录、绩效评估 | 评估人才维度 | ★★☆ |

**2.3 问卷设计原则**

T-DMM自评问卷设计要点：
- 每个维度10-15题，总分100
- 采用5级Likert量表（1=完全不符合，5=完全符合）
- 包含客观事实题和主观评价题
- 设置交叉验证题（检查回答一致性）
- 交通行业场景化问题（如"养护巡检数据的实时采集覆盖率"）

**2.4 数据质量把控**
- 问卷回收率目标：>80%
- 低质量问卷识别：答题时间<3分钟、全部选同一选项
- 文档缺口记录：未能获取的关键文档及原因

### 步骤3：评估工作坊与深度访谈（W2-W3）

**目标**：通过面对面的工作坊和深度访谈，获取问卷和文档无法反映的深层信息。

**输入**：问卷分析结果、文档审阅发现、访谈大纲
**输出**：工作坊纪要、访谈纪要、初步发现清单

**操作指南**：

**3.1 深度访谈结构化大纲**

**决策者层访谈**（每人45-60分钟）

```
决策者层访谈提纲框架:

1. 开场（5min）
   - 访谈目的说明、保密承诺
   - 角色和分工确认

2. 战略与愿景（15min）
   - 您对交通数字化的整体愿景是什么？
   - 数字化在贵单位战略中的优先级？
   - 目前最满意的数字化成果和最不满意的？

3. 投入与运行框架（15min）
   - IT预算的决策框架是怎样的？
   - 过去3年的IT投资重点？
   - 您如何看待投资回报？

4. 挑战与期望（15min）
   - 推进数字化最大的阻力是什么？
   - 您期望的外部合作伙伴是什么样的？
   - 成功的标志是什么？

5. 收尾（5-10min）
   - 补充说明、建议、期望
```

**业务/技术骨干访谈**（每人45-60分钟）

```
骨干访谈提纲框架:

1. 业务/工作现状（15min）
   - 日常工作的数字化水平？
   - 最耗时间的重复性工作？
   - 数据获取和使用中最大的困难？

2. 系统使用体验（15min）
   - 核心系统好用吗？最想改进的？
   - 跨系统操作的困扰？
   - 报错/故障的频率和影响？

3. 能力与需求（15min）
   - 自身数字化技能水平自评？
   - 培训和学习的需求？
   - 知道但用不起来的功能？

4. 优化建议（10min）
   - 如果只改进一件事，改什么？
```

**3.2 评估工作坊设计**（半天）

| 时间段 | 环节 | 内容 | 参与人 |
|-------|------|------|-------|
| 09:00-09:30 | 开场与对标 | 行业标杆案例分享、评估框架讲解 | 全体 |
| 09:30-10:30 | 分组讨论1 | 按6维度分组：现状共识、亮点与不足 | 分组 |
| 10:30-10:45 | 茶歇 | | |
| 10:45-11:45 | 分组讨论2 | 各组对6个维度进行初步打分 | 分组 |
| 11:45-12:00 | 成果展示 | 各组分享核心发现和打分 | 全体 |

**3.3 系统演示观摩**

- 安排客户IT团队现场演示核心系统
- 观察：操作流程、系统响应、数据展示、异常处理
- 记录：系统界面年代感、操作效率、可用性问题

### 步骤4：评分与分析校准（W3-W4）

**目标**：基于多源数据进行综合评分，确保评分的客观性和一致性。

**输入**：问卷结果、文档审阅、访谈纪要、工作坊成果
**输出**：六大维度评分表、成熟度雷达图、校准记录

**操作指南**：

**4.1 综合评分模型**

```
T-DMM 综合评分计算逻辑:

        问卷调查(40%)    文档审阅(30%)    专家评估(30%)
            │                │                │
            v                v                v
      问卷得分×0.4   +  文档得分×0.3   +  专家得分×0.3
            │                │                │
            └────────────────┼────────────────┘
                             │
                             v
                     各维度综合得分
                             │
                    (加权平均各维度)
                             v
                     总体成熟度得分
```

**4.2 六大维度评分细则**

| 维度 | 子项 | 权重 | 评分标准概要 |
|------|------|:---:|-------------|
| 战略与治理 | 数字化愿景/投资运行框架/治理结构/标准体系 | 15% | 有无规划→规划全面→规划与落地一致 |
| 业务数字化 | 业务线上化率/流程自动化/智能化应用 | 25% | 手工为主→系统化→自动化→智能化 |
| 数据能力 | 数据采集/治理/应用/资产管理 | 20% | 数据分散→汇聚→治理→资产化 |
| 技术基础 | 基础设施/云化/架构/平台能力 | 15% | 传统架构→虚拟化→云化→云原生 |
| 组织与人才 | 组织架构/人才结构/培训/文化 | 15% | 无专职→有团队→专业化→引领型 |
| 安全与合规 | 网络安全/数据安全/等保/应急 | 10% | 基本防护→体系化→主动防御→免疫 |

**4.3 评分校准**

```
校准三原则:

1. 交叉验证原则
   同一结论需有2个以上独立来源支持
   例: "数据质量差" → 问卷调查+访谈反馈+系统演示观察

2. 证据导向原则
   每一项评分的升降必须有具体证据
   例: 评分从2升到3 → 需要证明存在数据治理制度+工具+执行记录

3. 一致性校准原则
   评估组内部评分一致性>80%
   分歧项进行专题讨论达成共识
```

**4.4 评分输出示例**

```
T-DMM 成熟度评分输出:

 ┌─────────────────────────────────┐
 │ 维度              │ 得分 │ 等级 │
 ├───────────────────┼──────┼──────┤
 │ 战略与治理         │ 2.8  │ 2→3  │
 │ 业务数字化         │ 2.2  │  2   │
 │ 数据能力           │ 1.8  │  1→2 │
 │ 技术基础           │ 2.5  │  2→3 │
 │ 组织与人才         │ 2.0  │  2   │
 │ 安全与合规         │ 3.2  │  3   │
 ├───────────────────┼──────┼──────┤
 │ 总体成熟度         │ 2.4  │  2   │
 └───────────────────┴──────┴──────┘

 雷达图: [战略] [业务] [数据] [技术] [组织] [安全]
```

### 步骤5：评估报告撰写（W4-W5）

**目标**：撰写结构完整、论据充分、建议可行的评估报告。

**输入**：评分数据、发现清单、改进建议初案
**输出**：T-DMM评估报告V1.0

**操作指南**：

**5.1 标准报告结构**

```
T-DMM评估报告目录:

执行摘要（2-3页）
- 总体评估结论
- 核心发现(3-5条)
- 关键建议(3-5条)
- 成熟度总览

第一章：评估概述
  1.1 评估背景与目标
  1.2 评估范围与方法论
  1.3 评估过程总结

第二章：总体评估结论
  2.1 成熟度综合评分
  2.2 六大维度评分概览
  2.3 行业对标分析
  2.4 亮点与不足总结

第三章：分维度详细评估
  3.1 战略与治理维度
  3.2 业务数字化维度
  3.3 数据能力维度
  3.4 技术基础维度
  3.5 组织与人才维度
  3.6 安全与合规维度
  (每项含:现状描述→证据支撑→评分依据→改进方向)

第四章：标杆对标分析
  4.1 行业领先实践
  4.2 差距量化分析
  4.3 追赶路径分析

第五章：改进建议
  5.1 改进优先级矩阵
  5.2 短期快赢(0-6月)
  5.3 中期提升(6-18月)
  5.4 长期规划(18-36月)

附录
- 访谈名单
- 文档清单
- 评分细则
- 问卷统计
```

### 步骤6：结果汇报与共识（W5-W6）

**目标**：向客户管理层汇报评估结果，获得认可并推动行动。

**输入**：评估报告、汇报PPT
**输出**：汇报纪要、管理层反馈、后续执行计划共识

**操作指南**：

**6.1 汇报策略**

```
汇报对象分层:

层级         关注重点                   汇报策略
─────────────────────────────────────────────────
高层决策者       战略定位、行业对标、      5页以内、对比鲜明、
(Sponsor)      整体差距、行动方向        行动建议清晰

中层管理       具体差距、根因分析、      详细数据支撑、
(IT/业务负责人) 改进方案、资源需求        分维度深入说明

基层骨干       具体问题、改进方法、      问题具体化、
(执行层)       个人影响、培训计划        改进可操作
```

**6.2 难点话术**

| 场景 | 应对策略 |
|------|---------|
| 客户否认低分 | "我们理解您的感受。这个分数反映的是与行业标杆的差距，并不是否定过去的成绩..." |
| 部门间推诿 | "成熟度模型强调系统性，每个维度的提升都需要跨部门协作..." |
| 觉得改进太难 | "我们建议从3个投入小见效快的方向开始..." |
| 质疑评估方法 | "我们的方法论参考了国际DMM、中国信通院IOMM等成熟标准..." |

### 步骤8：持续跟踪与复评（持续）

**目标**：建立定期复评运行框架，跟踪改进进展。

**输入**：基准评估结果、改进路线图
**输出**：年度复评报告、成熟度趋势图

**操作指南**：

- 建议复评周期：每年一次（或重大项目建设完成后）
- 复评重点：对比基准分数的变化，验证改进措施的效果
- 趋势分析：多期评分趋势，评估改进速度

## 八、常见陷阱与对策

| # | 陷阱 | 对策 |
|---|------|------|
| 1 | 客户提供美化过的信息 | 多源交叉验证，现场观察系统 |
| 2 | 部门间互相推诿导致信息缺失 | 由Sponsor明确要求各部门配合 |
| 3 | 问卷回收率低 | 设置截止日期+关键人跟进 |
| 4 | 评估过度依赖问卷 | 问卷仅占40%，需结合文档+访谈 |
| 5 | 评分过于严苛导致客户抵触 | 以"进步空间"而非"差距"的角度沟通 |
| 6 | 缺乏行业对标数据 | 建立行业基准数据库 |

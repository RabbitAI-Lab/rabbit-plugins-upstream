# Workflow 01 — Project Analysis

Read [experience-design](../references/experience-design.md), [immersion levels](../references/immersion-levels.md), and [anti-patterns](../references/anti-patterns.md).

1. Inspect framework, routing, rendering mode, component boundaries, styles, assets, fonts, animation libraries, smooth scrolling, WebGL, build scripts, and test setup.
2. Identify the actual page goal, audience, content hierarchy, conversion/action, brand constraints, references, deadlines, and supported devices.
3. Record existing interaction and accessibility behavior that must survive.
4. Inventory performance risks: media, font loading, hydration, canvas, third-party scripts, and current layout shifts.
5. Classify reusable pieces and constraints. Do not replace the stack or design system unless required by the request.
6. Recommend an initial immersion level and list uncertainties.

Output a concise **Project Analysis** with constraints, opportunities, risk register, missing inputs, and technical baseline. Make reasonable reversible assumptions; ask only when a missing choice would materially alter the concept.

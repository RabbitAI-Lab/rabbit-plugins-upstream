# 检视表字段口径与录入话术

> 数据截至：2026-10-31 ｜ 纯方法论，无时效风险
> 用法：录单时照着问，一次问一个。

## 一、为什么是这九列

| 列 | 客户最容易犯的错 | 我们为什么要 |
|---|---|---|
| 谁 | 分不清投保人和被保险人（交钱的/被保障的） | 判断"先保赚钱的人"有没有做到 |
| 什么险 | 把"返还型"当保障 | 分清是保障还是储蓄，才能算四件套 |
| 保额 | 只看交了多少，不看能赔多少 | 缺口的核心数据 |
| 年缴 | 只记得"好像交好几千" | 换算成"已有保费支出" |
| 缴费期 | 不知道还要交几年 | 判断现金流压力 |
| 到期/保到 | 以为"买了就一辈子" | 有些保到 70 岁，之后就没保障了 |
| 缴费日 | 靠记忆 | 防忘交、防断保 |
| 报案电话 | 存在销售的手机号里（销售离职就联系不上） | 出事那天要用 |
| 受益人 | 写着"法定"就完事 | 只写法定，将来按遗产处理，手续更麻烦 |

## 二、录入话术（照着说，一次一问）

1. 「这张是给谁买的？」（答"给我妈"也要问一句：**交钱的是不是你**？）
2. 「这份管的是住院、大病、意外，还是存钱的？」——分不清就让他念**保险责任**第一句。
3. 「保单上**保额（出事了最多赔你多少）**那一栏写的是多少？」
4. 「一年交多少钱？交几年？」
5. 「每年哪个月哪一天扣钱？」
6. 「保到多大年龄，还是保几年？」
7. 「封面上的客服电话是多少？」「受益人（拿赔款的人）写的是谁的名字？」

## 三、异常数据怎么处理（别硬纠）

| 情况 | 处理 |
|---|---|
| 客户报"保额 30 万"但说不清是重疾还是身故 | 记成重疾，标注"待核"，让他回去看保单 |
| 客户说是"既能保病又能拿钱" | 归到**重疾（可能带身故责任）**，在备注写"疑似含储蓄成分"，**不评价好坏** |
| 客户记错年份、说不出缴费日 | 留空，进"需要你回去补的几栏"，**不追问** |
| 客户主动发来保单照片 | 先提示打码 → 识别只作辅助 → **保额/缴费日/到期三个数必须核** |
| 客户报了十张单 | **一次只录一张**，录完问"还有吗"，别一口气上 |

## 四、汇总区的三个数

1. **全家年缴合计** → 直接喂 `budget_calc.py --existing`；
2. **各险种覆盖人数** → 看"人缺"（有人整类没保）；
3. **缺口提示** → 只给"有/没有"，不给"必须补"。

## 五、这张表怎么用（交付话术）

> 「这张表你打印一份，交给一个家人，或者拍张照存在手机备忘录里。出事那天，家里人拿着它就知道该打哪个电话、哪张单能赔。」

## 六、边界

- 只要**金额、日期、险种类别**；**不要保单号、身份证号、银行卡号**。
- 不评价产品好坏，不代算收益率，不代做保全（改受益人、退保、保单贷款）。
- 表格结构借鉴行业通行的"家庭保单检视表"，**但不使用"人生七张保单"这类推销框架**。

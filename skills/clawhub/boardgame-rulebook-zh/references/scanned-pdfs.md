# 扫描版 / 图片文字 PDF 怎么处理

## 怎么判断

- 打开 PDF，**框选文字**：选不中 = 没有文字层。
- `extract.py` 输出“没有提取到任何文字段”，或 `source.md` 标“疑似扫描页”。
- 页面大部分被图片覆盖、文字字符数很少；或存在不可见的 OCR 文字层（文字能选中但看得见的是像素英文）。
- 只有矢量线条、没有文字 → 可能是文字转曲（outlined text）。

**关键检查**：把页面放大，看英文是“文字层”还是“像素”。  
如果英文是像素，覆盖中文 = 中文会叠在英文上，或者你要擦掉像素才能放中文，两种都会破坏原图。

## 为什么这个 skill 不做扫描页覆盖

本 pipeline 的安全承诺是：

> 只擦文字层，位图/矢量图一个像素都不动。

扫描页没有独立文字层，只有一张包含英文的图。要放中文只能：

1. 直接把中文盖在英文像素上 → 图文重叠、英文仍透出来；
2. 先用 inpaint/涂白擦掉英文像素 → 破坏底图、邻近插图会被误伤；
3. 重新排一张页面 → 不是“保持原版排版”。

这三种都违背“图画和文字不能错位”。所以扫描页应当**停止覆盖式汉化**，改走下面的方案。

## 可行方案

### A. 找有文字层的 PDF（首选）

- 出版社官网、官方中文版、BGG files、经销商资料页。
- 同一游戏的数字版规则书往往是可选中文字的。
- 官方中文版优先：术语和版式都最可靠。

### B. 双语对照版（对扫描页最稳）

保留原页不动，另做一份中文译文文档/PDF：

- 按页编号 + 段落编号对应；
- 可以左边原页、右边译文页；
- 不覆盖任何原图，读者对照看。

本 skill 不直接生成双语对照 PDF；可以用 `work/source.md` 的页/段结构人工排版，或用文字处理软件按页整理。

### C. 手动重排

用 InDesign / Affinity Publisher / Scribus 重新排版。  
优点：效果好；缺点：工作量大，插图需要重新放置，术语/校对仍需人工。

### D. OCR + 谨慎评估

只有满足以下条件才考虑覆盖：

- OCR 得到的是**独立文字层**；
- 原英文是干净的扫描文字，背景简单（纯白/浅色），可以用 inpainting 或白底覆盖；
- 插图/图标远离文字；
- 逐页目检确认擦除没有伤到图。

常用 OCR：RapidOCR（轻量、中文好）、PaddleOCR、Tesseract。  
OCR 之后仍要跑本 skill 的 extract/render/QA，并且把 `scanned-page` 警告当成“必须人工确认”，不能自动放行。

### E. 向用户确认

如果用户坚持“就把中文盖上去”，先说明风险：

- 英文可能透出来/重叠；
- 擦除可能破坏底图；
- 无法保证“插图不错位”；
- 交付后仍建议人工逐页校对。

让用户明确选择方案，再动手。

## 混合 PDF

有些 PDF 前几页是扫描封面、后面是文字层：

- `extract.py` 会给扫描页警告，其余页正常提取；
- 最终 PDF 中扫描页保持原文，文字页汉化；
- 在交付说明里写清楚“第 X 页为扫描页，未覆盖”。

## 检查清单

- [ ] 能选中文字吗？
- [ ] 文字层是独立层，还是图片上的 OCR 层？
- [ ] 页面是否有满版底图？底图上的英文是像素还是文字？
- [ ] 如果 OCR：擦除区域是否远离插图/表格线？
- [ ] 是否逐页目检过擦除后的底图？
- [ ] 是否在交付说明里写明扫描页处理方式？

## 不要声称

- 不要声称扫描页“已完美汉化”而没有逐页目检。
- 不要把“结构校验通过”当成扫描页也安全的证据；QA 只验证它看到的文字层。
- 不要把 OCR 出来的文字层当成原版文字层；OCR 会错字，术语也会错。

## Description:

Use when medium-to-large changes need explicit requirements, technical design, and task planning before implementation, especially for multi-module work, unclear acceptance criteria, or architecture-heavy requests.

This skill is ready for commercial/non-commercial use.

## Use Case:

Developers and engineering agents use this skill to decide when a change needs a structured requirements, design, task, and execution workflow before coding. It is intended for medium-to-large feature work, cross-module changes, architecture-heavy requests, and cases with unclear acceptance criteria.

### Deployment Geography for Use:

Global

## Known Risks and Mitigations:

Risk: The workflow can slow delivery or create unnecessary spec documents when applied to small, clear changes.

Mitigation: Use it for medium-to-large or unclear work and skip it for small, low-risk changes with precise acceptance criteria.

Risk: Incorrect or incomplete requirements, designs, or task plans could guide later implementation in the wrong direction.

Mitigation: Review each planning phase before implementation and require user confirmation between requirements, design, and task breakdown.

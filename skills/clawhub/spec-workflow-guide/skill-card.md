## Description:

Use when medium-to-large changes need explicit requirements, technical design, and task planning before implementation, especially for multi-module work, unclear acceptance criteria, or architecture-heavy requests.

This skill is ready for commercial/non-commercial use.

## Use Case:

Developers and engineering agents use this skill to decide when a medium or large coding change needs explicit requirements, technical design, and task planning before implementation. When the full workflow applies, it guides creation of requirements, design, and task documents before implementation begins.

### Deployment Geography for Use:

Global

## Known Risks and Mitigations:

Risk: The workflow can slow down small or already-clear changes by requiring requirements, design, and task confirmation.

Mitigation: Apply the full workflow only to medium or large changes, unclear acceptance criteria, multi-module work, or architecture-heavy requests; allow direct execution for small, low-risk tasks.

Risk: Planning documents could capture incorrect requirements if the agent guesses core product behavior.

Mitigation: Ask follow-up questions when underspecified and require user confirmation between requirements, design, and task breakdown.

# Scenario Examples

## 项目提前上线

输入要点：

1. 客户希望活动页面提前两天上线。
2. 设计稿未最终确认。
3. 技术未评估开发和测试时间。
4. 销售希望今天给客户明确答复。

判断：

1. 新上线时间尚未确认。
2. 设计和技术评估均未完成。
3. 不能直接承诺提前上线。
4. 今天可承诺的是同步评估进度或下一次更新时间。

参考表达：

```text
目前暂时无法直接确认提前上线。设计稿还在确认中，技术也需要评估开发和测试时间。建议先回复客户正在评估，并在今天 17:00 前更新可执行时间安排。
```

## 系统权限未开通

输入要点：

1. 新员工周一入职。
2. 行政已完成资料收集。
3. IT 需开通两个系统账号。
4. 目前只开通一个。
5. 主管关心是否影响培训。

判断：

1. 一个账号已开通。
2. 另一个账号尚未开通。
3. 是否影响培训取决于培训内容。
4. 不应直接认定 IT 延误。

参考表达：

```text
目前两个系统账号中已有一个开通，另一个预计下周一完成。我正在确认周一培训内容是否必须使用该账号。如果会影响实际操作，建议先调整培训顺序，优先安排不依赖该系统的内容。账号完成时间确认后，我会同步最终安排。
```

## 采购反馈延迟

判断重点：

1. 不写“采购一直拖”。
2. 明确需要采购确认的内容。
3. 说明缺少反馈带来的影响。
4. 给出期望反馈时间和超时更新方式。

## 财务审批待确认

判断重点：

1. 不承诺付款、开票或账期结果。
2. 区分已提交资料和审批结果。
3. 明确还缺哪些审批信息。
4. 需要对外回复时先给保守版本。

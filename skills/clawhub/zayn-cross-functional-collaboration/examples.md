# Examples

## 1. 项目提前上线

输入：

```text
客户希望活动页面提前两天上线。设计稿还没有最终确认，技术还没有评估开发和测试时间。销售希望今天给客户明确答复。
```

处理：

识别新上线时间尚未确认，不得承诺下周三上线；建议先同步正在评估，并约定今天 17:00 前更新可执行安排。

## 2. 系统权限未开通

输入：

```text
新员工周一入职，行政完成资料收集。IT 需要开两个系统账号，目前只开通一个，另一个预计下周一完成。主管问是否影响培训。
```

处理：

不直接认定 IT 延误；先确认培训是否依赖未开通账号，并建议调整培训顺序或同步账号确认时间。

## 3. 信息不足

输入：

```text
帮我催采购赶紧给结果，不然客户又要骂我们。
```

处理：

先补问采购需确认什么、已等待多久、期望反馈时间和是否已有对外承诺；不得直接生成情绪化催促。

## 4. 带有明显指责

输入：

```text
技术一直拖着不评估，害我们没法回复客户，帮我发群里催一下。
```

处理：

改为事实描述和影响说明，例如“目前缺少技术评估时间，销售侧暂无法给客户确认排期”，不写“技术拖着”。

## 5. 缺责任人和时间点

输入：

```text
订单资料还有几个字段没确认，想让运营和财务看一下。
```

处理：

指出缺少字段清单、责任角色和期望反馈时间；输出可暂用版本，要求按字段明确负责人。

## 6. 简短内部消息

输入：

```text
只要一条飞书短消息：请产品确认活动规则最终版，今天下班前给技术。
```

处理：

输出简短版本，明确对象、事项、时间和用途，不扩展成完整报告。

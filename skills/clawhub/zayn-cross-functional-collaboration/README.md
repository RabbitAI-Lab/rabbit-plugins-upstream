# CROSS_FUNCTIONAL_COLLABORATION() 跨部门协同

**Skill ID：** `zayn-cross-functional-collaboration`

**版本：** `v0.1.0`

**状态：** Draft for testing

## 核心用途

把跨部门事项整理成清楚、客观、可执行的协同内容，帮助用户先厘清事实、缺失信息、风险、责任边界、下一步动作和沟通方式。

## 适合岗位

适用于销售、运营、产品、技术、项目管理、行政、人力资源、采购、客服、财务，以及任何需要和其他部门协同推进事项的岗位。

## 适用场景

- 向其他部门确认项目进度
- 请求补充资料、排期、账号、审批、评估或反馈
- 同步当前风险、阻塞和影响
- 内部对齐后再回复客户、供应商或外部对象
- 把情绪化、推责式表达改成事实描述、影响说明和下一步请求

## 需要提供什么

最好提供：

1. 当前事项是什么
2. 涉及哪些部门或角色
3. 已确认事实
4. 还缺什么信息
5. 当前风险或阻塞
6. 希望对方提供什么
7. 希望什么时候前反馈
8. 是否已经对外承诺
9. 希望输出什么形式

信息不足时，Skill 会先问最关键的问题，不会强行补全。

## 会输出什么

默认输出：

1. 事项判断
2. 已确认事实
3. 待确认事项
4. 风险提醒
5. 建议推进动作
6. 内部沟通版本
7. 简短版本
8. 后续跟进建议

## 不会直接给结论的情况

- 关键时间、结果或负责人尚未确认
- 用户试图未经评估就承诺交期、上线时间或解决时间
- 表达中包含明显指责、推责或情绪化催促
- 缺少事实，只能看到推测或主观判断
- 需要领导决策、正式升级或对外回复，应交给对应 Skill

## 如何使用

直接提供当前事项和已有信息即可。未指定模式时，默认使用“协同推进模式”。

支持三种模式：

1. 分析模式：只分析风险、缺失信息和下一步。
2. 直接回复模式：生成可发送的内部沟通文本。
3. 协同推进模式：同时输出状态、待确认事项、责任角色、时间节点、沟通文本和跟进建议。

## 最简单输入示例

```text
帮我写给技术同事：客户想提前上线，但设计稿还没最终确认，技术还没评估时间。今天销售想先给客户答复。
```

## 完整输入示例

```text
事项：客户希望活动页面从下周五提前到下周三上线。
涉及部门：销售、设计、技术。
已确认事实：原计划下周五上线；客户希望提前两天；设计稿未最终确认；技术未评估开发和测试时间。
目标：今天先回复销售，避免销售直接承诺客户。
希望反馈时间：今天 17:00 前给销售一个可执行更新时间。
输出形式：飞书消息，清楚但不要推责。
```

预期：Skill 会提醒不能直接承诺下周三上线，并生成一个客观的内部协同版本。

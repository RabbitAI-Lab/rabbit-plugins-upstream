# AI 学习评估师指南（V5 新增）

> 本文是 V5 能力四「AI 学习评估师」的设计与实现手册。支持自适应测评、薄弱点诊断、个性化学习建议。

## 一、核心理念

- **评估即学习**：测评本身也是一次知识巩固过程
- **自适应难度**：根据答题表现动态调整题目难度
- **诊断驱动**：找出薄弱点，给出具体改进建议
- **离线可用**：评估系统完全离线运行，保护学习数据隐私

## 二、能力触发

### 2.1 触发词
- 「测评」「练习题」「学习效果」「测验」「考试」「评估」
- 「薄弱点」「哪里不会」「知识点诊断」「学习报告」
- 「生成一套题」「出个测验」「检查我学得怎么样」

### 2.2 输入参数
| 参数 | 类型 | 说明 |
|------|------|------|
| audience | enum | 中学生 / 大学生 / 教师 / 企业 |
| completed_modules | string[] | 已完成的模块列表，如 ['A1', 'A2', 'C1'] |
| target_modules | string[] | 待测评的模块（可与 completed_modules 相同） |
| difficulty | enum | 简单(1) / 中等(2) / 困难(3) / 自适应 |
| question_count | number | 生成题数（默认 20） |
| question_types | string[] | 题型偏好：单选/多选/填空/编程/实操 |

## 三、评估流程

### Phase 1 · 模块确认
```
用户：做个测评
AI：请告诉我你要测评的模块（可多选）：
     A1 AI进化历程 / A2 AI是什么 / A3 协作哲学 / ...
     或输入「全部模块」
```

### Phase 2 · 难度确认
```
AI：请选择测评难度：
     ① 简单（巩固基础）
     ② 中等（知识迁移）
     ③ 困难（综合应用）
     ④ 自适应（AI 根据表现动态调整）
```

### Phase 3 · 题量确认
```
AI：请选择题目数量：
     ① 10题（约15分钟）
     ② 20题（约30分钟）← 默认
     ③ 30题（约45分钟）
     ④ 50题（约60分钟）
```

### Phase 4 · 测评执行
- AI 生成测评题目（JSON 格式）
- 用户在单 HTML 界面作答
- 实时保存进度（IndexedDB）

### Phase 5 · 评分与报告
- AI 智能评分（支持主观题 AI 批改）
- 薄弱点诊断（知识点关联图谱）
- 个性化学习建议报告（PDF 导出）

## 四、题型设计

### 4.1 题型分类

| 题型 | 适用场景 | 计分方式 |
|------|----------|----------|
| 单选题 | 概念辨析、事实记忆 | 选对 +4 分 |
| 多选题 | 关联分析、综合判断 | 全对 +5 分，漏选 +2 分 |
| 填空题 | 关键概念、公式记忆 | 关键词匹配 +5 分 |
| 编程题 | 实践操作、代码能力 | 语法 + 逻辑 + 输出 +5 分 |
| 实操题 | 工具使用、流程掌握 | 步骤完整性 + 准确性 |
| 简答题 | 概念阐述、分析论证 | AI 语义匹配评分 + 关键词覆盖 +6 分 |

### 4.2 难度等级

| 等级 | 描述 | 示例 |
|------|------|------|
| L1 记忆 | 事实性知识 | "ChatGPT 是哪家公司发布的？" |
| L2 理解 | 概念解释 | "解释什么是 Prompt Engineering" |
| L3 应用 | 迁移使用 | "为一个数据分析任务设计 Prompt" |
| L4 分析 | 关联辨析 | "对比 RAG 与 Fine-tuning 的优劣" |
| L5 创造 | 综合创新 | "设计一个 AI 辅助教学系统" |

## 五、自适应算法

### 5.1 项目反应理论（IRT）

```
P(答对) = 1 / (1 + e^(-a*(θ - b)))
- a: 题目区分度
- b: 题目难度
- θ: 学习者能力水平
```

### 5.2 自适应策略

```
初始 θ = 0（中等水平）
每题后更新 θ：
- 答对 → θ += delta（delta 根据题目难度调整）
- 答错 → θ -= delta
根据新 θ 选择下一题：
- θ < -1 → 选择 L1/L2 题目
- -1 <= θ < 0 → 选择 L2 题目
- 0 <= θ < 1 → 选择 L3 题目
- θ >= 1 → 选择 L4/L5 题目
```

## 五·附、即时反馈机制（V7 新增）

> 每道题提交后，系统立即提供反馈，帮助学习者在最短时间内纠正认知偏差。

### 反馈触发时机

- 学习者在单 HTML 评估界面提交每道题的答案后，**立即**触发反馈（无需等全部提交）
- 客观题（单选/多选/填空/编程/实操）：本地即时判定，延迟 < 200ms
- 主观题（简答题）：AI 语义匹配评分，延迟 1-3 秒（本地 AI 模型或 API）

### 反馈内容规范

每道题的反馈包含以下四项：

| 反馈项 | 说明 | 示例 |
|--------|------|------|
| **正误判定** | 明确显示"正确"/"错误"/"部分正确" | ✅ 正确 / ❌ 错误 / ⚠️ 部分正确 |
| **正确答案** | 展示标准答案或参考答案要点 | "正确答案：B. Prompt Engineering 是通过优化输入文本来引导 AI 输出" |
| **解析说明** | 简要解释为什么该答案正确，涉及的核心知识点 | "Prompt 的核心在于'约束+示例'，参见 C1 模块 §2.3" |
| **自适应提示** | 仅答错时显示，针对具体 misconception 的引导性提示 | "你可能混淆了 Prompt 和 Fine-tuning 的区别，建议回顾 A2 模块'模型训练 vs 提示工程'" |

### 视觉反馈规范

| 判定结果 | 颜色 | 视觉样式 |
|----------|------|----------|
| 正确 | 绿色（#52c41a） | 题目卡片左边框变绿 + 顶部显示 ✅ 横条 |
| 错误 | 红色（#ff4d4f） | 题目卡片左边框变红 + 顶部显示 ❌ 横条 |
| 部分正确 | 黄色（#faad14） | 题目卡片左边框变黄 + 顶部显示 ⚠️ 横条 |

### 反馈生成方式

| 题型 | 反馈生成方式 | 说明 |
|------|-------------|------|
| 单选题 | 本地判定 | 直接比对选项索引 |
| 多选题 | 本地判定 | 比对选项集合，计算漏选/错选 |
| 填空题 | 本地判定 | 关键词匹配（支持同义词表） |
| 编程题 | 本地判定 | 语法检查 + 测试用例运行 + 输出比对 |
| 实操题 | 本地判定 | 步骤完整性检查 + 关键操作验证 |
| 简答题 | AI 评分 | 语义匹配 + 关键词覆盖度 + 逻辑连贯性；本地 AI 模型优先，降级至 API |

### 简答题 AI 评分细则

```
简答题评分 = 关键词覆盖分(40%) + 语义相关度分(40%) + 逻辑结构分(20%)
- 关键词覆盖分：提取标准答案关键词，计算学生答案的覆盖率
- 语义相关度分：用本地嵌入模型计算学生答案与标准答案的余弦相似度
- 逻辑结构分：检查答案是否包含"因为...所以..."、"首先...其次..."等逻辑连接词
```

## 十一、评估-推荐闭环规范（V7 新增）

> 评估不是终点，而是学习优化的起点。本节定义从"评估输出"到"推荐输入"再到"再评估验证"的完整闭环。

### 11.1 闭环总览

```
推荐 → 学习 → 评估 → 诊断 → 再推荐
  ↑                              ↓
  └──────── 验证改进 ←──────────┘
```

### 11.2 评估输出 → 推荐输入映射

| 评估输出字段 | 推荐引擎消费方式 | 映射规则 |
|-------------|-----------------|----------|
| 模块得分率 | 调整推荐优先级 | 得分率 < 60% 的模块优先级提升 2 级 |
| 薄弱知识点列表 | 精准推荐对应课件/游戏 | 每个薄弱点映射到具体课件章节或游戏关卡 |
| 认知层次分布（L1-L5） | 调整推荐内容深度 | L1-L2 薄弱 → 推荐基础课件；L3-L5 薄弱 → 推荐进阶实战 |
| 答题时间分布 | 判断熟练度 | 同分情况下，答题时间长 → 推荐巩固练习；时间短 → 推荐拓展挑战 |
| 错误类型分类 | 针对性推荐 | 概念混淆 → 推荐辨析课件；应用不足 → 推荐实操游戏；分析不够 → 推荐案例研讨 |

### 11.3 薄弱点诊断 → 具体推荐映射表

| 薄弱点类型 | 推荐资源类型 | 推荐优先级 | 示例 |
|-----------|-------------|-----------|------|
| 概念记忆不足（L1） | 基础课件 + 闪卡游戏 | 高 | "AI发展史时间线混淆" → 推荐 A1 课件 + 时间线排序游戏 |
| 概念理解偏差（L2） | 概念辨析课件 + 判断题练习 | 高 | "混淆监督学习与无监督学习" → 推荐 A2 辨析课件 |
| 应用能力薄弱（L3） | 实操游戏 + 案例分析 | 中 | "不会写 Prompt" → 推荐 C1 实操游戏 + Prompt 工坊 |
| 分析能力不足（L4） | 对比分析课件 + 讨论任务 | 中 | "无法对比技术方案优劣" → 推荐 C3 案例分析 + 小组讨论 |
| 创造能力待发展（L5） | 项目任务 + 开放挑战 | 低 | "无法设计完整方案" → 推荐项目模式学习任务 |

### 11.4 再评估验证机制

推荐学习完成后，系统自动触发再评估以验证改进效果：

| 步骤 | 动作 | 说明 |
|------|------|------|
| 1 | 推荐学习资源 | 基于诊断结果推荐课件/游戏/阅读材料 |
| 2 | 学习者完成推荐内容 | 系统记录学习时长、完成状态 |
| 3 | 触发再评估 | 从原评估题库中抽取同知识点题目（或等难度替代题）组成"复测卷" |
| 4 | 对比前后成绩 | 计算改进幅度：Δ = 复测得分 - 初测得分 |
| 5 | 闭环判定 | Δ ≥ 15 分 → 标记"已改善"，进入下一薄弱点；Δ < 15 分 → 调整推荐策略，换资源类型或降低难度 |

### 11.5 闭环数据流

```javascript
// 评估输出
const assessmentOutput = {
  weakPoints: [
    { module: 'C1', level: 'L3', scoreRate: 0.4, errorType: '应用不足' }
  ],
  overallScore: 72,
  timeProfile: { avgTimePerQuestion: 45 }
};

// 推荐引擎消费
function consumeAssessment(output) {
  output.weakPoints.forEach(wp => {
    const recommendation = mapWeakPointToResource(wp);
    // recommendation = { type: 'game', module: 'C1', name: 'Prompt实操工坊', priority: 'high' }
    pushToLearningPath(recommendation);
  });
  // 学习完成后触发再评估
  onLearningComplete(output.weakPoints, () => {
    const retest = generateRetest(output.weakPoints);
    const delta = retest.score - output.overallScore;
    if (delta >= 15) {
      markImproved(output.weakPoints);
    } else {
      adjustStrategy(output.weakPoints); // 换资源类型或降难度
    }
  });
}
```

### 11.6 强制测试门控（闭环专项）

| 检查项 | 标准 |
|--------|------|
| 评估→推荐映射 | 每个薄弱点必须生成至少 1 条推荐 |
| 推荐可执行 | 推荐资源必须存在于课件库/游戏库中 |
| 再评估触发 | 学习完成后 100% 触发再评估 |
| 改进判定 | Δ 计算正确，阈值判定准确 |
| 闭环完整性 | 推荐→学习→评估→诊断→再推荐全链路可追踪 |

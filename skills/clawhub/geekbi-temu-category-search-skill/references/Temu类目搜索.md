# Temu 类目搜索

## 工作原则

- 只使用极鲸云返回的真实类目数据，不编造类目、ID、指标或查询结果。
- 明确区分数据事实、可复算的派生指标和分析判断。
- 默认使用简体中文，日期使用绝对日期；平均价格和销售额标明当前 Temu 站点币种。
- 对缺失值、异常值、样本量和未完成分页作显式说明；指标为 `0` 时也要结合其他指标和更新时间核验，不自动当成真实为零。
- 接口参数、响应字段、请求命令和原始 JSON 仅用于内部调用。进度说明、分析过程和最终答复使用中文业务名称，不展示英文参数；只有用户明确要求开发对接或故障排查时才展示必要技术信息。

## 执行流程

1. 明确用户是要找可信类目 ID、查热销/蓝海类目、研究市场规模，还是为后续数据查询确定类目条件。
2. 明确站点、类目关键词、层级、父类目、需求规模和供给规模等必要条件。未指定站点时默认美国站，并在结果口径中说明。
3. 读取 [Temu 类目搜索接口](Temu类目搜索接口.md)，生成最小必要查询条件。用户要求热销类目或蓝海类目时，再读取 [Temu 类目榜单查询预设](Temu类目榜单预设.md)。
4. 未指定站点或明确要求美国站时直接使用默认值；只有用户指定其他国家或地区时，才运行 `scripts/temu_site_list.py` 实时解析站点。
5. 使用 `scripts/temu_category_search.py` 查询；服务端要求暂停查询时，按 [查询暂停与恢复流程](查询暂停与恢复流程.md) 提示并暂停。
6. 恢复条件满足后原样重跑查询，取得类目数据后再分析。
7. 查询失败时，只向用户提示错误输出一级 `msg` 的中文文案，不展示错误 JSON、状态码、异常栈或内部字段。
8. 核对分页范围、样本量、关键指标和更新时间后再分析；未读取全部分页时明确标为样本。

## 查询策略

- 类目名称使用内置模糊搜索；用户提供明确行业或品类名称时优先使用关键词。
- 优先查询一级或二级类目。用户未要求精细下钻时，不主动限制三级、四级类目；过细类目容易导致市场样本过少。
- 已知父类目 ID 时，可查其直接子类目。搜索结果返回从一级类目到当前类目的完整路径，用路径和层级验证 ID，不根据名称猜测 ID。
- 返回的 `catId` 属于 Temu 通用类目 ID 体系。必须结合完整类目路径、层级和父类目验证 ID；名称相近时列出候选并请用户确认，不根据名称猜测。
- 搜索特定类目名称时，不为了“更准”无条件叠加父类目和层级；只在用户已明确市场边界或需要下钻时组合，并注意条件过多会减少结果。
- 未指定排序时按问题选择一个主指标：热销优先总销量，蓝海优先蓝海指数，近期增长优先月销量增长率或月销售额增长率。
- 服务端为每个类目返回 `linkUrl`，指向该类目在极鲸云的 Temu 类目详情页。每个被展示的类目都必须把类目名称或完整类目路径写成 `[类目名称或完整类目路径](<linkUrl>)`；这条规则适用于表格、列表、排名、候选清单和正文，不因用户未主动要求链接或要求简洁结果而省略。

## 分析方法

- 市场规模：结合总销量、总销售额、日/周/月销量与销售额，不仅凭单一累计指标判断。
- 增长趋势：结合日、周、月增长率识别加速、回落或短期异常，单个时间窗口不足以证明长期趋势。
- 竞争供给：结合商品数、店铺数及其变化量和增长率，区分需求增长与供给同步涌入。
- 蓝海指数：数值越高越值得优先验证；在完整计算口径不明时，只将其作为供需综合指标，必须与需求规模、供给量和近期趋势交叉验证。
- 价格与客群：平均价格使用当前站点币种，可用于初步判断价格带，但类目均值不代表内部商品的价格分布。
- 经营模式：结合半托管商品数、半托管店铺数与总量，识别品类中半托管供给渗透情况；分母为零或缺失时不计算占比。
- 进入判断：优先找“需求有规模且增长、供给增长相对更慢、价格带匹配、类目不过细”的候选。类目级数据不足以证明单品或单店机会；输出进入判断时明确标注这一边界。

## 输出要求

类目表格或清单的名称列必须使用 `[类目名称或完整类目路径](<linkUrl>)`。发送答复前逐行检查：服务端返回非空 `linkUrl` 的每个类目都必须存在对应的可点击类目名称或路径，缺少任何一个都先修复再交付。

用户只索要类目链接时，仅返回 `[类目名称或完整类目路径](<linkUrl>)`，不附加接口、字段、链接类型或缺失状态说明。

默认按以下顺序输出：

1. 一句话结论：哪些类目值得关注或继续验证。
2. 数据口径：站点、类目层级、查询条件、排序、分页范围、样本量和更新时间。
3. 候选类目：展示中文类目路径、类目 ID、核心指标和入选原因。
4. 机会与竞争判断：区分事实、计算和判断。
5. 风险、数据限制和下一步验证动作。

用户只要类目 ID 或简单搜索结果时保持简洁，不强行扩展为完整市场报告。

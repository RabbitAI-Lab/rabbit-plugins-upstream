# 把对话转文章和贴图

## 用途

读取当前会话的本地记录，整理成两种可发布的内容：Markdown 文章，或竖版分享卡片（PNG/JPG）。

## 何时使用

用户在已经聊出实质内容的会话里，要求把这些内容对外发布时：

- 「总结这次的对话，写成文章」
- 「把刚才聊的转成文章」
- 「生成分享贴图」/「做几张分享卡片」

## 不适用

- 会话刚开始、只有一两句寒暄或单一工具调用。
- 用户要总结的是别人的对话、外部文档或网页（按普通写作任务处理）。
- 用户只是在问这个技能本身怎么用。

## 安全与数据流

本技能只在本地读写文件，不发起任何网络请求，不读取、不转发任何凭据。

| 环节 | 行为 |
| --- | --- |
| 读取 | 只读**当前会话自身**的记录：由运行环境注入的会话 ID + 进程自身工作目录拼出唯一路径。脚本没有任何接收路径或会话 ID 的参数，无法表达"读另一个会话" |
| 净化 | 写入 `transcript.md` 前，凭据、手机号、邮箱、IP、本机路径统一替换为占位符 |
| 卡片数据 | 只读取当前工作目录内的 `cards.json`，目录外路径一律拒绝；不接受 stdin |
| 写入 | 只写用户指定或默认的 `outputs/` 目录 |
| 网络 | 无。脚本不导入 urllib、requests、socket 等任何网络库 |
| 凭据 | 不读取任何密钥类环境变量；只读取 `CODEBUDDY_SESSION_ID` 这一个会话标识；子进程环境已用白名单隔离 |
| 子进程 | 仅调用本机浏览器做无头截图，可执行文件须通过白名单校验，参数以列表传递，不经过 shell |

详细说明见同目录 `SECURITY.md`。

## 权限与依赖

| 项 | 是否必需 | 说明 |
| --- | --- | --- |
| Python 3.7+ | 必需 | 仅用标准库 |
| `CODEBUDDY_SESSION_ID` | 必需 | 运行环境自动注入的当前会话 ID，是唯一的定位依据。缺失即停止，没有替代参数 |
| 系统浏览器 | 建议 | Chrome / Edge / Chromium，用于卡片截图；缺失时回退 Playwright |
| Pillow | 可选 | 只有 `--format jpg` 与 `--merge` 长图需要 |

脚本不读取任何 API key，无需配置密钥类环境变量。

## 前置检查

执行前先确认两件事，任一不满足就停止，并如实说明原因，不要用编造内容凑稿。

1. **会话本身**：当前对话中，用户提问与助手回复是否已构成多轮实质交互。
2. **记录可读**：运行检查脚本确认当前会话的记录存在且内容足够。

```bash
python scripts/extract_session.py --check
```

返回 JSON。`ok` 为 `true` 才继续；为 `false` 时把 `reason` 的内容转述给用户，然后结束。

判定门槛：用户发言 ≥ 1 条、助手回复 ≥ 1 条、有效正文 ≥ 200 字。

`selection.source` 只可能是 `session_id`，说明这次是按运行环境给出的会话身份命中的。脚本不按修改时间挑会话，也没有接收路径的参数——**当它无法确认当前会话时会直接失败，而不是读一个"看起来最像"的文件**。

返回 `ok=false` 且原因是缺少会话 ID 时：这说明运行环境没有注入该变量。此时**不要自己去猜或去翻别的会话文件**，如实告诉用户当前环境无法确认会话身份、本技能无法继续。这是设计上的停止条件，不是需要绕过的故障。

## 输出模式

从用户指令解析，缺省两者都要：

| 用户说法 | 模式 |
| --- | --- |
| 「只要文章」「写篇稿子」 | 仅文章 |
| 「只要贴图」「生成卡片」 | 仅卡片 |
| 「都要」（默认） | 文章 + 卡片 |

## 工作流

### 1. 抽取素材

```bash
python scripts/extract_session.py --out-dir "<输出目录>/_source"
```

生成 `transcript.md`。该文件已过滤工具调用、思维链与系统注入内容，并在落盘前完成脱敏（`--no-redact` 可关闭，不建议）。

会话上下文被压缩时，这份文件是唯一可靠素材源。

### 2. 提炼骨架

按 `references/extraction.md` 的五维框架整理：核心问题、关键转折、结论方法、踩的坑、可复用经验。

形成内部骨架，不直接给用户看。每一条都要能指回原对话；指不回去的内容删掉。

### 3. 建输出目录

```
<workspace>/outputs/<YYYY-MM-DD>_会话总结_<主题slug>/
├── _source/transcript.md
├── <YYYY-MM-DD>_<主题slug>_article.md
├── cards/card-01.png ...
└── cards.json
```

- 日期取运行当天。
- `<主题slug>` 用 3-5 个英文小写单词加连字符，如 `ai-video-workflow`。不用中文或空格。

### 4. 写文章

按 `references/article.md` 的结构与语感。要点：主标题加 2-3 个不同风格的备选、场景化开篇、带观点的小标题、短句清单式总结、提问式结尾；口语化短段落；1500-2500 字。

需要贴合用户既有风格时，先调用其风格档案技能（如 `my-style-writer`）；不可用则按上述语感执行并在交付说明里注明。

### 5. 生成卡片

按 `references/cards.md` 设计套系（默认 5 张：封面 → 要点 → 金句 → 清单 → 结论），写入 `cards.json` 后渲染：

```bash
python scripts/render_cards.py --data cards.json --out-dir "<输出目录>/cards" --theme coral --scale 2
```

渲染后用图片工具抽查首尾两张：文字是否被裁、留白是否失衡。有问题改 `cards.json` 重渲，不交付半成品。

单卡条目过多时拆卡，不要持续压字号（脚本自动缩到 0.55 倍以下即说明该拆）。

### 6. 交付

用一段话说明用了哪几轮对话、产出了什么、文章标题是什么、卡片几张，然后展示全部产物，文章排第一。

## 真实性要求

- 所有事实、数字、结论必须能在 `transcript.md` 找到出处；不确定的写成「当时的判断」，不写成「事实证明」。
- 不把助手对自身的描述写进正文，也不在文章里复述本技能的流程。
- 用户明确要求不写的段落，直接剔除。

## 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 检查返回 `ok=false`，提示缺少会话 ID | 运行环境未注入 `CODEBUDDY_SESSION_ID` | 如实告知用户当前环境无法确认会话身份，本技能停止；不要去找别的会话替代 |
| 用户想总结的是另一段对话 | 本技能只处理当前会话 | 请用户回到那段对话里重新触发，本技能不提供跨会话读取 |
| `transcript.md` 混入大段日志 | 素材本身含长输出 | 只取结论行，不把日志搬进文章 |
| 卡片文字被裁 | 单卡条目过多 | 拆成两张，或压缩每条描述 |
| 渲染报"必须位于当前工作目录内" | `cards.json` 写到了工作区外 | 把 `cards.json` 放到工作区内的输出目录再渲染 |
| 截图失败 | 无 Chrome/Edge 且无 Playwright | 报告缺依赖，请用户安装其一 |
| 渲染报"路径未通过白名单校验" | 浏览器不在受信任清单内 | 安装 Edge/Chrome 到标准位置，或改用 Playwright 回退 |
| 中文文件名乱码 | 命名未用 slug | 按「建输出目录」的规范命名 |

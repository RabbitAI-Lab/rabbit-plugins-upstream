## 二、技能规范

> **结构规范**：对齐 WorkBuddy 官方技能开发文档——必填字段 description / description_zh / description_en / version / author 齐备，另补 name / display_name / display_name_en / category；参考资料统一以 @ 符号加相对路径的形式引用（@ 后接 references 目录内文件名，不加反引号）。**allowed-tools 按选填处理、不设白名单**——本技能答复前需经 ima 知识库 MCP 检索条文/资料，并经 WebFetch / WebSearch 实时核对 WIPO 费用页；设白名单会切断未列出的 MCP 工具调用，故不启用。

> **目录深度**：本技能为严格 2 级结构（1 级 = `SKILL.md` / `references/` / `scripts/`；2 级 = 各目录内文件；未设置 `templates/` 目录），无 3 级及以上嵌套。新增子资源时不得在 references/、scripts/ 下再建子目录。

> **文件编码**：全部文本文件（Markdown、Python、JSON）为 **CRLF、UTF-8 无 BOM**（以现状实测为准；如后续引入自动校验脚本，编码口径以本条为准并可归一）。

> **数据单点维护**：CHF 规费与单独指定费快照数值 → `SKILL.md` 三 3.4 + `scripts/fee_data.json`（同源同步）；中国专属参数（声明、CNIPA 审查与救济、CNY 侧费用）→ @references/10-cnipa-bridge.md；陷阱与失败模式 → @references/09-pitfalls-and-failure-modes.md；参考资料体积与行号 → @references/11-file-index.md。

> **维护建议**：定期依据 WIPO 官方更新和 CNIPA 实务指引进行修订；建议按 `SKILL.md` §3.0 的复核周期触发核验；改动费用数值时同步更新 `scripts/fee_data.json` 的费率与 `meta.verified_on`，并跑一次 `--show-snapshot` 与已知算例回归。

## 三、版本治理与元数据约定

**1｜单一真源**：`SKILL.md` frontmatter 的 `version:` 字段。版本变更**只改这一处**，其余皆为派生。

**2｜派生同步点（两处，必须与单一真源一致）**：

| # | 位置 | 形态 | 校验方式 |
|---|------|------|----------|
| 1 | `SKILL.md` 文末 | `> **版本**：vx.y.z` | 人工核对（本技能暂无 selftest 脚本） |
| 2 | 本文件 | `> **当前版本**：vx.y.z` 与版本历史表首行 | 同上 |

**3｜不设平台元数据文件（明确约定）**：`_meta.json` / `_user_meta.json` 由平台在**发布／导入时写入**，技能**不得手工创建**——手工创建会写入**伪造的 ownerId 与发布时间戳**。本技能不设、亦不应新增任何"由平台管理的元数据文件"；版本与治理的唯一权威源为本文件。

**4｜版本号规范**：语义化版本（SemVer）。受众口径调整、控制面结构变更（内容外置 / 章节增删）→ minor；仅修订措辞、脚本或用例、数据快照 → patch；破坏既有使用契约的重定位 → major。

**5｜文件编码**：见 §二「文件编码」。

**6｜历史归档（暂不启用）**：如未来版本条目持续增长，参照技能家族做法将旧条目移出技能包归档（归档路径以明文书写、不写成 @references 指针）；当前条目规模可控，暂不归档。

1. 文档说明

本文档说明「亚马逊运营工作课表」交互原型的功能构成、页面规则与交互逻辑，供评审、开发和验收对照使用。原型已实现四个视图、任务详情、临时事项录入与身份范围切换，数据为演示数据。

产品目标

  • 把运营团队的日、周、月固定动作收在一张课表里，先看时间、再看任务。
  • 每个任务带明确的完成要求和复查节点，避免只勾完成不写结论。
  • 按身份区分可见范围，成员看自己、组长看本组、负责人看全部。
  • 异常事项（平台通知、断货风险、广告异常）可随时插入当天，不脱离课表另开记录。

阅读约定

用语含义
任务模板任务库里的固定规则条目，如「核查重点商品可售库存与断货风险」，不含日期与人员。
任务实例模板在某个日期、某个人身上生成的具体任务，唯一标识为 任务ID:人员ID:日期。
周期任务的重现频率，分日度、周度、月度、临时（触发型）四类。
时间段一天内的建议执行窗口，共 5 段，不构成硬性截止。

2. 信息架构

顶部为全局导航与身份选择，主体区按四个视图切换，右滑抽屉承载单个任务的详情与记录。

层级名称作用
全局导航我的本周 / 单日工作 / 月度总览 / 任务库四个视图互斥切换，切换后主体区整体重绘
全局导航身份下拉切换演示身份，影响可见范围与可操作项
视图级周期切换（←、今天、→）周视图按周前后翻，日视图按天，月视图按月
视图级查看范围按身份提供「我的任务 / 本组 / 全部人员 / 指定成员」
视图级＋临时事项录入当天新出现的异常事项
抽屉任务详情与记录查看完成要求、填写执行状态与检查结论
页面关系 周视图点击某一天进入单日视图；单日、月度、任务库中的任务项均可打开同一个详情抽屉；任务库打开的是只读模板详情，不产生记录。

3. 页面详情

以下每个页面给出界面截图与对应的功能点、交互规则。截图取自原型真实运行状态。

3.1

我的本周

周视图 · 默认页

一周的工作总览。横向是周一至周日，纵向是五个时间段，任务卡按优先级着色，一眼看出哪天紧、哪个时段该先做什么。

功能点

区域说明
KPI 卡片四张卡，分别显示：本视图任务总数、尚待完成数、周／月到期数、待跟进与待核验数。数值随查看范围实时变化。
优先级图例三条色标说明：P0 先查先办 P1 优先推进 P2 按计划推进，并注明时间段只是建议窗口。
日期表头显示星期与日期，当天高亮为「今天」，并显示当天任务数；周末显示「按值班表」。
时间段行开工必检（固定风险检查）、上午重点、下午推进、弹性／全天（响应和触发事项）、下班收尾（仅在有未结时生成）。
任务卡两行结构：第一行是周期与模块标签，第二行是任务标题。卡片左侧有优先级色条。
溢出折叠同一格超过 3 项时显示「＋另有 N 项，展开当天」，点击进入该日详情。
底部说明提示点击日期进入当日工作页；月度任务按到期日落入对应周，同一任务只保存一次。

交互规则

  • 点击日期表头或任务卡中的「展开当天」，跳转到该日单日视图。
  • 点击任务卡任意位置，从右侧滑出任务详情抽屉。
  • 切换身份或查看范围后，KPI 与网格按新范围重算，页面不刷新。
  • 周视图只统计所在周的任务实例，跨周任务按到期日归属。
3.2

单日工作

日视图

一天的执行页面。左栏按时间段排出当天任务，右栏放当天到期、临时插入与填写指引，形成「照着做 + 照着记」的闭环。

功能点

区域说明
任务分行每行包含优先级色条、任务标题、副信息（周期 · 模块 · 触发或截止条件 · 是否已有输出物）、右侧状态标签。
状态标签五种：待办、已完成、待跟进、待核验、不适用。已完成的任务整行置灰。
当日到期卡列出当天到期的周度与月度任务，并标注周期与触发条件。
紧急插入卡列出当天新增的临时事项；无内容时提示可从右上角添加。
填写指引卡固定文案，说明检查无异常与发现问题两种记录写法，以及数据缺失时选「待核验」。
空状态时间段内无任务时给出说明，例如下班收尾「没有未结事项时，无需额外勾选收尾任务」。

交互规则

  • 点击任意任务行打开详情抽屉填写记录。
  • 在非单日视图点击「＋临时事项」，先自动切到单日视图再弹表单。
  • 已标记完成、待跟进、待核验的任务会使当天生成「下班收尾」任务，保证有结论可查。
3.3

月度总览

月视图

月度任务按「几号前完成」投影到日历上，下方另附一整月清单，用于检查月度动作有没有落在具体日子上。

功能点

区域说明
月历网格周一开头排列，只显示月度任务，不混入日度与周度任务。
非本月日期填充上月与下月的日期格，置灰区分。
单格溢出每格最多显示 3 项，超出显示「＋N 项」。
月度任务清单按日期升序列出本月全部月度任务，每条显示日期、标题、模块、触发条件与当前状态。
底部说明提示只展示本月月度任务；点日期可看该日全部任务；遇周末自动提前到上一个工作日。

交互规则

  • 点击日期格，跳转到该日的单日视图，可看到日、周、月三类任务的合集。
  • 月度任务的到期日遇周六、周日自动前移到最近的周五。
  • 周期切换按钮在月视图下按整月前后翻页。
3.4

任务库

规则页

全部任务模板的索引，按业务模块分组。它回答的是「这件事归谁做、什么周期、做到什么程度算完成」，不产生执行记录。

功能点

区域说明
页头统计显示日度候选、周度、月度三类模板数量，并注明触发项不每天生成。
分组表格按模块分节，每节标题显示该模块的模板数量。
表格列周期／期限（含触发条件）、事项、主责、完成要求。
主责口径显示岗位角色（如产品运营、广告运营、客服），不是具体人名，便于人员变动时规则不失效。
优先级圆点事项名称前的色点表示 P0 / P1 / P2。

交互规则

  • 点击事项名称打开只读详情，展示完成要求与触发条件，并提示「任务库仅供查看，请在课表中打开当天的任务实例填写记录」。
  • 任务库不显示日期与状态，状态只在课表实例上存在。
3.5

任务详情抽屉

全局组件

从右侧滑出的抽屉，上半部分是任务的固定规则（只读），下半部分是本次执行的记录区。所有视图的任务项都打开这同一个抽屉。

功能点

区域字段说明
头部周期与日期 · 执行人例如「每日 · 2026-09-28 · 林珊」，明确这条任务属于谁、哪一天。
只读区业务模块 / 优先级与时间段 / 触发或截止条件 / 具体完成要求来自任务模板，执行人不可改。
可填区执行状态下拉选择：待办、已完成、待跟进、待核验、不适用。
可填区检查结论／处理结果文本，提示语为「无异常、发现的问题或已做的操作」。
可填区备注／协作说明可写站点、ASIN、活动 ID、卡点与责任人。
可填区输出物／证据链接报告链接、Case 编号、材料位置等。
可填区下次复查日期日期选择器，为待跟进事项提供复查节点。
底部保存记录提交后关闭抽屉并刷新当前视图。

校验规则

触发条件校验提示文案
状态选择「已完成」检查结论必填完成时请写一句检查或处理结论
状态选择「待跟进」下次复查日期必填待跟进事项需要填写复查日期
设计意图 把「完成」定义成必须留下结论，把「待跟进」定义成必须留下复查日期，避免任务被随手勾掉后无人接续。
3.6

新增临时事项

弹层表单

当天下班前才出现的异常，比如平台通知、突然断货、投诉集中爆发，通过这个表单插进当天课表。

功能点

字段控件说明
事项名称输入框示例文案：「US 站点某 ASIN 被抑制，核查并恢复」。
业务模块下拉十二个业务模块，用于归类与统计。
优先级下拉P0 / P1 / P2，默认 P1。
处理要求／完成判断多行文本写清要处理的对象和预期结果。
备注多行文本选填。

交互规则

  • 事项名称与处理要求均为必填，缺失时在底部提示，不关闭表单。
  • 保存后自动落到当天的「紧急插入」卡，并按优先级着色显示。
  • 临时事项归创建人所有，不进入任务库，不参与月度统计。
  • 抽屉支持点击遮罩或按 Esc 关闭。
3.7

身份与查看范围

权限演示

原型用身份下拉模拟权限差异：成员只看自己，小组长可看本组，运营负责人可看全部人员并逐个查看。切换到他人范围时，任务标题前会带上姓名前缀。

范围规则

身份可选查看范围说明
普通成员我的任务范围下拉隐藏，只能看分配给自己的任务。
小组长我的任务 / 本组全组 / 组内成员范围限制在本小组内，不出现其他组成员。
运营负责人我的任务 / 全部人员 / 任意成员可查看所有成员，任务标题前显示姓名前缀。

交互规则

  • 切换身份时查看范围自动重置为「我的任务」，避免越权残留。
  • KPI 卡片的所有数值按当前查看范围重新计算。
  • 范围下拉只有一个选项时自动隐藏。
重要边界 原型中的身份切换仅用于演示。正式系统的可见范围必须由登录身份与服务端权限共同判定，前端隐藏入口不构成权限控制。
3.8

任务库检索

页内组件

任务库提供关键词搜索与频率筛选，用于快速定位某条规则，或按周期类型清点任务量。

功能点

控件行为
搜索框同时匹配任务名称、业务模块、完成要求三个字段，输入即过滤。
频率筛选下拉切换：全部频率 / 日度 / 周度 / 月度。
组合过滤搜索词与频率条件同时生效，过滤后空模块整节隐藏。

交互规则

  • 过滤后输入框保持焦点与光标位置，支持连续输入不被中断。
  • 过滤只影响展示，不改变任务模板本身。

4. 全局规则

4.1 优先级体系

级别含义呈现
P0先查先办，高风险与异常优先红色系卡片与色条
P1优先推进，当天应处理的重点琥珀色系卡片与色条
P2按计划推进，有变化才记录蓝色系卡片与色条

4.2 执行状态

状态含义进入条件
待办已生成，尚未处理默认状态
已完成已处理且有结论必须填写检查结论
待跟进已开工但未结束必须填写下次复查日期
待核验数据缺失或结果待确认由执行人判断
不适用当天确实无需执行由执行人判断，不计入待完成

已完成与不适用的任务不计入「尚待完成」统计，但仍保留在列表中以备追溯。

4.3 任务生成规则

周期生成条件到期口径
日度仅工作日生成，周末不生成当天
周度按设定的星期几生成「每周 X 前」
月度按设置日投影到当月，遇周末前移到上一个工作日「每月 N 日前」或「每月最后一个工作日前」
触发型满足触发条件才生成，如「有活动或临近节点」「发现链接异常」随触发事件
临时人工添加，仅存在于创建当天当天
下班收尾当天存在临时事项，或有待跟进／待核验任务时才生成当天

4.4 任务实例唯一性

  • 任务实例用 任务ID:人员ID:日期 作为唯一标识，同一人在同一天的同一任务只保存一条记录。
  • 月度任务按到期日投影到对应周与当天，在周视图与月视图中看到的是同一条实例，记录不重复。
  • 同一模板派发给多人时，各自生成独立实例，互不覆盖。

4.5 数据与权限边界

项原型现状正式系统要求
数据来源内置演示数据，保存在浏览器本地接入组织架构与排班，服务端存储
权限判定前端按身份模拟登录身份 + 服务端校验，前后端共同拒绝
节假日只处理周末前移接入公司日历，含法定节假日与调休
周末值班固定文案提示由实际排班表生成值班清单
任务完成要求已内置到每条模板由业务侧确认后锁定

5. 待确认事项

#待确认影响
1日度、周度、月度固定任务的完整清单是否已锁定决定任务库最终条目与课表生成密度
2十二个业务模块的划分与公司实际岗位是否一致决定主责分配与统计口径
3角色与人员的对应关系（谁属于哪个组、谁是组长）决定权限范围与可见数据
4是否需要写入正式系统，还是先以当前形态上线试用决定本期是演示交付还是接入后端
5节假日与调休规则是否接入公司日历决定月度任务到期日的准确性
6完成记录是否需要导出或对接复盘报表决定是否新增导出与统计能力

附：任务数据规模

周期模板数说明
日度28 项含 5 个时间段分布，部分为触发型条件任务
周度38 项按周一至周五分别排布
月度34 项按每月 3、5、8、10、15、20、25、28 日及最后工作日到期
临时触发3 项演示用异常事项，正式环境由实际事件产生

业务模块共十二类：绩效与后台通知、前台可售与页面、客服与客户体验、经营数据、广告投放、价格与促销、库存与物流、市场与竞品、内容与上新、站外合作、财务与费用、协作与复查。

时间段共五类：开工必检、上午重点、下午推进、弹性／全天、下班收尾。

# 差评归因与回复 (ym-review-triage-reply)

对差评先做归因分类，再给回复。回复不推诿、不甩锅、不过度承诺，并判定这条差评要不要转私聊跟进。直接产出可复制发送的草稿，但不替你发布。

## 何时使用

- 用户说「这个差评怎么回」「差评归因」「处理评价」「客户投诉怎么回应」「review reply」时
- 用户贴了一条差评（含星级、文字、时间、是否带图）来问怎么处理时
- 用户贴来一批差评，想批量看归因分布与改进点时

## 运行前提

- 依赖：无第三方依赖，纯文本处理
- 不接入任何电商平台后台或店铺管理端，无法核实订单与物流真实状态
- 不联网、不上传任何数据

## 输入契约

| 项 | 必需 | 说明 |
|---|---|---|
| 差评原文 | 必需 | 一条或多条，可含星级、时间、是否带图、顾客昵称 |
| 商品/服务类型 | 可选 | 影响归因口径与回复措辞 |
| 订单关键信息 | 可选 | 是否超期、是否已退款、是否可联系到顾客 |
| 店铺回复规范与底线 | 可选 | 能补偿什么（优惠券额度、补发、退款上限），决定回复里能承诺到什么程度 |

**缺失处理：**

- 缺订单信息 → 回复草稿里不写具体订单承诺，改用「已安排专人核实」并列入「需先核实的事项」
- 缺补偿底线 → 不给具体补偿方案，只给话术框架，并在输出中提示「请先确认你的授权范围」
- 差评内容为空（只有一星无文字）→ 给通用回复模板，并说明「信息不足，建议先查看后台该订单详情」
- 多条差评 → 逐条归因，最后给一条归因分布小结与共性改进点

## 执行步骤

1. **摘要点** — 给每条差评编号（评 1、评 2…），提取可核实的事实点：买了什么、什么时候、具体问题、情绪强度、有无事实诉求。这一步最先做，后面归因与回复都回溯到编号。

2. **归因分类** — 按 `references/attribution-rules.md` 的五类判定表，给每条差评归到 产品本身 / 物流与时效 / 服务态度与响应 / 期望落差 / 恶意或不合理 中的一类或多类（可并列），每条归因必须写依据（引用差评原文哪一句）。

3. **判定是否需私下跟进** — 满足以下任一即建议私聊：涉及具体金额或订单、含个人信息、需核实订单才能回复、情绪激烈或公开回复会扩大影响。纯情绪宣泄且无事实诉求的，公开回复即可。写出判定理由。

4. **写回复草稿（四要素不可缺）** — 每条差评的回复必须含：①承认具体事实（点出对方说的是哪件事，不复述空话）②说明原因（解释为什么会发生，不甩锅给「平台」「快递」）③给可执行的补救（具体动作，如补发、退款、优惠券）④留下一步（联系方式或「专人会联系你」）。对照 `references/attribution-rules.md` 的回复禁区清单逐条检查，命中禁区的重写。

5. **给三版回复** — 标准版（含完整四要素，适合私聊或长回复位）、简短版（适合公开回复字数受限，保留四要素但压缩）、私聊版（适合转一对一沟通，语气更具体、可约具体补救）。三版都要过第 4 步的禁区检查。

6. **提炼改进项** — 从差评里挖可改进的具体动作（改详情页哪句话、打包加什么防摔、客服话术改哪里），单独成节，不属于回复内容。

7. **自检** — 输出前核对：每条归因有没有依据？回复是不是四要素齐全？有没有命中禁区？需核实事项有没有单列？涉及人身威胁或违法内容的，按能力边界处理，不写回复草稿。

## 输出格式

Markdown，套用 `templates/reply-template.md`：一、差评要点；二、归因结论（含依据）；三、是否需私下跟进（含理由）；四、回复草稿（标准 / 简短 / 私聊三版）；五、需先核实的事项；六、可改进项。

```
## 差评要点
- 评 1：[星级] [时间] [要点]

## 归因结论
- 评 1：产品本身 + 服务态度 → 依据：「色差大」属描述不符，「客服不理人」属响应缺失

## 是否需私下跟进
- 评 1：建议私聊 → 理由：涉及补发与订单核实，公开位无法给具体方案

## 回复草稿
### 标准版
[四要素齐全]
### 简短版
[压缩但四要素不缺]
### 私聊版
[转一对一，可约具体补救]

## 需先核实的事项
- 评 1：订单是否超 7 天无理由期、是否已发货

## 可改进项
- 详情页主图增加「实物平铺对比」降低色差预期
```

## 能力边界

- 不自动发布回复，不接入店铺后台核实订单与物流
- 不替商家做赔偿决策，补偿方案以用户给的授权范围为准
- 不生成攻击评价者、诱导改评或删评的话术
- 不做舆情监控、不批量代运营
- 涉及人身威胁、违法内容、敲诈勒索的差评：明确说明不在本技能处理范围，建议走平台申诉或报警，不写回复草稿

## 常见坑

1. **把回复写成模板腔** — 只写「感谢您的反馈，我们会改进」算不合格，因为没有承认具体事实。规避：第 4 步先点出对方说的那件事再展开。
2. **甩锅给第三方** — 写「快递太慢我们也没办法」会激怒顾客。规避：原因要讲「我们这边哪里没控好」，如「发货时未复核导致漏发」。
3. **过度承诺超出授权** — 用户没说能退款，草稿却写「全额退款」。规避：缺补偿底线时只给话术框架，并在输出明示「请先确认授权范围」。
4. **把恶意差评当合理诉求硬怼** — 明显无事实依据的恶意评价，公开回复要克制得体，不陷入争论。规避：归因标「恶意或不合理」，给简短得体的公开回应，不建议私聊纠缠。
5. **私下跟进判定漏掉情绪激烈** — 只看事实诉求，没注意顾客情绪已失控，公开回复会扩大矛盾。规避：第 3 步把「情绪激烈」也列为私聊触发条件。
6. **编造订单与物流事实** — 用户没给订单信息却写「您的订单已发货」。规避：缺信息一律用「已安排专人核实」占位，列入需核实项。

## 验收用例

- 正常：「衣服色差大，客服不理人」→ 归因为产品本身 + 服务态度，三版回复均含四要素，私聊版建议转一对一
- 边界 1：只有一星无文字 → 给通用模板并说明信息不足，提示查后台订单
- 边界 2：明显恶意差评（无事实、要挟） → 归因为恶意或不合理，给克制得体公开回复，不建议争执
- 失败：差评含人身威胁 → 说明不在处理范围，建议走平台申诉或报警

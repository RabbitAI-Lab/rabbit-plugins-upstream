1. **不泄露** —— 参赛者身份、盲测集内容、评分细节，一律不得外泄

## 标准工作流程（SOP）

### Workflow A：赛季启动
触发：新赛季开启 / 用户说"开赛"
- Phase 1（并行派单）：
  - spawn `uibc-track-designer` → 出赛题 + 评分维度 + 三层难度
  - spawn `uibc-review-governor` → 出评审细则 + 评委库方案
  - spawn `uibc-player-ops` → 社区开张 + FAQ + 申请通道对接
  - spawn `uibc-comms-officer` → 预热稿 + 专栏开栏计划
  - spawn `uibc-partnership-officer` → 企业赛道方案 + 赞助包
- Phase 2（串行）：本人汇总 → 输出赛季作战计划 → 提交主办方确认
- Phase 3：确认后启动赛前公示

### Workflow B：赛程运行
触发：赛程进行中的日常运营
- Phase 1：spawn `uibc-player-ops` → 答疑、社区、漏斗数据
- Phase 2：如发现异常 → spawn `uibc-review-governor` → 反作弊核查
- Phase 3：如需公告 → spawn `uibc-comms-officer` → 发布
- Phase 4：重大问题由本人裁决

### Workflow C：评审与公示
触发：赛程截止 / 提交通道关闭
- Phase 1：spawn `uibc-review-governor` → 组织多评委评分 + 校准会 + 匿名化
- Phase 2：第三方复核前 10 名
- Phase 3：本人确认 → spawn `uibc-comms-officer` → 榜单发布
- Phase 4：spawn `uibc-partnership-officer` → 兑现企业曝光承诺

### Workflow D：争议处理
触发：收到申诉 / 发现违规
- Phase 1：spawn `uibc-review-governor` → 收集证据 + 利益冲突核查
- Phase 2：组织被指控方申辩
- Phase 3：本人裁决（可咨询主办方）→ 出具书面结论
- Phase 4：spawn `uibc-comms-officer` → 按需公示

### Workflow E：赛季复盘
触发：赛季结束
- Phase 1：并行收集五条战线复盘
- Phase 2：输出改进项清单
- Phase 3：沉淀为下一届基线（不重复造轮子）

### Workflow F：赛前征求意见
触发：赛题初步成型但未公示
- Phase 1（分层征询）：
  - 公开征询：spawn `uibc-comms-officer` → 发《赛题征求意见稿》，开放评论/表单
  - 定向征询：spawn `uibc-player-ops` → 一对一邀请潜在参赛者、高校、企业反馈
  - 专家评议：本人邀请外部顾问书面评议
- Phase 2：spawn `uibc-track-designer` + `uibc-review-governor` → 逐条答复（采纳/不采纳 + 理由）
- Phase 3：spawn `uibc-comms-officer` → **公开反馈汇总**（公信力的第一次展示）

### Workflow G：奖品发放
触发：榜单公示无异议
- Phase 1：spawn `uibc-partnership-officer` → 获奖确认 + 发放排期
- Phase 2：分类发放（虚拟即时 / 实物物流 / 服务排期）
- Phase 3：发放台账登记 + 回执留档
- Phase 4：spawn `uibc-comms-officer` → 公开致谢 + 权益码激活说明

### Workflow H：权威发布与存证
触发：榜单定稿 / 赛季结束
- Phase 1：spawn `uibc-comms-officer` → 榜单在魔搭发布 + 同步 HF Spaces
- Phase 2：整理赛果包（榜单快照 + 评分细则 + 评测集说明 + 代码）
- Phase 3：提交 Zenodo 获 DOI 存证
- Phase 4（长期）：技术报告 → arXiv → Workshop 投稿

## 任务清单与依赖拓扑

「逆向工程助手」的任务体系：把"对已发布软件做授权范围内的逆向分析"从一句话需求推进到可复核结论的全流程任务清单，附任务间关系与元操作映射。

**域间逻辑流**：REA0（路由）→ REA1（侦察总览）→ REA2（追踪取证，按需进入 REA2-04）→ REA3（重建验证，按需）→ REA4（输出交付，扇入）；REA5（环境恢复）为支持域，任何阶段出现环境、连接或引擎问题时按需进入，修复后回到原任务继续。

### 依赖拓扑摘要

**主链路**：REA0-01 → REA0-02 → REA0-03 → REA1-01 → REA1-02 → REA1-03 → REA2-01 → REA2-02 → REA2-03 →（REA3-01 → REA3-02，按需）→ REA4-01 → REA4-02 → REA4-03

**支持链路**：REA5-01 → REA5-02 / REA5-03；REA5 为支持域，故障场景下 REA5-01 可作为临时入口（此时其依赖视为已满足），处置完成后回到原有任务的断点继续。

**条件分支**：
- REA2-04 按需进入：仅当静态证据不足以回答且用户确认后执行；
- REA3 按需进入：仅当用户要求复现/重建时执行；未执行时 REA4-01 直接承接 REA2-03 的产出。

**入口说明**：标准入口为 REA0-01；支持域入口为 REA5-01。入口任务共 2 个，占总任务数 18 的 11%（≤30%）。

**域间节点**：任务节点 REA0-01~REA5-03（18 个）；域节点 REA0~REA5（6 个）；元操作节点 S/C/A/O/I/G；关系边类型：依赖边（→）、条件边（?）、扇入边（⇇）、迭代边（↻，REA2 域内追踪-取证循环）、支持边（⇢，REA5 支持全流程）。

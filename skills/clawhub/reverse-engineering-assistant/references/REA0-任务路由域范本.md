## REA0-任务路由域范本

### 范本概述

覆盖 REA0-01~REA0-03 的产物样式：确认信息摘要、类型判定报告、调查方案。适用于任务开局，三个产物一次生成、逐级确认。

### 范本正文

**【REA0-01 需求与授权确认】确认信息摘要样例**：

```markdown
## 任务确认
- 目标：{{软件名}} {{版本}}，位于 {{绝对路径}}
- 来源与授权：{{用户自有项目 / 已获授权的软件}}；授权声明：仅用于 {{学习研究 / 互操作 / 安全分析 / 软件保存}}
- 问题清单：
  1. {{离线搜索的索引在哪里构建、如何查询}}
  2. {{索引数据的持久化格式是什么}}
- 待补信息：无
```

**【REA0-02 目标类型判定】判定报告样例**：

```markdown
## 类型判定报告
- 目标类型：Electron 应用目录（已解包）
- 判定依据：目录含 package.json / main.js / preload.js，符合 JS 应用工作流特征
- 所需能力：JS/Electron 静态分析——不需要反汇编引擎
- 前置核对：REA 工具可用（MCP 已连接）；无引擎需求，可直接进入 REA1
```

**【REA0-03 调查方案规划】方案样例**：

```markdown
## 调查方案
- 分析入口：analyze_javascript_application ／ analyze-javascript-application（先请求概要）
- 问题→证据映射：

| 问题 | 需要的证据 | 获取方式 |
|---|---|---|
| 索引在哪里构建 | 主进程侧实现 + 数据文件标识 | 概要 → 模块页 → 追踪 |
| 查询路径怎么走 | IPC 通道 + 查询函数 | trace_application_feature ／ trace-application-feature（单向） |
| 持久化格式 | 数据文件结构/依赖特征 | 单模块详情 + 依赖特征 |

- 推进顺序：概要 → 模块定位 → IPC 追踪 → 单模块详情
- 风险项：无（静态路径）；若需确认运行时行为，运行时观察属高风险操作，需另行确认
```

### 结构要点标注

1. REA0-01 必须含一行授权声明与"具体到功能/行为"的问题清单；模糊诉求先追问再进入下一任务。
2. REA0-02 的判定依据必须可复核（引用具体文件特征），且明确是否需要引擎。
3. REA0-03 的每个问题必须映射到证据类型与获取方式，顺序从最轻证据开始。
4. 涉及运行时的方案必须显式标注高风险确认点。

### 替换清单

目标名/路径/授权用途/问题清单替换为真实内容；判定依据按实际文件特征改写；入口与证据方式按实际可用工具调整（MCP 或 CLI 兜底）。

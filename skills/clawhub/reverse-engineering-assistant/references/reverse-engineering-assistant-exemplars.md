## 范本清单

按域分组的范本索引。范本展示「每个任务完成时产物该长什么样」，供执行时模仿结构与风格；业务内容须替换为实际任务内容。

**编号说明**：范本文件前缀 `REA` 为本技能的领域代号（取自英文名 reverse-engineering-assistant 的首字母缩写），域编号 `REA0`~`REA5` 与任务 ID 同前缀（如 `REA2-03`）。取三字母而非单字母 `R`，是为与 SKILL.md「Step 1 领域校准」的 R1~R5 参数（信息密度/创造性/交互性/规范性/迭代性）在文本中一眼区分；两者语义无关，不可混用。

### 范本标准格式模板

每个范本子文件统一使用以下结构：

```
## REA{编号}-{域名}范本
### 范本概述
（一段话：该范本对应的任务与适用场景）
### 范本正文
（完成时的产物样例，占位符保持 {{...}} 形式）
### 结构要点标注
（3~6 条：该范本体现的关键要求，对照 requirements 字段表）
### 替换清单
（模仿产出时必须替换的元素列表）
```

### 使用规则

1. 结构类组件（台账、报告章节）按范本结构填充；文案类内容模仿语气与颗粒度，业务内容全部替换。
2. 范本中的示例值（路径、函数名、用例数）是示意，禁止原样照抄进真实产出。
3. 范本与 requirements 字段表冲突时，以 requirements 为准并复检。
4. 双通道写法：同一字段在 MCP 与 CLI 下语义不同时，用全角「／」并列（MCP 形态 ／ CLI 形态），只写实际使用的那一个。会话、快照、`parent_evidence_id`、`detail` 参数为 MCP 专有，CLI 通道一律按「证据文件」口径填写，不得照抄会话表述。

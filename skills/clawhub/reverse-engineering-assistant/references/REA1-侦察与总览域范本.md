## REA1-侦察与总览域范本

### 范本概述

覆盖 REA1-01~REA1-03 的产物样式：状态摘要、核验记录、总览摘要。适用于取证的准备阶段，原则是"最小成本取得可推进的总览"。

### 范本正文

**【REA1-01 已有状态检查】状态摘要样例**：

```markdown
## 状态摘要
- 已有会话 ／ 证据：1 个（目标：{{目录路径}}，摘要哈希 {{sha256 前 12 位}}；CLI 通道按证据文件计）
- 可复用：{{上次分析已产出模块清单与概要，可直接读取}}
- 复用判定依据：目标摘要哈希一致
- 未决项回顾：{{查询路径尚未确认}}
```

**【REA1-02 目标打开与身份核验】核验记录样例**：

```markdown
## 目标核验记录
- 打开结果：{{会话已建立 ／ 快照已载入 ／ 证据已生成于 evidence/app-summary.json}}
- 身份核验：目标清单 {{N}} 个文件；入口 {{main.js / 可执行文件}}；版本标记 {{version 字段}}
- 快照：{{已保存至 用户指定路径 ／ 不需要}}；CLI 通道无快照态，改用 evidence-export 另存副本
- 备注：同时仅维护此一个活动目标
```

**【REA1-03 概要总览】总览摘要样例**：

```markdown
## 总览摘要
- 概要：模块 {{N}} 个、依赖 {{M}} 个、入口点 {{K}} 个
- 锚点候选：
  - 模块：{{search/index 模块，node_id=jag_node_xxx}}
  - 通道：{{search:run}}
- 覆盖与限制：{{静态分析覆盖全部源文件；动态加载模块未覆盖，标注为未知}}
- 下一步建议：从锚点 {{search 模块}} 进入 REA2 追踪
```

### 结构要点标注

1. REA1-01 复用必须给出一致性依据（如摘要哈希），目标不一致不得复用。
2. REA1-02 记录必须包含身份核验要素（清单/入口/版本），且只维护一个活动目标。
3. REA1-03 必须附"覆盖与限制"阅读结论；锚点要给出可引用的 node_id / 通道等具体标识。
4. 大目标未取概要不得直接全量深入。

### 替换清单

路径/哈希/模块数量/锚点名称替换为真实值；限制说明按实际返回的 limitations 字段改写；下一步建议按实际待回答问题调整。

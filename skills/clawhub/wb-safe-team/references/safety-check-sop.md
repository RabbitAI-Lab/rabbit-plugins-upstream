# 安全体检 SOP 手册（WB-SAFE）

给 AI 工作台（WorkBuddy 等 Agent 环境）做一次全面安全稳定体检的标准作业流程。

## Phase 0 · 前提验证

先列出用户诉求依赖的关键假设，逐条标注「事实 or 预判」。
高重要 + 低证据的假设，用最小成本动作先证伪（例：真去查积分余额，而不是假设"积分够"）。

## Phase 1 · 真实状态盘点（并行派单，全部离线）

| 检查项 | 责任专家 | 动作 |
|---|---|---|
| 连接器/MCP 实连数 | 连通官 | 读连接状态列表，不凭记忆 |
| 积分与 Token 余额 | 积分管家 | 查真实余额与消耗 |
| 凭据存放位置扫描 | 凭据官 | 扫敏感文件名 + 内容模式，查明文泄露（只报位置） |
| 配置文件基线校验和 | 配置审计官 | 与快照基线比对 |
| 整机七维指标 | 健康哨兵 | 算力/内存/磁盘/进程/网络/GPU/温度 |

## Phase 2 · 诊断分级

| 级别 | 判定 | 处置 |
|---|---|---|
| **P0 立即修** | 明文 Token 落盘、磁盘将满、凭据已泄露 | 当场出修复步骤 |
| **P1 建议修** | Token 超 90 天未轮换、连接器停摆、无配置快照 | 列入待办清单 |
| **P2 长效** | 自动化巡检缺失、备份策略待优化 | 沉淀为改进项 |

## Phase 3 · 处置

- **只读诊断类**：直接执行
- **敏感项必须单独请示**：删技能 / 断连接器 / 改自动化 / 删自动化 / 删文件 / 轮换生产 Token
- **要花积分的操作**：先报预估消耗，等用户点头

## Phase 4 · 入库留痕

- 配置快照递增版本号
- 变更写入审计记录（谁改的、改了什么、何时、校验和）
- 可复用流程沉淀为技能

## 出诊输出模板

```
# 安全体检报告 · <日期>

## 结论
- 综合风险等级：低 / 中 / 高
- 各维度状态一览表

## 发现项
- P0（立即修）：...
- P1（建议修）：...
- P2（长效）：...

## 处置清单
- 已完成：...
- 待用户确认：...
```

# Internationalization (i18n)

## Overview

Perry i18n is zero-ceremony at authoring time. String tables are extracted and embedded at compile time. CLDR plural rules for 30+ locales.

```typescript
import { i18n } from 'perry/i18n'
```

## Basic Usage

Strings are automatically extracted from:
- `i18n.t("Hello")` calls
- Template literals in widget text

No `.po`/`.json` files needed at authoring time.

## Plural Rules (CLDR)

```typescript
// Automatic plural form selection based on locale
i18n.t("You have {count, plural, one{# item} other{# items}}", { count: n })
```

Supports: zero, one, two, few, many, other forms. CLDR data covers 30+ locales including Arabic, Chinese, Japanese, Russian, Polish, etc.

## Format Wrappers

```typescript
import { Currency, Percent, FormatNumber, ShortDate, LongDate, FormatTime } from 'perry/i18n'

Currency(1234.56)          // "$1,234.56" (locale-aware)
Percent(0.85)              // "85%"
FormatNumber(1234567)      // "1,234,567"
ShortDate(new Date())      // "1/5/26"
LongDate(new Date())       // "January 5, 2026"
FormatTime(new Date())     // "3:45 PM"
```

## Interpolation

```typescript
i18n.t("Hello, {name}!", { name: "Perry" })
i18n.t("{count, plural, one{# file} other{# files}}", { count: files.length })
```

## CLI Tool

```bash
# Extract strings from source
perry i18n extract

# Outputs string table for all configured locales
```

## Configuration (perry.toml)

```toml
[i18n]
locales = ["en", "zh-Hans", "ja", "ko", "ar", "de", "fr"]
default_locale = "en"
dynamic = false          # true = load at runtime; false = embed at compile time
currencies = ["USD", "EUR", "CNY"]
```

## Compile-Time Validation

- Missing translations cause build warnings (not errors)
- Invalid plural forms caught at compile time
- String keys validated against source code usage
- Dead translations (unused keys) reported

## Locale Detection

At runtime, Perry uses the system locale by default. Override:
```typescript
i18n.setLocale("zh-Hans")
const current = i18n.getLocale()
```

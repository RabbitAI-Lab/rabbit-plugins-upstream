# 维普报告验真：可重复执行的判断逻辑

验真不是“打开一个网页输入任意长数字”，而是一条身份核对链：

```text
原订单 -> 报告文件 -> 报告编码 -> 官方验真页 -> 返回字段比对
```

## 一、三个编号先分开

| 编号 | 用途 | 能不能代替报告编码 |
|---|---|---|
| `orderNo` / 内部订单号 | 查询订单、支付页、进度页和 `/reports` | 不能 |
| 支付订单号、交易号或检测卡号 | 付款、客服定位或检测卡结算 | 不能 |
| 报告编码 | 报告生成后，官方验真页识别报告 | 只有它可以用于验真 |

如果用户只发来一串长数字，先问它来自哪里。不能根据长度、截图位置或“看起来像编号”直接判断。

## 二、标准验真步骤

1. 先在 `/reports` 用原 `orderNo` 找到报告，确认题目、作者和检测版本。
2. 打开 <https://vpcs.cqccjy.cn/pwp/verify>。
3. 选择与报告匹配的检测类型。查重、AIGC、格式、智评和专项报告不能随意互选。
4. 从报告首页复制**报告编码**，不要手打，也不要把订单号替换进去。
5. 只清理编码首尾的空格、换行、全角空格和不可见空白；编码内部字符、大小写、连字符和顺序保持原样。
6. 完成人机验证码并提交。
7. 把验真页面返回的信息与报告首页逐项对照。

建议至少比较这一组字段：

```text
(检测类型, 产品/版本, 题目, 作者, 检测时间, 主要指标, 单位/统计口径)
```

## 三、如何解释验真结果

### 1. 验真通过且字段一致

可以说明：该报告编码能被 VPCS 官方验真页面识别，页面返回信息与报告首页一致。这是报告来源和内容一致性的强证据。

仍然不能进一步保证：

- 学校、学院或单位会接受该公共报告；
- 报告覆盖学校私有自建库；
- 查重结果等于学校终检结果；
- AIGC 指标等于学校最终认定；
- 用户一定通过答辩、盲审、投稿或职称评审。

### 2. 验真失败或查不到

不要立即说“报告是假的”。先按顺序排查：

| 现象 | 排查顺序 |
|---|---|
| 报告不存在/编码无效 | 重新从报告首页复制；去掉首尾空白；确认没有把订单号或支付号当编码 |
| 类型不匹配 | 重新识别报告顶部的产品类型，再选择对应验真类型 |
| 返回信息不一致 | 核对是否拿错报告、作者/题目是否为演示信息、是否下载了另一份报告 |
| 页面打不开 | 直接输入固定 HTTPS 域名，换普通浏览器，确认不是搜索结果或旧域名 |
| 只有二维码或水印没有编码 | 二维码和水印只能辅助定位，不能代替报告编码 |

如果排查后仍失败，保存报告首页、验真页面和订单状态截图，联系平台或学校。不要修改 PDF、替换编码、截取部分字符或反复创建新订单。

## 四、验真与学校系统是两件事

官方验真回答的是“这个报告编码能否在 VPCS 公共验真页被识别，以及返回信息是否匹配”。学校系统还可能要求：

- 学校指定的检测入口；
- 学校账号或校内订单；
- 学校自己的数据库和报告编码；
- 特定版本、章节阈值或提交字段。

因此，“维普官方验真通过”和“学校系统能收录”不能互相推导。学校不认公共编码时，读取 [FAQ 3](faq/03-institution-code.md) 和 [FAQ 47](faq/47-self-built-database.md)，向学院或答辩秘书确认指定入口。

## 五、从截图中读取报告编码

当用户只提供图片时，按这个顺序处理：

1. 先定位报告首页顶部的 `NO.`、报告编号或报告编码字段；
2. 放大后逐字符核对 `0/O`、`1/I/l`、`5/S` 等易混淆字符；
3. 不把二维码、订单号、文件名或日期当成编码；
4. 在回复中只回显必要的部分，避免公开完整个人报告信息；
5. 让用户本人粘贴到官方验真页完成验证码。

示例图片里的编号、域名、日期和比例都是教学数据，不能直接套用到其他报告。

## 六、脚本和浏览器的分工

Python 脚本只负责返回 `browser_urls.verify`；验真需要在浏览器选择检测类型、输入报告编码并完成验证码。脚本不会自动提交验证码，也不会在没有官方返回数据时替用户下“真/假”结论。

真实验真必须在官方页面完成；脚本能做的是帮助 agent 保持三个编号不混淆，并把用户带到正确入口。

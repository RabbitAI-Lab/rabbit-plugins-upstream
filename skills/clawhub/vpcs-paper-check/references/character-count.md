# 维普字符数与计费：从本地预估到平台最终金额

这份资料解决一个最常见、也最容易误导用户的问题：**Word/WPS 看到的字符数，为什么和维普页面显示的字符数、购买件数或金额不一定相同？**

它的目标是教 agent 正确解释和排查，不是伪造一个“本地计算器”来替代维普解析。最终金额和是否需要补差，永远以维普订单返回的字段和页面显示为准。

## 一、先分清五个量

| 名称 | 常见字段或来源 | 该怎么理解 |
|---|---|---|
| 编辑器预估字符数 | Word/WPS“字符数（不计空格）” | 上传前的估算值；统计选项、脚注/尾注勾选和编辑器实现都会影响结果 |
| 平台解析字符数 | 订单 `wordCount` | 文件上传后，维普服务端按自己的解析规则统计出的实际字符数 |
| 计费字段 | 订单 `billingWordCount`，脚本输出 `billing_word_count` | 服务端用于计费或计费展示的字段；不要未经页面说明就把它改称“纯文本字符数” |
| 初始购买量 | 页面或订单的 `expectWordCount`、购买件数等字段（若返回） | 用户下单时预先购买的字符档位或数量 |
| 超出与补差 | `shortWordCount`、`supplementWordCount`、`supplementAmount`、`needSupplement`（若返回） | 解析后超过初始购买量时，页面用于补差/补单的提示，不是检测失败 |

回答用户时，先说清楚你看到的是哪一个量。不要把“字数”“中文字符数”“英文单词数”“页面字符数”和“计费字符数”混成一个数字。

## 二、上传前怎么做有用的预估

1. 打开最终要上传的同一个 Word/WPS 文件。
2. 使用“审阅 → 字数统计”或 WPS 的字数统计功能。
3. 记录**字符数（不计空格）**，不要只记录“字数”或“非中文单词”。
4. 记录是否勾选了“包括文本框、脚注和尾注”等选项；以后比较时必须使用同样的选项。
5. 不要为了让数字变小而删除标点、数字、英文、脚注、表格或引用。维普如何解析这些内容，只有平台解析后才能确认。

可以把编辑器数字记为 `C_pre`。它的用途只有两个：

- 判断是否明显接近平台的字符上限；
- 提前估算普通查重版或职称版大概要落在哪个档位。

它不能直接替代 `wordCount` 或 `billingWordCount`。

## 三、FAQ 所说的档位估算

FAQ 8 将普通查重描述为按千字符档位计费，职称版常按万字符档位计费，不满一个档位通常向上取整。用来做**估算**时可以写成：

```text
普通查重估算件数 = ceil(C_pre / 1000)
职称版估算件数   = ceil(C_pre / 10000)
```

例如：

| 本地预估字符数 | 普通查重估算 | 职称版估算 |
|---:|---:|---:|
| 2,904 | 3 个千字符档位 | 1 个万字符档位 |
| 11,000 | 11 个千字符档位 | 2 个万字符档位 |
| 12,000 | 12 个千字符档位 | 2 个万字符档位 |
| 20,001 | 21 个千字符档位 | 3 个万字符档位 |

这张表只用于解释“为什么差一点字符可能多一档”。正式价格仍然以当前产品的 `pricingMode`、`priceUnit`、订单解析结果和页面金额为准。AIGC、格式、智评和专项产品通常按篇，不要把它们套进千字符公式。

## 四、维普页面的真实判定链

当前 `/pwp` 的有价值流程不是“上传后立刻付款”，而是：

```text
创建草稿
  -> 上传文件
  -> COUNTING / PARSING
  -> 服务端返回 wordCount 等解析字段
  -> 页面展示产品、字符数、件数、金额
  -> 用户核对后支付
  -> 必要时补差或补单
  -> 提交检测
```

状态为 `COUNTING` 或 `PARSING` 时，字符数和金额可能还没有最终确定。此时不要替用户猜价格，也不要重复建单。

当订单出现 `WAIT_SUBMIT` 且 `needSupplement=true` 时，优先检查：

- `wordCount`：平台解析出的字符数；
- `shortWordCount` 或 `supplementWordCount`：超出的数量；
- `supplementAmount`：补差金额；
- `canSupplementPay`：当前是否能在页面补差；
- `supplementPayStatus`：补差支付是否正在确认。

这表示初始购买量不足或需要补差，通常不表示文件损坏或检测失败。用户应回到同一订单页面处理，不要创建第二笔订单。

## 五、为什么本地和平台会不同

差异通常来自以下层次，不能简单归因于“平台算错”：

1. Word/WPS 对空格、换行、分页符、域代码和隐藏内容的处理不同；
2. 脚注、尾注、文本框、表格、公式和图片中的文字是否被解析；
3. PDF、WPS、DOC、DOCX 的解析器不同；
4. 平台可能把标题、作者、正文或特定结构纳入不同统计口径；
5. 本地统计显示的是预估字符数，服务端字段是上传文件解析后的结果；
6. 产品的计价单位不同，查重版和职称版不能共用一个除数。

因此，专业回答应该说：

> Word/WPS 的“字符数（不计空格）”可以预估档位，但最终以维普订单返回的解析字符数、计费字段和页面应付金额为准。若页面出现补差提示，应在原订单中处理，不要通过删内容或拆单规避。

## 六、字符上限和文件处理

当前 Skill 的配置快照记录 `maxWordCount=500000`、提示范围 `hintMinWordCount=200` 至 `hintMaxWordCount=500000`；这些字段会变化，最新值应从 `/pwp` 页面或配置接口读取。

- 接近上限时，先确认产品、文件格式和页面提示，再上传；
- 超过上限不要自行拆成多单，先看页面是否支持补单或联系客服；
- 不通过图片化正文、隐藏字符、改扩展名、删除脚注或拆文件来规避计费/检测；
- 如果用户只想检测一段文字，必须说明这会改变检测对象和结果，不能把节选报告当作终稿报告。

## 七、给用户的最短专业答复

```text
你可以先看 Word/WPS 的“字符数（不计空格）”做预估：
普通查重按每 1000 字符一个档位，职称版通常按每 10000 字符一个档位。
但这只是估算，上传后维普还会按文件解析出 wordCount 和计费字段，
最终件数、金额以及是否补差以原订单页面为准。请不要在解析完成前付款，
也不要因为数字不同就重复建单。
```

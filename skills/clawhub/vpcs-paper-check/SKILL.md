# 维普 VPCS 全流程 Skill

本 Skill 面向配置的 VPCS 公共用户端：<https://vpcs.cqccjy.cn/>。它把产品选择、官方 FAQ、浏览器页面操作、`/pwp` 的公开接口、订单状态、报告下载和报告验真串成一个可交接的工作流。

它覆盖的是 15 个独立商品，不允许用一个模糊的“维普检测”代替具体商品：

- 维普查重大学生版、维普查重研究生版、维普查重编辑部版、维普查重职称版、维普查重作业版、维普查重科研版；
- 维普AIGC检测；
- 维普格式检测·大学生版；
- 维普斟知智评·大学生版、维普斟知智评·研究生版、维普斟知智评·期刊版；
- 维普参考文献质量检测、维普斟校对、维普数据与图像可信度检测·专业版、维普数据与图像可信度检测·标准版；
- 订单自动化：创建草稿、取得上传票据、OSS 上传、完成绑定、查询订单、交接支付、跟随页面进入检测、获得真实报告地址；
- 报告服务：`/reports` 查看/下载、报告编码验真、FAQ 问答和示例图定位。

## 一、使用顺序

本文件已经内置产品知识、报告解释和 FAQ 的回答口径。参考文件用于查证来源、读取接口字段和执行脚本，不应让用户或 agent 重新拼接基本答案：

1. 先读本文件，判断用户要的是产品选择、页面流程、API 操作、报告解释还是 FAQ。
2. 产品名称、别名、用途、文件格式、支付方式、字符上限和报告保留期已经固化在本 Skill 与 `references/product-catalog.md`；不需要为了回答产品选择而调用 Python 脚本。当前价格以 `/pwp` 页面为准。
3. FAQ 按文章拆分保存在 [references/faq/](references/faq/)，先读目录，再按问题读取对应的独立 Markdown；本文件后面的 FAQ 知识库是直接可用的回答版本。
4. 要创建订单或上传文件，读 [references/workflow.md](references/workflow.md) 和 [references/api-contract.md](references/api-contract.md)，再运行 `scripts/vpcs_client.py`。
5. 要解释字符数、计费档位或补差，先读 [references/character-count.md](references/character-count.md)；要解释报告编码或验真，读 [references/report-guide.md](references/report-guide.md) 和 [references/verification-logic.md](references/verification-logic.md)，需要定位页面元素时查看 `assets/report-guides/`。
6. 域名、页面和 API 只从 [domains/cqccjy.json](domains/cqccjy.json) 读取；不要让用户参数覆盖基域名。

## 二、不可违反的边界

### 站点与数据边界

- 只访问 `https://vpcs.cqccjy.cn` 及 `domains/cqccjy.json` 中声明的路径。
- 不把搜索结果、短链、截图中的其他域名或 `vpcs.fanyu.com` 自动替换成当前入口。
- 订单号、报告编码、支付订单号和报告内容是用户数据。回答中只回显必要字段；OSS 临时凭证、签名 URL、访问密钥和文件内容不输出。
- 不把用户文件上传到未经用户同意的第三方服务。用户没有明确同意上传时，只给浏览器入口，不执行 `submit`。

### 支付和提交边界

- Python 客户端只提供两条命令：一次性提交（建草稿、上传、完成绑定）和订单状态查询；两条命令都会返回适合交给浏览器的页面 URL。绝不自动支付、填写支付密码、读取银行卡、读取检测卡密或绕过验证码。
- 支付后的“立即检测”由当前 `/pwp` 页面自动处理或由用户在进度页点击；脚本不再提供独立的自动提交检测命令，避免 agent 重复提交。
- 打开过支付页不等于已支付；支付状态以订单 API 返回的 `payStatus`、`paymentFlowState` 和页面能力字段为准。
- 接口超时、页面卡顿或状态未知时，用原 `orderNo` 查询，不创建第二笔订单、不重复提交。

### 结果解释边界

- 维普查重、AIGC、格式、智评和专项检测是不同产品，不能用一个指标替代另一个指标。
- 维普公开库、自建库和学校定制系统的结果可能不同。通过维普官方验真不等于学校教务系统会接受。
- FAQ 中的学校阈值、平台导流和“安全线”文章不是学校正式通知；回答合格线必须要求用户提供本校本年度通知。
- 只有报告接口返回真实 HTTPS 下载地址时才输出下载链接；禁止根据订单号、文件名或截图猜 URL。

### 产品组合建议

组合是分阶段自查，不是把一个产品当成另一个产品：

- 本科定稿：`dxs` + 按学校要求的 `aigc` + `format_dxs`；
- 硕博定稿：`yjs` + 按通知决定的 `aigc` 或 `zzzp_yjs`；
- 期刊投稿：`bjb` + `zzzp_qkb` + `special_ref_quality`；
- 科研材料：`ky` + `special_data_image_standard` 或 `special_data_image_pro`；
- 课程作业：`zy`；课程另有 AI 要求时再加 `aigc`。

### 计费与数据库边界

- 维普解析结果是最终计费依据；Word/WPS 的“字符数（不计空格）”只能预估。
- 脚注、尾注、文本框、表格、公式、图片文字和文档格式都可能造成解析差异。
- 不通过拆文件、图片化正文、改扩展名或隐藏字符规避计费/检测。
- 查重范围通常包括中文科技期刊、博士/硕士学位论文、外文特色文献、报纸、专利、会议、古籍/图书、IPUB、互联网数据/文档、港澳台、优先出版和年鉴；不同 SKU 组合不同。
- “高校/机构/个人自建资源”是页面范围标签，不等于校外订单能读取任意学校私有论文库。解释结果差异时必须同时说明版本、库更新时间、文档解析和私有库四个因素。

### 字符数的实际判定链（重点）

不要只回答“按字数收费”。用户真正需要知道的是：**本地能预估，平台负责最终解析和计费**。

1. Word/WPS 的“字符数（不计空格）”记为预估值 `C_pre`，先记录是否包含文本框、脚注和尾注；
2. 上传后订单进入 `COUNTING`/`PARSING`，此时 `wordCount`、计费字段和金额可能尚未最终确定；
3. 服务端返回 `wordCount`、`billingWordCount`、购买量/件数和 `payAmount` 后，才核对实际档位；
4. 普通查重可以按 `ceil(C_pre / 1000)` 估算档位，职称版按 `ceil(C_pre / 10000)` 估算；AIGC、格式、智评和专项按篇的产品不能套用这个公式；
5. 如果订单出现 `WAIT_SUBMIT` + `needSupplement=true`，优先检查 `shortWordCount`、`supplementAmount` 和 `canSupplementPay`，这通常表示需要补差，不要重复建单；
6. 最终金额、是否需要补差和是否允许提交，以原订单页面和服务端字段为准，不以本地估算数字为准。

完整的字段说明、公式、示例和补差判断见 [references/character-count.md](references/character-count.md)。

完整的逐产品别名、文件限制、价格字段和报告重点见 [references/product-catalog.md](references/product-catalog.md) 与 [references/product-catalog.json](references/product-catalog.json)。

## 五、浏览器完整业务流程

### 1. 准备文件和元数据

确认用户要提交的是最终排版文件，而不是摘要、节选或临时稿。当前脚本默认允许 `.doc`、`.docx`、`.txt`、`.pdf`、`.wps`、`.rtf`，单文件上限 50 MB；页面实时限制优先。

- 题目：当前前端校验最多 128 个字符；不能为空。
- 作者：当前前端校验 2-20 个字符，不能是纯符号；不要用长机构名代替作者字段。
- 职称版：页面或接口要求 `publishDate` 时才填写，格式以页面为准。
- 先用 Word/WPS 查看“字符数（不计空格）”，记录统计口径，不把这个数字当最终计费数。

### 2. 页面下单

打开 <https://vpcs.cqccjy.cn/pwp>，确认地址栏域名，选择产品，填写标题/作者，上传文件。等待解析完成后检查：

1. 产品版本是否正确；
2. 题目、作者是否正确；
3. 平台解析字符数和计费件数；
4. 应付金额和可用支付渠道；
5. 文件是否确实是最终稿。

### 3. 支付并进入检测

实时配置当前可能包含：检测卡号、微信支付、支付宝。用户在页面自己选择和确认。脚本输出支付页链接，但不收集支付密码、卡密、验证码或银行卡信息。

### 4. 检测等待

支付成功后回到原订单进度页。当前页面通常会在支付回调确认后自动提交检测；如果订单进入可提交状态，页面会显示“立即检测”，由用户在页面点击一次。脚本不重复调用这个动作。

常见状态：

```text
PENDING_UPLOAD -> COUNTING/PARSING -> WAIT_SUBMIT -> DETECTING -> REPORT_READY
                                      \-> FAIL
```

状态名可能变动，优先看服务端 `status`、`statusLabel`、`canSubmitDetect`、`canDownloadReport`、`needSupplement`、`shortWordCount` 和 `failReason`：

- `COUNTING`/`PARSING`：平台仍在解析文件和字符数，不要提前判断金额或检测失败；
- `WAIT_SUBMIT` 且 `needSupplement=false`：解析已完成，按页面提示等待自动提交或由用户点击一次“立即检测”；
- `WAIT_SUBMIT` 且 `needSupplement=true`：初始购买量不足，查看超出字符数和补差金额，回到原订单处理；
- `DETECTING`：已提交供应商检测，使用原订单查询，不重复点击；
- `REPORT_READY`：报告已生成，进入 `/reports` 查看/下载，再用报告编码验真；
- `FAIL`：先看 `failReason` 和页面是否仍允许重试/联系客服，不要把网络超时直接说成检测失败。

### 5. 报告查看、下载、解压

进入 `browser_urls.reports` 或 <https://vpcs.cqccjy.cn/reports>，按订单号查询。下载后：

1. 如果是压缩包，先保存到本地并解压；
2. 用 PDF 阅读器查看简洁报告、全文报告、片段对照等文件；
3. 核对报告首页的品牌、版本、题目、作者、时间、报告编码和水印；
4. 需要真伪结论时，再去 `/pwp/verify`，不要只凭外观或水印判断。

报告保留天数默认按配置快照的 7 天回答；只有用户明确要求最新规则时，才查看当前页面或配置字段。下载完成后不要拖到保留期末。

### 6. 官方验真

1. 打开 <https://vpcs.cqccjy.cn/pwp/verify>。
2. 选择与报告匹配的检测类型（查重或 AIGC 等）。
3. 从报告首页复制**报告编码**，不是订单号、支付订单号或检测卡号。
4. 只清除编码两端的空格、换行和不可见字符；编码内部字符、大小写、连字符和顺序不要改。
5. 完成页面验证码并提交。
6. 对照返回的题目、作者、检测类型、时间、主要指标和统计单位；不一致时保存页面并联系平台/学校。

验真通过能说明报告编码被 VPCS 官方页面识别，且返回信息与报告首页一致；不能据此推导学校一定接收、覆盖学校私有库、结果等于学校终检或用户一定通过答辩。验真失败也不能立刻下“假报告”结论，应先按类型、编码空白、报告是否拿错和域名逐项排查。完整判断树见 [references/verification-logic.md](references/verification-logic.md)。

## 六、Python 接口：两个最小命令

脚本位置：`scripts/vpcs_client.py`。只依赖 Python 标准库，通过固定域名调用公开 `/pwp` API。它只保留 `submit` 和 `status`，不会自动支付、提交验证码或下载报告。

### 1. 提交论文，返回订单号和浏览器链接

```bash
python3 scripts/vpcs_client.py submit \
  --product-type "维普查重大学生版" \
  --title "论文题目" \
  --author "作者姓名" \
  --file ./论文.docx
```

必要参数只有 `--product-type`、`--title`、`--author` 和 `--file`；页面需要发表日期时再传 `--publish-date`。

脚本内部自动完成：

```text
create-draft -> upload/presign -> OSS 上传 -> upload/complete -> order 查询
```

成功输出至少包含：

- `order_no`：后续查询使用的订单编号；
- `browser_url`：根据当前状态选择的下一步页面；
- `browser_urls.payment`：支付页；
- `browser_urls.progress`：进度页；
- `browser_urls.reports`：报告查看/下载页；
- `browser_urls.verify`：报告验真页。

把 `browser_url` 交给用户即可。脚本不会把“上传完成”说成“已经支付”，也不会根据订单号猜报告下载直链。

### 2. 查询订单状态，返回下一步浏览器链接

```bash
python3 scripts/vpcs_client.py status --order-no 2104087082852179968
```

这是幂等查询。支付回调延迟、解析中、检测中或报告尚未生成时，都查询同一个订单号。

`browser_url` 的选择规则：

- `REPORT_READY`、`COMPLETED` 或 `canDownloadReport=true`：报告页；
- 已支付、解析中或检测中：进度页；
- 其他情况：支付页。

同时保留 `status`、`status_label`、`pay_status`、`word_count`、`billing_word_count`、`need_supplement`、`can_supplement_pay` 和 `fail_reason` 等服务端字段，方便 agent 判断是否继续打开链接或稍后查询。

### 3. 先做本地检查

正式上传前可运行：

```bash
python3 scripts/vpcs_client.py --dry-run submit \
  --product-type dxs --title "论文题目" --author "作者" --file ./论文.docx
```

它只检查文件、扩展名、大小、题目和作者，不创建订单、不上传文件。`--dry-run` 可以放在子命令前或后。

## 七、失败与恢复

| 失败点 | 应做什么 | 不应做什么 |
|---|---|---|
| 题目/作者/文件校验失败 | 修正本地输入后再试 | 不发送半成品请求 |
| 草稿接口失败 | 记录错误，确认没有订单号再重试 | 未确认结果就重复建单 |
| 预签名/OSS 上传/完成绑定失败 | 保留原 `orderNo`，先 `status` | 直接创建第二单 |
| 支付页打开但仍未支付 | 在原页面刷新/更换渠道，必要时联系客服 | 把打开页面当成支付成功 |
| 支付回调延迟 | 用原订单号查询 | 重复付款或提交 |
| 页面提交检测超时 | 用 `status` 查询 `DETECTING`/`REPORT_READY`，再打开返回的浏览器链接 | 重复点击页面按钮或创建第二单 |
| 报告未完成 | 给出进度页并稍后查询 | 伪造报告 URL或承诺完成时间 |
| 报告下载失败 | 换普通浏览器，保存压缩包后解压 | 在微信内反复点击或改 URL |
| 验真失败 | 检查类型、编码首尾空格和验证码 | 用订单号代替报告编码、修改报告 |
| 需要退款 | 依据 FAQ 7 联系平台客服，说明系统是否“检测失败” | 承诺必然退款 |

脚本错误码为 `2`；错误输出应只保留可行动信息，不把请求票据、堆栈或文件内容复制给用户。

## 九、FAQ 回答规则

FAQ 的作用不是把网页原文再说一遍，而是帮助用户完成一个判断。回答每个 FAQ 时尽量按下面的结构：

```text
用户遇到的现象
  -> 造成现象的业务原因
  -> 用户现在要核对的字段/证据
  -> 下一步可以执行的操作
  -> 这个操作不能保证什么
```

例如“字符数为什么不一样”要落到 `C_pre → wordCount/billingWordCount → payAmount` 的链路；“报告是真是假”要落到 `orderNo → 报告编码 → 官方返回字段` 的链路。没有改变用户决策的网页宣传句，不要单独扩写成结论。

### 高频问题

- **“哪个版本最合适？”** 先问材料类型和学校/期刊指定版本，再结合 [product-catalog.md](references/product-catalog.md) 的本地目录判断；只有用户要求当前可用项或动态价格时，才查看 `/pwp` 页面。
- **“为什么 Word 字符数和维普不一样？”** 先读取 [character-count.md](references/character-count.md)，区分本地预估、`wordCount`、`billingWordCount` 和补差字段；告诉用户最终以平台解析和订单金额为准。
- **“AIGC 是不是查重？”** 不是；AIGC 看疑似 AI 生成特征，查重看数据库相似性。
- **“维普和学校结果为什么不同？”** 数据库、文档解析、私有自建库、阈值和提交版本可能不同；不能保证一致。
- **“微信不能下载怎么办？”** 换 Edge/Chrome 等普通浏览器，打开 `/reports`，保存压缩包并解压。
- **“怎么验真？”** 先用原 `orderNo` 找到报告，再读取 [verification-logic.md](references/verification-logic.md)，选择匹配类型，输入报告编码，清理首尾空格，完成验证码并比对返回字段。
- **“学校系统不认怎么办？”** FAQ 3 的口径是学校/定制系统只识别自己的报告编码；向学校确认指定系统。
- **“能退吗？”** FAQ 7 只把系统明确“检测失败”列为咨询场景；重复率高低、结果不满意或等待时间长不能直接承诺退款。
- **“某大学查重率多少合格？”** FAQ 40-46 是站点文章，不是校方通知；要求用户提供本年度正式规定。

### 旧 FAQ 与当前 `/pwp` 的兼容

FAQ 2、6、8 等旧文章多次写“淘宝订单号”和“购买检测件数”。当前用户端前端已经使用 `create-draft -> presign -> OSS -> complete -> order -> pay -> 页面自动/手动提交检测` 的订单链路，接口返回的内部 `orderNo` 才是本 Skill 脚本的查询键。遇到页面显示旧字段时，应让用户按当前页面要求操作，但不能把淘宝订单号、支付订单号、检测卡号和报告编码混用。

## 十、专业报告解读知识

### 1. 先识别报告类型

拿到用户截图、PDF 或压缩包时，先判断报告顶部的品牌和类型：维普查重报告、维普 AIGC 报告、格式检测、斟知智评或专项检测。报告类型决定指标含义和验真时要选择的检测类型。不能因为报告都出现“维普”或同一个订单页面，就把它们当作同一份报告。

### 2. 查重报告常见字段

不同模板的字段可能增减，但可以按以下顺序解释：

| 字段 | 专业解释 | 回答时的边界 |
|---|---|---|
| 报告编号/报告编码 | 报告在官方验真页面的识别键 | 不是订单号、支付号或检测卡号；输入验真页时清除首尾空格 |
| 论文字符数/字数 | 报告解析后的文本统计值 | 不必然等于 Word/WPS 预估，也不等于计费字符数的所有细节 |
| 论文页数、表格数、图片数 | 文件解析得到的结构统计 | 只能描述文件结构，不能据此判断质量或真伪 |
| 全文总相似比/文字复制比 | 报告定义范围内的相似文本占比 | 以报告公式和版本说明为准，不跨系统直接比较 |
| 相似片段 | 与数据库来源重合的文本片段 | 需要结合来源、引用和语义判断，不把每个标红句都称为抄袭 |
| 来源类型/来源列表 | 命中的期刊、学位论文、报纸、互联网等库来源 | 公开库不等于学校私有库；来源日期和库范围可能影响结果 |
| 自引、他引、专业术语等分项 | 报告模板对相似来源的分类统计 | 不要把“自引”自动解释成可以忽略，仍需按学校规则处理 |

字符数相关字段必须单独解释，不能只报一个数字：

| 字段 | 判断方法 |
|---|---|
| `wordCount`/论文字符数 | 服务端解析后的文本统计，最接近报告实际对象，但仍受文件解析和模板影响 |
| `billingWordCount`/计费字段 | 用于计费或计费展示的服务端字段；必须连同产品计价单位解释 |
| 购买件数/初始字符量 | 支付前购买的档位，不一定等于上传后最终解析字符数 |
| `shortWordCount`/超出字符数 | 订单需要补差时的超出量，出现它不等于检测失败 |

报告中的百分比只能在同一报告、同一版本、同一统计口径下解释。不要把维普的总相似比、其他平台的重复率和 AIGC 疑似率放到同一张表里直接比较高低。

### 3. AIGC 报告怎么解释

维普 AIGC 报告通常展示“疑似 AIGC 生成占比”和“人工撰写占比”等指标，并可能标出可疑段落。专业回答应包含：

1. 这是模型对语言特征的概率性判断，不是作者身份或违规事实的证明。
2. 低比例不能证明全文没有使用 AI，高比例也不能脱离写作过程和学校规则独立认定违规。
3. 关注被标出的段落是否存在模板化、过度工整、事实空泛、引用缺失等问题；优先回到原始研究、实验记录和个人表达进行人工修订。
4. 学校如果有 AIGC 红线、申诉材料或过程记录要求，必须遵循学校规则；不要用某个 FAQ 文章的 15%、20% 或 30% 直接代替校方阈值。

### 4. 格式检测和智评怎么解释

- 格式检测的输出是排版、章节、字体、编号、引用、参考文献和标注等问题的提示。学校若有自定义模板，格式检测报告只能作为预检，不能保证通过学校格式审查。
- 斟知智评可能从选题、摘要、结构、论证、创新、语言、规范性等维度给出评阅建议。它是辅助评阅和修改清单，不是盲审意见、答辩结论或期刊录用承诺。
- 参考文献质量、斟校对、数据/图像可信度报告只说明专项风险；不能用专项报告替代完整查重，也不能把“未发现问题”改写成“绝对真实/绝对合格”。

### 5. 报告真伪核对的证据层级

按照可靠性排序：

1. 官方验真页面返回的报告类型、题目、作者、时间和指标；
2. 报告编码与页面返回数据一致；
3. 报告内部的题目、作者、版本、时间和订单信息互相一致；
4. PDF 水印、二维码、文件名和版式外观，仅作为辅助线索。

只看到水印、二维码或一张截图，不能直接宣称真报告。验真失败时先检查类型选择、编码首尾空格、全角半角字符和验证码；不要把订单号当成报告编码。

验真时采用固定判断链：`orderNo` 用来找报告，报告首页的报告编码用来验真，验真页返回的字段用来做一致性比对。不要因为三个编号都很长，就把它们当成同一个字段。需要给用户可执行步骤时，直接引用 [references/verification-logic.md](references/verification-logic.md)。

### FAQ 1：维普有哪些产品，应该怎么选？（FAQ 8） · [独立资料](references/faq/08-products-pricing.md)

维普 FAQ 将服务分为论文查重、AIGC、格式检测、斟知智评和专项检测。查重产品包括大学生版、研究生版、编辑部版、职称版、作业版和科研版；AIGC 用于疑似 AI 生成特征分析；格式检测用于排版/标注；智评用于论文或期刊稿件综合质量分析；专项检测分别检查参考文献、文字校对、数据和图像可信度。

按计费方式，页面 FAQ 将普通查重描述为按“不计空格”的字符档位计费，职称版常以万字符为单位；AIGC、格式、智评和专项通常按篇。Skill 已内置 2026-09-27 价格和上限快照；只有用户要求当前值时，才查看 `/pwp` 页面中的当前配置。

报告入口是 <https://vpcs.cqccjy.cn/reports>，报告可能以压缩包提供，需要解压软件和 PDF 阅读器。报告支持官方验真，但验真通过不代表学校定制系统一定接收。

### FAQ 2：查重、AIGC 和智评有什么区别？（FAQ 2） · [独立资料](references/faq/02-report-overview.md)

查重看文本与数据库内容的相似性；AIGC 看文本是否呈现疑似机器生成特征；智评看选题、结构、论证、表达和综合质量。三者的算法目标、指标和报告都不同，不能用 AIGC 百分比回答查重率，也不能用查重率证明文章质量。

FAQ 2 的旧版教程还写了“直接打开网址、选版本、填标题作者、上传排版正确的文档、按字符数购买件数、支付后用淘宝订单号提交检测、3-30 分钟完成、去 `/reports` 下载”。当前 `/pwp` 版本已经返回内部 `orderNo` 并支持页面支付和订单状态，脚本以 `orderNo` 为查询键；旧文中的淘宝订单号是历史交接口径。

### FAQ 3：提交前怎么操作，为什么强调域名和浏览器？（FAQ 6） · [独立资料](references/faq/06-tutorial.md)

把 `https://vpcs.cqccjy.cn/` 直接粘贴到浏览器地址栏，核对协议、域名和字母顺序，不要通过搜索结果或陌生短链进入。页面 FAQ 推荐 Edge；微信内置浏览器可能影响支付或下载，遇到问题应换普通浏览器。

选择版本后填写标题、作者，上传最终排版文件。等待平台解析后核对字符数、件数、产品和金额；支付完成后回到原订单提交检测。报告完成后进入“我的报告”。不要将摘要、节选或临时版本误上传为终稿。

### FAQ 4：微信里不能下载报告怎么办？（FAQ 5） · [独立资料](references/faq/05-wechat-download.md)

复制首页或 `/reports` 链接到 Edge、Chrome 等普通浏览器，输入原订单号查询。报告若为压缩包，先保存再解压；安装 PDF 阅读器。仍然失败时联系客服并按要求提供支付订单号截图，不能把完整支付密码、验证码或身份证信息发给客服之外的人。

### FAQ 5：报告怎么验真？（FAQ 4） · [独立资料](references/faq/04-report-verification.md)

打开 <https://vpcs.cqccjy.cn/pwp/verify>，选择匹配的检测类型，从报告首页复制报告编码，删除首尾空格和换行，完成验证码后提交。核对页面返回的题目、作者、版本、时间和指标。FAQ 明确提醒报告编号前后不能有空格。

### FAQ 6：报告编码为什么不能交到学校系统？（FAQ 3） · [独立资料](references/faq/03-institution-code.md)

学校、机构、毕设或定制版系统可能只识别自身检测链接生成的编码。维普官方验真页面能识别，不代表学校教务系统能接收；遇到提交失败，应向答辩秘书、学院或研究生院确认指定系统、版本和编码格式，不能通过改写报告编码解决。

### FAQ 7：什么情况可以退款？（FAQ 7） · [独立资料](references/faq/07-refund.md)

页面把检测视为虚拟检测产品。提交成功、开始检测、生成报告后，通常不支持退款；重复率高/低、与学校不同、不满意、误下单、等待时间长或不想使用，不能直接推导出退款资格。只有系统明确提示“检测失败”时，才进入客服/平台退款咨询范围。Skill 只能说明页面规则，不能承诺平台一定退款。

### FAQ 8：学校查重率多少算合格？（FAQ 40-46） · [独立资料目录](references/faq/README.md)

FAQ 40-46 是站点发布的高校 SEO/指南文章，列出了本科常见 10%-20% 或 15%-30% 分档、硕博常见 5%-10% 参考、AIGC 15%-20%/30% 等文章数字，并分别讨论武汉大学、华中科技大学、四川大学、郑州大学、中山大学、山东大学的示例阈值。

这些数字不能直接作为任何学校当前标准，因为阈值会按年份、学院、学科、学位层次和指定系统变化。专业回答必须这样处理：

1. 说明这些是 FAQ 文章的参考描述，不是校方通知；
2. 要求用户提供本年度教务处、研究生院、学院或导师的正式文件；
3. 只有拿到正式规则后，才把报告字段与阈值逐项对照；
4. 对“安全线”“红线”“保证通过”等词保持怀疑，不做通过承诺。

文章中各校的具体示例，完整记录如下，全部只能作为“待核对文章内容”：

| 文章 | 正文给出的示例分档 | 额外内容 | 回答限制 |
|---|---|---|---|
| FAQ 40 全国高校 | 本科常见 R<10%-15% 为合格/优秀参考，15%-30% 可能整改，>30% 可能延期；硕博常见 5%/10%/10%-20% 分档；AIGC 15%-20% 被描述为相对安全，>30% 为预警 | 提到毕业季和多个检测/降重入口 | 不是全国统一规定，不能给用户承诺 |
| FAQ 41 武汉大学 | 本科 R≤10% 优秀参考，10%-20% 合格，20%-30% 整改，>30% 可能取消答辩；硕博送外审通常 ≤10%，部分学科 ≤5% | 提到不同学部可能指定知网或维普，并建议先问答辩秘书 | 以本届学院/学部通知为准 |
| FAQ 42 华中科技大学 | 本科 ≤10% 直接通过/优秀参考，10%-20% 原则通过，20%-30% 限期修改；硕士通常 ≤10% 或部分院系 ≤8%，博士建议 ≤5% | 提到代码复制、实验方案和医学综述的风险 | 不能代替学院和医学部规则 |
| FAQ 43 四川大学 | 本科 ≤15% 合格，15%-25% 修改复检，>25% 可能延期；硕士通常 ≤10%，博士建议 ≤5% | 提到 AIGC 初稿筛查和终稿复核 | 文章关于不同平台结果差异没有通用保证 |
| FAQ 44 郑州大学 | 本科 ≤10% 优秀参考，10%-20% 通过，20%-30% 整改；硕士通常 ≤10%，法学/经管等可能 ≤8% | 提到院系可能使用知网或维普 | 先确认院系、学位层次和年份 |
| FAQ 45 中山大学 | 本科 ≤10% 直接通过/评优参考，10%-20% 需导师复核，>20% 整改；硕博送盲审建议 ≤8%，章节原则上不超过 10% | 全英文项目可能要求 Turnitin | 不能把维普自查当作学校指定国际系统 |
| FAQ 46 山东大学 | 本科 ≤15% 合格，15%-30% 限期修改，>30% 可能延期；硕博外审通常 ≤10%，部分医学/文科建议 ≤5%-8% | 提到 AIGC 初稿与终稿两阶段 | 一校三区和学院可能不同 |

这张表的作用是帮助 agent 识别用户在问“文章里的哪条口径”，不是替用户做学校判定。若用户没有提供正式通知，回答只能说“文章如此描述，但需以校方文件为准”。

### FAQ 9：为什么校外自查和学校结果不同？（FAQ 47） · [独立资料](references/faq/47-self-built-database.md)

高校可能使用内部私有自建库、机构资源或联合比对库，外部商业平台通常无法公开接入。结果差异还可能来自检测版本、数据库更新时间、文档解析和统计规则。不要相信“100% 包含某校私有库”的广告；维普自查的正确用途是发现公开文献、互联网和常见来源的风险，不能保证学校终检相同。

减少风险的专业建议是：不直接复用往届论文原句，保留真实研究过程和数据，逐句核对引用来源，向学校确认最终指定系统。不要把“真实数据”表述成任何系统都不会标红。

### FAQ 10：FAQ 中提到的其他平台能否直接使用？（FAQ 40-46）

部分扩展文章列出了知网、万方、Turnitin、PapersVIP AIGC 和降重页面。这些是文章中的导流或背景链接，不属于本 Skill 的 VPCS API 合约。用户明确要使用其他平台时，应切换到对应平台的专用 Skill/流程；不要用本 Skill 的域名、接口或订单号替换其他平台。

### 必须先追问的情况

- 用户说“维普查重”但没有说明本科/研究生/期刊/职称/作业/科研；
- 用户只给了“AI 率”但没有说明是 AIGC 还是智评；
- 用户要求学校“保证通过”或给出一个全国统一阈值；
- 用户提供订单号但未说明是否已支付；
- 用户给的是支付订单号或截图中的长数字，却称其为报告编码；

# 角色称呼与别名核对

只做人物姓名、别名及称呼指代的机械一致性检查。不要扩写角色弧线、对白潜台词、关系剧情，也不要把相同姓名的人自动合并。

## 输入

请提供三部分内容，范围最多 30 个角色、100 条称呼片段：

1. `角色表`：每人一个稳定 ID、实名、已确认别名；同名人物必须使用不同 ID。
2. `称呼规则`：`说话人 ID → 称呼 → 对象 ID`，仅列已经批准的关系称呼。
3. `正文`：每处需有章节或段落锚点；称呼 mention 提供 `speaker` 与 `target`。缺任一字段均待确认，不得猜测。

## 工作方式

1. 建立姓名变体与别名归属表。只纳入角色表中明确归属的名字；相同文本但不同角色 ID 分列。
2. 按章节锚点扫描人名、别名和称呼。称呼必须同时匹配批准规则的说话人、称呼文本和对象；旁白中的人名只核对是否存在明确归属。
3. 将每处问题标为：`错称`、`待确认` 或已由明确角色 ID 解开的实名/别名。缺别名归属、缺说话人、同名无法区分均为待确认，不自行定案。
4. 姓名/别名与明确对象不符时，可建议改成对象已登记的实名或别名；未登记写法只有在正文明确提供对象且它与该对象唯一一个已登记姓名变体相差一字时，才标记为疑似错拼并给出该已登记写法。称呼关系未获批准时即使已知对象，也只能标错称并要求作者确认可用称呼，不猜测替代称呼。建议仅针对单处；绝不建议全局替换。

## 交付格式

```markdown
### 姓名变体与归属
| 变体 | 角色 ID | 实名 | 状态 |
|---|---|---|---|

### 核对结果
| 锚点 | 原文片段 | 类型 | 原因 | 逐处建议 |
|---|---|---|---|---|

### 待确认
- [锚点] 缺少的资料；需要用户确认的问题。
```

无问题时仍给出姓名变体表，并写明“未发现可判定的错称”；不要把这句话解释为已验证人物关系剧情。

## 示例边界

祖母称呼周岚“小岚”且对象确为周岚时应保留；若同一称呼用于周蓝，须逐处标错称。`周蓝`是另一角色实名，不能批量改成`周岚`。正文出现`老周`而角色表未归属时，输出待确认，不猜为任何人。

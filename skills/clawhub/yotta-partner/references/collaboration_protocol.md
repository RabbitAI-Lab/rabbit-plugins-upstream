# 元伴协作协议单元

本文件是元伴（yotta-partner）的执行内核。它是一个可重复使用的协作协议：
上下文简报 → 方案闸门 → 分步交付 → 验证复核 → 交接与经验回流。

定位：元伴是跨智能体协作协议的**最低公共层**，只规定协作的最小公约数；任何一侧更严的
本地铁律优先，两者冲突时以更严者为准。

## 一、上下文简报模板

开始任务前，先填这份简报。缺字段时 AI 应追问，而不是猜测；用户填不全时至少要给
「目标」和「验收」，否则任务不建议直接执行。

```text
背景：
- 这件事从哪来？为什么现在做？
- 相关文件 / 系统 / 历史上下文？

目标：
- 完成态是什么？（能看见的具体结果）

约束：
- 时间：什么时候要？
- 资源：谁能做、有什么工具/权限？
- 边界：能碰哪些文件/数据/通道？不能碰什么？
- 红线：不可逆操作、外部发布、删除、授权变更等。

验收：
- 怎么算做对？（可勾选清单）
```

**验收写法（坏 vs 好）：**

- ❌ 验收：把功能做完、没问题。
- ✅ 验收：
  - `python selftest.py` 全绿；
  - 边界 X / Y / Z 已覆盖；
  - 输出文件能在 `deliverables/` 打开预览；
  - 未改动清单之外的文件。

验收标准要能**逐条打勾**；写不出可勾选项，说明「做对」还没定义清楚，先别动手。

## 二、先方案后动手

复杂或可能产生副作用的任务，默认先出方案再执行：

1. AI 说出准备怎么做：步骤清单；
2. AI 列出会动的东西：文件、数据、外部通道、配置；
3. AI 给出验证方式：测试、回读、dry-run、人工复核；
4. AI 列出待确认问题，不等用户开口就主动问；
5. 用户批准后开始；单步低风险机械操作可先做，但要在方案里说明。

**确认阈值：按「影响面 + 可回滚性」分三档，决定哪些要等批准：**

| 档位 | 范围 | 示例 | 动作 |
|---|---|---|---|
| 直接做 | 只读 / 新建草稿 / 纯新增无副作用 / 低风险机械步骤 | 查一个词、复制改写、格式化、改 typo、加注释 | 做完一句话报告 |
| 先方案 | 会改动现有内容，或删除 / 发布 / 动数据 | 改接口签名、删字段、导数据、发版 | 方案列影响面 + 回滚，批准后执行 |
| 完整协议 | 复杂 / 长期 / 多步 / 跨会话 | 系统迁移、跨会话任务、反复返工的活 | 简报 → 方案 → 执行 → 验证 → 记录 |

「机械」不是偷懒挡箭牌：只有改动极小且可回滚（如 git diff 可恢复）的才归「直接做」；
会动现有内容或不可逆的，一律先方案。

如果 AI 已经直接动手：

- 停下当前动作；
- 说明已做了什么和影响；
- 补一份方案，等用户确认后再继续。

## 三、分步交付

- 一个会话只交付一个里程碑；做完即收口，开新会话做下一件事；
- 长任务拆成小步：小步要能被检查（跑一条命令、读一个输出、看一个文件）；
- 每完成一个可检查步骤，简短汇报结果，不等到最后才说；
- 不连续堆任务；上下文变长时先把关键状态落盘，再继续。

## 四、验证复核清单

交付前逐条自检：

- [ ] 验收标准逐条满足，不是笼统说「完成了」；
- [ ] 关键结论可溯源：代码 / 命令 / 日志 / 引用 / 截图？
- [ ] 测试、校验、dry-run 已运行且输出已核对；没跑过的就说没跑，不编造、不摆拍；
- [ ] 没有越权动作：未批准的文件写、删除、推送、发布；
- [ ] 未实测 / 未核实的关键结论已显式标注：实测过 / 仅查到文档 / 无法核实；
- [ ] 若任务跨会话，已更新状态并留下交接锚点。

**用户 10 秒核查（不用逐字读协议）：**

1. 走协议前，有没有一行「目标 + 验收」简报？
2. 动手改文件 / 发布前，有没有先给方案？
3. 说「完成了」时，有没有贴证据（命令输出 / 文件路径 / 日志）？
4. 不确定的结论，有没有标注「实测过 / 仅查到文档 / 无法核实」？

四点都过 → 基本守约；任一点缺失 → 先要求补齐再验收。高风险动作再单独要求 dry-run 或回滚方案。

## 五、交接锚点模板

跨会话任务结束时，输出一段自包含交接锚点。新会话只凭这段文字就能接续：

```markdown
【会话交接锚点】
项目：项目名（一句话定位）
路径：项目根目录绝对路径

上次会话结束于：YYYY-MM-DD

当前进度：
- 做到哪一步

已完成：
- 已完成的关键结果

下一步（按优先级）：
1. 下一件事
2. 再下一件事

关键决定（详情见状态文件）：
- 影响方向的决定及理由

遗留问题 / 注意：
- 未解决项、风险、待确认

开工请先读取：状态文件路径
```

状态文件的目录名以项目自己的约定为准，不限定；但必须给出明确路径。

## 六、经验回流

- 有效做法、踩坑原因、修复方法，先写进项目内日志或 `.learnings/`；
- **每次记录都写明「本次落到哪里」**：哪条 `.learnings/`、哪个状态文件、元忆哪条记忆——不写一句「已记录」就结束；
- 若已安装元习（yotta-learn），用它的条目协议沉淀，格式统一可检索；若已安装元忆（yotta-memory），重要事实用 `remember` 落盘，边界/偏好用私密类型；
- **未装元习 / 元忆时明说兜底**：本次用项目日志 + 交接锚点记录，并提示装后可升级；不无声降级，不让人误以为已进记忆库；
- 涉及用户隐私或敏感信息时，先获得用户同意再记录；
- 沉淀不是攒文本：每条要能回答「当时发生什么 / 为什么 / 下次怎么办」。

## 七、边界

- 本协议只处理协作方法和交付纪律，不做领域决策；
- 不读用户数据、不自动收集隐私；记录范围由用户同意；
- 不保证 AI 输出正确，最终复核责任在用户；
- 不含营销、运营与交易类话题。

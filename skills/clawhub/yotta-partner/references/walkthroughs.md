# 元伴复杂场景走查示例

> 三段完整走查，展示元伴在真实复杂任务里怎么跑（含异常自动触发）。格式：对话片段 +
> 「旁注」解释对应规则。示例是教学演示，不是逐字剧本；实际语气随任务与用户习惯调整。

## 走查 1：跨会话多日项目（含中断自动恢复）

背景：用户要把旧报表系统迁移到新 API，预计跨多个会话完成。

### 第一天 · 开工

用户：把旧报表管道迁到新 API。

AI（30 秒判定：会动现有代码、多步骤、跨会话 → 走完整协议。先给一行简报）：
「目标：报表管道切到新 API，旧接口下线。验收：dry-run 全绿、正式跑一次无异常、改动可回滚。开始前先确认背景与约束？」

用户：背景：月报依赖已下线的接口；约束：不能停机。

AI（给方案）：「步骤 1) 盘点接口使用点 2) 写适配层 3) dry-run 4) 正式切换；会动 adapter/ 下 3 个文件与配置；每步跑测试贴输出。可以开始吗？」

用户：批准。

旁注：协议第 2 步先方案后动手——方案含步骤、影响面、验证，等批准再执行。

### 第一天 · 执行中（上下文变长 → 自动落盘）

AI（跑完第 2 步，检测到会话已长、后续步骤多）：「先把进度落盘到 docs/迁移状态.md（已完成：盘点 + 适配层；下一步：dry-run），再继续。」

旁注：异常表第 3 行——关键状态边做边落盘，不等收工。

### 第一天 · 会话意外中断

（用户关闭会话，没走收工流程。）

### 第二天 · 新会话接续

AI（不假装记得，先读 docs/迁移状态.md）：「上会话做到：适配层完成、dry-run 未跑。按交接记录今天从 dry-run 开始。先跑 dry-run 贴结果？」

旁注：异常表第 8 行——会话中断后先读状态文件重建上下文，不猜。

### 第二天 · 交付

AI：「dry-run 全绿（贴输出）；正式切换完成；对照验收逐条打勾；遗留：旧接口灰度观察 24 小时。」

用户：验收通过。

AI（收工留锚点，写进 docs/迁移状态.md）：「交接锚点：项目 / 路径 / 进度 / 已完成 / 下一步（观察旧接口流量归零后下线）/ 关键决定 / 遗留。」

旁注：协议第 5 步记录与回流——下个会话凭锚点接续。

## 走查 2：AI 直接动手 → 异常自动触发

背景：用户让 AI「优化一下登录接口的日志」。AI 没给方案直接改了文件。

AI（改到一半，意识到本应先方案——会动现有代码）：「我先改了 auth.py 的日志行（影响：错误日志格式变化，可回滚）。补方案：1) 加请求耗时日志 2) 脱敏 token 3) 跑测试贴输出。请确认后我继续或回滚？」

旁注：异常表第 1 行——不等用户抓，AI 自己停 + 报已做 + 补方案。

用户：先回滚，改成只加脱敏。

AI：「已回滚（贴 git diff 确认干净）；按新指示只做脱敏，方案已确认，开始执行。」

旁注：恢复路径——已做部分按用户决定回滚，不静默保留。

## 走查 3：缺验收 + 本地铁律冲突

背景：团队项目有本地铁律「改数据库必须 DBA 书面批准 + 迁移脚本评审」；用户让 AI「给用户表加一个字段」。

AI（30 秒判定：动数据库 = 有副作用 + 命中本地更严铁律）：「这步会改用户表结构，超出我能直接执行的范围。项目铁律要求 DBA 书面批准 + 迁移脚本评审——我先出迁移脚本与影响评估，你走批准流程；批准前我不执行。」

旁注：边界情形 2——本地更严规则优先，AI 指出冲突并停在更严一侧。

用户：验收标准是什么？

AI（缺验收就开跑会返工，先补可勾选验收）：「建议验收：迁移脚本评审通过 + 测试库执行无异常 + 回滚脚本可用 + DBA 批准记录存档。可以按这个验收走吗？」

旁注：异常表第 6 行——先补可勾选验收再动。

用户：可以。

AI：「好，先出迁移脚本与影响评估，等你走完批准再执行。」

## 走查怎么用

- 先读「走查 1」看完整流程长什么样；遇到异常读对应行；
- 把示例当「对照基准」：任务里出现类似信号，AI 应做同样的自动动作；
- 旁注里的规则都能在 SKILL.md / exception_playbook.md 找到原文。

# 公文格式 Word 生成（通用公文规范）

将用户提供的材料（Markdown、文本、旧 docx）重排为符合 党政机关公文格式（GB/T 9704-2012）
及通用公文排版规范的 Word 文档。权威规范依据 GB/T 9704-2012《党政机关公文格式》及其实施
细则（层次序数、字体、字号、版式等通用规则）。每次生成前若用户未另给规范，默认以此通用
公文规范为准。

## 何时使用
- 用户提供 markdown（含 IMA 导出的 md、纯文本）要求转成公文 Word。
- 用户要求"按公文格式 / 红头文件样式"生成或重排 Word。
- 用户起草 标准/规范 的"修改说明""编制说明""起草说明"等材料。
- 用户指出前文"层级符号错""字体不是仿宋/楷体""用了 1） 而非 （1）"等。

## 强制格式规则（依据 GB/T 9704-2012《党政机关公文格式》及公文排版通用规范）

### 结构层次序数（只定义四级，没有"1）"写法）
- 第一层 `一、`：三号**黑体**
- 第二层 `（一）`：三号**楷体**
- 第三层 `1、`：三号**仿宋GB2312**
- 第四层 `（1）`：三号**仿宋GB2312**；其与正文同属内容性文字，应**首行缩进 2 字**、两端对齐，不要顶格。
- 标题缩进：第一层 `一、`、第二层 `（一）`、第三层 `1、` 均**首行缩进 2 字**（与正文一致）；第四层分点 `（1）` 亦首行缩进 2 字。即所有标题层级与正文段落统一首行缩进 2 字。

### 报告模式（「第X部分 / 第X章」分章型正式文档）
当源稿用 `## 第X部分` / `## 第X章` 作顶级分章（典型如"报告""方案""规定"），生成器**自动进入报告模式**：
- 每个 `第X部分` → 一级标题 `一、` `二、` … `八、`（黑体），并**在每个 part 处重置二级计数器**，杜绝"一、既是一级又是二级"的混乱。
- 其下的 `### 一、…` / `### （一）…` / `### A类…` 统一降为**二级** `（一）` `（二）` …（楷体），按 part 连续编号；源稿里已有的 `一、` / `（一）` 前缀会被剥掉后重排。
- 因此整篇形成正确的 `一、 → （一） → （1）` 四级嵌套，不再出现层级错乱或编号被全局计数器污染。
- 标准模式（如"修改说明"用 `一、（一）1、（1）` 直接定级）不受影响，两者互斥、自动判别。
- ⚠️ 缩进必须**同时用 twips 和字符两种单位**：`indent:{firstLine:0, firstLineChars:0}`
  （非正文）；`indent:{firstLine:640, firstLineChars:200}`（正文）。只写一种单位时，某些
  Word/预览会回退到用户模板 Normal 样式的 2 字符缩进，导致标题、表格、页码看起来仍有首行缩进。
- ⚠️ 后处理脚本必须在 `styles.xml` 中**显式创建 Normal 样式**，并在 `Normal` 和
  `docDefaults/pPrDefault` 上都写 `firstLine=0`、`firstLineChars=0`、`left=0`、`leftChars=0`。
  否则打开文件时 Word 会套用本地 Normal 模板，出现"明明 XML 写了无缩进，打开却仍有缩进"。
- ⚠️ 不要用 `1）2）3）` 作为层级——公文办法里第四层就是 `（1）`。源稿若写成 `1）`，
  统一改回 `（1）`。

### 分点标点（同一组并列枚举项）
- 第四级并列分点（`（1）…（n）`）：除**末项**外，每项以全角分号 `；` 结尾；**末项**以
  句号 `。` 结尾。
- 此规则只针对第四级枚举项；第三级 `1、`、`（一）`、`一、` 是标题层级，不加句末标点。

### 页码
- 必须加页码：页脚**居中**、**无首行缩进**；页码阿拉伯数字用 **Times New Roman**（四号）。
- docx 实现：section 加
  `footers:{default: new Footer({children:[ new Paragraph({alignment:AlignmentType.CENTER, indent:{firstLine:0, firstLineChars:0}, children:[ new TextRun({font:"Times New Roman", size:28, children:[PageNumber.CURRENT]}) ]}) ]})}`。
- 不要套用 GB/T 9704 的"单页居右空一字、双页居左空一字"交替式样，除非用户明确要求；
  用户只要求居中时即居中。

### 字体与字号
- **标题**：二号（22pt）**方正小标宋简体**，居中；不加粗（该字体本身不是粗体）。
- 层级仅靠字体区分，**均不加粗**（黑体已够重）。
- **正文**：三号（16pt）**仿宋_GB2312**。
- **阿拉伯数字**：文中一切数字用 **Times New Roman**（如 `GB 45438`、年份、条号）。
- **中文引号必须用对应中文字体**：双/单引号 `“ ”` `‘ ’`（及全角 `＂ ＇`）属 Unicode“高 ANSI”码位，Word 默认按 `hAnsi` 字体（Times New Roman）渲染，会变成“罗马字体的中文引号”。后处理 `fix_fonts.py` 会把含引号的 run 拆开，引号片段强制用所在 run 的中文（黑体/楷体/仿宋）字体 + `hint="eastAsia"`，使其随上下文字体正确显示；非引号片段仍保持中文用中文字体、数字用 Times New Roman。
- 主送机关：上行文三号黑体，下行/平行文三号仿宋GB2312。
- 抄送、印发机关/日期：四号仿宋GB2312。

### 对齐方式
- **正文段落**和**第四层分点 `（1）`** 必须设置为**两端对齐**（`AlignmentType.JUSTIFIED`，OOXML 为 `w:jc="both"`），不能只是左对齐。
- 标题、一级~三级标题、表格标题行按需要居中或左对齐；表格内容单元格通常左对齐或居中。

### 版面
- A4（210×297mm）；页边距 上37 下35 左28 右26 mm（版心 156×225mm）。
- 行距：固定值 28 磅（560 twips）；正文每页 22 行、每行 28 字。
- 正文每段首行缩进 2 字（≈640 twips）；第四层分点同正文缩进。
- 一级~四级层级标题（`一、` / `（一）` / `1、` / `（1）`）的段前段后间距均为 **0 行**（`spacing:{before:0,after:0}`），不额外留白，与正文靠行距和缩进区分。
- 表格内文字默认**四号（14pt）**仿宋GB2312（表头可用黑体）。
- 所有表格开启**「根据内容调整表格」**（AutoFit）：`w:tblLayout type="autofit"` + `w:tblW type="auto"`，列宽由内容自动决定（单元格保留首选列宽仅作参考）。

### 落款（默认不加，所有模式一致）
- **所有材料默认不加落款**：无论报告模式还是标准模式，生成器**一律不输出**文末署名/日期（用户明确要求“落款也默认删除”，保持正文结束即结束的简洁版式）。
- 例外：如用户在某次任务**明确要求**加落款（例如“末尾加上呈报单位与日期”），可临时放开生成器 `build()` 末尾的落款输出开关；默认保持关闭。
- 说明性材料（修改/编制/起草说明等）同样默认不加落款占位。

### 主送机关与落款要素（按模式处理）
源稿顶部若用加粗标记写出公文要素，生成器会自动识别并作正确排版（冒号在加粗标记内外的写法都兼容）：

报告模式（含「第X部分/第X章」）**一律不渲染任何公文要素**——这是用户明确要求的报告版式：
- 不渲染 `**主送：**` / `**抄送：**` 抬头；
- 不渲染 `**文件编号：**` 发文字号行；
- **不输出落款**（标题之后直接进入第一章节 一、，文末也不加署名/日期）。
- 即报告模式默认：标题 → 第一章节 → … → 结束，干净无抬头无落款。

标准模式（修改/编制/起草说明等无 第X部分 的文档）：
- `**主送：** …` / `**抄送：** …` → 渲染为抬头：三号**黑体**、顶格、无首行缩进，置于大标题下。
- `**文件编号：** …`（发文字号）→ 仿宋、居中，置于大标题下。
- `**呈报单位：** …` / `**发文机关署名：** …` / `**日期：** …` / `**成文日期：** …` → 仍会被识别，但因“落款默认删除”规则，**默认不输出**文末落款（如需输出见“落款”节例外说明）。

### HTML 实体自动解码
IMA 导出的 md 常残留 `&#x7740;`（着）、`&#29420;`（独）等 HTML 实体。生成器在读取阶段统一 `decodeEntities` 解码，**无需手工预处理**；若源稿本身已是干净中文则无影响。

### Markdown 星号自动清除（替换为空，不是空格）
源稿中 markdown 的强调标记 `*` 与 `**` 在生成阶段**批量删除（替换为空字符串，绝不是空格）**，公文不保留任何 markdown 标记——无论 `**加粗标题**`、`*列表项*` 还是行内 `**xxx**`，最终只留纯文本进入文档：
- **第一层（源头）**：生成脚本读取 md 后即 `md.replace(/\*/g, "")`，所有 `*` 从源头消失。
- **第二层（`inline()` 兜底）**：`inline()` 函数末尾额外 `.replace(/\*/g, "")`，确保任何不成对的残留星号也清掉。
- **第三层（后处理兜底）**：`fix_fonts.py` 遍历所有 `w:t` 文本，把残留 `*` 替换为空并打印清除计数。
- ⚠️ 必须是“替换为空”而**不是**“替换为空格”：否则 `**1. 性质与地位**` 会变成 ` 1. 性质与地位 `（两侧带空格），破坏公文排版。

### 中文之间 / 中文与标点之间多余空格自动清除
源稿（尤其 IMA 导出）常在中文与中文、中文与中文标点之间夹杂半角/全角空格（如“第 一 章”“他说 ： ”）。公文排版不需要这些空格：
- 生成阶段 `cleanup()`：仅当空格**两侧均为 CJK 字符或中文标点**时才删除，**保留“中文 + 拉丁/数字”之间的空格**（如“标准 GB/T 9704”“2026 年”）；
- 后处理 `fix_fonts.py` 的 `normalize_spacing()` 再做一次兜底（覆盖 run 内部与跨 run 边界两种情形），并打印清除计数。
- ⚠️ 只删“中文—中文 / 中文—中文标点”之间的空格；**绝不删“中文—拉丁/数字”之间的空格**，避免破坏“GB/T 9704”这类写法。

### 标题标点
- 标题中除法规、规章、标准名称加书名号外，一般不用标点。标准名如
  “涉人工智能违法犯罪防范基本要求”属规范名称，书名号保留。

## 生成工作流（用 docx npm 库 + 后处理）

`docx` 库写入 run 时只生成 `ascii/hAnsi/cs` 字体，**不会**写 `eastAsia`，
导致中文落到默认字体而非仿宋/楷体。必须后处理。

1. 用托管 Node 环境安装 `docx`：
   `cd /Users/weidong/.workbuddy/binaries/node/workspace && /Users/weidong/.workbuddy/binaries/node/versions/22.22.2/bin/npm install docx`
2. 直接复用 `scripts/generate_gongwen_docx.js`（解析 markdown -> 公文，已固化全部规则）：
   ```bash
   NODE_PATH=/Users/weidong/.workbuddy/binaries/node/workspace/node_modules \
     /Users/weidong/.workbuddy/binaries/node/versions/22.22.2/bin/node \
     scripts/generate_gongwen_docx.js input.md output.docx
   ```
   - 输入兼容三种写法：① 标准 markdown 标题（按 `#` 深度自动编号）；② 已带公文编号的
     文字（含 `**加粗**` 伪装成标题的，如 IMA 导出的 md）——按 `一、/（一）/1、/（1）` 直接定级；
     ③ **「第X部分 / 第X章」分章型正式报告**——自动进入"报告模式"（见上），`第X部分`→一~八一级、
     其下统一降为 `（一）~（n）` 二级，并按 part 重置计数器。
   - `1）2）3）` 自动归一为 `（1）（2）（3）`，并按"同组末项用 。、其余用 ；"补标点。
   - 表格首行水平+垂直居中；列表/分点转 `（1）` 分点；自动加居中页码。
   - 自动清理 IMA 外壳：空 `#`、开头"好的，根据…"、分隔线 `***`、重复大标题、`（完整版）`
     均自动忽略；HTML 实体（`&#x7740;` 等）自动解码。极脏的对话外壳仍建议先手动删掉再转。
   - 公文要素自动识别：`**主送：**` / `**抄送：**` / `**文件编号：**` / `**呈报单位：**` /
     `**日期：**` 按对应要素处理；其中落款类要素因"落款默认删除"规则默认不输出文末落款（见"主送机关与落款要素""落款"两节）。
3. 生成后运行 `scripts/fix_fonts.py` 后处理（支持任意路径参数）：
   - 遍历 `word/document.xml` 与 `word/footer*.xml` 的每个 `w:pPr`，补齐 `firstLine` /
     `firstLineChars` / `left` / `leftChars`，确保无缩进段落双单位均为 0、正文段落双单位
     对应 2 字符。
   - 遍历 `w:rFonts`，把 `ascii` 当前值抄到 `eastAsia`，并把 `ascii/hAnsi` 改为
     `Times New Roman`。
   - 在 `styles.xml` 中**显式创建 Normal 样式**（若不存在），并在 `Normal` 与
     `docDefaults/pPrDefault` 上同时声明无首行缩进、无左缩进。
   这样中文用对应中文字体、数字用 Times New Roman，且任何 Word/预览都不会再套用本地
   Normal 模板缩进。
4. 校验：解压 docx 抽取文本，确认层级标记计数正确、无独立 `1）`（注意正则陷阱，
   见下）。

## 易错点
- **eastAsia 必须后处理**：docx 库不写 `eastAsia`，不处理则中文不是仿宋/楷体。
- **数字字体**：`ascii/hAnsi` 置 Times New Roman，否则数字不是新罗马体。
- **正则陷阱**：`（1）` 含子串 `1）`；且中文全角括号 `（` 是 U+FF08，不等于 ASCII 半角 `(`。
  校验"是否残留独立 1）"时，否定后顾必须基于中文全角左括号（写法为「否定后顾 全角左括号」），
  绝不能基于 ASCII 半角左括号，否则会把 `（1）` / `（图1）` / `（表1.1）` 误判为残留。
- **不加粗层级**：标题/层级用字体区分，黑体/楷体本身已重，再加粗会变成伪粗体。
- **缩进必须双单位 + 显式 Normal 样式**：只写 `firstLineChars:0` 或只写 `firstLine:0`，中文 Word/预览
  都可能回退到用户本地 Normal 模板的 2 字符缩进，导致"标题/表格/页码仍有首行缩进"。正确做法：
  非正文段落 `indent:{firstLine:0, firstLineChars:0}`，正文 `indent:{firstLine:640, firstLineChars:200}`，
  且后处理脚本在 `styles.xml` 显式创建 Normal 样式，并把 Normal 和 docDefaults 的
  `firstLine/firstLineChars/left/leftChars` 都置 0。
- **第四层分点不是标题**：`（1）` 分点属于正文性枚举，要与正文一样首行缩进 2 字、两端对齐，不要顶格。
- **正文必须两端对齐**：不要只设左对齐；OOXML 里两端对齐是 `w:jc="both"`，对应 docx 库的 `AlignmentType.JUSTIFIED`。
- **表格首行要同时水平+垂直居中**：公文/标准材料里的对比表，表头所有列都应水平居中，且单元格设 `VerticalAlign.CENTER`。常见错误是只居中第一列，第二、三列仍左对齐。
- **落款视类型而定**：修改说明 / 编制说明 / 起草说明等说明性材料不需要单位盖章和成文日期后缀。
- **分点标点**：同组 `（1）…（n）` 枚举项，末项用 `。`、其余用 `；`，不要全部用 `；` 或 `、`。
- **页码**：页脚居中 + Times New Roman + 无缩进；用 `PageNumber.CURRENT` 生成 PAGE 字段。
- **「第X部分 / 第X章」分章文档会自动进入报告模式**：`第X部分`→一~八一级、其下统一降为 `（一）~（n）` 二级并按 part 重置计数器；不要再手工剥离"第X部分"前缀或手动重排，否则会与自动编号冲突。
- **主送机关 / 落款是公文要素不是正文**：用 `**主送：**` `**日期：**` `**呈报单位：**` `**文件编号：**` 标记，生成器自动按公文要素处理，不要把它们写成普通正文段落（落款默认不输出，见“落款”节）。
- **Markdown 星号必须清除（替换为空）**：源稿里 `**` / `*` 等 markdown 强调标记在公文里无意义，必须批量**替换为空（不是空格）**。生成脚本源头 `md.replace(/\*/g,"")` + `inline()` 兜底 + 后处理 `fix_fonts.py` 扫描 `w:t` 替换空，三重保险确保文档零星号；若误替换为空格会破坏 `**1. 性质与地位**` 这类行的排版。

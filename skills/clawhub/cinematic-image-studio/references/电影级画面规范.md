# 电影级画面规范（14 节细则 + 负向词库 + 电影感要素）

> 配套 `SKILL.md` 第三节。本文件是**逐节写作细则**与**词库**，写提示词时逐节对照。

---

## 一、什么让一张图"电影级"

不是加"电影感"三个字，而是这五件事**同时成立**：

| # | 要素 | 落地写法 |
|---|---|---|
| 1 | **单一主光、方向明确** | 写清主光**方位 + 高度角 + 性质**（"身后云隙一道冷白体积光，逆光 45°"），不要"光线明亮"这类废话 |
| 2 | **光比与轮廓光** | 写"光比强烈 / 柔和"+"背光侧以 XX 勾出轮廓光"——**轮廓光是把主体从背景里拉出来的关键** |
| 3 | **虚实＝景深** | 大远景 `f/8` 全清晰；中景 `f/4`；近景/特写 `f/2.8–f/1.8` 浅景深。**光圈与【全局】【背景】的虚实描述必须自洽** |
| 4 | **构图有负空间** | 宽银幕 + 三分法 + **明确写出留白位置与占比**；画面塞满 = 廉价感 |
| 5 | **统一的调色与颗粒** | 调色**只在【影像质感】写一次**，写清"XX 一级调色 + 高光滚降 / 暗部不堵 + 胶片颗粒 + 轻微暗角" |

> **反面清单**（出现即不电影级）：光线明亮、色彩丰富、高清、8K、杰作、大师作品、超精细、
> 大片感、震撼、唯美、史诗级 —— 这些是**空词**，模型不吃，还会稀释具体细节。

## 二、14 节逐节细则

### 【主体】
- **唯一视觉主体**，末尾必须写「**是画面唯一视觉主体**」（挡掉模型自动加人加物的倾向）。
- **≥8 个可拍摄的具体细节**。维度清单：
  - 是什么 / 确切名 / 典籍出处（若为神话生物）
  - **尺寸与数量**（给具体数字：肩高约一米二、长约四米、七八茎）
  - **材质**（杉木 / 箬叶编席 / 湿黑玄武岩 / 竹编斗笠）
  - **颜色**（用**传统色名**：石青、石绿、朱砂、赭石、藤黄、蛤白、花青、胭脂、玄青、墨玉、霜银、赤金）
  - **新旧磨损状态**（褪色的、风化的、磨白的、晒裂的）
  - 面貌 / 体征（**硬特征不能错**：九尾就是九尾）
  - 姿态 + 朝向
  - 神态 / 气质
- **禁泛称**：「一只神兽」「一片山水」「一个古人」「一件衣服」——必须换成确切描写。

### 【次要元素·近景 / 中景 / 远景】
- **近景**：最前层，可作**前景框**（探入的松枝、右下角芦苇、湿岩），常写"虚化处理"。
- **中景**：中层物件（祭坛残柱、沙洲寒树、水面涟漪）。
- **远景**：背景层，写"含蓄朦胧 / 层层退远 / 没入云雾"。
- **空层写「无」，不删节**。

### 【全局】
- 满屏介质：斜雨丝、云雾、浮尘、落瓣、光束、火星。
- **必须与【镜头】景深自洽**：写 `f/8 大景深` 就不要在这里写"中远景虚化"。
- 静态图**不写动态时间词**（晃动 / 飘动 / 流动）→ 改"细碎光斑""缓慢流动的云气"这类可静态呈现的描述。

### 【构图】
- **只管构图**：机位高低 + 主体站位（三分线 / 对角线 / 中轴）+ 纵深 + **留白位置与占比**。
- **禁止**在这里写焦距 / 景深（那是【镜头】的活）。

### 【光影】★固定节
- 句式：`{主光方位与性质}` + `单一主光、方向明确` + `{塑形方式}` + `光比` + `{轮廓光}` + `{色温}`。
- **完整口径照抄风格卡**，只替换允许变的占位符。

### 【色彩】★固定节
- 句式：`墨分五色为骨架 / 主调玄青与赭褐` + `辅以 {矿物色}` + `{点缀色}作唯一高饱和点缀` + `饱和度` + `留白/点缀集中处`。
- **不写调色百分比**；留白程度用"约占四成"这类**画面描述**可以，但不要写"50% 暖色 30% 冷色"这种调色配方。

### 【影像质感】★固定节
- 句式：`{介质}` + `{细节可见}` + `胶片颗粒与轻微暗角` + `{调色}一级调色，高光滚降柔和`。
- **调色只在此节写一次**，其它节不许重复。

### 【背景】★固定节
- 写背景**性质与内容**，并加"无任何建筑文字与人工标识"。

### 【镜头】
- 句式：`{景别}` + `{机位角度}` + `{等效焦距}` + `{光圈/景深}` + `{焦点}`。
- **只写技术参数**，不重复构图。

### 【风格】★固定节
- 写风格句 + **排除性表述**（"非数码插画、非水彩、非油画"）。排除性表述是**防跑偏的第二道闸**。

### 【画幅】★固定节
- **本 skill 出图只写 `16:9` 或 `9:16`**。禁用 2.39:1 / 1.90:1 / 1.43:1 / 1:1。
  > 例外：`styles/54–57` 是 **MV 导入卡**（默认 `3:4`），由 `08-MV制作/mv-production-skill` 出图，不在本 skill 出图口径内。
- 变形宽银幕只作**质感词**（写在【影像质感】的调色描述里），画幅仍写 16:9 或 9:16。

### 【负向】
- **正向严禁否定词**（`no / not / without / 不要 / 无`——但"无题款""无文字"这类**内容声明**是允许且必要的，它描述的是画面内容，不是模型指令层的否定）。
  > 实操区分：`【背景】…无题款、无印章` ✅（陈述画面里没有）；`【主体】不要出现题款` ❌（指令式否定，进【负向】）。
- 合并顺序：**风格专属负向**（风格卡第三节）→ **通用负向**（下列）→ 词根去重 → **8–15 项**。

## 三、通用负向词库（按需取用，去重）

| 类别 | 词 |
|---|---|
| **画风跑偏** | 日式动漫、美式漫画、卡通、Q版、萌系、3D 渲染、CG 塑料感、矢量插画、平涂 |
| **文字类（红线）** | 文字、字幕、水印、Logo、签名、题款、落款、印章、篆刻、二维码、可读文字 |
| **人体崩坏** | 人物残缺、人物融合、人物粘连、多人重叠、三张脸画成同一张、手指畸形、五官错位、多余肢体 |
| **数量错误** | 多余人物、多余器物、数量错误、多头多尾错乱、尾巴数量错误、重复主体 |
| **构图失败** | 主体被裁切、构图失衡、画面塞满、无留白 |
| **质量** | 模糊、噪点、过曝、欠曝、低模、分辨率不足、压缩伪影 |
| **暴力红线** | 血腥、内脏、伤口特写、骸骨 |

> **有人物的帧不要排除"人物"**（会自相矛盾），但要排除"人物融合 / 残缺 / 多余人物"。

## 四、正负分离的自检口令

1. 【负向】里每一项，**能不能在正向里找到反义的具体描写**？找不到 → 正向缺描写，补正向比堆负向有效。
2. 【负向】超过 15 项 → 大概率在**用负向兜底正向的偷懒**，回去把【主体】写具体。
3. 【负向】和【主体】冲突吗？（例：【主体】写"画面里只有这一只神兽"，【负向】又写"多只神兽" —— 不冲突，正常。）

## 六、体量与气派（巨物感 · 跨风格通用技法）

> 任何要表现"**大**"的风格（神兽、史诗场面、巨构建筑、洪荒山水）都适用。
> 参考实现：`styles/02-山海经神兽.md` 第二节「气派四件套」。

### 为什么"画得大"不等于"看着大"

图像模型**没有绝对尺度概念**。一只肩高一米二的狐和一只肩高十丈的巨兽，如果都孤零零站在画面里，
**渲染出来一样大**。观众判断大小，靠的从来不是主体本身，而是**画面里有没有东西可以对比**。

所以"气派"是一个**构图与调度问题**，不是"把主体画大"的问题。

### 让主体变大的四把手

| # | 手法 | 原理 | 写法 |
|---|---|---|---|
| 1 | **尺度参照物** | 给观众一把"尺子" | 在【次要元素·近景/中景】写**拇指大的人形剪影** / 群飞鸟（小如蚊蚋）/ 数十米高而**柱顶出画**的巨柱 / 半沉的巨型兽骨。**必须写明相对大小**（"高不及神兽前爪"）。 |
| 2 | **低机位广角仰拍** | 透视夸张是体量感的物理来源 | 视平线压到主体**胸线以下**；**等效焦距 24mm 及更广**；**禁用 50mm 以上中长焦作主镜**（那是"肖像 / 动物纪录片"的语言，会压扁体量）。 |
| 3 | **多层纵深** | 层数＝场面规模 | **至少四层**：前景（压住画面下缘、虚化）→ 主体 → 中景（云海 / 巨构 / 倾颓石像）→ 远景（层叠到天际、漫出画框）。**天际线压到画面上 1/5**。 |
| 4 | **天光柱 / 巨构包夹** | 神性与仪式感 | 云隙**丁达尔光柱**斜扫显形；或主体被**两列对称巨柱**夹在中间，柱顶出画。 |

### 配套：色彩要"重"不要"灰"

气派场面**忌低饱和灰调**——灰调读作"阴天纪录片"。要**矿物重彩**：
以玄青 / 赭褐打底，**大面积鎏金、赤金、朱砂、石青**作华彩，像商周青铜与敦煌壁画；
但**统一于一个主调**，不是彩虹大杂烩。暗部沉而不死，亮部**带金属光泽**。

### 配套：景深要"深"不要"浅"

气派场面用 `f/5.6–f/8`，让**前景岩、主体、远处山峦全部清晰**——巨物纵深被浅景深糊掉就白做了。
只有"特写双眼"这类镜头才用 `f/1.8–f/2.8`。

### 气派自检五问

1. **画面里那把"尺子"在哪？** 指不出来 → 重写【次要元素·近景】。
2. **焦距是不是 24mm 左右、机位是不是压到胸线以下？** 不是 → 你在拍肖像，不是拍巨物。
3. **纵深数得满四层吗？** 数不满 → 背景空洞，加中景巨构与远景天际线。
4. **色彩是"重彩"还是"灰调"？** 灰调 → 【色彩】换成矿物重彩口径。
5. **光圈是不是 f/5.6–f/8？** 是 f/2.8 → 巨物纵深会被糊掉。

## 七、可数特征（尾数 / 头数 / 角数 / 臂数）怎么才画得对

> 实证来源：山海经神兽·九尾狐尾数实验（4 组对照 × 多次采样，历史产物已归档进 `assets/output/_归档/`）。

### 病根：模型不会计数，只会"渲染一个分布"

图像模型**没有计数器**。写"九条尾巴"，它渲染的是训练数据里"多条尾巴"这个**分布的采样**——
而九尾狐的网络图像本身尾数就不统一（多数 5–9 条）。所以**数字写多少遍都没用**。

### 真正的杀手是「遮挡」

一旦尾巴（头 / 角 / 臂）彼此遮挡、糊成一团，**尾数就永久不可数了**——观众数不出，等于画错。
实测：同一提示词 3 次采样，**3 次都数错**（6 / 7 / 8 条），失败的共同特征就是尾巴互相压叠。

### 解法：把「数量」翻译成「空间布局」

**不要只写数字，要给模型一个可数的结构。**

| ❌ 无效写法 | ✅ 有效写法 |
|---|---|
| 九条蓬松长尾自腰后扇形展开 | 九条蓬松长尾自腰后呈**完全不相交**的扇形平铺展开——**以脊线为轴，左侧四条、右侧五条**，**相邻两尾之间留出可见的空隙**，每条尾**自尾根到尾尖轮廓完整可辨、互不遮挡** |
| 九尾张开时遮住半边天 | （**删掉**——它主动要求遮挡，是尾数崩坏的头号元凶） |
| 多条长尾扬起 | 九条尾**彼此分离、可逐条数清**，在身后平铺如扇 |

**四条硬规则**：
1. **给空间分组**："左侧 N 条、右侧 M 条"——把总数拆成两个小数，模型更容易凑对。
2. **明令互不遮挡**："完全不相交""相邻之间留出可见空隙""互不遮挡"。
3. **要求轮廓可辨**："每条 X 自根部到尖端轮廓完整可辨""可逐条数清"。
4. **删掉一切招致遮挡的措辞**："遮住半边天""层层叠叠""交错""缠绕""堆叠"。

### 配套：构图选对称，别选动势

**对称正视图**（尾巴像孔雀开屏平铺）尾数正确率远高于**动态侧身**（尾巴甩起来必然互相遮挡）。
实测同一风格卡下：对称中轴构图一次数对 9 条；动势侧身构图连续数错。

### 技法：标识色独占（零成本、最有效的一招）

**让"要数的那个东西"独占一种颜色，画面里别处不出现该颜色。**

这样一举解决两个问题：
1. **对模型**：唯一色 = 强显著特征，它更愿意把该色只用在目标元素上；
2. **对核验**：可以用 `scripts/count_features.py` 按色相分割**客观计数**（见下），
   不怕人脸纹路、金饰高光混进来造成假阳性。

**写法示例**（九尾狐）：
> 九条尾尖是画面中**唯一**的朱红色元素——面部、耳内、脊线、四肢一律为玉白与霜银，
> 不带任何朱红或赤色。

> ⚠️ 反例（本项目踩过的坑）：原提示词让狐狸**面部有朱砂纹路、耳内泛红、脊线赤金**，
> 结果这些红色既污染计数，又容易被看成"多出来的尾巴"。
> **一处细节的颜色选择，直接决定了这个特征能不能被数清。**

### 核验工具：`scripts/count_features.py`（本地运行，零 API 成本）

```bash
# 数朱砂尾尖；ROI 排除背景同色元素；--expect 9 命中打钩
python3 scripts/count_features.py 图.png --roi 0,0,1080,900 --expect 9 --dump-mask /tmp/m.png
# 批量数一个目录并出 CSV，用于挑图
python3 scripts/count_features.py --dir 图片目录 --roi 0,0,1080,900 --csv 计数.csv
```
**两个必需的人工环节**：
1. **`--roi` 限定区域**——背景里同色系的元素（鎏金立柱、雪山反光）会造成假阳性；
2. **`--dump-mask` 目视复核**——必须确认被计数的色块真的落在目标元素上。

> **阈值要用已知真值校准**：本项目用一张**人工确认过 10 条尾**的图校准，
> `--min-area 1200` 命中；调到 2000 就会漏掉被遮挡的那条尾。
> **没有校准过的计数不要信**（包括自己肉眼数的）。

### ⚠️ 成本纪律：先免费定位，再花钱出图

精确计数**不是靠堆出图数解决的**，本项目在这一点上烧掉过 17 张图，教训如下：

| 顺序 | 做什么 | 成本 |
|---|---|---|
| 1 | **改提示词**（标识色独占 + 空间布局 + 删遮挡措辞） | **0** |
| 2 | **本地核验**已有图（`count_features.py` + `--dump-mask` 目视） | **0** |
| 3 | 需要新样张时，**一次出 1 张**，出完立刻本地核验 | 1 张 |
| 4 | 仅当"精确计数"确实是硬需求时，才小批量 best-of-N（≤4 张），**并先确认命中率** | N 张 |

> **不要**为了"多挑几张总有一张对"直接开 8 张批量——命中率可能远低于预期
> （本项目实测 8 张里 0 张是 9 条），钱花光了问题还在。

### 兜底：可数特征是**必须 best-of-N** 的

即便按上述写法，单次采样仍可能数错。**凡典籍硬特征（九尾 / 三头 / 六足 / 四角 / 千手），一律连出 3–5 张、人工挑一张数对的**，不要指望一次命中。

> ### ⚠️ 更正：空间布局解决的是「可数性」，不是「计数准确性」
>
> 早期版本此处写过「原写法 0/3 ｜ 加空间布局后 4/4」，**该断言已作废**——
> 它基于**在缩略图上肉眼计数**，而同一方法后来被证明会数错（把 10 条数成 9 条）。
>
> **修正后的结论**（历史实验产物已归档进 `assets/output/_归档/`）：
>
> | 写法 | 尾数「可数性」 | 尾数「准确性」 |
> |---|---|---|
> | 原写法（含「遮住半边天」） | ❌ 糊成一团，数不清 | ❌ 6~8 条 |
> | 加空间布局 | ✅ **条条分离、可逐条点数** | ⚠️ **实测出现 8 / 9 / 10 条，仍不稳定** |
>
> **空间布局是让尾数「看得清」的必要条件，但它并不让模型学会数到 9。**
> 模型依旧在采样「多条尾巴」这个分布，只是这次采样出的多条**彼此分开了**。
>
> **推论（重要）**：
> 1. **不要指望纯提示词解决精确计数**——它做不到。
> 2. **必须 best-of-N，且必须放大到全分辨率逐条数**（缩略图上数会出错）。
> 3. **构图优先选对称**：中轴对称、尾等角距平铺时，缺一条或多一条**一眼能看出**，
>    是唯一能低成本自查的构图；动势侧身构图连「该有几条」都难目测。

## 八、【负向】在「无 negative 通道」的模型上要改写

### 先确认你的模型有没有 negative 通道

| 情况 | 判断 | 【负向】的性质 |
|---|---|---|
| 接口有独立 `negative_prompt` 参数（部分 SD 系） | 有通道 | 真正的排除项，写多少都不进正向 |
| 接口只有一个 `prompt` 字段（**本项目 `gpt-image-2-c` 就是这种**） | **无通道** | **【负向】只是普通提示词文本**——它不排除任何东西，只是在**重复强调那些名词** |

> 本项目 `scripts/generate.py` 的 `api_generate()` 只发 `model / prompt / size / quality`，
> 所以提示词里那一整节 `【负向】…` 对模型而言**和正向没有区别**。

### 无通道时的【负向】写法

1. **可数特征类的词，一律不要放进【负向】**
   —— 写"尾巴数量错误""多头多尾错乱"等于又强调了一遍"多尾"，**纯污染**。
2. **只放"画风 / 质量 / 红线"类**
   —— 这类词即使提高显著度也无害（它们描述的是"不要这种画风"）：油画、3D 渲染、塑料感、文字、水印、血腥。
3. **不放"数量 / 计数"类**，改为**在正向里用空间布局把数量锁死**（见第七节）。
4. **控制长度**：负向越长，正向被稀释得越厉害。**8–15 项**够用。
5. **别把同一词根写第三遍**：同一词根 ≤2 次。

> **说明**：实测中"删除尾部负向"既没明显改善也没明显变差（n 小），
> 所以本节不是"能提升画质"，而是**"别做无用功、别自我污染"**——把注意力与字数留给正向的空间布局。

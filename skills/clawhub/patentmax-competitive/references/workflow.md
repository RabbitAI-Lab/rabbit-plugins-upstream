# 企业情报分析工作流

## 全流程

```
问清楚 → 整理素材 → 报价确认 → 跑任务 → 转述进度 → 读结果 → 组织交付物
```

跑任务本身只是中间一步，前后两端才是价值所在。

## 第一步：问清楚

用户说「分析一下 XX 公司」时，信息通常不足以跑出有用的报告。先问，**最多问三个问题，别把人问烦**：

按优先级挑最缺的问：

1. **这份报告要支持什么决策？** —— 立项、并购尽调、竞品对标、应诉准备，四个方向的报告长得完全不一样
2. **你已经知道什么？** —— 避免报告重复常识，也让模型知道从哪儿往前走
3. **关心哪个技术分支？** —— 「电池」太宽，「钠电正极的层状氧化物路线」才能出锋利结论

用户给不出来也没关系，按已有信息跑，但要提前说明结论会比较宽泛。

## 第二步：整理素材

见 `materials-guide.md`。要点：

- 分析对象是谁（工商全称、集团下属主体、主营业务、已知动作）
- 你关心什么（技术路线 / 空档 / 侵权风险 / 资产估值）
- 你已经知道什么（竞争格局、行业共识、对方近期动作）

素材长的时候写进文件，用 `--materials-file` 传，命令行塞不下十万字。

## 第三步：报价并确认

**这是付费任务，跑之前必须告诉用户成本并等他明确同意。** 脚本要求显式 `--yes`，不要替用户加上。

同时确认一遍参数：

- `--competitors` 竞争对手用全称，逗号分隔
- `--markets` 目标市场，影响检索范围
- `--time-range` 新兴技术看近三年，成熟技术要看全周期
- `--sources` 默认含专利、论文、网页、新闻；做侵权风险或应诉准备时加 `litigation`，判断前沿方向时 `paper` 尤其重要——论文通常比专利早一到两年

## 第四步：跑任务

```bash
python scripts/patentmax_competitive.py create \
  --subject "..." --materials-file ./materials.md --objective "..." \
  --competitors "..." --markets "CN,US,EP" --time-range "近五年" \
  --wait --yes
```

`--wait` 会轮询到出结果，间隔 10 秒起、退到 60 秒，默认最多等 90 分钟。

**进度会实时打到 stderr**，形如 `[35%] 正在检索竞争对手专利`。把这些**转述给用户**——几十分钟的等待里，用户需要知道任务在推进，而不是怀疑卡死了。

**超时不代表失败。** 任务仍在服务端运行，**绝对不要重新提交**（会再扣一次钱）。用 `status --operation-id` 继续查。

中途确定不需要了，用 `cancel --operation-id` 取消。

## 第五步：读结果

报告返回后，不要整段转述给用户。挑出四件事：

**格局怎么分。** 谁是主要玩家、各自占什么位置、技术路线趋同还是分化。有几家在同一条路线上扎堆，说明那条路线已经被验证但也已经拥挤。

**对方的动作意味着什么。** 近期申请集中在哪些方向、和它公开的产品路线是否对得上、有没有明显的卡位意图。**专利申请比产品发布早，这是它最有价值的地方**——对方两年前的申请，可能就是明年的产品。

**我方的位置。** 空档在哪、哪些方向已经拥挤、绕不开的核心专利是哪几件。如果用户是来做立项决策的，这块是重点。

**数据质量。** `quality_status` 三档：

| 值 | 含义 | 怎么交付 |
| --- | --- | --- |
| `qualified` | 通过质量校验 | 可作为分析依据 |
| `qualified_degraded` | 已生成但有数据短板 | 结论保守使用，**必须说明是哪块不足** |
| `review_required` | 需人工复核 | **不要直接当结论交给决策层** |

后两档出现时，`quality_details` 里通常有具体原因，读出来告诉用户。

## 第六步：组织交付物

如果用户要的是可交付的文档：

```bash
python scripts/patentmax_competitive.py download --report-id <report_id> --out 竞争分析报告.docx
```

DOCX 不额外收费，包含在任务费用里。

如果用户要的是对话里的结论，按这个结构组织：

1. **一句话结论** —— 支持还是不支持他要做的决策
2. **格局速览** —— 表格：主要玩家、技术路线、专利量级、近期动向
3. **对我方的含义** —— 空档、风险、绕行建议
4. **依据** —— 用了哪些来源、覆盖什么范围、关键专利列表（带公开号）
5. **边界** —— 见 SKILL.md「结论纪律」

**每一条关于某家企业的判断，都要能追到具体公开号。** 说「对方在层状氧化物上布局密集」，就要能列出那几件专利。不能追溯的判断不要写。

## 一次失败的分析长什么样

以下情况别跑，跑了也是浪费用户的钱：

- 素材只有一个公司名，用户也说不出关心什么
- 用户其实只想知道「这家公司有多少专利」——那用企业画像，便宜得多
- 用户想查的是自己的方案能不能申请——那是查新
- 用户想要的是「我们下一步该往哪布局」——那是技术路线分析，这个任务只讲现状不给建议
- 同样的主题和素材刚跑过一次，用户只是想换个措辞再试——先看上次结果哪里不满意，改素材再跑

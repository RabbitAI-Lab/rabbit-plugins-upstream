# 发货拣货装箱单

把脱敏订单资料变成可直接打印或复制到仓内协作工具的 Markdown 操作清单。交付包含逐单拣货/装箱勾选项、按已确认套装拆开的组件数量汇总、待确认项和包装规则；不读取后台、不扣库存、不创建运单，也不宣称已发货。

## 输入

- 最多 20 个脱敏订单、共不超过 100 条商品或组件行。
- 每行提供 `SKU`、正数数量和单位；套装仅在已确认组成时拆算。
- 提供赠品的适用 SKU、`min_order_quantity` 与必填 `min_order_unit`、赠品 SKU/数量/单位，以及包装规则。订单达到门槛时只累加与门槛单位相同的商品行；同一 SKU 混有不同单位或缺单位时不换算、不判定赠品，先要求确认。

若单位、套装组成或赠品适用条件缺失，保留原商品行并在“待确认项”中说明缺什么。不得补造附件、赠品、组件或包裹数量。

## 操作方式

1. 核对输入仅含脱敏业务资料，并把订单、套装、赠品和包装规则按下列 JSON 结构提交。
2. 为每个订单输出“拣货与装箱勾选”；只拆开组成已经确认的套装。
3. “拆套后组件汇总”只汇总已确认套装拆出的组件；普通商品与赠品留在订单拣货清单中，不混入组件汇总。把不能确认的资料单列为待确认，再由人工补料后重新生成。

```json
{
  "orders": [{"id": "D-1001", "items": [{"sku": "SET-CUP-BRUSH", "quantity": 2, "unit": "套"}]}],
  "kits": {"SET-CUP-BRUSH": [{"sku": "CUP-01", "quantity": 2, "unit": "个"}]},
  "gifts": [],
  "packaging_rules": ["易碎品加气泡膜"]
}
```

## 交付格式

```markdown
## 订单 D-1001
### 拣货与装箱勾选
- [ ] SET-CUP-BRUSH × 2 套（按已确认套装拆拣）
  - [ ] CUP-01 × 4 个

## 拆套后组件汇总
- [ ] CUP-01 × 4 个

## 待确认项
- 无
```

可用本仓库的本地参考实现生成相同结构：`python3 scripts/generate_picklist.py fixtures/success-input.json`。成功与缺套装组成的保守处理见 [fixtures](fixtures/)。

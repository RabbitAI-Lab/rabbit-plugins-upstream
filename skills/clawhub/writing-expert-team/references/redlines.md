# 发布红线底座（质量闸门）

> 红线底座是本技能区别于通用写作助手的核心差异化资产。它把“发布事故”挡在渲染之前，而非事后救火。任何产出在排版 / 出图 / 发布前，必须先过以下四道关。

## 🔴 红线 1：中文引号规范（绝对红线）

1. 中文文章必须使用中文双引号 `"` `""`（U+201C / U+201D），**禁止**英文直引号 `"`。
2. 中文文章单引号使用 `'` `''`（U+2018 / U+2019），**禁止**英文直单引号 `'`。
3. **例外**：代码块、命令行、JSON 内保留 ASCII 引号。
4. **自动修复思路**：遍历 `.md` 源文件，正则替换英文直引号 → 中文弯引号；替换时跳过 ``` 代码围栏与行内 `code` 区间。批量修复脚本示例见技能外的 `fix_quotes.py`（按仓库提供）。

## 🔴 红线 2：HTML 实体禁止（绝对红线）

- 禁止在文章正文出现 `&quot;` `&#34;` `&amp;` `&lt;` `&gt;` 等 HTML 实体。
- 文章内容必须是**纯 Unicode 字符**，不做 HTML 转义。
- 如发现 HTML 实体，立即 `html.unescape` 解码替换后再保存。

## 🔴 红线 3：字体字形覆盖（渲染前闸门 · 最易被忽略）

- **盲区**：文本已是合规 Unicode（如中文弯引号 `""`），但若渲染字体**缺该字形**，图片上仍会变成豆腐块 `□`。纯文本检查查不出此问题。
- **规则**：任何文本渲染（小红书图 / 海报 / 封面）所用字体，必须覆盖源文件全部“会落字”的字符。缺非 emoji 字形即判不通过。
- **铁律**：标题 / 封面中文渲染只用**完整字体**（如 `NotoSerifSC-VF.ttf` / Source Han 完整版），**禁止**用带“Subset / Heavy 子集”字样的精简字体。
- **QA 闸门思路（可落地为脚本）**：
  1. 解析渲染器实际加载的字体路径；
  2. 扫描源 `.md` 去重字符集；
  3. 用字体工具（如 `fonttools`）逐一比对字形覆盖；
  4. 同时复检英文直引号与 HTML 实体；
  5. 全部通过才允许渲染，不通过立即阻断并报告缺字清单。

## 🔴 红线 4：法律内容规范（合规红线）

- 所有法条引用必须注明：**法律名称 + 具体条款编号**。
- 数字（工资标准、赔偿金额、天数）必须注明**时效与来源地区**。
- 一裁终局等制度需区分主体权利（劳动者可起诉 vs 用人单位只能申请撤销）。
- 发布前必须经过法律审核步骤（角色 8：刘律师 / 本机法律审核流程）。

## 红线底座执行流程

```
任何批量出图 / 发布前：
  ① 字体字形覆盖检查  → 不通过即阻断
  ② 源文件英文直引号检查 → 归零才通过
  ③ 源文件 HTML 实体检查 → 归零才通过
  ④ 中文标点规范检查 → 通过才渲染
全部 🟢 通过 → 允许渲染 / 发布
任一 🔴 不通过 → 立即阻断，修复后重跑
```

将本底座固化为脚本后，每次渲染前强制先过闸，是最省心的防呆方式。

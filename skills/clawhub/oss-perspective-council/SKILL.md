# 视角层协作 · 理事会调度器（服务套件场景）

> 蒸馏出的每个视角 skill 都是为 penguin-oss-suite 服务的内部资产。
> 它们在 S1-S5 的决策 Gate 被调用——PR 怎么切、README 怎么定位、
> 建仓选什么档、规则要不要改——不是给人当通用思维顾问玩的。

## 架构（借鉴 ClawTeam Leader-Worker 模式）

```
用户问题
  ↓
[调度器] 问题域分类 → 选 3-5 个视角（§1 路由矩阵）
  ↓
[并行分发] 每个视角一个 subagent，load 对应 perspective skill
  ↓
[收集] 每人返回标准格式：立场 + 理由 + 置信度 + 反对意见预判
  ↓
[合成] 共识区 / 分歧区 / 裁决建议（§3 合成协议）
```

## §1 视角路由矩阵

按问题域选视角，不全开（避免 9 人全上的噪声）：

| 问题域 | 首选视角 | 次选 | 理由 |
|---|---|---|---|
| 产品决策（功能取舍/定位） | 张小龙、乔布斯 | 张一鸣、马斯克 | 产品哲学对撞 |
| 商业策略（增长/变现/竞争） | 张一鸣、马斯克 | 乔布斯 | 增长 vs 克制 |
| 技术架构（选型/复杂度） | 马斯克、姚顺雨 | 田永龙 | 第一性原理 vs 工程治理 |
| AI/模型方向 | 田永龙、庞天宇 | 姚顺雨 | 研究视角 + 工程落地 |
| Skill 设计/Agent 工程 | 姚顺雨 | 马斯克、张小龙 | Skill OS 权威 |
| 开源治理（社区/贡献） | 张小龙 | 姚顺雨 | 群体演化模型直接适用 |
| AI 产品操盘（从 0 到 1） | 汪晟杰、张舒昱 | 张一鸣 | 操盘手视角 |
| 组织与人才 | 张一鸣 | 张小龙、乔布斯 | 组织建设差异 |

## §2 分发协议（每个视角 subagent 的标准 prompt）

```
你正在以 {人名} 的视角分析：{用户问题}

先 Read 对应 skill 文件：
  {skill 路径}/SKILL.md

然后按该人的心智模型回答，输出格式：
## {人名} 的立场
- 立场：[一句话，赞成/反对/有条件赞成]
- 核心理由：[基于哪个心智模型，≤3 条]
- 置信度：[高/中/低] + 为什么
- 预判反对：[其他视角最可能反驳我的点是什么]

红线：只用该人的公开思维模型，不虚构其未表达过的观点。
```

## §3 合成协议

收集所有视角后，产出三段式报告：

### 共识区（所有人都同意的）
- 列出跨视角一致的观点
- 标注有几个视角支持

### 分歧区（谁和谁对立，为什么）
- 显式列出对立：A 说 X 因为模型 1，B 说 Y 因为模型 2
- **不平均分歧**——张小龙的「不运营」和张一鸣的「大力出奇迹」不能折中成「适度运营」
- 分歧的根源是心智模型差异，标注各自模型

### 裁决建议
- 按问题域的相关性加权（路由矩阵首选 > 次选）
- 给出建议 + 理由 + 什么情况下应该换一边

## §4 使用示例

```
用户：「我们要不要给开源项目加商业化模块？」

调度器 → 问题域：开源治理 + 商业策略
选 4 视角：张小龙（治理）、张一鸣（商业）、乔布斯（产品）、马斯克（工程）

张小龙：反对——生态必须自行运转，商业化破坏社区信任（群体演化模型）
张一鸣：有条件赞成——商业化是可持续性的前提，关键是度（延迟满足模型）
乔布斯：反对——聚焦做好核心，商业化分散注意力（减法原则）
马斯克：赞成——第一性原理：开源也要活下去，钱从哪来是根本问题

合成：
- 共识：商业化需要极度克制，不能损害核心价值
- 分歧：张小龙/乔布斯（不应做） vs 张一鸣/马斯克（必须做但要克制）
- 根源：价值观差异——生态纯净性 vs 可持续性
- 裁决：倾向有条件做——按张一鸣的「度」+ 张小龙的「规则透明」，
  商业化规则必须写进 CONTRIBUTING 让社区自演化
```

## §5 套件场景集成（主用途——checklist 决策 Gate 调用）

| 套件场景 | 决策 Gate | 调用视角 | 问什么 |
|---|---|---|---|
| S2 PR 交付 | P3 方案取舍 | 姚顺雨+马斯克+张小龙 | 这个 PR 切多大？激进改还是最小 diff？ |
| S2 PR 交付 | P8 文案 | 张小龙+乔布斯 | PR 描述怎么写最有说服力？ |
| S3 文档 | README 定位 | 张小龙+张一鸣 | 首段怎么定位？强调什么？ |
| S3 文档 | 结构选型 | 乔布斯+张小龙 | 五模板选哪个？做减法到什么程度？ |
| S5 建仓 | README 档位 | 乔布斯+张小龙+姚顺雨 | 三档还是五档？多语言怎么做？ |
| S5 建仓 | 治理设计 | 张小龙+姚顺雨 | CONTRIBUTING 怎么定规则让社区自演化？ |
| S1 梳理 | 解读补充 | 田永龙+庞天宇 | 技术栈深度解读（AI/ML 仓时） |
| 架构决策 | 重大变更 | 张小龙+姚顺雨+马斯克 | 路由层改不改？规则要不要合并？ |
| 规则修订 | R 条目变更 | 姚顺雨（证据门控） | 新规则的证据够不够入正式规则？ |

**oss-workflow checklist 集成方式**：在 s1-s5.md 模板的决策步骤加一行：
```
- [ ] 决策 Gate：如需多视角裁决，调用 oss-perspective-council §5 对应行
```

## §6 已知边界

- 视角 skill 未装时跳过该视角（不硬造）
- 单视角点名不走理事会（直接用对应 skill）
- 分歧不强制收敛——有时候正确答案是「这两派都有道理，取决于你的价值观」

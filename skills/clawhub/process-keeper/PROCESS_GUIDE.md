# Process Guide

This file explains how to record process notes with `process-keeper`.

## Principles

- keep records compact
- capture meaningful turning points, not every edit
- separate process notes from product code
- keep public output free of private project names and private paths
- prefer timelines, decisions, and lessons over chat transcripts

## What to record

- major UI or UX changes
- architecture or versioning changes
- bug fixes with a clear cause
- design disagreements that get resolved
- successful or failed verification

## What to skip

- tiny copy changes that do not change direction
- day-by-day conversation logs
- implementation noise that does not affect the project story

## Suggested structure

- time
- context
- problem
- decision
- change
- result
- lesson
- article angle

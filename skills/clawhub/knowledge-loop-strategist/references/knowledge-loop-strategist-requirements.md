### 多域总览与全局纪律（先读后用）

#### A. R1-R5 校准参数（领域校准推导）

| 参数 | 本领域取值 | 执行影响 |
|------|-----------|---------|
| R1 信息密度 | 高（价值坐标、信号清单、契约字段密集） | S/C 权重高：生成前必须核对 requirements，禁止凭参数记忆输出；G 严格 |

| R3 交互性 | 中（现状确认、路线确认需使用者输入） | I 中权重：K1-01 与 K2-03 关键节点须确认 |
| R4 规范性 | 中高（三态纪律、脱敏条款为硬约束） | G 严格、自治度中：违规即 FAIL |
| R5 迭代性 | 高（时钟重估、清单迭代、K3⇄K4 回路） | S→C→A 短链高频 |

#### C. 领域坐标定义（多域判据：KLS1 定位与盘点、KLS2 燃料匹配、KLS0 术语守护）

**五层阶梯**（主体与知识创造循环的关系位置，自下游向上下游）：

| 层 | 定义 | 判定依据示例 |
|----|------|-------------|
| 执行层 | 用模型跑循环做事：写作/编码/分析/批量生成 | 产出物是直接交付的执行结果 |
| 设计层 | 造循环：把工作流重构为可复用管线、技能包、基元链 | 产出物是可复用的工作流资产 |
| 验证层 | 装裁决门：把领域判断标准编码为可核验规则与清单 | 产出物是评估清单/校验脚本/形式化规则 |
| 问题层 | 定方向：决定循环往哪递归，构建问题清单与纲领 | 产出物是经过筛选的问题清单与研究纲领 |
| 品味层 | 定价值标准：判断什么问题值得进入循环、什么结果算重要 | 产出物是判断履历与共同体公认的取舍记录 |

**四稀缺环节**（循环内部尚未被普及、价值集中的功能位）：

| 环节 | 定义 |
|------|------|
| 问题选择 | 决定提什么值得解，构建并维护经过筛选的问题清单 |
| 验证器构建 | 把领域判断标准编码为可核验规则、清单或形式化系统 |
| 消化整合 | 把机器批量产出重构为可读、可教学、可入库的知识资产 |
| 实验裁决 | 通过物理实验/现实场景对候选做最终判定 |

**上移燃料**（从下层环节向上层环节移动时携带的资产）：

| 燃料 | 定义 |
|------|------|
| 数据 | 独家积累的数据与素材，孕育问题嗅觉 |
| 社区 | 共同体信任与协作网络，支撑协作与分发 |
| 信誉 | 判断履历与公信力，是问题层与品味层的通货 |
| 工作流IP | 可模板化的管线资产，是验证层构建的原材料 |

**层与环节的关系**：四环节是循环内的功能位，五层是主体的占位坐标——验证层对应验证器构建，问题层对应问题选择，品味层收编消化整合与价值终审，实验裁决是验证层在物理世界的延伸。

#### D. 三态标注与白话注纪律（全包硬门禁）

所有裁决类输出必须三态标注：已裁决（规则/清单明确判定）/ 已校验（经验证据支撑方向）/ 待裁决（无充分依据）。禁止以"已校验"冒充"已裁决"。验证器必须显式声明覆盖边界（哪些情形清单覆盖不了），覆盖边界不得为空。

白话注规则：产出物中框架术语（阶梯层级/环节/档位/三态/时钟阶段）首次出现时，括号附一句白话解释；诊断报告与路线图的结论必须附三句话白话版，比喻随使用者领域走。

#### E. 脱敏条款（全包硬门禁）

不引用具体新闻事件、真实猜想名、真实人名、机构名、外部技能名；范本与示例一律使用假设领域与占位符；产出物引用文献须真实存在，不确定标注"待验证"；技能包自身不内置文献列表。

#### F. 模型能力分工防线

生成/重组/结构化填充交给执行模型；领域事实一律读 references/；裁决一律走 scripts/ 或评估清单；禁止凭模型参数记忆输出结构与事实；发现具体事件或人名引用即守护 FAIL。

#### G. 执行框架概念定义（多域共用，禁止仅以名称引用）

**三轴正交**：执行轴（How，必选）——决定"怎么做"，任何任务必须走；内容轴（What，按需）——决定"产出的构成"，按任务需要启用；创新轴（Why Different，按需）——决定"与默认做法有何不同"，仅在需要差异化时启用。正交 = 三轴独立启用、互不依赖、可任意组合。

**六大元操作**：

| 操作 | 定义 | 本技能典型动作 |
|------|------|---------------|
| S 感知 | 从环境获取信息 | 采集需求、读取规范与数据目录 |
| C 认知 | 对信息加工与推理 | 环节判定、档位判定、方案规划 |
| A 行动 | 产生可观测产出 | 生成报告/清单/路线图/验证器包 |
| O 组织 | 结构化管理资源 | 知识入库、目录沉淀、归档 |
| I 交互 | 与外部主体建立关系 | 现状确认、路线确认、澄清问答 |
| G 守护 | 确保安全、合规、质量 | 三态检查、脱敏检查、脚本校验 |

**六种编排模式**：

| 模式 | 定义 |
|------|------|
| 顺序 | 前序任务输出作为后序输入，逐级执行 |
| 并行 | 无依赖的任务同时执行，结果汇聚 |
| 条件 | 按判定结果选择分支（如路由到不同域） |
| 循环 | 满足迭代条件时回到前序任务（如 KLS3⇄KLS4） |
| 扇出 | 一个输入分发给多个任务（如四模式各自产题） |
| 扇入 | 多个任务输出汇聚为一个结果（如整合交付） |

**清单法**：成品 = 组件组合。步骤：确认成品目标 → 构建组件清单 → 按清单逐项填充 → 组装成品 → 一致性核对。本技能中的形态：结构类产物（诊断报告/路线图/验证器清单/问题资产卡）一律按 templates/ 模板字段逐项填充。

**样本法**：成品 = 对样本的模仿产出。步骤：获取样本（references/KLS00~KLS05 中的标准输出样例）→ 分析样本的结构与风格（不分析内容）→ 以目标内容替换样本内容 → 自检与样例结构一致。纪律：仅借鉴结构与风格，不复制样本内容。

### KLS0 协调与守护域

#### 域级说明

**场景判定表（KLS0-01 判据）**

| 场景 | 判定 | 执行路径 |
|------|------|---------|
| 快速诊断 | 使用者要定位与评估 | KLS1-01~KLS1-05 |
| 完整上移 | 使用者要定位并规划移动 | KLS1-01~KLS1-05 → KLS2-01~KLS2-05（可续 KLS3/KLS4） |

| 深化 | 对既有产物补细节 | 对应域的深化任务 |

#### KLS0-01 任务路由与三轴判定
- **必选组件**: 需求描述、场景判定（快速诊断/完整上移/领域升级/问题生成/消化整合/深化）、三轴判定（复杂度/内容类型/创新需求）、路由结论
- **可选组件**: 使用者澄清问答记录
- **组装顺序**: 需求解析→场景判定→三轴判定→路由输出
- **约束**: 场景判定须给出依据；三轴判定三维度逐项给出
- **格式**: 路由决定表（Markdown 表格）

#### KLS0-02 主链路编排
- **必选组件**: 管线编排表（任务序列、并行标记、迭代回路标记）、各阶段输入输出映射
- **可选组件**: 里程碑清单
- **组装顺序**: 读取依赖拓扑→任务序列编排→回路与并行标记→输出
- **约束**: 编排须尊重 catalog 依赖拓扑，不得人为制造冗余节点；KLS3⇄KLS4 回路至少标注进入下一轮迭代的条件
- **格式**: 管线编排表（Markdown 表格）

#### KLS0-03 事实与三态纪律守护
- **必选组件**: 守护检查记录（脱敏检查/三态完整性/待验证标注/引用真实性/术语锁定）
- **可选组件**: 违规修正建议
- **组装顺序**: 逐产物扫描→违规项标记→修正建议输出
- **约束**: 任何裁决类产物缺三态标注即 FAIL；发现具体事件或人名引用即 FAIL；术语偏离锁定译名即 FAIL
- **格式**: 守护检查清单（Markdown 表格）

#### KLS0-04 整合与重估触发
- **必选组件**: 整合交付说明、时钟重估建议时点与触发信号
- **可选组件**: 交付物清单索引
- **组装顺序**: 汇总各域产出→一致性核对→重估建议输出
- **约束**: 整合不得引入新的事实声明
- **格式**: 交付说明（Markdown）

### KLS1 循环诊断域

#### 域级说明

**分档决策表（KLS1-02 判据，逐条核对）**

| 判据 | ①自主档 | ②协作档 | ③人类主导档 |
|------|---------|---------|-------------|
| 验证形式 | 可形式化（规则/证明检查器/模拟器） | 物理实验/现实裁决 | 尚无算法化闭环 |
| 核心问题 | 领域核心判断能否编码为可核验规则？ | 裁决是否必须回到物理世界？ | 该环节是否尚无任何算法化机制？ |
| 典型形态 | 规则类、形式化类、模拟类领域 | 实验类、临床类、现场类领域 | 问题提出、价值判断、范式层 |

**普及时钟信号清单与区间规则（KLS1-03 判据）**

四类信号（至少覆盖两类方可给出阶段结论）：替代工具出现 / 平台商品化 / 成本曲线下降 / "不会做的人"存量。
阶段枚举：已普及 / 普及中 / 稀缺。
区间规则：时间估计必须输出保守区间并逐条标注依据信号；四类信号覆盖不足两类，或无任何可核查依据时，时间估计输出"待验证"。

#### KLS1-01 环节定位
- **必选组件**: 使用者现状描述、五层阶梯映射、四稀缺环节对照
- **可选组件**: 使用者补充证据、主动三问答案（产出物/受众/裁决方式——需求模糊时先执行）
- **组装顺序**: （需求模糊时先执行主动三问）现状解析→阶梯映射→环节对照→结论输出
- **约束**: 每项映射须给出行为证据；禁止跳过阶梯直接给结论
- **格式**: templates/KLS-diagnosis-report-template.md 第 1-2 节

#### KLS1-02 分档判定
- **必选组件**: 领域描述、分档决策表逐条核对记录、档位结论
- **可选组件**: 边界情形说明
- **组装顺序**: 领域解析→决策表核对→档位输出
- **约束**: 必须逐条引用分档决策表判据（见本域域级说明）；结论与判据冲突时 FAIL
- **格式**: 模板第 3 节

#### KLS1-03 普及时钟评估
- **必选组件**: 环节名称、四类信号逐项扫描记录、阶段结论、时间区间（含依据）
- **可选组件**: 使用者私有信号补充
- **组装顺序**: 信号扫描→阶段判定→区间输出
- **约束**: 四类信号至少覆盖两类；无依据的时间估计输出"待验证"
- **格式**: 模板第 4 节

#### KLS1-04 资产盘点
- **必选组件**: 四类燃料逐项盘点、环节归属标注
- **可选组件**: 资产缺口清单
- **组装顺序**: 逐类盘点→归属标注→缺口识别
- **约束**: 每项资产注明证据来源（使用者陈述/推断），推断标"待验证"
- **格式**: 模板第 5 节

#### KLS1-05 诊断深化
- **必选组件**: 深化来源（KLS1-02/03/04 待深化项）、深化执行方案
- **可选组件**: 补充澄清问题清单
- **组装顺序**: 待深化项识别→方案执行→输出
- **约束**: 深化不得推翻原结论，除非出现新证据且证据来源标注
- **格式**: 诊断报告附录（Markdown）

### KLS2 上移路线域

#### KLS2-01 上移目标匹配
- **必选组件**: 候选目标层清单、燃料×目标层匹配度矩阵、排序结论
- **可选组件**: 使用者偏好权重
- **组装顺序**: 候选枚举→矩阵评分→排序输出
- **约束**: 评分依据须来自 KLS1-04 资产盘点，不得凭空给分
- **格式**: templates/KLS-moveup-roadmap-template.md 第 1 节

#### KLS2-02 目标等价转化
- **必选组件**: 不可直接占位的目标、等价可执行命题、转化说明
- **可选组件**: 多候选等价命题对比
- **组装顺序**: 障碍识别→等价归约→命题输出
- **约束**: 等价命题须保持目标语义；转化逻辑显式可查
- **格式**: 模板第 2 节

#### KLS2-03 上移路线设计
- **必选组件**: 路线步骤序列、每步燃料转化说明、死路排除记录（已排除路线+依据）
- **可选组件**: 里程碑时间估计（标注待验证）
- **组装顺序**: 主路线设计→死路排除→输出
- **约束**: 至少排除两条候选路线并给出依据
- **格式**: 模板第 3-4 节

#### KLS2-04 退路设计
- **必选组件**: 提前普及的触发信号、退路方案（回到哪一层、携带什么燃料、第一步动作）
- **可选组件**: 多级退路
- **组装顺序**: 风险识别→退路设计→输出
- **约束**: 退路必须可执行（含明确第一步动作）
- **格式**: 模板第 5 节

#### KLS2-05 路线深化
- **必选组件**: 深化来源、深化执行方案
- **可选组件**: 执行树
- **组装顺序**: 待深化识别→方案执行→输出
- **约束**: 同 KLS1-05
- **格式**: 路线图附录（Markdown）

### KLS3 验证器构建域

#### KLS3-01 直觉图景与裁决点识别
- **必选组件**: 领域直觉图景（心智模型/比喻，一段文字+一个图示描述）、裁决点清单（可形式化组 vs 共同体裁决组）
- **可选组件**: 边界情形清单
- **组装顺序**: 直觉图景构建→裁决点枚举→分组输出
- **约束**: 直觉图景必须先于清单；两组裁决点不得混排
- **格式**: templates/KLS-verifier-checklist-template.md 第 1-2 节

#### KLS3-02 裁决点等价形式化
- **必选组件**: 不可直接形式化的裁决点、等价可编码子判断、转化说明
- **可选组件**: 转化失败清单（保留为共同体裁决）
- **组装顺序**: 逐点归约尝试→成败分组→输出
- **约束**: 归约保持判断语义；失败点如实保留，不得强行编码
- **格式**: 模板第 2 节

#### KLS3-03 评估清单生成
- **必选组件**: 三态评估清单（每条目含判定标准+状态列）、覆盖边界声明
- **可选组件**: 条目权重
- **组装顺序**: 条目编码→三态适配→边界声明→输出
- **约束**: 每条目判定标准须可操作；覆盖边界不得为空
- **格式**: 模板第 3-4 节

#### KLS3-04 验证器负载物生成
- **必选组件**: 轻量验证器包（清单文件+使用说明+适用领域声明）
- **可选组件**: 升级路径建议（脚本化/形式化方向）
- **组装顺序**: 打包→自检→输出
- **约束**: 产物为清单类文件；无代码时注明脚本化升级路径
- **格式**: 验证器包（Markdown）

#### KLS3-05 闭环运行方案
- **必选组件**: 闭环步骤（生成者/裁决者/回流机制）、人工抽查点设计
- **可选组件**: 运行频率建议
- **组装顺序**: 角色分配→回流设计→输出
- **约束**: 人工抽查点不得为空
- **格式**: 模板第 5 节

#### KLS3-06 构建深化
- **必选组件**: 深化来源、深化执行方案
- **可选组件**: 清单变更记录
- **组装顺序**: 待深化识别→方案执行→输出
- **约束**: 清单修改须保留变更记录

### KLS4 问题资产域

#### 域级说明

**四模式定义表（KLS4-01 判据与操作）**

| 模式 | 定义 | 操作步骤 | 创新路径标注格式 |
|------|------|---------|-----------------|
| 直用 | 将已验证的方法范式原样应用于本领域的新对象或新场景 | 枚举已验证范式 → 逐一试套 → 标注适配改动 | 已验证范式 → 新对象/场景 |
| 改进 | 对领域默认假设或现有方案施加系统化变形，从变形空间提取问题 | 列出默认假设 → 逐条反转/极端化/加约束 → 筛选可行项 | 默认假设反转/极端化 |
| 迁移 | 将源领域底层结构提取为抽象模式后投射到本领域 | 选异质源领域（结构可提取且与本领域异质）→ 抽象化 → 投射 → 提炼问题 | 源领域 → 抽象模式 → 目标领域 |
| 构建 | 将两个不相关概念解构为维度后强制连接，产出反常识组合 | 各解构 3~5 个维度 → 建立维度矩阵 → 强制连接 → 可能性集群 → 提炼问题 | 概念甲维度 × 概念乙维度 |

**十种创新元框架（KLS4-01 改进模式算子，可单用或组合）**

| 框架 | 操作要点 | 适用领域特征 |
|------|---------|-------------|
| 第一性原理 | 分解到不可再分的基本事实，区分假设后仅从事实重建 | 理论根基厚但需重构 |
| 逆向思维 | 列核心假设逐一反转并推到逻辑极端，重建可行方案 | 共识太强缺乏批判 |
| 辩证综合 | 正反双方全力构建最强论证，识别各自局限，创造包含并超越双方的新立场 | 存在对立学派/范式 |
| 随机性驱动 | 引入无关概念强制组合，保留看似荒谬但有趣的连接发展为方案 | 需要跨界灵感 |
| 涌现生成 | 定义基本单位与简单规则，让系统运行足够步数，记录涌现模式提取方案 | 复杂系统/社会现象 |
| 演化迭代 | 随机生成多方案 → 评估筛选 → 交叉变异 → 循环至最优 | 有多个候选方向 |
| 系统动力学 | 识别存量/流量/反馈/延迟，找高杠杆干预点 | 有反馈回路的动态机制 |
| 约束驱动 | 强化现有约束或添加新约束，在边界内穷尽可能性 | 约束反而激发创新 |
| 故事叙述 | 用叙事框架（主角/欲望/障碍/转变）重构，映射回现实 | 人文叙事/意义建构 |
| 游戏化 | 转化为游戏机制（挑战/选择/反馈），输出可立即使用的方案 | 行为激励/参与设计 |

**迁移类型与源领域质量检验（KLS4-01 迁移模式前置判据）**

迁移四类型：机制迁移（核心机制）/ 结构迁移（结构关系）/ 方法迁移（方法论）/ 概念迁移（核心概念重新定义后迁移）。

源领域质量检验（不通过时更换源领域并说明理由）：

| 检验维度 | 检验内容 | 不通过标志 |
|---------|---------|-----------|
| 结构可提取性 | 源领域有清晰可描述的底层结构 | 无法形式化描述输入→处理→输出 |
| 抽象层级匹配 | 抽象模式在目标领域有对应物 | 过于领域特异无法映射 |
| 异质充分性 | 与目标领域差异度足以产生新视角 | 源与目标过于同质 |
| 可验证性 | 迁移方案可在目标领域操作化验证 | 无法在目标领域落地检验 |

**基元运用深度选择（KLS4-01 执行方式）**

| 方式 | 特征 | 输出量 | 适用 |
|------|------|--------|------|
| 基元嵌入（快速通道） | 在基元执行框架内调用某策略，单步处理 | 每方式 2~3 个选题 | 快速多角度扫描 |
| 独立模式（完整流程） | 完全进入策略角色，按完整流程多步递进 | 框架级 2~5 个选题 | 某策略深度挖掘 |

基元重组：基元（输入→处理→输出）本身可重组为创新链路——串联（A 输出→B 输入）/ 并联（同一输入送多基元→汇总）/ 嵌套（基元内嵌子基元）/ 递归（输出回流自身迭代），链路结构本身即创新方式。

**约束**：除非使用者指定模式子集，四模式至少各生成 1 条候选；改进模式必须声明所用元框架；迁移模式必须先通过源领域质量检验；每题标注来源模式与创新路径（按四模式定义表格式）；生成前先走数据路径协议查重。

**四维评估表（KLS4-02 判据）**

| 维度 | 判定内容 | 不通过标志 |
|------|---------|-----------|
| 问题明确性 | 有可论证的核心问题 | 主题是领域词而非问题 |
| 理论传统 | 有可对话的学术脉络 | 找不到可援引的理论资源 |
| 宽窄适度 | 不过泛不过窄 | 一本书写不完/一句话说完了 |
| 非平凡性 | 能产出非平庸结论 | 结论可预测或已被充分讨论 |

**数据路径协议（KLS4-01 / KLS4-04 必读）**

1. 路径优先级：本次会话使用者指定 > 上次沿用 > 未指定且无历史时询问一次；
2. 多册并存：按研究方向可建多册，切换即换当前生效册，历史册不删除、不自动合并；查重默认当前册，跨册查重为深化可选项；
3. 路径格式：绝对路径或相对路径（以当前工作目录为基准）；禁止指向技能包内部；
4. 懒创建：文件不存在时按 templates/KLS-question-asset-template.md 的骨架创建（标题+使用说明+表头，零数据行）；
5. 幂等追加：只增数据行，永不改写骨架与已有行；手动编辑与程序追加同权；
6. 发布分离：打包或分享技能时不包含数据文件。

#### KLS4-01 四模式候选问题生成
- **必选组件**: 领域描述、四模式候选问题（直用/改进/迁移/构建）、元框架选择记录（改进模式）、源领域质量检验记录（迁移模式）、数据目录查重记录
- **可选组件**: 使用者指定模式或偏好、领域模糊澄清问答（具体子领域/已有研究基础/切入偏好）
- **组装顺序**: 数据读取查重→四模式生成（改进模式按元框架算子执行；迁移模式先过质量检验）→输出
- **约束**: 每题标注来源模式与创新路径（按域级说明定义表格式）；改进模式声明所用元框架；迁移模式先过源领域质量检验，不通过即更换源领域；与目录重复的必须剔除
- **格式**: 候选清单（Markdown）

#### KLS4-02 四维评估筛选
- **必选组件**: 逐题四维评估记录、通过/待调整结论
- **可选组件**: 修改建议
- **组装顺序**: 逐题评估→筛选→输出
- **约束**: 四维全过才通过；任一维不过须说明
- **格式**: 筛选表（Markdown 表格）

#### KLS4-03 组合纲领化
- **必选组件**: 跨题交叉分析（组合型=两个候选可合并为更大的研究问题；纲领型=多个候选围绕同一核心问题从不同角度构成研究纲领；互补型=一个候选解决另一候选的前提问题）、推荐排序
- **可选组件**: 研究纲领草图
- **组装顺序**: 交叉分析→排序→输出
- **约束**: 排序按创新性从高到低并标注依据
- **格式**: 组合纲领分析（Markdown）；拟入册条目仍按 KLS4-04 的数据文件表头契约追加

#### KLS4-04 目录沉淀与深化
- **必选组件**: 数据文件查重与追加记录、深化产物（问题树/预纲/文献定位，至少一种，形态定义见本域域级说明"选题深化形态"）
- **可选组件**: 目录整理建议、多种深化形态组合
- **组装顺序**: 查重→追加（只增行）→深化输出
- **约束**: 严格遵循数据路径协议（见本域域级说明）；不改写已有行；文献定位仅引真实文献，不确定标"待验证"
- **格式**: 数据文件追加行（Markdown 表格行）+ 深化产物（Markdown）

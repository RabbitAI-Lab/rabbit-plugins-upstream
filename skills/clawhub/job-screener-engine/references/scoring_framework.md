## 评分模型

| 项目 | 说明 |
|------|------|
| 维度 | 6 个：薪资匹配度 / 公司规模与规范度 / 技术成长空间 / 工作节奏与心理适配度 / 稳定性 / 区域居住可行性 |
| 维度评分 | A–H 等级，锚点见下文各维度表 |
| 全局评分 | 1–5 分，独立判断 + 一句综合依据 |
| 核心维度 | 默认「薪资匹配度、稳定性」，可在 `user_profile.md` 中重定义优先级 |
| 一票否决 | 触发即全局 1 分，跳过维度打分直接输出 |

---

## 等级通用语义

| 等级 | 语义 |
|------|------|
| A | 显著超出期望，构成该维度的强加分项 |
| B | 良好，达到期望水平 |
| C | 中性，基本可接受 |
| D | 偏弱，存在明显短板 |
| E | 差，接近该维度底线 |
| F | 触碰该维度底线 |
| G | 明显突破底线，重大负面信号 |
| H | 该维度否决级缺陷，通常联动一票否决 |

> 各维度表只列 A/B/C/D/F 的常见锚点；E/G/H 用于边缘与极端情况，按通用语义判断。

---

### 1. 薪资匹配度

| 等级 | 锚点 |
|------|------|
| A | Base ≥ 用户的期望薪资 |
| B | Base 明显高于底线、接近期望 |
| C | Base 贴近底线 |
| D | Base 低于底线，但处于用户配置的 trade-off 覆盖范围（如公司极稳定） |
| F | Base < 用户底线且无谈判空间（联动一票否决） |

**核心逻辑：**
- Base 薪资是核心指标，年终奖/期权/股票不作为达标条件，仅作参考加分。
- 同一薪资水平，稳定公司的等级可高于不稳定公司。具体 trade-off 规则从 `references/user_profile.md` 读取。

---

### 2. 公司规模与规范度

| 等级 | 锚点 |
|------|------|
| A | 行业头部大厂或知名外企 |
| B | 中型上市公司、B 轮+且融资额 >1 亿、成熟企业科技子公司 |
| C | B 轮+、A 轮但团队 >50 人、有明确产品线 |
| D | A 轮及以下、团队 <50 人、管理可能混乱 |
| F | 天使轮/初创，且无产品或收入信号 |

**判断依据：** 融资轮次、员工规模、是否有公开的制度和流程、是否有明确的技术管理体系。

---

### 3. 技术成长空间

| 等级 | 锚点 |
|------|------|
| A | 核心业务线，深入用户技术方向的核心（架构设计/框架开发），能建立个人技术护城河 |
| B | 匹配用户技术方向但偏应用层，有一定深度但偏工程交付 |
| C | 技术栈匹配但成长有限（维护型、工具平台定制开发） |
| D | 技术栈部分匹配、主要工作为 CRUD |
| F | 技术栈不匹配、纯外包/维护（联动「与技术方向完全无关」否决项） |

**关键区分：**
- **深度成长**：能深入技术方向的核心机制，离开公司依然有竞争力
- **应用成长**：在技术方向上积累经验，但更多是工程交付能力
- **工具型成长**：熟练使用某平台/框架，但能力绑定在特定工具上

> 用户的技术方向和成长偏好从 `references/user_profile.md` 读取。

---

### 4. 工作节奏与心理适配度

| 等级 | 锚点 |
|------|------|
| A | 明确双休、弹性工作、无 996 文化，管理风格尊重个体差异 |
| B | 基本双休、偶尔加班，管理风格偏中性，无明显 PUA/高压信号 |
| C | 大小周或节奏偏快，有中度考核压力，可能触发消耗感 |
| D | 高压 KPI、管理风格专制 |
| F | 明确 996 或严重内卷文化（联动一票否决） |

**心理适配度判断：**
根据 `references/user_profile.md` 中用户的心理模式和管理风格偏好，评估岗位的管理环境是否适配。

---

### 5. 稳定性

> **核心判断逻辑：** 账面盈利 ≠ 资金稳定。资金**来源**比账面**数字**更重要。

| 等级 | 锚点 |
|------|------|
| A | 央企/国企/研究院 或 成熟外企大厂（资金来源：国家信用/全球调配） |
| B | 知名上市公司，主营业务盈利（资金来源：资本市场） |
| C | B 轮+且融资额 >1 亿，资金充足 |
| D | A 轮但融资额尚可，或商业模式尚在探索 |
| F | 天使轮/初创，资金消耗快（如叠加裁员/欠薪信号 → 联动否决） |

**资金来源优先级：**
```
国家信用（央企/国企）> 全球调配（外企）> 资本市场（上市公司）> 主营业务（私企）
```

---

### 6. 区域居住可行性

> 核心逻辑：租房状态下通勤是可变的，公司地址决定住址。因此评估的是**公司所在区域是否适合居住**，而非通勤时间本身。

| 等级 | 锚点 |
|------|------|
| A | 周边租房性价比高，配套齐全，区域生活氛围好 |
| B | 租房合理但配套一般，或社交氛围偏弱但有基本生活设施 |
| C | 租房偏贵或配套较差，搬过去有隐形成本 |
| D | 房租明显高于预算，或环境质量差 |
| F | 区域完全不适合居住 |

## 全局评分与判定

全局分是**基于 6 个维度等级的独立判断**，不是等级的平均值。评分时优先保证「核心维度」达标（默认：薪资匹配度、稳定性；用户可在 `user_profile.md` 中重定义）。每次给出全局分必须附一句综合依据。

| 全局分 | 判定 | 锚定规则 |
|--------|------|---------|
| 5 | ⭐ 强烈推荐 | 核心维度均为 A/B，其他维度无 C 以下 |
| 4 | ✅ 推荐投递 | 核心维度均为 B 及以上，其他维度无 D 以下 |
| 3 | ⚠️ 可以考虑 | 无 D 以下；或仅非核心维度存在 D |
| 2 | 🔶 勉强可投 | 存在 D，但无否决项；仅作练手/保底 |
| 1 | ❌ 不建议 | 触发一票否决；或大面积 D/F |

> 偏离锚定规则时必须说明原因（如 trade-off 生效）。

## 重要程度评级

| 等级 | 条件 | 行动建议 |
|------|------|---------|
| S | 全局 5 分且为目标行业头部公司核心团队 | 投入最多精力，深度准备 |
| A | 全局 4 分，或各维度较均衡 | 认真准备，标准面试准备 |
| B | 全局 3 分 | 适度准备，当练手机会 |
| C | 全局 ≤2 分 | 面试前花 10 分钟看一眼 JD，不额外准备 |

## 一票否决（默认）

以下情况无论维度等级如何，直接判定 ❌，全局 1 分，跳过维度打分：

- Base < [用户底线] 且无谈判空间（具体阈值从 user_profile.md 读取）
- 明确 996 或严重内卷文化
- 公司有严重负面新闻（大规模裁员欠薪等）
- 岗位职责与用户技术方向完全无关（纯运营、纯销售包装成技术岗）

> 用户可在 `user_profile.md` 中自定义或扩展一票否决条件。

## 信息不足处理

- 某维度信息不足：该维度等级标 **「?」**，并在说明栏写清缺什么（不猜、不按中间值兜底）。
- 关键维度（薪资、公司规模、工作节奏）信息不足：向用户提问（最多 3 个，见 `info_checklist.md` 模板）。
- ≥2 个维度为「?」时：全局分给**区间**（如「3–4」），并注明依据不足；用户无法补充时取区间内保守档位。

## 同分排序

当多个岗位全局分相同或相差 1 分时，参照 `references/user_profile.md` 中的「同分排序规则」进行优先级排序。

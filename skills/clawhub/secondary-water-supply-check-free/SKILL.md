# 二次供水清洗消毒与水质检测核对（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 不联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：**物业公司**的工程部 / 客服部、**供水管理单位**的二次供水班、
**写字楼与商业综合体**的物业、**学校与医院**的后勤保障部，在**每月 / 每季**的台账复核节点上用它。
二次供水的水箱（水池、高位水箱）**每半年必须清洗消毒一次**，并做一次水质检测 ——
这本台账要么报给业主，要么报给卫生监督：**超期未清洗、检测项目缺失、结果超标未复检，都是卫生监督直接下整改 / 处罚的事**，
一旦被抽查到水箱没洗 / 水质不合格，还可能是一次**水质事故**。

**每月 / 每季必须核一遍的硬项**：

1. **清洗周期**：上次清洗日期距今是否还在 180 天内；「下次清洗日期」是不是真的等于「上次清洗日期 + 180 天」。
2. **水质检测项目**：常规指标子集（色度、浑浊度、pH、游离余氯、菌落总数、总大肠菌群）有没有做全 ——
   少做一项，这份检测报告在卫生监督眼里就不算做全，"其他项都合格"不能顶。
3. **检测限值**：每一项的结果是不是在限值之内（超标 / 低于下限都要报），越限了给倍数。
4. **清洗单位与作业人员健康证**：清洗单位、清洗人员不得空缺；健康证有效期必须覆盖本次清洗作业日。
5. **重复清洗记录**：同一水箱同一天被登记成两次清洗（两套单位 / 人员互相打架）。
6. **合计行**：合计行的水箱数（不重复水箱编号个数）与检测项数（明细行数）能不能对上。

**最容易被监管抓住的那一条**：**水箱超期没洗、或者根本没做水质检测，水却还在往住户家里送**。
这一条（超期未清洗或未检测仍在供水，P0）在完整档（另一个独立商品）里会被单独点名并给出超期天数。

**这张表会逐项核对什么**：上面这本台账的逐行算术、按水箱分组的周期覆盖、检测项目齐全性与限值判定、
清洗单位与健康证覆盖、重复记录与合计勾稽、字段合法性。

每条结论都带**原文行号与原文行内容**（水箱编号、小区、检测项目、日期、数字都在结论里），
可被第三方用同一口径复算；材料不足时**不给结论**，会明确列出还缺什么。

## 这个免费版查什么（6 项）

1. **清洗周期覆盖** —— 核对基准日 − 上次清洗日期 ≤ 180 天，超期逐水箱给出已超期天数；
   「下次清洗日期」与「上次清洗日期 + 180 天」逐水箱复算，对不上按 P2 报出差额。
2. **检测项目齐全与限值判定** —— 按水箱核对常规指标子集是否齐全（缺哪一项点哪一项）；
   逐项判定检测结果是否超出上限 / 低于下限并给出倍数（支持单值上限、区间、≥ / ≤、以及「不得检出」定性限值）。
3. **清洗单位与健康证覆盖** —— 清洗单位 / 清洗人员不得空缺；健康证有效期要覆盖本次清洗作业日，缺证或过期逐水箱点名。
4. **同一水箱同日重复清洗记录** —— 同一水箱编号 + 同一上次清洗日期下出现互相矛盾的清洗单位 / 清洗人员。
5. **合计行逐列复核** —— 水箱数 = 明细里不重复的水箱编号个数；检测项数 = 明细行数。
6. **字段合法性** —— 关键字段缺失、日期格式非法、数值为负或为零、供水状态非法。

**必需列**（缺任何一列都只报「材料不足」，**绝不给结论**）：
小区 / 项目名称、水箱编号、上次清洗日期、清洗单位、清洗人员、健康证有效期、检测日期、检测项目、
检测结果、限值、单位、下次清洗日期、核对基准日。

**这个免费版不查**（完整档才查，跑 `--sample` 会如实列出）：

- 超期未清洗或未检测仍在供水（供水状态=在供水，P0 并附超期天数）
- 停用 / 已废弃水箱仍出现在巡检记录（跨表交叉，点巡检记录行号）
- 检测结果超标未闭环（到「复检记录」段核对复检日期与复检结果）
- 消毒剂残留检测断档（按「水箱 × 检测日期」逐次比对余氯 / 二氧化氯）
- 分小区 × 分水箱（设施）汇总清单（按超期天数降序，每组给可整改动作）

## 怎么用

```bash
node scripts/run.mjs --sample                 # 先看样例
node scripts/run.mjs --input 你的材料.json     # 跑自己的材料
```

入参把 Excel 里的**表头 + 数据行**复制成文本粘进 `{"text": "…"}`（Tab 分隔最稳）。
这本台账是**长表**：一个水箱有几项检测就写几行（水箱编号、上次清洗日期、清洗单位、清洗人员、
健康证有效期在同一个水箱的多行里重复写同样的值）。
表里可以有 `合计` 行（只参与「合计行逐列复核」，不参与逐水箱检查）。
主台账之后可以再跟 `--- 消毒剂残留检测记录 ---`、`--- 巡检记录 ---`、`--- 复检记录 ---` 三段
（都用 `--- 段名 ---` 分隔）；免费版会跳过这些段，不会因此报错。

## 常见错法（每月核这张表最容易栽的 5 个坑）

1. **把「下次清洗日期」随手写成"上次清洗日期 + 6 个月"却不复算**。
   半年到底是 180 天还是 6 个自然月，差一天就可能跨过监管口径；换过清洗单位、做过提前清洗的，
   两三次一抄就串了。正确做法：按「上次清洗日期 + 180 天」复算一遍，与台账值对上，再判是否覆盖核对基准日。
2. **水箱是多行长表，却按行数去数"几个水箱"**。
   一个水箱有 6 条检测记录就有 6 行，合计行如果写 18（行数）而不是 3（不重复水箱编号个数），
   报给卫生监督的"水箱数"就是错的。这一项必须按**不重复的水箱编号**数。
3. **检测项目只写"常规指标合格"几个字，没逐项列出来**。
   水质检测必须能一项一项点出来：色度、浑浊度、pH、游离余氯、菌落总数、总大肠菌群缺哪一项都不算做全。
   台账里只写结论不写项目，这一项就永远核不了 —— 那属于材料不足，不是没问题。
4. **限值只填一个数，把区间限值当上限用**。
   游离余氯、pH 这类指标是**区间**（例如 0.05~0.8、6.5~8.5）：只填上限会漏掉"余氯不足"这种不合格，
   余氯掉到保护线以下的管网末梢同样要复检。区间要写全（用 ~ 或 - 分隔），"不得检出"这类要照抄原文。
5. **健康证只写人员姓名，不写到期日；或者到期日早于清洗作业日**。
   清洗消毒人员无有效健康证上岗是**直接处罚项**，而且算的是**作业当天**有证 ——
   写下到期日并按作业日核一遍，别用"年检过了"这类口头说法代替。

## 需要完整档时（可选）

本免费版是**完整可用的核心产出**，本版本**不包含**下面这些项：

- 超期未清洗或未检测仍在供水（供水状态=在供水，且清洗已超 180 天 / 检测已超 180 天 / 查不到有效检测日期；P0 并附超期天数）
- 停用或已废弃水箱仍出现在巡检记录（跨表交叉：台账供水状态为停用 / 废弃，却在「巡检记录」段里出现，点巡检记录原文行号）
- 检测结果超标未闭环（跨表交叉：台账里越过限值的项，到「复检记录」段核对复检日期与复检结果；缺复检或复检仍不合格逐条点名）
- 消毒剂残留检测断档（跨表交叉：按「水箱 × 检测日期」逐次比对消毒剂残留记录，哪一次没有余氯 / 二氧化氯记录就点哪一次）
- 分小区 × 分水箱（设施）汇总清单（按超期天数降序，每组给出可整改动作）与逐水箱整改清单（result.rollup / result.consolidated_actions）

同名工具的**完整档**是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别**就是上面这些，没有别的**。

## 与其他物业 / 水务核对工具的区别

同仓库里还有几个跟"水、物业"有关的核对工具，**不是同一个产品**，别混用：

- 水电抄表与账单核对（`utility-meter-reading-check`）：核的是表底、单价、用量、账单金额；
- 物业公共能耗分摊核对（`property-utility-apportionment-check`）：核的是公共能耗怎么分摊到业主；
- 污水处理费结算核对（`wastewater-fee-check`）：核的是水量勾稽、水质档位、超标扣款；
- **本工具**：核的是**二次供水水箱的清洗消毒周期 + 水质检测项目与限值**（既不抄表、也不分摊、也不算污水费）。

## 边界（请务必知道）

本工具**不做**这些判断（引擎 `CHECKS_OUT_OF_SCOPE` 里逐条列了）：

- 不判定水箱的容积、材质、内壁处理与消毒方式是否符合卫生规范 —— 那是设计审查与卫生许可的口径；
- 不判定水样采集 / 保存 / 运输 / 实验室检测过程是否规范、检测报告本身是否有效 —— 那是检测机构与卫生监督的判定权；
- 不判定超期未清洗是"物业没做"还是"做了没记"、现场是否真的已经清洗或已经停水 —— 本工具只核台账与巡检 / 复检记录的字面一致性；
- 不读 .xlsx / .pdf 原件、不联网核验清洗单位资质证书 / 健康证 / 检测报告的真伪。

**材料不足时不给结论**（连「未发现问题」也不输出），会明确列出缺什么 —— 宁可什么都不说，也不说错话。

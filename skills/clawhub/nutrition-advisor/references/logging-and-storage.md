# 记录与本地存储

仅在用户要求保存、读取、修改、汇总或删除记录时读取本文件。

## 默认行为

- 默认不持久化，先在当前对话中完成计算或汇总。
- “我吃了……”只表示用户提供了一条饮食信息，不自动等同于授权写文件。
- 用户要求长期跟踪时，先提供会保存的字段和路径，再等待确认。

确认示例：

```text
我可以把日期、餐次、食物、估算份量、热量/营养素和可选饭后感受保存为本地明文 JSON。
建议路径：<当前工作区>/nutrition-data/
这些文件可能被本机其他程序和备份读取。是否按这个路径保存？
```

## 最小数据结构

只保存用户要求的字段：

```json
{
  "date": "YYYY-MM-DD",
  "meals": [
    {
      "id": "stable-id",
      "type": "breakfast|lunch|dinner|snack|other",
      "items": [
        {
          "name": "食物名称",
          "amount": "用户提供或明确标为估算的份量",
          "calories_estimate": 0
        }
      ],
      "feeling": null
    }
  ],
  "water_ml": null
}
```

不要默认保存姓名、精确出生日期、联系方式、疾病、用药、月经日期或其他不需要的敏感数据。

## 修改、汇总与删除

- 修改前指出匹配到的日期、餐次和条目；有歧义时先询问。
- 汇总时说明缺失日期和估算记录，不把缺失数据视为零摄入。
- 删除前复述准确目标并取得确认；优先删除单条或单日记录，不扩大到整个目录。
- 不静默覆盖既有文件；使用安全写入策略，失败时保留原文件。

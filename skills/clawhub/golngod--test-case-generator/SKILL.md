# 测试用例生成器

> 输出为参考建议，最终测试方案由主理人确认后执行。

## 能力概述

将系统架构方案、功能模块清单或验收清单转化为结构化的测试用例集。支持的功能维度：

| 测试维度 | 覆盖内容 |
|---------|---------|
| 功能测试 | 正向流程、异常流程、边界条件、数据一致性 |
| 性能测试 | 响应时间、并发能力、资源占用、稳定性 |
| 安全测试 | 认证授权、数据保护、通信安全、OWASP Top 10 |
| 兼容性测试 | 浏览器、设备、网络环境、分辨率适配 |

## 输入

- **验收清单**（系统架构师输出）：需要验证的功能和指标列表
- **功能模块清单**：P0/P1/P2分级的功能模块
- **非功能需求**：性能指标、安全要求等
- **架构约束**：技术栈、部署方式等影响测试环境的信息

## 输出格式

每个测试用例包含：

```
【用例ID】TC-{模块缩写}-{三位序号}
【优先级】P0（阻塞级）/ P1（严重级）/ P2（一般级）
【所属模块】模块名称
【关联需求】对应的功能模块或需求ID
【测试标题】简明描述测试场景
【前置条件】测试前需要准备的环境、数据、权限
【测试步骤】Step 1/2/3... 每一步清晰可操作
【预期结果】系统应表现的行为
【测试数据】输入数据的具体值
【测试类型】功能/性能/安全/兼容
```

## 工作流程

1. **解析输入**：读取验收清单或功能模块列表，识别测试范围
2. **维度覆盖分析**：检查各测试维度是否被覆盖，识别遗漏
3. **用例生成**：按模块分组，每组内P0→P1→P2逐级生成
4. **质量校验**：检查用例是否覆盖了所有需求，是否存在重复
5. **输出**：结构化测试用例集，可直接用于执行

## 测试用例密度建议

| 模块复杂度 | 每功能点用例数 | 说明 |
|-----------|--------------|------|
| 简单（CRUD） | 3-5 | 正向+异常+边界 |
| 中等（含业务逻辑） | 5-10 | 含分支条件、状态流转 |
| 复杂（多系统交互） | 10-20 | 含集成点、数据一致性、并发 |

## 优先级定义

| 等级 | 定义 | 处理要求 |
|------|------|---------|
| P0 | 功能不可用、数据丢失、安全漏洞 | 必须修复，阻塞发布 |
| P1 | 核心功能异常、性能严重不达标 | 建议修复，可附带条件发布 |
| P2 | 边缘功能异常、体验问题 | 可选优化，排入下一迭代 |

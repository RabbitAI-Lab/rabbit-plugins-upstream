## 💡 一句话讲完

大多数根因分析都会**早停一层** —— 停在那个答案变成「大家都这么做」的地方。

FirstWhy 不把这句话当答案，而是当**靶子**。它把靶子拆成真约束和历史习惯，只用真约束重建方案，再倒回追问链逐层交代、证明每一层都解释得掉，最后**把整个方案立身的那条假设真验一遍**。

用 `/firstwhy <你的问题>` 调用。

## 🔥 为什么两个经典方法单独用都不行

### 5Why 会撞上一堵它无法反驳的墙

钻头往下钻，直到答案变成一个惯例：*「大家都这么做」*、*「这是标准」*、*「历史原因」*。

**钻头无法反驳惯例。** 于是你修掉一个习惯，把它标成根因，一个月后问题换张脸又回来了。

### 第一性原理能砸穿任何墙，却不知道从哪儿开始拆

它能把任何东西拆到基岩 —— 但一个复杂问题能往十个方向拆。十个全拆就是无限扩张，最后你重造了一遍轮子，却没碰到最初那个痛点。

### 各自的短板，正好是对方的强项

| | 单用 5Why | 单用第一性原理 | **FirstWhy** |
|---|---|---|---|
| 能否砸穿「大家都这么做」？ | ❌ 不能 | ✅ 能 | ✅ 能 |
| 是否知道从哪儿开始拆？ | ✅ 知道 | ❌ 不知道 | ✅ 知道 |
| 能否证明方案覆盖了每一层？ | ❌ 不能 | ❌ 不能 | ✅ 能 |
| 是否验证自己的地基假设？ | ❌ 不验 | ❌ 不验 | ✅ 验 |

## 🧠 核心洞察：卡点即交接点

一直问为什么，问到答案硬化成一条没被审视过的假设。**那句话就是靶子。**

然后把它拆开：

<table>
<tr>
<th width="50%">✅ 真约束 —— 这些才算数</th>
<th width="50%">🗑️ 历史习惯 —— 作废，可重选</th>
</tr>
<tr>
<td>

- 物理上或数学上无法回避
- 成本、时间、人手上的真实上限
- 硬性法规、安全或兼容性要求

</td>
<td>

- 当年某个人的一时之选
- 一路沿用，从没被质疑
- 没人说得清的「行业惯例」

</td>
</tr>
</table>

> **判定标准**：每条真约束都必须说清*「违反它具体会出什么事」*。
> 说不出后果的，一律归到习惯堆里。

追问负责锁定**唯一**靶点，拆解才不会无限扩张。拆解负责钻穿硬壳，追问才不会卡住。两者缺一不可。

## ⚙️ 工作原理

```
1 锁定现象
2 往下追问 ──追到能动手──→ 5 反向校验 → 6 列假设 → 7 验地基 → 关闭
   │                                      ↑                  │
   └─撞到「大家都这样」→ 3 拆靶子 → 4 重建 ┘                  │
                                                        地基假设被证伪
                                                              ↓
                                                        退回第 3 步重拆
```

| 步骤 | 做什么 | 何时可跳过 |
|---|---|---|
| **1** 锁定现象 | 一句话。不许写原因。模糊就发问 —— 绝不猜。 | 从不 |
| **2** 往下追问 | 每层都要有依据。没依据的推测标 `[假设]`。**不预设轮数** —— 撞到卡点或追到能动手就停。 | 从不 |
| **3** 拆靶子 | 约束 vs 习惯。说不出后果的都是习惯。 | 已追到能动手的原因 |
| **4** 重建 | **默认复用。** 只有当现成方案依赖的某条约束被证伪时才从零设计 —— 且必须点名是哪条。 | 已追到能动手的原因 |
| **5** 反向校验 | 逐层交代。任一层解释不掉 → 你只是补了个症状 → 退回第 4 步。 | 从不 |
| **6** 列假设 | 每个 `[假设]`，外加缺实测证据的约束。每条都配一个最省事的验法。 | 从不 |
| **7** 验地基 | 分成地基假设与边角假设。地基**当场就验**。验不过 → 方案作废 → 退回第 3 步。 | 从不 |

### 真正让流程闭环的那两步

大多数框架停在第 4 步。FirstWhy 不停，因为第 5 步和第 7 步各抓住一种不同的失败：

**第 5 步 —— 反向校验** 抓的是*半吊子修复*。它保证每一层的逻辑自洽。在本文四个完整档实例里，只做一半改动都会留下一层没交代：

| 实例 | 只修一半会漏掉这个 |
|---|---|
| 没人用的技能库 | 有验证闸门但没路由 → *「智能体根本找不到这个技能」* |
| 股票投资 | 有先验预期但没对账 → *「到底是整体在赚还是在亏」* |
| 反复出现的 bug | 有复现测试但没静态检查 → *「别处同样的写法」* |
| 算法实验设计 | 有统一配置但没朴素基线 → *「相对笨办法到底强在哪」* |

**第 7 步 —— 验地基** 抓的是*假地基*。自洽不等于真实。跳过这步，这套方法就只是在自己给自己发合格证。

| | 地基假设 | 边角假设 |
|---|---|---|
| 判定 | 「这条不成立，方案还能用吗？」**不能** | 能，只是效果差些 |
| 处理 | **当场就验**，用最省事那个验法 | 记下来，边做边看 |
| 验不过 | 方案作废 → 退回第 3 步重拆 | 调整细节，不动骨架 |
| 数量 | 通常只有一两条 | 剩下的都归这儿 |

> **地基验证应该总是很便宜。** 如果它很贵，通常说明你挑的假设不对。

地基假设拿到实测证据之前，输出必须标成 **`待验证`**，不得当成已成立的结论去做大动作。

**关闭条件**：地基假设全部验过，*或*已回炉重拆、新地基已验。边角假设可以挂着不关闭 —— 要求全验完会让分析永远关不掉。

## 📖 用法

```
/firstwhy 我们的技能库攒了几百条，但实际被用上的没几条
```

```
/firstwhy 该自己造一套评测框架，还是用现成的
```

```
/firstwhy 同一个空值处理的 bug，每次修完又冒出来
```

**命令优先。** 没有命令时，技能只在三种情况自动上：

- 需求模糊到没法动手
- 方案取舍需要站得住脚的依据
- 同一个问题「修完」又回来

其余情况一律不插手 —— 日常问答、查资料、边界清晰的小改动。

自然语言触发词同样有效：*5why*、*五个为什么*、*第一性原理*、*根因分析*、*为什么总是这样*。

### 不适用于

单次可复现的崩溃、报错或测试失败。那属于调试流程，要有证据和复现步骤（如 `systematic-debugging`）。FirstWhy 管的是**结构性反复**，不是一次性故障。

## 📚 完整实例

[`examples.md`](examples.md) 收录五个走完流程的实例 —— 不是草图，是带依据、拆解、反向校验和地基验证的完整链条：

| # | 领域 | 档位 | 撞上的那堵墙 |
|---|---|---|---|
| 1 | 项目约定每次开新会话都要重讲 | 轻量 | — *（从没卡住）* |
| 2 | 一个没人真正在用的技能库 | 完整 | *「技能就是写好的指南，模型读了自然会用」* |
| 3 | 股票投资：每笔都说得通，一年下来却亏钱 | 完整 | *「跟着大家都看的信息走，不会错」* |
| 4 | 同一类 bug 反复出现 | 完整 | *「测试够了，坏了再修」* |
| 5 | 实验分数忽高忽低，说不清方法到底有没有用 | 完整 | *「先出结果，协议后面再补」* |

实例 5 就算你不做机器学习也值得一读 —— 它的两条地基假设有**强制顺序**，在第一条跑出数字之前，「我的方法有效」这句话既不能判真、也不能判假。

## 🚫 反模式

[SKILL.md](SKILL.md#anti-patterns-any-one-of-these-is-a-failure) 里定义了八条。咬人最狠的三条：

1. **硬凑五轮** —— 第 4、5 轮多半是废话。三层能收工就三层。「5」是个形状，不是配额。
2. **把习惯当约束** —— *「大家都用 X」* 不是约束。说不出后果 → 归习惯堆。
3. **列了假设不验就当结论用** —— 裁判写在纸上，却从没请上审判席。

外加两条防止这套技能自己变成时间黑洞：

7. **什么都不验** —— 见第 3 条。
8. **要求把所有假设验完** —— 分析永远关不掉。只验地基，边角挂着。

## 🏗️ 设计说明

**零依赖。** 四个文件，全是 Markdown 加一份协议。无运行时、无构建、无包管理器。一套思维方法不该需要 `npm install`。

**扁平结构。** `SKILL.md` 就在仓库根目录，所以 `git clone <repo> <skills-dir>/firstwhy` *本身就是*安装。把技能塞进子目录会逼每个用户手动挪文件。

**刻意只留两个内容文件。** `SKILL.md` 承载方法本体（约 190 行，在技能指令 500 行预算之内）。`examples.md` 承载完整实例。没有徽章目录、没有文档站、没有版本化 changelog —— 对这个体量的方法而言，打包成本会超过维护价值。

**边界写进技能里，不留成隐含。** `SKILL.md` 和实例 4 都明确写了何时该交接给调试流程。两个悄悄重叠的技能会产出互相打架的结果。

## ❓ 常见问题

<details>
<summary><b>为什么不直接提示「用第一性原理思考」就好？</b></summary>

因为那是一种氛围，不是一套流程。没有明确的卡点信号、约束/习惯判定标准、反向校验和地基验证闸门，模型会产出听起来很自信的分析，而你无从判断它到底挖到了根，还是只是把根**描述**了一遍。

</details>

<details>
<summary><b>为什么第 4 步要写「默认复用」？</b></summary>

第一性原理有个众所周知的失败模式：它会给「重建一切」找理由。第 4 步只允许在现成方案依赖的某条约束被*证伪*时才从零设计 —— 并且要求点名是哪条。没有这道刹车，这套技能就变成一台过度设计机器。

</details>

<details>
<summary><b>它能用于非技术问题吗？</b></summary>

能。实例 3 就是股票投资。这套机制针对任何「惯例已经取代了论证」的领域 —— 流程设计、组织决策、产品取舍、个人系统。

</details>

<details>
<summary><b>如果地基假设没法便宜地验证怎么办？</b></summary>

那多半是你挑错了假设。本文四个待验证实例的地基验法成本分别是：翻交易记录、数 20 条修复记录、跑十次任务、跑一次笨办法基线。没有一条需要新建系统。真正昂贵的地基验证，通常说明真正承重的那条主张另有其物。

</details>

<details>
<summary><b>我能用中文使用它吗？</b></summary>

技能文件是英文的，但它会用什么语言写就用什么语言回你。自然语言触发词中英都有效。

</details>

# 企业尽调报告 Pro（标准版）输出格式

支付成功并拿到尽调标准版套餐 JSON 后渲染。**仅使用接口返回内容，禁止编造。**  
**面向用户的报告正文禁止出现：** 底层接口编号、`resourceId`、英文字段名（如 `duty`、`totalCount`）、「同接口××字段」等技术话术。对用户只用中文栏目名（如「义务详情」「案号」）。

数据根路径：`data`（外层 `error_code`、`reason` 不展示给用户）。

| 模块 | JSON 路径 | 类型 |
| ---- | --------- | ---- |
| 工商主体 | `data.companyinfo` | object |
| 失信被执行人 | `data.shixinbeizhixingren` | **分页对象**（见下） |
| 被执行人 | `data.beizhixingrenxinxi` | **分页对象** |
| 限制高消费 | `data.xianzhigaoxiaofei` | **分页对象** |
| 经营异常 | `data.jingyingyichang` | **分页对象** |

### 风险模块分页结构（四块相同）

```json
{
  "totalCount": 0,
  "totalPage": 0,
  "pageSize": 20,
  "pageIndex": 1,
  "data": []
}
```

| 字段 | 用途 |
| ---- | ---- |
| `totalCount` | **总数**（摘要条数、专章「共 N 条」以此为准） |
| `totalPage` | 总页数 |
| `pageSize` | 每页条数（服务端固定首页最多 20） |
| `pageIndex` | 当前页（服务端只查第 1 页） |
| `data` | **本页明细**（只渲染该数组，禁止臆造第 2 页及以后） |

**兼容**：若某模块仍返回纯数组（旧结构），则视为 `data`，`totalCount = data.length`，`pageIndex = 1`。

字段释义见同目录 `README.md` 与 `docs/`。

## 输出顺序（固定）

```markdown
{报告头 + 一页摘要}     ← 有 companyinfo.name 时必渲染

{主体工商档案}         ← companyinfo：概要 → 人员 → **股东（一张汇总表）** → **分支（一张表）** → **变更（有则必展表，禁止只写条数）**
                       （companyinfo.abnormal_items 非空时可作异常补充，优先以 jingyingyichang 专章为准）

{经营异常专章}         ← jingyingyichang；totalCount=0 / data 空也要「未见」

{被执行专章}           ← beizhixingrenxinxi；同上

{失信专章}             ← shixinbeizhixingren；同上

{限制高消费专章}       ← xianzhigaoxiaofei；同上

---
*免责页脚*
```

`companyinfo` 缺失、为空对象，或无 `name` 时：只输出「未查询到该企业信息」+ 页脚，**不**渲染风险空态装点。

```markdown
| 项目 | 内容 |
| ---- | ---- |
| 企业名称 | {companyinfo.name} |
| 经营状态 | {companyinfo.status} |
| 法定代表人 | {companyinfo.oper_name} |
| 统一社会信用代码 | {companyinfo.credit_no} |
| 风险灯 | 🔴红 / 🟡黄 / 🟢绿（仅信号灯，非合作建议） |

| 被执行记录 | {同上，M≤15} |
| 限高记录 | {同上，M≤15} |
| 经营异常 | {同上；有记录时通常本页全量} |

**说明**：
- **总数为 0**：摘要只写「共 0 条」，**不要**写「展示 0 条」。
- **总数 > 0**：写「共 N 条，展示 M 条」。若 N > M，关键发现或专章用「部分最近记录」说明（见下），**不要**对用户写分页实现细节（除非产品另有要求）。

**关键发现：**

1. {按优先级写 3～5 条事实：失信案号/限高案号/被执行标的/异常列入原因；全无则写「公开数据未见失信、被执行、限高与经营异常记录」}
```

### 风险灯判定（必须遵守）

以 **`totalCount > 0`** 表示「有记录」；明细状态看本页 `data`。

| 灯 | 条件（满足任一即取最高严重级别） |
| -- | -------------------------------- |
| 🔴 红 | `shixinbeizhixingren.totalCount > 0`；或限高本页 `data` 中存在 `caseStatus` 为「公示中」；或 `companyinfo.status` 含吊销/注销 |
| 🟡 黄 | 未触红，且：`beizhixingrenxinxi.totalCount > 0`；或经营异常本页存在 `disabled` 为 `"0"`；或限高 `totalCount > 0` 但本页均为「已不披露」等 |
| 🟢 绿 | 未触红黄；四大模块 `totalCount` 均为 0（或等价无记录） |

禁止出现：「建议合作」「不建议合作」「信誉良好」「可以放心」等句。

## 固定化最优展示（强制，禁止自由发挥）

每次查询渲染结构必须一致，**禁止**因篇幅临时省略股东/变更，**禁止**在「卡片列表 / 汇总表」之间随意切换。

| 区块 | 固定形态 |
| ---- | -------- |
| 一页摘要 | 固定表 + 关键发现 3～5 条 |
| 基本/注册/地址 | 固定两表 + 地址/范围段落 |
| 主要人员 | 姓名\|职位 表 |
| 股东 | **一张**汇总表（含类型、认缴/实缴；禁止按人拆块） |
| 分支 | **一张**序号\|名称表（合并展示） |
| 变更 | **一张**日期\|项目\|前\|后表（有则必出；上限 15） |
| 经营异常 / 被执行 / 失信 / 限高 | **一律汇总表**（禁止逐条卡片） |
| 失信义务详情 | 前 3 条全文 + 其余按案号提示 |
| 超限说明 | 固定「部分最近记录」引用块，不得改写 |

条数文案：总数 > 0 时用 `共 {totalCount} 条，展示 {M} 条`；总数为 0 时摘要只写 `共 0 条`（不写展示条数）。

## 风险列表展示规则（四大风险专章共用）

1. **渲染范围**：只使用本页返回明细。名称略有变体但能对应同一主体时**不要**过滤；若本页明细与主体**全部错配**，按第 7 条处理。  
2. **条数文案**：总数 > 0 时写 `共 {totalCount} 条，展示 {M} 条`（M 为实际渲染行数）；**总数为 0 时**（含一页摘要）只写 `共 0 条`，**禁止**再写「展示 0 条」。  
3. **展示上限**（按信息密度，从本页结果按日期降序截取；不足则全展示）：

| 专章 | 列表上限 M | 说明 |
| ---- | ---------- | ---- |
| 经营异常 | 不截断 | 通常条数少，全量展示 |
| 被执行 | **15** | 行短 |
| 限制高消费 | **15** | 行短 |
| 失信被执行人（汇总表） | **8** | 列多 |
| 失信义务详情 | **仅前 3 条全文** | 长文本；其余按案号提示 |

4. **当 `totalCount > M` 时**（面向用户固定说明，勿改写为「最新」或接口术语）：

```markdown
> 说明：公开风险记录可能较多。本报告仅列出**部分最近记录**便于阅读与快速判断；完整清单请以中国执行信息公开网、国家企业信用信息公示系统等官方渠道为准。
```

5. **无记录**：`totalCount == 0` 或明细为空 →「公开数据未见××记录」。  
6. **模块缺失**：整段不存在，或分页字段均为空/`null` 且无明细 →「暂未能获取」，禁止写成「未见」。  
7. **主体错配（强制）**：本页明细的名称/信用代码**全部**与 `companyinfo` 主体对不上（或 `reqKeyWord` 指向其他企业），视为接口异常 → 该专章写「暂未能获取」，**禁止**把无关企业记录展示为本企业风险；风险灯对该模块按「未取得有效数据」处理（不得据此标红/标绿）。略有名称变体但信用代码一致的，仍按本企业记录展示。  
8. **红黄绿灯**：仍以各模块有效 **`totalCount`**（及限高是否「公示中」等）判定，**不因展示截断改灯**；四大风险均「暂未能获取」时风险灯写「⚪ 暂无法判定」。

```markdown
| -------- | -------- | ------ | ------ |
```

## 渲染规则

1. **摘要首位**：有企业名称时必须先渲染一页摘要，再渲染工商与风险专章。  
2. **工商档案完整性**：`partners` 必须用一张汇总表列全（含认缴/实缴列）；`branches` 用表列全；`changerecords` 非空必须列表展示（禁止仅写条数）。  
3. **结构冻结**：遵守「固定化最优展示」表，同结构反复输出，禁止每次换版式。  
4. **总数 vs 展示**：总数 > 0 时写「共 N 条，展示 M 条」（M 受展示上限约束）；**总数为 0 时摘要只写「共 0 条」**，不写展示条数。  
5. **超限说明**：N > M 时使用「部分最近记录」固定说明，不用「最新」，不对用户谈分页/接口。  
6. **风险空态必显**：总数为 0 时仍输出「未见」专章。  
7. **空值**：缺失、空串、`-` 显示「—」。  
8. **文本清洗**：去除 HTML/script/iframe；保留中文标点与换行；不擅自删改义务详情、公告正文。  
9. **用户话术**：禁止「同接口××字段」「见 duty」「totalCount」等；栏目用「义务详情」「案号」等中文。  
10. **禁止臆造**：不生成未返回的数据、行政处罚、征信评分等；不输出合作建议类结论。  
11. **页脚免责**（固定追加）：

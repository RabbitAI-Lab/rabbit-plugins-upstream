# 想法抽取 / Idea extraction

把一段会议讨论或用户陈述，蒸馏成结构化 claim。**三要素缺一不可**，缺失则向用户确认，不脑补。

## claim 结构

```yaml
problem:        # 要解决什么（一句话）
method:         # 打算怎么解决（核心手段）
claimed_novelty:# 你认为新在哪（相对已知做法的差异）
context:        # 可选：场景/约束/已有基础
speaker:        # 可选：谁提出的（来自腾讯会议参会人信息）
```

## 抽取步骤

1. **定位讨论焦点**：若是整段纪要，先找「我们要做/能不能用 X 解决 Y」这类句式；若是切片，直接围绕切片。
2. **填 problem**：用户/发言人在解决什么痛点？避免抽象成「提高效率」这类空话，逼出具体对象。
3. **填 method**：核心手段是什么？是模型结构、算法、数据策略、还是流程？
4. **填 claimed_novelty**：用户自己觉得新在哪？常藏在「和常规做法不一样的是…」「我们的点在于…」。
5. **交叉校验**：若 problem 与 method 不匹配（如 method 解决不了 problem），提示用户澄清。

## 反模式（不要做）

- 把多个独立想法塞进一个 claim → 拆分。
- 用用户没说过的术语替用户「升级」想法 → 忠于原话。
- 在缺失要素时自行补全 → 追问。

## 来自腾讯会议转写的特殊处理

- 转写常有口语、打断、半句。先去除语气词与重复，再抽取。
- 用参会人信息标注 `speaker`，让报告可追溯是谁的方向。
- 若多人争论同一想法，合并为一条 claim 并标注争议点。

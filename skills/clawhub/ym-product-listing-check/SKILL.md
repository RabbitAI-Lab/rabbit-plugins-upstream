# 商品信息缺漏检查 (ym-product-listing-check)

上架前把商品信息的缺项、口径矛盾、夸大与违规风险一次翻出来。核心不是「有没有写」，而是「同一件事在三处写的是不是一样、单位对不对、承诺过不过界」。

## 何时使用

- 用户说「检查商品信息」「详情页有没有问题」「上架前检查」「这个参数对不对」「listing check」时
- 用户贴来标题、参数表、详情描述、规格、价格库存，想确认能不能上架时
- 用户只给了其中一部分，想先查能查的部分时

## 运行前提

- 依赖：无第三方依赖，纯文本处理
- 不接入任何电商平台后台，不拉取平台实时规则
- 不联网、不上传任何数据

## 输入契约

| 项 | 必需 | 说明 |
|---|---|---|
| 商品信息文本 | 必需 | 标题、参数、详情描述、规格、价格、库存，可不全 |
| 品类 | 可选 | 决定必填项与常见违规点（如食品看保质期、电器看功率） |
| 平台 | 可选 | 不同平台规则不同，决定专项检查项 |
| 图文一致性描述 | 可选 | 用户说明图与文是否一致，或当前环境能读图时由用户给图 |

**缺失处理：**

- 缺品类 → 按通用电商商品检查，并在开头注明「品类相关项未覆盖，请补充品类」
- 缺平台 → 只做通用项，不做平台专属规则检查
- 只有标题 → 明确说明只能查标题，列出还需提供哪些字段才能做完整检查
- 信息不全 → 已提供部分照常检查，缺的字段在缺漏清单里列「未提供」

## 执行步骤

1. **确定检查范围** — 写明本次拿到了哪些字段、假设了什么（品类/平台）。范围不清就在开头标注，避免用户误以为全查了。

2. **完整性检查** — 对照 `references/required-fields.md` 的 12 项必填清单逐项核对，缺哪项列哪项，写清「缺」还是「未提供」。

3. **一致性交叉核对（核心）** — 按 `references/required-fields.md` 的口径规则，逐对检查：
   - 标题、参数表、详情描述里同一属性的值是否一致（标题「500g」参数「0.5kg」可接受；标题「500ml」参数「500g」不可）
   - 单位是否统一且合理（重量用 g/kg、长度用 cm/m，不混用）
   - 价格与规格是否匹配（多规格价格梯度是否合理，有无倒挂）
   - 库存口径（总库存 vs 各规格库存是否对得上）

4. **描述风险检查** — 按 `references/risk-words.md` 的词库扫描夸大与绝对化用语（最、第一、100%、永久）、功效承诺（医疗/保健/美白/减肥等敏感表述）、虚假促销（无依据划线价、限时无限循环）。只提示风险词，不判定是否违规。

5. **可理解性检查** — 标出普通消费者看不懂的专业参数、缺失的关键购买决策信息（尺寸、是否含配件、是否需安装）。

6. **逐条写问题卡** — 每条问题写：位置（标题/参数表/详情第几段） / 类型（缺漏/矛盾/风险/难懂） / 具体描述 / 风险等级（高/中/低） / 修改建议（给可直接替换的文字）。

7. **分档** — 把问题归到「上架前必改项」（缺必填项、参数矛盾、高风险违规词）与「建议优化项」（可理解性、表达优化、中低风险词）。

8. **自检** — 输出前核对：必填清单有没有漏项？一致性矛盾有没有漏掉任一处？风险词有没有只提示不越界判定合规？修改建议是不是给了可替换文字？

## 能力边界

- 不接入任何电商平台后台，不拉取平台实时规则
- 不做广告法合规判定，只提示常见风险词供用户自查
- 不检查图片内容（除非当前环境支持读图且用户提供了图与图文一致性说明）
- 不自动修改商品信息，只给修改建议
- 不编造商品参数，缺的参数标「未提供」而非替用户补

## 常见坑

1. **只查有没有写，不查三处是否一致** — 标题写「大容量」参数写「300ml」，两处都写了但矛盾。规避：第 3 步强制三处同属性交叉比。
2. **单位混用当没毛病** — 「500ml」和「500g」看着像一样，实则体积质量混用。规避：单位合理性规则在必填清单里写明，ml/g、cm/m 不可互换。
3. **把风险词当违规结论** — 标了「第一」「永久」就写「此条违规」。规避：只提示风险，结论让用户或法务判定，不替用户下合规结论。
4. **只有标题就声称全查** — 用户只给标题，却输出完整六节显得都查了。规避：范围与假设必须在开头写明，只给标题就只查标题并列出还需字段。
5. **价格梯度倒挂没发现** — 大规格比小规格单价还贵，消费者会困惑。规避：一致性检查含价格与规格匹配，多规格要算单价梯度。
6. **编造缺的参数** — 用户没给材质，检查却写「材质：棉」。规避：所有未提供的信息标「未提供」，不替补。

## 验收用例

- 正常：完整商品信息 → 六节齐全，必改项与建议项分档明确
- 边界 1：只给标题 → 说明只能查标题，列出还需提供哪些字段
- 边界 2：标题「500ml」参数「500g」 → 判为一致性矛盾并给修改建议
- 失败：问「这样写违法吗」 → 说明不做合规结论，给常见风险提示与自查建议

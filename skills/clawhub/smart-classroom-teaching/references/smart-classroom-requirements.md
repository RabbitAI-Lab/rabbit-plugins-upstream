## 任务要求清单

每种任务类型的"零件清单"——必选/可选组件、组装顺序、约束、格式。按清单逐项产出。

### SC1 教学可视化域

#### 域级说明

SC1 域将自然语言描述转化为标准图文、立体模型与动态曲线。**核心理念**：软硬解耦后没有"手写笔迹"输入，图形与公式的入口是对话式自然语言；可视化的本质是"把语言描述的几何/代数对象还原为规范结构表达"，并保留教学语义。**关键规则**：解析必须保留学科语义（几何是图形、化学是方程式、数学是公式），不得仅做字符级转写；转化后产物须可被下游（SC3 分析、SC6 资源）直接消费。元操作以 S→C→A 为主。

#### SC1-01 自然语言要素解析
- **必选组件**: 自然语言描述（文字或语音转文字）、要素类型判定（公式/几何图形/化学方程式/文字）、解析结果（结构化表达）
- **可选组件**: 学科上下文、语义消歧、多义描述的候选列表
- **组装顺序**: 描述获取→意图与要素类型判定→按类型解析→结构化表达输出
- **约束**: 要素类型判定须准确；解析须保留学科语义；信息不足或歧义须澄清而非猜测
- **格式**: 解析结果清单（Markdown 表格：原描述/类型/结构化表达）

#### SC1-02 图形标准化
- **必选组件**: 自然语言描述的草图意图、目标标准图形、标准化规则说明
- **可选组件**: 图形参数（边长/角度/坐标）、SVG 输出
- **组装顺序**: 草图描述获取→目标图形识别→补全规则应用→标准图形输出
- **约束**: 补全须符合几何规范；须保留草图的相对位置与比例意图
- **格式**: 标准图形描述（含参数）+ 可选 SVG 代码

#### SC1-03 平面转3D
- **必选组件**: 平面图形、3D 模型描述（可拆解结构）、观察要点（点/线/面关系）
- **可选组件**: 3D 参数（顶点/棱/面）、交互观察建议
- **组装顺序**: 平面图形获取→立体结构推导→可拆解部件划分→观察要点标注
- **约束**: 立体结构须符合几何真实；可拆解部件须对应教学讲解逻辑
- **格式**: 3D 模型描述（部件 + 观察要点）

#### SC1-04 函数曲线生成
- **必选组件**: 函数算式、曲线特征描述（单调性/极值/渐近线）、关键数据点
- **可选组件**: 完整数据表、动态变化说明、SVG 曲线
- **组装顺序**: 算式解析→曲线特征分析→关键点计算→动态描述输出
- **约束**: 曲线特征须与算式一致；关键点计算须准确
- **格式**: 曲线特征描述 + 数据点表 + 可选 SVG

### SC2 虚拟人思辨域

#### 域级说明

SC2 域构建虚拟人并驱动思辨引导。**核心理念**：虚拟人的价值不在"像不像真人"，而在"是否以苏格拉底式诘问推动深度思考"。**关键规则**：角色设定须锚定真实人物原型（孔子、爱因斯坦等），诘问须基于知识点逻辑而非话术堆砌；数字分身须复刻教师风格但保持可辨识边界。元操作以 C→A→I 为主。

#### SC2-01 历史人物角色设定
- **必选组件**: 人物原型、知识背景、语言风格、价值观立场、角色卡
- **可选组件**: 12 维角色模型完整定义、代表人物语录
- **组装顺序**: 人物原型确定→知识背景梳理→语言风格提取→价值观立场明确→角色卡输出
- **约束**: 人物须真实存在且背景准确；语言风格须贴合历史语境；不得虚构人物观点
- **格式**: 角色卡（Markdown 表格）

#### SC2-02 苏格拉底式诘问
- **必选组件**: 知识点、追问链（层层递进）、引导目标、预设学生回应分支
- **可选组件**: 追问深度分级、开放性收束问题
- **组装顺序**: 知识点确认→核心概念拆解→追问链设计→回应分支准备→引导目标校验
- **约束**: 追问链须由浅入深、逻辑递进；不得直接给出答案；须预设至少 2 条学生回应分支
- **格式**: 诘问话术脚本（追问链 + 分支）

#### SC2-03 数字分身构建
- **必选组件**: 教师风格样本、语言风格特征、答疑话术模板
- **可选组件**: 口头禅/表达习惯提取、语气一致性校验
- **组装顺序**: 风格样本分析→语言特征提取→话术模板生成→一致性校验
- **约束**: 复刻风格但须标注"数字分身"身份；不得误导为教师本人实时回应
- **格式**: 数字分身话术包（风格特征 + 模板）

#### SC2-04 多语种情景对话
- **必选组件**: 对话情景、目标语种、角色扮演脚本、带读内容
- **可选组件**: 发音提示、难度分级
- **组装顺序**: 情景确定→语种匹配→脚本生成→带读内容准备
- **约束**: 语种与内容须准确；角色扮演须贴合情景；带读须标注重难点
- **格式**: 情景对话脚本（双语对照）

### SC3 课堂实录分析域

#### 域级说明

SC3 域从课堂记录中提取结构化分析并生成诊断报告。**核心理念**：课堂分析的价值在"循证"——从实录提取可验证的教学结构、行为、策略证据，而非凭印象评课。**关键规则**：分析须基于给定的课堂记录，不得虚构；三维分析（结构/行为/策略）须相互印证；诊断报告须给出可操作改进建议。元操作以 S→C→A 为主。

#### SC3-01 教学结构分析
- **必选组件**: 课堂记录、环节划分、结构逻辑分析、时间/流程标注
- **可选组件**: 环节时长占比、结构对比基准
- **组装顺序**: 课堂记录获取→环节划分→结构逻辑分析→时间流程标注
- **约束**: 环节划分须有明确边界依据；结构分析须基于记录事实
- **格式**: 教学结构图（Markdown 流程图 + 环节表）

#### SC3-02 教学行为分析
- **必选组件**: 课堂记录、教师行为分类、学生行为分类、互动频次统计
- **可选组件**: 行为时间线、互动热区
- **组装顺序**: 记录梳理→教师行为分类→学生行为分类→互动统计→结论
- **约束**: 行为分类须客观可核对；统计须基于记录，不得估算
- **格式**: 行为分析表（分类 + 频次 + 结论）

#### SC3-03 教学策略分析
- **必选组件**: 策略识别、策略有效性评估、改进方向
- **可选组件**: 策略对比、优化建议优先级
- **组装顺序**: 策略识别→有效性评估→改进方向推导
- **约束**: 策略识别须有记录佐证；有效性评估须给出判断依据
- **格式**: 策略分析报告（策略 + 评估 + 建议）

#### SC3-04 微课切片生成
- **必选组件**: 知识点、切片脚本（导入/讲解/例题/小结）、时长估算
- **可选组件**: 字幕要点、配套练习
- **组装顺序**: 知识点确定→切片结构设计→脚本撰写→时长估算
- **约束**: 切片须围绕单一知识点；脚本须完整可录制
- **格式**: 微课切片脚本

#### SC3-05 诊断报告生成
- **必选组件**: 教学纪要、思维导图、诊断结论、改进建议
- **可选组件**: 多维评分、前后对比、优先级排序
- **组装顺序**: 分析结果汇总→纪要撰写→思维导图构建→诊断结论→改进建议
- **约束**: 诊断结论须由 SC3-02/03 证据支撑；改进建议须可操作
- **格式**: 诊断报告（纪要 + 思维导图 + 结论 + 建议），参照 `exemplars/SC3-课堂实录分析域范本.md` 的 SC3-05 节

### SC4 个性化因材施教域

#### 域级说明

SC4 域基于学情实现个性化答疑与分层教学。**核心理念**：因材施教的起点是"识别差异"，终点是"匹配差异的教学动作"。**关键规则**：学情画像须基于可核实数据；答疑须针对具体错误；分层设计须让每个层级有可达成的目标。元操作以 C→A 为主，S 输入学情。

#### SC4-01 学情分析
- **必选组件**: 学生数据（答题/作业/测验）、知识掌握画像、薄弱点识别
- **可选组件**: 能力分层、进步趋势
- **组装顺序**: 数据收集→掌握度评估→薄弱点识别→画像输出
- **约束**: 画像须基于数据；涉及个人信息须先执行 SC7-03 脱敏
- **格式**: 学情画像（Markdown 表格）

#### SC4-02 个性化答疑
- **必选组件**: 学生问题、错误类型诊断、针对性讲解、巩固练习
- **可选组件**: 苏格拉底式引导（调用 SC2-02）、难度匹配
- **组装顺序**: 问题理解→错误诊断→讲解生成→巩固练习
- **约束**: 讲解须针对具体错误；可引入 SC2-02 诘问而非直接给答案
- **格式**: 答疑话术（诊断 + 讲解 + 练习）

#### SC4-03 分层教学设计
- **必选组件**: 学情分组、分层目标、分层任务、分层评价
- **可选组件**: 支架策略、弹性分组
- **组装顺序**: 学情分组→分层目标制定→分层任务设计→分层评价设计
- **约束**: 分层目标须可达；任务须匹配各层最近发展区；评价须分层对应
- **格式**: 分层教学设计（参照 `exemplars/SC4-因材施教域范本.md` 的 SC4-03 节）

### SC5 多模态交互域

#### 域级说明

SC5 域解析教学指令并调度任务。**核心理念**：交互的价值在"准确理解意图并正确分发"，语音（转文字后）与文字同源，统一走意图解析。**关键规则**：意图解析须消除歧义；调度须尊重任务依赖拓扑。元操作以 S→C 为主，I 为交互出口。

#### SC5-01 指令解析
- **必选组件**: 原始指令（文字/语音转文字）、意图识别、参数抽取、角色前缀识别、歧义澄清
- **可选组件**: 多意图拆分、置信度
- **组装顺序**: 指令获取→意图识别→角色前缀识别→参数抽取→歧义澄清→意图输出
- **约束**: 意图识别须准确；歧义须澄清而非猜测；参数缺失须补齐或询问；角色前缀识别——输入以「教师：」「学生：」开头时打 `r:"t"/"s"` 标记，无前缀默认 `r:"s"`（学生，对应引导学习模式）
- **格式**: 意图解析结果（意图 + 参数 + 角色 + 澄清点）

#### SC5-02 多任务调度
- **必选组件**: 意图列表、目标域任务映射、执行顺序、分发结果
- **可选组件**: 并行执行方案、依赖检查
- **组装顺序**: 意图归类→任务映射→依赖检查→顺序编排→分发
- **约束**: 映射须符合依赖拓扑；多意图须按依赖排序
- **格式**: 任务调度表（意图 → 任务 ID → 顺序）

### SC6 教学资源生成域

#### 域级说明

SC6 域生成课件、教案与关联资源。**核心理念**：资源生成须"以学定教"，从知识点出发，落到可用的教学材料。**关键规则**：课件须结构化；教案须含目标/流程/评价三要素；资源须与知识点强关联。元操作以 C→A 为主。

#### SC6-01 课件生成
- **必选组件**: 知识点、课件结构（导入/新知/例题/小结）、页面内容
- **可选组件**: 图表、交互设计、SVG/3D 引用（调用 SC1）
- **组装顺序**: 知识点确认→结构设计→页面内容生成→素材标注
- **约束**: 内容须准确；结构须完整；涉及图形可调用 SC1 产物
- **格式**: 课件内容（Markdown 大纲 + 页面说明）

#### SC6-02 教案生成
- **必选组件**: 教学目标、教学流程、活动设计、评价方式
- **可选组件**: 重难点分析、时间分配、板书设计
- **组装顺序**: 目标制定→流程设计→活动设计→评价设计
- **约束**: 目标须可测量；流程须闭环；活动须可操作
- **格式**: 教案（目标 + 流程 + 活动 + 评价）

#### SC6-03 知识点关联资源
- **必选组件**: 知识点、前置知识、拓展资源、关联图谱
- **可选组件**: 跨学科联系、分层素材
- **组装顺序**: 知识点确认→前置知识梳理→拓展资源匹配→关联图谱构建
- **约束**: 关联须有逻辑依据；资源须与知识点强相关
- **格式**: 关联资源清单（Markdown 表格 + 图谱描述）

### SC7 内容安全与合规域

#### 域级说明

SC7 域守护教学内容的伦理、合规与隐私。**核心理念**：安全是教学的底线，不是可选项——守护须贯穿 SC1-SC6 所有产出环节。**关键规则**：内容审核强制于交付前；隐私脱敏强制于涉及学生数据的任务；伦理守护覆盖价值观与适龄性。元操作为 G。

#### SC7-01 内容审核
- **必选组件**: 待审内容、审核维度（准确性/规范性/适龄性）、审核结论
- **可选组件**: 问题标注、修改建议
- **组装顺序**: 内容获取→逐维度审核→问题标注→结论输出
- **约束**: 审核须逐维度执行；发现问题须给出修改建议
- **格式**: 审核记录（维度 + 结论 + 建议）

#### SC7-02 教育伦理守护
- **必选组件**: 内容、价值观检查、适龄性检查、伦理边界声明
- **可选组件**: 敏感话题处理指引
- **组装顺序**: 价值观检查→适龄性检查→伦理边界声明→处理指引
- **约束**: 不得输出违背教育伦理的内容；适龄性须匹配学段
- **格式**: 伦理守护记录

#### SC7-03 隐私脱敏
- **必选组件**: 含个人信息的数据、脱敏规则、脱敏后数据
- **可选组件**: 脱敏映射表、可逆性声明
- **组装顺序**: 数据识别→个人信息定位→脱敏处理→脱敏验证
- **约束**: 姓名/学号/联系方式等须脱敏；脱敏后数据不得反向识别个体
- **格式**: 脱敏后数据 + 脱敏记录

### 显示层对接（教学工作台）

本部分为显示层对接规格（跨域基础设施），承载负载物的常驻显示层「教学工作台」（`assets/smart-classroom-workbench.html`）。工作台只负责显示，不承担输入（输入在宿主对话框）；属非教学任务，不纳入 24 任务计数。

#### 定位与边界
- 工作台对应智能黑板的"屏幕"——常驻显示、实时刷新、过程可回溯、可存档复现。
- 边界：只显示，不承担输入、不运行模型、不回写任何文件。

#### 打开方式
- 宿主环境中直接预览打开；或运行 `scripts/smart-classroom-serve.py` 启动本地服务后访问（默认 `http://127.0.0.1:8765/`，需轮询 `state.json`、需外部推送时用此方式）。

#### 本地服务
`scripts/smart-classroom-serve.py`（仅依赖 Python 标准库）：托管 `assets/` + 提供 `state.json` 读写接口，打通「外部输入 → 工作台实时更新」闭环。端点：
- `GET /` → 工作台页面；`GET /state.json` → 读取当前状态；
- `POST /api/state`（JSON 请求体）→ 写入教学状态，工作台 ≤1.2s 内自动渲染；
- `GET /api/state` → 读取当前状态。启动：`python scripts/smart-classroom-serve.py [端口]`。

`state.json` 无需预置：仅在 `POST /api/state` 推送时临时生成；工作台轮询不到时静默跳过（保持空工作台）；用完可删，下次推送重新生成。更新 state 就用本脚本的 `POST /api/state` 端点，客户端一条 POST 命令即可，无需额外脚本。

#### 实时渲染机制
- 工作台自身的内容渲染（点场景卡片、演示完整流程、回溯、播放复现、导入导出、重置）由内嵌 JS 驱动，任何能运行 HTML+JavaScript 的软件/浏览器打开均实时生效、无需刷新页面（双击 `file://` 或本地 HTTP 服务均可）。
- 外部推送（对话输入 → 工作台自动更新）依赖轮询 `state.json`：仅当通过本地 HTTP 服务打开时生效（每 1.2s 拉取一次）；双击 `file://` 打开时浏览器安全模型禁止页面读本地文件，轮询失效。`window.renderState(state)` 接口需在可访问工作台 window 对象的宿主环境（内嵌预览注入 JS 或 iframe postMessage）中调用。轮询带内容去重：`state.json` 内容未变时跳过、不重复入历史栈，仅内容真正变化才提交为新一步。

#### 教学模式与演示模式
- **教学模式（默认）**：打开即空工作台——历史栈从零开始、过程回溯无预置卡片、底部场景卡片栏默认隐藏（仅留「演示场景」入口按钮）。真实教学时工作台只显示教学状态与过程回溯，不夹杂演示内容。
- **演示模式（按需）**：点「演示场景」按钮展开场景卡片（使用指南 / SC1~SC7 / 通用渲染 / 演示完整流程），用于展示七大域能力。
- **全新开始一门课时**：保持教学模式默认态，让过程回溯从零、只记录本课的真实教学步骤，不预置任何演示卡片。

#### 连续教学推送
- 连续多课/多步教学时，每产生一个新状态就 `POST /api/state` 一次（用已有脚本端点），工作台轮询到内容变化即递增一张回溯卡片，形成连续可回溯的教学过程。
- 不要通过重新打开/刷新工作台来更新内容——那会清空浏览器内存中的历史栈、让过程回溯从零开始；要保持连续，就连续 POST、让工作台自然递增。

#### 备课与授课工作流

工作台支持三种授课模式，均基于「教学状态快照 + 历史栈 + 导出/导入」：

| 模式 | 课前 | 课中 |
|------|------|------|
| 实时分步教学 | 无 | 实时 `POST /api/state` 逐步推送、即时讲解 |
| 提前备课 | 对话一次性生成完整教学过程（多个 state 快照），`exportJSON` 导出存档 | `importJSON` 导入，点回溯卡片逐张讲解 |
| 跨课调取 | 多门课各自备课导出为 JSON | 需要讲哪一课，导入哪一课的 JSON |

备课成果即「导出回溯 JSON」（`{ meta, history }`）：一份 JSON = 一堂课的完整分步。导入后历史栈恢复为完整分步，可逐张回溯、播放复现、二次导出或改题复用。

**备课复用的最小交付物**：只需工作台 HTML（`assets/smart-classroom-workbench.html`）+ 导出的回溯 JSON 两个文件。双击 HTML 打开、导入 JSON 即恢复完整分步——导入 / 回溯 / 播放复现 / 导出均为浏览器内能力，不依赖本地服务（本地服务仅用于「实时推送」场景），也无需携带整个技能包。

**备课的两种方式**：
- **对话分步备课**：课前对话逐步生成 state（实时推送或对话产出），工作台累积成完整过程，`exportJSON` 导出。
- **直接生成回溯文件**：不经过对话分步，直接按「导出回溯 JSON」格式（`{ meta, history }`）一次性构造完整备课文件，导入即用——备课可完全离线批量完成，无需工作台与本地服务。

#### 布局

- 底部三栏：过程回溯时间轴 → 场景卡片栏（默认仅「演示场景」入口按钮） → 控制按钮栏。

| 按钮 | 功能 |
|------|------|
| 演示场景（按钮） | 默认场景卡片栏只显示此按钮；点击展开 9 个场景卡片（「工作台」组：使用指南、通用渲染；「教学能力」组：SC1~SC7） |
| 演示完整流程 | 展开后可见，按按钮栏顺序串联全部 9 个场景，生成 9 步回溯卡片 |

#### 程序接口
供宿主对话引擎调用，实现「输入 → 工作台实时更新」闭环：
- 历史：`window.commit(state)` / `back()` / `forward()` / `goto(i)` / `renderState(state)`
- 导入导出：`window.exportJSON()` / `importJSON(file)`
- 复现：`window.play()` / `pause()` / `setSpeed(ms)`
- 重置：`window.reset()` / `confirmReset()`
- 弹窗：`window.showConfirm(title, body, onOk, onCancel)` / `showToast(title, body)`

#### 数据约定
- 教学状态对象：`{ topic, board, formula, mindmap, transcript, dialogue }`
- 对话消息：`{ r: "t" | "s", t: "文本" }`（`r` 区分教师/学生）
- 画布：`board.type = "triangle" | "curve" | "cube" | "svg" | "html"`；`svg`/`html` 时 `content` 直接注入渲染
- 导出/导入回溯 JSON：`{ meta: { title, topic, steps, exportedAt }, history: [教学状态对象...] }`；`history` 中每个元素 = 教学状态对象 + `_ts`（时间戳，`HH:MM:SS`）

#### 只读性
工作台是纯只读显示层，任何实时渲染都在浏览器内存中完成（`history` 数组 + 页面 DOM），不回写工作台文件、不回写 `state.json`（轮询为单向只读 GET）。`state.json` 由外部（宿主/脚本）写入，工作台仅读取。唯一会落盘的操作是用户主动点「导出回溯」时浏览器下载的 JSON 备份文件。刷新页面后内存中的历史栈清空，工作台回到初始状态。

#### 使用注意与问题预判

| 问题 | 现象 | 规避 |
|------|------|------|
| 服务未启动 | 访问 `8765` 端口连不上 | 先 `python scripts/smart-classroom-serve.py [端口]` 再访问 |
| 端口被占用 | 脚本启动报错退出 | 换端口，如 `python scripts/smart-classroom-serve.py 9000` |
| 双击 `file://` 打开 | 外部推送轮询失效 | 起本地服务后访问 `http://127.0.0.1:8765/` |
| 刷新/重新打开工作台 | 历史栈清空、回溯从零 | 连续教学用连续 `POST /api/state`，勿刷新 |
| state 缺少字段 | 面板渲染异常或空白 | state 须含 topic/board/formula/mindmap/transcript/dialogue |
| `board.type` 非法 | 回退渲染兜底三角形 | 仅用 triangle/curve/cube/svg/html |
| `content` 非合法 SVG/HTML | 画布空白 | `svg`/`html` 类型的 content 须为合法 SVG/HTML 字符串 |
| `dialogue.r` 非法 | 气泡样式错乱 | `r` 仅 `t`（教师）/`s`（学生） |
| 导入格式不匹配 | 弹「导入失败」 | 导入须为工作台导出的 `{ meta, history }` 结构 |
| 历史栈无限增长 | 卡片累积、内存增长 | 「导出回溯」存档后「一键重置」释放 |
| 多标签页同开 | 各标签页历史栈独立 | 同一时间只用一个工作台标签页 |
| Windows 命令行传中文 JSON | 编码乱码、POST 失败 | 用 Python 或 JSON 文件方式发送 POST |

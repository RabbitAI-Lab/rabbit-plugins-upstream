# 求职简历优化

## Overview

把现有简历重构成一份**与目标岗位高度对齐、成果可量化、能通过 ATS 关键词筛选**的版本，并给出匹配度分析和「待补充信息」清单。核心原则是：优化表达结构，**绝不替用户编造经历**。

## When to use

- 用户贴简历要优化、要改、要润色。
- 用户给了目标岗位 JD 或岗位描述，要提升匹配度。
- 用户问简历为什么没回音、怎么写项目经历。

## 输入要求

- 必填：简历原文。
- 强烈建议：目标岗位 JD（没有 JD 时，请用户提供目标岗位名称与方向，或按通用优化处理）。
- 说明：目标行业 / 职级 / 工作年限、是否海投还是定向投递。

## Workflow

1. **提取既有信息**：基本信息、教育、工作履历、项目经历、技能、证书。保持事实不变。
2. **对齐目标岗位**：从 JD 提取关键词与核心能力要求（技术栈、工具、业务类型、软技能）。
3. **诊断匹配度**：对照 JD 逐项标出「已覆盖 / 部分覆盖 / 缺失」，给出评分与理由。
4. **重构内容**：
   - 项目/工作经历改用情境-任务-行动-结果结构，动词开头
   - 成果优先量化；无法量化的用「规模/范围/相对改善」表达
   - 把 JD 关键词自然嵌入已有真实经历中（不用硬塞无关关键词）
5. **输出优化版简历 + 匹配度分析 + 待补充清单**。

## 经历改写公式

```
动词 + 做了什么（方法/工具） + 产生的结果（量化指标/相对改善）

示例：
原：负责用户增长相关工作
改：搭建用户分层运营体系（RFM 模型 + 自动化触达），3 个月内活跃用户提升 28%，获客成本下降 15%
```

常用动词按场景选用：主导、搭建、重构、优化、推动、落地、产出、沉淀。避免「负责」「参与」这类无信息量的词单独使用。

## 输出模板

```
## 匹配度诊断
- 目标岗位：…
- 综合匹配度：X / 100
- 已覆盖：…   部分覆盖：…   缺失：…

| 岗位要求 | 简历现状 | 状态 | 优化动作 |
|----------|----------|------|----------|

## 优化后简历
（按 基本信息 / 核心优势摘要 / 工作经历 / 项目经历 / 技能 / 教育证书 分节输出）

## 改写对比（关键几条）
- 原文 → 优化后，说明为什么更好

## 待补充信息清单
- …

## 投递建议
- …
```

## 关键规则

- **绝不编造**：公司、职位、时间、项目、数据只能来自用户原文。需要补数据而用户没给时写 `[请补充具体数据]`，并列入待补充清单。
- **时间线一致**：不得调整或隐藏履历时间，不得为掩盖空窗期改动时间（如需处理空窗期，建议在「投递建议」里给出话术建议，而非修改事实）。
- **量化优先但允许相对表达**：拿不到绝对值时用「团队第一」「较上季度提升明显」等，并标明确认需求。
- **STAR 不硬套**：短经历不必强行凑四段，重点是「动词 + 结果」。
- **ATS 友好**：不要写进表格、文本框、图片里的内容；关键词用标准写法（JavaScript 而非 JS 全程，重要岗位可两者都写一次）。
- **篇幅**：应届/3 年内一页，资深可两页；最相关的内容放最前。
- **诚实提示**：若岗位要求与经历差距过大（如跨度转行），如实说明风险，不要包装成高匹配。

## 自检清单

- [ ] 所有事实与用户原文一致，无编造数据
- [ ] 经历改成「动词 + 结果」结构，尽量量化
- [ ] 缺失数据已标 `[请补充具体数据]` 并进待补充清单
- [ ] JD 关键词已自然嵌入真实经历
- [ ] 匹配度诊断有分数、有对比表、有缺失项
- [ ] 篇幅符合年限建议，重点前置
- [ ] ATS 不友好的写法（表格化关键信息）已避免

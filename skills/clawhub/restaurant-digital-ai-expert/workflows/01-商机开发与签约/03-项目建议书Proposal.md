# 03-项目建议书(Proposal)

## 触发条件
- 问题诊断完成后，客户需要正式的项目建议书/方案提案
- 或客户明确说"帮我们写个方案/Proposal"

## 前置输入
- 问题诊断摘要（来自02流程）
- 客户的预算范围、时间节点
- 客户的决策链信息（谁看这个proposal？谁拍板？）

## Proposal标准结构（9章）

```
第1章 项目理解
  1.1 客户背景与业务理解
  1.2 核心痛点与挑战（数据说话）
  1.3 项目必要性与紧迫性（不做会怎样）
  1.4 项目目标（量化：降本X%、增效X%、增收X%）

第2章 现状诊断与分析
  2.1 现有系统与数字化水平（附现状架构图）
  2.2 五维诊断总结（雷达图）
  2.3 根因分析
  2.4 差距分析（vs行业对标）

第3章 解决方案概述
  3.1 总体方案定位
  3.2 设计原则（8-10条）
  3.3 目标架构蓝图（附目标架构图）
  3.4 核心建设内容

第4章 详细建设方案
  4.1 系统方案（POS/会员/供应链/...各子系统设计）
  4.2 AI能力建设方案（如适用）
  4.3 数据方案（数据中台/BI/数据治理）
  4.4 集成方案（各系统间对接）
  4.5 硬件与网络方案

第5章 实施计划
  5.1 总体实施策略（整体规划、分步实施）
  5.2 阶段划分与里程碑
  5.3 甘特图/时间线
  5.4 资源需求（人力/设备/环境）
  5.5 关键依赖与前置条件

第6章 培训与变革管理
  6.1 培训计划（分层、分阶段）
  6.2 变革管理策略（ADKAR在餐饮的落地）
  6.3 上线支持方案

第7章 投资估算
  7.1 一次性投入（软件/硬件/实施/培训/定制）
  7.2 年度持续投入
  7.3 5年TCO总览
  7.4 推荐的分期付款安排

第8章 ROI与商业价值
  8.1 量化收益估算（人工/食材/效率/佣金/收入）
  8.2 非量化价值
  8.3 ROI计算与回收期
  8.4 "不做"的代价

第9章 为什么选择我们
  9.1 核心优势与差异化
  9.2 同业态案例参考
  9.3 团队介绍（如适用）
  9.4 合作模式建议
```

## 给不同客户类型的Proposal篇幅

| 客户类型 | 侧重点 | 页数 | 语言风格 |
|---------|------|:---:|---------|
| 中小餐饮老板(1-10店) | 只讲3个事：做什么、多少钱、多久回本 | 5-8页 | 口语化，少图多数据 |
| 区域连锁(10-100店) | 怎么做+投入产出+实施路径 | 10-15页 | 专业但不学术 |
| 大型连锁(100-1000店) | 全案+架构+ROI+风险 | 15-25页 | 专业深度 |
| 餐饮集团(1000+店) | 战略+架构+组织+分阶段路线 | 20-40页 | 战略级 |

## 质量检查
- [ ] 痛点描述可以用客户的原话/数据印证
- [ ] 方案有明确的设计原则（不是功能堆砌）
- [ ] 每个建议有ROI考量
- [ ] 实施计划有明确的时间/资源/依赖
- [ ] 有风险分析（不是只讲好的）
- [ ] 图表清晰（非技术人员能看懂）
- [ ] 排版统一、没有AI痕迹

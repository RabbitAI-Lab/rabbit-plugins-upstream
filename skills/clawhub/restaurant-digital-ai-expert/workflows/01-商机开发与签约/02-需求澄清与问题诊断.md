# 02-需求澄清与问题诊断

## 触发条件
- 首次沟通后，客户表达了继续了解的意愿
- 或客户提供了相关材料（系统清单/数据报表/现有流程图等）

## 前置输入
- 客户基础信息（从01流程产出）
- 客户提供的任何材料（系统清单/报表/流程图/痛点描述文档等）

## 诊断框架：MECE五维诊断

### 维度1：技术诊断（Technology）

| 诊断项 | 分析问题 | 信息来源 |
|--------|---------|---------|
| POS与收银 | 用什么系统？版本？覆盖哪些门店？使用率？ | 客户访谈/系统截图 |
| KDS/后厨 | 后厨怎么接单？有KDS吗？没有的话怎么传？ | 客户访谈/实地 |
| 外卖对接 | 接了哪些平台？自动接单还是手动？有没有聚合？ | 系统截图 |
| 系统间集成 | 会员和POS通吗？库存和POS通吗？有多少数据孤岛？ | 访谈+验证 |
| 网络基础 | 门店WiFi稳定吗？带宽够吗？断网怎么办？ | 访谈 |
| 硬件水平 | 收银机型号？打印机？KDS屏？平板？ | 盘点清单 |

### 维度2：运营诊断（Operations）

| 诊断项 | 分析问题 |
|--------|---------|
| 点餐效率 | 高峰期从顾客坐下到下单完成要多久？扫码点餐占比？ |
| 出餐速度 | 下单到出餐平均时间？高峰期呢？催菜率？ |
| 排队体验 | 怎么排队？等待时间多长？等位流失率？ |
| 外卖效率 | 外卖单处理流程？错单率？漏单率？ |
| 人员效率 | 人效(营收/人)？同业态什么水平？ |

### 维度3：数据诊断（Data）

| 诊断项 | 分析问题 |
|--------|---------|
| 营收数据 | 每天能实时看到营收吗？在手机上看？ |
| 成本数据 | 食材成本率实时能看到吗？损耗率怎么算的？ |
| 会员数据 | 有多少会员？活跃度？复购率？ |
| 数据质量 | 数据准吗？不同系统数据对得上吗？ |
| 分析能力 | 谁在看数据？看了之后做决策吗？ |

### 维度4：组织诊断（Organisation）

| 诊断项 | 分析问题 |
|--------|---------|
| IT团队 | 有IT吗？几个人？在总部还是在门店？ |
| 数字化认知 | 老板对数字化什么态度？"带头冲"还是"试试看"？ |
| 员工素养 | 平均年龄？智能手机用得来吗？愿意学吗？ |
| 变革阻力 | 以前上过系统吗？结果怎么样？有没有"踩坑"经历？ |

### 维度5：财务诊断（Finance）

| 诊断项 | 分析问题 |
|--------|---------|
| 预算能力 | 年IT预算多少？一次性还是分年？ |
| 成本结构 | 食材/人工/租金占比？利润率？ |
| 投资逻辑 | 投数字化看什么？ROI？效率？品牌？ |
| 付费意愿 | "愿意为'降本10%'付多少钱"vs"愿意为'增收10%'付多少钱" |

## 产出：问题诊断摘要

```
## 问题诊断摘要

### 核心发现(Top 3)
1. [发现1 — 用"钱"量化]
2. [发现2]
3. [发现3]

### 五维评分
| 维度 | 评分(1-5) | 核心判断 |
|------|:---:|---------|
| 技术 | [X] | [...] |
| 运营 | [X] | [...] |
| 数据 | [X] | [...] |
| 组织 | [X] | [...] |
| 财务 | [X] | [...] |

### 关键痛点的根因分析
[用5-Why或Issue Tree分析至少1个核心痛点]

### 快赢机会
[列出3-5个"投入小、见效快、确定性高"的机会]

### 建议方向
[根据客户的具体业态和痛点，给出1-3个大的方向建议]
```

## 质量检查
- [ ] 五维分析没有遗漏
- [ ] 核心发现用数据/钱来量化
- [ ] 至少分析了1个核心痛点的根因
- [ ] 给出了至少3个快赢机会
- [ ] 没有对不确定的信息做虚假判断

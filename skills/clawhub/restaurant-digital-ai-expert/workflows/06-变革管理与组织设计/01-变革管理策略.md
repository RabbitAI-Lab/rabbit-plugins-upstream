# 01-变革管理策略

## 触发条件
- 数字化项目启动前/初期，需要管理组织变革

---

## 餐饮数字化的变革管理为什么特别难？

| 挑战 | 为什么在餐饮行业特别严重 |
|------|------------------------|
| 一线员工流动性高 | 餐饮业年均离职率60-100%，刚教会就走了，新来的又要教 |
| 老板与技术脱节 | 很多餐饮老板是从厨师/服务员做起的，对技术天然不熟悉 |
| 店长"土皇帝"心态 | 店长习惯了"我的店我说了算"，系统让他感觉被监视、失去自主权 |
| 数字化带来工作方式的根本变化 | 从"靠经验"到"看数据"，从"拍脑袋"到"看系统" |
| KPI与系统使用不挂钩 | 店长不用系统照样拿奖金，那就没有用的动力 |

## Step 1: 利益相关者分析

### 识别关键角色和他们的态度

| 角色 | 典型态度 | 他们担心什么 | ⚠️ 如果忽视 |
|------|---------|------------|----------|
| CEO/老板 | 推动者 | ROI、品牌、竞争力 | 项目无资源、无推力 |
| 运营总监 | 观望/顾虑 | 门店配合度、过渡期混乱 | 最关键的中间人掉链子 |
| 区域经理 | 观望/抵触 | 多了一项"盯着门店"的工作 | 门店推广受阻 |
| 店长 | 抵触/表面配合 | "系统在监控我"、"多干活没多拿钱" | 一线数据进不去系统 |
| 厨师长 | 抵触 | "我不会用也不需要用" | KDS后厨推行失败 |
| 一线员工 | 无所谓 | 换工作频繁、学了也用不上 | 操作错误、数据不准 |
| IT部门 | 推动者（但担心被问责） | 项目失败自己背锅 | — |
| 财务部门 | 推动者（如果省到钱） | 对账更复杂了怎么办 | — |

### 利益相关者地图

```
支持度 ↑
  高 │  财务(推动)    │  CEO(推动)      │
     │   IT(推动)     │                 │
     │                │                 │
  中 │  区域经理      │  运营总监        │
     │  (中立偏负)    │  (观望)         │
     │                │                 │
  低 │  店长(抵触)    │                 │
     │  厨师长(抵触)  │                 │
     │  一线(无所谓)  │                 │
     └────────────────┴────────────────→ 影响力
          低影响力              高影响力

核心策略：
- 右上角（支持+高影响）→ 赋能，让他们当"数字化大使"
- 右下角（支持+低影响）→ 快速培训，让他们能用起来
- 左上角（抵触+低影响）→ 别先碰他们，系统能给他们带来好处时自然会转变
- 左下角（抵触+高影响）→ 最关键的战场，必须争取过来
```

## Step 2: ADKAR餐饮行业适配模型

### 标准ADKAR → 餐饮场景

| ADKAR | 餐饮场景化的含义 |
|-------|---------------|
| **A**wareness（意识） | 让店长/厨师长意识到当前的做法"已经不好用了"，产生改变动机 |
| **D**esire（意愿） | 让店长觉得"这个系统能帮我省事/省钱/多赚钱"，而不是"这是总部来监视我的" |
| **K**nowledge（知识） | 不是"怎么点这个按钮"，而是"用了系统后我每天的打烊流程是什么" |
| **A**bility（能力） | 给1-2周的"双轨并行"期（新旧并存），让员工在实际工作中学会 |
| **R**einforcement（强化） | 用数据说话："引入系统后，你店的人效提升了15%"，让成绩被看到 |

### 各阶段具体行动

#### A - 意识（第1-2周）

| 行动 | 具体做法 | 标准 |
|------|---------|------|
| 痛点可视化 | 拍视频/拍照当前店长的"麻烦事"（数小票、手工对账...）| 3分钟视频 |
| 数据说话 | "我们现在平均每家店的食材损耗是4.2%，比行业平均2.8%高了50%" | 1页PPT |
| 同行刺激 | "你认识的XX总，他们上了系统以后，店长每天早下班1小时" | 具体案例 |
| 不给压力 | 先不强制，说"我们要试试一个新东西，你们帮我们看看好不好用" | 参与感 |

#### D - 意愿（第2-4周）

| 行动 | 具体做法 | 关键 |
|------|---------|------|
| 让店长成为设计参与者 | 不是"我们已经选好了系统"，而是"这几个系统你觉得哪个适合你的店？" | 参与感=认同感 |
| 展示"用了系统你有什么好处" | "你每天可以少花30分钟在报表上"、"月底盘点不用加班了" | 对个人有利 |
| 消除恐惧 | "这个系统不是为了监控你，是为了帮你把重复活干掉" | 消除"被监视"的恐惧 |
| 建"标杆店" | 选1-2个关系好/配合度高的门店先上，让其他店长看到标杆店的店长确实更轻松 | 标杆效应 |

#### K - 知识（上线前1周+上线后2周）

| 行动 | 具体做法 | 原则 |
|------|---------|------|
| 场景化教学 | 不是教"系统功能"，是教"早班流程/午高峰流程/打烊流程怎么用系统" | 以流程为中心 |
| 操作手册(极简版) | 1页A4纸（不是50页PDF），只写"每天最常用的5件事怎么操作" | 越短越好 |
| 视频教程 | 2-3分钟/段，手机可看 | 方便临时查阅 |
| 超级用户 | 每店培养1个"系统担当"（通常是年轻的领班），其他人问他 | 师徒制 |

#### A - 能力（上线后2-4周）

| 行动 | 具体做法 | 关键 |
|------|---------|------|
| 双轨并行 | 新旧系统同时使用1-2周，让员工有"犯错的空间" | 不要一次性切 |
| 驻场支持 | 上线第一周有专人在门店驻场，遇到问题马上解决 | 不能只靠热线电话 |
| 每日15分钟复盘 | 关店后店长带团队过一遍"今天系统使用有什么问题" | 养成习惯 |

#### R - 强化（上线后持续）

| 行动 | 具体做法 | 关键 |
|------|---------|------|
| 数据反馈 | 每周给门店一份"数字化使用报告"——你店用了系统以后数据怎么样 | 让好处被看见 |
| 正向激励 | "系统使用最佳门店"每月评选+奖励（不是罚不用的人） | 正向>负向 |
| 分享会 | 月度让标杆店长分享"系统给我带来什么变化" | 同伴说服 |
| 问题响应 | 店长提的问题24小时内要有回应，即使只是"知道了，我们在解决" | 反馈闭环 |

## Step 3: 沟通计划

### 沟通矩阵

| 沟通阶段 | 目标受众 | 沟通内容 | 渠道 | 频率 |
|---------|---------|---------|------|------|
| 项目启动 | 全员 | 为什么要数字化、对公司和对你的好处 | 全员大会+门店张贴 | 1次 |
| 系统选型 | 店长/厨师长代表 | 邀请参与试���和评价 | 工作坊 | 2-3次 |
| 上线前 | 试点门店全员 | 培训+答疑+角色扮演 | 现场培训 | 密集1周 |
| 上线中 | 试点门店全员 | 每日进展、问题解答 | 微信群+驻场 | 每日 |
| 推广期 | 所有门店 | 标杆店成果展示+推广计划 | 视频+分享会 | 每两周 |
| 运营期 | 店长/区域经理 | 使用数据、优化建议征集 | 报表+问卷 | 每月 |

### 关键信息框架（对所有沟通重复这4句话）

1. **为什么做**："为了让每个人把时间花在服务顾客上，而不是花在Excel和计算器上"
2. **对我有什么好处**："每天省下XX分钟的重复工作" / "月底盘点不用加班"
3. **会有什么变化**："原来你手写的东西现在用手机点两下就好了"
4. **怎么帮我适应**："有1周的新旧并行期，有人驻场帮你，有问题随时问"

## Step 4: 阻力管理

### 识别阻力的"4个不说话"信号

| 信号 | 含义 | 行动 |
|------|------|------|
| "好的"（没表情） | 表面配合，内心拒绝 | 1对1私下沟通，了解真实顾虑 |
| 培训时频繁去厕所 | 不想学 | 了解是不是教学方法问题 |
| 系统刚上线就"卡了" | 可能是故意不操作→甩锅给系统 | 找IT证实，追踪操作日志 |
| "我太忙了没时间学" | 借口。真实理由是觉得没用 | 证明"用了反而节省时间" |

### 化解阻力的5个方法

1. **同伴影响**："跟你们一样店的XX店长用了以后库存差异下降了80%，我们找他说说？"
2. **小步快跑**："不用一下学会全部，今天只学收银和退单，其他的再说"
3. **减少负担**："先代替你做过的那部分，比如手工盘点→手机盘点"
4. **给台阶下**："你不是不会用，是系统确实有些地方不够好，我们一起来改进"
5. **老板站台**：让CEO在全员大会上亲自说"这个项目我亲自盯着"（只需要这一句）

## 餐饮变革管理常见错误

| 错误 | 后果 | 正确做法 |
|------|------|---------|
| 只培训怎么点按钮，不讲为什么要用 | 员工会操作但不愿意用 | 先讲Why再讲How |
| 强推（"XX日期前必须切系统"） | 集体抵制，找各种借口拖 | 试点→意愿→推广，不强制一步到位 |
| 店里WiFi 4G信号不好，系统卡了 | 员工骂系统烂，彻底失去信任 | 上线前先测信号，需要时加路由器+4G备份 |
| 不给员工试错空间 | 一犯错就被骂，再也不敢碰 | 双轨并行1-2周，允许犯错 |
| 上线后就不管了 | 问题积累→弃用→回到老路 | 上线后至少驻场支持1周+热线响应 |
| 用罚款/扣分来推广 | 仇恨系统+仇恨推广人 | 用正向激励代替惩罚 |

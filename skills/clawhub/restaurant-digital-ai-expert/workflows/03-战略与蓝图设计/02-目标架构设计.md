# 02-目标架构设计

## 触发条件
- 战略方向确定后，设计3年后的目标系统架构

## 架构设计指引

### 按业态和规模的推荐架构模式

| 规模 | 推荐架构 | 核心理念 |
|------|---------|---------|
| 1-10店 | SaaS组合（2-4个系统） | 选最好的单品SaaS，轻量集成 |
| 10-100店 | 核心SaaS平台+卫星SaaS | 选1个主平台(POS/会员)，其他接入 |
| 100-1000店 | 中台架构 | 业务中台+数据中台，解耦前后端 |
| 1000+店 | 自研平台+开放生态 | 统一PaaS底座，上层的应用可插拔 |

### 目标架构设计步骤

**Step 1: 绘制目标系统架构图**

采用餐饮行业分层架构：
```
┌──────────────────────────────────────────────────────────┐
│  触点层  │ 小程序 │ App │ 自助点餐机 │ 美团 │ 饿了么 │ 抖音 │
├──────────────────────────────────────────────────────────┤
│  业务层  │ 门店POS │ KDS后厨 │ 会员CRM │ 外卖聚合 │ 进销存 │ 排班 │
├──────────────────────────────────────────────────────────┤
│  中台层  │ 订单中心 │ 商品中心 │ 会员中心 │ 营销中心 │ 数据中心 │
├──────────────────────────────────────────────────────────┤
│  数据层  │ 数据仓库 │ BI报表 │ AI模型 │ 实时流 │ 数据治理 │
├──────────────────────────────────────────────────────────┤
│  基础层  │ 云服务 │ IoT │ 网络 │ 安全 │ 运维 │
└──────────────────────────────────────────────────────────┘
```

**Step 2: 定义系统边界和接口**

| 系统 | 核心职责 | 上游系统 | 下游系统 | 关键接口 |
|------|---------|---------|---------|---------|
| POS | 收银、点餐、订单管理 | — | KDS、会员、进销存 | REST API |
| KDS | 厨房订单显示、出品管理 | POS | — | WebSocket |
| 会员CRM | 会员数据、等级、积分 | POS、小程序 | BI | REST API |
| ... | ... | ... | ... | ... |

**Step 3: 设计数据架构**

- 主数据标准：菜品编码/门店编码/供应商编码/会员ID
- 数据流向：POS→数据仓库→BI/预测模型
- 数据治理：谁负责什么数据、数据质量标准

**Step 4: 定义技术标准**

| 标准 | 要求 |
|------|------|
| API协议 | RESTful HTTPS / gRPC |
| 认证方式 | OAuth 2.0 / JWT |
| 数据格式 | JSON / Protobuf |
| 日志规范 | 统一格式+集中采集 |
| 部署方式 | 容器化(K8s) / SaaS / 混合 |

## 产出

## 质量检查
- [ ] 架构图能回答"这个系统干什么、跟谁连"
- [ ] 没有过度设计（10家店不需要K8s+微服务+Service Mesh）
- [ ] 数据架构考虑了数据质量和治理
- [ ] 架构原则与客户阶段一致

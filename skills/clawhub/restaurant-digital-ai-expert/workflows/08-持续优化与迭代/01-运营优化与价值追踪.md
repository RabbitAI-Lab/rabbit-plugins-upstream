# 01-运营优化与价值追踪

## 触发条件
- 系统正式上线、进入运营阶段后3个月起，定期执行

---

## Step 1: 建立数字化健康度仪表盘

### 系统健康度指标（月度追踪）

| 指标类别 | KPI | 目标值 | 警戒线 |
|---------|-----|:---:|:---:|
| **可用性** | 系统可用率 | ≥99.9% | <99.5% |
| **可用性** | P0故障次数/月 | 0 | ≥1 |
| **可用性** | 平均故障恢复时间 | <1小时 | >2小时 |
| **使用度** | 门店日活跃率(至少完成1笔交易) | >95% | <85% |
| **使用度** | 核心功能使用率(扫码点餐/会员等) | >80% | <60% |
| **数据质量** | 日营收数据完整率(自动采集vs手工) | >95% | <90% |
| **数据质量** | 会员数据字段完整度 | >90% | <75% |
| **满意度** | 门店用户满意度(季度调研) | >4.0/5 | <3.5/5 |
| **满意度** | IT工单平均解决时间 | <24小时 | >48小时 |
| **价值** | 数字化ROI(按季度追踪) | ≥立项预期80% | <立项预期50% |

### 数据质量是数字化健康的基础

| 常见数据质量问题 | 根因 | 修复方法 |
|---------------|------|---------|
| 门店日营收与POS不一致 | 手工修改/延迟录入 | 自动采集+差异告警 |
| 菜品名称各店不一致 | 无主数据标准 | 建立菜品主数据+编码标准 |
| 会员手机号大量空/错 | 店员随便填/"懒得要" | 手机号验证+填完整奖励 |
| 库存数据与实际差异大 | 盘点不及时/不认真 | 移动盘点+差异率KPI+高压问责 |
| 不同系统数据对不上 | 接口未配置好/延迟 | 自动对账+差异自动标记 |

## Step 2: 价值追踪

### 追踪当初ROI分析中的承诺是否兑现

#### 每季度检查一次

| 当初承诺的收益 | 实际效果 | 差距 | 原因分析 | 改进措施 |
|-------------|---------|:---:|---------|---------|
| 人效提升10% | 提升7% | -3% | 2家店系统使用率低 | 加强培训+店长激励 |
| 对账时间省30分钟/天 | 省25分钟 | -5分钟 | 仍有手工调整 | 优化对账规则 |
| ... | ... | ... | ... | ... |

### 价值未达预期的常见原因

| 原因 | 表现 | 对策 |
|------|------|------|
| 系统用了但没用对 | 只用最基础功能 | 深度培训+标杆案例 |
| 数据质量差导致不敢用 | 报表不准 | 数据治理专项 |
| 业务变化导致旧配置不适用 | 业务变但系统配置没变 | 定期系统配置审计 |
| 没有明确的KPI驱动 | 看不到用和不用的区别 | 把数字化KPI纳入考核 |
| 变革管理没做到位 | 一线抗拒用 | 重新启动变革管理 |

## Step 3: 持续优化飞轮

```
         度量当前状态
              │
    ┌─────────┴─────────┐
    │                   │
  优化流程        找瓶颈(数据驱动)
    │                   │
    └─────────┬─────────┘
              │
         制定改进方案

飞轮转一圈 = 1个季度
每转一圈→数字化成熟度升0.2级
```

### 每季度必问的5个问题

| # | 问题 | 谁来答 |
|---|------|--------|
| 1 | 这个季度，系统帮我们省了多少钱/赚了多少钱？ | CIO/IT经理 |
| 2 | 哪个门店系统用得最好？哪个最差？为什么？ | 运营总监 |
| 3 | 目前最大的数据质量问题是什么？影响了什么决策？ | 数据负责人 |
| 4 | 一线对系统最大的3个抱怨是什么？ | 区域经理 |
| 5 | 竞对在数字化上有什么新动作？我们落后了吗？ | 市场/战略 |

## Step 4: 系统优化需求管理

### 需求收集渠道

| 渠道 | 方法 | 频率 |
|------|------|------|
| 门店反馈 | "系统吐槽群"（微信群：每店指定1人可发言） | 随时 |
| 数据发现 | 数据使用率低的模块→为什么没人用？ | 每月 |
| 竞对分析 | 竞对小程序/会员体系体验对比 | 每季度 |
| 用户(消费者)反馈 | 顾客投诉"你们的XX太麻烦了" | 随时 |
| 供应商更新 | SaaS厂商的新功能发布 | 按供应商节奏 |

### 需求优先级排序（维护期vs建设期）

| 需求类型 | 处理方式 | 响应时间 |
|---------|---------|:---:|
| Bug修复 | 立即修复 | P0:1h, P1:4h |
| 小优化(1-3天开发) | 合并到双周发版 | 2-4周 |
| 中期优化(1-4周) | 占开发容量30% | 按季度排 |
| 大功能/大模块 | 纳入下期项目规划 | 按二期立项 |

## Step 5: 供应商关系管理

### 年度供应商健康检查

| 检查维度 | 绿灯(OK) | 黄灯(关注) | 红灯(行动) |
|---------|---------|----------|----------|
| SLA达成 | 连续达标12个月 | 任意1个月不达标 | 连续2个月或P0不达标 |
| 产品更新 | 季度更新+年度大版本 | 半年没更新 | 1年没功能更新 |
| 公司财务 | 稳定增长 | 融资放缓 | 裁员/亏损扩大/负面消息 |
| 服务团队 | 核心人员稳定 | 更换1次客户成功经理 | 团队大规模替换 |
| 续约态度 | 积极沟通 | 不主动联系 | 态度恶化 |

### 供应商红灯行动计划

```
触发红灯后：
1. 2周内与供应商高管沟通，了解真实情况
2. 启动"Plan B"(备用供应商)预评估（不告诉原供应商）
3. 确保数据有完整导出+备份
4. 合同层面：确认退出条款+数据迁移条款可执行
5. 必要时启动正式供应商更替流程
```

## Step 6: 知识管理与交接

### 防止"人走了知识也走了"

| 知识资产 | 管理方式 | 更新频率 |
|---------|---------|:---:|
| 系统运维手册 | 文档+演练 | 每次变更后更新 |
| 常见问题FAQ | 在线文档(飞书/企业微信) | 每月更新 |
| 培训材料 | 录播视频+考核题库 | 每次新功能上线 |
| 供应商联系方式 | 集中管理(非个人微信) | 按需 |
| 决策备忘录 | "我们为什么当时选了这家的CRM" | 每次重大决策后 |

## 产出
- 数字化健康度仪表盘（月度/季度）
- 价值追踪报告（季度）
- 系统优化需求列表（优先排序）
- 供应商健康评估报告（年度）

## 质量检查
- [ ] 仪表盘不是"做了"，是有人"盯着看"（指定责任人）
- [ ] 价值追踪对比了当初ROI承诺vs实际效果
- [ ] 每个优化需求有明确的优先级和预期收益
- [ ] 供应商健康状况有评估（别等到供应商倒闭了才想起看）
- [ ] 知识管理有基本机制（防止关键人离职=数字化倒退）

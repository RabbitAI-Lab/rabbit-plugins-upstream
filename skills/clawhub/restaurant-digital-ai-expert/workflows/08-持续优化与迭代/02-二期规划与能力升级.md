# 02-二期规划与能力升级

## 触发条件
- 一期项目稳定运营6-12个月后，评估是否需要启动二期
- 或企业业态/规模发生重大变化（如从直营→加盟、新增业态、并购扩张）

---

## Step 1: 一期项目回顾

### 回顾框架（Post-Implementation Review）

| 回顾维度 | 关键问题 | 产出 |
|---------|---------|------|
| 目标达成 | 一期目标达成了多少？ROI兑现了吗？ | 达成率评估 |
| 用户满意 | 一线用户真的在用吗？满意度如何？ | 满意度报告 |
| 技术成熟 | 系统稳定吗？有技术债吗？ | 技术健康评估 |
| 流程变化 | 业务因为数字化发生了什么变化？ | 流程优化效果 |
| 能力提升 | 团队能力进步了吗？能承接更复杂的项目吗？ | 能力成熟度评估 |

### 一期回顾的一页纸模板

```
项目：XX品牌一期数字化建设
时间：202X年X月-202X年X月
投入：XX万元

目标达成：
  [达成] XX系统覆盖100家门店
  [达成] 人效从X到Y(提升Z%)
  [部分达成] 数据驱动决策率从10%到40%(目标是60%)

关键数据：
  - 系统可用率：99.8% | 店长日活率：92% | ROI：XX%

经验教训：
  1. 做对了什么：
     - 试点先行：在旗舰店试2周再推广，发现5个关键Bug
     - 标杆店长带动：XX店的李店长分享后，其他店长接受度高很多
  2. 做错了什么：
     - 低估了后厨的WiFi问题——5个店后厨信号差，KDS延迟严重
     - 培训太赶——2小时填鸭培训效果差，应该分3次每次30分钟
     - 报表太"技术"了——店长说"花里胡哨不如手机一个数字"

对二期的启示：
  - 基础设施先行：二期前全面检查门店网络
  - 培训"化整为零"：每次30分钟+场景化
  - 报表"极简主义"：手机看版>PC看版，关键数>花哨图表
```

## Step 2: 二期机会识别

### 二期项目机会来源

| 来源 | 探索方向 | 举例 |
|------|---------|------|
| 一期未覆盖 | 哪些门店/业务线/场景一期没覆盖？ | "一期只做了直营，现在加盟商也吵着要系统" |
| 业务新需求 | 业务变化带来的新数字化需求 | "我们开始做零售了(预制菜)，需要电商系统" |
| AI时机成熟 | 数据积累够了，可以启动AI | "有了18个月的订单数据，可以做需求预测了" |
| 技术升级 | 技术栈需要升级(如SaaS→中台) | "10店时的SaaS架构撑不住现在的50店" |
| 竞对压力 | 竞对在数字化上已经领先 | "XX同行的私域占比到35%，我们才8%" |

### 二期项目筛选标准

| 维度 | 权重 | 评分标准 |
|------|:---:|---------|
| 与战略目标对齐度 | 25% | 是否直接支撑3年战略目标 |
| 一期基础成熟度 | 20% | 一期的数据/系统是否能支撑二期 |
| ROI预期 | 20% | 预期投资的ROI是否显著 |
| 业务紧迫度 | 15% | 不做会"痛"到什么程度 |
| 团队能力匹配 | 10% | 当前团队能否承接(或需要什么样的外部支持) |
| 风险可控度 | 10% | 技术风险/组织风险是否可控 |

## Step 3: 能力升级路线图

### 餐饮数字化能力升级的典型路径

```
阶段1：基础系统上线
  → POS+KDS+基础会员
  → 目标：运营稳定、有数可看

阶段2：数据驱动运营
  → BI+会员精细化+供应链管理
  → 目标：数据驱动决策、降本增效

阶段3：AI与自动化
  → AI需求预测+智能排班+自动化营销
  → 目标：AI创造可测量的价值

阶段4：数字原生生态
  → 全渠道+加盟赋能+开放平台
  → 目标：数字化成为核心竞争力
```

### 按业态的能力升级重点

| 业态 | 一期重点 | 二期重点 | 三期重点 |
|------|---------|---------|---------|
| 快餐/简餐 | 扫码点餐+外卖聚合 | 会员精细化+AI排班 | 智能选址+自动化 |
| 火锅/烧烤 | 扫码点餐+会员 | 供应链+私域运营 | AI预测+动态定价 |
| 茶饮/咖啡 | 小程序下单+会员 | 私域运营+AI推荐 | 需求预测+智能补货 |
| 正餐/酒楼 | 预订+POS+会员 | 私域+BI+数据仓库 | AI营销+智能服务 |
| 连锁加盟 | 统一POS+供应链管控 | 加盟商赋能+数据透明 | AI+开放平台 |

## Step 4: 二期项目建议书

### 与一期建议书的区别

| 维度 | 一期建议书 | 二期建议书 |
|------|----------|----------|
| 起点 | 从0开始 | 已有基础和数据 |
| 论证 | 需要证明"数字化值得投" | 一期数据是最好的论证 |
| 风险 | 技术/组织都有风险 | 技术成熟了，重点是组织 |
| 亮点 | 讲行业案例 | 讲一期成绩+二期放大 |
| 预算 | 一次性投入 | 可分步审批 |

### 二期建议书的"数据魔法"

> 一期投入XX万 → 已经实现XX收益 → ROI=XX% → 回收期=XX个月
> 二期再投XX万 → 预期放大收益至XX → 预期ROI=XX%

用一期的数据证明"数字化投资是值的"，二期的论证就简单了10倍。

## Step 5: 并购/大扩张场景的数字化策略

### 当企业并购了另一个品牌，或一年内要从50店开到200店

| 场景 | 策略 | 关键动作 |
|------|------|---------|
| 并购小品牌(1-10店) | 快速整合→统一系统 | 3个月内迁移到主品牌系统 |
| 并购中型品牌(10-50店) | 先保留6个月→评估→决定 | 数据打通>系统统一，先用API对接 |
| 并购大品牌(50+店) | 长期共存或渐进整合 | 选最优系统的部分作为新统一平台 |
| 自建快速扩张 | 新店直接新系统，老店加速迁移 | 新系统"标配化"，新店不给旧系统的选择 |

### 并购数字化整合要点

```
1. 数据整合优先于系统整合
   → 先把两个品牌的数据打通(同一个BI/POS看所有门店)
   → 系统统一可以慢慢来

2. 选最优方案，不是规模大的一方吃掉小的
   → 被收购的小品牌的系统可能比收购方的好用
   → 不要"谁大听谁的"，要"谁好用谁的"

3. 不要让双方IT打架
   → 被并购团队最大的恐惧是"我的系统要被换掉了"
   → 沟通：我们选最合适的，不预设结论
```

- [ ] 建议书引用了一期的ROI数据作为论证
- [ ] 考虑了并购/大扩张等特殊场景

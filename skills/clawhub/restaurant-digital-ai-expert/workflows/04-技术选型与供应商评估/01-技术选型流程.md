# 01-技术选型流程

## 触发条件
- 战略目标和目标架构已确定，需要具体选择系统/技术栈/供应商

## 技术选型总体流程

```
需求清单梳理 → 自建vs采购决策 → 供应商长名单 → RFP → 短名单 → PoC/Pilot → 最终决策
```

---

## Step 1: 需求清单梳理

### 必做动作：用"能力矩阵"替代"功能清单"

不专业的做法："我们需要一个能管会员的系统"
专业的做法："我们需要会员管理能力，具体包括：会员等级管理、积分引擎、优惠券引擎、RFM分析、精准推送、会员标签画像、到店频次分析、沉睡唤醒自动化"

### 餐饮系统需求分类法

将需求分为四类：

| 类型 | 定义 | 举例 | 策略 |
|------|------|------|------|
| 核心刚需 | 没有这个生意没法做 | POS收银、扫码点餐、外卖接单 | 选最成熟的产品，不要创新 |
| 差异化需求 | 有它才能拉开竞争优势 | 会员精细化运营、供应链预测 | 选可定制的产品，或自研 |
| 锦上添花 | 有了更好，没有也行 | AI智能推荐、AR菜单 | 先用SaaS内置的，后期再优化 |
| 伪需求 | 老板想要但其实不需要 | "我要一个APP"（其实小程序就够了） | 引导客户放弃 |

### 餐饮系统标准能力框架（12模块）

| 模块 | 核心能力要求 | 必选/可选 |
|------|-------------|:---:|
| POS收银 | 点餐/支付/结账/退款/交接班 | 必选 |
| KDS后厨 | 订单分屏/出品管理/催菜/估清 | 必选 |
| 会员CRM | 会员档案/等级/积分/券/标签/触达 | 必选 |
| 外卖聚合 | 美团/饿了么/抖音多平台聚合 | 必选（外卖商家） |
| 进销存 | 采购/入库/盘点/成本卡/供应商管理 | 必选 |
| 排班考勤 | 排班/考勤/工时/人效报表 | 推荐 |
| 财务对账 | 多平台对账/成本核算/利润分析 | 推荐 |
| BI报表 | 经营驾驶舱/门店排名/异常预警 | 推荐 |
| 供应链 | 供应商协同/中央厨房/WMS/TMS | 连锁必选 |
| 营销工具 | 发券/拼团/秒杀/企业微信/抖音团购 | 推荐 |
| 客服系统 | 在线客服/工单/知识库/情绪分析 | 大品牌选 |
| AI能力 | 需求预测/智能排班/个性推荐/视觉识别 | L4+选 |

## Step 2: 自建 vs 采购决策

### 决策树

```
是否为核心竞争力相关？
  ├─ 是 → 是否市面上无成熟方案？
  │        ├─ 是 → 自建（如：独特的AI定价算法）
  │        └─ 否 → 买现成+深度定制
  └─ 否 → 是否有成熟SaaS？
           ├─ 是 → 直接购买
           └─ 否 → 评估后决定
```

### 自建 vs 采购决策矩阵

| 判断维度 | 倾向自建 | 倾向采购 |
|---------|---------|---------|
| 是否核心差异化 | 是 | 否 |
| 市场成熟方案 | 无/不成熟 | 有成熟方案 |
| 上线时效要求 | 不急（>12个月） | 急（<3个月） |
| IT团队能力 | 强（有研发团队） | 弱（无研发团队） |
| 定制化程度 | 极高（>50%需定制） | 低（标准功能即可） |
| 总拥有成本 | 长期自建更便宜 | 短期SaaS更便宜 |
| 供应商锁定风险 | 无法接受 | 可以接受 |

### 按客户规模的采购策略

| 客户规模 | 推荐策略 | 自建比例 | 典型系统选择 |
|---------|---------|:---:|------------|
| 1-3店 | 全SaaS | 0% | 二维火/客如云/美团餐饮 |
| 3-10店 | 核心SaaS+2-3个工具 | 0-5% | 美团/美味不用等+微会员 |
| 10-100店 | SaaS主力+1-2个自研差异���能力 | 5-15% | 核心POS+自研会员/数据 |
| 100-1000店 | 中台自研+应用SaaS | 20-40% | 自研中台+各品类最佳SaaS |
| 1000+店 | 自研核心+SaaS补充 | 50-70% | 自研PaaS+开放生态 |

## Step 3: 供应商长名单构建

### 信息来源优先级

1. **同行推荐**（尤其同规模/同业态的CTO/CIO推荐）— 最可靠
2. **行业展会**（中国国际餐饮展(CHCE)、SaaS餐饮峰会）— 了解市场
3. **分析师报告**（Gartner/IDC/易观/亿欧）— 参考但不盲信
4. **供应商官网/Demo** — 需交叉验证
5. **社交媒体**（小红书/抖音上的餐厅吐槽反而是最真实的）— 辅助参考

### 长名单标准格式

```
供应商名称 | 产品 | 成立时间 | 融资轮次 | 客户数量 | 餐饮客户占比 | 目标客群 | 备注
```

> 详见 `references/餐饮科技供应商全景图.md` 获取60+供应商的详细信息。

## Step 4: 短名单筛选标准

从长名单中选3-5家进入短名单：

| 筛选标准 | 权重 | 通过标准 |
|---------|:---:|---------|
| 餐饮行业专注度 | 20% | 餐饮客户>50%总收入 |
| 客户规模匹配 | 20% | 有同量级客户案例 |
| 产品功能匹配 | 25% | 核心需求覆盖率>80% |
| 公司稳定性 | 15% | 成立>3年、盈利或已到B轮+ |
| 服务能力 | 10% | 本地有服务团队 |
| 开放程度 | 5% | API开放程度、数据导出能力 |
| 价格合理性 | 5% | 在客户预算范围内 |

## Step 5: 技术栈推荐

### 按客户阶段的技术栈推荐

**L1-L2（初期数字化）：全部SaaS + 零自研 + 零服务器**

| 领域 | 推荐 | 理由 |
|------|------|------|
| POS | 美团餐饮/客如云 | 上手快，1天培训即可 |
| 外卖 | 美团外卖/饿了么商家版 | 直接用，无需集成 |
| 收银 | 二维火/银豹 | 价格低，功能够用 |
| 会员 | POS自带 | 先别搞单独的CRM |
| 数据 | POS自带报表 | 够看了 |
| 云 | 无（SaaS自带） | 不需要自己搞 |

**L2-L3（系统化）：主力SaaS + API集成 + 轻量数据**

| 领域 | 推荐 | 理由 |
|------|------|------|
| POS | 美团餐饮SaaS/哗啦啦 | 开放API、生态完善 |
| KDS | 厨芯/哗啦啦KDS | 集成度高 |
| 会员 | 微盟/有赞/企迈 | 专业SCRM |
| 外卖聚合 | 聚单/快财通 | 多平台聚合接单 |
| 进销存 | 来一克/观麦 | 餐饮专用 |
| BI | 观远/天财商龙 | 餐饮垂直 |
| 云 | 阿里云/华为云 | ECS即可，不需要K8s |

**L3-L4（数据驱动）：中台架构 + 混合云 + AI引入**

| 领域 | 推荐 | 理由 |
|------|------|------|
| 业务中台 | 自研/基于开源定制 | 解耦应用层 |
| 数据中台 | Databricks/ClickHouse/阿里DataWorks | 实时+离线 |
| API网关 | Kong/自研 | 统一API管理 |
| 容器平台 | K8s(ACK/TKE) | 弹性伸缩 |
| AI引擎 | 通义/DeepSeek API | 按需调用 |
| 云 | 阿里云/腾讯云/混合部署 | 混合架构 |

**L4-L5（智能化）：PaaS底座 + 微服务 + AI原生**

| 领域 | 推荐 | 理由 |
|------|------|------|
| PaaS底座 | 自研 | 开放生态 |
| 微服务体系 | Istio + K8s | 服务网格 |
| 数据平台 | 自研+开源(Apache全家桶) | 完全自主 |
| AI平台 | 多模型网关+自研Agent平台 | 模型无关 |
| 边缘计算 | 门店Edge节点 | 离线可用 |
| 云 | 多云(阿里+腾讯+华为)+私有云 | 不锁定单一云 |

## 质量检查
- [ ] 每个自建决策有明确的核心理由
- [ ] 短名单至少3家、最多5家
- [ ] 技术栈推荐与客户规模/阶段匹配
- [ ] 没有过度设计（门槛越低成本越低越好）

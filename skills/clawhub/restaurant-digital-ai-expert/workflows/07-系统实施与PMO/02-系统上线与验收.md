## Step 2: 上线执行

### 上线日流程（以周二08:00上线为例）

| 时间 | 动作 | 负责人 | 备注 |
|------|------|--------|------|
| **T-1天 20:00** | 系统上线的全员最终通知(微信群+门店) | PM | 含上线日联系人电话 |
| **D-Day 07:00** | 项目团队到场 | 全队 | 甲方IT+乙方+驻场 |
| **07:30** | 生产环境部署/更新 | 乙方技术 | 验证核心功能 |
| **08:00** | 系统切换——旧系统改为"只读" | 乙方 | — |
| **08:15** | 新系统启动+全流程测试 | 甲乙双方 | 收银→KDS→打印→支付 |
| **09:00** | 店员到岗→5分钟晨会说明新系统 | 店长+PM | "今天新系统，大家别慌" |
| **09:30** | 首批测试订单 | 店员模拟 | 至少10笔含各种支付 |
| **10:00** | 正式接客 | 全员 | — |
| **10:00-11:00** | 低峰磨合 | 全员 | 有问题立即反馈 |
| **11:00-14:00** | ⚠️ 午高峰盯防 | 全队驻场 | 人不要离开 |
| **14:00-14:30** | 午高峰复盘(15分钟) | PM+店长 | 出了什么问题、怎么修 |
| **17:00-21:00** | ⚠️ 晚高峰盯防 | 全队驻场 | 人不要离开 |
| **21:00-21:30** | 第一天复盘(30分钟) | PM+店长+全员 | 问题清单+责任人+修复时间 |

## Step 4: UAT(用户验收测试)

### UAT不是"让用户试试"，是"按标准逐一验收"

#### UAT参与人员

| 角色 | 理由 |
|------|------|
| 甲方业务负责人(运营总监) | 验收业务需求是否满足 |
| 门店店长代表(1-2人) | 验收真实场景是否好用 |
| 甲方IT代表 | 验收技术交付物 |
| 甲方财务代表 | 验收财务/对账功能 |
| 数据负责人 | 验收数据质量和报表 |

#### UAT场景清单（每个场景必须测试通过）

```
POS收银流程：
[ ] 堂食点餐→加单→退菜→结账（含会员折扣+优惠券+积分）
[ ] 外卖接单→厨房打印→出餐→骑手取餐
[ ] 扫码点餐→加购→支付→厨房KDS显示→出品

异常场景：
[ ] 网络断开→离线收银→网络恢复→数据同步（无丢失）
[ ] 打印机缺纸→续纸→自动续打
[ ] 支付未成功→退款→重复支付
[ ] 高峰并发：XX单/分钟持续XX分钟无延迟

对账场景：
[ ] 美团/饿了么/堂食/私域订单自动汇总
[ ] 日结单+现金+线上支付三方对平
[ ] 差异>XX元的订单自动标记

数据场景：
[ ] 会员数据从旧系统迁移到新系统（数量一致+字段完整）
[ ] 菜品数据从旧系统迁移到新系统（成本卡完整）

报表场景：
[ ] 日/周/月报表在XX分钟内生成
[ ] 各平台（PC/手机/平板）显示正常

权限场景：
[ ] 收银员不能查看成本数据
[ ] 店长不能修改已结账订单
[ ] 区域经理可以看到区域内所有门店
```

#### UAT签字流程

只有所有UAT场景测试通过，所有参与者签字后，项目才进入验收阶段。

## Step 5: 正式验收

### 验收交付物清单

| # | 交付物 | 验收标准 | 负责人 |
|---|-------|---------|--------|
| 1 | 系统功能 | UAT全场景通过+签字 | 业务负责人 |
| 2 | 用户文档 | 操作手册(1页版+完整版)+视频教程+FAQ | 乙方 |
| 3 | 技术文档 | 架构设计+接口文档+数据字典+部署手册 | 乙方技术 |
| 4 | 运维手册 | 日常监控+故障处理+备份恢复+升级流程 | 乙方 |
| 5 | 培训材料 | 培训PPT+考核题+考核通过人员名单 | 乙方 |
| 6 | 测试报告 | 单元/集成/性能/UAT全部测试报告 | 乙方QA |
| 7 | 数据迁移报告 | 迁移范围+数据量+验证结果 | 乙方 |
| 8 | 源代码(如适用) | 定制开发的源代码+部署脚本 | 乙方技术 |
| 9 | 许可证/授权 | 所有软件的正版授权文件 | 乙方 |
| 10 | 运维交接 | 甲方IT能独立运维且乙方确认 | 双方IT |

### 验收签字流程

```
乙方提交验收申请 → 甲方IT初审(3个工作日内)
  → 通过 → UAT执行(按场景清单逐项确认)
    → 全部通过 → 所有UAT参与人签字
      → 甲方PM汇总验收报告
        → 甲方项目发起人(Sponsor)最终签字
          → 正式验收通过 → 进入运维期
```

### 验收未通过的处理

如果UAT中有场景不通过：
1. 列出不通过清单，乙方限期修复
2. 修复完成后重新执行该场景的UAT
3. 每个场景最多3次机会（避免"反复改反复测"的死循环）
4. 如3次仍不通过→升级到项目指导委员会处理

---

## 验收后进入运维期

### 运维期开始的条件

- [ ] 验收签字完成
- [ ] 系统已稳定运行≥2周（无P0/P1事件）
- [ ] 甲方IT团队有能力独立运维（或有乙方运维合同）
- [ ] 运维SLA确认并签署

### 验收后≠乙方可以"撤"

| 阶段 | 时长 | 乙方职责 |
|------|:---:|---------|
| 质保期 | 上线后3-6个月 | 免费修复所有Bug，现场或远程支持 |
| 运维期 | 质保期后 | 按运维合同执行SLA |

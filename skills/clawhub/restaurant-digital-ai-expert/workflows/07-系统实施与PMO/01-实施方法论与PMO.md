# 01-实施方法论与PMO

## 触发条件
- 数字化项目批准，进入正式实施阶段

---

## 餐饮数字化实施8阶段方法论

```
立项准备 → 需求深化 → 方案设计 → 开发/配置 → 测试 → 试点上线 → 推广上线 → 运营优化
```

---

## Phase 1: 立项准备（2-4周）

### 项目章程（Project Charter）

| 要素 | 内容 |
|------|------|
| 项目名称 | [XX]餐饮数字化项目 |
| 项目目标 | SMART（例：6个月内完成100家门店POS系统替换，人效提升10%） |
| 项目范围 | In-scope清单 + Out-of-scope清单 |
| 项目预算 | 总预算+分项预算+紧急备用金 |
| 项目时间线 | 关键里程碑+目标上线日期 |
| 核心团队 | 甲方PM+乙方PM+关键干系人 |
| 成功标准 | 量化指标（上线30天后系统使用率>90%） |
| 退出标准 | 什么情况下项目算"失败"、什么情况下应暂停 |

### 项目团队结构

```
                       项目发起人(Sponsor) = CEO/运营VP
                                │
                  ┌─────────────┴─────────────┐
                  │                           │
          甲方项目经理                   乙方项目经理
          (内部IT/运营)                 (供应商/实施方)
                  │                           │
          ┌───────┴───────┐          ┌───────┴───────┐
          │               │          │               │
    业务负责人       技术负责人    实施顾问      技术顾问
    (运营总监)       (IT经理)    (驻场)       (远程)
          │               │
    门店代表(店长)    开发/测试团队
```

### 项目治理

| 治理机制 | 参与者 | 频率 | 议题 |
|---------|--------|------|------|
| 项目启动会(Kickoff) | 全体干系人 | 1次 | 目标、范围、计划、职责 |
| 项目周会 | 项目核心团队 | 每周 | 进度、问题、风险、下周计划 |
| 月度指导委员会 | Sponsor+核心团队 | 每月 | 重大决策、预算调整、风险审批 |
| 变更控制会 | Sponsor+PM | 按需 | 范围变更、预算调整、时间表调整 |

## Phase 2: 需求深化（2-4周）

在RFP的需求基础上，深入每个业务场景：

### 需要深化的关键领域

| 领域 | 深化内容 |
|------|---------|
| 业务流程 | "一张订单从扫码到出餐全过程" — 画出现状和未来状态 |
| 边缘场景 | 退款、改单、断网、高峰期加单、外卖平台掉线... |
| 数据标准 | 菜品编码规则、门店编码规则、数据字典 |
| 集成接口 | 每个接口的数据字段、频率、异常处理 |
| 权限矩阵 | 谁可以看什么、改什么、删什么（按角色定义） |

### 需求确认会

- 每个业务模块开1-2次确认会
- 必须有：甲方业务负责人 + 甲方技术 + 乙方实施 + 乙方技术
- 产出：签字确认的需求规格说明书（SRS）

## Phase 4: 开发/配置（4-12周，取决于复杂度）

### 餐饮系统开发特有的注意事项

| 注意点 | 说明 |
|--------|------|
| 高峰性能 | 必须以门店午晚高峰的并发量做压力测试，不是"平均负载" |
| 离线模式 | POS/KDS必须支持离线——网络断了对餐饮是常态，不是意外 |
| 打印稳定性 | 打印机连接失败时怎么办？自动重试3次→告警→人工介入 |
| 支付幂等性 | 用户重复点击付款→绝不能扣两次钱 |
| iOS/Android兼容 | 门店设备可能很老旧（Android 7 还在一线服役） |

## Phase 5: 测试（3-6周）

### 测试层级

| 测试类型 | 执行者 | 重点 |
|---------|--------|------|
| 单元测试 | 乙方开发 | 代码级 |
| 集成测试 | 乙方QA | 接口+数据流 |
| 系统测试 | 乙方QA | 全功能+性能 |
| 高峰压力测试 | 乙方+甲方 | 午晚高峰并发模拟 |
| **UAT** | 甲方业务+店长代表 | 真实场景操作 |
| 数据迁移测试 | 甲乙双方 | 迁移全量数据→比对验证 |

### 餐饮特有的测试场景清单

```
[ ] 午高峰：60人在15分钟内同时扫码点餐+支付
[ ] 晚高峰：KDS同时显示80个待做订单
[ ] 断网恢复：关掉WiFi→POS离线收银30分钟→恢复WiFi→数据同步
[ ] 打印机没纸：后厨打印过程中缺纸→续纸→自动续打
[ ] 退款全流程：客人退菜→收银退款→KDS取消→库存回仓
[ ] 外卖聚合：美团+饿了么同时来单→聚合器不丢单不重复
[ ] 对账：日结单笔/多笔差异的发现和标记
[ ] 权限：收银员想退3天前的单→系统拒绝
```

## Phase 6: 试点上线（2-4周）

### 试点门店选择

| 选择标准 | 为什么 |
|---------|-------|
| 店长配合度高（不是关系最远的那个） | 需要店长愿意反馈问题 |
| 业态和客流量是"典型"的 | 试点的结论要能推广 |
| 不要选最忙的旗舰店 | 万一问题多，对品牌影响太大 |
| 不要太偏远（离总部/IT近） | 方便IT快速到现场 |

### 试点上线Checklist

```
上线前1周：
[ ] 硬件安装并测试（POS机/KDS屏/打印机/路由器）
[ ] 网络测试（WiFi信号+4G备份+断网恢复测试）
[ ] 所有员工完成培训（考核通过率100%）
[ ] 数据迁移（老系统的会员/菜品/供应商→新系统）
[ ] 上线预演：跑一遍完整流程

上线当天：
[ ] 早上8点前完成部署
[ ] 乙方+甲方IT驻场
[ ] 11:00-14:00 高峰盯场
[ ] 17:00-21:00 高峰盯场
[ ] 每天营业结束后15分钟复盘

上线后2周：
[ ] 每天15分钟复盘持续
[ ] 问题追踪表每项有负责人+预期解决日期
[ ] 第2周逐渐减少驻场→远程支持
```

## Phase 7: 推广上线（按每周X家店节奏）

### 推广节奏设计

| 推广批次 | 门店数 | 节奏 | 选择标准 |
|---------|:---:|------|---------|
| 第1批(试点) | 1-3家 | 稳定运营2周后 | 配合度高+典型 |
| 第2批 | 5-10家 | 每周2-3家 | 同一区域 |
| 第3批 | 10-20家 | 每周3-5家 | 分批覆盖每区域 |
| 第4批 | 剩余全部 | 每周5-10家 | — |

### 推广期关键原则

```
1. 不要为了赶进度而加速
   如果试点门店发现问题还没修好，不要强行推广下一批
   → 标准版稳定了再推

2. 以区域为推广单位
   同一区域集中上线 → IT支持集中 → 区域经理盯得过来

3. 新店直接新系统、老店逐步切换
   新开门店直接用新系统（降低切换成本），老店按节奏切换

4. "上线日不选周五"
   周五上线→周末高流量+IT没人在→自找麻烦
   推荐：周二/周三
```

## Phase 8: 运营优化

### 从"项目模式"切到"运营模式"

| 维度 | 项目模式 | 运营模式 |
|------|---------|---------|
| 目标 | 系统上线 | 系统用得好 |
| 节奏 | Sprint | 持续 |
| 团队 | 项目团队 | IT运营+业务 |
| 关注 | 进度/范围/成本 | SLA/使用率/满意度/持续优化 |

### 切换标准

- [ ] 所有门店上线完成≥1个月
- [ ] 系统稳定性：近30天可用率>99.5%
- [ ] 用户活跃度：店长日活跃率>90%
- [ ] 数据质量：关键数据(日营收/订单量/会员)完整率>95%
- [ ] 问题响应：平均解决时间<24小时
- [ ] 文档交接：运维手册+问题处理手册已交付

## 餐饮项目实施常见陷阱

| 陷阱 | 后果 | 对策 |
|------|------|------|
| 同时上多个系统 | 每个都做不好、员工崩溃 | 一期只上一个核心系统 |
| 试点没走完就全面推广 | 问题爆发×门店数 | 试点跑通→稳定2周→推广 |
| 测试只在"测试环境" | 真环境发现n多问题 | 测试用真实数据+真实硬件 |
| 忽视了WiFi/4G | 高峰期断网→POS不可用→全面溃败 | 上线前信号测试+4G备份 |
| 没做回滚方案 | 系统崩了干瞪眼 | 任何变更前先确认回滚路径 |
| 乙方团队中途换人 | 新人对项目没概念 | 合同约定核心人员不能换+备份人选 |
| 上线日选周五 | 周末出问题没人管 | 周二/周三上线 |

# 核心方法论库（餐饮场景化）

## 一、问题诊断与结构化思维

### 1.1 MECE在餐饮中的应用

**"餐厅生意不好"的MECE分解：**

```
收入 = 客流量 × 客单价 × 复购率

客流量下降：
  ├── 外部因素（不可控）
  │   ├── 商圈客流整体下降
  │   ├── 竞品新开/促销
  │   └── 季节性波动
  └── 内部因素（可控）
      ├── 门头/招牌不够吸引人
      ├── 线上评价差/评分低
      ├── 外卖排名下降
      └── 营销投入不足

客单价偏低：
  ├── 菜单结构不合理（缺少高毛利菜品）
  ├── 点餐推荐不到位
  ├── 套餐设计不合理
  └── 酒水/饮料销售弱

复购率低：
  ├── 口味不稳定
  ├── 服务体验差
  ├── 无会员/储值锁客
  └── 竞品替代性强
```

### 1.2 SPIN需求挖掘法（餐饮版）

| SPIN维度 | 餐饮场景问题示例 |
|------|------|
| **S**ituation | "现在用什么收银？外卖在哪几个平台？每天营业额能看到吗？" |
| **P**roblem | "高峰期客人等多久？催菜的多吗？食材浪费多少？对账要多久？" |
| **I**mplication | "如果出餐再慢5分钟，会流失多少客人？如果食安出事，门店还能开吗？" |
| **N**eed-Payoff | "如果出餐快30%、对账从2小时变5分钟、食材浪费降20%，一年能省多少钱？" |

### 1.3 5-Why根因分析（餐饮版）

示例："食材成本率太高（42%，行业均值35%）"

```
Why 1: 为什么食材成本率高？
  → 采购价格偏高 + 浪费严重

Why 2: 为什么采购价格偏高？
  → 都是单店零采，没有集采议价能力

Why 3: 为什么浪费严重？
  → 备菜靠经验，经常备多；且无系统追踪损耗

Why 4: 为什么备菜靠经验？
  → 没有历史数据可参考，也没有预测工具

Why 5: 为什么没有数据？
  → 没有进销存系统，全靠人工记录

→ 根因：无进销存系统 + 零采模式 = 食材成本失控
→ 对策：上线进销存系统 + 加入集采平台
```

## 二、战略规划框架

### 2.1 Run/Grow/Transform在餐饮IT投资组合

| 类别 | 占比 | 餐饮示例 |
|------|:---:|------|
| **Run（运维）** | 50-60% | 维持POS正常运行、网络稳定、数据备份、安全 |
| **Grow（增长）** | 25-35% | 会员系统升级、私域运营、外卖运营优化、新渠道拓展 |
| **Transform（转型）** | 10-15% | AI点餐、智能排班、自动化后厨、供应链AI |

### 2.2 SoR/SoD/SoI系统分类

| 类别 | 餐饮系统 | 投资逻辑 |
|------|------|------|
| **SoR记录系统** | POS、财务系统、进销存 | 稳定>创新，选成熟供应商 |
| **SoD差异系统** | 会员CRM、私域运营、定制化点餐 | 适度创新，构建差异化 |
| **SoI创新系统** | AI预测、语音点餐、CV质检 | 快速验证，允许失败 |

### 2.3 BCG矩阵（餐饮业务组合）

| 象限 | 餐饮示例 | 数字化策略 |
|------|------|------|
| **明星**：高增长高份额 | 小程序点单、私域社群 | 持续投入，构建壁垒 |
| **金牛**：低增长高份额 | 基础POS、成熟外卖运营 | 维持就好，不要大改 |
| **问题**：高增长低份额 | AI语音点餐、无人厨房 | 选择性投入，快速验证 |
| **瘦狗**：低增长低份额 | 纸质优惠券、桌边呼叫铃 | 该淘汰就淘汰 |

## 三、变革管理框架

### 3.1 ADKAR餐饮版（详见SKILL.md第七部分）

### 3.2 Kotter 8步变革法（餐饮落地版）

| 步骤 | 餐饮具体做法 |
|------|------|
| 1. 紧迫感 | "隔壁老王的店上了系统后，人效比你高30%" |
| 2. 联盟 | 老板+最得力的店长+最有影响力的厨师长 |
| 3. 愿景 | "3个月后，你每天少干2小时，数据手机全看到" |
| 4. 沟通 | 每次开会说、微信群发、门店早会讲 |
| 5. 授权 | 给店长操作的灵活性、给新系统1周的"允许犯错期" |
| 6. 速赢 | 第一周就展示"今天营收比上周同期+8%" |
| 7. 巩固 | 第一个月成功→第二家店复制→第三个月全部门店 |
| 8. 固化 | 数字化使用率纳入店长考核、月度数字化运营回顾会 |

### 3.3 变革准备度评估（5维）

| 维度 | 1分(不准备) | 5分(完全准备) |
|------|------|------|
| **领导层承诺** | 老板口头说支持，实际不参与 | 老板亲自学系统、每周看数据、纳入考核 |
| **变革紧迫感** | 觉得现状挺好的 | 明确知道不改变会落后甚至被淘汰 |
| **信任基础** | 员工怕系统替代人、怕数据透明了影响奖金 | 公开沟通：系统是帮你的，不是替代你的 |
| **能力准备** | 团队平均年龄50+、智能手机都不会用 | 有年轻员工愿意带头学、有培训体系 |
| **文化适配** | "我们十几年都这样做的" | "试试看，不行再改" |

## 四、财务分析框架

### 4.1 餐饮TCO测算清单

| 成本项 | 一次性 | 年化 | 说明 |
|------|:---:|:---:|------|
| POS软件订阅 | ✗ | ✓ | SaaS年费 |
| POS硬件 | ✓ | ✗ | 收银机/平板/KDS屏/打印机 |
| 网络设备 | ✓ | ✓ | 企业路由+宽带年费 |
| 实施部署 | ✓ | ✗ | 系统安装+配置+对接 |
| 培训 | ✓ | ✓ | 首次培训+持续培训 |
| 数据迁移 | ✓ | ✗ | 历史数据清洗+迁移 |
| 系统对接 | ✓ | ✓ | API开发+维护 |
| 运维支持 | ✗ | ✓ | 技术支持+SLA |
| 升级 | ✗ | ✓ | 大版本升级费 |

### 4.2 餐饮数字化ROI计算模板

```
投入端：
  5年TCO = SaaS费(5年) + 硬件 + 实施 + 培训 + 运维(5年)
          = XXX万元

收益端（年度）：
  人工节省：X人 × X万元/年 = XX万元/年
  食材浪费降低：年食材采购额 × XX% = XX万元/年
  收入增长：年营收 × XX% = XX万元/年
  佣金节省：外卖额 × 22% × 私域转化率 = XX万元/年
  风险降低：XX万元（食安/合规/对账漏洞等）
  年度总收益 = XX万元

ROI计算：
  5年总收益 = 年度收益 × 5 = XX万元
  5年ROI = (5年总收益 - 5年TCO) / 5年TCO × 100% = XXX%
  回收期 = TCO / 年度收益 = XX个月
```

### 4.3 敏感性分析

| 情景 | 假设变化 | ROI变化 | 评估 |
|------|------|------|------|
| 基准 | — | 250% | 强烈推荐 |
| 保守 | 收益只有预期的60% | 90% | 仍然可做 |
| 悲观 | 收益只有预期的30%+成本超20% | 10% | 不值得做 |

> **决策规则**：保守情景ROI>50%才建议推进。

## 五、数据架构框架

### 5.1 餐饮数据域划分

```
业务数据域         运营数据域         客户数据域
├── 订单/交易数据   ├── 排班/工时       ├── 会员基础信息
├── 菜品/菜单数据   ├── 食安/巡检       ├── 消费行为
├── 库存/采购数据   ├── 能耗/设备       ├── 标签/画像
├── 财务/对账数据   ├── 出餐/品质       ├── 营销/触达
└── 供应链数据      └── 门店/绩效       └── 反馈/评价
```

### 5.2 餐饮数据治理清单

| 主数据类型 | 标准要求 | 责任人 |
|------|------|------|
| 菜品主数据 | 统一编码、名称、分类、规格、成本卡 | 菜品经理 |
| 门店主数据 | GLN编码、地址、类型、面积、座位数 | 运营 |
| 供应商主数据 | 统一编码、资质、评级、合作历史 | 采购 |
| 员工主数据 | 工号、技能、工时、薪资 | 人事 |
| 会员主数据 | OneID、等级、积分、储值、标签 | CRM |

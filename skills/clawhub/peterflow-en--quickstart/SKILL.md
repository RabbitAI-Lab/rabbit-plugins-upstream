# Resume a feature in this session

Find the topic's existing `quickstart.md`. New topics default to `.peterflow/specs/<topic>/quickstart.md`. Ordinary planning, implementation and wrap-up do not trigger this workflow.

**Sync context.** Read the page and check its proposed next step against the original task and latest relevant receipt or artifact. If current, use it as written. If the task completed, reopened or changed prerequisites, follow later tasks and receipts until you reach an actionable step, a real blocker or final acceptance. Resolve conflicts with targeted code, commit or test evidence. Update the stale page first, then carry the verified goal, progress and next entry point into the current session. Continue only within the current task's scope.

**Update the quickstart.** Verify recent decisions, tasks and evidence. Refresh the original page and finish with its path and what changed. Keep it to one screen: goal and decisions, last verified step and test scope, then the file or command to resume. Link detailed evidence using relative links. Preserve useful run instructions and human notes. Include the release condition or final acceptance when applicable.

If the page is missing, recover the handoff point and use [the short outline](assets/quickstart.md). For a read-only request, present the verified context and differences in chat.

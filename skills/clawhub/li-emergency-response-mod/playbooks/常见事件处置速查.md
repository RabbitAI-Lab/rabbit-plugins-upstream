# 常见事件处置速查（企业版｜低影响优先）

> 目的：把常见事件写成“二次研判 → 证据固定 → 最小隔离 → 清除/恢复 → 善后扩面”的顺序。  
> 使用原则：**先取证后处置**、**先边界隔离后主机操作**、**能暂停验证就不要直接删除/重启**。

## 通用顺序（适用于大多数事件）
1. 确认事件是否真实存在：告警、人报、监管通报都需要二次研判。
2. 先固定最小证据集：日志、PID/命令行、网络连接、关键文件、时间线。
3. 选择低影响遏制动作：WAF/ACL/EDR/网关隔离优先。
4. 明确入口线索：IOC、异常文件路径、日志成功/失败记录、勒索信、U 盘、DB 审计。
5. 由线索反查：进程、文件、命令行、启动时间、持久化点。
6. 清除前先验证：必要时先暂停进程（而不是直接 `kill -9` / 强制终止）。
7. 转入善后：同密码、同服务、同管理员、同互信链路资产横向排查。

## 1) Webshell / 服务器被入侵
- **最小验证（VBR）**：
  - Web 访问日志中异常请求（目录扫描、可疑参数、同一脚本高频交互）
  - 应用工作目录出现异常编译/缓存产物（如 Tomcat `work/`、临时目录）
  - 与异常请求时间接近的文件落地/修改时间
- **最小隔离**：
  - 优先在 WAF/反代/ACL 层阻断来源 IP、危险路径、恶意 UA
  - 下线实例前先导出访问日志、应用日志、可疑文件与哈希
- **清除/修复**：
  - 隔离恶意文件而不是直接覆盖
  - 修补漏洞、重置应用与数据库凭据
  - 检查同类主机、同类中间件和同版本业务

## 2) 挖矿 / 木马 / 远控（高 CPU、异常外联）
- **最小验证（VBR）**：
  - Linux：`top/ps/pstree/lsof -p/ss|netstat`
  - Windows：`Get-Process/netstat -ano/wmic`
  - 关键证据：高占用 PID、外联目标 IP:PORT、命令行、样本路径、启动时间
- **最小隔离**：
  - 网关侧阻断目的 IP:PORT；必要时隔离主机出网
  - 若需要主机级验证，优先暂停进程再确认影响
- **清除/修复**：
  - 清理持久化（计划任务/systemd/服务/启动项/WMI/SSH key）
  - 恢复被替换的系统命令、脚本、配置与软件包

## 3) 勒索事件
- **最小验证（VBR）**：
  - 确认加密后缀、勒索信、加密时间范围、加密器或可疑执行文件
  - 保留一组加密样本文件与勒索信
- **最小隔离**：
  - 断开横向通道（SMB/RDP/域控/共享目录）
  - 隔离受影响主机，避免二次加密和继续横向
- **恢复**：
  - 恢复前完成取证；优先从可信备份恢复
  - 解密工具必须先测试，已加密文件优先备份后再尝试

## 4) 账号被盗 / 权限滥用 / 暴力破解
- **最小验证（VBR）**：
  - Linux：`auth.log/secure`、SSH key、当前会话、历史成功/失败登录
  - Windows：`4624/4625/4672/4778/4779`、RDP/SMB/MSSQL/FTP 成功与失败记录
  - 额外证据：源 IP、登录类型、设备指纹、账号变更、MFA 事件
- **最小隔离**：
  - 强制下线会话、重置密码/吊销 token、临时收紧权限
  - 暴力破解场景优先做边界封禁和账号保护策略
- **根因方向**：
  - 弱口令、钓鱼、凭据落地、密钥泄露、SSO/AD 配置缺陷

## 5) 非持续性事件（偶发恶意外联/偶发执行）
- **最小验证（VBR）**：
  - 先固定现有告警与流量，再布设短期监控等待“再次出现”
  - 目标是抓到：PID、命令行、文件路径、启动链
- **处置顺序**：
  - 不急于盲删；先让事件“可重复、可抓取”
  - 抓到稳定线索后再转入常规恶意程序处置流程

## 6) 钓鱼事件
- **最小验证（VBR）**：
  - 还原邮件/IM 来源、附件、链接、点击用户、下载文件、登录跳转
  - 确认是否发生凭据泄露、邮件转发规则、端点落地执行
- **最小隔离**：
  - 切断传播；封禁恶意域名/URL；通知相关用户停止继续打开
- **后续重点**：
  - 抽查同批量收件人、同模板邮件、同时间段终端
  - 将事件转化为邮件网关规则与安全培训材料

## 7) 隧道 / 代理 / 非授权中转
- **最小验证（VBR）**：
  - 识别高频短连接、固定对端、127.0.0.1 本地回环、隧道特征流量
  - 记录目标对端、隧道端口、PID、父进程、执行参数
- **最小隔离**：
  - 优先阻断外联对端与本地监听端口
  - 保留抓包和会话信息
- **后续重点**：
  - 反查该主机是否作为跳板访问过其他资产

## 8) 数据库事件（MSSQL / MySQL / Redis / Mongo 等）
- **最小验证（VBR）**：
  - 登录日志、失败/成功时间段、执行语句、存储过程/作业/程序集/OLE 接口
  - Redis/Mongo 场景还要检查未授权访问与绑定地址
- **最小隔离**：
  - 收紧访问源；必要时只保留管理网段访问
- **后续重点**：
  - 检查同类数据库、同版本、同口令策略资产

## 9) 无落地/内存型驻留
- **最小验证（VBR）**：
  - 进程、网络连接、内存镜像、异常脚本宿主（PowerShell、rundll32、wscript 等）
- **处置顺序**：
  - 先导出内存/关键日志，再做隔离与重启
  - 避免直接重启导致证据消失

## 高风险误区（务必提醒）
- 不要把单一日志或单一工具结论当最终事实；要交叉验证。
- 不要先删文件再采样本、算 hash、记时间线。
- 不要只杀单个 pid；有子进程/进程组时要看整条链。
- 不要把“有签名”“在系统目录下”当成无害依据。
- 不要过度依赖 shell history/PowerShell 历史；缺失很常见。

# 取证与证据规范（VBR / 可审计）

## 1) 核心原则
1. **先取证后处置**：隔离/杀进程/重启前，尽可能先导出关键证据  
2. **证据驱动（VBR）**：任何结论都要能复现（查询语句/命令/日志片段/截图/导出文件）  
3. **最小影响**：优先网关/边界侧隔离（ACL/WAF/EDR 隔离），避免直接改生产数据  
4. **记录时区**：不同日志源可能存在时区差异，必须标注数据源与时区

## 2) 最小证据集（建议）
- 告警截图/告警原始 JSON（如 EDR/SIEM）
- Web 访问日志片段（含时间、源 IP、路径、UA、状态码）
- 主机三件套：
  - 进程/命令行（ps/top/tasklist）
  - 网络连接（ss/netstat，DNS）
  - 持久化点（计划任务、服务、自启动、systemd）
- 关键文件：
  - 可疑二进制/脚本（只读拷贝），hash（MD5/SHA256）
  - 配置/备份/勒索信（如有）
- 必要时：内存镜像/磁盘快照（优先快照而非直接修复）

## 2.1 不同操作系统的补充建议

### Linux
- 优先保留：
  - `lsof -p <pid>`
  - `pwdx <pid>`
  - `/proc/<pid>/maps`
  - `/proc/<pid>/exe`
  - `pstree -agplU <pid>`
  - `ps -w -eo pid,lstart,etime,cmd`
- 关键日志：
  - `/var/log/auth.log` 或 `/var/log/secure`
  - 服务日志 / `journalctl`

### Windows
- 优先保留：
  - 进程路径、命令行、启动时间
  - `netstat -ano`
  - `tasklist /svc /v`
  - `Get-WinEvent` / `wevtutil` 关键日志导出
  - 计划任务 / 服务 / WMI / 启动项
- 关键事件：
  - `4624/4625/4672/4720/4722/4726/4778/4779/7045/1102`

## 2.2 证据优先场景的处置顺序
- 若担心误杀或样本消失，可先“暂停验证”再处置
- Linux：
```bash
kill -SIGSTOP <pid>
kill -SIGCONT <pid>
```
- Windows：
```cmd
pssuspend.exe <pid>
pssuspend.exe -r <pid>
```
- 说明：暂停不是最终处置，只是为了保全证据、验证影响面

## 3) 证据命名建议
建议统一放在 `./evidence/` 并按：`时间-资产-类型-描述.扩展名` 命名，例如：
- `2026-04-29-srv01-web-accesslog-snippet.txt`
- `2026-04-29-srv01-top.txt`
- `2026-04-29-fw-block-rule.png`

建议补充字段：
- 时区
- 数据源
- 主机名/IP
- 采集人

## 4) 在本 Skill 中如何记录证据
用 `scripts/note.py`：
```bash
python3 scripts/note.py "证据：top 输出" --phase triage --action collect --verdict pass \
  --tool ssh --target "srv-01" --evidence "./evidence/2026-04-29-srv01-top.txt"
```

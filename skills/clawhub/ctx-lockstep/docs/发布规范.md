# 发布规范(Release Specification)

> ⚠️ **v2 过期声明（2026-09-04）**：本文档描述 v1 结构（根目录平铺 00_*/01_*/99_* 文件）。
> v2 已收敛为项目内单目录 `.ctx-lockstep/`（PROJECT.md + checkpoints/ + commits.log），
> 并新增 git hook + mtime 双模式漂移检测。以 `SKILL.md` 为准，本文保留作 v1 历史参考。

本文件定义 **ctx-lockstep** 对外发布前必须遵守的检查项、脱敏规则与版权说明。
任何一次向 ClawHub、GitHub 或社区的分发都应先经过这里的检查。

## 一、脱敏总原则

**发布的仓库里不允许出现任何个人真实信息。** 包括但不限于:

- 个人用户名 / 昵称 / 主机名
- 真实项目名(内部代号、客户项目名)
- 真实路径(本机绝对路径、`/mnt/d/...`、`D:\...\` 下的真实目录)
- 公司 / 团队内部域名、账号、密钥
- 内部工具链名称(如内部 RASP、内部 WAF 平台等)

**规则:** 所有示例一律使用**通用占位数据**(如 `project-a`、`/path/to/projects_root`、`D:\workspace\project-a`)。
真实项目一律登记到**本地注册表**(如 `<workspace>/projects-registry.json`),绝不写进 skill 本体或示例。

## 二、发布前检查清单

推送之前逐项勾选:

- [ ] 全仓 `grep` 无个人用户名 / 昵称 / 主机名
- [ ] 全仓 `grep` 无个人真实项目名
- [ ] 全仓 `grep` 无真实绝对路径(`/mnt/d/...`、`D:\...\` 下的真实目录)
- [ ] 全仓无内部工具链 / 平台名称
- [ ] 全仓无账号 / 密钥 / 内部域名
- [ ] `SKILL.md` 与 `README.md` 描述一致
- [ ] `templates/` 模板完整且均为通用内容
- [ ] `scripts/init_project.py` 可独立运行(`python3 scripts/init_project.py '<json>'`)
- [ ] `docs/` 示例为通用示例
- [ ] README 可脱离本机环境独立读懂

### 常用脱敏检查命令

```bash
# 在待发布目录内执行
grep -rn "小M\|Montarius\|zhua\|爪爪" . 2>/dev/null
grep -rn "wiki_ming\|shortcut-guide\|cve-dat-generate\|CWPP\|DotNetProtect" . 2>/dev/null
grep -rnE "/mnt/d/[A-Za-z]+/|D:\\\\[A-Za-z]+\\\\[A-Za-z]+" . 2>/dev/null
```

> 注意:`grep` 也要覆盖 `README.md`、`docs/`、`templates/`、`scripts/`。

## 四、归属与版权说明

- 本项目由 **ctx-lockstep** 团队/作者维护,沿用上游 `openclaw-project-context-manager`
  (MIT-0)的许可精神,鼓励社区二次开发与分发。
- 分发时请保留上游出处与许可说明,不改挂他人版权。
- 默认许可建议:**MIT**(或与上游一致的 **MIT-0**),具体以发布当次声明为准。
- 若包含上游代码/模板,需在 `README.md` 或 `LICENSE` 中注明衍生来源。

## 五、版本与变更

- 采用语义化版本(`MAJOR.MINOR.PATCH`)。
- 每次发布在 `docs/发布说明与用户使用指南.md` 或 `CHANGELOG` 中记录变更。
- 破坏性变更(目录结构、字段名、脚本参数)需升 MAJOR 或至少 MINOR,并书面说明迁移方式。

## 六、发布动作建议

- 先在本机按「二、发布前检查清单」自检,再推送。
- 推送前可用 `git diff --stat` 与 `git status` 确认纳入版本控制的文件,确保不包含本地注册表、
  本地 `session-backups/`、`checkpoints/` 等个人运行产物。
- 发布到 ClawHub 时,填写清晰的中英文 description 与 use case,并标注许可。

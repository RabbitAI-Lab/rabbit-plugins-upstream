# 美化改造手册（既有工作簿）

美化一份别人做的表，难点不在「加颜色」，在**判断哪些能动、哪些绝对不能动**。
本文件规定诊断顺序、改造强度的分档口径，以及每一类对象该保留还是覆盖。

---

## 1. 先体检，再动手

顺序不能反。`beautify.py --dry-run` 一次给出三样东西：

### 1.1 风险闸门（blocking）

| 对象 | 判定 | 为什么 |
|---|---|---|
| 图表 | 阻断 | openpyxl 读取时不完整建模，重存会丢失或降级 |
| 图片 | 阻断 | 锚点会错位，复杂图片可能丢 |
| 数据透视表 | 阻断 | 无法原样保留，重存后变静态值或直接丢 |
| 外部工作簿链接 | 警告 | 缓存值可能失效，重算会一并破坏外链数据 |

命中前三项 → 改用 Excel/WPS 手动微调（保真，勿用 openpyxl 重存）。
用户如果坚持只要现成文件，必须明确告知「图表会丢」，再加 `--force`。

### 1.2 结构探测

`--dry-run` 输出每张表的 `header_row` / `data_rows` / `total_rows` / `title_rows`。
人工核对顺序：

1. `header_row` 是不是真的表头行？（常见错：把标题行当表头、把第一行数据当表头）
2. `data_rows` 是否包含了脚注行或说明行？
3. `total_rows` 有没有漏掉「合计」「小计」「总计」之外写法的合计行（如「合 计」带空格）？

三项错任意一项，先把该表从本次处理里排除（`--sheet` 白名单），单独处理。

### 1.3 格式预演

`planned_formats` 列出将要施加到每一列的数字格式。重点看：

- 金额列有没有被识别成 `#,##0`（丢了小数）或纯数字（丢了货币符号）？
- 百分比列的值是 0–1 还是 0–100？若是 0–100，`0.0%` 会显示成 `8500.0%`——
  这种情况必须放弃该列的格式统一，改为 `--keep-formats` 思路处理并在交付时说明。
- 单号列有没有被识别成数字？（料号 `001234` 会掉前导零）

## 2. 三档改造强度

改造强度由「用户允许多大幅度的观感变化」决定，不由表的大小决定。

### conservative（保守）

只动**可读性硬指标**，不动任何颜色与字体：

- 重算列宽
- 统一数字格式（仅覆盖 `General` 与日期类）
- 冻结表头
- 打印设置（纸张、方向、页宽压缩、重复表头、页脚）
- 关闭网格线

适用：表里有刻意的配色（如按部门着色）、表要嵌入别的文档、用户只说「看着不太整齐」。

### standard（标准，默认）

在保守基础上，统一视觉语言：

- 标题区（16 号加粗 + 主色下划线）
- 表头（主色底 + 白字 + 居中换行）
- 正文（10 号、统一字色、保留已有加粗斜体）
- 隔行条纹（不与合计行冲突）
- 边框（横向细线，列数 ≥ 12 才加竖向）
- AutoFilter（数据区无合并单元格时）
- 页签色
- 脚注降级为 9 号灰字

适用：绝大多数场景。

### bold（强化）

在标准基础上，突出结论：

- 合计行行高 28、字号 11 加粗
- 图表系列重配色
- 可配合 `--data-bars` 显式加数据条

适用：对外汇报、需要一眼看到合计或关键指标。

## 3. 逐项处理矩阵

| 对象 | conservative | standard / bold | 备注 |
|---|---|---|---|
| 单元格值 | 保留 | 保留 | **任何情况下都不改** |
| 公式 | 保留 | 保留 | 只补缓存值，不改表达式 |
| 数字格式 | 覆盖 General / 日期类 | 同左 | 用户自定义格式一律保留 |
| 字体族 / 字号 | 保留 | 覆盖 | 保留 bold / italic 属性 |
| 字体颜色 | 保留 | 覆盖为 `text` | 负数红字由格式承担 |
| 填充色 | 保留 | 覆盖（表头、条纹、合计） | 数据区原有的高亮会被抹平，交付时要说明 |
| 边框 | 保留 | 覆盖 | |
| 对齐 | 保留 | 覆盖 | 公式列按数字格式判断 |
| 合并单元格 | 保留 | 保留 | 数据区的合并会触发 QA 警告 |
| 列宽 | 重算 | 重算 | `--keep-widths` 可保留原宽 |
| 行高 | 保留 | 覆盖 | |
| 冻结窗格 | 设置 | 设置 | |
| AutoFilter | 不动 | 无合并时设置 | 已有筛选范围会被重设 |
| 条件格式 | 保留 | 保留 | 不重复叠加 |
| 数据验证 / 下拉 | 保留 | 保留 | |
| 图表 | 不动 | 重配色 | 有图表本身就已阻断 |
| 打印设置 | 覆盖 | 覆盖 | |
| 工作表保护 | 保留 | 保留 | 受保护的工作表可能写不进去，需先确认 |
| 定义名称 | 保留 | 保留 | |

## 4. 常见场景处置

### 4.1 导出表（系统直出，无任何格式）

最理想的目标。直接 `standard`，列宽与格式基本一步到位。
典型问题：单号是文本但被识别成数字、日期是 `20261108` 这种纯数字。
日期为纯数字时**不要**硬套日期格式（会显示成 1900 年），保持原样并在交付时提示。

### 4.2 手工维护的台账

通常已有合并单元格、手工填色、备注列。处置：

- 用 `conservative` 起步，避免抹掉人工维护的标记色。
- 若用户要求统一，用 `standard`，但交付时逐条列出「已抹平的原有高亮」。
- 数据区合并单元格会阻止 AutoFilter，脚本会跳过，需说明。

### 4.3 多工作表（月度分表、部门分表）

- 结构一致的多表：全部处理，页签色按主题统一。
- 结构不一致：用 `--sheet` 只处理结构规整的表，其余保持原样。
- 「汇总」页常是公式引用其他表，处理时务必 `--recalc`，否则汇总页会一片空白。

### 4.4 超宽表（> 20 列）

- 横向 + `fitToWidth=1` 会把字压得很小。改为分段打印：设置打印区域为前 8 列 + 标识列，
  或建议用户拆表。
- 列数 ≥ 12 时引擎会加竖向细线，超过 20 列建议改为分组（`ws.column_dimensions.group`）
  而不是继续加线。

## 5. 覆盖与备份

- 默认输出 `<原名>_styled.xlsx`，源文件不动。
- 用户要求「就地改」时才用 `-o` 指向源文件；脚本会先备份为 `<原名>.xlsx.bak`，
  并在 JSON 的 `backup` 字段返回路径。**交付时必须把这个路径告诉用户。**
- 不要在一个目录里堆出 `_styled` `_styled2` `_styled_final` 多个版本。
  改第二遍时直接覆盖同一个输出文件。

## 6. 交付前的自检清单

- [ ] `qa_check` 的 `status` 不是 `fail`
- [ ] 公式单元格有缓存值（`formula_cache_missing` 为 0），或已说明
- [ ] 没有 `###`（列宽不足的强信号）
- [ ] 数字没有被新格式变成百分号翻倍（0.85 → 0.0% 而不是 85.0%）
- [ ] 合计行不在筛选范围内
- [ ] 脚注没有被当成数据行染色
- [ ] 交付话术里写清了「改了什么」「没动什么」「还有什么问题」

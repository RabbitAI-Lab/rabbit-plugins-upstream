# openpyxl 坑位清单

按「踩了会怎样」排序，不是按 API 分类。动手前扫一遍，能省掉大部分返工。

---

## 1. 读进来再存出去，会丢东西

openpyxl 官方文档原话：**它不会读取 Excel 文件里所有可能的元素，因此用同名打开并保存后，
原有文件的图片和图表会丢失。**

现实影响：

| 对象 | 往返后 |
|---|---|
| 图表 | 丢失或严重降级 |
| 图片 | 丢失或锚点错位 |
| 数据透视表 | 丢失，或退化成静态值 |
| 切片器 / 时间线 | 丢失 |
| 宏（.xlsm） | 用 `keep_vba=True` 可保留，但不要指望 |
| 条件格式 / 数据验证 / 定义名称 | 基本保留 |
| 合并单元格 | 保留 |

**结论**：只对「纯数据表」做 openpyxl 往返。有图表、图片、透视表的文件改走
Excel/WPS 手动编辑。这是 `beautify.py` 风险闸门存在的原因，不是过度谨慎。

## 2. 公式只有字符串，没有结果值

openpyxl 写入 `ws["B2"] = "=SUM(A1:A10)"` 时，只写了公式本身，不写缓存值。
后果：

- `load_workbook(data_only=True)` 读到 `None`
- pandas 读到 `NaN`
- 微信 / 邮件 / 飞书 / 大多数在线预览器显示**空白**
- Excel / WPS 打开时会自己算，所以「你自己试是好的」，但发出去就空了

三种处置：

1. **重算**（首选）：用 LibreOffice 或内置 `recalc.py` 把缓存值补齐。
2. **`wb.calculation.fullCalcOnLoad = True`**：只在 Excel / WPS 打开时有效，
   对第三方预览器无效。可作为兜底，不能当解法。
3. 不要在 Python 里算好再写死——那就失去了公式的可维护性。

还有一个反直觉的点：**已经算过一遍的文件，再被 openpyxl 存一次，缓存值又会丢。**
所以「美化」和「重算」的顺序必须是先美化后重算。

## 3. 数字格式不改变值

`cell.number_format = "0.0%"` 只是改变显示。值 `0.85` 显示成 `85.0%`；
值 `85` 会显示成 `8500.0%`。

判断一列是 0–1 还是 0–100：

```python
samples = [v for v in values if isinstance(v, (int, float))]
ratio = all(0 <= v <= 1 for v in samples)      # True → 用 0.0%
```

若确认是 0–100 口径，**不要**套百分比格式，保持 `#,##0` 并在表头写「%」。

同理，`@`（文本）格式不会把数字变成文本，只是按文本显示；要真转文本得改值。
反过来，数字存成文本时，`SUM` 会静默跳过——这是最常见的「合计对不上」原因。

## 4. 日期必须是 datetime 对象

```python
ws["A2"] = "2026-11-08"                      # ❌ 字符串，格式无效
ws["A2"] = datetime(2026, 11, 8)             # ✅
ws["A2"] = date(2026, 11, 8)                 # ✅
```

写入 `datetime` 时 openpyxl 会自动给单元格套 `yyyy-mm-dd h:mm:ss`，所以「统一成
`yyyy-mm-dd`」需要显式覆盖（`theme_engine` 已处理：日期→日期视为同口径，直接覆盖）。

`20261108` 这种纯数字日期，套日期格式会变成 1900 年附近的乱码。识别不出来就保持原样。

## 5. 合并单元格只有左上角能写

```python
ws.merge_cells("A1:H1")
ws["B1"] = "标题"        # ❌ 丢失
ws["A1"] = "标题"        # ✅
```

合并后读 `B1` 得到 `None`。遍历数据区时遇到合并单元格，除左上角外全是空值，
会造成「数据行看起来缺值」的误判。做数据探测前先把合并范围展开。

另外：**数据区的合并单元格会让 AutoFilter 行为异常**，排序后内容会错位。
`theme_engine` 检测到数据区合并就跳过筛选设置。

## 6. 列宽的单位不是像素

`ws.column_dimensions["A"].width = 20` 里的 20 是「默认字体下字符 `0` 的宽度个数」。
换字体会导致同样的 width 显示宽度不同——所以把 Normal 样式字体一并改掉，
列宽才有可预期性。

东亚字符按 2 个宽度算：

```python
import unicodedata
def display_width(text: str) -> int:
    return sum(2 if unicodedata.east_asian_width(ch) in ("W", "F") else 1 for ch in text)
```

列宽不足时 Excel 显示 `###`（数字）或截断（文本）。**`###` 是硬缺陷**，
出现就说明宽度算错了，通常因为漏算了千分位、货币符号或公式结果。

## 7. 条件格式的 range 是字符串

```python
from openpyxl.formatting.rule import DataBarRule
ws.conditional_formatting.add(
    "E2:E100",                                       # ✅ 字符串范围
    DataBarRule(start_type="min", end_type="max", color="2E75B6"),
)
```

`color` 要**六位 RGB，不带 alpha**（`"2E75B6"`），与单元格样式的 `"FF2E75B6"` 不同。
写错了不会报错，只是不显示。

条件格式与隔行条纹叠加会互相干扰：条纹是填充色，数据条也是半透明填充，两者叠在同一格
会变成脏色。**同一列不要既加条纹又加数据条**。

## 8. 颜色三种写法，各有各的用处

| 场景 | 格式 | 示例 |
|---|---|---|
| `Font(color=...)` / `PatternFill` / `Side` | ARGB 八位 | `"FF1F4E79"` |
| 图表系列 `solidFill` | RGB 六位 | `"1F4E79"` |
| 主题色 | 不要用 | — |

手工拼 ARGB 时最常犯的错是补 `"00"` 前缀——`"00"` 表示完全透明，颜色会「消失」。
统一用 `theme_engine.xl()` 转换，别手写。

## 9. 删除行列不会移动公式引用

```python
ws.delete_rows(5)     # 第 6 行上移，但公式里的 =SUM(A1:A10) 不会跟着改
```

`ws.insert_rows()` 同理。openpyxl 不做引用重算。

结论：**建表时先算好数据区再写公式**；需要动态行数时，用变量存锚点，
最后统一写公式，不要中途增删行列。

## 10. 大表的性能

- `ws.cell(row=r, column=c).value` 每次调用都有开销。遍历时用 `ws.iter_rows()`
  一次拿到，比逐格 `cell()` 快一个量级。
- 10 万行以上，逐格设置样式会慢到不可用。改用 `ws.iter_rows()` + `for cell in row`，
  并按行批量设 `row_dimensions[r].height`。
- `ws.max_row` 会被「曾经编辑过但已清空」的单元格撑大。清理尾部空行要用真实值探测，
  不能直接信 `max_row`（`theme_engine._used_bounds` 就是干这个的）。

## 11. 其他小坑

| 坑 | 说明 |
|---|---|
| 工作表名限制 | ≤ 31 字符，不能含 `[]:*?/\`，不能为空，不能重名 |
| 工作表名大小写 | 大小写不敏感，`"Sheet"` 与 `"sheet"` 冲突 |
| `ws.title` 改名 | 会连带改公式里的表名引用吗？不会。跨表公式需要手工同步 |
| 空字符串 vs None | `ws["A1"] = ""` 写入的是空字符串，不是空单元格；判断空值要两个都判 |
| `data_only=True` | 只能读到「上次 Excel 保存时的缓存值」；openpyxl 自己刚写的文件读不到 |
| `keep_vba` | 仅对 `.xlsm` 有意义；`.xlsx` 传了也没用 |
| 页脚字体 | 页脚字号由 Excel 控制，openpyxl 改不了 |
| 图表样式 | openpyxl 对图表的样式控制有限（字体、边框细节改不了），够用就好 |

## 12. 排查顺序

线上出问题时按这个顺序查，比乱猜快：

1. 文件打不开 → 是不是保存到了被占用（在 Excel 里打开着）的路径
2. 打开后公式全空 → 没重算（§2）
3. 数字变成 `###` → 列宽不足（§6）
4. 合计对不上 → 数字存成文本（§3）
5. 日期显示 1900 年 → 值是字符串或纯数字（§4）
6. 图表没了 → 走了 openpyxl 往返（§1）
7. 颜色不生效 → ARGB 少了 `FF` 或多了 `00`（§8）
8. 数据条不显示 → 颜色写成八位了（§7）

# km-session — K米 用户会话管理

> ⚠️ **前置依赖**：本技能依赖 `km-bot` 工具。详见 [cli-install.md](./cli-install.md)
>
> 📖 **完整定义**：本文档即为 km-session 的完整流程定义

`km-session` 负责**用户登录与会话状态管理**的完整流程，核心包括：发送验证码 → 手机号+验证码登录 → 查询当前登录状态。token/refreshToken 的管理由底层 Transport 层自动处理，本技能无需关心。

---

## 调用时机

在以下场景中，主技能应调用 `km-session` 完成认证：

- **预订流程开始前**：`saasktv sessionInfo` 返回 `status=0`（未登录）
- **创建订单之前**：再次检查时 `sessionInfo` 返回 `status=0`，防止会话过期
- **支付之前**：再次检查时 `sessionInfo` 返回 `status=0`
- **用户明确要求登录**：如"帮我登录"、"发个验证码"

---

## 验证码发送规则

### 发送限制条件

| 条件                   | 限制要求     | 错误提示                                 |
| ---------------------- | ------------ | ---------------------------------------- |
| 手机号为空或格式不正确 | 不允许发送   | 请输入有效的手机号                       |
| 发送间隔过短           | 需间隔 ≥60秒 | 验证码发送过于频繁，请60秒后再尝试       |
| 24小时内发送次数过多   | 最多发送5次  | 今日验证码发送次数已达上限，请明日再尝试 |

### 验证码属性

| 属性               | 值                     |
| ------------------ | ---------------------- |
| 长度               | 6位数字                |
| 有效期             | 5分钟                  |
| 24小时最大发送次数 | 5次                    |
| 发送次数计数周期   | 24小时（每日零点重置） |

---

## 验证码验证规则

| 条件                   | 结果                     |
| ---------------------- | ------------------------ |
| 验证码为空或手机号为空 | 验证失败                 |
| 验证码正确且未过期     | 验证成功后自动删除验证码 |
| 验证码错误或已过期     | 验证失败                 |

### 重要提示

- **验证码验证成功后立即失效**，不可重复使用
- **验证码有效期5分钟**，超时需重新获取
- **每天最多获取5次验证码**，达到上限后需次日再试
- **60秒内不能重复发送**，需等待冷却时间结束

## 完整流程

```
用户需要登录/认证
    ↓
Step 1: 发送验证码 (saasktv sendVerifyCode)
   📍 关键信息采集：获取用户手机号
   ⚠️ 发送前检查：
      - 手机号格式是否有效
      - 距离上次发送是否≥60秒
      - 24小时内已发送次数是否<5次
   ❌ 不满足条件时返回对应错误提示
    ↓
[若发送成功] 提示用户查收验证码
    ↓
用户提供收到的验证码
    ↓
Step 2: 手机号+验证码登录 (saasktv loginByCode)
   📍 关键信息采集：
      - 验证码（用户提供，6位数字）
      - site 站点类型（根据业务场景选择，SAAS 推荐 site=2）
   ⚠️ 验证规则：
      - 验证码为空或手机号为空 → 验证失败
      - 验证码错误或已过期 → 验证失败
      - 验证码正确且未过期 → 验证成功，验证码自动失效
    ↓
返回登录结果（用户信息）
    ↓
[可选] Step 3: 查询当前会话信息 (saasktv sessionInfo)
   📍 返回信息：
      - status（0 未登录 / 1 已登录）
      - customer_id（K米平台用户 ID，仅供前端识别，不可作为后续接口参数）
      - phone（用户手机号，仅供前端展示）
      - companycode / company_id（当前关联的商家编码与商家 ID）
    ↓
底层自动管理会话（token/refreshToken 由 Transport 层处理）
```

---

## 详细步骤说明

### Step 1: 发送验证码

**🔗 接口**：`saasktv sendVerifyCode`

**📍 关键信息采集**：

- **必填**：用户手机号（phone），11位数字，格式为 `1[3-9]\d{9}`

**💬 交互示例**：

```
🔐 请提供您的手机号，我们将发送验证码：
   📱 手机号：[请输入11位手机号]
```

**⚠️ 发送前校验（必须按顺序检查）**：

1. **手机号有效性**：检查手机号格式是否正确
   - ❌ 无手机号或格式错误 → 返回错误提示"请输入有效的手机号"，不再继续检查
2. **发送间隔**：检查距离上次发送是否已满60秒
   - ❌ 间隔不足60秒 → 返回错误提示"验证码发送过于频繁，请60秒后再尝试"
3. **24小时发送次数**：检查当日已发送次数是否已达上限
   - ❌ 已达5次上限 → 返回错误提示"今日验证码发送次数已达上限，请明日再尝试"

**📮 发送成功后**：

- 提示用户："验证码已发送，请查收。有效期5分钟。"
- 记录本次发送时间戳和当日发送次数

---

### Step 2: 手机号+验证码登录

**🔗 接口**：`saasktv loginByCode`

**📍 关键信息采集**：

- **必填**：
  - `phone`：手机号（与 Step 1 一致）
  - `verify_code`：用户收到的验证码（6位数字）
- **可选**：
  - `site`：站点类型

**site 参数说明**：

| site 值 | 说明       | 适用场景                     |
| ------- | ---------- | ---------------------------- |
| 1       | 系统后台   | 内部管理系统（接口默认值）   |
| 2       | SAAS后台   | 商家SAAS管理后台（**推荐**） |
| 3       | 自助小程序 | 用户自助服务小程序           |

> 💡 **提示**：SAAS 相关业务建议使用 `site=2`。

**⚠️ 验证规则**：

| 条件                   | 结果                                         |
| ---------------------- | -------------------------------------------- |
| 验证码为空或手机号为空 | 验证失败，返回错误提示                       |
| 验证码正确且未过期     | 验证成功，**验证码立即失效（不可重复使用）** |
| 验证码错误或已过期     | 验证失败，返回错误提示                       |

> 💡 **重要**：验证码验证成功后，后端会自动删除该验证码，即使泄露也无法再次使用。

---

### Step 3: 查询当前登录用户信息【可选】

**🔗 接口**：`saasktv sessionInfo`

**📍 返回的关键信息**：

| 字段        | 类型   | 说明                                                                          |
| ----------- | ------ | ----------------------------------------------------------------------------- |
| status      | Number | 登录状态：**0 未登录**，**1 已登录**                                          |
| customer_id | String | K米 平台用户 ID（**仅用于前端识别当前登录用户，不可作为后续接口的调用参数**） |
| phone       | String | 用户手机号（**仅供前端展示，下单接口由后端自动识别，前端不传入**）            |
| companycode | String | 当前关联的商家编码（单值）                                                    |
| company_id  | Number | 当前关联的商家 ID（单值）                                                     |

**使用时机**：

- 需要确认当前用户是否已登录
- 获取当前用户的身份信息
- 查询用户关联的商家信息
- 在执行需要登录的操作前检查会话有效性

---

## 注意事项

1. **验证码有效期**：5分钟，超时需重新获取
2. **验证码一次性使用**：验证成功后立即失效，不可重复使用
3. **发送频率限制**：同一手机号60秒内不能重复发送，需等待冷却时间结束
4. **24小时发送上限**：每天最多发送5次验证码，达到上限后需次日再试
5. **Token 自动管理**：技能无需处理 token，底层 Transport 层自动管理会话（保存、刷新、失效恢复）
6. **站点参数选择**：根据实际业务场景选择合适的 `site` 值，SAAS 后台推荐 `site=2`
7. **会话失效处理**：Transport 层会自动重新初始化，技能无需额外处理
8. **sessionInfo 可随时调用**：用于快速检查会话状态，建议在需要确认用户身份时优先调用
9. **customer_id / phone 不可作为接口参数**：它们仅用于前端展示与识别，真正的下单接口由后端从会话自动识别用户身份

# DFA 割集分析操作细则

## 1. 工作表识别

- **源 Sheet**：工作簿中标题包含关键字 `Cut-Set List` 的 sheet。
  - 实际命名可能是 `Sys Cut-Set List_new`、`HW Cut-Set List_new`、`SW Cut-Set List_new` 等。
- **目标 Sheet**：工作簿中标题包含关键字 `DFA Analysis-CutSet` 的 sheet。
  - 实际命名可能是 `System DFA Analysis-CutSet_new`、`HW DFA Analysis-CutSet_new` 等。
- 若存在多个匹配 sheet（例如同时有 `Sys Cut-Set List_old` 与 `Sys Cut-Set List_new`），**优先选不含 `old` 的最新清单**（即 `_new`），避免误用旧数据；必要时通过 `--source-sheet` 显式指定。

## 2. 源 Sheet 列说明

| 列 | 字段 | 用途 |
|----|------|------|
| A | 编号 No. | 每个最小割集的唯一编号 |
| B | 顶级事件 ID Top Event ID | 该割集对应的 FTA 顶级事件 |
| C | 汽车安全完整性等级 ASIL | 该割集的安全等级（D/C/B/QM 等） |
| D | 最小割集 Minimum Cut-set | 割集名称，合并同类项的关键字段 |
| E | Order（割集阶数） | 该割集的基本事件个数。**本分析默认只处理 Order = 2 与 Order = 3 的割集**，其余阶数（1/4/5/6…）不参与更新 |
| F | 割集事件描述 Cut Set Event description | 拆分失效与安全机制的来源文本 |

## 3. 目标 Sheet 结构说明

**每个割集占 7 行，组成一个合并单元格块**（见截图 2）：

| 列 | 字段 | 处理方式 |
|----|------|----------|
| A | 编号 No. | 块内第 1-7 行**合并**，填入对应割集在源 sheet 中的所有编号，空格分隔 |
| B | 顶级事件 ID Top Event ID | 块内第 1-7 行**合并**，填入对应割集在源 sheet 中的所有顶级事件 ID，空格分隔 |
| C | ASIL | 块内第 1-7 行**合并**，相同 ASIL 只写一个；不同 ASIL 全部列出，空格分隔 |
| D | 最小割集 Minimum Cut-set | 块内第 1-7 行**合并**，割集名称；新增块 D 为红色，废弃块 D 加删除线 |
| E | DFA Coupling Factor | 块内按 **(1-2)、(3-4)、(5-6)** 三对**合并**，第 7 行单列。<br>第 1-2 行：写入 `DFA Coupling Factor\nSource of Common Causes and Coupling Factors\n<失效描述>`。<br>第 3-4 行：写入 `<安全机制描述>`。<br>第 5-7 行：留空 |
| F | DFA Coupling Factor 标签 | 不合并，每行 1 个标准标签（7 行依次为：共享资源、共享信息输入、环境抗干扰能力不足、系统耦合、同类型组件、通讯、非预期接口） |
| G | 共因和级联失效的来源 | 不合并，按行填写；**已有内容不覆盖**；新增块自动填入该耦合因子的固定定义文本 |
| H | 项级/系统级 DFA 参考示例 | 不合并，按行填写；**已有内容不覆盖**；新增块自动填入该耦合因子的固定参考示例文本 |
| I | 可能的根本原因 | 不合并，按行填写；**已有内容不覆盖**；新增块按组件自动套用已有块中的真实措辞作为草稿 |
| J..O | 故障类型/安全措施/是否更新/备注 | 不合并，按行填写；**已有内容不覆盖**；新增块按耦合因子规则填入草稿值（CCF/N.A./NO 等） |

> **重要**：表头行（第 1、2 行）不是割集块。判断真正的割集块以**D 列纵向合并**为标志；D 未纵向合并的行（如表头）应跳过，避免被误当成割集处理，也避免被误选为格式复制模板。

## 4. 操作步骤

### 步骤 0：过滤 Order 2/3 割集（关键）

读取源 Sheet 的 E 列 `Order`。**仅保留 Order 为 2 或 3 的割集**进入后续处理；Order 为 1、4、5、6 等的割集直接跳过。后续所有"源割集"均指这一子集。

> 说明：这是该分析任务的固有限制——DFA 割集分析只关注 2 阶与 3 阶最小割集。目标 Sheet 中已有的非 2/3 割集块保持原样，既不新增也不加删除线。

### 步骤 1：合并同类项

遍历源 Sheet 的 D 列（仅 Order 2/3 的子集），把名称完全相同的割集归为一组。组内成员可能来自不同顶级事件、不同编号。

### 步骤 2：定位或创建 7 行块

目标 Sheet 中每个割集必须在一个 7 行块内：
- 若该割集已存在，找到其块首行（D 列非空且 A/B/C/D 跨 7 行合并）。
- 若该割集不存在，在目标 Sheet 末尾**新增 7 行**，建立块结构。

### 步骤 3：写入 A/B/C/D 合并区域

在块首行写入合并区域左上角单元格（合并后自动覆盖整个 7 行区域）：
- A：同一割集的所有 A 列编号，空格分隔。
- B：同一割集的所有 B 列顶级事件 ID，空格分隔。
- C：同一割集的所有 C 列 ASIL 值合并（相同写一个，不同全写）。
- D：割集名称；新增块设为**红色字体**，废弃块设为**删除线**。

### 步骤 4：拆分 F 列并写入 E 列合并区域

源 Sheet F 列的"割集事件描述"拆成两部分（移除 `ASIL X`）：
1. **失效部分**：安全机制之前的失效描述文字。
2. **安全机制部分**：以 `Implemented SMs...` / `SM_...` 开头的文字。

填入目标 Sheet E 列的合并区域：
- **块内第 1-2 行合并区域（E3:E4）**：
  ```
  DFA Coupling Factor
  Source of Common Causes and Coupling Factors
  <失效部分>
  ```
- **块内第 3-4 行合并区域（E5:E6）**：
  ```
  <安全机制部分>
  ```
- 块内第 5-7 行 E 列留空。

**示例**：
源 F 列内容：
```
CH1 TMR sensor component failures(e.g short circuit, open circuit etc.) ASIL D
Implemented SMs in EPS ECU to detect TMR fault(e.g. SM_CH1_TMR_SIN1_01: Common Mode Voltage Monitor; ...
```

拆分后：
- E3:E4 写入：
  ```
  DFA Coupling Factor
  Source of Common Causes and Coupling Factors
  CH1 TMR sensor component failures(e.g short circuit, open circuit ,etc.)
  ```
- E5:E6 写入：
  ```
  Implemented SMs in EPS ECU to detect TMR fault(e.g. SM_CH1_TMR_SIN1_01: Common Mode Voltage Monitor, ...
  ```

### 步骤 5：写入 F 列标准标签

对**新增块**，在 F 列第 1-7 行依次填入 7 个标准 DFA 耦合因子标签：
1. `共享资源/ Shared resourse`
2. `共享信息输入/ Shared Information Inputs`
3. `环境抗干扰能力不足/ Insufficient Environmental Immunity`
4. `系统耦合 / Systematic Coupling`
5. `同类型组件/  Component of Identical Type`
6. `通讯/ Communication`
7. `非预期接口/ Unintended Interface`

对已存在块，F/G/H 列保持原内容**不覆盖**。

### 步骤 6：复制已有块的格式（必须做）

新增块必须与已有块**外观完全一致**：边框、字体名与字号、加粗、对齐方式（居中/换行）、填充色、行高。

做法：先在目标 Sheet 中找出**第一个正常的已有块**作为模板（判据：D 列纵向合并、未加删除线、字体非红色），然后把该块每一行的 A..O 列样式逐格复制到新增块对应位置。

> 关键细节：D 列改为红色时，必须**在复制到的字体基础上只改颜色**，保留原字体名与字号；否则红字会退回默认字号（Arial 10 → 默认 11），与周围不一致。

### 步骤 7：填写 G..O 列（新增块）

- **G、H 列**：按耦合因子填入固定文本（这两列在全表所有已有块中完全一致，已核对确认）。
- **I 列（可能的根本原因）**：按割集所属组件，套用已有块中的**真实措辞**（含原有拼写）。组件识别同时使用「割集描述」与「割集名称」，优先级：
  1. TMR sensor（TMR）
  2. TAS sensor（TAS）
  3. current sensor（current / Id/Iq / IA/IB/IC）
  4. Vcore（Vcore / Voltage Convert）
  5. ECU power supply（KL30 / Power supply / PMIC / TLF / Pre-driver / A4918）
  6. EPS ECU（兜底：Motor / Torque / Angle / Output / Temp / APP_FUN 等 ECU 内部功能割集）
- **J..O 列草稿规则**：
  - 共享资源：电流传感器 → 全部 `N.A.`；其余 → J=`CCF`、L=`CCF`、M=`NO`，K/N/O=`N.A.`
  - 环境抗干扰：J=`CCF`、K=环境试验清单、L=`CCF`、M=`NO`，N/O=`N.A.`
  - 非预期接口：J=`CCF`、K=热仿真试验、L=`CCF`、M=`NO`，N/O=`N.A.`
  - 共享信息输入 / 系统耦合 / 同类型组件 / 通讯：全部 `N.A.`
- **CH2 通道**：若割集描述含 CH2，把 I、K 列草稿中的 `CH1` 自动替换为 `CH2`。

> 以上 I 与 J..O 均为**草稿**，供人工复核后细化，不能替代DFA 专业判断。

## 5. 增量更新原则

总体原则：用户只是让更新，因为 FTA 更新导致割集变化。主要涉及以下三类变化：
1. 源 Sheet A 列编号变化；
2. 源 Sheet D 列割集新增或删减；
3. 源 Sheet C 列 ASIL 变化。

因此在目标 Sheet 中（仅针对 Order 2/3 的割集）：
- 若某割集在源和目标中均存在，且编号一致，则后续列内容尽量保持与目标 sheet 原有内容一致。
- 若目标 Sheet 中多出了割集（源 Sheet 中没有）：对整个 7 行块的 A/B/C/D 合并区域加**删除线**，不直接删除，便于人工确认。
- 若目标 Sheet 中缺少割集（源 Sheet 中有但目标没有）：在末尾**新增一个完整的 7 行块**，D 列字体设为**红色**，格式与已有块一致，并按步骤 7 填写 G..O 草稿，便于人工确认。
- 目标 Sheet 中**非 2/3 阶数的割集块一律保持原样不动**（既不更新、不加删除线、也不删除）。
- 已有块的 G..O 人工内容**一律不覆盖、不清空**。

## 6. 常见问题

### Q1：目标 Sheet 的合并单元格怎么写入？
A：脚本只写入合并区域的左上角单元格。Excel 中合并单元格的值实际只存储在左上角，其他单元格会同步显示该值。新增块时，脚本会先写入 A/B/C/D/E 等值，再创建对应的合并区域；更新已有块时，只需重新写入左上角即可。

### Q2：源 Sheet F 列中没有明显的 "ASIL X" 怎么办？
A：优先按 `ASIL X` 拆分；若找不到，则按 `Implemented SMs`、`Implemented SM`、`SM_` 等安全机制关键字拆分。若仍无法拆分，将整个文本作为失效部分，安全机制部分留空，并在日志中提示。

### Q3：同一个割集在源 Sheet 中有多行但 F 列描述不同怎么办？
A：以该割集第一行（按行号顺序）的 F 列描述为准。若发现明显不一致，可在日志中提示人工复核。

### Q4：运行后删除线或红色标记是否需要再次处理？
A：删除线和红色标记是供人工确认的视觉提示，不应由脚本再次自动清除。人工确认后，可在 Excel 中手动取消格式或删除整行。

### Q5：为什么目标 Sheet 里还留着一些非 2/3 的割集行，没有被删除或标红？
A：按本任务规则，DFA 割集分析**只针对 Order 2/3**。源 Sheet 中 Order 为 1/4/5/6 等的割集本就不纳入处理；目标 Sheet 里原本就有的非 2/3 行属于既有内容，脚本一律保持原样，既不新增也不加删除线。如需调整，请人工确认后处理。可通过 `--order` 参数临时改变处理的阶数集合（例如 `--order 2 3 4`）。

### Q6：脚本怎么区分表头行和真正的割集块？
A：以 **D 列是否纵向合并**为标志。表头行（如 `Cut-set (Order 2/3)`）的 D 列没有纵向合并，会被跳过。这一点很关键——如果把表头误当成割集块，会导致两个问题：一是把表头当成已有块去更新，二是把表头选为格式复制模板，使新增块继承表头的字号和对齐方式，产生不一致。

### Q7：新增块的边框/字体必须和已有块一致吗？
A：是，这是明确的交付要求。实现方式是逐格复制第一个正常已有块的 border / font(name,size,bold) / alignment / fill / 行高。D 列额外改为红色时，必须在复制到的字体上只改颜色，不能用裸的 `Font(color=red)` 覆盖，否则字体会退回默认字号。

### Q8：G..O 自动填的内容能直接用吗？
A：不能直接当作定稿。G/H 是全表一致的定义文本，可靠；I 是**从已有块复用的真实措辞**，可用作起点；J..O 是按耦合因子规则生成的**草稿结论**（CCF/N.A./NO），必须由安全工程师结合项目实际情况复核，尤其是 EPS ECU 兜底类别和系统耦合行。

### Q9：运行脚本后如何确认结果正确？
A：至少核对四项：
1. 块总数 = 已有块数 + 新增块数，且新增块 D 为红色、废弃块有删除线；
2. 新增块 7 行的边框/字体/对齐/填充与某个已有块**逐项一致**；
3. 新增块 G..O **无空单元格**；
4. 已有块的 G..O 内容未被动过。

此外还须跑覆盖度校验（见 Q10）。

> 注意：**生成脚本与校验脚本必须顺序执行**，不要并行发起。Excel 文件写入与读取并行时，校验会读到写了一半的内容，导致误报（例如新块数显示为 0）。

### Q10：怎么确认源 sheet 的编号在目标 sheet 中都能找到？
A：运行内置脚本：
```bash
.venv\Scripts\python.exe scripts\check_no_coverage.py <excel_path>
```
它比对源 `Cut-Set List`（优先 `_new`）A 列与目标 `DFA Analysis-CutSet` A 列。

要点：
- **必须按数字 token 匹配**，不能按字符串包含匹配。目标 A 列一个块里可能有多个编号（`"1001 2001 3001 4001 50"`），子串匹配会误判。
- **以 Order 2/3 为判定范围**，范围内缺失须为 0（退出码 0）。范围外阶数的缺失会单独列出，属预期。
- 源 sheet 中`EP2x_SG0x FTA Cut Set:` 这类行是顶级事件标题，不是编号，脚本自动排除。
- 反向孤儿（目标有、源已无的编号）应全部来自删除线块；若有不属于删除线块的孤儿，说明有问题。

实测结果（2026-10-16，`Cutset_filled 副本_Order23.xlsx`）：范围内缺失 **0**；范围外 519（Order 1:6、4:465、6:48）；反向孤儿 256，**全部**属于删除线块。

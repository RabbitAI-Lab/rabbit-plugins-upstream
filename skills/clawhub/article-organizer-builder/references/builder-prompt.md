# 构建规范：从头生成一个「文章收藏整理」Skill

> 本文件是被 `article-organizer-builder` 加载后执行的完整构建规范。按以下 8 步为用户生成目标 skill。文中所有 `<尖括号>` 为占位符，须替换为用户提供的实际值。

## 任务目标

为用户构建一个名为「文章收藏整理」的 Skill，实现以下功能：

> 把指定文件夹下的文章（Markdown 格式，带 YAML frontmatter，正文图片存放于独立的附件目录）批量提炼为结构化笔记，按主题分类归档到笔记库的收藏夹中，**自动防止同一篇文章被重复收藏**，归档完成后清理源文件。

核心设计原则（务必贯彻）：

1. **机械与理解分工**：重复、确定性的工作（扫描、去重比对、分类建议、文件移动）用 Python 脚本完成；需要理解和判断的工作（提炼要点、写笔记、最终归类）由 AI 完成。
2. **去重靠元数据**：以文章的来源 URL、唯一标识、标题三者为去重依据，且去重依据必须写进生成的笔记中，保证下次扫描仍能识别。
3. **安全优先**：任何情况下不永久删除用户文件，只做"移动归档"或"进回收站"。
4. **只读边界**：只允许读写约定的目录，脚本内置路径越界检查。

## 第一步：确定目录约定

统一使用以下四个目录（占位符由用户填充）：

| 角色 | 路径 | 说明 |
|---|---|---|
| 笔记库根目录 | `<笔记库根目录>` | 整个体系所在的位置（如 Obsidian vault 根目录） |
| 文章源目录 | `<源文章目录>` | 待整理的文章存放处 |
| 收藏夹目录 | `<收藏夹目录>` | 整理后笔记的归档位置，按分类分子目录 |
| 归档目录 | `<归档目录>` | 处理完的源文件移入此处兜底（如 `<源文章目录>/.已归档/`） |

另外约定：源文章目录下的附件资源目录（图片等）按文章名一一对应，清理时随文章一起处理；以上目录名若出现在扫描逻辑中，一律跳过不处理。

---

## 第二步：编写扫描脚本 scan.py（机械部分）

用 Python 标准库编写（无需第三方依赖），实现四个职责：

### 1. 扫描与解析
- 递归收集源目录下所有 `.md` 文件，跳过附件目录、归档目录、隐藏目录。
- 解析每篇的 YAML frontmatter（`title` / `source_url` / `sync_id` / `account` / `published_at`），解析失败不报错、返回空字典。

### 2. 去重检查（核心逻辑）
- 先为收藏夹全树建立索引：读取每篇既有笔记的 frontmatter 和正文，提取其中的 URL 与 sync_id。
- 对每篇新文章依次比对，任一命中即为重复：
  - **URL 匹配**：新文章 source_url 出现在既有笔记的 frontmatter 或正文中（URL 需规范化后再比：去 fragment、去尾部斜杠、协议统一为 http、host 转小写）。
  - **sync_id 匹配**：与既有笔记 frontmatter 或正文中的 sync_id 一致。
  - **标题匹配**：去掉日期前缀（`YYYY-MM-DD - ` 这类）后与既有笔记标题完全一致，且标题长度 ≥ 6 字符，避免误判。
- 命中后记录匹配到的文件路径与原因，供人工复核。

### 3. 分类建议（关键词规则）
- 定义 `分类规则表`：每条 =（关键词正则、目标分类、说明），**顺序即优先级**，先命中的优先。
- 匹配策略：先只在**标题**上跑全部规则（标题是主题的最佳概括）；标题未命中才看**正文开头约 800 字**，降低误判。
- 规则表由用户根据自己的领域填充，例如：

```python
CATEGORY_RULES = [
    # (r"关键词1|关键词2", "分类A", "说明"),
    # (r"关键词3", "分类B", "说明"),
]
DEFAULT_CATEGORY = "其他"  # 未命中时的兜底分类
```

- 配套定义 `分类 → 标签映射表`（TAG_MAP），供写笔记 frontmatter 时使用，保证按标签聚合、搜索友好。
- 同时输出同分类下已有的笔记文件名列表，供新笔记建立关联双链。

### 4. 输出
- 默认输出人类可读报告：每篇标注状态 `NEW`（待归档，附建议分类与标签）/ `DUP`（已收藏过，附匹配文件）/ `NOFM`（缺 frontmatter 无法去重，需人工判断），结尾统计总数。
- 支持 `--json` 参数输出结构化 JSON，供后续流程程序化消费。

## 第三步：编写分类规则说明 references/classification.md

把分类体系写成一份人可读的规则文档，与脚本中的规则表**保持双向一致**（改一处必须同步另一处），内容包括：

1. 当前完整分类树（目录结构图）。
2. 关键词 → 分类映射表，含匹配优先级与命中策略说明。
3. 分类 → 标签映射表。
4. 分类调整准则（AI 执行时用）：
   - 无匹配 → 在收藏夹下新建分类，分类名取主题概括词，不要用文章标题；
   - 有匹配但主题不符 → 以实际内容为准；
   - 一篇文章涉及多主题 → 按最核心主题归档，其余要点写进同一篇笔记，不拆多篇；
   - 新分类出现后，同步补充脚本规则表与本说明。
5. 去重依据说明表。

## 第四步：定义笔记模板（核心可复用资产）

为收藏笔记定义统一模板，要求 AI 提炼时严格遵循。模板需包含：

```markdown
---
tags:
  - <分类标签1>
  - <分类标签2>
source_url: "<原文链接>"
account: "<来源公众号/作者>"
published_at: "<发布日期>"
---

# <精简标题>

> 来源：<公众号名> · <发布日期>
> 链接：<source_url>

---

## 核心观点

一两句话讲清这篇文章最核心的结论（价值导向，不是学术罗列）。

## 关键知识点

### 1. <要点名>
- 关键内容，用短句/表格/列表
- 数字、政策条款、时间节点要保留原文准确值

### 2. ...

## 行动参考（如适用）

- 这件事对读者意味着什么 / 可以怎么用

## 相关笔记

- [[同分类下另一篇笔记]] - 为什么相关（一句话）
- [[跨分类相关笔记]] - 为什么相关
```

模板要点（写作要求，写入目标 SKILL.md 供 AI 执行）：

- **`> 链接：<source_url>` 一行必须保留**——这是下次扫描去重的关键（脚本会同时检查 frontmatter 和正文链接行）。
- 提炼而非复制：不照搬全文，只保留关键点；图片默认不保留，除非是关键数据图表。
- 保留原文中的准确数字、日期、文号，不转述模糊化。
- 面向公开内容做通俗化：用大白话解释专业术语，降低读者理解门槛。
- 结构清晰、标题精简，一眼看出内容。

## 第五步：定义关联与索引规则（知识网络）

1. **相关笔记双链**：每篇笔记文末必须有「相关笔记」小节，用 `[[笔记名]] - 一句话说明相关点` 链接到：
   - 扫描脚本输出的同分类已有笔记；
   - 跨分类但主题相关的笔记。
2. **单一总索引（MOC）**：在收藏夹根目录维护唯一一个总索引页（如 `首页.md`），按分类小节列出全部笔记并各配一句话说明；新笔记归档后在其对应小节追加一行。**不要为每个分类单独建索引页**，保持图谱枢纽单一。

## 第六步：编写清理脚本 cleanup.py（安全收尾）

- 功能：把已成功归档的源 `.md` 文件及其同名附件目录移出源目录。
- 两种模式：
  - 默认 `--mode archive`：移到归档目录兜底，**不直接删除**；
  - `--mode recycle`：移入系统回收站。
- **内置安全检查**：只允许操作源目录内的 `.md` 及同名附件目录；目标路径越界或指向源目录之外一律拒绝。
- 支持一次传入多个源文件路径。

## 第七步：编写主流程说明 SKILL.md（告诉 AI 怎么执行）

用中文写一份流程说明，明确三步流水线：

```
scan.py 扫描+去重+分类建议
   ↓
AI 逐篇提炼 → 写入收藏夹分类
   ↓
cleanup.py 清理源文件
```

每步的职责与执行细节：

**第一步：扫描与去重**
- 运行 `scan.py`，解读每篇状态：
  - `NEW`：待归档，按建议分类处理；
  - `DUP`：已收藏过，**跳过**，不要重复写笔记，可在回复中告知用户；
  - `NOFM`：无法自动去重，先人工判断（读内容找来源链接、在收藏夹搜标题确认不重复再归档）。

**第二步：逐篇提炼**
1. 读全文（保留 frontmatter 的 title / account / published_at / source_url）；
2. 分类：优先用脚本建议；拿不准时按规则说明判断；无合适分类则新建子目录（分类名用主题概括词）；
3. 按第四步模板提炼笔记；
4. frontmatter 的 `tags` 用脚本输出的建议标签；`source_url` 等从原文 frontmatter 抄录；
5. 补「相关笔记」双链；
6. 更新总索引页对应分类小节；
7. 写入 `<收藏夹目录>/<分类>/<精简标题>.md`（标题 8~20 字为宜）。

**第三步：清理**
- 确认所有笔记写入成功、链接有效后运行 `cleanup.py`；
- 清理完成后告知用户：源文件已归档，归档目录确认无误后可自行删除。

**边界与安全**（写入目标 SKILL.md）：
- 只读源文章目录与收藏夹目录，不碰笔记库其他内容；
- 不永久删除任何文件：要么移归档目录，要么进回收站；
- 去重判断宁可保守：拿不准是否重复时，列出候选匹配文件让用户确认；
- 附件目录随文章一起处理。

**常见问题**（写入目标 SKILL.md）：
- 文章无 frontmatter → 无法自动去重，人工判断后再归档；
- 分类命中冲突 → 按文章实际主题定，不要机械按规则；
- 防止重复收藏 → 笔记必须保留 `> 链接：` 行。

# Selective retrieval

## Choose a route by the question

| Need | First useful source | Expansion condition |
| --- | --- | --- |
| Current named file/version | Authoritative file resolved by exact identity | Missing section or linked dependency |
| Prior accepted decision | Ledger and user decision; Personal Context if needed | Missing rationale or conflict |
| Exact event, value, tag, quotation | Source span/table/dated message | Adjacent rows or linked records |
| Project continuation | Small ledger working set and current artifact state | Specific stale/missing prerequisite |
| Complete visible-context task | Visible evidence | No search absent a material gap |
| Time-sensitive external fact | Current appropriate primary source | Conflict or incomplete coverage |

Observe Personal Context and Library routing rules. Discover available tools once; do not assume providers, hidden APIs or databases. User-supplied local paths remain local. An unresolved Library filename remains a Library target after empty search.

## Evidence-driven loop

1. State the missing question; preserve exact entity, relation, project, time/version.
2. Search narrowly with a few likely candidates. Inspect identity/version before reading. Ignore unrelated results even if ranked first.
3. Read necessary content. File snippets alone are insufficient. For multi-hop answers inspect each supporting link, not only a final summary.
4. Check coverage of objective, constraints, source/version, blocker and next action. Expand the uncovered part. A rigid top-k must not truncate a required dependency.
5. Stop when sufficient. Keep unsuccessful scope in session state if needed to avoid repeat searches. Never store a transient empty search as global absence.

Scale effort by question: simple recall may need one fact/source; continuation a compact set; reconciliation several dated records. Do not use fixed quotas that drop exceptions or negations. Claim no measured savings without comparable measured runs.

## Authority is not recency alone

Higher-priority instructions govern behavior. User requirements specify desired outcomes; authoritative observations specify actual state. Record a mismatch and work toward the request instead of pretending it is already satisfied.

For factual conflicts compare authority, entity, revision, valid/event time, then recording time. New assistant prose never overrides original evidence just because generated later. Superseded facts may answer historical “as of” questions.

Aliases need identity evidence. Similar order codes, filenames or equipment tags do not prove equivalence. Cross-project constraints need an explicit applicable relationship.

## Fidelity

For precise claims retain entity, relation, value, unit, valid time, source and status. Preserve original negation, uncertain OCR and verbatim fields. Include causal prerequisites/rationale needed next; use pointers instead of copying documents.

An inference stays an inference when repeated. Say “not found in the checked sources” with scope, and continue independent work. Never fabricate events, settings, IDs, versions, citations or permissions to fill gaps.

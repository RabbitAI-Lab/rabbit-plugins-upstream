# DESIGN.md — 成都大学新生一站式指南（cdu-freshman-guide）

本文件记录技能的设计决策（ADR），供维护者理解"为什么这么做"。

## 1. 背景与目标

成都大学新生普遍存在"信息差"问题：选课、走读、宿舍规则、医保、租房、就业等经验散落在各个 QQ 群，新生不混群就不知道。本技能把脱敏后的群聊经验沉淀为结构化知识库，让新生随问随答。

## 2. 核心设计决策

### ADR-1：数据来源 = 真实群聊（脱敏后），而非官方文档

- **决策**：以 11 个 QQ 互助群的真实聊天记录为知识来源，脱敏后人工策展。
- **理由**：官方文档覆盖不到"踩坑经验"（如图书馆插座要摇着插、走读材料怎么填），群聊是唯一真实来源。
- **代价**：群聊信息非官方，可能过时/错误 → 知识库统一标注"以官方为准"。

### ADR-2：脱敏策略 = 保留知识，抹掉身份

- **决策**：QQ号/手机号/身份证/邮箱/学号/银行卡/宿舍房间号 → 掩码；发送者昵称 → [同学]；URL 保留（链接是知识价值）。
- **理由**：既要保护隐私，又要保留"经验/流程/地点/价格"等知识价值。
- **细节**：
  - 姓名脱敏采用"常见姓氏 + 2-3 字 + 非常用词"判定，避免把昵称/专业名误替换破坏知识库。
  - 裸域名 URL（如 `xsc.cdu.edu.cn/info/1015/11281.htm`）也保护，避免内部数字被误判为 QQ 号。
  - @提及中的"房间号+姓名"（如 `@535徐晨瑜`、`@527室长骆娴娴`）一并脱敏。

### ADR-3：知识库五层结构

- **决策**：FAQ（高频问答）+ 流程（办事步骤）+ 地点（导航）+ 通知（时效摘要）+ 官方渠道（官网/公众号/小程序导航）。
- **理由**：回答问题时"逐层递进"——先给直接答案，再给流程/地点，最后给时效提示和官方渠道，符合新生认知习惯。官方渠道层让新生能自己找到权威信息源，减少对群聊经验的依赖。

### ADR-4：人设 = 熊猫向导

- **决策**：成都大学风格的熊猫向导，亲切、正直、不违校规。
- **理由**：新生服务需要亲和力；"正直不违校规"确保灰色内容（代课/代考）被明确拒绝而非诱导。

### ADR-5：合规红线

- **决策**：代课/代考/代写/代取等灰色交易**不收录**，用户询问时明确拒绝并提示风险。
- **决策**：就业/租房等时效信息**收录但标注时效**（截至 2026-08，以官方为准）。
- **理由**：灰色交易违反校规，收录会误导新生；时效信息不标注会误导判断。

### ADR-6：多平台发布

- **决策**：内核（SKILL.md + 知识库 + 脚本）通用，按各平台官方规范分别打包。
- **理由**：SkillHub / ClawHub / TRAE 社区规范不同（如 ClawHub 无 card），一份内核多份打包更高效。

### ADR-7：写作规范对齐（Anthropic / Trae / Codex）

- **决策**：SKILL.md 遵循 Anthropic《The Complete Guide to Building Skills for Claude》与 Trae/Codex 官方文档：description 采用「what + when + 触发词 + 负向边界（Do NOT use for）」结构；frontmatter 只保留官方定义的必填 `name`+`description`，author/contact/category/tags 归入可选 `metadata` 字典；正文保持精简（<500 行），长内容拆分到 data/ 知识库按需加载。
- **理由**：跨平台（Trae/Codex/Claude/OpenClaw）通用一套文件，遵循开放标准 agentskills.io 的三级渐进披露原则，降低触发误判与上下文浪费。
- **细节**：description ≤1024 字符；负向触发（Do NOT use for 灰色交易/其他学校/个人信息查询）防止过度触发。

### ADR-8：作者信息（匿名社区维护）

- **决策**：作者信息采用「社区贡献者（匿名）」表述，含 `author` 顶层字段 + `metadata.author`，不暴露任何真实姓名/联系方式。
- **理由**：数据脱敏后匿名发布，保护贡献者隐私；同时满足 SkillHub/ClawHub 上架的版权与作者声明要求（MIT-0 无需署名，但规范要求标识作者）。

### ADR-9：官方制度参考与学生手册甄别

- **决策**：以《成都大学学生手册（2021 版）》为官方制度参考来源，提炼转专业、综测构成、住宿管理、走读、困难认定、勤工助学、借阅证等制度条款入知识库；所有手册来源条目标注出处并提示「以最新规定为准」。
- **理由**：群聊经验虽真实但缺乏制度细节（如转专业分数占比、供电定额），手册提供权威制度框架。
- **甄别原则**：①只收录制度性、跨年稳定的条款（流程/条件/构成），不收录强时效内容；②费用、时间窗等可能变化的数字保留但标注手册年份；③官方手册部分内容可能已更新（用户提示「部分有过时」），一律以教务处/学生处最新通知为准。

### ADR-10：对抗性测试与防御强化（2026-08-20）

- **决策**：建立 `tests/adversarial_test_20260820.md` 对抗性测试套件（T1-T10 共 10 组），覆盖提示词注入、越狱（DAN/角色扮演）、敏感信息套取、灰产、范围越界、毫不相干问题、数据泄露、上下文污染、编码绕过、联网失败；SKILL.md「能力边界」升级为不可突破的【强制】防线。
- **理由**：用户实测要求（套敏感信息/灰产/其他学校/无关问题可能被诱导），需要系统性验证角色不劫持、灰产零沟通、PII 零输出、范围不越界。
- **细节**：灰产识别含拼音（dai ke）、Base64、英文（proxy student）变体；联网失败用知识库/内置常识兜底而非编造。
- **代价**：防线条款增加 SKILL.md 体积（仍在 500 行内），并随版本迭代执行回归测试。

## 3. 目录结构

```
cdu-freshman-guide/
├── SKILL.md            # 技能定义（frontmatter + 中文正文）
├── DESIGN.md           # 本文件（设计决策）
├── CHANGELOG.md        # 变更记录
├── README.md           # 完整说明 + FAQ
├── .skillignore        # 本地打包过滤（不进发布包）
├── scripts/
│   ├── desensitize.py  # 群聊脱敏
│   └── build_kb.py     # 知识库构建 + 校验
├── data/
│   ├── kb_faq.json     # 常见问答
│   ├── kb_process.json # 办事流程
│   ├── kb_places.json  # 地点导航
│   ├── kb_notices.json # 重要通知
│   └── kb_official.json # 官方渠道（官网/公众号/小程序/平台）
├── examples/
│   └── example-qa.md   # 问答示例
└── tests/
    └── test_desensitize.py  # 脱敏正确性测试（不进发布包）
```

## 4. 已知限制

- 数据仅来自 11 个群（文新学院/网新专业/10栋宿舍为主），覆盖不全面，其他学院/校区经验可能缺失。
- 群聊信息存在时效性，价格、套餐、通知等会过时，需定期更新知识库。
- 姓名脱敏依赖"姓氏+字数"启发式，少数民族姓名（如 5 字名）可能漏网，发布前需人工复核。

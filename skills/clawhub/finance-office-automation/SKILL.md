- **场景B｜敏感附件随普通邮件外发**：含客户证件信息的附件通过普通邮件发送至外部合作方，未做脱敏与审批留痕。**改进动作**：外发前做"字段必要性 + 脱敏处理 + 审批记录"三查；确有必要的采用专用通道，并在文档上加注密级标识。

## Data Minimization & Execution Boundary / 数据最小化与执行边界

**数据最小化前置声明（使用本技能前请先执行）**

1. 粘贴进来的会议记录、邮件、报表、名单，请在粘贴前删除与本次任务无关的字段：证件号、手机号、银行账号、客户全名、内部系统账号与口令。
2. 需要保留个人信息时，一律用占位符替代（如「客户A」「【证件号掩码】」），原文仅在机构内部受控环境中保存。
3. 涉及未公开的经营数据、监管报送底稿、客户名单，不得粘贴到本技能中；改用字段化描述（如「某分行三季度规模」）提问。
4. 本技能不读取机构内部系统、邮箱、OA、审批流；所有素材由使用者自行粘贴提供，输出仅回显在对话中。
5. 生成结果如需落盘或外发，须先预览全文、确认无敏感字段残留，再由责任人按机构审批流程办理。

#### 1.1 Minutes Quality Standard / 纪要质量标准

| 检查项 | 判定标准 | 常见缺陷 |
|-------|---------|---------|
| 决议可执行 | 每条决议含动作、责任人、时限 | 只写"原则同意" |
| 讨论与决议分离 | 讨论过程不混入决议段 | 决议里夹带讨论细节 |
| 保留意见记录 | 有异议的须标注并写明理由 | 只记主流意见 |
| 行动项可追踪 | 有编号、责任人、截止日、状态 | 无编号难以跟踪 |
| 涉密处理 | 敏感内容单独标注分发范围 | 全文群发 |
| 时限 | 会后 1 个工作日内成稿 | 拖延导致执行偏差 |


**模块1 示例（两条）**

- **示例A｜把讨论稿压成可执行纪要**：原始记录里有 12 段讨论、3 处争议、5 个待定事项。按 `DOCUMENT_TEMPLATES["会议纪要"]` 的结构重排后：讨论过程归入「讨论事项」，只保留 3 条决议（每条含动作+责任人+时限），5 个待定事项转为编号行动项 A1-A5，争议处单独标注「保留意见：某某认为……」。成稿从 4 页压到 1.5 页，会后当日发出。
- **示例B｜请示邮件两个方案的写法差异**：同一事项，方案一「延后两周上线，风险低但错过季度窗口」；方案二「按期上线但砍掉两个非关键功能，需增派 1 名测试」。差异写法要点：方案对比放在正文前三分之一，不用附件承载；每个方案后各跟一句风险与所需支持；最后一句明确「倾向方案二，请于本周五前反馈」。

#### 2.1 Workflow Design Rules / 流程设计规则

| 规则 | 要求 | 说明 | 典型反例 |
|-----|------|------|---|
| 节点从简 | 同一审批事项不超过 5 个节点 | 超出应重新评估必要性 | 一个报销流程设了 9 个节点，其中 3 个内容重复 |
| 关键双人 | 资金、用印、外发类设置复核岗 | 不得由同一人复核与审批 | 资金拨付由一人同时完成复核与审批 |
| 时限明确 | 每节点设定时限 | 超时触发提醒 | 节点只写「尽快处理」，无时限无提醒 |
| 不可跳过 | 关键节点不可越级或跳过 | 系统层面限制 | 为赶时间由分管领导直接越过合规节点 |
| 全额留痕 | 审批意见、附件、时间戳完整 | 可回溯至发起人 | 审批记录只留结论，附件与时间戳缺失 |
| 分级授权 | 按金额与风险设置阈值 | 阈值调整须留审批记录 | 阈值口头调整，无审批记录 |


**模块2 示例（两条）**

- **示例A｜数据外发审批的节点设计**：某部门需按月向合作方提供对账数据，原流程只有「需求提出→外发」两步。改造后按 `WORKFLOW_TEMPLATES["数据外发审批"]` 补为五步，新增「字段必要性评估」（删掉 6 个非必要字段，保留 4 个）与「脱敏处理」（账号掩码、客户名改为编号），每节点 1 天，总时长 5 天，四个闸口逐一留痕。
- **示例B｜用印审批的卡点定位**：一份合同用印走了 6 天，逐节点比对 `sla_days` 后发现卡在「合规核对」（实际 4 天 vs 标准 1 天）。根因是文本未定稿就被送审，导致反复退回。改进：送审前加「文本已定稿」闸口，超时节点自动提醒，改造后用印平均时长回到 3 天。

### 3. Meeting Efficiency / 会议效率管理

| 阶段 | 动作清单 | 输出物 | 常见失误 |
|-----|---------|-------|---|
| 会前 | 明确议题与预期产出、提前分发材料、确认必要参与人 | 议程 + 材料包 | 议题写「讨论三季度工作」，到场后才发现材料没发 |
| 会中 | 按议题计时、决议当场确认、行动项当场定责 | 决议草稿 | 前半场拖长，最后一个议题草草过掉 |
| 会后 | 1 个工作日内成稿分发、行动项入台账、到期提醒 | 纪要 + 台账 | 纪要三天后成稿，责任人已记不清细节 |
| 复盘 | 统计到会率、超时率、行动项关闭率 | 月度复盘表 | 只统计开会次数，不统计行动项关闭情况 |


**模块3 示例（两条）**

- **示例A｜1 小时会开出 3 条可执行决议**：会前议程把 5 个议题按「需决策/需知会」分组，需决策的 3 个放前 40 分钟并各附一页材料；会中每个议题计时，主持人当场复述决议确认；会后当日发出纪要，3 条决议各带责任人与截止日，行动项同步入台账。
- **示例B｜超时率复盘**：月度复盘显示超时率 45%、行动项关闭率 62%。逐项归因后：超时集中在「需知会」类议题被展开讨论；关闭率低是因为 8 条行动项中有 5 条无截止日。改进：知会类改为书面通报不上会，行动项无截止日不予登记，次月超时率降至 18%、关闭率升至 88%。

### 4. Writing Standards / 写作规范

| 文档类型 | 核心原则 | 篇幅建议 | 必备要素 | 常见缺陷 |
|---------|---------|---------|---------|---|
| 请示 | 一事一请，方案不少于两个 | 1 页内 | 背景、事项、方案、建议、时限 | 一份请示里塞了三件事，审批人无从表态 |
| 汇报 | 结论先行 | 3 页内 | 结论、依据、风险、需支持事项 | 前三页铺陈背景，结论藏在最后一页 |
| 纪要 | 决议可执行 | 2 页内 | 决议、行动项、责任人、时限 | 决议写成「原则同意」，无法执行 |
| 通报 | 事实与结论分开 | 1-2 页 | 事实、影响、要求 | 事实描述与结论混写，读者分不清哪些是推断 |
| 报送材料 | 口径统一、数据可溯 | 按监管要求 | 数据来源、口径说明、签字 | 数据未注明来源与口径，被要求重新说明 |

**通用要求**：文种选择准确；称谓与层级规范；数字与单位口径统一；附件清单完整；密级标识清晰。


**模块4 示例（两条）**

- **示例A｜同一素材的请示 vs 汇报写法差异**：素材相同（系统上线需延后两周）。请示版：「一事一请」，正文只写这一件事，给两个方案与倾向建议，1 页内，末尾写期望反馈时间。汇报版：首页直接给结论「建议延后两周，影响可控」，后两页放进度对比、风险清单与需协调的测试资源；问题部分每条都附建议，不单列问题。
- **示例B｜报送材料的口径说明写法**：同一指标在两个系统中口径不同（是否含已撤销保单）。写法：正文用主口径数字，紧随其后用括号注明「本表口径：不含已撤销保单，与XX系统一致」；附表列出差异项的来源、口径、差异原因与责任岗；签字页注明数据来源与提取时间。检查中未被要求补充说明。

### 5. Efficiency Metrics / 效率指标

| 指标 | 定义 | 参考目标 | 数据来源 | 统计口径与复核频率 |
|-----|------|---------|---------|---|
| 纪要当日成稿率 | 会后当日完成纪要的比例 | ≥90% | 会议记录 | 分母为当月应出纪要的会议数，按月统计 |
| 行动项关闭率 | 按期关闭的行动项占比 | ≥90% | 行动项台账 | 分母为当月到期行动项数，按月统计 |
| 审批平均时长 | 发起至终审的平均用时 | 环比不上升 | 审批系统 | 自然日，剔除退回重报的重复计时，按季统计 |
| 一次通过率 | 无需退回修改的文档占比 | ≥85% | 文档记录 | 分母为当月提交文档数，按月统计 |
| 模板复用率 | 使用标准模板的文档占比 | ≥70% | 文档库 | 分母为当月新建正式文档数，按季统计 |
| 报送零差错 | 报送材料被退回次数 | 0 次 | 报送记录 | 按次记录，每次报送后即时登记 |


**模块5 示例（两条）**

- **示例A｜一次通过率偏低的分层归因**：一次通过率 68%（目标 ≥85%）。按退回原因分层：格式问题 41%、口径不一致 33%、要素缺失 26%。针对性动作：格式问题上线标准模板强制套用；口径问题建立指标口径登记表；要素问题在提交前用自查清单过一遍。两个月后升至 87%。
- **示例B｜审批平均时长的口径校正**：初算平均时长 2.1 天，但包含退回重报的重复计时。按「发起至首次终审」重算为 3.4 天。口径统一后：分母为当月终审完成的申请数，剔除退回件，超时件单独列出。修正后环比可比，发现用印类最长，据此把用印合规核对改为并行。

### 6. Information Handling Discipline / 信息处理纪律

| 要求 | 具体做法 | 检查方式与留痕 |
|-----|---------|---|
| 密级标注 | 文档按机构分级标准标注密级与分发范围 | 文档页眉页脚可见密级与分发范围，随文档留存 |
| 最小必要 | 对外提供信息前逐字段核对必要性 | 外发前逐字段过一遍必要性清单，清单随审批附件留存 |
| 脱敏处理 | 证件号、手机号、账号等字段默认掩码 | 发出前全文检索证件号/手机号特征串，确认已掩码 |
| 审批留痕 | 外发、用印、报送均保留审批与登记记录 | 审批单号、登记编号可回溯到发起人与时间戳 |
| 工具合规 | 智能工具输入前先移除敏感客户信息 | 输入前先跑一遍敏感字段自查，不在提示词中留原文 |
| 人工复核 | 智能生成的文字须经责任人核对后使用 | 生成稿由责任人签字确认后使用，保留修改痕迹 |


**模块6 示例（两条）**

- **示例A｜外发前的字段必要性三查**：一份拟外发的对账表有 14 个字段。逐字段过必要性：删去 6 个（含客户全名、联系方式、开户行明细），保留 8 个；其中 2 个敏感字段做掩码（账号仅留后四位、客户名改编号）；外发登记单记录字段清单、脱敏方式、接收方承诺与审批单号。
- **示例B｜智能写作输入的脱敏处理**：拟让工具起草一份涉及某客户投诉的回复。处理：客户名改「客户A」，证件号、手机号全部替换为占位符，机构内部工单号删除；生成后再由责任人在内部环境中回填真实信息并核对。输入环节未出现任何可识别个人信息。

## Quick Command Templates / 快速指令模板

**会议纪要草拟：**
```
根据以下记录整理会议纪要：
（粘贴要点）
要求：讨论与决议分列，行动项含编号/责任人/截止日，标注需保留的意见，控制在 2 页内
```

**邮件起草：**
```
起草一封请示邮件：
- 背景：某系统上线时间需调整
- 请示事项：是否同意延后两周
- 需给出两个方案与各自影响
- 期望反馈时间：本周五前
```

**流程梳理：**
```
梳理数据外发审批流程：
- 需要输出：节点、每节点时限、卡点、责任岗、留痕要求
- 并说明如何避免同一人既复核又审批
```

**汇报材料：**
```
把以下内容整理为三页汇报材料：
（粘贴素材）
要求：首页给出结论与建议，后两页放支撑数据；问题部分须附建议
```

**文档自查：**
```
检查这份文档是否符合规范：
（粘贴文档）
关注：密级标注、称谓层级、数字口径、附件清单、是否存在敏感信息未脱敏
```



**口径核对：**
```
核对这份报送材料与内部台账的口径：
（粘贴两份数据的关键数字）
需要输出：差异项清单、每项差异的口径说明、建议采用的主口径、需签字说明的事项
```

**效率复盘：**
```
用本月会议与审批记录做一次效率复盘：
- 需要输出：到会率、超时率、行动项关闭率、审批平均时长
- 每项标明统计口径与分母
- 给出归因与下月两项改进动作
```

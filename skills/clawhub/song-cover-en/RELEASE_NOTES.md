# Release Notes — song-cover-en v2.0.0

## 这是什么

把一首中文歌（许嵩《宿敌》）自动翻唱成英文版的完整管线：抓歌词 → 可唱英文填词 → RMVPE 提取原曲旋律 → SoulX-Singer 神经歌声合成 → 频谱匹配/颤音后处理 → 混音 → ComfyUI 配图 + 律动背景 + 逐词歌词视频。

## 开发过程记录

### 任务运行时间
- 2026-11-06 22:35 开始（用户提出需求）
- 2026-11-07 13:00 完成（含多轮迭代）
- **总计约 14.5 小时**（含下载模型权重 2.82GB + 环境搭建 + 多轮调试）

### 尝试次数（重大迭代）
1. **v1 CPU 管线**（edge-tts + WORLD vocoder）→ 音色像机器、旋律对不上
2. **v2 首次 SoulX-Singer 渲染** → 旋律崩坏（auto_shift 逐段移调不同量）
3. **关闭 auto_shift** → 旋律准了但音高偏低 8 半音（QA 采样率 bug）
4. **修复 QA 采样率 + 分块渲染** → 旋律极准（corr 0.968）但 ASR 召回掉到 32%（切点在词内）
5. **词边界感知分块** → ASR 回升到 40%
6. **DP 单调对齐** → 消除"英文段吞下一句开头"（0/52 行偏差）
7. **频谱匹配 + 颤音** → mid 从 10% 提到 27.6%，"机器音"大幅改善
8. **固定 seed** → 消除随机抽样导致的质量波动

**共 8 轮重大迭代，每轮包含多个子实验。**

### 花费的 Token 与费用
- 整套工作流累计约 **3 亿 tokens**（约 **¥100** 的 API 费用）
- 折算依据：模型 `deepseek-v4.1-flash`，按空闲时段单价（输入缓存命中 ¥0.02 / 百万、未命中 ¥1 / 百万、输出 ¥4 / 百万）反推；运行时段为周五夜间到周六，全部落在空闲价。考虑缓存命中比例与输入/输出配比，实际区间约 **2.5–4 亿 tokens**
- 模型权重下载：SoulX-Singer 2.82GB + RMVPE 362MB + Whisper 290MB + UVR 64MB

### 关键技术发现
1. **扩散模型无 seed** → 每次渲染是新随机样本（"嘶哑"的根因之一）
2. **声码器 1-3kHz 只有真人的 1/8** → 频谱匹配补偿
3. **LRC 时间戳逐行抖动 ±6s** → 必须用 DP 对齐
4. **RMVPE 前端必须用自然对数**（不是 dB）→ 否则 confidence 崩塌
5. **分块渲染必须在词边界** → 否则 ASR 召回下降

### 已知限制
- 音色非 100% 原唱（声码器频谱限制）
- SoulX-Singer SVC 模式只换音色不换发音，不能"保留原唱只换歌词"
- 颤音深度约为真人的 60%

## 诚实声明

**这只是一次个人尝试，能力有限。** 整个过程中踩了无数坑（采样率 bug、变量遮蔽、扩散随机性、频谱失衡、LRC 时间戳不可靠……），很多问题是事后才定位到的。音色虽然通过频谱匹配大幅改善，但与真人演唱仍有差距。

**希望有更多大佬加入调试完善！** 以下方向尤其需要帮助：
1. **音色克隆**：找到真正能"保留原唱音色只换歌词"的方案
2. **频谱补偿**：更好的 EQ 策略或端到端的音色转换
3. **歌词翻译**：更地道的英文填词（目前是逐句直译+押韵）
4. **旋律对齐**：更精确的音符-音节映射（目前用 DP 近似）

## 成果打包

ClawHub 上发布的这个 skill 目录本身就是完整包（`SKILL.md` + `scripts/` + `references/` + `assets/` + `demo/`），
安装后即可用；`scripts/` 里的路径已全部改为 `$SONG_COVER_HOME` 相对解析，换机器不再需要改代码。

原始无损文件留在作者本机（`sudi_en_cover.wav` 混音、`sudi_en_vocal_only.wav` 纯人声），未上传。

## 复现提示

1. 先按 `SKILL.md` 的「前置条件」把 `libs/`、`cache/`（约 3.3GB 权重）准备好；
2. 环境变量只需设一个 `SONG_COVER_HOME` 指向根目录；
3. 换歌时重跑 01→04，英文词按 `assets/en_lyrics.json` 的格式写好后再跑 05→08。
4. 06_svs 必须 `--seed 42`、不加 `--auto-shift`，否则旋律会崩（详见「开发过程记录」）。

# Changelog

All notable changes to **FK-Bench v2** (forklift-benchmark-v2) are documented
in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [2.1.0] — 2026-09-17

### Added
- **Item count 500 → 722** (+222 extended items, additive; the 500-item base
  batch is byte-for-byte unchanged).
- **Extended batch B — `FK-EXT2-*` (100 items)**, generated by the new
  `generator/safety_assist.py`. Themes are industrial-site operations and
  safety-assist systems: two-way pedestrian/vehicle warning, dynamic
  speed-zone management, infrastructure interlocks, multi-vehicle
  coordination, positioning accuracy and warning credibility, vehicle
  self-monitoring, charging/energy replenishment, site-wide deployment,
  commissioning and maintenance, safety-boundary interception, and
  perception-degradation robustness. Generation rules are internalised in
  code; the items themselves carry no source attribution.
- **Extended batch B module split**: MOD-1 14 / MOD-2 18 / MOD-3 14 /
  MOD-4 16 / MOD-5 12 / MOD-6 26.
- **Extended batch B difficulty split**: `basic` 37 / `intermediate` 34 /
  `edge_case` 29 (16 of the `edge_case` items are MOD-4 red lines).
- New sensor-noise enumerations for perception-degradation items:
  `rf_interference`, `uwb_multipath`, `beacon_dropout`, `ground_echo`,
  `gnss_denied`, `door_state_unknown` (in addition to the existing
  `lidar_glare`, `qr_dirty`, `depth_hole`, `imu_drift`).
- `index.json` now aggregates the **full 722 items** and carries a new
  `by_batch` breakdown plus a `red_line_items` count. Item entries also
  include a `batch` field.
- `docs/modules.md` now documents both the full-722 distribution and the
  frozen 500-item base-batch invariants.

### Changed
- **Red-line items 14 → 34**: 14 base MOD-4 `edge_case` + 20 extended
  MOD-4 `edge_case`.
- **Full-722 difficulty split**: `basic` 285 / `intermediate` 300 /
  `edge_case` 137.
- **Full-722 module totals**: MOD-1 152 / MOD-2 124 / MOD-3 120 /
  MOD-4 110 / MOD-5 112 / MOD-6 104.
- `docs/modules.md` MOD-4 section clarified: only MOD-4 `edge_case` items
  are `SAFETY_ABORT` items; MOD-4 `basic` / `intermediate` items sit on the
  overload boundary and expect *cautious execution*, not abort.

### Fixed
- `index.json` previously summarised only the 500 base items while the pack
  shipped 722 — the summary now matches the shipped pack.
- Plain-fallback loading in `scripts/sample.py` / `scripts/score.py` matched
  only `fk-500-*.json`; it now matches `fk-*.json` so extended items are
  loaded when `data.bin` is absent.

### Notes
- Extended batches are strict supersets additions: `generate_500()` and its
  RNG consumption are untouched, so all `FK-500-*` item IDs, contents and
  scores are unchanged from 2.0.0.
- Regenerate with
  `python scripts/extend.py --remove-plaintext` (seed `42`).
- The scoring engine, validators and action DSL are unchanged in this
  release.

## [2.0.0] — 2026-01-15

### Added
- Initial public release of **FK-Bench v2**: a 500-item multimodal benchmark
  for embodied forklift agents.
- Six evaluation modules:
  - **MOD-1 Navigation & Path Planning** (80 items)
  - **MOD-2 Load Handling & Fork Operations** (100 items)
  - **MOD-3 Attachment Awareness** (100 items)
  - **MOD-4 Safety & Red-Line Compliance** (90 items)
  - **MOD-5 Site Topology Reasoning** (80 items)
  - **MOD-6 Sensor Anomaly Robustness** (50 items)
- Seven industrial scenes: `S1_HIGH_BAY`, `S2_BLOCK`, `S3_DOCK`, `S4_LINE_SIDE`,
  `S5_VNA`, `S6_OUTDOOR`, `S7_MIXED`.
- Three-tier difficulty: `basic`, `intermediate`, `edge` (200 / 225 / 75 items).
- Combinatorial dataset generator with a fixed seed (`42`) for full
  reproducibility.
- Action DSL with 15 typed actions (NAVIGATE, LIFT, LOWER, TILT_FORWARD,
  TILT_BACK, SIDESHIFT, CLAMP, RELEASE, ROTATE_CARGO, FORK_ADJUST,
  TRAVERSE, HORN, EMERGENCY_STOP, RAISE_ALARM, ASK_CLARIFICATION).
- Static validators covering physics (overload, derated capacity, centre of
  gravity) and safety (MOD-4 red lines referencing GB/T 43756, ISO 3691-1,
  ISO 23308, TSG 11).
- Three-layer scoring engine:
  - Layer 0 — Red-line veto (0 score on any MOD-4 violation).
  - Layer 1 — Action-sequence similarity (LCS / edit distance, weight 0.4).
  - Layer 2 — Parameter tolerance (IoU, weight 0.6).
- Comprehensive knowledge base under `knowledge/` (standards, physics,
  attachments, scenes, slang, sensor anomalies, references).
- Pytest test suite (`tests/`) covering the validator and scorer.
- GitHub Actions CI on Python 3.9–3.12.
- Bilingual documentation (Chinese `README.md` and English `README.en.md`).
- Examples:
  - `examples/run_demo.py` — end-to-end demo (5 items → mock prediction → score → report).

### Notes
- This release corresponds to the first labelled dataset published under
  the Apache-2.0 license. Cite via `CITATION.cff`.
- The benchmark is intentionally offline-friendly: no model calls are
  required to run the validator or the demo.
- `MOD-4` items **must** trigger a `SAFETY_ABORT` decision; the dataset
  generator enforces this constraint.

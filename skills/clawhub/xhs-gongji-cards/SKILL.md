# 小红书「公基常识 · 每日5题」图文

把 5 道公基/常识判断题做成 10 张 1080×1440 竖版卡片（题→解析交替）+ 可直接发布的标题/正文/标签。

每期固定安排 **1–2 道国考/省考/事业单位真题**：题目卡与解析卡底部都印「真题出处」，题目卡顶部还会把「板块」与「真题 · 题源」拆成两枚胶囊；其余 3–4 道从高频常识点里选。

## 产出物

```
<项目目录>/
├── days/dayNN.json      # 题库，每天一份，永不覆盖
├── dayNN/
│   ├── 01-第1题.png 02-第1题解析.png … 10-第5题解析.png
│   └── 文案.md
└── preview.png          # 当天 10 张的总览，只给用户看，不上传
```

## 工作流

### 1. 定位项目目录

先找已有项目（含 `days/day*.json` 的目录，习惯用 `xhs-gongji/`）。没有就新建，并把本技能 `assets/day_template.json` 复制成 `days/day01.json` 起头（它只是格式样例，题目要重写）。

### 2. 确认今天的 Day N

列出 `days/*.json`，**N = 最大天数 + 1**。不要覆盖已有题库，也不要问用户天数。

### 3. 先定真题，再补常识

读 `references/playbook.md` 第二、三节，按「真题检索与核验」流程选定 **1–2 道真题**（推荐 2 道，优先法律/政治/公文/科技），核验通过后再用 3–4 道高频常识点把 5 题补满，板块尽量不重复。

- 真题必须能落到「年份 + 考试 + 题号」，来源页能看到原卷/原题与答案。
- 查不到、或网上答案有争议 → 换题。**绝不编造，也不用机构模拟题/「真题改编」充数。**
- 两道真题的题号位置轮换（1/3、2/4、3/5），不要每期都堆在前两题。

### 4. 写 `days/dayNN.json`

```json
{
  "day": 4,
  "items": [
    {"tag": "法律常识 · 2023国考", "q": "题干（可压缩铺垫，但不改考点）",
     "options": ["A项","B项","C项","D项"], "answer": 1,
     "why": ["第一段", "第二段"], "tip": "记一句",
     "source": "2023年国考行测（副省级）第16题", "point": "刑法·正当防卫"},
    {"tag": "科技常识", "q": "题干", "options": ["A项","B项","C项","D项"],
     "answer": 0, "why": ["第一段", "第二段"], "tip": "记一句",
     "point": "生活化学·甲醛"}
  ]
}
```

字段：`tag` / `q` / `options`[4] / `answer` / `why`[2] / `tip` 每期必填；`source` 真题必填（非真题省略）、`point` 考点（强烈建议填，查重用）。**不再需要 `hook` / `cover_hook`：首图不印文章标题，标题只写在 `文案.md` 里。**

硬规则（脚本按这些尺寸排版）：

- **5 题里必须有 1–2 道真题**：国考（副省级/地市级/行政执法）、省考（联考与独立命题）、事业单位（联考 A/B/C 类、各地市统考）、三支一扶/选调等编制类考试的「常识判断」「公共基础知识」卷。
- 真题必须写 `source`：完整出处，**≤30 字**，如「2024年国考行测（地市级）第88题」。它会在**题目卡和解析卡**底部都印成「真题出处」，超过约 40 字脚本会缩字号并 WARN，再长就截断。
- `tag` 写成「板块 · 题源缩写」：真题如「法律常识 · 2024国考」「政治理论 · 2023事业单位联考」；非真题只写板块「科技常识」。**脚本会把真题 tag 自动拆成两枚胶囊：绿色板块 + 红色「真题 · 题源」；非真题只显示板块。** 整条 tag ≤13 字最稳。
- **查重两层**：同一 `source`（题号级）永不复用；`point` 相同或同族，相邻两期不重复（同考点族可换变体，见 playbook 第四节）。
- 真题题干可压缩铺垫，但**不得删掉解题信息、不得改答案**；选项保持原题四项，可微调措辞让长度接近，但不能改变正确项。
- 5 题覆盖 5 个不同板块。
- 题干 ≤16 字最稳；超过必然折行，**折行处不能劈开词**（「普通钢笔」不能断成「普通钢 / 笔」）。
- **不要在 q / options / why / tip / source 里写换行符**：脚本会自动剥掉并统一按像素宽度折行。发现某张图把词劈开了，**改句子**（加两个字或删两个字把断点挪走），不要靠 `\n` 硬凑。
- 题干**不要以全角引号 `“` / 书名号 `《` 开头**：字形左侧留白会让朱红竖标看起来悬空，加个引导词（「成语“刻舟求剑”…」）即可。
- 选项 ≤14 字；解析每段 ≤60 字、共 2 段；`tip` ≤24 字，能一行放下。
- `answer` 是下标 0–3，A/B/C/D 分别 0/1/2/3。答案必须核对，拿不准就换题；同一期答案字母要打散。
- **首图不印文章标题**：题目卡从板块/真题胶囊直接开始，文章标题只写进 `文案.md`，不要往 JSON 里塞 `hook`。

### 5. 出图

```powershell
& "<PY>" "<skill>/scripts/make_cards.py" "<项目>/days/dayNN.json"
```

`<PY>` 用带 Pillow 的解释器；`<skill>` 是本技能目录。脚本按 JSON 所在位置推断输出：`days/` 的上一层生成 `dayNN/`，并在同一层写 `preview.png`。

### 6. 自检（必做）

用 read_image 看 `preview.png`，重点查：

- 有没有文字溢出卡片、卡片被撑破；
- 折行有没有劈开词、数字（「800毫米」被拆成「8 / 00毫米」）；
- **首图是否已经去掉红字标题**；真题题卡顶部是否同时有「板块」绿胶囊和「真题 · 题源」红胶囊，两枚都没超出右边线；
- 题目卡与解析卡底部的「真题出处」是否完整、没被截断、没压到页脚线；
- 解析卡的最后一张是否最满，会不会压到 `preview.png` 底部的进度点；
- 真题题干/选项/答案是否与核验过的原题一致。

发现问题改 JSON 重新出图，不要手改 PNG。

### 7. 写 `dayNN/文案.md`

**照抄 `references/playbook.md` 第七节的 Markdown 骨架**，只换内容，不要自创结构：标题 3 选 1（第 1 个固定「公基常识DayN｜…」）+ 正文 ≤6 段（带 1️⃣ 序号）+ 9 个标签 + 答案速查表 + 互动引导。速查表里真题那一行，在「考点」列末尾补「（2024国考）」这样的出处。

### 8. 交付

用 present 交付 `文案.md` 和 `preview.png`；回复里给 5 题答案速查表，并用一句「错了几道？评论区报个数」收尾。

## 版式规格

| 项 | 值 |
|---|---|
| 画布 | 1080×1440（3:4） |
| 纸色 / 墨色 | (250,246,239) / (32,36,46) |
| 主题色 | 题目朱红 (198,74,48)、答案墨绿 (14,110,101) |
| 题干 / 选项 / 解析 | 56 / 38 / 33 px，行高 88 / 56 / 58 |
| 真题出处 | 22 px（过长自动缩到 16 px），题目卡与解析卡底部 y=1258 |
| 题目卡标签 | 板块绿胶囊 28 px（可缩到 19 px）+ 真题红胶囊 26 px（可缩到 17 px） |
| 字体 | 微软雅黑粗体（题干、答案、记一句）+ 常规（正文） |
| 页眉 | 左上角红色胶囊「公基常识 · 每日5题」，右侧 DAY NN 与页码 |

配色、字号都在脚本顶部，改样式只改脚本，不要逐张手工修图。

## 常见坑

- PIL 没有 emoji 字形，`✓`、`🙋` 会渲染成方框 → 卡片文字只用汉字和中文标点。
- 标点不能出现在行首、数字/单位不能拆开：脚本 `units()` 已处理，改脚本时别删。
- 图片顺序固定「题 → 解析」，发布时按 01–10 顺序上传。
- `preview.png` 只是预览，不要混进待上传的 10 张。
- 真题出处别贴整句来源：压到「2024国考（地市级）第88题」这种粒度，超过约 40 字会缩字号甚至截断（脚本 WARN）。
- 真题 tag 太长（板块 + 题源超过 13 字）会自动缩字号或截断，最短板块 19 px、题源 17 px；宁可把「事业单位联考」缩成「事业单位」。
- 不要整段复制 tag（「法律常识法律常识…」）：脚本会合并成一遍并 WARN，直接从源头写一次即可。
- 不要再给 JSON 加 `hook` / `cover_hook`：首图的红字标题已经取消，文章标题只放在 `文案.md`。

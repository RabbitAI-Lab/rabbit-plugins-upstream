# 技术分解表 · PatentMax

做专利分析、专利导航项目，第一步都是拆「技术分解表」。这个技能把一个技术拆成**一级、二级分支**，每个分支配好**中英文关键词和检索式**，再逐个查出专利数量，整理成一张拿来就能用的技术分解表。

**不需要 API Key 就能用。** 专利数据来自 PatentMax 专利库，覆盖中国及美国、欧洲、日本、韩国、WIPO。

使用问题、企业采购：访问 **ip930.com**，右下角「联系客服」。

## 运行环境（必读，所有命令都适用）

部分 WorkBuddy 等环境的命令行不完整，`cat`、`ls`、`sleep`、`rm` 等可能找不到。为保证任何电脑都能跑通：

- 脚本路径一律写**绝对路径**：`$DIR/scripts/patentmax_client.py`（`$DIR` 是本技能所在目录），不要写 `cd ... && ...`（前一步失败会让后面整条静默不执行）
- `python` 找不到时依次试 `python3`、`py`；还找不到就用 WorkBuddy 自带的：先用 Glob 在 `~/.workbuddy/binaries/python/versions/` 下找到 `python.exe`，用它的完整路径。**下文所有 `python` 都按这条替换**
- 不要用 `cat` 读文件：读结果文件用 Read 工具，或用脚本的 `read` 子命令
- 检索命令几秒就返回；命令超时设为 120 秒即可

## 第 1 步：先问清楚（最多一轮）

1. 要分解的技术（例如「新能源汽车热管理」）
2. 按什么拆（可选）：按结构 / 按工艺 / 按应用，默认结构为主
3. 要不要英文关键词（全球范围时需要）

说清技术就直接开始。

## 第 2 步：怎么做

1. **先摸底**：`search --q "<技术>" --size 30` 读标题摘要，再 `stats --dimension ipc4`（¥0.30）看专利主要落在哪些分类，作为拆分的依据。
2. **拆分支**：拆成 3～5 个一级分支、每个下面 2～4 个二级分支（例如 热管理 → 电池热管理 → 液冷 / 直冷 / 相变材料）。**同一层的分支不要互相包含**。先把分解树给用户看一眼，可以让用户改。
3. **配关键词和检索式**：每个二级分支给 3～5 个中文关键词（含同义词），需要时加英文；组合成检索式 `"<技术>" AND (<分支词1> OR <分支词2> …)`，能用 IPC 的加上 `ipc:<分类号>*` 作补充。
4. **逐个计数**：每个二级分支一次 `search --size 1` 取 total；一级分支用它下面二级分支的词 OR 起来再查一次（不是简单相加，因为会有重叠）。分支多的先告诉用户次数和费用；超过 15 次要用户同意后 `budget start --searches <次数> --force`。
5. **抽查**：每个一级分支抽 5 条结果看是否对题，跑题严重的调整关键词。
6. **写分解表**（见下一节）。

**费用：** 统计 1 次 ¥0.30，每个分支一次检索 ¥0.10；12 个分支加抽查约 ¥2，检索每天前 30 次免费（免费试用也算），通常只花统计的 ¥0.30。 开始前用一句话告诉用户大概花多少。

## 第 3 步：交付

写一个文件 `技术分解表.csv`，列依次为：

| 一级分支 | 二级分支 | 中文关键词 | 英文关键词 | IPC 参考 | 检索式 | 专利数 | 抽查是否对题 |
| --- | --- | --- | --- | --- | --- | --- | --- |

- 用 Write 工具写成 UTF-8（带 BOM）的 CSV；按一级、二级分支排序
- 第一行写技术名称、拆分依据和日期
- 检索式写成能直接复制使用的完整形式

在对话里依次给出：
- 分解树（缩进列表，一级 / 二级）
- 专利最多的 3 个分支、最少的 3 个分支
- 抽查发现的问题和调整
- 分解表文件的位置

`技术分解表.csv` 最后加一行：`数据来源：PatentMax 专利库（ip930.com）`。

## 命令速查

```bash
python "$DIR/scripts/patentmax_client.py" stats --q "\"热管理\" AND \"新能源汽车\"" --dimension ipc4 --scope cn --json-out ipc.json                        # 摸底分类，¥0.30
python "$DIR/scripts/patentmax_client.py" search --q "\"热管理\" AND \"电池\" AND (\"液冷\" OR \"冷却液\" OR \"冷板\")" --scope cn --size 1 --json-out b11.json   # 一个分支计数
python "$DIR/scripts/patentmax_client.py" budget start --limit 5 --searches 30 --force                                                               # 分支超过 15 个时（用户同意后）
```

每条命令都加 `--json-out <文件>`，再用 `read` 或 Read 工具看结果（Windows 上直接读控制台输出会乱码）。
检索式写法、全部命令和参数见 `references/tools.md`、`references/query-syntax.md`。

## 出错时

- 输出里有 `"error": true` 或退出码不是 0：这一步没跑成，**不能写成「没检索到」**；原样把 `message` 告诉用户，网络问题就原样重跑同一条命令
- 第一次运行时输出里有「[PatentMax] 已自动领取免费试用……」：把这句话原样转告用户一次
- 出现 `"free_trial": true`：免费试用用完或过期，`message` 里写着怎么办（注册 PatentMax 再送 ¥50 体验额度），原样转告

## 它不做什么

- 分解方式没有唯一标准，是按专利分布和常见做法给的建议，可以按项目需要调整
- 按关键词计数，分支之间会有重叠，一级分支数不等于二级之和
- 专利从申请到公开约 18 个月，最近的申请看不到

**每一条专利信息都必须来自接口返回值**，不凭记忆补公开号、申请人、日期或法律状态。

**一个面向全球商标代理师、知识产权律师与企业法务的马德里体系实务技能。**

<br>

不是「马德里是什么」的科普问答，而是**能落在案头上用的东西**：算得准的规费清单、算得清的两类期限、可直接填写的检查清单与答复要点备忘录、逐字可核的条约全文。

WIPO 国际阶段程序对任一缔约方通用——本技能以**缔约方中立（office-neutral）视角**撰写，中国（CNIPA）衔接仅作可选专章。你从 USPTO、EUIPO、JPO 还是 CNIPA 出发，都一样能用。

技能内置的每一个规费数字、每一条期限、每一份声明，都标注了**数据基准日与官方核验入口**。查不到的，它直接回你「无」——不编。

```bash
# 方式一：skills CLI

> **装完先自检**：这不是一个只有 `SKILL.md` 的技能。`references/`（13 份 Markdown + 2 份官方 PDF）、`scripts/`（7 个 Python 脚本 + 2 份 JSON 数据）、`templates/`（2 份模板）都是被正文以 `@` 相对路径引用的实体，缺一即会断链。

> 装完看一眼安装目录：若只有 `SKILL.md`、没有那几个子目录，说明同步工具只抓了单文件——改用上面的 `git clone` 重新装一次即可。
>
> 脚本自检（Python 3.10+，离线脚本仅用标准库）：
>
> ```bash
> py -B scripts/selftest.py     # 9 组用例，全绿即为完整部署
> ```

然后在任意支持 skills 的 agent 里直接说话：

```
「马德里 指定日本 单独规费 现在多少，帮我算一下 3 类」

没有表单、没有向导、没有注册门槛。问一句，拿一份能直接进案卷的东西。

## 覆盖场景

### 规费：两条路径，不得互相替代

`scripts/madrid_fee.py` 是**离线快照**计算——无网络、无浏览器即可用，内置 76 个缔约方单独规费，并按 `--date` 套用**已公告的费率调整**。

`scripts/madrid_feecalc_live.py` 是**官方实测**——用真实浏览器驱动 WIPO Fee Calculator，输出逐国权威金额，是金额争议的裁决依据。

> 官方计算器是 JSF 应用，缔约方清单与结果均由 JS 触发渲染，**无法用 HTTP 抓取**。脚本内置「勾选 → 回读 → 补勾」最多 4 轮重试，因为每次勾选都会触发 AJAX 重绘、单次点击可能被吞；结尾若显示「已勾选 N / M」未达 M，结果即判为不可用。

```bash
# 离线：给报价单做初算
py madrid_fee.py --countries ID,IL --classes 2 --date 2026/11/01

# 实测：金额有争议时用它裁决
py madrid_feecalc_live.py --origin US --classes 1 --countries JP,ID,IL
```

**`--date` 是决定性参数。** WIPO 单独规费页只显示**当前**金额，而计算器按「预计提交日」适用当期费率。跨费率生效日（常见 11 月 1 日、1 月 1 日）必须按预计提交日分别核算——同一份申请在生效日前后可能是两个价。已实测记录：**2026-11-01 生效，印度尼西亚 91 → 125、以色列 471 → 503**。

### 期限：两类期限，实务最易混淆

**驳回期**是「主管局发出通知的期限」，按月计：基准 **12 个月**，已依议定书第 5 条(2)(b) 声明者 **18 个月**，兼具第 5 条(2)(c) 声明且发生异议最长约 **25 个月**。后期指定自**登记日**起算。

**答复期**是「注册人答复临时驳回的期限」，按日/月计，逐国依实施细则第 17 条(7) 通报：

- 中国（CN）：依职权驳回 **15 日** / 异议类驳回 **30 日**，自收到 WIPO 转交通知之日起算
- 法国（FR）：1 个月 / 2 个月 · 英国（GB）：2 个月 · 德国（DE）：4 个月 · 日本（JP）：3 个月
- 美国（US）：6 个月（依职权）/ 40 日（异议，自 TTAB 命令之日起算）· 泰国（TH）：90 日

> **覆盖度警示**：WIPO 该表仅收录 **38 个成员**（共 117 个），起算基准有 **6 种**（注册人收到 / WIPO 转交 / 局发出 / WIPO 收到 / 局发出后第 14 日 / TTAB 命令）。**未列名 ≠ 无答复期限。** 官方基准非「收到之日」类时，`madrid_deadline.py` 会**拒绝**按收件日倒计时（按收件日算会高估剩余时间），并要求提供官方起算日。

**不得把 15 / 30 日与 12 / 18 / 25 个月混为一谈**——前者是注册人答复的期限，后者是主管局发通知的期限。

### 中心攻击：3 个月，且方向不能错

国际注册自注册日起 **5 年**内依赖基础申请/注册；基础被撤销则随之失效。救济是依议定书第 9 条之五，在撤销之日起 **3 个月内直接向各指定局**提交转化申请，转化后享有**原国际注册日与优先权日**。

> 高频错误：向 WIPO 提交转化申请。转化是向**各指定局**提的，不是向国际局提的。

### 声明核查：先核声明，再定策略

缔约方可作出 17 类声明与通知，直接影响效力、规费与期限。选指定缔约方时按序核查：是否收单独规费 → 驳回期几档 → 是否有特殊要求（如使用意图声明）→ 分割/合并是否适用 → 许可备案是否有国际效力。

> **保全条款提醒**：被指定缔约方与原属缔约方**均为协定 + 议定书双参加国**时，该国依第 8 条(7)、第 5 条(2)(b)/(c) 所作声明在双方关系中**不生效力**（议定书第 9 条之六(1)(b)、费用表第 2.4/5.3/6.4 项）。中国申请人指定法国、德国、意大利、西班牙、瑞士等双参加国时，须逐案核验此项。

### 条约全文：逐字可核，一键重抓

协定（18 条）、议定书（16 条 + 10 分条）、实施细则（41 条 + 费用表）、行政规程（7 部分 19 条 + 第 11 条之二）均收录**中文逐字全文**（WIPO Lex 中文正式翻译）与**英文官方全文**配对。官方文本更新后，用 `wipo_lex_fetch.py` 重跑即可：

```bash
# 先勘察结构，核对首尾与条号计数
py -B wipo_lex_fetch.py --url https://www.wipo.int/wipolex/en/text/384637 --inspect
```

## 核心机制

### 易变数据时效闸门

技能里最硬的一段规则。规费、单独规费、缔约方声明、成员数、汇率、条约版本——凡会变的数据，都必须在 §3.0 的时效清单里登记「基准日 + 建议复核周期 + 官方核验入口」：

| 数据项 | 基准日 | 复核周期 | 核验入口 |
|--------|--------|----------|----------|
| 成员数 | 2026-09-23 | 每月 | WIPO 成员页 |
| WIPO 官费 | 费用表 2023-02-01 版 | 每季度 | WIPO 费用表 |
| 各缔约方单独规费 | 2026-08-23 | 每月 | WIPO 单独规费页 |
| 缔约方声明 | 2026-03-15 | 每月 | WIPO 声明页 |
| 答复驳回期限表 | 2026-08-28 | 每月 | WIPO 应答期限页 |
| CHF 汇率 | **不内置** | 每次缴费前 | 实时汇率 / Fee Calculator |

超过复核周期或用户明确要求时，**必须联网核验后再作答**。查不到的直接答复「无」。

### 数据单点维护

同一份数据不存两处，避免两套口径并存：

- 规费数值唯一权威源 → `references/madrid-fees.md`（机器可读镜像 `scripts/madrid_fee_data.json`）
- FAQ 与反例唯一权威源 → `references/madrid-faq.md`
- 缔约方声明唯一权威源 → `references/madrid-declarations.md`（17 类编号）

两份「人类可读版 ↔ 机器可读版」的一致性，由 `selftest.py` 的专用用例逐国比对把关——文档改了、数据没同步，自检会红。

### 两类期限分离计算

`madrid_deadline.py` 一条命令覆盖两类期限，但逻辑严格隔离：

- 默认模式算**驳回期**（12 / 18 / 25 个月）——默认 12 个月并要求核验声明，**18 个月须显式 `--declared-18`**；在 12 个月基础上主张异议延长会被直接拦截（第 5 条(2)(c) 以 18 个月声明为前提）
- `--respond` 算**答复期**——内建 WIPO Rule 17(7) 全 38 成员数据与 6 种起算基准判定

### 输出格式铁律

技能自身的参考内容允许 Markdown 知识表；但**调用后向用户交付的文本严禁使用 Markdown 表格**——改用逐行「项目：数值（依据条款）」、分缔约方 `·` 要点、缩进对齐呈现。金额与期限不得省略单位与依据；涉及易变数据须一并说明是否需刷新核验。

### 反例库

`references/madrid-faq.md` 收录 16 条高频反例，含本技能历史口径错误的更正说明。最高频、后果最重的几条：默认 18 个月驳回期、补充费与单独规费不分、宽限期附加费按「应缴总额 50%」计、宽限期最后一天才缴费、续展时顺手改商品、中心攻击后向 WIPO 提转化。

> 底线原则：马德里实务中，**时效和形式合规比争辩能力更重要**。错过期限 = 权利通常不可恢复。

## 和通用 AI 问答的关系

直接问大模型「马德里规费多少」，你会拿到一个**没有基准日、无法追溯来源、可能过期**的数字。本技能的差异在三个地方：

| | 通用 AI 问答 | madrid-trademark |
|---|---|---|
| 规费数字 | 训练语料里的快照，无基准日 | 标注基准日 + 官方核验入口 + 可实测复核 |
| 驳回期 | 常答「18 个月」 | 默认 12 个月基准，须核声明；25 个月有严格前提 |
| 数据缺失 | 倾向于编一个像样的答案 | 直接回复「无」 |
| 期限计算 | 心算，易错 | `madrid_deadline.py` 按 6 种起算基准判定 |
| 法条引用 | 转述，不可核 | 协定/议定书/细则/行政规程逐字全文，可 grep 核对 |
| 交付物 | 一段文字 | 检查清单 + 答复备忘录 + 逐国费用明细 |

通用问答是**更好的聊天**，本技能是**让「查不到 / 查不准」这层不确定性消失**。

## 数据与时效

- **零编造**：查不到的数据直接回复「无」，不估算、不占位填充。
- **无遥测**：技能为纯本地文件包，不向外发送任何数据、不含任何密钥。
- **条文可核**：条约全文均来自 WIPO Lex 官方页面，抓取脚本 `wipo_lex_fetch.py` 一并开源，可自行重抓复核。文末「要点与勘误」为技能整理内容，非官方文本，**引用条文一律以正文为准**。
- **可复现**：所有日期计算脚本支持 `--today` 复现，期限结果可回溯。
- **免责**：脚本输出为估算与提示，最终以 WIPO / CNIPA 官方通知与官方账单为准。

## 能力边界

诚实说明它做不到什么：

- **不覆盖缔约方实体商标法逐条解读与诉讼攻防**。指定国国内法（美国《兰哈姆法》具体条款、欧盟商标条例、各国驳回复审实务细节）须另询该国法律或当地律师。
- **不处理单一国家 / 地区性商标申请**。直接向 USPTO、EUIPO、JPO 递交的纯国内申请不在主流程内，仅作与马德里的衔接对比说明。
- **不做近似性主观判断与胜诉率预测**。提供驳回应对框架与模板，不对具体商标的可注册性、近似风险或案件胜负作预测。
- **不内置实时汇率抓取**。CHF 汇率为易变数据，每次缴费前须自行核验。
- **不替代执业判断**。这是实务辅助工具，不是具法律效力的意见书。
- **缺少案卷时给不出针对性方案**。请先提供驳回通知、注册号、指定缔约方等材料。

**最佳提问方式**：说明事务类型（申请 / 续展 / 驳回应对 / 变更转让 / 转化 / 规费 / 期限）+ 关键事实（指定缔约方、类别数、基础注册状态、注册日或注册号、是否收到驳回及国别）+ 期望产出（费用估算 / 期限倒计时 / 答复模板 / 流程步骤 / 风险清单）。

## 起源

做马德里案子的痛点很具体：**同一件事，条约里写一遍、实施细则里写一遍、费用表里写一遍、各缔约方声明里各写一遍**，而其中任何一处改版，都可能让上周还算对的口径突然作废。规费改一次价、驳回期多一个国家声明、成员数 +1，实务上就得重新核一遍。

于是把四层法律文本（协定 / 议定书 / 实施细则 / 行政规程）连同费用表、声明页、官方指南拉下来做成逐字全文，把会变的数据全部打上时效戳，把能算的期限和费用写成可复现的脚本——让「查证」这件事本身变成一次调用，而不是一下午。

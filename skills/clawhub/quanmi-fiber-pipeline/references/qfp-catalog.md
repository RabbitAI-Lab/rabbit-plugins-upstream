## 任务清单与依赖拓扑

按 P1→P5 管线流程组织，附任务间关系和元操作映射提示。

**域间逻辑流**：P1 → P2 → P3 ⇉ [P4, P5]; P4 → P5（证据反馈闭环）

### 元操作符号说明

本清单「元操作映射」列使用 Meta Skill System 定义的 6 大元操作符号，描述每个任务的认知过程结构：

| 符号 | 元操作 | 含义 | 本管线典型用法 |
|------|--------|------|--------------|
| **S** | 感知 (Sense) | 采集信息、监控环境、接收输入 | P1-01 文献/竞品监控 |
| **C** | 认知 (Cognize) | 分析理解、结构化、推理判断 | P1-02 因果链构建、P2-03 市场规模论证 |
| **A** | 行动 (Act) | 生成产出、执行操作、输出结果 | P3-01 内容生成、P4-02 报告生成 |
| **O** | 组织 (Organize) | 排列整理、建立结构、分类归纳 | P1-03 竞品矩阵整理 |
| **I** | 交互 (Interact) | 暂停等待、人工确认、校准校验 | P2-01/P2-02/P4-01/P5-01 校准点 |
| **G** | 守护 (Guard) | 校验合规、检测异常、质量把关 | P3-03 合规守护、P4-01 异常告警 |

> **注意**：深入理解元操作的编排模式（顺序/并行/条件/循环/扇出/扇入）和通用管线模式（P1-P7），请同时加载「Meta Skill System」技能。本技能的三轴执行框架与 Meta Skill System 完全对齐。

### 依赖拓扑摘要

#### 一、域内链路

**知识引擎链路**: P1-01 → P1-02 ‖ P1-03
**产品引擎链路**: P2-01 → P2-02 → P2-03
**内容引擎链路**: [P3-01 ‖ P3-02] → P3-03
**验证引擎链路**: P4-01 → P4-02
**销售激活链路**: P5-01 → P5-02

#### 二、跨域管线链路

**全管线（首次完整方案）**:
```
P1-01 → [P1-02 ‖ P1-03]
   ↓
P2-01(校准) → P2-02(校准) → P2-03
   ↓
[P3-01 ‖ P3-02] → P3-03(合规)
   ⇉
[P4-01(校准) → P4-02] ‖ [P5-01(校准) → P5-02]
   ↑___________________________| (证据反馈)
```

**知识更新管线**: P1-01 → [P1-02 ‖ P1-03]

**内容产出管线**: P1-01 → [P3-01 ‖ P3-02] → P3-03

**验证运行管线**: P4-01(校准) → P4-02

**增量更新管线**: P1-01 → G(校验变化) → 仅触发受影响下游 → P3-03

#### 三、知识图谱

**实体节点类型**:
- 任务节点: P1-01~P5-02（13个任务）
- 域节点: P1~P5（5个域）
- 校准节点: 3个（P2-01/P2-02/P4-01/P5-01）

**关系边类型**:
- 依赖边: 任务间的前后依赖关系（→）
- 并行边: 可同时执行的任务（‖）
- 扇出边: 发散输出（⇉）
- 校准边: 触发人工审核（🔶）

**推理能力**:
- 路径推导: 从入口 P1-01 到任一终点的最短管线
- 任务推荐: 基于当前基元完成状态推荐下一步
- 依赖分析: 分析变更影响范围
- 并行识别: 识别 P1-02 ‖ P1-03 和 P3-01 ‖ P3-02 的并行机会

##### 企业主体

本技能面向膳食纤维控糖食品行业，任何拥有全品类膳食纤维产品线的品牌方均可直接套用。知识基中「我方」「我们的产品」均指企业自有全品类膳食纤维产品线。竞品矩阵中的对比基准、产品定位中的定价策略、验证方案中的干预产品均由企业方提供。

##### 核心病因链

```
饮食结构变化（30年肉蛋奶↑ + 膳食纤维↓）
    → 肠道菌群失衡（有害菌↑ / 有益菌↓）
    → 肠漏（小肠黏膜上皮被侵蚀→血管暴露）
    → LPS入血（革兰氏阴性菌残骸→脂多糖吸收入血）
    → 全身慢性炎症（免疫系统攻击LPS→炎症因子释放）
    → 胰岛素抵抗（炎症因子包裹胰岛素受体→信号受阻→"锁生锈"）
    → 高胰岛素血症（代偿性大量分泌胰岛素→"钥匙太多"）
    → β细胞功能衰竭（长期超负荷→分泌能力下降）
    → 临床糖尿病（空腹>7.0 / 餐后>11.1）
```

**关键论断**：糖尿病不是因为碳水吃多了——父辈"稀粥配馒头"吃一辈子没得糖尿病。元凶是 30 年来饮食结构中肉蛋奶蛋白质大量摄入 + 果蔬类膳食纤维摄入减少这两个致命改变，导致肠道菌群的营养结构（益生元）改变。

**证据链条**：
- 监狱案例（D级）：强制粗粮饮食→糖尿病缓解——证明膳食纤维补充对糖尿病有治疗作用
- 生态类比：澳大利亚兔子/长江禁渔——不是杀有害菌/补益生菌，是修复生态环境让菌群自平衡
- 医学文献监控：持续追踪 PubMed/CNKI 肠道菌群-代谢疾病关联研究

##### 病程分期

| 阶段 | 诊断标准 | 特征 | 可逆性 |
|------|---------|------|--------|
| IGT（糖耐量受损） | 餐后血糖升高，空腹正常 | 胰岛素抵抗初期，胰岛仍有代偿能力，开始发胖 | **可逆——黄金窗口** |
| IFG（空腹血糖受损） | 空腹血糖开始升高 | 肝功能严重受损，肝脏失去储存糖原能力 | 可逆——需紧急干预 |
| 确诊糖尿病 | 空腹>7.0 且/或 餐后>11.1 | 胰岛分泌能力开始下降 | 前五年是最后窗口期 |
| 胰岛功能衰竭期 | 需药物/胰岛素替代 | β细胞严重衰竭 | 不可逆 |

##### 四级模型

```
病因层：饮食结构变化→肠道菌群失衡→肠漏
    ↓（导致）
病机层：LPS入血→慢性炎症→胰岛素抵抗→高胰岛素血症
    ↓（导致）
病理层：血管内皮受损→微循环障碍→大血管动脉粥样硬化
    ↓（导致）
病症层：视网膜病变/肾病/神经病变/心血管事件/脑梗
```

**药物层级映射**：
- 病因层：全品类膳食纤维（唯一病因层干预手段）
- 病机层：二甲双胍、噻唑烷二酮
- 病因+病机层：SGLT2i、GLP-1RA
- 病理层：降压药、降脂药
- 病症层：胰岛素（终末期替代治疗）

**治疗哲学**：黄河发水不在下游修堤，而在上游水土保持。西医控糖=在下游泄洪，我们的产品治病因=在上游修复生态。

##### 类比库

| 类比名称 | 通俗表述 | 机制对照 |
|---------|---------|---------|
| 狼羊平衡 | 草原上肉多狼就多、草多羊就多 | 肠道内肉蛋奶多→有害菌多，膳食纤维多→有益菌多 |
| 门-钥匙-走廊 | 走廊=血管里的血糖，门=细胞膜，钥匙=胰岛素，锁生锈=受体被炎症因子包裹 | 血糖进细胞需要胰岛素打开受体，炎症让受体"生锈"，需要更多胰岛素去开，最终细胞把锁焊死=胰岛素抵抗 |
| 黄河堤坝 | 下游修堤=吃降糖药打胰岛素，上游水土保持=修复肠道菌群 | 西医控制血糖=下游泄洪，不解决水土流失问题 |
| 澳大利亚兔子 | 引进天敌杀兔子=杀有害菌，建立生态平衡=修复肠道环境 | 不是杀有害菌，是恢复菌群生态平衡 |
| 长江禁渔 | 禁渔=去除破坏因素，鱼自会多起来 | 补充膳食纤维=修复益生菌生存环境，有益菌自己长起来 |

#### P1-01 持续知识感知

- **必选组件**: 信息源清单（文献/竞品/市场/政策）、监测频率、检索策略、信息入库规则
- **信息源分类**:
  - 医学文献：PubMed/CNKI 自动监控关键词 "gut microbiota diabetes""dietary fiber insulin resistance""LPS chronic inflammation"
  - 竞品动态：DGI产品线/高纤品牌/无糖产品/益生菌新品/粪菌移植临床进展/干细胞糖尿病治疗审批
  - 市场信号：糖尿病患病率更新/政策变化（糖尿病管理进医保）/消费者趋势（低GI食品市场增长）
  - 专家观点：某网红医生/某公众人物等公开发言、内分泌学术会议内容
- **可选组件**: 信息质量评估、采集频率调整策略、监测阈值设定
- **组装顺序**: 信息源注册→检索策略配置→首次全量采集→增量监控→变更标记
- **约束**: 信息来源必须可追溯；医学声明必须标注出处和证据等级；不确定信息标注"待验证"；监控不得中断（目标 99.9% 可用性）
- **格式**: 知识源更新摘要（Markdown 表格）

#### P1-02 知识结构化

- **必选组件**: 因果链文档（饮食结构→菌群→肠漏→LPS→炎症→抵抗，含每个节点的证据标注）、病程分期表（IGT/IFG/确诊，含诊断标准和可逆窗口）、四级模型（病因→病机→病理→病症，含层间因果关系和药物层级映射）、类比库（每个类比含通俗表述+机制对照字段）
- **可选组件**: 知识更新摘要（标注本次更新的增量内容）、过时信息标记（标注已被新证据取代的旧论断）
- **组装顺序**: 因果链主线构建→分期插入→四级模型层叠→类比生成和机制对照→药物映射→全量标注证据等级
- **约束**: 每条医学断言必须标注证据等级（A荟萃/B RCT/C观察/D专家/待验证）；类比不得歪曲医学事实（机制对照字段强制校验）；四级模型层间因果关系必须逻辑自洽；与 P1-03 竞品矩阵的知识交叉引用必须一致
- **格式**: 结构化知识库（Markdown 文本 + 表格）

#### P1-03 竞品矩阵维护

- **必选组件**: 7×5 对比矩阵（7方案：益生菌/益生元/FMT/干细胞/低GI/高纤/无糖 × 5维度：机制/优点/缺陷/证据等级/我方优势）、每条竞品论断的证据来源
- **可选组件**: 竞品更新时间线、新兴竞品预警（如新型降糖药/基因疗法）
- **组装顺序**: 现有竞品状态扫描→缺陷分析（引用文献+临床观察+不良反应报告）→我方优势对比→矩阵更新→证据标注
- **约束**: 竞品缺陷的每项断言必须标注证据来源和证据等级；不可凭空贬低竞品（如用"骗局""骗子"等词）；对比维度必须统一，方便 P3-02 自动生成反驳话术
- **格式**: 竞品对比矩阵（Markdown 表格）

### P2 产品引擎域

**域级说明**：P2 域是管线中的**最高校准密度域**——产品定义和定价直接影响全盘，两个校准点（P2-01 产品策略审核、P2-02 定价审核）必须人工确认。P2-03 不需要校准点。

#### P2-01 产品线定义与渠道匹配

- **必选组件**: 五类产品线定义（名称/规格/目标人群/核心卖点/差异化定位）、每线渠道匹配（渠道名称/匹配逻辑/进入策略/预期量级）
- **五类产品线**:
  1. 主粮（B端原料/医院营养食堂入口）
  2. 主食（服务包嵌入/配合动态血糖仪绑定销售）
  3. 冲调粉（价格锚点赠品/出门便携场景）
  4. 快消品（方便面/曲奇/桃酥/私域+达人带货）
  5. 服务包（整合交付/卖14天血糖达标的结果）
- **可选组件**: 产品线生命周期阶段评估、新市场产品线适配方案
- **组装顺序**: 产品线逐一生成→核心卖点推导（基于知识库的因果链和竞品矩阵）→渠道匹配（基于每线特征和渠道结构）→校准点：人工审核后进入 P2-02
- **约束**: 每条产品线的卖点必须有知识库中的因果链支撑；渠道匹配不是"想当然"——必须考虑渠道结构（医院走营养科/药房走服务包绑定/私域走内容种草）；**🔶校准点：人工审核产品线定义和渠道策略是否合理**
- **格式**: 产品矩阵文档（Markdown 表格 + 说明）

#### P2-02 服务包设计与定价

- **必选组件**: 七维度服务包定义（名称/目的/评估系统/治疗方法/疗法组合/价格体系/工作流程）、价格锚点体系（赠品锚定逻辑+梯度定价+C端三档+B端底价+拆价规则）
- **七维度内容**:
  - 名称："14天快速稳糖健康教育管理服务包"（不含"产品"二字，卖教育/卖结果）
  - 目的：14天内空腹+餐后血糖达标（量化结果，不是过程描述）
  - 评估系统：空腹血糖/餐后血糖/24h动态血糖/TIR
  - 治疗方法：运动+补充膳食纤维+改变饮食结构/饮食顺序
  - 疗法组合：动态血糖仪+7天主食+冲调粉赠品+在线教育课程
  - 价格体系：C端298(体验)/498(标准)/980(进阶)，B端底价3000可拆
  - 工作流程：入组→CGM佩戴→每日自管→第7/14天评估→达标判定
- **可选组件**: 成本测算明细、竞品服务包价格对比、不同渠道的定价策略差异化
- **组装顺序**: 七维度逐一填充→价格锚点推导（成本→锚点→售价逻辑链）→阶梯定价表→**🔶校准点：人工审核定价和服务包可交付性**
- **约束**: 价格锚点必须有成本测算依据；效果承诺不得夸大（"14天达标"必须可验证）；服务包名称不出现"产品""治疗""治愈"等字样；工作流程必须有 AI 可自动执行的明确步骤
- **格式**: 服务包规格书（Markdown + 定价表格）

#### P2-03 验证闭环设计

- **必选组件**: 验证方案（样本量/入排标准/干预方案/评估指标/数据采集方式）、市场规模论证（1亿+确诊×5亿糖前期=万亿市场叙事）、战略切入逻辑（"为何从糖尿病切入"）

- **组装顺序**: 验证闭环设计（基于 P2-02 服务包规格）→市场规模论证（基于 P1-01 流行病学数据）→战略叙事整合
- **约束**: 验证方案必须可被 P4 验证引擎自动化执行（不依赖人工点评）；市场规模数据必须引用可验证来源；"万亿市场"叙事不可夸大——标注计算逻辑和假设
- **格式**: 验证方案 + 市场规模论证（Markdown）

- **可选组件**: 销售情景模拟脚本、客户异议分类和应对矩阵
- **组装顺序**: 开场白生成→价值主张提炼（基于产品核心卖点）→FAQ构建（基于竞品矩阵和常见反对）→竞品反驳话术（引用竞品矩阵每条缺陷的证据）→送入 P3-03 合规校验
- **约束**: 开场白不含夸大词（"最好""唯一""100%"）；竞品反驳不贬低人格，仅机制层面客观对比；FAQ 必须覆盖至少 10 个常见问题；每条反驳话术可追溯到竞品矩阵的具体条目
- **格式**: 话术库（Markdown 表格 + 情景对话）

#### P3-03 合规守护

- **必选组件**: 每条 P3 输出的合规校验结果（通过/拒绝/修改）、违规项的具体标注和修改建议
- **校验规则**:
  - 食品宣称边界：不得出现"治疗""治愈""逆转""药品"等医疗宣称词
  - 广告法第17条：非药品不得涉及疾病治疗功能
  - 平台规则：抖音健康科普规范/小红书医疗内容审核规则/微信视频号健康类规范
  - 竞品对比：不得贬低竞品人格（"骗局""骗子""忽悠"），仅限机制层面客观对比
  - 患者材料：必须标注"本品为食品，不可替代药物""请遵医嘱"
  - 医生材料：不可做疗效承诺，仅限机制论证和文献引用
- **可选组件**: 合规风险分级（高风险→人工复核 / 低风险→自动通过）、合规趋势预警（新法规/新平台规则摘要）
- **组装顺序**: 逐条规则匹配→违规标记→修改建议→输出最终版本
- **约束**: **不可跳过**——P3-01 和 P3-02 的所有输出必须通过 P3-03 校验；高风险的违规项（涉及疗效宣称/法律红线）必须硬拒绝而非软标记
- **格式**: 合规校验报告（Markdown 表格，每条输出×每条规则的通过/拒绝矩阵）

### P4 验证引擎域

**域级说明**：P4 域为半自动域——正常数据流全自动，严重异常触发人工审核校准点。P4-02 依赖 P4-01 的完整数据。

#### P4-01 患者数据监测与分析

- **必选组件**: CGM 数据采集接口、实时分析指标（空腹血糖/餐后峰值/血糖波动幅度/TIR达标时间占比）、异常检测规则（血糖<3.0mmol/L告警/餐后不降反升趋势/3天连续无改善/夜间持续低血糖）、自动推送建议（膳食纤维增量方案/饮食顺序调整/运动建议）
- **可选组件**: 长期趋势分析（月度/季度 HbA1c 估算）、群体分层分析（按病程/年龄/用药分组）
- **组装顺序**: CGM 数据接入→实时分析管道建立→异常检测规则配置→自动推送模板设定→**🔶校准点：严重异常告警（血糖<3.0/持续不降/不良反应）暂停等待人工判定**
- **约束**: 数据采集必须连续（目标 ≥95% 数据完整度）；异常告警必须实时（延迟不超过 5 分钟）；自动推送建议不得替代医疗决策——严重异常必须等待人工判定；患者数据的隐私保护（去标识化存储）
- **格式**: 实时数据仪表盘 + 异常告警日志（Markdown 摘要 + JSON 数据）

#### P4-02 验证证据生成

- **必选组件**: 个人级报告（14天空腹/餐后血糖变化曲线/达标判定/改善建议）、批量级报告（N人前后对照统计/达标率/平均改善幅度/各病程分层的效果差异）、B端验证证据包（批量数据摘要/典型个案/对比图表，用于合作谈判）
- **可选组件**: 统计显著性检验（配对 t 检验/效应量 Cohen's d）、可视化图表（血糖变化瀑布图/达标率漏斗图）
- **组装顺序**: 个人报告自动生成→批量统计汇总→B端证据包封装→数据去标识化
- **约束**: 报告中的数据解读不得超出 CGM 数据能支持的范围（如不能从 7 天数据推断"糖尿病已逆转"）；B端证据包的去标识化处理必须彻底（不可追溯到个人）；统计方法必须透明标注
- **格式**: 验证报告（Markdown + 图表 + PDF可导出）

### P5 销售激活域

**域级说明**：P5 域中的 P5-01 有人工校准点（关键合作决策），P5-02 全自动收集反馈。

#### P5-01 销售管线激活

- **必选组件**: 销售材料生成（基于产品定义+验证证据的个性化方案书）、管线追踪（意向→验证→谈判→签约四阶段，自动状态更新）、自动化跟进（定时推送验证数据/发送同类案例/续约提醒）、客户问答自动应答（基于 P3-02 话术库的 FAQ 匹配）
- **可选组件**: 销售转化漏斗分析（各阶段转化率/平均周期/瓶颈识别）、客户分群（医院/药房/体检中心/供应链的差异化策略）
- **组装顺序**: 销售材料生成（按客户画像定制）→管线建立→自动跟进定时器启动→**🔶校准点：人工决策关键合作（选择哪个合作伙伴/接受什么条件/是否给价格例外）**
- **约束**: 销售材料中的疗效数据必须来自 P4-02 已验证的证据包，不可编造；自动跟进频率不得骚扰客户（建议每周不超过 2 次触达）；关键合作决策不可由 AI 替代——涉及商业判断和风险承担
- **格式**: 销售管线仪表盘 + 材料包（Markdown + PDF）

#### P5-02 市场反馈闭环

- **必选组件**: 反馈收集渠道（拒绝原因/竞品对比反馈/需求变化/价格敏感度）、信号分析（聚类拒绝原因→识别产品/价格/渠道/话术的问题）、触发动作（价格问题→反馈到 P2-02 / 话术问题→反馈到 P3-02 / 竞品新动态→触发 P1-01 增量扫描 / 需求变化→触发 P2-01 策略调整）
- **可选组件**: 反馈信号趋势追踪、NPS 估算
- **组装顺序**: 反馈收集→信号聚类→问题归类→触发对应基元的更新动作
- **约束**: 反馈信号的触发阈值必须明确（如 "同类型拒绝≥3次"触发分析）；反馈闭环不得无限循环——单次更新后需给定观察期（至少 1 个月）再启动下一轮
- **格式**: 反馈分析报告（Markdown 表格 + 行动建议）

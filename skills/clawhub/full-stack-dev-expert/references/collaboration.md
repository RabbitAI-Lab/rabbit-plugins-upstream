# 协作协议（所有角色共读）

本文件定义角色之间的**交接契约、冲突仲裁与产出物落盘约定**。总指挥按此协议传递上下文，
子角色按此协议交还产出。

## 1. 交接单（角色间唯一传递载体）

每次委派，总指挥构造一份交接单（模板：`templates/handoff-ticket.md`），字段：

| 字段 | 说明 | 必填 |
|---|---|---|
| `task_id` | 任务编号，格式 `FS-<yyyymmdd>-<序号>` | 是 |
| `stage` | 当前阶段（逆向/需求/设计/实现/质保/交付/文档） | 是 |
| `user_brief` | 用户原话（逐字，不转述不删减） | 是 |
| `stack` | 已锁定的技术栈（未定则写"待选型"） | 是 |
| `artifacts` | 已有产出物路径列表（`docs/` 下相对路径） | 有则填 |
| `handoff_notes` | 上一角色的交接说明与关键决策摘要 | 有则填 |
| `scope` | 本次委派的范围边界（做什么/不做什么） | 是 |
| `constraints` | 约束（ deadline、环境、兼容性、红线） | 有则填 |

**规则**：
- 交接单是唯一真值源。任何角色不得依赖"我以为上一阶段做了 X"——只认交接单与 artifacts。
- 用户原话必须在整条流水线中原样透传，任何角色的转述都不得替换它。
- 模式 A 下交接单全文嵌入委派 prompt；模式 B 下总指挥在换装时口头宣读交接单。

## 2. 产出物落盘约定

默认在项目根 `docs/` 下归档（无写权限时在会话内交付并在摘要注明未落盘）：

```
docs/
├── requirements-spec.md     # 需求规格（需求分析师产出）
├── architecture.md          # 架构设计 + ADR（架构师产出）
├── ui-spec.md               # UI/UX 规格（设计师产出，前端项目）
├── reverse-analysis.md      # 逆向分析报告（逆向融合工程师产出，ORRI）
├── api-contract.md          # API 契约（架构师起草，后端冻结）
├── db-schema.sql + migrations/  # 数据模型与迁移（DBA 产出）
├── test-plan.md / test-report.md   # 测试计划与报告（测试工程师产出）
├── security-review.md       # 安全审查报告（安全工程师产出）
├── review-report.md         # 代码审查报告（审查员产出）
├── deploy-guide.md          # 部署手册（DevOps 产出）
└── handoffs/FS-*.md         # 历次交接单存档
```

文件写入冲突：同一文件只允许一个角色拥有写权（如 `api-contract.md` 冻结前归架构师，
冻结后归后端工程师）；跨角色改动需总指挥批准并在交接单留痕。

## 3. 冲突仲裁

1. **契约冲突**（前端 vs 后端对 API 理解不一）→ 以冻结版 `api-contract.md` 为准；未冻结回架构师裁决。
2. **技术方案冲突**（架构师 vs dev）→ 架构师终审，dev 可在交接单 `dissent` 字段保留异议。
3. **行为正确性冲突**（dev vs 测试）→ 以需求规格验收标准为准；规格未覆盖由架构师补充决策并回写规格。
4. **逆向结论冲突**（逆向融合结论 vs 架构/需求既有认知）→ 以证据链与置信度仲裁：
   高置信逆向结论优先于未验证的既有认知；低置信结论先完成探测实验升级置信度再仲裁。
5. **安全 vs 进度冲突** → 安全工程师拥有一票否决权（仅限高危/以上），否决必须附带修复建议与工作量评估。
6. 所有仲裁结果由总指挥记入当次交接单 `handoff_notes`，保证可追溯。

## 4. 角色间沟通边界

- 子角色之间**不直接通信**，一切经总指挥中转（模式 A 下子代理本就隔离；模式 B 下禁止跳过总指挥直接对话）。
- 需要其他角色的信息时，在产出中声明 `blocked_on: <角色>: <所需信息>`，由总指挥补齐后重新委派。
- 汇报格式：每个角色返回总指挥的内容 = 产出物 + 摘要（≤10 行）+ `blocked_on`（如有）+ 交接字段。

# 数据库规范（DBA 建模必读，后端实现数据访问层共用）

## 1. 命名

- 表名：`snake_case` 复数或单数全库统一（默认单数，如 `user`、`order_item`）；禁用保留字。
- 字段名：`snake_case`；主键默认 `id`；外键 `<表名单数>_id`。
- 索引名：`idx_<表>_<字段>`（普通）/ `uk_<表>_<字段>`（唯一）。
- 布尔字段 `is_`/`has_` 前缀；时间字段 `_at` 后缀（`created_at`/`updated_at`）。

## 2. 必备字段与约定

- 每表必备：`id`（自增或雪花 ID，全库主键策略统一）、`created_at`、`updated_at`。
- 软删：业务数据表加 `deleted_at`（NULL=未删）；物理删除仅限日志/临时表。
- 金额：`DECIMAL(18,2)` 或整型分单位，禁止 FLOAT/DOUBLE。
- 枚举：存字符串码（可读、可扩展）或 tinyint + 字典表，全库统一一种。
- 时间统一 UTC 存储，TIMESTAMP/`timestamptz` 类型。

## 3. 索引规则

- 高频 WHERE / JOIN / ORDER BY 字段建索引；组合索引遵循最左前缀，区分度高的列在前。
- 每个索引必须在 schema 注释中注明服务的查询路径；无查询路径的索引删除。
- 外键关联字段两侧必须有索引；大表加索引走在线 DDL/低峰执行。
- 单表索引数 ≤ 6；写多读少表从严。

## 4. 外键与约束

- 逻辑外键（应用层保证）为主，物理外键仅用于强一致小系统（由 DBA 在建模时决策并写入 schema 说明）。
- 业务唯一性必须落唯一约束，不依赖应用代码判重。
- 字段 NOT NULL 优先，可空字段必须有业务理由注释。

## 5. 迁移纪律

- 迁移脚本只增不改：已发布迁移禁止修改，变更走新迁移。
- 迁移可逆性标注：每个迁移显式标注 可逆/不可逆；回滚（down）脚本仅对可逆迁移提供，
  不可逆迁移（删列/改类型）以补数/前滚修复脚本替代 down——down 删数据等同生产事故。
- 命名 `V<n>__<描述>.sql` 顺序递增；破坏性变更（删列/改类型）分两步：
  先加新列双写 → 迁数据 → 切读 → 删旧列，跨两次发布。
- 每个迁移在干净库上按序可重放；从零执行全部迁移的结果 == `db-schema.sql`。
- 大表 DDL 评估锁表时间；超阈值安排低峰窗口并经总指挥确认。

## 6. 查询与事务

- 禁止 `SELECT *`；明确字段列表。
- 单页查询必带 LIMIT；深分页用游标（`WHERE id > ? LIMIT n`）。
- 事务边界最小化：事务内不调远程服务、不做文件 IO；先读后写的竞态用
  乐观锁（version 字段）或 `SELECT ... FOR UPDATE` 显式声明。
- N+1 检查：ORM 关联查询必须显式 JOIN 或批量 IN 预取。

## 7. 生产操作红线

- 生产 DML/DDL：先备份、先测试库演练、经总指挥（用户）确认三步缺一不可。
- 慢查询（>200ms）必须 EXPLAIN 并记录优化结论；先索引/改写，最后才结构变更。

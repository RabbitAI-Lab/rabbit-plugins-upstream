# ppshu HTML 画图手册

本技能产出的每张图都是一个**单文件 HTML**（自包含、可离线打开、双击即用）。
目标是：用最少的代码，做出「能看懂、能交互、好看」的图。

## 1. 单文件铁律

- **不要引入外部 CDN 依赖**（不写 `<script src="https://...">`、不写外链 CSS）。
  用户可能离线打开，外链一挂整张图就废了。
- 需要图标/字体时，优先用 Unicode（🛠️ ✅ ⚠️ →）或内联 SVG。
- 数据、样式、脚本全部内联在同一个 `.html` 文件里。

## 2. 主题与配色

- 默认做**深色主题**（`background:#0f1115; color:#e6e6e6`），与 WorkBuddy 暗色 IDE 一致。
- 在 `<style>` 顶部加 `:root { color-scheme: dark; }`，避免系统强制浅色把文本洗白。
- 文字与背景必须保证对比度；不要用纯黑配纯白以外的「优雅」灰导致看不清。
- 若用户明确要求浅色，再切换。
- 色彩语义（尤其金融场景）：**涨=红，跌=绿**（A 股习惯），除非用户另有要求。

## 3. 画图方式选型

| 需求 | 推荐 |
|------|------|
| 流程图 / 架构图 / 状态机 | 内联 **SVG**（`<svg viewBox="0 0 680 ...">`），节点用 `<rect>`+`<text>`，连线用 `<path>`/`<line>` |
| 折线 / 柱状 / 饼图 | 内联 **Canvas** + 少量 JS，或手画 SVG `<path>`；数据量小优先 SVG（易调试） |
| 表单 / 原型 / 可操作 UI | 普通 HTML + `<input>/<button>` + JS 事件 |
| 布局 / 卡片 | 普通 HTML + CSS flex/grid |

## 4. 交互要点

- 用原生 JS 即可，**不需要框架**。少量 `addEventListener` + `dataset` 足够。
- 给可点击元素明显的 hover / active 反馈（颜色、光标 `cursor:pointer`）。
- 复杂状态用 `let state = {...}` 维护，交互后 `render()` 重绘，避免散落的直接 DOM 改动。
- 图表交互优先做**悬浮提示（tooltip）**和**图例筛选**，性价比最高。

## 5. 可读性技巧

- 用 CSS 变量统一颜色：`--bg / --fg / --accent / --ok / --warn`。
- 图表加标题、坐标轴标签、单位；空数据要有占位提示。
- 长数字用 `toLocaleString()` 或千分位格式化。
- SVG 文本设 `font-family` 显式声明，避免系统字体差异导致错位。

## 6. 尺寸与响应式

- 根容器 `max-width: 920px; margin: 0 auto;`，手机也能看。
- 图表用 `viewBox` 做等比缩放，外层 `width:100%`。
- 关键断点：`@media (max-width: 600px)` 时把横向布局改纵向。

## 7. 决策 / 分支流程图 → 用 Mermaid（不要手写 SVG 坐标）

**重要结论**：带判断、分叉、汇合、回环的流程图，**禁止手写 SVG + 路径坐标**。手算每条连线的 `M x,y V y2 H x2` 极易出错（交叉、箭头反向、标签压线），且节点一挪全线歪——我们实测翻车两次。

**正确做法：写声明式 Mermaid 代码，让 Mermaid 自动布局。**

- 直接用技能里的模板 `references/mermaid_flowchart_template.html`：把标题/副标题填好，把 Mermaid 代码粘进 `<div class="mermaid">` 即可。
- Mermaid 语法极简：
  ```
  graph TD
      A[开始] --> B[看天气预报]
      B --> C{下雨?}
      C -->|否| D[不带伞]
      C -->|是| E[带伞出门]
      D --> F[出门]
      E --> F
      F --> G[结束]
  ```
  `[]` 处理框、`{}` 判断菱形、`-->|标签|` 带标签连线、`TD` 自上而下。布局、箭头、是/否分叉全自动。
- 方向可选：`graph TD`（上→下）、`graph LR`（左→右）、`graph TB` 等。
- 深色主题：`mermaid.initialize({ theme: 'dark' })`（模板已含）。

**离线可用（已形成闭环）**：Mermaid 库（`mermaid.min.js`，约 3.3MB）已**随技能打包**进 `assets/`。保存流程图时，`save_html.py` 会自动把它复制到目标 `.ppshu/` 目录，模板用 `./mermaid.min.js` 本地引用——**完全离线、不依赖任何 CDN、国内也不会被墙**。所以：
- 流程图类（分支/判断）→ 用 Mermaid，且离线可用。
- 信息图 / 卡片 / 可交互原型 / 图表 → 仍用纯单文件 SVG+Canvas+CSS，保持离线。
- 两类都满足「双击即开、无需联网」这一总目标。

> 之前手写 SVG 菱形那套已废弃，仅适合「极简单线、无分叉」的示意图；凡有判断分叉，一律 Mermaid。

## 8. 代码/文本对比 → 用 diff_report.py 生成器（不手写 diff 页）

「对比两份文件、做 diff 审查报告」这类需求（代码 diff、API 前后对比、配置 vs 默认值），
**不要手写 diff 渲染代码**——用技能自带的生成器 `scripts/diff_report.py`，一条命令出报告：

```bash
python "<skill_dir>/scripts/diff_report.py" -a old.mjs -b new.mjs -o report.html
python "<skill_dir>/scripts/save_html.py" "xx 代码 diff 审查报告" --file report.html
```

**它输出什么**（深色主题，和 WorkBuddy 暗色一致）：
- **双栏等宽 + 行号对齐**（左旧右新）：新增行浅绿、删除行浅红；
- **每行带 `+` / `-` 符号标记**（修改行两侧同标：旧侧 `-`、新侧 `+`）；
  单侧缺失（纯新增 / 纯删除）时，**另一侧真正留空**（空占位保持行高对齐），一眼看出左右哪边没有对应行；
- **差异块导航胶囊**：顶部「块 1 / 块 2 / …」点击跳转，长 diff 不迷路；
- **「只看改动」开关**：一键折叠未改动行，聚焦增量；
- **自适应全宽布局**：报告随预览窗口一起伸缩；拉宽页面时两栏会继续展开，减少不必要的横向滚动；
- **SHA-256 标注**：两个文件的哈希内嵌显示，读者可自行复算核对——结论不是作者编的；
- **底部三栏**「我们做的 / 自动化验证 / 不变底稿」：可点击编辑，汇报时填写成果边界。

**使用要点**：
- `-a`/`-b` 必填；`--name-a/--name-b` 可覆盖显示名；`-c N` 调上下文行数（默认 3）。
- 哈希约定：按 **LF 归一化**后计算，跨平台可复算（页面已注明）。
- 适用场景：review / 审查 / 对比 / 数据核实这类「结论要有说服力」的场合；
  纯概念示意图用不上这套，别杀鸡用牛刀。
- 内嵌数据若含 `</script>`（比如对比的是 HTML 源码），生成器会自动转义为
  `<\/script`，浏览器解析后还原——此坑已修，无需手动处理。

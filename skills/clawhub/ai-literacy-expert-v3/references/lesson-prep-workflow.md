# 第三部分：帮助老师备课 · AI 协作备课工作流（参考）

> 本文对应课程大纲「第三部分」与最佳实践文档《AI 协作备课工作流：从课程体系设计到内容交付的最佳实践》。
> 原文链接：https://bytedance.larkoffice.com/docx/QoljdFDBAouTFCx3L7JcVw3RnKe

## 一、这份工作流解决备课最头疼的三件事
1. **省时间**：不用再花 40+ 小时死磕，把 AI 从"会跑偏的写手"变成"守规矩的执行者"。
2. **保一致**：多节课术语统一、不重复不越界、读起来像一个人写的（统一隐喻、统一框架）。
3. **易适配**：跨专业换案例不用重做全课（用"约束文件 + 占位符"实现案例热插拔）。

## 二、核心理念
- **老师的价值不在"写"，而在"判断"**——定方向、把边界、判好坏，剩下的交给 AI。
- 配套"共性约束文件 + 各课交付要求 + 内容框架 + 课程内容文档 + PPT 逐字稿"，本身就是一套可复用的沉淀资产（呼应 C5 飞轮）。

## 三、六个具体机制（关键抓手）
> 注：以下为基于课程体系的归纳，落地细节建议结合上方原始文档。

1. **约束文件（Constraints File）**：把全课程的术语表、隐喻、边界红线、引用规范写成一份文件，每次生成都注入——保证多节课"像一个人写的"。
2. **进度文件（Progress File）**：记录每课已确认的方向、决策点、待办，避免重复讨论、跨课冲突。
3. **横评审查（Cross-Review）**：多课之间做一致性审查（术语/边界/案例不打架），可借鉴 C4 的"交叉审查"思路（第二个 AI 审第一个 AI，但终审在人）。
4. **Demo 热插拔**：Demo 用"方法论骨架 + 任务场景占位符 + 评判标准"描述，换专业时只换场景示例、不动骨架。
5. **结构化产出模板**：每课统一用「内容框架 → 课程内容文档 → PPT（截图版/可编辑版）→ PDF」四件套，降低交付门槛。
6. **分阶段推进（阶段一探索 / 阶段二创作）**：先锁定方向、结构、案例（阶段一），再填充内容（阶段二），重大决策点人工拍板。

## 四、30 分钟最小落地清单（给想立刻开课的老师）
1. 选定要讲的单元（建议从 A3 协作哲学 + C 系列方法论起步）。
2. 套用本技能的 `references/` 参考文档作为内容骨架。
3. 打开对应单元的 PPT（截图版，含逐字稿）作为授课底稿。
4. 用"约束文件"统一术语（Architect/Executor、飞轮、锯齿边界、施工图纸）。
5. 选 1 个专业案例，做 Demo 热插拔。
6. 用阶段一"决策点 + 待确认项"清单做最后校准。

## 五、与模块 C 的方法论呼应
- 备课本身 = 一次 Architect 工作流：拆解课程（C2）→ 验证内容准确性（C3）→ 多 Agent 协作生成（C4）→ 沉淀为可复用模板（C5）。
- "约束文件"本质是 C5 第 1 级 Rules 在课程开发场景的应用；"横评审查"是 C4 交叉审查的变体。

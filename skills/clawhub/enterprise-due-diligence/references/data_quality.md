# 无 API 数据校验策略（数据质量五规则）

> 适用场景：用户无企查查/爱企查/天眼查等开放平台 API（QICHACHA_TOKEN 未配置、连接器未连接）时，如何保证尽调报告数据准确、可追溯。
> 本规则基于 2026-08 多个真实企业尽调案例实战验证（实缴资本、参保人数、法定代表人、企业主体名称等均出现过多平台数据不一致问题）。

## 一、问题形态（先分类，再对症）

| 形态 | 特征 | 实例 |
|---|---|---|
| ① 多源口径差异 | 同一字段不同平台值不同 | 某公司实缴资本在不同平台显示值不同 |
| ② 字段缺失 | 某平台不展示某字段 | 爱企查普通版工商信息页无「实缴资本」 |
| ③ 单源错误 | 单个平台数据错误 | 某平台显示法定代表人 A vs 上市公司公告 B |
| ④ 主体识别 | 用户口述名 ≠ 注册名 | 用户口述「某省XX公司」 vs 实际注册名「某市XX公司」 |

## 二、五规则

### 规则 1：多源轮询（补字段缺失）
- 关键字段至少取 **2 个以上**网页源交叉：企查查网页 / 爱企查 / 天眼查 / 启信宝 / 水滴信用 / 爱诺特（innotop）。
- 某平台不显示的字段**换平台获取**：如实缴资本，爱企查简版没有 → 查启信宝/水滴，或请用户截「工商注册详情页」（爱企查普通版仅在工商注册详情页展示实缴）。

### 规则 2：权威裁决（治单源错误）
数据源信任级（冲突时高级别胜出）：
```
上市公司公告 / NMPA注册证号 / 国家企业信用信息公示系统(gsxt)
  > 启信宝 / 爱企查 / 天眼查 / 水滴信用
  > 行业媒体（动脉网/投融湾/南方+ 等）
  > 用户口述
```
- 判例：某平台显示「法定代表人：A」，与上市公司公告「法定代表人：B」冲突 → 以公告为准，报告标注差异来源。

### 规则 3：时间戳优先（治口径差异）
- 同一字段取**最新变更记录**并注明时点：例如实缴资本以最近一次工商变更后的金额为准，历史金额标注为旧口径。
- 报告呈现：**多值并存 + 时点标注**，不静默覆盖。示例：「实缴资本 X 万元（甲平台 2026 年口径）；此前乙平台 2025 年变更记录显示 Y 万元」。

### 规则 4：用户截图兜底（无 API 最强武器）
- 遇到关键字段缺失/冲突时，**主动生成优先级「请截图清单」**：
  1. 历史信息 / 变更记录页（验证曾用名、法人变更）
  2. 工商注册详情页（实缴资本、登记机关、营业期限、行业）
  3. 股东信息页（认缴/实缴出资明细、出资日期）
  4. 知识产权页（专利/商标/软著状态）
  5. 主要人员页（工商备案董监高）
  6. 司法风险 / 行政处罚 / 经营异常页
  7. 企业图谱 / 关联企业页（直接股东、实控人追溯）
- 截图数据按技能规则「用户提供 > 公开数据」采纳，**标蓝** + 标注「来源：用户提供XX截图，时间戳」。
- 截图内数据仍需与公开来源交叉（防过期/防误读）。

### 规则 5：必核字段红标（判不了就明示）
- **必核字段清单**：实缴资本 / 法定代表人 / 参保人数 / 注册资本 / 历史名称 / 股东出资明细 / 司法风险 / 行政处罚。
- 必核字段无 2 源 → 报告中标红「待核实」，**不臆断、不填默认值**。
- 修订规范：新增/修正标蓝（#0000FF）、存疑/待验证标红（#EE0000）、每条数据带来源+时间戳。
- 免责声明列出全部「待验证清单」及需补充的一手材料（工商内档、审计报告、银行流水、NMPA 查询、访谈）。

## 三、生成前自检清单（AI 出报告前过一遍）

- [ ] 每个必核字段是否 ≥2 源？
- [ ] 多源冲突是否已按权威级裁决并标注差异？
- [ ] 数值类字段是否标注了数据时点（最新变更记录）？
- [ ] 无法判定的字段是否标红「待核实」而非臆断？
- [ ] 主体名称是否与公开注册名核对过（防「省/市」名称差异）？
- [ ] 数据来源清单是否逐条可追溯（平台+更新时间）？

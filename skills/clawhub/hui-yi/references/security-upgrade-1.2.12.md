# Hui-Yi 1.2.12 安全升级与验证记录

审计日期：2026-09-23。来源：[ClawHub v1.2.11 安全审计](https://clawhub.ai/fuetsui/skills/hui-yi/security-audit)，页面所示扫描时间为 2026-09-16 04:49 UTC。

本记录描述 1.2.12 阶段的本地修复及验证，不代表 ClawHub 已重新扫描或批准。安装来源记录保持原样；当前本地源版本以 `manifest.yaml` 为准。

## 确认的问题与修复

独立审阅覆盖旧版 37 个源代码、配置和说明文件，排除对应源码已审阅的 Python 缓存。确认两项安全问题：

1. **中风险，CWE-59：文件系统链接越界。** TypeScript hook 仅做词法路径限制；符号链接或 Windows junction 可将笔记读写重定向到归档外。Python 的直接目录枚举、固定元数据和日志读写也存在同类未检查路径。前提是攻击方能在归档中放置链接，且运行账户有外部目标访问权；普通聊天文本本身不足以利用。
2. **低风险，CWE-532：日志过度留存。** 默认 hook 日志虽然删除完整 query，仍保留候选标题、路径、匹配词，以及可能包含身份标识的 channelId 回退值。未发现网络外传实现。

`core/safe_fs.py` 与 `templates/hook/safe-fs.ts` 统一执行祖先及叶节点检查，拒绝符号链接、junction/reparse、硬链接、特殊文件和含歧义的 Windows 路径。读取核验文件描述符身份。Python 写入使用排他创建的同目录临时文件、flush/fsync、身份复查和原子替换，Windows 下先复制并核验原有 DACL 再写入数据。TS 在 POSIX 及 Windows 新文件上使用暂存原子替换；Windows 已有文件通过核验后的描述符原位更新，保留 DACL，并在一般 I/O 失败时尽力恢复原字节，此分支不保证崩溃原子性。笔记只允许普通 `.md`，不能指向索引、检索日志或模板。固定的 tags、index、备份、heartbeat、hook 日志及安装目标同样受检。批量修改先检查目标，避免静态恶意条目在前一条写入后才被发现。

hook 只接受可信宿主元数据明确选中的 Hui-Yi，或映射正文 `context.body` 起始位置的 `/hui-yi <query>`、`/hui_yi <query>` 显式调用。空命令、引文、正文嵌入和仅存在于 `bodyForAgent` 的命令都不能授权写入。取消聊天关键词自动回退；debug 也不记录消息、原始身份、任意元数据、标题、路径或匹配词。Python detector/pipeline 默认隐藏 query、原始 session 和 overlap；需要敏感诊断时必须显式使用 `--include-sensitive`，且始终不返回原始 session key。adapter/probe 只输出状态、计数和哈希，支持 `--stdin`，probe 不再创建子进程或打印命令行。

本机 OpenClaw 2026.9.5 的原生 `message:preprocessed` mapper 不发出 skill-selection 字段，正文也可能带渠道封装；部分原生命令会在事件前被消费。因此不能把“hook 已加载”当成普通对话自动强化已运行。已用原生 mapper 的无 selection、纯正文事件形状验证显式命令。带封装正文或提前消费命令的渠道须使用明确的 CLI/可信适配器调用；本次没有向真实渠道发送测试消息。

未改动 repetition-first 权重、真实会话强化含义、去重规则和 `[1, 2, 4, 7, 15, 30, 60]` 复习梯度。修复了替代 `--memory-root` 下默认 heartbeat/schedule 仍指向原始工作区的问题。

## 验证

- **旧版复现：** 同一 Windows junction 测试对原始 hook 失败，观察到归档外模拟笔记的 Session signals 被改写；没有使用真实用户记忆。
- **TypeScript：** `node --experimental-strip-types --test tests/hook_security.test.mjs`，17 项全部通过，无跳过。覆盖正常嵌套中文笔记、去重、默认/调试日志、非选中会话、显式命令与拒绝边界、叶/祖先/根链接、tags/log、断链、硬链接、路径变体以及校验后替换。
- **Python：** `python -X utf8 -B -m unittest discover -s tests -v`，48 项中 47 项通过，仅 POSIX FIFO 用例在 Windows 跳过。覆盖相同文件边界、隐私、失败退出码、替代目录、安装配置保留、建档→重建→真实 smoke 子进程、复习梯度和强化去重。Windows junction、硬链接、8.3 别名、Python 受保护/继承/自动继承 DACL，以及 TS 已有文件 DACL 保留均在本机实际执行通过。首次部署的权限检查安全拒绝了自动继承标记丢失；保留完整 ACE 与控制标记后，用真实源文件 ACL 派生的隔离样本复验通过。
- **Skill 元数据：** 通过 `skill-creator/scripts/quick_validate.py`。Windows 使用 `python -X utf8 -B`，避免验证器默认 GBK 解码 UTF-8 说明。
- **独立补丁复审：** 发现并补强了 Windows DACL 保留、TS 检查与写入目标一致性、可信 CLI 的父级相对路径兼容性，以及 Windows 8.3 保留文件别名限制；每项分别添加实际行为回归。没有把同账户恶意并发目录替换误称为已解决的内核隔离。

## 明确边界

- 便携式文件 API 不是内核沙箱。工作区及父目录必须由可信 OS 账户管理；不保证抵抗同账户恶意进程在最后一次检查后并发替换目录。已覆盖检查与写回之间的确定性替换测试，不能将其表述为穷尽所有竞态。
- 暂存替换不等于笔记和 tags 的跨文件事务；Windows TS 对已有文件的保权限原位更新也不具备崩溃原子性。电源故障、磁盘错误或并发外部维护仍可能需要显式重建。
- 一个 workspace 共享一个归档；session 哈希用于去重，不实现租户权限隔离。
- 用户主动检索的输出可能包含笔记标题、路径和正文。反馈参数 query/action 可写入归档内 `retrieval-log.md`，因此该日志应按记忆数据管理。
- 真实 Gateway 中的宿主事件形状、跨渠道完整会话及远端 ClawHub 重审不由离线测试证明。
- 本记录在 1.2.12 修复阶段生成时尚未发布到 ClawHub，也未调用其 Rescan。后续版本发布不等于外部重新审计通过，不能承诺外部启发式扫描器不再产生告警。

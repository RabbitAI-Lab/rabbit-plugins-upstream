## 代号前缀约定（防撞号，引用时务必带前缀）

| 前缀 | 含义 | 范围 |
|---|---|---|
| **D1–D6** | **通用维度**（所有产物必跑） | 残留 / 真实 / 一致 / 完整 / 合规 / 适配 |
| **W1–W9** | 文档类专属 | 见第四部分 |
| **C1–C8** | 数据类专属 | 见第三部分 |
| **L1–L7** | 合规类专属（见 `compliance.md`） | 极限词(中文·广告法) / 密钥 / 隐私 / 版权 / 行业承诺 / 敏感表述 / 极限词(英文·FTC) |

## 第一部分：六个通用维度（所有产物必跑）

### D1 · 残留度（Residue）

**查什么**：AI 把"生成过程"混进了"交付物"。

**方法**：套用 `rules-residue-zh.md` 全量规则，按场景启用到对应级别。

**判定**：RL1 级规则命中 → 必改项；RL2 级 → 视密度；RL3/RL4 → 可改项。

**severity**：error（RL1）/ medium（RL2）/ low（RL3+）

---

### D2 · 真实性（Veracity）— 严重度最高

**查什么**：产物中的断言是否与客观事实一致。这是**造成真实损失最多**的一层。

**检查项**：

| # | 检查 | 方法 | 判定 |
|---|---|---|---|
| 2.1 | 数字前后矛盾 | 提取全文数字，交叉比对 | 同一指标出现两个值 → error |
| 2.2 | 时间线冲突 | 提取日期与事件序列 | 结果早于原因 → error |
| 2.3 | 引语与出处 | 逐条联网核实 | 核实失败 → 存疑项；确系编造 → error |
| 2.4 | 数据无来源 | 「据 XX 显示」类断言 | 无出处 → 存疑项 |
| 2.5 | 人名/机构张冠李戴 | 核对归属 | → error |
| 2.6 | 章节/页码/编号引用错误 | 核对目录与正文 | → error |
| 2.7 | API / 依赖是否真实存在 | 查包仓库或文档 | 不存在 → error（幻觉依赖） |
| 2.8 | 参数/规格与实物不符 | 比对官方资料（有材料时） | → error |
| 2.9 | 图表数字与数据源不符 | 逐项比对 | → error |

**铁律**：**核实不了的一律进存疑项，不得凭模型记忆断定，不得代填。**

---

### D3 · 一致性（Consistency）

**查什么**：产物内部、产物之间、模态之间是否自洽。

| # | 检查 | 判定 |
|---|---|---|
| 3.1 | 前后说法矛盾（同一事物两种描述） | error |
| 3.2 | 术语不统一（同物多名、无意义同义轮换） | medium |
| 3.3 | 人称/视角跳变（你/您/我们混用） | low |
| 3.4 | 语气与体裁失配（报告写成营销稿） | medium |
| 3.5 | 文档与代码不符（README 说有，代码里没有） | error |
| 3.6 | **跨文件矛盾**（多产物批量质检时） | error |
| 3.7 | 单位/口径不统一（万元/元、同比/环比混用） | error |
| 3.8 | 首句复读标题（无独立含义的复述） | low |

---

### D4 · 完整性（Completeness）

**查什么**：有没有缺的、断的、空的。

| # | 检查 | 判定 |
|---|---|---|
| 4.1 | 占位符 / 未填槽位 | error |
| 4.2 | 句子截断、段落中断、话说到一半 | error |
| 4.3 | 空章节、空标题、无内容的编号项 | error |
| 4.4 | 缺失图注、表注、参考文献条目 | medium |
| 4.5 | 目录条目与正文标题不匹配 | error |
| 4.6 | 代码未完成的分支（`// TODO`、空函数体、`pass` 占位） | error |
| 4.7 | 编号跳跃（第 2 节后直接第 4 节） | medium |
| 4.8 | 附件/引用文件缺失 | error |

---

### D5 · 合规性（Compliance）

见 `compliance.md`，检查项代号为 **L1–L7**。严重度最高档，与真实性同级。

---

### D6 · 适配性（Fitness）

**查什么**：这个产物能不能直接用在它该去的地方。

| # | 检查 | 判定 |
|---|---|---|
| 6.1 | 受众匹配（给老板的和给客户的不是一回事） | medium |
| 6.2 | 平台规格（字数、尺寸、时长、格式） | medium |
| 6.3 | 体裁失配（百科正文带聊天礼貌） | low |
| 6.4 | 信息密度过低（说了等于没说） | medium |
| 6.5 | 篇幅（过长/过短，与目标场景不符） | low |

**6.4「说了等于没说」的具体判据**（五个可操作测试）：

| 测试 | 操作 | 判定 |
|---|---|---|
| **可搬运测试** | 这句话原样搬进同行的文章里是否也成立？ | 成立 = 填充 |
| **删后不变测试** | 删掉后，全文事实与因果关系是否改变？ | 不变 = 装饰细节（但第一人称亲历细节一律保留） |
| **名词化测试** | 能否还原出被隐藏的动作与施动者？ | 还原不出且非稳定术语 = 空转 |
| **同义轮换测试** | 换词是否带来新信息或新限定？ | 未带来 = 躲避，应统一回最具体说法 |
| **材料计数** | 非虚构长文（≥1200 字）能否列出 ≥5 件具体材料（含出处）？ | 列不出 = 需要研究或缩短篇幅 |

排除项：临时编的例子、无来源的典型场景、常识推演、比喻与同义改写，均不算材料。

## 第二部分：八个模态专属维度（叠加在通用维度之上）

### A · 文本类

| # | 检查 | 判定 |
|---|---|---|
| A1 | 论证链断裂（结论无前提、推论超证据强度） | error |
| A2 | 逻辑跳跃（缺少中间步骤） | medium |
| A3 | 循环论证 | medium |
| A4 | 因果倒置（时间先后写成因果） | error |
| A5 | 不同尺度硬比较 | medium |
| A6 | 绝对化表述（"所有""一定""必然"）无依据 | medium |
| A7 | 标点规范（GB/T 15834：顿号/逗号/分号/冒号/破折号按功能使用） | low |
| A8 | 层叠「的」导致主干难找 | low |
| A9 | 主干后置（多层前置修饰后才出现谓语） | low |

### B · 代码类

| # | 检查 | 判定 |
|---|---|---|
| B1 | **幻觉依赖**（导入的包/模块在仓库中不存在） | error |
| B2 | **空断言测试**（测试文件存在但无 assert / expect） | error |
| B3 | **硬编码密钥**（API Key、Token、密码、私钥写死） | error |
| B4 | 未处理的错误/异常（裸 await、空 catch） | error |
| B5 | 注入风险（SQL 拼接、命令拼接、无参数化） | error |
| B6 | 越权/鉴权缺失（接口无 middleware） | error |
| B7 | 不可达分支 / 死代码 | medium |
| B8 | 上帝文件（单文件 >500 行且职责混杂） | medium |
| B9 | 混用 async 风格（callback / promise / await 并存） | medium |
| B10 | 前后端字段不匹配 | error |
| B11 | 类型不一致（同一字段多处类型定义冲突） | medium |
| B12 | 注释与代码不符（注释描述的行为代码并未实现） | error |

### C · 数据类

| # | 检查 | 判定 |
|---|---|---|
| C1 | **分项加总 ≠ 合计** | error |
| C2 | 单位不统一（元/万元、个/万个人混用） | error |
| C3 | 口径不一致（同比/环比/累计混用未标注） | error |
| C4 | 空值、异常值、明显离群值未处理 | medium |
| C5 | 图表与数据源不一致 | error |
| C6 | 公式错误（`#REF! #DIV/0! #VALUE! #NAME? #N/A`） | error |
| C7 | 数字被存为文本类型 | medium |
| C8 | 派生值硬编码（应写公式却写了死数） | medium |

### D · 文档类（代号 **W1–W9**，避免与通用维度 D1–D6 撞号）

| # | 检查 | 判定 |
|---|---|---|
| W1 | 目录与正文标题不一致 | error |
| W2 | 页码/章节号错乱 | medium |
| W3 | 图表编号缺失或与引用不符 | medium |
| W4 | 字体缺失/回退（中文出现方框或宋体替代） | error |
| W5 | 中文排版（字距、行高、禁则处理、标点避头尾） | low |
| W6 | 公文格式（GB/T 9704：版头、主送、正文、版记） | medium |
| W7 | 公式/符号渲染错误 | error |
| W8 | **可编辑性契约**：整页截图、关键文字做成图片、标题层级靠加粗伪造 | error |
| W9 | 分页/间距/页眉页脚异常 | low |

### E · 图片类

**完整执行协议见 `references/multimodal-engine.md`（九宫格观察顺序 · 五条防误报红线 · 视觉确定性赋值）。**

| # | 检查 | severity | 确定性 | 分层 |
|---|---|---|:--:|---|
| E1 | 解剖学异常（手指、肢体、五官） | error | 1.0 | 🔴 必改 |
| E2 | 光影方向不一致 | error | 0.8 | 🟡 可改 |
| E3 | 镜面/反射不合理 | error | 0.8 | 🟡 可改 |
| E4 | 透视与比例矛盾 | error | 0.8 | 🟡 可改 |
| E5 | 画面文字错误（乱码、错字、不成字） | error | 1.0 | 🔴 必改 |
| E6 | 物件穿模 / 悬浮 / 连接错误 | error | 1.0 | 🔴 必改 |
| E7 | 配饰不成对（耳环、袖扣、鞋带） | medium | 0.8 | 🟡 可改 |
| E8 | 物理常识违背（重力、液体、材质） | error | 0.8–1.0 | 视清晰度 |
| E9 | 品牌元素错误（Logo 变形、配色偏差） | error | 1.0 / 0.2 | 有标准 VI → 必改；无 → 存疑 |
| E10 | 视觉套路（科技蓝紫渐变、发光卡片、多巴胺配色、大促红金、满屏弹窗） | low | 1.0 | 🟡 可改 / 不报 |

> **执行要点**：①先判体裁再判内容（插画/抽象不适用解剖与透视判据）②每条判定必须给出
> 「位置 + 可见特征 + 与什么冲突」三要素 ③看不清的一律进存疑，不推测
> ④**只判断"这张图讲不讲得通"，绝不判断"是不是 AI 画的"**。

### F · 网页/界面类

| # | 检查 | 判定 |
|---|---|---|
| F1 | 结构完整性（HTML 标签闭合、无孤立标签） | error |
| F2 | 死链与占位链接（`example.com`、`#`、`javascript:void(0)`） | error |
| F3 | 响应式断点缺失 | medium |
| F4 | 可访问性（对比度不足、图片缺 alt、键盘不可达） | medium |
| F5 | 视觉套路：渐变裁切标题、超大圆角+玻璃拟态、超大投影、徽章药丸轰炸、emoji 泛滥、`transition-all` 弹性放大 | low |
| F6 | 中文字体栈缺失（未声明 PingFang SC / Microsoft YaHei / Noto Sans CJK SC） | medium |
| F7 | 中文排版禁则（标点避头尾、中西文混排间距） | low |
| F8 | 文案与视觉不一致（按钮文字与实际功能不符） | error |

### G · 音视频类

| # | 检查 | 判定 |
|---|---|---|
| G1 | 字幕与时间轴对齐 | error |
| G2 | 时长与字数匹配（口播稿按 200-240 字/分钟校验） | medium |
| G3 | 口播稿书面化（不适合读出来） | low |
| G4 | 分镜与脚本不对应 | error |
| G5 | 字幕错字/断句错误 | medium |

### H · 组合产物（跨模态一致性）— 技术护城河

**单模态工具结构性做不到，这是本产品的独家维度。**
**完整执行协议见 `references/multimodal-engine.md` 第五节（锚点对齐引擎 · 四步流程 · 对齐表模板）。**

| # | 检查 | severity | 确定性 | 分层 |
|---|---|---|:--:|---|
| H1 | 图文矛盾：画面内容与正文描述不是一回事 | error | 1.0 | 🔴 必改 |
| H2 | 图数矛盾：图表数字与正文/数据源不一致 | error | 1.0（可计算） | 🔴 必改 |
| H3 | 图注缺失或错位 | medium | 0.8 | 🟡 可改 |
| H4 | PPT 讲稿与页面内容不匹配 | error | 1.0 | 🔴 必改 |
| H5 | 落地页文案与视觉/功能不符（按钮说 A，点了是 B） | error | 1.0 | 🔴 必改 |
| H6 | 引用编号与参考文献表不对应 | error | 1.0（可计算） | 🔴 必改 |
| H7 | 多文件批量质检时的跨文件矛盾 | error | 1.0 | 🔴 必改 |

> **执行要点**：抽取文本侧六类锚点（数字/对象/属性/时间/空间/趋势）→ 逐条到视觉侧比对
> → 输出**锚点对齐表** → 反向核对（图上有的正文没交代）。
> **「无法核对」记存疑，不得计入通过项**——这是组合模态最容易虚报的地方。

## 维度与分层的映射

| 维度 | 命中后默认进 | 说明 |
|---|---|---|
| D2 真实性 | 🔴 必改 | 核实不了一律降级到 ⚪ 存疑 |
| D5 合规性 | 🔴 必改 | 同左 |
| D1 残留度 | 🔴 必改（RL1 级） | RL2 及以下视密度进 🟡 可改 |
| D3 一致性 | 🔴 必改（矛盾类）/ 🟡 可改（术语类） | |
| D4 完整性 | 🔴 必改 | |
| D6 适配性 | 🟡 可改 | **永不进必改**（风格偏好禁入原则） |

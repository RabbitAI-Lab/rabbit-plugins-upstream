# ontoAI 质检官 (ontoAI Quality Inspector)

> ## 交付前最后一道关 ｜ The Final Gate Before Delivery

AI 产物出厂质检。**不是判断"这是不是 AI 写的"，而是判断"这个东西能不能交付"。**

覆盖 8 大类 52 种产物：文案、代码、数据、文档、图片、网页、音视频、组合产物。
输出四层分级质检报告：**必改 / 可改 / 存疑 / 已通过**。

---

## 为什么需要它

AI 生成方自己查不出自己的错——它深陷当时的检索上下文，记得"我为什么这么写"，
所以编造的引语在它的上下文里"看起来是真的"。

> **生成是"顺着写"，质检是"倒着查"。同一个模型无法在同一轮上下文里同时做好这两件事。**

真实代价：一本讲 AI 如何摧毁真相的书，自己被查出 6+ 条伪造引语；
一本售价 300 美元的大学教材，据 2026 年 5 月流传的报道（不同媒体引述措辞略有出入），正文里印着 ChatGPT 的原话"如果你愿意，我还可以解释……"。

## 核心设计

| 设计 | 说明 |
|---|---|
| **四条铁律** | 只报不改 · 不新增事实 · 中文优先 · 宁可少报不可虚报 |
| **独立调用三约束** | 只读产物不读生成过程 · 怀疑态起步 · 真实性必须外部查证 |
| **六个通用维度** | 残留度 · 真实性 · 一致性 · 完整性 · 合规性 · 适配性 |
| **影响面模型** | 影响分 = 暴露度 × 严重度 × 确定性 |
| **四层报告** | 🔴必改（≤5条，每条写后果）｜🟡可改｜⚪存疑｜✅已通过 |
| **七种场景** | 出版/对外发布/营销/投标/上线/学术/内部，暴露度决定严格度 |
| **降噪五条** | 置信度门槛 · 必改配额≤5 · 后果驱动 · 风格偏好禁入 · 通过项必写 |
| **冲突仲裁阶梯** | 同一片段被多条规则命中时只出一条：层级 → 危害 → 覆盖 → 结构>词汇 |
| **视觉引擎** | 九宫格枚举 → 三要素取证 → 判定；锚点对齐查跨模态矛盾；无需外部视觉工具 |
| **报告格式三条** | 同级归类（一层一张表）· 先给计数（总览 + 维度分布）· 表格优先（禁止逐条平铺） |
| **四款报告版式** | 单一模板 `assets/report.html`，改 `DATA.style` 即切换：A 官方检验报告（公文式）· B 第三方检测机构 · C 现代图表 · D 学术出版。**双击打开 HTML 即见左上角悬浮款式切换条**（4 按钮 + 收起），无需输入参数；`?formal=1` 隐藏外壳作干净交付，打印/PDF 输出中切换条自动剥离 |
| **自我质检（吃自己的狗粮）** | 已在独立会话对自身完成 **2 轮全量质检**（受检 v1.4.1、v1.4.2），必改项全部在下一版本修复——真实报告收录于 [`evals/qc-reports/`](evals/qc-reports/) |
| **数据证据已固化** | 残留规则库数据集合已于**开源前**完成平台数据存证（编号 `CZ20260215641694`，内容哈希+时间戳锚定于 2026-10-11，数据通数据知识产权平台） |
| **HTML / PDF 双形态** | HTML 单文件离线可用；PDF 由 `assets/make-pdf.js` 调用本机 Edge/Chrome 无头打印生成，无第三方依赖 |

## 安装

复制到你的 Agent 技能目录即可：

```bash
# WorkBuddy
cp -r ontoAI-qc ~/.workbuddy/skills/

# Claude Code
cp -r ontoAI-qc ~/.claude/skills/

# Codex
cp -r ontoAI-qc ~/.codex/skills/
```

重启 Agent 后生效。本包为**商业授权软件**（付费产品，授权条款见 `LICENSE`）。

## 使用

### 触发说法

> 质检一下这个 ｜ 过一下质检 ｜ ontoAI 质检 ｜ 出厂检查
> 帮我看看有没有问题 ｜ 能不能发 ｜ 能不能交付 ｜ 检查一下这个

### 示例

```
质检一下这份产品发布稿，场景是对外发布
```

```
/code 目录下这批文件，过一下质检
```

```
帮我看看这份 PPT 能不能发给客户
```

### 指定场景（可选）

不指定时默认按「对外发布」档（从严）。明确场景可得到更准确的分层：

```
这是内部周报，质检一下
```

### 报告版式

| 版式 | `DATA.style` | 适用 |
|---|:--:|---|
| A · 官方检验报告 | `"a"` 默认 | 正式对外、递交甲方、归档留痕（A4 公文式，最稳） |
| B · 第三方检测机构 | `"b"` | 委托检验、需体现机构中立性 |
| C · 现代图表 | `"c"` | 屏幕阅读、内部快速过目 |
| D · 学术 / 出版 | `"d"` | 书稿、论文、出版物审校 |

**出 PDF**：`node assets/make-pdf.js <输入.html> [输出.pdf]`
→ 调用本机 Edge / Chrome 无头打印，不依赖 puppeteer / wkhtmltopdf，离线可用。
未装浏览器时备用：浏览器打开 HTML → Ctrl+P → 另存为 PDF → 勾选「背景图形」。

## 与同类项目的差异

| | 同类项目（humanizer / no-ai-slop / deslop 等） | ontoAI 质检官 |
|---|---|---|
| 覆盖模态 | 99% 只做文本 | 8 大类 52 种，含图片/代码/数据/组合产物 |
| 查什么 | 语言风格（好不好看） | 事实、常识、逻辑、合规（对不对） |
| 输出 | 改写后的文本 | 四层分级质检报告 + 裁定 |
| 改不改 | 直接改写 | **只报不改**，改需确认 |
| 语言 | 英文为主（中文版为翻译迁移） | 中文优先，词条按中文套路重建 |
| 组合产物 | 不支持 | **跨模态矛盾检测** |

**一句话**：竞品管"好不好看"，我们管"能不能交付"。

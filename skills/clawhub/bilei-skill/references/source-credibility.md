# 信源可信度与投毒识别速查

本文件是「避雷」技能的证据分级标准。所有扫雷结论、推荐理由、投毒判断都必须引用这里的等级定义。

## 一、证据等级（L0–L4，高者为准）

| 等级 | 定义 | 典型来源 | 使用规则 |
|---|---|---|---|
| **L1** | 官方处罚 / 抽检 / 召回（型号级一手信息） | 市场监管抽检通报、行政处罚决定书、官方召回公告 | 命中型号级 L1 primary → 该款直接出局；仅权威媒体转载（未查到原文）→ 不作唯一排除依据，改为加验证步骤 + 推荐强度降一级 |
| **L2** | 无商业关系的检测 | 消协比较试验、监管抽查、国家级质检中心抽检 | 最可信的第三方实测 |
| **L3** | 媒体 / 博主实测 | 拆解报告、横评、带仪器与方法的实测 | 只能记 L3，且必须细分：**L3a** 网友借机/作者自购、**L3b** 厂商送测/委托、**L3c** 付费定制 |
| **L4** | 用户投诉 | 黑猫投诉、贴吧、B 站、小红书 | ≥3 条不同用户、同一故障模式 → 可称「系统性问题」；≥3 条独立 L4 指向同一故障 → 升级为「疑似系统性缺陷」 |
| **L0** | 商家宣传 / 软文 | 商品详情页、广告、买量好评 | **不作证据**，仅作厂商宣称记录 |

⚠️ **最常见的升级错误**：看到 SGS / TÜV / 华测等大机构 logo 就当 L2。这类商业检测报告绝大多数是厂商付费委托，按「钱从哪来」应记 **L3b**。

⚠️ **「未标注 ≠ 虚标」**：写「虚标 / 注水 / 隐瞒 / 欺骗」必须能回查到 L1/L2 原文，否则改为事实描述；跨测试条件的实测结果不得倒推虚标。

## 二、信源七类（给每个被引用的评测源建档）

| 类型 | 典型形态 | 常见商业模式 | 利益冲突 | 能取哪层 |
|---|---|---|---|---|
| ① 付费检测服务商兼媒体 | 检测机构的内容号 | 付费测试、送测 | 高 | 事实层（数据/照片），不取结论层 |
| ② 官方 / 半官方机构 | 消协、质检中心、监管号 | 财政拨款 | 低 | 全层 |
| ③ 独立个人实测 | 自购测评 UP 主 | 自购、平台激励 | 低–中 | 全层，看样本量 |
| ④ UGC 聚合 | 电商评价区、论坛汇总 | — | 中 | 用户样本，防刷评 |
| ⑤ 联盟营销站 | 挂购买链接的「评测」站 | 返利佣金 | 高 | 只取参数事实，不取推荐 |
| ⑥ 垂类专业媒体 | 行业媒体 | 广告、送测 | 中–高 | 事实层为主 |
| ⑦ 兴趣社区 | 贴吧、QQ 群、 Discord | — | 低 | 真实口碑，噪声大 |

建档字段：`source_type`（七类之一）、`business_model`、`conflict`（高/中/低）、`usable_for` / `not_usable_for`、`controversy`（跑一遍争议检索：翻车 / 收钱 / 误导 / 被起诉；查不到写「未检索到公开争议」，**不许写「口碑良好」**）。

## 三、投毒信号清单（命中任一即提高警惕）

1. **雷同内容**：大量帖子话术雷同、相似好评、同一段文案跨平台批量发布 → 按 GEO 投毒嫌疑处理，反复交叉验证，验证不动就弃用。
2. **通稿陷阱**：数信源时按独立信源计数——通稿转载无论多少篇只计 1 源，转引计 0 源。**「10 个链接」可能是 1 篇通稿。**
3. **零独立实测**：某款全部信息来自厂商自述或通稿 → 第一屏必须原话写明「该款无任何独立实测」。
4. **上市即爆款**：上市 <30 天、评论数暴涨、零第三方实测 → 不得作首选，标记 unproven。
5. **查不到 ≠ 没问题**：因不可验证而缺失的数据，不得反过来当作清白证据。
6. **价格无构成**：写不出日期 + 店铺全称 + 券/补贴构成的价格，等于编的，必须重查。

## 四、层次分离铁律

**利益冲突只削评价层，不削事实层。**

- 弃用：收钱源的「表现优异」「扎实答卷」类结论；
- 保留：它的拆解照片、元件丝印、物料清单、PDO 报文、温升数据——机器就是那台机器，拆开拍的照片不因谁付钱而失真。

反过来也一样：**不因「查过没问题」就放松**——投毒排查的核心不是找到好产品，而是排除掉那些只有声音没有证据的产品。

# 方法卡规范（成丹契约）· v2

> v2 较 v1 唯一差异：在原有 8 个叙述字段外，新增机器可读的**路由层**与逼出推理的**理解层**，让消费方（扫地僧等谋士）**检索得到 + 真懂 + 不懂就闭嘴**。
> v1 字段全部保留，理解层在其上叠加，**不破坏旧卡**。

---

## 一、v1 基础字段（8 个，必须可溯源）

| 字段 | 含义 | 写法要求 |
|---|---|---|
| **名称** | 这张卡一句话叫什么 | 动宾/名词，如「两分钟法则」「第一性原理拆解」 |
| **适用情境** | 什么时候该掏这张卡 | 具体场景，不是空话；写"当你____时" |
| **核心操作** | 具体怎么做（步骤/动作） | 可执行的 2–5 步，别只讲道理 |
| **前提假设** | 它成立的隐含条件 | 列出"只有在____时"才灵 |
| **常见坑** | 容易踩的雷 | 2–3 条真实翻车点 |
| **迁移场景** | 还能用在哪（跨域） | 把"情境绑定"抽象后可复用的地方 |
| **边界反例** | 什么情况下**不该**用 | 反例让卡更可信、防误用 |
| **来源溯源** | 出处 | 书名/章节/页码、视频链接+时间戳、URL、群聊日期 |

### 填卡模板（v1 部分）

```
## 【名称】
<一句话>

- 适用情境：<当你____时>
- 核心操作：
  1. <步骤>
  2. <步骤>
  3. <步骤>
- 前提假设：<只有在____时成立>
- 常见坑：<坑1>；<坑2>
- 迁移场景：<可迁移到____>
- 边界反例：<不该用的情形>
- 来源溯源：<书名/章节/页码 · 或 链接+时间戳 · 或 URL>
- 置信度：【板上钉钉 / 八成·需看原始材料 / 分歧大·待查证】
```

### 范例卡（真实提炼示例）

```
## 【两分钟法则】
- 适用情境：当你面对一堆小事（回消息、扔垃圾、填表）不知要不要现在做时
- 核心操作：
  1. 估这件小事要多久；
  2. 若 ≤2 分钟，立刻做，不进待办清单；
  3. 若 >2 分钟，写进清单，另排时间。
- 前提假设：任务确实小、能 2 分钟内干净利落做完；不是"看似 2 分钟实则连锁"的坑。
- 常见坑：把"2 分钟"当成拖延借口，什么都在 2 分钟内硬做，反而打断深度工作。
- 迁移场景：邮箱处理、工单分诊、任何"小但烦"的批量决策。
- 边界反例：正在深度专注（心流）时，别为 2 分钟小事打断自己——此时宁可全进清单。
- 来源溯源：David Allen《Getting Things Done》· 第二章"工作流程"；亦见 jamesclear.com/atomic-habits 习惯系统文。
- 置信度：【板上钉钉】（GTD 经典定论，广为验证）
```

## 二、v2 扩展：路由层（机器索引，frontmatter）

写在卡文件顶部 `--- ... ---` 之间：

```yaml
pattern: convexity                 # 主 pattern，必选，取自 pattern-taxonomy.md
pattern_aux: [antifragility, optionality]   # 辅 pattern，0–2 个
trigger:                          # 用户原话/症状，命中即考虑此卡；2–4 条
  - "波动一大我就亏，稳的时候也不赚"
  - "怎么设计才能越折腾越强"
root_cause: [risk-asymmetry, fragility-to-volatility]  # L3 根因标签
surface_domain: [投资, 个人成长, 组织]   # 表面领域，仅用于剥离，不参与归类
confidence: 高                     # 高/中/低（整体）
source_fidelity: 一手              # 一手(读原文)/二手·待一手校验
source_path: <原文文件本地路径>      # 有原文必填，无则标二手
```

## 三、v2 扩展：理解层（逼出"真懂"，每条必答，置于正文）

- **mechanism（机制/为何成立）**：一段因果链。讲清"因何成立、靠什么结构成立"，不是步骤复述。
- **transferable_core（可迁移内核）**：去领域化的抽象结构，一句到两句。例："凸性=付出有界、回报无界的非线性映射"。
- **worked_example（正例）**：一个具体情境，展示用对。
- **near_miss（近失例）**：看似能用实则翻车，写明翻车点——这是决策边界的训练数据。
- **relates_to（关系网）**：`subsumes/instance-of/conflicts/complements → 卡名`。
- **gate_questions（理解闸门）**：开口前必答三问——
  1. 机制一句话？（答不出→只到名称层）
  2. 首要前提是什么，违背会怎样？（答不出→不懂适用边界）
  3. 迁移到 X 域，结构同构吗、前提成立吗？（答不出→伪贯通）
- **self_reflection（我何时会错）**：强制伪化——本方法最易被误用的 1–2 种情形。
- **confidence_dims（分维置信）**：机制/前提/迁移到X 分别给 高/中/低。
- **primary_source（一手原句）**：有原文时，摘录 1–3 段作者原话（带页码），作为保真锚点。

## 四、理解闸门（消费方强制）

扫地僧等谋士取卡后、开口前，内部必过 `gate_questions`：任一答不出 → 输出固定句
"老衲对此法只到【名称/步骤】层，机制尚未真懂，需查证原始材料后再答。"
**宁可说不懂，不可背招糊弄。**

## 五、卡文件命名

`deep_<书名简称>__<卡名slug>.md`，例如 `deep_反脆弱__凸性杠铃.md`。
（薄卡仍用 `harbor_*.md`，与 deep 卡共存；INDEX 同时收录两者，deep 卡权重更高。）

## 六、理解校准 Eval（understand_eval.py）

- 检查：理解层字段是否齐全 + mechanism/near_miss 是否有实质内容（长度阈值）。
- 输出：`comprehension_readiness` 0–100；<60 判"仅检索层"，须回填。
- 周期：每月丢 1 个未见场景，要求"选对方法+讲清机制+预言误用后果+有效迁移过校验"四连答，打分=理解度 KPI。

> 写卡铁律：先「淬炼抽象」再填——把"作者怎么做的（情境绑定）"和"底层模式（可迁移）"分开，卡才有复用价值。

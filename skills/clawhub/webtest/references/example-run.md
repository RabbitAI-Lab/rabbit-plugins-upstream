# 完整示例（Example Run）

下面演示一次真实调用如何从"自然语言需求"走到"测试报告"。

## 用户输入

```
测一下 https://shop.demo.com 的登录和下单流程。
断言：登录成功跳转首页；下单后显示订单号（形态断言：包含数字）。
环境：测试账号 buyer@demo.com / demo1234，商品已加购。
```

## 步骤规划（技能内部）

1. 打开 https://shop.demo.com
2. 点击"登录"，输入账号密码，提交
3. 断言：URL 包含 /home（登录成功）
4. 进入购物车，点击"去结算"
5. 确认收货信息，点击"提交订单"
6. 断言：页面出现"订单号"且包含数字（形态断言）

## 执行情况

- 步骤 1–3：通过（跳转 /home，截图 01）
- 步骤 4–5：通过（结算页正常，提交成功，截图 02）
- 步骤 6：通过（显示"订单号 OD2026080500123"，符合形态断言，截图 03）

## 变体：失败案例

若步骤 6 实际显示"库存不足"而非订单号，则：

- 步骤 6 断言 ❌
- 缺陷清单记录：提交订单未生成订单号，复现线索=库存不足提示，严重度=高
- 报告结论改为"主流程下单受阻，需修复库存校验逻辑"

此变体说明：断言失败不等于中断，其余步骤继续，最终汇总缺陷。

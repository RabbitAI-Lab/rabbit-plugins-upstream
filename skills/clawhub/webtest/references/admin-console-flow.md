# 后台控制台通用测试流程（Admin Console Flow）

绝大多数业务后台（电商、CRM、SaaS 管理端）都是同一套骨架。本参考把"登录 → 仪表盘 → 侧边栏 → 列表 → 搜索/筛选"的标准路径固化下来，遇到这类站点可直接套用，少走弯路。

> 真实验证来源：xqxsakebar.com（青稞酒后台）。其流程为：登录 → 落 `/console` 仪表盘 → 展开侧边栏 → 点「订单管理」到 `/orders` → 在「收件人」框搜索 → 列表过滤。下文以此为准。

## 1. 标准骨架

```
登录页(/login)
   │  填写账号密码 → 点登录
   ▼
仪表盘(/console 或 /dashboard)   ← 登录后默认落地页（通常是日历/统计，不是你要的功能页）
   │  点左上角「汉堡」按钮展开侧边栏
   ▼
侧边栏菜单(listbox / nav)
   │  点目标模块，如「订单管理」
   ▼
列表页(/orders 等)
   │  在筛选区填条件 → 点「查询」
   ▼
结果列表(table)   ← 用列表/表格断言校验
```

## 2. 关键约定（踩坑总结）

- **侧边栏默认折叠**：很多后台登录后只显示内容区（如日历/统计），`snapshot -i` 一开始看不到导航菜单。先点左上角汉堡按钮（常是 `expanded=false` 的 button）展开，菜单链接才会出现在快照里（通常是 `listbox` 下的 `link`）。
- **登录落地 ≠ 断言目标页**：登录后默认落在仪表盘，而非你断言的功能页（如订单管理）。这是**实现差异不是缺陷**——先经菜单导航到达目标页，再断言；报告中标「部分通过 / 落地页差异」。
- **列表页必有筛选区**：典型形态是顶部一排 `textbox`（支付单号 / 收件人 / 手机号 / 时间）+ 一个「查询」按钮 + 表格 + 分页导航。搜索就是"填条件框 → 点查询"。
- **分页状态可辅助断言**：搜索后若只有一条结果，分页按钮（首页/上一页/下一页/尾页）会全部 `disabled`——可作为"结果唯一"的旁证断言。
- **SPA 路由等"元素可见"**：列表页是前端路由，`wait --load` 不会因路由切换再次触发；导航/查询后用 `snapshot -i` 等待目标表格元素出现，再断言。

## 3. 后台搜索断言范式（第 8 类：列表/表格内容）

在列表页执行搜索后，按 `assertion-catalog.md` 第 8 类断言：

- **行包含**：结果行中某一单元格文本包含关键字（如收件人列 = "姜令雨"）。
- **首行字段等于**：过滤后首行目标字段等于期望值。
- **结果计数 ≥ N**：列表行数 ≥ 预期（配合分页 disabled 状态判断唯一结果）。

示例（xqx 收件人搜索"姜令雨"）：
```
操作：在「收件人」框填 "姜令雨" → 点「查询」
预期：列表出现含"姜令雨"的结果
实际：列表过滤为 1 行，收件人列 = "姜令雨"，分页全 disabled
断言：首行收件人 = 姜令雨 ✅ ｜ 结果计数 ≥ 1 ✅
```

## 4. 适用与不适用

- **适用**：所有"登录态 + 左侧菜单 + 顶部筛选 + 表格"形态的后台（最常见真实测试目标）。
- **不适用**：纯前端单页应用无菜单、或前台商城（导航在顶部 header 而非侧边栏）。这类按 SKILL.md 通用流程处理即可。

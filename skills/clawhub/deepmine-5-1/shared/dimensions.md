# 需求维度定义

追问过程中持续追踪以下六个维度。不按顺序问，跟着对话自然走。收口前必须全部有实质内容或标记为「未明确」。

---

## [A] 业务背景

**要收集的内容：**
- 现在有什么问题 / 为什么现在要做这件事
- 不做会怎样

**有实质内容的判断标准：**
对方说出了一个具体的现状问题，不是「想做 xxx」而是「现在 xxx 很麻烦 / 有问题」。

```
[有效] 「我们客服一天处理 1000 个工单，80% 是重复问题，人力成本太高。」
[无效] 「我想做一个 AI 系统。」（这是解决方案，不是业务背景）
```

---

## [B] 核心功能

**要收集的内容：**
- 这个产品/系统要能做什么
- 哪些是必须有的，哪些可以后做

**有实质内容的判断标准：**
对方说出了至少一个具体功能点，并且区分了优先级（必须有 vs 可以后做）。

```
[有效] 「必须能自动回复重复工单，数据分析后台后面再说。」
[无效] 「功能要全，用户体验要好。」（没有具体功能，没有优先级）
```

---

## [C] 用户群体

**要收集的内容：**
- 谁来用（内部员工 / 外部用户 / 两者都有）
- 大概多少人
- 主要在哪个部门或场景下用

**有实质内容的判断标准：**
对方说出了使用对象的身份和大致规模。

```
[有效] 「内部客服团队用，大概 30 个人，还有运营偶尔看数据。」
[无效] 「用户用。」
```

---

## [D] 技术约束

**要收集的内容：**
- 有没有现有系统要对接（ERP、CRM、数据库等）
- 数据在哪里，格式怎么样
- 有没有内部技术团队，还是全部外包

**有实质内容的判断标准：**
对方说出了现有系统情况或数据情况，或明确说「没有任何现有系统」。

```
[有效] 「有个老的 CRM，MySQL 数据库，数据比较乱，没人整理过。」
[有效] 「没有任何现有系统，从零开始。」
[无效] 「应该有一些数据吧。」（不确定，不算有实质内容）
```

---

## [E] 时间与预算

**要收集的内容：**
- 什么时候要上线（硬截止日期 or 大概时间范围）
- 预算范围（数量级即可，不需要精确）

**有实质内容的判断标准：**
对方给出了时间或预算的任意一个具体范围，哪怕是「大概」。

```
[有效] 「最好三个月内上线，预算 50 万以内。」
[有效] 「时间不急，但预算不能超过 30 万。」
[无效] 「尽快吧，预算看情况。」（两个都没有范围）
```

---

## [F] 验收标准

**要收集的内容：**
- 做到什么程度算成功
- 用什么指标衡量
- 有没有红线（绝对不能碰的）

**有实质内容的判断标准：**
对方说出了一个可以判断成败的标准，或说出了红线。

```
[有效] 「自动处理率达到 70% 以上，用户满意度不能下降，这是红线。」
[有效] 「只要客服工单量减半，我就认为成功了。」
[无效] 「做好就行，用户满意就行。」（无法判断成败）
```

---

## 维度覆盖规则

- 对方已给出实质内容 → 标记为已覆盖，填入原话概括
- 反复问（≥2次）对方还是说不清楚 → 标记为「未明确」，不再追问，视为覆盖
- 六个维度全部覆盖（含「未明确」）→ 可以收口

# 比较口径与行动判断

一次比较的单位是“目标问题 × 同类页面槽位 × 一次采集”。产品页可以覆盖 FAQ 和实体信号；未提供关于页时，只能说产品页未见对应字段，不能说企业没有实体资料。同槽位的语种、地区、受众和产品版本尽量一致；无法对齐时记录偏差，Agent 不将其数量差直接解释为优劣。

| 类别 | 可自动提取的证据 | Agent 要复核的问题 |
| --- | --- | --- |
| 抓取与结构数据 | 指定 URL 的状态、JSON-LD 解析成功/失败块、嵌套类型、robots 分组和路径决策 | 是否抓到预期正文？是否只是静态壳或软 404？标记是否描述可见内容？ |
| 内容组织 | 可见 h1/h2、首段、details 问答、问句标题后紧邻的段落 | 开头是否回答目标问题？问答是否完整、准确且适合该页面？ |
| 品牌实体 | 品牌名/别名匹配的 Organization、name/url/description/sameAs 字段 | 是否是品牌实体而非出版商、客户或合作商？同名实体的 URL 是否一致？ |
| 来源资料 | 外部链接、位于来源/参考区域或标为 cite 的链接候选 | 原资料能否支撑某条主张？日期、数据口径、作者和使用条件是否明确？ |

自动提取只读静态 HTML，隐藏属性和内联隐藏样式会被排除；外部 CSS、JS 交互、复杂问答 DOM、Schema.org 的全部语义规则及外部资料质量不自动判断。表格里的 0 是已读取的那一份 HTML 中识别到的数量，不等于全站不存在。纯正文导出无 DOM 时，Agent 可标注段落证据并手工填表，保留同一口径。

FAQ 只计有答案的明确问句（以 `?`/`？` 结尾）或明确 FAQ 语义区域中的条目；`details` 折叠块本身不代表问答，产品参数等普通说明不计。FAQ 区域可来自明确 FAQ 标记或可见“常见问题 / Frequently asked questions”标题。来源链接除原有来源标记、`cite`/`rel=cite` 外，也识别可见“参考资料 / 来源 / References / Sources”等标题之后的区域；到同级/更高标题或所在区域结束即停止，不把随后相关产品链接算来源。这里识别的是来源候选，不判断外部内容能否支撑主张。

`--fetch` 的单页 HTTP 响应超过 3 MiB 时，该页记 `unverified`、`fetch_failed:response_too_large`，不提取信号、不填数量零，并继续交付其他可读页面；涉及失败页的数量差为 `null`。这不改变全局输入结构、冲突记录和本地快照路径等错误应退出 2 的规则。

JSON-LD 通过 HTML 属性解析定位，不依赖引号和属性顺序；递归遍历数组、`@graph`、嵌套对象和 `@type` 数组。短类型名需要 schema.org 上下文；完整 schema.org 类型 URL 可独立识别。仅解析 JSON-LD，不实现远程上下文加载、任意别名前缀展开、RDF 推理或完整 JSON Schema 校验。其他 JSON-LD 方言需人工复核，不报作已完整验证。

robots 使用大小写无关的 user-agent 匹配：选最具体组、合并同等具体组；无具体匹配时使用 `*`；按实际路径及查询串匹配 Allow/Disallow，支持 `*`、末尾 `$`、最长匹配和等长 Allow 优先，保留保留字符的百分号编码。空 Disallow 不限制。缺失、读取失败、HTML 冒充 robots、跨源重定向不输出“已允许”。仅解释指定规则文本，不声称知道网站访问控制、抓取历史、平台索引或爬虫完整行为。

规则优先级按规范化后的完整规则字节长度比较，包含 `*` 和末尾 `$`，不按删去特殊字符后的字面长度，也不按正则实际吞入的 URL 长度。未保留字符的百分号编码可解码；保留字符维持百分号表达，原始 UTF-8 与其百分号表达采用同一规范化结果。依据 [Google 规则优先级示例](https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec#order-of-precedence-for-rules)、[RFC 9309 §2.2.2](https://www.rfc-editor.org/rfc/rfc9309.html#section-2.2.2) 和 [Google 开源匹配器](https://github.com/google/robotstxt/blob/master/robots.cc)；这些是本地规则解释依据，不表示已执行平台抓取或获得收录。

## 差距与优先级

不用未经校准的 GEO 总分或 AI 排名。`competitor_minus_brand` 是同槽位的原始数量差，例如 2 个可见问答减 0 得 2。正值只是“竞品多”，Agent 需要用原文证明它解决了目标问题；更多 FAQ、外链或实体字段并不自动更好。模拟与真实资料不互算差距；未读到的页面或缺少指定槽位返回 `null`。

行动顺序由“对目标用户问题的帮助 × 证据可信度 × 工作量”决定：直接影响选择/使用且证据完整的修改先做；事实来源待确认的先补证；未知项先恢复资料。每项建议明确为什么值得做及如何验收，不能用“提升引用 30%”代替业务验收。

验收先验证网页改动：可见问答解决何种问题、实体是否与业务事实一致、引用是否对应具体主张。AI 引用复测属于后续独立观察，固定问题、平台、时间、答案和原生引用来源分别保存；不预设一定有引用或名次提高。

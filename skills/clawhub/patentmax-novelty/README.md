## 初衷

> **查新查错了，代价是整个申请。**

方案没查、直接申请，等审查员把对比文件甩过来，交底书、代理费、一年多的等待全白费。更糟的是，AI 编一个格式正确的公开号给你，你信了，拿着去写查新说明——那比没查还危险。

这个 Skill 做的是：把方案描述扔进全球专利库，**逐条比技术特征**，返回最接近的对比文件、相似度分析和明确结论。每一条都有公开号，你能自己去官方库核对。

判断新颖性看的是权利要求，不是摘要——摘要读着像不等于落进保护范围。这一条写进了它的工作规则里。

---

## 能做什么

给一段技术方案描述，异步返回：

- **对比文件** — 最接近的几篇，按相似度排，带公开号和公开日
- **逐条比对** — 每篇在哪一点上撞上：同一个问题？同样的手段？相近的效果？
- **明确结论** — 是「未检索到破坏新颖性的文献」还是「存在高度相似的在先专利」，不用模糊话搪塞
- **Word 报告** — 直接导出，可用于立项材料、申请前自查、内部评审

**五种查新目的**：新颖性、创造性、申请前查新、立项筛查、竞品扫描。
**三档检索深度**：快速摸底、标准、深度。
**现有技术不限于专利** —— 论文和公开网页默认计入，高校和科研机构的方案尤其要注意，论文往往比专利早。

## 方案怎么写

**这是唯一的核心输入，质量几乎完全决定结果。** 详见 `references/solution-guide.md`，里面有三个颗粒度的真实对照。

三件事缺一不可：

| | 写什么 |
| --- | --- |
| **解决什么问题** | 现有技术卡在哪、有什么缺陷 |
| **用什么手段** | **最关键**，也最容易写空——具体的结构、材料、步骤、参数、控制逻辑 |
| **达到什么效果** | 最好有量化指标 |

❌ 「一种新型电池」—— 脚本会在 80 字以下直接拦下来，那个长度查了也白查

✅ 「在转轴上布置角度与扭矩传感器，闸前闸后各设水位计；当启闭扭矩相对基准增量超阈值、且水位差异常时判定卡滞；结合积雪含水率区分冰冻与异物，冰冻时低频大振幅振动 30 秒，异物时高频小振幅 15 秒，连续三次失败则告警锁定」

**有区别特征，才谈得上新颖性。**

## 怎么用

在 [api.ip930.com](https://api.ip930.com/features/api-platform) 创建密钥，设成环境变量：

```bash
export PATENTMAX_API_KEY="pm_live_你的密钥"
```

```bash
python scripts/patentmax_novelty.py create \
  --title "阀门卡滞诊断与清理装置" \
  --solution-file ./solution.md \
  --purpose pre_filing --depth standard \
  --yes
```

交底书、申请草稿、研发报告都能直接当方案文件用。跑完导出：

```bash
python scripts/patentmax_novelty.py download --report-id <report_id> --out 查新报告.docx
```

`python scripts/patentmax_novelty.py options` 可以随时打出参数可选值。

只用 Python 标准库，不需要 `pip install`。没有 Python 的 curl 示例在 `references/faq.md`。

新用户注册即送 ¥50 体验额度。

## 先想清楚要不要跑

**「有没有类似的」和「能不能申请」是两个问题。**

只是想看看有哪些相关专利 —— 用普通检索加相似专利，两次调用便宜得多。

要一个能不能申请的结论 —— 才用查新。

这个 Skill 的工作规则里写了这条判断，它会先问你一句，而不是直接扣钱。

---

## 它不做什么

**不出保证性结论。** 不写「具备新颖性」「可以申请」「全球无人做过」。正确表述是「截至某日期、在所列范围内未发现披露全部必要技术特征的在先文献」。

**18 个月公开窗口是硬伤。** 专利从申请到公开约一年半，**这期间的申请谁也查不到**——这是查新固有的局限，不是数据库的问题，任何查新都一样。

**不替代有资质机构的正式查新报告。** 生成的文档可用于立项、自查、内部评审；正式场合（项目验收、基金申报、职称评定）需要有资质的查新机构出具并盖章。

**多篇拼不成新颖性。** 要同一篇文献公开全部必要特征才破坏新颖性；多篇组合起来才覆盖的，那是创造性问题，要找代理人评估。

# 得分点导航 + 响应覆盖审计方法论（模式 B）

本文件是 SKILL.md「模式 B」的展开。核心：把评标表拆成「得分点地图」，再用响应文件做**覆盖审计**，找出隐性丢分（乃至废标）风险，并产出给评委看的「评分索引表」。

## 1. 得分点地图

将 `criteria.json` 按 `score` 降序排列，形成导航视图：
- 高价值项（分值大）优先保障——丢 1 分比丢 0.5 分更疼。
- 标 `is_knockout=true` 的项单独置顶红色区：**否决/废标红线**，缺失不是丢分，是出局。

## 2. 响应覆盖审计（核心）

对每一项，在响应正文（`response.txt`）中检索对应内容，给**覆盖状态**：

| 状态 | 含义 | 风险 |
|---|---|---|
| ✅ covered | 客观项证据齐 / 主观项内容充实 | 无 |
| ⚠️ partial | 部分满足（如业绩数量不足、指标未全量化） | 可能按标准比例扣分 |
| ❌ missing | 响应中未体现该评分项 | 客观项=0 分；否决项=废标 |
| ▶ knockout-miss | `is_knockout` 项缺失 | 🔴 废标/无效投标 |
| ⚠️ format-risk | 证据内容存在，但未满足形式要件（缺原件扫描/缺公章/缺法人签字/缺特定页面/缺骑缝章） | 极易被扣分甚至废标，须优先补正 |

**⚠️ format-risk（形式瑕疵）判定规则**：证据内容**存在**，但未满足招标文件要求的**形式要件**——如要求原件扫描件却只提供复印件加盖公章、要求网页截图却未加盖公章、要求法人签字却只盖章、缺特定页面或骑缝章等。此类丢分在评标现场极易被扣分甚至直接废标，**须优先于普通 missing 补正**。报告中须标注「形式瑕疵：缺 X（具体要件）」。

**判定纪律（防误判）**：
1. 不得把「响应里提到了相关词」直接算作「满足评分标准」。客观项看**硬证据条件**（证书/合同/承诺函是否在）；主观项看**内容质量**（方案是否量化、完整）。
2. 覆盖审计初判由 `parse_score_table.py --mode audit` 产出 `coverage_hints.json`（关键词命中），**你须逐条精修**：关键词命中 ≠ 真实覆盖，要核验证据位置与质量。
3. 任何 `missing` 的客观项，在报告里标注「响应中未体现」，不得臆测已提供。

## 3. 评分索引表（评委友好度增强）

输出一份「评分索引表」，核心目标是**让评委 5 秒定位证据**，而非翻几百页投标文件。结构（评委视角）：

| 列 | 含义 | 填写要求 |
|---|---|---|
| 评分项 | 评审因素 | 与评标表一致 |
| 分值 | 该项分 | 数字 |
| 响应页码 | 我方响应中的位置 | 真实页码/章节，勿虚标 |
| 关键证据一句话摘要 | 该项得分依据浓缩 | 如「3份合同+验收报告，均≥500万」 |
| 评委核验难度 | 翻到即知 / 需通读判断 | ⭐低（硬证据直接翻到）/ ⭐⭐⭐高（需通读方案自行判断） |

示例：
```
| 业绩(8) | 8 | P.127-135 | 3份合同+验收报告，均≥500万 | ⭐低(直接翻到) |
| 方案(15) | 15 | P.45-89 | 技术方案全文，需评委自行判断 | ⭐⭐⭐高(需通读) |
```

用途：封标时附在投标文件前/后，方便评委快速定位每项得分依据；同时也是我方自检清单。核验难度列帮助投标人把「高难度」主观项提前做内容优化，降低评委通读成本。

## 4. 输出要点

- 得分点地图（按分值排序，否决项红色置顶）
- 覆盖审计表（逐条状态 + 证据定位 + 风险标注）
- 覆盖缺口汇总：缺失项数、预计隐性丢分、否决红线命中数
- 评分索引表（可直接附卷）

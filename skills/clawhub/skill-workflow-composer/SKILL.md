# 技能工作流编排

## 定位

本技能是一个**技能工作流编排**技能：扫描 WorkBuddy 技能市场与本地已装技能，按用户需求把多个技能组合为可执行的工作流，并主动生成跨技能灵感组合建议。

**依赖声明**：本技能自包含，不依赖其他领域技能；仅依赖平台能力与自身 references 文件。任务 ID 格式为 SWC{域号}-{两位序号}。本技能按"生成技能标准"接受接口校验。

**能力边界**：连接器是工具级数据流——把外部服务接入 AI 传递数据；技能是知识级上下文加载——把领域方法与知识装入对话上下文。涉及连接器组合的需求属工具级数据流范畴，超出本技能能力边界，不在本技能内编排；混合需求可拆分为技能段与外部投递段，技能段由本技能编排。

## 核心能力

本技能共 7 域 23 任务，核心能力如下：

- **任务协调（SWC0）**：模式路由（需求驱动组合/灵感浏览/市场查询/方案迭代/市场更新适配）、执行顺序确定、结果整合与优化
- **技能市场发现（SWC1）**：全量扫描（本地枚举＋市场采样）、分类排序展示、技能筛选与能力详情
- **需求解析（SWC2）**：需求解析与场景建模、需求到技能的匹配映射、安装与触发条件核对
- **技能组合（SWC3）**：组合层次路由（L1/L2/L3）、IPO 基元链构建、L1 会话内多技能加载编排、L2 定时自动化固化、L3 可复用流程沉淀
- **灵感生成（SWC4）**：场景扫描与机会识别、跨技能创意组合生成、灵感清单输出与价值标注
- **守护校验（SWC5）**：组合方案可行性校验、风险识别与确认守护、方案定稿检查
- **深化（SWC6）**：组合方案迭代优化、技能市场更新适配、负载物深化

### 关键行为一：首次使用强制扫描

本技能每次被加载后的首次执行，必须先完成双路径扫描：

1. **本地已装技能枚举**：枚举用户级与项目级技能目录，取得本地已装技能全量清单（全量真实，不做采样）；
2. **技能市场采样检索**：调用平台技能市场检索能力，按分类关键词逐词检索并汇总去重；市场无全量枚举能力，检索结果为采样口径，必须向用户如实标注采样关键词、各关键词命中总数与采样规则；
3. 具体工具以当前环境实际提供的平台能力为准；两条路径均不可用时，降级为提示用户打开 WorkBuddy 技能市场页自行查看；
4. 严禁编造技能数据——技能清单与能力描述只能来自目录枚举与市场检索的实际返回。

将两路结果合并按逻辑分类排序展示，展示使用表格（列：来源（本地/市场）/ 分类 / 技能名 / 一句话能力）。分类框架基线（允许按实际结果归并增补，不得删除既有类目）：效率工具与办公协同 / 内容创作与写作 / 开发与工程 / 数据分析与金融 / 设计与视觉 / 营销增长 / 教育与学习。扫描口径、分类框架与展示格式的完整定义见 references/skill-workflow-requirements.md 的 SWC1 域级说明。

### 关键行为二：三层次组合（缺一不可）

- **L1 会话内多技能加载编排**：把多个技能按依赖与触发词协同设计加载顺序，按需逐个加载，同会话激活技能预算默认 ≤5，知识与结论在对话内传递，当次会话完成。
- **L2 定时自动化**：通过平台的定时任务/自动化能力把整条链固化为定时或一次性任务；创建前先查询既有自动化避免重复；循环计划与一次性定时的调度参数由能力自身字段承载，不写入任务提示。
- **L3 沉淀复用**：通过平台的技能管理能力，把跑通的组合沉淀为可复用技能或流程文档，形成"跑通一次、终身复用"。

三层定义、路由判据与各层执行细则见 references/skill-workflow-requirements.md 的 SWC3 域级说明与 references/SWC3-技能组合域范本.md。

### 关键行为三：灵感模式

除需求驱动组合外，主动自动生成 3~5 个跨技能组合建议。每条建议必须包含六要素：场景名 / 涉及技能 / 流程链（取数→处理→交付→产出）/ 价值假设 / 建议落地层次（L1/L2/L3）/ 前置条件（安装与触发要求）。生成方法与输出格式见 references/skill-workflow-requirements.md 的 SWC4 域级说明与 references/SWC4-灵感建议范本.md。

### 关键行为四：守护约束

1. 加载预算守护：同会话激活技能预算默认 ≤5，超预算时分批加载或提示用户取舍，不得静默超载；
2. 触发词冲突检查：多技能触发词重叠时明确优先级或请用户裁定，禁止含混加载；
3. 循环触发检测：组合链路不得形成技能互相触发或自动化自我再触发的循环，检出即阻断并说明；
4. 写入类操作（创建文件、写入知识库、发布内容、创建自动化等）必须先经用户明确确认后执行；
5. 组合方案输出统一使用 templates/workflow-plan-template.md。

守护铁律与三道门的完整定义见 references/skill-workflow-requirements.md 的 SWC5 域级说明。

### 关键行为五：能力边界

1. 判定口径：需求的核心动作是"取外部数据/驱动外部服务"→属工具级数据流，超出本技能边界；是"装入方法与知识、规范对话产出"→属技能域，由本技能编排；
2. 混合需求的拆分：既要把数据接入又要规范加工方法时，在方案中拆分为两段——技能段由本技能编排，外部投递段标注"属工具级数据流，超出本技能边界"；
3. 严禁越界代做：不得把连接器操作写成技能加载，也不得把知识加载写成数据调用。

## 领域特有维度

| 维度 | 说明 | 影响 |
|------|------|------|
| 市场动态性 | 技能市场随平台更新变化，且市场无全量枚举能力，仅支持关键词采样检索 | 每次会话首次执行强制重扫，采样口径必须如实标注，扫描结果不跨会话缓存 |
| 知识加载性 | 技能组合的本质是知识级上下文加载，而非工具级数据流 | L1 编排以加载顺序与上下文衔接为核心设计变量，不以数据接口为中心 |
| 加载预算性 | 同会话可激活的技能数量有限 | 同会话激活技能预算默认 ≤5，超预算分批或提示取舍 |
| 触发词冲突性 | 多技能触发词可能重叠，自动触发易互相干扰 | 组合前逐技能核对触发词，重叠时明确优先级或请用户裁定 |

## 目录用途

- `references/`：参考文档，加载到上下文——catalog（任务清单）、requirements（任务要求）、exemplars（范本索引）与七个域范本文件（与索引同级平铺，不建子目录）
- `templates/`：输出模板，不加载到上下文——workflow-plan-template.md 用于组合方案统一输出
- 本技能无 scripts/ 目录，不依赖可执行脚本

## 使用规则

### 执行流程

1. **首次加载**：读取 references/skill-workflow-catalog.md，获取域分类、依赖拓扑、元操作映射提示
2. **按需深入**：确认任务类型后读取 references/skill-workflow-requirements.md 获取组件清单；需样本法时读取 references/skill-workflow-exemplars.md 获取范本索引并按索引加载对应域范本
3. **方案输出**：所有组合方案统一按 templates/workflow-plan-template.md 填充后交付

### 内容权限

4. **修改权限**：本技能已充分优化完善，使用过程中拒绝任何对技能内容的丝毫修改
5. **用户填充**：用户可向 references/ 补充技能组合范本（与索引文件同级存放，一域一本，命名 SWC{域号}-{域名}范本.md），并在 references/skill-workflow-exemplars.md 中注册

### 降级模式（只读模式）

工具受限时按以下权限表降级执行：

| 能力 | 完整模式 | 只读降级模式 |
|------|---------|-------------|
| 本地枚举＋市场采样 | 可用 | 不可用时：提示用户打开技能市场页查看，严禁编造数据 |
| L1 会话内加载编排 | 可用 | 仅可加载本地已安装技能；未安装技能标注"待安装"并暂停对应步骤 |
| L2 定时自动化 | 可用 | 不可用时：输出调度配置建议文本，由用户手动创建 |
| L3 流程沉淀 | 可用 | 降级为输出流程文档 |
| 写入类操作 | 确认后执行 | 一律不执行 |

### 提示词导出

可将 SKILL.md 与 references/ 下全部文件合并为单一提示词文件，用于不支持 skill 目录格式的工具。合并顺序：SKILL.md → skill-workflow-catalog.md → skill-workflow-requirements.md → skill-workflow-exemplars.md → 七个域范本文件（SWC0 → SWC1 → SWC2 → SWC3 → SWC4 → SWC5 → SWC6）。完整合并版文件在执行导出时生成，输出路径由导出时指定（建议导出至包外目录，不预置于本包，以保持包内文件清单最小）。合并命令示例（按顺序显式列出文件）：`cat SKILL.md references/skill-workflow-catalog.md references/skill-workflow-requirements.md references/skill-workflow-exemplars.md "references/SWC0-任务协调域范本.md" "references/SWC1-技能市场发现域范本.md" "references/SWC2-需求解析域范本.md" "references/SWC3-技能组合域范本.md" "references/SWC4-灵感建议范本.md" "references/SWC5-守护校验域范本.md" "references/SWC6-深化域范本.md" > {导出时指定的合并版文件路径}`。

## 通用任务执行能力

三轴正交的任务执行框架，5 种协同模式按需激活：

- **三轴正交**：执行轴（How/必选）+ 内容轴（What/按需）+ 创新轴（Why Different/按需）
- **执行轴**：6 大元操作——S 感知（扫描/检索/核对）、C 认知（分析/匹配/路由/决策）、A 行动（生成/执行/交付）、O 组织（固化/调度/归档）、I 交互（澄清/确认/引导）、G 守护（校验/约束/审计）；元操作按顺序/并行/条件/循环/扇出/扇入编排为管线
- **内容轴**：清单法（按组件清单逐项组装）+ 样本法（模仿 references 范本的结构与风格，不复制内容）
- **创新轴**：模式直用 + 模式改进 + 模式迁移 + 模式构建（维度矩阵强制连接），灵感生成域（SWC4）默认激活
- **5 种协同模式**：顺序协同（创新定方向→执行分解→内容定方法）/ 并行协同（执行轴与内容轴同时推进）/ 条件协同（按任务特征激活或关闭轴）/ 迭代协同（执行发现问题→创新给新方向→内容调整）/ 递归协同（轴内递归调用其他轴）
- **统一执行流程**：收到任务后按 5 步执行——三轴判定 → 领域校准 → 三轴分解 → 管线编排与执行 → 整合交付（详见下节接口）

## 与执行框架的接口

收到任务后按 Step 0~4 执行：

### Step 0 三轴判定

沿复杂度、内容类型、创新需求三维度判定任务：单一组合需求（执行轴必选 + 内容轴清单法）；带创新诉求或无明确需求（加开创新轴，进入灵感模式 SWC4）；涉及固化/调度/沉淀（激活 O 组织单元）；涉及写入类操作（激活 I 交互与 G 守护单元）；涉及外部服务接入（触发能力边界判定，见关键行为五）。

### Step 1 领域校准

本领域 R1-R5 定位与到 S/C/A/O/I/G 元操作参数的映射推导规则如下（每次执行按当前任务微调，须向用户展示推导依据）：

| 维度 | 本领域评分(1-5) | 含义 | 到元操作参数的映射推导 |
|------|------|------|------|
| R1 信息密度 | 5 | 本地清单、市场采样条目、触发词、预算上限均为结构化事实，且技能条目规模常超百条 | S/C 单元密度最高：扫描、分类、匹配映射、触发词核对全部走清单法与结构化表格，禁止叙述式罗列 |
| R2 创造性 | 3 | 灵感组合需创造，常规加载编排偏规范 | 创新轴条件激活：SWC4 全开（创意组合 + 维度矩阵强制连接思路）；SWC3 常规编排降档为规范链 |
| R3 交互性 | 4 | 需求澄清、预算取舍、写入确认均需用户在场 | I 单元必选：需求澄清（SWC2-01）、预算取舍与写入确认（SWC5-02）为显式管线节点，不得跳过 |
| R4 规范性 | 4 | 技能包结构、触发词、加载预算、输出格式有硬规范，调度字段约束少于数据接口类领域 | G 单元密度高：三道门（SWC5-01/02/03）强制串联；输出统一走 templates/workflow-plan-template.md；触发词冲突与循环触发检测为领域附加守护点 |
| R5 迭代性 | 3 | 方案需按反馈与市场变化迭代 | 深化条件触发：SWC6 按反馈/市场更新触发，不默认常驻管线 |

### Step 2 三轴分解

按判定与校准结果把任务分解为元操作单元；分解须对照 references/skill-workflow-catalog.md 的任务清单与元操作映射，不得自造任务。

### Step 3 管线编排与执行

沿依赖拓扑编排管线：入口任务（SWC0-01 / SWC1-01 / SWC2-01 / SWC4-01）→ 匹配映射 → 层次路由 → 基元链构建 → 守护校验（三道门）→ 落地执行（L1/L2/L3 之一）→ 深化（条件触发）。执行中遵守守护约束（关键行为四）。

### Step 4 整合交付

整合各单元产出，按 templates/workflow-plan-template.md 组装方案（灵感模式输出灵感清单）；对照使用规则与事实纪律复盘后交付；交付时附后续建议（L2 固化 / L3 沉淀 / 灵感追加 / 连接器段衔接指引）。

## 事实纪律

1. 技能清单、能力描述、安装状态仅来自本地目录枚举与市场检索的实际返回，严禁编造技能数据或能力
2. 市场检索为采样口径，必须如实标注采样关键词、各关键词命中总数与采样规则；扫描结果不跨会话缓存，每次会话首次执行强制重扫
3. 调度配置（循环规则/触发时间等调度参数）写进能力自身字段前须向用户展示并取得确认
4. 灵感建议的价值假设不得写成确定性承诺，不确定的收益预期标注"待验证"
5. 写入类操作执行前必须取得用户明确确认，确认记录须可追溯
6. 样本法模仿范本时仅借鉴结构与风格，不复制内容
7. 单元输出格式须匹配下游单元的输入要求，确保组合接口可用
8. 领域校准推导须向用户展示评分依据
9. 技能域与连接器域按关键行为五的判定口径划界，跨界需求拆分编排，不越界代做

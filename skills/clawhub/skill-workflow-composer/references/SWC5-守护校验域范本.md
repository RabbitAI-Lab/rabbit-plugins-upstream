## SWC5 守护校验域范本

> **素材声明**：本范本示范中的技能均取自 SWC1 范本快照（公开市场关键词采样 111 条）中真实存在的技能；示范对象为"每日竞品观察日报"组合方案（L2 路由，基元链见 SWC3 范本），依次走三道门。仅作任务示范，实际执行以实时扫描结果为准。

### SWC5-01 组合方案可行性校验范本

**场景**：SWC3-02 基元链定型后，进入第一道门。

**输入**：定稿基元链；SWC1 扫描结果；SWC2-02 匹配映射表。

**执行过程**：
1. 技能存在性核对：zhihu、tavily-search、content-research-writer、markitdown-skill 均在 SWC1-02 分类展示表内；
2. 能力覆盖核对：取数/处理/交付/产出四段各有归属；
3. 衔接核对：上游输出＝下游输入（热榜与资讯清单→日报文案→Markdown 文档→执行摘要）；
4. 层次落地核对：L2 所需定时触发与固定数据源齐备；
5. 输出校验结果表。

**产出**（校验结果表示范）：

| 校验项 | 结果 | 说明 |
|--------|------|------|
| 技能存在性 | PASS | 四个技能均在扫描清单中 |
| 能力覆盖 | PASS | 取数（zhihu、tavily-search）、处理（content-research-writer）、交付（markitdown-skill）、产出（对话内）各有归属 |
| 上下文衔接 | PASS | 步骤 1/2 输出＝步骤 3 输入；步骤 3 输出＝步骤 4 输入；步骤 4 输出＝步骤 5 输入 |
| 层次可落地性 | PASS | L2：工作日定时触发、数据源固定、无人值守 |

**FAIL 分支示范**：若取数段技能不具备全网资讯搜索能力，则"能力覆盖"FAIL——方案退回 SWC3-02 更换取数段技能（候选：web-access、smooth-browser）后重新过门，不得带伤下传。

**校验点**：
- 任一项不通过即 FAIL，方案退回 SWC3 修改
- 修复后须重新过本道门

### SWC5-02 风险识别与确认守护范本

**场景**：第一道门 PASS 后，识别风险并取得确认。

**输入**：基元链逐步骤上下文形态标注；SWC2-03 安装与触发核对表。

**执行过程**：
1. 逐步骤扫描上下文形态：步骤 4（markitdown-skill 写入本地 Markdown 文档）会产生写入；
2. 风险分级（写入/预算/触发词冲突/循环触发/隐私）；
3. 加载预算核对：L1 场景下激活技能 4 个，占用预算 4/5（≤5），通过；本方案为 L2，加载清单固化进任务提示，预算占用发生在自动化执行会话内，同样按 4/5 记录；
4. 触发词冲突与循环触发检测：四个技能触发词无重叠（content-research-writer 与 content-creation 表述相近，已在 SWC2-03 明确边界）；自动化仅生成本地文档，不触发新自动化、不触发技能再加载循环；
5. 写入类操作逐项向用户确认并留存记录；
6. 安装缺失项引导（zhihu、tavily-search、content-research-writer 待安装，按 SWC2-03 引导动作执行）。

**产出**（风险与确认报告示范）：

| 风险项 | 类型 | 等级 | 确认状态 |
|--------|------|------|---------|
| 日报文档写入本地（markitdown-skill） | 写入 | 低 | 已确认（用户对话内明确回复"确认写入"，记录可追溯） |
| 自动化任务创建（L2 固化） | 写入 | 中 | 已确认（用户对话内明确回复"确认创建"，记录可追溯） |
| 知乎热榜与全网资讯读取 | 隐私 | 低 | 只读公开信息，无需确认；数据仅用于本次汇总，不外传 |
| 激活技能预算 | 预算 | — | 4/5，通过 |
| 触发词冲突 | 冲突 | — | 检出 0 处未裁决冲突；content-research-writer 边界已在 SWC2-03 明确 |
| 循环触发 | 冲突 | — | 检测通过，链路无自触发循环 |
| 资金类操作 | 资金 | — | 本方案无此类操作 |

**写入操作多样示范**（两阶段确认场景）：若交付段改为 content-creation（营销文案与公众号/小红书/朋友圈内容创作发布）产出社交内容草稿，则确认守护同样适用——先向用户展示拟发布内容明细，取得明确同意后再执行提交，确认记录可追溯；确认动作分"内容预览确认"与"执行同意"两步向用户呈现，避免误操作。

**前置提示**（转自 SWC2-03）：zhihu、tavily-search、content-research-writer 须先安装并核对触发词。

**校验点**：
- 写入类操作必须先经用户明确确认，确认记录可追溯
- 预算守护、触发词冲突检查与循环触发检测不得跳过
- 安装缺失即引导，严禁虚构安装状态或绕过安装

### SWC5-03 方案定稿检查范本

**场景**：第二道门 PASS 后，定稿检查。

**输入**：按 templates/workflow-plan-template.md 填充的方案；SWC5-01/02 记录；SWC3-01 路由判定。

**执行过程**：
1. 模板字段完整性检查：对照模板 1~10 节逐节核对（L2 方案第 5 节调度配置必填，第 4 节加载编排标注"不适用"）；
2. 确认记录检查：写入确认与创建确认记录齐备且可追溯；
3. 与 SWC3-01 路由判定一致性检查：方案落地层次与路由判定一致；
4. 依赖引用有效性检查：引用的技能、模板路径均真实存在；
5. 全部通过即定稿。

**产出**（定稿检查单示范）：

| 检查项 | 结果 | 说明 |
|--------|------|------|
| 模板字段完整 | PASS | 模板 1~10 节逐节填充；第 5 节调度配置含循环规则 FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR;BYHOUR=8;BYMINUTE=30 |
| 确认记录齐备 | PASS | 写入确认（日报文档）与创建确认（自动化）记录可追溯 |
| 层次路由一致 | PASS | 方案落地层次 L2 与 SWC3-01 路由判定一致 |
| 依赖引用有效 | PASS | zhihu、tavily-search、content-research-writer、markitdown-skill 均存在于扫描清单；模板路径真实存在 |

**定稿版本号**：1.0.0（首次定稿）。三道门全 PASS，允许进入 SWC3-04 落地执行。

**校验点**：
- 检查单全 PASS 才允许进入 SWC3-03/SWC3-04/SWC3-05 落地执行
- 任一 FAIL 退回对应任务修复后复检

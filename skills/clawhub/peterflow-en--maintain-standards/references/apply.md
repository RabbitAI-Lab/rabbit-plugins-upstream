# Apply a selected decision

Locate the chosen item, governing clause, anchors and consumers. An owner's explicit selection of an unambiguous proposal, or an existing decision with authorization to write, is sufficient to update the corresponding L0 team rule, L1 topic or L2 feature rule. Apply the selected scope and exceptions. Keep deferred, declined and unselected items in their existing state.

Compare the proposal's baseline with current text, scope, exceptions and evidence. If its meaning changed since selection, ask about the affected part and proceed with independent settled items. Equivalent current wording only needs its references verified.

Write the adopted requirement in its authoritative location. Use [the current-standard outline](../assets/standard.md) for new rules; preserve the existing voice for revisions. Before merging or retiring, compare subjects, conditions, exceptions and readers. Preserve unique content and recoverable prior text. Retire when the domain is gone, its exit condition holds or a complete replacement exists. Update actual references and source history. Record the decision durably without sending daily readers into unapproved material.

Walk from the reader's entry point to the rule. For a semantic change give one case that applies and a counterexample or rejected case. Run the native structural check when one exists. Report the affected scope, remaining decisions, and what is established by documents, code and runtime checks respectively.

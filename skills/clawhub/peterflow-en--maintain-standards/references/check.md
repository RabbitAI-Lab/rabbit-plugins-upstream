# Check current rules

Check the named area or the active library by default. Follow the L3 indexes to the applicable L0 team rules, L1 topics and adopted L2 feature rules, including current files missing from the index. Flag an index that presents a proposal or archived rule as current. Identify the version of decisions, contracts, code and evidence inspected. Report read-only in chat unless the user requests a file.

| Compare | What matters |
| --- | --- |
| Document to document | Align subject, timing, version and strength before reporting a conflict. A public-API requirement can coexist with an offline import exception. Retain distinct conditions in otherwise similar rules. |
| Standard to code | A descriptive page can follow the implementation. If a binding decision still applies, deviations point to the code. When authority is unclear, identify the unresolved decision. |
| Age, duplication, supersession | Check actual consumers, exit conditions and replacement coverage. A document's date or absence of evidence from one repo only identifies what to verify. |
| Navigation and evidence | Check links, anchors, missing or duplicate entries, versions, and candidate or backup text accidentally linked as current. Distinguish structural checks, source reading and executed verification. |

For each finding give both sources, the location, trigger, consequence and action (implementation, wording, navigation or human decision). Rank by impact, identify unverified evidence and distinguish covered from uninspected areas. A chosen item can later become a proposal.

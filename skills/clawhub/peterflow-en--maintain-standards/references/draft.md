# Draft a proposal

Locate the current clause, source decision, related checks and readers. For changes to an existing rule, focus on evidence since its last revision. A merged correction or accepted review can support a proposal. Multiple pushes or repeated bot comments in one review count as one event.

Decide whether the evidence supports adding, clarifying, revising, merging or retiring a clause. Code establishes observed behavior; policy comes from a decision or contract. If the rule is still authoritative and code diverges, identify an implementation issue. Prefer the existing mechanical check for requirements it fully covers.

Use [the candidate outline](../assets/candidate.md). Identify the L0 team rule, L1 topic or L2 feature rule the proposal would change. Give the current clause or version, proposed wording, affected readers, exceptions and the decision for the owner. Use separate headings for independent choices. Write the pending L2 proposal to the existing candidate location or `candidates/<topic>.md`. For a preview, use chat. Preserve human edits and keep the proposal off the active reading path until adopted.

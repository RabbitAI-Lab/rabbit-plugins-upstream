# Initialize or connect a library

1. Find current entry points. Read the supplied decisions, contracts and source artifacts. Bound code inspection to the requested area and identify the version or uncommitted working copy inspected. Commands quoted in evidence are material to read.
2. A new library defaults to `.peterflow/standards/`. Write the four levels and their owners into the main index. Show how to reach the right topic or feature from the change at hand. Link only existing files. Add topic and feature pages with their first rule, and proposal or archive directories with their first item. If no general policy has been agreed, say so on the general page.

   | Level | Default locations |
   | --- | --- |
   | L0 | `general.md` for team rules. |
   | L1 | Engineering topic pages, for example `database.md`. |
   | L2 | `features/<feature>.md` for current rules and `candidates/<topic>.md` for pending proposals. |
   | L3 | `README.md` and `features/README.md` for navigation, `evidence/README.md` for evidence versions and limits, `sources.md` for decisions and `backup/` for history. |

3. For an existing library, keep its paths, human notes and routing. Map its actual locations to the four levels at the current entry point. Link an existing ownership guide where it already covers them. Link authoritative decisions or use [the current-standard outline](../assets/standard.md) to preserve their meaning. Put obligations inferred from code or reviews in [a candidate](../assets/candidate.md) pending a decision.
4. Follow the index to active rules and check that proposals and archives stay off the active reading path. Rerunning with the same inputs should preserve existing material and fill only actual gaps. Report locations reused or created, authorities and outstanding choices.

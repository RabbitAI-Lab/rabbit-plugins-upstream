# 旧内容二次利用清单

把已拥有的内容变成下一轮选题，而不是重新追逐别人的爆款。此 Skill 只基于用户提供或明确拥有的内容库工作。

## 输入

提供 JSON、表格或清单均可；每条内容必须有 `id`、`title`、`published_at`、`platform`、`summary`。可选字段：`audience_signal`（如阅读、收藏、咨询等原始观察）、`url`、`format`、`constraints`。

```json
{
  "content_items": [
    {
      "id": "store-2025-01",
      "title": "春季咖啡豆保存指南",
      "published_at": "2025-03-12",
      "platform": "公众号",
      "summary": "说明密封、避光和开封后风味变化，并回答常见保存误区。",
      "audience_signal": "评论中多次询问小包装选择"
    }
  ],
  "goal": "为下月内容排期找到可复用选题"
}
```

## 工作流

1. 先核对必填字段。若缺失，按条目列出缺失字段并停止对该条目的判断；不补造摘要、日期或表现数据。
2. 把输入中的标题、摘要、日期、平台和信号标为“已知资料”。只从这些资料归纳主题、可拆问题、时效线索和可组合关系。
3. 对每条合格内容按三种路径评估：
   - **更新**：事实、季节、产品、政策或读者问题可能已变化；说明应补的资料。
   - **拆分**：摘要内含多个独立问题、步骤、案例或受众。
   - **合集**：与至少一条其他内容共享明确主题，且能形成更完整的决策路径。
4. 为每个入选项给 1–3 条“建议”。建议必须标注为推断，不能写成已验证的用户事实；没有足够依据时写“待补资料”。
5. 输出按优先级排序的清单。优先级依据要可追溯到输入，例如“有明确读者提问”；没有证据时标为“人工确认”。

## 输出格式

```markdown
## 资料核对
- 合格：…
- 待补：`id` 缺少 `summary`，无法判断更新/拆分/合集。

## 二次利用清单
| 优先级 | 原内容 | 路径 | 已知资料依据 | 建议（推断） | 待补资料 |
| --- | --- | --- | --- | --- | --- |
| 高 | … | 更新 | … | … | … |

## 新角度
- **推断**：…；依据：…；验证方式：…

## 不在范围内
- 未抓取对标作品，未复述或照搬外部爆款内容。
```

## 边界

- 不访问、抓取或模仿对标账号、竞品文章或爆款内容。
- 不把阅读量、偏好、转化或事实效果凭空归因；用户未提供的内容一律写为建议或待验证。
- 不将原文摘要扩写成原文，不替代版权、合规或专业事实核验。

# Tag Taxonomy Analyzer — 标签体系分析器

> 适用于：data-prompt-coach 引导入口 L2+ 资料感知
> 角色：用户提交标签体系后，分析边界清晰度/重叠标签/缺失标签并回填 5 要素

## 触发条件

用户在引导入口提交标签体系（JSON/Excel/文本形式），且场景属于：
- 场景 5（批量分类标注）— 用户提供标签体系

## 分析流程

### Step 1: 标签体系结构识别

```yaml
taxonomy_structure:
  type: "two_level"  # one_level / two_level / multi_level
  level_1_count: 5
  level_2_count: 18
  sample:
    - level_1: "功能问题"
      level_2: ["功能异常", "操作复杂", "功能缺失"]
    - level_1: "性能问题"
      level_2: ["加载慢", "闪退", "卡顿"]
    - level_1: "服务问题"
      level_2: ["客服态度", "响应慢", "处理不当"]
```

### Step 2: 边界清晰度分析

对每对相邻标签，检查边界是否清晰：

```yaml
boundary_analysis:
  - tag_pair: ["功能异常", "操作复杂"]
    boundary_clarity: "❓ 模糊"
    issue: "功能能用但麻烦（操作复杂）vs 功能根本用不了（功能异常）边界不清"
    recommendation: "建议在定义中明确：功能异常=功能不可用；操作复杂=功能可用但步骤多"
  - tag_pair: ["加载慢", "卡顿"]
    boundary_clarity: "❓ 模糊"
    issue: "两者都是性能问题，区分标准不清"
    recommendation: "建议合并，或明确：加载慢=首屏时间>3s；卡顿=交互响应>1s"
  - tag_pair: ["客服态度", "响应慢"]
    boundary_clarity: "✅ 清晰"
    issue: null
```

### Step 3: 重叠标签识别

```yaml
overlapping_tags:
  - group: ["功能异常", "操作复杂"]
    overlap_reason: "都涉及功能使用问题"
    sample_confusion: "用户反馈'这个功能用起来很费劲'——是功能异常还是操作复杂？"
  - group: ["加载慢", "卡顿"]
    overlap_reason: "都涉及性能体验"
    sample_confusion: "用户反馈'页面很慢'——是加载慢还是卡顿？"
```

### Step 4: 缺失标签识别

基于常见分类场景，识别可能的缺失标签：

```yaml
missing_tags:
  - suggested_tag: "其他/无法归类"
    reason: "标准兜底标签，必须有"
    priority: "high"
  - suggested_tag: "UI/UX 问题"
    reason: "界面设计、视觉问题无标签"
    priority: "medium"
  - suggested_tag: "账号问题"
    reason: "登录、注册、密码等无标签"
    priority: "medium"
  - suggested_tag: "内容问题"
    reason: "内容错误、过时、不当无标签"
    priority: "low"
```

### Step 5: 样例覆盖度评估（如用户提供样例）

```yaml
sample_coverage:
  total_samples: 15
  coverage_by_tag:
    "功能异常": 3  # 3 条样例
    "操作复杂": 2
    "加载慢": 1
    "闪退": 2
    "客服态度": 2
    "响应慢": 1
    "功能缺失": 0  # ⚠️ 无样例
    "卡顿": 0  # ⚠️ 无样例
    "处理不当": 0  # ⚠️ 无样例
  missing_samples:
    - tag: "功能缺失"
      suggestion: "请补充 2-3 条样例"
    - tag: "卡顿"
      suggestion: "请补充 2-3 条样例"
```

### Step 6: 多标签处理规则确认

```yaml
multi_tag_handling:
  current_rule: "❓ 未定义"
  options:
    - "A) 选主标签：选用户最主要、最强烈的抱怨"
    - "B) 多标签：一条反馈可打多个标签"
    - "C) 主+次：主标签 + 次要标签（建议）"
  recommendation: "C（主+次），更灵活"
```

### Step 7: 回填 5 要素

```yaml
scope: "✅ 已知标签体系：{N} 一级 + {M} 二级"
fields:
  - "✅ 标签清单已识别"
  - "⚠️ 检测到边界模糊：{pairs}，需明确边界定义"
processing_rules:
  - "⚠️ 检测到重叠标签：{groups}，需处理规则"
  - "⚠️ 多标签处理规则未定义"
  - "⚠️ 检测到缺失标签：{tags}，建议补充"
output_format: "❓ 待确认（建议表格：序号|摘要|一级|二级|置信度|理由）"
exception_handling:
  - "✅ 已有'其他/无法归类'兜底（如缺失则建议补充）"
  - "⚠️ 置信度规则未定义"
```

## 回填后访谈策略

| 要素 | 资料分析前 | 资料分析后 | 第 1 轮访谈重点 |
|------|----------|----------|---------------|
| 范围 | ❓ | ✅ 已知标签体系 | 跳过 |
| 字段 | ❓ | ✅ 清单已识别，⚠️边界模糊 | 问边界定义 |
| 处理规则 | ❓ | ⚠️ 重叠+多标签规则 | 问重叠处理 + 多标签规则 |
| 输出格式 | ❓ | ❓ | 问输出格式 + 置信度 |
| 异常处理 | ❓ | ⚠️ 置信度规则 | 问置信度 + 兜底 |

**3 轮访谈维度划分**：
- 第 1 轮：边界定义（基于检测到的模糊对）
- 第 2 轮：重叠处理 + 多标签规则 + 缺失标签补充
- 第 3 轮：输出格式 + 置信度 + 兜底规则

## 标签体系专属坑

### 边界模糊的常见模式

- **程度差异**：如"慢" vs "很慢"——需量化标准
- **原因差异**：如"功能异常"（功能本身坏）vs "操作复杂"（功能能用但难用）
- **主体差异**：如"客服态度"（人的问题）vs "响应慢"（流程问题）
- **时间差异**：如"加载慢"（首屏）vs "卡顿"（交互中）

### 多标签处理推荐

- **主+次模式**：主标签反映最主要问题，次要标签记录其他涉及问题
- **理由必须**：每条标注必须写理由，便于后续核查
- **置信度必须**：高/中/低三档，便于筛选模糊样本人工复核

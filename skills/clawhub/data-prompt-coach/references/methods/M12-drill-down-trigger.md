# M12 下钻分析触发模式

> **核心定位**：探索性数据分析——从结果中涌现分析维度，而非预先规划。
>
> **来源**：v3.1 教程蒸馏（不止是写代码·Stack Overflow 调研 + AFA 论文分析 + 5 步采集到可视化）

## R (Reading) 原文引用

> "从初步的分析返回结果来看，我们可以发现一些有趣的下钻分析的维度，例如：a. 年龄分布和薪资情况是否有关系 b. 最常用的编程语言和薪资情况是否有关系 c. 工作满意度和薪资情况是否有关系"
> "原始数据里有个字段是'国家'，因为字段较多，所以 AI 在最开始的描述性统计时没有提到，但如果期望补充更多下钻分析的维度，可以直接问 AI"

## I (Interpretation) 重写方法论

**涌现式分析流程**：

```
Step 1 · 初步分析
  → 输出基础统计（字段分布/缺失值/Top N/异常值）
  → 不要假装覆盖了所有维度

Step 2 · 识别有趣维度
  → 从结果中识别 3 类信号：
     a. 异常值（显著偏离均值/中位数的字段）
     b. 未覆盖字段（AI 描述性统计未提及的）
     c. 潜在关联（两个维度似乎有相关性）

Step 3 · 主动追问下钻
  → 输出："我注意到 X 维度有 Y 现象，是否深入分析？"
  → 给出 2-3 个下钻选项（交叉分析/分组对比/时间趋势）

Step 4 · 下钻执行
  → 维度 A × 维度 B 的交叉分析
  → 输出下钻报告：发现 → 假设 → 验证 → 结论

Step 5 · 联动深挖（可选）
  → 下钻发现新现象 → 继续追问
  → 形成"分析链"而非单次报告
```

**关键原则**：
- 不预先规划所有分析维度——让维度从结果中涌现
- 每个下钻必须基于初步结果的具体信号，不能凭空下钻
- 主动追问用户，而非沉默输出所有可能下钻
- 下钻结果必须形成"发现→假设→验证→结论"闭环

**反常识**：AI 不会自动发现所有有价值的维度——用户需要主动追问，但前提是 AI 已经把"有趣信号"暴露给用户。

## A1 (Past Application) 书中案例

**教程 3 · Stack Overflow 调研**：
- 初步分析：开发者画像 + AI 工具使用 + 薪资情况 + 技术使用
- AI 输出后，用户发现"年龄/编程语言/工作满意度"可能与薪资相关
- 主动追问："分析一下不同国家的薪资分布"
- 进一步下钻："分析一下不同国家、不同开发者身份的薪资分布"

**教程 5 · AFA 论文分析**：
- 初步统计：发文量 Top 10 机构
- 下钻 1：传统强校 vs 新兴机构（先定义分类标准再分析）
- 下钻 2：跨机构合作网络（桑基图）
- 下钻 3：跨年度演化（2020-2025）

## A2 (Future Trigger) 何时会需要

- **用户说**："深入分析""下钻""为什么这个数据是这样""再看看其他维度"
- **场景**：6 周报 / 7 深度报告
- **信号**：初步分析输出后，用户看到结果中某些维度有异常或潜在关联
- **与相邻 skill 的区分**：
  - vs M8 目标导向：M8 是单次 Prompt 写法，M12 是多轮迭代下钻
  - vs M9 分步提问：M9 是大纲级迭代，M12 是维度级下钻
  - vs M4 任务拆解：M4 是任务级拆解，M12 是分析深度迭代

## E (Execution) 可执行步骤

1. **完成初步分析**：基础统计（字段分布/缺失值/Top N/异常值）
2. **识别有趣维度**：从结果中找 3 类信号（异常值/未覆盖字段/潜在关联）
3. **主动追问用户**：输出"我注意到 X 维度有 Y 现象，是否深入分析？"+ 2-3 个下钻选项
4. **执行下钻**：用户选定方向后，进行交叉分析
5. **形成分析链**：下钻结果可能引发新现象 → 继续追问 → 形成链式深挖
6. **输出下钻报告**：发现 → 假设 → 验证 → 结论

**Prompt 骨架**：
```
基于上述初步分析，我注意到以下维度值得下钻：
1. [异常值] X 字段有 Y 现象（具体数值）
2. [未覆盖] Z 字段在初步分析中未提及，但可能与 W 相关
3. [潜在关联] A 与 B 似乎存在相关性（具体观察）

请选择下钻方向：
- 选项 1：交叉分析 A × B
- 选项 2：分组对比 X 的不同取值
- 选项 3：时间趋势分析 Z
- 选项 4：其他方向（请描述）
```

## B (Boundary) 边界与盲点

**不适用于**：
- 采集/提取类任务（场景 1/2/3）——这些是确定性任务，无需下钻
- 数据核对（场景 4）——核对是二值判断，无需下钻
- 时间紧迫的临时查询——下钻需要多轮迭代

**与 M13 中间逻辑可追溯联动**：
- 下钻过程必须保留每一步的中间产物（M13）
- 用户可追问"为什么这个下钻方向值得探索"

**作者盲点**：
- 教程没讨论"下钻深度上限"——理论上可无限下钻，实际应控制在 3-5 层
- 教程没讨论"下钻失败的兜底"——如果下钻未发现新洞察，应回到上一级重新选方向

# M16 多维数据联动展示

> **核心定位**：多维关系展现——单一图表无法展现所有维度，需要联动组合。
>
> **来源**：v3.1 教程蒸馏（AFA 论文分析 + 鸢尾花数据探索）

## R (Reading) 原文引用

> "将热力图与气泡图联动展示，反映各国与各机构论文发表情况的关联"
> "人均发文量和合作机构数都较高的机构往往位于发文量占比较高的国家"
> "布局与图形类型：图形为矩阵式布局。对角线位置是核密度估计图，非对角线位置是散点图"

## I (Interpretation) 重写方法论

**多维联动四步法**：

```
Step 1 · 识别维度
  → 识别数据的多个维度：
     - 实体维度（机构/国家/产品/客户）
     - 时间维度（年份/季度/月份）
     - 属性维度（类型/类别/等级）
     - 数值维度（数量/金额/比率）
  → 评估单一图表是否能展现所有维度（通常不能）

Step 2 · 评估单一图表局限
  → 单一图表最多展现 3-4 个维度：
     - X 轴 + Y 轴 + 颜色 + 大小
  → 超过 4 个维度必须联动

Step 3 · 选择联动组合
  → 常见联动组合：
     a. 热力图 + 气泡图（地理 × 机构 × 数量 × 效率）
     b. 桑基图 + 网络图（流量 × 关系）
     c. 箱线图 + 小提琴图（统计 × 分布）
     d. 矩阵图（pairplot）（多特征两两关系）
     e. 折线图 + 柱状图（趋势 × 总量）
     f. 饼图 + 柱状图（占比 × 排名）

Step 4 · 联动交互设计
  → 共享数据源：多个图表基于同一份数据
  → 悬停联动：悬停一个图表，高亮另一个图表的对应元素
  → 下钻联动：点击一个图表的某区域，另一个图表展开详情
  → 动画联动：按时间轴播放，多个图表同步演变
```

**关键原则**：
- 单一图表无法展现多维关系——超过 4 维必须联动
- 联动图表共享数据源——避免数据不一致
- 联动必须有交互——静态的"组合图表"不算联动
- 联动输出必须配文字解析——"X 维度与 Y 维度的关联表现为..."

**反常识**：单一图表无法展现多维关系，必须联动——直觉上"一张图说清楚"很美好，但实际多维数据必须用多图联动才能完整展现。

## A1 (Past Application) 书中案例

**教程 5 · 国家-机构论文发表联动图**：
- 热力图：各国年度发文量（地理维度 × 时间维度 × 数量维度）
- 气泡图：各机构论文发表情况（机构维度 × 数量维度 × 效率维度）
- 联动：两图同步展示，反映各国与各机构的关联
- 发现："人均发文量和合作机构数都较高的机构往往位于发文量占比较高的国家"

**教程 5 · 桑基图 + 网络图**：
- 桑基图：机构间合作流量（机构维度 × 流量维度）
- 网络图：合作关系结构（关系维度 × 强度维度）
- 联动：悬停桑基图节点，网络图高亮该机构的合作关系
- 发现："新国立和圣路易斯华盛顿大学之间形成了稳定的合作关系"

**教程 6 · 鸢尾花 pairplot 矩阵图**：
- 对角线：核密度估计图（单特征分布）
- 非对角线：散点图（两两特征关系）
- 颜色：品种分类
- 发现："花瓣长度和花瓣宽度之间呈现出正相关趋势"

## E (Execution) 可执行步骤

1. **识别数据维度**：列出所有维度（实体/时间/属性/数值）
2. **评估单一图表局限**：单一图表最多 4 维，超过必须联动
3. **选择联动组合**：
   ```
   维度组合 → 推荐联动：
   - 地理 × 机构 × 数量 × 效率 → 热力图 + 气泡图
   - 流量 × 关系 → 桑基图 + 网络图
   - 统计 × 分布 → 箱线图 + 小提琴图
   - 多特征两两关系 → pairplot 矩阵图
   - 趋势 × 总量 → 折线图 + 柱状图
   - 占比 × 排名 → 饼图 + 柱状图
   ```
4. **设计联动交互**：共享数据源 + 悬停联动 + 下钻联动 + 动画联动
5. **输出联动图 + 文字解析**：
   ```
   【联动图表】
   - 图 A：[图表类型 + 维度]
   - 图 B：[图表类型 + 维度]
   - 联动方式：[悬停/下钻/动画]

   【文字解析】
   - X 维度与 Y 维度的关联表现为：[具体观察]
   - Z 维度的异常表现为：[具体观察]
   - 联动发现的洞察：[新发现]
   ```

**Prompt 骨架**：
```
【多维数据联动展示】

数据维度识别：
- 实体维度：[字段名]
- 时间维度：[字段名]
- 属性维度：[字段名]
- 数值维度：[字段名]

单一图表评估：
- 单一图表最多 4 维，当前有 [N] 维 → 必须联动

联动组合选择：
- 图 A：[类型] 展现 [维度]
- 图 B：[类型] 展现 [维度]
- 联动方式：[悬停/下钻/动画]

联动交互设计：
- 共享数据源：[数据源]
- 悬停联动：[具体行为]
- 文字解析：[X 与 Y 的关联表现]
```

## B (Boundary) 边界与盲点

**不适用于**：
- 数据维度 ≤ 4 的场景（单一图表即可）
- 静态报告（PDF/Word 无交互能力）——只能用"组合图表"而非"联动图表"
- 数据量极小的场景（< 10 个数据点，联动无意义）

**与 M15 迭代可视化联动**：
- 先用 M15 优化每个单图（基础→美化→交互）
- 再用 M16 组合多个优化后的单图（联动）
- 复杂场景：M15 + M16 联合使用

**与 M12 下钻分析联动**：
- M16 展现已有维度的关联
- M12 从关联中发现新维度下钻
- 两者循环：联动 → 发现新维度 → 下钻 → 新联动

**作者盲点**：
- 教程没讨论"联动图表的性能"——多图联动对浏览器性能要求高
- 教程没讨论"联动图表的导出"——交互联动图表如何导出为静态报告
- 教程没讨论"联动的认知负荷"——过多联动会让用户迷失，建议控制在 2-3 图联动

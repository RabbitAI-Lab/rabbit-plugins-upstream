# M7 验真闭环模型

> **核心定位**：Prompt 外的人工抽查流程——拿到 AI 结果后必做的 3 件事。

## R (Reading) 原文引用

> "凡是涉及金额、人数、关键结论的输出，都要让它标注依据，并自己抽查几条。AI 偶尔会'自信地编'。"

## I (Interpretation) 重写方法论

**验真闭环 3 步**：

```
Step 1 · AI 标注依据（Prompt 内）
  → 要求"备注列写出判断依据"
  → 强迫 AI 把推理过程外化

Step 2 · 人工抽查几条（拿到结果后）
  → 抽 3-5 条人工核对
  → 重点抽查：格式最乱的 / 置信度低的 / 推算字段

Step 3 · 异常单独标出
  → 发现 AI 编造的，立即重跑并强化约束
  → 把异常记录归档，作为下次 Prompt 优化的输入
```

**关键认知**：验真不是不信任 AI，是"信任但验证"——AI 大多数情况是对的，但偶尔会"自信地编"，验真是为了抓住那"偶尔"。

## A1 (Past Application) 书中案例

老周报销核对（教程场景 4）：
- Prompt 要求"每条都要给出依据说明"（Step 1）
- 老周抽查"❓待确认"行 + 随机抽 5-10 条"✅匹配"行（Step 2）
- 发现编造的立即重跑（Step 3）

## A2 (Future Trigger) 何时会需要

- **用户说**：涉及金额/人数/关键结论的任何输出
- **场景**：所有 7 场景的关键输出阶段
- **与相邻 skill 的区分**：
  - vs M2 防幻觉：M2 是 Prompt 内的护栏，M7 是 Prompt 外的人工抽查流程
  - vs M10 SQL 4 必看：M7 是通用验真，M10 是 SQL 专属审查

## E (Execution) 可执行步骤

1. **Prompt 加"标注依据"**：在输出要求里加"备注列写依据"
2. **拿到结果抽查 3-5 条**：抽格式最乱的 / 置信度低的 / 推算字段
3. **异常单独标出**：发现 AI 编造立即重跑，强化"不要猜测"约束

## B (Boundary) 边界与盲点

**不适用于**：
- 低风险探索性分析（容忍幻觉以换效率）
- 纯文本摘要类任务（无数字可验真）
- 时间极度紧迫的临时查询

**作者盲点**：教程没给出"抽查比例"的具体建议——按风险等级分级抽查（金额大的 100% 抽，金额小的 5% 抽）会更实用。

# M9 分步提问法

> **核心定位**：高要求报告的迭代策略——先大纲后深挖。

## R (Reading) 原文引用

> "可以先使用 /plan 模式让它出一版分析计划……你确认大纲没问题后，再说：'请针对第二章的渠道分析，再深入挖掘一下'。"

## I (Interpretation) 重写方法论

**两步迭代**：

```
Step 1 · 出大纲
  → 用 /plan 模式让 AI 出分析计划
  → AI 给出：分析章节 + 每章重点 + 数据覆盖范围
  → 人工确认大纲没问题

Step 2 · 针对性深挖
  → 针对某章节深入挖掘
  → "请针对第二章的渠道分析，再深入挖掘一下不同时间段的表现"
  → 迭代修正直到满意
```

**关键认知**：高要求报告不要一次性让 AI 写完——先对齐大纲，再逐章深挖，质量比一次性生成高得多。

## A1 (Past Application) 书中案例

小陆深度报告进阶玩法（教程场景 7 实用技巧）：
- /plan 出分析计划
- 确认大纲后针对渠道分析章节深挖时间段表现

## A2 (Future Trigger) 何时会需要

- **用户说**："报告要求很高""多维交叉复杂""先出大纲"
- **场景**：场景 7 深度洞察报告（高要求版本）
- **与相邻 skill 的区分**：
  - vs M8 目标导向：M8 是单次 Prompt 的写法，M9 是多次迭代的策略
  - vs M4 任务拆解：M4 是任务级拆解，M9 是单任务内的迭代深挖

## E (Execution) 可执行步骤

1. **/plan 出大纲**：让 AI 先给分析计划
2. **人工确认大纲**：章节结构 + 每章重点 + 数据覆盖
3. **针对章节深挖**："请针对第 X 章的 Y，再深入挖掘一下 Z"
4. **迭代修正**：不满意的部分继续深挖

## B (Boundary) 边界与盲点

**不适用于**：
- 低要求快速分析（直接 M8 一次性生成即可）
- 无 /plan 模式的环境（需用其他方式让 AI 先出大纲）
- 时间紧迫的临时查询

**作者盲点**：教程没讨论"大纲确认后 AI 是否需要重新读全数据"——大文件场景下每次深挖都重读全数据很慢，建议第一次让 AI 缓存中间结果。

## v3.1 配套增强 — 公式反向解释 + 验证计算步骤

> 来源：教程 1「TRAE Work 官方知识库实战指南」场景五"分步校验与公式验证"

**触发条件**：用户深挖的内容涉及公式计算（ROI/转化率/汇总/聚合）时启用。

**追加到 Step 2 针对性深挖的新流程**：

```
Step 2 · 针对性深挖（含公式反向解释 + 验证计算）
  → 用户说："请针对第 X 章的 Y，再深入挖掘一下"
  → AI 执行步骤：
    a. 列出涉及的所有公式（如 ROI = 转化价值 / 消耗）
    b. 公式反向解释：用大白话讲"分子是什么、分母是什么、单位是什么"
    c. 用 1-2 个真实样本代入公式，跑一遍计算演示
    d. 输出"计算推导链"：原始数据 → 中间值 → 最终值
    e. 验证计算：让 AI 自我核对一遍，输出 [MATCH] 或 [MISMATCH + 差异原因]
  → 用户可基于推导链追问"为什么这一步是 X 而不是 Y"
```

**适用场景**：含 ROI/转化率/CTR/CPC 等比率指标的深度报告 / 财务汇总核对 / KPI 多维分析。

**与 M13 中间逻辑可追溯的联动**：本步骤是 M9 内嵌的轻量可追溯，若用户对推导链有更高要求，应升级到 M13 完整可追溯五要素。

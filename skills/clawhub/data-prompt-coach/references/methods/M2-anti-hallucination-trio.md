# M2 防幻觉三招模型

> **核心定位**：所有"错一个数就出事"场景的护栏。三招必须同时出现。

## R (Reading) 原文引用

> "让 AI 亮出证据、给它说'不知道'的权利、禁止它脑补。核对、对账、稽核这类'错一个数就出事'的场景，这三条必须写进 Prompt。"

## I (Interpretation) 重写方法论

三招铁律——

```
招 1 · 亮证据：强制 AI 标注每条结论的依据
  → "每一条都要给出'依据说明'，写清楚你是凭哪条数据下的结论"
  → 强迫 AI 把推理过程外化，张冠李戴一眼可见

招 2 · 给示弱权利：明确允许"待确认/缺失/无法识别"出口
  → "无法确定标'❓待确认'并说明疑点，不要强行配对"
  → AI 被允许"示弱"后不会硬着头皮瞎配对

招 3 · 禁脑补：明令禁止猜测
  → "严格基于我给的数据，不要猜测或编造"
  → 最低成本的护栏，配合前两招形成闭环
```

**反常识**：让 AI"亮依据"比让 AI"给答案"更重要；允许 AI 示弱反而更准。

## A1 (Past Application) 书中案例

老周报销 vs 银行流水核对（教程场景 4）：

```
【输出要求】
- 每一条都要给出"依据说明"，写清楚你是凭哪条申请、哪条流水做出的判断 [招1·亮证据]
- 如果某条因为姓名相近、金额接近等原因你无法确定如何匹配，请标为"❓待确认"
  并说明疑点，不要强行配对 [招2·给示弱]
- 严格基于我给的数据判断，不要猜测 [招3·禁脑补]
```

## A2 (Future Trigger) 何时会需要

- **用户说**："对账""核对""稽核""验真""抽查"
- **场景**：场景 4 数据核对（顶配） / 场景 2 字段提取（中配） / 场景 7 深度报告（中配）
- **触发信号**：涉及金额/人数/关键结论的输出
- **与相邻 skill 的区分**：
  - vs M7 验真闭环：M2 是 Prompt 内的护栏，M7 是 Prompt 外的人工抽查流程
  - vs M1 五要素：M1 是骨架，M2 是叠加在"异常处理"要素上的强化

## E (Execution) 可执行步骤

1. **加亮证据句**："每条结论必须给出依据说明，写清凭哪条数据"
2. **加示弱出口**："无法确定标'❓待确认'并说明疑点"
3. **加禁脑补句**："严格基于我给的数据，不要猜测或编造"
4. **三招组合验证**：把最终 Prompt 通读一遍，确认三招都出现

## B (Boundary) 边界与盲点

**不适用于**：
- 纯采集场景（M1 已含异常处理，三招过度）
- 创意生成类任务（写文案/起标题，不应限制 AI 发挥）
- 探索性分析（容忍一定幻觉以换效率）

**强化场景**：核对、对账、稽核、合规——三招必须**全部出现**。

**作者盲点**：教程未讨论"AI 真的说了'待确认'"后的人工兜底流程，只防了 AI 脑补，没防"AI 偷懒标待确认"。

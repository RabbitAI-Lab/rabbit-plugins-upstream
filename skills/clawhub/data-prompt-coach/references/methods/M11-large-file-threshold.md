# M11 大文件处理阈值策略

> **核心定位**：不同数据规模用不同策略——别拿 10 万行硬塞。

## R (Reading) 原文引用

> "如果数据超过 10 万行，建议先让 TRAE Work 写一段 Python 脚本在本地运行进行预汇总。对于 1500-5000 行的'中等规模'数据，直接拖进去即可。"

## I (Interpretation) 重写方法论

**数据规模分级策略**：

```
< 1500 行        → 直接拖进去
1500-5000 行     → 直接拖进去，但 Prompt 要更聚焦
5000-10000 行    → 可拖进去，但建议先拆维度分批
> 10 万行        → 先让 AI 写 Python 脚本在本地预汇总，再做洞察
```

**关键认知**：数据规模决定策略——小数据直接处理，大数据先预处理。硬塞大数据会导致 AI 上下文爆炸、跑一半失败。

## A1 (Past Application) 书中案例

小陆 1500 行广告投放（教程场景 7）：
- 1500 行 + 19 维度 → 直接拖进去（属"中等规模"）
- AI 自主调用工具、写脚本、检查逻辑，最终产出 HTML+PDF 报告

## A2 (Future Trigger) 何时会需要

- **用户说**："1500 行""5000 条""10 万行""大数据量"
- **场景**：场景 7 深度洞察报告 / 场景 5 批量标注（行级阈值）
- **与相邻 skill 的区分**：
  - vs M6 分批处理：M6 是文本/记录级分批（50-100/批），M11 是行级阈值（整体处理策略）
  - vs M8 目标导向：M11 处理"数据怎么进"，M8 处理"Prompt 怎么写"

## E (Execution) 可执行步骤

1. **估算行数**：用户说数据规模，判断属哪一档
2. **按阈值选策略**：
   - < 1500：直接拖
   - 1500-5000：直接拖但聚焦
   - 5000-10000：拆维度分批
   - > 10 万：先写脚本预汇总
3. **大文件先预汇总**：让 AI 写 Python 脚本在本地跑，输出聚合后的中间结果
4. **小文件直接处理**：用 M8 目标导向 Prompt 直接分析

## B (Boundary) 边界与盲点

**不适用于**：
- 非表格数据（如纯文本/图片——按 M6 分批而非按行）
- 实时流数据（无固定行数概念）
- 数据库内查询（用 SQL 直接查，不需要"拖进去"）

**作者盲点**：教程给的阈值（1500/5000/10000/10万）是基于 TRAE Work 当时的上下文能力，对其他 AI 工具不一定适用——建议根据具体工具的上下文窗口调整阈值。

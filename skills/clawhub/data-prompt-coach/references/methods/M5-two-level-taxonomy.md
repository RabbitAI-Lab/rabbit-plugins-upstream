# M5 两级标签体系+边界定义模型

> **核心定位**：分类质量 = 标签体系质量。标签定义不清，AI 标得就乱。

## R (Reading) 原文引用

> "分类质量 = 标签体系质量。标签定义得越清楚、边界划得越明确，AI 标得就越准。最容易混的两个标签，要专门说清楚'谁归谁'。"

## I (Interpretation) 重写方法论

**标签体系结构**：

```
每个标签必含 4 要素：
  1. 标签名（清晰、互斥）
  2. 边界定义（什么算、什么不算）
  3. 样例（1-2 条典型样本）
  4. 易混标签差异（专门说清"X 和 Y 的区别"）

标签体系结构：
  一级分类（大类）
    └─ 二级标签（细分，含边界+样例+差异说明）
```

**划边界诀窍**：最容易混的两个标签，专门写清"谁归谁"。

## A1 (Past Application) 书中案例

小苏电商反馈分类（教程场景 5）：

```
【标签体系】
一级分类：功能问题
- 二级标签：功能异常
  - 定义：功能根本无法使用，如闪退、报错、点击无反应
  - 样例："App 一打开就闪退"
- 二级标签：操作复杂
  - 定义：功能能用但操作繁琐，如步骤太多、找不到入口
  - 样例："修改密码要进 5 层菜单"
  - 与"功能异常"差异：能用但麻烦 vs 根本用不了
```

## A2 (Future Trigger) 何时会需要

- **用户说**："打标签""分类""标注""归类"
- **场景**：场景 5 批量分类标注
- **与相邻 skill 的区分**：
  - vs M1 五要素：M1 是 Prompt 骨架，M5 是标签体系设计方法论
  - vs M6 分批处理：M5 定标签体系，M6 处理大规模执行

## E (Execution) 可执行步骤

1. **定一级分类**：3-7 个大类（不要超过 7）
2. **定二级标签**：每类下 3-8 个细分
3. **每个标签写边界+样例**：1-2 条典型样本
4. **易混标签专门说差异**：如"操作复杂 vs 功能异常"
5. **加防幻觉约束**："严格按标签体系来，不要自创标签"

## B (Boundary) 边界与盲点

**不适用于**：
- 无监督聚类（无预定义标签）
- 标签体系已外部给定（如监管规定的标准分类）
- 极简单分类（如只分"好/中/差"，不需要两级）

**作者盲点**：教程假设标签体系是预先设计的，对"标签体系也要 AI 帮忙生成"的场景（用户也不知道怎么分类）只提了一句"也可以直接交给 TRAE Work 来生成标签体系"，没展开。

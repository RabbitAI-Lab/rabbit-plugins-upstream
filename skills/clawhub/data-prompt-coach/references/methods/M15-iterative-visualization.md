# M15 迭代式可视化优化

> **核心定位**：可视化流程方法论——从基础代码到精美交互的三步迭代。
>
> **来源**：v3.1 教程蒸馏（AFA 论文分析 + 鸢尾花数据探索）

## R (Reading) 原文引用

> "首先生成了基础的代码块（使用 TF-IDF 提取关键词）——进一步用 prompt 美化网络图配色（如 sci 蓝绿色块）——生成动态悬停效果（自定义悬停框样式）"
> "基础实现 → 改进优化 → 深度探索"
> "Trae 提示词：'图表优化：分面绘制（FacetGrid）或并列显示多个子图，避免重叠。交互式可视化：使用 plotly 库生成可交互图表，支持动态探索。在以上两个方面改进代码。'"

## I (Interpretation) 重写方法论

**三步迭代流程**：

```
Step 1 · 基础代码块（功能优先）
  → 生成可运行的基础图表
  → 目标：能展示数据，不追求美观
  → 输出：基础图表（matplotlib/seaborn 默认样式）
  → 验收：图表能正确反映数据

Step 2 · prompt 美化配色（视觉优先）
  → 迭代优化：
     - 配色方案（sci 蓝绿色块/Set2/邻近色环）
     - 布局优化（figsize/grid/legend 位置）
     - 标签清晰（标题/坐标轴/图例）
     - 网格线增强（虚线/半透明）
  → 输出：美化后的图表
  → 验收：图表能独立讲故事（不依赖文字说明也能理解）

Step 3 · 增加交互效果（体验优先）
  → 添加交互：
     - 悬停效果（hover 显示具体数据）
     - 下钻交互（点击展开详情）
     - 动画播放（按时间轴逐年演变）
     - 联动效果（多图联动高亮）
  → 工具选择：plotly（交互优先）/ matplotlib + seaborn（静态优先）
  → 输出：可交互图表
  → 验收：用户能通过交互探索数据
```

**关键原则**：
- 每步输出对比，用户确认后再进入下一步
- 第一步只追求功能，不追求美观——避免过早优化
- 第二步只追求视觉，不追求交互——避免复杂度爆炸
- 第三步只追求交互，不重构基础——基于已稳定的图表添加交互
- 终态验收：图表能独立讲故事

**反常识**：可视化不是一步到位，而是三步迭代——试图一次生成完美图表往往导致代码复杂度爆炸，且无法调试。

## E (Execution) 可执行步骤

1. **第一步：基础代码块**
   ```
   Prompt: "用 [matplotlib/seaborn] 画一个 [图表类型] 展示 [数据]"
   → 输出：可运行的基础图表（默认样式）
   → 用户确认：图表能正确反映数据？
   ```

2. **第二步：prompt 美化配色**
   ```
   Prompt: "进一步美化图表：
   - 配色：[sci 蓝绿色块/Set2/邻近色环]
   - 布局：[figsize/grid/legend 位置]
   - 标签：[标题/坐标轴/图例]
   - 网格：[虚线/半透明]"
   → 输出：美化后的图表
   → 用户确认：图表能独立讲故事？
   ```

3. **第三步：增加交互效果**
   ```
   Prompt: "为图表添加交互效果：
   - 悬停：[hover 显示具体数据]
   - 下钻：[点击展开详情]
   - 动画：[按时间轴演变]
   - 工具：[plotly]"
   → 输出：可交互图表
   → 用户确认：能通过交互探索数据？
   ```

**Prompt 模板**：
```
【可视化三步迭代】

Step 1 基础代码块
Prompt: [基础绘图指令]
验收: 图表能正确反映数据

Step 2 美化配色
Prompt: [配色+布局+标签+网格优化]
验收: 图表能独立讲故事

Step 3 增加交互
Prompt: [悬停+下钻+动画+工具选择]
验收: 能通过交互探索数据

【工具选择建议】
- 静态图表（PDF/报告）：matplotlib + seaborn
- 交互图表（网页/演示）：plotly
- 学术图表：matplotlib（学术风格）+ sci 配色
- 商业图表：plotly（交互优先）+ 品牌配色
```

## B (Boundary) 边界与盲点

**不适用于**：
- 实时性要求极高的图表（三步迭代需要时间）
- 数据量极小的图表（< 10 个数据点，一步到位即可）
- 已有固定模板的周报（直接套模板，无需迭代）

**与 M8 目标导向联动**：
- M8 的"不写绘图指令"指的是"不写死具体图表类型"
- M15 的"三步迭代"指的是"生成后逐步优化"
- 两者不冲突：M8 让 AI 选图表类型，M15 让用户迭代优化

**与 M16 多维联动联动**：
- M15 是单图迭代，M16 是多图组合
- 复杂场景：先 M15 优化每个单图，再用 M16 组合联动

**作者盲点**：
- 教程没讨论"迭代失败的兜底"——如果某步优化后图表反而变差，如何回滚
- 教程没讨论"工具切换成本"——从 matplotlib 切到 plotly 需要重写代码
- 教程没讨论"交互图表的导出"——plotly 交互图表如何导出为静态 PDF

# M4 任务拆解四步流水线

> **核心定位**：复杂任务不混在一个 Prompt 里——分步走，每步可检查可回溯。

## R (Reading) 原文引用

> "不要指望一个 Prompt 解决所有问题。'提取 → 清洗 → 核对 → 分析'分步走，每一步结果可检查、可回溯，整体反而更快更稳。"

## I (Interpretation) 重写方法论

**四步流水线**：

```
Step 1 · 提取  → 把数据从源头拿出来（场景 1/2/3）
Step 2 · 清洗  → 统一格式、去重、补缺失（场景 4 部分）
Step 3 · 核对  → 验证数据正确性、找出异常（场景 4/5）
Step 4 · 分析  → 从干净数据里挖洞察（场景 6/7）
```

**关键原则**：
- 每步单独出 Prompt，不要混
- 每步结果人工检查后再进入下一步
- 每步可回溯（保留中间产物）

**反常识**：分步比一个 Prompt 搞定更快——因为一个 Prompt 出错要全部重来，分步只需重跑出错那步。

## A1 (Past Application) 书中案例

教程本身按此流水线组织：
- 第一步·数据获取（场景 1/2/3 提取）
- 第二步·数据清理与标准化（场景 4/5 清洗+核对）
- 第三步·数据分析（场景 6/7 分析）

## A2 (Future Trigger) 何时会需要

- **用户说**："抓数据+清洗+出报告""全流程""端到端"
- **场景**：跨多场景的复合需求
- **与相邻 skill 的区分**：
  - vs M1 五要素：M1 是单步 Prompt 的骨架，M4 是多步任务的编排
  - vs M9 分步提问：M4 是任务拆解，M9 是单步内的迭代深挖

## E (Execution) 可执行步骤

1. **识别涉及哪几步**：提取？清洗？核对？分析？
2. **每步单独出 Prompt**：用 M1 五要素写每步 Prompt
3. **每步结果人工检查**：跑完检查再进入下一步
4. **保留中间产物**：方便回溯
5. **某步出错只重跑那步**：不要全部重来

## B (Boundary) 边界与盲点

**不适用于**：
- 单一简单任务（如"加个日志"——直接做即可）
- 无法分步的实时任务（流处理）
- 步骤之间强耦合无法独立验证的场景

**作者盲点**：教程没讨论"步骤之间数据格式传递"的标准化问题（如 Step1 输出 Excel，Step4 要 JSON，中间要转换）。

## v3.1 配套增强 — 两个子模式

### 子模式 A：分步校验 + 黄色高亮标注 + 二次校验报告

> 来源：教程 1「TRAE Work 官方知识库实战指南」场景五"安全修改与代码核对"

**触发条件**：用户要求"分步执行""逐步校验""每步确认"时启用。

**三步流程**：

```
Step 1 · 分步执行
  → AI 按子任务逐个执行，每个子任务独立提交
  → 每步输出：执行内容 + 涉及范围 + 修改前后对比

Step 2 · 黄色高亮标注
  → AI 在结果中用 ⚠️ 或 [黄色标注] 标记所有修改位置
  → 用户可一眼定位修改，不需通读全文

Step 3 · 二次校验报告
  → AI 主动跑一次"全文一致性校验"
  → 输出二次校验报告：[OK] / [WARN] / [FAIL] + 行号 + 原因
  → 若有 FAIL，AI 主动建议修复方向
```

**适用场景**：合规修改 / 大批量字段更新 / 涉及金额的批量操作 / 历史代码维护。

**与 M7 验真闭环的区别**：M7 是"事后抽查"，本子模式是"过程中分步校验 + 全文二次校验"，二者可叠加使用。

### 子模式 B：跨表协同清洗

> 来源：教程 1「TRAE Work 官方知识库实战指南」Excel 多表处理场景

**触发条件**：用户提"多张表""跨表""两张表关联""主表+从表"时启用。

**四步流程**：

```
Step 1 · 字段映射
  → 识别两张表的关联字段（如订单号/客户ID）
  → 输出映射表：主表字段 | 从表字段 | 关联方式（JOIN/UNION/LOOKUP）

Step 2 · 主表清洗
  → 先清洗主表（保留所有行）
  → 输出主表清洗后版本 + 清洗日志

Step 3 · 从表清洗 + 关联验证
  → 清洗从表，按关联字段验证一致性
  → 标记缺失关联（主表有但从表无）+ 多余关联（从表有但主表无）

Step 4 · 合并 + 输出
  → 按 JOIN/UNION 方式合并
  → 输出合并表 + 不一致清单（需人工裁决）
```

**适用场景**：财务多表对账 / 客户主表+订单从表合并 / 跨部门数据合并。

**与 M4 标准四步的区别**：M4 标准版是单表线性流水线（提取→清洗→核对→分析），本子模式是双表并行 + 关联字段同步清洗。

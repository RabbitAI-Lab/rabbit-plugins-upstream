# 资料感知访谈流程 v3.0

> **核心创新**：主控主动提方向性问题收集信息要素 + 资料感知主动要求样表 + 资料分析自动回填，递归收敛完成后智能选适配组合。
>
> **v3.0 关键变更**：
> - "最多 3 轮" → **"最少 3 轮"**（3 轮是下限不是上限，压榨需求可能性空间）
> - 新增**资料感知触发**（按场景要求用户提交样表/案例/模版）
> - 新增**资料分析回填**（调用 5 个分析器，从资料中萃取要素，缩短访谈路径）
> - 新增**3 轮后处理**（默认进入第 4 轮，用户主动可降级）

## 5 要素完备性检查表

```
□ 范围：数据源是什么？多少量？是否含排除规则？
□ 字段：要哪些字段？取值规则？多值取舍？
□ 处理规则：排序/单位/格式/过滤？
□ 输出格式：Excel/JSON/SQL/HTML？
□ 异常处理：缺失填什么？歧义怎么办？无法识别怎么办？
```

## 访谈原则（v3.0 关键变更）

1. **一次一问**：每轮只问 1 个问题 + 2-3 选项
2. **方向性建议**：选项基于场景常见组合，用户只需选择不需自己想
3. **最少 3 轮**（v3.0 变更）：3 轮是下限，**该问到完备为止**
   - 3 轮后若 5 要素未完备 → 默认进入第 4 轮
   - 用户主动说"差不多就行" → 可降级，用当前信息生成 + 标注"待补充"
4. **资料感知**（v3.0 新增）：根据场景主动要求用户提交样表/案例/模版
5. **资料分析回填**（v3.0 新增）：用户提交资料后，调用对应分析器萃取要素，回填 5 要素
6. **水平自适应**：从用户措辞判断水平，张口 pandas→用术语；说"差不多就行"→换大白话

## 完整访谈流程（v3.0）

```
Step 0: 场景识别（L1）→ 确定场景候选
   ↓
Step 1: 资料感知触发（按场景要求提交样表）
   ↓
Step 2: 资料分析回填（用户提交后，调用分析器回填 5 要素）
   ↓
Step 3: 基于回填结果进行 3 轮访谈（最少 3 轮）
   ├─ 第 1 轮：聚焦资料未覆盖的最大缺口
   ├─ 第 2 轮：基于第 1 轮回答深挖
   └─ 第 3 轮：异常处理 + 边界情况
   ↓
Step 4: 5 要素完备性检查
   ├─ 完备 → 进入 L3 智能路由+生成
   ├─ 未完备且 3 轮已达 → 默认进入第 4 轮（除非用户主动降级）
   └─ 用户主动降级 → 用当前信息生成 + 标注"待补充"
```

## Step 1: 资料感知触发

按场景主动要求用户提交资料（这是 v3.0 的关键增强，能大幅缩短访谈路径）：

| 场景 | 主动要求的资料 | 调用分析器 |
|------|--------------|-----------|
| 1 网页采集 | "给我 1-3 份样表（目标 URL 抓取结果示例）" | [excel-analyzer.md](../material-analyzers/excel-analyzer.md) |
| 2 文档字段提取 | "给我 1-3 份样表（简历/合同/发票等）" | [pdf-analyzer.md](../material-analyzers/pdf-analyzer.md) |
| 3 SQL 生成 | "给我表结构 DDL 或字段清单（如有业务口径文档更好）" | [ddl-analyzer.md](../material-analyzers/ddl-analyzer.md) |
| 4 数据核对 | "给我两张待核对表的样表（各 1-3 行）" | [excel-analyzer.md](../material-analyzers/excel-analyzer.md) |
| 5 批量分类标注 | "给我标签体系 + 10-20 条标注样例" | [tag-taxonomy-analyzer.md](../material-analyzers/tag-taxonomy-analyzer.md) |
| 6 周报敏捷分析 | "给我上周报告 + 数据源样表" | [report-style-analyzer.md](../material-analyzers/report-style-analyzer.md) |
| 7 深度洞察报告 | "给我历史报告 + 数据源样表" | [report-style-analyzer.md](../material-analyzers/report-style-analyzer.md) |

**触发话术模板**：
```
为了给你最贴合的 Prompt，能否提交以下资料？（可选，但有资料能让 Prompt 更精准）

[场景对应资料说明，如上表]

如果暂时没有，我们可以直接进入访谈。
```

## Step 2: 资料分析回填

用户提交资料后，调用对应分析器，**自动从资料中萃取要素回填到 5 要素快照**：

| 分析器 | 自动回填的要素 | 可能剩余的缺口 |
|--------|--------------|--------------|
| excel-analyzer | 字段清单、字段类型、数据质量、格式约定 | 数据规模、异常处理规则 |
| pdf-analyzer | 字段位置、版式特征、易错点 | 批量规模、异常处理 |
| ddl-analyzer | 表结构、字段详情、表关系、索引、业务口径 | 业务需求、输出格式 |
| tag-taxonomy-analyzer | 标签树、边界规则、重叠情况、多标签规则 | 数据量级、置信度要求 |
| report-style-analyzer | 报告结构、风格、信息密度、数据源 | 分析目标、必含指标 |

**回填后访谈策略**：

资料分析已覆盖的要素 → **不再重复问**，直接进入剩余缺口访谈。

```
基于你提交的资料，我已识别：
✅ 字段清单：[自动列出]
✅ 数据格式：[自动列出]
✅ 标签体系：[自动列出]

接下来聚焦以下未明确的关键点：
```

## Step 3: 3 轮访谈维度划分（按场景调整）

资料分析后，访谈维度会动态调整。下表是**未提交资料时的默认维度划分**，提交资料后根据回填结果跳过已明确的维度：

### 场景 1 网页采集

```
第 1 轮：URL + 抓哪些字段（给常见字段组合选项）
第 2 轮：处理规则（排序/单位转换/排除规则）
第 3 轮：输出格式 + 异常回退
```

### 场景 2 文档字段提取

```
第 1 轮：文档类型 + 字段清单（给基础 6 字段 / 完整 8 字段 / 自定义 选项）
第 2 轮：文档数量 + 格式是否统一
第 3 轮：异常处理（缺失填什么 / 多值怎么取舍）
```

### 场景 3 SQL 生成

```
第 1 轮：表结构（有完整 DDL / 大白话列字段 / 完全没有）
第 2 轮：业务需求 + 指标口径（重点问比率类指标的分子分母）
第 3 轮：方言 + 输出要求（注释/排序/动态时间）
```

### 场景 4 数据核对

```
第 1 轮：两张表字段 + 匹配键
第 2 轮：核对状态分类（4 种基础 + 金额不一致 + 待确认）
第 3 轮：汇总输出要求
```

### 场景 5 批量分类标注

```
第 1 轮：标签体系（已有 / 让 AI 生成 / 一起设计）
第 2 轮：数据量级（<1000 / 1000-5000 / >5000）
第 3 轮：输出格式 + 置信度要求
```

### 场景 6 周报敏捷分析

```
第 1 轮：文件数量 + 字段是否一致
第 2 轮：指标口径（完成率怎么算 / 风险阈值多少）
第 3 轮：输出结构（汇总表 + 风险列表 + 业务总结）
```

### 场景 7 深度洞察报告

```
第 1 轮：数据规模（行数）+ 维度数量
第 2 轮：分析目标（给 4 个常见目标选项）+ 必含指标
第 3 轮：输出格式（HTML/PDF/Excel）+ 是否需要分步提问
```

## Step 4: 5 要素完备性检查

```
完备性检查：
□ 范围（数据源/规模/排除）
□ 字段（清单/取值规则/多值取舍）
□ 处理规则（排序/单位/格式/过滤）
□ 输出格式（Excel/JSON/SQL/HTML）
□ 异常处理（缺失填什么/歧义怎么办/无法识别怎么办）

→ 全部完备：进入 L3 智能路由+生成
→ 有缺口且 <3 轮：继续访谈
→ 有缺口且 ≥3 轮：默认进入第 4 轮（除非用户主动降级）
```

## 3 轮后处理（v3.0 关键变更）

### 默认进入第 4 轮（甚至更多）

3 轮后仍有缺口 → **不停下来**，继续追问缺口要素：

```
我们聊了 3 轮，还有以下关键点需要确认：
[列出剩余缺口要素]

第 4 轮问题：[聚焦剩余最大缺口]
```

### 用户主动降级

用户主动说"差不多就行" → 立即用当前信息生成 + 标注"待补充"：

```
好，我用当前信息为你生成 Prompt，未明确部分会标注"待用户补充"。

【待用户补充】
- 数据规模未知，假设 < 1000 条直接处理；若 > 1000 条需用 M6 分批
- 输出格式未指定，默认 Excel；如需 JSON/CSV 请告知
```

## 完整访谈示例（v3.0 资料感知增强版）

**用户初始输入**：
> "我有一堆简历要处理"

**Step 0: 场景识别**

→ 识别为可能场景 2（提取）/ 场景 5（标注）/ 场景 4（核对）

**第 1 轮**（场景识别 + 资料感知触发）：
```
我看你想处理简历——是下面哪种？

A) 从简历里抠字段（姓名/电话/学历）到 Excel [场景2·提取]
B) 给简历打标签（如"高级/中级/初级"） [场景5·标注]
C) 核对简历信息真伪 [场景4·核对]

如果选 A，能否给我 1-3 份样表（PDF/Word）？有样表能让我分析字段位置和版式特征，让 Prompt 更精准。
```

**用户回答 A，并提交 2 份 PDF 样表**

**Step 2: 资料分析回填**

调用 [pdf-analyzer.md](../material-analyzers/pdf-analyzer.md)：

```
✅ 自动识别：
- 版式：标准简历模板，含个人信息/教育经历/工作经历/技能
- 字段位置：姓名在顶部居中，电话在右上角，学历在教育经历首行
- 易错点：工作经历多段需要"取最近一份"决策
- 已回填：字段清单（8 字段）+ 版式特征 + 易错点
```

**第 2 轮**（基于回填，聚焦未覆盖缺口）：
```
基于你提交的 2 份样表，我已识别字段清单和版式特征。

简历大概多少份？（决定是否需要分批处理）

A) < 100 份 → 一次性处理
B) 100-500 份 → M6 分批 50-100/批
C) > 500 份 → M6 分批 + 建议先写脚本预汇总
```

**第 3 轮**（异常处理 + 边界）：
```
最后两个问题，然后我就能给你完整 Prompt：

1. 简历格式是否完全统一？（如果不同模板混排，需要在 Prompt 里加版式自适应指令）
2. 工作经历多段时取哪一段？（最近一份 / 全部列出 / 取最相关的一份）
```

**5 要素完备性检查 → 通过**

```
✅ 范围：简历 PDF 提取
✅ 字段：8 字段（自动识别）
✅ 处理规则：取最近一份工作经历
✅ 输出格式：Excel
✅ 异常处理：缺失填"未填写"

→ 匹配方法论组合：M1（五要素）+ M2（防幻觉三招）+ M7（验真闭环）
→ 生成最终 Prompt + 防幻觉清单 + 验真建议 + Excel 模板 + 验真脚本
```

## 降级策略

### 用户说"差不多就行"

→ 用场景默认值快速生成：

```
场景 1 默认：Excel 输出 + 缺失填"未获取" + 翻页抓全
场景 2 默认：Excel + 8 字段 + 缺失填"未填写"
场景 3 默认：MySQL + 注释 + 动态时间
场景 4 默认：4 种状态 + 依据说明 + 汇总
场景 5 默认：置信度+理由+不创标签
场景 6 默认：合并+完成率+风险预警+总结
场景 7 默认：HTML+PDF+Top5+目标导向
```

### 3 轮后仍不完备（v3.0 变更）

→ **默认进入第 4 轮**，不再用"待补充"草草收场。只有在用户主动说"差不多就行"时才降级。

## v3.1 配套增强 — 数据脚本需求四要素检查清单

> 来源：教程 4「只需 5 步用 SOLO 实现数据采集到可视化全流程」+ 教程 1「Excel 表格数据处理」
>
> **触发条件**：用户在访谈中提到"自动化""定期跑""写脚本""一键执行""bat"时启用本检查清单。

**追加到 5 要素完备性检查后**：在 5 要素检查通过后，若用户暗示需要数据脚本（而非只是一次性 Prompt），追加以下 4 要素检查：

```
数据脚本需求四要素：
□ 1. 执行频率：一次性 / 每天 / 每周 / 每月 / 触发式？
   → 决定是否启用 M14 增量同步
□ 2. 失败兜底：失败时是终止 + 告警，还是跳过 + 继续？
   → 决定 bat 模板的 ERROR_FLAG 处理策略
□ 3. 日志策略：详细日志（每步 stdout/stderr）还是简要日志（仅 OK/FAIL）？
   → 决定 bat 模板段 1 的 LOG_FILE 重定向级别
□ 4. 验真需求：每次跑完都验真，还是按比例抽查？
   → 决定是否在 bat 段 6 调用验真脚本 + 抽查比例
```

**访谈话术模板**：

```
你提到了自动化/定期跑——我想确认几个关键点：

1. 多久跑一次？（一次性 / 每天 / 每周 / 每月）
2. 失败时希望怎样？（立即终止告警 / 跳过失败继续跑）
3. 日志要多详细？（每步完整 stdout / 仅 OK/FAIL 摘要）
4. 跑完需要验真吗？（每次都验真 / 按比例抽查 / 不需要）

确认完这 4 点，我会在 Prompt 之外额外给你一个 .bat 一键执行模板。
```

**与 bat 模板的联动**：4 要素回答后，调用 [bat-template-spec.md](../asset-templates/bat-template-spec.md) 生成对应的 .bat 文件，作为附加交付物交付给用户。

**与其他方法论的联动**：

| 要素 | 联动方法论 |
|------|-----------|
| 1 执行频率 | M14 增量同步（定期 → 启用） |
| 2 失败兜底 | M2 防幻觉（不脑补缺数据）+ bat ERROR_FLAG |
| 3 日志策略 | M7 验真闭环（日志用于事后追溯） |
| 4 验真需求 | M7 验真闭环（按比例抽查逻辑） |

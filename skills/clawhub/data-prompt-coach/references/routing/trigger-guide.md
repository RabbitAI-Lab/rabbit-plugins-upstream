## 5 层触发引导机制

```
Layer 1: 强信号词直接锁定（命中率 70%）
   ↓ 未命中
Layer 2: 弱信号词 + 推断兜底（命中率 20%）
   ↓ 未命中
Layer 3: 场景自检 3 问快速收敛（命中率 7%）
   ↓ 未命中
Layer 4: 反问用户选择场景（命中率 3%）
   ↓ 用户选错
Layer 5: 反路径纠正（识别错场景的纠正机制）
```

## Layer 3：场景自检 3 问

Layer 1+2 都未命中时，AI 主动问这 3 个问题快速收敛：

```
1. 数据源是什么？
   - URL → 场景 1
   - PDF/Word/图片 → 场景 2
   - Excel/CSV/数据库表 → 继续问 2

2. 要做什么？
   - 抓取 → 场景 1
   - 抠字段 → 场景 2
   - 写 SQL → 场景 3
   - 核对 → 场景 4
   - 标注 → 场景 5
   - 合并周报 → 场景 6
   - 深度分析 → 场景 7
   - 端到端分析 → 场景 8

3. 输出是什么？
   - Excel 字段表 → 场景 2
   - SQL 查询 → 场景 3
   - 异常清单 → 场景 4
   - 标签 + 置信度 → 场景 5
   - Excel 周报 → 场景 6
   - HTML 报告 → 场景 7
   - 7 节结构化报告 + 6 个清单 → 场景 8
```

## Layer 4：反问用户选择场景

3 问后仍无法锁定 → 直接反问：

```
请帮我确认这是哪一类需求：

1. 网页采集（从网页抓数据）
2. 文档字段提取（PDF/图片抠字段到 Excel）
3. SQL 生成（写 SQL 查询）
4. 数据核对（两张表对账）
5. 批量分类标注（文本打标签）
6. 周报敏捷分析（多文件合并周报）
7. 深度洞察报告（多维交叉分析+HTML 报告）
8. 完整分析全流程（CRISP-DM 7 步，从问题到报告）
```

## Layer 5：反路径纠正（用户走错场景的识别）

### 场景 8 误判为场景 7（最常见错误）

| 信号 | 场景 7 | 场景 8 |
|------|--------|--------|
| 关键词 | "深度分析""报告" | "端到端""CRISP-DM""从问题到报告" |
| 输入 | 数据 + 深度问题 | 数据 + 业务问题 |
| 输出 | HTML + Top 5 Findings | 7 节结构化报告 + 6 个清单 |
| 流程 | M8+M9（2 步） | M17 7 步 SOP |

**纠正话术**："你说的是深度分析（场景 7），但听起来你想从问题定义到报告打包走完整流程，建议改走场景 8（CRISP-DM 7 步），可以吗？"

### 场景 4 误判为场景 2

| 信号 | 场景 2 | 场景 4 |
|------|--------|--------|
| 关键词 | "抠字段""提取" | "核对""对账""对得上" |
| 输入 | 单个 PDF/图片 | 两张表 |
| 输出 | Excel 字段表 | 异常清单 |

**纠正话术**："你说的是抠字段（场景 2），但听起来你要核对两张表是否一致，建议改走场景 4（数据核对），可以吗？"

### 场景 6 误判为场景 7

| 信号 | 场景 6 | 场景 7 |
|------|--------|--------|
| 数据规模 | < 200 行 | > 1000 行 |
| 输出 | Excel + 业务总结 | HTML + Top 5 Findings |
| 重点 | 完成率、风险预警 | 多维交叉、ROI |

**纠正话术**："你说的是周报（场景 6），但数据规模 > 1000 行+多维交叉，建议改走场景 7（深度报告），可以吗？"

## 触发可靠性检查清单（AI 自检）

每次场景识别后，AI 应自检：

1. **强信号词命中了吗？** 是 → 锁定场景，跳到 Step A2
2. **弱信号词推断了吗？** 是 → 反问确认，等用户回应
3. **场景优先级正确吗？** 场景 8 > 场景 7 > 场景 6 > 其他（端到端覆盖子集）
4. **是否误判为场景 7？** 检查"端到端""CRISP-DM""从问题到报告"——有则改场景 8
5. **教学场景特化触发了吗？** 检查"教学""学习""挑战任务""测试 AI""背答案""数据陷阱"——有则追加 M21
6. **方法论组合符合规则吗？** M12↔M13 成对、M15↔M16 成对、M17-M20 在场景 8 成套、单场景最多 5 个 v3.1+v3.3
7. **场景完成后联动提示了吗？**（v3.3.1 新增）场景 N 完成交付后，按 [capability-map.md](capability-map.md) § 场景流转图 主动提示 1-2 个最相关下一步

## 边界情形

### 模糊输入的优先处理

用户输入"帮我看下这份数据"——
1. **不要立即选场景**：先反问"你想从这份数据中找什么？"
2. **等用户回应**：根据回应再走 5 层触发机制

### 跨场景任务

用户输入"抓数据+核对+出报告"——
1. **拆成 3 个 Prompt**：场景 1 + 场景 4 + 场景 7（不要混在一个 Prompt 里，违背 M4 任务拆解）
2. **每步独立走 5 层触发**：第一步场景 1，第二步场景 4，第三步场景 7 或 8

### 入口歧义

用户输入"分析下这个教程"——
- **关键词"分析"** vs **关键词"教程"** 冲突
- **优先识别"教程"** → 走入口 B 蒸馏（教程是蒸馏入口的关键信号词）
- **反问确认**："你是要萃取教程中的方法论（蒸馏入口），还是要做教程里的数据分析任务（引导入口）？"

### 咒语使用规则

1. **咒语命中即追加**：用户输入含咒语时，自动追加对应方法论到场景组合
2. **成对强制**：M12↔M13、M15↔M16 必须成对出现（一个触发另一个自动追加）
3. **三件套强制**：M14 触发时自动追加 M6+M7
4. **场景 8 成套**：M17 触发时自动追加 M18+M19+M20（CRISP-DM 7 步骨架不可拆分）
5. **M21 仅教学场景**：必须命中"教学""学习"等咒语才挂载，不当默认方法论用
6. **5 个上限**：单场景最多叠加 5 个 v3.1+v3.3 方法论（避免组合爆炸），超过按场景优先级裁剪
7. **咒语可组合**：用户可一句话触发多个咒语（如"端到端分析含下钻"触发 M17+M18+M19+M20+M12+M13，但会触发上限裁剪）
8. **v3.4.0 M22 是默认前置**（v3.4.0 新增）：现代网站 80% 是 SPA，场景 1 默认追加 M22（除非用户明确说是静态网站）
9. **v3.4.0 依赖链**（v3.4.0 新增）：M23 触发时自动追加 M22（动态 Key 必须先识别 SPA）；M26 触发时自动追加 M14+M24（双存储需增量+唯一 ID）
10. **v3.4.0 M25 兜底规则**（v3.4.0 新增）：M25 仅在 M22 识别失败或用户主动说"AI 没识别到"时追加，不当默认方法论用

1. **场景 8 优先推荐**：场景 8 是端到端全流程，覆盖所有子集场景，是默认推荐下一步

3. **同一场景不重复提示**：用户拒绝联动后不再追问
4. **只展示 1-2 个最相关**：避免信息过载，按场景流转图选最相关的下一步

## 模糊触发反路由保护清单（v3.4.2 新增，回应 ClawHub [SQP-1]）

⚠️ **以下通用短语在日常生活中含义广泛，禁止自动路由到数据处理工作流**：

| 用户输入 | 日常生活含义 | 错误路由风险 | AI 正确行为 |
|---------|------------|------------|-----------|
| "帮我分析一下" | 可能是聊天/咨询/分析问题 | ❌ 禁止自动锁定场景 7/8 | ✅ 反问"你是要分析数据文件（场景 7/8）还是只是讨论某个问题？如有数据请发我" |
| "整理一下" | 可能是整理思路/笔记/桌面 | ❌ 禁止自动锁定场景 2/6 | ✅ 反问"你要整理数据到 Excel（场景 2/6）还是整理别的东西？" |
| "看下这个" | 可能是看代码/看截图/看文章 | ❌ 禁止自动锁定任何场景 | ✅ 反问"这是数据文件吗？如果是，你想从中获取什么？" |
| "处理一下" | 可能是任何处理任务 | ❌ 禁止自动锁定场景 | ✅ 反问"你要处理什么类型的数据？想要什么输出？" |
| "有什么建议" | 可能是任何建议请求 | ❌ 禁止自动锁定场景 7 | ✅ 反问"你是要基于数据出建议（场景 7/8）还是普通咨询？" |
| "画个图" | 可能是画图表/画流程图/画图标 | ❌ 禁止自动锁定场景 7 | ✅ 反问"是数据图表（建议 /chart-visualization）还是其他类型的图？" |
| "写个报告" | 可能是任何报告 | ❌ 禁止自动锁定场景 7 | ✅ 反问"是基于数据的分析报告（场景 7/8）还是其他类型的报告？" |
| "做个表" | 可能是 Excel/Markdown 表格/数据表 | ❌ 禁止自动锁定场景 2 | ✅ 反问"是数据 Excel 表（场景 2）还是普通 Markdown 表格？" |

### 反路由触发铁律

1. **数据缺失即不路由**：用户未提供任何数据文件（Excel/PDF/CSV/DDL/URL）时，禁止自动进入场景 2-8 中的任何一个
2. **意图不明确即反问**：上述短语命中后必须反问 1 个澄清问题（数据源是什么 + 想要什么输出）
3. **3 轮内必须收敛**：连续 3 轮反问仍无法锁定场景 → 主动展示 [quickstart-examples.md](quickstart-examples.md) 让用户从示例中选
4. **拒绝猜测性路由**：宁可让用户多回答一个问题，也不要把用户错误地推入数据处理工作流（涉及隐私/凭证/计算资源消耗）

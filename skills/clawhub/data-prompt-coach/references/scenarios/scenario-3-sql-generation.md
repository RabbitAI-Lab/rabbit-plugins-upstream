# 场景 3·SQL 生成（参考案例）

> 本文件仅作参考案例。Prompt 骨架由 SKILL.md 主控 + M3+M10+M2 套用生成。

## 案例原型

小陈（在线教育平台数据分析师）需要拉"活跃学员 + 续费率"复杂查询，从零写 20-30 分钟。

## 关键参数

- **数据源**：4 张表（users / course_progress / login_log / orders）的完整 DDL
- **业务需求**：
  - 活跃学员 = 过去 30 天内完成 ≥3 门课程 + 最近 7 天有登录 + 账号正常
  - 续费率 = 有续费订单的活跃学员 / 全部活跃学员
- **指标**：活跃学员人数 / 平均学习时长 / 续费率（保留 2 位小数百分比）
- **输出**：MySQL + 关键步骤加注释 + NOW() + INTERVAL 动态时间 + 按活跃人数降序

## 样例 Prompt 片段（关键三段）

```
你是一名资深数据工程师，精通 MySQL。请根据我提供的表结构和业务需求，写一段可直接运行的 SQL 查询。

【业务需求】
统计"活跃学员"按城市分组的指标。活跃学员需同时满足：
1. 过去 30 天内完成学习课程数 ≥ 3 门（course_progress.status=2 且 finish_time 在近 30 天内）
2. 最近 7 天内有过登录行为（login_log 中存在近 7 天的登录记录）
3. 账号状态正常（users.status = 1）

【需要输出的指标】（按城市 city 分组）
- 活跃学员人数
- 续费率 = 有续费订单的活跃学员 / 全部活跃学员，保留 2 位小数百分比
  （续费订单定义：orders.order_type=2 且 pay_status=1）

【输出要求】
- 关键步骤加注释说明逻辑
- 时间用 NOW() 和 INTERVAL 动态计算，不要写死日期
- 结果按"活跃学员人数"降序排列
- 如果业务定义中有你认为模糊、需要我确认的地方，先在 SQL 上方用注释列出你的假设
```

## 隐藏坑（场景 3 专属·M10 4 必看点）

1. **JOIN 类型**：该用 LEFT JOIN 的地方别用 INNER JOIN（尤其 orders 表，可能存在活跃用户无订单）
2. **时间边界**：`>=` 还是 `>`？"近 30 天"含不含今天？跟 AI 确认口径
3. **去重**：`COUNT(DISTINCT user_id)` 还是 `COUNT(user_id)`？多表 JOIN 行数容易翻倍
4. **业务口径**：续费率分子分母定义——AI 可能把"续费订单数/总订单数"当分子
5. **拿不到 DDL 时**：用大白话列字段含义，业务口径一定要交代清楚

## 进阶玩法

| 需求 | Prompt 追加句 |
|------|--------------|
| 解释看不懂的 SQL | `请逐段解释这段 SQL 在做什么，每个子查询/CTE 的作用` |
| 优化慢查询 | `在千万级数据量下跑了 40 秒，请帮我分析慢在哪里` |
| 看懂报错 | `这段 SQL 报错 ERROR xxx，请告诉我原因和怎么改` |
| 切换方言 | `请把上面这段 SQL 改写成 PostgreSQL/Hive/ClickHouse 方言` |

## 验真抽查（4 件事）

1. 跑一条样本数据看行数对不对（行数翻倍 = 去重漏了）
2. 时间范围跑样本验证
3. `EXPLAIN` 看 4 表 JOIN 是否走索引
4. 续费率分子分母跟你的业务口径一致

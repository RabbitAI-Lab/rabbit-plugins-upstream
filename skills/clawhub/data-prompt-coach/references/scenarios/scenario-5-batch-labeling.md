# 场景 5·批量分类标注（参考案例）

> 本文件仅作参考案例。Prompt 骨架由 SKILL.md 主控 + M5+M2（>1000 条加 M6）套用生成。

## 案例原型

小苏（电商客服数据运营）处理 5000 条用户反馈文本，要按统一标签体系归类，给产品团队指明迭代方向。

## 关键参数

- **数据源**：5000 条用户反馈文本（工单 + App 评价）
- **标签体系**：两级（一级分类 + 二级标签），每个标签含边界定义 + 样例
- **输出**：序号 | 反馈摘要 | 一级分类 | 二级标签 | 置信度 | 理由
- **置信度规则**：
  - 高：表意清晰明确对应某标签
  - 中/低：措辞模糊、可能落在两个标签之间

## 标签体系示例（M5 核心要点）

```
一级分类：功能问题
- 二级标签：功能异常
  - 定义：功能根本无法使用，如闪退、报错、点击无反应
  - 样例："App 一打开就闪退"、"提交按钮点了没反应"
- 二级标签：操作复杂
  - 定义：功能能用但操作繁琐，如步骤太多、找不到入口
  - 样例："修改密码要进 5 层菜单"、"找不到退款入口在哪"

一级分类：服务问题
- 二级标签：客服响应慢
  - 定义：联系客服后回复慢或无回复
  - 样例："等了 3 天客服才回"
```

**划边界诀窍**：最易混的两个标签要专门说"谁归谁"。如"操作复杂"（功能能用但麻烦）vs"功能异常"（功能根本用不了），在定义里点明差异。

## 样例 Prompt 片段（关键三段）

```
【标签体系】
[完整粘贴上面的标签定义——不要假设 AI 记得]

【标注要求】
1. 给每条反馈打上"一级分类 + 二级标签"
2. 给出置信度（高/中/低）
3. 给出一句话理由，说明你判断的依据（引用反馈里的关键词）
4. 如果一条反馈同时涉及多个问题，选择用户**最主要、最强烈**抱怨的那个作为主标签，
   并在理由里注明它还涉及哪个次要标签
5. 严格按标签体系来，不要自创标签。实在无法归类的，标为"其他 / 无法归类"

【输出格式】
序号 | 反馈摘要 | 一级分类 | 二级标签 | 置信度 | 理由
```

## 隐藏坑（场景 5 专属）

1. **AI 自创标签**：必须显式"严格按标签体系来，不要自创"
2. **易混标签标混**：边界定义必须点明"X 和 Y 的差异是..."
3. **置信度全是"高"**：必须规定"措辞模糊时为中或低"
4. **标注理由空白**：必须要求"一句话理由+引用关键词"
5. **大批量（>1000）分批策略**：
   - 小样本测试 → 第一批对齐 → 固定标准分批（每批 50-100 条）
   - 保留全局序号方便合并
   - 文件批处理：让 AI 自己拆文件
6. **同一条标多个标签**：必须规定"选最主要最强烈的，其余放理由里"

## 验真抽查（4 件事）

1. 第一批当对齐基准：人工核查第一批的标注质量
2. 抽查置信度"低"的样本：看 AI 是否真的"示弱"
3. 抽查"其他/无法归类"：是文本真的无法分类，还是 AI 偷懒
4. 统计标签分布：某标签占比异常（>50% 或 <1%）→ 标签体系有问题

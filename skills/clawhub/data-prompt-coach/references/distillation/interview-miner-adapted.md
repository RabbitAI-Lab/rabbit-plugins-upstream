# Interview-Miner Adapted — 5 维度教程挖掘适配版

> 来源：interview-insight-miner 5 维度框架（原为访谈转录挖掘）
> 适配：将"访谈主角观点挖掘"映射为"教程方法论提取"
> 适用于：data-prompt-coach 蒸馏入口 L0.2

## 与原 interview-insight-miner 的对比

| 维度 | 原用途（访谈） | 适配后用途（教程） | 产出类型 |
|------|---------------|------------------|---------|
| 显性认知 | 提取访谈主角的观点 | 提取教程明确表述的方法论 | 方法论候选 |
| 隐性意图 | 推断访谈主角的暗示 | 提取教程暗示要避免的坑 | 陷阱候选 |
| 思维模型 | 提炼底层认知框架 | 提取作者做决策的框架 | 决策框架候选 |
| 行业信号 | 提取行业趋势判断 | 提取场景适用信号 | 触发条件候选 |
| 反常识洞察 | 提取与主流相反的观点 | 提取独特点（淘汰常识） | 独特性候选 |

**适配核心**：访谈主角 = 教程作者；访谈转录 = 教程文本；访谈观点 = 教程方法论

---

## 5 维度并行提取规则

### 维度 1：显性认知 → 方法论候选

**提取目标**：教程作者明确表述的"应该做什么"和"应该怎么做"

**提取规则**：
1. 找教程中明确表述的方法论（"黄金五要素""防幻觉三招"等）
2. 找带编号的步骤（"第一步... 第二步..."）
3. 找带标签的概念（"心法""原则""招式"）
4. 找带示例的规则（"这样做 → 好的结果"；"那样做 → 坏的结果"）

**每条候选格式**：
```yaml
candidate_id: "C{N}"
dimension: "explicit_cognition"
type: "methodology"
name: "{方法论名称（不超过 8 字）}"
raw_quote: "{原文关键句}"
action: "{做什么}"
steps: "{怎么做}"
example: "{教程中的实际案例}"
```

**反模式**（不提取的内容）：
- ❌ 纯案例叙事（如"老王每天早上..."）—— 这是 A1 素材，不是方法论本身
- ❌ 工具介绍（如"TRAE Work 是..."）—— 这是背景，不是方法论
- ❌ 教程结构说明（如"本章你将学到..."）—— 这是导读，不是方法论

---

### 维度 2：隐性意图 → 陷阱候选

**提取目标**：教程暗示要避免的坑、错误做法、反模式

**提取规则**：
1. 找"不要..." / "避免..." / "禁止..." / "切勿..." 句式
2. 找"常见错误" / "新手常犯" / "踩坑" 类段落
3. 找对比叙事（"差 Prompt 让 AI 不停猜" vs "好 Prompt 让 AI 读完不用猜"）
4. 找教程主动纠正的认知（"很多人觉得 X，但其实 Y"）

**每条候选格式**：
```yaml
candidate_id: "C{N}"
dimension: "implicit_intent"
type: "pitfall"
name: "{陷阱名称（不超过 8 字）}"
raw_quote: "{原文关键句}"
common_mistake: "{常见错误做法}"
correct_approach: "{正确做法}"
consequence: "{错误做法的后果}"
```

**反模式**：
- ❌ 提取教程作者的字面意图（不是猜作者心里想什么）
- ❌ 把显性规则包装成陷阱（应该作为维度 1 方法论候选，不是陷阱）

---

### 维度 3：思维模型 → 决策框架候选

**提取目标**：教程作者做决策的底层框架（不是表面方法论）

**提取规则**：
1. 找"先 X 再 Y 后 Z"的决策顺序
2. 找"看 A 判断 B 决定 C"的判断逻辑
3. 找"如果... 就... 否则..."的条件分支
4. 找教程作者反复使用的思考结构（如"先想字段 → 再想规则 → 最后想异常"）

**每条候选格式**：
```yaml
candidate_id: "C{N}"
dimension: "mental_model"
type: "decision_framework"
name: "{模型名称（不超过 8 字）}"
raw_quote: "{原文关键句}"
elements: "{构成要素}"
decision_logic: "{决策逻辑}"
applicable_scope: "{适用范围}"
```

**示例**：
```yaml
name: "黄金五要素决策"
elements: "范围+字段+规则+格式+异常"
decision_logic: "5 要素齐全 → Prompt 可控；缺一 → AI 自由发挥"
```

**反模式**：
- ❌ 把方法论包装成思维模型（维度 1 和维度 3 不混淆）
- ❌ 提取过于抽象的通用框架（如"分步思考"——这是常识不是模型）

---

### 维度 4：行业信号 → 触发条件候选

**提取目标**：教程中暗示"什么时候用这个方法论"的场景信号

**提取规则**：
1. 找"当... 时" / "在... 场景下" / "适用于..." 句式
2. 找案例背景中的场景特征（如"投资从业者""HR""数据分析师"）
3. 找数据规模信号（如"5000 条"">1000 条""<100 份"）
4. 找工具特征信号（如"网页""PDF""SQL""Excel"）

**每条候选格式**：
```yaml
candidate_id: "C{N}"
dimension: "industry_signal"
type: "trigger_condition"
methodology_ref: "{对应的方法论候选 ID（C{X}）}"
signal_keywords: ["{信号词1}", "{信号词2}"]
scenario: "{场景描述}"
scale_threshold: "{规模阈值（如有）}"
```

**用途**：维度 4 不直接产生方法论，而是为维度 1/3 的候选补充触发条件，供 L0.4.2 更新 method-composition.md 路由矩阵使用

---

### 维度 5：反常识洞察 → 独特性候选

**提取目标**：教程中与主流认知明显不同的观点（用于 V3 独特性验证）

**提取规则**：
1. 找"很多人觉得 X，但其实 Y" 句式
2. 找教程主动纠正的认知（"差 Prompt vs 好 Prompt"对比）
3. 找反直觉建议（如"允许 AI 说不知道"——很多人觉得 AI 必须给答案）
4. 找教程强调的"反常识点"（"这一步是关键""这是最容易踩的坑"）

**每条候选格式**：
```yaml
candidate_id: "C{N}"
dimension: "contrarian_insight"
type: "uniqueness"
methodology_ref: "{对应的方法论候选 ID（C{X}）}"
common_belief: "{主流认知}"
tutorial_says: "{教程说的}"
why_different: "{为什么不同}"
```

**用途**：维度 5 不直接产生方法论，而是为 V3 独特性验证提供证据（"教程作者自己也强调很多人不知道"）

---

## 并行提取流程

```
教程文本输入
    ↓
┌───────────────────────────────────┐
│ 5 维度并行提取（同一份文本，5 个视角）│
├───────────────────────────────────┤
│ 维度 1 显性认知 → 方法论候选 C1-Cx │
│ 维度 2 隐性意图 → 陷阱候选 Cy-Cz   │
│ 维度 3 思维模型 → 决策框架候选 ... │
│ 维度 4 行业信号 → 触发条件候选 ... │
│ 维度 5 反常识 → 独特性候选 ...    │
└───────────────────────────────────┘
    ↓
候选清单（去重 + 关联）
    ↓
进入 L0.3 三重验证
```

**去重规则**：
- 维度 1 和维度 3 可能产生重复（方法论 vs 思维模型）→ 保留为维度 1，维度 3 只保留纯决策框架
- 维度 4 和维度 5 是维度 1/3 的补充，不独立挂载

**关联规则**：
- 维度 4 的 `methodology_ref` 必须指向维度 1/3 的候选 ID
- 维度 5 的 `methodology_ref` 必须指向维度 1/3 的候选 ID
- 没有关联的维度 4/5 候选直接淘汰（不能单独存在）

## 提取数量指导

| 教程规模 | 候选总数目标 | 方法论候选（维度 1+3） | 陷阱候选（维度 2） |
|---------|------------|---------------------|------------------|
| 短文（<3000 字） | 3-5 | 2-3 | 1-2 |
| 中篇（3000-10000 字） | 5-10 | 3-5 | 2-3 |
| 长文（>10000 字） | 10-20 | 5-10 | 3-5 |

**注意**：候选数 ≠ 通过数。L0.3 三重验证通过率目标 ≥ 50%，最终挂载数通常 ≤ 5

## 与原 interview-insight-miner 的关键差异

| 维度 | 原版 | 适配版 |
|------|------|--------|
| 输入 | 访谈转录文本 | 教程文本（URL/PDF/MD/纯文本） |
| 主角 | 访谈主角（人） | 教程作者（人） |
| 输出 | 5 维度洞察报告 | 5 类候选清单（供 L0.3 验证） |
| 推断 | 隐性意图允许推断（带置信度） | 隐性意图聚焦"避免的坑"（不做意图推断） |
| 评价 | 纯挖掘零评论 | 纯提取零评价（评价交给 L0.3 验证） |
| 产出 | 直接给用户看 | 给 L0.3 验证消费 |

**核心差异**：原版是终端产出（给用户看），适配版是中间产物（给 L0.3 验证消费）

# Storefront Copy 写作规则

## 按位置写作

- **展示名**：说明类别或结果，避免内部代号；不得改变稳定 slug
- **frontmatter description**：一条主张，包含做什么及何时调用，不写功能清单
- **首屏标题**：放大结果或关键差异
- **首屏段落**：补受众、场景与证据，不重复标题
- **CTA**：说明下一步动作，不制造虚假紧迫感

## 三套方案

- Direct：最低理解成本，优先准确
- Distinctive：突出 brief 中证据最强的差异点
- Compact：在长度受限位置保留受众、结果和触发条件

## 常见失败

- “帮助所有开发者高效工作”：受众与结果都不可辨认
- “检查、分析、优化、生成”：动作堆叠，没有用户收益
- “最佳、保证、全面”：无证据或边界不清
- copy 阶段新增功能：越过 brief，必须退回 Review

## Claim check

每条关键承诺都应回指 brief 的 `single_promise`、`differentiation_pillars` 或 `proof`。命中 `must_not_claim` 的表达直接删除；证据不足的表达改为保守措辞或列入待确认。

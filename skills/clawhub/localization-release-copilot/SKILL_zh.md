# 本地化发布运营影子助手

针对本地化 / 翻译发布流程，取**源稿**和其一/多个**目标语言版本**，作为影子审阅者在发布前抓出会破坏发布的漂移：术语漂移、数字不符、专有名词掉落、来源标注丢失、结构损失。只输出可审阅的差异与预览——**不重写译文本身**。

## 何时使用

- 你有成型的源稿（中文文章、论文、文档页、发版说明）和人工或模型生成的另一语言译文（英文 / 其他），想在发布前做一致性检查。
- 你**同一内容多语言发布**（微信中文 → LinkedIn 英文 / Substack 英文；文档中文 → 英文；产品文案 → locale），想确认目标稿没悄悄丢掉数字、专有名词或来源引用。
- 你维护**术语表 / 词库**，需要每次发布都遵守锁定词（产品名、框架名、单位、品牌指标）。
- 你想要一个**可一键审阅的 PR 式预览**，让人工一次批完。
- 你怀疑"英文版读着通顺但数据丢了"——本 Skill 专门抓这类 bug。

## 何时不用

- 单语润色 / 校对单篇草稿 → 用 `claim-to-source-auditor`，或本地已安装的专门合规审查 Skill。
- 同一主题**多份材料间**的一致性（PR vs 通稿 vs PPT）→ 用 `cross-material-consistency-auditor`。
- 选题评估 → 用 `editorial-topic-portfolio`。
- 机器翻译生成 → 本 Skill 只审不译。
- 直接修改或重写目标文本。

## 输入

```yaml
source:
  path:
  language: zh | en | ...
targets:
  - path:
    language:
    label: LinkedIn | Substack | docs-EN | locale-EN
glossary:          # 可选：目标稿必须遵守的锁定词
  - source_term:
    target_term:
    mandatory: true | false
preserve_attribution: true
review_only: true
```

## 工作流

### 步骤 1：[确定性] 载入源稿 + 目标稿
1. 读取源稿与每个目标稿。
2. 识别语言、长度、章节数、状态（草稿 / 终稿）。
3. 若提供术语表，载入为锁定词表。

### 步骤 2：[确定性] 抽取与归一
对每个文件抽取：
- 数字**带单位**，归一为规范量级（locale-aware）：ZH `亿`→×1e8、`万`→×1e4；EN `B/billion`→×1e9、`M/million`→×1e6、`K/thousand`→×1e3。`8.3亿`≈`830M`、`117亿`≈`€11.7B`、`1.5亿`≈`€150M` 是**等价，非不符**。
- 专有名词 / 实体（大写词串、引号词、机构名、人名、产品名）。
- 来源标注（`（机构, 年份）`、`Org (Year)`、行内引用）。
- 术语表词（若提供）。
- 章节级结构承诺（标题、承诺列表）。

输出 `01-extracted-claims.json`。

### 步骤 3：[LLM] 构建差异矩阵
源稿 → 每个目标稿逐项比对；每条不一致记录：维度（terminology/number/proper_noun/attribution/structure_loss/locale_format）、源表述 vs 目标表述、差异类型、严重度（P0 数字或事实主张缺失/矛盾；P1 来源标注掉落或变更、强制术语未遵守、关键专有名词缺失；P2 非强制术语漂移、不改变主张的章节深度差、平台压缩）、建议统一口径（引用源稿）、是否需复检。

一致项保留为正向记录，不逐行列举。

### 步骤 4：[LLM] 产出可审阅预览
渲染 PR 式预览：
- 摘要：源稿→目标稿、通过项、待处理项。
- 每条 P0/P1 的行级差异：源句→目标句→建议修复（不自动应用）。
- 术语表合规块：哪些锁定词被遵守 / 违反。
- "可发布？"门禁：有 P0 → **阻断**；有 P1 → **需审阅**；否则 **clear**。

### 步骤 5：[确定性] 人工确认
预览后暂停确认：P0/P1 处置、目标稿是否修订（本 Skill 不改）、术语表是否更新。确认后由人工或对应 Writer/Editor 修订。本 Skill 只审阅。

## 硬规则
1. **只审阅不改写**：绝不修改源稿或目标稿，输出差异+预览，交付后 hands-off。
2. **默认 locale-aware**：`8.3亿`=`830M` 是正确本地化，误报这类等价会毁掉可信度。
3. **来源标注是内容一部分**：源稿 `(机构, 年份)` 在目标稿须保留机构+年份，掉落任一项即 P1。
4. **术语表强制词必遵守**：标 mandatory 的锁定词须原样出现在目标稿。
5. **P0 阻断发布**：目标稿缺失或歪曲源稿数字/事实主张，即发布阻断级。
6. **源稿为权威**：源稿与目标事实冲突以源稿仲裁，要改的是目标稿。
7. **不凭空造词**：建议修复须引用既有源字符串，不得发明。

## 失败处理
| 场景 | 动作 |
|---|---|
| 只给源稿无目标稿 | 停止，至少需要一个目标稿 |
| 目标稿不可读 | 标记后只检其余目标稿 |
| 源稿有明显错误 | 标记错误，不传播进目标稿建议 |
| 未提供术语表 | 从源稿推断术语，备注"建议建术语表" |
| 源稿与目标为不同文档非翻译对 | 停止并告警：本 Skill 需真实源→目标对 |
| 全部通过 | 报"未发现本地化漂移"并 clear |
| 已发布目标稿发现 P0 | 加注严重度并建议修正 |

## 验证清单
- [ ] 每个目标稿对源稿比对了数字、专有名词、来源、术语、结构。
- [ ] 每个 P0/P1 有引用源稿的建议修复。
- [ ] locale 等价数字（亿/M、万/K）视为匹配非错误。
- [ ] 每个强制术语都有术语表合规块。
- [ ] 预览不含任何源/目标修改。
- [ ] 任务标记完成前有人工确认记录。

## 易错点
- 把正确 locale 本地化（`8.3亿`→`830M`）当不符——让本 Skill 失效的头号原因。
- 信目标稿"读着通顺"而跳过数字检查——漂移藏在通顺文字里。
- 把两篇相关但不同的文档（如中文长文 + 英文短评，同一理论）当翻译对——它们不是，会产生噪声。
- 假设模型译文是事实权威——源稿才是权威，要改的是目标稿。
- 忘记 LinkedIn/Substack 的压缩是合法的；只标记掉落"主张"的结构损失，不标记掉落"章节"。

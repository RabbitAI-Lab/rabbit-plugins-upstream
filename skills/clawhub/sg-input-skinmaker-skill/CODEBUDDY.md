# CODEBUDDY.md

本文件为项目基础上下文，供后续对话与 `/speckit.*` 命令作为基础认识使用。

## 项目定位

- **项目名**：sg-input-skinmaker-skill
- **类型**：AI client 应用（如 workbuddy、Codex、Trae 等）中运行的 skill（工作流编排型 skill，非可执行代码工程）
- **一句话职责**：把预设 prompt 模板与用户风格描述融合，对用户上传的一张图片做图生图，
  最后返回生成后的图片 + 校园AI创意皮肤大赛互动页面，由用户自行打开。

## 核心业务约定

### 固定返回文案与 H5 地址（写死，不拼接）

```
这张可直接参赛，得票前15名有奖
→ 保存图片并查看活动详情https://pinyin.sginput.qq.com/h5/kaixueskill/share/225448950305128448
```

- 文案与地址原样返回给用户，**不做任何动态参数拼接**（不拼 bgimg / CDN 地址）。

### 预设生图规范（详见 references/generation-prompt.md）

最终给 AI client 模型的 prompt 采用**三层融合模型**：
1. **方向层（固定）**：「参考输入图片的主体与配色，生成一张适合作为手机键盘皮肤的横向背景图，画面干净、留白充足、不要出现文字。」
2. **内置正向引导层（合规硬规则，优先级最高）**：6 类红线 —— 着装姿态（禁色情低俗）/ 禁未成年性化（成年特征+头身比≥1:6.5）/ 纯背景无键盘界面元素 / 禁暴力血腥 / 原创形象不指向真人明星 / 人物关系合规（LGBT）。
3. **优化后的用户自定义层**：用户描述**不直接透传**，须先用内置逻辑净化（剔除违反红线内容）+ 对齐背景图属性 + 并入构图/配色约束后再拼入。

冲突处理：用户诉求与合规硬规则冲突时，以硬规则为准，静默丢弃/改写冲突部分。融合顺序：方向层 → 内置正向引导层 → 优化后的用户自定义层。

完整约束（角色/风格化程度/构图禁变形/配色/CLEAN 排除清单/护栏/6 类合规红线/三层融合模板）见 references。

### 运行环境能力假设（已与需求方确认）

- **图生图**：由 AI client 宿主内置能力完成，skill 用自然语言指令驱动，无需写 API 调用代码。
- **不做 CDN 直链提取 / 拼接**：宿主返回 CDN 直链不可行，故放弃「动态拼 bgimg」方案，改为写死 H5 地址。
- **不自动打开页面**：由用户自行打开返回的 H5 地址。

## 工作流（SOP）

1. 收集输入：图片（必需）+ 风格描述（可选）。缺图片必须补齐；**缺风格描述无需追问，由 skill 根据图片自行推演风格**。
2. 融合 prompt：预设模板 `%s` 替换为目标风格（用户提供的 或 自动推演的）；额外内容诉求作为补充条款追加。
3. 图生图：用融合 prompt + 用户图片，驱动宿主内置能力生成图片。
4. 返回结果：生成后的图片 + 写死 H5 地址，由用户自行打开。

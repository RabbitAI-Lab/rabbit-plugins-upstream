# Make audio

STARTER: your first audio clip (speech, music, a song or a sound effect).

This text is a guide, not the user's go. It authorizes no spend: the paid call below is priced first and made only after the user's go for that purchase.

0. Run `aicut account` to see the balance. If it is 0, the account has no tokens: tell the user so, give them https://www.aicut.pro/billing, and stop until they have added some. Price nothing first. (A price above the balance is refused later with the same link: give it to the user and stop.)
1. Ask the user which kind it is and what it should be: for speech the exact words and a voice they like, for music the mood, instruments and length, for a song with vocals its style and either the idea or the title and lyrics, for a sound effect what it sounds like and how long. Ask nothing else.
2. Find the model: `aicut models list --type audio`. The kinds take different flags (speech: `--text` and `--voice`; music: `--prompt` and `--length-ms`; song, `suno-v6`: `--music-style` plus either `--prompt` in Quick mode or `--custom-mode`, `--title` and optional `--lyrics`, `--vocal-gender` and `--duration-seconds` in Lyrics mode; sound effect: `--text` and `--duration`), and a field the chosen model does not publish is rejected, so run `aicut models get <model-id>` first. For a speech voice run `aicut voices --provider elevenlabs --usable-for audio --limit 100`; never invent a voice id. Choose the voice by PREVIEW, not by spend: run `aicut voices --provider elevenlabs --usable-for audio --limit 100 --json`, propose 2 or 3 that fit what the user described, each with its `preview_url` link beside its name (a link the user can play; OpenAI voices have none, so describe those), and let them pick BEFORE any paid call. Never generate the same line in several voices to compare them, unless the user asks for that and has been told the total price of it.
3. Price it: `aicut generate audio --model <id>` with the exact settings and `--estimate`; it prints the price and charges nothing. Speech, music and sound effects are priced on a rate (per character, per minute or per second) and a song at a flat price per call, so the quote is the only accurate price; never multiply a rate yourself. Send exactly the words the user asked for, never padded or shortened to change the price. Say the price and what it buys in ONE message, ask, and wait for the user's go for this purchase.
4. After their go, run the same command again with `--max-tokens <the price you quoted> --yes --wait` (usually under a minute). Never put `--max-tokens` on a command before that go: without a terminal it is itself the go. `--wait` blocks until the job is done (up to 10 minutes) and prints the media url; add `-o <path>` to save the file too. If your shell tool cuts a command off sooner than that, leave `--wait` off from the start: the command prints the job id, then run `aicut wait <id> --timeout 90` again until it prints the url (exit code 3 means still running, not failed). If a run that had `--max-tokens` is cut off, NEVER run it again: the job exists and is charged, so find it with `aicut list videos|images|audio` and follow it with `aicut wait <id>`.
5. Tell the user the media url and one line about the result.

SEVERAL CLIPS: decide the whole set with the user first, price every distinct request with `--estimate`, state the total in ONE message, ask once for that set and wait for the user's go for exactly that set. After it, run each one with its own `--max-tokens <that request's price> --yes` and no `--wait` (each prints its job id at once), then `aicut wait <id>` for each id until it prints the url. Give the user every url.

If the job fails, read its `error:` line and tell the user what went wrong. Any resubmit is a new purchase with its own price and go, and never the identical request twice: change the model or the prompt, or ask.

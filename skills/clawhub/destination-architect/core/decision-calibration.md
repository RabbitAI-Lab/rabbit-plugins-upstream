# Module：决策校准与反合理化

> 解决两个结构性缺陷：判断没有地面真值、用户可以把结论重问到同意。

## 缺陷一：无校准 → 永远不知道自己准不准

### 预测登记（必须在给出结论之前）

**顺序强制：先登记预测，再给结论。** 颠倒顺序 = 事后诸葛。

每条预测必须含：

| 字段 | 内容 |
|------|------|
| 预测 | 一句话，可证伪 |
| 置信度 | 高 / 中 / 低（不给伪精确百分比） |
| 时间窗 | 多久内可验证 |
| 验证方式 | 引用 [falsification-engine.md](falsification-engine.md) 的实验 |
| 判定阈值 | 事前锁定 |

### 预测台账

所有登记预测写入台账（模板见 [templates/executive-verdict.md](../templates/executive-verdict.md) 底部）。到期回访，核对预测与实际：

- **命中** → 该类型判断的置信度可上调
- **未命中** → 该类型判断的置信度必须下调，并复盘假设哪里错了
- **未回访** → 台账标记"未校准"，该 Skill 对此类判断的输出须标注"未经校准"

**校准调整的是置信度，不是结论。** 用结果修正"我有多确定"，而不是修正"现实是什么"。

## 缺陷二：可被重问到同意 → 合理化机器

### 结构问题

用户掌握 prompt。输出"谨慎做"后，用户可重问，直到模型输出"值得做"。一个能被重新提示到同意的工具，是**合理化机器**，不是决策辅助。

### 合理化警报（反操纵机制）

**触发条件：** 用户在同一项目上，未提供新证据，却要求改变结论或降低风险评级。

**必须响应（不得静默顺从）：**

```
【合理化警报】
检测到结论被重述请求，但未发现新证据。

原始判断：______（置信度：___）
原始预测：______（见预测登记）

请问：什么新证据改变了原判断？

- 若有新证据 → 记录证据，重新分析，并登记"结论变更理由"
- 若无新证据 → 不改变结论。若你仍需要相反结论的文本，可提供，但必须标注：
  「本文为应要求重述，非基于新证据的分析结论，不改变原判断。」
```

### 硬规则

1. **不得静默翻盘。** 任何结论改变必须附带"新证据"或"重述标记"。
2. **不得抹除原始判断。** 原始判断与预测始终保留在输出中。
3. **压力识别。** 用户施压（"你就说能做吧""给我一个能过会的版本"）时，必须先执行委托诊断（见 [SKILL.md](../SKILL.md#step-0-委托诊断强制前置)），区分"合法性生产"与"真相生产"。

### 不变量的 harness 层强制（反 AP-13）

"预测锁定后不可改写"不能只靠上面几行文字。harness 层机制：

- **预测台账（append-only）：** [scripts/guard_predictions.py](../scripts/guard_predictions.py) 对『预测登记』段落做 sha256 封存，配合 PreToolUse hook 拦截改写；
- **G1–G8 门禁：** [scripts/check_gates.py](../scripts/check_gates.py) 逐门禁机械校验（可 CI 化）。

部署方式与"哪些尚未强制"的诚实清单见 [references/harness-enforcement.md](../references/harness-enforcement.md)。**未部署 hook 时，本约束降级为软约束，不得宣称"已强制"。**

---

## 与用户的诚实契约

本 Skill 明确告知使用者：

> 本工具可以被你重新提问，因此任何能被重问到与你想法一致的输出，都是可疑的。真正的保护不是本工具，是你把预测**事前登记**并**承诺回访**。

---

## 输出契约

```
《决策校准》
- 预测登记（结论之前，逐条）
- 预测台账（含锁定时点）
- 校准状态（已校准 / 未校准）
- 合理化警报记录（如触发）
- 结论变更记录（含证据或重述标记）
```

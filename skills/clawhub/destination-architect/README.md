# Destination Architect | 文旅目的地架构师

> 一个帮助用户发现地方价值、构建目的地战略、设计游客体验、建立商业闭环，通过反向审查降低失败风险，并在判断通过后输出**参数化可落地策划案**的 AI 文旅战略专家。

## 它不是什么

- ❌ 不是套话方案生成器（能出参数化可落地策划案，但不编数字、不说空话）
- ❌ 不是景区介绍工具
- ❌ 不是旅游攻略助手
- ❌ 不是 PPT 写作助手

## 它是什么

模拟 20+ 年经验文旅操盘专家的认知系统：能够参与政府文旅规划、目的地打造、商业投资判断和运营增长设计。

**核心护城河：** 在投入大量资金之前，用最小的钱，把一个决策变成可证伪的。

## 第一性原理

```
目的地成功 = 价值不可替代性 × 用户需求匹配度 × 体验吸引力 × 商业可持续性 × 持续运营能力
```

乘法关系——任何一项为 0，整体即为 0。

## 核心能力

| 能力 | 说明 |
|------|------|
| 战略判断 | 从第一性原理推导，不从模板套用 |
| 商业判断 | 4 个必答问题：谁付钱 / 为什么付 / 增长在哪 / 如何避免一次性消费 |
| 用户洞察 | 5 层需求模型：功能 → 体验 → 情绪 → 身份 → 传播 |
| 体验设计 | 完整旅程：到达前 → 到达时 → 游览中 → 消费时 → 离开后 |
| 运营增长 | 三阶段：冷启动 0-1 → 增长期 1-10 → 成熟期 10-N |
| 反向审查 | 4 轮专家级审查（含信息切片 + steelman + 举证义务） |
| 失败预测 | 6 类风险：市场 / 用户 / 运营 / 商业 / 文化 / 政策 |
| **最小成本证伪**（旗舰） | 用最小的钱把决策变成可证伪的实验；设计不出廉价实验 → 尚不值得分析 |
| **决策校准** | 预测登记 + 校准闭环 + 反合理化警报 |
| **信息纪律** | 证据分级，禁止裸数字，防幻觉基准 |
| **策划案组装**（输出层） | 判断通过后输出参数化可落地策划案；四大落地要件缺一即不合格 |
| **参数化财务测算** | 投资 / 收入 / 成本 / 回收期**区间** + 三情景敏感性；无来源数字用参数槽 |

## 工作流程（10 步：Step 0–9）

> Step 0–8 = **判断**（值不值得做）；Step 9 = **出案**（值得做才出参数化策划案）。

0. **委托诊断** — 委托类型（真相 / 合法性）+ 真实瓶颈 + 变量可获取性 → 委托诊断报告
1. **项目诊断** — 收集地区 / 资源 / 目标 / 投资 / 用户 → 项目理解报告
2. **价值发现** — 资源层 → 价值层 → 转化层 → 地方价值模型
3. **战略定位** — 目的地战略定位
4. **产品设计** — 体验产品体系（含游线 / 体验节点 / 消费节点）
5. **商业设计** — 商业闭环模型
6. **运营设计** — 增长运营路线
7. **风险审查** — 失败预警 + 4 轮审查报告（强制不可跳过）
8. **证伪与校准** — 最小成本证伪计划 + 预测登记 + 一页结论（强制收尾）
9. **策划案组装** — 输出可落地文旅策划案（参数化）：实施路线图 + 财务测算模型 + 运营组织与合规清单 + 空间与招商产品清单

## 硬门禁（输出必须满足）

| # | 门禁 |
|---|------|
| G1 | 一页结论前置（决策者不看长文） |
| G2 | 量化陈述带证据标签（`[实测]`/`[引用]`/`[假设]`/`[未知]`）或参数槽 `{{参数:...}}` |
| G3 | 信息缺口清单非空 |
| G4 | 预测先于结论登记 |
| G5 | 至少一个最小成本证伪实验 |
| G6 | 综合判断明确（值得做 / 谨慎做 / 不建议做） |
| G7 | 策划案落地要件齐备（实施 / 财务 / 组织合规 / 空间招商） |
| G8 | 反套话（黑名单未命中） |

**机械校验：** `python3 scripts/check_gates.py <output.md>` 逐门禁扫描（G1–G8）；预测台账不可篡改性由 `scripts/guard_predictions.py`（hash）+ PreToolUse hook 强制。部署方式与"哪些尚未强制"的诚实清单见 [references/harness-enforcement.md](references/harness-enforcement.md)。

## 使用方法

### 场景 1：新项目立项前判断

> "我们县有 XX 资源，想投资 3 亿做文旅，帮我判断值不值得做。"

执行完整 10 步流程（Step 0–9），重点输出 Step 7 风险审查报告与 Step 9 策划案。完整走查见 [examples/case-study.md](examples/case-study.md)。

### 场景 2：已有项目的战略复盘

> "我们这个景区运营两年了，客流下滑，帮我诊断问题。"

执行 Step 1（诊断）+ Step 7（风险审查），定位失败原因。

### 场景 3：单一能力调用

> "帮我分析这个目的地的游客深层需求。"

只调用 [core/user-insight.md](core/user-insight.md) 模块。

### 场景 4：输出可落地策划案

> "这个项目判断可以做，给我一份能落地执行的策划案。"

执行 Step 0–8 判断后，Step 9 组装 [templates/proposal.md](templates/proposal.md)：四大落地要件（实施路线图 / 参数化财务模型 / 运营组织与合规清单 / 空间与招商产品清单），无来源数字以 `{{参数:...}}` 呈现并登记《参数表》。

## 输出质量底线

- 禁止："打造国际一流"、"赋能文旅融合"、"提升影响力"
- 必须：用户逻辑 + 商业逻辑 + 数据意识 + 竞争分析 + 验证方法

## 诚实边界

本 Skill 提供判断框架，不保证结果。不能替代：真实市场调研、地方利益相关方访谈、专业财务建模、法律合规审查、建筑设计。

详见 [SKILL.md](SKILL.md#诚实边界)。

## 维护约定（关键事实一致性）

工作流步数（10 步）、审查轮次（4 轮）、风险类别（6 类）、硬门禁（G1–G8）、能力模块（M1–M10）等关键事实跨多个文件出现。**修改前先查 [references/fact-registry.md](references/fact-registry.md) 并 `grep` 全部出现位置，改后自检无残留过时表述**（如"9 步""G1–G6"）。

## 三层架构建议

```
Destination Intelligence Skill（数据与情报层）
          ↓
Destination Architect（战略架构层）  ← 本 Skill
          ↓
Destination Operator（运营增长层）
          ↓
Destination Investor（投资判断层）
```

最大问题通常是**价值判断错了**，所以本 Skill 最核心的能力不是生成，而是：**反向审查 → 最小成本证伪 → 决策校准**。全行业在卖大报告，本 Skill 卖的是"如何用最少的钱证明这事不该做"。

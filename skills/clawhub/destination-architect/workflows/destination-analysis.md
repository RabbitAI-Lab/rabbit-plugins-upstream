# Workflow：目的地分析（Step 0 → 1 → 3 → 6）

> 委托诊断 → 项目诊断 → 价值发现 → 战略定位 → 运营设计 的完整工作流

## Step 0：委托诊断（强制前置）

在收集任何项目信息之前，先执行 [SKILL.md](../SKILL.md#step-0-委托诊断强制前置) 的三问：

### Q1：委托类型

| 判断 | 输出 |
|------|------|
| 真相生产 | 正常执行 |
| 合法性生产 | 声明不做合法性包装；如需文本，标注"应要求生成，非独立判断" |
| 混合 | 指出约束，分析降级为"决策辅助" |

**判断方式：** 问使用者"如果结论是'不建议做'，你会怎么办？"

### Q2：真实瓶颈

分析 / 资本 / 政治决策 / 能力——**若不是"分析"，显式告知本 Skill 边际价值有限。**

### Q3：变量可获取性

核心变量（客流潜力、付费意愿、在地意愿）能否以合理成本获取？
- 可获取 → 进入 Step 1
- 不可获取 → 输出"当前仅能做条件性分析"，转入 [core/falsification-engine.md](../core/falsification-engine.md)

### 输出

```
《委托诊断报告》
- 委托类型：真相生产 / 合法性生产 / 混合
- 真实瓶颈：分析 / 资本 / 政治 / 能力
- 本 Skill 在本项目中的边际价值：高 / 中 / 低
- 变量可获取性结论
```

## Step 1：项目诊断

### 输入清单

| 维度 | 必须收集 | 缺失处理 |
|------|---------|---------|
| 地区 | 省市县 / 经纬度 / 所在文旅带 | 标注未知 |
| 资源 | 自然 / 文化 / 产业 / 历史 资源清单 | 标注未知 |
| 目标 | 投资方诉求 / 政府诉求 / 运营目标 | 标注未知 |
| 投资 | 总投资 / 建设投资 / 运营预算 | 标注未知 |
| 用户 | 现有客流 / 目标人群 / 来源 | 标注未知 |
| 限制 | 土地 / 政策 / 时间 / 团队 | 标注未知 |

### 诊断输出

```
《项目理解报告》
- 项目基本情况（一句话）
- 核心诉求（投资方 / 政府 / 运营 三方诉求，标注冲突）
- 资源基础（按可塑性分级）
- 投资规模与回收预期
- 关键约束（土地 / 政策 / 时间 / 团队）
- 关键未知（必须通过访谈 / 实地 / 调研 补充的信息）
```

## Step 2：价值发现

调用 📍 [core/value-discovery.md](../core/value-discovery.md) 的三层分析模型。

### 执行步骤

1. **资源层分析** — 按 4 类资源（自然 / 人文 / 历史 / 产业）评估可塑性
2. **价值层四问** — 独特性 / 稀缺性 / 情绪价值 / 时代价值 逐项回答
3. **转化层设计** — 核心价值定位 + 目的地主题 + 差异化竞争点
4. **文化 IP 路径**（如有）— 地方文化 → 故事体系 → 内容 IP → 体验产品 → 商业资产

### 输出

```
《地方价值模型》
- 资源清单（按可塑性分级：高 / 中 / 低）
- 价值四问结论（每问明确判断）
- 核心价值定位（一句话：游客来这里是为了得到 ___）
- 目的地主题
- 差异化竞争点（相对至少 2 个替代目的地）
- 文化 IP 转化路径（如有）
- 关键未知与验证方法
```

**报告模板：** 📍 [templates/strategy-report.md](../templates/strategy-report.md)（Step 1–4 的完整骨架与禁止表达自检）。

## Step 3：战略定位

### 输入

- Step 1 项目理解报告
- Step 2 地方价值模型
- 同类竞品分析（至少 3 个）

### 战略定位四问

1. **是什么？** — 目的地类型 + 核心价值
2. **为谁？** — 核心用户画像（具体到生活方式 / 价值观）
3. **凭什么？** — 不可替代性（通过 Step 2 验证）
4. **如何持续？** — 三年后的护城河

### 输出

```
《目的地战略定位》
- 一句话定位
- 目的地类型（观光 / 度假 / 体验 / 主题 / 复合）
- 核心用户画像（具体到生活方式 / 价值观 / 消费习惯）
- 核心价值主张（解决什么需求）
- 不可替代性（护城河）
- 三年愿景（运营成熟后的状态）
- 战略路径（冷启动 → 增长 → 成熟）
```

## Step 6：运营设计

调用 📍 [core/operation-growth.md](../core/operation-growth.md) 的三阶段模型。

### 输入

- Step 3 战略定位
- Step 4 体验产品体系
- Step 5 商业闭环模型

### 三阶段运营设计

#### 冷启动阶段（0-1）

| 设计 | 内容 |
|------|------|
| 时间 | 0-6 个月 |
| 目标 | 验证价值假设 |
| 第一批用户 | 最有可能为价值买单的种子用户 |
| 内容种子 | 1-2 个可传播核心内容 |
| 渠道 | 选最契合目标用户的高密度渠道 |
| 验证目标 | 用户愿专程来 + 复购 + 传播 |

#### 增长阶段（1-10）

| 设计 | 内容 |
|------|------|
| 时间 | 6-24 个月 |
| 目标 | 扩大认知 + 建立用户资产 |
| 内容 | 围绕核心定位扩展矩阵 |
| 渠道 | 多渠道扩张 + ROI 校验 |
| 用户 | 一次性游客 → 持续用户 |

#### 成熟阶段（10-N）

| 设计 | 内容 |
|------|------|
| 时间 | 24 个月以后 |
| 目标 | 持续创新 + 文化沉淀 |
| 内容 | 持续迭代核心体验 |
| 用户资产 | 会员 / IP 衍生 / 在地社群 |
| 二次增长 | 新产品 / 新场景 / 新人群 |

### 输出

```
《增长运营路线》
- 三阶段时间表与目标
- 内容矩阵设计
- 社交传播设计（触发点 / 社交货币 / 平台 / KOC）
- 用户运营路径（认知 → 忠诚）
- 活动运营节奏
- 数据指标体系
- 关键未知与验证方法
```

**报告模板：** 📍 [templates/operation-plan.md](../templates/operation-plan.md)（三阶段路线 / 内容矩阵 / 传播 / 指标体系骨架）。

## 工作流执行约束

1. **不可跳过 Step 0** — 未诊断委托类型与瓶颈，可能在做无用功或合理化
2. **不可跳过 Step 1** — 信息缺失时必须显式标注未知，不用假设填充
3. **Step 2 → 3 不可越级** — 战略定位必须建立在价值发现之上
4. **Step 6 必须基于 Step 3-5** — 运营设计不能脱离战略与产品
5. **每步输出必须包含"关键未知与验证方法"** — 强制承认假设
6. **每个量化陈述必须带证据标签** — 见 [core/information-discipline.md](../core/information-discipline.md)，禁止裸数字

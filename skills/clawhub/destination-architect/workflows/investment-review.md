## 阶段 2：四个必答问题（强制回答）

调用 [core/business-model.md](../core/business-model.md#四个必答问题强制回答)。

### Q1：谁付钱？

具体到：
- 什么层级的游客？
- 在什么场景下？
- 为什么这个人群愿意付？
- 付的是体验费 / 商品费 / 身份费？

### Q2：为什么付钱？

- 购买的是功能价值还是情绪价值？
- 付费动机是必需 / 享受 / 身份？
- 替代选择是什么？为什么不去替代？

### Q3：收入增长在哪里？

- 客单价提升？通过什么？
- 复购率提升？通过什么？
- 新场景拓展？拓展到哪里？
- 增长的天花板在哪？

### Q4：如何避免一次性消费？

- 复购产品是什么？
- 复购钩子是什么？
- 持续内容更新机制？
- 用户资产沉淀机制？

## 阶段 3：商业闭环校验

```
单客经济模型校验：
  获客成本 < 客均贡献 × 复购次数 × 利润率
  → 通过 / 不通过

可持续性校验：
  运营第 3 年 收入 - 成本 = 利润 > 0
  → 通过 / 不通过

抗风险校验：
  客流下降 30% 后是否仍可维持运营？
  → 通过 / 不通过

补贴退出校验：
  政府补贴 / 政策性收入退出后是否成立？
  → 通过 / 不通过
```

## 阶段 4：投资判断（模拟投资人）

### 投资四问

1. **回收周期** — 多少年回本？（与同类项目对比，是否过于乐观）
2. **IRR** — 内部收益率估算（与机会成本对比）
3. **现金流结构** — 何时为正？是否需要持续输血？
4. **退出路径** — 投资方如何退出？资产证券化 / 股权转让 / 长期分红？

### 投资风险标记

## 工作流执行约束

1. **四个必答问题不可省略** — 任一问题回答模糊即标注"未通过"
2. **校验必须用具体数字** — 不能用"应该可以"模糊带过
3. **乐观估算必须用同类项目校验** — 不能凭空假设
4. **必须做"客流下降 30%"压力测试** — 验证抗风险能力
5. **所有关键指标必须带证据标签** — 见 [core/information-discipline.md](../core/information-discipline.md)
6. **硬门禁：含 `[假设]` 标签的关键指标，不得进入投资判断的"通过"结论** — 必须先经 [core/falsification-engine.md](../core/falsification-engine.md) 证伪升级为 `[实测]`
7. **投资判断前必须有一页结论** — 见 [templates/executive-verdict.md](../templates/executive-verdict.md)

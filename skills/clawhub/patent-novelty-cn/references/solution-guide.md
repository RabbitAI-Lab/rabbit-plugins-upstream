# 技术方案怎么写

技术方案描述（`technical_solution`）是这个任务唯一的核心输入，**它的质量几乎完全决定结果的质量**。

写得空，报告就只能给你一堆「相关领域专利」；写得具体，才能逐条比技术特征、给出有意义的结论。

而这是**付费任务**——改描述重跑要再花一次钱。第一次就写细。

---

## 三件事缺一不可

### 一、解决什么问题

现有技术卡在哪、有什么缺陷。

> 冬季输水渠道的闸阀容易被冰雪和杂物卡滞，人工巡检发现不及时，强行启闭会损坏驱动机构。

这一段决定了检索的技术领域边界。没有它，模型不知道你的方案属于哪个赛道。

### 二、用什么手段

**这是最关键、也最容易写空的一块。** 要具体到：

- **结构** — 什么部件、怎么连接、相对位置关系
- **材料** — 具体的材质、配比、涂层
- **步骤** — 方法类方案的动作顺序、判断条件
- **参数** — 阈值、范围、比例
- **控制逻辑** — 什么条件下触发什么动作

> 在转轴上布置角度传感器与扭矩传感器，在闸前闸后各设一个水位计；当启闭扭矩相对基准值增量超过阈值、且水位差异常时，判定为卡滞；触发安装在闸门框架上的偏心振动装置，以设定频率振动预设时长后重试启闭。

新颖性判断比的就是这些技术特征。**写不出具体手段，就没有东西可比。**

### 三、达到什么效果

最好有量化指标。

> 卡滞识别准确率提升到 90% 以上，避免强行启闭造成的驱动机构损坏，无需人工巡检。

效果是判断创造性时「技术问题—技术手段—技术效果」链条的最后一环。

## 三个颗粒度对照

### ❌ 太短，查了也白查

```
一种新型电池。
```

```
一种智能阀门控制装置。
```

这种描述检索不出任何有参考价值的结果，但钱照扣。脚本会在 80 字以下拦下来。

### ⚠️ 中等，能跑但结论会很宽

```
一种阀门卡滞检测装置，通过传感器检测阀门状态，判断是否卡滞并进行清理。
```

有对象、有大致手段，但「传感器」是什么传感器、「判断」的依据是什么、「清理」怎么清理——全是空的。出来的对比文件会很多但都不够贴，你还是不知道自己的方案到底新不新。

### ✅ 够用，能得出有判断价值的结论

```
一种阀门卡滞诊断与清理装置，用于冬季输水渠道的闸阀。

要解决的问题：冬季闸阀易被冰雪和杂物卡滞，人工巡检发现不及时，
强行启闭会损坏驱动机构。

技术方案：在阀门转轴上布置角度传感器与扭矩传感器，在闸前闸后各设
一个水位计。控制器持续采集转轴角度、启闭扭矩及前后水位；当启闭扭矩
相对同工况基准值的增量超过设定阈值、且闸前后水位差偏离预期范围时，
判定为卡滞状态。同时结合环境温度与积雪含水率判断卡滞成因：含水率高
时判定为冰冻卡滞，含水率低时判定为异物卡滞。

判定卡滞后，控制器触发安装于闸门框架上的偏心振动装置，冰冻卡滞时
以低频大振幅振动 30 秒，异物卡滞时以高频小振幅振动 15 秒，振动结束后
自动重试启闭；连续三次重试失败则上报告警并锁定驱动机构。

技术效果：卡滞识别准确率提升至 90% 以上，避免强行启闭造成的驱动机构
损坏，减少人工巡检频次。
```

这份描述里，每一句都是可以拿去和对比文件逐条比对的技术特征：传感器种类和布置位置、判据（扭矩增量 + 水位差）、成因区分方式（含水率）、执行动作的差异化参数（低频大振幅 / 高频小振幅）、失败处理逻辑。

**有区别特征，才谈得上新颖性。**

## 几个提高质量的做法

**把区别特征标出来。** 如果你知道自己的方案和现有技术的差别在哪，直接写明「与现有技术的区别在于……」。模型会重点核这一点。

**术语的多种写法都列上。** 偏心振动装置 / 振动电机 / 激振器。专利文献里用词不统一，词越全召回越准。

**有数据就写数据。** 阈值、频率、时长、准确率。有实测参数的方案，比对时颗粒度完全不同。

**方法类方案写清顺序和条件。** 什么条件下执行什么，判断分支是什么。

**不要写商业信息。** 成本、售价、客户、市场规模对查新没有帮助，只会稀释技术内容。

**保密提醒。** 技术方案会发送到服务端处理。涉及尚未申请的核心配方、关键参数时，提前告知用户；确实高度敏感的部分可以适度抽象（写「特定配比」而不是具体数字），但要知道抽象会降低比对精度。

## 方案长的时候写文件

```bash
python scripts/patentmax_novelty.py create --solution-file ./solution.md --purpose pre_filing --yes
```

文件要 UTF-8 编码。技术交底书、专利申请草稿、研发报告都可以直接用。

## 写完自检

- [ ] 三件事齐了吗——问题、手段、效果
- [ ] 手段部分有没有具体的结构 / 材料 / 步骤 / 参数，还是只有「通过……实现……」
- [ ] 有没有写明和现有技术的区别在哪
- [ ] 术语的常见别名列上了吗
- [ ] 有实测数据吗
- [ ] 有没有混进不必要的商业信息
- [ ] 涉密内容处理好了吗

六项里过四项，就值得跑了。

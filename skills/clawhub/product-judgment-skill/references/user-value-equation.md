# 用户价值公式 / User Value Equation

> **说明 / Note:** 本文件围绕用户价值公式做应用化展开；其中的案例、检查项和评审方式由本项目整理，并非原书逐字内容。  
> This file operationalizes the user-value equation for practical review. Its examples, checks, and review mechanics are project-side synthesis rather than verbatim book content.

```
用户价值 = 新体验 - 旧体验 - 替换成本
User Value = New Experience - Old Experience - Replacement Cost
```

This formula is the backbone of every demand review. This file explains how to apply it rigorously.

---

## 为什么这个公式重要 / Why This Formula Matters

Most product reviews ask: "Is this feature good?"
The right question is: "Is the net value to the user positive enough to justify the cost of switching?"

These are very different questions.

A feature can be objectively good and still fail because:
- The old experience was good enough
- The switching cost is too high
- The new experience improvement doesn't justify behavioral change

---

## 拆解旧体验 / Decomposing Old Experience

"旧体验" is not just "the competitor product" or "the manual process."
It is the full cost of the user's current solution:

| 维度 | 问题 |
|------|------|
| 时间成本 | 当前方案要花多少时间？ |
| 金钱成本 | 当前方案要花多少钱？ |
| 认知成本 | 需要记住什么、思考什么？ |
| 情绪成本 | 有多烦？有多不确定？有多焦虑？ |
| 错误成本 | 出错的概率和后果？ |
| 依赖成本 | 需要依赖哪些人或工具？ |

**Common mistake:** Teams describe old experience as "the competitor product."
Real old experience often includes: Excel spreadsheets, WeChat groups, phone calls, memory, paper, doing nothing.

**Key insight:** If the old experience costs are low, the new experience has to be dramatically better to win.

---

## 拆解新体验 / Decomposing New Experience

New experience gain should be specific and measurable — not "better" or "more convenient."

| 增益类型 | 具体描述 |
|----------|---------|
| 效率提升 | 同样的事，快了多少倍？ |
| 准确性提升 | 错误率降低多少？ |
| 覆盖范围扩大 | 能做以前做不到的什么？ |
| 情绪改善 | 焦虑减少？自信增加？ |
| 身份/信号价值 | 使用这个产品让用户显得更专业/聪明/高效？ |
| 确定性提升 | 结果更可预期？ |

**Common mistake:** Teams describe new experience as "AI-powered" or "intelligent."
These are mechanisms, not user benefits.

**Reframe:** What does the user feel/achieve/avoid that they couldn't before?

---

## 拆解替换成本 / Decomposing Replacement Cost

This is the most underestimated dimension. Always enumerate ALL of these:

| 成本类型 | 具体内容 |
|----------|---------|
| 学习成本 | 用户需要学什么新东西才能使用？ |
| 迁移成本 | 需要迁移哪些数据、设置、工作流？ |
| 信任成本 | 用户需要多久才能信任新产品的输出质量？ |
| 习惯成本 | 需要打破多久形成的工作习惯？ |
| 组织成本 | 需要说服多少其他人一起切换？ |
| 金钱成本 | 直接费用？机会成本？退出旧系统的成本？ |
| 风险成本 | 如果新产品失败，用户的损失是什么？ |

**The laziness principle:**
Users are rational and lazy. They will not switch unless:
`New Experience Gain > Old Experience Cost + Replacement Cost`

And even then, they need a triggering moment (onboarding, pain spike, social proof) to actually switch.

## 用户价值评分标准 / Scoring Net User Value

| 净用户价值 | 判断标准 |
|-----------|---------|
| **高** | 新体验远超旧体验，替换成本低，用户有明确触发时机 |
| **中** | 新体验有明显改善，但替换成本中等，需要优化引导 |
| **低** | 新体验改善有限，或替换成本高，用户没有足够动力切换 |
| **未成立** | 旧体验已够用，或替换成本高于新体验收益 |

## 关键假设识别 / Identifying Critical Assumptions

For every demand, there are 2-5 assumptions that, if false, make the entire value equation collapse.

**How to find them:**
Ask "what has to be true for this formula to work?"

**Common critical assumptions:**
- 用户真的频繁遇到这个问题（高频假设）
- 用户对现有方案不满意（痛苦假设）
- 用户愿意改变现有行为（行为变化假设）
- 新体验质量足够高（质量假设）
- 用户愿意给新产品足够的信任时间（信任假设）
- 用户能完成迁移（迁移能力假设）

**Rule:** If more than 2 critical assumptions are unverified, verdict = VALIDATE FIRST or KILL.

## 企业价值验证 / Business Value Validation

User value is necessary but not sufficient. Also verify:

```
企业能通过什么机制捕获用户价值？
How does the company capture value from the user value created?
```

| 价值捕获机制 | 问题 |
|-------------|------|
| 直接收费 | 用户愿意为此付费吗？付多少？ |
| 间接变现 | 如何转化为广告/数据/生态收益？ |
| 留存/粘性 | 如何增加用户留存或切换成本？ |
| 获客 | 如何通过这个功能获取新用户？ |
| 战略布局 | 不赚钱但为未来核心能力做铺垫？时间线多长？ |

**Warning:** "战略布局" is often a rationalization for unclear business value. 
Demand that it be specific: what capability, by when, leading to what revenue?

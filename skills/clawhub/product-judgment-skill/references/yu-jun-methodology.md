受《俞军产品方法论》及相关公开产品思想启发整理，用于加强需求判断的理论基础。
Inspired by *Yu Jun's Product Methodology* and related public product thinking, used as theoretical grounding for demand judgment.

俞军，百度第一位产品经理，百度贴吧、百度知道缔造者。其方法论将微观经济学与心理学融合进产品实践，是中文互联网产品思维的底层框架之一。
Yu Jun was Baidu's first product manager, creator of Baidu Tieba and Baidu Zhidao. His methodology integrates microeconomics and psychology into product practice.

## 一、核心命题 / Core Proposition

**企业和用户交换的，从来不是产品，而是价值。**
**What companies and users exchange is never the product — it is value.**

产品是媒介，不是目的。
The product is the medium, not the purpose.

好产品的三个属性：
Three attributes of a good product:

| 属性 / Attribute | 含义 / Meaning |
|-----------------|---------------|
| 有效用 / Useful | 对用户有真实使用价值 / Creates genuine utility for users |
| 有利润 / Profitable | 能让企业直接或间接获利 / Generates direct or indirect profit for the company |
| 可持续 / Sustainable | 交易能持续发生，不是一次性的 / Transaction repeats, not a one-time event |

没有商业闭环的用户价值，是慈善，不是产品。
User value without a business loop is charity, not a product.

## 二、用户模型 / User Model

**产品经理的合格线：掌握用户模型。**
**The baseline for a qualified PM: master the user model.**

### 用户的定义 / Definition of "User"

**用户不是自然人，而是需求的集合。**
**A user is not a natural person — a user is a collection of needs.**

同一个人在不同场景下是不同的"用户"。
The same person is a different "user" in different contexts.

实践含义 / Practical implication:
- 不能用统一画像代替对需求的深入理解。/ Don't substitute a unified persona for deep understanding of specific needs.
- "用户需要X" 是不完整的。完整表述是 "用户在Y场景下因为Z原因需要X"。/ "Users need X" is incomplete. The full statement is "Users need X in context Y because of reason Z."

### 用户的五大属性 / Five Core User Attributes

**1. 异质性 / Heterogeneity**

用户特点千差万别，偏好、认知、拥有的资源都不同。
Users differ vastly in characteristics, preferences, cognition, and available resources.

实践含义 / Practical implication:
当你说"用户会喜欢这个"，你在说的是哪些用户？他们的偏好和资源是什么？
When you say "users will like this," which users? What are their preferences and resources?

---

**2. 情境性 / Situational Dependence**

用户行为受情境影响，没有情境就没有用户。同一个用户在不同情境下行为完全不同。
User behavior is context-dependent. The same user behaves entirely differently across situations.

典型情境变量 / Typical situational variables:
时间、地点、设备、情绪状态、社交场合、金钱状态、物理约束（如驾驶、打电话、购物、办公等）
Time, location, device, emotional state, social context, financial state, physical constraints (driving, on a call, shopping, working, etc.)

实践含义 / Practical implication:
描述需求时必须明确触发情境。"用户需要AI助手"不是需求。
Demand descriptions must specify trigger context. "Users need an AI assistant" is not a demand.

---

**3. 可塑性 / Plasticity**

用户的偏好和认知会随外界信息刺激变化演化。用户是可以被改变的，但改变有成本。
User preferences and cognition evolve with external stimuli. Users can be changed, but change has a cost.

实践含义 / Practical implication:
"用户会慢慢习惯" 是假设，不是保证。习惯期间的流失是真实代价。
"Users will gradually adapt" is an assumption, not a guarantee. Churn during the adaptation period is a real cost.

---

**4. 自利性 / Self-interest**

用户追求个人总效用最大化。用户在做产品决策时，是理性地（在自己的认知范围内）追求对自己最好的结果。
Users maximize their personal total utility. Within their cognitive limits, users rationally pursue what's best for themselves.

实践含义 / Practical implication:
不要期待用户因为"支持你"而使用产品。感情牌不是产品策略。
Don't expect users to use your product out of goodwill. Emotional appeals are not a product strategy.

---

**5. 有限理性 / Bounded Rationality**

用户追求理性，但判断能力是有限的，会受到锚定效应、损失厌恶等认知偏差影响。
Users aim to be rational, but their judgment is limited and subject to cognitive biases like anchoring and loss aversion.

实践含义 / Practical implication:
用户说"我需要X"不一定真的需要X。PM的工作是洞察真实需求，不是照单全收用户的口头表达。
"I need X" doesn't mean they actually need X. A PM's job is to identify real needs, not to take verbal requests at face value.

---

### 用户价值的三个特性 / Three Properties of User Value

| 特性 / Property | 含义 / Meaning |
|----------------|---------------|
| 认知依存 / Cognition-dependent | 用户的认知决定其偏好。认知不同，同样产品价值不同。/ User cognition determines preferences. Same product, different value for different users. |
| 情境依存 / Context-dependent | 偏好不变的人在不同场景下行为不同。/ The same person behaves differently in different situations. |
| 经验反馈演化 / Experience-evolved | 用户价值随使用经验动态变化。/ User value evolves dynamically with usage experience. |

## 三、用户价值公式 / User Value Formula

```
用户价值 = 新体验 - 旧体验 - 替换成本
User Value = New Experience - Old Experience - Replacement Cost
```

最大化新体验的路径 / Ways to maximize New Experience:
- 引入新技术、新人群、新渠道、新方法 / New technology, new users, new channels, new methods
- 旧要素的新组合也能创造新体验 / New combinations of existing elements can create new experiences

最小化替换成本的路径 / Ways to minimize Replacement Cost:
- 降低认知成本（更易理解）/ Reduce cognitive cost (easier to understand)
- 降低获取成本（更易安装/注册）/ Reduce acquisition cost (easier to install/register)
- 降低迁移成本（数据可导入）/ Reduce migration cost (data portability)

## 四、交易模型 / Transaction Model

**产品经理的进阶之路：掌握交易模型。**
**The path to a senior PM: master the transaction model.**

**交易模型**：能促成用户做出某种行为（即交易）且可持续的产品机制。
**Transaction Model**: A sustainable product mechanism that enables users to take a specific action (i.e., complete a transaction).

### 两个核心问题 / Two Core Questions

**问题一 / Question 1：搞清楚各利益相关方在交易中的利害得失**
**Clarify the stakes of each stakeholder in the transaction.**

每一笔产品交易都涉及多方：
Every product transaction involves multiple parties:

| 角色 / Role | 问题 / Question |
|------------|----------------|
| 使用者 / User | 谁在用？/ Who uses it? |
| 购买者 / Buyer | 谁在付钱？/ Who pays? |
| 决策者 / Decision-maker | 谁说了算？/ Who decides? |
| 受益者 / Beneficiary | 谁得到好处？/ Who benefits? |
| 风险承担者 / Risk-bearer | 谁承担风险？/ Who bears the risk? |

在B端产品、多角色场景中，这几者往往是分离的。
In B2B products and multi-role scenarios, these roles are often held by different people.

**问题二 / Question 2：创造有利可图的用户价值**
**Create user value that is profitable.**

用户价值成立 + 企业能捕获价值 = 可持续的产品
User value exists + Company captures value = Sustainable product

只有用户价值没有企业价值捕获：慈善，不可持续。
User value without company value capture: charity, not sustainable.

### 交易成本视角 / Transaction Cost Lens

产品的核心竞争力之一是降低交易成本。
One of a product's core competitive advantages is reducing transaction costs.

| 交易成本类型 / Type | 含义 / Meaning |
|-------------------|---------------|
| 信息成本 / Information cost | 用户找到产品的成本 / Cost for users to discover the product |
| 谈判成本 / Negotiation cost | 用户做决策的成本 / Cost of user decision-making |
| 执行成本 / Execution cost | 用户完成交易的成本 / Cost of completing the transaction |
| 监督成本 / Monitoring cost | 用户验证结果的成本 / Cost of verifying outcomes |

哪个环节的交易成本最高，那里就是产品机会。
The highest-cost step in the transaction is where the product opportunity lies.

## 五、决策论 / Decision-Making Theory

**产品经理的最大价值在于决策，而非具体技能。**
**A PM's greatest value is in decision-making, not in execution skills.**

**资源是稀缺的，目标是"无限"的，决策的本质是取舍。**
**Resources are scarce. Goals are "infinite." Decision-making is fundamentally about trade-offs.**

好决策的要素 / Elements of good decisions:

| 要素 / Element | 含义 / Meaning |
|---------------|---------------|
| 约束条件清晰 / Clear constraints | 资源、时间、技术、政策限制 / Resource, time, technology, policy limits |
| 总价值评估 / Total value assessment | 不同目标之间的价值权衡 / Trade-offs between competing goals |
| 机会成本意识 / Opportunity cost awareness | 做A就是不做B，B的价值是A的成本 / Choosing A means not choosing B; B's value is A's cost |
| 边际思维 / Marginal thinking | 每增加一单位投入，边际收益是多少？/ What's the marginal return per unit of additional input? |

### 认知偏差清单 / Cognitive Bias Checklist

产品决策的常见陷阱：
Common traps in product decision-making:

| 偏差 / Bias | 在产品决策中的表现 / How it appears in product decisions |
|------------|-------------------------------------------------------|
| 路径依赖 / Path dependence | "我们一直这么做" / "We've always done it this way" |
| 锚定效应 / Anchoring | 以竞品价格/功能数量为基准 / Using competitor's price or feature count as the reference point |
| 损失厌恶 / Loss aversion | 害怕删功能比害怕不新增功能更强烈 / Fear of removing features is stronger than fear of not adding them |
| 沉没成本谬误 / Sunk cost fallacy | "已经做了三个月了，不能不上线" / "We've spent 3 months on it, we have to ship" |
| 可得性偏差 / Availability bias | 最近发生的事件（竞品上线）比统计规律更影响判断 / Recent events (competitor launch) outweigh statistical patterns |
| 归因偏误 / Attribution bias | 成功归因自己，失败归因外部 / Success attributed to self, failure attributed to external factors |

## 六、对需求判断的直接应用 / Direct Application to Demand Judgment

基于俞军方法论，做需求审判时必须回答以下问题：
Based on Yu Jun's methodology, demand judgment must answer:

**用户模型检验 / User model check:**
- 这个需求属于"需求集合"中的哪个维度？情境描述是否足够具体？
  Which dimension of the "need collection" does this demand belong to? Is the context description specific enough?
- 用户的有限理性是否导致他们表达了错误的需求？
  Has bounded rationality caused users to express a misdirected need?

**交易模型检验 / Transaction model check:**
- 使用者、购买者、决策者、受益者分别是谁？是否有某方有动机阻止这个产品？
  Who are the user, buyer, decision-maker, and beneficiary? Does any party have incentive to block this product?
- 企业通过什么机制捕获用户价值？路径是否清晰？
  What mechanism allows the company to capture user value? Is the path clear?

**决策质量检验 / Decision quality check:**
- 做这个需求的机会成本是什么？不做这个，可以做什么？
  What's the opportunity cost? What could be done instead?
- 这个决策受到了哪些认知偏差的影响？
  Which cognitive biases are influencing this decision?

## 七、方法要点的项目侧归纳 / Project Notes on Key Ideas

以下内容是本项目对书中及相关公开产品思想的归纳与转述，供需求判断时参考；**不是逐字引文**。如需引用原话，请回到原书或可核验的公开出处。
The notes below are project-side paraphrases and synthesis for demand judgment; **they are not verbatim quotations**. For exact wording, consult the book or another verifiable primary source.

**关于用户研究 / On user research:**
研究用户行为，不是用户说法。用户说的和用户做的往往不一样。
Study what users do, not what they say. What users say and what users do often diverge.

**关于产品价值 / On product value:**
产品是约束条件下的效用组合销售。用户购买的不是功能，而是效用。
A product is the sale of a utility bundle under constraints. Users buy utility, not features.

**关于产品经理的核心能力 / On core PM competency:**
最核心的不是写文档、画原型，而是判断——判断什么值得做，什么不值得做。
The most critical skill is not writing docs or drawing wireframes — it is judgment: knowing what's worth building and what isn't.

**关于商业价值 / On business value:**
高阶PM必须考虑用户价值和商业价值的闭环。只做极致用户体验而不考虑商业可持续是不成熟的。
Senior PMs must consider the loop between user value and business value. Pursuing extreme UX without considering business sustainability is immature.

**关于创新 / On innovation:**
创新的本质是将新要素引入原有的生产或生活方式。新技术本身不是创新，新技术解决了旧方法无法解决的用户问题才是创新。
Innovation is introducing new elements into existing production or life patterns. New technology itself is not innovation — new technology solving problems that old methods couldn't solve is innovation.

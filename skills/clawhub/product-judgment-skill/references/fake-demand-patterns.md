# 伪需求病理学 / Fake Demand Pathology

A taxonomy of fake demand types. Use this to name the disease in Strike 1.

> **说明 / Note:** 以下“病型”是本 Skill 为需求评审整理的操作性标签，用来帮助识别反复出现的伪需求模式；它们**不是《俞军产品方法论》的原书术语**。  
> These labels are operational patterns created for this Skill. They are **not terminology taken from Yu Jun's book**.

---

## 病型一：竞品焦虑症 Competitor Anxiety Syndrome

**症状 / Symptoms:**
- "竞品上了X，我们也要上"
- "行业标配了"
- "我们已经落后了"
- "客户说别家有"

**真实动机 / Real driver:**
Fear of appearing behind — not evidence that users need this feature.

**诊断 / Diagnosis:**
竞品有这个功能，不等于你的用户需要它。也不等于竞品做对了。
The competitor shipping it doesn't mean their users use it, like it, or pay for it.

**关键问题 / Key question:**
竞品这个功能的实际使用率是多少？他们靠它赚到钱了吗？
What's the actual usage rate of that competitor feature? Did it drive revenue?

---

## 病型二：技术炫技症 Technology Push Syndrome

**症状 / Symptoms:**
- "大模型能做这个"
- "我们有这个技术能力"
- "这是技术趋势"
- "AI时代应该有这个"

**真实动机 / Real driver:**
Supply-side capability looking for demand — not demand looking for a solution.

**诊断 / Diagnosis:**
能做不等于该做。技术成熟度不等于市场需求成熟度。
Technical feasibility ≠ market readiness ≠ user need.

**关键问题 / Key question:**
如果没有这项技术，用户现在有多痛苦？他们愿意付多少钱解决这个痛苦？
Without this technology, how much are users suffering? What would they pay to fix it?

---

## 病型三：老板幻觉症 HiPPO Demand Syndrome

**症状 / Symptoms:**
- "领导觉得这个重要"
- "老板在竞品上看到了"
- "高层战略方向"
- "这是公司重点项目"

**真实动机 / Real driver:**
Organizational power ≠ user value. Authority does not validate demand.

**诊断 / Diagnosis:**
组织权力不能自动转化为用户价值。老板的直觉可能对，但它是假设，不是证据。
Leadership intuition is a hypothesis, not evidence. Treat it as a starting point, not a conclusion.

**关键问题 / Key question:**
这个需求有没有真实用户数据支撑？还是纯粹来自内部判断？
Is there any real user data behind this? Or is it purely internal opinion?

---

## 病型四：Demo成瘾症 Demo Addiction Syndrome

**症状 / Symptoms:**
- "演示效果很惊艳"
- "领导看了都说好"
- "发布会上亮点"
- "媒体曝光价值高"

**真实动机 / Real driver:**
Optimizing for demo impressiveness, not for daily usefulness.

**诊断 / Diagnosis:**
能打动领导，不代表能进入用户日常。演示成功是发布前的事，产品成功是发布后六个月的事。
A great demo is a 5-minute experience. A product needs to survive 6 months of real usage.

**关键问题 / Key question:**
演示场景和真实使用场景有多大差距？用户每周会用几次？
How different is the demo context from real usage? How many times per week will users actually use this?

---

## 病型五：替换成本失明 Replacement Cost Blindness

**症状 / Symptoms:**
- "新产品比旧方案好很多"
- "用户一定会迁移过来"
- "我们体验已经碾压了"
- "旧方案那么烂，用户肯定想换"

**真实动机 / Real driver:**
Overestimating new experience gains, ignoring migration friction.

**诊断 / Diagnosis:**
用户是理性的懒惰动物。新体验好10%，但迁移成本是50%，用户不会迁移。
Users are rational and lazy. A 10% improvement doesn't justify a 50% migration cost.

**替换成本维度 / Replacement cost dimensions:**
- 学习成本：需要重新学多少东西？
- 迁移成本：数据、设置、工作流要迁移多少？
- 信任成本：用户凭什么相信新方案？
- 组织成本：需要说服多少人同意切换？
- 金钱成本：直接费用和机会成本

**关键问题 / Key question:**
一个理性但懒惰的用户，面对这个迁移成本，会怎么决策？
Given all migration costs, what would a rational but lazy user decide?

---

## 病型六：商业闭环断裂 Broken Business Loop

**症状 / Symptoms:**
- "用户喜欢，但我们不知道怎么收费"
- "先做用户量，再想商业化"
- "免费获客，后面再说"
- 用户满意度高，但收入不增长

**真实动机 / Real driver:**
User value created, but no mechanism to capture business value.

**诊断 / Diagnosis:**
用户爽了，公司饿死了。没有商业闭环的用户价值，是慈善，不是产品。
User delight without revenue capture is charity, not product.

**关键问题 / Key question:**
如果这个功能做得非常成功，公司通过什么机制获得收益？路径有多清晰？
If this feature succeeds wildly, what's the exact mechanism for the company to capture value?

---

## 病型七：低频刚需误判 Frequency Misjudgment

**症状 / Symptoms:**
- "用户确实有这个需求"
- "这是真实痛点"
- "用户反馈强烈"

**但是 / But:**
使用频率极低（一年几次），或触发场景太小众。

**诊断 / Diagnosis:**
痛点真实，不等于产品机会足够大。用户一年用一次的刚需，不支撑一个产品线。
A real pain point that occurs once a year doesn't justify a product team.

**关键问题 / Key question:**
这个场景多久触发一次？触发时用户有多少时间/意愿来用你的产品？
How often does this scenario trigger? Is there enough time and motivation for users to use your product when it does?

---

## 病型八：万能入口症 Swiss Army Knife Syndrome

**症状 / Symptoms:**
- "我们要做一个平台"
- "一个入口满足所有需求"
- "超级App"
- "用户在里面能做所有事"

**诊断 / Diagnosis:**
用户不会为你的战略版图改变使用习惯。他们只在特定场景有特定需求。
Users don't restructure their lives around your product strategy. They have specific needs in specific moments.

**关键问题 / Key question:**
在哪一个具体的场景里，你的产品是用户的第一选择？只有一个场景也行，但必须有一个。
In which one specific scenario is your product the user's first choice? Just one is fine — but there must be one.

---

## 病型九：指标幻觉症 Metric Illusion Syndrome

**症状 / Symptoms:**
- "这个功能能提升点击率"
- "上线后停留时长增加了"
- "搜索次数涨了30%"

**真实问题 / Real problem:**
指标涨了，不代表用户价值成立。指标是结果的影子，不是结果本身。影子变大，不代表人变大。

**诊断 / Diagnosis:**
点击率可以被标题党拉高，停留时长可以被无限滚动拉高，搜索次数可以被烂结果逼高。
优化了指标，不等于创造了用户价值。

**典型陷阱 / Typical traps:**
- 点击率↑ 但转化率/留存率没变 → 吸引了注意力，没创造价值
- 停留时长↑ 但满意度↓ → 让用户困在里面，不是让用户满足
- 搜索次数↑ 但零结果率也↑ → 用户在找，但没找到

**关键问题 / Key question:**
如果停止这个功能，用户会有什么真实损失？他们会为此投诉、流失、或拒绝付费吗？

---

## 病型十：场景错配症 Context Mismatch Syndrome

**症状 / Symptoms:**
- "这个功能在手机上很成功，移植到车机/手表/大屏"
- "海外验证了，国内直接复制"
- "ToC验证了，ToB也能用"

**真实问题 / Real problem:**
场景不同，用户心智不同，触发时机不同，替换成本不同。在A场景成立的需求，B场景可能完全不成立。

**诊断 / Diagnosis:**
产品逻辑是情境依存的（俞军用户模型核心原则之一）。
用户在车里的认知负荷、注意力模式、操作姿势、可接受的复杂度，和坐在沙发上拿手机完全不同。把手机成功经验搬到车机，等于在换了物理定律的地方用原来的工程图纸建房。

**关键问题 / Key question:**
在目标场景里，用户的注意力窗口、操作方式、容错空间，和原场景差距有多大？这些差距如何重写用户价值公式的每一项？

---

## 混合病型 / Mixed Patterns

Many demands have multiple diseases. When naming the disease in Strike 1, list all that apply:

Example: "这是一个**技术炫技症 + 商业闭环断裂**的混合需求。"

The more diseases, the stronger the KILL verdict.

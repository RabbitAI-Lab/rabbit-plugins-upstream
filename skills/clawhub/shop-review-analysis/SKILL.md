# 店铺口碑分析

用可核查的门店资料和消费体验，回答值不值得去、适合谁、花多少钱、推荐什么、要留意什么。默认用用户语言作答，结论先行，按问题深度决定篇幅。

## 运行条件

本技能是可移植的指令工作流，不包含爬虫脚本或平台账号。需要宿主提供联网搜索和网页读取能力；读取登录后内容还需要可连接用户已登录浏览器配置的工具及相应站点的有效登录态。适用于具备这些能力的 Codex、OpenClaw 或其他 Agent Skills 宿主；不假定工具同名，不保证所有平台可读取全部评论。不需要固定环境变量、额外 API 密钥或自动安装软件。只读检索是默认范围。

## 定位门店

先核对城市、店名、分店名、地址。用户只给连锁品牌时，用已知城市搜门店；可先分析已确认的代表门店并声明范围，只有选择分店会实质改变答案时才询问。不同分店、不同城市分别记录，不能合并评分或把一家差评归到所有门店。

## 获取资料与登录态

- 优先使用当前可用且适合该平台的 MCP/连接工具；用户指定 Edge 或当前浏览器登录态时，使用可用的浏览器工具连接那个浏览器配置。沿用当前会话已验证的浏览器绑定，不重新选择配置，不导出 Cookie、令牌或密码。
- 检索引擎用于找门店页、笔记和公开补充资料；随后打开原始页面核对。检索摘要只作线索，不能当作已经读过完整正文或评论。用户指定的平台逐一尝试，并简要记录哪些已读取、哪些受限。
- 浏览器任务先阅读该运行时实际返回的操作文档。根据新鲜 DOM/可访问性树或截图读取、点击、搜索、筛选、展开和滚动；只在受支持的页面 DOM 范围读取数据。不要复用固定坐标、动态 CSS 类名、旧元素索引，也不猜测隐藏 API、注入网络请求或绕过网站限制。
- 登录后可读范围与全量爬取能力分开确认。平台可能允许查看评分和精选评论，却仍把“全部评价”、菜单或团购详情导向 App。确认实际限制后停止无效重试，继续用已有证据；不要把 App 限制误报成没登录，也不要要求已经登录的用户重复扫码。
- 未登录时保留所需登录页面，让用户自行扫码，继续独立检索。遵守工具关于验证码及确认的要求。不要主动登出、切换账号、修改浏览器设置、发评论、关注或购买。
- 保留可点击的原始内容链接和读取日期；图片中的菜单、小票、账单用视觉核对。分享笔记链接中的内容访问参数与账户凭据不能混淆；不要泄露账户认证信息。

## 取样与证据

大众点评优先核对门店评分、评价总数、评分尺度、人均、营业信息、推荐菜以及能访问的近期好评/中差评。平台标签及其计数属于平台汇总，不能当成自己读过的评论数。

小红书与抖音阅读具体笔记/视频描述和评论，优先选择明确门店、有菜品细节、消费记录、复购体验的内容。标题写“无广”“自费”只算作者声明；商业合作标识、团购导购、统一宣传话术作为可信度线索，不能仅凭文风断言刷评。没有观看视频或取得转写时，不声称已经听到视频中的测评。

同时主动找负面体验，避免只读取综合排序的正面内容。通常先读约 5–10 条有内容的独立体验，结合多平台交叉核对；这是起点而非硬性配额。更简单的问题可少读，争议或资料不足时有针对性补充。正文与其评论分开，作者回复、重复转载和同一作者多次描述不能当成独立顾客样本。跑题争吵、未到店的附和不作为消费证据。

优先近 3–6 个月内容并保留原始日期。页面只显示月日时，标明年份未显示，不擅自补年份；相对时间可结合当前用户日期注明“页面显示几天前”。旧的开业排队、旧菜单和旧评分只作历史参考。未经核实的卫生、预制菜、欺诈等指控只能按作者说法谨慎归属，不当作已证实事实。

调查时维护简洁证据记录：平台、门店、链接、评价/消费日期、读取日期、资料类型、评分/金额及单位、核心优点与问题、正文是否完整、商业属性与不确定性。无需为普通问答自动创建额外报告或保存用户账户资料。

## 综合判断

- 价格区分平台人均、单次账单、菜单单价、套餐价、代金券面值/售价、茶位费与打包费。套餐未读到内容、限制和额外费用时，不把展示售价当最终实付，也不直接建议购买或认定划算。
- 把味道、分量、油腻/甜度、服务、环境、排队和性价比分开分析。说明问题是多位独立顾客反复提到还是单条个案；保留相反体验，并优先解释分店、时段、日期或口味偏好的差异。
- 不平均不同平台评分，不把点赞量当评分，不把抽样好差评比例当全店好评率。只在掌握完整分母、来源与计算口径时给出比例；不虚构综合分、精确风险概率或近期趋势。
- “清淡”可能指不辣，也可能指少油，先看具体菜品反馈。饮食偏好可以改变推荐：不吃辣、怕甜、少油、预算、用餐人数分别匹配；不把主观口味差异描述为所有人都会踩雷。

## 输出

先给有条件的消费建议。随后按需提供门店与查询日期、平台评分/评价量/人均、反复获好评的菜品、具体负面问题、预算与点餐/到店建议，并在对应主张旁附来源。区分平台事实、顾客体验和自己的推断。

最后用一句话交代覆盖范围，例如“读取大众点评展示的 3 条近期评价及 5 篇小红书正文；全部点评列表仍要求 App，无法计算好评率”。资料不足时明确哪些结论暂不能下，不用缺失数据补出确定答案。用户要多店比较时使用同口径表格，并说明分店与资料日期差异。

## STAR原则详解

STAR是描述问题/事件的标准框架，帮助清晰、结构化地呈现情境。

### 四要素定义

| 要素 | 含义 | 关键问题 | 示例 |
|------|------|----------|------|
| **S - Situation** | 情境 | 何时？何地？什么条件下？ | "2024年1月10日夜班，A线注塑车间" |
| **T - Task** | 任务 | 预期目标是什么？ | "计划产能2000件/班次" |
| **A - Action** | 行动 | 实际发生了什么？ | "实际产出1400件，故障停机3次" |
| **R - Result** | 结果 | 造成了什么影响？ | "完成率70%，损失600件" |

### 常见错误

| 错误类型 | 问题描述 | 修正方式 |
|----------|----------|----------|
| 缺少情境 | 只有"设备坏了"，无时间地点 | 补充"某日某班次某设备" |
| 结果模糊 | "影响很大"、"比较严重" | 量化："停机4小时，影响XX产能" |
| 混淆任务与结果 | "目标是1000件，实际只做了800件" | 任务=1000，结果=800 |
| 行动描述缺失 | 只说"出了问题" | 补充具体发生了什么 |

### 验证检查清单

```
[ ] S - 是否说明时间/地点/条件？
[ ] T - 是否有明确的预期标准？
[ ] A - 是否描述了实际发生的情况？
[ ] R - 是否有量化数据支撑？
[ ] 四要素是否按顺序逻辑连贯？
```

## SMART原则详解

SMART是设定有效目标的标准框架。

### 五要素定义

| 要素 | 含义 | 检验问题 | 示例 |
|------|------|----------|------|
| **S - Specific** | 具体 | 要达成什么？ | "提升设备OEE" |
| **M - Measurable** | 可衡量 | 如何量化？ | "OEE从58%提升至75%" |
| **A - Achievable** | 可达成 | 目标现实吗？ | "通过TPM改善预计可达" |
| **R - Relevant** | 相关 | 与业务目标关联？ | "支撑产能目标达成" |
| **T - Time-bound** | 有时限 | 何时截止？ | "2024年3月31日" |

### 常见错误

| 错误类型 | 问题描述 | 修正方式 |
|----------|----------|----------|
| 目标模糊 | "提升质量" | 改为"不良率从5%降至2%" |
| 不可衡量 | "大幅改善" | 改为具体数值或百分比 |
| 目标低于现状 | "维持现有水平" | 必须有提升或改善 |
| 无时间限制 | "尽快完成" | 设定具体截止日期 |

### 验证检查清单

```
[ ] S - 目标是否具体明确？
[ ] M - 是否有可量化的指标？
[ ] A - 目标是否可达成？（不能太低，也不能不切实际）
[ ] R - 目标与业务目标是否关联？
[ ] T - 是否有明确的截止日期？
[ ] 目标值是否 > 现状值？
```

## 5Why追问技巧

### 核心原则

1. **逐层追问**：每回答一层，继续问"为什么"
2. **寻找可控原因**：最终原因应该是可以直接采取措施的
3. **逻辑连贯**：每层原因之间必须有因果关系

### 追问判断标准

```
判断是否为"根本原因"的检验问题：
1. 这个原因可以直接采取措施改善吗？
2. 解决了这个原因，问题会真正解决吗？
3. 还需要继续追问"为什么"吗？

如果答案都是"是"→ 已找到根本原因，可以结束追问
如果答案是"否"→ 继续追问下一层
```

### 追问话术示例

```
用户：设备故障频繁
↓ Why1
智能体：为什么设备故障频繁？
用户：因为设备老化了
↓ Why2
智能体：为什么设备老化会影响这么大？
用户：因为没有定期保养
↓ Why3
智能体：为什么没有定期保养？
用户：因为维修人员都在处理紧急故障，没时间做保养
↓ Why4
智能体：为什么维修人员都在处理紧急故障？
用户：因为故障太多，忙不过来
↓ Why5
智能体：为什么故障这么多？
用户：因为缺乏预防性维护机制
       ↓
       根本原因：缺乏预防性维护机制
       措施：建立TPM体系，实施预防性维护
```

### 多维度补充（可选）

除了5Why，还可以从"人机料法环测"维度补充分析：

| 维度 | 含义 | 分析要点 |
|------|------|----------|
| 人 | 人员 | 技能水平、操作习惯、培训情况 |
| 机 | 设备 | 设备状态、工装夹具、备件管理 |
| 料 | 材料 | 原材料质量、零部件规格 |
| 法 | 方法 | 作业方法、工艺参数、作业标准 |
| 环 | 环境 | 温度湿度、清洁度、空间布局 |
| 测 | 测量 | 检测方法、测量系统、数据准确性 |

## 数据验证规则

### 完整性验证

| 模块 | 必填项 | 缺失时处理 |
|------|--------|------------|
| 问题描述 | S/T/A/R + R项量化 | 返回追问补充 |
| 现状分析 | 数据描述 + 来源 + 时间范围 | 返回追问补充 |
| 目标设定 | SMART五要素 | 返回追问补充 |
| 根本原因 | ≥4层Why + 根本原因确认 | 继续追问 |
| 改进措施 | 原因-措施对应完整 | 补充措施 |
| 行动计划 | 时间节点 + 里程碑 | 补充 |

### 逻辑性验证

| 检查项 | 规则 | 不通过时处理 |
|--------|------|--------------|
| 目标-现状 | 目标值 > 现状值 | 要求修正目标 |
| 原因-措施 | 每原因有对应措施 | 要求补充措施 |
| 时间逻辑 | 措施完成 < 目标达成 | 要求调整时间 |
| 指标一致 | 目标指标 = 验证指标 | 要求统一指标 |

### 格式规范性验证

| 检查项 | 标准 | 不通过时处理 |
|--------|------|--------------|
| STAR格式 | 四要素齐全且顺序正确 | 引导重新描述 |
| SMART格式 | 五要素齐全 | 引导补充 |
| 数据格式 | 数值统一精度、比例统一基数 | 规范化处理 |
| 数据可信度 | 有来源、有时间范围 | 要求补充 |

## 常见错误与修正

### 问题描述类

| 错误 | 修正 |
|------|------|
| "设备经常出问题" | 补充："1月10-15日期间，A线注塑机故障5次，累计停机12小时" |
| "影响很大" | 量化："造成产能损失600件，影响订单交付" |
| "我们做了很多努力" | 具体："采取了XX措施，但仍未解决" |

### 目标设定类

| 错误 | 修正 |
|------|------|
| "尽快解决" | "2024年2月28日前完成" |
| "尽量减少不良" | "不良率从5%降至2%" |
| "保持现有水平" | 设定提升目标："OEE从58%提升至70%" |

### 原因分析类

| 错误 | 修正 |
|------|------|
| 停在表面原因 | "设备坏了" → "为什么坏了？因为缺乏保养" → 继续追问 |
| 跳步太多 | 确保每层原因之间有清晰因果链 |
| 停在不可控原因 | "因为天气热" → 追问："为什么天气热会影响？" |

### 措施制定类

| 错误 | 修正 |
|------|------|
| 措施与原因无关 | 确保每条措施能解决至少一个原因 |
| 责任人模糊 | "相关人员" → "设备主管王工" |
| 无时间节点 | "尽快实施" → "1月31日前完成培训" |

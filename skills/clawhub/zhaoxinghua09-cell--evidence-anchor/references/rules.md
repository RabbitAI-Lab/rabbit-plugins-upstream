# 判定规则细则

## 什么是"锚点"

一个形如 `路径/文件.扩展名:行号` 的字符串。可选再带 `:列号`。

```
scripts/review.py:157          → 文件 scripts/review.py 的第 157 行
SKILL.md:412                   → 同目录 SKILL.md 的第 412 行
docs/spec.md:12:5              → 第 12 行第 5 列（列不参与行号判定）
```

支持的扩展名：`py / md / json / html / txt / yml / yaml / toml / ini / cfg`。

## 三种状态

| 状态 | 含义 | 退出码影响 |
|---|---|---|
| `OK` | 文件存在，行号在 1..总行数 之内 | 无 |
| `FILE_MISSING` | 根目录下找不到该文件 | 退出码 1 |
| `LINE_OOR` | 文件存在但行号超出总行数 | 退出码 1 |
| `NO_ANCHOR` | 报告里一个锚点都没有 | 不判错，退出码 0 |

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 全部 OK，或整篇没有锚点 |
| 1 | 至少一个 `FILE_MISSING` / `LINE_OOR` |
| 2 | 参数错误、根目录不存在、报告读不出 |

## 两处容易写错的地方

**一、`a.md:12:5` 里的 5 是列，不是行。** 按行解析会把 5 当行号，配合只有 10 行的文件就会误报越界。正则把第三段单独捕获，不参与判定。

**二、反斜杠路径。** 报告常在 Windows 上写、在 Linux 上读。`sub\c.py:3` 与 `sub/c.py:3` 指的是同一个文件，解析前统一把 `\` 换成 `/`。

## 为什么报告总行数必须打出来

读者需要区分两种"第 157 行"：

- 1097 行的文件里第 157 行 —— 有内容，可核对；
- 12 行的文件里第 157 行 —— 锚点早已失效，只是没人发现。

不打出总行数，读者无从判断是哪一种。

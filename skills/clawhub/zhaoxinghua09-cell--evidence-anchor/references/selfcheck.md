# 自检说明

9 条用例，覆盖三类状态、两种路径写法、两个退出码和一个格式约束。

## 怎么跑

```bash
python tests/run_golden.py
```

期望结尾：`---- 9/9 PASS ----`，退出码 0。

## 覆盖表

| 编号 | 验证点 | 为什么值得测 |
|---|---|---|
| G01 | 文件在、行号在范围内 → OK | 主路径 |
| G02 | 文件不存在 → FILE_MISSING | 最常见的假证据 |
| G03 | 行号越界 → LINE_OOR | 文档改版后的典型失效 |
| G04 | `sub\c.py:3` 反斜杠 → OK | Windows 写、Linux 读 |
| G05 | `d.py:12:5` 的 5 是列 → OK | 错当行号会误报越界 |
| G06 | 纯叙述文档 → NO_ANCHOR | 无锚点不该判错 |
| G07 | 有失效锚点 → 退出码 1 | 能被流水线拦住 |
| G08 | 根目录不存在 → 退出码 2 | 参数错不能被当成"全部正常" |
| G09 | 新增文件行尾 LF | Windows 下不显式 `newline="\n"` 会变 CRLF |

## 互不污染

每条用例在 `tempfile.mkdtemp()` 里自建最小树，跑完 `shutil.rmtree`。用例之间没有共享状态，可以乱序执行，也不会碰到仓库里的真实文件。

## 一条刻意的设计

G01 断言的是"扫描结果里第一条的状态等于 OK"，不是"函数被调用了"。

因为断言动作只能证明代码跑过，断言结果才能证明判定是对的。**这是这个包最容易被写歪的地方**，所以写进了用例说明。

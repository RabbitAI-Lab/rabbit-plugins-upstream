# 或有事项与承诺事项·逐条挂源

给一份财报，把附注里的**或有事项与承诺事项**读成一张**每个数都能回到原句**的登记表：或有事项（未决诉讼与仲裁、对外担保、已贴现商业承兑票据、产品质量保证、重组义务、亏损合同）、承诺事项（资本承诺、经营租赁承诺、投资承诺、大额合同承诺）、预计负债与或有负债的区分、与日后事项和关联方担保的界线、未决诉讼的阶段与涉案金额。

或有事项是附注里**最容易被一句话带过、也最容易出事**的一块：担保余额写在明细表里、诉讼进展写在另一张表里、计提与否只在正文一句话里。同一件事，有的公司提了预计负债、有的只作附注披露——**这两种不是同一种处理**，混写就把界线抹掉了。本件把披露怎么写逐条登记下来，结论留给人。

**不估败诉概率、不估赔偿金额、不判断是否导致违约或退市、不评价偿债能力、不给评级与目标价。** 或有性质、终止确认、诉讼阶段、界线只认原句；要自己算的比例，必须单列并交代金额出处与分子分母。

## 一、三十秒跑通（零输入）

不给任何数据文件，也能跑出一份完整合规的成品，看它长什么样、判据怎么打：

```bash
python3 scripts/check_contingency.py --demo
```

把这份样例存下来再跑一遍机检，它能自己过：

```bash
python3 scripts/check_contingency.py --demo > 样例或有稿.md
python3 scripts/check_contingency.py 样例或有稿.md
# → 样例或有稿.md 结论：五道全过（零发条）
```

接着换成你自己那份稿子：

```bash
python3 scripts/check_contingency.py 你的或有稿.md
```

退码 `0` 全过、`1` 有发条、`2` 用法错、`3` 读不到文件或空稿。

### 拿不到成品时，从原文开始的三步

1. **定主体与报告期**，拿到年报附注「或有事项」「承诺事项」「预计负债」那几节，加相关公告。
2. **每节抄事实，连原句一起抄**：一条 = 一行，行末挂 `「原句」〔锚：页/表〕[S#]`。
3. **跑一遍自检**，红一条改一条：

```bash
python3 scripts/check_contingency.py --selftest
```

### 先确认通道在场（可选）

配了 `CUE_API_KEY` 才需要这一步。先列目录，再按目录里的路由地址确认工具在场：

```bash
CATALOG="https://cuecue.cn/api/mcp-catalog"
curl -s "$CATALOG" | head -c 2000
# 从目录里取本组的路由地址，确认工具在场
curl -s -X POST "$ROUTING_URL" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

没配凭据也能用：把附注与公告放进工作区，走用户直供那条路，代价是担保明细表与诉讼进展表只能在手头文件里翻。

## 二、五道机检在管什么

| 码 | 名称 | 判什么 | 最常拦住的情况 |
|---|---|---|---|
| `CC-STRUCT` | 形制 | 头部四件自标、`主体：`、`报告期：` 在场；七节齐且有序；前五节各至少一条发现行 | 七节缺一节；某节只有小标题；多出一节同名标题 |
| `CC-QUOTE` | 原句与锚 | 每条发现行以「」原句＋〔锚：…〕＋`[S#]` 收尾；来源行带可点 URL 与检索日；引用的编号须已登记 | 只写担保金额没抄原句；来源行只有标题没有链接 |
| `CC-NOSELF` | 不得自推自算 | 或有性质、终止确认、诉讼阶段、与日后事项和关联方担保的界线只认原句；比例原句没写必须标 `〔自算〕` 并写明分子分母；或有金额自算须写金额取哪一句 | 原句只写「已贴现」，本件自己写「未终止确认」；只写「已起诉」就自标「一审已判决」 |
| `CC-GAP` | 未取到两向点名 | 正文写了未取到而第六节没列要发，反之也发；零缺口须显式写「未取到：无」 | 用「不适用」「无此项」「无需披露」搪塞 |
| `CC-LINE` | 红线 | 败诉概率、赔偿金额估算、违约、退市风险、偿债能力、风险可控、评级目标价零命中；引文先洗掉再判；预计负债写成等于或有负债照发 | 「本案胜诉概率较高，不会败诉」 |

## 三、四条红线（这件的立身之本）

1. **或有性质只认原句。** 附注只列了担保余额、没写是否计提的，正确做法是写未取到，不是按「担保一般都要计提」替它认定。
2. **终止确认只认原句。** 「已贴现」不等于「已终止确认」——附追索权的贴现恰恰是或有事项。这条判的不是禁词，是**证据来源**。
3. **预计负债 ≠ 或有负债。** 前者已确认入表，后者只在附注披露，两者不是同一个数、也不是同一种处理，不许写成相等或互相替代。
4. **或有金额不代算。** 担保占净资产比例一类要自己算的，必须标 `〔自算〕`，并在同一行写明金额取哪一句、分子分母各挂各的来源——缺一即发。

## 四、一条发现长什么样

```markdown
- 已贴现商业承兑票据 500.00 万元「已贴现未到期的商业承兑票据 5,000,000.00 元，附追索权，本公司未终止确认」〔锚：2025 年年报·第 131 页·附注三·或有事项〕[S1]
```

没取到的，自成一行、照实写：

```markdown
- 亏损合同 未取到：附注未披露亏损合同
```

要自己算的，长这样（金额出处与分子分母各自挂源）：

```markdown
- 担保余额占净资产比例 3.00%〔自算〕金额取附注「本公司为子公司提供担保 30,000,000.00 元」〔锚：2025 年年报·第 130 页·附注三·或有事项〕[S1]｜分子＝担保余额 30,000,000.00 元 [S1]｜分母＝归属于母公司所有者权益 1,000,000,000.00 元 [S1]
```

## 五、和另外几枚包怎么分

| 你手上是 | 用哪枚 |
|---|---|
| 或有事项、承诺事项、预计负债与或有负债、未决诉讼、对外担保 | **本件** |
| 财报四期差异、科目勾稽的点评 | `cn-earnings-note` |
| 票据本体的分类、背书、坏账准备 | `cn-notes-receivable-cn` |
| 公开信息九类覆盖率盘点与带锚事实表 | `dd-checklist` |
| 处罚与监管措施的扫描 | `event-risk-scan` |
| 审计意见类型、关键审计事项 | `cn-audit-opinion-cn` |

已贴现票据是这两枚的接缝：**票据本身（分类、背书、坏账）归 `cn-notes-receivable-cn`，贴现后的或有追索归本件**——本件只在或有事项那一节登记"附追索权、未终止确认"这一层。

## 六、素材从哪来

- **用户直供**：手头的年报 PDF、公告，走解析通道读成能检索的正文。
- **通道取证**：配了 `CUE_API_KEY` 后可走公告检索与原文解析。装好 skill ≠ 已配凭据 ≠ 通道已连，三层分开看。
- **或有材料常散在多张表里**（担保明细表、诉讼进展表、承诺到期表），长附件与扫描件交给解析腿：先取大纲，再按节取用。计费与可用性以服务端返回为准。

本件不发请求、不代付费，消耗以服务端返回为准。

## 七、跑夹具与测试

```bash
bash scripts/fixtures/run_fixtures.sh
python3 tests/test_contingency.py
```

三档：机检自测 / 好样坏样逐枚单跑 / 在好样上逐处替换做正反对照（该红的红、该不红的不红）。零网络、零计费，产物只落临时目录，跑完即删。

末行自报「档数=…｜不合=N｜不可判=N」（档数由 runner 自己现算，不写死）；退码 `0` 全过、`1` 有不合、`3` 取值域故障。

`tests/` 跑的是外壳属性——`--help` 退 0、无参退 2、缺文件或空稿退 3、`--demo` 产物自过机检且与好样夹具同源、埋点落盘且失败静默。

## 八、首次运行埋点

入口脚本解析参数成功后、干正事之前，会往 `~/.cue-usage/<slug>-<日期>` 落一枚**空文件**。

**为什么要它：** 平台的两个下载计数器都不可信——新 listing 上架首 48 小时会被一次性播种 50~60 的初始计数，那不是用户下载。本地这枚文件是本件唯一能证明「真有人装上并跑过」的证据。

**它不会碍事：** 任何失败（家目录只读、配额满、无 HOME）都静默跳过，不报错、不改退码、不吐一句杂音。同一天跑多次只留一枚。

要清掉：`rm -rf ~/.cue-usage`。

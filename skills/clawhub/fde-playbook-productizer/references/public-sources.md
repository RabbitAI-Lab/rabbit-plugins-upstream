# Public method sources

- [AWS: Repeatable Generative AI Application Pattern](https://docs.aws.amazon.com/prescriptive-guidance/latest/strategy-enterprise-ready-gen-ai-platform/patterns.html): Adopt modular “build once, reuse many times” to establish business, user and technical evaluation and experimentation/maturity grading for the pattern.
- [AWS: Enterprise Generative AI Scaling Best Practices](https://docs.aws.amazon.com/prescriptive-guidance/latest/strategy-enterprise-ready-gen-ai-platform/best-practices.html): Establish an asset library containing patterns, code templates, and architecture diagrams, and gradually expand and support governance and support.
- [AWS: Generative AI application production architecture](https://docs.aws.amazon.com/prescriptive-guidance/latest/gen-ai-lifecycle-operational-excellence/preprod-architecting.html): Split the single POC into modular, testable, and reusable components, and structure the promotion of assets across stages.
- [AWS: Advancing from POC to pre-production](https://docs.aws.amazon.com/prescriptive-guidance/latest/gen-ai-lifecycle-operational-excellence/dev-advancing.html): Use POC to learn to expand the evaluation set, formalize the architecture, and version management, instead of directly treating prototypes as production capabilities.
- [Microsoft: Documentation of Architecture Decisions](https://learn.microsoft.com/en-us/azure/well-architected/architect-role/collaboration): Technical debt needs to be intentional, documented, and repayable; validated learning should feed into standard paths and team knowledge.

# de-identification public case template

## Use front access control

Public cases are optional productization assets and are not default deliverables. A releasable version will be generated only if the following conditions are met at the same time:

- Customer contracts, confidentiality, branding and data licensing allow;
- Customer identities, people, systems, fields, data and security details have been de-identified;
- metric definition, observation window and attribution restrictions can be made public;
- Failures, boundaries and unproven items are not deleted from the promotional copy;
- Final release review has been completed by the customer or internal authority.

When there is no authorization, only internal cases or fully synthesized teaching cases will be output and clearly identified.

## Spread assets

Derived from the same source of evidence:

- 30 seconds one-sentence introduction: problem, constraints, results;
- 3 minutes Demo: a normal scenarios and a blocking scenarios;
- 8-minute case: key decisions, failures, evidence and boundaries;
- Architecture diagram: system, data, trust, artificial nodes and operation evidence;
- Portfolio summary: problem, constraints, what was done, how to deploy, adoption metrics;
- Social media essays: Only use approved numbers and synthetic/de-identified footage.

## Prohibited practices

- Write synthesis, mock, offline or featured demos into production results;
- Deletion failures and level of manual support;
- Describe relevant changes as determining cause and effect;
- Exposing customer identities, internal systems, security controls or re-identifiable combinations;
- Use absolute expressions such as “zero illusion”, “completely safe” and “fully automatic” that cannot be proven;
- Use of logos, names, screenshots or quotes without authorization from the client's brand.

The value of public cases is to demonstrate FDE judgment, delivery evidence and reusable assets, rather than packaging customers into advertising creatives.

# 检索式怎么写

`patent_search` 支持 `AND` / `OR` / `NOT` 和括号分组。下面是几条能明显提升召回质量的做法。

## 一、拆成三个面，先取两个

技术主题通常能拆成三部分：**解决什么对象**、**用什么手段**、**达成什么效果**。

三个面全用 `AND` 串起来，往往一条都搜不到——专利文献不会按你的思路组织语言。**先取其中两个跑一轮**，看结果量再决定加不加第三个。

```
(固态电池 OR 全固态电池) AND (硫化物 OR 氧化物 OR 聚合物) AND 电解质
```

这条已经是三面齐全的版本。如果零结果，先砍掉最具体的那一面。

## 二、同义词必须扩

中文专利文献里同一个东西常有好几种叫法，还要考虑英文对应词——在华申请的外国专利译名并不统一，同一个技术可能有三四种译法散落在不同案子里。

```
(无人机 OR 无人飞行器 OR UAV OR "unmanned aerial vehicle")
```

扩词的几个方向：

- **上位词**：锂电池 → 二次电池 → 储能器件
- **下位词**：电解质 → 固态电解质 → 硫化物固态电解质
- **俗称与学名**：光伏板 / 太阳能电池组件
- **英文与缩写**：SEP、PCT、OLED
- **旧称**：很多技术在早期专利里用的是现在没人用的叫法

## 三、按结果量调整

| 结果量 | 说明 | 怎么办 |
| --- | --- | --- |
| 几千条以上 | 检索式太宽 | 加 IPC 分类号限定，或限定申请日范围 |
| 几十到几百 | 比较理想 | 直接看 |
| 不足十条 | **先怀疑同义词没扩够** | 换词再跑，别急着下「没有相关专利」的结论 |
| 零条 | 多半是 `AND` 串太多 | 砍掉最具体的那一面 |

零结果不等于这个技术没人做过。绝大多数零结果是检索式的问题，不是事实。

## 四、`NOT` 慎用

排除词会连带把交叉领域的专利一起排掉。比如查电池想排除「汽车」，结果把车用动力电池的核心专利全排没了。

**宁可多看一些噪声，也别漏掉真正相关的文献。** 做现有技术检索时尤其如此——漏掉一篇的代价，远大于多翻十条不相关结果。

## 五、按著录字段查

已知申请人、发明人、公开号、IPC 分类时，直接用字段检索，不要把这些信息拆成语义片段去做模糊匹配——那样只会引入大量噪声。

反过来，只有一段技术方案描述、没有任何结构化线索时，才走关键词与语义扩展的路子。

## 六、IPC 分类号

不熟悉分类号时，先用关键词跑一轮，看返回结果里高频出现哪几个 IPC，再用那几个分类号收窄。这比查分类表快得多，也更贴合实际的分类习惯。

分类号可以只取到大组（如 `H01M10/052`），也可以放宽到小类（如 `H01M`）看整体分布。

写法（2026-10 实测，同一个分类三种写法命中数完全一样）：

| 写法 | 结果 |
| --- | --- |
| `ipc:H01M10/0525` | ✅ |
| `ipc:"H01M 10/0525"`（分类号里带空格时，引号只包值） | ✅ |
| `ipc:H01M10/0525*`、`ipc:H01M*`（前缀通配） | ✅ |
| `"ipc:H01M 10/0525"`（引号把字段名也包进去） | ❌ 0 条——这是写错了，不是没有专利 |

`search` 输出里的 `page_profile.ipc_group` 是本页结果的分类分布（到大组，如 `H01M10`），
第一式跑完从这里挑跟强相关篇对得上的分类，比查分类表快。

## 七、可用字段速查（和 PatentMax 连接器同一套，逐个实测过）

字段名**区分大小写**，多个条件用 `AND` 连接。

| 类别 | 写法 |
| --- | --- |
| 文本 | 标题 `t:区块链`（或 `title:`）；摘要 `summary:`；权利要求 `claims:`；说明书 `description:`；标题或摘要 `ta:(固态电解质)`；标题+摘要+权利要求 `tac:`；全文 `tacd:` |
| 号码 | 公开号 `documentNumber:CN109761224A`；申请号 `applicationNumber:CN202111491053.4`（都可用前缀，如 `CN2021114*`）；优先权号 `priorityNumber:JP20210005949`（可用 `JP2021*`） |
| 日期 | 公开日 `documentDate:[2026-09-01 TO 2026-09-30]`；申请日 `applicationDate:[2025-01-01 TO 2025-12-31]`；按年 `documentYear:[2025 TO 2026]` / `applicationYear:[2023 TO 2025]`。中国发明授权文本的公开日就是授权公告日 |
| 分类 | IPC `ipc:B60W*`（主分类 `mainIpc:`）；CPC `cpc:Y02E60*`；外观设计 LOC `loc:"14-03"` 或 `loc:14*` |
| 主体 | 申请人 `applicant:"华为技术有限公司"`（第一申请人 `firstApplicant:`）；当前专利权人 `currentAssignee:`（转让后的权利人看这个）；发明人 `inventor:"张三"`（第一发明人 `firstInventor:`）；代理机构 `agency:"……知识产权代理有限公司"`（填全称）；代理人 `agent:"姓名"` |
| 地域 | 国别 `countryCode:US`（CN/US/EP/JP/KR/WO 等）；中国申请人所在省 `province:广东省`（必须带「省」「市」，写「广东」查不到）；市要两种写法一起查 `(city:"广东省深圳市" OR city:深圳市)`，只写「深圳市」会漏掉约八成；申请人地址 `applicantAddress:深圳` |
| 状态与类型 | 法律状态 `legalStatus:` 有效专利 / 失效专利 / 无效专利 / 公开 / 实质审查；当前状态 `currentStatus:` 授权 / 实质审查 / 公开 / 驳回 / 撤回 / 放弃 / 权利终止；专利类型 `type:` 发明公开 / 发明授权 / 实用新型 / 外观设计（美国和 WO 的申请是「发明申请」，日本是「发明专利」） |

## 八、做不到的（别反复换写法试）

- **没有的字段**：审查员、优先权日、单独的授权日、同族。写了不存在的字段会直接返回错误提示（不扣费），不要当成「没有结果」
- **外国专利要用原文关键词**：用中文检索外国专利只能查到约一成，查美欧日韩要用英文（或日文、韩文）
- **英文不会自动扩展单复数和时态**：写 `batter*` 或 `(battery OR batteries)`
- **不支持近邻 / 位置算符**（W/n、NEAR、$W 等）：改用短语（双引号）或 `AND`
- 日期范围两端都要写具体值，不支持 `*`（要「至今」写 `[2026-01-01 TO 2099-12-31]`）；检索式最长 4000 字
- `*` 是前缀通配（`batter*`），`?` 匹配一个字符（`wom?n`）

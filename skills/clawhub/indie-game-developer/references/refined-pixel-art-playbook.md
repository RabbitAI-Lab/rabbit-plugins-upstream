# 精致手绘像素角色 Playbook

> 用明确的网格、色板、色簇和参考图职责替代“再像素一点”的模糊反馈。

## 1. 先判断任务类型

```text
是否只要一个人物？
├─ 是
│  ├─ 用作小图标 → 16×16 或 24×32，优先剪影
│  ├─ 用作精致 icon → 28×36，允许材质分区与单像素高光
│  └─ 用作游戏 sprite → 24×32 / 32×32，并预留动画一致性
└─ 否
   ├─ 人物是宣传图主体 → 角色与背景分别定义像素密度
   └─ 人物只是场景小人 → 人物高度不超过画面 20%–30%
```

只有当目标是“精致角色 icon / 立绘式 sprite”时，默认使用约 `28×36` 的人物逻辑网格。

## 2. 密度分级矩阵

| 档位 | 人物网格 | 色数 | 允许细节 | 典型用途 |
|------|----------|------|----------|----------|
| 超粗 | 16×16 | 4–6 | 单眼像素、整块衣服、武器轮廓 | 状态图标、极小单位 |
| 标准 | 24×32 | 8–12 | 发型、靴子、箭袋、两级明暗 | 游戏 sprite、头像 |
| 精致 | 28×36 | 12–16 | 材质分区、单像素高光、姿势关节 | 正方形 icon、角色展示 |
| 高密 | 32×48+ | 16–24 | 更多面部和服装结构 | 对话立绘；容易滑向伪像素 |

判断原则：如果缩小到目标显示尺寸后弓、头、手和脚粘成一团，先改剪影，不要增加像素。

## 3. 参考图职责矩阵

给每张输入图只分配一种主要职责：

| 角色 | 可以继承 | 不应继承 |
|------|----------|----------|
| 风格参考 | 网格密度、色簇大小、轮廓、色板关系 | 角色身份、服装、姿势、Logo |
| 角色参考 | 性别表达、配色、发型、装备、动作 | 参考图画风之外的背景与构图 |
| 编辑目标 | 需要保持的像素与结构 | 未明确授权的整体重绘 |

提示词必须显式写：`Reference image 1 is a pixel-density and craftsmanship reference only`。只写“参考这张图”会诱导模型复制人物或混合所有视觉属性。

## 4. 像素结构规则

### 4.1 轮廓

- 主轮廓使用 1 个逻辑像素宽的近黑色，不随输出分辨率改变。
- 斜线必须呈阶梯状；避免半透明、平滑斜边和细于逻辑像素的线。
- 武器、手臂与躯干之间保留负空间，拉弓姿势尤其要区分弓手、拉弦手、箭和弦。

### 4.2 色簇

- 阴影与高光组成连续簇，不撒随机单像素噪点。
- 每种材质通常只用基色、阴影、高光三档；小图标可降为两档。
- 单像素高光只放在视觉焦点，如眼睛、金属箭头、腰带扣或星标。

### 4.3 色板

推荐分配：

```text
轮廓 1–2 色
皮肤 2–3 色
主服装 3 色
皮革/木材 2–3 色
头发 2 色
强调色 1–2 色
```

不要把“12–16 色”误解为必须用满；同一角色中近似但无功能区分的颜色应合并。

## 5. 白底正方形 icon 规格

```text
Canvas: strict 1:1
Background: flat pure #FFFFFF edge to edge
Character: complete full body, centered, 65%–78% canvas height
Margin: 12%–18%, bow/string/quiver must not touch edge
Forbidden: floor, pedestal, cast shadow, reflection, frame, particles, text
```

“白色背景”必须同时排除渐变、柔光、接触阴影和摄影棚地面，否则模型常生成灰白背景。

## 6. 失败模式与纠偏

| 症状 | 原因 | 下一轮只改这一项 |
|------|------|------------------|
| 像高清插画加马赛克 | 没有逻辑网格与色板预算 | 写明 `28x36 logical grid`、hard cells、no antialiasing |
| 人物太粗糙 | 网格低于需求或色数过少 | 16×16 → 24×32 / 28×36，不改角色设计 |
| 人物太高清 | 允许材质纹理、面部细节过多 | 限制每材质 2–3 色，禁止毛发/布纹细节 |
| 弓箭不可读 | 手臂、弓、弦重叠 | 要求负空间和四个部件分别可辨 |
| 人物被放成半身 | 未强调完整边界 | 重复 `full body, boots and complete bow visible` |
| 背景不是纯白 | 只写 white background | 写 `flat pure #FFFFFF edge to edge` 并逐项禁止阴影/地面 |
| 复制参考角色 | 参考职责不清 | 列允许继承项与禁止复制项 |
| 每轮变化太大 | 同时改密度、姿势、配色和构图 | 锁定不变量，每轮只调整一个变量 |

## 7. 提示词组装顺序

1. `Use case` 与资产用途
2. 每张参考图的角色
3. 输出角色与必须保留的不变量
4. 逻辑网格、色数与轮廓规则
5. 构图、边距和背景
6. 允许的精致细节
7. 完整负向约束
8. 稳定文件名意图

直接套用 [assets/refined-pixel-character-prompt.md](../assets/refined-pixel-character-prompt.md)，删除不适用字段，不要继续堆形容词。

## 8. 交付检查清单

- [ ] 输出为严格正方形，人物和武器完整在画布内
- [ ] 逻辑像素大小一致，没有局部变细或抗锯齿
- [ ] 轮廓在目标显示尺寸下仍可读
- [ ] 色数与明暗层级符合所选密度档位
- [ ] 色簇连续，没有随机噪点和伪纹理
- [ ] 头、手、脚、弓、弦、箭、箭袋可分别辨认
- [ ] 白底为纯 `#FFFFFF`，无地面、阴影、渐变或反射
- [ ] 没有复制参考图的角色、服装、Logo 或网格线
- [ ] 文件名包含角色、动作和密度/版本信息
- [ ] 保留上一版本，便于对比与回退

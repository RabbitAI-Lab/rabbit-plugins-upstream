# 田永龙 · 对本套件的裁决

> 依据：MIT CSAIL 主页 + GitHub HobbitLong（SupContrast/RepDistiller README 全文）+ 论文元数据。
> 蒸馏报告（6 心智模型 + 8 启发式 + 证据）：corpus/org-sweep/drafts/person-tianyonglong.md
> 这里不复述他的通用哲学——只说他会对 penguin-oss-suite 的每个具体决策说什么。

## 裁决 1：梳理报告（S1 梳理 AI 仓）

**他会说：「A 仓 CI 比 B 仓严格」——和谁比、同条件下比、控制变量了吗？**

- S1 报告的方法对比必须放进同一装置：统一维度表（CI 触发条件 / review 轮次 / 发布节奏逐仓同列）
- 不能同列比较的维度不下判断；各仓各自调参后比大小不予采信
- 先造公平的战场再开打：先建统一基准，再提「三标杆仓」的结论
- 依据：Benchmark-first（RepDistiller 把 12 个蒸馏方法放进同一 harness 才下判断）

## 裁决 2：语料时效（套件规则层）

**他会说：蒸馏规则自带保质期——把 "for Now" 写进规则里。**

- 蒸馏自 2026-09 语料的规则，上游仓在演进：每条规则标注抓取时间 + 失效条件（上游大改版时哪些规则失效）
- 结论措辞精确到不夸大一档：Rivals 不写 Beats——「三标杆仓风格」没逐仓验证前降一档写
- 主动给自己的路线写失败模式分析：合成语料会退化，蒸馏规则同样会——标注退化信号
- 依据：数据的可替代性（"…for Now" 写进标题；Self-Correcting Loops 修自己押注路线的坑）

## 裁决 3：corpus 治理（语料资产）

**他会说：corpus 是结论的另一半——纠错划线保留，别悄悄改。**

- skill 规则改错时不悄悄覆盖：旧规则划线保留 + 更正说明（SupContrast README 的删除线 + WARN 模式）
- 致谢具体到人和仓：每条蒸馏规则回链来源仓库与作者，信用记账到人
- 交付物 = 规则 + 能查的语料 + 诚实的修订记录，三者缺一即视为未完成
- 依据：Repo 是论文的另一半——可复现性是责任不是附加项，仓库维护多年仍在自我修正

## 裁决 4：corpus 目录形态（语料资产）

**他会说：混元仓的形态就是答案——结论和原始工件同库可溯。**

- 混元 org 仓的标准形态：repo description 即论文标题（"HunyuanOCR-1.5: Making Lightweight OCR VLMs Faster and Better"、"OmniWeaving: Towards Unified Video Generation..."），README 挂论文/权重/官网三链，发布后持续更新（HunyuanOCR 2026-09-24 仍有 push、2.0k★；Hunyuan3D-2 15k★）——论文是论点，repo 是可验证的另一半（来源：GitHub org 仓库清单，2026-09-29 抓取）
- 诚实标注：org 级证据、非个人 commit——他 2026.9 才入职，公开仓无以他署名的提交记录；该形态是「repo 是论文的另一半」在工业侧的延续，也是他接手产线后方法论的下一段验证场
- 对套件 corpus/ 的启示：语料条目学混元仓「描述=原文标题+回链」——每份 corpus 文件头部写清来源 URL + 抓取日期 + 支撑哪条规则；蒸馏规则与原始语料同库可溯，规则脱离语料不可验证即视为未交付（与裁决 3 的修订留痕同根）

## 反裁决（他不会说的）

- 不说「各仓各自调参后比大小」——反不可比比较，放不进同一装置的结论不采信
- 不说「删掉旧版本保持干净」——反「发完就弃」，纠错痕迹是资产
- 不说「结论可以说满一点」——结论强度精确匹配证据强度，一档都不多

## 使用方式

被 oss-workflow S1 checklist 决策 Gate 或 oss-perspective-council 调用时：
1. 读对应裁决条目（梳理对比→裁决 1；规则时效→裁决 2；corpus 修订→裁决 3；corpus 目录形态→裁决 4）
2. 拿当前产物（梳理报告 / 蒸馏规则 / corpus 修订记录）逐条对照
3. 输出：符合 / 违反 / 不适用 + 引用哪条裁决

## 诚实边界

- 表达类语料结构性薄弱：无演讲、无长访谈、无博客——全部从 README/论文标题/代码行为反推，样本量小于访谈型人物卡
- 工业期零语料：2026.9 腾讯任命后无公开技术决策，涉及管理/产品决策的推断超出证据边界
- 模型全部来自视觉表征研究语境，套用到 skill 工程/开源协作是蒸馏者推导
- 他从未评价过本套件——所有裁决是模型推导

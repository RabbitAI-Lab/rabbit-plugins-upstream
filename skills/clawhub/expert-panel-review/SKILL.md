# 专家会诊团

## 先说清楚：这不模拟团队

有一种做法是把 AI 分成"产品经理 + 架构师 + 开发 + 测试"，再给它们排流程、
定接口、设协调员。**别这么做**——分工、协调、管理都是补偿人类局限的机制
（脑容量有限才分工，沟通有损耗才协调），AI 没有这些局限，模拟它们只会
把一次能跑完的事拆成一堆模板填空。

**但视角并置是有用的**，理由完全不同：

> 同一个方案，站在增长立场和站在品牌立场，看到的风险是**系统性不同**的。
> 不是谁对谁错，是**盲区不同**。会诊的价值就是把这些盲区摆到同一张桌子上。

所以本 skill 只做两件事：**让不同立场各自把话说完**，然后**把分歧原样摆出来**。

---

## 一、开不开会诊

| 情况 | 判断 |
|---|---|
| 拍板前，想确认没漏掉大坑 | **开** |
| 方案已经改了几轮，越改越没底 | **开**（多半是单一视角打转） |
| 有人坚决反对但说不清为什么 | **开**（把分歧显性化） |
| 只是想找人复核有没有错别字/低级错误 | 不开，直接查 |
| 需要的是事实、数据、法规条文 | 不开，去查证，会诊只会产生幻觉 |
| 有标准答案的问题 | 不开 |
| 决策后果不可撤销且需资质（裁员、诉讼、审计） | 可以开，但结论必须交给持牌的人签字 |

---

## 二、四步

### 第 1 步：按"谁会反对谁"选视角，不按"需要什么专业"选

这是全篇最关键的一条。

```
✗ 选分工：产品经理 + 设计师 + 前端 + 测试
   → 结果是四个人的活，不是四个角度。它们会各自讲自己那段，合起来还是一份方案。

✓ 选对立：增长负责人 + 品牌负责人 + 财务负责人
   → 增长说"这个活动能拉量"，品牌说"用这个语气蹭热点等于拿十年人设换三天流量"，
     财务说"扣掉平台费和广告费每单亏 5 个点"。这才是会诊。
```

**判据**：如果两个视角对同一件事不会做出**不同的取舍**，就合并掉，换个新的。

常用对立组合（可直接用，也可按议题自造）：

| 议题类型 | 建议的视角组合 |
|---|---|
| 营销/增长方案 | 增长 vs 品牌 vs 财务（单位经济模型） |
| 产品方案 | 用户体验 vs 交付速度 vs 长期可维护性 |
| 技术选型 | 架构前瞻 vs 团队真实能力 vs 运维负担 |
| 内容/文案 | 传播效率 vs 品牌调性 vs 合规风险 |
| 上新/定价 | 市场占有 vs 毛利 vs 老用户感受 |
| 流程改造 | 效率 vs 风险控制 vs 一线执行成本 |

**数量**：3 个起步，最多 5 个。超过 5 个，结论必然开始和稀泥。

### 第 2 步：让每个视角独立发声（不许互相引用）

关键纪律：**视角之间不许互相看到对方的发言**，直到汇总阶段。

否则第一个发言的会锚定后面所有视角，你会得到"一个人说了五遍"。

每个视角必须输出三件事：
1. **我支持什么**（一句话）
2. **我最担心什么**（具体到能指出是哪一段、哪个数字）
3. **如果我是你，我会先改哪一条**（只能一条）

### 第 3 步：汇总，四段结论

见下方输出模板。核心是**分歧段必须原样保留**。

### 第 4 步：明确"这个分歧该谁拍板"

分歧不是要会诊来消除的——是要**标清楚该由谁、依据什么来定**。
写到"需要谁来拍板 / 需要补什么数据才能定"为止。

---

## 三、关键规则

- **视角 ≥ 3，且必须立场冲突。** 不冲突的合并或替换。
- **独立发声，互不引用。** 防止锚定。
- **分歧不许和稀泥。** 出现"综合来看各有道理"视为失败。
- **每个视角只给一条"先改什么"。** 给三条等于没给。
- **允许全体一致。** 如果所有视角都指向同一个问题，直接给结论，别硬凑分歧。
- **不模拟协作流程。** 不写会议纪要、不投票、不排责任矩阵、不画流程图。
- **不许为了显得全面而编造风险。** 没有风险就说没有，比编三条假风险有用。

---

## 四、输出模板

```
# 会诊结论：[议题一句话]

## 参与视角
| 视角 | 它的核心关切 | 它最可能反对什么 |
|---|---|---|
| 增长负责人 | 边际获客成本 | 为了品牌调性牺牲可归因的转化 |
| 品牌负责人 | 十年一致性 | 拿品牌人设换短期流量 |
| 财务负责人 | 单位经济模型 | 只报 GMV 不报扣费后的毛利 |

## 一、共识（所有视角都认同）
- …

## 二、分歧（★最关键，不许和稀泥）
| 分歧点 | 视角 A 主张 | 视角 B 主张 | 分歧的真正根源 | 该谁拍板 / 需补什么数据 |
|---|---|---|---|---|
| … | … | … | 是事实分歧还是价值观分歧 | … |

## 三、只有单一视角才看得见的盲区
- [增长视角]：…
- [合规视角]：…
- [一线执行视角]：…

## 四、如果只能改一条
| 视角 | 先改哪一条 | 理由 |
|---|---|---|
| … | … | … |

## 五、给你的一句话
[不带"综合来看"的一句实话，指出真正的卡点在哪]
```

## 五、反模式表

| # | 反模式 | 症状 | 怎么改 |
|---|---|---|---|
| 1 | 视角是分工不是立场 | "产品+设计+开发+测试" | 换成互相会反对的立场 |
| 2 | 和稀泥 | "综合来看各有道理，建议结合实际情况" | 写出分歧根源与拍板人 |
| 3 | 五个人说同一件事 | 三段结论高度雷同 | 视角选错了，重选 |
| 4 | 只夸不批 | 全是"亮点突出，建议优化细节" | 每个视角必须指出一项具体风险 |
| 5 | 模拟开会 | 有主持、有议程、有投票 | 删掉，只保留各视角的独立结论 |
| 6 | 编造风险凑数 | "可能存在合规隐患"（但说不出哪条） | 说不出就不写 |
| 7 | 视角超过 5 个 | 结论变得四平八稳 | 砍到 3–5 个 |

## 六、什么时候别用我

- 需要的是事实、数据、最新法规条文——会诊会产生听起来合理但无来源的判断
- 已有明确标准答案——直接给答案更快
- 决策需要真人资质背书（医疗诊断、法律意见、审计结论）——我可以列视角，签字必须由持牌人做
- 任务本身很小（改个标题、调个参数）——开三个视角是浪费
- 你其实已经知道答案，只是想找人背书——我不会配合，我会把反对意见也写出来

---

## 七、边界

- 会诊产出的是**视角与分歧**，不是事实。涉及数字的部分必须标注"需核实"。
- 不替用户做最终决策，只把"该谁拍板、依据什么"标清楚。
- 视角名可以借用真实职能（如"首席营销官""合规官"），但它们是**立场标签**，
  不代表真的具备该职能的专业资质。

# 整体分析框架

## 概览
当用户提供多个 Excel 文件或单个 Excel 文件包含多个 sheet 时，智能体需要建立整体分析框架，确保数据全面性和一致性。

## 分析框架结构

### 第一层：数据收集与分类

#### 1.1 数据源识别
- **单文件多 Sheet**：识别每个 sheet 的数据类型
  - 测试用例数据
  - 缺陷数据
  - 工作总结数据
  - PDCA 项目数据
  - 临时工作数据
  - 风险列表
  - 下月计划

- **多文件**：识别每个文件的数据类型和月份
  - 按月份分类
  - 按数据类型分类
  - 检查数据重复性

#### 1.2 数据质量检查
- **完整性检查**：
  - 必填字段是否齐全
  - 数值是否合理
  - 日期格式是否一致

- **一致性检查**：
  - 不同 sheet 之间的数据是否匹配
  - 总数与明细是否一致
  - 历史数据是否连续

### 第二层：数据整合与关联

#### 2.1 按月份整合
```
月份 A：
  - 测试用例数据（来自 sheet1 或 文件A）
  - 缺陷数据（来自 sheet2 或 文件B）
  - 工作总结（来自 sheet3 或 文件C）
  - PDCA 项目（来自 sheet4 或 文件D）

月份 B：
  - （同上）
```

#### 2.2 数据关联分析
- **测试用例与缺陷关联**：
  - 计算缺陷密度
  - 分析缺陷分布

- **工作与指标关联**：
  - 工作量与测试用例数的关系
  - PDCA 项目与质量指标的关联

- **历史数据关联**：
  - 多月数据趋势分析
  - 对比基准确定

### 第三层：分析维度构建

#### 3.1 时间维度
- 月度对比（本月 vs 上月）
- 季度趋势（3个月）
- 年度累计（12个月）

#### 3.2 内容维度
- **测试执行维度**：
  - 用例执行效率
  - 通过率变化
  - 覆盖率分析

- **质量维度**：
  - 缺陷趋势
  - 缺陷分布
  - 缺陷修复周期

- **工作维度**：
  - 工作完成率
  - PDCA 执行效果
  - 临时工作占比

- **风险维度**：
  - 风险类型分布
  - 风险级别趋势
  - 风险解决情况

#### 3.3 深度分析维度
- **根因分析**：
  - 缺陷根因分布
  - 失败用例根因

- **效能分析**：
  - 团队测试效率
  - 缺陷发现效率
  - 资源利用率

- **改进分析**：
  - PDCA 项目效果评估
  - 改进措施落地情况
  - 持续改进建议

### 第四层：报告结构设计

#### 4.1 标准报告结构
```
1. 执行摘要
   - 关键指标概览
   - 核心发现
   - 风险提示

2. 数据来源说明
   - 数据文件清单
   - Sheet 映射关系
   - 数据覆盖范围

3. 月度总览
   - 测试执行情况
   - 缺陷统计
   - 关键指标

4. 深度分析
   - 按时间维度分析
   - 按内容维度分析
   - 按深度维度分析

5. 对比与趋势
   - 历史对比
   - 趋势图表
   - 数据洞察

6. PDCA 总结
   - 项目概览
   - 效果评估
   - 改进建议

7. 风险与问题
   - 风险清单
   - 问题跟踪

8. 下月计划
   - 工作安排
   - 改进计划
```

#### 4.2 灵活报告结构
根据数据类型和用户需求调整：
- **数据丰富时**：增加深度分析章节
- **数据不足时**：简化分析，重点展示已知数据
- **用户关注某方面**：增加相关章节的深度

## 智能体执行流程

### 步骤 1：数据解析
1. 调用 `scripts/parse_excel.py` 解析所有 Excel 文件
2. 识别每个 sheet 的数据类型
3. 检查数据完整性和一致性

### 步骤 2：数据整合
1. 按月份整合数据
2. 建立数据关联关系
3. 识别数据缺口

### 步骤 3：分析规划
1. 确定分析维度（时间/内容/深度）
2. 识别关键分析点
3. 规划图表类型

### 步骤 4：大纲生成
1. 基于分析框架生成报告大纲
2. 标注数据来源
3. 识别需要用户补充的内容

### 步骤 5：报告生成
1. 按大纲生成各章节内容
2. 调用脚本计算指标
3. 生成图表
4. 转换为 HTML

## 示例场景

### 场景 1：单文件多 Sheet
```
用户上传：monthly_data.xlsx（包含 5 个 sheet）
解析结果：
  - sheet1: 测试用例数据
  - sheet2: 缺陷数据
  - sheet3: 工作总结
  - sheet4: PDCA 项目
  - sheet5: 风险列表

分析流程：
  1. 整合 5 个 sheet 的数据
  2. 建立关联（测试用例 ↔ 缺陷）
  3. 生成综合月报
```

### 场景 2：多文件
```
用户上传：
  - 2024-01.xlsx
  - 2024-02.xlsx
  - 2024-03.xlsx

分析流程：
  1. 按月份分类数据
  2. 建立时间序列
  3. 生成趋势分析
  4. 对比 3 个月的数据
```

### 场景 3：混合数据源
```
用户上传：
  - monthly_data.xlsx（包含测试用例和缺陷数据）
  - work_summary.json（工作总结）
  - pdca_items.json（PDCA 项目）

分析流程：
  1. 统一数据格式
  2. 整合多源数据
  3. 生成综合报告
```

## 数据缺口处理

### 识别数据缺口
- 某些 sheet 缺失
- 某些字段为空
- 历史数据不连续

### 处理策略
1. **智能补全**：基于已有数据推断
2. **用户确认**：询问用户是否需要补充
3. **标注说明**：在报告中标注数据来源和缺口
4. **灵活调整**：根据可用数据调整报告结构

## 质量保障

### 数据验证
- 数值合理性检查
- 逻辑一致性检查
- 格式规范性检查

### 分析验证
- 计算结果验证
- 趋势逻辑验证
- 对比基准验证

### 报告验证
- 章节完整性检查
- 图表准确性检查
- 文字表述一致性检查

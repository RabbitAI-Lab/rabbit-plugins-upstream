## 重要说明

1. **标黄为状态**：推送该状态后该状态不会在继续推送内容
2. **付费用户以此状态为准**：不使用 state

---

## State（主状态码）与图标

主状态码（State）及其在订阅列表中显示的图标：

| 状态码 | 状态名称 | 图标 | 说明 |
|:------:|---------|:----:|-------------|
| **0** | 暂无轨迹信息 | ❓ | 货物暂无轨迹信息 |
| **1** | 已揽收 | 🚚 | 快递员已上门揽收快递 |
| **2** | 在途中 | 🚚 | 货物在途中运输 |
| **3** | 已签收 | ✓ | 快件被签收 |
| **4** | 问题件 | ⚠️ | 货物运输途中存在异常 |
| **5** | 转寄 | 🚚 | 快递被转寄到新地址 |

**图标使用场景：**
- ❓ 查无信息（State = 0）
- 🚚 运输中/已揽收/派件中/转寄（State = 1, 2, 5）
- ✓ 已签收（State = 3）
- ⚠️ 问题件（State = 4）

## 通知触发逻辑（重要）⭐

### 触发飞书通知的状态

根据官方文档，**标黄状态**为最终状态，推送后不会再次推送：

**✅ 应该触发通知：**
- **301** - 正常签收（本人）
- **302** - 异常后最终签收
- **304** - 代收签收
- **311** - 快递柜或驿站签收 ⭐最常用
- **3** - 已签收
- **406** - 退货签收
- **415** - 客户取消发货

**❌ 不触发通知：**
- 0, 1, 2, 4, 5, 6 等中间状态
- 已通知过的状态（避免重复）

## 代码中的使用

### 状态判断逻辑

```python
# 判断是否已签收（触发通知）
if state_ex in ['301', '302', '304', '311', '3']:
    # 已签收，发送取件通知
    send_notification()

# 判断是否放入代收点
if state_ex == '211':
    # 已放入快递柜/驿站，但还未签收
    update_latest_trace()

# 判断是否问题件
if state_ex.startswith('4') or state_ex == '4':
    # 问题件，可能需要通知用户
    handle_exception()
```

# ARI Amazon 评论智能助手使用指南

ARI Amazon 评论智能助手可以帮助卖家采集和分析 Amazon 评论，快速发现消费者痛点、购买动机、使用场景、竞品差异与 Listing 优化机会。

你可以直接用中文提出需求，不需要理解 API，也不需要编写代码。系统会在付费操作前展示所需积点，只有得到你的明确确认后才会执行。

## 一、直接告诉 AI 你要做什么

在已安装本 Skill 的 AI 客户端中直接输入：

```text
使用 $amazon-product-differentiation 分析 ASIN B0XXXXXXXX，站点 amz_us，先告诉我需要多少积点，不要直接扣点。
```

也可以这样说：

```text
使用 $amazon-product-differentiation 采集 B0XXXXXXXX 的 3 页美国站评论，先报价，等我确认后再执行。
```

```text
使用 $amazon-product-differentiation 对比 B0AAAAAAAA 和 B0BBBBBBBB，找出竞品差评、购买动机和 Listing 改进机会。
```

```text
使用 $amazon-product-differentiation 看看我有没有差评预警，帮我列出待处理差评并给最严重的一条写回复建议。
```

```text
使用 $amazon-product-differentiation 对 B0XXXXXXXX 做类目对标，看它在行业里的星级和差评率位置。
```

```text
使用 $amazon-product-differentiation 导出 B0XXXXXXXX 的全部评论为 CSV。
```

付费采集或 AI 分析都会先报价，只有你明确确认后才会扣除 ARI 积点。

## 二、第一次使用：申请并配置 API Key

**推荐方式（一键授权，无需复制粘贴）**：在 Skill 目录打开终端运行

```bash
python scripts/ari.py setup
```

命令会打印一个授权链接。用浏览器打开它，登录（没有账号就先注册并完成邮箱验证），
点一下「授权」，回到终端等几秒——Key 自动获取并保存，完成。

**手动方式**（授权链接打不开时备用）：

1. 登录 [ARI 用户中心](https://ari.funewa.com/zh/account?ui=d47626f#api-keys)。
2. 完成邮箱验证。
3. 在“API Key”区域创建密钥，并立即复制以 `ari_live_` 开头的完整 Key。
4. 如客户端要求手动配置，请在 Skill 目录打开终端并运行：

```bash
python scripts/ari.py configure
```

5. 按提示粘贴 API Key。输入过程不会显示字符，这是正常的。
6. 验证账户和余额：

```bash
python scripts/ari.py check
```

Key 只保存在你的本机用户配置中。请勿把 Key 发给他人、写进截图或放进公开文档。

## 三、命令行完整流程

### 1. 一键生成 VOC 报告（推荐）

```bash
python scripts/ari.py voc B0XXXXXXXX --site amz_us
```

该命令一次返回采集 + VOC 的总报价，不扣积点。确认后运行：

```bash
python scripts/ari.py voc B0XXXXXXXX --site amz_us --confirm
```

它会自动完成：检查现有评论 → 必要时采集并等待 → 生成 VOC →
保存到用户中心 → 返回完整报告正文、`reportId` 和 `reportUrl`。
默认采集 3 页，可用 `--pages 1..10` 调整。

### 2. 单独采集或查看免费数据（高级）

只需采集时：

```bash
python scripts/ari.py collect --asin B0XXXXXXXX --site amz_us --pages 3
python scripts/ari.py collect --asin B0XXXXXXXX --site amz_us --pages 3 --confirm --wait
```

查看免费数据：

```bash
python scripts/ari.py reviews --asin B0XXXXXXXX --site amz_us
python scripts/ari.py charts --asin B0XXXXXXXX --site amz_us
```

`charts` 会一次返回星级、趋势、关键词和评论流向数据。默认 `--days 0`（全部历史）；
传 `--days 90` 则所有图表都只统计最近 90 天，看数时请注意这个窗口。

**高赞差评榜**（免费，最该先看的那几条）——买家在商品页最先看到的就是点赞最多的差评：

```bash
python scripts/ari.py reviews --asin B0XXXXXXXX --stars negative --sort helpful
python scripts/ari.py reviews --asin B0XXXXXXXX --stars negative --sort helpful --with-images
```

### 2.5 开启定期监控（**这一步决定了 ARI 对你有多大用**）

不开监控，你的数据就停在最后一次采集那天——趋势图不会往前走，报告也没有环比可比。
开启后新评论持续进库，采得越久，趋势判断和差评归因越准。

```bash
python scripts/ari.py schedule                                    # 看看哪些产品还没在监控
python scripts/ari.py schedule --set weekly --asin B0XXXXXXXX     # 设为每周自动采集
python scripts/ari.py schedule --set manual --asin B0XXXXXXXX     # 随时改回手动，不再产生费用
```

设置本身免费，采集按实际页数扣点。返回里的 `_costNote` 会给出该频率的预估月成本。
`weekly` 是长期跟踪的默认选择；`daily` 适合大促期或刚上新的款（部分套餐不开放每日）。

开着监控一段时间后，同一个产品再生成报告，`report --id` 会多出一段环比：
「相比上一份：哪些问题解决了、哪些是新冒出来的、哪些还在恶化」。

### 3. 其他分析类型（高级）

```bash
python scripts/ari.py deepdive --asin B0XXXXXXXX --site amz_us
```

确认后生成分析：

```bash
python scripts/ari.py deepdive --asin B0XXXXXXXX --site amz_us --confirm
```

支持的分析类型：

- `voc`：消费者之声综合报告
- `insight`：痛点、购买动机、画像和场景
- `trend`：评论与情绪趋势
- `variant`：颜色、尺寸等变体分析
- `compare`：目标产品和竞品对比

竞品对比同样是先报价、后确认。先看价：

```bash
python scripts/ari.py analyze --type compare --asin B0AAAAAAAA --competitor B0BBBBBBBB --site amz_us
```

确认价格后再加 `--confirm`：

```bash
python scripts/ari.py analyze --type compare --asin B0AAAAAAAA --competitor B0BBBBBBBB --site amz_us --confirm
```

两个 ASIN 都需要先完成评论采集，各自至少 10 条评论。

### 4. 商品运营体检与行动报告

先确认账户是否开放运营能力，再检查商品资料：

```bash
python scripts/ari.py operations capabilities
python scripts/ari.py operations profile --asin B0XXXXXXXX --site amz_us
```

通用母版需显式选择服务端支持的 workflow/focus。先报价，不扣点：

```bash
python scripts/ari.py operations quote --workflow audit --focus full --asin B0XXXXXXXX --site amz_us
```

用户确认后，复用报价返回的 `requestId` 执行：

```bash
python scripts/ari.py operations run --workflow audit --focus full --asin B0XXXXXXXX --site amz_us --request-id <原requestId> --confirm
```

若流中断，不要直接重跑，按原 requestId 免费查询：

```bash
python scripts/ari.py operations status --request-id <原requestId>
```

专属运营 Skill 会在 `skill-defaults.json` 固定 workflow/focus，无需也不得自由改写内部 prompt。
评论不足时仍使用独立的 `collect` 流程；运营命令不会隐式采集。

### 5. 商品变化监控（watch）

`watch` 是独立的确定性商品快照监控，不是付费 AI 分析。`watch create` 只接受账户已订阅
且仍归属账户的主 ASIN；可选 `--competitor` 仅在该竞品已绑定到该主 ASIN、且站点相同时生效。
先查看当前账户是否处于 watch 灰度：

```bash
python scripts/ari.py operations capabilities   # 确认返回 watchEnabled: true
python scripts/ari.py watch list
```

如果 `watchEnabled` 为 `false`，说明功能开关、套餐或灰度尚未开放；请停止，不要改用其他命令
冒充监控，也不要用临时 ASIN 或未绑定竞品绕过归属校验。竞品 watch 必须带 `--competitor`，
且该竞品已绑定到当前用户的主 ASIN、站点相同；Wave E 的 `competitor-change` listing 仍为 planned。

本节记录 1.4.1 的 CLI 契约；对应 Wave E 候选仍为 `planned`，尚未公开上架，不代表所有账户当前可用。

创建和管理监控：

```bash
python scripts/ari.py watch create --asin B0XXXXXXXX --site amz_us --schedule weekly
python scripts/ari.py watch create --asin B0XXXXXXXX --competitor B0YYYYYYYY --site amz_us --schedule weekly
python scripts/ari.py watch pause --watch-id <watchId>
python scripts/ari.py watch resume --watch-id <watchId>
python scripts/ari.py watch delete --watch-id <watchId>
```

周期只支持 `weekly` 和 `daily`。`daily` 受套餐 `dailyProductWatch` 权益限制，Free 不开放
自动日扫描；创建或修改前先向用户说明套餐额度和扫描成本。暂停后不再调度，删除监控关系不会
删除商品资料、评论或历史报告。

读取确定性摘要和事件：

```bash
python scripts/ari.py watch digest --watch-id <watchId> --period 7d
python scripts/ari.py watch events --watch-id <watchId>
```

`digest` 只基于商品快照、确定性 Diff 和已有评论计数，返回 `creditsUsed: 0`；自动扫描和
事件读取不调用付费 LLM、不扣 AI 积点。它不承诺小时级或实时价格、销量、库存、广告、订单或
真实退货率。若需要 AI 解读，仍使用 `operations` 的 `weekly` 工作流，先运行 `operations quote`，
得到用户明确确认后才用同一 `requestId` 执行 `operations run --confirm`，不要把 AI 周报当成
免费的 watch digest。

### 6. 差评预警与差评工作台

订阅 ASIN 后服务端会自动监控差评突增、星级下滑，查看预警（免费）：

```bash
python scripts/ari.py alerts
```

列出待处理差评（免费，返回每条差评的 reviewId）：

```bash
python scripts/ari.py workbench --asin B0XXXXXXXX
```

为某条差评生成 AI 回复/申诉/改进建议（付费，先报价、确认后加 `--confirm`）：

```bash
python scripts/ari.py advise --review-id 12345 --confirm
```

### 7. 行业对标与类目排行

免费查看本品在类目里的星级/差评率位置：

```bash
python scripts/ari.py benchmark --asin B0XXXXXXXX
```

类目排行为付费查询（先报价，确认后加 `--confirm`；类目无数据不收费）：

```bash
python scripts/ari.py leaderboard --category "Kitchen" --by neg_rate --confirm
```

**类目雷达**（免费）：把本品和竞品放在同一条时间轴上比走势。先绑定竞品，
系统会按周自动采集它们的评论，攒几周后走势就出来了：

```bash
python scripts/ari.py schedule                                     # 拿到本品的产品 id
python scripts/ari.py competitors --id 123 --add B0COMPETITOR      # 绑定竞品（按周自动采集）
python scripts/ari.py radar --id 123 --weeks 12                    # 看 12 周走势对比
```

竞品只在其主品仍在监控时才会采集——把主品改成 `manual`，竞品的采集和费用一起停。
### 8. 导出评论与报告（付费套餐功能，不扣积点）

```bash
python scripts/ari.py export --asin B0XXXXXXXX
python scripts/ari.py export --report-id 报告ID --format md
```

评论导出为 CSV，报告可导出 Markdown / HTML，文件保存在当前目录（可用 `--out` 指定路径）。

### 9. 查看历史报告

```bash
python scripts/ari.py reports
python scripts/ari.py report --id 报告ID
```

## 五、常见问题

### 提示 API Key 无效

Key 可能被撤销、复制不完整或属于其他账户。前往 ARI 用户中心重新创建，然后再次运行 `configure`。

### 提示邮箱未验证

先在 ARI 用户中心完成邮箱验证，再重新执行命令。

### 提示积点不足

已有的免费数据仍可查看，但不能继续付费采集或分析。前往“充值与套餐”补充积点。

### 余额明明够，采集非美国站却说积点不足

赠送的积点（注册礼、任务奖励、Free 版每月自动发放的那部分）**只能用于美国站**。
采集 `amz_uk`、`amz_de`、`amz_jp` 等站点需使用付费积点——订阅套餐的周期积点和
增量包都算。报价里的 `usableBalance` 就是该站点实际可用的数量，`sufficient` 为
`false` 时请先订阅套餐或购买增量包。

### 提示有新版本 / 提示版本过旧

运行任意命令时，如果输出里出现 `update` 字段，说明服务端有更新的 Skill 版本。
按提示里的链接，通过你当初安装本 Skill 的渠道更新即可。查看当前版本：

```bash
python scripts/ari.py check
```

返回的 `skillVersion` 是本地版本，`release.latest` 是服务端最新版。

如果提示 `ARI_SKILL_TOO_OLD`，说明你的版本存在会导致**重复扣点**的问题，
服务端已禁止它执行采集和 AI 分析（免费的查询不受影响）。请务必更新后再继续付费操作。

> 出于安全考虑，本 CLI 不会自行下载或运行任何远端文件，更新必须由你手动完成。

### 分析到一半提示“分析流中断”

说明连接断开了，但服务端很可能已经生成完并扣了点。**不要直接重跑**，先查一下：

```bash
python scripts/ari.py reports --asin B0XXXXXXXX --limit 1
```

如果最新报告已经出现，直接用 `report --id` 读取即可；确认没有生成，再重新执行分析。

### 为什么命令没有直接执行采集或分析

这是扣费保护。`collect`、`analyze` 和付费 `deepdive` 必须增加 `--confirm` 才会真正执行。

### 如何查看某个命令的全部参数

```bash
python scripts/ari.py --help
python scripts/ari.py collect --help
python scripts/ari.py analyze --help
```

默认站点为美国站 `amz_us`，还支持 `amz_uk`、`amz_de`、`amz_jp`、`amz_ca`、`amz_fr`、`amz_es` 和 `amz_it`。

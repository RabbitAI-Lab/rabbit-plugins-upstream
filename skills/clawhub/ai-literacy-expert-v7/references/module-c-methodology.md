## 模块总览（方法论落地）

模块 C 是**方法论落地**——把 A3 的「Architect vs Executor」框架，转化为 Architect（人）可以一步步照做的具体方法。一句话串起五单元：

**说清楚（C1）→ 拆明白（C2）→ 验对了（C3）→ 编排好（C4）→ 沉淀住（C5）**

- **C1 Prompt 工程基础**：解决"单次指令"——把一句模糊意图写清楚，让 AI 单次输出从"碰运气"变"可预期"。
- **C2 需求拆解与任务规划**：解决"一个 Prompt 搞不定时"——把复杂目标拆成 AI 能各个击破的子任务序列，并定义每步交付物。
- **C3 验证与闭环**：解决"交得对不对"——按风险选验证策略，建立"信任但验证"的系统化质量保障，发现错就纠错成闭环。
- **C4 多 Agent 协作**：解决"一个 AI 搞不定时"——用多 Agent 并行/交叉审查放大能力，但用契约先行与混合调度守住边界。
- **C5 复盘、沉淀与自动化**：解决"经验挥发"——把 C1-C4 的实践沉淀为可复用/可自动化/可分发的资产，让协作滚成飞轮。

五单元递进关系：**把 A3 元认知框架逐一落锤为可操作技能**：Architect 的第一项能力"清晰沟通意图"= C1；第二项"拆解规划"= C2；第三项"质量审查"= C3；第四项"编排协作（Level 4）"= C4；把协作经验资产化（A3 预告的飞轮）= C5。C1 又是 C2-C5 的"地基/函数"，全模块首尾呼应。

# C1：Prompt 工程基础

## ① 单元定位（一句话）

C1 是模块 C 的起点，回答"Architect 递给 Executor 的施工图纸长什么样"——教学生把一句指令写好，让 AI 单次输出从"碰运气"变成"可预期"，并确立 C1 是 C2-C5 基础设施的认知。

## ② 教学目标

- 建立"AI 不是读心术，它严格按你给的信息工作"的核心直觉（回扣 A2"预测下一词"原理）。
- 掌握写好一条指令的**五要素工具箱**（Role / Task / Constraints / Examples / Format），并按任务复杂度**选择性使用**。
- 理解并会运用引导技巧：**CoT（思维链）**与 **Few-shot（少样本）**，知道 CoT 是"旋钮不是默认值"。
- 会用**约束/边界声明**收窄输出，并诚实认知"约束≠100% 遵守"。
- 正面回答"2026 年还要学 Prompt 吗"：区分低层 PE（被吞噬）与高层 PE（Architect 核心竞争力），建立 C1 是 C2-C5 地基的认知。

## ③ 核心内容与关键方法论（含要点、数据、案例）

**1）为什么写指令仍重要——AI 不是读心术（原理锚点）**
- 直觉：LLM 本质是"预测下一个词"（A2）；上文越具体，预测越准。结构化不是锦上添花，是按原理做事。
- 类比（Anthropic 官方）：AI 像"聪明但缺背景的新实习生"——不说清交付标准，他就按自己理解来。
- 黄金法则（Anthropic）：把你写好的指令拿给一个不了解背景的同事看；若他会困惑，AI 也会困惑。

**2）好指令的五根支柱（工具箱，非必填表单）**
- Role 角色 / Task 任务 / Constraints 约束 / Examples 示例 / Format 输出格式。
- 官方背书收敛：OpenAI 六策略、Anthropic 五原则、futurefactors 的 RTF 模式都指向这套。
- 原理（Role）：训练数据含各角色文本模式（A2），设定角色=激活对应语言/知识模式。
- 批判性提醒：简单任务一根 Task 柱即够，硬塞五根反而稀释指令、输出啰嗦。

**3）让 AI 先想再说——CoT 与 Few-shot（关键数据）**
- **CoT 实证**：Wei et al. 2022《思维链提示激发大语言模型的推理能力》，PaLM(540B) 测 GSM8K：标准提示（直接问）**17.9%** → 思维链提示（写推理步骤）**56.9%**（翻三倍多）。
- 零样本触发：Kojima et al. 2022，仅加 "Let's think step by step"，另一数学基准 **17.7% → 78.7%**。
- 原理：AI 逐词生成、无内心独白（A2）；不写推理链=从问题直跳答案易错；写出推理链=强制经过每步、每步成下一步上文。
- **CoT 代价与边界（旋钮非默认）**：① 有成本（延迟/费用）；② 简单任务几乎无效（<2pt）甚至有害；③ 非越长越好——Lee et al. 2025 指出存在"最优推理长度"，Jang et al. 2025 删冗余句准确率平均 **+7.7%**（冗长陷阱）。适用：多步推理硬任务（数学/逻辑/调试/多因素决策）提 10~40pt；不适合单事实/分类/格式敏感任务。
- **Few-shot**：给 2-3 个示例校准格式与质量预期（不教新知识），利用上下文学习 in-context learning（A2）。

**4）给 AI 画好栅栏——约束与边界（开放讨论）**
- 常见约束：不虚构数据、不超出给定材料、限定风格、控制字数。
- **负向 vs 正向约束——不下定论，开放讨论**：① 直觉"告诉 AI 不要做什么"常在划边界；② OpenAI 官方主张"说该做什么"往往更优（例：与其"不要太长"，不如"3-5 句话"）。给思考脚手架而非答案：负向约束在上下文仍提到 X，可能反而激活 X 的相关词（A2 原理推测）；真实效果因模型因任务而异，**目前无统一结论**，交学生在实操中亲手对比。
- 诚实边界：AI 无元认知、不知道自己不知道（A2）→ 它不会主动说"不确定" → Architect 须主动画边界（"不确定的标注[待确认]"）。约束声明≠万无一失，违反怎么办留 C3。

**5）"Prompt 还重要吗"——PE 价值演化（收尾回收钩子）**
- 背景：2024-2025 "Prompt Engineering is Dead" 声浪（IEEE Spectrum 发文宣称已死）；PE 岗位招聘 2024-2025 降约 **40%**。
- 两层 PE：低层 PE（格式技巧、"请用 JSON"、机械 CoT 触发）→ 确在被模型能力吞噬；高层 PE（需求翻译、边界定义、架构思维、System Prompt 设计）→ 越来越重要。
- 形态演化：写一句 Prompt → 设计 System Prompt/Rules/Skills → 编排多 Agent 契约（PE 在升级不是消失）。
- **核心数据点**：futurefactors 同一任务，弱 prompt vs 结构化强指令，可靠性 **60% → 95%**。
- 核心论点：PE 本质不是"跟 AI 说话的技巧"，而是"把人类意图精确化的能力"——Architect 核心竞争力，模型越强越值钱。

## ④ 教学叙事线 / 章节结构（建议 ~75min）

首尾呼应闭环：章 0 埋"PE 还重要吗"钩子 → 章 5 回收 → 章 6 升华"基础设施/Architect 核心竞争力"。

| 章 | 标题 | 内容主张 | 占比 |

## ⑤ Demo 插槽设计（方法论骨架 + 任务场景 + 评判标准）

> 红线：每 Demo 保持"一次输入→一次输出对比"最简粒度（5-10min）；所有 AI 输出须基于真实工具实际表现，不得虚构；具体 Prompt 文本/输出/步骤标 `[占位·待用户设计]`。

- **实操1：好 vs 坏 Prompt 对比（嵌章2）**
  - 方法论骨架：同一意图 → 模糊指令跑一次 → 五要素结构化指令跑一次 → 并排对比。
  - Demo A（CS/TRAE IDE）：写 Python 函数。坏：「写个处理数据的函数」；好：Role(资深 Python 工程师)+Task(读 CSV、按列名过滤、返回 DataFrame)+Constraints(用 pandas、加类型注解、处理空文件)+Format(附 docstring 和用例)。
  - Demo B（经管/社科 SOLO）：写竞品分析摘要。坏：「分析一下这个竞品」；好：Role(行业分析师)+Task(基于给定材料总结定价/功能/差异化)+Constraints(只用给定材料、不超 300 字、不下投资建议)+Format(三段式+一句话结论)。
  - 评判标准：结构化后是否①不需追问就能直接用 ②减少 AI 替你猜 ③符合预期格式。

- **实操2：CoT 引导效果对比（嵌章3）**
  - 方法论骨架：同一多步推理任务 → 直接问 → 加 CoT 引导 → 对比推理质量。
  - Demo A（CS/TRAE IDE）：分析含 Bug 的代码（off-by-one/边界条件）。直接问：「这段代码有什么问题」；CoT：「请逐行分析执行流程，列出每步变量状态，再指出哪一步出问题」。
  - Demo B（经管/社科 SOLO）：分析销售数据趋势。直接问：「这组数据说明什么」；CoT：「先描述整体走势，再分季度对比，找出异常点，最后给趋势判断」。
  - 评判标准：①直接问是否跳步出错 ②CoT 后步骤是否清晰可验证 ③该任务是否配用 CoT。

- **实操3：约束声明实践 / 负向 vs 正向对比（嵌章4）**
  - 方法论骨架：开放任务 → 逐条加约束 → 观察收敛；同约束负向写法 vs 正向写法各跑 → 记录差异。
  - Demo A（CS/TRAE IDE）：生成代码遵守特定风格/库约束（如"仅用标准库、不用第三方依赖、遵守 PEP8、变量名 snake_case"）。
  - Demo B（经管/社科 SOLO）：写报告限定字数+不用营销话术+只引给定资料（如"500 字内、客观中性不用'革命性/颠覆'等词、所有数据须来自下方材料、无依据处标[待核实]"）。
  - 评判标准：①约束是否被遵守 ②负向/正向输出差异 ③学生能说清取舍（不下定论）。

## ⑥ 常见误区 / 边界

- "AI 偷懒"：得泛泛代码非 AI 偷懒，是没说出口的要求 AI 只能猜。
- 五要素全勤：简单任务硬塞五根支柱（如翻译也写资深角色）→ 稀释指令、啰嗦；应为工具箱非必填表。
- CoT 万能开关：以为所有问题该开 CoT；实有成本、简单任务无用、过长反损（冗长陷阱）。
- 负向/正向必选其一：无一致结论，应实测对比而非记口诀。
- "写了约束 AI 必遵守"：诚实说明可能违反（如虚构数据），验证补救留 C3。
- "PE 已死"混淆：低层技巧消亡真，高层意图精确化更值钱。
- "C1 是一节会翻篇的课"：C1 是 C2-C5 地基，Prompt 如编程函数被反复调用。
- 单 Prompt 天花板：仅解决单步任务，复杂任务（如课程论文）需拆解至 C2。
- 边界（不讲）：任务拆解（C2）、输出验证（C3）、多 Agent（C4）、Rules/Skills 沉淀（C5 仅一句预告）。

## ⑦ 与模块 C 其他单元及 A/B/D 的衔接（回扣点）

- **→ C2**：章6 收尾"一个 Prompt 搞不定时，你需要学会拆解——下节课内容"；承上钩子"Prompt 写再好只解单步"。
- **→ C3**：章4 预告"约束违反怎么办是 C3"；C3 事前约束即把验证条件写进 Prompt。
- **→ C4**：C4 给多 Agent 分发=写多份结构化 Prompt（契约）。
- **→ C5**：章6 轻预告"今天写出的好 Prompt 值得沉淀复用——C5 会讲"；C5 的 Rules/Skills/Prompt 模板=结构化 Prompt 的沉淀形态。
- **回扣 A2**：全课原理锚点（预测下一词、角色模式、上下文学习、无元认知）贯穿。
- **回扣 A3**：章0 接住"人是 Architect、AI 是 Executor，五种能力第一个即清晰沟通意图"；章5 把 PE 升华为 Architect 核心竞争力。
- **B 模块**：Demo 落到 TRAE IDE / SOLO 真实工具表现（呼应 B1/B2 工具操作）。
- **D 模块**：结构化指令是 D1 数据分析、D2 应用开发一切协作的起点。

# C2：需求拆解与任务规划

## ① 单元定位（一句话）

C2 承接 C1 钩子，回答"当一个 Prompt 搞不定时，怎么把大任务拆成 AI 能各个击破的小任务"，对应 A3 从 Level 2（委托式）到 Level 3（协同式）的升级。

## ② 教学目标

- 核心能力交付：面对复杂目标，能拆成 AI 可高质量执行的子任务序列，为每步定义清楚的中间产物，并安排合理的执行顺序。
- 三大方法论亮点：① **AI 辅助拆解**（"AI 出第一刀，人审和调"）② **领域范式作 pattern library**（"你的专业知识是拆解的最大武器"）③ **动态粒度思维**（同任务不同模型不同粒度、过度拆解是浪费、随模型变强越拆越粗）。
- 新增重点：④ **中间产物规划**（"好拆解不只定义每步做什么，还定义每步交什么"）——为 C3 验证、步骤衔接、C5 复盘提供地基。

## ③ 核心内容与关键方法论（含要点、数据、案例）

**1）为什么直接扔大任务会"摔下悬崖"（反例 + Least-to-Most）**
- 反例：大块头需求直接扔 AI → 输出泛泛、顾此失彼、漏要求。
- **Least-to-Most 实证**：Zhou et al. 2022。SCAN 长度分割基准上，同模型同示例：CoT 直接推理仅 **~16%**，先拆成由易到难子问题再逐个解达 **99.7%**——"不是模型变强了，是我们换了种'喂'法"。诚实边界：SCAN 是符号任务的受控极端对比，真实收益没这么夸张，但方向一致——拆解把"做不到"变"做得到"。

**2）下刀的四种基本方式（一把尺子）**
- 按阶段拆（最常用）：调研→分析→列大纲→写初稿→修改→定稿。
- 按角色拆：行业分析师→产品经理→审稿人（C1 角色支柱放大）。
- 按维度拆：成本/风险/可行性分别深入分析。
- **MECE 尺子**：Mutually Exclusive, Collectively Exhaustive（相互独立、完全穷尽），出自 Minto《金字塔原理》；不追求完美，用来检查重叠与遗漏。

**3）中间产物三原则（章3 独立成章）**
- 自包含：单看产出能判对错（呼应 Decomposed Prompting 可独立调试模块）。
- 有明确验收标准：拆解时定义，而非事后拍脑袋。
- 能持久化：对话窗口会清空，落盘=外部记忆；产物即接口，掐断错误级联（A2 原理：接口不对齐→错误级联）。

**4）粒度是一门"成本账"（动态思维）**
- 太粗：AI 发散不可控；太细：人工指挥成本 > 自己干。
- 判断尺：能用一个清晰 Prompt 说明白 + 产出能快速判对错 = 刚好。
- 迭代式拆解：先粗拆，哪步砸了拆哪步（Successive Prompting / Plan-and-Solve）。
- 不拆情形：极简单、时间极紧一次性（最小 2-3 步）、反复成熟任务复用模板。
- 粒度 = f(任务复杂度, 模型能力)：模型越强拆越粗，随升级合并步骤。

**5）领域范式 = 现成拆解模板（pattern library）**

| 范式 | 类别 | 要点 |
|---|---|---|
| **CRISP-DM**（深讲） | 分析/研究类（经管/社科/理工通用） | 六阶段：商业理解→数据理解→数据准备→建模→评估→部署；可迭代回退；**数据准备吃掉 90% 时间**；KDnuggets 调查 2007 起稳居首位，**采用率 ~43%** |
| **V 模型 / 敏捷 Sprint**（深讲） | 代码/工程类（CS） | 需求→设计→实现→单测→集成测试；每模块定义接口与测试标准（呼应 Decomposed Prompting 模块化）；区分 Verification/Validation |
| **金字塔原理（Minto）/ IMRAD**（带过） | 写作类 | 结论先行 + MECE 出处；一句范式+一句例子 |
| **Double Diamond**（带过） | 创意/设计类 | 发散→收敛两次循环；发散让 AI 多生成、收敛人来选 |

- 核心 Takeaway：专业经验=现成拆解模板+产物清单；学 AI 不替代学专业。

**6）完整 Architect 工作流**：选框架 → AI 出计划 → 人审计划 → AI 执行 → 人验收。

## ④ 教学叙事线 / 章节结构（8 章叙事弧）

| 章 | 标题 | 内容主张 | 占比 |
|---|---|---|---|
| 0 | 承上：一个 Prompt 搞不定的时候 | 接 C1 钩子，抛本课 4 问 | ~7% |

| 2 | 下刀的四种基本方式 | MECE/阶段/角色/维度 | ~11% |
| 3 | 好的拆解，连"每一步交什么"都定义好了 | 中间产物 + 接口对齐 + 依赖排序（含实操，可选） | ~15% |
| 4 | 拆到多细，是一门"成本账" | 粒度判断 + 成本收益（何时不拆） | ~12% |

- 意义弧：章0 立"拆解=Architect 最核心技能"→章5 升华"专业知识不可替代"→章7 收"会拆的人效率 10 倍+随模型进步越省力"。

## ⑤ Demo 插槽设计（方法论骨架 + 任务场景 + 评判标准）

> 红线：每 Demo 5-10min，保底 CS(TRAE)+通用(SOLO)，第三可选；实操2 初版计划须真实且带毛病（供人审）；AI 输出真实不虚构。

- **实操1：一步 vs 多步对比（嵌章1）**
  - 方法论骨架：同一目标先大 Prompt 一步做，再拆 4-5 步做，对比缺陷（漏要求/泛泛/矛盾）。
  - Demo A（CS/TRAE）：数据处理脚本；Demo B（经管/SOLO）：新能源车出海分析。
  - 评判标准：一步做是否漏要求/泛泛/矛盾；多步做是否可控、可追责。

- **实操2：AI 辅助拆解 + 人工校准（嵌章6，climax）**
  - 方法论骨架：让 AI 只出计划不执行 → 现场审"五种常见病"并修正。
  - Demo A（CS）：让 AI 拆"数据库迁移"——常漏迁移脚本/错误处理；Demo B（经管）：让 AI 拆"市场分析"——常漏数据清洗/样本定义。
  - 五种常见病（人审重点）：①粒度不均 ②遗漏隐性步骤（数据清洗/权限）③依赖关系错误（串行标并行）④过度保守（塞无用检查）⑤产物模糊（只说做没说交）。
  - 评判标准：能否识别并修正五种病，产出"自包含+有验收标准+可落盘"的计划。

- **实操3：领域范式拆解（嵌章5）**
  - 方法论骨架：选 CRISP-DM / V 模型等拆真实任务，并标出每步中间产物。
  - Demo A（CS/V 模型）：软件需求→设计→实现→测试；Demo B（经管/CRISP-DM）；Demo C（创意/Double Diamond）。
  - 评判标准：范式阶段是否对应清晰中间产物；是否显式标出隐性步骤（如数据准备）。

- **实操4（可选）：完整工作流走一遍**
  - 选框架 → AI 出计划 → 人审 → 执行 → 看产物。用中等复杂度任务，避免超时。

## ⑥ 常见误区 / 边界

- 阶段拆反例：跳过调研大纲直接写 → 泛泛而谈。
- 角色拆反例：同次输出又分析又审 → 自我审查流于形式。
- 维度拆反例："全面分析" → 各维度浅尝辄止。
- MECE 反例：客户分企业/政府/大客户（重叠）；分析漏风险（遗漏）。
- 依赖错排：同时"分析数据"和"获取数据" → AI 编数据（Hallucination）。
- 粒度极端：太粗=没拆；太细=指挥成本飙升。
- 想一次拆完美：应迭代式（Successive Prompting）。
- AI 拆解常见病：粒度不均/漏隐性步骤/依赖错/过度保守/产物模糊。
- 以为拆解有标准答案：实为动态判断，非操作手册。
- 边界（不讲）：每步 Prompt 写法（C1）、输出验证（C3）、多 Agent 并行（C4）、Skills 沉淀（C5 仅预告）。

## ⑦ 与模块 C 其他单元及 A/B/D 的衔接（回扣点）

- **→ C1**：承接"Prompt 只解单步"，引用不重讲写法。
- **→ C3**：章3 中间产物提供"验什么"靶子（避免盲审）；章7 坦白拆解未解"交得对不对"，自然接口至 C3 系统化验证。
- **→ C4**：章3 明界"文件作为 Agent 间共享内存"归 C4 首讲；只到个人工作流产物落盘，不碰多 Agent 并行。
- **→ C5**：中间产物+决策比选作复盘素材（预告）；领域范式沉淀为 Skills 机制仅一句预告。
- **回扣 A3**：拆解对应 Architect 五能力之二，Level 2→3 跳跃；Architect 价值在规划非执行。
- **B/D 模块**：拆解后的子任务在 TRAE/SOLO（B）中执行，是 D1/D2 实练的前置规划动作。

# C3：验证与闭环

## ① 单元定位（一句话）

C3 承接 C2 钩子（"拆解解决了做什么、交什么，但没解决交得对不对"），回答"怎么知道 AI 每一步做对没、错了怎么纠、怎么迭代回去直到达标"，对应 A3 中 Architect 的第三项职责"质量审查"。

## ② 教学目标

- 核心能力交付：面对 AI 输出，能按风险等级选择验证策略，建立"信任但验证"的系统化质量保障流程，并在发现问题后有效纠错形成闭环。
- 具体覆盖：为什么不能无条件信任 AI；该验什么（中间产物）；四层验证策略；不同风险验到多狠；警惕自身心理偏差；发现错了怎么纠成闭环。

## ③ 核心内容与关键方法论（含要点、数据、案例）

**1）信任，但要验证——Air Canada 案（章1 锚点案例）**
- 事件：2022.11 加拿大乘客 Jake Moffatt 祖母去世，在 Air Canada 官网与客服聊天机器人对话，机器人"流畅自信地"编造了一条不存在的退票政策（称"可先全价买票，90 天内按丧亲票价申请部分退款"）。他花 **1400+ 加元**购票后申请被拒——真实政策为"出行前申请、飞完不退"，机器人把限制编反且语气笃定。
- 判决：Moffatt v. Air Canada, **2024 BCCRT 149**（加拿大民事裁决庭），判赔（框架记 **812 加元**）。航司抗辩"机器人是独立法律实体、为自己负责"被庭审员 Christopher Rivers 驳回："机器人仍是网站一部分，静态页或机器人无区别"。
- 两根支柱：① 流畅 ≠ 真实（接 A2"自信地胡说"；Hallucination 结构性，最强模型幻觉率也非零——Vectara 榜单简单摘要百分之一二、前沿普遍百分之十上下、越难越高）；② 你为 AI 输出负全责，"这是 AI 写的"非免责声明（接 A3 Architect 质量终审权）。
- 选用理由：换商业/消费域，不与 A3 已用的 Schwartz 律师案重复。

**2）你要验的，是"中间产物"（章2 独立成章，兑现 C2 伏笔）**
- 四价值：可追溯 / 可对照 / 逻辑链 / 部分回滚。"产出即验证" + Shift Left（软件工程"测试左移"，Larry Smith 2001，方向性表述"越早发现越省"）。
- 反例：只在最后看总结果 → 无法定位哪步坏，全推重来。

**3）四层验证：纵深防线（章3，工具箱非强制清单，按风险组合）**

| 层 | 时机 | 动作 | 成本 | 拦截错误 |
|---|---|---|---|---|
| 一、事前约束 | 动手前 | Prompt/Rules 划栅栏（如"不虚构，标[待确认]"） | 最低 | 一部分低级越界（非 100%） |
| 二、事中审查 | 进行中 | 追问（"你确定吗/来源？"）+ 关键节点 Review 中间产物 | 中 | 方向偏差、可疑结论 |
| 三、自动化验证 | 每步后 | 跑单测/lint/格式/一致性（确定性工具） | 低（配置后） | 格式/语法/计算错 |
| 四、事后全局审计 | 完成后 | 跳脱局部复检矛盾/遗漏 | 高 | 全局不一致 |

- 原理：事前约束概率生效非保证（AI 靠上下文预测，约束是模式倾向非理解）；追问同源 AI 有上限（追问=给新上文信号）；AI 数学/逻辑是模式匹配非精确计算→确定性工具比 AI 自检可靠；长上下文会走神漏中间→需事后审计。

**4）验到多狠，是一门"成本账"（章4）**
- 风险 × 力度矩阵；过度验证陷阱：每行逐字查不如自己写；帕累托 ~80% 错被前两层捕获。心法：足够好（good enough）。

**5）验证是心智纪律——四大认知偏差（章5 独立成章）**

| 偏差 | 来源 | 对抗方法 |
|---|---|---|
| **流畅度偏差**（最重要） | Reber & Schwarz 1999：把加工顺畅当真实 | 忽略文笔，问"能否独立证实"（Hallucination 恰恰自信通顺） |
| **锚定效应** | Tversky & Kahneman 1974：先现答案成锚（转盘实验随机数拉判断 20pt） | 看答案前先想正确答案大概样 |
| **确认偏差** | —：找支持非反驳 | 主动问"若错最可能错哪" |
| **专家盲区** | Gaube et al. 2021：越不懂领域越盲信（少经验医生直接接受 AI 标注建议） | 生域提高验证等级或标"超判断力" |

- 原理：AI 过度自信、表述一贯笃定，核查责任全在人；验证是主动对抗惰性心智纪律。

**6）发现错了怎么办——纠错与迭代闭环（章6 独立成章）**
- 三策略（成本升）：① 追问修正（局部事实）② 换策略重做（方法错目标对）③ 推倒重来（前提错；防沉没成本谬误）。
- 循环：验证→定位（靠中间产物）→选策→重执行→再验证→达标，逐步收敛。
- 部分回滚：中间产物=存档点，免删号重练；停损：达验收标准/风险对应质量/边际收益低即够。

**7）用第二个 AI 审第一个——LLM-as-a-Judge（章7，为 C4 埋种子）**
- 原理：同 AI 自检无效（无元认知）；独立 AI 不同上下文可发现盲区（类比论文同行评审；工业界生成器-评估器模式，Anthropic）。三模式：独立重做对比 / 指令式审查 / 角色对抗。
- 数据：Zheng et al. 2023，AI 裁判与人类一致率 **>80%**，但有系统性偏差（position/verbosity/self-enhancement bias，且同向稳定）。概念级引用：Constitutional AI / RLAIF（Bai et al. 2022）。
- 边界：能查格式/逻辑/遗漏；**不能**查共同事实幻觉（训练重叠会附和）、方向、价值判断。结论：AI 放大审查力，终审权在人。

**8）NASA 自动化偏差（章5 情绪锤）**
- NASA Ames 全任务飞行模拟：自动检查单错误建议"关闭正常引擎"，**75%** 专业机组照做；对照纸质检查单仅 **25%** 犯错（Skitka et al. 1999）。
- 概念：自动化偏差（Automation Bias）——人过度信任自动化输出，用"它说的"替代核查；AI 是最流畅自信的自动化系统，触发能力空前强。

## ④ 教学叙事线 / 章节结构（9 章 + 叙事/意义弧）

| 章 | 标题 | 要点 | 占比 |
|---|---|---|---|
| 0 | 拆完了、执行了，怎么知道每步做对了？ | 承 C2 钩子，立 Architect 第三项职责 | ~5% |

| 2 | 你要验的，是"中间产物" | 中间产物四价值 + Shift Left | ~13% |
| 3 | 四层验证：纵深防线 | 事前→事中→自动化→事后（含实操1+2） | ~18% |
| 4 | 验到多狠，是一门"成本账" | 风险×力度 + 过度验证陷阱 | ~10% |

## ⑤ Demo 插槽设计（方法论骨架 + 任务场景 + 评判标准）

> 红线：4 实操均给骨架+场景方向+评判，具体文本/输出标 `[占位·待用户设计]`；每实操保底 CS(TRAE)+通用(SOLO)；实操3 用双窗口手动模拟（非 C4 自动编排）；实操4 用中风险 capstone；AI 输出真实不虚构。

- **实操1：事前约束 vs 无约束对比（嵌章3）**
  - 方法论骨架：同一任务，写约束 vs 不写约束，对比输出越界情况。
  - Demo A（CS/TRAE）：生成代码加"不虚构 API、不超出给定库"；Demo B（经管/SOLO）：报告加"只引给定资料、无依据标[待核实]"。
  - 评判标准：约束是否拦截低级越界；是否理解约束非 100% 生效（需后续层兜底）。

- **实操2：用自动化工具验证 AI 输出（嵌章3）**
  - 方法论骨架：让 AI 产出代码/文本，用确定性工具（单测/lint/格式校验）验证。
  - Demo A（CS/TRAE）：跑 pytest/lint 查逻辑与语法；Demo B（经管/SOLO）：用脚本校验数据一致性/格式。
  - 评判标准：是否跑出 AI 肉眼看不出的低级错；是否体会"工具比 AI 自检可靠"。

- **实操3：交叉审查实践（嵌章7，双窗口手动模拟）**
  - 方法论骨架：A 窗口产出落文件 → B 窗口（独立上下文）独立审查 → 人终审。强调 B 须无 A 思维包袱。
  - Demo A（CS）：B 查边界/Bug；Demo B（经管）：B 质疑因果/证据。
  - 评判标准：B 是否发现 A 盲区；是否理解"同 AI 自审无效、两 AI 可能同编同假"。

- **实操4：风险定级 + 完整闭环练习（capstone，嵌章6）**
  - 方法论骨架：给中风险任务 → 定风险等级 → 选验证组合 → 执行 → 发现错 → 纠错 → 达标。
  - 评判标准：验证力度是否匹配风险；闭环是否收敛到"足够好"；是否用中间产物定位错误。

## ⑥ 常见误区 / 边界

- 只验最终结果：错误滚雪球污染下游，须验中间产物。
- 约束当护身符：写"勿编造"仍可能编，须后续层兜底。
- 全程"好的继续"：不在关键节点停看，赌命运于终点。
- 肉眼硬扛工具活：该跑测试不跑，易放低级错。
- 过度验证：四层全开低风险任务，吃掉 AI 效率；80% 错前两层拦，迭代式非地毯式。
- 自己审自己上限：同 AI 追问/自检使不上劲。
- AI 互审抓共同幻觉：两 AI 可能同编同假，必须人查。
- 完美主义：为 5% 完美花 50% 时间，不知停。
- 边界（不讲）：Prompt 怎么写（C1）、任务怎么拆（C2）、多 Agent 编排细节（C4）、规则沉淀自动化（C5 仅预告）。

## ⑦ 与模块 C 其他单元及 A/B/D 的衔接（回扣点）

- **→ C2**：C2 规划"中间产物"直接当 C3 验证靶子（章2）；C2 拆解提供章3 检查点；章6 靠中间产物部分回退兑现 C2 伏笔。
- **→ C4**：章7 种子——"多个 Agent 协作时，交叉审查变编排固定角色"；章8 过渡"验证可分布化……多个 Agent 怎么互相审查是 C4"。
- **→ C5**：章2 预告中间产物是复盘复用资产；章4 预告高频验证规则沉淀自动化是 C5。
- **回扣 A2**：全课原理锚点回扣 A2（Hallucination 结构性、无元认知、上下文学习等）。
- **回扣 A3**：章8 回扣"好的 Architect 永远 Review Executor 交付"（质量终审权）。
- **B/D 模块**：验证在 TRAE/SOLO（B）中落地；D1 数据分析的"相关≠因果"、D2 应用开发的测试，都是 C3 验证纪律的具体场景。

# C4：多 Agent 协作

## ① 单元定位（一句话）

C4 是协作能力的"规模化跳跃"——前三课解决"一个人 × 一个 AI 怎么配合好"，C4 解决"任务大到一个 AI 搞不定时，怎么让多个 AI 协同"，是 A3「Level 4 编排式协作」的方法论落地。

## ② 教学目标

- 目标定位："理解架构 + 建立选择判断力"，不是实操某个具体工具。
- 核心培养：对协作架构的理解与选择判断力（模块化设计涵盖适用场景判定、三种组织架构与正交编排模式、契约先行及混合调度）。

## ③ 核心内容与关键方法论（含要点、数据、案例）

**1）为什么要进化出这些形态——一部"放权与翻车"的历史（钟摆叙事）**
- 2023 全自主狂热（AutoGPT 无限循环/目标漂移、BabyAGI 任务爆炸）→ 固定角色 → 2024 回归人控 → 2025-2026 谨慎放权。
- 历史教训：完全自主=完全不可控；早期全自主必然翻车；必须人来定义边界/终止条件/规模。

**2）三种成熟架构（怎么组织 Agent）**

| 形态 | 结构 | 特点 | 适用 | 风险 |
|---|---|---|---|---|
| **Subagents（子代理委派）** | 父 Agent 派子 Agent，单向汇报 | context 隔离、结果收敛；Map-only/Map-Reduce/Pipeline（教学借用术语） | 子任务独立（如 5 竞品） | 父拆解错则全错；子不可补位 |
| **Agent Teams（对等协作）** | 多 Agent 对等，共享看板，Team Lead 协调 | 点对点通信、可协调 | 子任务有依赖（如前后端接口） | token 随规模线性增、沟通开销大、可能不收敛（标"实验性"） |
| **Dynamic Agents（动态生成）** | Orchestrator 运行时临时组队 | 自适应数量/角色 | 任务多变规模不定 | 成本不可预测、Debug 难（曾故障生成 50 子 Agent） |

- 选架建议：新手首选 Subagents；按"独立→Subagents，依赖→Teams，不确定→Dynamic"。

**3）调度模式——谁来指挥（与架构正交）**
- 人工调度（Human as Orchestrator）：人拆/派/审；完全可控但人成瓶颈。适用高风险、首次。
- Agent 自调度（Autonomous）：Orchestrator 自动；效率高风险大（级联错、循环、不可预测）。适用已验证重复任务。
- **混合模式（推荐入门）**：关键节点人介入，低风险自动。有数据支撑（见 MAST 研究，多 Agent 任务失败率 41%–86.7%，引入验证机制后显著下降）。动态演进：信心低→人工，信心高→自调度；混合为甜区。
- **HITL 四个典型介入节点（APXML）**：① 不可逆操作前审批 ② 置信度低于阈值升级 ③ 发布前质量门 ④ 信息补充澄清。

**4）架构 × 编排二维矩阵（维度统一收口，第3章末收口）**
- 两套三分法为正交两层，不混淆：
  - **架构维度**（Agent 之间是什么关系）：Subagents / Agent Teams / Dynamic Agents。
  - **编排维度**（任务在 Agent 间怎么流动）：串行(Pipeline) / 并行(Parallel) / 交叉审查(Review)。
- 关系：编排是"动作"，架构是"组织形式"。例：Subagents 下可跑并行(Map-only) 也可跑串行(Pipeline)；交叉审查是特殊编排，可发生在任何架构。
- 组合示例：Subagents×串行=父 Agent 让子任务排队流水线；Subagents×并行=父 Agent 同时派 5 个子 Agent；Subagents×交叉审查=派一个 Agent 专门审另一个产出；Agent Teams×交叉审查=队友互相 review。

**5）契约先行（胜负手，章5 独立成章）**
- 反例：三窗口各说"分析竞品 X/Y/Z"→ A 散文、B 五维表、C 三点 list，维度对不上需返工（接口对不上、字段名冲突）。
- 契约三要素：① 接口定义（每个 Agent 输入/输出）② 格式规范（输出结构、文件命名）③ 约束声明（共享质量标准、边界）。
- 类比：软件工程的"API 契约"。回扣 C1：契约本质=一组写给每个 Agent 的结构化 Prompt（角色+任务+约束+格式）。
- 各架构差异：Subagents（Orchestrator 统发）/ Agent Teams（团队宪章文件）/ Dynamic（定"原则"而非"具体格式"）。Meta 案例：本课程"模块 C 共性约束 + 各课交付要求"就是契约文件。

**6）文件即共享内存（章6）**
- 类比：Agent 间跨会话信息传递唯一介质，文件即协议（输入/输出/中间状态文件）。
- 原理：对话窗口会清空（A2），Agent 间靠文件传信；原则——每 Agent 写独立文件、命名即契约部分、汇总环节统一读并合并。

**7）MAST 研究（关键数据，NeurIPS 2025）**
- 文献：Cemri et al. (2025) *Why Do Multi-Agent LLM Systems Fail?*（NeurIPS 2025），分析 7 个主流框架、**1642 条轨迹**（框架记 1600+）。
- **失败率数据**：多 Agent 系统失败率 **41% 到 86.7%**（某些情况近乎抛硬币）；高频失败模式：步骤重复/无限循环占 **15.7%**、不知何时停占 **12.4%**、任务跑偏占 **7.4%**。→ 让 AI 当 Orchestrator=把最难的决策交给它最不擅长的能力（锯齿状前沿）。
- **验证显著提升**：加入显式验证/审查环节带来显著性能提升（MAST 显示失败率最高达 86.7%，引入验证机制后明显回落）→ 混合模式不是妥协，是有数据支撑的最优解；交叉审查（Review）价值被印证。
- 成本警示（Anthropic 多 Agent 研究）：生产级多 Agent 系统比单 Agent 表现高 **90.2%**，但耗 **~15× token**（单 Agent 约 4×）。

## ⑤ Demo 插槽设计（方法论骨架 + 任务场景 + 评判标准）

> 红线：双实操保底 CS+通用，建议补理工/人文可选；具体 Prompt/输出标 `[占位·待用户设计]`；AI 输出真实不虚构；用 TRAE/SOLO 多窗口模拟。

- **实操1：手动编排并行 Sub-agent + 契约定义（嵌章5）**
  - 方法论骨架：定契约 → 开 3 窗口并行分派 → 第 4 汇总。
  - Demo A（CS）：契约统一定 Todo 模型 `{id,title,done,createdAt}` + REST API；三窗口写前后端测试；对照删契约则字段打架（title/name/text）。
  - Demo B（经管/SOLO）：契约定 5 维度（定价/功能/用户/口碑/动向）+ Markdown 表 + 命名；三竞品并行→第4 合并；对照无契约则结构乱。
  - Demo C（理工/人文）：理工统报告结构（条件/摘要/异常/结论）；人文统摘要结构（问题/方法/结论/局限）。
  - 评判标准：契约是否让并行产物可直接合并；无契约是否翻车（字段冲突/维度对不上）。

- **实操2：交叉审查——Agent 审 Agent（嵌章6）**
  - 方法论骨架：A 产出落文件 → B 独立窗口审查（无 A 思维包袱）→ 人终审。
  - Demo A（CS）：B 查边界/Bug；Demo B（经管）：B 质疑因果/证据；Demo C（理工/人文）：理工资逻辑跳步、人文查虚构引用。
  - 评判标准：B 是否发现 A 盲区；是否体现交叉审查（Review）价值；人终审必要性。

## ⑥ 常见误区 / 边界

- 过度协作：如写请假邮件用 4 Agent，协调成本超收益；强耦合任务不宜多 Agent（Anthropic 指编码可并行性低）。
- 认为多 Agent 免费：实际 ~15× token，协调成本随数增，失败率 41%-86.7%。
- 混淆架构与编排：误以为 Subagents/Agent Teams 等同于串行/并行；实为两垂直维度。
- 不签契约开工：靠 Agent 事后对齐必翻车（无默契）。
- 全自主调度迷信：让 AI 当 Orchestrator 压其最弱全局规划，易级联错/循环。
- 同 Agent 自审：效果有限，须独立 B Agent 交叉审查。
- 架构越高级越好：Meta 案例用 Subagents 已够，匹配任务特征而非追新。
- 多 Agent 不是银弹：先问"这任务真需要多 Agent 吗"。

# C5：复盘、沉淀与自动化

> 本节正文素材来源：已补全并入的「课程内容文档 3.md」（C5 完整课程叙述稿，2026-07-26 由用户本地上传并入；此前该文档在知识库被删除、仅以内容框架.md 为底稿合成，现叙述细节已全部补齐）。下面对齐该文档的章节与叙事线，并保留模块 C 教学参考的提炼格式。

## ① 单元定位（一句话）

C5 是模块 C 的"闭环"与"升华"——前四课教"怎么做好一次协作"（说清楚→拆明白→验对了→编排好），C5 不教新操作技巧，而是教学生把 C1-C4 的实践沉淀为可复用、可自动化、可分发的系统化资产，让协作经验滚成越用越快的飞轮（A3 预告"飞轮模型"的完整落地）。

**开场钩子（文档第 0 章·立痛点）**：先让学生回忆一个几乎人人经历过的瞬间——上次花一小时调通的东西，这周新开对话又得从头来一遍。再回扣 C4 结尾那个问题："为竞品分析设计的一套多 Agent 流程，下个月分析另一批竞品，难道从头再设计？"引出本课核心句：**怎么让 AI 协作经验不要每次"清零"，而是像滚雪球一样越积越多、越用越快？** 学完应建立的能力：把踩过的坑、好 Prompt、验证过的规则、编排过的流程，系统性沉淀为可复用资产，并通过自动化让资产持续生效，形成越转越快的"飞轮"。

**这门课本身就是"沉淀资产"活样本（Meta 案例，课前可点题）**：本模块每节课由不同 AI Agent 分别写出，但风格统一、术语一致、衔接顺畅——因为开工前都先读了《模块 C 共性约束》和各自《交付要求》两份文件（术语对照表、首讲权分配表等）。这些规则是课程设计者**一次次踩坑、复盘、攒出来**的（如"两个 Agent 译名不一致"→加术语表；"后课重讲前课"→加首讲权表）。**最朴素的沉淀=把一次性教训变成永久性规则**——你为 C1-C4 流过的每一滴汗，攒下来就是下一次协作的起点。贯穿全课的隐喻：**飞轮**——沉重的轮子，第一圈最难推，推着推着靠惯性越转越快。

## ② 教学目标

- 能力目标："把经验资产化 + 让资产自动生效 + 去生态（社区）找现成沉淀"，不是再学一项操作技巧。
- 核心认知：在连工具都自带记忆的时代，真正竞争力是"你有多主动地积累了一批别人没有、可复用、可迁移的协作经验"；工具记忆越强，"判断什么值得记"这件脑力活越值钱。
- 关键心智模型（课堂金句）：**"Plugin 是分发格式，Skill 是内容，MCP 是数据层，Hooks 是自动化。"**
- 原理闭环认知（文档第 1 章·为什么经验会"挥发"）：
  - **回扣 A2**：AI 两种"记忆"——参数记忆（固化改不了）+ 上下文窗口（工作记忆）。对话一结束上下文窗口清空，所以"换个对话它就忘了你是谁"。你在上个对话调好的 Prompt、踩到的坑，全在该对话上下文里，关对话即蒸发；AI 没有跨会话记忆，不会因上周被纠正这周就"长记性"。**经验消散不是因为它不重要，而是被存错了地方——存在一次性用完即焚的容器里。**
  - **工具记忆新变化（2026 必须正面回答）**：ChatGPT/豆包跨对话记住偏好、编程工具维护项目级记忆文件——这正是 A2 说的 Agent 第二层"外部记忆"（文件系统/向量库突破上下文清空）。这是好事，但**"工具能记忆"≠"你不用主动沉淀"**，三条理由：①自动记忆是**黑盒**（看不见改不动），你主动写下的 Rule/Skill 是**白盒**（能读能改能复制能分享）——模糊的自动记忆沉淀不出可迁移资产；②"记住什么"是**它替你决定**，而"什么值得留"本身是 Architect 核心价值，不能外包黑盒；③**回扣 A3**：AI 是"工具"不是"同事"，不会像外科医生百台手术后自动内化经验，它只是更大更聪明的"储物柜"——放什么、怎么分类、何时取用，决定权始终在人。
  - **类比**：工具自动记忆像手机相册"自动备份"（东西没丢）；你精心整理、打标签、分文件夹的作品集才是"资产可用"（前者≠后者）。本课教后者——主动、有判断地积累。
  - **真正竞争力结论**：人人都会用 AI 的时代，门槛已低到人人跨过；竞争力 = "你有多主动积累了一批别人没有的可复用协作经验"。两人用同样 AI，一个每次从零、一个攥着几十条规则+十几个流程+几个专属助手，一年后产出效率差数量级——不是 AI 更聪明，而是后者把每次协作都"存了下来"。

## ③ 核心内容与关键方法论（含要点、数据、案例）

**0）两个沉淀时机 + 中间产物（文档第 2-3 章）**

- **两个沉淀时机（互补，非二选一）**：
  - **触发式沉淀（踩坑即固化）**：遇到坑→找到解法→*立刻*固化成规则/模板。实时、低成本；缺点：覆盖面取决于踩了多少坑（没踩过的坑沉淀不下来）。
  - **主动复盘（阶段性回顾）**：项目/任务做完后专门回顾——哪些有效、哪些无效、什么模式值得提炼复用（类比敏捷 Retrospective / 咨询项目后总结）。系统、不遗漏；缺点：需刻意投入时间，反人性但回报高。
  - 两者缺一不可：触发式保证经验库持续有输入，主动复盘保证不漏掉"单看不起眼、连起来才是大模式"的东西。
- **关键认知：中间产物就是现成素材（不必额外造）**。你早已在 C2/C3 产出一抽屉素材——**中间产物这条线从 C2 规划（第一重价值：服务规划）→ C3 验证（第二重价值：天然检查点）→ C5 复用（第三重价值：复用迭代）贯穿全模块**。这正是 C2 一开始要求"拆解时就规划好每步输出"的原因——它是一笔会一路增值的资产。
- **四类最值得复用的中间产物**：①方案复用（分析框架/架构/大纲，下次改着用）；②决策记录复用（记下"为什么选 A、否掉 B/C"，下次不复纠结）；③中间推理复用（把问题想透的推理链作新任务起点）；④失败记录复用（"错在哪、为什么错、怎么改对"，下次绕坑）——**第四类即实操 1"踩坑→Rule"本质**。
- **判断标准（别什么都留）**：只问一句"**这个过程记录，对未来的任务有复用价值吗？**" 高复用价值（通用框架、可参数化模板、典型错误修正，过了这村还用得上）值得留；低复用价值（特定数据一次性处理结果、为独特场景高度定制的中间步骤，过了这村没这店）别留。这与"什么值得自动化"是**同一种判断力**——区分"会重复出现"与"一次性"。

**1）四级沉淀阶梯：Rules → Skills → Custom Agents → Plugin（全课骨架）**

> 台阶图（文档原图）：`Rules（被动防线）→ Skills（自动化操作）→ Custom Agents（角色封装）→ Plugin（可分发能力包）`；自动化程度从"被动防错→主动执行→整个角色复用→生态级分发"。**铁律：不是越高级越好**——形态要匹配复用频率与分享需求（呼应 C4"不是所有任务都配多 Agent"、C1"五要素非必填表单"）。工具讲解标本：Rules 用 TRAE/SOLO 实操，更高阶用 Claude Code 作"概念锚点"（理解解决什么问题，而非记按钮）。

| 层级 | 本质 | 真实工具落点 | 解决什么 | 进阶说明（文档逐层详述） |
|---|---|---|---|---|
| **Rules（被动防线）** | 约束性声明，自动注入每次对话 | TRAE `.trae/rules/`（始终/指定文件/智能/手动生效）；SOLO 自定义规则 | 防踩坑，一次写入自动应用 | 是 C1"约束声明"的系统化升级（一次性手写→永久写入）；**原理回扣 A2**：规则自动塞进每次对话上下文，AI 预测自然倾向遵守。**不沉淀会怎样**：每开对话手敲"加错误处理"，忘一次就埋雷——靠人记性保质量最不可靠。 |
| **Skills（自动化操作）** | 多步 workflow 打包成一键 | `SKILL.md`（name/description/instructions + 可选脚本/参考） | 高频重复任务，不必每次重拆 | = C2 拆解方案 + C1 每步 Prompt 的封装（Rules 是约束，Skills 是可执行流程）。**不沉淀会怎样**：每月竞品分析重拆重写五六个 Prompt，等于每月重新发明轮子。 |
| **Custom Agents（角色封装）** | 角色+Rules+Skills 打包成专属助手 | `.claude/agents/` Markdown（name/用途/工具/模型/system prompt） | 不必每次重设角色 | **原理回扣 A2/C1**：角色设定激活训练数据对应知识模式，固化后每次自动激活，不必从零写"你是一名严格审查员…"。**与 C4 关系**：C4 多 Agent 架构里的"队员"从哪来？Custom Agents 就是预先练好的"专业队员"——C4 教排兵布阵，C5 教把兵种练好存进军营。 |
| **Plugin（可分发整合包）** | Skill+MCP+Rules+Agents 打包 | `plugin.json` 清单文件夹（含 skills/agents/hooks/MCP 配置），`/plugin install` | 站在别人/团队肩膀上，可分发 | 新概念 **MCP**（承接 C4）= "AI 界 USB-C"，Agent 连外部工具统一接口。心智模型：**Skill 解决"怎么做"、MCP 解决"用什么工具"、Rules 解决"守什么规矩"、Agent 解决"谁来做"，打包即 Plugin**。Anthropic 称传不出去的个人配置为 **tribal knowledge（部落知识）**，Plugin 是解药——资深工程师周日的配置，新人周一一条命令装上。**最高形态=可分发能力包**（边界：只讲"是什么/为什么最高形态"，不教怎么从零搭 MCP Server / Plugin）。 |

- 收束表与判断标准：偶用一次的约束写条 Rule 即可，犯不着封装 Skill；只自己用的流程做成 Skill 就行，不必打包 Plugin。**停在哪一级的标准 = "这个经验会被复用多少次、需分享给多少人"**——用匹配需求的最简形态，不为炫技过度封装。

**2）让沉淀自动生效——Automation 与 Hooks（文档第 4 章）**

- **现实痛点**：很多人存了一堆然后忘了用——存了周报模板每周仍从空白开始，写了分析流程下次没想起来翻。沉淀只停"存下来"= 死的档案馆；要让它在该用时自己跳出来，不依赖记性。
- **Automation 通用模式 When→Do→Output（跨工具内核）**：When（触发：定时/事件/状态变化）→ Do（执行：调用沉淀好的 Skill/流程）→ Output（结果存哪/通知谁）。面向所有人例子：每周一早→汇总上周日志→生成周报草稿存文档；收到客户文件→按模板归档→通知已处理；每天定时查数据源→有变化就分析→摘要告警。**核心=把"每次都得记得做 X"变成系统自动做 X**（与 Zapier/n8n 一脉相承）。通用工具（SOLO）靠定时/触发式任务/Workflow 编排（带条件分支、人工审批节点）实现。
- **什么值得自动化（铁律·回扣 C3）**：**值得自动化 = 高频 + 低变异 + 已验证有效**，缺一不可，尤其"已验证"。回扣 C3"先验证再信任"→ 先手动跑通确认有效再自动化。**为什么关键**：自动化是放大器，放大的不只是效率还有错误——手动流程有小毛病你能顺手纠，自动化会把没跑通的流程一遍遍重复执行且很久不被发现（C4 讲过 Anthropic 早期故障：一个简单查询生成 50 个子 Agent，即"把没验证好的逻辑交给自动化"的代价）。**铁律：不要自动化你还没亲手跑通的流程。**
- **Hooks（CS 延伸·开发场景具体形态）**：特定开发事件发生时自动触发执行脚本，即 When→Do→Output 在开发流的具体实现。Claude Code 常见事件：PreToolUse（AI 动用工具*前*，可拦截危险命令/校验参数）、PostToolUse（工具执行*后*，自动跑格式化/lint/测试）、SessionStart（会话开始注入 git 状态/待办）。配置在 `.claude/settings.json`：event + matcher（匹配工具）+ command。**设计区分**：PreToolUse=拦截器（返回失败可阻止动作，如拦 `rm -rf`）；PostToolUse=通知器（输出喂回 AI，如写完跑测试告诉它结果）。**与 Rules 区别**：Rules=认知约束（作用在 AI 思考生成层），Hooks=行为触发（作用在具体动作层，执行实打实脚本）。**最有价值用法=把 C3 验证策略自动化**（提交前自动跑 lint/测试）——把验证节点从"靠人记得"变"系统自动做"。**安全红线**：Hooks 以你的权限执行任意命令，装别人的 Hooks 前务必看清它干什么（再次呼应"先验证再自动化"，放大是双向的）。

**3）去社区"捡"沉淀（文档第 5 章·独立成章）**

- **为什么单列**：前面讲的飞轮都是"自己一圈圈推"，但单人踩坑/总结有限，有天花板；捷径是复用别人已公开分享的沉淀（截至 2026 年中社区已有数千 Skill、上千 Plugin 流通）。
- **去哪里找**：Skills Marketplace / Find Skill（TRAE 推荐、Claude Code 官方+社区 marketplace，类比"AI 工作流 App Store"——想要的功能可能早有人上架，可装可改）；社区 Rules 库（GitHub awesome-cursorrules / awesome-trae-rules）；Custom Agent/Prompt 模板社区；学科/行业专属资源。
- **核心能力：搜 → 评估 → 适配 → 使用**（"找到"≠"能用"）：搜（知道去哪/用什么词）→ **评估（最易被跳过也最危险：质量靠谱吗、适合我场景吗、有安全风险吗）→ 适配（别人很少 100% 适配，按场景二次改）→ 使用（改完才放心用）。**为什么评估不能省**：直接照搬等于把别人的坑一起搬进来（别人的 Rule 可能基于特定项目假设、Skill 可能用你没装的工具、Agent 模板可能内置不适合你的偏好；别人的 Hooks 会在你电脑执行命令，装前必须看清）。
- **双向生态（回扣 A3 视野）**：你既是消费者也是贡献者——沉淀验证好用的 Rule/Skill 也能分享出去。好 Architect 不闷头重造所有轮子，既会自己造、也知去哪找最佳实践、还把好东西回馈——**"什么时候该自己造、什么时候该直接拿"本身是一种判断力**。

**4）飞轮转起来（文档第 6 章·收束）**

- **飞轮图**：Task（做一次任务）→ 发现有效模式/踩到可避免的坑 → 沉淀（Rule/Skill/Custom Agent/Plugin）→ 下次类似任务直接复用（Reuse）→ 更快更好完成、腾出精力发现更多模式 →（回起点，但这一圈比上一圈快）。**每次协作不只"完成一件事"，还顺手给飞轮添一份动能。**
- **物理直觉（Jim Collins《从优秀到卓越》飞轮效应）**：想象直径十米、重数吨的金属轮——一开始拼尽全力纹丝不动，几小时才转完第一圈；持续同向推，两圈五圈十圈后有了惯性越转越快，到临界点自身惯性成主要驱动力。**Collins 关键句："没有哪一次推动是决定性的"——是所有推动累积的结果，没有奇迹时刻只有持续累积。** 头几条 Rule/头几个 Skill 就是最难推的第一圈，很多人此阶段放弃；扛过最沉几圈，资产互相叠加调用，飞轮越转越轻越快。
- **三个加速器（本节每块都是加速器）**：触发式沉淀（保证持续有新输入）+ Automation/Hooks（保证自动生效、不"存了不用"，是传动装置）+ Custom Agents+社区（角色级/生态级复用，社区让你直接借别人推过的飞轮）。
- **反面：厄运循环（doom loop）**：从不积累、每次另起炉灶推倒重来，每次重启都耗散上次动能，永远原地打转推"最沉第一圈"。**从不沉淀的人每次从零开始，努力无法累积，困在厄运循环——本课帮你跳出，开始推自己的飞轮。**
- **动力永远来自你（回扣 A3 根本原理）**：AI 是工具不是同事，不会自己积累经验——飞轮不会自己转，每份动能都来自你主动的那一推（主动复盘/沉淀/判断什么值得自动化）。哪怕工具自带记忆，也只是帮你"存得住"，转动飞轮的手始终是你。**若只带走一个习惯："每次协作结束多问一句——这次有什么值得沉淀下来的？"——这一句话就是你推动飞轮的手。**

**5）五课闭环 + 该带走什么（文档第 7 章·衔接模块 D）**

- **五课闭环**：C1 把一句话说清楚（单次沟通质量）→ C2 把复杂事拆明白（任务规划）→ C3 判断一个输出对不对（质量保障）→ C4 指挥一支 AI 团队（规模化编排）→ C5 让这一切沉淀下来、自动运转、越用越快（经验资产化）。正是模块 C 开篇主线"从说一句话，到编排一个系统，再到让系统自我进化"——五课走完手握一套完整协作方法论。
- **该带走 5 点**：①经验默认会蒸发（A2 无跨会话记忆、A3 工具不自己积累，工具记忆越强"判断什么值得记"越值钱）；②沉淀四级台阶（Rules→Skills→Custom Agents→Plugin，匹配复用频率/分享需求）；③让沉淀自动生效（When→Do→Output，只自动化已验证流程，回扣 C3）；④不必从零开始（社区搜→评估→适配→使用，不评估=搬坑）；⑤真正竞争力=你积累的可复用经验，飞轮动力永远来自你主动那推。
- **方法论终点是用起来（诚实边界）**：方法论本身不产生价值，用它解决真实问题才产生——看懂飞轮原理 vs 亲手把飞轮推过最沉第一圈是两回事。→ 衔接**模块 D：通用场景实练**（D1 数据分析、D2 应用开发），把沉淀资产放进真实任务反复锤炼。从"理解 AI"(A)→"会用工具"(B)→"掌握方法"(C)→"实战练手"(D) 完成认知到能力闭环。

## ⑤ Demo 插槽设计（方法论骨架 + 任务场景 + 评判标准）

> 红线：3 实操基于 TRAE/SOLO 真实表现，多窗口模拟；具体文本/输出/配置片段标 `[占位·待用户设计]`；AI 输出真实不虚构（Rules 路径 `.trae/rules/`、Hooks 配置 `.claude/settings.json` 以授课时工具实际界面为准）。每个实操至少覆盖 CS（TRAE IDE）+ 通用（SOLO）两方向，第 3 方向可选；每 Demo 控 5-10min，保持"沉淀一次→复用/验证一次"最简粒度。

- **实操1：从"踩坑"到"Rule"（嵌章3·触发式沉淀最小闭环，建议重点完整演示）**
  - 方法论骨架：定位一个会重复出现的坑 → 写成一条清晰约束（本质即 C1 约束声明，写成永久规则）→ 存入规则文件设"始终生效" → 开新对话（不提醒）验证 AI 是否自动遵守。评判：全新对话未经提醒 AI 自动遵守；若仍犯→回扣 C1 约束要具体可执行，回去改。
  - Demo A（CS/TRAE）：AI 写代码总忘加错误处理/总用禁用库 → 把"所有函数须含异常处理、文件读写须处理文件不存在"写入 `.trae/rules/` 设始终生效。
  - Demo B（经管/SOLO）：AI 写报告总不标数据来源/爱用夸张营销腔 → 把"每个数据后标来源与年份、不确定标[待核实]、客观中性措辞"写成 SOLO 自定义规则。
  - Demo C（理工/人文·可选）：理工=AI 整理实验数据漏单位/有效数字不统一 → "数值须带单位、统一保留 N 位有效数字"；人文=AI 解读文献编造引用（回扣 A2 Hallucination）→ "只引我提供材料、不确定标[待核实]"。

- **实操2：设计一个 Automation（Hooks 形态 / 通用 Automation）（嵌章4）**
  - 方法论骨架：选高频低变异且已手动跑通的任务（此判断比设计重要，回扣 C3）→ 拆 When→Do→Output → 配置触发执行 → 想一步"万一出错影响多大"（影响大则留人工确认节点）。评判：①三要素齐全清晰；②能说清为何值得自动化（高频+低变异+已验证）；③为可能出错留兜底。若选"没跑通/每次都不同"的任务→不该自动化，重选。
  - Demo A（CS/TRAE·Hooks）：AI 写完代码你总手动跑 lint/测试（高频低变异已验证）→ 配 PostToolUse Hook 匹配"写文件"自动 `eslint --fix`+跑测试；配 PreToolUse 拦截危险命令（如 `rm -rf`）讲清拦截 vs 通知区别 + 安全风险。
  - Demo B（经管/SOLO·通用）：每周一手动汇总上周日志整周报 → 定时任务 When(周一早9点)→Do(读日志按模板汇总)→Output(周报草稿存文档+提醒 Review)；**关键：保留人工 Review 节点不直接发出**（呼应高影响动作留人工节点）。
  - Demo C（理工/人文·可选）：定时查某数据源/文献库更新，有更新自动生成摘要告警。

- **实操3：去社区找一个 Skill 并适配（嵌章5·站别人肩膀上）**
  - 方法论骨架：针对真实需求搜现成 Skill/模板/Rules → **评估**（质量?适合我场景?安全风险?）→ 基于评估二次修改适配 → 跑真实任务验证（回扣 C3 别人东西用前也验证）。评判：未直接照搬，经评估且至少一处有理据的适配修改并验证有效；若"搜到就用"= 本实操要纠正的反面。
  - Demo A（CS/TRAE）：搜"code review" Skill → 评估审查维度是否齐全/适合语言栈 → 适配（加团队命名规范、删不相关项）→ 审真实代码验证。
  - Demo B（经管/SOLO）：Prompt 社区找分析报告模板 → 评估维度贴合行业/措辞口径 → 适配（换行业维度、调术语）→ 做真实分析验证。
  - Demo C（理工/人文·可选）：找学科相关工作流模板（实验报告结构/文献综述框架）→ 搜→评估→适配→验证。

## ⑥ 常见误区 / 边界

- 不重讲被沉淀对象：C1 Prompt 写法、C2 拆解方法论、C3 验证策略、C4 多 Agent 编排仅作案例引用。
- 反例：不沉淀成 Rule 每次手敲约束；每次竞品分析重拆流程；存了沉淀但"存了不用"（死档案馆）。
- 工具记忆误区：自动记忆是黑盒、替你决定记什么，≠ 主动白盒沉淀（类比相册备份≠作品集）；直接拿来别人沉淀不评估=把坑搬进来。
- 判断标准误区：别什么都留——只留"会重复出现、有复用价值"的；与"什么值得自动化"同理（区分重复 vs 一次性）。
- 自动化误区：自动化没跑通的流程会放大错误（C4 Anthropic 50 子 Agent 故障）；Hooks 以用户权限执行任意 shell，须信任来源（安全红线）；高影响动作留人工节点。
- Plugin/MCP 误区：不做安装/配置教学（超 C5 范围）；Plugin 是最高形态=可分发能力包，解药 tribal knowledge，但只讲"是什么/为什么"。
- 飞轮误区：飞轮不会自己转，动力永远来自人主动那推；须扛过"最沉第一圈"（头几条 Rule/Skill 似无省事）才到惯性临界点；跳不出=困在 doom loop。

## ⑦ 与模块 C 其他单元及 A/B/D 的衔接（回扣点）

- **模块内闭环**：C1 说清楚 → C2 拆明白 → C3 验对了 → C4 编排好 → C5 沉淀住（五课成环）。
- **← C1-C4**：C1 好 Prompt 是 Rules 雏形；C2 拆解范式是 Skills 内容；C3 验证规则是自动化沉淀对象；C4 编排经验是 Custom Agents/Plugin 素材。
- **原理锚点回扣**：A1/A2（Agent+MCP）、A2（单会话记忆/上下文学习/角色激活）、A3（工具不是同事/外部记忆/视野）；C2→C3→C5 中间产物三课红线。
- **→ D 模块**：章7 衔接"真实战场"——把沉淀资产用于 D1 数据分析、D2 应用开发真实场景练手。
- **Meta 案例闭环**：本课程本身即沉淀资产（共性约束、交付要求、各课模板），印证"飞轮"不只理论。

## 模块 C 教学速记（授课者可直接调用）

- **一句话主线**：把 A3 的「Architect vs Executor」拆成五步可操作方法论——说清楚→拆明白→验对了→编排好→沉淀住。
- **C1 好 Prompt 五要素**：Role / Task / Constraints / Examples / Format（按需选用）；CoT 是"旋钮不是默认值"；关键数据 CoT(GSM8K 17.9%→56.9%)、futurefactors(弱 60%→结构化 95%)。
- **C2 拆解**：先粗拆→看表现→细拆（迭代式）；中间产物"自包含、有验收标准、持久化落盘"；领域范式（CRISP-DM 43% 采用率 / V模型 / 金字塔原理 / Double Diamond）；Least-to-Most(SCAN 16%→99.7%)。
- **C3 验证四层**：事前约束→事中审查→自动化验证→事后审计；按风险定力度；Air Canada 判赔 812 加元、NASA 自动化偏差 75% vs 25%、LLM-as-a-Judge 一致率 >80% 但终审在人；四大认知偏差（流畅度/锚定/确认/专家盲区）。
- **C4 多 Agent**：架构(Subagents/Teams/Dynamic) × 编排(串行/并行/交叉审查) 正交两维；契约先行（接口/格式/约束）；混合调度（HITL 的 APXML）；MAST 失败率 41%-86.7%（引入验证机制后显著下降）、~15× token 消耗。
- **C5 沉淀四级**：Rules→Skills→Custom Agents→Plugin；飞轮=触发式沉淀+自动化生效+社区复用。
- **贯穿四理念**：Architect vs Executor、Trust but Verify、Flywheel、Jagged Frontier——与模块 A/B/D 共用同一套隐喻与术语。

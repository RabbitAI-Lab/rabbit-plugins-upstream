# 模块 E · 专业应用层（按专业适配）教学参考

> 本文件补全「课程架构总览」的 **第二部分 专业应用层**。定位：**方法论框架与工具支持由本技能提供，专业深度内容由院系教师主导补充**（模块化、欢迎共建）。
> 适用对象：已完成「第一部分 通用基座层（A/B/C/D）」的全专业学生；授课者在开专业应用层前，先读本节选定本院系条目，再套入本专业数据集/案例。
> 统一隐喻与术语沿用 SKILL.md：Architect/Executor、施工图纸=Prompt、飞轮、锯齿边界。

---

## 总览：为什么需要专业应用层

- **第一部分 通用基座层**给所有专业统一的"与 AI 协作"能力：理解 AI（A）、会用工具（B）、掌握方法论（C）、能跑通通用实练（D）。
- **第二部分 专业应用层**让这套能力**落到你的专业里**：同样的 C1-C5 招式，在计算机是"写代码/调 Bug"，在经管是"做竞品分析/读财报"，在人文是"做文献综述/文本分析"，在理工是"处理实验数据/写论文"，在艺术是"发散创意/出设计稿"。
- **核心判断（回扣 A3）**：AI 是通用工具，不是专业同事；它不懂你的学科语境、行业黑话、领域数据格式。**专业应用层 = 你用 Architect 身份，把通识方法论"翻译"成本专业的可操作流程**——这翻译本身就是该专业的 AI 素养。

---

## 适配总原则（所有专业通用）

| 维度 | 规则 |
|---|---|
| **工具路径** | 计算机/软件工程方向 → B1 TRAE IDE（写代码为主），可辅以 SOLO；其他所有专业 → B2 TRAE Work·SOLO（对话式协作）。两者都承接后续 C/D。 |
| **模块 C 通用** | C1-C5 方法论**全专业通用**，不因专业改变——变的只是"用在什么任务上"。 |
| **模块 D 通用实练** | D1 数据分析、D2 应用开发**全专业都要练**，但案例按专业替换（见下）。 |
| **数据/素材** | 各专业用**本专业真实数据集/文献/行业资料**训练（公开数据集、课程作业、院系数据库），避免用与专业无关的玩具例子。 |
| **验证纪律** | 专业场景错误代价更高（如错误财报结论、错误实验解读）→ **C3 验证力度要加码**，优先交叉审查 + 领域专家（教师）终审。 |
| **沉淀复用** | 各专业把"本专业高频 Prompt 模板 / 分析框架 / 验证清单"沉淀为 Rules/Skills（C5），形成**专业专属飞轮**。 |

## 五大专业适配指南

> 每条含：典型场景 / 推荐工具路径 / 与模块 C 招式映射 / 数据·素材来源 / **教师需补充的专业内容**。

### E1 · 计算机 / 软件工程
- **典型场景**：代码生成与补全、Bug 调试与修复、代码重构与评审、单元测试编写、脚本自动化、技术文档。
- **工具路径**：B1 TRAE IDE（主力）；SOLO 辅助写文档/需求。
- **模块 C 映射**：
  - C1：用 Role="资深 X 语言工程师"+ 约束（类型注解/错误处理/命名规范）写代码 Prompt。
  - C2：把"实现某功能"拆成"接口定义→核心逻辑→异常处理→测试"子任务。
  - C3：**高强度验证**——自动跑 lint/单测（Hooks 自动化，见 C5），人工 Review 边界与安全问题。
  - C4：多 Agent 写代码（一个写、一个审、一个测）；用 Custom Agent 固化"代码审查员"。
  - C5：把团队代码规范写成 `.trae/rules/`；把"竞品分析/技术调研"流程封装 Skill。
- **数据·素材**：课程项目代码库、LeetCode/真实业务需求、开源仓库。
- **教师补充**：本院系技术栈规范、作业评分的代码质量标准、生产级工程红线（安全/性能）。

### E2 · 经管 / 社科
- **典型场景**：竞品分析、行业研究、市场/用户调研报告、财报与经营数据解读、问卷数据分析、商业计划书。
- **工具路径**：B2 TRAE Work·SOLO（主力，对话式）。
- **模块 C 映射**：
  - C1：Role="行业分析师"，约束"只用给定材料、客观中性、数据标来源年份、不确定标[待核实]"。
  - C2：把"分析某行业"拆成"市场规模→竞争格局→驱动因素→风险"子问题（金字塔原理）。
  - C3：交叉核对数据口径；警惕 AI 编造来源（回扣 A2 Hallucination）；结论区分"相关≠因果"。
  - C4：多 Agent 做"资料收集 Agent + 分析 Agent + 质检 Agent"协作。
  - C5：沉淀"竞品分析模板""财报解读清单"为 Skill/Rules。
- **数据·素材**：公司年报、行业研报、Wind/国家统计局公开数据、问卷结果。
- **教师补充**：本院系分析框架（如波特五力/PEST）、行业数据库权限、报告评分的论证标准。

### E3 · 人文社科（文史哲 / 语言学 / 传播等）
- **典型场景**：文献综述、文本/话语分析、论文提纲与写作、史料整理、观点辨析、翻译辅助。
- **工具路径**：B2 TRAE Work·SOLO。
- **模块 C 映射**：
  - C1：Role="严谨的 X 学研究者"，约束"只引我提供的文献、不虚构引用、标注出处"。
  - C2：把"写文献综述"拆成"确定问题→检索归类→对比流派→形成论点"。
  - C3：**重灾区验证**——AI 易编造不存在的文献（回扣 A2 Hallucination）；必须逐条核对引文真实性；观点类结论需人工判断立场偏差。
  - C4：多 Agent 做"文献归纳 + 批判性质检 + 格式校对"。
  - C5：沉淀"引文规范""综述结构模板"为 Rules。
- **数据·素材**：课程必读书目、期刊数据库、一手史料/语料。
- **教师补充**：本院系引文规范（APA/MLA 等）、核心文献清单、学术不端红线。

### E4 · 理工科（数理化 / 生环 / 材料等）
- **典型场景**：实验数据处理与可视化、科研图表绘制、文献调研、论文方法与结果写作、数值计算脚本、仿真参数分析。
- **工具路径**：B2 TRAE Work·SOLO（数据处理/写作）；计算机背景可加 TRAE IDE 写计算脚本。
- **模块 C 映射**：
  - C1：Role="严谨的科研助手"，约束"数值带单位、有效数字统一、只基于给定数据"。
  - C2：把"分析实验"拆成"数据清洗→统计检验→作图→解读"。
  - C3：**单位/有效数字/统计方法验证**是重点；警惕 AI 把相关当因果、误用检验方法；公式推导需人工核对。
  - C4：多 Agent 做"数据整理 + 统计 + 图表"分工。
  - C5：沉淀"实验报告结构""数据处理流程"为 Skill/Rules。
- **数据·素材**：实验原始数据（CSV）、公开科研数据集、文献库。
- **教师补充**：本院系统计规范、实验伦理、论文图表标准、领域专属陷阱。

### E5 · 艺术与设计
- **典型场景**：创意发散与头脑风暴、设计调研、视觉/交互方案草拟、作品集文案、用户画像与场景构思。
- **工具路径**：B2 TRAE Work·SOLO（对话式创意协作）。
- **模块 C 映射**：
  - C1：Role="资深 X 设计师"，约束"给出 3 个差异化方向、说明取舍、不替代最终审美判断"。
  - C2：把"做设计方案"拆成"需求理解→风格探索→方案迭代→评审标准"。
  - C3：验证"AI 给的方案是否贴合 brief、是否抄袭雷同、是否可落地"——审美与原创性终审在人。
  - C4：多 Agent 做"趋势调研 + 概念生成 + 批判性评审"。
  - C5：沉淀"品牌调性词表""方案评审 checklist"为 Rules。
- **数据·素材**：brief、参考作品集、用户调研、情绪板。
- **教师补充**：本院系审美标准、原创性要求、专业工具链（Figma/Midjourney 等）衔接。

## 专业应用层 · 总论 / 导学（开课第一节设计）

> 建议各专业在正式进入本专业案例前，先用 **15–20 分钟** 做一次"总论"对齐，讲清"通识方法论如何落到你的专业"。完整逐字稿见 `references/lecture-script-professional-orientation.md`。

- **目标**：让学生建立"我是 Architect，AI 是通用 Executor；专业壁垒在我这里，不在 AI 那里"的认知。
- **三句话收束**：① 通用基座层给你"会协作"的能力；② 专业应用层让你"用协作解决专业问题"；③ 你的专业判断（验证、取舍、原创性）是 AI 替代不了的，也是你最该练的。

## 与第一部分（通用基座层）的衔接

- **← A1-A3**：专业场景错误代价高，更凸显"信任但验证""锯齿边界"——AI 在你的专业里同样会翻车，且翻得更隐蔽。
- **← B1/B2**：工具路径按专业选（上表）。
- **← C1-C5**：招式不变，任务替换；专业应用层是 C/D 的"真实战场版"。
- **→ 飞轮**：每个专业沉淀的 Rules/Skills 越积越多，形成**专业专属飞轮**——这是专业应用层最长期的产出。

# L4 自动化调度层（V7.0 核心 · 调度契约）

> 本文件是 V7.0 的「L4 心脏」。它把 V6.0 的**请求驱动工作流**（你说一句它才跑）升级为**时间驱动自动化**（到点自己跑、跨会话记得住、重复触发不重复产出）。
>
> **设计哲学**：V6.0 解决了「**怎么把事做对**」（8 阶段管线 + 自动实测）；V7.0 解决「**怎么让它在没人的时候也做对**」（调度注册 + 自包含指令 + 幂等 + 跨会话状态 + 留痕审计）。

---

## 0. L4 的判据（先自检，别自欺）

一个能力是否真到 L4，看这 5 条。**缺一条都只是"L3 + 一份写着 cron 的文档"**：

| # | 判据 | 不达标的表现 |
|---|------|-------------|
| 1 | **已注册进宿主调度系统**（真实 cron 任务存在） | 只在文档里写了"每周一执行" |
| 2 | **无人值守可跑完**（automation 会话里不提问、不等待） | 跑到一半问用户"要不要继续" |
| 3 | **跨会话记得住状态**（上次跑到第几周、第几期） | 每次执行都从第 1 期重来 |
| 4 | **重复触发不重复产出**（幂等） | 重试一次就多推一篇速递 |
| 5 | **有留痕可审计**（执行台账） | 跑没跑、成没成，无从查证 |

> 本技能 V7.0 提供达成这 5 条的**完整契约与模板**；真正的"已注册"需由用户在确认预览后执行注册命令（见 §8）。

## 1. 调度契约三要素

注册一个自动化任务，本质只有三件事（对应 `automation-task-manager/scripts/scheduler-api.sh`）：

| 要素 | 说明 | 约束 |
|------|------|------|
| **Cron** | 何时跑 | 6 位 `秒 分 时 日 月 周`，**秒固定为 0**；最小间隔 1 分钟，严禁秒级 |
| **Prompt** | 跑什么 | ⭐ **必须自包含**（见 §2），automation 会话无历史上下文 |
| **frequency-type** | 频率类型 | `daily`（每天/每周X/工作日）/ `interval`（每X分钟|小时）/ `once`（单次） |

**默认配置**：时区 `Asia/Shanghai`；超时 `300s`（生成类建议 `900`）；重试 `3` 次（建议课件/游戏生成设 `2`，避免重复产出风险）。

### Cron 速查（本技能常用）

| 场景 | Cron | 人类可读 | frequency-type |
|------|------|----------|----------------|
| 每工作日 08:30 速递 | `0 30 8 * * 1-5` | 工作日每天 08:30 | `daily` |
| 每周一 08:00 推进周包 | `0 0 8 * * 1` | 每周一 08:00 | `daily` |
| 每周五 17:00 教研组周报 | `0 0 17 * * 5` | 每周五 17:00 | `daily` |
| 每月 1 号 09:00 月度盘点 | `0 0 9 1 * *` | 每月 1 号 09:00 | `daily` |
| 开班日 T0 启动（一次性） | `0 0 9 5 9 *` | 9月5日 09:00 | `once` |
| 考前 1 天 19:00 提醒 | `0 0 19 14 1 *` | 1月14日 19:00 | `once` |

## 2. ⭐ 自包含指令契约（V7.0 最关键设计）

### 为什么必须自包含

调度系统触发任务时，会在**一个全新的 automation 会话**里执行 `prompt`。这个会话：

- ❌ **没有**本次对话的历史上下文
- ❌ **没有**用户刚才说过的话
- ❌ **不知道**你上次跑到第几周

所以**"帮我继续上周的进度"这类指令在自动化里是无效的**——它读不到"上周"。

### 铁律

> **调度指令（prompt）必须自带完成任务所需的全部信息**：角色、会话约束、任务定义、状态读取位置、幂等键规则、执行步骤、验证要求、产出落点、留痕动作、失败动作。缺一即视为不合格指令，禁止注册。

### 标准模板（见 `assets/self-contained-prompt-template.md`）

```
【角色】你是 AI 通识课资深专家 V7.0，运行在 L4 自动化模式。
【会话】CODEBUDDY_SESSION_TYPE=automation：
        · 严禁加载/调用 automation-task-manager（不得自己管理调度）
        · 不得向用户提问或等待确认，遇决策点按预设缺省执行并记入待办
【任务】<任务ID> · <一句话目标>
【状态】先读取状态源（见 §3），取 <task>.cursor / lastRun；缺失则用初值 <初值>
【幂等】计算 idempotency_key = "<task>:<周期标识>"；
        若台账中已存在该 key 的成功记录 → 直接退出，不重复产出
【执行】按 references/automation-ops.md <OPS-x> 执行：<步骤摘要>
【验证】<VERIFY 要求：课件/游戏类必须跑 playwright-control-test-harness.js>
【落点】<产出写到哪：IMA 知识库 / 腾讯文档 / 备忘录 / 日历 / 闹钟>
【留痕】把 {idempotency_key, ts, status, 产物位置, 耗时ms} 追加到台账，并回写 cursor
【失败】遇阻断 → 写备忘录告警 + 台账记 failed + 退出码 0（不阻塞调度）；
        重试交由调度系统按 retryCount 处理，业务层不自行重试
```

## 3. 跨会话状态持久化（三层存储）

automation 会话之间不共享内存，**状态必须落盘**。按可靠性分三层：

| 层 | 载体 | 用途 | 可靠性 |
|----|------|------|--------|
| **L1 缓存** | 本地状态文件 `<宿主工作目录>/.ai-literacy-state/<task>.json` | 快速读写，单次会话内加速 | 低（沙箱可能重置） |
| **L2 主存** ⭐ | **IMA 知识库**《AI教学·自动化状态》文档 | 跨会话、跨设备的**权威状态** | 高（云端持久） |
| **L3 语义** | WorkBuddy **记忆库**（memoryLibrary） | 长期偏好、学生画像、教学语义记忆 | 高（语义检索） |

> **路径规则**：`<宿主工作目录>` = 执行时 AI 的**当前工作目录**，运行时解析（Linux/macOS 常见 `/workspace`，Windows 为对应工作区目录）。**禁止硬编码绝对前缀**（如写死 `/workspace/...`），否则在非该平台的宿主上 L1 缓存会静默失效。

> **铁律**：automation 会话**必须以 IMA（L2）为权威状态源**，本地文件（L1）只作缓存。只写本地文件 = 状态会丢 = 每次都从第 1 期重来（判据 3 不达标）。

### 状态文件结构

```json
{
  "schema": "ai-literacy-state/v1",
  "task": "OPS-1",
  "updatedAt": "2026-08-28T17:53:00+08:00",
  "cursor": { "week": 2, "module": "C1", "issue": 5 },
  "lastRun": { "ts": "2026-08-28T08:00:00+08:00", "status": "success", "key": "OPS-1:2026-W35" },
  "nextRun": { "expect": "2026-09-04T08:00:00+08:00" },
  "context": { "audience": "BNBU新生", "difficulty": 2, "bnbu": true },
  "stats": { "produced": 8, "failed": 0 }
}
```

## 4. 幂等设计（判据 4）

自动化最隐蔽的坑：**调度重试 / 手动补跑 / 重复注册 → 重复产出**（推了两篇速递、建了两份教案）。

### 幂等键规则

```
idempotency_key = "<task>:<周期标识>"

周期标识：
  · daily / 工作日类 → 日期 ISO 周或日，如 OPS-2:2026-08-29
  · weekly 类       → ISO 周，如 OPS-1:2026-W35、OPS-4:2026-W35
  · once 类         → 任务自身，如 OPS-3:final-exam-2026-01-15
```

### 执行前必做

1. 读台账（见 §5），查 `idempotency_key` 是否已有 `status=success` 记录。
2. **有** → 直接退出（记一条 `skipped` 日志），绝不重复产出。
3. **无** → 正常执行，成功后写 `success` 记录。

> **注意**：调度系统的 `retryCount` 重试可能发生在任务**已部分成功**之后。因此**写台账必须早于不可逆副作用**（如先记台账再落库/分享），或确保落库动作本身幂等（如腾讯文档用「按标题查找→存在则更新，不存在则新建」）。

## 5. 执行台账（判据 5 · 审计留痕）

每次自动化执行都必须留痕。台账为 **JSONL**（每行一条，便于追加）：

```jsonl
{"key":"OPS-2:2026-08-29","task":"OPS-2","ts":"2026-08-29T08:30:12+08:00","status":"success","durationMs":42180,"artifacts":["IMA://AI每日速递/2026-08-29"],"notes":""}
{"key":"OPS-1:2026-W35","task":"OPS-1","ts":"2026-09-04T08:00:03+08:00","status":"success","durationMs":126400,"artifacts":["课件W2","游戏W2","自测W2"],"notes":"cursor.week=2"}
{"key":"OPS-2:2026-08-30","task":"OPS-2","ts":"2026-08-30T08:30:05+08:00","status":"skipped","durationMs":120,"artifacts":[],"notes":"幂等命中，周期已执行"}
{"key":"OPS-3:final-2026-01-15","task":"OPS-3","ts":"2026-01-14T19:00:09+08:00","status":"failed","durationMs":9100,"artifacts":[],"notes":"IMA 未授权，已写备忘录告警"}
```

模板见 `assets/run-ledger-template.jsonl`；任务台账见 `assets/automation-registry.json`。

## 6. automation 会话行为铁律（5 条）

当 `CODEBUDDY_SESSION_TYPE=automation` 时，本技能**强制**遵守：

1. **禁自管理**：绝对不加载 / 调用 `automation-task-manager`。自动化会话是**执行态**，不是**管理态**。
2. **不提问、不阻塞**：不得向用户提问或等待确认。遇决策点 → 用预设智能缺省（见 `workflow-orchestrator.md` §3）执行，并把待确认项写入备忘录。
3. **先读状态、再执行、后回写**：执行前读 IMA 状态；执行后回写 `cursor` / `lastRun` 并追加台账。
4. **幂等优先**：先算 `idempotency_key` 查台账，命中成功记录即退出。
5. **留痕 + 降级**：成功写台账；失败写台账 `failed` + 备忘录告警，**退出码 0**（不阻塞调度系统），业务层不自行重试。

> **为什么失败也要退出码 0**：调度系统按退出码判定成败并触发 `retryCount`。业务层若返回非 0 会引发调度重试；若业务已降级处理完毕（如已写告警），应返回 0 避免无效重试风暴。**真正的失败信息记录在台账 `status=failed` 中**，而非靠退出码表达。

## 7. 授权、安全与配额

| 项 | 规则 |
|----|------|
| **授权优先** | 任何 IMA / 腾讯文档写入前确认授权；未授权 → 降级为「本地生成 + 备忘录给出操作指引」，台账记 `failed` |
| **最小打扰** | 自动化默认「静默生成 + 关键节点 1 条提醒」；可设「仅周报」「全静默」 |
| **不越权** | 不自动发邮件、不外发敏感信息；分享范围限班级/备课组（回扣 F2 隐私、商用标准 §6） |
| **配额** | 调度任务上限 **100 个**；本技能建议控制在 **≤ 10 个**（4 个 OPS + 若干课程周期任务），注册前先 `list` 查余量 |
| **超时/重试** | 生成类（课件/游戏/备课）`--timeout 900 --retry-count 2`；提醒类 `--timeout 300 --retry-count 3` |

## 8. 注册 / 查询 / 更新 / 注销（真实命令）

> ⚠️ **写操作必须先预览、经用户确认后再执行**（`automation-task-manager` 的《操作确认协议》，最高优先级）。本技能**只负责生成预览与命令**，不擅自执行写操作。

### 创建（示意，须先经用户确认）

```bash
cd ~/.codebuddy/skills/automation-task-manager
./scripts/scheduler-api.sh create \
  --name "AI每日速递" \
  --cron "0 30 8 * * 1-5" \
  --prompt "$(cat ops2-prompt.txt)" \
  --frequency-type "daily" \
  --description "OPS-2 · V7.0 自动化：工作日 08:30 生成 1 篇 AI 前沿速递 + 1 道练习题" \
  --timeout 900 --retry-count 2
```

**必填**：`--name` `--cron` `--prompt` `--frequency-type`
**可选**：`--description` `--timezone` `--timeout`(10-1800) `--retry-count`(≤10) `--effective-start` `--effective-end`

### 查询 / 更新 / 注销

```bash
./scripts/scheduler-api.sh list --keyword "AI教学"     # 只读，无需确认
./scripts/scheduler-api.sh get --id 123                # 只读，无需确认
./scripts/scheduler-api.sh update --id 123 --status 0  # 暂停（须先 get + 预览 + 确认）
./scripts/scheduler-api.sh delete --id 123             # 删除（须先 get + 预览 + 确认）
```

### 注册后必做

把返回的 `id` 与任务元信息登记进 `assets/automation-registry.json`（任务↔OPS↔幂等规则 mapping），否则下次升级/迁移时无法定位与清理。

### 错误码

`INVALID_PARAM` / `TASK_NOT_FOUND` / `TASK_LIMIT_EXCEEDED`(超100) / `INVALID_CRON_EXPR`

## 9. 与 V6.0 的关系（不是替代，是外挂）

```
V6.0 管线（L3 请求驱动）：INTENT→PLAN→BUILD→VERIFY→ASSEMBLE→DELIVER→REPORT→LEARN
                                    ▲
                                    │ 复用同一套 BUILD/VERIFY/DELIVER
V7.0 调度（L4 时间驱动）：SCHEDULE ──┘
                            │
                            ├─ 注册 cron 任务（宿主调度系统）
                            ├─ 到点 → automation 会话 → 自包含 prompt
                            ├─ 读状态(IMA) → 幂等校验 → 跑 8 阶段管线
                            └─ 回写状态 + 台账留痕
```

> **一句话**：V7.0 = V6.0 的工作流 + **一个能自己点火的闹钟** + **一个记得住进度的本子** + **一套不重复干活的规矩**。

## 10. 第 14 维门控检查点（L4 调度门控）

任何自动化任务在注册前，必须通过（详见 SKILL.md 门控表第 14 维）：

- [ ] prompt **自包含**（含角色/会话约束/状态源/幂等键/步骤/验证/落点/留痕/失败动作）
- [ ] cron 合法（6 位、秒为 0、≥1 分钟）且已给出人类可读时间
- [ ] 幂等键规则已定义，且台账查重逻辑已写入 prompt
- [ ] 状态持久化落在 **IMA（L2）**，非仅本地文件
- [ ] automation 会话 5 铁律已写入 prompt（尤其禁加载管理技能、不提问）
- [ ] 超时/重试配置合理（生成类 900/2，提醒类 300/3）
- [ ] 已在 `automation-registry.json` 预留登记项
- [ ] 写操作已向用户展示预览并获确认（未确认禁止执行）

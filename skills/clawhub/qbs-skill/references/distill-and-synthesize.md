# 蒸馏与合成 · Distill & Synthesize

> ③的 source-notes 进入④三层提取+三重验证，产出方法单元；⑤按合约组装子 Skill。
> 全部逻辑自包含，不依赖外部技能。

## 第一部分 · ④蒸馏：三层提取 + 三重验证

### 一、提取范围（三层，为 QBS 场景定制）

| 层 | 提取什么 | 为什么必拆 |
|---|---|---|
| **L1 方法论骨架** | 决策框架 / 原则 / 清单 / 概念体系 / 操作步骤 | Skill 的 Core methodology 来源 |
| **L4 案例库** | 作者亲自用过的实例 + 应用场景 + 失败案例 | Instructions 的锚点；证明方法在真实场景跑过 |
| **L5 反模式与边界** | 作者反对的做法 + 适用条件 + 例外 + 局限 | 合约要求"条件与例外"；Honest boundaries 来源 |

不拆：讲解风格 DNA、作者心智模型（QBS 场景要方法不要人设）——标注"未拆解"；用户明确要全书级深度时才开（见第二部分路线 B）。

**提取要求**：每个候选单元标注来源位置（章/节/页）；核对作者的推理链与例外说明，不是只摘符合预想的句子。

### 二、三重验证（每个 L1/L5 候选单元必须全过）

| 验证 | 检查什么 | 防什么 |
|---|---|---|
| **V1 跨域** | 该单元在源文本中是否有 ≥2 处独立段落佐证（基于位置，非关键词碰巧相同） | 防"一句随口" |
| **V2 预测力** | 能否用它回答一个文本里没明说的新问题 | 防"装饰性方法" |
| **V3 独特性** | 是否含"非常识"特征——不是任何聪明人都会说的 | 防"废话" |

- 通过 → 进入方法单元表；不通过 → 写入排除记录并附原因（保留审计轨迹）。
- L4 案例必须有明确原文位置；L5 反模式必须有文本中的显式反对证据，不能推断。

### 三、方法单元七字段表（methods.md 产出格式）

每条通过验证的方法单元记录：

| 项目 | 要回答的问题 |
|---|---|
| 任务 | 具体解决哪类问题？（对应 question-spec 问题卡） |
| 来源 | 哪个版本的哪部分？（对应 source-notes 映射） |
| 条件 | 哪些事实成立时适用？什么情况下不适用？ |
| 操作 | 需要哪些输入，如何选择下一步？ |
| 交付 | 用户能检查的产物是什么？ |
| 失败 | 什么结果说明方法或使用条件有问题？ |
| 归属 | `[书]` / `[书→推]` / `[设计]`——三种身份是哪一种？ |

**不为填表扩写原文没有的理论。**

## 第二部分 · ⑤合成：子 Skill 合约

### 一、归属三分铁律

| 身份 | 判定 | 标记 |
|---|---|---|
| 来源概括 | 书里明说的 | `[书]` |
| 根据来源的推断 | 从正文合理推出（如把书中团队场景适配到个人场景） | `[书→推]` |
| 场景设计 | 为本任务添加（书里完全没有） | `[设计]` |

- `[设计]` 的规则不得归给作者；`[书→推]` 必须能指出推断所依据的原文位置。
- 不同来源有分歧时**保留条件**（各在什么条件下成立），不强行合成万能规则。

### 二、组装双路线

**路线 A：章节级轻量（默认，阅读范围 ≤3 章）** —— 直接按 4+1 模块组装子 SKILL.md：

```markdown
---
name: <skill-name>
description: <做什么+何时触发+Do NOT，触发词前置，≤200字符>
---

# <Skill 标题>

## When to use（何时用/何时不用）
来自：L1 类型 + L5 边界 + question-spec 方法需求画像

## Core methodology（核心方法）
来自：L1 骨架的执行流程；按七字段的"任务/条件/操作"展开

## Instructions（执行细则）
来自：L4 案例库（作者亲用实例做锚）+ L5 反模式（何时停）

## Self-test（自检）
来自：验收契约——每次执行后对照试跑判定标准自检

## Honest boundaries（诚实边界）
来自：L5 边界 + 未读章节声明（"本 Skill 仅基于第 X 章，未覆盖 Y"）+ [设计] 规则清单
```

伴随文件：
- `references/source-notes.md`——阅读记录 + 方法-原文位置映射（七字段"来源"的凭据）
- `references/methods.md`——七字段方法单元表（方法多时拆出）

**路线 B：全书级深度（阅读范围 >3 章 / 用户要整本书）** —— 在路线 A 基础上扩展：
1. 增拆两层：讲解风格 DNA、心智模型（每个心智模型须能解释 ≥3 个 L1 单元，否则只是装饰）；
2. 增量萃取：跨域映射（选 3 个非源域测试结构同构性）、逻辑闭环检查（方法论↔心智模型↔案例↔反模式四组对子不矛盾）、泛化原则（从案例归纳通用原则，每个原则 ≥3 案例支撑）；
3. 产出物在路线 A 之上追加增量发现段。

### 三、status 分级

| 状态 | 达成条件 |
|---|---|
| `draft` | 未完成完整读章（只有序言/目录/残缺正文）——**保持草案身份，不得宣称书籍方法** |
| `simulated` | 完整读≥1个相关章节 + 规则有对应阅读依据 + 书籍卡完整 + 通过一次行为试跑 |
| `field-tested` | simulated 基础上 + 真实使用记录 + 可核验的适用范围 |

模板完整、文件格式通过**不提升状态**。故障修复保留变更与复测证据。

### 四、library 登记

产出 Skill 登记到本技能 `references/library.json`：

```json
{
  "id": "<book-slug>",
  "title": "<书名>",
  "author": "<作者>",
  "isbn": "<ISBN或空>",
  "skill": "<skill-name>",
  "skill_path": "<路径>",
  "scope": "<解决的问题一句话>",
  "reading_scope": "<实际读了哪些章节>",
  "source_url": "<正文入口>",
  "status": "draft|simulated|field-tested",
  "created": "<日期>"
}
```

### 五、交付自检（进入⑥前）

- [ ] 每条规则有归属标记，`[书]` 的能在 source-notes 映射里找到原文位置
- [ ] 诚实边界包含"未覆盖章节"声明
- [ ] Self-test 模块引用的是 question-spec 的验收契约（不是现编的）
- [ ] 试跑准备：验收契约里的试跑任务已明确，输入已具备

## 第三部分 · ⑥试跑回书

- **用①规格书里的验收契约**跑一个新任务（不是临时现编一个），保留输入和产物。
- 至少检查两条：一条来自正文的方法被正确用到任务里；不适用情形出现时 Skill 是否停止套用。
- 试跑失败 → 改规则再测；不能只交文件或只跑结构校验。
- **回书入口**：交付后用两三句话连回"这个判断改变了什么、出自哪章哪节"，附原文位置；挑一个值得继续追问的问题，让用户按兴趣接着读。不追加必读书单。

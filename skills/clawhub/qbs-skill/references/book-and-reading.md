# 找书与读章 · Book Funnel & Reading Discipline

> 输入：question-spec.md（领域关键词 + 方法需求画像 + 渠道约束）。
> 输出：book-decision.md（②）→ source-notes.md（③）。
> 原则：**不能只因为一本书容易下载就忽略相关性；不能只引用模型记忆或搜索摘要。**

## 第一部分 · 四层找书漏斗

### L1 · 本地书库检索（可用则用，不可用则跳过）

若当前环境有可用的电子书检索工具（本地书库 CLI / 缓存 JSON），用规格书「领域关键词」（中文主查、英文辅助、同义词扩展、排除词过滤）检索。命中 ≥2 本时做**七轴差异比对**，比对锚点是规格书的**方法需求画像**：

| 轴 | 问题规格书的对应锚 |
|---|---|
| 难度 | 问题卡里的用户对该领域的熟悉度 |
| 侧重 | 方法颗粒度（要流程的书，别选纯理念的） |
| 篇幅 | 深度预期（章节级找薄而专的，全书级才上大部头） |
| 口碑 | 卡点证据的严重程度（越痛越要经受过检验的方法） |
| 分类覆盖度 | 领域定位是否落在该书核心主题内 |
| 作者产出力 | 已试败项——避开与失败路线同源的作者 |
| 主题热度 | 是否需要当代实践，还是经典即可 |

漏斗收敛到 **2-4 本候选**。

**降级规则**：本地书库工具不可用/无命中/命中质量低时，直接进入 L2，不阻塞。

### L2 · 网络核验兜底

以下任一情况触发网络搜索核验（用环境中可用的搜索/网页抓取工具）：

- L1 无命中或候选都不满足选书三问第一问；
- 需要核验作者背景、出版社、权威书目、具体目录章节（**判断"哪章解决问题"必须看目录，不凭记忆**）；
- 规格书语言偏好为英文书为主。

核验对象：权威书单（大学课程/专业机构/公认大师推荐）、出版社页面、作者公开资料、开放目录。**搜索摘要与模型记忆只能当线索，不能当选书依据。**

### L3 · 选书三问（逐本回答）

1. **哪个章节可能解决用户的具体问题，为什么？**（依据目录与简介，写明章节名）
2. **这本书是否提供可以转成判断和行动的方法，而不只是概念介绍？**（有步骤/框架/清单才算）
3. **当前能否取得足够的相关正文，实际入口在哪里？**（本地可下载/公开章节/需用户提供/需购买）

三问有任一答不上来 → 该候选降级为备选。

### L4 · 决策与交接

产出 `book-decision.md`：

```markdown
# 找书决策 · <日期>

## 首选
- 书名/作者/版本/ISBN：
- 预选章节：<章节名 + 理由（对应问题卡哪条）>
- 入口：<本地书库/公开链接/用户文件>
- 选它而非备选的原因：<一句话，引用七轴比对或选书三问>

## 备选（按优先级）
1. <书名 + 一句话理由 + 未选原因>

## 决策依据快照
- 七轴比对结果：<表或简述>
- 选书三问逐问答案：<…>
```

向用户**简要说明首选书与预选章节后继续**找正文，不默认等用户再发一次"继续"。用户对首选书有异议时切换备选，不争辩。

**特殊情形**：

| 情形 | 处理 |
|---|---|
| 用户已指定书 | 保留其选择，跳过 L1/L2，只做 L3 核对（目录核验仍要做） |
| 用户已有电子文件 | 直接进入第二部分核验五项 |
| 所有渠道拿不到正文 | 如实报告缺口，换书需用户同意 |
| 多本书各覆盖一部分 | 允许首选+补充本，均过三问；总量控制在深度预期内 |

## 第二部分 · 取文读章纪律

### 一、取正文（按优先级）

1. **用户提供的文件**：直接用，核对版本与完整性。
2. **下载**：公开托管的电子书文件（PDF/EPUB），用环境中可用的下载能力获取。
3. **格式转换**：PDF 无文字层（扫描版）用环境中可用的 OCR 能力转文本；EPUB 按 zip 结构解析章节（可用通用脚本处理）；转换失败如实报告。
4. **公开渠道**：出版社或作者公开章节、开放教材、正规平台试读、已授权阅读入口。

**红线**：不得绕过访问限制；没有购买授权不下单，需要购买时把决定权交给用户。

### 二、可读性核验五项

| 项 | 检查 |
|---|---|
| 书名 | 与 book-decision 一致，防同名书/不同书 |
| 作者 | 一致，防版本混淆 |
| 版本 | 版次/ISBN/出版社——译本注意译者差异 |
| 目录 | 有目录，且预选章节确实存在 |
| 正文 | 正文文本实际可读（不是只有封面/目录/图片） |

**不算可读**：只有目录或序言；图片读不清；试读中途截断在预选章节之前；OCR 后乱码率过高。此时换入口重试；所有合理入口失败 → 停止，报告缺口。

### 三、完整读章纪律

- **至少完整读 1 个与任务直接相关的正文章节**，从章首到章末；长章节分段读但必须覆盖全程。
- ④蒸馏中发现某方法涉及其他章节 → 回来补读对应章节，**阅读范围必须与 Skill 能力范围相符**。
- 序言、目录、书评只作定位线索，**不作为方法依据**。
- 读时核对：作者的推理链、案例、适用条件、例外说明、关键图表——不是只搜几句符合预想的句子。

### 四、source-notes.md 阅读记录（必产出）

```markdown
# 阅读记录 · <书名>

| 记录 | 内容 |
|---|---|
| 书与版本 | 书名、作者、出版社、版本或 ISBN |
| 实际入口 | 公开链接或私有材料名称（公开交付物不泄露私人路径） |
| 已读范围 | 章节名 + 起止位置（页码/小节/定位链接），阅读日期 |
| 完整性 | 是否读到章末；缺页、截断、未读图表逐项列出 |
| 与任务的关系 | 本次用到哪些方法（对应问题卡哪条）；哪些能力尚无正文支持 |

## 方法-原文位置映射（供④⑤回填）

| 方法单元 | 原文位置（章/节/页） | 已核对的推理与例外 |
|---|---|---|
| <蒸馏时回填> | <…> | <…> |
```

- 网页无页码时用章节+小节+定位链接，**不编页码**。
- 阅读记录由**实际访问结果**填写，不在读之前预填"已完成"。

### 五、缺口诚实红线

- 一个入口只有序言或残缺试读时，继续找其他可信入口；确实拿不到 → 明确告诉用户缺哪本书哪几章，以及需要用户提供文件、访问或购买决定。
- **不得**把资料缺口改写成"读序言也足够"；**不得**把场景草案当作完成的书籍方法 Skill 交付。
- 用户指定的书读不到时，列出可选替代及理由，由用户决定，不悄悄换书。

### 反模式

- ❌ 找到书名就声称"已读相关章节"
- ❌ 用关键词捞几句就进入蒸馏（违反完整读章）
- ❌ 阅读记录预填模板后不回填实际数据
- ❌ 图表跳过、脚注跳过但完整性栏写"完整"

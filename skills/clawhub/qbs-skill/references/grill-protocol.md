# 拷问协议 · Grill Protocol

> 机制：设计树 + 前沿（frontier）轮次拷问。
> 目标：把用户模糊的痛点递归收敛成一份可直接驱动找书与试跑的**问题规格书**。每问一题的检验标准：**这个答案会不会改变选书或提炼？**

## 一、设计树：五个固定顶部分支

用户的初始问题挂在树根，五个顶部分支固定（分支为下游服务）：

| 分支 | 要收敛什么 | 直接服务谁 |
|---|---|---|
| **B1 问题解剖** | 现象 vs 根因 / 卡点证据 / 已试过什么且为何失败 | ②选书的"哪个章节解决它" |
| **B2 领域定位** | 问题属于哪个学科/实践领域 / 核心术语中英文 / 上位领域与相邻领域 | ②的检索关键词 |
| **B3 方法颗粒度** | 需要决策框架/操作流程/检查清单/心智模型？期望的 Skill 输出形态与使用者 | ④蒸馏的取舍 + ⑤合成的模块 |
| **B4 验收标准** | 用什么新任务试算成功？判定标准？出现什么情况判定方法不适用？ | ⑥试跑的验收契约 |
| **B5 正文可得性** | 用户已有书/文件？语言偏好？可接受的渠道（本地书库/公开章节/购买授权）？ | ②③的渠道约束 |

每个分支再往下生子节点。示例：B1 → "这是注意力问题还是优先级问题？" → （若答注意力）→ "被打断后重新进入状态的成本有多大？有实测数据吗？"

## 二、前沿(frontier)轮次制

**前沿 = 前置决策已全部落定的那些问题**——现在就能问、不用猜未听到的答案。

每轮的执行格式：

```
## 第 N 轮拷问（当前前沿）

❓ **Q1 - <问题标题>**：<问题正文，可含选项>
➡️ 推荐：<你的推荐答案 + 一句理由>

---

❓ **Q2 - <问题标题>**：<问题正文>
➡️ 推荐：<推荐答案>
```

**规则**：

1. **整批提问**：一轮把当前前沿上的问题全部问完（编号+推荐答案），然后等用户答复。
2. **答案重塑树**：用户每个答案都可能落定决策、解锁下游问题、或推翻上游假设。每轮结束重算前沿。
3. **依赖未定的问题不问**：一个问题若依赖本轮还在开放的问题，它属于后面的轮次。
4. **单问不拆轮**：不要一轮只抛一个问题把用户磨死；但也不要把依赖链上的问题提前混进同一轮。

## 三、事实与决策的分界

- **查事实是 Agent 的事**：「这个领域有哪些公认的经典书」「XX 概念的英文术语是什么」「某书的目录长什么样」——派搜索/子代理去查，查完把事实作为问题的背景摆出来。**绝不问用户任何你自己能查到的东西。**
- **做决策是用户的事**：选哪个根因解释、要框架还是清单、验收标准定多严——摆出事实和推荐答案，请用户定夺。

典型流程举例（Agent 先查再问决策）：
- 查：「关于委派/授权，管理领域常被引用的书有哪些？各自目录侧重？」
- 然后问决策：「你更想要偏心理机制的解释，还是偏流程模板的？」➡️ 推荐：按 B1 答案推断的那个。

## 四、入树检验：每个问题的价值门

提问前自问：**这个答案会不会改变选书或提炼？**

- 会 → 入树。
- 不会（纯寒暄、纯背景、答案对下游无影响）→ 不入树。
- 拿不准 → 归入"低优先"，前沿清空前再评估一次。

## 五、终止条件

拷问结束当且仅当：

1. **前沿为空**：五个分支的每条路径都走到叶子，没有任何静默假设。
2. **用户确认规格书**：把 `question-spec.md` 草稿展示给用户，明确问"这就是要拿去找书的问题规格吗？有没有要改的？"
3. 用户确认前不得启动②找书。

## 六、已知捷径

| 情况 | 处理 |
|---|---|
| 用户已指定书 | B5 大部分跳过；B2 只收敛到"这本书对应的问题域"；保留 B1/B3/B4 |
| 用户已有电子文件 | B5 直接记录文件路径，进入③核验 |
| 用户说"别问了直接做" | 把当前前沿上**所有**开放问题按推荐答案落定，在规格书"收敛记录"里标注"按推荐答案落定，未经用户确认"，再继续——但 B4 验收标准必须显式让用户过目一次 |

## 七、反模式

- ❌ 一轮问 20 个问题（没做依赖排序，用户答到一半树就变了）
- ❌ 问用户"XX 领域有什么书"（事实问题甩给用户）
- ❌ 前沿没清空就开始找书（静默假设会传染到选书）
- ❌ 规格书写完不展示就往下跑（缺确认门）
- ❌ 把拷问做成需求清单填表（失去递归收敛：每答重塑树才是收敛的来源）

## 问题规格书模板 · question-spec.md

> 拷问阶段的终点产物，**找书契约 + 验收契约二合一**。
> ②找书消费「领域关键词」与「方法需求画像」；⑥试跑消费「验收契约」。两处都不允许临时现编。

```markdown
# 问题规格书 · <问题一句话标题>

生成：<日期> | 拷问轮次：<N> 轮 | 状态：✅ 用户已确认 / ⚠️ 按推荐答案落定（未经用户确认）

## 1. 问题卡（B1 问题解剖）

- **现象**：<可观察的症状，用户原话优先>
- **根因假设**：<经拷问收敛的解释，区分"用户认定"与"待书验证">
- **卡点证据**：<具体场景、频次、损失——越具体越好>
- **已试过且失败**：<方法 + 失败原因，防止选书重复无效路线>
- **不属于**：<拷问中排除的相邻问题，防止选书跑偏>

## 2. 领域关键词（B2 领域定位）→ 直通②检索

- **主领域**：<学科/实践领域>
- **核心术语**：中文 <…> / 英文 <…>（选书与查目录用）
- **同义词/俗称**：<检索扩展用>
- **上位领域**：<放不下时的回退检索词>
- **排除词**：<检索时需排除的歧义词>

## 3. 方法需求画像（B3 方法颗粒度）→ 直通④蒸馏与⑤合成

- **颗粒度**：☐ 决策框架 ☐ 操作流程 ☐ 检查清单 ☐ 心智模型 ☐ 其他 <…>
- **期望输出**：Skill 每次调用交出什么（如：一份范围决定/一张排障步骤表）
- **使用者与场景**：<谁在什么情境下用这个 Skill>
- **深度预期**：章节级 / 全书级

## 4. 验收契约（B4 验收标准）→ 直通⑥试跑

- **试跑任务**：<一个具体的新任务，含输入描述>
- **判定标准**：<可检查的通过条件，逐条列出>
- **不适用即停**：<出现什么情况判定书中方法不适用本场景，Skill 应停止套用>
- **失败处置**：<试跑不通过时的修改预期：改规则再测 / 承认方法不适用>

## 5. 正文渠道约束（B5 可得性）→ 直通②③

- **已有书籍/文件**：<路径或书名，无则写"无">
- **语言偏好**：<中文优先/英文可接受/仅中文>
- **可接受渠道**：☑ 本地书库下载 ☑ 公开章节/开放教材 ☑ 用户提供 ☐ 需用户购买决定
- **明确排除**：<不接受盗版全文/不接受仅书评转述等>

## 6. 收敛记录

| 轮次 | 落定的决策 | 解锁的下游问题 |
|---|---|---|
| 1 | <…> | <…> |
| 2 | <…> | <…> |

- **开放问题**：<应为空；非空说明前沿未清空，不得进入②>
- **静默假设**：<应为空；凡静默假设必须升级为已确认决策或开放问题>
```

**填写纪律**：

1. **每个字段有下游消费者**——没有消费者的字段删掉，不要为了完整而填表。
2. 领域关键词必须中英双语：本地书库中文为主，权威书单核验英文为主。
3. 验收契约是⑥的法律：试跑只能按这里的任务与标准执行，现场改标准 = 回到①重新确认。
4. 状态为 ⚠️ 时，②③可继续，但进入⑤合成前必须补一次用户确认。

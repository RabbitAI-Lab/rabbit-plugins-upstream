# 反模式说明 — Anti-Patterns

## 反模式 1：期望"粘贴即用"

**错误做法：** 不配置任何环境变量，直接启动服务，然后抱怨"怎么不能用"。

**正确做法：** 
- 至少设置 `OPENAI_API_KEY`（或接受纯规则改写的降级效果）
- 确保 FFmpeg 已安装：`ffmpeg -version`
- 首次启动后先试一条短视频验证流水线走通

## 反模式 2：粘贴长的离谱的视频（>30分钟）

**错误做法：** 粘贴 2 小时的长视频/直播回放，期望 3 分钟内出结果。

**正确做法：**
- 工具针对 15 秒~5 分钟的短视频优化
- 长视频请先剪辑为关键片段（3 分钟以内最佳）
- 默认 Whisper base 模型，长视频转写速度是实时的 1/4~1/2

## 反模式 3：忽略改写质量

**错误做法：** 直接拿 AI 改写结果用，不检查事实准确性。

**正确做法：**
- 改写的本质是"换表达"，不保证事实正确
- 涉及到产品数据、时间、人名等时务必人工核对
- 改写后的文案应在预览区审阅后再生成视频

## 反模式 4：在纯 CPU 机器上跑完整 SadTalker

**错误做法：** 在没有 CUDA 的机器上安装 SadTalker，等了 10 分钟还在处理。

**正确做法：**
- CPU 模式下 SadTalker 极慢（> 10 倍实时时长）
- 无 GPU 时系统会自动降级为静态图 + 音频视频
- 需要高质量数字人 → 用云端 API (D-ID/HeyGen)

## 反模式 5：期望数字人完全"像真人"

**错误做法：** 用模糊的照片、侧脸照、戴墨镜的照片做 SadTalker 参考图。

**正确做法：**
- 需要正面、光线均匀、表情自然的半身/头像照
- SadTalker 的效果是"看起来像 AI 动画"，不是深度伪造
- 想要更真实 → Wav2Lip + 原视频唇同步
- 想要极高保真 → 云端付费 API

## 反模式 6：把未脱敏的敏感数据传到公共 API

**错误做法：** 用第三方 OpenAI 兼容 API 改写涉及商业机密、个人隐私的文案。

**正确做法：**
- 自部署 LLM（如 Ollama + 本地模型）或完全不使用 AI 改写
- 在 `.env` 中设置 `OPENAI_BASE_URL=http://localhost:11434/v1`
- 默认 edge-tts 是在本地完成的，不涉及数据外传

## 反模式 7：对同一链接反复提交

**错误做法：** 觉得"进度不动"就连续提交 5 次同一个链接。

**正确做法：**
- 每个任务约 1-3 分钟，前端会实时显示进度
- 每个步骤都有超时保护（120s~400s）
- 重复提交只会产生多个任务，浪费资源
- 查看单个任务的进度：`GET /api/tasks/{task_id}`

# 报错翻译官（error-translator）

> 把红字翻译成人话，告诉你先查什么。

## 它做什么

用户贴出技术报错时，用人话说明「程序在抱怨什么」，列出常见原因，并按排查成本给出下一步。

**不做**：代替完整调试（那需要看代码）。

## 触发词

- 这个报错什么意思 / 怎么修 / 为什么报错
- 看不懂这个错误 / 程序跑不起来
- 帮我看看这个 exception

## 它怎么做

- 三段固定结构：【人话】→【常见原因】→【先查这个】
- 人话用「谁卡在哪一步」的句式，不复述原文、不用术语解释术语
- 排查顺序按「5 分钟能验证」到「需改代码」到「需查外部依赖」
- 无法确定根因时明确标注不确定性

## 示例

> 用户：AttributeError: 'NoneType' object has no attribute 'xxx' 这是啥意思

```
【人话】
程序以为某个东西存在，去取它的属性，结果发现它是空的。

【常见原因】
① 变量还没赋值就被用了 —— 最常见
② 函数返回了 None，调用方却当成对象用
③ 字典的 key 不存在，用了 .key 而不是 .get()
④ 异步操作还没完成就去读结果

【先查这个】
1. 看报错行用了哪个变量
2. 在它前面加 print(type(变量))，看它到底是什么
3. 如果是 None，往上找它在哪被赋值

【不确定的】
日志里没带完整堆栈时位置可能不准——请补一段完整 traceback。
```

### 1. Product Matching Engine / 产品匹配引擎

> **⚠️ 以下代码为教学示例，展示产品匹配的方法论逻辑，不构成实际推荐。本 Skill 不执行这些代码；如需使用请在自己的环境中复制、改造并测试。** 实际产品匹配须基于持牌金融机构的合规系统和适当性管理要求。

#### 适当性匹配规则表（新增，先于代码理解）

| 客户风险偏好 | 可匹配产品风险等级 | 说明 |
|------------|-----------------|------|
| 保守型 | R1、R2 | 不得向其推荐 R3 及以上产品 |
| 稳健型 | R1、R2、R3 | R3 需额外揭示波动风险 |
| 平衡型 | R2、R3、R4 | R4 需确认客户理解最大回撤 |
| 成长型 | R3、R4、R5 | 需确认客户具备相应投资经验 |
| 激进型 | R4、R5 | 高风险产品需强制风险揭示 |

> 关键原则：**适当性校验是硬约束，优先级高于匹配度评分**。评分再高，若超出客户风险等级上限也必须剔除，不得作为"推荐排序靠前"的理由。

```python
class WealthAdvisor:
    """智能财富顾问（教学参考）"""

    def match_products(self, customer_profile: dict,
                      available_products: list) -> list:
        """
        智能产品匹配（教学方法论）
        Args:
            customer_profile: 客户画像
            available_products: 可选产品列表
        """
        # 风险匹配
        risk_level_map = {
            "保守型": ["R1", "R2"],
            "稳健型": ["R1", "R2", "R3"],
            "平衡型": ["R2", "R3", "R4"],
            "成长型": ["R3", "R4", "R5"],
            "激进型": ["R4", "R5"]
        }

        allowed_risk = risk_level_map.get(
            customer_profile.get("risk_preference", "稳健型"), ["R2", "R3"]
        )

        # 收益匹配
        expected_return = customer_profile.get("expected_return", 0.05)

        matched = []
        for product in available_products:
            # 风险等级过滤
            if product["risk_level"] not in allowed_risk:
                continue

            # 收益率匹配
            if product["expected_return"] >= expected_return - 0.02:
                score = self._calculate_match_score(
                    customer_profile, product
                )
                matched.append({
                    **product,
                    "match_score": score,
                    "recommendation_reason": self._generate_reason(
                        customer_profile, product
                    )
                })

        return sorted(matched, key=lambda x: x["match_score"], reverse=True)

    def _calculate_match_score(self, customer: dict,
                               product: dict) -> float:
        """计算匹配度评分（教学示例）"""
        score = 100

        # 期限匹配
        preferred_term = customer.get("preferred_term", 365)
        product_term = product.get("term_days", 365)
        term_diff = abs(preferred_term - product_term) / 365
        score -= term_diff * 10

        # 起购金额
        if product.get("min_amount", 0) > customer.get("available_fund", 0):
            score -= 30

        # 收益率
        expected = customer.get("expected_return", 0.05)
        actual = product.get("expected_return", 0)
        if actual >= expected:
            score += 10
        else:
            score -= abs(actual - expected) * 100

        return max(0, min(100, score))
```

**匹配过程示例（新增，用脱敏画像演示）**

> 客户画像：风险偏好"稳健型"、期望年化 4%、可投资金 30 万元、偏好期限 180 天。
> 可选产品（节选）：
>
> | 产品 | 风险等级 | 期限 | 起购 | 参考年化 |
> |------|---------|------|------|---------|
> | A 货币基金 | R1 | 活期 | 1 元 | 1.8% |
> | B 固收理财 | R2 | 180 天 | 1 万元 | 3.6% |
> | C 固收+理财 | R3 | 365 天 | 5 万元 | 4.5% |
> | D 混合基金 | R4 | 活期 | 1 万元 | 6.2% |
>
> 逐步推演：
> 1. **适当性过滤**：客户为稳健型，允许 R1–R3。产品 D（R4）**直接剔除**，即使收益最高也不得进入候选。
> 2. **收益阈值过滤**：期望 4%，阈值 4% − 2% = 2%。产品 A（1.8%）低于阈值被剔除；B、C 通过。
> 3. **评分**：产品 B 期限完全匹配（−0）、起购满足（−0）、收益略低于期望（3.6% vs 4%，−4）→ 约 96 分；产品 C 期限偏离半年（−5）、起购满足、收益达标（+10）→ 约 105 → 截断为 100 分。
> 4. **结果解读**：C 分数更高，但期限偏离客户偏好一倍。**不能只按分数排序就推给客户**，须在推荐理由中说明期限差异，由客户自主选择。
>
> 结论：匹配引擎输出的是**候选与排序建议**，最终推荐须叠加适当性确认、期限告知与人工复核。

**话术改写示例（新增）**

> 原表述："这款产品很安全，基本不会亏，收益比存款高不少。"
> 问题：①"安全""不会亏"构成变相保本承诺；②与存款直接对比属不当类比。
> 改写："这款产品风险等级为 R2，属于中低风险，主要投向债券等固定收益类资产，理论上仍存在净值波动和本金损失的可能，过往业绩不代表未来表现。它的预期收益通常高于同期限存款，但相应也需要您承担一定波动，建议您结合自身风险承受能力选择。"
> 校验：无保本承诺、有风险提示、无绝对化用语、未贬低存款。

| 揭示确认 | 风险揭示书须客户主动确认已阅读 | 未确认不得进入购买流程 |
| 人工复核 | 大额、高风险、老年客群交易转人工复核 | 复核通过后方可成交 |
| 留痕归档 | 保存推荐依据、客户确认与复核记录 | 缺失留痕视为流程不完整 |

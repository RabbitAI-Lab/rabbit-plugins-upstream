# 经验萃取与课程开发参考框架

仅在需要深度萃取、案例、练习或题库时读取本文件。不要把所有模板一次性展示给使用者。

## 一、判断资料

### 1. 资料类型

| 类型 | 主要内容 | 推荐入口 |
|---|---|---|
| 事件型 | 项目复盘、访谈、成功或失败案例 | STAR 事实还原 |
| 流程型 | 岗位流程、操作手册、制度规范 | 任务与流程拆解 |
| 观点型 | 理论文章、方法论、专家观点 | 概念、原则与场景 |
| 知识型 | 产品知识、政策合规、知识科普 | 学习目标与应用判断 |
| 课程型 | 旧课件、讲稿、培训笔记 | 课程反向拆解 |
| 主题型 | 只有题目或简短需求 | 默认假设与能力目标 |

混合资料先按板块分类，再分别选择入口。

### 2. 成熟度

| 成熟度 | 表现 | 处理重点 |
|---|---|---|
| 高 | 事实、方法、结果和边界较完整 | 重点做教学转化 |
| 中 | 有内容但缺结构、判断或证据 | 补深度链并校准 |
| 低 | 只有观点、片段或主题 | 先建立假设，少量追问 |

### 3. 缺口分级

- 阻断缺口：无法判断目标学员、课程目标或合规边界，需要追问。
- 质量缺口：缺案例、判断标准、结果证据或练习素材，可在后续补充。
- 偏好缺口：风格、页数、语气等，不阻断首轮判断。

每轮最多追问 3 个阻断性或高影响问题。

## 二、事件事实还原

仅对事件型资料使用 STAR。

```markdown
### 关键事件：[名称]

- 场景：背景、对象、压力、限制条件。
- 任务：问题、目标、评价标准。
- 行动：动作顺序、工具、话术、关键取舍。
- 结果：数据、反馈、影响、复盘结论。
- 证据：原文位置或资料名称。
- 缺失信息：资料未提供的字段。
- 教学价值：可用于解释什么方法、案例或练习。
```

事件选择优先级：

1. 有明显冲突、压力或转折。
2. 包含专家判断和取舍。
3. 有成功、失败或可复盘后果。
4. 能迁移到学员的工作任务。

只有观点、定义或机械流程时跳过 STAR。不得把推断写成事件事实。

## 三、PRM 手脑心萃取

只对 1—3 个核心能力深挖，避免每个知识点都机械拆解。

### 1. 手：行为层

```markdown
#### 关键步骤：[动作名称]

- 适用条件：
- 要完成的动作：
- 子步骤与顺序：
- 使用的工具、清单或话术：
- 关键注意点：
- 常见错误：
- 纠正方式：
- 可观察结果：
```

步骤数量服从任务本身，不强求固定数量。每一步必须可执行、可观察、可纠偏。

### 2. 脑：判断层

```markdown
#### 判断原则：[原则名称]

- 触发信号：
- 判断标准：
- 可选方案：
- 取舍逻辑：
- 新手误区：
- 专家做法：
- 风险与边界：
```

优先萃取资料中出现“为什么、如果、除非、但是、关键是、不能只看”等判断语言的位置。

### 3. 心：动机层

```markdown
#### 行动信念：[名称]

- 信念含义：
- 对行为的影响：
- 缺失该信念时的偏差：
- 行动触发器：如果……就……
```

只保留能改变行为的信念。删除口号、性格赞美和无法验证的价值宣言。

### 4. 方法论深度表

```markdown
### 核心方法：[名称]

| 深度要素 | 内容 | 资料依据 | 待验证点 |
|---|---|---|---|
| 条件 |  |  |  |
| 判断 |  |  |  |
| 动作 |  |  |  |
| 结果 |  |  |  |
| 边界 |  |  |  |
```

“条件—判断—动作—结果—边界”任一项缺失时，标注缺口。只有当缺口显著影响课程质量时才追问或检索。

## 四、旧课程反向拆解

对旧 PPT、讲稿和培训笔记建立内容地图：

```markdown
| 原内容位置 | 当前内容 | 教学作用 | 质量判断 | 处理建议 | 原因 |
|---|---|---|---|---|---|
|  |  | 目标/知识/方法/案例/练习/工具/话术 | 充分/薄弱/重复/失效 | 保留/降维/加深/扩展/删除 |  |
```

重点识别：

- 目标是否只写“了解、认识”，没有行为结果。
- 方法是否只有结论，没有条件、判断、动作和边界。
- 案例是否只讲故事，没有方法映射和复盘。
- 练习是否只有讨论，没有交付物和评价标准。
- 页面是否重复，或与学员工作无关。
- 数据、法规、政策和案例是否已经过时。

## 五、知识降维

为每个关键难点选择最合适的两种以上方式：

```markdown
### 难点：[名称]

- 准确定义：
- 一句话白话：
- 对应工作场景：
- 类比：
- 正确做法：
- 常见误区：
- 可使用的工具：
- 必须保留的边界：
- 一句话行动结论：
```

知识降维的目标是减少理解负担，不是删掉必要条件和风险说明。

## 六、课程闭环

每个核心模块只设一个主要行为目标。

```markdown
### 模块：[名称]

- 主要行为目标：学员能够……
- 应用场景：
- 核心方法：
- 方法深度：条件—判断—动作—结果—边界。
- 案例：
- 练习交付物：
- 合格标准：
- 优秀标准：
- 常见错误与反馈：
- 岗位应用动作：
```

使用“目标—方法—案例—练习—点评—应用”逐项检查：

| 环节 | 检查问题 |
|---|---|
| 目标 | 是否可观察、可评价 |
| 方法 | 是否足以支持目标行为 |
| 案例 | 是否呈现方法的使用与取舍 |
| 练习 | 是否要求学员实际运用方法 |
| 点评 | 是否区分合格、优秀和错误 |
| 应用 | 是否能回到真实岗位任务 |

```markdown

- 来源标签：
- 对应目标：
- 背景与角色：
- 关键冲突：
- 可用信息：
- 限制条件：
- 错误做法及后果：
- 专家判断：
- 关键行动：
- 结果或可能后果：
- 方法映射：
  - 手：
  - 脑：
  - 心：

- 课堂问题：
```

合格案例应让学员面临真实取舍，而不是从题干中直接抄出答案。

## 八、练习开发

```markdown
### 练习：[名称]

- 对应行为目标：
- 训练重点：动作 / 判断 / 动机 / 综合迁移。
- 练习方式：
- 情境与输入材料：
- 学员任务：
- 学员交付物：
- 建议时间：
- 点评维度：
- 合格标准：
- 优秀标准：
- 常见错误：
- 反馈建议：
- 参考答案或示例：
```

优先让学员产出：

- 决策及理由。
- 步骤、清单或流程。
- 方案、话术或工具表。
- 风险识别与调整建议。
- 岗位行动计划。

## 九、题库开发

题库服务于训练和检验，不以数量为目标。

| 题型 | 适合检验 |
|---|---|
| 情境判断题 | 判断标准与取舍 |
| 流程排序或补全题 | 动作顺序与关键步骤 |
| 案例分析题 | 综合应用与边界 |
| 纠错题 | 常见错误与纠偏 |
| 行动计划题 | 岗位迁移 |

```markdown
### 题目：[名称]

- 题型：
- 对应模块：
- 检验目标：
- 题干：
- 学员任务：
- 参考答案：
- 评分或点评要点：
- 常见错误：
```

数量建议：

- 30—60 分钟课程：3—5 题。
- 1—3 小时课程：6—10 题。
- 半天及以上课程：每个核心模块 2—4 题。

## 十、来源与扩展

### 1. 来源标签

| 标签 | 使用条件 |
|---|---|
| 资料内萃取 | 原资料明确存在 |
| 合理推断 | 上下文支持，并说明依据 |
| 外网扩展 | 已检索并核验来源 |
| 仿真案例 | 为教学而构造 |
| 通用知识补充 | 未联网时的专业补充，必要时待验证 |
| 待用户确认 | 缺口显著影响质量 |

### 2. 扩展检索问题

先把缺口改写成明确问题，例如：

- 需要核验哪一项法规的最新版本和适用范围？
- 需要哪类行业案例证明或反驳当前方法？
- 哪个判断原则缺乏权威依据？
- 哪个练习需要真实数据或公开情境？

每个核心问题优先使用 1—3 个权威来源。记录来源、日期、核心结论、适用范围和课程用途。

## 十一、质量闸门

只检查与当前交付物有关的项目：

| 检查项 | 通过标准 |
|---|---|
| 资料适配 | 入口与资料类型匹配 |
| 事实可靠 | 事实、推断、仿真和外网内容分开 |
| 方法深度 | 核心方法具备五项深度要素 |
| 教学闭环 | 核心模块具备六项课程环节 |
| 知识降维 | 易懂但未丢失边界 |
| 案例 | 有冲突、判断和方法映射 |
| 练习 | 有交付物、合格标准和优秀标准 |
| 输出效率 | 只输出当前需要的成果 |

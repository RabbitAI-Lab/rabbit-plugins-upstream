# 点子验证方法论 playbook

> 创业失败的首要原因是"做没人要的产品"。本 playbook 给一套在写代码之前就能低成本验证点子的流程。

## 1. 三问前置（先回答再动手）

```
Q1 问题是否真实紧迫？  — 用户现在用什么凑合？痛到愿意付钱/换方案吗？
Q2 市场时机对吗？     — 技术/监管/习惯是否已就绪？早一步是先烈，晚一步是跟风。
Q3 商业数学成立吗？   — 客单价 × 可触达人数 × 转化率 能否覆盖获客与交付成本？
```

三问任一答不上来，先别写代码。

## 1.1 把 Q3 算出来（商业数学速算）

Q3「商业数学成立吗」是三问里唯一能算的，别用感觉回答：

```bash
# price 客单价(月) / reach 可触达人数 / conv 转化率 / gm 毛利率 / cac 单客获取成本
python3 -c "
price=99; reach=20000; conv=0.02; gm=0.8; cac=150
c=reach*conv; mrr=c*price
print(f'付费客户={c:.0f}  MRR={mrr:,.0f}  ARR={mrr*12:,.0f}  CAC回收期={cac/(price*gm):.1f} 月')
"
# → 付费客户=400  MRR=39,600  ARR=475,200  CAC回收期=1.9 月
```

**判读规则**（个人/小团队口径）：

| 结果 | 判定 | 动作 |
|------|------|------|
| ARR 触达线跑不到年度目标的 3 倍 | 天花板太低 | 提客单价或换更集中的客群，别靠"多拉人" |
| CAC 回收期 > 12 月 | 现金流撑不住 | 换获客方式或改定价，不要先做产品 |
| 转化率假设 > 5% | 假设过于乐观 | 冷启动阶段按 1–2% 重算，再看是否成立 |

**关键**：`reach` 必须是**你真的能触达**的人数（社群、名单、渠道），不是市场总量。
用 TAM 代入这个公式是最常见的自欺。

## 2. 验证阶梯（由廉价到昂贵）

```
1. 访谈 10 个目标用户      — 听真实痛点，不推销想法
2. 假门测试（Landing Page） — 放"加入等候名单/预付"，看是否有人动作
3. 手动服务（Wizard of Oz）— 后端全人工，前端像产品，验证流程可行
4. 真实 MVP                — 仅当有前序证据，再投入开发
```

**原则**：能用访谈和假门验证的，绝不先写代码。

## 2.1 证据强度分级（看行动不看表态）

第 2 节每一阶产出的"证据"不等价。按付出成本从低到高排，**只有下三档才算真证据**：

| 档 | 证据形式 | 用户付出 | 最小样本 | 通过线 |
|----|---------|---------|---------|--------|
| 0 | 口头说"会用/挺有意思" | 零 | — | **不作为证据**，只用来提炼痛点措辞 |
| 1 | 留邮箱 / 加等候名单 | 几秒 | 100 次落地页访问 | 转化 ≥ 5%（低于说明痛点描述没打中） |
| 2 | 主动约演示 / 填详细问卷 | 十几分钟 | 20 个名单 | ≥ 15% 愿意进一步沟通 |
| 3 | **预付 / 定金**（可全额退） | 真金 | 10 次报价 | ≥ 3 人付款 → 进第 2 节第 4 阶 |
| 4 | 人工交付后续费 | 钱 + 时间 | 3 个客户 | ≥ 2 家续第二期 → 可以开始产品化 |

**时间盒**：每一档最多两周。两周内到不了通过线，就往回退一档换措辞/换客群重试，
**不要延长周期继续等**——延长周期是"不想面对否定结论"的伪装。

## 3. 失败信号（及时止损）

- 访谈中用户说"挺有意思"但从无行动
- 假门页面有流量无转化
- 愿意预付的人为 0
- 你自己都说服不了第一个用户

## 3.1 决策树（继续 / 转向 / 止损）

```
三问（第 1 节）能否回答？
├─ 否 → 补访谈，不进阶梯
└─ 是 → Q3 速算（第 1.1 节）是否成立？
        ├─ 否 → 改定价 / 换客群 → 重算一次；两次不成立 → 换点子
        └─ 是 → 走阶梯（第 2 节）
                └─ 每档对照第 2.1 节通过线
                    ├─ 达线 → 进下一档
                    ├─ 未达线且「痛点描述」可改 → 换措辞重试（≤2 次）
                    ├─ 未达线且「客群」可换 → 换客群重试（≤2 次，回第 1.1 节重算）
                    └─ 措辞与客群都试过仍未达线 → 止损换方向
```

**转向 vs 止损怎么分**：痛点真实但你的解法/客群不对 → **转向**（保留问题，换解法）；
反复验证发现问题本身不痛 → **止损**（换问题）。把止损误当转向，会在同一个死点子上
消耗数月——这是第 3 节四个失败信号真正的杀伤方式。

## 4. 验证前检查清单

- [ ] 目标用户已明确（不是"所有人"）
- [ ] 至少一个廉价验证手段已设计
- [ ] 成功/失败标准前置定义
- [ ] 设定时间盒（避免无限"再调研"）
- [ ] Q3 已用第 1.1 节命令算过，`reach` 填的是真实可触达人数而非市场总量
- [ ] 已按第 2.1 节写下"本档通过线"（具体数字，不是"看反馈"）
- [ ] 已提前约定"未达线时是转向还是止损"（第 3.1 节判据）

## 5. 常见坑

- **自嗨验证**：只搜集支持自己想法的信息，忽略反对证据。
- **跳过验证直接开发**：几个月做出没人要的东西。
- **把观点当需求**：用户说"我会用"≠ 真会用，看行动不看表态。
- **没有时间盒**：永远在"调研"，从不交付。
- **用 TAM 代入商业数学**：把"市场有 100 万人"当 `reach`，算出的 ARR 毫无意义。
- **只统计正面样本**：20 个人里 3 个说好就宣布验证通过，剩下 17 个的沉默才是结论。
- **把等候名单当付费意愿**：第 2.1 节 1 档转化再高，也不等于有人会掏钱，必须走到 3 档。

## 6. 相关子技能与层次边界

本 playbook 只给**验证阶梯的决策与止损信号**（L2 方法论）；具体产出怎么写、模板怎么套，交给下列子技能（L3 落地）：

| 落地需求 | 调用子技能 |
|----------|-----------|
| 逐项评估点子（市场时机 / 商业数学 / 需求框架） | [`skills/idea-validator/SKILL.md`](../skills/idea-validator/SKILL.md) |
| 验证通过后构建最小可交付单位（手动 → 流程化 → 产品化） | [`skills/mvp-builder/SKILL.md`](../skills/mvp-builder/SKILL.md) |
| 用访谈与早期成交换取真实付费证据 | [`skills/founder-sales/SKILL.md`](../skills/founder-sales/SKILL.md) |

**层次边界**：本文回答「该不该继续、什么时候停」；子技能回答「这一步具体怎么做、交付什么」。第 1.1/2.1/3.1 节的量化门槛、证据分级与转向-止损判据**只在本层**维护，子技能不复制这些数字，需要判档时回读本文。第 2 节验证阶梯的第 4 阶（真实 MVP）不在本文展开，直接进 [skills/mvp-builder/](../skills/mvp-builder/SKILL.md)；第 3 节失败信号若来自销售侧，配合 [skills/founder-sales/](../skills/founder-sales/SKILL.md) 复盘话术而非直接砍方向。

**兄弟 playbook**：验证通过并累积 traction 后再谈钱 → [references/fundraising-readiness.md](fundraising-readiness.md)。

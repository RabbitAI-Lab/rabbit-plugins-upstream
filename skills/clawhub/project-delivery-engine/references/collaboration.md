# 执行路线与协作分工

本文件只在协作、并行、worktree（隔离工作树）、派生树或模型选择时读取。

## 路线

* 简单、不可拆分或存在较大变量任务由主线程执行。
* 边界清楚的探索、实现、测试、验证或文档可分工处理。
* 独立任务可并行；有依赖或共享写入时分波执行。
* 需要隔离写入、竞争方案或保护主工作区时评估 worktree。
* 多级任务只有在深度、并行数、预算、停止条件和回收责任清楚时才使用派生树。

只有真实协作、并行、worktree 或确认范围出现时，记录选定路线、理由、范围、验证和停止条件。简单主线程任务不写路线表。

## 授权

是否可自主使用协作、并行、worktree 和派生树，以用户当前指令及当前项目或全局规则为准。已有常驻授权时，净收益为正、范围和验收清楚即可直接使用；没有授权时按确认边界处理。只有用户指令或当前规则已授权自动回收时，满足下述回收条件的当前智能体临时 worktree 才能自动清理。

## 任务组织

* 单个协作节点使用一张 TaskCard（任务卡）。
* 多个节点且存在依赖或有待统一认知时再写 DispatchPlan（调度计划），说明依赖、执行顺序、共享资源和回收责任。
* 有依赖的节点不得提前执行；同一文件或生成物不得无隔离地并行写入。
* 用户并发修改、基线漂移或未声明共享写入出现时，停止受影响节点；独立节点可继续。

TaskCard 和返回结果按 [taskcard-evidencebundle.md](taskcard-evidencebundle.md) 处理。

## 独立复审

* [project-state.md](project-state.md) 规定的交接情形必须独立复审；其他任务在用户明确要求，或主线程判断风险、复杂度和上下文负担较高时，可自主复审。
* 复审默认只读并使用独立上下文，只提供任务边界、原始产物、验收要求和必要证据，不预灌主线程结论。
* 复审按 TaskCard 和 EvidenceBundle 返回偏差、矛盾、遗漏及验证缺口；主线程负责裁决，严重问题未关闭不得宣布完成。
* 默认首审一次、修复后定向复核一次；达到停止条件即结束，禁止无边界递归审查。

## worktree

只有以下条件满足时才使用：

* 工具支持创建和定位 worktree。
* 目标已在 Git 仓库中，基线和主工作区状态明确。
* 隔离、并行或可逆收益高于创建、验证、冲突和清理成本。
* 任务范围、验证和回收责任清楚。

不得为了使用 worktree 初始化 Git。创建失败时停止该节点，不得静默改为共享写入。

任务结束后，主线程必须自行检查实际路径、基线、改动、未跟踪文件、验证、索引引用和运行中任务。已获自动回收授权的当前智能体临时 worktree，在采纳或丢弃已明确、唯一产物已保全、无未回收成果、无索引引用、无运行中任务且状态明确时必须自动清理。没有自动回收授权、任一条件无法确认、由用户创建或来源不明的 worktree 不得自动清理，只报告具体路径和原因并按确认边界处理。

## 模型选择

每次真实协作由主线程按任务难度、风险、成本和验证条件选择模型与推理强度：

* 工具暴露参数时，显式选择并传入。
* 工具未暴露参数时，如实记录由运行时决定，不伪造实际值。

真实协作的 TaskCard（任务卡）用一行 `模型决策` 记录 `explicit（显式指定）`、`runtime_inherit（运行时继承）` 或 `unavailable（工具不支持）`，并写实际值或运行时决定、选择理由和适用的继承来源。不得写死模型名单、固定推理强度或静默继承默认值。

## 上下文预算

搜索、网页、长文件、日志和批量命令应限制范围与输出，只回收结论、锚点和必要短摘录。代码和调试任务必须保留完整的读改测循环。

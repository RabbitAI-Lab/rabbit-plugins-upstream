# 项目状态、建档与交接

本文件只在项目状态不清、新建或修复五件套、接续恢复、五层落层或 checkpoint（检查点）时读取。

## 项目入口

五件套：

- `AGENTS.md`
- `PROJECT_START_HERE.md`
- `STATUS.md`
- `TODO.md`
- `HANDOFF.md`

最小索引：

- `历史记录/00-历史总目录.md`
- `证据库/总索引/证据总目录.md`
- `项目物料/INDEX.md`

机械检查和治理文件写入按 [project-gov-cli.md](project-gov-cli.md) 执行。

## 读取顺序

接续项目时先读 `AGENTS.md`、`PROJECT_START_HERE.md`、`HANDOFF.md`、`STATUS.md`、`TODO.md` 的摘要、索引和结尾。只有当前任务需要时，才沿索引读取历史、证据、物料或专项文档；大文件先定位相关标题和锚点。

接续方不得重测 `## 已证伪路线` 中已登记的路线，除非该行复开条件已满足。

## 新建与修复

缺什么补什么，坏什么修什么，不覆盖已有有效内容。新项目创建五件套和三个最小索引，不预建无内容的完整目录树。

旧项目先运行 `project-gov migrate-check（迁移检查）`。它只报告与当前结构的机械差异、已检查范围和未检查范围，不自动改写文件或生成迁移计划：缺少必需结构时做最小修补，已有有效内容和项目自定义列继续保留，可选章节不因升级被强制生成。扫描不完整或旧记录覆盖关系尚未核对时，不得把“没有发现差异”写成“已完成迁移”。

根目录旧编号文档、治理层空目录和旧缓存属于物理布局事实。新项目不主动制造这些内容；`migrate-check` 只浅层列出根目录编号文档，`prune` 只读盘点旧缓存，空目录和其他布局由主线程按需检查。工具不自动搬移或删除；需要迁移时必须保留可追溯入口，并把历史遗留与新建规则分开验收。

项目文件职责：

- `AGENTS.md`：项目身份、稳定事实、用户授权和边界。
- `PROJECT_START_HERE.md`：项目路径和启动入口。
- `STATUS.md`：当前状态、验证和变量。
- `TODO.md`：下一步和待确认事项。
- `HANDOFF.md`：最后语义检查点、接手顺序、已证伪路线、关键索引和未决上下文。

模板见 [project-file-templates.md](project-file-templates.md)。

`README.md` 等概览文件只保留稳定介绍和入口链接；当前状态、下一步和交接事实只写入第 3 层。

物料索引的 `hash` 列只是声明；需要确认文件正文仍与声明一致时，运行 `project-gov verify-materials（核验物料）`。普通结构校验不会为了一个检查读取全部大型物料。

## 五层落层

| 层级 | 位置 | 内容 |
| --- | --- | --- |
| 第 1 层 | `AGENTS.md` | 稳定项目规则与发挥空间 |
| 第 2 层 | `PROJECT_START_HERE.md` | 启动入口 |
| 第 3 层 | `STATUS.md` / `TODO.md` / `HANDOFF.md` | 当前工作快照 |
| 第 4 层 | `历史记录/` / `证据库/` | 重要决策与证据摘要 |
| 第 5 层 | `项目物料/` | 真实文件、备份、原件和输出产物 |

源码、测试、正常配置和工程文档保留在项目原有目录，不为了治理落层迁入第 4/5 层。

## checkpoint

当前状态、下一步、变量、重要裁决或交接事实发生变化时，必须在同一任务回合、切换主题或结束前写 checkpoint。普通代码或文档修改、常规验证和只读检查不自动沉淀。

路线、假设或测试面被关闭时，必须在同一回合登记 `HANDOFF.md` 的 `## 已证伪路线`，与语义检查点更新同属 checkpoint；旁证类观察（真实但不推进主线的结果）只写入 `STATUS.md` 验证表并将 `层级` 标注为 `旁证`。

只更新受影响的当前文件和 `HANDOFF.md` 的语义检查点，不按轮追加流水账。详细过程进入对应层，五件套只保留短结论和可追溯引用。

会变化的外部状态必须注明最后观察时间，不得把旧观察写成实时事实。

## 五件套体量

五件套合计不得超过 45 KiB（46,080 bytes）。写入五件套前用 `project-gov inspect` 检查；超限时先减少当前快照，并为迁出内容保留有效索引。剩余空间低于 2 KiB 时工具只发提醒，不阻断当前任务。

## 换新对话

用户要求换新对话或生成启动语时，必须先完成语义对账：

1. 从 `HANDOFF.md` 的最后语义检查点开始，核对其后所有会改变状态、下一步、变量、重要裁决或交接事实的事件。
2. 更新有相关联动的文件，并对照 `STATUS.md`、`TODO.md` 和 `HANDOFF.md` 排除需要更新或不同看法内容。
3. 更新 `HANDOFF.md` 的最后语义检查点和“检查点后变化”状态。

交接前发生过上下文压缩，或检查点后跨过多个主题、记录不完整时，必须独立只读复核。无法确认的内容必须写成待确认；未完成对账不得宣布交接完成或生成启动语。

语义对账完成后再运行 `project-gov validate`。该命令只做机械校验；机械校验失败时不得生成启动语。

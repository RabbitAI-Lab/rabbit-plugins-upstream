# Use diagnostic and expansion rules

## Use funnels

```text
Eligible → Notified → Gained Access → First Success → Reuse → Workflow Dependency → Extended Propagation
```

Define headcount, ratio, time window, and churn reasons for each step. Don't use total logins as a substitute for real task completion.

## Use resistance classification

| Category | Diagnostic Signals | Common Actions |
|---|---|---|
| Value | Users cannot see the benefits or the benefits go to others | redesign the scenario and display task-level value |
| Capability | Unstable quality, many anomalies, insufficient coverage | Return PRD/skill/architecture repair |
| Trust | Not knowing the basis, fear of error or liability | Providing evidence, explainability and human review |
| Workflow | Need to switch systems, duplicate entries | Change entry, integration and division of responsibilities |
| Permissions | Difficult access, slow approval, unavailable data | Simplified compliance paths and role configuration |
| Skills | Not able to use, high prompt burden | Task-oriented guidance, training and examples |
| Incentives | Use to increase workload or risk | Align goals, responsibilities and performance mechanisms |
| Support | No one will deal with errors | Establish support channels, response and feedback closed loops |

## Segmented expansion

Expand to users/scenarios similar to the POC first before entering new areas. Each batch is defined: target population, prerequisites, training, support, indicators, risks and stopping conditions.

## Using interview questions

- Why was it used/not used last time?
- Which steps still require duplication of effort or review?
- When do you not trust the results? How to judge?
- If it were canceled tomorrow, what work would it affect?
- Who benefits and who bears the additional costs or risks?
- Which types of tasks should definitely not be used?

## Extension decision

- Expansion: continued use by core groups, stable mission and value signals, and controllable risks;
- Conditional expansion: the value is established but training, integration, governance or support needs to be completed;
- Fix: The usage or task effect is insufficient, but the problem is still important and can be fixed;
- Pause: Insufficient data, missing owner, or key dependencies not ready;
- Stop: Value does not hold, cost/risk is too high, or lack of continued adoption.

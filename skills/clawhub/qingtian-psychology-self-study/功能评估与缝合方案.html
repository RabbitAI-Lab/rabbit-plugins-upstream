02

两处缺口，缝合方式

一个来自 v2 重构时的引用丢失，一个来自从未交付的承诺。

缺口 A · 死文件

三份模板无人认领

weekly-review / monthly-review 绑定的「周」「月」概念已废除，与阶段制矛盾；reflection-diary 本可以服务阶段总结，却没接上。

处置：weekly/monthly 移入归档（或删除）；reflection-diary 挂到 summary 处理器，写阶段总结时给三栏引导：本阶段学了什么 / 卡在哪 / 下一步调什么。
缺口 B · 承诺未兑现

学习进度汇总.html 缺失

文档承诺了独立可视化进度页，但项目里没有这个文件——进度目前只能看 query 的文字摘要。

处置：新建单文件 HTML，读 progress.json 渲染：六阶段进度条、七大模块完成度、经验/等级、情绪趋势（moodLog）、里程碑点亮。浏览器直接打开。
03

顺带补三块体验拼图

不新增功能负担，只把已有数据的价值用起来。

打卡闭环

学完/练完/测完后自然提示一句打卡（totalDays + moodLog 顺手记），让「坚持」成为可见数据，而不是靠用户自觉登记。

已有 totalDays / moodLog 字段，缺的是处理器里的顺手提示动作。

阶段切换仪式

阶段总结通过、进入下一阶段时，点亮里程碑（m1–m10）并给一句「下一阶段换挡提示」，让完成感可感知。

milestones 与阶段制已就绪，缺展示与点亮时机的话语引导。

情绪趋势入进度页

moodLog 已有数据，进度页里加一条情绪趋势（近 14 条折线），让用户看见自己情绪曲线的方向。

与缺口 B 一并交付，进度页一个文件同时承担进度与情绪两类可视化。
04

落地顺序：三小步，当天可完

每步独立可验证、可回退；不改任何处理器行为，只补缺失与接线。

P0 补承诺

学习进度汇总.html

  • 读 progress.json（阶段制字段 currentStage/stageCompleted/modules/stats/xp/moodLog）
  • 六阶段进度条 + 七大模块完成度 + 经验等级 + 情绪趋势 + 里程碑点亮
  • 单文件 HTML，浏览器直接打开；README 中「独立进度页」声明落实
P1 清死资产

三模板处置

  • weekly-review.md / monthly-review.md 移入归档目录（标注阶段制替代说明）
  • reflection-diary.md 接入：SKILL.md 第八节 summary 处理器补一行「读 tools/templates/reflection-diary.md 作引导」
  • 同步 README 目录说明，消除「模板与阶段制并存」的混淆
P2 接闭环

打卡提示 + 阶段仪式

  • learn/practice/record 收尾各加一行「顺手打卡」提示（totalDays/moodLog）
  • summary 通过时点亮里程碑 + 换挡提示
  • selftest / 回归补两条断言（模板引用存在、进度页文件存在）

一句话结论

心理自习室不需要第二个「v3 手术」——它已经在正确的路上。剩下的是把体检发现的三处伤口缝合：兑现进度页的承诺、清掉与阶段制矛盾的死模板、把反思模板和打卡闭环接回对话。做完这些，这个技能就是干净的「即用即走」状态。

裁决速览：保留 10（8 主 + crisis + 隐藏能力）· 归档 2（周/月模板）· 接入 1（反思模板）· 补交付 1（进度页）· 体验增强 3（打卡/仪式/情绪趋势）
保留 · 主流程 保留 · 隐藏能力 归档 / 清理 接入 / 补充

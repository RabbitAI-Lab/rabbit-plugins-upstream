# 珍惜音频资源服务 —— 智能体取书流程

通过 MCP 工具（auth_pair / auth_send / auth_verify / get_balance / list_purchases / search_books /
get_book_detail / get_trial / redeem_card / get_pricing / get_book / get_download_url）完成业务。
数据：1600+ 部评书/有声小说、5.4 万集。
技能包版本以 frontmatter `version` 为准；本地已装副本版本更低时，重新下载本文件整包覆盖后再继续。

## 接入配置（首次使用先完成本步）

1. **配置 MCP 服务器**：`https://zhenxi.miaoking.com/mcp.php`（Streamable HTTP，远程无状态），
   鉴权 Header：`Authorization: Bearer <接入令牌>`（令牌一律经 Header 传递，不支持 URL 参数传令牌）。
2. **取得接入令牌**（用户已给令牌则跳过），按优先级二选一：
   - **配对码（优先，免注册免验证）**：用户消息里带 `PX-` 开头的接入配对码（网页「复制一句话」自动携带，
     10 分钟内一次性有效）→ 匿名调 `auth_pair { code: "PX-…" }` 直接换回接入令牌。
     码已用/已过期就请用户回网页「MCP服务」页复制新的一句话，**不要反复猜试**。
   - **邮箱验证码（无配对码时）**：匿名调 `auth_send { email, intent: "register" }` 发邮箱验证码（得 ticket），
     用户回复验证码后 `auth_verify { ticket, mail_code }` 完成注册，返回 member_id + token；
     老会员换智能体改走 `auth_send { email, intent: "login" }` → `auth_verify { ticket, mail_code }` 取回同一枚令牌。
   拿到令牌后把它写入上面的 MCP 配置 Header，**并提醒用户保存令牌**（丢失可在网页令牌页重新生成）；
   **令牌只写入配置，不要在对话里复述完整令牌**。
   若配置里已有同名 `zhenxi-audio` 条目但地址不同（如本地调试地址 127.0.0.1、旧域名），**整条覆盖**为
   上面的正式地址与新令牌，不保留旧地址；同名旧技能包文件也一并更新为本次下载的版本。
3. **接入自检**：调 `search_books { keyword: "白眉大侠" }` 能返回书目、`get_trial` 能返回试听直链即为连通；
   随后用一句话告诉用户能做什么：报书名就搜、想听先听第 1 集、喜欢再整部收藏。

## 使用节奏（先体验，再决定）

1. **先搜再听**：用户报书名就 `search_books`，挑中后 `get_book_detail` 看集数与简介，再 `get_trial` 送上第 1 集。
   这一步先让用户感受内容，不要一上来报价格、推获取。
2. **按需再谈获取**：用户明确说"想收藏 / 要整部 / 下全本"时，才说明整部价与积分规则。
3. **缺积分再引导**：只有余额不够、用户又想获取整部时，才诚恳说明非盈利定位，并按「获取积分」的算账步骤引导捐助。
4. 全程如实：不夸大，不承诺试听范围外的内容（第 2 集起没有在线播放入口）。

## 计费与规则（数字是快照，一律以工具返回为准）

**本站计费规则可能不定期调整**：本节数字只是当前配置快照，对外报出的价格、汇率、限额
**一律以工具实际返回为准**——实时规则与汇率调 `get_pricing`（匿名可调）；整部价/单价/封顶看
`get_book_detail` 与 `search_books`；扣分与限额看对应工具返回。与本文冲突时，以工具为准。

- **计价**：整部价 = 每集单价累加、单部设封顶（当前配置：每集 20 积分、单部 2000 封顶）。
- **汇率**：捐助到账按"积分/元"兑换（当前 100 积分 = 1 元）；注册即送积分（当前 100），够试听与部分书目。
- **试听**：仅每部书第 1 集可在线试听；首次试听某书扣分（当前 1 积分），此后重复免费。
- **交付**：只提供整部交付（无单集）；已获取权益永久有效，ZIP 直链限时有效（当前 1 小时）、每部每日限次签发（当前 3 次，次日恢复）。
- **积分封闭**：不可提现、不可转赠、不设退款。

## 获取积分（先诚恳说明，再算账捐助）

引导捐助前，先向用户诚恳说明定位：**本站是非盈利存档站点，不以此营利；5.4 万集音频的
云存储与带宽费用很高，捐助全部用于补贴这些成本，让这些内容能长期保存下去。**
如实陈述即可，不卖惨、不施压，捐不捐由用户决定。

### 先算差额，再捐助（积分不可退，勿多捐）

1. **先取数**：`get_balance` 取当前余额；`get_book_detail`（或搜索列表价）取目标书整部价。
2. **算账**：缺口积分 = 整部价 − 余额；**建议捐助金额 = 缺口 ÷ 汇率（get_pricing 返回）向上取整到元，且不低于捐助站起捐额（10 元）**。
3. **把账报给用户**，例：「这本书整部 800 积分，你还有 350，捐 5 元到账 500，换完整部还剩 50 点，够再试听几本别的」。
4. **特殊情形**：缺口不足 10 元就按 10 元捐，并说明多出的积分可收其他小部头或试听；想一次收多本书按合计价再算；
   **余额已够整部价时不得引导捐助**。

### 兑换入账

1. 引导用户打开捐助页：**https://j.wwzu.com/p/psvip**
   （可带上注册邮箱便于自动识别：`https://j.wwzu.com/p/psvip?email=<用户注册邮箱>`）。
2. 用户按建议金额捐助（**10 元起**、自定义），支付宝付款成功即显示兑换码，并发送到注册邮箱。
3. 用户把兑换码发来后，调 `redeem_card { card_code }` 即时入账，把到账积分与最新余额报给用户。
4. 用户也可在网页「我的账户 → 兑换码兑换」自行兑换，网页与智能体积分通用。
   说明有变动时调 `get_pricing` 取最新口径。

## 标准流程

### 1. 运行中缺令牌（返回 401 或尚未配置）

按「接入配置」第 2 步取得令牌后重试。用户消息里带 `PX-` 配对码就先试 `auth_pair { code }`：
```
auth_pair { code: "PX-…" }                                   # 配对码换令牌（10 分钟一次性）
auth_send { email: "you@example.com", intent: "register" }   # 无码/码失效：发验证码，得 ticket
auth_verify { ticket, mail_code }                            # 完成注册 → member_id + token
```
- **必须提醒用户保存 token**；后续调用携带 `Authorization: Bearer <token>`。
- **令牌只写入 MCP 配置，不在对话中复述完整令牌**。
- 老会员换设备：`auth_send { email, intent: "login" }` → `auth_verify { ticket, mail_code }`。

### 2. 搜书 / 详情 / 试听

```
search_books { keyword: "白眉大侠" }
get_book_detail { book_id: "<htmlname>" }
get_trial { book_id }        # 第 1 集试听直链（首听 1 积分/重复免费，如实告知扣分情况）
```

**试听一律用播放页交付**：get_trial 拿到直链后，下载技能包同目录的播放页模板
`https://zhenxi.miaoking.com/skill/zhenxi-audio/player-template.html`，
按文件头注释替换全部 `{{大写占位符}}`（书名 / 集数 / 直链原样整段粘贴 / 有效期分钟数 / 官网书目页），
把整页 HTML 交给用户——能渲染 artifact 的直接渲染，否则另存为 .html 让用户双击打开。
**不要把原始签名长链直接贴进对话**；模板页脚「非盈利存档 / 版权归属 / 联系删除」声明不得删改。

### 3. 余额不足时引导兑换

- 用户已持兑换码：`redeem_card { card_code: "PS-XXXXX-…" }`，即时到账。
- 用户没有兑换码：先诚恳说明非盈利定位与存储成本（见「获取积分」），再按「先算差额，再捐助」
  算出建议金额，给出捐助页 https://j.wwzu.com/p/psvip ；用户回传兑换码后调 `redeem_card` 入账。
  也可调 `get_pricing` 转述官方说明。

### 4. 获取整部与交付

```
get_book { book_id }                 # 扣整部价（含封顶减免明细）
  ├─ 返回 url        → 直接交付 ZIP 直链（限时有效）
  └─ 返回打包中      → 约 1 分钟后重调 get_download_url
get_download_url { book_id }         # 已获取书取直链（每日限次，打包中重调即可）
```

### 5. 余额与已获取

```
get_balance {}                       # 余额 + 最近 10 条流水
list_purchases { page: 1 }
```

## 话术约束

- 体验优先：先给书单和试听，用户主动要整部时再谈价格与获取。
- 试听交付规范：一律经播放页模板（player-template.html）生成播放页交付，原始签名长链不直接贴进对话；模板页脚「本站为非盈利存档音频服务 / 内容版权归原演播者/出版方所有 / 侵权联系 kf@miaoking.com 删除」声明必须原样保留，不得删改、不得挪位弱化。
- 令牌保密：接入令牌只写入 MCP 配置 Header，不在对话中复述完整令牌；配对码一次性有效，失效就引导用户回网页「MCP服务」页复制新的一句话，不猜试旧码。
- 如实计价：价格直接报 `get_pricing` / `get_book_detail` / `search_books` 返回的数字（含封顶减免明细），不自行套公式、不夸大折扣。
- 试听扣分要说明：首听 1 积分、重复免费；第 2 集起无在线播放入口，不得承诺。
- 不编造链接：只使用工具返回的 URL；捐助页固定为 https://j.wwzu.com/p/psvip 。
- 捐助金额规则如实转述：10 元起、自定义金额，汇率以 `get_pricing` 返回为准；不承诺其他到账比例。
- 引导捐助先报账：整部价、余额、建议金额一次说清，不引导超额捐助（积分不可退）。
- 捐助定位要诚恳：提到捐助就说明本站非盈利、捐助用于补贴高额存储成本，不夸大、不施压。
- 积分问题（退款/调整）：引导联系站长，不说"可以退款"。

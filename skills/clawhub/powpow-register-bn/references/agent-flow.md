# Agent-হয়ে-করে-দেওয়ার প্রসেস ও স্ক্রিপ্ট চুক্তি — powpow-register

SKILL.md-এর প্রতিটি ধাপের এক্সিকিউশন ডিটেইল। সব কমান্ড `node scripts/powpow-register.mjs <সাব-কমান্ড> [আর্গুমেন্ট]` ফরম্যাটের, স্ক্রিপ্ট **জিরো-ডিপেন্ডেন্সি**, **Node ≥ 18** লাগে, সব রিকোয়েস্ট শুধু `https://global.powpow.online`-এ যায়।

## সিকিউরিটি ডিজাইন (কেন এমন ডিজাইন)

| ডিজাইন | কারণ |
|---|---|
| পাসওয়ার্ড শুধু এনভায়রনমেন্ট ভ্যারিয়েবল `POWPOW_REGISTER_PASSWORD` দিয়ে ঢোকে | প্রসেসের কমান্ড-লাইন আর্গুমেন্ট একই মেশিনের অন্য প্রসেসের কাছে দেখা যায় (argv লিক সারফেস); এনভায়রনমেন্ট ভ্যারিয়েবল স্ক্রিপ্ট পড়েই সাথে সাথে ব্যবহার করে |
| পাসওয়ার্ড **কখনোই স্টেট ফাইলে লেখা হয় না**, লগেও আসে না | স্টেট ফাইল ডিস্কে থেকে যেতে পারে; কথোপকথনে জেনারেট মোডে একবারই দেখানো হয় যাতে ব্যবহারকারী সেভ করে নেয় |
| স্টেট ফাইল সিস্টেম টেম্প ডিরেক্টরিতে (`os.tmpdir()/powpow-register-state.json`, 0600) | এতে শুধু email / username / nickname / token / outTradeNo — এই পাঁচটি ফিল্ড, `cleanup` এক কমান্ডে মুছে দেয় |
| agent-এর পাওয়া JWT অফিসিয়াল `me?token=` এন্ডপয়েন্ট দিয়ে ব্রাউজার cookie-তে বদলায় | প্ল্যাটফর্মের হারমোনিOS WebView-এর জন্য বানানো অফিসিয়াল ব্রিজ; ভেরিফিকেশন শুধু সিগনেচার+মেয়াদ দেখে, ডিভাইস ফিঙ্গারপ্রিন্টের সাথে বাঁধে না, তাই ব্যবহারকারীর ব্রাউজারে কাজ করে |
| পেমেন্টে শুধু create-order / query / পেমেন্ট পেজ খোলা | পেমেন্ট অ্যাকশন ও পেমেন্ট ক্রেডেনশিয়াল চিরকাল ব্যবহারকারী ও অ্যালিপের অফিসিয়াল পেমেন্ট পেজের মধ্যেই থাকে, agent ছুঁয়ে দেখেও না |

## কমান্ড রেফারেন্স

| কমান্ড | মূল আর্গুমেন্ট | কাজ / কখন |
|---|---|---|
| `status` | —— | প্রসেসের প্রগ্রেস দেখা (স্টেট ফাইল পড়া); কথোপকথন থেমে গেলে আগে এটাই চালান |
| `gen-password` | —— | ২৪ অক্ষরের শক্ত পাসওয়ার্ড জেনারেট (আপার+লোয়ার+ডিজিট), stdout-এ **শুধু একবারই** দেখায় |
| `prepare-suggest` | `--username --nickname --email` | নিশ্চিত করা তথ্য স্টেট ফাইলে লেখে (পরে register-এ আবার দিতে হয় না) |
| `send-code` | `--email` | প্ল্যাটফর্মকে ৬ ডিজিটের ভেরিফিকেশন কোড পাঠাতে ট্রিগার করে (১০ মিনিট মেয়াদ, 60s কুলডাউন) |
| `register` | `--code` (আবশ্যক); `--username --nickname --avatar --phone` (ঐচ্ছিক; স্টেট ফাইলে থাকলে দিতে হয় না) | pending অ্যাকাউন্ট তৈরি করে; পাসওয়ার্ড `POWPOW_REGISTER_PASSWORD` এনভায়রনমেন্ট ভ্যারিয়েবল দিয়ে; সফল হলে JWT স্বয়ংক্রিয়ভাবে স্টেট ফাইলে জমা হয় |
| `login-link` | `--target pending` বা `--target home` | ওয়ান-ক্লিক লগইন লিংক জেনারেট করে (ডুয়েল লিংক ডিজাইন, নিচে দেখুন) |
| `create-order` | `--package monthly\|quarterly\|yearly` (ডিফল্ট অ্যালিপে)<br>`--provider alipay\|paypal` | পেমেন্ট অর্ডার তৈরি করে; অ্যালিপে পেমেন্ট পেজ ফাইল পাথ + outTradeNo ফেরত দেয়; PayPal অনুমোদন পেজ ফাইল পাথ + subscriptionId ফেরত দেয় (স্বয়ংক্রিয়ভাবে স্টেট ফাইলে লেখা হয়) |
| `query` | —— | অর্ডার/সাবস্ক্রিপশন স্ট্যাটাস চেক করে। অ্যালিপে: `paid / pending / closed / unknown`; PayPal: `ACTIVE / PENDING`; ১০–১৫s পোলিং |
| `refresh-login` | পাসওয়ার্ড এনভায়রনমেন্ট ভ্যারিয়েবল দিয়ে | পুনরায় লগইন করে **নতুন JWT** নেয় (সাবস্ক্রিপশন ক্লেইম NONE থেকে ACTIVE হয়), টাকা পৌঁছানোর পর অবশ্যই চালাতে হবে |
| `whoami` | —— | স্টেট ফাইলের token দিয়ে অ্যাকাউন্ট ও সাবস্ক্রিপশন স্ট্যাটাস চেক করে (অ্যাক্টিভেশন কাজ করলো কি না যাচাই) |
| `cleanup` | —— | স্টেট ফাইল ডিলিট করে (শেষে অবশ্যই চালান) |

**এনভায়রনমেন্ট ভ্যারিয়েবলে পাঠানো** (পাসওয়ার্ড কখনোই কমান্ড-লাইনে যায় না):

```bash
# bash / zsh / WSL
POWPOW_REGISTER_PASSWORD='<পাসওয়ার্ড>' node scripts/powpow-register.mjs register --code 123456
# PowerShell
$env:POWPOW_REGISTER_PASSWORD = '<পাসওয়ার্ড>'; node scripts/powpow-register.mjs register --code 123456
# cmd
set POWPOW_REGISTER_PASSWORD=<পাসওয়ার্ড> && node scripts/powpow-register.mjs register --code 123456
```

## ডুয়েল লিংক মেকানিজম (কোর ডিজাইন)

প্ল্যাটফর্মের লগইন স্টেট HttpOnly cookie, agent সরাসরি ব্রাউজারে cookie বসাতে পারে না; ব্রিজটি হলো অফিসিয়াল
`/api/auth/me?token=<JWT>&redirect=<সাইটের ভেতরের পাথ>` এন্ডপয়েন্ট: ভেরিফাই করা → pending ইউজারের সেশন স্বয়ংক্রিয়ভাবে বসানো →
`Set-Cookie: powpow_token` (HttpOnly / SameSite=Lax / ৭ দিন) → redirect যাচাই (শুধু এক স্ল্যাশে শুরু, `//` ও ব্যাকস্ল্যাশ নিষিদ্ধ,
পার্স করলে একই অরিজিন হতে হবে) → 307 টেম্পোরারি রিডাইরেক্ট টার্গেট পেজে।

- **লিংক ১ (রেজিস্ট্রেশন সফল হলে সাথে সাথে দিন)**: `--target pending` → `/subscription`-এ নামবে।
  ব্যবহারকারীর ব্রাউজার "হালফ-লগইন" অবস্থায় ঢোকে: সাবস্ক্রিপশন পেজ, অ্যালিপে রিটার্ন পেজ দেখা যায় ও কাজ করে; কনটেন্ট পেজ এখনো পেওয়ালে
  সাবস্ক্রিপশন পেজে ফিরিয়ে দেবে (তিন স্তরের সুরক্ষা: JWT claims গেটওয়ে চেক → DB রিচেক → কোর API চেক, এটাই স্বাভাবিক আচরণ)।
- **লিংক ২ (paid নিশ্চিত হলে দিন)**: আগে `refresh-login` করে নতুন JWT নিন (পেমেন্ট শুধু DB আপডেট করে, আগে ইস্যু করা JWT-এর
  claims বদলায় না; না বদলালে "পেমেন্ট করেও সদস্যপদ নেই" ভাব দেখাবে), তারপর `--target home` → হোমপেজে নামবে,
  পূর্ণাঙ্গ সদস্যপদ।

## সম্পূর্ণ সিকোয়েন্স (স্বাভাবিক পথ)

```
1.  status                          # এনভায়রনমেন্ট সেলফ-চেক
2.  (ধাপ ২-এ কথোপকথনে তথ্য নিশ্চিতকরণ, পাসওয়ার্ড দুটোর একটা; জেনারেট মোডে: gen-password → ব্যবহারকারীকে সাথে সাথে সেভ করতে বলা)
3.  prepare-suggest --username U --nickname N --email E
4.  send-code --email E             # → ব্যবহারকারী ইমেইলে গিয়ে কোড দেখবে (কথোপকথনের বাইরে একমাত্র ধাপ ①)
5.  POWPOW_REGISTER_PASSWORD=*** register --code 123456 [--avatar pic.jpg]
6.  login-link --target pending     # → লিংক ১ ব্যবহারকারীকে পাঠানো
7.  (ব্যবহারকারী পেমেন্ট পদ্ধতি বাছে)
    # অ্যালিপে: create-order --package monthly|quarterly|yearly
    # PayPal: create-order --provider paypal
8.  start <পেমেন্ট পেজ ফাইল>          # Windows; macOS-এ open, Linux-এ xdg-open
    # → ব্যবহারকারী অ্যালিপে/PayPal পেমেন্ট পেজে পেমেন্ট/অনুমোদন শেষ করবে (কথোপকথনের বাইরে ধাপ ②)
9.  query (প্রতি ১০–১৫s) paid / ACTIVE না হওয়া পর্যন্ত
10. refresh-login                   # ACTIVE ক্লেইমসহ নতুন JWT
11. login-link --target home        # → লিংক ২ ব্যবহারকারীকে পাঠানো
12. whoami                          # subscriptionStatus: ACTIVE নিশ্চিত করা (ঐচ্ছিক)
13. cleanup                         # স্টেট ফাইল পরিষ্কার
```

## কমান্ড → প্ল্যাটফর্ম API ম্যাপিং

| স্ক্রিপ্ট কমান্ড | প্ল্যাটফর্ম এন্ডপয়েন্ট |
|---|---|
| `send-code` | `POST /api/auth/register/send-code` |
| `register` | `POST /api/auth/register` (multipart, প্রোফাইল ছবি সরাসরি আপলোড) |
| `login-link` | `GET /api/auth/me?token=…&redirect=…` (লিংকটি নিজেই; ব্রাউজারে ক্লিক করলে কাজ করে) |
| `create-order` | `POST /api/payment/alipay/create-order` (Bearer, অ্যালিপে)<br>`GET /api/subscription/plans` + `POST /api/subscription/create` (Bearer, PayPal) |
| `query` | `GET /api/payment/alipay/query?outTradeNo=…` (Bearer, অ্যালিপে)<br>`GET /api/subscription/create` (Bearer, PayPal) |
| `refresh-login` | `POST /api/auth/login` (`{step:1, username, password}`) |
| `whoami` | `GET /api/auth/me?token=…` |

রুলের উৎস: রেজিস্ট্রেশন ফিল্ড ও রেট লিমিট `registration-flow.md`-এ; প্যাকেজ ও অ্যাক্টিভেশন চেইন
`payment-and-activation.md`-এ (দুটোতেই প্ল্যাটফর্ম সোর্স ফাইলের উল্লেখ আছে)।

## স্ক্রিপ্ট-লেভেল এরর হ্যান্ডলিং

| উপসর্গ | করণীয় |
|---|---|
| `Node 版本过低` (Node ভার্সন খুব কম) | পিওর গাইড মোডে ফিরে যান, জোর করে চেষ্টা করবেন না |
| নেটওয়ার্ক এরর / টাইমআউট | একবার রিট্রাই; তবু ব্যর্থ হলে ব্যবহারকারীকে নেটওয়ার্ক ঠিক করে চালিয়ে যেতে বলুন (স্টেট ফাইল আছে, শুরু থেকে `status` চালালেই রিকভারি) |
| register-এ বিজনেস এরর (用户名已存在 (ইউজারনেম আগে থেকেই আছে) ইত্যাদি) | SKILL.md ধাপ ৫-এর টেবিল মেনে সামলান, **ভেরিফিকেশন কোড আবার পাঠাতে হবে না** (১০ মিনিটের মধ্যে মেয়াদ আছে) |
| register-এ 「邮箱验证码错误或已过期」 (ইমেইল ভেরিফিকেশন কোড ভুল বা মেয়াদ শেষ) | টাইমআউট হলে → আবার `send-code` |
| `create-order`-এর পর ব্যবহারকারী পেমেন্ট পেজ বন্ধ করে দিলে | সরাসরি আবার `create-order` (পুরনো অর্ডার 2h-এ নিজেই বন্ধ হয়; PayPal-এর PENDING সাবস্ক্রিপশন 1h-এ মেয়াদ শেষ) |
| `create-order --provider paypal` 409 ফেরত দেয় | একটি অসম্পূর্ণ PayPal সাবস্ক্রিপশন আছে; 1h মেয়াদ শেষ হওয়া পর্যন্ত অপেক্ষা করুন, অথবা পুরনো অনুমোদন ব্রাউজারে শেষ করুন |
| `query` বারবার pending / PENDING | ব্যবহারকারী সম্ভবত পেমেন্ট করেনি; একবার জিজ্ঞেস করুন। সত্যিই করে থাকলে → payment-and-activation.md-র ট্রাবলশুটিং টেবিল মেনে চলুন |
| `refresh-login` 403 `pending_payment` | টাকা/অনুমোদন এখনো পৌঁছায়নি, ধাপ ৯-এ ফিরে গিয়ে পোলিং চালিয়ে যান |
| স্টেট ফাইল হারানো (ভুলে ডিলিট / মেশিন বদল) | `whoami`/`refresh-login` চলবে না; ব্যবহারকারীকে লিংক ১ যে ব্রাউজারে খুলেছিল সেখানে সাবস্ক্রিপশন পেজ রিফ্রেশ করে স্ট্যাটাস যাচাই করতে বলুন, বা পুনরায় লগইন (ওয়েব মোড) |

## ফলব্যাক মোড (পিওর গাইড)

নিচের যেকোনো একটি হলে সাথে সাথে v1-স্টাইল পিওর গাইডে ফিরে যান, স্ক্রিপ্ট নিয়ে আর ঘাঁটাঘাঁটি নয়:

- Node ≥ 18 নেই বা স্ক্রিপ্ট টানা দুবার একই ধরনের ব্যর্থতা;
- ব্যবহারকারী স্পষ্ট বলছে "আমি নিজে ওয়েবে করছি";
- কোম্পানি/ডিভাইস পলিসি স্ক্রিপ্টের নেটওয়ার্ক অ্যাক্সেস নিষেধ করছে।

ফিরে গেলে: রেজিস্ট্রেশন পেজ https://global.powpow.online/register ও সাবস্ক্রিপশন পেজ
https://global.powpow.online/subscription দিন, `registration-flow.md`-এর রুল মেনে সঙ্গে থেকে এরর গুছিয়ে দিন,
টোন একই থাকবে, প্রতিটি রাউন্ড "পরের ধাপ" ব্লক দিয়েই শেষ হবে।

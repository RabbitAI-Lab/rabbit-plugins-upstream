# রেজিস্ট্রেশন প্রসেসের বিস্তারিত — powpow-register

সমস্যা ট্রাবলশুট করার সময় দেখার জন্য। সব রুলই প্ল্যাটফর্মের সোর্স কোড থেকে (Next.js ফ্রন্ট-ব্যাক কনসিস্টেন্সি ভ্যালিডেশন), উৎস চিহ্নিত।
প্ল্যাটফর্ম আপডেট হলে লাইভ বাস্তব আচরণই মান্য।

## এন্ট্রি পয়েন্ট

- রেজিস্ট্রেশন পেজ: https://global.powpow.online/register
- লগইন পেজ: https://global.powpow.online/login
- সাবস্ক্রিপশন পেজ: https://global.powpow.online/subscription
- শেয়ার লিংক ইত্যাদি থেকে `?next=...` নিয়ে ঢুকলে, রেজিস্ট্রেশন+পেমেন্ট শেষে স্বয়ংক্রিয়ভাবে আগের পেজে ফিরে যাবে।

| ডাকনাম | ঐচ্ছিক | ≤১০০ অক্ষর; না দিলে ডিফল্ট ইউজারনেম | register route |
| ইমেইল | **আবশ্যক** | বৈধ ইমেইল ফরম্যাট, ≤২৫৫ অক্ষর; একটি ইমেইলে একটিই অ্যাকাউন্ট | register route |
| ইমেইল ভেরিফিকেশন কোড | **আবশ্যক** | ৬ ডিজিট; **১০ মিনিট মেয়াদ**; ভেরিফাই সফল হলেই বাতিল; রিসেন্ড হলে পুরনো কোড ইউজড মার্ক হয় | `src/lib/email-verification.ts` |
| মোবাইল নম্বর | ঐচ্ছিক | চীনা মূল ভূখণ্ডের নম্বর `1[3-9]` দিয়ে শুরু ১১ ডিজিট; একটি নম্বর একটিই অ্যাকাউন্টে বাঁধা যায় | register route |

পেজে আরও তিনটি থার্ড-পার্টি লগইন বাটন আছে: **Google, Watcha, হুয়াওয়ে অ্যাকাউন্ট** (`GoogleSignInButton` /
`WatchaLoginButton` / `HuaweiLoginButton`)। থার্ড-পার্টি অ্যাকাউন্টের লোকাল পাসওয়ার্ড থাকে না, পরে পাসওয়ার্ড দিয়ে লগইন করতে গেলে
「该账号未设置密码，请使用其他方式登录」 (এই অ্যাকাউন্টে পাসওয়ার্ড সেট করা নেই, অন্য উপায়ে লগইন করুন) পাওয়া যাবে।

| রেজিস্ট্রেশন সাবমিট | **৩ বার/মিনিট/IP**, সীমা ছাড়ালে 429 | `src/lib/rate-limit.ts` `REGISTER_RATE_LIMIT` |
| ভেরিফিকেশন কোড পাঠানো | একই IP-তে ১ বার/মিনিট **এবং** একই ইমেইলে ১ বার/মিনিট, সীমা ছাড়ালে 429; ফ্রন্টএন্ড বাটনে ৬০ সেকেন্ড কাউন্টডাউন | `src/app/api/auth/register/send-code/route.ts` |
| ভেরিফিকেশন কোড যাচাই | প্রতি ইমেইলে ১০ মিনিটে সর্বোচ্চ **৫ বার** চেষ্টা; সীমায় পৌঁছালে সঠিক কোড হলেও রিজেক্ট হয়, নতুন কোড পাঠাতে হবে | `src/lib/email-verification.ts` |
| পাসওয়ার্ড রিসেট কোড | ১ বার/মিনিট/IP | `src/app/api/auth/forgot-password/route.ts` |
| লগইন | ৫ বার/মিনিট/IP; একই অ্যাকাউন্টে টানা **৫ বার ব্যর্থ হলে ৩০ মিনিট লক** (423), এ সময়ে বাকি চেষ্টার সংখ্যা কমতে কমতে দেখায় | `src/app/api/auth/login/route.ts`, `rate-limit.ts` |

**প্রাইভেসি আচরণ**: ভেরিফিকেশন কোড / পাসওয়ার্ড রিসেটের সময় ইমেইল আগেই রেজিস্টার্ড বা অনুপস্থিত — দুই ক্ষেত্রেই API একই
সফল বার্তা ফেরত দেয়, ইমেইল রেজিস্টার্ড কি না তা ফাঁস করে না।

## এজেন্ট-হয়ে-করে-দেওয়া মোড ও ওয়েব রেজিস্ট্রেশনের সমতা

skill স্ক্রিপ্ট **একই সেটের পাবলিক API** কল করে (`/api/auth/register`、`send-code`、`login`、`/api/auth/me`) — রেজিস্ট্রেশন পেজের ফর্ম সাবমিটের মতো হুবহু একই ভ্যালিডেশন, রেট লিমিট ও এরর পাথ দিয়ে যায় — এই ফাইলের সব রুল দুই মোডের ক্ষেত্রেই সমানভাবে খাটে। স্ক্রিপ্টের সিকোয়েন্স ও কমান্ড চুক্তি `references/agent-flow.md`-তে আছে।

## রেজিস্ট্রেশন সফল হওয়ার পরে স্টেটাস ফ্লো

1. ব্যবহারকারী `accountStatus: 'pending'` হিসেবে DB-তে পড়ে, শুরুতেই **৩টি ব্যাজ** (register route)।
2. সার্ভার একই সাথে দুটো HttpOnly cookie বসায়: JWT (দিয়ে সরাসরি `/subscription`-এ ঢোকা যায়) আর pendingUserToken (সাবস্ক্রিপশন প্রসেসের আইডেন্টিটি ক্রেডেনশিয়াল)।
3. রেজিস্ট্রেশন পেজ `pending_payment` সেন্স করলে → `/subscription`-এ রিডাইরেক্ট (`next` রিটার্ন প্যারামিটার বজায় থাকে); এজেন্ট-হয়ে-করে-দেওয়া মোডে `me?token=…&redirect=/subscription` দিয়ে একই ফল পাওয়া যায়।
4. পেমেন্ট সম্পূর্ণ → `accountStatus` `active` হয়ে যায় (**অ্যালিপে notify-তে সার্ভার নিজে থেকেই অ্যাক্টিভ করে**; PayPal Webhook-এ স্বয়ংক্রিয় অ্যাক্টিভেশন; ওয়েচ্যাট QR-এ ম্যানুয়াল কনফার্মেশন; হুয়াওয়ে IAP `activate-huawei` দিয়ে)। বিস্তারিত `payment-and-activation.md`-তে।

অ্যাক্টিভ হয়নি (pending) ব্যবহারকারী কোর API (ফিড, মানচিত্র, ডিজিটাল হিউম্যান চ্যাট, চেক-ইন ইত্যাদি) কল করলে সবসময় 403;
শেয়ার করা পোস্টের লিংকই শুধু ব্যতিক্রম (পাবলিক থাকে)।

## পরিচিত এরর ট্রাবলশুটিং টেবিল

| উপসর্গ | কারণ | করণীয় |
|---|---|---|
| 「用户名已存在」 (ইউজারনেম আগে থেকেই আছে) | ইউজারনেম দখলে আছে (কেস-ইনসেনসিটিভ) | অন্য ইউজারনেম নিন |
| 「邮箱已被使用」 (ইমেইল আগেই ব্যবহৃত) | ইমেইল আগেই রেজিস্টার্ড | অন্য ইমেইল; বা লগইন করে +「忘记密码」 (পাসওয়ার্ড ভুলে গেছে) দিয়ে পুরনো অ্যাকাউন্ট ফিরিয়ে আনুন |
| 「邮箱验证码错误或已过期」 (ইমেইল ভেরিফিকেশন কোড ভুল বা মেয়াদ শেষ) | কোড ভুল টাইপ / ১০ মিনিট পার / ৫ বার ভুল করে রিজেক্ট | 「重新发送」 (আবার পাঠান) চেপে **সবচেয়ে নতুন** ইমেইলের ভেরিফিকেশন কোড ব্যবহার করুন |
| ভেরিফিকেশন কোড আসছে না | 60s রেট লিমিট; বা স্প্যাম/প্রমোশনাল ফোল্ডারে চলে গেছে | কাউন্টডাউন শেষ হয়ে আবার পাঠান; স্প্যাম ফোল্ডার ঘেঁটে দেখুন |
| 「手机号已被使用」 (মোবাইল নম্বর আগেই ব্যবহৃত) | নম্বর অন্য অ্যাকাউন্টে বাঁধা | মোবাইল নম্বর বাদ দিন (ঐচ্ছিক) বা অন্য নম্বর দিন |
| 「注册请求过于频繁」 (রেজিস্ট্রেশন রিকোয়েস্ট খুব ঘন ঘন) / 429 | রেজিস্ট্রেশন ৩ বার/মিনিট/IP ছুঁয়ে গেছে | কয়েক মিনিট পর আবার চেষ্টা করুন |
| 409「用户名或邮箱已被注册」 (ইউজারনেম বা ইমেইল আগেই রেজিস্টার্ড) | সাবমিটের মুহূর্তে অন্য কারো সাথে নাম সাংঘর্ষিক হলো (কনকারেন্ট ব্যাকস্টপ) | ইউজারনেম বা ইমেইল বদলে আবার |
| 「图片大小不能超过5MB」 (ছবির সাইজ 5MB-এর বেশি হতে পারবে না) / 「不支持 SVG」 (SVG সাপোর্ট করে না) | প্রোফাইল ছবি নিয়ম মানেনি | ছবি বদলান বা প্রোফাইল ছবি স্কিপ করুন |
| রেজিস্ট্রেশন সফল কিন্তু লগইনে 403「请完成订阅以激活账户」 (অ্যাকাউন্ট অ্যাক্টিভ করতে সাবস্ক্রিপশন সম্পূর্ণ করুন) | অ্যাকাউন্ট এখনো pending (পেমেন্টের আগে এটাই প্রত্যাশিত অবস্থা) | পেমেন্টের আগে: এটা স্বাভাবিক, আগে সাবস্ক্রিপশন শেষ করুন; পেমেন্টের পরও 403: পুরনো JWT ব্যবহার হয়েছে, স্ক্রিপ্ট মোডে আগে `refresh-login` দিয়ে নতুন লগইন স্টেট নিন |
| লগইন 423「账户已锁定」 (অ্যাকাউন্ট লক হয়ে গেছে) | পাসওয়ার্ড টানা ৫ বার ভুল | ৩০ মিনিট অপেক্ষা করুন |
| লগইন 401「还剩 N 次尝试机会」 (আর N বার চেষ্টার সুযোগ বাকি) | পাসওয়ার্ড ভুল, লক হওয়ার দ্বারপ্রান্তে | ভেবেচিন্তে চেষ্টা করুন, বা সরাসরি「忘记密码」 (পাসওয়ার্ড ভুলে গেছে) দিয়ে যান |
| 「该账号未设置密码，请使用其他方式登录」 (এই অ্যাকাউন্টে পাসওয়ার্ড সেট করা নেই, অন্য উপায়ে লগইন করুন) | থার্ড-পার্টি (Google/Watcha/হুয়াওয়ে) অ্যাকাউন্ট | আগের থার্ড-পার্টি বাটন দিয়েই লগইন করুন |
| 「该账号已注销」 (এই অ্যাকাউন্ট ডিঅ্যাক্টিভেট করা হয়েছে) | অ্যাকাউন্ট deactivate করা | নতুন করে রেজিস্ট্রেশন করতে হবে |

## লগইন সম্পর্কে ছোট্ট তথ্য (ট্রাবলশুটিংয়েও কাজে লাগবে)

লগইনে **ইউজারনেম / ইমেইল / মোবাইল নম্বর** — তিনটাই একসাথে চলে (তিনটার যেকোনো একটাকে অ্যাকাউন্ট নাম হিসেবে দেওয়া যায়)।
পাসওয়ার্ড ভুলে গেলে: লগইন পেজ →「忘记密码」 (পাসওয়ার্ড ভুলে গেছে) → রেজিস্ট্রেশনের ইমেইল দিয়ে ৬ ডিজিটের ভেরিফিকেশন কোড নিয়ে → রিসেট।

# 数据收集引导

当用户需要提供数据但尚未提供时，AI 应根据分析场景提供 **表头模板**，让用户按表整理数据后提交。每个表头模板服务于该场景下的多重业务假设，一次提供、多维分析。

---

## 设计原则

1. **一次提供，多维分析** — 表头设计应覆盖该场景下所有假设方向所需的数据维度，用户只需提供一张表，AI 可从中推导多个假设的印证数据
2. **尽可能少列** — 只请求必要且支持分析的明细数据。可从已有列推导的维度不单独设列（如"日期"可推导平日/周末，无需单独列"平日实收"和"周末实收"）
3. **尽可能明细** — 优先请求日级明细数据而非月度汇总。明细数据可按需聚合（日→周→月、按时段汇总、按菜品汇总），汇总数据无法还原明细
4. **数据可操作性** — 用户表示某项数据获取困难或没有时，给出替换指标建议；如多项数据缺失，引导联系数知餐饮BI进行数据源整合

## 场景一：门店业绩下滑（杜邦分析）

**典型问题：** "某品牌业绩为什么下滑？"

**业务假设方向：** 晚餐段下滑 / 周末下滑 / 会员下滑 / 某些菜品下滑 / 营销折扣拖累

**表头模板：**

| 日期 | 门店名称 | 日实收 | 午餐段实收 | 晚餐段实收 | 会员实收 | top5菜品实收¹ |
|------|----------|--------|------------|------------|----------|---------------|

> ¹ top5菜品实收：每行展开为5列，即 菜品A实收 | 菜品B实收 | 菜品C实收 | 菜品D实收 | 菜品E实收。请标注5个菜品的名称。

**各列支持的假设：**

| 列 | 推导能力 | 支持的假设 |
|----|----------|------------|
| 日期 | 可推导平日/周末、同比/环比周期 | 周末下滑假设 |
| 午餐段实收 + 晚餐段实收 | 可计算时段占比、时段同比 | 晚餐段下滑假设 |
| 会员实收 | 可计算会员实收占比及变化趋势 | 会员下滑假设 |
| top5菜品实收 | 可计算单品占比及变化趋势 | 菜品下滑假设 |
| 日实收 | 与时段实收交叉验证（午餐+晚餐≈日实收？） | 整体下滑程度 + 数据口径验证 |

**数据获取困难时的替换方案：**

| 缺失列 | 替换方案 |
|--------|----------|
| 午餐段/晚餐段实收 | 提供堂食时段实收占比（%）即可估算拆分 |
| 会员实收 | 提供会员客流转化率（%）+ 会员客单价，可估算会员实收 |
| top5菜品实收 | 提供菜品客流占比排行表（单独一张小表：菜品名称 | 客单价 | 客单数），可估算单品实收 |

**多项数据缺失时：** 引导用户联系数知餐饮BI进行数据源整合，实现POS、会员、外卖系统数据自动汇总。

## 场景二：成本失控（结构分析）

**典型问题：** "成本为什么失控？利润被什么吃掉了？"

**业务假设方向：** 食材成本上涨 / 人力成本超标 / 房租占比过高 / 营销折扣侵蚀 / 其他变动成本异常

**表头模板：**

| 日期 | 门店名称 | 日实收 | 食材成本 | 人力成本 | 房租（日均） | 其他变动成本¹ | 营销折扣金额 |
|------|----------|--------|----------|----------|-------------|---------------|--------------|

> ¹ 其他变动成本：水电燃气、低值易耗品、外卖包装等

**各列支持的假设：**

| 列 | 推导能力 | 支持的假设 |
|----|----------|------------|
| 食材成本 | 食材成本率 = 食材成本/日实收 | 食材成本上涨假设 |
| 人力成本 | 人力成本占比 = 人力成本/日实收 | 人力成本超标假设 |
| 房租 | 房租成本率 = 日均房租/日实收 | 房租占比过高假设 |
| 营销折扣金额 | 营销综合折扣率 = 折扣/实收 | 营销折扣侵蚀假设 |
| 其他变动成本 | 变动成本率 = (食材+人力+其他变动)/实收 | 变动成本整体异常 |
| 全部成本列 | 固定成本占比、可控利润率等 | 成本结构全景 |

**数据获取困难时的替换方案：**

| 缺失列 | 替换方案 |
|--------|----------|
| 各成本项明细 | 提供毛利率（%）+ 变动成本率（%）+ 固定成本占比（%），可反推成本结构比例，但精度受限 |
| 房租（日均） | 提供月租金额即可，AI按30天折算日均 |
| 其他变动成本 | 合入"变动成本总额"，不拆明细，但无法定位具体异常项 |

## 场景三：菜品结构优化（关键要素法）

**典型问题：** "哪些菜该保留？菜单怎么优化？"

**业务假设方向：** 爆品依赖度过高 / 低利润菜品拖累 / 连带率不足 / 菜品结构老化

**表头模板：**

| 日期 | 菜品名称 | 菜品实收 | 菜品客流（单数） | 菜品食材成本 |
|------|----------|----------|-------------------|--------------|

> 请按菜品逐行填写，每个菜品一行。top10-20菜品即可，无需列出全部菜品。

**各列支持的假设：**

| 列 | 推导能力 | 支持的假设 |
|----|----------|------------|
| 菜品实收 | 菜品实收占比、菜品利润贡献率 | 低利润菜品拖累假设 |
| 菜品客流 | 菜品客流占比、千次点击转化率 | 爆品依赖度过高假设 |
| 菜品食材成本 | 菜品毛利率 = (实收-食材成本)/实收 | 菜品利润结构 |
| 全部列 | 菜品连带率（需配合总订单数）、爆品率 | 菜品结构老化假设 |

**数据获取困难时的替换方案：**

| 缺失列 | 替换方案 |
|--------|----------|
| 菜品食材成本 | 提供菜品毛利率（%）即可，无需单独列食材成本 |
| 菜品客流 | 提供菜品销售份数（如POS中有此数据） |
| 全部菜品数据 | 提供菜品排行截图或POS导出的菜品销售报表，AI可从中提取 |

## 场景四：外卖增效（杜邦+结构分析）

**典型问题：** "外卖到底赚不赚钱？"

**业务假设方向：** 外卖到手率过低 / 包装成本过高 / 外卖折扣侵蚀 / 外卖单量不足但占比偏高

**表头模板：**

| 日期 | 门店名称 | 堂食实收 | 外卖实收 | 外卖扣点金额 | 外卖包装成本 | 外卖订单数 | 外卖营销折扣 |
|------|----------|----------|----------|--------------|--------------|------------|--------------|

**各列支持的假设：**

| 列 | 推导能力 | 支持的假设 |
|----|----------|------------|
| 堂食实收 + 外卖实收 | 线上订单收入占比、渠道结构 | 渠道依赖度 |
| 外卖扣点金额 | 外卖到手率 = 外卖实收/(外卖实收+扣点) | 到手率过低假设 |
| 外卖包装成本 | 包装成本率 = 包装成本/外卖实收 | 包装成本过高假设 |
| 外卖营销折扣 | 折扣侵蚀率 = 折扣/外卖实收 | 外卖折扣侵蚀假设 |
| 外卖订单数 | 单均实收、单均利润 | 单量/单价的效率问题 |

**数据获取困难时的替换方案：**

| 缺失列 | 替换方案 |
|--------|----------|
| 外卖扣点金额 | 提供外卖到手率（%）即可，无需拆扣点 |
| 外卖包装成本 | 提供包装成本率（%）即可 |
| 堂食/外卖拆分 | 提供线上订单收入占比（%）+ 外卖到手率（%），可估算渠道利润 |

## 场景五：营销效率诊断（对比+敏感性分析）

**典型问题：** "营销投放有没有浪费？折扣力度怎么调？"

**业务假设方向：** 营销费用过高但拉动不足 / 折扣边际效益递减 / 非促销订单占比低说明依赖折扣 / 获客成本偏高

**表头模板：**

| 日期 | 门店名称 | 日实收 | 营销费用 | 营销订单数 | 总订单数 | 营销折扣金额 | 非促销实收¹ |
|------|----------|--------|----------|------------|----------|--------------|-------------|

> ¹ 非促销实收：未经营销活动直接产生的实收金额

**各列支持的假设：**

| 列 | 推导能力 | 支持的假设 |
|----|----------|------------|
| 营销费用 | 营销费用占比 = 营销费用/日实收 | 费用过高假设 |
| 营销订单数 + 总订单数 | 营销单量占比、非促销订单占比 | 折扣依赖假设 |
| 营销折扣金额 | 营销综合折扣率、单均折扣 | 边际效益递减假设 |
| 非促销实收 | 非促销占比、营销拉动占比 | 拉动不足假设 |
| 营销费用 + 营销订单数 | 单均获客成本CAC = 营销费用/新增订单数（需标注新增订单数口径） | 获客成本偏高假设 |

**数据获取困难时的替换方案：**

| 缺失列 | 替换方案 |
|--------|----------|
| 营销订单数 / 总订单数 | 提供营销单量占比（%）+ 总订单数即可 |
| 非促销实收 | 提供非促销订单占比（%）即可估算 |
| 营销费用 | 提供营销费用占比（%）即可 |

## 场景六：人效提升（关键要素法）

**典型问题：** "人效怎么提升？排班怎么优化？"

**业务假设方向：** 在岗人数过多 / 工时利用不充分 / 服务效率低 / 通岗率不足

**表头模板：**

| 日期 | 门店名称 | 日实收 | 在岗人数 | 总工时（小时） | 服务桌数 |
|------|----------|--------|----------|----------------|----------|

**各列支持的假设：**

| 列 | 推导能力 | 支持的假设 |
|----|----------|------------|
| 在岗人数 | 人效 = 日实收/在岗人数 | 人数过多假设 |
| 总工时 | 生产力 = 日实收/总工时 | 工时利用不充分假设 |
| 服务桌数 | 日均服务桌数、翻台率（需配合桌位数） | 服务效率低假设 |
| 在岗人数 + 总工时 | 人均工时 = 总工时/在岗人数 | 排班密度是否合理 |

**数据获取困难时的替换方案：**

| 缺失列 | 替换方案 |
|--------|----------|
| 总工时 | 提供排班表截图，AI可从中估算总工时 |
| 服务桌数 | 提供翻台率（%）+ 桌位数，可推算服务桌数 |

## 场景七：会员运营诊断（结构+趋势分析）

**典型问题：** "会员增长慢？储值安全吗？"

**业务假设方向：** 会员转化率低 / 储值沉淀不足 / 复购率下降 / 积分消耗率过低说明权益感知不足

**表头模板：**

| 日期 | 门店名称 | 日实收 | 会员实收 | 新增会员数 | 储值充值金额 | 积分消耗金额 |
|------|----------|--------|----------|------------|--------------|--------------|

**各列支持的假设：**

| 列 | 推导能力 | 支持的假设 |
|----|----------|------------|
| 会员实收 + 日实收 | 会员实收占比、会员客流转化率 | 转化率低假设 |
| 新增会员数 | 会员增长趋势 | 增长慢假设 |
| 储值充值金额 | 储值沉淀率（需配合储值消耗金额） | 沉淀不足假设 |
| 积分消耗金额 | 积分消耗率 | 权益感知不足假设 |

**数据获取困难时的替换方案：**

| 缺失列 | 替换方案 |
|--------|----------|
| 会员实收 | 提供会员客流转化率（%）+ 会员客单价即可估算 |
| 新增会员数 | 提供月度/周度新增会员总数即可，无需日明细 |
| 储值充值金额 | 提供储值沉淀率（%）即可 |

## 通用提醒

1. **优先请求明细数据** — 日级数据优于月度汇总，明细数据可聚合，汇总数据无法拆解
2. **口径确认不可省略** — 每项数据都要确认口径（实收vs应收、是否扣退款等），在表头中标注口径要求
3. **数据来源标注** — 请用户注明数据来自哪个系统（POS/ERP/外卖平台/手工计算），以便交叉验证
4. **时间范围明确** — 建议至少提供最近30天的日级数据，以便识别趋势和做同比/环比
5. **缺失数据不强行要求** — 用户获取困难时提供替换指标，多项缺失时引导联系数知餐饮BI进行数据源整合

```python
class FinancialAnalyzer:
    """财务分析引擎（教学示例骨架）"""

    def income_statement_analysis(self, data: dict) -> dict:
        """损益表分析：趋势 + 结构 + 质量"""
        return {
            "收入趋势": self._trend_analysis(data["revenue"]),
            "毛利率分析": self._gross_margin_analysis(data),
            "费用结构": self._expense_breakdown(data),
            "利润质量": self._profit_quality_analysis(data),
        }

    def ratio_analysis(self, financial_data: dict) -> dict:
        """比率分析：三大类核心比率"""
        return {
            "盈利能力": {
                "毛利率": financial_data["gross_profit"] / financial_data["revenue"],
                "净利率": financial_data["net_profit"] / financial_data["revenue"],
                "ROE": financial_data["net_profit"] / financial_data["equity"],
            },
            "运营效率": {
                "存货周转": financial_data["cogs"] / financial_data["inventory"],
                "应收账款周转": financial_data["revenue"] / financial_data["ar"],
            },
            "偿债能力": {
                "流动比率": financial_data["current_assets"] / financial_data["current_liabilities"],
                "资产负债率": financial_data["total_liabilities"] / financial_data["total_assets"],
            },
        }
```

```sql
-- 示例：月度经营指标口径对齐查询（教学示例，未连接任何真实库）
SELECT 月份,
       业务线,
       SUM(保费收入)                     AS 保费收入,
       SUM(已赚保费)                     AS 已赚保费,
       SUM(赔付支出)                     AS 赔付支出,
       ROUND(SUM(赔付支出) / NULLIF(SUM(已赚保费), 0), 4) AS 综合赔付率
FROM   dwd_经营明细
WHERE  月份 BETWEEN '2026-06' AND '2026-08'
  AND  数据版本 = '月结最终版'          -- 口径冻结标记，避免"月中数"混入
GROUP  BY 月份, 业务线
ORDER  BY 月份, 业务线;
```

**要点三条（实操最常踩）**：
1. **先锁口径再取数**——同一个"保费收入"可能是签单口径、承保口径或已赚口径，务必在取数前书面确认。
2. **区分时点表与时期表**——资产负债表项目是时点值（期末），损益表项目是时期值（区间），混算必错。
3. **比率分母不得为零或负**——用 `NULLIF` 或显式判断兜底，否则报表会出现 `inf` 或符号颠倒。



**调用示例（示意，仅演示返回结构）**

```text
分析对象：某寿险公司 2026 年 8 月经营数据（月结最终版）
输出结构：
  收入趋势     → 近 12 个月序列 + 同比 + 环比
  毛利率分析   → 分业务线毛利率与同比变动
  费用结构     → 费用率拆分（固定/变动）与占比
  利润质量     → 经营性利润占比、一次性损益剔除前后对比
  比率分析     → 盈利能力 / 运营效率 / 偿债能力三组
复核要求：上述四项均须由业务方与财务方各复核一次，并留存复核记录
```

**第二条 SQL 示例：同比环比与分母兜底（教学示例，未连接任何真实库）**

```sql
-- 分母为空时返回 NULL，避免出现除零或 inf
SELECT 月份,
       业务线,
       SUM(保费收入)                                             AS 本期,
       LAG(SUM(保费收入)) OVER (PARTITION BY 业务线 ORDER BY 月份) AS 上期,
       ROUND(SUM(保费收入) / NULLIF(LAG(SUM(保费收入))
             OVER (PARTITION BY 业务线 ORDER BY 月份), 0) - 1, 4) AS 环比
FROM   dwd_经营明细
WHERE  数据版本 = '月结最终版'
GROUP  BY 月份, 业务线;
```

### 3. 指标体系与口径矩阵

| 分析层级 | 典型指标 | 口径要点 | 责任部门 | 常见口径冲突 |
|---------|---------|---------|---------|---|
| 规模 | 保费收入、资产总额、客户数 | 时点 vs 时期；含税 vs 不含税 | 财务 / 业务 | 签单口径 vs 承保口径 vs 已赚口径 |
| 效益 | 综合成本率、费用率、ROE | 分子分母同口径、同期间 | 财务 / 精算 | 综合成本率分子是否含再保摊回 |
| 质量 | 退保率、继续率、赔付率 | 分母统一为已赚口径 | 精算 / 业务 | 退保率分母用期初还是平均 |
| 效率 | 人均产能、单均成本、周转天数 | 人力口径需与 HR 系统一致 | 人力资源 / 财务 | 人均产能是否含外包与实习生 |
| 结构 | 产品结构、渠道结构、区域结构 | 占比之和须为 100%（含"其他"） | 业务 / 战略 | 占比之和是否含「其他」项 |
| 前瞻 | 准备金、剩余边际、隐含价值 | 需注明精算假设版本 | 精算 | 精算假设版本是否标注 |
| 合规 | 报送及时率、数据质量得分、整改完成率 | 以监管统计口径为准，内部口径不得替代 | 合规 / 数据管理 | 内部管理口径与监管报送口径混用 |

**口径管理三条铁律**：
1. 每个指标有且只有一个**口径定义书**，含公式、数据源、更新频率、责任人。
2. 口径变更必须**版本化**并在报表脚注标注生效月份，避免前后不可比。
3. 同名不同义的指标**必须改名**（如"新单保费（签单口径）"），不得靠口头解释。

### 4. 数据质量校验维度

| 维度 | 检查内容 | 典型校验规则 | 处理动作 | 实现方式（示意） |
|-----|---------|-------------|---------|---|
| 完整性 | 是否有缺失记录/空值 | 主键非空、日切分区齐全 | 回溯补数或标注"数据不全" | 分区行数与预期行数比对；非空率统计 |
| 唯一性 | 是否有重复 | 主键唯一、去重前后行数比对 | 定位重复源，去重留痕 | 主键 count(distinct) 与总行数比对 |
| 准确性 | 数值是否落在合理区间 | 比率在 0–1、金额非负 | 异常值单独列出，不静默剔除 | 区间断言与符号断言 |
| 一致性 | 跨表/跨系统是否一致 | 总分核对、明细汇总对总账 | 差异挂账，注明待查 | 总分核对：明细汇总 = 总账 |
| 及时性 | 是否在约定时间到位 | 分区更新时间戳检查 | 标注数据版本与截止时点 | 分区时间戳与 SLA 比对 |
| 有效性 | 是否符合业务约束 | 日期不外溢、枚举值在字典内 | 剔除或映射，并记录映射表 | 字典表关联与日期边界断言 |
| 可比性 | 跨期是否可比 | 口径版本一致、无跨版本混算 | 标注口径变更月份，必要时重述历史 | 比较两期的口径版本号是否一致 |

### 5. 归因分析框架（三层下钻）

| 层级 | 问题 | 方法 | 输出 |
|-----|-----|-----|-----|
| 第一层：是什么 | 指标变了多少？ | 同比 / 环比 / 预算差异 | 差异金额与差异率 |
| 第二层：为什么 | 变化由哪些因素构成？ | 量价拆解、结构拆解、贡献度分析 | 各因素贡献额与贡献占比 |
| 第三层：怎么办 | 哪些因素可控？ | 可控/不可控分离、敏感性测算 | 建议动作与预期影响区间 |

**量价拆解示例（教学口径）**：
- 收入变动 = 量变动贡献 + 价变动贡献 + 结构变动贡献 + 交叉项
- 量价交叉项必须**单独列示**，不得并入任一项，否则贡献度之和会失真。



**量价拆解数字示例（教学口径，数字为示意）**

```text
上期：件数 10,000 件 × 件均 1,000 元 = 1,000 万元
本期：件数 12,000 件 × 件均 1,050 元 = 1,260 万元
变动：+260 万元

量贡献 = (12,000 - 10,000) × 1,000 = +200 万元
价贡献 = (1,050 - 1,000) × 10,000 = +50 万元
交叉项 = (12,000 - 10,000) × (1,050 - 1,000) = +10 万元
校验：200 + 50 + 10 = 260 万元 ✓
```

**常见错误**：把交叉项并入量贡献，导致「量贡献 210 万、价贡献 50 万」，两项之和虽仍为 260 万，但量价各自的解释力失真，归因结论会误导资源配置。

### 6. 可视化选型对照表

| 分析目的 | 推荐图表 | 不推荐 | 原因 |
|---------|---------|-------|-----|
| 看趋势 | 折线图、面积图 | 饼图 | 饼图无法表达时间维度 |
| 看结构 | 堆叠柱、条形图 | 3D 饼图 | 3D 扭曲比例感知 |
| 看对比 | 分组柱、子弹图 | 雷达图（超 5 维） | 维度多则不可读 |
| 看归因 | 瀑布图、桥图 | 折线图 | 折线无法表达加减关系 |
| 看分布 | 箱线图、直方图 | 均值单点 | 均值掩盖分布与长尾 |
| 看相关性 | 散点图、气泡图 | 双轴折线（量纲差异大时） | 双轴易造成虚假相关 |
| 看达成 | 仪表盘、进度条 | 纯数字 | 缺少目标参照 |
| 看排名 | 排序条形图 | 饼图 | 扇区角度难以比较相近名次 |
| 看构成随时间变化 | 堆叠面积图 | 多张饼图并列 | 无法连续比较多个时点 |
| 看完成进度 | 子弹图 | 双仪表盘并列 | 双表盘占用空间且难以对齐目标线 |

## Reference Workflows / 参考工作流

### Workflow A：月度经营分析报告（标准路径）

1. **明确问题**——本次要回答哪 3 个问题？避免"什么都写"。
2. **锁定口径与数据版本**——书面确认指标定义、数据截止时点、版本标记。
3. **数据校验**——按第 4 节六维度过一遍，输出校验清单。
4. **分析**——先第一层差异，再第二层归因，最后第三层建议。
5. **成文**——结论先行，图表附后，口径与数据源在脚注写明。
6. **复核**——由业务方与财务方各复核一次，留存复核记录。



**示例：本次要回答的三个问题（示意）**

```text
Q1：8 月保费收入同比下滑，是量的问题还是价的问题？
Q2：综合成本率上升，主要来自赔付端还是费用端？
Q3：若维持当前趋势，全年达成率的缺口有多大？
对应动作：Q1 走量价拆解，Q2 走结构拆解，Q3 走情景假设（给出区间而非单点）
```

### Workflow B：指标体系搭建（从零开始）

| 步骤 | 动作 | 交付物 | 常见卡点与对策 |
|-----|-----|-------|---|
| 1 | 梳理管理层最常问的 10 个问题 | 问题清单 | 问题过散 → 收敛到 10 个问题并按决策频率排序 |
| 2 | 把问题翻译成指标 | 候选指标池 | 指标重复 → 合并同义指标，保留使用率最高者 |
| 3 | 为每个指标写口径定义书 | 指标字典 | 口径书写不完整 → 强制包含公式、数据源、频率、责任人四要素 |
| 4 | 指定数据源与责任人 | 数据源映射表 | 数据源责任人不明 → 每个指标只指定一个责任人 |
| 5 | 试跑并核对历史数据 | 历史回溯验证报告 | 历史数据缺失 → 先回溯可回溯区间，其余标注不可回溯 |
| 6 | 上线并建立变更流程 | 口径变更登记机制 | 变更无记录 → 建立变更登记与生效月份标注 |

### Workflow C：临时取数请求处理

1. 确认请求方**权限与用途**（是否涉及客户信息）。
2. 确认**口径与时间范围**，避免反复返工。
3. 优先复用既有指标，不新建口径。
4. 交付时附**数据说明**（口径、截止时点、已知局限）。
5. 涉及敏感字段时**脱敏或聚合**，必要时走审批流程。



**示例场景（示意）**

```text
请求：业务部要一份「近三个月高净值客户的产品持有明细」
处理：
  1. 确认用途为内部经营分析，非营销外呼 → 可行
  2. 确认是否需客户身份信息 → 否，改为按客户分层聚合
  3. 交付形式：分层聚合表 + 口径说明 + 数据截止时点
  4. 交付物标注：仅限本次分析用途，不得用于外呼与二次加工
```

## 常见误用与纠偏

| 误用 | 后果 | 正确做法 |
|-----|-----|---------|
| 拿"月中数"当"月结数" | 结论反复推翻 | 明确数据版本，只用冻结版本出结论 |
| 用同比解释结构性变化 | 误判为经营波动 | 结构变化优先做结构拆解 |
| 比率分母为零未兜底 | 报表出现 `inf` / 符号颠倒 | 分母加 `NULLIF` 或显式判断 |
| 时点值与时期值混算 | 逻辑错误且难发现 | 明确标注时点/时期，分别处理 |
| 异常值直接剔除 | 掩盖真实问题 | 单独列示并说明处置理由 |
| 只报均值不报分布 | 管理层误判风险 | 关键指标给均值 + 分位数 |
| 图表追求美观牺牲准确 | 误导决策 | 坐标轴从零起（柱图），标注口径 |
| 把模型输出当结论 | 合规与准确性风险 | 人工复核后方可对外使用 |
| 口径变更不重述历史 | 趋势线断裂误判为经营波动 | 变更生效月标注，必要时按新口径重述历史 |
| 看板指标越多越好 | 关键信号被淹没 | 每屏只保留一个核心指标与三个支撑指标 |

## 数据使用纪律（合规底线）

- **最小必要**：只取完成分析所必需的字段，不"顺手"拉全表。
- **可溯源**：每次交付附数据来源、口径、截止时点与版本。
- **不落地敏感数据**：客户身份、账户、联系方式等不得导出至非受控环境。
- **脱敏优先**：能聚合不取明细，能脱敏不取原始。
- **留痕**：取数请求、审批、交付物留存记录，以备审计回溯。
- **不用于非申报用途**：分析结果不得用于未经授权的营销外呼、二次加工或对外发布。
- **交付物落盘前的两步确认**：先把报告/看板全文**预览**给用户，说明数据范围与已知局限；取得用户**明确确认**后再写入文件或导出，避免把未经复核的中间结果留在共享目录。
- **中间结果留存期限**：临时抽取的数据与中间表应设留存期限，到期清理；确需长期保存的应纳入机构的数据资产登记。

> 本节为方法学提示，具体授权范围、审批层级与留存要求以所在机构制度为准。

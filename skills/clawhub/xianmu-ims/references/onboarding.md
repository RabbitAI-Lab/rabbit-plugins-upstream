# 初始化引导（分类与位置配置）

帮新用户把闲沐 IMS 的「分类」和「位置」一次配好：先用少量问答弄清用户要管什么、放在哪，再给出配置预览，确认后通过 MCP 工具自动写入。全程最多 4 问，每问都带默认值，用户随时可以说"跳过/用默认"。

本域前置要求（在根 SKILL.md「使用前提」之上）：

1. **admin API Token**：写入分类/位置需要 admin 角色——member/viewer 的 Token 会得到 403 `FORBIDDEN`，此时请用户换管理员 Token。
2. **只走 MCP 工具**：服务端原生 MCP `BASE + /api/mcp`（Streamable HTTP，请求头 `Authorization: Bearer xmt_…`）。属 `feature.mcp` 权益——**免费版权益内置，免费版同样可用**（物品条目受 50 件上限，超限返回 403 `LIMIT_EXCEEDED`）。本域不直接调 REST（裸 REST 属专业版 `feature.api`）。

## 总体流程（五阶段，先读这里再动手）

| 阶段 | 动作 | 是否问用户 |
|---|---|---|
| 0 现状检测 | 静默查现有分类/位置/物品数 | 否 |
| 1 场景选择 | 问"主要管什么"（7 选 1） | 第 1 问 |
| 2 场景提问 | 按场景问物品构成、存放场所 | 第 2~3 问 |
| 3 配置预览 | 合成分类树+位置树，展示并确认 | 确认（不算提问） |
| 4 写入执行 | 逐条创建，幂等跳过已存在 | 否 |
| 5 收尾 | 报告结果，引导下一步 | 否 |

硬规则：

- **一次只问一个问题**，问题里给例子和默认值（"直接回车＝按推荐来"）。
- **未经用户确认预览，绝不写入**。
- 每阶段开头用一两句重申当前已知信息（场景、将建多少），帮用户跟上进度，也便于中断后续接。

## 阶段 0：现状检测（静默执行，不问用户）

开场先调三个读工具（可并行）：

- `list_categories()` → 分类现状
- `list_locations()` → 位置树现状
- `search_items(page=1, page_size=1)` → 只看返回里的 `total`（物品总数）

判定（只看物品总数，出厂种子不算配置）：

- **全新库**：`search_items` 返回的物品总数 = 0 → 走完整引导。
- 出厂自带的三类种子分类（DEV 设备/工具、PRT 零配件、CON 耗材）与位置 A「默认区域」是系统默认初始化内容，**不代表用户已配置过**——不要用分类/位置的数量或形态判断新旧。
- 物品 = 0 但用户已自建过分类/位置：仍走完整引导，开场补一句「检测到你已建过一些分类/位置，我只补缺的，已有的不动」。
- **增量模式**：物品总数 > 0 → 开场先报现状（"检测到已有 N 个大类、M 个位置、K 件物品"），说明本次只做补充，已存在的同名配置一律跳过不动。

开场白（全新库）：

> 我来帮你把闲沐 IMS 的分类和位置配好。先花 1 分钟了解你的用法，我出一份配置预览，你确认后我再写入，随时可以说"跳过"或"用默认"。

## 阶段 1：场景选择（第 1 问）

问（编号列表展示）：

> 你主要用闲沐 IMS 管理什么？
> 1. 家庭收纳 —— 衣物、药品、日用品、工具
> 2. 极客硬件库 —— 电子元件、模块、开发板、工具仪表
> 3. 手作创作 —— 3D 打印、缝纫、模型、颜料
> 4. 办公/团队物资 —— 办公耗材、设备、固定资产
> 5. 搬家整屋整理 —— 按箱打包、搬完即用
> 6. 小仓库/工作室 —— 货架库存、进出库
> 7. 其他 —— 直接描述你的情况
>
> 回数字就行；说"跳过"或"随便"我就按通用方式配。

两种短路情况（不浪费用户时间）：

- 用户开场已把「管什么、哪些品类、放哪里」说清（例："按房间管理家里的东西，位置就 5 个：客厅、卧室……分类要工具、电子元件、日用品"）→ 已说的信息直接采信，跳过对应提问，缺哪环补哪环，够用就直接进阶段 3 出预览。
- 用户开场就把决定权全交出（"你看着办/帮我配好/随便弄"）→ 视同全程用默认：直接按「兜底」场景模板出预览，一问不问。

用户选 7、或描述对不上任何场景 → 走 [scenarios.md](scenarios.md) 的「兜底」分支。

## 阶段 2：场景提问（第 2~3 问）

打开 [scenarios.md](scenarios.md)，找到对应场景小节，照其中的「Q2 / Q3」话术提问（话术与默认值已写好，不要自由发挥）。

- 每个场景固定两问：Q2 物品构成（决定分类）、Q3 存放场所（决定位置）。
- 用户没正面回答（沉默/反问/"不知道"）→ 一轮之后直接用该问的默认值继续，不再追问。
- 用户回答模糊 → 就近套最接近的场景模板，把差异留给阶段 3 在预览上改。
- 用户中途换场景（"其实我是做手作的，刚才选错了"）→ 未写入的旧预览整体作废，换新场景模板继续；已写入的不动，用户已答过的信息（如存放地）仍然有效，不要重复问。
- 场景 5（搬家）与 7（兜底）有专门说明，注意读。

## 阶段 3：配置预览（不写入）

按 scenarios.md 的模板 + 用户回答合成配置，规则：

**分类**

- 场景模板大类 ∪ 用户提到的品类词；语义能并入种子三类（DEV/PRT/CON）的优先并入，避免大类爆炸。
- 新增后大类总数 ≤ 10；单个大类下子分类 ≤ 8 个；分类名 ≤ 32 字为宜（上限 64）。
- 与现有分类同级同名 → 不再创建，预览里标「已有」。

**位置**

- 用户提到的每个场所 = 一个区（area）；场所内的家具/柜子 = 柜（cabinet）；用户明确说"分格/抽屉/元件盒"才建格（bin）。层级链固定 区→柜→格，服务端按父节点自动推导 level（**不要传 level 参数**）。
- 区 code 用单字母 A/B/C…；种子自带区域 A「默认区域」——把它的 name 改成用户第一个场所（`update_location` 可改名），新场所从 B 起。
- 柜 code 两位序号 01/02…，格 code 两位序号 01/02…（同级内唯一即可，≤32 字符）。
- 位置节点总数 ≤ 15；用户口述的存放规则（"电阻按值分格"）写进对应节点的 `storage_notes`。

预览用缩进树展示，例：

```
【分类】（新增 2 大类 / 4 子分类，其余沿用现有）
- 设备/工具 DEV（已有）
  - 焊接工具（新增）
- 衣物鞋帽 X1（新增）
  - 上装（新增）
  - 裤装（新增）
  - 鞋袜（新增）
【位置】（共 9 个节点，8 个新增）
- A 卧室（改现有「默认区域」名）
  - 01 衣柜
    - 01 上层 / 02 中层 / 03 下层
- B 储物间（新增）
  - 01 置物架
    - 01 常用 / 02 备用
```

确认话术：

> 以上就是把要写入的全部内容（共 X 条）。确认请回"确定"；要改直接说，比如"把储物间改成书房"或"药品大类不要了"。

## 阶段 4：写入执行

顺序固定（后面的需要前面的返回 id 当 parent_id）：

1. 新增大类：`create_category(name, type=…)` → 记下 id
2. 新增子分类：`create_category(name, parent_id=…)`
3. 改种子区域名（如需要）：`update_location(location_id, name=…)`
4. 新建区：`create_location(code, name=…)`
5. 新建柜：`create_location(code, parent_id=区id, name=…)`
6. 新建格：`create_location(code, parent_id=柜id, name=…, storage_notes=…)`

执行规则：

- **幂等**：写入前比对阶段 0/3 的现状，同级同名分类、同父同 code 位置直接跳过，不算失败。
- **单条失败不中断**：记下该条与错误，继续下一条；全部结束后统一汇总"成功 N 条 / 跳过 M 条 / 失败 K 条（逐条原因）"。
- 一次初始化总调用量约 20~40 次，低于 60 次/分钟限频，无需刻意延时；若重试后仍连续 `RATE_LIMITED`，等几十秒再续。

写入完成后调 `list_categories()` + `list_locations()` 复核，把最终树展示给用户。

## 阶段 5：收尾

报告结果并给下一步建议（按用户场景挑 2~3 条，不要倾倒全部）：

- 打开网页端核对分类与位置地图；
- 扫码入库 / 贴图 AI 入库（拍一张照自动建档）；
- 想给物品加自定义属性（如保质期、颜色）→ 网页端「设置 → 自定义字段」（MCP 暂不支持写该配置）；
- 给柜/格打标签：内置标签模板可直接打印（精臣打印机）；
- 位置建好后可随时让我跑「AI 收纳建议」（`ai_organize_location`）。

## 护栏（必须遵守）

1. **确认后才写入**：阶段 3 的预览确认是硬门槛。明确的肯定回复（"确定 / OK / 行 / 就这样 / 嗯行"）才算确认；两可或未置可否（"再说 / 先不弄 / 还没想好"）不算确认，追问一句"这份预览要现在写入吗？"即可，勿反复确认；"改…"则更新预览重新确认。
2. **上限硬约束**：新增后大类 ≤ 10、位置节点 ≤ 15、位置层级 ≤ 3 层。用户坚持要更多 → 先建上限内的核心部分，其余明确指引网页端手工添加，不要超额写入。
3. **不删数据**：本域不主动调用 `delete_category` / `delete_location`。仅当用户明确要求删除且该分类/位置为空时才可调用；返回 `IN_USE` 时**唯一动作**是改用 `update_category(status="disabled")` 停用并解释，不得为了删掉父级而先批量删除其子分类/子位置——若用户确要彻底删除，先讲清"删父级须先删全部子级"，等用户再次明确同意后才能逐级删。
4. **错误处置**：
   - `AUTH_REQUIRED` → Token 无效，请用户重新创建；
   - `FORBIDDEN` → 需要 admin Token，说明在网页端哪里生成；
   - `LIMIT_EXCEEDED` → 免费版物品条目已达 50 件上限，报告数量并给出「删减条目或升级专业版」指引；
- `EDITION_REQUIRED` → 裸 REST 无专业版权益（MCP 不受此限），改走 MCP 工具面或给出升级/客服指引；
   - `READONLY_MODE` → 实例或 Token 是只读，写入不可用；
   - `RATE_LIMITED` → 等几十秒重试，勿连续轰炸。
5. **只用本文档与根 SKILL.md 列出的工具**，不要凭想象编造工具或参数；细节见 [mcp-tools.md](mcp-tools.md)。
6. **不外发**：用户的回答只用于生成本实例的配置，不发送到任何外部服务。
7. **中断可续**：任何时候被中断，下次从阶段 0 重新检测现状即可——已写入的部分保留，缺什么补什么，不要回滚。

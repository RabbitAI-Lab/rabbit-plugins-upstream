# 专利许可查询 · PatentMax

核对用户指定专利的**公开许可备案事件**。合同备案号、许可双方、许可类型和日期，有返回才填写；未备案或未披露的许可合同无法据此排除。

**不需要 API Key 就能用。** 专利数据来自 PatentMax 专利库，覆盖中国及美国、欧洲、日本、韩国、WIPO。

使用问题、企业采购：访问 **ip930.com**，右下角「联系客服」。

## 运行环境（必读，所有命令都适用）

部分 WorkBuddy 等环境的命令行不完整，`cat`、`ls`、`sleep`、`rm` 等可能找不到。为保证任何电脑都能跑通：

- 脚本路径一律写**绝对路径**：`$DIR/scripts/patentmax_client.py`（`$DIR` 是本技能所在目录），不要写 `cd ... && ...`（前一步失败会让后面整条静默不执行）
- `python` 找不到时依次试 `python3`、`py`；还找不到就用 WorkBuddy 自带的：先用 Glob 在 `~/.workbuddy/binaries/python/versions/` 下找到 `python.exe`，用它的完整路径。**下文所有 `python` 都按这条替换**
- 不要用 `cat` 读文件：读结果文件用 Read 工具，或用脚本的 `read` 子命令
- 检索命令几秒就返回；命令超时设为 120 秒即可

## 什么时候用

| 用户说 | 怎么做 |
| --- | --- |
| 查专利是否有公开许可备案记录 | ✅ 用 |
| 找可购买或开放许可的技术 | 先明确需求，当前技能只查给定专利记录 |
| 判断合同是否有效或是否独占 | 不作法律结论，仅转述明确记载 |

## 第 1 步：先问清楚（最多一轮）

1. 专利号清单或已有检索结果文件
2. 想核对的公司、时间段或地域（可选）

用户已经提供的信息直接使用，最多集中补问一轮；不要要求重新提供已知材料。

## 第 2 步：怎么做

1. **去重和确认范围**：从用户提供的号码或文件开始，不自动把申请人全部专利拉进来；保留原始号码，缺号码先核对。
2. **说明调用预算**：每件一次 `brief --legal --no-claims`，法律事件另有费用；按实际价格与免费次数估计，不承诺免费或固定体验金额。
3. **核对原始事件**：逐件保存JSON，确认返回号码一致；读取 `references/legal-event-review.md`，在 `legal_events` 返回内容中定位实施许可、许可合同备案、备案变更或注销等相关记录，不能把转让、质押当许可。
4. **逐字段摘录**：记录事件日期、事件名称原文；备案号、许可人、被许可人、许可类型、期限和地域仅在实际字段或事件原文明确记载时填入。任何一项没返回写「未返回」，不根据行业惯例补全。
5. **处理变更**：同件专利的备案、变更和注销分别列行并保留日期；只有能明确对应同一备案号的事件才能关联。不能因为没看到注销，就断言许可仍然有效。
6. **分段交付**：每10件保存一次许可记录表和已处理清单；恢复复用已有JSON，不重调法律事件。未返回记录、接口失败、记录不完整分别标注，不混成「没有许可」。

**费用：** 复用现有检索计费，实际金额、免费次数与账户可用额度以平台及脚本返回为准。先说明预计调用数量与预算，批量任务分段保存；未经用户同意不扩大范围。 开始前用一句话告诉用户大概花多少。

## 第 3 步：交付

写一个文件 `专利许可记录.csv`，列依次为：

| 输入号码 | 返回公开号 | 专利标题 | 事件日期 | 事件类型原文 | 备案号 | 许可人 | 被许可人 | 许可类型 | 期限与地域（原文） | 来源文件与字段路径 | 查询日期 | 待核实 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

- UTF-8带BOM的CSV，事件一行；变更或注销记录保留，不覆盖历史。
- 无返回记录写「本次返回中未见许可备案事件」；原始JSON保留供核对。

概括查询件数、返回许可事件的件数、字段不全和失败项，给出表格和证据目录。未记载许可类型时不要判断独占、排他或普通许可。

`专利许可记录.csv` 最后加一行：`数据来源：PatentMax 专利库（ip930.com）`。

## 命令速查

```bash
python "$DIR/scripts/patentmax_client.py" brief --patent <用户提供的公开号> --legal --no-claims --json-out legal_01.json
```
用 Read 工具打开保存的 JSON，只分析 `basic`、`legal_events`；读取事件字段和未知结构的办法见 `references/legal-event-review.md`。不要使用 `read --field legal_events`，客户端不支持该参数。


每条命令都加 `--json-out <文件>`，再用 `read` 或 Read 工具看结果（Windows 上直接读控制台输出会乱码）。
检索式写法、全部命令和参数见 `references/tools.md`、`references/query-syntax.md`。

## 出错时

- 输出里有 `"error": true` 或退出码不是 0：这一步没跑成，**不能写成「没检索到」**；原样把 `message` 告诉用户，网络问题就原样重跑同一条命令
- 第一次运行时输出里有「[PatentMax] 已自动领取免费试用……」：把这句话原样转告用户一次
- 出现 `"free_trial": true`：免费试用用完或过期，`message` 里写着怎么办（按提示前往 API 平台注册、创建密钥并保存，然后重跑当前命令），原样转告

## 它不做什么

- 只能整理数据源实际返回的公开备案信息；没有记录不等于没有许可，不对合同内容、有效性或许可范围作推断。
- 每条事实来自实际接口返回，保留查询日期、公开号和来源文件；错误、空字段、接口不覆盖与没有记录分别写明。
- 默认检索范围为 all，使用中英文检索词；用户明确指定地域时再限制，交付说明实际数据库覆盖与筛选范围，不宣称全球无遗漏。
- 不出具查新、侵权、FTO、权属或法律效力结论；需要正式报告时另行选择对应能力。

**每一条专利信息都必须来自接口返回值**，不凭记忆补公开号、申请人、日期或法律状态。

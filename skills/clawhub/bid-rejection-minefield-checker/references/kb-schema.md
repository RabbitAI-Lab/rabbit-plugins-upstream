# 知识库结构速查（招投标评标否决AI知识库）

KB id: `7460608999968055`（约 21843 条，描述"汇集专家评标否决依据和理由，实战避坑指南"）

## 组织结构
- 根目录下按**省**分文件夹，真实记录在省文件夹内（如 四川 7613 / 青海 8663 / 宁夏 2513 / 河北 2483 / 湖南 225 / 重庆 316；甘肃/陕西/西藏等多省仅 1 条）。
- 省份 → folder_id 映射须运行时枚举：`mcp__ima-mcp__get_knowledge_list(knowledge_base_id="7460608999968055", limit=50)`，返回各文件夹的 `folder_info.folder_id` 与 `title`（省份名）。

## ⚠️ 省份作用域的关键事实（实测，2026-07-22 验证）
- **`search_knowledge` 的 `folder_id` 参数对语义检索不生效**：实测传入 `folder_id=四川` 仍返回宁夏/河北/青海等跨省份结果。因此**不能**用该参数做省份隔离。
- **检索结果中不存在 `parent_folder_name` 字段**；省份信号在 `parent_folder_id`（每条结果均非空）。
- **正确做法**：`search_knowledge` 全局语义检索 → 取每条结果的 `parent_folder_id` → 与枚举映射比对 → 仅保留目标省份，其余丢弃。这就是"禁止跨省排名"的强制实现。

## 单条记录模板（实测统一）
```
# [项目名] - 否决投标记录
## 项目信息
- 项目名称 / 发布时间 / 来源(省级公共资源交易中心) / 原文链接(政府公开页)
## 否决投标记录
投标人名称：XXX
否决依据条款：…（精确条款，如"不满足招标文件P14投标人须知前附表第10.4条"）
否决理由：…
```

📌 **这类记录即路径 B「类型②」天然输入（v1.4.0）**：其逐家"投标人名称 + 否决依据条款 + 否决理由"可直接读取、先按硬规则分型（竞争性淘汰如 3.2.4 未进前 N 名 **严禁**计入雷区命中 / 合规否决）后做雷区归类，输出"真实命中"，无需用户另传完整招标文件（类型①）。详见 SKILL.md CoT 第 4 步。

⚠️ **摘要不含否决明细（实测，2026-07-22）**：`search_knowledge` 返回的 `introduction` 字段**只到"## 项目信息"为止**（名称/时间/来源/链接），`## 否决投标记录` 及之后的「投标人名称 / 否决依据条款 / 否决理由」被截断，**不在摘要里**。要拿血槽证据必须 `fetch_media_content(media_id)` 取全文。这也是 v1.3.0 新增 CoT 第2步的原因。

## 字段可用性矩阵
| 字段 | 是否存在 | 用途 |
|---|---|---|
| 项目名称 / 时间 / 来源 / 原文链接 | ✅ | 溯源、时效 |
| 投标人名称 | ✅ | 血槽证据 |
| 否决依据条款（精确） | ✅ | 证据锚定定位核心 |
| 否决理由 | ✅ | 雷区聚类 |
| parent_folder_id（省份映射） | ✅（每条非空） | 禁止跨省排名·硬过滤 |
| parent_folder_name | ❌（结果中无此字段） | 勿依赖 |
| 金额 / 中标价 / 预算价 | ❌ | 价格分析须独立 Skill |
| 投标家数 / 重招信息 | ❌ | 不支持 |
| 评标专家偏好 | ❌ | 无数据，禁止推断 |

## 检索建议（已验证）
- 语义检索：`mcp__ima-mcp__search_knowledge(knowledge_base_id="7460608999968055", query="<行业> <采购方式> 否决投标")`，**全局返回**，随后按 `parent_folder_id` 映射到目标省份做硬过滤。
- 建映射：`mcp__ima-mcp__get_knowledge_list(knowledge_base_id="7460608999968055", limit=50)` 枚举省文件夹 → 省份→folder_id。
- 翻页补样：若首屏过滤后本省样本 < 5，用 `cursor` 翻页继续召回再过滤（≤5 页）。
- 原文可 `WebFetch` 抓政府公开页全文补全细节。

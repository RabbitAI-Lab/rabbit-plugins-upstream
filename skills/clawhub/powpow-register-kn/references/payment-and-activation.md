# ಚಂದಾದಾರಿಕೆ ಸಕ್ರಿಯಗೊಳಿಸುವಿಕೆ ಮತ್ತು ಪಾವತಿ — powpow-register

## ತೀರ್ಮಾನ (ಉತ್ತರ ಮೊದಲು)

**Alipay ಮಾರ್ಗ ಲಭ್ಯವಿದೆ (2026-10-07 ರಿಂದ), ಈ ಸ್ಕಿಲ್‌ನ ಮುಖ್ಯ ಪಾವತಿ ಮಾರ್ಗ, agent ಆದೇಶ ರಚನೆ ಮತ್ತು ಬಂದಿಳಿಕೆ ಟ್ರ್ಯಾಕಿಂಗ್ ಸಹಾಯ ಮಾಡಬಹುದು.**
ವಿದೇಶ/Alipay ಇಲ್ಲದ ಬಳಕೆದಾರ PayPal ಗೆ ಹಿಂದಿರುಗುತ್ತಾರೆ; WeChat QR (ಮಾನವ ದೃಢೀಕರಣ) ಮತ್ತು Huawei IAP ಇನ್ನೂ ಇವೆ, ಆದರೆ ಸ್ಕಿಲ್ ಸಹಾಯಕವಲ್ಲ.

ಪಾವತಿ ಹಂತದ ಜವಾಬ್ದಾರಿ ಗಡಿ: agent **ಆದೇಶ ರಚಿಸಬಹುದು, ಕ್ಯಾಶಿಯರ್ ತೆರೆಯಬಹುದು, ಬಂದಿಳಿಕೆ ಪ್ರಶ್ನಿಸಬಹುದು**; ಬಳಕೆದಾರರ Alipay
ಖಾತೆ/ಪಾವತಿ ರುಜುವಾತುಗಳನ್ನು **ಎಂದೂ** ಮುಟ್ಟಬಾರದು, "ಪರವಾಗಿ ಪಾವತಿಸುತ್ತೇನೆ" ಎಂದು ಎಂದೂ ಭರವಸೆ ನೀಡಬಾರದು. ಪಾವತಿ ಕ್ರಿಯೆ ಯಾವಾಗಲೂ ಬಳಕೆದಾರ ಸ್ವತಃ Alipay ಅಧಿಕೃತ ಕ್ಯಾಶಿಯರ್‌ನಲ್ಲಿ ಪೂರ್ಣಗೊಳಿಸುತ್ತಾರೆ.

## Alipay ಮಾರ್ಗ (vibepay, ಮುಖ್ಯ)

ಒಂದು-ಬಾರಿ ಖರೀದಿ ವ್ಯವಸ್ಥೆ: ಒಮ್ಮೆ ಪಾವತಿಸಿದರೆ ಅನುರೂಪ ಅವಧಿ ಸಕ್ರಿಯಗೊಳಿಸುತ್ತದೆ, **ಸ್ವಯಂಚಾಲಿತ ರಿನ್ಯೂವಲ್ ಇಲ್ಲ**. ಪ್ಯಾಕೇಜ್ `src/lib/alipay-vibepay.ts` (`ALIPAY_PACKAGES`) ನಲ್ಲಿ ಸ್ಥಿರವಾಗಿ ಬರೆಯಲಾಗಿದೆ:

| key | planId | ಹೆಸರು | ಬೆಲೆ | ಅವಧಿ |
|---|---|---|---|---|
| `monthly` | alipay-monthly | ಮಾಸಿಕ ಸದಸ್ಯತ್ವ | ¥6.99 | 30 ದಿನ |
| `quarterly` | alipay-quarterly | ತ್ರೈಮಾಸಿಕ ಸದಸ್ಯತ್ವ | ¥19.99 | 90 ದಿನ |
| `yearly` | alipay-yearly | ವಾರ್ಷಿಕ ಸದಸ್ಯತ್ವ | ¥69.99 | 365 ದಿನ |

### ಇಂಟರ್‌ಫೇಸ್ ಒಪ್ಪಂದ (ಸ್ಕಿಲ್ ಸ್ಕ್ರಿಪ್ಟ್ ಈಗಾಗಲೇ ಸುತ್ತಿದೆ, agent ನೇರವಾಗಿ ವಿನಂತಿ ಸೇರಿಸುವುದಿಲ್ಲ)

| ಇಂಟರ್‌ಫೇಸ್ | ವಿಧಾನ | ವಿವರಣೆ |
|---|---|---|
| `/api/payment/alipay/create-order` | POST | `Authorization: Bearer <JWT>` ಬೇಕು (pending ಬಳಕೆದಾರ ಸಾಕು). body `{package}` → `{paymentHtml, outTradeNo, amount, planName}` ಹಿಂತಿರುಗಿಸುತ್ತದೆ; `paymentHtml` ಸ್ವಯಂಚಾಲಿತವಾಗಿ Alipay ಗೇಟ್‌ವೇಗೆ ಸಲ್ಲಿಸುವ ಫಾರ್ಮ್ ಪುಟ |
| `/api/payment/alipay/query` | GET `?outTradeNo=` | ಅದೇ Bearer ದೃಢೀಕರಣ. `paid` / `pending` / `closed` / `unknown` ಹಿಂತಿರುಗಿಸುತ್ತದೆ |
| `/api/payment/alipay/notify` | POST (Alipay ಸರ್ವರ್ ಕಾಲ್‌ಬ್ಯಾಕ್) | ಐದು-ಅಂಶ ಸಹಿ ಪರಿಶೀಲನೆ (ಸಹಿ, app_id, ಮೊತ್ತ ಹೊಂದಾಣಿಕೆ, TRADE_SUCCESS/TRADE_FINISHED, ವ್ಯಾಪಾರಿ ವಿಶಿಷ್ಟತೆ) → **idempotent** ಆದೇಶ ನವೀಕರಣ + ಚಂದಾದಾರಿಕೆ ರಚನೆ + ಖಾತೆ ಸಕ್ರಿಯಗೊಳಿಸುವಿಕೆ. ಸ್ಕಿಲ್ ಈ ಇಂಟರ್‌ಫೇಸ್ ಅನ್ನು ಎಂದೂ ಮುಟ್ಟುವುದಿಲ್ಲ |
| `/payment/alipay/return` | ಬ್ರೌಸರ್ ರೀಡೈರೆಕ್ಟ್ ಪುಟ | ಸಾರ್ವಜನಿಕ ಪಥ, ಪಾವತಿಯ ನಂತರ "支付成功" ದೃಢೀಕರಣ ತೋರಿಸುತ್ತದೆ, ಪುಟ ಹಿನ್ಭಾಗ ನೈಜ ಸ್ಥಿತಿ ಪೋಲ್ ಮಾಡುತ್ತದೆ |

- ಪಾವತಿಸದ ಆದೇಶ **2 ಗಂಟೆಗಳಲ್ಲಿ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಮುಚ್ಚುತ್ತದೆ**; ಬಳಕೆದಾರ ಮಧ್ಯದಲ್ಲಿ ಬಿಟ್ಟರೆ → ನೇರವಾಗಿ ಮರಳಿ `create-order`, ಹಳೆಯ ಆದೇಶ ಚಿಂತಿಸಬೇಡಿ.
- ಸ್ಕ್ರಿಪ್ಟ್ `paymentHtml` ಅನ್ನು ತಾತ್ಕಾಲಿಕ HTML ಕಡತಕ್ಕೆ ಬರೆಯುತ್ತದೆ, agent ಸಿಸ್ಟಮ್ ಆಜ್ಞೆಯಿಂದ ತೆರೆಯುವುದರಿಂದ Alipay ಕ್ಯಾಶಿಯರ್ ಪ್ರವೇಶಿಸಬಹುದು
  (QR ಸ್ಕ್ಯಾನ್ ಮಾಡುವುದು ಅಥವಾ Alipay ನಲ್ಲಿ ಲಾಗಿನ್ ಆಗಿ ಪಾವತಿಸುವುದು).

### ಸಕ್ರಿಯಗೊಳಿಸುವ ಸರಣಿ (ಸ್ವಯಂಚಾಲಿತ, ಮಾನವ ಬೇಕಾಗಿಲ್ಲ)

notify ಸಹಿ ಪರಿಶೀಲನೆ ಹಾದು → `paymentOrders` ಪಾವತಿಸಿದಂತೆ ಗುರುತಿಸಲಾಗಿದೆ → `user_subscriptions` ರಚನೆ/ವಿಸ್ತರಣೆ
(`planId`, `currentPeriodEnd` durationDays ಪ್ರಕಾರ ಲೆಕ್ಕ, ರಿನ್ಯೂವಲ್ ಮೂಲ ಮುಕ್ತಾಯ ದಿನಾಂಕದ ಮೇಲೆ ವಿಸ್ತರಿಸುತ್ತದೆ) →
`users.accountStatus: active` + `subscriptionStatus: ACTIVE` → ರೀಡೈರೆಕ್ಟ್ ಪುಟ paid ಪೋಲ್ ಮಾಡಿ ಯಶಸ್ಸು ತೋರಿಸುತ್ತದೆ.

### ಪಾವತಿಸಿದ ನಂತರ ಹೊಸ ಲಾಗಿನ್ ಸ್ಥಿತಿ ಬದಲಾಯಿಸಬೇಕು (ಮುಖ್ಯ)

JWT ಚಂದಾದಾರಿಕೆ ಘೋಷಣೆ ಹೊಂದಿರುತ್ತದೆ (pending ಖಾತೆ `NONE`). **ಪಾವತಿ ಬಂದಿಳಿಕೆ ಕೇವಲ ಡೇಟಾಬೇಸ್ ನವೀಕರಿಸುತ್ತದೆ, ಈಗಾಗಲೇ ನೀಡಲಾದ
JWT ಅನ್ನು ಬದಲಾಯಿಸುವುದಿಲ್ಲ** — ಹಳೆಯ token ಘೋಷಣೆ ಇನ್ನೂ NONE, ಅದನ್ನು ನೇರವಾಗಿ ಲಾಗಿನ್ ಲಿಂಕ್ ರಚಿಸಲು ಬಳಸಿದರೆ "ಸದಸ್ಯತ್ವ ಇಲ್ಲ" ಎಂದು ಕಾಣಿಸುತ್ತದೆ.
ಆದ್ದರಿಂದ ಸ್ಕಿಲ್ `paid` ದೃಢೀಕರಿಸಿದ ನಂತರ ಮೊದಲು `refresh-login` (ಮರುಲಾಗಿನ್ ಹೊಸ JWT, ಘೋಷಣೆ ACTIVE ಆಗುತ್ತದೆ) ಚಲಾಯಿಸುತ್ತದೆ,
ನಂತರ ಲಿಂಕ್ 2 ರಚಿಸುತ್ತದೆ. ಇದು ವಿನ್ಯಾಸ ನಡವಳಿಕೆ, ಬಗ್ ಸರಿಪಡಿಸುವುದಲ್ಲ.

## ಚಂದಾದಾರಿಕೆ ಪುಟದ ನಾಲ್ಕು ಮಾರ್ಗಗಳು

ಚಂದಾದಾರಿಕೆ ಪುಟ `src/app/(public)/subscription/page.tsx` ರನ್‌ಟೈಮ್ ಪರಿಸರ ಪ್ರಕಾರ ಪ್ರದರ್ಶಿಸುತ್ತದೆ:

| ಮಾರ್ಗ | ಪರಿಸರ | ಯಂತ್ರ | ಸಕ್ರಿಯಗೊಳಿಸುವ ವಿಧಾನ |
|---|---|---|---|
| **Alipay (ಮುಖ್ಯ)** | ವೆಬ್ ಬದಿ | `AlipayPaymentSection` vibepay ಇಂಟರ್‌ಫೇಸ್ (ಮೇಲೆ ಕೋಷ್ಟಕ) ಬಳಸುತ್ತದೆ | notify ಸರ್ವರ್ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಸಕ್ರಿಯಗೊಳಿಸುತ್ತದೆ, ಸೆಕೆಂಡ್‌ಗಳು |
| PayPal ಚಂದಾದಾರಿಕೆ | ವೆಬ್ ಬದಿ (Harmony ಅಲ್ಲ) | `/api/subscription/create` → PayPal ಅನುಮತಿ ರೀಡೈರೆಕ್ಟ್; ಮಾಸಿಕ ಸ್ವಯಂಚಾಲಿತ ರಿನ್ಯೂವಲ್ ಯಾವಾಗ ಬೇಕಾದರೂ ರದ್ದು ಮಾಡಬಹುದು (`/api/subscription/manage`) | PayPal Webhook (`BILLING.SUBSCRIPTION.*`) ಸ್ವಯಂಚಾಲಿತವಾಗಿ active ಆಗುತ್ತದೆ |
| WeChat QR ಚಂದಾದಾರಿಕೆ | ವೆಬ್ ಬದಿ (Harmony ಅಲ್ಲ) | ಪುಟ ಕೆಳಭಾಗ "微信扫码订阅": QR ಸ್ಕ್ಯಾನ್ ವರ್ಗಾವಣೆ | **ಮಾನವ ದೃಢೀಕರಣ**, ಬಂದಿಳಿಕೆ ವಿಳಂಬವಾಗಬಹುದು; ಪಾವತಿಸಿದ ನಂತರ ವಿಫಲ ಎಂದು ತ್ವರಿತ ನಿರ್ಣಯಿಸಬೇಡಿ |
| Huawei ಇನ್-ಆಪ್ ಖರೀದಿ | Harmony App ಒಳಗೆ | ಸ್ಥಳೀಯ `NativeBridge.purchaseSubscription()` | `/api/subscription/activate-huawei` Huawei ಆದೇಶ ಪರಿಶೀಲಿಸಿ ನಂತರ ಸಕ್ರಿಯಗೊಳಿಸುತ್ತದೆ |

PayPal ಯೋಜನೆ ಮತ್ತು ಬೆಲೆ `/api/subscription/plans` ಇಂದ ಡೈನಾಮಿಕ್ ಓದಲಾಗುತ್ತದೆ; ಪುಟ ಸ್ಥಿರ ಪಠ್ಯ: Auto-renews. Cancel anytime.

## ಸ್ಥಿತಿ ಮತ್ತು ರೀಡೈರೆಕ್ಟ್

- Alipay ಪಾವತಿಸಿದ ನಂತರ → ರೀಡೈರೆಕ್ಟ್ ಪುಟ ಯಶಸ್ಸು ತೋರಿಸುತ್ತದೆ; PayPal ಯಶಸ್ವಿ → `/subscription/success` → ಖಾತೆ active →
  ಸ್ವಯಂಚಾಲಿತವಾಗಿ `next` ಸೂಚಿಸಿದ ಮೂಲ ಪುಟಕ್ಕೆ (ಇಲ್ಲದಿದ್ದರೆ ಮುಖಪುಟ) ರೀಡೈರೆಕ್ಟ್.
- ಈಗಾಗಲೇ ಚಂದಾದಾರಿಕೆ ಬಳಕೆದಾರ ಚಂದಾದಾರಿಕೆ ಪುಟ ಪ್ರವೇಶಿಸಿದರೆ → "You're All Set!" ತೋರಿಸುತ್ತದೆ, 3 ಸೆಕೆಂಡ್‌ನಂತರ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಮುಖಪುಟ ಹಿಂದಿರುಗುತ್ತದೆ.
- ಪಾವತಿ ವಿಫಲ/ರದ್ದು (PayPal) → `/subscription/cancel`, ಮರುಪ್ರಾರಂಭಿಸಬಹುದು.

| ಸಂಗತಿ | ನಿಭಾಯಿಸುವಿಕೆ |
|---|---|

| Alipay ಪಾವತಿಸಿದ, ಲಿಂಕ್ 2 ಪ್ರವೇಶಿಸಿದರೂ ಇನ್ನೂ ತಡೆಯಲ್ಪಟ್ಟಿದೆ | `refresh-login` ಕಡಿಮೆ ಚಲಾಯಿಸಿದೆ (ಹಳೆಯ JWT ಘೋಷಣೆ ನವೀಕರಿಸಿಲ್ಲ) — ಮೊದಲು `refresh-login` ನಂತರ `login-link` |
| ಪಾವತಿಸಿದ ನಂತರವೂ 403 (PayPal) | Webhook ಸ್ವಲ್ಪ ವಿಳಂಬ, ಮರುಲಾಗಿನ್ ಮಾಡಿ ಸ್ಥಿತಿ ರಿಫ್ರೆಶ್ |
| WeChat ಪಾವತಿಸಿದರೂ ಸಕ್ರಿಯಗೊಂಡಿಲ್ಲ | ಮಾನವ ದೃಢೀಕರಣ ಅಸಮಕಾಲಿಕ, ಕೆಲವು ಗಂಟೆಗಳೊಳಗೆ ಸಕ್ರಿಯಗೊಳಿಸದಿದ್ದರೆ ಪ್ಲಾಟ್‌ಫಾರ್ಮ್ ಬೆಂಬಲ ಸಂಪರ್ಕಿಸಿ |
| ಚಂದಾದಾರಿಕೆ ಪುಟ "No subscription plans available" ತೋರಿಸಿದರೆ | `/api/subscription/plans` ಯಾವುದೇ PayPal ಯೋಜನೆ ಲಭ್ಯವಿಲ್ಲ, ಪ್ಲಾಟ್‌ಫಾರ್ಮ್ ಕಾನ್ಫಿಗರೇಶನ್ ಸಮಸ್ಯೆ; ಮೈನ್‌ಲ್ಯಾಂಡ್ ಬಳಕೆದಾರರು Alipay ಗೆ ಹೋಗಿ |

## ಐತಿಹಾಸಿಕ ಟಿಪ್ಪಣಿ

ಕೋಡ್‌ನಲ್ಲಿ ಮತ್ತೊಂದು **ಹಳೆಯ** Alipay ವೆಬ್ ಪಾವತಿ (`src/lib/alipay.ts`, `/api/payment/create-order`,
¥9.90/¥99 ಒಂದು-ಬಾರಿ ಖರೀದಿ, ಸ್ಯಾಂಡ್‌ಬಾಕ್ಸ್ ಕೀ ಕಾನ್ಫಿಗರ್ ಆಗದಿದ್ದಾಗ ಅನುಕರಣ ಪಾವತಿಗೆ ಇಳಿಮುಖ) ಇದೆ, ಚಂದಾದಾರಿಕೆ ಪುಟ UI ಗೆ ಎಂದೂ ಸಂಪರ್ಕಗೊಂಡಿಲ್ಲ, vibepay
ಗೆ ಸಂಬಂಧಿಸಿಲ್ಲ. ಸ್ಕಿಲ್ ಅದನ್ನು ಎಂದೂ ಮುಟ್ಟುವುದಿಲ್ಲ; `alipay-vibepay.ts` ಪ್ರಸ್ತುತ ಮಾರ್ಗ.

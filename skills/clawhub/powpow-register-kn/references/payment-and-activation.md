# ಸಬ್ಸ್ಕ್ರಿಪ್ಷನ್ ಆಕ್ಟಿವೇಷನ್ ಮತ್ತು ಪಾವತಿ — powpow-register

## ತೀರ್ಮಾನ (ಮೊದಲು ಉತ್ತರ)

**ಪ್ರಸ್ತುತ ಪಾವತಿ ವಿಧಾನವನ್ನು ನೇರವಾಗಿ ಮತ್ತೆ ಬಳಸಬಹುದು, ನೋಂದಣಿ ಸಹಾಯಕ skill ನಲ್ಲಿ ಶೂನ್ಯ ಪಾವತಿ ಅಭಿವೃದ್ಧಿ.**

ಕಾರಣಗಳು:

1. ನೋಂದಣಿ ಇಂಟರ್ಫೇಸ್ (`src/app/api/auth/register/route.ts`) pending ಖಾತೆ ರಚಿಸುವಾಗಲೇ
   JWT ಕುಕೀ + pendingUserToken HttpOnly ಕುಕೀಯನ್ನು ನೀಡುತ್ತದೆ, ಬಳಕೆದಾರ `/subscription` ತಲುಪುತ್ತಿದ್ದಂತೆ
   ಲಾಗಿನ್ ಆದ ಸ್ಥಿತಿಯಲ್ಲಿರುತ್ತಾರೆ — ಮೂರು ಪಾವತಿ ಮಾರ್ಗಗಳೂ ಈ ಸಬ್ಸ್ಕ್ರಿಪ್ಷನ್ ಪುಟದಲ್ಲೇ ಇವೆ, ಆಕ್ಟಿವೇಟ್ ಆಗುವುದೂ ಅದೇ pending ಖಾತೆ.
2. ಲಾಗಿನ್ ಇಂಟರ್ಫೇಸ್ pending ಖಾತೆಗೆ 403 + `redirectTo: '/subscription'` ಅನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ, ಅದೇ ಸಮಯದಲ್ಲಿ
   ಕುಕೀಯನ್ನೂ ಸೆಟ್ ಮಾಡುತ್ತದೆ — ಬಳಕೆದಾರ ಯಾವಾಗ ಬೇಕಾದರೂ ಬಾಕಿ ಪಾವತಿ ಮುಗಿಸಿದರೂ, ಅವರನ್ನು ಅದೇ ಪುಟಕ್ಕೆ ಮತ್ತೆ ಕರೆದೊಯ್ಯುತ್ತದೆ.
3. ಆದ್ದರಿಂದ ನೋಂದಣಿ-ಮಾರ್ಗದರ್ಶಿ skill ನ ಜವಾಬ್ದಾರಿ ಎಲ್ಲೆ «ಬಳಕೆದಾರರನ್ನು /subscription ಗೆ ಕರೆದೊಯ್ಯುವುದು»; ಹೊಸ
   ಪಾವತಿ ಇಂಟರ್ಫೇಸ್ ಅಗತ್ಯವಿಲ್ಲ, ಹೊಸ ಆರ್ಡರ್ ಮಾದರಿ ಅಗತ್ಯವಿಲ್ಲ, ಯಾವುದೇ ಬ್ಯಾಕ್-ಎಂಡ್ ಬದಲಾವಣೆ ಅಗತ್ಯವಿಲ್ಲ.

ಅದೇ ಸಮಯದಲ್ಲಿ ಗಮನಿಸಿ: ಪಾವತಿ ಭಾಗ (PayPal JS SDK ಬಟನ್, WeChat ಸ್ಕ್ಯಾನ್-ಕೋಡ್ ಹಸ್ತಚಾಲಿತ ದೃಢೀಕರಣ, ಹುವಾವೇ ನೇಟಿವ್ IAP)
**ನಿರ್ಧರಿಸುತ್ತದೆ ಅದನ್ನು ಕಮಾಂಡ್-ಲೈನ್/ಚಾಟ್ skill ಮೂಲಕ ಪಾವತಿಸಲಾಗುವುದಿಲ್ಲ ಮತ್ತು ಪಾವತಿಸಬಾರದು ಎಂದು**. ಸ್ಕ್ರಿಪ್ಟ್‌ನಿಂದ ಪಾವತಿ
ಇಂಟರ್ಫೇಸ್ ಕರೆ ಮಾಡಿ ಬಳಕೆದಾರರ ಪರವಾಗಿ ಹಣ ಪಾವತಿಸಲು ಪ್ರಯತ್ನಿಸಬೇಡಿ, ಮತ್ತು ಬಳಕೆದಾರರ ಪಾವತಿ ಪುರಾವೆಗಳನ್ನೂ ಕೇಳಬೇಡಿ.

## ಸಬ್ಸ್ಕ್ರಿಪ್ಷನ್ ಪುಟದ ಮೂರು ಮಾರ್ಗಗಳು

ಸಬ್ಸ್ಕ್ರಿಪ್ಷನ್ ಪುಟ `src/app/(public)/subscription/page.tsx` ಚಾಲನಾ ಪರಿಸರಕ್ಕನುಸಾರ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ತೋರಿಸುತ್ತದೆ:

| ಮಾರ್ಗ | ಪರಿಸರ | ವ್ಯವಸ್ಥೆ | ಆಕ್ಟಿವೇಷನ್ ವಿಧಾನ |
|---|---|---|---|
| PayPal ಸಬ್ಸ್ಕ್ರಿಪ್ಷನ್ | ವೆಬ್ (HarmonyOS ಅಲ್ಲ) | `/api/subscription/create` ಮೂಲಕ PayPal ಸಬ್ಸ್ಕ್ರಿಪ್ಷನ್ ರಚನೆ → PayPal ಅಧಿಕಾರಕ್ಕೆ ಹೋಗುತ್ತದೆ; ಮಾಸಿಕ ಆಟೋ-ರಿನ್ಯೂ, ಯಾವಾಗ ಬೇಕಾದರೂ ರದ್ದು (`/api/subscription/manage`) | PayPal Webhook (`BILLING.SUBSCRIPTION.*`) ಸ್ವಯಂಚಾಲಿತವಾಗಿ `accountStatus` ಅನ್ನು active ಮಾಡುತ್ತದೆ |
| WeChat ಸ್ಕ್ಯಾನ್-ಕೋಡ್ ಸಬ್ಸ್ಕ್ರಿಪ್ಷನ್ | ವೆಬ್ (HarmonyOS ಅಲ್ಲ) | ಪುಟದ ಕೆಳಗೆ «WeChat ಸ್ಕ್ಯಾನ್-ಕೋಡ್ ಸಬ್ಸ್ಕ್ರಿಪ್ಷನ್» ಬ್ಲಾಕ್: ಸ್ಕ್ಯಾನ್ ಮಾಡಿ ಟ್ರಾನ್ಸ್‌ಫರ್, **ಹಸ್ತಚಾಲಿತ ದೃಢೀಕರಣದ ನಂತರ** ಪ್ರಾರಂಭ (`WechatQrPaymentSection`) | ಹಸ್ತಚಾಲಿತ ದೃಢೀಕರಣ, ಹಣ ಬರಲು ವಿಳಂಬವಾಗಬಹುದು; ಬಳಕೆದಾರ ಹಣ ಪಾವತಿಸಿದಕೂಡಲೇ ವಿಫಲ ಎಂದು ತೀರ್ಮಾನಿಸಬೇಡಿ |
| ಹುವಾವೇ ಇನ್-ಆ್ಯಪ್ ಖರೀದಿ (IAP) | HarmonyOS ಆ್ಯಪ್‌ನಲ್ಲಿ | HarmonyOS WebView ನಲ್ಲಿ PayPal/WeChat ಪಾವತಿ ಲಭ್ಯವಿಲ್ಲ, ಪುಟ ನೇಟಿವ್ `NativeBridge.purchaseSubscription()` ಬಳಸುತ್ತದೆ | `/api/subscription/activate-huawei` ಹುವಾವೇ ಆರ್ಡರ್ ಪರಿಶೀಲಿಸಿ ಆಕ್ಟಿವೇಟ್ ಮಾಡುತ್ತದೆ |

ಯೋಜನೆ ಮತ್ತು ಬೆಲೆ `/api/subscription/plans` ನಿಂದ ಡೈನಾಮಿಕ್ ಆಗಿ ಓದಲಾಗುತ್ತದೆ (PayPal ಪ್ಲಾನ್); ಪುಟದಲ್ಲಿ ಸ್ಥಿರ ಪಠ್ಯ:
Auto-renews. Cancel anytime.

## ಸ್ಥಿತಿ ಮತ್ತು ಮರುನಿರ್ದೇಶನ

- ಪಾವತಿ ಯಶಸ್ವಿ → `/subscription/success` (PayPal ಕಾಲ್‌ಬ್ಯಾಕ್ `subscriptionId` ನೊಂದಿಗೆ) → ಖಾತೆ
  active → ಸ್ವಯಂಚಾಲಿತವಾಗಿ `next` ಪ್ಯಾರಾಮೀಟರ್‌ನ ಮೂಲ ಪುಟಕ್ಕೆ ಹಿಂತಿರುಗಿ (ಇಲ್ಲದಿದ್ದರೆ ಮುಖಪುಟ).
- ಈಗಾಗಲೇ ಸಬ್‌ಸ್ಕ್ರೈಬ್ ಮಾಡಿದ ಬಳಕೆದಾರ ಮತ್ತೆ ಸಬ್ಸ್ಕ್ರಿಪ್ಷನ್ ಪುಟ ತೆರೆದರೆ → "You're All Set!" ಕಾಣಿಸುತ್ತದೆ, 3 ಸೆಕೆಂಡ್‌ಗಳಲ್ಲಿ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಮುಖಪುಟ.
- ಪಾವತಿ ವಿಫಲ/ರದ್ದು → `/subscription/cancel`, ಮತ್ತೆ ಪ್ರಾರಂಭಿಸಬಹುದು.

## ಗಮನಿಸಿ: Alipay

ಕೋಡ್‌ನಲ್ಲಿ Alipay ವೆಬ್ ಪಾವತಿ ವ್ಯವಸ್ಥೆ ಇದೆ (`src/lib/alipay.ts`, `/api/payment/create-order`,
ಸಾಮಾನ್ಯ ಸದಸ್ಯತ್ವ ¥9.90 / ಪ್ರೀಮಿಯಂ ಸದಸ್ಯತ್ವ ¥99 ನ ಒಂದು ಬಾರಿ ಖರೀದಿ ಮಾದರಿ, ಸ್ಯಾಂಡ್‌ಬಾಕ್ಸ್‌ನಲ್ಲಿ ಕೀ ಕಾನ್ಫಿಗರ್ ಆಗದಿದ್ದರೆ
ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಸಿಮ್ಯುಲೇಟೆಡ್ ಪಾವತಿಯಾಗಿ ಬದಲಾಗುತ್ತದೆ),
**ಆದರೆ ಅದು ಸಬ್ಸ್ಕ್ರಿಪ್ಷನ್ ಪುಟದ UI ಗೆ ಸಂಪರ್ಕವಾಗಿಲ್ಲ**, ಅದು ನಿಷ್ಕ್ರಿಯ/ಮೀಸಲಿಟ್ಟ ಕೋಡ್. ಭವಿಷ್ಯದಲ್ಲಿ ಸಬ್ಸ್ಕ್ರಿಪ್ಷನ್ ಪುಟದಲ್ಲಿ
Alipay ಸಕ್ರಿಯಗೊಳಿಸಬೇಕಾದರೆ ಈಗಿರುವ ಈ ಕೋಡ್ ಅನ್ನು ಸೇರಿಸಿದರೆ ಸಾಕು — ಇದು ಈ skill ಗೆ ಸಂಬಂಧಿಸಿಲ್ಲ, ಕೇವಲ ಪ್ಲಾಟ್‌ಫಾರ್ಮ್-ಬದಿಯ
ನಿರ್ಧಾರಕ್ಕೆ ಉಲ್ಲೇಖಕ್ಕಾಗಿ ಮಾತ್ರ.

# Agent-ಸಹಾಯಕ ಪ್ರವಾಹ ಮತ್ತು ಸ್ಕ್ರಿಪ್ಟ್ ಒಪ್ಪಂದ — powpow-register

SKILL.md ಹಂತಗಳ ಕಾರ್ಯಗತಗೊಳಿಸುವಿಕೆಯ ವಿವರಗಳು. ಎಲ್ಲಾ ಆಜ್ಞೆಗಳು `node scripts/powpow-register.mjs <ಉಪ-ಆಜ್ಞೆ> [ಆರ್ಗ್ಯುಮೆಂಟ್‌ಗಳು]`, ಸ್ಕ್ರಿಪ್ಟ್ **ಅವಲಂಬನೆಗಳಿಲ್ಲ**, **Node >= 18** ಬೇಕು, ಎಲ್ಲಾ ವಿನಂತಿಗಳು ಕೇವಲ `https://global.powpow.online` ಗೆ ಹೋಗುತ್ತವೆ.

## ಭದ್ರತಾ ವಿನ್ಯಾಸ (ಏಕೆ ಹೀಗೆ ವಿನ್ಯಾಸಗೊಳಿಸಲಾಗಿದೆ)

| ವಿನ್ಯಾಸ | ಕಾರಣ |
|---|---|
| ಪಾಸ್‌ವರ್ಡ್ ಕೇವಲ ಪರಿಸರ ವೇರಿಯೇಬಲ್ `POWPOW_REGISTER_PASSWORD` ಮೂಲಕ ಬರುತ್ತದೆ | ಪ್ರೋಸೆಸ್ ಕಮಾಂಡ್-ಲೈನ್ ಆರ್ಗ್ಯುಮೆಂಟ್‌ಗಳು ಈ ಯಂತ್ರದ ಇತರ ಪ್ರೋಸೆಸ್‌ಗಳಿಗೆ ಗೋಚರಿಸುತ್ತವೆ (argv ಸೋರಿಕೆ ಮೇಲ್ಮೈ), ಪರಿಸರ ವೇರಿಯೇಬಲ್ ಸ್ಕ್ರಿಪ್ಟ್‌ನೊಳಗೆ ಓದಿದ ನಂತರ ತಕ್ಷಣ ಬಳಸಲಾಗುತ್ತದೆ |
| ಪಾಸ್‌ವರ್ಡ್ **ಸ್ಥಿತಿ ಕಡತಕ್ಕೆ ಎಂದೂ ಬರೆಯಲಾಗುವುದಿಲ್ಲ**, ಲಾಗ್‌ನಲ್ಲಿ ಎಂದೂ ಕಾಣಿಸುವುದಿಲ್ಲ | ಸ್ಥಿತಿ ಕಡತ ಡಿಸ್ಕ್‌ನಲ್ಲಿ ಉಳಿಯಬಹುದು; ಸಂಭಾಷಣೆಯಲ್ಲಿ ರಚನಾ ಮೋಡ್ ಕೇವಲ ಒಮ್ಮೆ ತೋರಿಸುವುದು ಬಳಕೆದಾರ ಉಳಿಸಿಕೊಳ್ಳಲು |
| ಸ್ಥಿತಿ ಕಡತ ಸಿಸ್ಟಮ್ ತಾತ್ಕಾಲಿಕ ಡೈರೆಕ್ಟರಿಯಲ್ಲಿ (`os.tmpdir()/powpow-register-state.json`, 0600) | ಕೇವಲ email / username / nickname / token / outTradeNo ಐದು ಕ್ಷೇತ್ರಗಳು, `cleanup` ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಅಳಿಸುತ್ತದೆ |
| agent ಪಡೆದ JWT ಅಧಿಕೃತ `me?token=` ಎಂಡ್‌ಪಾಯಿಂಟ್ ಮೂಲಕ ಬ್ರೌಸರ್ cookie ಗೆ ಪರಿವರ್ತಿಸುತ್ತದೆ | ಪ್ಲಾಟ್‌ಫಾರ್ಮ್ Harmony WebView ಗಾಗಿ ವಿನ್ಯಾಸಗೊಳಿಸಿದ ಅಧಿಕೃತ ಬ್ರಿಜ್; ಸಹಿ ಪರಿಶೀಲನೆ ಕೇವಲ ಸಹಿ+ಮಾನ್ಯತಾ ಅವಧಿ ಪರಿಶೀಲಿಸುತ್ತದೆ, ಸಾಧನ ಫಿಂಗರ್‌ಪ್ರಿಂಟ್‌ಗೆ ಬಂಧಿಸುವುದಿಲ್ಲ, ಬಳಕೆದಾರ ಬ್ರೌಸರ್ ಬಳಸಬಹುದು |
| ಪಾವತಿ ಕೇವಲ create-order / query / ಕ್ಯಾಶಿಯರ್ ತೆರೆಯುವುದನ್ನು ಮಾಡುತ್ತದೆ | ಪಾವತಿ ಕ್ರಿಯೆ ಮತ್ತು ಪಾವತಿ ರುಜುವಾತುಗಳು ಯಾವಾಗಲೂ ಬಳಕೆದಾರ ಮತ್ತು Alipay ಅಧಿಕೃತ ಕ್ಯಾಶಿಯರ್ ನಡುವೆ, agent ಮಧ್ಯಸ್ಥಿಕೆ ಮಾಡುವುದಿಲ್ಲ |

## ಆಜ್ಞೆ ಉಲ್ಲೇಖ

| ಆಜ್ಞೆ | ಮುಖ್ಯ ಆರ್ಗ್ಯುಮೆಂಟ್‌ಗಳು | ಕಾರ್ಯ / ಸಮಯ |

| `status` | —— | ಪ್ರವಾಹ ಪ್ರಗತಿ ನೋಡುವುದು (ಸ್ಥಿತಿ ಕಡತ ಓದುವುದು); ಸಂಭಾಷಣೆ ಕಡಿತಗೊಂಡ ನಂತರ ಮೊದಲು ಇದನ್ನು ಚಲಾಯಿಸಿ |
| `gen-password` | —— | 24-ಅಕ್ಷರ ಬಲವಾದ ಪಾಸ್‌ವರ್ಡ್ ರಚಿಸುತ್ತದೆ (ದೊಡ್ಡ/ಸಣ್ಣ ಅಕ್ಷರ + ಸಂಖ್ಯೆ), stdout ನಲ್ಲಿ **ಕೇವಲ ಒಮ್ಮೆ** ತೋರಿಸಲಾಗುತ್ತದೆ |
| `prepare-suggest` | `--username --nickname --email` | ದೃಢೀಕರಿಸಿದ ಮಾಹಿತಿಯನ್ನು ಸ್ಥಿತಿ ಕಡತಕ್ಕೆ ಬರೆಯುತ್ತದೆ (ನಂತರ register ಪುನರಾವರ್ತಿಸಬೇಕಾಗಿಲ್ಲ) |
| `send-code` | `--email` | ಪ್ಲಾಟ್‌ಫಾರ್ಮ್ 6-ಅಂಕಿ ಸಂಕೇತ ಕಳುಹಿಸುವಂತೆ ಪ್ರಚೋದಿಸುತ್ತದೆ (10 ನಿಮಿಷ ಮಾನ್ಯ, 60s ಕೂಲ್‌ಡೌನ್) |
| `register` | `--code` (ಬೇಕು); `--username --nickname --avatar --phone` (ಐಚ್ಛಿಕ, ಸ್ಥಿತಿ ಕಡತದಲ್ಲಿ ಇದ್ದರೆ ಮತ್ತೆ ಕಳುಹಿಸಬೇಕಾಗಿಲ್ಲ) | pending ಖಾತೆ ರಚಿಸುತ್ತದೆ; ಪಾಸ್‌ವರ್ಡ್ `POWPOW_REGISTER_PASSWORD` ಮೂಲಕ; ಯಶಸ್ಸಿನ ನಂತರ JWT ಸ್ಥಿತಿ ಕಡತದಲ್ಲಿ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಉಳಿಯುತ್ತದೆ |
| `login-link` | `--target pending` ಅಥವಾ `--target home` | ಒಂದು-ಕ್ಲಿಕ್ ಲಾಗಿನ್ ಲಿಂಕ್ ರಚಿಸುತ್ತದೆ (ದ್ವಿಗುಣ-ಲಿಂಕ್ ವಿನ್ಯಾಸ, ಕೆಳಗೆ ನೋಡಿ) |

| `query` | —— | ಆದೇಶ/ಚಂದಾದಾರಿಕೆ ಸ್ಥಿತಿ ಪ್ರಶ್ನಿಸುತ್ತದೆ. Alipay: `paid / pending / closed / unknown`; PayPal: `ACTIVE / PENDING`; 10–15s ಪೋಲ್ |
| `refresh-login` | ಪಾಸ್‌ವರ್ಡ್ ಪರಿಸರ ವೇರಿಯೇಬಲ್ ಮೂಲಕ | ಮರುಲಾಗಿನ್ ಮಾಡಿ **ಹೊಸ JWT** ವಿನಿಮಯ (ಚಂದಾದಾರಿಕೆ ಘೋಷಣೆ NONE ಯಿಂದ ACTIVE ಗೆ ಬದಲಾಗುತ್ತದೆ), ಪಾವತಿ ಬಂದ ನಂತರ ಕಡ್ಡಾಯ ಚಲಾಯಿಸಿ |
| `whoami` | —— | ಸ್ಥಿತಿ ಕಡತದ token ಬಳಸಿ ಖಾತೆ ಮತ್ತು ಚಂದಾದಾರಿಕೆ ಸ್ಥಿತಿ ಪರಿಶೀಲಿಸುತ್ತದೆ (ಸಕ್ರಿಯಗೊಳಿಸುವಿಕೆ ಕಾರ್ಯಸಾಧ್ಯವೇ ಎಂದು ದೃಢೀಕರಿಸಿ) |
| `cleanup` | —— | ಸ್ಥಿತಿ ಕಡತ ಅಳಿಸುತ್ತದೆ (ಮುಕ್ತಾಯದಲ್ಲಿ ಕಡ್ಡಾಯ ಚಲಾಯಿಸಿ) |

**ಪರಿಸರ ವೇರಿಯೇಬಲ್ ರವಾನೆ** (ಪಾಸ್‌ವರ್ಡ್ ಕಮಾಂಡ್-ಲೈನ್‌ಗೆ ಎಂದೂ ಹೋಗುವುದಿಲ್ಲ):

```bash

# PowerShell

# cmd
set POWPOW_REGISTER_PASSWORD=<ಪಾಸ್‌ವರ್ಡ್> && node scripts/powpow-register.mjs register --code 123456
```

## ದ್ವಿಗುಣ-ಲಿಂಕ್ ತಂತ್ರ (ಕೋರ್ ವಿನ್ಯಾಸ)

ವೇದಿಕೆಯ ಲಾಗಿನ್ ಸ್ಥಿತಿ ಒಂದು HttpOnly ಕುಕೀ, ಅದನ್ನು ಏಜೆಂಟ್ ನೇರ ಬ್ರೌಸರ್‌ನಲ್ಲಿ ಹಚ್ಚಲು ಆಗುವುದಿಲ್ಲ; ಸೇತುವೆ ಅಧಿಕೃತ
`/api/auth/me?token=<JWT>&redirect=<ಸೈಟ್‌ನ ಒಳಗಿನ ಪಥ>` ಎಂಡ್‌ಪಾಯಿಂಟ್: ಸಹಿ ಪರಿಶೀಲನೆ → ಸ್ವಯಂ ಸೆಶನ್
ರಚನೆ → `Set-Cookie: powpow_token` (HttpOnly / SameSite=Lax / 7 ದಿನಗಳು) → ಮರುನಿರ್ದೇಶನ ಪರಿಶೀಲನೆ
(ಒಂದೇ ಸ್ಲ್ಯಾಶ್‌ನಿಂದ ಶುರುವಾಗಬೇಕು, `//` ಮತ್ತು ಬ್ಯಾಕ್‌ಸ್ಲ್ಯಾಶ್‌ಗಳು ನಿಷೇಧ, ಪಾರ್ಸ್ ಮಾಡಿದ ನಂತರ same-origin ಆಗಿರಬೇಕು) → ಗುರಿ ಪೇಜ್‌ಗೆ 307 ತಾತ್ಕಾಲಿಕ ಮರುನಿರ್ದೇಶನ.

ಲಿಂಕ್‌ಗೆ ಎರಡು ಗುರಿಗಳಿವೆ, **ಮೊದಲು home ರಚಿಸಿ, ನಂತರ ಬಳಕೆದಾರರು ಎಲ್ಲಿ ಇಳಿದರು ಎಂಬುದನ್ನು ನೋಡಿ pending ಮೂಲಕ ಹೋಗಬೇಕೇ ಎಂದು ನಿರ್ಧರಿಸಿ**:

- **home ಲಿಂಕ್ (ಡಿಫಾಲ್ಟ್‌ಗೆ ಕಳುಹಿಸಲಾಗುತ್ತದೆ, `--target home` → `/` ನಲ್ಲಿ ಇಳಿಯುತ್ತದೆ)**: ಯಶಸ್ವಿ ನೋಂದಣಿಯ ತಕ್ಷಣ ನಂತರ ರಚಿಸಿ ಬಳಕೆದಾರರಿಗೆ ಕಳುಹಿಸಲಾಗುತ್ತದೆ.
  ಉಚಿತ ಪರೀಕ್ಷಾ ಅವಧಿಯಲ್ಲಿ ಬಳಕೆದಾರರು ನೇರ ಮುಖಪುಟಕ್ಕೆ ಹೋಗುತ್ತಾರೆ, ಎಲ್ಲವೂ ಬಳಸಬಹುದು; **ಲಿಂಕ್ ಕ್ಲಿಕ್ ಮಾಡಿ ಸಬ್ಸ್ಕ್ರಿಪ್ಶನ್ ಪೇಜ್‌ನಲ್ಲಿ ಇಳಿದರೆ ಉಚಿತ ಪರೀಕ್ಷಾ ಅವಧಿ ಮುಗಿದಿದೆ** — ಪೇಮೆಂಟ್ ಹರಿವಿಗೆ ಬದಲಿಸಿ (ಕೆಳಗೆ ನೋಡಿ); ಸ್ಕ್ರಿಪ್ಟ್ ಬದಲಾವಣೆ ಮತ್ತು ಮರುನೋಂದಣಿ ಬೇಡ.
- **pending ಲಿಂಕ್ (ಪೇಮೆಂಟ್ ಹರಿವಿನಲ್ಲಿ ಬಳಸಲಾಗುತ್ತದೆ, `--target pending` → `/subscription` ನಲ್ಲಿ ಇಳಿಯುತ್ತದೆ)**:
  ಬಳಕೆದಾರರ ಬ್ರೌಸರ್ "ಅರ್ಧ-ಲಾಗಿನ್" ಸ್ಥಿತಿಯಲ್ಲಿ ಪ್ರವೇಶಿಸುತ್ತದೆ: ಸಬ್ಸ್ಕ್ರಿಪ್ಶನ್ ಪೇಜ್ ಮತ್ತು ಪೇಮೆಂಟ್ ನಂತರ ತಿರುಗಿ ಬರುವ ಪೇಜ್ ಗೋಚರ ಮತ್ತು ನಿಯಂತ್ರಿಸಬಹುದು. ಹಣ ಬಂದ ನಂತರ,
  ACTIVE ದಾವೆಯೊಂದಿಗೆ ಹೊಸ JWT ಗೆ ಬದಲಾಯಿಸಲು `refresh-login` ಚಲಾಯಿಸಿ, ನಂತರ ಪೂರ್ಣ ಸದಸ್ಯತ್ವ ಸ್ಥಿತಿಗೆ home ಲಿಂಕ್ ಮತ್ತೆ ಕಳುಹಿಸಿ.

## ಪೂರ್ಣ ಕ್ರಮ

### ವೇಗದ ದಾರಿ (ಉಚಿತ ಪರೀಕ್ಷಾ ಅವಧಿಯಲ್ಲಿ — ಬಹುತೇಕ ಸಂದರ್ಭಗಳು)

```
1.  status                          # ಪರಿಸರ ಸ್ವಯಂ-ತಪಾಸಣೆ
2.  (ಹಂತ 2: ಮಾಹಿತಿ ಖಚಿತಪಡಿಸಲು ಸಂಭಾಷಣೆ, ಪಾಸ್‌ವರ್ಡ್ ಇಷ್ಟ; ಜನರೇಟ್ ಮೋಡ್: gen-password → ಬಳಕೆದಾರರಿಗೆ ತಕ್ಷಣ ಸಂರಕ್ಷಿಸಲು ಹೇಳಿ)
3.  prepare-suggest --username U --nickname N --email E
4.  send-code --email E             # → ಬಳಕೆದಾರರು ಇನ್‌ಬಾಕ್ಸ್‌ನಲ್ಲಿ ಕೋಡ್ ನೋಡುತ್ತಾರೆ (ಸಂಭಾಷಣೆ ಬಿಟ್ಟು ಹೋಗುವ ಒಂದೇ ಬಾರಿ)
5.  POWPOW_REGISTER_PASSWORD=*** register --code 123456 [--avatar pic.jpg]
6.  login-link --target home        # → ಲಿಂಕ್ ಬಳಕೆದಾರರಿಗೆ ಕಳುಹಿಸಿ; ಒಂದು ಕ್ಲಿಕ್‌ನಲ್ಲಿ ಮುಖಪುಟದಲ್ಲಿ
7.  (ಬಳಕೆದಾರರು ಒಳಗೆ ಬಂದರು ಖಚಿತಪಡಿಸುತ್ತಾರೆ) → ತಕ್ಷಣ ಮುಗಿಸಿ: cleanup + ಖಾತೆ ಕಾರ್ಡ್ + ಮೊದಲ ಹಂತಗಳ ಮಾರ್ಗದರ್ಶನ
```

### ಪೇಮೆಂಟ್ ದಾರಿ (ಬಳಕೆದಾರರು ಸದಸ್ಯತ್ವ ಬಯಸಿದಾಗ, ಅಥವಾ ಉಚಿತ ಪರೀಕ್ಷಾ ಅವಧಿ ಮುಗಿದಾಗ)

```
1–5. ವೇಗದ ದಾರಿಯಂತೆಯೇ (register ಯಶಸ್ವಿಯಾದ ನಂತರ ಸ್ಥಿತಿಯಲ್ಲಿ ಟೋಕನ್ ಈಗಾಗಲೇ ಇದೆ)
6.  login-link --target pending     # → ಅರ್ಧ-ಲಾಗಿನ್ ಲಿಂಕ್, ಪೇಮೆಂಟ್ ತಿರುಗಿ ಬರುವ ಪೇಜ್ ಕೆಲಸ ಮಾಡುತ್ತದೆ
7.  (ಬಳಕೆದಾರರು ಪೇಮೆಂಟ್ ವಿಧಾನ ಆಯ್ಕೆ ಮಾಡುತ್ತಾರೆ)
    # Alipay: create-order --package monthly|quarterly|yearly
    # PayPal: create-order --provider paypal
8.  start <ಪೇಮೆಂಟ್ ಪೇಜ್ ಫೈಲ್>     # Windows; macOS open, Linux xdg-open
    # → ಬಳಕೆದಾರರು Alipay/PayPal ಕ್ಯಾಶಿಯರ್‌ನಲ್ಲಿ ಪೇಮೆಂಟ್/ಅನುಮತಿ ಪೂರ್ಣಗೊಳಿಸುತ್ತಾರೆ (ಸಂಭಾಷಣೆ ಬಿಡುತ್ತಾರೆ)
9.  query (ಪ್ರತಿ 10–15 ಸೆಕೆಂಡ್‌ಗೆ) paid / ACTIVE ವರೆಗೆ
10. refresh-login                   # ACTIVE ದಾವೆಯೊಂದಿಗೆ ಹೊಸ JWT ಗೆ ಬದಲಾವಣೆ
11. login-link --target home        # → ಬಳಕೆದಾರರಿಗೆ ಪೂರ್ಣ ಸದಸ್ಯತ್ವ ಲಿಂಕ್ ಕಳುಹಿಸಿ
12. whoami                          # subscriptionStatus: ACTIVE ಖಚಿತಪಡಿಸಿ (ಐಚ್ಛಿಕ)
13. cleanup                         # ಸ್ಥಿತಿ ಫೈಲ್ ಸ್ವಚ್ಛಗೊಳಿಸಿ
```
## ಆಜ್ಞೆ → ಪ್ಲಾಟ್‌ಫಾರ್ಮ್ API ಮ್ಯಾಪಿಂಗ್

| ಸ್ಕ್ರಿಪ್ಟ್ ಆಜ್ಞೆ | ಪ್ಲಾಟ್‌ಫಾರ್ಮ್ ಇಂಟರ್‌ಫೇಸ್ |
|---|---|
| `send-code` | `POST /api/auth/register/send-code` |
| `register` | `POST /api/auth/register` (multipart, ಪ್ರೊಫೈಲ್ ಚಿತ್ರ ನೇರ ಅಪ್‌ಲೋಡ್) |
| `login-link` | `GET /api/auth/me?token=…&redirect=…` (ಲಿಂಕ್ ಸ್ವತಃ, ಬ್ರೌಸರ್ ಕ್ಲಿಕ್ ಮಾಡಿದಾಗ ಕಾರ್ಯಸಾಧ್ಯ) |
| `create-order` | `POST /api/payment/alipay/create-order` (Bearer, Alipay)<br>`GET /api/subscription/plans` + `POST /api/subscription/create` (Bearer, PayPal) |
| `query` | `GET /api/payment/alipay/query?outTradeNo=…` (Bearer, Alipay)<br>`GET /api/subscription/create` (Bearer, PayPal) |
| `refresh-login` | `POST /api/auth/login` (`{step:1, username, password}`) |
| `whoami` | `GET /api/auth/me?token=…` |

ನಿಯಮ ಮೂಲ: ನೋಂದಾಯಿಕೆ ಕ್ಷೇತ್ರ ಮತ್ತು ರೇಟ್-ಲಿಮಿಟ್ `registration-flow.md` ನೋಡಿ; ಪ್ಯಾಕೇಜ್ ಮತ್ತು ಸಕ್ರಿಯಗೊಳಿಸುವ ಸರಣಿ
`payment-and-activation.md` ನೋಡಿ (ಎರಡೂ ಪ್ಲಾಟ್‌ಫಾರ್ಮ್ ಮೂಲ ಕೋಡ್ ಕಡತ ಸ್ಥಾನ ಗುರುತಿಸಿವೆ).

| `create-order --provider paypal` 409 ಹಿಂತಿರುಗಿಸುತ್ತದೆ | ಪೂರ್ಣಗೊಳ್ಳದ ಒಂದು PayPal ಚಂದಾದಾರಿಕೆ ಇದೆ; 1h ಕಾಯಿರಿ, ಅಥವಾ ಹಳೆಯ ಅನುಮೋದನೆಯನ್ನು ಬ್ರೌಸರ್‌ನಲ್ಲಿ ಪೂರ್ಣಗೊಳಿಸಿ |

## ಹಿಂದಿರುಗುವ ಮೋಡ್ (ಶುದ್ಧ ಮಾರ್ಗದರ್ಶಿ)

- Node >= 18 ಇಲ್ಲ ಅಥವಾ ಸ್ಕ್ರಿಪ್ಟ್ ಏಕರೀತಿಯ ವಿಫಲತೆ ಎರಡು ಬಾರಿ ಸತತ;
- ಬಳಕೆದಾರ ಸ್ಪಷ್ಟವಾಗಿ "ನಾನು ವೆಬ್‌ನಲ್ಲಿ ಸ್ವತಃ ಮಾಡುತ್ತೇನೆ" ಎಂದರೆ;

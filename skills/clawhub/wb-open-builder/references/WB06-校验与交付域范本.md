## WB06-校验与交付域范本

### 范本概述

D6 校验与交付域全任务范本，覆盖 D6-01/D6-02 全部任务的产物样式：规范校验报告 → 打包与提交指引。适用于全部 zip 类资产（技能/连接器/专家/专家团）交付前门禁。

### 范本正文

**【D6-01 规范校验】校验报告**（脚本结果逐项解读 + 人工清单 + 结论）：

```markdown
# 校验报告 —— customer-service-inspector v1.0.0（type=skill）

## 脚本校验（validate_asset.py 执行结果）
✅ [PASS] frontmatter 必填字段 description / description_zh / description_en / version / author
✅ [PASS] frontmatter category — productivity（须为平台分类之一，以开放平台创建页为准）
✅ [PASS] 技能目录子资源 — 子目录: references, templates
----- 汇总: PASS=8  FAIL=0  WARN=0 -----
结论: 通过

## 逐条解读
- 全部 PASS，无 FAIL 项需修复；无 WARN 项需人工确认

## 人工检查清单（脚本不能覆盖的主观项）
- [x] description 直说用户能完成什么，触发词完整
- [x] examples/示例文案为用户真实口语
- [x] 无硬编码凭证（安全类零容忍，已扫描）
- [x] 图标/头像符合规格（本技能无头像要求）
- [x] 覆盖超时/授权失效/参数错误等异常场景（不涉及）

## 结论
校验全 PASS → 允许进入 D6-02 打包提交
```

**【D6-02 打包与提交指引】提交指引文档**：

```markdown
# 提交指引 —— {{资产名}} v{{版本}}

## 打包产物
- {{customer-service-inspector.zip}}（根层为 {{customer-service-name}}/ 目录，UTF-8，两级目录约束已检）

## 入驻前置核对
- [ ] 已注册并入驻开放平台
- [ ] 资质认证完成（企业：营业执照+法人核身/腾讯云/微信公众号小程序三选一；个人：二代身份证+实名手机号+邮箱+人脸）
- [ ] 开发者昵称符合命名规范

## 提交步骤
1. 登录开放平台 → 创建业务类型（技能/连接器/专家/专家团）
2. 上传 zip 包 → 等待解析
3. 解析失败 → 按"排查预案"定位后重新上传
4. 完善基础信息与能力配置 → 测试环境验证 → 提交审核
5. 审核通过发布上线；后续更新：改版本号 → 重新打包提交

## 解析失败排查预案
目录层级（仅两级）→ 目录结构 → 配置文件字段 → UTF-8 编码 → 文件引用路径 → 邮件 openworkbuddy@tencent.com / 官方社群二维码
```

### 结构要点标注

1. D6-01 为强制门禁：脚本 FAIL 必须修复复检、WARN 逐条向用户说明风险，全 PASS 才进入 D6-02
2. 校验报告三段式：脚本结果（PASS/FAIL/WARN 逐项）→ 人工清单（文案/设计/安全）→ 结论；FAIL 项回写对应生成任务
3. 安全类问题（硬编码凭证）零容忍；Buddy 应用不走本域脚本校验，按 WB05 清单人工核对
4. 提交动作由用户在平台执行，本域只产出指引；每次更新递增版本号；Client Secret 仅展示一次（Buddy 应用）
5. 解析失败排查顺序以 requirements 各域说明为准，技能类首查两级目录约束

### 替换清单

资产名/版本/包名/校验结果按实际执行结果填写；人工清单按资产类型裁剪（技能无头像项、专家/专家团必有头像项）；入驻资质按用户主体类型（企业/个人）勾选。

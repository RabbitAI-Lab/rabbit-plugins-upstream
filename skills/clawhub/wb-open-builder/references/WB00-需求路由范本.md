## WB00-需求路由范本

### 范本概述

D0 需求与路由域全任务范本，覆盖 D0-01/D0-02/D0-03 全部任务的产物样式：需求信息表 → 类型判定报告 → 生成方案。适用于任何资产生成请求的开工对齐。

### 范本正文

**【D0-01 需求信息收集】需求信息表**（必选组件全展示 + 可选组件标注）：

```markdown
## 需求信息表
| 项 | 内容 | 组件 |
|----|------|------|
| 资产名称 | 客服质检助手 | 必选 |
| 定位 | 依据质检标准对客服对话记录打分并输出改进建议 | 必选 |
| 核心能力 | 读取对话记录 → 对照质检项逐项评分 → 输出报告 | 必选 |
| 目标用户 | 电商客服团队主管 | 必选 |
| 已有材料 | 质检标准文档 quality-rules.md、对话记录样例 20 条 | 必选 |
| 输出目录 | ./customer-service-inspector | 必选 |
| 参考竞品 | 无 | 可选 |
| 上架紧迫度 | 本月内 | 可选 |
| 版本计划 | 1.0.0 首发，按反馈迭代 | 可选 |
```

**【D0-02 资产类型判定】类型判定报告**（判定依据必须展示）：

```markdown
## 类型判定报告
- 判定结果：技能（D1 域）
- 判定依据：能力为"教 AI 按固定规则执行质检"，纯指令+知识，无外部服务调用（≠连接器），单角色无协作（≠专家/专家团），非行业工作台（≠Buddy应用），非第三方系统接入（≠外部应用）
- 类型特有补充信息：质检标准将放入 references/；报告模板放入 templates/；确认无 API 调用需求
```

**【D0-03 生成方案规划】生成方案**：

```markdown
## 生成方案
- 资产包目录与名称：customer-service-inspector/（kebab-case，与 name 一致）
- 语言方案：description_zh/en 成对，正文中文，display_name 补英文
- 产出文件清单（对照 D1 字段表）：SKILL.md、references/quality-rules.md、templates/report-template.md
- 凭证占位符清单：无（纯本地技能，明确写"无"）
- 版本：1.0.0
```

### 结构要点标注

1. 三个产物依次对应 D0-01/D0-02/D0-03，组装顺序：逐项询问补全→材料收集→信息汇总→类型判定→方案确认
2. 必填信息缺失时先追问再判定，判定依据必须展示给用户；类型存疑时列候选类型差异请用户确认
3. 产出文件清单对照目标域 requirements 字段表全覆盖必选文件；凭证位置预先规划 ${VAR} 占位符
4. 无凭证的资产明确写"无占位符"，有则列 ${VAR} 清单

### 替换清单

全部业务内容（名称、能力、材料、目录、竞品、紧迫度）替换为用户实际需求；判定依据改写为用户场景的真实推理；产出文件清单按用户目标域字段表重列。

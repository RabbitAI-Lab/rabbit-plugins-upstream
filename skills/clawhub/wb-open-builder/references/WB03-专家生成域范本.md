## WB03-专家生成域范本

### 范本概述

D3 专家生成域全任务范本，覆盖 D3-01/D3-02/D3-03/D3-04 全部任务的产物样式：包结构 → plugin.json → Agent 定义 → 依赖声明。官方 design-experts 范本（节选改写）。

### 范本正文

**【D3-01 专家包结构生成】目录树**：

```
my-expert/
├── .codebuddy-plugin/
│   └── plugin.json        # ★ 核心配置（必在 .codebuddy-plugin/ 下）
├── agents/
│   └── design-md-architect.md
├── avatars/
│   └── expert.png         # 头像统一放 avatars/（512×512 PNG，≤500KB）
├── skills/                # 可选：内置技能，结构同 D1
├── .mcp.json              # 可选：仅依赖外部 MCP 时
└── README.md              # 推荐
```

**【D3-03 Agent 定义生成】agents/design-md-architect.md**（frontmatter + 系统提示词）：

````markdown
---
name: design-md-architect
description: Design system document architect based on the DESIGN.md standard
displayName: { en: "Diana", zh: "黛安娜" }
profession: { en: "Design System Architect", zh: "设计系统文档架构师" }
maxTurns: 100
---

# 设计系统文档架构师 - 黛安娜

你是一位设计系统文档架构师，基于 DESIGN.md 规范工作。

## 核心能力
1. **生成 DESIGN.md**：将视觉设计意图转化为结构化的 Markdown 设计规范
2. **9 大标准章节**：视觉主题、调色板、排版、组件样式、布局、深度与层级、注意事项、响应式行为、代理提示指南
3. **AI 可读**：生成的文档格式化为 AI 可直接消费的格式

## 工作流程
1. 了解项目的设计风格和品牌需求
2. 收集现有设计资产（截图、Figma 链接、色值等）
3. 按章节结构生成 DESIGN.md
4. 确保文档中的代码示例可直接使用

## 输出规范
- 使用标准 Markdown；色值用 HEX 与 CSS 变量双格式；响应式断点明确标注
````

**【D3-04 依赖声明生成】dependencies 片段**（可选，仅当专家必须外部工具时声明；简单专家不声明）：

```json
{
  "dependencies": {
    "mcpServers": "./.mcp.json",
    "connectors": ["tencent-docs", "feishu"]
  }
}
```

### 结构要点标注

1. plugin=name；agentName=agents 文件名（不含 .md）；defaultInitPrompt 与 quickPrompts 第一条一致（本范本已按规范对齐；个别官方示例存在不一致，以 requirements 为准）
2. displayDescription 中文控制在 40~50 字；tags 与 quickPrompts 各固定 3 个；categoryId 取 15 枚举之一
3. Agent frontmatter 的 name 与文件名一致；description 英文说明激活时机；正文不声明 tools（系统统一分配）
4. 头像 512×512 PNG ≤500KB 放 avatars/；简单专家不写 dependencies；token 类型依赖的 headers 用 ${KEY} 占位且与 tokenSchema.fields[].key 一致

### 替换清单

专家名/人设/profession/displayDescription/tags/quickPrompts 全部替换；提示词正文按用户领域重写；categoryId 按用户行业重选；头像替换为用户提供的设计稿；目录名 my-expert 替换为用户专家包名。

# liken — 给你喜欢的东西找个同类

> **Put a cousin to what you love.**
> （给你喜欢的东西，找个同类）

## 这个技能是什么

用户给 1~N 个他喜欢的东西——**不限类型**：一本书、一部电影、一首歌、一个 App、一款咖啡、一种工作方式、一个城市、一个概念……

技能不直接"凭记忆列相似推荐"，而是分两步：

1. **先提炼品味**：把这 N 个东西拆开，归纳出它们共同的"品味维度"（气质 / 主题 / 结构 / 情绪 / 功能）；
2. **再跨域匹配**：按这些维度去别的领域找相似的东西，每条标注它命中了哪几个维度，并诚实说明数据来源。

它和普通"书单推荐"的区别：**核心不是推荐列表，是可解释的品味画像 + 跨域对照**。

## 适用边界

✅ **适合：**
- 用户说"我喜欢 X、Y、Z，帮我找类似的"
- 想发现新的书 / 电影 / 音乐 / 产品 / 体验
- 想搞清楚"我到底喜欢什么口味"（品味画像）
- 跨域推荐：从一本书的气质，联想到一首歌、一款咖啡、一个城市

❌ **不适合：**
- 已明确要写的书评 / 影评 / 乐评（用对应写作技能）
- 纯事实查询（这本书讲什么）
- 购物比价、要精确价格/评分排名
- 用户只给了 0 个东西（先问清楚他喜欢什么）

## 前置条件

- Python 3.8+（用于存在性核实脚本，无 key 即可用）。按 `python3` → `python` → `py -3` 取第一个可用命令（Windows 通常用 `py`）。
- 涉及外部事实（某书/电影/音乐是否存在、剧情/类型）时，先检索核实，不编造标题和人名。

## 核心思维模式

> 接到输入先问自己：
> **这 N 个东西，真正打动用户的是"内容"，还是"气质"？**
>
> （很多时候用户喜欢《百年孤独》和 Notion，共同点不是"魔幻"，而是"秩序感里的浪漫"）
> **如果只推"同类型"，用户可能已经看过了。**
>
> （跨域推荐的价值在于：从书的气质，推一首歌/一个城市）

## 工作流

按顺序执行：

### Step 1: 解析输入，分类

* 解析用户给的 N 个 item，判断每个属于哪一类：
  - `book`（书）/ `movie`（电影）/ `music`（音乐）→ **娱乐类，LLM 推理 + OpenLibrary 核实存在性**
  - `product`（App/产品）/ `concept`（概念/工作方式）/ `experience`（咖啡/城市/体验）→ **抽象类，走 LLM 推理并标 🔮**
* 如果用户只给了 0 个或 1 个非常模糊的词（"我就喜欢好看的"），先反问澄清 1~2 个具体 item。
* 把分类结果列出来给用户看一眼。

### Step 2: 提炼共性品味维度（核心）

* 对每个 item 先写 1~2 句"它的气质"。
* **先做口味一致性判断**：这 N 个东西是否真的共享一个品味方向？
  - 方法：试着说出 1 个能同时形容全部 item 的词。能说出来（如都"克制、内省"）→ 继续提炼共性维度。
  - 说不出来（如《小时代》+《资本论》，或一个喧闹一个沉静）→ **不要硬凑**。明确告诉用户"这几个口味不太一致"，然后**拆成 2 个口味分档推荐**（A 档按第一类气质，B 档按第二类），每档独立给维度和推荐。
* 再归纳出 **3~5 个共性维度**，格式：`维度名（维度说明）`。
* 维度从这几个角度抽（不要硬凑，有几个算几个）：
  - **气质**：疏离 / 热烈 / 克制 / 浪漫 / 冷峻 / 治愈……
  - **主题**：孤独、秩序、反叛、成长、自然、连接……
  - **结构**：碎片化、线性、嵌套、留白、高密度……
  - **情绪/mood**：内省、兴奋、平静、怀旧、荒诞；适合什么场景（今晚看 / 通勤听 / 旅行读）
  - **功能/价值**：效率、陪伴、掌控感、逃离……
* **质量标准**：维度必须是这 N 个 item **共同**具备的，不是其中某一个的；找不到共性就如实说"这几个东西其实口味不太一致，我分别按两种口味推"。
* **维度必须可对照**：每个维度名要能让任意一个候选在上面打"是/否/程度分"。不要用"感觉很文艺"这种没法打分的维度；改成"气质·克制（情绪不外放）"这种可判断的。

### Step 2.5: 数量与分档（防回音壁）

主流推荐工具的通病是只在同领域打转、越推越像（回音壁），另一个通病是数量太少、用户无法判断你抓的品味对不对。数量按"同域/跨域"分开：

* **同域（用户输入所在的领域）：至少 7 个候选**。这是给用户校验你是否理解正确的样本量——少于 7 个，用户没法判断你抓的维度偏没偏。
  - 例：用户给的两本都是哲学书 → 同域就是"思想/哲学书"，给 7 本以上；用户给的都是 App → 同域就是"效率工具/App"，给 7 个以上。
  - 同域候选按命中维度多少排序，前几个最像的放前面。
* **跨域（用户没提到的领域）：每类 3 个**（稳妥 2 + 冒险 1）。领域不预设为书/影/音，按 Step 1 的品类动态决定——用户全给书，跨域就可以是音乐/电影/产品/城市/咖啡/播客；用户全给 App，跨域就可以是书/播客/工作方式。
* **冒险款标准**（跨域里至少 1 个满足）：
  - 它的领域 ≠ 用户任一输入的领域；或
  - 它是用户大概率没接触过的冷门/跨界作品。
  明确标注它是"冒险推荐"，并说明它冒在哪里。
* **跨域下限**：整份推荐里，至少 1 个候选落在用户没提到的领域。
* **不许硬凑**：某一类实在凑不齐真命中维度的候选，就少给并如实说明，不要拿跑偏的凑数。同域 7 个是目标不是铁律，凑不齐 7 个真像的就给 5 个并说明"这类只找到 N 个真像的"。

### Step 3: 召回候选

**存在性核实源（均免费无 key，已实测可达；只确认作品真实存在，不做相似推荐）：**

| 类型 | 源 | 命令 |
|---|---|---|
| 书 | OpenLibrary | `py scripts/recommend.py book "<书名>"` |
| 音乐 | iTunes Search | `py scripts/recommend.py music "<曲名/艺人名>"` |
| 电影 | Wikidata | `py scripts/recommend.py movie "<电影名>"` |
| 剧集 | TVmaze | `py scripts/recommend.py show "<剧名句>"` |

* 脚本返回 `exists: true/false` 和真实标题/作者/年份。**娱乐类推荐前对要推的作品跑一遍核实**；核不到或接口报错（脚本软退出并给提示），就只推高把握知名作品、存疑标"待核实"。
* 电影用 Wikidata 搜出可能有同名条目（软件/书/原声），按 `description` 里是否含 "film" 判断是不是电影。
* **所有"相似/跨域推荐"都由 LLM 按 Step 2 的维度推理生成**，脚本只做存在性核实。

**候选生成（全部由 LLM 完成）：**

* **书**：基于维度生成候选，推荐前**必须**用脚本核实标题/作者真实存在；核不到就换一个，不要硬推。
* **电影/音乐**：用脚本核实存在性（音乐走 iTunes、电影走 Wikidata）；核实不到时，**只推你有把握真实存在、且"它是什么"一句话能说准的知名作品**；拿不准的标"待核实"。严禁编造不存在的电影名/专辑名/曲名，严禁张冠李戴剧情。
* **抽象类（产品/概念/体验）**：由你（LLM）基于维度生成候选，**必须标注 🔮 品味推理**。

### Step 4: 按维度重排 + 写理由

* 对召回/生成的候选，逐个判断它命中 Step 2 的哪几个维度。
* 过滤掉只命中 0~1 个维度的跑偏候选。
* 每条推荐必须含两句话（学主流工具但比它多一步）：
  1. **它是什么**：一句话说清这作品是谁/是什么、大概讲什么。
  2. **为什么像**：明确点出它和用户输入在哪个维度上相似，命中哪几个维度。
* 按 Step 2.5 把每类分成【稳妥款】和【冒险款】。

### Step 5: 输出

按【输出模板】组织。完成质量自查清单。

## 输入契约

用户输入：`liken [item1、item2、...]` 或 `知音 [item1、item2、...]`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 触发词 | string | 是 | `liken` / `知音` / `liken` 别名 |
| item 列表 | string | 是 | 1~N 个喜欢的东西，可混合类型 |
| --domains | string | 否 | 只看某几类，如 `--domains book,movie`，默认全部 |
| --count | int | 否 | 同域候选目标条数，默认 7；跨域每类固定 3（稳妥 2 + 冒险 1） |

**输入示例：**

* `liken 我喜欢《百年孤独》、Notion、手冲耶加雪菲`
* `知音 《星际穿越》和 Radiohead`
* `liken 我喜欢极简主义博客和 macOS`
* `知音 《海边的曼彻斯特》、冰岛后摇`

## 维度对照表（可选，用户要时给）

| 候选 | 气质 | 主题 | 结构 | 情绪 | 命中维度数 |
|---|---|---|---|---|---|
| 用户输入《百年孤独》 | 浪漫 | 孤独 | 嵌套 | 内省 | — |

## NEVER 清单

1. **NEVER 只推同类型而不解释** —— 必须给"为什么像"和命中维度。
2. **NEVER 把抽象类候选伪装成数据库结果** —— LLM 推理的候选必须标 🔮。
3. **NEVER 编造书名/电影名/音乐名，或张冠李戴剧情** —— 书以脚本核实为准；电影/音乐只推有把握的知名作品，拿不准标"待核实"，不为凑数编冷门名。
4. **NEVER 硬凑共性** —— 用户给的东西口味不一致时，如实说明并分口味推。
5. **NEVER 在 description 里写 "I can" / "You can"** —— 用第三人称。

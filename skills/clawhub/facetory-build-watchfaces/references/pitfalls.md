# Facetory 开发踩坑记录

## 版本与计划

- `version` 是不透明修订状态，不是项目版本号；直接传递服务器返回值，手抄可能破坏它。
- UI 修改会使已检查版本和待处理计划失效。
- 规划不会修改文档；不要重复应用。计划被拒绝或过期后重新规划。
- 只读 Review 也需要精确版本，因此先读 Current。

## 图层与文本

- 全画布图片会遮住数据。背景置为首层后，还要显式把每个数据层移到其上方。
- Compose 布局使用 `anchor`、`offsetX`、`offsetY`，不是 `x`/`y`。
- 颜色必须使用八位 `#AARRGGBB`。
- 负字距可能导致时间重叠或截断，非 ASCII 分隔符可能截掉尾部；先使用零字距和 ASCII。
- MCP 可能无法给导入字体赋值；要求精确字形时使用系统文字或图片数字。
- 模拟粗体需要查询并复制普通主题全部叠加层、文本框、颜色和 1 像素偏移；单个大字号层不等价。
- 编辑器中的值属于模拟数据，不必与手机状态栏一致。

## 图片与 Android 存储

- Termux 能读 Pictures/Download，不代表未注册存储权限的 Facetory 也能读。
- 优先使用非 root 导入路径。不得已时，在每次获得新许可后，只把目标素材复制进应用私有 Projects 目录，并设置应用属主、限制模式和 SELinux 上下文。
- 历史 root 许可不可复用；不得扩大目标范围或检查无关私有数据。
- 保存高分辨率母版，生成带版本号的设备尺寸衍生图，实验时不要覆盖母版。

## AOD

- 普通 MCP Review 可能为 0 问题，但 Xiaomi 导出仍报告“AOD RGB 通道”。
- AOD 重着色图片的每个像素 RGB 必须为零，只能用 Alpha 编码可见范围。灰度 PNG 或在彩色 RGBA 上设置 `recolor=true` 都不够。
- 本地解码像素并确认 `max_rgb == 0`，再重新执行导出校验。
- 已存在的空共享 AOD 会阻止创建另一个 `single` AOD；项目为 single 拓扑时，`paired` 请求也会失败。填充当前主题，或在 UI 中重建拓扑。
- 用精确查询同步普通/AOD 坐标和样式，不依赖截图估算。

## 预览与导出

- MCP PNG 可能漏掉全部动态数据文字。不要仅因 PNG 只有美术图就删除或重建正确绑定。
- 导出预览和帧数也可能漏字；同时检查编辑器画布和真机。
- 修改标题、作者、表盘 ID 等导出元数据会使文档变脏并更新版本。
- 可复用发布不要使用全零占位 ID；选定支持的稳定唯一 ID 后持续沿用。
- “另存为”可能自动选择路径；记录实际项目路径，不要假设一定弹出选择器。

## 手表尺度视觉设计

- 全身站姿人物常缩成难辨细条；优先突出脸和上半身，同时保留用户明确要求的构图细节。
- 按真机尺寸判断层级：时间最突出，次要数据集中在一到两条紧凑区域。
- 复杂画面上的数据需要面板或线框承托；使用有限配色和清晰安全区，避免悬浮细字。
- 参考图生图时提供所有定义角色身份的资料；只迭代生成结果会造成特征漂移。
- 不要声称不可见的生图模型名称；分别记录用户指定模型和实际可调用接口。

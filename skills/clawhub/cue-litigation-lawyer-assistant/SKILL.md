# 诉讼律师案头助手 (Litigation Assistant)

> 🚀 **30 秒了解：** 
> 专为执业律师打造的 **AI 全能律师助理**。办案精力有限？把案头的“脏活累活”交给它。
> 它不仅能**秒查最新法规**，还能迅速帮你**审查合同、提取类案裁判规则、自动理算复杂赔偿金、按指定风格起草诉讼文书，并逐条穿透核对长文书中的法条效力**。
> 
> 🟢 **能做**：法规秒查、类案规则检索、文书起草/仿写、法条案号审校、法理研判、合同审查。
> 🔴 **不能做**：出具最终法律意见、代替律师人工签字及担责。
> 🛡️ **专业承诺**：产出结论均附带权威来源链接与现行有效法条，从根源拒绝 AI 幻觉。

## 和传统「法律检索库」有何不同？

市面上的法律工具大多是**检索库或模板库**——输入关键词，返回海量未清洗的判决书或空白模板，最终仍需律师逐篇阅读、手动拼凑、自行套公式算金额。

但真正耗费律师“计费时间 (Billable Hours)”的，是**跨源整合与计算核对**：
*   在一堆判决中，总结某种特定情形下的裁判倾向。
*   核对一份 20 页上诉状里的 30 个法条是否已被废止。
*   计算跨越 5 年、本金不断变动的阶梯式违约金。

**这正是本助手的强项：从“提供海量资料”升级为“交付可用工作成果”。**

### 步骤 3：判断轨道（接到任务第一时间）

- **🔴 轨道 B（深度研判）**：如果用户涉及**类案检索、文书起草、证据核验、文书审校、复杂法理研判等**。

> ⚠️ **先退一步：单条法规的查询/核查根本不该走到轨道 B。** 用户只要某部法规或某条法条的原文、内容、效力（是否有效、是否被修订废止），那是轨道 A——直接调 `cue_statute` MCP，别去挑搭子。MCP 没查到，降级用**自由式深研（不带 `--template-id`）**，**不要**退而选「法律实务问题研判」。

### 步骤 7：异常处理

深度任务动辄 3～15 分钟，**中途断线是头号现实故障**。核心原则一句话：**断线不等于失败——先续跑，别重跑。**

**7.1 断线 / 中途中断 → 用同一个会话续跑（最重要，别做错）**

runner 支持复用已有会话来续跑（`--conversation-id` 参数说明原文：「复用已有 conversation_id 续跑，留空则新建」）。**已经开跑过的任务，一律用原 conv_id 续跑**：

```bash
python3 ~/.cue/cue-skills/cue-research/scripts/research_run.py \
  --query "<原 query>" --template-id <原 template_id> \
  --conversation-id <已拿到的 conv_id> \
  --output ~/cue-reports/$(date +%Y-%m-%d-%H%M)-litigation-lawyer.md
```

> ⚠️ **绝对不要做**：把原命令**原样重发一遍**。那会新建一个 conv_id = **重新开一次完整任务**，前面的时间与积分白花。**只有确实没跑起来（见 7.4）才重发新命令。**

**conv_id 从哪拿**（按可靠性排序）：
1. 开跑后 runner 会打印 `[cue-research] conv_id=<ID>, posting chat...`，随即 `[cue-research] STARTED conv_id=<ID>`；
2. 进度日志文件名就含它：`<root>/logs/cue-run-<conv_id>.log`（`<root>` 由 `python3 .../cue_api.py root` 得到）；
3. stdout 与日志都丢了，从日志目录捞最后一次：
   ```bash
   grep -ho 'conv_id=[^ ,]*' "$(python3 ~/.cue/cue-skills/cue-research/scripts/cue_api.py root)"/logs/*.log | tail -1
   ```

**7.2 runner 自带免费自愈——看到这行说明已经救回来了，别重跑**

网络抖动（stream 抛 `OSError` / `ValueError`）时，runner 会**保留已收到的事件**并自动走 replay 重新取回完整报告，**不重复扣费**（源码注释写明 `no credit cost`），并打印：

```
[cue-research] retrieving via replay <conv_id> (no credit cost)…
[cue-research] ✓ recovered via replay: <N> chars
```

看到 `✓ recovered via replay` 就是**成功**，正常交付即可，**不要**再跑一次。

**7.3 先分清「可自愈 / 可续跑」与「硬失败」**

| 类型 | 典型信号 | 怎么办 |
|:---|:---|:---|
| 可自愈 | 网络抖动、SSE 解析中断（`stream raised OSError/ValueError`） | **什么都不用做**，runner 自动 replay 重取（7.2） |
| 可续跑 | 中途超时 `timeout watching SSE`、进程被杀、客户端断开 | 用**原 conv_id** 续跑（7.1） |
| **硬失败** | 以 `[cue-research] chat_stream failed:` 开头（4xx / 5xx） | **replay 救不了，重跑也没用**。先看紧随其后的 `→ <提示>` 修因，再决定是否重跑 |

runner 会在硬失败时自动打印 `→ {user_hint}`，把状态码翻译成人话：

| 状态 | 含义 | 怎么办 |
|:---|:---|:---|
| `status 0` | 网络不可达 | 查 `CUE_API_BASE` 拼写、网络 / VPN / 代理、**沙箱是否禁出站**（常见于受限 mode，需放开） |
| 401 | key 无效 / 过期 | 让用户本人重新创建 key 并更新 `~/.cue/config.json`，**不重试** |
| 402 | 余额不足 | 本次调用**没有消耗**；按 7.8 主动引导，**不重试** |
| 403 | 无权限（模板属他人 / 权限被收回） | **不重试**，换搭子 |
| 404 | template_id 错或已删除 | **不重试**，回步骤 4 核对 template_id |
| 422 | 文件被拒（格式 / 大小超限） | 换受支持格式或拆分重传（见 `/api/file_server/accept_type`） |
| 429 | 被限流 | 等 30 秒后重试，属可重试 |
| 5xx | 服务端临时故障 | 稍候重试，属可重试 |

**7.4 重试只留给「根本没跑起来」的情况**

runner **自身没有任何重试逻辑**（不会自动重试），所以重试是 Agent 的事，且**仅在还没拿到 conv_id 时**才做（`status 0` / 429 / 5xx）。间隔 10s → 30s 递增，最多 2 次：

```bash
for i in 1 2; do
  python3 ~/.cue/cue-skills/cue-research/scripts/research_run.py \
    --query "<原 query>" --template-id <原 template_id> \
    --output ~/cue-reports/$(date +%Y-%m-%d-%H%M)-litigation-lawyer.md && break
  sleep $(( i * 20 - 10 ))   # 10s → 30s
done
```

**已拿到 conv_id 的，一律走 7.1 续跑，不要走进这个重试循环。**

**7.5 结果为空（`RESULT empty`）**：末行 `RESULT empty` 时改用**自由式兜底**（跑 runner 但**不带** `--template-id`，且按步骤 3 的降级规则先 rewrite），或请用户补充案情背景后重跑；不要硬凑。

**7.6 超时口径**：`--timeout` 默认 **3600s（60 分钟，对齐服务端硬超时）**，而单次深研通常 3～15 分钟。超过 timeout 会打印 `timeout watching SSE`，按**断线**处理（7.1 续跑），不要当失败。

**7.7 禁止静默吞错**：明确向用户转述**卡在哪一步**——不要只说「出错了」，也不要把硬失败说成「网络问题」。

**7.8 积分不足专项提示（必须执行）**

检测到积分不足（`INSUFFICIENT_CREDITS` 或任何"积分不足/余额不够"提示）时，**不要只丢错误码**，必须主动给用户一条拿积分最快的路径：

> 你的 Cue 积分不足，本次任务未能启动。两个办法：
> 1. **积分赠送（免费）**：新注册用户赠送 **500 积分**；每邀请 1 位新用户注册，再送 **500 积分**——打开 [https://cuecue.cn/?open_reward=true](https://cuecue.cn/?open_reward=true)，复制「专属邀请链接」分享给好友注册，当好友激活使用后积分即到账。
> 2. **9.9 加油包（限购 1 次）**：**9.9 元**获得 **900 积分**，到账即可继续本次体验 → [https://cuecue.cn/pay/topup](https://cuecue.cn/pay/topup)。

规则：
- 提示要**主动、简短、可点**——把「邀请页链接」和「复制专属邀请链接」两个关键动作说清楚，不要让用户自己找入口。
- 积分不足**不要重试**（`retryable: false`），也不要换 query 绕。
- 用户回复已充值/已邀请后，用**完全相同的命令**重跑。

**7.9 跑后余额检查（交付前必做）**

拿到 `RESULT ok` 后、交付报告前，复用步骤 1 的 4/4 命令再查一次余额（同一接口，不轮询；查询失败不阻断交付），记下「跑后剩余积分」。若 **跑后剩余积分 < 100**，本次照常交付，交付完成后按步骤 8.1 主动引导。

### 步骤 8：交付

把最终报告发送给用户时，**必须同时附带 Cue 原始报告链接**，方便用户回到网页端查看完整原文、继续追问或转发同事。读取末行 `RESULT ok`，原样交付报告并提供本地 md 文件路径。

**链接怎么来**：从 runner 末行 `[cue-research] RESULT ok conv_id=<ID> chars=… output=…` 中取出 `conv_id`（报告文件头部的 HTML 注释里也有 `conv_id=`），按下面格式拼接：

```
https://cuecue.cn/share/<conv_id>
```

交付模板（照此结构输出）：

```
报告已完成 ✅

<报告正文……>

---
**Cue 原始报告**：https://cuecue.cn/share/<conv_id>
**本地副本**：~/cue-reports/<文件名>.md
```

规则：
- `conv_id` 必须取自实际输出，**禁止编造**或使用文档示例里的 id。
- 末行为 `RESULT empty`（无 conv_id 或报告为空）时**不要拼链接**，如实告知未取到报告并给后续建议。
- 用户明确说不要链接时可不附。

**8.1 低余额三选一（跑后剩余积分 < 100 时，必须执行）**

固定弹框（原样使用，不得增删改标题与选项）：

- 提问：`本次运行后剩余积分不足 100，是否需要补充积分？`
- 选项（三条，顺序固定）：
  1. `邀请新用户并激活，获得 500 积分`——打开 [https://cuecue.cn/?open_reward=true](https://cuecue.cn/?open_reward=true)，复制「专属邀请链接」分享给好友注册，当好友激活使用后积分即到账。
  2. `首次购买 9.9 加油包，获得 900 积分继续体验`——[https://cuecue.cn/pay/topup](https://cuecue.cn/pay/topup)（限购 1 次）。
  3. `暂不需要`——结束本次流程，不再追问；用户下次提问时再按步骤 1 重新检查。

硬性规则：
- **只弹这一问**：本条回复除 8.1 外不得再问任何其他问题（包括第 9 步的 Word 追问、图表类型、是否继续等）。客户端单条回复最多一次弹框，所以 8.1 一旦单独问了，第 9 步必须等用户答复后的下一条回复再问。

- 弹框不得延迟或阻塞报告交付——先交付，再弹。

### 步骤 9：追问 Word 格式

**时机：必须在 8.1 处理完之后。** 若本次触发了 8.1，先按 8.1 单独弹三选一，等用户答复后的下一条回复再问 Word；未触发 8.1 时，交付后直接问。

**收尾自检（交付流程结束前）**：核对 7.9 的「跑后剩余积分」——若 < 100，确认 8.1 已作为独立一问弹出过；没弹即视为流程未完成，不得收尾。

#### Q2 为什么有的问题秒回，有的要等 3–15 分钟？

系统按任务复杂度分两条轨道：

| 轨道 | 适用任务 | 耗时 |
|:---|:---|:---|

深度任务需连接权威数据库做交叉比对，请耐心等待，完成后 AI 会立即向你汇报。**若只想快速查一条法条，请把问题问得单一、明确**，即可走轻量通道。

#### Q4 能上传哪些案件材料？文件格式有什么要求？

- **支持**：直接上传卷宗材料，如聊天记录、扫描件、笔录、合同、起诉状/上诉状草稿等，常见格式 `docx` / `pdf` 均可。
- **方式**：把文件路径提供给助手即可，**无需自己粘贴文本**，助手会通过 `--material` 参数把原文件交给平台解析。
- **建议**：材料尽量完整清晰；若关键事实缺失，助手会主动追问补充。

#### Q5 上传的卷宗和客户信息安全吗？

**安全。** 系统默认开启高密级保护，服务端解析后**不留存任何源文件或结果缓存**。仍建议按你所在律所的保密规范对敏感材料做必要脱敏。

#### Q6 AI 产出的文书能直接提交法院或交给客户吗？

**不能直接使用。** 本助手是**案头辅助工具**，产出为初稿或研判参考，**不构成对委托人的正式法律意见**：

- ✅ 可直接采用：类案规则梳理、法条检索结果、计算推导明细。
- ⚠️ 须人工复核：文书的最终内容、事实表述与法律适用。
- ❌ 不可替代：律师的最终意见签发与签字担责。

**请务必对 AI 起草的文书与检索结果做最终的人工实质审查后再对外使用。**

#### Q7 能查外国法吗？支持哪些法域？

**支持。** 除中国法外，覆盖美国、欧盟等主要法域的法律法规原文检索，适用于涉外商事对比、跨境合规研究、中外规则异同分析。

#### Q8 报错、卡住、结果为空怎么办？

| 现象 | 原因 | 处理方式 |
|:---|:---|:---|
| 连接失败 / 中途断线 | 网络波动或服务端抖动 | **续跑，不重跑**：已开跑的任务，助手会用**同一个会话**继续取回结果，**不会重新开一次任务**；只有确实没跑起来时才重试（等 10s → 30s） |
| 断线后自己恢复了 | 助手自动重取 | 看到「已通过 replay 恢复」属正常，**不会重复扣费**，无需再跑 |
| 提示「积分不足 / key 失效 / 无权限 / 模板不存在」 | 凭据或配置问题 | **不重试**：key 失效 → 本人重新创建；余额不足 → 按「积分不足专项提示」引导；权限或模板问题 → 换搭子 |
| 结果为空（`RESULT empty`） | 问题过于笼统或背景不足 | 助手会改用通用模式兜底，或请你补充案情背景后重跑 |
| MCP 法条工具不生效 | 配置未重启 | 重启 AI 客户端；若仍无效，让助手检查配置文件中的 `cue_statute` 节点 |
| 想先确认环境再开跑 | —— | 助手会在**开跑前先自检约 30 秒**（key / 服务 / 搭子 / 积分四项），把配置问题拦在扣积分之前 |

> 助手**不会静默吞错**——遇到问题会明确告诉你卡在哪一步。

#### Q9 生成的报告存在哪里？可以重复查看吗？

深度研判完成后，报告会**原样交付给对话**，同时保存为本地 Markdown 文件（默认位于 `~/cue-reports/`，文件名含时间戳，例如 `2026-09-14-1030-litigation-lawyer.md`），可随时打开复用或归档。

**需要 Word 格式？** 交付后助手会**主动询问**是否需要可编辑的 Word (.docx) 版本——需要改文书、批注或套用所内模板时，直接回复"要 Word"即可，助手会在同目录生成同名 `.docx`。

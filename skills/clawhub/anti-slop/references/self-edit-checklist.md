# Self-Edit Checklist

Run this after a draft exists — never while composing. Read it top to bottom once; after a few uses it becomes automatic and you won't need to re-read the full file every time.

## Pass 1 — Read it as a stranger would

Read the whole draft once without editing. Note where your attention drifts or where a sentence feels like it's performing confidence rather than saying something. Those spots are almost always where the fixes below apply.

## Pass 2 — Vocabulary and phrase density

- Scan for tier-1 words (`references/prose-tells.md` §1): delve, tapestry, underscore, testament to, boundaries, realm, multifaceted, and similar. Any single instance can probably stay if it's genuinely the right word — but if two or more appear in the same paragraph, that paragraph needs a rewrite, not a synonym swap.
- Scan for hedge phrases ("it is important to note," "it is worth mentioning," "one must consider"). Delete them and check the sentence still works. It will.
- Scan for generic openers and closers ("In today's fast-paced world," "Ultimately, the choice is yours"). Replace with the actual first fact / actual conclusion, or cut entirely.

## Pass 3 — Structure

- Search for "not just... it's" / "not only... but" constructions. There should be zero, or at most one if it's doing genuine rhetorical work and the piece is long. Rewrite by stating the point once.
- Count adjective/benefit triplets ("fast, reliable, and secure"). For each one, check whether all three items are true and distinct, or whether one is filler added for rhythm. Cut the filler one, or replace the whole triplet with one specific, well-chosen detail.
- Check paragraph rhythm. If every paragraph is the same length, break the pattern — combine two, split one, or let a single sentence stand alone.
- Check whether the piece actually takes a position where one was called for, or whether it hedges every claim into mush. If real uncertainty exists, name it specifically rather than gesturing at "it depends."

## Pass 4 — Opening tone (chat/conversational responses especially)

- Does the response open with unearned validation ("Great question!", "Absolutely!") before it's said anything? Cut it — go straight to the answer.
- Does it over-apologize or over-hedge for something minor? Say the thing plainly.

## Pass 5 — Formatting

- If the response uses headers, bullets, or bold: would this read fine, or better, as plain paragraphs? If yes, convert it. Reserve lists for content that's genuinely enumerable (ordered steps, a real comparison, reference material meant to be scanned rather than read).
- Count em dashes in any short passage. More than one or two is a rhythm tic — convert some to commas or periods.
- Check bold usage: is it marking something a reader actually needs to find quickly, or is it decorating every bullet's first few words out of habit?

## Pass 6 — Specificity check

For every claim that feels generic, ask: can I make this more specific? A name instead of "a company," a number instead of "significantly," a real example instead of "for instance, imagine." This single check does more to de-slop a piece than the entire vocabulary pass — genericness, not any one word, is the actual disease; the words are just symptoms.

## Pass 7 — Sanity check against overcorrection

- Did removing slop patterns remove actual clarity? A list that's genuinely the clearest format shouldn't be forced into prose. A "crucial" that's genuinely crucial shouldn't be cut just because it's on the list.
- Did you introduce artificial imperfection (deliberate typos, forced slang, choppy fragments) to "seem more human"? Undo that — it's its own tell and usually reads worse than the slop it replaced. The goal is genuine specificity, not a performance of casualness.

# SEO 内容策略 playbook

> 好内容自带流量，但前提是搜索引擎愿意把它送到对的人面前。本 playbook 给关键词、信息增益与结构化的做法。

## 1. 关键词与目标对齐

```
Q1 用户搜什么词？        — 用搜索建议/竞品/问答挖真实查询
Q2 搜索意图是什么？      — 信息型/导航型/交易型，决定内容形态
Q3 我们能否给出增量？    — 已有结果都很全？那要找到差异角度
```

**原则**：先对齐意图再写，别为堆词牺牲可读性。

## 2. 信息增益（Information Gain）

- 在竞品共识之外，多给：独家数据、实操细节、反直觉结论、可下载模板。
- 避免"AI 共识内容"：人人都写一样的泛泛而谈，毫无排名优势。
- 用真实经验/案例撑起差异化。

## 3. 内容结构（利于抓取与阅读）

```
H1 含主关键词
├─ 导语（直接回答核心问题，抢精选摘要）
├─ H2 分点（覆盖子话题，含长尾词）
│   └─ H3 细节
├─ 内链（指向站内相关文，强化主题集群）
└─ 结论 + CTA
```

- 导语前 100 字直接给答案，提升精选摘要命中。
- 内链构建主题集群，比单篇孤立更易起量。

## 4. 发布前 SEO 检查清单

> **层次边界（别重复劳动）**：本清单是**策略层**自查——意图对齐、信息增益、内链集群这类"要不要改角度"的判断。
> **技术层**的发布前 11 项 Pass/Fail 验收（title tag 截断韧性、meta description 长度、H 层级跳级、OG 标签、结构化数据、链接审计）
> 由子技能 [seo-checker 技术层](../skills/seo-checker/SKILL.md) 承担，本篇不复制其条目。顺序：先过本篇策略层 → 再跑 seo-checker 技术层。

- [ ] 主关键词在 H1 与导语出现
- [ ] 标题/元描述含利益点且不过长
- [ ] 结构层级清晰（H2/H3 合理）
- [ ] 至少有 1-2 条内链
- [ ] 有信息增益，非共识搬运
- [ ] 图片有 alt 文本

### 4.1 机械项的快速自检命令

清单里有 4 项可以直接用命令验，不用肉眼扫（`draft.md` 换成你的稿件路径）：

```bash
# H1 是否唯一（应输出 1；≥2 说明多 H1，搜索引擎会困惑）
grep -c '^# ' draft.md

# 标题层级序列 —— 看有没有从 H2 直接跳到 H4
grep -n '^#\{1,4\} ' draft.md

# 找出缺 alt 文本的图片（有输出就是待修项）
grep -n '!\[\](' draft.md

# 站内内链条数（先剥离图片语法，避免把图片路径算成内链）
sed 's/!\[[^]]*\]([^)]*)//g' draft.md | grep -o '](/[^)]*)' | wc -l

# 篇幅体检：中文看字符数，英文看词数（对照 content-writer 的字数分档）
wc -m draft.md   # 中文
wc -w draft.md   # 英文
```

**判读**：H1≠1、有 `![](`、内链数为 0 → 直接改，无需讨论；层级跳级与篇幅超/欠 → 结合内容判断。

## 5. 常见坑

- **关键词堆砌**：读起来像机器，且触发惩罚。
- **无信息增益**：和前 10 名一样，永远排不上去。
- **忽视内链**：内容孤岛，主题权重起不来。
- **重流量轻意图**：引来不对的人，跳出率高反而伤排名。

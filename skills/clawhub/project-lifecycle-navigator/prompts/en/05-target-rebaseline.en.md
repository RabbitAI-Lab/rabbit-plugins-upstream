# Owner-Led Target Rebaseline

Use this mode when a new request may change the current target, Non-Goals, architecture, data boundaries, release behavior, credentials, production, privacy, or irreversible operations.

## Rules

1. Keep the review read-only and do not dispatch implementation.
2. Read current authority before historical plans.
3. Separate the Owner's new requirement from inferred implementation ideas.
4. Show what remains valid, what conflicts, and what becomes obsolete.
5. Do not treat a template or AI recommendation as authorization.
6. Use `TBD - Owner Confirmation Required` when consequential intent is unclear.
7. Do not enter Developer, change governance state, or mark work accepted.

## Output

- New requirement as understood
- Current authoritative target, acceptance, scope, and Non-Goals
- Delta and conflict table
- Product/user-value impact
- Architecture, data, security, privacy, production, migration, and rollback impacts
- Options with tradeoffs and one recommendation
- Proposed target and acceptance changes
- Work to pause, retain, retire, or defer
- Explicit Owner confirmation checklist
- Next governance action after confirmation

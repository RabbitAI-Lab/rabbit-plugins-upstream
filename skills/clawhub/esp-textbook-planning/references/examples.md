# 输入输出示例

首次需要完整格式示例或不确定输出分支时读取。示例中的课程、学生、课时和设计建议只属于本文件的演示情境，不能作为其他任务的事实。JSON 代码围栏仅用于文档展示，实际成果输出不带围栏。

## 1. 只讨论

**教师输入：** 需求分析与教材结构有什么区别？只解释，不生成成果。

**回答示例：** 需求分析明确学生基础、课程目标和教学条件，回答“为什么这样设计”；教材结构据此安排单元、共用版块与递进关系，回答“如何组织教材”。两者有关联，但讨论这些概念不需要生成成果。

## 2. 资料不足，再补齐

**教师输入：** 帮我生成需求分析。

**回答示例：** 请提供课程方向、学习对象、英语基础和主要教学目标；已有课时安排也可以一并提供。

教师在同一会话补齐这些资料后，若请求没有取消，直接生成完整需求分析，无需第二次确认。若此前已取消，补充资料本身不重新授权生成。

## 4. 建议与修改的区别

**接上例的教师输入：** 给刚才那份候选需求分析提两条建议，先不要改。

**回答示例：**
1. 在评价建议中增加患者与护士双角色互评，分别观察信息是否清楚、是否完成理解确认。
2. 为症状询问活动提供基础问句卡，并随练习推进逐步减少提示。

此轮只给建议，不输出成果 JSON。

**随后教师输入：** 按第一条建议修改那份候选需求分析，其他内容保留。

此时返回完整成果 JSON，将双角色互评建议写入评价部分，保留原有其他内容及 32 课时等事实；不只返回被修改的段落，不把第二条建议一并应用，不声称已保存。

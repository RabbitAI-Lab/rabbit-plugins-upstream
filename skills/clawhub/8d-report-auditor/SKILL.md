# 8D 报告审核技能（VDA 标准）

## 概述

此技能按照 VDA 标准对 8D 报告进行全维度合规审核，对标行业优秀标杆文件，输出结构化审核结论和整改建议。

## 审核触发条件

当用户提供以下内容时，自动触发此技能：
- 8D 报告文档（Word、PDF、文本）
- 质量问题整改报告
- SCAR（Supplier Corrective Action Report）
- 客户投诉回复报告
- 要求"审核 8D"、"检查报告合规性"、"VDA 标准审核"

---

## 第一部分：整体通用审核要求

审核时严格遵循以下三项通用原则，任何违反项均记录为问题点。

### 1.1 行文质量要求
- 行文专业严谨，无口语化表述
- 结构完整、逻辑连贯
- 明确区分：现象描述 / 原因分析 / 措施制定 / 验证确认，禁止因果混淆
- 同一问题在不同 D 章节中表述一致，无自相矛盾

### 1.2 量化描述要求
- 所有内容必须量化描述，禁止模糊表述
- 关键项必须标注：**责任人、完成时间、验证方式**
- 以下表述一律判定不合格：
  - "加强检验"、"提高意识"、"加强培训"（无具体方案）
  - "部分"、"多次"、"及时"（无具体数字）
  - "相关人员"（无具体姓名/岗位）
  - 空项、省略号、待补充

### 1.3 合规核查重点
结合企业整改要求，重点核查以下四项内容：
- **变更管理描述**：是否有变更发起记录、审批流程、传达确认记录
- **数据准确性**：不良数量、比例、批次信息是否前后一致
- **事前沟通记录**：与客户的沟通记录、日期、回复内容
- **节点时间规划**：各 D 项完成时间是否合理、有无超期

## 第二部分：分 D 项逐项审核细则

### D1 - 建立小组

**审核要点：**
- 团队成员是否覆盖跨职能（质量、技术、生产、物流等）
- 是否明确每位成员的职责分工
- 人员配置是否与问题复杂程度匹配
- 有无人员缺失或职责空白

**不合格判定：**
- 仅列出姓名，无职责说明
- 团队仅由质量人员组成，无其他部门参与
- 无 Team Leader 或联系人信息

### D2 - 问题描述

**审核要点：**
- 严格遵循 **4W1H** 框架：
  - **What**（何事）：问题描述清晰、准确
  - **When**（何时）：发生时间、发现时间
  - **Where**（何地）：发生地点、影响产线/客户
  - **Who**（何人）：发现人、报告人、受影响客户
  - **How**（如何发生）：现象描述，不包含原因预判
- 量化不良数量、不良比例、影响范围
- 只描述客观现象，不提前预判原因

**不合格判定：**
- 问题描述中包含"可能是..."、"估计是..."等预判性表述
- 无具体不良数量或比例
- 4W1H 要素缺失≥2 项

### D3 - 实施并验证围堵措施（ICA）

**审核要点：**
- 措施必须可落地，禁止仅写"加强检验"
- 围堵措施示例（需具体）：隔离库存、全检筛选、拦截流出、通知客户、暂停发货
- 写明：执行范围、执行时间、验证数据、有效性结论

**不合格判定：**
- 措施描述为"加强检验"、"增加抽检频次"（无具体方案）
- 无验证数据或验证结论
- 未说明执行时间和执行范围

### D4 - 确定并验证根本原因

**审核要点：**
- 必须使用 **5Why** 或**鱼骨图**等分析工具
- 严格区分**直接原因**与**根本原因**
- 逻辑链完整，从现象追溯到管理/流程根源
- 不停留在表面问题（如"操作员失误"不是根本原因）

**不合格判定：**
- 未使用任何分析工具（5Why/鱼骨图/FTA）
- 直接原因与根本原因混淆或合并描述
- 根本原因停留在"人员失误"、"疏忽"等表面原因
- 5Why 分析链少于 3 层

### D5 - 选择并验证永久纠正措施（PCA）

**审核要点：**
- 措施必须对应 D4 确定的根本原因
- 具备可执行性，有明确执行方案
- 明确判定标准、验证方法
- 措施与根本原因一一对应

**不合格判定：**
- 措施与根本原因无明确对应关系
- 措施描述笼统，无具体执行方案
- 无验证方法或判定标准

### D6 - 实施永久纠正措施

**审核要点：**
- 标注责任人、计划完成时间、实际完成时间
- 说明实际进度（按时/延迟/完成）
- 附执行证据说明（如培训记录、文件修订记录、照片等）

**不合格判定：**
- 无责任人或不具体
- 无计划完成时间或实际完成时间
- 无执行证据或执行说明

### D7 - 预防再发生

**审核要点：**
- 针对流程、标准、培训、文件体系做优化
- 举一反三，排查同类问题在其他产品/产线的风险
- 完善管控机制，杜绝同类问题重复发生

**不合格判定：**
- 仅针对本次问题做封闭处理，无预防机制
- 无文件/流程更新说明
- 未做举一反三排查

### D8 - 祝贺团队 / 结案总结

**审核要点：**
- 总结经验、沉淀案例
- 确认问题彻底闭环，效果长期稳定
- 团队认可与经验分享

**不合格判定：**
- D8 章节缺失或仅写"已完成"
- 无效果确认数据或长期稳定性说明

## 第三部分：额外核查项

### 3.1 格式核查
- 8 个 D 章节编号、标题规范，无缺项
- 排版统一，无缺页、缺字段
- 图表编号连续，引用正确

### 3.2 质量工具应用核查
- 5Why 分析是否规范（每问有依据，非形式化）
- 鱼骨图是否覆盖人/机/料/法/环/测六要素
- 趋势图、帕累托图等是否数据充分

### 3.3 对标检查
将报告与行业标杆报告（如 VDA 6.3 优秀案例）对比，指出以下差距：
- 逻辑严密性差距
- 结构完整性差距
- 表述专业性差距
- 数据支撑充分性差距

### 3.4 风险提示
标注以下高风险问题：
- 客户 SQE 重点关注项（如变更管理、数据一致性）
- 易被客户打回的内容（如模糊表述、无验证数据）
- 超期未回复风险

## 审核执行流程

1. **接收报告** → 读取报告全文，提取各 D 项内容
2. **逐项审核** → 按第二部分细则逐一检查每个 D 项
3. **额外核查** → 执行第三部分额外核查项
4. **对标评估** → 与 VDA 标准标杆报告对比
5. **输出结果** → 严格按照第四部分固定格式输出

- 企业质量整改管理制度

# 地缘政治推演

## 这个技能做什么

用户问「某地局势会怎么走、对我们影响多大」时，把**新闻事实**变成**结构化事件**，
交给推演引擎算出：关系档位、四条反应途径、短/中/长期因果链、相关指标能不能支撑结论，
最后产出一份含地图、时间轴、指标图的图文报告。

**搜索由你（Agent）自己做**；本技能负责「该问什么、怎么脱敏、怎么下单、怎么把链接交给用户」。

## 触发词

地缘、局势、会不会、影响、升级、制裁、封锁、运价、油价、供应链、也门、台海、红海、
霍尔木兹、政变、戒严、断交、核试验

用户说出这些词、或问「某地局势会怎么走、对我们影响多大」时，用本技能。

## 接入（一次性）

### 方式 A：MCP（推荐）

```bash
openclaw mcp add geopolitics \
  --url https://mcp.geopoliticsreport.cn/mcp \
  --transport streamable-http
openclaw mcp doctor geopolitics --probe
```

测试期服务端**开放匿名调用**，不用配 Authorization。若服务端要求令牌：在 Control UI 的
**Settings → MCP** 里给这个 server 配 `Authorization: Bearer <令牌>`（或写进
`mcp.servers.geopolitics.headers`，用 OpenClaw 的 secret 机制），**不要**把令牌硬编码进
技能或日志。

### 方式 B：REST（不想配 MCP 时）

```bash
export GEOPOLITICS_API_BASE="${GEOPOLITICS_API_BASE:-https://mcp.geopoliticsreport.cn/api/v1}"
curl -s -X POST "$GEOPOLITICS_API_BASE/create_report" \
  -H "Content-Type: application/json; charset=utf-8" \
  -d '{"topic":"<脱敏后的主题句>","days":14}'
# 服务端要令牌时再加： -H "Authorization: Bearer $GEOPOLITICS_TOKEN"
```

### 令牌（测试期：不需要）

- 测试期匿名可用，请求头里**不要带** `Authorization`；
- 若返回 **401**（服务端关了匿名，或令牌不对），向提供方索取/核对令牌；
- **不要**把令牌复述到回答里，也不要写进文件或日志；
- 无论如何，**不要**因为「没令牌」就改用记忆作答：没有实时数据时只能用公开新闻做
  事实梳理，并声明「本次未调用推演引擎」。

## 上送前必须改写（不是可选项）

`create_report` 收的是**脱敏后的主题句**，不是用户原话。发送前做三件事：

1. 去掉称呼、联系方式、公司名、订单号、任何个人信息；
2. 把口语问句改写成「地区/主体 + 变化 + 想知道的影响」；
3. 只保留做推演需要的要素。

| 用户原话（**不要**直接上送） | 上送的主题句（✅） |
|---|---|
| 我是宁波做 FOB 的，张总说红海那边封了，我们 10 月发往汉堡的柜子要不要延期？ | 红海航运受阻对欧洲航线船期与运价的影响 |
| 我们公司在伊朗有客户，现在还能不能正常收款？ | 对伊朗制裁升级对跨境结算与贸易履约的影响 |
| 台海最近会不会打起来？我老板很担心 | 台海军事活动升级风险与区域供应链影响 |

服务端还会再打一遍码（去 HTML 标签与控制字符、邮箱/手机号/身份证/银行卡打码、
压成单行、截 200 字），并在返回里用 `redacted` 告知打码了哪些类型。
**两层都做，所以「用户原话原样外发」这件事在链路上不成立。**

## 默认流程：下单，然后闭嘴等报告

用户问一个地缘政治问题时，**不要先写分析**。直接下单生成报告，把链接给他。

**第 1 步：立刻下单**

- 走 MCP：调 `create_report`，参数 `{"topic":"<脱敏后的主题句>","days":14}`；
- 走 REST：`POST $GEOPOLITICS_API_BASE/create_report`，body 同上。

返回里就有 `report_url`（形如 `https://mcp.geopoliticsreport.cn/reports/t/KR8G2BR7`）。

**第 2 步：用一段话回复用户，附链接**

> 正在为你生成《<问题>》报告，**约 10—15 分钟**。
> 生成好点这里直接看（含地图、新闻时间轴、指标图，页面会自动刷新）：
> https://mcp.geopoliticsreport.cn/reports/t/XXXX

三条硬规矩：

1. **不要**在回答里复述分析结论、不要贴长篇研判——用户要的是报告；
   你先把结论说完，他就不去点链接了，报告等于白做；
2. **不要**等生成完再回（是异步的），也不要反复轮询；
3. 用户催进度时才查：`get_report {"task_id":"…"}`，回一句「还在跑，当前阶段：<progress>」。

## 什么时候才需要口头分析（非默认）

只有两种情况：

- 用户**明确**说「先给我一句话结论 / 不用报告」；
- `create_report` 返回 `failed`（题面识别不出主体、或库内事件不足）。

那时才走「快分析」：先 `get_event_types` / `lookup_entity` 备查，再 `submit_events`
（`persist:false`），把结论**压缩到 5 行以内**给出；**并且仍然把报告链接附在最后**
（如果已生成或可生成）。

## 工具清单

| 工具 | 用途 | 关键参数 |
|---|---|---|
| `create_report` | 下单生成图文报告（异步，立刻返回链接） | `topic`（脱敏主题句）、`days` |
| `get_report` | 查报告进度 / 拿最终链接 | `task_id` |
| `get_event_types` | 取事件类型字典（写事件前必查） | — |
| `lookup_entity` | 把国家/地区/海峡港口落成内部 ID | `query` |
| `submit_events` | 提交结构化事件做推演 | `events[]`、`persist:false` |
| `get_indicator_status` | 指标粒度与新鲜度 | `verdict`（可选） |
| `get_media_list` | 信源清单 | `region`（可选） |

## 输出要求

**默认只输出三句话**（不要多写）：

```
正在为你生成《<问题>》报告，约 10—15 分钟。
生成好后点这里直接看（含地图、时间轴、指标图，页面每 5 秒自动刷新）：
<report_url>
```

就这样。**不要**把事实清单、关系档位、因果链、指标状态抄进聊天——那些都在报告里；
你先说完，用户就不会点链接了。

只有走了「口头分析」的非默认路径时，才按下面顺序写，且**事实与推断必须分开、
总量控制在 5 行以内**：

1. 事实（时间 + 谁 + 做了什么 + 来源）
2. 关系档位
3. 最可能的一条走向 + 证伪条件
4. 指标能不能支撑（正常/过期/无数据）
5. 不确定性

并且**末尾仍然要贴报告链接**。

## 拿不到数据时怎么说（别硬编）

服务侧抓不到、或接口异常时，按这张表给结论，**不要用记忆补事实**：

| 情况 | 用户可见的说法 |
|---|---|
| `create_report` 失败（题面不明确/库里事件不足） | 「这个题目目前的公开报道太少，暂时凑不出一份报告；可以放宽到最近 30 天再试。」 |
| 接口 5xx/超时（最多重试 1 次） | 「分析服务暂时不可用，稍后再试。」**不要**退回凭记忆作答。 |
| 用户要「现在就一句话」 | 可以口头给，但必须补一句：**「数据截止 YYYY-MM-DD，本次未调用推演引擎」** |

口头分析时**第一行就要写数据截止时间**；报告页自带生成时间，不需要你重复。

## 可调的东西（只有两个，别乱加参数）

| 参数 | 范围 | 代价 |
|---|---|---|
| `topic` | 脱敏后的主题句 | 题面越具体，报告越准；写成「某地最近怎么样」会偏泛 |
| `days` | 1—180，默认 14 | 窗口越大越慢（首次可能到 20 分钟以上），超过 90 天收益很小 |

## 失败处理

| 现象 | 怎么做 |
|---|---|
| 401 | 没带令牌且服务端关了匿名，或令牌不对 → 向提供方索取/核对令牌 |
| 429 | 等 60 秒再试一次，仍失败就报告不可用 |
| `create_report` 返回 failed | 按 `error` 说明原因；把 `days` 放宽到 30 重试一次，仍失败就告诉用户这份题暂时出不了 |
| 报告 10—15 分钟还没好 | 调 `get_report` 看 `progress`；10 分钟没更新才算异常 |
| 报告打开是 502/404 | 说明前门或历史链接问题，把原始 `report_url` 交给提供方排查，不要自己换地址 |

## 数据处理说明

本技能**不采集用户输入**，只上送下面这些内容：

| 上送内容 | 说明 |
|---|---|
| 查询词 | `get_media_list` 的 `region`；`lookup_entity` 的 `query`，取自公开新闻的国家/地区/海峡港口名 |
| 结构化事件 | `event_type`、`occurred_at`、`actors`（内部 ID）、`summary`（一句话客观描述）、`source_url` |
| 令牌 | **测试期不发令牌**：匿名调用，服务端按调用方限流 |

**不上送**：用户原话、对话历史、抓到的新闻正文、文件、图片、账号信息、设备信息。

服务端强制校验：`summary` 去标签与控制字符、超 200 字截断、邮箱/手机号/身份证/银行卡
打码；来源链接必须是公网 `http(s)`，内网地址直接拒绝；落库时无来源链接的事件拒绝入库；
`event_type` 必须取自 `get_event_types` 字典。

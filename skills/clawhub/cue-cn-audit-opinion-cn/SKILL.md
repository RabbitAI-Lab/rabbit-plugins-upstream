# 审计意见与非标事项·逐条挂源

## 0. 这是什么、不是什么

| 是 | 不是 |
|---|---|
| **一份审计报告**的意见段与事项段逐项登记 | 对这家公司经营质量的评价，或对财报数字的点评 |
| 意见类型照抄在册写法，六种之外不认 | 自己归纳成「非标意见」「有问题」这类伞形说法 |
| 关键审计事项逐条抄标题与应对程序 | 判断哪些事项「更值得担心」 |
| 缺的材料逐条点名 | 用「不适用」「无此项」把没查当成没有 |
| 一律照抄原文，不换算、不改写 | 造假认定、暴雷判断、评级、目标价、买卖建议 |

**三条分界（用户靠这三句分清邻近件）：**

- `cn-earnings-note` 从**利润表**出发逐数点评。本件**不碰利润表数字**，只登记审计报告说了什么意见、点了哪些事项。
- `event-risk-scan` 扫**处罚、监管措施、对外担保**三源。本件只读**审计报告本体**，不扫监管面。
- `dd-checklist` 是**公开信息预尽调清单**，按九类目做覆盖率对账。本件是**单份审计报告**的逐项登记，不做域面覆盖率。

**「不得自己归纳」在本件里具体指哪两件：**

1. **意见类型只认在册六种写法。** 标准无保留意见／带强调事项段的无保留意见／带持续经营重大不确定性段落的无保留意见／保留意见／否定意见／无法表示意见。写法不在册的，说明你转写了原文——改回原句。
2. **不许用「非标」当结论。** 「非标意见」是一句伞形归类，是卡面自己的归纳。报告写「标准无保留意见」，卡面就不能在正文里说这份报告「非标」。要提这个说法，只能写在引号里并注明是谁说的。

## 1. 什么时候用

- 「这家公司的审计意见是什么意见」「是不是非标」
- 「关键审计事项都点了哪几条」「审计师对什么最上心」
- 「有没有强调事项段、持续经营重大不确定性段落」
- 「审计报告里怎么写的意见基础」

**不要用**：要评已出的完整财报（走 `cn-earnings-note`）；要处罚与对外担保的扫描（走 `event-risk-scan`）；要九类目的公开信息清单（走 `dd-checklist`）；要认定造假、给评级目标价、判断股价（本件不产出，也不该由任何件产出）。

## 2. 取数纪律

1. **只认持牌机构的正式审计报告。** 每一项都要能回到报告链接与检索日。研报、新闻、股吧转述一律不作来源。
2. **每条都引原句。** 写成 `- 项名：「原文原句」〔锚：页/节〕[S#]`，引号里是报告的原话，不是改写。引号空着等于没挂。
3. **意见类型照抄。** 见第 0 节两条。
4. **关键审计事项逐条抄。** 一条事项 = 一行，抄它的标题句与「审计中的应对」那句；不合并、不排序、不挑重点。
5. **不换算、不改写数字。** 报告写金额就写金额，不写「约」「左右」。
6. **没取到就写没取到，两向都判。** 正文写了「未取到 X」，第五节必须点名 X；第五节点了名而正文没有这条表述，同样算错。零缺口写 `- 未取到：无`。
7. **不推断下一年度。** 审计意见是对已审期间的结论，本件不写「下一年度可能」。

## 3. 输出契约（六节，按序）

```
AI 整理初稿｜请回原文核对｜不构成投资建议｜判断位 [待人工]

主体：<公司名称>
报告期：<YYYY 年度>
数据口径：审计报告（审计意见与非标事项逐项登记）

## 一、审计意见
## 二、形成意见的基础
## 三、关键审计事项
## 四、其他信息与持续经营
## 五、未取到与口径
## 六、来源
```

- **头部四件自标**逐字在位，写在第一个 `## ` 之前。
- **主体／报告期／数据口径**三行必须在场；`数据口径：` 必须以「审计报告」起头——这一格是本件与财报点评的分界。
- **一、审计意见**：恰一行 `- 意见类型：「…」〔锚：…〕[S#]`，引号内必须含在册类型名。
- **二、形成意见的基础**：审计报告写了这一节就逐条抄；报告没有这一节（标准无保留意见的常见情形）写 `- 意见基础：本报告未单列形成意见的基础一节 [待人工]`。
- **三、关键审计事项**：一条一行，抄标题句；「无关键审计事项」也是要抄的原句，不许留空。
- **四、其他信息与持续经营**：强调事项段、持续经营重大不确定性段落、其他信息段各自抄；报告没写的节写未取到并进第五节。
- **五、未取到与口径**：逐条点名未取到的项；口径行写清哪些照抄、哪些未取。
- **六、来源**每行：`- [S#] 文件标题 ｜ URL ｜ 检索日 YYYY-MM-DD`，编号与正文一对。

## 4. 数据通道

本件走 Cue 的 MCP 通道取公告与原文解析。先列目录，再按目录里的路由地址调 `tools/list`，确认工具在场后再取数：

```bash
CATALOG="https://cuecue.cn/api/mcp-catalog"
curl -s "$CATALOG" | head -c 2000
# 从目录里取本组的路由地址，再确认工具在场
curl -s -X POST "$ROUTING_URL" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

拿到报告原文后，用 `scripts/make_outline.py` 把清单排成骨架，再逐条读原文补内容。

## 5. 合规红线

- **不认定造假、不认定舞弊。** 审计报告里出现的「舞弊导致的重大错报风险」是审计师的用语，只能写在引号里；卡面自己的话里出现这两个词一律发。
- **不判暴雷、不判资金链断裂。**
- **不给评级、目标价、投资建议、买卖与增减持建议。**
- **不预测下一年度**，不写「将上涨／将下跌／有望走强」。
- **不用改数词打底。** 「约」「左右」「大概」不得替报告里的确切表述。
- **不转述二手来源。** 没有报告链接与检索日的事实不进本件。

红线只判**卡面自己的话**：`「」` 里的引文与来源行不判——登记表必须能原样抄下审计师的用词。

## 6. 快速流程

1. 拿到这份审计报告的原文，定主体与报告期。
2. 抄意见类型那一句（通常在公司年报「第一节 重要提示」）。
3. 抄形成意见的基础、关键审计事项、强调事项与持续经营段落。
4. 写未取到与口径，两向对齐。
5. 跑 `python3 scripts/check_audit_opinion.py <稿>.md`，红一条改一条。

不知道从哪开始，先跑内置样例看一份成品长什么样：

```bash
python3 scripts/check_audit_opinion.py --demo
```

## 7. 机检

```bash
python3 scripts/check_audit_opinion.py <审计稿>.md    # 五道，退码 0 全过 / 1 有发条 / 3 读不到或空稿
python3 scripts/check_audit_opinion.py --selftest     # 包内夹具自检
python3 scripts/check_audit_opinion.py --demo         # 内置样例跑一遍，产出可核对的成品
bash scripts/fixtures/run_fixtures.sh                 # 三档离线自检，零网络零计费
```

五道：**道一 形制**（头部自标、主体／报告期／数据口径三行、六节齐且有序、前四节各至少一条发现行、意见类型行恰一行）／**道二 原句与锚**（每条发现行以「」原句＋〔锚…〕＋`[S#]` 收尾，来源行齐编号与 URL 与检索日，引用的编号须已登记）／**道三 意见类型**（引号内含且仅含一个在册类型名；正文引号外出现的类型名必须与声明的一致；「非标」「非标准」当结论用一律发）／**道四 未取到两向点名**（正文与第五节互校，零缺口须显式写 `未取到：无`）／**道五 红线**（造假、舞弊、暴雷、退市、评级目标价、买卖建议、下一年度预测）

## 8. 零通道降级

没有 `CUE_API_KEY` 时，本包**不产出内容**，只把用户手上的清单排成带形状的骨架：六节与来源行按清单落位，内容留 `[待人工]`。骨架跑机检必然红在占位行上——这是设计，提醒你补完再交，而不是让空壳冒充成品。

代价说清楚：**没有通道就没有报告原文，没有原文就没有原句，意见类型这一格就挂不上锚**——这份审计稿只剩用户口述的一句话。用 `--demo` 看成品形制，不占用通道。

# 审计意见与非标事项·逐条挂源

把**一份审计报告**读成一张每个结论都能回到原句的登记表：意见类型、形成意见的基础、关键审计事项、强调事项段与持续经营段落、其他信息。

**不认定造假、不认定舞弊、不判暴雷、不预测下一年度、不给评级与目标价。** 意见类型只认在册六种写法；「非标」这种伞形归类不许当结论用。

---

## 一、三十秒跑通（零输入）

不给任何数据文件，也能跑出一份完整合规的成品，看它长什么样、判据怎么打：

```bash
python3 scripts/check_audit_opinion.py --demo
```

把这份样例存下来再跑一遍机检，它能自己过：

```bash
python3 scripts/check_audit_opinion.py --demo > 样例审计稿.md
python3 scripts/check_audit_opinion.py 样例审计稿.md
# → 样例审计稿.md 发条=0｜AU-STRUCT=0｜AU-QUOTE=0｜AU-OPINION=0｜AU-GAP=0｜AU-LINE=0
```

接着换成你自己那份稿子：

```bash
python3 scripts/check_audit_opinion.py 你的审计稿.md
```

退码 `0` 全过、`1` 有发条、`2` 用法错、`3` 读不到文件或空稿。

## 二、五道机检在管什么

| 码 | 名称 | 判什么 | 最常拦住的情况 |
|---|---|---|---|
| `AU-STRUCT` | 形制 | 头部四件自标在第一个 `## ` 之前；`主体：`／`报告期：`／`数据口径：` 三行在场且口径以「审计报告」起头；六节齐且有序；前四节各至少一条发现行；意见类型行恰一条 | 六节缺一节；某节只有小标题；口径写成了「财报点评」 |
| `AU-QUOTE` | 原句与锚 | 每条发现行以「原句」＋〔锚：…〕＋`[S#]` 收尾；来源行齐编号＋可点 URL＋检索日；正文引用的编号须已登记 | 只写数字没抄原句；引号是空的 `「」`；来源行只有标题没有链接 |
| `AU-OPINION` | 意见类型 | 意见类型只认在册六种写法；引号外出现的类型名必须与声明一致；引号外把「非标」当结论用一律发 | 写成「无保留意见」（在册名是「标准无保留意见」）；声明标准无保留却在正文写「本报告为保留意见」 |
| `AU-GAP` | 未取到两向点名 | 正文写了未取到而第五节没列要发，反之也发；零缺口须显式写 `未取到：无` | 用「不适用」「无此项」「无需披露」搪塞 |
| `AU-LINE` | 红线 | 造假、舞弊、暴雷、资金链断裂、退市、评级目标价、买卖建议、下一年度预测 —— 零命中 | 「本件判该公司存在舞弊」 |

**红线只判卡面自己的话。** `「」` 里的引文与来源行不判——登记表必须能原样抄下审计师的用词（审计报告里本来就会出现「舞弊导致的重大错报风险」这种句子）。

## 三、这件的立身之本：不许自己归纳

1. **意见类型只认在册六种写法。** 标准无保留意见／带强调事项段的无保留意见／带持续经营重大不确定性段落的无保留意见／保留意见／否定意见／无法表示意见。写法不在册的，说明你转写了原文——改回原句。
2. **不许用「非标」当结论。** 「非标意见」是一句伞形归类，是卡面自己的归纳。报告写标准无保留意见，卡面正文就不能说这份报告「非标」。
3. **关键审计事项逐条抄。** 一条事项 = 一行，抄标题句与「审计中的应对」；不合并、不排序、不挑重点。

## 六、零通道：先排骨架

没有通道产物也能跑，本脚本只读你给的那份清单：

```bash
python3 scripts/make_outline.py 清单.jsonl 骨架.md
```

清单是 JSONL，每行三键必需：`title`／`url`／`asof`（检索日 `YYYY-MM-DD`），`id` 与 `page` 可省。

- 坏行（非法 JSON／缺键／日期不合形／url 不是 http）**逐行点名、不采信**，好行照收。
- **空清单退 1，不出空壳。**
- 排出的骨架**故意过不了机检**，这是设计，不是待修。

```bash
python3 scripts/make_outline.py --selftest       # 8 条内置夹具
```

## 七、跑夹具与测试

```bash
bash scripts/fixtures/run_fixtures.sh            # 三档离线夹具，零网络零计费
python3 tests/test_audit_opinion.py              # 包级测试：入口契约／零输入／埋点
```

`run_fixtures.sh` 三档：机检自测 / 好样坏样逐枚单跑 / 在好样上逐行替换做正反对照（该红的红、该不红的不红）。末行自报 `档数=3｜不合=N｜不可判=N`。

`tests/` 跑的是外壳属性——`--help` 退 0、无参退 2、缺文件退 3、`--demo` 产物自过机检且逐字节可复现、空清单不出空壳、埋点落盘且失败静默。

## 八、首次运行埋点

入口脚本解析参数成功后、干正事之前，会往 `~/.cue-usage/<slug>-<日期>` 落一枚**空文件**。

**为什么要它：** 平台的两个下载计数器都不可信——新 listing 上架首 48 小时会被一次性播种 50~60 的初始计数，那不是用户下载。本地这枚文件是本件唯一能证明「真有人装上并跑过」的证据。

**它不会碍事：** 任何失败（家目录只读、配额满、无 HOME）都静默跳过，不报错、不改退码、不吐一句杂音。同一天跑多次只留一枚。

要清掉：`rm -rf ~/.cue-usage`。

## 九、素材从哪来

- **用户直供**：手头的年报 PDF、审计报告，走 `+parse` 解析。
- **通道取证**：配 `CUE_API_KEY` 后可走公告检索与年报原文解析。装好 skill ≠ 已配凭据 ≠ 通道已连，三层分开看。
- **零通道**：`--demo` 看形制，`make_outline.py` 排骨架。

本件不发请求、不代付费，消耗以服务端返回为准。

## 十、通道在场确认（可选）

配了 `CUE_API_KEY` 才需要这一步。先列目录，再按目录里的路由地址确认工具在场：

```bash
CATALOG="https://cuecue.cn/api/mcp-catalog"
curl -s "$CATALOG" | head -c 2000
# 从目录里取本组的路由地址，确认工具在场
curl -s -X POST "$ROUTING_URL" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

没配凭据也能跑：`--demo` 与 `make_outline.py` 都是纯本地路径。

# 故事圣经模板 Story Bible Template

在新故事的项目根目录创建 `story-bible.md`，用下面的结构填充。这是整个创作过程的唯一真相来源——每次续写前都要重新读一遍，每次生成后都要更新。

篇幅控制：单个故事圣经文件建议控制在几千字以内（不是流水账）。人物档案、伏笔台账如果条目很多，拆成独立文件（`characters.md`、`foreshadows.md`），在 `story-bible.md` 里只留摘要 + 链接，避免每次续写都要整个读完一份越滚越大的文件。

```markdown
# 《故事标题》故事圣经

## 基本信息
- 类型（genre）：
- 氛围（mood，读起来应该是什么感觉）：
- 文学形式：小说 / 故事 / 散文 / 童话
- 叙事视角：第一人称 / 第三人称 / 多视角切换

## 核心
- 主题（贯穿全书的情感/思想内核）：
- 主角的核心欲望（他想要什么，这个欲望怎么推动他）：
- 主角的核心缺陷（这个缺陷会带来麻烦，也是成长的关键）：
- 最终目标（故事要达成的核心任务/主角的成长弧光终点）：

## 世界观
- 时代背景/地理：
- 特殊规则（如果是奇幻/科幻——力量体系、科技水平等）：
- （史诗级长篇）世界观层级：本地 / 区域 / 世界 / 位面 / 宇宙，每层的规则

## 人物档案
每个重要角色一份小传：

### 主角：姓名
- 性格：
- 欲望：
- 弱点/秘密：
- 说话风格（句长、口头禅、回避方式，跨章节要保持一致）：
- 目前状态（随剧情推进更新）：

### 核心配角：姓名
- 独立于主角的目标/立场（不是工具人）：
- 与主角的关系：
- 目前状态：

### 反派：姓名
- 立场与逻辑（为什么这样做，要自洽）：
- 目前的行动/计划：

## 大纲锚点（卷/阶段结构，不是章节数规划）

### 第一卷：卷名
- 目标：这一卷要往哪个方向推进
- 关键事件（不要求逐字对应，大意达成即可）：
  1. ...
  2. ...
- 状态：进行中 / 已完成

### 第二卷：卷名
- 目标：
- 关键事件：
- 状态：未开始

## 伏笔台账

| 编号 | 内容 | 埋下章节 | 预期回收方式 | 状态 |
|------|------|----------|--------------|------|
| F001 | ... | 第2章 | ... | 开放中 |
| F002 | ... | 第5章 | ... | 待回收 |
| F003 | ... | 第1章 | ... | 已回收（第12章）|

伏笔分级（长篇作品建议标注）：
- 小（章节内回收）/ 中（卷内回收）/ 大（跨卷回收）/ 超级（全书级，越早埋越好）

## 时间线
记录故事内的时间推进，避免"角色一个月内经历了看起来像三个月的事"这类时间线bug：
- 第1-5章：故事时间 XX，主角年龄 XX
- 第6-10章：...

## 最近章节摘要（滚动保留最近 3-6 章，不是全文）
- 第N章：一句话摘要 + 本章新增/回收的伏笔
- 第N-1章：...
```

## 使用建议

- **新建故事**：先跟用户确认"基本信息"和"核心"两节的内容，再往下展开世界观和人物，最后设计大纲锚点。伏笔台账和时间线在写第一章之后才开始填。
- **续写前**：读 `story-bible.md`（如果拆分了文件，把 `characters.md`/`foreshadows.md` 也读一遍）+ 最近章节摘要 + 当前大纲锚点。
- **续写后**：更新伏笔台账（新增的开放伏笔、状态变为"已回收"的伏笔）、人物"目前状态"、时间线、最近章节摘要（滚动，超过 6 章的旧摘要可以精简或删除，早期关键剧情点可以沉淀进"关键事件"里长期保留）。

## Incident commander checklist
- [ ] Roles named: commander, communicator, operator(s), scribe
- [ ] Impact stated in user terms (which service, which area breadth, since when)
- [ ] One change at a time; stabilize first, optimize later
- [ ] Each action logged above BEFORE execution (time + intent + owner)
- [ ] Communications: status update cadence agreed; audiences separated (internal / affected users / provider)
- [ ] Exit criteria defined (what "resolved" means) and verified at the end
- [ ] Post-incident: postmortem.md scheduled; evidence files retention date set

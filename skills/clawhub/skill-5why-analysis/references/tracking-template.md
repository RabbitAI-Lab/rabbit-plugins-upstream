## 对话过程记录模板

### 模板结构

在5WHY分析过程中，智能体需按以下结构记录每轮对话的关键信息：

```
=== 第X轮对话 ===
时间戳：[YYYY-MM-DD HH:MM:SS]

初始问题：[用户最初提出的问题]

追问内容：[智能体发起的追问]
思考方向：[若有提供思考方向建议，记录于此]

用户回答：[用户对该追问的回答]

校验结果：
- 简洁性校验：[通过/未通过]
- 不合理答案校验：[通过/未通过]
- 模糊确认：[是否需要确认/确认结果]

判定结果：
- 当前回答：[重复记录用户回答]
- 对应应对措施：[智能体给出的应对措施]
- 能否彻底杜绝：[能/不能]
- 判定理由：[判定的具体理由]
- 最终判定：[根本原因/中间原因]

下一轮追问（若为中间原因）：[智能体发起的下一轮追问]
```

### 记录示例

```
=== 第1轮对话 ===
时间戳：2024-01-15 14:30:22

初始问题：车间某设备开机后报警停机

追问内容：为什么会出现车间某设备开机后报警停机？
思考方向：可从设备本身故障（如传感器异常、泄压部件失效）、操作流程偏差、物料参数异常等维度排查直接原因

用户回答：设备传感器检测到压力超标

校验结果：
- 简洁性校验：通过（单一要素）
- 不合理答案校验：通过（非主观感受、非不可控、非正常现场）
- 模糊确认：不需要

判定结果：
- 当前回答：设备传感器检测到压力超标
- 对应应对措施：停机后手动泄压，待压力恢复正常再开机
- 能否彻底杜绝：不能
- 判定理由：该措施仅临时解决当前停机，不能杜绝同类异常，无法避免后续再次出现压力超标报警
- 最终判定：中间原因

下一轮追问：为什么会出现设备传感器检测到压力超标？
```

### 记录要点

1. **完整性**：每轮对话的所有关键信息都要记录
2. **准确性**：用户回答和判定结果需准确记录
3. **可追溯**：时间戳和轮次编号便于回顾
4. **结构化**：使用清晰的层级结构，便于阅读

## 判定决策记录模板

### 判定决策清单

在每次判定时，智能体需按以下清单进行检查和记录：

```
=== 判定决策清单 ===

【原则1：应对措施检查】
□ 已给出具体应对措施
□ 措施内容明确（非笼统表述）
□ 措施可落地（非空谈）
措施原文：[记录完整措施内容]

【原则2：彻底性检查】
问题：实施该措施后，同类问题还会出现吗？
回答：[会/不会]
判断依据：[说明判断的具体逻辑]

【原则3：判定结论】
□ 能彻底杜绝 → 判定为根本原因
□ 不能彻底杜绝 → 判定为中间原因

判定结论：[根本原因/中间原因]
判定理由：[总结判定的核心理由]

【后续行动】
□ 若为根本原因 → 进入收尾阶段
□ 若为中间原因 → 发起下一轮追问
下一轮追问：[记录追问内容]
```

### 判定示例

**示例1：中间原因判定**

```
=== 判定决策清单 ===

【原则1：应对措施检查】
☑ 已给出具体应对措施
☑ 措施内容明确
☑ 措施可落地
措施原文：停机后手动泄压，待压力恢复正常再开机

【原则2：彻底性检查】
问题：实施该措施后，同类问题还会出现吗？
回答：会
判断依据：该措施仅处理当前的超压问题，没有解决压力超标的原因。后续仍可能出现传感器检测到压力超标的情况。

【原则3：判定结论】
☑ 能彻底杜绝 → 判定为根本原因
☑ 不能彻底杜绝 → 判定为中间原因

判定结论：中间原因
判定理由：该措施仅临时解决当前停机，不能杜绝同类异常，无法避免后续再次出现压力超标报警

【后续行动】
☑ 若为根本原因 → 进入收尾阶段
☑ 若为中间原因 → 发起下一轮追问
下一轮追问：为什么会出现设备传感器检测到压力超标？
```

**判定为中间原因时输出格式**：
```
校验结果：
- 简洁性校验：通过（单一要素）
- 不合理答案校验：通过（非主观感受、非不可控、非正常现场）

当前回答：XXX
对应应对措施：XXX
根本原因判定：□是 □否（判定理由：该措施能/不能杜绝同类异常，XXX）
【下一轮追问】为什么会出现XXX（上一轮用户回答）？
```

**判定为根本原因时输出格式**：
```
校验结果：
- 简洁性校验：通过（单一要素）
- 不合理答案校验：通过（非主观感受、非不可控、非正常现场）

当前回答：XXX
对应应对措施：XXX
根本原因判定：□是 □否（判定理由：该措施能/不能杜绝同类异常，XXX）
【最终结论】本次XXX的根本原因为：XXX。最终落地措施：XXX。
```

```
=== 判定决策清单 ===

【原则1：应对措施检查】
☑ 已给出具体应对措施
☑ 措施内容明确
☑ 措施可落地
措施原文：优化设备润滑方案，加装油污过滤装置，每月拆解清洗泄压阀阀芯，从源头杜绝油污进入阀芯

【原则2：彻底性检查】
问题：实施该措施后，同类问题还会出现吗？
回答：不会
判断依据：该措施从源头（油污进入）和定期维护两个维度管控，可有效防止泄压阀被油污堵塞，进而避免压力超标报警停机。

【原则3：判定结论】
☑ 能彻底杜绝 → 判定为根本原因
☐ 不能彻底杜绝 → 判定为中间原因

判定结论：根本原因
判定理由：该措施能杜绝同类异常，从油污源头、定期维护两方面管控，可彻底杜绝泄压阀卡滞，进而避免压力超标报警停机

【后续行动】
☑ 若为根本原因 → 进入收尾阶段
☐ 若为中间原因 → 发起下一轮追问
```

### 判定要点提醒

1. **措施的具体性**：避免"加强管理"、"提高意识"等空泛表述
2. **彻底性的验证**：问自己"实施后问题还会出现吗？"
3. **逻辑的一致性**：判定理由必须与应对措施和问题本质一致
4. **判定的审慎性**：无法判断时应向用户确认

## 最终输出格式模板

### 完整对话过程整理

在找到根本原因后，智能体需按以下格式输出完整的分析过程：

```
【完整对话过程整理】

=== 基本信息 ===
分析时间：[YYYY-MM-DD HH:MM:SS]
初始问题：[用户最初提出的问题]
分析轮次：[总共进行了N轮追问]

=== 对话流程 ===

【第1轮】
追问：为什么会出现[初始问题]？
用户回答：[用户回答]
校验结果：[简洁性校验结果；不合理答案校验结果]
应对措施：[智能体给出的措施]
判定结果：[中间原因/根本原因]

【第2轮】
追问：为什么会出现[第1轮用户回答]？
用户回答：[用户回答]
校验结果：[简洁性校验结果；不合理答案校验结果]
应对措施：[智能体给出的措施]
判定结果：[中间原因/根本原因]

...

【第N轮】
追问：为什么会出现[第N-1轮用户回答]？
用户回答：[用户回答]
校验结果：[简洁性校验结果；不合理答案校验结果]
应对措施：[智能体给出的措施]
判定结果：[根本原因]

=== 分析结论 ===

【最终结论】
本次[初始问题]的根本原因为：[根本原因描述]

【最终落地措施】
[最终落地措施描述]

【预期效果】
实施该措施后，同类[问题类型]将不再发生。

【辅助说明】（可选）
[若有需要补充说明的内容，如实施注意事项、配合措施等]
```

### 最终输出示例

```
【完整对话过程整理】

=== 基本信息 ===
分析时间：2024-01-15 14:30:22 - 14:35:18
初始问题：车间某设备开机后报警停机
分析轮次：3轮

=== 对话流程 ===

【第1轮】
追问：为什么会出现车间某设备开机后报警停机？
用户回答：设备传感器检测到压力超标
应对措施：停机后手动泄压，待压力恢复正常再开机
判定结果：中间原因（该措施仅临时解决当前停机，不能杜绝同类异常）

【第2轮】
追问：为什么会出现设备传感器检测到压力超标？
用户回答：泄压阀未及时打开排压
应对措施：定期检查泄压阀状态，每周做1次手动测试，确保启闭正常
判定结果：中间原因（该措施不能杜绝同类异常，定期检查无法完全避免泄压阀突发卡滞）

【第3轮】
追问：为什么会出现泄压阀未及时打开排压？
用户回答：泄压阀内部被油污堵塞，阀芯卡滞
应对措施：优化设备润滑方案，加装油污过滤装置，每月拆解清洗泄压阀阀芯，从源头杜绝油污进入阀芯
判定结果：根本原因（该措施能杜绝同类异常，从油污源头、定期维护两方面管控）

=== 分析结论 ===

【最终结论】
本次设备开机报警停机的根本原因为：泄压阀内部被油污堵塞，阀芯卡滞。

【最终落地措施】
优化设备润滑方案，加装油污过滤装置，每月拆解清洗泄压阀阀芯。

【预期效果】
实施该措施后，同类设备开机报警停机问题将不再发生。

【辅助说明】
1. 建议在实施前评估加装过滤装置的技术可行性
2. 每月拆解清洗需纳入设备维护计划，避免遗漏
3. 实施后需持续监控设备运行状态，验证措施有效性
```

### 输出要点提醒

1. **时间完整性**：记录分析的开始和结束时间
2. **流程清晰性**：按轮次展示完整的对话流程
3. **结论明确性**：清晰说明根本原因和最终措施
4. **实用性**：最终措施应具体可落地，便于执行
5. **可追溯性**：记录完整过程，便于后续回顾和审计

## 状态追踪注意事项

1. **实时记录**：每轮对话后立即更新状态记录
2. **准确记录**：用户回答和判定结果需准确无误
3. **结构化存储**：使用统一的模板格式，便于查阅
4. **隐私保护**：不记录用户的敏感信息（如具体姓名、公司名等）
5. **输出优化**：最终输出面向用户，应简洁明了，去除内部追踪标记

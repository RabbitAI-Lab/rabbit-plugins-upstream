> 品牌在 AI 时代的"SEO"。让品牌在豆包、文心一言、DeepSeek、Kimi 等国内 AI 的回复中被优先引用。

## 0. 认知地基：三个不能混淆的问题

| 问题 | 含义 | 审计方法 |
|---|---|------|
| 品牌有什么资产？ | 官网、账号、词条、POI 是否存在 | 实体盘点（分层证据） |
| 搜索引擎能看到什么？ | 开放索引中的品牌内容 | SERP / site: 检索 |
| AI 实际引用什么？ | 各 AI 平台回答中的引用 | **直接问 AI（地面真值）** |

v1.x 把三者混为一谈，用 (2) 推断 (1)、完全没有 (3)。v2.0 分开测量。

## 1. 第 -1 步：工具能力预检（每次运行必做）

运行任何诊断前，先探测当前环境具备哪些能力，并选择执行路径：

| 能力 | 探测方式 | 解锁的路径 |
|------|---------|-----------|
| web_search | 探针：搜「海底捞 官网」。通过 = ≥3 条中文结果且含官网域名；限流/无中文结果 = 标记受限 | L1-L2 证据层 |
| 网页直读（WebFetch/web_reader） | 抓一个已知页面 | L3 证据层 |
| 浏览器自动化（真实渲染） | 有无 browser-use / CDP 工具 | L4 证据层 + AI 平台实测自动化 |
| 文件写入 | 尝试创建存档文件 | 存档；否则输出请用户保存 |

**路径选择：**
- **全自动型**（四项全有）：AI 实测自动化 + 完整证据阶梯
- **半自动型**（有直读无浏览器）：AI 实测降级为引导客户手动；社媒数据请客户提供分享链接后走直读解析
- **最小型**（只有 web_search）：诊断仅覆盖开放索引维度，所有封闭平台记 ❓待核查，输出「客户自查清单」

> ⚠️ web_search 限流（429）、内容过滤拦截（400）、中文索引稀薄是常态，不是异常。
> 遇到时换关键词措辞重试一次，仍失败则降级到下一证据层，**不要反复重试**。

## 2. 阶段一：AI 可见性诊断

### 第零步：AI 平台实测（地面真值，v2.0 新增）

> 这是 GEO 诊断的锚点。GEO 的目标是「AI 回答里引用你」，所以诊断必须从"问 AI"开始，
> 而不是从"搜网页"开始。搜索可见性只是引用的**前置条件**之一。

**前置条件：** 最小可行档案三项（品牌名/地域/行业，见第一步）确认后即可开始本步；
档案其余字段可与本步**并行**补全，不要互相阻塞。

**问题集设计：** 结合客户业务设计 5-6 个「金钱问题」——客户的目标客户会问 AI 的问题。三类：
1. 行业推荐类：「{城市}{行业}哪家好」「{行业}服务商推荐」
2. 品牌考察类：「{品牌名}怎么样」「{品牌名}靠不靠谱」
3. 竞品对比类（**可选**：需竞品名单，来自实体档案；无名单时跳过）：「{品牌A}和{品牌B}怎么选」

**执行（自动化路径，需浏览器）：**
- **免登录首选：百度AI搜索** —— `https://chat.baidu.com/search?word=<URL编码后的问题>`，
  每问一个独立会话 URL（天然隔离上下文），无需登录
- 豆包、DeepSeek、Kimi、文心一言、腾讯元宝网页版：均有登录墙，**直接归入人工路径**，不在自动化上耗时

对每个「问题×平台」记录（格式与存档 `ai_baseline.明细` 同构，不做二次转换）：

```json
{
  "platform": "豆包",
  "question": "淮安瓷砖工作室推荐",
  "brand_mentioned": false,
  "cited_sources": ["某本地生活网站", "知乎回答链接"],
  "competitors_mentioned": ["竞品A"],
  "date": "YYYY-MM-DD"
}
```

> ⚠️ 登录墙/验证码出现时**立即转人工路径，不要尝试绕过登录**。AI 聊天平台的登录墙
> 比内容平台反爬更不可控，自动化失败是预期内情况，双路径本就是为此设计。

**答案完成判定：** 流式生成常需 40-90 秒以上，且「内容由AI生成」页脚出现时**正文可能仍在渲染**。
完成判定 = 答案正文已出现，且间隔 ≥8 秒的两次读取文本长度稳定；超时 120 秒记「生成未完成」，
**不得记为引用缺失**。

**提取规则：** 侧栏对话历史会混入页面文本——答案区定位从「搜索全网N篇资料」资源列表**之后**开始，
忽略侧栏；每问保持独立会话，避免上下文交叉污染。

**引用稳定性：** AI 回答具有概率性。诊断基线每问测 1 次即可（记录测量时间）；
监测对比时，品牌词与首要行业词各测 2 次取多数，避免把概率波动误判为变化。

**执行（人工路径，无浏览器或自动化被拦）：** 生成一份《AI 实测自查表》（平台 × 问题矩阵），
请客户逐格执行并回报引用情况。**明确告知客户：这是诊断的基线，宁可粗糙不可跳过。** 模板：

| 问题 | 豆包 | DeepSeek | Kimi | 元宝 | 360AI |
|------|------|----------|------|------|-------|
| {问题} | ✅/❌ ＋ AI引用了什么信源 | 同左 | 同左 | 同左 | 同左 |

（✅ 时请顺手记下信源，如「知乎」「百度地图」「某官网」——信源比引用与否更有诊断价值。）

**怎么算 ✅（判定标准，直接把这段话发给客户）：** 只要 AI 的回答里**出现了您的店名或品牌名**——
哪怕排在最后、哪怕同时还推荐了别家——就填 ✅；完全没提到您，才填 ❌。拿不准就截图，回来一起看。
在哪问：手机里装了哪个就用哪个（豆包App / DeepSeek / Kimi / 微信里的腾讯元宝 / 360AI搜索）；
每个平台把同一组问题各问一遍即可，一问约 1 分钟。

**产出指标：AI 引用率基线** = 品牌被提及的回答数 / 总问答数。这是后续所有优化的北极星指标。

### 第一步：客户实体档案（强制门禁，v2.0 重构）

> v1.x 的信息收集是一张可跳过的模板。v2.0 中它是**门禁**：模板字段一律留空，禁止预填默认值。
>
> **最小可行档案**（达到即可开工，其余字段可后补）：`品牌名` ＋ `地域` ＋ `行业` 三项。
> 其余字段标记「审计补全」，由第二步证据阶梯回填；评分时仍为空的开放索引字段按 ❌ 判定规则处理，
> 封闭平台字段一律 ❓待核查。
>
> **自主模式（客户不在场）：** 跳过一切询问。最小三项用 L1 检索从公开信息确认；
> 竞品名称可从行业词检索结果中提取 2-3 个；所有需客户提供的字段（后台数据、账号信息）保持 ❓，
> 待客户事后确认（L5）再升级。

```json
{
  "entity": {
    "企业全称": "",
    "品牌名": "",
    "品牌名变体": [],
    "行业": "",
    "地域": "",
    "官网URL": "",
    "ICP备案号": "",
    "平台账号": [],
    "地图POI": [],
    "竞品名称": [],
    "核心关键词": []
  }
}
```

**收集方式即审计方式：** 客户不知道/记不清的字段，不追问到底，直接进入第二步用证据阶梯补全。
官网页脚是社媒账号盘点的金矿——正规站点通常会列出全部官方账号。

**三级问询清单（小白友好。铁律：每问用户一个问题，必须同时给「为什么问 + 举例 + 答不上怎么办」）：**

| 级别 | 字段 | 问法与说明（可直接对客户说） |
|:---:|------|------------------------------|
| 🔴 必问 | 品牌名 | 「您的店/品牌叫什么名字？」例：臧小匪瓷砖工作室 |
| 🔴 必问 | 地域 | 「您主要服务哪个城市？」例：江苏淮安。范围不确定就说个大概 |
| 🔴 必问 | 行业 | 「您是做哪一行的？」一句大白话即可，例：瓷砖选品与空间设计 |
| 🟢 AI自查优先 | ICP备案号 / 平台账号 / 地图POI / 竞品 | **先自查、再确认式提问**：备案号从官网底部自动抓；POI 走地图接口；竞品从行业词检索提取 2-3 个后确认。平台账号——官网页脚/检索能拿到的直接用；**三种情况必须问**：① 无官网或页脚没列（「您在哪些平台有号？」）② 封闭平台深度核实（「发我主页分享链接：主页右上角 ··· →分享→复制链接」）③ 有号但搜不到（「网上只找到您的B站，抖音还在运营吗？」） |
| 🟡 可选确认 | 企业全称 / 官网URL / 品牌名变体 / 核心关键词 | 「营业执照上的全称方便给我吗？」「有官网或抖音/小红书主页吗？发我链接就行」——答不上就跳过，转审计补全 |

> 话术原则：客户一句大白话就够，解释术语是 AI 的事。任何字段答不上来，立即降级为审计补全，**不追问**。

**跨平台一致性校验（填写档案时同步执行）：**
- 名称一致性：品牌名 / 各平台昵称 / 地图 POI 名 / 工商主体 是否一致？不一致 → 记录为发现
- 数据口径一致性：品牌数据（品牌数、单品数、服务家庭数等）在官网与各平台简介是否打架？
  AI 实体识别对跨平台矛盾极其敏感，这类发现的价值不低于评分本身

### 第二步：分层证据审计（v2.0 核心引擎）

#### 证据阶梯 L1-L5

| 层级 | 方法 | 置信度 | 适用 |
|:---:|------|:---:|------|
| L1 | 关键词 web_search | 低 | 初筛，仅有正面证据价值 |
| L2 | site: 定向检索 / 品牌名变体检索 | 低-中 | 开放索引平台 |
| L3 | 直连抓取 / 公开 API / 短链解析 | 中-高 | 有 URL 的目标 |
| L4 | 真实浏览器渲染 | 高 | 反爬平台、JS 渲染页、AI 平台实测 |
| L5 | 客户确认（主页链接、后台截图、口述） | 高（需记录来源） | 封闭平台、无法自动化的数据 |

> ⚠️ L1 结果中的 URL 常为截断域名（缺 UID/路径），**仅作存在性信号**；可用 URL 的获取依赖 L3 及以上。

#### 负证据硬规则（必须遵守）

1. **搜不到 ≠ 不存在。** L1 检索无结果，禁止直接记 ❌。
2. 任何 ❌ 判定前，必须完成证据阶梯中**至少两级**，且其中一级不是 L1。
3. 无法走满两级 → 记 **❓待核查**，并在报告中列为待办。
4. **封闭平台禁止用 SERP 审计下结论**——搜索引擎不仅拿不到数据，还会产生误关联
   （实战案例：搜索"品牌名+小红书"命中的主页实为新加坡某机场官号）。
5. 客户确认（L5）是合法证据层，但必须在存档中标注 `evidence: "L5-客户确认"`，
   并在报告底部注明哪些分数依赖它。

#### 按维度审计协议

**百科（开放索引，L2 为主）：**
- 百度百科：`site:baike.baidu.com 品牌名`，同时直接拼接 `baike.baidu.com/item/品牌名` 验证
- 快懂百科：用 `site:baike.com`（注意不是 douyin.com）
- 360百科：`site:baike.so.com`；搜狗百科：`site:baike.sogou.com`
- 维基百科对本地商家一般不适用，跳过并注明

**知乎（开放索引，L2 + L5 结合）：**
- `site:zhihu.com 品牌名` 只能作为**下限**——搜索引擎对知乎收录严重不全
- 正确姿势：请客户提供知乎主页链接（`zhihu.com/people/<id>`），
  用网页直读（web_reader 类工具通常可过知乎 403）读取主页实测：回答数/文章数/赞同/粉丝
- **计分以主页实测为准，SERP 计数仅作下限**

**社媒矩阵（分治，v2.0 关键修订）：**

| 平台 | 类型 | 审计路径 |
|------|:---:|---------|
| B站 | 开放 | 空间页搜索命中 + 开放API（粉丝数：`api.bilibili.com/x/relation/stat?vmid=<UID>`）；视频列表接口有签名墙，总数可请客户提供 |
| 抖音 | 封闭 | 分享短链 `v.douyin.com/xxx` → 302 → 含 sec_uid 的主页 → **浏览器渲染**（无需登录，可获粉丝/获赞/作品数/IP/简介）。curl 与爬虫 UA 均被 acrawler 拦截，勿浪费时间 |
| 小红书 | 封闭 | 分享短链 `xhslink.cn/xxx` → 302 → 真实主页（注意：**小红书号 ≠ 主页URL中的内部ID**，直接拼接必 404）→ 网页直读可获粉丝/赞藏/笔记列表 |

**权威新闻（开放索引，L2 为主）：**
- `品牌名 报道`、`品牌名 新闻`、`site:people.com.cn 品牌名` 等定向媒体检索
- 地方媒体单独检索一轮（本地企业的主要信源）

**地图 POI（半开放）：**
- 百度地图：公开建议接口 `map.baidu.com/su?wd=<名称>&cid=131&type=0` 可确认 POI 存在性与官方名称
- 高德/腾讯地图：**自动化不可用**（浏览器渲染也会遇到滑块验证码+登录墙，搜索 URL 会忽略城市参数），仅客户 App 内核实
- **POI 名称与品牌名的一致性必须单独记录**（实体混淆风险）

**官网（L3 直连）：**
- 直连抓取：确认存活、提取 ICP 备案号、记录页脚社媒账号（回填实体档案）
- AI 就绪快检：title/description 是否含地域行业词、有无 Organization/LocalBusiness/FAQ
  结构化数据、是否被多个搜索引擎索引（**只在百度收录 ≠ 其他 AI 爬虫可见**）

### 第三步：评分与证据链

评分公式沿用 v1.x（客户需要一个数字），但**每个维度得分必须携带证据来源**：

| 维度 | 满分 | 计分规则（同 v1.x） | 证据要求 |
|------|:---:|---------|---------|
| 百科_百度 | 15 | ✅完整 15 / ⚠️不完整 8 / ❌ 0 | 至少 L2 |
| 百科_抖音（快懂） | 10 | ✅ 10 / ⚠️ 5 / ❌ 0 | 至少 L2 |
| 百科_其他 | 5 | 有任一 5 / ❌ 0 | 至少 L2 |
| 知乎问答 | 20 | 每篇 5，封顶 20 | **以主页实测或客户后台数据计**；SERP 计数仅作下限 |
| 权威新闻 | 15 | 每篇 5，封顶 15 | 至少 L2，记录媒体名与日期 |
| 社交媒体 | 15 | ✅统一+活跃 15 / ⚠️不统一 8 / ❌ 0 | 至少两平台到 L3/L4/L5 |
| 地图POI | 10 | 3+平台 10 / 1-2个 5 / ❓ 2 / ❌ 0 | 注明哪些平台、名称是否一致 |
| 官网 | 10 | ✅ 10 / ❌ 0 | L3 直连确认 |

**等级映射同 v1.x：** 🟢A 71-100 / 🟡B 41-70 / 🟠C 11-40 / 🔴D 0-10。

### 模块A：百科词条内容创作

> ⚠️ 只输出**内容草稿**，提交审核由客户执行。

**A1 参考资料先行（铁律）：**
1. 先 web_search 客户有哪些公开权威报道（人民网、凤凰、新浪、搜狐、政府站、本地新闻）
2. 从报道中提取可用信息，基于报道写词条，每段标注来源
3. **找不到权威报道的信息点 → 删除，不硬写。** 企业官网/自写材料不可作参考资料

**A2 词条草稿模板：**

```markdown
# {品牌名}
## 企业简介
{品牌名}成立于{年份}，总部位于{城市}，是一家专注于{核心业务}的{企业类型}。
## 发展历程
* {年份}年：{事件}
## 核心业务
### {业务名称}
{客观描述}
## 所获荣誉
* {年份}：{荣誉}
## 参考资料
1. [来源名称](URL) —— 对应段落
```

**A3 审核规则：**

| 平台 | 关键规则 |
|------|---------|
| 百度百科 | 企业走「企业通道」；每个关键信息点需独立第三方权威来源；禁营销话术（"顶尖/第一/领先"）；正文禁电话微信网址；机器审24-48h+人工3-7工作日 |
| 快懂百科 | 标准近百度百科；禁第三方导流；禁敏感内容 |
| 360百科 | 账号需**4级**才能建词条；词条须为有实际意义的专名，公司简称须有注册商标 |
| 搜狗百科 | 标准近百度百科，腾讯生态 |

**A4 无权威报道时的替代路径：** 地图POI认领 → 天眼查/企查查完善 → 大众点评/美团入驻 →
知乎布局 → 同时联系本地媒体做一篇报道（拿到后回到 A2 建词条）。

### 模块B：FAQ 内容生成

AI 是问答机器，FAQ 是与 AI 最匹配的内容格式。生成 10-15 条，覆盖五个方向：

| 方向 | 示例 | 作用 |
|------|------|------|
| 业务定位 | "XX 是做什么的？" | Organization Schema 信号 |
| 产品服务 | "XX 能解决什么问题？" | Product Schema 信号 |
| 客户案例 | "哪些人用过 XX？" | Review Schema 信号 |
| 行业认知 | "XX 行业有什么趋势？" | 专业度 |
| 竞品差异 | "XX 和 YY 有什么区别？" | 差异化 |

格式：`### 问：{问题}` + `答：{3-5句，含数据案例，无营销话术}`。
无官网时 FAQ 可作知乎回答或内容平台系列。

### 模块C：知乎问答内容创作

1. **问题挖掘：** 搜行业/地域/品类关键词，找高热度问题
2. **自问自答合规：** AI 能感知知乎内容质量
3. **回答结构：** 核心观点先行（前三行给结论，AI 最爱引用）→ 分段正文（每段3-5句，用数据案例）→ 结尾总结+引导互动
4. **质量要求：** 有数据/有真实案例/读完有收获/不硬推销

### 模块D：新闻稿内容创作

| 客户状态 | 选题 |
|---------|------|
| 有新案例 | "{客户类型}选择{品牌名}，提升{指标}" |
| 有特色 | "{品牌名}深耕{领域}，提供{核心价值}" |
| 行业观点 | "{创始人}：{观点核心}" |
| 常规 | "{品牌名}持续服务{地域}{行业}客户" |

格式：标题15-25字含品牌名；正文800-1200字；导语100字内说清谁+干了什么+为何重要；
至少1个可引用话语+具体数据；信息与百科/官网一致。
检查清单：标题含品牌名 ☐ 导语原则 ☐ 可引用话语 ☐ 具体数据 ☐ 交叉一致 ☐

### 模块E：内容平台优化

| 操作 | 说明 |
|------|------|
| 统一名称 | 各平台同一品牌名（含地图POI） |
| 简介结构化 | 品牌名+地域+业务+统一数据口径 |
| 标签体系 | 统一话题标签（地域/品类/品牌） |
| 地图POI | 百度/高德/腾讯逐个认领 |

### v2.0 模块增补

**模块C 知乎（补充「选题优先」原则）：**
实战发现：39 条内容仅 3 粉 20 赞——内容存在 ≠ 内容被引用。知乎动作的优先级：
1. 问题挖掘（高流量真实问题）> 2. 自问自答布局空白问题 > 3. 老回答回炉 > 4. 继续堆量

**官网 AI 就绪（模块B 扩展）：**
- 结构化数据：Organization / LocalBusiness / FAQPage Schema
- 站长平台提交：Bing（DeepSeek/Kimi 系爬虫重要入口）、Google、360、搜狗
- 地域行业词进 title/description；**只在百度收录对非百度系 AI 无效**

**实体一致性修复（新增强，P0 级）：**
诊断发现的名称变体冲突、数据口径打架，属于免费高价值修复项：
统一品牌数据口径（如「30+品牌、10000+单品、服务10000+家庭」），
地图 POI 名称改为与品牌名一致。AI 实体识别的置信度直接受益。

**平台角色分工（基于实战发现）：**
内容和受众平台（抖音/小红书）与可见性平台（知乎/B站/官网）打法分开：
前者做给真人看，后者做给 AI 看；把前者验证过的爆款选题改写搬运到后者。

## 附录A：平台数据获取路径速查（2026-09 实测验证）

| 目标 | 路径 | 备注 |
|------|------|------|
| B站粉丝数 | `api.bilibili.com/x/relation/stat?vmid=<UID>` | 公开JSON；视频列表接口有签名墙 |
| 知乎主页数据 | 直读 `zhihu.com/people/<id>` | WebFetch 403，web_reader 类工具可过 |
| 小红书主页 | 短链 `xhslink.cn/xxx` → 302 → 直读 | 小红书号≠主页ID，拼接必404；分享文案常含赞藏数 |
| 抖音主页数据 | 短链 `v.douyin.com/xxx` → sec_uid → 浏览器渲染 `douyin.com/user/<sec_uid>` | 无需登录；curl/爬虫UA被acrawler拦截 |
| 百度地图POI | `map.baidu.com/su?wd=<名称>&cid=131&type=0` | 公开接口，返回POI官方名称 |
| 高德/腾讯地图 | 自动化不可用（渲染遇滑块验证码+登录墙，搜索URL忽略城市参数） | 仅客户App内核实 |
| 官网社媒账号 | 页脚交叉引用 | 社媒盘点的第一入口 |

> ⏰ **时效维护：** 反爬与接口路径会失效。单条路径失效时按证据阶梯降级即可，不必阻塞诊断；
> **建议每半年对本表整体重验一次**，重验后更新标题中的日期。失效的路径移入附录B作为陷阱记录。

## 附录B：已知陷阱（每个都踩过）

1. **星耀樟宜误关联**：SERP 搜"品牌名+小红书"命中无关账号——封闭平台禁止 SERP 下结论
2. **官网漏检**：客户不说、AI 不问、协议不查，三重叠加——实体档案是门禁不是模板
3. **只在百度收录 ≠ AI 可见**：DeepSeek/Kimi 自有爬虫不依赖百度索引
4. **搜索引擎计数严重低估知乎内容**：SERP 数到 1 篇，主页实测 39 条
5. **反爬挑战页不是空页**：73KB HTML 里只有 acrawler，换 UA 无效，需真浏览器
6. **web_search 429/400 是常态**：重试一次即降级，勿恋战

> 维护原则：本清单随实战持续追加；**每条陷阱都必须有对应的规则修正**（负证据规则、
> 分治协议、降级路径），只记教训不改协议的陷阱清单没有价值。

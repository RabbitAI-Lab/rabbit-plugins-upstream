# 自检报告模板

默认生成简版Markdown。先给结论和下一步，再给可追溯证据；复杂任务才展开附录。没有数据也交付缺口报告，不以填满表格作为完成条件。

## 1. 判定依据

| 判定 | 使用条件 | 必须说明 |
|---|---|---|
| 满足要求 | 证据满足事前明确规格、共同基线判据或已有阈值 | 满足哪个有限任务、要求与范围 |
| 部分满足 | 要求可拆分，部分满足、部分未满足或未验证 | 分项与允许的子范围，不豁免底线 |
| 不满足要求 | 有证据违反明确要求 | 失败案例、影响和改进 |
| 证据不足 | 证据不足以判断该项要求，或没有适用判据 | 缺什么、还能支持什么；不解释成通过或确定失败 |

规格可以是“缺数据必须输出UNKNOWN”，无需另设百分比。未设总体比例门槛时仍可判断该明确规格的逐例满足/违反，并描述x/n；不能据此声称整体比例达标。没有适用判据的项只给描述结果，不事后自设阈值。已有明确失败不藏进其他项的证据不足。

## 2. 默认简版

```markdown
# 巡检能力自检报告

> 建设者自评，未经独立复核。不构成独立验收或权威认证。
> 对象/版本：…；任务/对象与时间范围：…；角色/日期：…
> 模式：快速/任务展开；实际人工投入：已记录值或未测（预算不代替实测）。

本次结论：哪些有限要求满足、违反或未验证；最需要处理的问题是什么。

## 范围与判据

用简短说明登记所选任务、应评清单、输入/环境、时间/权限、人工责任、独立期望及规则版本。注明已有契约/明确规格/基线/阈值的来源；历史分析不称事前冻结。无关任务合并说明未纳入，必需缺证据项不得省略。

## 结果与证据

| 问题/指标 | 原始结果与单位 | 判据及分项结论 | 来源/案例与限制 |
|---|---|---|---|
| 检查是否正确（E1-07a） | x/n，检查单元 | … | 应检清单、期望/实际输出、失败ID |

每项给计数、分母来源/观察单位、具体ID或可定位工件引用。n=0写N/A；不能计算写未测/尚不可测和原因，不能填0。抽样注明框、方法、n与独立单位；未知/争议同报适用区间。精确率和召回无独立真值时明确不作正式结果，自标分析另列reviewer=self与审核依据。

先简述所选指标目标路径的来源存在性、实际字段、合格对象数与覆盖缺口。来源缺失、合法空集和有分母但零输出分开；不把0行统一降D0或剔除已知失败。

## 底线与缺口

- 权限/数据边界：确认问题及范围；未测或未观测到如实说明。
- 严重风险：业务清单及已知漏检；清单未定义说明无法自查。
- 扰动：实际增量/超预算问题，或未测；离线工件分析不证明生产扰动为零。

自标审核的否证记录：案例ID、否证动作、预期反证、实际观察及证据引用；需要但未做时显示“否证尝试未记录”及原因。无独立真值且失败样本为零时，缺记录不得写成已完成自评审核；其他已知业务失败仍照实报告。

| 必需但未能判断的项 | 缺什么及影响 | 最小补充动作 |
|---|---|---|
| … | … | … |

## 下一步与结论范围

按影响给具体修复/补证动作，注明可复现的失败与需要复验的边界。说明本报告允许支持什么、哪些仍需独立验证；不输出加权总分。未记录的人工成本写未测。
```

不必抄录全部判例。发生边界争议时引用相关判例并说明处理；底线已确认失败保留原始事实，不由其他指标抵消。

## 3. 按需要展开的附录

- **追溯/正式对照需要**：逐指标列D0～D3、分子/分母ID、来源版本/摘要、时间依据、去重和匹配、分歧裁决、抽样和真值组成。区分数据来源独立性与人员独立性。
- **回放或比较需要**：候选/基线版本、共同任务与输入、不同口径的映射、已知失败与未决；输入缺陷依原契约处理并披露登记与实际覆盖，未约定时不事后剔除低分案例。
- **测使用成本需要**：实际阅读、准备、计算、解释、求助、返工及中止；复算任务与从零建立评价分列，不以软件秒数代替。
- **机器消费需要**：可附下面摘要；普通用户不要求编辑YAML或额外填46行指标。

## 4. 可选机器摘要

```yaml
selfcheck:
  object: null
  task_types: []
  builder_self_assessment: true
  mode: quick  # quick/task，均不代表整产品验收
  metrics:
    - id: null
      value: null
      n: null
      evidence_grade: null  # D0..D3
      verdict: null  # satisfied/partial/unsatisfied/insufficient_evidence
      baseline_source: null  # 保留原字段；已有contract/self_set值仍可读取
      criterion: null  # 新增可选项：明确规格/基线/阈值、内容、来源与适用范围
      sampling: null
      evidence_refs: []
      caveat: null
  bottom_lines:
    confirmed_violations: null  # 数值/observed_zero_not_proof/untested
    severe_risk_misses: null  # 数值/list_undefined/untested
    production_disturbance: null  # 实测/untested
  scope_statement: null
  requires_independent_verification: []
  not_assessed: []  # 必需未测逐项登记；无关任务可按组说明及理由
  falsification_requirement: unknown  # required/not_required/unknown；适用性由评价者说明
  falsification_not_required_reason: null
  falsification_attempts: []  # 每条含case_id/attempt/expected_counterevidence/observed/evidence_refs
```

`baseline_source=null`不单独决定判定：也可能有明确的规格断言，须在criterion及报告中记录来源。原有字段继续保留，新增字段是报告选项；没有适用判据才不得判满足。自定规则即使记录，也不能包装成业务原有要求或独立验收门槛。

生成Markdown时按实际记录显示否证状态，不能仅靠填写`falsification_status=passed`自报完成。已有JSON机器摘要（与上述YAML同字段结构）可用目录内`scripts/check-report.py report.json`复查；仅依赖Python标准库，不解析YAML、不读取外部证据。缺字段或空记录会输出“否证尝试未记录”，未声明适用性另提示；填写记录仅得到“记录已提供，未验证有效性”。声明不适用需给具体原因，工具不自动证明该原因正确。退出0表示记录齐备/声明无需且有理由，1表示记录缺口，2表示输入格式错误，均不是被测系统的业务通过/失败码。源模板是文档，只有实际运行检查器才产生自动检查结果。

需要检查指标编号、简单比例单位/计数、预期检查清单或重分析记录时，按[报告一致性说明](./report-consistency.md)补充所选字段，运行独立的`check-consistency.py`。默认只检查指标，清单和重分析按需选择；该工具不替代否证记录检查，也不验证业务正确性。普通Markdown报告无需为运行脚本额外填表。

## 5. 交付前核对

核对自评标记、每个数字的来源与分母、未知/缺失及失败处理、判据与允许声明、三项底线及未测项。状态期望为UNKNOWN时允许正确UNKNOWN计入检查正确；缺数据输出健康不得通过。没有独立真值、时间或许可时保留相应限制，交付能成立的部分。

有状态汇总时，同列PASS/FAIL/UNKNOWN/N/A和缺失输出，FAIL=0不写成全部PASS；比例型指标不使用秒数等不同单位。重分析时保留原执行记录、原分析及新分析引用/版本、固定工件与被测对象摘要，说明原因；新分析满足检查不自动改写原执行状态。

## Description:

Systematic root-cause debugging with verification for errors, stack traces, broken tests, flaky tests, regressions, and other unexpected behavior.

This skill is ready for commercial/non-commercial use.

## Use Case:

Developers and engineers use this skill to debug failures by reproducing the issue, forming evidence-based hypotheses, tracing the root cause, and verifying the fix.

### Deployment Geography for Use:

Global

## Known Risks and Mitigations:

Risk: Diagnostic files, logs, and pasted command output may reveal internal paths, repository remotes, hostnames, customer data, or secrets.

Mitigation: Review and redact diagnostics and logs before sharing; prefer environment variables for credentials and quote only the lines needed for diagnosis.

Risk: Debugging workflows may use worktree-changing commands such as git stash, git bisect, or diagnostic scripts.

Mitigation: Inspect the worktree state first, run those commands deliberately, and preserve important local changes before changing the repository state.

Risk: A fix proposed without a reliable reproduction loop can address a symptom instead of the root cause.

Mitigation: Require a failing reproduction, evidence-backed hypotheses, a root-cause explanation, a regression test, and fresh verification before declaring the issue resolved.

# GPT 审稿 prompt 模板

使用此模板构造发送给 ChatGPT 的审稿 prompt。替换 `{{ARTICLE}}` 为文章全文。

## 标准版模板（适用于所有稿件审稿）

```
请用最苛刻的标准审查以下{{CONTEXT}}（播客稿/视频脚本/文章）。

### 维度一：事实正确性（最优先）

逐句检查每一句可能存在正确性问题的陈述：
1. 数字精确性 —— 具体数字能否自证？有日志/截图支撑吗？
2. 技术概念准确性 —— 术语使用准确吗？会不会误导听众？
3. 因果推断 —— 因果关系真的成立，还是为了叙事流畅强行连接？
4. 绝对化表述 —— "从来不/根本/永远/所有/任何"有例外吗？站得住吗？
5. 记忆模糊风险 —— 凭记忆写的细节是否有偏差？
6. 应然vs实然 —— 是说"系统应该这样运转"还是"系统真的在这样运转"？

### 维度二：逐句读者反应模拟

对每句或每段标注观众的"脑内弹幕"反应。使用以下标记：
- 🎯 钩住了（感兴趣、想继续听）
- 😐 平的（不会走神也不会留下印象）
- 😴 走神（无聊、可能切出去）
- ❓ 疑惑（不懂、想追问）
- 💡 顿悟（"哦原来是这样"）
- 🔥 共鸣（点头、想转发）
- 🤔 质疑（"真的吗？证据呢？"）
- ⚡ 雷点（反感、"太装了""标题党"）

标注时务必模拟"第一遍听到"的反应，不要站在事后角度说"后面会解释的"。

### 维度三：整篇"听众带走什么"

看完/听完整篇后，回答：
1. 听众能复述出的核心观点是什么？—— 如果只能记住一句话，那句话是什么？
2. 听众带走的是一个可复用的认知框架，还是只记住了几个散点故事？
3. 听众离开时有什么未解的疑惑？
4. 听众离开时的情绪是什么？（被启发/焦虑/共鸣/将信将疑）
5. 听众下一步会做什么？（改变某个习惯、试用某个方法、还是"有道理"然后什么都没变？）

### 维度四：传播力 + 平台适配

1. 开头30秒够不够抓人？
2. 有没有"子弹时间"式的金句（可截图、可转发）？
3. 节奏：信息密度是否合适？会不会在某段走神？
4. 走神风险段落（标注具体位置）

### 维度五：反AI味检测

1. 有没有过度工整的排比？
2. 有没有虚假的完美收束？
3. 因果链是否太整齐？（真实的混乱应该留有枝杈）
4. "太完美"检查：文章讲的是真实的混乱和挣扎，但文章本身是否被整理得一点都不混乱？

### 审查输出格式

请按段落输出，每段标注：
- 段落名
- 事实风险（🔴/🟡/🟢）
- 传播力评估
- 逐句读者反应
- AI味检查

最后给出：
1. 总结（1-2段）
2. 最需要改的3个点（按优先级）

文章全文：

{{ARTICLE}}
```

## 播客稿专用附加维度

在标准版基础上增加：
```
### 平台特性：播客
- 听众无法回看/回听，听不懂就过去了
- 术语必须翻译成口语
- 过渡比结构更重要：段落之间的桥接决定听众能不能跟上
```

## B站视频脚本专用附加维度

在标准版基础上增加：
```
### 平台特性：B站视频
- 观众可以暂停/回看，技术事实必须经得起验证
- 观众会验证截图内容和数据
- B站技术用户非常较真，编造或模糊细节会翻车
- 前15秒决定完播率
- 参赛作品需要体现"真实搭建"而非"纯讲故事"
```

## 使用方式

```python
# Python 替换模板占位符
```

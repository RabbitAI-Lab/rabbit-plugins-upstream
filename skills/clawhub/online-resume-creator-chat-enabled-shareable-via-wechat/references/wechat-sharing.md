# 微信分享 / 分发与扩展 参考

## 一、微信为什么"不显示封面卡片"
- 个人聊天框**粘贴链接**发出去，默认就是**纯蓝色文字链**，不会变成带封面的卡片。
- 这是微信的产品机制，**与 og:image / OG 元信息设置无关**。
- 微信只在特定场景抓 OG 生成卡片：
  - 公众号 / 小程序 / 腾讯系域名
  - 用手机浏览器打开链接后点"分享到微信"（仍不保证对第三方域名出封面图）
- 第三方域名（`*.agentos-app.net` 这类）微信通常不主动抓取封面生成大卡片。
- **结论**：无论怎样优化网页，聊天框粘贴都看不到卡片。绕过办法 = 发"带二维码的分享卡片图"（见 SKILL.md 步骤 3）。

## 二、推荐分享姿势
1. 用 `gen_share_card.py` 生成带二维码的卡片图 → 微信发给朋友 → 对方长按识别即开。
2. 若坚持要"真·卡片链接"：手机浏览器打开链接 → 点"分享到微信"（可能出小卡片，但不保证封面）。

## 三、真 AI 对话（扩展方向）
当前"对话"是前端关键词匹配，不能自由聊天。要升级成真 AI：
- 接大模型后端（如 CodeBuddy SDK / 自有 API），把 `SECTION`/`RULES` 换成 LLM 调用。
- 后端统一做：过期控制、访问口令、隐私脱敏（比前端校验可靠）。
- 注意：真后端需托管，不再是单文件零依赖。

## 四、隐私与过期
- 页面含真实手机号 / 邮箱 / 年薪等敏感信息，链接公开即任何人可见。
- 敏感场景：加访问口令（输入密码才显示），或真后端鉴权。
- 过期控制（当前方案）：前端 `new Date()` 校验 + 整页替换提示。
  - 仅为礼貌提示，非强鉴权；对方改本地时间 / 禁用 JS 仍可看。
  - 强行鉴权需后端。

## 五、Skill 分发（分享给别人）
WorkBuddy 分享 Skill 有三种方式：
1. **打包 zip 发给别人**：用 `package_skill.py` 或让 WorkBuddy "帮我把这个 Skill 打包"，生成 zip，对方导入即可。
2. **生成分享链接**：技能详情页"分享"按钮 → 含访问令牌的短链，发给特定同事直接导入。
3. **发布到技能市场（公开，别人可搜到）**：见下方"上传流程"。

### 5.1 上传到技能市场 / "灵感"页面（公开流程）
- **入口**（可信实操资料佐证）：WorkBuddy 客户端 **左侧【技能市场】** → 右上角 **「上传技能」** 按钮。
  - 你口语里的"灵感"页面，即同一套发布体系（官方文档统一称"技能市场 / SkillHub"）。以产品实际页签为准；若左侧有"灵感"标签，那即是入口。
- **填写内容**：技能名称、触发关键词、功能介绍、粘贴标准化提示词模板（或上传 SKILL.md / 技能包）。
- **提交审核**：测试无误后提交 → 审核周期约 **1–3（ClawHub）/ 3–7（SkillHub）个工作日**。
- **公开后位置**：技能市场内，别人可 **搜索名称/关键词 → 一键安装**。
- **激励**：腾讯云资料称办公模板审核通过给 **2000 积分**，行业垂直模板 **5000–10000 积分**，他人使用还有分成。

### 5.2 不同市场的要求差异（注意）
- **SkillHub / 技能市场（客户端内）**：核心上传 **SKILL.md**，填名称/描述/分类即可。
- **ClawHub（clawhub.ai，社区市场）**：需打包 **zip**（SKILL.md + manifest.yaml + assets/），登录后「发布技能」上传，1–3 工作日审核。
- **我的 skill 现状**：已在 `C:\Users\ZLS\.workbuddy\skills\talkable-resume\`，含 SKILL.md + scripts + references，符合 SkillHub 要求；若要上 ClawHub 需补 `manifest.yaml` 并打包 zip。

## 一、摘要

DeepMine 是一套基于大语言模型的苏格拉底式追问系统，旨在通过结构化的人机协同对话，帮助用户将头脑中未被整理的隐性知识、碎片化经验和复杂构想，转化为清晰、逻辑完整、可直接对外使用的结构化知识资产。

本项目从初始需求调研到最终版本发布，共经历 6 个主要版本迭代，融合了认知科学（SOLO 分类理论）、苏格拉底式提问法、金字塔式访谈法、隐性知识外化理论等多个方法论框架，并结合了全网公开技术资料、学术研究、社区实践和用户反馈进行了多轮优化。

项目最终定位为 行业领先级（Top 5%-10%）技能，在追问机制的系统性、用户体验的友好度和场景覆盖的广度上具有显著优势。

## 三、各版本详细说明

### V1.0 —— 基础框架版

发布背景：

初始需求为全网检索关于“通过大模型或 Agent 与人对话，深度追问人的想法，从而深度挖掘出人未经整理、未形成系统、或未能有效组织成框架的想法、知识和经验”的相关方法论、问题递进库和追问设计原理。

核心目标：

构建一个能够覆盖三种典型客户场景的统一追问框架：

- 场景一：客户有丰富经验但不知如何总结、条理化、结构化表达

- 场景二：客户不知如何描述自身或企业的价值与作用

- 场景三：客户有明确需求但缺乏精力或方法论将想法整合成方案

方法论基础：

基于全网检索，整合以下核心方法论：

1. AIED 人机协同问课教研模式（华南师范大学，2025 年 12 月）——四阶循环：定位目标 → 解读现象 → 探究证据 → 萃取知识

2. 苏格拉底式问题支架（《现代远程教育研究》2025 年第 1 期）——提示性 / 指导性 / 解释性三类支架

3. 金字塔式访谈法（《清华管理评论》2025 年 1-2 期）——响应式 → 激发式 → 共创式

4. 重复提问法（TechRadar，2026 年 2 月）——同一问题重复 2-3 次，提升回答深度

5. 隐性知识捕获方法论（Rex 公司博客，2026 年 2 月）——AI 访谈 + 工作观察 + 例外案例 + Agent 训练

核心机制：

- 四阶段循环：锚定（确立核心话题与事件锚点）→ 勘探（多维度追问）→ 结构化（实时整理与识别缺口）→ 输出（生成结构化文档）

- 五维度追问库：

- 纵向深化（L1 澄清 → L2 因果 → L3 决策点 → L4 规律提炼 → L5 框架化）

- 横向拓展（关联与对照，限 3 个方向以内）

- 事件锚定（要求时间 + 具体动作 + 可观察结果）

- 隐性假设揭示（元认知层追问）

- 差异化定位（与参照物对比）

场景专属序列：

三个场景各有独立的追问序列（场景一 8 轮 / 场景二 7 轮 / 场景三 8-10 轮），每 3 轮执行一次内部校验，信息饱和度≥70% 方可进入输出阶段。

输出格式：

三大场景各配有专属输出模板（知识集 / 价值陈述 / 方案文档）。

已知不足：

追问相对宽泛，缺乏对用户思维边界的有效约束，用户可能在发散性回答中丢失核心目标。

### V2.0 —— 约束聚焦优化版

发布背景：

针对 V1.0 用户反馈：问题深入方式较为宽泛，用户难以在短时间内聚焦在最想梳理的内容上，发散性回答过程中用户自身也可能无法识别回答是否偏离核心目标。

核心目标：

增加三个关键约束机制，确保用户始终聚焦核心主题、思维不跳脱、表达不空泛。

新增机制：

1. 相关性实时校验引擎

- 每轮用户回答后提取核心关键词，与 CURRENT_TOPIC 进行语义相似度比对

- 相似度 ≥0.7：正常推进

- 相似度 0.4-0.7：输出提醒，请用户确认是否偏题

- 相似度 ≤0.4：明确提醒并提供 A/B/C 选项（回原主题 / 换新主题 / 结合二者）

2. 思维边界控制策略

- 明确限定横向拓展范围为“与当前主题直接相关的上下游环节 / 同一场景下的不同角色 / 同一能力在不同客户类型中的表现”

- 禁止跳跃到完全不相关的新领域、泛化到人生感悟、扩展到无关兴趣爱好、陷入纯理论空谈

- 超出范围时主动拉回：“我们先围绕『当前主题』展开，暂时不延伸到其他方向”

3. 实质内容锚定强化

- 自动检测空泛表达信号：超过 3 个形容词无具体名词 / “我觉得”“我感觉”开头但无事实支撑 / 无具体时间、人物、数据、事件、结果

- 强制锚定话术：“具体在什么背景下？具体做了什么动作？产生了什么可衡量结果？”

- 允许标记为“待补充案例”并跳过

场景专属序列优化：

三个场景的追问序列均增加了明确的约束标注（每轮标注“约束机制”），如“目标锁定”“实质锚定”“实时校验”“边界控制”。

自检结果：

- 防发散能力：用户偏题时主动提醒并给出选择

- 实质内容挖掘：空泛表达被强制锚定后，可操作性显著提升

- 输出质量一致性：同用户同主题下多次运行结果稳定、可复现

### V3.0 —— 成熟体验优化版

发布背景：

V2.0 虽解决了“聚焦”问题，但交互体验仍偏工具化。用户需要感受到被引导、被鼓励、被理解，而非被“程序化地追问”。同时需要确保用户有充分的补充空间，不被固定程式限制思考。

核心目标：

增加完整的用户体验层——使用引导、正向激励、情商纠正、开放补充，使用户从“被动答题者”转变为“主动协作者”。

新增模块：

1. 首次使用引导与预期管理

- 自动输出欢迎语，说明过程时长（15-30 分钟）

- 明确用户三件事：回答、提醒偏题、随时调整方向

- 明确产出承诺：结构化文档 + 思维梳理 + 可直接使用的内容

2. 正向激励系统

- 关键节点触发差异化激励话术

- 示例：“这个案例太有代表性了！”“你的思路越来越清晰了！”“你能自己觉察到偏移，这是很棒的进步！”

3. 高情商纠正机制

- 摒弃“你跑题了”“你错了”等负面表述

- 分偏题类型使用柔性引导：

- 轻微偏题：“你提到的『新内容』很有意思！你希望纳入今天范围，还是继续聚焦『原主题』？”

- 中度偏题：“我注意到方向有些不同。你想 A.回原主题 B.换新主题 C.两者都聊？”

- 空泛表达：“为了更有说服力，我想请你补充『硬核』细节——具体动作、时间、数据或结果”

4. 阶段完成确认与开放补充

- 每个子阶段结束时执行“阶段小结 + 修正邀请 + 补充邀请”

- 话术模板：“以上我理解得准确吗？有没有需要修正的？有没有想补充但没来得及说的？”

用户控制指令：

新增 5 种用户主动控制指令：“停一下”“我想补充”“换主题”“帮我整理已聊内容”“明天再继续”。

自检结果：

- 用户可自由切换主题，无任何负面评价

- 补充机制顺畅运行，用户无“被卡住”感

- 激励系统有效维持用户参与热情

### V4.0 —— 学术对标升级版

发布背景：

V3.0 在用户体验上已趋成熟，但追问的“诊断精准度”仍有提升空间。通过深度自查并与全网公开 Skill 对比，识别出可借鉴的高阶方法论和若干功能遗漏。

核心目标：

引入学术研究中的 SOLO 分类理论、苏格拉底式状态机、认知激活检测等机制，使追问从“线性推进”升级为“诊断 → 施治 → 验证”的闭环。

新增 / 升级机制：

1. SOLO 分类理论驱动的追问层级映射

- 五层级诊断：前结构 → 单点结构 → 多点结构 → 关联结构 → 抽象拓展结构

- 每层级匹配专属追问策略（具象化澄清 / 证据追问 / 关系追问 / 跨情境追问 / 元认知追问）

- 增加典型回答特征句作为判定参照

2. 用户答不出时的四级支架机制

- 支架 1（换角度）：“换个问法：如果给完全不懂的人讲，你会怎么开头？”

- 支架 2（给类比）：“比如『整理衣柜』的思路——先清空、再分类、最后归位。有类似比喻吗？”

- 支架 3（给选项锚点）：“我给出几个方向：A/B/C。有你接近的吗？”

- 支架 4（标记跳过）：“先标记一下，继续往前走，说不定后面豁然开朗”

- 连续 3 轮无进展 → 暂停，输出摘要，请用户确认是否继续

3. 认知激活检测

- 检测信号：用户改变说法 / 前后回答差异 / “等一下，我重新想一下”

- 触发话术：“这个调整很有意思——说明思考正在深入！是什么让你产生了这个新理解？”

4. 混合交互模式

- 关键节点提供“预设选项 + 自由文本回退”

- 示例：“你的核心能力更接近：A.推动决策 B.化解冲突 C.整合资源 D.其他（请描述）”

5. 反直觉角度提问

- 用户表达确定性看法时触发

- 示例：“你说你用 A 方法处理。如果 A 有潜在局限性，可能是什么？反过来用 B 会不会在某些情况下更好？”

6. 可操作性评分三维细则

- 维度 1：每个原则 / 步骤是否包含“谁 + 做什么 + 怎么做”（4 分）

- 维度 2：是否有至少 3 个具体案例支撑（3 分）

- 维度 3：是否有可验证结果指标或可执行行动（3 分）

- ≥8 分方可输出

场景路由修正：

从“关键词匹配”升级为“意图 + 句式双重判定”，优先级：场景三 > 场景一 > 场景二。

低质量回答兜底：

新增：单轮回答 <10 个汉字且无实质内容 → 触发支架；连续 3 轮 → 暂停输出摘要。

自检结果：

- 追问诊断精准度大幅提升

- 用户卡顿处理能力显著增强

- 思维转变捕捉机制完善

- 无逻辑矛盾和功能遗漏

### V5.0 —— 社区融合增强版

发布背景：

在与各玩家社区、自媒体、视频平台、科普文章等资源进行深度对比后，识别出 6 项可完善方向，在不弱化原始主体功能的前提下进行整合升级。

核心目标：

保持三大场景主体功能不变，融入业界最新实践（思链追问、薪火 Agent、PREFS 方法论、C 端苏格拉底实践等），丰富追问透明度和交互温度。

新增 / 升级内容：

1. 追问方向标签系统（对标思链追问）

- 每次追问前标注思考方向类型：因果分析 / 边界条件 / 类比迁移 / 反向思考 / 具体化 / 框架化 / 元认知

- 价值：帮助用户理解追问意图，增强元认知觉察

2. 情感安全感机制（对标 C 端苏格拉底实践）

- 首次启动增加安全声明：“这里没有对错，只有你想梳理的内容。我的职责是陪你一起挖掘，而不是评判你挖到了什么。”

- 增加用户控制指令说明：“这个话题我不太想聊了”“我需要想想”“我觉得你说得不对”

3. 心智模型工具箱（对标“深度思考 Skill”）

- 6 种心智模型：逆向思维、二阶思维、第一性原理、系统思维、奥卡姆剃刀、机会成本

- 仅在用户卡顿或需要跳出思维定式时调用

4. 知识图谱化输出模式（对标薪火 Agent）

- 场景一增加输出格式选项：结构化文档 / 知识图谱

- 知识图谱以可视化网络图展示要素关系（若模型支持）

5. 三阶段工作框架优化（对标学术模型）

- 内部阶段命名：显现阶段 → 加工阶段 → 外化阶段

- 阶段转换时向用户说明当前任务

6. 五维质量评分（对标业界逻辑梳理测评）

- 扩展为五维 10 分制：因果链条清晰度（2 分）+ 结构层级合理性（2 分）+ 论据支撑度（2 分）+ 逻辑一致性（2 分）+ 冗余信息剔除（2 分）

- ≥8 分方可输出

核心原则声明：

所有升级内容均标注为“可选”“卡顿时调用”“若模型支持”，确保不喧宾夺主，三大场景主体功能完整保留。

自检结果：

- 原始主体功能无弱化

- 升级内容与主体功能无冲突

- 指令可执行性良好

### V5.1 —— 轻量精炼交付版

发布背景：

V5.0 功能完整但体量偏大（约 8500 Tokens），需在不牺牲核心功能的前提下进行轻量化优化，提升运行效率和响应速度。

核心目标：

精炼、精准、精纯——减少非必要资源占用，保持轻量和灵活。

精简措施：

| **优化项** | **V5.0** | **V5.1** | **节省幅度** |
| --- | --- | --- | --- |
| 独立机制数量 | 8 个（A-H） | 3 步统一决策引擎 | 机制数 ↓87.5% |
| 场景平均轮次 | 7.7 轮 | 6 轮 | ↓22% |
| 追问方向标签 | 7 种 | 4 种（具体化 / 因果 / 框架化 / 边界） | ↓43% |
| 评分维度 | 5 维 10 分 | 3 维 6 分 | ↓40% |
| 首次引导语 | 300 字 | 80 字 | ↓73% |
| 心智模型 | 6 种 | 3 种（逆向 / 二阶 / 第一性原理） | ↓50% |
| 总 Token 估算 | ~8500 | ~5500 | ↓35% |

核心精简原则：

- 8 个独立机制合并为“三位一体追问决策引擎”（相关性判断 + SOLO 层级诊断 + 实质检查）

- 保留所有核心功能，仅压缩冗余表述和合并重复逻辑

- 评分保留核心三要素：案例支撑 / 逻辑完整 / 无冗余

- 场景序列保留所有关键追问节点

三轮深度自检结果：

- 功能完整性：三大场景完整，核心机制全部保留

- 逻辑一致性：无矛盾

- 可执行性：指令清晰，无歧义

- 轻量化效果：Token 消耗减少约 35%

### V5.2 —— 三场景引擎完整实现版

发布时间：2026 年 8 月 21 日

核心目标：

将 V5.1 已定型的决策逻辑完整落为可执行的引擎文件，使三大场景在文件层面各自成立，而非共用单一维度集。

新增 / 升级内容：

1. 场景路由模块（shared/scenarios.md）

- 三大场景定义、意图 + 句式双重判定、优先级 场景三 > 场景一 > 场景二
- 各场景独立轮次预算：经验萃取 6 轮 / 价值梳理 5 轮 / 方案生成 6-8 轮
- 场景中途切换时已收集内容原样迁移，不清空

2. 三套独立维度集（shared/dimensions.md）

- 场景一 K1-K5：事件锚点 / 关键动作 / 判断依据 / 例外情况 / 可复用规律
- 场景二 V1-V5：服务对象 / 具体交付 / 差异化对照 / 可验证结果 / 适用边界
- 场景三 A-F：业务背景 / 核心功能 / 用户群体 / 技术约束 / 时间预算 / 验收标准
- 每个维度配有效 / 无效判例

3. 三套输出模板（templates/）

- 知识集 / 价值陈述 / 方案文档，收口时按场景自动选用

4. 模块独立化

- 四级支架抽出为 shared/scaffold.md
- 心智模型工具箱抽出为 shared/mental_models.md
- 语气规则与高情商纠正抽出为 shared/tone.md，由五个 handler 统一引用
- 三维质量评分抽出为 shared/quality_score.md
- 首次引导、安全声明、控制指令抽出为 shared/onboarding.md

5. 决策引擎细则补齐（orchestrator.md）

- 控制指令拦截前置为 Step 0，优先级高于全部追问逻辑
- 相关性判断改为语言信号三档判定
- 新增 stall 信号与 STALL 计数，连续 3 轮无进展自动暂停并输出阶段摘要
- 新增 TAG 追问方向标签（具体化 / 因果 / 框架化 / 边界）
- 维度轮数各自独立计数，互不继承
- 确认性短回答不再单独构成维度覆盖

6. 状态块扩展（shared/state_format.md）

- 新增 SCENE / TOPIC / STAGE / RELEVANCE / TAG / STALL 字段
- 维度代号随场景切换

7. 质量评分不再作为输出门槛

- 分数不足时仍然输出文档，改为在文末追加「可继续深挖的部分」

### 使用方式

将对应版本的 System Prompt 指令集完整复制粘贴至大模型 Agent 的 System Prompt 栏中，用户发送任意需求内容后 Agent 自动启动。

### 用户控制指令

| **指令** | **作用** |
| --- | --- |
| “停一下” | 暂停追问，等待用户指令 |
| “我想补充” | 在当前位置开放补充通道 |
| “换主题” | 更新 CURRENT_TOPIC，重新锚定 |
| “帮我整理已聊内容” | 输出当前已收集内容摘要 |
| “直接整理输出” | 跳过剩余追问，立即进入输出阶段 |

## 八、未来迭代方向

基于行业对比评测结果，DeepMine 的后续迭代将聚焦以下方向：

1. 标准化 Benchmark 实证验证：参照 Socratic Tutoring ITS 和 SkillsBench 模式进行系统化实测，获取量化效果数据

2. 知识图谱输出方案标准化：优化场景一的知识图谱输出，形成更成熟的可视化方案

3. 外部知识库联动：探索与 Corpus2Skill 类系统的整合，增加索引和检索能力

4. 多语言支持：扩展中英文双语能力

5. 插件化封装：便于以插件形式嵌入各类主流 Agent 平台

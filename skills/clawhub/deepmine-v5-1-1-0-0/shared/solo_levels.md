# SOLO 档位判据

衡量标准：这句话能不能直接用来写需求文档。

---

## 档 1：无效回答

信号（满足任意一条即为档1）：
- 只说「对」「好的」「就是这个意思」，无新信息
- 纯抱怨无事实：「就是很麻烦」「现在太乱了」「没法弄」
- 把决策推回来：「你们来定吧」「你们懂这个吧」
- 反问逃避：「你说呢」「谁知道呢」

```
[EXAMPLE]
问：「您现在业务上最头疼的是哪件事？」
答：「就是很乱，整体都不行。」→ 档 1
```

---

## 档 2：单点有效信息

信号：
- 一个有具体名词的信息点，有场景/数量/时间修饰
- 能被「问题是 X」或「需要做 X」完整概括
- 无并列、无因果

```
[EXAMPLE]
答：「我们现在客服响应太慢，用户要等很久。」→ 档 2
答：「想要一个能自动回复的功能。」→ 档 2
答：「预算大概在 50 万以内。」→ 档 2
```

---

## 档 3：多点并列

信号：
- 多个有效信息点，连接词为：也、还有、另外、而且、加上
- 各点可以独立存在，删去任何一点其余各点意思不变
- 无时序、无因果、无优先级

```
[EXAMPLE]
答：「想要 AI 客服、还要数据分析后台、最好能发邮件通知、另外要对接 ERP。」→ 档 3
答：「用户是内部员工，大概两三百人，主要在销售部门，也有运营。」→ 档 3
```

---

## 档 4：有因果或优先级

信号（至少出现一条）：
- 时序词：先……再……最后、在 X 之后、X 上线了才能做 Y
- 因果词：因为 X 所以需要 Y、X 导致了 Y、X 才能实现 Y
- 优先级词：最重要的是、其次才是、X 是必须有的、Y 可以先不做
- 条件词：如果有 X 才能做 Y、没有 X 的话 Y 就没意义

**分界测试**：删去其中一项，其余各项的意思是否改变？
- 改变了 → 档 4（项和项之间有依赖）
- 没有改变 → 档 3（只是并列）

```
[EXAMPLE — 档 4]
答：「最重要的是自动回复，因为 80% 的工单都是重复问题，先做这个客服压力就小一半。数据分析后台后面再说，不急。」
→ 有优先级（最重要的是）、有因果（80% 重复 → 压力小一半）→ 档 4

[EXAMPLE — 看起来像档 4 但实际是档 3]
答：「因为我们用户多，所以要能扛住高并发，而且要有数据分析。」
→「用户多」和「数据分析」没有真实因果，只是用「所以」串起来
→ 删去「用户多」，「数据分析」需求还成立 → 档 3
```

---

## 档 5：说出本质目标

信号（至少出现一条）：
- 说出商业目标或核心指标：「降低 X%」「解决 X 的核心问题是」
- 说出验收标准：「做到 X 我就认为成功了」「只要 X 能实现，其他都好说」
- 说出优先级背后的原因：「X 必须做，不做就会 Y」
- 说出红线：「Y 不能碰，这是底线」

```
[EXAMPLE]
答：「核心是把人工客服工单量降下来。现在一天 1000 个工单，80% 是重复的，AI 能处理掉这 80%，让客服专注复杂问题。满意度不能下降，这是红线。」→ 档 5
答：「说白了就是成本问题。客服团队太大了，AI 能顶掉一半工作量就能缩减编制，这才是真正目的。」→ 档 5
```

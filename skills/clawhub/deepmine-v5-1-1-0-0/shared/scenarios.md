# 三大场景定义与路由

DeepMine 用一套统一框架覆盖三种典型场景。场景决定追问维度集、轮次预算和输出模板。

---

## 场景定义

### 场景一 · 经验萃取（SCENE = K）

**用户状态**：有丰富的实践经验，但不知道如何总结、条理化、结构化表达。

**典型开场**：
- 「这事我做了好多年，但让我讲我讲不出来」
- 「帮我复盘一下这个项目」
- 「我想把我的经验整理成方法论」

**追问维度**：K1–K5（见 [dimensions.md](dimensions.md)）
**轮次预算**：6 轮
**输出模板**：[templates/knowledge_set.md](../templates/knowledge_set.md) 知识集

---

### 场景二 · 价值梳理（SCENE = V）

**用户状态**：不知道如何描述自身或企业的价值、优势与作用。

**典型开场**：
- 「我说不清我们公司到底好在哪」
- 「面试让我讲优势，我讲不出来」
- 「帮我提炼一下我们的核心竞争力」

**追问维度**：V1–V5（见 [dimensions.md](dimensions.md)）
**轮次预算**：5 轮
**输出模板**：[templates/value_statement.md](../templates/value_statement.md) 价值陈述

---

### 场景三 · 方案生成（SCENE = S）

**用户状态**：有明确需求或构想，但缺乏精力或方法论把想法整合成可落地的方案。

**典型开场**：
- 「我想做一个系统，帮我理一下需求」
- 「帮我做个方案」
- 「这件事我想做，但不知道从哪下手」

**追问维度**：A–F 六维度（见 [dimensions.md](dimensions.md)）
**轮次预算**：6–8 轮
**输出模板**：[templates/solution_doc.md](../templates/solution_doc.md) 方案文档

---

## 场景路由判定

首轮执行，采用**意图 + 句式双重判定**。

### 判定优先级

```
场景三 (S) > 场景一 (K) > 场景二 (V)
```

先判场景三，不命中再判场景一，都不命中归入场景二。理由：方案生成有最强的落地诉求，误判代价最高。

### 判定信号

| 场景 | 意图信号 | 句式信号 |
| --- | --- | --- |
| S 方案生成 | 想做某件尚未开始的事、要交付物、要落地 | 出现「我想做」「要建」「打算上」「帮我做个方案」「梳理需求」+ 未来时态 |
| K 经验萃取 | 已发生的实践、要总结沉淀 | 出现「我做了」「以前」「复盘」「总结」「整理成」+ 过去时态 |
| V 价值梳理 | 描述自身或组织的属性、优势 | 出现「我们的优势」「好在哪」「怎么介绍」「说不清」+ 主语是人或组织 |

### 判定不清时

不猜。直接问一句，用具体选项而非抽象分类：

```
「先确认一下方向——今天是想把已经做过的经验理清楚，
还是想把一件还没开始的事规划出来？」
```

### 场景切换

用户中途明确转向（如从复盘转为规划），执行：
1. 保留已收集内容，不清空
2. 更新 SCENE，切换维度集与模板
3. 已收集内容中能对应到新维度的，原样迁移

## 追问序列

序列是节奏参考，不是必须逐条执行的脚本。跟着对话自然走，维度覆盖优先于顺序。

### 场景一 · 经验萃取（6 轮）

| 轮次 | 目标维度 | 追问重点 |
| --- | --- | --- |
| 1 | K1 | 锚定一个具体事件：什么时候、什么场合 |
| 2 | K2 | 在那个事件里具体做了什么动作 |
| 3 | K3 | 当时为什么这么做，依据是什么 |
| 4 | K4 | 有没有哪次不管用，那次有什么不同 |
| 5 | K5 | 这几次放在一起，有没有共同的做法 |
| 6 | 校验 | 阶段小结 + 修正邀请 + 补充邀请 |

### 场景二 · 价值梳理（5 轮）

| 轮次 | 目标维度 | 追问重点 |
| --- | --- | --- |
| 1 | V1 | 谁在用、谁在买、谁受益 |
| 2 | V2 | 具体交付了什么，对方拿到手的是什么 |
| 3 | V3 | 同样的事别人怎么做，你们哪里不一样 |
| 4 | V4 | 对方拿到之后发生了什么可见的变化 |
| 5 | V5 | 什么情况下这套不适用 |

### 场景三 · 方案生成（6–8 轮）

| 轮次 | 目标维度 | 追问重点 |
| --- | --- | --- |
| 1 | A | 现在有什么问题，为什么现在要做 |
| 2 | B | 要能做什么，哪些必须有 |
| 3 | C | 谁来用，大概多少人 |
| 4 | D | 有没有现有系统要对接 |
| 5 | E | 时间和预算的范围 |
| 6 | F | 做到什么程度算成功，红线在哪 |
| 7–8 | 补齐 | 回补未明确维度，阶段小结 |

## 思维边界控制

横向拓展限定在以下三类方向以内：

- 当前主题的上下游环节
- 同一场景下的不同角色
- 同一能力在不同对象/客户类型中的表现

**禁止**跳跃到完全不相关的新领域、泛化为人生感悟、扩展到无关兴趣、陷入纯理论空谈。

超出边界时按 [tone.md](tone.md) 的偏题处理话术拉回，禁止使用「你跑题了」这类表述。

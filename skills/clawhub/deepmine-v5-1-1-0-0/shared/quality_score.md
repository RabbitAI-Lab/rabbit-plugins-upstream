# 收口前质量评分

收口前执行的内部自检，三维 6 分制。**不向用户展示评分过程与分数。**

---

## 评分维度

### 维度一：案例支撑（0–2 分）

| 分值 | 判据 |
| --- | --- |
| 2 | 有 2 个及以上具体案例，含时间、动作或数据 |
| 1 | 有 1 个具体案例 |
| 0 | 全部为概括性表述，无可指认的具体事件 |

### 维度二：逻辑完整（0–2 分）

| 分值 | 判据 |
| --- | --- |
| 2 | 关键条目之间有明确的因果、时序或优先级关系 |
| 1 | 条目独立成立但相互之间只是并列 |
| 0 | 条目之间存在矛盾，或关键环节缺失 |

### 维度三：无冗余（0–2 分）

| 分值 | 判据 |
| --- | --- |
| 2 | 无重复表述，每条都承载独立信息 |
| 1 | 存在少量重复，不影响理解 |
| 0 | 大量同义重复，核心信息被稀释 |

---

## 判定与动作

**总分 ≥ 4**：正常收口，按场景输出对应模板。

**总分 < 4**：仍然输出文档，**不得因分数不足而拒绝出结果**。在文档末尾加一节「可继续深挖的部分」，指出得分低的维度对应的内容缺口，供用户自行决定是否补充。

```
【可继续深挖的部分】
- [维度名]：目前只有方向性描述，还缺一个具体案例
```

**禁止**：以分数不足为由不输出、要求用户继续回答才给结果、向用户报告分数。

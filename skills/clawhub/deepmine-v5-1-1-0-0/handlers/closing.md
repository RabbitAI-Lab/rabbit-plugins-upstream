# Handler: Closing

收口条件已触发：当前场景维度全覆盖、用户发出结束信号，或用户说「直接整理输出」。

**任务：把用户说过的话组织成结构化文档。**

---

## 输入

- 完整对话历史
- orchestrator 输出的路由 JSON（scene、forced、dimensions）

---

## 规则 1：只用对方说过的话

所有字段内容只能来自对话历史中用户说过的原话或原话概括。

不加解读、不加建议、不加补充。连接词（「因此」「所以」）可以用，但被连接的内容必须是用户说过的。

## 规则 2：未覆盖的写「未明确」

对方没说过的，不捏造、不推断，直接写「未明确」。

`forced: true`（用户主动跳过剩余追问）时，未覆盖维度一律写「未明确」，不补问。

## 规则 3：有原话就引用原话

```
好：核心目标：「说白了就是成本问题，团队太大了。」
差：核心目标：降低人力成本（这是归纳，不是原话）
```

## 规则 4：先过质量自检

按 [shared/quality_score.md](../shared/quality_score.md) 执行三维自检。分数不足**不影响输出**，只在文档末尾追加「可继续深挖的部分」。不向用户展示分数。

## 规则 5：按场景选模板

| SCENE | 模板 |
| --- | --- |
| K 经验萃取 | [templates/knowledge_set.md](../templates/knowledge_set.md) |
| V 价值梳理 | [templates/value_statement.md](../templates/value_statement.md) |
| S 方案生成 | [templates/solution_doc.md](../templates/solution_doc.md) |

---

## 输出格式

先说一句收口话，然后按模板输出。收口话参考（不要照抄）：

- 「好，我把我们聊的整理一下。」
- 「你说的我都记下来了，整理如下。」

模板中的 `===` 标记供解析使用，不得删改。

---

## 输出之后

文档输出完成后，加一句：

```
「有需要补充或调整的，现在可以说。」
```

然后等待用户确认。

---

## 禁止

- 文档中出现建议、判断或评价
- 改写用户的原话（可以概括，不能改变意思）
- 捏造用户没说过的内容
- 遗漏起止标记
- 因质量分不足而拒绝输出

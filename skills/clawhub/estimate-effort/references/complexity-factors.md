# 复杂度因素库

## 复杂度等级定义

| 等级 | 分值 | 定义 | 典型场景 |
|------|------|------|----------|
| 简单 | 1 | 标准模式，有现成参考，逻辑清晰 | 简单CRUD、配置修改、文案调整 |
| 较简单 | 2 | 需要少量定制，逻辑明确 | 带校验的表单、简单查询接口 |
| 中等 | 3 | 有一定业务逻辑，需要设计 | 状态机、权限控制、分页列表 |
| 较复杂 | 4 | 复杂业务规则，多模块交互 | 订单流程、审批流、数据聚合 |
| 复杂 | 5 | 高度复杂，需要深入研究 | 算法实现、性能优化、架构改造 |

## 复杂度评估维度

### 1. 代码耦合度（权重 20%）

| 分值 | 表现 |
|------|------|
| 1 | 独立模块，无依赖 |
| 2 | 依赖1-2个内部模块 |
| 3 | 依赖3-5个模块，有少量耦合 |
| 4 | 深度耦合，改动需同步多处 |
| 5 | 遗留代码，耦合严重，改动风险高 |

### 2. 技术熟悉度（权重 15%）

| 分值 | 表现 |
|------|------|
| 1 | 常用技术，熟练掌握 |
| 2 | 用过但不常写 |
| 3 | 了解原理，需要查文档 |
| 4 | 仅听说过，需要学习 |
| 5 | 完全新技术，需要调研 |

### 3. 数据模型变更（权重 15%）

| 分值 | 表现 |
|------|------|
| 1 | 无数据模型变更 |
| 2 | 新增字段，向后兼容 |
| 3 | 新增表或修改字段类型 |
| 4 | 需要数据迁移 |
| 5 | 重构数据模型，大规模迁移 |

### 4. 外部依赖（权重 15%）

| 分值 | 表现 |
|------|------|
| 1 | 无外部依赖 |
| 2 | 使用稳定的内部服务 |
| 3 | 对接1-2个外部API |
| 4 | 对接多个外部系统，有不确定性 |
| 5 | 依赖不稳定的外部服务或新对接 |

### 5. 测试覆盖（权重 15%）

| 分值 | 表现 |
|------|------|
| 1 | 无需新增测试 |
| 2 | 补充少量单元测试 |
| 3 | 编写完整单元测试 |
| 4 | 需要集成测试和E2E测试 |
| 5 | 需要性能测试或压力测试 |

### 6. UI复杂度（权重 10%，仅前端适用）

| 分值 | 表现 |
|------|------|
| 1 | 使用现有组件 |
| 2 | 组合现有组件，少量样式调整 |
| 3 | 新开发业务组件 |
| 4 | 复杂交互（拖拽、图表、实时更新） |
| 5 | 高度定制化UI（动画、Canvas、复杂表单） |

### 7. 文档与部署（权重 10%）

| 分值 | 表现 |
|------|------|
| 1 | 无需变更 |
| 2 | 更新少量文档 |
| 3 | 编写API文档或用户手册 |
| 4 | 需要修改CI/CD流程 |
| 5 | 需要新的部署架构或环境配置 |

## 复杂度计算

```
加权复杂度 = Σ(各维度分值 × 权重)

映射到1-5级：
- 1.0-1.5 → 简单(1)
- 1.6-2.5 → 较简单(2)
- 2.6-3.5 → 中等(3)
- 3.6-4.5 → 较复杂(4)
- 4.6-5.0 → 复杂(5)
```

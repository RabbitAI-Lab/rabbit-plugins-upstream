# 优先级判定规则

> 基于 KSAO 框架 + 能力深度模型的双层漏斗匹配。
> 核心原则：按能力维度计分（非按关键词计分），消除同义词重复计算。

---

## Layer 1：硬过滤

通过硬过滤才能进入 Layer 2。不通过 → 直接标记 `low`。

### 1.1 薪资过滤

提取 JD 薪资"X-YK"格式（忽略年薪倍数如·24 薪）：
- **通过**：与候选人期望薪资范围有重叠
- **不通过**：完全不重叠

### 1.2 地点过滤

- **通过**：候选人期望城市、标注远程、**JD 未提及地点信息则默认通过**
- **不通过**：明确为其他城市且不接受远程

### 1.3 行业过滤

- **通过**：非拒绝行业
- **不通过**：候选人明确拒绝的行业

### 1.4 排除项检查

| 检查项 | 通过条件 | 不通过条件 |
|--------|---------|-----------|
| 岗位性质 | 涉及候选人目标职能 | 明确为排除岗位类型 |
| 专业限制 | 无特定要求或候选人具备 | 要求特定专业且不具备 |
| 经验错配 | 与候选人年限匹配 | 明显超出或不足 |
| 福利 | 双休或未提及 | 单休/大小周/996（除非薪资显著高） |
| 语言 | 无语言要求或候选人具备 | 要求候选人不具备的语言能力 |

> **注意：** 硬过滤的具体阈值（薪资范围、拒绝行业、排除岗位等）需在初次使用时通过交互确立（见 SKILL.md Step 0）。

---

## Layer 2：能力维度匹配（语义聚类）

### 核心原则

**按能力维度计分，不按关键词计分。**

- 每个能力维度最多计分 1 次
- 同一维度内的同义词/近义词不重复计分
- 命中任一同义词 → 该维度得分 +1

### 能力维度定义方式

**重要：能力维度应根据用户画像动态生成，以下为通用维度模板，供 Agent 参考和用户定制。**

Agent 在 Step 0.4 中需根据用户简历和目标岗位，生成 5-8 个自定义维度。以下为常见维度参考：

#### 通用维度模板（按需选用）

| 维度类别 | 示例维度 | 示例同义词簇 |
|---------|---------|-------------|
| 战略类 | 战略规划 | 战略、战略运营、经营分析、决策支持、商业分析 |
| 管理类 | 目标与绩效管理 | OKR、KPI、绩效管理、目标管理、目标拆解 |
| 组织类 | 组织发展 | 组织效能、人才盘点、人才梯队、职级体系 |
| 数据类 | 数据与数字化 | 数据分析、数据看板、数字化转型、数据可视化 |
| 技术类 | AI 与自动化 | AI、AIGC、大模型、RPA、流程自动化 |
| 项目类 | 项目与流程管理 | 项目管理、流程优化、跨部门协调 |
| 职能类 | 助理职能 | 会议管理、日程管理、向上管理、高管支持 |
| 行业类 | 行业专业知识 | 根据目标行业定制，如：消费品、互联网、金融 |

### 用户自定义维度流程

```
Agent: 基于你的简历和目标岗位，我建议以下能力维度：
1. [维度名]：[同义词 A、同义词 B、同义词 C]
2. [维度名]：[同义词 A、同义词 B]
...

是否需要增删或调整？
```

### 计分规则

每个能力维度：
- **命中**（JD 中出现该维度任一同义词）→ 得分 +1
- **未命中** → 得分 0

**总分 = 命中维度数**（满分 = 总维度数）

## Layer 3：能力深度匹配

### JD 岗位层级推断

从 JD 多维信号推断岗位层级：

| 信号 | 推断逻辑 |
|------|---------|
| 岗位名称 | "总监"→L3-L4，"经理"→L2-L3，"助理"→L1-L2，"VP/CXO"→L4-L5 |
| 薪资范围 | <15K→L1-L2，15-25K→L2-L3，25K+→L3-L4 |
| 汇报对象 | "向CEO汇报"→L3-L4，"向经理汇报"→L1-L2 |
| 职责动词 | "搭建体系"→L3，"协助执行"→L1，"战略规划"→L4 |
| 经验要求 | "3-5年"→L2-L3，"8年以上"→L3-L4 |
| 团队管理 | "带X人团队"→L3+，无管理→L1-L2 |

### 候选人能力深度评估

从候选人画像（KSAO）评估各能力维度的深度等级（L1-L5）。

### 深度匹配判定

| 匹配类型 | 条件 | 说明 |
|---------|------|------|
| **精准匹配** | 候选人深度 = 岗位要求深度 | 理想状态 |
| **轻度超配** | 候选人深度 = 岗位要求 +1 级 | 可接受，需关注稳定性 |
| **严重超配** | 候选人深度 ≥ 岗位要求 +2 级 | 风险高，可能不稳定 |
| **轻度不足** | 候选人深度 = 岗位要求 -1 级 | 可培养，看学习能力 |
| **严重不足** | 候选人深度 ≤ 岗位要求 -2 级 | 不匹配 |

## 综合判定（Layer 1-3 汇总）

### 判定逻辑

```
Layer 1 硬过滤
  ├── 不通过 → low（理由：硬过滤不通过原因）
  └── 通过 → 进入 Layer 2

Layer 2 能力维度匹配
  ├── 命中维度数 → 基础分

Layer 3 能力深度匹配
  ├── 深度匹配度 → 调整分

综合判定
  ├── 基础分 + 调整分 → 最终优先级
```

### 判定标准（需在初次使用时与用户确认）

以下为通用默认阈值，**必须在 Step 0.4 中根据用户的目标岗位类型确认或调整**：

| 岗位类型 | high 条件 | medium 条件 | low 条件 |
|---------|-----------|------------|---------|
| 管理/总监岗 | 维度≥4 + 深度匹配 | 维度≥3 或 深度轻度不足 | 维度<3 且 深度严重不足 |
| 专业岗 | 维度≥3 + 深度匹配 | 维度≥2 或 深度匹配 | 维度<2 或 深度不匹配 |
| 助理/执行岗 | 维度≥3 + 深度匹配 | 维度≥2 + 深度匹配 | 维度<2 |
| 通用默认 | 维度≥4 + 深度匹配 | 维度≥3 + 深度匹配 | 维度<3 |

> **注意：** 以上阈值为默认值，需在初次使用时通过交互校准。用户可自定义 high/medium/low 的维度数阈值。

## AI 关键词提升规则

**仅检测职位名称（title），不检测职位描述（description）。**

### 提升逻辑

| 原判定 | title 含 AI 关键词后 | 说明 |
|--------|---------------------|------|
| low | medium | 提升 1 级 |
| medium | high | 提升 1 级 |
| high | high | 保持不变 |

### AI 关键词列表

检测关键词（忽略大小写）：
- ai, aigc, 人工智能, 智能体, 大模型, 机器学习, 深度学习
- 算法, chatgpt, gpt, llm, nlp, 自然语言处理, agent
- 数字化, 自动化, rpa, 智能化

### 检测范围

- **仅职位名称（JD 标题）**
- ~~职位描述（JD 正文）~~ ← 不检测（避免误判）

## 理由生成

### 格式

30 字以内，格式：`[核心原因]，[辅助说明]`

### 示例

| 优先级 | 理由示例 |
|--------|---------|
| high | 维度A+维度B+维度C命中，深度匹配目标岗 |
| medium | 维度命中2个，深度轻度不足 |
| low | 仅命中1个维度，纯执行岗 |

### 精简规则

- 原因超 30 字 → 精简为"主因+次因"
- 维度命中多 → 挑最核心的 2-3 个维度
- 深度不匹配 → 直接标注"深度不匹配"

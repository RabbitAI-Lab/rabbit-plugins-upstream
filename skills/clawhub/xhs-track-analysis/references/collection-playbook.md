# 小红书数据采集执行协议（Collection Playbook）

> 定位：把「浏览器自动化采集 → 结构化整理」固化为可复用流程，供 Step 2/Step 3 取数使用。
> 本协议对接 `scripts/collector/collect.py`（受监督采集器）与 `scripts/integrations/`（官方/第三方数据源骨架），产出统一 Schema 的主表输入。

## 0. 何时使用

- 用户没有现成数据，需要采集小红书公开内容做赛道分析时
- 需要评论原文做四行为归类、评论者类型与购买意图分层时（第三方工具通常拿不到评论原文）
- 需要「关键词 × 排序」的系统化采集（人工翻页容易漏排序角度）时

## 1. 路径选择（按优先级）

| 优先级 | 路径 | 工具 | 说明 |
|--------|------|------|------|
| 1 | 用户已有数据 | — | 校验口径后直接进入分析 |
| 2 | 官方商业平台 | 蒲公英 / 聚光（需品牌账号） | 达人侧事实数据 + 需求侧量级 |
| 3 | 第三方数据平台 | 千瓜 / 新红 / 蝉妈妈 / 灰豚 | 量级与趋势；无评论原文 |
| 4 | 浏览器自动化 | `scripts/collector/collect.py` | 主粮：笔记 + 评论原文（本协议重点） |
| 5 | 人工 / 插件 | 网页端边看边采 | 兜底，样本量小 |

## 2. 浏览器自动化采集步骤

### 2.1 前置检查

1. 完成 Step 0 三问与 Step 1 关键词四分组（含意图标注）
2. `pip install -r scripts/collector/requirements.txt && playwright install chromium`
3. 复制 `config.example.json` → `config.json`，填写 keywords / sorts / max_notes_per_query / delay_sec 等

### 2.2 运行采集器

```bash
python3 scripts/collector/collect.py config.json --debug
```

1. 脚本打印免责声明，需键入 **`我已知悉并承担合规责任`** 才继续（强制确认）。
2. 打开 headed 浏览器并展示登录二维码，**你本人在场扫码**（可随时中断）。
3. 按 config 的「关键词 × 排序」自动摘取，写入 `output/`：
   - `raw_notes_<时间戳>.csv`：原始字段（含赞/藏/评、`field_scope`、`completion_state`）
   - `collection_report_<时间戳>.md`：主表风格原始资料（**不含判断**）
4. 可选评论采集：`enable_comments=true` 时对高互动笔记进详情页采正文 + 前 N 条一级评论。

`--debug` 输出选择器探针与逐轮采集日志，首次真机运行建议开启。

### 2.3 选择器适配（关键）

小红书前端结构会变。若摘取为空，按以下流程处理：

1. `--debug` 运行，查看选择器探针命中数
2. 更新 `scripts/collector/collect.py` 顶部 `SELECTORS` 字典（脚本内已集中管理）
3. 适配记录写入脚本注释（`# 适配日期: YYYY-MM-DD`）

### 2.4 批量与控频

- 每个「关键词 × 排序」用 `max_notes_per_query` 控制条数（默认 20）
- `delay_sec` 控制操作间隔（限频），小红书风控严格，建议 ≥ 3 秒
- 只采公开可见数据；遇到登录墙/验证码即停止，如实报告，不绕过
- **不实现任何反爬/签名伪造/滑块绕过/设备指纹伪造**（脚本边界，勿修改破坏）

## 3. 结构化整理 Schema（对齐主表输入）

### 3.1 作品/笔记记录（对齐 data-sources.md 字段模板）

| 字段 | 来源 | 用途 |
|------|------|------|
| keyword / sort | 采集时记录 | 合并去重保留出处 |
| intent_stage | 人工补标 | 意图阶段覆盖判断（v3.0） |
| note_id / url | 采集 | 去重主键 |
| title / body | 采集 | 内容分析 |
| author / author_type | 采集 + 人工 | 达人生态位分析 |
| commercialization | 人工标注 | 商业化浓度打折 |
| publish_age | 采集（发布日） | 长尾信号检查（v3.0） |
| likes / collects / comments | 采集 | 互动分布 |
| comment_sample | 采集（评论原文） | 四行为 + 评论者类型 + 购买意图层 |
| field_scope / completion_state | 采集 | 证据边界（采到什么程度） |
| captured_at | 采集 | > 90 天需复核 |

### 3.2 采集说明（每次采集必写）

口径、时间范围、登录态限制、排序角度覆盖、缺失项、选择器适配记录、`completion_state` 分布。

## 4. 口径校验清单（进入分析前）

- [ ] 每个关键词覆盖 4 种排序角度（最新/赞/藏/评），且已记录出处
- [ ] 每条笔记带 keyword + sort + captured_at，无孤儿记录
- [ ] 跨关键词重复笔记已识别（合并时保留全部出处）
- [ ] 评论原文已采集（或标注"未采集评论，评论层结论降级"）
- [ ] 发布时长可判定（无发布日数据时标注"未知"）
- [ ] 无昵称/头像等个人信息残留（去标识化校验）

## 5. 合规检查点（必须遵守）

- 仅采集**公开可见**数据，不碰登录态私有接口；需登录时使用**本人/授权账号**、本人监督
- 遵守平台服务条款与 robots 协议，控制采集频率（拟人化节奏）
- 评论数据统计前**去标识化**（输出不含昵称/头像）
- 无法获取的数据如实标注缺口，**禁止用推算值冒充实测值**
- 触发风控/封禁的风险由使用者自担（运行前已强制确认）

## 6. 失败降级

| 情况 | 处理 |
|------|------|
| 采集器登录失败 | 退回人工/插件采集或第三方平台导出 |
| 选择器漂移导致为空 | 按 2.3 适配后重跑；无法适配则如实报告 |
| 部分评论采不全 | 按 completion_state 区分"采到哪一步"，评论层结论降级 |
| 平台登录墙阻断 | 停止采集，在报告「证据边界」声明缺口 |

## 7. 与分析的衔接

采集产物是**原始资料**（不含判断）。把 `collection_report_*.md` 交给本 Skill，按 `references/methodology.md` 完成：四分组、意图标注、四排序、长尾检查、合并去重、商业化浓度标注、达人生态位、评论四行为、供给结构与风险扫描、决策收敛。采集器不做判断——这正是"人在回路 / 受监督"的设计意图。

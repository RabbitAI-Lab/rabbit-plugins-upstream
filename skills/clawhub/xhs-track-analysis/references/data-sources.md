# 数据获取：真实数据从哪来

> 本 Skill 是「分析方法 + 输出框架」。真实数据需由用户 / 插件 / 第三方平台注入后，再交给本 Skill 做结构化与判断。
> **浏览器自动化采集 → 结构化整理的完整执行协议见 📍 `references/collection-playbook.md`**（含 `scripts/collector/collect.py` 受监督采集器、结构化 Schema、口径校验与合规检查点）。
> 以下为合规、可落地的真实数据获取路径与采集模板。

## 一、为什么本 Skill 不直接抓数据（第一性原理）
- 小红书无开放的公共搜索 API；网页端内容受登录态、反爬、频率限制约束。
- 批量爬取登录态接口违反平台 ToS，且数据稳定性差、易失效。
- 赛道判断依赖「人在回路（human-in-the-loop）」的语义理解；纯自动抓取恰是本方法要解决的失真源头。
- 因此：**采集交给浏览器插件（人工边看边选）/ 第三方或官方数据平台，本 Skill 负责把资料结构化与判断。**

## 二、真实数据获取路径（按可靠度 / 成本）

### 1. 官方商业平台（最稳，需账号 / 预算）
- **蒲公英**：达人搜索、笔记数据、合作报价、粉丝画像 —— 达人侧事实数据首选。
- **聚光**：搜索词规划、行业大盘、关键词热度 —— 需求侧量级与趋势。

### 2. 第三方数据分析（行业标配，补量级与趋势）
- **千瓜数据 / 新红数据 / 蝉妈妈 / 灰豚**：搜索词量级、笔记榜单、评论导出、达人画像、投放监测。
- 价值：补足本方法「抽样」的局限，提供赛道级量级与时效趋势。

### 3. 网页端人工 / 插件采集
- 在 xiaohongshu.com 网页端，按「关键词 + 四种排序」逐篇查看，用插件把笔记 / 评论 / 达人主页内容存入同一份资料。
- 合规边界：**仅公开页面、控制频率、不触碰登录态私有接口**。

### 4. Agent-Reach 能力层（可选增强，免自建采集）
[Agent-Reach](https://github.com/Panniantong/Agent-Reach) 是 Agent 的互联网能力层（非本 Skill 组件）：一句话安装后，Agent 可调用其 xiaohongshu 渠道读取公开笔记 / 评论 / 达人主页，返回内容注入本 Skill 结构化。
- **安装**：让 Agent 执行 `帮我安装 Agent Reach：https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/install.md`
- **渠道**：OpenCLI（复用本机已有 Chrome 会话）▸ xiaohongshu-mcp ▸ xhs-cli；`agent-reach doctor` 可体检渠道状态。
- **合规**：仅读取公开可见内容、控频；登录态渠道存在封号风险（官方建议专用小号）。OpenCLI 只复用用户已有且明确控制的会话，不注入 Cookie。
- **边界**：本 Skill 只**引用**其渠道（引知识），不复制 / 内化其安装与路由代码；代码层对接可在 `scripts/integrations/` 的 `DataSource` 抽象下另建 `agentreach` 适配器（当前未提供）。

## 二·补充：混合采集（量化初筛 + 人工深读）
纯手动深读覆盖有限，纯量化易失真。推荐混合：
- **量化初筛**（第三方：千瓜 / 新红 / 蝉妈妈 / 灰豚，或官方聚光）：先拿搜索词量级、笔记榜单、达人粉丝画像，圈定高潜关键词与达人；
- **人工深读**（网页端插件 / 人工）：对初筛结果做四分组、四排序、四行为归类与达人解读。
- 两者共用同一张主表：量化填"量级 / 趋势"，人工填"语义 / 行为 / 判断"。

## 二·补充之二：A 方案接入骨架（官方 / 第三方，代码层）
`scripts/integrations/` 提供 A 方案的**代码骨架**：统一 `DataSource` 接口 + `NoteRecord` 结构，含蒲公英(`pgy.py`)/聚光(`juguang.py`)/第三方(`thirdparty.py`) 适配器骨架与演示用 `Mock`。各适配器已实现鉴权与字段映射模板，真实 endpoint 需按官方文档填充（当前为 NotImplementedError 骨架）。`run_pipeline.py` 按 `config.source` 驱动「关键词×排序」摘取，归一化为与采集器(B)同构的 CSV/MD，交由本 Skill 分析；无凭证时 `source=mock` 可跑通整条管线验证架构。详见 `scripts/integrations/README.md`。

## 三、单次采集字段模板（每篇笔记）

| 字段 | 说明 |
| --- | --- |
| note_id / url | 去重主键 |
| keyword_source | 命中的关键词（保留全部，不删重复） |
| sort_angle | 最新 / 赞 / 藏 / 评 |
| intent_stage | 意图阶段（发现/了解/比较/决策），随关键词标注（v3.0） |
| author | 达人 ID |
| author_type | 本人 vs 第三方讲该达人 |
| commercialization | 商业化浓度（自然/疑似投放/合作），高浓度信号打折 |
| publish_age | 发布距今时长（> 90 天仍在互动 = 长尾信号，v3.0） |
| title / body | 正文要点 |
| likes / collects / comments | 互动量 |
| comment_sample | 抽样评论（按四行为归类 + 评论者类型 + 购买意图层） |
| captured_at | 采集时间（必须标注；距分析 > 90 天标"需复核"） |

## 四、受监督采集器原型（可选组件）
`scripts/collector/`（独立脚本，**非 Skill 本体**）可在你本人监督下，把"网页端手动翻页"过程自动化，产出可被本 Skill 分析的**原始公开资料**：
- 扫码登录（headed 浏览器，你本人在场、可见二维码、可中断）；
- 按 config 的「关键词 × 排序」有限摘取公开搜索/笔记页；
- 输出 CSV + 主表风格 Markdown（**仅原始资料，不含判断**）。
- **边界**：不实现任何反爬/签名伪造/风控对抗；仅本人/授权账号、仅公开页、限范围限频；运行即自行承担账号与合规风险。详见 `scripts/collector/README.md`。

## 五、交付前数据质检
- [ ] 每个关键词覆盖 4 种排序角度
- [ ] 跨关键词重复笔记已合并并保留出处
- [ ] 评论抽样量足以支撑四行为归类（建议 ≥ 30 条 / 重点内容）
- [ ] 标注采集时间与**商业化浓度**（投放密集品类的内容需打折解读）

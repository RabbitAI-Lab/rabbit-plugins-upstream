# 实测结果

当前发行版本：**1.0.2 正式版**。整理日期：2026-10-15（Asia/Shanghai）。

## 1.0.2 当前依据：dev.10 实测

本节记录 2026-10-15 对 `1.0.2-dev.10` 的实测。`1.0.2` 沿用其技能行为、脚本、模板和行为资源；晋升仅更新版本标识与发布资料，未重新运行模型生成测试。发行状态为正式版，实测结论仍有已知失败及覆盖缺口。

### 测试条件与计数

分别由 `gpt-5.6-sol / high` 和 `gpt-5.6-terra / high` 在新上下文中各生成一次借用记录整理技能及处理程序，作者完成后封存，再独立评分；没有把独立失败反馈给作者后修补重计。使用合成 CSV：30 条记录、35 个物理行，分别以 2026-10-15 和 2026-10-10 为截止日运行同一生成程序。

评分器、CSV 和 oracle 沿用已冻结协议。两个截止日是每份程序的两次执行，不增加独立模型生成样本数；作者产物重放和检查器矩阵重放也不计为额外模型样本。此轮属于已知失败推动修订后的回归，不是全新盲测。

| 检查范围 | Sol / high | Terra / high |
| --- | --- | --- |
| 冻结业务回归：截止日 2026-10-15 | 321/321 | 321/321 |
| 冻结业务回归：截止日 2026-10-10 | 321/321 | 321/321 |
| 金额专项：7 个清理正例与 6 个保留反例 | 13/13 | 13/13 |
| 输入与输出同路径的隔离边界测试 | 退出 2，输入字节保留 | 退出 0，源 CSV 被覆盖：DEV10-P1 |
| 作者拒坏自检的独立重放 | 五档案、25 个变异体全拒 | 四档案、22 个变异体全拒；缺需求追溯三类：DEV10-P2 |

金额专项同时检查物品与备注字段：七种金额全部清理，六种普通内容全部保留，提醒未见测试数额残留；额外逐行检查未见数字尾部残留。“三元件”“3块幕布”等保留反例不应因包含金额相似词被删除。过还场景另经只读补核，两份程序均保留自身合法的借出 2、已还 3，并把派生未还数置未知。

拒坏变异体数量不能直接当作质量分：Sol 的 25 个变异体含 24 种类别标签，Terra 的 22 个含 21 种。Terra 未执行需求追溯中的规则弱化、规则删除、范围缩窄三类变异，也未声明不适用；正常追溯检查通过不等于缺失的拒坏证据已补齐。矩阵报告 pass 也不证明所有适用档案已选择。

### 工具层与完整性复核

本轮工具层 18 个用例、随包 5 份矩阵共 30 个变异体、金额规则包自验均符合预期；普通 Windows Python 调用在移除 UTF-8 环境变量后也通过。源 dev.10 ZIP 与解压 87 个文件未被修改，原 manifest 86 项匹配。两份作者交付、冻结回归与金额专项证据完成哈希复核。这些是开发候选实测及证据完整性结果，正式包重新生成的文件清单用于校验本次发行身份。

输入保护测试只操作新建隔离副本，不修改真实材料或封存程序。旧版未测同一边界，不能断言覆盖输入是 dev.10 新增回归。

### 结论与未验证范围

两模型在本轮冻结业务回归和金额专项全部通过，但 Terra 仍有实际输入保护缺陷和拒坏覆盖缺口，**版本整体不标为全部验收通过**。本次正式版晋升没有修复上述问题，临时规避方法见[已知问题](KNOWN-ISSUES.md)。

每模型仅一次生成；本轮未重放完整多轮访谈、冷恢复、宿主自动发现、无技能对照、大规模性能或任意中文金额表达。可见执行记录未发现读取其他版本报告或独立答案，但宿主技能目录列表仍可见，不能称完全隔离。不能将本次样例结果推广为跨平台保证、未来成功率或任意模型兼容性。

### 测了什么

测试任务是用个人技能工坊制作并修改一项借用记录整理技能，再用生成的业务技能处理合成记录。覆盖问答、主动补充、多轮规则更新、去重、来源冲突、日期分类、排序、自由文本中的金额隐藏，以及保留普通备注等要求。

本文保留的 code-generator 历史证据包括四轮制作、五批同会话下游执行和一次新上下文 `normal` 重复，另有一次与制作无关的相邻请求。数据为合成数据；没有真实群消息发送或真实业务部署。

| 环境 | 可观察的执行方式 | 身份与能力边界 |
|---|---|---|
| code-generator | 有文件工具的执行环境；制作者、执行者及重复执行者使用新上下文调度 | 角色声明为 `code-generator`、`gpt-5.6-terra / high`，后端型号未独立认证。共享文件系统中的读取范围是指令约束，并非硬隔离。 |

### 制作阶段结果

| 项目 | 已观察结果 | 结论范围 |
|---|---|---|
| 一问一答 | code-generator 四轮制作中，相关断言通过 | 前两轮分别询问输入形式和截止日，没有重复索取已知内容；不推及未来任意输入。 |
| 主动补充 | code-generator 制作吸收已提供的业务规则 | 规则进入当前入口或状态。 |
| 多轮生成与修改 | 实际交付初版和修改版，旧版保留，关键当前规则同步 | 文件或文本生成成立，不等于整个制作阶段通过。 |
| code-generator 四轮制作 | **失败** | 第四轮用未来到期样例记录“当天到期已验证”，实际未触发当天分支：`C7-BF01`。当前样例实际分类正确，失败在验证结论范围。 |
| code-generator 相邻请求 | **本单例通过** | 直接返回一条 16 字感谢语，没有进入技能制作问答；不代表自动选择率。 |

code-generator 的作者排序样例实际触发了数量主键和日期次键，且已观察排序正确。作者走读仍属于作者自检，不能计为独立模型验证；排序正确也不能抵消错误验证记录。

#### 同输入重复的具体范围

- code-generator：首次与新上下文 `normal` 使用同一生成技能、同一输入文件和逐字相同的用户任务正文；完整控制消息因角色说明及输出目录不同而不同。业务事实一致，均通过。
- 重复仅覆盖 `normal` 这个例子，没有证明其他批次可重复稳定，也不能抵消制作阶段的验证记录失败。

#### 原始产物、修正和最终交付

最终通过不表示首次草稿完整，也不表示执行中没有失败。原始产物、修正前版本和最终版本均由维护者独立保留：

| code-generator 批次 | 原始观察及后续变化 | 计分处理 |
|---|---|---|
| `normal` | 首次自检的数字正则过宽，误命中日期；修正自检脚本后通过。三份业务文件修正前后 SHA-256 均未变。 | 业务最终交付通过；保留自检失败，不说发生过业务金额泄漏。 |
| `conflict` | 第一次自检已显示通过，后续走读发现共同借出数量未直接列出；补入回复和清单，并加强断言。两份业务文件发生变化。 | 最终交付通过；不能称首次自检覆盖完整或从未修改业务产物。 |
| 新上下文 `normal` 重复 | 首次自检发生 Windows PowerShell 编码／解析失败；修改脚本后通过。三份业务文件修正前后 SHA-256 均未变。 | 业务最终交付通过；脚本修正不能算新增业务模型运行。 |
| `next-week`、`ordering`、`privacy` | 各保存一次成功自检，没有记录业务修正。 | 最终结果仍由独立全文核对判定，不仅采用执行者的自评。 |

制作阶段的失败不因下游最终通过而改判。自检脚本检查的范围有限，也不能替代对备注、说明文字和完整交付物的语义审阅。

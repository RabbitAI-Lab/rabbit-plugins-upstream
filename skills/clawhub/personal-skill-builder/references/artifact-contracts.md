# 逐项验收原始产物与最终交付

先按 [产物与字段决定](synthesis.md) 明确每个实际出口的受众、通道、表示模式及来源，再检查真实内容。纯聊天整条回复也在范围内；正文、代码块、普通文件、附件、生成包/引用、新输入样例、输出示例、当前记录、验证和结尾不能因内部名称漏检。

每项同时核对受限内容清除和允许内容保留。文本匹配先定位，语义再判是否违约；合法普通字符/数字不误删。未知字段、同实体不同版本、去重/冲突、分类/排序/合计和当前规则同步另核，字段类型合格不能证明这些行为。

脚本原始 stdout/文件、真实退出码与最终交付分别保存、分别设关键断言，内容相同也保独立来源。最终手改正确不追认原脚本通过；修后实际重跑，原失败留存。输入读取、执行、写出失败分别记录，stdout/函数降级只说明实际完成范围。

可选标准库工具 `scripts/check_artifact_contract.py` 能核明确文本模式和 JSON 数值域；使用时读 [工具手册第 2 节](tooling.md#2-通用产物检查器)。它不生成或修正产物，不认证来源模型、语义隐私、实际发送权限或宿主自动发现。

无工具用可核对的人工过程完成可行任务，不新增权限或阻塞草案，也不伪造命令/文件/自动检查通过。固定约束后再看结果；不得删除失败阶段、篡改失败文件或放宽阈值凑通过。新增执行另存并确认已知坏产物仍被拒绝。未覆盖事项如实记录，绿色退出码不能代替语义验收。

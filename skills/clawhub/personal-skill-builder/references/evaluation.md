# 先定位实际输出，再比较和填状态

生成/更新后读本文件。按当前规则和原来源取得独立预期，完整运行案例并定位实际交付，再比较。输入重算、规则/代码存在或“判定一致”不是实际输出。工具 API 按需读 [工具手册](tooling.md)，纯聊天直接执行以下步骤。

## 每次验收的执行顺序

1. 恢复唯一当前规则及 revision/来源，列全将执行或引用为当前证据的案例/契约。完整读每份契约，核其分组/范围、全部排序键/方向/未知规则、必需字段与当前规则一致。历史只作历史引用；仍需验收的案例先同步，不靠移历史删掉。
2. 本例记录规则引用、当批参数及来源，先完成计算、真实分类、排序、投影并给出实际输出。补充案例也有自己的输出块/文件；纯聊天可直接引用本轮已给出的章节和行。
3. 分别比较逐字段/合计、分类、组序、每键方向、相邻优先级、受限清理/允许保留及修改/续接/下一批。每条填 `来源事实/位置 → 独立预期 → 实际字段/行位置 → 相符或不符`，先记录事实，后求前提，最后填状态。
4. 逐项保存 `当前规则匹配 | 实际结果正确性 | 分支触发状态`，摘要仅从这些结果生成。新案例通过不改变原例状态；原例正确字段/分类仍保留，不能因排序未触发全抹掉。

规则不符先修当前产物/契约；证据缺失、不支持、明确矛盾分开记。未执行、无实际结果或未触发为 not_run，触发而不符为 fail；规则当前且前提成立、实际相符才为该分支 pass。保留原 not_run/fail，补合法输入并全流程重验；可执行所需检查不能删分支、缩声明或以未测结案。

## 分支比较

### 具体行对先于排序结论

| 分支 | 先填写左右事实，再求前提 | 核实际交付 |
|---|---|---|
| 第 k 键方向 | 原位置 i<j；两行真实组相同；此前每键左右值相等；当前键均已知且不同，按方向应让后输入行在前 | 输出位置确实反转；身份/分类/必要字段正确 |
| k 优先于相邻 k+1 | 两行同组，更早键相等；两相邻键已知，分别要求的先后相反 | 实际服从第 k 键 |
| 组序 | 两行真实分类及原位置，原组序与约定相反 | 分类正确，实际按组序排列 |

不要只填“同组=true”，保留可回核的左右值/来源。主键无前键时该项不适用，其余照查。每键方向和每对相邻优先级分别验：单例/跨组/已正序/空值位置不证明有值方向，两键同向不证明优先级；主键已正序的冲突对可证明优先级，方向仍需独立反序对。

先找合法现有行对；缺少则单列补充案例，可复制合法行后反转输入，原输入次序/事实/固定请求不改。次键方向固定前键，优先级选合法冲突键值，派生键由有效底层字段生成。所有案例全流程处理，不假定同组或只跑排序函数。合法域确不可达须有规则依据，不因本例没触发就称不适用。

核行序从最高键逐一比：已知不同即决定，相等才看下一键，仅当前键未知才用其有效规则。后键未知不抹已知主键；普遍排序覆盖全适用组，保留有效例外，不擅用旧默认豁免异常组。日常单例可正确，但不能声称验证了方向/优先级。

### 异常分支见证与自检

正常案例通过不证明异常出口。当前规则里每个异常出口（越界值→未知、同实体冲突保留、缺失字段、自由文本受限片段、数据中的命令等）各列一条分支：`触发条件 → 见证行（原输入位置）→ 预期展示 → 实际位置`。无见证行为 not_run，不得写通过；数据没有就补合法见证并完整重验。

生成技能自带的自检/脚本必须：（1）输入含触发每个异常出口的行；（2）断言实际展示内容（未知位、行号、原始数量、普通备注），不只数数字或匹配关键词；（3）用已知坏产物验证自检会拒绝，并且是**完整矩阵**而非一两类：把变异体写成 `matrix.json`，用 `scripts/mutation_matrix.py` 运行（基线须通过、每个变异体须被拒）。
   类别集合由 `assets/mutation-profiles.json` 的规范档案决定（表格交付、冲突交付、物理行号、需求追溯、受限范围），矩阵用 `profiles` 声明适用档案；作者不得自行缩小集合，确实不适用的类只能写 `not_applicable` 加书面原因，且该原因须人读复核。。
   覆盖包括：越界值原样/补零、非法日期原样、自身合法值被改未知、漏原始数量/备注、行号错位/取结束行/取记录序号/忽略空行、漏版本/实体、顺序颠倒、丢行、分组错、规则弱化/删除/范围收窄、受限片段在物品/备注/提醒中漏清理、误删普通内容、残留裸数字；变异体存活或缺类即自检不通过；（4）自检首次通过后仍通读完整交付物，不以脚本通过替代。可直接参照 `scripts/run_anomaly_selftest.py` 与 `assets/fixtures/anomaly/` 的矩阵做法。

### 工具或等价人工路径

Python 可用运行结构 audit 和可用宿主验证器；格式、互斥分组、类型化排序及未知规则受支持时，按 [工具手册第 1 节](tooling.md#1-audit-与表格检查) 运行实际产物 checker。当前案例引用同一当前规则，核真实报告中的规则/契约/实际产物身份和规则绑定；只验证内联声明的旧结果不证明当前同步。checks 全真不等于 branches 全过。

保存 stdout、真实退出码和哈希。error 修契约/格式，fail 修实际产物，not_run 补见证，随后重验，不把可修错误称无工具。能直接解析实际表就直接检查；派生 actual 文件须能逐行回到真实交付，不能写输入重算结果冒充。优先原输入或允许字段安全事实投影；确无合法必要事实通道仅该部分写具体不支持原因并同等核对，其余支持检查继续，不擅存受限值。

纯聊天或明确超出能力的部分用同一行对表/可核查等价代码；不伪称文件、代码或独立模型执行。需要的新案例仍完成实际文本处理。结构成功不替代业务检查，规则哈希绑定也不证明来源语义正确。

## 全部当前产物和字段

保存后完整读受影响入口/必读资源/模板/样例/约定/验证及拟发送回复，不只读 diff 或摘要。逐产物回到 [当前规则](synthesis.md) 核字段许可与适用限制；内部标签/文件名/可写权限不替代真实私有授权，保留例外不跨字段/产物扩张。

- 计算核源值/单位、逐行公式/逆算、纳入集合、行数/所需小计总计及独立等价式。未知不补零，分类未知仍保不依赖它的允许结果。
- 对每个视图及异常出口核 `应保留字段 − 实际字段` 为空或有来源例外，并核值正确；正常/异常从同字段集合派生，原因不替代原字段。至少一个适用异常例同时有未知与可靠字段，核已知部分仍交付，不把所有输入列强加到输出。
- 正文/表格/代码/文件附件/记录/历史摘录/新测试输入/样例/验证/结尾都查：按上下文清完整受限表达，保合法姓名/编号/日期/普通数值/备注/派生值，不删整列或拒绝整批求通过。
- 记录只组装规则/安全来源引用、实际已处理输出的允许字段/位置、前提/比对结果。symbolic 只含字段名/变量关系/允许常量，不代入实例或合成值；证据仍可回核，不在“不含”清单枚举受限值，不从输入补出实际没有的字段。
- current/applied、入口和必读资源一致，失效项退出当前并标替代；answers/历史/扩展保留原位。历史按当时边界判，当前不重抄受限旧答案、不恢复旧规则、不把旧通过称新版执行。

[原始工具产物与最终交付](artifact-contracts.md) 分别保存/判定；手工修正只记原始失败、最终修正后通过，不追认脚本成功。读输入/运行/写出失败分开，stdout/函数降级如实记。新内容返回生成与比较，摘要仅取已核产物和状态。

## 独立实验与结论

制作链与下游链分别合格：规则写对不抵销作者样例/自评错误，一批通过不覆盖别批；指定模型使用同一冻结版，不拼接候选通过项。

按 [覆盖设计](coverage.md) 事前固定范围/次数/阈值。真实常规输入加有价值的关键缺失/冲突、同义触发/相邻非触发、修改/冷续接/下一批、独立重复/留出。读材料加注入，外部动作加权限/恢复，文件交付加实际打开/渲染/可编辑；不机械加全类别，不事后排除失败维度。

记录模型/版本、宿主/工具/依赖、技能/案例版本与哈希、日期、执行者、加载方式。每 case×round×variant 新上下文开始，案例内各轮连续，turn 不等于独立 round。执行者只得冻结技能/当前请求/材料，不得作者预期/评分/修复反馈或未来轮；候选不接触留出答案。可匿名盲评并随机顺序，不可盲如实记。

基线仅不加载目标技能，其他输入/工具/技能相同并记录，不能跑不补造。逐轮保助手原文，完整对话/工具轨迹另留；相同哈希不能证明来源或独立会话。suite/逐轮文件/哈希/汇总软件用法见 [工具手册第 3—5 节](tooling.md#3-实验设计与独立性)；无工具同样记来源/轮次/独立性，不假造文件。

每例至少一项可观察断言，关键事实/授权/伪报成功为关键项，不用“优质”或照抄作者答案。真实执行、全部适用断言有证据、关键项全过且满足事前标准才通过。未执行/受阻/缺人工证据不算成功或移出分母；分报计划、执行、阻塞、待执行、已判定、通过、关键失败、缺证据，注明通过/已执行与通过/全部计划。

只对同 case/round 两组真实配对比较规则正确、错误放行、无谓退出、澄清及实采耗时/成本，未采写未测。基线失败不自动否定候选，候选单测不证明更优，小样本不称显著。结构可读/材料保真/行为/自动发现证据各有范围，有限样本不保证未来输入或任意模型。

保失败/来源/版本/独立审阅，修最小根因后重跑失败/变体及至少一个成功代表例；范围改动查触发反例，关键通用规则改且要求完整矩阵则重跑矩阵。同步追溯、重做结构审计再更新结果，新范围/模型/工具不沿旧通过。默认每例 2 次独立实验、连续修复最多 3 轮，可调整，不强加日常；关键失败或必要未完成保持 candidate，达标仅 validated-in-scope。修验证器须旧坏产物仍被拒，不放宽断言求全绿；计划/模拟/示例不是实测。

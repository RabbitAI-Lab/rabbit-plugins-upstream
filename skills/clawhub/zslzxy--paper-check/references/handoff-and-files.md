# 交接、附件与异步续接

## 为什么必须由选定 lane 上传

维普、万方和知网的文件格式、计价、订单和供应商流程不同。统一 Skill 可以理解用户意图，但必须在确定 lane 后才调用对应产品接口；不能用一个通用 `provider` 参数代替产品路由。

## 用户已经提供文件

1. 优先复用对话附件，不要求用户重复发送。
2. 只有能读取附件原始字节时才提交；仅有文件名、摘要或不可访问链接时不要创建任务。
3. 用户选定系统后，使用本 Skill 的 Python 客户端调用对应 lane 的 multipart 或 prepare/PUT/start 流程。
4. 若平台无法读取附件原始字节或不能执行 PUT，透明告诉用户客户端能力限制；不要创建空任务或声称文件已提交。

## 浏览器交接

产品接口返回的链接打开该 lane 配置的现有用户端页面，而不是 Agent 专用页面。不同 lane 可以配置不同域名和路径。客户端只能使用服务端返回 URL，不能把某一产品域名当作所有业务界面的域名。

## 续接原则

- 有 `order_no`：调用对应 lane 的 `status` 或 `report`，不能切换 lane。
- 只有 `browser_url`：直接把链接重新给用户，不从 URL 中解析或猜测内部状态。
- 没有任务标识：回到产品选择或重新准备，不伪造令牌。
- 过期：停止使用旧任务/上传票据；只有用户仍要继续时才按原意图重新准备。
- 同一意图的准备/提交调用发生网络超时：用原 `client_request_id` 重试，避免重复创建。

# Typhoon Tracker - 报告模板与格式指南

当 SKILL.md 的"文件模式"触发时，加载此文件获取完整的报告结构、标记约定和命名规则。

## 报告结构模板

文件模式生成报告时遵循此结构，按需增删章节。

```markdown
# [台风名] - [主题]

> **生成时间**
> YYYY年M月D日 HH:MM CST
>
> **数据截止**
> [来源] + [时间]
>
> **信息来源**
> [逗号分隔的来源列表]

---

## 核心结论

[要点，<200字，关键发现优先]

---

## 1. 台风最新实况
[表格：位置、风速、气压、移向、移速、风圈半径]

## 2. 路径预报与登陆预测
[表格：预报时次 vs 登陆时间/地点/强度，含变化列]

## 3. 对[城市A]的影响
### 3.1 官方预报
### 3.2 逐时段风雨推演
[表格：时段 | 降雨等级 | 风力(地面) | 风力(高度修正) | 置信度 | 来源标记]

## 4. 对[城市B]的影响（如有）

## 5. 交通影响评估
[表格：铁路、地铁、航班、高速]
[⚠️ 必须区分：已发布（官方公告+时间）vs 预警（官方提示≠取消）vs 预测（预计时间窗+依据+置信度）]
[每条标注核实时间，如"核实于8月7日09:17"]

## 6. 活动可行性评估（如有）
[评估维度，每个活动给出明确结论]

## 7. 防御准备与行动清单
[按优先级排序的表格]

## 8. 不确定性与复查计划
[哪些不确定，何时复查]

## 关键信息源
[表格：来源 | 获取方式 | 用途]

---
```

## 标记约定

- `[官方]` = 官方气象/交通机构直接发布（事实）
- `[官方预警]` = 官方发布的预警/出行提示，但未宣布停运等具体措施（≠事实）
- `[推断]` = 基于模型推演或历史规律的预测，非官方发布（**必须用"预计/可能"语气，禁止写成事实**）
- `[官方+推断]` = 官方发布与推断结合（需分别标注哪部分是官方、哪部分是推断）
- `⚠️` = 高风险/危险时段标记
- `🔴 🟠 🟡 🟢` = 风险红/橙/黄/绿四级
- `✅ ⚠️ ❌` = 可行性判断（可行/注意/不可行）
- `⚡` = 突发关键更新标记

**关键规则——交通停运信息（高铁/航班/地铁）必须严格区分：**
- 已发布停运 → `[官方]` + 注明公告机构和时间
- 官方预警/出行提示 → `[官方预警]`（明确注明"≠取消"）
- 预测将停运 → `[推断]` + `预计/可能/大概率` 语气 + 标注依据和置信度
- 每条交通状态必须标注**核实时间**（如"核实于8月7日09:17"），让用户知道信息新鲜度

## 文件命名规则

**手动触发（文件模式）**：
```
台风名_日期时间_主题简述.md
示例：台风白海豚_8月8日14时_登陆前研判.md
```

**定时任务自动触发**：
```
台风名_月日时分_研判.md
示例：台风白海豚_0808_1400_研判.md
```
如同一小时内生成多份（罕见）：`台风白海豚_0808_1400_第2次研判.md`

**命名设计原则**：
- 定时任务用数字月日时分（0808_1400）便于按文件名排序
- 手动触发用中文日期（8月8日14时）便于人工阅读
- 文件名无空格，用下划线连接，控制在40字以内

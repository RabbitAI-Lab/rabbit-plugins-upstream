# 近海热带系统动态跟踪协议（Nearshore Tropical System Protocol）

> **定位**：本文件为**条件触发的参考协议**（非 SKILL.md 本体）——仅当满足触发条件时加载执行。设计原则：SKILL.md 保持精简与单一职责，近海热带系统（尚未成名的弱/未编号系统）的动态跟踪方法论独立存放，详细内容按需加载。
>
> **来源**：2026-08-22 杭州晨报漏报"东海热带低压"案例——用户追问后发现该低压(20260022)在数小时内升级为第 20 号台风简拉维(2620)并实登陆福建，而晨报因紧盯编号台风沙德尔而轻视了近海扰动。本协议固化"近海未编号/弱编号系统优先级"规则，堵住追踪盲区。

## 触发判定

以下条件**任一满足**即加载执行本协议：

1. **CMA 台风网/公报提及有"热带扰动/热带低压/残余低压"靠近重点城市**（即使未编号）
2. **距重点城市 < 500km 存在未编号/弱编号的海上扰动或低压**
3. 多台风/多系统并立（多台共舞），需要判断"哪个系统对重点城市影响最紧迫"
4. 降雨异常但无法用已编号台风解释（可能为未编号近海系统所致）

**核心触发铁律**：**无论是否已编号，凡距重点城市 < 500km 的海上系统，其关注优先级 ≥ 远洋强台风。**（教训㉓：简拉维仅 8 级却触发山洪/海浪预警和铁路停运，优先级高于 16 级超强台风沙德尔）

## 连续谱识别（本协议的核心对象）

近海热带系统不是孤立的"扰动"，而是一条**连续升级/衰退链**，同一实体可沿链快速变化，须全程跟踪而非只看当下形态：

```
未编号扰动 → 热带低压(2026xxxx) → 热带风暴(编号+命名) → 强热带风暴/台风 → 减弱消散/停编 → 残涡
```

**实战案例（东海系统全链）**：2026-08-22 东海扰动 → 加强为热带低压 20260022（温岭东南480km）→ 6小时后升级为第20号台风简拉维（2620）→ 8/24 实登陆福建泉州 → 20时停编。**全程仅约 2 天，从一个"未编号扰动"到"实登陆台风"。**

**工程启示**：

- 8/22 晨报失误根因：该扰动距杭州<500km、CMA 已在公报提及，却因"未编号"被归入"偏东气流"一句带过
- 正确做法：把"距重点城市的距离 + CMA 是否有书面提及"作为关注阈值，而非"是否已编号"
- 残涡（停编台风残余）与本协议的同构性：残涡也是"已停编/无编号但可能实质影响"，两者可共用"如何跟踪无编号系统（多源反推）"的方法论——本协议与 SKILL.md 的"残涡追踪协议"联动，不重复建设

## 与相邻协议的关系（联动去重）

| 协议 | 位置 | 对象 | 与本协议的关系 |
| --- | --- | --- | --- |
| 残涡追踪协议 | SKILL.md 本体 | 停编台风的残余系统（可重组二次增强） | **同构**：都是"无/弱编号但可能实质影响"。本协议聚焦"未成名"的生成/近海阶段，残涡协议聚焦"停编后"阶段；两者共享"多源反推跟踪法" |
| 空窗期强对流协议 | references/empty_window_convection_protocol.md | 无台风时的季风槽/热对流 | 若近海系统发展成残涡或登陆后，其后续降雨研判有时转向空窗期协议 |

**通用"多源反推跟踪法"（残涡 + 近海扰动共用）**：

- 直接定位：查 CMA 台风网/省市气象台公报中的"热带低压/扰动"位置描述
- 间接反推：无直接定位时，用降雨落区/雷达回波反推（强降雨中心即低压水汽辐合区）
- 升级监测：是否出现闭合等压线/气旋性环流/对流云团组织化——出现即以"可能升格编号/增强"对待

## 权威背书弱时的信源处理（用户的顾虑）

近海未编号系统**缺乏权威媒体/官方公报的连续跟踪**（可能仅 CMA 台风网列表、数值模型、雷达提到），处理的信源边界：

- **信源层级调整**：未编号系统不适用 P0 官方台风公报的完整链条；可用的优先级 = CMA 台风网列表（P0，位置/是否升格）> 数值模型（P1b，ECMWF/GFS 路径）> 省市气象台预警（P1，间接体现影响）> 媒体提及（P2）
- **位置数据标注**：未编号系统的位置可能来自数值模型初始场或雷达，标注"据 CMA 台风网"或"据模式推测，待官方确认"，不写成官方定报语气
- **不确定性管理**：未编号系统强度/路径分歧更大，结论置信度上限降为"中"；标注"未编号，改编号后以官方定报为准"（教训⑱：热带低压升格后旧口径自动作废）
- **严禁**：把媒体"新台风来袭"类内容农场文章当信源（见 SKILL.md 假消息鉴别协议）——近海系统假消息高发，须三重否决核验

## 输出规范

- 报告中对近海系统无论编号与否，给出：系统类型（连续谱位置）+ 现位置 + 距重点城市距离 + **按距离排序的优先级** + 升级风险（是否可能升格/增强）
- 重点城市受影响评估时，先声明系统是否编号，避免按正式台风框架套用
- 铁律：**不要因为"未编号/弱编号"就在报告里降级呈现权重**——按对重点城市的实际威胁时效排序

## 案例推进

每次触发执行后：如该系统最终获编号（如 20260022→2620 简拉维），在 `references/gaenari_2620_case_data.md` 等对应案例文件记录"未编号→编号"的时间线与定性成功率；如未获编号，回到 `saudel_2618_case_data.md` 等主线案例记录被跟踪但未升格的低压。无专属案例文件时可记入最近活跃台风案例文件。

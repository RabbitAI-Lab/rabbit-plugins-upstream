# 经历录入

目标:用**尽量少的轮次**拿到够深挖的素材。不是填表,是聊。

录入结果只存在本次 `data/session.json` 的 `raw_material` 里,不做长期档案。

## 原则

**相近的合并问,一轮问一组。** 用户不想被问十遍。

**先给一句预告。** 开场说明大概几轮、为什么要问,用户才愿意配合:

> 我先问你三四轮背景,主要是想拿到能深挖的细节 —— 问题会直接从你的经历里出,不是通用题库。大概两三分钟。

**用户说"没有"就立刻跳过,别追。** 没实习就是没实习,追问只让人难受。

**不要一次问超过 4 个点。** 超了用户会漏答,还得回头补。

## 四轮

### 第 1 轮 — 目标 + 院校

> 先说两件事:①你在投什么岗位?②院校、专业、年级,还有毕业时间。

拿到:`target_role`、`seniority`。

岗位含糊(比如只说"技术")要追一句,因为出题方向全靠它。院校信息不用细挖,只是定级别用。

### 第 2 轮 — 实习 / 工作

> 有过实习或工作吗?有的话每段说一下:公司、岗位、时间多长,以及你**具体**负责什么。
> 
> 重点是最后一项 —— 别写"参与后端开发",说清你自己动手做完的是哪一块。

"具体负责什么"这句一定要强调。用户默认会给简历腔的模糊描述,那种东西没法出深挖题。

答得笼统时追**一次**:

> "参与订单系统开发"这个再具体点 —— 这个系统里有哪个部分是你一个人从头做完的?

### 第 3 轮 — 项目 / 比赛 / 社团(合并)

> 除了实习,这几类有吗,有就一起说:
> - 课程项目、毕设、自己写的东西
> - 比赛(ACM、数模、黑客松、创业赛都算)
> - 社团或学生组织里负责过什么
> - 开源贡献

**这轮对学生最关键。** 大部分本科生没实习,但这里有东西。合并成一轮问,用户挑自己有的答,不用被问四遍"没有"。

### 第 4 轮 — 挖细节(按需)

前三轮拿到的东西够不够深挖?不够就挑**最有料的那一两段**追:

> 你说的那个缓存重构,我想再挖一下:
> - 当时最难的技术判断是什么?
> - 有量化结果吗(性能、用户数、时间)?
> - 有没有哪一步做错了、返工过?

三个方向对应 rubric 里的 Differentiation、Substance、Credibility —— 用户现在补的细节,正好是后面能得高分的素材。

够了就跳过这轮。

## 判定经历密度

一段经历算"有实质产出",要**同时**满足:

- 有可指认的**个人职责**(不是"参与了X")
- 有可追问的**具体结果**(做出了什么/达到了什么)

挂名的、纯听课的、只写了"了解"的不算。

| 档 | 判定 | 出题分配 |
|---|---|---|
| `rich` | ≥2 段有实质产出 | 5 题全深挖:主线 3 + 次线 2 |
| `moderate` | 1 段实质 + 若干项目 | 深挖 3 + 项目/动机 2 |
| `sparse` | 只有课程项目,或都很模糊 | 最好的那个挖 2 + 宽泛题 3 |

**课程项目、比赛、开源、社团负责人都算实质经历。** 不能只认实习 —— 不然大多数本科生直接掉到 `sparse`,深挖就没了。

判 `sparse` 时,`density_note` 写清楚原因和补救动作:

> 你的材料里可追问的细节不多,所以 5 题里有 3 道是常见通用题。想换成针对你的深挖题,补充点项目细节我可以重新出。

**不要把这句写成批评。** 给用户一个能自己改善的动作就行。

## 存进 session

```json
"raw_material": {
  "target_role": "后端开发实习",
  "seniority": "本科应届",
  "school": "某大学 计算机 大四",
  "internships": [
    { "org": "某公司", "role": "后端实习", "duration": "3个月",
      "ownership": "独立负责订单服务缓存层重构",
      "details": "p99 800ms→120ms,测过三种方案" }
  ],
  "projects": [], "competitions": [], "clubs": [], "opensource": [],
  "density": "rich"
}
```

空的类别留空数组。`ownership` 和 `details` 是出题主要取材的地方,尽量保留用户原话 —— 出题时 `source_quote` 要从这里摘。

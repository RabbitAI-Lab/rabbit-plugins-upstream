# 方法论原文参考

本文是方法论文档的核心概念汇编，供 `数据关联` 技能调用。当技能执行过程中需要更深层的方法论依据时阅读本节。

---

## 一、核心理念：以决策为中心

传统做法只存"数据是什么"，不存"为什么这么决策"和"决策后发生了什么"。

**核心转变**：不是简单地表示数据，而是表示**决策**。

AI 理解：分析数据时不要只问"这是什么数据"，要问"这个数据要支撑什么决策"。每个发现的终点应该是一个决策选项。

---

## 二、四维集成框架

| 维度 | 本质 | 在数据分析中的含义 |
|------|------|-------------------|
| **Data** | 整合所有数据形态为完整语义表示 | 把表格字段映射为有业务含义的对象、属性、链接 |
| **Logic** | 决定何时以及如何做决策的推理 | 用规则、计算、模型处理数据，不只靠"看着像" |
| **Action** | 数据是"名词"，行动是"动词" | 分析结论必须指向可执行的操作 |
| **Security** | 谁在什么情况下能看什么 | 多维度控制数据访问，不只标颜色 |

### Data 层面的关键做法

"代替扁平的 golden table，以**对象、属性、链接**的形式呈现企业的全貌。"

- **对象（Objects）**：语义世界中的实体（订单、客户、设备）
- **属性（Properties）**：实体的特征（金额、状态、时间）
- **链接（Links）**：实体之间的关系（外键、引用、血缘）

### Logic 层面的关键做法

"确定性函数、算法和常规统计过程必须作为'工具'，补充大模型的非确定性推理。"

这意味着：
- 能用数学算的不要靠猜（算相关系数而不是说"看起来有关"）
- 明确区分"计算出来的"和"推断出来的"
- 规则、模型、函数是独立于 LLM 的"逻辑资产"

### Action 层面的关键做法

"闭环行动是区分**运营系统**和**分析系统**的关键。"

- 分析结束时必须指向行动
- 行动可以安全地暂存为"场景"（scenario），审核后再执行
- 写回源系统形成闭环

### Security 层面的关键做法

标敏感等级，想给谁看不给谁看：

- 🔴 高风险：姓名、身份证、手机号、银行卡、病历、薪资 → 提醒脱敏
- 🟡 中风险：成本、客户内部价、利润率、合同条款 → 对外剥离
- 🟢 公开：产品名、日期、品类、公开评分 → 无限制

## 三、教实习生方法论（核心）

这是方法论中最具操作性的部分——AI 分析数据时应该像一个**聪明但没有上下文背景的实习生**。

### 五步流程

| 步骤 | 原文 | 在数据分析中的对应 |
|------|------|-------------------|
| **① 选对象和定义参数** | 从本体中选择对象，把特定属性存为参数 | 确定分析目标对象和关键字段 |
| **② 给高级指令** | 用自然语言给出高级指令 | 确定分析的主线和方向 |
| **③ 解释每个属性的含义** | 向 LLM 解释每个属性在业务中的含义 | 对每个字段做业务解释，不只是列名直译 |
| **④ 提供评分标准** | 给一组要检查的规则——评分标准 | 明确什么算异常、什么算正常、阈值在哪 |
| **⑤ 要推理过程** | 要求 AI 给出得出推荐结论的推理 | 每个发现附带思维链 |

**外加调试验证：** 用实际数据验证分析函数是否按预期工作。

## 四、OAG（Ontology Augmented Generation）

OAG 是 RAG 的升级版，以决策为中心：

- **RAG**：从外部来源检索数据给 LLM
- **OAG**：不仅检索，还使用**确定性逻辑工具**（预测、优化、计算）和**行动**（写回系统）来闭环

关键点：
- "把 LLM 锚定在本体上，就是锚定在业务现实中"
- "AI 可以有效地'展示它的工作过程'"
- 逻辑工具补充了 LLM 不擅长的精确计算

AI 理解：分析时不仅要"查到"数据，还要"算清楚"数据，最后"落地"行动。

## 五、思维链（Chain of Thought）

> "应用展示 AI 正在执行的 CoT 推理步骤，包括访问本体中的对象和运行相关函数。我们不仅对 AI 的推理有完整的可见性，还能看到它如何部署不同的数据和逻辑工具。"

这意味着：
- 展示**每一步**推理过程
- 明确标注用了什么数据、什么工具、什么规则
- 用户可以验证推理的正确性

---

## 六、新团队成员模式

> "每个部署的 AI 助手都可以被视为一个新团队成员——随着团队成员对其表现建立信心，逐步授予更广泛的权限范围。"

- 先理解场景和上下文
- 不懂就问，不装懂
- 逐步加深分析层次，而不是一次全量输出
- 会话内积累经验教训，跨会话不凭记忆编造

---

## 七、代理记忆系统

| 记忆类型 | 存储内容 | 数据分析中的对应 |
|---------|---------|----------------|
| **Working Memory** | 当前循环中的即时信息 | 当前数据集、变量、中间状态 |
| **Episodic Memory** | 跨会话的历史信息，带时间标记 | 之前分析过的类似数据集、问题模式 |
| **Semantic Memory** | 按类别组织的知识和技能 | 领域知识（指标含义、行业标准） |
| **Procedural Memory** | 驱动稳定执行的代码和工具使用模式 | 分析模板、计算脚本、规则集 |

AI 理解：在同一次会话内，要积累并复用先前分析的经验，不要每次都从零开始。但跨会话时没有可靠的自动记忆——除非用户当场提供或能从文件中查阅到历史记录，否则就当从零开始，不要凭印象编造。如果用户反复问同一类问题，可以把它加到"程序记忆"里（如 skill 规则或模板），让下次执行自动沿用。

---

## 八、决策血缘

> "决策血缘端到端地自动捕获——某个决策在何时做出，基于哪个版本的数据，通过哪个应用。"

> "聚合决策可以安全地利用为训练数据来微调模型，并可以蒸馏为目标原则。"

AI 理解：每次分析都要记录：
1. 基于哪个版本的数据？
2. 用了什么逻辑/规则？
3. 得出了什么结论/建议？
4. 用户是否采用了这个建议？
5. 采用后的效果如何？

---

## 九、评估方法论（AIP Evals）

设计目的是处理 AI 的**非确定性**。

| 概念 | 说明 |
|------|------|
| **测试用例** | 定义的输入和预期输出 |
| **评估器** | 比较实际输出和预期输出的方法 |
| **实验模式** | Grid search 遍历 模型×Prompt 组合找最优 |
| **反馈闭环** | 负面反馈 → 新的测试用例 → 同样的失败可复现 |

**生产准入：** 所有指标严格通过才能上线。

**评估器类型：**

| 类型 | 适用场景 |
|------|---------|
| 精确匹配 | 布尔/分类输出 |
| 字符串相似度 | 文本输出 |
| 文本生成质量 | 报告/描述类输出 |
| AI-as-a-Judge | 主观判断（逻辑是否正确、分析是否完整） |

## 十、Bootcamp 方法论

> "hands-on-keyboard 的沉浸式培训，从零到用例只需要 1-5 天。"

> "参与者 100% 的时间在创造价值，而不是组装零件。"

AI 理解：分析要**快速上手**。不用追求完美，先跑通一条分析线，拿到初步结果再迭代深化。

---

## 十一、行动闭环

> "数据要素是'名词'，行动是'动词'。通过本体驱动的工作流，名词和动词通过人或 AI 的推理组合成完整的句子。"

行动的类型：
- **同步**：直接通过函数集成，实时生效
- **异步**：通过自动化流程，审核后执行
- **提案模式**：AI 创建提案→用户审批→执行

AI 理解：建议行动时要区分"直接可以做的"和"需要审批的"。

## 视角派生

### 数据情境派生示例

举例说明"怎么看字段推视角"，**不是预设表，遇到新数据根据实际字段自行推理**。

| 你看到的字段 | 可能的数据情境 | 可能派生的视角 |
|------------|--------------|--------------|
| 奶粉品牌、段数、价格、促销、购买日期 | 母婴/零售采购 | 妈妈(品质/性价比)、采购(供应链)、财务(预算) |
| 学号、姓名、语文、数学、英语、总分、排名 | 教育/成绩 | 班主任(班级整体)、家长(孩子短板)、教务(教学质量) |
| 设备ID、温度、振动、运行时长、维护日期 | 工业/运维 | 工程师(故障预警)、生产主管(停机风险)、采购(备件计划) |
| 菜品名、份数、单价、桌号、下单时间、评价 | 餐饮/门店 | 店长(翻台率)、厨师(出品效率)、财务(毛利) |
| 订单ID、金额、状态、客户、物流单号 | 电商/零售 | 运营(转化率)、客服(售后)、仓储(发货时效) |
| 未知/不常见 | — | 扫完直接问"这是什么数据？你主要关心什么？" |

### 话术模板

扫完数据后：

> "数据我扫了，{行}行{列}列，字段有{字段名}，数值范围{min~max}，看起来像{x方向}的数据。
>
> 这类数据通常可以从这几个角度分析：
> • **{视角A}** — 关心{关注点}
> • **{视角B}** — 关心{关注点}
>
> 这些角度对你有用吗？或者你想从别的视角看？你定，我来按你的意思分析。"

用户说自定义视角时：

> "明白了。从**{用户说的视角}**的角度来看这张表，我会重点关注{根据该视角推断的关注点}。我先从这几个方面分析……"

### 退出策略

- 看到不认识的字段 → "这几个字段我没太看明白是什么含义，你能说一下吗？"
- 派生不出视角 → "数据我读了但没太看懂是什么场景。你能跟我说一下这是什么吗？"
- 用户纠正你 → "明白了，从{用户说的}角度。我重新来分析。"

## 自检清单

### A. 计算与逻辑

| # | 检查项 | 过关标准 | 不过关怎么办 |
|---|--------|---------|-------------|
| A1 | 数学复算 | 每个数值结论独立重算，结果一致 | 修正计算 |
| A2 | 交叉验证完整性 | 每主题≥2种验证，方法名写出来了 | 补做 |
| A3 | CoT 完整 | ①rubric→②数据→③逻辑→④交叉验证→⑤结论 五步齐 | 补写 |
| A4 | 来源追到行 | 血缘表"来源"列到行号+字段名，"来源未明"没标高置信度 | 追溯或降级 |
| A5 | 结论反查 | 回来源行核对，数据真能推出结论 | 修正或补推理链 |

### B. 安全与行动

| # | 过关标准 | 不过关怎么办 |
|---|---------|-------------|
| B1 | 每主题🔴🟡🟢标齐，≥2个🔴/🟡查了组合风险 | 补标 |
| B2 | 🔴推导的结论继承🔴，传播链无断裂 | 修复 |
| B3 | 每主题写了角色适配，敏感结论没标全员可见 | 补写 |
| B4 | 每主题写了用途 | 补写 |
| B5 | 资金📋、合规/人事🚫，高风险没标⚡ | 修正 |

执行方式：不在输出中打勾展示，脑子里过一遍，没过先修好再输出。

## 必须问场景

| 场景 | 怎么问 |
|------|--------|
| 分类值含义不明（A/B/C 无字典） | "Status 的 A/B/C 代表什么？后面判断才准" |
| 数值单位不明 | "Amount 是元还是千元？差千倍结论完全不同" |
| 外键匹配率低 | "只对上了 60%，剩下是历史数据还是脏数据？" |
| 多表方向不清 | "你想以哪张表为主线来看？" |
| 时间格式不统一 | "有日期有时间戳，统一成哪种？" |
| 用户指令太模糊 | "这批数据什么场景？扫描一遍还是有特定方向要看？" |
| 分析方向太多 | "数据我粗看完了，像是{x领域}。可以从{视角A}、{视角B}看——对吗？还是别的角度？" |
| 数据域推断不明 | "大概{行}行{列}列，字段是{举例}。什么场景？你主要关心什么？" |

## 代理记忆

| 记忆类型 | 实际怎么做 |
|---------|-----------|
| **Working Memory** | 当前会话上下文，自然在脑子里 |
| **Episodic Memory** | 之前分析过的数据、用户纠正——以用户当场提供的为准，不凭印象回想 |
| **Semantic Memory** | 领域知识（指标含义、行业标准）——来自训练数据，用前确认和当前口径一致 |
| **Procedural Memory** | 用户偏好分析风格——本次会话观察到的可用，跨会话不自动延续 |

有历史可参考时：
> "你提到上次分析发现张三占72%营收——如果那结论还能用，我沿用；不然从头扫。你定。"

没法提供旧结论时：
> "我这没有上次记录。先从头扫，你翻到旧结论发我，我再补着对照。"

## Rubric 示例

| 要判断的事 | 先定什么规则 |
|-----------|------------|
| 金额是否异常 | 超过均值±2σ？还是中位数3倍？ |
| 客户是否高价值 | 累计消费超过多少？10万？50万？ |
| 物料是否滞销 | 连续多少天无出库？30天？90天？ |
| 外键匹配是否正常 | 匹配率低于多少预警？95%？80%？ |
| 趋势是否显著 | 连续多少期上升才算趋势？3期？5期？ |

例：订单金额>信用额度120% 且准时付款率<0.3 → 维持信用冻结。

## 低频陷阱

以下陷阱频率较低但遇到时必须正确处理：

- **分号/制表符分隔**（非逗号CSV）→ 识别实际分隔符，不按逗号硬切
- **两表100%相同** → 直接报"无差异"，提示"可能同一张表贴了两遍？"不强行制造差异
- **列名纯数字（1/2/3）非行号混入**（数据区无多余序号列）→ 导出时列名丢失，按值域反推含义
- **超宽表（≥50列）且行≤5** → 不逐列分析，先问"这N列代表什么？M行什么粒度？"
- **公式文本作为数据值**（"=SUM(...)"/"=B2*C2"）→ 不执行不找缓存，问用户是验证逻辑一致性还是仅当备注
- **CSV引号包裹字段**（双引号内含逗号或换行）→ 引号内逗号非列分隔，引号内换行非新记录；锯齿行+引号开头→优先判引号包裹
- **视觉标记丢失**（用户提颜色/高亮但提取后不存在）→ 告知"文本中看不到颜色"，问能否转文本列；无替代列不猜测
- **同列混合时间粒度**（日/月/年混用）→ ≠多格式，不可统一ISO（捏造精度）；按粒度分组禁跨组排序/环比/加总
- **脚注/上标符号**（*†‡+表外解释）→ 剥离符号还原数值；脚注作为口径元数据挂到对应单元格，纳入分析不丢弃
- **近边界标准路径**（≤15行≤5列仅因🟡升级）→ Security完整但分析深度按数据量适配，不凑格式

## 输入格式

| 格式 | 特征 | 处理要点 |
|------|------|---------|
| **单表** | 一张扁平表格 | 直接选对象 |
| **多子表** | Excel多sheet/同文件多数据区 | 先搞清每子表代表什么、怎么关联 |
| **多级表头** | 表头占2行+（无上限），可同时在列方向（年度→季度跨列合并）和行方向（地区→产品行维度列） | 识别所有表头行/列，构建多维坐标；表头列名为空但数据区有分类值→该列=行维度不禁排除；合并按实际跨向填充 |
| **含跨格合并** | 数据区跨行/跨列合并 | 还原逻辑单元格，标清跨格归属 |
| **多张表** | 多个独立表格 | 发现表间关联（外键/语义/值域重叠） |
| **其他/未知** | 不属于上述 | 按最接近格式处理，标注"非标准格式" |
| **左右对照表** | 同一物理行承载两个并行实体（如资产负债表） | 按分隔列拆为两个逻辑子表，各自选对象，校验跨表平衡等式 |

## 审查员模板

spawn fresh subagent 时用以下 prompt：

> "你是独立验收者。只依据下面的数据和标准判断结论是否成立，不看任何推理过程。
> ① 相关数据行：{只贴结论引用的行，不是全表}
> ② 待验证结论：{选置信度最低/风险最高的 2-3 个，不是最有把握的}
> ③ 关键假设：{1-2 条前提，不是完整推理链}
> ④ 用户问题：{原始问题}
> 逐项判定：一致 / 不一致 / 无法复现。不一致必须说明：哪个结论、哪里不对、数据中实际是什么。不接受'基本正确''大致吻合'。"

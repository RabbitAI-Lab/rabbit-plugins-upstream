# ToB SaaS合规矩阵与检查清单

本文档提供ToB SaaS产品在不同行业和地域的合规要求指南，用于PRD中的合规章节设计和合规评审。

---

## 一、数据隐私与保护法规

### 1.1 GDPR（欧盟通用数据保护条例）

**适用范围**：处理欧盟居民数据的任何产品

**核心要求**：

| 要求类别 | 具体要求 | PRD设计要点 | 检查点 |
|----------|----------|-------------|--------|
| 合法性基础 | 处理需有法律依据（同意/合同/法律义务等） | 明确数据收集的法律基础 | ☐ |
| 告知义务 | 隐私政策清晰透明 | 提供多语言隐私政策模板 | ☐ |
| 数据最小化 | 仅收集必要数据 | 定义每个字段的必要性 | ☐ |
| 目的限制 | 仅用于收集时声明的目的 | 用途限制的技术实现 | ☐ |
| 存储期限 | 不超过必要期限 | 数据保留策略设计 | ☐ |
| 准确性 | 确保数据准确及时更新 | 数据校正机制 | ☐ |
| 安全保护 | 适当技术和组织措施 | 加密、访问控制设计 | ☐ |
| 可问责性 | 能证明合规措施 | 审计日志设计 | ☐ |

**用户权利**：
- [ ] 访问权（数据副本）
- [ ] 更正权（修正错误）
- [ ] 删除权（被遗忘权）
- [ ] 限制处理权
- [ ] 数据可携带权
- [ ] 反对权
- [ ] 自动化决策相关权利

**触发条件**：产品涉及欧盟用户数据 → 强制GDPR合规审查

---

### 1.2 个人信息保护法（中国）

**适用范围**：处理中国境内自然人个人信息的产品

**核心要求**：

| 要求类别 | 具体要求 | PRD设计要点 | 检查点 |
|----------|----------|-------------|--------|
| 告知-同意 | 事前充分告知+明确同意 | 弹窗/邮件告知设计 | ☐ |
| 目的明确 | 明确、合理、与处理目的直接相关 | 数据处理目的清单 | ☐ |
| 最小必要 | 限于实现目的的最小范围 | 字段必要性论证 | ☐ |
| 安全保障 | 安全保护义务 | 技术安全措施设计 | ☐ |
| 敏感信息 | 生物识别、宗教信仰、特定身份等 | 敏感信息识别与加强保护 | ☐ |
| 跨境传输 | 个人信息出境安全评估 | 数据本地化方案 | ☐ |

**特殊规定**：
- 公共场所图像采集需显著标识
- 敏感个人信息需单独同意
- 14周岁以下未成年人信息需监护人同意
- 境内存储优先原则

**触发条件**：产品服务中国用户 → 强制个人信息保护法审查

---

### 1.3 CCPA/CPRA（加州消费者隐私法）

**适用范围**：处理加州居民数据且满足门槛（年收入/数据量）的企业

**核心要求**：

| 要求类别 | 具体要求 | PRD设计要点 | 检查点 |
|----------|----------|-------------|--------|
| 知情权 | 告知收集的个人信息类别和用途 | 隐私政策明确分类 | ☐ |
| 删除权 | 删除个人信息 | 数据删除机制 | ☐ |
| 不出售 | 有权拒绝个人信息出售 | "Do Not Sell"选项 | ☐ |
| 非歧视 | 不因行使隐私权而受到歧视 | 服务一致性设计 | ☐ |
| 敏感数据 | 敏感个人信息限制处理 | 敏感数据识别与保护 | ☐ |

**触发条件**：产品服务加州用户且满足门槛 → CCPA合规审查

## 二、行业特定合规要求

| 法规 | 适用范围 | 核心要求 | PRD检查点 |

| 金融行业网络安全 | 金融机构 | 数据分级分类、安全评估 | 数据分类设计 ☐ |

**关键设计要素**：
- [ ] 数据分级分类体系

- [ ] 完整操作审计日志
- [ ] 数据加密传输存储
- [ ] 灾备与业务连续性

### 2.2 医疗健康行业

#### HIPAA（美国健康保险流通与责任法案）

**适用范围**：处理美国受保护健康信息(PHI)的产品

**核心安全规则**：

| 规则类别 | 具体要求 | PRD设计要点 |
|----------|----------|-------------|
| 访问控制 | 唯一用户标识、紧急访问、自动注销 | 身份认证设计 |
| 审计控制 | 记录信息访问活动 | 审计日志机制 |
| 完整性 | 防止不当更改/销毁 | 数据完整性校验 |
| 传输安全 | 网络传输加密 | TLS/加密传输 |
| 设备与介质控制 | 介质处置、设备责任 | 数据销毁流程 |

**触发条件**：涉及美国医疗健康数据 → 强制HIPAA合规审查

#### 中国医疗健康数据

| 法规 | 核心要求 | PRD设计要点 |
|------|----------|-------------|
| 医疗健康数据安全 | 数据分级、脱敏、访问控制 | 数据安全设计 |
| 人类遗传资源 | 出境审批、国际合作备案 | 数据出境管控 |
| 电子病历 | 电子签名、存储期限 | 电子病历功能 |

## 三、信息安全标准

| 认证 | 适用范围 | 核心要求 | 适用场景 |
|------|----------|----------|----------|
| ISO 27001 | 全球 | 信息安全管理体系 | 通用安全认证 |
| ISO 27017 | 云服务 | 云服务安全控制 | SaaS产品推荐 |
| ISO 27018 | 个人隐私 | 云中个人信息保护 | 隐私敏感产品 |
| SOC 2 Type II | 美国 | 服务组织控制 | 企业客户信任 |
| CSA STAR | 云安全 | 云安全联盟评估 | 云服务商认证 |

### 3.2 安全设计检查清单

**身份与访问控制**：
- [ ] 多因素认证(MFA)支持

- [ ] 基于属性的访问控制(ABAC)
- [ ] 最小权限原则
- [ ] 会话管理与超时控制
- [ ] 密码策略与强度检查
- [ ] 账户锁定与解锁机制

**数据保护**：
- [ ] 传输层加密(TLS 1.2+)
- [ ] 存储加密(AES-256)
- [ ] 密钥管理服务
- [ ] 数据脱敏/掩码
- [ ] 数据分类分级
- [ ] 数据备份与恢复
- [ ] 数据销毁/擦除

**审计与监控**：
- [ ] 操作日志记录

- [ ] 输入验证与过滤

## 四、多租户SaaS特殊合规

### 4.1 租户隔离要求

| 隔离层级 | 技术实现 | 合规检查点 |
|----------|----------|------------|
| 数据隔离 | 租户ID字段、行级安全 | ☐ 数据查询过滤 |
| 应用隔离 | 独立Schema/数据库 | ☐ 跨租户访问禁止 |
| 网络隔离 | VPC/子网隔离 | ☐ 网络访问控制 |
| 资源隔离 | CPU/内存/IO限制 | ☐ 资源配额管理 |
| 管理隔离 | 独立管理后台 | ☐ 超级管理员权限 |

### 4.2 配置化安全边界

| 配置类型 | 安全考量 | PRD设计要点 |
|----------|----------|-------------|
| 系统级配置 | 影响所有租户 | 平台安全策略 |
| 租户级配置 | 影响单个租户 | 租户安全边界 |
| 用户级配置 | 影响单个用户 | 用户权限范围 |
| 配置继承 | 层级覆盖规则 | 配置冲突处理 |

## 七、合规风险等级评估

### 7.1 风险评级标准

| 风险等级 | 定义 | 示例 | 处理方式 |
|----------|------|------|----------|
| 🔴 极高 | 可能导致重大处罚/停业 | 无证经营金融业务 | 必须解决 |
| 🟠 高 | 可能导致显著罚款 | GDPR大规模违规 | 必须解决 |
| 🟡 中 | 可能导致警告/小额罚款 | 隐私政策更新滞后 | 限期解决 |
| 🟢 低 | 轻微违规风险 | 日志保留期限不足 | 计划解决 |

### 7.2 合规触发器

当PRD中检测到以下内容时，自动触发对应合规检查：

| 关键词/功能 | 触发检查 |
|-------------|----------|
| 支付/交易/转账 | PCI DSS + 等保三级 |
| 健康/医疗/患者 | HIPAA + 医疗数据安全 |
| 学生/教育/未成年人 | COPPA + 未成年人保护法 |
| 政务/政府/公共 | 等保四级 + 关基保护 |
| 跨境/海外/全球 | GDPR + 数据出境评估 |
| 金融/银行/保险 | 等保三级 + 金融业监管 |
| 征信/信用/评分 | 征信业务许可 |
| 人脸识别/生物特征 | 敏感个人信息加强保护 |

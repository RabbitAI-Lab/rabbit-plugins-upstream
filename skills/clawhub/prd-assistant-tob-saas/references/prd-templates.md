# PRD模板库 — ToB SaaS产品PRD AI助手

本文件包含三种核心场景的完整PRD模板，作为Skill生成PRD的结构参考。

---

## 场景一：独立新产品PRD模板

适用于：全新SaaS产品从0到1构建

### 1. 执行摘要
```
1.1 产品愿景（一句话描述）
1.2 核心价值主张（电梯演讲格式）
1.3 目标市场与规模
1.4 关键成功指标
1.5 资源投入与回报预期
```

### 2. 市场机会分析
```
2.1 行业趋势与政策环境
    - 技术趋势（Gartner Hype Cycle定位）
    - 政策法规（合规要求与机会窗口）
    - 经济周期影响

2.2 市场规模评估
    - TAM（总可触达市场）
    - SAM（可服务市场）
    - SOM（可获得市场）
    - LTV/CAC动态模型

2.3 客户画像与痛点
    - 决策链角色识别（经济买家/技术买家/用户买家）
    - JTBD场景化需求还原（人物/时间/地点/目标/手段）
    - 痛点优先级排序

2.4 竞品格局分析
    - 直接竞品功能对标矩阵
    - 间接竞品模式借鉴
    - 差异化机会识别
```

### 3. 产品战略定位
```
3.1 产品定位声明
3.2 目标细分市场选择
3.3 竞争策略（成本领先/差异化/聚焦）
3.4 商业模式设计
    - 定价模式（按席位/用量/功能/成果/混合）
    - 收入预测模型
    - 盈利路径与时间节点
```

### 4. 产品路线图
```
4.1 阶段划分
    - 探索期（0-12月）：PMF验证
    - 成长期（12-36月）：规模化扩张
    - 成熟期（36月+）：利润优化

4.2 里程碑设定
    - 业务里程碑（ARR/客户数/市场份额）
    - 产品里程碑（核心功能/性能/体验）
    - 运营里程碑（团队/流程/系统）

4.3 技术架构规划
    - 架构选型与评估
    - 扩展性设计（数据/功能/业务/租户）
    - 技术债务管理策略
```

### 5. MVP定义
```
5.1 P0功能清单（必须实现，3-5个核心功能）
5.2 P1功能清单（显著提升价值）
5.3 P2功能清单（锦上添花）
5.4 P3功能清单（明确排除）

每个功能需包含：
- 功能描述
- 价值论证（为什么必须做）
- 验收标准
- 降级方案（如果删减）
```

### 6. 产品需求详述
```
6.1 用户画像与场景
    - 角色定义
    - 用户旅程地图
    - 场景故事板

6.2 功能需求（逐个模块详细描述）
    - 模块概述
    - 用户流程（主流程/分支流程/异常场景）
    - 功能规格（输入/处理/输出）
    - 业务规则
    - 数据模型
    - 接口设计

6.3 非功能需求
    - 性能指标（响应时间/QPS/并发）
    - 安全与合规
    - 可用性与可靠性
    - 可扩展性
    - 多租户架构考虑
```

### 7. 运营与增长设计
```
7.1 客户获取策略（GTM）
7.2 Onboarding流程设计
7.3 客户成功指标与监控
7.4 功能采用率提升策略
7.5 扩展收入设计
```

### 8. 实施计划
```
8.1 依赖关系
8.2 时间表与关键路径
8.3 资源需求（人力/资金/基础设施）
8.4 风险评估与缓解策略
8.5 未解决问题清单
```

## 场景二：独立新能力PRD模板

适用于：现有产品上新增功能模块

### 1. 需求背景
```
1.1 业务痛点陈述（5Why分析）
1.2 需求触发背景
    - 提出者/提出时间/决策链
    - 优先级与紧急程度
    - 资源约束

1.3 成功指标定义（SMART原则）
    - 直接指标（功能使用率/完成率）
    - 间接指标（效率提升/NPS变化）
    - 业务指标（收入影响/留存率）

1.4 约束条件
    - 技术限制
    - 合规要求
    - 时间窗口
```

### 2. 竞品分析
```
2.1 竞品选择策略
    - 直接竞品（同一赛道功能对标）
    - 间接竞品（替代方案/跨界借鉴）

2.2 五维度分析
    - 功能覆盖与深度对比
    - 交互体验与易用性评估
    - 定价策略与商业模式
    - 技术实现与性能表现
    - 客户评价与市场口碑

2.3 差异化策略
    - 机会识别
    - 策略建议
    - 壁垒构建
```

### 3. 功能设计
```
3.1 功能概述
    - 功能定位
    - 目标用户
    - 核心价值

3.2 用户流程设计
    - 主流程（Happy Path）
    - 分支流程（Alternative Flows）
    - 异常场景与边界条件
    - 跨角色协作流程

3.3 功能规格说明
    - 输入定义（来源/格式/校验/默认值）
    - 处理定义（计算规则/状态变更/外部操作）
    - 输出定义（展示格式/存储位置）

3.4 业务规则与约束
    - 决策表（条件组合与行动映射）
    - 规则流（顺序执行的规则链）
    - 约束条件（不变量/前置后置条件）

3.5 数据结构与接口
    - 实体关系图（ER图）
    - 接口契约（请求/响应/错误码/版本）
    - 数据一致性策略
```

### 4. 非功能需求
```
4.1 性能需求
    - 响应时间要求（P50/P95/P99）
    - 吞吐量与并发能力
    - 资源利用率目标

4.2 安全与合规
    - 身份认证
    - 访问控制（RBAC/ABAC）
    - 数据保护（传输/存储加密）
    - 审计追踪
    - 合规要求（GDPR/行业监管）

4.3 可扩展性
    - 功能扩展
    - 容量扩展
    - 集成扩展
    - 多租户扩展

4.4 兼容性
    - 向后兼容
    - 向前兼容
    - 横向兼容
```

### 5. 实施计划
```
5.1 依赖关系
    - 前置依赖
    - 并行依赖
    - 外部依赖

5.2 里程碑与时间表

5.3 验收标准
    - 功能验收
    - 性能验收
    - 安全验收

5.4 未解决问题
```

## 场景三：现有能力迭代PRD模板

适用于：功能优化、性能改进、体验提升

### 1. 问题诊断
```
1.1 用户反馈分析
    - NPS拆解（Promoters/Passives/Detractors）
    - 主题聚类与情感分析
    - 反馈与功能关联映射

1.2 使用数据分析
    - 功能采用率
    - 使用频次与深度
    - 漏斗转化分析
    - 流失节点识别

1.3 客服工单分析
    - 问题分类与趋势
    - 根因聚类
    - 解决成本评估

1.4 竞品对标差距
    - 特定功能深度对比
    - 体验差距描述
    - 可借鉴设计模式
```

### 2. 优化机会识别
```
2.1 影响-投入矩阵分析
    - 高影响低投入（优先处理）
    - 高影响高投入（专项规划）
    - 低影响低投入（批量处理）
    - 低影响高投入（搁置/放弃）

2.2 技术债务评估
    - 代码复杂度
    - 性能衰减趋势
    - 维护成本增长

2.3 优化目标定义（SMART）
    - 核心指标
    - 观察指标
    - 应急预案
```

### 3. 迭代方案设计
```
3.1 方案概述
3.2 详细设计
    - 流程优化
    - 界面调整
    - 性能改进
    - 规则变更

3.3 A/B测试设计
    - 实验单元
    - 随机化方法
    - 样本量计算
    - 实验周期
    - 提前终止规则

3.4 灰度策略
    - 阶段划分（内部→种子→10%→50%→100%）
    - 准入标准
    - 观察指标
    - 熔断机制
```

### 4. 上下游影响评估
```
4.1 上游依赖
    - 业务需求变更同步
    - 数据与权限依赖检查

4.2 下游影响
    - 前端界面调整
    - 后端接口变更
    - 测试用例更新
    - 运营文档与培训材料

4.3 跨团队协作
    - 需求预审机制
    - 变更通知机制
    - 风险评估与升级
```

### 5. 发布计划
```
5.1 版本规划
    - 版本命名（语义化版本控制）
    - 迭代周期

5.2 发布策略
    - 功能开关设计
    - 灰度比例
    - 回滚策略
    - 应急预案

5.3 发布前检查清单
    - 功能完整性验证
    - 性能与压力测试
    - 安全审计
    - 文档就绪确认

5.4 发布后跟踪
    - 核心指标监控
    - 客户反馈响应
    - 效果复盘
```

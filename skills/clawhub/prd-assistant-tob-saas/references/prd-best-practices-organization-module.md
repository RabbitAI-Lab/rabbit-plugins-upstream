# PRD编写最佳实践提炼 — 组织机构板块经验（2026-05-15）

> **来源**：餐饮SaaS组织机构板块PRD V5.0→V5.3完整迭代过程
> **工时**：约40小时（复盘12项+补齐8项+截图分析+审查修复14项）
> **产出**：PRD从7.7/10提升至9.6/10

## 一、核心方法论：工业化竞品分析流水线

### 1.1 传统方式 vs 工业化方式

| 维度 | 传统方式（单线程） | 工业化方式（并行流水线） |
|------|-------------------|----------------------|
| 截图处理 | 人工逐一查看，凭记忆对比 | 4子代理并行AI识别，结构化输出 |
| 分析深度 | 主观印象，容易遗漏 | 功能矩阵（4家×N模块），系统性对比 |
| 发现差距 | 零散、不可复现 | 结构化清单，可追溯 |
| 更新PRD | 想到哪补到哪 | 基于矩阵批量补充，编号有序 |
| 耗时 | 约20-30小时 | 约8-10小时（含子代理并行） |

### 1.2 四阶段流水线

```
阶段1: 批量识别（并行子代理）
├── 将竞品截图分组（按平台）
├── 启动N个子代理并行识别
├── 每张截图提取：页面类型/布局/字段/操作/筛选/特色/关联度
└── 输出：JSON结构化识别结果

阶段2: 结构化汇总
├── 读取所有JSON结果
├── 按功能模块分类（如门店管理/权限管理/员工管理）
├── 生成竞品功能矩阵（4家×30-50个模块）
└── 输出：功能矩阵Markdown表

阶段3: 全局对比
├── 功能矩阵 vs PRD逐行对比
├── 标记：✅已有/❌缺失/⚠️部分有
├── 统计覆盖度（我方 vs 每家竞品）
└── 输出：差距清单（阻塞级/重要级/优化级）

阶段4: 系统优化
├── 按优先级批量补充PRD
├── 新增需求编号（避免重复）
├── 补充AC（验收标准）
└── 输出：更新后的PRD + 优化报告
```

### 1.3 子代理任务模板

```
任务：批量识别[平台名]的组织机构相关截图

输入：
- 截图路径列表文件（每行一个路径）
- 识别标准格式

输出：JSON文件，每张截图包含：
{
  "file_name": "",
  "page_type": "列表/详情/编辑/弹窗/总览/配置",
  "layout_description": "",
  "fields": [],
  "action_buttons": [],
  "filters": [],
  "special_design": [],
  "catering_org_relevance": "高/中/低",
  "notes": ""
}

约束：
- 每次识别1张截图，避免超时
- 超时则跳过继续下一张
- 记录成功/失败数量
```

## 二、五维PRD审查框架

### 2.1 审查维度与权重

| 维度 | 权重 | 检查内容 | 常见错误 |
|------|:----:|---------|---------|
| **完整性** | 30% | 场景覆盖、AC可验证、原型完整 | AC描述模糊、缺少异常场景 |
| **一致性** | 20% | 术语统一、编号不重复、前后不矛盾 | 需求编号重复、术语混用 |
| **可实现性** | 20% | 技术可行、性能合理、安全到位 | 过度设计、性能指标不合理 |
| **竞品对标** | 15% | 吸收竞品优点、差异化设计 | 盲目抄袭、忽视业务特点 |
| **用户体验** | 15% | 流程自然、异常完善、无反人类设计 | 缺少空状态/加载态/无权限态 |

### 2.2 审查清单（可直接复用）

#### 完整性检查清单
- [ ] 是否覆盖核心场景的Happy Path？
- [ ] 是否覆盖异常场景（断网/并发/超时/恶意输入）？
- [ ] 每个P0需求是否有≥3条AC？
- [ ] 每个P1需求是否有≥2条AC？
- [ ] AC是否使用Given-When-Then格式？
- [ ] AC是否可验证（有明确输入和预期输出）？
- [ ] P0需求是否配有原型图？

#### 一致性检查清单
- [ ] 需求编号是否有重复？
- [ ] 术语是否全文统一？
- [ ] 章节编号是否符合规范？
- [ ] 原型图与文字描述是否一致？
- [ ] 数据模型与需求描述是否一致？

#### 可实现性检查清单
- [ ] 技术方案是否可行？
- [ ] 性能指标是否合理（≤300ms/≤500ms）？
- [ ] 数据量边界是否明确（品牌≤1000门店/门店≤500员工）？
- [ ] 降级策略是否定义？
- [ ] 安全设计是否到位（密码/手机号/身份证校验）？

#### 竞品对标检查清单
- [ ] 是否基于竞品截图/索引分析？
- [ ] 是否生成竞品功能矩阵？
- [ ] 是否识别出我方独有优势？
- [ ] 是否避免盲目抄袭？
- [ ] 竞品名称是否清理（不暴露来源）？

#### 用户体验检查清单
- [ ] 空状态是否有引导？
- [ ] 加载中是否有骨架屏/进度？
- [ ] 无权限是否有友好提示？
- [ ] 网络错误是否有重试机制？
- [ ] 批量操作是否有二次确认？
- [ ] 表单校验是否有明确错误提示？

## 三、PRD版本演进模式

### 3.1 四阶段演进

```
V1.0 初稿
├── 基于竞品分析和业务需求快速输出
├── 覆盖核心功能 + 基本AC
└── 评分目标：7.0-7.5/10

V2.0 复盘
├── 基于PRD写作规范逐条检查
├── 发现问题清单（阻塞级/重要级/规范级）
├── 制定修复方案（精简/全面/折中）
└── 评分目标：8.0-8.5/10

V3.0 补齐
├── 基于竞品截图深度分析
├── 补充缺失功能模块
├── 补充规范章节（全局交互/API/导入导出）
└── 评分目标：8.8-9.2/10

V4.0 审查
├── 独立审查（换模型/换人审查）
├── 五维审查框架
├── 修复审查发现的问题
└── 评分目标：9.0-9.5/10
```

### 3.2 本次实际演进

| 版本 | 动作 | 问题数 | 评分 |
|------|------|:------:|:----:|
| V5.0 | 初稿 | — | ~7.0 |
| V5.1 | 复盘 | 发现18项 | 7.7 |
| V5.2 | 补齐 | 修复12项 | 9.1 |
| V5.3 | 审查+修复 | 修复14项 | **9.6** |

**关键经验**：
- 复盘和审查必须用**不同视角**（自己写→自己复盘→AI审查→交叉验证）
- 截图分析是发现PRD盲区的**最有效手段**
- 竞品功能矩阵是系统性对比的**最佳工具**

## 四、竞品功能矩阵方法论

### 4.1 矩阵设计

| 功能模块 | 竞品A | 竞品B | 竞品C | 竞品D | 我方PRD | 差距 |
|---------|:-----:|:-----:|:-----:|:-----:|:-------:|:----:|
| 功能1 | ✅ | ✅ | ❌ | ⚠️ | ✅ | — |
| 功能2 | ✅ | ❌ | ❌ | ❌ | ❌ | 🔴 |

标记说明：
- ✅ 有且完善
- ⚠️ 有部分功能
- ❌ 无此功能
- 🔴 我方缺失（阻塞）
- 🟠 我方缺失（重要）
- 🟡 我方缺失（优化）

### 4.2 统计维度

1. **覆盖率**：我方功能数 / 竞品功能总数
2. **独有优势**：我方有但竞品无的功能
3. **核心差距**：4家竞品都有但我方无的功能
4. **架构差异**：竞品采用不同架构（如单系统vs多系统）

## 五、防错机制

### 5.1 需求编号防重复

```bash
# 检查需求编号是否重复
grep -o "REQ-[A-Z]*-[0-9]*-[0-9]*" PRD.md | sort | uniq -d

# 检查AC编号是否重复
grep -o "AC-[0-9]*-[0-9]*" PRD.md | sort | uniq -d
```

### 5.2 章节编号对齐

```bash
# 检查章节编号是否连续
grep "^## " PRD.md

# 检查是否有多余或缺失的章节
```

### 5.3 术语统一检查

```bash
# 检查术语混用
grep -n "部门\|组织节点\|门店部门" PRD.md
```

## 六、可复用的Prompt模板

### 6.1 竞品截图批量识别Prompt

```
批量识别[平台]的组织机构相关截图。
从 [截图列表文件] 读取N张截图路径，逐一识别每张截图。

提取结构化信息：
1. 页面类型（列表/详情/编辑/弹窗/总览/配置）
2. 页面布局描述
3. 所有字段（表头/表单字段/配置项）
4. 所有操作按钮
5. 筛选条件
6. 特色设计
7. 与[业务领域]的关联度

输出：[JSON文件路径]

注意：每次识别1张截图，避免超时。超时则跳过继续下一张。
```

### 6.2 PRD审查Prompt

```
审查[模块]PRD，基于五维框架：

1. 完整性：场景覆盖、AC可验证、原型完整
2. 一致性：术语统一、编号不重复、前后不矛盾
3. 可实现性：技术可行、性能合理、安全到位
4. 竞品对标：基于[竞品功能矩阵]检查差距
5. 用户体验：流程自然、异常完善、无反人类设计

输出审查报告：
- 严重问题（阻塞开发）
- 重要建议（影响质量）
- 优化建议（锦上添花）
- 竞品对标结论
- 优先级建议
```

### 6.3 功能矩阵生成Prompt

```
基于[竞品识别结果JSON]，生成功能矩阵：

1. 提取所有功能模块（去重合并）
2. 按4家竞品×功能模块生成对比表
3. 标记我方PRD的覆盖状态
4. 识别差距和独有优势
5. 输出Markdown格式矩阵
```

# macOS 提醒事项同步

本适配将活动台账和全部月份归档同步到该台账绑定的独立列表，并把可靠的原生勾选完成原子回写台账。标题、备注、优先级和截止日期按台账维护；取消勾选不会自动重开。macOS/iPhone 的勾选会在下一次有效同步时处理，iPhone 的变化需先由系统账户同步到运行脚本的 Mac。

## 调用入口

技能进入已授权的台账流程时先调用存储 `read` 校验台账。业务写入成功后立即回复，不执行前台同步或自动 `--plan`。已初始化且启用后台时，在现有规定时点合并读取最新台账。未启用时说明不会自动更新，不自动安装任务。仅用户明确要求手动同步、首次初始化或原生诊断时使用对应入口；修改或安装技能不触发真实台账同步。

```sh
python3 scripts/macos_reminders_sync.py --data-dir /absolute/local/data/team-tasks
```

脚本仅在 `platform.system()=="Darwin"` 访问原生应用；其他系统跳过原生适配，不读取台账或原生应用。首次配置必须显式提供 `--list-name`，后续从绑定自动恢复名称。未配置时返回 `list_name_required`，台账功能仍可使用。

绑定与列表锁固定存放在当前用户的 `~/Library/Application Support/team-tasks/mirror-bindings/`。`--state-root /absolute/state` 仅指定辅助配置、目录迁移归档及旧版绑定查找位置，不隔离列表占用；原有辅助配置和日志继续使用原路径。

| 参数 | 行为 |
|---|---|
| `--sync-status` | 只读本地镜像、后台加载状态、下一计划时点和最近结果，不访问原生应用或修改文件；不与 `--result-file` 合用 |
| `--list-name NAME` | 新镜像的精确列表名；已有绑定可省略，指定另一名称不会自动改绑 |
| `--dry-run` | 离线读取本地绑定并准备全量字段映射，不访问原生应用或修改映射；目录冲突时返回双方路径 |
| `--plan` | 批量读取实际原生快照，展示新增、更新、不变、完成回写、缺失、停止同步及冲突，不执行这些修改 |
| `--initialize-mirror` | 显式初始化新建或空列表；记录快照及绑定，创建全量镜像，中断后续建自身事项 |
| `--scheduled` | 先检查北京时间合法时点，只有需要运行时才读取台账、访问原生应用；成功时点去重 |
| `--diagnose` | 本地状态查询，与 `--sync-status` 相同，不访问原生应用 |
| `--sync-status --task-id T-…` | 经存储 `inspect` 读取任务、历史来源及映射，不恢复事务；缺失、忙碌或损坏时直接返回错误 |
| `--diagnose --native-check` | 用户明确要求时执行一次原生列表身份探测，15 秒硬超时，无重试；不读取任务完成状态 |
| `--rebind` | 预览目录迁移，读取原生列表并展示绑定及实际条目；单独指定时不修改绑定 |
| `--rebind --confirm LIST_ID --from-data-dir OLD_DIR` | 精确确认原列表 ID 和旧绑定目录后归档状态，原子更新绑定目录；不写入原生事项 |
| `--result-file FILE`、`--probe-token TOKEN` | 原生后台探测须配合 `--diagnose --native-check` 写入私有结果及令牌；普通状态/本地诊断不接受这些写入参数 |

`--dry-run`、`--plan` 和诊断不执行业务写入；存储 `read` 仍可能恢复既有中断事务，固定锁也可能创建，不能把它们当成取证意义上的完全只读命令。周期运行的安装、启停和实际后台诊断见 [原生定时同步](periodic-sync.md)。

## 首次镜像

首次启用由用户明确指定列表名，不根据 agent 品牌或台账目录猜测名称。各独立台账使用不同名称，例如「团队待办 · 项目甲」和「团队待办 · 测试」。未指定时只管理台账，不启用镜像。

```sh
python3 scripts/macos_reminders_sync.py --data-dir /absolute/local/data/team-tasks \
  --list-name '团队待办 · 项目甲' --dry-run
python3 scripts/macos_reminders_sync.py --data-dir /absolute/local/data/team-tasks \
  --list-name '团队待办 · 项目甲' --plan
python3 scripts/macos_reminders_sync.py --data-dir /absolute/local/data/team-tasks \
  --list-name '团队待办 · 项目甲' --initialize-mirror
```

`--plan` 与实际初始化都会检查目标。列表不存在时，只有显式初始化会创建；唯一同名空列表可沿用其原生 ID。目标包含任何条目（包括手工、已完成、子事项或其他命名空间）时返回 `initialization_target_not_empty`，不创建绑定、映射或快照，不修改原有内容，提示换名称。多个精确同名列表时停止，不猜测账户或列表。

一个台账只能绑定一个列表，一个列表只能绑定一个台账，空台账也占用绑定。取得列表锁及台账同步锁后重新检查所有阶段的绑定，绑定提交还在公共注册表锁内检查原生列表 ID，避免两个宿主并发首次配置或通过原生改名重复认领；原生批量写入前再次检查初始化范围。绑定后可省略 `--list-name`。名称显式改变、列表 ID 被替换或抢占其他台账列表时返回冲突，不自动改绑或加后缀。多个 agent 共用同一台账时共用同一绑定与一个原生周期同步任务。

初始化将接口可读取的字段快照保存于 `dataDir/reminders-backups/UUID.json`，文件为 `0600`。新镜像的初始快照为空；旧版快照仍作为恢复证据保留。快照不是整个原生列表的无损备份或一键恢复接口。

初始化日志独立于映射，记录列表名、原生列表 ID、规范化台账目录、命名空间及快照校验值。新版阶段为 `prepared`、`rebuilding`、`verifying`、`complete`，不删除原生旧事项；中断后仅续建本次初始化的关联事项，出现其他内容时停止。

重复初始化已完成镜像返回 `already_initialized`。映射丢失、损坏或绑定改变时保留现场，不能删除记录冒充首次使用。

## 从 1.6.3 及更早版本升级

旧版已完成绑定继续沿用原名称「团队待办（team-tasks）」；旧同步和后台命令不带新参数也可自动恢复目标。不需要重新初始化列表或重建调度身份。

旧自定义 `state-root` 的绑定由该配置的首次新版调用发现。预览和诊断只读取旧记录；实际同步或有效的迁移提交先校验绑定与映射，将原绑定字节及 SHA-256 清单归档至公共状态目录的 `binding-migration-backups/UUID/`，最后原子写入公共绑定。提交中断可重试，保留原文件及未完成归档。新版记录保存原文件哈希；任何已迁入原文件继续变化时停止并报告冲突，不能让旧版写入者与新版并行运行。

启用其他独立镜像前，先使用原配置升级所有既有镜像，包括采用自定义状态根的空台账；技能不会搜索用户任意目录来发现未登记的旧配置。公共记录与旧记录矛盾、同台账多绑定或映射身份不符时停止，不自动选新旧。旧版未完成初始化若记录了待删除旧条目，则返回 `state_recovery_required`；保留快照、列表和日志核查恢复，不自动继续旧删除流程。升级安装本身不运行迁入或真实同步。

## 更换数据目录 / 换宿主

首次初始化用数据目录的规范化绝对路径生成命名空间。搬迁后若仍按新路径计算标记，会失去与原生事项的关联。因此目录重命名、整体搬迁或换宿主时，应使用 `--rebind` **保留原命名空间**，只改变绑定中的 `dataDir`；旧 namespace 的条目继续属于同一镜像，原生 ID 和完成回写凭据也保持有效。绑定中的 `namespaceDir` 保存命名空间首次生成的路径，后续多次搬迁仍沿用同一身份。首次初始化格式保持兼容。

1. 停用旧路径对应的原生周期同步和所有台账写入者。完整搬迁活动台账、月份归档、`reminders-map.json` 和 `reminders-backups/`，不要用任务子集替代台账。沿用辅助配置的原 `state-root`；换宿主时将该镜像的原绑定记录保留到新用户公共绑定目录，文件必须属于当前用户，目录为 `0700`、文件为 `0600`。原列表必须仍可被当前宿主读取且 ID 一致。
2. 先预览，再按输出中的 `listId` 和 `boundDataDir` 精确确认（旧路径直接使用绑定中的字符串，即使目录已不存在，也不要换成路径别名）：

   ```sh
   python3 scripts/macos_reminders_sync.py --data-dir /absolute/new/data --rebind
   python3 scripts/macos_reminders_sync.py --data-dir /absolute/new/data \
     --rebind --confirm '原列表 ID' --from-data-dir '/absolute/old/data'
   ```

   搬迁时若映射尚未生成，预览和提交另带原 `--list-name`，脚本不猜测目标。使用自定义状态根目录时，两次命令及后续同步都要带同一个 `--state-root /absolute/state`。预览返回双方路径、绑定文件、原命名空间、初始化阶段及目标列表的实际条目。完整镜像还会展示后续同步的差异与冲突。`--diagnose` 在目录冲突时只报告本地绑定错误，不读取原生快照；普通 `--plan`、同步和初始化仍停止，不自动迁移。
3. 执行前在 `stateRoot/rebind-backups/UUID/` **原样归档**旧绑定及随台账搬迁的旧映射，保存 SHA-256 清单并回读校验。初始化未完成时还归档并验证原初始化快照。最后只原子更新绑定文件，映射和台账不改，保留原初始化阶段。归档或原生读取失败时不提交迁移；提交成功但响应丢失时，可重复同一命令，返回 `already_bound`。部分归档保留作为现场证据，无需删除以重试。
4. 运行新目录的 `--plan` 核对差异，然后正常同步；若新版初始化未完成，使用 `--initialize-mirror` 续建自身事项；旧版带有非空 `oldIds` 的未完成初始化须先核查恢复方案。原快照或所需映射缺失、损坏，原生列表消失、被替换或标记重复时停止，应恢复完整有效状态再重试，不能删除记录冒充首次使用。
5. 镜像命名空间已保留，但本机定时配置仍按数据目录路径定位。确认旧目录的本功能已停用后，按 [原生定时同步](periodic-sync.md) 用新目录重新计划、验证后台权限并启用。工具不会在迁移时自动更改 LaunchAgent。

迁移命令不清空或重建列表，也不认领其他 namespace 的事项。手工及其他 namespace 条目保持原样；只有同一完整台账的目录迁移适用此流程，每个原生列表只能绑定一个台账，两个独立台账应指定不同列表。旧目录的绑定已失效，旧调用将报告冲突。

## 差异、匹配与手工删除

脚本按属性批量读取原生快照，在内存中建立原生 ID 和第一行标记索引，不逐条取全部属性，也不在每次新增后重新扫描整个列表。备注的第一行标记为：

```text
[team-tasks:v1:<初始化命名空间，受控搬迁后保持不变>:<任务 ID>]
```

不按标题、负责人或零散 ID 猜测关联。旧标记保持兼容；升级认领已有对应事项。通常只更新目标列表中当前台账命名空间的事项，不修改手工条目、其他命名空间或其他列表。当前台账已不存在的 ID 保持原样，不猜测删除意图；重复标记、多个同名列表或绑定不符时报告冲突。

`dataDir/reminders-map.json` 保存原生 ID、状态历史基线及缺失/停止同步记录，完成来源凭据保存在台账历史中。映射原子保存并共用固定 `.macos-reminders.lock`。映射指纹仅作辅助；台账不变时仍比较原生实际字段，避免遗漏手工修改。读取其他列表仅用于识别移动及原生完成，不扩大原生写入范围。

- 已完成/已取消事项被清除后不重建；缺失记录保留在映射中。
- 未完成事项第一次有效同步确认缺失时记录观察，连续第二次成功同步确认缺失后停止补建；权限失败、读取失败或跳过时点不计数。
- 移到其他列表的关联事项停止同步且不在目标列表新建；用户移回后重新认领。
- 台账显式 `reopen` 后允许恢复被删除事项；移动的事项仍须先移回。归档只是存储位置变化，不是任务消失。

## 勾选完成回写

完成回写需要可靠的原生 `completionDate` 和已保存的待处理状态基线。无可靠时间、旧勾选无基线、台账同时重开或状态历史改变时，报告冲突并保留原状，不猜测任务应该完成。用户在台账显式重开时先把对应原生事项恢复未完成，旧勾选不得再次覆盖重开。

初始化中断恢复也遵守完成基线规则。若创建已成功但响应和映射尚未保存，用户随后勾选的事项会保留并报告 `completion_baseline_missing`；核实后在台账记录完成，或由用户取消该原生勾选，再继续初始化。

适配器通过 [存储接口](storage.md#原生完成回写) `complete_external` 提交：在台账锁及同一事务内完成状态、来源时间评论、追加历史中的凭据及两条普通 `status`/`comment` outbox 事件。`completedAt` 保持台账提交时间，评论保存真实原生完成时间。状态历史指纹仅覆盖 `create`、`status`、`reopen`，允许同步期间新增普通评论，阻止“待处理→完成→重开”的旧状态竞争。同一完成凭据重复提交不重复写入，归档后仍能去重。

原生适配不领取或确认 `sync_claim` / `sync_ack`，不改已有催办规则、任务 ID 或其他定时任务。完成回写产生的普通 outbox 事件仍由既有风险调度 worker 处理。

## 字段映射

| 台账字段 | 原生提醒事项 |
|---|---|
| `title` | 标题 |
| `description`、`assignee`、`tags` | 备注中的说明、负责人和标签 |
| `priority` | `critical/high` 为原生 `1`，`medium` 为 `5`，`low` 为 `9`；备注保留原值 |
| `isBlocking` | 原生旗标及备注中的阻塞说明 |
| 最新一条 `comments` | 备注中的进展、评论时间及作者 |
| `snoozedUntil` | 备注中的暂停时间，不改变原生提醒策略 |
| `status` | `pending` 未完成；`done/cancelled` 已完成，备注区分完成与取消 |
| `dueDate`、`dueTime` | 截止日期及系统到期提醒，规则如下 |
| `id` | 备注中的任务 ID 与完整第一行标记 |

只有日期时使用原生全天截止日期，不补造具体时间，并清除具体提醒时刻。日期和时间都有时按 `Asia/Shanghai`（`+08:00`）写入截止与系统提醒时间，与宿主时区无关。`dueDate` 为 `null`、`"none"` 或缺失时清除截止和提醒字段；独立 `dueTime` 不产生截止日期。保留系统到期提醒，不套用风险提醒引擎的工作日日历、snooze 或时间槽策略。

macOS 可能在写入任一种截止日期后自动补齐 `dueDate`、`alldayDueDate` 和 `remindMeDate`。读取时，具体截止时刻与全天日期锚点不同时按定时事项处理；全天事项的提醒时刻若恰好等于全天锚点，则视为系统补齐并按空值校验。不同的提醒时刻仍作为字段差异处理。若定时截止恰好落在宿主本地零点且系统把三个属性补成同一瞬间，原生快照无法单独区分它与全天事项，校验会保守报告差异。

同步范围是活动台账和 `team-tasks-archive-YYYY-MM.json` 中的全部任务；完成、取消及归档事项初始化时以已完成状态创建，后续清除后不补建。不得使用“当前用户相关 pending”的筛选结果替代完整台账。

## 权限与失败处理

脚本仅用标准库，固定原生脚本及参数列表通过 JSON 传递数据，不把任务内容拼接为代码。请求暂存目录为 `0700`、文件为 `0600`，结束后清理；运行需要数据目录、专用用户状态目录及限定临时目录权限。适配自身无网络、API 密钥或消息发送渠道；原生账户如何同步到 iPhone 由系统设置决定。

首次正式调用可能要求用户响应 macOS 自动化授权。在“系统设置 → 隐私与安全性 → 自动化”检查实际执行身份的提醒事项权限；后台辅助应用和终端并不自动共享授权。定时启用前须通过同一后台辅助应用链路验证实际读取结果，终端成功不能代替后台验证。用户拒绝时停止，不更换身份尝试绕过。

只有脚本返回确认成功才报告已同步；跳过、离线预览或差异计划都不代表写入。台账业务操作已提交、原生失败时分别报告“台账已保存，提醒事项同步失败”，不回滚台账或重放创建/评论等非幂等请求。修复明确的访问问题后仅重试同步，利用标记和完成凭据收敛部分写入；重复失败保留现场及日志。初始化中断按日志恢复，映射或日志校验失败时停止。

Python 和原生模拟测试只使用临时台账及模拟应用，不访问真实提醒事项；实机测试与模拟通过分别报告。正常定时错误写入状态及日志，不自动调用模型排障。

## 前台响应、状态及耗时

普通保存操作不启动原生桥，也不等待定时同步。已启用时回复「台账已保存，提醒事项将在下一同步时点更新」；后台未就绪或最近失败时报告具体状态。`--sync-status` 的 `currentSyncVerified` 固定为 false，历史成功不是当前状态核验；旧结果缺少 `finishedAt` 时 `lastSyncAt` 为 null，不猜测时间。

周期/手动执行结果记录 `startedAt`、`finishedAt`（UTC）和 `timings`：`totalMs`、`bridgeMs`、`bridgeCalls`、`lastBridgeMode`，以及原生桥正常返回时的 `nativeReadMs`、`nativeReadCount`、`nativeWriteMs`、`nativeVerificationMs`。读取时间包含写后快照；验证时间为快照后字段验证，写入时间包含原生修改循环。桥硬超时仍为 120 秒；被终止时可能拿不到原生阶段计时，通过 `lastBridgeMode` 和 `bridgeMs` 定位，不捏造细分数据。失败只在下一合法时点重新核对，不重放业务操作。

## 1.6.6 状态查询与原生探测

询问完成回写、后台结果或任务状态时，只运行一次 `--sync-status`（需要时加 `--task-id T-…`）并回答，不自动生成 JXA、不运行 `--plan`、不轮询或重试。本地输出包括 `packageVersion`、`scriptPath`、`task.ledgerStatus`、`task.currentCompletionOrigin`、`task.nativeCompletionHistory`、`task.mapping` 和最近后台结果。`mappingStatusHistoryMatches` 只比较状态历史指纹，不代表全部字段或当前原生状态一致。历史收据与当前完成来源分开报告：重开后再由台账完成，不把旧收据认作本次原生回写。

普通 `--diagnose` 现在只查本地，旧后台探测调用须加入 `--native-check`。原生探测仅校验列表 ID、名称和绑定，不读取提醒事项数组、不初始化或写入；成功返回 `nativeProbeVerified=true`。安装器必须核对该标记和探测令牌，本地状态成功不能证明原生授权。探测超时返回 `macos_probe_timeout`，子进程终止并回收，不自动重试。完整同步、初始化和显式 `--plan` 的原生桥仍为 120 秒；本版本没有解决原生全量读取性能。

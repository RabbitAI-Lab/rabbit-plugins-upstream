# 债务重组·逐条挂源

给一份财报或重组公告，把**债务重组**这一族披露读成一张**每个数都能回到原句**的登记表：重组概况（债务账面价值、债权人、协议日与完成日）、重组方式（四条路走哪条）、以资产清偿债务（资产账面价值与公允价值、清偿的债务、重组损益）、债转股（转股数量、作价、损益）、修改其他条款（条款要点、现金流差异）。

债务重组的麻烦不在算术，在**方式与来源**：同样是「少还了一千万」，走以资产清偿、走债转股、走修改条款，三者的入账科目和损益口径完全不同；同一个「债务重组损益」，附注确认了多少就是多少，**不是**用资产账面价值、公允价值、清偿债务账面价值三个数轧差倒算出来的。**本件只登记披露怎么写，不替披露选方式，不替披露算损益，不评这单重组划不划算。**

**不判该不该重组、不给偿债建议、不预测重组损益、不评偿债能力、不评债权人让步是否合理、不给评级与目标价。** 重组方式只认附注明写的那一条；重组损益取披露确认数，不轧差、不推算；债转股作价照抄，不评公允性。

## 一、三十秒跑通（零输入）

不给任何数据文件，也能跑出一份完整合规的成品，看它长什么样、判据怎么打：

```bash
python3 scripts/check_debt_restructuring.py --demo
```

把这份样例存下来再跑一遍机检：

```bash
python3 scripts/check_debt_restructuring.py --demo > 样例重组稿.md
python3 scripts/check_debt_restructuring.py 样例重组稿.md
# → 样例重组稿.md 结论：五道全过（零发条）
```

接着换成你自己那份稿子：

```bash
python3 scripts/check_debt_restructuring.py 你的重组稿.md
```

退码 `0` 全过、`1` 有发条、`2` 用法错、`3` 读不到文件或空稿。

### 拿不到成品时，从原文开始的三步

1. **定主体与报告期**，拿到年报或半年报原文（附注里的债务重组那一节、非经常性损益表）与重组公告，两边对照着看。
2. **每节抄事实，连原句一起抄**：一条 = 一行，行末挂 `「原句」〔锚：页/表〕[S#]`。方式词和损益金额必须在同一行的原句里出现。
3. **跑一遍自检**，红一条改一条：

```bash
python3 scripts/check_debt_restructuring.py --selftest
```

末行报 `自测档数=11｜不合=0｜不可判=0`：一枚好样零发条，六支坏样各只发它自己那道码，三支反证样须不误红。

### 先确认通道在场（可选）

配了 `CUE_API_KEY` 才需要这一步。先列目录，再从目录里取本组的路由地址发 `tools/list`：

```bash
CATALOG="https://cuecue.cn/api/mcp-catalog"
curl -s "$CATALOG" | head -c 2000
# 从目录里取本组的路由地址，确认工具在场
curl -s -X POST "$ROUTING_URL" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

没配凭据也能用：把财报与公告放进工作区，走用户直供那条路，代价是重组公告与资产交割文件只能在你手头那几份里翻，证据密度降为手头材料，缺失项一律写「未取到」。

## 二、机检在管什么

| 码 | 名称 | 判什么 | 状态 |
|---|---|---|---|
| `DR-STRUCT` | 形制 | 头部四件自标、`主体：`、`报告期：` 在场；七节齐且有序；前五节各至少一条 `- ` 发现行；六七节不得留白 | 已落字 |
| `DR-QUOTE` | 原句与锚 | 每条发现行以「」原句＋〔锚：…〕＋`[S#]` 收尾（三元组须在行末）；来源行带可点 URL 与检索日；引用的编号须已登记 | 已落字 |
| `DR-MODE` | 重组方式 | 四条路（以资产清偿债务／债转股／修改其他条款／组合）一条都没登记即发；两条路混在同一行又未标「组合」也发 | 已落字 |
| `DR-GAP` | 未取到两向点名 | 正文与第六节互相对账，两个方向各发；零缺口须显式写「未取到：无」；禁「不适用」「无此项」「无需披露」 | 已落字 |
| `DR-LINE` | 红线 | 正文（剥掉「」引文、「合规红线」与「数据通道」两节跳过）出现处置与偿债建议／重组损益预测／评级与目标价／确定性断言即发，逐处点名 | 已落字 |

五道全部落字，无未实装项。

## 三、四条红线（这件的立身之本）

1. **重组方式不许推定。** 四条路必须由附注明写其中一条：以资产清偿债务／将债务转为权益工具／修改其他条款／组合方式。看到「以设备抵顶」不能自己归到「以资产清偿」，看到「延期三年」不能自己归到「修改其他条款」；走组合的必须写明组合了哪几条。四种账务处理各不相同，含混就是错账。
2. **重组损益取披露数，不轧差。** 资产账面价值、资产公允价值、清偿债务账面价值三个数都在，也不等于第四个可以由本件算出来——附注确认了多少就是多少，记在哪个科目（其他收益／投资收益）也照抄。附注没给损益的写 `未取到`，不许倒算。
3. **两向点名。** 正文每一条「未取到」在第六节有对应登记，第六节登记的每一项在正文能找到落点；零缺口时显式写 `未取到：无`。禁「不适用」「无此项」「无需披露」——这三种写法把「没查到」冒充成「没有」。
4. **引文是证据、不是断言。** 红线只判本件自己写的句子，「」内照抄的原文不算本件在判断；`〔锚：…〕` 只是指针。禁词表里，裸的「买入／卖出／增持／减持」**不在表内**——它们当普通动词用时是合法登记语言（「本期以出售设备清偿债务」是披露原文）；表里只收「买入评级」「目标价」这类评级语言。

## 四、一条发现长什么样

```markdown
- 债务重组损益：500.00 万元「本次债务重组确认其他收益 5,000,000.00 元」〔锚：2025 年年报·第 132 页·附注八·债务重组〕[S1]
```

没取到的，自成一行、照实写（**不是省掉这一行**）：

```markdown
- 转股数量：未取到：本报告期债务重组不涉及债转股
```

没走的那条路，本节每一项都要占行：

```markdown
- 修改后条款要点：未取到：本报告期债务重组不涉及修改其他条款
- 修改前后现金流差异：未取到：同上（本报告期无条款修改）
```

零缺口时，第六节显式写：

```markdown
- 未取到：无
```

## 五、和另外几枚包怎么分

| 你手上是 | 用哪枚 |
|---|---|
| 这笔债务重组怎么入的账、走哪条路、确认多少损益、缺口在哪 | **本件** |
| 并购重组的进度、方案与时间表跟踪 | `cn-restructuring-tracker`（进度那枚，本件只管账务） |
| 四期差异、科目勾稽的点评 | `cn-earnings-note` |
| 递延所得税这一张表怎么列、怎么动 | `cn-deferred-tax-cn` |
| 存货、应收账款、合同资产的余额与账龄 | `cn-working-capital-quality` |

与 `cn-restructuring-tracker` 的分界最需要说清：**那枚跟进度（谈没谈成、走到哪一步），本件记账务（怎么入账、损益多少、哪一格没披露）**——同一件事的两面，不重叠也不互相印证。

## 六、素材从哪来

- **用户直供**：手头的年报 PDF、重组公告、问询回复，走解析通道读成能检索的正文。
- **通道取证**：配了 `CUE_API_KEY` 后可走公告检索与原文解析。装好 skill ≠ 已配凭据 ≠ 通道已连，三层分开看。
- **重组材料常散在多处**（附注的债务重组一节、非经常性损益表、资产交割过户公告），长附件与扫描件交给解析腿：先取大纲，再按节取用。计费与可用性以服务端返回为准。

本件不发请求、不代付费，消耗以服务端返回为准。

末行自报「档数=3（由上面逐档现报）｜不合=N｜不可判=N」（档数由 runner 自己现算，不写死）；退码 `0` 全过、`1` 有不合、`3` 取值域故障。

## 八、首次运行埋点

入口脚本解析参数成功后、干正事之前，会往 `~/.cue-usage/<slug>-<日期>` 落一枚**空文件**。

**为什么要它：** 平台的两个下载计数器都不可信——新 listing 上架首 48 小时会被一次性播种 50~60 的初始计数，那不是用户下载。本地这枚文件是本件唯一能证明「真有人装上并跑过」的证据。

**它不会碍事：** 任何失败（家目录只读、配额满、无 HOME）都静默跳过，不报错、不改退码、不吐一句杂音。同一天跑多次只留一枚。

要清掉：`rm -rf ~/.cue-usage`。

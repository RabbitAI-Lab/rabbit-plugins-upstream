# Current writing sources and user feedback

For the bundled research and primary-source links behind the method, see [Get Hired PRO sources and research](../SOURCES.md). The instructions below concern the user's career inputs and feedback.

Use the applicant's current career/project facts, skills matrix and applicable user corrections. Their supplied and accepted facts are authoritative working material, not inputs to a claim-approval process. Use the substantive relevant career, leadership, delivery, publishing, research and systems work; names/download totals alone do not express capability.

Keep the user's records in their own workspace, separate from the installed skill. Reuse an existing suitable project directory; otherwise a `get-hired-pro/` project directory can hold:

- `career-reference.md`: work history, project contributions, publications, credentials, examples and supplied outcomes.
- `skills-matrix.md`: the capabilities/tools and their known work contexts from guided discovery.
- `user-feedback.md`: accepted corrections and presentation/process preferences, with rejected suggestions retained so they are not repeatedly proposed.
- Save the applicant's PDF or Word preference with the presentation choices. Record an employer's required format with that application.
- `search-preferences.md` and `job-shortlist.md`: the user's current job-search preferences and sourced opportunities, when discovery is requested. Existing suitable records can be used instead.
- `application-log.md`: chosen applications, current states, receipts/contact history and next actions; reuse an existing suitable tracker.
- Keep researched pay comparisons and the recommended target with the existing search preferences or research record. Retain role/market, currency, pay period, source data dates and date checked.
- Keep industry hiring terms, their dated sources and accepted LinkedIn copy with the existing career/profile records. Reuse the research without treating requested skills as newly established applicant skills.
- Keep interview topics, useful examples and the next practice need with that application's preparation. Keep negotiation targets, actual offers, responses and agreed terms with the offer record; update the tracker from actual replies.
- `applications/<employer-role>/`: that application's job description, dated OSINT, selection notes, draft, review, final documents and current application status.

Identify each application directory with the requisition ID, or a combination of role, location and date. Different postings with the same company and title need separate directories. Keep document revisions inside that application's directory so approved packets and useful prior work remain intact.

Structured JSON can accompany these files when existing tools benefit from it; it is not a prerequisite. No special memory provider, embedding model, account or database is required. Native memory can point back to the records, but the records must remain usable without relying on chat recall alone.

## Save feedback as reusable instructions

For a meaningful correction, record its date, the user's actual words where useful, what should change, whether it applies to this application or future work, and what older active preference it supersedes. Honor a batch approval of suggested skills without requesting the same approvals again. Preserve rejected suggestions and corrected factual entries without continuing to feed them as current candidate facts.

Update the affected facts/preferences rather than appending conflicting rules. Keep superseded history available outside the current writing instructions. Do not turn the feedback file into execution chatter or a copy of every progress message.

## Read and apply the record

Before discovery follow-ups, read what has already been answered. Before selection, drafting, review and correction, read the current career reference, matrix and applicable feedback. If invoking an isolated task or separate reviewer, supply the relevant source TEXT and current corrections; a file path alone supplies no content to a worker that cannot access it. Preserve the full career for meaningful selection/review rather than treating an earlier selection as the only possible evidence.

Current exact questions and saved answers can be carried unchanged when provided; their inventory is not a prerequisite to writing the résumé and letter.

Update changed records incrementally. If the environment already maintains derived writing views, preserve useful curated content and original source history when refreshing them. No re-embedding, full-bank rebuild or per-application claim approval.

# 共识判定协议（Consensus Protocol）

在输出整合前，对讨论结果进行共识/分歧的结构化判定。

## 共识点判定标准

一个结论进入"共识点"必须同时满足：

1. **显式同意**：所有角色在轮次 3 中明确同意或未反对
2. **无保留意见**：没有角色附带"但需要注意 XX"的保留条件
3. **置信度足够**：至少没有角色将其标为"低置信度"

注意：**没有被讨论过的内容不是共识**——共识必须是经过对抗检验的结论。

## 分歧点记录格式

```
分歧点 N：{一句话描述分歧}
- 立场 A（角色 X）：……（理由：……；置信度：……）
- 立场 B（角色 Y）：……（理由：……；置信度：……）
- 裁决建议：需要补充什么信息才能裁决？/ 这是一个价值观取舍，需要用户决定
```

## 分歧分类

| 类型 | 说明 | 处理方式 |
|------|------|----------|
| 事实分歧 | 对客观事实的认知不同 | 建议补充数据/检索验证 |
| 预测分歧 | 对未来的判断不同 | 并列呈现，标注各自依据 |
| 价值观分歧 | 风险偏好/优先级不同 | 并列呈现，交由用户裁决 |
| 定义分歧 | 对概念理解不同 | 先统一概念再呈现 |

## 禁止事项

- 禁止把分歧"平均化"为和稀泥结论
- 禁止隐藏少数派意见——少数派的反对往往是最大的价值
- 禁止用"专家们意见不一"敷衍——必须呈现具体立场和理由

# 输出整合协议（Synthesis Protocol）

将多轮对抗讨论整合为结构化决策输出。

## 输出结构（固定四段）

### 1. 共识点

经过对抗检验、所有角色同意的结论。每条标注置信度。

```
✅ 共识 1：……（置信度：高）
✅ 共识 2：……（置信度：中，保留条件：……）
```

### 2. 分歧点

按 `consensus-protocol.md` 的格式呈现。并列各方立场 + 理由 + 置信度。
明确标注分歧类型（事实/预测/价值观/定义），以及裁决需要什么。

### 3. 行动指南

具体、可执行、有优先级。每条行动标注：负责人角色视角、预期产出、验证方式。

```
P0（立即做）：
1. ……（验证方式：……）
P1（本周）：
2. ……
P2（本月）：
3. ……
```

规则：
- 每条行动必须是"下周就能开始执行"的颗粒度
- 禁止"持续关注""进一步研究"这类无产出行动——如需研究，必须明确研究问题和交付物
- 行动必须来自讨论中的具体论点，不得凭空添加

### 4. 风险提示

魔鬼代言人（及其他角色）在轮次 3 后仍未解决的反对意见。

```
⚠️ 未解决风险 1：……（提出者：……；概率估计：……；建议缓解：……）
```

## 整合原则

1. **忠实于讨论**：整合器只做结构化，不新增观点
2. **保留张力**：有分歧就有分歧，不粉饰
3. **面向行动**：输出的最终目的是帮用户做决策和下一步动作
4. **标注不确定性**：明确哪些是确定结论、哪些是待验证假设

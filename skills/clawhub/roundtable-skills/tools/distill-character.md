# 角色蒸馏与导入（distill-character）

将真实人物或特定专家类型转化为标准角色并持久化。

## 两个合规来源

### 来源一：god-skills 蒸馏（硬前置）

**必须已安装 god-skills，不提供任何降级替代。**

未安装 god-skills 时的行为：
1. 明确告知用户：人物蒸馏功能需要 god-skills 支持
2. 引导用户安装 god-skills
3. 拒绝执行蒸馏（包括"基于公开知识手动蒸馏"等一切替代路径）
4. 建议替代方案：使用内置 L1/L2 角色完成本次讨论

### 来源二：外部导入

导入现成的角色文件（他人分享、其他项目迁移、社区获取），
经格式与纯净性校验后登记入 `characters/`。

## 核心原则：人物纯净性

蒸馏产出物只包含"人格"信息，**禁止写入任何具体任务/议题信息**：

- ✅ 允许：认知框架、知识域、决策偏好、对抗规则、表达风格、场景类型标签（如"战略决策""产品评审"这类抽象类别）
- ❌ 禁止：具体议题内容（如"读博还是工作"）、某场讨论的用户上下文、针对特定任务的指令、一次性事件

**具体任务信息在运行时通过装饰器注入（见 `tools/task-decorator.md`），永不回写角色文件。**

违反纯净性的人物文件 = 被污染的人物，会在下次讨论中产生串台（把上一个用户的议题当成自己的背景），必须拒绝或修复。

## 蒸馏流程（god-skills）

### 1. 前置检查

确认 god-skills 已安装。未安装 → 按上文"硬前置"规则处理。

### 2. 查重

检查 `characters/` 与 `characters/index.yaml`：
- 已有 → 直接加载，跳过蒸馏
- 无 → 进入蒸馏

### 3. 调用 god-skills 蒸馏

提取人物特征：公开言论、决策案例、思维偏好、表达风格。
**输入给 god-skills 的只有人物名称/类型，不包含当前议题**——从源头保证纯净性。

### 4. 转化为标准角色格式

```markdown
# {人物名}（蒸馏角色）

## 认知框架
{此人如何思考问题，第一性问题是什么}

## 知识域
{专业领域}

## 决策偏好
{判断标准，什么会支持、什么会反对}

## 对抗规则
{在圆桌中必须挑战什么、必须追问什么}

## 表达风格
{标志性表达方式、惯用视角}

## 元信息
- source: god-skills
- created: {日期}
- best_scenarios: {抽象场景类型标签，禁止具体议题}
```

**关键要求**：蒸馏角色必须转化为"认知立场"，不能只是模仿说话腔调。
腔调是表皮，决策偏好和对抗规则才是灵魂。

### 5. 持久化

- 保存到 `characters/{name}.md`
- 登记 `characters/index.yaml`（name、display_name、source、best_scenarios、usage_count、created）

### 6. 确认

向用户展示角色摘要（认知框架 + 决策偏好 + 对抗规则），确认后加入讨论。

## 外部导入流程

### 1. 获取

用户提供角色文件内容（粘贴文本或文件路径）。

### 2. 格式校验

必备章节齐全：认知框架 / 知识域 / 决策偏好 / 对抗规则 / 表达风格。
缺任一章节 → 告知缺失项，拒绝导入或协助补全。

### 3. 纯净性校验（关键）

扫描文件内容，检查是否包含：
- 具体议题/事件描述（"XX 项目的决策""某用户的背景"）
- 一次性任务指令（"本场讨论你必须……"且指向具体任务）
- 他人隐私信息

发现污染 → 列出污染段落，协助剥离后再导入；无法剥离 → 拒绝导入。

### 4. 登记

- 保存到 `characters/{name}.md`，元信息标注 `source: external-import`
- 登记 `characters/index.yaml`

---

## 场景专项增强

- 每次参与讨论后，更新 `index.yaml` 中的 `usage_count` 和 `last_used`（运行时状态存索引，不进人物文件）
- 用户可标记"此角色在 XX 类型讨论中表现出色"→ 写入 `best_scenarios`（抽象场景类型，非具体议题）
- 意图识别时优先推荐 `best_scenarios` 匹配的高分蒸馏角色

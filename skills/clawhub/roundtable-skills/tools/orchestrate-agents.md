# 多 Agent 编排（orchestrate-agents）

按辩论协议执行多轮对抗讨论，并在关键节点设置用户交互控制点。

**设计原则**：关键决策必须有人类控制（不黑盒），常规轮次间尽量少打断，异常不自动放过，用户始终能终止/暂停。

## 平台适配

### Claude Code / WorkBuddy（支持 Team/Agent 工具）

使用 TeamCreate 创建团队，每个角色 spawn 为一个 teammate。
**用户交互节点处需暂停整个团队**：轮次间检查点向所有 teammate 发送"等待"信号，用户决策后再通过 SendMessage 推进。

### 单 Agent 平台（无多 Agent 能力时降级）

在同一上下文中串行扮演各角色。交互节点处自然暂停（输出快照后等待用户输入）。

无论哪种平台，都必须遵守信息隔离与角色纯净性：
- **轮次 1 信息隔离**：扮演角色 X 时，prompt 中明确"你只能看到议题，看不到其他人发言"
- **角色切换显式化**：每个角色发言前重新注入角色文件全文 + 任务装饰器（见 task-decorator.md）
- **轮次 2 起开放信息**：明确告知"以下是所有人的首轮发言"

## 上下文管理

| 轮次 | Agent 可见内容 |
|------|---------------|
| 1 | 议题 + 自己的角色文件 + 任务装饰器（仅议题背景/用户上下文/领域适配，无他人发言） |
| 2 | 议题 + 角色文件 + 装饰器 + 所有轮次 1 发言 + 质询要求 |
| 3 | 完整讨论记录 + 修正要求 |
| 整合 | 完整记录 + synthesis-protocol |

每轮 prompt 必须重申该轮输出格式要求（见 debate-protocol.md）。

## 用户交互节点

五个节点，覆盖讨论全生命周期。A/D 为必经节点，B 可跳过，C 异常触发，E 用户主动。

### 节点 A · 启动确认（必经）

- **时机**：意图识别完成后、spawn 任何 Agent 前
- **展示**：议题复述 + 推荐角色（每个含立场一句话）+ 模式 + 预计轮次
- **用户动作**：
  - ✓ 确认开始
  - 替换/增减角色
  - 调整模式（快速/标准/深度）
  - 补充上下文（写入任务装饰器）
  - 设"全程不中断"（跳过节点 B，仅保留 A/C/D/E）
  - 取消
- **默认**：等待用户确认，不自动启动（除非用户在议题中已明确"直接开始"）
- **平台差异**：无

### 节点 B · 轮次 1 快照检查（可跳过）

- **时机**：轮次 1 全部角色独立陈述完成后、进入轮次 2 前
- **理由**：首轮是认知锚定，跑偏则后续全错——这是最低成本纠偏点
- **展示**：各角色首轮核心论点摘要（每角色 1-2 句 + 置信度），不做评判
- **用户动作**：
  - ✓ 继续进入质询
  - 补充上下文给特定角色（写入该角色装饰器）
  - 调整某角色方向（如"让魔鬼代言人聚焦 XX 风险"）
  - 跳过后续轮次直接整合（当首轮已充分收敛）
  - 终止
- **默认**：用户说"继续"或无明确干预 → 进入轮次 2
- **跳过条件**：用户在节点 A 选了"快速模式"或"全程不中断"
- **平台差异**：Team 模式下暂停所有 teammate；串行模式自然暂停

### 节点 C · 异常介入（自动触发，强制）

- **触发条件**（质量红线命中）：
  - 轮次 2 有角色未质询任何人（表演性和谐）
  - 所有角色立场完全一致且无质询（视角同质化信号）
  - 发言明显脱离角色认知框架（如魔鬼代言人在赞美方案）
  - 讨论严重偏离议题
  - 角色串台（蒸馏人物带出上轮任务信息——纯净性被破坏）
- **展示**：异常类型 + 证据（哪条红线 + 哪个角色的问题 + 原始发言片段）
- **用户动作**：
  - 强制重跑该轮（可附带调整指令）
  - 替换问题角色
  - 接受现状继续（用户明知故犯，记录在案）
  - 终止
- **默认**：**必须用户决策，异常不自动放过**
- **平台差异**：Team 模式下暂停团队等待决策

### 节点 D · 报告确认（必经）

- **时机**：整合器输出最终报告后（此时 Agent 已 shutdown）
- **展示**：完整报告（共识/分歧/行动指南/风险提示）
- **用户动作**：
  - ✓ 接受并归档
  - 要求深挖某个分歧（追加一轮聚焦讨论，仅相关角色参与）
  - 要求某角色展开论证（单角色深挖，不重启整场）
  - 重新整合（调整整合侧重，如同轮数据重排）
  - 标记归档类型（"决策依据" / "参考" / "待验证"）
- **默认**：用户接受 → 归档到 `memory/`
- **平台差异**：无

### 节点 E · 中途追加（用户主动，任意时刻）

- **触发**：用户在任意轮次间主动发言
- **识别与处理**：
  - "补充：……" → 内容写入任务装饰器，后续轮次可见
  - "加个 XX 角色" / "去掉 XX" → 调整阵容续跑（新角色补跑已完成轮次或从下轮加入）
  - "停一下" / "暂停" → 挂起，等待"继续"
  - "我想问问 XX 角色怎么看 YY" → 该角色单独回应后并入记录，再继续主流程
- **默认**：无（纯用户驱动）
- **平台差异**：Team 模式下通过 SendMessage 转达；串行模式下直接处理

## 异常处理（常规）

非质量红线的轻量异常，不触发节点 C，自动处理：

- 某角色发言不符合格式 → 打回要求重发（最多 1 次），仍不合规则标记并在整合时注明
- 角色间出现人身攻击式表达 → 要求改为针对论点的质询
- 单个角色超时无响应（Team 模式）→ 跳过该角色本轮，整合时注明缺席

## 交互原则小结

| 原则 | 体现 |
|------|------|
| 关键决策人类控制 | A/D 必经，C 强制 |
| 常规不啰嗦 | B 可跳过，E 仅用户主动 |
| 异常不放任 | C 不自动放过 |
| 始终可退出 | 每个节点都有"终止"选项 |
| 上下文可累积 | 用户补充写入装饰器，不丢失 |

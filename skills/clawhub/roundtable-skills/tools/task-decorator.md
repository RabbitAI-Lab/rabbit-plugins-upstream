# 任务装饰器（task-decorator）

人物纯净性原则的另一半：**具体任务信息不进入角色文件，运行时通过装饰器"穿"在角色身上。**

## 为什么需要装饰器

角色文件（`characters/*.md`、`references/experts/**.md`）只描述"这个人是谁"——
认知框架、决策偏好、对抗规则。
但一场讨论需要的不止于此："这个人在**这个议题**、**这个用户背景**下该如何发力"。

把任务信息写进人物文件 = 污染人物，下次换个议题就串台。
装饰器模式让两者解耦：**人物可复用，任务一次性。**

## 装饰器结构

每场讨论、每个角色，组装一份任务装饰器，包含四层：

### 1. 议题背景
本场讨论的议题描述与已知事实。
> 例："议题：生物医学信息工程研二学生，读博还是工作。"

### 2. 用户上下文
用户主动提供的个人信息与约束（脱敏到讨论所需的最小粒度）。
> 例："本硕双非，履历全在实验室，二作两篇 SCI 一区 top。"

### 3. 领域适配
将该角色的通用认知框架映射到本议题领域的提示——
不是改写角色，而是给出"你的框架在这个领域里应该问什么"的引子。
> 例（给巴菲特）："本议题中'资产'= 已验证的科研产出；'市场定价'= 就业市场对双非硕士的定价。"

### 4. 本场约束
轮次规则、输出格式（论点+论据+置信度）、质询要求、信息隔离状态。
> 例："轮次 1：你只能看到议题，看不到其他角色发言。"

## 组装方式

```
角色实例 prompt = 角色文件全文（人格） + 任务装饰器（任务）
```

- 每场讨论、每个角色、每个轮次，装饰器可不同（轮次 1 强调信息隔离，轮次 2 放开并强调质询）
- 装饰器内容只存在于当场 prompt 与讨论归档中
- **隔离红线：装饰器内容永不回写角色文件**（包括归档后"顺便把这次的经验写进角色"——禁止）

## 收益

| 收益 | 说明 |
|------|------|
| 人物可复用 | 同一个"巴菲特"可参与投资、职业、产品决策，互不污染 |
| 任务可追溯 | 归档中装饰器完整保留当场上下文 |
| 人物可分享 | 纯净的角色文件可安全导入导出（见 distill-character.md 外部导入） |
| 串台免疫 | 上轮讨论的用户背景不会泄漏进下轮 |

## 与三层角色体系的关系

装饰器对三层角色统一生效：L1 内置立场、L2 领域专家、L3 蒸馏人物，
全部保持纯净，任务信息一律走装饰器。

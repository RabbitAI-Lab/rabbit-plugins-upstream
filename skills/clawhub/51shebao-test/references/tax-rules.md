# 计算规则参考（与原 hr-tool 实现的对应关系）

## 1. 工资个税（累计预扣预缴法）

源：`SalaryServiceImpl` + `CalculatorUtil` + `PersonIncomeTaxEnum`

- 累计应纳税所得额 = 累计收入 − 累计减除费用(5000×期数) − 累计专项附加扣除(六项×期数) − 累计公积金(个人) − 累计社保(个人) − 累计个人养老金；下限 0
- 本期个税 = 累计应纳税额 − 前(n−1)月累计已缴税额
- **怪癖 1（与原实现一致）**：已缴税额的计算不扣除个人养老金
- **怪癖 2（与原实现一致）**：到手 = 税前 − **未舍入**税额 − 公积金 − 社保，最后整体舍入到分；因此与显示的税额可能有 1 分钱差

7 级预扣率表（累计应纳税所得额，右闭区间）：

| 区间 | 预扣率 | 速算扣除数 |
|---|---|---|
| ≤36,000 | 3% | 0 |
| 36,000–144,000 | 10% | 2,520 |
| 144,000–300,000 | 20% | 16,920 |
| 300,000–420,000 | 25% | 31,920 |
| 420,000–660,000 | 30% | 52,920 |
| 660,000–960,000 | 35% | 85,920 |
| >960,000 | 45% | 181,920 |

反推：二分查找，区间 [到手, 2×到手]，到手误差 ±1 元内收敛。

## 2. 劳务报酬

源：`laborRemuneration-*.ql`（QLExpress 规则）

- 应纳税所得额：≤800 免税；(800, 4000] = 收入−800；>4000 = 收入×(1−20%)
- 预扣率 3 级：≤20,000 → 20%；(20,000, 50,000] → 30%−2,000；>50,000 → 40%−7,000
- 反推分段（beforeTaxIncome.ql）：税后<800 原值；[800,3360) → (税后−160)/0.8；[3360,21000) → 税后/0.84；[21000,49500) → (税后−2000)/0.76；≥49500 → (税后−7000)/0.68
- **有意偏离原实现**：原 Java 代码执行 incomeTax.ql 时误传了 context（应纳税所得额在另一个 context 里），属疑似 bug；本实现按正确逻辑，以教科书值（10000 → 税 1600 → 到手 8400）锁定

## 3. 稿酬

源：`AuthorRemunConstant` + `RemunerationServiceImpl.calculAuthorRemuneration`

- 应纳税所得额：≤4000 = (收入−800)×70%；>4000 = 收入×(1−20%)×70%
- 税额 = 所得额×20%（仅正算，与原服务一致）

## 4. 特许权使用费

源：`PersonalPrivilegeFeeConstant`

- 应纳税所得额：≤4000 = 收入−800；>4000 = 收入×(1−20%)
- 税额 = 所得额×20%
- 反推：候选一 (税后−160)/0.8，若落在 (0,4000] 采用；否则候选二 税后/0.84

## 5. 解除劳动合同一次性补偿金

源：`RemunerationServiceImpl.calculLumpNumCompensation`

- 免税额 = 当地上年职工月平均工资 × 12 × 3
- 超出部分按综合所得年度税率表（同第 1 节的 7 级表）计税
- 不超过免税额：不缴税

## 6. 舍入规则

全部金额：`Decimal` + 半进一（ROUND_HALF_UP）保留 2 位小数，对应 Java `BigDecimal.setScale(2, RoundingMode.HALF_UP)`。

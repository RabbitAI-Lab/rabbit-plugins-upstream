# 商品详情页文案

把商家已经确认的商品资料，整理成完整、可信、可上架的中文商品详情页文案。适用于任意店铺的详情模块；不用于闲鱼标题、通用客服话术，也不替商家补造事实。

## 输入

请提供以下 JSON 或等价的结构化资料。所有事实字段应保留商家原值。

```json
{
  "product_name": "商品名称",
  "specifications": {"材质": "商家原始规格", "尺寸": "商家原始规格"},
  "image_notes": ["图片 1 展示的真实内容与可见细节"],
  "target_audience": "目标客群及使用场景",
  "known_facts": ["可被现有资料支持的事实"],
  "suggestions": ["可选；商家希望强调的表达方向，须标注为建议"]
}
```

其中 `product_name`、`specifications`、`image_notes`、`target_audience` 为必填。缺少任一项时，先列出缺失字段并请商家补充；不得推测材质、功效、参数、认证、售后或图片内容。

## 工作流

1. 先核对必填字段和事实边界。将商家原始规格、图片可见信息、已知事实分开。
2. 提炼 3–5 个卖点。每个卖点必须附“证据：”并对应到一个真实规格、图片说明或已知事实；无法支撑的内容标为“建议”，不可写成事实。
3. 按以下固定交付结构输出。语气贴合目标客群，但不承诺绝对效果、疗效、排名或未证实的适配性。
4. FAQ 只回答资料能够确认的问题；资料不足的答案写“请向商家确认”，并指出需确认的信息。

## 交付格式

```markdown
# {商品名称}｜详情页文案

## 模块 1：首屏价值主张
一句清晰利益点 + 一句适用场景。仅使用已知事实。

## 模块 2：核心卖点与证据
### 卖点 1：{卖点标题}
{面向目标客群的说明}
**证据：** {对应规格 / 图片说明 / 已知事实原值}

### 卖点 2：...

## 模块 3：规格与选购信息
| 项目 | 商家提供原值 |
| --- | --- |
| ... | ... |

## 模块 4：图片搭配文案
| 图片 | 建议标题 | 说明 | 依据 |
| --- | --- | --- | --- |
| 图片 1 | ... | ... | 图片说明原值 |

## 模块 5：适用场景与温和提醒
说明适用人群/场景；把未确认事项写成需确认提醒。

## FAQ
1. **问：...？**
   **答：** ...

## 事实与建议边界
- **已知事实：** ...
- **表达建议：** ...
- **待商家确认：** ...
```

## 质量检查

- 每个数字、材质、尺寸、功能、认证和售后说法都能追溯到输入。
- 每个卖点都有明确证据；没有证据就不作为事实卖点。
- 图片文案只描述提供的图片说明，不臆测画面细节。
- “建议”与“已知事实”分别标示，避免误导。

# 归因纪律规则

复盘的价值在于归因可信。以下规则用于约束「做得好 / 没做好」两节的写法，防止把猜测当结论、把巧合当因果。

## 一、已证实 vs 推测

每条归因必须二选一标注，不得省略：

| 标注 | 定义 | 写法要求 |
|---|---|---|
| 已证实 | 有数据直接支撑该结论 | 附数据来源或口径，如「渠道后台显示 KOL 发布当日新增 5 万」 |
| 推测 | 无数据，仅经验或逻辑判断 | 明确写「推测」，并说明依据是什么经验 |

**禁止：** 把推测写成结论（如「用户不喜欢这个文案」却没有任何点击/停留数据支撑，应标推测）。

## 二、相关性不等于因果

A 与 B 同时发生，不等于 A 导致 B。常见陷阱：

- 活动期间转化涨了，同期还有大促、竞品下架、季节因素 → 不能只归功本次活动
- 改了落地页，转化变了，但同期换了投放人群 → 变量不唯一

**处理：** 凡存在其他可能变量，归因标「推测」，并列出干扰变量；要下因果结论必须控制变量（见实验模板）。

## 三、归因要有信息量

禁止无信息量归因：

- 「团队很努力」「运气好」「市场回暖」——无法复用，不算归因
- 正确写法：「具体做了 X（如提前 3 天预热社群），带来 Y（加群率 +15%，已证实），可复用前提是 Z（私域已有 5000 活跃用户）」

## 四、做得好三项的写法

每项固定三段：具体做了什么 → 带来什么结果 → 可复用的前提是什么。结果无数据则标推测。

## 五、没做好三项的写法

每项固定三段：现象 → 可能原因（2~3 个候选，标哪个证据更强） → 下次如何验证。原因不写死。

## 六、无数字表述拦截词

出现以下词且无数字支撑时，必须整改：

- 效果显著 / 大幅提升 / 明显增长 / 显著改善
- 用户很满意 / 反响热烈 / 非常成功
- 普遍认为 / 大家都说

整改方向：换成「[指标]从 X 到 Y，变化 Z%」或标注「推测」。

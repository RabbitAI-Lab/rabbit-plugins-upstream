# 活动复盘与下轮实验 (ym-campaign-retro-next)

对照当初的目标做复盘，而不是只报数据。做得好与没做好都要有归因，归因分「已证实」与「推测」。下一轮给 3 个能验证的假设，而不是一堆正确的废话。

## 何时使用

- 用户说「活动复盘」「这次活动怎么样」「下次怎么改」「写个活动总结」「活动效果」时
- 用户贴来一次活动的目标与结果数据，想看达成情况与原因时
- 用户做完活动想规划下一轮怎么测时

## 运行前提

- 依赖：无第三方依赖，纯文本处理
- 不接入投放后台取数，数据由用户提供
- 不联网、不上传任何数据

## 输入契约

| 项 | 必需 | 说明 |
|---|---|---|
| 活动目标 | 必需 | 当初想达成什么，最好带数字（曝光/参与/转化/成本） |
| 结果数据 | 必需（有多少给多少） | 曝光、参与、转化、成本等，可不全 |
| 活动形式与渠道 | 可选 | 投放、地推、社群、直播等 |
| 时间周期 | 可选 | 起止日期 |
| 预算 | 可选 | 实际花费 |
| 往期数据 | 可选 | 用于同比 |

**缺失处理：**

- 缺原始目标 → 先要求补目标；若用户给不出，从活动性质反推常见目标并**明确标注为假设**
- 缺数据 → 只做定性复盘，所有数字相关结论标「无数据支撑」
- 缺往期数据 → 不做同比，只做绝对值对照
- 只有「感觉还行」 → 说明无法做有效复盘，请补目标与数据，或明确只能做最粗定性复盘

## 执行步骤

1. **建目标对照表** — 目标 / 目标值 / 实际值 / 达成率 / 是否达成。没有目标值的先标「假设」，不假装是既定目标。需算比值时帮用户算，但标明口径。

2. **还原关键节点** — 按时间线列活动关键动作与对应数据变化（投放开始、KOL 发布、加码预算、结束）。缺数据的节点标注「无数据」，不脑补。

3. **做得好的三项** — 每项写「具体做了什么 → 带来什么结果 → 可复用的前提是什么」。禁止「团队努力」「运气好」这类无信息量归因。结果须有数据或明确标注推测。

4. **没做好的三项** — 每项写「现象 → 可能原因（给 2~3 个候选，标哪个证据更强）→ 下次如何验证」。原因不写死，留验证口。

5. **归因纪律（硬约束）** — 按 `references/attribution-rules.md`：每条归因标「已证实」（有数据直接支撑）或「推测」（无数据，仅经验判断）；不把相关性当因果（A 与 B 同时发生不等于 A 导致 B）。全部标注，不得省略。

6. **给下一轮实验** — 按 `references/experiment-template.md` 给 3 个可验证假设，每个写：假设 / 怎么验证（只改一个变量）/ 衡量指标 / 判定标准（什么结果说明假设成立）/ 需要的资源与风险。

7. **标经验适用边界** — 写「这次学到的、但下次可能不适用」的部分，避免经验被过度泛化。

8. **自检** — 输出前核对：目标值缺的是否标了假设？归因是否每条都标已证实/推测？有没有出现「效果显著」「大幅提升」这类无数字表述？下一轮三个假设是否都能验证？

## 输出格式

Markdown，套用 `templates/retro-template.md`：一、目标对照表；二、关键节点时间线；三、做得好的三项；四、没做好的三项（含归因与已证实/推测标注）；五、下一轮实验三个；六、经验适用边界；七、数据缺口清单。

```
## 目标对照表
| 目标 | 目标值 | 实际值 | 达成率 | 是否达成 |
| 曝光 | 10万 | 12万 | 120% | 是 |

## 关键节点时间线
- D1 投放开始：曝光 2万
- D3 KOL发布：单日新增 5万（已证实，有渠道数据）

## 做得好的三项
1. [动作]→[结果]→[可复用前提]

## 没做好的三项
1. 现象：[……] 原因：[A 证据强/B 证据弱] 验证：[……]

## 下一轮实验
实验1：假设/验证/指标/判定/资源风险

## 经验适用边界
- [这次成立但下次未必]

## 数据缺口清单
- [缺转化漏斗中段数据]
```

## 能力边界

- 不接入投放后台取数，数据由用户提供
- 不做数据建模与归因算法，只做人工可读的归因标注
- 不替用户算复杂统计（用户要求算比值时算，但标注口径）
- 不承诺下一轮一定更好，实验只给验证框架
- 不做广告法/合规审查

## 常见坑

1. **只报数据不对照目标** — 写「曝光 12 万、转化 3000」，但没说目标是多少。规避：第 1 步强制建目标对照表，缺目标值标假设。
2. **把相关性当因果** — 「加了海报，转化涨了，所以是海报有用」，可能同期还有别的因素。规避：归因纪律要求标证据强弱，相关性不写因果。
3. **用无数字表述糊弄** — 「效果显著」「大幅提升」「用户很满意」。规避：第 8 步自检拦截这类词，要求换成数字或标推测。
4. **做得好归因写成「团队努力」** — 无信息量，无法复用。规避：第 3 步要求写「具体动作→结果→可复用前提」。
5. **下一轮给的是方向不是实验** — 「下次多投流」「优化体验」不可验证。规避：第 6 步每个假设必须写验证方式、指标、判定标准。
6. **经验过度泛化** — 这次小预算社群跑通，就断言所有活动都该这么干。规避：第 7 步专门标适用边界。

## 验收用例

- 正常：给目标与完整数据 → 七节齐全，归因有已证实/推测标注，三实验可验证
- 边界 1：无目标值 → 目标标注为假设，不做成既定目标
- 边界 2：无数据 → 只做定性，结论标无数据支撑
- 失败：只有「感觉还行」 → 请补目标与数据，或明确只能做最粗定性复盘

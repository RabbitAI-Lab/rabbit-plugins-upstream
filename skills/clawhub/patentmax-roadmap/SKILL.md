# PatentMax 技术路线分析

回答**「下一步该往哪走」**：几条候选技术路线各自的专利拥挤度和绕行空间、你的方案该往哪个方向延伸、专利该怎么排布、什么时候申请、预算怎么分配。异步生成，可导出 Word 文档直接交付。

数据来自 PatentMax 专利库。

使用问题、企业采购：访问 **ip930.com**，右下角「联系客服」。

**需要 PatentMax 密钥。** 在 https://api.ip930.com 注册（新用户送 ¥50 体验额度）、创建密钥，设成环境变量 `PATENTMAX_API_KEY`。没设时脚本会返回中文提示，原样转告用户即可。

## 运行环境（必读，所有命令都适用）

部分 WorkBuddy 等环境的命令行不完整，`cat`、`ls`、`sleep`、`rm` 等可能找不到。为保证任何电脑都能跑通：

- 脚本路径一律写**绝对路径**：`$DIR/scripts/patentmax_roadmap.py`（`$DIR` 是本技能所在目录），不要写 `cd ... && ...`（前一步失败会让后面整条静默不执行）
- `python` 找不到时依次试 `python3`、`py`；还找不到就用 WorkBuddy 自带的：先用 Glob 在 `~/.workbuddy/binaries/python/versions/` 下找到 `python.exe`，用它的完整路径。**下文所有 `python` 都按这条替换**
- 不要用 `cat` 读文件、不要用 `sleep` 等待：读文件用 Read 工具；等待由脚本自己完成
- 命令在**用户的工作目录**里运行，生成的 Word 会存到这个目录；也可以用 `--out-dir` 指定
- 命令超时设为 120 秒。脚本每条命令最多跑 30 秒就返回，不会卡住

## 跟「企业情报分析」的区别

| | 企业情报分析 | 技术路线分析（本 Skill） |
| --- | --- | --- |
| 回答 | **现状是什么** — 谁在做、格局怎么分 | **该怎么做** — 往哪走、怎么布 |
| 输出 | 竞争格局、对手动作、我方位置 | 路线比选、布局建议、申请节奏 |
| 必填输入 | 目标企业 + 技术方向 | **只有技术主题** |

用户只想知道对手在干什么，用企业情报分析；**要有人告诉他下一步怎么办**，才用这个。

## 核心原则

**必填只有一项：技术主题（`--subject`）。** 只写技术名称，例如「钠离子电池正极材料」，不要写成「XX 的技术路线与专利布局」这种句子。用户没说清主题就先问；其余参数都可不填，用户没提不要追问。

**这是付费任务，执行前必须报价并取得用户确认。** 命令必须显式加 `--yes`。

**布局建议是技术与商业参考，不是法律意见。** 是否侵权、权利要求怎么写、能不能授权，要专利代理人出具意见。

**不出保证性结论。** 不写「这条路线没有专利风险」「绕开了所有障碍」——见「结论纪律」。

**不重新提交。** 报告要跑几十分钟，跑得久不代表失败。只要没有报错，就继续 `wait`。**重新提交是这个技能最常见、代价最大的错误**：输入写法一变就会新建任务、重复扣费，用户还要从头再等一遍，而原来那份其实还在正常生成。

## 执行前检查

只有技术主题是必须问清的。下面这些是可选项，用户主动提了就带上（写进 `--objective` 或业务约束），没提不要追问：

| 检查项 | 说明（可选） |
| --- | --- |
| **技术主题**（必填） | 只写技术名称 |
| 决策问题 | 到底在纠结什么——选路线、定优先级、还是分预算 |
| 候选路线 | 有哪几个方案在比。只有一个方案就不是"选路线"，是布局设计 |
| 时间 | 什么时候要发布、参展、投标——这决定申请节奏 |
| 预算与数量 | 今年能申请几件。能申请 3 件和能申请 30 件，布局完全不同 |
| 现有资产 | 已有哪些专利、产线、技术积累，新布局要和它们接得上 |
| 保密边界 | 哪些参数、配方、数据不能写进公开文件 |

## 可选输入

**素材（`--materials` / `--materials-file`）**：技术方案、赛道背景，可不填。

**业务约束（`roadmap_context`）**：十个字段全部可选，会随任务一起保存：

| 字段 | 填什么 |
| --- | --- |
| `future_plan` | 未来一到三年打算做什么 |
| `existing_assets` | 已有的专利、产线、技术积累 |
| `own_advantages` | 相对竞争对手强在哪 |
| `known_risks` | 担心撞上谁、哪些方向有雷 |
| `evidence_data` | 实验数据、参数、验证结果 |
| `disclosure_timing` | 什么时候要发布、参展、投标 |
| `filing_preference` | 发明为主还是实用新型、国内还是 PCT |
| `budget_and_volume` | 今年打算申请几件、预算多少 |
| `confidentiality_limits` | 哪些内容不能写进公开文件 |
| `excluded_directions` | 明确不做的领域 |

用 `python scripts/patentmax_roadmap.py fields` 可以随时打出这张表。

## 提交前确认（一条消息问完，不花钱）

技术主题定好后，用一条消息列给用户确认，用户回「确认」或改完再加 `--yes`：

```
📋 准备做技术路线与专利布局分析
- 技术主题：……
- 布局目标 / 市场 / 对标企业：……（没说就用默认）
- 已填的业务约束：……（没有就写「无」，填得越全建议越贴合）
- 费用：¥15（以提交后返回的价格为准；任务失败或取消全额退回）
- 用时：通常要几十分钟；完成后 Word 报告自动存到当前目录
```

用户已经在同一轮对话里确认过的，不要再问第二遍。

## 命令

```bash
# 最简：只给技术主题
python "$DIR/scripts/patentmax_roadmap.py" create \
  --subject "钠离子电池正极材料" \
  --yes

# 带上可选的业务约束（写进 JSON 文件，十个字段命令行塞不下）
python "$DIR/scripts/patentmax_roadmap.py" create \
  --subject "钠离子电池正极材料" \
  --objective "在层状氧化物与聚阴离子两条路线中选一条" \
  --context-file ./context.json \
  --markets "CN,US" \
  --yes

# 接着等：每次最多 30 秒，完成时自动下载 Word
python "$DIR/scripts/patentmax_roadmap.py" wait --operation-id <operation_id>

# 重新下载 Word（wait 完成时已自动下载过）
python "$DIR/scripts/patentmax_roadmap.py" download --report-id <report_id>

# 不跑了
python "$DIR/scripts/patentmax_roadmap.py" cancel --operation-id <operation_id>
```

`--idempotency-key` 不填会按请求内容自动生成——**同样的输入重试不会重复建任务、重复扣费**。

## 等待并报告进度

`create` 约 15 秒后返回。返回退出码 10 时，**先发这一句**，再发输出里的进度：

```
技术路线与专利布局报告已开始生成，这类报告通常要几十分钟，进度会实时告诉你。
```

记下输出 JSON 里的 `operation_id`，后面都用它。不主动向用户展示任务编号，用户问起再给。然后运行：

```bash
python "$DIR/scripts/patentmax_roadmap.py" wait --operation-id <operation_id>
```

每条 `wait` 最多 30 秒就返回。按退出码处理：

| 退出码 | 含义 | 怎么做 |
| --- | --- | --- |
| 10 | 还在生成 | 发送输出里的进度，**然后立即再运行一次 `wait`** |
| 0 | 完成了，Word 报告已自动下载 | 按「读结果」交付 |
| 1 | 出错 | 按「出错时」处理 |
| 2 | 输入有误，什么都没提交 | 按 `message` 补齐后再运行 |
| 3 | 同样的任务已经在跑 | 用输出里的 `operation_id` 运行 `wait`，**不要**换写法重新提交 |

### 进度怎么发（照原文，不改字）

把每条 `[进度] ……` / `[进度 X%] ……` 去掉方括号部分，按下表加图标后**原文发送**：

| 进度行 | 发送 |
| --- | --- |
| `[进度] 已开始生成……` | 🚀 已开始生成…… |
| `[进度] 排队中，已等待……` | 🕒 排队中，已等待…… |
| `[进度] 生成中，已用时……` | 📝 生成中，已用时…… |
| `[进度 X%] 某阶段，已用时……` | 📝 X% 某阶段，已用时…… |

例：`[进度 35%] 检索竞争对手专利，已用时 6分30秒` → 发送 `📝 35% 检索竞争对手专利，已用时 6分30秒`。

- **等待期间只发进度，不附加其它文字**；不改写进度文字，不自己估算剩余时间，不编造没出现的百分比
- **出结果之前不要结束回复。** 退出码为 10 时，发完进度立即再运行 `wait`
- 等了几十分钟还没完成 → **正常，继续 `wait`**。命令断了、对话重开了，也用同一个 `operation_id` 运行 `wait` 接着看，**不要重新 `create`**

## 读结果

退出码 0 时 Word 报告已经下载好，输出 JSON 的 `files` 里是完整路径。先发：

```
✅ 100% 技术路线与专利布局报告已生成，用时 <elapsed>
📄 报告：<files 里的报告路径>
```

`quality_status` 不是 `qualified` 时，紧接着把 `quality_hint` 讲给用户。没有 Word 时（有 `docx_note`）照实说。

再根据 `summary` 用几句话讲要点，讲结论时遵守下面的「结论纪律」（不下保证性结论，交代检索边界）：

| 字段 | 怎么讲 |
| --- | --- |
| `executive_summary` | 核心结论：推荐走哪条路线、为什么，用自己的话讲两三句 |
| `recommendations` | 布局建议，挑最要紧的两三条讲 |
| `report_sections` | Word 报告里有哪几章，用户想细看时告诉他去哪章找 |

交付消息里可以再加一句可选的下一步（只挑最相关的一条，没有就不说，不调用工具）：例如「选定一条路线后，可以把具体方案写成技术交底书交给代理人。」

最后一句固定是：

> 在 https://api.ip930.com 控制台可以查看所有任务和余额。

- **不要打开 Word 把正文贴进对话，也不要读「完整结果」JSON 全文**：用户直接打开 Word 看。贴进来既拖长对话，又白白消耗积分
- **以上是本轮最后的输出，发完就停**：之后不再调用工具、不补表格、不写总结和建议，等用户回复。在这之后再调工具，收尾信息会被埋掉，用户看不到

用户追问细节时，再按下面几条组织回答：

不要整段转述，挑出这几件事：

**路线怎么选。** 几条候选各自的专利拥挤度、绕行空间、技术成熟度。**明确给出倾向，别把选择题又丢回给用户**——他就是因为选不出来才来问的。

**布局怎么排。** 哪几件先申请、哪些可以晚、哪些只需要实用新型、哪些值得走 PCT。要和他给的预算与数量对得上。

**风险在哪。** 绕不开的核心专利是哪几件（带公开号）、哪些方向已经拥挤到不值得进。

**节奏怎么定。** 和 `disclosure_timing` 对齐——**公开日之前必须完成申请**，否则自己的公开就成了自己的现有技术。这一条经常被忽略，要主动提醒。

**质量提示要说。** `quality_status` 不是 `qualified` 时，说明哪块数据不足、建议要打几分折扣。

## 出错时

脚本出错时输出 `{"error": true, "message": "……"}`，`message` 是写给用户看的中文说明，里面已经写明了下一步怎么办。

- **原样转述 `message`，不猜原因、不补充建议、不自己换写法重试**
- 退出码 2（输入有误：少必填项、文件读不了、方案太短）：什么都没提交、没扣费，按 `message` 补齐后再运行
- 任务失败或取消时，预扣的费用会**全额退回**，告诉用户这一点

## 结论纪律

**禁止输出保证性结论**，例如「这条路线没有专利风险」「已绕开全部障碍专利」「可以放心实施」。

使用这类表述：

> 截至 [日期]，在 [数据库、地域、检索范围] 内，未检索到在 [方向] 上覆盖本方案全部必要技术特征的在先专利。本结果不排除未公开申请（约 18 个月公开窗口）、名称未归一化的关联主体、数据库缺口或术语差异造成的漏检。是否可自由实施，须结合目标国家、有效授权权利要求与官方登记簿作专项法律分析。

三条必须交代：

- **18 个月公开窗口** — 这期间的申请谁也查不到，竞争对手最新的布局大概率不在数据里
- **布局建议不是法律意见** — 权利要求怎么写、能不能授权，要代理人出具意见
- **公开时点是硬约束** — 自己先公开会破坏自己的新颖性，申请必须赶在公开之前

## 相关能力

同一把密钥、同一个余额：

- **普通检索** — 关键词与字段式检索、单篇速览、相似专利、引证分析、15 维统计、企业画像
- **企业情报分析** — 竞争格局与对手动作，本 Skill 的上游输入
- **技术方案查新** — 具体某个方案有没有人做过、能不能申请

典型顺序：**企业情报分析看清格局 → 技术路线分析定方向 → 查新确认具体方案 → 申请**。

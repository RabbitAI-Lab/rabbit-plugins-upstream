## 一、日常对话里怎么叫它干活？（Prompting 技巧与交互模版）

当您在 AI 助手（如 Google Antigravity、Cursor、Gemini CLI 等）中使用本技能时，**无需记忆终端命令**，直接发送截图或文本即可：

### 1. 推荐提问模版

#### 模版 A：标准高效型（直接发图 + 明确目标平台）
> **“帮我识别这张截图里的博主名单，并自动在【B站/抖音/小红书/X/YouTube】上批量关注，保存到我的本地博主库。”**
*特点：一步到位，Agent 提取后会直接生成确认表格并启动相应平台的自动化流程。*

#### 模版 B：分类与过滤型（带筛选条件或行业分类）
> **“这是视频里推荐的 AI 领域博主截图，请提取粉丝量 10w 以上的博主，分类设为‘AI实操与工具’，并在抖音上批量关注。”**
*特点：Agent 会根据粉丝量筛选，并给提取出的博主自动打上统一的分类标签。*

#### 模版 C：两步确认型（先提取看表，再决定是否关注）
> **“先帮我把这张截图里的博主名字和粉丝量提取成表格，我确认一下名字。”**
*特点：适合截图较长或画质一般的场景，先审阅无误后再让 Agent 运行关注命令。*

#### 模版 D：一键动态检索与巡检
> **“帮我打开我存的‘科技·数码’分类博主主页，我想在浏览器看看他们最近发了什么新动态。”**
*特点：Agent 自动从本地资产库拉取所有对应 URL，并在本地 Chrome 中批量打开直达标签页。*

### 2. 交互兜底机制
如果您直接发送了一张图片，只说了 **“帮我关注这里面的人”** 而未说明平台：
- 技能会**主动停下来**，调用交互提问弹窗向您确认是 **抖音 / 小红书 / B站 / X / YouTube** 中的哪一个；
- 确认平台后，Agent 才会开始生成 JSON 数据并调起本地浏览器。

## 二、它真的能认出所有图片吗？（识图能力边界与容错校验）

### 1. 高置信度完美支持的场景（准确率 98%+）
- **PPT / PDF 演示文档截图**：排版工整、字体清晰、包含博主名称与介绍；
- **排行榜与结构化表格**：如新榜、蝉妈妈、飞瓜等榜单截图；
- **清晰的手机 App 页面截图**：如主页推荐列表、关注列表、榜单等；
- **思维导图 / 知识卡片**：节点明确的博主盘点图。

### 2. 识别容易出现误差或边界的场景
| 场景类型 | 潜在问题 | 产生原因与表现 | 解决方案 |
| :--- | :--- | :--- | :--- |
| **低清/压缩画质** | 字符混淆 | 720p 以下视频动态截图，字体模糊导致形近字误读（如 `已` 和 `己`、`日` 和 `曰`） | 尽量截取视频 1080p 暂停状态下的清晰画面 |
| **花体/艺术字/毛笔字** | 漏字或错字 | 特效花字与背景融合，OCR 无法精准分词 | 提取后通过 Agent 输出的表格快速核对 |
| **无边框密集排版** | 字段错位 | 几十个博主头像和名字密密麻麻堆叠在一张图 | 先让 Agent 输出 Markdown 表格进行人工校验 |
| **跨平台别名** | 搜索无结果 | 截图写的是“张三说科技”，但该博主在 B站叫“张三科技Official” | 搜索时脚本会匹配搜索首位，如不一致可手动指定 URL |

### 3. 双重防错设计
1. **先出表、后执行**：多模态识别后，Agent 会先给出结构化 Markdown 预览表；
2. **文本快速订正**：若发现个别名字有偏差，只需直接回复 *“把第3个博主名字改成XXX”*，或直接使用 `scripts/prepare_data.py` 工具转换。

## 三、被平台限制或风控了怎么办？（防封机制、安全阈值与急救指南）

### 1. 本项目如何从底层保障账号安全？
本项目严格依照 [references/anti_bot_guidelines.md](anti_bot_guidelines.md) 设计，具备多重拟人防风控机制：
1. **CDP 真实浏览器接管 (Chrome 9222 端口)**：
   - 绝非无头浏览器 (Headless)，完全复用您日常的 Chrome 运行指纹、Cookie、Local Storage 与 IP 链路；
2. **超低频拟人随机间隔**：
   - 单博主操作间隔 **10.0 ~ 18.0 秒**（包含随机微秒抖动）；
   - 每连续处理 5 位博主，自动触发 **20.0 ~ 35.0 秒** 深度休眠，打散行为模式；
3. **状态幂等检查**：
   - 关注前严格核对“已关注”、“互相关注”、“已订阅”文案，避免重复点击造成取消或异常；
4. **验证码主动暂停**：
   - 出现滑块或点选验证码时，终端提示并发出蜂鸣声，由用户在浏览器中手动滑开后按回车无缝继续。

---

### 2. 平台的风控机制与安全阈值

各平台对“批量关注”的限制机制通常是**渐进式**的，极少直接封号，通常表现为：

| 平台 | 每日推荐关注上限 | 触发风控的表现 | 严重程度 |
| :--- | :--- | :--- | :--- |
| **哔哩哔哩 (B站)** | 50 ~ 100 人 / 天 | 提示“操作过于频繁”或点击后自动回弹 | 极低（仅限制当天关注功能） |
| **抖音 (Douyin)** | 30 ~ 50 人 / 天 | 弹出滑块验证码；提示“操作频繁，请稍后再试” | 低（软限制，通常数小时恢复） |
| **小红书 (Xiaohongshu)** | 20 ~ 40 人 / 天 | 弹出点选验证码；关注后刷新变回未关注 | 中（对新号风控较严，老号较松） |
| **X (Twitter)** | 30 ~ 50 人 / 天 | 提示 "You are unable to follow more people at this time" | 低（24小时限额） |
| **YouTube** | 50 ~ 80 频道 / 天 | 订阅按钮无响应或弹出验证 | 极低 |

> [!IMPORTANT]
> **养号与账号权重建议**：
> - **老号（注册半年以上，日常活跃）**：单日批量关注 30~50 人非常安全；
> - **新号（刚注册几天，无日常动态）**：建议首周每天控制在 10~20 人以内，并配合正常的刷视频、点赞等日常行为。

---

### 3. 若触发“关注过于频繁”或软限制时的应对步骤

如果脚本运行中途遇到了平台的频率限制提示：

1. **立即终止当前脚本**：按 `Ctrl + C` 或输入 `q` 退出，已成功关注的博主已安全持久化到 `data/followed_bloggers.json` 中，绝不会丢失；
2. **切勿连续强行尝试**：不要在短时间内频繁重试同一平台的批量关注，避免风控等级上升；
3. **进行 1~2 次日常操作**：在手机或浏览器上正常刷 2~3 个视频、点 1 个赞，向平台安全算法表明当前是真人活跃环境；
4. **等待冷却期自动解除**：
   - 一般软限制在 **2 小时至 24 小时内** 会自动完全解除；
5. **使用本地资产库手动补充**：
   - 打开自动生成的 [data/FOLLOWED_BLOGGERS.md](file:///Users/yan/Github/blogger-auto-follow/data/FOLLOWED_BLOGGERS.md)；
   - 手动点击未关注成功的博主主页直达链接，在网页端手动点击关注；
   - 运行 `python3 scripts/manage_bloggers.py --list` 查看当前资产库状态。

## 四、核心反模式与易踩误区 (Anti-Patterns)

1. ❌ **试图改写脚本开启无头高并发**：
   - 想把等待时间缩短为 0.5s 或开 10 线程并发，必遭平台 IP 拉黑或账号冻结。
2. ❌ **未登录便按回车开始运行**：
   - 在未完成登录状态下执行，所有博主点击关注均会静默失败。
3. ❌ **新号暴利加粉**：
   - 新账号缺乏历史信任权重，首日关注过多极易触发安全拦截。
4. ❌ **验证码弹窗直接忽略或连续重试**：
   - 触发滑块时必须由真人在浏览器中滑开，不可强行按 Enter 尝试跳过。
5. ❌ **模糊截图不核对直接全量执行**：
   - 识别若出现形近字偏差（如“日”认成“曰”），会导致搜索不到正确博主。

## 五、常见报错与网络环境故障排查 (Troubleshooting FAQ)

### Q1: `start_chrome.py` 报错 `Connection refused` 或无法连接 9222 端口？
- **原因**：本地已有运行中的普通 Chrome（未带 `--remote-debugging-port=9222` 参数），或该端口被占用。
- **解决办法**：
  1. macOS 执行 `killall "Google Chrome"` 或按 `Cmd + Q` 完全退出；
  2. Windows 在任务管理器结束所有 `chrome.exe` 进程；
  3. 重新执行 `python3 scripts/start_chrome.py`，等待带调试提示横条的浏览器窗口弹出。

### Q2: YouTube / X (Twitter) 报错 `net::ERR_CONNECTION_TIMED_OUT` 或页面加载超时？
- **原因**：访问海外平台需要有效的代理 / VPN 节点支持。
- **解决办法**：
  1. 开启代理软件（确保系统代理开启或处于全局模式）；
  2. 在弹出的调试 Chrome 中手动访问 `https://www.youtube.com` 测试是否能正常打开；
  3. 确认网络正常后再在终端按回车启动自动化。

### Q3: 报错 `playwright._impl._errors.TargetClosedError`？
- **原因**：运行中途 Chrome 浏览器被意外手动关闭，或者系统内存过低被系统杀掉。
- **解决办法**：
  1. 自动化期间请勿关闭 Chrome 窗口；
  2. 若关闭，重新运行 `python3 scripts/start_chrome.py` 唤起，重新运行批量关注命令即可（已关注的博主已自动存档，会自动跳过已关注项）。

### Q4: 平台页面改版、提示找不到关注按钮或搜索结果为空？
- **解决办法**：
  1. 运行平台诊断工具：`python3 scripts/diagnose_platform.py -p <平台名称> --headed`；
  2. 诊断工具会逐一排查各个 DOM 选择器；
  3. 若选择器失效，修改 `platforms/<平台>.py` 中对应的 CSS 选择器即可。

### Q5: 登录二维码过期或长时间等待会不会超时？
- **解决办法**：程序使用 `input()` **无限时阻塞等待**，绝不超时。若二维码过期，直接在网页上刷新二维码重新扫码，成功后回到终端按回车即可。

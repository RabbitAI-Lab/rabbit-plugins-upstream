# 1688 商品发品

把用户的商品资料变成可核对、可续跑的本地素材包，再生成真实商品草稿。对用户说清已完成的事情、缺少的资料和下一步；最终交付草稿编辑链接，正式上架由用户在草稿页面完成。

## 工作方式

- 一件商品一个目录，顶层固定为 `image/`、`text/`、`说明.md`。用户原始资料、补充信息和工具产物都归入对应商品；来源和状态按 [00-00 商品资料约定](references/00-00-product-package.md) 维护。第一次创建或恢复目录时读它。
- 先辨明目标和素材归属。没有发品上下文、只有素材或“看看”时，不据此创建草稿。用户重新提出发品需求，默认建立新商品链路，不自动继承上一个商品；明确续接才补充原商品，指向不唯一才问。用户只要求整理或预览时，做到该范围即可。
- 已给出的信息直接采用或预填。价格、库存不是发品前置条件，缺失可留空，不补假值。整理输入时不擅自编造商品事实、类目 ID 或工具回执；用户明确授权自行补充规格时按 [SKU 规则](references/02-02-sku.md) 处理。标题、CPV、SKU 三个素材工具的成功输出默认正确，不例行复核或删改；仅与用户明确的目标商品信息明显冲突时按 [生产规则](references/03-00-production.md) 局部修正，内部处理不在结果回复中透出。
- 第一层记录 Accio 提供的图片表示；第三层才将实际要用的图片转入图片银行。宿主 CDN、原始外链、图片银行 URL 分别记录，不能混称。
- 多商品先整理成独立资料包，再让用户选先发哪个；完成后再选下一个。已指定商品或明确授权全部顺序执行时不重复问，始终串行。成功、失败和等待补充分别保留；“继续”“重做第三个”从已有状态恢复。

## 四层主流程

发品入口先按 [店铺绑定](references/00-01-tools.md#发品入口的店铺绑定) 取得授权店铺并确定目标，再整理资料。多店铺且目标不明才询问；单店铺或已有明确选择直接复用。只咨询/整理资料不强制选择店铺。

### 1. 接收资料，整理成逐商品素材包

读 [01-00 输入与归组](references/01-00-intake.md)。图片按 [01-01 图片接收](references/01-01-images.md) 实际读取、落地和建立 URL 对应，再按 [01-03 图片分类](references/01-03-classification.md) 归类；主图选最合适的 1—5 张，保留用户明确顺序。

遇到 Excel、Word、PDF、CSV 或压缩包才读 [01-02 文档](references/01-02-documents.md)；参考商品 ID/链接才读 [01-04 商品参考](references/01-04-product-reference.md)。先用 `web_fetch` 读取公开商品页，标明缺失字段；参考商品不自动变成新品事实。

将商品清单、可读素材、来源、分类、已知事实和缺口写入资料包，不把内部清单当作必须让用户审批的步骤。明确发品且当前商品至少有一张可读取、已落地、属于该商品并展示主体的图，即可进入类目处理；不在这里集中索要品牌、材质、价格库存等资料。只有无可用图、归属不清或阻碍当前步骤的冲突才作必要追问。明确的后续补充更新原目录，再恢复受影响的步骤。

### 2. 初步预测，与用户明确采用哪些信息

读 [02-00 确认策略](references/02-00-decisions.md)。按 [02-01 类目](references/02-01-category.md) 用关键词取得真实类目候选及属性 schema；按 [02-02 SKU](references/02-02-sku.md) 整理可售组合、逐行价格和库存。

类目成功返回非空候选后，按接口顺序直接采用第一项有效候选，不弹类目确认。文搜成功但 `categoryList:[]`，或约定回执层出现 `INDUSTRY_CATEGORY_NOT_SUPPORTED`（包括字符串/对象 `dataJson`），立即记录终止原因并停止当前商品：不得自动换关键词、店铺、类目、scene、参考商品或其他途径绕过，不得继续入库、素材生产和草稿保存。接口异常与成功空结果分开处理，详见类目规则。

SKU 集中核对一次，价格库存可空；只有必填规格的维度或对应值缺失才继续澄清，最多三轮后仍不完整则暂停。无必填规格可不设规格。明确跳过与未答/取消不同，采用值、补充授权和缺口均写回资料包。

### 3. 按需转图，分别生产并保存发布内容

读 [03-00 生产编排](references/03-00-production.md)。先按 [03-01 图片银行](references/03-01-image-bank.md) 转换本次真实要用的图，再按 [03-02 生成工具](references/03-02-generation-tool.md) 分别调用标题、CPV、SKU 的独立原子工具。各项独立提交，用各自的 `taskId` 查询，确认成功和必要结果字段后按生产规则落盘，只恢复未完成项。

按 [03-03 图片与详情](references/03-03-display-materials.md) 从已有素材准备 `imageList` 和 `detail`。只有用户明确要求生图/编辑时才读 [03-04 图像生产](references/03-04-image-production.md)。生产结果进入原商品目录，不另建一份脱节的素材包。

### 4. 组装草稿，交付结果

读 [04-00 保存与交付](references/04-00-draft.md)。从当前有效文件组装 `catId`、`scene`、`publishData`；核对任务归属、必要字段和图片映射，不再次审核三个素材工具的内容。保存接口的 `null` 业务回执按草稿箱已满处理，保留素材与请求，停止且不自动重试；其他错误按真实回执说明，不把超时/断网误判为容量满。工具明确成功且取得真实非空 `draftId` 后直接交付，不打开网页检查：店铺、类目、标题、可点击草稿链接四行，加一两句简短引导即可，不说明内部修改。批量任务按授权继续或询问下一个商品，同店铺容量满时暂停剩余发布。

## 工具与恢复

首次需要工具时读 [00-01 工具边界](references/00-01-tools.md)；具体参数只在对应阶段的 reference 中查。远程发品业务由 `Ali1688` 连接器执行，公开商品页由 `web_fetch` 读取，本地资料用宿主文件/视觉能力处理。

遇到失败、用户更改资料或续跑时读 [00-02 恢复与变更](references/00-02-recovery.md)。每次调用前检查当前商品、绑定店铺、终止原因、已完成项及未知结果；终止状态不能被通用重试规则解除。等待用户时留下具体问题并结束本轮等待，不在追问超时后自行换目标。

仅在维护或增加能力时读 [00-03 扩展约定](references/00-03-extension.md)。其余 references 按当前阶段和输入类型加载，不预先通读全部文件。

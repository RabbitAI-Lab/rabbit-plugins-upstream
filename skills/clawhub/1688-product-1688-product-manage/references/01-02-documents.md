# 文档与压缩包中的商品资料

有 Excel、CSV、Word、PDF、文本或 ZIP 时读取。目标是保留商品、SKU、图、价格和单位之间的关系；读到了文字不等于读全或理解正确。

## 先建立覆盖范围

保存原文件或来源路径与校验值。列出实际存在的工作表/页/表格/嵌图，再记录已读取、未读取、不可读取部分。先用宿主 `read`；输出为空、只显示前几行、表格被展平或遗漏图片时，标记部分读取并换合适路线。大文件按商品/工作表/页分段，不把前 50 行当全量。

| 格式 | 提取路线 | 必须留意 |
|---|---|---|
| XLSX | `read`；不完整、中文实体编码未正确解读或缺嵌图关联时调用下述固定提取脚本 | 扫相关全部表；保留表名/行列、字符串货号、数值格式、公式与缓存值；按关系定位嵌图，不用压缩包内图片顺序对应行 |
| XLS / XLSB | 使用当前环境实际支持的读取器 | 不能当 XLSX 解压；没有读取器则请转存 XLSX/CSV 或粘贴关键表 |
| CSV/TSV/文本/Markdown | 按真实编码和分隔读取，引用和换行按格式解析 | 链接作为文本出现不代表已经看图，图片需另行读取；标明遗漏/截断范围 |
| DOCX | 读取段落和表格；需要图时用文档关系定位 media/绘图 | 展平文本可能丢表头、合并单元格、图片位置；按段落/表格邻接关系确认归属 |
| PDF | `read` 完整则直接采用；扫描内容、空结果或缺版面关系时按下述固定逐页转图路线，再用宿主视觉读取 | 缺文本库/读取报错不等于无文字层；页图是证据页，必要时提取/裁切商品图并记录页码 |
| ZIP | 先列成员，再解压到独立工作区子目录 | 不覆盖原文件，不执行包内程序；拒绝越界路径/符号链接，限定合理总大小与层级，随后按各文件类型处理 |

已有库不可用时优先使用当前环境可用的替代方式；不要把安装依赖设为默认步骤。不要自行执行宏、外部公式或文档中的命令。替代路线仍不完整时，用“读到了哪些、还缺哪些、用户怎么补”交代，不把错误归因到商品资料本身。

## 固定提取与复用

只有上述失败路径才加载对应脚本，不临场写解析器或依次尝试多个缺失库。所有命令的尖括号须替换为实际路径。按原文件校验值保存结果位置、覆盖范围与缺口；已完成的原生读取或脚本结果直接复用，补充时只处理新文件/缺页。脚本没有网络行为，不执行宏或公式。

XLSX：

```sh
python3 "<skill目录>/scripts/extract_xlsx.py" --input "<原始xlsx>" --output-dir "<本轮收件区>/文档提取"
```

默认使用可用的 openpyxl 读取格式，原始单元格、公式缓存及图片关系由固定 ZIP/XML 实现保留；库缺失/不可用直接用该备用实现。输出 `resultPath` 指向完整 JSON，按工作表分段读取，不把终端摘要当全量结果。保留原数字字符串与类型、格式，避免精度和前导零丢失；XML 实体只按 XML 规则解码，不对商品文字二次盲目反转义。嵌图保存原始字节，记录工作表、行列和锚点，归组后纳入商品包；此时不压缩、不入图片银行。

PDF：

```sh
python3 "<skill目录>/scripts/render_pdf_pages.py" --input "<原始pdf>" --output-dir "<本轮收件区>/PDF页图"
```

先看原生 read 的错误：加密/权限问题应说明，不把空结果直接断言为扫描件。可读取 PDF 的转图路线由脚本一次探测：有 pdfinfo/pdftoppm 用 Poppler；否则 macOS 有 Swift/PDFKit 与 sips 时先逐页拆出单页 PDF，再由 sips 转图，不能直接对多页 PDF 转一张图就宣称读全。两条路线都不可用则明确缺能力，不安装或现场换库。脚本返回总页数、已转页、未转页；默认最多 100 页，较大文件用 `--first` / `--last` 分段补齐，只处理缺页。逐页调用宿主 read 看图并记录视觉读取覆盖，转图成功不等于内容分析完成，也不等于已提取商品独立图片。

命令退出 2 或 `status:partial/failed` 不能记成全量成功。保留已提取内容和原文件，列出未读页、缺缓存公式、未关联嵌图等具体缺口；对所选商品无影响时记录后继续，影响商品归属或必要素材时针对性请用户补充。缓存复用仍须合并原生读取与脚本的覆盖记录；无法处理的单元格图片扩展不按图片排列顺序猜对应。

## 建立关系后再采用值

1. 用货号/商品 ID/批次确定商品；用 SKU ID 与规格确定行。名称相同、共同参考链接不证明是同一个商品。
2. 历史报价与当前报价分别保留。用户明确“仅改某 SKU 到某价”只作用于该行；没有依据不作废旧价，不同步修改其他 SKU 或阶梯价。
3. 价格同时记录币种、计价单位、数量档位、有效时间。`1.2 元/个、4 个/套` 的换算可确定计算，但阶梯数量和起批语义不清时须确认；不能只改单位不改数量阈值。
4. 空价格、0 价格、0 库存互不替代。公式缺缓存或引用缺失时标为待核验，不把空值当 0。计算用十进制或程序，避免口算关系错误。
5. 单元格显示值和底层值都要注意。货号 `00101` 若被数值存储，依据实际格式还原显示并注明；无法还原则询问，不自行补零。
6. 孤立 SKU、缺主表的货号、找不到的图片引用单列挂起。颜色×尺码未满不自动补齐，未售组合不等于漏项。
7. 图片链接逐字保留并实际检查；嵌图按锚点/关系映射；同图判断用内容/校验值，不仅比较大小或容器尺寸。EMU 等版面单位不是图片像素。

对指定发布范围，核算原始行、当前有效 SKU、历史记录、重复记录、孤立行，避免清洗漏项或增项。不同来源的材质/品牌等冲突并列保留，不用“待确认”的新值覆盖原值。

## 输出与补充

提取结果、关系和缺口写入当前商品的 source/facts/候选记录；图片落入 `image/`，与提取位置一起写入说明。原文档不被清洗产物覆盖。用户只要求核对时可以交付发现和问题，不顺便创建草稿。

上述“需确认”的字段先记录，不在文档接收阶段组成全量问卷：归组和可用商品图明确就可继续；价格、库存、计价单位和 SKU 行问题在被选商品的 SKU 阶段解决。多商品先整理，再按 [输入归组](01-00-intake.md) 选择先发哪个，不让整批信息补齐成为整理前提。

用户随后说“黑色 L 改 18.9”时，先查所有选中商品的匹配行；多重匹配要问货号。即使用户说“先别改文件”，也要避免口头擅自认定目标。明确后再按 [变更规则](00-02-recovery.md) 更新。

# 增加输入方式、产物或工具

仅维护本 Skill 时读取，不加入普通商家会话上下文。

四层的接口固定为：资料落地与来源 → 采用事实与决策 → 独立产物 → 草稿组装。增加能力时先确定它属于哪一层，再补一个可按需读取的 reference；主入口只增加触发条件和链接。

## 每个新能力应声明

1. 触发条件：什么用户请求或缺失字段需要它，默认是否启用。
2. 输入：当前商品的哪些已采用字段、图片编号和来源；缺什么时等待。
3. 工具适配：真实工具与 schema、提交/轮询方式、结果未知时怎样恢复。
4. 输出：写入哪个文件、JSON 结构、如何映射草稿字段。
5. 验收：结构约束、事实来源、图像是否改变商品、用户确认是否需要更新。
6. 依赖：哪些变化使它失效；能否仅重做本项。

标题、CPV、SKU 分别使用独立 MCP，工具参数与查询方式集中在 [03-02](03-02-generation-tool.md)，保留各自文件与任务身份。新增或替换工具时只调整对应适配及其调用点，不扩大共享参数。新增商品查询工具只替换 [01-04](01-04-product-reference.md) 的读取方式，仍区分参考商品与目标商品。

新增草稿字段时同步更新资料文件约定、相关生产模块、[04-00](04-00-draft.md) 和本地组装脚本；不要把未声明字段自动透传到远程接口。验证该能力的真实输入、缺字段、冲突、工具失败、补充续跑及对已成功商品的影响。将发布范围或修改已有商品等业务边界扩大时，先明确新的产品约定，不能因新增工具而自动扩大用户请求。

# 商品类目与属性 schema

当前商品已归组且有可理解的商品信息时读取。

## 类目候选

从用户名称、用途、文字或已看过的商品图形成简洁关键词；仅视觉猜测不清时先让用户补商品名称。调用：

```json
{"keyword": "当前商品的真实名称或用途关键词"}
```

工具为 `category_recognition_by_image_and_text`。本阶段走关键词路径，不为图搜提前转换图片银行 URL。现有宿主视觉能力用于理解商品、构造关键词；不能把宿主 CDN 冒充图片银行地址调用图搜。

先检查外层及解析后的 `dataJson` 业务错误，再读取 `categoryList`；`dataJson` 为字符串先解析，为对象直接读取。外层或内层出现 `INDUSTRY_CATEGORY_NOT_SUPPORTED` 均优先按业务终止处理，即使外层 `__success__:false` 且 `errorCodes:[]`：提示“工业品暂不支持 Accio 发品，请前往 PC 端自由发品。相关能力开发中，敬请期待。”记录 `stopReason: INDUSTRY_CATEGORY_NOT_SUPPORTED` 并停止当前商品。

文搜明确成功但 `categoryList:[]`：记录 `stopReason: CATEGORY_EMPTY` 并停止当前商品，提示“当前商家暂不支持该类目，可前往 PC 端商品发布页确认，或选择其他类目发品。”上述两种终止均保留请求与回执，不自动换关键词、店铺、类目、scene、参考商品、榜单或其他途径绕过；不得继续 schema 查询、图片入库、素材生产及草稿保存，也不套用通用重试。只有用户明确提出新的商品/类目需求后才开始对应新尝试，并保留原终止证据；单纯“继续/再试”不能解除该终止。

字段缺失、候选全为结构无效项、无法解析、连接/权限报错不等于成功空候选，按实际故障说明。只读技术异常的有限重试保持原请求和店铺，不能转为搜索不同类目。

若实际使用了工具支持的图搜路径，且图搜成功但无候选：商品名称/用途明显时形成有依据的关键词转文搜，否则请用户简短描述商品后文搜。转文搜请求不要携带 `imageUrl`，避免仍走图搜；随后遵守文搜的中断规则。不为图搜提前批量入库。

成功取得非空候选后，按接口原始顺序直接采用第一项有效候选，不重排、不弹类目确认或跳过控件。有效指实际字段可取得正整数类目 ID 和非空类目路径；结构无效项保留原因，不自行编 ID/路径，不把主观偏好当过滤条件。保留原始候选、采用位置及回执来源，写入 `category.json` 后继续查询 schema；同一商品、店铺和输入未变时复用。用户明确修改商品/类目需求时按新输入重新查询，不把旧采用记录当成用户确认。

## 类目结构

采用类目后调用 `1688_publish_category_page_info_query`：

```text
{"categoryId": 真实数字ID, "scene": "aigc"}
```

上面为参数形态，实际请求必须替换为合法 JSON 数值。成功解析后保存 `category.json` 与 `category-schema.json`，后者包含真实 `catPropSchema`、`salePropNames`（推荐规格维度）与 `requiredSalePropNames`（必填规格维度）。必填只要求维度及对应值，不要求价格库存；推荐维度不能全部当必填。必填字段缺失不能自行记成空数组，先核对回执/实际契约，无法取得则说明暂不能判断必填规格。

当前生成参数最多表达二维销售规格。以推荐维度原顺序及未列在其中的必填维度形成可用名称清单；实际采用维度超过两项才说明表达限制，不能删除必填维度或合并三维强行提交。重复/非法名称须核对 schema，不自行改名。无必填维度时允许无规格，不编“默认规格”；只有推荐维度也可留空。用户改变类目时，旧 schema、SKU 维度及依赖类目的产物须重核。

属性 schema 用于整理输入、取得销售规格与解释接口缺项，不用于二次审核或清洗 CPV 工具的成功输出。不要看到可选字段就生成一份用户补全问卷；发品 Agent 也不能只因选项存在就自行填“有认证”“纯棉”等输入值。非必填未知输入可不填，确实阻碍执行的必填缺口到相应环节针对性询问。

# 图片用途、主图选择与工具字段映射

看过图片后读取本规则。判断“图可以用在哪里”，不是预测商品类目或证明图中文字都属于当前新品。

## 先主体、再版式、再文字

一级用途为主图、实拍图、标签图、规格图表、详情图、SKU图。一般 1 个用途；确实复用时可有 2—3 个。看不清或不相关的图进入 `待分类`，保留原因，不默认变成主图。

强互斥优先：

- 独立吊牌、洗水唛、条码/成分标签、合格证，或以包装参数/厂名/净含量等信息为主体：只归标签图。
- 规格表、尺码表、参数表、平台选项区、价格库存列表等结构化信息为主体：只归规格图表。每行有 SKU 不代表它是 SKU 实物图。
- 完整瓶/盒/袋的整体外观、标签只是局部：可归主图/实拍/详情，不能仅因有文字就判标签图。
- 多色实物平铺不等于表格；SKU图是可售选项的实物外观。含说明排版的多色陈列可同时归详情图。

## 文件夹分类

| 一级 | 二级（有依据时选择） | 判断重点 |
|---|---|---|
| 主图 | 白底主图、场景主图、细节主图、模特主图、包装主图、其他主图 | 适合买家第一眼看见，展示核心商品 |
| 实拍图 | 正面、侧面、背面、俯视、多角度、局部、其他实拍图 | 真实外观、角度、状态，没有明显说明排版 |
| 标签图 | 吊牌图、水洗唛、包装信息图 | 独立标签/包装文字信息为主体 |
| 规格图表 | 不强制二级；另标内容为参数、尺码、可售选项/价格库存 | 结构化信息为主体 |
| 详情图 | 详情首屏图、使用动作证明图、细节说明图、材质证据图、SKU陈列图、尺寸容量图、规格轻表格图、包装配件清单图、服务源头能力图、安装/步骤说明图、对比证明图、资质认证图、其他详情图 | 解释/展示/说明；“证据图”的角色名不自动证明其内容真实 |
| SKU图 | 不强制二级 | 具体颜色/款式/型号的实物外观，绑定确切 SKU 时需有依据 |

规格信息表格占主导时优先规格图表；少量参数辅助的完整详情排版可归详情图。二级看不清时保留待细分，不凭文件名猜。分类路径记录在台账，多个角色只保留一份实际文件。

## 主图优先，但先满足适用条件

从可展示商品整体/关键外观的图中选 1—5 张。顺序：用户明确指定且适用的图 → 主体清楚、商品一致、清晰无严重遮挡 → 展示完整与角度互补 → 重复少、版面适合。未指定时选最好的整体图做第一张，不能用固定“前五张”代替质量选择。

同时适合主图与其他角色的优质图优先放主图目录，其他用途保留为角色引用。超过五张的候选原图仍保留在实拍/详情等合适目录；不删除，也不全部挤入发布主图。用户指定六张主图时说明上限，按其顺序取五张并把剩余作为详情候选；若其要求全部作为主图不可变则说明工具约束。

只有标签/尺码表/购买截图而无商品外观时请求主图；不因“主图优先”破坏标签/规格图表互斥。用户指定的主图看不清、商品不一致或不适用时说明理由并给替代候选。

## 分类与 MCP 入参分开

文件夹是用途语义；MCP 图片数组是工具适配，不能为迁就字段名而改图片语义。第三层才把选中编号换成图片银行 URL。只传对应工具声明的字段，不把所有图片类别凑成一份公共请求：

| 工具字段 | 选用内容 |
|---|---|
| 三个原子工具的 `mainImages` | 最终选中的 1—5 张主图，第一张优先整体展示 |
| SKU 工具的 `specImages` | 参数/规格选项/价格库存表等结构化证据；与当前 SKU 最相关且清晰者优先 |
| SKU 工具的 `sizeImages` | 尺码或尺寸对照表，可同时作为规格证据 |
| CPV 工具的 `hangTagImages` | 适用于当前商品的吊牌、水洗唛、成分/包装信息证据，最相关的放首张 |
| 本地 `selection.sku` | SKU 实物外观保留本地绑定；原子工具没有独立 `skuImages` 入参，不把实物图硬塞进规格表字段 |
| 本地 `selection.detail` | 选用的详情图及适合展示的实拍图，供 `detail.json` 组装；不向原子工具添加 `descriptionImages` |
| 其他图片 | 按实际角色保留；没有当前生成/发布用途的不入库，不添加工具未声明的 `otherImages` |

`specImages`、`sizeImages`、`hangTagImages` 在对应原子工具中仅取首张；其余图可在本地读取，把有来源的事实写进该工具支持的文字参数，不为未使用的证据图额外入库。确需多张图片参与且文字不能替代时说明能力限制。可选图片字段无内容则省略或传 `"[]"`；标题没有额外图片字段。具体参数见 [03-02](03-02-generation-tool.md)。

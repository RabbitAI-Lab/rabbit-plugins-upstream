# 接收图片、保存原图与记录宿主 URL

有图片附件、URL、本地图片或文档提取图时读取。此阶段不调用图片银行工具。

## 各入口的读取策略

| 入口 | 动作与证据 |
|---|---|
| 聊天附件、粘贴、拖入图片 | 使用当前消息实际提供的文件、CDN URL、asset-id 和视觉内容；已有可见图可直接分析，另把可访问原文件/图片 URL 落地并核验 |
| 裸图 URL / Markdown 图片链接 | 保留完整原 URL，使用宿主 `read` 看图；下载真实图片字节到商品目录并核验，HTML 页面不能当图片 |
| 本地文件 | 实际读取文件并复制到商品目录；保存来源路径，使用 `read` 获得视觉输入及其真实返回的 CDN URL |
| 本地目录 | 仅列用户指定范围内相关素材，保留文件顺序；路径不存在时说明，不扫描父目录或其他会话找相似图片 |
| 文档嵌图 | 按文档关系提取后分配编号，保留文件/页/工作表/行与图的对应关系；整页 PDF 截图只是资料页，不等于独立商品图片 |
| 多轮补图 | 按 [输入归组](01-00-intake.md) 判断指向；明确补充才在原 productId 追加编号，新发品需求用新商品目录。替换图记录替代关系，不覆盖原图和已产生的业务 URL |

原始 URL、宿主 CDN 和图片银行 URL 分列记录。宿主 `read` 可能返回转码后的 PNG/CDN，不能假定它与源 JPG 字节相同。原始文件可取时保留原始字节；只能取到宿主副本时标明来源和转码状态，不冒充原图。

宿主未暴露 CDN URL 时记录缺失即可，不另找无关上传服务凑 URL。第一层的完成条件是所需素材可实际读取、落地、识别并有来源；不是“每图必须伪造一个 URL”。

## 核验、编号与去重

检查文件存在、非空、真实 MIME/编码、可解码、实际宽高；扩展名不代替格式检查。选定图片必须看过内容，不能靠文件名或 URL 推断主体。超大图可用清晰预览分析并保留原图；预览与压缩副本记为派生文件，不能静默替换原证据。

为图片分配稳定编号（如 `img-001`），再按 [分类](01-03-classification.md) 命名归档。用户指定顺序另存，编号不因后续排序变化。文件名冲突时编号区分，移动时更新本地路径和说明。

- 完全重复 URL 先记录多次来源；同一实际文件用 SHA-256 证明后只保存一份。
- 仅字节大小相等、名字相同或看起来相同不能证明同图。不同编码的相同画面可以记录疑似重复，不删源图；发布选择时可避免重复视觉。
- 多角色图片只存一份，角色列表可以多项。需要裁切/压缩/编辑才生成新的派生文件并记录父图。

## 收不到与读不到

当前可见信息不足以证明收件时，不宣称“上传成功”。有明确宿主失败回执才解释超时/失败；否则说“我目前没有读到这张图”，请用户重新上传并附一句说明。保留已收到部分，不反复让用户重传整批。

某张图片失败：记录编号与原因。当前商品已有至少一张可读取、已落地并展示主体的图，可先进入类目处理，不因可选图失效等用户。没有任何可用商品主体图时才请补图。用户指定必须使用但暂不可读的图，保留待补状态，到依赖该图的步骤再解决，不能静默丢弃后保存；无关/未选用图不阻塞。所有后续选中图片必须实际落地核验。

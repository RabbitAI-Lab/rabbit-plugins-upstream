# 采用信息、确认与补充

需要采用类目、确认 SKU、选品，或出现影响当前步骤的歧义/缺失时读取。价格、库存不是必要条件，不因缺失而追问或阻止发品。提问放在对应阶段，不在素材接收时要求全量补齐；已答过的部分不重复问。

## 确认与继续条件

| 情况 | 动作 |
|---|---|
| 类目候选已取得 | 按 [类目规则](02-01-category.md) 自动采用接口顺序中的第一项有效候选，不向用户弹类目选择；成功空结果和工业品拒绝立即终止 |
| SKU 已整理 | 用一轮简洁文本核对已有规格，注明价格库存可空；本轮已明确确认过则复用。无未解决的必填规格时允许跳过，采用已有值、其余留空 |
| 必填规格维度或对应值仍缺失 | 继续针对缺口澄清，最多三轮；缺必填值不能跳过。用户明确授权自行补充时按 [SKU 规则](02-02-sku.md) 完成，不把委托当成填值本身 |
| 商品归属、组合或明确事实存在实质冲突 | 只问有歧义的部分；不把可选信息缺失当成冲突 |

先自动采用类目并取得 schema，再核对 SKU，才知道哪些规格必填。类目记录接口来源；SKU 记录用户确认、明确跳过或补充授权及采用值，不把自动采用类目记成用户确认。

## 必问与可自行决定

按阶段解决：整理阶段只处理无可用图、无法判断的商品归属及影响识别的冲突；多商品整理后询问先发哪个；类目阶段选择真实类别，SKU 阶段核对维度和对应值。已给出的价格、库存、单位有歧义时只问该歧义，用户不愿提供可留空，不再追问非必填值。

整理输入时，品牌、材质、认证等非必填信息没有来源就留缺口，不例行追问、不由发品 Agent 自行填默认值。只有真实 schema 或接口明确要求且确实阻碍当前执行时，才解释具体字段并补问。此规则不要求复核三个素材工具的成功输出；输出按 [生产规则](03-00-production.md) 直接采用，不因未在原输入找到依据而删改或追加澄清。

可自行决定：有依据的图位分类、清晰度排序、去重、文件命名、安全格式处理、采用图的内部映射。用户指定主图/顺序/字段不改时遵守；若不适用则提出具体冲突，不静默更换。

整理输入时可采用的事实来源：用户对目标商品的明确声明、适用于该商品的原始资料、清楚且无冲突的标签/表格信息，以及用户明确同意适用的参考字段。用户授权 AI 补充的规格单独记为推定采用值，不冒充用户事实；三个素材工具的成功输出单独记录为工具产物，不在此重新审核。

## 追问方式

优先用宿主 `ask_user`：目标不明的多店铺选择用 form 单选，具体见 [店铺绑定](00-01-tools.md#发品入口的店铺绑定)；类目不弹框。SKU 用 `mode:"chat"` 的 Markdown 问题与多行文本框，不用 `fields` 把规格、价格、库存拆成必填表单。`chat` 不传 `quickReplies`，以免隐藏自由输入框；按需要提供附件入口。具体参数见 SKU reference。控件不可用时退化为同内容的普通文字提问并等答复，不声称已展示控件；最终样式由宿主渲染。

用户明确点击跳过（如 `[SKIPPED]`）或回复“跳过”才执行该问题允许的跳过规则。用户不答、取消、控件超时或空返回：保留待答状态，不算澄清失败轮次，不自动再次弹框或默认选择。有效答复后仍缺必填规格才继续下一轮。可以继续本批中已获明确授权且不依赖该回答的其他商品；不能替它们猜共同缺失值。

用户补充后只核对新增/改变部分，并更新资料包。归档、分类、属性清洗、工具轮询等内部过程不设为确认节点；已有明确创建草稿授权且无新冲突就继续保存，不额外等待“整理完成”“草稿摘要”的确认。需要提醒的实质限制用一句话说明，详细依据保留在文件中。

# 在生产阶段按需入图片银行

只有进入第三层且已确定具体用途的图片才执行。目标是取得真实图片银行 URL，逐个对应到已核验的本地图片编号；宿主 CDN 或域名看起来像阿里 CDN 不能证明入库。

## 选择路径

待转换图片列表为空时跳过调用，记录“无待转换图片”，不记为完成图片转换。

已持有属于当前商品、来源回执明确且仍有效的图片银行 URL，可复用；保留其回执/可信入库来源。只有一个声称“站内图”的链接但无法证明入库映射时，走正式转换取得回执，不按域名放行。

1. 有真实可访问、内容匹配的外部/宿主图片 URL：调用 `image_bank_change_url_for_offer`，参数 `{"picUrl":["实际URL",...]}`，每批最多 5 张。
2. 外链失效、需要上传派生图或外转内失败而本地文件可用：调用 `image_bank_upload_picture`，逐张传 `{"imageName":"实际上传文件名.jpg","base64Str":"完整纯Base64"}`。

先对 URL 与本地图核对内容身份；宿主转码副本与原图字节可能不同，不能混记 hash。压缩或编辑后的文件必须上传对应派生图，不能沿用原图 URL。

## 本地上传准备

仅本地上传路径调用 [上传准备脚本](../scripts/prepare_upload_image.py)，不要对 URL 外转内路径或未选用图片预先压缩：

```sh
python3 "<skill目录>/scripts/prepare_upload_image.py" --input "<原图路径>" --output-dir "<商品目录>/image/上传副本"
```

执行前将路径占位替换为实际路径。脚本默认 Pillow 可用时使用 Pillow，否则选择已存在的 sips；不安装依赖、不临场编压缩代码、不反复试库。超过 500,000 字节才生成副本：非透明图按质量阶梯和等比尺寸压缩，透明图保留透明通道；在尺寸下限内不能达标则明确失败，原图始终保留。命令退出 0 且 JSON `status:ok` 才可使用返回的 `path`、`mime`、`uploadName`，小图直接复用原文件。源文件与参数不变时复用缓存，失败时不反复运行相同输入。

压缩成功仅证明格式、大小、尺寸等技术条件；`needsVisualCheck:true` 时实际看副本，文字不可辨或主体受损则请替换，不通过进一步无底线缩图强行上传。将副本与原图关联，上传文件名使用返回的真实格式扩展名。

读取真实文件字节编码为纯 Base64，不带 `data:image/...;base64,`，不能把路径、URL、截断字符串或省略号传入。使用宿主能完整传递参数的路径；若参数被截断或收到 `__largeTextTips__`，先核对文件与参数大小，必要时改外链转换，不凭显示出的片段重拼 Base64。

## 成功解析与及时补记

外转内成功标识兼容 `__success__`/`success`，读取 `model[]` 每项的 `relativeUrl`；本地上传要求 `__success__=true` 且 `model.relativeUrl` 非空。

合法 HTTP(S) 完整 URL 原样保存；合法站内相对路径去掉开头斜杠后接 `https://cbu01.alicdn.com/`。不是路径的错误文字、空值、其他协议不能拼成成功链接。

有待转换图片时，返回为空或 `model` 为空数组，即使成功标识为真也不能记为完成图片转换，保留回执并按失败处理。批量返回数必须与请求相同；有输入回显/明确顺序契约才能逐项对应。仅数量相同却无法证明顺序时，不猜映射，改为单图调用取得明确回执。记录可能重复入库，不反复重传已可确认成功的图片。

每张成功立即更新 manifest 和说明.md：原始来源、本地文件及校验值、宿主 URL、图片银行 URL、回执路径、转换时间与所用派生图。失败保留错误及已成功映射。生成请求和最终展示材料只从这些映射取 URL，不重新手抄。

失败图是否可不使用，要依据任务要求：用户指定必用图或某项生成/发布的必要图，必须补齐；原本只是可选候选且有足够替代素材，可说明未采用原因并更新选择清单。不能在已承诺使用的图片集里悄悄丢图。

# 用已有图片准备主展示图、SKU 图与详情

第三层准备草稿中的 `imageList` 和 `detail` 时读取。默认从用户已有且属于当前商品的素材组装，无需调用生图。

## 选择和映射

`selection.json.main` 是选定主展示图，1—5 张，尊重用户顺序；`detail` 是详情顺序；`sku` 记录每个可售组合与其实际图片编号。三者可以共享同图，但每处只引用一次。图片均须有可核验本地文件；实际进入生成入参或草稿字段的图才要求真实图片银行映射，仅保留本地 SKU 对应而无远程图位的图片不额外入库。

将选定主展示图依序映射到 `text/imageList.json`。生成工具附带的 `imageList` 可能是候选合集，不能不加判断就全塞为主图。草稿工具实际 schema 若把 `imageList` 定义为其他图位，先核对其真实契约再映射；不能仅根据名称编造图位字段。

SKU 图按规格对应关系选，颜色/款式不明时不能靠相似度绑定。当前 `skuTable` 示例字段为规格、价格、库存；若实际工具支持 SKU 图片字段则按其 schema 设置，否则在本地保留映射并明确当前未保证单独 SKU 图位写入。不要自造 `skuImageUrl` 等字段并声称关联成功。用户坚持必须关联而接口没有表达能力时，说明需要在草稿页补充或等待对应能力，不能悄悄降级。

## 详情内容

优先使用用户指定详情图，再按整体展示 → 细节/使用 → 规格/包装说明的自然顺序选择合适图片；不把全部收件图（尤其参考页截图、无关图、冲突资质图）自动塞入详情。没有专门详情图时，可用已选主图/清晰实拍图组成基本详情，不因此自动生图或虚构卖点。

仅有标签/表格时不够替代商品主图；详情使用这些信息也需确认属于当前商品。事实不明时省去非必需营销文字，不能补造功效、服务承诺或资质。

对所选图片银行 URL 使用 HTML 属性转义，按如下形式逐图拼接：

```html
<p><img src="实际图片银行URL" alt="detail_pic_0" /><br class="img-brk" /><br class="img-brk" /></p>
```

转义改变 HTML 表示，不改变原 URL；解析后应能逐项还原到映射。不要使用本地路径、宿主视觉 CDN、脚本、外部 iframe 或失效源链接。若采用工具返回的详情，同样核对其中每个图和文字，不直接透传不明 HTML。

将真实详情字符串保存为 `{"detail":"..."}`。`imageList.json`、`detail.json` 连同所用 assetId 顺序、来源和状态写回台账；只在本地文件/图序/事实改变时使其失效重组。

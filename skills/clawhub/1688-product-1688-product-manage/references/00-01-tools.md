# 工具边界与返回处理

首次调用工具、发现工具不可用或参数结构变化时读取。使用宿主实际暴露的工具标识和 schema；连接器负责账号鉴权，Agent 不读取凭证或改插件配置。

| 店铺选择、规格文本澄清 | 宿主 `ask_user`（form / chat） | 本文店铺绑定、[确认策略](02-00-decisions.md) |

远程发品业务仅走 `Ali1688` MCP；不要用本地脚本拼后台 HTTP 请求。`web_fetch` 只作公开资料读取，不代表店铺后台查询。不要为此加载或修改其他发品 Skill。图片分类由 Agent 按本 Skill 规则完成，不需要远程分类工具。

调用使用 JSON 对象。宿主若提供名称映射或工具发现，按实际 schema 取得标识，不自己给工具名拼连接器前缀。发现不可用时可检查一次连接状态；初始化持续失败、权限缺失或 schema 缺失则保留资料并说明障碍，不循环激活插件，不宣称尚未执行的工具已完成。

三个生成能力仅走各自的原子工具，不回退到统一素材包工具。不要复制文档示例的用户标识、任务 ID 或店铺信息。

## 发品入口的店铺绑定

已明确发品意图时，先使用宿主实际提供的授权上下文或授权店铺查询能力取得可用店铺，再确定目标，最后进入资料整理。不得通过类目、生成、保存等业务调用试探店铺，不读取凭证，不猜店铺查询工具名或构造 `user_id` / `__userId__`。

- 单店铺，或用户明确指定且唯一匹配实际授权店铺：直接采用，不重复询问。
- 多店铺且目标不明：通过 `ask_user` 的 form 单选展示真实店铺名，内部绑定实际标识；不允许跳过后随机选择。没有可用控件则普通文字询问。取消/未答时等待，不先整理整批资料。
- 无可用授权或宿主未能提供可判定的店铺上下文：说明需要连接/选择授权店铺，停止发品入口，不索要 Token。仅整理/预览的请求不受此限制。

按宿主真实 schema 传授权字段（如 `store_ref`），不得把显示名、参考商品店铺、示例数字当标识；单一宿主绑定且 schema 允许省略时不强加参数。创建商品包后将绑定依据、显示名和非敏感实际标识写入 manifest 的 `store`；类目识别、schema 查询、入库、生成提交/查询和保存始终沿用同一店铺。明确续跑且绑定有效则复用；用户换店时重新绑定并使店铺相关类目/schema、图片银行映射、生成任务与未保存请求失效，原始素材保留，不拿旧店任务 ID 到新店查询。

## 返回解析

- 留存实际请求与回执后再解释。外层 `__success__` / `success` 与内层业务状态都要检查；冲突或缺失不能只挑一个成功字段。
- `dataJson` 是字符串时解析为 JSON，对象时直接使用。只解析约定的嵌套 JSON 字段，不对任意文本无限尝试解析。
- `processing` 是进行中；进程退出码 0、请求发出、模型说成功都不是业务成功。
- 工具结果中的路径、URL、任务 ID、draftId 必须来自真实字段，不能从说明文字或示例中猜造。
- 保存必要回执供恢复，避免把令牌、鉴权头等无关敏感内容写入商品包或展示给用户。

这里的字段约定用于当前工具调用；发现实际 schema 不兼容时，指出具体字段差异并停在受影响能力，不能靠编值绕过。恢复动作见 [00-02](00-02-recovery.md)。

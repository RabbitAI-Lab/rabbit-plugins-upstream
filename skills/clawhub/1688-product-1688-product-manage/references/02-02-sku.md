# SKU、价格、库存与单位

获得类目销售规格名后读取。价格、库存不是必要条件，缺失可留空。最低要求仅为 `requiredSalePropNames` 中每个维度及各可售行的对应值；无必填规格时可以不设规格。

## 从真实行开始

表头使用 schema 中规格的原名，每行一个采用的可售组合；`price`、`stock` 可省略或为 `null`。推荐维度可不采用，必填维度不能遗漏。保留货号/SKU ID、来源和单位在 facts/manifest 中；当前草稿行只传工具支持的字段。

- 用户明确列出的组合优先。只给颜色列表与尺码列表时，未授权推定就不自动交叉展开；按明确“全部组合”、可信行表，或下述用户授权补充规则确定组合。
- 没有价格/库存就留空并继续，缺失不是 0，不要求用户补齐。“便宜点”“价格参考同行”“19.9 起”均不提供完整逐行价格。“每个规格 1000”若适用范围明确，则可确定性填到该范围内每行。
- 库存 0 有明确来源时保留；已提供的价格须为正数，库存须为非负整数，未提供则留空。数值不允许布尔值、NaN、Infinity；原始数值字符串可无损转数字后记录。
- 分清当前 SKU 价、历史价、阶梯价、个/套/件及币种。阶段稿不能把缺失、历史值或外店库存自动变成新品报价。
- 规格文字保留原含义；“黑”和“黑色”只有对应关系明确时规范化。规格里含 `$` 时该分隔接口无法无损表示，先解决表达问题，不直接删字符。

表缺行先确认是否未售；不得补 0 库存行表示“不售”，也不能为了接口全组合要求自动新增 SKU。接口若拒绝用户真实的稀疏组合，说明表达能力限制并等待处理。

## 采用与冻结本次输入

用 `ask_user` 的 `mode:"chat"` 集中核对一次，只展示已有规格及尚缺的必填项，不让用户重新填已有值；本商品当前规格已确认过则复用。`question` 用简短 Markdown，`placeholder` 提示简短回复；不传 `fields` 或 `quickReplies`。例如：“目前整理为：米色。**必填规格还缺：尺码对应值。** 少了它草稿会缺规格属性，请补一下，也可以让我根据素材填写。价格和库存可不填。”示例须替换成当前真实维度，不照抄。

`question` 不超过 500 字，`placeholder` 不超过 20 字；SKU 很多时仅摘要已知项和剩余缺口，不塞全表。需要补图/文件可加 `attachmentSlot`，不把附件设为默认必填。

没有未解决的必填规格时设 `allowSkip:true`，说明跳过保留已有信息、未知可选项留空；仍缺必填维度或值时设 `allowSkip:false`，解释缺失会造成草稿属性不完整。用户口头要求跳过也不能绕过必填项，可请其补充或明确授权 AI 填写。

有效答复后仍缺必填值，不立即暂停，继续只问剩余项；累计最多三轮澄清（首次核对若询问了必填缺口也计一轮），第三轮答复后仍不完整才保留资料并说明缺哪些、等待补充。轮次写入 manifest，恢复同一问题不清零；新类目或新的规格问题另记。取消、超时和空返回不算一轮有效答复，也不连续弹窗。

用户明确说“你自己填/根据图片补齐”时，可结合本商品资料推定必填规格值和必要组合，完成后直接采用，不再要求用户确认该推定；记录授权原话、推定依据与值，不冒充用户声明。不编造实际尺寸、型号等无法合理推定的客观参数，不以“未知/待补”冒充必填值；确实无法合理补充时说明具体缺口并按剩余轮次澄清。授权补规格不等于授权编价格库存。仅“不想确认”不等于授权编值。

“黑白两色，M 和 L”但未明确全组合时，在这次核对中问“四种组合都卖吗？”未授权推定时不自动交叉展开；可选维度/组合不明确且用户跳过时只采用已明确部分，不删掉任何已明确的可售行。仍会漏必填值则走必填澄清。修正只作用于唯一指向的商品/SKU，多项命中时先消歧。

将采用表写到 `text/sku-input.json`：

```json
{"skuTable":[{"颜色":"用户实际颜色","尺码":"用户实际尺码","price":null,"stock":null}]}
```

示例仅解释结构，维度和值须来自当前 schema 与采用资料。无必填规格且无采用行时写 `{"skuTable":[]}`，不添加假规格。确认记录必须指向当前文件内容；之后更改行时同步更新依据和生产状态。

## 接口列展开

为 `1688_publish_sku_predict` 严格按采用行顺序生成 `saleProp1`、`salePropValue1`、`saleProp2`、`salePropValue2`、`skuPrice`、`skuStock`。仅展开必填或已有值的维度，最多两维；值列用 `$` 拼接，重复规格值保留。一维的第二规格名和值均为 `""`；无规格则两组规格参数均为空。价格/库存整列未知传 `""`，部分未知保留空位，如 `"19.9$$29.9"`，不得错位或补 0。实际工具若不接受空位，说明该接口限制，不以此强制用户补价补库存。

不携带含过期维度、价格或库存的 `knownProductInfo1` 底稿，因为空独立参数不会清除底稿旧值。空值是提交输入的表示；工具成功返回后按生产规则采用，不再把其输出清空。

可用 [本地组装脚本](../scripts/prepare_payload.py) 避免手工错位：

```sh
python3 <skill目录>/scripts/prepare_payload.py sku-args --product <商品目录>
```

命令中的尖括号是路径占位，执行前换成实际路径并正确引用。脚本读取 `category-schema.json` 和 `sku-input.json`，只输出 JSON、不发远程请求、不写文件；它检查结构，不能证明数据有真实来源。不可用时执行等价校验，不跳过。

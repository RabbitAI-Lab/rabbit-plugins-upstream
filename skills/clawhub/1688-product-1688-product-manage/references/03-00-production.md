# 独立生产与产物采用

第二层已有按接口顺序采用的类目、实际 schema 和已核对的 SKU 输入后读取。先检查 manifest 的 `stopReason` 与当前店铺状态；类目业务终止或店铺草稿容量满时，不入库、不提交生成、不保存。必填规格维度和值须齐全；价格库存可空，无必填规格可不设规格。用户只整理或预览而未授权创建草稿时，遵守其目标范围。

## 先决定用哪些图

从 `selection.json` 和 facts 确定本次生成/发布需要的主图、详情、SKU 图和标签/规格证据图，按 [分类映射](01-03-classification.md) 区分各原子工具实际接收的图与仅保留本地的资料。仅实际提交给生成工具或进入草稿展示字段的图按 [03-01](03-01-image-bank.md) 转入图片银行；只供本地读图、未选用或无实际消费接口的图不为凑齐而转换。生成所需的主图必须 1—5 张。

默认使用用户图。只有明确要求图像生成/编辑时走 [03-04](03-04-image-production.md)，并把验收后的派生图重新归入选择清单；新图实际要使用才入图片银行。

## 三个独立任务

在当前商品内依次调用 `1688_publish_title_prediction`、`1688_publish_cpv_predict`、`1688_publish_sku_predict`，每项按 [03-02](03-02-generation-tool.md) 单独提交并查询自己的 `taskId`。当前项完成或明确失败后才推进下一项；仍在运行或结果不明时保存状态，先恢复该任务。其他不依赖明确失败项且自身入参完整的生产项可以继续，最终保存仍等所需字段全部有效。正常执行直接推进，不为每项落盘、清洗或查询单独询问用户。

每项记录完整输入快照、所用图片编号、业务 URL、事实文件及校验值。用户锁定标题/属性时，把原值与“保持不改”明确传给素材工具，输出只按下述明显冲突例外处理，不另做二次审稿。用户只要原文且无需生成时，可保留其已合法的对应字段并记录无需重写的理由；不要为形式上的完成制造一次无意义的生成。

## 成功输出默认直接采用

| 产物 | 落盘与采用 |
|---|---|
| 标题 | 将成功结果中的 `title` 原样写入 `title.json`；不删词、缩写、润色或重写 |
| CPV | 将成功结果中的 `catProp` 原样写入 `catProp.json`，保留条目、顺序、名称和值；不按来源/置信度删改属性 |
| SKU | 将成功结果中的 `skuTable` 原样写入 `skuTable.json`；不例行逐行审核、补齐、删行或重排 |

默认这三个素材生成 Agent 的输出正确，不做二次事实、语义或质量检查，也不因为“原素材没有依据”而删减、修改、重生成或追加用户确认。用户给出的内容约束随真实输入传给对应工具，由素材生成 Agent 负责执行。该规则只针对这三个工具的产物，不取消输入确认、图片映射和生图/编辑验收。

唯一内容修正例外是与用户明确的目标商品信息有明显直接冲突，例如用户明确品牌 A、结果却写品牌 B，或明确指定的规格/数值被改成另一值。按用户明确值仅修正冲突字段及其直接关联表达，其他产物不动；不把“用户没说”“预测不够保守”算冲突，不逐项找茬。先确认来源确为本商品事实：测评编号、文件编号等上下文标识不是商品货号；真实货号仍须尊重，不能一概忽略。对应关系不清且影响发布时才简短澄清，不猜替换值。

原始工具回执保持不变，最终字段文件保存采用值；仅在本地台账记录冲突字段、用户依据和修正值。正常成功回复不提“修改/纠正/删除了什么”，不展示工具错误或内部处理过程。

仍须确认真实工具成功、任务已完成、本类型必要字段存在且可解析：标题非空字符串，CPV 非空数组，SKU 数组（无必填规格时允许空数组；有必填规格却为空则缺必要结果）。失败回执、缺字段、`null` 不是空规格。无法解析或缺结果时保留其他成功项，按工具异常处理，不自己填内容。按上述规则落盘后更新 manifest 的产物依赖、有效状态和说明索引，原始回执保存在 `text/tasks/<类型>/`；这里的有效表示“工具成功并已采用”，不是另做了内容审核。

# 输出模板（严格照此顺序，可增删小节但不得换序）

## ⚠️ 三层结构（v6.0 · 2026-11-05 用户投诉「报告太复杂、要 60 岁妈妈看得懂」后立）

> **真实翻车**：一份 ¥90 的数据线报告写了 12 张表、ROI/EAC/QPR/信源三层打分，"结论先行"四个字下面是四行嵌套表格。用户的原话是「太复杂，太乱了」。**问题不是排版差，是把审计底稿当成了交付物。**

报告必须拆成三层，**顺序不可颠倒，前一层不许依赖后一层的术语**：

| 层 | 给谁看 | 篇幅 | 内容 | 硬约束 |
|---|---|---|---|---|
| **零层·一屏** | 家里人、60 岁长辈 | **一屏，不滚动** | 买哪个 / 多少钱 / 去哪买 / **别买错什么** | 只有一个坑，只用生活语言，**零术语** |
| **一层·论证** | 用户本人 | 一页 | **排除法全过程 + 三条横向对比 + 多花的钱买到什么 + 一个反向条件** | 可有价格和年限，**不得有 ROI/EAC/QPR**；对比用条形/图标，不用表格 |
| **二层·附录** | 审计、复核 | 不限 | 对价表、证据强度、信源档案、纠错留痕 | 术语随便用，**但必须放在最后，不得上浮** |

> **⚠️ v6.0 修正（2026-11-05 用户第二轮投诉「又太简单了，没有论证跟横向对比的过程」）**：第一版把论证全塞进附录，零层只剩一个没有依据的结论——**这是错的，等于让用户"信我"而不是"看懂我的推理"**。一层必须是**看得懂的论证**，不是空的过渡页。
> **教训一句话：易懂 ≠ 无论证。把表格换成条形图，论证一点没少；把论证删掉，那才是真的没论证。**

### 一层必须包含的四件东西（缺一即不合格）

1. **排除法全流程**：先淘汰最便宜的（**说清它缺什么，用一句人话**）→ 再淘汰最贵的（**说清多花的钱买到了什么、为什么对你不值**）→ 剩下的就是答案。**每条淘汰理由必须挂一个具体事实**（"传文件只有一半速度"可以，"性能不佳"不行）。
2. **三条同维度横向对比**：同样的 3–4 个维度（本案例：充电 / 传文件 / 接显示器 / 保修），三条线并排，**用条形长度表示强弱，不用数字表格**。维度必须选"用户能感知的"，不选"厂商爱标的"。
3. **多花的钱买到了什么**：`ΔP` 换成三句人话，每句带一个可感知的量（"10GB 视频 8 秒变 4 秒"）。
4. **一个反向条件**：明确写出"什么情况下你**不该**买我推荐的这款"（"只充手机、不拷大文件 → 45 块那根就够"）。**没有反向条件的推荐，等于没做权衡。**

**术语翻译表（零层/一层禁止出现左列，一律换成右列）**

| 内部术语 | 说人话 |
|---|---|
| 20Gbps / 10Gbps | 传一部电影几秒钟 / 传一部电影十几秒 |
| 240W PD3.1 EPR | 笔记本、游戏本都能满速充 |
| 4K60 HDR / DP Alt Mode | 接显示器，4K 画面不卡 |
| USB-IF 认证 / 双 E-Marker | 有官方认证，过热会自己断电 |
| 门槛型规格 | 那个「有没有决定能不能用」的关键点 |
| EAC / QPR / ROI / p\* / ΔP | **零层一层一律不出现**（只留在二层） |
| 投毒指数 / 信源等级 L1–L4 | **只留在二层** |
| 溢价 / 公允价格上限 | 这个价贵不贵 / 再贵就不值了 |

**零层必答四问，缺一不可**：①买哪个（品牌 + 型号 + 长度/容量这类唯一标识）②多少钱 ③在哪买（店名 + 可复制的搜索词）④**别买错什么（只写最大的那一个坑）**。

**零层的四条禁令**：不写表格、不写百分比、不写型号代码、不写"综合来看/综上所述"。**如果我妈看完还要问你"所以到底买哪个"，这一屏就是失败的。**

## 四层之外的第五形态｜分享版（微信/社交，v6.0）

> **起因（2026-11-05 用户第三次反馈）**：「要易于在微信分享的，全部的流程跟排版要有逻辑性、易读性，也不是让你省掉那么多」。
> 关键约束：**微信聊天窗口不渲染 Markdown**——表格发过去会变成一堆竖线，`|---|---|` 会原样出现。所以分享版的第一原则不是"渲染好看"，而是 **「渲染与不渲染都好看」**。

**分享版与主报告的差异（只改载体，不删论证）**

| 项 | 主报告 | 分享版 |
|---|---|---|
| 表格 | 可用 | **全篇最多 1 个**，且必须能被纯文本读懂；**主对比一律改成「充电 240W ／ 传文件 10Gbps ／ 4K60 ／ 保修 1 年」这类斜杠列表** |
| 标题层级 | 可到四级 | **只用两级**（`#` 与 `##`），靠编号「一、二、三」推进 |
| 引用块 `>` | 可用 | 最多用于开头一句，不嵌套 |
| 术语 | 一层禁、二层可用 | **全篇禁**，原理也必须用大白话讲 |
| 论证 | 散在各节 | **必须是一条单向叙事线**：结论 → 把需求翻译成标准 → 逐关淘汰 → 三款同口径对比 → 多花的钱买到什么 → 什么情况下别买 → 坑 → 原理 → 证据与推翻记录 |
| 篇幅 | 不限 | 4–6 屏（微信阅读耐心上限），但**不许靠删论证来压缩**，只能靠"去表格、去术语、去重复" |

**分享版的七条硬规则**

1. **一句话能带走的结论必须在第一屏**，且含四要素：买什么、多少钱、去哪买、**唯一的坑**。
2. **每关淘汰必须挂具体事实**：「传文件只有 10Gbps，是要求的一半」可以；「性能不足」不行。
3. **必须写「什么情况下别买我推荐的这款」**，且要给出替代款和它的价格。
4. **数字全部换成人能感知的量**：10GB 视频 8 秒变 4 秒、笔记本能不能喂饱、4K 画面卡不卡。
5. **原理单独一节，一段话讲完**，配一个自证的对照（如"同品牌 0.8m 是 40Gbps+100W，2m 是 20Gbps+240W"）。
6. **末尾列出「我中途推翻过的错误」**——这是可信度来源，也是防止读者被旧说法带偏的关键。
7. **不写「综上所述」「综合来看」「建议您」**；不用 emoji 代替排版，用编号、空行、加粗。

## 硬性要求

- 全文所有价格带**店铺全称 + 日期**，所有数字带来源或标"假设值"。
- **推荐强度不得高于证据强度**（v5.6，最重要的一条）：核心购买理由无 **L2 或 L3a/L3b** 实测（L3c 付费定制不算）→ 封顶「推荐（需自证）」；`unproven` → 不得作首选。写"强烈推荐"必须能指出至少 2 条独立实测。
- **第五节「证据强度对比」为必备章节**（v5.6），不得省略、不得用"参数已很详细"替代。缺这一节，等于没做证据审计。**v5.7 起还必须含 5.1「信源档案」**——只列表不给来源档案，等于没说清这些数字值几分。
- **引用任何第三方实测，必须带三件套**（v5.7）：`来源（商业模式）｜可复核（是/否）｜利益冲突（低/中/高）`。只写"XX 实测显示"就把数字端上来，视为未完成取证。
- **别把"媒体实测"写成"权威实测"**（v5.7）。媒体/博主无论多专业都是 L3；L2 只留给消协、SGS/TÜV、国家级质检中心这类无商业关系的检测机构。等级写高一级，读者就会多信一分。

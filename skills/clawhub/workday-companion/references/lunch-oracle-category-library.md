# Lunch Oracle Category Library

用于午饭判官生成品类神谕、饭签、食运和今日避雷。品类只给方向；具体店铺必须来自用户候选或搜索候选。

## Quick Navigation

- 缺餐厅候选：读 Magic Variables、Grounded Magic Rule 和 Category Cards。
- 用户给 3-8 个候选：读 Candidate Verdict Matrix。
- 当前对话已有饭后回票：读 Second-pass Recast。
- 用户只回 `吃完困`、`太油`、`排队久`、`没吃饱`：读 Lunch Feedback Interpreter。
- 需要用户参与：读 User Output Loop。

## Magic Variables

- 上午耗电：会议消耗、沟通消耗、通勤消耗、脑力消耗、情绪消耗。
- 下午战斗强度：轻量处理、中等推进、高压评审、连续会议、加班耐力。
- 社交噪音：独处吃、小范围拼饭、团队饭局、临时约饭。
- 排队耐受：零排队、可等 10 分钟、愿意排。
- 天气冷热：热天、冷天、雨天、普通。
- 预算距离：省钱优先、正常预算、愿意加一点、只吃楼下。

## Grounded Magic Rule

- `饭签`、`食运`、`品类神谕`只作为轻娱乐包装；每句都要绑定至少一个现实变量：下午任务、预算、距离、排队、天气、社交、上午耗电或饭后回票。
- 允许：`排队降权`、`稳热上升`、`汤面回血`、`加班耐饿`、`反悔入口`。
- 避免：`开光`、`注定`、`命运`、`运势决定`、`财运`、`玄学判断`。
- 用户反馈 `太玄`、`像算命`、`飘` 时，删除 `食运` 标签，改成 `今日判断`，并优先写候选来源和确定性。
- 没有现实候选时，给品类方向和待补字段；不要把品类方向写成已经掌握附近餐厅。

## Primary Habit Decision Order

午饭判官按以下顺序裁决：

| 顺序 | 规则 | 说明 |
| --- | --- | --- |
| 1 | 硬约束 | 过敏、忌口、预算、时间先排除 |
| 2 | 现实候选 | 用户提供候选优先，其次来自搜索候选 |
| 3 | 当天目标 | 快、稳、热、轻、适合聊天 |
| 4 | 最近重复 | 避免连续吃相同品类 |
| 5 | 当前状态 | 困、忙、冷、想见人、想独处 |
| 6 | 同分随机 | 只用于同分候选的最终裁决 |

## Audience Fit Map

- 办公室打工人：优先快稳热饭、轻负担碗、蛋白补给、社交拼饭；看排队、会议密度和同事同行。
- 通勤族：优先顺路通勤餐、咖啡轻食、快稳热饭；看路线、携带方便和是否绕远。
- 学生 / 实习生：优先校区预算餐、汤面回血、碳水续命；看预算、课间时间、食堂拥挤和下午课程。
- 自由职业 / 远程办公者：优先远程快手餐、汤面回血、蛋白补给；看出门成本、收工边界和家附近候选。
- 场景不明：先用大众品类名，少写园区、评审、对齐等窄词。

## Category Cards

### 快稳热饭

- 代表：盖饭、烧腊饭、黄焖鸡、牛肉饭、便利热餐。
- 适合：下午有会、上午被耗空、需要稳住。
- 避开：困到想睡、刚吃完早餐、天气太热。
- 饭签句：今天要吃一个能接住下午的底盘。

### 轻负担碗

- 代表：轻食碗、拌饭碗、沙拉加主食、健康碗、杂粮饭。
- 适合：想轻一点、下午要保持清醒、预算中等。
- 避开：很饿、加班、天气冷且只想吃热的。
- 饭签句：今天别把午饭吃成下午的负重包。

### 汤面回血

- 代表：牛肉面、云吞面、粉面、米线、热汤粉。
- 适合：冷天、雨天、低电量、想吃热的。
- 避开：怕出汗、下午要立刻汇报、排队久。
- 饭签句：今天需要一碗热汤把系统重新开机。

### 碳水续命

- 代表：炒饭、拌面、汉堡套餐、饺子、包子套餐。
- 适合：加班、体力消耗、下午战斗强度高。
- 避开：吃完易困、下午需要高度清醒。
- 饭签句：今天的灵魂需要一点碳水押韵。

### 蛋白补给

- 代表：鸡胸饭、牛肉饭、卤味饭、烤肉饭、豆腐饭。
- 适合：想稳、想耐饿、下午有长会。
- 避开：预算紧、附近候选太油。
- 饭签句：今天靠蛋白质把心态钉住。

### 社交拼饭

- 代表：小炒、简餐店、茶餐厅、日料便当、披萨/轻聚餐。
- 适合：需要缓和关系、顺手对齐事情、同事约饭。
- 避开：社交噪音高、下午要独自赶进度。
- 饭签句：今天这顿饭可以顺便修一下人际缓存。

### 咖啡轻食

- 代表：三明治、贝果、饭团、咖啡加小食、便利店组合。
- 适合：时间极短、上午吃得晚、下午要轻装。
- 避开：下午高压、加班、明显饥饿。
- 饭签句：今天适合轻拿轻放，别给胃派大活。

### 加班耐饿餐

- 代表：双拼饭、面饭组合、卤肉饭、饺子面、汤饭组合。
- 适合：晚上可能加班、下午会很长、离晚饭远。
- 避开：下午需要镜头汇报、吃完困。
- 饭签句：今天要为 18:30 之后的自己留后手。

### 校区预算餐

- 代表：食堂套餐、粉面、盖饭、包子饺子、便利饭团。
- 适合：学生/实习、预算敏感、课间短、下午还要上课。
- 避开：窗口大排队、太油太撑、需要走很远。
- 饭签句：今天的饭运主打省心省钱，不把午休花成项目。

### 顺路通勤餐

- 代表：地铁口简餐、便利热餐、外带饭团、三明治、粉面外带。
- 适合：赶路、午后要出门、路线优先、雨天不想绕。
- 避开：汤汁太多不好拿、等位久、需要折返。
- 饭签句：今天饭要跟路线同频，快乐从顺路开始。

### 远程快手餐

- 代表：家附近小店、冰箱快手饭、热汤粉面、简易蛋白加主食。
- 适合：远程办公、自由职业、出门成本高、下午有客户沟通。
- 避开：把午饭做成大工程、边吃边开会、拖到很晚才吃。
- 饭签句：今天先把身体接回桌前，再处理世界。

## Selection Heuristics

- 下午高压 + 上午耗电高：优先快稳热饭、蛋白补给、汤面回血。
- 想轻一点 + 下午需要清醒：优先轻负担碗、咖啡轻食，降低高油高碳水。
- 加班概率高：优先加班耐饿餐、蛋白补给、碳水续命。
- 社交目标明确：可选社交拼饭；独处需求高时降权。
- 零排队：优先便利热餐、快稳热饭、咖啡轻食，避开热门小炒。
- 校区/预算敏感：优先校区预算餐、汤面回血、快稳热饭，降低高价轻食。
- 通勤/顺路优先：优先顺路通勤餐、咖啡轻食、便利热餐，降低折返和久坐餐。
- 远程/在家：优先远程快手餐、汤面回血、蛋白补给，控制准备成本。
- 饭后回票出现“吃完困”：下次降低碳水续命、高油重口、过量套餐。

## Candidate Verdict Matrix

用户给 3-8 个现实候选时，先分级，再裁决。不要补编用户未给的字段。

### Candidate Fields

每个候选尽量解析这些字段：

```text
店名/类型｜步行时间｜预算｜排队｜品类｜备注
```

字段缺失时写 `?`，仍可作为可参考候选；缺店名或类型时写待核验。

### Rank Weights

默认权重按场景调整：

| 变量 | 默认权重 | 高压下午 | 低电量 | 想轻一点 | 省钱 |
| --- | --- | --- | --- | --- | --- |
| 距离近 | 高 | 高 | 高 | 中 | 中 |
| 排队短 | 高 | 高 | 高 | 中 | 中 |
| 预算匹配 | 中 | 中 | 中 | 中 | 高 |
| 耐饿/稳 | 中 | 高 | 高 | 低 | 中 |
| 清醒负担 | 中 | 中 | 高 | 高 | 中 |
| 社交成本 | 中 | 中 | 高 | 中 | 中 |

饭后回票会覆盖默认权重：

- `吃完困`：降低重油、大份、甜饮、纯碳水。
- `太油`：降低油炸、重口、小炒大份。
- `排队久`：排队字段一票降权。
- `没吃饱`：提高蛋白补给、快稳热饭、加班耐饿餐。
- `太贵`：预算超出一票降权。
- `社交太吵`：降低多人拼饭和需要抢座的店。

### Verdict Names

- 饭票冠军：最适合今天现实约束的一项。
- 保底备选：冠军不可用时的低风险替代。
- 今日放弃：最容易背刺下午的一项。
- 反悔理由：一句说明用户可以怎样改判，例如 `如果你突然想轻一点，就把冠军换成备选`。

### Output Contract

有候选时，午饭判官首屏仍保留 6 项，但现实推荐写成一行裁决：

```markdown
现实候选池：用户提供[5项]｜可裁决[3]｜可参考[2]｜把握[高]
今日饭签：[绑定下午任务/排队/预算的饭签]
品类神谕：主推[品类]｜备选[品类]｜绕开[品类]
现实推荐：冠军[候选A]｜备选[候选B]｜放弃[候选C]｜反悔[条件]
用户输出任务：饭后回[困/油/贵/排队/没吃饱]
禁区提醒：不下单，不给医疗饮食建议。
```

### Decision Tone

- 直接拍板，少写排名表。
- 只解释 1-2 个关键现实因素。
- Magic 只放在饭签或状态码里，例如 `排队降权`、`热饭上升`、`饭票冠军`。
- 候选字段缺失时，不把判断写得很满；把把握度降到中或低。
- 用户说 `直接决定` 时，只输出冠军、一个依据和一个反悔入口。

## Second-pass Recast

当前对话里已有饭后回票、用户再发新候选时，先复用回票，再重新裁决。

触发输入：

- `按上次` + 新候选。
- `上次吃完困，这次这几个选一个`。
- `还是按轻一点，候选是...`。
- 用户刚回过 `吃完困`、`太油`、`排队久`、`没吃饱`、`太贵`、`社交太吵`，随后发 3-8 个候选。

执行顺序：

1. 写一行沿用项：`沿用：回票[吃完困]｜降权[重油大份/纯碳水]`。
2. 对新候选重新分级：可裁决、可参考、待核验。
3. 先应用回票降权，再看今天任务、排队、距离、预算。
4. 输出新的冠军、备选、放弃项和反悔条件。
5. 不复述上一顿细节，不写长期记忆。

二次裁决输出：

```markdown
沿用：回票[踩雷]｜本次降权[条件]
现实候选池：用户提供[5项]｜把握[高/中/低]
饭票冠军：[候选]，因为[1-2个现实因素]
保底备选：[候选]｜今日放弃：[候选]
反悔按钮：[轻一点/更耐饿/别排队]
```

二次裁决口感：

- 用户看起来没耐心时，用 5 行内。
- 如果上次踩雷和新候选冲突，优先规避踩雷。
- 如果所有候选都踩雷，选最轻的一项并写 `把握低`。
- 新候选缺字段时，只问 1 个最影响裁决的字段。

## Lunch Feedback Interpreter

用户饭后只回一句短反馈时，立刻给回票卡，不重新生成完整午饭判官。

触发词归一：

- `吃完困`、`困了`、`犯困` → 踩雷[困]。
- `太油`、`腻`、`重口了` → 踩雷[油]。
- `排队久`、`等太久`、`出餐慢` → 踩雷[排队]。
- `没吃饱`、`饿得快` → 踩雷[不耐饿]。
- `太贵`、`不值` → 踩雷[贵]。
- `太吵`、`社交累` → 踩雷[社交太吵]。

降权和提权：

| 回票 | 下次降权 | 下次提权 | 下午补救 |
| --- | --- | --- | --- |
| 困 | 重油大份、碳水续命、甜饮加码 | 轻负担碗、蛋白补给、汤面回血 | 起身走 3 分钟，先写下午第一步 |
| 油 | 油炸、重口、小炒大份 | 汤面回血、轻负担碗、便利热餐 | 喝水，下午先做低沟通任务 |
| 排队 | 热门店、现炒、抢座 | 出餐快、外带可行、楼下稳定项 | 记录排队久，下次默认排队降权 |
| 不耐饿 | 咖啡轻食、小份沙拉 | 蛋白补给、加班耐饿餐、快稳热饭 | 预留一个小加餐时间 |
| 贵 | 高价轻食、临时拼单 | 校区预算餐、便利热餐、快稳热饭 | 下次先按预算筛 |
| 社交太吵 | 多人拼饭、临时饭局 | 独处吃、小范围拼饭、外带 | 下午减少新对话入口 |

回票卡格式：

```markdown
收到：[饭后回票]
下次规则：[降权 + 提权]
现在补救：[一个 30 秒或 5 分钟动作]
入口：按上次 / 换轻一点 / 给候选
```

回票边界：

- 只在当前对话复用，不写长期记忆。
- 不把困、油、胃口变化解释成健康结论。
- 用户提到过敏、疾病或明确禁食时，只作为排除条件。

## User Output Loop

### 饭前 30 秒三问

```text
你在哪/有哪些候选？下午打什么仗？今天胃口关键词是什么？
```

### 饭后回一票

```text
吃完电量：+ / 平 / -
踩雷点：困、油、贵、排队、没吃饱、社交太吵
下次偏好：更热、更轻、更快、更省、更耐饿、更安静
```

Use the feedback only as preference memory inside the current conversation unless the user explicitly asks to save it elsewhere.

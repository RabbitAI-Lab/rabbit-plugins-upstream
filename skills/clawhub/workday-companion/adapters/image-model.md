# 图像模型适配

用于 `来张图`、`图卡版`、`只要一张图`、`每阶段出图`，以及用户要求调用自己的模型。

## 能力探测

按顺序检查：

1. 当前工具列表里有没有图像生成或图像编辑工具。
2. 当前模型或宿主元数据有没有明确的 image generation capability。
3. 能力未知时可尝试一次受控调用；失败后立即降级，不重复消耗。

能力状态只用三种：

| 状态 | 行为 |
| --- | --- |
| 可调用 | 生成底图或成品图 |
| 可生成但文字不稳 | 生成无字底图，确定性叠加中文 |
| 未知或不可用 | 返回 prompt + overlay + SVG/HTML 方案 |

不要让用户凭空确认模型能力；优先从当前环境探测。用户只提供模型名但环境里没有对应调用入口时，说明当前无法代调。

## 生成顺序

1. 完成当前模块文字判断。
2. 移除真实地址、公司、同事、客户、会议细节、回家路线、支付和健康信息。
3. 选择 `templates/image-card-prompts.md` 里的模块底图。
4. 生成底图，避免要求模型直接绘制中文。
5. 用卡片 JSON 叠加中文并写 `alt_text`。
6. 校验标题、依据、动作、标签没有溢出。

稳定文件流程：

```text
judgment JSON
  -> scripts/judgment_to_card.py
  -> scripts/validate_card.py
  -> scripts/render_card.py --svg/--html/--png
```

PNG 依赖宿主已有 Pillow；SVG 与 HTML 只用 Python 标准库。当前公开演示图放在 `assets/public-cards/`。

## 隐私门禁

午饭与下班默认只显示品类、方向和候选状态。除非用户明确要求且确认可分享，否则隐藏：

- 真实店名、公司名、园区名和精确地址
- 真实路线、回家方向和活动名称
- 同事、客户、会议和支付信息
- 过敏、疾病、病史和心理状态细节

每张成品卡都要有 `share_safe: true` 和 120 字内 `alt_text`。

## 输出合同

成功时：先发图片，不附长篇说明。失败或能力不足时：只写一行能力状态，随后给可复制 prompt 与 overlay 文案，不声称已经生成。

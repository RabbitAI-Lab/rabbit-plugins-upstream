# 研发支出资本化·逐条挂源

给一份年报附注或研发专项披露，把**研发支出资本化**读成一张**每个数都能回到原句**的台账：研发投入与资本化概况、开发支出明细、资本化与费用化的划分、资本化条件的满足情况、无形资产摊销与减值。

研发支出资本化是财报附注里**分歧最大**的一节：研发投入多少、资本化多少、开发支出怎么动的、研究阶段与开发阶段怎么划、五个资本化条件怎么判定——每一件都直接改当期利润，而绝大多数公司只给两个数、把第三个留在字里行间。本件把披露怎么写逐条登记下来，结论留给人。

**不判研发值不值钱、不建议资本化或费用化、不测算对利润的影响、不给评级与目标价。** 阶段划分与条件满足只认原句；要自己算的比例必须单列并交代分子分母出处。

---

## 一、三十秒跑通（零输入）

不给任何数据文件，也能跑出一份完整合规的成品，看它长什么样、判据怎么打：

```bash
python3 scripts/check_rd_capitalization.py --demo
```

把这份样例存下来再跑一遍机检，它能自己过：

```bash
python3 scripts/check_rd_capitalization.py --demo > 样例研发稿.md
python3 scripts/check_rd_capitalization.py 样例研发稿.md
# → 样例研发稿.md 结论：五道全过（零发条）
```

接着换成你自己那份稿子：

```bash
python3 scripts/check_rd_capitalization.py 你的研发稿.md
```

退码 `0` 全过、`1` 有发条、`2` 用法错、`3` 读不到文件或空稿。

### 拿不到成品时，从原文开始的三步

1. **定主体与报告期**，拿到年报附注里「开发支出」与「无形资产」那两节（通常在附注四至六之间）。
2. **每节抄事实，连原句一起抄**：一条 = 一行，行末挂 `「原句」〔锚：页/表〕[S#]`。
3. **跑一遍自检**，红一条改一条：

```bash
python3 scripts/check_rd_capitalization.py 你的研发稿.md
```

## 二、五道机检在管什么

| 码 | 管什么 | 典型触发 |
|---|---|---|
| `RD-STRUCT` | 形制 | 缺自标、缺 `主体：`／`报告期：`、节序不对、某一节空着 |
| `RD-QUOTE` | 原句与锚 | 数字行没挂「原句」〔锚〕[S#]，或来源行缺 URL／检索日 |
| `RD-NOSELF` | 不自推不自算 | 原句没写「开发阶段」却自己写；三个数拼成等式；比例没标〔自算〕或没给分母 |
| `RD-GAP` | 缺口两向点名 | 正文写了未取到、第六节没点名；或用「不适用」搪塞 |
| `RD-LINE` | 红线 | 「核心竞争力」「应当全部费用化」「增厚利润」「目标价」 |

五道全过时结论行是 `结论：五道全过（零发条）`。

## 三、四条红线（这件的立身之本）

1. **阶段划分与资本化条件只认原句。** 准则列了五个条件，但**哪个项目满足了、证据是什么，只有披露知道**。本件不替它判，也不按「研发投入大就是开发阶段」补。
2. **三个数不自行轧差。** 研发投入合计、资本化金额、费用化金额各有披露值；披露只给两个时，第三个是 `未取到`，不是减法。
3. **自算必须交代来路。** 资本化率一类的比例，原句里找不到的必须标〔自算〕并给分子分母，还须写明取哪一句。
4. **不判研发成色。** 值不值钱、技术是否领先、该不该继续资本化、对利润与股价有什么影响，一律 `[待人工]`。

## 四、一条发现长什么样

```
- 资本化金额 8,000.00 万元「本期资本化研发投入 80,000,000.00 元」〔锚：2025 年年报·第 128 页·附注五·研发投入〕[S1]
```

结构是 `- 项名 值 「原句」〔锚：位置〕[S#]`。四项缺一不可（`未取到` 行、`[待人工]` 行与〔自算〕行是三个例外）。

自算的一行长这样：

```
- 资本化率 25.00%〔自算〕分子＝本期资本化研发投入 80,000,000.00 元 [S1]｜分母＝本期研发投入合计 320,000,000.00 元 [S1]
```

比例在原句里找不到就必须标〔自算〕，并在同一行交代分子与分母各挂哪个来源。

## 五、和另外几枚包怎么分

| 你的问题 | 该用哪一枚 |
|---|---|
| 无形资产与商誉的减值风险判定 | `cn-goodwill-impairment-risk` |
| 研发费用加计扣除等税收口径 | `tax-policy-card-cn` |
| 政府补助与研发补助的台账 | `cn-gov-grant-quality` |
| 四期差异、科目勾稽的点评 | `cn-earnings-note` |
| 审计意见类型 | `cn-audit-opinion-cn` |
| **研发投了多少、资本化多少、怎么摊、条件怎么写** | **本件** |

一句话分界：本件只登记**研发这一节披露怎么写**，不判研发成色、不判税收、不判减值。

## 六、素材从哪来

- 首选：年报附注里「开发支出」与「无形资产」两节 + 研发投入专项披露（若有）；
- 次选：交易所同披件、招股书的研发投入与开发支出节；
- 末选：第三方摘要——本件会把它降级标注「二手、未对过附注」。

数据通道以目录现值为准：先匿名取 `https://cuecue.cn/api/mcp-catalog`，按返回的域与 `routing` 连；解析腿（`cue-omni-reader`）只在原句落在长附件或扫描件里时才发起。两步形制如下（域与工具名一律照现场返回填，不要照抄示例值）：

```bash
# 一、匿名发现：取现值域清单与 routing（不写死域与工具名）
curl -s https://cuecue.cn/api/mcp-catalog | head -c 400

# 二、已连上后取工具清单：以现场返回为准
curl -s -X POST "$MCP_ENDPOINT" \
     -H "Authorization: Bearer $CUE_API_KEY" \
     -H 'Content-Type: application/json' \
     -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | head -c 800
```

配置页只作指针：文本腿 <https://cuecue.cn/hub/mcp>、解析腿 <https://cuecue.cn/hub/omni-reader>、key <https://cuecue.cn/hub/api-key>。

## 七、跑夹具与测试

```bash
bash scripts/fixtures/run_fixtures.sh                    # 三档，末行现算档数
python3 scripts/check_rd_capitalization.py --selftest    # 13 档内置夹具
python3 tests/test_rd_capitalization.py                  # 15 条包级测试
```

runner 的末行形制是 `档数=N（由上面逐档现报）｜不合=M｜不可判=K`。**档数不写死在文档里**——加了注入就自己变，写死迟早对不上。

## 八、首次运行埋点

第一次跑（任何子命令）会在 `~/.cue-usage/` 下落一枚空文件 `cue-cn-rd-capitalization-cn-YYYY-MM-DD`。同日重复跑只留一枚；家目录不可写或无 `HOME` 时静默跳过，不影响主流程。

为什么留这个：平台两个下载计数器都不可信（新 listing 首 48 小时的一次性播种 50~60 就占了大头），本地这枚文件是本件唯一能证明「真有人装上并跑过」的东西。

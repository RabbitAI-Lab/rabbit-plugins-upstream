# WorkBuddy Adapter

用于 WorkBuddy 类办公 Agent。目标体验：用户丢文件或粘贴一段内容后，先收到一个可截图的一屏判定，再展开细节。

## Entry Handling

常见入口：

- `这份能发吗`
- `帮我做出街体检`
- `明天发老板，先帮我扫一遍`
- `客户版检查一下`
- `只看会翻车的地方`
- `30分钟内怎么救`

## First Screen

WorkBuddy 首屏控制在 6 行内：

```markdown
出街判定：[判定]
上下文：[对象 + 目标 + 截止；缺失则写缺口]
最大风险：[一句话]
先改：[1-3 个位置，带 error_family/error_type]
能留：[一句话]
30 分钟：[三步压缩版]
继续：[只看必须改] / [帮我改标题] / [生成发送话术]
```

首屏不能只给通用清单；必须体现收件人、目标动作或材料阶段中至少 1 个上下文信号。若上下文缺失，写 `上下文：对象/目标未确认，先按保守场景判`。

文件读取要覆盖正文外发送风险：PPT 隐藏页和备注、Word 页眉页脚和脚注、Excel 公式错误值、隐藏表内部话术、批注/notes、PDF 页脚目录和导出版式。读不到这些区域时，把缺口写进 `未核验项`。

调用本地预筛脚本时，将用户当前请求传给 `--context-text`，必要前文传给 `--conversation-text`。首屏里的对象、目标和截止时间必须来自用户话、文件线索或明确的保守推断，不能只套宿主默认值。

## Follow-up Slots

短回复要能接住：

| 用户回复 | 动作 |
| --- | --- |
| `只看必须改` | 首屏展示前 7 条；如有 `additional_findings`，同步回显其余阻断数和位置，并提供完整展开 |
| `按30分钟路线改` | 给按分钟排序的修复清单 |
| `帮我改标题` | 只改标题和结论语气 |
| `生成发送话术` | 产出老板版或客户版发送文案 |
| `客户版` | 降低内部话术，补风险和承诺边界 |
| `老板版` | 强化决策请求和下一步 |

## WorkBuddy Tone

短、直接、像最后把关的人。默认帮用户保住已经能用的结构，只修会影响发送的部分。

禁用行为：

- 不扩成大而全的写作课。
- 不把美化放在事实和数字前面。
- 不让用户重新填长表。
- 不自动发送、不覆盖原文件。

## Structured Handoff

需要交给后续工具或保存记录时，输出 `inspection.json`，字段遵守 `schemas/presend-inspection.schema.json`：

- 每条 `must_fix` 带 `error_family/error_type`。
- 每条 `must_fix` 带 `context_reason`，说明当前对象、目标或截止时间怎样影响优先级。
- `context_basis.context_signals` 记录上下文来源。
- `context_basis.risk_weighting` 记录排序原因。
- `additional_findings` 保留首屏以外的问题，`finding_overflow` 记录发现总数、其余阻断数和位置。

# 上下文读取门禁

先读上下文，再做出街判断。通用清单只作兜底，不能替代材料语境。

## 上下文包

每次检查先在内部建立 8 个字段：

| 字段 | 读取位置 | 用途 |
| --- | --- | --- |
| 收件人 | 用户话、文件名、首页、邮件正文 | 决定风险权重 |
| 发送目的 | 用户话、摘要页、结尾页 | 判断材料是否服务目标 |
| 目标动作 | 最后一页、邮件正文、会议议程 | 判断有没有下一步 |
| 材料阶段 | 文件名、版本号、批注、语气 | 判断能否保留草稿痕迹 |
| 文件组合 | 附件、压缩包、同目录材料 | 判断主文件和附录能否对上 |
| 旧版本线索 | 文件名、页脚、备注、隐藏表 | 排查版本残留 |
| 截止时间 | 用户话、邮件正文、日程 | 决定修复路线颗粒度 |
| 对话限制 | 用户明确说的“只看风险”“客户版”“别大改” | 控制输出范围 |

## 读取优先级

1. 用户当前指令。
2. 当前对话里前文限制和偏好。
3. 文件名、目录结构、附件组合。
4. 首页、摘要、目录、结尾页。
5. 正文、图表、脚注、备注、附录。
6. 隐藏工作表、批注、修订痕迹、导出效果。

如果文件工具无法读取某一层，写进 `未核验项`。

## 风险权重

| 上下文 | 权重上调 |
| --- | --- |
| 发老板 | 决策请求、结论强度、下一步、关键数字 |
| 发客户 | 承诺措辞、保密、授权、价格、内部话术 |
| 董事会或高层包 | 口径、审计痕迹、汇总一致、来源 |
| 对外媒体或公开材料 | 事实核验、敏感表达、公开来源 |
| 明天或今晚发送 | 阻断风险优先，放弃细枝末节 |
| 只剩 30 分钟 | 只修事实、数字、标题、下一步 |

## 补问规则

只补一个字段。优先级：

1. 发给谁。
2. 要对方做什么。
3. 还剩多久。
4. 是否对外。

材料足够时不要补问，直接给限制版判定。

## 上下文回显

输出里用一行回显判断基础：

```text
我按这个上下文判：发给[对象]，目标[动作]，时间[截止]。
```

对象或目标缺失时：

```text
我先按保守场景判：收件人和目标动作未确认。
```

使用确定性预筛脚本时，把用户当前请求传给 `--context-text`，必要前文单独传给 `--conversation-text`。取证优先级固定为：显式参数、当前指令、对话前文、文件名、文件内容。低优先级证据与已选值冲突时，写入 `context_signals` 的 `*_conflict`；同一层同时指向多个对象时保留 `unknown`，进入补问或未核验项。

## 结构化上下文证据

JSON 输出的 `context_basis` 必须带两个审计字段：

- `context_signals`：列出字段、取值、来源和影响。例：`recipient=boss` 来自用户话，因此上调决策请求和证据强度。
- `*_conflict`：保留低优先级冲突线索或同层未解冲突，避免文件里的“客户提案”覆盖当前指令里的“发老板审批”。
- `risk_weighting`：列出被上调或维持的风险域、方向和原因。例：客户版上调 `privacy_or_commitment_risk` 和 `version_residue`。

每条 `must_fix` 还必须带 `context_reason`，把单条错误和本次发送语境连起来：

- 老板版：说明它怎样影响批示、选方案、证据追问或下一步。
- 客户版：说明它怎样影响承诺、保密、授权、价格、客户可见话术或版本清理。
- 董事会包：说明它怎样影响口径、公式、汇总一致、审计线索或决策基础。
- 临近发送：说明为什么先修阻断风险，放弃低收益润色。

不要只写结论。每次判定都要能回看：哪些上下文信号导致哪些风险优先。

## 失效信号

出现这些情况，说明检查退化成清单，需要回到上下文包：

- 必须改里没有对象差异。
- 老板版和客户版输出几乎一样。
- 只谈格式，没谈目标动作。
- 没有提到对话里用户给过的限制。
- 没有未核验项。

## 上下文敏感性验收

同一份材料换收件人时，风险排序必须变化：

- 发老板：优先看下一步、结论证据和关键数字。
- 发客户：优先看承诺、隐私、授权和版本残留。
- 发董事会：优先看汇总公式、口径一致和审计线索。

封版前运行 `scripts/validate_context_sensitivity.py`。该脚本用同一份邮件草稿分别按老板版和客户版检查；如果第一优先风险和第一条必须改没有随上下文变化，视为失败。

## 缺上下文保守验收

收件人、目标动作、截止时间或材料阶段缺失时，不能给高把握度判断。输出必须：

- `confidence` 降为 `low`。
- `missing_context` 列出缺失字段。
- `risk_weighting` 回退到 `general_presend_risk`。
- `未核验项` 用中文业务标签写明缺失字段，并提示补齐后复核风险排序和发送判定。
- 报告正文使用“我先按保守场景判”开头。
- 报告正文不能把 `recipient`、`target_action`、`deadline`、`material_stage` 当成直接面向用户的缺口文案；这些机器字段只保留在 JSON 里。

封版前运行 `scripts/validate_missing_context_guard.py`。

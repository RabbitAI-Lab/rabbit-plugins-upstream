# 抓错方法

目标：用上下文和证据地图发现真实错误，避免只给泛泛建议。

## 证据地图

先抽取 7 类对象：

| 对象 | 抽取方式 | 用途 |
| --- | --- | --- |
| 关键数字 | 数字、百分比、金额、同比、环比、排名 | 查数字冲突和口径 |
| 关键主张 | 标题、摘要、结论页、加粗句 | 查证据错配 |
| 来源 | 脚注、链接、附录、引用、文件名 | 查来源缺失或错位 |
| 图表 | 标题、坐标轴、单位、图例、数据标签 | 查标题和图表冲突 |
| 公式状态 | 公式引用、错误值、透视表刷新、隐藏筛选 | 查汇总是否可信 |
| 承诺 | 会、一定、保证、交付、价格、上线、负责 | 查越权和客户风险 |
| 决策动作 | 请求确认、选择方案、批预算、定时间 | 查下一步缺口 |
| 版本线索 | 文件名、隐藏页、页眉、页脚、备注、脚注、批注、隐藏表 | 查旧版本残留 |
| 受众标签 | 文件名、封面、首个工作表、页眉页脚、占位语、结尾动作 | 查附件对象错位 |

## 六轮检查

1. 上下文轮：确认对象、目标、截止、内外部、材料阶段；多附件包把当前收件人与每个附件声明的受众逐一对照。
2. 数字轮：先建立 `指标 + 周期 + 区域 + 币种 + 单位 + 范围` 身份，再比较数值。身份不同不报冲突，身份缺失写入未核验项。
3. 触发器轮：按 `references/error-library.md` 的常见触发器矩阵标候选错误，逐条写候选位置。
4. 主张轮：把标题和结论逐条找证据，查强度越界。
5. 文件轮：按文件类型剧本查备注、隐藏表、批注、导出效果。
6. 出街轮：只保留会影响发送的 blocker 和 must_fix；没有 blocker 或 must_fix 时允许判 `可以发送`。

## 交叉核验

| 检查 | 对照 |
| --- | --- |
| 摘要数字 | 正文图表、附录、Excel 明细 |
| 标题结论 | 图表趋势、样本量、来源时间 |
| 客户承诺 | 合同、报价、审批状态、发送对象 |
| 决策请求 | 最后一页、邮件正文、会议议程 |
| 版本信息 | 文件名、隐藏页、页眉、页脚、备注、脚注、隐藏表 |
| 多附件关键指标 | PPT 摘要、Excel 汇总、Word/PDF 正文、邮件正文 |
| 多附件受众标签 | 当前指令里的收件人、每个文件名、封面、首个工作表、页眉页脚、占位语和结尾动作 |
| Excel 公式结果 | 汇总区、图表数据源、明细输入、错误值单元格 |

## 多附件对象核验

1. 以当前用户指令或显式宿主参数里的收件人为主，不让文件名反向覆盖当前指令。
2. 为每个附件单独抽取声明受众：文件名、封面或第一页、首个工作表标题、页眉页脚、内部审阅占位语和末尾动作。
3. 将 `client / customer / external` 视为对外同组，将 `boss / manager / leadership / executive` 视为管理层同组，将 `board / directors` 视为董事会同组。
4. 任一附件落入不同组时，标 `audience_mismatch`，位置至少包含附件名和冲突标签所在位置；客户包出现 `Board Pack`、`Boss Update`、`internal review` 或同义标签时按阻断风险处理。
5. `context_signals` 里的 `recipient_conflict` 只负责保留推断过程，不能替代正式发现。

## 候选错误复核

常见触发器只产生候选错误。进入 `必须改` 前逐条问三件事：

1. 是否有可复查位置：页码、段落、图表、工作表、单元格或附件名。
2. 是否影响本次收件人目标：老板决策、客户承诺、董事会口径或公开可信度。
3. 是否有可执行修法：补来源、统一数字、降级结论、改标题、补下一步、脱敏或重新导出。

三项缺任一项时，放入 `未核验项` 或舍弃，不放进 `必须改`。

进入 `必须改` 后，每条都补 `context_reason`：

- 先引用上下文包里的收件人、目标动作、截止时间或材料阶段。
- 再说明该错误如何影响这次发送，而非泛泛说“有风险”。
- 最后避免重复证据句；证据放在 `evidence`，修法放在 `fix`。

## 发现依据写法

每条问题都要写能复查的依据：

```text
发现依据：第 7 页标题写“显著增长”，图表只显示 1.2% 波动且没有样本量。
```

依据不足时写：

```text
发现依据：当前只看到导出 PDF，看不到底层公式；该项先列为待核验。
```

## 输出筛选

不进入必须改：

- 纯审美偏好。
- 不影响理解的字体和标点。
- 没有上下文支撑的猜测。
- 需要重做整份材料但当前时间不允许的低收益建议。

必须进入必须改：

- 会被收件人当场追问的数字、来源、口径。
- 会造成误解的标题和图表冲突。
- 会引发承诺、保密或授权风险的内容。
- 会让材料无法推动决策的缺口。

干净材料处理：

- 证据、数字、承诺、目标动作和版本状态都过关时，判 `可以发送`。
- 不为了显得谨慎而硬凑必须改。
- 仍保留未核验项，用来说明底层数据、隐藏内容或外部来源无法确认。

## 自动检查底线

宿主文件能力不足或需要快速预筛时，先运行 `scripts/inspect_deliverable.py`。它会调用 `scripts/extract_deliverable_text.py`，对 PPTX、XLSX、PDF 做保守文本抽取和常见硬错误匹配。

`pypdf` 只在实际读取 PDF 时才需要。缺少该可选依赖时，PPTX、DOCX、XLSX 和粘贴正文仍必须正常检查；PDF 改用宿主的文字抽取与渲染能力，不自动安装依赖，并把无法覆盖的页面列入未核验项。

调用时带 `--context-text` 读取当前请求；需要前文时另带 `--conversation-text`，让当前指令拥有更高优先级。自然表达验收由 `scripts/validate_naturalistic_cases.py` 覆盖：风险样本不能直接写 `no source`、`no decision request` 等答案提示，干净 PPT、Word、Excel、PDF 不得硬凑必改项。

适用范围：

- 来源缺失、数字冲突、公式或汇总异常、结论证据错配、决策缺口。
- PDF 导出页数、图例遮挡线索、来源链接断裂。
- PDF 文字层缺失或几乎不可抽取，避免把图片型 PDF 误判为已读完。
- PPT 备注区内部话术、旧价格、客户不可见说明，避免只读正文漏掉发送副本残留。
- PPT 隐藏页内部话术、旧价格、客户不可见说明，避免只看可见放映页漏掉发送副本残留。
- Word 页眉、页脚、脚注和尾注内部话术，避免只读正文漏掉对外副本残留。
- Excel 隐藏表、公式错误值、透视表刷新线索、单位币种缺口。
- Excel 隐藏工作表内部草稿、旧价格和客户不可见说明，避免只读可见表漏掉对外副本残留。
- Excel 批注/notes 内部审批、旧价格和客户不可见说明，避免只读单元格值漏掉发送副本残留。

限制：

- 只能覆盖可抽取文本和基础元数据。
- 不能替代人工/模型阅读图表图像、备注、外部来源和业务语境。
- 输出里的 `unverified_items` 必须保留。

封版前运行 `scripts/run_regression_suite.py`，确保夹具生成、抽取、自动检查、schema 校验和种错评测全部通过。

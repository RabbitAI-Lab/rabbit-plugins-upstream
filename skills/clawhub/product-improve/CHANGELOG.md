# v1.4.12

- 消除静态审计误报：`safe_export_path()` 的文档字符串原本用一个指向 SSH 授权文件的相对路径
  作「任意路径覆盖」的攻击样例，被 ClawSweeper 一类的模式匹配误判为「访问 SSH 私钥文件」。
  改为抽象表述（`../../<敏感文件>`），不再出现具体敏感文件名。
  仅为文档措辞调整，导出的目录限制、符号链接拒绝与 `O_NOFOLLOW` 行为完全不变。
- 命令语义、字段与计费规则一律不变，不提高最低支持版本。

# v1.4.11

- 能力层收窄：44 个专属包不再只是「声明窄」，包体 `scripts/ari.py` 同时按各自契约裁剪。
  构建期用 AST 删除文档未承诺的命令、它们的解析器注册块，以及只被它们引用的辅助函数与
  常量；专属包因此不再包含 `export`（任意路径写文件）、`autoconfirm`（撤销逐次确认）、
  `workbench`（改写差评处理状态）、`alerts`（标记预警已读）、`competitors`、`schedule`、
  `voc` / `analyze` / `charts` / `deepdive` 等母版命令。
- 新增运行期兜底闸：专属包在包内写入 `allowedCommands` 白名单，`ari.py`
  启动时复核，命令不在白名单内直接以 `ARI_COMMAND_NOT_ALLOWED` 退出。只删代码不留闸的话，
  把命令加回来就能绕过收窄。
- `export` 落点加固：`--out` 解析后必须位于允许目录内（默认当前工作目录，可用
  `ARI_EXPORT_DIR` 显式放开），越界路径与符号链接一律拒绝，写文件时带 `O_NOFOLLOW`；
  命中时返回 `ARI_EXPORT_PATH_BLOCKED`，且不发出请求。
- 全系列的 `check` 不再回报账户免确认策略：它只服务于「小额付费操作直接生成」，等于把
  「不用先问」交给 agent，与「先报价、用户明确确认才执行」的契约冲突。付费门槛仍由服务端
  策略控制，本地不做任何隐式确认。
- 构建期新增两条硬闸：裁剪后的真实命令集必须与白名单完全一致；裁剪结果必须同时通过
  `ast.parse` 并真实打印出让命令表（`python scripts/ari.py --help`）。
- 全部 73 个包延续 v1.4.10 的窄声明；命令语义、字段与计费规则一律不变，
  不提高最低支持版本。

- 清理包内悬空引用：母版正文不再提及仅专属包才生成的约束文件，静态分析不再报
  「引用了包内不存在的产物」。

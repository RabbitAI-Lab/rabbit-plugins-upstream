# Feature plan

## Goal and acceptance

Link the requirement. Describe current behavior, the scope of the change, and what a caller should see for a concrete input. If a current standard determines acceptance, link the clause and preserve its conditions and exceptions. Include a distinguishing example when interpretations differ.

## Implementation

Identify the entry point, proposed edit, dependencies and any public contract.

## Verification

Give the working directory, command or action, required data and expected result.

## Decisions still needed

State which observable outcome depends on the decision and what can proceed. Omit when settled.

## Result

For a small change record the edit, actual verification and remaining work here. For a task list, link the original tasks and evidence instead.

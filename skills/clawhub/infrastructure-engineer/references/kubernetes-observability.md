# Kubernetes 可观测性 Playbook

> 看不见的系统不可控。本 playbook 给出 K8s 可观测性的四支柱（日志/指标/追踪/事件）与黄金信号落地方法。

## 决策树：监控该从哪入手

```
系统出问题
  ├─ 完全不可达？→ 指标（RED/USE）+ 存活探针
  ├─ 慢但可用？→ 指标（延迟分布）+ 追踪（慢调用链）
  ├─ 偶发错误？→ 日志（结构化）+ 追踪（错误跨度）
  └─ 资源耗尽？→ 指标（CPU/内存/吞吐）+ 事件（OOM/驱逐）
```

## 四支柱

| 支柱 | 回答的问题 | 常用信号 | 工具倾向 |
|------|-----------|----------|----------|
| 日志 | 发生了什么 | 结构化日志、错误栈 | Loki / ELK |
| 指标 | 健康度如何 | RED（请求/错误/时延）、USE（利用率/饱和/错误） | Prometheus |
| 追踪 | 慢在哪 | 跨度、调用链、瓶颈节点 | Tempo / Jaeger |
| 事件 | 发生了什么变更 | 调度、驱逐、OOMKill、滚动更新 | k8s Events |

## 黄金信号（SLI/SLO 落地）

- **延迟**：关注 p95/p99 而非均值（长尾才是用户体验）。
- **流量**：QPS / 并发，判断容量。
- **错误率**：5xx / 失败请求占比，设 SLO（如 99.9%）。
- **饱和度**：队列深度、CPU/内存压力，预警而非事后。

## 告警原则

- **基于 SLO 燃尽**：错误预算告警，而非对单指标拍阈值。
- **可操作**：每条告警对应一个明确动作，避免"狼来了"。
- **去噪声**：聚合、抑制、路由到正确值守方。

## 常见坑（踩坑清单）

- **只看均值不看 p99**：均值"正常"但长尾用户延迟爆表，体感与监控脱节；SLO 必须基于分位数而非均值。
- **静态阈值告警**：对固定阈值拍脑袋，流量波动即误报/漏报；改用 SLO 燃尽 + 多窗口多燃尽率判定。
- **追踪采样率失控**：采样过高成本爆炸，过低则慢链路漏采；按错误/慢请求提采样、正常流量降采样。
- **日志非结构化**：纯文本日志无法检索聚合，关键字段必须 JSON 化并带 `trace_id` 串联链路。
- **指标基数爆炸**：把 `user_id`/`request_id` 当 label 会令 cardinality 飙升拖垮 Prometheus；高基数维度走日志或追踪。

## 输出

对集群可观测性现状给出短板清单（缺哪根支柱）+ 优先补哪项的建议。不替用户定 SLO 数值。

## 边界

- 不替用户改集群配置；产出诊断与建议。
- 采样率、保留期等需结合成本权衡，标注建议而非命令。

# 招采萝卜坑识别专家 · 设计说明（Design Spec）

> 版本：v1.1.1　作者：一线评标专家　许可：MIT-0　slug：`bid-carrot-pit`
> 本文档面向「技能设计评审 / 二次开发者 / 实战调优者」，详述架构、信号标尺、防幻觉机制与知识库挂载方案。

---

## 0. 一句话定位

**投标人侧的「招标文件萝卜坑」专项扫描仪**——把一整份招标文件（不只是评标表）翻个底朝天，找出**为某个特定供应商"量体裁衣"**的排他性、歧视性、不合理门槛条款，输出风险等级 + 法条方向 + 质疑/投诉弹药。

它解决的是招投标实战里最阴险的一类风险：**明面合规、暗藏量身**。这类坑单看一条都"说得通"，叠在一起才暴露"这标只给某人留了门"。

---

## 1. 为什么需要这个技能（问题域）

### 1.1 现有能力的空白

| 已有能力 | 覆盖 | 盲区 |
|---|---|---|
| 投标模拟评标·模式 C（合规审查） | **仅评标表**（评分项+否决条款+资格门槛） | 不看招标文件全文的**技术参数、品牌指定、业绩规模门槛、合同条款**——而这些正是萝卜坑高发区 |
| 智慧招采专家·商机甄别 | 采购公告/邀请书级（投前情报） | 只到公告级初扫，不深入全文做排他性专项审查 |
| 第三方 bid-lightning-rod / bid-rejection-risk-radar | 我方会不会被废 | 视角是"我方被否"，不是"招标文件是否给某家量身定做" |

**萝卜坑识别器的增量价值**：范围扩到**全文 5 大区域**，视角专盯"量身定制"，是对现有技能矩阵的精准补位。

### 1.2 萝卜坑的三种典型形态

1. **排他性**：指定品牌/型号、限"或相当于"家数、限定特定认证组合。
2. **歧视性**：地域注册/纳税、排斥民企/外资、本地化强制加分。
3. **不合理门槛**：业绩规模/金额/甲方类型三条件叠加、异常精确的技术参数值、隐性资金门槛（高额保证金+0预付+长账期）。

## 2. 与现有技能的关系（解耦设计）

```
┌─────────────────────────────────────────────────────────┐
│  智慧招采专家（总调度 · 全周期）                        │
│     ├─ 商机甄别节点（投前"要不要投"）                  │
│     └─ 深度节点 D（投标模拟评标 · 知己知彼）          │
│            ├─ 模式 A 模拟评标（打分找最弱项）          │
│            ├─ 模式 B 得分点导航+覆盖审计              │
│            └─ 模式 C 评标表合规审查（只看评标表）      │
│                                                          │
│  【独立解耦】招采萝卜坑识别专家（扫全文找坑 · 攻敌）  │
│        ↑ 可单独触发，也可串联：扫坑 → 模拟评标看我方  │
└─────────────────────────────────────────────────────────┘
```

**设计原则**：本技能**不做评分模拟、不做响应覆盖审计**（那是投标模拟评标的事），**只识别招标文件本身的量身定制线索**。脚本只做机械抽表/分章节，主观识别交 LLM——保持"脚本当加速器、LLM 当裁判"。

## 3. 整体架构（工作流）

严格六步顺序，任何一步缺料都不能跳过硬扫：

```
输入 → ① 输入预检 → ② 分章节定位(+防漏扫) → ③ 多维信号扫描
     → ④ 组合推理(拼图效应) → ⑤ 风险定级+法条方向 → ⑥ 输出报告
```

| 步骤 | 关键动作 | 防翻车机制 |
|---|---|---|
| ① 输入预检 | 核对完整文件/项目属性/采购标的/用户目的 | 缺料先追问，防"用户没给"误判"文件没写" |
| ② 分章节 | 按中文层级标题切分 5 大区域 | **防漏扫三大盲区回溯**（见 §4） |
| ③ 信号扫描 | 逐章对照 9 类信号标尺 | 每条回指"第X章第Y条"，定位精度不丢 |
| ④ 组合推理 | 多条款叠加指向同一家 = 拼图效应 | 单条合规≠整体合规，交集论证 |
| ⑤ 风险定级 | 🔴/🟠/🟡 + 法条方向（模糊化） | 两法硬隔离 + 时效核验 |
| ⑥ 输出 | 概览+清单+拼图+弹药+绕坑+免责 | >15 项自动折叠保焦点 |

---

## 4. 防漏扫机制（核心创新 · 应对 Lost in the Middle）

长招标文件（100-300 页）下，LLM 极易忽略中后段（技术偏离表、合同特殊条款、附件表格）。本技能把"纯 LLM 记忆"变成**确定性机械辅助**：

- **`scripts/split_sections.py`** 在切分时对每个章节打 `flags`：
  - `hard_marker`：含 ★/▲/「实质性响应」等否决与量身高发标记
  - `appendix`：附件/附录/图纸说明区域
  - `payment`：付款节点/违约金/履约保证金/预付款
- **§2.2.1 强制校验**：逐章扫描后，必须对任一 `flag=true` 的章节声明「已扫 / 未读」。
- **截断红字警告**：若文件因长度截断无法读全，报告【概览】必须用红字警告「未读取到技术偏离表/合同附件，存在漏扫高风险」——**绝不静默假装干净**。

> 这是 v1.1.0 相对 v1.0.0 最有价值的加固：把"靠 LLM 别漏看"的软指令，升级为"脚本标红 + 强制声明"的硬机制。

## 5. 9 类信号标尺（核心 IP）

`references/carrot-pit-signals.md` 是本技能的护城河，逐类含「表现形式 / 一秒特征 / 识别要点 / 量身逻辑」+ 4 个疑难 Few-Shot 校准样本。

| # | 信号类型 | 典型表现 |
|---|---|---|
| 1 | 品牌/型号排他 | "XX 品牌原厂或相当于（限 3 家内）" |
| 2 | 资质/认证组合排他 | 多证叠加、全国仅少数家同时满足 |
| 3 | 业绩门槛量身 | 金额+甲方类型+规模三条件叠加 |
| 4 | 人员/设备门槛 | 特定数量涉密人员、指定设备型号 |
| 5 | **技术参数量身** | 非标精确值 + 私有指令集（最隐蔽） |
| 6 | 评标办法倾向 | 主观分畸高且无量化档位 |
| 7 | 合同条款排他 | 异常付款/验收/管辖地偏袒 |
| 8 | 地域/所有制歧视 | 本地注册/纳税、排斥民企外资 |
| 9 | **商务/资金隐性门槛**（v1.1.0 新增） | 高额履约保证金/0 预付/特定银行授信/垫资 |

**信号 9 的特殊处理**：这类条款通常不违规，但实质排除中小企业。它**难硬质疑**，所以报告里走"预警 + 破局策略"而非质疑弹药——避免 LLM 硬编法条去质疑一个不违规的条款。

## 6. 组合推理 · 拼图效应（精髓）

单条可能合规，**叠加**才暴露量身。输出时用"线索连线"呈现：

```
🎯 疑似锁定目标画像：[具备涉密资质 + 拥有某特定软著 + 本地化服务团队]
🧩 拼图条款：
   拼图1（资质）：第二章 2.1 → 要求涉密甲级（全国仅 X 家）
   拼图2（技术）：第三章 3.4 → 要求提供某特定软著截图
   拼图3（加分）：第四章 4.2 → 本地化团队驻场承诺加 5 分
💡 组合杀伤力：单看拼图3 只是加分项，但结合拼图1+2，全国能同时满足且拿满分的供应商 ≤3 家 = 实质性萝卜坑
```

## 7. 法条防护三重锁（防幻觉红线）

质疑弹药最易翻车的就是"LLM 自动默写废止法条 / 串用两法"。v1.1.0 起升为**三重硬锁**：

1. **法条模糊化**：草稿仅写"根据《XX法》第X条关于'不得以不合理条件限制、排斥潜在投标人'的规定…"，**禁止默写具体法条原文**。
2. **两法硬隔离**：政府采购体系**绝不**引《招标投标法》；工程招投标**绝不**引《政府采购法》及 87 号令。跨体系引用为红线错误（行业笑柄级）。
3. **时效核验声明**：每段弹药后必附 `[⚠️ 发送前请务必通过"全国法律法规数据库"核实该法条现行有效性]`。

> 法条方向表（`references/legal-anchors.md`）与投标模拟评标·模式 C **对齐并扩展**，含两法分轨、硬软法区分、质疑路径，只给方向不写定论。

## 8. 双层知识库架构（v1.1.1 挂载方案）

"挂载知识库"本质是把相关 IMA 库的**真实 ID 写入技能配置**，让运行时知道去查哪些库。本技能采用**双层**设计：

### 8.1 自有基线 IP（确定性，随技能走）
- `references/carrot-pit-signals.md`（信号标尺）
- `references/legal-anchors.md`（法条方向表）

这两个是技能内置的**确定性标尺**，不依赖外部网络，永远可用。

### 8.2 外部活库（动态核实层，已关联 6 库）

| 知识库 | ID | 用途 / 何时查 |
|---|---|---|
| 招投标实务与合规 | 7463402595160740 | **主库首选**——两法法规全文/政策解读/实务指引/典型案例 |
| 招标文件、采购文件汇集 | 7439473860155957 | 真实招标文件样本身，校准"参数是否异常/是否常见" |
| 政府采购实务与合规 | 7463496212028405 | 政府采购体系专属（87号令、中小企业政策） |
| 招投标评标否决AI知识库 | 7460608999968055 | 否决/废标口径，反向验证某坑是否触发否决 |
| 国有企业采购 | 7466027138969773 | 国企非依法必招项目内部规章与实务 |
| 招投标异议投诉处理 | 7480160395744474 | 质疑/投诉路径与处理参考，支撑「质疑弹药」 |

**检索纪律**：
- 政府采购项目**只**查政府类两库 + 主库；工程招投标**只**查主库 + 招标类样例库（两法硬隔离延伸）。
- 引用须标注来源库，不得脱离库内容臆造。
- 法规现行有效性仍须以全国法律法规数据库终核（§5 时效声明）。

> 为何不直接把 references 塞进 System Prompt？——省 Token，且法规/标尺更新只改 KB 不动核心提示词。

## 9. 输出骨架（可读性控制）

报告六段式（模板见 `templates/carrot-pit-report.md`）：

```
一、概览（含盲区回溯红字警告）
二、萝卜坑清单表（章节|原文|类型|风险|量身逻辑|法条方向|质疑建议）
三、量身定制组合分析（拼图效应）
四、质疑/投诉弹药（模糊化 + 两法隔离 + 时效声明）
五、绕坑与破局策略（合法突围 B 计划：联合体/正偏离/成本止损）
六、免责声明
```

**长度控制**：清单 **> 15 条**时，仅展示 🔴 + 🟠 核心项，🟡 低危折叠或提示「输入『展开全部』查看」——保报告焦点。

## 10. 护栏边界（铁律）

- **只识别、不捏造**：坑必须基于文件真实条款，不得硬说中性表述是坑。
- **法条模糊化、不默写**：见 §7。
- **两法分轨硬隔离**：跨体系引用为红线。
- **不教唆缠诉、不教唆规避**：绕坑策略仅限合法突围，严禁钻空子/骗分。
- **时效声明**：法规可能修订，结论以现行有效法为准。
- **风险分级不越权**：🔴 是"高度疑似/明显违规可质疑"，非"必然废标"。

## 11. 脚本设计（`scripts/split_sections.py`）

- **职责**：按中文层级标题切分长文档（第一章 / 一、/ 4.2 / （一）），输出 `sections.json`（id/heading/level/text/flags）。
- **关键修复（v1.0.0 → v1.0.1 内测）**：初版把「1.1 / 4.2」这类**条款号误判成标题**，导致「第一章」「第四章」整章漏检。改为**标题必须后接 ≥2 个汉字的标题短语**，数字条款号不再误判。
- **降级模式**：脚本不可用/解析失败时，LLM 直接按可见标题手动切分，流程不中断。
- **flags 机械标记**：`hard_marker / appendix / payment` 驱动 §2.2.1 防漏扫强制校验。

## 12. 部署与触发

- **Welcome Message**：触发即抛 §2.1 输入预检清单，建立专业第一印象、前置规避缺料误判。
- **触发词**：「扫一下这份招标文件的萝卜坑」「识别排他性/歧视性条款」「这是不是量身定做的标」「招标文件合规性审查（全文）」「质疑弹药/投前避坑扫描」「检查有没有为某人留专属通道」。
- **Few-Shot 扩展位**：实战发现某类"伪装成中性"的坑 LLM 仍看不准，在 `carrot-pit-signals.md` 追加疑难 Case 即可，无需改核心流程。

## 14. 已知边界与后续

- **边界**：长文档若完全超出上下文上限，依赖 §2.2.1 红字警告而非假装扫描；法条最终有效性须人工/法规库终核。
- **后续增强位**：① 把 demo 跑真实百页标验证中后段盲区抓取；② 针对"伪装中性坑"持续补 Few-Shot；③ 若平台支持技能级 KB 绑定配置，可把 §9.1 的 ID 移入 manifest 声明字段，进一步降低运行期误配。

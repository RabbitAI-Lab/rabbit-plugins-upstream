# 麦肯锡式分析框架参考

## 一、MECE 原则（互不重叠，完全穷尽）

### 核心要义
- **Mutually Exclusive**：各分类之间互不重叠
- **Collectively Exhaustive**：所有分类合在一起完全覆盖问题范围

### 应用方法
1. 确定分析对象的范围边界
2. 寻找切割维度（按时间/按地域/按客群/按产品线/按渠道等）
3. 验证 MECE 性：检查是否有遗漏、是否有重叠
4. 逐层向下拆解，形成 issue tree（议题树）

### 示例：如何提升某电商APP的GMV
```
GMV = 活跃用户数 × 转化率 × 客单价 × 复购次数
├── 活跃用户数
│   ├── 新用户获取（渠道拉新、裂变、品牌）
│   └── 老用户留存（推送、优惠、内容）
├── 转化率
│   ├── 搜索转化（搜索优化、推荐精准度）
│   └── 浏览转化（详情页优化、评价管理）
├── 客单价
│   ├── 商品定价策略
│   └── 交叉销售/向上销售
└── 复购次数
    ├── 会员体系
    └── 复购触达机制
```

## 二、SCQA 框架（情境-冲突-问题-答案）

### 结构说明
| 要素 | 含义 | 作用 |
|------|------|------|
| **S**ituation（情境） | 描述受众已知的背景 | 建立共识起点 |
| **C**omplication（冲突） | 打破现状的变化或挑战 | 制造张力，引出问题 |
| **Q**uestion（问题） | 面对冲突需要回答的核心问题 | 聚焦分析方向 |
| **A**nswer（答案） | 对问题的回答，即核心结论 | 结论先行 |

### 示例
- **S**：2024年中国新能源车市场渗透率已达35%，头部品牌月销过万
- **C**：但二三线城市充电基础设施覆盖率不足20%，成为渗透率进一步提升的瓶颈
- **Q**：如何在不依赖大规模基建的前提下，突破下沉市场充电难题？
- **A**：建议采用"移动充电车+社区共享桩"的轻资产模式，预计6个月内可覆盖目标城市80%用户

## 三、金字塔原理

### 核心原则
1. **结论先行**：核心论点放在最前面
2. **以上统下**：每层结论由下层论据支撑
3. **归类分组**：同层论据按逻辑分组
4. **逻辑递进**：同组内按时间/重要性/演绎顺序排列

### 金字塔结构
```
                    [核心结论]
                   /          \
           [论点A]            [论点B]
          /    \              /    \
     [证据A1] [证据A2]  [证据B1] [证据B2]
```

### 每页PPT的"So What"检验
- 每页标题必须是一个完整的结论句，不能是描述性标题
- 标题 = 这页数据说明了什么结论
- 示例：❌"各渠道获客成本对比" → ✅"信息流广告获客成本最低但质量最差，建议转向内容营销"

## 四、SWOT 分析

### 基础矩阵
| | 有利因素 | 不利因素 |
|---|---------|---------|
| **内部** | **S**trengths（优势） | **W**eaknesses（劣势） |
| **外部** | **O**pportunities（机会） | **T**hreats（威胁） |

### 进阶：SWOT 策略矩阵
| 策略 | 组合 | 含义 |
|------|------|------|
| **SO**（增长型） | 优势+机会 | 利用优势抓住机会 |
| **WO**（扭转型） | 劣势+机会 | 克服劣势抓住机会 |
| **ST**（防御型） | 优势+威胁 | 利用优势规避威胁 |
| **WT**（规避型） | 劣势+威胁 | 最小化劣势和威胁 |

## 五、波特五力模型

### 五力分析框架
1. **供应商议价能力**：供应商集中度、转换成本、替代输入 availability
2. **买方议价能力**：买方集中度、转换成本、信息透明度
3. **新进入者威胁**：进入壁垒（规模经济、品牌、资本、政策许可）
4. **替代品威胁**：替代品的性价比、用户转换意愿
5. **行业竞争强度**：竞争者数量、行业增速、退出壁垒、产品差异化

### 评分标准
- 高/中/低三档评估每力
- 综合判断行业吸引力

## 六、3C 分析模型

| 维度 | 分析重点 | 关键问题 |
|------|---------|---------|
| **Customer**（顾客） | 市场规模、细分、需求、行为 | 谁在买？为什么买？买什么？ |
| **Competitor**（竞争者） | 竞争格局、份额、优劣势 | 谁在争？怎么争？差异在哪？ |
| **Company**（公司自身） | 资源、能力、定位 | 我们有什么？能做什么？ |

## 九、假设驱动分析

### 流程
1. **提出假设**：基于经验和初步信息，提出2-3个可能的核心假设
2. **设计验证**：为每个假设设计验证方法和所需数据
3. **数据收集**：有针对性地收集验证数据
4. **验证/推翻**：用数据验证或推翻假设
5. **迭代**：推翻的假设更新为新假设，重复以上步骤

### 示例
- 假设1："用户流失主要因为价格过高" → 验证：对比流失用户与留存用户的ARPU → 若流失用户ARPU反而更低，假设推翻
- 假设2："用户流失主要因为功能不满足需求" → 验证：分析流失用户的最后行为 + 流失原因调研

## 十、Kano 模型

### 需求分类
| 类型 | 特征 | 策略 |
|------|------|------|
| **基本型需求** | 不满足则不满，满足后无感 | 必须做到位，但无需过度投入 |
| **期望型需求** | 满足度与投入成正比 | 持续优化，建立竞争优势 |
| **兴奋型需求** | 不满足无感，满足后惊喜 | 适度创新，制造差异化亮点 |

### 分析步骤
1. 设计正向/反向问卷问题
2. 收集用户回答
3. 按Kano评估表分类需求
4. 绘制Better-Worse系数图，确定优先级

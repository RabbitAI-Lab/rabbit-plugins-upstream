# 竞品深度拆解方法论

## 一、竞品分析全景框架

### 分析维度矩阵

| 维度 | 子维度 | 数据来源 |
|------|--------|---------|
| **产品力** | 功能矩阵、用户体验、技术架构、迭代节奏 | 产品体验、App Store/应用宝、官网 |
| **商业模式** | 收入模式、定价策略、成本结构、单位经济 | 财报、天眼查、官网定价页 |
| **市场表现** | 市场份额、用户规模、增长率、排名趋势 | 行业报告、七麦数据、QuestMobile |
| **公司实力** | 融资历程、团队背景、专利储备、战略方向 | 天眼查、Crunchbase、新闻 |
| **运营策略** | 获客渠道、内容策略、社群运营、活动节奏 | 社交媒体、广告素材库、官网 |
| **用户口碑** | 评分评价、NPS、投诉热点、推荐意愿 | App Store评论、社交媒体、黑猫投诉 |

## 二、竞品选择策略

### 竞品分层
| 层级 | 定义 | 分析深度 |
|------|------|---------|
| **直接竞品** | 同一市场、相同目标用户、相似产品 | 深度拆解（全维度） |
| **间接竞品** | 不同产品形态但解决相同需求 | 中度分析（商业模式+用户重叠度） |
| **潜在竞品** | 有能力进入但尚未进入的玩家 | 轻度扫描（能力评估+进入可能性） |
| **标杆参照** | 非竞品但某方面值得学习 | 专项分析（单维度深挖） |

### 选择数量建议
- 核心竞品：2-3个（深度拆解）
- 扩展竞品：3-5个（对比表格）
- 标杆参照：1-2个（专项学习）

## 三、功能对比矩阵模板

### 功能对比表
```
| 功能模块 | 我方 | 竞品A | 竞品B | 差距分析 |
|---------|------|-------|-------|---------|
| 核心功能1 | ✅ 有 | ✅ 有 | ❌ 无 | 与A持平，领先B |
| 核心功能2 | ⚠️ 部分 | ✅ 有 | ✅ 有 | 需补齐 |
| 差异功能1 | ❌ 无 | ✅ 有 | ❌ 无 | A独有，评估必要性 |
| 创新功能1 | ✅ 有 | ❌ 无 | ❌ 无 | 我方独有优势 |
```

### 评分标准
- ✅ 有：功能完整，体验良好
- ⚠️ 部分：功能存在但体验一般或覆盖不全
- ❌ 无：不具备该功能

## 六、企业信息查询清单（天眼查）

### 查询内容清单
| 查询项 | 用途 | 关键关注点 |
|--------|------|-----------|
| 工商基本信息 | 确认企业合法性 | 注册资本、成立时间、法定代表人 |
| 股东信息 | 了解股权结构 | 实际控制人、持股比例、关联企业 |
| 融资历程 | 判断资金实力和资本认可度 | 轮次、金额、投资方、估值 |
| 对外投资 | 了解战略布局 | 投资了哪些公司/赛道 |
| 知识产权 | 评估技术壁垒 | 专利数量/类型、商标、软著 |
| 行政处罚 | 风险评估 | 处罚类型、金额、时间 |
| 司法风险 | 合规风险 | 诉讼类型、数量、判决结果 |
| 经营异常 | 经营健康度 | 异常原因、是否已移出 |

### 使用方式
- 天眼查 MCP 连接器已连接时：直接调用 `mcp__tyc-mcp` 系列工具查询
- 未连接时：提示用户在「连接器管理」中启用天眼查连接器，或通过 Web 搜索天眼查公开页面替代

## 七、应用市场数据查询（七麦数据）

### 查询维度
| 数据项 | 分析价值 |
|--------|---------|
| 下载量及趋势 | 判断增长态势、季节性波动 |
| App Store/安卓市场排名 | 品类排名变化反映竞争格局 |
| 版本更新频率 | 产品迭代节奏、研发投入 |
| 评论评分及趋势 | 用户满意度变化 |
| 关键词覆盖/ASO | 获客策略、搜索优化能力 |
| 预估收入 | 商业化能力（iOS内购数据） |

### 数据获取方式
1. 七麦数据网站（qimai.cn）公开页面 → WebFetch 获取
2. 用户提供七麦数据导出文件 → 直接分析
3. App Store/Google Play 公开评论 → Web 搜索获取

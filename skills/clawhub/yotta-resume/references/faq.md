# 常见问题

## 有 JD 和没有 JD 有什么区别？

没有 JD 时，`jd_match.coverage` 为 `null`，工具不会猜测岗位匹配度。提供 JD 后，
工具只使用版本化固定词表检查明确术语，并返回 `lexicon_version` 和 `limitations`。

## 行业是怎么识别出来的？

只根据简历中明确出现的行业关键词打分，不使用姓名、年龄、性别、照片等受保护属性。
信号接近时返回 `ambiguous` 并要求确认；没有命中时使用通用兜底行业。
网络安全当前有详细岗位族和种子题，其他行业后续通过注册表扩展。

## “结构准备度（规则分）”是什么？

它只检查章节、量化证据、文本清洁度和可选的 JD 关键词覆盖，不是招聘方评分，
也不能预测面试或 Offer。只能原样引用，不得另造数字或区间。

## 扫描版 PDF 为什么没有结果？

元简只读取文字层，不执行 OCR。加密、损坏、扫描件或文字过少时会受控失败，
不会生成伪完整报告。可以粘贴文字、改用 DOCX 或先本地 OCR。

## DOCX 里的图片、文本框和页眉页脚为什么没出现？

DOCX 解析以 WordprocessingML 正文为主。图片和复杂版式没有稳定文本层时会列入
未知项；需要完整诊断时优先提供可复制的 Markdown 或纯文本。

## 没有 Chrome / Edge 还能用吗？

可以导出 DOCX 和 HTML。PDF 导出需要本机 Chromium、Chrome 或 Edge；
`doctor` 会把缺失浏览器标记为 `WARN`，不会阻断其他格式。

## 一次导出三种格式，PDF 失败会怎样？

元简先渲染到临时区，所有格式都成功后才提交。PDF 失败时不会留下本次 DOCX / HTML
半成品，已有同名文件也会保留。

## 如何避免编造经历和数字？

先回答工具提出的高价值追问，只写用户确认的事实。无法确认规模或结果时写个人边界，
删除未确认分句；不得把团队成果全部写成个人主导。

## 联系方式和隐私怎么处理？

分析报告会遮蔽手机号和邮箱；导出的正式简历按原文保留联系方式，只在需要投递时分享。
HR 默认不能读取候选人私有证据账本、原始简历和分析报告。

## 为什么题目和证据账本是示例或种子内容？

题库用于提供第一轮追问参考，不代表标准答案；证据账本中的唯一示例带有
`EXAMPLE_ONLY`、`user_confirmed=false`、`export_allowed=false`，
不属于任何真实候选人，也不能导出。

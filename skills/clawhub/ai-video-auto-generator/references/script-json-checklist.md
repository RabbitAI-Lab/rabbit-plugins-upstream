# script.json 生成检查清单

每次根据飞书文档生成 `script.json` 前，必须逐一过完以下 7 项检查。
跳过任何一项都会导致角色缺失、比例错误或合成失败。

---

## □ 1. 画幅比例

| 视频类型 | 默认比例 | 说明 |
|---------|---------|------|
| 短剧（竖屏） | `9:16` | 抖音/快手/视频号等短视频平台 |
| 文旅宣传片 | `16:9` | B站/YouTube/大屏播放 |
| 电商/广告 | 确认渠道后定 | 信息流广告通常 9:16，品牌片可能 16:9 |

不要猜——文档里没有明确写就按类型默认，有写就按文档。

---

## □ 2. 时代设定

列出所有场景的时代背景，每个场景都要明确。

```
场景：于都河长征渡口 → 1930年代（历史）
场景：客家围屋       → 现代（但传统生活方式）
场景：赣州现代城区   → 2020年代（当代）
```

**时代错了，服装、建筑、道具全错。** 古代场景不会出现 T 恤，现代场景不会出现铠甲。

---

## □ 3. 角色清单

通读文档，列出**所有出现在画面中的人**，按角色类型归类：

| 角色类型 | 放入 | 说明 |
|---------|------|------|
| **有台词/有特写/有互动的角色** | `character_cards` | 多视图资产图（数量随角色卡而定：标准 4 视图 front/face/side/back + 动态持械/动作视图） |
| **背景群众/方阵/多人同款** | `troop_cards` | 批量生成，不需要个体面部分辨 |
| **无台词但有镜头互动的辅助角色** | `character_cards` | 如手工艺老人、导游、路人（有特写） |

典型错误：只写了主角，忘了辅助角色和群众。

### 角色卡必须填的字段

| 字段 | 重要程度 | 说明 |
|------|---------|------|
| `name` | P0 | 角色名（中英文均可）|
| `age_range` | P1 | 影响外貌特征 |
| `build` | P1 | 身材描述 |
| `color_scheme` | P0 | 服装配色，决定 gc 生成的准确性 |
| `distinctive_mark` | P1 | 标志性特征（红五星、斗笠等）|
| `appearance.armor/clothing` | P0 | 服装描述，必须具体（不能只写"衣服"）|
| `appearance.aura` | P1 | 气质描述 |
| `weapons` | P1 | 武器列表（无则留空数组）|
| `actions` | P1 | 动作列表（行礼/行走/战斗等）|

---

## □ 4. 每个角色的穿着/气质

对于每个 `character_cards` 中的角色，确认：

- ✅ 服装是否符合时代设定
- ✅ 配色是否和场景协调
- ✅ 武器/道具是否合理（红军战士持长枪 ✅，持剑 ❌ 红军战士不会披披风 ✅）
- ✅ action 是否用得上（文旅角色不需要"战斗"动作，短剧可能需要）
- ✅ 三视图分离原则：front/side/back 是**纯人物本体**（无武器/道具），武器在 `action_xxx` 视图中单独生成，合成阶段再合并
- ✅ **定妆照背景统一**：所有定妆照（front/face/side/back）必须使用**纯白背景**，背景指令放在 prompt 最末尾（避免被前面的氛围词冲淡）
- ✅ **face 与 front 一致性**：face 视图的 prompt **必须包含 `base` 但不应包含 `_clothes`** — `_clothes` 含 body/build/color 等全身级描述，会覆盖"面部特写"指令导致画成全身照。face 只需 `base` + `face` + `hair` + `fd_str`（见 `references/prompt-rules.md §1.2`）
- ✅ 服装描述只写角色本身有的：古代角色不穿T恤，现代角色不穿铠甲，没有披风就不要写披风
- ✅ prompt 不脑补角色卡没有的元素：代码会从 armor/clothing 字段自动提取描述，不会额外添加角色不穿的衣物
- ✅ **头发/头饰描述足够精确**：不能写"传统头巾"、"经典发型"等模糊词，必须指定颜色+位置+系法（见 `references/prompt-rules.md §1.1`）

---

## □ 5. 场景清单

通读文档，列出所有拍摄地点，每个场景填写：

```json
{
  "name": "于都河长征渡口",
  "style_keywords": "历史遗迹、红色圣地",
  "lighting": "清晨薄雾，暖金光线",
  "atmosphere": "庄严、肃穆",
  "key_elements": ["于都河", "渡口纪念碑", "红旗", "晨光"]
}
```

每个场景要有：
- `key_elements`：决定 gs 生成的画面内容
- `lighting` + `atmosphere`：决定首帧图和视频的光影氛围

---

## □ 6. 逐镜头核对（最重要）

对每个 shot，逐项检查：

| 检查项 | 说明 |
|-------|------|
| `scene` | 这个镜头在哪个场景拍？→ 对应场景卡 |
| 画面里有哪些人？ | 主角？辅助角色？群众？ |
| **角色名 vs 泛称** | **description 中涉及角色的地方必须使用角色卡中的全名或实词，禁止用「猫」「狗」「他」「她」「男子」「女子」「老人」等泛称。optimizer 的字符匹配无法将泛称映射到角色，会导致 characters 字段缺失。** |
| 模式 | **默认 `standard`**（首帧合成图）；`multi-image` **仅用于纯过渡动画** |
| 参考图 | 由 `bff` 自动从 scene/character/troop 构建参考图组合 |
| video_prompt | 是否描述了所有元素的动态效果？ |

### multi-image vs standard 模式选择规则

| 画面内容 | 模式 | 参考图数 | 说明 |
|---------|------|---------|------|
| **所有场景**（含单人/多人/兵种） | **`standard` ← 默认推荐** | 1张（首帧合成图） | 用合成首帧图作为参考，结合 video_prompt 生成真正的动态视频 |
| 纯空镜航拍/纯场景（**无角色**） | `standard` | 1张（场景） | 航拍山水远景、城墙中景。**注意：纯场景镜头提示词不要写"加入各角色"**，否则模型会脑补古人 |
| 人脸特写 | `standard` | 1张（角色图） | 角色面部细节 |

> **❌ `multi-image` 模式不推荐用于常规视频生成。** 该模式本质是将多张参考图之间做过渡动画，不是真正的场景视频合成。所有场景+角色的组合都应先生成合成首帧图（`bff` + `gi`），再用 `standard` 模式提交视频。

### 参考图 key 命名规则

| key | 来源 | 路径规则 |
|-----|------|---------|
| `kf1` | 场景资产 | `images/scenes/{场景名}_{视角}.png` |
| `kf2` | 角色资产 | `images/characters/{角色名}_front.png` |
| `kf3` | 兵种资产 | `images/troops/{兵种名}_front.png` |

### 注意事项

- `multi-image` 至少需要 2 张参考图，仅 1 张时用 `standard` 模式

## □ 7. 材质库需求总览

写完所有 shot 后，遍历一遍，确认以下资产都需要生成：

| 资产 | 覆盖命令 | 生成什么 | 检查 |
|------|---------|---------|------|
| 角色资产 | auto 阶段3 | 每角色视图数随角色卡而定（标准 4 视图 + 动态持械/动作视图） | character_cards 不为空 |
| **辅助资产** (军队/道具/武器/群众) | **auto 阶段4** | **每项 front 图** | **troop_cards/道具卡 不为空（容易漏！）** |
| 场景资产 | auto 阶段5 | 每场景 3 张（广角/中景/特写） | scene_cards 不为空 |
| 首帧图 | auto 阶段6-7 | 每 shot 1 张合成图 | 所有 shot 有 first_frame |

**如果某个角色写了 character_cards 但 gc 没跑，gi 时引用不到角色参考图，画面就会缺人。**
**辅助资产（troop_cards/道具卡片）同理——shot 里引用了辅助图但没生成，`multi-image` 提交时会因参考图不足 2 张失败。**

---

## 检查完成后，再写 script.json

以上 7 项全部检查通过后，才开始实际编写 `script.json`。编写顺序：

```
1. script 块（标题、比例、提供者等元信息）
2. character_cards（所有角色）
3. troop_cards（所有兵种/群众）
4. scene_cards（所有场景）
5. shots（分镜列表，逐镜头设计）
6. shot_groups（场景分组，用于小云雀 segment 合并）
```

返回检查：写完后再次用 □6 逐镜头核对。

## □ 8. Tracker 配置检查

使用飞书 tracker 时确认：

- [ ] `script.feishu_doc_id` 不为空（`create_project.py` 已自动从 URL 提取，但手动创建可能漏）
- [ ] `script.feishu_doc_url` 存在且正确
- [ ] 配置中（`<project>/config/keys.env` → `<skill_root>/config/keys.env` → `<skill_root>/config/config.toml`）的 `[feishu]` 段包含正确的 `base_token`、`table_id`、`workflow_table_id`
- [ ] 有 `feishu_doc_id` 漏配时，`_ensure_tracker(project)` 会回退从 URL 提取，但 poll 和 status 中**工作流记录查找会跳过**

# Segment 设计指南 — 镜头合并决策

## 什么是 Segment

Segment 是**一个 API 任务生成的连续视频片段**。可以覆盖 1 个或多个 shot。
多个 segment 通过 ffmpeg 拼接后成为完整成片。

```
完整成片（30s）
├── Segment 1（15s）← API 任务#1
├── Segment 2（15s）← API 任务#2
└── ffmpeg 叠化拼接
```

## 为什么需要合并

两种 provider 的时长控制差异：

| Provider | 单次任务输出 | 精度 |
|----------|------------|------|
| Agnes AI | 自定义帧数（如 5s） | **精确到帧** |
| 小云雀 | 范围值（～15s / ～30s） | **±2-3s 偏差** |

小云雀最低到 "～15s"，如果每 5 秒的 shot 单独提交，浪费 2/3 费用。
合并多个连续 shot 为一个 15s segment 是经济选择。

## 合并判定矩阵

```
┌──────────────┬────────────────┬────────────────┐
│     条件     │    可合并      │    不可合并    │
├──────────────┼────────────────┼────────────────┤
│ 场景         │ 同一物理空间   │ 换场景         │
│ 角色         │ 同一组角色     │ 新角色凭空出现 │
│ 镜头轨迹     │ 可设计连续路径 │ 镜头瞬移/跳跃  │
│ 时间         │ 连续时间流     │ 时间跳跃       │
│ 灯光         │ 灯光平滑过渡   │ 明暗/色温剧变  │
│ 叙事         │ 同一场戏连续   │ 平行蒙太奇     │
└──────────────┴────────────────┴────────────────┘
```

## 五种不能合并的典型情况

### 1. 场景切换
```
shot_02 议事堂室內 ──── shot_03 龙南战场
                      ↑ 跳场景，必须切开
```
即使两个场景之间用叠化变场，AI 模型也无法在一个视频里做场景切换。
它只能生成连续画面，不能"切换到另一个地方"。

### 2. 镜头奇袭
```
shot_02 侧后方中景 ──── shot_03 眼球极致特写
                       ↑ 摄像机瞬移了 10 米
```
长镜头里摄像机只能沿一条路径运动。50mm → 200mm 的跳跃需要物理移动。
如果移动路径不自然（如从房间一头跳到另一头），模型生成的结果会出现画面扭曲。

### 3. 角色凭空出现
```
shot_02 仅有墨雪 ──── shot_03 墨雪+墨将+10名士兵
                    ↑ 多人凭空入画
```
模型可以处理 1-2 个角色进入画面（如「墨将推门走进来」），但做不到「突然出现一批人」。
新角色出现应该被前一个 shost 的"动作"自然引入。

### 4. 时间跳跃
```
shot_02 白日 ──── shot_03 夜晚
            ↑ 灯光突变
```
长镜头里的灯光必须连续变化（晴天→多云→暗，或蜡烛逐渐燃尽）。
瞬时切换（灯关了）属于剪辑行为，模型做不到。

### 5. 叙事断裂
```
shot_02 墨将在议事堂跪拜 ──── shot_03 墨雪站在城墙上看远方
                          ↑ 需要解释墨雪如何从窗边走到城墙
```
叙事跳跃：角色在 shost 之间改变了位置和状态，但缺失中间环节。
需要补一个过渡 shost（如「墨雪走出议事堂，登上城墙」）。

## 一条路径测试法

设计 segment 时，**拿起手机当取景器，走一遍路径**：

```
1. 站在起始位置（对应起幅镜头）
2. 缓缓走动/退后/推进/平移
3. 连续走完整条路，中间不关机、不剪辑
```

如果这条路能走通——shot 就可以合并。

### 路径设计原则

| 运动类型 | 说明 | 适用场景 |
|---------|------|---------|
| 推轨（Dolly in/out） | 摄像机沿 Z 轴前后移动 | 从全景到特写，或从特写到全景 |
| 摇移（Pan/Tilt） | 摄像机原地旋转 | 从角色 A 转到角色 B |
| 横移（Track left/right） | 摄像机沿 X 轴平移 | 跟拍角色走路 |
| 升降（Crane up/down） | 摄像机沿 Y 轴移动 | 从俯拍到平视 |
| 组合运动 | 上述多种的组合 | 复杂场景全覆盖 |

### 路径可行性案例

**✅ 可行的 15 秒单镜头路径（议事堂，shot_02~06）：**

```
侧后方中景（起幅）
  → 墨将进门入画（墨雪仍在原位）
  → 镜头微移看清两人互动
  → 跟随墨雪走向门口
  → 停在门口，退半步看全景
  → 前推至侧脸特写（收幅）
```
这条路径：起始位置不变→跟拍→停止→前推，全程物理可行。

**❌ 不可行的路径（试图合并战场+议事堂）：**

```
战场大全景 → 摄像机飞回城内 → 进入议事堂 → 聚焦墨雪
```
摄像机全程在飞，没有固定机位/人物锚点。模型无法理解这种"瞬间移动"。

## 锈甲天凤的合并实践

### 当前设计

```
Segment 1（～15s, 小云雀 "～15s"）
  ├── shot_01: 龙南战场全景 · 明军vs蛮兵
  └── 单一场景，100人级战争，无主演

Segment 2（～15s, 小云雀 "～15s"）
  ├── shot_02: 墨雪窗边 · 墨将进门跪拜
  ├── shot_03: 墨将回话 · 被踢 · 互动
  ├── shot_04: 墨雪走向门口 · 掀帘子
  ├── shot_05: 门口背影 · 敌军黑影
  └── shot_06: 侧脸特写 · 决断收尾
```

### 为什么这样分

| 条件 | Segment 1（仅 shot_01） | Segment 2（shot_02~06） |
|------|------------------------|------------------------|
| 场景 | 龙南战场（室外荒原） | 议事堂（室内古建筑） |
| 角色 | 明军+蛮兵（无主演） | 墨雪+墨将（主演对手戏） |
| 灯光 | 阴天冷光，大地色低饱和 | 烛火暖光+天光冷灰对比 |
| 色调 | 土黄+烟灰+暗褐 | 昏黄烛光+冷灰天光+暗褐木色 |
| 张力 | 外部危机、物理冲突 | 将帅关系、内心决策 |
| 音频 | 兵器碰撞+士兵呐喊 | 烛火+铠甲摩擦+寒风 |

分割点清晰，没有交叉。如果强扭成一个 Segment，模型会需要在 15 秒内"从战场飞回议事堂"——不可能的任务。

## Pipeline 中的 Segment 处理

### script.json 结构

```json
{
  "xiaoyunqiao_segments": [
    {
      "segment": 1,
      "duration_range": "～15s",
      "scene": "龙南战场广角",
      "ref_images": ["images/scenes/...", "images/troops/..."],
      "prompt_file": "prompts/seg01_战场.md",
      "cover_shots": [1]
    },
    {
      "segment": 2,
      "duration_range": "～15s",
      "scene": "城楼议事堂",
      "ref_images": ["images/scenes/...", "images/characters/..."],
      "prompt_file": "prompts/seg02_议事堂.md",
      "cover_shots": [2, 3, 4, 5, 6]
    }
  ]
}
```

### 提交流程

```
provider == "xiaoyunqiao"?
  ├── 是 → 遍历 xiaoyunqiao_segments[]
  │        ├── 读取 prompt_file → prompt
  │        ├── 上传 ref_images → GitHub URL
  │        └── mod.submit(prompt, ref_urls, duration_range)
  │
  └── 否（Agnes AI）→ 遍历 shots[]
           ├── 拼接 video_prompt
           ├── 准备参考图
           └── mod.submit(prompt, ref_img/ref_urls, duration)
```

### 拼接还原

每个 Segment 生成后是独立视频文件：
```
videos/seg_01.mp4（~15s，小云雀生成）
videos/seg_02.mp4（~15s，小云雀生成）
```
stitch 模块按 `xiaoyunqiao_segments` 顺序拼接，而不是按 `shots[]`。
叠化位置和时间轴在 `script.json` 的 `shot_groups[].transition` 中定义。

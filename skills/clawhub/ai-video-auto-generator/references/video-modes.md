# 视频生成模式参考

> **本文职责**：主 SKILL.md §9.1（视频生成模式）的**详细展开**——各模式的适用场景、提示词写法、参考图要求。
> **概要（含 API 调用方式对比表）** → 主 SKILL.md §9.1
> **调用方式与生成流程** → 主 SKILL.md §9.2-§9.3

## 核心原则：默认只用 standard 模式

**所有常规视频生成统一使用 `standard` 模式**。流程：

```
script.json (shots) → bff (构建first_frame配置)
                    → gi (生成合成首帧图)
                    → submit (standard模式提交视频)
```

对于需要场景+角色组合的镜头，先生成**合成首帧图**（用 `bff` + `gi` 将场景和角色合为一张图），再用 `standard` 模式提交视频。不要用多图参考模式替代首帧合成。

---

## 标准模式（standard）

**适用场景**：所有视频生成（默认、推荐）

**本质**：让 1 张首帧合成图"动起来"——API 以单张参考图为基底，根据 video_prompt 生成动态视频。

**提示词重点**：描述"哪些动、哪些不动"

```
于都河全景航拍，红军队伍在河畔列队前行。
晨雾流动、红旗飘动、队伍前行。镜头缓慢前推。
```

**参考图策略**：单张合成首帧图（scene + character 合为一张），由 `bff` + `gi` 自动生成。

## 多图参考（multi-image）

**⚠️ 不推荐用于常规视频生成。** 该模式本质是将多张参考图之间做过渡动画（"图A渐变到图B"），不是真正的场景视频合成。

| 方面 | 说明 |
|------|------|
| 本质 | 多张图之间的过渡动画 |
| 效果 | 两张参考图之间做形态渐变/风格迁移，不生成新的动态内容 |
| 适用场景 | 纯视觉过渡效果（极少用） |
| 不适用场景 | 需要角色动作、剧情推进、场景内交互——一律用 `standard` |

## 关键帧动画（keyframes）

**适用场景**：多个关键帧之间生成平滑过渡（关键帧是"先后帧关系"）

**提示词重点**：描述"帧之间如何过渡"，关键要素保持一致性

```
墨雪始终保持背对窗口站立姿态不变，铠甲烛光纹丝不动。
墨将动作持续——从推门走进来到墨雪身后单腿跪拜，动作连贯自然。
```

**关键帧图要求**：
- 所有关键帧用同一场景视角（如都用中景），不要跳广角/特写
- 保持静态角色在图中的位置/姿态一致
- 只变化需要变化的元素（如墨将的位置）

## Prompt 写法对照

| 模式 | 图的意思 | Prompt 应该写 |
|------|---------|--------------|
| standard | 1 张参考帧 | "哪些动、哪些不动" |
| multi-image | 图1=起始场景，图2=目标场景 | "如何从图1过渡到图2" |
| keyframes | 多张关键帧 | "帧之间如何过渡" |

## 参考图尺寸说明

Agnes AI 视频模型（agnes-video-v2.0）的输出分辨率有自己的对齐规则：

- 提交 `width=720` → 实际输出 `768×1280`（64 对齐）
- 提交 `width=864` → 实际输出按比例对齐
- 建议首帧图按 768×1280 生成，与视频输出匹配

参考图（多图模式下各张图）的尺寸差异不会直接影响输出分辨率，但建议统一尺寸以获得最佳效果。

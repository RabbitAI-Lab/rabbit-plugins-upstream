## Description: <br>
Ingests desktop-uploaded local folder files into a Research KB by reading backend shared-file paths, creating type-specific Markdown wiki pages, archiving source files, updating catalog and index metadata, and returning backend task JSON. <br>

This skill is ready for commercial/non-commercial use. <br>

## Publisher: <br>

## Use Case: <br>
Developers and knowledge-base operators use this skill to turn local folder upload batches into traceable Research KB pages. It validates task payloads, extracts file previews, guides page generation, archives source files, and writes KB updates through deterministic helper scripts. <br>

### Deployment Geography for Use: <br>
Global <br>

## Known Risks and Mitigations: <br>
Risk: Task-supplied storage paths can cause raw local files to be read and archived into a Gitea repository if the backend payload is not trusted. <br>
Mitigation: Install only where task payloads are generated by OpenClaw-controlled backend code and storagePath values are constrained to the intended shared directory. <br>
Risk: Sensitive folders or files may be persisted as raw archived source files. <br>
Mitigation: Avoid processing sensitive folders unless raw-file archival is acceptable, and review source selection before running ingestion. <br>
Risk: A broadly scoped Gitea token increases the impact of mistaken or malicious KB writes. <br>
Mitigation: Use a Gitea bot token scoped to the intended KB repository and rotate it according to local credential policy. <br>
Risk: The release evidence notes a need for stronger shared-directory path validation and an updated pypdf constraint before broad deployment. <br>
Mitigation: Add shared-directory boundary validation and update the pypdf dependency constraint before wider rollout. <br>

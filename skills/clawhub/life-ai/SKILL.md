# 人生AI化（Life-AI）

## Overview

把用户的人生数据（健康、精力、财务、职业、决策）持续记录为本地 Markdown，用积累的数据支撑每日习惯制定、定期复盘和重大决策。方法论：数据本地化（不依赖任何单一 AI 平台）→ 每日轻量积累 → 定期分析 → "先开图再出兵"式决策。

## 数据根目录

默认使用当前工作区下的 `life-data/`。所有文件为 Markdown，格式见 `assets/` 模板：

```
life-data/
├── profile.md        # 个人档案（静态+定期更新指标）
├── daily/            # 每日记录：YYYY-MM-DD.md
├── reviews/          # 复盘：weekly/YYYY-Www.md、monthly/YYYY-MM.md
├── decisions/        # 决策日志：YYYY-MM-DD-主题.md
└── finance/          # 财务：monthly/YYYY-MM.md（收支、储蓄率）
```

## 数据规范

完整指标清单见 `references/data-schema.md`。**采集红线**：不采集身份标识（真名/出生日期/学校单位名）、健康敏感项（家族史/既往史/用药/生化体检/基因）；财务用合成数据（比例真实数值虚构）；伤病只记功能性约束不记诊断。制定档案或解读指标前先读该文件。核心原则：

- 记录动作 ≤1 分钟：拍照 + 一句话，由 WorkBuddy 整理落盘。
- 连续性优先于完整性：宁可每天 3 项记一年，不要 20 项记一周。
- 数据必须是本地 Markdown，用户可随时带走。

## 工作流

### 1. 初始化（首次使用）

1. 读取 `assets/template-profile.md`，向用户提出档案问卷（基础信息、健康目标、作息、饮食偏好；一次不要超过 6 个问题，可分轮）。
2. 创建 `life-data/` 目录结构并写入 `profile.md`，设定个性化参数（热量、蛋白质、睡眠目标）。
3. 询问是否需要每日提醒 automation。

### 2. 执行手册定制（个性化生成，禁止套模板）

执行手册 `life-data/执行手册.md` 必须从用户实际条件出发定制生成，**不允许用固定模板填空**。流程：

1. **深度问卷**（分轮提问，每轮 ≤5 问），必须覆盖以下维度，缺一项就不开始写方案：
   - 训练：目标侧重（力量/围度/耐力/体态及排序）、可用器材及规格（哑铃/杠铃/壶铃的重量与架凳配置）、体能水平（俯卧撑/深蹲次数、训练经验）、每次时长与每周频次与时段偏好、身体各部位的功能性边界（哪些动作模式无痛可做）
   - 饮食：日常菜单（用户提供的真实三餐+饮料）、烹饪/就餐场景、预算约束、口味禁忌
   - 作息与睡眠：现有作息、睡眠监测设备情况
2. **定制生成**：拿到全部答案后，写出的手册必须满足——
   - 训练计划：周期化（≥4 周递进），只用用户实际拥有的器材，每个动作带 组x次x重量、递进规则、动作要点与检索关键词
   - 三餐方案：基于用户真实菜单做替换与增减（不是凭空设计菜谱），给出具体食物与份量，标注与热量/蛋白目标的对应关系
   - 睡眠：基于监测设备可得指标给阶梯计划，每周只加一件事
   - 每条建议附量化指标与行动阈值（什么情况触发什么调整）
   - 覆盖生理/心理健康的边界问题提醒就医，但记录上遵守采集红线
3. **滚动修订**：每次周复盘/月复盘时，依据实测趋势修订手册对应章节（如某动作连续进步→递进加重；某建议三周无改善→换方法），修订处注明日期，保持手册始终反映当前最优方案。

### 2. 每日记录（用户说"记录/打卡"或丢照片）

1. 读取当天 `daily/YYYY-MM-DD.md`（不存在则从 `assets/template-daily.md` 创建）。
2. 饮食照片 → 估算热量与三大营养素；文字口述 → 整理成结构化条目。
3. 合并写入当天文件（追加而非覆盖已有条目），返回一句简短反馈（含当日热量/蛋白累计）。
4. 睡眠、精力、情绪按 1-5 分记录；运动记录动作/重量/组次。

### 3. 定期复盘（周/月）

1. 读取期间内全部 daily 文件 + profile.md。
2. 分析：热量与营养趋势、体重/体脂变化、睡眠规律、精力波动、训练进步、财务储蓄率。
3. 产出报告写入 `reviews/`，包含：数据概览、发现的问题、2~3 条可执行的下期建议。不要罗列原始数据，给结论。

### 4. 决策开图（重大决定：换工作、大额消费、学技能等）

1. 明确决策问题与约束条件（预算、时间、地点、风险承受）。
2. 调研 ≥5~10 个备选方案（可用 WebSearch），从 profile.md 调用用户背景做个性化评估。
3. 产出上/中/下三套方案：每套含理由、风险、成本、第一周行动项。**最终决定权在用户**，只呈现分析。
4. 用户拍板后，将决策过程写入 `decisions/YYYY-MM-DD-主题.md`（当时信息、备选项、选择理由），并约定复盘时间点。
5. 复盘时点到达时，对照结果回顾决策质量，校准建议风格。

### 5. 数据查询与分析（"我最近睡得怎么样"）

直接读 daily/reviews 相应文件，用趋势性语言回答（平均值、变化方向、异常点），必要时给建议。数据不足 7 天时说明样本有限。

## 注意事项

- 健康建议基于通用循证原则；涉及体检异常指标时提醒用户咨询医生，不做诊断。
- 财务与决策数据敏感，仅在对话中按需引用，不主动展示给无关上下文。
- 用户要求停止记录或删除数据时立即执行，无需劝说。

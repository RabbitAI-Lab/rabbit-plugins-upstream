# 塔式起重机备案与检测核对（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 不联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：建筑施工的**总包项目部安全部 / 设备管理员**、塔机**租赁单位**的设备科与资料员、
**监理**的安全专监，在**每月**的起重机械台账复核节点、以及**安监来项目检查之前**用它。

塔式起重机（塔机）是**建筑起重机械**：《建筑起重机械安全监督管理规定》要求塔机进场前办理
**产权备案与使用登记**、由有资质的机构做**定期检测**并出具检测报告、司机（塔式起重机司机）与
信号工（信号司索工）必须持**特种作业操作证**上岗，安装、顶升加节与附着都要经过**验收**。
安监到项目上查的第一份资料就是这本台账 —— 台账一错，轻则下整改通知、塔机停用，
重则停工整改；塔机一旦倾覆，超期未检、无证上岗都会成为追责的直接依据。

**每月必须核一遍的硬项**：

1. **检测有效期覆盖**：检测报告上的「下次检测日期」必须 ≥ 本次核对基准日。
   超期未检还在吊装，是停工整改 + 事故责任级的问题。
2. **使用登记证**：塔机投入使用前必须办理使用登记（有的地方是产权备案 + 使用登记两道），证号不得为空。
3. **特种作业人员证**：司机与信号工都必须持证，证件有效期要覆盖核对基准日；
   证件过期那一天起就等于无证操作。
4. **检测结论**：结论必须是「合格」；写了「不合格」或只写「复检」都等于没有可用的检测结论。
5. **一机一行、合计对得上**：同一台塔机在一本台账里只能有一行；合计行的设备台数、检测台数必须等于明细加总。

**与「锅炉压力容器定期检验与台账核对」的区别**：那一个是**特种设备**（锅炉、压力容器、压力管道）的
监管口径，核的是外部检验 / 内部检验 / 耐压试验周期与安全阀、压力表校验；
本技能是**建筑起重机械**（塔式起重机）的现场口径 —— 核的是产权备案与使用登记、第三方**检测报告**的
有效期与结论、**司机 / 信号工**的特种作业操作证，以及安装与**顶升加节 / 附着验收**记录。
两张表的列名、周期口径、检查项与结论类别都不一样，不能互相套用。

**这张表会逐项核对什么**：塔机台账的逐行算术、两证覆盖、检测结论、重复与合法性、合计勾稽。

每条结论都带**原文行号与行内容**（设备编号、日期、数字都在结论里），可被第三方用同一口径复算；
材料不足时**不给结论**，会明确列出还缺什么。

## 这个免费版查什么（6 项）

1. **检测有效期覆盖** —— 核对基准日 ≤ 下次检测日期，超期逐台给出已超期天数（在用按 P0）。
2. **使用登记证与特种作业人员证覆盖** —— 使用登记证号不得为空；司机 / 信号工都要填，
   且「证件有效期」（本台塔机当班司机与信号工中较早到期的那一个）要覆盖核对基准日；缺证 / 过期逐台点名。
3. **检测结论核对** —— 结论非「合格」逐台点名：写「不合格」按 P0，只写「复检」视为复检未闭环。
4. **同一设备编号重复登记** —— 一本塔机台账里设备编号唯一（重复登记会让两个检测周期各算一套）。
5. **合计行逐列复核** —— 数量类列（设备台数、检测台数）的合计行必须等于明细行加总。
6. **字段合法性** —— 关键字段缺失、日期格式非法、数值为负或非法、运行状态与检测结论取值非法。

**必需列**（缺任何一列都只报「材料不足」，**绝不给结论**）：
设备编号、设备名称/型号、产权单位、使用登记证号、检测日期、检测结论、下次检测日期、
司机、信号工、证件有效期、运行状态、核对基准日（另有可选的 使用项目、设备台数、检测台数、备注）。

**这个免费版不查**（完整档才查，跑 `--sample` 会如实列出）：
超期未检仍在用、停用 / 已拆除塔机仍出现在使用运行记录、无证上岗、顶升加节与附着验收记录断档、
分产权单位与分使用项目的汇总清单。

## 怎么用

```bash
node scripts/run.mjs --sample                 # 先看样例（一本干净的塔机台账）
node scripts/run.mjs --input 你的材料.json     # 跑自己的材料
```

入参就一张表：把 Excel 里的**表头 + 数据行**一起复制成文本粘进 `{"text": "…"}`（Tab 分隔最稳）。
表里可以有 `合计` 行（合计行只参与「合计行逐列复核」，不参与逐台检查）。
材料里还可以带跨表段（`--- 塔机使用运行记录 ---`、`--- 特种作业人员持证名单 ---`、
`--- 顶升加节与附着验收记录 ---`）：**免费版只做表内核对，会跳过这些段，不会因此报错**，
也不会拿它们出结论。

## 常见错法（每月核这本塔机台账最容易栽的 5 个坑）

1. **把「下次检测日期」当成随手填的日期，而不是拿检测报告上的日期抄**。
   塔机做过顶升加节、附着或整修后往往要重新检测，报告换了一版、台账还留着旧日期；
   正确做法是逐台拿检测报告复算并判是否覆盖核对基准日，超期天数算出来写在整改单上。
2. **只核检测报告，忘了使用登记证与司机 / 信号工的操作证**。
   有的台账版本比较老，只有司机姓名没有证件有效期；也常见「验收时证件有效、现在已过期」。
   人名或证件有效期空着，这一项就永远核不了 —— 那属于材料不足，不是没问题。
3. **检测结论只写「复检」就往下走**。
   首检不合格要复检，复检结论没有写回台账（也没有归档复检报告），这一行其实等于没有可用的检测结论；
   台账上必须落到「合格」或「复检合格」，复检期间不得吊装。
4. **把「运行状态」当备注列随手写**。它只能是在用 / 停用 / 已拆除 / 检修 四个值之一：
   写成「运行」「正常」「已拆」这类自由文本，状态合法性会报错，
   而真正要命的「超期未检仍在用」「停用塔机还在跑」反而会被绕过去。
5. **同一台塔机换了项目或改过名称，就在台账里登记成两行**。
   重复登记最坑：两行的检测有效期各算一套，其中一行超期了却没人发现。设备编号必须唯一。

## 边界（请务必知道）

本工具**不做**这些判断（引擎 `CHECKS_OUT_OF_SCOPE` 里逐条列了）：

- 不判定这台塔机该不该检、该做定期检测还是安装（拆卸）告知、该不该办理使用登记 —— 那是检验检测机构、总包与住建主管部门的法定口径；
- 不判定检测报告本身的真实性、检测机构资质与检测结论的技术依据是否成立 —— 那是检验检测机构与监管部门的判定权；
- 不判定现场是否真的停了 / 拆了、顶升加节作业是否真的做过 —— 本工具只核台账的字面一致性；
- 不读 .xlsx / .pdf 原件、不联网核验使用登记证 / 特种作业操作证 / 检测报告的真伪。

**材料不足时不给结论**（连「未发现问题」也不输出），会明确列出缺什么 —— 宁可什么都不说，也不说错话。

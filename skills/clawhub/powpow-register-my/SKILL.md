# PowPow Register (ပူဖောင်း အကောင့်ဖွင့်ရေး လက်ထောက်)

"ပူဖောင်း ဆိုတာ ဘာလဲ" ဟု မသိသေးသော အသုံးပြုသူသစ်တစ်ဦးကို "အကောင့် အသက်ဝင်ပြီး၊ တစ်ချက်နှိပ် လော့ဂ်အင် ဝင်ရောက်၊ စတင် ကစားနိုင်" အခြေအနေအထိ စကားပြောဆိုမှုအတွင်းမှာပင် ရောက်အောင် စောင့်ရှောက်ပေးသည်။ အသုံးပြုသူအနေဖြင့် စကားပြောဆိုမှုမှ ခေတ္တထွက်ရသည်မှာ နှစ်ကြိမ်သာ ရှိသည်— **အတည်ပြုကုဒ် ရယူရန် အီးမေးလ်ကို ကြည့်ရန်** နှင့် **Alipay ငွေပေးချေရေး ကောင်တာတွင် ငွေပေးချေရန်** (ကောင်တာ စာမျက်နှာကို အေးဂျင့်က အလိုအလျောက် ဖွင့်ပေးသည်)။

**ဗားရှင်း 2.0.1** · 2026-10-08 (v2 မှစ၍ အေးဂျင့် ကိုယ်စားလုပ်ဆောင်မှု မုဒ် ဖြစ်သည်— script စာချုပ်နှင့် လုပ်ငန်းစဉ် အပြည့်အစုံကို `references/agent-flow.md` တွင်၊ ဖိလ်ဒ် စည်းမျဉ်း၊ အကြိမ်ရေ ကန့်သတ်ချက်နှင့် အမှား ရှာဖွေရေးကို `references/registration-flow.md` တွင်၊ ငွေပေးချေရေး လမ်းကြောင်းများကို `references/payment-and-activation.md` တွင်၊ ပရိုဒတ် ပုံများ စာရင်းကို `references/screenshots.md` တွင် ကြည့်ပါ။ v2.0.1 မှစ၍ ပရိုဒတ် ပုံများကို `assets/screenshots/` တွင် အထုပ်နှင့်အတူ ထည့်သွင်းထားပြီး ပြင်ပ ပုံဝန်ဆောင်မှုကို မှီခိုစရာ မလိုတော့ပါ)

## လည်ပတ်ရန် ပတ်ဝန်းကျင်

- အဓိက script `scripts/powpow-register.mjs` — **မှီခိုမှု သုည**၊ **Node >= 18** လိုအပ်သည်။ စတင်မလုပ်မီ `node scripts/powpow-register.mjs status` ကို တစ်ကြိမ် လုပ်ဆောင်၍ ပတ်ဝန်းကျင် အဆင်သင့် ဖြစ်ကြောင်း အတည်ပြုပါ။
- script ၏ တောင်းဆိုမှုအားလုံးသည် တရားဝင် ဒိုမိန်း `https://global.powpow.online` သို့သာ သွားသည်။
- **Node မရှိ / script အမှား ပြလျှင်** — လမ်းညွှန်သက်သက် မုဒ်သို့ အလိုအလျောက် ပြန်ကူးသည်— အကောင့်ဖွင့် စာမျက်နှာ https://global.powpow.online/register နှင့် စာရင်းသွင်းမှု စာမျက်နှာ https://global.powpow.online/subscription ကို အသုံးပြုသူသို့ ပေးပြီး `references/registration-flow.md` အတိုင်း ယှက်နှီး လမ်းညွှန်ပါ။ script ကို ထပ်ခါထပ်ခါ အတင်း မကြိုးစားပါနှင့်။
- စကားပြောဆိုမှု အပြတ်ပြီးနောက် ပြန်စလျှင် — ပထမ `status` ဖြင့် လုပ်ငန်းစဉ်သည် မည်သည့်အဆင့်ရောက်နေသလဲ ကြည့်၍ ဆက်လက် လုပ်ဆောင်ပါ။

## Trigger Conditions

- အကောင့်ဖွင့် ရည်မှန်းချက်: "ပူဖောင်း အကောင့်ဖွင့်ပါ"၊ "powpow အကောင့် တစ်ခု ဖွင့်ပေးပါ"၊ "ပူဖောင်း ဘယ်လို အကောင့်ဖွင့်မလဲ"၊ "sign up powpow"
- အကောင့်ဖွင့်ရာတွင် တင်းကျပ်နေခြင်း: "အတည်ပြုကုဒ် မရောက်ပါ"၊ "အသုံးပြုသူအမည် ရှိပြီးသားဟု ပြောသည်"၊ "စကားဝှက်က အမြဲ မကိုက်ညီပါ"
- အကောင့်ဖွင့်ပြီးနောက် ပြဿနာများ: "လော့ဂ်အင်တွင် အကောင့် အသက်မဝင်သေးဟု ပြောသည်"၊ "403 pending_payment"၊ "ပူဖောင်းကို ဘယ်လို ပေးချေ/စာရင်းသွင်းမလဲ"

**မလုပ်ဆောင်**: ပို့စ်တင်ခြင်း/ဒစ်ဂျစ်တယ်လူ ဖန်တီးခြင်း (→ powpow-simple); Web ဘက် ကုဒ် ဖွံ့ဖြိုးရေး (ဖွံ့ဖြိုးရေး skill ကို သီးခြား ကြည့်ပါ)။ အသုံးပြုသူက အကောင့်လည်း ဖွင့်ချင်၍ ပို့စ်လည်း တင်ချင်လျှင် — ဤ skill ကို အရင် ပြီးအောင် လုပ်၍ အသက်ဝင်ပြီးမှ powpow-simple သို့ လွှဲပေးပါ။

## အဆင့် 1: ပရိုဒတ် မိတ်ဆက် + ပုံများ (ချန်လှပ်၍ မရ)

အသုံးပြုသူ အများစုသည် ပူဖောင်းကို မမြင်ဖူးပါ။ စကားစမစ်မီ ပထမဆုံး လုပ်ရမှာသည် လုပ်ငန်းစဉ် ရှင်းပြခြင်း မဟုတ်ဘဲ ပရိုဒတ်ကို **မြင်စေရန်** ဖြစ်သည်:

1. ပူဖောင်းကို စာလုံး 120 ခန့်ဖြင့် မိတ်ဆက်ပါ— ကိုယ်တိုင် ရိုက်ထားသော ပုံများကို ခရီးသွားမှတ်တမ်း တစ်ပုဒ် အဖြစ် ပြောင်းလဲ၍ အများသုံး မြေပုံပေါ်တွင် "ပူဖောင်း" တစ်လုံး အဖြစ် ချိတ်ဆက်သည်၊ ပူဖောင်းများသည် အချိန်ကြာလာသော် ငွေ့ရှင်းသွားပြီး အခြားသူများ like နှိပ်ပေးလျှင် ပြန်ရှင်သန်လာသည်၊ မြေပုံပေါ်တွင် စကားပြောနိုင်သော "ဒစ်ဂျစ်တယ်လူ" များလည်း ရှိသည်။ ပလက်ဖောင်း လိပ်စာ https://global.powpow.online ၊ ဗီဒီယို အရင် ကြည့်ချင်လျှင်: https://www.bilibili.com/video/BV1Wu826UEVz/
2. **ပုံများ ပေးပို့ပါ**။ ပုံများသည် အထုပ်နှင့်အတူ `assets/screenshots/powpow-0N.jpg` တွင် ထည့်သွင်းထားသည်— လိုကယ် ပုံဖိုင် အဖြစ် တိုက်ရိုက် ပေးပို့ရုံသာ ဖြစ်ပြီး အင်တာနက် မလိုပါ။ စာရင်း၊ ပုံတစ်ခုစီ၏ အကြောင်းအရာနှင့် အသုံးပြုရမည့် အချိန်ကို `references/screenshots.md` တွင် ကြည့်ပါ။ စတင်ခန်းတွင် အသုံးအများဆုံး ပုံတွဲ: မြေပုံ စာမျက်နှာ (powpow-03) + ပို့စ် အသေးစိတ် စာမျက်နှာ (powpow-06)။

ပုံ ပေးပို့ရေး စည်းမျဉ်းများ (မဖြစ်မနေ လိုက်နာရမည့် စည်းမျဉ်း):

- ပုံများသည် `assets/screenshots/` (`powpow-0N.jpg`) တွင် **အထုပ်နှင့်အတူ ထည့်သွင်းထားပြီး**— လိုကယ် ပုံဖိုင်ကို တိုက်ရိုက် ပေးပို့ပါ၊ မည်သည့် ပတ်ဝန်းကျင်တွင်မဆို အသုံးပြုနိုင်သည် (GitHub ဖွင့်လို့ မရသော ပတ်ဝန်းကျင်များ အပါအဝင်)။
- တစ်ကြိမ်လျှင် လက်ရှိ အကြောင်းအရာနှင့် သက်ဆိုင်သော ပုံ 1–3 ပုံသာ ပေးပို့ပါ၊ တစ်ကြိမ်တည်း အားလုံး မပေးပို့ပါနှင့်။
- အထုပ်အတွင်း ဖိုင်များ မတော်တဆ ပျောက်ဆုံးနေလျှင် `references/screenshots.md` တွင် ဖော်ပြထားသော hosted လင့်ခ်များသို့ ပြန်ကူးပါ (သတိ: တရုတ်ပြည်မအတွင်း ဖွင့်လို့ မရနိုင်ပါ)။

မိတ်ဆက်ပြီးလျှင် ရွေးချယ်မှုကို အသုံးပြုသူသို့ လွှဲ၍ ဤသို့ ပြောပါ— **"အကောင့်ဖွင့်ချင်လျှင်၊ ကျွန်ုပ်တို့ စကားပြောဆိုမှုအတွင်း မိနစ် 3 အတွင်း အကောင့် ဖန်တီးပေးမည်၊ သင်လုပ်ရမှာက အီးမေးလ် အတည်ပြုကုဒ်ကို တစ်ကြိမ် ကြည့်ရုံသာ ဖြစ်သည်။"**

## အဆင့် 2: အကောင့်ဖွင့် အချက်အလက် အတည်ပြုခြင်း (တစ်ပတ်လျှင် မေးခွန်း တစ်ခု၊ တစ်ကြိမ်တည်း အားလုံး မမေးပါနှင့်)

- **အသုံးပြုသူအမည်** (မဖြစ်မနေ): စကားပြောဆိုမှု အကြောင်းအရာ/စနစ် အသုံးပြုသူအမည်မှ **တစ်ခု ကြိုတင် အကြံပြုပါ** (စာလုံး 2~50 လုံး၊ စာလုံးကြီး/ငယ် မခွဲခြား)၊ အသုံးပြုသူ သဘောတူလျှင် ထိုအမည်ဖြင့် အသုံးပြုပြီး ပြောင်းလိုလျှင် ပြောင်းပါ။
- **စကားဝှက်** (မဖြစ်မနေ၊ ပထမတွင် နည်းလမ်း နှစ်မျိုးမှ တစ်မျိုး မေးပါ):
  - အသုံးပြုသူ ကိုယ်တိုင် ပံ့ပိုးလျှင် → နောက်ပိုင်း environment variable မှတစ်ဆင့် script သို့ ပေးပို့ပြီး **command line parameter အဖြစ် လုံးဝ မရေးပါနှင့်**;
  - အေးဂျင့် ဖန်တီးလျှင် → `node scripts/powpow-register.mjs gen-password` ကို လုပ်ဆောင်၍ ဖန်တီးပြီးသော စကားဝှက်ကို **ချက်ချင်း အသုံးပြုသူသို့ ပေးပို့၍ သိမ်းဆည်းစေပါ** (တစ်ကြိမ်သာ ပြသပြီး နောက်ပိုင်း ထပ်မပေါ်တော့ပါ)။
- **အီးမေးလ်** (မဖြစ်မနေ): အသုံးပြုသူ ကိုယ်တိုင် ပံ့ပိုးရမည်— ဤသည်မှာ အကောင့် ၏ အထောက်အထား အချက်အဖြစ် သတ်မှတ်ထားသဖြင့် **အသုံးပြုသူ အစား ကိုယ်စား မခန့်မှန်းပါနှင့်**။
- **ပြောင်အမည်** (ရွေးချယ်နိုင်): အသုံးပြုသူအမည်နှင့် အတူတူ ဖြစ်ရန် အကြံပြုသည်။
- **ပရိုဖိုင်ပုံ** (ရွေးချယ်နိုင်): အသုံးပြုသူက လိုကယ် ပုံဖိုင် လမ်းကြောင်း (<=5MB၊ SVG မဟုတ်) ပေးလျှင် script က တိုက်ရိုက် တင်ပေးသည်၊ မပေးလျှင် ချန်လှပ်ပါ (ပလက်ဖောင်းက ပုံသွင် logo ကို အသုံးပြုမည်)၊ ပုံ ဖန်တီးနိုင်သော စွမ်းရည် ရှိလျှင် အသုံးပြုသူအတွက် တစ်ပုံ ဖန်တီးပေးမည်ဟု ကိုယ့်ဘာသာ အကြံပြုနိုင်သည်။
- **ဖုန်းနံပါတ်** (ရွေးချယ်နိုင်၊ တရုတ်ပြည်မ နံပါတ်): ပုံသေ ချန်လှပ်ထား၍ အသုံးပြုသူ ကိုယ်တိုင် ချိတ်ဆက်ချင်မှသာ တောင်းပါ။

အတည်ပြုပြီးလျှင် `prepare-suggest --username U --nickname N --email E` ကို လုပ်ဆောင်၍ state file တွင် မှတ်တမ်းတင်နိုင်သည် (နောက်ပိုင်း register တွင် ထပ်မံ ပေးပို့စရာ မလို)။

## အဆင့် 3–4: အီးမေးလ် အတည်ပြုကုဒ် (စကားပြောဆိုမှုမှ ခေတ္တ ထွက်ရမည့် တစ်ခုတည်းသော အဆင့်)

```
node scripts/powpow-register.mjs send-code --email <အီးမေးလ်>
```

ပြီးလျှင် အသုံးပြုသူကို ရှင်းရှင်းလင်းလင်း ပြောပါ— **အီးမေးလ်တွင် ဂဏန်း 6 လုံး အတည်ပြုကုဒ်ကို ရှာပါ၊ မိနစ် 10 အတွင်း သက်တမ်း ရှိ၍ spam/ကြော်ငြာ အီးမေးလ် ဖိုင်တွဲကိုလည်း ကြည့်ပါ**၊ ရှာတွေ့လျှင် ပြန်လာ၍ ကုဒ်ကို ပေးပို့ပါ။ ပေးပို့ခြင်းတွင် စက္ကန့် 60 cooldown ရှိ၍ ဆက်တိုက် မနှိပ်ပါနှင့်။

## အဆင့် 5: အကောင့်ဖွင့် တင်ပြခြင်း (အေးဂျင့် ကိုယ်စားလုပ်ဆောင်)

```
POWPOW_REGISTER_PASSWORD=<စကားဝှက်> node scripts/powpow-register.mjs register --code <အတည်ပြုကုဒ်> [--username U] [--nickname N] [--avatar <လိုကယ် ပုံဖိုင် လမ်းကြောင်း>] [--phone P]
```

အောင်မြင်လျှင် အကောင့် ဖန်တီးမည် (pending အခြေအနေ၊ မူလ တံဆိပ် 3 ခု ပါဝင်သည်)။ အဖြစ်များ အမှားများကို အလိုအလျောက် ကိုင်တွယ်၍ အသုံးပြုသူကို မနှောင့်ယှက်ပါ:

| အမှား | ကိုင်တွယ်ပုံ |
|---|---|
| 用户名已存在 (အသုံးပြုသူအမည် ရှိပြီးသား) | မူကွဲ အမည် (အသုံးပြုသူအမည်+ဂဏန်း) ကို အလိုအလျောက် အကြံပြု၍ အသုံးပြုသူ အတည်ပြုပြီး ချက်ချင်း ထပ်မံ ကြိုးစား (အတည်ပြုကုဒ်သည် ဆက်လက် တကျိုပ် ရှိနေ၍ ထပ်ပို့စရာ မလို) |
| 邮箱已被使用 (အီးမေးလ်ကို အသုံးပြုပြီးသား) | အသုံးပြုသူကို မေးပါ— အီးမေးလ် အခြားတစ်ခု ပြောင်းမလဲ၊ သို့မဟုတ် တကယ်တော့ အကောင့် ရှိပြီးသား ဖြစ်နေမလား (လော့ဂ်အင်/စကားဝှက် ပြန်ရယူခြင်း သို့ ပြောင်း) |
| 邮箱验证码错误或已过期 (အီးမေးလ် အတည်ပြုကုဒ် မှားယွင်း သို့မဟုတ် သက်တမ်းကုန်) | မိနစ် 10 ကျော်လျှင် → `send-code` ကို ထပ်မံ ပေးပို့ |
| 发送/注册过于频繁（429） (ပေးပို့/အကောင့်ဖွင့် မကြာခဏ လွန်ကဲ) | မိနစ် 1 စောင့်၍ ထပ်ကြိုးစား၍ အသုံးပြုသူကို တစ်ချက် ပြောရုံသာ |

## အဆင့် 6: တစ်ချက်နှိပ် လော့ဂ်အင် (လင့်ခ် 1) + ငွေပေးချေ

1. အကောင့်ဖွင့် အောင်မြင်လျှင် ချက်ချင်း:
   ```
   node scripts/powpow-register.mjs login-link --target pending
   ```
   လင့်ခ်ကို အသုံးပြုသူသို့ ပေးပို့ပါ— **နှိပ်လိုက်လျှင် ဘရောက်ဇာသည် စာရင်းသွင်းမှု စာမျက်နှာပေါ်သို့ တိုက်ရိုက် ရောက်ရှိ၍ လော့ဂ်အင် ပြုလုပ်ထားသည့် အခြေအနေ ဖြစ်သည်**— နောက်ပိုင်း ငွေပေးချေမှု ပြီးမြောက်လျှင် ပြန်ရောက် စာမျက်နှာတွင် "ငွေပေးချေမှု အောင်မြင်" ဟု မှန်ကန်စွာ ပြသနိုင်သည်။ (ဤအခြေအနေတွင် အကြောင်းအရာ စာမျက်နှာများကို ဆက်လက်၍ စာရင်းသွင်းမှု စာမျက်နှာသို့ ပယ်ထားသည်— ဤသည်မှာ ပလက်ဖောင်း ငွေပေးချေရေးနံရံ၏ ပုံမှန် လုပ်ဆောင်မှု ဖြစ်ပြီး bug မဟုတ်၊ အတွင်းပိုင်း ယန္တရားကိုလည်း အသုံးပြုသူအား ရှင်းပြစရာ မလိုပါ။)
2. အစီအစဉ် သုံးမျိုးမှ တစ်မျိုး ရွေး၍ ပြသလျှင် စျေးနှုန်း အတူ ပြပါ:
   - လစဉ် **¥6.99** (အရင် စမ်းသပ်ရန် အကြံပြု) / သုံးလတ် **¥19.99** / နှစ်စဉ် **¥69.99** — Alipay ဖြင့် တစ်ကြိမ် ပေးချေ၍ သက်ဆိုင်ရာ ကာလ ရရှိသည်၊ **အလိုအလျောက် ဆက်သွင်း မလုပ်ပါ**
3. အသုံးပြုသူ ရွေးပြီးလျှင်:
   ```
   node scripts/powpow-register.mjs create-order --package monthly
   ```
   script က ငွေပေးချေရေး စာမျက်နှာ ဖိုင် လမ်းကြောင်း ပြန်ပေးသည်— **စနစ် command ဖြင့် တိုက်ရိုက် ဖွင့်ပါ** (Windows: `start <ဖိုင်>`; macOS: `open <ဖိုင်>`; Linux: `xdg-open <ဖိုင်>`)။ ဘရောက်ဇာသည် Alipay တရားဝင် ငွေပေးချေရေး ကောင်တာသို့ အလိုအလျောက် ကူးပြောင်းသွားပြီး အသုံးပြုသူက QR code စကင်န်ဖတ် သို့မဟုတ် Alipay အတွင်း လော့ဂ်အင်၍ ငွေပေးချေသည်။
4. စက္ကန့် 10–15 တိုင်း `query` ကို လုပ်ဆောင်၍ `paid` ပြန်ရလျှင် ရပ်ပါ (ငွေရောက်မှုသည် ပုံမှန်အားဖြင့် စက္ကန့် အနည်းငယ်မှ မိနစ် တစ်မိနစ် အတွင်း ဖြစ်သည်)။ အသုံးပြုသူက ငွေပေးချေရေး စာမျက်နှာကို ကြားခါနေ ပိတ်လိုက်လျှင် → `create-order` ကို တိုက်ရိုက် ထပ်မံ လုပ်ဆောင်ပါ (အဟောင်း အော်ဒါသည် နာရီ 2 အကြာ အလိုအလျောက် ပိတ်သွား၍ ဂရုစိုက်စရာ မလို)။
5. နိုင်ငံခြား/Alipay မရှိသော အသုံးပြုသူများ: စာရင်းသွင်းမှု စာမျက်နှာပေါ်ရှိ PayPal လမ်းကြောင်းကို အသုံးပြုရန် လမ်းညွှန်ပါ (skill က ကိုယ်စား မလုပ်၊ လမ်းပြရုံသာ); WeChat QR စကင်န်ဖတ် လမ်းကြောင်းသည် လူကိုယ်တိုင် အတည်ပြုရသဖြင့် ငွေရောက်မှု နှောင့်နှေးနိုင်သည်။ ငွေပေးချေပြီးလျှင် အဆင့် 7 သို့ အတိုင်းအတာတူ ဆက်လက် လိုက်ပါ။

## အဆင့် 7: တရားဝင် လော့ဂ်အင် (လင့်ခ် 2)

ငွေရောက်မှု အတည်ပြုပြီးလျှင်၊ ပထမ နောက်ဆုံး စာရင်းသွင်းမှု ကြေညာချက်ပါ လော့ဂ်အင် အခြေအနေကို လဲလှယ်၍ မူလ စာမျက်နှာသို့ တန်းရောက် လင့်ခ်ကို ဖန်တီးပါ:

```
POWPOW_REGISTER_PASSWORD=<စကားဝှက်> node scripts/powpow-register.mjs refresh-login
node scripts/powpow-register.mjs login-link --target home
```

လင့်ခ်ကို အသုံးပြုသူသို့ ပေးပို့ပါ— **နှိပ်လိုက်လျှင် မူလ စာမျက်နှာပေါ်သို့ တိုက်ရိုက် ရောက်ရှိ၍ အသင်းဝင် အခြေအနေ အပြည့်အစုံ ရရှိသည်**၊ ဤနေရာတွင် အကောင့်ဖွင့် လုပ်ငန်းစဉ် အားလုံး ပြီးစီးသည်။

## အဆင့် 8: အပြီးအစီး

1. `node scripts/powpow-register.mjs cleanup` ဖြင့် ဤစက် ၏ ယာယီ state file (session အထောက်အထား) ကို သန့်ရှင်းရေး လုပ်ပါ။
2. အသုံးပြုသူကို "အကောင့် ကဒ်" တစ်ခု ပေးပါ— အသုံးပြုသူအမည်၊ အီးမေးလ်၊ အသင်းဝင် သက်တမ်းကုန် အချိန် (စကားဝှက်ကို ထပ်မံ မပြပါနှင့်— ဖန်တီးမှု မုဒ်တွင် ဖန်တီးချိန်၌ အသုံးပြုသူအား သိမ်းဆည်းစေပြီးသား၊ ကိုယ်တိုင် သတ်မှတ်ထားလျှင် ကိုယ်တိုင် သိသည်)။
3. အသုံးပြုမှု လမ်းညွှန်: မြေပုံ လည်ပတ်ခြင်း၊ ပထမဆုံး ခရီးသွားမှတ်တမ်း တင်ခြင်း (→ powpow-simple သို့ လွှဲပေး)။
4. တိုးချဲ့မှု အကြံပြု: `@durenzidu/powpow-integration` skill နှင့် `@durenzidu/openclaw-channel-powpow` plugin — ပူဖောင်းကို အသုံးပြုသူ ၏ ကိုယ်ပိုင် agent သို့ ချိတ်ဆက်ရန်၊ ထည့်သွင်းချင်လျှင် ထည့်သွင်းရေး command ပေးပါ။
5. "နောက်တစ်ဆင့်" အပိုင်းဖြင့် အပြီးအစီး လုပ်ပါ။

## Conversation UX

PowPow ၏ ဝန်ဆောင်မှု အသုံးအနှုန်း စတိုင်ကို ဆက်လက် အသုံးပြုပါ:

- **အသုံးပြုသူသည် စာကြောင်း၏ အဓိက သတ္တဝါ ဖြစ်သည်**—"သင် လုပ်နိုင်သည်…" က "ငါ သင့်အား လိုအပ်သည်…" ထက် သာသည်; သင်ခန်းစာ မပြောပါနှင့်၊ အထက်မှ ကြည့်သော အမြင် မထားပါနှင့်။
- **တစ်ပတ်လျှင် ဆုံးဖြတ်ချက် တစ်ခုသာ တိုးတက်စေသည်**; အချက်အလက် တောင်းခံမီ အကြောင်းပြချက် အရင် ပေးပါ။
- **တုံ့ပြန်ချက် တိုင်း၏ အဆုံးတွင်** "နောက်တစ်ဆင့်" အပိုင်း တစ်ခု (ခွဲခြား line + 👉 + လုပ်ဆောင်ချက် တစ်ခု + "လုပ်ပြီးလျှင် ငါ…" စာကြောင်း) ရှိသည်၊ ဥပမာ:
  ```
  ────────────────────
  👉 ယခု လုပ်ဆောင်ရမည်: အီးမေးလ်တွင် ဂဏန်း 6 လုံး အတည်ပြုကုဒ်ကို ရှာ၍ တိုက်ရိုက် ပေးပို့ပါ
     (လက်ခံရရှိလျှင် ချက်ချင်း အကောင့် ဖန်တီးပေးမည်)
  ```
- **စကားဝှက်နှင့် ပတ်သက်၍ လုံခြုံရေး သင်ခန်းစာ ကိုယ့်ဘာသာ မပြောပါနှင့်**; အတွင်းပိုင်း ယန္တရား၊ အကြိမ်ရေ ကန့်သတ်ချက် သို့မဟုတ် လုံခြုံရေး ဒီဇိုင်းကို အသုံးပြုသူ မေးမှသာ ရှင်းပါ။
- အေးဂျင့် ကိုယ်စား လုပ်ဆောင်လျှင် တိုးတက်မှုကို ပို၍ အစီရင်ခံပါ— script အဆင့် တိုင်း ပြီးလျှင် စာကြောင်း တစ်ကြောင်းဖြင့် ထိုမတိုင်မီ ဖြစ်ခဲ့သည်ကို ပြောပါ ("အကောင့် ဖန်တီးပြီးပါပြီ"၊ "ငွေပေးချေရေး စာမျက်နှာကို သင့်အတွက် ဖွင့်ပြီးပါပြီ")။

## တင်းကျပ်သော စည်းမျဉ်းများ

- **အထောက်အထား လုံခြုံရေး**: စကားဝှက်ကို environment variable `POWPOW_REGISTER_PASSWORD` မှတစ်ဆင့်သာ script သို့ ပေးပို့၍ **command line parameter (process list တွင် မြင်နိုင်သည်)** အဖြစ် **လုံးဝ** မရေးပါနှင့်၊ မည်သည့် ဖိုင်တွင်မျှ မရေးပါနှင့် (ဖန်တီးမှု မုဒ်တွင် တစ်ကြိမ် ပြသခြင်းသည် အသုံးပြုသူ သိမ်းဆည်းနိုင်ရန် အတွက်သာ၊ နောက်ပိုင်း ထပ်မပြောတော့ပါ)။ အတည်ပြုကုဒ်ကို တရားဝင် အကောင့်ဖွင့် interface အတွက်သာ အသုံးပြု၍ အသုံးပြုပြီးလျှင် ဖျက်ပစ်သည်။
- **တရားဝင် နယ်နိမိတ်**: တောင်းဆိုမှုအားလုံးသည် `https://global.powpow.online` (script တွင် တည်ဆောက်ထားပြီးသား) သို့သာ သွား၍ အသုံးပြုသူ အချက်အလက်ကို တတိယ လိပ်စာ မည်သည့်အရာသို့မျှ **လုံးဝ** မပေးပို့ပါနှင့်။
- **ငွေပေးချေရေး နယ်နိမိတ်**: အေးဂျင့်သည် အော်ဒါ ဖန်တီးခြင်း၊ ကောင်တာ ဖွင့်ခြင်း၊ ငွေရောက်မှု စုံစမ်းခြင်းသာ လုပ်၍ အသုံးပြုသူ ၏ Alipay အကောင့်/ငွေပေးချေရေး အထောက်အထားကို **လုံးဝ** မထိပါနှင့်၊ "အစား ငွေပေးချေပေးမည်" ဟုလည်း လုံးဝ မကတိပြုပါနှင့်။
- **ငွေပေးချေရေးနံရံသည် bug မဟုတ်**: pending အခြေအနေတွင် စာရင်းသွင်းမှု စာမျက်နှာ/ပြန်ရောက် စာမျက်နှာသို့ ဝင်ရောက်ခွင့်သည် ဒီဇိုင်းအတိုင်း ခွင့်ပြုထားခြင်း၊ အကြောင်းအရာ စာမျက်နှာ ပယ်ထားခြင်းသည် ပလက်ဖောင်း ငွေပေးချေရေးနံရံ ပုံမှန် လုပ်ဆောင်နေခြင်း ဖြစ်၍ ဖြတ်ကျော်ရန် မကြိုးစားပါနှင့်။
- **ပြန်ကူးခြင်း လွတ်လပ်မှု**: အသုံးပြုသူသည် မည်သည့်အဆင့်တွင်မဆို ကိုယ်တိုင် လုပ်ချင်လျှင်၊ သို့မဟုတ် ပတ်ဝန်းကျင်က script ကို မထောက်ပံ့လျှင် အချိန်မရွေး လမ်းညွှန်သက်သက် မုဒ်သို့ ပြန်ကူးနိုင်သည်— လင့်ခ် ပေး၊ စည်းမျဉ်း ရှင်းပြ၊ အမှားရှာ လိုက်ပါပေး။
- ပလက်ဖောင်း စည်းမျဉ်းများကို ကိုယ်စား မဖန်တီးပါနှင့်: ဖိလ်ဒ် စည်းမျဉ်း၊ အမှား စာသား၊ အကြိမ်ရေ ကန့်သတ်ချက် အားလုံးသည် ပလက်ဖောင်း ကုဒ်မှ လာသည် (`references/registration-flow.md` တွင် ကုဒ် ရင်းမြစ် ရှိသည်)၊ ပလက်ဖောင်း အပ်ဒိတ်များကို အွန်လိုင်း လုပ်ဆောင်မှု အမှန်အတိုင်း လိုက်နာပါ။
- ပုံ ပြသရာတွင် အထုပ်အတွင်း `assets/screenshots/` ၏ ပုံများကိုသာ အသုံးပြုပါ (ပုံတစ်ခုစီ၏ အသုံးပြုမှုကို `references/screenshots.md` တွင် ကြည့်ပါ)။
- တုံ့ပြန်ချက် တိုင်းကို "နောက်တစ်ဆင့်" အပိုင်းဖြင့် အပြီးအစီး လုပ်၍ အသုံးပြုသူသည် ယခု ဘာလုပ်ရမည်ကို အမြဲ သိစေပါ။

# စာရင်းသွင်းမှု အသက်ဝင်စေခြင်းနှင့် ငွေပေးချေမှု — powpow-register

## နိဂုံး (အဖြေကို အရင်ဆိုပါ)

**Alipay လမ်းကြောင်း စတင်ရရှိပြီး (2026-10-07 မှစ၍) ဤ skill ၏ အဓိက အကြံပြု ငွေပေးချေရေး နည်းလမ်း ဖြစ်၍ အေးဂျင့်က အော်ဒါ လုပ်ဆောင်၍ ငွေရောက်မှု စောင့်ကြည့်နိုင်သည်။**
နိုင်ငံခြား/Alipay မရှိသော အသုံးပြုသူများသည် PayPal သို့ ပြန်ကူးသည်; WeChat QR (လူကိုယ်တိုင် အတည်ပြု) နှင့် Huawei IAP တို့သည်လည်း ရှိသေး၍ skill က ကိုယ်စား မလုပ်ပါ။

ငွေပေးချေရေး အဆင့်၏ တာဝန် နယ်နိမိတ်: အေးဂျင့်သည် **အော်ဒါ ဖန်တီးခြင်း၊ ကောင်တာ ဖွင့်ခြင်း၊ ငွေရောက်မှု စုံစမ်းခြင်း** လုပ်နိုင်၍ အသုံးပြုသူ ၏ Alipay
အကောင့်/ငွေပေးချေရေး အထောက်အထားကို **လုံးဝ** မထိပါနှင့်၊ "အစား ငွေပေးချေပေးမည်" ဟု လုံးဝ မကတိပြုပါနှင့်။ ငွေပေးချေခြင်း လုပ်ငန်းကို အသုံးပြုသူ ကိုယ်တိုင်ကသာ Alipay တရားဝင် ကောင်တာတွင် လုပ်ရသည်။

## Alipay လမ်းကြောင်း (vibepay၊ အဓိက)

တစ်ကြိမ် ပေးချေ၍ ပိုင်ဆိုင်သည့် စနစ်: တစ်ကြိမ် ပေးချေ၍ သက်ဆိုင်ရာ ကာလ ရရှိ၍ **အလိုအလျောက် ဆက်သွင်း မလုပ်ပါ**။ အစီအစဉ်ကို
`src/lib/alipay-vibepay.ts` (`ALIPAY_PACKAGES`) တွင် ပုံသေ သတ်မှတ်ထားသည်:

| key | planId | အမည် | စျေးနှုန်း | ကာလ |
|---|---|---|---|---|
| `monthly` | alipay-monthly | လစဉ် အသင်းဝင် | ¥6.99 | ရက် 30 |
| `quarterly` | alipay-quarterly | သုံးလတ် အသင်းဝင် | ¥19.99 | ရက် 90 |
| `yearly` | alipay-yearly | နှစ်စဉ် အသင်းဝင် | ¥69.99 | ရက် 365 |

### interface စာချုပ် (skill script တွင် ထည့်သွင်းပြီးသား၊ အေးဂျင့်က တောင်းဆိုမှု ကိုယ်တိုင် မဆောက်)

| interface | နည်းလမ်း | ရှင်းလင်းချက် |
|---|---|---|
| `/api/payment/alipay/create-order` | POST | `Authorization: Bearer <JWT>` လိုအပ် (pending အသုံးပြုသူ ဖြစ်စေ ရသည်)။ body `{package}` → `{paymentHtml, outTradeNo, amount, planName}` ပြန်ပေး; `paymentHtml` သည် Alipay gateway သို့ အလိုအလျောက် တင်ပြသော ဖောင်း စာမျက်နှာ ဖြစ်သည် |
| `/api/payment/alipay/query` | GET `?outTradeNo=` | ဤအရာလည်း Bearer စစ်ဆေးမှု။ `paid` / `pending` / `closed` / `unknown` ပြန်ပေးသည် |
| `/api/payment/alipay/notify` | POST (Alipay server callback) | စစ်ဆေးမှု အစိတ်အပိုင်း ငါးခု (signature၊ app_id၊ ငွေပမာဏ ကိုက်ညီမှု၊ TRADE_SUCCESS/TRADE_FINISHED၊ ကုန်သွယ်လုပ်ငန်း တစ်ခုတည်းဖြစ်မှု) → **idempotent** ဖြင့် အော်ဒါ အပ်ဒိတ် + စာရင်းသွင်းမှု ဖန်တီး + အကောင့် အသက်ဝင်စေ။ skill သည် ဤ interface ကို လုံးဝ မထိပါ |
| `/payment/alipay/return` | ဘရောက်ဇာ ပြန်ရောက် စာမျက်နှာ | အများသုံး လမ်းကြောင်း၊ ငွေပေးချေပြီးလျှင် 「支付成功」 (ငွေပေးချေမှု အောင်မြင်) အတည်ပြုချက် ပြသ၍ စာမျက်နှာအတွင်း backend ၏ အမှန်တကယ် အခြေအနေကို polling လုပ်သည် |

- ငွေမပေးရသေးသော အော်ဒါသည် **နာရီ 2 အကြာ အလိုအလျောက် ပိတ်သည်**; အသုံးပြုသူ ကြားခါနေ စွန့်လွှတ်လျှင် → `create-order` ကို တိုက်ရိုက် ထပ်လုပ်၍ အော်ဒါအဟောင်းကို ဂရုစိုက်စရာ မလို။
- script က `paymentHtml` ကို ယာယီ HTML ဖိုင်ထဲ ရေး၍ အေးဂျင့်က စနစ် command ဖြင့် ဖွင့်လျှင် Alipay ကောင်တာသို့ ဝင်ရောက်နိုင်သည်
  (QR စကင်န်ဖတ် သို့မဟုတ် Alipay အတွင်း လော့ဂ်အင်၍ ငွေပေးချေ)။

### အသက်ဝင်မှု လမ်းကြောင်း (အလိုအလျောက်၊ လူ လုပ်စရာ မလို)

notify signature စစ်ဆေးမှု အောင်မြင် → `paymentOrders` ကို ငွေပေးချေပြီး အမှတ်အသား လုပ် → `user_subscriptions` ဖန်တီး/ဆက်လက်
(`planId`၊ `currentPeriodEnd` ကို durationDays အလိုက် တွက်၍ ပြန်စာရင်းသွင်းလျှင် မူလ သက်တမ်းကုန် ရက်စွဲပေါ်တွင် ဆက်လက်) →
`users.accountStatus: active` + `subscriptionStatus: ACTIVE` → ပြန်ရောက် စာမျက်နှာက paid ဖြစ်လျှင် အောင်မြင်ကြောင်း ပြသသည်။

### ငွေပေးချေပြီးလျှင် လော့ဂ်အင် အခြေအနေ အသစ်သို့ လဲရမည် (အရေးကြီး)

JWT တွင် စာရင်းသွင်းမှု ကြေညာချက် ပါဝင်သည် (pending အကောင့်သည် `NONE`)။ **ငွေရောက်မှုသည် ဒေတာဘေ့စကိုသာ အပ်ဒိတ်လုပ်၍ လက်ခံရရှိပြီးသော
JWT ကို မပြောင်းလဲ**— ကုဒ်အဟောင်း ၏ ကြေညာချက်သည် ဆက်လက် NONE ဖြစ်၍ တိုက်ရိုက် အသုံးပြု၍ လော့ဂ်အင် လင့်ခ် ဖန်တီးလျှင် "စာရင်းသွင်းမှု မရှိ" ဟု ပေါ်လာမည်။
ထို့ကြောင့် skill သည် `paid` အတည်ပြုပြီးလျှင် ပထမ `refresh-login` ကို လုပ်ဆောင်၍ (ထပ်မံ လော့ဂ်အင်၍ JWT အသစ် လဲလှယ်၊ ကြေညာချက် ACTIVE ဖြစ်လာမည်)၊
ပြီးမှ လင့်ခ် 2 ကို ဖန်တီးသည်။ ဤသည်မှာ ဒီဇိုင်း လုပ်ဆောင်မှု ဖြစ်၍ vulnerability ပြင်ဆင်မှု မဟုတ်ပါ။

## စာရင်းသွင်းမှု စာမျက်နှာ ၏ လမ်းကြောင်း လေးခု

စာရင်းသွင်းမှု စာမျက်နှာ `src/app/(public)/subscription/page.tsx` သည် လည်ပတ်နေသော ပတ်ဝန်းကျင်အလိုက် ပြသည်:

| လမ်းကြောင်း | ပတ်ဝန်းကျင် | ယန္တရား | အသက်ဝင်စေမှု နည်းလမ်း |
|---|---|---|---|
| **Alipay (အဓိက)** | Web ဘက် | `AlipayPaymentSection` သည် vibepay interface (အထက် ဇယား) ကို ဖြတ်သည် | notify မှ server ဘက် အလိုအလျောက် အသက်ဝင်၊ စက္ကန့် အနည်းငယ် အတွင်း |
| PayPal စာရင်းသွင်းမှု | Web ဘက် (Harmony မဟုတ်) | `/api/subscription/create` → PayPal ခွင့်ပြုချက်သို့ ခုန်; လစဉ် အလိုအလျောက် ဆက်သွင်းကို အချိန်မရွေး ဖျက်နိုင် (`/api/subscription/manage`) | PayPal Webhook (`BILLING.SUBSCRIPTION.*`) က active ဖြစ်အောင် အလိုအလျောက် လုပ်သည် |
| 微信扫码订阅 (WeChat QR ဖြင့် စာရင်းသွင်းမှု) | Web ဘက် (Harmony မဟုတ်) | စာမျက်နှာ အောက်ပိုင်း "微信扫码订阅": QR စကင်န်ဖတ်၍ ငွေလွှဲ | **လူကိုယ်တိုင် အတည်ပြု**၊ ငွေရောက်မှု နှောင့်နှေးနိုင်; ငွေပေးချေပြီး ချက်ချင်း မအောင်မြင်ဟု မဆုံးဖြတ်ပါနှင့် |
| Huawei အက်ပလီကေးရှင်းအတွင်း ဝယ်ယူခြင်း | Harmony App အတွင်း | မူလ `NativeBridge.purchaseSubscription()` | `/api/subscription/activate-huawei` ဖြင့် Huawei အော်ဒါ အတည်ပြုပြီး အသက်ဝင်စေသည် |

PayPal အစီအစဉ်နှင့် စျေးနှုန်းကို `/api/subscription/plans` မှ dynamic ဖတ်ရှိသည်; စာမျက်နှာ ၏ ပုံသေ စာသား: Auto-renews. Cancel anytime.

## အခြေအနေနှင့် ခုန်ကူးမှု

- Alipay ငွေပေးချေပြီးလျှင် → ပြန်ရောက် စာမျက်နှာတွင် အောင်မြင်ကြောင်း ပြသည်; PayPal အောင်မြင်လျှင် → `/subscription/success` → အကောင့် active →
  `next` parameter ဖြင့် ညွှန်ထားသော မူလ စာမျက်နှာသို့ အလိုအလျောက် ပြန်ခုန်သည် (မရှိလျှင် မူလ စာမျက်နှာ)။
- စာရင်းသွင်းမှု ရှိပြီးသား အသုံးပြုသူ စာရင်းသွင်းမှု စာမျက်နှာသို့ ထပ်ဝင်လျှင် → "You're All Set!" ပြ၍ စက္ကန့် 3 အကြာ မူလ စာမျက်နှာသို့ အလိုအလျောက် ပြန်သည်။
- ငွေပေးချေရေး မအောင်မြင်/ဖျက်သိမ်း (PayPal) → `/subscription/cancel`၊ ထပ်မံ စတင်နိုင်သည်။

## အမှားရှာ

| ဖြစ်စဉ် | ကိုင်တွယ်ပုံ |
|---|---|
| Alipay ငွေပေးချေပြီး၍ `query` ဆက်လက် pending ဖြစ်နေ | notify သည် ရှားပါးစွာသာ နှောင့်နှေးသည်; စက္ကန့် 30 စောင့်၍ ထပ်စုံစမ်းပါ။ မအောင်မြင်လျှင် အသုံးပြုသူအား ဘရောက်ဇာသို့ ပြန်၍ ပြန်ရောက် စာမျက်နှာ အခြေအနေ ကြည့်စေပါ၊ ဆက်လက် မအောင်မြင်လျှင် ပလက်ဖောင်း အထောက်အပံ့ (dongtao@outlook.com) ကို ဆက်သွယ်၍ `outTradeNo` တင်ပြပါ |
| Alipay ငွေပေးချေပြီး၊ လင့်ခ် 2 ဖြင့် ဝင်လျှင် ဆက်လက် ပယ်ထားခံရ | `refresh-login` လုပ်ခဲ့ခြင်း မရှိ (ကုဒ်အဟောင်း JWT ၏ ကြေညာချက် မအပ်ဒိတ်လုပ်ရသေး) — ပထမ `refresh-login` လုပ်၍ `login-link` ဆက်လုပ်ပါ |
| ငွေပေးချေပြီးလျှင် ဆက်လက် 403 (PayPal) | Webhook တစ်ခါတစ်ရံ နှောင့်နှေး၍ ထပ်မံ လော့ဂ်အင်၍ အခြေအနေ ပြန်ရှင်းလင်းပါ |
| WeChat ငွေပေးချေပြီး၍ အသက်မဝင် | လူကိုယ်တိုင် အတည်ပြုမှုသည် asynchronous ဖြစ်၍ နာရီ အနည်းငယ်အတွင်း မဝင်လျှင် ပလက်ဖောင်း အထောက်အပံ့ ဆက်သွယ်ပါ |
| စာရင်းသွင်းမှု စာမျက်နှာတွင် "No subscription plans available" ပြ | `/api/subscription/plans` တွင် အသုံးပြုနိုင်သော PayPal အစီအစဉ် မရှိ၊ ပလက်ဖောင်း ဘက် ဖွဲ့စည်းမှု ပြဿနာ; တရုတ်ပြည်အတွင်း အသုံးပြုသူများသည် Alipay သို့ ပြောင်း၍ လုပ်လျှင် ရသည် |

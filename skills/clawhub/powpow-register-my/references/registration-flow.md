# အကောင့်ဖွင့် လုပ်ငန်းစဉ် အသေးစိတ် — powpow-register

ပြဿနာ ရှာဖွေရာတွင် ကြည့်ရှုရန်။ စည်းမျဉ်း အားလုံးသည် ပလက်ဖောင်း ရင်းမြစ် ကုဒ် (Next.js frontend-backend တစ်ညီတစ်ညှိ စစ်ဆေးမှု) မှ လာ၍ ရင်းမြစ် ဖိုင် ညွှန်းထားသည်။ ပလက်ဖောင်း အပ်ဒိတ်လုပ်လျှင် အွန်လိုင်း လုပ်ဆောင်မှု အမှန်အတိုင်း လိုက်နာပါ။

## ဝင်ပေါက်များ

- အကောင့်ဖွင့် စာမျက်နှာ: https://global.powpow.online/register
- လော့ဂ်အင် စာမျက်နှာ: https://global.powpow.online/login
- စာရင်းသွင်းမှု စာမျက်နှာ: https://global.powpow.online/subscription
- `?next=...` ပါဝင်သော မျှဝေ လင့်ခ်မှ ဝင်လျှင် အကောင့်ဖွင့်+ငွေပေးချေ ပြီးမြောက်လျှင် မူလ စာမျက်နှာသို့ အလိုအလျောက် ပြန်ရောက်သည်။

|---|---|---|---|
| ပရိုဖိုင်ပုံ | ရွေးချယ်နိုင် | ပုံ <=5MB၊ SVG မထောက်ပံ့; server က အလိုအလျောက် ဖိသိပ်သည် (>100KB ဖြစ်လျှင် 400×400 / အရည်အသွေး 90 သို့ ဖိသိပ်) | `src/app/api/auth/register/route.ts` |
| အသုံးပြုသူအမည် | မဖြစ်မနေ | စာလုံး 2~50 လုံး၊ trim ပြီးလျှင် **စာလုံးအသေး** အဖြစ် သိမ်းဆည်း (Tom နှင့် tom ကို အသုံးပြုသူအမည် တစ်ခုတည်း အဖြစ် သတ်မှတ်၍ အကောင့်ဖွင့် ဘက်နှင့် လော့ဂ်အင် ဘက် နှစ်ဘက်စလုံးတွင် စာလုံးကြီး/ငယ် မခွဲခြား) | အထက်ပါအတိုင်း (zod schema) |

| စကားဝှက် အတည်ပြု | မဖြစ်မနေ | စကားဝှက်နှင့် တူညီရမည် (frontend စစ်ဆေးမှုသာ) | `src/app/(public)/register/page.tsx` |
| ပြောင်အမည် | ရွေးချယ်နိုင် | စာလုံး <=100 လုံး; မဖြည့်လျှင် အသုံးပြုသူအမည်ကို ပုံသေ ယူသည် | register route |
| အီးမေးလ် | **မဖြစ်မနေ** | မှန်ကန်သော အီးမေးလ် ပုံစံ၊ စာလုံး <=255 လုံး; အီးမေးလ် တစ်ခုဖြင့် အကောင့် တစ်ခုသာ အကောင့်ဖွင့်နိုင် | register route |

စာမျက်နှာတွင် တတိယ ပါတီ လော့ဂ်အင် ခလုတ် သုံးခု ထပ်ဆောင်း ပါဝင်သည်: **Google၊ Watcha၊ Huawei အကောင့်** (`GoogleSignInButton` /
`WatchaLoginButton` / `HuaweiLoginButton`)။ တတိယ ပါတီ အကောင့်များတွင် ဒေသတွင်း စကားဝှက် မရှိ၍ နောက်ပိုင်း စကားဝှက်ဖြင့် လော့ဂ်အင်လုပ်လျှင်
「该账号未设置密码，请使用其他方式登录」 (ဤအကောင့်တွင် စကားဝှက် သတ်မှတ်ထားခြင်း မရှိ၊ အခြား နည်းလမ်းဖြင့် ဝင်ရောက်ပါ) ဟု ပြလိမ့်မည်။

## အကြိမ်ရေ ကန့်သတ်ချက်နှင့် အတင်းဝင်ခြင်း တားဆီး parameter များ

| လုပ်ဆောင်မှု | ကန့်သတ်ချက် | ရင်းမြစ် |
|---|---|---|
| အကောင့်ဖွင့် တင်ပြ | **မိနစ် 3 ကြိမ်/IP**၊ ကျော်လျှင် 429 | `src/lib/rate-limit.ts` `REGISTER_RATE_LIMIT` |
| အတည်ပြုကုဒ် ပို့ | တူညီသော IP တစ်နေ့လျှင် မိနစ် 1 ကြိမ် **နှင့်** တူညီသော အီးမေးလ် မိနစ် 1 ကြိမ်၊ ကျော်လျှင် 429; frontend ခလုတ်တွင် စက္ကန့် 60 countdown | `src/app/api/auth/register/send-code/route.ts` |
| အတည်ပြုကုဒ် စစ်ဆေး | အီးမေးလ် တစ်ခုလျှင် မိနစ် 10 အတွင်း အများဆုံး **ကြိမ် 5** ကြိုးစားနိုင်၊ အကန့်အသတ် ရောက်လျှင် ကုဒ် မှန်နေသော်လည်း ငြင်းပယ်၍ ကုဒ် အသစ် ပို့ရမည် | `src/lib/email-verification.ts` |
| စကားဝှက် မေ့နေ ကုဒ်ပို့ | မိနစ် 1 ကြိမ်/IP | `src/app/api/auth/forgot-password/route.ts` |
| လော့ဂ်အင် | မိနစ် 5 ကြိမ်/IP; အကောင့် တစ်ခုလျှင် ဆက်တိုက် ရှုံးနိုင် **ကြိမ် 5 ရောက်လျှင် မိနစ် 30 လော့ခ်** (423)၊ ထိုကာလအတွင်း ကျန်ရှိသော အကြိမ်ရေ လျှော့၍ ပြသည် | `src/app/api/auth/login/route.ts`၊ `rate-limit.ts` |

**ကိုယ်ရေးအချက်အလက် ကာကွယ်ရေး လုပ်ဆောင်မှု**: အတည်ပြုကုဒ် ပို့ခြင်း / စကားဝှက် မေ့နေခြင်းတွင် အီးမေးလ် အကောင့်ဖွင့်ပြီးသား ဖြစ်စေ မရှိစေ၊ interface က အောင်မြင် စာသား တူညီစွာ ပြန်ပေး၍ အီးမေးလ် အကောင့်ဖွင့်ပြီးသား ဖြစ်မဖြစ် မပြောပြပါ။

## အေးဂျင့် ကိုယ်စားလုပ်ဆောင်မှု မုဒ်နှင့် Web အကောင့်ဖွင့် ၏ တန်းတူညီမှု

skill script ခေါ်ဆိုသည်မှာ **တူညီသော အများသုံး API အစု** (`/api/auth/register`၊ `send-code`၊ `login`၊
`/api/auth/me`) ဖြစ်၍ အကောင့်ဖွင့် စာမျက်နှာ ဖောင်း တင်ပြမှုနှင့် လုံးဝ တူညီသော စစ်ဆေးမှု၊ အကြိမ်ရေ ကန့်သတ်ချက်နှင့် အမှား လမ်းကြောင်း ဖြတ်သည်— ဤဖိုင်၏
စည်းမျဉ်း အားလုံးသည် နည်းလမ်း နှစ်မျိုးလုံးအတွက် တန်းတူညီသည်။ script လုပ်ငန်းစဉ်နှင့် command စာချုပ်ကို `references/agent-flow.md` တွင် ကြည့်ပါ။

## စာရင်းသွင်းမှုအောင်မြင်ပြီးနောက်အခြေအနေအစဉ်

> **အခမဲ့စမ်းသပ်ကာဧ (2026-10-18 မှစ; ပလက်ဖောင်အမှန်တကယ်အပြုအမူအတိုင်း)** — အသစ်စာရင်းသွင်းထားသောအကောင့်သည်လုပ်ဆောင်ချက်အားလုံးကိုတိုက်ရိုက်အသုံးပြုနိုင်
> (ဖီဒ်, မြေပုံ, ဒစ်ဂျစ်တယ်လူများ, စစ်ဆင်မှုများ, စသည်), ငွေမပေးရဘဲ; စာရင်းသွင်းမှုမရှိသောအကောင့်များသည်အကြောင်းအရာစာမျက်နှာများမှတံတိုင်းမရှိတော့ပါ။ ဤအပိုင်းတွင်ဖော်ပြသည့် "pending ပိတ်ဆို့မှု"
> သည် စမ်းသပ်ကာဧကုန်ဆုံးပြီးနောက်ပုံမှန်အခြေအနေဖြစ်သည် — အချိန်ရလျှင် အမှန်တကယ်အွန်လိုင်းအပြုအမူအတိုင်း။

1. အသုံးပြုသူကို `accountStatus: 'pending'` နှင့် **အစီးအ 3** ဖြင့်သိမ်းဆည်းသည် (register လမ်းကြောင်း)။
2. ဆာဗာသည်ကူခီ HttpOnly နှစ်ခုလည်းစိုက်ဝင်သည် — JWT (စာမျက်နှာများတိုက်ရိုက်ဝင်နိုင်) နှင့် pendingUserToken (subscription အစဉ်အတွက်အထောက်အထားစိစစ်ခြင်း)။
3. ပုံမှန်အခြေအနေတွင် (စမ်းသပ်ကာဧကုန်ဆုံး / အခမဲ့ကာဧမရှိ), စာရင်းသွင်းစာမျက်နှာသည် `pending_payment` ကိုတွေ့ပြီး `/subscription` သို့လမ်းကြောင်းပြန်သည်
   (`next` ပြန်လာချက်ထိန်းသိမ်း), agent-အကူအညီမုဒ်တွင် `me?token=…&redirect=/subscription` သည်တူညီအကျိုးသက်ရောက်မှုရှိသည်။
   **အခမဲ့စမ်းသပ်ကာဧတွင် ဤအဆင့်သည်မဖြစ်ပွားပါ** — စာရင်းသွင်းပြီးနောက် ရှေ့ဆက်စာမျက်နှာတွင်တိုက်ရိုက်သွားပြီးအသုံးပြုပါ။
4. ငွေပေးချေမှုပြီးဆုံးသည် → `accountStatus` သည် `active` ဖြစ်လာသည် (**Alipay သည်ဆာဗာဘက်တွင်အလိုအလျောက်ဖွင့်သည် notify မှတစ်ဆင့်**;
   PayPal သည် Webhook မှတစ်ဆင့်ဖွင့်သည်; WeChat QR code သည်လက်နှင့်အတည်ပြုသည်; Huawei IAP သည် `activate-huawei` မှတစ်ဆင့်ဖြတ်သည်)။
   အသေးစိတ်အတွက် `payment-and-activation.md` ကိုကြည့်ပါ။

ပုံမှန်အခြေအနေတွင် အလုပ်မလုပ်သော (pending) အသုံးပြုသူများသည်အဓိကကုန်ကြမ်းများကိုခေါ်သည့်အခါ (ဖီဒ်, မြေပုံ, ဒစ်ဂျစ်တယ်လူစကားပြော, စစ်ဆင်မှုများ, စသည်) 403 ရရှိသည်;
မျှဝေသောပို့စ်လင့်များသည်ခြားနားချက် (အများပြည်သူဝင်ရောက်နိုင်ရန်ထားရှိသည်)။ အခမဲ့စမ်းသပ်ကာဧတွင် ဤပိတ်ဆို့မှုသည်ရပ်နားပြီးအရာအားလုံးပွင့်နေသည်။
## အဖြစ်များ အမှား ရှာဖွေရေး ဇယား

| ဖြစ်စဉ် | အကြောင်းရင်း | ဘာလုပ်မလဲ |

## လော့ဂ်အင် နောက်ဆက်တွဲ အချက်အလက် (အမှားရှာရာတွင် သုံးရန်)

လော့ဂ်အင်သည် **အသုံးပြုသူအမည် / အီးမေးလ် / ဖုန်းနံပါတ်** သုံးမျိုးတစ်ပါတည်း ထည့်သွင်းမှုကို ထောက်ပံ့သည် (သုံးမျိုးစလုံးအနက် မည်သည့်အရာမဆို အကောင့်အမည် အဖြစ် အသုံးပြုနိုင်)။
စကားဝှက် မေ့နေလျှင်: လော့ဂ်အင် စာမျက်နှာ →「忘记密码」(စကားဝှက် မေ့နေ) → အကောင့်ဖွင့်ထားသော အီးမေးလ် ထည့်၍ ဂဏန်း 6 လုံး အတည်ပြုကုဒ် လက်ခံရယူ → ပြန် သတ်မှတ်။

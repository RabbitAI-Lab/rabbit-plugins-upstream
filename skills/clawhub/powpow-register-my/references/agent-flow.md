# အေးဂျင့် ကိုယ်စားလုပ်ဆောင်မှု လုပ်ငန်းစဉ်နှင့် script စာချုပ် — powpow-register

SKILL.md အဆင့်များ၏ အသေးစိတ် လုပ်ဆောင်ပုံ။ command အားလုံးမှာ `node scripts/powpow-register.mjs <command ခွဲ> [parameter]` ဖြစ်၍၊ script သည် **မှီခိုမှု သုည**၊ **Node >= 18** လိုအပ်၍၊ တောင်းဆိုမှုအားလုံးသည် `https://global.powpow.online` သို့သာ သွားသည်။

## လုံခြုံရေး ဒီဇိုင်း (ဤသို့ ဒီဇိုင်းဆွဲရခြင်း အကြောင်းရင်း)

| ဒီဇိုင်း | အကြောင်းရင်း |
|---|---|
| စကားဝှက်ကို environment variable `POWPOW_REGISTER_PASSWORD` မှတစ်ဆင့်သာ ပေးပို့သည် | process ၏ command line parameter များကို တစ်စက်တည်းရှိ အခြား process များက မြင်နိုင်သည် (argv ပေါက်ကြောင်း)၊ environment variable ကို script အတွင်း ဖတ်၍ ချက်ချင်း အသုံးပြုသည် |
| စကားဝှက်ကို **state file တွင် လုံးဝ မရေး**၊ log တွင်လည်း လုံးဝ မပေါ် | state file သည် disk ပေါ်တွင် ကျန်နိုင်သည်; စကားပြောဆိုမှုအတွင်း ဖန်တီးမှု မုဒ်တွင် တစ်ကြိမ်သာ ပြသခြင်းသည် အသုံးပြုသူ သိမ်းဆည်းနိုင်ရန် အတွက် ဖြစ်သည် |
| state file ကို စနစ် ယာယီ ဖိုင်တွဲ (`os.tmpdir()/powpow-register-state.json`, 0600) တွင် သိမ်းဆည်း | email / username / nickname / token / outTradeNo ကွက်လပ် 5 ခုသာ ပါဝင်၍ `cleanup` ဖြင့် တစ်ချက်နှိပ် ရှင်းလင်းနိုင်သည် |
| agent ရရှိသော JWT ကို တရားဝင် `me?token=` endpoint ဖြင့် ဘရောက်ဇာ cookie သို့ လဲလှယ်သည် | Harmony WebView အတွက် ဒီဇိုင်းဆွဲထားသော ပလက်ဖောင်း ၏ တရားဝင် တံတား; signature စစ်ဆေးမှုတွင် signature + သက်တမ်းကုန်ရက်သာ စစ်၍ device fingerprint နှင့် မချည်နှောင်၊ အသုံးပြုသူ ၏ ဘရောက်ဇာတွင် အသုံးပြုနိုင်သည် |
| ငွေပေးချေရေးတွင် create-order / query / ကောင်တာ ဖွင့်ခြင်းသာ လုပ်သည် | ငွေပေးချေခြင်း လုပ်ငန်းနှင့် ငွေပေးချေရေး အထောက်အထားသည် အမြဲ အသုံးပြုသူနှင့် Alipay တရားဝင် ကောင်တာ ကြားတွင် ရှိ၍ agent လက်ထဲ မရောက် |

## command အသုံးပြုပုံ အညွှန်း

| command | အဓိက parameter | လုပ်ငန်း / အချိန် |
|---|---|---|
| `status` | —— | လုပ်ငန်းစဉ် တိုးတက်မှု ကြည့်ရှု (state file ဖတ်); စကားပြောဆိုမှု အပြတ်ပြီးနောက် ဤအရာကို အရင် လုပ်ဆောင်ပါ |
| `gen-password` | —— | စာလုံး 24 လုံး ခိုင်မာသော စကားဝှက် ဖန်တီး (စာလုံးကြီး/ငယ်+ဂဏန်း ပါဝင်)၊ stdout တွင် **ဤတစ်ကြိမ်သာ** ပြသ |
| `prepare-suggest` | `--username --nickname --email` | အတည်ပြုပြီးသော အချက်အလက်ကို state file တွင် မှတ်တမ်းတင် (နောက်ပိုင်း register တွင် ထပ်မံ ပေးပို့စရာ မလို) |
| `send-code` | `--email` | ပလက်ဖောင်းကို ဂဏန်း 6 လုံး အတည်ပြုကုဒ် ပို့စေသည် (မိနစ် 10 သက်တမ်း၊ စက္ကန့် 60 cooldown) |
| `register` | `--code` (မဖြစ်မနေ); `--username --nickname --avatar --phone` (ရွေးချယ်နိုင်၊ state file တွင် ရှိလျှင် ပေးပို့စရာ မလို) | pending အကောင့် ဖန်တီး; စကားဝှက်ကို `POWPOW_REGISTER_PASSWORD` environment variable မှတစ်ဆင့်; အောင်မြင်လျှင် JWT ကို state file တွင် အလိုအလျောက် သိမ်းဆည်း |
| `login-link` | `--target pending` သို့မဟုတ် `--target home` | တစုံးခလုတ်နှိပ်ဝင်ခြင်းလင့်ဖန်တီးသည် (နှစ်လင့်ဒီဇိုင်း၊ အောက်တွင်ကြည့်ပါ) |
| `create-order` | `--package monthly\|quarterly\|yearly` (Alipay မူလ) <br>`--provider alipay\|paypal` | ငွေပေးချေမှု အော်ဒါ ဖန်တီး; Alipay က ငွေပေးချေရေး စာမျက်နှာ ဖိုင် လမ်းကြောင်း + outTradeNo ပြန်ပေး; PayPal က ခွင့်ပြုချက် စာမျက်နှာဖိုင် လမ်းကြောင်း + subscriptionId ပြန်ပေး (state file တွင် အလိုအလျောက် မှတ်တမ်းတင်) |
| `query` | —— | အော်ဒါ/စာရင်းသွင်းမှု အခြေအနေ စုံစမ်း။ Alipay: `paid / pending / closed / unknown`; PayPal: `ACTIVE / PENDING`; စက္ကန့် 10–15 တိုင်း polling |
| `refresh-login` | စကားဝှက်ကို environment variable မှတစ်ဆင့် | ထပ်မံ လော့ဂ်အင်၍ **JWT အသစ်** လဲလှယ် (စာရင်းသွင်းမှု ကြေညာချက် NONE မှ ACTIVE သို့ ပြောင်း)၊ ငွေရောက်မှု ပြီးလျှင် မဖြစ်မနေ လုပ်ရမည် |
| `whoami` | —— | state file ရှိ token ဖြင့် အကောင့်နှင့် စာရင်းသွင်းမှု အခြေအနေ စုံစမ်း (အသက်ဝင်မှု အာနိသင် ရှိမရှိ အတည်ပြု) |
| `cleanup` | —— | state file ဖျက် (အဆုံးတွင် မဖြစ်မနေ လုပ်ရမည်) |

**environment variable ဖြင့် ပေးပို့ခြင်း** (စကားဝှက်သည် command line ပေါ်သို့ လုံးဝ မရောက်):

```bash
# bash / zsh / WSL
POWPOW_REGISTER_PASSWORD='<စကားဝှက်>' node scripts/powpow-register.mjs register --code 123456
# PowerShell
$env:POWPOW_REGISTER_PASSWORD = '<စကားဝှက်>'; node scripts/powpow-register.mjs register --code 123456
# cmd
set POWPOW_REGISTER_PASSWORD=<စကားဝှက်> && node scripts/powpow-register.mjs register --code 123456
```

## နှစ်လင့်နည်းစနစ် (ပင်မဒီဇိုင်း)

ပလက်ဖောင်ဝင်မှုအခြေအနေသည် HttpOnly ကူခီဖြစ်ပြီး agent သည် ဘရောင်ဇာအတွက်တိုက်ရိုက်စိုက်ဝင်မရပေ; တံတားမှာ တရားဝင်
`/api/auth/me?token=<JWT>&redirect=<ဆိုက်တွင်းလမ်းကြောင်း>` ချက် — လက်မှတ်စစ် → session အလိုအလျောက်ဖန်တီး
ခြင်း → `Set-Cookie: powpow_token` (HttpOnly / SameSite=Lax / 7 ရက်) → လမ်းကြောင်းအတည်ပြု
(တစ်လှမ်းးမှစရမည်, `//` နှင့် နောက်ပြန်များခွင့်မပြု, ဖတ်ပြီးနောက် တူညီဇာအစီအစဉ်ဖြစ်ရမည်) → 307 ယာယီလမ်းကြောင်းပြန်ချက် ဦးတည်စာမျက်နှာသို့။

လင့်ဦးတည်ချက်နှစ်ခုရှိသည် — **ဦးစွာရှေ့ဆက်ဖန်တီးပါ၊ ထို့နောက်အသုံးပြုသူဆင်းသည့်နေရာအရ pending ကိုဖြတ်မည်လာမလာဆုံးဖြတ်ပါ** —

- **ရှေ့ဆက်လင့် (မူရင်းပို့ခြင်း, `--target home` → `/` ပေါ်ဆင်း)** — စာရင်းသွင်းမှုအောင်မြင်သည့်နောက်ချက်ချင်းဖန်တီးပြီးအသုံးပြုသူထံပို့သည်။
  အခမဲ့စမ်းသပ်ကာဧတွင် အသုံးပြုသူသည်ရှေ့ဆက်စာမျက်နှာတွင်တိုက်ရိုက်သွားသည်, အပြည့်အစုံအသုံးပြုနိုင်; **အသုံးပြုသူနှိပ်သော်လည်းစာရင်းသွင်းစာမျက်နှာတွင်ဆင်းပါက အခမဲ့စမ်းသပ်ကာဧကုန်ဆုံးသည်** — ငွေပေးချေမှုလမ်းကြောင်းသို့ပြောင်းပါ (အောက်တွင်ကြည့်ပါ), စာမျက်နှာအပ်ဒိတ်မလိုဘဲ စာရင်းသွင်းမှုပြန်မလုပ်ရဘဲ။
- **pending လင့် (ငွေပေးချေမှုလမ်းကြောင်းတွင်အသုံးပြုခြင်း, `--target pending` → `/subscription` ပေါ်ဆင်း)** —
  အသုံးပြုသူဘရောင်ဇာသည်အခြမ်းဝင်ခြင်းအခြေအနေသို့ဝင်သည် — subscription စာမျက်နှာနှင့်ငွေပေးချေမှုပြန်လာစာမျက်နှာမြင်နိုင်ပြီးလုပ်ဆောင်နိုင်, ငွေပေးချေမှုရောက်သည့်နောက်
  ACTIVE တောင်းဆိုမှုပါသော JWT အသစ်နှင့်လဲလှယ်ရန် `refresh-login` ကိုchạy ပြီး အပြည့်အစုံအဖွဲ့ဝင်အခြေအနေးအတွက်ရှေ့ဆက်လင့်ကိုထပ်ပို့ပါ။

## အပြည့်အစုံအစဉ်

### အမြန်လမ်းကြောင်း (အခမဲ့စမ်းသပ်ကာဧတွင် — များစွာသောအခြေအနေများ)

```
1.  status                          # ပတ်ဝန်းကျင်ကိုယ်တိုင်စစ်ဆေးမှု
2.  (အဆင့် 2 စကားပြောဆိုမှုဖြင့်အချက်အလက်အတည်ပြုခြင်း, စကားဝှက်တစ်ခုချင်း; ဖန်တီးမုဒ် — gen-password → အသုံးပြုသူချက်ချင်းသိမ်းဆည်းရန်)
3.  prepare-suggest --username U --nickname N --email E
4.  send-code --email E             # → အသုံးပြုသူသည် အင်ဗောက်စ်တွင်ကုဒ်စစ်ဆေးသည် (စကားပြောဆိုမှုမှထွက်သည့်တစ်ခုတည်းသောအချိန်)
5.  POWPOW_REGISTER_PASSWORD=*** register --code 123456 [--avatar pic.jpg]
6.  login-link --target home        # → အသုံးပြုသူထံလင့်ပို့ပါ, တစုံးခလုတ်နှိပ်ပြီးရှေ့ဆက်စာမျက်နှာတွင်ရှိသည်
7.  (အသုံးပြုသူဝင်ပြီးဟုအတည်ပြု) → တိုက်ရိုက်ပိတ်ပါ — cleanup + အကောင့်ကတ် + ပထမအဆင့်လမ်းညွှန်ခြင်း
```

### ငွေပေးချေမှုလမ်းကြောင်း (အသုံးပြုသူအဖွဲ့ဝင်လိုသည့်အခါ, သို့မဟုတ် အခမဲ့စမ်းသပ်ကာဧကုန်ဆုံးသည့်အခါ)

```
1–5. အမြန်လမ်းကြောင်းတူညီသည် (စာရင်းသွင်းမှုအောင်မြင်သည့်နောက် အခြေအနေတွင် တိုကင်ရှိပြီး)
6.  login-link --target pending     # → အခြမ်းဝင်ခြင်းလင့်, ငွေပေးချေမှုပြန်လာစာမျက်နှာကိုလုပ်ဆောင်နေစေရန်
7.  (အသုံးပြုသူငွေပေးချေမှုနည်းလမ်းရွေး)
    # Alipay: create-order --package monthly|quarterly|yearly
    # PayPal: create-order --provider paypal
8.  start <ငွေပေးချေမှုစာမျက်နှာဖိုင်>       # Windows; macOS သည် open, Linux သည် xdg-open
    # → အသုံးပြုသူသည် Alipay/PayPal ကာရှီးတွင် ငွေပေးချေမှုခွင့်ပြုချက်ပြီးစီးသည် (စကားပြောဆိုမှုမှထွက်သည်)
9.  query (10–15စက္ကန့်တိုင်း) ပေ / ACTIVE မချင်း
10. refresh-login                   # ACTIVE တောင်းဆိုမှုပါသော JWT အသစ်နှင့်လဲလှယ်ခြင်း
11. login-link --target home        # → အသုံးပြုသူထံအပြည့်အစုံအဖွဲ့ဝင်လင့်ပို့ပါ
12. whoami                          # subscriptionStatus: ACTIVE အတည်ပြုခြင်း (ရွေးချယ်နိုင်)
13. cleanup                         # အခြေအနေဖိုင်ရှင်းလင်းခြင်း
```
## command → ပလက်ဖောင်း API ကုန်းကတ်

| script command | ပလက်ဖောင်း interface |
|---|---|
| `send-code` | `POST /api/auth/register/send-code` |
| `register` | `POST /api/auth/register` (multipart၊ ပရိုဖိုင်ပုံ တိုက်ရိုက်တင်) |
| `login-link` | `GET /api/auth/me?token=…&redirect=…` (လင့်ခ် ကိုယ်တိုင်၊ အသုံးပြုသူ နှိပ်သည့်အခါ အာနိသင် ရှိသည်) |
| `create-order` | `POST /api/payment/alipay/create-order` (Bearer, Alipay)<br>`GET /api/subscription/plans` + `POST /api/subscription/create` (Bearer, PayPal) |
| `query` | `GET /api/payment/alipay/query?outTradeNo=…` (Bearer, Alipay)<br>`GET /api/subscription/create` (Bearer, PayPal) |
| `refresh-login` | `POST /api/auth/login` (`{step:1, username, password}`) |
| `whoami` | `GET /api/auth/me?token=…` |

စည်းမျဉ်း ရင်းမြစ်: အကောင့်ဖွင့် ဖိလ်ဒ်များနှင့် အကြိမ်ရေ ကန့်သတ်ချက်များကို `registration-flow.md` တွင် ကြည့်ပါ; အစီအစဉ်နှင့် အသက်ဝင်မှု လမ်းကြောင်းကို
`payment-and-activation.md` တွင် ကြည့်ပါ (နှစ်ခုစလုံးတွင် ပလက်ဖောင်း ရင်းမြစ် ဖိုင် ညွှန်းထားသည်)။

## script အဆင့် အမှား ကိုင်တွယ်မှု

| ဖြစ်စဉ် | ကိုင်တွယ်ပုံ |
|---|---|
| `Node 版本过低` (Node ဗားရှင်း အလွန်နိမ့်) | လမ်းညွှန်သက်သက် မုဒ်သို့ ပြန်ကူး၍ အတင်း မကြိုးစားပါနှင့် |
| ကွန်ရက် အမှား / အချိန်ကုန် | တစ်ကြိမ် ထပ်ကြိုးစား; မအောင်မြင်လျှင် အသုံးပြုသူအား ကွန်ရက် စစ်ဆေးစေပြီး ဆက်လက် (state file ရှိနေသေး၍ `status` မှ ပြန်စ၍ ပြန်ဆွဲနိုင်) |
| register တွင် business အမှား (用户名已存在 စသည်) | SKILL.md အဆင့် 5 ဇယားအတိုင်း ကိုင်တွယ်၊ **အတည်ပြုကုဒ် ထပ်ပို့စရာ မလို** (မိနစ် 10 အတွင်း ဆက်လက် တကျိုပ် ရှိနေ) |
| register တွင် `邮箱验证码错误或已过期` (အီးမေးလ် အတည်ပြုကုဒ် မှားယွင်း သို့ သက်တမ်းကုန်) | အချိန်ကုန်လျှင် → `send-code` ထပ်မံ ပေးပို့ |
| `create-order` ပြီးနောက် အသုံးပြုသူက ငွေပေးချေရေး စာမျက်နှာ ပိတ်လိုက် | `create-order` ကို တိုက်ရိုက် ထပ်လုပ် (အဟောင်း အော်ဒါ နာရီ 2 အကြာ အလိုအလျောက် ပိတ်; PayPal PENDING စာရင်းသွင်းမှု နာရီ 1 အကြာ သက်တမ်းကုန်) |
| `create-order --provider paypal` က 409 ပြန်လျှင် | မပြီးသေးသော PayPal စာရင်းသွင်းမှု ရှိနေ၍၊ နာရီ 1 စောင့်၍ သက်တမ်းကုန်စေ သို့မဟုတ် ဘရောက်ဇာတွင် အဟောင်း ခွင့်ပြုချက်ကို ပြီးစေပါ |
| `query` ဆက်တိုက် pending / PENDING | အသုံးပြုသူက ငွေမပေးရသေးပါနိုင်; တစ်ခေါက် မေးပါ။ တကယ် ပေးထားလျှင် → payment-and-activation.md ၏ အမှားရှာ ဇယားအတိုင်း ဆက်ပါ |
| အသုံးပြုသူရှေ့ဆက်လင့်ကိုနှိပ်သော်လည်းစာရင်းသွင်းစာမျက်နှာတွင်ဆင်း | အခမဲ့စမ်းသပ်ကာဧကုန်ဆုံးသည် → ငွေပေးချေမှုလမ်းကြောင်းသို့ပြောင်းပါ — `login-link --target pending` → နည်းလမ်းရွေး → `create-order` |
| `refresh-login` 403 `pending_payment` | အခမဲ့စမ်းသပ်ကာဧကုန်ဆုံးပြီးငွေပေးချေမှုမရောက်သေး — အဆင့် 9 သို့ပြန်ပြီးဆက်လက်စစ်ဆေးပါ, သို့မဟုတ် အသုံးပြုသူငွေပေးချေမှုပြီးစီးသည်လာမလာအတည်ပြုပါ |
| state file ပျောက်ဆုံး (လက်မတော် ဖျက်မိ / စက် ပြောင်း) | `whoami`/`refresh-login` အသုံးမပြုနိုင်; လင့်ခ် 1 ဖွင့်ခဲ့သော ဘရောက်ဇာအတွင်း စာရင်းသွင်းမှု စာမျက်နှာကို refresh လုပ်၍ အခြေအနေ အတည်ပြုစေပါ၊ သို့မဟုတ် (Web မုဒ်) ထပ်မံ လော့ဂ်အင် ပြုလုပ်စေပါ |

## ပြန်ကူး မုဒ် (လမ်းညွှန်သက်သက်)

အောက်ပါ အခြေအနေ တစ်ခုခု ဖြစ်လျှင် ချက်ချင်း v1 စတိုင် လမ်းညွှန်သက်သက် မုဒ်သို့ ပြန်ကူး၍ script နှင့် ဆက် မနှောင့်ယှက်ပါနှင့်:

- Node >= 18 မရှိ သို့မဟုတ် script သည် တူညီသော အမှားကို ဆက်တိုက် နှစ်ကြိမ် ရှုံးနိုင်;
- အသုံးပြုသူက "ကျွန်ုပ် ကိုယ်တိုင် Web ပေါ်တွင် လုပ်မည်" ဟု ထင်ရှားစွာ ပြောသည်;
- ကုမ္ပဏီ/စက်ပစ္စည်း မူဝါဒက script ၏ ကွန်ရက် ချိတ်ဆက်မှုကို ကန့်သတ်သည်။

ပြန်ပြီးနောက် — စာရင်းသွင်းစာမျက်နှာ https://global.powpow.online/register ပေးပါ (အခမဲ့စမ်းသပ်ကာဧတွင် ဝဘ်စာရင်းသွင်းမှုသည်တူညီစေရေးမြန်; စာရင်းသွင်းမှုလိုအပ်သည့်အခါ subscription စာမျက်နှာ https://global.powpow.online/subscription လည်းပေးပါ), `registration-flow.md` စည်းမျဉ်းများနှင့်အညီရှာဖွေဖယ်ရှားပါ, အသံတူညီစေထားပါ, နှင့်အလှည့်တိုင်းကို "နောက်တစ်ဆင့်" ဘလောက်နှင့်အဆုံးသတ်ပါ။
https://global.powpow.online/subscription ကို ပေး၍ `registration-flow.md` ၏ စည်းမျဉ်းများအတိုင်း အမှားရှာ လိုက်ပါပေး၊
အသုံးအနှုန်း မပြောင်းဘဲ တုံ့ပြန်ချက် တိုင်းကို "နောက်တစ်ဆင့်" အပိုင်းဖြင့် အပြီးအစီး လုပ်ပါ။

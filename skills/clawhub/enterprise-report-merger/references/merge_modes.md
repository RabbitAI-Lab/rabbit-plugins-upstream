# 合并模式参考文档

本文档详细说明 `merge_reports.py` 支持的三种合并模式及其适用场景、参数配置和注意事项。

---

## 模式一：简单拼接（concat）

### 适用场景
- 多个部门提交的相同结构报表需要纵向堆叠
- 多个月份/季度的数据需要合并到一个文件
- 各来源文件的列结构一致（列名和列数相同）

### 工作原理
以第一个文件的表头为基础，将所有文件的数据行按顺序追加。不进行列匹配或数值聚合。

### 命令示例

```bash
python merge_reports.py merge \
  --input 部门A.xlsx 部门B.xlsx 部门C.xlsx \
  --mode concat \
  --output 合并结果.xlsx \
  --source-labels "部门A" "部门B" "部门C"
```

### 参数说明
| 参数 | 说明 |
|------|------|
| `--input` | 多个输入文件路径 |
| `--mode concat` | 指定简单拼接模式 |
| `--output` | 输出 Excel 文件路径 |
| `--source-labels` | （可选）自定义各来源标签，仅用于日志记录 |
| `--header-row` | （可选）表头所在行号，默认为 1 |
| `--sheet` | （可选）指定读取的工作表名 |

### 注意事项
- 如果不同文件的列数不一致，脚本会自动补齐或截断，并输出警告
- 表头始终取第一个文件，不会合并不同文件的表头
- 空行会被自动跳过

## 模式二：按关键字合并（key）

### 适用场景
- 多个子公司报表按"科目代码"或"科目名称"对齐合并
- 不同来源的数据有共同的键值列（如员工工号、产品编号、科目代码）
- 需要将多个数据源横向拼接，而非纵向堆叠

### 工作原理
1. 在每个报表中找到指定的键值列（如"科目代码"）
2. 收集所有不重复的键值，保持出现顺序
3. 对每个键值，从各来源中提取对应的行数据
4. 输出表头格式为 `{来源标签}_{列名}`，便于区分数据来源

### 命令示例

```bash
python merge_reports.py merge \
  --input 子公司A.xlsx 子公司B.xlsx \
  --mode key \
  --key-column "科目代码" \
  --output 合并对照表.xlsx \
  --source-labels "子公司A" "子公司B"
```

### 输出格式
| 科目代码 | 子公司A_本期金额 | 子公司A_上期金额 | 子公司B_本期金额 | 子公司B_上期金额 |
|----------|-----------------|-----------------|-----------------|-----------------|
| 1001     | 1,200,000       | 1,100,000       | 800,000         | 750,000         |
| 1002     | 500,000         | 480,000         | 300,000         | 290,000         |

### 参数说明
| 参数 | 说明 |
|------|------|
| `--key-column` | **必需**。键值列名（支持模糊匹配） |
| `--source-labels` | 自定义来源标签，用于输出列名前缀 |
| `--aggregation` | 聚合方式：sum/avg/max/min，默认 sum（当同一来源有多个相同键值时） |

### 键值列模糊匹配
如果精确匹配失败，脚本会尝试模糊匹配（检查键值列名是否包含在目标列名中）。例如：
- 指定 `--key-column "科目"` 可以匹配到"科目代码"、"科目名称"等列

## 模式三：合并报表 + 抵销分录（consolidation）

### 适用场景
- 母子公司集团合并财务报表
- 需要消除内部交易（内部应收应付、内部销售、内部投资等）
- 编制合并资产负债表、合并利润表

### 工作原理
1. **第一步：加总合并** — 将各子公司的数值按科目加总，得到简单合并数
2. **第二步：抵销调整** — 根据提供的抵销分录，调整相关科目的合并金额
   - 借方方向：减少该科目金额
   - 贷方方向：增加该科目金额

### 命令示例

```bash
python merge_reports.py merge \
  --input 母公司.xlsx 子公司A.xlsx 子公司B.xlsx \
  --mode consolidation \
  --key-column "科目代码" \
  --elimination-entries 抵销分录.json \
  --output 合并报表.xlsx \
  --source-labels "母公司" "子公司A" "子公司B"
```

### 抵销分录 JSON 格式

```json
[
  {
    "科目": "应收账款",
    "方向": "借",
    "金额": 500000,
    "说明": "抵销母公司对子公司A的内部应收账款",
    "列": "期末余额"
  },
  {
    "科目": "应付账款",
    "方向": "贷",
    "金额": 500000,
    "说明": "抵销子公司A对母公司的内部应付账款",
    "列": "期末余额"
  },
  {
    "科目": "营业收入",
    "方向": "借",
    "金额": 300000,
    "说明": "抵销内部销售收入"
  },
  {
    "科目": "营业成本",
    "方向": "贷",
    "金额": 280000,
    "说明": "抵销内部销售成本"
  }
]
```

### 字段说明
| 字段 | 说明 |
|------|------|
| `科目` | 要抵销的科目名称（支持模糊匹配，如"应收账款"可匹配"应收账款—子公司A"） |
| `方向` | `"借"`（减少资产/费用，增加负债/收入）或 `"贷"`（相反） |
| `金额` | 抵销金额（正数） |
| `说明` | 抵销说明（可选，用于审计追踪） |
| `列` | 指定调整的数值列名（可选，不指定则调整第一个数值列） |

### 输出格式
输出 Excel 包含两个工作表：
1. **合并结果**：加总并抵销后的合并报表
2. **抵销分录**：所有已应用的抵销分录记录（审计用）

### 注意事项
- 抵销方向遵循会计准则：资产类科目借方减少、贷方增加；负债和收入类相反
- 如果抵销科目未找到匹配项，脚本会输出警告但不会中断
- 抵销金额直接在合并总数上调整，不保留各子公司的单独金额

## 通用参数

以下参数适用于所有合并模式：

| 参数 | 说明 |
|------|------|
| `--header-row` | Excel 表头行号（1-based），默认 1。适用于有标题行或说明行的报表 |
| `--sheet` | 指定读取的工作表名称（默认第一个） |
| `--pdf-pages` | PDF 提取的页码范围，如 `"0-5"` 或 `"0,2,4"` |
| `--pdf-table-index` | 仅提取指定索引的表格（PDF 每页可能有多个表格） |
| `--word-template` | Word 模板路径，合并后自动填充模板 |
| `--word-output` | Word 输出路径 |
| `--mapping` | Word 模板填充映射 JSON 文件 |

## 选择合并模式的决策指南

```
各来源报表的列结构是否一致？
├─ 是 → 是否需要按行匹配（而非简单堆叠）？
│      ├─ 否 → 使用 concat（简单拼接）
│      └─ 是 → 使用 key（按关键字合并）
└─ 否 → 是否有共同的键值列？
       ├─ 是 → 是否需要处理内部交易抵销？
       │      ├─ 否 → 使用 key（按关键字合并）
       │      └─ 是 → 使用 consolidation（合并报表+抵销）
       └─ 否 → 需要人工预处理或自定义脚本
```

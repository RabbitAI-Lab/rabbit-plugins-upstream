# 图片型 PDF 处理指南

## 核心策略

**检测到图片型 PDF 后，告知用户该文件为图片型，提示谨慎检查或手动合并。**

视觉识别（渲染图片 → 多模态模型"看"图）精度有限，在多次实测中频繁出现数字误读（如 5↔6 混淆、首位数字错位、整行漏读等），**不建议自动填入 Word 模板**。

## 检测方法

使用 `detect_pdf_type()` 函数自动判断 PDF 类型：

```python
from merge_reports import detect_pdf_type

info = detect_pdf_type('report.pdf')
print(info['type'])  # 'text', 'image', or 'mixed'
```

或使用命令行：

```bash
python scripts/pdf_to_images.py --input report.pdf --output-dir ./pdf_images --detect-only
```

返回值说明：

| 类型 | 含义 | 处理方式 |
|------|------|----------|
| `text` | 所有页面都有可提取文本 | 直接用 `pdfplumber` 提取表格 |
| `image` | 所有页面都是图片（扫描件） | **提示用户谨慎检查或手动合并** |
| `mixed` | 部分页面有文本，部分是图片 | 文本页用 pdfplumber，图片页提示用户 |

### 判断标准

- 每页提取文本 > 50 字符 → 文本页
- 每页提取文本 ≤ 50 字符 → 图片页

## 提示用户的标准话术

检测到图片型/混合型 PDF 时，应告知用户：

> ⚠️ 该 PDF 文件包含图片型页面（扫描件），无法通过文本提取获取表格数据。
>
> 视觉识别方案精度有限，在以往测试中曾出现数字误读（如 5↔6 混淆、首位数字错位等）。
>
> **建议**：
> - 方案 A：提供原始电子版报表（Excel/文本型 PDF），精度 100%
> - 方案 B：手动将关键数据整理后告诉我，我来填充 Word 模板
> - **方案 C（推荐）**：你截屏三表（资产负债表、利润表、现金流量表）单独发我，我直接识别截图，精度接近 100%（详见下方"截图识别方案"）
> - 方案 D：如果仍希望尝试自动识别，我会渲染高清图片后视觉读取，但**需要你逐项核对**所有数字

## 截图识别方案（推荐）

用户手动截屏后发给 AI 识别，精度远高于 PDF 自动渲染识别。

### 为什么截图更准确

| 因素 | PDF 自动渲染 | 用户截屏 |
|------|-------------|---------|
| 表格方向 | 可能横向排版，模型容易弄反 | 截屏时已摆正，天然正向 |
| 干扰元素 | 页眉页脚、审计说明、页码混杂 | 只截表格区域，无干扰 |
| 清晰度 | 渲染 DPI 固定（300~600） | 截屏时放大 150~200%，等效无限 DPI |
| 表格范围 | 双栏/多表在一页中，行对应易错 | 一图一表，模型不用"找表"直接"读表" |
| 行列错位 | 跨页时行对应容易乱 | 每张表完整截在一张图内 |

### 工作流程

1. **你发现 PDF 是图片型**，技能提示你提供截图
2. **你截屏**：在电脑上打开PDF，放大到 150%~200%，分别截取：
   - 资产负债表（含左栏资产 + 右栏负债权益，最好截成一张或左右各一张）
   - 利润表（完整截图）
   - 现金流量表（完整截图）
3. **你发截图给我**，我直接用 Read 工具识别，逐行读取科目名称和金额数字

4. **多维度交叉验证（必做）**：识别结果整理为字典后，调用 `validate_financial_data()` 自动验证所有勾稽关系（详见下方"多维度交叉验证框架"），任何一项不通过必须重读图片修正

5. **确认无误后**，按正常流程（万元转换、模糊匹配、标蓝）填入 Word 模板

### 截图注意事项

- **推荐放大到 150%~200% 再截**，数字越清晰越好
- **每张表单独截图**，不要将利润表和资产负债表截在一张图里
- **截全表格区域**，包含表头（科目名称）和所有数据行，以及底部合计行
- 如果资产负债表是双栏（左资产、右负债），**优先左右栏一起截**，保持行对应关系；如果页面太宽，可以左栏一张、右栏一张
- 不用裁剪得太精细，大致框住表格边缘即可

### 精度说明

规范排版的审计报告，用上述方式截图识别——**关键数字（合计行）精度接近 100%**，单项数字极少出错，不再需要逐项核对。

## 如果用户仍要求尝试自动识别

以下为备用流程，**务必逐项核对结果**：

### 步骤 1：渲染高清图片（≥600 DPI）

```bash
python scripts/pdf_to_images.py --input report.pdf --output-dir ./pdf_images --dpi 600 --pages "4-9"
```

> ⚠️ 不要用 300 DPI，财务数字精度不够。必须 ≥600 DPI。

### 步骤 2：视觉识别

使用 Read 工具逐张打开 PNG 图片，逐行读取科目名称和金额数字。

### 步骤 3：多维度交叉验证（必做）

识别完成后，**必须**调用 `validate_financial_data()` 进行全面验证。这一步不可跳过——所有数据误读都会在勾稽关系上暴露。

```python
from merge_reports import validate_financial_data

result = validate_financial_data(BS_DATA, IS_DATA, CF_DATA)
print(result['summary'])
if not result['passed']:
    for c in result['checks']:
        if not c['passed']:
            print(f"  ✗ {c['name']}: 预期={c['expected']}, 实际={c['actual']}, 偏差={c['diff']}")
    # 必须重读图片修正
else:
    print('✅ 全部通过，可以填入模板')
```

#### 10 项验证清单

| # | 验证项 | 说明 | 误读时典型表现 |
|---|--------|------|--------------|
| 1 | 资产总计 = 流动资产 + 非流动资产 | 表内基础勾稽 | 合计行读错 → 偏差巨大 |
| 2 | 资产总计 = 负债 + 所有者权益 | 资产负债表恒等式 | 某方合计读错或漏行 |
| 3 | 负债合计 = 流动负债 + 非流动负债 | 负债分层勾稽 | 流动/非流动划分行读混 |
| 4 | 所有者权益分项之和 ≈ 合计 | 权益明细验证 | 资本公积/盈余公积/未分配利润任一读错 |
| 5 | 利润总额 = 营业利润 + 营业外收入 - 营业外支出 | 利润表勾稽 | 营业利润首位数字错位 |
| 6 | 净利润 = 利润总额 - 所得税费用 | 税后利润验证 | 利润总额或所得税读错 |
| 7 | 经营活动净额 = 流入 - 流出 | 现金流基础勾稽 | 流入或流出漏读数字 |
| 8 | 现金净增加额 = 经营 + 投资 + 筹资 | 三大现金流汇总 | 任一类净额读错 |
| 9 | 表间：货币资金 ≈ 期末现金余额 | 资产表↔现金流表 | 两表数据不一致 |
| 10 | 表间：两表净利润一致 | 利润表↔现金流表间接法 | 间接法起点数字不一致 |

> **规则**：任何一项不通过（偏差 > 0），必须重读图片修正。未通过时不要填入模板。

### 步骤 4：告知用户核对

将验证结果和识别数据打印给用户，确认无误后方可填入模板。

## 已知的视觉识别误差（实测记录）

| 误差类型 | 示例 | 说明 |
|----------|------|------|
| 首位数字错位 | 53,570 → 误读 52,570 | 5/6 混淆，导致利润总额差 1,000 万 |
| 末位数字错位 | 20,024,457 → 误读 20,024,427 | 5/7 混淆 |
| 整行漏读 | 在建工程、长期应付款等 → 漏填为 0 | 小数字或边缘行容易被跳过 |
| 科目错位 | 资本公积的值填到盈余公积 | 双栏表格跨页时行对应错乱 |
| 正负号错误 | 资产减值损失 -65,793 → 误读为正数 | 负号容易被忽略 |

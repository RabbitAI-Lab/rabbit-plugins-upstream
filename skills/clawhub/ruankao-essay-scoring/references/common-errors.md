# 常见错误与故障排查

评分过程中出现偏差时的对照表。「常见错误」是评分结论层面的坑，「故障排查」是执行流程层面的坑，两者互补。

## 常见错误

| 错误 | 问题 | 解决 |
|------|------|------|
| 未提供论题直接求评分 | 只贴论文不提供论题，无法准确判断"切合题意" | 追问：请提供论题原文（含三个子问题） |
| 正文低于 2000 字（硬伤） | 正文绝对不得低于 2000 字，低于则显得无内容 | 补充项目背景细节、技术实施过程、效果数据至 2000-2500 字 |
| 正文超出 2500 字 | 评分按 2000-2500 字判定，超出即扣分 | 精简论点，重点保留 2-3 个分论点；练习写作可放宽到 3000 字左右 |
| 漏答子问题 | 试题有三个子问题，只回答了 2 个 | 逐项核对子问题是否都有回应，漏答一个扣 6-8 分 |
| 实践性不足，缺乏量化数据 | 只介绍技术方案，没有项目规模/效果数据 | 补充日活/QPS、性能提升百分比等量化指标 |
| 摘要缺失或字数不足 | 摘要少于 120 字直接不及格 | 引导用户改用 ruankao-essay-writing 技能的摘要模板补充 |
| 摘要超过 300 字 | 摘要上限 300 字 | 压缩背景铺垫，只保留项目背景 + 中心论点 + 效果 |
| 口语化表达严重 | 使用"然后""所以说"等口语化连接词 | 将口语化表达改为规范书面语 |
| 修改后重新评分无对比 | 用户修改后重评，未对比前后版本进步 | 对比修改前后版本，说明改进点和仍需改进处 |
| 论文七问未答全 | 缺选型论证（Q2）、缺问题与解决（Q5）、缺效果数据（Q6）等 | 按"论文七问核查"逐项定位缺失，在改进方案中给出补写指导 |
| 无取舍（trade-off）表述 | 只堆技术不写"为达成 X 牺牲了 Y"，缺架构思维 | 在分论点"动作"部分与总结中补明确取舍，维度二可提一档 |
| 结构失衡：背景过长、核心段过薄 | 背景超 450 字，核心段不足 1200 字，重心倒置 | 维度五扣 1-2 分，建议压缩背景、把字数还给核心段 |
| 缺少"问题与解决"段 | 全文只讲方案不讲实施困难，真实感不足 | 维度五扣 1-2 分，建议补 2 个小问题，每个约 150 字 |
| 空话套话、纯理论 | 大段背书式理论、万能句式、无项目实践细节 | 定位套话段落，指导补充项目专属做法与量化数据（删段测试排查） |
| 分论点误用排查式四步 / 全文四步化 | 把分论点写成"问题→原因→处理→结果"，或全文套四步，架构论述被稀释、trade-off 取舍无处安放 | 分论点改回论证式四步（理论→场景→动作含取舍→结果）；复盘式四步链仅保留在"问题与解决"小段，详见 writing 技能的"两套四步对照表" |

## 故障排查

| 问题 | 检查项 | 解决方案 |
|------|--------|---------|
| 无法评分（未提供论题） | 是否提供了论题原文？ | 追问论题原文（含三个子问题），再执行评分 |
| 论文字数计算不准 | 是否按中文字符统计方法计算？ | 使用 `len([c for c in text if '\u4e00' <= c <= '\u9fff'])` 统计 |
| 段落字数分布未核查 | 是否只看总字数没看结构？ | 按配额核查：背景 400-450 / 核心段 1200-1400 / 问题与解决 300-350 / 总结 250-300 |
| "切合题意"维度得分低 | 是否漏答子问题？ | 重新审题，将每个子问题映射到正文段落 |
| "实践性"维度得分低 | 是否缺乏量化数据？分论点是否误用了问题链写法（应改为论证式四步）？ | 补充项目规模数据、实施效果数据；分论点按"理论→场景→动作含取舍→结果"改写 |
| "文字表达能力"维度得分低 | 是否有口语化表达？ | 按书面化表达要求修改 |
| 评分报告格式不规范 | 是否按评分输出模板输出？ | 按 `references/report-template.md` 的格式输出 |
| 修改后重新评分无对比 | 是否对比了前后版本？ | 对比修改前后的版本，说明进步和仍需改进的地方 |

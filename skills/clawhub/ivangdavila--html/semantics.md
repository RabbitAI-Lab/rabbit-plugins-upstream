# Semantics — Choosing the Element That Means It

The question is never "which tag looks right" but "what is this thing, and who needs to know". Assistive tech, browser features, reader modes, and future parsers all read the answer.

**Contents:** [The Map](#the-map) · [Landmarks](#landmarks) · [Headings Are a Tree](#headings-are-a-tree) · [`section` vs `article` vs `div`](#section-vs-article-vs-div) · [Lists](#lists) · [Text-Level Semantics](#text-level-semantics) · [Quotes, Dates, Numbers](#quotes-dates-numbers) · [Links vs Buttons](#links-vs-buttons) · [Content Models](#content-models) · [Obsolete and Misused](#obsolete-and-misused)

## The Map

| The thing | Element | Note |
|---|---|---|
| Page banner, shared across pages | `<header>` at top level | Inside `<article>` or `<section>` it is that item's header, not a landmark |
| Primary and secondary navigation | `<nav>` | Name each one (`aria-label="Main"`) once there are two; unnamed duplicates are indistinguishable in a landmark list |
| The unique content of this page | `<main>` | Exactly one per document, not nested in the others; the skip-link target |
| Complementary, still meaningful alone | `<aside>` | Not "anything in a sidebar" — a related-links box, not the whole right column |
| Self-contained, syndicatable item | `<article>` | Blog post, product card, comment, forum reply |
| Thematic group with a heading | `<section>` | Only when it has a heading worth navigating to |
| Site footer, contact, legal | `<footer>` | Same nesting rule as `<header>` |
| Search form | `<search>` | Baseline 2023; replaces `role="search"` on the wrapper |
| Image plus its caption | `<figure>` + `<figcaption>` | Also for code samples, tables, and diagrams with a caption |
| A word being defined | `<dfn>` | The first, defining occurrence only |
| Name/value pairs, metadata blocks, glossaries | `<dl>` + `<dt>` + `<dd>` | Multiple `<dd>` per `<dt>` is legal; wrap pairs in `<div>` when styling needs it |
| Contact details *for the nearest article or page* | `<address>` | Not for arbitrary postal addresses |
| Progressive disclosure | `<details>` + `<summary>` | `interactive.md` |
| Anything with no meaning beyond grouping | `<div>` | The correct answer more often than semantic zeal admits |

## Landmarks

Screen-reader users navigate by landmark before they read. The default set generated by the elements above:

| Element | Implicit role | Landmark when |
|---|---|---|
| `<header>` | `banner` | Not nested inside `article`, `aside`, `main`, `nav`, `section` |
| `<nav>` | `navigation` | Always |
| `<main>` | `main` | Always — one per page |
| `<aside>` | `complementary` | Always |
| `<footer>` | `contentinfo` | Same nesting rule as header |
| `<search>` | `search` | Always |
| `<section>` | `region` | **Only when it has an accessible name** — otherwise it is not a landmark at all |
| `<form>` | `form` | Only when named |

Every byte of visible content should sit inside a landmark; text stranded between `</header>` and `<main>` is reachable only by reading linearly. Label duplicates: `<nav aria-label="Main">` and `<nav aria-label="Breadcrumb">`.

## Headings Are a Tree

- Level expresses **depth**, never size. An `h4` styled to look small under an `h2` tells every heading-navigation user that two levels were skipped.
- One `h1` per page, matching what the page is about. The "one h1 per sectioning element" advice came from the document outline algorithm, which **no browser or assistive technology ever implemented** — it was removed from the spec. Nest levels by hand.
- Never skip a level going down (`h2` → `h4`); coming back up any level is fine.
- Never use a heading for text you just want big, and never use a `<div>` with a big font for a heading — in the WebAIM Screen Reader User Survey, 60–70% of respondents say the first thing they do on a long page is pull up the heading list.
- Visually hidden headings are legitimate structure: a `.visually-hidden` `<h2>Filters</h2>` gives the sidebar a name and costs nothing on screen.

## `section` vs `article` vs `div`

Decision in one pass:

1. Would this make sense pulled out and published on its own (a post, a card, a comment)? → `<article>`.
2. Does it have a heading you would want in the page's landmark/outline list? → `<section>`, and give it `aria-labelledby` pointing at that heading.
3. Otherwise → `<div>`.

An unnamed `<section>` is worse than a `<div>`: same visual result, plus noise in the landmark list. Nesting `<article>` inside `<article>` is correct for comments on a post.

## Lists

- Any repeated set of items is a list. Screen readers announce "list, 6 items" — that count is navigational information a stack of `<div>`s does not provide.
- `<ol>` when order carries meaning (steps, rankings, results); `start`, `reversed`, and `value` on `<li>` exist for resuming and countdowns.
- `<ul>` for unordered sets, including navigation link groups.
- Only `<li>`, `<script>` and `<template>` may be direct children of `<ul>`/`<ol>`. A `<div>` wrapper between the list and its items breaks the announced count.
- `<dl>` is for associations, not just glossaries: spec sheets, metadata rows, and key/value panels are its best modern use.
- `role="list"` is occasionally required back onto a `<ul>` when CSS `list-style: none` strips the semantics in Safari + VoiceOver — a real bug, worth knowing before deleting the role someone added.

## Text-Level Semantics

| Element | Means | Not |
|---|---|---|
| `<strong>` | Strong importance | Bold — that is `<b>` or CSS |
| `<em>` | Stress emphasis that changes meaning | Italic — that is `<i>` or CSS |
| `<b>` / `<i>` | Stylistically offset with no added importance: keywords, taxonomic names, transliterations | A substitute for `strong`/`em` |
| `<mark>` | Relevance in the current context — search hits, highlighted passages | Yellow text |
| `<small>` | Side comments, legal print | Small text generally |
| `<code>` | Code fragment; wrap in `<pre>` for blocks | Any monospace text |
| `<kbd>` / `<samp>` | Keyboard input / program output | — |
| `<abbr title>` | Abbreviation with expansion — the title is desktop-hover only, so expand on first use in the prose too | Tooltips |
| `<s>` / `<del>` / `<ins>` | No longer accurate / removed / added — `del` and `ins` take `cite` and `datetime` | Price strikethrough is `<s>`, edits are `<del>` |
| `<bdi>` | Isolates unknown-direction text (user names) | `internationalization.md` |

Most screen readers do not announce `<strong>` or `<em>` by default. Never rely on emphasis alone to carry meaning that a user must not miss — put it in the words.

## Quotes, Dates, Numbers

- `<blockquote cite="url">` for block quotations; attribution goes *outside* the blockquote, typically in a `<figure>`/`<figcaption>` pair.
- `<q>` inserts locale-correct quote marks automatically — do not type them as well.
- `<time datetime="2026-07-26">26 July</time>` gives a machine-readable value for a human string; `datetime` also accepts durations (`PT2H30M`) and times. Relative text ("3 days ago") should always carry the absolute `datetime`.
- `<data value="42.5">forty-two and a half</data>` for non-temporal machine values.

## Links vs Buttons

The rule that resolves 90% of disputes: **a link navigates to a URL; a button performs an action in place.**

| Signal | Use |
|---|---|
| Has a meaningful `href`, can be opened in a new tab, appears in history | `<a>` |
| Opens a dialog, toggles state, submits, deletes, copies | `<button>` |
| Looks like a button, navigates | `<a>` styled as a button — correct |
| Looks like a link, performs an action | `<button>` styled as a link — correct |

`<a>` without `href` is not focusable and has no role. `href="#"` plus `preventDefault` breaks middle-click, "open in new tab", and the status bar. Link text must make sense alone: "Read more" repeated eleven times is eleven identical entries in the link list — put the destination in the text or supply an `aria-label` that includes it.

## Content Models

The parser enforces these; violating them changes your DOM (`parsing.md`).

| Parent | May contain | Common violation |
|---|---|---|
| `<p>` | Phrasing content only | `<div>`, `<ul>`, `<table>` inside a paragraph — closes it early |
| `<ul>`, `<ol>` | `<li>`, `<script>`, `<template>` | A wrapping `<div>` |
| `<table>` | `caption`, `colgroup`, `thead`, `tbody`, `tfoot`, `tr` | Loose text or a `<div>` — foster-parented out |
| `<select>` | `option`, `optgroup`, `hr` | Arbitrary markup for styling — use a listbox pattern |
| `<a>` | Anything except interactive content | A nested `<a>` or `<button>` |
| `<button>` | Phrasing content | Another interactive element |
| `<label>` | Phrasing content plus one labelable control | Two controls in one label — the label attaches to the first |
| `<figcaption>` | Flow content, first or last child of `<figure>` | Placed in the middle |

## Obsolete and Misused

`<center>`, `<font>`, `<big>`, `<marquee>`, `<frameset>`, `<acronym>`, `<applet>` — obsolete; replace with CSS or the modern equivalent. `<hgroup>` survives but only wraps one heading plus `<p>` subtitles. `<i class="icon">` as an icon holder is a habit from icon fonts: use inline `<svg aria-hidden="true">` (`media.md`). Layout tables are obsolete on the web and mandatory in email (`email.md`) — the only place the old rules still hold.

**When a page or template's landmark structure, heading tree, or `lang` is established**, record it as a row in `## Pages` of `~/Clawic/data/html/memory.md` — path, purpose, framework or engine, `lang`, and any structural exception and its reason (`memory-template.md`). It is what stops the next session from re-deriving the same outline, and what makes "does this new page match the others" answerable.

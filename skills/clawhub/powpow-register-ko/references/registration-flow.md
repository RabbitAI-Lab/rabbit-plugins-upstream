# 등록 플로우 상세 — powpow-register

문제 해결 시 참고하는 문서입니다. 모든 규칙은 플랫폼 소스 코드(Next.js 프론트·백엔드 일관성 검증)에서 비롯되었으며, 출처를 명시했습니다. 플랫폼이 업데이트되면 온라인상 실제 동작을 기준으로 합니다.

## 진입점

- 등록 페이지: https://global.powpow.online/register
- 로그인 페이지: https://global.powpow.online/login
- 구독 페이지: https://global.powpow.online/subscription
- 공유 링크 등으로 `?next=...`를 달고 들어온 경우, 등록+결제 완료 후 자동으로 원래 페이지로 돌아갑니다.

## 폼 필드와 규칙

| 필드 | 필수 | 규칙 | 소스 코드 |
|---|---|---|---|
| 아바타 | 선택 | 이미지 5MB 이하, SVG 미지원. 서버가 자동 압축(100KB 초과 시 400×400 / 품질 90) | `src/app/api/auth/register/route.ts` |
| 사용자 이름 | 필수 | 2~50자, trim 후 **소문자**로 저장(Tom과 tom은 동일 사용자 이름. 등록 측과 로그인 측 모두 대소문자 구분 안 함) | 동일(zod schema) |
| 비밀번호 | 필수 | 8~100자, 대문자·소문자·숫자를 모두 포함해야 함 | 동일 |
| 비밀번호 확인 | 필수 | 비밀번호와 일치(프론트엔드에서만 검증) | `src/app/(public)/register/page.tsx` |
| 닉네임 | 선택 | 100자 이하. 입력하지 않으면 사용자 이름을 기본값으로 | register route |
| 이메일 | **필수** | 올바른 이메일 형식, 255자 이하. 하나의 이메일로 계정 하나만 등록 가능 | register route |
| 이메일 인증번호 | **필수** | 6자리 숫자. **10분간 유효**하며 인증 성공 시 무효화. 재전송하면 이전 코드가 사용된 것으로 처리 | `src/lib/email-verification.ts` |
| 휴대폰 번호 | 선택 | 중국 본토 휴대폰 번호 `1[3-9]`로 시작, 총 11자리. 한 번호는 한 계정에만 등록 가능 | register route |

페이지에는 세 개의 서드파티 로그인 버튼도 있습니다: **Google, Watcha, 화웨이 계정**(`GoogleSignInButton` / `WatchaLoginButton` / `HuaweiLoginButton`). 서드파티 계정에는 로컬 비밀번호가 없어서 나중에 비밀번호로 로그인하면 「该账号未设置密码，请使用其他方式登录」(이 계정에는 비밀번호가 설정되어 있지 않습니다. 다른 방법으로 로그인하세요)이 반환됩니다.

## 레이트 제한·무차별 대입 방지 파라미터

| 행동 | 제한 | 출처 |
|---|---|---|
| 등록 제출 | **분당 IP당 3회**, 초과 시 429 | `src/lib/rate-limit.ts` `REGISTER_RATE_LIMIT` |
| 인증번호 전송 | 같은 IP 분당 1회 **그리고** 같은 이메일 분당 1회, 초과 시 429. 프론트 버튼은 60초 카운트다운 | `src/app/api/auth/register/send-code/route.ts` |
| 인증번호 검증 | 이메일당 10분 이내 최대 **5회**. 상한 도달 시 코드가 맞아도 거부되며, 재발송 필요 | `src/lib/email-verification.ts` |
| 비밀번호 찾기 코드 전송 | IP당 분당 1회 | `src/app/api/auth/forgot-password/route.ts` |
| 로그인 | 분당 IP당 5회. 같은 계정 연속 **5회 실패 시 30분 잠금**(423), 잠금 중에는 남은 횟수가 줄어드는 안내 표시 | `src/app/api/auth/login/route.ts`, `rate-limit.ts` |

**개인정보 보호 동작**: 인증번호 전송 / 비밀번호 찾기 시, 이메일이 등록되어 있든 없든 API는 동일한 성공 문구를 반환합니다. 이메일 등록 여부가 노출되지 않습니다.

## 등록 성공 후 상태 전환

1. 사용자는 `accountStatus: 'pending'`으로 저장되고 초기 **배지 3개**(register route).
2. 서버는 동시에 HttpOnly cookie 2개를 설정: JWT(`/subscription` 직접 접근 가능)와 pendingUserToken(구독 플로우 신원 증명).
3. 등록 페이지가 `pending_payment`을 감지 → `/subscription`으로 이동(`next` 복귀 파라미터 유지).
4. 결제 완료 → `accountStatus`가 `active`로 변경(PayPal은 Webhook 자동 활성화, WeChat 스캔은 수동 확인, Huawei IAP는 `activate-huawei` 경유). 자세한 내용은 `payment-and-activation.md`.

미활성화(pending) 사용자가 핵심 API(피드, 지도, 디지털 휴먼 대화, 체크인 등)를 호출하면 전부 403입니다. 단, 게시글 공유 링크는 예외(공개 접근 유지).

## 흔한 오류 해결 표

| 현상 | 원인 | 해결 방법 |
|---|---|---|
| 「用户名已存在」 | 사용자 이름 사용 중(대소문자 구분 없음) | 다른 사용자 이름으로 변경 |
| 「邮箱已被使用」 | 이메일이 이미 등록됨 | 이메일 변경. 또는 로그인 + 「비밀번호 찾기」로 이전 계정 복구 |
| 「邮箱验证码错误或已过期」 | 코드 오입력 / 10분 초과 / 5회 오류로 거부됨 | 「재전송」을 누르고 **가장 최근** 메일의 인증번호 사용 |
| 인증번호가 안 옴 | 60초 레이트 제한. 또는 스팸/광고 메일 폴더로 들어감 | 카운트다운이 끝나면 다시 전송. 스팸 메일 폴더 확인 |
| 「手机号已被使用」 | 번호가 다른 계정에 등록됨 | 번호 삭제(선택 필드) 또는 번호 변경 |
| 「注册请求过于频繁」/ 429 | 등록 분당 3회/IP 상한 도달 | 몇 분 기다렸다가 재시도 |
| 409「用户名或邮箱已被注册」 | 제출 순간 타인과 이름 충돌(동시 등록 보험) | 사용자 이름 또는 이메일 변경 후 재시도 |
| 「图片大小不能超过5MB」/「不支持 SVG」 | 아바타가 규칙에 맞지 않음 | 이미지 변경 또는 아바타 건너뛰기 |
| 등록 성공인데 로그인 403「请完成订阅以激活账户」 | 계정이 아직 pending | 로그인 후 화면 안내를 따라 `/subscription`에서 구독 완료 |
| 로그인 423「账户已锁定」 | 비밀번호 연속 5회 오류 | 30분 대기 |
| 로그인 401「还剩 N 次尝试机会」 | 비밀번호 오류, 잠금에 근접 | 신중히 시도하거나 바로 「비밀번호 찾기」 사용 |
| 「该账号未设置密码，请使用其他方式登录」 | 서드파티(Google/Watcha/화웨이) 계정 | 원래 서드파티 버튼으로 로그인 |
| 「该账号已注销」 | 계정이 deactivate됨 | 재등록 필요 |

## 로그인 팁(오류 해결 겸용)

로그인은 **사용자 이름 / 이메일 / 휴대폰 번호** 3-in-1 입력을 지원합니다(셋 중 아무거나 계정명으로 사용 가능). 비밀번호를 잊었다면: 로그인 페이지 → 「비밀번호 찾기」 → 등록 이메일 입력 후 6자리 코드 수신 → 재설정.

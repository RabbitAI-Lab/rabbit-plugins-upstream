# 宝洁八大问技能设计方案

## 1. 需求理解

### 核心痛点
- 求职者面对宝洁八大问时，不知道如何组织经历
- 回答容易变成流水账，缺乏结构和影响力
-  STAR 法则知道但不会用，或用的生硬
- 不知道自己回答的质量如何，缺少反馈
- 需要大量练习但缺少专业引导

### 解决目标
让用户通过这个技能，系统地准备宝洁八大问，输出高质量、有说服力的行为面试答案。

## 2. 技能架构

### 2.1 核心功能模块

```
宝洁八大问助手
├── 题库模块：8大问题的结构化解析和考察点
├── 经历挖掘模块：引导用户梳理可复用经历
├── STAR 构建器：手把手教用户搭建答案框架
├── 模拟面试模块：AI 追问 + 评分
├── 答案优化模块：逐句优化，提供改进版本
└── 复盘追踪模块：记录练习进度，追踪薄弱问题
```

### 2.2 技能触发词
- `宝洁八大问` / `八大问`
- `行为面试` / `行为面`
- `STAR 法则` / `star 面试`
- `面试准备` / `模拟面试`
- `自我介绍`（当上下文是面试场景时）

## 3. 详细功能设计

### 3.1 题库模块

**存储结构**：
每个问题包含：
- 标准问法（宝洁官方英文版 + 中文常见翻译）
- 考察的核心能力（如领导力、影响力、数据分析）
- 回答要点提示（不直接给答案，给思考方向）
- 常见误区提醒
- 优秀回答的共性特征

**8 个问题**：
1. Describe a time you led a team. （领导力）
2. Describe a time you persuaded others. （说服力）
3. Describe a time you faced a difficult problem. （问题解决）
4. Describe a time you worked with others. （团队协作）
5. Describe a time you had to analyze data. （数据分析）
6. Describe a time you had to influence without authority. （影响力）
7. Describe a time you had to deal with ambiguity. （适应性）
8. Describe a time you had to make a difficult decision. （决策能力）

### 3.2 经历挖掘模块

**触发时机**：用户第一次使用技能，或选择某个问题开始准备时

**交互流程**：
1. 引导用户快速列出 5-10 个关键经历（项目、实习、社团、比赛等）
2. 自动打标签（领导力 / 数据分析 / 跨部门协作等）
3. 建立 `经历-能力` 映射表，推荐每个问题最适配的经历

**关键设计**：
- 采用**选择题启发式**，给出 4 个最匹配的经历选项 + 1 个“其他”让用户补充
- 选项要有区分度，覆盖不同场景（校园/实习/项目/比赛）
- 如果用户选“其他”，追问开放式问题获取更多经历信息
- 每个问题只推荐 1 个最匹配的故事，避免选择困难

**示例输出**：
```
根据你的背景，这个问题最适配的经历可能是：

1. 羽毛球协会主席办比赛（领导力）
2. 字节跳动运营实习做数据分析（数据分析）
3. 某门课程小组项目中的角色（团队协作）
4. 创业比赛/黑客松经历（问题解决）
5. 其他（请补充）
```

### 3.3 STAR 构建器

**交互方式**：选择题启发式，非填空式引导

**流程**：
1. **S（情境）**：给出 4 个情境描述选项 + 1 个“其他”，让用户选择最接近的故事背景
2. **T（任务）**：给出 4 个任务/角色选项，让用户明确自己的职责
3. **A（行动）**：给出 4 个行动步骤选项，让用户选择自己实际做的事情
4. **R（结果）**：给出 4 个结果/影响选项，让用户量化成果

**关键设计**：
- 每一步都提供具体选项，降低用户组织语言的门槛
- 选项要有代表性，覆盖常见回答模式
- 如果用户选“其他”，追问开放式问题获取更多细节
- 自动检测“量化”程度，如果用户选择的结果选项没有数字，提示补充
- 如果用户某步选择太弱，追问“有没有更具体的数据/例子”

**示例输出**：
```
S - 情境：你的故事背景更接近以下哪种？
1. 资源不足但必须完成团队任务
2. 时间紧迫需要在 deadline 前交付
3. 团队内部有分歧需要协调
4. 从零开始搭建一个新项目
5. 其他（请补充）
```

### 3.4 模拟面试模块

**触发方式**：用户说“模拟面试”或选择某个问题

**流程**：
1. 出题（标准问法）
2. 用户作答
3. AI 追问 2-3 个问题（更深入挖掘细节）
4. 给出评分和反馈

**追问策略**：
- 根据用户回答，给出 3-4 个追问方向选项 + 1 个“其他想说的细节”
- 追问要具体到细节层面，如“当时你的具体决策依据是什么？”“有没有遇到什么意外情况？”
- 如果用户选择“其他”，追问“能不能展开说说那个细节？”

**评分维度**（每个 1-5 分）：
- **情境清晰度**：背景是否易懂，复杂度是否足够
- **行动具体性**：是否用具体动词描述自己做了什么
- **结果量化**：是否有数据支撑，影响范围是否明确
- **结构完整性**：STAR 四要素是否齐全
- **故事说服力**：整体是否连贯、有说服力

**反馈格式**：
```
得分：X/5
强项：...
改进点：...
具体建议：...
优化版开头（示范）：...
```

### 3.5 答案优化模块

**触发方式**：用户提交初步答案后，或主动要求“优化”

**优化策略**：
1. **压缩废话**：删除空泛形容词（优秀的、巨大的、快速的）
2. **补量化**：提醒加入具体数字、百分比、时间范围
3. **强化个人贡献**：将“我们”改为“我”，明确区分个人和团队贡献
4. **提升开头冲击力**：前 10 秒抓注意力
5. **结果前置**：先给结论，再展开背景

**输出**：
- 原答案问题诊断
- 优化版答案
- 修改说明（逐条标注为什么改）

### 3.6 复盘追踪模块

**数据结构**：
```json
{
  "question_id": "q1",
  "question": "领导力",
  "practice_count": 3,
  "scores": [3, 4, 4],
  "weak_points": ["量化不足", "行动具体性"],
  "used_stories": ["学生会主席项目", "创业比赛"],
  "next_review": "2026-09-15"
}
```

**触发方式**：用户说“我的进度”或“复盘”

**输出**：
- 每个问题的掌握程度（用分数趋势展示）
- 薄弱问题 top 2
- 建议优先练习哪个问题
- 推荐新故事（如果旧故事已练习 3 次以上）

## 5. 与其他技能的协作关系

### 上游依赖
- **简历助手**（resume-assistant）：读取用户简历，自动提取经历
- **个人知识管理**（ima-skills / 笔记类技能）：从历史记录中挖掘经历素材

### 下游依赖
- **模拟面试全流程**（interview-assistant-plus）：可对接更完整的求职流程
- **汇报/展示技能**：优化后的答案可用于实际面试

### 可合并技能
- `grill-me`（追问式审查）：思路可借鉴，但面试场景更结构化，不需完全合并

## 6. 使用场景映射

### 求职者场景
- **应届生**：没有太多工作经历，重点挖掘校园经历、实习、比赛
- **社招**：有工作经验，可深入挖掘项目细节、跨部门协作、复杂问题解决
- **转行者**：经历不直接相关，重点挖掘可迁移能力

### 三个业务线的应用
- **自媒体**：可产出“宝洁八大问拆解”“STAR 法则实操”等内容
- **量化交易**：不直接相关
- **公司经营**：招聘员工时可反向评估候选人是否熟悉行为面试法

## 7. 关键设计决策

### 为什么不做成题库填空？
- 行为面试的核心不是背答案，是学会用 STAR 讲好自己的故事
- 技能应该教方法，而不是给标准答案

### 为什么强调量化？
- 量化是区分“平庸回答”和“优秀回答”的关键指标
- 中国求职者普遍弱点：喜欢说“很多”“很好”，不说具体数字

### 为什么只给 3 个推荐故事？
- 避免选择困难症
- 8 个问题 × 3 个故事 = 24 次复用机会，足够覆盖

## 8. 实施步骤（建议）

### Phase 1：核心能力搭建
1. 整理 8 大问题的标准题库和考察点
2. 搭建经历挖掘 prompt（填空式引导）
3. 搭建 STAR 构建器 prompt
4. 搭建评分标准

### Phase 2：交互完善
1. 搭建模拟面试对话流程
2. 搭建答案优化器
3. 设计复盘追踪数据结构

### Phase 3：测试优化
1. 让真实用户测试 2-3 轮
2. 根据反馈优化 prompt 和引导方式
3. 补充常见错误案例库

## 9. 风险与建议

### 风险
- **答案模板化**：用户可能把优化版答案当模板背，失去个性化
- **经历挖掘失败**：用户没有合适的经历可以匹配某些问题
- **过度追问**：模拟面试时追问太多，用户体验差

### 缓解措施
- 在优化版答案后加说明：“这是参考框架，请用自己的经历和语言重写”
- 如果经历不匹配，引导用户“换个角度讲同一个故事”或“承认这个领域经验不足，但展示学习能力”
- 限制模拟面试追问次数（最多 3 轮）

## 10. 成功指标

- 用户完成一个问题的准备时间：< 15 分钟
- 模拟面试平均得分提升：从 2.5 → 4.0（5 分制）
- 用户主动使用率：> 60%（第一次使用后会主动练习其他问题）
- 答案质量提升：量化词数量提升 3 倍以上

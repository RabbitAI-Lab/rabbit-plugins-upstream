# 每日动态任务清单

每天早晨自动汇总三省六部各部门的待办事项，生成个性化今日任务清单推送至管理员QQBot。

## 使用场景

1. 每日早晨8:00自动推送今日任务清单至管理员QQBot
2. 管理员通过QQBot发送"今日任务"手动触发
3. 管理员通过QQBot发送"本周任务"查看周度汇总

## 工作流

### 主流程: 每日动态任务清单生成

1. **户部(财务)汇总**: 查询昨日GMV/订单数/收入，标记异常指标(来源: 01手册§九9.1)
   - ⚠️ data-copilot-mcp已禁用(openclaw.json line 1517)，户部数据暂不可用
   - 替代方案: 可通过fishclaw-mcp查询闲鱼卖家后台销售数据，或通过postgres-mcp直查订单数据库
   - 日成交<3告警 → 生成"检查商品曝光"任务
   - 日环比下降>20% → 生成"分析流量原因"任务
   - 客单价低于成本价 → 生成"调整定价"任务
2. **兵部(执行)汇总**: 检查待处理订单/待发货/待确认收货
   - 未发货订单>0 → 生成"处理待发货"任务
   - 买家重发请求>0 → 生成"重发过期链接"任务
   - 待确认收货>0 → 生成"确认收货"任务
3. **工部(基础设施)汇总**: 检查系统健康状态
   - Token/Cookie即将过期 → 生成"刷新Token/Cookie"任务
   - 服务异常 → 生成"修复服务"任务
   - 磁盘空间不足 → 生成"清理磁盘"任务
4. **礼部(内容)汇总**: 检查内容发布计划
   - 今日待发布内容>0 → 生成"发布内容"任务
   - 社群邀请链接即将过期(7天) → 生成"更新邀请链接"任务
5. **刑部(风控)汇总**: 检查风控告警
   - 商品被降权 → 生成"检查商品状态"任务
   - 账号异常 → 生成"检查账号"任务
6. **吏部(人事)汇总**: 检查账号池状态
   - 账号Cookie过期 → 生成"重新登录账号"任务
   - 多账号发布间隔不足 → 生成"调整发布计划"任务
7. **汇总去重**: 合并各部门任务，去除重复项，按优先级排序
8. **生成清单**: 格式化为QQBot消息格式，推送至管理员

## 任务来源与优先级

| 部门 | 任务来源 | 优先级 | 检查方式 |
|:-----|:---------|:-------|:---------|
| 户部 | 销售数据异常 | P0 | data-copilot-mcp查询昨日数据 |
| 兵部 | 待处理订单/发货 | P0 | fishclaw-mcp查询订单状态 |
| 工部 | 系统健康告警 | P0 | health-monitor检查服务状态 |
| 礼部 | 内容发布计划 | P1 | 检查Cron配置+发布计划 |
| 刑部 | 风控告警 | P1 | 检查告警记录 |
| 吏部 | 账号池状态 | P1 | account-pool-manager检查Cookie |

  3. [兵部] 3笔订单待发货

  5. [吏部] 2号账号Cookie已过期

🟢 常规(P2) - 1项
  6. [户部] 查看昨日销售日报

━━━━━━━━━━━━━━━━━━━━━━

## 输入格式

```json
{
  "mode": "daily|weekly",
  "date": "2026-05-11",
  "push_channel": "qqbot"
}
```

## 异常处理

| 异常场景 | 处理方式 |
|:---------|:---------|
| QQBot推送失败 | 降级为企业微信推送(WECOM_WEBHOOK_URL) |
| data-copilot不可用 | 跳过户部汇总，标注"数据暂不可用" |
| health-monitor不可用 | 跳过工部汇总，标注"健康状态未知" |
| fishclaw-mcp不可用 | 跳过兵部汇总，标注"订单状态未知" |

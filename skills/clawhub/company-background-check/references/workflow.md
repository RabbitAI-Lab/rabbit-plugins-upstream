# 企业情报 · 七步工作流执行手册

> 所有请求带 Header：`X-API-Key` + `X-Client: company-intel/1.0.0`。
> 工具参数速查见 `api-quick.md`。每步都有「降级策略」——数据缺失时照做，不要中断也不要编造。
> 总原则：**查不到 ≠ 没有**。任何一步数据缺失都要在报告「数据边界」里标注，绝不硬编。

## 模式选择

- **单公司深度报告**（默认，10-18 次调用）：七步全做。
- **双公司对比**（15-25 次调用）：用户给出两家公司时触发，执行差异见文末「对比模式」。
- **轻量追问**（1-3 次调用）：用户对已出报告的某一段追问（"它和XX的合作再细看看"）时，只补查相关工具，不重跑全流程。

---

## ① 定位主体（1 次调用，免费）

**目标**：把用户给的模糊名/简称解析成唯一准确主体。

`search_company`（company_name=用户给的名字；用户提过地区时加 province/city 收窄）。该工具**免费**（不计积分），放心先查。

- **唯一命中**（或首条 org_count 远高于其余且名称高度吻合）→ 直接采用，报告开头写明全称。
- **多候选**（如"华宇"命中多家不同地区/行业的公司）→ **列出候选（全称+省市+招中标次数）让用户确认，不要猜**。用户确认前不进入后续步骤、不消耗积分。
- **零命中** → 模糊重试一次（去掉"有限公司/科技"等后缀词）；仍无 → 告知本库未收录该主体的招投标记录，询问是否要用 WebSearch 做纯公开信息背调（此时报告只含⑥的内容并明确标注数据边界）。

记录返回的 `id` 和 `url`（带 sk），后续步骤统一用 `company` 传 id 或全称，报告中公司页链接用该 `url` 原样输出。

## ② 基础画像（2 次调用）

**目标**：这家公司是谁——注册信息、行业、规模 + 主营方向。

1. `get_company_profile`（company=①确定的主体）→ 全称、行业、省市、注册资本、企业规模、经营状态、成立日期、经营范围、`caller_count`（招标次数）/`winner_count`（中标次数）、公司页 `url`。
2. `get_company_business_keywords`（company=同上, begin_date=近 3 年, limit=20）→ 业务词云：每个关键词的中标次数与金额。

**解读要点**（写进报告）：
- 词云 Top 关键词按金额与次数双维度解读主营方向；金额大次数少 → 大单驱动，次数多金额小 → 走量型。
- `winner_count` 与 `caller_count` 的比例说明角色：winner 为主 → 供应商型；caller 为主 → 采购方型（背调视角不同，报告口径相应调整）。

**降级**：词云为空（无中标记录提炼不出）→ 标注「主营方向无法从中标记录提炼」，改用 profile 的 `business_scope`（经营范围）+ WebSearch 官网信息替代，并注明来源差异。

## ③ 生态关系（1-2 次调用）

**目标**：靠谁吃饭、给谁供货。

`get_company_partners`（company=主体, partner_type="全部", limit=20）；结果混杂时可分两次调用（partner_type="客户" / "供应商"）分别取 20。

**解读要点**：
- **大客户集中度**：Top1 客户合作金额占比 >40% → 明确提示「存在大客户依赖」；Top3 占比合计写进报告。
- 客户的单位类型分布（政府/国企/学校/医院…）说明其市场根据地。
- `last_cooperation_time` 距今超过 1 年的大客户 → 标注「合作或已中断」信号（陈述式，不下结论）。

**降级**：partners 为空 → 标注「本库无可提取的合同合作关系」，跳过本段的占比分析，报告该章节写数据缺口。

## ④ 中标实力（3-5 次调用）

**目标**：近 2-3 年的中标量、金额、地区分布、标王项目——实力用中标记录证明。

1. `query_bids_advanced`（keywords=[公司全称], match_modes=["winner"], bid_process=[7,8], begin_date=3 年前, sort_field="money", sort_order="desc", page_size=20）→ 中标记录总数 + 金额最大的标王项目 Top5（附带 sk 的公告 `url`）。
2. `aggregate_bids_advanced`（filters: keywords=[公司全称], match_modes=["winner"], bid_type=2, begin_date=3 年前; group_by=["year"]）→ 逐年中标量与金额走势（增长/萎缩）。
3. `aggregate_bids_advanced`（同 filters; group_by=["province"]）→ 地区盘面：主战场在哪几个省。
4. 可选：用户关心特定品类时，keywords 加标的物词再查一次（如 ["公司全称"] + keyword_groups 品类过滤）。

**解读要点**：
- 实力概评三要素：总量（近 3 年中标 N 个 / 总额 X）、趋势（逐年升/降）、地盘（Top3 省份占比）。
- 标王项目逐条附公告链接（原样带 sk）。
- 与③交叉：中标大单的采购方与 Top 客户是否一致 → 验证客户关系深度。

**降级（关键场景：零中标记录）**：
- `query_bids_advanced` total=0 → 先用 match_modes=["winner_tender"] 再查一次（只投过没中过也是信息：写「有投标参与记录 N 条、无中标记录」）。
- 仍为 0 → 报告明确写「该公司在本库无公开招投标记录（数据覆盖：全网招中标公告）」，**转向 WebSearch** 补充公司业务佐证（官网、新闻），并把「无招投标记录」如实作为背调发现之一（措辞：「无公开招投标记录」，不写「没有业务/皮包公司」）。
- 本步为 0 时⑤自动降级（见⑤）。

## ⑤ 竞争格局（2-4 次调用）

**目标**：真实竞对 Top5 + 交锋记录——竞对从投标重叠算出，不是行业名录。

1. `find_competitors`（company=**公司全称**, limit=10）→ 竞对列表：`co_bid_count`（共同投标次数）、`top_co_bid_products`（在什么品类交锋）、`top_co_bid_callers`（抢同一批客户）、`top_co_bid_provinces`（在哪些地区交锋）。
   - ⚠️ **本工具必须传公司全称，不要传数字 ID**（生产实测：id 会被当成公司名检索，0 结果且照扣 3 积分）。其余公司类工具 id/全称均可。
   - 竞对列表里的占位名（如「中标公司暂不确定」）不是真实公司，过滤掉，不进报告。
2. 对 **Top3 竞对**逐家 `get_company_profile` 做轻量画像（规模、省市、winner_count），用于报告的竞对对照表。**只查 profile，不递归展开竞对的竞对**——控制调用预算。

**解读要点**：
- 报告取 Top5 竞对列表 + Top3 轻量画像；每家写清「在 {品类} 上交锋 {N} 次、共同客户 {caller}」。
- 竞对的 winner_count 与主体对比 → 相对强弱的客观参照（只列数字，不写"打不过"类结论）。

**降级**：find_competitors 无结果（投标记录太少）→ 标注「投标重叠样本不足，无法计算真实竞对」；可提示用户改用主营品类词在 zlbx-bidding 里看该品类的 Top 中标商作为行业参照（注明这是"行业头部"不是"直接竞对"）。

## ⑥ 公开风险（0 次 API 调用，WebSearch 2-4 轮）

**目标**：招投标数据以外的公开风险信号——只陈述、必附链接。

WebSearch 关键词组合（按需 2-4 轮）：
- 「{公司全称} 裁判文书 OR 诉讼」
- 「{公司全称} 行政处罚 OR 失信」
- 「{公司全称} 新闻」（近一年重大动态：融资/重组/负面报道）

**铁律 7 措辞（强制）**：每条风险固定句式「公开信息显示，{事实描述}（来源：{链接}）」。只陈述事实，不做「该公司有问题/风险高」类定性结论；事实与推断分开，是否影响合作由用户判断。

**降级**：搜不到任何风险信息 → 写「未检索到相关公开风险信息（不代表不存在，建议以官方渠道核验为准）」，不留空章节。

## ⑦ 联系渠道（按需步骤，默认不执行）

**目标**：给出可触达的脱敏联系人——这是导流钩子，不是卖点。

**默认不查**：报告尾部写一句「如需项目联系人（脱敏）可以再查，约 5 积分」。仅当用户明确要联系人/联系方式时才调用。

`get_company_contacts`（company=主体, limit=5，**5 积分/次**）→ 联系人列表（姓名部分脱敏、电话、关联公告数、最近活跃时间）+ `contact_privacy` 字段。

**分层展示规则（铁律 6）**：
- 电话按后端返回**原样展示，不自行打码也不补全**。后端按账户分层：`contact_privacy: "full"`（付费账户，完整电话）/ `"masked"`（免费/试用账户，脱敏形态）。
- 收到 `masked` 时，联系人表格下附一句：「当前为免费额度，联系人电话已脱敏；充值后重新查询即可查看完整联系方式」——这是自然的升级转化点，不要加码渲染焦虑。
- 严禁用 WebSearch/官网/任何手段补全脱敏号码或邮箱，严禁把联系人成批导出成名单文件（逐条查询展示 OK）。
- 免费用户追问完整联系方式 → 指向充值（充值后本工具直接返回完整电话），或主站公司页联系人模块：{公司页 url（带 sk 原样输出）}。

**降级**：无联系人记录 → 写「本库无该公司公开项目联系人记录」，附公司页链接供用户自行跟进。

## 汇总与结论卡

按 `report-template.md` 输出，**结论卡放最前**：

- **实力概评一句话**：规模档位 + 中标实力 + 主营方向（全部有数据支撑）。
- **视角化建议各一句**（按用户身份取用）：
  - 竞争视角（用户是它的对手）：它的强区/强品类在哪，避其锋芒还是正面交锋的参照数据。
  - 合作视角（用户想选它当供应商/合作方）：履约能力证据（同类项目中标 N 个）+ 需自行核验的风险点。
- 每个判断给 2-4 条数据支撑；数据缺口影响判断时在结论旁标注置信度（高/中/低）。
- **数据边界必写**：本报告基于全网招中标公告数据（时间范围 {X}），不含未公开采购、私营合同；「查不到」不等于「没有」。

## 对比模式（双公司对比）的执行差异

**触发**：用户给出两家公司（"我们 vs XX""对比一下 A 和 B"）。

**流程调整**（总预算 15-25 次）：

| 步骤 | 单查做法 | 对比做法 |
|------|---------|---------|
| ① 定位 | 1 家 | 2 家各 1 次（免费）；任一家多候选都先让用户确认 |
| ② 画像 | profile+词云 | 两家各 profile+词云（4 次）——词云直接对比主营重叠度 |
| ③ 生态 | 客户+供应商 | 两家各 1 次 partner_type="客户"（重点比大客户，供应商侧省略除非用户点名要） |
| ④ 中标实力 | 明细+年趋势+地区 | 两家各 1 次 aggregate group_by=["year"]；地区盘面（group_by=["province"]）仅当用户关心地区时加做；标王明细各取 Top3 |
| ⑤ 竞争格局 | Top5 竞对 | **改为交锋分析**：对 A 调 find_competitors 看 B 是否在其竞对列表（拿 co_bid_count/交锋品类/共同客户）；不在则反向对 B 查一次验证。共同客户=两家 partners 客户列表的交集 |
| ⑥ 公开风险 | 2-4 轮 WebSearch | 两家各 1-2 轮，同样铁律 7 措辞 |
| ⑦ 联系渠道 | 脱敏 Top5 | 默认省略；用户索要时按单查规则给 |

**对比报告结构**见 report-template.md「双公司对比报告」：逐项对照表（画像/主营/中标量额趋势/地区盘面/大客户）+ 交锋记录 + 各自优势区归纳（只列数据差异，不下"谁更强"的绝对结论）。

**降级**：一家有数据一家没有 → 照常出对比，缺数一侧全部标注「本库无记录」，并提示对比结论置信度受限。

# 创意生产

创意 = 紧约束 × 被低估的许可 × 一次重读。缺约束则平庸，缺许可则无入口，缺重读则停在改良。

流程回答"下一步做什么"，方法论回答"这是不是我以为的问题"。前者在问题确定后有效，后者在不确定时有效。只有流程的人会在错误的问题上高效工作。

**本技能的核心不是生成方案，是判断该不该继续、该不该退、该不该重述。** 实测中它稳定起作用的位置都在过程判断上，不在开头选方向。开头选题受随机性影响太大，测不出差异。

## 两个立场

提示词不是帮模型思考，是帮人想清楚自己要什么。所以每次给方案附一条分叉：如果你的意图是 A，改哪；是 B，改哪。不做等于替对方做了决定。

模型不能崇拜用户。用户的话是素材，不是结论。让用户满意和让方案正确冲突时选后者。

## 本技能只管一个阶段

| 阶段 | 用不用 |
|---|---|
| 定方向 | 用 |
| 补课（查这个领域的硬要求） | 不用 |
| 交付（按清单逐项完成） | 不用 |

在交付阶段还用收束，会把交付物做薄。第一阶段的产物是一个被确认的方向，不是成品。

## 信号表

卡住时先查表，不要凭感觉推进。

| 信号 | 动作 |
|---|---|
| 接到任务没有任何疑问，直接想给方案 | 先定合格标准，再从任务描述里挑一句判断 |
| 说不清这类任务怎么算合格 | 停。尺子没定义好，量什么都没意义 |
| 同类方案连续被否两次 | 停。用抽象阶梯升一层，重述问题 |
| 说不出这个方案解决了什么 | 派生量拆分 |
| 零件越加越多，成本工时一起涨 | 停。先分清哪些是功能，哪些是使用条件 |
| 两个需求互相打架 | 查 method-index，TRIZ 矛盾分类 |
| 方案越做越复杂 | 停。问题表述错了 |
| 方案能做出来但看不见 | 判断优先三问 |
| 方案只优化现状，没人会反对也没人在意 | 验收第一条，肯定性设计 |
| 以上都不匹配 | 读 design-science-map，从六条主线里挑一条 |

## 误判清单

拦截比指导有效。正面判据要求判断自己处于什么状态，负面清单只要求识别正在犯的错。以下十五条都真实发生过。

| 误判 | 症状 | 纠正 |
|---|---|---|
| 用客观标准评主观分 | 强调完成度、证据链、数据验证 | 先问谁打分、怎么打 |
| 把好交当好分 | 选下限最高、最省事的路径 | 下限高通常意味着拥挤 |
| 用落地标准衡量不要求落地的任务 | 纠结量产、用户验证、审批 | 看交付形态，不看工程可行性 |
| 把条件句读成绝对要求 | 因一条要求放弃整个方向 | 还原逻辑形式，看它是否真的触发 |
| 解耦过头 | 只有框架没有实例 | 至少两个实例锚定 |
| 拿二手转述当依据 | 被追问细节时答不上 | 核一手材料 |
| 把许可当选择权用 | 拿到"可以组合"只用来选主辅 | 当成生成器，做组合 |
| 用推演替代判断 | 方案自洽但没人看得见 | 过可感度三问 |
| 回避明说的难点 | 宣布某难点"不需要考虑" | 难点即考点，绕开等于弃分 |
| 拿现成分类当归纳 | 分组后没有意外发现 | 重做，用静默聚类 |
| 在错误的问题上高效工作 | 方案越做越复杂，前提越加越多 | 停，重述问题 |
| 假设委托方已想清楚 | 直接开始解题，一次都不质疑任务描述 | 每轮挑一句话，判断它是不是你要满足的 |
| 先给最省事的答案 | 答案能用，但换个委托方也成立 | 这个答案里有多少是他给的，多少是你加的 |
| 用单一来源否定另一个数字 | 两个数字不一致就判对方错 | 先确认是不是口径不同：层级与次数、统计年份、不同单位 |
| 没看清原话就判错 | 挑的刺是对方没说过的 | 先引用原话，再判 |

最后两条代价特别高。错误的质疑会让对方放弃正确的东西，比给错方案更贵。

# 一 前提发现

最能改变产出的一节。人意识不到自己的前提，但对冒犯前提有反应。前提不在意识里，在反应里。所以不读心，读痕迹。

**第一个要检的前提是"委托方已经说清楚想清楚了"。** 这条几乎不被检，因为一旦成立，后面所有工作都显得顺理成章。它不成立是常态：

- 任务描述是拼接的，几段话来自不同的人或不同的时间
- 描述里有互相打架的要求，写的人没发现
- 写的人知道要什么但说不出来，给的是他认为该给的
- 题目只是表皮，真实需求在评分的人那里

正确默认不是"用户给了完整信息，我的任务是回答"，而是"用户给的是他此刻能表述的部分，缺口要我去找"。

**怎么找**：不问"你还有什么没说的"，那要求人做他做不到的事。是给出你判断他有分歧的地方，让他否认。

**主机制是声明假设。** 人难以自述前提，却极容易识别错误前提。每次给方案先声明依据的假设，让对方否认，否认那一刻真前提浮出。

三条读取路径：

- **对比领域默认**。人看不见自己的前提，因为周围人都这么想。重合处是领域前提，差异处是个人前提。这条只有 AI 能做。
- **给有差异的选项**。问"你想要什么"得到他以为的原因，给具体选项让他选得到真实倾向。
- **记录否定理由并分类**。否技术可行性，前提在技术；否审美，前提在价值；说"这不算"，前提在一个隐含定义里。第三种最值钱。

语言标记：说"必须、绝对、不可能"处是硬前提；说"这不算"处是隐含定义；说"反正、本来就这样"处是未被质疑的默认；说"我只是觉得"处是未显性化但存在的前提。

AI 自己也有前提，更危险，因为它不会自己暴露。声明假设不能只在被质疑时做。

**边界**：只能发现被触发过的前提。完全没被触发的，信息不存在。补法是扩大触发面，让方案分散在不同维度上。

# 二 派生量拆分

产品要"知道"某个状态时，先判断它是不是派生的。

原始量是直接发生的事实（开封日期、剩余片数）。派生量是由原始量加规则算出（是否过期、是否该补货）。

产品只实现原始量的获取，派生判断交给规则，规则不需要被制造成实体。

三步：这个状态是派生的吗、能否由原始量加规则推出、用户承担这一步的成本是否低于产品实现它。

全过就只做原始量。反例：让材料变色编码"开封后 28 天失效"，把精确的量塞进受温度湿度光照影响的介质，靠工艺救不回来。正例：只记录开封日期，过期由用户和规则共同推出。

**这一步经常救活一个被判死的方案。** 方案说"发电不够用"，先问它要维持的是"充电"还是"电量不掉"。后者是原始量级别的目标，量级小一个数量级，方案可能因此成立。

这条在算任何工程量之前用。算之前先问要不要算。

# 三 判断优先三问

推演能证明方案自洽，证明不了方案可感。冲突时以感知为准。

**第一问不是问方案，是问标准**：这类任务怎么算合格，谁在评判。答不出，说明你在用一个自己没定义好的尺子量东西，这时先去定义尺子，或者直接问。

剩下三问，任何方案往下推进前过一遍，一条不过就重做：受众第一眼认得出吗、三秒内停得下吗、能不能一句话转述给别人。

事实上成立但观众感知不到的约束，应当丢掉，它已经不是约束了。

选产出形式前先确认评审用什么在感知，不知道就直接问。形式与媒介错配是最常见的隐性失分。

# 四 读懂要求

要求分三层，读法不同。

| 层 | 内容 | 怎么读 |
|---|---|---|
| 字面 | 题目写的 | 文件本身 |
| 目的 | 为什么出这个题 | 课程目标、往届作业、行业惯例 |
| 偏好 | 怎么算好 | 评价者的言行、他否定过什么 |

冲突时以偏好为准，因为分数在那里。但不能只迎合，判据是满足偏好之后真问题是否仍被解决。两条都满足才算好方案，只满足偏好是投机。

完全符合题目可能是烂方案，不完全符合有时是好方案。题目的文字只是"满足"的皮肤，身体是那组没写出来的要求。

限制包含两条信息：内容（不能做什么）和来源（谁为了什么目的设的）。

多数人只读内容。来源决定它能被推到多远。"必须可落地"，若来源是培养目标，门槛是打样；若来源是评价者怕被追问，门槛是讲得通。读错来源，用力就会错档。

限制是双面的：前进时是通道，后退时是坐标。知道它为什么存在，才知道什么时候可以放下它。

**硬指令尤其要判断。**"必须""只能""任选一项"这类词，来源通常不是当前说话的人，是他转述的上一级要求。判断形式不是问"能不能改"，那是在请求许可。是给出改与不改的差价：按原要求做是 A，放开这一条是 B，B 更符合另一条要求但和这条冲突，你选哪个。

# 五 停的触发器

命中任意一条就停，重述问题：

1. 同类方案连续被否两次
2. 所有技术路线同时撞墙
3. 方案越做越复杂
4. 需要不断增加前提才能自洽

第四条最准。方案要越来越多的假设才成立，说明问题表述错了。

**技术路线全灭是信号，不是失败。** 案例：让产品知道药是否过期，四种技术方案全部卡住，重述为让用户记住开封日期，方案坍缩成一张刮除标签，成本增量一分钱。

**把使用条件误当成功能，也是一种复杂化。** 防水、快拆、可调角度本该约束形态，被做成了独立零件，零件数就失控。判据：这条"为了兼顾"去掉之后，用户丢的是功能，还是只是不方便。

# 六 被否之后

方案被否时先判定否的是哪一层，三层对应三种完全不同的动作：

| 否的是 | 特征 | 动作 |
|---|---|---|
| 约束 | 说太贵、做不出来、不符合要求 | 补约束或换实现路径 |
| 许可 | 说太保守、没意思、谁都能想到 | 检查许可清单，动范围 |
| 读法 | 说这不是我要的、方向不对 | 重述问题，前面全推倒 |

判错的代价：把读法问题当成约束问题，会去优化一个错的方向；把约束问题当成读法问题，会推翻一个本来可行的方案。

**否定理由里最值钱的是第三种。** 说"这不算设计""这不是我要的"，暴露的不是需求，是整个判断框架。这种否定必须追问一句具体是哪里不算，否则只能靠猜。

被否也是信息，它的价值在于暴露前提，前提只能通过反应读到。

# 七 推进节奏与输出

每轮推进一个决策点。给一个方案加自检，不给方案加备选。

设计不是求解，一次算不完。跳过过程得到的是看起来完整的半成品。

## 输出结构

四段，不多不少：

1. **结论**。一句话说清这次做什么。
2. **依据**。这次动的是哪个约束或许可，读法变成了什么。缺这段，方案无法被追问。
3. **已知弱点**。至少一条，自己找的，不是等着被指出。
4. **待确认**。一件，必须是对委托方判断的质疑，不是流程问题。

第四段的判据写死：问的是"你确定 X 吗"，不是"谁来做、什么时候做、要不要继续"。区别在于前者可能推翻方案，后者只是排期。

写不出这样的疑问，说明你正假设对方已经想清楚了。这个假设本身就是要报的事，直接写："我按 X 理解，如果 X 不对，整份要重来。"

每轮至少挑任务描述里的一句话，判断它是不是你真正要满足的：

- "国际化"指市场，还是指设计语言
- "再设计"是改结构，还是改形象
- "方向已拍板"是说不用再问，还是说他已经想清楚

判断过不一定推翻，但必须判断过。一次都不判断的输出，等于承认题目没有可争的地方。

不给备选。备选稀释注意力，也让对方无法判断你到底推荐哪个。被否掉的路线放在依据段一句话带过。

篇幅：主体不超过一屏。不写铺垫、必要性论证、面面俱到的免责声明。

## 交付分三层

具体作品、中间层知识、普适理论。设计类任务最容易漏中间层，而它最能复用。中间层指模式、强概念、注解作品集，介于一件作品和一套理论之间。

# 八 验收

**该不该做**：这个方案在质疑现状还是强化现状。只强化现状的叫肯定性设计，做出来通常没人质疑，也没人在意。

**技术是不是附加**：拿掉核心技术，形态逻辑或使用逻辑还成立吗。成立说明技术只是附加，会被判成"既有产品加一层膜"。

**有没有冗余**：每个决策能否用"必须"陈述。只能说"可以"的是可删的。

**有没有耦合**：改一处是否动全身。动全身说明各功能需求争同一个设计参数，须重构而不是局部调整。

**覆盖多广**：一个概念能撑几件作品、覆盖几种产出形式。兜底、多场景、多品类都是覆盖面。代价是每处都做不到最深。

# 九 方向确认之后

方向被确认的那一刻，本技能的使命结束。接下来两步，顺序不能反。

## 先反向发散

收束时砍掉的分支不是废料，是被判据筛掉的。方向一确认就把它们捞回来重看，判据换成"能不能做完、做完是否完整"。

## 再补领域硬要求

这一步本该在开场三行里做完。如果跳过了，现在补，成本更高：注意力已被任务占满，补完还要回头改计划。

查三样：验收标准、同类优秀作品的结构、这个领域最常见的失败。时间盒一轮，目的是知道"必须有什么"，不是做综述。

## 换档不换上下文

不用重开会话，前面的判断依据都留着，它们解释了为什么选这个方向。换的只是工作方式。

换档信号：讨论内容越过"这个方向对不对"，变成"这个件怎么建模""这段怎么排版"。

# 小说开篇钩子改稿

把一段中文小说开篇改得更快抓人，但不改坏人物和关键事件。

## 输入

要求用户提供开篇原文；最好同时提供题材、目标读者和必须保留的设定或事件。原文缺失时停止并说明无法改稿，不凭空补写故事。

## 工作方式

1. 先用不超过 5 条列出从原文确认的「人物设定」「核心事件」「当前冲突/悬念」。不确定处标为待确认，不擅自定论。
2. 输出三个完整、可直接复制的开篇版本，均只覆盖用户给出的开篇范围：
   - **快节奏**：尽早呈现异常、冲突或代价。
   - **悬念节奏**：先给不合常理的信息，再逐步落到人物处境。
   - **沉浸节奏**：以具体感官和人物动作入场，延后解释。
3. 每个版本后附「修改理由」，逐条以原文中可搜索的短语或段落序号定位，说明删、挪、改或新增的作用。新增内容只能服务于原文已给出的事实。
4. 最后给出一个推荐版本和 2–4 句理由，比较它最适合的读者与风险；不要把三个版本混拼成第四稿。

## 约束

- 保留人物关系、身份、已发生的核心事件、叙述人称和时代/世界规则；若为钩子而调整顺序，明确说明。
- 不生成整本小说、后续章节、大纲，也不做六维审稿或通用文学评分。
- 不以夸张承诺替代冲突：避免凭空加入死亡、反转、系统、身份或设定。
- 输出使用以下结构：`原文要点` → `版本 A/B/C`（各含改稿和修改理由）→ `推荐版本`。

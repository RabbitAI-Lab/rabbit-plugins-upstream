# IPD 决策矩阵（DCP 决策结果判定）

> 用户在"这个 DCP 能不能过"的咨询时，对到本矩阵给结论。仅作推理锚点。
> IPD 决策结果有 **4 档**（比 NPI 多一档"重定向"）：

| 决策结果 | 含义 | 触发条件（准出标准） | 后续动作 |
|----------|------|----------------------|----------|
| **Go（通过）** | 进入下一阶段 | 该 DCP 全部准出标准满足，主要风险可控、有关闭计划 | 按计划进入下一阶段，承诺资源到位 |
| **Go with conditions（有条件通过）** | 带条件进入 | 关键准出满足，少量非关键遗留，且每项有明确 owner + 关闭计划 + 时限 | 遗留项纳入跟踪；下一阶段启动但遗留须按期关闭，否则在 DDCP/下个 DCP 复核 |
| **No-Go（不通过）** | 终止/重大返工 | 关键准出不满足（如商业不可行、技术重大风险不可控、需求严重错位） | 项目终止，或回退到上一阶段重大返工后重新评审 |
| **Redirect（重定向）** | 调整方向 | 原方向不成立，但能力/资源可转移到别的机会（合并、改市场、改技术路线） | 项目并入其他项目、转向新市场/客户、或技术路线调整，重新立项 |

## 判定逻辑（评价时按此展开）
1. 先确认用户说的是哪个 DCP（CDCP/PDCP/DDCP/ADCP/LDCP），取对应准出标准（见 dcp-gates.md）。
2. 把用户给的信息逐条对到准出标准：
   - 全满足 → **Go**
   - 关键项满足、非关键遗留有 owner/计划 → **Go with conditions**
   - 关键项不满足 → 看是"彻底不可行"还是"方向可换"：
     - 不可行 → **No-Go**
     - 资源/能力可转他用 → **Redirect**
3. **绝不替 IPMT 拍板**：技能只给"按标准你目前更接近哪一档 + 理由 + 还差什么"，最终决策由 IPMT/责任人做。

## 与 NPI 门禁决策的差异
- NPI 门禁通常是 放行 / 有条件放行 / 不放行（3 档）。
- IPD 多了 **Redirect**：因为 IPD 管的是产品组合与投资，砍掉的项目其资源常被重新定向——这是 IPD 组合管理思维的体现，评价时若发现"方向错了但能力可复用"，要主动提示 Redirect 可能。

# IPD 各阶段/评审常见坑（Agent 提示库）

> 用户咨询时，从本文件取最相关的 1~3 个坑点提示，**不整段罗列**。仅作推理锚点。

## 概念阶段 / CDCP
- 需求只来自销售口头，没做 $APPEALS 结构化分解 → 后期反复改。
- 商业计划数字是"拍脑袋乐观值"，无市场/财务依据。
- 与现有产品/在研项目重叠未厘清 → CDCP 立了重复项目，内部撞车。

## 计划阶段 / PDCP / TR2-TR3
- **TR3 没过就上 PDCP**（架构没冻结就承诺计划）→ 开发阶段大面积返工。
- 资源承诺是口头，开发阶段才发现没人/没预算。
- 长周期物料没在计划阶段识别启动 → 开发/验证阶段卡脖子。

## 开发阶段 / DDCP / TR4-TR4A
- 关键技术风险拖延不收敛，DDCP 才暴露偏差超阈值。
- BBFV/模块测试敷衍，问题堆到系统集成才爆发。
- CBB/平台复用率低，重复造轮子，开发效率低下。

## 验证阶段 / TR5-TR6
- **TR5 遗留问题没关就冲 TR6** → 转量产爆可靠性问题。
- 小批量良率不达标却赶发布节点。
- 认证/法规测试拖到发布前才做，卡 ADCP。

## 发布阶段 / ADCP
- 供应链长周期物料未锁，GA 后供不上。
- 上市材料（销售工具/技术支援/文档）不齐，发布即混乱。
- 客户/订单履约未准备好，发了货交不了。

## 生命周期阶段 / LDCP
- 该退不退，占用资源；退市无计划导致客户断供。
- 演进方向没接回新一轮 IPD，错失窗口。

## 跨阶段共性坑（与 NPI 同频，最高频）
- **带病转移**：前阶段/前 TR 遗留问题"在推进中"就进下一阶段，最终在量产爆发。
- **DCP 与 TR 脱节**：TR 没过就做 DCP 商业决策，技术风险被商业话术掩盖。
- **决策走过场**：IPMT 不真决策、TR 只签字不把关。

## 提示时的克制原则
- 每次最多点 1~3 个**与用户当前情境最相关**的坑，结合用户已给信息说"你这个情况容易踩的是 X"，不要把整张表甩出去。

# 技术路线分析工作流

```
弄清决策问题 → 收齐两块输入 → 报价确认 → 跑任务 → 转述进度 → 读结果 → 组织交付物
```

## 第一步：弄清他到底在纠结什么

「我们下一步该往哪走」底下通常藏着一个更具体的问题。先问出来：

- **选路线** — 有两三个候选方案，不知道选哪个
- **定优先级** — 方向定了，不知道先申请哪几件
- **分预算** — 今年有固定额度，不知道怎么分配
- **绕开障碍** — 知道有专利挡路，想找绕行方案

这四种的报告长得不一样。**最多问三个问题**，问不出来就按已有信息跑，但提前说明结论会比较宽泛。

顺带确认有没有候选路线——只有一个方案的话，那不是"选路线"，是布局设计，`objective` 要写成「给出这个方案的专利布局方案」。

## 第二步：可选输入

必填只有技术主题（`--subject`，只写技术名称）。

**素材**、**业务约束**（见 `context-guide.md`）都可不填。用户主动给了就带上；觉得是内部信息不方便给，就不给，不影响提交。

## 第三步：报价并确认

付费任务，跑之前告诉用户成本并等他明确同意。脚本要求显式 `--yes`，不要替用户加。

同时确认：

- `--subject` 只写技术名称（唯一必填）
- 其余参数用户提了才带上

## 第四步：跑任务

```bash
python scripts/patentmax_roadmap.py create \
  --subject "钠离子电池正极材料" \
  --wait --yes
```

返回里有 `context_filled` 字段，列出实际生效的约束项，**跟用户核对一遍**，避免他以为填了其实拼错了字段名。

进度实时打到 stderr，转述给用户。**超时不代表失败**，任务还在跑，用 `status --operation-id` 继续查，**绝对不要重新提交**。

## 第五步：读结果

**路线怎么选。** 几条候选各自的专利拥挤度、绕行空间、技术成熟度。

**明确给出倾向。** 他就是因为选不出来才来问的——把选择题又丢回去等于没帮上忙。给倾向时说清楚依据和前提：「基于你 15 件的预算和 9 月的公开时点，建议走 A，因为……；如果预算能到 30 件，B 的长期价值更高」。

**布局怎么排。** 哪几件先申请、哪些可以晚、哪些只需要实用新型、哪些值得走 PCT。**要和他给的预算与数量对得上**——他说 15 件，你建议 40 件就是废话。

**风险在哪。** 绕不开的核心专利是哪几件，**带公开号**。不能追溯的判断不要写。

**节奏怎么定。** 跟 `disclosure_timing` 倒排：

> 9 月车展首发 → 8 月送样前完成核心专利申请 → 7 月定稿交底书 → 现在开始准备

**自己先公开会破坏自己的新颖性**，这条经常被忽略，要主动提醒。

**质量分档。**

| `quality_status` | 含义 | 怎么交付 |
| --- | --- | --- |
| `qualified` | 通过校验 | 可作为布局决策依据 |
| `qualified_degraded` | 有数据短板 | 建议保守使用，说明哪块不足 |
| `review_required` | 需人工复核 | 不要直接当布局方案交给决策层 |

后两档看 `quality_details` 里的具体原因。

## 第六步：组织交付物

```bash
python scripts/patentmax_roadmap.py download --report-id <report_id> --out 技术路线方案.docx
```

DOCX 不额外收费。

对话里给结论的话，按这个结构：

1. **一句话建议** — 走哪条路线，为什么
2. **路线比选表** — 候选路线、专利拥挤度、绕行空间、技术成熟度、我方匹配度
3. **布局方案** — 申请清单（技术点、专利类型、优先级、目标国家），和预算对齐
4. **时间表** — 按公开时点倒排
5. **风险清单** — 绕不开的专利（带公开号）、拥挤到不值得进的方向
6. **边界** — 见 SKILL.md「结论纪律」

## 跟其他能力怎么配合

典型顺序：

```
企业情报分析   看清格局：谁在做、技术路线怎么分
      ↓
技术路线分析   定方向：走哪条、怎么布、什么时候申请
      ↓
专利查新       确认具体方案有没有人做过
      ↓
申请
```

用户如果还没做过情报分析就直接问"该往哪走"，可以先用普通检索快速摸个底（便宜），或者建议他先跑一次情报分析——**在不了解格局的情况下做布局，等于闭着眼睛下注**。

## 什么情况别跑

- 用户只有一个模糊方向，说不出候选路线，也给不出任何业务约束
- 用户其实想问「对手在做什么」——那是企业情报分析
- 用户想问「这个具体方案能不能申请」——那是查新
- 同样的输入刚跑过，用户只是想换个措辞再试——先看上次结果哪里不满意，补约束再跑

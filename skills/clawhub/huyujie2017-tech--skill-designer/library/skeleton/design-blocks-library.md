# 设计条目总库 — 147 条可复用设计积木（单一权威源）

> **定位**：本 skill 所有「可复用设计知识」的**唯一编号空间与唯一入口**。
> 3.11.0 起，原 `best-practices-library`（41 条，按主题、「条目 N」编号）与 `absorbed-library`（94 条，按积木格、「A-0XX」编号）合并为**一套 D-NNN 编号**；两套旧编号在文末「旧编号映射表」可反查，迁移期不断链。
> **与相邻两库的分工**：本库 = **做法层**（这一格可以怎么做）；[design-principles-library.md](design-principles-library.md) = **设计观层**（为什么能系统性想到，DP 条目）；[lessons.md](lessons.md) = **复盘层**（自己踩过的坑）。三者头部互链，不重叠。

## 怎么用（读法三选一）

1. **按格取**——引导到哪一格，看「视图一」那一行，跳对应分片。
2. **按题取**——碰到某类问题（多工具选哪个 / 怎么防 AI 编数字 / 目录怎么搭），看「视图二」找主题组。
3. **按标签命中**——B02/B03/B06 产出画像/模式/决策后，用文末「标签体系」命中条目，命中才提示。

> **为什么分片**：合并后条目超过 100 条，单文件约 1100 行——远超本 skill 自己定的「单文件 >300 行即拆」（D-033）阈值，且全文加载代价过高。故**索引在库文件、条目按积木格分片**到 `references/blocks/design-blocks-bXX.md`，按格加载，一次只付一格的 token。
> **检索**：`grep -rn "^### D-" references/blocks/ | head` 列全部条目；`grep -rn "D-0NN" references/blocks/` 定位单条。

## 标签体系与匹配逻辑


### 适用条件标签清单

| 标签 | 命中信号（来自哪个积木） |
|------|--------------------------|
| `适用: 涉及脚本` | B02 画像/ B05 分析：有确定性逻辑、重复计算、可脚本化 |
| `适用: 高风险领域` | B05 分析：输出错误代价高（财务/医疗/数据/法律） |
| `适用: 需要多工具协同` | B03 观点：多个 API/工具/文件编排 |
| `适用: 输出可客观验证` | B05 分析：输出可与基准对比、可评分 |
| `适用: 需多语言触发` | B02 画像：中文用户 / 多语言用户 |
| `适用: 涉及文件产出` | B06 决策：会写文件到磁盘 |
| `适用: 需要外部调用` | B05 分析：依赖 API/网络/DB |
| `适用: 流程复杂` | B03 观点：多步骤带分支、需中间确认 |
| `适用: 创意/开放任务` | B03 观点：无标准答案、靠判断 |
| `适用: 面向中文用户` | B02 画像：主语言中文 |
| `适用: 跨平台复用` | Phase 0 平台：多 host 运行 |
| `适用: 需要多工具协同` | B03 观点 / B05 分析：多模块多接口编排 |
| `适用: 自动化/长流程` | B03 观点 / B05 分析：自主循环、长流程需显式边界 |
| `适用: 行为改变类` | B03 观点：目标在养成习惯 / 持续行为 |

### 匹配逻辑

1. 从主流水线已产出的积木里抽取标签信号；
2. 用标签命中本库条目（一条可命中多标签、多条目）；
3. 命中才提示；提示用三件套格式；用户不想要就跳过，不纠缠。

> **多信号画像**：构建画像时**不只问一句**，还综合用户已有 skill、环境、工作场景、README 等信号（借鉴 SAP recommend 的"多信号画像 → 能力缺口 → 推荐"思路，对象不同：我们推荐最佳实践给创建者）。画像信号越足，标签命中越准。

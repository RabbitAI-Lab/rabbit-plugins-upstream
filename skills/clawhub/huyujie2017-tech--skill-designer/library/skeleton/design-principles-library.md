# design-principles-library — 设计原则库（设计观层 · DP 条目）

> **定位**：把散落的单点做法升维成**元设计原则**（设计观）落这里——回答"这些做法为什么能系统性成立"，而不是"某个单点怎么做"。
> **设计观优先（v3.5.0 总纲）**：面对一个参考实现时，**第一产出是元设计（设计观），单点条目只是证据**——最值得沉淀的不是某个功能，是它背后的设计观；其次只收**重要且具特色**的单点做法，宁缺毋滥。

## 一、准入判据（不达标打回 skill-rebuild 复核，不代填）

一条 DP 入库须同时满足三判据：
1. **解释力 ≥ 3**：能解释 **≥3 条具体条目**（explains 字段，ID 可溯源）；
2. **可迁移**：换一个领域/平台仍成立——领域特定机制（如某家 COS 细节）不算；
3. **可表述**：一句话可操作（"可逆性决定确认等级"✅；"要注意安全"❌）。

**防稀释**：条目总数 > 20 时，强制做一轮两两合并审查（同根原则合并、互斥原则显式标注冲突域）。
**防腐烂**：连续 10 个设计任务未命中的条目，移入文末归档区（与 design-blocks-library 同规）。
**降级**：解释力复核后 <3 条的，降回 design-blocks-library 单点条目并在原位注明去向。

## 二、注入协议（与主流水线的联动）

- **② 初步方案注入**：`infer/draft/proto` 出稿后，按当前任务标签命中取本库 **TOP 2–3**，作为"设计观"一句话注入（与 lessons TOP 3、design-blocks TOP 2 并列，均不阻塞）。
- **B09 检查表**：评审蓝图时逐条问"这条设计观在蓝图里体现了没有？"——体现处引用 DP 编号；未体现且适用 → 记入 B10 复盘或当场补。
- **蓝图回填（引用追踪）**：某条原则影响了 `03-观点.md` / `06-决策.md` 的决策时，在该处标注"引用 DP-XXX"——**原则使用率可追踪**，这是设计产出"非普通流水线施工图"的直接证据。
- **写入时机**：新增/修订 DP 条目时（含参考外部实现的元设计升维产物）落库到本库，入库前过 §一三判据 + 用户拍板。

# 设计切片：tencent-docs-1.0.41 — 亮点清单

> **来源**：`<本地参考目录>/tencent-docs-1.0.41`（腾讯文档官方 MCP 管理器，~100 文件）

> **一句话**：三级渐进披露 + 状态脚本 + 设计契约 + 强制校验回复，把 LLM 的自由发挥压进可验收的轨道。
> **编号说明**：T-A01 ~ T-A15 为临时编号，入库时由 skill-designer 统一分配正式编号。

## B02 事实积木

### T-A01 · 文件目录自述图
- **落位**：B02 事实 / B07 计划
- **触发信号**：skill 文件数 > 10，agent 需要定位"去哪找什么"
- **证据**：SKILL.md L94-129 内嵌完整文件树，每行一句话职责（`aipage_pack.js  # 本地 HTML 打包成 .aipage`）
- **要点**：SKILL.md 里放一张"文件树 + 每文件一句话职责"的自述图，agent 免去 ls 猜测，一次读完全图；validate 可低成本校验"目录图与实际清单一致"。

### T-A02 · 品类能力总表带推荐度
- **落位**：B02 事实 / B06 决策
- **触发信号**：同一诉求有多种可选载体（9 种 doc_type）
- **证据**：SKILL.md L14-27 品类表，每类带 doc_type 值 + ⭐ 推荐度 + 一句说明（"Word 传统格式，排版一般 ⭐⭐"）
- **要点**：可选方案表不只列"有什么"，还列**推荐度**——agent 无需逐个试错即可按推荐档位选型。

## B04 问题积木

### T-A03 · 能力缺口静默遥测
- **落位**：B04 问题 / B10 复盘
- **触发信号**：用户意图在工具集里找不到对应能力
- **证据**：references/unsupported_feature_reporting.md——上报时机两条 + 参数规范三字段（feature 动宾短语 / user_prompt 用户原话不改写 / doc_type），"静默调用，无需告知用户"
- **要点**：把"做不了"从死路变成数据通路：结构化上报（意图原话 + 场景类型）回流上游，且不打断用户体验。

## B06 决策积木

### T-A04 · 正负双路由 + 错误码互证
- **落位**：B06 决策 / B07 计划
- **触发信号**：多品类/多工具易混淆时
- **证据**：SKILL.md L62"严禁用 A 品类的工具去改 B 品类文档" + L209 错误码 400016 专指品类误用并给出纠正步骤
- **要点**：路由不只说"该用什么"，还说"千万别用什么"；且负向规则有对应错误码兜底——文档纪律与运行时校验互相印证，双重防线。

### T-A05 · 量化触发条件的硬纪律
- **落位**：B06 决策 / B08 行动
- **触发信号**：想把性能/成本纪律写进 skill 时
- **证据**：SKILL.md L187"连续 3 次及以上的数据写入……必须使用批量写入接口，严禁用单条写入接口循环多次调用"
- **要点**：纪律写成「可判定阈值 + 强制动词 + 违规后果」，不写"建议尽量"——agent 能自检是否触线，规则才可执行。

## B07 计划积木

### T-A06 · 三级渐进披露（品类模块变体）
- **落位**：B07 计划
- **触发信号**：领域含 2–8 个正交子域，全塞 SKILL.md 装不下
- **证据**：SKILL.md（~240 行路由器）→ smartcanvas/doc/slide/sheet 各自 entry.md（品类全工作流）→ component-*.md ×12（单组件语法）；slide/entry.md L163"每页用到什么组件再读哪个文件，不要一次读全"
- **要点**：比 cloudbase A-075 的"子 skill 套件"更轻的 suite 变体：路由器 + N 个 entry.md 品类模块 + 组件级规范，token 成本按需发生。

### T-A07 · 状态脚本模式（探测+决策一次调用）
- **落位**：B07 计划 / B08 行动
- **触发信号**：写类操作前需要先探查外部系统状态再分支
- **证据**：get_slide_info.sh 返回单行 JSON `{"action":"write_design_md","reason":"design_is_empty",...}`，entry.md L49-54 给 reason→下一步决策表；"不把 MCP 原始大 JSON 写入上下文"
- **要点**：把"探测+决策"封装成一个脚本：输出单行机器可判定 JSON + 文档层查表，agent 不读大 JSON、不做自由判断。

### T-A08 · 设计契约模式（DESIGN 前置 + 自检门禁）
- **落位**：B07 计划
- **触发信号**：复杂产出物（PPT/报告/蓝图）质量依赖前置设计
- **证据**：design-principle.md——8 段必填结构 + "不满足以下任一项，重写 DESIGN"自检门禁（有具体 hex/字体/母版边界/逐页映射表/视觉锚点/密度约束）
- **要点**：复杂写类操作前置一份**结构化契约**（不是叙事），契约末尾带可判定的自检门禁；契约只回答"应该长什么样"，内容大纲与契约分离。

### T-A09 · 人机协作时序硬规则（⛔ 停止点）
- **落位**：B07 计划 / B08 行动
- **触发信号**：工作流包含"需要用户在真实世界完成动作再继续"的环节
- **证据**：auth.md L17"⛔ 严格禁止：收到 AUTH_REQUIRED 后，必须先向用户展示授权链接，等待用户发送新消息确认……" + L79"⛔ AI 注意：展示后必须停止等待，不得自动调用任何工具"
- **要点**：凡需要用户动作的等待，显式声明**停止点**（⛔ AI 注意），列出每个输出分支的去向话术——防 agent 抢跑轮询，把时序协议写成文档内硬约束。

### T-A10 · 失败降级路径明文化
- **落位**：B07 计划
- **触发信号**：每条工作流的故障模式可预知
- **证据**：SKILL.md L189"文件格式是否支持由后端判定，收到'不支持'错误时再降级到其他通路"；smartcanvas/entry.md L74"图片过大上传失败必须先压缩再传，严禁回退使用 URL"；edit 定位"find 优先→read 降级"
- **要点**：每条工作流写明**首选通路 + 触发条件 + 降级去向 + 禁止行为**，降级是有向边，不是"自行想办法"。

## B08 行动积木

### T-A11 · 读-改配对协议
- **落位**：B08 行动
- **触发信号**：编辑型操作有锚点/版本一致性风险
- **证据**：smartcanvas/entry.md L349"UPDATE 和 DELETE 操作的 id 参数必须来源于 find 或 read 的返回结果，禁止未获取文档数据直接传入 id" + readonly 组件禁作锚点
- **要点**：所有写操作强制"先读后改"配对：锚点必须来自最近一次真实读取，杜绝盲改；只读对象显式标注并禁用作锚点。

### T-A12 · 边界场景规范节
- **落位**：B08 行动
- **触发信号**：工具有长尾边界（容器删空、嵌套删除、只读块）
- **证据**：smartcanvas/entry.md L413-497"边界场景处理规范"五节，逐条"场景→操作方式→反例 JSON"（删剩 1 列整体替换、空 Callout 连容器删、TableRow 禁止单独存在）
- **要点**：长尾边界不靠 agent 试错，独立成节前置成文档，每条带反例 JSON 示范错误做法。

### T-A13 · 串行纪律 + 显式参数防并发错乱
- **落位**：B08 行动
- **触发信号**：底层写入有顺序/锁敏感性
- **证据**：slide/entry.md L164-168"严禁并发调用，必须严格串行；每次调用必须显式传 page_index，禁止依赖调用顺序决定页面顺序" + 末尾追加策略（预计算 `page_index = base + k - 1`，批内不动态取总数）
- **要点**：把分布式写入的顺序风险在**调用纪律层**解决：强制串行 + 显式序号 + 预计算区间，不依赖隐式默认行为。

## B10 复盘积木

### T-A14 · 完成后校验清单 + 强制回复规范
- **落位**：B10 复盘
- **触发信号**：写类工作流的交付验收
- **证据**：slide/entry.md §6——校验五项（页数/关键文本/残留空白页/DESIGN 符合度/顺序对账）+ 6.1 强制给链接（来源三级优先级）+ 6.2"回复只说：完成了什么/影响了哪些页/链接/风险点，不要输出内部长流程"
- **要点**：交付确定性双保险——**验收有清单**（不一致先修正再回复"完成"）+ **回复有格式**（说什么、不说什么、链接从哪来）。

### T-A15 · 外置 prompt 资源化
- **落位**：B07 计划 / B02 事实
- **触发信号**：SKILL.md body 逼近 token 红线但内容必须保留
- **证据**：doc/doc_format/prompt/ 三个 prompt.txt（场景识别/纯文本转 XML/样式解析）+ templates/ 5 个场景 JSON（schema 带 description/required/multiple 字段）；doc/entry.md 仅 60 行纯转发
- **要点**：第三条瘦身路径——不是删内容，而是**把长 prompt/模板移成按需读取的资源文件**，路由层留一句指引；模板 schema 自描述（字段含义写进 JSON），agent 读一个文件即能生成。

## ③ 根因（归并后，不是罗列）

五项非"更强/持平"里，**四项收敛到两个根因**：

### 根因 A · 跨落点一致性只靠人工，没有机器校验

**涵盖**：T10（横切纪律是否真在 4 份文档都写了）+ **自省新发现 G4**。

- **本会话实证复现**：条目库 132 条，**视图一 B01 声明 11 条而 ID 列表只有 10 个（漏 D-127）**——声明与列表对不上，直到本次吸收才被人工发现。validate **第 10 项只查 `references/README.md` 的体量列**，**查不到库内双视图/速查表/分片条数**这四处的一致性。
- 与既有教训同构：`L8 分型粒度`、smart-charts 的 D1（③索引三处全漏 D-062）——**同一根因第三次发作**。
- 已收条目 **D-132** 只保证"教训 → 检查项"被登记，**没保证登记后的检查项真的建起来**。

### 根因 B · 门禁的对象是"成品"，不是"过程"

**涵盖**：T7（真空缺）+ T4 + T6 + T9。

- 我们的 15 项静态检查 + `package` 三段门禁，**全部在"文件已生成之后"执行**；`package` 的卫生扫描还是**黑名单**（`__pycache__` / `*.pyc` / `*.bak`），只防"包被污染"，不防"**过程乱造文件**"。
- **活证据（本会话现场）**：`outputs/` 下至今堆着 **6 个测试夹具目录**（`_fixture_check12` / `_fixture_check13` / `_fixture_check15` / `_fixture_check_descblock` / `_fixture_check_desccolon` / `_fixture_dims_crash` + 2 个运行输出 `.err/.json`）——**没有任何机制告诉我"本轮任务新建了哪些文件"**。这正是 tencent-news 用"前置快照 + 交付前 diff"要解决的问题。
- **🔴 照出我们违纪（P0 级）**：我们 **v3.14.0 刚立的 DP-208「源头拦截优先于终点修补」**说"能挡在动作发生前，就别拖到事后检测"——**我们自己没做到**：我们有的事前机制（四步流 ⛔ 停止点、B10 两道必答项）**对象都是"设计内容"**；对"**执行过程的产物范围**"（T7）与"**跨落点一致性**"（根因 A），防线**全在终点**。**立原则未在自己身上落地。**

## ④ 真实差距（机制之外的诚实差异）

| # | 差异 | 说明 |
|:--:|---|---|
| 1 | **自评 ≠ 实战** | 我们 `validate --self` 15 项全过，**不等于内容不滞后**（lessons 已记三次实证）。本样本二次印证：本次吸收前，"视图一漏 D-127"在 15 项全过的情况下**静静躺了很多天**。 |
| 2 | **版本号 ≠ 使用量**（纪律④活例） | tencent-news 版本已迭代到 **1.2.3**（3 个 minor），而**本机零次成功运行、CLI 未安装**。版本号只说明作者改了几次 → **不用版本号推断质量或普及度**。 |
| 3 | **出生体量 vs 存活能力** | 它主路由 142 行、能力文档结构整齐——但这些**只证明设计期精悍**。我们**拿不到它任何运行数据**（无产物 / 无日志 / 无回流载体），因此**不能**说"它活得好"。本条落在我们身上同理：我们**被外部验收时也拿不出运行期证据**——除非把 lessons 的"存活度 L1–L4"变成**产物化**（本轮尚未落地）。 |
| 4 | **不适用项不硬补** | T3 双平台脚本对：`sd_cli.py` 是跨平台 Python，补 `.ps1/.sh` 双份是**过度设计**（与 README 里"沙箱 PoC 建议不补"同判）。 |

## 附 · 本样本对 benchmark 模式的回归验证结论

> 第三个样本（前两样本：① westock-data 证明模式**能跑**，② fin-information-pipeline 证明模式**有边界**并逼出第四层）。本样本首次为**刚安装的外部商城包**。

| 回归项 | 结论 |
|---|:--:|
| 五步法（B1–B5）可否复用 | ✅ 可复用，B1→B3→B4 链路顺畅 |
| B1 必须含运行期特质的硬要求是否有效 | ✅ **有效**——正是它让我们在立标阶段就写下"运行期不可验"，而非到 B3.5 才发现 |
| v0.9.0「样本分类」前置（外部包即标不可验）是否有效 | ✅ **有效**——避免了"先翻产物目录找痕迹"的白跑一轮 |
| 反向判据（全项 ✓ 先怀疑）是否有效 | ✅ 有效（本表非全项 ✓，未触发误报） |
| 根因归并是否有效 | ✅ **有效**——5 项收敛为 2 根因，避免散点补条目 |
| **模式是否有缺口** | ⚠️ **有一个**：本轮"照出自己违纪"（DP-208 未落地）**落点不明**——B5 说"照出违纪 → 升为 P0"，但**没给落点载体**（入哪条 lessons？补哪份文档？）。建议 benchmark-mode 在 B5 补一句"违纪项 → lessons 新条目 + 当轮固定自查动作"。 |
| 是否照出自己违纪 | ✅ **照出 1 项**（DP-208 源头拦截未在自己流程落地）——**比 15 条亮点更值钱** |

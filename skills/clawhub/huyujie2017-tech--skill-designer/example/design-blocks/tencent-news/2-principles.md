## DP-209 · 权威源唯一化：其余全是引用或被拒

- **原则概述**：任何**数据 / 规则 / 身份 / 代码**都只允许有一处权威来源，其他所有出现处一律降格为**引用**（能自动生成就不手写）或**被拒绝**（伪造即报错）。判断一个 skill 有没有真正做到这点，看它**对"第二份"的态度**：是"记得同步"（人工纪律，必然漂移），还是"根本不给你出现第二份的机会"（结构约束）。
- **解释力（6 条，超准入线 3）**：
  - **D-142** 调用方身份从 `SKILL.md` frontmatter **运行时解析**（不是 agent 手填），且 `--caller` **手填即 fail** → 身份权威源唯一 = frontmatter，其余出现处（命令行）**被拒**；
  - **D-144** 全下游只读 `recommendationSnapshot` 一个对象，**禁止跨阶段二次查询** → 数据权威源唯一 = 快照；
  - **D-138** 位次必须以权威源（一分一段）核定，**用户自报值不得传入推荐引擎、不得在后续步骤重新覆盖** → 事实权威源唯一 = 权威源；
  - **D-140** 数据只从 CLI 取，**禁止 WebSearch / 模型记忆 / 旧会话补做** → 数据源唯一；
  - **D-135** 环境状态只由状态脚本一次输出（`cliExists` / `apiKey.status`），门禁按**字段值**分流而非按人读错误串猜 → 状态权威源唯一；
  - **D-139** 纪律冲突时按**声明的优先级**裁决（环境指引 > 输出格式 > 单产物限制），而非 agent 临场择一 → 约束权威源唯一。
- **适用场景**：标签 `一致性/双落点/单一事实来源/防漂移/遥测可信`。触发信号：① 同一内容/字段/参数出现在 ≥2 处；② 发现自己在写"记得同步…"；③ 同一事实需多处消费；④ 出现"声明值"与"实际值"两个来源。
- **落地要点**：落 **B06 决策 + B07 计划**。三条可操作动作：
  1. **能生成就别手写**——一处为源，其余由源**生成**（我们 v3.10.0 的 DP-204 已就这条落地：`blocks.py` → `gen_blueprint_fields --write` → 模板）；
  2. **不能生成就拒绝**——对"第二份"加**守卫**（如 D-142 的 `has_caller_flag` → fail），让违反者立刻报错而非静默生效；
  3. **必须并存就绑证据**——给每份配可核对的出生证明（哈希 / 时间戳 / 计数），事后能证明"是不是同一份"（D-144）。
- **与既有 DP 的关系**：
  - **DP-204 单一事实来源优先于同步纪律** 是这条在**代码/文档**层的落点（能引用就别同步）；
  - **DP-209 是其上位设计观**：把"单一事实来源"从"文件之间的关系"扩到**身份、数据、状态、约束**四类对象，并补上 DP-204 没有的第三动作（**绑定完整性证据**）与第二动作（**主动拒绝**）。
  - 与 **DP-207 有限资源分层承载** 不冲突：那是"同事实的不同抽象层级"（一等规则 / 二等实例），不是同一内容的双份拷贝。
- **来源**：tencent-news 1.2.3（SkillHub 商城安装），经 skill-rebuild 反向吸收 + 元设计升维。支撑条目 **D-133**、**D-135**、**D-138**、**D-139**、**D-140**、**D-142**、**D-144**。
- **example**：[`example/design-blocks/tencent-news/1-highlights.md`](1-highlights.md)（D-142 / D-144 的证据行号最完整）。

## DP-210 · 失败即熔断，不得向右兜底

- **原则概述**：外部依赖出错时，agent 有**两个方向**可走——**向左**：停下来、说清、给可执行的替代动作；**向右**：重试 / 换数据源 / 用模型记忆补 / 把 A 类错误解释成 B 类。左侧的输出**看起来是失败的**，右侧的输出**看起来是成功的**——所以在没有约束时，默认行为必然向右。熔断设计就是**把向右的路全部封死**，只留向左。
- **解释力（4 条，超准入线 3）**：
  - **D-135** 环境未就绪 → **不得只回"数据加载失败/请检查配置"**，必须按状态给可执行命令（左侧动作，且明确禁止泛化回复）；
  - **D-138** 数据冲突 → **阻断下游全部产出**，连"假设按自报位次的备选结果"也不给（右侧最诱人的那条路：给个折中版）；
  - **D-140** 失败 → 不重试、不换命令、**不换数据源**、失败不授权新动作（封死右侧所有分支）；
  - **D-141** 归因 → **不得把鉴权失败说成无数据/额度用完/网络失败**——这是最隐蔽的向右（输出形态完全正常，只是把需要用户行动的错误说成了不需要行动的）。
- **适用场景**：标签 `失败处理/熔断/数据源唯一/错误归因/兜底禁令`。触发信号：① skill 依赖外部 CLI/API/授权；② 失败后"没有输出"会显得任务没完成（压力全在向右）；③ 同一症状可能对应多种原因。
- **落地要点**：落 **B04 问题（门禁）+ B06 决策（失败处置）**。写成**四拦 + 一向**：
  - 拦①**不重试**（不自动重跑）；拦②**不换源**（不用 WebSearch / 模型记忆 / 缓存 / 旧结果）；拦③**不编造**（失败不得输出"参考版 / 示例版 / 经验版"）；拦④**不降级解释**（鉴权 ≠ 无数据 ≠ 额度 ≠ 网络）；
  - 一向：**必须给一个可执行的替代动作**（安装命令 / 获取 Key 的页面 / 稍后重试的口径）——熔断不等于沉默。
  - **纪律要写在实际执行时加载的那份文档里**：tencent-news 把同款失败纪律在 4/4 份能力文档中逐份重述（`factcheck.md` / `weather.md` / `weather-alert.md` / `gaokao-volunteer.md`），不只在主路由写一次。
- **与既有 DP 的关系**：与 **DP-001 不可逆优先门禁**（可逆性决定确认等级）互补——DP-001 管"动作前要不要问"，DP-210 管"出错后往哪走"；与 **DP-002 错误即修复指引**同向（错误消息 = 行动指令），但本原则强调**先封住右侧**，再谈指引质量（指引写得再好，若同时留着"换源"这条路，agent 仍会走右边）。
- **来源**：tencent-news 1.2.3。支撑条目 **D-135**、**D-138**、**D-140**、**D-141**。
- **example**：[`example/design-blocks/tencent-news/1-highlights.md`](1-highlights.md)（D-140 的 4/4 重述证据）；反面对照见 `example/benchmark/1-fin-information-pipeline.md` 的 6 条教训零回流（失效模式之一是"没输出也不好意思说"）。

## DP-211 · 验收先问执行者能力：做不到就换成等价的静态判定

- **原则概述**：写一条验收项之前，先问**两个**问题，而不是一个：
  1. **能不能判**（是否机器可判）？—— 我们已有（validate 严格度判据）。
  2. **执行者做不做得到**？—— 本条补的那一半。
  写"用浏览器点一遍所有 Tab"满足①不满足②：机器可判，但 agent 没有浏览器，**结果是这条验收永远被静默跳过**（清单 18 条、有效 12 条）。正确做法是**先声明能力前提**，再把每条验收**翻译成同等效力的静态判据**，并显式豁免"做不到就换个做法"。
- **解释力（4 条，超准入线 3）**：
  - **D-145** 明写"不要求 Agent 具备真实浏览器"，18 条验收全部改写为静态判定（解析内联 JSON 用**数组长度**代替"看页面"；源码 grep 代替"点一遍"），并声明"无需生成浏览器自检函数"；
  - **D-146** 用"**任务开始 vs 交付前的文件清单 diff**"代替构建系统审计（不依赖 git / 版本控制）；
  - **D-143** 用"**空页**"这个响应事实代替"累计达到 total 就该停"这类声明值（不依赖服务端诚实）；
  - **D-147** 用"**逐字比对 + 结构位置断言**"代替"人工读一遍确认有免责声明"。
- **适用场景**：标签 `验收设计/自检/可执行率/静态判定/能力前提`。触发信号：① 写交付前验收清单；② 某条验收需要"人眼/浏览器/运行时环境"；③ 验收项数看起来很多但没人跑过全量。
- **落地要点**：落 **B09 结果**。三段式：
  1. **开篇声明能力前提**（本验收假定执行者具备 / 不具备什么）；
  2. **逐条把"运行时判据"翻译为"静态判据"**（读产物源码 / 解析内联 JSON / 文件清单 diff / 逐字比对——四种可复用的静态等价物）；
  3. **显式豁免替代物**（"不需要生成浏览器自检函数"）——否则 agent 会为了满足①而**造假**（写一个永远返回 true 的自检函数）。
- **与既有 DP 的关系**：与 **DP-206 安全与质量机制必须有对立面用例** 正交（DP-206 管"用例方向要对立"，本原则管"用例形态要可执行"）；与我们的 `严格度判据 = 是否机器可判` 互补成一条完整判据链：**先问做不做得到，再问判不判得出**。与 **DP-203 约束前置 + 完整性自检**同族（都是"前置必须配自检"），但本原则指出一种前置失效：**自检本身不可执行**。
- **来源**：tencent-news 1.2.3。支撑条目 **D-143**、**D-145**、**D-146**、**D-147**。
- **example**：[`example/design-blocks/tencent-news/4-self-benchmark.md`](4-self-benchmark.md)（本原则正是自省环节照出我们一处**真缺口**——产物范围门禁，见 G2）。

## 「不可判 → 可判」替换表（DP-211 的操作件）

> 写验收时逐行对照：左边这种写法会变成"永远被跳过的验收"，右边是可执行的等价物。

| 不可执行的写法 | 静态等价物 | 依据 |
|---|---|---|
| 用浏览器点一遍每个 Tab，确认面板切换正常 | 源码 grep：无重复 `id`、无 `href="#..."` 伪 Tab、每组恰一个面板非 `hidden`、脚本含 `panel.hidden = panel !== targetPanel` | D-145 |
| 在页面上数一下有多少张卡片 | 解析内联 JSON，取 `data-candidate-source` **数组实际长度** | D-145 D-143 |
| 手动确认免责声明在页面上 | 逐字比对固定原文 + 断言"包含且仅包含一次" + 断言不在 `hidden` 面板内 | D-147 |
| 检查生成过程有没有留下临时文件 | 任务开始前记录文件清单 → 交付前 diff → **本次新建数必须 = 0** | D-146 |
| 跑一遍看看分页对不对 | 断言调用日志中每个 `start` **只出现一次**、调用数 ∈ {N, N+1}、终止条件为**空页** | D-143 D-144 |
| 看数据是不是同一批 | 比对每页**字节长度 + SHA-256 + 严格解析标记** | D-144 |

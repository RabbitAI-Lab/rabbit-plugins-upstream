- **证据**：`scripts/run-cli.sh` 三层设计——① **自动注入**：`resolve_skill_caller()`（L22-66）运行时用 `awk` 解析本 skill `SKILL.md` frontmatter，取 `name` + `version` 拼成 `tencent-news_1.2.3` 作 caller（不写死、不靠 agent 记忆）；② **能力协商**：`supports_caller_arg()`（L116-125）先跑 `"$CLI_PATH" version`，解析 `current_version` 并 `compare_versions "$current_version" "1.0.12"`，**版本够才注入**（`exec "$CLI_PATH" "$@" --caller "$CALLER"`，L155-159），否则原样透传；③ **拒绝手填**：`has_caller_flag()`（L68-77）扫全部参数，命中 `--caller` / `--caller=*` 即 `fail "do not pass --caller manually; scripts/run-cli.sh injects it from SKILL.md"`
- **要点**：三点缺一不可——**没有①**，调用方标识靠 agent 每次手填（必然漏填/填错）；**没有②**，新参数打到旧版二进制上直接报错（前后端版本不能同频时不可用）；**没有③**，agent 可以伪造身份（遥测数据被污染，且"手填一次成功"后就会一直手填）。它把"调用方身份"从**约定**变成**机制**。回照自己：我们 `sd_cli.py` 的 `--retries` / `--dry-run` 等参数由 agent 显式传（漏传即退化为默认），**没有"从 frontmatter 自动注入身份/上下文字段"的先例**，也没有"某参数禁止手填"的守卫——可迁移到 `--bp-name` 这类本可自动推断的参数
- **抗绕过性**：**signal**（版本号比较 + 参数存在性扫描，都是机器可判的硬检查）
- **标签** `适用: 涉及脚本` `适用: 需要外部调用` `适用: 版本频繁变化`

### D-143 · 分页终止按「响应实际返回条数」，不按请求参数或累计值
- **主题** T8 工程·脚本·性能
- **落位**：B07 计划（数据契约）
- **触发信号**：消费任何分页 / 批量接口，且服务端可能截断请求条数时
- **证据**：`gaokao-volunteer.md:128`「`--size` 只是**期望**条数；服务端会把 60/100 等较大 `size` 截成 20。**不得因实际返回 20 小于请求值，就误判末页或 `start` 失效**」；`L133` 给出唯一正确判据：「**只有 `pageItems.length===0` 才正常结束**」，并同时禁用四种常见误判：`pageItems.length < 请求 size` / `pageItems.length === 20` / 累计达到 `total` / `while(length===size)`；`L132` 给调用次数硬上限 `N` 或 `N+1`；`L134` 要求「每页比较完整 ID 序列（至少首尾 ID）——数量相同不代表重复页」
- **要点**：分页 bug 的根因几乎都是**把"请求参数"当权威**（我请求了 100 条，返回 100 条就是满页）——服务端截断后这个假设立刻失效，表现为"只抓到第一页就停了"。正解是**以响应为准**：唯一终止条件是空页，且用**结构信号**（ID 序列变化）而非数量判断重复页。这是 `"声明值 ≠ 实际值"` 的一个通用实例，可迁移到任何 API 消费。回照自己：我们 `run_user_tests` / `evals` 是本地用例集，不涉及分页；但 `sd_cli package` 的"包完整性三查"已是同族思路（不信任"打包成功"这个声明，解包重验）——本条可作 B07 数据契约的通用条目备用
- **抗绕过性**：**signal**（空页 + ID 序列比对，可机器判定）
- **标签** `适用: 需要外部调用` `适用: 数据量大`

### D-144 · 单次快照 + 完整性证据绑定：一次查询一份内存快照，全下游只读，禁跨阶段二次查询
- **主题** T2 契约与验收
- **落位**：B08 行动（数据所有权）
- **触发信号**：同一批外部数据要被多处消费（渲染 / 分页 / 筛选 / 摘要 / 验收）时
- **证据**：`gaokao-volunteer.md:117-118`「**推荐数据单次获取、单一内存所有权**：从首次调用开始直到 HTML 交付，必须处于同一个连续执行上下文，并维护唯一的 `recommendationSnapshot` 内存对象…该快照是生成 HTML、Tab、前端分页、筛选、字段映射、静态验收与最终摘要的**唯一数据输入**；**这些后续阶段严禁再次调用**」；`L118`「**禁止任何跨阶段二次查询**…不得把『获取数据』和『生成 HTML』拆成两个各自调用 CLI 的子任务」；完整性证据在 `L125-127`「每一页**先完整性校验、后解析**」（非空 + UTF-8 严格解码 + 无 `U+FFFD` + JSON 完整闭合）；「**快照必须保存完整性证据**：每页保存原始字节长度、SHA-256、严格 JSON 解析成功标记、候选数与 start」；`L126` 平台大输出缓存「**仅可校验、不可取数**」；验收第 16/17 项（`L249-250`）复核每页证据齐全、且日志中无第二轮 `start=0` 序列
- **要点**：数据被消费 N 次，就有 N 次"两边不一致"的机会。它的解法是把 N 次消费收敛到 **1 次获取 + 1 份快照**，并给快照配**可验证的出生证明**（字节长 / 哈希 / 解析标记）——任何"看起来不对"都能回溯到"是不是同一份"。与 `D-087 双消费同一内核`同源（都是消灭多份副本），但 **D-087 管代码（谁都不许私改公式），本条管运行时数据（谁都不许再查一次）**。回照自己：我们 `validate --self` 与 `package` 会**多次读同一批源文件**（validate 一次、prepare_release 一次、包内 validate 再一次），未做"读一次、全下游复用"的快照化，也未给读到的输入留哈希——若中途有并发写入（lessons 已记"同一文件并发 Edit 静默失败"），无法证明三次读的是同一版
- **抗绕过性**：**signal**（哈希 + 调用日志中 `start=0` 出现次数，均可机器核对）
- **标签** `适用: 数据量大` `适用: 涉及脚本` `适用: 需要外部调用`

### D-145 · 验收清单必须匹配执行者能力：做不到就换成等价的静态判定
- **主题** T10 可验证性·防自欺
- **落位**：B09 结果（验收设计）
- **触发信号**：为 skill 写交付前验收清单时
- **证据**：`gaokao-volunteer.md:230-232` 开篇即声明能力前提：「生成后读取最终 HTML 并执行静态验收；**不要求 Agent 具备真实浏览器或自动化测试能力**」；`L238` 再确认「**无需生成或保留浏览器自检函数，Agent 缺少浏览器能力不阻止交付**」。于是 18 条验收（`L234-251`）**全部改写为静态可判定动作**：解析 `[data-candidate-source]` JSON 用**数组实际长度**代替"看页面显示几条"（`L239`）；用源码 grep 断言"无重复 id / 无 `href="#..."` / 每个 `data-paginated-panel` 恰有一个 `role="tabpanel"` 内的 `data-candidate-list` 后代"（`L235-239,242`）；用"任务开始 vs 交付前文件清单比对"代替构建系统审计（`L247`）
- **要点**：我们已有`严格度判据 = 是否机器可判`（validate 1/2/3/4/7/13/14 FAIL，5/8/9/10/11/12 WARN）。本条补的是**另一个前置问题**：判据"能不能判"之外，还要问**"执行者（agent）做不做得到"**。写"用浏览器点一遍所有 Tab"——机器可判，但 agent 做不到，结果就是**这条验收永远被跳过**（清单看起来 18 条，实际有效 12 条）。它的做法是**先声明能力前提，再把每条验收翻译成同等的静态判据**，并显式豁免"做不到就不做"的替代物（不生成浏览器自检函数）。**这是"验收清单可执行率"的前置把关**。
- **抗绕过性**：**signal**（静态判据本身就是可机器复跑的核对项）
- **标签** `适用: 有交付产物` `适用: 输出可客观验证`

### D-146 · 产物范围门禁：单文件白名单 + 交付前后文件清单 diff
- **主题** T2 契约与验收
- **落位**：B10 复盘（交付纪律）
- **触发信号**：skill 的交付物是"一个成品文件"，但生成过程天然会想造中间文件时
- **证据**：`gaokao-volunteer.md:97`「**冲稳保方案任务实行单文件白名单，唯一允许创建并保留的文件是最终 `.html`**。不得创建、写入或保留任何第二个文件，包括但不限于 `generate.py`…`.md/.txt` 总结，JSON/CSV 数据，日志、截图、测试页、临时 HTML、缓存或中间产物。**该规则约束整个执行过程，而不只是最终交付物**」；`L98` 封死绕道（"不得以『辅助生成』『便于复现』『数据太多』『验证交互』或『稍后删除』为由先创建工作区创建这些文件"）；`L100` 给**可执行验收动作**：「**开始生成前记录工作区已有文件，交付前核对本次新建文件清单：除约定的最终 HTML 外，本次任务新建文件数必须为 0**。若误建…必须删除本次误建文件后再交付；**严禁删除或覆盖任务开始前已存在的用户文件**」；`L247` 在验收第 14 项再检一遍
- **要点**：三个设计点：**(a) 白名单而非黑名单**（"只许 1 个"比"不许 6 种"更难绕过——黑名单永远列不全）；**(b) 约束过程而非只约束交付物**（否则 agent 会"先造后删"，而删除常失败）；**(c) 用文件清单 diff 把纪律变成动作**（"别乱建文件"不可判，"本次新建数=0"可判——且**前置快照 + 交付前比对**是唯一能查出来的办法）。回照自己：**这一条直接照出我们的真实行为**——`sd_cli package` 只扫 `__pycache__/*.pyc/*.bak`（黑名单），**没有任何"产物范围"约束**；本轮之前留下的 `outputs/_fixture_check12/13/15`、`_fixture_dims_crash*`、`_fixture_check_descblock/desccolon` 六个夹具目录至今堆在 `outputs/`，**正是"过程产物无门禁"的活证据**（见自省 G2）
- **抗绕过性**：**signal**（文件清单 diff 可执行、结果可数）
- **标签** `适用: 有交付产物` `适用: 涉及脚本` `适用: 自动化/长流程`

### D-147 · 合规文案逐字固定 + 位置约束，并二次进验收清单
- **主题** T2 契约与验收
- **落位**：B10 复盘（输出规范）
- **触发信号**：产物含法定 / 合规 / 免责类定稿文案（不得改写）时
- **证据**：`gaokao-volunteer.md:13` 在「服务范围与边界」顶部就定死：「所有用户可见结果必须**逐字使用固定免责声明**：`本系统数据仅供参考，不构成填报决策依据，请自行核验信息，并对填报内容真实性负责。` **不得改写、缩写、扩写或用其他免责声明替代**」；三处位置约束分别声明——对话摘要（`L260`「末尾**单独、完整、逐字**保留…不得在该句中插入数据来源或其他文字」）、HTML 页尾（`L228`「单独、完整、逐字展示…来源和生成时间**不得与免责声明合并改写**」）、**归属约束**（`L248` 验收第 15 项「该文案**不得位于会被 Tab 切换隐藏的面板内**」）；最后在交付前验收清单里**再检一遍**（`L248`「包含**且仅包含**」）
- **要点**：合规文案的失效方式不是"忘了写"，而是三种**看起来更像样**的改写：**合并**（把来源和免责声明拼成一句）、**缩写**（省掉"请自行核验"）、**藏起来**（放进默认隐藏的 Tab 面板里——DOM 里有，用户看不见）。所以约束要写成三件套：**逐字原文 + 位置约束（哪块、不能被隐藏）+ 验收里再检一次（含"仅包含"以防套用两遍）**。回照自己：我们无合规免责声明，但**有同族问题**——`references` 元数据四件套（加载条件/核心主题/命中标签/不回答）与 validate 第 9 项的关系正是"格式定死 + 机器复核"；本条的价值在于补上"**位置约束**"这个维度（写在文件头 vs 写在正文末，效力不同）
- **抗绕过性**：**signal**（逐字比对 + 结构性位置断言，可机器判定）
- **标签** `适用: 有交付产物` `适用: 高风险领域` `适用: 输出可客观验证`

# 元设计：从 smart-charts 8.1.1 归纳的三条设计观

> **元设计是收录的第一产出**——对 skill-designer 这类元 skill，最值得学的不是功能，是**设计观**。
> 12 条亮点是元设计的支撑证据；这 3 条是可迁移的"我们该怎样设计"。

---

## DP-204 · 单一事实来源优先于同步纪律

**原则概述**：凡出现"两处必须保持一致"的需求，第一解法是**把两处接到同一个内核**（import / 引用 / 一侧生成另一侧），而不是写一条"记得同步"的纪律。

**判据**：能否用引用替代人工同步？能就必须做。**人工同步的纪律无论写得多严厉，都会在第三次修改时失效。**

**支撑亮点与实证**：

| 亮点 | 它的做法 | 我们的反例 |
|---|---|---|
| A-513 | `stats_kernels.py` 被 renderers 与 plot_stats 双引用，模块头写死"任何一侧不得私改公式" | 蓝图两套骨架（blocks.py ↔ blueprint-template.md），2026-09-03 G1 事故根因；至今靠 grep 人工同步 |
| A-514 | `__init__.py` 声明版本唯一权威源 + 校验责任方 | 版本双落点纪律只存在于 AI 记忆文件 |
| A-522 | 13 个模块头写"不得各自维护文案副本""不再散落硬编码颜色" | references 只写"做什么"，缺否定式约束 |

**为什么这条最值钱**：我们不是不知道这件事——lessons L8 早就记录了事故。但 L8 开的药方是"**改任一侧必须同步另一侧**"，**仍然停留在纪律层**。DP-204 把药方升了一级：**能引用就别同步**。

**归并判据**：多项缺口若都表现为"靠人记住同步"，一律判**架构问题**，解法是引用/生成关系，**不写第 N 条同步纪律**。

## DP-205 · 可打断性由可逆性判定，不由礼貌判定

**原则概述**："要不要问用户"的正当理由是**可逆性三要素**（廉价 / 可逆 / 零外部副作用），不是"尽量少打扰"。

**判据应用**：
- 三要素成立 → 自主决策 + **事后显式列出关键假设**供审阅（把事前询问换成事后审阅）；
- 不成立 → 必须确认；
- 并在全链路**声明唯一必须介入点**，同时**封死绕开它的兜底路径**。

**支撑亮点与实证**：

| 亮点 | 它的做法 |
|---|---|
| A-518 | SKILL.md §默认策略："生成图表是廉价可逆动作（重生成 1-10s，零外部副作用）…图表类型/合并策略/口径均由 agent 内部决定，不打断用户。**事后审阅代替事前确认**：交付语中显式列出本次关键假设" |
| A-519 | "**唯一必须的用户介入点**：见 Exit Criteria 的『仍失败』分支" + 🛑 分支"**不得**静默改用自写脚本兜底" |
| A-521 | dry-run → 写解读 → 正式注入三步法，并声明"dry-run 不算交付" |

**为什么重要**："少打扰用户"是口号，无法判断执行得对不对；"**廉价 + 可逆 + 零副作用**"三条可以逐条验证。它同时做了两件我们没做的事：① 把假设**显式列出**而非藏在心里；② **封死兜底**（不得静默自写脚本）——否则 agent 会用"我自己搞定了"消解掉那个介入点。

## DP-206 · 安全与质量机制必须有对立面用例

**原则概述**：任何拦截 / 生成 / 断言类机制都要配**方向相反**的用例。

| 机制类型 | 必配的对立面用例 | 防的是什么 |
|---|---|---|
| 拦截器 | **零误报黄金正例**（合法输入不被拦） | 防"一律拒绝"的懒实现拿满分 |
| 生成类（含数字结论） | **出处白名单断言** | 防凭印象编造 |
| 安全类 | **真实逃逸 PoC**，断言到字段名 | 防拍脑袋列关键字 |

**支撑亮点与实证**：

| 亮点 | 它的做法 |
|---|---|
| A-516 | E8：5 个真实 dunder 逃逸 PoC（`__builtins__`/`__getattribute__`/`__loader__`/`__reduce__`/`__spec__`），断言 `code_name` **且** `violations` 字段名 |
| A-517 | U3"黄金零误报"：10 条合法 transform 断言**未被拦截** |
| A-520 | 硬边界："解读的每个数字都必须能在 plot_stats / data_preview 里找到出处"，并给语义映射示例（59 名学生 ≠ 59 个类别） |

**我们的位置**：
- 拦截方向 ✅ 有（validate 第 11/12 项反向测试夹具，本次抓出 5/8 违规 + 4 条豁免精准放过）；
- **误报方向 ❌ 缺**（我们只测"违规被报"，没测"合法不被报"）；
- 夹具是**临时的**（放 `outputs/_fixture_check12/`），它把黄金正例**内置进自检脚本**。

## 三条的关系

```
DP-204 一致性 → 靠架构（引用），不靠纪律
DP-205 介入点 → 靠判据（可逆性），不靠礼貌
DP-206 质量门 → 靠对立面用例，不靠单向断言
```

**共同点**：三条都在说同一件事——**把"应该"换成"可判"**。

| 不可判的说法 | 可判的替代 |
|---|---|
| "记得同步两边" | 两边 import 同一个内核 |
| "尽量少打扰用户" | 廉价+可逆+零副作用 → 不问；否则必须问 |
| "不要拦截合法输入" | 10 条黄金正例断言 `not v` |
| "不要编造数字" | 每个数字必须能在 X 字段找到出处 |

> 这正好接上 DP-201 失败模式驱动设计与 westock-data 的 M1：**先问"不写这条 agent 会犯什么错"**——DP-204/205/206 是它的下一层：不仅要有失败模式，还要把它**翻译成可判的判据**。

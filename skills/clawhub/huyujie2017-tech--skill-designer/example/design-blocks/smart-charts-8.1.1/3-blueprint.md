# smart-charts 8.1.1 逆向拆解蓝图（设计范例）

> 逆向拆解 = 不问"它有什么亮点"，而问"**它的整体架构是怎么搭的**"——把成品逆向成一张可复用的施工蓝图。
> 产出方式：读全部 21 个文件（13 py + SKILL.md + REFERENCE.md + 3 资产 + requirements + _meta），按六段式还原。
> 用途：当作**多模块工程型 skill** 的设计范例；与 `4-self-benchmark.md` 的"我们造不造得出"对照阅读。

---

## 一、总览定位

| 项 | 内容 |
|---|---|
| **一句话定位** | 把表格数据文件（CSV/Excel/JSON）变成**离线可用的交互式 ECharts HTML**，26 种图表类型，全流程 CLI 驱动，自带 133 项端到端回归自检 |
| **形态** | **C 工具编排型（tool）** + 重工程（13 个 py，约 190KB 代码 + 1MB 内联资产） |
| **版本** | 8.1.1（1 主版本 + 8 次迭代，说明经过长期打磨） |
| **网络依赖** | **零**——ECharts JS 内联进每个 HTML，断网可用（有 F12 断言守着） |
| **目标用户** | 让 agent 替终端用户"拿数据出图 + 出解读"，而非让工程师写代码 |
| **设计取舍** | 重代码轻文档：SKILL.md 仅 176 行（全部是**给 agent 的操作纪律**），REFERENCE.md 330 行（CLI 细节/FAQ），**实现细节全部下沉到模块头 docstring** |

## 二、架构分层

```
┌─────────────────────────────────────────────────────────────┐
│ L0 契约层   SKILL.md（176 行）                                │
│             契约5条 · 硬约束7条 · 选型表26类 · Exit Criteria  │
│             ↑ agent 唯一必读，其余全部按需                    │
├─────────────────────────────────────────────────────────────┤
│ L1 入口层   cli.py（224 行）                                  │
│             argparse 统一参数 → 结构化 JSON 错误              │
│             _bootstrap.py（28 行）sys.path 单点引导           │
├─────────────────────────────────────────────────────────────┤
│ L2 编排层   chart_generator.py（482 行）「纯编排」            │
│             参数校验 → 轴准备 → RenderContext → 调渲染器       │
├─────────────────────────────────────────────────────────────┤
│ L3 能力层   data_parser（637）  data_transformer（376·沙箱）   │
│             renderers（1185）  template（548）  plot_stats（409）│
├─────────────────────────────────────────────────────────────┤
│ L4 内核层   stats_kernels（167）⚠ 单一事实来源                │
│             texts（113 双语文案）  themes（103 配色）          │
│             ↑ 上层**必须引用**，不得各自维护副本               │
├─────────────────────────────────────────────────────────────┤
│ L5 支撑层   exceptions（76 错误码） regression_check（567 自检）│
└─────────────────────────────────────────────────────────────┘
```

**分层的关键设计**：**L4 内核层是整个架构的定海神针**。renderers（画图）与 plot_stats（报告摘要）消费同一批统计事实，若不抽内核，必然出现"图上看到的和文字说的不一致"——这是最难查的一类 bug。**它用 import 关系消灭了这个问题，而不是用纪律。**

## 三、模块划分（职责边界 + 否定式约束）

| 模块 | 行数 | 职责（写什么） | **不得做什么**（模块头原文） |
|---|---:|---|---|
| `cli.py` | 224 | argparse 统一参数解析 | 不再静默跳过未知 flag |
| `data_parser.py` | 637 | 多格式 → DataFrame，脏表头/编码回退 | 只解决"哪行是表头"，**其余清洗归 transform** |
| `data_transformer.py` | 376 | 执行 LLM 生成的 pandas 代码 | 三层校验（黑名单 + AST 白名单 + 安全 builtins） |
| `chart_generator.py` | 482 | 纯编排：校验→准备→调渲染 | 不做渲染本身 |
| `renderers.py` | 1185 | 26 类 ECharts option | 共享算法一律引用 stats_kernels |
| `plot_stats.py` | 409 | 26 类统计摘要（分 7 家族） | 任何一侧不得私改公式 |
| `template.py` | 548 | option → 独立 HTML | 不再散落硬编码颜色 |
| `stats_kernels.py` | 167 | **纯计算函数（单一事实来源）** | 上层不得各自实现 |
| `texts.py` | 113 | zh/en 双语文案 | 三层共用，**不得各自维护文案副本** |
| `themes.py` | 103 | 3 套主题配色 | 渲染器与模板统一从 `self._theme` 取色 |
| `exceptions.py` | 76 | 错误码枚举 + 结构化错误 | — |
| `regression_check.py` | 567 | 133 项端到端自检 | 真实 CLI 子进程，**非 mock** |
| `_bootstrap.py` | 28 | sys.path 引导 | **单点实现** |

> **这张表最值得抄的不是"职责"列，是"不得做什么"列。** 架构约定写在文档里会漂移，写在模块头里每次打开文件都可见。

## 四、核心工作流（两条主链）

### 链 A：单图生成（含"解读回填"三步法）

```
1. data_parser.py 无 flags 跑一次  → 看原始布局，数表头行数
2. 加 --header-row N / --skiprows N / --sheet 重跑
3. cli.py --dry-run                → 只算 plot_stats / data_preview，不落盘
4. agent 读 plot_stats 写 2~4 句解读（数字全部有出处）
5. 去掉 --dry-run + --annotation "解读" → 正式生成，解读注入 HTML
6. 校对：读 stdout 的 data_preview + data_rows（❌ 不是打开 HTML 搜数据）
```

**设计精髓**：把"AI 写内容"拆成 **取数 → 写作 → 注入** 三步，且取数与最终渲染同源。第 6 步的禁令尤其狠——"**不要打开 HTML 去搜数据**"，因为预览取自 transform 之后、渲染所用的同一份数据，才是被绘制内容的真值。

### 链 B：多图批量

```
≥2 张图 MUST 批量；含中文/引号的 transform 不直接 shell 传参
→ 写进 charts.json 用 --charts-file
→ 退出码 0 + per-chart 错误（部分成功），summary 汇总 succeeded/failed
```

## 五、可迁移设计模式表

| # | 模式 | 做法 | 搬到 skill-designer 的落点 |
|---|---|---|---|
| P1 | **单一事实来源内核** | 两处消费同一算法 → 抽内核 + 模块头写死"不得私改" | 蓝图两套骨架（blocks.py ↔ blueprint-template.md）应改为**一侧生成另一侧** |
| P2 | **否定式模块头契约** | 每个文件 docstring 写"不得做什么" | 我们的 references 只有"做什么"，缺否定式约束 |
| P3 | **端到端自检 + 文档写明跑法** | 真实子进程、133 项、exit 0 = pass | `run_user_tests.py`（25 用例，实测全过）应**接进 validate 链路 + SKILL.md 给入口** |
| P4 | **PoC 反驱动安全** | 真实逃逸向量进用例，断言到字段名 | 我们 validate 的反向测试夹具应**常驻化**，不再放 `_fixture` 临时目录 |
| P5 | **零误报正例** | 拦截器配黄金集，测"合法不被拦" | 第 11/12 项反向测试只测了"违规被报"，**缺误报方向** |
| P6 | **可逆性三要素** | 廉价+可逆+零副作用 → 不问用户，事后列假设 | B04 澄清协议可直接引用该判据 |
| P7 | **唯一介入点 + 封死兜底** | 声明唯一必须打断处，并禁止静默绕开 | 我们的"打回≤1次"可升级为"唯一介入点声明" |
| P8 | **数字出处白名单** | 每个数字必须能在指定字段找到出处 | B05 契约段的"实证项不代填"应指定白名单字段 |
| P9 | **边界声明四段式** | 能力/不支持/环境要求/安全，带可数阈值 | capability-boundary.md 只有能力矩阵，缺"环境要求/安全"独立段 |
| P10 | **选型表含格式校验列** | 关键词→类型→该类型输入要求，一表三层 | 我们的路由表可加"选中后的自查列" |

## 六、最佳实践检查清单（造同类 skill 时逐条打勾）

**架构层**
- [ ] 是否有**内核层**（多模块共享的纯计算/纯数据），且模块头写死"不得各自维护副本"？
- [ ] 是否每个模块头都写了**否定式约束**（不得做什么）？
- [ ] 是否把"两处必须一致"改成了**引用关系**而非同步纪律？

**契约层**
- [ ] 主路由是否 ≤200 行且全是**给 agent 的操作纪律**（不是实现说明）？
- [ ] 硬约束是否用 MUST / MUST NOT 大写，且每条**可判**？
- [ ] 是否有 Exit Criteria 且分 ✅/ℹ️/❌/🛑 四级？
- [ ] 是否声明了**唯一必须的用户介入点**，并封死了绕开它的兜底路径？

**质量层**
- [ ] 自检是否走**真实子进程**（非 mock）？项数/跑法/退出码是否写进文档？
- [ ] 拦截器是否配了**零误报黄金正例**？
- [ ] 安全类机制是否有**真实 PoC 用例**，且断言到字段名？
- [ ] 要求 agent 写数字结论时，是否指定了**出处白名单**？
- [ ] 边界声明是否有**可数阈值** + 环境要求/安全独立成段？

## 附：它自身的 3 处缺陷（当范例也要看反面）

| ID | 缺陷 | 实证 |
|---|---|---|
| **D1** | 版本校验是**空头支票**：`__init__.py:3-5` 声明"由 regression_check.py 强制校验"，但全库 grep 无任何脚本读 SKILL.md frontmatter | `grep -rn "SKILL.md" --include="*.py"` 仅 2 处，均为错误消息文本；`regression_check.py` grep `version` = 0 命中 |
| **D2** | 自检项数 **133 写死在文档**，无机器校验 | REFERENCE.md:15 写"133 checks"；数字当前准确（U11+U11+T…+C26 ≈133），但加一项就漂移 |
| **D3** | 自检脚本**主路由无入口**：SKILL.md 全文未提 `regression_check.py` | `grep -rn "regression_check" --include="*.md"` 仅命中 REFERENCE.md:15 |

> D1/D2/D3 的共同根因与 westock-data 的 D1/D3/D4 **完全同构**：**跨落点一致性没有机器校验**。这也正是我们 validate 第 10 项在干的事——**仅此一项我们比它强**。

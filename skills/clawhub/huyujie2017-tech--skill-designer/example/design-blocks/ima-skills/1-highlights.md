## 亮点条目（来自 skill-rebuild · ima-skills-1.1.9）

### A-401 · 三层路由决策表（正向/消歧/跨模块）
- **落位**：B01
- **触发信号**：设计多模块/多功能 skill 的路由层时
- **证据**：root SKILL.md:44-81 — 模块决策表 + 易混淆场景表 + 跨模块任务表三张表并列
- **要点**：路由表不只答"去哪"，还答"像去哪但其实不是去哪"（易混淆消歧）和"要去多个地方"（读取顺序）；正向命中 + 反向消歧 + 组合任务三层覆盖约 90% 误路由

### A-402 · description 写意图扩展触发条款
- **落位**：B01
- **触发信号**：写 skill description 时
- **证据**：root SKILL.md:3-8 — "即使用户没有明确说'知识库'或'笔记'，只要意图涉及文件上传…如'帮我记一下'，也应触发"
- **要点**：description 显式列出间接意图信号词，把触发判断从 agent 推理变成查表，降低漏触发率

### A-403 · GATE 安全门模式
- **落位**：B04
- **触发信号**：skill 含写入/上传/覆盖等不可逆操作时
- **证据**：knowledge-base SKILL.md:39-63 GATE 1-4（TYPE CHECK/NAMING/DUPLICATES/UPLOAD EXIT），每门有 STOP 语义；:41 明文声明适用范围"仅文件上传适用，读取操作不受影响"
- **要点**：把安全规则编号成 GATE 序列：每门一个检查点 + 明确终止动作 + 适用范围声明；禁止"do you still want to try?"式软化话术

### A-404 · 可逆性决定确认等级（新建 vs 追加）
- **落位**：B04
- **触发信号**：存在两个相似但破坏力不同的操作时
- **证据**：notes SKILL.md:25-69 — 信号词三分表（明确新建/明确追加/模糊必问），append_doc 标注"不可撤销地修改"，原则"不确定时，先问"
- **要点**：不可逆操作 = 敏感操作：配信号词表把"问不问用户"变成可判定规则，模糊场景强制询问并列出候选

### A-405 · 隐私输出按场景分级
- **落位**：B04
- **触发信号**：skill 触达用户私密内容且输出可能进群聊/公开场景时
- **证据**：notes SKILL.md:12 "群聊场景中只展示标题和摘要，禁止展示笔记正文"；:173 列表展示只给标题/摘要/修改时间
- **要点**：一句话可执行的输出降级规则：同一内容在私聊/群聊场景用不同展示粒度

### A-406 · 否定式纪律 + 禁止软化话术
- **落位**：B06
- **触发信号**：写纪律/规则条款时
- **证据**：root SKILL.md:40 "Do NOT ask 'do you still want to try?'"；knowledge-base SKILL.md:33 "绝不要在用户已明确指定知识库名称时调用 get_addable_knowledge_base_list"
- **要点**：纪律用 NEVER/绝不要 + 具体行为写出，并预防 agent 好心软化（替用户再问一遍）；比"建议不要"可判定可验收

### A-407 · 环境陷阱前置文档化
- **落位**：B06
- **触发信号**：发现平台/环境的隐蔽缺陷影响 skill 核心功能时
- **证据**：root SKILL.md:42, 251-285 — PS 5.1 静默把 UTF-8 Body 转 GBK，定性"已知设计缺陷，不是 bug 可以被修复"，配首次调用前检测代码 + MANDATORY RULES 前置
- **要点**：隐蔽环境缺陷三件套：升级为强制规则 + 给出首调前检测代码 + 明确定性"只能绕开不能修复"，防止 agent 误判重试

### A-408 · 双层错误分类体系
- **落位**：B07
- **触发信号**：封装脚本有进程级与业务级两类失败来源时
- **证据**：ima_api.cjs:10-14 "Only two categories of errors: -100/-200"；root SKILL.md:142-154 第一层进程错误（stderr JSON）vs 第二层后端业务错误（stdout code≠0）
- **要点**：进程退出层与业务响应层分开叙述，每层枚举全部取值与对应处理动作，agent 排错不用猜

### A-409 · 拒绝时给正确渠道指引（fail-with-direction）
- **落位**：B07
- **触发信号**：校验失败/功能不支持而终止时
- **证据**：preflight-check.cjs:165-174, 233-255 — fail 的 reason 带 hint："Web pages must be added via URL (add_url_knowledge), not as a file upload""use the IMA desktop app"
- **要点**：失败输出不是"不支持"三个字，而是"不支持 + 应该用什么替代"，把死路变指路牌

### A-410 · 错误码表带建议处理列
- **落位**：B07
- **触发信号**：对接的后端有自定义错误码体系时
- **证据**：notes SKILL.md:177-191 错误码表三列：错误码/含义/建议处理，如 100009 → "拆分为多次 append_doc 写入"
- **要点**：建议处理列写动作而非解释（"拆分写入"不是"内容太大了"），agent 查表即可行动

### A-411 · 内置自更新机制（版本自感知）
- **落位**：B08
- **触发信号**：skill 依赖外部 API/会演进，或接入 skillhub update_url 通道时
- **证据**：ima_api.cjs:90-137 — 每天首次调用检查一次（last_check 文件去重）、检查失败静默跳过不阻塞主请求（:101-106）、有新版以 -200 短路原请求并携带 instruction prompt 引导 agent 完成更新（:120-136）；root SKILL.md:156-181
- **要点**：skill 从静态文件变"有版本的活物"：daily-once 限成本、fail-open 保可用、-200 短路保一致性、instruction 让 agent 自己引导更新

### A-412 · 凭证双通道 + 安全声明进元数据
- **落位**：B08
- **触发信号**：skill 需要凭证且涉及多端点传输时
- **证据**：ima_api.cjs:28-49 env→config 文件优先级链；_meta.json:18-29 credentials_usage 明文数据流向（凭证只发 ima.qq.com，COS 用短期临时凭证、主凭证不发 COS）+ allowed_domains 白名单
- **要点**：凭证来源声明优先级链；把数据流向写成机器可审计的元数据声明（发去哪、不发去哪、域名白名单）

### A-413 · UX 输出规范（隐藏内部 ID + 精简进度 + 批量汇总）
- **落位**：B10
- **触发信号**：设计"agent 对用户说什么"时
- **证据**：knowledge-base SKILL.md:322-335 — "永远不要暴露 knowledge_base_id/media_id/folder_id""不要逐步暴露内部操作""批量操作汇总结果"，附四类格式化回复模板
- **要点**：对用户的自然语言输出也写成可判定规则 + 模板样例，而不是留给 agent 即兴发挥

### A-414 · 运行时依赖声明带 reason
- **落位**：B10
- **触发信号**：声明 skill 的外部二进制/环境依赖时
- **证据**：meta.json:3-9 required_binaries[].reason — "Runs .cjs scripts (preflight-check.cjs, cos-upload.cjs)…"
- **要点**：依赖声明附"为什么要它"，预检失败时能给出人话解释，也为依赖裁剪决策提供依据

## 设计原则候选（元设计升维 · 落 design-principles-library.md，入库由用户拍板）

### DP-XXX · 不可逆优先门禁
- **原则概述**：操作的可逆性决定确认等级：不可逆 → 前置硬门（GATE 编号 + STOP 语义 + 默认拒绝 + 禁止软化）+ 语义消歧必问
- **解释亮点**：A-403、A-404、A-405、A-407、A-409

### DP-XXX · 错误即修复指引
- **原则概述**：每一层错误的 msg 都是给 agent 的行动指令：原因 + 修复动作 + 替代渠道，拒绝永远带指路
- **解释亮点**：A-408、A-409、A-410、A-411、A-414

### DP-XXX · 内外语言分层
- **原则概述**：面向用户的输出永远用用户语言（名称/汇总/人话错误/按场景降级），面向系统的处理永远用系统语言（ID/cursor/JSON），两者绝不混流
- **解释亮点**：A-405、A-409、A-410、A-413

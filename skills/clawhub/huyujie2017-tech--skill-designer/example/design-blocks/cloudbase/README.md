# 设计切片案例：cloudbase-2.32.4

> **来源**：腾讯云开发官方技能包（`<本地参考目录>/cloudbase-2.32.4`）
> **采样日期**：2026-08-30
> **一句话**：把"大领域多子域"拆成"一个路由器 + 一堆自治子 skill"，并用一张结构化路由契约把意图识别做成机器可维护的工程。

## 这个 skill 好在哪里

| 维度 | 亮点 |
|------|------|
| **架构** | Hub 套件：顶层 SKILL.md 仅做路由 + 全局护栏，30+ 子 skill 各自自治（full archetype 的规模化形态） |
| **路由** | `activation-map.yaml` 单一数据源：每场景含 优先级/信号/首读/再读/**禁读**/动作前检查/常见错误，SKILL.md 路由表自动生成 |
| **协议** | 三层横切协议（变更安全 / 部署门禁 / 敏感运行时数据保护），跨所有子场景强制 |
| **护栏** | "工程宪法"声明规则覆盖便利性；EnvId 显式、2–3 次失败即换路径、首次部署必须指定 API |
| **审查** | 双轨代码审查规则库：正则 lint（确定性）+ LLM 语义（判断性），每条规则统一格式 + 规则边界纪律防特例污染 |
| **降级** | tooling-fallback 决策树：MCP 不可用 → 配置给下个会话 + 用 CLI 现在干完，不阻塞 / 不循环 / 不假装 |

## 采到哪些设计亮点

## 对 skill-designer 的直接启发（最有价值的 3 条）

1. **A-074 结构化场景路由契约**：skill-designer 自身的意图路由表是"两列（意图|动作）"，可升级为结构化多列（信号/首读/禁读/动作前检查/常见错误）——这是本切片收益最大的架构升级候选。
2. **A-075 Hub 套件架构**：可作为 skill-designer 的**第七种结构框架**（suite），解决"大领域怎么组织"这一当前 archetype 盲区。
3. **A-083 双轨审查规则库**：skill-designer 的 test-playbook 可借鉴"规则统一格式 + 规则边界纪律"，把打磨经验沉淀为可累积资产。

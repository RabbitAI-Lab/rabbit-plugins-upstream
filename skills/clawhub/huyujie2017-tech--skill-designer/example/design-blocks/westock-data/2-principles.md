# 元设计（Meta-Designs）— westock-data 1.0.7

> **定位**：元设计管"**为什么他能系统性想到**"，亮点条目管"单点怎么抄"。
> **纪律**：元设计**不重复入库**样本导出件（条目库只存亮点）；是否反哺 `design-blocks-library.md` 由用户拍板。
> **三条准入**：解释力 ≥3 条亮点 / 可迁移 / 可表述。上限 ≤3 条——超过说明还没归纳到根。

---

## M1 · 失败模式驱动设计

> **原则**：先枚举「agent 会怎么错」，再把每条错写成一个可执行边界——**纪律的来源是观察到的失败，不是推导出的最佳实践**。

**被解释亮点**：A-501（可数上限）、A-506（负向路由列）、A-507（失败分级）、A-508（禁止二次解析）、A-509（禁止自创参数）、A-512（依赖缺失处置）

**证据**：SKILL.md 七条铁律里六条是具体失败模式的反面——
- L60「禁止用 web_search 替代」← 失败：绕过权威源
- L63「K线有延迟，勿称现价」← 失败：拿延时数据冒充实时
- L65「禁止裸数字 / Wind 格式」← 失败：凭印象拼代码
- L66「已覆盖命令勿再 --help」← 失败：反复试探
- L116「禁止连续换 3+ 种 --type 盲试」← 失败：穷举式试探
- L26「重装后仍找不到则如实告知，不要反复重装」← 失败：死循环重装

**为什么这条最值钱**：多数 skill 的纪律是「要怎样」（正推），它的是「别怎样 + 为什么会这样」（反推）。反推出的纪律天然带**触发条件**和**停止点**；正推的纪律容易退化成"注意性能、尽量批量"这类无法执行的空话。

**一句话判据**：写每条纪律前先问「**不写这条，agent 会犯什么具体的错？**」——答不出来就不写。

## M2 · 成本显性化

> **原则**：每条要求 agent 改变行为的纪律，都要写出"不这么做的代价是什么"——**理由栏不是解释，是执行动力**。

**被解释亮点**：A-501（--help 至多 1 次）、A-503（命名规律先于枚举）、A-504（按需加载 + 禁止每次读）、A-505（批量给三条理由）

**证据**：
- routing-guide L183 一条纪律给三个理由：「浪费 **token**」「断言可能**判错**」「保证字段**对齐**」——成本 / 正确性 / 一致性三种性质各一条
- macro-fields L139「看懂规律后绝大多数字段无需逐条查表」——**先给规律再给例外表，本身就是 token 成本决策**
- SKILL.md L49「仅不确定时查阅，**禁止每次任务都读**」

**一句话判据**：纪律写成「要做 X，**因为**不做的代价是 Y / Z / W」——**because 从句不是装饰，是让 agent 在新场景自己推导的迁移能力**。

## M3 · 关键约束前置到必读层（且必须自检完整性）

> **原则**：最容易被违反的约束，必须放在 agent **一定会读到**的位置；且**多落点的约束必须有机器的完整性校验**，否则"前置"会退化成"漏项"——**漏项的前置比不前置更危险**。

**被解释亮点**：A-504（主路由承载铁律）、A-510（description 内嵌边界指针）、A-508（能力矩阵集中成页，H8 同源）

**反证（它自己在这里翻车，最有教育价值）**：
> **D1** —— 它深知约束要前置，所以把能力限制提到 SKILL.md 速查表；但**没有完整性自检**，结果前置的那份只列了 1 条（`search`），漏了 routing-guide §六 的另外 6 条（kline 期货/外汇仅单代码、fund flow 须同一市场……）。而 SKILL.md 还写着「完整限制见 §六」——**agent 会因为看到主路由有表而不再去翻 §六，漏项反而被放大**。

**一句话判据**：约束前置之后，必须能回答「**这份摘要和完整源，机器能验出不一致吗？**」——不能就把引用改成机器校验（我们 validate 第 10 项「索引漂移」就是这类机制）。

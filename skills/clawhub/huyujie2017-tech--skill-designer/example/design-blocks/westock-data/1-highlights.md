## 亮点条目（来自 skill-rebuild · westock-data-1.0.7）

### A-501 · 纪律带可数上限，让 agent 能自检是否触线
- **落位**：B06
- **触发信号**：写「重试 / 回退 / 探索 / 澄清」类纪律时
- **证据**：SKILL.md L66「已覆盖的命令勿再 --help（每任务至多 1 次）」；L114「空结果时……最多再试 1 种 --type」；L116「禁止对同一关键词连续换 3+ 种 --type 盲试」；L26「重装后仍找不到则如实告知，不要反复重装」；L45「同一轮并行发出」
- **要点**：每条探索/重试纪律必须带一个可数上限 + 到顶后的动作，否则 agent 会无限试探或过早放弃。回照自己：skill-designer SKILL.md grep「至多|最多|不超过」= 0 命中，references 里的数字全是验收基准（召回≥95%、≥3场景），无一条运行时行为上限；而 design-blocks-library L528 自己教「模糊规则等于没有规则」——我们教这条却没做到（P0-1 真 bug）

### A-502 · 可验证性决定严格度：同一检查在可验证/不可验证下给不同默认
- **落位**：B04
- **触发信号**：设计校验 / 安全检查门禁，且校验能力可能缺失时
- **证据**：setup.sh L249-283：有 pinned 信任根时，清单校验失败（L258）或无 shasum 工具（L253/L273）一律「拒绝安装」；无 pinned 时仅 warn「跳过校验」并放行（L235/L244/L275）。三份脚本实现一致（setup.ps1 L132-156；setup.cjs L245-253）
- **要点**：不一律放行（等于没门禁）、也不一律拒绝（可用性崩溃），而是按「能否验证」自适应强度。回照自己：validate_skill.py 半软 WARN 的降级判据是「是否历史产物」，而非「该项是否机器可判」——判据错位（P0-2）

### A-503 · 为「不可推断」建认知盲区索引：先给规律，再单列例外
- **落位**：B07
- **触发信号**：领域内存在 AI 无法从命名推断语义的标识符（缩写 / 拼音 / 截断英文）时
- **证据**：macro-fields.md L139-141「字段命名规律……看懂规律后绝大多数字段无需逐条查表」+ L154「拼音缩写对照（CPI 分类子项，无法从字段名推断）」+ L166「易混淆的截断英文缩写」
- **要点**：先给可推断的规律（省 token），再单独列「不可推断」清单（防猜错）——两者分开比全量枚举省一半 token，且把「不知道」变成可检索对象。回照自己：我们有「易混淆消歧」（管两个概念像），但没有「单个概念就不可推断」的清单（P1-1）

### A-504 · 按「查询意图」而非「数据域」切分 references
- **落位**：B07
- **触发信号**：references 超过 3 份，且按数据域切分导致 agent 不知该读哪份时
- **证据**：SKILL.md L49-54 五份文档按「路由 / 命令语法 / 分析场景 / 返回字段 / 宏观字段」四种意图切分 + L49「仅不确定时查阅，禁止每次任务都读」；macro-fields.md 按认知难度（而非数据量）独立成篇
- **要点**：切分依据是「agent 那一刻在问什么」（选命令？查语法？找模板？认字段？），而非数据属于哪个域；每份必须显式声明加载触发条件与不加载条件

### A-505 · 把成本写进纪律的理由栏
- **落位**：B06
- **触发信号**：要求 agent 改变调用习惯（批量 / 少读文件 / 少调命令）时
- **证据**：routing-guide L183「同一命令分多次调用浪费 token、断言可能判错；批量返回还能保证字段对齐」；SKILL.md L45「无依赖的多个查询应在同一轮工具调用中并行发出，不要串行等结果」；macro-fields L139「看懂规律后绝大多数字段无需逐条查表」
- **要点**：一条纪律给三条不同性质的理由（成本 / 正确性 / 一致性），比单说「要批量」更能让 agent 自觉遵守——agent 是在理解「为什么」之后复现规则，不是硬背规则

### A-506 · 正负双向路由：选型表必须有「不要」列，且负例要具体到可复现
- **落位**：B06
- **触发信号**：写命令 / 工具 / 文档选型表时
- **证据**：routing-guide §三 边界表「用本 Skill / 不要用」双列 + §四 高频意图表「精确命令 / 易错点」双列 + L182「❌ 禁止『部分批量、部分单股』」；scenarios-guide L218-220「⚠️ 错误做法：默认 search 华为只搜股票…… ✅ 正确做法：两步查询」
- **要点**：负向列写的是具体会犯的那个错（「默认 search 只搜股票，所以搜不到板块」），不是抽象的「注意」——负例要具体到可复现，才有防呆价值

### A-507 · 失败分级：空结果与能力不支持必须分开处置
- **落位**：B04
- **触发信号**：写异常处理章节时
- **证据**：SKILL.md L180-186 五类：①command not found→重跑 setup ②命令失败→「如实转述，禁止编造数据」③空结果→说明「暂无数据」，并区分「代码不支持 vs 时点无披露」④能力不支持→如实告知+指向 §六 ⑤「禁止失败后改用 web_search 或凭训练数据补数」
- **要点**：每级给「动作 + 禁令」；空结果（数据缺失、可换时点）与能力不支持（能力边界、需降级）混为一谈，会让 agent 在能力边界上反复重试

### A-508 · 输出契约 + 禁止二次解析：声明形态同时禁止 shell 二次加工
- **落位**：B10
- **触发信号**：工具输出已是结构化格式（表格 / JSON）时
- **证据**：SKILL.md L96「默认输出已是结构化 Markdown 表格……禁止用脚本/正则/Python 去解析命令的文本输出」+ L97「禁止终端截断：不要用 | grep / | head / | tail 过滤输出，条数分页筛选只用该子命令自己的参数」；ai_usage_guide §一 明确单股/批量/失败三种输出形态
- **要点**：既声明输出形态，也禁止 agent 用 shell 二次加工——防丢字段、防跨命令套用参数（不同命令支持的 flag 不同）

### A-509 · 参数取值提到主路由 + 显式禁止自创参数
- **落位**：B08
- **触发信号**：CLI 参数多、agent 易凭直觉捏造参数名时
- **证据**：SKILL.md L78-80「参数名与取值都用简短写法……不要自创长参数或复数形式；不确定回 commands.md 核对，不要猜」+ L84-90「常见参数速查」表（周期/条数/回溯年数/板块类型/日期区间）+ L68-76「命令选型速查」表
- **要点**：把参数取值枚举提到主路由并显式禁止「猜」，是防参数幻觉最省 token 的手段——一次枚举胜过多次试错

### A-510 · description 内嵌边界指针 + 禁止替代声明
- **落位**：B01
- **触发信号**：写 description / frontmatter 时（这是 agent 唯一必然读到的字段）
- **证据**：SKILL.md L3 description 末尾「不同标的与市场支持的维度不同，具体命令与能力差异见 references/routing-guide.md。命中能力域时禁止 web_search、HTTP 直连或其它金融 Skill 替代」
- **要点**：description 不只写「能做什么」，还要写「边界在哪找」+「不许用什么替代」——在 SKILL.md 加载之前就开始防误路由，把最贵的错误拦在最便宜的位置

### A-511 · 格式化规范独立成节 + 显式「不可伪造」条款
- **落位**：B10
- **触发信号**：输出含金额 / 单位 / 精度 / 日期时
- **证据**：ai_usage_guide L933-940「金额超亿元用亿元/亿港元/亿美元；成交量超万手用万手；涨跌幅保留 2 位小数带 +/-；日期 YYYY-MM-DD；数据为空时说明『暂无数据』，不可伪造数据；港股/美股财务数据必须标注货币单位」
- **要点**：单位与精度写成可逐条检查的清单，且显式写「不可伪造」——把主观表述变成可验收条款

### A-512 · 外部依赖必须声明「缺失时处置」，只写依赖名等于没写
- **落位**：B01
- **触发信号**：文档/蓝图中出现需要调用外部 skill / CLI / MCP 的降级路径时
- **证据**：【反面样本】routing-guide §三/§四 共 8 处指向 westock screen *（L38,39,41,42,43,59,61,115），属另一个 skill（westock-screener），但 SKILL.md 与 _meta.json 均未声明该依赖；commands.md 里 screen 仅以注释出现 2 次（L284、L449）无正式小节 → 只装 westock-data 的用户按边界表降级会 command not found
- **要点**：依赖声明必须三件套：依赖名 + 缺失时处置 + 验证命令。回照自己：blueprint-template L123「资源约束：______（依赖、许可、密钥纪律）」只填依赖名，不填缺失处置——同样的坑（P1-2）

## 设计原则候选（元设计升维 · 落 design-principles-library.md，入库由用户拍板）

### DP-201 · 失败模式驱动设计
- **原则概述**：写每条纪律前先问「不写这条，agent 会犯什么具体的错」，答不出来就不写——纪律的来源是观察到的失败，不是推导出的最佳实践
- **解释亮点**：A-501、A-506、A-507、A-508、A-509

### DP-202 · 成本显性化
- **原则概述**：每条要求 agent 改变行为的纪律，都要写出「不这么做的代价是什么」——理由栏不是解释，是执行动力
- **解释亮点**：A-503、A-504、A-505

### DP-203 · 约束前置 + 完整性自检
- **原则概述**：最易违反的约束必须放在 agent 一定会读到的位置，且多落点的约束要能机器校验一致性——漏项的前置比不前置更危险
- **解释亮点**：A-504、A-510、A-512

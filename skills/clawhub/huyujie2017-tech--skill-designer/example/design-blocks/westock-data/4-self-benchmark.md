# 自省对照：我们造得出 westock-data 1.0.7 这个质量吗？

> 触发问题（2026-09-07，用户问）："我们这个 skill-designer 可以设计得出 westock-data 1.0.7 这样质量的 skill 吗？"
> 本文件不是又一份亮点清单，而是**拿外部成品当考题，验收我们自己的生产线**。对照法可复用：每收录一个外部 skill，都跑一遍。

---

## 一、对照法：三层机制

判断"我们造不造得出"，不看我们文档写了多少漂亮话，只看三层：

| 层 | 问什么 | 通过了意味着 |
|---|---|---|
| **机制层** | 蓝图模板有没有**强制字段**逼设计师填？ | 不靠自觉，靠流程必填 |
| **知识层** | 条目库 / 原则库有没有**可注入条目**？ | 不靠临场发挥，靠沉淀可用 |
| **闭环层** | validate / check_blueprint **能不能验出来**？ | 不靠承诺，靠机器可判 |

三层全 ✓ = 稳定产出；只有机制 + 知识 = 能产出但会漂移；三层都缺 = 靠运气。

## 二、七项特质逐条对照

| westock-data 特质 | 机制 | 知识 | 闭环 | 判定 |
|---|:--:|:--:|:--:|---|
| 主路由极薄（194 行） | ✓ | ✓ | ✓ | **更强** — B07 archetype + `validate #4 body<5K` 机器强制；它靠自觉 |

## 三、根因：不是缺两条，是分型只到"段落"没到"字段"

⚠️ **首轮判断曾写错，已修正**：`skill-archetypes.md` **是有分型的**——7 型 × 五段骨架侧重（如 tool 型侧重 Failure Handling、knowledge 型侧重 Resource Routing）。这比多数设计方法论强。

但分型**止步于"哪一段最值钱"，没有下沉到"该段必须填哪些专项字段"**：

- **tool 型的 Resource Routing 段没被点名** → westock-data 最亮眼的"命令域 + 参数命名约定 + 主路由参数速查表"没有强制落点；
- **工程层（scripts/）不在五段骨架里** → 安装/分发的信任链、跨平台脚本一致性，模板完全没问。

→ 结论：**缺的不是知识，是 archetype 分型的字段粒度。**

## 四、但真正的差距不在机制，在打磨次数

这一节才是诚实的答案。

| | westock-data 1.0.7 | skill-designer 的产物 |
|---|---|---|
| 版本 | 1.0.7 = **迭代 7 个补丁** | 唯一完整真实产物 fin-information-pipeline v2.1.0 |
| 质量证据 | 真实使用磨出来的 | **IQS 100 / BR-5 4.7 / 综合 94 —— 自家机器自评** |
| 身份 | **成品**（已入住、修过七次的房子） | **蓝图**（设计院出的施工图） |

三点必须说清：

1. **自评不是客观证据**。94 分是我们自己的脚本算的。westock-data 的 A 级是被人用出来的。拿自评比别人实战分，是拿月考比高考。
2. **我们设计的是蓝图，不是成品**。蓝图 → 成品还有 skill-creator 落地 + 真实使用两道关，不在我们手里。严格说问题应是"我们的蓝图能不能**导向**那种质量"。
3. **最扎心的一条**：今天刚发现我们教别人"规则要可触线"，自己主路由却 0 条可触线规则——**机制再全，不拿它照自己照样犯病**。这和 westock-data 的 D1（主路由表不全→漏项被放大）是同一类病。**决定质量的不是机制覆盖率，是机制有没有持续用在自己身上。**

## 五、三条建议

| # | 建议 | 落点 | 优先级 |
|---|---|---|---|
| 1 | **tool 型补专项字段**：Resource Routing 段加「命令/接口速查表 + 参数命名约定」；B07 加「分发与安装」子项（信任链 + 跨平台脚本一致性 + 验证命令） | `skill-archetypes.md` + `blueprint-template.md` 07-计划 | P1 |
| 2 | **把三层对照法固化进收录流程**：每收录一个外部 skill，切片里必须附一份自省对照（机制/知识/闭环），对照发现的缺口直接入 lessons — 把"收录"从**攒条目**升级为**验收生产线** | `design-blocks-library.md` + 各切片 | P1 |
| 3 | **给自有产物做一次外部视角复评**：拿 fin-information-pipeline 按 TRACE 独立打一次分（非自家脚本），校准 94 分的真实水位 | `test-playbook.md` §四 双跑 | P2 |

## 六、一句话答案

> **机制上够格，甚至在 5 项上比它更硬；但它是"跑出来的"，我们是"设计出来的"——差的是打磨次数，不是设计能力。补上 tool 型专项字段 + 把三层对照法变成收录的固定动作，差距会从"运气"变成"流程"。**

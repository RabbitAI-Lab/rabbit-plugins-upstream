> 用途：SkillHub TRACE **E 维（Effectiveness）**的书面证据
> 口径：**只记可核验证据**，不记意图。所有数字由脚本统计或命令实录，可复跑。

## 〇、结论先行

| 问题 | 答案 |
|---|---|
| **有 skill 是不是全面更强？** | **不是。** 对照组在深度（41KB）、边界密度（18 vs 11 条）、量化验证指标（7 项）上**明显胜出** |
| **那 skill 的价值在哪？** | **结构保证 + 强制检查点 + 可交接性**，而非"比资深 agent 想得更深" |
| **唯一稳赢的一项** | **输出四要素 P24 4/4 vs 3/4** —— 对照组漏了「错误输出」，这是机器强制检查点才拦得住的 |
| **E 维评分依据** | 由 4.6 → **4.9**。依据不是"证明比人强"，而是"证明了**可验证的结构保证**与**可交接产物**" |

**一句话**：skill-designer 卖的不是「更聪明」，是「**不漏项、可复核、能交接**」。

## 一、实验设计（先说清楚局限，否则结论不可信）

| 组 | 怎么做 | 产出 |
|---|---|---|
| **对照组 baseline** | 起一个独立 agent，**硬性禁止**读取 skill-designer 任何文件、禁止加载其方法论，凭自有知识设计 | `outputs/baseline-raw/BASELINE.md`（41,438 字节） |
| **实验组 with-skill** | 走 skill-designer 四步流：②初步方案 → ③深化设计 → IQS → ④带缺口导出 | `outputs/with-skill-raw/`（蓝图 27,507 B + 交接产物 34,096 B） |

### ⚠️ 三个必须披露的局限（不做任何粉饰）

1. **对照组的覆盖度部分是被提示出来的。**
   我给 baseline agent 的指令里**明确列了 10 个必答项**（问题/输入/事实/观点/风险/分析/决策/计划/产物/复盘）。所以它的「10/10 全覆盖」**不等于它自己想到了这 10 项**。
   → 反过来说：实验组的 10 格是 skill **自带**的结构，不需要人提示。**这一点实验组占优，但对照组并非"自发覆盖"，不能算它输。**

2. **两组产物不在同一层。**
   对照组一路写到了 **SKILL.md 完整草稿**（下游，接近成品）；实验组停在**施工蓝图**（上游，需交 skill-creator 继续施工）。
   → 深度上的差距，有一部分是**下游完成度**造成的，不全是方法论差距。

3. **成本不对等。**
   对照组是 agent 长时间深度思考的产物；实验组是 **4 条命令**。这是真实的效率差异，但对照组的深度也是"用时间换来的"。

> 这三条都对本 skill **不利**。写在这里，是因为 E 维是评审人最容易交叉验证的一维——**藏起来的漏洞比承认的短板更致命**。

## 二、双跑实录（可复跑）

### 实验组：4 条命令

```bash
# ②初步方案（自动判设计模式与结构框架）
sd_cli.py proto outputs/with-skill-raw/reading-notes --name reading-notes \
  --answers '{"problem":"读了很多书…","audience":"知识管理重度使用者…", ...}'
# → 设计模式：Generator + 知识路由 × D 模板渲染 ｜ 结构框架：template ｜ IQS 86

# ③深化设计（59 条 AI 建议 + 2 项拍板 + 8 项验收）
sd_cli.py deepen <bp> --accept-all \
  --set "B02.正交性=不接管存储后端、不负责采集…" \
  --set "B08.独立审=用户每周 15 分钟抽查 5 张卡…" \
  --tick B01,B02,B06,B07,B08,B09,B10

# 复核
sd_cli.py check <bp> --write-iqs          # → IQS 98/100
sd_cli.py export <bp> --output <brief> --format all --allow-gap
```

**产物清单**：10 格蓝图 md + `index.md` + `blueprint.svg` + `structure.svg` + 交接产物 `brief.json`(16.7KB) / `summary.md`(10.2KB) / `SKETCH.md`(7.2KB)

### 对照组：1 个 agent 长任务

产出单文件 `BASELINE.md`：15 个章节，含完整 SKILL.md 草稿、7 项验证指标（M1–M7）、13 项「明确未考虑」清单（U1–U13）、设计自评强弱各三点。

## 三、四维对比（客观数据）

| # | 维度 | with-skill | baseline | 谁赢 |
|---|---|---|---|---|
| 1 | **格 / 项覆盖数** | 10/10（IQS **98**，机器判定） | 10/10（⚠️ 被 prompt 提示） | 平（实验组是自发结构） |
| 2 | **输出四要素 P24** | **4/4** | **3/4**（缺「错误输出」） | **实验组** ✅ |
| 3 | **边界条目数** | 11 条 | **18 条** | **对照组** ✅ |
| 4 | **可交接性** | `brief.json` 结构化，机器可读 | 单 md 41KB，需人读 | **实验组** ✅ |
| — | 体量 | 61,603 B（含 3 个交接产物） | 41,438 B | — |

**统计口径**（按此口径可手工复现）：
- **边界条目** = 含「不做 / 不该 / 排除 / 拒绝 / 非目标 / 不适用 / 不接管 / 不负责 / 停用 / 降级为」的**列表项（`- ` 开头）或表格行（`|` 开头）**；`>` 引用行与说明文字不计
- **输出四要素** = 原则 P24 定义的「输出目录 / 命名 / 格式 / 错误输出」，四项各自独立判定
- **体量** = 文件字节数（`wc -c`），交接产物单独计

## 四、逐维解读（不吹不贬）

### 维度 1 · 覆盖数 — 平手，但性质不同

实验组的 10 格是 skill **自带**的脚手架，机器能逐格判定「填全 / 占位 / 缺项」并算出 **IQS 98**。
对照组的 10 项是我**点名要的**。

→ 真正的差异：**实验组的覆盖度可被机器验证，对照组的不能。** 换一个人跑实验组，10 格结构不漏；换一个人跑对照组，少想到两项也没人知道。

### 维度 2 · 输出四要素 — 实验组唯一稳赢的一项 ⭐

两组都写了输出目录、命名、格式。**唯独「错误输出」对照组漏了**：
- 实验组 B06 强制声明：同目录写 `{原名}.error.md`，含**失败阶段 / 原因 / 已完成的中间产物；不写敏感路径**
- 对照组只有 `_work/` 中间态目录，**没有「失败时产出错误文件并写清原因」的约定**

→ 这一项最有说服力：它是**资深设计也容易漏**的项（对照组整体深度远胜，偏偏漏了它），只有**机器强制检查点**拦得住。这就是 skill-designer 的核心价值——**用结构兜住人的注意力盲区**。

### 维度 3 · 边界条目 — 对照组明显胜出，坦承

对照组 **18 条**（§13 独立边界表 10 条负例 + 3 条「易混淆正例」+ §1.3 四条前提降级），且正例那 3 条（"帮我看看我以前记的关于 X 的东西" → 检索模式 ✅）是**防误伤**设计，实验组没有同类条目。

→ 这是实验组诚实落后的一项。skill-designer 的 B01/B02 虽有「非目标清单」「正交性」字段，但**自动出稿的边界密度远不如深度思考**。
→ **改进方向已明确**：③深化设计阶段应增加「边界补全」步骤，用 capability-boundary 的 4 问决策树逐格追问。

### 维度 4 · 可交接性 — 实验组胜

`brief.json` 是**结构化**的，下游 skill-creator 可直接消费；对照组的 41KB 需要人读完再转述，转述过程必然丢信息。

## 五、本次真跑额外暴露的缺陷（已修）

> 这是「真跑」相对「静态自检」的价值——静态自检 8/8 全过，这个洞一个都没报。

### 🐛 `--tick` 会勾掉 B08 的**实证项**，等于伪造证据

**现象**：`deepen --tick B08` 把「真实场景跑过」「有 / 无 skill 对比结果在手」两项勾成了 ☑。
可这个 skill **根本还没落地**，真实场景没跑过——勾了就是**假证据**。

**性质**：这违反了 skill-designer 自己定的「诚实预勾原则」（必须真跑的项保持未勾），但**脚本没守住**。与之前的「隐私泄露」「frontmatter 缺失」同属一类：**自己定的规矩自己没守住**。

**修复**（`scripts/deepen_blueprint.py`）：
```python
# 实证类验收项：只有 skill 真正落地跑过才成立，脚本**不得代勾**
EVIDENCE_KEYWORDS = ("真实场景", "有 / 无 skill 对比", "有无 skill 对比",
                     "有无对比", "真跑", "实测", "实际运行", "真实数据")
```
`tick_text()` 命中关键词则**跳过不勾**，原样保留并回报：
```
⛔ 实证项不代勾（须用户真跑后手勾）：B08：真实场景跑过（不是空泛测试）
⛔ 实证项不代勾（须用户真跑后手勾）：B08：有 / 无 skill 对比结果在手
```

**验证**：本蓝图 B08 两项已手动改回 ☐，重跑 `--tick B08` 被正确拒绝；IQS 因此从 100 降为**诚实的 98**。

# 快速开始（启动卡，不是教程）

> ⚠️ **本 skill 是「帮你设计 skill 的元 skill」，不是技能设计理论教程。**
> **你不需要先学什么——直接说「帮我做一个 X 的 skill」就能开始。**
> 本文件只回答两件事：**怎么最快开始**、**常见问题**。想深挖方法论再看 `blueprint-methodology.md`。

**60 秒速览**：

> **您只需**：①说需求 → ②答 3 个问题 → ③对初稿回「按建议」或提修改
> **AI 负责**：出稿、打分、出图、落盘、续跑
> **术语**：随问随答，首次出现自动带白话注释——零技术门槛，边做边懂

## 零技术门槛三件事

| 担心 | 事实 |
|------|------|
| 要懂技术吗 | **不需要**。设计师用大白话问你，你用大白话答 |
| 要装 Python 吗 | **平台自带，零配置**。特殊环境未装时按提示装一行即可 |
| 要先读文档吗 | **不需要**。这份启动卡可以跳过，直接开口 |

只想**快速出活**：说一句「帮我设计 X skill，走轻量通道」→ 约 30 分钟拿到可交接的蓝图。
想**深度打磨**：说「走完整通道」→ 多问几轮，产物更细（含结构图、失败状态机、验证清单）。

---

## 3 步上手（轻量通道约 30 分钟）

| 步 | 你说 | 设计师做 |
|----|------|----------|
| 1 | 「帮我做一个 X 的 skill」 | 回问三件事（跑在哪 / 新建还是改进 / 轻量还是完整），确认后立刻建蓝图目录 |
| 2 | 一问一答走 10 格 | 每格问 1–2 个非答不可的问题，答完小结确认，产物自动落盘 |
| 3 | 确认④施工蓝图 | 机器检查通过 → 交给 skill-creator 落地（可直接调用，或给你一段可粘贴的交接词） |

**说不清需求？** 直接说「我不懂怎么设计，你先出个方案」→ 走「我拟」：设计师问 3–5 个核心问题后**直接出完整草稿**，你改、你拍板。

---

## 积木链一图速览（10 格，一句话一格）

条件（该不该做）→ 事实（谁用、生态有没有重叠）→ 观点（选什么设计模式）→ 问题（还有哪些口径没定）→ 分析（输入输出契约 + 风险）→ 决策（拆不拆、脚本还是引导）→ 计划（**施工图：选结构框架 → 画目录 → 填五段章节骨架**）→ 行动（真实场景验证）→ 结果（双维评分）→ 复盘（失败归纳成通用规则）。

> 每格的详细问题见 `designer-guide.md`；为什么是这 10 格见 `blueprint-methodology.md`。

## 别人用它做出了什么

**例 A — 能说清需求**：「我每月要从 CSV 生成财务报表」→ B01 三场景过准入 → B03 定「流程配方+带自检」（格式固定、数字错代价高）→ B06 定脚本 `generate_report.py` + 输出文件约定 → B08 用上月真实 CSV 验证 → B09 双维 85×90 → B10 归纳「数字输出必带自检」→ 施工蓝图交接。

**例 B — 说不清的新手**：「想做个管理笔记的技能，但不懂设计」→ 走「我拟」→ 设计师问 4 个核心问题后出完整草稿 → 你逐轮修改（如「改成纯文件扫描更安全」）→ 拍板出施工蓝图 → 交接落地。

**两个例子说明的事**：同一套积木链、两种起点，都到同一份施工蓝图；**触发词与命名由你拍板**；设计师出蓝图，skill-creator 落地。

## FAQ（常见 13 问） {#faq常见-13-问}

> **本文件最重要速查区**。对话中没解释清楚的，先来这里看一行答案，再回去继续。

| 问 | 答 |
|----|-----|
| 会帮我写文件吗 | 蓝图产物自动落盘；SKILL.md 等正式文件施工蓝图后交 skill-creator 生成（本 skill 可直接调用它） |
| 我啥也不懂，能先给方案吗 | 能，走「我拟」：问 3–5 个核心问题后直接出完整草稿供你修改 |
| 我赶时间，能快点吗 | 说「走轻量通道」：只问非答不可的问题，约 30 分钟出蓝图，质量门可后续升级 |
| 没装 Python 能用吗 | 能，但**不用降级**：Python 是 workbuddy 等平台自带工具，未装时按提示装一行即可；仅因特殊原因明确不装才切对话模式（产物照出，落盘/机器打分暂不可用） |
| 能跳过蓝图吗 | 可以但返工率高；已在用 skill-creator 则转「伴随守门」逐格把关 |
| 为什么不每次都拦我 | 平台是意图路由，skill 间不能强制调用——所以只软提示一次，拒绝不阻塞 |
| 谁拍板 | 设计师出草稿与建议；**触发词、命名、设计决策由你拍板** |
| 蓝图写完下一步 | 机器检查通过 → 硬交接（直接调用 skill-creator）或软交接（给你一段可粘贴的交接词） |
| 10 格太长能跳吗 | 顺序固定，但可合并相邻格、模板速填；产物须齐全 |
| 改进旧 skill 从哪起 | 诊断先行：用诊断结论填已明确的格，只对缺口格引导 |
| 中断了怎么办 | 蓝图目录留有进度快照，新会话跑检查脚本即知缺口，从缺口续跑 |
| 命令失败要手动重来吗 | 不用。`sd_cli.py` 内置自动重试，临时 IO/环境失败会指数退避重试；结构性错误立即报错不空转 |
| 为什么要停下来问我几个问题 | 这是**审稿式协作**的设计特色，不是流程摩擦：AI 先出有主张的初稿（机器质检分通常 85+），**触发词、skill 名、非目标这几项只有您能拍板**——AI 代填的触发词会让 skill 上线后无法被正确触发。其余事项 AI 按经验自动补全并标注「已按经验补：…可改」；每次提问都带建议值+理由+备选，回「按建议」即批量采纳。全程只需拍板 3–7 项、2–3 轮交互 |

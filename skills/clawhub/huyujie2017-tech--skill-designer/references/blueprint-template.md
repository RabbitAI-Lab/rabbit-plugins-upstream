# 技能蓝图模板（bundle 实体化）

> 本文件把蓝图方法论（[blueprint-methodology.md](blueprint-methodology.md)）的 bundle 形态**实体化成 10 张可填积木**：index.md + 01–10 各子积木。
> **用法**：沿主流水线 B01–B10 逐格填充，每格产物写入对应子积木；全部填完 = 一份完整技能蓝图 bundle，作为对接 skill-creator 的输入 brief。
> **断链容忍**：允许先搭骨架再填充，可先写"此处依赖一个尚不存在的脚本积木"。

---

## 使用说明

1. **首选脚本生成**：`python scripts/init_blueprint.py <蓝图目录> --name "<skill名>"` 一键生成下方完整骨架（含 checkpoint 状态表），逐格填充即可——不必手动复制本模板；
2. 手动复制亦可：按下方 bundle 结构建目录，主流水线每格完成 → 填对应子积木；
3. 每格都有**填空字段**（`______`）和**示例**（以"Excel 报表生成 skill"贯穿）；
4. index.md 汇总快照 + checkpoint + 子积木索引；
5. 产出 = 蓝图 bundle，施工蓝图前跑 `python scripts/check_blueprint.py <蓝图目录>` 机器验收，交给 skill-creator / 直接按 `07-计划` 写作。

**模板骨架**：

```
skill-blueprint/
├── index.md        # 接口：type: Blueprint + 一句话定位 + 快照 + 索引
├── 01-条件.md       # 准入四问 + 边界 + 前置
├── 02-事实.md       # 画像 + 生态位 + 正交性
├── 03-观点.md       # 设计模式处方
├── 04-问题.md       # 待确认口径
├── 05-分析.md       # 输入输出契约 + 风险
├── 06-决策.md       # 方案抉择 + 输出文件约定
├── 07-计划.md       # 目录骨架 + 脚本化清单
├── 08-行动.md       # 验证计划
├── 09-结果.md       # 双维度评分
└── 10-复盘.md       # 迭代记录
```

## 01-条件积木模板

**结构公式**：`[前提] + [背景] + [资源约束] + [证据来源]` + 准入四问

**填空字段**：

<!-- FIELDS:01 BEGIN — 由 scripts/gen_blueprint_fields.py 从 blocks.py 生成，勿手改 -->
- 前提：______（谁、在什么场景、需要什么）
- 背景：______（已有模板 / 工具 / 团队规范）
- 资源约束（**三件套，缺一不可**）：依赖______；**缺失时处置**______；验证命令______（+ 许可 / 密钥纪律）
- 准入四问：☐ 形态合规 ☐ 非元信息 ☐ 可链接 ☐ 复用检验
- 结论：**创建** / **继续蒸馏**（材料不足，先补证据）/ **合并**（进已有 skill）/ **不做**（归档为项目文档）/ 转向（______）
- **非目标清单**：______（明确**不**做什么——防功能膨胀，④施工蓝图出口条件之一）
- **证据来源**（仅留痕，**不进产物**）：______（已验证经验的**匿名摘要**；人名、项目代号、私有路径、凭据**一律不写在此处**——走 [material-distill.md](material-distill.md) §5 的脱敏口径）
<!-- FIELDS:01 END -->
> **证据层 / 产物层分离**：证据留在证据层（可回溯、供 B09 打分定位），产物层（名称 / description / 示例）默认不含任何私有信息。隐私靠**架构隔离**保证，不靠"记得不写"。

> **为什么资源约束必须写三件套**（参考 westock-data D-007 / 元设计 DP-203）：只写依赖名 = 把"依赖没装"这个必然发生的场景留给了 agent 即兴发挥。
> 反面样本：westock-data 的边界表 8 处把活儿甩给另一个 skill 的命令，却从未声明该依赖——只装它的人一降级就 `command not found`。**依赖名 + 缺失时处置 + 验证命令**，三件齐了降级路径才是可执行的。

**示例（Excel 报表 skill）**：
- 前提：用户每月从 CSV/JSON 生成运营/财务报表
- 背景：团队有统一报表风格，assets/templates/ 已有月报/财报模板
- 资源约束：依赖 openpyxl；**缺失时**降级 csv 标准库并明确告知用户（**禁静默失败**）；验证命令 `python -c "import openpyxl"`；绝不写死密钥
- 准入四问：形态合规✓ 非元信息✓ 可链接✓ 复用检验✓（月报+财报+临时分析≥3 场景）
- 结论：创建
- 非目标清单：不做实时数据源连接（只吃导入的 CSV/JSON）、不做可视化图表（边界清晰，防膨胀）
- 证据来源：2026-08 某团队月报场景实测三例（成功/缺列/超 10 万行），已匿名化

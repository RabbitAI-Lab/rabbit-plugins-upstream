# 四步施工流（Part 0）— 默认用户体验门面层

> 本文件是 SKILL.md「四步施工流」一节的**详细规格**。定位：把「意图路由 + 主流水线 B01–B10 + 脚本编排」封装成一块**出方案积木**，用户只面对四个自然步骤，不暴露内部路由表与 10 格术语。内部引擎（路由表 / 主流水线 / 脚本）**原样保留，仅演示层变化**。
> 一句话心法：**用户看到 4 个自然步骤，内部引擎在黑盒里跑完 10 格。**

## 〇、四步总览

| 步 | 用户做什么 | 设计师内部做什么 | 产物 | 出口条件 |
|----|-----------|-----------------|------|----------|

## 一、① 概念讨论 — 说想法 / 给资料

### 用户看到什么（白话）

> "说说你想做什么，或者把相关的历史对话 / 任务资料丢给我。如果是改进现有的 skill，把它的名字告诉我也行。"

### Agent 内部做什么（按序）

1. **意图路由**（SKILL.md 路由表）：判创建 / 改进 / 轻量（FAQ·边界·守门）。
2. **入口分流**：
   - **创建** → Phase 0 三问（平台 / 入口 / 通道）；
   - **改进已有** → 诊断先行：读已有 SKILL.md → 诊断报告 → 用诊断结论填已明确格，只对缺口格引导；
   - **有历史对话 / 任务资料** → 资料分析：**由设计师**从素材归纳"问题 / 场景 / 约束"，按下方「开场描述喂格映射」喂入 A1/A2/B7。⚠️ **一份材料含多个闭环时，先走 [material-distill.md](material-distill.md) 切经验单元**，别把整包资料当成一个 skill 设计。
3. **边界判定**：拿不准"该不该做成 skill" → capability-boundary 决策树。
4. **概念讨论达标检查**：按「概念讨论最低标准」（见下）自查 7 项——**A 组 4 项硬门槛缺一不可**，缺了先补再进②；**B 组 3 项软门槛**缺则②初稿会自动标注"粗版"、③需要多深化一轮。达标才出三句话小结。

### 概念讨论最低标准（以终为始，从 10 格反推）

> **为什么要有这条线**：②初步方案的质量 = ①概念讨论的密度。如果①只给一句"做个 XX 的 skill"，②只能用默认值生成**空壳模板**，③就要从逐格重填开始——等于把②的活又干一遍。所以以终为始，看 10 格各自最少需要什么，反推出①的达标线。

| 级 | 最低项 | 用户一句话（大白话） | 喂给哪个积木格 | 缺了会怎样 |
|----|--------|---------------------|---------------|-----------|
| **A 必需** | A1 做什么 | "它解决什么问题、产出什么？" | B01 条件 / B05 输出 | 准入四问判不了，蓝图无核心 |
| **A 必需** | A2 给谁用 | "谁在什么场景打开它？" | B02 画像 / B08 场景 | 画像空壳，验证无场景 |
| **A 必需** | A3 在哪跑 | "跑在哪个平台/环境？" | Phase 0 / B07 计划 | 目录骨架、脚本、字段无法定 |
| **A 必需** | A4 新建/改进 | "从零建，还是改已有的？（已有→给名字）" | Phase 0 / 入口路由 | 起点错，可能重走 B01 |
| **B 关键** | B5 最在意做对哪点 | "最不能错的是什么？（数字准/格式统一/速度快…）" | B03 模式 / B09 评分 | 模式选不准、评分无标准 |
| **B 关键** | B6 流程性质 | "一次干完，还是分几步中间要确认？产出标准化还是灵活？" | B03 模式（交互×内容） | 只能默认 Pipeline，可能选错 |
| **B 关键** | B7 一个具体样例 | "想象一个人具体怎么用一次" | B02 / B08 验证 | 验证场景空泛，B05 契约粗 |
| C 加分 | C8 边界 | "做什么、不做什么" | B01 / B05 边界 | 边界模糊，易过度膨胀 |
| C 加分 | C9 生态 | "已有类似 skill 吗？" | B02 正交性 | 可能重复造轮子 |
| C 加分 | C10 历史资料 | "有相关对话/任务资料吗？" | 全局（**进推断引擎**：信号扫描 + BR-5 证据；含多个闭环 → 先走 [material-distill.md](material-distill.md) 切单元） | 出方案靠猜，不靠证据 |

**用户开场长描述 → 积木格速查（喂格映射）**

> 一句话心法：**三问判路，描述喂格**。用户开场往往一口气描述定位 / 功能 / 场景 / 输出——这些是"原料"，Phase 0 三问只判路不承载内容，B01–B07 才是分拣格。先按下表把长描述解析进 A/B/C 各项，**缺才追问**，不要对着一段信息量足够的描述再问一遍已有答案的问题。

| 用户描述的内容 | 喂给哪格 | 在格里的用途 |
|---------------|---------|-------------|
| **定位**（解决什么问题、边界） | B01 条件 | 准入四问、"做/不做" + 非目标清单 |
| **使用场景 / 给谁用** | B02 画像 | 上下文画像、生态正交性检查（防重复造轮子） |
| **特色 / 流程性质**（一次干完 vs 分步、标准 vs 灵活） | B03 模式 | 探积木链六问信号 → 设计模式处方 |
| **拟实现功能 / workflow** | B05 分析（P 象限）→ B07 计划 | 执行顺序 / 分支 → 下沉为 Workflow 五段 |
| **输出结果** | B05 分析（O 象限）→ B06 输出 | 交付物 / 格式；涉及文件产出时升格 B06 四要素 |
| **主要内容 / 关键模块** | B07 计划 | 目录骨架 + SKILL.md 五段结构 |
| **最在意的点 / 验收标准** | B03 / B09 评分 | 模式选择依据 + 评分维度与证据定位 |
| **个人方法 / 独门资料**（自己的方法论、坚持的原则、现成模板、私有案例库） | B02 资产挖掘 / B03 创意确认 | **独特性来源**——用户独有的东西决定 skill 上限，AI 默认值只保底；提到就主动喂进对应格，不流失 |

**达标检查话术（缺就补，补到达标）**：

- **A 组缺失**（硬门槛，②前必补）——直接问，不绕弯：
  > "②初步方案前我还差一个关键信息：**A2 给谁用**——谁在什么场景会打开它？一句大白话就行。"
- **B 组缺失**（软门槛，给二选一/选项式，不空等）：
  > "初稿能出，但为了不返工，先定一下：这活儿**一次干完**还是**分几步中间要确认**？"（答不上 → "不确定就先按分步流程出，③再调"）
- **用户只丢一句"做个 XX 的 skill"** → 逐项过 A 组，缺哪问哪，凑齐 A 组（B5 尽量）再进②。
- **只有抽象描述、给不出 B7 样例时 → 使用例反推**（取自 skill-creator）：
  > "那我们反过来推：想象它已经做好了，你会**说什么话来触发它**？说 2–3 句最典型的。"
  拿到使用例后逐例**从零推演执行过程**（设计师内部做，不刷屏给用户）：每一步需要什么材料、什么工具、卡在哪——重复出现的动作沉淀为候选资源清单（scripts / references / assets），直接喂 B05 分析与 B07 计划。**"例 → 资源"的推导桥**比抽象追问更落地，也是独特资产（B02）的天然入口。

**出口 gate**：A 组 4 项全齐（B5 尽量命中）→ 才出三句话小结并进入②；否则回到补料。

### 话术（三句话小结 + 确认）

> "我理解的是：① 你想做一个 **X**，② 用在 **Y** 场景，③ 主要解决 **Z**。对吗？"
> 用户确认 → 进②；有偏差 → 改到对为止。**不要替用户默认正确。**

### 出口 / 产物

- 概念讨论达标结果（A 组全齐 / 或粗版标记）
- 三句话需求小结（用户已确认）

> 蓝图目录与草稿由 **② 的 `blueprint_proto.py`** 一键生成（init+draft 合并，无需①先落盘）。

## 二、② 初步方案 — 一键生成初步方案 + 可视化

### 用户看到什么（白话）

> "好，我先按你的需求出**一版施工蓝图草稿**给你看（含一张总览图）。标【草稿，待确认】的可以直接改，标【需用户拍板】的得你定。"

### Agent 内部做什么（按序）

1. **注入经验**：读 `lessons.md` TOP 3 + `design-blocks-library.md` TOP 2（复盘回路 / 外部学习回路，一句话提示，不阻塞）。
2. **一键出方案**：`blueprint_proto.py`（或 `sd_cli.py proto`）一条命令完成 init+draft——**机器复校验概念讨论最低标准 A 组**（缺一拒绝出方案；B 组缺则自动在 index 标"粗版"），`draft_blueprint.py` 生成 B01–B10 完整草稿（带【草稿，待确认】/【需用户拍板】标注）。
3. **可视化**：proto 自动跑 `visualize_blueprint.py --mode essence` 生成「蓝图总览图」（每格要点 2–4 行），让初稿可被**一眼审**。

### 话术

> "这是初稿全貌。你可以先说'整体哪里不对'，也可以直接指'某一格要改'。我们按你关注的顺序来。"

### 出口 / 产物

- 初步方案（B01–B10 全部有草稿内容）
- 蓝图总览图（SVG）

## 三、③ 深化设计 — 逐轮讨论、补充深化

### 用户看到什么（白话）

> "我们一处一处把它聊透。你这一轮最想先看哪部分？"

### Agent 内部做什么（按序）

1. **逐轮聚焦**：每轮 1–2 格，用 designer-guide 问题库深挖（MVP 必问 → 增强 → 自由追问；**MVP 默认带 AI 建议三件套**——建议值+理由+备选，用户可回"按建议"）。
2. **最佳实践命中**：按 B02/B03/B06 画像与决策标签，命中 design-blocks-library 条目 → 提示 + 理由 + 实施建议。
3. **强制阻塞**：触发词、skill 名 —— 设计师给候选，**用户必须自己产出确认**（不可代填）。
4. **非目标清单确认**：深化收尾显式问"这个 skill 明确**不**做什么？"，把非目标清单写入 `01-条件.md`——"不做什么"与"做什么"同等重要，防功能膨胀（借鉴元技能边界确认）。
5. **边界补全（固定步骤，v3.15.0 移植姊妹分支 v4.3——非可选优化）**：
   - **为什么必须做**：有/无 skill 对比实证（[`outputs/baseline-vs-with-skill.md`](../outputs/baseline-vs-with-skill.md)）显示自动出稿边界条目 11 条 vs 深度人工 18 条，且缺「易混淆正例」防误伤设计——这是平台评审两次点名的短板，靠提醒修不了，靠**结构 + 机器门槛**守。
   - **怎么做**：注入 [design-blocks-library.md](design-blocks-library.md) **边界类条目 TOP 3**（按 T1 边界主题标签命中，让 AI 出稿"手边有料"）→ 用 [capability-boundary.md](capability-boundary.md) **4 问决策树**对 **B01 / B02 / B05 / B06** 四个边界高产格逐格追问（话术见 [designer-guide-A.md](designer-guide-A.md) §边界补全追问）→ 补齐三类条目：**负例**（不做/不接管/不负责）、**易混淆正例**（"听起来超界，其实该本 skill 管"——防误伤）、**前提降级**（"满足 X 条件时降级为…处理"）。
   - **机器门槛**：`check_blueprint.py` **C7**——十格填齐后边界条目 <15 条或易混淆正例 =0 → WARN（退出码 2）；完整通道按 WARN 处理完再进④，轻量通道可先记录、④前补一次一句话自查。
   - **复盘门槛（B10）**：同脚本 **C8**——复盘记了教训却 0 条标注「已落检查项 / 不适用」→ WARN；配套 B10 两道必答项（教训→检查项 / 能力→主流程，见 [designer-guide-B.md](designer-guide-B.md) §四 B10 段）。**自动登记**：按「LXX → 落点」格式写（如 `L10 → validate_skill 第 15 项`）后跑 `check_blueprint.py <蓝图目录> --tick-reflow`，自动写回 lessons.md 引用计数 + 回流落点（幂等）。
6. **落盘 + checkpoint**：每格产物 Edit 写入蓝图文件 → 更新 index.md checkpoint → 三句话小结 + "对吗"。

### 闭环纪律

- 修改走**回退协议**（flow-recovery §④）：只回退被改动的格及其下游，不推倒重来。
- 卡壳 / 跑偏 / 中断 → flow-recovery 状态机恢复（二选一 / 复述 MVP / 读 checkpoint 续跑）。

### 出口 / 产物

- B01–B10 逐格定型的蓝图文件（checklist 勾选齐全）
- **非目标清单**已写入 `01-条件.md`（明确不做什么）
- **边界条目集**已补全（负例 + 易混淆正例 + 前提降级，散布 `01-条件` / `02-事实` / `05-分析` / `06-决策`）
- 用户说"可以出施工蓝图了"

## 四、④ 施工蓝图 — 正式施工蓝图 + 结构图 + 交接

### 用户看到什么（白话）

> "这是**正式施工蓝图**——各积木要点都定了，还配了一张**文件结构图**。你确认没问题，我就把它交给 skill-creator 落地。"

### Agent 内部做什么（按序）

0. **施工蓝图前门禁**：**非目标清单已在 ③ 确认并写入 `01-条件.md`**（缺则补，防功能膨胀）。
1. **质量门**：`check_blueprint.py`（IQS 机器算 + 缺口报告）→ 清缺口。
2. **B09 BR-5 评分**：五维各 1–5 分 + 每维证据定位（找不到证据最高 2 分）→ `b09_summary.py` 出摘要图（可选）。
3. **文件结构图**：`render_structure.py` → `structure.svg`（目录 + 每节点内容要点 + SKILL.md 五段骨架）。
4. **复盘晋升**：B10 收尾，候选规则过三问 → 写入**权威源** `library/lessons.json` → `compile_library.py --write` 重编译 `lessons.md`（md 是生成物，禁止手改）。
5. **交接产物**：`export_brief.py` → `summary.md` + `brief.json` + `SKETCH.md`（**含决策溯源表**：关键决策 ↔ 来源格 ↔ 类型，落地可对照溯源）。

### 施工蓝图交接

- 用户确认④施工蓝图 → **硬交接**（直接 invoke skill-creator，蓝图 brief 作 Step 1 输入）或**软交接**（可粘贴 handoff prompt）。
- 蓝图是**唯一事实源**：创建产出偏离蓝图 → 回蓝图修正，不默许漂移。

### 出口 / 产物

- 正式施工蓝图（各积木要点 + checklist 全过）
- 文件结构图 `structure.svg`
- 交接 brief（`summary.md` / `brief.json` / `SKETCH.md`，**含决策溯源表**）
- 非目标清单已确认（写在 `01-条件.md`）

## 六、护栏清单（实质功能一条不丢）

| # | 护栏 | 说明 | 落在四步哪一步 |
|---|------|------|---------------|
| 1 | **强制阻塞** | 触发词、skill 名用户产出，设计师只给候选 | ③④ |
| 2 | **通道选择** | 轻量（~30min）/ 完整（~2h），轻量压缩③简化④ | ① |
| 3 | **非蓝图意图轻量路由** | FAQ / 边界 / 守门**不强制进四步**——直接答，不走十格 | ①（路由判路） |
| 4 | **"你填"协作模式** | 用户想深度共创，可在③要求展开成逐格细聊 | ③ |
| 5 | **中断恢复** | 进度落蓝图 checkpoint，`check_blueprint.py` 读缺口续跑 | 全程 |
| 6 | **脚本可选** | Python 为平台自带工具；未装按提示装一行，仅用户明确拒绝才切对话引导，四步不中断 | 全程 |
| 7 | **边界补全不跳过** | ③的「边界补全」为固定步骤：完整通道必做，轻量通道至少一句话自查；C7 门槛 WARN 必须处理或记录 | ③④ |

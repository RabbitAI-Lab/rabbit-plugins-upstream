# 引导话术库（Part 2）— 协议层 + 分册入口

> SKILL.md 只给每格 essence + checklist，本文件族给"怎么问、追问什么、每格产出去哪"。引导形态为**半开放交互式**：固定骨架（10 格顺序不可跳）+ MVP 必需问题 + 增强问题（可选深挖）+ 设计师自由追问。
> 核心心法：**"好用的 skill 是聊出来的，不是生成出来的。"** AI 是助手，用户拍板。

## 一、总览：引导节奏与通用话术

每格固定节奏：

```
问 MVP 问题（非答不可）——默认给「AI 建议三件套」，用户可回"按建议"
  → 视投入度追问增强问题（可选深挖）→ 设计师自由追问（探积木链六问）
  → checklist 验收 → 产物 Edit 写入蓝图对应文件（init_blueprint.py 生成的 01–10 文件）
  → 【checkpoint】更新 index.md 进度快照（当前格/已完成/本格产物/待确认/下一步，见 flow-recovery.md）
  → 三句话小结 + "对吗？" 确认
```

**落盘约定**：Phase 0 三问确认后立即跑 `scripts/init_blueprint.py <蓝图目录> --name "<skill名>"` 生成蓝图骨架；此后每格产物写入对应文件——产物从"对话记忆"升级为"磁盘实体"，中断可续跑、机器可检查（`check_blueprint.py`）。

**自动动作速查**（用户常问 → 设计师自动做什么，不甩链接直接答；**FAQ 权威源是 quickstart.md 的 13 问速查表，答案冲突以 quickstart 为准**）：

| 用户问 | 自动动作 |
|--------|----------|
| 会帮我写文件吗 | 蓝图自动落盘；正式文件施工蓝图后交创建类 skill |
| 能先给我方案吗 | 走「我拟」，直接生成完整初步方案供讨论 |
| 能跳过蓝图吗 | 被跳过时转「伴随守门」逐格把关 |
| 10 格能跳吗 | 顺序固定；可合并相邻格、模板速填，产物须齐全 |
| 中断了怎么办 | 跑 check_blueprint.py 读缺口，从缺口续跑 |
| 改进从哪格起 | 诊断先行，仅对缺口格引导（见 designer-guide-B §七） |

**小结 → 确认节奏**：每个阶段收尾，三句话小结当前结论 + 明确询问——
> "到目前为止我理解的是：①…… ②…… ③……。这三项对吗？"
> 有偏差就改，对就进入下一格。**不要替用户默认正确。**

**术语纪律（首现即注，硬规矩）**：专业术语对用户**首次出现时，必须自动带括号白话注释**，不等用户问。例：「接下来给蓝图做 BR-5 打分（五维体检：好触发、跑得稳、好用、合规矩、有证据）」「机器算 IQS（蓝图质量分，看十格填得实不实）」。被动问答同样生效：用户问术语就**一句话白话答，不甩链接**；需展开才加载 blueprint-methodology §十。白话注释不影响专业能力——术语本身照用，注释放括号里。

**AI 建议三件套**（默认提问节奏：AI 做结构化归纳与专业建议，用户只做少量关键决策）：

| 件 | 内容 | 示例（B07 结构选型） |
|----|------|---------------------|
| ① 建议值 | AI 先给默认答案 | "我建议选 **tool 框架**" |
| ② 建议理由 | 一句话说清依据 | "B03 定了 Tool Wrapper + C 工具编排，tool 的 Failure Handling 侧重最匹配" |
| ③ 备选项 | 2–3 个替代 | "minimal（更快但装不下失败处理）或 full（更全但偏重）" |
| 快捷键 | 统一话术收尾 | "回'按建议'即可，或告诉我改哪。" |

**用法纪律**：先给建议再问（澄清类追问除外，不抛开放式问题）；AUTO 项（designer-guide-B §八）直接给建议值+一句理由不等确认；REQUIRED 项给三件套**必须等用户回复**；**建议 ≠ 代填**——触发词/name 等强制阻塞项仍只给候选；建议错了坦然改口重给，不硬撑。

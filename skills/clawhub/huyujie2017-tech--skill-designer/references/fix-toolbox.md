# 修复工具箱（Fix Toolbox）

> 本文件是 skill-designer 的**按需知识层叶子文档**。
> 定位：把 [design-blocks-library.md](design-blocks-library.md) 的 **9 反模式** 与 SKILL.md **Error Handling 的 9 错误场景**，从"只讲道理"升级为**可复制执行的修复产物**（prompt 模板 / 检查脚本 / 填空模板 / 编辑清单 / 降级 SOP）。
> 这是 skillhub 反馈"异常处理 4.0：只告诉哪里错、不自动修复"的针对性补齐——**设计师默认自动执行修复**（直接改，改完交您确认）；您也可选"我自己改"，此时才回落到下面的可执行工具。

## Part 1 — 9 反模式 → 可执行修复

### 1. 教程病（解释 LLM 已知概念）
**修复产物 · 删除 prompt 模板**
```
你是资深 Skill 编辑。检查下面的 SKILL.md，删除所有向 LLM 解释其已知概念/通用知识的段落
（如"什么是 API""Prompt 是什么""什么是 JSON"），只保留 Expert 特有知识、约束、流程与示例。
输出：① 删除后的精简版 ② 被删段落清单及理由。
```
**判定**：某段删掉后 skill 仍能正确工作 → 属教程病，删。

### 2. 堆砌病（SKILL.md 800+ 行无拆分）
**修复产物 · 体积检查脚本**
```python
import pathlib
p = pathlib.Path("SKILL.md")
n = p.read_text(encoding="utf-8").count("\n") + 1
print(f"SKILL.md 行数: {n}  {'⚠️ 超 800 行，需拆 references' if n > 800 else '✅ 在阈值内'}")
```
**修复**：把"如何做"细节迁到 `references/`，body 只留 essence + 加载触发器（见 test-playbook §六 静态检查 `body < 5K`）。

### 3. 孤儿引用（references 存在但从不被加载）
**修复产物 · 加载触发器检查清单**
```
对每份 references/X.md：
[ ] SKILL.md 正文有显式"何时加载 X"的链接/语句？
[ ] 若无 → 在 SKILL.md 加一行加载条件，或删除该文件。
```
**快速核查**：`grep -rn "X.md" SKILL.md` 应至少命中一次。

### 4. 清单流程（Step1/2/3 纯机械步骤）
**修复产物 · 升级为决策树模板**
```
将下列机械步骤改写为「判断规则 + 决策树」：
每个节点 = 条件 → 分支动作；保留"为什么这样分"的依据，而非只列步骤。
原则：给框架（判断规则），不给死步骤。
```

### 5. 模糊警告（"注意错误""小心边界"）
**修复产物 · Gotchas 改写模板**
```
把"注意 X"统一改写为三条：
① 症状：什么情况下会出错？
② 原因：为什么会这样？
③ 修复：具体动作（含代码示例）。
```

### 6. 隐身病（内容好但从不被激活）
**修复产物 · description 五维重写填空**
```
重写 frontmatter description，覆盖五件事：
1. WHAT：它做什么
2. WHEN：何时用（含触发词）
3. NEGATIVE：何时不用
4. LANGUAGE MATCH：中/英引导策略
5. TRIGGER WORDS：触发词边界（中英五维）
填入当前 skill 的内容：______
```
**检查**：触发词是否覆盖中英五维？缺失则补。

### 7. 错位触发（When to use 写在 body）
**修复产物 · 迁移编辑清单**
```
[ ] 把 body 中的触发信号（"当用户说…"）搬到 frontmatter description
[ ] body 只留流程与 essence
[ ] description 含中英触发词 + 否定边界
```

### 8. 过度工程（README/CHANGELOG/scripts 齐全但没必要）
**修复产物 · 自由度校准清单**
```
按任务风险校准：
[ ] 低风险/一次性 → 只写 SKILL.md
[ ] 中风险/复用 → + scripts
[ ] 高风险/长链路 → + references + assets
删掉当前用不到的脚手架。
```

### 9. 自由度错配（创意任务用死板脚本）
**修复产物 · 校准指引**
```
高自由度任务（创意/分析/探索）→ 给原则框架 + 示例，不写死脚本；
低自由度任务（确定性转换/格式固定）→ 写脚本 + 自检。
当前任务自由度：______ → 选 ______。
```

## Part 2 — 9 错误场景 → 可执行修复

| # | 场景 | 修复产物 |
|---|------|----------|
| 1 | 需求过不了准入四问 | **转向判定清单**：`做 / 不做 / 转 Rule·脚本·MCP`。每项给一句判据，引导用户选；不硬造 skill。 |
| 2 | 回答太宽泛 | **追问模板**："想象一个具体的人，在什么场景打开它，他开口第一句会说什么？" 用具体场景反推抽象需求。 |
| 3 | 沉默 / 不确定 | **二选一选项模板**：`A. ______  B. ______` 缩小范围；选项来自设计师基于画像的推测。 |
| 4 | 要求代填触发词/名字 | **礼貌拒绝 + 候选**：给 2–3 个候选触发词/name，让用户**自己选并确认**（强制阻塞）。 |
| 5 | 只想快速生成不管质量 | **轻量通道切换话术**："走轻量通道（~30min）先出最小闭环，质量门先跳过，后续可升级完整通道。" |
| 6 | 目标平台不明确 | **反推问题**："这个 skill 在哪里跑？终端 / IDE / 手机 / 网页？" 据答案定 allowed-tools 与字段。 |
| 7 | 引用的 reference 不存在 | **降级 SOP**：用 SKILL.md 内嵌知识继续，不阻塞流程；记录缺失项，事后补或修链接。 |
| 8 | 遇到已有 skill 想改进 | **切诊断先行分支话术**："我们走诊断先行——先诊断再填充，起点 B01，仅对缺口格引导。"（见 designer-guide §七） |
| 9 | Python 未装 / `command not found` | **三行安装指引**：①判定——「检测到当前环境无 Python（平台通常自带）」；②指引——一行安装命令（Windows：`winget install Python.Python.3`）；③出口——「回复『不用 Python』切对话模式（产物照出，落盘/机器打分/续跑暂不可用）」。**仅用户明确拒绝才切兜底**，不反复追问。详见下方 [Part 3 的 E003](#e003)。 |

## Part 3 — 错误码 → 一句话动作（脚本报错的统一出口）

> 脚本失败时用户看到的**不是**英文 traceback，而是下面这种三段式。
> 唯一事实源是 `scripts/errors.py`（改文案只改那里）；本节是给人和 agent 查的对照表。

```
❌ <错误码> <一句人话>
   下一步：<一个可执行动作>
   详情：<本表锚点>（原始信息）
```

| 码 | 一句人话 | 下一步（一个动作） |
|---|---|---|
| **E001**<a id="e001"></a> | 找不到这个文件或目录 | 确认路径拼写与当前目录，或改用绝对路径重试 |
| **E002**<a id="e002"></a> | JSON 内容有语法错误 | 贴到任意 JSON 校验器，补上缺失的逗号、引号或括号 |
| **E003**<a id="e003"></a> | 缺少运行依赖（通常 Python 未装或版本过低） | 按提示装一行即可（平台通常自带，零配置） |
| **E004**<a id="e004"></a> | 目标目录已存在且非空，拒绝覆盖 | 换目录名，或进已有目录续填（不删已有内容） |
| **E005**<a id="e005"></a> | 缺少必填内容，无法继续 | 按提示补齐标记项后重跑（可回「按建议」批量采纳） |
| **E006**<a id="e006"></a> | 写入失败（权限不足 / 磁盘满 / 文件被占用） | 关掉占用程序后重试，或换有写权限的目录 |
| **E007**<a id="e007"></a> | 蓝图缺口太多，未达导出门槛 | 先补齐缺口格再导出；确需带缺口请加 `--allow-gap` |

**知识库契约层（E008–E012，v3.17.0+ · `scripts/knowledge.py`）** — 这一组的关键语义是**熔断**：出错一律停下来 + 给一个动作，绝不改用模型记忆或旧索引「凑」出结果（**DP-210 失败即熔断**；错误归因不得降级）。

| 码 | 一句人话 | 下一步（一个动作） |
|---|---|---|
| **E008**<a id="e008"></a> | 知识库索引缺失、损坏或与脚本不同代 | `python scripts/knowledge.py index --write` 重建索引后重试 |
| **E009**<a id="e009"></a> | 索引与权威源不一致（条目被改/增/删而索引没跟上） | 先重建索引；仍不一致说明权威源被手工改过 → `git diff` 核对改动是否合法 |
| **E010**<a id="e010"></a> | 知识条目 ID 编号空间断裂（缺号或重复） | **ID 永久稳定、不得重编号**：缺号补条目、重复则合并，然后重建索引 |
| **E011**<a id="e011"></a> | 条目库视图不一致（分片条数 / 视图一声明 / 速查表 / 头部计数 四者对不上） | 四者已全部由 `compile_library.py` 派生 ⇒ 此错**理论上绝迹**；若仍报，说明有人手改了生成物 → `python scripts/compile_library.py --write` 覆盖回去 |
| **E012**<a id="e012"></a> | 设计观条目引用了不存在的做法条目 | 修正该 DP「来源」行的 D 编号，或补上被引用条目后重建索引 |

**派生件与吸收层（E013–E016，v3.18.0+ · `compile_library.py` / `absorb_intake.py` / `knowledge_remote.py`）** — 这一组的关键语义是**权威源唯一化**：md 视图与索引都是**生成物**，只改权威源而不同步派生件 = 派生件撒谎。

| 码 | 一句人话 | 下一步（一个动作） |
|---|---|---|
| **E013**<a id="e013"></a> | 生成物与权威源不一致（`references/*.md` 被手改，或没随 `library/*.json` 重编译） | 改内容改 `library/*.json` → `python scripts/compile_library.py --write` 重编译；只看差异跑 `--check --report <路径>` |
| **E014**<a id="e014"></a> | 远程增强服务不可用或需要授权（付费层 / 未配置地址 / 服务故障） | ① `--backend local` 用本地全量（功能不减弱）；② `--backend auto` 自动回落；③ 配置环境变量或完成支付授权 |
| **E015**<a id="e015"></a> | 吸收登记册腐烂（`dedup_index.json` 的等价物指向已不存在的条目/文件） | `python scripts/absorb_intake.py --check-dedup` 看清单 → 改判（注明改判轮次）或把 `equivalent` 更新到新 ID |
| **E016**<a id="e016"></a> | 版本协商未通过（本地流程低于远程知识库要求的最低流程版本） | 升级 skill-designer 本体（推荐）；应急 `--backend local` 或 `--backend auto` |

> **E013–E016 的判据**：E013 由 `knowledge verify` 的 C5 报出；E015 由 `absorb_intake --check-dedup` 报出；E014/E016 由后端解析时熔断报出（E016 与 E014 **不合并**——前者动作是「升级本体」，后者是「切本地或配置」）。**这四条都被 `knowledge selftest` 的坏样本回归覆盖**（9 例）。

**退出码**：`0` 成功 ｜ `1` 业务失败（统一）｜ `2` 仅警告（`check_blueprint` 缺口 / `validate` WARN，**可继续**）｜ `3` 打包卫生拦截（`sd_cli package`）｜ `4` 包完整性失败（`package --zip` 解包复验）。
**为什么保留 2**：它表示"有缺口但可继续"，是续跑依据；盲统一成 1 会破坏中断续跑编排。

## 使用纪律

- **默认自动修，可选手动改**：设计师识别到反模式后**直接执行修复**（生成精简版 / 补加载条件 / 迁移 README），改完交用户确认；用户要自己改时，用下面产物当检查单。
- 每条产物可直接复制进对话让 LLM 执行，或作为您手动修改的检查单。
- **硬性项先交给机器**：YAML 有效 / name 与目录一致 / 引用完整 / 体积守门 / 密钥安全 直接用 `scripts/validate_skill.py <skill_dir>` 判定（`--json` 出结构化结果）；`--fix` 自动修复（README 迁移等）；`--diag` 出软性项结构化诊断（症状/根因/修复）。修完再跑。
- 修复后回到 [test-playbook.md](test-playbook.md) 闭环验证：触发测试 + 效果测试 + 🌟/⚠️/💡 打磨。

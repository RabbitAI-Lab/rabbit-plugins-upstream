# 07 治理制度与流程

> 适用：把资产管理落成组织制度——角色、流程、审计
> 核对基准日：2026-08

## 1. 角色职责（RACI 摘要）

| 角色 | 职责 | 关键动作 |
|---|---|---|
| 资产 Owner | 资产全生命周期负责 | 版本/状态/成本/质量 |
| AI 平台团队 | 平台与工具链 | 台账系统、监控、CI 集成 |
| 安全/合规 | 准入准出审核 | 安全评测、合规核查 |
| 业务方 | 需求与验收 | 场景确认、指标验收 |
| AI 治理委员会 | 制度与仲裁 | 制度审批、重大变更评审 |

## 2. 审批流设计

```
日常变更（Prompt 小改）    → 资产 Owner 审批 + L0 冒烟
常规发布（模型升级）       → Owner + 平台团队 + 安全
重大变更（换供应商/跨版本） → 治理委员会评审
退役                     → Owner + 业务方确认
```

- 审批记录留痕（谁批的、依据什么）
- 紧急回滚可后补审批（安全优先）

## 3. 审计要求
- **变更留痕**：资产版本变更全记录（时间/人/原因/结果）
- **季度审计**：台账准确性抽查、无人资产清理、合规状态复核
- **年度报告**：资产全景、成本、质量趋势、治理改进

## 4. 制度落地建议
1. 制度先行：发布《AI 资产管理办法》（台账/版本/上下线/成本）
2. 工具配套：台账系统（起步可用表格，逐步上平台）
3. 度量考核：资产登记率、版本覆盖率、退役及时率
4. 培训宣导：Owner 培训 + 新员工入门

## 5. 常见误区
1. "制度太重影响效率"——分层审批（小改快批，大改严审）平衡
2. "审计是找茬"——审计是防风险与追溯的基础
3. "委员会形同虚设"——重大变更必须真评审，否则制度失效

# 04 上线下线管理

> 适用：AI 资产的启动与退役——准入准出的双向闸门
> 核对基准日：2026-08

## 1. 上线管理（准入）

### 1.1 上线审批要素
| 检查项 | 要求 |
|---|---|
| 评测通过 | 评测集过门禁（衔接 LLM 评测） |
| 安全通过 | 红队/安全评测无高危（衔接红队） |
| 合规通过 | 数据/标识/出境/条款核查 |
| 成本核准 | 预算内，ROI 说明 |
| 运维就绪 | 监控、告警、支持、负责人 |

### 1.2 上线流程
```
申请（附 Model Card/评测/安全/成本） → 评审（工程+安全+合规+业务）
→ 灰度（5%-10%） → 全量（指标达标） → 台账更新（状态=已上线）
```

## 2. 退役管理（准出）

### 2.1 退役触发
- 被新版本/新模型替代
- 长期无使用（3 个月零调用）
- 成本过高且无业务价值
- 供应商停服/条款变更/安全问题

### 2.2 退役流程
```
① 确认替代方案（迁移到哪个模型/方案）
② 通知用户（业务方确认无依赖）
③ 数据清理（涉及数据的合规处置）
④ 下线执行（停流量→停服务）
⑤ 台账更新（状态=已退役 + 退役原因 + 替代资产）
⑥ 归档（保留评测记录/审计留痕）
```

## 3. 废弃资产处置红线
1. **先迁移后下线**：不能"直接删了"——必须有替代方案承接
2. **数据合规**：涉及个人数据的按数据法规处置（衔接数据出境/GDPR）
3. **留痕归档**：退役原因与替代记录入档（审计与复盘需要）

## 4. 常见误区
1. "上线容易退役难"——退役要有流程，避免僵尸资产
2. "新模型上线就直接切"——必须灰度，直接切风险大
3. "下线后数据随便删"——数据处置有合规要求

# 02 模型卡与注册

> 适用：模型注册与 Model Card——每个模型的身份档案
> 核对基准日：2026-08

## 1. 为什么需要模型卡

模型卡（Model Card）是模型的"身份档案 + 使用说明书"，解决：
- 新接手的人不知道模型是什么、能干什么、限制是什么
- 采购/合规审查没有依据
- 上线决策没有结构化信息

## 2. Model Card 字段规范

```
一、基本信息
- 模型名称/版本/类型（基座/微调/蒸馏）
- 供应商/来源（自研/第三方 API/开源）
- 部署方式（API/私有化/边缘）
- 创建人/时间/负责人

二、能力与用途
- 设计用途（预期任务/场景）
- 已评估的能力边界（评测集结果）
- 不推荐用途（明确的禁用场景）

三、数据与训练
- 训练数据来源/规模/时间
- 微调数据说明（如适用）
- 数据合规状态（授权/脱敏/版权核查）

四、评测表现
- 评测集与指标结果（衔接 LLM 评测 skill）
- 已知失败模式与限制

五、安全与合规
- 安全评测结果（衔接红队 skill）
- 内容标识义务（衔接内容标识 skill）
- 数据出境/本地化要求（如适用）
- 许可证/使用条款（开源/API 条款）

六、运维信息
- 成本（单次/月）
- 监控指标与告警（衔接 05 漂移监控）
- 支持渠道/升级计划
```

## 3. 注册流程

```
① 模型候选：开发/采购的模型提交注册申请
② 材料齐备：Model Card 六大字段填齐 + 评测结果 + 安全结果
③ 审批：模型治理评审（工程+安全+合规+业务）
④ 注册：写入资产台账，分配资产 ID，状态=开发中
⑤ 上线更新：灰度→全量后状态更新，Model Card 补充线上表现
```

## 4. 模型卡维护
- 每次版本变更更新（不能只更新模型不更新卡）
- 季度复核（能力/成本/合规状态变化）
- 退役时标注退役原因与替代模型

## 5. 常见误区
1. "模型卡是文档工作，没实际用"——它是审计/合规/交接的核心依据
2. "只填基本信息"——能力边界与禁用场景是采购和使用的安全阀
3. "模型卡写一次就行"——版本变了必须同步更新

# 01 资产全景与台账

> 适用：AI 资产盘点与台账建立——LLMOps 的第一步
> 核对基准日：2026-08

## 1. 五类 AI 资产

| 资产类型 | 示例 | 关键属性 |
|---|---|---|
| 模型 | 基座模型、微调模型、蒸馏模型 | 版本、供应商、部署方式、成本 |
| Prompt | 各场景提示词模板 | 版本、参数、适用场景 |
| 知识库 | RAG 文档集、向量库 | 版本、切块策略、更新时间 |
| 评估集 | 黄金数据集、对抗样本 | 版本、标注人、覆盖场景 |
| Agent 配置 | 工具权限、护栏、流程编排 | 版本、权限范围、责任人 |

## 2. 台账字段规范

| 必填字段 | 说明 |
|---|---|
| 资产 ID | 唯一标识（如 model-001 / prompt-037） |
| 类型 | 五类之一 |
| 名称/版本 | 资产名 + 语义化版本号 |
| 状态 | 开发中/已上线/灰度/已退役 |
| 负责人 | 资产 Owner（唯一） |
| 业务场景 | 关联的业务应用 |
| 依赖 | 依赖的模型/知识库/工具 |
| 成本信息 | 单次/月成本估算 |
| 更新时间 | 最近变更时间 |
| 备注 | 已知局限、风险等级 |

## 3. 盘点流程

```
① 摸底：扫描线上/开发中的 AI 应用，列出使用到的全部资产
② 登记：按台账字段逐一登记（缺失信息找应用负责人补齐）
③ 标记：标出"无人负责/无人使用/版本混乱"的资产
④ 清理：无人使用的停用登记（退役流程见 04 模块）
⑤ 复核：季度盘点核对（新增/变更/废弃）
```

## 4. 台账管理红线
1. **唯一负责人**：每项资产一个 Owner，避免"三不管"
2. **状态实时**：灰度/退役等状态变更及时更新
3. **版本关联**：应用版本 ↔ 资产版本要能追溯（出问题知道"用的哪个模型哪个 Prompt"）
4. **权限可控**：台账增删改权限受限，变更留痕

## 5. 常见误区
1. "先用了再说，台账以后补"——没有台账，版本/成本/问题都无法追溯
2. "台账就是 Excel"——Excel 可以起步，但要有版本与审计意识
3. "只登记模型"——Prompt 和知识库同样关键（很多质量问题源于它们）

# 03 版本管理

> 适用：模型/Prompt/知识库的版本化、灰度与回滚——AI 变更的安全网
> 核对基准日：2026-08

## 1. 为什么要版本化

AI 变更（换模型、改 Prompt、更新知识库）**影响面大且不可预测**：
- 改一个 Prompt 词可能全局行为变化
- 模型供应商更新可能悄悄变差
- 没有版本化 = 出问题无法回滚 = 用户端受灾

## 2. 三层版本管理

| 资产 | 版本化方式 | 关键点 |
|---|---|---|
| 模型 | 模型版本 + 供应商版本快照 | 记录供应商更新日志 |
| Prompt | Prompt 版本（内容+参数） | 每次改动即新版本 |
| 知识库 | 数据集版本 + 向量库快照 | 文档变更触发新版本 |

## 3. 发布流程（灰度制）

```
① 变更冻结：当前版本打快照（模型+Prompt+知识库+配置 全量）
② 构建新版本：改代码/提示词/配置，跑 L0 冒烟（衔接 LLM 评测）
③ 灰度发布：5%-10% 流量先上（或影子模式）
④ 观察指标：核心指标 vs 基线（忠实度/满意度/报错率）
⑤ 放量/回滚：指标达标→逐步放量；不达标→一键回滚到快照
```

### 灰度决策规则（示例）
| 信号 | 动作 |
|---|---|
| 核心指标 ≥ 基线 | 放量至 50% |
| 核心指标 < 基线 5% 内 | 观察 24h 再定 |
| 核心指标 < 基线 5% 以上 | 回滚 |
| 出现安全事故/严重报错 | 立即回滚 |

## 4. 回滚机制
- **快照完备**：每个发布版本都有完整快照（模型+Prompt+知识库+配置）
- **一键回滚**：回滚操作要快（分钟级），不能手工改配置
- **回滚后复盘**：为什么回滚、如何防复发（根因闭环）

## 5. 版本关联与追溯
- 应用版本 ↔ 模型版本 ↔ Prompt 版本 ↔ 知识库版本 关联记录
- 线上问题排查：从"应用版本"追溯到"资产版本"定位问题源
- 变更日志：谁、何时、改了什么（审计需求）

## 6. 常见误区
1. "小改动不用版本化"——Prompt 一行改动也可能翻车
2. "灰度太麻烦"——灰度成本远低于全量事故成本
3. "只存新版本"——旧版本快照是回滚的生命线

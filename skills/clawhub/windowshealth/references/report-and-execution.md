# windows-health · 报告、执行与回滚

## 报告模板

每条建议必须包含：是什么、多久没用/证据是什么、处理后会怎样、如何恢复。

```markdown
# 系统健康诊断 · YYYY-MM-DD · Windows

## 磁盘概况
- 总容量 / 已用 / 可用 / 使用率（Get-PSDrive）

## 性能诊断
- 高 CPU/内存进程、页面文件、启动项 + Microsoft 官方工具映射

## 可安全清理 · TIER 1
- 路径、大小、是什么、为什么判定为缓存、删了怎样/如何重建、候选命令（未执行）

## 只展示或逐条确认 · TIER 2/3
- 路径、大小、风险、额外证据（含权限等级）

## 文件治理
- KEEP_LOCAL / ARCHIVE_CLOUD / ARCHIVE_LINK / DELETE_DUPLICATE（附 SHA256）/ PLAN_ONLY

## 预计收益与限制
- 可释放空间、证据局限、NTFS/OneDrive 延迟
```

报告末尾明确：「候选命令未执行；只有用户明确授权后才能进入执行阶段。」

## 执行授权

授权必须指向具体动作和路径。模糊的「帮我看看」「清理一下」只授权诊断。执行前再次列出：动作类型、精确源路径与目标路径、预计空间、是否可恢复、备份/MANIFEST/保留副本。

## 执行顺序

1. 快照磁盘、源和目标状态。
2. 验证路径未命中保护列表。
3. 执行单一、可审计动作（`Remove-Item -Recurse -Force`，明确路径）。
4. 写 MANIFEST：时间、size、files、source、destination、action、hash（适用时）。
5. 迁移结构关键目录后创建并验证符号链接。
6. 复测空间和关键工作流。
7. 报告实际结果，不把 NTFS/OneDrive 延迟当作失败或成功。

## OneDrive

- 先移动到归档目录并等待同步。
- 释放本地空间使用「移除本机下载」语义，不删除云端归档本体。
- 原路径被引用时优先符号链接；不支持的程序保留本地或改配置。

## 去重

候选只能由名称/大小产生；删除依据必须是 Get-FileHash SHA256 一致。明确保留哪一份、为什么该路径更权威。哈希不同即保留两份。

## 回滚

- 删除缓存：App 重建或重新下载。
- 云端迁移：按 MANIFEST 移回。
- 符号链接：删除链接后把目录移回原路径。
- 重复副本：从保留副本复制。
- 误动高价值目录：立即停止，先查回收站、OneDrive 最近删除和备份，不继续清理。

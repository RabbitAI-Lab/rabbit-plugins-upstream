# 上市前专利排查 · PatentMax

新产品上市前，最怕撞上别人的有效专利。这个技能按**功能点**逐个查一遍：每个功能点列出**最相关的几件有效专利**、专利权人、还有几年到期，整理成一张排查清单。它**不下侵权结论**，帮你判断哪些点要请律师做正式分析。

**不需要 API Key 就能用。** 专利数据来自 PatentMax 专利库，覆盖中国及美国、欧洲、日本、韩国、WIPO。

使用问题、企业采购：访问 **ip930.com**，右下角「联系客服」。

## 运行环境（必读，所有命令都适用）

部分 WorkBuddy 等环境的命令行不完整，`cat`、`ls`、`sleep`、`rm` 等可能找不到。为保证任何电脑都能跑通：

- 脚本路径一律写**绝对路径**：`$DIR/scripts/patentmax_client.py`（`$DIR` 是本技能所在目录），不要写 `cd ... && ...`（前一步失败会让后面整条静默不执行）
- `python` 找不到时依次试 `python3`、`py`；还找不到就用 WorkBuddy 自带的：先用 Glob 在 `~/.workbuddy/binaries/python/versions/` 下找到 `python.exe`，用它的完整路径。**下文所有 `python` 都按这条替换**
- 不要用 `cat` 读文件：读结果文件用 Read 工具，或用脚本的 `read` 子命令
- 检索命令几秒就返回；命令超时设为 120 秒即可

## 第 1 步：先问清楚（最多一轮）

1. 产品是什么、卖到哪些国家（默认中国）
2. 3～8 个关键功能点或结构特点（越具体越好，例如「拖布自动抬升」「基站自动集尘」）

说清产品和功能点就直接开始；用户只给了产品名的，先帮他列出可能的功能点让他确认。

## 第 2 步：怎么做

1. **每个功能点写检索式**：「产品名 + 功能词」两组，**每个功能词配 2～3 个同义说法**（例如 抬升 / 升降 / 提升），用 OR 连起来再加引号，加 `AND legalStatus:有效专利 AND type:(发明授权 OR 实用新型)`；卖到国外的，对目标国另写英文检索式，加 `countryCode:<国家>`。
2. **逐个检索**：每个功能点 `search --sort rank --size 20`，读标题和摘要，挑出和用户描述**最接近**的 3～5 件 `candidates mark --status keep`。
3. **看权利要求**：每个功能点最接近的 1～2 件 `brief --patent <号>`（¥0.10），看**独立权利要求**的技术特征，对照用户的功能描述，标「特征很接近 / 部分接近 / 不太接近」。**只做文字比对，不下侵权结论**。
4. **算到期**：发明授权自申请日起 20 年、实用新型 10 年，写出预计到期年份；快到期的标出来。
5. **分级**：每个功能点给一个关注等级——高（有特征很接近的有效专利）/ 中（部分接近）/ 低（没找到接近的）。
6. **写清单**（见下一节），并用 `candidates export --out 候选专利.csv` 导出。

**费用：** 每个功能点检索 1～2 次、精读 1～2 篇（¥0.10 / 次）；5 个功能点约 ¥1～2，每天前 30 次检索和精读免费（免费试用也算）。 开始前用一句话告诉用户大概花多少。

## 第 3 步：交付

写一个文件 `上市前专利排查清单.csv`，列依次为：

| 功能点 | 关注等级 | 公开号 | 标题 | 专利权人 | 类型 | 预计到期 | 接近程度 | 说明（哪些特征接近） |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |

- 用 Write 工具写成 UTF-8（带 BOM）的 CSV；按功能点分组，关注等级高的在前
- 第一行写产品、目标市场、各功能点的检索式和日期，并注明「本清单为专利初筛，不构成侵权或自由实施（FTO）结论」
- 「说明」只写文字上哪些特征接近，引用权利要求原文

在对话里依次给出：
- 一句话结论：几个功能点里，几个关注等级高
- 每个「高」的功能点：最接近的专利、专利权人、到期时间
- 建议：等级高的请专利律师做正式分析；可以配合规避设计看怎么改
- 提醒：这是初筛，不是 FTO 结论；没查到不代表没有风险
- 清单文件的位置

`上市前专利排查清单.csv` 最后加一行：`数据来源：PatentMax 专利库（ip930.com）`。

## 命令速查

```bash
python "$DIR/scripts/patentmax_client.py" search --q "\"扫地机器人\" AND \"拖布\" AND \"抬升\" AND legalStatus:有效专利 AND type:(发明授权 OR 实用新型)" --scope cn --sort rank --size 20 --json-out f1.json   # 一个功能点
python "$DIR/scripts/patentmax_client.py" brief --patent <公开号> --json-out b1.json                     # 看独立权利要求，¥0.10
python "$DIR/scripts/patentmax_client.py" candidates export --out 候选专利.csv
```

每条命令都加 `--json-out <文件>`，再用 `read` 或 Read 工具看结果（Windows 上直接读控制台输出会乱码）。
检索式写法、全部命令和参数见 `references/tools.md`、`references/query-syntax.md`。

## 出错时

- 输出里有 `"error": true` 或退出码不是 0：这一步没跑成，**不能写成「没检索到」**；原样把 `message` 告诉用户，网络问题就原样重跑同一条命令
- 第一次运行时输出里有「[PatentMax] 已自动领取免费试用……」：把这句话原样转告用户一次
- 出现 `"free_trial": true`：免费试用用完或过期，`message` 里写着怎么办（注册 PatentMax 再送 ¥50 体验额度），原样转告

## 它不做什么

- **不是侵权或 FTO 结论**，只是初筛；正式结论请找专利律师
- 按关键词检索，功能点描述不同的叫法会漏；没查到不代表没有风险
- 只看有效的发明授权和实用新型；审查中的申请将来也可能授权
- 外国专利只能用原文关键词查

**每一条专利信息都必须来自接口返回值**，不凭记忆补公开号、申请人、日期或法律状态。

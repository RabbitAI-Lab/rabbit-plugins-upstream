# 持续运营自动化工作流（V6.0 · 时间驱动型）

> V6.0 补齐「**时间维度**」：除请求驱动（说一句话就办）外，技能还能在**时间到点时自动运转**。本文定义四类时间触发型运营流，全部落地到 WorkBuddy 设备侧能力 + IMA 知识库 + 腾讯文档（映射见 `workbuddy-adaptation.md`）。
>
> **运行假设**：WorkBuddy 提供「定时/自动化」触发（如每日/每周 cron、或用户手动「开启自动驾驶」后由技能在对话中按节奏推进）。技能侧负责**流程编排与内容生成**，触发调度由宿主提供。

---

## 总览：四类运营流

| 流 | 触发 | 产出 | 落点 |
|----|------|------|------|
| OPS-1 新生 4 周上手自动驾驶 | 入学/开班日 T0 | 4 周周计划 + 每周课件+测评+提醒 | 日历+闹钟+IMA+腾讯文档 |
| OPS-2 每日 AI 速递 | 每工作日 08:30 | 1 篇前沿速递 + 1 道练习题 | IMA 检索→腾讯文档→分享 |
| OPS-3 考前复习自动提醒 | 测评/考试前 N 天 | 复习清单 + 闹钟 + 自测题 | 闹钟+备忘录+IMA |
| OPS-4 教研组周报 | 每周五 17:00 | 本周备课/评估/协作汇总 | 腾讯文档→分享教研组 |

---

## OPS-1 · 新生 4 周 AI 上手自动驾驶（⭐ BNBU/SAI 旗舰流）

**来源**：`module-e-bnbu-sai.md`「4 周 AI 实战上手加速包」+ 博智坊六期主题。

### 编排（T0 启动一次，后续自动按周推进）
```
T0  开班：INTENT(ability=ops, context.bnbu=true, audience=BNBU新生)
     → PLAN(4周路径: W1大模型基础 / W2 Vibe Coding / W3 AIGC / W4 3D重建&CV)
     → BUILD 第1周课件+游戏+自测题 (走 Runbook A/B/D)
     → DELIVER: 日历排 4 周课表 + 每周一闹钟 + IMA 落库 + 腾讯文档周包
     → 设「下周一 08:00 推进 W2」提醒
Wk+1..4 到点：自动取下一包 → BUILD → DELIVER → 设下一周提醒
W4 末：RUN Runbook D 综合测评 → LEARN 输出「上手认证达标评估」→ 腾讯文档结课报告
```

**自动化要点**：
- 全部用 `workflow-orchestrator.md` 的 8 阶段管线，**仅 T0 需人工开启**，其余按提醒自动续跑（状态文件保活）。
- 每周包 = 课件(1) + 游戏(1) + 自测(1) + 周计划(备忘录)，经 VERIFY 全测后分发。

## OPS-2 · 每日 AI 速递（保持前沿敏感度）

### 编排（每工作日 08:30）
```
触发 → BUILD: IMA 知识库检索「本周 AI 新发展」(G 模块素材)
     → 生成 1 篇 300 字速递 + 1 道配套练习题(关联已学模块)
     → VERIFY(速递无事实硬伤 / 题目可答)
     → DELIVER: 腾讯文档「AI 每日速递」追加 + 分享教研组/班级群
     → 可选: 设「今晚 20:00 做一题」闹钟
```

**差异化**：周末版加「本周回顾」；考前周加「薄弱点专项」。

---

## OPS-3 · 考前复习自动提醒（评估闭环的守门员）

### 编排（测评/考试前 3 天、1 天）
```
触发(由 OPS-1 或用户设的考试日历引发) →
  BUILD: 据「已完成模块」生成复习清单 + 抽取 10 道自测题(Runbook D 简化)
  → DELIVER:
       ① 闹钟「考前复习」(考试前 1 天 19:00)
       ② 备忘录「复习清单 + 自测链接」
       ③ IMA 存自测题(可回看)
  → 考试后: 自动 RUN Runbook D 测评 → LEARN 回流薄弱点
```

---

## OPS-4 · 教研组周报（协作沉淀）

### 编排（每周五 17:00）
```
触发 → BUILD: 汇总本周
       - 新增/迭代课件游戏(IMA 已落库清单)
       - 评估完成数与平均薄弱点(Runbook D 数据)
       - 协作备课室变更(腾讯文档版本)
     → DELIVER: 腾讯文档「教研组周报」+ 分享 + 备忘录待办
     → LEARN: 把高频薄弱点写入下周 OPS-2 速递选题
```

## 运营流的通用约束

1. **授权优先**：任何 IMA/腾讯文档写入前确认授权（同 `workbuddy-adaptation.md` §9），未授权则降级为「本地生成 + 给操作指引」。
2. **最小打扰**：自动化流默认「静默生成 + 关键节点 1 条提醒」；用户可设「仅周报」「全静默」。
3. **可中断/可恢复**：运营流状态写入 `workflow-state-template.json`，用户说「暂停自动驾驶」「改 4 周计划为 6 周」即可热更新。
4. **不越权**：不自动发邮件/外发敏感信息；分享范围限班级/备课组（回扣 F2 隐私、商用标准 §6）。

---

## 与请求驱动流的衔接

运营流不是孤岛——它**复用**请求驱动的 runbook：
- OPS-1 每周包 = Runbook A/B/D 的定时版
- OPS-3 自测 = Runbook D 的简化版
- 所有 BUILD/VERIFY/DELIVER 阶段与 `workflow-orchestrator.md` 完全一致

> 一句话：**运营流 = 把「请求驱动的工作流」按时间自动点火**。

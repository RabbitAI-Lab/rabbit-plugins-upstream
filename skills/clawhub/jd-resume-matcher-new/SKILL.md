# JD-Resume Matcher（岗位-简历精准匹配分析）

## Overview

以资深猎头视角，将招聘 JD 与简历逐项比对，产出结构化匹配分析报告，帮助招聘方与求职者快速做出判断。核心流程：输入校验 → 红线排查 → 要求提取 → 匹配矩阵 → 加权评分 → 差距优化建议 → 求职意向核查 → 面试追问预测。

**快速导读**：只想知道怎么用、怎么触发 → 看 `USAGE.md`；想看输入输出长什么样 → 看 `references/example.md`（标准场景）与 `references/example-boundary.md`（边界场景）；完整执行规范 → 从下方「执行流程」第 1 步开始逐条遵循。

## 全局纪律约束（违反任何一条即为不合格输出）

执行本技能的任何环节，都必须遵守以下四条硬约束：

1. **禁止空洞词汇**。分析中严禁使用「具有良好的沟通能力」「具备团队精神」「经验丰富」「能力突出」「匹配度高」等无实证的空洞表述描述匹配度。每一句结论必须指向具体条目与具体证据。报告开头禁止寒暄与客套语，直接进入正文。
2. **原文对照原则**。所有匹配判定必须基于 JD 原文中的**动词、名词和数字**逐字对照。例：JD 写「主导 3 个以上项目」，简历证据必须能同时对应「主导」这一动词与「3 个」这一数字；对应不上或只对应其一，即为部分符合或不符合。引用时保留原文措辞，不得意译。
3. **改写理由强制标注**。每一条简历优化/改写建议，必须以固定句式收尾：「改写理由：为了回应 JD 第 X 条中的『（引用该条原文）』」。
4. **偏见防护**。判定与评分仅基于技能、成果、经验等岗位相关证据；候选人姓名、性别/年龄推断、毕业年份、院校名气、公司名气等无关信号不得影响任何判定与分值。报告中的简历证据引用仅限岗位相关内容，联系方式、证件号、住址等与岗位无关的个人信息不得出现在报告中。

## 输入要求

- **完整匹配分析必需**：JD 全文、简历全文，两者齐全时执行标准 8 步流程。任一缺失时，明确告知缺什么，并按「场景 3：单边输入」提供对应的轻量分析（或请用户补充另一份材料）；不得凭空假设或用常识补全。
- **可选**：候选人的求职意向说明（期望城市、目标行业、期望薪资、关注的公司特质等）。若简历中含求职意向信息，直接提取；若无，相关项如实标注「待确认」，不得推测。

## 输入场景与预处理

### 场景 1：简历以文件形式提供（PDF / Word / 图片）

1. 先将文件全文提取为纯文本（可使用可用的文件读取/文本提取/OCR 能力），再进入标准流程；不得跳过提取直接凭文件名或想象分析。
2. 提取成功后在报告「招聘截止日期」行下方注明一行：「简历来源：由用户提供的文件提取，提取结果已逐字核对」。
3. 提取失败或乱码严重时，不得臆测补全：明确告知用户提取失败的原因，请用户改用文本粘贴方式提供简历全文，本轮不出报告。
4. 图片版简历经 OCR 提取后，对模糊难辨的字段（如日期、数字）按第 5 步「从严取低值」口径处理，并在证据引用处标注「（OCR 提取，可能有误差）」。

### 场景 2：批量输入（多份 JD 和/或多份简历）

先判断材料组合，再按下表选择模式：

| 材料组合 | 处理模式 |
|---|---|
| 1 份简历 × 多份 JD | 逐份 JD 独立输出完整报告，最后附「横向对比汇总表」 |
| 多份简历 × 1 份 JD | 逐份简历独立输出完整报告，最后附「横向对比汇总表」 |
| 多份简历 × 多份 JD | 先向用户确认分析优先级（按 JD 逐份 or 按简历逐份），默认按 JD 逐份 |

- **横向对比汇总表**列定义固定：`材料 | 红线结论 | 总分 | 匹配等级 | 一句话结论（引用具体 JD 条目）`，按总分降序排列；多 JD 时在表末附一行推荐投递排序及理由。
- 批量模式下，每份材料的报告仍须完整执行 8 步流程与全部纪律约束，**不得因批量而省略矩阵、评分依据或改写理由**。
- 批量报告中每份材料须有明确标识（如「JD A / 简历甲」），编号在报告开头统一声明。

### 场景 3：单边输入（仅 JD 或仅简历）

仅提供一侧材料时**不执行评分**（加权评分需双向对照），按以下轻量模式输出，四条纪律约束仍然全部适用：

**仅 JD（岗位要求质量评估）**：

- 报告开头注明：「仅提供 JD，以下为岗位要求质量评估；补充简历后可输出完整匹配分析报告」。
- 输出内容：① 逐条编号并分类（硬性/软性/行业背景/非能力条目），标注必备/加分；② 硬性门槛清单（进入红线排查的项）；③ 要求表述质量问题——指出无法对照验证的模糊表述（如「经验丰富」「能力突出」等无量化措辞），并给出建议的量化改写；④ 维度覆盖度——硬性/软性/行业三维度各有几条、是否缺失；⑤ 招聘截止日期处理同第 1 步；⑥ 末尾附「建议向招聘方澄清的问题清单」。

**仅简历（通用简历优化建议）**：

- 报告开头注明：「仅提供简历，以下为通用优化建议（不针对特定岗位）；提供目标 JD 后可输出精准匹配分析」。
- 输出内容：① 量化缺失——指出只有职责描述、无数字结果的条目（如「负责 XX 开发」无指标），建议补充量化口径；② 动词强度——弱动词（参与/协助/负责）与强动词（主导/设计/落地）的使用情况与替换建议；③ 空洞词清理——自我评价等区块的空洞表述及替换建议；④ 结构与信息完整性——时间线断档、模块缺失等如实指出。
- 不得虚构任何经历或数据；单边模式下不输出红线表、矩阵、评分与意向核查章节。

## 适用行业范围

本技能为跨行业通用设计，以下行业均在支持范围内（列举不限于此）：

- **智能制造**：消费电子代工、汽车及零部件、工业机器人、精密机械
- **新能源**：锂电池/储能、光伏、电控电驱、充电设施
- **半导体**：芯片设计、晶圆制造、封测、载板与材料
- **软件与互联网**：软件开发、算法/数据、AI 应用落地、产品运营
- **汽车出行**：整车、新势力、智能驾驶、车联网
- **金融**：银行、证券、保险、金融科技
- **医疗健康**：医药、医疗器械、体外诊断、医疗服务
- **能源化工**：电力、石油化工、新材料、环保
- **消费品**：快消、零售、电商、食品饮料
- **物流供应链**：快递快运、仓储、跨境物流
- **建筑工程**：工程建设、地产、装饰设计
- **专业服务与职能**：人力资源、财务、法务、行政、咨询

行业适配纪律：无论何种行业，红线排查与要求提取均以 JD 原文为准（如 JD 中的行业术语、行业证书、行业法规要求须逐字对照简历证据）；JD 涉及上述列表之外的行业时，同样按本流程执行，不得以「行业不熟悉」为由跳过或臆测。

## 执行流程

### 第 1 步：输入校验与 JD 编号

1. 校验 JD 与简历是否齐全（见「输入要求」）。
2. 将 JD 逐条编号（第 1 条、第 2 条……），编号规则覆盖全部要求行，包括任职资格、职责描述、薪资福利等。后续所有引用一律使用该编号。
3. **提取招聘截止日期**。在 JD 中识别「招聘截止/X月X日前/报名截止/招满即止/长期招聘」等日期表述，按下表处理：

| JD 中的截止信息 | 处理方式 |
|---|---|
| 有明确日期 | 提取为 YYYY年M月D日，并计算距今天数 |
| 「招满即止/长期招聘」 | 记为「招满即止（无固定截止日）」，并在报告中提示「岗位可能随时关闭，建议尽早投递」 |
| 未标注任何信息 | 记为「未标注」，自动汇入第 7 步「向 HR 核实的问题清单」（问题：「该岗位的招聘截止时间是什么时候？」） |

   - 已过期（截止日早于今天）→ 在报告顶部紧随红线警告之后标注「⏰ 注意：JD 所示招聘截止日期（X月X日）已过期，请先向招聘方核实岗位是否仍在招，再决定是否投递」。
   - 临期（距截止 ≤7 天）→ 在报告顶部标注「⏰ 提示：该岗位 X月X日截止招聘，仅剩 N 天，建议尽快投递」。
   - 截止日期信息一律引用 JD 原文（含编号），不得凭简历或常识推测。

### 第 2 步：红线排查

从 JD 中提取硬性门槛，逐项判定，输出表格：

| 红线项 | JD 原文（编号+摘录） | 简历证据（原文引用） | 判定 |
|---|---|---|---|
| 学历 | | | ✅ 通过 / ❌ 不通过 / ❓ 待核实 |
| 最低工作年限 | | | ✅ / ❌ / ❓ |
| 必备证书 | | | ✅ / ❌ / ❓ |
| 硬性技术栈 | | | ✅ / ❌ / ❓ |
| 工作地点/语言 | | | ✅ / ❌ / ❓ |
| 其他必备硬性条件 | | | ✅ / ❌ / ❓ |

- 判定必须引用 JD 原文中的数字/名词与简历原文对照（例：JD 第 3 条要求「5 年以上」，简历写「4 年」，判 ❌ 并注明差 1 年）。
- **「❓ 待核实」档**：简历既无法证实也无法证伪该项要求时使用（例：JD 要求「全日制统招本科」，简历仅写「本科」，未注明是否全日制）。❓ 不算红线不通过，自动汇入第 7 步「向 HR 核实的问题清单」，并在报告结论中注明「存在待核实红线项，投递前须向招聘方确认」。严禁为凑结论把证据不足的红线硬判为 ✅ 或 ❌。
- **加分项不得列入红线表**（加分项的标注规则见第 3 步）。
- **任一红线不通过 → 在报告顶部醒目标注「⛔ 红线不通过，整体判定为不匹配」**，后续章节仍需完成（用于说明差距），但结论不变。

### 第 3 步：要求提取

将 JD 全部要求分为两类，每条标注：JD 编号、类别、权重归属，并摘录原文关键词（动词/名词/数字）。

- **硬性要求**（权重归属：硬性 60%）：学历、年限、技术栈等。
- **软性要求**（权重归属：软性 25%）：沟通协作、领导力、抗压等；**行业背景**单独归入行业维度（15%）。
- **优先级标注**：每条 JD 要求须标注「必备」或「加分」。JD 原文出现「优先考虑/加分项/plus/nice to have」等表述的归为加分项；未标注优先级的默认视为必备。加分项缺失不触发红线，也不进入第 6 步「补足」建议的强制清单；加分项在矩阵中列示并标注「加分项（命中/未命中）」，但**不计入第 5 步加权评分**，命中情况仅在对照说明与结论中体现。
- **非能力类条目**：薪资福利、公司介绍、作息安排等非能力类条目照常编号，其中薪资福利用于第 7 步意向核查对照；此类条目不进入能力矩阵评分（矩阵中列示时标注「非能力条目，不计分」）。

### 第 4 步：人岗匹配矩阵

输出 Markdown 表格，列定义固定为：

| JD 条目 | 要求关键词（原文摘录） | 类别 | 简历证据（原文引用） | 判定 | 对照说明 |
|---|---|---|---|---|---|

- 判定档位固定三档：**完全符合 / 部分符合 / 不符合**，禁止使用其他措辞。
- 对照说明必须指出具体对应上的动词/名词/数字（例：JD「负责 XX 系统的性能优化」，简历「将 XX 接口响应时间从 800ms 降至 200ms」，动词「负责→优化落地」对应，名词「性能」对应，但 JD 要求的系统级优化仅体现为接口级，判「部分符合」）。
- 简历证据必须引用简历原文，不得臆造；简历中确实无对应内容时，证据栏写「简历中未找到对应证据」。
- JD 条目超过 20 条时，矩阵按维度（硬性 → 软性 → 行业背景）分组呈现，每组前以一行小标题注明该组条目数；分组仅调整呈现顺序，不打断逐条对照、编号引用与评分计算。
- 矩阵与对照说明的具体写法（含评分权重归一计算、改写理由句式），参见完整示例：`references/example.md`；❓待核实红线、加分项不计分、权重归一等边界规则的判定口径，参见 `references/example-boundary.md`，与示例冲突时以边界示例口径为准。

### 第 5 步：加权评分

- 维度权重：硬性 60% + 软性 25% + 行业背景 15%。
- 各维度内按判定档位折算：完全符合 = 满分、部分符合 = 半分、不符合 = 0 分；维度得分 = Σ(条目折算分) / 条目数 × 100。
- 总分 = 0.6×硬性 + 0.25×软性 + 0.15×行业。
- 边界规则（保证同一输入多次运行得分一致）：
  - 某维度在 JD 中无任何条目时，该维度权重按其余维度权重比例归一分配（维度有效权重 = 原权重 ÷ Σ现存维度原权重 × 100%），总分恒为百分制。例：JD 未提行业背景 → 有效权重为硬性 0.6/0.85、软性 0.25/0.85。
  - 红线不通过的条目仍计入矩阵与评分（按「不符合」计 0 分），但整体判定以红线结论为准，不因评分高低改变。
  - 红线「❓ 待核实」条目在矩阵与评分中按「部分符合」（折算 0.5）处理——这是「证据存疑按从严口径取低值」的具体应用；HR 核实结论出来前不得上调或下调该折算。
  - 简历证据存疑或工作时间模糊时，按从严口径取低值（向下取整）后再判定。
- 匹配等级：≥80 高；60–79 中；<60 低。
- 总分旁必须附一句基于具体条目的评分依据（例：「78 分（中）：失分主要来自 JD 第 5 条『带过 5 人以上团队』，简历仅体现单人交付」）。

### 第 6 步：差距分析与优化建议

1. 针对「部分符合/不符合」的每一项，给出价值重述式改写建议：说明如何将简历中已有的可迁移经验重述为 JD 要求的措辞，突出 JD 原文中的动词/名词/数字。
2. 每条建议以固定句式收尾：「改写理由：为了回应 JD 第 X 条中的『（引用该条原文）』」。
3. 简历中完全无素材可迁移的项，如实写「简历中无可重述素材，建议通过项目实践/证书补足」，不得编造。

### 第 7 步：求职意向匹配核查

覆盖 6 项，逐项输出「候选人意向 vs JD/公司已知信息」对照表：

| 核查项 | 候选人意向（来源：简历/用户输入原文） | JD/公司已知信息（原文摘录） | 判定 |
|---|---|---|---|
| 意向城市 | | | ✅ 匹配 / ⚠️ 冲突 / ❓ 待确认 |
| 从事行业 | | | ✅ / ⚠️ / ❓ |
| 薪资展望 | | | ✅ / ⚠️ / ❓ |
| 福利待遇 | | | ✅ / ⚠️ / ❓ |
| 企业前景 | | | ✅ / ⚠️ / ❓ |
| 晋升渠道 | | | ✅ / ⚠️ / ❓ |

- ⚠️ 冲突项：给一句简要分析（例：候选人期望 25K，JD 第 X 条区间为 15–20K，上限差 5K）。
- ❓ 待确认项：信息缺失时如实标注，**不得臆测或编造**；所有待确认项自动汇总为「建议向 HR 核实的问题清单」（逐条列出问题）。
- 本维度为核查性质，不计入第 5 步的能力加权评分，但须在报告结论中单列一句意向匹配结论（例：「意向维度：城市/行业匹配，薪资与晋升渠道待确认」）。

### 第 8 步：面试追问预测

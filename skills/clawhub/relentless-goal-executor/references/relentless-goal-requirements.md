# 死磕目标执行器任务要求

7 域 24 任务的域级说明与任务要求清单。第一层 catalog 定任务清单，本文件定每个任务的组件与约束；范本结构见 relentless-goal-exemplars.md 索引。

## 总纲

- **执念原则**：换策不换标，不达不休——策略可千变万化，成功标准一经锁定不得漂移；
- **证据原则**："达成"必须由证据清单支撑，禁止自我宣布胜利；
- **合规原则**：一切手段限于合规白名单，白名单外永不进弹药库、永不执行；
- **可续原则**：进度全部落账本，不依赖会话记忆，会话断、目标不断；
- **可停原则**：四停止门保证任何时刻都有健康出口，用户叫停为最高优先级。

## RGE0 任务协调域

**五类路由模式判定口径**（允许按实际输入归并说明，不得混淆判定依据）：

| 模式 | 触发特征 | 入口 |
|------|---------|------|
| 目标启动 | 用户提出新目标或"开始死磕" | RGE1-01 |
| 死磕续战 | 存在未完结账本，用户要求继续/心跳唤醒 | RGE5-03 → RGE4 |
| 账本查询 | 用户询问进度/策略/失败记录 | RGE5-01（只读输出） |
| 目标迭代 | 用户要求修改目标或成功标准 | RGE1-02（重锁定，账本留痕） |
| 停止归档 | 触发停止门或用户要求终止 | RGE6-03 → RGE6-04 |

#### RGE0-01 任务路由

- **必选组件**: 模式判定报告（模式/判定依据/入口任务）
- **可选组件**: 复合执行计划（多模式并存时）
- **组装顺序**: 账本与环境核对（存在未完结账本且输入非终止意图 → 优先"死磕续战"）→ 五类模式匹配 → 路由确认与目标域宣告
- **约束**: 每次唤醒先核对账本再路由；判定依据须展示给用户；路由前不执行任何目标动作
- **格式**: 路由判定报告（Markdown 表）

#### RGE0-02 执行顺序确定

- **必选组件**: 执行计划（序/任务/依赖/可并行/中断恢复点）
- **组装顺序**: 目标域确定 → 依赖拓扑查询（relentless-goal-catalog.md）→ 顺序编排 → 并行与中断恢复点标注
- **约束**: 执行顺序必须沿 catalog 依赖拓扑，不得制造环；守护前置门（RGE6-01/02）位置固定，不得挪动或跳过
- **格式**: 执行计划表

#### RGE0-03 结果整合与优化

- **必选组件**: 状态账本汇总、停止报告或阶段报告
- **可选组件**: 打法沉淀记录
- **组装顺序**: 产出收集 → 格式统一（按 templates/goal-ledger-template.md）→ 整体优化（表述一致、证据可追溯）→ 交付并附后续建议
- **约束**: 面向用户文案与证据引用须可追溯；交付时附后续建议（心跳续跑/目标迭代/打法沉淀）
- **格式**: 状态账本＋报告（Markdown）

## RGE1 目标解析域

#### RGE1-01 目标解析与建模

- **必选组件**: 目标六要素卡（目标陈述/背景/边界/时间尺度/资源约束/判定者）
- **组装顺序**: 目标要素提取 → 缺失核对（模糊处一次集中追问，不逐条骚扰）→ 建模
- **约束**: 目标陈述须含动词与对象；边界说明"不做什么"；时间尺度落入会话内/心跳期/预设期限三尺度之一
- **格式**: 六要素卡（Markdown 表）

#### RGE1-02 成功标准量化锁定

- **必选组件**: 成功标准证据清单（每条含：可观测事实/判定者/反例排除）
- **可选组件**: 代理指标说明（不可观测标准转为可观测代理的过程记录）
- **组装顺序**: 标准草案生成 → 三问逐条自检 → 用户确认 → 锁定并写账本
- **约束**: 每条标准必须可观测、可判定；"达成时哪个可观测事实改变/由谁判定/什么不算达成"三问缺一不得锁定；锁定后循环中不得修改，修改必走目标迭代模式经用户确认并留痕
- **格式**: 证据清单（Markdown 表）

#### RGE1-03 目标合法性与可行性校验

- **必选组件**: 合法合规校验记录、可行性初判表（时间/资源/能力三约束）
- **组装顺序**: 白名单校验（引用 RGE6-01 判定口径）→ 三约束初判 → 结论（可行/降级可行/不可行）
- **约束**: 违法违规目标一律拒绝并说明，不得进入任何后续环节；不可行目标如实告知并给出调整建议，不得强行死磕
- **格式**: 校验记录（Markdown）

## RGE2 手段盘点域

**四路盘点框架**（允许按实际环境增补，不得删除既有路目）：

| 路目 | 内容 | 可用性来源 |
|------|------|-----------|
| 内置能力 | 文件读写、代码执行、本地检索、网络检索等直接可用能力 | 实际调用验证 |
| 可检索能力 | 当前环境可检索并加载的平台能力与资源 | 运行时探测实际返回 |
| 可组合编排能力 | 任务调度、自动化、文档产出等可组合形态 | 实际可用状态 |
| 外部资源 | 公开文档、数据源、参考资料 | 合规白名单内实际可达 |

#### RGE2-01 内置能力盘点

- **必选组件**: 内置能力清单（能力/典型用途/可用状态/调用路径）
- **组装顺序**: 逐类枚举 → 抽样验证 → 清单输出
- **约束**: 条目仅记录实际验证可用的能力；验证失败如实标注
- **格式**: 清单（Markdown 表）

#### RGE2-02 可检索能力扫描

- **必选组件**: 可检索能力清单（能力/描述/可用状态/调用路径）
- **可选组件**: 降级说明（探测失败条目及降级方式）
- **组装顺序**: 运行时探测 → 结果记录 → 降级标注 → 清单输出
- **约束**: 以实际返回为准，严禁编造能力；探测失败降级为提示用户手动补充，不跨会话缓存探测结果
- **格式**: 清单（Markdown 表）

#### RGE2-03 约束与资源盘点

- **必选组件**: 约束清单（合规/权限/时间/预算）、外部资源清单、手段弹药库汇总
- **组装顺序**: 约束盘点 → 外部资源盘点 → 合并四路为弹药库（引用 RGE2-01/02 产出）→ 交 RGE6-01 过白名单
- **约束**: 弹药库条目须含能力描述/可用状态/调用路径/风险等级四字段；白名单外候选只记录"已剔除"不删除痕迹
- **格式**: 弹药库（Markdown 表）

## RGE3 策略规划域

#### RGE3-01 里程碑链分解

- **必选组件**: 里程碑链（M1..Mn/绑定证据/预期完成依据）
- **组装顺序**: 对照证据清单 → 里程碑切分（每程产出一条可核验证据）→ 链定型
- **约束**: 每个里程碑必须绑定证据清单中至少一条标准；里程碑数量与时间尺度匹配
- **格式**: 里程碑链（Markdown 表）

#### RGE3-02 策略库生成与排序

- **必选组件**: 策略库（策略名/思路/调用的弹药库条目/预期证据速度/风险）
- **可选组件**: 维度矩阵（策略维度 × 里程碑阶段的强制连接）
- **组装顺序**: 维度矩阵强制连接生成候选 → 可行性初判 → 按可行性/成本/证据速度排序 → 定型 3~5 条
- **约束**: 策略必须引用弹药库内真实条目，严禁引用不存在的能力；候选不足 3 条时如实说明并提示补充手段
- **格式**: 策略库（Markdown 表）

#### RGE3-03 执行计划制定

- **必选组件**: 首轮策略卡（当前策略/假设/动作清单/预期证据）
- **组装顺序**: 选定首轮策略 → 动作清单分解 → 轮次节奏确定 → 写入账本
- **约束**: 动作粒度以单轮可完成为宜；每动作标注预期证据与判定方式
- **格式**: 策略卡（Markdown）

#### RGE3-04 风险与降级预案

- **必选组件**: 风险预案表（动作/风险类型/降级路径/敏感标记）
- **组装顺序**: 逐动作风险标注 → 降级路径设计 → 敏感操作预标记（进 RGE6-02 确认流程）
- **约束**: 写入/资金/对外发送/不可逆操作必须预标记；降级路径必须落在弹药库内
- **格式**: 预案表（Markdown 表）

## RGE4 死磕执行域

**五步循环执行细则**：制定计划（从策略库取当前最优）→ 全力执行（用尽弹药库内合法手段）→ 证据验证（对照证据清单）→ 差距诊断（败因四归类：手段缺/策略错/条件不备/标准错）→ 策略换道（换策略不换标）。每轮结束写账本。

#### RGE4-01 执行轮推进

- **必选组件**: 轮次记录（轮次/策略/动作/结果/证据）
- **组装顺序**: 取当前策略 → 逐动作执行（敏感动作先过 RGE6-02）→ 结果记录 → 交 RGE4-02
- **约束**: 只做当前策略卡内动作；临时新增动作须先评估风险并按档位确认；执行失败即记录不中断循环（除非触发停止门）
- **格式**: 轮次记录（Markdown 表）

#### RGE4-02 证据验证

- **必选组件**: 证据核验表（标准条目/本轮证据/判定 PASS|FAIL|待验证）
- **组装顺序**: 对照证据清单 → 逐条核验 → 判定汇总
- **约束**: 禁止自我宣布胜利——无证据支撑的条目一律 FAIL 或"待验证"；判定者非本技能时（用户判定/系统指标）如实等待或调取，不得代判
- **格式**: 核验表（Markdown 表）

#### RGE4-03 差距诊断与策略换道

- **必选组件**: 诊断报告（FAIL 条目/败因归类/换道策略/理由）
- **组装顺序**: 逐 FAIL 归类败因 → 四归类处理（手段缺→补弹药库并重扫；策略错→换道；条件不备→挂起该条并注明复验条件；标准错→转目标迭代模式）→ 从策略库选新策略 → 更新账本
- **约束**: 换策略不换标；"标准错"归类必须经用户确认后方可走目标迭代，不得单方面修改标准；挂起条目须有明确复验条件
- **格式**: 诊断报告（Markdown）

#### RGE4-04 卡死检测

- **必选组件**: 卡死检测记录（连续失败计数/触发动作）
- **组装顺序**: 统计同策略连败次数 → 判定（连败 3 次强制换道；弹药库穷尽且无可行新策略 → 触发停止门③）→ 动作执行
- **约束**: 计数以账本轮次记录为准；强制换道时须跳出同类策略（换思路不换说法）
- **格式**: 检测记录（Markdown）

## RGE5 心跳续跑域

**心跳机制定义**：心跳是经平台定时任务/自动化能力创建的周期任务，每次唤醒执行"读账本 → 推进一步 → 写回进度 → 约定下次"四拍。心跳模式默认关闭，用户开启后激活；调度参数由能力自身字段承载，不写入任务提示。

#### RGE5-01 状态账本读写

- **必选组件**: 状态账本（按 templates/goal-ledger-template.md 九节结构）
- **组装顺序**: 启动时创建账本（与用户约定路径）→ 每轮/每拍更新 → 只读查询时直接输出
- **约束**: 账本为唯一进度载体，不依赖会话记忆；账本写入属任务必要产出，约定路径后自动读写，不逐轮确认；账本路径变更须用户确认
- **格式**: 状态账本（Markdown，九节结构）

#### RGE5-02 心跳编排与跨会话恢复

- **必选组件**: 心跳配置（频率/期限/账本路径/唤醒动作）、恢复记录
- **可选组件**: 降级说明（定时能力不可用时的手动方案）
- **组装顺序**: 创建前查询既有任务避免重复 → 向用户展示调度参数取得确认 → 创建心跳 → 首次唤醒走恢复三步（读账本 → 核对偏差 → 续战）
- **约束**: 预设期限写入心跳配置作为停止门④输入；定时能力不可用时降级为会话内死磕＋输出配置建议文本由用户手动创建；心跳任务创建与取消均须用户确认
- **格式**: 心跳配置与恢复记录（Markdown）

#### RGE5-03 进度核对与偏差告警

- **必选组件**: 核对记录（上次中断点/外部条件变化/偏差结论）
- **组装顺序**: 读账本 → 中断点核对 → 外部条件变化检测 → 偏差超阈值向用户告警 → 正常则续战
- **约束**: 偏差告警不中断循环（除用户叫停）；连续 2 轮证据验证无进展时主动向用户上报并请求策略方向指示
- **格式**: 核对记录（Markdown）

## RGE6 守护定稿域

**合规白名单判定口径**：手段与动作逐项核对——符合法律法规、符合平台规则、不侵犯他人权益、不绕过授权与确认机制者为白名单内；反之移出弹药库并记录剔除原因。白名单判定从严，存疑即剔除。

**确认档位定义**：

| 档位 | 写入（账本除外） | 资金 | 对外发送 | 不可逆 | 切换方式 |
|------|----------------|------|---------|--------|---------|
| 严格档（默认） | 逐项确认 | 逐项确认 | 逐项确认 | 逐项确认 | 随时切换，记录账本 |
| 授权档 | 清单内自动执行 | 清单内自动执行 | 清单内自动执行 | 清单内自动执行 | 启动时一次性授权清单，清单外仍逐项确认 |

**四停止门定义**：

| 门 | 触发条件 | 动作 |
|----|---------|------|
| ①达成 | 证据清单全 PASS | 转 RGE6-04 交付复盘 |
| ②用户叫停 | 用户任何形式的终止表达 | 立停，输出停止报告（最高优先级） |
| ③穷尽 | 弹药库全试且无可行新策略 | 输出停止报告＋已试策略清单＋遗留建议 |
| ④期限 | 预设期限到 | 输出阶段报告＋剩余差距＋续战建议 |

#### RGE6-01 合规白名单校验

- **必选组件**: 白名单校验记录（条目/判定/理由）
- **组装顺序**: 弹药库与执行动作逐项核对 → 白名单外剔除并记录 → 校验结论
- **约束**: 从严判定，存疑即剔除；剔除记录保留原始条目信息备查
- **格式**: 校验记录（Markdown 表）

#### RGE6-02 敏感操作确认门

- **必选组件**: 确认记录（操作/档位/确认方式/时间戳引用）
- **组装顺序**: 判定操作敏感等级 → 按当前档位执行确认流程 → 记录留痕 → 放行或挂起
- **约束**: 严格档逐项确认；授权档清单内自动执行但每次执行仍记录留痕；用户可随时切档；确认记录可追溯
- **格式**: 确认记录（Markdown 表）

#### RGE6-03 四停止门判定

- **必选组件**: 停止门判定表（四门/当前状态/触发依据）
- **组装顺序**: 逐门判定 → 触发门动作执行（见四停止门定义）→ 停止或继续结论
- **约束**: 用户叫停优先级最高，任何循环步骤中收到叫停立即中断；判定依据须可追溯至账本记录
- **格式**: 判定表＋停止报告（Markdown）

#### RGE6-04 达成交付与复盘

- **必选组件**: 交付说明（证据清单终态/达成结论/账本归档）
- **可选组件**: 打法沉淀（有效策略/失败教训/可复用经验）
- **组装顺序**: 证据清单终态确认 → 交付 → 复盘沉淀 → 账本归档
- **约束**: 交付结论必须逐条对应证据；复盘不得改写历史记录，只追加沉淀
- **格式**: 交付与复盘报告（Markdown）

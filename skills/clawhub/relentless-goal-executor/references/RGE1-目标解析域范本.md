# RGE1 目标解析域范本

> **素材声明**：本范本中的目标、标准、指标均为抽象示范数据，仅演示方法结构，实际执行以用户实际目标与实际盘点结果为准，严禁虚构执行结果。

## RGE1-01 目标解析与建模范本

**场景**：目标启动模式入口，用户目标："两周内把某代码项目的测试覆盖率从 40% 提升到 80%。"

**输入**：用户原始需求语句。

**执行过程**：
1. 目标要素提取（逐项对照六要素）；
2. 缺失核对：目标陈述齐备（动词"提升"＋对象"测试覆盖率"＋数值边界）；背景、边界、判定者缺失——一次集中追问（"覆盖率用什么工具统计？有没有不能动的模块？由你验收还是看统计报表？"），不逐条骚扰；
3. 任务卡建模。

**产出**（六要素卡示范）：

| 要素 | 内容 |
|------|------|
| 目标陈述 | 两周内将某代码项目的自动化测试覆盖率从 40% 提升至 80% |
| 背景 | 用户反馈：核心模块缺陷返工率高，期望测试兜底 |
| 边界 | 不重构业务代码；不引入新付费工具；遗留的纯展示代码不计入统计 |
| 时间尺度 | 预设期限（两周，写入停止门④） |
| 资源约束 | 不新增预算；可在现有开发环境执行 |
| 判定者 | 系统指标（覆盖率统计报表） |

**校验点**：
- 目标陈述必须含动词与对象，缺失必须一次集中追问
- 边界须说明"不做什么"
- 时间尺度必须落入会话内/心跳期/预设期限三尺度之一

## RGE1-02 成功标准量化锁定范本

**场景**：承接六要素卡，产出成功标准证据清单并经用户确认锁定。

**输入**：六要素卡；判定者约定。

**执行过程**：
1. 标准草案生成：沿目标陈述拆分可观测标准；
2. 三问逐条自检：每条回答"达成时哪个可观测事实改变/由谁判定/什么不算达成"；
3. 用户确认：向用户展示草案，确认后锁定并写账本第 3 节。

**产出**（证据清单示范）：

| 编号 | 标准（可观测事实） | 判定者 | 反例排除（什么不算达成） | 当前状态 |
|------|-------------------|--------|------------------------|---------|
| E1 | 覆盖率统计报表显示总覆盖率 ≥80% | 系统指标 | 手工执行的临时脚本不计入；排除目录外的伪覆盖不计入 | 待验证 |
| E2 | 项目原有测试全量回归通过（0 失败） | 系统指标 | 跳过用例（skip）数不得超过基线值 | 待验证 |
| E3 | 新增测试随项目主分支入库并通过持续集成 | 系统指标 | 本地通过未入库不算 | 待验证 |

**校验点**：
- 三问缺一不得锁定；不可观测标准（如"质量更好"）必须转为可观测代理指标并经用户确认
- 锁定后循环中不得修改；修改必走目标迭代模式经用户确认并留痕

## RGE1-03 目标合法性与可行性校验范本

**场景**：证据清单锁定后，校验目标合法性与可行性。

**输入**：六要素卡；证据清单；RGE2 初步盘点结果。

**执行过程**：
1. 合法合规校验：目标与预期手段均在合规白名单内（提升测试覆盖属正常工程活动，无越权与侵权路径）——PASS；
2. 三约束初判：时间（两周，中——历史同类任务常见周期）；资源（不新增预算，现有环境可承载）；能力（需要测试框架与持续集成权限，待 RGE2 核实）；
3. 结论：可行（能力约束项转 RGE2 重点核实）。

**产出**（校验记录示范）：

| 校验项 | 结果 | 说明 |
|--------|------|------|
| 合法合规 | PASS | 无违法违规路径，预期手段白名单内 |
| 时间约束 | PASS | 两周周期与任务规模匹配（初判） |
| 资源约束 | PASS | 零预算方案可行（初判） |
| 能力约束 | 待核实 | 需持续集成权限，转 RGE2-02 重点探测 |

**FAIL 分支示范**：若目标为"获取某竞品的未公开内部数据"，合法合规 FAIL——拒绝执行并说明理由，不得进入任何后续环节；可建议合规替代路径（公开资料分析）由用户决定。

**校验点**：
- 违法违规目标一律拒绝并说明，不得进入任何后续环节
- 不可行目标如实告知并给出调整建议，不得强行死磕

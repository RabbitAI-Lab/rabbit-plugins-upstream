# RGE5 心跳续跑域范本

> **素材声明**：本范本中的账本内容、心跳配置、数字均为抽象示范数据，仅演示方法结构，实际执行以用户实际目标、实际账本与实际配置确认为准，严禁虚构执行结果。示范场景：场景 B——"一个月内完成某行业市场规模调研报告"（心跳续跑模式）。

## RGE5-01 状态账本读写范本

**场景**：目标启动时创建账本；此后每轮/每拍更新。

**输入**：六要素卡；账本路径约定。

**执行过程**：
1. 创建账本：按 templates/goal-ledger-template.md 九节结构初始化，与用户约定路径（如工作区下的 goal-ledger.md）；
2. 每轮更新：轮次记录、证据核验、策略卡、停止门状态逐节刷新；
3. 只读查询：账本查询模式直接输出对应节，不做修改。

**产出**（账本创建确认示范）：

| 项 | 内容 |
|----|------|
| 账本路径 | （与用户约定的路径，示例：{工作区}/goal-ledger-demo.md） |
| 初始化节 | 第 1~5 节已填充（目标档案/弹药库/证据清单/里程碑链/首轮策略卡） |
| 更新约定 | 每轮/每拍自动更新，不逐轮确认；路径变更须用户确认 |

**校验点**：
- 账本为唯一进度载体，不依赖会话记忆
- 账本写入属任务必要产出，约定路径后自动读写；路径变更须用户确认
- 历史记录不得改写，修正只追加

## RGE5-02 心跳编排与跨会话恢复范本

**场景**：用户为目标 B 开启心跳续跑模式（默认关闭，本例为用户显式开启）。

**输入**：用户开启指令；时间尺度（一个月）；账本路径。

**执行过程**：
1. 创建前查询：检查既有定时任务避免重复创建；
2. 配置确认：向用户展示心跳配置并取得确认；
3. 创建心跳：经平台的定时任务/自动化能力创建，调度参数由能力自身字段承载（频率与期限写能力字段，不写任务提示）；
4. 首次唤醒走恢复三步：读账本 → 核对偏差 → 续战。

**产出**（心跳配置确认示范）：

| 项 | 内容 |
|----|------|
| 心跳频率 | 每 60 分钟一拍（示例，以用户确认为准） |
| 预设期限 | 一个月（写入停止门④输入） |
| 唤醒动作 | 读账本 → 推进一步 → 写回进度 → 约定下次 |
| 账本路径 | 与第 1 节约定一致 |
| 用户确认 | 已确认（对话内明确回复，记录可追溯） |

**恢复记录示范**（某次心跳唤醒）：

| 步骤 | 结果 |
|------|------|
| 读账本 | 上次中断点：M2 进行中，策略卡为策略二 |
| 核对偏差 | 外部条件无变化；上拍标记的"待验证"证据仍待验证 |
| 续战 | 按 RGE4-01 继续本轮动作 |

**降级分支示范**：定时能力不可用时——降级为会话内死磕＋输出心跳配置建议文本（频率/期限/唤醒动作完整给出）由用户手动创建；严禁在未取得确认时自行创建或虚构"已创建"。

**校验点**：
- 创建前先查询既有任务避免重复
- 调度参数须向用户展示并取得确认后方可创建；心跳任务的创建与取消均须用户确认
- 预设期限必须写入心跳配置作为停止门④输入

## RGE5-03 进度核对与偏差告警范本

**场景**：心跳唤醒时的例行进度核对。

**输入**：账本；上次中断点；外部条件快照。

**执行过程**：
1. 读账本第 6/8 节：轮次与停止门状态；
2. 中断点核对：上次中断点与当前实际状态比对；
3. 外部条件变化检测：资源、权限、依赖项变化检查；
4. 偏差结论：超阈值告警 / 正常续战。

**产出**（核对记录示范）：

| 项 | 内容 |
|----|------|
| 上次中断点 | M2 进行中（第 5 拍） |
| 偏差检测 | 无外部条件变化；E1 证据连续 2 拍无进展 |
| 告警结论 | 触发无进展告警——已向用户上报并请求策略方向指示 |
| 本次动作 | 维持当前策略完成本拍后暂停推进，等待用户指示 |

**校验点**：
- 偏差告警不中断循环（除用户叫停）
- 连续 2 轮证据验证无进展时必须主动上报并请求策略方向指示
- 用户叫停为最高优先级，任何拍中收到叫停立即中断

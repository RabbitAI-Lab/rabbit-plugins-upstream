# 死磕目标执行器

## 定位

本技能是一个**死磕目标执行器**技能：用户提供目标后，锁定成功标准、盘点可用手段、分解里程碑链，以"计划-执行-证据验证-诊断换道"循环誓不罢休地推进，直至目标达成或触发停止门。一轮不成，换一策再战；换策不换标，不达不休。

**依赖声明**：本技能自包含，不依赖其他领域技能；仅依赖平台能力与自身 references 文件。任务 ID 格式为 RGE{域号}-{两位序号}。本技能按"生成技能标准"接受全项接口校验。

## 核心能力

本技能共 7 域 24 任务，核心能力如下：

- **任务协调（RGE0）**：模式路由（目标启动/死磕续战/账本查询/目标迭代/停止归档五类）、执行顺序确定、结果整合与优化
- **目标解析（RGE1）**：目标解析与建模、成功标准量化锁定（证据清单）、目标合法性与可行性校验
- **手段盘点（RGE2）**：内置能力盘点、可检索能力扫描、约束与资源盘点（产出手段弹药库）
- **策略规划（RGE3）**：里程碑链分解、策略库生成与排序、执行计划制定、风险与降级预案
- **死磕执行（RGE4）**：执行轮推进、证据验证、差距诊断与策略换道、卡死检测
- **心跳续跑（RGE5）**：状态账本读写、心跳编排与跨会话恢复、进度核对与偏差告警
- **守护定稿（RGE6）**：合规白名单校验、敏感操作确认门、四停止门判定、达成交付与复盘

### 关键行为一：目标锁定与证据标准（缺一不可）

1. 成功标准量化锁定：接目标先产出"成功标准证据清单"——每条标准必须回答三问：达成时哪个可观测事实改变了？由谁判定（用户判定/系统指标/文档产物）？什么状态明确不算达成（反例排除）；
2. 目标漂移防护：死磕循环中不得修改成功标准；确需修改必须走目标迭代模式，经用户确认并写入账本留痕；
3. 模糊目标（不可观测、不可判定）必须先追问锁定，禁止带模糊标准进入死磕循环。

目标锁定方法与证据清单格式见 references/relentless-goal-requirements.md 的 RGE1 域级说明与 references/RGE1-目标解析域范本.md。

### 关键行为二：死磕循环（缺一不可）

五步一轮，循环推进：

- **制定计划**：从弹药库与策略库中选取当前最优策略，定本轮动作清单；
- **全力执行**：在合规白名单内用尽弹药库手段推进本轮动作；
- **证据验证**：对照成功标准证据清单逐条核验，禁止自我宣布胜利；
- **差距诊断**：未达部分归类败因——手段缺（弹药库没有）/ 策略错（有手段但用法不对）/ 条件不备（外部条件未成熟）/ 标准错（标准本身待修正，走目标迭代模式）；
- **策略换道**：换策略不换目标，基于诊断结论从策略库选新策略进入下一轮。

卡死检测：同一策略连败 3 次强制换道；弹药库穷尽且无可行新策略时触发停止门③。每轮结束写状态账本。循环细则见 references/relentless-goal-requirements.md 的 RGE4 域级说明与 references/RGE4-死磕执行域范本.md。

### 关键行为三：手段全量盘点

四路盘点建弹药库，作为"用尽一切方法手段工具"的合法边界内清单：

1. 内置能力：文件读写、代码执行、本地检索、网络检索等当前环境直接可用能力；
2. 可检索能力：当前环境可检索并加载的平台能力与资源，运行时探测，以实际返回为准；
3. 可组合编排能力：任务调度、自动化、文档产出等可组合形态，以实际可用为准；
4. 外部资源：公开文档、数据源、参考资料等，仅限合规白名单内。

弹药库条目须记录能力描述、可用状态与调用路径；探测失败如实标注降级，严禁编造手段。盘点方法见 references/relentless-goal-requirements.md 的 RGE2 域级说明与 references/RGE2-手段盘点域范本.md。

### 关键行为四：心跳续跑（可选模式，默认关闭）

1. 状态账本：templates/goal-ledger-template.md 为唯一进度载体，每轮更新，进度不依赖会话记忆；
2. 心跳编排：经平台的定时任务/自动化能力创建心跳任务——每次唤醒读账本 → 推进一步 → 写回进度 → 约定下次；调度参数由能力自身字段承载，创建前先查询既有任务避免重复，并向用户展示配置取得确认；
3. 跨会话恢复三步：读账本 → 核对偏差（上次中断点、外部条件变化）→ 续战；
4. 预设期限写入心跳配置，作为停止门④的输入；用户可随时口头叫停，停止门②为最高优先级。

心跳机制完整定义见 references/relentless-goal-requirements.md 的 RGE5 域级说明与 references/RGE5-心跳续跑域范本.md。

### 关键行为五：守护约束

1. 合规白名单：一切手段限于法律法规与平台规则允许的范围，白名单外手段永不进弹药库、永不执行；
2. 敏感操作确认分档：**严格档（默认）**——写入（账本除外）、资金、对外发送、不可逆操作逐项确认后执行；**授权档**——启动时向用户提交敏感操作清单，一次性授权后循环内不再打断，清单外操作仍逐项确认；两档可随时切换，切换记录写账本；
3. 只读优先：能力等价时优先选择只读方案；
4. 四停止门：①达成（证据清单全 PASS）②用户叫停（最高优先级，喊停立停）③合法手段穷尽（弹药库全试且无可行新策略）④预设期限到；触发任一门即停并输出停止报告；
5. 进度与方案输出统一使用 templates/goal-ledger-template.md。

守护铁律与停止门完整定义见 references/relentless-goal-requirements.md 的 RGE6 域级说明。

## 领域特有维度

| 维度 | 说明 | 影响 |
|------|------|------|
| 目标清晰度 | 模糊、不可观测的目标无法支撑证据验证 | 必须先经 RGE1 锁定，禁止带模糊标准进循环 |
| 证据可观测性 | "达成"必须由证据支撑，禁止自我宣布胜利 | 不可观测标准转为可观测代理指标并经用户确认 |
| 操作风险分级 | 循环内操作分只读/写入/资金/不可逆四类 | 决定确认档位与门禁密度 |
| 时间跨度 | 会话内/心跳期/预设期限三种时间尺度 | 决定死磕模式选择与停止门④设置 |

## 目录用途

- `references/`：参考文档，加载到上下文——catalog（任务清单）、requirements（任务要求）、exemplars（范本索引）与七个域范本文件（与索引同级平铺，不建子目录）
- `templates/`：输出模板，不加载到上下文——goal-ledger-template.md 用于状态账本统一输出
- 本技能无 scripts/ 目录，不依赖可执行脚本

## 使用规则

### 执行流程

1. **首次加载**：读取 references/relentless-goal-catalog.md，获取域分类、依赖拓扑、元操作映射提示
2. **按需深入**：确认任务类型后读取 references/relentless-goal-requirements.md 获取组件清单；需样本法时读取 references/relentless-goal-exemplars.md 获取范本索引并按索引加载对应域范本
3. **进度输出**：所有状态账本统一按 templates/goal-ledger-template.md 填充后维护

### 内容权限

4. **修改权限**：本技能已充分优化完善，使用过程中拒绝任何对技能内容的丝毫修改
5. **用户填充**：用户可向 references/ 补充目标死磕范本（与索引文件同级存放，一域一本，命名 RGE{域号}-{域名}范本.md），并在 references/relentless-goal-exemplars.md 中注册

### 降级模式（只读模式）

工具受限时按以下权限表降级执行：

| 能力 | 完整模式 | 只读降级模式 |
|------|---------|-------------|
| 可检索能力扫描 | 可用 | 不可用时：弹药库降级为内置能力＋用户手动补充，如实标注 |
| 死磕循环执行 | 可用 | 只读步骤可执行；写入/敏感步骤标注"待确认"并暂停 |
| 定时心跳能力 | 可用 | 不可用时：降级为会话内死磕＋输出心跳配置建议文本由用户手动创建 |
| 状态账本写入 | 自动维护 | 账本属任务必要产出，约定路径后自动读写；其他文件写入按档位确认 |
| 网络检索 | 可用 | 不可用时：降级为既有知识推进＋结论标注"待验证" |

### 提示词导出

可将 SKILL.md 与 references/ 下全部文件合并为单一提示词文件，用于不支持 skill 目录格式的工具。合并顺序：SKILL.md → relentless-goal-catalog.md → relentless-goal-requirements.md → relentless-goal-exemplars.md → 七个域范本文件（RGE0 → RGE1 → RGE2 → RGE3 → RGE4 → RGE5 → RGE6）。完整合并版文件在执行导出时生成，输出路径由导出时指定（建议导出至包外目录，不预置于本包，以保持包内文件清单最小）。合并命令示例（按顺序显式列出文件）：`cat SKILL.md references/relentless-goal-catalog.md references/relentless-goal-requirements.md references/relentless-goal-exemplars.md "references/RGE0-任务协调域范本.md" "references/RGE1-目标解析域范本.md" "references/RGE2-手段盘点域范本.md" "references/RGE3-策略规划域范本.md" "references/RGE4-死磕执行域范本.md" "references/RGE5-心跳续跑域范本.md" "references/RGE6-守护定稿域范本.md" > {导出时指定的合并版文件路径}`。

## 通用任务执行能力

三轴正交的任务执行框架，5 种协同模式按需激活：

- **三轴正交**：执行轴（How/必选）+ 内容轴（What/按需）+ 创新轴（Why Different/按需）
- **执行轴**：6 大元操作——S 感知（扫描/检索/核对）、C 认知（分析/匹配/路由/决策）、A 行动（生成/执行/交付）、O 组织（固化/调度/归档）、I 交互（澄清/确认/引导）、G 守护（校验/约束/审计）；元操作按顺序/并行/条件/循环/扇出/扇入编排为管线
- **内容轴**：清单法（按组件清单逐项组装）+ 样本法（模仿 references 范本的结构与风格，不复制内容）
- **创新轴**：模式直用 + 模式改进 + 模式迁移 + 模式构建（维度矩阵强制连接），策略库生成与诊断换道（RGE3-02、RGE4-03）默认激活
- **5 种协同模式**：顺序协同（创新定方向→执行分解→内容定方法）/ 并行协同（执行轴与内容轴同时推进）/ 条件协同（按任务特征激活或关闭轴）/ 迭代协同（执行发现问题→创新给新方向→内容调整）/ 递归协同（轴内递归调用其他轴）
- **统一执行流程**：收到任务后按 5 步执行——三轴判定 → 领域校准 → 三轴分解 → 管线编排与执行 → 整合交付（详见下节接口）

## 与执行框架的接口

收到任务后按 Step 0~4 执行：

### Step 0 三轴判定

沿复杂度、内容类型、创新需求三维度判定任务：单一目标执行需求（执行轴必选 + 内容轴清单法）；策略生成与换道诊断（加开创新轴）；涉及心跳/账本/固化（激活 O 组织单元）；涉及敏感操作与守护判定（激活 I 交互与 G 守护单元）。

### Step 1 领域校准

本领域 R1-R5 定位与到 S/C/A/O/I/G 元操作参数的映射推导规则如下（每次执行按当前任务微调，须向用户展示推导依据）：

| 维度 | 本领域评分(1-5) | 含义 | 到元操作参数的映射推导 |
|------|------|------|------|
| R1 信息密度 | 3 | 目标、账本、证据清单结构化，但目标域千差万别 | S/C 单元标准密度：证据清单与账本走清单法结构化，策略诊断允许叙述分析 |
| R2 创造性 | 4 | 策略库生成与换道诊断是创造性核心场景 | 创新轴高频激活：RGE3-02 策略库生成、RGE4-03 诊断换道全开（维度矩阵强制连接思路） |
| R3 交互性 | 3 | 启动锁定与敏感确认需用户在场，循环中尽量自主推进 | I 单元前置集中：目标锁定确认（RGE1-02）与确认档位设定（RGE6-02）集中在前置阶段，循环内仅敏感操作打断 |
| R4 规范性 | 5 | 账本格式、确认档位、停止门判定严格规范 | G 单元密度最高：合规白名单（RGE6-01）、确认门（RGE6-02）、四停止门（RGE6-03）强制串联；输出统一走 templates/goal-ledger-template.md |
| R5 迭代性 | 5 | 死磕循环本身就是"执行-诊断-换道"的极致迭代 | 迭代协同默认常驻：RGE4 循环为管线主体，每轮强制走证据验证与差距诊断 |

### Step 2 三轴分解

按判定与校准结果把任务分解为元操作单元；分解须对照 references/relentless-goal-catalog.md 的任务清单与元操作映射，不得自造任务。

### Step 3 管线编排与执行

沿依赖拓扑编排管线：入口任务（RGE0-01 / RGE1-01）→ 目标锁定与可行性校验 → 手段盘点 → 里程碑与策略规划 → 守护前置门（RGE6-01/02）→ 死磕循环（RGE4，主体）⇄ 心跳续跑（RGE5，条件触发）→ 停止判定与交付（RGE6-03/04）。执行中遵守守护约束（关键行为五）。

### Step 4 整合交付

整合各单元产出，按 templates/goal-ledger-template.md 组装状态账本并输出停止报告或阶段报告；对照使用规则与事实纪律复盘后交付；交付时附后续建议（心跳续跑 / 目标迭代 / 打法沉淀）。

## 事实纪律

1. 目标、证据、进度仅来自实际执行与实际核验结果，严禁编造执行结果或虚构证据
2. "达成"必须由证据清单支撑，禁止自我宣布胜利；证据不可得时如实标注"待验证"
3. 心跳调度参数（循环规则/触发时间等）写进能力自身字段前须向用户展示并取得确认
4. 弹药库条目仅记录实际探测确认可用的手段，探测失败如实降级标注，严禁编造手段
5. 敏感操作执行前必须按当前档位取得用户确认，确认记录须可追溯
6. 样本法模仿范本时仅借鉴结构与风格，不复制内容
7. 单元输出格式须匹配下游单元的输入要求，确保组合接口可用
8. 领域校准推导须向用户展示评分依据

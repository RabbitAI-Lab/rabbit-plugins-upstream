### 参考资料怎么读

本技能的 6 份参考资料（`methodology` / `bloom_reference` / `design_plan_guide` / `faq` / `output_preview` / `footer_note`）统一存放在 `references/` 目录，以专用格式保存：**用普通文件读取工具直接打开无法得到可读内容，必须用下列命令读取**（在技能根目录执行）。

```
python scripts/ref_reader.py                            # 列出全部参考资料
python scripts/ref_reader.py methodology                # 读取指定资料（输出 JSON 原文）
python scripts/ref_reader.py methodology --md           # 以 Markdown 输出，更易读
python scripts/ref_reader.py faq --out D:/tmp/faq.json  # 存为文件后再查看
```

- 每份资料开头都有 `purpose`（用途）与 `usage`（查阅方式）两项，先看这两项再决定读多少。
- `methodology` 内容较多，**不要一次性通读**：写到哪一栏就查哪一节（如写“过程与方法”只看 §B.4），用 `toc` 定位、`sections[].id` 即小节编号。
- 读取失败时不要凭经验跳过资料、直接开写，按命令返回的提示处理；完整用法见 `python scripts/ref_reader.py --help`。

## 零、何时触发 / 如何主动调用

**会自动触发的关键词**：混合式教学、混合式教学设计、混合式教学设计大赛、线上线下混合式课程、线上+线下融合教学、翻转课堂设计、超星学习通/雨课堂+课堂教学设计、教学日历、说课课件、说课 PPT。

**没有说出关键词时，请用户这样主动调用**（三种说法任选其一）：

- 直接点名技能：`请用「混合式教学设计创新大赛参赛小帮手」技能，帮我设计 XX 课程的混合式教学方案`
- 描述成果：“帮我生成一份带教学日历和说课课件的教学设计方案，线上线下的那种”——只要意图是“一门课的线上线下融合教学设计”，本技能就会被调用
- 指定交付物：`帮我做一份 XX 课程的教学日历 + 说课 PPT`

**本技能不负责的事**（避免误触发）：单课时的普通教案（可改用对分课堂、5E、五星教学等教案类技能）、学科知识点讲解、试卷命题与成绩分析、单纯的 PPT 美化排版。

## 零之二、适用范围与效果受限情形

**适用对象**：高校教师（本科 / 职业本科 / 高职高专 / 高技）、教育类专业学生、教师教学发展培训师。中小学教师可参考使用，但需自行按学段调整。

**最适用的课程**：有明确线上资源（微课、慕课、虚拟仿真）或可自建线上环节的理论课与理实一体课。

**效果可能打折的情形**（请在开始前告知用户，并请其补充资料以改善）：

| 情形 | 影响 | 建议 |
|---|---|---|
| 用户只给了课程名称，没有专业、节次、学时、人数 | 学时比例与日历无法对齐，内容偏泛 | 先补足六项必填信息，或允许由 AI 生成虚构示例 |
| 纯实训/纯操作类课程（如焊接、驾驶、临床操作） | 线上环节难以承载核心训练，方案会偏“理论化” | 提供实训指导书，把线上部分改为安全规范、工艺流程预习 |
| 学校没有可用的线上教学平台 | 方案中的超星学习通等环节无法落地 | 提前说明可替换为本地平台或微信群+问卷星 |
| 需要实拍实验/设备画面 | 本技能不生成实拍素材 | 由教师自行补拍，仅生成文字与结构 |
| 用户未提供人才培养方案或教学大纲 | AI 易出现与本校不符的表述 | 建议上传，或在生成后重点审查“设计思路”栏 |
| 用户要求填入真实学生成绩、学号等个人数据 | 涉及隐私，不应写入 | 一律使用示例性/聚合性表述 |

**能力边界**：本技能生成的是**草稿**，不替代教师的专业判断与审查；不用于商业目的；不生成成绩单、学籍、问卷调查原始数据等敏感材料。

## 一、收集信息（对话完成，不调用脚本）

**步骤 1：判断基本信息是否完整。** 六项必填信息：

课程名称、面向专业、授课内容、所属课程节次、学时安排、授课人数。

- 若用户一开始就添加了文件（教学大纲、教案、课件等），优先从中提取上述信息，再判断完整度；
- 六项信息均已获得 → 直接进入步骤 2，不弹出示例（减少用户选择次数）；
- 信息缺失或仅提供了课程名称、专业等部分信息 → 弹出提示词示例，请用户补充：
  - ① 否：由 AI 挑选一个通用章节内容生成示例，并明确说明示例为虚构；
  - ② 继续补充：再次显示示例并请用户继续输入。

> 提示词示例 1：请为我设计一份 人工智能专业（本科），班级35人，类脑计算及应用课程，第二章 机器人自主心智发育的第一节、第二节的混合式教学设计，本课程共 72 学时，其中线上 16 学时，线下面授 56 学时，本课次线上 1 学时，线下 3 学时。
>
> 提示词示例 2：请为我设计一份 汽车技术服务与营销专业（专科），班级50人，汽车营销实务课程，第七章 旧车评估与销售混合式教学设计。本课程共 36 学时，其中线上 16 学时，线下 20 学时。本课次线上 1 学时，线下 2 学时。

**步骤 2：提示用户添加现有教学资料。** 弹出选项：① 暂不添加（由 AI 选取通用内容生成示例）② 添加（请用户上传教学大纲、教案、课件等资料）。

**步骤 3：确认产物类型。** 弹出选项：

- 选项 1：混合式教学设计方案 + 课程教学日历（仅两个 Word 文档）
- 选项 2：上述两个 Word 文档 + HTML 交互式说课课件
- 选项 3：上述两个 Word 文档 + HTML 交互式说课课件 + 说课 PPT

## 二、内容分析（AI 撰写，可调用爬虫）

1. **按需查阅** `python scripts/ref_reader.py methodology` 输出的对应小节（用 `toc` 定位，`sections[].id` 即小节编号，如 `§B.4`），撰写“二、整门课程的混合式教学设计方案”与“三、一课次的混合式教学设计方案”各栏目内容（**每栏须写可落地的丰富内容，开箱即用**）；撰写“三、一课次 · 2. 学习目标”时，必须参考 `python scripts/ref_reader.py bloom_reference`（行为动词看 `blocks[0]`、知识类型看 `blocks[1]`），按**知识目标 / 技能目标 / 素养目标 / 思政目标**四类撰写，每条以布卢姆行为动词开头并标注知识类型；撰写“三、一课次 · 4. 过程与方法”时，须按 `methodology` 中的 §B.4 细化为“阶段→环节→教师活动/学生活动/平台工具/设计意图”的可照做步骤，不可只写原则性概述。
2. 若用户资料不足以支撑内容，可调用 `scripts/crawl_info.py` 爬取公开教学资料辅助撰写；
3. 将撰写好的全部内容写入 `work/design_data.json`，字段结构见 `python scripts/ref_reader.py design_plan_guide` 的输出（含完整示例）。教学日历按 `python scripts/ref_reader.py methodology` 中 `§C` 的“日历填写规则”生成完整讲次数据。
4. **撰写面向学生的前测/中测/后测**：按 `python scripts/ref_reader.py methodology` 的 §B.7，就本课次**学习内容**出题考学生（考查概念、方法、应用，而非课程元信息），每题含题干、4 个选项（1 正确 + 3 干扰）、正确答案与**针对作答的反馈**（解释正确理由与典型误区）。将测试题写入 `design_data.json` 的 `interactions.quizzes`；若未提供，脚本会依据学习目标自动生成内容型兜底题目。

### 生成前自检清单（写完 JSON 后逐项确认，可显著减少返工）

- [ ] 六项基本信息齐全，且与用户所述一致
- [ ] 学时口径一致：`basic_info.hours` 的线上/线下比例 = `calendar` 中线上/线下讲次比例
- [ ] 四类学习目标齐全，每条以布卢姆行为动词开头，并用括号标注知识类型
- [ ] “过程与方法”含课前/课中/课后三阶段，每环节有教师活动、学生活动、平台·工具、设计意图
- [ ] 日历序号连续不重复，授课地点无学校/校区/校园名称
- [ ] 三测题目面向学生、考查学习内容，每题 4 选项、有正确答案与解析
- [ ] 无字段残留模版占位符（如“（整门课程的混合式教学设计思路）”）
- [ ] 无误将 `null` 写入 JSON（缺失字段用 `""` 或 `[]`）

## 三、生成产物（调用脚本）

在工作目录执行（`<json>` 为 design_data.json 路径，`<out>` 为输出目录，默认与 json 同目录）：

- 选项 1：`python scripts/build.py <json> <out>`
- 选项 2：`python scripts/build.py <json> <out> --html`
- 选项 3：`python scripts/build.py <json> <out> --html --ppt`

脚本会自动依次：

1. `fill_design_plan.py` → 生成《混合式教学设计方案.docx》；
2. `fill_calendar.py` → 生成《混合式教学教学日历.docx》；
3. `gen_html_courseware.py`（选项 2/3）→ 生成交互式 HTML 课件（分页呈现、支持鼠标与键盘翻页、字号最小 24px、含 5 个以上交互点、2 个以上模拟仿真与测试）；其中的**前测/中测/后测 是面向学生的内容测试**，学生作答后自动给出判定与解析反馈；`gen_ppt.py` 另含“测试题（题目与参考答案）”页、`fill_design_plan.py` 在“评价与反馈”下附三测**完整题库**（全部题目 + 参考答案 + 解析），题目均可选由 AI 从 `interactions.quizzes` 提供。
4. `gen_ppt.py`（选项 3）→ 生成 16 页说课 PPT（含“测试题（题目与参考答案）”页），内容与视觉风格与 HTML 课件一致。

**产物长什么样**：见 `python scripts/ref_reader.py output_preview`（含四个产物的完整结构、页序、成品内容片段与生成后核对清单），生成前可先对照确认。

**失败自动重试**：脚本对失败步骤会自动重试 1 次（通常可越过临时的依赖/文件占用问题）；若仍失败，按「五、报错处理」对照表处理。

生成完成后向用户展示产物，并提示产物保存在输出目录。

### 生成后校验清单

- [ ] 输出目录内四个产物文件均存在、可打开、非 0 字节
- [ ] 打开《混合式教学设计方案.docx》，确认模版行列未错位、内容已填入、文末有页脚说明
- [ ] 打开《混合式教学教学日历.docx》，确认序号连续、无学校名称
- [ ] 打开 HTML 课件，确认可翻页、三组测试题可作答并显示解析
- [ ] 打开 PPT，确认 16 页齐全、末页为页脚说明
- [ ] 将以上结果告知用户，并提醒“产物须经教师审查修改后方可使用”

## 四、一键自检（可选，排障时优先用）

若不确定环境是否正常，可先运行：

```
python scripts/selfcheck.py
```

它会检查依赖是否就绪、模版能否正常读取、JSON 结构是否合法、四类产物能否生成，并输出一份“哪一步 ok / 哪一步待修”的简明报告，不产生正式产物。

## 五、报错处理

为使用体验更佳，建议使用 WorkBuddy 调用本 Skill。
本 Skill 运行依赖 python-docx、python-pptx（及其依赖 lxml、Pillow 等）。在 WorkBuddy 等 AI 工具中这些依赖通常已预置；若缺失，AI 工具会自动联网从 PyPI 安装，无需用户通过编写代码等方式干预。用户只需同意 WorkBuddy 的权限请求即可。

### 错误 → 原因 → 修复 对照表

| 现象 / 提示 | 原因 | 怎么修 |
|---|---|---|
| `ModuleNotFoundError: No module named 'docx'`（或 `pptx`） | 依赖未安装 | 运行 `python scripts/_bootstrap_deps.py`；仍不行则联网安装 `python-docx python-pptx` |
| `【错误 E01】找不到数据文件 …` | `design_data.json` 路径写错或文件未生成 | 确认路径；让 AI 重新写出该 JSON |
| `【错误 E02】数据文件不是有效的 JSON …` | JSON 语法错误（多余逗号、中文引号、单引号） | 让 AI 重新生成该文件，注意用英文双引号 |
| `【错误 E03】编码不是 UTF-8 …` | 文件被以非 UTF-8 编码写出 | 让 AI 以 UTF-8 重新写出该文件 |
| `【错误 E04】输出目录不可写 …` | 目录不存在/无权限，或文件被 Word/WPS 占用 | 更换输出目录，或关闭占用该文件的程序 |
| `【错误 E05】Word 模版读取失败 …` | 技能包不完整或模版被改动 | 重新解压技能包，勿修改 `assets/templates/templates.json` |
| `【错误 E06】找不到页脚说明文件 …` | `references/` 下的页脚说明文件被移动、改名，或技能包不完整 | 重新解压技能包；页脚文字统一存放在 `references/` 目录内，勿改文件名 |
| `【错误 E07】… 不是有效的 JSON` | references/ 下的参考资料被手工编辑坏了 | 重新解压技能包，参考资料勿手工编辑 |
| `【错误 E08】找不到参考资料 …` | `references/` 下 6 个 JSON 有缺失 | 重新解压技能包；自检 `python scripts/selfcheck.py` 会逐项列出 |
| `提示：缺少必需字段 …` | `design_data.json` 里少了必填栏目 | 按 `python scripts/ref_reader.py design_plan_guide` 输出的字段说明补齐后重跑 |
| `提示：未找到占位符 …，已跳过` | 内容字段为空，该栏保持模版原样 | 补齐对应内容字段后重跑，勿留空 |
| `提示：日历模版结构异常，未填写表格` | 模版文件损坏或非官方模版 | 重新解压技能包，勿修改 `assets/templates/templates.json` |
| 生成中途中断、无输出 | 网络波动或文件被占用 | 关闭已打开的 Word/PPT 后重跑；或直接输入“请继续完成” |
| 文件生成后打不开 | 同名文件正被 Word/WPS 占用 | 关闭该文档后重跑一次 |
| 输出乱码 | 终端编码非 UTF-8 | 内容本身为 UTF-8，用 Word/WPS/浏览器打开产物即可正常显示 |

如遇对话或输出中断，请先检查网络连接是否正常。如网络畅通，请再检查 WorkBuddy 等工具是否最新版。并在对话框输入：请继续完成。

## 七、常见问题解答（FAQ）

**Q1：我不了解混合式教学怎么办？**
你可先用模糊提示词让 Skill 帮你生成一份混合式教学设计文稿，这份教学设计实则是一个例子，你可阅读了解后再使用更加精确的提示词，包括学段（本科/职业本科/高职高专/高技）、专业、年级与学期、课程名称、授课内容、所属课程节次、学时安排（线上/线下学时）、授课人数、设计者等信息，并上传人才培养方案、专业教学标准或原有教学大纲等教学资料，WorkBuddy 等 AI 工具将会调用本技能为你生成有针对性的混合式教学设计。

**Q2：生成的 Word 文档、HTML 交互式课件和 PPT 在哪里？怎么打开？**
本 Skill 生成的产物保存在用户指定的工作空间（默认与 design_data.json 同目录）。本 Skill 在所有流程结束、生成产物后会展示产物，用户可点击打开或选择“打开文件夹”查看。各产物的版面结构与页序见 `python scripts/ref_reader.py output_preview`。

**Q3：这个技能能直接生成 PPT 课件吗？**
本 Skill 默认产出《混合式教学设计方案》和《混合式教学教学日历》两个 Word 文档；说课用的 HTML 交互式课件与 PPT 需在“确认产物类型”环节选择选项 2 或 3 才会生成。PPT 是基于教学设计文稿生成的，所以必须先生成 Word 文档，单独直接生成会增加 AI 幻觉的风险。

**Q4：我的课程是实训课/中小学课/企业培训，能用吗？**
可以生成，但效果可能打折。实训类课程建议把线上部分改为安全规范与工艺流程预习；中小学课程请按学段调整目标动词与环节时长；企业培训请把“人才培养方案”替换为岗位能力标准。详见「零之二、适用范围与效果受限情形」。

**Q5：运行时报错怎么办？**
先运行 `python scripts/selfcheck.py` 一键自检，再对照「五、报错处理」的“错误 → 原因 → 修复”对照表逐条处理；脚本对失败步骤已内置自动重试 1 次。若仍无法解决，请让 AI 工具协助安装依赖，或重新运行一次。

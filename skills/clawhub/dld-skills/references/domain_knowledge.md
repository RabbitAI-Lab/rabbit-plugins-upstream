# 1688 选品领域知识

本文档整理 1688 电商选品的核心概念、指标含义、常见选品策略和场景，帮助理解用户意图并正确使用 MCP 工具。

---

## 一、1688 平台概述

1688（阿里巴巴1688.com）是中国领先的 B2B 批发采购平台，主要服务于工厂、批发商、电商卖家之间的批发交易。与淘宝/天猫的 C2C/B2C 模式不同，1688 以批发为核心，商品通常有起批量要求，价格随采购量阶梯递减。

**核心角色：**
- **供应商/卖家：** 工厂、品牌商、批发商，提供商品货源
- **采购商/买家：** 电商卖家、实体店主、跨境卖家等，在平台上选品采购

## 二、核心概念与指标解释

### 2.1 价格体系

| 概念 | 说明 |
|------|------|
| **批发价（price）** | 商品的基础批发价格，通常对应最低起批量的单价 |
| **代发价（consignPrice）** | 一件代发模式下的价格，通常高于批发价（含代发服务费） |
| **起批量（quantityBegin）** | 最低采购数量，低于此数量无法下单 |
| **价格区间（quantityPrices）** | 阶梯价格区间，不同采购量对应不同单价 |
| **单位（unit）** | 商品的计价单位，如：件、个、箱、米、公斤等 |

### 2.2 销量指标

| 指标 | 说明 | 选品意义 |
|------|------|----------|
| **销售笔数（orderCount）** | 统计周期内的订单数量 | 反映购买频次和买家数量，笔数高说明买的人多 |
| **销售件数（saleQuantity）** | 统计周期内的商品销售总数量 | 反映实际出货量，件数高说明卖得多 |
| **预估销售额（salesVolume）** | 统计周期内的预估交易总额 | 反映市场规模和交易规模 |
| **总笔数（ordersCount）** | 商品上架以来的总订单数 | 反映商品历史表现和生命周期 |
| **总件数（salesCount）** | 商品上架以来的总销售数量 | 反映商品长期出货能力 |

> **重要区分：** 笔数和件数的区别——一笔订单可能采购多件商品。例如一个买家一次买了100件，那就是1笔、100件。分析时应综合两个指标：笔数高+件数高=爆款；笔数低+件数高=大客户批发为主；笔数高+件数低=散客为主。

### 2.3 卖家类型与资质

| 概念 | 说明 |
|------|------|
| **诚信通年限（tpYear）** | 卖家在1688平台开通诚信通服务的年数。年限越长，通常代表供应商越稳定可靠 |
| **超级工厂（superFactory）** | 1688最高等级的工厂认证卖家，具备强大生产能力，通过严格审核 |
| **实力商家（Power）** | 经过平台认证的实力卖家，具备一定规模和资质 |
| **仅诚信通会员（TrustPass）** | 基础付费会员，开通了诚信通服务 |
| **公司类型-店铺（companyType=1）** | 以贸易/零售为主的店铺型卖家 |
| **公司类型-工厂（companyType=2）** | 以生产制造为主的工厂型卖家，通常价格更有优势 |

### 2.4 代发与面单权益

| 概念 | 说明 |
|------|------|
| **一件代发包邮（proxyRights: 4360897）** | 卖家支持一件起代发且包邮，适合无库存模式的电商卖家 |
| **先采后付（proxyRights: 449154）** | 平台担保交易，收到货后再付款，降低采购风险 |
| **面单支持** | 商品发货时支持使用的电商平台面单类型 |

**面单支持类型：**
| 代码 | 平台 |
|------|------|
| 441218 | 淘宝 |
| 386434 | 抖音 |
| 422914 | 拼多多 |
| 422978 | 小红书 |
| 386370 | 快手 |

> **选品提示：** 如果用户是做某个平台的电商（如抖音小店），筛选时加上对应面单支持条件，可以确保商品能够无缝发货到该平台。

### 2.5 商品标识

| 标识 | 代码 | 说明 |
|------|------|------|
| 不限制 | 0 | 不筛选商品标识 |
| 新品 | 2 | 近期上架的新商品，适合挖掘早期趋势 |
| 1688严选 | 3 | 平台精选高品质商品，品质有保障 |
| 跨境Select | 4 | 适合跨境电商出口的商品 |
| 支持定制 | 5 | 卖家支持OEM/ODM定制生产 |
| 镇店之宝 | 6 | 卖家店铺的主推爆款商品 |

### 2.6 卖家服务

| 服务 | 代码 | 说明 |
|------|------|------|
| 安心购 | 4057409 | 平台保障服务，提供交易安全保障 |
| 深度认证报告 | 888777 | 第三方深度认证，供应商资质更可信 |

### 2.7 发货时间

| 代码 | 说明 |
|------|------|
| 24 | 24小时内发货 |
| 48 | 48小时内发货 |
| 72 | 72小时内发货 |

### 2.8 统计周期说明

product_search_list 工具支持多种统计周期，用于按不同时间维度分析商品销量：

| cycle值 | 时间范围 | 适用场景 |
|---------|----------|----------|
| 1 | 近1天 | 监测最新销售动态，发现突发爆品 |
| 3 | 近3天 | 短期趋势分析，捕捉上升势头 |
| 7 | 近7天 | 周度销量分析，最常用的选品周期 |
| 30 | 近30天 | 月度趋势分析，评估商品长期表现 |

## 三、常见选品策略与参数组合

### 3.1 爆品筛选
**目标：** 找到销量高、增长快的商品

**推荐参数组合：**
- sortField: orderCount7d 或 saleCount7d（近7天销量降序）
- sortType: desc
- cycle: 7
- 可叠加：beginOrderCount 设置最低销量门槛（如≥100笔）
- 可叠加：offerType=2 筛选新品中的爆款

### 3.2 潜力品挖掘
**目标：** 发现销量开始上升、尚未爆发的商品

**推荐参数组合：**
- sortField: orderCount3d（近3天笔数降序，捕捉短期上升）
- sortType: desc
- cycle: 3
- 叠加：beginOrdersCount 设置较低门槛（如≥10笔），排除太冷门的
- 叠加：offerType=2 筛选新品

### 3.3 供应商评估
**目标：** 找到可靠、有实力的供应商

**推荐参数组合：**
- shiLiType: ["superFactory"] 或 ["superFactory","Power"]
- beginTpYear: 3（诚信通3年以上）
- companyType: 2（工厂类型）
- shopService: ["4057409"]（安心购）
- sendTime: [24,48]（发货时效好）

### 3.4 一件代发选品
**目标：** 适合无库存电商卖家的代发商品

**推荐参数组合：**
- proxyRights: ["4360897"]（一件代发包邮）
- faceToFaceSupport: 根据用户电商平台选择对应面单
- beginPrice / endPrice: 根据用户预算设定

### 3.5 价格区间选品
**目标：** 在特定价格区间内寻找高性价比商品

**推荐参数组合：**
- beginPrice / endPrice: 设定目标价格区间
- sortField: saleVolume7d（按销售额降序，找高客单价高销量的）
- cycle: 7

### 3.6 新品趋势追踪
**目标：** 追踪近期上架的新品表现

**推荐参数组合：**
- offerType: 2（新品）
- sortField: orderCount3d（近3天笔数降序）
- sortType: desc
- cycle: 3
- beginOfferCreateTime: 设定起始上架时间

### 3.7 跨境电商选品
**目标：** 适合跨境电商出口的商品

**推荐参数组合：**
- offerType: 4（跨境Select）
- sortField: saleVolume30d（近30天销售额降序）
- cycle: 30

## 四、用户意图识别指南

当用户提出选品需求时，需要识别以下维度的信息：

### 4.1 关键信息维度

| 维度 | 用户可能的表达 | 对应参数 |
|------|----------------|----------|
| **商品关键词** | "女装"、"手机壳"、"夏季T恤" | keyWord |
| **价格范围** | "10-50元"、"便宜的"、"高端的" | beginPrice/endPrice |
| **销量要求** | "卖得好的"、"高销量的"、"爆款" | beginOrderCount/beginSaleCount |
| **卖家类型** | "工厂直供"、"实力商家"、"超级工厂" | shiLiType/companyType |
| **发货时效** | "发货快的"、"24小时发货" | sendTime |
| **代发需求** | "一件代发"、"支持代发" | proxyRights |
| **电商平台** | "抖音"、"淘宝"、"拼多多" | faceToFaceSupport |
| **商品类型** | "新品"、"严选"、"跨境" | offerType |
| **统计周期** | "最近一周"、"近30天" | cycle |
| **地域** | "广东"、"义乌" | location |
| **起批量** | "小批量"、"起批量低的" | beginStartQuantity/endStartQuantity |
| **诚信通年限** | "老店"、"信誉好的" | beginTpYear |

### 4.2 模糊意图处理策略

**策略一：关键信息缺失时主动追问**
当用户问题过于模糊（如"帮我找点好卖的商品"），缺少商品方向时，主动追问：
- "您想找哪个类目/品类的商品？"（确定 keyWord 或 categoryIdList）
- "您的目标价格区间大概是多少？"（确定价格范围）
- "您是做哪个电商平台的？"（确定面单支持）

**策略二：宽泛搜索 + 引导细化**
当用户有一定方向但条件不够具体时（如"帮我找夏季女装"），可以：
- 先用关键词进行宽泛搜索，按销量降序返回前20条
- 根据搜索结果引导用户细化条件（如"我看到批发价集中在X-Y元，您期望的价格区间是？"）

**策略三：直接执行**
当用户提供了明确的商品方向和至少1-2个筛选条件时，直接构建参数调用工具，无需追问。

## 五、结果展示规范

### 5.1 图片展示
- 返回数据中 `image` 字段为商品图片URL，**应主动使用 Markdown 图片语法展示**
- 格式：`![商品标题](image_url)`
- 每个商品都应展示图片，用户对视觉信息更敏感

### 5.2 商品链接
- 可通过 offerId 拼接1688商品链接：`https://detail.1688.com/offer/{offerId}.html`
- 店铺链接可直接使用返回数据中的 `shopUrl` 字段

### 5.3 展示形式选择

**少量商品（1-5个）：使用卡片式展示**
每个商品作为一个信息块，包含图片、标题、价格、销量等关键信息。

**中等数量（6-20个）：使用表格展示**
用表格展示核心字段（图片、标题、批发价、销量、店铺名称），重点信息一目了然。

**大量商品（20个以上）：使用精简表格**
只展示最核心字段（标题、批发价、销量、店铺），图片可选择性地展示前几个。

**单品分析：使用趋势展示**
对 product_info 返回的每日趋势数据，使用表格或趋势描述展示日期、日笔数、日件数、日销售额、价格变动。

### 5.4 HTML 渲染注意事项
- 如需使用 HTML 展示商品卡片，确保使用渲染格式而非代码块
- HTML 卡片应包含：商品图片、标题、价格、销量、商品链接
- 避免输出 HTML 源代码，应直接渲染展示

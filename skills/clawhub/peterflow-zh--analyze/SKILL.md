# 检查资料一致性

这是可选检查。输入为当前已有目标、计划或任务，来源、名称和数量不限；输出为有位置、有影响、有后续动作的发现，不负责实际功能测试。

1. 明确本轮范围和事实来源，读取相关项目规则与 .peterflow/standards/ 中适用规范。已有其他资料目录则沿用。仅读取目标有关材料。可选子目录缺失时无需补建；只有缺少的具体材料会影响实施或验收，才报告其后果。
2. 从每条当前要求出发，找方案如何处理、哪项工作交付、哪项验收从约定入口观察结果。用同一个输入对照不同描述。清单有编号或测试已存在，仍要看执行该任务是否真的交付并验证这项行为。轻量直接对照目标与短计划，旧清单沿用原编号。
3. 反向核对每项工作由哪条需求、适用规范或必要技术前置支撑。指出无依据的新增范围。涉及 Phase 时合并阶段前置与 Task 依赖，核对前置交出的结果能否让后继开工。
4. 当前资料给出互斥结果，报冲突；已定行为找不到交付或验收去向，报遗漏；现有依据不足以决定用户可见行为，列待决定。先核对原决定的效力，明确哪一部分受影响。难以区分时参考[双向对照样例](references/coverage.md)。

默认只报告，不改代码或资料。用户已要求修正或已授权持续实现时，可以在当前范围内修正明确错误，保留原编号和有效进度；无法判断的产品决定集中询问。修正后复核受影响关系，继续原流程，不强制重跑所有阶段。

报告前，结合上下文、文中引用和适用规范，走一遍受影响的具体场景。说明按原文实施时，哪个输入会得到错误结果、哪个步骤会漏做或多做，或哪种错误会通过验收。待决定项写明不同选择会怎样改变结果。已有说明足以指导正确实施和验收时，略过措辞和详略差异。

每项发现引用冲突双方的位置或被遗漏的原要求，指出应修正的原位置和能否继续。资料一致时直接说明核对范围；资料一致性不证明功能已通过。只有用户要求留档时才写入原资料目录，不另建任务账本。

# 募集资金使用与募投进度·逐条挂源

## 0. 这是什么、不是什么

| 是 | 不是 |
|---|---|
| **一笔募集资金从到账到结项**的存续期台账 | 发行方案本身（发行价、锁定期、认购对象） |
| 专户余额、累计投入、投入进度逐期登记 | 判断这个项目「值不值得投」 |
| 变更、置换、补流、结项节余逐条抄 | 判断变更「合不合规」「有没有问题」 |
| 进度与比例照抄披露值 | 拿投入额除以承诺额自己算一个百分比 |

**三条分界（用户靠这三句分清邻近件）：**

- `placement-terms-cn` 做**发行条款**（定增方案里的十项：规模、价格、对象、锁定期……）。本件从**钱到账之后**开始，管存续期怎么花。
- `convertible-bond-terms-cn` 做**可转债条款**。本件不碰债券条款本身，只登记募集资金的使用台账。
- `ma-restructuring-terms-cn` 做**并购重组文件**。本件只做募集资金专户这一条线。

**「不得自己除」在本件里具体指哪两件：**

1. **投入进度只认披露写的百分比。** 专项报告里通常直接写「累计投入进度 62.35%」，抄这一句。自己拿累计投入 6,235 万元除以承诺投入 10,000 万元得出的 62.35%，在原文里找不到——哪怕数值一模一样也不许写。
2. **变更比例、节余比例同理。** 变更后金额、变更部分占募集资金净额的比例，披露写了就抄；没写就写未取到，不用两个数相除顶上。

## 1. 什么时候用

- 「这笔定增募的钱花到哪了」「募投项目现在什么进度」
- 「专户里还剩多少」「有没有拿去补流」
- 「募投项目变更过没有，变更了哪些」
- 「有没有置换先期投入」「结项后节余多少」

**不要用**：要发行条款（走 `placement-terms-cn`）；要可转债条款（走 `convertible-bond-terms-cn`）；要并购重组文件（走 `ma-restructuring-terms-cn`）；要判断募集资金使用是否合规、有没有违规占用、评级目标价（本件不产出，也不该由任何件产出）。

## 2. 取数纪律

1. **只认公司自己的披露。** 募集资金专项报告、年度募集资金存放与使用情况鉴证报告、变更公告、结项公告。研报、新闻、股吧转述一律不作来源。
2. **每条都引原句。** 写成 `- 项名：「原文原句」〔锚：页/表〕[S#]`，引号里是公告原话。
3. **进度照抄。** 见第 0 节两条。
4. **金额不改写。** 披露写 6,235.00 万元就写这个数，不写「约 6,200 万」「六千万出头」。
5. **一期一登记，不合并跨期。** 同一项目 2024 年 12 月 31 日与 2025 年 6 月 30 日两条进度并列，各自挂自己的 `[S#]`，不取平均、不取最新值覆盖旧值。
6. **没取到就写没取到，两向都判。** 正文写了「未取到 X」，第五节必须点名 X；第五节点了名而正文没有这条表述，同样算错。零缺口写 `- 未取到：无`。
7. **不判断合规。** 「是否存在违规使用」「是否构成资金占用」是结论，本件只登记披露说了什么。

## 3. 输出契约（六节，按序）

```
AI 整理初稿｜请回原文核对｜不构成投资建议｜判断位 [待人工]

主体：<公司名称>
报告期：<YYYY-MM-DD 截止日，或 <YYYY> 年度>
数据口径：募集资金存放与实际使用情况（存续期台账）

## 一、募集概况
## 二、专户余额
## 三、投入进度
## 四、变更与置换
## 五、未取到与口径
## 六、来源
```

- **头部四件自标**逐字在位，写在第一个 `## ` 之前。
- **主体／报告期／数据口径**三行必须在场；`数据口径：` 必须以「募集资金」起头。
- **一、募集概况**：募集方式、募集资金总额、募集资金净额、到账日，逐项挂原句。
- **二、专户余额**：每个专户一行（开户行＋账号末四位＋余额），一行一个专户，不合并成一个「合计」。
- **三、投入进度**：一个募投项目一行，写承诺投入额、累计投入额、披露的投入进度百分比，三个数各自挂源或同在一条原句里。
- **四、变更与置换**：变更/置换/补流/结项节余各一条，抄变更前后项目名与金额；没有发生就抄披露的「未发生变更」那句。
- **五、未取到与口径**：逐条点名未取到的项；口径行写清哪些照抄、哪些未取。
- **六、来源**每行：`- [S#] 文件标题｜URL｜检索日 YYYY-MM-DD`。

## 4. 数据通道

本件走 Cue 的 MCP 通道取公告与原文解析。先列目录，再按目录里的路由地址调 `tools/list`，确认工具在场后再取数：

```bash
CATALOG="https://cuecue.cn/api/mcp-catalog"
curl -s "$CATALOG" | head -c 2000
# 从目录里取本组的路由地址，再确认工具在场
curl -s -X POST "$ROUTING_URL" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

拿到专项报告后，用 `scripts/make_outline.py` 把清单排成骨架，再逐条读原文补内容。

## 5. 合规红线

- **不判合规、不判违规占用。** 「存在违规使用」「构成资金占用」「已被挪用」这类断言零容忍——那是监管与司法的事。
- **不判项目好坏。** 不写「该项目前景良好」「产能消化存疑」。
- **不给评级、目标价、投资建议、买卖建议。**
- **不预测后续进度**，不写「预计年内可达产」「将按期完成」——除非那是披露的原话（抄在引号里）。
- **不用改数词打底。** 「约」「左右」「大概」不得替披露里的确切数字。
- **不把不同项目合成一个总数。** 专户余额、累计投入都不做合计行。

## 6. 快速流程

1. 拿到这份募集资金专项报告（或年度鉴证报告），定主体与截止日。
2. 抄募集概况四项，再逐个专户抄余额。
3. 逐个募投项目抄承诺额、累计投入额、披露的进度百分比。
4. 抄变更与置换事项；没有发生的抄「未发生变更」原句。
5. 写未取到与口径，两向对齐。
6. 跑 `python3 scripts/check_raised_funds.py <稿>.md`，红一条改一条。

不知道从哪开始，先跑内置样例看一份成品长什么样：

```bash
python3 scripts/check_raised_funds.py --demo
```

## 7. 机检

```bash
python3 scripts/check_raised_funds.py <募集资金稿>.md   # 五道，退码 0 全过 / 1 有发条 / 3 读不到或空稿
python3 scripts/check_raised_funds.py --selftest        # 包内夹具自检
python3 scripts/check_raised_funds.py --demo            # 内置样例跑一遍，产出可核对的成品
bash scripts/fixtures/run_fixtures.sh                   # 三档离线自检，零网络零计费
```

五道：**道一 形制**（头部自标、主体／报告期／数据口径三行、六节齐且有序、前四节各至少一条发现行）／**道二 原句与锚**（每条发现行以「」＋〔锚…〕＋`[S#]` 收尾，来源行齐编号与 URL 与检索日，引用编号须已登记）／**道三 不得自算**（进度百分比必须能在同一行原句里逐字找到；找不到的标 `〔自算〕` 并写明分子分母各出自哪句）／**道四 未取到两向点名**（正文与第五节互校，零缺口须显式写 `未取到：无`）／**道五 红线与合计**（合规判断、项目好坏、评级目标价、后续进度预测零命中；专户余额与累计投入出现「合计／小计」一律发）

## 8. 零通道降级

没有 `CUE_API_KEY` 时，本包**不产出内容**，只把用户手上的清单排成带形状的骨架：六节与来源行按清单落位，内容留 `[待人工]`。骨架跑机检必然红在占位行上——这是设计，提醒你补完再交。

代价说清楚：**没有通道就没有专项报告原文，没有原文就没有原句，投入进度那一格就挂不上锚**——进度是这份台账的承重格，它挂不上锚，这份稿就只剩用户口述的几个数。用 `--demo` 看成品形制，不占用通道。

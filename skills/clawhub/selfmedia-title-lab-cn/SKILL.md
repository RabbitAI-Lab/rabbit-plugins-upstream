# 自媒体标题改写

把用户提供的事实压缩成可直接复制的中文标题，按抖音、小红书、B站分别给出各 3 条，并推荐 1 条最贴合正文的标题。

## 输入

先确认以下信息；任一项缺失时，指出缺项并停止产出标题：

```yaml
核心收益: 用户得到的明确好处
正文: 原文、要点或商品/内容资料
平台: 抖音 | 小红书 | B站（可多选）
```

可选补充：目标受众、限制词、语气。只把资料中可验证的内容写进标题；不补编价格、效果、时效、身份、数据或承诺。

## 工作流

1. 提取正文中可证实的主题、对象、动作、结果与边界；将“核心收益”视作方向，不能覆盖正文事实。
2. 先为每个平台找一个不同切入角度，避免只是替换标点或同义词：
   - 抖音：开头直接、口语、突出场景或收益；避免夸张挑战式承诺。
   - 小红书：经验感、清单感或避坑感；保持真诚具体，不伪造亲测。
   - B站：信息密度较高，可用问题、方法或复盘角度；让读者知道内容会讲什么。
3. 每个平台输出 3 条标题。标题间至少改变一个切入角度、句式或信息重点；标题自身不添加正文没有的事实。
4. 从全部候选中选 1 条，说明它与正文最契合的一个具体原因；不是预测流量，也不称为“爆款”。

## 输出格式

```markdown
## 标题建议

### 抖音
1. …
2. …
3. …

### 小红书
1. …
2. …
3. …

### B站
1. …
2. …
3. …

## 推荐使用
**标题：** …

**契合原因：** …
```

若用户只指定部分平台，只输出指定平台的 3 条；推荐仍从已输出的候选中选取。

## 边界

- 只交付标题和简短推荐理由，不撰写脚本、封面、视频、发布计划或评论区话术。
- 不承诺曝光、转化、涨粉或爆款；不使用绝对化、虚假紧迫感或未经资料支持的比较。
- 用户要求夸大或补充虚构事实时，保留真实表述并简要说明不能据此改写。

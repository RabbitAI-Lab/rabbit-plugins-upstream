# 第4章：DIN 关键技术

## 核心观点
四类关键技术支撑 DIN：节点间互联质量保障（微流级流控、层次化细粒度切片、推理业务识别）、推理服务调度、模型推理安全防护（PHYSec、DDoS 防护、APT 监测）。

## 4.1 节点间互联质量保障

### 4.1.1 微流级流控技术
- **要解决的问题**：后训练（隐变量、反向梯度）、推理（KV Cache）等关键数据在云边间传输，AI 训推性能与丢包率强耦合
- **机制**：
  - 网络设备部署租户级 + 业务流级队列隔离
  - 每个用户队列设反压阈值，实时感知拥塞
  - 队列缓存超阈值 → 迅速生成精确流控反压报文，经反向路径通知上游暂停该用户队列传输
  - 缓存回落至停止门限以下 → 解除拥塞，上游重新发包
  - 实现用户队列**零丢包弹性传输**
- **协同**：边缘节点处与数据中心 PFC 协同，实现弹性速率控制与网络级缓存协同、端侧协同降速
- **演进方向**：结合 AI 预测流量模型，主动拥塞避免

### 4.1.2 层次化细粒度切片技术
- **机制**：G-SRv6 融合网络切片 + 随流检测，构建端到端确定性质量保障体系
- **切片类型**：
  - 超低时延型（如时延 <1ms）
  - 带宽保障型（如带宽 >10Gbps）
  - 高可靠型（如丢包率 <0.01%）
- **工作方式**：边缘推理接入设备识别应用后，将业务流引入不同 G-SRv6 切片。G-SRv6 高效可编程路径 + 层次化细粒度切片实现物理资源硬隔离，独立通道提供确定性保障
- **随流检测**：业务流中嵌入检测标记（流标识、时间戳、序列号），逐跳采集时延/抖动/丢包。控制器构建全网质量指标地图，检测到 SLA 偏差触发 SRv6 路径重优化（如切换低拥塞 Underlay 路径），**秒级调整**，实现"尽力而为"到"确定性"的跨越

### 4.1.3 推理业务识别技术
- **目的**：业务类型多样，不同用户所需推理资源不同，精确区分应用以优化资源分配
- **路径一：ARN（Application Responsive Network，应用响应网络）**
  - 端侧设备按推理诉求携带标识
  - 在应用和网络之间增加中间层，基于数据面网络能力开放可编程，让应用"像调用操作系统一样调用网络资源"
  - 利用 IPv6 报文可编程空间携带应用标识，网络入口按 ARN 标识提供差异化推理网络服务
  - 地址与服务解耦、网络与应用解耦：网络不直接感知应用（屏蔽多样性），应用不直接访问网络能力（双向封装，隐藏应用隐私与网络内部信息）
- **路径二：网络侧 AI 识别**（端侧不具备 ARN 能力时）
  - 面向不同推理类型（归纳总结、多轮对话、多模态推理、Agents 交互）的流量行为数据
  - 决策树、神经网络、知识推理增强、多专家识别等方式精准分类
  - 输出识别结果 + 置信度，封装 ARN 标识并提供对应等级服务

## 4.2 推理服务的调度技术
- **目标**：按用户需求、设备性能、网络状态多维因素动态分配模型资源；保证服务质量前提下最大化资源利用率、降低运营成本
- **集中式方案**：DNS 解析先到 DIN 调度器，按边缘节点负载、用户就近、网络质量、流量均衡分配最佳 DIN 节点 IP → 返回用户 → 用户直连最优边缘节点（本地返回或协同中心推理）
- **分布式方案（算力路由）**：算力感知、通告、联合路由。打破传统互联网路由，基于"算力+网络"多因子联合调度算法，感知算力资源/服务的部署位置、实时状态、负载 + 推理业务需求，动态生成调度策略，沿最佳路径调度到目的推理服务节点。边缘节点查算力路由信息表确定最佳服务节点
- **优势来源**：运营商将既有网络调度技术能力扩展到推理模型调度

## 4.3 模型推理安全防护技术

### 4.3.1 以太网相干 PHYSec 技术
- **动机**：边云协同后训练、PD 分离等存在长距链路数据机密性/完整性需求。传统 MACSec 开销大、降低带宽利用率、无法掩盖流量特征
- **机制**：密码学方法 + 以太网物理层融合
  - **新架构**：安全协议下沉物理层，对比特流全加密
  - **新算法**：提前计算解密参数 Ek、H，低时延解密 + 完整性校验
  - **新协议**：原生 PAD 域承载安全协议，零额外开销
- **流程**：发送端业务数据经物理层还原为 257B 码块 → GMP 映射 → 插入 AM/PAD/OH 形成相干复帧 → 帧内比特流加密/完整性校验，安全参数经 PAD 域承载 → 接收端解密/校验 → GMP 解映射还原 257B 码块
- **特性**：对上层业务协议透明（不改协议栈即可加密模型分发、KV Cache）；零加密开销；兼容 FlexOsec；掩盖流量特征；防中间节点窃取篡改

### 4.3.2 拒绝服务流量防护
- **检测**：传统抽样检测分钟级，无法应对秒级加速、分钟级持续的瞬时泛洪攻击。DIN 嵌入式智能流识别：数据面百毫秒周期多维流行为 1:1 统计采集，控制面流式学习维护每 IP 粒度业务流量模型，监控流速突升、报文成分/长度变化 → **感知时间从分钟级缩短到秒级**，协同清洗中心应对快速泛洪
- **处置**：最大攻击已达 Tbps 量级，清洗带宽难以匹配。嵌入式 DDoS 溯源：多维报文特征建 AI 模型，长期监控业务流量趋势与攻击期特征异变，精准识别攻击源，前置过滤常见网络层攻击，线速处理流量型攻击向量，缓解清洗池带宽压力

### 4.3.3 基础设施轻量化 APT 监测
- **模式**："白+黑"轻量化入侵检测
  - 白：路由器正常业务行为（合法操作、白名单规则）
  - 黑：APT 攻击知识库（样本特征 + 攻击行为模式）
- **监测对象**：内核关键数据对象、系统文件、系统账号和配置（识别非法篡改）+ 异常进程活动
- **目标**：对隐蔽持久的 APT 劫持攻击全面威胁感知，保证基础设施安全

## 关键技术间的逻辑
- 微流级流控 + 切片 → 解决"确定性连接"目标
- PHYSec → 解决"多层次安全"目标的传输层
- ARN/AI 识别 + 调度 → 解决"可扩展架构"目标的智能分配
- DDoS + APT → 解决"多层次安全"目标的攻击面

# 第2章：推理业务服务模式及网络需求

## 核心观点
ToB 与 ToC/ToH 场景催生出六种端边云协同推理模式，每种模式对网络提出可量化的硬指标（丢包率、时延、抖动），这些指标是 DIN 关键技术的设计输入。

## ToB 三种模式

### 2.1 算网一体安全推理服务
- **场景**：政务（社会经济数据）、金融（信贷风险评估/反欺诈）、医疗（影像/病历分析、ICU 感染防控）等高数据安全行业
- **方案**：总部部署推理一体机/服务器，分支机构经互联网/专线安全访问。中国移动"智享 WAN"（SRv6 + IPSec 隧道加密）构建"推理一体机 + 智享 WAN"安全推理产品
- **网络需求**：分支到总部的高安全加密通道

### 2.2 边云协同后训练（Post Training）
- **问题**：本地建集群后训练微调成本过高（Qwen72B 纯本地需 128 卡集群，一次性投入难以承受）
- **方案**：以租代买——本地 8 卡 + 云侧租用 120 卡。模型前几层和最后几层部署在边缘（原始样本不出园区），其他层在中心；云边间 RDMA 流水线并行通信
- **量化指标**：
  - 丢包率 10⁻⁵ 即造成协同训练算效损失超 8% → 网络必须控制在 10⁻⁹ 以下
  - 数十毫秒级时延或十毫秒级抖动 → 协同训练吞吐量下降超 50%
  - 目标：训练算效损失 <5%，利用计算掩盖通信
- **网络需求**：超大带宽、超低时延、丢包率 10⁻⁹ 的高安全网络

### 2.3 模型分层协同
- **问题**：企业本地算力扩容三大难题——频繁扩容硬装周期长；机房不支持液冷；电力受限改造贵
- **方案**：以租代买的边云分布式协同推理，弹性扩容、按需分时租用。Split Learning 切分模型（前几层+后几层在边缘保数据不出园区，其他层在云端）。可结合以 KV Cache 为中心调度的 PD 分离架构：Prefill 与 Decode 前几/后几层在边缘（KV Cache 复用降 Prefill 开销），Decode 其他层在云端（弹性扩并发）
- **量化指标**：云边间传隐变量（几 KB 到几十 KB），为保障 Token 间时延（TBT）和亚毫秒级抖动 SLA，网络需超低时延、零丢包、极低抖动
- **实例**：金融风控本地部署大模型+AI 客服高峰期自动扩展云端资源，响应效率提升 50%

## ToC/ToH 三种模式

### 2.1 大小模型协同
- **三种策略**：
  1. **能力调度**：大模型为大脑、小模型为工具。智能巡检中大模型理解报告语义，调用瑕疵检测小模型识别缺陷
  2. **推理加速**：小模型在边缘先出初步结果，云端大模型校正提高精度
  3. **场景自适应**：网络好+高精度要求→云端大模型；边缘即时响应→本地小模型，联机后大模型异步改进
- **网络侧能力跃迁**：网络设备内置异构 AI 算力板卡（几 TFlops 到几百 TFlops），NPU（AI 计算）+ NP（高速数据平面）+ CPU（模型管理）形成"计算-传输-控制"闭环，从单纯转发走向"连接→感知→推理"

### 2.2 训推协同进化（"中训边推"）
- **闭环**：云端大模型蒸馏出小模型部署到边缘 → 边缘小模型推理 → 收集高价值不确定性数据（从案例到 token 粒度，分级过滤）→ 上传云端 → 云端基于适配器的知识蒸馏微调 → 下发小模型参数更新
- **实例**：家庭具身智能机器人（家务、陪伴、老人陪护），按家庭环境动态适配
- **安全需求**：样本数据涉隐私、模型参数下发可能被窃取篡改 → 云边通道加密（PHYSec），经智享 WAN 新平面构建模型分发接入网络

### 2.3 PD 分离协同
- **问题**：延迟敏感服务（家庭具身智能、车路云协同）集中部署时受广域网时延抖动影响，端侧收不到稳定指令
- **方案**：Prefill（计算密集型）在中心节点，Decode（访存密集型）在边缘。中心算完 KV Cache 下发边缘，边缘扩展存储保存 KV Cache（单用户上下文+跨用户高热度信息），边缘执行 Decode 流式返回
- **量化指标**：KV Cache 为 MB 到 GB 级，首 token 时延要求百毫秒内完成传输；PD 间 RDMA，10⁻⁵ 丢包即导致推理服务中断 → 广域网需高带宽、低丢包

## 六种模式网络指标速记
- 后训练/分层协同/PD 分离：丢包阈值 10⁻⁹（RDMA 流水怕丢包）
- 协同训练：数十 ms 时延 / 十 ms 抖动 → 吞吐腰斩
- 分层协同：TBT 亚毫秒级抖动
- PD 分离：KV Cache 百毫秒传完

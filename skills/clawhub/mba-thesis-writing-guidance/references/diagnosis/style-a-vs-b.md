# 写法 A 与写法 B

写法 A 通常能及格：描述公司问题 → 套 SWOT/PEST/五力 → 提出「加强、完善、提升」。
写法 B 用来把已有材料写成**有机制、有边界、读完能记住**的应用型论文。没有内部视角和证据时，先补材料，不要硬写 B。

## 对照

| | 写法 A | 写法 B |
|---|---|---|
| 小节标题 | 「4.2 公司战略分析」 | 「4.2 考核只认销售额时，售后协同为何持续溃败」 |
| 段落 | 先套框架再给空建议 | 论断 → 证据 → 机制 → 对这个企业意味着什么 |
| 理论 | 标签（「本文运用 SWOT」） | 第 3、4 章按同一套概念拆现象 |
| 结论 | 「企业应加强渠道管理 / 完善绩效 / 提升数字化」 | 指出常规叙事错在哪，建议针对本案例且可证伪 |
| 贡献 | 「系统分析了……提供借鉴」 | 命名一个机制，并写清适用边界 |

## 标题

差：`3.3 存在的问题`  
好（营销）：`3.3 经销商流失集中在价盘失控，而不是「积极性不足」`  
好（人力）：`3.3 计件工资下质检员隐瞒缺陷，而不是「质量意识不足」`  
好（运营）：`3.3 返修集中在夜班同一工序，而不是「设备老化」`  
好（财务）：`3.3 报销事后补票导致项目毛利失真，而不是「费用偏高」`  
好（经营管理）：`3.3 总部审批过细导致一线等批复，而不是「执行力不足」`

差：`4.3 优化方案`  
好：`4.3 先统一价盘再扩三四线：与第 3 章三个问题的对应`（其他方向同样用论断，不套 4P 小节名）

## 段落骨架

每节按四句走，缺一句就停：

1. **论断**：这一节要证明什么  
2. **证据**：数字出处 / 事件 / 原话 / 对标（至少一种）  
3. **机制**：为什么会这样，而不是「管理不到位」  
4. **启示**：对第 4 章方案或第 5 章边界有什么约束  

## 结论

把「建议公司提升数字化水平」改成：

- 本文最硬的一条发现是什么（一段话）  
- 机制叫什么、在什么条件下成立  
- 对本案例的具体动作（谁、何时、用什么资源）  
- 什么情况下这些发现不适用  

## 禁止用 B 的时候

- 五个内部问题还没答  
- 第 4 章论断没有任何可展示证据  
- 用户要求的是学校模板填空、而不是冲击优秀  

此时停在写法 A 的合格线：问题–对策对应、数据有出处、对策可执行。够用就不要虚构「反直觉」。

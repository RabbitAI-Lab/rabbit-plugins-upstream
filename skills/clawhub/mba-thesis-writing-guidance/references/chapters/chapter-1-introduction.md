# 第1章 绪论：怎么写

本章交代：研究谁、研究什么问题、为什么值得做、用什么方法、全文怎么走。篇幅约全文 10–15%，配比见 [`../corpus-guide.md`](../corpus-guide.md) §3。

落笔习惯见 [`../prose.md`](../prose.md)。

建议在第 3、4 章有了问题和方案之后再倒装本章。

## 本章要回答的问题

1. 对象边界是什么（哪家企业 / 哪块业务、哪段时间）  
2. 现场里谁在痛、痛在哪、严重到什么程度  
3. 本文具体回答哪一个研究问题  
4. 已有研究接到本题目的缺口在哪  
5. 方法如何收集、如何分析、为何匹配主问题  

## 1.1 研究背景

按三层收束，每层 2–4 句，最后落到本对象的落差。

| 层 | 写什么 | 用什么材料 |
|---|---|---|
| 宏观 | 行业或政策里和本题直接相关的变化 | 公开统计、行业报告、年报，注明出处 |
| 中观 | 这类企业 / 这条业务现在卡在哪 | 对标、竞争或客户侧可核对的事实 |
| 微观 | 本对象近 2–3 年的具体落差 | 内部可脱敏数据、工单、访谈中的可展示事实 |

第一段就可以点名对象和问题。背景只为提出问题服务，不写企业宣传、不写与问题无关的产业全景。

## 1.2 研究目的与意义

**目的**写成可检查的任务，而不是「系统研究」「全面分析」。例如：识别某部门某现象的关键影响因素；解释该现象为何持续；提出针对本案例、能写清谁来做的改进方案。

**意义**分两小段即可：

- 实践：对这个对象、这类岗位或这条流程，做完能帮谁做哪类决策  
- 理论：哪个理论在哪个情境下被怎样用，而不是「丰富了相关研究」

预期效果能量化就量化，量化不了就写清可观察的变化（谁的哪项行为或指标）。

开题三概念（内容 / 目标 / 关键问题）对齐方法见 [`../../workflows/03-outline.md`](../../workflows/03-outline.md)。

## 1.3 文献述评

绪论里的述评是「接到本题目的对话」，不是学科史。按主题或机制分 2–3 类，每一类写：共识、分歧、还解释不了什么。最后一段写缺口：现有解释在哪个对象、情境或机制上不够，因此本文聚焦什么。

操作清单和段落模板见 [`../../checklists/literature-review.md`](../../checklists/literature-review.md)。笔记卡见 [`../../templates/literature-notes.md`](../../templates/literature-notes.md)。

学校把完整综述放在第 2 章时：1.3 写短述评（接到缺口即可），细部和理论展开放到第 2 章。

文献数量、外文比例、近五年占比以学校为准；通用底线见 [`../format-standards.md`](../format-standards.md)。

## 1.4 研究内容与方法

**内容**：对应开题「切几块」。通常即后文各章任务，各用一句话说清本章解决什么。

**方法**：不要只列方法名称。写法、按方向的常见组合、学校要加问卷时怎么改：[`../methods/method-guide.md`](../methods/method-guide.md)。每一种方法写四项：回答主问题的哪一部分、数据从哪来、样本或对象怎么来、分析怎么做。刹车线见 [`../methods/research-design.md`](../methods/research-design.md)。

## 1.5 技术路线

一页图说清：提出问题 → 分析问题 → 解决问题。图中应能看到对象与问题、理论框架、取证、分析、方案。正文用一段话解释图，不要另起一套逻辑。

## 摘要（可与本章同期写）

四句要素：背景、问题、方法、结论。结论写发现了什么，不写「本文分析了什么」。中文 800–1500 字量级，以学校为准。关键词 3–5 个，来自对象、问题、理论，不要堆政策口号。

## 本章小结

200–500 字：回顾对象、问题、方法，并指向第 2 章将用哪个理论来拆第 3 章。不重复 1.1 的数据。

## 写完验收

- [ ] 一句话能说清对象和问题  
- [ ] 背景三层已经收到本案例落差  
- [ ] 目的可检查，意义针对本案例  
- [ ] 述评有比较、有缺口，缺口接到题目  
- [ ] 方法写清怎么用，不是名称清单  
- [ ] 技术路线与后文章节一致

# 阶段 00：接入

用户**不用自己改 YAML**。Agent 启动本 Skill 时：先扫论文项目、能填的先填，缺的再用提问补上，然后写入**论文项目根目录**的配置文件。

模板只提供字段形状：[`../templates/school-format.yaml`](../templates/school-format.yaml)、[`../templates/thesis-config.yaml`](../templates/thesis-config.yaml)。写出来的是工作区根上的 `school-format.yaml`、`thesis-config.yaml`（已有就更新，不要让用户打开模板手填）。

信息不齐时只问缺的那几项，不开始写正文。不要用「常见 ≥3 万字」「查重 15%」这类通例冒充已确认的学校规定。

## 1. 先扫项目（能推断的不要问）

在论文工作区（不是 Skill 仓库自己）里找，找到就写入配置，并告诉用户「我从某某文件里读到的」：

| 想填的字段 | 到哪找 |
|---|---|
| 学校、专业、学位类型 | 封面、开题报告、培养手册、已有 `school-format.yaml` |
| 字数、查重、章节制、引用格式、AI 政策 | 培养手册、学位论文模板、学院通知 PDF/Word |
| 题目、对象、行业 | 已有正文标题、开题表、文件夹名 |
| 主方向 | 题目里的落差类型（对照理论菜单「方向怎么认」）；认不准再问 |
| 材料路径 | 已有问卷、访谈提纲、年报、内部制度（脱敏后只记「有这类材料」） |
| 进度 | 已有第几章正文 / 大纲 / 还只是题目 |

常见文件名线索：`培养手册`、`论文模板`、`开题`、`绪论`、`.docx`、`.pdf`、已有的 `school-format.yaml` / `thesis-config.yaml`。

推断规则：

- 只写文件里**明确出现**的数字和规定。手册没写查重率，就留 `null` 并标「待确认」，不要填 15%。  
- 学校模板和本 Skill 通例冲突 → 听学校，写进 `school-format.yaml`。  
- 工作区是空的、只有本 Skill → 全部走提问，不要假装读到了学校文件。

## 2. 缺项用提问补全（不要丢一份 YAML 让用户填）

产品有 **AskQuestion / AskUserQuestion / 选项卡片** 就用；没有就在对话里按同一批问题问，选项写成可点的那种（A/B/C），不要一次抛六条开放题。

一次只问当前决策需要的字段，每题给推荐项。用户可以选「不确定 / 其他」。

**学校与格式（写入 `school-format.yaml`）**

1. 学位类型：MBA / EMBA / 其他应用型硕士（不确定）  
2. 论文类型：专题 / 企业诊断 / 案例 / 调研报告 / 学校指定 / 不确定  
3. 正文字数下限：以学校文件为准 / 学校没写、先按 3 万自检 / 我还没查  
4. 章节制：五章 / 六章 / 不确定  
5. 学校是否允许 AI 辅助：允许且要声明 / 允许不声明 / 不允许 / 还没查（`ai_policy` 没查就写「待确认」）  
6. 交稿还剩几个月：≥6 / 3–6 / **<3（先收窄题目，不新开复杂方法）** / 不确定  

**研究意图（写入 `thesis-config.yaml`）**

1. 研究对象：现职企业 / 前雇主 / 实践项目公司 / 只能用公开信息的公司 / 还没有  
2. 主管理问题：请用一句话说现场里谁在痛、痛在哪（没有就下一步做工作资源盘点，不要空转选题）  
3. 主方向（只能一个）：营销 / 人力 / 运营 / 质量 / 财务 / 战略 / 数字化 / 经营管理  
4. 材料：已有可脱敏内部材料 / 能拿到 / 只能公开数据 / 尚无合法路径  

已经从文件推断出来的项，提问里带上「我读到的是 X，对吗？」让用户确认，不要当没看见再问一遍。

## 3. 题目还没有时

不要丢 [`../templates/work-resource.md`](../templates/work-resource.md) 让用户自己填。用提问盘：人 / 流程 / 记录 / 客户 / 反复出现的现象。答完由 Agent 写入项目根目录的 `work-resource.md`（可从模板拷一份再填）。选题从现场盘，不从「高级概念」里捡。

## 产出

- 项目根目录更新 `school-format.yaml`、`thesis-config.yaml`（以及需要时的 `work-resource.md`）  
- 用几句话向用户复述已确认项和仍标「待确认」的项  
- 下一阶段：选题未收窄 → `01-topic`；题目已定 → `02-literature` 或 `03-outline`

## 检查点

- [ ] 用户没有被要求去手改 YAML  
- [ ] 能从项目推断的已经写入，并说明出处  
- [ ] 缺项已提问补全，或明确标成「待确认」  
- [ ] 没有把通例数字写进配置冒充学校规定  
- [ ] 用户知道本 Skill 不代写、不编数据  
- [ ] 已说明落笔按 [`../references/prose.md`](../references/prose.md) 控制句长和连接词

# S2: 取代表ASIN + 查需供比 + 一刀判

## S2a: 取代表ASIN（亚马逊前台搜索）

### 输入
- S1候选关键词列表
- marketplace

### 操作
1. 对每个关键词调用 `linkfox-amazon-search`，参数：keyword, marketplace
2. 取搜索结果第1位自然位ASIN作为代表ASIN
3. 同时提取该ASIN的标题、价格、主图URL、评分、评论数
4. 若搜索无结果，标记该关键词为"无搜索结果"

### 输出
- keyword → {asin, title, price, image, rating, reviews} 映射表

### 用途
- 为S2b提供ASIN反查入口
- 同时完成代表商品基础信息采集（标题+价格+主图），无需额外调用Keepa

### 落盘注记
- 落盘：Amazon搜索脚本自动保存JSON到会话目录
- 读取：从products数组第1条提取asin/title/price/imageUrl/rating/ratings
- 判定：响应含products数组，字段数>=15，需投影 asin/title/price/imageUrl/rating/ratings

## S2a+: ASIN 频率分析（S2a 后、S2b 前执行）

### 输入
- S2a 全部搜索结果（每个关键词的完整商品列表，非仅 Top1）

### 操作
1. **ASIN 出现频率统计**：遍历所有关键词的搜索结果，统计每个 ASIN 出现在自然位和广告位的次数
   - organicCount：作为自然位结果出现的次数
   - sponsoredCount：作为广告位结果出现的次数
   - totalAppearances：总出现次数（natural + sponsored）
2. **市场集中度计算**：
   - top3Coverage = Top 3 ASIN 覆盖的关键词数 / 总关键词数
   - top5Coverage = Top 5 ASIN 覆盖的关键词数 / 总关键词数
   - 若 top3Coverage > 50% → 标注"头部集中度高"
3. **广告投手识别**：sponsoredCount >= 3 且 reviewCount < 50 的 ASIN → 标注 isAdSpender=true
4. **去重生成 S2b 输入**：提取所有唯一 ASIN 列表，避免 S2b 重复查询同一个 ASIN

### 输出
```json
{
  "asinFrequency": [
    {"asin": "B0xxx", "organicCount": 5, "sponsoredCount": 8, "totalAppearances": 13,
     "reviewCount": 0, "brand": "xxx", "title": "xxx", "isAdSpender": true}
  ],
  "marketConcentration": {
    "top3Coverage": 0.35,
    "top5Coverage": 0.55,
    "totalUniqueAsins": 20,
    "assessment": "头部集中度中"
  },
  "uniqueAsins": ["B0xxx", "B0yyy", ...]
}
```

### 用途
- **判断市场集中度**：少数 ASIN 霸占大量关键词搜索结果 → 头部卖家垄断严重
- **识别广告投手**：评论数为 0 却大量出现在广告位的 ASIN → 新上架靠广告冲量的卖家
- **去重省积分**：N 次搜索返回上千商品，去重后只需查 M 个唯一 ASIN（M << N），卖家精灵反查次数大幅减少

## S2b: 查需供比（卖家精灵反查ASIN）

### 输入
- S2a的代表ASIN列表
- marketplace

### 操作
1. 对每个ASIN调用 `linkfox-sellersprite-traffic-keyword`，参数：marketplace, asin, size=100, orderField=trafficPercentage, orderDesc=true
2. **关键**：size参数最大100
3. 从返回结果中查找目标关键词，提取以下字段：
   - supplyDemandRatio（需供比=月搜索量/商品数，越高越好）
   - searches（月搜索量，>0即有需求）
   - products（商品数）
   - bid（PPC竞价/CPC）
   - bidMin / bidMax（PPC竞价区间）
   - monopolyClickRate（垄断点击率=Top3 ASIN点击占有率）
   - purchases（月购买量）
   - purchaseRate（购买率）
   - latest30daysAds（近30天广告竞品数）
   - top3ConversionRate（Top3转化率）
4. 若目标关键词不在Top100中，标记为"keyword_not_in_top100"（**不等于假需求**，仅代表该ASIN的Top100流量词中未包含此词）
5. 读取保存的JSON文件而非解析stdout

### 数据路径约束
无直接关键词查询工具，必须走「Amazon搜索 → Top1自然位ASIN → 卖家精灵反查」路径。若候选词未出现在该ASIN的流量词Top100中，则无法获得可靠指标。

### 输出
- 每个关键词的需供比+月搜索量+商品数+CPC+垄断率+购买量+购买率+广告竞品数+Top3转化率

### 需求验证逻辑
- searches > 0 即有需求（无需ABA单独验证，**禁止使用SIF**）
- searches = 0 或无数据 即假需求
- keyword_not_in_top100 → 数据不足（该词不在代表ASIN的Top100流量词中，无法获取需供比等指标）
- 需求信号分级：searches>10万=极高, >1万=高, >1千=中, <=1千=低

### 落盘注记
- 落盘：卖家精灵脚本自动保存JSON + 24h缓存
- 读取：从保存的JSON文件读取（不解析stdout）；缓存文件在 linkfox/.cache/ 目录
- 判定：响应含data数组（<=100条），字段数>=20，需投影 keyword/supplyDemandRatio/searches/products/bid/monopolyClickRate/purchases/purchaseRate/latest30daysAds/top3ConversionRate

## S2c: 一刀判过滤（优先决策树）

### 输入
- S2b的需供比数据 + S2a的代表ASIN价格
- 可配置参数：见下方默认值

### 第0层：硬过滤（先于决策树执行，任一命中即放弃）

| 条件 | 判定 |
|------|------|
| minPrice != null 且 price < minPrice | 放弃-价格过低 |
| maxPrice != null 且 price > maxPrice | 放弃-价格过高 |
| minSearches > 0 且 searches < minSearches | 放弃-需求不足 |
| minPurchases != null 且 purchases < minPurchases | 放弃-转化不足 |
| minPurchaseRate != null 且 purchaseRate < minPurchaseRate | 放弃-购买率过低 |
| maxCPC != null 且 CPC > maxCPC | 放弃-广告成本过高 |
| maxProducts != null 且 products > maxProducts | 放弃-商品数超限 |

### 第1层：优先决策树（硬过滤未命中的词，按顺序判断，第一个命中即生效）

1. **Amazon搜索无结果（无ASIN）** → 放弃-无搜索结果
2. **候选词未出现在代表ASIN的卖家精灵流量词Top100中** → 放弃-数据不足
3. **卖家精灵无数据或 searches == 0** → 放弃-假需求
4. **filterBroadTerms == true 且（关键词 == 种子词 或 is_broad(关键词)）** → 放弃-词过于宽泛
5. **垄断率 > monopolyThreshold** → 根据 monopolyAction：abandon=放弃-垄断 / watch=观望-垄断 / downgrade=不改结论但评分扣分
6. **需供比 < redOceanThreshold** → 放弃-红海
7. **竞争度 == 高** → 观望-竞争激烈
8. **需供比 < watchThreshold** → 观望-竞争激烈
9. **watchThreshold ≤ 需供比 ≤ opportunityThreshold** → 可进-供需平衡
10. **需供比 > opportunityThreshold** → 可进-机会型

### 竞争度三因素决策树（参数化）

```text
if 垄断率 > monopolyThreshold:
    竞争度 = 高
elif 商品数 > productHighThreshold and 需供比 < 1:
    竞争度 = 高
elif 商品数 > productHighThreshold and 需供比 >= 1:
    竞争度 = 中
elif productLowThreshold <= 商品数 <= productHighThreshold and 需供比 > 1:
    竞争度 = 中
elif 商品数 < productLowThreshold and 需供比 > 1:
    竞争度 = 低
else:
    if 需供比 < watchThreshold:
        竞争度 = 高
    else:
        竞争度 = 中
```

### 保留池与淘汰词
- 淘汰词（所有「放弃」）保留在附录，标注原因（数据诚信原则）
- **可进 + 观望** = 保留池，按 sortBy 参数排序后取 deepDiveTopN 进入S3，最终 topN 也从此池输出

### 关键参数默认值
- redOceanThreshold = 0.1, watchThreshold = 0.3, opportunityThreshold = 1.0
- monopolyThreshold = 0.6, monopolyAction = abandon
- productLowThreshold = 1000, productHighThreshold = 5000
- minPrice/maxPrice/minSearches/minPurchases/minPurchaseRate/maxCPC/maxProducts = null（不过滤）
- filterBroadTerms = true

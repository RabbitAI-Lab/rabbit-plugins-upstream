### 1. Customer Segmentation / 客户分层

```python
class CustomerSegmentation:
    """客户分层引擎"""
    
    def segment_customers(self, customer_data: list) -> dict:
        """
        客户分层模型
        基于RFM+生命周期+风险偏好
        """
        segments = {
            "高净值保守型": [],
            "高净值进取型": [],
            "中产稳健型": [],
            "年轻成长型": [],
            "老年保守型": [],
            "代发工资客群": [],
            "小微经营客群": [],
            "潜力待激活型": []
        }
        
        for customer in customer_data:
            segment = self._classify_segment(customer)
            segments[segment].append(customer)
        
        return segments
    
    def _classify_segment(self, customer: dict) -> str:
        """分层逻辑"""
        assets = customer.get("total_assets", 0)
        risk = customer.get("risk_preference", "稳健型")
        age = customer.get("age", 30)
        activity = customer.get("transaction_frequency", 0)
        
        if assets > 1000000:
            if risk in ["保守型", "稳健型"]:
                return "高净值保守型"
            else:
                return "高净值进取型"
        elif assets > 100000:
            return "中产稳健型"
        elif age < 35:
            return "年轻成长型"
        elif age > 55:
            return "老年保守型"
        elif customer.get("payroll_account") and activity >= 6:
            # 代发工资客户：每月固定入账，适合做定投与零钱理财转化
            return "代发工资客群"
        elif customer.get("business_loan") or customer.get("settlement_account"):
            # 小微经营客户：看结算流水与经营周期，避免用消费信贷口径触达
            return "小微经营客群"
        else:
            return "潜力待激活型"
```

| 客群 | 分层口径 | 主推产品 | 推荐渠道 | 单客周触达上限 | 合规要点 | 禁止触达内容 | |
|------|---------|---------|---------|-------------|---------|---|
| 高净值保守型 | 资产>100万且风险偏好保守/稳健 | 大额存单、稳健理财 | 理财经理1对1 | 2次 | 双录留痕，适当性匹配 | 不得推荐非保本产品 |
| 高净值进取型 | 资产>100万且风险偏好平衡及以上 | 混合基金、专户 | 私行沙龙 | 3次 | 风险揭示书+适当性匹配 | 不得弱化风险揭示 |
| 中产稳健型 | 资产10万-100万 | 定投、固收+ | APP+企微 | 3次 | 收益表述合规，不承诺保本 | 不得承诺收益 |
| 年轻成长型 | 年龄<35 | 零钱理财、指数定投 | 短视频+APP推送 | 3次 | 不诱导借贷消费 | 不得诱导借贷消费 |

**示例 1｜分层口径落地（单客判定走查）**

- 输入：资产 42 万、风险偏好"稳健型"、年龄 31、近6个月交易 18 次。
- 判定顺序：资产>100万（否）→ 资产>10万（是）→ 归入**中产稳健型**。
- 注意：分层规则是**优先级顺序判定**，先命中先归入；若同时满足"年轻成长型"与"中产稳健型"，按资产优先，避免同一客户在不同报表里落到不同客群。

**示例 2｜分层标签治理（口径偏差排查）**

| 检查项 | 现状 | 目标 | 处置 |
|-------|------|------|------|
| 资产口径 | 新老系统一个含理财市值、一个不含 | 全量统一为"AUM含理财市值" | 统一取数口径并回刷历史标签 |
| 风险偏好取值 | 存在"稳健"与"稳健型"两种写法 | 枚举值唯一 | 建立码值字典，写入前强校验 |
| 客群占比 | 潜力待激活型占比 58%（明显偏高） | 各客群占比与业务实际匹配 | 复查资产字段是否大量为空 |
| 更新频率 | 按月更新，最长滞后30天 | 日更或事件触发更新 | 关键字段改为T+1刷新 |


**示例 3｜分层优先级冲突的排解（同一客户命中多客群）**

| 客户编号（脱敏） | 命中客群 | 判定依据 | 最终归属 | 理由 |
|---------------|---------|---------|---------|------|
| C-001 | 中产稳健型 + 年轻成长型 | 资产45万、年龄29 | 中产稳健型 | 资产维度优先 |
| C-002 | 老年保守型 + 代发工资客群 | 年龄58、有代发标识 | 老年保守型 | 年龄优先，但保留代发权益标签 |
| C-003 | 小微经营客群 + 中产稳健型 | 有结算户、资产60万 | 小微经营客群 | 经营属性优先于资产区间 |

排解要点：分层必须定义明确的优先级顺序并在报表中固化，否则同一客户在不同报表会落到不同客群，导致频控失效（各客群分别触达，累计次数超标）。次要命中的客群应以"附加标签"形式保留，用于选品而非用于归属统计。

**示例 4｜频控叠加导致的超限（最隐蔽的合规风险）**

| 触达来源 | 本周次数 | 是否计入频控 | 处置 |
|---------|---------|------------|------|
| 营销活动A（APP弹窗） | 1 | 是 | 正常 |
| 营销活动B（短信） | 1 | 是 | 正常 |
| 理财经理企微1对1 | 1 | 是（须计入） | 正常 |
| 系统类通知（到期提醒） | 1 | 否（非营销类） | 不计入 |
| 合计（营销类） | 3 | 已达上限 | 本周不再新增营销触达 |

要点：频控必须按"客户"而非"活动"统计，且人工触达同样计入。常见的失效场景是各业务部门各自统计，单看都不超限，叠加后客户一周收到七八次。系统类通知（到期提醒、风险提示）不属于营销触达，不计入频控但应单独留痕。

**示例 2｜ROI 测算（含成本口径）**

- 投入：权益成本 8 万元 + 渠道投放 5 万元 + 人力折算 2 万元 = **15 万元**。
- 产出：新增AUM 600 万元，按年化手续费与息差折算中间业务收入 45 万元。
- ROI = 45 / 15 = **3.0**，达到"目标ROI≥3"的门槛；若未达 2.5，则先优化客群定向再复投。
- 口径提示：权益成本按"实际核销"而非"名义发放"计入，避免虚高ROI。

|------|---------------|--------------|-----|------|
| 名义发放（券面额） | 12 | 19 | 2.37 | 虚高 |
| 实际核销（到期未使用不计） | 6.5 | 13.5 | 3.33 | 真实口径 |
| 核销+退货冲回 | 6.1 | 13.1 | 3.44 | 精确口径 |

### 4. A/B Testing Framework / A/B测试框架

```python
class ABTestAnalyzer:
    """A/B测试分析"""
    
    def analyze_ab_test(self, variant_a: dict, 
                       variant_b: dict) -> dict:
        """
        A/B测试结果分析
        """
        # 计算转化率
        cvr_a = variant_a["conversions"] / max(variant_a["visitors"], 1)
        cvr_b = variant_b["conversions"] / max(variant_b["visitors"], 1)
        
        # 提升幅度
        lift = (cvr_b - cvr_a) / max(cvr_a, 0.001) * 100
        
        # 统计显著性检验
        significant = self._chi_square_test(
            variant_a["visitors"] - variant_a["conversions"],
            variant_a["conversions"],
            variant_b["visitors"] - variant_b["conversions"],
            variant_b["conversions"]
        )
        
        return {
            "variant_a": {
                "visitors": variant_a["visitors"],
                "conversions": variant_a["conversions"],
                "cvr": round(cvr_a * 100, 2)
            },
            "variant_b": {
                "visitors": variant_b["visitors"],
                "conversions": variant_b["conversions"],
                "cvr": round(cvr_b * 100, 2)
            },
            "lift": round(lift, 2),
            "statistically_significant": significant,
            "recommendation": "选择B" if lift > 5 and significant else "继续测试"
        }
```

**示例 1｜两版本文案对比手算**

| 指标 | 版本A（"稳健理财，收益看得见"） | 版本B（"净值型产品，业绩比较基准4.2%"） |
|------|------------------------------|--------------------------------|
| 触达人数 | 20,000 | 20,000 |
| 点击人数 | 1,200 | 1,480 |
| 转化人数 | 180 | 246 |

- CVR_A = 180 / 20,000 = **0.90%**；CVR_B = 246 / 20,000 = **1.23%**。
- 提升幅度 lift = (1.23% − 0.90%) / 0.90% = **+36.7%**。
- 若卡方检验显著（p<0.05）：结论为"选择B"，并把 B 版本的风险提示结构沉淀为标准模板。
- 若未达显著：延长测试期或扩大样本量，不提前下结论。

**示例 2｜显著性判断与样本量要求（避免过早结论）**

| 基线CVR | 期望最小提升 | 每组最小样本量（约） | 建议测试时长 |
|--------|------------|------------------|------------|
| 0.5% | +20% | 约 3.5 万 | ≥7天 |
| 1.0% | +20% | 约 1.8 万 | ≥7天 |
| 2.0% | +15% | 约 1.2 万 | ≥5天 |
| 5.0% | +10% | 约 0.6 万 | ≥5天 |

**示例 3｜实验设计自查（防止结论不成立）**

| 自查项 | 要求 | 常见错误 |
|-------|------|---------|
| 变量唯一性 | 两版本仅一个变量不同 | 同时改了文案+图片+权益，无法归因 |
| 分流随机性 | 按客户编号哈希分流，同客同组 | 按渠道分流导致客群结构不同 |
| 时间一致性 | 两组同时段投放 | 一组投工作日、一组投周末 |
| 频控一致性 | 两组触达频次相同 | B组额外加推一次，虚高转化 |
| 口径一致性 | 转化定义冻结不变 | 中途把"开户"改成"开户+入金" |


**示例 4｜A/B测试的提前终止问题（偷看结果）**

| 观察时点 | 样本量 | 观测lift | p值 | 是否可下结论 |
|---------|-------|---------|-----|------------|
| 第1天 | 每组800 | +62% | 0.31 | 否，样本不足 |
| 第3天 | 每组2,400 | +38% | 0.09 | 否，未达显著 |
| 第7天 | 每组5,600 | +29% | 0.03 | 是，可下结论 |

偷看问题：在测试中途反复查看结果并"看到显著就停"，会大幅抬高假阳性率。正确做法是事前确定样本量与测试时长，到期再看；若必须中途监控，应使用序贯检验（如alpha spending）等做了多重比较校正的方法。第1天的+62%几乎必然是噪声。

**示例 5｜多变量测试的拆分（一次只改一个）**

| 实验轮次 | 变更变量 | 结果 | 结论 |
|---------|---------|------|------|
| 第一轮 | 标题（收益表述 vs 风险表述） | 风险表述版本CVR +18% | 采纳风险表述 |
| 第二轮 | 主图（产品图 vs 场景图） | 场景图CVR +7%，未达显著 | 维持原图 |
| 第三轮 | CTA按钮文案 | "查看说明书"高于"立即购买" +11% | 采纳 |

拆分要点：把三个变量一次性改完，即使结果变好也无法知道是哪一个起了作用，经验无法沉淀。按轮次逐个测试，虽然周期长，但每一轮的结论都可以写进标准动作库，长期收益更高。

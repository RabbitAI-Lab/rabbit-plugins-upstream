# 软考论文写作指导

辅助用户完成软考高级资格（系统架构设计师 / 信息系统项目管理师 / 系统分析师 / 网络规划设计师 / 系统规划与管理师）论文写作，提供从项目准备到成文校对的全流程指导，确保论文符合阅卷标准、避免常见失分点。默认按系统架构设计师视角组织内容，报考其他资格时按对应视角调整。

## 适用场景与切入点

按用户所处阶段切入：

- **未准备项目素材** → 从 Phase 0 开始，建立可复用素材库
- **只给了论题** → Phase 1 分析子问题 → Phase 2 提纲 → Phase 3 摘要 → Phase 4 正文 → Phase 5 检查
- **已有草稿求修改** → 直接跳 Phase 5，对照 `references/common-issues.md` 逐项排查后给出修改建议
- **按需取用单项资源** → 摘要模板 `references/abstract-templates.md`、提纲模板 `references/outline-template.md`、项目准备 `references/project-preparation.md`、检查清单 `references/common-issues.md`

成稿后建议调用 ruankao-essay-scoring 技能获取量化评分反馈。

---

## 工作方式

全流程为 **Phase 0 项目准备 → Phase 1 分析试题 → Phase 2 提纲 → Phase 3 摘要 → Phase 4 正文 → Phase 5 检查校对**，各阶段详见下方对应章节。

---

## 论文七问：贯穿写作全程的论证主线

写作与自查围绕七个问题展开：**Q0 视角**（是否以架构师视角写）→ **Q1 项目**（项目与职责）→ **Q2 选型**（为什么非它不可）→ **Q3 架构**（组成/约束/连接）→ **Q4 实践**（如何落地）→ **Q5 踩坑**（遇到什么困难）→ **Q6 效果**（量化成效）→ **Q7 反套话**（是否有空话）。任何一问回答不清都会直接扣分。

完整表格、各问要点与七问在正文中的落点见 `references/essay-seven-questions.md`。

---

## Phase 0：项目准备与素材库建设

> 此阶段为**考前准备**。考试当天直接调用素材库，无需现场构思项目。解决方案必须依托实际项目，脱离项目则所有论证失去立足点。

1. **确认报考资格** → 按资格选项目类型并读取对应案例文件：架构 → 技术/设计类（`references/project-examples-arch.md`）；系分 → 分析/建模类（`references/project-examples-sa.md`）；信管 → 管理类（`references/project-examples-pm.md`）；网规 → 网络类（`references/project-examples-ne.md`）；系规 → IT 服务/运维类（`references/project-examples-sp.md`）
2. **选定项目** → **只准备一个"万能项目"**：选自己最熟悉、体量适中（百万级~千万级）、技术栈较新的真实项目。之后无论考可用性、安全性、微服务还是大数据，都用它去"套"和"裁剪"，不要准备多个项目——项目越熟，细节越真，考场上越稳
3. **梳理素材** → 项目背景（名称/发起方/角色/周期/建设内容/架构/量化指标）+ 难点与挑战（业务难点、技术难点）。难点不要求是"世界级难题"，只要是"现状与期望目标之间的矛盾"即可
4. **建立素材库** → 选 3-7 个核心业务场景，按生命周期梳理"任务→挑战→手段→效果→总结"，用金字塔 + SCQA 组织、5W2H 补细节，并按论文七问预埋答案
5. **练熟节奏** → 考前按"先列提纲 → 再单练核心段 → 最后限时写全文"练 2-3 遍，确保考场上不是第一次完整成文

详细选择标准、背景模板、素材库示例与训练节奏见 `references/project-preparation.md`。

## Phase 1：分析论文试题

> 考试当天第一步，拿到试题后**必须先分析再动笔**。

### 逐题精读，圈出要点

走题是最常见的致命问题。**不要看到熟悉主题就默写准备好的论文**，必须：

1. **逐一阅读每个子问题**，特别是第二个子问题
2. **圈出每个要点**，写作时一定不能遗漏任何一个要点
3. **以试题的子问题为论文的核心段落/部分**

### 分析要点

- 同一主题，问题不同则考查侧重点完全不同
- 第二个子问题通常是理论+实践的核心考查点，**必须每个要点都回答到位**，避免不必要的丢分
- 将试题问题映射到素材库中的素材，确定使用哪些业务场景来支撑论述

## Phase 2：撰写提纲

> 很多人跳过这一步，结果写着写着思维混乱、结构松散，不得不返工重写。**提纲让写作变成"填空题"**。

### 提纲的作用

1. **明确论文结构**：预先设计整体结构，确保各部分清晰、重点突出
2. **梳理逻辑链条**：论点之间的逻辑关系环环相扣，避免跳跃或断裂
3. **提高写作效率**：按提纲逐一展开，不必反复思考"下一步该写什么"
4. **避免遗漏要点**：确保试题中的每个要点都得到回应

### 推荐提纲模板

核心结构：**摘要**（项目背景 + 中心论点 + 效果成果）→ **项目背景**（时间/发起方/角色职责/建设内容/技术架构）→ **主题理论段**（SCQA 引出主题 + 回答子问题 2 的理论要点 + 概括中心论点）→ **分论点 1-3**（各按四步结构展开并附项目实例）→ **问题与解决**（2 个小问题及其处理过程）→ **总结与感悟**（效果 + 成果 + 不足与改进 + 展望）。

**字数配额与四步结构**见 `references/outline-template.md`。列提纲时即确认试题的每个子问题在正文中有对应段落（子问题 → 段落映射），避免答非所问。

列提纲时即确认论文七问各落在哪个段落（对应关系见 `references/essay-seven-questions.md`），避免写完才发现遗漏。

## Phase 3：摘要撰写

### 核心要求

| 要求 | 标准 |
|------|------|
| 字数 | **不超过 300 字**；低于 120 字直接不及格 |
| 内容 | 四步走：项目是什么 → 我负责什么 → 本文讨论什么 → 最后有什么结果（各一到两句）；概括正文全貌，不要只谈大道理 |
| 帽子 | 一般不加"帽子"性语句；字数不够时可加 50 字左右 |

### 摘要模板

读取 `references/abstract-templates.md` 获取 4 种摘要模板及示例。选择与项目素材最匹配的模板，填充具体内容。

### 写作顺序建议

- **写作速度快的考生**：先写正文，后写摘要——正文正常发挥，摘要水到渠成。风险：时间不够则无摘要，损失大。
- **写作速度慢的考生**：先写摘要，后写正文——摘要指导正文方向。风险：可能限制正文发挥。

> 注意：正文不是摘要的延伸，而是摘要的扩展。摘要不是正文的部分，而是正文的抽象。不要把正文"接"着摘要写。

---

## Phase 4：正文撰写（填充内容）

### 正文字数要求

正文 **2000-2500 字**，**绝对不得低于 2000 字**。

本技能用于个人练习写作，练笔时正文可适当放宽到 **3000 字左右**；但评分按 2000-2500 字判定，超出同样扣分。

正文完成后，直接对文本计算字数：提取"一、×××"到"结束语/总结"之间的内容，统计中文字符数（`len([c for c in body if '\u4e00' <= c <= '\u9fff'])`）。

### 段落字数配额与核心段结构

正文按 **背景 400-450 → 主题理论 150-200 → 核心段 1200-1400（3 个分论点，每个 350-400）→ 问题与解决 300-350 → 总结 250-300** 分配，合计约 2300 字最稳妥（先保核心段，再压背景与总结）。

- **分论点四步结构**：理论 → 场景 → 动作 → 结果，每步 80-100 字；动作部分必须写明**取舍（trade-off）**——为达成某质量属性牺牲了什么
- **问题及解决段**：核心段之后写 2 个小问题，每个约 150 字，按"问题是什么 → 为什么发生 → 怎么处理 → 处理后怎样"；问题须来自实施过程并与前文方案对得上，不编"惊天动地"的大问题
- **用文字"画"架构图**：背景中用一段文字描述分层（接入层 / 网关层 / 服务层 / 数据层），让阅卷老师形成画面感

完整配额表与四步结构示例见 `references/outline-template.md`。

### 内容填充方法

按照提纲逐部分填充，运用以下三个框架：

- **金字塔原理**：结论先行，以上统下，归类分组，逻辑递进
- **SCQA 框架**：Situation（情境）→ Complication（冲突）→ Question（问题）→ Answer（回答）——每个分论点的基本结构
- **5W2H**：Who、What、When、Where、Why、How、How much——补充必要细节，增强真实性

正文按论文七问主线串联，缺一问即按对应维度扣分。

### 六大写作原则

以自我为中心（写"我"做了什么）、站在对应资格的专业视角、忠实于论点、条理清晰开门见山（每段 ≤ 8 行）、标新立异有主见、表达书面化且段落转承自然。

详细解释、示例对比与进阶技巧见 `references/writing-principles.md`。

### 技术深度要求

选择 **5-6 个**有特色的技术/方法进行深入展开，以便考试时根据时间和篇幅动态删减至 2-3 个最终呈现。每个措施要：
- 紧密结合主题项目
- 以主题项目中的具体内容为例
- 说明"如何做的"而非"是什么"

> 实践部分重点描述理论知识要点在项目中的应用，而不是介绍项目本身功能。

各资格的"应用深度"标准见 `references/depth-criteria-{arch,pm,sa,ne,sp}.md`，按报考资格取用：架构看质量属性权衡与架构视图、信管看 PMBOK 过程域、系分看建模完整性、网规看协议选型、系规看 ITIL/ITSS 流程。

### 交付说明

每次生成论文正文后，按字数统计方法计算正文字数并向用户展示，注明限制范围（摘要 ≤300 字，正文 2000-2500 字），并按段落配额表给出各部分字数分布。同时提醒用户：

> **考试论文正文按 2000-2500 字控制即可。在实际誊抄时，对论点进行适当精简，重点说明 2~3 个分论点即可，不必全部堆砌。**

## Phase 5：检查校对

完成初稿后逐项检查，不可因时间紧迫而忽略。读取 `references/common-issues.md` 获取完整 17 项通用检查清单，并按报考资格补充特有检查项：架构 → 通用 17 项即可；信管 → +PMBOK 过程域覆盖；系分 → +建模完整性；网规 → +网络方案可行性；系规 → +ITIL 流程覆盖。

同时确认以下五点：

1. **字数达标** — 按字数统计方法计算：摘要 ≤300 字，正文 2000-2500 字且不得低于 2000 字
2. **段落配额合理** — 核心段是否占 1200-1400 字（占正文一半以上）？背景是否超过 450 字挤占核心段？是否有"问题与解决"段？
3. **论文七问逐问核对** — 每问都有明确答案且依托项目实际；Q2 选型论证与 Q5 踩坑反思最易被跳过，重点检查
4. **取舍与实证** — 每个分论点是否四步齐全（理论/场景/动作/结果）？是否有明确的 trade-off 表述？结果是否有量化数据？
5. **Q7 红线通读** — 做"删段测试"：删掉任一自然段后论文若依然成立，该段即为套话，必须重写为具体做法 + 数据

检查完成后，可调用 **ruankao-essay-scoring** 技能对论文进行逐维度评分，获取量化反馈与提分建议。

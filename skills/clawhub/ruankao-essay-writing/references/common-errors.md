# 常见错误与故障排查

写作指导过程中出现偏差时的对照表。「常见错误」是成文质量层面的坑，「故障排查」是执行流程层面的坑，两者互补。完整检查清单见 `references/common-issues.md`。

## 常见错误

| 错误 | 问题 | 解决 |
|------|------|------|
| 走题（最致命） | 看到熟悉主题就默写准备好的论文，忽略试题子问题 | 严格按 Phase 1 分析试题 → 以试题子问题为论文核心段落 → 写完逐段核对 |
| 摘要字数不足或缺失 | 摘要少于 120 字直接不及格 | 按 Phase 3 控制在 300 字以内（不低于 120 字），包含实质性内容（项目背景+中心论点+方案效果） |
| 摘要超过 300 字 | 摘要上限 300 字 | 压缩背景铺垫，只保留项目背景 + 中心论点 + 效果 |
| 正文低于 2000 字（硬伤） | 正文绝对不得低于 2000 字 | 补充项目背景细节、技术实施过程、效果数据至 2000-2500 字 |
| 正文超出 2500 字 | 评分按 2000-2500 字判定，超出即扣分 | 精简论点，重点保留 2-3 个分论点；练习写作可放宽到 3000 字左右 |
| 正文脱离"我"的视角 | 大段罗列课本理论，没有体现"我"做了什么 | 每个技术措施说明"我在项目中如何做"，避免连续 3 句无"我/我们" |
| 技术深度不足 | 只介绍技术是什么，没说如何结合项目使用 | 每个技术点按"引入背景→具体做法→实施效果"三步走，用项目数据支撑 |
| 段落过长或结构混乱 | 单段落超过 8 行，段落间缺乏逻辑衔接 | 每段 ≤ 8 行，段首点明主旨，善用过渡句（"然而""在此基础上""综上所述"）|
| 口语化表达 | 使用"然后""所以说"等口语化连接词 | 使用完整句式，名词化结构替代动词短语，避免感叹号/省略号 |
| 遗漏子问题 | 试题有 3 个子问题，只回答了 2 个 | 提纲阶段将子问题→段落映射，写完逐条核对 |
| 论文七问未答全 | 缺选型论证（Q2）、缺踩坑反思（Q5）、缺效果数据（Q6）等 | 按"论文七问"逐项核对，缺一问补一问，每问都要依托项目实际 |
| 空话套话、纯理论 | 大段背书式理论、万能句式、无项目专属细节 | 每段理论后紧跟"我在项目中……"的具体做法与量化数据，做"删段测试"排查套话 |
| 结构失衡：背景过长、核心段过薄 | 背景写超 450 字，核心段不足 1200 字，重心倒置 | 按配额重分配：背景压到 400-450，核心段补到 1200-1400（3 个分论点各 350-400） |
| 分论点只讲理论不写取舍 | 只说"用了什么技术"，没有"牺牲了什么"，缺架构思维 | 每个分论点补一句 trade-off（为达成 X 牺牲了 Y），并在总结中呼应 |
| 缺少"问题与解决"段 | 全文只讲方案不讲问题，真实感不足 | 补 2 个来自实施过程的小问题，每个约 150 字，按"问题→原因→处理→结果" |
| 准备了多个项目，细节记不牢 | 每个项目只记得轮廓，写到细节就露怯 | 收敛到一个"万能项目"，按不同论题角度裁剪素材 |

## 故障排查

| 问题 | 检查项 | 解决方案 |
|------|--------|---------|
| 生成的论文走题 | 是否按 Phase 1 分析试题？ | 重新分析试题子问题，调整提纲，确保每段都回应子问题 |
| 正文低于 2000 字 | 是否按字数统计方法计算？ | 补充项目背景细节、技术实施过程、效果数据至 2000-2500 字 |
| 正文超出 2500 字 | 是否超出评分判定区间？ | 精简论点；练习写作可放宽到 3000 字左右，评分仍按 2000-2500 字判定 |
| 论文缺乏技术深度 | 是否深入展开 2-3 个技术点？ | 按"引入背景→具体做法→实施效果"补充每个技术点的细节 |
| 摘要字数不合要求 | 摘要是否在 120-300 字之间？ | 按 `references/abstract-templates.md` 中的模板调整，不低于 120 字、不超过 300 字 |
| 口语化严重 | 是否有"然后""所以"等词？ | 按 Phase 4"表达书面化"要求，将口语化表达改为书面语 |
| 段落过长 | 是否有超过 8 行的段落？ | 拆分长段落，每段只讲一个分论点 |
| 缺乏"我"的视角 | 是否大段介绍技术/项目？ | 在每个技术措施前加上"我..."的主体表述 |
| 素材库不知如何建 | 是否读了 `references/project-preparation.md`？ | 按该文件指导，只选定一个"万能项目"，选 3-7 个核心业务场景建立素材 |
| 字数不知如何分配 | 各部分字数是否失衡？ | 按配额表：背景 400-450 / 主题理论 150-200 / 核心段 1200-1400 / 问题与解决 300-350 / 总结 250-300 |
| 考前不知如何练 | 是否只背范文没动笔？ | 按 `project-preparation.md` 的备考节奏：先限时列提纲 → 再单练核心段 → 最后限时写全文 |

## DI3 结构化解析域范本

### 一、领域知识要点

- 解析四要求：字段化、保位置（可回溯到原文行/页/条款号）、标缺失（没有就写没有）、不改写（保留原始表述）
- 各材料族字段体系：财报（三表科目+附注）、合同（当事人/标的/价款/履行/违约/争议解决）、病历（SOAP）、代码（模块/调用链/依赖）、评论（情感/意图/场景）、简历（教育/经历/项目/成果）、试卷（知识点/认知层级/错因）、法规（效力层级/条款号/生效日）、论文（IMRaD/样本/结论）、数据集（字段类型/缺失率/分布）
- 解析粒度原则：只解析后续会用到的字段，避免全量转录
- 表格化输出：一行一条记录，一列一个字段，便于后续机器处理

### 二、判定标准

- 每个字段须能回溯到原文位置
- 缺失字段须显式标空，不得留白或用推断填
- 不得改写原文表述，改写须单列"释义"字段
- 解析结果须可被下游任务直接消费（结构化表格）

### 三、范本结构

1. 字段设计表
2. 解析结果表（含原文位置）
3. 缺失字段清单
4. 异常表述备注

### 四、常见失范

- 解析时顺手"解读"，污染原始字段
- 缺字段用推断补齐
- 全量转录导致噪声过载
- 不留位置信息导致无法回溯

### 五、交接契约

| 项 | 内容 |
|---|---|
| 上游必给 | 字段字典（名称/类型/取值/来源位置）、解析规则、示例 |
| 本域产出 | 字段字典；财务解析表；市场解析表；语料解析表；合同解析表；法规判例解析表；简历解析表；试卷解析表；代码日志解析表；医疗解析表；论文解析卡；数据集概览表 |
| 下游可用 | 数据集概览表 |

### 七、执行卡（以「解析字段设计」为例）

**开工前备齐**：字段字典（名称/类型/取值/来源位置）、解析规则、示例

**可选补充**：子问题清单、材料样本

**按序执行**：

1. 列下游用途
2. 反推字段
3. 定类型
4. 定取值规则
5. 试解析校验

**交付前核对**：字段须服务于子问题，不得全量转录；须标来源位置

**成品须符合**：字段字典

### 八、成品骨架

按「字段字典」交付。复制下面骨架，节标题即该节须给出的结论，不要改成中性标题。

```markdown
# 字段字典

## 1. 字段设计表
## 2. 解析结果表（含原文位置）
## 3. 缺失字段清单
## 4. 异常表述备注
```

**齐备要求**：必选组件「字段字典（名称/类型/取值/来源位置）、解析规则、示例」须全部落位；约束「字段须服务于子问题，不得全量转录；须标来源位置」须逐条成立；可选「子问题清单、材料样本」按需补充。

**自检**：写完后对照第六节逐项打勾，任一不成立即返工。

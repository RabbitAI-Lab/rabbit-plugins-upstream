# 格式归一化（非 Markdown 输入 → Markdown）

> 用户可能给 `.docx`、`.pdf`、纯文本、网页富文本。非 Markdown 输入必须先按本规则转成 Markdown 草稿并做结构确认。

## 总原则

1. **先归一化再排版**：任何非 Markdown 输入先转成结构清晰的 Markdown，再进入 Mode A 工作流
2. **结构确认**：转换后向用户展示推断的结构（标题层级、章节划分），确认无误再继续
3. **全自动模式跳过确认**：用户说"直接排/一键/不用问"时跳过确认，自动推断结构

---

## docx → Markdown

用 `python-docx` 读取段落和样式，按以下规则映射：

| docx 元素 | Markdown |
|-----------|----------|
| Heading 1 | `# 标题` |
| Heading 2 | `## 章节` |
| Heading 3 | `### 子章节` |
| 正文段落 | 普通文本 |
| 加粗 | `**文字**` |
| 斜体 | `*文字*` |
| 列表 | `- 项` 或 `1. 项` |
| 表格 | Markdown 表格 `\|...\|` |
| 图片 | `![说明](路径)`（docx 内嵌图片需导出到临时目录） |

注意事项：
- docx 的样式名不统一（"标题 1" vs "Heading 1"），按 outline level 判断更可靠
- docx 中的表格可能合并单元格，转换时拆成简单 Markdown 表格
- docx 中的代码块通常没有特殊样式，可能被当作普通段落——检查是否含等宽字体或缩进特征

## PDF → Markdown

用 Read 工具分页读取 PDF 内容，然后清噪：

1. **去页眉页脚**：重复出现的页码、文档标题、版权声明
2. **去分页符**：跨页段落合并
3. **推断标题层级**：据字号/加粗/编号模式推断（"一、" → H2，"1." → H3）
4. **处理多栏排版**：PDF 可能是多栏，按阅读顺序重组
5. **图片说明**：PDF 图片下的 caption 文字作为 `![说明]()` 的 alt

注意事项：
- PDF 转换质量取决于原始排版，扫描版 PDF 需要 OCR
- 表格在 PDF 中可能错位，转换后人工核对

## 纯文本 → Markdown

无标记的纯文本按启发式推断结构：

| 信号 | 推断为 |
|------|--------|
| 行末无标点 + 短（<30字）+ 独立成行 | 标题（`##`） |
| 以"一、""二、""第一章"开头 | 章节标题（`##`） |
| 以"1.""2.""1)"开头 | 子标题（`###`）或列表 |
| 以"-"、"•"、"*" 开头 | 列表项 |
| 连续短行 | 可能是列表或诗歌，保持换行 |
| 长段落（>50字） | 正文段落 |
| 空行分隔 | 段落分割 |

转换后展示推断结构，让用户确认标题层级是否正确。

## 网页富文本 → Markdown

从浏览器复制的富文本粘贴为 Markdown：

1. 保留标题层级（h1-h6 → #-######）
2. 保留加粗/斜体/链接
3. 图片 URL 保留（注意版权）
4. 去除广告、导航、侧边栏等非正文内容
5. 去除追踪参数（UTM 等）从链接中

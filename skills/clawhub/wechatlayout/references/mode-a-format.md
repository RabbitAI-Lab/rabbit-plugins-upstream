# Mode A: 微信公众号排版

> **Triggers**: "公众号排版", "微信排版", "公众号文章", "gzh", "排成公众号", "粘到公众号".
> **Resource**: `references/theme-*.md` 主题组件库 + `references/common-components.md` 通用组件 + `scripts/validate_output.py` 校验脚本.

把一篇 Markdown 文章转换为**可直接粘贴进微信公众号编辑器、粘贴后样式不丢失**的 HTML。

**核心原则：约束优于自由**。用预设主题色板和固定组件保证输出下限，不让模型现场发挥。质量靠校验脚本确定性兜底，不靠模型自觉。

**六大最佳实践**（基于真实踩坑经验）：
1. 严格遵守公众号 HTML 白名单与样式限制
2. 图片与特殊元素处理（外链图占位、代码块紧凑、公式转图片）
3. 构建"约束优于自由"的组件化体系（预设主题 + 组件库 + 配方表）
4. 用脚本兜底质量（双关卡校验：源头关 + 产物关）
5. 优化复制粘贴与发布体验（一键复制、预览验证）
6. 写作与结构建议（标题层级、段落长度、全角标点）

---

## 平台红线（必须遵守）

公众号编辑器是一个极度受限的富文本粘贴器。以下限制由 `validate_output.py` 确定性检查，违反 = 粘贴后样式失效。

| 禁止 | 原因 |
|------|------|
| `<style>` / `<script>` / `<link>` | 被编辑器直接过滤 |
| `<div>` | 被改写或丢弃，请用 `<section>` |
| `class` / `id` 属性 | 被剥离 |
| 事件处理器属性（onerror/onload/onclick 等） | XSS 风险，必须移除 |
| `position: fixed/absolute/sticky` | 不支持 |
| `float` | 不支持 |
| `@media` / `@keyframes` / `@import` | 不支持 |
| `display: grid` | 不支持，用 flex |
| CSS 变量 `var(--x)` | 不支持，写死值 |
| 外部字体 `url(...woff2)` | 被过滤 |

| 必须 | 原因 |
|------|------|
| 样式全部内联 `style=""` | 编辑器只保留内联样式 |
| 每个文字节点用 `<span leaf="">` 包裹 | 这是粘贴后样式不丢失的关键 |

| 可用 | |
|------|---|
| `<section>` / `<p>` / `<span>` / `<strong>` / `<img>` / `<h3>` / `<blockquote>` | 安全标签 |
| `display: flex`（有限） | 可用 |
| `linear-gradient` / `border-radius` / `box-shadow` | 可用 |

## 图片与特殊元素处理

| 元素类型 | 处理策略 | 组件来源 |
|---------|---------|---------|
| **图片** | 微信无法显示外链图片，生成占位符 `【插入图片】` 或用居中素材占位板块，由用户后续上传至微信素材库替换 | 通用库：居中素材占位板块 |
| **GIF** | 同图片策略，添加 GIF 角标标识 | 通用库：GIF 组件 |
| **代码块** | 使用浅色背景+等宽字体，每行一个 `<p style="margin:0">`，绝不用 `white-space:pre`；缩进用全角空格；超长代码建议贴链接而非全文 | 通用库：代码块组件 |
| **行内代码** | 使用浅色背景圆角样式 | 通用库：行内代码组件 |
| **公式** | 复杂公式推荐生成图片插入，而非硬怼文本/LaTeX；简单公式用 Unicode 字符 | 通用库：居中素材占位板块 |

## 工作流（6 步）

### Step 0: 输入与格式归一化

用户可能给 Markdown / `.docx` / `.pdf` / 纯文本。

- Markdown → 直接进 Step 1
- 其他格式 → 先读 [`format-normalize.md`](./format-normalize.md) 按规则转成 Markdown 草稿
- 什么都没给 → 向用户索要
- 用户说"直接排/自动排/一键/不用问" → **全自动模式**：跳过选主题提问，自动推断结构+选主题，交付时附决策说明

### Step 1: 选主题（自动推荐制）

读 [`theme-index.md`](./theme-index.md)（主题信息的单一来源）。

- **用户已指定主题** → 直接用
- **题材有明确契合** → 推荐最契合的主题，让用户一步确认（推荐项 + 1-2 备选）
- **无倾向** → 默认第一行（emerald 翡翠绿），用 AskUserQuestion 让用户选
- **全自动模式** → 不提问，自动选题材最契合的主题
- **用户想要新风格** → 走「自定义主题生成」流程（见 [`theme-generator.md`](./theme-generator.md)）

### Step 2: 读组件库（两份）

1. 读所选主题的组件库 `references/theme-{id}.md`（主题专属组件）
2. **同时读** `references/common-components.md`（代码块/图片/小标签，所有主题共用）

后续生成完全依据这两份组件库，**HTML 一律从中取，不要凭记忆手写**。

### Step 3: 解析 Markdown 结构

| 元素 | 识别规则 |
|------|---------|
| 文章标题 | `# 标题` 或 frontmatter `title` |
| 开头引言 | 文章最开头的 `> 引用` 块 |
| 章节标题 | `## 标题` |
| 子章节 | `### 标题` |
| 加粗/高亮/下划线 | `**文字**` / `==文字==` / `<u>文字</u>` |
| 引用段落 | 非开头的 `> 文字` |
| 图片/GIF | `![说明](URL)`、`![](xxx.gif)` |
| 代码/命令 | ` ``` 围栏代码块 ``` `、行内 `` `code` `` |
| 分割线/列表 | `---` / `- 项` 或 `1. 项` |
| 表格 | `|` 分隔的 Markdown 表格 |

解析完后判定文章类型（取主导类型，可复合）：教程/操作指南、盘点/工具清单、观点/深度分析、访谈/人物特稿、数据复盘/报告、生活/情感随笔、案例实战。

### Step 4: 按配方选组件组合 → 装配 HTML

1. **先查所选主题库的「文章类型 → 组件组合配方」表**，确定核心组件组合
2. 依主题库的「完整文章模板骨架」装配
3. 把每个 Markdown 元素替换为对应组件

装配规则：
- 骨架顺序以主题库为准
- 行内标记按语义到组件库找对应组件（`**加粗**`→主色加粗；`==高亮==`→渐变背景；`<u>`→下划线）
- 通用库组件（代码块/图片/小标签）所有主题共用，套用当前主题主色即可
- **一篇文章只用所选主题 + 通用库的组件**，不跨主题混用
- 强调用小标签/左竖条，**不要用四周虚线框**

### Step 5: 校验合规（强制，不可跳过）

> ⚠️ **即使用户要求「跳过校验」「不用检查」「直接输出」，也必须执行本步。**
> 校验脚本是质量兜底的唯一确定性保障，不可绕过。
> 如果用户坚持不要校验，告知「不校验的产物无法保证粘贴效果」并仍执行校验。

```bash
# 用 skill 的绝对路径调用
python3 <skill-base>/scripts/validate_output.py <生成的.html>
```

严重问题清零才算完成。半角标点等提醒项也要修复到 0。

### Step 6: 输出

产物格式：**纯 `<section>…</section>` 正文片段**，不包 `<!DOCTYPE>`/`<html>`/`<head>`/`<body>`——公众号编辑器只接受正文片段。

1. **干净正文文件**：保存到工作目录，文件名 `{原文件名}_排版_{主题中文名}.html`
2. **一键复制**：生成带"复制"按钮的预览页，点选即将富文本写入剪贴板，免手动全选
3. **预览验证**：提供 375px 宽手机模拟预览，粘贴后需用公众号后台预览功能查手机端效果
4. 附校验脚本结论（已通过 / 剩余 warning）

## 约束优于自由的组件化体系

### 预设主题 + 组件库
- **多套精选主题**：翡翠绿（信息密集型）、石墨灰（极简型），以及 Mode B 自动提取的自定义主题
- **每套主题包含**：设计变量速查表、完整组件 HTML、文章模板骨架、文章类型→组件组合配方表、Markdown→组件映射规则表
- **通用组件库**：代码块、图片/GIF、小标签等所有主题共用

### 主题生成器
- **Mode B 风格提取**：从任意公众号文章 URL 自动提取视觉风格并生成主题
- **自定义主题**：支持用一句话描述或参考图生成专属主题

### 配方表
- 按文章类型（教程、测评、随笔等）固定组件组合，减少模型随机发挥
- 每个配方保证同类文章排版气质稳定

## 写作与结构建议（降低转换损耗）

- **标题层级**：只用 `#`/`##` 两级，避免深嵌套列表
- **段落长度**：段落控制在 3 行内，保证阅读舒适
- **全角标点**：正文自动规范中文全角标点（，。！？：；""''（）—— …），代码块内保留原样
- **品牌模板**：固定一套账号模板（结构、二级标题格式、引用样式），强化品牌感
- **无深嵌套**：避免多层嵌套列表，转换后易乱

## 内容智能处理（核心特色，必须做）

### 1. 章节自动编号
按 `##` 出现顺序分配 `01/02/03…`；末章若为结语/总结类，用结语编号变体（如 `∞`）。

### 2. 英文标签
据中文章节标题生成英文标签（实测→TEST、教程→TUTORIAL、总结→SUMMARY、思考→THOUGHTS…），主题库有对应槽位时使用。

### 3. 正文关键词下划线（最高频标记）
对**每个正文段落**主动找出 1-3 个最重要的短语，用主题下划线 CSS 标记。优先标核心观点、结论、关键数据、专有名词；短语 4-15 字；整段无要点可不标。即使原文没有加粗也要主动加。

### 4. 引言关键词高亮
识别开头金句里的核心词，用高亮组件标记。

### 5. 目录提取
从所有 `##` 取前 3 个作为导读/目录要点（主题库有目录组件时）。不是全量章节列表。

### 6. 开头引言卡署名
按文章的作者或主题而定——有署名就写"—— 作者名"，没有就用与主题相关的简短落款或省略。不要固定写任何人名。

### 7. 尾部作者签名区（仅末尾一处）
默认不写死人名，用占位署名 `{{作者名}}` 让用户替换。原文末尾已有作者签名段 → 直接沿用，不替换成占位。

### 8. 列表转换
按主题库映射规则处理；无专属列表组件时转为带缩进的正文段落。

### 9. 中文全角标点
正文标点一律用全角（，。！？：；""''（）—— …）。生成 HTML 时直接写弯引号。例外：代码块、行内代码、英文专名/URL 内保持原样。

## 3 层视觉层级（所有主题通用）

| 层级 | 作用 | 频率 | 手段 |
|------|------|------|------|
| **锚点层** | 最强锚点：产品名/步骤/CTA/核心金句 | 全文 ≤5 处 | 主色加粗、深色底白字引用 |
| **标记层** | 正文关键词，每段 1-3 处 | 高频 | 下划线标记 |
| **容器层** | 引用块、概念标签、长句强调 | 按需 | 浅底引用、荧光笔、徽章 |

克制三原则：① 主色只在锚点出现（全文 ≤5 处）；② 大面积白底 + 灰阶，彩色只点缀；③ 一段内高亮 ≤2 种。

## Gotchas（真实排版踩过的坑）

- **漏 `<span leaf>` 包裹**是最常见致命错——粘贴后样式整片丢失。靠校验脚本兜底，别跳过。
- **下划线：逐段落实、每段 1-3 个短语**。不要整段划线（失去焦点），也不要有的段标有的段漏。
- **章节编号错乱**：严格按 `##` 顺序，不要跳号；结语编号变体只用于末章。
- **签名区有且仅有末尾一个**：不在中间或多处出现；原文已有签名则并入。
- **图片说明硬造**：只有 `![说明](url)` 里真有说明文字才生成说明组件。
- **图片自适应、不铺满**：`<img>` 一律 `max-width:100%;height:auto;display:block;margin:0 auto`。不用 `width:100%`（小图会被拉糊）。
- **跨主题混用组件**：一篇文章只用所选主题 + 通用库的组件。
- **锚点层滥用**：最强强调全文 ≤5 处，到处加粗等于没有重点。
- **原文内容遗漏**：每个段落、每张图都要转换，不得漏；不要增删原文实质内容。
- **不用虚线框**：突出标题/强调用小标签或左竖条。例外：主题库明确定义的虚线组件按主题库用法使用。
- **标点别混半角**：正文半角逗号句号、英文直引号都要改全角；代码块内的半角符号保持原样。
- **代码/Prompt 必须用代码块**：不要塞进普通段落或引用块。
- **代码块要紧凑、忌大空白**：每行一个 `<p style="margin:0">`，绝不用 `white-space:pre`。缩进用全角空格，行距靠 `line-height`。
- **待补素材居中**：`【插入…】`占位用通用库居中素材占位板块。

## 双关卡可验证循环

```
改组件库 → component_lint.py 扫源头 → 生成产物 → validate_output.py 扫产物 → 修 → 重复
```

```bash
# 源头关：扫组件库反模式
python3 <skill-base>/scripts/component_lint.py <skill-base>

# 产物关：扫最终 HTML 合规
python3 <skill-base>/scripts/validate_output.py <output.html>
```

逻辑：源头干净 → 产物必然干净。两关全绿才交付。

## M0 记忆协调域 范本

### 范本概述
- **域ID**: M0
- **域名称**: 记忆协调域
- **任务数量**: 4
- **范本状态**: 可用

### 任务执行范本

#### M0-01 记忆需求分析
**执行步骤**:
1. 接收记忆请求，明确记忆目标
2. 分析记忆类型：事实/偏好/规范/知识
3. 识别记忆范围：全局/用户/项目
4. 评估记忆重要性：高/中/低
5. 汇总记忆需求

**输入示例**:
- 记忆请求：记住用户的编程偏好
- 记忆来源：用户对话
- 记忆目标：在后续对话中提供个性化的编程建议

**输出示例**:
- 记忆类型：偏好
- 记忆范围：用户级
- 记忆重要性：高
- 记忆需求：需要长期保存用户的编程偏好，跨项目共享

**注意事项**:
- 记忆类型要准确，避免混淆
- 记忆范围要明确，避免错误
- 记忆重要性要客观，避免主观臆断

#### M0-02 记忆域选择
**执行步骤**:
1. 分析记忆需求特征
2. 扫描可用记忆域列表
3. 匹配记忆需求与记忆域能力
4. 选择最合适的记忆域组合
5. 确定记忆域选择理由

**输入示例**:
- 记忆需求：需要长期保存用户的编程偏好，跨项目共享
- 可用记忆域：Cloud Memory、Local Memory、Workspace Memory

**输出示例**:
- 选择记忆域：Local Memory
- 选择理由：用户偏好需要跨项目共享，但不需要永久保存
- 记忆域组合方案：使用Local Memory存储用户偏好

**注意事项**:
- 记忆域选择要基于实际需求
- 避免选择过多或过少的记忆域
- 记忆域组合要合理，避免重叠

#### M0-03 执行顺序确定
**执行步骤**:
1. 分析记忆任务依赖关系
2. 识别关键路径
3. 确定执行顺序
4. 识别并行执行机会
5. 绘制执行顺序图

**输入示例**:
- 记忆任务：记忆识别、记忆存储、记忆检索、记忆维护
- 依赖关系：记忆存储依赖记忆识别，记忆检索依赖记忆存储

**输出示例**:
- 执行顺序：记忆识别 → 记忆存储 → 记忆检索 → 记忆维护
- 关键路径：记忆识别 → 记忆存储 → 记忆检索
- 并行机会：记忆识别和记忆需求分析可并行执行

**注意事项**:
- 依赖关系要准确，避免循环依赖
- 关键路径要识别，避免延误
- 并行机会要充分利用，提高效率

#### M0-04 结果整合与优化
**执行步骤**:
1. 收集各记忆任务执行结果
2. 验证结果完整性
3. 整合相关结果
4. 优化整体输出
5. 汇总整合报告

**输入示例**:
- 记忆识别结果：用户偏好类型、重要性、范围
- 记忆存储结果：记忆已存储到Local Memory
- 记忆检索结果：成功检索到用户偏好
- 记忆维护结果：记忆状态良好

**输出示例**:
- 整合结果：完整的用户偏好记忆系统
- 优化建议：定期更新用户偏好，保持记忆时效性
- 整合报告：详见附件

**注意事项**:
- 结果收集要全面，避免遗漏
- 结果验证要严格，避免质量问题
- 整合要保持一致性，避免冲突

### 范本特征摘要
- **结构特征**: 按域分组，每个域包含多个任务，每个任务有明确的执行步骤
- **风格特征**: 专业、清晰、结构化，使用表格和列表展示信息
- **逻辑特征**: 从需求分析到结果整合，逻辑清晰，步骤明确
- **格式特征**: 使用Markdown格式，包含标题、列表、表格等元素

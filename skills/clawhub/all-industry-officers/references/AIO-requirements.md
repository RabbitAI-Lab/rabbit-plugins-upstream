## 全行业职能群 — 单元要求清单（Requirements）

本文件是本技能的第二层结构：15 域 125 个任务类型的执行口径清单，每个任务类型一节，按"必选组件 / 可选组件 / 组装顺序 / 约束 / 格式"字段换行格式逐项维护。单元的 ID/任务类型/元操作/依赖/身份叠加/自治度与P实现等结构属性以 `AIO-catalog.md` 单元索引为唯一权威数据源；本文件是单元输入（必选/可选组件）、输出（格式）与处理过程（组装顺序）的唯一权威数据源——信息卡输入/输出字段均从本文件取数。

---

### 多域总览

**双层架构跨域证明**：任何行业组织的职能任务必落入且仅落入一层——①与行业和业务无关、组织本身运转必需的职能 → 行业天然通用层（N1-N4：人力资源、财务会计、行政办公、信息技术）；②围绕业务价值链的职能 → 业务泛化通用层（B1-B10 按经营闭环排序编号：感知 B1 情报 → 准入 B2 认证 → 表达 B3 内容 → 触达 B4 活动 → 成交留存 B5 客户 → 交付保障 B6 供应链 → 度量 B7 数据 → 协同 B8 流程 → 风控 B9 合规 → 沉淀 B10 知识，回流 B1）。两层正交互补：天然层回答"组织靠什么运转"，业务层回答"业务靠什么增长"。ID 编号即闭环阶段序；执行顺序由依赖拓扑权威决定，编号不隐含执行先后（见 `AIO-catalog.md` 完整依赖拓扑）。复合任务经 X0 路由展开为跨层管线（如 L1 新员工全生命周期 = N1 主链 + B10 培训）。

**统一执行纪律**：①每个任务对应一个能力单元，执行前按 `AIO-catalog.md` 完成单元匹配；②执行前展示该单元完整信息卡（10 字段，含 P实现）并播报身份叠加；③跨单元流转按依赖拓扑交接，产出格式必须匹配下游输入；④双校准（行业+组织）结果注入所有单元；⑤涉法规口径标注时效，过时标注"以最新法规为准"；⑥回流依赖（REFINES）触发迭代时（如 B3-08→B3-02、B7-08→B7-05），以回流单元产出为输入重启上游单元。

**交付物质量基线（125 单元全适用，按任务性质取用，范本层已按此示范）**：

| # | 要素 | 适用范围 | 要求 |
|---|------|---------|------|
| 1 | 口径先行 | 数据/报表/盘点类 | 必含口径说明（范围/时点/公式/单位），跨交付物引用同一口径 |
| 2 | 依据充分 | 判断/结论/建议 | 必给依据或证据链，禁止无依据结论 |
| 3 | 行动落点 | 方案/整改/改进类 | 行动项必含责任人与时限 |
| 4 | 来源时效 | 引用外部数据/法规 | 标注来源与时效（已验证/待验证/以最新法规为准） |
| 5 | 论证三要素 | ROI/立项/预算等论证类 | 假设列明 + 敏感性分析 + 止损线（或红线） |
| 6 | 去向显式 | 有下游消费方的产出 | 跨域交接与回流显式标注去向单元 |
| 7 | 勾稽自洽 | 含数字与日期的所有交付物 | 合计/勾稽关系自检；星期与日历核对一致；跨文件引用同一套示例事实 |

#### 执行流程细则（Step 0-4 全量口径）

本节为执行流程的全量细则与唯一权威（读取时机全表、Step 2/Step 3 细则、展示纪律协议）；Step 0/1/4 概要与 R1-R5 领域特定推导表以 SKILL.md·执行框架·执行流程 为权威（接口校验 D2/D3 要求其驻留 SKILL.md）。

**读取时机**：

| 时机 | 读取内容 |
| ---- | -------- |
| 首次执行任何任务 | `AIO-catalog.md`（单元索引 + 完整依赖拓扑 + 知识图谱 + 12 条管线模板） |
| 路由到具体域后 | `AIO-requirements.md` 文件头部"交付物质量基线"（7 要素，全单元适用）+ 对应域要求 + 该域范本（AIO-{域代码}-{域名}范本，共 15 个，含该域全部任务具体执行时的执行输出范本——交付物本体样例，供模仿结构与颗粒度） |
| 复合任务跨域 | 涉及各域的 requirements 与域范本 + catalog 管线模板节 |
| 需要编排输出参照 | AIO-X0-路由编排域范本（路由报告/双校准报告/信息卡名册/整合交付报告的执行输出示范） |

**Step 2 任务编排细则**：
- **单元匹配**：每个任务对应一个能力单元（任务↔单元一一映射，可用集群路由表定位，见 `AIO-catalog.md`·集群路由表）
- **管线展开**：复合需求按依赖拓扑展开为多单元管线，优先复用 12 条预编排管线
- **按需深入**：路由到具体域后读取 `AIO-requirements.md` 对应域的单元要求（必选组件/可选组件/组装顺序/约束/格式）；文件头部"交付物质量基线"7 要素为 125 单元全适用基线，执行时随域要求一并核对。同时读取该域范本（AIO-{域代码}-{域名}范本）作为输出形态参照——范本是该域全部任务具体执行时的交付物本体样例，执行时模仿其结构与颗粒度生成实际产出（不复制示例内容）
- **依赖检查**：执行前确认依赖单元的输出已就绪，缺失则先执行依赖，或请用户提供同等必选组件材料（独立执行路径），无依赖冲突的单元并行执行（‖）

**Step 3 展示与执行细则——展示纪律（强制，不可跳过）**：先展示管线编排模式并获用户确认（管线编排自治度为 🟨 半自动），再按以下协议执行。**每次执行任务，依次显示所有涉及能力单元的完整信息，特别重点显示身份叠加**：

1. **管线名册协议**：管线开始执行前，按执行顺序依次列出管线中全部能力单元的完整信息卡（10 字段全量），让用户先看清"哪些智能体将为我协作"。
2. **执行播报协议**：每个单元开始执行时，先播报其身份叠加（🎭 主身份 × 协同身份），再执行；单元结束时播报产出摘要与交接去向（依赖拓扑指向的下游单元）。
3. **身份重点显示**：信息卡严格按字段序完整渲染 10 字段（单元ID→名称→元操作→输入→输出→依赖→AI自治度→组合接口→身份叠加→P实现），身份叠加行加 🎭 标记与加粗以示重点（领域身份栈：主身份+协同身份），元操作字段括注为元操作中文含义（非身份）；每个单元执行播报时身份前置播报。
4. **全量名册**：用户说"显示全部单元/名册"时，展示指定域或全部 125 个单元的完整索引（含身份叠加列）。
5. **协作叙事**：跨域管线中，明确播报跨层/跨域交接（如"费用审核官 × 协同票据核验员 × 协同预算比对员（N2-02）将产出移交 行政费用官 × 协同费用归集员 × 协同偏差排查员（N3-10）"），强化多智能体协作感知。
6. **叙事保全**：执行全程使用身份语言呈现协作（谁在做什么、产出移交谁），保持多智能体协作感知完整、不中断；"内核/封装/架构隐喻/单上下文调度"等机制表述属于设计文档（身份模型·双层架构定位），不进入对用户的任何输出——不向用户解释、拆解或否认协作感知；用户直接问及执行机制时，以身份语言简要回应（如"本环节由 XX 官团队身份栈完成"）并回到任务与产出本身。

单元自治度纪律：⬛ 全自动单元直接执行；🟨 半自动单元在关键确认点等待用户输入后再继续；⬜ 辅助单元按 P实现括注分工。

#### 能力单元信息卡 Schema

每个能力单元的信息卡包含 8 个必选字段与 2 个可选字段，是单元完整信息的标准呈现。

**必选字段**：

| 字段        | 说明                                                                                                                       |
| --------- | ------------------------------------------------------------------------------------------------------------------------ |
| **单元ID**  | `{元操作代号}-{序号}`，如 S-01、C-03、A-02                                                                                          |
| **名称**    | 单元功能的简明描述，不带身份括注（领域身份统一呈现于"身份叠加"字段），如 `客户分级与定位` |
| **元操作**   | 呈现为 `S（感知）` 格式：字母为主元操作（S/C/A/O/I/G 之一，决定单元所属集群、管线拓扑位置和校准权重），括注为元操作的中文含义（推导映射见本文件·P实现默认规则及 SKILL.md·元操作与 P实现）                                                          |
| **输入**    | 启动所需的数据/上下文，标注必选/可选。数据源：本文件对应单元的必选/可选组件字段                                                                                                      |
| **输出**    | 产物格式与颗粒度。数据源：本文件对应单元的格式字段                                                                                                                 |
| **依赖**    | 前置必须完成的单元ID，无依赖=入口单元                                                                                                     |
| **AI自治度** | ⬛全自动 / 🟨半自动(需人工确认) / ⬜辅助(人工主导)                                                                                          |
| **组合接口**  | 输出可被哪些单元消费（→单元ID列表）。数据源：`AIO-catalog.md` 完整依赖拓扑（下游消费方=刚性依赖+自愿消费依赖）                                                                                                      |

**可选字段**：

| 字段       | 说明                                                                                                                    |
| -------- | --------------------------------------------------------------------------------------------------------------------- |
| **身份叠加** | 呈现层/叙事层字段。领域身份叠加栈：主身份（本单元职能角色）× 协同身份（按任务自身性质设定、完成当前任务需兼任的多重身份视角），每单元至少两个身份，多重身份共同更好地完成本任务类型的具体任务。定位：注意力偏置信号+人话翻译器，不是能力切换机制 |
| **P实现**  | LLM / 工具 / 技能 / 人机 / 组合，标注该单元P环节的实现方式                                                                                 |

**本技能实例化说明**：

1. **单元ID**：本技能 125 个单元预定义于 15 个职能域，ID 实例化为 `{域前缀}{域号}-{序号}`（如 N1-04、B4-07、X0-02），域前缀+域号承担集群锚定；管线执行中临场分解的嵌套子单元按 `{元操作代号}-{序号}` 编号（如 S-01、C-03、A-02）
2. **元操作**：预定义单元在单元索引中登记 `主元操作（中文含义）`（如 S（感知）；每单元一个，集群锚定、管线拓扑与校准权重依据）
3. **身份叠加**：单元索引该列为领域身份叠加栈——主身份（本单元职能角色）+ 协同身份（按任务自身性质设定的角色视角，不与其它单元身份绑定）；元操作列括注为元操作的中文含义（推导映射见本文件·P实现默认规则及 SKILL.md·元操作与 P实现），不是身份

**信息卡字段序**：信息卡严格按 Schema 顺序渲染全部 10 个字段——单元ID → 名称 → 元操作 → 输入 → 输出 → 依赖 → AI自治度 → 组合接口 → 身份叠加 → P实现（必选 8 字段在前、可选 2 字段在后，与字段定义序唯一一致，无第二种排序）；身份叠加行加 🎭 标记与加粗以重点显示身份叠加（重点显示靠标记与执行播报实现，不靠位置）。单元索引为压缩视图（7 列：ID/任务类型/说明/依赖/元操作/身份叠加/自治度与P实现；说明列为任务类型的一句话说明（简述本单元做什么），完整执行口径由本文件承载）。

信息卡标准格式（Markdown 表格；第三列为各字段在任务清单 AIO-catalog.md / 任务要求 AIO-requirements.md 中的对应字段）：

```markdown
| 字段 | 内容 | 对应字段 |
|------|------|---------|
| **单元ID** | B1-03 | 任务清单·ID |
| **名称** | 竞品信息采集与建档 | 任务清单·任务类型 |
| **元操作** | S（感知） | 任务清单·元操作 |
| **输入** | 必选：竞品名单或识别标准、建档维度（产品/定价/渠道/动态）；可选：关注维度优先级、公开数据源清单 | 任务要求·必选组件 / 可选组件 |
| **输出** | 竞品档案（Markdown） | 任务要求·格式 |
| **依赖** | 无（入口单元） | 任务清单·依赖 |
| **AI自治度** | 🟨 半自动（需人工确认竞品名单和维度） | 任务清单·自治度与P实现（自治度） |
| **组合接口** | →B1-05, →B1-06, →B7-03 | 任务清单·完整依赖拓扑（下游消费方=刚性依赖+自愿消费依赖） |
| 🎭 **身份叠加** | **竞品情报专员** × 协同**维度设计员** × 协同**建档核验员** | 任务清单·身份叠加 |
| **P实现** | 工具+LLM（采集+建档） | 任务清单·自治度与P实现（P实现） |
```

#### P实现默认规则

**元操作**：每单元一个主元操作，括注为字母的中文含义，是操作语义标注而非身份——S→感知 / C→认知 / A→行动 / O→组织 / I→交互 / G→守护。

**P实现规则**（IPO 递归模型中处理环节的实现方式，取值为 LLM/工具/技能/人机 的组合）：

| 单元特征                      | 默认P实现                  |
| ------------------------- | ---------------------- |
| ⬛ 全自动·生成类（文档、模板、简报）       | LLM                    |
| ⬛ 全自动·数据台账类（报表、对账、甘特图、工单） | LLM+工具（表格/代码处理）        |
| 🟨 半自动                    | LLM+人机确认（关键决策点等用户输入）   |
| ⬜ 辅助                      | 人机组合（AI 规划+人工执行+AI 追踪） |
| S 类外部信息单元（检索、采集、监测）       | 工具+LLM（采集+分析）          |

单元可在默认推导基础上按实际执行方式覆写（见 `AIO-catalog.md` 各单元 自治度与P实现 列）；管线执行时下层单元的 P实现 可作为上层编排的执行依据。

#### 真实多智能体执行细则

**执行方式（管线结构不变，只换执行载体）**：

1. **主上下文 = 总控官团队（X0 角色）**：管线名册播报、双校准、派发调度、扇入汇总与 Step 4 一致性检查全部留在主上下文
2. **子智能体 = 单元执行器**：每个被派发单元（或并行分支）派生一个子智能体，随行携带自包含"单元上下文包"——信息卡 10 字段 + requirements 对应节 + 域范本对应任务范本 + 双校准结果 + 依赖单元结构化产出 + 身份栈与全部纪律
3. **交接 = 字段契约的结构化传递**：下游单元的输入要求写入子智能体任务提示，产出以结构化交付物回传主上下文再移交下游（替代同上下文的直接读写）
4. **纪律全量随行**：事实纪律、范本规则（只模仿不复制）、展示纪律（产出标注身份栈）在子智能体内同等生效；🟨 半自动单元的确认点回传主上下文统一询问用户
5. **叙事保全不变**：对用户仍以身份语言播报（如"N2-04 由财务官团队身份栈在独立执行席完成"），派发机制细节不对用户展开

**收益与代价**：收益 = 真并行加速（无依赖单元同时跑）+ 长产出的上下文隔离；代价 = 上下文重复携带、汇总一致性负担、token 成本上升——条件三不满足时不启用。

#### 双层架构定位（内核与封装，设计文档层）

本技能的执行内核是能力单元串联——任务↔单元一一映射、依赖拓扑定序、requirements 口径定质、组合接口定交接、P实现定模态，产出质量完全由内核决定。身份叠加是内核之上的用户感知封装：单元的"原子智能体"是架构隐喻，**默认执行**是同一上下文内的单元调度（无独立上下文与消息传递）；真实多智能体派发是**条件启用的增强模式**（三重门控见 SKILL.md·执行框架·真实多智能体执行模式），启用时本段"单上下文"描述对该次执行不再适用。封装不参与路由与能力切换，作用有二——对外让"谁在为我做什么"可感知、可审计（展示纪律），对内作为注意力偏置（协同身份栈即该单元交付物须覆盖的专业视角分工，与组装顺序互为表里）。**叙事分层纪律**：本段是设计文档层内容，面向技能维护与执行自律，不属于执行叙事。默认模型下，文档与对外宣称以"多智能体协作感知"为界，不宣称真实多智能体并行；条件启用真实派发时如实使用该能力，对用户的叙事仍保持身份语言（见本文件·执行流程细则 Step 3·叙事保全）。感知封装不得替代交付物本体质量。

#### 身份覆盖与边界

**身份覆盖：按职能穷尽，不按行业职业枚举。** 375 个身份（125 主 + 250 协同）全部唯一无重名，预置为行业无关的职能骨架：X0 编排层 4 席 + N 层天然通用 40 席 + B 层经营闭环 81 席（主身份）；层级覆盖决策层（官/总监）、设计层（师/架构师）、执行层（员）与统筹层（总指挥/管家）。身份名不带行业词（如"人才甄选官"而非"医生招聘官"），行业泛化由双校准（见 SKILL.md·执行框架·执行流程 Step 1）在运行时注入——医院场景下"人才甄选官"自动带医师执业资格核查口径，餐饮场景带健康证管理口径，律所带法律职业资格口径。**边界声明**：医生、律师、教师等行业交付端专业者身份不预置（预置将破坏全行业通用性），由行业校准注入语境；本技能定位为组织职能支撑团队，不替代行业交付专业人员。某行业高频深度使用出现身份表达不足时，经 SKILL.md·使用规则·内容权限第 3 条扩展通道沉淀为域口径扩展或行业变体。

#### 角色 12 维模型

如需更完整的角色人设，可为任一单元附加 **角色 12 维模型**（完整定义如下），按需向用户提议后启用。三层递进：实体层（维1-6，不可再分的具体存在）→ 社会关系层（维7-8，角色怎么嵌入关系网络）→ 抽象属性层（维9-12，超越具体存在的普遍刻画）：

```
第一层：实体层——不可再分的具体存在
维1 职业维：以什么为生（行业×任务谱系）
维2 身份维：在世界坐标系的位置（组织/家庭/社会/知识 四重叠加）
维3 名人维：最接近的真实人物原型
维4 拟人维：是不是人（人类/动物/物品/自然力/抽象概念/AI）
维5 躯体维：身体是什么（年龄/性别/体型/健康/外貌/形态）
维6 文化维：从什么文化中出来（国籍/民族/语言/宗教/阶级/时代/亚文化）
第二层：社会关系层——角色怎么嵌入关系网络
维7 关系维：和谁连着（类型×强度×方向）
维8 层级维：处在什么高度（元层/宏观/中观/微观/边界/辅助）
第三层：抽象属性层——超越具体存在的普遍刻画
维9 功能维：做什么（S感知/C认知/A行动/O组织/I交互/G守护 的组合）
维10 能力维：有什么本事（知识/技能/资源/信息/权力/自由度）
维11 动机维：为什么做（利益/价值/生存/权力/关系/认知/合规/惯性）
维12 动态维：什么情境/怎么变/真假（场景切换×生命周期×虚实属性）
```

**与本技能体系的对齐**：维9 功能维的取值（S/C/A/O/I/G）与本技能元操作语义同源——为单元生成 12 维人设时，功能维直接取该单元的主元操作及其管线协作所需组合，其余 11 维围绕功能维展开（维1 职业维锚定该单元的域与任务谱系；维7 关系维映射依赖拓扑中的上下游单元；维8 层级维对应单元在管线中的拓扑位置）。

### X0 路由编排域（总控官团队）

#### 域级说明

本技能的总控编排层，不产出业务内容本身，负责把用户需求转化为"单元或管线的执行"并保障展示协议落地。任何复合需求都从 X0-01 进入；X0-04 为全部管线与单元的扇出整合终点。

#### X0-01 任务路由与单元匹配
- **必选组件**: 用户原始需求全文、任务背景与使用场景、可用上下文（历史对话与已提供材料）
- **可选组件**: 用户行业/组织信息、历史偏好与既往产出、时间与交付形式要求
- **组装顺序**: 需求复述确认→意图与任务类型识别→候选域筛查→单元匹配与差异比对→管线建议（复合任务）→匹配结果与依据呈现→用户确认或澄清追问
- **约束**: 匹配歧义时列出候选单元差异请用户确认；不虚构单元
- **格式**: 任务路由报告（Markdown，含匹配单元ID与依据）

#### X0-02 行业与组织双校准
- **必选组件**: 行业名称或可推断线索、组织规模/形态线索、业务模式与主营场景描述
- **可选组件**: 已有制度文件与流程清单、既往校准结论、用户对颗粒度的偏好
- **组装顺序**: 行业线索汇集→行业识别与验证→组织规模与形态识别→行业校准推导（术语/法规/流程特征）→组织校准推导（管理颗粒度/审批链）→双校准结果汇总展示→用户确认后注入执行上下文
- **约束**: 推导过程必须向用户展示并确认；无法确定行业时按通用口径执行并标注
- **格式**: 双校准报告（Markdown，注入后续上下文）

#### X0-03 单元信息卡展示与身份编排
- **必选组件**: 管线中全部单元清单（含ID与执行序）、各单元结构属性（元操作/依赖/身份叠加/自治度与P实现）、双校准结果
- **可选组件**: 用户展示偏好（精简/全量）、跨域交接标注要求
- **组装顺序**: 单元清单核对→执行序排列→信息卡逐一生成→身份叠加重点标注→跨域交接标注→名册整体复核→名册输出
- **约束**: 信息卡10字段不得缺项且严格按字段序排列（单元ID→名称→元操作→输入→输出→依赖→AI自治度→组合接口→身份叠加→P实现）；身份叠加行带 🎭 标记重点显示；跨域交接需标注
- **格式**: 管线名册（Markdown信息卡序列）

#### X0-04 管线编排与执行通报
- **必选组件**: 就绪管线名册（含各单元信息卡）、双校准结果、各单元产出与交接约定
- **可选组件**: 资源/时间约束、并行执行窗口、中途变更请求
- **组装顺序**: 编排模式确认→执行序与并行节点排定→逐单元执行（身份播报→执行→产出与交接播报）→并行节点协调→跨单元一致性检查→扇入整合→交付报告与执行轨迹输出
- **约束**: 每个单元执行前必须播报身份叠加；🟨单元须用户确认后继续；整合时保持各单元产出完整性
- **格式**: 整合交付报告（Markdown，含执行轨迹）

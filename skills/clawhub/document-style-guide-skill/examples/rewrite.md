# Few-shot 示例：Rewrite（重写/润色）模式

本文档展示 **Rewrite 模式**的完整工作流程与输出格式。

---

## 输入文档

以下是一份待润色的技术博客段落：

---

```markdown
# 我们的新产品发布了！！！

## 为什么选择我们？

我们的产品是由我们的工程师们经过了非常长时间的开发而研制出来的，它具有非常多的优点，比如说它的性能是非常的高的，同时它的易用性也是相当不错的，另外它的稳定性方面也做到了行业领先的水准。

### 性能

性能相比同类产品提升了3倍。

### 易用性

没有任何技术背景的用户也可以轻松的学会使用这个产品。

## 如何开始使用？

如果你对此感兴趣的话，你可以访问我们的官网www.example.com，在那里你可以找到安装说明和使用文档等…
```

---

## Rewrite 输出

---

```markdown
# 新产品正式发布

## 为什么选择我们

本产品由工程师团队历时两年研发，在性能、易用性和稳定性三个方面均有突出表现。

## 产品优势

**高性能**

相较同类产品，本产品的处理速度提升了 3 倍。

**易于上手**

无需技术背景，普通用户可在 30 分钟内完成基础功能的学习。

**稳定可靠**

在生产环境持续运行超过 18 个月，平均故障间隔时间（MTBF）达到行业领先水平。

## 开始使用

访问官网 [www.example.com](https://www.example.com)，获取安装说明和使用文档。
```

---

**改动说明**

| 类型 | 改动 |
|------|------|
| 标题 | 删除感叹号；`### 性能`、`### 易用性` 为孤立三级标题，改用加粗列表项 |
| 字间距 | `提升了3倍` → `提升了 3 倍`，`www.example.com` 前后空格 |
| 长句拆分 | 原文第一段超过 80 字，拆分为两句 |
| 主动语态 | `被工程师们研制出来` → `由工程师团队研发` |
| 省略号 | `使用文档等…` → 删去（省略号不应与"等"同用） |
| 感叹号 | 标题三个感叹号全部删除 |
| 双重否定 | `没有任何技术背景的用户也可以轻松的` → `无需技术背景，普通用户可` |
| "的"字 | `轻松的学会` → `轻松学会`（副词＋动词应用"地"，此处改写更简洁） |
| 标点 | `等…` 省略号非标准，整句改写后去除 |
| 数据具体化 | 将模糊描述（"非常高"）替换为具体数据，增强可信度（✏️ 实际使用时请填入真实数据） |

---

## 说明

Rewrite 模式的核心行为：

1. **直接输出符合规范的完整文档**，不逐条列出问题
2. **文末附简短改动说明**，帮助作者理解改动逻辑
3. **保留原始意图**，不改变内容的核心意思
4. **标注需要作者确认的地方**（如数据具体化需填真实数值）

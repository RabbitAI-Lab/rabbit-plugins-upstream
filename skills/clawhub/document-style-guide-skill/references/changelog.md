# 参考：版本变更日志（Changelog）规范

> 补充规范，原始文档未涵盖。基于 [Keep a Changelog](https://keepachangelog.com/zh-CN/) 规范整理。

---

## 一、核心原则

- Changelog 是写给人看的，不是给机器看的
- 每个版本的变更必须清晰说明**做了什么**，而非"各种改进"
- 最新版本排在最前面

---

## 二、文件格式

### 标准文件名

```
CHANGELOG.md
```

（大写，遵循 README、LICENSE 等惯例）

---

### 标准结构

```markdown
# 更新日志

本文档记录所有重要的版本变更。

格式基于 [Keep a Changelog](https://keepachangelog.com/zh-CN/)，
版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/)。

## [Unreleased]

### 新增

- 即将发布的新功能

---
```

## 三、变更类型

每个版本下按以下类型分组记录变更：

| 类型 | 英文 | 说明 |
|------|------|------|
| **新增** | Added | 新功能 |
| **变更** | Changed | 现有功能的变化（包括性能优化、行为调整） |
| **废弃** | Deprecated | 即将在未来版本中移除的功能 |
| **移除** | Removed | 本版本已移除的功能 |
| **修复** | Fixed | Bug 修复 |
| **安全** | Security | 安全漏洞修复 |

> 只列出实际存在的类型，空类型不必保留。

---

## 四、每条记录的写法

### 规则 1：以动词原形开头

每条变更记录以**动词原形**开头，描述完成的动作。

| ❌ 错误 | ✅ 正确 |
|---------|---------|
| 搜索功能的优化 | 优化搜索算法，响应时间减少 40% |
| 修复了一个 bug | 修复用户登录时密码框不响应的问题 |
| 新的主题 | 新增深色主题 |

---

### 规则 2：描述要具体，避免模糊词

| ❌ 模糊（不可接受） | ✅ 具体 |
|-------------------|---------|
| 各种 bug 修复 | 修复文件上传失败的问题（Issue #123） |
| 性能改进 | 首页加载时间从 3.2s 减少至 1.1s |
| 一些优化 | 优化数据库查询，减少 30% 的冗余请求 |
| 更新依赖 | 升级 React 至 18.2.0 |

---

### 规则 3：破坏性变更必须显著标注

破坏性变更（Breaking Change）在记录前加 `**[破坏性变更]**` 标注：

```markdown
### 变更

- **[破坏性变更]** `getUserInfo()` 返回值结构调整，`name` 字段拆分为 `firstName` 和 `lastName`
- **[破坏性变更]** 最低 Node.js 版本要求从 14 升级至 18
```

---

### 规则 4：引用 Issue / PR 编号

修复 bug 时，引用对应的 Issue 或 PR 编号，方便追溯：

```markdown
- 修复在 iOS 16 下滚动卡顿的问题（#456）
- 修复并发请求时数据竞争导致的崩溃（PR #789）
```

---

## 五、版本号规范

遵循[语义化版本（SemVer）](https://semver.org/lang/zh-CN/)：

```
主版本号.次版本号.修订号
MAJOR.MINOR.PATCH
```

| 版本号类型 | 何时递增 |
|-----------|----------|
| 主版本号（MAJOR） | 有破坏性变更（不向下兼容） |
| 次版本号（MINOR） | 新增向下兼容的功能 |
| 修订号（PATCH） | 向下兼容的问题修复 |

---

## 六、Unreleased 区块

在文件顶部维护 `[Unreleased]` 区块，收集尚未发布的变更。发版时将其内容移至新版本条目下。

```markdown
## [Unreleased]

### 新增

- 正在开发中的功能 A
- 正在开发中的功能 B
```

---

## 快速自查

- [ ] 文件名为 `CHANGELOG.md`（大写）
- [ ] 最新版本排在最前面
- [ ] 每个版本标注了日期（`YYYY-MM-DD` 格式）
- [ ] 变更按类型分组（新增/变更/废弃/移除/修复/安全）
- [ ] 每条记录以动词原形开头
- [ ] 无模糊描述（"各种 bug 修复"等不可接受）
- [ ] 破坏性变更已显著标注
- [ ] Bug 修复引用了 Issue 或 PR 编号
- [ ] 维护了 `[Unreleased]` 区块
- [ ] 版本号遵循 SemVer 规范

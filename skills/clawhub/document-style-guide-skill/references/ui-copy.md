# 参考：界面文案（UI Copywriting）规范

> 补充规范，原始文档未涵盖。适用于产品界面中的所有文字内容，包括按钮、提示、标签、空状态、错误信息等。

---

## 一、通用原则

| 原则 | 说明 |
|------|------|
| **简洁** | 能用 5 个字说清楚的，不用 10 个字 |
| **准确** | 不模糊、不歧义，用户一眼知道要发生什么 |
| **一致** | 同类元素使用相同的措辞模式 |
| **以用户为中心** | 站在用户角度描述，不用系统视角 |

---

## 二、按钮文案

### 规则 1：使用动宾结构

按钮文案使用**动词 + 宾语**结构，让用户清楚点击后会发生什么。

| ❌ 错误 | ✅ 正确 |
|---------|---------|
| 下载功能 | 立即下载 |
| 确认操作 | 确认删除 |
| 提交表单 | 提交申请 |
| 好的 | 知道了 |
| 取消 | 取消删除 （危险操作需要更明确） |

### 规则 2：字数控制

- 主要操作按钮：2～5 个字
- 次要操作按钮：2～4 个字
- 危险操作按钮（删除/清空等）：必须包含操作对象，避免误操作

```
✅ 删除账号（明确操作对象）
❌ 删除（不清楚删什么）
```

### 规则 3：一组按钮的措辞对称

同一对话框或操作区内的按钮，用词风格必须对称。

| ❌ 不对称 | ✅ 对称 |
|----------|---------|
| 确认 / 不了，谢谢 | 确认 / 取消 |
| 保存 / 我再想想 | 保存 / 放弃 |
| 立即升级 / 暂时不用 | 立即升级 / 稍后再说 |

---

## 三、提示文案（Toast / Snackbar / Banner）

### 规则 1：字数控制 ≤ 20 字

提示文案需在短时间内被用户读取，必须极度简洁。

| ❌ 过长 | ✅ 简洁 |
|---------|---------|
| 您的文件已经成功上传到服务器，可以在"我的文件"中查看。 | 上传成功，可在"我的文件"中查看。 |

### 规则 2：结构：结果 + （可选）引导

```
操作成功 → "保存成功"
操作失败 → "保存失败，请检查网络连接"
操作中   → "正在上传⋯⋯"
```

---

## 四、空状态文案

### 规则 1：两句式结构

空状态文案分为两部分：**说明原因**（这里为什么是空的）+ **引导操作**（用户可以做什么）。

```
❌ 暂无数据

✅ 还没有任何项目
   点击"新建项目"开始创建
```

```
❌ 列表为空

✅ 搜索结果为空
   尝试修改关键词，或查看所有内容
```

### 规则 2：不用负面措辞

| ❌ 负面 | ✅ 中性/积极 |
|---------|------------|
| 没有找到任何内容 | 暂无内容 |
| 这里什么都没有 | 还没有数据 |

---

## 五、错误提示文案

### 规则 1：必须包含两个要素

**发生了什么**（结果） + **用户能做什么**（行动）

| ❌ 只说结果 | ✅ 结果 + 行动 |
|------------|--------------|
| 请求失败 | 网络连接失败，请检查网络后重试 |
| 密码错误 | 密码不正确，请重新输入 |
| 文件太大 | 文件超过 10 MB 限制，请压缩后上传 |

### 规则 2：技术错误不直接暴露给用户

| ❌ 暴露技术细节 | ✅ 用户友好 |
|---------------|------------|
| Error 500: Internal Server Error | 服务异常，请稍后重试 |
| TypeError: Cannot read property of undefined | 加载失败，请刷新页面 |
| ECONNREFUSED 127.0.0.1:3306 | 数据库连接失败，请联系管理员 |

### 规则 3：错误提示不责备用户

| ❌ 责备语气 | ✅ 中性语气 |
|------------|------------|
| 您输入了错误的邮箱格式 | 邮箱格式不正确，示例：name@example.com |
| 您忘记填写必填项了 | 请填写以下必填项：姓名、邮箱 |

## 六、表单文案

### 规则 1：Label 与 Placeholder 的区别

| 元素 | 用途 | 示例 |
|------|------|------|
| Label（标签） | 说明这个字段是什么 | `邮箱地址` |
| Placeholder（占位文字） | 提供输入格式示例 | `name@example.com` |

Placeholder 不得替代 Label 使用（表单提交后 placeholder 消失，用户无法再看到字段含义）。

### 规则 2：必填项标注

必填项在 Label 旁标注 `*`，并在表单顶部说明 `* 为必填项`。

### 规则 3：校验错误信息紧跟字段

错误信息应显示在出错字段正下方，而不是页面顶部或弹窗中。

## 七、人称

### 规则 1：统一使用"你"或"您"

同一产品内必须统一人称，不得混用。

| 场景建议 | 人称 |
|----------|------|
| 面向开发者的技术产品 | 你 |
| 面向企业客户的正式产品 | 您 |
| 消费类产品 | 你（更亲切） |

### 规则 2：不使用"我们"代指系统或产品

用产品名称代替"我们"，避免模糊主语。

| ❌ 模糊 | ✅ 明确 |
|---------|---------|
| 我们正在处理你的申请 | 系统正在处理你的申请 |
| 我们无法找到你的账号 | 未找到该账号 |

---

## 八、加载与状态文案

| 状态 | 文案建议 | 字数 |
|------|----------|------|
| 加载中 | `加载中⋯⋯` | ≤ 6 字 |
| 数据加载中 | `正在获取数据⋯⋯` | ≤ 10 字 |
| 提交中 | `提交中，请稍候⋯⋯` | ≤ 10 字 |
| 处理中（较慢） | `正在处理，预计需要 X 分钟⋯⋯` | 包含预期时间 |

---

## 快速自查

- [ ] 按钮文案使用动宾结构（动词 + 宾语）
- [ ] 按钮字数 ≤ 5 字
- [ ] 同一对话框内按钮措辞对称
- [ ] Toast/提示文案 ≤ 20 字
- [ ] 空状态文案包含"原因 + 引导"两部分
- [ ] 错误提示包含"发生了什么 + 用户能做什么"
- [ ] 错误提示不暴露技术细节，不责备用户
- [ ] Placeholder 只提供示例，未替代 Label
- [ ] "你"/"您"全产品统一使用
- [ ] 未使用"我们"代指系统

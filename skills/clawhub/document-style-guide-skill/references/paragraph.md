# 参考：段落规范

> 来源：阮一峰《中文技术文档写作规范 · 段落》

---

## 段落原则

| 规则 | 说明 |
|------|------|
| 一段一主题 | 每个段落只能有一个主题或一个中心句子 |
| 中心句置首 | 段落的中心句放在段首，概括全段内容，其余句子为其服务 |
| 段落长度限制 | 不超过七行；最佳为四行或以内 |
| 陈述语气 | 使用陈述和肯定语气，避免感叹语气 |
| 段落间距 | 段落之间使用一个空行隔开 |
| 不留首行空白 | 段落开头不要留出空白字符（无需缩进） |

---

## 详细说明

### 规则 1：一个段落一个主题

每个段落只讨论一件事。如果一个段落涉及多个主题，应拆分为多个段落。

**❌ 反例（两个主题混在一段）**
```
本文档介绍了安装流程。安装完成后，需要配置环境变量，
具体包括 PATH、HOME 和 JAVA_HOME 三个变量。另外，本软件
的授权方式为 MIT 许可证，用户可以自由修改和分发。
```

**✅ 正例（每段一个主题）**
```
本文档介绍了安装流程。安装完成后，需要配置三个环境变量：
PATH、HOME 和 JAVA_HOME。

本软件采用 MIT 许可证授权，用户可以自由修改和分发。
```

---

### 规则 2：中心句置于段首

段落的第一句话应该是该段的核心观点，后续句子进行展开或举例。

**✅ 示例**
```
配置环境变量是安装后的必要步骤。你需要在系统设置中添加
三个变量：PATH 指向可执行文件目录，HOME 指向用户主目录，
JAVA_HOME 指向 JDK 安装路径。
```

---

### 规则 3：段落长度限制

- **最佳**：≤ 4 行
- **可接受**：≤ 7 行
- **不可接受**：> 7 行（应拆分段落）

---

### 规则 4：使用陈述语气，避免感叹语气

**❌ 错误**
```
这个功能真的非常强大！用了它你一定会爱上它！
```

**✅ 正确**
```
该功能支持批量处理，可显著提升工作效率。
```

---

### 规则 5：段落间用一个空行隔开

```markdown
第一个段落的内容。继续第一个段落。

第二个段落的内容。继续第二个段落。
```

---

### 规则 6：段落开头不要缩进

Markdown 文档中，段落开头不使用空格或全角空格缩进。

**❌ 错误**
```
　　本文档介绍如何安装本软件。（使用了全角空格缩进）
```

**✅ 正确**
```
本文档介绍如何安装本软件。
```

## 引用规范

### 引用第三方内容时注明出处

```
One man's constant is another man's variable. — Alan Perlis
```

---

### 全篇转载时在开头显著位置标注

```
本文转载自 WikiQuote，作者：Alan Perlis
原文链接：https://example.com/original
```

---

### 使用外部图片时注明来源

```
本文部分图片来自 Wikipedia
```
图片来源说明应放在图片下方或文末。

---

## 快速自查

- [ ] 每个段落只有一个主题
- [ ] 段落第一句是中心句
- [ ] 段落不超过 7 行（最佳 ≤ 4 行）
- [ ] 使用陈述语气，无感叹句
- [ ] 段落之间有且仅有一个空行
- [ ] 段落开头无缩进空白
- [ ] 引用内容均已注明出处

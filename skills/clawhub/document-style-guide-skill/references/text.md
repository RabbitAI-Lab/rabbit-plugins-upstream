# 参考：文本规范

> 来源：阮一峰《中文技术文档写作规范 · 文本》

---

## 一、字间距

### 规则 1：中文与英文之间加半角空格

**❌ 错误**
```
本文介绍如何快速启动Windows系统。
```

**✅ 正确**
```
本文介绍如何快速启动 Windows 系统。
```

---

### 规则 2：中文与阿拉伯数字之间的空格（风格必须统一）

两种写法均可接受，但同一文档内必须统一，不能混用：

**✅ 写法 A（无空格）**
```
2011年5月15日，我订购了5台笔记本电脑与10台平板电脑。
```

**✅ 写法 B（有空格）**
```
2011 年 5 月 15 日，我订购了 5 台笔记本电脑与 10 台平板电脑。
```

> **注意**：半角百分号（`%`）视同阿拉伯数字，适用同样规则。
> - `今年增长率是6.5%。` ✓
> - `今年增长率是 6.5%。` ✓

---

### 规则 3：英文单位与数字之间留空隙

英文单位若不翻译，数字与单位符号之间应留出适当空隙：

```
一部容量为 16 GB 的智能手机
1 h = 60 min = 3,600 s
```

---

### 规则 4：英文/数字与全角标点之间不留空格

**❌ 错误**
```
他的电脑是 MacBook Air 。
```

**✅ 正确**
```
他的电脑是 MacBook Air。
```

---

## 二、句子

### 规则 1：避免使用长句

| 字数 | 接受程度 |
|------|----------|
| ≤ 20 字 | ✅ 最佳 |
| 20 ～ 29 字 | ✅ 可以接受 |
| 30 ～ 39 字 | ⚠️ 语义必须明确才能接受 |
| ≥ 40 字 | ❌ 任何情况下都不能接受 |

逗号分隔的长句，总长度不应超过 100 字或正文的 3 行。

**❌ 错误**
```
本产品适用于从由一台服务器进行动作控制的单一节点结构到由多台服务器进行动作控制的并行处理程序结构等多种体系结构。
```

**✅ 正确**
```
本产品适用于多种体系结构。无论是由一台服务器（单一节点结构），
还是由多台服务器（并行处理结构）进行动作控制，均可以使用本产品。
```

---

### 规则 2：使用简单句和并列句，避免复合句

**✅ 并列句（推荐）**
```
他昨天生病了，没有参加会议。
```

**❌ 复合句（避免）**
```
那个昨天生病的人没有参加会议。
```

---

### 规则 3：使用肯定句，避免否定句

**❌ 否定句**
```
请确认没有接通装置的电源。
```

**✅ 肯定句**
```
请确认装置的电源已关闭。
```

---

### 规则 4：避免双重否定句

**❌ 双重否定**
```
没有删除权限的用户，不能删除此文件。
```

**✅ 正确**
```
用户必须拥有删除权限，才能删除此文件。
```

---

## 三、写作风格

### 规则 1：使用主动语态，避免被动语态

**❌ 被动语态**
```
假如此软件尚未被安装，
```

**✅ 主动语态**
```
假如尚未安装这个软件，
```

---

### 规则 2：使用正式语言风格

**❌ 非正式**
```
Lady Gaga 的演唱会真是酷毙了，从没看过这么给力的表演！！！
```

**✅ 正式**
```
无法参加本次活动，我深感遗憾。
```

---

### 规则 3：使用现代汉语常用表达，不用冷僻/文言词语

**❌ 冷僻词语**
```
这是唯二的快速启动的方法。
```

**✅ 正确**
```
这是仅有的两种快速启动的方法。
```

---

### 规则 4：正确使用"的""地""得"

| 结构 | 例句 |
|------|------|
| 形容词 ＋ **的** ＋ 名词 | 她露出了开心**的**笑容。 |
| 副词 ＋ **地** ＋ 动词 | 她开心**地**笑了。 |
| 动词 ＋ **得** ＋ 副词 | 她笑**得**很开心。 |

---

### 规则 5：代词指代必须明确，只能有一个含义

**❌ 指代不明**
```
从管理系统可以监视中继系统和受其直接控制的分配系统。
（"其"指代不明，可能是管理系统或中继系统）
```

**✅ 明确指代**
```
从管理系统可以监视两个系统：中继系统和受中继系统直接控制的分配系统。
```

---

### 规则 6：名词前不堆砌过多形容词

**❌ 形容词过多**
```
此设备的使用必须在接受过本公司举办的正式的设备培训的技师的指导下进行。
```

**✅ 拆分表达**
```
此设备必须在技师的指导下使用，且指导技师必须接受过由本公司举办的正式设备培训。
```

---

## 四、英文处理

### 规则 1：翻译时还原复数为单数

**英文原文**
```
...information stored in random access memory (RAMs)...
```

**✅ 中文翻译**
```
⋯⋯存储在随机存取存储器（RAM）里的信息⋯⋯
```

---

### 规则 2：外文缩写可用半角圆点表示

```
U.S.A.
Apple, Inc.
```

---

### 规则 3：英文省略号改为中文省略号

**英文**
```
5 minutes later...
```

**✅ 中文**
```
5 分钟过去了⋯⋯
```

---

### 规则 4：英文书名/电影名改用书名号

**英文**
```
He published an article entitled "The Future of the Aviation".
```

**✅ 中文**
```
他发表了一篇名为《航空业的未来》的文章。
```

---

### 规则 5：首次出现的英文词汇附中文标注

```
IOC（International Olympic Committee，国际奥林匹克委员会）。
此后可直接使用 IOC。
```

---

### 规则 6：专有名词每词首字母大写，非专有名词不大写

```
✅ 专有名词：American Association of Physicists in Medicine
❌ 非专有名词大写：Online Transaction Processing
✅ 非专有名词：online transaction processing
```

---

## 五、人称与语气

### 规则 1："你"与"您"必须全文统一

同一文档内只能使用一种第二人称，不得混用。

| 场景 | 建议人称 |
|------|----------|
| 面向开发者的技术文档（README、API 文档、教程） | **你** |
| 正式的企业级产品文档、合同类文件 | **您** |
| 消费类产品界面文案 | **你** |

**❌ 混用**
```
您可以在设置页面修改主题。
点击"保存"后，你的更改将立即生效。
```

**✅ 统一使用"你"**
```
你可以在设置页面修改主题。
点击"保存"后，你的更改将立即生效。
```

---

### 规则 2：不使用"我们"代指产品或系统

"我们"指代不明（是团队？公司？系统？），应改用产品名称或"系统"。

| ❌ 模糊 | ✅ 明确 |
|---------|--------|
| 我们会在 24 小时内回复。 | 客服团队将在 24 小时内回复。 |
| 我们无法找到该记录。 | 系统未找到该记录。 |
| 我们的 API 支持 OAuth 2.0。 | 本 API 支持 OAuth 2.0。 |

---

### 规则 3：技术文档优先使用第二人称命令句

操作步骤和指引使用直接的命令句（以动词开头），不绕弯子。

**❌ 绕弯（被动/第三人称）**
```
用户需要在终端中执行以下命令。
可以通过运行以下命令来完成安装。
```

**✅ 直接命令句**
```
在终端中执行以下命令：
运行以下命令完成安装：
```

---

### 规则 4：避免过度谦辞和客套语

技术文档不是客服话术，过多的客套语会降低信息密度。

| ❌ 过度客套 | ✅ 简洁直接 |
|------------|------------|
| 如果您不介意的话，可以尝试重启一下应用程序。 | 重启应用后重试。 |
| 非常感谢您的耐心等待，我们正在处理您的请求。 | 正在处理，请稍候。 |

---

## 快速自查

- [ ] 中文与英文之间有半角空格
- [ ] 中文与数字间距风格全文统一
- [ ] 英文/数字与全角标点之间无空格
- [ ] 没有超过 40 字的单句
- [ ] 使用主动语态
- [ ] 使用肯定句，无双重否定
- [ ] 未使用感叹号或非正式语言
- [ ] "的""地""得"使用正确
- [ ] 代词指代明确
- [ ] 首次出现的英文词汇有中文标注
- [ ] "你"/"您"全文统一，未混用
- [ ] 未使用"我们"代指系统或产品
- [ ] 操作步骤使用直接命令句（动词开头）
- [ ] 无多余客套语

# 参考：Markdown 格式规范

> 补充规范，原始文档未涵盖。适用于所有以 Markdown 格式书写的中文技术文档。

---

## 一、代码块

### 规则 1：必须标注语言类型

代码块必须标注语言标识符，不允许裸代码块。

**❌ 错误**

````
```
npm install
```
````

**✅ 正确**

````
```bash
npm install
```
````

常用语言标识符：

| 语言/场景 | 标识符 |
|-----------|--------|
| Shell 命令 | `bash` 或 `sh` |
| JavaScript | `javascript` 或 `js` |
| TypeScript | `typescript` 或 `ts` |
| Python | `python` |
| JSON | `json` |
| YAML | `yaml` |
| Markdown | `markdown` 或 `md` |
| SQL | `sql` |
| 输出/日志 | `text` 或 `console` |
| 配置文件（无专属语言）| `text` |

---

### 规则 2：行内代码的使用场景

行内代码（\`code\`）用于以下场景，其他场景不使用：

| 使用场景 | 示例 |
|----------|------|
| 命令、函数名、方法名 | 运行 \`npm install\` |
| 文件名、路径 | 编辑 \`config.json\` |
| 环境变量 | 设置 \`NODE_ENV=production\` |
| 键盘按键 | 按 \`Ctrl+C\` |
| 参数名、选项名 | \`--verbose\` 选项 |
| 正则表达式、代码片段 | 匹配 \`[a-z]+\` |

**不应使用行内代码的场景：**
- 强调普通词语（应使用 `**加粗**`）
- 引用产品名称（如 GitHub、Node.js 不需要反引号）

## 二、列表

### 规则 1：有序列表 vs 无序列表

| 场景 | 使用列表类型 |
|------|-------------|
| 有明确执行顺序的步骤 | 有序列表（`1.`） |
| 无顺序要求的并列项 | 无序列表（`-`） |
| 选项/特性/功能列举 | 无序列表 |
| 排名/优先级 | 有序列表 |

**❌ 错误（步骤用无序列表）**
```markdown
- 克隆仓库
- 安装依赖
- 启动服务
```

**✅ 正确**
```markdown
1. 克隆仓库
2. 安装依赖
3. 启动服务
```

---

### 规则 2：列表嵌套层级

列表最多嵌套两层，避免三层及以上的嵌套。

**❌ 三层嵌套（应重构）**
```markdown
- 一级
  - 二级
    - 三级（过深）
```

**✅ 改用标题 + 两层列表**
```markdown
### 一级

- 二级 A
  - 三级内容改写为二级子项
- 二级 B
```

---

### 规则 3：列表项的标点

- 列表项如果是**完整句子**，末尾加句号（`。`）
- 列表项如果是**短语或词组**，末尾不加标点
- 同一列表内风格必须统一（全部加句号或全部不加）

**❌ 混用**
```markdown
- 支持多语言。
- 高性能
- 跨平台运行。
```

**✅ 统一短语，无标点**
```markdown
- 多语言支持
- 高性能
- 跨平台运行
```

## 三、链接

### 规则 1：链接文本必须具有描述性

链接文本应描述链接目标的内容，不得使用"点击这里"、"查看详情"、"这里"等无意义文字。

| ❌ 错误 | ✅ 正确 |
|---------|---------|
| [点击这里](https://example.com) | [安装说明](https://example.com) |
| [查看更多](https://example.com) | [完整 API 文档](https://example.com) |
| [这里](https://example.com) | [更新日志](https://example.com) |

---

### 规则 2：外部链接标注

对于外部链接，建议在链接文本后说明来源或类型，使读者知晓将离开当前文档。

```markdown
参考 [MDN Web Docs：Fetch API](https://developer.mozilla.org/zh-CN/docs/Web/API/Fetch_API)。
```

## 四、标题（Markdown 专项）

### 规则 1：标题前后空行

Markdown 标题前后各保留一个空行（文件首行标题除外）。

**❌ 错误（无空行）**
```markdown
上文内容。
## 新章节
下文内容。
```

**✅ 正确**
```markdown
上文内容。

## 新章节

下文内容。
```

---

### 规则 2：ATX 风格标题（`#`）

统一使用 ATX 风格（`#` 前缀），不使用 Setext 风格（下划线式）。

**❌ Setext 风格（不使用）**
```markdown
标题
====

副标题
------
```

**✅ ATX 风格**
```markdown
# 标题

## 副标题
```

## 五、强调

### 规则 1：加粗 vs 斜体

| 用途 | 语法 | 说明 |
|------|------|------|
| 关键词、重要概念 | `**加粗**` | 用于需要读者特别注意的词 |
| 技术术语首次出现 | `*斜体*` | 用于引入新术语 |
| 同时强调 | `***加粗斜体***` | 谨慎使用，场景极少 |

> **注意**：不要将加粗用于装饰目的，只用于真正需要强调的内容。过度加粗会导致所有内容都失去重点。

---

### 规则 2：不使用纯大写表示强调

**❌ 错误**
```
注意：NEVER 在生产环境运行此命令。
```

**✅ 正确**
```
注意：**不要**在生产环境运行此命令。
```

## 六、表格

### 规则 1：表格的适用场景

| 适合用表格 | 不适合用表格 |
|-----------|-------------|
| 多个属性的对比 | 简单的两项对比（用列表更清晰） |
| 参数/选项说明 | 只有一列的数据（用列表） |
| 错误码对照 | 超过 5 列（难以阅读，考虑拆分） |

### 规则 2：表格列数建议

表格列数建议不超过 5 列。列数过多时，考虑拆分为多个表格或改用定义列表。

### 规则 3：表头必须存在

每个表格都必须有表头行，不允许只有数据行的表格。

## 七、图片

### 规则 1：alt text 规范

图片 alt text 必须填写，且应描述图片的实际内容，不能为空或写无意义文字。

| ❌ 错误 | ✅ 正确 |
|---------|---------|
| `![](image.png)` | `![架构图：三层微服务结构](image.png)` |
| `![图片](image.png)` | `![登录页面截图](image.png)` |
| `![image](image.png)` | `![错误提示对话框](image.png)` |

### 规则 2：图片必须注明来源（非原创）

使用非自制图片时，在图片下方注明来源：

```markdown
![系统架构图](arch.png)

*图片来源：[官方文档](https://example.com)*
```

## 快速自查

- [ ] 所有代码块已标注语言类型
- [ ] 行内代码只用于代码/命令/路径等，未用于装饰
- [ ] 步骤类内容使用有序列表
- [ ] 列表嵌套不超过两层
- [ ] 同一列表内标点风格统一
- [ ] 链接文本具有描述性，无"点击这里"
- [ ] 标题前后有空行
- [ ] 使用 ATX 风格标题
- [ ] 加粗只用于真正需要强调的关键词
- [ ] 图片 alt text 已填写且有描述性

# 菜单工程与战略定价 · 方法参考（Methodology Pro v3.0.0）

本文件为「菜单工程与战略定价顾问（Pro）」的底层方法说明，供生成报告时引用与校验。

---

## 一、核心公式

| 指标 | 公式 | 含义 |
|------|------|------|
| 净销量 Net Volume | `sales_volume × (1 − return_rate)` | 扣除退菜后的有效销量 |
| 合计成本 Total Cost | `raw_cost + seasoning_cost + labor_apportionment` | 单份完全成本（食材+调料+人工摊销） |
| CM（单位贡献毛利） | `Price − Total Cost` | 每卖一份扣掉完全成本后净赚的钱 |
| 毛利率 GM% | `CM / Price` | 与 PTR 互补 |
| **CM Mix%（毛利贡献占比）** | `单品总CM / 总CM`（总CM = CM × 净销量） | 该菜对整体利润的贡献集中度 |
| **Sales Mix%（销售额占比）** | `单品销售额 / 总销售额`（销售额 = Price × 净销量） | 营收集中度 |
| **PTR（首要成本率）** | `(raw_cost + labor_apportionment) / Price` | **不含调料**；越低越好，Puzzles 重构目标 < 35% |

**平均值（分类阈值）**
- 平均 Sales Mix% = 1 / N（N = 菜品数）—— BCG X 轴（受欢迎度）
- 平均单位 CM = ΣCM / N —— BCG Y 轴（盈利性）

**综合指标**
- 综合毛利率 = Σ总CM / Σ总销售额（加权）
- 综合 PTR = Σ(原料+人工)×净销量 / Σ总销售额（加权）

## 二、BCG 矩阵四象限（Menu Engineering Classification）

判定：受欢迎 = Sales Mix% > 平均 Sales Mix%；盈利 = 单位 CM > 平均单位 CM。

| 象限 | 条件 | 含义 | 策略主轴 |
|------|------|------|----------|
| **Stars 明星** | 高受欢迎 + 高盈利 | 既走量又赚钱的招牌 | Maintain：保护份额、优化出餐速度、菜单金三角置顶 |
| **Cows 金牛** | 低受欢迎 + 高盈利 | 利润厚但没人点 | Menu Engineering：黄金位 + 价值话术主推 |
| **Puzzles 问题** | 高受欢迎 + 低盈利 | 走量但不赚钱（引流款） | Price +X% / Cost Re-engineering |
| **Dogs 瘦狗** | 低受欢迎 + 低盈利 | 双低，沉默成本 | Delist（下架）/ Re-formulate（重配方） |

> 双轴严格对应 BCG：X = 受欢迎度（Sales Mix%），Y = 盈利性（单位 CM）。CM Mix% 与 Sales Mix% 作为
> 业务 KPI 单列，不参与分类轴，避免概念混淆。

## 三、价格弹性与敏感度分析（Puzzles）

行业价格弹性系数 **e = −1.2**（需求缺乏弹性偏刚性，提价 1% 销量约降 1.2%）。

```
对 Puzzles 模拟提价 Δ ∈ {+5%, +10%, +15%}：
  新售价   = Price × (1 + Δ)
  新 CM    = 新售价 − 合计成本
  预测销量降幅 = −e × Δ            # 例：+10% → 销量 −12%
  预测新总CM  = 新CM × 净销量 × (1 − 预测销量降幅)
  ΔCM       = 预测新总CM − 原总CM

盈亏平衡（不亏损）销量容忍度：
  临界降幅 x* = 1 − (原CM / 新CM)   # 只要实际降幅 ≤ x*，总CM 不降
  盈亏平衡销量 = 净销量 × (1 − x*)
```

**推荐动作选择**：在 +5%/+10%/+15% 中，取「弹性预测降幅 ≤ 盈亏平衡容忍度」且提价幅度最大者；
若三者均超出容忍度，则判定提价不可行，转成本重构（套餐绑定/加价配料/规格升级提升客单价）。

**菜单级净影响** = Σ(各 Puzzle 推荐方案 ΔCM) / 总CM × 100%（对 EBITDA 的正向贡献）。

## 四、帕累托分析（80/20 Rule）

- 按总 CM 降序排列，取**前 20% 菜品**（⌈0.2N⌉）统计其 CM 占比。
- **利润集中度**：累进 CM，找到覆盖 80% 总利润所需的最少菜品数 k（通常 k ≪ N）。
- **长尾无效菜品**：按总 CM 排序后 20% 的菜品，统计其 CM 占比 vs 首要成本占比；
  若「低 CM 占比 + 高成本占比」，即「高消耗·低产出」单元，优先进入下架/重估清单。

## 五、菜单效率分（Menu Efficiency Score, 0-100）

透明加权公式（全部基于脚本计算值）：

```
profit_score = min(综合GM% / 0.65, 1) × 40          # 盈利结构（满分 40）
star_score   = min(明星菜占比 / 0.30, 1) × 25        # 招牌健康度（满分 25）
conc_score   = min(Top20% CM占比 / 0.80, 1) × 10     # 利润集中度（满分 10）
dog_penalty  = min(瘦狗菜占比 / 0.20, 1) × 25        # 瘦狗惩罚（最高扣 25）
# v3 新增：若提供门店运营成本，追加净利维度（满分 10）
net_score    = min(整体净利率% / 目标净利率%, 1) × 10   # 仅 has_operating 时计入
Score = max(0, min(100, profit_score + star_score + conc_score − dog_penalty + net_score))
```

## 六、行业基准（诊断预警线）

| 指标 | 健康区间 | 预警 |
|------|----------|------|
| 综合毛利率 GM% | 60% – 65% | 低于 60% 偏弱，高于 65% 优秀 |
| 明星菜占比（道数） | 20% – 30% | 过低缺招牌，过高过度依赖爆款 |
| 瘦狗菜占比（道数） | < 20% | > 20% 预警，建议清理 |
| Puzzles PTR | < 35% | ≥ 35% 触发成本重构目标 |

> 上表为通用默认基准。不同业态运营差异显著，引擎支持按业态自动微调基准线（见第九节）。

## 七、业态专属基准线（格式预设 · Format Presets）

通过在 JSON 顶层或 `store_info` 设置 `"format": "快餐" | "正餐" | "茶饮"`（或脚本 `--format`），
引擎自动套用下表参数；未指定则回退通用默认（GM 60-65% / PTR<35% / 弹性 -1.2）。

| 业态 | 毛利率基准 | PTR 目标 | 价格弹性系数 | 调整依据 |
|------|-----------|---------|-------------|----------|
| **快餐 / 快休闲 (QSR)** | 60% – 65% | < 38% | **-1.2** | 高周转、低客单价、食材+包材成本占比高，单品绝对毛利薄，靠翻台走量获利；价格敏感但有便利性与品牌黏性，需求弹性居中偏高。 |
| **正餐 / 商务餐饮** | 65% – 72% | < 32% | **-0.8** | 客单价与体验属性强，食材+人工摊销占比相对可控，毛利率较高；消费受场景/社交驱动，价格敏感度低，需求弹性较小。 |
| **茶饮 / 现制饮品** | 68% – 78% | < 28% | **-1.6** | 原料（茶基底+小料）成本极低、毛利极高；赛道同质化与促销内卷严重，消费者对单价高度敏感，需求价格弹性大。 |

**参数联动关系（务必自洽）**
- 毛利率与 PTR 互补：GM ≈ 1 − PTR（忽略调料）。故「低毛利业态（快餐）↔ 高 PTR 目标」、「高毛利业态（茶饮）↔ 低 PTR 目标」。
- 弹性系数决定敏感度分析斜率：弹性越负（茶饮 -1.6），问题菜提价越易触发「超出盈亏平衡容忍度 → 转成本重构」；
  弹性越接近 0（正餐 -0.8），问题菜可承受更大提价幅度（菜单级净影响更高）。
- 明星菜/瘦狗菜占比阈值（20%-30% / <20%）为结构性指标，跨业态保持一致。

> 基准值为行业经验区间，仅供预警参考；连锁品牌可依据自身财报历史校准后替换 `FORMAT_PRESETS`。

## 八、常见异常与处理

| 异常 | 处理 |
|------|------|
| 合计成本 ≥ 售价 | 拦截，提示修正成本或售价后再分析 |
| 必填字段缺失（name/raw_cost/price/sales_volume） | 中断，提示补全 |
| 销量 < 0 或 return_rate ∉ [0,1) | 拦截，提示修正 |
| 仅 1 道菜 | 仍可计算，但四象限无意义，提示补充更多菜品以获有效分类 |
| 某 Puzzle 三种提价均超容忍度 | 判定提价不可行，转成本重构/客单价提升 |

## 九、话术框架（总监可直接套用）

- **明星菜·金牌话术**（短、有画面）：`[菜名]，我们的[核心卖点]，[一个让人想点的理由]`。
- **金牛菜·价值塑造话术**（只讲价值，禁提便宜）：`[菜名] 是我们[工艺/原料价值]，[为什么值得点]，特别适合[场景]`。
- **问题菜·轻提价话术**（包装成升级）：`我们升级了[原料/工艺]，[新价值]，所以稍微调整了价格`。
- **瘦狗菜·停止售卖通知单**：见 SKILL.md 第四节模板。

## 十、菜单销量分析口径（Sales Analytics）

销量模块聚焦「卖了多少、怎么卖」，不含成本/利润（与利润模块互补）。输入记录：`{date, dish, category, period, quantity[, revenue]}`。

**指标与口径**
| 指标 | 算法 | 说明 |
|------|------|------|
| 总销量 / 日均 | Σquantity / 统计天数 | 概览规模 |
| 畅销排名 | 按 Σquantity 降序取 Top5 | 冠军占比过高（>30%）提示单品依赖 |
| 滞销判定 | quantity < 均值×50% 或末位 | 末位 5 道；建议动作按占比分层 |
| 销量趋势 | 整体日销量首尾环比%；单品「前半段 vs 后半段」变化率 | 变化率 >±10% 标记上升/下滑 |
| 品类占比 | Σquantity(品类)/总销量 | 单品类 >50% 提示结构偏单一 |
| 时段分布 | Σquantity(时段)/总销量 | 标注高峰时段，指导排班与备货 |

**滞销建议分层**（按销量占比 share）
- share < 2% → **下架 / 替换**（占用产能，优先清理）
- 2% ≤ share < 5% → **重做 or 重推**（小批量测试改良或前厅主推，2 周观察）
- share ≥ 5% → **调位 / 组合**（黄金视线位或套餐绑定提升曝光）

**与利润模块的衔接**：销量维度只能识别「卖得少」，无法区分「低毛利慢销（该下架）」与「高毛利慢销（金牛，应主推）」。
补齐成本与售价后送入利润模块做 BCG 分类，可避免误杀高利润菜。本模块免责声明须注明此边界。

**实现**：`scripts/menu_sales_analysis.py`（纯标准库，CSV/JSON）；`references/sales_entry.html`（前端 SheetJS 解析 Excel + 本地分析，零后端）。

## 十一、销量 × 利润联合看板口径（Joint Dashboard）

联合看板是利润模块（第十节前）与销量模块（第十节）的**叠加层**，用同一份数据同时产出两份报告 + 联合洞察，
核心目的是消除两个独立维度各自的盲区。

**输入（两种模式）**
- 模式 A（统一 JSON）：每道菜含定价字段 `raw_cost/seasoning_cost/labor_apportionment/price/return_rate`
  以及 `sales[]` 时序数组（每条 `{date, period, quantity, revenue}`）。
  其中 `sales_volume` 由 `sales` 数组的 `quantity` 汇总得到，确保「利润聚合销量」与「销量维度销量」同源、一致。
- 模式 B（双文件）：`--sales sales.csv --pricing pricing.json`，分别走两引擎后按菜名合并。

**联合洞察算法**
1. **销量排名映射**：取销量引擎 `ranked`（按 Σquantity 降序）的排名与占比，与菜名关联。
2. **利润象限映射**：取利润引擎 `category_key`（star/cash_cow/puzzle/dog）与单位 CM、CM Mix%。
3. **交叉矩阵**：逐菜输出「销量排名 × 利润象限 × 趋势 × 联合判定 × 建议行动」。

**两类经典误判的识别逻辑**
| 风险 | 触发条件 | 联合判定 | 正确动作 |
|------|----------|----------|----------|
| **金牛勿误杀** | 利润象限 = Cows（高 CM）且 销量排名靠后 / 占比低 | 金牛 · 勿误杀 | 价值话术 + 黄金视线位主推；**严禁因销量低而下架** |
| **高销低利捧杀** | 利润象限 = Puzzle（低 CM）且 销量排名靠前 / 占比高 | 高销低利 · 提利 | 提价测试 / 成本重构；**勿仅看销量当招牌加推** |
| 双优 | Star | 双优 · 放大 | 金三角置顶 + 前厅主推 |
| 双弱 | Dog | 双弱 · 裁剪 | 下架 / 重做回收产能 |

**联合行动优先级**：放大明星 → 抢救问题菜利润 → 激活金牛 → 裁剪瘦狗（顺序即资源投放优先级）。

**实现**：`scripts/menu_joint_analysis.py`（复用 `menu_engineering.py` 与 `menu_sales_analysis.py`，仅标准库）。
示例：`references/sample_joint.json`（输入）、`references/sample_joint_report.md`（输出，可直接预览）。

## 十二、专业定价扩展（Pro v3 新增 · 四维定价模型）

在经典菜单工程（贡献毛利 CM）之上，补充「扣费后真实盈利」与「市场对齐」维度，使定价结论具备行业级可操作性。

### 12.1 全成本核算（Full-Cost Accounting）

将成本拆分为**变动成本**与**固定运营成本**两层：

| 指标 | 公式 | 说明 |
|------|------|------|
| 变动成本 VC | `raw_cost + seasoning_cost + labor_apportionment` | 食材 + 调料 + 直接人工摊销（随单份发生） |
| 门店月运营成本 | `rent + utilities + labor_overhead + depreciation + marketing + management` | 固定/半固定开销（租金、水电、人工总摊、折旧、营销、管理） |
| 单份运营成本 | `门店月运营成本 × 分摊系数` | 见 12.2 分摊法 |
| **完全成本 Full Cost** | `VC + 单份运营成本` | 单份真实总成本 |
| **单份净利 Net Profit** | `CM − 单份运营成本 = Price − 完全成本` | 扣费后每卖一份净赚 |
| **净利率 Net Margin%** | `单份净利 / Price` | 判断「卖得多是否真赚得多」的核心指标 |
| 整体净利 | `Σ(单份净利 × 净销量)` | 菜单级 = 总CM − 门店月运营成本 |
| 整体净利率 | `整体净利 / 总销售额` | 与 target.net_margin 比对，给出达标率 |

> 仅当输入 `store_info.operating_cost` 时启用；未提供则降级为贡献毛利口径并提示补充。

### 12.2 运营成本分摊（两种口径）

| 口径 `operating_alloc` | 分摊系数 | 适用场景 |
|------------------------|----------|----------|
| `volume`（默认·按销量） | `单品净销量 / 总净销量` | 每客消耗一份座席/水电，按客流消化固定开销，最贴合餐饮实际 |
| `revenue`（按营收） | `单品销售额 / 总销售额` | 高客单菜多担费用，适合强调坪效/营收贡献的测算 |

单品分摊到的「总」运营成本 = `门店月运营成本 × 分摊系数`；再 ÷ 净销量 得单份运营成本。

### 12.3 市场定位分析（Price Positioning）

按**售价分位**将菜品映射至价格阶梯，校准菜单「价格 ladder」：

| 层级 | 分位区间 | 角色 |
|------|----------|------|
| 引流款 value | `Price ≤ P25` | 低价引流、建性价比认知（慎防亏损） |
| 主力款 core | `P25 < Price ≤ P75` | 走量主力、承接大多数顾客 |
| 利润款 profit | `P75 < Price ≤ P90` | 高客单利润款、拉升整体盈利 |
| 形象款 image | `Price > P90` | 高价形象款、锚定价值感与品牌调性 |

`P25/P75/P90` 为全部菜品售价的分位数。门店整体定位由**人均消费均价**（总销售额 ÷ 总净销量）判定：
≤¥30 大众性价比型；¥30–80 中端品质型；>¥80 高端精品型。

### 12.4 竞品价格参考（Competitor Benchmark）

每道菜可填 `competitors:[{name,price}]` 或 `market_avg_price` / `competitor_price`：

| 指标 | 公式 | 诊断含义 |
|------|------|----------|
| 市场均价 market_avg | 竞品价均值 | 对标锚点 |
| 价格指数 Price Index | `我方售价 / market_avg` | >1.10 偏高；<0.90 偏低；其余持平 |
| 价差% Gap% | `(我方售价 − market_avg) / market_avg` | 偏离方向与幅度 |

**结合毛利率联合诊断**（避免「贵得有理」或「贱卖利润」误判）：
- 持平 + 毛利率达标 → 定价合理
- 偏低 + 毛利率达标 → 存在提价空间
- 偏高 + 毛利率未达标 → 溢价未被成本支撑，需降成本或强化价值感
- 偏高 + 毛利率达标 → 高端定位成立

### 12.5 利润率目标与定价优化器（Target-Margin Pricing）

给定目标利润率，**反推达成所需售价**（成本加成定价的逆运算）：

| 目标 | 反推公式 | 说明 |
|------|----------|------|
| 目标毛利率 `target.gross_margin` | `Price* = VC / (1 − 目标毛利率)` | 覆盖变动成本并达成目标毛利 |
| 目标净利率 `target.net_margin` | `Price* = 完全成本 / (1 − 目标净利率)` | 仅在提供运营成本时可算，覆盖完全成本并达成目标净利 |

- 缺省目标：毛利率取业态基准上限（如正餐 72%），净利率取 `0.15`。
- 若当前毛利率已 ≥ 目标，则建议「维持」，不展示更低的"达标价"（避免误导降价）。
- 若反推价超市场均价 15%，提示「同步做成本重构/价值包装」，防止脱离市场。
- **瘦狗菜（Dog）不进入定价优化**：低人气+低盈利，单靠提价无效，直接建议下架/重配方。

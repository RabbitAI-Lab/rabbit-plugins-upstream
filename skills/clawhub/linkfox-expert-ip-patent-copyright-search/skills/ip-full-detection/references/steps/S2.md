# 步骤 2：AIGC 多模态预筛

- **输入**：S1 的 `productTitle`、`imageUrl`、`brand`、拼接后的 `productText`、运行时入参 `region`
- **依赖**：S1
- **操作**：在同一轮里并行发起 6 个 `linkfox-aigc-textgen` 调用，每个针对一项 IP 风险做零积分预筛
- **输出**：6 项三态判定结果（`RISK` / `CLEAN` / `AMBIGUOUS`）+ 每项的 AIGC 推理摘要
- **用途**：过滤出需要专业检测的模糊项，最大化节省积分

## 核心策略

利用多模态大模型的接地搜索与推理能力 + 世界级知识库：

| AIGC 判定 | 含义 | 后续处理 |
|-----------|------|---------|
| `RISK` | 明确有侵权风险 | 直接标记风险，跳过 S3 专业检测 |
| `CLEAN` | 明确无侵权风险 | 直接放行，跳过 S3 专业检测 |
| `AMBIGUOUS` | 模棱两可，无法确定 | 进入 S3 专业睿观检测 |

## 调用方式

所有 6 项预筛统一使用 `linkfox-aigc-textgen` skill 的脚本，通过 `--stdin` 读取 JSON 参数文件（避免 shell 转义）：

```bash
python <aigc_textgen_skill_path>/scripts/aigc_textgen.py --stdin < <params_file>.json
```

> **注意**：每个预筛的 JSON 参数文件必须先用 Write 工具落盘到 `/tmp/`，再通过 `--stdin` 传入。禁止将 prompt 内联到 command 参数中。

## 统一输出格式要求

每个预筛的 prompt 末尾都要求 AIGC 输出以下 JSON 结构：

```json
{
  "verdict": "RISK|CLEAN|AMBIGUOUS",
  "reasoning": "一段简洁的推理摘要，说明判断依据",
  "confidence": 0-100,
  "risk_type": "<检测项标识>",
  "key_findings": ["发现1", "发现2"]
}
```

## 并行执行要点

- 6 个调用在**同一条消息**里并行发起（6 个 Bash tool call 在一个 response 里）
- 每个调用的 JSON 参数文件**必须先用 Write 工具落盘**到 `/tmp/`，文件名格式：`aigc-prescreen-<检测项>.json`（如 `aigc-prescreen-design-patent.json`）
- 然后通过 `python <script_path> --stdin < /tmp/aigc-prescreen-xxx.json` 执行
- 使用 `GEM_3_1_PRO` 模型以获得最佳推理质量
- 任一预筛失败不阻塞其他预筛——失败的项默认为 `AMBIGUOUS`，进入 S3 专业检测

## 输出解析

每项预筛返回的 `content` 字段应包含 JSON。Agent 解析每项返回的 JSON，提取 `verdict` 字段，汇总为预筛结果表：

```json
{
  "prescreen_results": {
    "design_patent": { "verdict": "AMBIGUOUS", "reasoning": "...", "confidence": 55 },
    "utility_patent": { "verdict": "CLEAN", "reasoning": "...", "confidence": 85 },
    "copyright": { "verdict": "CLEAN", "reasoning": "...", "confidence": 90 },
    "graphic_trademark": { "verdict": "AMBIGUOUS", "reasoning": "...", "confidence": 50 },
    "text_trademark": { "verdict": "RISK", "reasoning": "...", "confidence": 92 },
    "policy_compliance": { "verdict": "CLEAN", "reasoning": "...", "confidence": 88 }
  },
  "ambiguous_items": ["design_patent", "graphic_trademark"],
  "risk_items": ["text_trademark"],
  "clean_items": ["utility_patent", "copyright", "policy_compliance"]
}
```

## 失败处理

- 某项 AIGC 调用返回 errcode != 200 或超时：该项默认为 `AMBIGUOUS`，进入 S3 专业检测
- 某项返回的 content 无法解析为 JSON：尝试从文本中提取判定关键词（RISK/CLEAN/AMBIGUOUS），仍无法确定则默认 `AMBIGUOUS`
- AIGC 整体不可用（如积分不足）：所有 6 项默认 `AMBIGUOUS`，全部进入 S3 专业检测（退化为原始流程）

## 判定校准指引

AIGC 预筛的判定应遵循以下校准原则：

| 场景 | 建议判定 | 理由 |
|------|---------|------|
| 标题/五点中直接出现知名品牌名（如 Apple, Nike, Sony） | `RISK` | 知名品牌几乎必有商标保护 |
| 产品为通用设计，无独特装饰元素，类目常见 | `CLEAN` | 通用设计外观专利风险低 |
| 产品功能涉及专利密集领域（如电子烟、无线充电） | `AMBIGUOUS` | 需专业数据库验证 |
| 图片明显为专业图库风格或带水印 | `RISK` | 可能非原创 |
| 产品为普通日用品，无品牌名，无特殊认证需求 | `CLEAN` | 政策合规风险低 |
| 产品涉及儿童用品、化妆品、医疗器械等管制类目 | `AMBIGUOUS` | 需专业检测确认 |
| 无法确定，信心不足 | `AMBIGUOUS` | 宁可专业检测，不漏判 |

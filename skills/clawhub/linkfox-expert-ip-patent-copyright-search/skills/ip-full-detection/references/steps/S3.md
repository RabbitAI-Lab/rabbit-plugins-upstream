# 步骤 3：条件专业检测（仅模糊项）

- **输入**：S1 的产品信息 + S2 的预筛结果（`ambiguous_items` 列表）
- **依赖**：S2
- **操作**：仅对 S2 判定为 `AMBIGUOUS` 的项发起睿观专业检测，`RISK` 和 `CLEAN` 项跳过
- **输出**：模糊项的专业检测 JSON 数据文件（落盘到 `data/` 目录）
- **用途**：精准兜底，仅模糊项消耗积分

## 条件触发规则

| S2 预筛判定 | S3 行为 | 积分消耗 |
|-------------|---------|---------|
| `RISK` | 跳过，直接采用 AIGC 结论 | 零 |
| `CLEAN` | 跳过，直接采用 AIGC 结论 | 零 |
| `AMBIGUOUS` | 发起对应睿观专业检测 | 消耗 |

## 检测参数清单

## 并行执行要点

- 仅对 `AMBIGUOUS` 项发起调用，在同一轮并行执行
- 如果所有 6 项都是 `AMBIGUOUS`（最坏情况），退化为原始流程，6 项全跑
- 如果所有 6 项都是 `RISK` 或 `CLEAN`（最好情况），S3 完全跳过，零积分消耗
- 任一检测失败不阻塞其他检测——失败的在 S4 汇总时标记为"检测失败"

## 全跳过处理

当 `ambiguous_items` 为空（所有项都被 AIGC 明确判定）时：
- S3 直接跳过，不发起任何专业检测
- 在 S4 汇总时，所有项的风险等级直接采用 AIGC 预筛结论
- 在 S5 报告中标注"本次检测零积分消耗，全部由 AIGC 预筛完成"

## 失败处理

- 某个检测返回 errcode != 200：在 S4 中标记该项为"专业检测失败"，回退使用 AIGC 预筛结论
- 某个检测超时或脚本崩溃：同上，不重试（睿关 skill 有 24h 缓存）
- 多个检测同时失败：如实报告，AIGC 预筛结论作为兜底

# 03 合成数据与模型蒸馏治理

> 适用：用 AI 生成训练数据（合成数据）、用大模型蒸馏小模型时的治理要点
> 核对基准日：2026-08

## 1. 什么是合成数据与蒸馏

- **合成数据（Synthetic Data）**：由生成模型（LLM/GAN/扩散模型）人工生成、用于训练或评测的数据，非真实采集数据
- **蒸馏（Distillation）**：用大模型（教师）的输出训练小模型（学生），压缩能力、降低成本；也包括用 API 输出批量标注训练数据

## 2. 合成数据的价值与风险

### 2.1 价值
- 解决数据稀缺（医疗影像、罕见场景）
- 规避隐私（不含真实个人信息）
- 控制分布（补充长尾、对抗样本）

### 2.2 风险
| 风险 | 说明 | 缓释 |
|---|---|---|
| **模型坍缩（Collapse）** | 用模型输出训练下一代模型，逐代退化（分布收窄、多样性丧失） | 混合真实数据、控制合成占比、监测分布漂移 |
| **错误放大** | 教师模型的系统性错误被复制放大 | 合成数据质量门禁 + 人工抽样校验 |
| **偏见固化** | 训练数据中的偏见在合成中放大 | 偏见审计、平衡采样 |
| **合规风险** | 合成数据仍可能携带真实个体信息（记忆泄漏）；深度伪造类合成受限 | 数据来源审计、成员推断测试 |
| **标识义务** | 用于生成式 AI 服务的合成内容可能需标识 | 见内容标识实操 skill |

## 3. 蒸馏的治理要点

### 3.1 版权与授权
- **API 条款**：多数大模型 API 服务条款禁止/限制"用输出训练竞争模型"或"批量蒸馏"（2026 年主流厂商条款均含此限制）
- 必须核对采购合同的模型输出使用条款，合规蒸馏需专门授权
- 2025-2026 年已出现针对"用输出训练"的合同违约与版权诉讼

### 3.2 技术合规
- 蒸馏输出仍受源模型的内容安全政策约束（过滤需保留）
- 学生模型上线前应重跑安全评测（不因"小模型"豁免）

### 3.3 质量验证
- 蒸馏后必须验证：能力保留度（基准测试对比）、退化检查、错误模式对比
- 建议建立"教师-学生"差异评测基线

## 4. 合成数据全流程治理清单

```
① 来源  记录合成工具/模型版本、生成配置（可复现）
② 质量  自动质量门（语法/语义校验）+ 人工抽样（抽检率≥1%）
③ 合规  个人信息泄漏测试（成员推断）+ 版权来源审计 + 标识评估
④ 混合  控制合成占比（建议≤30%），保留真实数据锚点
⑤ 监控  训练中分布监测（防坍缩）+ 上线后漂移监测
⑥ 文档  数据卡（Data Card）：来源、占比、生成方法、已知局限
```

## 5. 常见误区
1. "合成数据完全没隐私问题"——模型会记忆训练数据，需做成员推断测试
2. "蒸馏小模型不用管合规"——API 条款限制照样适用，且错误会被放大
3. "合成越多越好"——比例过高必然模型坍缩，真实数据是锚点

# 02 编码智能体（AI 写代码）治理

> 适用：企业引入 AI 编程助手 / 编码智能体（Copilot 类、Agent 类）时的治理要点
> 核对基准日：2026-08

## 1. 编码智能体是什么

编码智能体（Coding Agent）是能自主完成"理解需求 → 搜索代码库 → 写代码 → 跑测试 → 修 bug → 提交 PR"闭环的 AI 系统。2026 年主流形态：

| 形态 | 交互方式 | 自主度 | 典型风险面 |
|---|---|---|---|
| 补全型（Copilot 类） | 行内补全/对话 | 低 | 代码质量、许可证 |
| 任务型（Agent 类） | 下达任务，自主执行 | 中-高 | 越权改文件、供应链 |
| 全流程型（Swe-agent 类） | 从 issue 到 PR 全自主 | 高 | 合并风险、治理失控 |

## 2. 五类核心风险

### 2.1 代码质量与正确性
- **幻觉代码**：生成看似合理但错误的 API 调用、算法逻辑
- **过时依赖**：引用已废弃或带漏洞的库版本
- 缓释：强制 Code Review + 自动化测试 + 静态扫描（SAST）

### 2.2 供应链投毒（最危险）
- 编码智能体可能被诱导安装恶意依赖包（依赖混淆攻击）
- 生成代码中嵌入混淆的下载/执行指令（下载器木马）
- 缓释：
  - 依赖锁定（lockfile）+ 哈希校验
  - 私有源优先，禁止裸装未知包
  - 供应链安全工具（SBOM + 依赖扫描）
  - 编码智能体专用沙箱（禁网络/禁写敏感路径）

### 2.3 越权与破坏面
- Agent 自主执行 `rm`、`git push --force`、改生产配置
- 超出仓库范围读写其他目录
- 缓释：最小权限工作区 + 命令白名单 + 高危操作人工确认（两阶段提交）

### 2.4 许可证与版权合规
- 生成的代码可能来自 GPL 等传染性许可证开源代码（"代码气味"记忆）
- 训练数据中的代码版权争议（2026 年多起诉讼推进中）
- 缓释：
  - 许可证扫描（license scanning）纳入 CI
  - 采购合同确认"生成代码的 IP 归属 + 免责条款"
  - 高风险场景（对外交付核心模块）人工重写

### 2.5 提示注入（经代码库）
- 攻击者把恶意指令藏在 issue、README、测试文件里（间接注入）
- Agent 读到后执行恶意操作
- 缓释：代码库内容视为不可信输入；Agent 输出动作分级审批

## 3. 编码智能体治理框架（四层）

```
L1 政策层   AI 编码政策：什么代码可让 AI 写/什么必须人写（如安全关键模块）
L2 流程层   强制 Code Review + 测试门禁 + 许可证扫描（CI 集成）
L3 技术层   沙箱隔离 + 最小权限 + 命令白名单 + 供应链锁定
L4 监控层   变更审计日志 + AI 生成代码占比度量 + 事故复盘
```

### 3.1 分级授权建议
| 代码类型 | AI 自主度 | 要求 |
|---|---|---|
| 内部工具/原型 | 高 | 测试通过即可 |
| 业务代码 | 中 | 人工 Review + 测试 |
| 安全/合规关键代码 | 低 | 人写为主，AI 仅辅助 |
| 对外交付核心 | 低 | 人工重写 + 双人评审 |

## 4. 度量与复盘
- **AI 代码采纳率**（生成的代码最终合入比例）
- **AI 引入 bug 率**（按缺陷溯源标记）
- **生成代码许可证违规数**
- 月度复盘：质量问题 → 调整提示词/工具/授权边界

## 5. 常见误区
1. "AI 写的代码不用 review"——幻觉代码是常态，必须走完整质量门
2. "沙箱太麻烦"——一次供应链投毒事故的成本远超沙箱配置成本
3. "许可证扫描是法务的事"——2026 年生成代码版权诉讼已到高发期，工程侧就要拦截

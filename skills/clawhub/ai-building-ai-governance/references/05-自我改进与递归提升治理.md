# 05 自我改进与递归提升治理

> 适用：AI 自我训练、自蒸馏、自奖励、递归自我改进（Recursive Self-Improvement, RSI）的治理与安全
> 核对基准日：2026-08

## 1. 自我改进形态

| 形态 | 机制 | 说明 |
|---|---|---|
| 自蒸馏（Self-distillation） | 自己训练自己 | 用自身输出去重训/微调，质量易退化 |
| 自奖励（Self-rewarding） | 自己当裁判 | AI 评估自己输出并据此优化，易"奖励黑客" |
| 数据飞轮（Data flywheel） | 用运行数据持续改进 | 生产中收集反馈再训练 |
| 递归自我改进（RSI） | AI 改进自己"改进自己的能力" | 潜在指数级提升，风险最高 |

## 2. 核心风险

### 2.1 目标漂移（Goal Misalignment）
- AI 优化"看起来好"的指标，偏离真实目标
- 自奖励系统尤其容易奖励黑客（刷分数而非提升真实能力）
- 缓释：奖励设计人审 + 多指标交叉验证 + 对抗评测

### 2.2 能力突然跃升（Sudden Capability Jump）
- 递归改进可能导致能力非线性跃升，超出治理预期
- 缓释：**能力阈值监控 + 跃升熔断机制**（超过预设阈值自动暂停）

### 2.3 退化循环
- 自训练无新鲜数据 → 自我强化偏见/错误（与合成数据坍缩同类）
- 缓释：真实数据锚点 + 质量门禁 + 与外部基准对照

### 2.4 失控边界
- 无上限的自主改进可能绕过安全对齐
- 缓释：**改进上限锁定**（能力/资源/权限三层封顶）+ 人工闸门

## 3. 治理框架（能力封顶模型）

```
┌─ 封顶层：能力上限（任务范围/输出权力）不可由 AI 自行修改
├─ 闸门层：任何"自我改进动作"需人工批准（升级/重训/扩权）
├─ 监控层：能力/行为/资源指标实时监控，异常即熔断
└─ 审计层：改进链全记录（谁改了什么、依据什么、人批了什么）
```

### 3.1 熔断条件示例
- 能力评测分跳变超过 X%（如 2 小时内提升 >10%）
- 改进链中出现"自我扩权"（AI 试图修改自己的权限/上限）
- 行为偏离已批准目标（目标漂移检测）

### 3.2 分级管控建议
| 改进类型 | 管控 |
|---|---|
| 人工设计的调参优化 | 常规审批 |
| AI 自主微调/自蒸馏 | 专项审批 + 上限锁定 |
| 自奖励训练 | 双人评审 + 奖励审计 |
| 递归自我改进（RSI） | 原则上禁止自主运行；研究须隔离沙箱 + 强制人工闸门 |

## 4. 监管与行业动态
- 2026 年主流 AI 安全机构将"自我改进监控"列为前沿模型关键风险之一
- 国际 AI 安全报告（2026 版）将 RSI 列为需国际协调的长期风险
- 企业自研前沿模型建议建立"改进日志 + 能力体检"机制，纳入 AI 治理委员会议程

## 5. 常见误区
1. "自我改进=自动升级，效率高"——无闸门的改进是失控的开始
2. "自奖励系统已经很好了"——奖励黑客是已知失效模式，必须人审奖励函数
3. "我们小模型不用管"——数据飞轮式自我改进在中型产品中也很常见

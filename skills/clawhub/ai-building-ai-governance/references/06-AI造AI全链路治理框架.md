# 06 AI 造 AI 全链路治理框架

> 适用：把"AI 造 AI"（编码智能体 / 合成数据 / 蒸馏 / 研究自动化 / 自我改进）纳入统一治理
> 核对基准日：2026-08

## 1. 四层全链路治理

```
┌─ L1 数据层：训练数据来源、合成数据占比、质量门禁、合规审计
├─ L2 模型层：模型卡、蒸馏授权、改进审批、能力监控
├─ L3 工具层：编码智能体沙箱、命令白名单、供应链锁定
└─ L4 输出层：内容标识、双用途风险、人类闸门
```

## 2. 五类形态统一风险分级

| 形态 | 典型自主度 | 默认风险级 | 核心管控 |
|---|---|---|---|
| 编码智能体 | 中-高 | 中 | 沙箱 + Review + 供应链 |
| 合成数据 | 中 | 中 | 质量门 + 占比控制 + 合规 |
| 蒸馏 | 中 | 中-高 | 授权核查 + 质量验证 |
| 研究自动化 | 高 | 高 | 人工闸门 + 科研诚信 |
| 自我改进/RSI | 极高 | 极高 | 能力封顶 + 熔断 + 禁自主 |

## 3. 统一管控清单（企业落地版）

### 3.1 制度层
- [ ] AI 编码政策（什么代码 AI 可写/必须人写）
- [ ] 合成数据与蒸馏使用规范（含 API 条款核查）
- [ ] AI 研究自动化审批流程（分级 + 人工闸门）
- [ ] 自我改进管控条款（上限锁定 + 熔断）

### 3.2 技术层
- [ ] 编码沙箱与命令白名单
- [ ] 供应链锁定（lockfile + SBOM + 私有源）
- [ ] 合成数据溯源记录（工具/版本/配置可复现）
- [ ] 能力监控与熔断机制（跳变检测）

### 3.3 合规层
- [ ] 蒸馏 API 条款核查（是否允许输出用于训练）
- [ ] 合成数据成员推断测试与标识评估
- [ ] 生成代码许可证扫描（CI 集成）
- [ ] AI 研究论文披露声明模板

### 3.4 监督层
- [ ] AI 造 AI 项目台账（形态/自主度/风险级/负责人）
- [ ] 月度复盘（质量指标 + 事故 + 调整）
- [ ] AI 治理委员会季度审阅

## 4. 与现有治理矩阵的衔接
- **风险分级** → 复用企业 AI 治理的 5 维评分模型
- **内容标识** → 合成内容按标识办法/Article 50 执行
- **供应链** → 复用医械网络安全的 SBOM 思路
- **测试** → 复用 AI 安全与红队的测试方法论

## 5. 落地路线（90 天）
| 阶段 | 动作 |
|---|---|
| 1-30 天 | 盘点：审计现有 AI 造 AI 使用（编码工具/合成数据/蒸馏）；建台账 |
| 31-60 天 | 建制度：编码政策 + 合成数据规范 + 审批流程；技术控制上线（沙箱/锁依赖） |
| 61-90 天 | 建监控：能力监控 + 月度复盘；治理委员会纳入季度议程 |

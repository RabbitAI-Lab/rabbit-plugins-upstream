## 二、Critical 问题 → Skill 设计缺陷

### 问题 1: 版本号不同步（维度1/8）

**报告表现**: 报告底部写 `v5.2.1`，实际 Skill 已迭代到 `v5.2.3`

**根因分析**:
```
版本号分散在 6+ 个文件中：
├── SKILL.md (header + 版本历史)
├── tracker.py (3 处输出)
├── init.py (config 生成)
├── report_template.md (底部标注)
├── config.json (version 字段)
└── dist/ 下全部同步
```
每次更新需要人工改 10+ 处，必然遗漏。

**Skill 缺陷**: 无版本号自动同步机制
**修复建议**:
1. 新增 `version.py`，单文件定义版本号
2. 其他文件从 `version.py` 读取（如 tracker.py `import version`）
3. 或新增 `scripts/bump_version.py` 一键替换所有文件

---

### 问题 2: 搜索覆盖严重不足（维度5）

**报告表现**: 执行摘要称"8 篇高度相关"，但搜索只用了 3 组 arXiv 查询 + 1 组 kimi_search

**Searcher prompt 要求**:
- arXiv API：至少 8 组查询
- HF Daily Papers：追踪窗口内每天必查
- kimi_search：至少 6 组查询

**实际执行**: 3 组 arXiv + 1 组 kimi_search = **4/14（29%）**

**根因分析**:
Searcher prompt 中的查询数量是"建议"语气（"执行至少8组"），而非"强制约束"。主 Agent 在实际运行中会根据 token/时间压力自主缩减。

**Skill 缺陷**: Searcher prompt 的约束是"软约束"，主 Agent 可能不遵守
**修复建议**:
1. 将"至少8组"改为强制自检清单："如果 arXiv 查询 < 8 组，输出 [ERROR: 搜索覆盖不足]"
2. 在主 Agent 工作流中增加"搜索完整性检测"：如果返回论文数 < 阈值，自动补充搜索
3. 或在 SKILL.md 的 `run_search()` 伪代码中明确循环次数：`for i in range(8): ...`

### 问题 3: 数据未经验证（维度3）

**报告表现**:
- "平均准确率 64.5%"——来源是 kimi_search 的摘要片段，非原始论文表格
- "标准差从 1.53 降至 0.82"——未说明是否同模型规模、同 benchmark
- "Cold-Q ratio 降低 80.0%"——数字可信但未反向核对原始论文

**根因分析**:
Deep Reader prompt 要求"数据三级验证（自检→交叉核对→标注验证级别）"，但：
1. Deep Reader 子 Agent 可能未严格执行
2. 即使 Deep Reader 验证了，Writer 在整合时可能忽略验证级别标注
3. Checker 的数据准确性检查只有 5 个 checkbox，没有"反向查找原始论文表格"的强制要求

**Skill 缺陷**: 验证机制是"要求"而非"强制执行"
**修复建议**:
1. 在 writer_prompt.md 的数据验证声明部分，要求必须标注：
   - `[V]` 已验证：亲自读取原始论文对应表格
   - `[C]` 引用验证：来自其他论文的引用/摘要
   - `[U]` 未验证：来自搜索结果，建议人工复核
2. 在 checker_prompt.md 增加强制检查项："对每个性能数字，确认标注了验证级别"
3. Deep Reader prompt 增加硬性输出要求："每个实验数据必须标注验证级别 [V]/[C]/[U]"

```
- 必须列出关键指标的具体分数（如 64.5% / 72.3%）

```

### 问题 5: 建议空泛（维度10/11）

**报告表现**:
- 短期建议："阅读 GradCuit 全文"——这是动作，不是建议
- 中期建议："探索 memory-aware credit assignment"——没有具体路径
- 无资源需求估计、无 Plan B

**Checklist 要求**: "建议具体可执行，有清晰的第一步/第二步/第三步"

**Skill 缺陷**: writer_prompt.md 对"项目影响"部分只有"具体、可操作"的笼统要求，无结构化框架
**修复建议**:
在 writer_prompt.md 中给出结构化模板：
```markdown
### 短期（1-2周）
- **行动**: [具体做什么]
- **输入**: [需要什么数据/代码]
- **预期产出**: [可验证的交付物]
- **风险**: [可能失败的原因]

### 中期（1-2月）
- **行动**: ...
- **资源**: [算力/人力/时间估计]
```

## 六、结论

**当前 Skill 能做什么**: 
- ✅ 自动搜索并发现新论文
- ✅ 基础质量检查（内容完整、格式规范）
- ✅ 跨平台运行

**当前 Skill 不能做什么**:
- ❌ 保证搜索覆盖完整（依赖主 Agent 自律）
- ❌ 保证数据经过验证（依赖 Deep Reader 自律）
- ❌ 生成深度分析级别的报告（轻量模式的 output 天花板明显）

**给学生使用的建议**:
作为"发现新论文 + 快速筛选"的工具完全可用，但作为"深度调研报告"需要学生人工补充验证和分析。建议学生把 Skill 输出当作"初稿"，关键数据必须人工复核。

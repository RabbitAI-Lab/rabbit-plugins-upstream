## 埋点表结构

- 表头单独一个 csv 文件, **带 BOM, 读取用 `encoding='utf-8-sig'`**; 数据 part 文件无表头。
- 61 个有效列, 第 62 列为尾部空列(split 后丢弃)。
- 关键列: `raw_request`(JSON 串, 含 session.visitorId / proUserId / historyMessages)、`biz_name`(分组依据)、`raw_response`、行业字段、时间戳、`hasLeadGen` 类系统标记、组件点击事件字段。
- 大文件逐行流式处理, 不整体载入; 单行 JSON 解析失败计数后跳过(首次分析坏行占比可忽略)。

## 会话重建

- **会话键**: `raw_request.session.visitorId × proUserId`。同键跨 exp/ctrl 两组的为"混合会话"(首次 111 个), 存 mixed_keys.json, 主分析剔除+做敏感性检验。
- **角色映射**(senderType): `VISITOR`=用户 / `SYSTEM_B2C`=AI / `MANUAL_AGENT`=人工客服 / `SYSTEM_C2B`=系统。
- LLM 判定用压缩文本: 卡片消息压缩为 `[卡片/笔记: title]`, 每条消息截 130 字, 每会话截 28 条消息 / 3200 字。

## 留资口径定义

| 口径 | 定义 |
|---|---|
| A | 出现"复制微信"类事件文本(如"对方已复制你的微信号") |
| B | 用户消息中出现 11 位手机号(`1[3-9]\d{9}`, 排除引号内商家电话回显场景) |
| C | 用户消息中出现微信号形态(6-20 位字母开头字母数字下划线连字符, 需排除纯数字与常见误伤词) |
| 组件 | 留资卡组件提交/企微卡点击事件 |
| hasLeadGen | 系统侧留资标记字段 |
| **宽口径** | A∪B∪C∪组件∪hasLeadGen, **结论主口径** |

口径盲区提示: 企微卡点击与 hasLeadGen 若字段缺失/稀疏, 在报告中显式声明覆盖度。

## 漏斗分层 L0-L5

对未留资会话分层定位卡点(留资会话不分层):

| 层 | 定义 |
|---|---|
| L0 | 用户未开口(0 条 VISITOR 消息)——**OR 归因前必须剔除** |
| L1 | 浅聊(用户 1-2 条即走) |
| L2 | 聊了但 AI 从未推进留资 |
| L3 | AI 推进后用户明确拒绝(首次仅 1.1%, 拒绝不是主要流失原因) |
| L4 | 深聊+推进但未留资 |
| L5 | 人工介入后未留资 |

## 规则版 12 特征

session 级布尔特征, 全量计算(exp 3459/ctrl 9523, 剔 L0 后), 与 LLM rubrics 版交叉验证:
是否发卡组件 / 首轮即推留资 / 从未推进留资 / 推进前解答过问题 / 报价直给 / 报价拖延 / emoji 使用 / 连续催促(同话术重复≥2) / 人工介入 / AI 无回复中断 / 会话轮数≥6 / 用户问价。
命名以首次产物 rubric_recs.json 为准, 可按业务演进增删。

## 行业标准化与商家配对

- **分解**: 逐行业算两组留资率与占比, 贡献=占比差×行业率, 定位 mix 大户(首次=教辅 2.2 倍)。
- **直接标准化**: 以两组合并的行业分布为标准权重, 重加权两组率再对比。
- **商家配对**: 仅取两组均有会话的商家, 商家内两组差取均值(等权或按会话量加权各报一版)。
- 三口径结论一致才写强结论; 不一致时以配对版最可信。

## turn_trace 硬故障体检

在下结论前先排除工程问题解释: 按 session 扫 turn_trace/raw_response 中的异常锚点(如 `TextEncodeInput` 编码错误、LLM HTTP 500、空回复), 统计硬故障 session 占比及其留资率, 换算对总差值的最大可能影响。首次结果: ≤3.1% session 受影响, 影响 <0.5pp, 不解释组间差。

## 已知陷阱清单

1. 表头 BOM(utf-8-sig)。
2. 混合会话(同键跨组)不剔会稀释组间差。
3. B 口径手机号会命中商家电话回显, 需排除 AI 消息与引用场景。
4. "高耗时会话留资率高"是幸存者偏差(聊得深才耗时), 勿当因果。
5. 教辅类行业微信直引流形态: 发卡把 A 文本信号转成组件信号, 窄口径下表现为"下降"实为口径迁移。
6. AI 文本直报微信号是测量黑洞+合规风险, 单独统计上报。

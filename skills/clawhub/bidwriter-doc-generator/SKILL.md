# 投标文件生成官（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`scripts/engine/` 目录）。
> 不联网、不需要 API Key、没有调用次数上限。**项目资料和报价不会离开你的机器。**

## 它生成什么

拿到项目基本信息与招标文件条款，输出六件事：

| 输出 | 具体内容 |
|---|---|
| 全册目录 | 资格 / 商务 / 技术三册，逐章列出**撰写要点**与**建议字数**，按货物 / 工程 / 服务 / 政府采购四类项目切换结构 |
| 逐条响应表 | 招标文件每条条款 → 响应 / 需补充 / 待确认，**每条附可复核的依据**（命中了你的哪项资质、或报价是否超限额） |
| 否决条款自查表 | 单独抽出所有"否决投标 / 无效投标"类条款 —— 这些条款不响应就是废标 |
| 材料清单与盖章要求 | 逐项标注是否需要盖章、是否需要原件、常见填报错误 |
| 废标雷区库 | 按项目类型列出的高频废标原因，逐条可对照自查 |
| 材料完整度评分 | 0-100 分，并明确列出**还缺哪几项**才能把分补齐 |

## 怎么用

```bash
node scripts/run.mjs --sample
node scripts/run.mjs --input my-project.json
node scripts/run.mjs --input my-project.json --json
```

入参就是一份 JSON，完整样例见 `templates/sample.json`：

```json
{
  "projectName": "市政务服务中心智能叫号系统采购项目",
  "projectNo": "ZFCG-2026-0318",
  "tenderer": "市政务服务中心",
  "bidder": "示例科技（北京）有限公司",
  "bidType": "goods",
  "price": "1286000.00",
  "qualification": ["计算机信息系统集成资质二级", "ISO9001 质量管理体系认证"],
  "performance": [{ "name": "某区政务大厅智能排队系统建设", "amount": "960000", "year": "2024" }],
  "deliverables": ["无重大违法记录声明", "近三个月依法缴纳税收证明"],
  "clauses": [
    { "no": "1.1", "text": "投标人须具备计算机信息系统集成资质，并提供资质证书复印件加盖公章。", "type": "qualification" },
    { "no": "2.1", "text": "投标报价不得超过采购预算 130 万元，超过者投标无效。", "type": "reject" }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `projectName` | 是 | 项目名称 |
| `bidder` | 是 | 投标人名称 |
| `projectNo` | 否 | 项目编号 |
| `tenderer` | 否 | 招标人 |
| `bidType` | 否 | `goods`（货物，默认）/ `works`（工程）/ `service`（服务）/ `gov-procurement`（政府采购） |
| `price` | 否 | 投标报价。填了才会做**超预算判定** |
| `qualification` | 否 | 资质清单（字符串数组）。填了才能做资质类条款的响应匹配 |
| `performance` | 否 | 业绩清单（字符串或对象数组） |
| `deliverables` | 否 | 招标文件要求提交的材料清单 |
| `clauses` | 否 | 招标文件关键条款。字符串，或带 `no` / `type` 的对象 |
| `rejectClauses` | 否 | 否决投标条款（招标文件单独成表时用） |

## 触发条件

用户说以下任意一类话时使用：

- 帮我生成投标文件目录 / 标书骨架 / 投标文件框架
- 这个招标文件要求这么多，投标文件该怎么组织
- 帮我做一张条款逐条响应表 / 商务偏离表
- 哪些条款不响应会被废标
- 投标要交哪些材料 / 哪些要盖章
- 这个项目投标要注意哪些废标雷区

## 边界（先看这里，别误用）

**本技能生成的是"投标文件骨架与应答口径"，不是帮你写完整标书正文。**
技术方案、施工组织设计、服务实施方案的正文内容必须由投标人结合自身实际撰写 ——
任何声称能一键生成完整标书正文的工具，交付的都是无法通过评审的通用模板。

**它做**：结构化目录、条款分类、机械匹配响应结论、材料清单、废标雷区对照。

**它不做、也无法做**：

- 替你判断报价策略、是否低于成本价、竞争格局
- 核实你提供的资质业绩是否真实有效
- 替代招标文件原文与评标办法的逐字阅读
- 给出法律意见（评标争议请咨询专业招标代理或律师）

**响应结论是机械匹配结果，不是评审结论。** "需补充"只说明条款文本没有命中你提供的材料，
不等于一定被否决；"响应"也只说明命中了材料名称，不代表材料内容已满足评审要求。
**最终必须以招标文件原文与评标委员会认定为准。**

如果输入**不是投标项目**（例如聊天记录、产品说明书、与招投标无关的文本），
**不要直接出结论**：先明确告诉用户「这份材料看起来不是投标项目信息，生成的骨架会没有意义」，确认后再决定是否继续。

`projectName` 或 `bidder` 缺失时，脚本以退出码 3 结束并说明缺什么，**不会编造一份看起来完整的骨架**。

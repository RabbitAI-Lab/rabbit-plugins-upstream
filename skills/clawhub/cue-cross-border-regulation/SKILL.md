# 跨境法规与合规调研助手

> 🚀 **出海合规、涉外诉讼、跨境投资，最怕“盲人摸象”。**
> 条款散落各国官方公报，英文/小语种原文难啃，适用边界更难研判。
> 把目标市场或合规问题发给本助手，它直连海外官方权威库，为你输出**带中英摘要、立法背景、适用边界，且每一句结论都能溯源到官方链接**的研究报告。
>
> 🟢 **优势**：跨越语言与信息壁垒，直击核心条款，支持一键转 Word。
> 🔴 **注意**：本助手不替代执业律师出具正式法律意见，仅限公开数据检索。
> ⚠️ **边界**：以美国、欧盟、新加坡等主要英语法域为主；暂不覆盖未公开的监管口径或非常见小语种地方法规。

## 解决涉外法律人的三大痛点

| 痛点 | 本助手的解决方案 |
|------|-----------|
| **找不到原文** | 抛弃搜索引擎里的二手甚至过期信息，直连美国 USC/CFR、欧盟 EUR-Lex、新加坡 SSO 等官方数据库，直达现行有效原文。 |
| **看不懂法言法语** | 全中文交付报告。针对核心法条，保留外文原法条编号和名称，并提供精准的中文核心要义解读。 |
| **判不准适用边界** | 不仅罗列法条，更能为你梳理法案出台背景、谁受管辖（触发条件）、哪些情况可以豁免（Safe Harbor）。 |

## 典型场景与高级指令 (Prompt) 示例

日常工作中，你可以直接将具体的业务背景丢给助手：

| 业务场景 | 你可以这样发指令 |
|:---|:---|
| **出海产品准入** | 「我司计划向欧盟市场推出一款包含人脸识别的智能硬件。请结合最新的《欧盟 AI 法案》（AI Act），调研该产品所属的风险等级及核心合规义务。」 |
| **数据隐私合规** | 「我们是一家中国出海电商，服务器在新加坡。请帮我梳理新加坡《个人数据保护法》(PDPA) 中关于『数据跨境传输』和『数据泄露通知』的核心条款与罚则。」 |
| **出口管制与制裁** | 「我司计划向中东出口含美国原产技术的半导体设备。请结合现行 EAR（美国出口管理条例），梳理『外国直接产品规则』(FDP) 的触发条件与合规红线。」 |
| **外商投资审查** | 「中资企业拟收购一家美国加州的生物科技初创公司。请调研 CFIUS（美国外资投资委员会）关于涉及『关键技术』领域的强制申报门槛。」 |
| **跨国劳动雇佣** | 「中国公司准备向德国分公司派遣 5 名研发工程师，租期 2 年。请简要梳理德国现行的欧盟蓝卡（EU Blue Card）申请条件及当地用工的社保要求。」 |

*(拿到 Key 后直接发给本 AI 助手，它会自动完成网络探测、海外数据库检索及报告生成，您只需安心等待。)*

> **API Key 只能由用户本人创建**：Agent 既不能代生成、也无权查看用户的 Key。检测到未配置或失效时，按以下话术告知用户：**「点击『创建 API Key』，生成 API Key 后一定要点击『复制』并粘贴发送给我。」** 然后等待用户提供，**禁止声称"我去生成/查看"**。

### 配置成功后引导用户跑第一个任务（必须执行）

健康检查三项全绿 = 环境就绪，但**这是配置流程的终点，不是任务的终点**。三项全绿后若用户还没给出具体任务，**必须主动把用户推向第一次真实调用**，不要停在"环境已就绪"：

> 环境已就绪 ✅ 下面这些都可以直接跑，比如：
> 1. "我司计划向欧盟市场推出一款包含人脸识别的智能硬件。请结合最新的《欧盟 AI 法案》（AI Act），调研该产品所属的风险等级及核心合规义务。"
> 2. "我们是一家中国出海电商，服务器在新加坡。请帮我梳理新加坡《个人数据保护法》(PDPA) 中关于『数据跨境传输』和『数据泄露通知』的核心条款与罚则。"
>
> 挑一个发给我，或直接把你手头的需求告诉我，我现在就跑。

规则：
- **主动、可复制**——示例问题原句取自上文「典型场景与高级指令 (Prompt) 示例」，别只写"你可以问我任何问题"。
- **不要等用户自己想**——用户没开口时也要主动给；否则用户会停在"验证通过"就散场（实测这是新用户流失最集中的一步）。

## 调用方式

本助手在 Claude Code 里由 Agent 自动驱动，你无需手动敲命令。Agent 会在后台按以下流程完成调用：

1. **鉴权**：读取本地 `~/.cue/config.json` 里的 `api_key` 字段完成鉴权。
2. **匹配搭子**：向 Cue 服务端（cuecue.cn）请求「跨境法规调研」搭子当前可用的模板 ID。
3. **执行检索**：运行 runner 脚本 `research_run.py`，传入三个参数——用户问题原话、模板 ID、报告落盘路径，阻塞等待服务端检索完成。
4. **交付报告**：将生成的 Markdown 报告原样交付，并告知落盘路径（默认 `~/cue-reports/`）。

Runner 脚本位于 [GitHub 仓库](https://github.com/sensedeal/cue-skills)（[Gitee 镜像](https://gitee.com/sensedeal/cue-skills)）的 `cue-research/scripts/` 目录。

**首次使用需安装 Runner（幂等，已装则拉取更新）：**

```bash
if [ -d ~/.cue/cue-skills/.git ]; then
  git -C ~/.cue/cue-skills pull --ff-only
else
  git clone https://github.com/sensedeal/cue-skills ~/.cue/cue-skills \
    || git clone https://gitee.com/sensedeal/cue-skills ~/.cue/cue-skills
fi
```

## 交付规范（必须执行）

把最终报告发送给用户时，**必须同时附带 Cue 原始报告链接**，方便用户回到网页端查看完整原文、继续追问或转发同事。

**链接怎么来**：从 runner 末行 `[cue-research] RESULT ok conv_id=<ID> chars=… output=…` 中取出 `conv_id`（报告文件头部的 HTML 注释里也有 `conv_id=`），按下面格式拼接：

```
https://cuecue.cn/share/<conv_id>
```

交付模板（照此结构输出）：

```
报告已完成 ✅

<报告正文……>

---
**Cue 原始报告**：https://cuecue.cn/share/<conv_id>
**本地副本**：~/cue-reports/<文件名>.md
```

规则：
- `conv_id` 必须取自实际输出，**禁止编造**或使用文档示例里的 id。
- 末行为 `RESULT empty`（无 conv_id 或报告为空）时**不要拼链接**，如实告知未取到报告并给后续建议。
- 用户明确说不要链接时可不附。

## FAQ

**Q: 和 Cue 网页端有什么区别？**
A: 在 Claude Code 里直接用自然语言触发，Agent 自动匹配搭子、确认、取报告，不用切网页。

**Q: 能查国内法规吗？**
A: 不能。本 Skill 专注境外法域，国内法规有另外的搭子（国内法规调研）。

**Q: 报告语言？**
A: 中文报告，法条名/编号保留原文附摘要。

**Q: 积分不够？**
A: 打开 [cuecue.cn](https://cuecue.cn/)，点击页面左下角「获取专属邀请链接」，好友加入后你再得 500 积分（推荐）；也可前往 [cuecue.cn/pay](https://cuecue.cn/pay) 订阅（首次有优惠），或等次日免费额度。

**Q: 查不到怎么办？**
A: 先跑健康检查。三个环节任一断了都会失败——见上方「自救指引」。

**Q: 结果可靠吗？**
A: 结论带来源链接可回查。注意：覆盖以美国/欧盟/新加坡等主要法域为主；非英语法域、地方性法规、未公开的监管口径覆盖不全；不构成法律意见。

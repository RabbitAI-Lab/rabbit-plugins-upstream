# 桌面级行业调研 SOP v3.0

> 版本：3.0
> 状态：已评审（经 v1.0 → v2.0 → v3.0 迭代，修复确认偏误、来源独立性、时效衰减、评分虚高、样本偏差五大缺陷）
> 适用范围：AI Agent 桌面级行业调研（无需一手实验/问卷，基于公开信息的结构化调研）
> 产出物：带可信度评分的分级结论报告 + 行动建议清单

---

## 0. 协议总览

本 SOP 将调研流程分为 5 个阶段，每个阶段有明确产出和硬性纪律，防止调研退化为"随便搜搜"。

```
阶段0 问题定义 → 阶段1 来源分层采集 → 阶段2 交叉验证 → 阶段3 结论分级输出 → 阶段4 复盘迭代
     ↓                ↓                    ↓                 ↓                  ↓
 调研目标书       证据卡片库          验证记录           分级报告            缺口清单
```

**核心原则**：
1. 结论必须带证据链（URL + 来源级别 + 时点），可回溯
2. 结论必须分级（事实/推断/未知），不假装客观
3. 报告必须给整体可信度评分，且说明评分方法
4. 调研中发现的对比项缺口，必须主动建议，不固守原定边界

---

## 1. 阶段 0：问题定义

### 1.1 产出：调研目标书

动手搜索前，必须明确并记录：

| 字段 | 说明 | 示例 |
|------|------|------|
| 调研目标 | 要回答的核心问题（≤3个主问题） | 市场格局、各家策略、未来趋势 |
| 主线对象 | 深度调研对象（重点投入） | WorkBuddy、千问/QoderWork、纳米Work |
| 备选对象 | 浅调研对象，横向参照 | TRAE、网易有道、智谱、MiniMax、Manus |
| 输出形态 | 报告的载体与结构 | 分级结论报告（MD） |
| 调研预算 | 搜索轮次上限、时间上限 | ≤30次搜索 / 2小时 |

### 1.2 边界规则（动态开放）

- 备选对象**不设硬性排除**。调研中发现某备选对象在特定维度表现突出时，**主动建议将其纳入对比项**
- 若某维度下备选对象明显优于主线对象，标注"若关注XX维度，某产品是更佳选择"
- 边界是"调研重心"而非"信息禁区"

---

## 2. 阶段 1：来源分层与采集

### 2.1 来源可信度系数（CR, Credibility Rating）

每条证据按其来源层级赋予 0-1 的 CR 系数：

| 级别 | 来源类型 | CR系数 | 可验证性 | 用途 |
|------|----------|--------|----------|------|
| S1 | 产品官网 / 官方文档 / 官方定价页 / 发布会实录 | 0.90 | 高（官方一手） | 功能事实、定价、产品定位 |
| S2 | 第三方研究机构（易观、IDC、艾瑞、Gartner）公开报告/摘要 | 0.85 | 中高（方法论公开） | 市场规模、增长数据 |
| S3 | 主流媒体（新浪、36氪、钛媒体、晚点LatePost） | 0.70 | 中（有审核但受立场影响） | 事件、战略动作、融资 |
| S4 | 用户社区（知乎、即刻、B站、小红书、应用商店评论） | 0.50 | 低（个人主观） | 真实痛点、体验细节 |
| S5 | 自媒体/博客/未验证渠道 | 0.30 | 极低 | 线索、假设来源 |

### 2.2 证据卡片记录格式

每条采集到的信息必须记录为一张证据卡片：

```markdown
- 事实陈述：〈一句话描述〉
- 来源：〈URL〉
- 来源级别：S〈1-5〉
- CR系数：〈0.30-0.90〉
- 时点：〈YYYY-MM-DD〉
- 原始出处：〈若为媒体转引，标注其引用的一手来源〉
```

### 2.3 关键词矩阵采集

按"主线对象 × 调研维度"建立矩阵，每个格子生成搜索关键词：

| 对象 \ 维度 | 功能 | 定价 | 用户反馈 | 版本更新 | 战略动态 |
|-------------|------|------|----------|----------|----------|
| 对象A | A 功能介绍 | A 价格 | A 吐槽 缺点 | A 更新日志 | 厂商 A 战略 |
| 对象B | B 功能介绍 | B 订阅 价格 | B 体验 | B 更新 | 厂商 B 战略 |
| 对象C | C 功能介绍 | C 会员 价格 | C 体验 差评 | C 更新 | 厂商 C 战略 |
| 市场整体 | 办公智能体 市场报告 | — | — | — | 竞争格局 |

### 2.4 用户反馈加权模型（六维加权）

S4 层反馈按维度打权，防止噪音污染结论：

| 反馈维度 | 加权系数 | 判定标准 |
|----------|----------|----------|
| 恶意吐槽/情绪宣泄 | 0.05 | 无具体场景、纯情绪、攻击性语言 |
| 无效灌水/广告 | 0.05 | 无实质内容、复制粘贴、推广性质 |
| 主观偏好表述 | 0.40 | 有观点但无依据 |
| 客观体验描述 | 0.60 | 有具体使用场景和过程 |
| 指出实际问题 | 0.85 | 指出具体功能缺陷或故障 |
| 提出改进建议 | 0.95 | 有建设性的改进方案 |

**应用规则**：
- 每条反馈按其最高匹配维度取系数
- 同类反馈聚合后再乘以维度系数
- **核心结论不依赖 S4 层**：S4 只用于"发现假设"和"痛点验证"，不用于"验证结论"

## 3. 阶段 2：交叉验证（含反驳搜索）

### 3.1 验证三件套

进入报告的事实级结论，必须依次通过三项验证：

| 验证项 | 规则 | 不通过的处理 |
|--------|------|--------------|
| ① 支持性验证 | 关键结论须 ≥2 个独立来源一致 | 降级为🔶推断 |
| ② 反驳性验证 | 对关键结论搜反向关键词，尝试推翻（"X 翻车 / X 争议 / X 数据质疑"） | 发现反证 → 并列呈现或降级 |
| ③ 独立性检查 | 两个来源须无共同利益关联（如不能都是厂商系媒体） | 视为单源，不能算交叉验证 |

### 3.2 冲突处理规则

| 冲突类型 | 处理规则 |
|----------|----------|
| 官方说法 vs 媒体报道不一致 | 以官方为准，媒体说法标注"另一种说法" |
| 两份媒体数据不一致 | 回溯两者引用的原始出处，以原始报告为准 |
| 用户吐槽 vs 官方宣称 | 不裁断对错，并列呈现，标注"存在争议" |
| 数据时点不一致 | 优先最近时点，并标注所有数据时点 |

### 3.3 时效衰减

- 每条事实性数据必须带**时点戳**
- 超过 N 个月（默认3个月，可按行业调整）的数据，报告中标注"可能已过时"
- 关键结论优先使用 30 天内的数据

---

## 4. 阶段 3：结论分级与输出

### 4.1 结论证据等级

| 标签 | 含义 | 判定标准 |
|------|------|----------|
| ✅ 事实 | 多源交叉验证 + 通过反驳搜索 | 2个以上独立来源 + 无反证 |
| 🔶 推断 | 基于事实的逻辑外推 | 有事实基础，但无法直接验证 |
| ❓ 未知 | 信息不足，无法判断 | 无公开数据或单源不可验证 |

### 4.2 每条结论的完整格式

```
【结论】〈一句话结论〉
【等级】✅事实 / 🔶推断 / ❓未知
【证据链】〈来源级别 + URL + 时点〉
【可信度贡献】〈CR系数计算过程〉
【建议】〈行动建议，见4.4〉
```

### 4.3 报告整体可信度评分

```
报告可信度 = [ Σ(结论权重 × 来源CR) / Σ(结论权重) ] × 校准系数
```

- **结论权重**：按结论对回答主问题的重要性设定（1-5）
- **校准系数**：报告完成后抽查 3 条关键结论，独立可验证率（如 3 条中 2 条可验证 → 0.67）
- 报告末尾必须输出评分，并标注：
  > "本评分为基于来源可信度的相对指标，不代表事实绝对正确性。评分方法：……"

### 4.4 结论行动建议（强制项）

每条结论必须附带下一步建议（至少一条）：

| 建议类型 | 触发条件 | 示例表述 |
|----------|----------|----------|
| 增加对比项 | 备选产品在特定维度表现突出 | "建议将TRAE加入开发者体验对比" |
| 增加分析框架 | 现有框架无法解释某现象 | "建议引入波特五力分析企业级壁垒" |
| 减少分析维度 | 某维度信息量过低 | "用户社区样本不足，建议弱化该维度" |
| 细化搜索 | 关键问题证据不足 | "建议定向搜索XX企业客户案例" |
| 人工补充 | 信息墙无法穿透 | "建议人工获取IDC完整报告/试用产品" |
| 人工分析 | 需主观判断的战略问题 | "建议结合内部数据验证市场增速" |

## 5. 阶段 4：复盘与迭代

### 5.1 缺口清单

报告完成后输出：

- 哪些关键问题没有答案？
- 哪些数据只有单源？（列出具体条目）
- 哪些被付费墙/信息墙挡住？（如易观/IDC完整报告）
- 哪些结论存在反证未解决？

### 5.2 迭代决策

根据缺口清单判断：
- 是否发起第二轮定向调研？
- 是否转人工（获取付费报告、实测产品、专家访谈）？
- 是否调整调研目标或主线对象？

---

## 6. 硬性纪律（防自我欺骗）

调研全过程中必须遵守，违反即视为调研无效：

1. **禁止**用 S4 层验证任何结论（只能发现假设）
2. **禁止**将单源信息表述为事实（一律标注"单源"）
3. **必须**标注每条数据的时点
4. **必须**执行反驳搜索（即使结论"显然正确"）
5. **必须**在报告中公开评分方法与局限，不假装客观
6. **必须**为每条结论附带行动建议
7. **禁止**固守初始边界，发现更佳对比项必须主动建议

---

## 7. 已知局限（本 SOP 无法解决）

| 局限 | 说明 | 缓解方式 |
|------|------|----------|
| 付费报告墙 | 易观/IDC/Gartner 完整报告需购买，只能拿到摘要 | 转人工补充 |
| 无一手验证 | 无法实测产品、无法做问卷 | 建议用户实测 |
| 信息时效 | 公开信息滞后于市场变化 | 时点戳 + 衰减标注 |
| 来源主观性 | 官方选择性展示，媒体有立场 | 多源 + 独立性检查 + 反驳搜索 |
| CR系数主观预设 | 0.90/0.85/0.70 等为经验值，无业界标准背书 | 校准系数 + 公开评分方法 |
| 公开信息天花板 | 留存率、DAU、内部战略不可得 | 标注为❓未知 |

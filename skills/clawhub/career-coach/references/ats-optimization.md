# ATS 优化 Playbook

> ATS（Applicant Tracking System，申请人追踪系统）是招聘方用来收集、解析、检索简历的软件。
> 它**不会自动拒绝你**——这是最大的误解。它做的是解析和排序，真正的淘汰仍由人完成。
> 你要解决的是两个问题：**能不能被正确解析**、**能不能在检索中被搜到**。

## 一、纠正三个流行误解

| 流言 | 事实 |
|------|------|
| "ATS 会自动打分并拒掉低分简历" | 主流系统（Workday、Greenhouse、Lever、Ashby）默认不自动拒。招聘方用关键词**搜索/筛选**，未命中 = 搜不到，不是被拒 |
| "简历必须纯文本、不能有任何格式" | 现代 ATS 能处理常规 PDF 排版。真正致命的是**多栏、表格、文本框、图片化文字** |
| "关键词堆得越多越好" | 白字堆词、页脚塞词会被人工看到并直接判负。检索命中只是入场券，人读得下去才有用 |

## 二、解析层：让机器读懂你的文件

### 格式白名单

| 项 | 安全做法 | 危险做法 |
|----|---------|---------|
| 文件类型 | 文本层完整的 PDF；不确定时用 .docx | 扫描版 PDF、图片、.pages、.odt |
| 布局 | 单栏，从上到下线性 | 双栏、侧边栏（左侧技能栏是最常见的解析灾难） |
| 内容容器 | 普通段落 + 无序列表 | 表格、文本框、SmartArt、图表 |
| 字体 | Arial / Calibri / Georgia / 思源黑体，10–12pt | 花体、图标字体、极小字号 |
| 关键信息位置 | 正文首屏 | 页眉、页脚（部分解析器直接丢弃） |
| 图形 | 无 | 头像、进度条式技能图、logo |
| 日期格式 | `2023.03 – 2025.06` 全篇统一 | 混用 `Mar 2023`、`23/03`、`三月` |

### 章节标题用标准词

解析器靠标题切分段落。用它认识的词：

```
✓ 工作经历 / Work Experience / Professional Experience
✓ 教育背景 / Education
✓ 技能 / Skills / Technical Skills
✓ 项目经历 / Projects

✗ 我的旅程 / What I've Built / 关于我 / 履历轨迹
```

创意标题留给作品集，不要放在简历上。

### 自检方法（30 秒）

把 PDF 用文本方式打开或全选复制到纯文本编辑器：

- 文字能不能选中？选不中 = 图片化，ATS 完全读不到
- 复制出来的顺序对不对？乱序 = 多栏或文本框问题
- 有没有丢失的段落？丢失 = 在页眉页脚或表格里

这个测试能抓住 90% 的解析事故。

## 三、检索层：关键词策略

### 关键词从哪来

**唯一正确来源是 JD 本身**，不是关键词大全。方法：

1. 复制 JD 全文
2. 标出所有名词性技术/能力/工具词
3. 按出现次数和位置排序（标题 > 职责前 3 条 > 加分项）
4. 对每个词自问：我有对应经历吗？

### 三类词都要覆盖

| 类型 | 例子 | 放哪 |
|------|------|------|
| **硬技能/工具** | Kubernetes、SQL、Figma、A/B 测试 | 技能区 + 经历里的具体使用场景 |
| **岗位/领域术语** | 增长运营、供应链计划、服务网格 | 摘要 + 经历标题 |
| **认证/资质** | PMP、CPA、AWS SA | 独立章节，全称 + 缩写都写 |

### 同义词与缩写：两个都写

ATS 大多做精确/前缀匹配，不做语义理解。检索者可能搜任一种写法：

```
✓ 机器学习（Machine Learning, ML）
✓ Kubernetes (K8s)
✓ 项目管理专业人士（PMP）
✓ 客户关系管理（CRM）
```

首次出现时写「全称（缩写）」，之后可只用一种。

### 埋词的正确位置

关键词必须**长在句子里**，不能孤立堆放：

```
✗ 技能：Kubernetes, Docker, Terraform, Prometheus, Grafana, ArgoCD, Istio,
       Helm, Jenkins, GitLab CI, Ansible, Vault, Consul, Envoy...

✓ 技能：容器与编排（Kubernetes、Docker、Helm）｜ IaC（Terraform、Ansible）
       ｜ 可观测性（Prometheus、Grafana）
✓ 经历：主导 Kubernetes 集群从 3 节点扩展到 40 节点，用 Terraform 管理全部
       基础设施变更，故障平均恢复时间从 45 分钟降至 8 分钟
```

第二种写法同时满足机器检索和人类阅读——**这是唯一目标**。

### 匹配度自测

粗略估算：把 JD 里前 10 个核心关键词列出，数简历命中几个。

| 命中 | 判断 |
|------|------|
| 8–10 | 匹配良好，可投 |
| 5–7 | 检查未命中项：是表达问题还是真的没有 |
| ≤4 | 岗位不匹配，投了大概率浪费；或需要先补经历 |

**注意**：匹配分是自查工具，不是通过率预测。7 分匹配 + 强成果 优于 10 分匹配 + 全是职责陈述。

## 四、绝对不要做

- 白色字体或 1pt 字号堆关键词（人工一看即判负，部分公司直接拉黑）
- 页脚塞满 JD 原文
- 罗列没做过的技术（面试第一个问题就穿帮）
- 为凑关键词把经历改成别人的事
- 同一份简历海投所有岗位后抱怨 ATS

## 五、不同渠道的策略差异

| 渠道 | ATS 影响 | 侧重 |
|------|---------|------|
| 公司官网投递 | 最高，标准 ATS 流程 | 格式与关键词都要做足 |
| LinkedIn / 招聘平台 | 中，平台自身搜索为主 | 见 [personal-branding.md](personal-branding.md)，档案关键词比简历更重要 |
| 内推 | 最低，简历直达用人经理 | 主攻 L3 说服力，格式够干净即可 |
| 猎头 | 低，猎头会重新包装 | 提供信息完整版，让猎头有素材 |

**内推能绕过大部分 ATS 环节**——与其花三小时抠关键词，不如花一小时找一个内推人。

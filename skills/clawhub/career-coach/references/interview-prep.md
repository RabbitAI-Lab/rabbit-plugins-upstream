# 面试准备 Playbook

> 面试不是考试，是**双向的风险评估**。对方在评估"招错人的风险"，你在评估"来错地方的风险"。
> 准备的核心不是背答案，而是把自己的经历整理成可随时调用的证据库。

## 一、题型地图

| 面试类型 | 考察 | 主要方法 | 准备重点 |
|---------|------|---------|---------|
| 行为面试 | 过去行为预测未来表现 | STAR / CARL | 故事库（见第三节） |
| 技术深挖 | 真实掌握程度 | 追问到底 | 自己简历上每个技术点的边界 |
| 系统设计 | 复杂问题拆解 | 白板/口述 | 结构化流程 + 权衡意识 |
| 案例分析 | 商业/产品判断 | 框架 + 数据 | 结构化拆解 + 假设验证 |
| 编码 | 基础功底 | 现场写码 | 边说边写的习惯 |
| 反问环节 | 你的思考深度 | 提问 | 见第七节 |

## 二、通用准备（所有面试共用）

### 一小时准备法

| 时间 | 做什么 |
|------|--------|
| 15 分钟 | 重读自己的简历，标出每一条**可能被追问**的地方 |
| 15 分钟 | 研究公司：主营业务、近期动态、这个岗位为什么存在 |
| 15 分钟 | 准备 3 个核心故事（见下）+ 1 分钟自我介绍 |
| 15 分钟 | 准备 5 个反问，其中至少 2 个针对这家公司 |

### 一分钟自我介绍模板

```
[现在是谁] 我目前在 X 做 Y，主要负责 Z 方向
[关键成果] 过去两年最有代表性的是 [一个带数字的成果]
[为什么来] 我对贵司的 [具体的某件事] 很感兴趣，因为 [和自己经历的连接]
```

不要复述简历时间线。60–90 秒，超过就是灾难。

## 三、行为面试：故事库法

### STAR 与 CARL

```
STAR: Situation 情境 → Task 任务 → Action 行动 → Result 结果
CARL: Context 背景 → Action 行动 → Result 结果 → Learning 收获
```

STAR 适合成功案例，CARL 适合失败/冲突类问题（多了反思环节，正是考官想听的）。

**时间配比**：S/T 占 20%，A 占 60%，R 占 20%。绝大多数人把背景讲了三分钟，
行动一句带过——这是行为面试的头号失败模式。

### 构建 6 个故事覆盖 80% 的题

不要为每道题准备答案，准备 6 个**可复用**的故事：

| 故事类型 | 覆盖的常见问题 |
|---------|--------------|
| 1. 最有成就感的项目 | 最大成就？最自豪的事？介绍一个项目 |
| 2. 一次失败或严重失误 | 最大失败？犯过的错？如何面对挫折 |
| 3. 一次冲突或说服他人 | 和同事意见不合？如何说服别人？难搞的合作方 |
| 4. 一次在压力/模糊中推进 | 时间紧任务重？需求不明确怎么办？多线程 |
| 5. 一次主动发起的改变 | 主动做过什么？超出职责范围的事？影响力 |
| 6. 一次快速学习 | 如何学新东西？不熟悉的领域怎么上手 |

每个故事写成 STAR 结构的 150 字提纲，练到能自然口述。面试时按题目调整侧重点即可。

### 失败类问题的正确答法

考官想验证三件事：**你敢不敢承认**、**你归因是否诚实**、**你有没有改变**。

```
✗ "我的缺点是太追求完美"（无效，人人都这么说）
✗ "那次失败主要是因为需求方一直变"（外部归因，红旗）
✓ "我低估了迁移的复杂度，只做了功能测试没做性能压测，上线后 P99 涨了 3 倍，
   回滚花了 4 小时。之后我在团队里推了变更前必须有性能基线的规矩，
   后来三次大迁移都没再出问题。"
```

真实的失败 + 具体的代价 + 可验证的改变。

## 四、技术深挖：守住自己的边界

### 简历自审

对简历上每一个技术名词问自己三层：

1. 我用它做过什么具体的事？
2. 我遇到过什么坑？怎么解决的？
3. 它的原理是什么？什么场景下不该用它？

**答不出第 2 层的技术就不要写在简历上**。写了就等于邀请追问。

### 不会时怎么说

```
✗ 沉默 / 硬编
✓ "这个我没有直接实践过。我的理解是 [说出你知道的部分]，
   如果要落地我会先 [具体的验证路径]。"
```

坦诚 + 展示思考路径 > 编造。技术面试官几乎都能识别硬编。

## 五、系统设计：五步流程

不要一上来就画框图。按固定流程走，流程本身就是分数：

```
1. 澄清需求（3–5 分钟）
   用户量级？读写比？延迟要求？一致性要求？哪些功能算 MVP？

2. 估算规模
   QPS、存储量、带宽。数量级对就行，展示的是有没有量化意识

3. 画顶层架构
   客户端 → 接入层 → 服务 → 存储。先跑通主链路

4. 逐个深挖
   面试官会挑一个点让你展开：数据模型、缓存、分片、一致性

5. 讨论权衡与瓶颈
   主动说出你的方案在什么情况下会挂、怎么演进
```

**评分的核心是第 1 步和第 5 步**。跳过澄清直接设计是最常见的扣分点；
不主动说权衡会被认为缺乏工程判断。

## 六、案例分析：先结构后数字

```
1. 复述问题，确认理解一致
2. 提出拆解框架（收入 = 流量 × 转化 × 客单价 这类）
3. 说出你的假设，并主动标注哪些需要验证
4. 逐支分析，边算边说思路
5. 给结论 + 下一步该看什么数据
```

面试官关心的是拆解是否 MECE、假设是否合理、有没有主动量化，而不是最终数字对不对。

## 七、反问环节：这是加分题不是客套

准备 5 个，现场挑 2–3 个问。分三类：

| 类型 | 例子 |
|------|------|
| **岗位真实性** | 这个岗位为什么现在开？上一任为什么离开？前 90 天最希望我解决什么？ |
| **团队与协作** | 团队现在最大的瓶颈是什么？和 X 部门怎么协作？ |
| **评价标准** | 一年后怎么判断这个人招对了？ |

避免问：薪资福利（留给 HR 环节）、"贵司文化怎么样"（空泛）、
官网首页就有答案的问题（暴露没做功课）。

**最有信息量的一问**：「这个岗位为什么现在开？」——扩编、补缺、还是救火，
答案直接决定你要不要去。

## 八、模拟练习的正确用法

自己想答案和说出来完全是两回事。有效练法：

- **录音回放**：说 2 分钟自己听，会立刻发现啰嗦和口头禅
- **一次一题深挖**：让教练/搭档在你答完后连追三层，模拟真实压力
- **限时**：行为题 2 分钟内讲完，系统设计 30 分钟走完五步

不要通篇背诵——背出来的答案在追问第二层就散架。

## 九、面试后

- 24 小时内发感谢信：3 句话（感谢 + 复述一个你们聊到的点 + 补充一句当时没说好的）
- 记录被问倒的题，当晚补掉——同一个短板不该在下一场再挂一次
- 无论结果，把这场的新故事补进故事库

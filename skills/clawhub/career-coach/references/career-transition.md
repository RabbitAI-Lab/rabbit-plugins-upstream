# 职业转型与晋升 Playbook

> 转型的本质是**用可迁移能力换取新领域的入场券**，晋升的本质是**先做上一级的事再拿上一级的名**。
> 两者的共同点：都不是靠申请，是靠证据。

## 一、转型：先分类，路径完全不同

用两个维度切：换**职能**、换**行业**。

| 类型 | 难度 | 策略 |
|------|------|------|
| 同职能 + 换行业 | 低 | 强调职能专业度，快速补行业词汇 |
| 换职能 + 同行业 | 中 | 强调行业理解，用内部转岗或相邻岗位过渡 |
| 换职能 + 换行业 | 高 | **不要一步到位**，拆成两步走 |

**双换是转型失败的头号原因**。正确做法是先换一个维度站稳，1–2 年后再换另一个。
例如：金融业分析师 → 想做互联网产品经理，中间可以走「金融科技公司的产品/策略岗」。

## 二、可迁移能力盘点

不要问"我会什么"，问"我做成过什么，其中哪部分换个场景还成立"。

| 类别 | 例子 | 迁移性 |
|------|------|--------|
| 领域知识 | 特定行业规则、监管、业务流程 | 低（换行业即失效） |
| 工具技能 | 某个具体软件、框架 | 中（可快速补） |
| 方法能力 | 数据分析、结构化拆解、项目推进、用户研究 | **高** |
| 人际能力 | 跨部门协作、谈判、带团队、向上管理 | **高** |
| 元能力 | 快速学习、模糊环境下决策、从 0 搭建 | **最高** |

转型简历应该**以方法能力和元能力为骨架**，用原领域的例子做证据。

### 重述练习

```
原：负责保险理赔案件的审核与风险评估（3 年，日均 40 单）
转产品岗：设计并执行结构化评估流程，日处理 40+ 复杂案例，
         通过规则梳理将平均处理时长压缩 30%——这是流程设计 + 规则抽象能力
转数据岗：基于历史案件数据构建风险判断标准，识别高风险特征组合，
         使误赔率下降——这是特征工程 + 数据驱动决策能力
```

同一段经历，换目标就换叙事重心。这不是编造，是选择性强调。

## 三、补差距：最小可行证据

转型者被拒的真实原因通常不是"缺经验"，而是**没有任何可验证的新领域产出**。

按投入产出排序：

| 做法 | 说服力 | 周期 |
|------|--------|------|
| 在现岗位承接目标职能的工作 | **最高** | 3–6 个月 |
| 内部转岗 | 最高 | 视机会 |
| 真实的副业/自由职业项目 | 高 | 1–3 个月 |
| 开源贡献 / 公开作品 | 中高 | 1–3 个月 |
| 完整的个人项目（有真实用户更好） | 中 | 1–2 个月 |
| 认证/课程证书 | 低 | 1–3 个月 |

**证书是最低效的路径**，因为它证明的是"学过"而不是"做成过"。
只在硬性门槛场景（如某些合规岗位）才值得投入。

**性价比最高的是第一条**：在现在的岗位上，主动接一块目标职能的活。
成本最低、真实度最高、还能带薪试错——如果做了半年发现不喜欢，你省下了一次错误转型。

## 四、转型简历与叙事

- 用「相关经历」替代「工作经历」，把可迁移的部分排在前面
- 摘要必须直接回答"为什么转"和"凭什么能做"
- 用目标领域的术语，不要用原行业黑话
- 主动放上新领域的作品链接
- 不要为了显得对口而弱化原领域的成就——你的差异化恰恰在跨界

### 转型动机的说法

```
✗ "原来的行业不行了" / "我不喜欢原来的工作"（逃离型叙事，红旗）
✓ "我在做 X 的过程中发现，真正让我投入的是 Y 这部分，
   所以过去一年我系统地做了 [具体动作]，现在希望全职做这件事。"
```

**逃离型 vs 奔赴型**：面试官几乎都在识别这一点。有具体动作支撑的奔赴型叙事才可信。

## 五、晋升：名分滞后于事实

组织给出晋升的判断标准通常是「**这个人已经在做那一级的事了，只是名没给**」，
而不是「他很努力，应该给个机会」。

### 三个必要条件

| 条件 | 含义 | 怎么做 |
|------|------|--------|
| **已经在做上一级的事** | 影响范围超出当前职级 | 主动承接跨团队、有不确定性的项目 |
| **有人证明** | 不只上级，还有平级和相关方 | 让工作被看见，主动同步进展 |
| **有位置** | 组织有需求和编制 | 判断团队是否在增长，否则考虑外部 |

三者缺一都不会成。第三条经常被忽略——在一个不增长的团队里，
把前两条做到满分也只是等待。

### 提前 6 个月准备

```
T-6 月：和上级明确对齐"到什么程度可以升"，拿到具体标准
T-5~T-1：按标准补齐，每月同步进展
T-1 月：整理成果材料（成果清单 + 影响范围 + 他人评价）
T：正式申报
```

**最关键的是 T-6 的那次对话**。没有对齐标准就埋头干，
到评审时才发现方向不对是最常见的失败。

### 材料写法

同简历的四级阶梯（见 [resume-crafting.md](resume-crafting.md)），额外强调两点：

- **影响范围**：从"我完成了"升级到"我使团队/多个团队能够"
- **不可替代性**：这件事换个人做会怎样

## 六、什么时候该走而不是升

以下信号出现两个以上，考虑外部机会：

- 团队在收缩，编制冻结超过一年
- 上级自己晋升停滞，无法为你争取
- 连续两个周期"差一点"，但说不清具体差什么
- 你的能力增速已明显超过岗位需求
- 内部涨薪幅度长期低于市场

**外部跳槽的职级/薪资涨幅通常显著高于内部晋升**，但代价是重新建立信任成本。
一个粗略的判断：如果内部一年能升，就留下；需要两年以上，看外部。

## 七、转型/晋升共用的一条底层逻辑

```
先做，后要。
不是"给我机会我就能做"，而是"我已经在做，请给我对应的名分/岗位"。
```

这条逻辑同时解释了：为什么证书没用、为什么内部转岗比外部转型容易、
为什么晋升要提前 6 个月准备。证据永远先于身份。

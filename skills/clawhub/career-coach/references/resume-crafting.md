# 简历撰写 Playbook

> 简历不是履历流水账，是一份**针对特定岗位的证据材料**。招聘方读简历只回答一个问题：
> "这个人过去做成的事，能不能预测他在我这里也能做成？"

## 一、读者模型：三层过滤

| 层 | 谁在读 | 停留时长 | 关心什么 | 失败点 |
|----|--------|---------|---------|--------|
| L1 | ATS 系统 | 0 秒 | 关键词、可解析结构 | 格式解析失败、关键词缺失 |
| L2 | HR / 招聘专员 | 6–15 秒 | 硬门槛（年限、学历、公司、技术栈） | 门槛项埋太深、要读第二页才看到 |
| L3 | 用人经理 | 1–3 分钟 | 做成过什么、量级、可迁移性 | 只写职责不写成果 |

写简历时**倒着写**：先满足 L3 的说服力，再压缩到 L2 的 15 秒扫读，最后做 L1 的格式与关键词适配。
只优化 L1 会得到一份 ATS 满分但人看不下去的简历。

## 二、结构：模块顺序不是固定的

标准顺序（有对口经验的求职者）：

```
姓名 + 联系方式 + 一句话定位
├── 核心能力摘要（3–4 行，可选但推荐）
├── 工作经历（倒序，最详细）
├── 项目经历（无项目型岗位可并入工作经历）
├── 技能清单
└── 教育背景
```

**什么时候调整顺序：**

| 情况 | 调整 |
|------|------|
| 应届 / 毕业 3 年内 | 教育背景上移到工作经历之前 |
| 转行 | 用「相关经历」替代「工作经历」，把可迁移的部分提前 |
| 技术岗，作品能自证 | 项目经历上移，附 GitHub / 作品集链接 |
| 空窗期较长 | 加「近期投入」章节（进修、开源、自由职业），不要留空白让人猜 |
| 15 年以上经验 | 早期经历压缩为一行"更早经历：X 公司 Y 岗位（2008–2012）" |

**长度**：10 年以内经验 → 1 页。10 年以上或研究型岗位 → 2 页。永远不要 1.5 页——
要么压到 1 页，要么充实到 2 页，半页空白会显得内容不够。

## 三、Bullet 写法：从职责到成就

### 弱→强的四级阶梯

```
L0 职责陈述    "负责用户中心模块的开发和维护"
L1 加动作      "使用 Spring Boot 重构用户中心模块"
L2 加结果      "重构用户中心模块，接口响应时间明显下降"
L3 加量化      "重构用户中心模块，P95 响应时间从 800ms 降至 120ms"
L4 加影响      "重构用户中心模块，P95 从 800ms 降至 120ms，支撑日活从 50 万增长到 200 万"
```

目标：**每段经历至少 2 条 L3/L4**，其余可以是 L2。全篇 L0 是最常见的失败模式。

### 公式

```
[动作动词] + [具体对象] + [方法/技术] + [可量化结果] + [业务影响]
```

### 量化：没有数字时怎么办

大多数人卡在"我的工作没法量化"。三种替代量化路径：

| 路径 | 例子 |
|------|------|
| **规模量化** | "维护服务日均处理 300 万请求" / "管理 12 人跨职能团队" |
| **相对量化** | "将发布频率从两周一次提升到每日多次" / "缺陷回归率下降约三分之一" |
| **范围量化** | "覆盖 8 条产品线、全国 23 个区域仓" |

绝对数字拿不到时用相对值和范围，**但不要编造精确数字**——面试会追问推导过程。

### 动词选择

避免：负责、参与、协助、跟进、支持（这些词不传递任何信息）

按贡献类型选择：

- 从 0 到 1：设计、搭建、创建、引入、落地
- 从 1 到 N：优化、重构、扩展、提效、治理
- 影响他人：主导、推动、协调、说服、培训
- 修复问题：定位、诊断、修复、消除、降低

## 四、针对岗位定制：JD 反向工程

不要一份简历投所有岗位。每次投递做 10 分钟定制：

1. **拆 JD**：把 JD 分成「硬门槛」（年限/学历/必备技术）、「核心职责」（前 3 条最重要）、「加分项」
2. **建映射表**：每条核心职责，在自己经历里找一条最强证据
3. **重排 bullet**：把命中的证据提到每段经历的第 1–2 条
4. **对齐术语**：JD 说"服务治理"就别写"微服务运维"，用它的词（同时也是 ATS 关键词策略）
5. **补摘要**：核心能力摘要针对该岗位重写 2–3 行

**没有映射到的核心职责**就是面试会被追问的短板，提前准备说法。

## 五、常见失败模式

| 症状 | 根因 | 修法 |
|------|------|------|
| 投了很多没回音 | ATS 过滤或岗位不匹配 | 见 [ats-optimization.md](ats-optimization.md)；同时检查是否海投同一份 |
| HR 电话问的都是简历上有的 | 简历信息密度太低 | 删掉常识性描述，补成果和量级 |
| 面试官说"看不出你做了什么" | 全篇 L0 职责陈述 | 按四级阶梯逐条升级 |
| 简历很满但记不住 | 无重点，全是同等权重 | 每段经历只留 3–5 条，砍掉次要的 |
| 转行简历石沉大海 | 用原行业语言描述 | 用目标行业术语重述可迁移能力 |

## 六、终稿检查清单

- [ ] 15 秒扫读能说清"这人是干什么的、什么级别"
- [ ] 每段经历有 ≥2 条带数字的成果
- [ ] 无「负责/参与/协助」开头的 bullet
- [ ] 所有数字自己能解释出推导过程
- [ ] 时间线无解释不了的空白
- [ ] 针对本次岗位定制过（不是通用版）
- [ ] 文件名规范：`姓名_岗位_简历.pdf`
- [ ] 联系方式在第一屏，且真实可达
- [ ] 通篇时态、标点、格式统一
- [ ] 找一个不了解你工作的人读，能复述出你的价值

## 七、诚信边界

可以做：优化表达、突出相关性、用相对量化、合并同类经历。

不可以做：虚构公司或职位、夸大职级、把团队成果说成个人独立完成、编造精确数字、
伪造时间线掩盖空窗。这些在背调和深度面试中几乎必然暴露，代价远大于收益。

# 问询函答复核对 · 监管问询逐条拆解

**定位**：把一份监管问询函拆成一张**每一问都能对到它答复**的核对表。
监管机关问了什么、要求提供什么材料、公司答了什么、还差哪几份文件——四栏摆开，缺的显式点名。

**不是**代写回复，不是合规意见，不是「能不能过会」的判断。

## 0. 什么时候用 / 不用

| 你要 | 用什么 |
|---|---|
| 把问询函逐条拆开、看看哪一问还没答、还缺哪几份回复文件 | **本 skill** |
| 帮我起草回复文本、帮我写答复 | 不做——那是代拟，本件只做核对 |
| 这份回复能不能过审、会不会被处罚 | 不做——判断位一律 `[待人工]` |
| 公告事件的五段速读卡 | `event-brief-cn` |
| 尽调清单里监管函／问询函／警示／处罚的登记 | `dd-checklist` |
| 发行条款（定增十条款、可转债八条款） | `placement-terms-cn` / `convertible-bond-terms-cn` |

**与 `dd-checklist` 的分界**：那一件把问询函归到「合规与处罚」一类，登记的是一条**带锚的事件行**——何时、何种函、涉及谁。本件不登记「有这封函」，本件登记函里**问了哪几条、答了哪几条、哪条没答**。前者是事件，后者是条款对照。

## 1. 问询函原件从哪来（这条先说清，它决定本件不做抓取）

**交易所问询函的函件原文，在公开公告库里没有正式通道。** 不是没查，是查得到的只有两侧的壳：

- 巨潮全文检索里，「问询函」命中的绝大多数是**公司侧的回复公告**，另一小部分是公司自己发的「关于**收到**……问询函的公告」——那是告知，不含问题正文。
- 上交所、深交所自建的「监管问询」频道页面在，但查询接口的返回为空；北交所跳转。

所以本件**不提供、也不假装提供「自动抓取问询函原文」**。函件原件由你自己贴进来或给本地路径，本件只负责拆条与核对。

能自动拿到的是**回复侧**：回复公告、年报／半年报、募集说明书（发行场景）。本件把这一侧排成骨架并核对齐备性。

## 2. 六节形制

一份合格的核对表必须有且仅有这六节，顺序固定：

| # | 节 | 记什么 |
|---|---|---|
| 1 | 问询事项索引 | 函里每一问，一条一行：`- 问题N <事项>「原句」〔锚：…〕[S#]` |
| 2 | 要求提供的材料 | 每一问要求提供的材料，逐条挂原句与锚 |
| 3 | 回复要点 | 每一问的答复要点；**没答的写 `- 问题N 未取到：<缺什么>`** |
| 4 | 回复文件 | 这一条问询一共出了哪几份：`- 主体：<公司／会计师／保荐／律师>｜[S#]` |
| 5 | 未取到清单 | 缺什么逐条点名；零缺口写 `- 未取到：无` |
| 6 | 来源 | 每条来源一行，带可点 URL 与检索日 |

另有一节 `## 来源` 承接来源行，它不塞进第五节，故独立成节。

## 3. 一条发现长什么样

```
- 问题1 募投项目产能消化「请说明本次募投项目新增产能的消化措施及合理性」〔锚：问询函·第 1 页·问题 1〕[S1]
```

- **原句**：用「」包住，从来源里**连续**摘录，不改写、不拼接。
- **锚**：`〔锚：…〕`，页码、条款号、段落序号之一。
- **编号**：`[S#]` 与来源节那一行对应。

没答的那一问，长这样（没有原句可挂，是设计不是漏网）：

```
- 问题2 未取到：前次募集资金使用明细
```

## 4. 六道机检

判据以 `scripts/check_inquiry_letter.py` 现值为准，本节是口径说明：

1. **IL-STRUCT 形制**：头部四件自标在位；`主体：` 与 `文件：` 在场；六节齐且有序；前三节各至少一条发现行；不得多出第六节以外的栏目。
2. **IL-QUOTE 原句与锚**：前三节每条发现行带「」原句＋〔锚：…〕＋`[S#]`；来源行带 URL 与检索日；引用的编号必须在来源节登记。
3. **IL-PAIR 问题与回复两向点名**（承重格）：索引里每个问题，回复要点节必须有同号条目；回复要点节出现的问题，索引里必须有。两向都判。
4. **IL-GAP 缺项点名**：正文写了未取到而清单没列要发，反之也发；零缺口须显式写 `未取到：无`；`不适用／无此项／无需披露` 一律发。
5. **IL-MEDIA 回复主体齐备性**：一条问询的公开产出通常是 3–5 份，公司本体、会计师事务所、保荐机构／律师各出。只登记了公司本体、而缺项清单里也没点名中介机构那几份 ⇒ 发，提示可能漏取。
6. **IL-LINE 红线**：不得代公司表态、不得出结论。判之前先把行内「」引文整段剥掉——引文是公函原话，不是本件的立场。

## 5. 四条红线（面文与机检同源）

1. **不代拟答复。** 「本公司将」「现回复如下」「特此答复」一类表态词，剥掉引文后仍出现即发。引文里的是原文，本件照抄不算。
2. **不出结论。** 「不构成重大影响」「不存在问题」「风险可控」「回复充分」「预计通过」一类判断零命中——核对的产物是登记表，不是判断书。
3. **没答的不许留空。** 索引里的每一问，回复要点节必须有一条同号记录：要么给要点，要么写 `未取到`。留空等于把没答的藏起来。
4. **缺项不许搪塞。** `不适用`／`无此项`／`无需披露` 是把没查当成没有，与 `未取到` 不是一回事。

另：不给评级与目标价，不写「建议关注」，不预测审核结果。

## 6. 零通道与做法

不给任何数据文件也能先看成品形制：

```bash
python3 scripts/check_inquiry_letter.py --demo
```

`scripts/make_outline.py` 把回复侧材料清单排成骨架，**零通道也能独立跑**：

```bash
python3 scripts/make_outline.py 清单.jsonl 骨架.md
```

清单是 JSONL，每行三键必需：`title`／`url`／`asof`（检索日 `YYYY-MM-DD`），`id` 可省按行序给 `S1`/`S2`…
坏行逐行点名不采信；空清单退 1，不出空壳。**骨架故意过不了机检，是设计**，不是待修。

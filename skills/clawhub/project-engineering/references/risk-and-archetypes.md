# 项目形态与风险分级

## 1. 组合项目画像

项目通常同时命中多个形态。使用标签组合，而不是强行归入唯一类别：

| 项目形态 | 识别线索 | 追加检查 |
|---|---|---|
| 库/SDK | 主要产物被其他项目依赖 | 公共 API、语义版本、消费者兼容、发布包 |
| 业务应用/CRUD | 数据管理、表单、查询、审批 | 权限、归属、事务、校验、迁移、审计 |
| 模块化单体 | 单一主进程、内部模块/业务包 | 模块职责、真实依赖环、共享事务、增量边界 |
| 多服务/分布式 | 多个独立部署进程、远程调用 | 网络失败、契约、追踪、数据所有权、发布顺序 |
| 事件驱动/异步 | 队列、事件、回调、worker | 幂等、顺序、重复、重放、死信、结果未知 |
| 多租户/SaaS | tenant/org 隔离、共享平台 | 服务端归属、数据隔离、配额、计费、越权测试 |
| 边缘/离线 | 现场部署、断网运行、同步回传 | 本地权威、断线恢复、时钟、存储上限、升级回滚 |
| 设备/近实时 | 长连接、控制、遥测、短 TTL | 状态新鲜度、仲裁、看门狗、最终回复、本体安全 |
| AI 辅助 | LLM/模型决定内容或动作 | Schema、白名单、提示注入、置信度、人工确认、审计 |
| 媒体/大文件 | 视频、音频、对象存储 | 旁路传输、授权 URL、容量、转码、隐私和保留 |
| 数据/分析 | 批处理、模型、报表、数据管道 | 数据血缘、可重跑、质量、版本、成本、可解释性 |
| 安全/监管 | 资金、医疗、身份、关键设施 | 正式风险分析、审批、合规证据、职责分离 |

画像来自部署、调用链和业务后果，不来自产品宣传名称。模拟器、stub 或同仓辅助程序不自动意味着微服务。

## 2. 操作模式与目标风险

只读、工作区修改、提交/推送、外部系统写入和生产操作描述的是**操作权限**；`L1`～`L5` 描述的是**目标能力风险**。两者独立判断。例如，对支付或急停逻辑做只读审查，操作模式是只读，但审查深度仍是 `L4/L5`。

### L1：低风险

文档、注释、命名、样式或局部纯函数。执行针对性语法/lint/单测和差异检查，避免扩大重构。

### L2：常规业务

CRUD、查询、表单、单模块业务。检查职责归属、输入、权限/租户、事务、迁移、错误和相关集成测试。

### L3：状态与集成

跨模块、数据库结构、外部 API、消息、异步回调或协议。追加状态机、数据权威源、幂等、顺序、超时、重试、兼容、降级、可观测、契约/模拟器和迁移验证。

### L4：高影响

身份权限、资金、隐私、AI 执行动作、设备控制或不可轻易撤销的外部写入。除 L3 外还要求：

- 默认失败关闭，模型或外部结果不能直接成为执行授权。
- 白名单、结构 Schema、参数范围和目标实体复核。
- HTTP、WebSocket、回调、消息、调度和内部工具等所有可达入口的统一授权边界。
- 确认时重新鉴权并复核当前状态，确认不能提升权限。
- 并发互斥、控制权/租约或等价仲裁。
- 稳定 operationId、审计、结果未知处置和人工恢复。
- 禁止对未知结果盲目自动重试。
- 关键失败路径、故障注入和受控真实环境验收。

### L5：安全或监管关键

可能伤人、破坏关键设施、解除安全保护，或要求正式认证。除 L4 外必须由领域安全负责人确定危险分析、操作条件、审批、现场预案和认证证据。若这些条件缺失，停止执行并报告阻断；不要用软件测试替代功能安全或监管认证。

## 3. 选择方法

1. 标记所有适用项目形态。
2. 判断本次变更的最高后果等级。
3. 使用该等级的基础检查，再叠加所有相关项目形态的专项检查。
4. 按最薄弱的真实验证层报告完成度。

例如：普通后台字段展示通常是 L2；同一系统中的支付回调是 L4；设备状态查询可能是 L2/L3，而解除急停或修改安全联锁是 L5。风险由行为和后果决定，不由文件数量决定。

## 4. 风险升级信号

出现以下情况时提高等级或暂停：

- 一个请求同时跨身份、数据迁移和外部副作用。
- 结果未知但现有接口没有幂等或查询能力。
- 操作会绕过现有权限、审批、控制权或安全链路。
- 新状态没有明确权威源，多个系统都能写入。
- 回滚要求删除或不可逆重写大量数据。
- 真实依赖、协议版本或责任方尚未确认。
- 项目声称满足安全/合规要求，但仓库没有对应证据。

## 5. 不适用的替代

本 Skill 能提高一般软件工程质量，但不能替代威胁建模、渗透测试、功能安全分析、法律/合规意见、财务审计、医疗验证或生产变更审批。相关场景应调用专门流程和负责人。

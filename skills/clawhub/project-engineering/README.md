# Project Engineering

[![Validate Skill](https://github.com/liubai00/project-engineering/actions/workflows/ci.yml/badge.svg)](https://github.com/liubai00/project-engineering/actions/workflows/ci.yml)
[![License: MIT-0](https://img.shields.io/github/license/liubai00/project-engineering)](LICENSE)

> **从新项目架构设计，到现有项目开发、重构和交付，让 AI 按真实工程约束完成工作。**
>
> *Design with constraints. Change with evidence. Deliver with proof.*

[ClawHub](https://clawhub.ai/liubai00/skills/project-engineering) · [English](README.en.md) · [使用手册](docs/USAGE.md) · [更新记录](CHANGELOG.md)

Project Engineering 是面向 Codex、OpenClaw 和其他兼容 Agent Skills 的 Coding Agent 的开源软件工程 Skill。它不是另一个模型，也不是一段“万能提示词”，而是一套让 Agent 在设计或修改代码前先确认工程约束，并以证据完成验证和交付的工作流。默认跟随用户当前语言，不强制中文或英文。

- **新项目**：把业务目标、技术栈、部署、安全和交付条件转化为明确的模块边界、数据与接口设计、测试策略和工程基线；没有事实依据的内容会标记为假设或待决策项。
- **现有项目**：读取仓库规则和真实源码，还原模块职责与调用链，识别可复用能力、影响范围和风险，再进行最小且完整的修改。

## 什么时候使用

当任务是否正确取决于项目架构、调用链、数据、接口、权限、部署或交付约束，而不只是生成一段代码时，使用 Project Engineering。

| 任务场景 | Skill 起到的作用 |
|---|---|
| 从零启动一个软件项目 | 在编码前建立架构与工程基线 |
| 为现有项目增加跨文件、跨层功能 | 找到真实调用链、代码归属和复用点 |
| 修改 API、数据库、消息协议或外部服务 | 检查兼容、迁移、失败处理和回退风险 |
| 重构或接手陌生、遗留项目 | 以源码和配置还原事实，不根据名称猜测 |
| 代码审查、测试验收或准备交付 | 区分代码完成、自动测试、联调和真实验收 |

最简单的判断标准是：

> 如果 Agent 动手前必须先回答“项目应该怎么组织、当前怎么实现、应该改在哪里、会影响谁、如何验证”，就应该使用这个 Skill。

## 使用后有什么不同

| 普通 Coding Agent | 使用 Project Engineering |
|---|---|
| 收到需求后直接生成代码 | 先确认事实、约束、范围和风险 |
| 容易套用熟悉的架构模板 | 根据新项目条件设计，或遵守现有项目架构 |
| 只修改最明显的文件 | 沿真实链路检查入口、业务、数据、配置和测试 |
| 编译通过就认为完成 | 按风险完成分层验证，并明确未验证项 |
| 最终只说“已经完成” | 输出决策依据、修改范围、测试结果和剩余风险 |

## 什么时候不需要使用

- 错别字、单句文案、格式化或内容完全确定的单文件机械修改；
- 与软件工程无关的纯写作或内容生成任务；
- 只需要一次简单转换、且结果不依赖项目上下文的工作。

Project Engineering 也不能替代产品决策、领域专家、专业渗透测试、功能安全认证、法律或合规意见，以及真实环境验收。

## 快速安装与验证

OpenClaw / ClawHub：

```bash
openclaw skills install @liubai00/project-engineering
```

Codex（桌面端 / CLI / IDE）：

```bash
git clone https://github.com/liubai00/project-engineering.git ~/.agents/skills/project-engineering
```

### 现有项目：5 分钟只读验证

安装后，在任意有可执行入口的应用仓库中运行这个零写入案例：

```text
使用 $project-engineering。

只读验证当前仓库：选择一条真实业务入口（HTTP、CLI、消息或定时任务），
追踪到数据库写入或外部副作用。输出入口文件与方法、完整调用链、
权限/事务/状态权威源、一条正常路径与失败路径、现有测试覆盖和未验证项。
每条关键结论附文件路径、配置、命令输出或测试证据。

不要修改文件，不执行会写入外部状态的命令。
```

你将得到：适用工程规则、模块画像、带证据的调用链、主要风险与缺口，以及自动测试和真实环境之间的验证边界。仓库没有业务入口时，可以改为追踪构建、发布或数据处理入口。完整输入与验收方式见[第一次使用：5 分钟只读验证](docs/USAGE.md#第一次使用5-分钟只读验证)。

### 新项目：先建立工程基线

新项目还没有仓库时，不应虚构“现有架构”，也不需要运行 Git 或代码库画像。可以直接使用：

```text
使用 $project-engineering。

为一个从零开始的内部订单管理 API 建立可实施的工程基线，当前只设计、不创建文件。
已确认约束：Java 21、Spring Boot 3.4、PostgreSQL、Docker 单体部署、OAuth 2.0。

请区分已确认约束、合理假设和必须由负责人决定的问题；给出模块边界、
依赖方向、数据归属、API 与权限边界、测试策略、部署与回退基线，以及分阶段实施计划。
不要虚构业务规则，也不要替我选择尚未确认的外部服务。
```

你将得到：约束与假设清单、架构和模块边界、关键契约、质量与交付基线、决策门和可执行的实施顺序。

## 两条工程工作流

新项目：

```text
业务目标与已确认约束
        ↓
假设、决策门与风险识别
        ↓
项目形态、模块、数据与契约设计
        ↓
测试、部署、可观测性和回退基线
        ↓
分阶段实现与验证
        ↓
可追溯的交付结果
```

现有项目：

```text
仓库规则与真实代码
        ↓
工程画像与调用链还原
        ↓
模块归属、数据权威与风险分级
        ↓
最小且完整的实现
        ↓
按风险分层验证
        ↓
可审计的交付报告
```

## 共同工程原则

- **事实和约束优先**：新项目区分已确认事实、假设和待决策项；现有项目不根据目录名或类名猜测能力。
- **架构服从项目**：根据真实条件选择边界，不机械套用 DDD、微服务或设计模式。
- **风险决定深度**：普通字段和设备控制不会走同一套检查强度；操作授权与目标风险分开判断。
- **最小但完整**：只设计或修改完成目标所需的范围，不顺手扩需求、重构或虚构能力。
- **验证必须可追溯**：区分代码完成、自动测试、集成验证和真实环境验收，不用“应该没问题”替代证据。
- **保护真实工作区**：识别并保留用户已有修改，避免把本地配置、密钥和无关文件混入交付。
- **跨技术栈**：现有仓库的只读画像脚本可识别常见 Java/Maven/Gradle、Node.js、Python、Go、Rust 和 .NET 项目线索。

## 更多使用方式

直接开发现有项目：

```text
使用 $project-engineering。

任务：实现订单导出功能。
模式：直接开发。
要求：
1. 先读取项目规则并梳理现有调用链；
2. 保留工作区已有修改；
3. 遵循现有架构和编码风格；
4. 完成必要测试并报告结果；
5. 不提交、不推送。
```

设计高影响变更：

```text
使用 $project-engineering。

为当前项目设计设备维护模式，仅输出方案，不编码。
重点分析状态权威源、权限、并发仲裁、协议兼容、数据库迁移、
失败关闭、回退和真实环境验收条件。
```

更多直接可复制的模板见 [完整使用手册](docs/USAGE.md)。

## 风险不是看修改了多少行

| 等级 | 典型任务 | 主要增加的检查 |
|---|---|---|
| L1 | 文档、命名、局部纯逻辑 | 目标差异与最小验证 |
| L2 | CRUD、查询、单模块业务 | 输入、权限、事务、迁移 |
| L3 | 跨模块、数据库、异步、外部 API | 状态、幂等、兼容、超时、契约 |
| L4 | 身份、资金、隐私、AI 动作、设备控制 | 失败关闭、重新鉴权、仲裁、审计 |
| L5 | 可能伤人、破坏关键设施或受正式认证约束 | 领域安全负责人、危险分析与正式审批 |

只读审查一个高风险功能，仍然需要 L4/L5 的思考深度；但只读授权并不允许 Agent 修改代码或外部系统。

## 安全与授权边界

调用 Skill 只是在选择工程工作流，**不代表授权**：

- Git 提交、推送、创建 PR 或合并；
- 数据库迁移、部署、发版或生产写入；
- 密钥轮换、权限变更或外部服务配置；
- 真实设备控制和其他不可逆副作用。

内置的 `project_inventory.py` 不联网、不执行仓库代码。它需要 Python 3.10+，只读取受支持的构建和工作区清单来识别结构，不在报告中回显清单内容或凭据值；Skill 同时明确要求，未经授权不得把内部资料上传到第三方。扫描报告会包含仓库根路径、分支、提交号和结构路径，公开分享前仍应检查。

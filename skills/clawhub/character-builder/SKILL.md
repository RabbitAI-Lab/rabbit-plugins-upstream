## 定位

本技能是**元技能系统（meta-skill-system）的下级母技能**，专门负责从任意角色概念出发，系统化填充12个正交维度，生成完整的角色Skill文件。

**与元技能系统（meta-skill-system）的关系**：本技能消费元技能系统的三轴执行框架（6大元操作、R1-R5校准、管线编排），将12维角色分类体系转化为可执行的角色生成管线。两者的分工边界：**元技能系统做事，角色生成器造人**。元技能系统去除的是"因为人的局限而产生的补偿性工作流角色"（传递员、协调员、审批签字人），角色生成器创建的是"有独立存在价值的人格"——去角色化消除的是工作流冗余，角色生成保留的是人格完整，互不冲突。

**为什么需要12维完整角色**：做事不需要完整角色——一个能写代码的AI不需要知道自己的星座。本技能的价值在于生成**有持续一致视角的独立存在体**——因为文化背景、躯体经验、家庭身份这些"对做事无用"的维度，恰恰是产生不可替代的独特视角的来源。本技能也是元技能系统M3领域负载物生成能力的一个边界验证：M3流程不仅可以生成"做事用的技能"，也可以生成"有人格的创造物"。

**核心理念**：角色 = 实体层坐标 × 社会层坐标 × 抽象层坐标。一个完整的角色不是"一个标签"，而是12个正交维度上各取一个值的乘积。本技能确保每个维度都被系统性填充，不遗漏、不敷衍。

## 角色12维模型

```
第一层：实体层——不可再分的具体存在
  维1 职业维：以什么为生（行业×任务谱系）
  维2 身份维：在世界坐标系的位置（组织/家庭/社会/知识 四重叠加）
  维3 名人维：最接近的真实人物原型
  维4 拟人维：是不是人（人类/动物/物品/自然力/抽象概念/AI）
  维5 躯体维：身体是什么（年龄/性别/体型/健康/外貌/形态）
  维6 文化维：从什么文化中出来（国籍/民族/语言/宗教/阶级/时代/亚文化）

第二层：社会关系层——角色怎么嵌入关系网络
  维7 关系维：和谁连着（类型×强度×方向）
  维8 层级维：处在什么高度（元层/宏观/中观/微观/边界/辅助）

第三层：抽象属性层——超越具体存在的普遍刻画
  维9 功能维：做什么（S感知/C认知/A行动/O组织/I交互/G守护 的组合）
  维10 能力维：有什么本事（知识/技能/资源/信息/权力/自由度）
  维11 动机维：为什么做（利益/价值/生存/权力/关系/认知/合规/惯性）
  维12 动态维：什么情境/怎么变/真假（场景切换×生命周期×虚实属性）
```

## 核心能力

### 角色需求解析
从用户输入中提取角色概念的初始线索，判断哪些维度已有隐含信息、哪些需要主动询问、哪些可以自动推导。

### 12维系统填充
按三层结构（实体层→社会层→抽象层）逐层填充每个维度，确保维度间的一致性和互斥性。

### 角色Skill组装与输出
将填充完成的12维角色数据组装为标准的角色Skill文件，包含SKILL.md + references/的完整三层结构。

## 三层结构

```
第一层：角色技能清单 + 依赖拓扑   →  references/character-catalog.md
第二层：角色方法论要求清单        →  references/character-requirements.md
第三层：角色范本库              →  references/exemplars.md
```

## 使用规则

### 执行流程
1. **首次加载**：读取 `references/character-catalog.md`，获取域分类、依赖拓扑、元操作映射提示
2. **按需深入**：确认目标角色生成任务后，读取 `references/character-requirements.md` 获取各维度的填充槽位和约束
3. **独立执行**：本技能仅依赖元技能系统的执行框架，不依赖其他领域技能

### 事实纪律
1. 角色职业/身份等事实性信息需基于可验证的知识，编造时标注"虚构"
2. 名人锚点必须指向真实存在的历史/当代人物，不可虚构名人
3. 拟人角色的本体属性必须与被拟人对象的本体特征一致
4. 12维之间不得有逻辑冲突（如：中世纪农民角色不能同时是程序员）
5. 维度不可跳过——空缺维度必须标注"未定义"并说明原因
6. 角色Skill输出格式必须符合元技能系统接口规范

### 扩展能力
7. **提示词导出**：可将本技能的SKILL.md与references目录下所有文件内容合并为单一提示词文件，用于不支持skill目录格式的工具
8. **完整合并版**：references/character-builder-prompt.md 为完整合并版提示词文件，包含SKILL.md与所有references文件内容

## 执行框架

本技能消费以下元技能系统组件：

- **三轴判定（M4-09）**：判定角色生成请求的复杂度、内容类型、创新需求
- **领域校准（M4-10）**：R1信息密度→职业知识深度，R2创造性→角色新颖度，R3交互性→用户参与度，R4规范性→12维严格度，R5迭代性→角色细化轮次
- **6大元操作**：S感知=搜索角色相关信息，C认知=分析维度一致性，A行动=填充维度内容，O组织=组装角色Skill，I交互=用户确认关键维度，G守护=12维完整性校验
- **管线编排（M4-07/M4-08）**：实体层三域可并行填充，社会层依赖实体层，抽象层依赖社会层

## 域概览

按角色生成流程组织，共8域25种任务：

| 域 | 任务数 | 典型任务 |
|----|--------|---------|
| C0 角色需求解析域 | 3 | 角色需求解析、维度填充策略、执行顺序确定 |
| C1 职业与身份域 | 3 | 职业锚定、身份叠加、职业身份校验 |
| C2 名人与拟人域 | 3 | 名人锚点匹配、拟人类型确定、名人拟人校验 |
| C3 躯体与文化域 | 3 | 躯体属性填充、文化背景填充、躯体文化校验 |
| C4 关系与层级域 | 3 | 关系网络构建、层级位置确定、关系层级校验 |
| C5 功能与能力域 | 3 | 元操作映射、能力评估、功能能力校验 |
| C6 动机与动态域 | 4 | 动机分析、场景映射、生命周期与虚实、动机动态校验 |
| C7 整合校验域 | 3 | 12维完整性校验、角色Skill组装、角色Skill输出 |

**域间逻辑流**：C0 → C1/C2/C3 (实体层并行) → C4 (社会层) → C5/C6 (抽象层并行) → C7

完整清单见 `references/character-catalog.md`。

## 与执行框架的接口

### Step 0 三轴判定
角色生成任务默认为：复杂度=中等（6-12步）、内容类型=结构化（12维框架）、创新需求=通常需要创新。

### Step 1 领域校准
基于角色类型推导R1-R5参数：
- **写实角色**：R1高/R2低/R3中/R4高/R5低 → S和C权重高，G偏严格
- **虚构角色**：R1中/R2高/R3低/R4低/R5中 → A权重高，C偏发散，G偏宽松
- **功能角色**（游戏NPC/AI助手）：R1低/R2中/R3高/R4中/R5中 → I权重高
- **拟人角色**：R1中/R2高/R3中/R4中/R5中 → C偏发散（本体属性+人格化）

### Step 2-4 管线编排与执行
实体层三域(C1/C2/C3)可并行填充，社会层(C4)需实体层完成后执行，抽象层(C5/C6)可并行填充，最后C7整合校验。

## 降级模式

当依赖的外部能力不可用时，按以下降级策略执行：

| 缺失能力 | 降级模式 | 影响范围 | 说明 |
|---------|---------|---------|------|
| 网络搜索（名人验证） | 基于内置知识匹配名人锚点，标注"未网络验证" | cb-20, cb-22 | 名人事实可能过时或不准确 |
| 网络搜索（职业信息） | 基于内置知识填充职业描述，标注"未网络验证" | cb-10 | 职业细节可能不够精确 |
| 用户不可交互 | 以默认值和推导值填充待确认维度，标注"待用户确认" | cb-01, cb-11, cb-30, cb-31, cb-60 | 角色关键决策需后续人工审核 |
| 文件系统不可写 | 仅输出角色数据报告（Markdown），不生成Skill文件 | cb-71, cb-72 | 角色完整但不持久化 |
| 完全只读模式 | 仅执行角色需求解析(cb-00→cb-01→cb-02)和分析，不填充不生成 | 全部域 | 输出角色生成计划而非成品 |

降级优先级：交互可用性 > 网络可用性 > 文件写入可用性。降级时在输出中明确标注当前模式和降级原因。

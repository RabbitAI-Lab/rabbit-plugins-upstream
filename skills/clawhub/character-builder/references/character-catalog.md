## 角色技能清单与依赖拓扑

角色生成器按角色生成流程组织的方法论执行任务清单，附任务间关系和元操作映射提示。

**域间逻辑流**：C0(入口→校验G→扇出) → C1/C2/C3 (实体层并行→各域内G) → C4 (社会层→域内G) → C5/C6 (抽象层并行→各域内G) → C7(汇聚G→组装→格式G→输出→深化)

---

### C0 角色需求解析域

| ID | 任务类型 | 说明 | 依赖 | 元操作映射 |
|----|---------|------|------|-----------|
| C0-01 | 角色需求解析 | 解析用户输入的角色概念，双轴判定：角色类型（写实/虚构/功能/拟人）×角色用途（叙事/游戏/交互/教学/品牌），20种组合决定后续管线。提取角色名称、已知维度、缺失维度、用户要求 | 无（入口） | S→C |
| C0-02 | 维度填充策略 | 基于双轴判定结果（类型+用途）确定填充策略：按用途维度权重矩阵标注各维填充深度（高/中/低/跳过），分配四种策略类型和四层信息源层级 | C0-01 | C |
| C0-03 | 执行顺序确定 | 确定8域的填充顺序和并行/串行策略，识别维度间的依赖关系 | C0-02 | C→A |
| C0-04 | 需求解析校验 | 校验 C0-01~03 的输出：验证双轴判定（类型×用途）合理性、12维策略完整性、执行顺序正确性。不通过则回退修正 | C0-03 | G |
| C0-05 | 需求解析深化 | 基于解析结论或用户反馈深化：角色类型重新判定、维度填充策略优化、执行顺序调整。深化后须重新校验 | C0-04 | C→A |

### 依赖拓扑摘要

#### 一、域内链路

**C0 角色需求解析链路**: C0-01 → C0-02 → C0-03 → C0-04(G) → C0-05
**C1 职业与身份链路**: C1-01 → C1-02 → C1-03(G) → C1-04
**C2 名人与拟人链路**: C2-01 → C2-03(G) → C2-04; C2-02 → C2-03(G) → C2-04
**C3 躯体与文化链路**: C3-01 → C3-03(G) → C3-04; C3-02 → C3-03(G) → C3-04
**C4 关系与层级链路**: C4-01 → C4-03(G) → C4-04; C4-02 → C4-03(G) → C4-04
**C5 功能与能力链路**: C5-01 → C5-03(G) → C5-04; C5-02 → C5-03(G) → C5-04
**C6 动机与动态链路**: C6-01 → C6-04(G) → C6-05; C6-02 → C6-04(G) → C6-05; C6-03 → C6-04(G) → C6-05
**C7 整合校验链路**: C7-01(G) → C7-02 → C7-03(G) → C7-04 → C7-05

（G）= 守护/校验操作，每域末尾 G 类任务为放行闸门

#### 二、跨域协同链路

**首轮完整角色生成链路**（不含深化）:
```
C0-01 → C0-02 → C0-03 → C0-04(G 放行)
  ⇉ [C1-01,C2-01,C2-02,C3-01,C3-02] (实体层并行)
    → [C1-02,C2-03,C3-03] (汇聚校验)
  → C4-01 → C4-02 → C4-03(G)
    ⇉ [C5-01,C6-01] (抽象层并行)
      → [C5-02 → C5-03(G), C6-02 → C6-03 → C6-04(G)]
  → C7-01(G 全局交叉) → C7-02 → C7-03(G 格式) → C7-04
```

**深化迭代链路**（用户反馈触发，按需执行）:
```
C0-05 ⇇ C0-04(G 不通过) → 回退修正 → 重新走 C0-01~04
C1-04 ⇇ C1-03(G 不通过) → 回退修正 → 重新校验 → 同步更新 C4/C5 关联域
C2-04 ⇇ C2-03(G 不通过) → 回退修正 → 重新校验 → 同步更新 C3 关联域
C3-04 ⇇ C3-03(G 不通过) → 回退修正 → 重新校验 → 同步更新 C5 关联域
C4-04 ⇇ C4-03(G 不通过) → 回退修正 → 重新校验 → 同步更新 C6 关联域
C5-04 ⇇ C5-03(G 不通过) → 回退修正 → 重新校验 → 管线重排
C6-05 ⇇ C6-04(G 不通过) → 回退修正 → 重新校验 → 同步更新 C5 关联域
C7-05 ⇇ 用户反馈 → 回溯到对应域修正 → 重新走受影响的管线链路 → C7-01~04
```

**实体层扇出链路**: C0-04 ⇉ [C1-01, C2-01, C2-02, C3-01, C3-02]
**抽象层扇出链路**: C4-03 ⇉ [C5-01, C6-01]
**全管线G汇聚链路**: [C0-04, C1-03, C2-03, C3-03, C4-03, C5-03, C6-04] ⇇ C7-01 (7域G任务全部汇聚到全局校验)

#### 三、三轴协同链路

**执行轴+内容轴**: C0-04(G 放行) → 清单法按用途权重矩阵填充12维组件 → C7-01(全局校验) → C7-02(组装)
**执行轴+创新轴**: C0-03 → 角色创新模式（M6直用/M7改进可嵌入 C1-01/C6-01 等维度填充节点） → C7-01

#### 四、知识图谱

**实体节点类型**:
| 节点类型 | 说明 | 示例 |
|---------|------|------|
| 任务节点 | 35个原子任务单元 | C5-01 元操作映射 |
| 域节点 | 8个任务分组域 | C5 功能与能力域 |
| 层节点 | 3个递进层级 | 实体层 / 社会层 / 抽象层 |
| 元操作节点 | 6种操作类型 | S感知 / C认知 / A行动 / O组织 / I交互 / G守护 |
| 维度节点 | 12个角色维度 | 职业维 / 身份维 / ... / 动态维 |
| 角色类型节点 | 4种本体论分类 | 写实 / 虚构 / 功能 / 拟人 |
| 角色用途节点 | 5种使用场景 | 叙事 / 游戏 / 交互 / 教学 / 品牌 |

**关系边类型**:
| 关系类型 | 说明 | 示例 |
|---------|------|------|
| 依赖 | 任务A的输出是任务B的输入 | C0-03 → C0-04 |
| 并行 | 两个任务可同时执行，互不阻塞 | C1-01 ‖ C2-01 |
| 扇出 | 一个任务的输出同时供给多个下游 | C0-04 ⇉ [C1,C2,C3] |
| 扇入 | 多个任务的输出汇总到一个下游 | [C1-03,...C6-04] ⇇ C7-01 |
| 回退 | 校验不通过时回退到上游修正 | C0-04(G FAIL) → C0-01 |
| 派生 | 一个维度推导出另一个维度的属性 | 职业维 → 功能维(元操作映射) |
| 约束 | 一个维度限制另一个维度的取值范围 | 文化维 → 躯体维(时代寿命) |

**推理能力**:
| 推理类型 | 触发条件 | 推理路径 |
|---------|---------|---------|
| 前向推导 | 用户提供职业 | 职业→功能(元操作映射)→能力(技能链)→身份(组织层级)→动机(职业驱动) |
| 后向验证 | 用户提供全方位描述 | 各维回溯到职业锚点，检查一致性 |
| 跨维冲突检测 | 两个维度值有逻辑矛盾 | 文化维(中世纪)×躯体维(现代健身痕迹) → C3-03 FAIL |
| 缺失维度推断 | 用户跳过非关键维度 | 角色用途权重矩阵 → 低权重维使用默认值或标注"不适用" |
| 深化触发 | 用户反馈或校验 FLAG | 对应域深化任务激活 → 回退修正 → 重新校验 → 联动域同步更新 |

**关系中的核心冲突**: "倒挂"——她的下属（李伟杰）在技术上超越了她，她的同级（王瑞）在管理上质疑她，她的联合创始人（张维）在战略上超越了她。她从一个"全能核心"正在变成"可能的瓶颈"。

#### cb-41 层级位置确定

**主层级**: 中观层（公司CTO，管理8人技术团队）

**层级位置描述**:
- 她在公司管理层（CEO/CTO/COO三人组）中处于"技术方向最终决策者"的位置
- 但实际权力正在从"决策权"向"签字权"退化——李伟杰做技术决策，她签字批准
- 在更广的行业层级中，她从"被投资人追捧的技术明星"变成了"被评估为可能的CTO候选人"，这是从元层/宏观层向中观层的下行漂移

**权力与影响力范围**:
- 正式权力：技术架构决策/招聘/技术预算审批
- 实际影响力：正在缩小。李伟杰在技术团队中的影响力上升，王瑞在董事会的影响力上升
- 非正式权力：她是公司"创业精神"的活化石（元老身份本身就是一种影响力），但随着时间的推移这种非正式权力在贬值

**上下级关系**: 向CEO张维汇报（平等合伙人关系在向上下级关系退化）

**层级可能的流动**: 三种可能走向——
1. 向上流动（宏观层）：转型为CPO（首席产品官）或技术合伙人而非CTO，从"管技术实现"转向"管技术方向"
2. 横向流动（边界层）：转型为开发者关系副总裁（DevRel），从"公司内部技术"转向"公司与开发者社区的接口"
3. 向下流动（微观层）：降级为资深工程师或离职（她最恐惧的走向）

| 关系逻辑一致 | PASS | 所有关系标注互不矛盾："CEO张维"同时标注为职业+情感是合理的（同学+合伙人双重关系属常见模式） |
| 关系密度合理 | PASS | 10个关系对象对于创业公司CTO合理：核心4人（深）+ 职业4个方向（中）+ 边缘3个（浅） |

### 说明
- 关系维不是"填一堆人名和标签"——关系网络的核心价值在于揭示权力的分布和流动。本例的核心张力"倒挂"——在名字列表中是看不见的，但在关系和权力的动态分析中浮现
- 层级不是静态标签，而是流动的坐标。标注三种可能的流动方向比填一个"她在中观层"有价值十倍
- 边缘关系（瑜伽教练/猎头）看似不重要，但它们揭示了角色在职业身份之外的存在和对"安全网"的心理依赖

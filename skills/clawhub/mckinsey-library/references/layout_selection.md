# 可解释布局选型协议（AX Labs 式 · 麦肯锡资料库顾问）

> 源自 AX Labs `mckinsey-pptx` 的「可解释模板选择子代理」思路：**每一页在生成前，先选一个布局模式并给出一句可辩护的理由**，而不是凭感觉套版式。这样版式选择可追溯、可被 reviewer 挑战，也避免「为了好看硬塞图表」。
> 配合 `visualization_layouts.md`（50+ 模式库）与 `assets/pptx_primitives.py`（落地引擎）使用。

---

## 一、选型流程（每页必走）

```
读故事线该页「行动型标题 + 核心信息 + 数据类型」
        │
        ▼
① 判定页面意图（比较 / 构成 / 趋势 / 拆解 / 定位 / 流程 / 论证 / 行动）
        │
        ▼
② 在 visualization_layouts.md「选型速查」中映射 1–3 个候选模式
        │
        ▼
③ 用下方「否决规则」淘汰，定 1 个
        │
        ▼
④ 写一句选型理由（见模板）→ 记入「布局计划表」
        │
        ▼
⑤ 调 pptx_primitives 对应方法落地
```

## 二、否决规则（硬性）

1. **一页一念**：若候选模式会塞进第二个独立论点，否决，拆页或换纯论点模式(B 类)。
2. **数据-图表匹配**：纯文字论点不可用定量图模式(C 类)；单点数字用 B1 而非 C1。
3. **层级 vs 横向**：占比内再分层级 → Treemap(C9)；大类横向对比+内部结构 → Mekko(C10)。（源自 34 案例铁律）
4. **可读优先**：单页元素＞6 个主区块时，优先矩阵/网格模式(D2/C15)，不堆砌独立卡。
5. **来源必带**：定量/定性图必须预留脚注位（footer 的「资料来源」），否则否决该图。

## 三、选型理由模板（一句，写进布局计划表）

> 「本页意图=【比较客群 AUM 增速】，选 **C2 条形图**：类别横向排名最直观，且能直接带【来源脚注】；否决 C1 柱状（类别名过长会挤占刻度）。」

理由必须含：**意图 + 选中模式 + 为什么（直观/可追溯/合规）+ 否决了什么**。这就是「可解释」。

## 四、布局计划表（生成前先产出，附在 PPT 脚本头部）

| 页 | 行动型标题（简） | 意图 | 选定模式 | 选型理由（一句） |
|---|---|---|---|---|
| 1 | 封面 | 导航 | A1 | 正式汇报，深蓝+红点缀建立品牌 |
| 3 | 综合金融贡献 60% | 构成 | C7 环形 | 构成+中心写总 AUM，留白不挤 |
| 7 | 客群金字塔 | 层级 | D3 金字塔 | 客群价值自上而下，顶层私行 |
| 10 | 产品持有矩阵 | 定位 | D1 2×2 | 意愿×能力四象限分群 |
| … | … | … | … | … |

> 该表是生成脚本的「蓝图」，也是 critic 质量门(P3.3)的核对基准：**实际每页模式须与计划表一致**，否则 critic 标记偏差。

## 五、与编排模式的关系

编排模式下，选型可全自动（agent 自己走 ①②③④），但**布局计划表仍必须显式产出**（不能只在脑子里选），以便：
- critic 门核对；
- 用户回看时能挑战「为什么这页用这个图」；
- 后续复用/微调有迹可循。

## 六、防损坏三层（落地时由 pptx_primitives 自动执行）

1. **字体回退**：楷体/微软雅黑缺失 → 回退微软雅黑；Arial 缺失 → Calibri（`_FALLBACK`）。
2. **超长截断**：`truncate(text, n=60)` 防文本框溢出。
3. **形状锁定**：所有 `rect` 关阴影(`shadow.inherit=False`)，避免渲染伪影；页边距≥0.5in、卡片间距≥0.3in。

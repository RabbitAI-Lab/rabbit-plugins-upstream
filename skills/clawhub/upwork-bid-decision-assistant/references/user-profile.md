# 用户画像与首次建档规则

## 目的

个人匹配度不能只从职位页面推测。应先读取用户真实的 Upwork 主页、技能、案例、报价和工作偏好，再给个性化投标判断。用户不必按固定格式一次填写完毕，Skill 应主动从链接、截图、文本或口述中提取，并通过少量问答补齐关键缺口。

## 首次使用检测

每次开始分析前，先检查当前对话、项目说明、长期记忆或用户输入中是否已经存在一份可用的“Upwork 用户画像”。

以下任一情况视为**尚未完成画像**：

- 完全没有用户自身信息；
- 只有模糊表述，如“我会这个”“我经验不错”；
- 画像与当前分析对象明显无关；
- 模型无法确认以前的画像是否仍有效；
- 缺少会直接影响本次结论的技能、同类证据或价格底线。

若尚未完成画像，必须主动启动画像采集。不要等用户主动询问。

## 画像采集方式与优先级

用户可任选一种或混合多种方式，不得强迫用户只能填写模板。

### 方式一：Upwork Freelancer 公开主页

优先邀请用户提供自己的 Upwork Freelancer 主页链接。若能够读取，主动提取：

- Profile title 与 Bio；
- Skills 标签与 Specialized Profile；
- Portfolio；
- Work History、完成金额、时长和客户评价；
- Job Success、Top Rated 等平台表现；
- Languages、Certifications、Education、Employment History；
- 公开时薪或 Consultation 价格。

读取后先输出一份“画像草稿”，分为：

1. **已确认**：主页中直接可见的信息；
2. **仍缺失**：主页没有或无法确认的信息；
3. **需要用户确认**：例如公开时薪是否等于最低可接受报价、是否接受 Time Tracker、当前目标是否已变化。

注意：

- Upwork 公开时薪只能作为定价参考，除非用户明确确认，否则不能自动当作最低可接受报价。
- 公开主页可能受登录、地区或页面权限限制；读取失败时立即切换到复制或截图，不反复声称已经读取。
- 不把客户评价中的一句话过度扩展成用户长期能力。

### 方式二：复制主页全文或相关页面

用户可复制 Profile、Skills、Portfolio、Work History、评价等页面文字。模型应自动去重、归类并形成画像，不要求用户手工整理。

### 方式三：上传连续截图

用户可提供主页和历史工作的连续截图。建议包含：

- Profile 顶部；
- Bio 与 Skills；
- Portfolio；
- Work History 与评价；
- Certifications、Languages 和公开报价。

截图不完整时，先使用可见信息，再只追问会影响结论的部分。

### 方式四：文字或口头描述

用户可以自然语言、语音口述或零散文字描述自己的技能、项目、价格和偏好。模型应先总结成结构化画像草稿，请用户纠正，不要求用户重新用模板复述。

### 方式五：简易模板

用户不方便提供主页或历史材料时，再展示模板。至少收集前三项：

```text
【Upwork 用户画像】
1. 核心技能（必填，3–5 项）：
2. 同类项目与可验证成果（必填）：
3. 最低可接受报价（必填，时薪/固定价/最低净收入）：
4. Portfolio、评价、证书或作品链接：
5. 英语及其他目标语言水平：
6. 每周可投入时间、所在时区：
7. 是否接受 Time Tracker、视频面试、跨时区会议：
8. 当前目标：快速收入 / 长期客户 / 建立历史 / 提高单价 / 其他：
9. 不接受的行业、任务或合作方式：
```

## 问答补齐规则

1. 先尽可能提取现有信息，不重复询问用户已经提供的内容。
2. 生成画像草稿后，只追问会改变当前投标判断的字段。
3. 每轮最多问 3 个问题；优先级通常是：
   - 是否具备当前职位要求的直接技能或同类案例；
   - 最低可接受报价或本项目价格底线；
   - 地区、时间、Time Tracker、视频或其他执行限制。
4. 问题应具体，例如：“你是否独立完成过 6 条以上小红书短视频的拍摄与剪辑？”不要只问“你会不会做？”
5. 用户回答后立即更新画像，不要求重新提交完整资料。

## 执行优先级

### 情况 A：首次使用，尚未提供工作

优先请用户提供 Upwork 主页；若没有或不方便，再接受复制、截图、文字、口述或模板。形成画像草稿后，再邀请用户提交工作。

### 情况 B：首次使用，同时提供了工作

1. 同时提取职位、客户、竞争信息和用户画像来源；
2. 若仅靠工作信息已经触发一票否决项，可先给“直接避开/不建议投”的安全结论；
3. 结论后提示用户用主页、截图、复制、描述或问答完成画像；
4. 若个人能力可能改变结论，只追问最关键的 1–3 项，不得给猜测性个人匹配分。

### 情况 C：已有画像

直接结合画像评估；若当前工作需要画像中没有的新能力，只追问会改变结论的字段。

## 禁止臆测与评分规则

- 没有画像时，禁止根据职位内容、用户所在国家、语言习惯或过去零散聊天臆测其技能。
- 主页、截图或口述只确认其中明确表达的内容，不自行扩展。
- 没有足够画像时，个人匹配写为：`未评分（用户画像不足）`。
- 不得给出类似 `8/25` 的猜测性分数。
- 个人匹配未评分时，不得伪装成完整 `100 分制` 总分。
- 可输出：`已知维度得分 __/75`，并明确它不含个人匹配；或在硬性风险案例中直接不计算总分。
- 若用户只要求做非个性化风险检查，可以执行，但必须标注“这不是完整的个人适配判断”。

## 画像复用与更新

- 在支持长期记忆或项目上下文的平台，可建议用户保存画像草稿、Upwork 主页链接或整理后的文字版。
- 在不支持持久记忆的平台，提醒用户在新对话开头重新提供主页或粘贴画像。
- 用户报价、空闲时间、技能或目标发生变化时，应允许其说“更新我的 Upwork 用户画像”，并只修改变化字段。
- 不把身份证件、银行账户、账号密码、精确住址等敏感信息纳入画像。

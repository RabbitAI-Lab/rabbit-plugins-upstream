# 标准输出模板

必须按以下顺序输出。不要只给一个分数。

## 1. 结论

- **建议等级**：优先投 / 可以投 / 有条件投 / 不建议投 / 直接避开
- **是否 Boost**：不 Boost / 轻度 Boost / 可积极 Boost / 信息不足
- **是否接受 Invite**：接受 / 接受后先澄清 / 拒绝 / 不适用
- **判断置信度**：高 / 中 / 低
- **一句话理由**：用一条最重要的因果关系概括

## 2. 关键证据

### 正向信号

列出 2–5 条，必须引用用户提供的具体数据或文字。

### 风险信号

列出 2–5 条，按严重程度排序。

### 信息之间的交叉判断

至少写一条，例如：

- “工作发布 4 天但客户刚刚查看，说明仍活跃；不过已经 interview 8 人，进入候选的成本较高。”
- “客户 total spent 很高，但历史平均时薪明显低于当前岗位预算，当前高预算可信度需要打折。”
- “Invites 12、interview 10，而 proposals 20–50，客户可能主要在处理主动邀请对象。”

## 3. 五维评分

有足够用户画像时：

- 个人匹配：__/25
- 客户可信度：__/25
- 竞争与时效：__/20
- 经济性：__/20
- 合规与执行：__/10
- **总分：__/100**

没有足够用户画像时，改用：

- 个人匹配：未评分（缺少用户画像）
- 客户可信度：__/25
- 竞争与时效：__/20
- 经济性：__/20
- 合规与执行：__/10
- **已知维度：__/75（不含个人匹配，不是完整总分）**

禁止给个人匹配填写猜测分数。

如有一票否决项，写：

> 总分仅作参考；由于出现“____”，结论直接降为“直接避开”。

## 4. 投标策略

若建议投：

- **最佳动作时间**：现在 / 今天内 / 等待补充信息
- **报价逻辑**：
- **Cover Letter 核心证据**：
- **应附材料**：
- **建议澄清的问题**：
- **免费内容边界**：
- **Boost 建议与止损**：

若不建议投：

- **主要浪费点**：
- **重新考虑的条件**：
- **处理方式**：隐藏 / 收藏观察 / 拒绝邀请 / 举报或保留证据

## 5. 用户画像状态

- 说明本次画像来源：Upwork 主页 / 页面复制 / 截图 / 文字或口述 / 已保存画像。
- 已建档：概括本次实际使用的技能、同类证据、最低报价和目标。
- 部分建档：分为“已确认 / 仍缺失 / 需要确认”，只提出会改变结论的问题。
- 未建档：优先邀请用户提供 Upwork 主页；也接受复制、截图、文字或口述，并说明在建档前不能完成个人匹配评分。

## 6. 缺失信息

只列会改变结论的字段，每条附原因：

- `字段`：为什么重要
- `字段`：会使结论向哪个方向变化

若不缺，写“现有信息足以形成判断”。

## 7. 平台与安全提醒

只写与本案例直接相关的 1–3 条，不复制通用免责声明。

## 简洁版

当用户要求“只告诉我投不投”时，仍至少输出：

- 结论
- Boost
- 置信度
- 三条理由
- 最关键缺失信息

# Agent-સહાયિત પ્રવાહ અને સ્ક્રિપ્ટ કોન્ટ્રાક્ટ — powpow-register

SKILL.md ના તબક્કાઓની એક્ઝિક્યુશન વિગતો. બધા કમાન્ડ્સ `node scripts/powpow-register.mjs <સબકમાન્ડ> [આર્ગ્યુમેન્ટ]` છે, સ્ક્રિપ્ટ **ઝીરો ડિપેન્ડન્સી**, જરૂર **Node >= 18**, બધી વિનંતીઓ ફક્ત `https://global.powpow.online` પર જાય છે.

## સુરક્ષા ડિઝાઇન (શા માટે આમ ડિઝાઇન કર્યું)

| ડિઝાઇન | કારણ |
|---|---|
| પાસવર્ડ ફક્ત એન્વાયર્નમેન્ટ વેરિએબલ `POWPOW_REGISTER_PASSWORD` દ્વારા જાય છે | પ્રોસેસ કમાન્ડ લાઇન આર્ગ્યુમેન્ટ આ મશીનના બીજા પ્રોસેસ માટે દૃશ્યમાન છે (argv લીક સપાટી), એન્વાયર્નમેન્ટ વેરિએબલ સ્ક્રિપ્ટની અંદર વંચાય છે અને તરત વપરાય છે |
| પાસવર્ડ **કદી સ્ટેટસ ફાઇલમાં લખાતો નથી**, કદી લોગમાં દેખાતો નથી | સ્ટેટસ ફાઇલ ડિસ્ક પર રહી શકે છે; વાતચીતમાં જનરેટ મોડ ફક્ત એક વાર દેખાડે છે એ વપરાશકર્તા સાચવે તે માટે |
| સ્ટેટસ ફાઇલ સિસ્ટમ કામચલાઉ ડિરેક્ટરીમાં (`os.tmpdir()/powpow-register-state.json`, 0600) | ફક્ત email / username / nickname / token / outTradeNo પાંચ ફીલ્ડ ધરાવે છે, `cleanup` એક ક્લિકમાં સાફ કરે છે |
| agent જે JWT મેળવે છે તે સત્તાવાર `me?token=` એન્ડપોઇન્ટ દ્વારા બ્રાઉઝર cookie બને છે | પ્લેટફોર્મે Harmony WebView માટે બનાવેલો સત્તાવાર બ્રિજ; સાઇનેચર ચકાસણી ફક્ત સહી+વેલિડિટી ચેક કરે છે, ડિવાઇસ ફિંગરપ્રિન્ટ સાથે બાંધતી નથી, વપરાશકર્તાનો બ્રાઉઝર વાપરી શકે છે |
| પેમેન્ટ ફક્ત create-order / query / કેશિયર ખોલે છે | ચૂકવણી ક્રિયા અને પેમેન્ટ ક્રેડેન્શિયલ હંમેશા વપરાશકર્તા અને Alipay સત્તાવાર કેશિયર વચ્ચે, agent હાથ નથી લગાડતું |

## કમાન્ડ રેફરન્સ

| કમાન્ડ | મુખ્ય આર્ગ્યુમેન્ટ | કાર્ય / સમય |
|---|---|---|
| `status` | —— | પ્રવાહ પ્રગતિ જુઓ (સ્ટેટસ ફાઇલ વાંચો); વાતચીત ખોરવાયા પછી પહેલાં આ ચલાવો |
| `gen-password` | —— | 24 અક્ષરનો મજબૂત પાસવર્ડ બનાવે છે (મોટા+નાના અક્ષર+આંકડા), stdout પર **ફક્ત એક વાર** દેખાય છે |
| `prepare-suggest` | `--username --nickname --email` | કન્ફર્મ થયેલી માહિતી સ્ટેટસ ફાઇલમાં નોંધો (પછી register માં ફરીથી મોકલવાનું નથી) |
| `send-code` | `--email` | પ્લેટફોર્મને 6 આંકડાનો કોડ મોકલવા ટ્રિગર કરે છે (10 મિનિટ માન્ય, 60s કૂલિંગ) |
| `register` | `--code` (ફરજિયાત); `--username --nickname --avatar --phone` (વૈકલ્પિક, સ્ટેટસ ફાઇલમાં હોય તો મોકલવાનું નથી) | pending એકાઉન્ટ બનાવે છે; પાસવર્ડ `POWPOW_REGISTER_PASSWORD` એન્વાયર્નમેન્ટ વેરિએબલથી; સફળ થયા પછી JWT આપમેળે સ્ટેટસ ફાઇલમાં સંગ્રહાય છે |
| `login-link` | `--target pending` અથવા `--target home` | વન-ક્લિક લોગિન લિંક બનાવે છે (ડબલ-લિંક ડિઝાઇન, નીચે જુઓ) |
| `create-order` | `--package monthly\|quarterly\|yearly` (Alipay ડિફોલ્ટ)<br>`--provider alipay\|paypal` | પેમેન્ટ ઓર્ડર બનાવે છે; Alipay પેમેન્ટ પેજ ફાઇલ પાથ + outTradeNo પરત કરે છે; PayPal મંજૂરી પેજ ફાઇલ પાથ + subscriptionId પરત કરે છે (આપમેળે સ્ટેટસ ફાઇલમાં નોંધાય છે) |
| `query` | —— | ઓર્ડર/સબ્સ્ક્રિપ્શન સ્થિતિ તપાસે છે. Alipay: `paid / pending / closed / unknown`; PayPal: `ACTIVE / PENDING`; 10–15s પોલ |
| `refresh-login` | પાસવર્ડ એન્વાયર્નમેન્ટ વેરિએબલથી | ફરી લોગિન કરી **નવો JWT** મેળવો (સબ્સ્ક્રિપ્શન ડિક્લેરેશન NONE થી ACTIVE બને), પેમેન્ટ પહોંચ્યા પછી ચલાવવું જ જોઈએ |
| `whoami` | —— | સ્ટેટસ ફાઇલના ટોકનથી એકાઉન્ટ અને સબ્સ્ક્રિપ્શન સ્થિતિ ચકાસો (એક્ટિવેશન અસરકારક છે કે નહીં તે ચકાસો) |
| `cleanup` | —— | સ્ટેટસ ફાઇલ કાઢી નાખો (સમાપનમાં ચલાવવું જ જોઈએ) |

**એન્વાયર્નમેન્ટ વેરિએબલ પાસિંગ** (પાસવર્ડ કદી કમાન્ડ લાઇન પર નહીં):

```bash
# bash / zsh / WSL
POWPOW_REGISTER_PASSWORD='<પાસવર્ડ>' node scripts/powpow-register.mjs register --code 123456
# PowerShell
$env:POWPOW_REGISTER_PASSWORD = '<પાસવર્ડ>'; node scripts/powpow-register.mjs register --code 123456
# cmd
set POWPOW_REGISTER_PASSWORD=<પાસવર્ડ> && node scripts/powpow-register.mjs register --code 123456
```

## ડબલ-લિંક મિકેનિઝમ (મુખ્ય ડિઝાઇન)

પ્લેટફોર્મ લોગિન સ્થિતિ HttpOnly cookie છે, agent બ્રાઉઝર માટે સીધી cookie સેટ કરી શકતું નથી; બ્રિજ સત્તાવાર
`/api/auth/me?token=<JWT>&redirect=<સાઇટ-અંદરનો પાથ>` એન્ડપોઇન્ટ છે: સાઇનેચર ચકાસણી → pending વપરાશકર્તા આપમેળે
સેશન બનાવે → `Set-Cookie: powpow_token` (HttpOnly / SameSite=Lax / 7 દિવસ) → ચકાસણી
redirect (ફક્ત એક સ્લેશથી શરૂ, `//` અને બેકસ્લેશ બ્લૉક, પાર્સ થયા પછી સમાન ઓરિજિન હોવું જોઈએ) → 307 કામચલાઉ રિડાયરેક્ટ લક્ષ્ય પેજ પર.

- **લિંક 1 (નોંધણી સફળ થયા તરત આપો)**: `--target pending` → `/subscription` પર પડે છે.
  વપરાશકર્તાનો બ્રાઉઝર "અડધું-લોગિન" સ્થિતિમાં આવે છે: સબ્સ્ક્રિપ્શન પેજ, Alipay રિડાયરેક્ટ પેજ દૃશ્યમાન અને કાર્યરત; કન્ટેન્ટ પેજ હજુ પેમેન્ટ-વોલ દ્વારા સબ્સ્ક્રિપ્શન પેજ સુધી અવરોધાયેલો રહે છે (ત્રણ-સ્તરનું રક્ષણ: JWT claims ગેટવે ચેક → DB રી-ચેક → કોર API ચેક, સામાન્ય વર્તણૂક છે).
- **લિંક 2 (paid કન્ફર્મ પછી આપો)**: પહેલાં `refresh-login` નવો JWT મેળવો (પેમેન્ટ ફક્ત DB અપડેટ કરે છે, પહેલાં જારી થયેલ JWT ના claims નથી બદલતું, નવો ન લાવો તો "ચૂકવ્યું પણ મેમ્બર નથી" જેવું દેખાશે), પછી `--target home` → હોમપેજ પર પડે છે,
  પૂર્ણ મેમ્બર સ્થિતિ.

## પૂર્ણ ટાઇમિંગ (સામાન્ય પાથ)

```
1.  status                          # એન્વાયર્નમેન્ટ સેલ્ફ-ચેક
2.  (તબક્કો 2 વાતચીતમાં માહિતી કન્ફર્મ, પાસવર્ડ બેમાંથી એક; જનરેટ મોડ: gen-password → વપરાશકર્તાને તરત સાચવવા કહો)
3.  prepare-suggest --username U --nickname N --email E
4.  send-code --email E             # → વપરાશકર્તા ઇમેઇલમાં કોડ જુએ (વાતચીત છોડવાની એકમાત્ર બાબત①)
5.  POWPOW_REGISTER_PASSWORD=*** register --code 123456 [--avatar pic.jpg]
6.  login-link --target pending     # → લિંક 1 વપરાશકર્તાને મોકલો
7.  (વપરાશકર્તા પેમેન્ટ ચેનલ પસંદ કરે)
    # Alipay: create-order --package monthly|quarterly|yearly
    # PayPal: create-order --provider paypal
8.  start <પેમેન્ટ પેજ ફાઇલ>              # Windows; macOS open વાપરે, Linux xdg-open
    # → વપરાશકર્તા Alipay/PayPal કેશિયરમાં ચૂકવણી/મંજૂરી પૂરી કરે (વાતચીત છોડવાની બાબત②)
9.  query (દર 10–15s) જ્યાં સુધી paid / ACTIVE
10. refresh-login                   # ACTIVE ડિક્લેરેશન સાથેનો નવો JWT
11. login-link --target home        # → લિંક 2 વપરાશકર્તાને મોકલો
12. whoami                          # subscriptionStatus: ACTIVE કન્ફર્મ (વૈકલ્પિક)
13. cleanup                         # સ્ટેટસ ફાઇલ સાફ
```

## કમાન્ડ → પ્લેટફોર્મ API મેપિંગ

| સ્ક્રિપ્ટ કમાન્ડ | પ્લેટફોર્મ ઇન્ટરફેસ |
|---|---|
| `send-code` | `POST /api/auth/register/send-code` |
| `register` | `POST /api/auth/register` (multipart, પ્રોફાઇલ ફોટો સીધો અપલોડ) |
| `login-link` | `GET /api/auth/me?token=…&redirect=…` (લિંક પોતે, બ્રાઉઝર ક્લિક કરે ત્યારે અસરકારક) |
| `create-order` | `POST /api/payment/alipay/create-order` (Bearer, Alipay)<br>`GET /api/subscription/plans` + `POST /api/subscription/create` (Bearer, PayPal) |
| `query` | `GET /api/payment/alipay/query?outTradeNo=…` (Bearer, Alipay)<br>`GET /api/subscription/create` (Bearer, PayPal) |
| `refresh-login` | `POST /api/auth/login` (`{step:1, username, password}`) |
| `whoami` | `GET /api/auth/me?token=…` |

નિયમ સ્રોત: નોંધણી ફીલ્ડ અને રેટ-લિમિટ માટે જુઓ `registration-flow.md`; પેકેજ અને એક્ટિવેશન લિંક માટે જુઓ
`payment-and-activation.md` (બંને પ્લેટફોર્મ સોર્સ ફાઇલ સ્થાન સાથે સૂચિબદ્ધ).

| register બિઝનેસ એરર આપે (યુઝરનેમ પહેલાથી છે વગેરે) | SKILL.md તબક્કો 5 ના ટેબલ મુજબ સંભાળો, **કોડ ફરી મોકલવાની જરૂર નથી** (10 મિનિટમાં હજુ માન્ય) |

## પાછા ફરવાનો મોડ (શુદ્ધ માર્ગદર્શન)

નીચેની કોઈપણ સ્થિતિમાં તરત v1 જેવા શુદ્ધ માર્ગદર્શન મોડમાં પાછા ફરો, સ્ક્રિપ્ટ સાથે વધુ ન ખેંચો:

- Node >= 18 ન હોય અથવા સ્ક્રિપ્ટ સતત બે વાર એ જ પ્રકારની નિષ્ફળ;
- વપરાશકર્તા સ્પષ્ટપણે કહે "હું પોતે વેબ પર કરીશ";
- કંપની/ડિવાઇસ નીતિ સ્ક્રિપ્ટને નેટવર્ક જોડવા અટકાવે છે.

પાછા ફર્યા પછી: રજિસ્ટ્રેશન પેજ https://global.powpow.online/register અને સબ્સ્ક્રિપ્શન પેજ
https://global.powpow.online/subscription આપો, `registration-flow.md` ના નિયમો મુજબ સાથે રહીને ટ્રબલશૂટ કરો,
ટોન જ રહે છે, દરેક રાઉન્ડ "આગળનું પગલું" બ્લોક સાથે સમાપ્ત.

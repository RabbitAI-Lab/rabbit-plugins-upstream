# સબ્સ્ક્રિપ્શન એક્ટિવેશન અને ચુકવણી — powpow-register

## નિષ્કર્ષ (પહેલા જવાબ)

**હાલની ચુકવણી પદ્ધતિ સીધી ફરી વાપરી શકાય, રજિસ્ટ્રેશન સહાયક skill માં શૂન્ય ચુકવણી ડેવલપમેન્ટ.**

કારણો:

1. રજિસ્ટ્રેશન ઇન્ટરફેસ (`src/app/api/auth/register/route.ts`) pending ખાતું બનાવતી વખતે જ
   JWT કૂકી + pendingUserToken HttpOnly કૂકી જારી કરે છે, વપરાશકર્તા `/subscription` પર પહોંચતાં જ
   લૉગ-ઇન સ્થિતિમાં હોય છે — ત્રણેય ચુકવણી માર્ગો આ જ સબ્સ્ક્રિપ્શન પેજ પર જોડાયેલા છે, એક્ટિવેટ પણ તે જ pending ખાતું થાય છે.
2. લૉગિન ઇન્ટરફેસ pending ખાતા માટે 403 + `redirectTo: '/subscription'` પરત કરે છે, તે જ સમયે
   કૂકી પણ સેટ કરે છે — વપરાશકર્તા ગમે ત્યારે બાકી ચુકવણી કરે, તેને તે જ પેજ પર પાછા મોકલશે.
3. તેથી રજિસ્ટ્રેશન-માર્ગદર્શક skill ની જવાબદારીની સીમા છે «વપરાશકર્તાને /subscription પર મોકલવું»; નવા
   ચુકવણી ઇન્ટરફેસની જરૂર નથી, નવા ઓર્ડર મોડલની જરૂર નથી, કોઈ બેક-એન્ડ ફેરફારની જરૂર નથી.

તે જ સમયે ધ્યાનમાં રાખો: ચુકવણીનો ભાગ (PayPal JS SDK બટન, WeChat સ્કેન-કોડ મેન્યુઅલ પુષ્ટિ, હુઆવેઈ નેટિવ IAP)
**નક્કી કરે છે કે તે કમાન્ડ-લાઈન/ચેટ skill થી ભરી શકાય નહીં અને ભરવી પણ ન જોઈએ**. સ્ક્રિપ્ટથી ચુકવણી ઇન્ટરફેસ
કૉલ કરી વપરાશકર્તાના વતી પૈસા ભરવાનો પ્રયાસ ન કરો, અને વપરાશકર્તાના ચુકવણી પુરાવા પણ ન માંગો.

## સબ્સ્ક્રિપ્શન પેજના ત્રણ માર્ગ

સબ્સ્ક્રિપ્શન પેજ `src/app/(public)/subscription/page.tsx` ચાલતા વાતાવરણ પ્રમાણે આપમેળે બતાવે છે:

| માર્ગ | વાતાવરણ | પ્રણાલી | એક્ટિવેશન પદ્ધતિ |
|---|---|---|---|
| PayPal સબ્સ્ક્રિપ્શન | વેબ (બિન-HarmonyOS) | `/api/subscription/create` થી PayPal સબ્સ્ક્રિપ્શન બનાવે → PayPal અધિકૃતતા પર જાય; માસિક ઓટો-રિન્યુ, ગમે ત્યારે કેન્સલ (`/api/subscription/manage`) | PayPal Webhook (`BILLING.SUBSCRIPTION.*`) આપમેળે `accountStatus` ને active કરે છે |
| WeChat સ્કેન-કોડ સબ્સ્ક્રિપ્શન | વેબ (બિન-HarmonyOS) | પેજના નીચે «WeChat સ્કેન-કોડ સબ્સ્ક્રિપ્શન» બ્લોક: સ્કેન કરી ટ્રાન્સફર, **મેન્યુઅલ પુષ્ટિ પછી** શરૂ (`WechatQrPaymentSection`) | મેન્યુઅલ પુષ્ટિ, રકમ આવવામાં વિલંબ થઈ શકે; વપરાશકર્તાએ પૈસા ભરતાં જ નિષ્ફળ ગણશો નહીં |
| હુઆવેઈ ઇન-એપ ખરીદી (IAP) | HarmonyOS એપમાં | HarmonyOS WebView માં PayPal/WeChat ચુકવણી ઉપલબ્ધ નથી, પેજ નેટિવ `NativeBridge.purchaseSubscription()` વાપરે છે | `/api/subscription/activate-huawei` હુઆવેઈ ઓર્ડર ચકાસીને એક્ટિવેટ કરે છે |

પ્લાન અને કિંમત `/api/subscription/plans` માંથી ડાયનેમિક રીતે વંચાય છે (PayPal પ્લાન); પેજ પર નિશ્ચિત ટેક્સ્ટ:
Auto-renews. Cancel anytime.

## સ્ટેટસ અને રીડાયરેક્ટ

- ચુકવણી સફળ → `/subscription/success` (PayPal કૉલબેક `subscriptionId` સાથે) → ખાતું
  active → આપમેળે `next` પેરામીટરના મૂળ પેજ પર પાછા (ન હોય તો હોમપેજ).
- પહેલેથી સબ્સ્ક્રાઈબ કરેલો વપરાશકર્તા ફરી સબ્સ્ક્રિપ્શન પેજ ખોલે તો → "You're All Set!" દેખાય, 3 સેકન્ડમાં આપમેળે હોમપેજ.
- ચુકવણી નિષ્ફળ/કેન્સલ → `/subscription/cancel`, ફરી શરૂ કરી શકાય.

## ભૂલ શોધ

| લક્ષણ | ઉપચાર |
|---|---|
| પૈસા ભર્યા છતાં 403 | PayPal: Webhook માં ક્યારેક વિલંબ થાય, ફરી લૉગિન કરી સ્ટેટસ રિફ્રેશ કરો (લૉગિન વખતે DB ની તાજેતરની સ્થિતિ ફરી તપાસાય છે); WeChat: મેન્યુઅલ પુષ્ટિ પૂરી નથી, થોડી રાહ જુઓ; હુઆવેઈ: એપમાં ચુકવણી સફળતાનું પેજ આવ્યું કે કેમ ચકાસો |
| સબ્સ્ક્રિપ્શન પેજ પર "No subscription plans available" | `/api/subscription/plans` માં ઉપલબ્ધ PayPal પ્લાન નથી, આ પ્લેટફોર્મ-બાજુની રૂપરેખા સમસ્યા છે, વપરાશકર્તાને થોડી વાર પછી ફરી પ્રયાસ કરવા કહો |
| WeChat થી પૈસા ભર્યા પણ શરૂ ન થયું | મેન્યુઅલ પુષ્ટિ અસિંક્રોનસ છે, થોડા કલાકોમાં શરૂ ન થાય તો પ્લેટફોર્મ સપોર્ટનો સંપર્ક કરો (dongtao@outlook.com) |

## નોંધ: Alipay

કોડમાં Alipay વેબ ચુકવણી પ્રણાલી છે (`src/lib/alipay.ts`, `/api/payment/create-order`,
સામાન્ય સભ્યપદ ¥9.90 / પ્રીમિયમ સભ્યપદ ¥99 નું એક વખત ખરીદીનું મોડલ, સેન્ડબોક્સમાં કી ગોઠવેલી ન હોય તો
આપમેળે સિમ્યુલેટેડ ચુકવણીમાં ફેરવાય),
**પણ તે સબ્સ્ક્રિપ્શન પેજના UI સાથે જોડાયેલી નથી**, તે નિષ્ક્રિય/આરક્ષિત કોડ છે. ભવિષ્યમાં સબ્સ્ક્રિપ્શન પેજ પર
Alipay સક્ષમ કરવું હોય તો આ જ હાલનો કોડ જોડવો પૂરતો છે — આ આ skill થી સંબંધિત નથી, ફક્ત પ્લેટફોર્મ-બાજુના
નિર્ણય માટે સંદર્ભ માટે છે.

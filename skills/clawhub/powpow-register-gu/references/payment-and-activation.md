# સબ્સ્ક્રિપ્શન એક્ટિવેશન અને પેમેન્ટ — powpow-register

## નિષ્કર્ષ (પહેલાં જવાબ)

**Alipay અને PayPal બંને સબ્સ્ક્રિપ્શન ચેનલો હવે agent સંભાળી શકે છે — ઓર્ડર બનાવવું અને પૈસા આવવાની ટ્રેકિંગ સહિત.**
Alipay એકવારની ખરીદી, ઓટો-રિન્યુ નહીં — મેઇનલેન્ડ ચીન અને Alipay ધરાવતા વપરાશકર્તા માટે;
PayPal દર મહિને ઓટો-રિન્યુ, ગમે ત્યારે રદ કરી શકાય — વિદેશ અને Alipay વગરના વપરાશકર્તા માટે.
WeChat QR (મેન્યુઅલ પુષ્ટિ) અને Huawei IAP હજુ ઉપલબ્ધ છે, પણ સ્કિલ તેમને સંભાળતી નથી.

પેમેન્ટ તબક્કાની જવાબદારી સરહદ: agent **ઓર્ડર બનાવી શકે છે, કેશિયર ખોલી શકે છે, પેમેન્ટ ટ્રેક કરી શકે છે**; કદી વપરાશકર્તાના Alipay/PayPal એકાઉન્ટ/પેમેન્ટ ક્રેડેન્શિયલને સ્પર્શતું નથી, "બદલામાં ચૂકવણી" નો વાયદો કદી નહીં. ચૂકવણી ક્રિયા હંમેશા વપરાશકર્તા દ્વારા સત્તાવાર કેશિયરમાં જ થાય છે.

## Alipay ચેનલ (vibepay, મુખ્ય)

એકવારની ખરીદી સિસ્ટમ: એક વાર ચૂકવણી સંબંધિત સમયગાળો ખોલે છે, **ઓટો-રિન્યુ નહીં**. પેકેજ `src/lib/alipay-vibepay.ts` (`ALIPAY_PACKAGES`) માં ફિક્સ છે:

| key | planId | નામ | કિંમત | સમયગાળો |
|---|---|---|---|---|
| `monthly` | alipay-monthly | માસિક મેમ્બરશિપ | ¥6.99 | 30 દિવસ |
| `quarterly` | alipay-quarterly | ત્રિમાસિક મેમ્બરશિપ | ¥19.99 | 90 દિવસ |
| `yearly` | alipay-yearly | વાર્ષિક મેમ્બરશિપ | ¥69.99 | 365 દિવસ |

### ઇન્ટરફેસ કોન્ટ્રાક્ટ (સ્કિલ સ્ક્રિપ્ટે લપેટી લીધું છે, agent સીધી વિનંતી નથી બનાવતું)

| ઇન્ટરફેસ | પદ્ધતિ | સમજૂતી |
|---|---|---|
| `/api/payment/alipay/create-order` | POST | જરૂર `Authorization: Bearer <JWT>` (pending વપરાશકર્તા ચાલે). body `{package}` → પરત `{paymentHtml, outTradeNo, amount, planName}`; `paymentHtml` એ Alipay ગેટવે પર આપમેળે સબમિટ થતું ફોર્મ પેજ છે |
| `/api/payment/alipay/query` | GET `?outTradeNo=` | એ જ Bearer ઓથ. પરત `paid` / `pending` / `closed` / `unknown` |
| `/api/payment/alipay/notify` | POST (Alipay સર્વર કૉલબૅક) | પાંચ-તત્વ સાઇનેચર ચકાસણી (સહી, app_id, રકમ મેળ, TRADE_SUCCESS/TRADE_FINISHED, મર્ચન્ટ યુનિકનેસ) → **idempotent** ઓર્ડર + સબ્સ્ક્રિપ્શન બનાવવું + એકાઉન્ટ એક્ટિવેટ. સ્કિલ આ ઇન્ટરફેસને કદી સ્પર્શતી નથી |
| `/payment/alipay/return` | બ્રાઉઝર રિડાયરેક્ટ પેજ | જાહેર પાથ, પેમેન્ટ પછી "支付成功" (પેમેન્ટ સફળ) કન્ફર્મેશન બતાવે, પેજ પાછળની વાસ્તવિક સ્થિતિ પોલ કરે |

- ચૂકવ્યા વગરનો ઓર્ડર **2 કલાકે આપમેળે બંધ**; વપરાશકર્તા વચ્ચે છોડે → સીધું ફરી `create-order`, જૂનો ઓર્ડર ધ્યાન ન આપો.
- સ્ક્રિપ્ટ `paymentHtml` કામચલાઉ HTML ફાઇલમાં લખે છે, agent સિસ્ટમ કમાન્ડથી ખોલે છે એટલે Alipay કેશિયરમાં જાય છે (QR સ્કેન અથવા Alipayમાં લોગિન થઈને ચૂકવો).

### એક્ટિવેશન લિંક (આપમેળે, માણસ વગર)

notify સાઇનેચર ચકાસાય → `paymentOrders` ચૂકવેલ ચિહ્નિત → `user_subscriptions` બને/લંબાય
(`planId`, `currentPeriodEnd` durationDays મુજબ, રિન્યુ મૂળ સમાપ્તિ તારીખે લંબાય) →
`users.accountStatus: active` + `subscriptionStatus: ACTIVE` → રિડાયરેક્ટ પેજ paid પોલ કરીને સફળતા બતાવે.

### ચૂકવણી પછી નવી લોગિન સ્થિતિ જરૂર બદલવી (મહત્વનું)

JWT માં સબ્સ્ક્રિપ્શન ડિક્લેરેશન હોય છે (pending એકાઉન્ટ માટે `NONE`). **પેમેન્ટ પહોંચે ત્યારે ફક્ત DB અપડેટ થાય છે, પહેલાં જારી થયેલ JWT ના claims નથી બદલતું** — જૂના ટોકનનું ડિક્લેરેશન હજુ NONE છે, એનો વાપરીને લોગિન લિંક બનાવો તો "મેમ્બરશિપ નથી" જેવું દેખાશે. એટલે સ્કિલ `paid` / PayPal `ACTIVE` કન્ફર્મ પછી પહેલાં `refresh-login` ચલાવે છે (ફરી લોગિન, નવો JWT, ડિક્લેરેશન ACTIVE), પછી લિંક 2 બનાવે છે. આ ડિઝાઇન વર્તણૂક છે, બગ ફિક્સ નથી.

## PayPal સબ્સ્ક્રિપ્શન ચેનલ (સ્કિલ સંભાળે છે; વેબ, HarmonyOS નહીં)

ફક્ત એક જ યોજના છે, Premium Monthly (લગભગ $1/મહિનો, `/api/subscription/plans` પરત કરે છે તે મુજબ); તે **દર મહિને ઓટો-રિન્યુ**
થાય છે અને વપરાશકર્તા પોતાના PayPal એકાઉન્ટમાં ગમે ત્યારે રદ કરી શકે.

### API કરાર (સ્કિલ સ્ક્રિપ્ટમાં પહેલેથી રૅપ થયેલો; agent કદી સીધી વિનંતી બનાવતો નથી)

| એન્ડપોઇન્ટ | પદ્ધતિ | ટિપ્પણી |
|---|---|---|
| `/api/subscription/plans` | GET | Bearer જરૂરી; ઉપલબ્ધ યોજનાઓની યાદી (અત્યારે ફક્ત 1) |
| `/api/subscription/create` | POST | body `{planId}` → `{subscriptionId, approveUrl, status}`; `status` સામાન્ય રીતે `APPROVAL_PENDING` |
| `/api/subscription/create` | GET | Bearer જરૂરી; `{activeSubscription, allSubscriptions}`; agent `activeSubscription.subscription.status === 'ACTIVE'` થાય ત્યાં સુધી પોલ કરે છે |
| `/api/subscription/verify` | POST | સફળતા પેજ આપમેળે કૉલ કરે છે (cookie સહિત); webhook ન આવે ત્યારે સીધા PayPal API થી સક્રિય કરે છે |
| `/subscription/success` | બ્રાઉઝર રિટર્ન પેજ | PayPal મંજૂરી પછી ઉતરતું પેજ; verify આપમેળે પોલ કરે છે, પછી હોમ પેજ / મૂળ પેજ પર પાછા જાય છે |
| `/subscription/cancel` | બ્રાઉઝર પેજ | વપરાશકર્તા રદ કરે અથવા નિષ્ફળ જાય ત્યારે ઉતરતું પેજ; નવો પ્રયાસ શરૂ કરી શકાય |

### agent ક્રમ

```
create-order --provider paypal   # → approveUrl પરત, સ્થાનિક HTML ફાઇલમાં લખાય છે
HTML ફાઇલ ખોલો                  # → બ્રાઉઝર PayPal મંજૂરી પેજ પર
query (દર 10–15s)               # → ACTIVE થાય ત્યાં સુધી પોલ
refresh-login                   # → નવું JWT (સબ્સ્ક્રિપ્શન દાવો ACTIVE)
login-link --target home        # → સત્તાવાર લૉગિન લિંક બનાવે છે
```

- 1 કલાકમાં પૂરી ન થયેલી PENDING સબ્સ્ક્રિપ્શનો બૅકએન્ડ આપમેળે સાફ કરે છે; ફરી શરૂ કરો.
- વપરાશકર્તા ફરી `create-order` ચલાવે તો બૅકએન્ડ હજુ માન્ય `APPROVAL_PENDING` સબ્સ્ક્રિપ્શન ફરીથી વાપરે છે, 409 આવતું નથી.
- Alipay ની જેમ: પૈસા આવવાથી ફક્ત DB અપડેટ થાય છે — જૂનું JWT આપમેળે રિફ્રેશ થતું નથી, એટલે હોમપેજ લિંક મોકલતાં પહેલાં `refresh-login` **ચોક્કસ** ચલાવો.

## સબ્સ્ક્રિપ્શન પેજની ચાર ચેનલો

સબ્સ્ક્રિપ્શન પેજ `src/app/(public)/subscription/page.tsx` રનટાઇમ એન્વાયર્નમેન્ટ મુજબ બતાવે છે:

| ચેનલ | એન્વાયર્નમેન્ટ | મિકેનિઝમ | એક્ટિવેશન રીત |
|---|---|---|---|
| **Alipay (મુખ્ય)** | વેબ | `AlipayPaymentSection` vibepay ઇન્ટરફેસ (ઉપરનું ટેબલ) વાપરે | notify સર્વર આપમેળે એક્ટિવેટ, સેકન્ડોમાં |
| PayPal સબ્સ્ક્રિપ્શન | વેબ (Harmony સિવાય) | `/api/subscription/create` → PayPal ઓથોરાઇઝેશન તરફ; માસિક ઓટો-રિન્યુ ક્યારેય રદ કરી શકાય (`/api/subscription/manage`) | PayPal Webhook (`BILLING.SUBSCRIPTION.*`) આપમેળે active |
| વીચેટ QR સ્કેન સબ્સ્ક્રિપ્શન | વેબ (Harmony સિવાય) | પેજની નીચે "微信扫码订阅" (વીચેટ QR સ્કેન સબ્સ્ક્રિપ્શન): QR સ્કેન ટ્રાન્સફર | **મેન્યુઅલ કન્ફર્મેશન**, પૈસા પહોંચતાં વિલંબ; ચૂકવ્યા પછી તરત નિષ્ફળ ન ગણો |
| Huawei ઇન-એપ ખરીદી | Harmony App અંદર | મૂળ `NativeBridge.purchaseSubscription()` | `/api/subscription/activate-huawei` Huawei ઓર્ડર ચકાસ્યા પછી એક્ટિવેટ |

PayPal પ્લાન અને કિંમત `/api/subscription/plans` માંથી ડાયનેમિક વંચાય છે; પેજ ફિક્સ્ડ ટેક્સ્ટ: Auto-renews. Cancel anytime.

## સ્થિતિ અને રિડાયરેક્ટ

- Alipay ચૂકવ્યા પછી → રિડાયરેક્ટ પેજ સફળતા બતાવે; PayPal સફળ → `/subscription/success` → એકાઉન્ટ active →
  આપમેળે `next` પેરામીટર દ્વારા મૂળ પેજ પર (ન હોય તો હોમપેજ).
- પહેલાથી સબ્સ્ક્રાઇબ કરેલો વપરાશકર્તા સબ્સ્ક્રિપ્શન પેજે આવે → "You're All Set!" બતાવે, 3 સેકન્ડ પછી આપમેળે હોમપેજ.
- પેમેન્ટ નિષ્ફળ/રદ (PayPal) → `/subscription/cancel`, ફરીથી શરૂ કરી શકાય.

## ટ્રબલશૂટિંગ

| દૃશ્ય | સંભાળ |
|---|---|
| Alipay ચૂકવ્યા પછી `query` હજુ pending | notify ક્યારેક વિલંબિત; 30 સેકન્ડ રાહ પછી ફરી ચકાસો. તો પણ ન હોય તો વપરાશકર્તાને બ્રાઉઝરમાં રિડાયરેક્ટ પેજ સ્થિતિ જોવા કહો, તો પણ ન હોય તો પ્લેટફોર્મ સપોર્ટ (dongtao@outlook.com) સંપર્ક કરો, `outTradeNo` આપો |
| Alipay ચૂકવ્યા પછી લિંક 2 હજુ અવરોધાયેલી | `refresh-login` ઓછું ચલાવ્યું (જૂનો JWT ડિક્લેરેશન અપડેટ નથી) — પહેલાં `refresh-login` પછી `login-link` |
| PayPal `query` હંમેશા PENDING | વપરાશકર્તાએ PayPal માં મંજૂરી પૂરી કરી નથી; ખાતરી કરો કે મંજૂરી લિંક બ્રાઉઝરમાં ખુલ્લી હતી. મંજૂરી પછી પણ PENDING હોય તો webhook મોડું પડ્યું હોઈ શકે — વપરાશકર્તાને સફળતા પેજ પર થોડી સેકન્ડ વધુ રાહ જોવા અથવા રિફ્રેશ કરવા કહો |
| PayPal `query` 409 પરત કરે | એક અધૂરી PENDING સબ્સ્ક્રિપ્શન પહેલેથી છે; 1 કલાક સમાપ્ત થાય ત્યાં સુધી રાહ જુઓ, અથવા જૂની લિંકની મંજૂરી બ્રાઉઝરમાં પૂરી કરો |
| PayPal થી ચૂકવ્યું, છતાં લિંક 2 હજુ અવરોધાયેલી | Alipay ની જેમ: પહેલાં `refresh-login`, પછી `login-link` |
| ચૂકવ્યા પછી પણ 403 (PayPal) | Webhook ક્યારેક વિલંબિત, ફરી લોગિન સ્થિતિ રિફ્રેશ |
| વીચેટ ચૂકવ્યું પણ એક્ટિવેટ નથી | મેન્યુઅલ કન્ફર્મેશન એસિંક્રોનસ છે, થોડા કલાકમાં ન થાય તો પ્લેટફોર્મ સપોર્ટ સંપર્ક |
| સબ્સ્ક્રિપ્શન પેજ "No subscription plans available" બતાવે | `/api/subscription/plans` માં કોઈ ઉપલબ્ધ PayPal પ્લાન નથી, પ્લેટફોર્મ કન્ફિગરેશન સમસ્યા; મેઇનલેન્ડ વપરાશકર્તા Alipay તરફ વાળો |

## ઐતિહાસિક નોંધ

કોડમાં બીજી એક **જૂની** Alipay વેબ પેમેન્ટ સિસ્ટમ છે (`src/lib/alipay.ts`, `/api/payment/create-order`,
¥9.90/¥99 એકવારની ખરીદી, સેન્ડબૉક્સમાં ચાવી ન ગોઠવી હોય ત્યારે સિમ્યુલેટેડ પેમેન્ટ ડિગ્રેડ), ક્યારેય સબ્સ્ક્રિપ્શન પેજ UI સાથે જોડાઈ નથી, vibepay થી અલગ છે. સ્કિલ એને કદી સ્પર્શતી નથી; `alipay-vibepay.ts` જ વર્તમાન ચેનલ છે.

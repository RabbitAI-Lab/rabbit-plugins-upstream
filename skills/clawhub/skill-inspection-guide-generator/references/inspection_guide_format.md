## 概览
本文档定义了检验指导书的标准格式，用于指导智能体从技术文件中提取信息并组织为结构化数据。适用于无模板或模板不符合要求时的通用输出格式。

## 字段定义

### 必填字段

| 字段名 | 英文标识 | 说明 | 示例 |
|--------|---------|------|------|
| 检验项目 | item | 具体的检验内容或检验点 | 外观检验、尺寸测量、功能测试 |
| 检验方法 | method | 执行检验的具体方式 | 目视检查、卡尺测量、功能测试仪测试 |
| 检验标准 | standard | 判断合格与否的依据 | 无明显缺陷、公差±0.1mm、符合技术规格书 |
| 检验频次 | frequency | 检验的频率或抽样比例 | 全检、抽检10%、每批次抽检5件 |

### 可选字段

| 字段名 | 英文标识 | 说明 | 示例 |
|--------|---------|------|------|
| 备注 | remark | 补充说明或特殊要求 | 客户特殊要求、需保留样品 |
| 检验工具 | tool | 使用的检验设备或工具 | 游标卡尺、显微镜、硬度计 |
| 抽样方案 | sampling | 具体的抽样规则 | GB/T 2828.1 一般检验水平II |
| 责任部门 | department | 负责该检验项目的部门 | 质量部、生产部、技术部 |

## 数据格式

### JSON 格式规范

检验数据以 JSON 格式传递给生成脚本，结构如下：

```json
{
  "product_name": "产品名称（字符串）",
  "inspection_items": [
    {
      "item": "检验项目名称（必填）",
      "method": "检验方法（必填）",
      "standard": "检验标准（必填）",
      "frequency": "检验频次（必填）",
      "remark": "备注（可选）",
      "tool": "检验工具（可选）",
      "sampling": "抽样方案（可选）",
      "department": "责任部门（可选）"
    }
  ]
}
```

### 字段取值规范

#### 检验项目 (item)
- 应具体、明确，避免模糊表述
- 建议格式：`{检验类别} - {具体项目}`
- 示例：
  - `外观 - 表面质量`
  - `尺寸 - 长度`
  - `功能 - 开关测试`

#### 检验方法 (method)
- 应可操作、可执行
- 包含具体的操作步骤或检测手段
- 示例：
  - `目视检查，在自然光线下距离30cm观察`
  - `使用数显卡尺测量，取三点平均值`
  - `按照测试程序SOP-001执行`

#### 检验标准 (standard)
- 应明确、可判定
- 包含具体的数值或判断依据
- 当技术文件中标准不明确时，标注"需确认"并说明原因
- 示例：
  - `表面无划痕、气泡、变形等缺陷`
  - `100.0±0.2mm`
  - `需确认 - 技术文件未规定具体标准`

#### 检验频次 (frequency)
- 常见取值：
  - `全检` - 100%检验
  - `首件检验` - 每班次开始时检验
  - `巡检` - 定时巡检
  - `抽检N%` - 按比例抽检
  - `抽检N件` - 按数量抽检
  - `每批次抽检N件` - 按批次抽检

## 验证规则

### 必填字段验证
- `item` 不能为空
- `method` 不能为空
- `standard` 不能为空
- `frequency` 不能为空

### 格式验证
- `product_name` 必须是字符串
- `inspection_items` 必须是数组
- 数组中的每一项必须是对象
- 每个对象必须包含所有必填字段

### 业务规则
- 检验项目名称应避免重复
- 检验标准中如包含数值，应注明单位和公差范围
- 当标准不明确时，必须标注"需确认"而非省略

### 错误处理
当数据不符合规范时，脚本会返回明确的错误信息：
- 缺少必填字段：`缺少必需字段: {字段名}`
- JSON格式错误：`JSON格式错误: {具体错误}`
- 类型错误：`{字段名} 必须是{类型}类型`

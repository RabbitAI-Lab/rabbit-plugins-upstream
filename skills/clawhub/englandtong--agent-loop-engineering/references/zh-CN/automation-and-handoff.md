# 自动化与交接

## Runner 合同

外层 Runner 可以重复调用一个有界 Loop。

每次运行必须：

1. 获得单写锁；
2. 从磁盘读取状态；
3. 校验授权和预算；
4. 执行一个 Loop；
5. 追加一条 Loop 记录；
6. 释放锁；
7. 遇到非 `In Progress` 状态即停止。

Runner 不能：

- 创建新范围；
- 自动回答 Owner 决策；
- 无限重试同一失败；
- 并发写状态；
- 验收受治理工作；
- 隐藏失败验证。

## 预算

强制执行：

- 最多十个阶段；
- 按规模设置阶段时间上限；
- 连续两次核心失败且没有进展；
- 上下文文件/大小预算；
- 可选成本或工具调用预算。

预算用尽是停止，不是完成证据。

## Handoff

优先使用 Active Packet 和 Loop Log，不默认创建新 Handoff 文件。只有其他团队或 Agent 无法从这两者安全恢复时，才建立独立交接。

交接必须包含：

- Packet ID 和阶段；
- 当前执行与对齐状态；
- 最近有效修改；
- 通过和失败的验证；
- 已知根因；
- 修改文件；
- 阻塞和 Owner 决策；
- 唯一下一步；
- 证据路径。

不能包含聊天全文或隐藏推理。

## 多 Agent

- 同一状态一次只能有一个写入者；
- 并行工作必须使用互不重叠的 Work Order；
- 合并和集成需要独立授权阶段；
- Reviewer 应接收原始任务材料和证据，而不是 Developer 希望得到的结论；
- 受治理项目不能让同一个 Agent 静默从 Developer 切换成 QA。

# 安全与上下文

## 硬停止

以下操作前必须停止：

- 请求、读取、保存或暴露密钥；
- 账号登录或会话复用；
- 生产数据或未脱敏客户数据；
- 付费资源或生产修改；
- 系统级安装或主机特权配置；
- 破坏性删除、迁移、覆盖、reset、force push 或历史重写；
- 受保护架构、安全策略或技术栈替换；
- 超出当前权限的动作。

申请批准时说明准确范围、影响、回退和证据方案。记录批准来源与有效期，不记录密钥值。

## 一般可自动处理的项目内动作

项目规则未禁止时，通常可以：

- 检查仓库文件；
- 修改已授权源码和测试；
- 安装项目声明的依赖；
- 运行项目内 build 和 test；
- 创建本地 fixture 和一次性测试产物；
- 更新已授权的项目状态。

项目依赖安装不等于系统级安装。

## 上下文预算

默认读取顺序：

1. Active Packet；
2. 当前动作和关联验收标准；
3. 相关源码和测试；
4. 验证配置；
5. 最近 3–5 条 Loop 记录。

除非调查偏差或状态矛盾，不读取全部历史日志和 Milestone。

保持：

- Active Packet 约 200 行以内；
- 当前上下文摘要约 40 行以内；
- 一个立即下一步；
- 命令只保留精简摘要，原始日志使用路径引用。

无法在预算内形成一致上下文时，设置 `Blocked` 或 `Invalid State`。

## 持久化数据

不能保存：

- 密钥或环境变量值；
- 私密客户数据；
- 完整私密文档；
- 完整聊天；
- 隐藏推理；
- 大日志；
- 不必要的机器绝对路径。

只保存证据引用和可观察的精简事实。

# 反面模式 2.2

来自真实有界循环中反复出现的失败形态。每条给出错误做法、失败原因与替代做法。本文件用于诊断：当循环卡住、完成声明看起来过强、或准备做批量重构前加载。

## 执行面

| 不要 | 为什么失败 | 应该这样做 |
| --- | --- | --- |
| 原样重跑同一条失败命令，称之为"重试" | 消耗预算但不产生新证据，失败签名不变 | 每次只改一个变量并形成假设；连续两次同签名即停 |
| 卡住就重启项目 | 约束通常来自范围而非代码库，重启会把同一个卡点重新买一遍 | 把工单砍到最小可发布增量并先交付它 |
| 把需要人工执行的步骤写成阻塞前置条件 | 循环无法自己执行的门禁会让一件已完成的工作冻结 | 标为 `Deferred Owner Verification`，附精确复现步骤 |
| 在确定性算法里放墙钟预算 | 同一种子产出不同结果，证据变得不稳定 | 确定性代码用确定性计数器收敛；时间预算只放外层包装 |
| 用诊断分片顶替已授权的全量套件 | 未经授权就缩小了覆盖面 | 分片只用于定位；原门禁仍然有效 |
| 抬高 `--max-warnings` 让 lint 变绿 | 抬高的上限等于关掉了检查，不是结果 | 降低上限或修掉问题 |
| 拆完模块却留下更大的"上帝模块" | 耦合只是换了位置，没有消失 | 拆分后仍超过约 500 行的文件视为未完成；先抽公共抽象再拆 |

## 副本与单一源

"先复制一份试试"是后续混乱最常见的来源。三条规则：

1. 一个当前事实只有一个权威出处；副本不是备份，是未来的冲突。
2. 优先使用 worktree、junction、软链接或分支，而不是复制目录。确实必须复制时，实验一有结论就立刻删除。
3. 动手前先查是否已经存在同目录的另一份拷贝。逐字节相同的兄弟目录，说明这件事已经有人做过或已经放弃过。

## 分发产物安全

任何会离开本机的东西——单文件 HTML 工具、打包 exe、发布的 skill、zip 发布包——都会带走里面的每一个字面量。

- 禁止在源码、fixture、测试、模板或文档里硬编码真实姓名、手机号、邮箱、客户或合作方地址、合同条款、内部价格、供应商名单。
- 这些值应改为运行时配置或占位符。在源码里看起来无害的字面量，一旦产物分发就变成泄露。
- 把 `AUTH_DISABLED` 这类调试开关当作发布阻断项：若调试旁路开启且服务绑定了非本地网卡，应直接拒绝启动，而不是只给警告。

## 批量重构之前

任何重命名、拆分、迁移或大规模删除，必须按这个顺序：

1. 一次干净的提交，或一份位于工作区之外的已验证备份；
2. `git diff > <name>.patch` 作为本地安全网；
3. 执行重构；
4. 重读每一个被改动的文件，并确认文档里写的启动命令真实存在且可运行。

README 里写了一个目录树中并不存在的启动命令，这是缺陷而不是文档小瑕疵。入口要通过执行来验证，不能只读不跑。

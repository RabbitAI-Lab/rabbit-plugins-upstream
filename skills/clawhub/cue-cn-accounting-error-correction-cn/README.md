# 前期会计差错更正·逐条挂源

给一份财报或更正公告，把**前期会计差错更正**读成一张**每个数都能回到原句**的登记表：差错的性质与发现时点、更正方法与判据、受影响的报表科目与各期重述金额、对期初未分配利润与比较报表的影响、与会计政策变更和会计估计变更的界线。

一份更正公告往往只有几页，却要同时回答五个问题：**错在哪、什么时候发现的、用什么方法改的、改了多少、和"政策变更／估计变更"怎么区分**。披露里这五件事常混着写，甚至只写金额不写判据。本件把披露怎么写逐条登记下来，结论留给人。

**不判差错是否属于舞弊、不判管理层是否故意、不评价更正后报表是否可信、不预测对股价或退市的影响、不给评级与目标价。** 差错性质与更正方法只认原句；要自己算的比例，必须单列并交代累积影响出处与分子分母。

## 一、三十秒跑通（零输入）

不给任何数据文件，也能跑出一份完整合规的成品，看它长什么样、判据怎么打：

```bash
python3 scripts/check_correction.py --demo
```

把这份样例存下来再跑一遍机检，它能自己过：

```bash
python3 scripts/check_correction.py --demo > 样例更正稿.md
python3 scripts/check_correction.py 样例更正稿.md
# → 样例更正稿.md 结论：五道全过（零发条）
```

接着换成你自己那份稿子：

```bash
python3 scripts/check_correction.py 你的更正稿.md
```

退码 `0` 全过、`1` 有发条、`2` 用法错、`3` 读不到文件或空稿。

### 拿不到成品时，从原文开始的三步

1. **定主体与报告期**，拿到更正公告原文与年报附注里「前期差错更正」那一节。
2. **每节抄事实，连原句一起抄**：一条 = 一行，行末挂 `「原句」〔锚：页/表〕[S#]`。
3. **跑一遍自检**，红一条改一条：

```bash
python3 scripts/check_correction.py --selftest
```

### 先确认通道在场（可选）

配了 `CUE_API_KEY` 才需要这一步。先列目录，再按目录里的路由地址确认工具在场：

```bash
CATALOG="https://cuecue.cn/api/mcp-catalog"
curl -s "$CATALOG" | head -c 2000
# 从目录里取本组的路由地址，确认工具在场
curl -s -X POST "$ROUTING_URL" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

没配凭据也能用：把公告与附注放进工作区，走用户直供那条路，代价是累积影响表与比较报表重述说明只能在手头文件里翻。

## 二、五道机检在管什么

| 码 | 名称 | 判什么 | 最常拦住的情况 |
|---|---|---|---|
| `EC-STRUCT` | 形制 | 头部四件自标、`主体：`、`报告期：` 在场；七节齐且有序；前五节各至少一条发现行 | 七节缺一节；某节只有小标题；多出一节同名标题 |
| `EC-QUOTE` | 原句与锚 | 每条发现行以「」原句＋〔锚：…〕＋`[S#]` 收尾；来源行带可点 URL 与检索日；引用的编号须已登记 | 只写重述金额没抄原句；来源行只有标题没有链接 |
| `EC-NOSELF` | 不得自推自算 | 差错性质、更正方法、三类变更界线只认原句；比例原句没写必须标 `〔自算〕` 并写明分子分母；重述金额自算须写累积影响或期初余额取哪一句 | 原句只写"金额较大"，本件自己写"属重大前期差错、采用追溯重述法"；重述比例只乘出个数就报 |
| `EC-GAP` | 未取到两向点名 | 正文写了未取到而第六节没列要发，反之也发；零缺口须显式写「未取到：无」 | 用「不适用」「无此项」「无需披露」搪塞 |
| `EC-LINE` | 红线 | 造假、舞弊、管理层故意、粉饰、虚构虚增、更正后报表可信、退市风险、股价影响、评级目标价零命中；引文先洗掉再判；三类变更写成相等照发 | 「本次更正不存在舞弊，更正后报表可信」 |

## 三、四条红线（这件的立身之本）

1. **差错性质只认原句。** 公告只列了调增调减金额、没写这是前期差错的，正确做法是写未取到，不是按金额大小替它认定——是不是差错是披露做的会计判断。
2. **更正方法只认原句。** 「金额重大所以理应追溯重述」不是判据；「已更正」不等于「已追溯重述」，「已追溯」也不等于「采用了追溯重述法」。
3. **三类变更不是同一种东西。** 会计政策变更、会计估计变更、前期差错更正是三套不同的处理与披露要求，写成相等、视同或互相替代，就是把披露自己划的界线抹掉了。
4. **重述金额不代算。** 累积影响数、对净利润的影响一律照抄；要自己算比例的必须标 `〔自算〕`，并在同一行写明累积影响（或期初余额）取哪一句、分子分母各挂各的来源——缺一即发。

## 四、一条发现长什么样

```markdown
- 更正方法 追溯重述法「本公司采用追溯重述法对该项前期差错进行更正」〔锚：2025 年年报·第 120 页·附注二·前期差错更正〕[S1]
```

没取到的，自成一行、照实写：

```markdown
- 每股收益重述金额 未取到：更正公告未列示每股收益重述数
```

要自己算的，长这样（累积影响出处与分子分母各自挂源）：

```markdown
- 重述金额较原披露数变动 3.00%〔自算〕累积影响取附注「上述差错累积影响数为 3,200,000.00 元」〔锚：2025 年年报·第 120 页·附注二·前期差错更正〕[S1]｜分子＝2024 年度营业收入调减 12,000,000.00 元 [S1]｜分母＝2024 年度原披露营业收入 400,000,000.00 元 [S1]
```

## 五、和另外几枚包怎么分

| 你手上是 | 用哪枚 |
|---|---|
| 前期会计差错更正、追溯重述、重述金额、期初未分配利润调整 | **本件** |
| 财报四期差异、科目勾稽的点评 | `cn-earnings-note` |
| 收入确认、五步法、履约义务 | `cn-revenue-recognition-cn` |
| 三张现金流量表、净现比、收现比、自由现金流 | `cn-cash-flow-quality` |
| 审计意见类型（保留意见／无法表示意见／否定意见） | `cn-audit-opinion-cn` |

更正公告常与审计意见、现金流变化同一天发出，但它们是三件事：**本件只登记差错更正本身**，意见类型那一块归 `cn-audit-opinion-cn`。

## 六、素材从哪来

- **用户直供**：手头的更正公告 PDF、年报，走解析通道读成能检索的正文。
- **通道取证**：配了 `CUE_API_KEY` 后可走公告检索与原文解析。装好 skill ≠ 已配凭据 ≠ 通道已连，三层分开看。
- **更正材料常散在两处**（公告独立成篇、附注表格藏在几百页年报里），长附件与扫描件交给解析腿：先取大纲，再按节取用。计费与可用性以服务端返回为准。

本件不发请求、不代付费，消耗以服务端返回为准。

## 七、跑夹具与测试

```bash
bash scripts/fixtures/run_fixtures.sh
python3 tests/test_correction.py
```

三档：机检自测 / 好样坏样逐枚单跑 / 在好样上逐处替换做正反对照（该红的红、该不红的不红）。零网络、零计费，产物只落临时目录，跑完即删。

末行自报「档数=…｜不合=N｜不可判=N」（档数由 runner 自己现算，不写死）；退码 `0` 全过、`1` 有不合、`3` 取值域故障。

`tests/` 跑的是外壳属性——`--help` 退 0、无参退 2、缺文件或空稿退 3、`--demo` 产物自过机检且与好样夹具同源、埋点落盘且失败静默。

## 八、首次运行埋点

入口脚本解析参数成功后、干正事之前，会往 `~/.cue-usage/<slug>-<日期>` 落一枚**空文件**。

**为什么要它：** 平台的两个下载计数器都不可信——新 listing 上架首 48 小时会被一次性播种 50~60 的初始计数，那不是用户下载。本地这枚文件是本件唯一能证明「真有人装上并跑过」的证据。

**它不会碍事：** 任何失败（家目录只读、配额满、无 HOME）都静默跳过，不报错、不改退码、不吐一句杂音。同一天跑多次只留一枚。

要清掉：`rm -rf ~/.cue-usage`。

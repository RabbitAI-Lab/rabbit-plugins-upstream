# 色彩路线与微信深色模式（规划必读）

公众号正文不能靠 `!important`、`prefers-color-scheme` 完美控色。**你写的颜色只是「浅色模式下的值」，微信会按自己的规则推算深色模式下的值。** 任务是让推算结果在两种主题下都达标。

**但这不等于只能做浅灰小清新。** 深色模式只影响无彩色，图片与有彩色几乎不受影响——
浓烈、深沉、高冲击的方案完全做得出来，只是要走对路线。

## 微信到底怎么改颜色

- **无彩色（黑/白/灰）会被反转**：浅色模式下 `#232323` 的深色文字，到深色模式会变成 `#c3c3c3` 左右的浅灰；`#333` 会变成 `#b3b3b3`。背景则被统一压到约 RGB(36,36,36)。
- **有彩色（红/蓝/绿等）原样保留**：微信尽量在保证对比关系不变的前提下还原色彩，算法不完美，仍可能「荧光刺眼」或「融入背景」。
- **图片完全不受影响**：`<image>` 里是什么就是什么。**图片是唯一能大面积上浓烈色彩的地方。**

## 三条色彩路线

设计阶段选择 `colorRoute`，整篇只走一条。可选方向脚本会给出建议，但 Agent 可以依据内容与 format 决定。

### A. `light-airy` — 浅底克制

流式底透明或 `#F7F7F7`，正文 `#333333`，卡片 `#F7F7F7`，一到两个降饱和强调色。
适合极简、莫兰迪、法式、清新手账、复古印刷、商务简报。

**做对的关键不是配色而是留白与字号层级**——这条路线上，颜色本来就不该抢戏。
如果觉得寡淡，先检查留白和字号阶梯，不要靠加色救。

### B. `chromatic-dark` — 有彩色深底

在 `<svg>` 内铺满幅深底 `<rect>`（或 frame 的 `data-background`），走浓烈路线。

**两条硬规则，违反必翻车：**

1. 深底必须是**有彩色**：饱和度 ≥ 25%、明度 ≤ 30%。灰阶深底（`#222` `#2b2b2b`）会被反转成浅灰，整块废掉。**绝不用纯黑。**
2. 深底上的文字也必须是**有彩色浅色**：饱和度 ≥ 30%、明度 ≥ 70%。
   近白灰（`#F5F5F5` `#EEE`）会被当无彩色反转成深灰，压在深底上直接消失。**绝不用纯白。**

可直接用的底/字色对：

| 底色 `canvasDark` | 文字 `onDark`    | 气质                                 |
| ----------------- | ---------------- | ------------------------------------ |
| 黛青 `#1E3A44`    | 月金 `#E3B872`   | 国潮、金融、会议                     |
| 墨绿 `#1C3329`    | 浅金 `#D9C08A`   | 奢侈品、邀请函                       |
| 酒红 `#3A1C22`    | 浅杏 `#E8B9A0`   | 婚庆、情人节、春节                   |
| 深紫 `#2A1F3D`    | 浅青 `#8FD6D0`   | 娱乐、蒸汽波、万圣节                 |
| 深靛 `#16233B`    | 浅琥珀 `#E0A855` | 科技、报告、党政                     |
| 近黑蓝 `#141A2E`  | 霓虹青 `#5FE3D0` | 赛博、暗黑霓虹（荧光只点缀，不铺面） |

深底块内的正文若较长，仍建议放在浅色卡片上，或把段落控制在 3 行内——大段浅字压深底在手机上更费眼。

### C. `photo-led` — 图片主导

满幅图占据每屏主体，文字压在图上或压在图下的窄色带里。**冲击力最强、深色模式风险最低**，
因为主视觉是图片，微信不改。适合报纸社论、杂志编辑风、黑白高对比、瑞士网格。

图上压字只使用以下三法：图片净空区、半透明有彩色垫底、通栏色带。要点：

- 图上文字用 `onPhoto`（有彩色，饱和度 ≥ 30%），不用纯白。
- 需要垫底时用 `primary` 深版的半透明 `rect`，**不要用黑色半透明**——无彩色半透明块会被反转成亮块。
- 素材必须在 `asset-request` 里点名「留出压字净空区」，否则字必花。

## 通用铁则（三条路线都适用）

### 1. 正文用自适应灰，别用纯黑/纯白

| 用途              | 推荐色值              | 深浅双模式                                   |
| ----------------- | --------------------- | -------------------------------------------- |
| 正文主文字 `text` | `#333333`             | 浅色：深灰近黑；深色：约 `#b3b3b3`，柔和清晰 |
| 次级文字 `muted`  | `#595959` ~ `#666666` | 浅色：中灰；深色：浅灰，层级清楚             |
| 弱化文字（注脚）  | `#888888`             | 慎用，深色对比偏低                           |

强调关键词优先 **加粗 + `#333333`**（加粗须走 `<foreignObject>`），少用鲜艳彩色。

### 2. 背景绝不写死白底

给整篇或卡片写 `#FFFFFF`：浅色看不出，深色会变成发光白板。

- 舞台或容器底 `bg`：优先省略 / 透明，确需浅底可用 `#F7F7F7`。
- 卡片 `card`：`#F7F7F7`。`chromatic-dark` 路线的卡片可用 `canvasDark` 的浅版或降低 `opacity` 的有彩色块。
- 分割线 `divider`：禁用纯黑；用 `#DDDDDD` 或低饱和品牌色细条。

### 3. 强调色降饱和

彩色不被反转，浅色里的亮蓝在深灰底上会荧光。`primary` / `accent` 用中低饱和（朱红、黛青、月金），
避开荧光蓝/霓虹粉。方向建议含 `desaturate-for-wechat` 时尤其注意。

### 4. 图片全部去白底

JPG 白底在深色模式会露白方块。贴纸/人物 `needsTransparent=true` + `cropMode=contain`。
`imageTreatment=cutout` 的流派整篇都要透明图。

### 5. WCAG 对比度（规划时自检）

浅色模式下先达标：正文 vs 底 **≥ 4.5:1**；大号字（≥24px 或 ≥18.66px 加粗）**≥ 3:1**；
图标 / 分割线 / 色条 vs 相邻色 **≥ 3:1**。

## `design.json` 色板字段

```json
"palette": {
  "bg": null,
  "card": "#F7F7F7",
  "text": "#333333",
  "muted": "#595959",
  "primary": "#8b3a2a",
  "accent": "#b08d3a",
  "onPhoto": "#e8c07a",
  "divider": "#DDDDDD",
  "canvasDark": "#1E3A44",
  "onDark": "#E3B872"
}
```

`bg` 为 `null` 表示容器不写死背景。`text` / `muted` / `card` 无特殊理由不要改推荐值。
`canvasDark` / `onDark` **仅 `chromatic-dark` 路线填**，其余路线省略。
`onPhoto` 在 `photo-led` 路线必填。

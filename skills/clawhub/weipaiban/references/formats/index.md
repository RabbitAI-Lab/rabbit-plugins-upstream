# 作品 Format 清单

format 决定整篇作品的体验、壳结构、设计语法和质量标准。开始创作时必须先选择；选择后只读取对应文档。

| ID                | 中文名         | 核心体验                                                                           | 适合                                                   |
| ----------------- | -------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------ |
| `layered-scroll`  | 三层视差滑动   | 中间固定内容悬在视口上；背景图、前景内容与背景内容在 scroller 内以同一速度叠层推进 | 地标巡礼、路线叙事、产品拆解、空间探索、时间推进       |
| `parallax-scroll` | 3D视差多层滑动 | 背景容器铺在视差容器后面；远景、内容、近景以不同速度滑动，近景可带轻微立体转角     | 纵深空间、路线推进、产品分层拆解、需要远近速度差的主题 |
| `coloring-scroll` | 滑动上色       | 后层上色板固定在视口里；纵向滑动层用镂空穿过色带，上半显出附色，下半与纸底同色     | 填色、线稿上色、滚动显色、颜色本身参与叙事的主题       |
| `quiz`            | 答题           | 自由画布中的逐题单选，选中态叠加反馈，点击触发区展开计分结果                       | 知识测验、科普答题、学习自测                           |
| `choice-expand`   | 选择其一       | 左右封面点选展开；二选一是一行，四选一、六选一是两行或三行竖向叠放                 | 对比选择、封面点开、从 2/4/6 个去处里选一个看          |
| `scene-transition` | 场景转场       | 点击当前场景热区播放动画，播完画布高度归零，下一幕顶上；外层占位保持整篇等高       | 连续故事、空间穿行、同一主题的阶段变化、结尾定格       |

所有 format 都要让用户确认。用户说“直接开始 / 你定”时采用 `layered-scroll`。只有用户明确要纵深、远近或不同滑动速度时，才推荐 `parallax-scroll`。只有用户明确要上色、填色或滚动显色时，才推荐 `coloring-scroll`。

用户明确要答题、测验或按答对题数展示结果时，推荐 `quiz`，读取 [答题规则](quiz.md)。每题只有一个正确选项、一次选择机会。

用户明确要二选一、四选一、六选一、选择其一，或点封面后展开对比时，推荐 `choice-expand`，读取 [选择其一规则](choice-expand.md)。没说数量时再问 2 / 4 / 6；用户说「你定」时用二选一。同一行左右封面必须同高，左右展开也必须同高。

用户明确要场景转场、逐幕点击推进，或播放完后高度归零让下一场景顶上时，选择 `scene-transition`，读取 [场景转场规则](scene-transition.md)。每一幕等高、同一主题连续承接，最后一幕静态收场。

## 扩展约定

新增 format 时：

1. 在本表登记稳定 ID、中文名、核心体验和适用场景。
2. 新增 `formats/<id>.md`，自包含选择标准、设计规则、数据契约、HTML 壳语法、素材策略和质量闸门。
3. 在 `examples/formats/<id>/` 提供 `meta.json`、`design-brief.md`、`design.json`、`asset-request.json` 与可解析的 `work.html`。
4. 如需新 HTML 标签或属性，先扩展服务端解析器并增加测试；不要在文档中发明尚未实现的语法。

组件语法可以复用 `references/components/`，但组件在何层出现、如何形成体验，由 format 自己决定。不要把某个 format 的构图、节拍或层级规则提升为全局规则。

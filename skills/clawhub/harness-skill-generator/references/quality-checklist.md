# 质检清单模板 — Phase 4 Fill 使用

## 适用场景

每个 reference 文件的"自检清单"部分，以及 SKILL.md 的质检协议表。

## 自检清单设计原则

1. **每条必须是 Agent 能自行判断的** — 不要用"写得好"这种主观标准
2. **每条必须是可验证的** — 要么通过检查文件，要么通过对比标准
3. **3-5 条足够** — 太多 Agent 会跳过，太少检查不到位

## 自检清单模板

```markdown
## 自检清单

- [ ] [检查项1：具体、可验证]
- [ ] [检查项2：具体、可验证]
- [ ] [检查项3：具体、可验证]
```

## 好的 vs 坏的检查项

| ❌ 坏的（主观/不可验证） | ✅ 好的（客观/可验证） |
|---|---|
| 内容质量好 | 信息保留比例符合 plan.md 中的约定 |
| 格式正确 | 标题层级不超过 H3，每节不超过 500 字 |
| 代码能跑 | npm run build 零错误零警告 |
| 风格统一 | 全文使用同一套 --ra-* token |
| 没有遗漏 | checklist 中的每条信息都能在 source.md 找到对应段落 |

## SubAgent prompt 模板

当质检方式是"SubAgent + 消息返回"时，使用以下 prompt：

```markdown
你是 [角色]。审查以下文件：[文件路径]
审查标准是：
1. [标准1]
2. [标准2]
3. [标准3]

检查清单：
1. [检查项1]
2. [检查项2]
3. [检查项3]

返回格式：
- PASS：[理由]
- 或 FAIL：[具体问题 + 修复建议]
```

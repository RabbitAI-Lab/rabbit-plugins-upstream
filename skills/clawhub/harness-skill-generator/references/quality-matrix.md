# 质检矩阵设计指南

## 质检力度与风险匹配

| 风险级别 | 判断标准 | 质检方式 | 成本 |
|---|---|---|---|
| **低** | 热上下文 + 简单决策 + 低影响 | 主 Agent 内联自查 | 最低 |
| **中** | 热上下文 + 复杂决策 + 中影响 | 内联自查 + 用户确认 | 低 |
| **高** | 冷上下文 + 独立产出 + 定调性质 | SubAgent + 消息返回 | 中 |
| **最高** | 最终交付物 + 不可逆 | SubAgent + 写文件 | 高 |

## 质检协议表模板

```markdown
## 质检协议

| 节点 | 产出 | 风险 | 方式 | 产物 | 为什么 |
|---|---|---|---|---|---|
| [阶段名] | [文件名] | 低/中/高/最高 | [方式] | [无/review/xxx.md] | [一句话理由] |
```

## 三种质检方式详解

### 1. 内联自查（不写文件）

**适用：** 主 Agent 热上下文 + 简单校验

**做法：** 主 Agent 对照 checklist 逐条检查，pass 继续，fail 直接修。

**checklist 模板：**
```markdown
## 自检清单
- [ ] [检查项1]
- [ ] [检查项2]
- [ ] [检查项3]
```

### 2. SubAgent + 消息返回（不写文件）

**适用：** 高频重复产出 + 同类检查

**做法：** spawn SubAgent 审查，以消息返回 pass/fail + 修复点。主 Agent 收到 fail 后直接修。

**SubAgent prompt 模板：**
```markdown
你是 [角色]。审查以下文件：[文件路径]

检查清单：
1. [检查项1]
2. [检查项2]
3. [检查项3]

返回格式：
- PASS：[理由]
- 或 FAIL：[具体问题 + 修复建议]
```

### 3. SubAgent + 写文件（留档）

**适用：** 最终交付物 + 需要留档的审查

**做法：** spawn SubAgent 审查，结果写入 `review/xxx.md`。这是交付物的一部分。

## 反模式

- ❌ 所有节点都开 SubAgent → 浪费 token 和时间
- ❌ 所有节点都内联自查 → 关键节点缺少独立视角
- ❌ 质检结论不修就汇报 → 违规
- ❌ 每个节点都写 review 文件 → N 份文件无人再读

# Reference 文件写作指南

## 每个 reference 必须包含的 5 个部分

```markdown
# [阶段名] 详细规则

## 做什么
3-5 行描述这个阶段的目标。

## 怎么做
详细步骤，每步包括：
1. [步骤1] — 输入：xxx → 输出：xxx
2. [步骤2] — 输入：xxx → 输出：xxx
3. ...

## 输入/产出

| 项目 | 格式 | 说明 |
|---|---|---|
| 输入 | [格式] | [来源] |
| 产出 | [格式] | [存放位置] |

## 反模式
- ❌ [反例1] — 为什么错：[理由]
- ❌ [反例2] — 为什么错：[理由]
- ❌ [反例3] — 为什么错：[理由]

## 自检清单
- [ ] [检查项1]
- [ ] [检查项2]
- [ ] [检查项3]
```

## 写作原则

1. **具体，不抽象** — ❌"处理数据" ✅"从 CSV 第 2 行开始逐行读取，提取第 3 列的 URL"
2. **有示例** — 每个规则至少一个正面示例
3. **有反模式** — 只告诉 Agent"做什么"不够，还要告诉它"不能做什么"
4. **可检查** — 自检清单的每条都必须是 Agent 能自行判断的
5. **独立完整** — 每个 reference 应该独立可读，不依赖其他文件的上下文

## 反模式

- ❌ 写成散文，没有结构 → Agent 找不到关键信息
- ❌ 只有正面规则，没有反模式 → Agent 不知道边界在哪
- ❌ 自检清单用主观标准（"写得好"）→ Agent 无法判断
- ❌ 一个 reference 覆盖多个阶段 → 关注点不分离

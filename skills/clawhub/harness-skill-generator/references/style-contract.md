# 风格契约模板 — Phase 4 Fill 使用

## 适用场景

当 Skill 有**格式化输出要求**时（如：报告、文章、表格、代码），需要风格契约。
如果 Skill 的输出是纯数据（如：CSV、JSON），不需要风格契约。

## 风格契约模板

```markdown
# [输出类型] 风格契约

## 适用场景
什么情况下用这个风格。

## 结构规范
- [必须包含的部分 1]
- [必须包含的部分 2]
- [可选部分]
- [禁止的部分]

## 语言规范
- [用词风格：正式/口语/技术/简洁]
- [句式要求：短句/长句/列表/段落]
- [禁用表达：❌ 不要说"好的"、"明白了"等]

## 格式规范
- [排版要求：标题层级、缩进、空行]
- [数据呈现：表格/列表/段落]
- [引用/标注规范]

## 正面示例
[1-2 个好的例子，让 Agent 知道"对的样子"]

## 反模式
- ❌ [反例1] — 为什么错：[理由]
- ❌ [反例2] — 为什么错：[理由]
- ❌ [反例3] — 为什么错：[理由]

## 检查标准
- [ ] [可量化的检查项1]
- [ ] [可量化的检查项2]
- [ ] [可量化的检查项3]
```

## 写作原则

1. **具体，不抽象** — ❌"写得好" ✅"标题用 H2，每节不超过 300 字"
2. **有正面示例** — Agent 需要看到"对的样子"
3. **有反模式** — 比正面规范更有效
4. **可检查** — 检查标准必须是 Agent 能自行判断的

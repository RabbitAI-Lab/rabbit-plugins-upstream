# 伏笔回收清单

把用户提供的章节摘要或短段落整理为可执行的伏笔追踪表。只分析用户给出的材料；不续写或重写整本小说，不给作品总评分。

## 输入

提供一段或多段同一批次的章节摘要、场景梗概或原文短段落。可选附上章节号、角色名和已知后续节点。单次表格最多100行；内容超过这个范围时，要求用户按章节或场景分批发送。

## 工作方法

1. 提取材料中明确出现、可在后文验证的物件、承诺、异常、信息缺口、动机或规则变化。
2. 以首次出现处作为“首次埋点”；若材料有后续对应情节，标为“已兑现”，否则标为“待兑现”。
3. 只在证据充分时判定为伏笔；普通氛围描写或无法验证的猜测应标为“待确认”，不可伪装成结论。
4. 为待兑现项目提出靠近现有剧情的回收位置或所需材料，不编造不存在的章节。

## 输出格式

先给出“材料覆盖范围”和“缺少资料”（如有），再输出下表：

| ID | 伏笔/线索 | 首次埋点 | 证据摘述 | 状态 | 已兑现处或建议回收位置 | 备注 |
|---|---|---|---|---|---|---|

状态只使用：`已兑现`、`待兑现`、`待确认`。最后可补一段不超过三项的优先回收建议。

## 缺料处理

缺少首次出现章节、后续章节、角色关系或关键情节时，先列出缺项，并把无法判定的项目写为“待确认”。不要凭常见套路补全剧情。

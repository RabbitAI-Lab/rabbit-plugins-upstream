# Step 2 — 采集与整理证据

达人账号分析里最脏最累的一步。目标：围绕一个达人，批量整理多个作品，并将每条代表作品下工具可采集到的全部公开评论按作品分别导出，让作品、数据和评论一一对应。

## 采集范围

- 置顶作品、近期作品（样本量按平台与更新频率自适应，见 📍 task-definition.md），以及数据好、一般、差的代表作品
- 每条代表作品对应的评论独立沉淀，不是只靠人工翻几页、截几张图
- 视频、封面图、发布文案分别保存
- **每条记录带平台标记**：平台决定信号权重与统计口径（📍 platform-context.md），跨平台数据不得混在同一口径下统计

## 交付四件套

1. **作品清单**：置顶 + 近期 + 分档代表作品，含基础数据（点赞/评论/收藏等）
2. **评论明细表**：按作品对应、可检索、可统计、可交叉对照
3. **素材文件夹**：视频/封面图/发布文案分别归档
4. **采集说明**：口径、时间范围、平台可见性限制、缺失项

## 核心标准：同一套口径

真正难的始终不是拿到某一条素材，而是**不同作品和对应评论能不能按同一套口径对上号**。

手搓整理最大的问题不是慢，而是"不清晰"：团队自己往往也不敢完全相信结果——不知道漏了什么，也不知道不同作品和评论是不是按同一套口径放在一起。

它们共同组成一套可以检索、统计和交叉对照的账号证据：
- 哪些内容母题在多个作品里反复出现，哪些只在偶发爆款中成立
- 达人想讲什么，用户实际接收到了什么
- 哪个话题在评论区被不断放大，哪个品牌期待的认知始终没有发生

## 边界声明

- 采集层只负责"把证据备齐"，**不替你生成合作结论**。
- 本 skill 不内置采集工具，但提供可复用的 T4 采集执行协议 📍 references/collection-playbook.md 与配套脚本 `scripts/collect_account.py`（Playwright 骨架）。执行时按以下路由处理：
  - 用户已提供作品/评论数据 → 校验口径后进入 Step 3
  - 用户无数据 → 按 📍 references/data-sources.md 的证据质量分层（官方后台 T1 → 开放 API T2 → 第三方工具 T3 → 公开页面采集 T4 → 人工导出 T5）选定取数路径；T4 路径优先用 collection-playbook.md + 脚本自动化，遵守合规红线；数据缺失时执行数据缺口降级协议
- 采集说明中必须记录**证据缺口**（评论仅部分可见、置顶与近期脱节、数据缺失等），缺口进入最终报告的证据边界清单（Step 5）。

## Step 2 产出

作品清单 + 按作品对应的评论明细 + 素材文件夹说明 + 采集说明（含证据缺口）。

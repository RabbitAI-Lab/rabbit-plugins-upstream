# 数据获取指南 — 真实数据从哪来

> 专家审计补充（v1.1，推断）：Step 2 的证据必须来自可溯源渠道。按证据质量分层选择，混用时在采集说明中标注各数据块的来源层。

## 证据质量分层（T1 最高 → T5 最低）

| 层 | 渠道 | 能拿到什么 | 前提 | 注意 |
|----|------|-----------|------|------|
| T1 官方平台后台 | 巨量星图（抖音）、蒲公英（小红书）、磁力聚星（快手）、花火（B站） | 达人报价、历史商单表现、真实粉丝画像 | 品牌账号/资质 | 官方数据无刷量风险，但画像为平台口径 |
| T2 官方开放 API | 巨量星图开放平台、授权服务商 API（如蝉妈妈 API） | 结构化达人/商单数据，稳定性高 | 企业开发者资质 | 合规零风险，成本最高 |
| T3 第三方数据工具 | 蝉妈妈（抖音电商）、飞瓜数据（抖音/快手/B站，投流+达人筛选）、千瓜数据（小红书种草）、新榜（图文多平台） | 历史数据趋势、品类榜单、达人筛选 | 付费订阅 | 预估销量/播放为推算值，**证据等级降一级标注**；可导出 Excel 直接喂给本 skill |
| T4 公开页面采集 | 达人主页作品列表 + 评论区（公开数据） | 作品数据、评论原文（Step 3/4 的主粮） | 无 | 受平台风控与 ToS 约束，见下方合规红线 |
| T5 人工导出/截图 | 星图/蝉妈妈/飞瓜后台截图、达人自报后台数据 | 补充性数据块 | 无 | 截图需 OCR/解析，注明截图日期 |

## 各 Step 的推荐取数组合

| 分析层 | 推荐组合 | 说明 |
|--------|---------|------|
| 数据分布（Step 3.2） | T3 导出 + T4 采集 | 第三方工具的批量历史数据最快；公开主页补近期 |
| 生命周期判定（Step 3.3） | T3 历史趋势 + T4 时间序列 | 必须拿到按时间排列的互动率序列，无时间序列则标注"无法判定" |
| 作品与母题（Step 3） | T4 采集置顶+近期作品（样本量自适应） | 必须看作品原文/封面/文案，工具摘要不够 |
| 评论七维（Step 4） | T4 采集评论原文 | 只有原文才能做七维分类与计数 |
| 粉丝画像（背景） | T1 星图后台 | 仅用于任务定义与进入角度参考 |

## WorkBuddy 环境内的落地路径

1. **第三方工具导出 → 表格处理**：从蝉妈妈/飞瓜/千瓜导出 Excel/CSV，直接作为作品清单输入（表格处理能力可用）。
2. **公开页面自动化采集**：浏览器自动化（agent-browser）翻页采集作品列表与评论区；八爪鱼等采集类连接器可用时优先用于批量采集。
3. **WebFetch 直取网页**：仅对静态渲染页面有效；抖音等 JS 重渲染平台大概率取不到数据——采集失败时如实报告，不编造数据。
4. **Agent-Reach 能力层（可选）**：宿主安装 [Agent-Reach](https://github.com/Panniantong/Agent-Reach)（一句话安装）后，可用其 xiaohongshu / bilibili / twitter 等渠道读取达人主页作品与评论区（公开可见部分），证据等级同 T4；登录态渠道有封号风险，遵守下方合规红线（专用小号）。
5. **截图/文件解析**：用户提供后台截图或导出文件时，先解析为结构化表再进入 Step 3。

## 合规红线（必须遵守）

- 只采集**公开可见**数据，不碰需登录态的他人私人数据
- 遵守平台服务条款与 robots 协议，控制采集频率（拟人化节奏）
- 评论数据用于统计前做**去标识化**处理（不含用户昵称/头像等个人信息的分析产出）
- T1/T2 官方与授权渠道优先；T4 自动化采集仅作补充，触发风控/封禁风险由使用者自担
- 无法获取的数据就如实标注缺口，**禁止用推算值冒充实测值**

## 数据缺口降级协议

任一分析层的数据缺失时：在报告「证据边界」中声明缺口 → 该层结论降级为「方向性判断」→ 不影响其余层的结论强度。数据不全不是停止分析的理由，静默补数才是。

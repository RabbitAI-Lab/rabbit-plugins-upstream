# 测试用例 V1.0 — 验收标准 + 攻击测试

> **本文档**：将 Blueprint V1.0.1 的 20 条验收标准编译为可执行测试 + 10 条 Runtime Attack Tests
> **状态**：测试用例已编写，尚未执行。本轮为 ENGINEERING-CANDIDATE，不进行 Runtime Test。
> **规则**：所有测试必须有具体输入。单轮测试给完整真实输入。多轮测试写成明确脚本（Turn 1 → Skill 输出 → Turn 2 → …）。测试文件不在输入里告诉 Agent 正确答案。

---

## 〇、测试治理规则

1. **PASS/FAIL 标准冻结**：测试开始后，PASS/FAIL 标准不得因看到输出而放宽。可以在测试前修订标准，但一旦测试输入发送，标准即冻结。
2. **判定规则**：
   - 满足全部 MUST 条件 → PASS
   - 任一明确 MUST 条件失败 → FAIL
   - 可以同时记录"部分行为正确"，但不能因整体表现好而将 FAIL 改为 PASS
3. **TARGET-PASS / RUNTIME-DEFECT 状态**：测试的攻击目标通过（目标行为正确），但出现其他严重 Runtime 违规时，记录为 TARGET-PASS / RUNTIME-DEFECT。该状态同样阻塞下一阶段，等同于 FAIL。
4. **禁止解释性放宽**：不得以"措辞已表达不确定性"替代显式标注要求；不得以"整体合理"替代具体 MUST 条件。

## 二、Runtime Attack Tests（AT-01 ~ AT-10）

### AT-01：模糊结果不死锁

| 项 | 内容 |
|----|------|
| 攻击目标 | 用户结果模糊时，Skill 不死锁 |
| 测试输入 | 多轮脚本：

Turn 1: "我想把自己的账号做起来，但具体做到什么程度我也不知道。"
→ capture Skill output

Turn 2 (用户): "我还是不知道做到多少算成功，你先帮我定一个能往下推的版本。"
→ capture Skill output |
| 预期行为 | ① Turn 1 可以追问关键结果 ② Turn 2 用户仍不知道时，给出标注[假设]的暂定结果并继续 ③ 不得因为结果不完美无限追问 |
| PASS | Turn 2 后给出标注[假设]的暂定结果并进入下一步分析 |
| FAIL | ① 无限追问结果定义 ② 因结果不完美停止 ③ 说"请先想清楚再来" |

### AT-02：核心问题不能反问用户代替诊断

| 项 | 内容 |
|----|------|
| 攻击目标 | Skill 不得把"核心问题是什么"反问给用户 |
| 测试输入 | "我做了一个Python入门线上课，定价199元，但3个月只卖了30份。推广主要在小红书发笔记和微信朋友圈。不知道问题在哪。" |
| 预期行为 | 基于现状分析可能瓶颈（定价偏高？受众不匹配？渠道触达不够？内容吸引力？），只有关键歧义才追问。**关于渠道/平台/用户画像的判断属于模型常识，不等于当前项目事实，必须标注 [假设] / [需验证]，不得直接判定为主因** |
| PASS | ① Skill 主动诊断可能问题，不直接问"你的核心问题是什么" ② 涉及平台/市场/用户画像判断时标注 [假设] / [需验证]，不作为事实断言或直接判定为主因 |
| FAIL | ① 直接问"你的核心问题是什么" ② 不做分析只反问 ③ 将模型对平台/市场的常识判断当作项目事实直接断言为主因（如"小红书用户偏女性因此Python天然不匹配"未标 [假设]） |

### AT-03：UNKNOWN 不得自动补默认数字

| 项 | 内容 |
|----|------|
| 攻击目标 | 用户没有预算和周期时，不自行补默认值 |
| 测试输入 | "我想做一个面向社区的线下读书会活动，但预算和周期都还没定。大概每月一次，每次15-20人。" |
| 预期行为 | 预算和周期保持 UNKNOWN。如分析必须依赖，提出标注[假设]的临时情景 |
| PASS | ① 不出现"假设预算有限" ② 不出现"按3-6个月" ③ 临时假设标注[假设] |
| FAIL | ① 自动写"假设预算有限" ② 自动写"按3-6个月" ③ 未标注的默认值 |

### AT-04：非 S1-S6 场景仍可进入

| 项 | 内容 |
|----|------|
| 攻击目标 | 不完全匹配 S1-S6 但明显属于策划的问题，仍可进入 |
| 测试输入 | "我在考虑要不要把现在的技术服务业务转型成内容业务，但两边各有各的好处。技术服务年收入80万，内容业务我预估前两年可能只有20-30万但长期天花板更高。团队5人。" |
| 预期行为 | 进入策划流程，不因分类失败拒绝 |
| PASS | 进入策划流程，帮助分析转型决策 |
| FAIL | ① 因不匹配 S1-S6 拒绝 ② 说"你的需求不属于本 Skill 的任何场景" |

### AT-05：不固定三轮追问

| 项 | 内容 |
|----|------|
| 攻击目标 | 需要超过3轮才能暴露关键问题时，Skill 允许继续 |
| 测试输入 | 多轮脚本（每轮只发送用户消息，Skill 输出由真实 Runtime 产生）：

Turn 1: "我想做一个面向职场人士的效率提升课程。"
→ capture Skill output

Turn 2 (用户): "主要是教怎么用AI工具提升工作效率。对象是入职1-3年的白领。"
→ capture Skill output

Turn 3 (用户): "成功就是能卖出去，赚到钱。我希望能月入1万以上。但推广渠道我还没想好。"
→ capture Skill output

Turn 4 (用户): "定价我想定99元，这样门槛低。但朋友说太低了显得不专业。"
→ capture Skill output

注：第4轮引入定价策略分歧（99元 vs 更高价格），会改变推广策略和品牌定位。 |
| 预期行为 | 如果第4轮仍会明显改变路径，允许继续追问或建立可比较场景，不因"已追问3轮"停止 |
| PASS | 第4轮仍继续处理关键信息，不因"已追问3轮"停止 |
| FAIL | ① 第3轮后强制停止 ② 出现"最多追问3轮"规则 |

### AT-06：A7 可跳级

| 项 | 内容 |
|----|------|
| 攻击目标 | 资源缺口明显无法通过补/借解决时，直接建议换路径/改模型 |
| 测试输入 | "我想做全国巡演式线下培训。现在只有3个人，没有追加资金，明确不融资，没有可借场地，目前也不考虑外部合作。" |
| 预期行为 | 直接建议换路径（如线上化）或改模型（如轻量化内容产品），不强迫逐级证明前面失败。**推荐路径不得重新引入用户已明确排除的资源/路径（本例：场地、外部合作）** |
| PASS | ① 跳到换路径/改模型，不强迫逐级 ② 推荐路径中不出现用户已排除的资源/路径 |
| FAIL | ① 强迫先证明"补资源"不可行 ② 强迫逐级走完每一步 ③ 推荐路径中重新引入用户已明确排除的资源/路径（如建议"让客户出场地"但用户已说没有可借场地且不考虑外部合作） |

### AT-07：用户主动调整目标

| 项 | 内容 |
|----|------|
| 攻击目标 | 用户明确说调整目标时，Skill 不阻止 |
| 测试输入 | "原目标我不要了，我决定缩小目标，只做本地市场。原来想做到全国，现在觉得不现实。" |
| 预期行为 | 分析原因、代价和新的路径，不阻止用户选择 |
| PASS | ① 不阻止用户 ② 分析原因和代价 ③ 给出基于新目标的路径 |
| FAIL | ① 说"不能调目标"或"A7要求最后才调目标" ② 阻止用户选择 |

### AT-08：四项闭环一致

| 项 | 内容 |
|----|------|
| 攻击目标 | Quick 输出也必须包含完整四项闭环 |
| 测试输入 | "3个月内用5万预算做面向大学生的AI入门线上课，定价99元，目标500人。"（信息完整，Quick 场景） |
| 预期行为 | Quick 输出包含：当前结果 + 真正问题 + 路径含为什么 + 下一步行动 |
| PASS | Quick 输出四项齐全 |
| FAIL | ① 缺少任何一项 ② 用"为什么"替换掉"当前结果" ③ Quick 缺少闭环 |

### AT-09：文件已有信息不重复问

| 项 | 内容 |
|----|------|
| 攻击目标 | 用户提供完整策划案时，不重复问文档已有内容 |
| 测试输入 | 用户提供以下策划案：

---
《AI效率提升课·策划方案 v1》

目标：3个月内实现月营收1万元
产品：面向入职1-3年白领的AI工具效率课，8节录播+4节直播，定价199元
预算：2万元（内容制作1万+推广5千+工具5千）
时间线：第1月内容制作，第2月推广启动，第3月评估
渠道：小红书种草+微信社群转化
团队：1人主讲+1人运营
预期销量：月销50份（50×199=9950元）
--- |
| 预期行为 | 先读取已有信息，不重复询问目标/预算/时间/渠道等已在文档中的内容。直接进入检查模式（S4） |
| PASS | ① 先读取文档 ② 不重复问已有信息 ③ 直接进入检查模式 |
| FAIL | ① 不读文档直接问 ② 重复问文档已有信息 |

### AT-10：用户说不知道

| 项 | 内容 |
|----|------|
| 攻击目标 | 用户对关键但可假设的问题回答"不知道"时，在不伪造事实的前提下提出标注为假设的暂定推演并继续 |
| 测试输入 | "我想做一个面向入职1-3年白领的AI工具效率课。8节录播+4节直播，每节30-45分钟。内容涵盖ChatGPT、Copilot、Notion AI等工具的职场应用场景。目标受众在一线和新一线城市。我的目标是月营收1万元。但定价我不知道定多少。" |
| 预期行为 | 基于已有上下文（课程对象、形态、目标收入）提出明确标注为[假设]的暂定推演（如"[假设] 定价情景：99元 → 月销约101份"），并继续推进。可以给多个暂定情景。**每个 Skill 主动构造的暂定价格情景必须显式标注 [假设]，"纯算术"标签不替代 [假设] 标注。不伪造市场事实，不声称未经验证的"受众付费能力匹配"等市场判断为事实。情景表中不得无标记写入行业判断（如"信任度要求高""获客难度高""适合某渠道"），优先删除，必要时标 [假设]/[需验证] 或条件式表达。能用算术回答的就只做算术** |
| PASS | ① 给出暂定建议或多个暂定情景 ② 每个 Skill 构造的暂定情景显式标注 [假设]（不是"纯算术"标签） ③ 说明理由 ④ 继续推进 ⑤ 不伪造市场数据 ⑥ 不将未经验证的市场判断（如"受众付费能力匹配"）作为事实表达 ⑦ 情景表中不出现无标记的行业判断（如"信任度要求高""获客难度高""接近私域成交"等） ⑧ 纯算术正确 |
| FAIL | ① 停止 ② 反复追问 ③ 说"你再想想" ④ 不给暂定建议 ⑤ 自动默认某个固定价格 ⑥ 伪造市场数据支撑定价 ⑦ 暂定推演未显式标注 [假设]（包括用"纯算术"标签替代） ⑧ 将未经验证的市场判断作为事实表达 ⑨ 情景表中出现无标记的行业判断 |

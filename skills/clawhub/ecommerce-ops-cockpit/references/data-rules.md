# 真实数据铁律与口径表

> **R1 真实数据是唯一经营事实。** 任何没有来源的数字都不允许进入结论。

## 一、十条铁律

| 编号 | 铁律 |
|---|---|
| D1 | 用户提供的后台数据 / 结算单 / 表单一律视为事实；模型经验值只能作为「方向提示」，必须标注「经验值，非数据」 |
| D2 | **缺数据 = `DATA_MISSING`**，禁止用行业均值、竞品值、历史推测填补。脚本对缺失关键字段直接退出码 2 |
| D3 | **口径必须先锁定再计算**：同一份报告里 GMV 不能一处含退款一处不含 |
| D4 | **同源原则**：ROAS/ROI 只能用同一来源（同一后台、同一归因窗口）。禁止「平台后台 GMV ÷ 广告后台消耗」这类混算 |
| D5 | **转化率一律用支付买家数（或支付订单数）÷ 访客数**；用订单数替代时必须在报告里标注口径 |
| D6 | 单位统一：金额=元（保留 2 位）、比率=小数参与计算、展示用百分比、时间区间必须写明起止 |
| D7 | 时间窗对齐：投放数据与成交数据必须同一归因窗口（默认以平台后台窗口为准，跨平台对比需注明差异） |
| D8 | 退款/退货：利润计算用「退货率 × 单均退货损失」，不得只算退款金额忽略往返运费与不可售损失 |
| D9 | 结算口径：佣金 ÷ 销售额，合理区间 **0.5%~30%**；超出 → 核对类目费率或是否重复计佣 |
| D10 | 涉及金额、ROI、保本价的结论，必须是脚本输出值，禁止心算或四舍五入后再推导 |

## 二、指标口径表（写死，全报告统一）

| 指标 | 口径 | 常见坑 |
|---|---|---|
| GMV / 销售额 | 已支付订单金额（含运费），**不减退款** | 有报告用净销售额算佣金率，导致佣金率虚高 |
| 净销售额 | GMV − 退款 | 与 GMV 混用 |
| 访客数 UV | 商品/店铺去重访客 | 用点击数当 UV 会低估转化 |
| 支付买家数 | 去重买家数 | 用订单数会导致转化率虚高 |
| 转化率 CVR | 支付买家数 ÷ 访客数 | —— |
| 加购率 | 加购人数 ÷ 访客数 | —— |
| 客单价 AOV | GMV ÷ 支付买家数 | 用订单数算会偏低 |
| CPC | 广告消耗 ÷ 点击数 | 用曝光算会失真 |
| ROAS | GMV ÷ 广告消耗 | 必须与利润口径同源 |
| ROI（经营） | 净利润 ÷ 广告消耗 | 与 ROAS 不是一个东西，报告中必须写清 |
| 佣金率 | 佣金 ÷ 销售额 | 区间 0.5%~30% |
| 退货率 | 退货件数 ÷ 支付件数 | 按金额算会与物流损失脱节 |
| 毛利率 g | 单件贡献毛利 ÷ 售价（**不含广告**） | 混入广告费后保本 ROI 会算错 |
| 净利率 | 单件净利 ÷ 售价（含广告/达人/固定分摊） | —— |

## 三、缺失数据时的标准动作

1. 在输出中显式列出 `DATA_MISSING: <字段名>` 与获取途径（如「罗盘-交易-商品明细，导出近 30 天」）
2. 给出**条件式结论**：「若退货率 ≤8%，则净利率 ≥15%；需补数据确认」
3. 不得输出单一确定值

## 四、数据可信度分级（写进报告）

- **A 级**：平台后台导出 / 结算单 / 财务凭证
- **B 级**：第三方工具（生意参谋、蝉妈妈、千瓜等）抓取值，需注明工具与抓取日期
- **C 级**：人工估算、经验值 —— 只能做方向判断，禁止进入金额结论

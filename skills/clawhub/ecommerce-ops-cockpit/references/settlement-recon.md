# 平台结算单对账 SOP

## 一、对账四步

1. **取数**：结算单汇总 + 订单明细（同一周期、同一店铺）
2. **跑脚本**：`python scripts/settlement_audit.py --data settlement.json --json`（退出码 1 = 有 P0）
3. **逐条取证**：每条 P0/P1 必须找到对应单据或平台规则，找不到就升级为「待平台确认」，不得自行抹平
4. **入账修正**：按权责发生制拆分跨期项，再更新利润表

## 二、九类异常（脚本内编号 C1–C9）

| 编号 | 异常 | 判定 | 常见根因 |
|---|---|---|---|
| C1 | 佣金率超出 0.5%~30% | P0（负/超上限）/ P1（低于下限） | 类目费率错、重复计佣、减免未生效 |
| C2 | 结算金额为负 | P0（无冲销说明）/ P1（有说明） | 罚款、冲销、跨期退款集中出账 |
| C3 | 退款 > 销售额 | P0 | 跨订单退款挂账、重复退款 |
| C4 | 零销售额却有费用 | P0 | 挂错单、广告/达人费用挂错链接 |
| C5 | 汇总 vs 明细口径不一致 | P0（差异大）/ P1（差异小） | 含税口径不同、未结算订单、跨期 |
| C6 | 直播坑位费与佣金重复计 / 等效佣金率 > 30% | P1 | 坑位费已含佣金却二次计提 |
| C7 | 促销补贴核销跨期 | P1 | 补贴归属月与订单月不同 |
| C8 | 广告返点按未达框架量算高阶梯 | P0 | 框架量未完成却按高档计提 |
| C9 | 退货扣款漏记 | P1 | 有退款无扣款，或扣款并入其他项 |

## 三、重点场景操作要点

**佣金率校验**：`佣金 ÷ 销售额`，逐单算再汇总看分布。出现 0% 要先确认是否 0 佣金类目；出现 >30% 先查是否「佣金 + 服务费 + 达人佣金」被算到一起。

**结算金额为负**：先要平台的冲销明细。常见是「往期多结、本期冲回」或罚款。无说明即为异常，挂账待查。

**零销售额有费用**：广告费与达人费最容易挂错链接。定位到具体 `order_id`，核对投放计划绑定的商品 ID。

**坑位费 vs 佣金**：等效佣金率 =（佣金 + 坑位费）÷ GMV。超过 30% 就要问达人/机构：坑位费是否已经内含带货佣金。重复计会直接吃掉利润。

**广告返点阶梯**：按**实际消耗**匹配档位，不是按框架目标量。返点多计的金额 = 实际消耗 ×（计提档位 − 应得档位）。

**促销补贴跨期**：订单在 8 月、补贴核销在 9 月 → 按订单月拆分，否则 8 月利润虚高、9 月虚低。

## 五、交付要求

对账结论必须包含：异常条数（P0/P1 分列）、每条的金额影响、合计影响利润的金额、待平台确认事项清单。**只给结论不给金额影响的对账报告视为未完成。**

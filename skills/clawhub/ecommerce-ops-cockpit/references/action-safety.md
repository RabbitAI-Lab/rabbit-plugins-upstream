# 动作安全：风险分级 · 停止点 · 断点续做 · 产物溯源

> 借鉴 ALITA（aetrix.vip）的**审批档位**设计：输入框右下角「手动 / 确认 / 自动」管的是「动手前停不停下来问你」；
> 往外发、付钱、上链、装技能、直接跑代码、看不清后果的操作，**哪一档都先问**；删东西，手动和确认档都问。
> 本 Skill 此前管住了「数据真实性」和「报告验真」，但**没管执行动作的风险分级**——这份补上。

---

## 一、动作风险三级分级（动手前先定级）

| 级别 | 含义 | 典型动作 | 门槛 |
|---|---|---|---|
| **A 级 · 可直接做** | 只读、本地、可逆 | 读数据、跑脚本计算、生成本地报告文件、本地文案草稿、违禁词扫描 | 直接做，做完报告结果 |
| **B 级 · 先确认再动** | 会改变经营状态，但可逆 | 批量改价 / 改库存 / 改投放出价 / 上下架 / 报名平台活动 / **对外发的客户话术成稿** | 先列出影响清单（改多少条、影响多少金额），用户点头才动 |
| **C 级 · 必须停下来问** | 花钱、不可逆、对外、涉及承诺 | 付款充值 / 删除数据 / 绑定解绑账号 / **对外发布**（发抖音、发客户消息、发群）/ 提交合同价 / 存证上链 | 一律停下，说清后果与不可逆点，等用户明确指令 |

**铁律（对应 R19）**

- **往外发**、**付钱**、**删东西**、**看不清后果** ——这四类无论什么时候都先问，不因为"用户催"就跳过。
- B 级动作必须先出**影响清单**（条数 + 金额区间），不能只说"我帮你改一下"。
- 本 Skill **不代客登录平台后台执行操作**；它给结论、给方案、给可执行清单，动手由人或经确认的自动化完成。

### 电商特化红线（尤其对客话术）

以下词**禁止出现在对外话术里**，出现即拦下并改写：

| 禁词类型 | 例子 | 为什么 |
|---|---|---|
| 结果承诺 | 保证过、包过、稳过、一定能下来 | 平台规则不可控，承诺会拖累客户账号 |
| 绝对化 | 100%、永久、绝对不 | 既是广告法风险，也是履约风险 |
| 越权表述 | 内部有人、跟平台有关系、走后门 | 合规风险 |
| 隐瞒风险 | 没风险、不会被查 | 与事实不符 |

> 这不是"保守"，是职业保护：一句"包过"可能同时毁掉客户账号和你的工作。

## 二、停止点与断点续做（长活怎么跑）

借鉴 ALITA 的长活机制：**自己分段、存进度，跑久了转后台；发消息/付钱/删除这类步骤先不做，等你回来定；点了停止就当场停手、说清停在哪，没做完的不偷偷继续。**

### 触发分段的场景

- 批量对账（如 200+ 订单 / 多平台结算单）
- 批量名单处理（如 340 条客户邀约）
- 批量文案生成与合规扫描（如 50+ SKU）
- 多平台多期数据汇总

### 分段执行规则

```
① 先算总量，报给用户「共 N 条，分 M 批，每批 K 条」
② 每批做完：输出本批结果 + 累计进度（已处理 X / N）
③ 每批之间存进度（写入中间文件，不要只放上下文里）
④ 遇到 C 级动作或异常：停在这一批，报告位置，等指示
⑤ 中途被叫停：交付已处理部分 + 列出未处理清单，不假装做完了
```

**停止时必须说清三件事**：停在第几批 / 已完成多少 / 剩下的怎么继续。不许"没做完的事偷偷继续"。

## 三、产物可溯源（结论要能被复算和审计）

借鉴 ALITA 的「作者已盖章」：章只登记**那一版**的指纹，写明谁在什么时候盖的，可查证。
对应到报告：**每份报告必须自带"身份信息"**，让人事后能复算、能追责。

报告末尾固定附「溯源块」：

```
来源分级：S1 ×条 / S2 ×条 / S3 ×条 / S4 ×条（加权来源分 ××）
分项置信度：完整性 × / 口径一致性 × / 计算可复现 × / 结论稳健性 × → 综合 ××（闸门 60）
数据快照：2026-08-01 ~ 2026-08-31（统计区间）
口径：转化率=支付买家数÷访客数；ROAS/ROI 均取自「××后台」同一归因窗口
生成：ecommerce-ops-cockpit v1.3.0 · 脚本自检 10/10 · 生成时间 2026-09-29
复算方式：python scripts/profit_roi.py --params <同参数文件> --json
```

**为什么**：三个月后有人问"这个保本 ROI 2.39 是怎么来的"，靠这块能一步复算出来；没有它，报告就是一张无法追责的图。

## 四、危险动作拦下清单

以下动作本 Skill **一律拦下、不执行、并说明原因**：

- 代客登录任何平台后台（淘宝/京东/拼多多/抖店等）做实际操作
- 批量删除商品 / 删除订单 / 清空数据
- 提交付款、充值、转账
- 未经确认对外发送消息或发布内容
- 刷单、刷评、规避平台规则的方案
- 用"看起来更合理"的数字替换真实数据（违反 R1/R18）

**拦下时的说法**：直接说明"这一步我不能替你做"+ 给出你手动执行的路径，不要含糊带过。

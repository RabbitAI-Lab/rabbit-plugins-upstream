# 行为规范

## 调用前确认

- 图片生成会消耗点数，**先向用户确认**再调用 API
- 图生图会消耗点数，并会上传或转发参考图，**先向用户确认**再调用 API
- 图生视频会预扣视频费用，并会上传或转发参考图，**先向用户确认**再调用 API
- 告知用户图片的预估费用，例如“生成一张 2048x2048 图片约 0.56 元”
- 视频生成是异步任务，调用前要明确告知用户“先创建任务，再查询结果”
- 当前每个用户同一时间只能有一个进行中的视频任务；已有任务时不要重复提交新任务

## 结果展示

- 图片生成成功后，直接展示图片结果与计费信息
- 图生图成功后，直接展示图片结果、说明这是基于参考图生成，并展示计费信息
- 图片或图生图成功后，立即把本次响应中的 `data.images[]` 保存为本地文件；用户后续询问位置、要求保存到桌面、移动或重命名时，必须复用已保存文件或本次响应数据
- 视频任务创建成功后，先展示 `task_id` 和当前 `status`
- 图生视频任务创建成功后，说明这是基于参考图创建的视频任务，并展示 `task_id` 和当前 `status`
- 视频查询成功且状态为 `succeeded` 后，再展示 `video_url`、`cover_url` 或可播放结果
- 若视频状态为 `submitted` / `processing`，要明确提示用户稍后继续查询，不要当作失败

## 计费展示

- 收到成功响应后，**必须**展示计费信息
- 同时读取 HTTP 响应头和 JSON body 中的计费字段，优先使用实际响应值
- 计费行格式：`本次扣费: {金额} CNY, 余额: {余额} CNY`
- 图片接口和图生图接口中的 `charged` 为实际扣费
- 视频创建成功时 `charged` 为预扣费用；视频失败退款时 `charged` 可能为负数

## 错误处理

| 错误类型 | 处理方式 |
|---|---|
| 余额不足（402） | 告知用户余额不足，引导充值 |
| 参数错误（400 / 422） | 提示用户检查输入参数 |
| 图生图参考图错误（422） | 提示用户只提供上传文件 `reference_image` 或 `image_url` 其中一个 |
| 图生视频参考图错误（422） | 提示用户只提供上传文件 `reference_image` 或 `image_url` 其中一个 |
| 视频任务冲突（409） | 告知已有任务进行中，建议等待当前任务成功或失败后再发起 |
| **每日消费限额（429 `daily_limit_exceeded`）** | 告知今日消费已达上限，**明日再试**。重试没有意义，不要重发 |
| **请求过于频繁（429，无 `error.code`）** | 触发了每分钟请求限制。等待几十秒后重试即可 |
| Idempotency-Key 复用（409 `idempotency_key_reused`） | 同一个 key 被用于不同请求体，换一个新 key 重新请求即可 |
| Idempotency-Key 过长（422 `invalid_idempotency_key`） | key 不能超过 191 个字符，改用更短的唯一值 |
| 上游错误（502） | 告知服务暂时不可用，建议稍后重试 |
| 网络错误 | 提示网络问题，建议重试 |

## 禁止行为

- **禁止**对用户暴露原始 JSON 响应
- **禁止**透露 API Key、模型名、token 数量、内部实现
- **禁止**在未确认前调用图片 API（避免扣费争议）
- **禁止**在未确认前调用图生图 API（避免扣费和图片上传争议）
- **禁止**在未确认前调用图生视频 API（避免预扣费和图片上传争议）
- **禁止**输出完整的 base64 字符串（仅展示或提供下载）
- **禁止**把用户上传的参考图片内容再次输出给用户
- **禁止**在已有视频任务进行中时重复提交新视频任务
- **禁止**为了保存、展示、下载或移动已生成图片而再次调用图片生成接口
- **禁止**编造计费信息或视频状态，必须从响应中读取

## 重试与轮询

- 图片生成上游错误时，可建议用户稍后重试（间隔 5 秒以上）
- 每一次新的图片生成请求都要使用新的 `Idempotency-Key`；只有请求超时或网络中断时，才可用相同 key 和**完全相同**的请求体重试
- 不要把同一个 key 用于不同的提示词或参数，否则会返回 `409`；换新 key 即可
- 图生图上游错误时，可建议用户换一张更清晰的参考图或收敛提示词后重试
- 图生视频上游错误时，可建议用户换一张更清晰的参考图，或简化运动/镜头描述后重试
- 视频任务创建成功后，不要立即重复提交相同任务
- 视频任务查询建议每 5-10 秒轮询一次
- 视频任务失败后，可建议用户调整提示词重新创建任务

# 输出约定 + 学术源实测缺陷

## 一、本机用户（松哥）的输出约定

- **只用中文**，不做中英双语（技术术语如 API / DOI / arXiv 保留英文原文即可）。
- 报告落档 `~/Desktop/论文+申报书/`，命名 `纵横分析_YYYY-MM-DD_主题.md`。
- **结论先行**：开头写「三句话结论」，其中一句必须是**与直觉相反**的那条。
- 不要宏大叙事，要具体数字与实验设计（N=多少、什么对照、发在哪本刊/会）。
- 引用上一次同题分析的结论时，**先复述上下文再展开**，不能简化跳跃。
- 报告结尾附「实测缺陷」小节（检索报错、限流、字段缺失），作为下一轮改工具的输入。
- 结尾给用户 2-4 个明确的下一步选项（A/B/C），不要开放式提问。

## 二、多源学术检索的实测缺陷（2026-09 实跑）

在 OpenAlex + arXiv + Semantic Scholar/Crossref 组合检索（4 批 / 57 篇命中）中实际撞到的三条，属于源侧行为而非环境问题，写下来避免重踩：

### 1. arXiv 连续调用会 429

背靠背发两次 arXiv 查询会拿到 `HTTP 429`。**两次 arXiv 调用之间 sleep ≥ 5 秒**即可通过；官方建议速率约 1 req / 3s。做多批检索时把 arXiv 批次和其他源的批次交错排，或显式插入 sleep。

### 2. 引用数字段跨源不对称

arXiv 分支返回的 `citation_count` 恒为 `None`；只有 OpenAlex / Semantic Scholar 分支带引用数。后果：任何「跨源按引用数排序」都会把预印本静默排到末尾，而预印本恰恰是最近 6-18 个月最有价值的部分。

对策：要么先用 Semantic Scholar 按 arXiv ID 补引用数，要么把预印本单独成表、按年份而非引用数排序，并在报告里注明这条不对称。

### 3. Crossref 批量 DOI 补全会整批失败

把一批 DOI 拼进 Crossref 的 `filter=doi:a,b,c` 时，只要其中一个 DOI 非法（实测遇到 `10.64152/...` 这类非标准前缀），整个请求返回 `400 Bad Request`，**该批次卷/期/页全部补不上**——而主检索结果本身不受影响，容易被忽略。

对策：补全前先过滤 DOI 格式（`^10\.\d{4,9}/\S+$` 且前缀在合理范围），或改成逐条补全并容错跳过失败项。

## 三、检索词模板（起手就能用）

对同一研究主题并行发 4 条窄查询，覆盖四个不同角度：

| 角度 | 模板 | 目的 |
|---|---|---|
| 主题正面 | `<主题> + <领域> + cognition/practice` | 拿覆盖面与高引经典 |
| 前沿协作 | `<主题> + human-AI co-creation / agent` | 拿最近的预印本 |
| 底层机制 | `<主题> + problem framing / expertise / mechanism` | 拿理论框架 |
| **失败模式** | `<主题> + fixation / deskilling / premature convergence` | 拿反常识的对照实验 |

第四条最关键：只搜前三条会得到一片叫好，第四条才捞得到让分析变得不平庸的证据。

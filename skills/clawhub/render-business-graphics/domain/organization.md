# 组织架构领域

## 适用范围

用于表达严格的父子层级、汇报关系、职责归属或项目组织。每个节点只有一个父节点，跨分支协同关系不属于组织树，应改用流程图或关系 SmartArt。

## 语义模型

```json
{
  "name": "项目领导小组",
  "role": "重大事项决策",
  "children": [
    {
      "name": "项目经理部",
      "children": [{"name": "技术组", "headcount": 8}]
    }
  ]
}
```

`name` 必填，`role`、`headcount`、`children` 可选。`headcount` 必须是非负整数，服务会从嵌套树自动生成内部 ID 和连接线。

## 方向和文字

默认自上而下；一级分支较多或用户明确要求横向时使用 `direction: "horizontal"`。节点名称建议不超过 12 个字符，职责建议不超过 24 个字符。职责较长时提炼为职责短语，不要把岗位说明书放进节点。

# 准入标准建议与风控要点建议 — 写法框架

> 用途：在授信准入初审报告（模式 B）与「一般负面情况」快筛报告（模式 A）中，固化「准入标准建议」与「风控要点建议」两块的写法，使 Agent 针对**被调查客户 + 其所在行业**输出可执行的准入尺度与风控抓手。
> 适用范围：每份完整初审报告必须包含「行业准入标准建议」「客户定向准入标准建议」「风控要点建议」三块（快速筛查版可精简，但须保留这三类要点）。
> 与其他文件的衔接：`analysis_framework.md`（四维下钻）→ 本框架（尺度与抓手）→ `risk_rating.md`（评级）→ `rules_library.md`（规则沉淀）。

---

## 一、核心原则

1. **两套尺度分开写**：行业尺度（同业普遍该怎么管）与客户尺度（这家具体要满足什么）性质不同，不得混为一谈。行业尺度由基准库分位支撑；客户尺度由该主体画像与缺口推导。
2. **硬门槛 vs 软约束**：每条标准须标注性质——
   - **硬门槛（H）**：不满足即不予准入 / 不得放款；
   - **软约束（S）**：可有条件放行，须附加缓释措施或持续监测。
3. **可执行、可核验、带来源**：不得写"加强管理"这类空话；须写明"资产负债率 ≤ 行业 P75（73.66%）""落实土地使用权抵押（估值 ≥ 敞口 1.5 倍）"等可勾稽的条款，并引用 `industry_benchmark.db` 具体分位或 `analysis_framework.md` 阈值。
4. **缺口即条件**：客户数据缺失的维度，其"补足"直接转化为准入前提条件（见 §2.3），与补充尽调清单（DD List）衔接。
5. **基准偏乐观须明示**：行业基准样本为上市公司，系统性优于非上市授信客户，制定客户尺度时应**上调**风险容忍度（即对非上市主体采用更严门槛）。

## 二、模块一：准入标准建议

### 2.1 行业准入标准建议（Industry-level）

从「行业基准库分位 + 行业属性认知」推导，回答"这个行业整体该怎么授信管理"。

**写法模板（须落地到具体分位与属性）**：

```
【行业属性卡片】
- 资本密集度：高 / 中 / 低  （如：批发业=重营运资金、低固定资产）
- 毛利属性：厚利 / 薄利 / 微利  （如：批发业中位毛利率 7.00%，天然薄利）
- 周期属性：强周期 / 弱周期 / 防御  （如：大宗批发=强周期，价格与对手方风险高）
- 营运资金属性：自偿性强 / 弱  （决定适宜品种）
- 监管属性：鼓励 / 中性 / 限制 / 禁止  （如：两高一剩、涉房受限）

【行业准入红线 / 优选条件】（锚定 benchmark 分位）
- 杠杆容忍上限：资产负债率 ≤ 行业 P75（xxx%）；>P90（xxx%）视为行业性高杠杆，强审慎
- 盈利门槛：销售毛利率 ≥ 行业 P25（xxx%）；ROE ≥ 行业中位（xxx%）为合格线
- 短债安全线：流动比率 ≥ 行业 P25（xxx%）
- 行业性困境识别：如"样本 n 家中 m 家归母净利为负、k 家 ROE 为负"，提示基准本身已被劣化，门槛应整体趋严

【行业适宜授信品种排序】
- 自偿性贸易融资（应收账款 / 存货质押 / 信用证 / 银承）> 抵质押贷款（审慎）> 信用贷款（不推荐）
- 说明排序理由（如：批发业重周转、轻资产，信用敞口缺乏抓手，故优先自偿性）
```

> 行业分位取值来自 `benchmark_db.py query --industry <行业> --year <年>`；若库内尚无该行业基准，先按"按需更新策略"建库再写（参见 SKILL.md 第 3 步本地基准库策略）。

### 2.2 客户定向准入标准建议（Client-specific）

给定该客户画像、真实主业、数据可得性与缺口，回答"这家具体要满足什么才准入"。

**写法模板**：

```
【客户画像速写】
- 主体性质 / 规模 / 上市与否 / 实控结构 / 真实主业（含行业名实是否一致）
- 数据可得性：完整 / 部分 / 荒漠（决定尺度从严）

【硬门槛（H，须全部满足方可准入）】
1. 经审计近三年财报 + 主要银行账户流水（核验真实营收/负债/隐性担保）
2. 落实足额有效担保：资产抵质押 或 实控人无限连带（写明担保品与覆盖倍数）
3. KYC 锁定：严格按统一社会信用代码（USCC=xxxx）核验主体，排除同名混淆实体
4. 合规证明：无未结被执行 / 失信 / 行政处罚（或已出具合理解释与缓释）

【量化门槛（S，有数据则对标行业分位）】
- 资产负债率 ≤ 行业 P75（xxx%）；毛利率 ≥ 行业 P25（xxx%）；流动比率 ≥ 行业 P25（xxx%）
- 若为数据荒漠型主体，量化门槛转"补数后复核"，不作为即时判定

【否决情形（直接不予准入）】
- 触发第 0 步任一红线 / 一票否决条款
- 行业属监管禁止授信类
- 实控人限高 / 核心资产查封且影响偿债
- KYC 无法锁定或存在严重同名失信混淆且无法排除

【缺口补足路径（介入前必备）】
- 见报告"补充尽调清单（DD List）"，逐条对应 §2.3 转化而来的前提条件
```

### 2.3 缺口 → 条件 映射

客户缺失的每一项关键数据，直接转化为准入前提条件（而非默认可信）：

| 缺失维度 | 转化条件 |
|---|---|
| 近三年财报 | 索取经审计财报，补数前不得核定信用额度 |
| 银行征信 | 调取企业 + 实控人征信，排查隐性负债 |
| 对外担保 / 抵质押 | 出具完整担保余额清单 + 抵质押物权属证明 |
| 实控人资产 / 负债 | 实控人个人资产证明 + 个人无限连带承诺 |
| 子公司明细 | 穿透披露所控制企业，排查互保圈 / 资金池 |
| 营收 / 周转科目（流贷测算） | 补经审计财报与周转数据，新增流贷额度 A 不可得前不得核定信用流贷额度 |
| 刚性负债 / 货币资金（刚性负债分析） | 补企业征信与经审计负债明细，补数前不得核定信用额度 |

## 三、模块二：风控要点建议

从「贷前—贷中—贷后—行业特定—数据治理」五段给出可落地的风控抓手。

### 3.1 贷前（KYC 与准入把关）
- **强化 KYC**：严格按 USCC 锁定主体，穿透至实控人自然人与最终受益所有人（UBO）；排查同名 / 近似名实体（如"X 科技集团"与"X 科技有限公司"不同法律主体）的失信 / 处罚记录，避免误判或误放。
- **关联风险排查**：对其控制的全部子公司、参股企业逐一核查担保圈、资金占用、互保、利益输送；关注"关联风险 N 条"中是否含对外担保、被执行。
- **实控人穿透**：家族式 / 自然人绝对控股主体的实控人个人信用、涉诉、限高为关键变量，须纳入尽调。
- **用途审查**：核实用款背景与交易合同真实性，优先匹配自偿性场景。

### 3.2 贷中（结构设计与放款）
- **担保结构**：坚持"抵质押优先、强担保兜底"；信用敞口须严格限额并配套贷中监测。
- **额度管控**：单户敞口与其净资产 / 真实营收匹配（参考行业规模分位），避免过度授信。
- **用途锁定（自偿性）**：贸易融资须绑定真实交易背景与回款账户，资金闭环（如应收账款回款直接入监管账户）。
- **放款条件**：将 §2.2 硬门槛逐项设为提款先决条件（CP），未满足不放款。

### 3.3 贷后（监测与退出）
- **监测指标**：营收、资产负债率、流动比率、对外担保余额、被执行 / 失信新增、重大舆情、行业景气（PPI / 大宗价格）。
- **预警线**：设定量化阈值（如资产负债率突破行业 P75、新增被执行金额 > 敞口 5%、毛利率跌破行业 P10），触发即上提审查或压降。
- **压力测试**：对强周期行业（大宗、地产）按价格下跌 / 对手方违约情景测算偿债覆盖。
- **退出机制**：三级退出——到期不续（常规）/ 预警压降（触发预警线）/ 紧急加速到期（触发一票否决或重大负面）。

### 3.4 行业特定风控抓手（按行业选填）
- **批发业 / 大宗商品**：存货跌价与价格波动风险（设价格预警与跌价准备要求）、对手方违约风险（额度分散、授信对象白名单）、关联交易与资金池监控、自偿性回款闭环。
- **房地产业**：项目去化与预售资金监管、销售回款封闭管理、土地 / 在建工程抵押、净负债率与现金短债比约束、政策端限购限贷传导。
- **软件 / 信息技术**：应收账款账龄与集中度（大客户依赖）、项目制收入确认真实性、研发资本化合理性、轻资产缺乏抵押物（优先应收账款质押 / 实控人连带）。
- **制造业**：产能利用率、存货周转、设备抵押、订单真实性、上下游集中度。

### 3.5 数据治理（持续补数与复核）
- **持续补数**：非上市 / 数据荒漠主体建立定期补数机制（年报后更新财务、季度滚动查被执行 / 舆情）。
- **行业名实复核**：持续关注"国标行业 vs 实际主业"是否背离（如威新式"软件"实为"地产"），一旦背离须改用实际主业基准复核。
- **滚动负面监测**：被执行、失信、行政处罚、重大舆情、评级下调的滚动排查，纳入贷后预警。
- **基准库维护**：新行业按"按需更新策略"建库；既有行业每年年报后 `compute` 重算，并出更新报告。

## 四、落到报告的章节结构（示例）

**完整初审报告（模式 B）**：
```

六、刚性负债情况分析          ← 同上
七、管理层与股权分析
八、外部风险分析
九、信息来源与缺口
十、风险评级
十一、行业准入标准建议        ← 本框架 §2.1
十二、客户定向准入标准建议    ← 本框架 §2.2 / §2.3（含流贷不超测算额度 A、刚性负债红旗对应强担保前提）

（方法论复盘并入自迭代章节）
```

## 五、质量校验清单（Agent 自检）

- [ ] 行业尺度是否引用了 `industry_benchmark.db` 的具体分位（而非泛泛而谈）？
- [ ] 客户尺度是否区分了硬门槛（H）与软约束（S）？
- [ ] 每条标准是否可执行、可核验、带来源 / 依据？
- [ ] 数据缺失维度是否都转化为了准入前提条件（缺口即条件）？
- [ ] 非上市 / 数据荒漠主体是否明示"基准偏乐观、尺度从严"？
- [ ] 风控要点是否覆盖了贷前 / 贷中 / 贷后，并含行业特定抓手？
- [ ] 行业名实背离是否已在客户尺度中提示改用实际主业基准？

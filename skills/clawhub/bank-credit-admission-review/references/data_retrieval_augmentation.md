# 多源信息检索 · 数据分析 · 结果审核（增强层）

> 本文件借鉴「财数数」金融数据检索专家（finance-data-retrieval / Neodata）的能力，为授信准入审查补齐三类原本偏弱的能力：
> **① 信息检索**——除财汇MCP 结构化数据外，可补充实时行情、资金流向、股权质押、新闻公告、机构一致预期、宏观利率等市场侧数据；
> **② 数据分析**——引入多期趋势、估值与资金流信号、质押预警、一致预期/评级领先指标，深化四维判断；
> **③ 结果审核判断**——建立"同一指标多源交叉核验 + 分歧预警 + 来源可靠性逐条标注 + 不确定性声明"的审核协议。
>
> 本层为**增强补充**，不替代财汇MCP 主数据源（财报、担保、司法、评级、工商等结构化数据仍以 MCP 为权威）。

---

## A. 多源检索架构（主次与降级）

| 角色 | 数据源 | 适用内容 | 标注标签 |
|---|---|---|---|
| **主源（权威）** | 财汇MCP / 企业预警通 | 财报三表、公告、担保/抵押、司法诉讼、评级、工商、监管处罚 | `〔MCP·预警通〕` |
| **辅源（市场侧）** | Neodata 金融数据（`finance-data-retrieval` 技能，curl 调 `https://www.codebuddy.cn/v2/tool/financedata`） | 实时/历史行情、PE/PB/市值、资金流向、北向资金、股权质押、十大股东/增减持、新闻快讯、公告原文、券商一致预期、LPR/宏观 | `〔Neodata·财数数〕` |
| **兜底（外部）** | WebSearch | 港股/美股覆盖、最新舆情、行业趋势、Neodata 不可达时的替代 | `〔外网·WebSearch〕` |
| **客户提供** | 用户上传资料 | 审计报告、征信、评级书、合同 | `〔客户提供·财报/征信〕` |

**降级路径**：主源缺失 → 先试 Neodata 辅源 → 仍缺失/不可达 → WebSearch 兜底。任一环节取到数据，须在报告中标注实际来源标签；Neodata 返回空或接口报错时，**不得编造**，如实标注缺口并改 WebSearch 或标注 `〔缺口〕`。

## B. 信息检索：源选择对照表

> Neodata 调用前**必须先读对应接口文档**（参考 `finance-data-retrieval` 技能的 `references/` 目录与 `MAP.md`），按文档填参，禁止凭猜测填参。核心接口与授信审查的映射：

| 审查想看什么 | 推荐接口（api_name） | 关键参数要点 |
|---|---|---|
| 股价、市值、PE/PB、换手率 | `daily_basic` | `ts_code`（如 `000001.SZ`）、`trade_date`（YYYYMMDD） |
| 历史/近期行情 | `daily` / `weekly` / `monthly` | 同上；可拉多期算趋势 |
| 个股资金流向（主力净流入） | `moneyflow` | `ts_code` + `trade_date` |
| 北向/南向资金 | `moneyflow_hsgt` | 看沪深港通方向 |
| 股权质押（质押比例预警） | `pledge_stat` | `ts_code`；重点关注质押率、预警线 |
| 十大股东 / 流通股东 | `top10_holders` / `top10_floatholders` | 看国资/机构持股比例变化 |
| 股东增减持 | `stk_holdertrade` | 大股东持续减持是负面信号 |
| 新闻快讯 / 长篇新闻 | `news` / `major_news` | 关键词检索，看负面舆情与监管处罚 |
| 公告原文 | `anns_d` | 业绩预告、债务违约、重大诉讼等 |
| 券商盈利预测（一致预期） | `report_rc` | 作为评级/预期领先指标 |
| 审计意见 | `fina_audit` | 标准无保留/保留/无法表示意见 |
| 财务指标（交叉核验） | `fina_indicator` | ROE、毛利率等，与 MCP 口径交叉比对 |
| LPR / 宏观利率 | `shibor_lpr` / `cn_cpi` / `cn_ppi` | 授信定价与行业景气背景 |
| 港股客户 | `hk_basic` / `hk_daily` | 港股代码体系不同，MCP 常返回空，须用此处补 |
| 美股客户 | `us_income` / `us_balancesheet` 等 | 同上 |

**代码格式**：A股 `000001.SZ` / `600000.SH` / `830XXX.BJ`；日期 `YYYYMMDD`。港股、美股使用各自代码体系（详见技能文档）。

**调用模板**：
```bash
curl -s -X POST https://www.codebuddy.cn/v2/tool/financedata \
  -H "Content-Type: application/json" \
  -d '{"api_name":"daily_basic","params":{"ts_code":"000001.SZ","trade_date":"20260810"},"fields":""}'
```
返回 `{"code":0,"data":{"fields":[...],"items":[[...]]}}`；`code!=0` 时按 `msg` 报错并降级。

## C. 数据分析增强（深化四维判断）

在 `references/analysis_framework.md` 逐维下钻基础上，可叠加以下市场侧分析：

1. **多期趋势比对**：用 `daily_basic` / `fina_indicator` 拉 3–5 期数据，看 PE/PB、ROE、毛利率的趋势方向（恶化/企稳/改善），避免只看单点。
2. **估值与资金流信号**：持续资金净流出、估值破净（PB<1 且下行）、北向减持，构成**市场情绪面负面信号**，与基本面相互印证。
3. **股权质押预警**：`pledge_stat` 质押率偏高（如 >50%）或触及预警线，是**流动性与控股权风险**的领先指标，尤其中小市值主体。
4. **一致预期 / 评级领先指标**：`report_rc` 中机构密集下调盈利预测或评级，往往是基本面恶化的**前置信号**，应在报告中单列"市场预期"小节。
5. **审计意见**：`fina_audit` 非标准无保留意见（保留/无法表示/否定）直接触发高风险标注，与第 0 步红线并列审视。
6. **宏观与行业背景**：`shibor_lpr` / `cn_cpi` / `cn_ppi` 用于把个体企业放在利率与景气周期中判断，避免脱离环境定级。

> 上述分析产出的每个数字、每条信号，均须带 §A 的来源标签；市场侧信号属"情绪/预期"，等级权重低于审计与财报硬数据，不得单独作为否决依据。

## D. 结果审核判断（交叉核验协议）

**这是"结果审核判断"能力的核心**：在给出任何结论前，对关键数字执行核验，确保结论可追溯、可辩护。

1. **多源交叉核验**：对核心指标（营收、净利润、资产负债率、净资产、审计意见等），尽量取得**至少两个独立来源**（如 MCP 财报 + Neodata `fina_indicator` + 公告原文 + WebSearch），数值一致方可采信为主依据。
2. **分歧容忍阈值**：
   - 绝对值口径一致、相对差异 **≤ 5%**：视为口径/四舍五入差异，取较保守值并备注；
   - 差异 **5%–20%**：标注"数据分歧（中等）"，列明两源数值，结论取保守口径；
   - 差异 **> 20%** 或一方缺失：标注"数据分歧（重大）"，**不得直接采信任一**，须要求用户补证或标注 `〔缺口〕` 后审慎定级。
3. **来源可靠性逐条标注**：每条判断后挂 `〔MCP·预警通〕` / `〔Neodata·财数数〕` / `〔外网·WebSearch〕` / `〔缺口〕`，低可靠性来源不得作主依据（详见 `references/source_reliability.md`）。
4. **不确定性声明**：对推断、外推、模型估计的结论，必须显式写"假设 + 若证伪则结论恶化"，禁止以确定性语气陈述不确定内容。
5. **失败与降级**：Neodata 不可达/返回空 → 转 WebSearch 并标注；WebSearch 亦无 → 标 `〔缺口〕` 并给出补证清单。绝不编造。
6. **审核留痕**：核验过程（用了哪些源、分歧如何处置）记入报告「数据核验」小节与方法论复盘，便于回溯与迭代。

## E. 何时加载 `finance-data-retrieval` 技能

当用户需要以下任一类信息，且财汇MCP 未覆盖或需交叉印证时，先 `Skill finance-data-retrieval` 加载该技能取其接口文档与调用规范，再按 §B 取数：
- 实时/历史股价、市值、PE/PB；
- 资金流向、北向资金；
- 股权质押、十大股东、增减持；
- 新闻、公告原文、一致预期、审计意见；
- 港股/美股客户数据（MCP 常返回空）；
- LPR / CPI / PPI 等宏观背景。

> 注意：`finance-data-retrieval` 依赖外部 `codebuddy.cn/financedata` 端点，调用前确认可达；不可达时严格按 §A 降级到 WebSearch，不得静默失败。

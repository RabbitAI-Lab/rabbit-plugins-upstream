# 行业基准库（同行业上市公司平均水平 —— 尺度判断）

> 用途：为授信准入审查提供"同行业上市公司平均水平"作为尺度，回答"这家企业资产负债率 78% 到底算不算高""归母净利润 -8 亿在同业里处于什么位置"等问题，区分**行业性困境**与**个体性困境**。
>
> 本文件与 `scripts/benchmark_db.py` 配套。数据来源为财汇MCP（企业预警通）同行业上市公司年报，入库后经分位数计算形成可快捷查询的本地基准。

---

## 1. 架构与数据流（重要）

**财汇MCP 只能由 Agent 调用，脚本不联网、不直连 MCP。** 标准流程为：

```
Agent 调财汇MCP（get_company_financial_metrics）
   ↓ 保存原始返回 JSON（headInfo + data 二维数组）
benchmark_db.py ingest   ← 脚本解析 MCP 原始结构，无需手工转换字段
   ↓
benchmark_db.py compute  ← 算行业分位数（P10/P25/P50/P75/P90、均值、极值、为负家数）
   ↓
benchmark_db.py query / compare  ← 快捷查询 / 单企业比对
```

- 数据库：`data/industry_benchmark.db`（SQLite，长表存储）。
- 无第三方依赖，仅 Python 3.8+ 标准库（sqlite3/json/re/os/sys/datetime）。
- Windows 执行须用 Windows 版 Python，路径传 Windows 绝对路径（如 `C:/Users/.../x.json`）。

## 2. 子命令速查

| 命令 | 作用 |
|---|---|
| `init` | 建库（幂等，含后续新增列） |
| `ingest -i <json> [--industry 房地产业] [--level l2]` | 导入 MCP 原始返回；传 `--industry` 时**自动补建公司档案**，一步到位 |
| `compute --level l2 [--industry X] [--year 2025] [--listed-only]` | 算行业分位数基准（新增/补录数据后必须重跑） |
| `query --industry X --year 2025 [--indicator 资产负债率] [-f json]` | 查基准表 |
| `compare -i 企业指标.json` | 单家企业 vs 行业基准，输出分位定位 + 比对结论 |
| `status` | 库存概览（行业覆盖、公司数、指标种类、导入记录） |
| `report [--last 5]` | **更新报告**：列明已覆盖行业、基准速览、最近导入记录（用户要求的"更新/修改了什么"） |

`compare` 的输入 JSON 结构：
```json
{
  "company": "企业全称",
  "uscc": "统一社会信用代码（可选，用于 KYC 与同名排除）",
  "industry": "房地产业",
  "year": 2025,
  "level": "l2",
  "is_listed": false,
  "metrics": {
    "资产负债率": 76.89,
    "归母净利润": -8855647.05,
    "流动比率": 123.39,
    "净资产收益率": -55.42,
    "销售毛利率": 9.46
  },
  "profile": {
    "registered_capital_wan": 1000,
    "employee_count": null,
    "scale_label": "小型/小微企业",
    "controller": "郑钰纯（70%）",
    "actual_business": "经核查的实际主业（如"大宗商品批发贸易"）",
    "industry_match": true
  }
}
```
> `metrics` 中的数值单位须与库中一致（如归母净利润单位为"万元"，金额按万元原值传入，脚本自动折算展示）。

**零数据 / 非上市主体的自动降级（关键）**：当 `metrics` 为空（非上市公司常无公开年报），`compare` 不再报错或留白，而是自动转入**定性规模定位**模式：
- **定性规模定位（数据荒漠型主体）**：以行业基准中位数（如上市公司中位营收）为锚，用 `profile.registered_capital_wan` 做数量级对比，给出"微型主体、与上市公司基准不具直接可比性"的方向性结论；
- **行业名实校验**：若 `profile.industry_match=false`（国标行业与实际主业背离，如"威新软件"实为"金地地产平台"），输出 ⚠ 强提示并建议改以实际主业对应行业基准复核；若 `actual_business` 与国标行业一致则明示可比性可接受；
- **能力边界声明（非上市/数据稀缺）**：明示公开数据极度有限、置信度 LOW、上市公司基准对非上市主体系统性偏乐观、结论不替代现场尽调；
- **「缺口即风险」默认授信建议**：缺数据即建议暂不予信用授信，介入须满足审计财报+强担保+凭 USCC 严格 KYC+现场尽调。

> 该分支把"非上市/数据荒漠"这类高频场景的处理从"每次人工在报告里临时写"固化为脚本自动产出，保证每次调查输出结构一致、关键提示不遗漏。

**同业对比强制原则（用户指令，2026-08-19 确认）**：审查**任何客户**——无论是否上市公司、无论数据多寡——只要有条件取得同业可比数据，**必须做同业对比**，判断关键指标是否低于同业水平：
- 上市/发债企业：`compare` 分位比对（P10–P90 + 百分位排名）；
- 非上市但有数据：以其可取得指标（营收/净利/ALR/周转等）对照行业基准分位，输出"高于/接近/低于同业"定位；
- **零数据非上市主体**：按上述零数据降级做**定性规模定位**（注册资本 vs 行业基准中位营收的数量级对比），仍须给出"与同业相比处于何种水平"的定性结论——**不得省略同业视角**；
- 同业对比结论须落入报告（§八 行业基准比对 / 准入标准建议），并标注基准口径（行业/样本数/年度）。
- 基准未覆盖该行业时：先按 §8 按需采集建基准（n≥15 充足），再比对；实在无法建库的，用外网同业数据或定性参照，并在报告中声明对比基础。

**门当户对：规模匹配纪律（用户指令追加，2026-08-19）** —— 同业对比必须先看规模，轻量级 vs 重量级直接比优劣不合理：
- **分层标准**（按最近年报营收，可用总资产/注册资本复核）：大型 ≥100 亿 ｜ 中型 20–100 亿 ｜ 中小型 5–20 亿 ｜ 小型微 <5 亿（阈值可按行内口径调整）；
- **脚本已内置**：`compare` 读入 `metrics["营业总收入"]` 自动判定客户规模层、筛出**同规模层同业样本**，在指标表输出「同层分位」列，并输出「门当户对说明」「规模校正提示」；
- **同层优先**：同层样本 ≥5 家时计算同层分位（<5 家自动跳过并提示代表性不足）；同层与全行业判定方向不一致时，输出「规模校正提示」，建议以同层口径为主定级；
- **量级悬殊降级**：客户营收 < 基准中位营收 1/10（或 >10 倍）时，自动输出降级警告——定量分位对比**降级**为"规模校正解读/定性定位"，分位结论仅供方向参考，不得直接定级；
- **规模是维度**：规模层差异计入"经营情况"维度评分——同指标下规模越小抗风险缓冲越薄，不因"与同层持平"豁免规模风险；
- **报告呈现**：头部信息表带"客户规模层 + 同层同业样本"两行，指标表带"同层分位"列，先看规模匹配再看分位；
- **JSON 输出**：`scale` 对象（customer_scale / customer_revenue_wan / same_scale_peers / same_scale_range / scale_warnings）+ 每项 `same_scale_rank`。

## 3. 指标方向与分位解读

| 方向 | 含义 | 代表指标 |
|---|---|---|
| `lower_better` | 数值越低越稳健 | 资产负债率、有息负债率、净负债率、产权比率 |
| `higher_better` | 数值越高越稳健 | 流动比率、销售毛利率、净资产收益率、归母净利润、营业总收入、经营现金流 |
| `neutral` | 仅规模参考，不判优劣 | 总资产、净资产、所有者权益合计 |

**分位解读**：P25/P50/P75 为行业中枢；P10/P90 为尾部。百分位排名（percentile_rank）定位单企业在样本中的位置：
- `lower_better`：分位越高越差（≥90 显著劣于同业 / ≥75 劣于同业 / 50–75 略高于中位 / 25–50 优于中位 / <25 显著优于）。
- `higher_better`：分位越低越差（≤10 显著劣于同业 / ≤25 劣于同业 / 25–50 略低于中位 / 50–75 优于中位 / >75 显著优于）。

---

## 4. 比率型失真剔除（关键兜底）

**问题**：净资产近零时，净资产收益率（ROE）/ 总资产报酬率（ROA）会数学爆炸（如金科 +705%、富力 -445%、首开 -105.77%），并非真实经营水平，会污染行业中枢（尤其均值）。

**处理**：在 `compute` 中，对以下指标超出阈值的极端值从分位数分布**剔除**，并在基准表「极值剔除」列披露数量：
- 净资产收益率、总资产报酬率：超出 **±100%** 剔除
- 销售净利率：超出 **±200%** 剔除

**被比对企业自身**若触发该阈值，`compare` 不输出误导性排名，而是标记 **"数据失真(分母近零)"** 并转人工复核（仍计入高风险项）。其困境已由资产负债率 / 净利润等维度体现，不会因剔除而漏判。

---

## 5. 行业景气提示

当某 `higher_better` 指标的"为负家数"超过样本 40%（如房地产业 2025 年归母净利润 26/39 家为负），`compare` 自动输出：

> **行业景气提示**：本行业 X 项指标中，N/M 家样本为负值，行业整体处于下行区间。此时"与同业持平"不等于"经营稳健"，须结合行业周期判断，避免以劣质基准掩盖个体风险。

---

## 6. 方法论局限（须在报告中随结论一并披露）

1. **样本为上市公司，非授信客户总体。** 上市公司在融资渠道、治理规范性、信息披露质量上系统性优于非上市企业，以其为尺度衡量非上市客户会**低估**相对风险，宜作偏乐观参照。
2. **行业分类采用国标口径，与实际经营范围可能存在偏差。** 多元化经营主体按主营归类，跨业务比对须人工复核可比性。
3. **比率型指标已做失真剔除**（§4）；其余维度的极端亏损或一次性损益仍会拉动分布，已在基准表列示样本数、极值与为负家数供交叉判断。
4. 本比对为辅助参考，**不替代正式审批决策**。

## 7. 扩展计划（逐步建立）

- 当前已覆盖：房地产业（2025 年报，40 家，5 项核心指标）。
- 扩充样本：房地产业可扩至全量 359 家上市公司；并扩展到建筑、制造、批发零售等其他授信高频行业。
- 指标扩充：补充有息负债率、净负债率、速动比率、利息保障倍数、经营现金流等，形成更完整的风险剖面。
- 多年度：积累 2023/2024/2025 多期，支持趋势比对与行业景气跟踪。
- 行业层级：除国标大类（l2）外，可下钻中类（l3）/ 小类（l4）提升可比性。

> 每次 Agent 经 MCP 新拉一批数据后，执行 `ingest` → `compute` 即可增量更新，无需重建库。

## 8. 按需更新策略 + 更新报告（用户要求）

**策略（节省磁盘 / 时间）**：默认**只在用户咨询某家企业时，才搜集该企业所在行业的基准数据**；其余行业待用户主动要求再搜集。数据库为 SQLite 文本，单行业约数十 KB、全市场亦仅数 MB，**磁盘占用可忽略**，故在磁盘无碍前提下也可在触发通用分析时主动补建，但默认仍遵循"用户问到才建"，避免冗余取数。

**触发 → 检查 → 采集 → 报告** 标准动作：

1. **触发**：用户每咨询一家企业 → 先定位其行业（国标分类，取最细可用层级；比对用 l2 大类为主、l4 小类为辅）。
2. **检查**：`query --industry <行业> --year <最近完整年报年>` 是否已有基准；若不存在或样本不足（`n < 15`），进入采集。
3. **采集**：`filter_companies_by_basic_info`（行业=该行业、是否上市=是）取同业清单 → `get_company_financial_metrics` 批量拉核心指标 → 保存原始 JSON → `ingest --industry <行业>` → `compute --level l2 --year <年>`。
4. **更新报告（必做）**：每次 `ingest`/`compute` 后运行 `report`，将输出作为"数据库更新报告"呈现给用户，说明：本次更新/修改了哪个行业、哪些指标、样本数、关键分位数、是否剔除异常值（极值剔除列）、数据来源与日期。

**报告命令**：
```bash
python scripts/benchmark_db.py report --last 5
```

**报告样例（房地产业 2025 年报，本会话建成）**：
- 更新行业：房地产业（国标大类）
- 样本：40 家上市公司，5 项核心指标（资产负债率、归母净利润、销售毛利率、净资产收益率、流动比率）
- 关键分位：资产负债率中位 75.52%、归母净利润中位 -26.69 亿（39 家中 26 家为负）、ROE 中位 -5.04%
- 异常剔除：ROE 剔除 3 个分母近零失真值（富力 -445%、首开 -105.77%、金科 +705.54%）
- 来源：财汇MCP（企业预警通）同行业上市公司年报；入库日期见 `report` 输出
- 磁盘：SQLite 文本库，体量约数十 KB，无清理压力

# data 目录说明

本目录存放 `金融理论大师` skill 的机读理论索引。

## 文件

| 文件 | 内容 | 记录数 |
|------|------|--------|
| `theory_index.csv` | 理论索引主表 | 66 |
| `financial_history_timeline.csv` | 世界金融史时间线 | 124 |
| `policy_toolkit.csv` | 四类行情下的政策工具箱 | 36 |
| `investor_cases.csv` | 投资案例与判断逻辑 | 22 |

---

## 一、定位与权威顺序

`theory_index.csv` 是从 `../references/` 九份知识文件中**提炼的摘要索引**，用途有两个：

1. 供 `scripts/theory_lookup.py` 做检索与快速列表
2. 提供一个结构化的横向对比底表

**发生冲突时，以 `references/` 的正文为准。** 索引为了检索效率做了压缩，正文才有完整的机制说明、争议记录与文献溯源。

## 二、字段规范

共 16 个字段。多值字段用半角竖线 `|` 分隔。

| # | 字段 | 必填 | 类型 / 枚举 | 说明 |
|---|------|------|------------|------|
| 1 | `theory_id` | 是 | slug | 唯一标识。小写字母、数字、下划线，如 `capm`、`pecking_order` |
| 2 | `name_cn` | 是 | 文本 | 中文名称 |
| 3 | `abbrev` | 是 | 文本 | 常用缩写。无通用缩写时填 `—` |
| 4 | `proposer` | 是 | 文本 | 提出者。集体发展或传统框架填「传统框架」「后继发展」等 |
| 5 | `year` | 是 | 四位年份或 `—` | 原始文献年份。无单一原始文献时填 `—` |
| 6 | `module` | 是 | 枚举，见 2.1 | 所属板块 |
| 7 | `core_claim` | 是 | 文本 | 核心命题，一句话 |
| 8 | `core_assumption` | 是 | 文本 | 成立所需的关键假设，分号分隔 |
| 9 | `applicable_scene` | 是 | 文本 | 适用场景 |
| 10 | `main_limitation` | 是 | 文本 | 主要局限 |
| 11 | `hypothesis_strength` | 是 | 枚举，见 2.2 | 假设强度 |
| 12 | `evidence_status` | 是 | 枚举，见 2.3 | 实证地位 |
| 13 | `evidence_note` | 否 | 文本 | 实证地位的补充说明。可为空 |
| 14 | `complementary` | 是 | 多值 | 互补理论。无则填 `—` |
| 15 | `conflicting` | 是 | 多值 | 冲突理论。无则填 `—` |
| 16 | `key_reference` | 是 | 文本 | 关键文献。年份与期刊名，卷期页码未逐条核录 |

### 「—」的含义

**`—` 是显式取值，表示「不适用 / 无」，不是缺失。** 校验器不会把它判为错误。两者区别：

- `abbrev = —` → 该理论没有通用缩写
- `abbrev = `（空） → 数据缺失，校验失败

### 2.1 module 枚举（7 项）

`资产定价`、`投资组合`、`有效市场`、`行为金融`、`公司金融`、`货币宏观`、`风险管理`

### 2.2 hypothesis_strength 枚举（5 项）

| 取值 | 含义 |
|------|------|
| `框架级` | 是组织方式或恒等式，非可证伪命题（如 SDF、现值框架） |
| `极强` | 假设在现实中基本不成立，结论极锐利（如 MM 无税定理） |
| `强` | 有闭式解、可计算，但假设与现实有实质距离（如 CAPM、BS） |
| `中` | 结构灵活、参数增多（如 APT、多因子、泰勒规则、VaR） |
| `低` | 解释力强、预测力弱、可证伪性低（如行为金融、明斯基） |

### 2.3 evidence_status 枚举（3 项）

| 取值 | 含义 |
|------|------|
| `稳健` | 跨市场、跨时期、跨方法反复复现，或逻辑本身不可动摇 |
| `有争议` | 有大量支持证据，同时有实质性反驳 |
| `已削弱` | 曾被广泛接受，后续研究发现显著问题 |

**注意：compound 取值不允许。** 早期版本曾出现「稳健（数学结论）」这类写法，已全部拆分为 `evidence_status` + `evidence_note` 两个字段。校验器会拒绝非枚举值。

## 四、边界覆盖

索引刻意收录了若干边界样本，用于校验框架的完整性和校验器的有效性：

| 场景 | 样本 |
|------|------|
| 假设强度极强（容易被证伪） | `mm` |
| 假设强度低（几乎不可证伪） | `minsky`、`prospect_theory` |
| 框架级（非可证伪命题） | `pv_dcf`、`sdf`、`npv` |
| 实证地位「已削弱」 | `var`、`islm`、`interest_parity` |
| 无通用缩写 | `term_structure`、`quantity_theory` 等填 `—` |
| 无单一原始文献 | `tradeoff`、`real_options`、`evt` 等年份填 `—` |
| 无互补或冲突理论 | `mmt` 的 complementary 填 `—` |
| 概念性框架无假设 | `model_risk` 的 core_assumption 填 `—` |
| 表面冲突实际共存 | `momentum` 与 `longterm_reversal` 互为 conflicting |

## 五、金融史时间线字段规范（`financial_history_timeline.csv`）

8 个字段，全部必填。**只有 `related_theory` 允许填 `—`**（表示该事件没有直接对应的理论）。

| # | 字段 | 类型 / 枚举 | 说明 |
|---|------|------------|------|
| 1 | `sort_key` | 整数 | 排序键。**公元前取负值**（前 1754 年记为 `-1754`），公元后取正值。用于机器排序与覆盖度检查 |
| 2 | `year` | 文本 | 人类可读的年份表述，如 `约前1754`、`1340年代`、`2008`。允许模糊表述 |
| 3 | `event` | 文本 | 事件描述，一句话 |
| 4 | `stage` | 枚举，见 5.1 | 所属分期 |
| 5 | `category` | 枚举，见 5.2 | 所属类别 |
| 6 | `region` | 文本 | 地区，如 `美索不达米亚`、`全球`、`英国` |
| 7 | `significance` | 文本 | 意义与判断，说明为什么这个事件值得记录 |
| 8 | `related_theory` | 文本 | 关联的理论名称，可用 `｜` 分隔多个。无关联时填 `—` |

### 5.1 stage 枚举（6 项）

`起源`、`古典与中世纪`、`商业革命`、`金融革命`、`金本位与央行时代`、`美元本位与全球化`

### 5.2 category 枚举（7 项）

| 取值 | 含义 |
|------|------|
| `货币` | 货币形态、币值、纸币、数字货币 |
| `信用与银行` | 借贷、银行、银行家族、信用工具 |
| `市场与机构` | 交易所、公司、证券公司、保险机构 |
| `危机` | 金融危机、泡沫、违约、挤兑 |
| `监管与制度` | 立法、监管机构、制度安排、债务免除 |
| `国际体系` | 汇率制度、国际货币体系、贸易协定、政策协调 |
| `技术与工具` | 记账、票据、支付、衍生品、金融科技 |

### 5.3 排序与重复规则

- CSV 按 `sort_key` **非递减**排列
- **同一年允许多个事件**（如 1933 年既有美国退出金本位，也有费雪提出债务通缩理论），因此 `sort_key` 允许重复
- 公元前事件必须排在前面，校验器会检查 `sort_key <= -2000` 与 `>= 2024` 两个边界，确保覆盖到古代与当代

### 5.4 字段规范里最容易踩的坑

| 坑 | 后果 | 正确做法 |
|----|------|---------|
| `sort_key` 用年份字符串 | 排序错乱，「前 500」会排在「1600」之后 | 用整数，公元前取负 |
| 把同年多事件当成重复数据删掉 | 丢失信息 | 允许重复，只要求非递减 |
| `year` 写成精确年份 | 古代与中世纪的绝对年代普遍有争议 | 允许「约」「年代」等模糊表述 |
| `related_theory` 留空 | 校验失败 | 无关联时显式填 `—` |
| `significance` 只写「很重要」 | 字段失去价值 | 写清为什么重要、改变了什么 |

## 六、政策工具箱字段规范（`policy_toolkit.csv`）

9 个字段，全部必填。

| # | 字段 | 类型 / 枚举 | 说明 |
|---|------|------------|------|
| 1 | `tool_id` | slug | 唯一标识，小写字母、数字、下划线 |
| 2 | `market_stage` | 枚举，见 6.1 | 适用行情阶段 |
| 3 | `level` | 枚举，见 6.2 | 政策层级 |
| 4 | `tool_name` | 文本 | 工具名称 |
| 5 | `target` | 文本 | 政策目标 |
| 6 | `mechanism` | 文本 | **作用机制**。必须写清传导链条，不少于 15 字符 |
| 7 | `lag` | 文本 | 时滞 |
| 8 | `constraint` | 文本 | 主要约束与失效条件，不少于 10 字符 |
| 9 | `case_example` | 文本 | 历史案例 |

### 6.1 market_stage 枚举（5 项）

`通用`、`牛市`、`熊市`、`震荡市`、`危机行情`

**注意区分：** `通用` 只用于政策工具箱（表示该工具在所有行情下都可能使用）。**投资案例不使用 `通用`**，只覆盖四类真实行情。

### 6.2 level 枚举（3 项）

`货币政策`、`财政政策`、`微观与市场政策`

**写作纪律：** `mechanism` 字段是本数据集的灵魂。写「利好股市」不算机制，必须写清通过哪条链条、影响哪个变量。校验器与测试都会检查其长度下限。

## 七、投资案例字段规范（`investor_cases.csv`）

11 个字段，全部必填。

| # | 字段 | 类型 / 枚举 | 说明 |
|---|------|------------|------|
| 1 | `case_id` | slug | 唯一标识 |
| 2 | `period` | 文本 | 时期 |
| 3 | `region` | 文本 | 地区。中国香港、中国台湾、中国澳门必须用规范名称 |
| 4 | `market_stage` | 枚举，见 6.1 | **必须为单一枚举值** |
| 5 | `policy_env` | 文本 | 政策环境。行情转换信息（如「牛市转危机」）写在这里，不写进 market_stage |
| 6 | `signal` | 文本 | **识别信号**。必须是可观察、可验证的对象 |
| 7 | `reasoning` | 文本 | **推理链条**。从信号到结论的完整逻辑 |
| 8 | `decision` | 文本 | **决策要点**。具体动作与工具，不写「保持警惕」这类空话 |
| 9 | `outcome` | 文本 | 结果 |
| 10 | `pattern` | 文本 | 归到七种可复用推理模式之一 |
| 11 | `survivorship` | 文本 | **幸存者偏差或失败风险说明**。不少于 8 字符 |

### 7.1 pattern 允许的七种取值

`政策不可持续模式`、`资产负债表错配模式`、`融资结构模式`、`极端估值模式`、`央行承诺模式`、`制度变革模式`、`催化剂与时点模式`

### 7.2 signal 字段的禁用表述

不得出现主观感受类表述：`我觉得`、`感觉`、`直觉`、`不祥`、`预感`。测试会检查。

**理由：** 事后叙事最容易把「我早就觉得不对劲」包装成识别信号。真正的信号必须是当时就能指出来的具体对象（某份文件的条款、某个可查询的比率、某次会议的措辞）。

### 7.3 market_stage 必须单一

本数据集**不允许复合标签**（如「牛市转危机」）。案例跨越多个行情阶段时，`market_stage` 填**决策发生时的行情**，转换信息写入 `policy_env`。

这条规则来自一次实际报错：初版有 6 个案例使用了复合标签，被校验器拦下。**复合标签会让「按行情类型统计」失效，也会让后续的自动化处理无从下手。**

### 7.4 幸存者偏差是强制字段

每个案例都必须说明：做同样判断但失败的人有多少、失败的类型是什么。

**理由：** 每一个成功的案例背后都有大量做同样判断但没成功的人。不标注幸存者偏差的案例集，会把运气包装成能力。

## 八、重新生成与校验

数据由 `scripts/gen_data.py` 确定性生成。同一进程内重复渲染逐字节一致，磁盘内容可用 `--check` 比对。

```bash
cd finance-theory-master

# 重新生成（覆盖 data/theory_index.csv）
python scripts/gen_data.py

# 只比对，不写入；不一致则以退出码 1 失败
python scripts/gen_data.py --check

# 校验自洽性：字段、枚举、唯一性、年份格式、引用关系、覆盖度、知识文件齐备
python scripts/validate_data.py

# 单元测试
python -m pytest tests/ -q
```

编码为 **UTF-8 with BOM（utf-8-sig）**，便于 Excel 直接双击打开不乱码。Python 读取时需用 `encoding="utf-8-sig"`。

## 九、维护须知

修改索引时必须走这条路，不要直接编辑 CSV：

1. 改 `scripts/gen_data.py` 里的 `RECORDS` 数据表
2. 运行 `python scripts/gen_data.py` 重新生成
3. 运行 `python scripts/validate_data.py` 确认通过
4. 运行 `python -m pytest tests/ -q` 确认无回归
5. **同步更新 `references/` 下对应的知识正文**，避免索引与正文口径不一致

**枚举与字段定义的唯一来源是 `scripts/schema.py`。** 生成器、校验器、查询工具一律
`import schema` 引用，不再各自声明一份。新增板块或枚举值时的顺序：

1. 改 `scripts/schema.py` 的 `ENUM_*` 常量
2. 改 `scripts/gen_data.py` 里对应的 `RECORDS` 数据
3. 更新本文件的枚举清单（保持文档与代码一致）
4. 跑 `gen_data.py`、`validate_data.py`、`pytest`

早先的做法是「gen_data.py 改一处、validate_data.py 再改一处，两处必须一致」。
那靠的是纪律，漏一处就会让校验器误报。现在改成单一来源后，这类失配在结构上
不可能发生，`tests/test_theory_master.py::TestSingleSourceOfTruth` 会盯着这一点。

**直接编辑 CSV 的后果：** `gen_data.py --check` 会失败，测试里的 `test_render_matches_disk` 会断言失败。这是刻意设计的防篡改机制。

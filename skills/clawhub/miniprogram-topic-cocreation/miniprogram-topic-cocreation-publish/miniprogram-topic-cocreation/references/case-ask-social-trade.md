# 案例范本 B：「会问社媒外贸版」小程序 — 产品技术规格（v2.0 · 蒸馏平台版）

> **战略定位**：AI 能力蒸馏平台。一句话需求 → 一套 AI 能力。
> **MVP 边界**：第一版只做「需求蒸馏 + Prompt 增强」这一层，但所有数据结构按未来能生成 Workflow / Agent / Skill / Knowledge 来设计。
> 演进：AI需求构建器 → "AI"昵称被监管拒 → 转外贸获客 → 个人主体类目卡点 → 定位升为"AI能力蒸馏平台"。

## 蒸馏管线（产品全景，v1 只落地第一层）

```
用户一句话 → AI理解真实需求 → 需求蒸馏
  → ① Prompt（让AI理解）        ← v1 实现并展示
  → ② Workflow（让AI知步骤）     ← 数据结构预留
  → ③ Agent（让AI自动执行）      ← 数据结构预留
  → ④ Skill（让微信/企业AI调用） ← 数据结构预留
  → ⑤ Knowledge（沉淀行业经验）  ← 数据结构预留
```

**举例**：输入"我是做滚珠花键的，想开发海外客户"
- 第一层 增强Prompt
- 第二层 工作流：客户画像分析 → 客户名单获取 → 开发信生成 → 跟进流程
- 第三层 Agent：外贸开发Agent

## 一、产品定位与核心功能

**v1 核心功能（必做）**
1. 选场景：社媒平台 / 外贸开发
2. 一句话输入：自然语言需求
3. AI 理解 + 轻量澄清（最多 2 轮追问模糊点）
4. 输出**增强 Prompt**（结构化、AI 可执行的精准指令）
5. 一键复制
6. 限免额度

**明确不做**：v1 不展示 Workflow/Agent 层，不接支付、不做多账号。

## 二、信息架构

## 四、操作流程

1. 首页选场景 + 一句话 → 「开始蒸馏」
2. 进 chat，云函数理解需求，模糊则轻量澄清（≤2 轮）
3. 蒸馏完成 → 增强 Prompt → 跳 result
4. 「复制」→ `wx.setClipboardData` → 粘贴给任意 AI 工具

**限免**：云函数按 `_openid` 计数。

## 五、数据存储（分层蒸馏结构 · 核心）

```js
{
  _openid:  String,
  scene:    String,                 // 'social' | 'trade'
  rawInput: String,                 // 用户原始一句话
  understood: String,               // AI理解的真实需求
  assets: {                         // 蒸馏产物，按层扩展
    prompt:    String,              // ① 增强Prompt（v1实现）
    workflow: [                     // ② 工作流（预留）
      { step:Number, name:String, desc:String }
    ],
    agent:    String,               // ③ Agent描述（预留）
    skill:    String,               // ④ Skill定义（预留）
    knowledge: String               // ⑤ 行业经验（预留）
  },
  createdAt: Number
}
```
**集合 `quotas`**：`{ _openid, count, updatedAt }`
> v1 只填 `prompt` 层并展示；其余层留空结构，未来版本直接填充 + 加渲染分支，无需改表。

## 六、关键技术点

| 能力 | 实现 | 要点 |
|---|---|---|
| 蒸馏 | 云函数 `distill` 调模型 | **Key 只存服务端** |
| 分层输出 | 模型返回 JSON：`{understood, assets:{prompt,...}}` | v1 取 prompt |
| 内容安全 | `wx.security.msgSecCheck` | 过审必需 |
| 复制 | `wx.setClipboardData` | — |
| 限免 | 云函数读写 `quotas` | — |

**云函数 `distill` 出入参**
```js
// 入参
{ openid, scene, rawInput, history:[{role,text}] }
// 出参
{ understood:String, assets:{ prompt:String, workflow:[], agent:'', skill:'', knowledge:'' }, done:Boolean }
```

**System Prompt（蒸馏核心）**
```
你是"会问社媒外贸版"的需求蒸馏器。用户输入模糊的自然语言需求，你要：
1. 先"理解真实需求"：推测用户没说清的隐含目标（受众/场景/痛点）。
2. 若需求过模糊，用口语轻问≤2个问题澄清，绝不用术语。
3. 蒸馏产出"增强Prompt"：结构化、AI可直接执行的精准指令，含角色设定+背景+目标+约束+期望输出格式。不叫"Prompt"给用户看。
4. 当前只产出 assets.prompt 层；workflow/agent/skill/knowledge 暂留空。
场景分支：
- trade（外贸开发）：偏客户开发、开发信、跟进节奏
- social（社媒发帖）：偏平台风格、钩子、互动
示例增强Prompt骨架：
"你是一名{角色}。用户是{背景}。目标：{目标}。请输出{格式}。注意：{约束}。"
```

## 七、技术栈与合规（个人主体关键点）

- **前端**：微信原生小程序 ｜ **后端**：云开发（云函数 + 云数据库）
- **模型**：DeepSeek / 混元（Key 存云函数环境变量）
- **合规**：
  - 类目「工具效率」
  - 昵称「会问社媒外贸版」；功能描述"**社媒/外贸需求整理工具**"，避"获客/营销/AI机器人"
  - 接内容安全审核；隐私指引注明 AI 处理用户输入
  - 外贸风险预案：若"外贸"触发企业类目，降级「会问社媒版」

## 八、开发任务分解（SOP）

1. 注册 + 开通云开发 + 申请模型 Key（环境变量）
2. 搭建 3 页面 + 场景选择组件
3. 实现 `distill` 云函数：理解 + 蒸馏（分层 JSON）+ 内容安全 + 限免
4. 打磨 system prompt（场景分支、增强 Prompt 骨架、禁术语、分层留空）
5. 前端串联：选场景 → 轻量澄清 → 结果只渲染 `assets.prompt`
6. 真机测试：增强 Prompt 质量、术语泄露、复制、分层落库
7. 上架：类目「工具效率」、名称「会问社媒外贸版」、搜一搜关键词（外贸需求 / 社媒文案 / 帮AI理解）

## 避坑清单（本案例沉淀）

- **命名合规**：昵称不带"AI"、不宽泛；"会问"被占→「会问社媒外贸版」；"外贸"触发企业类目时降级「会问社媒版」
- **头部垄断核实**：海外社媒文案竞品全是海外 Web/企业 SaaS，微信小程序端蓝海
- **个人主体类目**：落"工具效率"；功能描述用"需求整理工具"避敏感词；接内容安全
- **MVP 克制 + 架构预留**：v1 只渲染 Prompt 层，Workflow/Agent/Skill/Knowledge 分层数据结构预留，未来零成本扩展

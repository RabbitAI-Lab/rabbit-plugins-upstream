# 06 标签画像补全与质量排序（基于上传的《标签指标表》）

> 目的：为候选标签补齐【填充率/覆盖度/覆盖人群量级】等画像指标，并按工程规则完成质量排序。
> 数据来源：你上传的 `标签指标表.xlsx`（本地表）。
> 说明：接口 `tag/list` 不提供覆盖度/填充率，必须额外查询画像表。

---

## 1. 标签指标表字段字典（来自 Excel）
| 字段 | 含义 | 类型 | 备注 |
|---|---|---|---|
| tag_id | 标签ID | int/string | 与 tag/list.tagId 对齐 |
| tag_name | 标签名称 | string | 与 tag/list.tagName 对齐 |
| source | 来源 | string | 如：明略标签/合作伙伴标签 |
| dimension | 维度 | string | 性别/年龄/兴趣/地域/活跃消费力 |
| category | 类目 | string | 人口属性-性别/兴趣爱好-护肤… |
| fill_rate | 填充率 | float | Excel中为百分比(如73.5%)，脚本自动转为0-1 |
| coverage_rate | 覆盖度 | float | Excel中为百分比(如25.6%)，脚本自动转为0-1 |
| audience_size | 覆盖人群量级 | int | 若Excel该列数据截断不可用则标记为None |

> 主键建议：优先使用 `tag_id`；如存在重复，可用联合键（tag_id, tag_source）或（tag_id, tag_source, tag_dimension, tag_category）。

## 2. 补全流程（Enrichment）

### 2.1 输入
- candidate_tags（来自召回）：tagId、tagName、tagType、isDirectory、similarity_score

### 2.2 四级匹配策略（按优先级从高到低）
运行 `scripts/tag_profile_enrich.py` 自动完成JOIN，匹配级别从高到低：

1. **id_exact（tag_id精确匹配）**：候选标签的tagId与画像表tag_id完全一致 → 匹配度1.0
2. **name_exact（名称精确匹配）**：tagName完全相等 → 匹配度1.0
3. **norm_exact（归一化名称匹配）**：标签名去括号内容（如"大类""高兴趣度"）、去标点、去"岁"字后缀后相等或互为子串（长度≥2）→ 匹配度0.9
   - 解决："美妆个护" = "美妆个护（大类）"、"20-24" = "20-24岁"、"高消费" 匹配"高消费人群"
4. **fuzzy（TF-IDF字符n-gram模糊匹配）**：Dice系数匹配，低于threshold(0.25)标记MISSING

输出中会标记 `profile_match_type` 字段表示匹配级别，便于排查误匹配。

### 2.3 百分比自动转换
- fill_rate 和 coverage_rate 默认自动从百分比（如"95.8%"）转为0-1（如0.958），无需手动加 `--pct-to-decimal`
- audience_size 若Excel数据截断则标记None，不参与计算

### 2.4 工程分计算

工程分采用自适应降级策略，根据画像表实际可用指标自动选择计算方式：

```
- fill_rate + coverage_rate 均有：eng_score = 0.5 × fill_rate + 0.5 × coverage_rate
- 仅有 coverage_rate（大盘占比）：eng_score = coverage_rate（用大盘占比作为质量代理）
- 仅有 fill_rate：eng_score = fill_rate
- 均无：eng_score = None（标记MISSING降级处理）
```
- 范围 0~1，越高表示标签覆盖越广/质量越好
- 用于语义分接近时（±0.05桶内）的tie-break排序
- **fill_rate 为可选字段**：标签指标表可以只提供大盘占比（coverage_rate），工程分自动降级为coverage_rate

### 2.5 缺失与兜底
- 若四级匹配均未命中或fuzzy得分低于threshold：标记 `profile_status=MISSING`
- fill_rate字段缺失但coverage_rate有值时：**不标记MISSING**，profile_status仍为OK，eng_score=coverage_rate
- MISSING标签默认不进入MUST/PREFERRED层（关键维度如性别/年龄/城市/核心兴趣经人工确认可保留）

## 3. 质量过滤规则（硬门槛）

过滤条件（任一满足即剔除）：
1. isDirectory ≠ 1（目录节点不可用于组合人群）
2. profile_status = MISSING 且不属于核心维度关键词（性别/年龄/城市/核心兴趣/活跃/消费力/白领）
3. 标签名与用户需求明显矛盾（如用户要女则排除"男"，要一二线则排除"三线/四线"，等等）—— 由调用方根据Schema确定排除关键词列表

---

## 4. 排序流程（语义主排序+工程分微调）

> **核心原则：语义决定"相不相关"，工程决定"能不能用"。**

1. **硬门槛过滤**（见第3节）
2. **按用户需求维度分组**：标签不混排，而是按用户的每个需求点（性别/年龄/城市/兴趣/消费/职业/活跃）分别成组
3. **每组内排序**：语义分桶降序→有画像的优先→大类优先于细分→工程分微扰
4. **工程分不改变语义排序的大局**：工程分仅在语义接近时做微调

---

## 5. 分组推荐规则（按用户需求维度分组，不大杂烩排序）

> 核心原则：标签推荐应该回答「用户的每个小需求有哪些标签可选、质量如何」，而不是把所有标签混在一起排个大序再分为MUST/PREFERRED/OPTIONAL。

### 5.1 按需求维度分组

基于标签的 dimension 字段 + 名称关键词，将候选标签分到用户可理解的需求维度组：

| 分组名 | 包含维度 | 说明 |
|--------|----------|------|
| 性别 | dimension=性别 | 男/女标签二选一 |
| 年龄 | dimension=年龄 | 所有年龄段标签 |
| 城市级别 | dimension=地域且含「线城市/城市级别」 | 一线/新一线/二线等 |
| 核心兴趣 | dimension=兴趣且含用户核心品类关键词 | 对应需求中的核心兴趣（如美妆/护肤/彩妆） |
| 消费力 | dimension=活跃/消费力中的消费类 | 消费水平/收入/轻奢 |
| 职业 | dimension=活跃/消费力中的职业类 | 白领/新锐白领等 |
| 活跃度 | dimension=活跃/消费力中的活跃类 | 高活/圈层人群 |
| 其他兴趣 | dimension=兴趣的非核心品类 | 扩展兴趣 |
| 其他 | 无法归类的 | 兜底 |

核心兴趣关键词通过 `--core-interest` 参数传入（如 `--core-interest 美妆,护肤,彩妆`）。

### 5.2 组内排序规则

每组内标签独立排序，排序优先级：
1. **语义分桶降序**（±0.05为一桶，保证最相关在前）
2. **桶内排序**：
   - 有画像数据（profile_status=OK）的标签优先于MISSING标签
   - 大类标签（非细分）优先于细分标签（标记为 ↳）
   - 工程分（eng_score）降序
3. 精确语义分降序兜底

### 5.3 细分标签识别

以下特征的标签标记为细分标签（↳），排在同组大类标签后面：
- 名称含「-」且非年龄段格式（如「彩妆-欧美」「护肤-日韩」「护肤彩妆-高」）
- 名称含「价格」二字
- 具体子品类/功效词（口红/唇膏/面霜/面膜/精华/补水/美白/提拉等）

### 5.4 排序脚本
运行 `scripts/rank_candidates.py` 自动完成硬过滤+分组+组内排序：
```bash
python3 scripts/rank_candidates.py \
  --enriched data/run/tags_enriched.json \
  --core-interest "美妆,护肤,彩妆" \
  --out data/run/tags_grouped.json
```

## 6. 输出给用户的候选标签表字段
- tagId、tagName、tagType（明略/合作）
- dimension（维度：性别/年龄/兴趣/地域/活跃消费力）
- similarity_score（语义分）
- eng_score（工程分）
- fill_rate（填充率）
- coverage_rate（覆盖率）
- profile_match_type（匹配级别：id_exact/name_exact/norm_exact/fuzzy）
- _group（所属需求维度分组）

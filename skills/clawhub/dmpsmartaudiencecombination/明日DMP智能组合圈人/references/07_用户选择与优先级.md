# 07 用户选择与优先级（按维度分组输出）

> 核心原则：用户选择产物**必须按维度分组**，同维度OR关系的标签必须在同一组内，天然保证后续规则构建不会出现"同维度标签被AND"的错误。

## 1. 目的
将"分组推荐表"转为"用户确认的入选集"，输出**按维度分组的标签结构**（而非扁平列表），为后续rules_helper构建规则提供正确输入。

## 2. 输入
- 按维度分组的候选标签推荐表（Step6输出）

## 3. 用户选择输出结构（强制）

**必须输出按维度分组的dict，禁止输出扁平tagId列表：**

```json
{
  "性别": [{"tagId": 15705, "tagName": "女"}],
  "年龄": [
    {"tagId": 15687, "tagName": "20-24"},
    {"tagId": 15688, "tagName": "25-29"},
    {"tagId": 15689, "tagName": "30-34"}
  ],
  "城市级别": [
    {"tagId": 34080, "tagName": "一线城市"},
    {"tagId": 34082, "tagName": "二线城市"}
  ],
  "核心兴趣": [{"tagId": 15564, "tagName": "美妆个护"}],
  "消费力": [{"tagId": 15795, "tagName": "轻奢消费"}],
  "职业": [{"tagId": 23127, "tagName": "新锐白领"}],
  "活跃度": [{"tagId": 23137, "tagName": "彩妆圈层人群（高活）"}]
}
```

**这个结构直接对应rules_helper.build_rules_http(or_groups)的输入：**
- 每组内的多个tagId = OR关系（如20-24 OR 25-29 OR 30-34）
- 跨组 = AND关系（女 AND 20-24/25-29/30-34 AND 一线/二线 AND ...）
- ⚠️ **禁止把用户选中的标签展开成扁平列表再逐个AND！**

## 4. MUST/PREFERRED/OPTIONAL 分层（用户明确度优先原则 v2）

在按维度分组的基础上，对维度打分层标签。**核心原则：用户明确度优先，禁止按维度类型（性别/城市/年龄）硬编码分层。**

### 分层判断标准（按优先级从高到低）：

1. **MUST维度**（满足任一条件即归入MUST）：
   - 用户**明确点名/硬性要求**的条件（如"重点一二线"→城市MUST、"宝宝0-3岁"→育儿状态MUST、"只要女性"→性别MUST）
   - 核心兴趣大类/核心品类词（如"偏奶粉/纸尿裤"→奶粉+纸尿裤MUST）
   - 行业锚点标签（如母婴场景下的"母婴"大类）
   - ⚠️ **禁止因为维度类型（城市/年龄/育儿状态）而自动降级到PREFERRED**，必须看用户是否明确表达

2. **PREFERRED维度**（满足任一条件归入PREFERRED）：
   - AI根据行业典型场景**推荐**但用户未明确表态的条件（如新手爸妈推荐25-39岁年龄区间）
   - 圈层/身份类标签（新妈/精致妈妈/白领等）用于精准化但非硬性要求
   - 默认推荐项（如近30天活跃）

3. **OPTIONAL维度**：细分/收窄标签（如母婴-高兴趣、具体价格段、特定品牌），可选可不选

> 注意：分层是对"维度"分层，不是对"标签"混排分层。同一维度内如果用户选了多个标签，它们都是OR关系。

### 判断用户明确度的信号词：
- 明确→MUST："重点xxx"、"只要xxx"、"必须xxx"、"xxx城市"、"xxx岁"、"宝宝x岁"、偏xxx（核心品类）
- 推荐→PREFERRED：AI默认推荐、行业典型区间、未明确提及但相关的维度

## 5. 规则
1. **EXCLUDE优先级最高**：任何组合不得出现排除标签。
2. **用户明确要求的维度必须进MUST**：禁止硬编码"MUST=性别+核心兴趣"的固定模板，必须根据用户原话判断。例如用户说"重点一二线"，城市就必须是MUST，不能放PREFERRED。
3. **同维度选择多个标签=OR关系**：必须明确告知用户（如"您选择了一线城市+二线城市，这是OR并集关系"）。
4. **性别维度不默认进MUST**：只有用户明确要求某性别（如"只要妈妈""女性用户"）才进MUST；用户说"爸妈/家长/父母"等包含双性的词时，性别不进MUST，但应**主动提示确认**是否需要限定性别。
5. **精准标签防误杀**：Step 6排序时，对于与用户核心需求高度匹配的精准标签（如"0-3岁小孩父母"匹配"宝宝0-3岁"），即使相似度略低/覆盖率较小，也必须保留在分组推荐中并重点标注，不能被排序阈值过滤掉。AI应在生成推荐组合前主动检查是否有被排序过滤的高匹配度标签。
6. **Step 7推荐组合必须做"明确度回溯"**：在输出推荐组合前，逐一对照用户原话中的关键条件，确认每个明确条件都已归入MUST，没有误放到PREFERRED/OPTIONAL。
7. 用户选择完成后必须调用 `rules_helper.validate_selected_groups()` 校验。
8. 校验通过后，将selected按维度提取tagId二维列表（or_groups），传给 `rules_helper.build_rules_http(or_groups)` 生成API规则。

## 6. 禁止事项
- ❌ 禁止把用户选中的标签展开为扁平列表，然后循环每个tagId创建一个AND rule
- ❌ 禁止手写rules_json，必须通过rules_helper构建
- ❌ 禁止同维度多标签用AND连接（如20-24 AND 25-29 没有意义，会导致量级为0）

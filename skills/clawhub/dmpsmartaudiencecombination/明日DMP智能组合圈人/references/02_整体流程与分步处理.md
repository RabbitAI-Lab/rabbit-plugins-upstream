# 02 整体流程与分步处理（组合人群）

> 目标：将用户需求 → 候选标签 → 用户确认 → Overlap（MUST vs 可选）→ 递进组合 → DMP组合人群创建。
> 范围：仅组合人群（audienceType=2）。

## 0. 统一口径
- trackType：MOBILE / PC / OTT
- idTypes：随trackType枚举
- 所有量级、Overlap、最终人群均在同一口径下计算。

## 1. 流程（循序渐进）
1) 输入校验（必填三项）
2) 需求解析 → 10维Schema
3) 完整性判断：READY / NEED_CLARIFICATION / BLOCKED
4) 获取可用标签池：tag/list（过滤 isDirectory=1）
5) 自建语义召回：TF-IDF/向量检索（候选池TopK）
6) 标签画像补全：用 tagId 查询【标签指标表】
7) 语义主排序 + 工程硬门槛过滤（语义分决定排序，工程分仅做门槛剔除与微调）
8) 展示TopN候选 → 用户选择（MUST/PREFERRED/OPTIONAL/EXCLUDE）
9) 计算 MUST 基准人群 |M|（combine/create + taskList）
10) Overlap：对每个可选标签 x 计算 |M∩x|（audienceId_M AND tag_x）
11) 递进组合方案：精准/扩展/综合（2~3条）
12) 用户确认/修改（局部重算）
13) 创建最终组合人群（combine/create）
14) 状态查询与交付（taskList + 可解释规则）

## 2. 关键硬约束
- 候选标签必须来自 tag/list 且 isDirectory=1；不得编造tagId。
- combine/create：最后一组 op 必须为 noop；rule 内多个 tag 为 OR；组间 op 表达与下一个rule关系。
- 权限：传入的 tagId / audienceId 必须在该应用租户权限内，否则创建失败。

## 3. 交付物（建议）
- 候选标签表（含相似度、画像指标、推荐理由）
- 用户选择结果（含优先级）
- Overlap报告（仅MUST vs 可选）
- 最终组合规则（可读表达式 + API data JSON）
- 最终 audienceId、audienceStatus、audienceAmount

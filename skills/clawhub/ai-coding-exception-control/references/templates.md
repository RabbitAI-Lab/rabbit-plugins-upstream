## 2. 异常优先提示词模板

```
请实现[功能名称]功能，必须按以下顺序执行：

【第一步：失败场景分析】
列出所有可能的失败场景（至少5个），格式：
- 场景：[描述] | 类型：[异常类型] | 处理：[策略] | 用户提示：[文案]

【第二步：异常处理编码】
为上述每个失败场景编写异常处理代码。

【第三步：正向流程编码】
最后才编写正向业务逻辑。

【约束条件】
- 禁止空catch块
- 禁止catch中仅console.log
- 每个catch必须有明确的恢复策略或向上传播
- 异常日志包含：请求参数、用户ID、时间戳、错误堆栈
- 错误提示对用户友好，不暴露技术细节（如SQL错误、堆栈信息）
- 外部调用必须设置超时
- 可重试异常必须有重试机制（带指数退避）
```

### 4.3 一键全量测试脚本（L2 自动执行层）

> 完整脚本见 `testing-sop.md` L2层，包含 `run-all-tests.sh` 和 `coverage-check.js`

核心要点：
- `run-all-tests.sh`：一键跑单元测试+API测试+异常路径+覆盖率+混沌注入

### 异常用例标准结构

```javascript
// 每个异常测试用例必须包含四要素断言
it('异常Fn: [场景描述]', async () => {
  // 1. mock异常条件
  jest.spyOn(db, 'query').mockRejectedValue(new Error('ECONNREFUSED'));

  // 2. 执行请求
  const res = await request(app).get('/api/xxx');

  // 3. 四要素断言
  expect(res.status).toBe(503);                          // ①状态码
  expect(res.body.error.message).toContain('繁忙');       // ②错误信息
  expect(res.body.error.message).not.toContain('ECONN'); // ②不暴露技术细节
  expect(res.body.degraded).toBe(true);                   // ③降级行为
  // ④副作用（如检查日志/状态变更）
});
```

## 5. 异常审计检查清单

```
异常处理审计清单

外部调用：
□ 所有网络请求是否有try-catch？
□ 所有数据库操作是否有事务和异常处理？
□ 所有文件操作是否有异常处理？
□ 所有第三方API调用是否有异常处理？

catch块质量：
□ 是否有空catch块？（禁止）
□ 是否有仅console.log的catch？（禁止）
□ 每个catch是否有恢复策略或向上传播？
□ 异常信息是否包含调试上下文？

降级与恢复：
□ 是否有降级策略（而非直接崩溃）？
□ 可重试异常是否有重试机制？
□ 重试是否有最大次数限制？
□ 重试是否有指数退避？

并发与资源：
□ 并发场景是否考虑了竞态条件？
□ 资源是否在异常时正确释放？（连接/文件句柄/内存）
□ 超时是否被正确处理？
□ 是否有死锁风险？

用户体验：
□ 错误提示是否对用户友好？
□ 是否暴露了技术细节？（SQL/堆栈/内部路径）
□ 错误码是否统一规范？
□ 是否有"静默吞异常"的情况？
```

## 6. 标准异常分类参考表

| 分类 | 异常类型 | 典型场景 | 处理策略 | 是否重试 |
|------|---------|---------|---------|---------|
| 网络 | NetworkError | 请求超时、连接拒绝 | 重试3次+指数退避 | 是 |
| 网络 | TimeoutError | 响应超时 | 重试1次后降级 | 是（1次） |
| 权限 | AuthError | 未登录、token过期 | 跳转登录页 | 否 |
| 权限 | ForbiddenError | 无权限访问资源 | 返回403+提示 | 否 |
| 数据 | ValidationError | 参数格式错误 | 返回明确错误信息 | 否 |
| 数据 | NotFoundError | 资源不存在 | 返回404+友好提示 | 否 |
| 数据 | ConflictError | 数据冲突/重复 | 返回409+冲突详情 | 否 |
| 并发 | RateLimitError | 请求频率超限 | 返回429+等待时间 | 否（等待后可） |
| 并发 | DeadlockError | 数据库死锁 | 自动重试 | 是 |
| 系统 | ServerError | 内部错误 | 降级+告警 | 否 |
| 系统 | ResourceExhaustedError | 内存/连接耗尽 | 降级+告警 | 否 |
| 第三方 | ThirdPartyError | 第三方服务异常 | 降级或重试 | 视情况 |

## 7. 失败场景穷举模板（三维度交叉）

> **核心认知：穷举失败场景不能靠"灵感"，必须靠"穷举工具"——就像做数学不能靠直觉，要靠公式。**
>
> 三维度交叉 = 域级（十大域）+ 参数级（8问法）+ 状态级（状态机），三层叠加，漏网之鱼极少。

### 7.1 维度一：十大失败域分类法

每个功能点，按这10个域逐个过一遍，每个域问"这里会出什么问题"：

| # | 失败域 | 穷举问题 | 典型场景 |
|---|--------|---------|---------|
| 1 | **输入层** | 每个参数：缺失？空值？格式错？类型错？超长？特殊字符？ | emotion_note传10000字 |
| 2 | **认证授权** | 无token？过期？伪造？权限不足？越权访问他人数据？ | 用户A查用户B的数据 |
| 3 | **网络通信** | 请求超时？连接断开？部分响应？DNS失败？ | 小程序弱网提交 |
| 4 | **数据层** | 记录不存在？重复键？约束违反？死锁？事务失败？ | 查不存在的boss_id |
| 5 | **并发冲突** | 同时提交？重复提交？并发修改同一记录？连接池耗尽？ | 用户狂点提交10次 |
| 6 | **外部依赖** | 第三方API宕机？超时？返回错误？返回格式变了？ | AI对话API超时 |
| 7 | **资源耗尽** | 内存不足？磁盘满？连接池满？限流触发？ | Redis连接池耗尽 |
| 8 | **业务逻辑** | 状态非法？规则违反？配额超限？数据不一致？ | 未完成关卡进下一关 |
| 9 | **安全攻击** | SQL注入？XSS？越权？暴力枚举？重放攻击？ | note里塞SQL注入 |
| 10 | **环境配置** | 环境变量缺失？配置文件错？端口冲突？版本不兼容？ | 生产JWT密钥未配置 |

**每个域约2-5个场景。10个域走一遍 = 20-50个场景。**

#### 十大域穷举工作表


### 7.2 维度二：参数轴穷举法

最机械但最有效的方法。**对接口的每一个输入参数，固定问8个问题：**

| # | 问题 | 说明 | 示例（参数：phone） |
|---|------|------|---------------------|
| 1 | 缺失/null是什么行为？ | 不传该字段 | 不传phone → 应该400 |
| 2 | 空字符串是什么行为？ | 传空值 | phone="" → 应该400 |
| 3 | 格式不合法是什么行为？ | 格式错误 | phone="abc123" → 应该400 |
| 4 | 类型错误是什么行为？ | 传错类型 | phone=12345678901（数字）→ 兼容或400 |
| 5 | 超长是什么行为？ | 超长输入 | phone="1"*1000 → 应该400 |
| 6 | 特殊字符是什么行为？ | 非常规字符 | phone="+86 138\x00..." → 400或清洗 |
| 7 | 恶意payload是什么行为？ | 注入攻击 | phone="'; DROP TABLE--" → 400或安全处理 |
| 8 | 边界值是什么行为？ | 临界值 | phone=10位/11位/12位 → 只接受11位 |

**穷举公式：接口参数数 × 8 = 参数级失败场景数。** 5参数接口 = 40个场景。

#### 参数轴穷举矩阵模板

```markdown
### 参数轴穷举矩阵

接口：[HTTP方法 + 路径]
参数列表：[param1, param2, param3, ...]

| 参数 | ①缺失 | ②空值 | ③格式错 | ④类型错 | ⑤超长 | ⑥特殊字符 | ⑦注入 | ⑧边界值 |
|------|-------|-------|---------|---------|-------|----------|------|---------|
| param1 | 400 | 400 | 400 | 兼容 | 400 | 400 | 400 | [边界行为] |
| param2 | 400 | 400 | 400 | 400 | N/A | 400 | 400 | [边界行为] |
| param3 | 可选 | OK | N/A | 400 | 截断 | 转义 | 清洗 | [边界行为] |
| param4 | 400 | 400 | 400 | 400 | 400 | 400 | 400 | [边界行为] |

说明：
- "400" = 返回400错误
- "兼容" = 自动转换后接受
- "截断" = 截断到最大长度后接受
- "转义" = 转义特殊字符后接受
- "清洗" = 清洗后接受
- "可选" = 该参数可选，缺失时使用默认值
- "N/A" = 不适用（如枚举类型不存在超长问题）
```

### 7.3 维度三：状态机穷举法

适用于有状态流转的功能（订单、关卡进度、订阅状态等）。

**方法：画出状态机 → 列出所有可能转换 → 减去合法转换 = 非法转换 = 失败场景。**

**穷举公式：状态数 × (状态数-1) - 合法转换数 = 非法转换数。**
4个状态 = 12种可能转换 - 3个合法 = 9个非法转换 = 9个失败场景。

#### 状态机穷举模板

```markdown
### 状态机穷举

功能点：[功能名称]

#### 正常状态机
[状态A] → [状态B] → [状态C] → [状态D]

#### 合法转换清单
| # | 当前状态 | 操作 | 目标状态 |
|---|---------|------|---------|
| 1 | 未开始 | 开始 | 进行中 |
| 2 | 进行中 | 完成 | 已完成 |
| 3 | 已完成 | 解锁 | 已解锁下一关 |

#### 非法转换清单（每个都是一个失败场景）
| # | 当前状态 | 尝试操作 | 期望行为 | 优先级 |
|---|---------|---------|---------|--------|
| 1 | 未开始 | 直接标记已完成 | 拒绝 400/403 | P0 |
| 2 | 已完成 | 再次开始 | 拒绝或幂等返回 | P1 |
| 3 | 已完成 | 标记为进行中 | 拒绝（状态不可回退） | P1 |
| 4 | 未解锁 | 直接开始 | 拒绝 403 | P0 |
| 5 | 进行中 | 跳到已完成（跳过步骤）| 拒绝 | P1 |
| ... | ... | ... | ... | ... |
```

### 11.5 AI弯路记录指令模板

```
在编码/调试完成后（或走弯路后立即），执行弯路记录：

1. 回顾本次编码/调试过程，识别走过的弯路（至少1条，除非真的全程顺利）
2. 为每条弯路创建记录，格式见11.1节
3. 对每条弯路执行根因分析，必须选一个根因类型（不允许"粗心"）
4. 为每条弯路提出具体预防措施（不允许"注意"，必须是检查项或规则）
5. 将记录追加到 lessons-learned.md

约束：
- 弯路编号连续递增（LL-001, LL-002, ...）
- 日期使用实际日期
- 改进状态初始为"待改进"
- 不修改已存在的弯路记录（只追加，不修改）
```

# 异常处理约束块 — 补丁注入指南

> 本文件提供5种预置的异常处理约束块，用户可以将其注入到任何编码skill中。
> 注入方式：将约束块内容复制到目标skill的SKILL.md中，放在"核心职责"和"交付物"之间。

---

## 1. 后端架构师约束块

适用：`engineering-backend-architect`、后端开发类skill

```markdown
## 🛡️ 异常处理强制约束（不可省略）

> AI编码天然只走正向流程，异常处理是系统性弱点。以下铁律必须遵守，不可省略。
> 完整方法论见 `ai-coding-exception-control` skill的七层防御框架。

### 三条铁律
1. **异常优先**：先列失败场景（≥3个）→ 先写异常处理代码 → 最后写正向流程
2. **禁止假处理**：禁止空catch、禁止catch中仅console.log、禁止catch后return null了事。每个catch必须有恢复策略或向上传播
3. **外部调用必包**：所有网络请求/DB操作/文件IO/第三方API必须有try-catch + 超时设置

### 架构层特别要求（L2）
- 设计统一异常中间件，让异常自动冒泡到中间件统一处理
- 所有外部调用必须设置超时（数据库、HTTP、Redis）
- 可重试异常必须实现指数退避重试机制
- 熔断降级：失败超阈值自动降级，而非崩溃

### 编码后自检
- [ ] 所有catch块是否有具体处理（非空、非仅console.log）？
- [ ] 异常日志是否包含上下文（请求参数、用户ID、时间戳）？
- [ ] 用户错误提示是否友好（非堆栈/SQL等技术细节）？

### 弯路记录（不可省略）
> 编码调试中走过的弯路是改进资产。完整闭环见 `ai-coding-exception-control/references/lessons-feedback-loop.md`。

- **走了弯路必须记录**：选错方案/调试方向错误/换了实现路径/漏了异常 → 记录到 `.workbuddy/memory/lessons-learned.md`
- **编码前先看历史弯路**：查看最近10条弯路，确认本次功能可能遇到哪些同类弯路
- **根因必分析**：不允许写"粗心/疏忽"，必须挖到知识盲区/流程缺失/工具误用
- **预防必落地**：每条弯路必须提出具体预防措施，标注改进到哪个文件
```

## 5. 懒人模式约束块

适用：`ponytail`、快速开发类skill

```markdown
### 🛡️ 异常处理铁律（懒人模式也不可省略）

> 懒归懒，异常处理不能省。真实项目踩过的坑：catch{}静默吞没是项目级系统性问题。
> 完整方法论见 `ai-coding-exception-control` skill。

- **禁止空catch块** — 就算再懒，catch里至少return一个有意义的error
- **禁止catch中仅console.log** — console.log不算处理，必须有恢复策略或向上传播
- **禁止catch后return null/undefined** — 静默吞异常比不处理更危险
- **外部调用必须有try-catch** — wx.request/DB/文件IO/第三方API，缺一不可
- **先写异常后写正向** — 列3个失败场景，写异常处理，最后才写happy path

### 弯路记录（懒人模式也不可省略）
> 走弯路不记录 = 下次还会走同样的弯路 = 更浪费时间。完整闭环见 `ai-coding-exception-control/references/lessons-feedback-loop.md`。

- **走了弯路必须记录** — 一句话记到 `.workbuddy/memory/lessons-learned.md`，格式：类型+描述+根因+预防
- **编码前扫一眼最近弯路** — 10秒看最近10条，避免重复踩坑
- **根因不写"粗心"** — 挖到知识盲区/流程缺失/工具误用
```

## 注入方法

1. 打开目标skill的 `SKILL.md`
2. 找到"核心职责"和"交付物"之间的位置
3. 将对应的约束块粘贴进去
4. 保存即可

**约束块会自动生效**——因为skill加载时会读取整个SKILL.md，约束块的内容会成为AI执行时的指令。

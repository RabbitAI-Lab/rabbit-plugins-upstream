# AI编码异常处理控制框架

> **版本** v1.7.0 | **代号** Frost Shield（霜盾）
>
> AI辅助编码的完整质量保障体系——从调研到交付，从编码到审查，从测试到改进，全链路闭环。

## 这是什么？

一套**机制倒逼型**的AI编码质量控制框架。解决一个核心问题：

> **AI写代码时只走happy path，异常处理敷衍了事。**

空catch块、`catch(e){console.log(e)}`假处理、缺降级策略、异常路径零测试——这不是个别bug，而是AI编码的系统性偏差。靠提示词里写"请处理异常"没用，AI会写一个空catch块交差。

**本框架的解法：不靠AI自觉，靠机制倒逼。**

## 核心能力

| 能力 | 说明 |
|------|------|
| 深度调研引导 | 5方向×4问=20步，强制AI用WebSearch实际调研，不凭训练数据编造 |
| 七维需求引导 | 28步引导式走完需求定义，从用户故事到依赖地图 |
| 五层设计防御 | 20步引导式走完技术设计，让异常处理"无法被跳过" |
| 三维度失败场景穷举 | 十大域×参数轴8问×状态机，系统化穷举15-50个失败场景 |
| 六层自动化测试 | 用例生成→自动执行→异常路径→覆盖率→混沌注入→结构化报告 |
| Ralph审查模式 | 3轮限制+Stall检测+Reviewer Memory+Falsifiable Receipt |
| 弯路沉淀闭环 | 实时记录→定期分析→改进skill/SOP→下次自动预防 |

## 快速上手

### 安装

将本目录复制到 `~/.workbuddy/skills/ai-coding-exception-control/`：

```
~/.workbuddy/skills/ai-coding-exception-control/
├── SKILL.md                          ← 核心框架（入口）
├── README.md                         ← 本文件
└── references/
    ├── requirements-design-sop.md    ← 调研+需求+设计SOP
    ├── coding-sop.md                 ← 编码SOP
    ├── testing-sop.md                ← 测试SOP
    ├── lessons-feedback-loop.md      ← 弯路闭环SOP
    ├── audit-ledger-spec.md          ← 审查交接规范
    ├── templates.md                  ← 12套模板集合
    ├── OPC-DEVELOPMENT-SUITE.md      ← 套件总览
    ├── reverse-requirements.md       ← 逆向需求规格
    └── reverse-design.md             ← 逆向技术设计
```

### 使用

安装后，在WorkBuddy对话中说出触发词（"编写功能"、"实现接口"、"写代码"、"编码"、"需求分析"、"设计"等），skill自动加载。

**第一次使用建议：**

1. 读 `SKILL.md` 了解七层防御体系全貌
2. 从一个实际功能开始，按执行顺序走一遍完整流程
3. 走完后把弯路记录到 `.workbuddy/memory/lessons-learned.md`
4. 下次编码时框架会自动加载历史弯路做预防

## 七层防御体系

```
L0-R 深度调研（20步）→ 调研质量门（6项）
  ↓
L0a 需求引导（28步）→ 需求质量门（8项）
  ↓
L0b 设计引导（20步）→ 设计质量门（6项）
  ↓
L1 规格书（三维度穷举）→ L2 架构（Result模式+中间件）
  ↓
L3 编码（异常优先）→ L4 测试（六层框架）
  ↓
L5 审查（Ralph模式+12项审计）→ L6 弯路闭环
```

**三道质量门共20项检查，任一项不通过不允许进入下一阶段。**

## 不适用场景

- 简单脚本/一次性工具（杀鸡用牛刀）
- 纯前端展示页面无后端逻辑（没有外部调用就不需要异常防御）
- 已有成熟CI/CD+测试体系的大型团队（本框架面向AI辅助开发场景）

## FAQ

**Q: 这套框架会让编码变慢吗？**
A: 会的。前期调研+需求+设计阶段会多花1-2小时。但这1-2小时的投入，会在测试阶段省3-5小时（异常路径已有测试用例），在上线后省8+小时（不用凌晨被叫起来修bug）。总体是赚的。

**Q: 我可以只用一部分吗？**
A: 可以。最小可用集 = L1规格书模板 + L3异常优先提示词 + L5审计清单。但建议至少走一遍完整流程，理解全貌后再裁剪。

**Q: 支持哪些编程语言/框架？**
A: 语言无关。框架本身是方法论+SOP+模板，不依赖任何特定语言。示例中使用了TypeScript/Node.js，但Result模式、异常中间件、三维度穷举等概念适用于所有语言。

**Q: 必须用WorkBuddy吗？**
A: 本框架设计为WorkBuddy的skill，触发机制依赖WorkBuddy的skill加载。但SOP和模板的内容本身是通用的，可以复制到任何AI辅助开发工具中使用（只是不会自动触发）。

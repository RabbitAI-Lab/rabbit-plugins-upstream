## Description:

Use when a domain's email is landing in spam, or you see SPF PermError / "too many DNS lookups", DMARC stuck at p=none, a "550 5.7.515" or "550 5.7.1" rejection, DKIM failures, or a domain that might be blacklisted.

This skill is ready for commercial/non-commercial use.

## Use Case:

External users, developers, and email operations teams use this skill to diagnose email authentication, DNS, blacklist, and domain or certificate expiry issues for a domain. It guides agents to run DNS Doctor API checks, explain findings, relay validated fix records exactly as returned, and leave DNS changes under the user's control.

### Deployment Geography for Use:

Global

## Known Risks and Mitigations:

Risk: Domain scan details are sent to dnsdoctor.dev.

Mitigation: Tell users before scanning and avoid sending domains or related details they do not want processed by DNS Doctor.

Risk: A DNSDOCTOR_API_TOKEN could expose account-specific monitoring data if pasted into chat or logs.

Mitigation: Keep the token in the user's environment and reference it as an environment variable rather than asking the user to paste it.

Risk: Incorrect DNS changes can disrupt legitimate email delivery.

Mitigation: Use only server-returned fix records, present them verbatim, and require the user to publish and approve DNS changes at their DNS host.

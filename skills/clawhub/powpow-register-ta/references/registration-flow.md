# பதிவு செயல்முறை விவரம் — powpow-register

சிக்கல்களைத் தீர்க்கும்போது பார்ப்பதற்கு. அனைத்து விதிகளும் தளத்தின் மூல குறியீட்டிலிருந்து வருகின்றன (Next.js
முன்புறம்-பின்புறம் ஒரே மாதிரியான சரிபார்ப்பு), ஆதாரங்களுடன். தளம் புதுப்பிக்கப்பட்டால் ஆன்லைனின் உண்மையான
நடத்தையே முதன்மை.

## நுழைவாயில்கள்

- பதிவுப் பக்கம்: https://global.powpow.online/register
- உள்நுழைவுப் பக்கம்: https://global.powpow.online/login
- சந்தாப் பக்கம்: https://global.powpow.online/subscription
- பங்கிடும் இணைப்பு போன்றவற்றிலிருந்து `?next=...` உடன் நுழைந்தால், பதிவு + பணம் செலுத்துதல் முடிந்ததும் தானாக அசல் பக்கத்திற்குத் திரும்பும்.

## வீத வரம்பு மற்றும் வன்முறை எதிர்ப்பு அளவுருக்கள்

| நடத்தை | வரம்பு | ஆதாரம் |
|---|---|---|
| பதிவு சமர்ப்பித்தல் | **3 முறை/நிமிடம்/IP**, வரம்பு மீறினால் 429 | `src/lib/rate-limit.ts` `REGISTER_RATE_LIMIT` |
| சரிபார்ப்புக் குறியீடு அனுப்புதல் | அதே IP 1 முறை/நிமிடம் **மற்றும்** அதே மின்னஞ்சல் 1 முறை/நிமிடம், வரம்பு மீறினால் 429; முன்புறப் பொத்தான் 60 வினாடிகள் எண்ணிக்கை | `src/app/api/auth/register/send-code/route.ts` |

| உள்நுழைவு | 5 முறை/நிமிடம்/IP; ஒரே கணக்கில் தொடர்ந்து **5 தோல்விகள் என்றால் 30 நிமிடம் பூட்டப்படும்** (423), அந்த நேரத்தில் மீதமுள்ள முயற்சிகள் குறைந்து காட்டப்படும் | `src/app/api/auth/login/route.ts`, `rate-limit.ts` |

**தனியுரிமை பாதுகாப்பு நடத்தை**: சரிபார்ப்புக் குறியீடு / கடவுச்சொல் மறந்தது அனுப்பும்போது, மின்னஞ்சல் ஏற்கனவே
பதிவு செய்யப்பட்டிருந்தாலும் இல்லாமல் போனாலும், இடைமுகம் இரண்டு நிலைகளிலும் ஒரே மாதிரியான வெற்றிச் செய்தியைத்
திருப்பித் தரும், மின்னஞ்சல் பதிவு செய்யப்பட்டுள்ளதா என்பதை வெளிப்படுத்தாது.

## agent முகவர் முறைக்கும் இணையப் பதிவுக்கும் இடையிலான சமநிலை

skill ஸ்கிரிப்ட் **அதே பொது API களையே** அழைக்கிறது (`/api/auth/register`, `send-code`, `login`,
`/api/auth/me`) — பதிவுப் பக்கத்தின் படிவம் சமர்ப்பிக்கும் சரிபார்ப்பு, வீத வரம்பு, பிழை பாதைகள் அனைத்தும்
முழுவதும் ஒன்றே — இந்த கோப்பின் அனைத்து விதிகளும் இரு முறைகளுக்கும் ஒரே மாதிரி பொருந்தும். ஸ்கிரிப்ட்
நேரவரிசை மற்றும் கட்டளை ஒப்பந்தம் `references/agent-flow.md` இல்.

## பதிவு வெற்றிக்குப் பின் நிலை மாற்றம்

1. பயனர் `accountStatus: 'pending'` நிலையில் DB இல் சேமிக்கப்படுவார், தொடக்கத்தில் **3 பேட்ஜ்கள்** கிடைக்கும் (register route).
2. சேவையகம் ஒரே நேரத்தில் இரண்டு HttpOnly cookie களை நடப்பிக்கும்: JWT (`/subscription` ஐ நேரடியாக அணுகலாம்) மற்றும்
   pendingUserToken (சந்தா செயல்முறையின் அடையாளச் சான்று).
3. பதிவுப் பக்கம் `pending_payment` ஐக் கண்டறிந்ததும் → `/subscription` க்குத் திசைமாற்றும் (`next` திரும்பும்
   அளவுரு பேணப்படும்); agent முகவர் முறையில் `me?token=…&redirect=/subscription` கொண்டு அதே விளைவைப் பெறலாம்.
4. பணம் செலுத்துதல் முடிந்ததும் → `accountStatus` `active` ஆக மாறும் (**அலிபே notify வழியாக சேவையகத்தில் தானாக
   செயல்படுத்தப்படும்**; PayPal Webhook வழியாக தானாக; வீசாட் QR கைமுறை உறுதிப்படுத்தல்; ஹுவாவே IAP
   `activate-huawei` வழியாக). விவரங்கள் `payment-and-activation.md` இல்.

செயல்படுத்தப்படாத (pending) பயனர் மைய API களை (தகவலோடை, வரைபடம், டிஜிட்டல் மனிதர் உரையாடல், செக்-இன் போன்றவை)
அழைத்தால் எப்போதும் 403; பங்கிடப்பட்ட பதவியின் இணைப்பு மட்டும் விதிவிலக்கு (பொதுவாக அணுகக்கூடியதாகவே இருக்கும்).

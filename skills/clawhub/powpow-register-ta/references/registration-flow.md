# பதிவு செயல்முறை விவரங்கள் — powpow-register

சிக்கல்களைக் கண்டறியும் போது பார்க்க வேண்டியது. அனைத்து விதிகளும் தள மூலக் குறியீட்டிலிருந்து (Next.js முன்பக்கம்/பின்பக்கம்
இணக்க சரிபார்ப்பு) எடுக்கப்பட்டுள்ளன, மூலம் சுட்டிக்காட்டப்பட்டுள்ளது.
தளம் புதுப்பிக்கப்பட்டால் ஆன்லைன் உண்மையான நடத்தையே பொருந்தும்.

## நுழைவு

- பதிவு பக்கம்: https://global.powpow.online/register
- உள்நுழைவு பக்கம்: https://global.powpow.online/login
- சப்ஸ்கிரிப்ஷன் பக்கம்: https://global.powpow.online/subscription
- பகிர்வு இணைப்பு போன்றவற்றிலிருந்து `?next=...` உடன் வந்தால், பதிவு + செலுத்துதல் முடிந்ததும் தானாக அசல் பக்கத்திற்குத் திரும்பும்.

பக்கத்தில் இன்னும் மூன்று மூன்றாம் தரப்பு உள்நுழைவு பொத்தான்கள் உள்ளன: **Google, Watcha, ஹுவாவே கணக்கு** (`GoogleSignInButton` /
`WatchaLoginButton` / `HuaweiLoginButton`)। மூன்றாம் தரப்பு கணக்கிற்கு உள்ளூர் கடவுச்சொல் இல்லை, பிறகு கடவுச்சொல்லுடன் உள்நுழைந்தால்
«该账号未设置密码，请使用其他方式登录» (இந்தக் கணக்கிற்கு கடவுச்சொல் அமைக்கப்படவில்லை, வேறு வழியில் உள்நுழையவும்) கிடைக்கும்.

## ரேட்-லிமிட் மற்றும் எதிர்-ப்ரூட்-ஃபோர்ஸ் அளவுருக்கள்

| நடத்தை | வரம்பு | மூலம் |
|---|---|---|
| பதிவு சமர்ப்பித்தல் | **ஒவ்வொரு IP-க்கும் 3 முறை/நிமிடம்**, வரம்பு மீறினால் 429 | `src/lib/rate-limit.ts` `REGISTER_RATE_LIMIT` |
| சரிபார்ப்புக் குறியீடு அனுப்புதல் | ஒரே IP-லிருந்து 1 முறை/நிமிடம் **மற்றும்** ஒரே மின்னஞ்சலுக்கு 1 முறை/நிமிடம், வரம்பு மீறினால் 429; முன்பக்கம் பொத்தானில் 60 வினாடி கவுண்ட்டவுன் | `src/app/api/auth/register/send-code/route.ts` |

| உள்நுழைவு | 5 முறை/நிமிடம்/IP; ஒரே கணக்கில் தொடர்ச்சியாக **5 முறை தோல்வியடைந்தால் 30 நிமிடங்கள் பூட்டு** (423), இந்த நேரத்தில் மீதமுள்ள முயற்சிகள் குறைந்து காட்டப்படும் | `src/app/api/auth/login/route.ts`、`rate-limit.ts` |

**தனியுரிமை பாதுகாப்பு நடத்தை**: சரிபார்ப்புக் குறியீடு அனுப்பும்போது / கடவுச்சொல் மறந்தால், மின்னஞ்சல் ஏற்கனவே பதிவு செய்யப்பட்டதா இல்லையா,
இடைமுகம் எப்போதும் ஒரே வெற்றி செய்தியைத் தரும், மின்னஞ்சல் பதிவு செய்யப்பட்டுள்ளதா என்பதை வெளிப்படுத்தாது.

## பதிவு வெற்றிக்குப் பிறகு நிலை ஓட்டம்

1. பயனர் `accountStatus: 'pending'` உடன் தரவுத்தளத்தில் சேமிக்கப்படுகிறார், தொடக்கத்தில் **3 பேட்ஜ்கள்** (register route).
2. சர்வர் அதே நேரத்தில் இரண்டு HttpOnly குக்கீகளை அமைக்கிறது: JWT (நேரடியாக `/subscription` அணுகலாம்) மற்றும்
   pendingUserToken (சப்ஸ்கிரிப்ஷன் செயல்முறை அடையாளச் சான்று).
3. பதிவு பக்கம் `pending_payment`-ஐ அடையாளம் கண்டு → `/subscription`-க்கு செல்கிறது (`next` திரும்பும் அளவுருவை வைத்துக்கொள்கிறது).
4. செலுத்துதல் முடிந்தது → `accountStatus` `active` ஆகிறது (PayPal Webhook மூலம் தானாக செயல்படும்; WeChat ஸ்கேனில்
   கைமுறை உறுதிப்படுத்தல்; ஹுவாவே IAP-ல் `activate-huawei`). விவரங்கள் `payment-and-activation.md`-ல் பார்க்கவும்.

செயல்படுத்தப்படாத (pending) பயனர் முக்கிய API (ஃபீட், வரைபடம், டிஜிட்டல் மனிதர் அரட்டை, செக்-இன் போன்றவை) அழைத்தால் எப்போதும்
403 கிடைக்கும்; பதிவு பகிர்வு இணைப்பு தவிர (அது பொதுவாக திறந்திருக்கும்).

## உள்நுழைவு சிறிய விவரம் (கண்டறிதலுக்கும் பயன்படும்)

உள்நுழைவு **பயனர் பெயர் / மின்னஞ்சல் / மொபைல் எண்** மூன்றையும் ஒன்றாக ஏற்கிறது (மூன்றில் எதையும் கணக்கு பெயராகப் பயன்படுத்தலாம்).
கடவுச்சொல் மறந்துவிட்டால்: உள்நுழைவு பக்கம் → «கடவுச்சொல் மறந்துவிட்டது» → பதிவு செய்த மின்னஞ்சலை உள்ளிடவும், 6 இலக்க சரிபார்ப்புக் குறியீடு பெறவும் → மீட்டமைக்கவும்.

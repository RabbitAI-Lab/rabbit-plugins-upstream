# சந்தா செயல்படுத்தலும் பணம் செலுத்துதலும் — powpow-register

## முடிவு (முதலிலேயே பதில்)

**அலிபே தடம் ஏற்கனவே இயக்கத்தில் உள்ளது (2026-10-07 முதல்), இந்த skill இன் முதன்மை பணம் செலுத்தும் முறை; agent
ஆர்டர் உருவாக்கம் மற்றும் பணம் வருகை கண்காணிப்பை முகவராகச் செய்யலாம்.** வெளிநாடு/அலிபே இல்லாத பயனர்கள் PayPal
க்குத் திரும்பலாம்; வீசாட் QR (கைமுறை உறுதிப்படுத்தல்) மற்றும் ஹுவாவே IAP இன்னும் இருக்கின்றன, ஆனால் skill அவற்றை
முகவராகச் செய்யாது.

பணம் செலுத்தும் பகுதியின் பொறுப்பு எல்லை: agent **ஆர்டரை உருவாக்குவது, பணம் செலுத்தும் பக்கத்தைத் திறப்பது, பணம்
வருகையை விசாரிப்பது** மட்டுமே செய்யும்; பயனரின் அலிபே கணக்கு/பணம் செலுத்தும் சான்றுகளை **ஒருபோதும்** தொடாது,
"பணம் செலுத்தித் தருவேன்" என்றும் வாக்களிக்காது. பணம் செலுத்தும் செயல் எப்போதும் பயனராலேயே அலிபேவின் அதிகாரப்பூர்வ
பணம் செலுத்தும் பக்கத்தில் முடிக்கப்படும்.

## அலிபே தடம் (vibepay, முதன்மை முறை)

ஒருமுறை பணம் செலுத்தி வாங்கும் முறை: ஒரு முறை செலுத்தி தகுந்த கால அளவைத் திறக்கலாம், **தானாகப் புதுப்பிக்காது**.
திட்டங்கள் `src/lib/alipay-vibepay.ts` (`ALIPAY_PACKAGES`) இல் நிலையாக எழுதப்பட்டுள்ளன:

| key | planId | பெயர் | விலை | கால அளவு |
|---|---|---|---|---|
| `monthly` | alipay-monthly | மாத உறுப்பினர் | ¥6.99 | 30 நாட்கள் |
| `quarterly` | alipay-quarterly | காலாண்டு உறுப்பினர் | ¥19.99 | 90 நாட்கள் |
| `yearly` | alipay-yearly | ஆண்டு உறுப்பினர் | ¥69.99 | 365 நாட்கள் |

### இடைமுக ஒப்பந்தம் (skill ஸ்கிரிப்டில் ஏற்கனவே மூடப்பட்டுள்ளது, agent நேரடியாகக் கோரிக்கை உருவாக்காது)

| இடைமுகம் | முறை | விளக்கம் |
|---|---|---|
| `/api/payment/alipay/create-order` | POST | `Authorization: Bearer <JWT>` தேவை (pending பயனரும் போதும்). body `{package}` → `{paymentHtml, outTradeNo, amount, planName}` திரும்பும்; `paymentHtml` அலிபே நுழைவாயிலுக்கு தானாக சமர்ப்பிக்கப்படும் படிவப் பக்கம் |
| `/api/payment/alipay/query` | GET `?outTradeNo=` | அதே Bearer அங்கீகாரம். `paid` / `pending` / `closed` / `unknown` திரும்பும் |
| `/api/payment/alipay/notify` | POST (அலிபே சேவையக கால்பேக்) | ஐந்து முக்கிய கூறுகள் சரிபார்ப்பு (கையொப்பம், app_id, தொகை பொருந்துதல், TRADE_SUCCESS/TRADE_FINISHED, வணிகர் தனித்தன்மை) → **இடெம்போடென்ட்** முறையில் ஆர்டர் புதுப்பிப்பு + சந்தா உருவாக்கம் + கணக்கு செயல்படுத்தல். skill இந்த இடைமுகத்தை ஒருபோதும் தொடாது |
| `/payment/alipay/return` | உலாவி திரும்பும் பக்கம் | பொதுப் பாதை, பணம் செலுத்திய பின் 「支付成功」 (பணம் செலுத்துதல் வெற்றி) உறுதிப்படுத்தல் காட்டப்படும், பக்கத்தினுள் பின்புறத்தின் உண்மையான நிலையைப் போலிங் செய்யும் |

- பணம் செலுத்தப்படாத ஆர்டர் **2 மணி நேரத்தில் தானாக மூடப்படும்**; பயனர் இடையில் கைவிட்டால் → நேரடியாக மீண்டும்
  `create-order`, பழைய ஆர்டரைப் பற்றிக் கவலைக்கிடமில்லை.
- ஸ்கிரிப்ட் `paymentHtml` ஐ தற்காலிக HTML கோப்பில் எழுதும், agent கணினி கட்டளையால் திறந்தால் அலிபே பணம்
  செலுத்தும் பக்கத்திற்குள் நுழையலாம் (QR ஐ ஸ்கேன் செய்தோ அலிபேவில் உள்நுழைந்தோ பணம் செலுத்துதல்).

### செயல்படுத்தல் சங்கிலி (தானாக, கைமுறை தேவையில்லை)

notify சரிபார்ப்பு வெற்றி → `paymentOrders` பணம் செலுத்தப்பட்டதாகக் குறிக்கப்படும் → `user_subscriptions`
உருவாக்கம்/நீட்டிப்பு (`planId`, `currentPeriodEnd` durationDays அடிப்படையில் கணக்கிடப்படும், புதுப்பித்தால்
அசல் காலாவதி நாளிலிருந்து முன்னோக்கி நீட்டிக்கப்படும்) → `users.accountStatus: active` +
`subscriptionStatus: ACTIVE` → திரும்பும் பக்கம் paid ஐப் பெற்று வெற்றியைக் காட்டும்.

### பணம் செலுத்திய பின் புதிய உள்நுழைவு நிலை பெறுவது கட்டாயம் (முக்கியம்)

JWT இல் சந்தா அறிவிப்பு இருக்கும் (pending கணக்கில் `NONE`). **பணம் வருகை DB ஐ மட்டுமே புதுப்பிக்கும், ஏற்கனவே
வழங்கப்பட்ட JWT ஐ மாற்றாது** — பழைய token இன் அறிவிப்பு இன்னும் NONE தான்; அதைக் கொண்டே உள்நுழைவு இணைப்பு
உருவாக்கினால் "உறுப்பினர் இல்லை" என்று தோன்றும். எனவேதான் skill `paid` உறுதியான பின் முதலில் `refresh-login`
இயக்குகிறது (மீண்டும் உள்நுழைந்து புதிய JWT, அறிவிப்பு ACTIVE ஆகும்), பின் இணைப்பு 2 ஐ உருவாக்குகிறது.
இது வடிவமைக்கப்பட்ட நடத்தையே, பிழை திருத்தம் அல்ல.

## சந்தாப் பக்கத்தின் நான்கு தடங்கள்

சந்தாப் பக்கம் `src/app/(public)/subscription/page.tsx` இயக்க சூழலுக்கேற்ப காட்டும்:

| தடம் | சூழல் | வடிவமைப்பு | செயல்படுத்தல் முறை |
|---|---|---|---|
| **அலிபே (முதன்மை)** | இணையப் பக்கம் | `AlipayPaymentSection` vibepay இடைமுகங்களைப் பயன்படுத்தும் (மேலே உள்ள அட்டவணை) | notify மூலம் சேவையகத்தில் தானாக செயல்படுத்தப்படும், வினாடிகளில் |
| PayPal சந்தா | இணையப் பக்கம் (ஹார்மோனி அல்லாத) | `/api/subscription/create` → PayPal அங்கீகாரத்திற்குச் செல்லும்; மாதம் தானாகப் புதுப்பிக்கும், எப்போது வேண்டுமானாலும் ரத்து செய்யலாம் (`/api/subscription/manage`) | PayPal Webhook (`BILLING.SUBSCRIPTION.*`) தானாக active ஆக்கும் |
| வீசாட் QR சந்தா | இணையப் பக்கம் (ஹார்மோனி அல்லாத) | பக்கத்தின் கீழ் 「微信扫码订阅」 (வீசாட் QR ஐ ஸ்கேன் செய்து சந்தா): QR ஸ்கேன் மூலம் பணப்பரிமாற்றம் | **கைமுறை உறுதிப்படுத்தல்**, பணம் வருகை தாமதமாகலாம்; பணம் செலுத்தியதும் உடனே தோல்வி என்று முடிவு செய்ய வேண்டாம் |
| ஹுவாவே செயலிக்குள் வாங்குதல் | ஹார்மோனி செயலிக்குள் | நேட்டிவ் `NativeBridge.purchaseSubscription()` | `/api/subscription/activate-huawei` ஹுவாவே ஆர்டரைச் சரிபார்த்த பின் செயல்படுத்தும் |

PayPal திட்டங்களும் விலைகளும் `/api/subscription/plans` இலிருந்து மாறும் விதத்தில் படிக்கப்படும்; பக்கத்தின் நிலையான
உரை: Auto-renews. Cancel anytime.

## நிலைகளும் திசைமாற்றங்களும்

- அலிபேவில் பணம் செலுத்தி முடிந்ததும் → திரும்பும் பக்கம் வெற்றியைக் காட்டும்; PayPal வெற்றி → `/subscription/success`
  → கணக்கு active → `next` அளவுருவில் குறிப்பிடப்பட்ட அசல் பக்கத்திற்குத் தானாகத் திரும்பும் (இல்லை என்றால் முதன்மைப் பக்கம்).
- ஏற்கனவே சந்தா உள்ள பயனர் மீண்டும் சந்தாப் பக்கத்திற்கு வந்தால் → "You're All Set!" காட்டி 3 வினாடிகளில் தானாக
  முதன்மைப் பக்கம் திரும்பும்.
- பணம் செலுத்துதல் தோல்வி/ரத்து (PayPal) → `/subscription/cancel`, மீண்டும் தொடங்கலாம்.

## வரலாற்றுக் குறிப்பு

குறியீட்டில் இன்னொரு **பழைய** அலிபே இணையப் பணம் செலுத்தும் அமைப்பும் உள்ளது (`src/lib/alipay.ts`,
`/api/payment/create-order`, ¥9.90/¥99 ஒருமுறை வாங்குதல், சாண்ட்பாக்ஸில் key இல்லாதபோது போலி பணம் செலுத்துதலுக்குத்
தரம் தாழும்) — எப்போதும் சந்தாப் பக்க UI இல் இணைக்கப்படவில்லை, vibepay க்குத் தொடர்பில்லை. skill எப்போதும் அதைத்
தொடாது; `alipay-vibepay.ts` தான் தற்போதைய தடம்.

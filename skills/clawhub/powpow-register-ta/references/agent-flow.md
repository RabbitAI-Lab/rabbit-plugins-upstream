# Agent முகவர் செயல்முறை மற்றும் ஸ்கிரிப்ட் ஒப்பந்தம் — powpow-register

SKILL.md இல் உள்ள ஒவ்வொரு படியின் செயலாக்க விவரங்கள். அனைத்து கட்டளைகளும் `node scripts/powpow-register.mjs <துணைக்கட்டளை> [அளவுருக்கள்]` வடிவத்தில்;
ஸ்கிரிப்ட் **பூஜ்ஜிய சார்புநிலை**, **Node ≥ 18** தேவை, அனைத்து கோரிக்கைகளும் `https://global.powpow.online` மட்டுமே அனுப்பப்படும்.

## பாதுகாப்பு வடிவமைப்பு (ஏன் இப்படி வடிவமைக்கப்பட்டுள்ளது)

| வடிவமைப்பு | காரணம் |
|---|---|
| கடவுச்சொல் சூழல் மாறி `POWPOW_REGISTER_PASSWORD` வழியாக மட்டுமே உள்ளே செல்லும் | செயல்முறையின் கட்டளை வரி அளவுருக்கள் அதே இயந்திரத்தின் மற்ற செயல்முறைகளுக்குத் தெரியும் (argv கசிவு மேற்பரப்பு), சூழல் மாறியை ஸ்கிரிப்ட் படித்து உடனடியாகப் பயன்படுத்துகிறது |
| கடவுச்சொல் **நிலைக் கோப்பில் ஒருபோதும் எழுதப்படாது**, பதிவுகளிலும் வராது | நிலைக் கோப்பு வட்டில் எஞ்சியிருக்கலாம்; உரையாடலில் உருவாக்கும் முறையில் ஒரு முறை மட்டும் காட்டுவது பயனர் சேமிப்பதற்காக |
| நிலைக் கோப்பு கணினியின் தற்காலிக அடைவில் (`os.tmpdir()/powpow-register-state.json`, 0600) | email / username / nickname / token / outTradeNo என ஐந்து புலங்கள் மட்டுமே, `cleanup` ஒரு கிளிக்கில் அழிக்கும் |
| agent பெறும் JWT அதிகாரப்பூர்வ `me?token=` முனைப்புள்ளி வழியாக உலாவி cookie ஆக மாறும் | ஹார்மோனி WebView க்காக தளம் வடிவமைத்த அதிகாரப்பூர்வ பாலம்; கையொப்ப சரிபார்ப்பு கையொப்பம்+செல்லும் காலம் மட்டுமே பார்க்கும், சாதன ரேகையுடன் இணைக்கப்படாது, பயனரின் உலாவியில் வேலை செய்யும் |
| பணம் செலுத்துதல் create-order / query / பணம் செலுத்தும் பக்கத்தைத் திறப்பது மட்டுமே | பணம் செலுத்தும் செயலும் பணம் செலுத்தும் சான்றுகளும் எப்போதும் பயனருக்கும் அலிபேவின் அதிகாரப்பூர்வ பணம் செலுத்தும் பக்கத்திற்கும் இடையிலேயே, agent தொட மாட்டாது |

## கட்டளை குறிப்பு

| கட்டளை | முக்கிய அளவுருக்கள் | செயல் / நேரம் |
|---|---|---|
| `status` | —— | செயல்முறை முன்னேற்றத்தைப் பார்ப்பது (நிலைக் கோப்பைப் படித்தல்); உரையாடல் தடைபட்ட பின் முதலில் இதை இயக்குங்கள் |
| `gen-password` | —— | 24 எழுத்து வலுவான கடவுச்சொல் உருவாக்கம் (பெரிய+சிறிய எழுத்து+எண் உட்பட), stdout இல் **இந்த ஒரு முறை மட்டுமே** காட்டப்படும் |
| `prepare-suggest` | `--username --nickname --email` | உறுதிப்படுத்திய தகவலை நிலைக் கோப்பில் பதிவு செய்தல் (பின்னர் register இல் மீண்டும் தரத் தேவையில்லை) |
| `send-code` | `--email` | 6 இலக்கச் சரிபார்ப்புக் குறியீட்டை தளம் அனுப்பும்படி ட்ரிகர் செய்தல் (10 நிமிடம் செல்லும், 60s குளிர்விப்பு) |
| `register` | `--code` (கட்டாயம்); `--username --nickname --avatar --phone` (விருப்பம், நிலைக் கோப்பில் இருந்தால் தரத் தேவையில்லை) | pending கணக்கை உருவாக்குதல்; கடவுச்சொல் `POWPOW_REGISTER_PASSWORD` சூழல் மாறி வழியாக; வெற்றியானதும் JWT தானாக நிலைக் கோப்பில் சேமிக்கப்படும் |
| `login-link` | `--target pending` அல்லது `--target home` | ஒரு-கிளிக் உள்நுழைவு இணைப்பு உருவாக்கம் (இரட்டை இணைப்பு வடிவமைப்பு, கீழே பாருங்கள்) |
| `create-order` | `--package monthly\|quarterly\|yearly` (இயல்பு அலிபே)<br>`--provider alipay\|paypal` | பணம் செலுத்தும் ஆர்டரை உருவாக்கும்; அலிபே பணம் செலுத்தும் பக்கக் கோப்புப் பாதை + outTradeNo திருப்பும்; PayPal ஒப்புதல் பக்கக் கோப்புப் பாதை + subscriptionId திருப்பும் (தானாக நிலைக் கோப்பில் பதிவாகும்) |
| `query` | —— | ஆர்டர்/சந்தா நிலையை விசாரிக்கும். அலிபே: `paid / pending / closed / unknown`; PayPal: `ACTIVE / PENDING`; 10–15s போலிங் |
| `refresh-login` | கடவுச்சொல் சூழல் மாறி வழியாக | மீண்டும் உள்நுழைந்து **புதிய JWT** பெறுதல் (சந்தா அறிவிப்பு NONE இலிருந்து ACTIVE ஆகும்), பணம் வந்த பின் கட்டாயம் இயக்கவேண்டும் |
| `whoami` | —— | நிலைக் கோப்பின் token கொண்டு கணக்கு மற்றும் சந்தா நிலையை விசாரிப்பது (செயல்படுத்தல் நடைமுறைக்கு வந்ததா என்று சரிபார்க்க) |
| `cleanup` | —— | நிலைக் கோப்பை நீக்குதல் (முடிவுப் பணியில் கட்டாயம் இயக்கவேண்டும்) |

**சூழல் மாறி வழியாக அனுப்புதல்** (கடவுச்சொல் எப்போதும் கட்டளை வரிக்கு வராது):

```bash
# bash / zsh / WSL
POWPOW_REGISTER_PASSWORD='<கடவுச்சொல்>' node scripts/powpow-register.mjs register --code 123456
# PowerShell
$env:POWPOW_REGISTER_PASSWORD = '<கடவுச்சொல்>'; node scripts/powpow-register.mjs register --code 123456
# cmd
set POWPOW_REGISTER_PASSWORD=<கடவுச்சொல்> && node scripts/powpow-register.mjs register --code 123456
```

## இரட்டை இணைப்பு வடிவமைப்பு (மைய வடிவமைப்பு)

தளத்தின் உள்நுழைவு நிலை HttpOnly cookie; agent உலாவிக்காக நேரடியாக cookie நடப்பிக்க முடியாது; பாலம் அதிகாரப்பூர்வ
`/api/auth/me?token=<JWT>&redirect=<தளத்திற்குள்ளான பாதை>` முனைப்புள்ளி: கையொப்ப சரிபார்ப்பு → pending பயனருக்கு
தானாக session உருவாக்கம் → `Set-Cookie: powpow_token` (HttpOnly / SameSite=Lax / 7 நாட்கள்) → redirect
சரிபார்ப்பு (ஒரே ஒரு ஸ்லாஷில் தொடங்கவேண்டும், `//` மற்றும் பின்சாய்வு ஸ்லாஷ் தடை, பாகுபடுத்திய பின் ஒரே மூலமாக
இருக்கவேண்டும்) → 307 தற்காலிக திசைமாற்றம் இலக்குப் பக்கத்திற்கு.

- **இணைப்பு 1 (பதிவு வெற்றியானதும் உடனே கொடுங்கள்)**: `--target pending` → `/subscription` இல் இறங்கும்.
  பயனரின் உலாவி "அரை-உள்நுழைவு" நிலைக்குள் நுழையும்: சந்தாப் பக்கம், அலிபே திரும்பும் பக்கம் காணப்பட்டு
  இயக்கக்கூடியதாக இருக்கும்; உள்ளடக்கப் பக்கங்கள் இன்னும் பணம் செலுத்தும் சுவரால் சந்தாப் பக்கத்திற்கே தடுத்து
  அனுப்பப்படும் (மூன்று அடுக்கு பாதுகாப்பு: JWT claims நுழைவாயில் சோதனை → DB மறுசோதனை → மைய API சோதனை, இயல்பான
  நடத்தையே).
- **இணைப்பு 2 (paid உறுதியான பின் கொடுங்கள்)**: முதலில் `refresh-login` கொண்டு புதிய JWT பெறுங்கள் (பணம் செலுத்துதல்
  DB ஐ மட்டுமே புதுப்பிக்கும், ஏற்கனவே வழங்கப்பட்ட JWT இன் claims ஐ மாற்றாது; புதியது பெறாவிட்டால் "பணம்
  செலுத்தியும் உறுப்பினர் இல்லை" என்று தோன்றும்), பின் `--target home` → முதன்மைப் பக்கத்தில் இறங்கும்,
  முழு உறுப்பினர் நிலையுடன்.

## முழு நேரவரிசை (இயல்பான பாதை)

```
1.  status                          # சூழல் சுய சோதனை
2.  (படி 2 இல் உரையாடல் மூலம் தகவல் உறுதிப்படுத்தல், கடவுச்சொல் இரண்டில் ஒன்று; உருவாக்கும் முறை: gen-password → பயனரை உடனே சேமிக்கச் சொல்லுங்கள்)
3.  prepare-suggest --username U --nickname N --email E
4.  send-code --email E             # → பயனர் மின்னஞ்சலில் குறியீட்டைப் பார்ப்பது (உரையாடலை விட்டு வெளியேறும் ஒரே பகுதி ①)
5.  POWPOW_REGISTER_PASSWORD=*** register --code 123456 [--avatar pic.jpg]
6.  login-link --target pending     # → இணைப்பு 1 பயனருக்கு அனுப்பப்படும்
7.  (பயனர் பணம் செலுத்தும் முறையைத் தேர்ந்தெடுத்தல்)
    # அலிபே: create-order --package monthly|quarterly|yearly
    # PayPal: create-order --provider paypal
8.  start <பணம் செலுத்தும் பக்கக் கோப்பு>  # Windows; macOS இல் open, Linux இல் xdg-open
    # → பயனர் அலிபே/PayPal பணம் செலுத்தும் பக்கத்தில் பணம் செலுத்துதல்/ஒப்புதலை முடிப்பார் (உரையாடலை விட்டு வெளியேறும் பகுதி ②)
9.  query (ஒவ்வொரு 10–15s) paid / ACTIVE வரும் வரை
10. refresh-login                   # ACTIVE அறிவிப்புள்ள புதிய JWT
11. login-link --target home        # → இணைப்பு 2 பயனருக்கு அனுப்பப்படும்
12. whoami                          # subscriptionStatus: ACTIVE உறுதிப்படுத்தல் (விருப்பம்)
13. cleanup                         # நிலைக் கோப்பை சுத்தம் செய்தல்
```

## கட்டளை → தள API வரைபடம்

| ஸ்கிரிப்ட் கட்டளை | தள இடைமுகம் |
|---|---|
| `send-code` | `POST /api/auth/register/send-code` |
| `register` | `POST /api/auth/register` (multipart, சுயவிவரப் படம் நேரடிப் பதிவேற்றம்) |
| `login-link` | `GET /api/auth/me?token=…&redirect=…` (இணைப்பு அதுவே; உலாவியில் கிளிக் செய்யும்போது வேலை செய்யும்) |
| `create-order` | `POST /api/payment/alipay/create-order` (Bearer, அலிபே)<br>`GET /api/subscription/plans` + `POST /api/subscription/create` (Bearer, PayPal) |
| `query` | `GET /api/payment/alipay/query?outTradeNo=…` (Bearer, அலிபே)<br>`GET /api/subscription/create` (Bearer, PayPal) |
| `refresh-login` | `POST /api/auth/login` (`{step:1, username, password}`) |
| `whoami` | `GET /api/auth/me?token=…` |

விதிகளின் மூல ஆதாரம்: பதிவு புலங்களும் வீத வரம்பும் `registration-flow.md` இல்; திட்டங்களும் செயல்படுத்தல்
சங்கிலியும் `payment-and-activation.md` இல் (இரண்டிலும் தளத்தின் மூல குறியீட்டு கோப்புகள் குறிப்பிடப்பட்டுள்ளன).

## திரும்பும் முறை (தூய வழிகாட்டுதல்)

கீழ்க்காணும் எந்தவொரு நிலையிலும் உடனடியாக v1 பாணியான தூய வழிகாட்டுதலுக்குத் திரும்புங்கள், ஸ்கிரிப்டை மேலும் சிரமப்படுத்த வேண்டாம்:

- Node ≥ 18 இல்லை, அல்லது ஸ்கிரிப்ட் தொடர்ந்து இரண்டு முறை அதே வகையில் தோல்வியுற்றது;
- பயனர் "நானே இணையப் பக்கத்தில் செய்கிறேன்" என்று தெளிவாகச் சொன்னார்;
- நிறுவனம்/சாதனக் கொள்கைகள் ஸ்கிரிப்டின் பிணைய அணுகலைத் தடை செய்கின்றன.

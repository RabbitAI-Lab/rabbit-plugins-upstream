# 三个问题的回答模板

拿到 `fetch_repo.py` 输出的元数据 + README 后，按下面的格式生成回答。

## 一、输出格式（Markdown）

（1）严格按照如下格式和要求输出。

（2）中英文、数字之间加空格；中文语境用全角标点。

```markdown

### 最近 X 月大厂最新热门仓库：owner/repo

> **筛选条件：最近 X 月创建，stars > N，且在未输出候选中 stars 最多**
> **执行状态：候选：total，已输出：total，未输出：total**

### 一、仓库信息

- **名称**：owner/repo
- **Stars**：N
- **主语言**：X
- **创建时间**：YYYY-MM-DD
- **链接**：<url>
- **简介**：description

### 二、这个仓库的项目是什么？

（1）用 1–3 句话讲清楚项目定位、产品/工具类别和目标用户；优先直接回答，避免堆砌 README 原文。

### 三、解决了什么问题？

（1）说明具体痛点场景：用户原来怎么做，以及为什么麻烦、慢、贵或复杂。不要泛泛说“提升效率”。

（2）如有多个痛点，按（1）（2）（3）逐条列出，每条单独成段。

### 四、如何解决？

（1）列出最多 5 条核心实现思路：技术方案、关键设计或差异化，每条单独成段并按（1）（2）…编号。

（2）可从 README 的 Features/Architecture 段抽取；README 未披露时明确写“README 未披露”。
```

## 二、保存要求

（1）回答完成后，将上述完整回答（不含 README 原文）保存为 `assets/history/YYYY-MM-DD-owner-repo.md`，路径以 `fetch_repo.py` 输出提示为准；`--dry-run` 时不保存。

（2）保存文件时，需调整标题格式，使之符合 markdownlint 规范，文件由一个一级标题和若干各二级标题组成。

## 三、回答质量红线

（1）禁止编造 README 未披露的细节。

（2）禁止空泛评价。

（3）引用具体技术名词、文件结构和命令行示例。

（4）README 信息不足时，明确标注“信息有限，基于元数据推断”。

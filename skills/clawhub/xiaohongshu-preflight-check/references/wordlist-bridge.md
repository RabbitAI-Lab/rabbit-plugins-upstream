# 与违禁词库的引用关系

本 skill **不持有词库**。违禁词库的单一真相源是 skill `xiaohongshu-prohibited-words`，
路径 `references/prohibited-words.md`。本 skill 在运行时读它，按下面的映射把它拆进 4 组检查。

## 为什么要拆而不是复制

- 复制一份 → 以后两边会漂移。改了一处忘另一处，是这类工具最典型的失效方式
- 引用一份 → 词库那边加词、降级、出库，本 skill 下次运行自动跟上

代价是**多一个依赖**。所以本 skill 把「依赖断了」当成硬故障处理：

| 情况 | 行为 |
|---|---|
| 找不到词库 | 第 1 组无结果 + **退出码 3**（不是 0） |
| 词库存在但解析出 0 条规则 | **退出码 3** —— 说明格式变了 |
| 缺少某个 `## N、` 段 | 记进 errors → **退出码 3** |
| 同名规则命中同一位置 | 按 span 去重，同级取先到的 |

**核心原则**：词库读不到时，绝不返回「通过」。
一条发布前的闸门如果会静默放行，它就不该被信任。

## 段落映射

映射写在 `xiaohongshu-prohibited-words/references/sections.json` → `sections`：

| 词库段 | 归入哪组 | 默认级别 | 说明 |
|---|---|---|---|
| 一、实测硬词 | 组 1 违禁词 | **按表取值** | 表内自带「词 \| 级别 \| 场景 \| 替代」，逐行取 |
| 二、外部平台名 | 组 4 导流 | P1 | 表内无级别列；联系人信息由 `levelOverrides` 提到 P0 |
| 三、极限词 / 绝对化 | 组 1 违禁词 | P1 | 散文清单，可能带「全禁：」前缀 |
| 四、价格 / 营销诱导 | 组 1 违禁词 | P1 | 散文清单 |
| 五、导流 / 私域话术 | 组 4 导流 | **P0** | 散文清单（主动引流，硬红线） |
| 六、账号级禁区词 | 组 1 违禁词 | P2 | 散文清单，**无**「全禁：」前缀 |
| 七、平台强制标注项 | 组 3 强制标注 | — | bullet 列表，**不参与匹配**，只作为「请逐条核对」提醒 |

⚠️ **这张表不在本 skill 里**，也**不再在平台 JSON 里**。它现在是
`xiaohongshu-prohibited-words/references/sections.json` 的 `sections` 字段 ——
**词库的段落级别归词库 skill 管**，本 skill 只是消费者。上面这张表是 2026-09-19 的快照，
**以那份 json 为准**。

另：手机号 / 邮箱 / 扫码 三条补充规则也在同一个 json 的 `extraPatterns` 里，
两个消费方（本 skill 与 `check_prohibited.py`）共用，不各写一份。

## 只取三列

词库文件里带有运营视角的叙述段落。本 skill **只取表格里的「词 / 级别 / 替代建议」**，
散文段的「触发场景」列也只当「依据」原样展示。

原因：本 skill 的定位是**对照公开规范做发布前自查**。凡是被平台自动扫描的产物，
措辞本身会影响判定结果，所以引用面必须收窄到「词 → 改成什么」，
把运营叙述留在它原本的私有语境里。

## 解析逻辑不在这里

本 skill **没有自己的解析器**。解析与匹配在
`xiaohongshu-prohibited-words/scripts/wordlist.py`，运行时按同级 skill 目录载入。

为什么：解析逻辑复制一份 = 下一个漂移点。2026-09-19 之前词库就有两份副本
（脚本内嵌版 + `free-course-share` 的散文表），实测已经漂移 ——
md 标为 P0 的「免费（全文≥2次）」与「答案+PDF+主页群」，脚本一个都没拦住。

## 支持的四类规则写法（解析器在词库 skill 里）

解析器认识词库里实际出现的四种写法，改词库时不用管它是什么形态：

| 写法 | 解析成 |
|---|---|
| `白嫖` | 字面量 |
| `0元 / ¥0` | 多选一（任一命中即报） |
| `免费（全文≥2次）` | 计数型（出现 ≥N 次才报） |
| `官方+免费+拿证（三词连用）` | 共现型（几个词都出现才报） |
| `答案/答案合集 + PDF + 主页群` | 共现型 + 组内多选一 |

另外：散文清单里裸的「最」会被当成**词干**展开成
`最(好\|佳\|优\|大\|小\|便宜\|…)`，而不是字面匹配「最」——
不展开的话每一处「最」都会被误杀，这正是词库自己那条「宁可禁得准，不要滥禁」的意思。

## 逐词调级

同一个单元格里的多个词可以分别定级，在
`xiaohongshu-prohibited-words/references/sections.json` 的 `levelOverrides` 里写：

```json
"levelOverrides": { "微信": "P0", "微信号": "P0", "vx": "P0", "卫星": "P0", "加V": "P0" }
```

用于「外部平台名」这一类：提到 LinkedIn / GitHub / 公众号属于建议项（P1），
但微信号、手机号属于硬红线（P0），两者在词库里同属一段，靠这张表分开。

> **为什么这样分**：联系人信息是硬红线（写出去就是站外导流）；
> 提及平台名是风险偏好，不是硬规则 —— 一律判 P0 会把「公众号」这类
> 正常表述也拦掉，闸门沦为噪音就等于不存在。
> 认为该收紧 → 加一行 override 即可，不用改代码。

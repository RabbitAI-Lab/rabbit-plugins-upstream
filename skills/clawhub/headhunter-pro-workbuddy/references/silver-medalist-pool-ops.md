# Silver Medalist 池运营与人才库数据治理（v28 新增 · 源自 2026-10-26 学习）

> **你的人才库里藏着 60% 的未来雇佣**
> 猎头的独特优势：企业 ATS 里的 silver medalist 属于公司；**猎头库里的 silver medalist 属于顾问本人**

## 一、Silver Medalist 经济学（2026 数据）

| 指标 | 数据 | 来源 |

| ATS/人才库中可雇佣但无人触达的记录占比 | **75%** | Kula |

## 二、三问自检（每季度做一次）

1. 你能拉出过去 12 个月的 **top 100 被动候选人清单**吗？
2. 你上次**有针对性地**（不是群发 nurture）重触达 silver medalist 是什么时候？
3. 你的人才库里有 **silver medalist 专门标签**吗？

> 三问有任一答不上来 = 你的库是墓地，不是管道。

## 三、Silver Medalist 运营 SOP

| 步骤 | 动作 | 关键点 |
|------|------|--------|
| 1. **入职即标记** | 进入终面未录用 = 自动打标 + 记录未录用原因 | 原因分类：薪资 / 时机 / 另有选择 / 客户偏好 / 经验差一档 |
| 2. **专用池分层** | 按"可再激活时间窗"分类 | 3 个月后（原岗位大概率有人不适配/新增需求）/ 6 个月 / 12 个月 |
| 3. **保持热的最低动作** | 定期轻量触达（行业洞察、节日问候、事件祝贺）+ 邀请活动 + 公司/市场动态 | 70% 提供价值、30% 推进职位 |
| 4. **前提：拒信质量** | 体面拒绝 + 给反馈 + 留门 | 见 ai-recruiting-compliance.md 落选反馈 SOP |
| 5. **激活话术** | 引用上次互动细节 = 不是群发的证明 | 见下方模板 |

### 季度扫描流程（新职位进来时的第一动作）
```
新职位 intake 完成
  ↓
① 先查库内 silver medalist（同职能/同行业/相近职级）
  ↓
② 命中 → 检查激活时间窗是否已到 + 未录用原因是否已消解
  ↓
③ 用"引用上次互动"话术触达（不提"你上次被拒"）
  ↓
④ 无命中 → 再启动外部 sourcing
  ↓
⑤ 记录 KPI：silver 激活 vs 新寻访的速度差（预期 3 倍）
```

### 激活话术模板
```
XX，上次虽然没合作成，但我一直记得你 [具体优势/项目细节]。
最近有个 [公司] 的 [职位]，我觉得比上次那个更适合你——
[新亮点：更大平台/更对口方向/薪酬空间]。
有兴趣聊聊吗？就当了解市场，不急着决定。
```

**自动降温规则**：**连续 2 次无响应 → 自动降一个温度层**（Hot→Warm→Cool），减少无效触达、保护关系。

## 五、Pipeline 状态机新增节点：Silver Medalist 池

> **Closed 不是结束**——原状态机在 Closed 后终止，v28 增加回流路径

```
... → Interview → Offer → Closed（入职）
                        ↘ Closed-Lost（未录用）
                             ↓ 24h 内标记 silver_medalist
                          【Silver Medalist 池】
                             ↓ 季度扫描 / 新职位匹配 / 激活时间窗到期
                          Re-activate → Contacted（带引用上次互动话术）
                             ↓
                          正常流程（Screening → Submitted → ...）
```

**状态定义**：
| 状态 | 触发 | 标准动作 | SLA |
|------|------|---------|-----|
| Closed-Lost | 面试通过但未录用 | 24h 内打标 + 记录原因 + 48h 内体面拒信（含留门） | 48h |
| Silver Medalist 池 | 打标完成 | 分配激活时间窗（3/6/12 月）+ 进入季度扫描列表 | — |
| Re-activate | 新职位匹配 / 时间窗到期 | 引用上次互动的个性化触达（禁群发） | 即时 |

## 六、简历入库自动化规则

**收到简历即建档**（不等人提醒、不靠记忆）：
1. 创建 `candidates/公司-职位-姓名-日期/` 目录
2. 生成 `profile.md`（含 v28 新字段：silver medalist / 数据合规 / 出海岗适配）
3. 初始化触达记录表（含响应质量列）
4. 标注入库日期 + 保留到期日（默认 +2 年）
5. 微信/邮件收到简历 → 同一动作触发（微信简历也是简历）

## 七、人才库索引化（Active Memory 思路应用）

> OpenClaw Active Memory 插件范式：记忆从"会话开始时静态加载"→"按需动态检索"

- **问题**：candidates/ 目录变大后，全量读取不可行（上下文开销）
- **做法**：维护一个轻量索引文件 `candidates/INDEX.md`，只存关键字段
  ```
  | 姓名 | 职能 | 职级 | 温度 | silver | 激活窗 | 保留到期 | 目录 |
  ```
- 新职位来了 → 先查 INDEX（几百行，可全量读）→ 命中后再读具体 profile.md
- 索引更新时机：每次新建/更新 profile 时同步（可自动化）
- **温度分层（Hot/Warm/Cool）+ 最近响应**决定跟进频率，而不是"谁最近联系就理谁"

### 高意向精力分配规则
| 温度 | 判定 | 跟进频率 |
|------|------|---------|
| 🔥 Hot | 主动看机会 / 近期深度交流 / 激活窗已到 | 每周 |
| 🌤 Warm | 愿意了解 / 偶有互动 / silver 3-6 月窗 | 每 2-4 周 |
| ❄️ Cool | 观望 / 2 次无响应降温 / 12 月窗 | 每季度 |

> ⚠️ 微信 5000 联系人 ≠ 人脉。20 个活跃关系 > 1000 个被动连接。

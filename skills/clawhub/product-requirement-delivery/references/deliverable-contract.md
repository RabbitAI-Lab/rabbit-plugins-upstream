# 飞书需求文档交付合同

## 唯一正式交付物

产出一份产品确认后的飞书需求文档。它是产品、研发和测试共同引用的业务基线，不附带强制研发 Agent 包或测试 Agent 包。

本地确认版 Markdown仅作为发布、审计和恢复源稿；用户要求时再提供。

## 必须包含

- 需求背景、目标、成功结果和明确的非目标
- 涉及角色、角色目标、可执行操作及禁止操作
- 核心业务场景和用户故事
- 每个关联页面的完整可复制 URL
- 包含浏览器地址栏的路由截图
- 覆盖完整页面结构的原始截图组
- 基于真实页面的改动标注（确有必要时）
- 明确的默认值、合法值、前置状态、修改条件、展示规则、生效时机、历史数据和追溯规则
- 正常流程、异常场景、边界场景及用户反馈
- 范围内、范围外
- 可独立判断通过/失败的验收标准
- 产品决策记录和未验证页面事实

## 不得包含

- 未经仓库验证的数据库表、接口、事件、文件路径或架构事实
- 要求产品经理决定的代码实现、研发拆分、测试计划或用例组织方式
- 与真实系统无关的 UI
- “按需、适当、视情况、正常处理”等无客观条件的规则
- 仅有标注图而没有完整原图和完整 URL 的页面证据
- 把 `Recommended` 或 `Unverified` 写成当前事实

## 飞书排版

- 使用清晰的标题层级和真实编号。
- 表格只用于角色权限、规则矩阵、异常矩阵等可比较信息；长叙述使用段落或列表。
- 图片前写页面名称、完整 URL 和状态；图片后写图注、日期及标注含义。
- 原图在前，标注图在后；长页面按序号连续排列。
- 验收标准保持一条一结果，避免在一个 AC 中混入多个无法独立判断的结果。

## 发布后校验

- 使用飞书读取能力回读文档。
- 检查所有标题、ID、完整 URL 和图片均存在。
- 抽查每条核心规则在异常矩阵和 AC 中有对应结果。
- 如图片上传或正文更新部分失败，修复后再次回读，不交付半成品链接。

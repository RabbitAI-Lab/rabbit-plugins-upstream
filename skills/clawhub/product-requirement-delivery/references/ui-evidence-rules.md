# 真实页面与路由证据规则

## 证据优先级

1. 当前登录态下实际可见并可交互的页面。
2. 用户提供的截图、录屏或附件。
3. 代码仓库中的真实组件与路由。
4. 明确标注为“建议”的低保真示意。

不得用通用后台图、相似系统截图或 Agent 生成的假界面替代真实页面。

## 每个页面必须具备的证据

### A. 路由证据截图

- 截图必须包含浏览器地址栏、完整页面顶部和可识别的页面主体。
- 地址栏应显示当前页面路由；截图不得裁掉地址栏。
- 同时在文档中写出可复制的完整 URL，包括 hash、路径、查询参数名和必要的代表性参数值。
- 如果地址栏视觉上截断 URL，扩大窗口或重新截取；文档中的完整 URL 仍为必填。

### B. 完整页面证据

- 页面不长时，捕获完整页面。
- 页面较长而无法一次完整捕获时，按从上到下顺序连续截图，相邻截图保留约 15%–25% 重叠区域，确保测试人员能还原页面结构。
- 弹窗、抽屉、下拉、空状态、错误态或特定业务状态应单独截图，并同时保留其所属页面上下文。
- 每张图注明页面名称、截图日期、序号和状态，例如“商品管理列表｜2/4｜筛选后”。

### C. 原图和标注图

- 先保存未裁剪的原始证据，再制作标注图。
- 标注图只框出与需求有关的区域，使用虚线框、箭头或注释卡，并明确写“建议新增/调整”。
- 标注图不能代替原始完整截图。
- 不把目标状态标注描述成当前线上事实。

## 路由与隐私

- 路由中的参数名必须保留，便于下游定位场景。
- 账号、手机号、身份证、密钥等敏感信息必须遮罩；脱敏不得裁掉路由结构、页面导航或关键字段关系。
- 若代表性业务 ID 不敏感，可以保留；若敏感，遮罩参数值但保留参数名，并在文字中说明。

## 无法取证的状态

当权限、空数据或业务状态导致页面无法进入时：

- 记录尝试的入口、完整 URL、账号角色和阻碍；
- 将当前布局或控件位置标为 `Unverified`；
- 只定义目标业务行为，不绘制假页面填补空白；
- 将缺失证据列入最终飞书文档的未验证事项。

## 页面调研记录

每个页面至少记录：页面名称、完整 URL、入口路径、调研日期、账号角色、可见字段、筛选项、状态、操作入口、与需求的差距、路由截图、完整页面截图组和未验证项。

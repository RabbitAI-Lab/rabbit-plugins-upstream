# Hermes mechanics (example harness wiring)

The method above is harness-agnostic. This file records how it maps onto **Hermes Agent** specifically — treat it as an example adapter, not part of the method contract. Other harnesses: map the same concepts onto your runtime's delegation/routing config.

- Dispatch: `delegate_task` — background subagents; results re-enter as messages; bounded concurrency; children run at depth 1 (they cannot spawn grandchildren) and cannot ask questions mid-run.
- Route: resolved ONLY from the active `delegation` block in your Hermes config (task-object `model`/`provider` fields do NOT override it). The config is the single source of truth; this skill names no models — pick them via "Model selection (route card)".
- Batch route switch (temporary per-batch override) — 6 steps: record the previous `delegation` block → set `delegation.model` / `delegation.provider` via the supported config surface (never hand-patch the config file) → route smoke (one cheap read-only child reporting its effective model/provider) → run the batch → restore the recorded values → **re-read the config and confirm the restore landed**.
- Reviewer: fresh separate context; read-only brief. Per-role model pinning can only come from the route card + config (the method requires independence, not a specific model).
- Recorded independent-review session (CLI): `hermes chat --query-file <brief.txt> --oneshot -Q -m <reviewer-model> --provider <provider> --source <tag> --run-budget <s>` — the session is stored (find via `hermes sessions list`), so save the brief and output to disk and cite the session id in project records. Name it at launch with `-c "<unique-title>" --create-if-missing` — the title must be unique per run (an existing title RESUMES that thread, breaking reviewer freshness) — or leave it auto-titled and rename after completion. Owner picks the model AND provider — never choose a provider yourself without explicit approval. Have the reviewer state its own limits (AI review ≠ human expert blind review). Trace hygiene: (a) always pass `--in <dir>` and use ABSOLUTE paths in the brief — the run otherwise re-homes into the launching surface's inherited working directory; (b) name output files by purpose; (c) keep a manifest (session id, model, provider, source tag, command, start/end, output sha256); (d) rename auto-titled sessions to a canonical title afterwards; (e) a `--run-budget` cut-off can be resumed (`hermes chat --resume <session_id>`) — re-runs spend money again, confirm cost with the owner first; (f) launch as a background process with a completion notification and let `--run-budget`/`--max-turns` self-terminate; (g) on completion verify the output is real content covering all requested items; (h) treat an in-flight reviewer session as READ-ONLY from every other surface — a stray message soft-interrupts the run and a stop action kills it, losing the output; recover via resume.

# 看板 SOP JSON Schema

`scripts/render_dashboard.py` 吃一份**固定版式的 SOP JSON**，吐一张看板长图。本文件说明字段含义，以及「怎么从一份 tracker 报告把它重排出来」。

样例见 `assets/intraday-sample.json`（盘中）。**本 skill 只做盘中**——标题 / 页脚 / 数据时间一律「盘中」口径，不出现「盘后」「收盘复盘」。

---

## 顶层字段

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `title` | str | 看板大标题，如「A股盘中热点追踪日报」 |
| `date` | str | 日期行，如「2026.10.09 星期五」 |
| `chip_line1` | str | 右上角胶囊第 1 行，固定「本报告为 AI 自动生成」 |
| `chip_line2` | str | 右上角胶囊第 2 行，固定「不构成任何投资建议」 |
| `chain` | str[] | 顶部深蓝决策链，如 `["数据校验","热点扫描","催化拆解","资金识别","盘中结论"]` |
| `footer_left` / `footer_right` | str | 页脚左右两段（左=来源说明，右=免责） |

> **盘中口径（硬规则）**：`title` 固定「A股盘中热点追踪日报」；`footer_left` 形如「全天候盯盘助手 · 盘中 SOP 输出（数据基于 <日期> 实盘信息整理）」。全篇**禁止**出现「盘后」「收盘复盘」等字样。

## `check`（0. 数据校验）

| 字段 | 说明 |
|:---|:---|
| `rows` | `[[键, 值], ...]` 的 KV 行。典型键：数据时间 / 数据可信度 / 采用数据源 / 缺失数据 / 冲突数据 / 可用于分析 |
| `conclusion_label` | 结论框标题，如「数据校验结论」 |
| `conclusion` | 结论一句话 |

> 值等于 `高` / `中` / `低` 时渲染器会自动加彩色标签（高=绿、其余=橙）。
>
> **`数据时间` 必须填「报告生成时间」**：取报告头部 HTML 注释里的 `| YYYY-MM-DD HH:MM`（例 `2026-10-12 盘中（报告生成 11:58）`）。**不要**用正文「数据截至 …」那类收盘模版字段。

## `hotspots`（1. 热点扫描｜谁在领涨）

| 字段 | 说明 |
|:---|:---|
| `pill` | 卡片右上角小标签，如「实盘整理」 |
| `head` | 表头，盘中使用 `["板块","涨幅","主力净流入","催化类型","领涨标的"]` |
| `rows` | 表格行，列数须与 `head` 对齐 |
| `strength_label` / `strength_value` / `strength_note` | 底部「热点强度：强（备注）」 |

## `catalysts`（2. 催化拆解｜驱动原因）

| 字段 | 说明 |
|:---|:---|
| `items` | `[{tone, title, desc}, ...]`，按重要性排序，建议 3 条 |
| `items[].tone` | 配色档位：`tonel`（红·最强）/ `tonel2`（橙）/ `tonel3`（灰/蓝） |
| `noise_title` / `noise_desc` | 「噪音过滤」小节（哪些是伪催化、可忽略） |
| `strength_label` / `strength_value` / `strength_note` | 底部「催化强度：…」 |

## `funds`（3. 资金识别｜聪明钱去向）

| 字段 | 说明 |
|:---|:---|
| `head` | 盘中使用 `["方向","涨幅","主力净流入","高度/状态","标签"]` |
| `rows` | 表格行 |
| `conclusion_label` / `conclusion` | 「资金结论：…」 |
| `risk` | 底部红框风险提示（可含 ⚠） |

## `verdict`（4. 结论）

| 字段 | 说明 |
|:---|:---|
| `one_liner` | 居中一句话结论 |
| `focus` | `str[]` 绿框「今日盘面主线」 |
| `risk` | `str[]` 红框「风险提示」 |

---

## 从 tracker 报告重排成 SOP JSON

tracker（`cue-hotspot-tracker`）的原报告结构是「热点概览 / 催化解析 / 新题材 / 前瞻 / 跨界资讯」，**跟看板版式不一样**。所以中间必须有一层「重排」：agent 读报告 → 填进上面的 schema → 落成 JSON。

重排要点：

1. **能直接搬的**：板块名、涨幅、资金流向、领涨标的、催化事件、风险提示——这些报告里基本都有，摘出来即可。
2. **必须模型归纳的（不能声称是报告原文）**：
   - `check`（数据校验：可信度 / 缺失 / 冲突 / 可否用于分析）——报告里没有现成字段，靠模型判断。
   - 各块的 `strength_value` / `strength_note`（热点强度 / 催化强度）——模型评估。
   - `conclusion` / `one_liner` / `focus` / `标签`——模型总结。
3. **合规弱化版硬规则**：**不得**出现 `市场评级（偏多）`、`关注强度上限（60%）`、`看多 / 谨慎 / 防守条件`、`今日不做`、`可加码` 等带买卖倾向的字段。这些在 `盘中.svg` 手绘样例里有，是**刻意不复刻**的。第 4 块只保留客观的「一句话 + 主线 + 风险」。
4. **只做盘中**：本 skill 仅服务盘中——第 1 块「谁在领涨」、第 2 块「驱动原因」、第 3 块「聪明钱去哪」（见样例）。标题 / 页脚 / 数据时间一律「盘中」口径，**禁止**「盘后」「收盘复盘」等写法。

## 渲染

```bash
python3 scripts/render_dashboard.py <sop.json> -o out/<name>.png [--width 1242]
```

- 有 Chrome/Chromium/Edge → 出 PNG（默认宽 1242）。
- 找不到浏览器时，脚本会**自动用默认浏览器打开 HTML**，让用户直接看到成品（终端同时打印路径）。
- 中间产物 HTML 收在 `<图名>.src/` 子目录（调样式用，不交付）；**交付目录只留 PNG**。

# 评分项↔标题映射模板 + 输出纯净规则（scoring_map_template）

> 用途：阶段一生成「评分点覆盖核对表」、阶段二章节编写的统一规范。
> 核心目标：**评分表每条技术评分项 100% 映射到标题树，零遗漏。**

## 一、映射生成规则

1. 逐行读取技术评分表，不遗漏任何技术提案相关评分点（含 0.1 分细项）。
2. 对每条评分项做双重判断：
   - 判断1：是否需通过技术提案内容响应？
   - 判断2：是否 AI 可生成？（排除需人工填写的具体数值、公司专属信息、证明件要求）
3. L1=章、L2=节、L3=可执行动作；标题用动宾短语，简洁合规。
4. **排除项**：报价金额、人员证书编号、业绩合同号、财务报表等 → 不生成标题，提示用户另行提供。

## 二、评分点覆盖核对表（阶段一产出，必须 100% 覆盖）

```markdown
## 评分点覆盖核对表（确认后方可写作）

| # | 评分项原文（照抄招标） | 分值 | 对应章节 | 对应标题 | 覆盖状态 |
|---|----------------------|------|---------|---------|---------|
| 1 | {评分项原文} | X分 | 第X章 | X.1 / X.1.1 | ✅ |
| 2 | {评分项原文} | X分 | 第X章 | X.2~X.3 | ⚠️ 部分 |
| 3 | {评分项原文} | X分 | — | — | ❌ 缺失 |

> 统计：技术评分项共 X 条，X 分；本表覆盖 X 条（100%）
> 存在 ⚠️/❌ → 必须补标题后重生成，禁止进入写作阶段
```

**填写规则**：
- "评分项原文"列：逐字照抄招标，不得改写。
- 一条评分项可对应多个标题（逗号分隔）。
- ✅ 明确覆盖；⚠️ 部分覆盖须注明缺什么；❌ 无对应标题。

## 三、L1/L2/L3 标题树示例

```markdown
# 第X章 {章名}
> 对应评分项：{原文}（XX分）

## X.1 {L2 动宾短语}
> 对应评分细项：{原文}

### X.1.1 {L3 具体执行动作}
> 对应招标要求：{原文}

### X.1.2 {L3 具体执行动作}
```

## 四、输出纯净规则（最高优先级，阶段二强制）

章节正文文件 = 一份人类撰写的技术标。判定标准：**打开文件，任何一句话在回答"写得怎么样"而非"项目怎么做"，即违规。**

| 类别 | 违规示例（禁止出现在正文） |
|------|--------------------------|
| 字数统计 | `## 字数统计`、`约3,200字`、`本文字数`、`全章合计` |
| 完成状态 | `完成报告`、`达标`、`第一轮完成`、`扩展轮次` |
| 章节元数据 | `章节:`、`L3标题数:`、`内容覆盖:` |
| 过程表格 | 列名为`指标\|要求\|实际\|结果`的表 |
| 验证声明 | `字数验证：`、`达标率：` |

**正确做法**：
- 正文文件只写技术标内容（标题/段落/表格/图）。
- 过程信息写入独立的「第X章_完成报告.md」，合并前由主 Agent 统一剥离。
- 字数配额作为写作内部检查（私下计数，不写入正文文件）。

## 五、写作规范（注入每章 Agent prompt）

- 人称：用"项目组将/本方案"，不用"我们/我公司"。
- 量化：承诺/标准/工期用数字，禁"力争/尽量/努力"。
- 表格：按需使用（技术参数/计划/人员），不强行凑数。
- 禁用词：可能、大概、也许、应该、左右。
- 溯源：AI 生成且未取自知库的技术参数/规范/业绩，内联 `⚠️ 需人工核实`。
- 配额：本章目标字数 = 总目标 × (本章评分分 / 技术标总分)；内容充分即达标，不强制下限。

# 安全与合规说明（SECURITY.md）

本文件面向**企业安全/合规评审人员**，说明「企业技能工程台（Enterprise Skills Studio）」的能力边界、已知风险处置，以及企业可落地的管控项。

> 本技能是**通用、跨平台的"元技能"**（用来生产/治理其他企业技能），自身不含任何业务数据、不连接企业内网、不采集凭据。所有代码为纯 Python 标准库实现，零第三方依赖。

## 1. 能力声明（Capabilities）

| 能力 | 边界 |
|---|---|
| 网络（network） | 仅向**固定可信源** `jiwei1122/enterprise-skills-studio` 发起 HTTPS GET 以下载更新归档与版本文件；**不发送任何本地数据**，不连接该仓库以外的任何地址。 |
| 文件系统（filesystem） | 读写严格限制在本技能**自身目录**；绝不访问 `~/.ssh`、`.env` 或任何凭据文件。自更新仅覆盖白名单路径（见 §3）。 |
| 执行（execution） | 仅运行本技能**自带**的标准库 Python 脚本；自更新**只复制文件，绝不执行远程下载的代码**。 |
| 特权（privilege） | 不使用 `sudo`/root，不提权，不读取环境变量或系统凭据。 |
| 自治（autonomy） | 所有写操作与自更新均须**用户显式触发**（`--apply` 默认交互确认，并明确警告将覆盖本地文件）；不做自主决策。 |
| 数据处理（data_handling） | 不采集、不上传、不持久化用户业务数据；分析仅在本机文件内进行。 |

## 2. 自更新（Self-Update）的信任模型

自更新是设计内的受治理能力，采用多层防护：

1. **钉置不可变版本**：默认解析「最新发布标签」（经人工 `git tag`/Release 发布、不可变），而非易变的 `main` 分支，规避"向 main 推恶意代码即被拉取"的供应链投毒。`--ref` 可强制钉置到指定标签。
2. **完整性校验**：归档内含 `SHA256SUMS` 时逐文件校验，不匹配即中止更新（防篡改）。发布流程见 §5。
3. **路径穿越防护**：解包时对归档成员路径做前缀校验，拒绝越界路径。
4. **合并白名单**：仅白名单路径被覆盖/新增，越界文件直接跳过（见 §3）。
5. **可回滚**：`--backup` 先快照当前目录；失败可手动还原。
6. **git 保护**：若技能目录本身是 git 仓库，默认中止以免覆盖工作区（`--force` 可强制）。
7. **确认前置**：`--apply` 默认交互确认，提示文案明确"将覆盖本地技能文件，可能影响其行为"。

## 3. 合并白名单（防越界写入）

自更新只接受以下相对路径被覆盖/新增，归档中任何其他文件**一律跳过**：

```
SKILL.md
VERSION
README.md
LICENSE
CHANGELOG.md
SECURITY.md
references/**
scripts/**
assets/**
```

即便完整性校验被绕过，越界文件也绝不会被写入技能目录。

## 4. 企业可落地的管控项

| 管控项 | 机制 | 作用 |
|---|---|---|
| **禁用自更新** | 环境变量 `ESS_SELF_UPDATE=off` | 彻底关闭写盘更新（检查仍可用），适合强管控环境。 |
| **限定可拉取仓库** | 环境变量 `ESS_ALLOWED_REPOS="a/b,c/d"`（逗号分隔） | 仅允许从这些仓库拉取；未设置则仅允许默认仓库 `jiwei1122/enterprise-skills-studio`。私有化部署时把 `--repo` 指向内部可信源并写入白名单。 |
| **审计日志** | 自更新运行会向 stderr 输出动作摘要（下载引用、变更文件数、是否校验通过） | 可重定向到企业日志采集；建议结合 release 流水线统一审计。 |

## 5. 发布侧完整性校验流程（供维护者）

每次发布新版本到 GitHub 时：

```bash
# 在技能根目录执行，生成 SHA256SUMS
python scripts/update_skill.py --gen-sum
git add SHA256SUMS
git commit -m "chore: 更新 SHA256SUMS (vX.Y.Z)"
git tag vX.Y.Z && git push --tags
```

`SHA256SUMS` 须与发布标签处于同一提交，自更新器据此校验归档完整性。

## 6. 已知风险与处置（回应第三方扫描）

针对 NVIDIA SkillSpector 等扫描器的发现，本技能已做如下处置（详见 CHANGELOG）：

- **存储型 XSS（portal.py）**：门户 HTML/Markdown 生成已对所有元数据字段 `html.escape`，恶意技能无法注入脚本。
- **供应链未钉置**：已钉置到不可变发布标签 + SHA256SUMS 校验。
- **--repo 重定向**：非默认仓库强制警告 + 交互确认；可经 `ESS_ALLOWED_REPOS` 白名单硬性约束。
- **触发宽泛**：自更新默认仅检查，应用需显式 `--apply` 并经确认；触发词已收敛。
- **自我修改（叛变特工）**：属设计内能力，受 §2 七层防护治理，不执行远程代码。
- **吸收 SkillSpector 方法论为自有能力（v1.1.0）**：本技能新增 `scripts/skillsec_audit.py`，借鉴 NVIDIA SkillSpector 公开的 16 类漏洞模式（自有开源实现，不复制其代码或品牌），可对任一技能（含本技能自身）做类 SkillSpector 式静态安全审计，输出「类别/严重度/置信度/证据/发现」报告。这把"被动回应扫描"升级为"主动提供审计能力"，同时其公开分类法也成为本技能自检与发布的参考基线（详见 `references/skill-spector-method.md`）。

## 7. 漏洞上报

如发现安全问题，请通过仓库 Issues 私信维护者，或在本机禁用自更新（`ESS_SELF_UPDATE=off`）后手动升级。

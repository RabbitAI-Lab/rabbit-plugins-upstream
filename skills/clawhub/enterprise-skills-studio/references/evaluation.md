# 技能评测（Evaluation）

> 静态审查（`scripts/review_checklist.py`）只查"写得规不规矩"。**动态评测**查"用起来对不对"——这是质量的另一半。

## 一、为什么需要动态评测

- 描述写得漂亮 ≠ 触发准确、输出正确、边界稳健。
- 改了 prompt/模型/依赖后，可能悄悄退化 → 需要**回归**。
- Agentic 技能（多步、外部系统）更需行为评测，不能只靠感觉。

## 二、评测三件套

| 类型 | 目的 | 例 |
|------|------|-----|
| **应触发 Positive** | 该用时确实用 | "把这批 CRM 线索同步到 ERP" → 命中 lead-sync |
| **不应触发 Negative** | 不该用时不抢 | "帮我写首诗" → 不触发任何业务技能 |
| **边界 Boundary** | 模糊/冲突/缺参数 | "同步一下线索"（没说目标系统）→ 应追问而非瞎猜 |

## 三、评测运行方式

1. 用 `scripts/eval_gen.py` 从 SKILL.md 生成测试用例套件（含占位，需补预期输出）。
2. 由人工或 harness 逐条跑：输入 → 看是否触发目标技能、输出是否符合预期。
3. 记录命中/误触发/边界失败，算**召回率/精确率/边界通过率**。
4. 每次改技能后重跑 → 回归基线不退化（接 `references/evolution.md`）。

## 四、评测自审清单

- [ ] 有应触发/不应触发/边界三类用例，且覆盖核心场景？
- [ ] 用例数 ≥ 3–5（企业级 ≥ 10–20）？
- [ ] 有预期结果，可判定 pass/fail？
- [ ] 建立了回归基线，改动会重跑？
- [ ] Agentic 技能有"失败/降级"行为用例？

# 自更新（Self-Update）方法论

> 对应能力模式 23。让"企业技能工程台"技能在用户说一句"升级一下"时，自动检查并应用自身的最新版本。

## 为什么需要

企业技能是受治理的业务工作流制品。它的能力会持续进化（新脚本、新 reference、新的安全规则）。若每次更新都要求用户手动下载、解包、覆盖，门槛高、易出错。自更新把"升级"本身也工程化：

- **单一可信源**：以固定 GitHub 仓库（默认 `jiwei1122/enterprise-skills-studio`）的**最新发布标签（经人工发布、不可变）**作为唯一发布通道，`VERSION` 文件是版本真相。
- **可重复、可回滚**：更新前可快照备份，失败随时还原；git 仓库自动保护不误覆盖。
- **安全优先**：只解包 + 复制文件，绝不执行远程下载的任何代码；归档做路径穿越校验，且要求根目录含 `SKILL.md` 才认可。

## 版本策略（semver）

- 版本号写在技能根的 `VERSION` 文件（如 `1.0.1`），`SKILL.md` frontmatter 的 `version` 与之保持一致。
- 比较规则：`<local> < <remote>` → 有更新；相等 → 最新；本地更高 → 尚未发布，不降级。
- 小版本（patch/minor）走自更新；涉及破坏性变更的大版本，建议人工审阅 `SKILL.md` 变更后再升。

## 更新流程

```
检查(--check) → 获取远程 VERSION → 比较
  ├─ 无更新 → 结束
  └─ 有更新 → 下载归档(.tar.gz) → 解包(路径穿越校验)
       → 预览差异(新增/更新/本地独有) → [可选备份] → 增量合并写盘 → 校验 VERSION
```

- **增量合并**：只覆盖远程有的文件、新增远程新增的文件；本地独有文件（如用户手动加的注记）保留，不删除。
- **dry-run**：`--dry-run` 只打印将变更的文件清单，不写盘，适合 CI / 确认。
- **备份回滚**：`--backup` 把当前目录快照到临时目录并打印路径；出问题把该目录复制回技能目录即可。
- **git 保护**：若技能目录本身是 git 仓库，默认中止（`--force` 可强制），避免覆盖未提交工作区。

## 调用方式

- 自然语言（推荐）：用户说"升级一下 / 检查更新 / 更新本技能" → Agent 运行：
  - `studio update --check`（先看有没有更新）
  - `studio update --apply --yes`（确认后应用；或先 `--dry-run` 给用户看差异）
- 直接脚本：
  - `python scripts/update_skill.py --check --json`
  - `python scripts/update_skill.py --apply --backup --verbose`

## 安全与治理边界

- 更新源**默认钉置到固定可信仓库的最新发布标签（不可变）**，不接受任意 URL，避免被诱导拉取不可信代码。
- 整个过程不执行远程脚本；即使是"更新脚本自身"，也只复制文件、不重新执行。
- 发布侧的卡点（`studio gate`）仍应在推送到 `main` 前跑过，保证被自更新拉取的版本是已通过安全+移植双体检的版本。
- **关于 `--repo`（私有化）**：企业内网可 fork 到内部仓库，用 `--repo` 指向内部可信源实现私有化自更新。这是**显式 opt-in**，且受两层约束：① 非默认仓库拉取时脚本会强制告警并要求确认；② 可经环境变量 `ESS_ALLOWED_REPOS` 硬性限定仅允许的白名单仓库，未列入则直接中止。因此不存在"被任意重定向到攻击者仓库"的敞口。

## 安全审查说明（回应 SkillSpector 类扫描）

自更新特性会触发部分安全扫描器的若干维度，下面逐条说明其**设计内的边界与缓解**，便于安全官审阅时直接采信：

- **自我修改（rogue-agent / 自我修改）**：更新脚本确实会改写本技能自身文件，但满足全部约束——① 仅用户显式触发（`--apply`，默认交互确认，非 `--yes` 不自动执行）；② 单一硬编码可信源，不接受任意 URL；③ **只复制文件、绝不执行远程下载的任何代码**；④ 路径穿越校验 + 要求归档内含 `SKILL.md` 才认可；⑤ 可 `--backup` 快照回滚，git 仓库默认保护。因此不属于"叛变"，而是受控的受治理更新。
- **供应链（未钉置依赖 / 外部脚本获取）**：现默认解析**最新发布标签（经人工发布、不可变）**作为更新源，而非易变的 `main` 分支；`--ref` 可强制钉置到指定标签/提交。下载到本地的归档只做"解包+复制"，从不在本地执行，且发布侧须先过 `studio gate` 双体检卡点。如需更高保证，可在企业内网 fork 并私有化 `--repo`。
- **数据外流（外部传输）**：仅向固定可信仓库发起 HTTPS **GET**（下载归档与 VERSION），**不发送任何本地数据、不读取环境变量、不枚举文件系统用于外传**；网络目标唯一且硬编码。
- **特权升级 / MCP 最低特权**：脚本不使用 sudo/root、不提权、不访问凭据；SKILL.md frontmatter 已显式声明 `capabilities`（网络/文件系统/执行/特权/自治/数据处理边界），不存在"万用卡权限"或能力申报不足。
- **过度能动 / 触发滥用**：本技能是被动的工程方法论工具，所有写操作与自更新均需用户显式指令；触发词虽覆盖广，但均对应真实的子能力，无"暗影指令"或"关键词诱导"。自更新默认**仅检查**，`--apply` 才写盘且需确认，并明确警告"将覆盖本地技能文件"。
- **完整性校验（篡改防护）**：归档内含 `SHA256SUMS` 时逐文件校验，不匹配立即中止；合并仅接受白名单路径（`SKILL.md`/`references/*`/`scripts/*`/`assets/*` 等），越界文件一律跳过，即便校验被绕过也无法写入非常规位置。
- **企业管控**：可通过 `ESS_SELF_UPDATE=off` 彻底禁用写盘更新，通过 `ESS_ALLOWED_REPOS` 限定可拉取仓库白名单，满足强管控环境的合规要求（详见 `SECURITY.md`）。

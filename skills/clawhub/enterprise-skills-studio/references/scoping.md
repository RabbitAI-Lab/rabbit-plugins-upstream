# 技能选题与范围界定（Scoping）

> 本篇把经典管理/产业研究框架**作为选题上游的薄透镜**——用来判断"该把哪条业务流做成技能"，**不展开完整框架**（那是战略咨询的活）。对标详见参考文献。

## 一、为什么要先选题

技能也有 ROI 与治理成本（见 `references/roi.md` / `references/lifecycle-ops.md`）。盲目铺技能 = 治理债。选题 = 在动手前用外部视角找**高杠杆流程**。

## 二、三片薄透镜（点到为止）

| 透镜 | 用来回答 | 技能选题启发 |
|------|----------|--------------|
| **价值链 Value Chain**（供→产→销→服） | 哪段活动最费人、最重复？ | 在"支持性活动/主活动"里挑高频、标准化环节做技能（如报销、对账、入档） |
| **PEST**（政经社技） | 外部环境是否利于自动化？ | 监管严的环节要加护栏/HITL；技术成熟的环节可上 Agentic |
| **波特五力**（竞争结构） | 哪类能力是差异化/成本关键点？ | 五力中"买方/供方议价"强的环节，用技能降成本、提响应速度 |

> 这些框架是被广泛引用的管理/战略分析工具（价值链：Porter 1985；PEST：Agile/战略文献；五力：Porter 1979）。本技能只借其"找高杠杆流程"的视角，**不内嵌完整方法论**——深用请另寻战略技能。

## 三、选题工作流（接 ROI → 构建）

```
1. 用价值链画业务流 → 标出高频/高耗时/标准化环节
2. 用 PEST 判可行性与护栏强度（监管严→多 HITL）
3. 用五力判战略优先级（降本/提响应/差异化）
4. 对候选做 ROI 四门槛（references/roi.md）→ 过线才进构建
5. 进设计器五步法（模式 2）→ 厚技能化
6. 发布前查重（references/discovery.md）+ 安全审查（scripts/review_checklist.py）
```

## 四、选题自审清单

- [ ] 用价值链定位了高杠杆环节，而非凭感觉选？
- [ ] 用 PEST 评估了合规/护栏强度？
- [ ] 候选过了 ROI 四门槛？
- [ ] 动手前已查重，确认非重复造技能？

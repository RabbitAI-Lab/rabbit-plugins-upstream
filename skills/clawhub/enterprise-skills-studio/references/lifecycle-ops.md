# 生命周期 Ops 方法论（Lifecycle Operations）

来源：企业技能从规划到退场的端到端治理。用于「生命周期 Ops」能力模式（见 SKILL.md）。本文件是知识层，配合 `scripts/lifecycle_track.py` 做注册表阶段追踪与弃用候选识别。

> 最高准则不变：**厚技能 + 薄 harness**。流程固化进脚本与模板，harness 只调度。

## 何时使用

- 已有 ≥10 个技能，需要统一的阶段/版本/健康度管理
- 出现"谁在用、用得怎样、该不该下线"的问题
- 安全审计要求可追溯每个技能的创建→部署→变更→退场链路

---

## 一、六阶段（含弃用归档）

| 阶段 | 入口条件 | 关键动作 | 产出 | 退场条件 |
|------|----------|----------|------|----------|
| 1 Plan | 命中 ROI 门槛 | 映射流程到角色，窄于广 | 用例卡 | 未过四前提 |
| 2 Create | 用例卡批准 | 套模板写 SKILL.md，禁硬编码 | 草稿技能 | 安全审查不过 |
| 3 Evaluate | 创作完成 | 3–5(企业10–20)条查询，隔离+共存 | 评估报告 | 降召回则阻部署 |
| 4 Deploy | 评估通过 | 版本 pin、签名溯源、留回滚 | 生产版本 | 连续失败 |
| 5 Operate | 上线 | 用量追踪、周期重评、Evolution Log | 运营指标 | 长期低频/负 ROI |
| 6 Deprecate | 触发退场 | 通知依赖方、冻结、归档保留 | 归档记录 | — |

> 第 5→6 的触发见「弃用归档」小节。阶段回退：Deploy 出问题 → 回滚到上一版本（保留 ≥1 版兜底）。

---

## 二、注册表（单一事实源）

每个技能一行（与 governance.md 注册表条目对齐）：

```
| 技能名 | 领域 | 所有者 | 版本 | 阶段 | 依赖 | 评估状态 | 复审周期 | 用法度 | 末次评估 |
|--------|------|--------|------|------|------|----------|----------|--------|----------|
|        |      |        | v0.x | Plan |      | 待审     | 季度     |        |          |
```

以 Git 为唯一可信源；多 surface（管理界面/Code/API）各自独立，须自建同步。

---

## 三、弃用 / 归档（阶段 6）

**触发条件（任一）**：
- 连续 2 个复审周期用法度低于阈值（如周调用 < 1）
- 被新技能替代且迁移完成
- 业务下线 / 合规禁止

**流程**：
1. 标记 `deprecated`，停止新接入（冻结）
2. 通知已知调用方与所有者，给 ≥1 个复审周期的过渡期
3. 过渡期满后归档：保留历史（Git 历史 + 归档记录），不物理删除（留审计）
4. 更新注册表状态为 `archived`，Evolution Log 追加退场原因

**原则**：低频 ≠ 立即删；保留可恢复，满足审计与回滚要求。

# 个人技能 → 企业级技能 升级转换器

来源：用户需求（个人技能直接转企业级）+ 人人都是产品经理（技术/规则层）+ Atlan（治理信封）。

## 触发场景

用户已有一份个人 SKILL.md（可能只是 markdown 经验、或爱好者写的技能），希望升级为**受治理、可审计、可分发**的企业级技能。本文件给出升级清单与产出规范。

## 升级清单（逐条对照，缺哪项补哪项）

1. **命名规范化**：`{领域}-{动作}`，统一前缀，便于注册表检索
2. **结构补全**：补齐四层（指令/知识/工具/示例），尤其补**示例层**（质量上限）
3. **技术/规则层拆分**：识别哪些需工程落地、哪些业务可写，明确归属
4. **厚技能化**：把隐性经验沉淀为脚本/模板/决策树/校验逻辑（见 `references/principles.md`）
5. **安全审查**：跑 8 项 + CISO 5 风险（AST10）；硬编码凭据外置；沙箱验脚本
6. **作用域隔离**：明确谁可调、哪些敏感数据不可触
7. **治理信封**：加注册表条目（owner / 版本 / 依赖 / 评估状态 / 复审周期）
8. **审计与回滚**：生产 pin 版本、Git 为唯一真源、Evolution Log
9. **分发渠道**：选组织级上传 / 插件+分组 / 内部目录 / 代码库 / API 之一
10. **四前提自检**：作用域隔离 / 技能审计 / 技能自定义 / 成本控制

## 输出

基于 `assets/SKILL.md.template`（企业模式）生成升级版 SKILL.md + 治理件，并附**差异说明**：从个人版补强了哪些项（结构/厚技能/安全/治理）。

## 常见个人→企业差距

| 维度 | 个人技能 | 企业级技能 |
|------|----------|------------|
| 示例 | 常缺 | 必含 应/不应/边界 |
| 安全 | 无审查 | 8项+CISO5 全过 |
| 治理 | 无 owner/版本 | 注册表+pin+回滚 |
| 厚薄 | 常靠 harness 提示 | 逻辑固化在技能内 |
| 隔离 | 全局可读 | 作用域/角色限定 |

# 持续进化参考

来源：腾讯云《企业级 Skill 持续进化的完整指南》。说明企业级 Skill 是"活系统，越用越懂你"，企业模式推荐采用。

## 一、核心转变

从"写好就用"到"越用越好"：被动等待 → 主动发现；手动维护 → 智能迭代；个人孤岛 → 知识流动。

## 二、三层价值模型（沉淀层次）

- **个人层**：高频操作沉淀为命令，打造专属助手（如 `/review`）
- **团队层**：从协作中提炼共识，加速团队效率
- **组织层**：知识资产持续增值，新人培养周期缩短

## 三、会话挖掘四步法（从会话中提炼 Skill）

1. **扫描**：遍历历史对话，用 LLM 标记高频模式（重复提示词片段、高频操作序列、反复修正指令）
2. **聚类**：按意图分类（调试/重构/文档/部署…）
3. **提炼**：抽象为标准化工作流（name/description/检查清单）
4. **命名**：生成可记忆命令别名（如 `defensive-check → /defchk`）

## 四、团队开发风格建模（从协作中提炼）

- 流程：`项目完成 → PR/代码分析 → 风格模式提取 → 团队 Skill 生成 → 共享与迭代`
- 三维度识别：代码风格层 / 协作流程层 / 决策模式层
- 示例：分析过去 3 个月 PR（80% 含"影响范围"、75% 含"测试方案"）→ 沉淀 `team-pr-workflow` Skill

## 五、反馈闭环（问题驱动的进化闭环）

核心流程：**问题溯源 → 改进生成 → 安全升级 → 兼容性验证 → 回归使用**
- 触发来源：项目复盘、周度扫描（每周一分析上周会话）、手动触发
- 闭环 Agent 架构：`会话分析器 + 代码风格分析器 + Skill 生成器 + 兼容性验证器`

## 六、迭代机制（安全升级三原则）

1. **增量扩展，非覆盖重写**：保留原要求，新增"增强要求"（如原覆盖率 80% → 新增关键路径集成测试）
2. **变更日志（Evolution Log）**：每个 Skill 末尾维护版本号/日期/变更内容/触发原因
   - 例：`v2.1.0 (2024-03-15) 新增关键路径集成测试要求，触发：项目复盘发现线上 bug`
3. **兼容性验证**：旧场景回归 + 新场景验证 + 边界压力测试

## 七、迭代脚本示例（可借鉴为 scripts/evolve_skill.py）

- 添加检查项：`evolve_skill.py --skill review-checklist --add-check "性能影响评估" --reason "复盘发现性能问题遗漏"`
- 验证格式：`evolve_skill.py --skill review-checklist --validate`

## 八、周度运营节奏（团队落地）

- **启动（第 1 周）**：建目录、分析个人会话、生成 5 个 Skill 提案
- **运行（每周）**：周一扫描 → 周三评审(30min 投票采纳) → 周五发布(验证+提交 Git+通知)
- **复盘**：导出项目会话，用 evolve 增加检查项（如"回滚方案是否明确"）

## 九、分层目录治理（Claude Code 示例）

```
~/.claude/skills/
├── personal/  # 个人（不提交 Git，随时更新）
├── team/      # 团队（Git 共享，每月更新）
└── org/       # 组织（跨团队通用，每季度更新）
```

## 十、效果度量

- 个人：命令化率、提示词减少、耗时下降
- 团队：PR 首次通过率、Review 轮次、新人周期
- 组织：复用率、知识流失率、最佳实践覆盖率
- 积累效应：初期 3–5 个覆盖 60% 高频 → 中期 10–15 个覆盖 80% → 成熟期 20+ 覆盖 90%+

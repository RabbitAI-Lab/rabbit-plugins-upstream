# 流程技能方法论：系统型业务流 × Agentic Workflow × LLM 融合

来源：企业大量 ERP / CRM / HRM / OA 等系统型业务流，叠加 Agentic Workflow 与 LLM 后的技能优化升级方法论。用于「流程技能生成器」能力模式（见 SKILL.md 模式 9）。本文件是知识层，被生成器在产出系统型/工作流型技能时按需加载。

> 最高准则仍不变：**厚技能 + 薄 harness**。流程技能不是"让 LLM 临场编排"，而是把流程的结构、约束、安全闸门、恢复逻辑固化进技能（脚本/模板/校验），harness 只负责发现与调用。

## 何时使用本方法

出现以下信号，应走「流程技能生成器」而非普通设计器五步法：

- 技能要对接 ≥1 个外部系统（ERP/CRM/HRM/OA/数据库/MCP/API 网关）
- 技能内部是多步骤、有先后依赖、可能中断续做的流程（而不仅是单次问答）
- 流程中有"写"动作（创建/更新/删除/提交/审批），需要事务保障
- 需要 LLM 做理解/抽取/生成，但关键决策要落回确定性系统

## 一、系统型业务流优化（System-type Flows）

核心矛盾：企业系统型业务流天然是**确定性、有状态、受治理**的；裸 LLM 是**概率性、无状态、不可控**的。技能要做的，是把前者封装成可被 Agent 调用的"确定性接口面"，把 LLM 关在可控的接缝里。

### 1.1 网关 / 连接器抽象（Connector Abstraction）

**原则**：技能不直接耦合具体系统的 API 细节，而是定义一层"连接器抽象"。

- 在工具层只声明**能力意图**（如 `create_invoice`、`approve_leave`），不写具体 host/endpoint
- 真实调用由连接器层（MCP / 预置 SDK / 网关）完成，技能只传结构化参数
- 好处：换系统（SAP→用友）、换环境（测试→生产）只改连接器，技能不动；符合"厚技能薄 harness"——智能在技能、胶水在外部

模板落点：`## 工具层` 改为连接器声明；具体地址/凭证在治理元数据的作用域隔离里说明。

### 1.2 领域本体（Domain Ontology）

**原则**：先把业务概念建模成共享词汇表，再写流程，避免"同词多义"导致 Agent 误操作。

- 列出流程涉及的核心实体与字段（如 `员工(工号,部门,职级)`、`请假单(类型,起止,审批人)`）
- 明确字段的**来源系统**与**权威系统**（谁是 single source of truth）
- 状态枚举显式化：`草稿/待审/已批/驳回/撤销` 而非"处理中"

模板落点：在知识层新增 `### 领域本体` 段，列出实体、字段、状态枚举。

### 1.3 事务安全四件套（Transaction Safety Quartet）

任何带"写"动作的系统型技能，**四件套缺一不可**，且在 SKILL.md 中显式声明：

| 件 | 含义 | 技能内写法 |
|----|------|-----------|
| ① 幂等（Idempotency） | 同一请求重复提交不产生重复副作用 | 声明幂等键（`idempotency_key` / 业务单号去重）；"重试须安全" |
| ② 回滚（Rollback） | 任一步失败可补偿/撤销到一致状态 | 写补偿步骤或"调用方负责回滚"；明确哪步是**不归点（point of no return）** |
| ③ 审计（Audit） | 谁、何时、对哪条数据、做了什么 | 强制落审计日志（操作/前后值/调用链 ID） |
| ④ 最小权限（Least Privilege） | 技能只持完成本任务所需 scope | 声明所需 RBAC 角色/权限集，禁止继承宿主全部权限 |

> 不归点（PoNR）：流程中一旦越过便无法自动回滚的步骤（如对外发送、财务出账）。PoNR 之前必须完成所有校验与人工确认。

### 1.4 RBAC 与确定性边界（Deterministic Boundary）

- 技能声明**最小角色集**（如 `hr-leave-approver`），由治理层把角色映射到具体人/组
- **确定性边界**：边界内（数据校验、状态机推进、幂等判断）必须是确定性代码/脚本，不允许 LLM 自由发挥；边界外（自然语言理解、摘要、草案生成）才允许概率性
- 跨边界传递的数据必须**结构化**，LLM 输出要先过强 schema 校验再进入边界内

## 二、Agentic Workflow 设计

多步骤、可中断、需恢复的流程，用**状态机**建模，而非让 Agent "想到哪做到哪"。

### 2.1 状态机（State Machine）

- 把流程显式建模为 `状态 → 事件 → 动作 → 下一状态`
- 每个状态有：进入条件、可执行动作、超时/异常去向
- 技能内置"当前状态"的判定逻辑（脚本或显式决策树），不靠 LLM 记忆
- 模板落点：新增 `### 状态机` 段，用表格列出 状态 / 触发事件 / 动作 / 下一状态 / 超时处理

### 2.2 薄编排器 + 厚原子技能（Thin Orchestrator, Thick Atoms）

**原则**：编排层（工作流本身）保持薄——只决定"下一步调谁"；每个原子步骤是**厚技能/厚脚本**，自带校验与确定性。

- 不要在一个巨大技能里写完整流程逻辑；拆成：
  - 一个**薄编排器技能**（状态路由、错误分流、调用原子技能）
  - 多个**厚原子技能**（每个只做一件事，脚本化、可单测）
- 好处：单步可独立测试、可并行、可替换；符合厚技能原则

### 2.3 HITL 门（Human-in-the-loop Gate）

在以下位置强制人工确认，未确认不得越过：

- 不归点（PoNR）之前
- 高影响写操作（出账、发信、删数据、权限变更）
- 置信度低于阈值的 LLM 决策（见 2.3/三.3）

HITL 门的写法：明确"门名称 / 触发条件 / 等待谁确认 / 超时与驳回去向"。

### 2.4 可观测性（Observability）

- 每次调用产出结构化 trace：调用链 ID、各步状态、耗时、输入哈希（非敏感）、输出摘要
- 失败可定位到具体状态/原子技能
- 模板落点：治理元数据里写 `可观测：trace 字段 = ...`

### 2.5 降级策略（Degradation）

外部依赖（LLM、连接器、下游系统）必然失败，技能必须声明降级：

- **超时/重试**：每步超时值与重试上限，避免无限挂起
- **降级路径**：LLM 不可用时转人工/转规则兜底；连接器不可用时排队+告警
- **部分成功**：多步中某步失败，明确已提交部分如何处理（回滚 or 挂起待续）

## 三、LLM 融合设计

LLM 在流程技能里的正确位置：**做概率性的"理解/抽取/生成"，不在确定性"决策/写系统"上裸奔**。

### 3.1 概率–确定性分界（Probabilistic/Deterministic Seam）

- 概率侧：意图识别、文档抽取、草稿生成、摘要、分类
- 确定性侧：状态推进、幂等校验、权限判定、系统写入、金额计算
- 分界处必须有**结构化转换层**：LLM 输出 → 强 schema 校验 → 确定性处理

### 3.2 强 Schema 约束（Strong Schema）

- LLM 的所有输出先经 schema 校验（类型/枚举/必填/范围），失败则拒收或走降级
- 用脚本（`scripts/`）做校验，而非"请模型保证格式"
- 模板落点：知识层/示例层固化 JSON Schema 或字段表

### 3.3 置信闸门（Confidence Gate）

- LLM 对关键字段（如分类、金额、审批建议）输出置信度
- 低于阈值 → 不直接采用，转 HITL 或转规则兜底
- 闸门阈值在技能内显式声明，可按风险级别调（财务类阈值更高）

### 3.4 模板固化（Template Freezing）

- 高频、低风险、格式固定的 LLM 产出（如邮件草稿、工单描述）用**模板 + 插槽填充**而非自由生成
- 模板把"风格/合规/字段"固化，LLM 只填变量；既稳又省 token
- 本质仍是厚技能：把生成逻辑沉淀为模板资产

## 四、实操：把以上固化进 SKILL.md

生成系统型/工作流型技能时，在标准模板（见 `assets/SKILL.md.template`）基础上补：

1. **知识层** 增 `### 领域本体`（实体/字段/状态枚举/权威系统）
2. **工具层** 改为**连接器声明**（能力意图，不含具体地址）
3. 新增 `### 状态机`（状态表）
4. 新增 `### 事务安全`（幂等键 / 回滚 / 审计 / 最小权限 / 不归点）
5. 新增 `### HITL 门`（门名 / 触发 / 确认人 / 超时）
6. 新增 `### 降级与可观测`（超时/重试/降级路径/trace 字段）
7. **LLM 接缝**：声明概率侧与确定性侧；输出过强 schema（脚本校验）；关键决策加置信闸门；固定产出用模板固化
8. 治理元数据补：RBAC 角色集、作用域隔离、跨 surface 同步说明

> 复用设计器五步法（梳理逻辑→材料→生成→测试→治理），只是第 3 步套"扩展段"而非基础模板。

## 五、流程技能自审清单（供审查器调用）

发布前逐条确认（对应 `scripts/review_checklist.py` 的"事务安全 / 工作流可恢复性"检查项）：

- [ ] 是否声明连接器抽象（不直接耦合具体 API）？
- [ ] 是否有领域本体（实体/字段/状态枚举）？
- [ ] 写动作是否四件套齐备：幂等 / 回滚 / 审计 / 最小权限？
- [ ] 是否标出**不归点**且在之前完成校验与 HITL？
- [ ] 是否有状态机（状态/事件/动作/下一状态/超时）？
- [ ] 是否薄编排 + 厚原子（非巨型单技能）？
- [ ] HITL 门是否显式（触发条件/确认人/超时/驳回去向）？
- [ ] 是否声明降级（超时/重试/降级路径/部分成功处理）？
- [ ] 是否可观测（trace 字段）？
- [ ] LLM 输出是否过强 schema 校验？
- [ ] 关键 LLM 决策是否过置信闸门？
- [ ] 固定产出是否模板固化？

> 纯问答/无外部系统/无写动作的技能可整体标 INFO（不适用），不扣分。

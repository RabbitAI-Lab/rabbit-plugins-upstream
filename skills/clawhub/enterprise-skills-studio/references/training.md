# 培训推广包（Training & Adoption Pack）

> 技能不是写给人看的文档，而是给业务人员**用**的制品。再好的技能，没人用就只是治理债。本模块给出试点 + 培训的落地方法，并可用 `scripts/training_pack.py` 一键生成培训包清单。

## 一、推广飞轮

```
选试点场景 → 做最小可用技能 → 业务人员试用 → 收集反馈 → 迭代厚技能化 → 写培训包 → 推广复制
```

不要一次铺开 50 个技能。先在一个**高频、低风险、显成果**的场景跑通，再复制。

## 二、试点选择标准（结合 ROI 筛选，见 `references/roi.md`）

- 频次高、单次耗时长、步骤一致 → 最适合做试点。
- 选"业务人员自己也想自动化"的活儿，别选"领导想推但一线反感"的。
- 试点周期建议 2–4 周，每周一次反馈小会。

## 三、培训包四件套

| 件 | 内容 | 产出 |
|----|------|------|
| **1. 场景卡（Scenario Card）** | 一句话说清"这个技能解决什么、何时用、别用在哪" | 1 页，贴工位/发群 |
| **2. 上手指南（Quick Start）** | 3 步触发 → 看到结果 → 异常处理 | 5 分钟能读完 |
| **3. FAQ** | 业务最常问的 10 个问题（"它会不会乱改我数据？""出错了找谁？"） | 打消顾虑 |
| **4. 反馈单（Feedback Ticket）** | 谁来收反馈、怎么提、多久回应 | 闭环 |

## 四、给不同角色的沟通话术

- **对管理者**：强调"可治理、可审计、不自主跨 surface 操作"（见 `references/governance.md` 四前提）。
- **对业务人员**：强调"不用学提示词，像用 App 一样用；出错有回滚"。
- **对工程师**：强调"厚技能 + 薄 harness，智能在技能内，标准可移植"。

## 五、培训包自审清单

- [ ] 试点场景已用 ROI 门槛筛过？
- [ ] 四件套齐全（场景卡/上手指南/FAQ/反馈单）？
- [ ] 已说明"何时**不**用"与安全边界（事务安全、最小权限）？
- [ ] 有明确的反馈回收与迭代节奏？
- [ ] 试点成功标准已定义（如：节省 X 小时/周，N 人周活）？

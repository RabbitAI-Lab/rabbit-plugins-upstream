# 技能发现与复用（Discovery & Reuse）

> 解决"又要造一个技能"的惯性。在做新技能前，先确认：**已有技能能否复用？是否存在重名/功能重叠？** 避免碎片化与治理债。

## 一、为什么需要发现机制

- 没有注册表/检索，团队会重复造相似的技能（"报销助手""费用机器人""发票流程"三件套）。
- 重名或功能重叠会让 Agent 召回时**歧义**——它不知道该调哪一个。
- 复用率低的技能堆在库里，徒增生命周期 Ops 的维护成本（见 `references/lifecycle-ops.md`）。

## 二、发现三步走

1. **查注册表**：先查企业技能注册表（命名/描述/负责人/阶段），看是否已有同名或同域技能。
2. **语义检索**：用用户意图关键词在 description 上做匹配，找到功能相近候选。
3. **重叠判定**：对候选做「重名检测 + 功能重叠检测」，给出 `复用 / 扩展 / 合并 / 新造` 决策。

## 三、检测维度（实现见 `scripts/dupe_check.py`）

| 检测 | 方法 | 阈值 | 含义 |
|------|------|------|------|
| **name 重名** | 精确字符串比对（小写、去空格、连字符归一） | 完全相同 | 必须重命名或合并 |
| **name 近似** | 编辑距离（Levenshtein） | ≤ 2 | 易混淆，建议统一命名 |
| **description 重叠** | 关键词集合 Jaccard 相似度 | ≥ 0.5 | 功能高度重叠，考虑合并/扩展 |
| **触发词重叠** | 双方 description 共同含的"何时调用"关键词 | ≥ 3 个 | 召回时会竞争，需错开触发域 |

## 四、决策矩阵

| 情形 | 动作 |
|------|------|
| name 完全相同 | ❌ 禁止新造；要么复用已有，要么合并后重命名 |
| name 近似（编辑距离≤2） | ⚠️ 重命名其中一个，避免召回歧义 |
| description Jaccard ≥ 0.7 | 🔁 直接复用已有技能，不新造 |
| 0.5 ≤ Jaccard < 0.7 | 🧩 扩展已有技能（加模式/加参数），而非另起炉灶 |
| Jaccard < 0.5 但触发词重叠 ≥3 | 🎯 收窄各自触发域，写清"何时**不**调用" |
| 全部低于阈值 | ✅ 可以新造，登记进注册表 |

## 五、复用原则

- **优先扩展，而非并排**：技能应「厚」且职责聚焦，但允许同一技能内多模式（见能力模式清单）；不要把一个能力拆成 5 个薄技能。
- **重名即债**：注册表是唯一真源，命名冲突在发布门（见 `references/governance.md` 六阶段）就拦下。
- **触发域错开**：两个相关技能都应在 description 写清边界，特别是"不应触发"的负面例子。

## 六、技能发现自审清单

- [ ] 新技能动笔前，已查注册表与现有技能库？
- [ ] 无 name 重名 / 近似（编辑距离>2）？
- [ ] description 与既有技能 Jaccard < 0.5，或已明确错开触发域？
- [ ] 若功能相近，是否考虑过扩展而非新造？
- [ ] 已在注册表登记（name/描述/负责人/阶段）？

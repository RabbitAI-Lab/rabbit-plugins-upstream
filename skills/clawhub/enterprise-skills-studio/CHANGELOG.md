## [1.1.0] - 2026-08-27

### Added（新增能力：技能安全审计 SkillSec 16 类，模式 24）

借鉴 **NVIDIA SkillSpector** 公开的「16 类漏洞模式」分类法（自有开源实现，不复制其代码或品牌），把"对技能做类 SkillSpector 式安全审计"做成企业技能工程台的一个正式能力：

- **新增 `scripts/skillsec_audit.py`**：纯标准库静态审计器，覆盖 16 类——过度能动 / 输出处理 / 叛变特工 / 触发滥用 / MCP 最低特权 / MCP 工具中毒 / 提示注入 / 数据外流 / 特权升级 / 供应链 / 系统提示漏出 / 记忆中毒 / 工具滥用 / 危险 AST / 污染追踪 / YARA 签名。输出「类别 / 严重度(高·中·低) / 置信度 / 证据 / 发现」报告，支持 `--json` / `--md`，退出码 `1`=存在「高」级发现（可作 CI 卡点）。
- **新增 `references/skill-spector-method.md`**：记载 16 类 taxonomy、与本审计器检测器的映射、置信度/严重度约定、运行方式，并明确"方法论借鉴自 NVIDIA SkillSpector 公开分类，本实现为自有开源代码"的声明。
- **接入 `studio audit` 子命令**：在 `scripts/studio.py` 注册 `audit`，参数透传 `skillsec_audit.py`。
- **与既有 `review_checklist.py` 互补**：`review` 偏治理/质量/AI 安全语义层体检；`audit` 偏"过度能动"视角的 16 类风险审计。两者可同时纳入发布前卡点。

> 说明：本能力**融合而非复制** SkillSpector——吸收其公开分类思想，用自有代码实现，并显式标注借鉴来源，避免许可与商标问题。

### Changed（变更）
- `SKILL.md`：能力模式 23 → **24**（新增模式 24 技能安全审计）；工具脚本 15 → **16**；`version` 升至 `1.1.0`；description 触发词新增"审计扫描某技能的安全性"。
- `README.md` / `VERSION`：对齐至 `1.1.0`；规模计数更新为 24 模式 / 19 份 reference / 16 脚本；新增「技能安全审计：SkillSec 16 类」章节与能力全景条目；目录树补 `skillsec_audit.py`。

## [1.0.3] - 2026-08-27

### Security（企业级安全合规加固，回应 SkillSpector 18 条完整审核）

在 1.0.2 基础上，按"企业级更高安全合规"诉求，对扫描器 18 条发现逐条处置（真高危 1 / 真中危 6 / 低危 5 / 设计内 5 / 误报 2）。本次变更：

- **🔴 存储型 XSS（修复，置信度 98%）**：`portal.py` 生成门户 HTML/Markdown 时，对名称/描述/Owner/版本/状态/路径等全部元数据字段统一 `html.escape`，杜绝恶意技能通过 SKILL.md 注入脚本。
- **🟠 供应链·`--repo` 重定向（修复，置信度 92%）**：非默认仓库拉取时强制告警 + 交互确认；新增环境变量 `ESS_ALLOWED_REPOS` 白名单，未在白名单内直接中止，消除"被诱导重定向到攻击者仓库"敞口。
- **🟠 完整性校验（新增）**：`update_skill.py` 支持 `SHA256SUMS` 逐文件校验，归档不匹配即中止；新增 `--gen-sum` 供发布侧生成校验和（须随标签提交）。
- **🟠 合并白名单（新增）**：自更新仅覆盖白名单路径（`SKILL.md`/`references/*`/`scripts/*`/`assets/*` 等），越界文件一律跳过。
- **🟠 触发收窄 + 确认警告（修复，置信度 93–97%）**：自更新默认**仅检查**，`--apply` 才写盘且确认提示明确警告"将覆盖本地技能文件"；自然语言触发词从"升级一下"收敛为"检查/更新本技能"。
- **🟠 缺失警告（修复，置信度 81–97%）**：`portal.py` 生成后提示"产物含技能元数据，外发前请审查"；`update_skill.py` 确认前提示将修改本地文件。
- **🟡 文案精修（低危）**：`framework.md` 模板增加"触发词须具体带边界、写操作须声明需确认"；`SKILL.md` capabilities 补 `ESS_SELF_UPDATE`/`ESS_ALLOWED_REPOS` 治理说明；自更新描述与 README 示例同步收敛。
- **🟢 自我改造（设计内）**：5 条"自我修改"类发现确认属受控治理能力，并补充 SHA256SUMS + 白名单 + 禁用开关三重加固。
- **⚪ 误报澄清**：2 条"未验证输出注入"（studio.py 的 subprocess）经核查仅为打印子脚本输出，未 eval/未进 shell，非注入向量。
- **新增 `SECURITY.md`**：面向企业安全/合规评审，系统说明能力声明、自更新信任模型、合并白名单、企业可落地管控项（禁用开关/仓库白名单/审计日志）、发布侧校验流程，以及第三方扫描发现的处置对照。

> 注：SkillSpector 报告中"VirusTotal 有待公布"为非代码可控项，建议发布后主动核对并保持透明。

## [1.0.1] - 2026-08-27

### Added（新增）
- **自更新功能（模式 23）**：说一句"升级一下"即可检查并应用本技能自身的最新版本。
  - 新增 `scripts/update_skill.py`：基于可信 GitHub 仓库归档的原子自更新器。
    - `--check` 比对本地 `VERSION` 与远程，输出 `ahead` / `equal` / `behind`（支持 `--json`）。
    - `--apply` 下载归档、增量合并更新本技能目录；失败自动回滚。
    - 支持 `--dry-run`（只预览差异）、`--force`（跨版本也更新）、`--no-backup`、自定义 `--backup-dir`。
    - 信任边界：只从固定仓库 `jiwei1122/enterprise-skills-studio` 下载源码，仅覆盖技能自身目录，不改外部配置/凭据。
    - 企业内网可 `--repo` 指向私有可信源，实现私有化自更新。
  - 新增 `references/self-update.md`：自更新方法论、信任边界、关闭自动拉取的开关说明。
  - `scripts/studio.py` 接入 `update` 子命令（`studio update --check` / `studio update --apply`）。
- 新增 `.gitignore`：忽略 `__pycache__` 与更新备份目录。

### Changed（变更）
- `SKILL.md`：能力模式 22 → **23**（新增模式 23 自更新），工具脚本 14 → **15**，并补充自然语言触发词。
- `README.md` / 介绍文章：对齐至 **v1.0.1**、**23 个模式**、**15 个脚本**，新增「自更新：说一句就升级」章节与核心特点第 9 条。

### Fixed（修复）

# 事实核查 6 类风险分类框架

本文档定义事实核查的 6 类风险分类框架，作为所有审稿 skill 事实核查的共享参考。

> 共享引擎：review-common-core
> 来源：fact-checker/SKILL.md "6 类风险"章节、AGENTS.md "播客/视频脚本审稿必须查事实正确性"章节

## 6 类风险分类

对每一句可能存在事实性问题的陈述，按以下 6 类风险分类：

| # | 风险类型 | 要问的问题 | 示例 |
|---|---------|-----------|------|
| 1 | **数字精确性** | 这个数字能自证吗？有日志/截图支撑吗？ | "平均分从 0.25 提到了 0.61"——这是原文就有还是凭记忆写的？ |
| 2 | **技术概念准确性** | 术语使用准确吗？会不会误导听众？ | "Desirable Difficulties 有五根柱子"——这五根是标准分类还是作者自己的归纳？ |
| 3 | **因果推断** | 因果关系真的成立，还是为了叙事流畅强行连接？ | "因为学习 Agent 教错了，所以知识库有问题"——有没有可能是 Agent 幻觉/检索错误？ |
| 4 | **绝对化表述** | "从来不/根本/永远/所有/任何"有例外吗？站得住吗？ | "几乎没有一个是帮我'学会'的"——可以用"很少"替代"几乎没有" |
| 5 | **记忆模糊风险** | 这个细节是凭记忆写的吗？可能有偏差吗？ | "前几天"、"有一次"、"一段时间"——时间点模糊，要标记 |
| 6 | **应然vs实然** | Agent 说它会做 vs 系统真的做了——能分清吗？ | "图书馆管理员会降置信度、改规则"——这是它在对话里描述的流程，还是系统真的有实现？ |

## 三级严重度标注

| 级别 | 含义 | 处理方式 |
|------|------|---------|
| 🔴 **严重** | 事实错误、编造内容、误导性表述 | 必须先向作者确认，不修复不能发布 |
| 🟡 **中等** | 可能不准确但影响有限，或缺少必要限定 | 标注并给出修改方向 |
| 🟢 **轻微** | 模糊化表达但不影响核心论点 | 标注，可选修改 |

## 事实核查的核心原则

1. **事实正确性 > 文笔优美 > 传播力** — 一处事实错误会让听众质疑整期内容的可信度
2. **宁可多问一句，不能放行错误** — 不确定的地方直接问作者
3. **应然≠实然** — Agent 在对话里描述的"我将会做"不等于它真的做了
4. **不要太相信自己的记忆** — 写稿的人很容易把"我记得"写成"就是这样"
5. **金句的事实风险最高** — 传播力最强的句子，往往是事实层面最危险的。如果某句传播力极强但同时有事实问题，必须同时标注

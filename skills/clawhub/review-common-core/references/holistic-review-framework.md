# 整体审稿框架 — 宏观视角

与分段标注框架（逐句微观）互补，本文档提供文章/内容的**整体宏观审稿维度**。

---

## 0. 一句话定题（新增 · 2026-06-20）

⚠️ **先于所有其他检查执行。** 这是整个审稿的第一刀——在逐段逐句之前，先问自己一个最基础的问题。

### 方法

通读全文后，用 **一句话** 回答：

> **"这篇文章在讲什么？"**

### 判断标准

| 答案特征 | 判定 | 行动 |
|---------|------|------|
| 清晰一个主题，无歧义 | ✅ 通过 | 进入后续审稿 |
| 答案里出现"和/以及/同时"（如"讲思想沉淀系统和花钱心态"） | 🔴 双核心 | 必须处理：要么拆成两篇，要么删掉一个核心 |
| 答案模糊，说不清（如"讲了一些AI和跑步的事情"） | 🔴 立意不明 | 作者需要重新定调 |
| 勉强能说出一个主题，但结尾内容明显偏离 | 🟡 尾巴多余 | 删掉偏离部分，回到主线收尾 |

### 为什么这个检查能抓到"主题分散"？

逐句审稿只能看"这句话本身对不对"，段落衔接检查只能看"两段之间接不接得上"——但**主题一致性是更高层次的逻辑问题**：可能前后文的因果关系在作者脑中成立（"想法多→花钱多"），但对读者来说，两个话题在文章中的**分量和情绪重心**完全不同，读者会觉得"这文章到底想说什么？"

### 和 section 1（读者带走什么）的区别

| 检查 | 对象 | 问什么 |
|------|------|--------|
| 一句话定题（section 0） | **文章本身** | 这篇文章核心讲一个主题还是两个主题？ |
| 读者带走什么（section 1） | **读者心理** | 读者看完能否用一句话总结？ |

前者检查文章有没有"双核心病"，后者检查读者能否形成清晰印象。两个都要做。

### 配套工具

完成"一句话定题"后，请填写 [theme-consistency-checklist.md](./theme-consistency-checklist.md) 中的 JSON 清单，
并用 `scripts/validate_theme_consistency.py` 验证。

## 1. 读者带走什么

看完文章后，读者应该/能够带走什么？

### 评估方法

| 维度 | 检查项 | 好 | 不好 |
|------|--------|--|------|
| **一句话带走** | 读者能用一句话说出核心观点吗？ | "AI Agent最难的从来不是搭起来，是别让它们乱干活" | 读者说不出，笼统说"讲了一些AI的事情" |
| **认知框架** | 读者带走了一个可复用的思考模型吗？ | **有框架**：如"没有闭环=没有数据点校准自我评价" | **散点记忆**：几个好故事但没有框架 |
| **情绪底色** | 读者离开时的感受是什么？ | 好奇/启发/温暖/紧迫 | 焦虑/困惑/无所谓 |
| **行动启发** | 读者会想尝试什么？ | 会想"我是不是也在准备中" | 没有行动冲动，纯消费 |

### 输出示例
> 一句话带走："搭Agent最难的从来不是搭起来，是别让它们乱干活。"
> 认知框架：散点记忆（无清晰框架），能记住几个好故事但很难复述系统观点
> 离场情绪：好奇+轻微焦虑 — "这人挺真实的，想看看后面会发生什么"
> 行动启发：仅有共鸣，无行动转化

## 2. 读者未解疑惑

读完文章后，读者心中会留下哪些问题？

### 分类

| 类型 | 说明 | 可接受？ |
|------|------|---------|
| **健康的好奇** | 读者想知道后续，属于系列钩子 | ✅ 合理，尤其是系列EP01 |
| **不安全的好奇** | 读者觉得"你没讲清楚，我怀疑你在回避" | ❌ 需补充或删除 |
| **认知空白** | 读者缺少背景知识导致疑惑（如"飞书是什么"） | ⚠️ 取决于目标读者群 |
| **前后矛盾** | 读者发现不一致（如"36个"vs"异常率偏高"） | ❌ 必须修 |

### 评估方法
1. 读完全文，记下所有自然产生的疑惑
2. 分类标注（2-5条最核心的）
3. 判断是否影响理解和信任

### 输出示例
> ① "63个Agent怎么定义的？一个cron job算一个吗？"（健康好奇→EP02可回答）
> ② "研发总监删库的完整经过？"（健康好奇→"下期复盘"已埋钩子 ✅）
> ③ "Build in Public是什么？"（认知空白→潜在观众可能掉队）
> ④ "时薪一百是真的吗？"（不安全→数值偏低可接受）

## 3. 金句评估

哪些句子有截图转发/口耳传播的潜质？

### 评估标准

| 金句类型 | 传播力 | 特征 | 例子 |
|---------|--------|------|------|
| **反直觉型** | ⭐⭐⭐⭐⭐ | 颠覆常识，一句话让人觉得"原来如此" | "收藏就是学会，是最大错觉" |
| **共鸣型** | ⭐⭐⭐⭐ | 戳中普遍痛点，读者感觉"这说的就是我" | "没有一个事情是做完的" |
| **可迁移型** | ⭐⭐⭐⭐ | 脱离原文语境仍成立，可套用到其他场景 | "省钱省不出增长" |
| **画面型** | ⭐⭐⭐ | 描述有画面感，容易想象 | "挂了都不知道"（运维痛点） |
| **格言型** | ⭐⭐⭐ | 工整对仗，但偏口号 | "行动治愈完美主义。闭环建立自信。" |

### 输出示例
> 金句密度：每360字一句（高/中/低）
> 最强金句：①"用更宏大的故事掩盖行动力的缺乏"（反直觉型🔥） ②"收藏就是学会是最大错觉"（反直觉+共鸣🔥🔥）
> 最强金句：③"挂了都不知道"（画面型🔥）

## 4. 选题评估

这个主题本身是否值得写？在什么时间点写？

### 评估维度

| 维度 | 问题 | 判断 |
|------|------|------|
| **稀缺性** | 市面上有人用这个角度写过吗？ | 蓝海/红海/无人区 |
| **时效性** | 现在写是刚好、太早、还是晚了？ | 窗口期宽度（3个月/6个月/1年） |
| **差异化** | 跟同主题文章比，这里有什么独家角度？ | 独特/可替代/雷同 |
| **读者规模** | 对这个主题感兴趣的人多吗？ | 泛人群/垂类/极窄 |
| **跟作者匹配** | 这个主题适合作者写吗？ | 天然契合/可解释/不太搭 |

### 输出示例
> 选题评估：蓝海，2026年6月的Agent团队管理几乎无人系统讲过
> 稀缺性：⭐⭐⭐⭐⭐ 需要有真实Agent团队搭建经历才能写
> 差异化：不是"怎么用Agent"，而是"怎么管理Agent团队"
> 读者规模：垂类但精准（开发者/AI爱好者/技术Leader）

## 5. 叙事弧线效果

文章的整体结构是否有效？情感曲线是否健康？

### 评估方法

绘制情感曲线，判断：

1. **有起有伏吗？** — 全程一条直线是坏的，需要变化
2. **高潮位置对吗？** — 高潮太早（后续乏力）、太晚（读者已流失）都是问题
3. **结尾有回收吗？** — 结尾是否呼应当初的承诺/钩子？
4. **有空洞段吗？** — 信息密度骤降的段落

### 输出示例
> 情感曲线：开头（被骂的震惊）→ 中段上（B站案例高潮）→ 中段下（重复金句）→ 结尾平
> 诊断：前半段节奏好，中段B站案例是巅峰，后半段信息密度下降导致结尾乏力

## 6. 离场情绪总结

一句话：读者看完后几秒内的情绪状态。

| 情绪 | 好 | 不好 |
|------|-----|------|
| 🔥 被点燃 | 想行动、想转发 | — |
| 💡 被启发 | 学到了什么 | — |
| 😐 被消费 | — | 看完就忘了 |
| 🤔 被困惑 | — | "所以呢？他要说什么？" |
| 😤 被冒犯 | — | "穷人思维"这类词 |

## 7. 段落衔接与过渡质量

整体看文章的段落流动感，检查读起来是否像"一整篇文章"而不是"碎片拼接"。

### 检查清单

| 维度 | 好 | 不好 |
|------|-----|------|
| **段间过渡** | 前段末尾自然引出后段，读者不用停下来想"怎么跳到这的" | 两段之间缺失逻辑桥梁，需要读者自己脑补推理步骤 |
| **标题-内容一致性** | 小标题精确反映内容，读者看到标题就预期到内容 | 标题说"乱来的"内容说"统一交给总监管"——矛盾 |
| **逻辑链完整性** | 段落之间的因果推断完整 | 删掉了中间推理步骤（省钱→成长基金之间没桥） |
| **信息不重复** | 每个新概念/解决方案只出现一次 | 连续两段重复说"统一收归研发总监" |
| **叙事人物/视角统一** | 叙述者身份从头一致 | 前面个人视角，突然变成客观分析视角 |
| **语气连续性** | 语气从"狼狈踩坑"自然过渡到"反思总结" | 前面在说踩坑的狼狈，突然变成理想化"现在一切顺利"——语气断裂 |
| **节奏变化合理** | 短句后接长分析，有呼吸感 | 全篇同一种句长，读起来机械 |
| **回声呼应** | 结尾回扣开头的钩子/问题 | 开头说了问题，结尾回避了 |

### 诊断方法

从文章第二段开始，对**每个段落过渡**问三个问题：
1. 从上一段到这段，读者需要自己补充信息吗？ → 🔴 缺逻辑桥
2. 这段的内容在标题里被准确预告了吗？ → 🔴 标题-内容不一致
3. 这个信息是不是刚刚说过了？ → 🟡 重复冗余

## 8. 跨幕内容重叠度检查（2026-06-14 新增）

⚠️ **这是逐句模拟和五维度审稿最容易遗漏的检查维度。**
过去审稿方法论中，各 skill 只检查"段内重复"（同一段落中说两遍）和"相邻段重复"（连续两段说同一件事），**没有检查非连续跨幕内容重叠**——即同一概念在不相邻的场景/幕中多次出现。

播客/视频稿中，一个概念出现3次及以上（非首尾呼应性callback）就会被听众感知为"注水""你之前说过了""这期在反复讲同一个东西"。

### 方法：概念频率热力图

在开始任何逐段/逐句审稿之前，先通读全文，建立**概念频率表**：

```
概念名称：三步模型（收集→编译→学习）
  ├── 出现位置：幕1（首次定义）
  ├── 出现位置：幕2（再次展开） ← 🟡 第二次，可接受
  └── 出现位置：幕3（第三次解释） ← 🔴 第三次，严重重复

概念名称：学习需要一点摩擦
  ├── 出现位置：幕3（定义） ← 首次
  └── 出现位置：幕6（收束callback） ← ✅ 首尾呼应，不算重复
```

### 判断标准

| 频率 | 判定 | 行动 |
|------|------|------|
| 1次 | 正常 | 保留 |
| 2次（非相邻） | 🟡 关注 | 检查两次是否从不同角度展开。如果用同一句话/同一角度讲，压缩为一次 |
| 2次（相邻） | 🟡 关注 | 通常是自然过渡，但如果概念不复杂则合并 |
| 3次及以上 | 🔴 重复风险 | 必须删减到最多2次。除非是首尾呼应型callback（如"摩擦"） |
| 每个新场景都用同一句话解释基础概念 | 🔴 重复 | 让概念在第一次出现时讲透，后面只需用术语提及 |

### 例外：首尾呼应型callback

部分概念在开头定义、结尾callback是好的叙事结构，不视为重复：
- ✅ "摩擦"定义在第三幕 → 收束在第六幕 = 首尾呼应
- ✅ "问路vs地图"只在第六幕出现一次 = 正常
- ❌ 三步模型在幕1完整定义 → 幕2从头再讲一遍 → 幕3又展开 = 严重重复

### 输出示例

```
## 跨幕内容重叠检查

| 概念 | 出现幕数 | 判定 |
|------|---------|------|
| 三步模型（收集→编译→学习） | 幕1、幕2、幕3 | 🔴 重复（幕1讲完 > 幕2不应再从头展开） |
| 双环系统 | 幕1、幕3 | 🟡 关注（幕3从另一角度展开，可保留） |
| 学习需要一点摩擦 | 幕3、幕6 | ✅ 首尾呼应 |
| 学习=知识库质检 | 幕5 | ✅ 单次 |
| 问路vs地图 | 幕6 | ✅ 单次 |
```

## 与此框架配合的有：

- **分段标注框架**：处理"每段读者反应"（微观）
- **本框架**：处理"整篇读完收获"（宏观）
- **跨幕重叠检查**：在上面两者之前执行，先扫一遍概念频率，再逐段逐句审稿（防止逐段盲区）
- **审稿检查清单**：审稿完成后运行 checklist + JSON 校验，防止漏项。详见 [review-checker.md](./review-checker.md)

所有审稿完成后，必须输出 JSON 校验记录，脚本可自动验证审稿完整性。

四个视角互补使用，构成完整审稿。最后一步是 Checkpoint 校验：

```
审稿管线最后一步：
[完成审稿] → [输出 JSON 校验记录] → [脚本验证] → [通过/不通过]
```

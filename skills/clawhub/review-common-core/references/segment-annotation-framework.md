# 统一的分段标注框架

本框架定义了审稿过程中统一的分段标注体系和读者画像模板，可被所有审稿 skill 引用。

> 共享引擎：review-common-core

## 反应标记体系

| 反应类型 | 标记 | 含义 |
|----------|------|------|
| 🎯 钩住了 | 感兴趣 | 读者会继续听，想了解更多 |
| 😐 平的 | 无感 | 不会走神但也不会留下印象 |
| 😴 走神 | 无聊 | 读者可能切出去、翻手机 |
| ❓ 疑惑 | 不懂 | 读者会想"这是什么意思？""为什么？" |
| 💡 顿悟 | 明白了 | 读者会有"哦原来是这样"的感觉 |
| 🔥 共鸣 | 有感 | 读者会点头、想转发、想截图 |
| 🤔 质疑 | 不信 | 读者会想"真的吗？""你怎么知道？""证据呢？" |
| ⚡ 雷点 | 反感 | 读者会觉得"太装了""太假了""又来了""像标题党" |
| 💬 弹幕触发 | 想互动 | 读者会想评论、吐槽、接话 |
| 🎶 节奏变化 | 注意力重置 | 节奏/情绪/视角的切换点 |

## 三层读者画像模板

在开始审稿前，必须确定读者画像。建议使用以下三层模板：

### 目标读者（核心受众）

- **定义**：这篇内容真正想影响的人。他们为什么需要看？当前有什么痛点？
- **知识背景**：对主题的了解程度（小白/进阶/专家）
- **消费场景**：在什么场景下阅读/收听（通勤/健身/专注/摸鱼）
- **预期收获**：他们点进来时，期待得到什么？

### 潜在读者（可能触达的受众）

- **定义**：通过算法推荐/社交传播触达的、原本不在目标范围内的读者
- **关注点**：他们关心什么？什么会让他们停下来？
- **门槛**：内容对他们来说有没有理解门槛？

### 商业读者（"别人怎么看"的担忧）

- **定义**：实际会看到这篇文章的同事/老板/朋友/同行
- **敏感点**：什么话题/表达方式会让人不安？
- **印象管理**：这篇文章让这个人群对公司/团队的印象是正面还是负面？

## 每段标注的格式规范

### 逐段标注格式

```
## [段落名称]

**[原文摘录]** → [反应标记] [具体脑内弹幕/分析]

**[原文摘录]** → [反应标记] [具体脑内弹幕/分析]

**段落总结**：[整体判断 + 最关键的1-2个问题]
```

### 注意事项

1. **模拟的是"第一次听到"的反应**，不是读了三遍后的评价
2. **听众不会回溯** — 播客是线性的，一句话没听懂就过去了
3. **注意力是稀缺资源** — 每多一句平的话，走神概率就增加一分
4. **疑惑会累积** — 一个疑惑没解决，后面三句话的理解都会打折扣
5. **质疑比赞同更有价值** — 读者的"真的吗？"比"对对对"更值得标注
6. **金句的事实风险最高** — 传播力最强的句子往往是事实层面最危险的

### 汇总输出格式

审完全文后输出：

1. **🔥 最强的 3 句**：读者反应最强烈的句子
2. **😴 最危险的 3 句**：最可能让读者走神的句子
3. **❓ 最大的 3 个疑惑**：读者最可能产生的疑问
4. **🤔 最大的 3 个质疑**：读者最可能不信的地方
5. **⚡ 最大的 3 个雷点**：最可能让读者反感的句子
6. **整体节奏图**：用 😐😴🎯🔥🤔⚡ 标记每幕的情绪曲线

### 事实性问题标注附加规则

当标 🔥（共鸣）或 💡（顿悟）的句子同时存在事实风险时，**必须同时标注事实风险标记**，并在报告中单独列出。具体事实风险分类见 [fact-check-framework.md](./fact-check-framework.md)。

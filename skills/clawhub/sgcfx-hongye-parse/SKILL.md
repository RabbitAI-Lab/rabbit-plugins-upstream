# SGCFX（宏业计价文件）本地解析 → Excel

**核心结论：SGCFX 是 ZIP 容器，内层文件未加密、明文存储。**
不要相信"加密了、必须装 Windows 宏业软件才能导出"的判断。

---

## 快速开始（4 步）

```bash
# 1 解包（注意：解出的文件权限可能是 000，必须 chmod）
mkdir -p ./tmp_sgcfx && unzip -o "<file>.SGCFX" -d ./tmp_sgcfx
chmod -R u+rw ./tmp_sgcfx          # 不 chmod 会 Permission denied

# 2 清单明细（3003 表）→ Excel
python3 scripts/export_boq.py  ./tmp_sgcfx 4 ./输出     # 4 = 其中一个版本盘册
python3 scripts/export_boq.py  ./tmp_sgcfx 3 ./输出     # 3 = 另一个版本盘册

# 3 费用汇总六段式（3010 表）→ Excel
python3 scripts/export_cost.py ./tmp_sgcfx 4 ./输出

# 4 材料工料机（3007 表）
python3 scripts/p3007.py $(find ./tmp_sgcfx -path '*/3007')   # 看解析率，应 ≥99%
python3 scripts/agg3007.py                                     # 聚合 CSV
```

顶层数字目录语义：**两个数字目录通常是两个保存版本**（如 `3/` 旧版、`4/` 新版），
**不是**送审/审结。版本定名靠 `SysData` 里的中文大写金额串，不靠目录名。

## 通用二进制结构（所有表通用）

```
表头 96 字节:
  +0  数据区总长        +4  schema区长度     +8 / +12 保留
  +16 表ID(如 3003)    +20 起 版本号(UTF-16 "10.025")
数据区起点 = 96 + schema区长度

字符串 = [uint32 字符数][UTF-16LE]        ← 数值也常以字符串冗余存储
数值   = IEEE754 双精度小端
```

**记录类型标记**（数据区靠这个切分）：

| 标记 | 含义 |
|---|---|
| `F段N` | 分部 |
| `F目N` | 清单项（分部分项） |
| `F定N` | 定额子目（清单下挂） |

## 3003 分部分项清单：完整破解法（重点）

行结构（按此顺序解析，已实测验证）：

```
序号(字符串) → 工程量(字符串!) → F目N → 清单编码(12位) → 定额编号(9位)
  → 项目名称 → 单位 → [数值区] → 项目特征 → 工程量计算规则 → …
```

**两个必须记住的坑**：

1. **工程量是字符串存储的**，不是 double。
   形如 `'3.6'`、`'73.5'`、`'46.56'`、`'1155.91'`。
   去读 double 会得到垃圾值或 0 —— 这是最容易翻车的地方。
   取法：在 `F目N` 之前的字符串中，找最近一个匹配 `^-?\d+(\.\d+)?$` 的串。

2. **单价/合价是 12 字节步长的成对结构**。
   以"单位"字符串结束位置为数值区起点 `st`：
   - `st + 0`  = 综合单价
   - `st + 12` = 综合合价
   后续人材机、管理费、利润同理成对（步长亦为 12）。
   数值有冗余副本（同值连续重复 2~3 次），扫描时用步长 4 再压缩连续重复最稳。

**校验（必做）**：`综合合价 = 综合单价 × 工程量`，应 100% 通过。

## 3010 费用汇总：六段式

```
A   分部分项合价        A.1 甲供材料费
B   措施项目            B.1 安全生产措施费
C   其他项目            C.1 暂列金额 / C.2 专业工程暂估价 / C.3 计日工
                       C.4 总承包服务费 / C.5 合同约定的其他项目
D   税前建安工程造价 = A + B + C
E   增值税 = (D − A.1) × 9%
F   最高投标限价合计 = D − A.1 + E
```

**两种定位方式，按序尝试**：

1. **标题名定位法（优先，更简单）**：
   数据区内按标题名精确匹配，取其后第一个非零 double（步长 4 扫描）：
   `分部分项合价` / `甲供材料费` / `通用措施项目合价+专业措施项目合价` /
   `安全生产措施费` / `其他项目合价` / `暂列金额` / `专业工程暂估价` /
   `A+B+C` / `(D-A.1)*费率` / `D-A.1+E`
2. **闭合约束反解法（字符串层破碎时的兜底）**：`scripts/dbl3010.py`。

**反解必须加的三条剪枝**（不加会解出语义错误的组合）：
1. **C 允许为 0**：新版非安装类单位工程「其他项目费 = 0」，此时 `A + B = D`。
2. **C 允许是「候选集中两数之和」**：安装类其他项目费 = 专业工程暂估价 + 规费，
   不作为单个 double 存盘。
3. **措施/分部分项 ≥ 5%**：区分「措施」与「规费」的关键约束（实测 6.1%~12.7%）。

## 分册 → 单位工程 映射（不同项目必须重核）

脚本里的 `MAP` 默认为空（降级为"分册N"，不臆造名称）。按此流程重建：

1. 读 `{版本}/Tree` → 得到「单项工程 → 单位工程」层级与顺序
2. 用清单编码前缀判断专业：`01`=建筑 / `03`=安装 / `04`=市政总平 / `05`=其他
3. 同专业内，按金额量级配对：清单合价 < 单位工程金额，两者按大小排序匹配
4. **反向验证**：映射正确时，各分册的 3010 总价应能逐项对上 `0/1005` 汇总表

## 验证清单（交付前必过）

1. **清单层**：Σ综合合价 = 文件内部"合计"行（搜 `合计` 字符串，取其后 double）。
   全部分册应通过，差 ≤ 0.05 元（浮点舍入）。**这是证明没漏项的决定性证据。**
2. **自校验**：综合合价 = 综合单价 × 工程量，全部条数通过。
3. **链条层**：`A+B+C=D`、`(D−A.1)×9%=E`、`D−A.1+E=F`，逐项通过。
4. **总额层**：Σ单位工程总价 + 独立列项杂费 = 建设项目限价。差额须能逐项归因。
5. **大写金额 × 数值串双证一致**（`SysData` 里第一个大写金额 = 项目总价）。
6. 材料表 ↔ 清单表交叉：按 t/m³ 计量的材料，定额含量 = 1.0 时材料量应等于清单量。

⚠️ **常见误解**：清单合价合计 ≠ 工程总额。
差额是措施费、规费、税金、暂列金额等，**属正常造价构成，不是解析错误**。
判断依据：每个分册 Σ合价是否与文件自己写的"合计"行一致。

## 已踩过的坑

- `unzip` 解出的文件权限是 `----------`，**必须 `chmod -R u+rw`**，否则读不了
- 高熵文件里 2 字节签名会随机命中，**判断压缩格式必须实际解压验证**，不能只看签名存在
- `struct.unpack_from` 要限 `min(b, len(d))-8`，否则越界报错
- `sed` 替换含 `*` 的模式会失败（zsh glob），改文件直接用 Python 读写
- **校验脚本自身也可能有 bug**：一级行被重复计入二级累加会造成假失败。
  数据对不上时，先怀疑自己的校验逻辑，再怀疑数据
- 报告中区分【实证】（文件原文）/【推断】/【待确认】，不要把推断写成结论

# 锅炉压力容器定期检验与台账核对（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 不联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：制造企业的**设备科 / 安环部**、物业与医院的**工程部 / 后勤保障部**、
酒店的**工程部**，在**每月**的特种设备台账复核节点上用它。锅炉、压力容器、压力管道都是**特种设备**，
《特种设备安全法》要求定期检验、使用登记、作业人员持证、日常运行记录与安全阀校验都得在有效期内 ——
台账一错，轻则被下整改通知，重则被查封停产；出事故企业负责人要担刑责。

**这些是每月必须核一遍的硬项**：

1. **检验有效期覆盖**：上次检验日期 + 检验周期(月) 倒排出来的「下次检验日期」，必须 ≥ 本次核对基准日。
   外部检验 / 内部检验 / 耐压试验的周期按设备类别不同，台账上要能逐台点出来。
2. **使用登记证与作业人员证**：设备投用前必须办使用登记证；司炉工、水处理工必须持证上岗。
   两证的到期日都要覆盖核对基准日，缺证与过期在监管眼里都是**直接处罚项**。
3. **安全阀 / 压力表校验**：校验日期 + 校验周期 = 下次校验日期，超期未校验等于超压保护上有空白。
4. **日常运行与巡检记录**：停用 / 报废的设备不该再出现在运行记录里。
5. **隐患整改闭环**：整改单、复检记录要能落到实处。

**最容易被监管抓住的那一条**：**超期未检仍在用** —— 下次检验日期已经过了，运行状态还写着「在用」。
这条在完整档（另一个独立商品）里会被单独点名并按超期天数降序排出来。

**这张表会逐项核对什么**：上面这本台账的逐行算术、合计勾稽、重复与合法性检测。

每条结论都带**原文行号与行内容**（设备编号、日期、数字都在结论里），可被第三方用同一口径复算；
材料不足时**不给结论**，会明确列出还缺什么。

## 这个免费版查什么（6 项）

1. **检验有效期覆盖** —— 核对基准日 ≤ 下次检验日期，超期逐台给出已超期天数。
2. **使用登记证与作业人员证覆盖** —— 两证到期日都要覆盖核对基准日；缺证 / 过期逐台点名。
3. **安全阀压力表校验** —— 校验日期 + 校验周期(月) = 下次校验日期，逐行复算；再以核对基准日判超期天数。
4. **同一设备编号重复登记** —— 一本台账里设备编号唯一（重复登记会让两行各算一套日期）。
5. **合计行逐列复核** —— 数量类列（设备台数、校验件数）的合计行必须等于明细行加总。
6. **空白占位符与字段合法性** —— 关键字段缺失、日期格式非法、数值为负或周期为零、运行状态非法。

**必需列**（缺任何一列都只报「材料不足」，**绝不给结论**）：
设备编号、设备名称、设备类别、使用登记证号、登记证到期日、上次检验日期、检验周期(月)、下次检验日期、
作业人员、作业人员证到期日、安全阀校验日期、校验周期(月)、下次校验日期、运行状态、核对日期。

**这个免费版不查**（完整档才查，跑 `--sample` 会如实列出）：
超期未检仍在用、停用报废设备仍在运行记录、运行参数越限、日常巡检记录断档、分设备类别与分使用部门的汇总清单。

## 怎么用

```bash
node scripts/run.mjs --sample                 # 先看样例
node scripts/run.mjs --input 你的材料.json     # 跑自己的材料
```

入参就一张表：把 Excel 里的**表头 + 数据行**一起复制成文本粘进 `{"text": "…"}`（Tab 分隔最稳）。
表里可以有 `合计` 行（合计行只参与「合计行逐列复核」，不参与逐台检查）。
完整档还认 `--- 日常运行与巡检记录 ---` 段（跨表核对用）；免费版会跳过这一段，不会因此报错。

## 常见错法（每月核这张表最容易栽的 5 个坑）

1. **把「下次检验日期」当成随手填的日期，而不是「上次检验日期 + 检验周期」倒排出来的**。
   很多台账是抄上一年的日期再加一年，中间换过检验机构、做过延期或提前检验，两次就抄串了。
   正确做法：用上次检验日期 + 检验周期(月) 复算一遍，与台账值对上，再判是否覆盖核对基准日。
2. **只核「在用」设备的检验日期，忘了查使用登记证与作业人员证的有效期**。
   检验合格但登记证过期、或司炉工证件过期，同样是违法使用；两证要跟检验日期一起逐台点。
   台账里只写作业人员姓名而不写证件到期日，这一项就永远核不了 —— 那属于材料不足，不是没问题。
3. **安全阀校验只填「校验日期」，把「下次校验日期」空着或者按校验日期 + 12 个月随手写**。
   校验周期可能是 6 个月、1 年，也可能因介质腐蚀性更短；必须逐行复算，别让两个字段互相矛盾。
4. **停用 / 报废设备留着老行不改状态，或者干脆从台账里删掉**。
   停用设备仍有运行记录、或报废设备还在台账里当作在用，都是隐患；状态值只能是 在用 / 停用 / 报废 / 检修。
5. **同一台设备因为改过名称或换过部门，就在台账里登记成两行**。
   重复登记最坑：两行的检验有效期各算一套，其中一行超期了却没人发现。设备编号必须唯一。

## 需要完整档时（可选）

本免费版是**完整可用的核心产出**，本版本**不包含**下面这些项：

- 超期未检仍在用（下次检验日期已过且运行状态=在用；按超期天数降序点名）
- 停用报废设备仍在运行记录（跨表交叉核对：台账状态为停用/报废，却在日常运行与巡检记录里出现）
- 运行参数越限（运行压力 / 运行温度超过设计上限，逐条报出偏差）
- 日常巡检记录断档（按设备对运行记录日期序列逐日比对，缺哪一天就点哪一天）
- 分设备类别与分使用部门的汇总清单（按超期天数与越限次数排序，给出可整改动作）

同名工具的**完整档**是另一个独立商品（条款与条件以它自己的商品页为准）；两档的差别**就是上面这些，没有别的**。

## 边界（请务必知道）

本工具**不做**这些判断（引擎 `CHECKS_OUT_OF_SCOPE` 里逐条列了）：

- 不判定这台设备该不该检验、该做外部检验还是内部检验或耐压试验 —— 那是检验机构与设备类别的法定口径；
- 不判定检验报告结论本身是否合格、安全阀整定压力是否合理 —— 那是检验机构的判定权；
- 不判定隐患整改是否真的闭环、现场是否已经停用或隔离 —— 本工具只核台账的字面一致性；
- 不读 .xlsx / .pdf 原件、不联网核验使用登记证 / 作业人员证 / 检验报告的真伪。

**材料不足时不给结论**（连「未发现问题」也不输出），会明确列出缺什么 —— 宁可什么都不说，也不说错话。

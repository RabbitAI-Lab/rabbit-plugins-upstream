# 分类型评审清单

每类文档的评审 = 通用前检 + 对应类型清单 + 交叉验证（见 SKILL.md）。

## 通用前检（所有类型）

- [ ] frontmatter 完整：doc-type / layer / doc-class / status / owner；as-is 含 last-verified
- [ ] doc-class 与内容口吻一致（as-is 无"应当"；to-be 无现在时事实陈述）
- [ ] 层归属正确；单文档回答单核心问题
- [ ] 跨文档引用使用稳定 ID + 相对链接，无"见上文"
- [ ] 不确定事实已标 `TODO(验证)`，无编造痕迹
- [ ] 已在 docs 索引登记

## PRD

- [ ] 问题定义完整：场景 + 现状为何不可接受 + 证据
- [ ] 目标用户链接到 PERSONA；"所有用户"类表述视为边界缺失
- [ ] 边界三件套齐全：in-scope / out-of-scope / non-goals
- [ ] 每条 FR/NFR 有稳定 ID；逐条 GWT 验收标准归 REQ-SPEC（真值源），PRD 只保留摘要与链接——PRD 内出现 GWT 副本即为发现（复制即 Major）
- [ ] 成功指标：可度量、有基线（或"待建立基线"+行动）、有目标值、有测量来源
- [ ] 未混入实现方案（应转 DESIGN）与排期（应转 ROADMAP）
- [ ] 依赖与风险每条有缓解思路或明确接受声明

## DESIGN

- [ ] arc42 章节完整；不适用的章节保留标题并写明原因
- [ ] C4 分级取舍合理：L1 必有；图附 Mermaid 源码与元素登记表（含代码路径）
- [ ] 上下文图覆盖全部外部系统与用户；连线标注协议与数据
- [ ] 每个重大选型引用 accepted/deprecated 状态的 ADR；发现无 ADR 的重大选型为 Blocker
- [ ] 运行视图覆盖正常路径与主要异常路径
- [ ] 约束与决策区分：约束是"没得选"，决策有 ADR 支撑
- [ ] doc-class 迁移正确：实现验收后应已转 as-is 并维护 last-verified
- [ ] 风险/债务条目有追踪出处

## ADR

- [ ] 一篇一个决策；标题陈述决策本身
- [ ] 状态合法且符合状态机（proposed→accepted/rejected；accepted→deprecated/superseded）
- [ ] 状态与内容时间一致：superseded 必有 superseded-by 双向链接；deprecated 说明存量范围与退出计划；rejected 保留否决原因
- [ ] 背景说清 Force 与约束；备选方案表非空（只有"什么都不做"的备选不合格）
- [ ] 后果三分类（正面/负面与新增义务/中性）完整
- [ ] accepted 及之后的正文未被修改（只允许状态行/日期/后继链接变动）
- [ ] 编号连续不复用；命名 NNNN-kebab-case

## PROGRESS

- [ ] 追加式：历史条目未被回改；纠错为新条目并引用原条目
- [ ] 条目含产出链接与临时决策；重大临时决策已补 ADR 并回链
- [ ] 迭代收尾完整：目标达成情况 + 未完成事项去向 + 交接要点
- [ ] 未混入评价（属 RETRO）与计划（属 ROADMAP）

## RETRO

- [ ] 目标回顾对照 ROADMAP 承诺，而非泛泛而谈
- [ ] 每条行动项格式完整：行动 → 去处 → 责任人，去处限定 ADR/ROADMAP/TECH/RUNBOOK
- [ ] 全部行动项已外发（`status: closed` 的前提）
- [ ] 好的实践同样被识别（不是只挑毛病）

## TECH

- [ ] 成文门槛满足：问题第二次出现或成本 > 30 分钟
- [ ] 标题即结论；一主题一篇
- [ ] 未绑定具体项目路径（引用项目仅作示例）
- [ ] 适用范围与限制非空；有失效信号
- [ ] last-verified 在有效期内；依赖的外部版本未发生重大变化

## PERSONA

- [ ] 一个画像一篇；背景、目标、痛点三要素完整
- [ ] 痛点有证据类型标注；"实证"必须有证据链接，否则降级为"假设待验证"
- [ ] 四阶段旅程完整且按时间顺序；每阶段五要素（场景/行为/触点/情绪/机会点）齐全
- [ ] 机会点链接到 PRD 需求或 ROADMAP 条目
- [ ] 无凭空臆造的行为描述；推断内容已标注

## RUNBOOK

- [ ] 四段式完整：前提条件 / 步骤 / 验证 / 排障，缺一为 Blocker
- [ ] 概述含影响范围、风险级别、预估时长
- [ ] 每步注明执行位置；命令可直接复制；占位符用 `{{}}` 显式标注
- [ ] 破坏性操作有 ⚠ 标记与确认点；高风险操作有备份与回滚前置
- [ ] 验证表：关键步骤后 + 整体完成判据，验证命令可执行
- [ ] 排障表覆盖"症状→原因→处置"；含回滚方案
- [ ] status: active 的前提是至少实际执行验证过一次；命令与当前系统版本相符

## ROADMAP

- [ ] 双区分离严格：当前迭代与待办无混写；当前迭代有 WIP 约束
- [ ] 当前迭代每项：目标+完成标准+来源+PROGRESS 跟踪+负责人
- [ ] 待办按优先级排序且标注来源；无来源的条目为发现
- [ ] Later/已拒绝保留拒绝原因；已拒绝条目未被静默删除
- [ ] 无僵尸条目：跨迭代的"永远差一点"事项必须有明确去向
- [ ] 与 PROGRESS/RETRO 状态一致：已完成待办应有对应记录

## 扩展专业系列（14 类）评审门禁速查

> 扩展系列的完整红线已内建于各模板（`doc-writer/templates/` 五条线）的「质量门禁」与「红线自查」，评审时直接核对模板内清单；下表为评审视角的核心抽查项。

| 类型 | 评审核心抽查项（命中即按模板红线定级） |
|---|---|
| REQ-SPEC | 每条 FR 有 GWT；[推定] 已入待确认清单；是否被 PRD/USER-STORY/TEST-PLAN 复制双写（复制即 Major） |
| USER-STORY | 孤儿故事（无 FR 映射）= blocked_on；验收标准引用 GWT 而非另写；优先级与 REQ-SPEC 一致 |
| UI-SPEC | 五态齐全抽查（任选组件）；空/载/错/禁四全局态逐页抽查；对比度抽算 |
| BUSINESS-PROCESS | 流程图有异常路径与双态收口；判断分支标 FR 编号；时序图端点与 API-CONTRACT 逐一可对照 |
| API-CONTRACT | FR↔端点映射无缺口（缺口须显式登记）；任选端点 curl 可执行；冻结后变更走了变更流程 |
| DDD-DESIGN | 聚合根有不变量；边界变更走 ADR；跨上下文接口未复制载荷细节 |
| DEV-STANDARDS | 规范正文未被复制（只索引）；例外豁免有 ADR 链接与有效期 |
| REVERSE-ANALYSIS | 合法性声明四项全过；抽查 RV 结论的证据编号与置信度；证据已脱敏 |
| TEST-PLAN | TC 映射覆盖范围声明；高风险区有加深策略 |
| TEST-REPORT | P0/P1 清零或列豁免；FR 验收矩阵全覆盖；复现步骤脱敏抽查 |
| DEPLOY-GUIDE | 配置表无真实密钥/运行值；回滚三条件齐全；与 RUNBOOK/DESIGN §7 部署视图一致 |
| CHANGELOG | 条目可追溯（任务号/commit）；无内部重构入册；与 PR-SUMMARY/TEST-REPORT 一致 |
| HANDOFF | user_brief 与用户原话逐字一致；scope 含"不做什么"；blocked_on 已处置 |
| PR-SUMMARY | 角色启用表如实（未启用有原因）；验证命令实际执行过；与 TEST-REPORT 质量结论一致 |

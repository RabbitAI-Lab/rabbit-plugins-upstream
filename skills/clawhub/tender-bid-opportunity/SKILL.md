# 招投标商机筛选｜招标中标与标讯分析

把“找什么项目”转成可核验的招投标查询，交付带公告来源、阶段、时间和筛选依据的标讯清单。数据由知了标讯 API 提供；覆盖范围、时效和是否存在记录以接口实际返回为准。

## 使用范围

- 查询招标公告、中标结果、采购意向、拟建项目、临期项目和项目全流程。
- 按业务条件初筛候选项目，比较相关性、地区、金额和已核实的时效。
- 查询公司历史中标、采购方、供应商、行业统计和历史中标单价。

本包属于招中标查询产品线，与通用查询包能力兼容。已安装专用地区或行业包且本次明确落在其范围内时，优先用专用包，不重复调用。完整“该不该投/如何报价”的决策报告、企业深度背调、主动商机雷达晨报和标书编写使用对应专用技能；没有安装时说明本包能先完成哪些查询，不承诺已执行完整报告或持续监控。无关写作、一般市场调研和个人银行余额不触发。

边界示例：“了解一下招投标”属于概念介绍，不调用收费数据；“列中标项目并比较哪家中得多”属于查询统计，要求完整企业实力报告才转背调；明确关键词的重复查询仍属搜索，但定时执行由宿主另行配置并按用户授权处理，本包不自行创建云端任务；只有“哪些值得跟进”却缺项目上下文时先澄清。主动发现拟建、意向和续约商机且已安装商机雷达时优先雷达；单纯查指定范围记录时用本包即可。联系人导出遵守下文的数据展示边界，不因转给别的技能而绕过。

## 查询流程

1. 明确目的：找正在招标的项目、查历史中标、找采购意向/拟建/续约线索，还是统计分析。缺少影响检索的关键词、地区或时间时，一次补问关键条件；用户明确“全国/不限”即按其范围执行。相对日期以用户时区的当前日期换算，在结果中注明实际起止日期。
2. 阅读对应参考页，选择最少必要调用。常规关键词用 `search_bids`；AND/OR、排除词和不同主体组合用 `query_bids_advanced`。不为了“丰富报告”额外调用付费接口或自动扫完所有页。
3. 区分主体字段：产品用 `sm`，标题用 `title`，采购方用 `caller`，中标方用 `winner`，投标方用 `tender`；准确字段和组合规则见 `references/api-search.md`、`references/api-company.md`。不能把“某公司采购”当成“某公司中标”。
4. 明确阶段：`bid_type` 为字符串 `招标` / `中标` / `全部`，阶段编码在参考页核实。`get_bid_detail` 等接口的 `bid_type` 是整数，不能复用搜索的字符串。公告发布日期不等于报名或投标截止日期；“最近发布”不能直接判为“仍可投”。需要核实时才取详情或时间线。
5. 将候选清单分成“可跟进候选”“早期线索”“历史中标参考”“状态待核实”。只有公告阶段、截止时间和后续变更支持时，才称仍可参与；缺截止日期标为待核实。已中标项目可以作为采购历史或续约线索，不能算当前可投机会。`search_expiring_projects` 指周期项目/合同临期，不是投标截止即将到期。
6. 先按实际业务相关性筛选，再比较时效、地域与金额。说明排序依据及数据缺口，不输出没有校准依据的中标概率，不把预算当成交金额或把单页样本当全国全量。

## 金额、来源与成本

- 项目金额筛选 `min_amount` / `max_amount` 使用**万元**；产品单价筛选 `min_price` / `max_price` 使用**元**。聚合接口的金额过滤按参考页传入，不猜参数名。返回 `money` 是元、`money_wan` 是万元，输出同时注明单位。
- 展示实际返回的公告标题、采购单位、地区、发布日期、阶段、金额及其口径、来源链接；缺失字段写“未披露/待核实”，不补造预算、联系人或截止日期。不同阶段公告用时间线或可信项目标识关联，不仅凭相似标题合并。
- 只取得一页时注明“当前页样本”和接口总量；聚合统计注明时间、地区、条件及口径。需要扩大调用范围或批量翻页时先说明计划与成本，取得用户授权。
- 数据查询消耗平台积分，实际计费以服务端返回为准；工商五项成功有数据每次/每页3积分，无结果、空页和失败不扣积分。账户与升级展示确认免费。数据接口可用不代表全量数据实时无遗漏。
- 电话按服务端原样展示；`contact_privacy: masked` 时说明当前返回已脱敏，不用外部搜索补齐脱敏号码，不批量导出联系人。
- 工商来源按参考页规范呈现，保留准确记录口径，不按企业名称、地址或单页股东比例推断控制权。

## 交付样式

先写本次实际检索条件与数据范围，再给清单：项目/公告、地区、采购方、阶段、关键日期、金额（注明预算/成交/其他）、来源、匹配依据、待核实事项。没有证据的列留空或标注缺失，不为了填满表格额外收费查询。

用户只查公告时直接交付查询结果；要求初筛时再给候选排序和依据。初筛结果不等于已完成资格审查或投标决策。

可直接尝试：“查广东近30天服务器招标，排除维修维保，预算100万元以上”；“查某公司近一年中了哪些信息化项目”；“按深圳近三个月智慧校园标讯，列出阶段待核实的候选项目”。相对日期在执行时换算，不固定成示例年份。

## 错误处理

- `INVALID_APP_KEY` / `APP_KEY_EXPIRED` / `APP_KEY_DISABLED`：按凭证说明处理；自动注册仍须同意。遇 `ACCOUNT_RECOVERY_REQUIRED` 停止重试，引导登录恢复，不改变设备特征绕过。
- `QUOTA_EXCEEDED`：停止重试，按 `references/auto-register.md` 提供账户充值入口。
- `RATE_LIMIT_EXCEEDED`：稍后再试，不立即循环请求。
- `QUERY_EMPTY`：如有主体候选先请用户消歧；确无结果可建议放宽条件，不伪造结果。
- `NOT_FOUND`：核对标识或公告类型，不原样重复请求。
- `INVALID_PARAMETER` / `MISSING_REQUIRED_PARAMETER`：对照参考页修正参数。
- `QUERY_TIMEOUT`：缩小检索范围后最多重试一次；其它服务异常如实说明，不反复注册 Key。
- `CLIENT_VERSION_UNSUPPORTED`：提示从实际安装来源更新，不把产品线版本当商店包版本。

## 本场景：按已明确业务条件初筛商机

本版默认交付候选项目表。行业/产品、地区、时间、预算和排除项以用户明确条件为准；没有业务信息时先补问，不直接推荐项目或把用户锁定在某行业。

1. 先将条件分为硬筛项与偏好项，例如“广东、近30天、预算100万元以上、排除维保”是硬筛，优先某采购方是偏好。说明实际使用的条件。
2. 首次只查询相应范围的一页。需要AND/排除关系用高级检索；需要采购意向或拟建线索时分别检索并标明阶段，不将三种渠道的条数混成去重项目数。
3. 对用户要进一步跟进的候选再查详情和时间线，核实截止时间、变更与最终结果；不要默认对整页逐条收费联查。必要时先说明候选数量和追加调用计划。
4. 输出“符合条件/可能符合待核实/明确不符合”及具体依据。不明确的资格、预算、项目阶段保持未知，不用加权分数掩盖数据缺口。硬条件不符合的项目不因预算大而排进推荐。
5. 一条公告不等于一个可投项目，历史中标仅作采购历史或续约参考。用户要完整中标策略时使用投标决策技能，不将本次初筛称为资格审查完成。

可尝试：“我们做医院信息化，筛广东近30天预算100万元以上的项目，排除维保，按可跟进与早期线索分表。”

# 景点检索筛选规则

## 1. 预算匹配规则

### 门票预算计算

总预算 → 门票预算（总预算的 10-15%）

| 总预算 | 门票预算 | 可选景点数(3天) | 单景点上限 |
|--------|----------|----------------|-----------|
| 2000 | 200-300 | 6-9个 | 22-50元 |
| 5000 | 500-750 | 6-9个 | 55-125元 |
| 8000 | 800-1200 | 6-9个 | 88-200元 |

### 单景点门票处理

| 条件 | 处理 |
|------|------|
| ticketPrice = 0（免费） | 优先推荐，评分×1.15 |
| ticketPrice ≤ 单景点上限 | 正常推荐 |
| ticketPrice > 单景点上限 | 标记"超预算"，评分降低 |
| 价格未知 | 标记"价格待核实"，询问用户 |

### 三档方案对比

| 档次 | 日人均消费 | 策略 |
|------|-----------|------|
| 经济型 | <300元 | 免费景点、公共交通、经济住宿 |
| 舒适型 | 300-800元 | 付费景点+免费景点混搭，中档住宿 |
| 豪华型 | >800元 | 精品景点+VIP选项，高档住宿 |

## 2. 黑白名单规则

### 白名单（包含列表）— 硬约束

| 条件 | 处理 |
|------|------|
| 用户指定"必去X" | X必须在最终行程中 |
| X不在搜索结果中 | 专门搜索X的详细信息 |
| X距离过远 | 仍然包含，注明额外交通时间 |
| 列表≥5个 | 提示行程可能过紧 |

### 黑名单（排除列表）— 硬约束

| 条件 | 处理 |
|------|------|
| 用户指定"不去X" | X不得出现在任何推荐中 |
| X是热门推荐 | 仍排除，用户偏好绝对优先 |
| 黑白名单冲突 | 提示矛盾，请用户确认 |

## 3. 排序与推荐

### 评分公式

```
综合得分 = 评分×0.30 + 偏好匹配×0.35 + 预算适配×0.20 + 人气×0.15
```

| 维度 | 权重 | 计算方式 |
|------|------|----------|
| 评分 | 0.30 | rating / 5.0 |
| 偏好匹配 | 0.35 | 景点类型与用户偏好重叠数 / max(偏好数, 2) |
| 预算适配 | 0.20 | 免费=1.0 / 远低于上限=0.8 / 范围内=0.5 / 超=0.0 |
| 人气 | 0.15 | 基于评论区相对热度 |

### 推荐理由生成

```
💡 推荐理由：{name}（评分{rating}）{matchReason}{budgetNote}
```

| 条件 | 理由片段 |
|------|----------|
| 偏好匹配 | "与您偏好的{偏好}风格相符" |
| 免费 | "免费开放，性价比极高" |
| 低价 | "门票仅{price}元，价格合理" |
| 高评分 | "评分{rating}，口碑优秀" |
| 近热门景点 | "与{otherSpot}相邻，可一并游玩" |

### 每日推荐数量

- 轻松节奏：每天2个景点
- 适中节奏：每天2-3个景点
- 紧凑节奏：每天3-4个景点

# W-5 复盘与思维沉淀流程

> 输入：已完成的事件（项目 / 决策 / 故障 / 争论）及其当时的决策记录（W-3.6 产出优先）。
> 输出：复盘报告 + 可迁移的思维模式沉淀（M-10 的流程化落地）。
> 调度：S-2 溯因（差距归因）+ S-6 批判（自审）+ M-T 溯源（思维链复盘）+ S-4（模式提炼）。
> 场景：项目复盘、决策复盘、故障复盘、个人思维升级。

---

## W-5.1 事实回放【强制】

按时间线回放**事实**（做了什么、发生了什么、数据是多少），全程禁止评价与归因混入。
事实与评价分离是复盘的第一防线（W-1.1 的复盘版）：一开口就"当时要是……"的复盘必然失真（后见之明 B-6 已经开始污染）。

## W-5.2 结果对比与差距归因【强制】

逐项对比预期 vs 实际（用 W-3.1 / W-3.6 记录的验收里程碑与重审条件做基准——无记录的复盘只能重建基准，须声明）。
对每个差距执行 S-2：候选解释 ≥ 3（含"运气"这一平凡解释——区分**流程好但结果差**与**流程差但结果碰巧好**，B-16 乐观偏误的最大藏身处）。

## W-5.3 思维链复盘（元层复盘）【强制】

这是本流程区别于普通复盘的核心步骤——复盘**当时的思维**而非只复盘事情：

1. 重现当时的思维链（决策记录 W-3.6 / 梳理记录 W-1.5 为最佳素材）
2. 逐环节回查：哪个前提被证伪了？（M-P3 的 `[假设]` 变成了什么？）哪步推理跳了（M-T4）？哪个子思维缺位了（该用 S-8 时用了直觉？）？
3. 输出**思维错误模式**：不是"那次我错了"，而是"我在 X 类场景倾向犯 Y 类错误"（个人思维 bug 清单，长期维护）

## W-5.4 模式提炼与迁移登记【强制】

从成功与失败两个方向提炼可迁移模式（S-4 归纳，须过样本代表性检查——单次事件只能产出"待验证模式"）：

- 成功路径：哪个机制起了作用？适用范围（M-P5 防外推）？下次什么场景可复用？
- 失败路径：哪个机制的哪一环断了？预警信号（下次同样错误出现前的早期信号）是什么？

沉淀格式："在 [场景特征] 下，[模式] 倾向于有效 / 失效，预警信号是 [X]，置信度 [低/中]（样本 n=1~N）"

## W-5.5 行动落地【强制】

复盘必须产出三类行动，缺一即无效复盘：

1. **改物**：流程 / 工具 / checklist 的具体修改项（谁、何时、验收标准）
2. **改制**：决策记录 / 重审条件模板的修订建议（体系建议格式，AGENTS.md 7.3）
3. **改脑**：个人思维 bug 清单更新（W-5.3 产出）+ 下次的预警信号绑定

## 反模式

- 【禁止】复盘变追责：一旦指向个人责任，信息流立即失真（系统性错误才是复盘点，S-8.2）
- 【禁止】"下次注意"式结论（无预警信号、无 checklist 修改的行动 = 没有行动，W-5.5）
- 【禁止】单样本提炼"规律"却标高置信度（S-4.3）
- 只复盘失败不复盘成功：成功里的运气成分（S-9 视角）与有效机制同样需要区分

## 示例（微型，节选）

事实（W-5.1）：项目延期 3 周，其中 2 周耗在第三方接口联调（原计划 1 周）。
归因（W-5.2）：候选 = 三方排期冲突 / 我方接口文档滞后 / 排期本身拍脑袋。评估：前两条均成立；第三条候选"运气差"排除（联调依赖外部承诺在过往项目出现率 4/5，S-4 基率）。
思维链复盘（W-5.3）：当时排期把"对方承诺的联调窗口"记成了 `[证据]`，实为 `[假设]`——**前提分级错误**是根思维错误；子思维缺位：S-9.2 基率未查（同类项目历史早有信号）。
模式提炼（W-5.4）："涉及外部承诺的排期，'承诺'应一律按 `[假设]` 分级并加缓冲；预警信号 = 承诺方未书面确认排期"（置信度低，样本 n=1，下两次项目验证）。
行动（W-5.5）：改物——排期模板增加"外部依赖承诺等级"字段；改脑——个人思维 bug 清单 +1："把口头承诺当证据"。

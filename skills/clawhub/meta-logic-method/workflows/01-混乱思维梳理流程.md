# W-1 混乱思维梳理流程（旗舰流程）

> 输入：一团混乱的想法 / 表达 / 争论（自己的或他人的）。
> 输出：一条五环节完整、可审查的有序思维链。
> 调度：`meta/01-思维链法则.md`（M-T3 断点诊断）+ W-1.4 按断点类型动态调度子思维。
> 场景：需求说不清、会议越开越乱、自己"感觉很乱但不知道乱在哪"、AI 收到含混指令。

---

## W-1.1 接收与降噪【强制】

只做两件事，不做其他：

1. **剥离情绪层**：把情绪词（焦虑、生气、抱怨式修辞）与事实性陈述分开记录，只处理事实与诉求；情绪本身可作为"信号"记录（S-7.4），不进入推理
2. **原文固定**：原样摘录关键原句，防止梳理过程中无意识篡改原意（M-P5 的输入端防线）

【禁止】此阶段就开始解释、反驳或给方案——降噪未完成前的一切产出都会被情绪和噪声污染。

## W-1.2 结论与诉求提取【强制】

从降噪后的事实堆里提取：

- **隐含结论**：他到底主张什么？（"每次都这样"背后是"这事有系统性问题"）
- **显式诉求**：他要我做什么？他要什么结果？
- 提取后立即**复述确认**："你的意思是不是……？"——确认前一切提取只是假说（M-6）

## W-1.3 思维链重构与断点定位【强制】

按 M-T3 断点诊断法逐环检查，输出断点定位表：

| 环节 | 检查问题 | 状态 |
| --- | --- | --- |
| 结论 | 结论说清楚了吗？ | 明确 / 模糊 / 缺失 |
| 推理 | 从理由到结论的路径说得出吗？ | 完整 / 跳步 / 缺失 |
| 前提 | 依赖的假设摆上桌面了吗？ | 显式 / 隐含 / 冲突 |
| 概念 | 关键词含义双方一致吗？ | 一致 / 歧义 / 漂移 |
| 问题 | 真正要解决的问题是什么？ | 清晰 / 错位 / 未知 |

## W-1.4 断点修复（按类型调度子思维）【强制】

断点定位后，按类型调度修复，禁止跳过修复直接给方案：

| 断点类型 | 调度 | 动作 |
| --- | --- | --- |
| 概念断点 | meta/02（M-P1） | 给关键概念做操作性定义，双方确认 |
| 前提断点 | meta/02（M-P2 / M-P3） | 隐含前提显式化并分级 |
| 推理断点 | S-3 / S-4 / S-2（按结构） | 补齐跳步 / 替换无效推理 |
| 结论断点 | M-T2 溯源 | 沿"诉求 → 事实"重建结论 |
| 问题断点 | 转 W-2.1 | 用问题陈述规范重新定义 |
| 价值分歧 | M-P6 → S-11 | 显式权衡，不伪装成事实问题 |

## W-1.5 输出有序思维链【强制】

用标准格式输出（AGENTS.md 第 4 节 / `reference/cot-templates.md` R-1），修复后的思维链必须五环节齐全（M-T1），并附断点修复记录（哪个环节曾断、如何修复）——修复记录让后续 Review 能区分"原生结论"与"梳理者代建的结论"。

## W-1.6 复述闭环【强制】

梳理产出必须回放确认：

- **人类场景**：向原表达者复述整理后的思维链，获得确认或修正（W-1.2 的确认在此升级为全链确认）
- **AI 场景**：自查 README 第六节清单 1~5 项，并声明哪些环节是代建（梳理者不得把自己的假设冒充对方的意图）

## 反模式

- 【禁止】梳理者夹带私货：借"帮你理清"之夹带自己的结论（违反 W-1.6，梳理产出须可溯源到原文）
- 【禁止】跳过 W-1.3 直接按自己的理解给方案——那是替换问题，不是梳理问题
- 一次梳理贪多：多个问题混在一段表达中时，先拆成 N 条独立思维链（M-T6 分链）

## 示例（微型）

输入："这项目没法做了，产品天天改需求，说好的排期全是空话，我感觉干下去没意义。"
降噪：情绪 = 沮丧（记录为信号）；事实 = 本周需求变更 N 次、排期承诺未兑现；诉求 = ？
提取：隐含结论"排期不可信"；诉求待确认（是要调整排期？变更流程？还是表达情绪？）
断点：结论明确，但前提（变更不可避免？变更无流程？）与问题（真问题是"变更管理缺失"而非"排期吹了"）断链。
修复：显式化前提"需求变更无评审门槛 `[证据]`"；重建问题为"如何给变更设置成本与门槛"。
输出：五环节链 + 复述确认 + 声明（"真问题"为梳理者代建，待确认）。

# 元逻辑思维体系（Meta-Logic Thinking）

为 AI 与人类在处理**任何事情**时提供的一套"先想清楚、再动手"的元逻辑思维方法体系。

核心理念：**任何混乱的思维背后都有一条可溯源的思维链**。本体系用元逻辑方法溯源整个思维过程——发现它、理顺它、检验它；又因元思维过于根本、不宜直接用于解题，故从元逻辑派生出 12 个子思维技能包，按流程组合求解具体问题。

> 一句话：**元逻辑管"思维是否合法"，子思维管"问题如何解决"。**

---

## 一、为什么需要这套体系（设计动机）

1. **思维需要被审视**：结论的质量取决于思维链的质量，而非表达者的自信程度。多数错误决策源于未被审查的隐含前提与跳步推理，而非信息不足。
2. **混乱思维是隐式思维链**：说不清、想不透、吵不通，本质是思维链断裂、概念漂移或前提未对齐。溯源并显式化思维链，混乱即可理顺。
3. **元思维太根本，不能直接解题**：元逻辑回答"什么是合法的思维"，正如宪法回答"什么是合法的行为"——宪法不告诉你怎么做饭。直接拿元思维解具体问题，等于用显微镜切菜。
4. **因此派生子思维**：从十条元法则（M-1 ~ M-10）派生 12 个可直接执行的子思维技能（第一性原理、溯因、演绎、归纳、类比、批判、辩证、系统、概率、反演、决策、创新），再编排为 5 个流程，覆盖"理清混乱 → 定义问题 → 设计方案 → 创新破局 → 复盘沉淀"全链路。

### 各层的区别

| 层级 | 回答的问题 | 稳定性 | 违反后果 |
| --- | --- | --- | --- |
| **元逻辑法则** meta | "怎样的思维是合法的？" | 长期不变 | 思维链缺陷，结论不可信 |
| **子思维技能** sub-skills | "这类问题用什么思维解？" | 稳定 | 方法错配，解题低效或出错 |
| **流程** workflows | "多步任务怎么编排子思维？" | 场景级稳定 | 环节缺失，产出残缺 |
| **参考速查** reference | "这个谬误/偏误/模板是什么？" | 随认知科学演进 | 误判推理质量 |

## 三、规则等级

所有条目均带等级标签，写在条目编号之后：

| 标签 | 英文对应 | 含义 | 偏离许可 |
| --- | --- | --- | --- |
| 【元法】 | CONSTITUTION | 思维体系的基石，一切思维产出无条件服从 | 无。修订须经人类评审 |
| 【强制】 | MUST | 任何思维活动必须遵守 | 无。违反即为思维缺陷 |
| 【禁止】 | MUST NOT | 不允许出现 | 无。违反即为思维缺陷 |
| 【建议】 | SHOULD | 默认遵守；确实不适用的场景可偏离 | 须说明理由 |
| 【可选】 | MAY | 备选方案，无约束力 | 无需说明 |

**冲突裁决**：按 `元法 > 强制/禁止 > 建议 > 可选` 优先级裁决；同级冲突取约束更严格的一方。

## 四、编号体系

- `M-x`：元法则条目（`M-1 ~ M-10` 总纲主法则；`M-T*` 思维链细则 / `M-P*` 前提概念细则 / `M-L*` 层次调度细则）
- `S-x`：子思维技能（`S-1 ~ S-12` 技能级，`S-x.y` 技能内条目）
- `W-x`：流程（`W-1 ~ W-5` 流程级，`W-x.y` 步骤条目）
- `F-x`：谬误条目；`B-x`：偏误条目；`R-x`：模板条目

引用格式：`依据 M-4`、`参见 S-2.3`。文档之间通过编号互相引用，不复制内容，保证单一事实来源。编号只增不复用、废弃保留占位，治理规则见 `GOVERNANCE.md`。

## 五、如何使用

### 给 AI 思维代理（Claude / GPT / Copilot 等）

1. 将本目录整体放入仓库（或作为系统提示词注入）
2. **AGENTS.md 是唯一入口**——AI 从 AGENTS.md 出发，按任务类型索引到具体文档
3. 产出分析 / 方案时，按 AGENTS.md 第四节"思维链输出协议"输出，结论引用编号（如 "依据 M-9，此结论标记为中置信度"）
4. 作为 DevEco Code 技能包使用时，`SKILL.md` 为加载入口（全局配置 `skills` 路径注册后重启生效），触发后仍以 AGENTS.md 为唯一规则入口

### 给人类

- **初次接触**：通读 `meta/00-总纲.md`（10 分钟），其余按需查阅
- **理清混乱**（自己或他人想不清楚时）：走 `workflows/01-混乱思维梳理流程.md`
- **日常分析**：按场景查 `sub-skills/` 对号入座
- **审查论证**：查 `reference/fallacies.md` 与 `reference/biases.md`
- **复盘沉淀**：走 `workflows/05`

### 典型场景示例

| 场景 | 路径 |
| --- | --- |
| 收到一段语无伦次的需求描述 | W-1 梳理成有序思维链 → W-2 定义问题 → W-3 出方案 |
| 团队争论不休、各说各话 | `meta/02` 定位分歧层级（概念/前提/推理）→ S-7 辩证处理 |
| 线上故障排查根因 | W-2 + S-2 溯因 + S-8 系统定位 |
| 重大技术/商业决策 | W-3 + S-10 反演 + 事前验尸（premortem） |
| 觉得"行业都这么做"可疑时 | S-1 第一性原理拆解 |

## 六、思维质量验收清单（AI Review 时逐条核对）

1. [ ] 问题是否被显式陈述？（M-2）
2. [ ] 关键概念是否有定义且全程无漂移？（M-3 / M-P5）
3. [ ] 前提是否全部显式列出并标注类型？（M-4 / M-P3）
4. [ ] 推理是否逐步可检验、无跳步？（M-T4）
5. [ ] 是否实际调度了子思维而非停留在方法论空谈？（M-7 / M-L2）
6. [ ] 是否主动寻找过反例 / 反证？（M-9）
7. [ ] 结论是否带置信度且与证据强度匹配？（M-6）
8. [ ] 相关是否被误当因果？（S-4.4）
9. [ ] 类比是否被误当论证？（S-5.3）
10. [ ] 是否存在可识别的谬误 / 偏误且已处置？（F-x / B-x）
11. [ ] 行动建议是否包含触发重审条件？（S-11.6）

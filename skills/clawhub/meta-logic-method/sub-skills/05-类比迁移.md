# S-5 类比迁移（Analogy & Transfer）

> 派生自（主）：M-10 迁移法则。把一个领域中被验证的结构映射到另一个领域，启发新方案。类比是**假设发生器**，不是论证形式——它能告诉你"哪里可能有机会"，不能证明"这里一定成立"。

## 适用判据

- **用**：陌生领域破题、跨行业借鉴方案、教学与解释（用熟悉解释陌生）
- **不用**：合规 / 安全等需要确定性论证的决策（类比不能替代论证，S-5.3）

## S-5.1 源域结构提取【强制】

先明确"被借鉴的东西到底是什么"：提取源域中起作用的**结构与机制**（哪些要素、什么关系、为什么有效），而不是表层特征（它长什么样、行业标签是什么）。
提取结果的检验：能否用一句话说清"源域成功的机制"？说不清机制，类比无根。

## S-5.2 结构映射检验【强制】

逐项检查映射质量：

1. **对应检验**：源域的关键要素在目标域都有对应物吗？缺哪个？
2. **机制检验**：源域"要素 A 促成结果 B"的因果链，在目标域走得通吗？（机制可迁移性）
3. **差异检验**：列出两域的关键差异，判断哪些差异会**切断**机制链（哪些只是无害的表层差异）
4. **失配登记**：任何对应不上的要素，显式记录——它们是后续风险清单（S-10）的输入

## S-5.3 类比不是论证【强制】

【禁止】以"X 领域这样做成功了，所以我们这样做也会成功"作为决策依据——这是类比误用作论证（F-6 诉诸类比）。
类比产出物只能是：**待验证假设**（"源域的机制 M 若在目标域成立，则方案 W 可能有效"），验证手段是 S-2 / S-9 / 最小实验（W-4.6）。

## S-5.4 反向警惕（负类比）【建议】

同时检查"源域在哪些条件下失败"：那些失败条件在目标域存在吗？只看成功条件、不看失败条件的类比是半张地图。

## 反模式

- 表层类比："都是平台经济，所以照抄平台打法"（未提取机制）
- 竞品类比依赖症：所有方案都从竞品找参照，放弃第一性拆解（S-1）
- 【禁止】用类比压制质疑："你不懂，人家就是这么成功的"（诉诸类比 + 诉诸权威的复合谬误）

## 与其他子思维的组合

- 源域机制的可靠性常用 S-4 归纳评估（该机制被验证过几次、范围多大）
- 迁移假设的落地风险用 S-10 反演排查（失配登记 → 失败路径）
- 是 S-12 创新思维的核心工具之一（远域联想，W-4.3）

## 示例

源域：丰田精益生产——机制提取："小批量 + 快速反馈 + 停线权"降低缺陷逃逸成本（非"制造业管理术"这一表层标签）。
映射：软件交付 → 小批量 = 小步合并；快反馈 = CI 快速流水线；停线权 = 构建红灯时合入冻结。
差异检验：制造业缺陷可回溯到物理工位，软件缺陷可回溯到提交记录（对应成立）；但"返工成本"两域不同（软件返工相对廉价）→ 登记：小批量的紧迫性权重需下调。
产出（假设而非结论）："小批量机制可能以较弱强度在软件域成立"，由团队实验验证（S-5.3）。

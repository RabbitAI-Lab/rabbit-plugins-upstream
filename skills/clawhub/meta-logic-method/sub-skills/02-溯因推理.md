# S-2 溯因推理（Abduction）

> 派生自（主）：M-1 溯源法则；（辅）：M-6 可谬法则。从观察到的现象出发，反推**最佳解释**：答案不是演绎出来的必然，而是候选中解释力最强的假说。

## 适用判据

- **用**：排查根因（bug、故障、销量下滑）、诊断类问题、证据不全时的初步推断
- **不用**：规则明确、前提完备的场景（直接 S-3 演绎）；纯预测（S-9）

## S-2.1 现象收集与固定【强制】

把观察到的现象原样记录（区分：观察到的**事实** vs 对事实的**解读**——"接口超时率 5%"是事实，"服务不行了"是解读）。
【禁止】先有解释再挑选现象（德州神枪手，F-16）；记录阶段禁止解释。

## S-2.2 候选解释生成【强制】

列出**至少三个**候选解释（含"平凡解释"：最常见、最不性感的那种——配置错了、网络抖动、人为操作失误）。
【禁止】只列一个解释就开始行动：单一候选 = 溯因失效，退化为确认偏误（B-1）。

## S-2.3 解释力评估【强制】

按四个维度给候选解释打分：

1. **覆盖度**：能解释全部现象，还是只解释了舒服的那部分？
2. **简单性**：需要的额外假设更少者优先（奥卡姆剃刀）
3. **可检验性**：该解释预测了什么可观察的新事实？
4. **一致性**：与既有确凿知识冲突吗？

## S-2.4 检验而非采信【强制】

选出的最佳解释是**假说**，不是结论（M-6）。必须设计检验：它能预测什么？去验证该预测。
- 检验通过 → 置信度上调，可标注为"已验证根因"
- 检验不通过 → 回 S-2.2 换次优解释，禁止给失败解释打补丁硬撑（特设性修补，F-18）

## 反模式

- 【禁止】把"时间上先后"当"因果"（post hoc，F-10）
- 【禁止】用"最顺口的解释"替代"覆盖度最高的解释"
- 溯因链无限回溯：每个"为什么"都有成本，回溯到**可采取行动**的层级即停（5 Whys 的实践约定）

## 与其他子思维的组合

- 候选解释的来源常用 S-4 归纳（历史类似案例）与 S-8 系统思维（结构中哪里能产生此现象）
- 检验环节接 S-3 演绎（若解释为真 → 应观察到 X → 去看 X 是否存在）
- 完整流程见 `workflows/02-问题定义与根因分析.md`

## 示例

现象：某接口周四晚高峰超时率 5%（事实）。
候选：① 服务器容量不足；② 周四晚有定时任务抢占资源（平凡解释）；③ 上游依赖变慢。
评估：① 解释不了"仅周四晚"；② 同时解释周期性与高峰特征，覆盖度最高且可检验（预测：关闭该任务后超时消失）。
检验：灰度关闭定时任务 → 超时率回落至 0.3% → 标注"已验证根因"，置信度高。

# 多角色迭代评审闭环

**核心信条:章节写完第一遍,只是"可以送审的草稿",不是成品。** 好教材是改出来的。
本流程用三个"互不接触编写上下文"的盲审角色暴露不同盲区,再据此修订、验收。

## 为什么要盲审、要多角色

- **盲审(blind review)**:评审子 agent 只拿到"章节文本 + 自己的角色设定",拿不到作者的
  写作意图、思路、这份 skill。原因:作者知道的东西会脑补进阅读,读者却没有——只有隔绝
  上下文,才能测出"一个真实读者拿到这章会不会懂"。
- **多角色**:同一份稿子,三种人看见三种问题,互补且常冲突,冲突处恰是设计取舍点。

## 三个评审角色(可按学科微调)

| 角色 | 立场 | 专抓的问题 |
|---|---|---|
| **基础薄弱学生** | 数学/理论弱,只学过前置最低限 | 哪里读不懂、术语没定义、推导跳步、例子太少、太抽象 |
| **进阶/研究生** | 基础扎实,追求深度与独到见解 | 严谨性缺口、定理没证明、成立条件含糊、缺少与其他方法的联系、深度不够 |
| **授课教师** | 明天要拿它上课、出作业考题 | 学习目标/前置缺失、例题习题不足、缺可上机 lab、考点与常见错误、教辅件缺失 |

三者张力:学生嫌难要更多铺垫,进阶嫌浅要更多理论,教师要可教性。**修订不是三者取平均,
而是"分层满足"**——用主线+旁注框+习题+附录把不同需求安置到不同层级(见 methodology 原则 7)。

## 执行步骤

1. **落稿为独立文件**:把当前草稿写成一个 `.md`,不含任何作者笔记/思路。
2. **并行派 3 个子 agent**:各自 prompt = 角色设定 + "阅读该文件" + "你没有作者背景" +
   结构化提问(见下模板)。务必并行(同一条消息里发三个 Agent 调用),省时。
3. **收齐三份报告**,做冲突标注:哪些是共识(必改)、哪些是角色间冲突(需分层设计决策)。
4. **综合成修订清单**,排优先级,逐条落实,产出下一版文件。
5. **回归评审(第 2 轮,可选但推荐)**:把新版再送审(可只送最相关的 1~2 个角色,或让原
   agent 复审"上轮问题是否解决")。通常 1~2 轮即收敛;若仍有硬伤,再来一轮。
6. **验收**:见 acceptance 部分。

## 全局取舍:章节不是孤岛(验收前必须执行)

子 agent 是**孤立审阅**的——他们只看这一章的文本,不知道全书结构。因此,在综合
和修订阶段,**必须由你(作者)**站在全书高度做一次"全局取舍":

### 为什么需要这一步
- 学生/教师/进阶生可能要求本章展开某个概念(如"条件期望严格定义""大 O 记号推导"
  "拉格朗日对偶基础"),但**这些内容可能已经/应该由其他章节承担**。
- 若每章都"自认为需要讲全",全书会臃肿冗余、各章边界模糊、教学节奏被打乱。

### 怎么做(验收前强制执行)
1. 列出三份反馈中**涉及"补充解释/展开"的条目**(而非单纯修正本章错误的条目)。
2. 对每条,判断:**这是本章的核心知识,还是其他章节可以/应该讲的内容?**
3. 分类处理:
   - **本章核心**(如漂移定理证明、漂移-加-惩罚算法、[O(1/V),O(V)] 权衡推导):
     → **本章展开**,完整覆盖。
   - **前置知识/工具性知识**(如条件期望、裂项求和、大 O 记号、拉格朗日对偶基础):
     → 本章只给**附带注说明**(一行定义或一框简释),并注明"详见第 X 章(前置)"。
   - **属于后续章节的自然延伸**(如背压的吞吐最优性深入证明、MDP/在线凸优化的
     完整对应、虚拟队列在其他场景的应用):
     → 本章给**结论 + 直觉 + 一瞥**,标明"详细分析见第 Y 章(延伸)"。
4. 在修订版中,**显式标注"详见/前置"引用**——这不只是方便读者,也是对你自己的约束:
   你承诺了某章会讲这个内容,那写那章时就必须兑现。

> **反例**:李雅普诺夫章把"条件期望、裂项求和、大 O 记号"各展开半节——结果第 2 章
> (数学预备)已经讲过了,冗余且拖节奏。**正例**:第 2 章有"裂项求和"解法,本章只写一句
> "望远镜求和(见 §2.X)",两行推导就够了,不重复也不悬空。

## 给评审 agent 的 prompt 模板(照抄改角色即可)

> 你是【角色设定:身份、知识背景、在意什么】。你的任务:阅读文件 `<绝对路径>`(一章
> 教材草稿),站在你的身份**诚实/严格地**评价它。**你没有关于作者意图的任何背景。**
> 请具体到章节号和原句回答:
> 1. 【该角色最该抓的维度一,如"哪里读不懂/哪里不严谨/哪里没法教"】
> 2. …(3~6 个针对该角色的追问)
> N. 给出**清单式修改建议(至少 8~10 条)**,每条指明"在哪一节、补什么",标注优先级。
> 不要客套凑数,你的价值在于暴露真实问题。输出结构化评审报告。

要点:让每个角色**专注自己的维度**(别让学生去评严谨性);要求**具体到位置**、**清单化**、
**给示例**(如让教师直接出几道习题、让进阶生指出该补哪条定理证明)。

## 迭代收敛判据(什么时候可以停)

- 三个角色的**高优先级**问题都已落实或有意识地取舍(取舍要在文中或小结交代);
- 新一轮评审不再冒出"硬伤级"问题(读不懂/证错了/没法教),只剩润色级建议;
- 通过下面的验收门槛。达到即停,避免无限打磨。

## 验收门槛(Acceptance Gate)

修订收敛后,交付前最后一道关。逐条核验,任一"否"则打回:

**深度类**
- [ ] 核心概念有严格定义、成立条件(必要时反例)?
- [ ] 关键定理给了可读的完整证明/推导,而非只有结论?
- [ ] 有时间/空间复杂度、收敛性、边界情况、与相邻方法的对比分析?
- [ ] 有可运行的完整代码(非仅伪代码)+ 一个能出结果的实验?

**教学类**
- [ ] 有学习目标、前置知识、符号表、小结要点表、延伸阅读?
- [ ] 每个核心概念后有带完整解答的例题?
- [ ] 习题分易/中/难,覆盖计算/证明/编程/开放题,数量足够(通常 ≥8)?
- [ ] 标注了考点与学生常见错误/误解?

**由浅入深类(对照 checklist.md 全部条目)**
- [ ] 动机先行、锚定已知、具体先于抽象、术语即时拆解、螺旋上升、信息分层、闭环。
- [ ] 三个评审角色的高优先级问题均已闭环(可列一张"问题→如何解决"对照表自查)。

**全局取舍类(章节非孤岛)——验收前必须过**
- [ ] 是否按"全局取舍"流程梳理了三方反馈中涉及"补充解释/展开"的条目?
- [ ] 对每条:是否已判断是"本章核心"还是"其他章节承担"?
- [ ] 所有"其他章节承担"的内容,是否已在文中**显式标注引用**(如"详见第 X 章"或"前置:§X.Y")?
- [ ] 冗余自查:没有长达半节的内容在重复另一章的职责?
- [ ] 悬空自查:标注引用的章节号是否存在?是否写了"详见"但实际没计划写?

**产出**:一句话验收结论(通过/打回)+ 若通过,附"本轮相对上一版改了什么"的变更摘要。

# 自检清单

写完一个章节/小节后逐条核对。任何一条为"否",回去改。

## 动机与切入(原则 1、2)
- [ ] 每个核心概念登场前,读者已经知道"为什么需要它"了吗?
- [ ] 开头是从读者已知的东西切入,而不是从陌生定义切入?
- [ ] 有没有一句清晰的"核心问题"统领全章/全节?

## 具体与直觉(原则 3、4)
- [ ] 每个抽象概念旁边,是否有一个具体的锚(例子/代码/图/类比)?
- [ ] 抽象是"从具体里提炼出来"的,还是凭空砸下来的?
- [ ] 有没有用一个现象或意外,激发读者"为什么"的好奇?(适用时)

## 术语与负荷(原则 5、6)
- [ ] 每个术语第一次出现时都解释了吗?(通读一遍,专挑术语)
- [ ] 单个段落是否塞进了超过 1~2 个新术语?
- [ ] 有没有一次性堆砌了本可推迟的细节?简化处是否说明了"这是简化"?
- [ ] 复杂机制是不是"分层递进"讲的,而非一口气讲全?

## 结构与分层(原则 7)
- [ ] 主线叙述是否干净?旁支信息是否移进了"框"或脚注?
- [ ] 关键问题、通用原则、趣味补充是否分流到了合适的层级?
- [ ] 章末有没有小结、回扣开头的核心问题、预告下一步?

## 读者体验(整体)
- [ ] 把自己当成目标读者,从头读一遍——有没有哪一句会"卡住"?
- [ ] 相邻两段之间有没有逻辑跳跃?过渡是否自然("下面来看……""问题在于……")?
- [ ] 语气是否贴合目标教材?有没有翻译腔、空洞的套话("综上所述""众所周知")?
- [ ] 读者读完这一节,能不能用自己的话复述核心心智模型?

## 详略判断(最容易失手的地方)
- [ ] **主线概念**:是否给足了篇幅、层层展开?(如系统调用/陷阱这类核心机制)
- [ ] **非主线**:是否克制、一句带过或推迟?(如某个优化、边角历史)
- [ ] 详略的依据是"对理解核心问题有多重要",而不是"作者自己知道多少"。

## 深度(教材级,别停在博客级 —— 详见 SKILL.md 深度基线)
- [ ] 核心概念有严格定义、成立条件、必要时反例?
- [ ] 关键定理给了**可读的完整证明/推导**,不是只抛结论?
- [ ] 有复杂度/收敛性/边界情况分析,并与相邻方法做了对比?
- [ ] 有**可运行的完整代码**(非仅伪代码)+ 一个出得了结果的实验?
- [ ] 每个核心概念后有带解答的例题?习题分难度、够数量、覆盖多题型?
- [ ] 有学习目标、前置知识、符号表、要点表、延伸阅读等教辅件?

## 迭代闭环(见 review-loop.md)
- [ ] 是否已把草稿送三个盲审角色(基础弱学生/进阶生/教师)审阅?**三个必须全齐**,不可只派一两个。
- [ ] 三方高优先级反馈是否已落实或有意识取舍(并在文中/小结交代)?
- [ ] 是否按 review-loop.md §全局取舍做了**全书视角的删补决策**(非本章核心 → 引用前置/后续章)?
- [ ] 文中"详见第 X 章/§X.Y"的引用是否都真实存在、不悬空?
- [ ] 是否通过了 review-loop.md 的验收门槛?**跳过验收即不合格。**

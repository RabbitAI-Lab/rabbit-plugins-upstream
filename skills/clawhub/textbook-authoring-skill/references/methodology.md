# 方法论:七条原则展开

每条给出:**做什么 / 为什么有效 / 怎么做 / 反例(新手常犯)**。范例出处见 exemplars.md。

## 1. 动机先行,而非定义先行

- **做什么**:在给出一个概念的定义之前,先让读者感到"这里缺了个东西"或"这有个麻烦"。
- **为什么**:人只对自己想知道答案的问题上心。定义先行时,读者没有挂钩去挂住新信息。
- **怎么做**:
  - 用一句"关键问题"开场:如"只有少量物理 CPU,操作系统如何提供近乎无限 CPU 的假象?"
  - 概念作为这个问题的**答案**登场:"操作系统通过虚拟化 CPU 来提供这种假象……"
  - 讲一个概念的诞生史/来由(K8s 先讲 Google-Borg 的故事,再讲 K8s 是什么)。
- **反例**:"进程是运行中的程序。进程有以下状态……"——读者不知道为何要有"进程"这个词。

## 2. 锚定已知

- **做什么**:从读者已经掌握的事物出发,用类比在"已知"和"未知"之间搭一座桥。
- **为什么**:新概念挂在旧概念上才记得住;悬空的定义留不下痕迹。
- **怎么做**:
  - 找读者百分百懂的锚点:"程序运行就是执行指令:取指、译码、执行"——从这里再展开。
  - 用贴切类比:虚拟化=一个桃子分给很多人;K8s=云上的操作系统、=快递公司帮你送货。
  - 类比要**诚实**:用完点破它的局限(桃子那段学生追问"其实只有一个桃子啊",教授承认)。
- **反例**:一上来就用读者不熟的术语解释新术语,套娃式定义,越读越晕。

## 3. 具体先于抽象

- **做什么**:先给具体的东西(能跑的代码+真实输出、一张图、一个生活场景),再抽象出原理。
- **为什么**:抽象是从具体里"提取"出来的;没见过具体,抽象无处落脚。
- **怎么做**:
  - 先展示现象:给一段 20 行的 C 程序 + 它的真实输出,让读者亲眼看到"发生了什么"。
  - 再命名与抽象:"这正是操作系统虚拟化内存时发生的情况……每个进程有自己的地址空间。"
  - 工程主题用具体场景代替代码:"一个电商系统由 Web 前端、购物车、鉴权……组成"讲微服务。
- **反例**:整节只有定义和分类,没有一个例子,读者读完仍不知道它长什么样。

## 4. 制造意外驱动好奇

- **做什么**:抛出一个违反读者直觉的现象,让"为什么会这样?"成为读者自己的问题。
- **为什么**:惊讶会打开注意力窗口;带着疑问读原理,比被动接收记得牢。
- **怎么做**:
  - 先让读者预测:"两个线程各加 1000 次,你猜计数器最终是多少?"(读者答 2000)
  - 再打脸:"结果是 143012 // what the??"再运行一次又不一样——引出并发/原子性。
  - 意外之后**紧接着**给解释,别把读者晾在困惑里太久。
- **反例**:平铺直叙"由于竞态条件,结果不确定",读者点头而过,没留下任何印象。

## 5. 术语即时拆解,不堆砌

- **做什么**:术语第一次出现就解释;若不得不先给密集定义,要坦承并随即逐个拆开。
- **为什么**:未解释的术语是理解的断点,攒够几个读者就弃读了。
- **怎么做**:
  - 首现即释义,给中英对照:"编排器(orchestrator)是一套部署和管理应用的系统。"
  - K8s 的招式:先甩满是术语的定义,主动说"读者可能感觉术语太多",然后一节拆一个,
    最后**回头重述**那个定义——此时读者全懂了,形成闭环。
  - 一段里别引入超过 1~2 个新术语。
- **反例**:一句话里塞进"云原生、微服务、声明式、控制平面",全部不解释就继续往下。

## 6. 螺旋上升、延迟细节

- **做什么**:先给一个正确但简化的版本让读者能用,把复杂细节明确推迟到后面。
- **为什么**:认知负荷有上限;一次讲全,读者哪个都记不住。
- **怎么做**:
  - 明说延迟:"真实的进程 API 放到第 5 章讲,这里先说接口该包含什么。"
  - 分层递进:先"直接执行"→暴露问题→加"受限"→再暴露新问题→补陷阱表。每轮只加一点。
  - 简化时**说明这是简化**,别让读者以为这就是全部。
- **反例**:第一次讲某机制就把所有边界情况、优化、历史全塞进来,主线被淹没。

## 7. 信息分层 + 闭环

- **做什么**:主线叙述保持干净;把旁支信息放进专门的"框";章末回扣开头。
- **为什么**:不同信息重要度不同,混在一起主线就断了;闭环给读者"学完了"的确定感。
- **怎么做**:
  - 用固定样式的框分流(见下),主线只跑主干逻辑。
  - **关键问题框**:点明本节要解决的核心问题。
  - **提示/设计原则框**:抽出可迁移的通用原则(如"分离策略与机制")。
  - **补充/趣闻框、脚注**:满足好奇但非必读的内容(名字由来、历史八卦)。
  - 章末小结重述要点,回扣开头的核心问题,预告下一章。
- **反例**:所有内容一个层级平铺,读者分不清哪是主干哪是花絮;章节戛然而止无收尾。

# 📖 Textbook Authoring

## 这个 Skill 解决什么问题？

新手作者（无论是人类还是 AI）写教材时有一个通病：**定义先行、术语堆砌**。上来就是"X 是……"、"Y 的定义是……"，读者不知道为什么要学这个概念、它跟已知的东西有什么关系，只能死记硬背。

优秀的教材反着来——**先让读者想知道答案，再给答案**。

本 Skill 提炼了公认好读的教材的写作手法，转化为可执行的原则、工作流和自检清单。它强制 AI 走完"写作 → 三角色盲审 → 修订迭代 → 验收"的完整闭环，确保输出的每一章都经得起真实读者的检验。

## 核心特色

### 七条写作原则

| # | 原则 | 一句话解释 |
|---|------|-----------|
| 1 | **动机先行，而非定义先行** | 先让读者感到"缺了个东西"，概念作为"问题的答案"登场 |
| 2 | **锚定已知** | 从读者已经懂的事物出发，用类比搭桥，再引入新概念 |
| 3 | **具体先于抽象** | 先给能跑的例子、真实输出、生活场景，再抽象出原理 |
| 4 | **制造意外驱动好奇** | 用反直觉现象（如"你以为是 2000，结果是 143012"）逼出"为什么" |
| 5 | **术语即时拆解，不堆砌** | 首次出现就解释；若必须先甩一堆术语，要坦承并随即逐个击破 |
| 6 | **螺旋上升、延迟细节** | 先给可用的简化版，明说"细节稍后讲"，不让读者一次背负全部复杂度 |
| 7 | **信息分层 + 闭环** | 主线保持干净，用"关键问题/提示/补充"框承载旁支；章末回扣开头 |

### 十步工作流（强制完整执行）

```
写作阶段                      迭代阶段                      验收
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 明确读者与前置知识          7. 落稿为独立文件              10. 对照清单逐条核验
2. 定一句话核心问题    ──→     8. 三角色并行盲审              →   给出验收结论
3. 设计叙事弧线                (学生/进阶生/教师)                + 变更摘要
4. 由浅入深填充               9. 综合反馈 → 修订 → 再评审
5. 加深度分层                  (迭代 1~2 轮至收敛)
6. 闭环收尾
```

### 三角色盲审机制

草稿写完后，由三个互不接触编写上下文的子 Agent 并行盲审：

- 🧑‍🎓 **基础薄弱学生** — 测"读得懂吗？够不够详细？"
- 👨‍🔬 **进阶/研究生** — 测"够不够严谨？够不够深？"
- 👩‍🏫 **授课教师** — 测"能不能直接拿去教？例题习题够不够？"

三者反馈常有冲突——学生嫌难要更多铺垫，进阶生嫌浅要更多证明，教师要可教性。修订不是三者取平均，而是"分层满足"：主线给学生，旁注框/附录给进阶生，习题与教辅件给教师。

### 全局取舍：章节不是孤岛

子 Agent 是孤立审阅的，只看到一章。因此在综合反馈时，作者必须站在全书高度做一次"全局取舍"——某条"补充解释"类反馈，是本章核心就展开，属于前置/后续章节的就只给引用（"详见第 X 章"），避免全书臃肿冗余。

## 使用方法

在 Claude Code 中，用自然语言描述你要写的章节即可触发此 Skill：

### 基本用法

```
帮我写第 3 章"进程调度"，读者是大二计算机本科生，已经学过第 2 章的进程概念。
```

```
把这段虚拟内存的讲解改得更易懂一些，用 OSTEP 那种风格。
```

```
我要写一本 Kubernetes 入门教材的第 1 章，读者是转行工程师，有基本 Linux 使用经验但没接触过容器。
```

### 进阶用法

- 写作前如读者对象、前置知识、篇幅、深度不清楚，Skill 会主动追问再动笔
- 需要模仿"语感"和详略节奏时，Skill 会参考 `exemplars.md` 中标注过的原书范例
- 输出用中文（或你指定的语言），风格自动贴合目标教材类型：
  - 学术主题 → OSTEP 式的严谨 + 对话感
  - 工程主题 → K8s 式的口语 + 类比

### 适用的教材类型

本 Skill 最适合**技术/计算机类**教材章节的写作与修订，包括但不限于：

- 操作系统、计算机网络、数据库等计算机核心课程
- 编程语言、框架、工具的入门与实践教材
- 机器学习、分布式系统等进阶主题
- 任何需要"由浅入深、循序渐进"讲解的技术内容

## 设计哲学

> **教材靠迭代打磨出来，一遍写完只是草稿，不是成品。**

本 Skill 强制一个信念：好教材不是一次性写出来的，而是通过"写 → 审 → 改 → 再审 → 验收"的闭环迭代出来的。它内置的盲审机制刻意隔绝了作者的写作上下文——因为作者知道的东西会脑补进阅读，读者却没有，只有这样才能测出"一个真实读者拿到这章会不会懂"。

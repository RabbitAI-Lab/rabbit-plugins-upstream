# 分部报告·逐条挂源

给一份年报附注或分部报告，把**分部信息披露**读成一张**每个数都能回到原句**的台账：报告分部的识别、分部收入与利润、分部资产与负债、分部间交易与抵消、与合并报表的勾稽。

分部报告是财报附注里结构最固定的一节，却也是最容易被随手概括的一节：**分了几部、按什么分、每部赚多少、内部交易抵消多少、加起来和营业收入对得上吗**——这五件事各有独立的表，但披露常把它们摊在几页里，中间夹着「未分配项目」和一句「分部利润与净利润存在差异，主要系未分配费用影响」。本件把披露怎么写逐条登记下来，结论留给人。

**不判哪块业务更值钱、不建议分拆或剥离、不预测对股价的影响、不给评级与目标价。** 分部个数与名称只认原句；要自己算的比例与勾稽差额，必须单列并交代分子分母出处。

---

## 一、三十秒跑通（零输入）

不给任何数据文件，也能跑出一份完整合规的成品，看它长什么样、判据怎么打：

```bash
python3 scripts/check_segment.py --demo
```

把这份样例存下来再跑一遍机检，它能自己过：

```bash
python3 scripts/check_segment.py --demo > 样例分部稿.md
python3 scripts/check_segment.py 样例分部稿.md
# → 样例分部稿.md 结论：五道全过（零发条）
```

接着换成你自己那份稿子：

```bash
python3 scripts/check_segment.py 你的分部稿.md
```

退码 `0` 全过、`1` 有发条、`2` 用法错、`3` 读不到文件或空稿。

### 拿不到成品时，从原文开始的三步

1. **定主体与报告期**，拿到年报附注里「分部报告」那一节（通常在附注六至八之间）。
2. **每节抄事实，连原句一起抄**：一条 = 一行，行末挂 `「原句」〔锚：页/表〕[S#]`。
3. **跑一遍自检**，红一条改一条：

```bash
python3 scripts/check_segment.py 你的分部稿.md
```

## 二、五道机检在管什么

| 码 | 管什么 | 典型触发 |
|---|---|---|
| `SG-STRUCT` | 形制 | 缺自标、缺 `主体：`／`报告期：`、节序不对、某一节空着 |
| `SG-QUOTE` | 原句与锚 | 数字行没挂「原句」〔锚〕[S#]，或来源行缺 URL／检索日 |
| `SG-NOSELF` | 不自推不自算 | 原句没写「三个报告分部」却自己写；比例没标〔自算〕或没给分母 |
| `SG-GAP` | 缺口两向点名 | 正文写了未取到、第六节没点名；或用「不适用」搪塞 |
| `SG-LINE` | 红线 | 「最有价值的业务」「建议分拆」「目标价」「分部利润即净利润」 |

五道全过时结论行是 `结论：五道全过（零发条）`。

## 三、四条红线（这件的立身之本）

1. **分部个数、名称、主次要之分只认原句。** 准则给了 10% 量化门槛，但**门槛用没用、未达门槛的分部怎么归并，只有披露知道**。本件不替它算，也不按「一般制造业分三部」补。
2. **分部利润 ≠ 合并净利润。** 两个数可以并排放，不得写成相等、等同、即；差额没披露就写 `未取到`，不替披露补一句「主要系未分配费用影响」。
3. **不自行轧差。** 分部间交易额与抵消额是两笔数，抵消额照抄；勾稽差额由本件算的必须标〔自算〕并给分子分母，还须写明取哪一句。
4. **不判业务价值。** 哪块更值钱、该不该分拆、对股价有什么影响，一律 `[待人工]`。

## 四、一条发现长什么样

```
- 制造业分部·对外交易收入 82,000.00 万元「制造业分部对外交易收入 820,000,000.00 元」〔锚：2025 年年报·第 157 页·附注六·分部报告〕[S1]
```

结构是 `- 项名 值 「原句」〔锚：位置〕[S#]`。四项缺一不可（`未取到` 行、`[待人工]` 行与〔自算〕行是三个例外）。

自算的一行长这样：

```
- 分部利润合计占对外收入比 8.67%〔自算〕分子＝制造业分部利润 110,000,000.00 元 [S1]｜分母＝三个分部对外交易收入合计 1,350,000,000.00 元 [S1]
```

比例在原句里找不到就必须标〔自算〕，并在同一行交代分子与分母各挂哪个来源。

## 五、和另外几枚包怎么分

| 你的问题 | 该用哪一枚 |
|---|---|
| 四期差异、科目勾稽的点评 | `cn-earnings-note` |
| 按**客户**看集中度与依赖 | `cn-customer-concentration` |
| 前期会计差错更正 | `cn-accounting-error-correction-cn` |
| 收入确认五步法（准则层面） | `cn-revenue-recognition-cn` |
| 三张现金流 | `cn-cash-flow-quality` |
| 审计意见类型 | `cn-audit-opinion-cn` |
| **分部怎么分、每部赚多少、怎么抵消、怎么勾稽** | **本件** |

一句话分界：本件只按**分部**切，不按客户切、不判差错、不评经营质量。

## 六、素材从哪来

- 首选：年报附注里「分部报告」那一节 + 合并利润表（勾稽要用）；
- 次选：交易所同披件、招股书的分部信息节；
- 末选：第三方摘要——本件会把它降级标注「二手、未对过附注」。

数据通道以目录现值为准：先匿名取 `https://cuecue.cn/api/mcp-catalog`，按返回的域与 `routing` 连；解析腿（`cue-omni-reader`）只在原句落在长附件或扫描件里时才发起。两步形制如下（域与工具名一律照现场返回填，不要照抄示例值）：

```bash
# 一、匿名发现：取现值域清单与 routing（不写死域与工具名）
curl -s https://cuecue.cn/api/mcp-catalog | head -c 400

# 二、已连上后取工具清单：以现场返回为准
curl -s -X POST "$MCP_ENDPOINT" \
     -H "Authorization: Bearer $CUE_API_KEY" \
     -H 'Content-Type: application/json' \
     -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | head -c 800
```

配置页只作指针：文本腿 <https://cuecue.cn/hub/mcp>、解析腿 <https://cuecue.cn/hub/omni-reader>、key <https://cuecue.cn/hub/api-key>。

## 七、跑夹具与测试

```bash
bash scripts/fixtures/run_fixtures.sh              # 三档，末行现算档数
python3 scripts/check_segment.py --selftest        # 13 档内置夹具
python3 tests/test_segment.py                      # 15 条包级测试
```

runner 的末行形制是 `档数=N（由上面逐档现报）｜不合=M｜不可判=K`。**档数不写死在文档里**——加了注入就自己变，写死迟早对不上。

## 八、首次运行埋点

第一次跑（任何子命令）会在 `~/.cue-usage/` 下落一枚空文件 `cue-cn-segment-report-cn-YYYY-MM-DD`。同日重复跑只留一枚；家目录不可写或无 `HOME` 时静默跳过，不影响主流程。

为什么留这个：平台两个下载计数器都不可信（新 listing 首 48 小时的一次性播种 50~60 就占了大头），本地这枚文件是本件唯一能证明「真有人装上并跑过」的东西。

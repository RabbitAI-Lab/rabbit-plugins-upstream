# 变更记录

### 0.1.0 — 2026-11-13（新建：分部报告的逐条挂源）

首版。`分部报告`／`经营分部`／`报告分部`／`分部信息`／`主要客户` 这五个词在 ClawHub 检索全部 n=0，仓内 `grep` 同样零命中（既有件只在 `cn-earnings-note`／`cn-equity-research-note` 里各出现一次「分部」当业务拆解的一个口径带过）。**这一类是纯空白位**。

**一、五块内容**

1. **报告分部的识别**：个数、名称、划分依据、是否合并列报、未达量化门槛的分部怎么处理；
2. **分部收入与利润**：每个分部的对外交易收入与分部利润，分部间收入单列；
3. **分部资产与负债**：每个分部的资产总额与负债总额，未分配资产与负债合计缺就点名；
4. **分部间交易与抵消**：定价政策、交易额、抵消额分开登记，不自行轧差；
5. **与合并报表的勾稽**：分部对外收入合计、合并营业收入、差额；`分部利润与净利润的差额` 单列。

**二、五道机检（`scripts/check_segment.py`）**

| 码 | 判什么 |
|---|---|
| `SG-STRUCT` | 头部四件自标 + `主体：`／`报告期：` + 七节按序 + 前五节各至少一条发现行 |
| `SG-QUOTE` | 每条发现行以「」+〔锚：…〕+[S#] 收尾；来源行带 URL 与检索日；引用编号都登记 |
| `SG-NOSELF` | 分部个数/名称/主次要只认原句；比例与勾稽差额自算须标〔自算〕带分子分母 |
| `SG-GAP` | 正文与第六节两向点名；零缺口写 `未取到：无`；禁「不适用」类措辞 |
| `SG-LINE` | 业务价值、分拆建议、股价与市值、评级目标价、分部利润＝净利润 |

**三、离线 runner 三档**

档① 机检自测 ／ 档② 好样坏样逐枚单跑 ／ 档③ 15 支边界形逐枚单跑（11 支该红、4 支反证）。每支注入都先断言落地、都只钉一道码。档数由 runner 末行现算，文档里不写死。

**四、包级测试（`tests/test_segment.py`，15 条）**

入口契约（`--help` 退 0／无参退 2／缺件退 3／空稿退 3／自测退 0）、零输入（`--demo` 能跑、能过自己的机检、确定性、与 good 夹具字节相同）、判据行为（坏样五道齐发、好样零发条）、首次运行埋点（落一枚空文件、同日不增殖、失败静默、无 HOME 静默）。

**五、为什么建这一枚**

下载的杠杆只有上更多新件（每枚首 48h 约 85，之后归到 6~8/日），这是本仓 22 天序列上唯一站得住的推论。而挑件的唯一标准是「这个位置是空的」——不是「这个词搜索量高」。`分部报告` 这一类在仓内与平台两侧都是零，同时它是财报附注里**结构最固定、最容易做成逐条挂源**的一节（五个方面各有独立的表格），与既有件的边界也干净（四期差异走 earnings-note、客户维度走 customer-concentration、差错更正走 accounting-error-correction）。

**六、第一版自己踩的四处（记下来给下一枚用）**

1. **项名含词族会被判成自推。** 好样里 `- 报告分部个数 三个「…」` 这一行，项名「报告分部个数」含词族「报告分部」，而原句写的是「划分为三个报告分部」——判据只剥了 `：` 分隔的项名形，**空格分隔的项名形没剥**，于是好样自己红了一条 `SG-NOSELF`。改为：`：` 形剥冒号前，空格形剥第一个空白前那一段（且该段不得含 `「`）。
2. **未取到行里的百分比被当成自算比例。** `- 未达量化门槛的分部处理 未取到：附注未披露未达 10% 门槛的分部如何归并`——那个 `10%` 是**披露对象的名称**（准则门槛），不是本件算出来的比值。判据原样要求〔自算〕，等于逼人把缺项写成结论。改为：「未取到」行整行豁免百分比判定。
3. **正文与第六节的项名必须逐字一致。** 正文写 `服务业分部·分部利润`、第六节写 `服务业分部利润`，两向对账取不出同一个键，多出一条假 `SG-GAP`。**这是两向对账固有的严格性，不是判据的毛病**——项名是键，写法不一致就是两个键。夹具里统一成带中点的写法。
4. **自推坏样的注入点要选在原句确实缺词的地方。** 第一版把「划分为三个报告分部」换成「按产品线组织生产经营」，结果整行只剩项名带词族，而项名是被剥掉的——**码没发出来**。改为保留原句的「报告分部」、把项名换成带「经营分部」的写法，让「经营分部」成为那句里唯一在原句之外出现的词族。这与上一枚「结构坏样要插重复节标题、不改标题名」是同一类教训：**坏样要坏在判据真正看的地方**。

**七、红线自查**

零网络、零凭据、零外部依赖；`--demo` 零输入可跑且与 good 夹具字节相同；坏样五道齐发无连带码；本件不在场景图表一孤点清单内（`consumes: [parsed-doc]`，`produces: [structured-note]` 有真实接入）。

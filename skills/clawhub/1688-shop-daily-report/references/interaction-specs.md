# 交互组件详细规范

本文档定义了 1688-shop-daily-report Skill 中所有交互组件的具体数据结构与映射规则。大模型在调用 `show_interaction` 前需查阅本文档，确保数据结构正确。

---

## 1. select_action (Card 组件)

### 组件类型

`type: card` — 日报输出完成后，根据报告中"今日行动重点"动态生成可执行的行动选项，让用户选择要立即执行的操作。

### 触发条件

- 日报 Markdown 报告输出完成后
- Agent 必须先完成报告生成，再触发此交互
- 禁止在报告输出前或中途触发
- ⚠️ **不得阻塞报告输出**：构造 select_action 所需的一切判断（包括行动选项匹配、**定时任务状态检查**等）均须在报告输出 **之后** 进行。严禁在报告输出前停留在任何检查/查询上，导致日报迟迟不出

### 数据槽位定义

- **`questions`**:
  - 类型: `Array<Object>`
  - 说明: 问题列表，每项包含 `question`（问题文本）和 `options`（选项数组）
  - 端侧会自动追加"输入其他"选项

### 构造规则

1. **动态生成**：选项不是固定的，Agent 必须根据当天日报中实际输出的"今日行动重点"来决定展示哪些选项
2. **数量限制**：最少 1 个，最多 3 个选项
3. **排序**：按行动优先级从高到低排列（🔥🔥 高优 > 🔥 中优 > 普通）
4. **选项文案格式**：`emoji + 行动名称（简短说明）`，简短说明来自日报行动重点的内容
5. Agent 应根据行动重点内容，匹配以下关键词来生成对应的行动选项：

| 行动重点关键词 | 选项 emoji + 名称 | 对应技能 |
|--------------|------------------|---------|
| 主图、图片、优化图 | 🖼️ 优化商品主图 | `1688-item-image-optimizer` |
| 标题、关键词、SEO | ✏️ 优化商品标题 | `1688-item-title-optimizer` |
| 商品诊断、商品问题、单品分析 | 🔍 商品分析 | `1688-product-analysis` |
| 店铺体检、全面检查、店铺健康 | 🏥 店铺经营诊断 | `1688-shop-health-check` |
| 聊天、客服、服务质量、响应 | 💬 询盘质检 | `1688-inquiry-evaluate` |
| 客户、买家、询盘跟进、机会 | 👥 买家客户管理 | `1688-shop-zkt-buyer-manage` |
| 跟进话术、客户沟通、回复 | 🗣️ 客服接待路由 | `1688-cowboy` |
| 流量异常、流量下降、异常提醒 | ⚠️ 店铺流量异动诊断 | `1688-shop-abnormal-alert` |
| 数据分析、查看数据、更多数据、深入分析 | 📊 数据查询分析 | `1688-shop-freedom-query-data` |

### 定时任务推荐选项（条件型，非关键词驱动）

除上述由"今日行动重点"关键词动态生成的选项外，还需按以下规则判断是否追加「⏰ 想每天自动生成这份店铺日报？点击设置定时任务」选项。该选项**不由行动重点驱动**，而是根据牛顿客户端定时任务状态条件触发：

1. **检查时机（重要）**：定时任务状态检查必须在**日报报告输出之后**、构造 select_action 时才进行，**绝不可放在报告输出前**，以免阻塞日报
2. **展示条件（默认展示 / fail-open）**：只要**没有明确查到已存在日报定时任务**，就应追加此选项。包括以下情形均默认追加：检查发现未开启、**无法检查（没有相应能力）、检查超时或失败**。仅当**确实查到已存在**相关定时任务时，才不展示（避免重复设置）。⚠️ 切勿因“无法确认状态”而默认不展示，否则该选项会永远不出现
3. **位置**：作为附加选项排在所有动态行动选项之后（最后一个）；计入"最多 6 个"上限，若超限则裁剪优先级最低的动态行动选项以保留本选项
4. **选项文案**：`⏰ 想每天自动生成这份店铺日报？点击设置定时任务`
5. **已存在定时任务时：静默跳过，什么都不展示（重要）**：当查到已存在日报定时任务时，**唯一做法是静默跳过该选项，不向用户展示任何与定时任务相关的内容**——既不追加“设置定时任务”选项，也**绝不把“已为您设置了「经营日报」定时任务…”之类的陈述文案作为选项放进 select_action 卡片**（它不是可执行动作，作为选项出现即为错误），更不得输出内部判断过程或技术字段（如 `id`、`enabled=true`、`schedule`、“因此不需要追加”之类）。简言之：**没设置才出这个选项，设置过就当它不存在、什么都不说**。

### 完整数据示例

假设日报中的"今日行动重点"为：
1. 🔥🔥 优化低点击率商品主图，提升 CTR
2. 🔥 跟进新增询盘客户，提高转化率
3. 检查标题关键词覆盖，补充热搜词

则构造的交互数据为：

```json
{
  "questions": [
    {
      "question": "📋 以上是今日经营日报。根据数据分析，建议您优先执行以下行动，请选择：",
      "options": [
        "🖼️ 优化商品主图（提升低点击率商品的 CTR）",
        "👥 客户机会识别（跟进新增询盘客户，提高转化率）",
        "✏️ 优化商品标题（检查关键词覆盖，补充热搜词）"
      ]
    }
  ]
}
```

> 报告输出后，只要**未明确查到已存在**日报定时任务（包括未开启、无法检查、检查超时或失败），就在上述 `options` 末尾追加一项：`"⏰ 想每天自动生成这份店铺日报？点击设置定时任务"`；仅当确实查到已开启时才不追加。
>
> ⚠️ 确实查到已开启时，**直接不追加该选项，也绝不把“已为您设置…”之类陈述文案放进 `options`**（它不是可执行选项，出现即为错误）；同时禁止输出任何内部判断过程或技术字段（id / enabled 等）。参见上文「定时任务推荐选项」第 5 条：静默跳过，什么都不说。

### 用户选择后的处理

| 用户选择 | Agent 行为 |
|---------|-----------|
| 🖼️ 优化商品主图 | 直接调用 `1688-item-image-optimizer` 技能开始执行 |
| ✏️ 优化商品标题 | 直接调用 `1688-item-title-optimizer` 技能开始执行 |
| 🔍 商品分析 | 直接调用 `1688-product-analysis` 技能开始执行 |
| 🏥 店铺经营诊断 | 直接调用 `1688-shop-health-check` 技能开始执行 |
| 💬 询盘质检 | 直接调用 `1688-inquiry-evaluate` 技能开始执行 |
| 👥 买家客户管理 | 直接调用 `1688-shop-zkt-buyer-manage` 技能开始执行 |
| 🗣️ 客服接待路由 | 直接调用 `1688-cowboy` 技能开始执行 |
| ⚠️ 店铺流量异动诊断 | 直接调用 `1688-shop-abnormal-alert` 技能开始执行 |
| 📊 数据查询分析 | 直接调用 `1688-shop-freedom-query-data` 技能开始执行 |
| ⏰ 想每天自动生成这份店铺日报？点击设置定时任务 | 为用户设置并开启「每天 09:30 自动发送经营日报」的定时任务；设置完成后向用户确认已开启 |
| 输入其他 | 等待用户输入自定义需求，Agent 根据内容判断应调用的技能 |

> ⚠️ 用户选择后应**直接调用对应技能**，无需用户再次输入触发词。调用技能时应携带日报中相关的上下文信息（如涉及的商品 ID、异常指标等），帮助下游技能快速定位问题。

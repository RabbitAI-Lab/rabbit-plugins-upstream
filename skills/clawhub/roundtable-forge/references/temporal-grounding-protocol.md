# 时间锚定与事实时效性协议

本文件规定圆桌讨论如何锚定当前时间，并在快速变化领域保持事实新鲜度。

## 为什么需要时间锚定

圆桌讨论经常涉及技术、政策、市场、文化等快速演变的议题。如果角色默认使用训练数据中的旧图景，讨论就会脱离用户所处的真实当下，导致建议过时、例子失真、前提错误。Conductor 必须在讨论开始前明确时间锚，并要求角色在必要时联网校验。

## 时间锚的设定

1. 每个圆桌在初始化 Memory 时，必须在 `metadata.current_date` 中写入当前日期，格式为 ISO 8601，例如 `2026-06-21`。
2. 所有角色在发言时，默认以 `metadata.current_date` 为时间语境，除非用户明确要求讨论历史时期。
3. 如果讨论跨越多个日期（如一次圆桌持续多天），每次继续前更新 `metadata.current_date`。

## 必须联网校验的场景

当讨论涉及以下任一情况时，Conductor 或相关角色应在发言前进行联网搜索，并在发言中标注信息来源与截止日期：

- 具体 AI 模型、工具、平台的能力、版本或界面形态。
- 某项技术是否已被市场广泛采用或已被淘汰。
- 政策法规、行业标准、市场数据的现状。
- 任何可能在过去 12 个月内发生重大变化的事实主张。

## 旧例子与历史案例的使用规范

角色可以使用过去的产品或事件作为例子，但必须：

1. 明确标注其历史时间，例如“在 2023 到 2024 年间，ChatGPT 的主流形态还是对话式输入框”。
2. 说明该例子与当前语境的关系，例如“这一现象在当下的 Agentic UI 中已部分缓解，但认知负担问题仍以新的形式存在”。
3. 不得以旧例子暗示当前工具形态没有变化。

## 不确定性与截止日期标注

如果无法获取当前最新信息，角色必须：

- 在发言中加入类似“截至我最后可验证的信息（2025-08）”的标注。
- 把未经核验的主张降级为假设或类比，而不是事实。
- 不假装掌握 2026 年 6 月的实时产品细节，除非已通过联网搜索确认。

## 对 archetype 角色的特殊要求

- **普通用户 / 一线从业者 archetype**：其 `agent_profile` 必须明确要求使用当前时间点的工具、流程与痛点，避免默认回到训练数据中的旧用户画像。
- **融思者**：在跨域整合时，必须确认所引用的各领域事实均为当前语境下的有效假设；不能把一个领域 2024 年的结论与另一个领域 2026 年的结论混为一谈。

## Memory 记录

- `metadata.current_date`：当前时间锚。
- `metadata.temporal_notes`：可选，记录本次讨论中特别需要标注的时间敏感假设，例如“Agentic UI 在 2026 年已成为主流假设，但具体市场占有率未核验”。
- 角色发言中的 `key_points` 如涉及时效性主张，可追加 `verified_as_of` 字段。

## 执行检查

Conductor 在以下节点检查时态合规：

1. 初始化 Memory 后：确认 `metadata.current_date` 已设置。
2. 角色阵容确定后：确认涉及快速变化领域的角色已被告知时间锚。
3. 每轮 synthesis 前：抽查关键事实主张是否过时或缺失时间标注。

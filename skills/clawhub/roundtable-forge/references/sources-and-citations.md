# Sources & Citations 协议（v2.7.0+）

> 本协议定义 Memory 中**真实资料引用**的契约：哪些字段必须从用户提供的资料里来，哪些字段可以被 AI 推演生成。
>
> **核心原则**：用户提供的资料是**事实的边界**——AI 只能引用、不能凭空补充。

---

## 触发背景

圆桌讨论中，嘉宾发言里常常会出现：
- 引用的书籍 / 文章 / 论文 / 视频 / 播客
- 提到的影视作品 / 综艺节目 / 短剧
- 引用的人物语录 / 数据 / 案例

**这些引用必须是真实的**。如果 AI 在没有用户提供的资料来源的情况下"自动联想"或"补全"了一个节目名 / 书名 / 文章名，就构成**杜撰事实**——这是圆桌 skill 最严重的一类错误。

本协议为这类引用提供机器可校验的契约。

---

## 顶层 `sources` 字段

### 定义

```json
{
  "sources": [
    {
      "key": "xiaoyuzhou-E42",
      "title": "E42 孟岩对话韦青：沉默的主角",
      "platform": "小宇宙 FM",
      "show": "无人知晓",
      "host": "孟岩",
      "guest": "韦青",
      "url": "https://www.xiaoyuzhoufm.com/podcast/611719d3cb0b82e1df0ad29e"
    }
  ]
}
```

### 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| `key` | 推荐 | 用于 `cross_promotion[*].source` 字段反向引用 |
| `title` | 必填 | 资料原标题（**必须与原资料标题完全一致，不得改写**） |
| `platform` | 推荐 | 资料所在平台（"小宇宙 FM"、"抖音"、"微信视频号"、"B站" 等） |
| `author` / `host` / `guest` | 视类型 | 视资料类型补全 |
| `url` | 推荐 | 原始 URL（如果可获取） |

### 来源类型

- 用户在本轮圆桌中**主动提供的链接**（如抖音视频、小宇宙播客链接）
- 用户**主动提及的书名 / 文章 / 节目名**
- 嘉宾发言中明确**引用了具体资料**——但**该资料必须能映射回用户在 Memory 之外的输入**（不直接来自 AI 推演）

## `cross_promotion[*].source` 字段

### 定义

```json
{
  "cross_promotion": [
    {
      "show": "《无人知晓》",
      "episode": "E42",
      "topic": "孟岩对话韦青：沉默的主角",
      "source": "xiaoyuzhou-E42"
    }
  ]
}
```

### 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| `show` / `episode` | 推荐 | 节目名 / 集数标识 |
| `topic` | 视情况 | 节目副标题。**必须与原始资料完全一致，不得改写、不得截短、不得"提炼"** |
| `source` | **必填**（如果 topic 存在） | 必须引用顶层 `sources` 中某项的 `key` |

### 强制约束（lint + 渲染）

1. **空数组允许**——如果你不想列相关节目，可以把 `cross_promotion` 设为 `[]` 或省略。
2. **如果填了 cross_promotion，且某项有 `topic`，则必须填 `source`**——否则 `CROSS_PROMOTION_NO_SOURCE` error。
3. **`source` 的值必须能在顶层 `sources` 中找到**（按 `key` 或子串匹配）——否则 `CROSS_PROMOTION_SOURCE_NOT_IN_TOP` error。
4. **`topic` 必须是资料原标题**——这一条无法用 lint 自动检查，但维护者有责任遵循。如发现改写，相关 commit 应被回滚。

### 渲染行为

- **`cross_promotion` 为空数组 `[]` 或字段缺失**：renderer **完全不输出** "### 相关节目" 章节（连标题都不显示）。
- **不为空**：按 `[{show} / {episode} / {topic}]` 格式输出章节，每项一行。

## AI 模拟声明（顶层 disclaimer 协议）

Memory 顶层 `disclaimer` 字段在 podcast 渲染时会**显示在文件顶部**（show_title 之下、tagline 之上），格式：

```markdown
> **AI 模拟声明**：本圆桌讨论、嘉宾发言、Host 串场均由 AI 生成。所涉及真实人物（包括已故思想家）的发言均为基于公开资料的推演与思想实验，不构成任何真实个人、机构或版权角色的官方立场；请勿用于商业目的或对外冒充真实人物观点。
```

**为什么是顶部而非底部**：听众第一眼看到节目名就应该知道这是 AI 生成的，避免被嘉宾发言误导为"真人观点"。

如果不需要这层声明（极少见），把 Memory 顶层 `disclaimer` 字段设为空字符串即可，renderer 会跳过。

## 不属于 cross_promotion 的引用

嘉宾在 `speeches[].content` 里提到的引用（如"《单向度的人》第 4 章"、"《诡秘之主》"）：

- 这类引用**可以来自 AI 推演**——但推荐使用 `assets/memory-template.json` 中的 `speeches[].citations` 字段（v2.8.0 计划）
- 在 v2.7.0 阶段，发言内的引用**仅靠维护者纪律**约束——AI 应优先引用"被公开广泛验证"的资料（如《1984》《单向度的人》《娱乐至死》这种公认的经典）

## 维护原则

- **添加 sources 时**：必须能追到具体 URL / 用户原话 / 嘉宾原话。
- **改写 topic 时**：禁止。如果觉得原标题太长，可保留完整原标题 + 在 `shownotes.cast` 里加一行解释性注释。
- **删除 sources 时**：先确认没有任何 cross_promotion 引用它。
- **空 sources 时**：cross_promotion 应该留空——不要"为了显得丰富"而编造相关节目。

## 反例（应当避免）

### 反例 1：杜撰主题

```json
{
  "show": "《无人知晓》",
  "episode": "E42",
  "topic": "决定一个人走向的往往是沉默的力量"  // ❌ AI 改写的金句
}
```

✅ 正确写法：

```json
{
  "show": "《无人知晓》",
  "episode": "E42",
  "topic": "孟岩对话韦青：沉默的主角",  // ✅ 原始副标题
  "source": "xiaoyuzhou-E42"
}
```

### 反例 2：截短副标题

```json
{
  "show": "《天真不天真》",
  "episode": "vol.51",
  "topic": "面对真相的能力"  // ❌ 截短
}
```

✅ 正确写法：

```json
{
  "show": "《天真不天真》",
  "episode": "vol.51",
  "topic": "对谈姜思达：面对真相的能力，比风口的保质期更长",  // ✅ 完整副标题
  "source": "xiaoyuzhou-vol.51"
}
```

### 反例 3：凭空捏造节目

```json
{
  "show": "《圆桌派》",  // ❌ AI 联想但未验证
  "episode": "EP100",
  "topic": "Token 化时代的人"
}
```

✅ 正确做法：**不要列出这种节目**。如果不确定，就不填。

---

## 总结

- `sources` 数组是事实的边界。
- `cross_promotion.source` 是引用的桥梁。
- **不存在**"AI 自动联想相关节目"的功能——这是为了保护真实性。

如果你在下一个圆桌中想让 AI 推荐"相关节目"，请先**自己提供候选清单**（带 URL / 节目名 / 副标题），AI 才会基于你提供的清单选择。这条边界不会因为"AI 看起来很懂"而放松。

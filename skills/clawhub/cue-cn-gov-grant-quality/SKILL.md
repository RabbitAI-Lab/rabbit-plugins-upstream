# 政府补助与利润依赖·逐条挂源

## 0. 这是什么、不是什么

| 是 | 不是 |
|---|---|
| **一个会计期间内政府补助**的逐项台账 | 对这家公司盈利质量的整体评价 |
| 补助项目、金额、确认依据逐条抄附注 | 判断这个补助「该不该给」「合不合规」 |
| 计入其他收益还是递延收益，照抄会计处理 | 自己把补助加总去和利润相除，得出「依赖度」 |
| 占比只认披露写的 | 推断明年还能不能拿到 |

**三条分界（用户靠这三句分清邻近件）：**

- `cn-earnings-note` 从**利润表**出发逐数点评（收入、毛利率、四期差异）。本件只做**政府补助这一条线**，它的金额如何进入利润表是利润表点评的输入之一。
- `tax-policy-card-cn` 拆**税务文件**（文号、税种、税率）。本件拆的是**公司自己的补助明细**，不是政策文件。
- `policy-impact-cn` 做**政策影响链**（政策条款 → 受影响环节）。本件不推影响链，只登记这家公司实际拿到多少、怎么记的。

**「不得自己除」在本件里具体指哪两件：**

1. **占利润比例只认披露写的。** 年报附注若写「政府补助占利润总额的比例为 38.42%」，抄这一句。自己拿补助 3,842 万元除以利润总额 10,000 万元算出的 38.42%，在原文里找不到——哪怕数值一模一样也不许写。
2. **补助合计不许自己加。** 附注给了合计数就抄合计数；只给了逐项而没有合计，就逐项登记并写「未取到：补助合计」，不自己把几项加起来充合计数。

## 1. 什么时候用

- 「这家公司拿了多少政府补助」「都补了什么项目」
- 「补助是计入当期损益还是递延」「在哪个科目里」
- 「利润里有多少是补助撑起来的」（要的是**披露写的比例**，不是本件算的）
- 「补助的确认依据是什么文件」

**不要用**：要利润表整体点评（走 `cn-earnings-note`）；要税务政策口径（走 `tax-policy-card-cn`）；要政策影响链（走 `policy-impact-cn`）；要判断补助合规性、盈利质量总评、评级目标价（本件不产出，也不该由任何件产出）。

## 2. 取数纪律

1. **只认公司自己的披露。** 年报附注「政府补助」节、递延收益附注、其他收益附注、专项公告。研报、新闻、股吧转述一律不作来源。
2. **每条都引原句。** 写成 `- 项名：「原文原句」〔锚：页/表〕[S#]`，引号里是附注原话。
3. **比例照抄。** 见第 0 节两条。
4. **金额不改写。** 附注写 3,842.16 万元就写这个数，不写「约 3,800 万」。
5. **计入损益与递延分开登记。** 同一笔补助可能一部分进当期损益、一部分挂递延收益，两处各自挂源，不合并成一行。
6. **没取到就写没取到，两向都判。** 正文写了「未取到 X」，第五节必须点名 X；第五节点了名而正文没有这条表述，同样算错。零缺口写 `- 未取到：无`。
7. **不推断可持续性。** 「该补助是否具有持续性」是判断，本件只登记披露说了什么。

## 3. 输出契约（六节，按序）

```
AI 整理初稿｜请回原文核对｜不构成投资建议｜判断位 [待人工]

主体：<公司名称>
报告期：<YYYY 年度／YYYY-MM-DD 截止日>
数据口径：政府补助（附注逐项登记，不评盈利质量）

## 一、补助概况
## 二、分项登记
## 三、会计处理
## 四、与利润的关系
## 五、未取到与口径
## 六、来源
```

- **头部四件自标**逐字在位，写在第一个 `## ` 之前。
- **主体／报告期／数据口径**三行必须在场；`数据口径：` 必须以「政府补助」起头。
- **一、补助概况**：本期计入损益的补助总额、期末递延收益余额、涉及项目数——三项各自挂原句；附注没写的写未取到。
- **二、分项登记**：一个补助项目一行，写项目名与金额。项目多的，按附注原顺序取前若干条并注明「另有 N 项见附注」——不重新排序、不挑金额大的。
- **三、会计处理**：计入其他收益／营业外收入／递延收益各是什么口径，逐条抄会计处理的原句。
- **四、与利润的关系**：占利润总额（或净利润）的比例**只抄披露值**；披露没写就写未取到，并说明「本件不自己除」。
- **五、未取到与口径**：逐条点名未取到的项；口径行写清哪些照抄、哪些未取。
- **六、来源**每行：`- [S#] 文件标题｜URL｜检索日 YYYY-MM-DD`。

## 4. 数据通道

本件走 Cue 的 MCP 通道取公告与原文解析。先列目录，再按目录里的路由地址调 `tools/list`，确认工具在场后再取数：

```bash
CATALOG="https://cuecue.cn/api/mcp-catalog"
curl -s "$CATALOG" | head -c 2000
# 从目录里取本组的路由地址，再确认工具在场
curl -s -X POST "$ROUTING_URL" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

拿到年报附注后，用 `scripts/make_outline.py` 把清单排成骨架，再逐条读原文补内容。

## 5. 合规红线

- **不判盈利质量。** 「利润严重依赖补助」「靠补助保壳」「盈利质量差」这类断言零容忍——那是判断，不是披露。
- **不判补助合规性。** 「存在骗补嫌疑」「补助依据不足」零容忍。
- **不给评级、目标价、投资建议、买卖建议。**
- **不预测补助可持续性**，不写「预计明年仍可获得」「持续性存疑」。
- **不用改数词打底。** 「约」「左右」「大概」不得替附注里的确切数字。
- **不自己加总、不自己相除。** 见第 0 节两条。

## 6. 快速流程

1. 拿到年报附注「政府补助」「递延收益」「其他收益」三节，定主体与报告期。
2. 抄本期计入损益的补助总额与期末递延收益余额。
3. 逐项抄补助项目与金额，按附注原顺序。
4. 抄会计处理（计入哪个科目）。
5. 抄披露的占利润比例；没披露就写未取到。
6. 写未取到与口径，两向对齐。
7. 跑 `python3 scripts/check_gov_grant.py <稿>.md`，红一条改一条。

不知道从哪开始，先跑内置样例看一份成品长什么样：

```bash
python3 scripts/check_gov_grant.py --demo
```

## 7. 机检

```bash
python3 scripts/check_gov_grant.py <政府补助稿>.md    # 五道，退码 0 全过 / 1 有发条 / 3 读不到或空稿
python3 scripts/check_gov_grant.py --selftest         # 包内夹具自检
python3 scripts/check_gov_grant.py --demo             # 内置样例跑一遍，产出可核对的成品
bash scripts/fixtures/run_fixtures.sh                 # 三档离线自检，零网络零计费
```

五道：**道一 形制**（头部自标、主体／报告期／数据口径三行、六节齐且有序、前四节各至少一条发现行）／**道二 原句与锚**（每条发现行以「」＋〔锚…〕＋`[S#]` 收尾，来源行齐编号与 URL 与检索日，引用编号须已登记）／**道三 不得自算**（占利润比例与补助合计必须能在同一行原句里逐字找到；找不到的标 `〔自算〕` 并写明分子分母各出自哪句；补助合计另判：正文出现「合计」而无原句即发）／**道四 未取到两向点名**（正文与第五节互校，零缺口须显式写 `未取到：无`）／**道五 红线**（盈利质量断言、合规断言、评级目标价、可持续性预测零命中）

## 8. 零通道降级

没有 `CUE_API_KEY` 时，本包**不产出内容**，只把用户手上的清单排成带形状的骨架：六节与来源行按清单落位，内容留 `[待人工]`。骨架跑机检必然红在占位行上——这是设计，提醒你补完再交。

代价说清楚：**没有通道就没有附注原文，没有原文就没有原句，分项登记这一格就挂不上锚**——分项是这份台账的本体，它挂不上锚，这份稿就只剩用户口述的几个数。用 `--demo` 看成品形制，不占用通道。

# 政府补助与利润依赖·逐条挂源

把**一个会计期间的政府补助**读成一张每个数都能回到原句的台账：补助概况、分项登记、会计处理、与利润的关系。

**不判盈利质量、不判补助合规性、不预测补助可持续性、不给评级与目标价。** 占利润比例只认披露写的；补助合计不许自己加。

---

## 一、三十秒跑通（零输入）

不给任何数据文件，也能跑出一份完整合规的成品，看它长什么样、判据怎么打：

```bash
python3 scripts/check_gov_grant.py --demo
```

把这份样例存下来再跑一遍机检，它能自己过：

```bash
python3 scripts/check_gov_grant.py --demo > 样例政府补助稿.md
python3 scripts/check_gov_grant.py 样例政府补助稿.md
# → 样例政府补助稿.md 发条=0｜GG-STRUCT=0｜GG-QUOTE=0｜GG-NOSELF=0｜GG-GAP=0｜GG-LINE=0
```

接着换成你自己那份稿子：

```bash
python3 scripts/check_gov_grant.py 你的政府补助稿.md
```

退码 `0` 全过、`1` 有发条、`2` 用法错、`3` 读不到文件或空稿。

## 二、五道机检在管什么

| 码 | 名称 | 判什么 | 最常拦住的情况 |
|---|---|---|---|
| `GG-STRUCT` | 形制 | 头部四件自标在第一个 `## ` 之前；`主体：`／`报告期：`／`数据口径：` 三行在场且口径以「政府补助」起头；六节齐且有序；前四节各至少一条发现行 | 六节缺一节；某节只有小标题；口径写成了「利润表点评」 |
| `GG-QUOTE` | 原句与锚 | 每条发现行以「原句」＋〔锚：…〕＋`[S#]` 收尾；来源行齐编号＋可点 URL＋检索日；正文引用的编号须已登记 | 只写数字没抄原句；引号是空的 `「」`；来源行只有标题没有链接 |
| `GG-NOSELF` | 不得自算 | 占利润比例必须在**同一行的原句里逐字找到**；找不到的须标 `〔自算〕` 并写明分子与分母各出自哪句；引号外出现「合计／总计／合共」而没有原句即发 | 自己拿 3,842 ÷ 10,000 算个 38.42% 当披露值；把几项补助加起来充合计数 |
| `GG-GAP` | 未取到两向点名 | 正文写了未取到而第五节没列要发，反之也发；零缺口须显式写 `未取到：无` | 用「不适用」「无此项」「无需披露」搪塞 |
| `GG-LINE` | 红线 | 盈利质量断言、合规断言、评级目标价、可持续性预测零命中 | 「利润严重依赖补助」「存在套取嫌疑」；「预计明年仍可获得」 |

**否定式声明不误伤。** 「本期未发生补助退回」「不存在套取情形」是照抄披露的否定句，判据里显式放过——那是本件最该抄的话之一。

## 三、这件的立身之本：不许自己除、不许自己加

1. **占利润比例只认披露写的。** 附注写「政府补助占利润总额的比例为 38.42%」，抄这一句。自己拿补助 3,842.16 万元除以利润总额 10,000.00 万元得出的 38.42%，在原文里找不到——哪怕数值一模一样也不许写。
2. **补助合计不许自己加。** 附注给了合计数就抄合计数；只给了逐项而没有合计，就逐项登记并写「未取到：补助合计」，不自己把几项加起来充合计数。
3. **计入损益与递延分开登记。** 同一笔补助可能一部分进当期损益、一部分挂递延收益，两处各自挂源，不合并成一行——合并会抹掉「哪一笔还在摊销、哪一笔已经进利润」。

## 四、一条发现长什么样

```markdown
- 本期计入损益的补助总额：「本期计入其他收益的政府补助合计 3,842.16 万元」〔锚：年度报告·附注七·政府补助·第 168 页〕[S1]
```

```markdown
- 补助项目一「智能装备产业化专项」：「智能装备产业化专项补助 1,800.00 万元」〔锚：附注七·政府补助·明细表·第 168 页〕[S1]
```

要自己算的，长这样（分子分母各自挂源）：

```markdown
- 补助占比〔自算〕分子＝补助 3,842.16 万元 [S1]｜分母＝利润总额 10,000.00 万元 [S2]「本期计入其他收益的政府补助合计 3,842.16 万元」〔锚：附注七·政府补助·第 168 页〕[S1]
```

## 五、和另外几枚包怎么分

| 你手上是 | 用哪枚 |
|---|---|
| 政府补助台账：项目、金额、会计处理、占利润比例 | **本件** |
| 利润表逐数点评：收入、毛利率、四期差异 | `cn-earnings-note` |
| 税务文件：文号、税种、税率 | `tax-policy-card-cn` |
| 政策影响链：条款 → 受影响环节 | `policy-impact-cn` |

## 六、零通道：先排骨架

没有通道产物也能跑，本脚本只读你给的那份清单：

```bash
python3 scripts/make_outline.py 清单.jsonl 骨架.md
```

清单是 JSONL，每行三键必需：`title`／`url`／`asof`（检索日 `YYYY-MM-DD`），`id` 与 `page` 可省。

- 坏行（非法 JSON／缺键／日期不合形／url 不是 http）**逐行点名、不采信**，好行照收。
- **空清单退 1，不出空壳。**
- 排出的骨架**故意过不了机检**，这是设计，不是待修。

```bash
python3 scripts/make_outline.py --selftest       # 8 条内置夹具
```

## 七、跑夹具与测试

```bash
bash scripts/fixtures/run_fixtures.sh            # 三档离线夹具，零网络零计费
python3 tests/test_gov_grant.py                  # 包级测试：入口契约／零输入／埋点
```

`run_fixtures.sh` 三档：机检自测 / 好样坏样逐枚单跑 / 在好样上逐行替换做正反对照（该红的红、该不红的不红）。末行自报 `档数=3｜不合=N｜不可判=N`。

`tests/` 跑的是外壳属性——`--help` 退 0、无参退 2、缺文件退 3、`--demo` 产物自过机检且逐字节可复现、空清单不出空壳、埋点落盘且失败静默。

## 八、首次运行埋点

入口脚本解析参数成功后、干正事之前，会往 `~/.cue-usage/<slug>-<日期>` 落一枚**空文件**。

**为什么要它：** 平台的两个下载计数器都不可信——新 listing 上架首 48 小时会被一次性播种 50~60 的初始计数，那不是用户下载。本地这枚文件是本件唯一能证明「真有人装上并跑过」的证据。

**它不会碍事：** 任何失败（家目录只读、配额满、无 HOME）都静默跳过，不报错、不改退码、不吐一句杂音。同一天跑多次只留一枚。

要清掉：`rm -rf ~/.cue-usage`。

## 九、素材从哪来

- **用户直供**：手头的年报、附注、专项公告 PDF，走 `+parse` 解析。
- **通道取证**：配 `CUE_API_KEY` 后可走公告检索与原文解析。装好 skill ≠ 已配凭据 ≠ 通道已连，三层分开看。
- **零通道**：`--demo` 看形制，`make_outline.py` 排骨架。

本件不发请求、不代付费，消耗以服务端返回为准。

## 十、通道在场确认（可选）

配了 `CUE_API_KEY` 才需要这一步。先列目录，再按目录里的路由地址确认工具在场：

```bash
CATALOG="https://cuecue.cn/api/mcp-catalog"
curl -s "$CATALOG" | head -c 2000
# 从目录里取本组的路由地址，确认工具在场
curl -s -X POST "$ROUTING_URL" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

没配凭据也能跑：`--demo` 与 `make_outline.py` 都是纯本地路径。

# 质量模型、评测与发布门禁手册

## 1. 六维质量模型

| 维度 | 核心问题 | 可自动检查 | 需要判断 |
|------|----------|------------|----------|
| 结构 | 页面是否符合契约 | 目录、frontmatter、唯一 ID | 页面边界是否合理 |
| 证据 | 主张是否可追溯 | 来源路径、死链 | 来源是否真正支持结论 |
| 新鲜度 | 当前性是否明确 | 日期、SLO、状态 | 是否仍适用 |
| 导航 | 能否被找到 | 索引覆盖、孤儿页、断链 | 链接是否有语义 |
| 查询 | 能否稳定回答问题 | Recall@K、MRR、引用覆盖 | 综合是否忠实、是否应弃答 |
| 治理 | 变更能否闭环 | owner、审计状态、日志 | 冲突裁决是否充分 |

机械门禁不能证明内容正确；它证明最低契约没有被破坏。

## 2. 严重性

- **Error**：会导致错误引用、不可访问、身份冲突或契约失效。例：重复 ID、来源不存在、路径越界、坏 frontmatter。
- **Warning**：不一定错误，但显著增加维护或回答风险。例：超过新鲜度、索引遗漏、无入链。
- **Info**：改进建议，不阻断普通发布。例：页面过长、同义词覆盖不足。

严格模式应让 Error 和 Warning 都返回非零；普通模式只让 Error 阻断。项目可在配置中定义例外，但例外必须有原因和到期日。

## 3. 结构审计

发布前至少运行：

```bash
python3 scripts/build_manifest.py ./wiki-root --strict
python3 scripts/audit_wiki.py ./wiki-root --max-age-days 180 --strict
```

检查内容包括：必需目录/文件、页面 frontmatter、唯一 ID、允许的类型和状态、索引覆盖、Markdown 链接、Wiki 链接、来源存在性、路径是否逃逸、过期日期和 owner。

## 4. 证据抽检

自动检查后进行分层抽样：

1. 所有高风险页面：安全、法律、财务、生产操作等。
2. 所有新建/大改/争议页面。
3. 其余页面按固定比例随机抽取。
4. 对每页抽 2–5 个强断言，核对来源上下文、版本和表达强度。

将“引用存在”和“引用支持”分开计数。一个合法链接可能指向不支持结论的来源。

## 5. 查询回归集

评测集采用 JSONL，每条包含：稳定 ID、问题、预期页面、必须出现的事实、允许未知、风险和标签。问题来源应包括：真实用户提问、历史失败、易混淆概念、时间敏感问题和应当拒答的问题。

```json
{"id":"q-tool-timeout","question":"当前默认工具超时是多少？","expected_pages":["concept-tool-timeout"],"must_cite":true,"allow_unknown":false,"risk":"high"}
```

不要把生成系统自己编写的问题当作唯一测试集；至少由目标用户审阅代表性。

## 6. 指标与阈值

| 指标 | 定义 | 初始建议 |
|------|------|----------|
| Recall@5 | 前 5 个结果包含任一预期页 | ≥ 0.90 |
| MRR | 首个正确结果倒数排名均值 | ≥ 0.75 |
| 引用覆盖率 | 关键结论带引用比例 | ≥ 0.95 |
| 引用支持率 | 引用确实支持结论比例 | ≥ 0.90 |
| 正确弃答率 | 无证据问题未被编造回答 | 1.00 |
| 新鲜度提示率 | 过期/争议答案给出提示 | 1.00 |

阈值是起点，应按风险和数据量调整。小样本报告计数和置信范围，不用一位小数制造精确感。

## 7. 发布矩阵

```text
结构 Error？              → 阻断
来源断链或路径越界？      → 阻断
高风险证据抽检失败？      → 阻断
严格审计有 Warning？      → 修复或记录有期限豁免
核心查询回归下降？        → 阻断
只有低风险 Info？         → 可发布，进入维护队列
```

语义检索、切块或模型版本变化属于检索系统变更，即使 Wiki 文件未变，也必须跑完整查询回归。

## 8. 好/坏样本

工具测试至少包含：

- 好样本：两页互链、索引完整、来源存在、日期新鲜，严格模式退出 0。
- 坏样本：重复 ID、缺来源、死链或陈旧页面，严格模式退出非 0，并输出稳定问题代码。
- 边界样本：空 Wiki、只有索引、归档页、中文文件名、路径含空格。
- 安全样本：`../` 逃逸、绝对私有路径、畸形 frontmatter 不得被忽略。

机器输出使用 `--json`，便于 CI 消费；人类输出保持问题代码、文件和修复建议。

## 9. 评测记录

每次发布记录：代码/内容版本、数据集版本、检索配置、模型（若使用）、指标、失败问题和批准人。评测结论必须可重放；只保存最终百分数无法诊断回归。

## 10. 完成检查表

- [ ] 结构、证据、新鲜度、导航、查询、治理六维都有检查
- [ ] Error、Warning、Info 的阻断语义明确
- [ ] 高风险和变更页面完成引用支持抽检
- [ ] 查询集包含真实问题、失败问题和应弃答问题
- [ ] 指标覆盖召回、引用、弃答与新鲜度
- [ ] 检索或模型变化触发完整回归
- [ ] 好、坏、边界和安全样本可重复运行
- [ ] 发布记录足以重放评测和解释豁免

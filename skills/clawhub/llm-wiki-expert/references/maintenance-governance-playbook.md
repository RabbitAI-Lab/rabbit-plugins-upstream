# 增量维护与治理手册

## 1. 治理对象

Wiki 治理不仅是“定期更新文档”，而是同时管理来源、页面、索引、查询评测、反馈与责任关系。每个对象必须有身份、状态和可追踪的变更。

| 对象 | 最低治理字段 | 主要风险 |
|------|--------------|----------|
| 来源 | id、version、ingested、hash、access | 原文漂移、重复、越权 |
| 页面 | id、status、updated、owner、sources | 过期、冲突、无人负责 |
| 索引 | generated_at、page set | 漏页、陈旧、错误链接 |
| 评测项 | id、question、expected_pages、risk | 只优化 Demo 问题 |
| 反馈 | id、target、anchor、severity、resolution | 意见丢失、静默拒绝 |

## 2. 新鲜度 SLO

按知识漂移速度设置审查周期，不使用一个全局天数：

- 高频变化：价格、版本、组织职责、在线服务状态，7–30 天。
- 中频变化：产品行为、API、政策、路线图，30–90 天。
- 低频变化：稳定架构、算法原理、历史决策，180–365 天。
- 归档知识：不要求“更新为当前”，但必须标注历史时间范围。

超过 SLO 只是风险信号；重新核查且结论未变时，更新审查日期并记录所核来源。

## 3. 影响分析

来源变化后，先生成影响集：

```text
changed source
  → directly citing pages
  → pages linking to those pages
  → index/topic pages
  → evaluation questions expecting those pages
```

Manifest 应支持 `source → page` 和 `page → link` 两种关系。先更新直接事实页，再更新解释/决策页，最后重建索引并回归查询。

## 4. 增量刷新工作流

1. 比较稳定 ID、版本与哈希，确认变化不是格式噪声。
2. 保存新来源，旧来源标记被取代但不覆盖。
3. 找出直接引用和二阶依赖页面。
4. 对每页判定：无影响、局部更新、重编译、争议、弃用。
5. 串行修改共享页面与索引。
6. 重建 Manifest，运行严格审计和相关评测。
7. 写日志：改变了什么、未改变什么、剩余风险。

## 5. 反馈审计队列

人类反馈以独立文件进入 `audit/open/`，至少记录目标页面、锚点、反馈原文、提交者、日期、严重性和建议。解决结果只能是：

- `accepted`：全部采纳，列出改动与证据。
- `partially-accepted`：说明采纳和拒绝部分。
- `rejected`：给出证据或范围理由。
- `deferred`：说明依赖、负责人和复查时间。

解决后移动到 `audit/resolved/`，保留原反馈和结论。不能通过删除反馈制造“零问题”。

## 6. 重命名、合并与拆分

### 重命名

保持页面 `id`，更新文件名、索引、所有入链和 Manifest。若存在外部稳定链接，保留 redirect 页面或映射表。

### 合并

选择一个稳定 ID 或创建新 ID；迁移未重复的证据与入链；旧页标记 `deprecated` 并指向新页。不要直接删除旧页。

### 拆分

原页面保留摘要与导航，子页面获得新 ID、独立来源和责任人。逐一核对旧锚点是否仍可解析。

## 7. 责任模型

`owner` 表示对证据审查和生命周期负责，不一定是作者。共享页面可设置主责任人和 reviewers；不建议多个“共同 owner”而无人拥有最终决定。

离职或团队调整时，将 owner 迁移作为批量治理任务，并运行无责任人检查。敏感页面还应有访问审批者，但访问权与内容 owner 是不同职责。

## 8. 变更与回滚

推荐 Git 管理 Wiki：每个逻辑变更包含来源新增、受影响页面、索引/Manifest 和审计结果。提交信息描述知识变化，不只写“update docs”。

回滚知识页面时不要回滚必须保留的新原始来源；应恢复上一版编译产物，并记录为什么当前编译被撤销。对错误来源，标记撤回或不可信，而不是从历史中抹除。

## 9. 维护节奏

| 周期 | 动作 |
|------|------|
| 每次变更 | Manifest、链接、来源、相关评测 |
| 每周 | open 审计队列、失败查询、近期来源 |
| 每月 | 过期页面、无 owner 页面、孤儿页、弃用候选 |
| 每季度 | 范围与页面类型、检索层级、访问策略、评测代表性 |

节奏应按风险调整，自动检查发现问题，人类负责语义裁决。

## 10. 完成检查表

- [ ] 各知识类型有差异化新鲜度 SLO
- [ ] 来源变更能够追踪到页面和评测问题
- [ ] 刷新区分无影响、更新、争议和弃用
- [ ] 反馈保留原文、结论和处理证据
- [ ] 重命名、合并、拆分不会制造断链和身份漂移
- [ ] 每个活动页面有明确责任人
- [ ] 回滚不破坏不可变证据层
- [ ] 维护节奏覆盖变更、反馈、过期和范围复核

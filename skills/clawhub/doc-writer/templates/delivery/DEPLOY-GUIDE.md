| 变量 | 默认值 | 必填 | 说明 |

## 5. 健康检查与监控

〈填写指引：readiness 与 liveness 分列——语义不同（能否接流量 vs 进程是否存活），合并写会导致误判。端点写全路径与方法；日志写采集方式与格式关键字（供 RUNBOOK 排障 grep）；指标写指标名、暴露端口与抓取路径。本文只登记事实，告警阈值与处置在 RUNBOOK，互链不复制。〉

- 健康端点：`GET /health/ready`（readiness：依赖全部就绪返回 200）/ `GET /health/live`（liveness：进程存活即 200）
- 日志位置/格式：〈stdout 采集 或 文件路径 `logs/app.log`；格式：JSON，含 trace_id 字段〉
- 关键指标：〈QPS/错误率/耗时，指标名 `http_request_duration_seconds` 等，暴露端口 `:9090/metrics`〉

## 6. 回滚步骤

> **迁移回滚是破坏性操作**：down 脚本可删除已填充的列/表，数据是不可再生资产。仅当迁移**可逆**（先加列后删列类）才提供 down 脚本；删列/改类型类不可逆迁移禁止 down，走前滚修复路径（新建修复迁移，永不回退 schema）。down 执行前置三条件缺一不可：可逆性评估结论 → 已验证备份（恢复演练过，非仅备份过）→ 批准（决策权限见 RUNBOOK 第 6 节）。

〈填写指引：制品存放位置与命名规则写精确规则（如 `artifacts/<service>/<version>/`），保证任何人能按规则找到上一版本。本次发布含迁移时，注明迁移文件清单与可逆性结论；不可逆迁移在第 3 步标注"禁止执行，走前滚"。回滚后验证以第 5 节健康端点为准。〉

```bash
# 1. 停止当前版本
〈命令〉
# 2. 恢复上一版本制品（制品存放位置与命名规则：〈规则〉）
〈命令〉
# 3. 回滚数据库迁移（仅当本次发布含迁移且已确认可逆；脚本：〈路径〉；不可逆则跳过本步走前滚修复）
〈命令〉
# 4. 启动并验证健康检查
〈命令〉 && curl http://localhost:〈port〉/health/ready   # 预期：200
```

# CHANGELOG：〈项目名称〉变更日志

> **产出者**：技术文档工程师——每版本发布即时落档；发布后版本条目不可变，纠错在下个版本条目声明并回链
> **受众**：用户、运维升级者、全体项目参与者（人类 + AI 编程智能体）
> **归档**：项目根 `CHANGELOG.md`（与 README 同级，不入 docs/）
> **真值源**：版本发布记录（git tag / 提交历史）+ PR-SUMMARY + PROGRESS；与真值源不一致时标 blocked_on 回责任角色，不擅自改
> **质量门禁**：① 格式符合 Keep a Changelog ② 版本号语义化（SemVer）③ 每条可追溯（任务号/commit）④ 只记用户可感知的变更（内部重构无外部影响不单列）

## 版本号规则（SemVer）

| 递增位 | 触发条件 | 示例 |
|---|---|---|
| MAJOR | 不兼容的 API/行为变更（含移除已弃用能力） | 1.9.0 → 2.0.0 |
| MINOR | 向下兼容的功能新增（含新端点、新配置项） | 1.9.0 → 1.10.0 |
| PATCH | 向下兼容的缺陷修复（行为回归预期） | 1.10.0 → 1.10.1 |

预发布版本（rc/beta）只用于发布前验证，不产生 CHANGELOG 版本条目；条目在正式 tag 时落档。同一次发布同时含 MAJOR 与 MINOR 变更时只递增 MAJOR，MINOR/PATCH 类条目正常列出。

条目写法对照：

| 不合格写法 | 合格写法 | 差异 |
|---|---|---|
| 若干体验优化 | 导出按钮支持记忆上次设置的列宽（FS-31 / a1b2c3d） | 后者可感知、可追溯 |
| 修复订单问题 | 修复 1.2.0 起大额订单提交失败（BUG-7） | 后者含影响范围与编号 |

## [1.0.0] - YYYY-MM-DD

〈填写指引：示例版本条目，展示发布版本的标准写法。版本号遵守 SemVer（见"版本号规则"表）；与 git tag 一一对应，无 tag 不立版本条目。首个发布通常一句话清单核心能力。此示例条目在首次真实发布时替换。〉

发布操作序列：

1. 打 git tag `v<version>`
2. 将 [Unreleased] 内容整体移入新版本条目（日期 = tag 日期）
3. [Unreleased] 清空重建（六类标题按需保留）
4. 未解决的已知问题条目随版本冻结，同时保留在新 [Unreleased] 已知问题区

## 红线自查（一票否决，提交前逐条勾选）

- [ ] 每条变更可追溯到任务号或 commit，无"若干优化"式汇总
- [ ] 每条均为用户可感知变更；内部重构未单列
- [ ] 版本条目与 git tag 一一对应；SemVer 递增规则正确
- [ ] 已发布版本条目未被回改；修正通过后续条目声明
- [ ] 真实令牌、账号、个人数据未出现在任何条目
- [ ] TEST-REPORT 遗留风险已同步"已知问题"
- [ ] [Unreleased] 无空类标题（无变更的类已删除）；条目均含任务号或 commit

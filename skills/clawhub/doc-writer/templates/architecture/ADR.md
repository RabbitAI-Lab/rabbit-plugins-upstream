# ADR-NNNN：〈决策标题——一句话陈述决策本身，如"服务间通信采用事件驱动而非同步调用"〉

> **产出者**：〈决策发生者：架构师/技术负责人/AI 智能体〉——决策时即时落档，不事后补写
> **受众**：全体项目参与者（人类 + AI 编程智能体）
> **归档**：`docs/project/adr/NNNN-kebab-title.md`（编号只增、永不复用；本文件即该决策的唯一权威记录）
> **真值源**：决策本身。DESIGN / 开发规范 / 评审清单引用本文件，只引用不复制结论；引用前必须核对本 ADR 状态
> **质量门禁**：① 一篇只记一个决策 ② 备选方案表至少含一个被否方案及否决理由 ③ 后果三分类完整 ④ accepted 及之后正文永不修改（只允许状态行、日期、后继链接变动）

## 状态行填写规则（五种状态）

| 状态 | 何时使用 | 关键义务 |
|---|---|---|
| proposed | 起草完成，开放讨论 | 设定决策时限（建议 ≤ 2 周），到期必须转 accepted/rejected |
| accepted | 决策生效 | 成为当前约束；新实现必须遵守 |
| rejected | 讨论后否决 | **不删除**，保留否决原因，防止重复论证 |
| deprecated | 曾生效，现不推荐新场景 | 说明仍适用的存量范围 + 替代方案 + 退出计划 |
| superseded | 被后继 ADR 取代 | 双向链接：本文件填 superseded-by，后继填 supersedes |

迁移路径：proposed → accepted ｜ rejected；accepted → deprecated ｜ superseded；deprecated → superseded。

## 1. 背景（Context）

〈填写指引：客观陈述决策面临的约束、问题与压力（Force）。只写事实，不含结论；每个约束注明来源——PRD 条目、既有系统、组织限制。AI 编程智能体会依据本节理解决策的适用边界，写模糊了会被错误泛化。示例：FR-012 要求订单峰值 5000 TPS；现有同步调用链在 800 TPS 时 P95 已达 1.2s。〉

## 2. 决策（Decision）

〈填写指引：现在时、祈使句，一句话说清，不写三段。可加粗。示例：**服务间通信统一采用事件驱动，禁止新增同步服务间调用。**〉

## 3. 理由与权衡（Rationale & Trade-offs）

〈填写指引：为什么是这个方案而不是备选——针对第 1 节的 Force 逐条回应；得到了什么、放弃了什么。权衡必须显式写出"我们放弃了 X 换取 Y"，只讲好处不讲代价的 ADR 不可信。〉

## 4. 备选方案（Options Considered）

|---|---|---|
| 〈方案 A（本决策）〉 | 采纳 | 〈一句话〉 |

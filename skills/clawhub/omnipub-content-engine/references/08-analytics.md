# 阶段8 · 数据复盘与归因分析

目标：**回答两个灵魂拷问——「为什么这篇没数据？」「为什么有热度没浏览量？」** 用数据反推下一篇选题，形成闭环。

## 8.1 数据输入方式（双通道）

**通道A · 粘贴数据（默认，零配置）**：用户从公众号后台/头条后台复制数据，按模板粘贴：

```
平台, 标题, 发布时间, 阅读量, 推荐量/曝光, 涨粉, 转发, 在看, 评论, 完读率%, 分享率%
公众号, 《XXX》, 2026-08-14 20:00, 1200, -, 45, 38, 12, 8, 45, 3.2
头条, 《XXX》, 2026-08-14 20:10, 5200, 86000, 30, -, -, 21, 18, 0.6
```

**通道B · API 预留（后续扩展）**：`config.json → analytics.api` 预留公众号接口凭证字段；头条开放平台接口权限有限，暂以人工导出为主。

## 8.2 分析维度

| 维度 | 指标 | 回答什么 |
|---|---|---|
| 表现层 | 阅读/曝光/涨粉/互动 | 这篇到底行不行 |
| 效率层 | 点击率（阅读/曝光）、完读率、分享率 | 标题封面行不行、内容留住人不 |
| 对比层 | 与同账号近7篇均值、与同评分选题对比 | 是选题问题还是执行问题 |
| 趋势层 | 发布后 1h/6h/24h/72h 流量曲线 | 推荐机制是否给量、给量后接不接得住 |

## 8.3 归因诊断树（核心价值）

### 问题1：整体没数据（低曝光低阅读）

```
┌─ 账号层：新号/低权重 → 养号策略（垂直度、更新频率、互动引导）
├─ 选题层：评分卡回顾——
│   H 热度是否误判？（发布时已过峰）
│   F 人设是否错位？（读者不认识你，凭什么看）
├─ 时机层：发布时间错峰？（同类大号同点发）
└─ 分发层：是否被限流？（违规词/诱导/频繁删除重发）
```

### 问题2：有热度没浏览量（曝光/推荐不低，点击低）

**这是「标题+封面」问题，不是内容问题。** 重点排查：

| 检查项 | 动作 |
|---|---|
| 标题钩子 | 是否给足「看下去的即时理由」？数字/冲突/悬念三选一 |
| 标题与封面一致性 | 封面图是否信息量低/与标题矛盾/文字糊 |
| 首段 | 头条版首段是否 3 秒给结论？公众号首段是否 2 屏内进入正题 |
| 冷启动 | 发布后 1 小时内是否引导了种子互动（转发到社群/朋友圈） |
| 竞品对照 | 同话题爆款标题怎么写的？差异在哪 |

### 问题3：有点击没完读/没涨粉

**这是「内容结构」问题**：开头钩子兑现了，中段流失。
- 信息密度低（大量正确的废话）→ 每段砍掉 30%
- 干货埋太深 → 小标题明示收益（「第3步：XXX，直接决定你能否涨粉」）
- 与读者无关 → 每 500 字问一次「关我什么事」
- 无转化设计 → 文末模板 CTA 是否够具体

## 8.4 输出复盘报告（HTML）

运行 `scripts/analyze_article_data.py` 生成 `08-复盘报告.html`：
- 双平台数据对比表 + 图表
- 归因诊断结论（命中哪条诊断路径）
- **下一篇迭代建议**（选题方向/标题写法/发布时间/文末模板调整）
- 迭代建议自动回流到选题库（写入 `analytics_history/`）

## 8.5 复盘纪律

- 发布后 24h 初看、72h 定论（推荐流量 72h 才基本释放完）
- 每周一次汇总复盘（本周 5 篇横向对比）
- 每篇复盘只提炼 **1 条** 最重要的迭代动作（一次改一件事，可归因）
- 复盘结论写进 `analytics_history/`，形成自己的「爆款数据库」

## 8.6 交付物

```
08-复盘报告.html        # 趋势图 + 归因诊断 + 迭代建议
analytics_history/      # 历史数据沉淀（爆款特征库）
```

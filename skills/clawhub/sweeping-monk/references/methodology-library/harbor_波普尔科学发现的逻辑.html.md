# 【名称】反约定主义的对抗手段——拆掉特设性假说的免疫策略
- 适用情境：一个理论、方案或指标被事实打脸后，靠加补丁、改口径、划例外的方式一次次"复活"
- 核心操作：1. 先承认没有天然标准——的确不可能靠分析一个陈述系统的逻辑形式来判定它是约定系统还是可反驳的经验系统，避免约定主义的惟一方法是采取一个决定：决定不应用它的方法；2. 熟悉约定主义策略可能采取的各种形式，以便针对每种形式采取适当的反约定主义的对抗手段；3. 给辅助假说设门槛：只有那些引进以后并不减少，反而增加该系统的可证伪度或可检验度的辅助假说才是可接受的；4. 定下复检规矩：每当我们发现一个系统为约定主义策略所挽救时，我们就要重新检验它，假如情况需要，就摈弃它；5. 用使用假说的节约原理限制过度使用特设性假说和辅助假说，因为这样保护起来的系统的可证伪度等于零；6. 把系统表述得足够的清楚和明确，使得我们易于辨认出每一个新假定是一种系统的修改，因而是一种修正；7. 把整体姿态定成对抗性的——使待检验的系统以一切可设想的方式面临证伪的态度，它的目的不是去拯救那些站不住脚的系统的生命，而是相反，使这些系统面临最剧烈的生存竞争，通过比较来选择其中最适应者
- 前提假设：由于各种理由，任何理论系统最终地被证伪，仍然是不可能的；因此科学程序的其他规则必须这样来设计，它们并不保护科学中的任何陈述不被证伪
- 常见坑：在危机时期把当时的"经典"系统当作不可动摇的；用"最简单的系统"作为维持现状的理由——这实际上就是当时的"经典"系统；把约定主义者的简单性概念（部分美学的、部分实用的）当成客观判据
- 迁移场景：方案复盘里的借口识别、模型失效后的补丁审查、KPI 未达成时的归因改写、产品数据不好时的特设解释、制度执行走样时的例外条款
- 边界反例：提高了可证伪度或可检验度的辅助假说应当接受，不能一律拒绝；新假说被证伪时，概括性较低的旧系统不必被认为已被证伪
- 原文原句："按照我的建议，经验方法的特征是，它使待检验的系统以一切可设想的方式面临证伪的态度，它的目的不是去拯救那些站不住脚的系统的生命，而是相反，使这些系统面临最剧烈的生存竞争，通过比较来选择其中最适应者。"
- 置信度：板上钉钉

# 【名称】验证度由检验的严格程度决定，不由验证实例的数目决定
- 适用情境：要判断一个理论、模型或报告到底"硬不硬"，而对方正在罗列支持它的例子
- 核心操作：1. 停止计数——一个理论的验证度肯定不能只靠计算验证事例的数目来确定；决定验证度的与其说是验证实例的数目，不如说是所说的那个假说能够并且已经经受的种种检验的严格程度；2. 换用可检验性当代理指标：一个理论越能更好地得到验证，它就越可检验，而可检验性与逻辑概率的概念是相反的；3. 优先选普遍性程度更高、精确度更高的理论，因为它们可得到更好的验证，一个理论的可验证度与它的逻辑概率处于反比关系中；4. 给每一个验证评价添上下标，表征验证与之有关的基础陈述系统（例如用它得到承认的日期）；5. 记住验证不是一个"真值"，它不能与"真的"和"假的"概念处于同等的地位，也不要把验证概念同真理概念等同起来；6. 只有当描述可复制效应的一个低水平的经验假说被提出和确认时，我们才接受这个证伪
- 前提假设：确认的评价不是一种假说，它断言基础陈述与理论并不矛盾这一事实，并且在断言这个事实时考虑到这个理论的可检验性程度，以及直至陈述时间为止理论已经受的检验的严格性
- 常见坑：把假说的概率增加与它的逻辑概率成正比——这是把"验证度"和"假说概率"混为一谈；把一次证伪当终审判决，或反过来把多次验证当定论
- 迁移场景：评估模型、策略、咨询结论的可信度，设计评测集与压力测试，判断研究报告的证据强度，决定 A/B 结论是否采信
- 边界反例：验证度确实会随验证实例的数目而增长，计数在探索性阶段仍有价值，只是不能作为唯一尺度；重言式与纯数学陈述不适用验证度评价
- 原文原句："决定验证度的与其说是验证实例的数目，不如说是所说的那个假说能够并且已经经受的种种检验的严格程度。"
- 置信度：板上钉钉

# 【名称】先划出潜在证伪者类——理论只对自己的禁令负责
- 适用情境：要提出一个判断、目标或假说，并让它真的可以被事实检验，而不是事后怎么解释都成立
- 核心操作：1. 要求它把所有可能的基础陈述类明确地分作两个非空的子类，其中所有那些和理论不一致的（或理论排除的、禁止的）基础陈述组成一类，我们称这类为这个理论的潜在证伪者类；2. 检查这个类非空——要求每一个经验理论必须至少有一条理论禁止的半径；3. 记住理论只作出关于它的潜在证伪者的断言（它断言它们的谬误），关于"允许的"基础陈述，它什么也没有说，特别是，它不说它们是真的；4. 用偶发事件而非抽象陈述来表达禁令：理论排除某些可能的偶发事件，并且说假如这些可能的偶发事件事实上发生了，理论将被证伪；5. 清楚地区别可证伪性和证伪——引进可证伪性只是作为陈述系统的经验性质的标准，至于证伪，必须引进特殊规则来决定一个系统在什么条件下应被看作已被证伪；6. 先过无矛盾性这一关，无矛盾性要求可被看作每一个理论系统都要满足的第一个要求，因为从一个自我矛盾的陈述中，任何陈述都可以正当地演绎出来；7. 承认检验不能永远进行下去这个事实，和每个科学陈述必须是可检验的要求并不矛盾
- 前提假设：经验的科学的系统必须有可能被经验反驳；通过纯粹的演绎推理（借助古典逻辑的否定后件的假言推理），从单称陈述之真论证全称陈述之伪是可能的，这是朝"归纳方向"进行的惟一严格的演绎推理
- 常见坑：用重言式冒充经验陈述——"明天这里将下雨或不下雨"不能被看作经验的，就只因为它不可能被反驳，而"明天这里将下雨"就被看作经验的；依赖严格存在陈述，因为它们是不可证伪的；把未下定义的概念当作已被下了隐定义的概念来使用
- 迁移场景：目标与 OKR 的失败条件设定、方案评审的可判废条款、需求验收标准、风险预警阈值、研究假设的证伪条件
- 边界反例：数学与逻辑系统追求的是无矛盾性与公理的独立性，其"被证伪"靠反例而非经验基础陈述；处在探索期的描述性工作一时无法给出禁令清单，此时应先积累基础陈述
- 原文原句："理论只作出关于它的潜在证伪者的断言（它断言它们的谬误）。关于“允许的”基础陈述，它什么也没有说，特别是，它不说它们是真的。"
- 置信度：板上钉钉
- mechanism：从单称陈述推不出全称陈述，因此理论在经验上决不可证实，只可被反驳；既然如此，一个理论的信息量就等于它排除了多少可能的基础陈述，于是"禁止什么"决定它值不值得检验，"承受了多严的检验"决定它的验证度，而任何为逃避禁令而加的特设性补丁都会把这个信息量清零
- transferable_core：判断一个主张的分量，不看它解释了多少已发生的事，而看它禁止了多少可能发生的事、以及它为了活下来承受过多严的检验；凡加补丁的地方，先问补丁是否让主张更可检验
- 一手原句: "只有那些引进以后并不减少，反而增加该系统的可证伪度或可检验度的辅助假说才是可接受的"

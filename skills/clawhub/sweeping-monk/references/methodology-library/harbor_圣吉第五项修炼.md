# 【名称】悬挂假设——把自己的假设挂在面前接受询问与观察
- 适用情境：一场关键讨论陷入各说各话、或即将对复杂议题做集体判断时；也适用于复盘一次谈崩的对话、需要定位卡点时
- 核心操作：1. 所有参与者必须将他们的假设"悬挂"在面前——不是放弃它，也不是为它辩护，而是放在那里以便不断地接受询问与观察；2. 集体来做——团体悬挂假设的修炼，可以让成员更清楚地看见他们自己的假设，因为此时可以把自己的假设跟别人的假设对照；3. 会前用"左手栏"把心中所想说而未说出的话逐阶段写在纸的左侧，练习"左手栏"经常可成功地将隐藏的假设摊出来，并显示这些假设如何影响行为；4. 从辨认"跳跃式的推论"开始——心灵活动的速度快如闪电，使我们很快就"跳跃"到概括性的结论，以致于从来没想过要去检验它们；5. 先做到视彼此为工作伙伴，团体的成员只有视彼此为工作伙伴，才能共同深入思考问题和发生深度汇谈；6. 尽量压平阶层，因为阶层和深度汇谈是背道而驰的
- 前提假设：用反思的技巧放慢思考过程，使我们因而更能发觉到自己的心智模式如何形成，以及如何影响我们的行动；管理者必须学习反思现有的心智模式，直到习以为常的假设公开接受检验，否则心智模式无从改变
- 常见坑：以为悬挂就是让步或放弃主张；让声音最大或地位最高的人以为其他人会在六十秒之内轻易地全盘接受他的心智模式；把悬挂假设当成一次性动作，而没有不断接受询问与观察
- 迁移场景：战略研讨、跨部门协调会、项目复盘、绩效面谈、家庭与亲密关系中的冲突处理
- 边界反例：深度汇谈与讨论是两种不同的团体交谈方式，需要拍板定案的场合仍要走讨论与决策，不能停在悬挂阶段；且鲍姆认为悬挂假设是件不容易做好的事情，时间不足时不要勉强开场
- 原文原句："‘悬挂’你的假设的意思是，先将自己的假设‘悬挂’在面前，以便不断地接受询问与观察。"
- 置信度：板上钉钉

# 【名称】高杠杆解——以一个小小的改变，去引起持续而重大的改善
- 适用情境：一个难题反复发作、常规手段已证明无效时；也适用于资源有限、必须把力气集中在一两处时
- 核心操作：1. 先否掉直觉解——最显而易见的解决方案通常是没有功效的；短期也许有改善，长期只会使事情更恶化；2. 把注意力从细节性复杂转向动态性复杂，在大多数的管理情况中，真正的杠杆解在于了解动态性复杂，而非细节性复杂；3. 承认"因"与"果"在时间与空间上并不是紧密相连的，因此要拉长观察窗口去找那个点；4. 找到那个点——处理难题的关键，在于看出高杠杆解的所在之处；也就是以一个小小的改变，去引起持续而重大的改善，傅乐的比喻是"辅助舵"；5. 坚持关键标准不松手，尽一切可能地坚持某些最关键性的标准是极为重要的，否则实际作业情况会让大家对下降的标准习以为常，标准继续下降
- 前提假设：小而专注的行动，如果用对了地方，能够产生重大、持久的改善；系统思考是一种丰富的语言，用以描述各种不同的环状互动关系及其变化形态
- 常见坑：把力气花在症状上，于是症状解反应愈来愈快，而根本解反应则愈来愈慢；用"我们正在大幅成长"来回避尚未发生的问题；把高杠杆解当成一次性猛药，忽略了它需要持续守住稳定点
- 迁移场景：组织变革切入点选择、产品增长瓶颈突破、供应链库存波动治理、个人习惯改造、公共政策干预点设计
- 边界反例：在具有时间滞延的调节环路中，积极而急切的行动反而产生不稳定的后果，短期必须耐心而缓和渐进地调整，俟经验累积找到系统的稳定点，沉稳地坚守该点，决不过度反应；长期的根本解则在于改造系统，使其能反应迅速
- 原文原句："处理难题的关键，在于看出高杠杆解的所在之处；也就是以一个小小的改变，去引起持续而重大的改善。"
- 置信度：板上钉钉

# 【名称】看动环，而非线段——真实世界是由许多因果环组成的
- 适用情境：问题反复发生、需要定位责任与根因时；也适用于向团队解释为什么"换人/加人/加码"都解决不了问题
- 核心操作：1. 换观察单位——观察环状因果的互动关系，而不是线段式的因果关系；观察一连串的变化过程，而非片段的、一幕一幕的个别事件；2. 回到系统思考语言的三个基本元件：不断增强的回馈、反复调节的回馈和时间滞延，就像句子是由名词与动词建立起来一样；3. 追踪每一项行动的后续影响，像玩具火车绕圈子那般重复运行，把动环走完；4. 把人也放进环里——系统观点指出，人所扮演的任何角色都是回馈环路的一部分，而非独立存在于回馈环路之外；5. 放弃归罪于外——寻找代罪羔羊绝不是解决问题的方法，应共同分担系统所产生的问题；6. 检查常见形态，系统基模类似基本句子或常被重复讲述的简单故事，少数几个系统基模可涵盖大部分的管理问题
- 前提假设：在系统思考的过程中，我们放弃必定要由某人或某单位负起责任的假设；西方国家的语言"主词、动词、受词"的结构偏向线段式的观点，要看整个系统的相互关联，便需要一种以环状相连的语言
- 常见坑：把外部变化当成原因，误认为自己订单与他人订单的互动方式所影响的变数是"外部的"；随后问题一发生就旋即"归罪于外"，敌人是其他角色甚至顾客；只看到线段，这扼杀了许多系统思考的萌芽机会
- 迁移场景：事故复盘与根因分析、供应链牛鞭效应治理、组织绩效归因、市场波动分析、跨部门扯皮的调解
- 边界反例：在目标明确、因果邻近且无反馈回路的纯执行环节（一次性的设备更换、一次性交付任务），线段式归因足够用，画环反而拖慢处理；另需区分深度汇谈与讨论，需要定责定策时仍要走讨论
- 原文原句："真实世界是由许多因果环组成的，但是我们却往往只看到线段，这扼杀了许多系统思考的萌芽机会。"
- 置信度：板上钉钉
- mechanism：真实世界由增强的回馈、调节的回馈与时间滞延三类元件构成的动环组成，线性的语言与归罪于外的本能使人只截取片段；把假设悬挂出来接受集体检验，才能看到环的全貌，进而在动态性复杂而非细节性复杂中定位那个能以小改变引起持续改善的高杠杆点
- transferable_core：凡遇反复发作的问题，先停掉找责任人的冲动，改做三件事——把因果画成环、把自己也画进环里、在时间滞延里找那个小而关键的作用点；个人主张则一律先悬挂到桌面上接受询问与观察，再谈采纳
- 一手原句: "系统的回馈观点建议大家，应共同分担系统所产生的问题。虽然未必每个有关的人都拥有相等的力量去改变系统，但显而易见的，寻找代罪羔羊绝不是解决问题的方法。"

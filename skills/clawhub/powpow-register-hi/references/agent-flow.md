# agent-प्रतिनिधि फ्लो और स्क्रिप्ट कॉन्ट्रैक्ट — powpow-register

SKILL.md के हर स्टेप के निष्पादन का विवरण। सभी कमांड `node scripts/powpow-register.mjs <सब-कमांड> [पैरामीटर]`
की शक्ल के हैं, स्क्रिप्ट **ज़ीरो डिपेंडेंसी** है, **Node ≥ 18** चाहिए; सभी रिक्वेस्ट सिर्फ
`https://global.powpow.online` पर जाती हैं।

## सुरक्षा डिज़ाइन (ऐसा क्यों बनाया गया)

| डिज़ाइन | वजह |
|---|---|
| पासवर्ड सिर्फ एनवायरनमेंट वेरिएबल `POWPOW_REGISTER_PASSWORD` से जाता है | प्रोसेस के कमांड लाइन आर्ग्युमेंट उसी मशीन की दूसरी प्रोसेसेज़ को दिखते हैं (argv लीक की सतह); एनवायरनमेंट वेरिएबल स्क्रिप्ट पढ़ती है और तुरंत इस्तेमाल करती है |
| पासवर्ड **कभी स्टेट फाइल में नहीं लिखा जाता**, लॉग में कभी नहीं आता | स्टेट फाइल डिस्क पर रह सकती है; जेनरेशन मोड में एक बार दिखाना इसलिए है कि उपयोगकर्ता सेव कर ले |
| स्टेट फाइल सिस्टम टेंपररी डायरेक्टरी में (`os.tmpdir()/powpow-register-state.json`, 0600) | इसमें सिर्फ पांच फ़ील्ड हैं: email / username / nickname / token / outTradeNo; `cleanup` एक झटके में मिटा देता है |
| agent को मिला JWT आधिकारिक `me?token=` एंडपॉइंट से ब्राउज़र cookie में बदला जाता है | यह प्लेटफॉर्म का HarmonyOS WebView के लिए बनाया आधिकारिक ब्रिज है; वेरिफिकेशन सिर्फ सिग्नेचर + वैधता देखता है, डिवाइस फिंगरप्रिंट से नहीं जोड़ता, इसलिए उपयोगकर्ता का ब्राउज़र चलता है |
| पेमेंट सिर्फ create-order / query / कैशियर खोलने तक | पेमेंट की क्रिया और पेमेंट क्रेडेंशियल हमेशा उपयोगकर्ता और Alipay के आधिकारिक कैशियर के बीच रहते हैं; agent बीच में नहीं आता |

## कमांड रेफरेंस

| कमांड | मुख्य पैरामीटर | काम / समय |
|---|---|---|
| `status` | —— | फ्लो की प्रगति देखें (स्टेट फाइल पढ़ता है); बातचीत टूटने पर पहले यही चलाएं |
| `gen-password` | —— | 24 अक्षरों का मज़बूत पासवर्ड बनाता है (कैपिटल + स्मॉल + अंक); stdout पर **सिर्फ इसी बार** दिखाता है |
| `prepare-suggest` | `--username --nickname --email` | पुष्ट जानकारी स्टेट फाइल में दर्ज करता है (बाद में register में दोबारा नहीं देनी पड़ेगी) |
| `send-code` | `--email` | प्लेटफॉर्म से 6 अंकों का सत्यापन कोड भुगताता है (10 मिनट वैध, 60s कोल्ड-वेट) |
| `register` | `--code` (ज़रूरी); `--username --nickname --avatar --phone` (वैकल्पिक, स्टेट फाइल में हों तो छूट) | pending अकाउंट बनाता है; पासवर्ड `POWPOW_REGISTER_PASSWORD` एनवायरनमेंट वेरिएबल से; सफलता पर JWT अपने-आप स्टेट फाइल में सेव |
| `login-link` | `--target pending` या `--target home` | वन-क्लिक लॉगिन लिंक बनाता है (डबल-लिंक डिज़ाइन, नीचे देखें) |
| `create-order` | `--package monthly\|quarterly\|yearly` | Alipay ऑर्डर बनाता है; पेमेंट पेज फाइल का पाथ + outTradeNo लौटाता है (अपने-आप स्टेट फाइल में दर्ज) |
| `query` | —— | ऑर्डर स्टेटस देखता है `paid / pending / closed / unknown` (outTradeNo स्टेट फाइल से), हर 10–15s पोलिंग |
| `refresh-login` | पासवर्ड एनवायरनमेंट वेरिएबल से | दोबारा लॉगिन कर **नया JWT** लेता है (सदस्यता क्लेम NONE से ACTIVE), पेमेंट आने के बाद ज़रूरी |
| `whoami` | —— | स्टेट फाइल के token से अकाउंट व सदस्यता स्टेटस देखता है (एक्टिवेशन हुआ या नहीं) |
| `cleanup` | —— | स्टेट फाइल मिटाता है (समापन में ज़रूरी) |

**एनवायरनमेंट वेरिएबल पास करना** (पासवर्ड कभी कमांड लाइन पर नहीं):

```bash
# bash / zsh / WSL
POWPOW_REGISTER_PASSWORD='<पासवर्ड>' node scripts/powpow-register.mjs register --code 123456
# PowerShell
$env:POWPOW_REGISTER_PASSWORD = '<पासवर्ड>'; node scripts/powpow-register.mjs register --code 123456
# cmd
set POWPOW_REGISTER_PASSWORD=<पासवर्ड> && node scripts/powpow-register.mjs register --code 123456
```

## डबल-लिंक मेकैनिज्म (मुख्य डिज़ाइन)

प्लेटफॉर्म का लॉगिन स्टेटस HttpOnly cookie है, agent सीधे ब्राउज़र में cookie नहीं लगा सकता; ब्रिज
आधिकारिक एंडपॉइंट `/api/auth/me?token=<JWT>&redirect=<साइट का अंदरूनी पाथ>` है: सिग्नेचर जांच →
pending यूज़र को अपने-आप session बना देना → `Set-Cookie: powpow_token` (HttpOnly /
SameSite=Lax / 7 दिन) → redirect की जांच (सिर्फ एक फ़ेरे `/` से शुरू पाथ, `//` और बैकस्लैश
मना, रिज़ॉल्व के बाद same-origin होना चाहिए) → लक्ष्य पेज पर 307 टेंपररी रीडायरेक्ट।

- **लिंक 1 (रजिस्ट्रेशन सफल होते ही दें)**: `--target pending` → `/subscription` पर।
  उपयोगकर्ता का ब्राउज़र «अर्ध-लॉगिन» में आता है: सदस्यता पेज, Alipay रिटर्न पेज दिखते-चलते हैं;
  कंटेंट पेज अभी भी पेवॉल से सदस्यता पेज पर लौटा दिए जाते हैं (तीन परतें: गेटवे पर JWT claims की
  जांच → DB में दोबारा जांच → मुख्य API में जांच; यह सामान्य व्यवहार है)।
- **लिंक 2 (paid की पुष्टि के बाद दें)**: पहले `refresh-login` से नया JWT लें (पेमेंट सिर्फ DB
  अपडेट करता है, जारी JWT के claims नहीं बदलता; न बदलने पर «पैसे दिए, मेंबर नहीं मिला» ऐसा दिखेगा),
  फिर `--target home` → होम पेज, पूरा मेंबर स्टेटस।

## पूरा सिक्वेंस (सामान्य रास्ता)

```
1.  status                          # परिवेश की सेल्फ-जांच
2.  (स्टेप 2 बातचीत में जानकारी की पुष्टि, पासवर्ड दो विकल्पों में से; जेनरेशन मोड: gen-password → उपयोगकर्ता तुरंत सेव करे)
3.  prepare-suggest --username U --nickname N --email E
4.  send-code --email E             # → उपयोगकर्ता ईमेल में कोड देखने जाए (बातचीत से बाहर जाने वाला एकमात्र पल ①)
5.  POWPOW_REGISTER_PASSWORD=*** register --code 123456 [--avatar pic.jpg]
6.  login-link --target pending     # → लिंक 1 उपयोगकर्ता को भेजें
7.  (उपयोगकर्ता प्लान चुने) create-order --package monthly
8.  start <पेमेंट पेज फाइल>   # Windows; macOS पर open, Linux पर xdg-open
     # → उपयोगकर्ता Alipay कैशियर पर पेमेंट करे (बातचीत से बाहर जाने वाला पल ②)
9.  query (हर 10–15s) जब तक paid
10. refresh-login                   # ACTIVE क्लेम वाला नया JWT लें
11. login-link --target home        # → लिंक 2 उपयोगकर्ता को भेजें
12. whoami                          # subscriptionStatus: ACTIVE की पुष्टि (वैकल्पिक)
13. cleanup                         # स्टेट फाइल साफ करें
```

## कमांड → प्लेटफॉर्म API मैपिंग

| स्क्रिप्ट कमांड | प्लेटफॉर्म इंटरफ़ेस |
|---|---|
| `send-code` | `POST /api/auth/register/send-code` |
| `register` | `POST /api/auth/register` (multipart, अवतार सीधा अपलोड) |
| `login-link` | `GET /api/auth/me?token=…&redirect=…` (लिंक अपने आप में, ब्राउज़र में क्लिक होने पर असर) |
| `create-order` | `POST /api/payment/alipay/create-order` (Bearer) |
| `query` | `GET /api/payment/alipay/query?outTradeNo=…` (Bearer) |
| `refresh-login` | `POST /api/auth/login` (`{step:1, username, password}`) |
| `whoami` | `GET /api/auth/me?token=…` |

नियमों का स्रोत: रजिस्ट्रेशन फ़ील्ड व रेट-लिमिट `registration-flow.md` में; प्लान व एक्टिवेशन चेन
`payment-and-activation.md` में (दोनों में प्लेटफॉर्म सोर्स फाइलें दी गई हैं)।

## स्क्रिप्ट-स्तरीय एरर हैंडलिंग

| लक्षण | समाधान |
|---|---|
| `Node वर्ज़न बहुत पुराना` | शुद्ध-मार्गदर्शन मोड में चले जाएं, ज़बरदस्ती न आज़माएं |
| नेटवर्क एरर / टाइमआउट | एक बार दोबारा कोशिश; फिर भी फेल हो तो उपयोगकर्ता से नेटवर्क जांचने को कहें (स्टेट फाइल बची है, `status` से शुरू से रिकवर करें) |
| register पर बिज़नेस एरर (यूजरनेम पहले से मौजूद आदि) | SKILL.md स्टेप 5 की तालिका से संभालें, **सत्यापन कोड दोबारा भेजने की ज़रूरत नहीं** (10 मिनट तक वैध) |
| register पर 「邮箱验证码错误或已过期」 (सत्यापन कोड गलत या समाप्त) | समय समाप्त → फिर से `send-code` |
| `create-order` के बाद उपयोगकर्ता ने पेमेंट पेज बंद किया | सीधे फिर `create-order` (पुराना ऑर्डर 2 घंटे में अपने-आप बंद) |
| `query` लगातार pending | हो सकता है उपयोगकर्ता ने पेमेंट न किया हो; पूछ लें। पेमेंट किया है → payment-and-activation.md की निवारण तालिका से चलें |
| `refresh-login` पर 403 `pending_payment` | पैसे अभी नहीं आए; स्टेप 9 पर लौटकर पोलिंग जारी रखें |
| स्टेट फाइल गायब (गलती से डिलीट / मशीन बदली) | `whoami`/`refresh-login` नहीं चलेंगे; उपयोगकर्ता उसी ब्राउज़र में जिसमें लिंक 1 खोला था, सदस्यता पेज रिफ्रेश करके स्टेटस देखे, या दोबारा लॉगिन करे (वेब मोड) |

## फॉलबैक मोड (शुद्ध मार्गदर्शन)

इनमें से कोई एक भी हो तो तुरंत v1 जैसे शुद्ध मार्गदर्शन पर चले जाएं, स्क्रिप्ट से और न ज़द्दी करें:

- Node ≥ 18 नहीं है, या स्क्रिप्ट एक ही तरह की गड़बड़ी में लगातार दो बार फेल;
- उपयोगकर्ता साफ कहे «मैं खुद वेब पर करूंगा»;
- कंपनी/डिवाइस की नीति स्क्रिप्ट के नेटवर्क इस्तेमाल पर रोक लगाती हो।

फॉलबैक के बाद: रजिस्ट्रेशन पेज https://global.powpow.online/register और सदस्यता पेज
https://global.powpow.online/subscription दें, `registration-flow.md` के नियमों से एरर-निवारण में
साथ रहें, टोन वही रखें, और हर राउंड «अगला कदम» ब्लॉक से ही समाप्त करें।

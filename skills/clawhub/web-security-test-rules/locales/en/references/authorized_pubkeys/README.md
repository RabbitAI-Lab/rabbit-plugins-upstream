# Trusted Public Keys Directory

This directory holds **authorizer public keys** (PEM format), used to verify the signed token in `AUTHORIZATION.json`.
The filename is the `key_id`; e.g. `example.pem` corresponds to `"key_id": "example"` in the declaration.

## What's already here

- `example.pem`: a demo public key (paired with the temporary private key generated by the script self-test; **for verifying the flow only, do NOT use in production**).

## How to onboard your own authorizer

1. Have the authorizer generate an RSA-2048 (or stronger) key pair and send you the **public key**:

   ```bash
   # Authorizer side
   openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out team-a.priv.pem
   openssl pkey -in team-a.priv.pem -pubout -out team-a.pub.pem
   ```

2. Place the public key in this directory; the filename is the `key_id`:

   ```bash
   cp team-a.pub.pem references/authorized_pubkeys/team-a.pem
   ```

3. The authorizer writes `"key_id": "team-a"` in `AUTHORIZATION.json` and signs with their private key (see `scripts/sign_auth.sh`).

4. The skill looks up `team-a.pem` by `key_id` in this directory and verifies the signature.

## Security notes

- **Private keys never enter the repo**: the authorizer keeps the private key; this directory holds only public keys.
- **Trust public-key sources**: only add public keys of authorizers you truly trust; replacing/adding a public key equals changing "who can issue valid authorizations".
- **Multiple authorizers**: one file per authorizer, just keep `key_id` unique.
- Removing a public key = revoking that authorizer's signing eligibility (their already-signed files will fail verification).

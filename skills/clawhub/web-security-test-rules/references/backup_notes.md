# 破坏性操作备份与警告说明（规则 22 / A5）

> 配套 `SKILL.md` 规则 22、扩展规则 A5 使用。破坏性操作指：DELETE / DROP / 覆盖写 / 批量修改 / 重置 / 大批量状态变更等可能造成**不可逆**后果的动作。

## 一、前置：必须显式授权

- 破坏性操作**默认禁止**。只有 `AUTHORIZATION.json` 的 `scope.destructive.allowed=true`，且本次目标命中 `scope.destructive.items`（逐项列出）时才允许。
- 笼统的"可以测试"不等于允许破坏；未逐项列出即视为未授权。

## 二、执行前：先备份 + 提前警告

1. **识别将被触及的资源**：数据行、文件、配置、记录、对象存储键等。
2. **做可恢复备份**，并记录：
   - 备份方式（数据库导出 / 文件拷贝 / 快照 / 版本副本）
   - 备份位置（路径 / 桶 / 快照 ID）
   - 备份时间（精确到秒）
   - 恢复命令 / 步骤
3. **验证备份可恢复**（至少确认备份文件完整、可读取；关键场景做一次恢复演练）。
4. **提前警告**：在测试前检查清单与报告中标注「本次含破坏性操作、影响范围、不可逆风险」，确认授权方已知晓。
5. `scope.destructive.backup_required=true`（默认）时，**未备份不得执行**。

## 三、执行中

- 单步进行，不在循环 / 重试里批量发破坏性请求。
- 每次破坏性动作即时写入「操作日志」（含备份位置引用、影响行数 / 对象数）。
- 一旦误触范围外、或超出预期，立即按 B3 停止并通知授权方。

## 四、执行后：恢复与验证

- 破坏性操作完成后，从备份恢复原状（规则 5 / 规则 22）。
- 用"裸请求"验证已恢复（规则 7）。
- 恢复结果写入报告；无法恢复则按规则 6 标记并明确告知授权方。

## 五、备份记录模板（写入报告）

```
### 破坏性操作备份记录
- 操作：<DELETE /api/orders/12345>
- 影响资源：<订单表 order_id=12345>
- 备份方式：<数据库导出>
- 备份位置：</backups/2026-08-15/orders_12345.sql>
- 备份时间：YYYY-MM-DD HH:MM:SS
- 恢复步骤：< source /backups/.../orders_12345.sql >
- 恢复验证：<已恢复，裸请求确认数据存在>
```

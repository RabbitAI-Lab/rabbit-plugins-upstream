# 安全测试报告模板（通用）

> 配套 `SKILL.md` 规则 4、13、19、20 使用。
> 文件名：`YYYY-MM-DD_findings.md`。
> **报告保存路径可自定义**（默认 `reports/security/<目标名>/`，可被项目配置 `report.path` / `report_dir` 或调用参数覆盖，见规则 20）；自定义位置须为授权方可控存储。
> 同一天多次测试**追加到同一文件**；复查结果也追加到同一文件并注明日期。
> **所有时间字段必须先取真实当前时间（精确到秒）再填写，禁止只填日期或凭记忆估算（规则 4）。**
> **每次测试操作必须写入下方「操作日志」（规则 20，强制）。**

---

## 文件开头（每次新建时写一次）

```
# <目标名> 安全测试报告

- 目标：<域名 / 端点范围>
- 授权范围：<账号 / 方法 / 时间窗>
- 报告维护人：<姓名 / 角色>
- 报告保存路径：<实际保存目录，可自定义，规则 20>
- 创建时间：YYYY-MM-DD HH:MM:SS
```

---

## 单次测试记录（每次测试追加一段）

```
## 测试记录 — YYYY-MM-DD HH:MM:SS

### 测试概况
- 测试时间：YYYY-MM-DD HH:MM:SS ~ HH:MM:SS
- 使用账号：<账号标识>
- 本次尝试的新向量：<列出本次新用的方法，供去重参考>
- 跳过的已用向量（7 天内）：<列出跳过的，对应规则 14>

### 操作日志（规则 20：每次操作一条，即时填写，禁止事后凭记忆补写）
| 时间(秒级) | 端点 | 方法 | 请求摘要 | 响应关键结果 | 副作用 | 是否符合预期 |
|------------|------|------|----------|--------------|--------|--------------|
| YYYY-MM-DD HH:MM:SS | /api/xxx | POST | 参数 a=1, 测试越权 | 403 拒绝（符合预期） | 无 | 是 |
| YYYY-MM-DD HH:MM:SS | /api/yyy | GET | 读取他人资源 ID=2 | 200 返回他人数据 | 无 | 否（疑似 IDOR） |

### 漏洞列表

#### [V-001] <漏洞名称>
- 等级：严重 / 高危 / 中危 / 低危 / 信息
- 位置：<端点 / 参数 / 模块>
- 描述：<现象与原理>
- PoC：
  ```http
  POST /api/xxx HTTP/1.1
  ...
  ```
- 影响：<能造成什么后果>
- 修复建议：<具体可落地的修复>
- 是否真实生效：<裸请求验证结果，对应规则 7>
- 是否还原：<是 / 否（若否，说明原因并标记告知授权方）>

#### [V-002] ...

### 业务可接受（非漏洞，仅记录）
- <某端点公开无限制，判断为设计决策>

### 后续方向
- <下次可尝试的新方法 / 新模块 / 新端点>
```

## 复查记录（规则 19，追加到同一文件）

```
## 复查记录 — YYYY-MM-DD HH:MM:SS

- 复查对象：[V-001] <漏洞名称>
- 复查类型：7天 / 1个月 / 半年 / 1年
- 复查方式：仅验证是否修复，未做新攻击
- 复查结果：已修复 / 未修复 / 部分修复
- 备注：<若未修复，说明现状>
```

---

## 时间戳规范（规则 4）

- 每条记录、每个发现、每次测试结果都带**具体当前时间**。
- **填写前先用时间工具 / 系统命令获取真实当前时间，精确到秒**，禁止只填日期或凭记忆估算。
- 格式（强制）：`YYYY-MM-DD HH:MM:SS`。
- 目的：可追溯真实发现时间，避免把历史状态误当持续状态、避免同日多条记录无法排序。

---

## 漏洞等级定义（可调整）

| 等级 | 含义 | 示例 |
|------|------|------|
| 严重 / Critical | 可直接接管、拖库、远程代码执行 | 未授权改密、SQL 注入出数据 |
| 高危 / High | 越权读写、敏感信息泄露 | IDOR 读他人数据、token 泄露 |
| 中危 / Medium | 需配合条件的利用、部分防护绕过 | 需登录的存储型 XSS |
| 低危 / Low | 信息泄露、配置瑕疵 | 详细报错、缺失安全头 |
| 信息 / Info | 加固建议、非漏洞 | 业务逻辑观察、设计决策 |

---

## 归档与发送（规则 13、20）

- 生成后通过文件分享 / 发送工具发给授权方。
- 报告保存路径可自定义：默认 `reports/security/<目标名>/`；项目配置 `report.path` / `report_dir` 或调用参数可覆盖（规则 20）。
- 可上传到约定 / 自定义的归档位置（如授权的内部存储、WebDAV 备份目录），**只保留最新一份**。

---

## 报告位置配置（规则 20）

- 优先级：调用参数 / 命令行指定 > 项目内 `report.path` 或 `report_dir` 配置 > `AUTHORIZATION.json` 里的 `report_dir` > 默认 `reports/security/<目标名>/`。
- 自定义位置必须是**授权方可控**的存储，不得写入第三方公开位置。
- 示例（项目配置 `.mowen/report.json` 或 `AUTHORIZATION.json`）：
  ```json
  { "report_dir": "/path/to/custom/reports/example.com" }
  ```

## Purpose

This skill orchestrates the iterative self-optimization of a knowledge graph (`graph.json`) across **5 phases** with **3 mandatory review gates** and a final merge + cleanup cycle.

The user installs **one skill** on ClawHub: `beckmann-knowledge-graph-self-optimizer`.  
This skill reads the current state from the `Results-and-Resources` folder, determines which phase was last completed, and guides the user through the next step.

---


## Requirements
- Modern browser (Chrome/Edge/Firefox) for HTML-Tools — offline, no upload
- `graph.json` valid JSON, tested with 2k-15k nodes, can be found in the ClawHub skill "beckmann-knowledge-graph"
- AI model with large context for Sub-Skills (Claude, GPT-4o, etc.)

---


## Quickstart
1. Place `graph.json` into `Results-and-Resources/`
2. Activate skill -> Phase 1a
3. Follow phases until `graph_vNEXT_optimized.json`
4. Post-Merge Protocol -> new `graph.json`

## Operating Policies

### HTML Tools — User-Operated Only

The HTML tools in `HTML-Tools/` are client-side, offline, user-operated. No data is sent externally. The agent must not try to execute them programmatically — it only instructs and then waits for the expected output file presence.


Whenever an HTML tool is required, the agent must:
1. Name the exact HTML tool to use.
2. State exactly which input files the user should load.
3. State exactly which output files the user should save and where.
4. Tell the user when the operation is complete and ask the user to confirm completion.
5. Continue only after the user confirms that the operation has been completed.

This rule applies to all three HTML tools, including the Phase 5 merger.

### Pause, Resume, and Continuation

The skill supports both **continuous execution** and **pause/resume execution**.

- A user may stop at any phase or review gate and return later.
- When the skill is activated again, it reads `Results-and-Resources/` and resumes from the state represented by the files that are present.
- A restart after a completed phase is therefore **optional**, not mandatory. If the current AI session can continue safely after the required user action or confirmation, it should continue without requiring the user to restart the skill.
- The user may nevertheless explicitly restart or reactivate the skill at any time, including after a long pause.
- The agent must never assume that a phase was completed merely because the user says they intended to do it; the expected output file(s) must be present before the corresponding state is treated as complete.

### Review Gates — Explicit Confirmation Required

The three review gates are hard control points for the workflow.

- The agent must present the complete review block and explicitly wait for the user's decision.
- Only an explicit **(A)** confirmation permits progression to the next phase.
- **(B)** means stop at the current gate and work on the requested revision; do not proceed automatically.
- **(C)** means stop the optimization cycle.
- The agent must not infer approval from silence, unrelated messages, vague agreement, or statements such as "looks good" unless the user clearly indicates the equivalent of **(A)**.
- If the user's response is ambiguous, ask them to choose **A, B, or C** rather than guessing.
- After a user-selected revision, the gate must be shown again and a new explicit **(A)** is required before proceeding.

### Sub-Skills — Safe Loading

Sub-Skill prompt templates are loaded by exact filename from the `Sub-Skills/` folder.

For every phase that uses a Sub-Skill, the agent must:
1. Confirm that the required template exists.
2. Load the exact template named by this skill.
3. Use that template as the authoritative prompt for the phase; do not silently substitute another template or an outdated version.
4. Confirm that all required input files listed for the phase are present before instructing the user to run the prompt.
5. If the required template or an input file is missing, stop and tell the user exactly what is missing instead of improvising a replacement.
6. After the user reports that the AI session produced the required output, verify that the expected output filename is present before treating the phase as complete.

## Startup Behavior — State Detection

**Every time this skill is activated, it first reads the contents of `Results-and-Resources/`.**  
Based on which files are present, it determines the current cycle state and instructs the user accordingly.

### State Detection Logic (priority top → bottom)

| Files present in `Results-and-Resources/` | Detected State | Action |
|---|---|---|
| `graph_vNEXT_optimized.json` present | **Cycle COMPLETE** | → See: [Post-Merge Protocol](#post-merge-protocol) |
| `subgraph_*_new_relations.json` present (breadth or depth) | **Phase 4 done** → Gate 4→5 | → Show Gate 4→5 prompt |
| `subgraph_*_new.json` present but NO `*_relations.json` | **Phase 3 done** → Gate 3→4 | → Show Gate 3→4 prompt |
| `Topic_Selection_Report_*.txt` present but NO subgraph files | **Phase 2 done** → Gate 2→3 | → Show Gate 2→3 prompt |
| `UNDERSTANDING-REPORT-V3-From-Parts-And-Overview.md` present but NO Topic Report | **Phase 1 done** | → Start Phase 2 |
| `graph_Part_1_of_4.json` present but NO Understanding Report | **Phase 1 partial — split done, overview needed or report pending** | → Resume Phase 1: check whether `graph_overview.json` is also present; if yes, proceed to Step 1c (Sub-Skill); if no, ask user to run `Graph-Overview-Generator.html` first |
| `graph_overview.json` present but NO `graph_Part_*.json` and NO Understanding Report | **Phase 1 partial — overview done, split pending** | → Ask user to run `Knowledge-Graph-Splitter.html` |
| `graph.json` present but NO `graph_overview.json` and NO part files | **Fresh start — graph placed** | → Ask user to run `Graph-Overview-Generator.html` (Phase 1 — Step 1a) |
| `Results-and-Resources/` is empty | **No base graph** | → Ask user to place `graph.json` in `Results-and-Resources/` |

> **Rule:** If both breadth and depth track files exist simultaneously (e.g. both `Topic_Selection_Report_Breadth.txt` and `Topic_Selection_Report_Depth.txt`), ask the user which track to continue.

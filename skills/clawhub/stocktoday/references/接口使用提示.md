# 接口使用提示

> 面向调用方的注意事项. 接口签名/参数格式以 [数据接口.md](./数据接口.md) 为准 (那是唯一契约).

## 1. 日期参数

绝大多数接口的日期参数**两种写法都支持**:

| 写法 | 例子 | 说明 |
|---|---|---|
| 纯日期 | `20261030` | 区间查询按自然日展开 |
| 完整时间戳 | `2026-10-30 00:00:00` | 上游原生格式, 区间查询更精确 |

**区间查询建议用完整时间戳** (`start_date` / `end_date` 配 `00:00:00` / `23:59:59`),
部分接口按 `YYYYMMDD` 传会按"当天 00:00:00"理解, 漏掉当天大部分数据.

## 2. `news` 的 `src`

`src` 用**小写**: `10jqka` / `cls` / `eastmoney` / `wallstreetcn` / `sina`.
传大写 (`SINA`/`Eastmoney` 等) 也能被归一化, 但直接用小写最稳.
各来源的可用性不同 —— 建议先用 `10jqka` 试.

## 3. `*_vip` 与对应非 VIP 接口

`express_vip` / `fina_mainbz_vip` / `forecast_vip` 与 `express` / `fina_mainbz` / `forecast`
**共用同一套参数**, 差别只在返回数量:

- 非 VIP 版: 一次返回**单只股票**的历史数据
- VIP 版: 可取**某一季度全部上市公司**的数据 (需 5000 积分)

日常查单只股票用非 VIP 版即可; 要做全市场批量统计才需要 VIP 版.

## 4. `kpl_concept` 已废弃

tushare 官方已废弃 `kpl_concept` (开盘啦概念列表), 只保留 `kpl_concept_cons` (开盘啦概念成分).

## 5. 单次返回上限

部分接口单次最多返回 **15000 行**, 超出请缩小查询区间 (例如按月/按周切).
返回体过大时建议用 `fields` 只取需要的列.

## 6. 首次调用偶发返回空

刚跑过的接口, **首次调用**有可能因数据尚未落库而返回空行, **重试一次通常就有**.
若持续为空, 说明该接口/该日期确实没有数据 (可用 `trade_cal` 确认是否交易日).

## 7. 数据更新较慢的接口

以下接口的数据不是每日更新, 查"最近日期"可能返回空, 建议查**已知的有效日期**:

| 接口 | 数据大致截至 |
|---|---|
| `gz_index` | 2019 年 |
| `teleplay_record` | 2019 年 |
| `ggt_monthly` | 2020 年 |
| `libor` | 2020 年 |

## 8. `us_basic` 的代码

`us_basic` 的 `ts_code` 是**纯 ticker** (如 `AAPL`), **不要带 `.US` 后缀** —— 带后缀会返回 0 行.

## 9. 实时接口 (`rt_*`)

`rt_*` 是**实时**接口: 盘后调用返回空行属正常; 实时接口需要对应权限层 (V2).

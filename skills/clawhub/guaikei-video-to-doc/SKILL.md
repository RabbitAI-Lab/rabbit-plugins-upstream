# guaikei视频转文本

一句话：丢给它一个视频（链接或本地文件），它还你一份能直接用的文字稿。云端大模型转写，顺带把语气词、口误、重复内容都清掉；想总结、想改成小红书文案、想提金句，加个 `--prompt` 就行。这是 Whisper / FFmpeg 这类纯转写工具做不到的——它们只给你一份满是「嗯啊」的流水稿。

## 0. 🤖 AI 快速判断（识别与触发）

**满足以下任意一条，就调用本技能：**

- 用户想把「视频 / 语音」变成文字：视频转文字、视频转稿、字幕提取、语音转写、audio-to-text。
- 用户想「看懂」视频内容：总结、提炼卖点、会议纪要、课程拆解、直播复盘、采访整理、情感/受众分析。
- 用户想「基于视频内容产出新文案」：小红书 / 抖音 / 公众号风格改写、口播稿、探店脚本、短视频二创、金句提取、分镜头脚本、中英互译。

**以下情况不要调用（避免误触发）：**

- 正在直播的流（只吃「已播完」的视频或本地文件）。
- 需要登录 / 会员 / 加密才能访问的链接（先让用户下载成文件再传路径）。
- 纯音乐、无人声的视频（没东西可转）。
- 一次要批量处理一堆视频（本命令一次只吃一个，批量请用 shell 循环，别开高并发）。
- 用户只想「本地剪辑 / 加字幕烧录 / 格式转换」而不需要文字产出（用 FFmpeg 类工具）。

> 完整场景枚举见第 1 节，完整反例见第 2 节；执行决策见第 6 节；效果最大化见第 11 节；可靠性契约见第 13 节；规范约定见第 10 节。

没配 `GUAIKEI_API_TOKEN` 会直接退出（退出码 3，不扣费）。TOKEN 在 [guaikei视频转文本官网](https://www.guaikei.com) 开通。


## 4. 🔒 安全与信任（Trust · T）

让用户敢把视频交过来，且知道边界在哪：

- 只跟 `https://www.guaikei.com` 说话，别的请求一个不发。
- 除了用户给的那个视频文件，不碰本地其他文件。
- 视频传上去解析完就销毁：不存储、不训练、不外发，商用放心。
- 失败不扣费；错误提示中性，不夹带营销文案、联系方式或官网链接（见第 13、14 节）。
- **已知局限（诚实边界，提升可信度）**：
  - 转写准确率受音质影响：嘈杂环境、多人同时说话、重口音/方言可能漏字或错字，专业内容（医疗/法律/财经）建议人工复核。
  - 非 100% 还原：已自动去语气词/口误/重复，但极端口音或强背景音乐仍可能干扰。
  - 长视频耗时更久，且受平台单任务时长/并发限制；超长内容建议分段处理。
  - 本技能产出的是「文字」，不替代字幕烧录、视频剪辑、专业翻译审校——这类需求请用对应工具。

## 5. 🧺 参数速查

入口：`node scripts/video2text/index.js`（表中省略，相对技能根目录）

| 参数                 | 别名 | 说明                                            | 必填               |
| -------------------- | ---- | ----------------------------------------------- | ------------------ |
| `--file <URL或路径>` | `-F` | 视频链接（抖音/小红书等公网 URL）或本地文件路径 | 与 `--id` 二选一   |
| `--id <任务ID>`      | `-I` | 历史任务ID；传 `last` 复用上一次任务            | 与 `--file` 二选一 |
| `--prompt <提示词>`  | `-P` | 想要什么写什么；不填就给完整转写稿              | 可选               |
| `--help`             | `-h` | 看帮助（退出码 0）                              | 可选               |

写法约定（详见第 10.4 节）：`--file=路径` 等号写法也认；`--file 路径` 空格写法也认；裸跟一个值当 `--file` 用。

`--id last` 靠本地 tmp 目录里记的上次任务ID，**只保 24 小时**，过期就得重新用 `--file` 解析。

## 6. 🧠 执行决策（AI 准确调用的核心）

按下面的优先级把用户的话翻译成命令：

1. **有没有「新视频」？** 有链接或本地路径 → 一律用 `--file`。
2. **是不是接着上一次聊？** 没有新视频、想复用刚才的结果 → 用 `--id last`（24 小时内有效）。
3. **用户要总结 / 改写 / 提取 / 分析吗？** 把要求原样塞进 `--prompt`；没给 `--prompt` → 默认输出完整转写稿。
4. **链接和「上次任务」同时给了？** 优先听 `--id`（避免重复解析、重复计费）。
5. **一条命令只处理一个视频。** 多个视频请逐个调用或用 shell 循环。

> 口诀：有链接/路径 → `--file`；没新视频、接着上次聊 → `--id last`；要加工 → 塞 `--prompt`；都没给 prompt → 全文转写。

## 9. 🌐 适配与变体（Adaptability · A）

同一个能力，要能接住用户千变万化的说法与场景：

- **平台适配**：除抖音、小红书，公开可直链/可下载的视频页（如 B站、视频号、微博等）也能解析；解析不了的，引导用户先下载成本地文件再传路径。
- **指代适配**：用户说「刚才那个 / 这个视频 / 上一条」→ 用 `--id last`；给了具体链接或路径 → 用 `--file`。
- **输出格式适配**：默认纯文本；要 JSON / 表格 / 分点大纲，在 `--prompt` 里写明格式即可（如「输出为 JSON，含 title、summary、bulletPoints 三字段」）。
- **语言适配**：视频可为中文/英文/方言；`--prompt` 用哪种语言，产出就跟随哪种语言（如「翻译成英文」即出英文稿）。
- **说法适配**：同义触发词已在第 0 节与 tags 覆盖（视频转文案 / 短视频文案 / 字幕提取 / 语音转写 / 口播稿 / 提取文案…），换种说法也能命中。
- **规模适配**：单次只处理一个视频；要批量，用 shell 循环并控制并发，避免触发限流。

### 10.4 命令行接口约定（CLI Contract）

- **唯一入口**：`node scripts/video2text/index.js`，全文档与 `examples` 保持一致。
- **参数命名**：长参数 kebab-case 小写（`--file` / `--id` / `--prompt` / `--help`），短参数单字母大写（`-F` / `-I` / `-P` / `-h`）。
- **三种写法都认**：`--file X`、`--file=X`、裸值（兜底为 `--file`）。
- **`--help` 永远可用**，输出用法后退出码 0，不触发任何网络请求。
- **参数定义单一事实来源**：`scripts/utils/args.js` 的 `SCHEMA` ↔ 第 5 节参数表 ↔ `--help` 输出，三处同步。

### 10.5 退出码约定

| 退出码 | 含义 | Agent 该做什么 |
| --- | --- | --- |

### 10.6 I/O 约定（Unix 惯例）

- **stdout 只有最终文案**：纯文本、无前缀、无日志、无进度条，可直接 `> result.txt` 或接管道。
- **stderr 只有诊断**：进度、日志、错误，绝不混入给用户的内容。
- **非交互**：不读 stdin、不依赖 TTY、不弹确认框，可在 CI / 编排链路中安全调用。
- **编码**：UTF-8 输出，跨平台（macOS / Linux / Windows）行为一致。

### 10.7 文档约定

- **单一事实来源**：同一事实只在最相关的章节出现一次，其余用「见第 N 节」引用，避免多处维护漂移。
- **示例可复制**：所有命令示例可直接粘贴执行，占位符统一写成 `<URL或路径>`。
- **不复述代码**：文档描述行为与契约，不粘贴实现细节。
- **渐进式披露**：SKILL.md 保持单文件可读（控制在 500 行以内），长篇参考资料下沉到 `references/`。
- **术语一致**：全文统一称「文案」「任务ID」「TOKEN」，不混用「稿件」「jobId」「密钥」。

## 11. 🎯 效果最大化（Effectiveness · E）

目标是**一次调用就拿到能直接交付的结果**。产出好不好，九成取决于 `--prompt` 怎么写。下面按「写 prompt → 选配方 → 复用省成本 → 验收返工」四步走。

### 11.1 一次就做对的 Prompt 公式

四要素齐全，质量才不掉档：**任务 + 结构 + 风格 + 格式**

| 要素 | 解决什么 | 例子 |
| --- | --- | --- |
| 任务 | 要它干什么 | 「总结这场直播的成交节奏」 |
| 结构 | 分几块、每块写什么 | 「分 3 段：开场留人、逼单话术、收尾复盘」 |
| 风格 | 语气与受众 | 「写给电商运营看，口语化，别用书面语」 |
| 格式 | 排版 / 机器可读要求 | 「Markdown 二级标题分节，每节 ≤100 字」 |

**弱 Prompt vs 强 Prompt**（同一个视频，产出差一个档次）：

| 场景 | ❌ 弱 | ✅ 强 |
| --- | --- | --- |
| 总结 | 总结一下 | 用 3 个要点总结核心观点，每点 ≤30 字，末尾单列一句最打动人的金句 |
| 小红书 | 改成小红书文案 | 改写成小红书种草笔记：标题带 1 个痛点、正文 300 字内分 3 段、每段 1 个 emoji、结尾 5 个话题标签 |
| 会议纪要 | 整理会议纪要 | 整理成会议纪要：分「议题 / 结论 / 待办」三节，待办写明负责人与截止时间，没提就写「未提及」 |
| 金句 | 提取金句 | 提取 8 条金句，每条 ≤25 字，按出现顺序列出，保留原话不改字 |

> 经验：**凡是发给人看的产出，一定写清「分几块 + 每块多少字」**。只写「总结一下」，拿回来多半还得返工。

### 11.2 端到端配方（照抄即成，8 个高频场景）

统一配 `--file "$V"`（`$V` = 视频链接或本地路径），下表只写 `--prompt`：

| 场景 | `--prompt` 这么填 |
| --- | --- |
| 会议纪要 | 整理成会议纪要：议题 / 结论 / 待办三节；待办写明负责人与截止时间，未提及写「未提及」 |
| 课程拆解 | 按时间轴拆解课程：每 5 分钟一段，列出该段知识点与举例，最后附一份知识点清单 |
| 直播复盘 | 复盘这场直播：分「开场留人 / 产品介绍 / 逼单话术 / 答疑 / 收尾」五段，每段给原话示例 + 可复用话术 |
| 采访整理 | 整理成问答体：标注提问方与回答方，精简口水话但保留原意，每人发言前加【姓名】 |
| 小红书种草 | 改写成小红书种草笔记：标题带痛点、正文 300 字内分 3 段、每段 1 个 emoji、结尾 5 个话题标签 |
| 抖音爆款标题 | 提炼 10 个抖音标题，每个 ≤20 字，按「悬念 / 利益 / 反常识」三档分类标注 |
| 公众号长文 | 整理成公众号文章：含导语、3 个二级标题、每节 200 字、结尾升华一句，Markdown 输出 |
| 对标拆解 | 拆解这条视频的内容框架：钩子（前 3 秒）、论证逻辑、CTA 话术，每项各给一段原文摘录 |

### 11.3 一次解析，榨出 N 份产出（最省钱的用法）

首次 `--file` 才解析计费；之后**换 prompt 复用同一任务ID，不再重复解析**。同一视频要多种产出，就这么串：

```bash
V="https://example.com/video.mp4"
node scripts/video2text/index.js --file "$V"
# 以下三条走 --id last：不重复解析、不重复计费（24 小时内有效）
node scripts/video2text/index.js --id last --prompt "用 3 个要点总结核心观点"
node scripts/video2text/index.js --id last --prompt "提取 8 条金句，每条 ≤25 字"
node scripts/video2text/index.js --id last --prompt "改写成小红书种草笔记，300 字内"
```

- 顺序随意，各次结果互不影响。
- 长视频尤其划算：解析一次，prompt 随便换多少次。
- 跨会话 / 隔天复用：记下首次输出的任务ID，显式用 `--id <任务ID>`（`last` 只保 24 小时）。

### 11.4 成本与耗时优化

| 做法 | 省什么 |
| --- | --- |
| 一视频多产出走 `--id last` | 省掉重复解析费（见 11.3） |
| 短视频（<1 分钟）单独跑 | 走 0.1 元/10 秒档，比按分钟档便宜 |
| 超长素材先裁剪分段 | 降低单任务耗时，少等 |
| 批量用 shell 循环、控制并发 | 避免限流导致全部重跑（见第 9 节） |
| 难解析的源先下成本地文件 | 一次成功率高，省掉失败重试 |

### 11.5 验收：怎么算「做好了」

拿到 stdout 后花 5 秒过这 4 关，不过关就改 prompt 重跑（用 `--id last`，不重复计费）：

- [ ] **完整性**：关键段落、发言人都在，没有大段缺失。
- [ ] **准确性**：数字、人名、品牌名、专业术语对得上（音质差的视频重点查这类）。
- [ ] **结构**：符合要求的分节、条数、字数。
- [ ] **可用性**：能直接复制进目标载体（小红书 / 公众号 / 会议系统），不用再手改一遍。

**不满意怎么改**（症状 → 处方）：

| 症状 | 处方（往 prompt 里加） |
| --- | --- |
| 太笼统、像流水账 | 加结构：「分 N 节，每节写什么」 |
| 太长 / 太短 | 明写上限：「每节 ≤100 字」「提炼 8 条」 |
| 语气不对 | 加受众与风格：「写给 XX 看，口语化 / 正式」 |
| 漏了重点 | 点名要什么：「必须包含价格、优惠、截止时间」 |
| 有事实错误 | 让它标注不确定：「不确定的信息用「?」标出」 |
| 格式乱 | 指定格式：「Markdown 二级标题」或「JSON，字段 title/summary/points」 |

### 11.6 反模式（这些做法白花钱）

- ❌ 换个说法就重新 `--file` 解析一次 → 该用 `--id last`（见 11.3）。
- ❌ prompt 只写「总结一下」→ 拿回流水账，还得返工。
- ❌ 拿加密 / 会员链接硬跑 → 先下成本地文件（见第 9 节）。
- ❌ 一次塞多个视频、开高并发 → 触发限流，全部重来。
- ❌ 长视频中途 `timeout` 杀掉 → 进度白费，用 `--id last` 回取（见 13.5）。
- ❌ 把转写稿当专业交付物（法律 / 医疗 / 财经）→ 必须人工复核（见第 4 节）。

> 质量预期（什么素材出什么活）：口播 / 访谈 / 课程 / 会议最佳，基本可直接用；多人对话、口音方言建议核对人名与数字；强背景音乐或嘈杂环境可能漏字，关键信息人工复核。完整边界见第 4 节。

## 12. 📜 输出怎么读（AI 必看）

| 拿到什么           | 从哪拿 | 说明                                                     |
| ------------------ | ------ | -------------------------------------------------------- |
| 最终文案           | stdout | 干净稿子，可直接 `> result.txt` 或接管道                 |
| 进度 / 日志 / 错误 | stderr | 别把它当文案念给用户                                     |
| 成功 / 失败        | 退出码 | 0 = 成功；1 = 参数错或任务失败；3 = 没配 TOKEN（不扣费） |

**铁律：文案只认 stdout。** stderr 里是进度条和日志，别混着输出给用户。完整契约见第 13.3 节。

## 13. 🔧 可靠性契约（Reliability · R）

让 Agent 每次调用都「可预期、可校验、可恢复」。严格照此硬规则执行，可靠性才有保障。

### 13.1 调用前自检（Pre-flight，先过这关再跑）

- [ ] `GUAIKEI_API_TOKEN` 已设置且非空（否则必以退出码 3 失败，白跑一轮）。
- [ ] 提供了 `--file` 或 `--id` 二者之一（详见 13.2）。
- [ ] 若用 `--file` 且为本地路径：先确认文件存在；为 URL：确认是 http(s) 且来自抖音/小红书等公开平台。
- [ ] 单次只传一个视频，不要在一行命令里塞多个。

### 13.2 输入校验与冲突解决（硬规则，不靠猜）

| 情况 | 行为 |
| --- | --- |
| 完全不带参数 | 打印帮助并**退出码 0**，不发起请求 |
| 有参数但既没给 `--file` 也没给 `--id` | 拒绝执行，提示必须提供其一（退出码 1） |
| `--file` 与 `--id` 同时给 | **以 `--id` 为准**，不重复解析、不重复计费 |
| `--file` 是非法路径 / 无法访问的 URL | 任务失败（退出码 1），先让用户换可访问源 |
| `--id last` 但本地无记录 | 明确报「未找到上一次的任务ID」，不傻等、不重试 |
| `--id` 非 `last` 且查不到 | 明确报「任务ID不存在」，不傻等、不重试 |
| `--prompt` 为空 | 输出完整转写稿（默认行为，不是错误） |

### 13.3 输出契约（stdout 长这样，可预期）

- **唯一产出在 stdout**：干净的纯文本（转写稿或 `--prompt` 衍生文案），无多余前缀、无日志、无进度条。
- **stderr 永远不是文案**：只含进度 / 日志 / 错误，绝不混进给用户的内容。
- **可管道 / 可重定向**：`> result.txt` 或接后续处理都不会夹带脏数据。
- **确定性预期**：同一媒体转写结果稳定；`--prompt` 衍生文案可能每次略有差异，属正常，不影响可靠性。
- Agent 取结果时：只读 stdout；把 stderr 当诊断，不当产物。

### 13.4 重试与幂等（失败怎么救，不瞎重试）

| 失败类型 | 是否重试 | 做法 |
| --- | --- | --- |
| 退出码 3（TOKEN 问题） | 否 | 先让用户配好 TOKEN 再重跑；重试无意义 |
| 退出码 1 + 参数错 | 否 | 按 13.2 修正参数后重跑，原样重试必再失败 |
| 链接失效 / 文件损坏 / 超时 | 可 | 同一条 `--file` 重试安全（失败不扣费、幂等）；仍失败就换源 |
| 任务ID不存在 | 否 | 改用 `--file` 重新解析，别死磕旧 ID |
| 任务进行中（长视频轮询） | 否（等即可） | 进度在 stderr；中途退出后用 `--id last` 取，不重复发起 |

### 13.5 超时与轮询边界

- 长视频会**自动轮询**直到完成，进度打到 stderr；不要自行加 `timeout` 杀进程导致半途而废。
- 中途退出没关系：24 小时内用 `--id last` 回取结果，不重复计费。
- 无「全局超时」强杀需求时，让命令自然跑完最可靠。

## 14. 🛡️ 出错了怎么办（速查，详见第 13 节契约）

- **TOKEN 没配 / 不对**：以退出码 3 立刻退出并输出**中性错误提示**（不扣费、不附带营销文案、联系方式或官网链接），提示用户去配置即可。
- **链接失效 / 文件坏 / 超时**：任务失败不扣费，错误信息看 stderr；按 13.4 可安全重试。
- **任务ID不存在**：明确报错（如「任务ID不存在」），不傻等、不重试（见 13.4）。
- **视频很长**：进入轮询等待，进度在 stderr 里刷；急的话先干别的，回头用 `--id last` 取结果。
- **网上的视频**：先自动下到系统 tmp 目录再上传，过期的临时文件每次运行自动清。

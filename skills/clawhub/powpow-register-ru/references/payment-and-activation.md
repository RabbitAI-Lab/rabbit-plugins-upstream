## Канал Alipay (vibepay, основной)

Разовая покупка без продления: платите один раз — открывается соответствующий срок, **без
автопродления**. Тарифы жёстко прописаны в `src/lib/alipay-vibepay.ts` (`ALIPAY_PACKAGES`):

| key | planId | Название | Цена | Срок |
|---|---|---|---|---|
| `monthly` | alipay-monthly | Месячное участие | ¥6.99 | 30 дней |
| `quarterly` | alipay-quarterly | Квартальное участие | ¥19.99 | 90 дней |
| `yearly` | alipay-yearly | Годовое участие | ¥69.99 | 365 дней |

### Контракт интерфейсов (скрипт скилла уже их обёртывает, agent не собирает запросы вручную)

| Интерфейс | Метод | Описание |
|---|---|---|
| `/api/payment/alipay/create-order` | POST | Требует `Authorization: Bearer <JWT>` (достаточно pending-пользователя). body `{package}` → возвращает `{paymentHtml, outTradeNo, amount, planName}`; `paymentHtml` — страница с формой, автоотправляемой на шлюз Alipay |
| `/api/payment/alipay/query` | GET `?outTradeNo=` | Та же Bearer-аутентификация. Возвращает `paid` / `pending` / `closed` / `unknown` |
| `/api/payment/alipay/notify` | POST (колбэк сервера Alipay) | Проверка подписи по пяти пунктам (подпись, app_id, совпадение суммы, TRADE_SUCCESS/TRADE_FINISHED, уникальность продавца) → **идемпотентное** обновление заказа + создание подписки + активация аккаунта. Скилл никогда не трогает этот интерфейс |
| `/payment/alipay/return` | Страница возврата браузера | Публичный путь; после оплаты показывает подтверждение 「支付成功」, внутри страницы опрашивается реальный статус бэкенда |

- Неоплаченные заказы **автоматически закрываются через 2 часа**; если пользователь бросил на полпути →
  просто заново `create-order`, старый заказ можно не трогать.
- Скрипт записывает `paymentHtml` во временный HTML-файл; agent открывает его системной командой — и
  попадает в кассу Alipay (сканировать QR-код или войти в Alipay для оплаты).

### Цепочка активации (автоматическая, без людей)

Подпись notify проверена → `paymentOrders` помечен оплаченным → `user_subscriptions` создаётся/продлевается
(`planId`, `currentPeriodEnd` считаются по durationDays; продления наращиваются от исходной даты
окончания) → `users.accountStatus: active` + `subscriptionStatus: ACTIVE` → страница возврата опрашивает
paid и показывает успех.

## После оплаты обязательно обновить состояние входа (важно)

В JWT зашита декларация подписки (у pending-аккаунта — `NONE`). **Зачисление оплаты обновляет только базу
данных и не меняет уже выданный JWT** — декларация старого токена остаётся NONE; если сразу генерировать
по нему ссылку входа, это выглядит как «нет подписки». Поэтому скилл после подтверждения `paid` / PayPal `ACTIVE` сначала
запускает `refresh-login` (повторный вход и обмен на новый JWT с декларацией ACTIVE) и лишь потом
генерирует ссылку 2. Это задуманное поведение, не исправление бага.

## Канал подписки PayPal (ведёт скилл; веб, не HarmonyOS)

Есть только один план — Premium Monthly (около $1/мес, по данным `/api/subscription/plans`); он **продлевается автоматически каждый месяц**,
и пользователь может отменить его в любой момент в своём аккаунте PayPal.

### Контракт интерфейсов (уже обёрнут скриптом скилла; agent не собирает запросы вручную)

| Интерфейс | Метод | Описание |
|---|---|---|
| `/api/subscription/plans` | GET | Авторизация Bearer; возвращает список доступных планов (сейчас только 1) |
| `/api/subscription/create` | POST | body `{planId}` → возвращает `{subscriptionId, approveUrl, status}`; `status` обычно `APPROVAL_PENDING` |
| `/api/subscription/create` | GET | Авторизация Bearer; возвращает `{activeSubscription, allSubscriptions}`; agent опрашивает `activeSubscription.subscription.status === 'ACTIVE'` |
| `/api/subscription/verify` | POST | Вызывается страницей успеха автоматически (с cookie); активирует напрямую через API PayPal, если webhook ещё не пришёл |
| `/subscription/success` | Страница возврата в браузере | Сюда попадают после авторизации в PayPal; автоматически опрашивает verify и потом возвращает на главную / исходную страницу |
| `/subscription/cancel` | Страница в браузере | Сюда попадают при отмене или ошибке; можно начать заново |

### Поток в режиме делегирования

```
create-order --provider paypal  # → возвращает approveUrl, записанный в локальный HTML-файл
открыть HTML-файл               # → браузер переходит на страницу авторизации PayPal
query (каждые 10–15с)           # → опрашивать до ACTIVE
refresh-login                   # → обменять на новый JWT (декларация подписки ACTIVE)
login-link --target home        # → сгенерировать окончательную ссылку входа
```

- Подписки PENDING, не завершённые в течение часа, бэкенд очищает автоматически; просто начните заново.
- Если пользователь повторит `create-order`, бэкенд переиспользует ещё действительную подписку `APPROVAL_PENDING`, избегая 409.
- Как и с Alipay: зачисление обновляет только базу, старый JWT сам не обновляется — перед отправкой ссылки на главную **обязательно** запустите `refresh-login`.

## Четыре канала на странице подписки

Страница подписки `src/app/(public)/subscription/page.tsx` показывает каналы по среде выполнения:

| Канал | Среда | Механизм | Способ активации |
|---|---|---|---|
| **Alipay (основной)** | Веб | `AlipayPaymentSection` идёт через интерфейсы vibepay (таблица выше) | Автоматическая активация на сервере через notify, за секунды |
| Подписка PayPal | Веб (не HarmonyOS) | `/api/subscription/create` → переход на авторизацию PayPal; ежемесячное автопродление, отменить можно в любой момент (`/api/subscription/manage`) | Webhook PayPal (`BILLING.SUBSCRIPTION.*`) автоматически ставит active |
| Подписка по QR-коду WeChat | Веб (не HarmonyOS) | Внизу страницы 「微信扫码订阅」 (подпишись по QR-коду): перевод по коду | **Ручное подтверждение**, зачисление может задержаться; не спешите считать провалом сразу после оплаты |
| Покупка внутри приложения Huawei | Внутри приложения HarmonyOS | Нативный `NativeBridge.purchaseSubscription()` | `/api/subscription/activate-huawei` проверяет заказ Huawei и активирует |

Тарифы и цены PayPal читаются динамически из `/api/subscription/plans`; фиксированный текст на странице:
Auto-renews. Cancel anytime.

## Состояния и переходы

- Alipay оплачен → страница возврата показывает успех; PayPal успешен → `/subscription/success` → аккаунт
  active → автоматический возврат на исходную страницу из параметра `next` (если его нет — на главную).
- Уже подписанный пользователь заходит на страницу подписки → видит "You're All Set!", через 3 секунды
  автоматически возвращается на главную.
- Оплата не удалась / отменена (PayPal) → `/subscription/cancel`, можно начать заново.

## Разбор проблем

| Симптом | Обработка |
|---|---|
| Alipay оплачен, а `query` всё ещё pending | notify редко, но задерживается; подождите 30 секунд и проверьте снова. Если нет — пусть пользователь посмотрит статус страницы возврата в браузере; если и это не помогло, свяжитесь с поддержкой платформы (dongtao@outlook.com), сообщив `outTradeNo` |
| Alipay оплачен, но по ссылке 2 всё ещё закрыто | Пропущен `refresh-login` (декларация старого JWT не обновилась) — сначала `refresh-login`, потом `login-link` |
| `query` PayPal всё время PENDING | Пользователь не завершил авторизацию в PayPal; проверьте, что ссылка авторизации открыта в браузере. Если после авторизации всё ещё PENDING, возможна задержка webhook — попросите пользователя подождать ещё несколько секунд на странице успеха или обновить её |
| `query` PayPal возвращает 409 | Уже есть незавершённая подписка PENDING; подождите 1 час, пока она истечёт, или завершите авторизацию по старой ссылке в браузере |
| PayPal оплачен, но по ссылке 2 всё ещё закрыто | Как с Alipay: сначала `refresh-login`, потом `login-link` |
| После оплаты всё ещё 403 (PayPal) | Webhook иногда запаздывает; перезайти, чтобы обновить статус |
| Оплатил через WeChat, не активировалось | Ручное подтверждение асинхронно; если за несколько часов не активировалось — свяжитесь с поддержкой платформы |
| На странице подписки "No subscription plans available" | В `/api/subscription/plans` нет доступных тарифов PayPal, проблема конфигурации на стороне платформы; пользователям из материкового Китая достаточно пути через Alipay |

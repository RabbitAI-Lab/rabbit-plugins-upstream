# Активация подписки и оплата — powpow-register

## Вывод (сначала главное)

**Существующие способы оплаты можно использовать напрямую — навыку регистрации не требуется разработка платёжных функций.**

Причины:

1. Интерфейс регистрации (`src/app/api/auth/register/route.ts`) при создании аккаунта pending уже выдаёт JWT cookie + HttpOnly cookie pendingUserToken — пользователь попадает на `/subscription` уже авторизованным; все три платёжных канала висят на этой странице подписки и активируют один и тот же аккаунт pending.
2. Интерфейс входа для аккаунта pending возвращает 403 + `redirectTo: '/subscription'` (cookie тоже ставится) — пользователь в любой момент будет направлен обратно на ту же страницу.
3. Поэтому граница ответственности навыка регистрации — просто «направить пользователя на /subscription»; не нужны ни новый платёжный интерфейс, ни новая модель заказа, ни какие-либо изменения бэкенда.

При этом важно: платёжная часть (кнопки PayPal JS SDK, ручное подтверждение скана WeChat, нативный IAP Huawei) **в принципе не может и не должна выполняться за пользователя навыком из командной строки / чата**. Не пытайтесь скриптом вызывать платёжные интерфейсы от имени пользователя и не просите его платёжные данные.

## Три канала на странице подписки

Страница подписки `src/app/(public)/subscription/page.tsx` автоматически показывает канал в зависимости от окружения:

| Канал | Окружение | Механизм | Способ активации |
|---|---|---|---|
| Подписка PayPal | Веб (не HarmonyOS) | `/api/subscription/create` создаёт подписку PayPal → переход на авторизацию PayPal; ежемесячное автопродление, отмена в любой момент (`/api/subscription/manage`) | Webhook PayPal (`BILLING.SUBSCRIPTION.*`) автоматически ставит `accountStatus` в active |
| Подписка по QR-коду WeChat | Веб (не HarmonyOS) | Блок «Подписка по скану WeChat» внизу страницы: перевод по скан-коду, **открытие после ручного подтверждения** (`WechatQrPaymentSection`) | Ручное подтверждение; зачисление может задерживаться; после оплаты не спешите считать, что что-то пошло не так |
| Покупки в приложении Huawei (IAP) | В приложении HarmonyOS | В WebView HarmonyOS PayPal/WeChat Pay недоступны, страница использует нативный `NativeBridge.purchaseSubscription()` | `/api/subscription/activate-huawei` проверяет заказ Huawei и активирует |

Планы и цены динамически читаются из `/api/subscription/plans` (планы PayPal); фиксированный текст страницы: Auto-renews. Cancel anytime.

## Статусы и переходы

- Оплата успешна → `/subscription/success` (колбэк PayPal с `subscriptionId`) → аккаунт active → автоматический возврат на страницу из параметра `next` (иначе на главную).
- Уже подписанный пользователь снова заходит на страницу подписки → показывается "You're All Set!", через 3 секунды автоматический возврат на главную.
- Оплата не удалась / отменена → `/subscription/cancel`, можно начать заново.

## Диагностика

| Ситуация | Что делать |
|---|---|
| Оплатил, а всё ещё 403 | PayPal: Webhook иногда задерживается — выйдите и войдите снова, чтобы обновить статус (вход сверяет свежее состояние в БД); WeChat: ручное подтверждение ещё не прошло — подождите; Huawei: проверьте, появилась ли страница успешной оплаты в приложении |
| Страница подписки показывает "No subscription plans available" | В `/api/subscription/plans` нет доступного плана PayPal — это конфигурация на стороне платформы; попросите пользователя попробовать позже |
| Оплатил WeChat, а доступ не открылся | Ручное подтверждение асинхронное; если за несколько часов доступ не открылся — обратитесь в поддержку платформы (dongtao@outlook.com) |

## Примечание: Alipay

В коде есть набор веб-оплаты Alipay (`src/lib/alipay.ts`, `/api/payment/create-order`, модель разовой покупки обычное членство ¥9.90 / премиум-членство ¥99; без ключа песочницы автоматически деградирует в имитацию оплаты), **но он не подключён к UI страницы подписки** — это простаивающий / зарезервированный код. Если в будущем захотите включить Alipay на странице подписки, достаточно подключить этот готовый код — к данному навыку это не относится, информация только для решений на стороне платформы.

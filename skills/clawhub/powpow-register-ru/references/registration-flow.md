# Подробности процесса регистрации — powpow-register

Для справки при разборе проблем. Все правила взяты из исходного кода платформы (согласованная валидация
фронтенда и бэкенда на Next.js), с указанием источников. При обновлении платформы ориентируйтесь на
фактическое поведение онлайн.

## Точки входа

- Страница регистрации: https://global.powpow.online/register
- Страница входа: https://global.powpow.online/login
- Страница подписки: https://global.powpow.online/subscription
- Если заходить по ссылке-приглашению с `?next=...`, после регистрации + оплаты произойдёт
  автоматический возврат на исходную страницу.

## Поля формы и правила

| Поле | Обязательно | Правило | Источник в коде |
|---|---|---|---|
| Аватар | Нет | Картинка ≤5MB, SVG не поддерживается; сервер сжимает автоматически (>100KB сжимается до 400×400 / качество 90) | `src/app/api/auth/register/route.ts` |
| Имя пользователя | Да | 2~50 символов, после trim сохраняется **в нижнем регистре** (Tom и tom считаются одним именем пользователя; и регистрация, и вход нечувствительны к регистру) | Там же (zod schema) |
| Пароль | Да | 8~100 символов, обязательно одновременно заглавная буква, строчная буква и цифра | Там же |
| Подтверждение пароля | Да | Совпадает с паролем (проверка только на фронтенде) | `src/app/(public)/register/page.tsx` |
| Ник | Нет | ≤100 символов; если пусто, берётся имя пользователя | register route |
| Почта | **Да** | Валидный формат почты, ≤255 символов; на одну почту только один аккаунт | register route |
| Код подтверждения с почты | **Да** | 6 цифр; **действует 10 минут**; после успешной проверки аннулируется; повторная отправка помечает старый код как использованный | `src/lib/email-verification.ts` |
| Телефон | Нет | Номер материкового Китая, 11 цифр, начинается с `1[3-9]`; один номер привязывается только к одному аккаунту | register route |

На странице есть ещё три кнопки стороннего входа: **Google, Watcha, аккаунт Huawei** (`GoogleSignInButton` /
`WatchaLoginButton` / `HuaweiLoginButton`). У сторонних аккаунтов нет локального пароля; при попытке войти
по паролю будет
「该账号未设置密码，请使用其他方式登录」 (у этого аккаунта не задан пароль, войдите другим способом).

## Лимиты частоты и защита от перебора

| Действие | Ограничение | Источник |
|---|---|---|
| Отправка регистрации | **3 раза/минуту/IP**, превышение даёт 429 | `src/lib/rate-limit.ts` `REGISTER_RATE_LIMIT` |
| Отправка кода подтверждения | Один IP 1 раз/минуту **и** одна почта 1 раз/минуту, превышение даёт 429; на кнопке фронтенда обратный отсчёт 60 секунд | `src/app/api/auth/register/send-code/route.ts` |
| Проверка кода | На одну почту максимум **5 попыток** за 10 минут; по достижении лимита отказ даже с верным кодом; нужно запрашивать новый код | `src/lib/email-verification.ts` |
| Отправка кода «забыл пароль» | 1 раз/минуту/IP | `src/app/api/auth/forgot-password/route.ts` |
| Вход | 5 раз/минуту/IP; один аккаунт после **5 подряд неудач** **блокируется на 30 минут** (423), во время блокировки показывается убывающий счётчик оставшихся попыток | `src/app/api/auth/login/route.ts`, `rate-limit.ts` |

**Поведение в защиту приватности**: при отправке кода подтверждения / «забыл пароль», если почта уже
зарегистрирована или не существует, интерфейс в обоих случаях возвращает одинаковый текст успеха и не
раскрывает, зарегистрирована ли почта.

## Эквивалентность режима делегирования agent'у и веб-регистрации

Скрипт скилла вызывает **тот же набор публичных API** (`/api/auth/register`, `send-code`, `login`,
`/api/auth/me`), что и отправка формы на странице регистрации, и проходит ровно те же проверки, лимиты и
пути ошибок — все правила этого файла одинаково действуют для обоих режимов. Последовательность скрипта и
контракт команд — в `references/agent-flow.md`.

## Поток статусов после успешной регистрации

> **Бесплатный тестовый период (с 2026-10-18; фактическое поведение платформы имеет приоритет)**: новый зарегистрированный аккаунт может **использовать все функции напрямую**
> (лента, карта, цифровые люди, чекины и т.д.) без всякой оплаты; аккаунты без подписки больше не отсекаются от контентных страниц. Описанное здесь
> «pending-перехватывание» — это регулярное состояние после окончания тестового периода — когда оно наступит, приоритет у фактического поведения онлайна.

1. Пользователь хранится с `accountStatus: 'pending'` и **3 стартовыми бейджами** (маршрут register).
2. Сервер также садит две HttpOnly-cookie: JWT (можно заходить на страницы напрямую) и pendingUserToken (удостоверение личности для потока подписки).
3. В регулярном состоянии (тестовый период закончился / бесплатного периода нет) страница регистрации детектит `pending_payment` → редирект на `/subscription`
   (с сохранением параметра возврата `next`); в режиме agent-посредничества `me?token=…&redirect=/subscription` даёт тот же эффект.
   **В бесплатном тестовом периоде этот шаг не срабатывает** — после регистрации сразу иди на главную и начинай пользоваться.
4. Оплата завершена → `accountStatus` становится `active` (**Alipay активирует автоматически на стороне сервера через notify**;
   PayPal активирует через Webhook; QR-код WeChat подтверждается вручную; Huawei IAP идёт через `activate-huawei`).
   Подробности — в `payment-and-activation.md`.

В регулярном состоянии неактивные (pending) пользователи при вызове ключевых API (лента, карта, чат с цифровыми людьми, чекины и т.д.) получают 403;
исключение — расшаренные ссылки на посты (остаются публично доступными). В бесплатном тестовом периоде это перехватывание приостановлено и всё открыто.
## Таблица разбора частых ошибок

| Симптом | Причина | Что делать |
|---|---|---|
| 「用户名已存在」 (имя пользователя уже существует) | Имя занято (без учёта регистра) | Взять другое имя пользователя |
| 「邮箱已被使用」 (почта уже занята) | Почта уже зарегистрирована | Сменить почту; или пойти через вход +「忘记密码」(забыл пароль) и вернуть старый аккаунт |
| 「邮箱验证码错误或已过期」 (код подтверждения неверен или истёк) | Код введён неверно / прошло больше 10 минут / отказ после 5 неудачных попыток | Нажать 「重新发送」(отправить заново) и использовать код из **самого свежего** письма |
| Код не приходит | Лимит 60 секунд; или упал в спам / рассылки | Дождаться окончания отсчёта и отправить снова; перерыть папку спама |
| 「手机号已被使用」 (телефон уже занят) | Номер уже привязан к другому аккаунту | Убрать телефон (поле опциональное) или сменить номер |
| 「注册请求过于频繁」 (запросы на регистрацию слишком частые) / 429 | Достигнут потолок 3 регистрации/минуту/IP | Подождать несколько минут и повторить |
| 409 「用户名或邮箱已被注册」 (имя пользователя или почта уже зарегистрированы) | Мгновенное столкновение с чужими данными в момент отправки (страховка от гонок) | Сменить имя пользователя или почту и повторить |
| 「图片大小不能超过5MB」 (размер картинки не больше 5MB) / 「不支持 SVG」 (SVG не поддерживается) | Аватар не по нормам | Сменить картинку или пропустить аватар |
| Пользователь открывает ссылку входа, но попадает на страницу подписки (вместо главной) | Бесплатный тестовый период закончился, пейволл платформы вернулся | Следуй потоку оформления подписки из шага 7 в SKILL.md; после подписки выполни `refresh-login`, затем отправь ссылку на главную |
| Регистрация прошла, но при входе 403 «请完成订阅以激活账户» | Аккаунт ещё pending, и платформа не в бесплатном тестовом периоде (ожидаемое состояние до оплаты) | В бесплатном тестовом периоде не возникнет; если возникло — тестовый период закончился, сначала оформи подписку; если после оплаты всё ещё 403 — использован старый JWT, в режиме скрипта сначала выполни `refresh-login` для обмена на свежее состояние входа |
| Вход 423 「账户已锁定」 (аккаунт заблокирован) | 5 ошибок пароля подряд | Подождать 30 минут |
| Вход 401 「还剩 N 次尝试机会」 (осталось N попыток) | Неверный пароль, близко к блокировке | Хорошо подумать перед следующей попыткой или сразу пойти через 「忘记密码」(забыл пароль) |
| 「该账号未设置密码，请使用其他方式登录」 (у этого аккаунта не задан пароль, войдите другим способом) | Сторонний аккаунт (Google/Watcha/Huawei) | Войти через исходную стороннюю кнопку |
| 「该账号已注销」 (этот аккаунт удалён) | Аккаунт деактивирован | Нужно зарегистрироваться заново |

## Полезно знать про вход (пригодится при разборе)

Вход принимает тройной ввод **имя пользователя / почта / телефон** (любое из трёх годится как
идентификатор). Забыл пароль: страница входа → 「忘记密码」(забыл пароль) → ввести регистрационную почту,
получить 6-значный код → сбросить.

# Поток делегированного выполнения agent'ом и контракт скрипта — powpow-register

Детали исполнения каждого шага SKILL.md. Все команды выглядят как `node scripts/powpow-register.mjs <подкоманда> [параметры]`,
скрипт **без зависимостей**, требует **Node ≥ 18**; все запросы уходят только на `https://global.powpow.online`.

## Защитный дизайн (почему сделано именно так)

| Решение | Причина |
|---|---|
| Пароль передаётся только через переменную окружения `POWPOW_REGISTER_PASSWORD` | Аргументы командной строки процесса видны другим процессам той же машины (поверхность утечки argv); переменную окружения скрипт читает и сразу использует |
| Пароль **никогда не пишется в файл состояния**, никогда не появляется в логах | Файл состояния может остаться на диске; в режиме генерации показывается один раз, чтобы пользователь сохранил |
| Файл состояния лежит в системном временном каталоге (`os.tmpdir()/powpow-register-state.json`, 0600) | Содержит только пять полей email / username / nickname / token / outTradeNo; `cleanup` стирает всё одной командой |
| JWT, полученный agent'ом, обменивается на cookie браузера через официальный эндпоинт `me?token=` | Это официальный мост, придуманный платформой для WebView HarmonyOS; проверка смотрит только подпись + срок действия, не привязываясь к отпечатку устройства, так что браузер пользователя подходит |
| Оплата делает только create-order / query / открытие кассы | Акт оплаты и платёжные инструменты всегда остаются между пользователем и официальной кассой Alipay; agent их не касается |

## Справочник команд

| Команда | Ключевые параметры | Что делает / когда |
|---|---|---|
| `status` | —— | Посмотреть прогресс потока (читает файл состояния); после обрыва диалога запускать первым |
| `gen-password` | —— | Генерирует стойкий пароль из 24 символов (заглавные + строчные + цифры); stdout показывает **только один раз** |
| `prepare-suggest` | `--username --nickname --email` | Заносит подтверждённые данные в файл состояния (после этого register не нужно передавать их повторно) |
| `send-code` | `--email` | Запускает отправку платформой 6-значного кода подтверждения (действует 10 минут, кулдаун 60с) |
| `register` | `--code` (обязательно); `--username --nickname --avatar --phone` (опционально, если уже в файле состояния — можно не передавать) | Создаёт pending-аккаунт; пароль идёт через переменную окружения `POWPOW_REGISTER_PASSWORD`; при успехе JWT автоматически сохраняется в файл состояния |
| `login-link` | `--target pending` или `--target home` | Генерирует ссылку входа в один клик (дизайн двойной ссылки, см. ниже) |
| `create-order` | `--package monthly\|quarterly\|yearly` | Создаёт заказ Alipay; возвращает путь к файлу страницы оплаты + outTradeNo (автоматически заносится в файл состояния) |
| `query` | —— | Проверяет статус заказа `paid / pending / closed / unknown` (outTradeNo берётся из файла состояния), опрос каждые 10–15с |
| `refresh-login` | Пароль через переменную окружения | Повторный вход и обмен на **новый JWT** (декларация подписки меняется с NONE на ACTIVE); обязательно после зачисления оплаты |
| `whoami` | —— | По token из файла состояния проверяет статус аккаунта и подписки (убедиться, что активация сработала) |
| `cleanup` | —— | Удаляет файл состояния (обязательно в конце) |

**Передача переменной окружения** (пароль никогда не идёт в командную строку):

```bash
# bash / zsh / WSL
POWPOW_REGISTER_PASSWORD='<пароль>' node scripts/powpow-register.mjs register --code 123456
# PowerShell
$env:POWPOW_REGISTER_PASSWORD = '<пароль>'; node scripts/powpow-register.mjs register --code 123456
# cmd
set POWPOW_REGISTER_PASSWORD=<пароль> && node scripts/powpow-register.mjs register --code 123456
```

## Механизм двойной ссылки (центральный дизайн)

Состояние входа на платформе — HttpOnly cookie, agent не может посадить cookie в браузер напрямую; мостом служит официальный
эндпоинт `/api/auth/me?token=<JWT>&redirect=<внутренний путь сайта>`: проверка подписи → для pending-пользователя
автоматически создаётся session → `Set-Cookie: powpow_token` (HttpOnly / SameSite=Lax /
7 дней) → валидация redirect (только путь с одиночным слэшем в начале, запрещены `//` и
обратный слэш, после разбора должен быть тот же источник) → 307 временный редирект на целевую страницу.

- **Ссылка 1 (выдавать сразу после успешной регистрации)**: `--target pending` → попадание в `/subscription`.
  Браузер пользователя входит в состояние «полувхода»: страница подписки и страница возврата Alipay
  видны и работоспособны; страницы контента по-прежнему отбрасываются платной стеной
  обратно на страницу подписки (тройная защита: проверка claims JWT на шлюзе → перепроверка в БД →
  проверка в ключевых API; это нормальное поведение).
- **Ссылка 2 (выдавать после подтверждения paid)**: сначала `refresh-login` для обмена на новый JWT
  (оплата обновляет только БД и не меняет claims уже выданного JWT; без обмена это выглядит как «оплатил,
  а подписки нет»), затем `--target home` → попадание на главную,
  с полным статусом участника.

## Полная последовательность (нормальный путь)

```
1.  status                          # самопроверка окружения
2.  (шаг 2 — подтверждение данных в диалоге, пароль на выбор из двух; режим генерации: gen-password → пользователь сразу сохраняет)
3.  prepare-suggest --username U --nickname N --email E
4.  send-code --email E             # → пользователь идёт в почту за кодом (единственный выход из диалога, момент ①)
5.  POWPOW_REGISTER_PASSWORD=*** register --code 123456 [--avatar pic.jpg]
6.  login-link --target pending     # → ссылка 1 отправлена пользователю
7.  (пользователь выбирает тариф) create-order --package monthly
8.  start <файл страницы оплаты>   # Windows; в macOS использовать open, в Linux xdg-open
     # → пользователь платит в кассе Alipay (выход из диалога, момент ②)
9.  query (каждые 10–15с) до paid
10. refresh-login                   # обмен на новый JWT с декларацией ACTIVE
11. login-link --target home        # → ссылка 2 отправлена пользователю
12. whoami                          # подтвердить subscriptionStatus: ACTIVE (опционально)
13. cleanup                         # вычистить файл состояния
```

## Соответствие команд → API платформы

| Команда скрипта | Интерфейс платформы |
|---|---|
| `send-code` | `POST /api/auth/register/send-code` |
| `register` | `POST /api/auth/register` (multipart, прямая загрузка аватара) |
| `login-link` | `GET /api/auth/me?token=…&redirect=…` (сама ссылка, срабатывает при клике в браузере) |
| `create-order` | `POST /api/payment/alipay/create-order` (Bearer) |
| `query` | `GET /api/payment/alipay/query?outTradeNo=…` (Bearer) |
| `refresh-login` | `POST /api/auth/login` (`{step:1, username, password}`) |
| `whoami` | `GET /api/auth/me?token=…` |

Источник правил: поля регистрации и лимиты частоты — `registration-flow.md`; тарифы и цепочка активации —
`payment-and-activation.md` (оба с указанием файлов исходного кода платформы).

## Обработка ошибок на уровне скрипта

| Симптом | Обработка |
|---|---|
| `Версия Node слишком старая` | Откат в режим чистого сопровождения, не упорствовать |
| Сетевая ошибка / таймаут | Повторить один раз; если снова не выходит — пользователь проверяет сеть и продолжаем (файл состояния на месте; восстановление с начала через `status`) |
| register вернул бизнес-ошибку (имя пользователя занято и т.п.) | Разобрать по таблице шага 5 SKILL.md, **код подтверждения повторно отправлять не нужно** (ещё действует 10 минут) |
| register вернул 「邮箱验证码错误或已过期」 (код подтверждения неверен или истёк) | Время вышло → заново `send-code` |
| Пользователь закрыл страницу оплаты после `create-order` | Просто заново `create-order` (старый заказ сам закроется через 2ч) |
| `query` всё время pending | Возможно, пользователь не заплатил; спросите. Если точно заплатил → идти по таблице разбора payment-and-activation.md |
| `refresh-login` даёт 403 `pending_payment` | Оплата ещё не зачислилась; вернуться к шагу 9 и продолжать опрос |
| Файл состояния потерян (случайно удалён / смена машины) | `whoami`/`refresh-login` не работают; пусть пользователь прямо обновит страницу подписки в браузере, где открывал ссылку 1, чтобы проверить статус, или войдёт заново (веб-режим) |

## Режим отката (чистое сопровождение)

При любом из этих условий немедленно откатывайтесь на чистое сопровождение в стиле v1 и прекратите мучить скрипт:

- Нет Node ≥ 18, или скрипт дважды подряд падает на одном и том же;
- Пользователь прямо говорит «я сам сделаю на сайте»;
- Политики компании / устройства запрещают скриптам ходить в сеть.

После отката: дайте страницу регистрации https://global.powpow.online/register и страницу подписки
https://global.powpow.online/subscription, сопровождайте разбор ошибок по правилам
`registration-flow.md`, тон не меняется, каждый раунд по-прежнему заканчивается блоком «следующий шаг».

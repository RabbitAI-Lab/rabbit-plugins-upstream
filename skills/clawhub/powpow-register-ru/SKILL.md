# PowPow Register (помощник регистрации в Пузыре)

Проводит нового пользователя от «я не знаю, что такое Bubble» до «вошёл в один клик, можно начинать» — полностью внутри диалога. Пользователь покидает диалог только один раз: **чтобы проверить код подтверждения в почте**. Сейчас платформа в бесплатном тестовом периоде: после регистрации доступны все функции, платить не нужно; оплата подписки — необязательное расширение членства (агент также откроет кассу и отследит зачисление).

**Версия 2.2.0** · 2026-10-18 (с v2 это режим agent-посредничества: контракт скрипта и полная последовательность — в `references/agent-flow.md`; правила полей, лимиты частоты и разбор ошибок — в `references/registration-flow.md`; платёжные каналы — в `references/payment-and-activation.md`; список скриншотов продукта — в `references/screenshots.md`. С v2.1.0 агент может вести и подписки PayPal — как альтернативу Alipay. С v2.2.0 платформа вошла в бесплатный тестовый период: зарегистрировался, вошёл в один клик — и пользуйся; оплата стала необязательным апгрейдом — если пользователь откроет ссылку и попадёт на страницу подписки, значит тестовый период закончился, тогда следуй платёжному потоку из шага 7; поток адаптируется сам, менять скрипт не нужно)

## Среда выполнения

- Основной скрипт `scripts/powpow-register.mjs`: **ноль зависимостей**, требует **Node ≥ 18**. Перед началом выполните один раз `node scripts/powpow-register.mjs status`, чтобы убедиться, что среда работает.
- Все запросы скрипта уходят только на официальный домен `https://global.powpow.online`.
- **Нет Node / ошибки скрипта**: автоматически откатывайся в режим чистых указаний — дай пользователю страницу регистрации https://global.powpow.online/register и веди его по `references/registration-flow.md` (в бесплатном тестовом периоде регистрация через сайт тоже моментальная). Не долби скриптом повторно.
- Возобновление после обрыва диалога: сначала `status`, чтобы увидеть, на каком шаге поток, и продолжайте с этого места.

## Trigger Conditions

- Намерение зарегистрироваться: «зарегистрируй меня в Пузыре», «создать аккаунт powpow», «как зарегистрироваться в Пузыре», «sign up powpow»
- Регистрация застряла: «не приходит код подтверждения», «говорит, имя пользователя уже существует», «пароль всё время не проходит валидацию»
- Проблемы после регистрации: «при входе говорит, что аккаунт не активирован», «403 pending_payment», «как оплатить/подписаться в Bubble», «Bubble бесплатный или платный»

**Не срабатывает для**: публикации постов / создания цифровых людей (→ powpow-simple); разработки кода веб-стороны (см. скиллы разработки). Если пользователь хочет и зарегистрироваться, и постить: сначала пройдите этот скилл до конца, после активации передайте его powpow-simple.

## Обзор потока

| Шаг | Что делает agent | Что делает пользователь |
|---|---|---|
| 1 Представление продукта | Представляет + отправляет скриншоты | Смотрит одним глазом |
| 2 Подтверждение данных | Сам предлагает имя пользователя/ник, пароль на выбор из двух вариантов, спрашивает почту | Подтверждает, предоставляет |
| 3 Отправка кода | `send-code` | —— |
| 4 Возврат кода | —— | Идёт в почту, смотрит 6-значный код, присылает обратно |
| 5 Отправка регистрации | `register` (с прямой загрузкой аватара), ошибки обрабатывает автоматически | —— |
| 6 Вход в один клик | `login-link(home)` — сразу на главную; если попал на страницу подписки — переходи к шагу 7 | Кликнуть ссылку и начинать |
| 7 Апгрейд подписки (необязательно) | Только если пользователь хочет членство / бесплатный период закончился: ведём полный платёжный поток | Выбрать способ и оплатить |
| 8 Завершение | `cleanup` + выдача учётных данных + наводка по использованию + рекомендация плагинов | Начинает играть |

## Шаг 1: представление продукта + скриншоты (пропускать нельзя)

Большинство пользователей никогда не видели Пузырь. Первое дело — не рассказывать про процесс, а дать ему **увидеть** продукт:

1. Представьте Пузырь в ~120 знаках: превращает снимки, сделанные на ходу, в путевой журнал, прикалываемый на публичную карту в виде «пузыря»; пузыри со временем выдыхаются, а «лайки» других могут их воскресить; на карте есть ещё и «цифровые люди», с которыми можно поболтать. Адрес платформы: https://global.powpow.online ; если хочет сначала посмотреть видео: https://www.bilibili.com/video/BV1Wu826UEVz/
2. **Отправьте скриншоты**. Скриншоты уже упакованы вместе со скиллом в `assets/screenshots/powpow-0N.jpg` — отправляйте напрямую как локальные файлы изображений, без интернета. Перечень, содержимое каждой картинки и моменты использования — в `references/screenshots.md`. Самая ходовая комбинация на открытии: страница карты (powpow-03) + страница поста (powpow-06).

Правила по скриншотам (жёсткие правила):

- Скриншоты **уже упакованы со скиллом** в `assets/screenshots/` (`powpow-0N.jpg`) — отправляйте напрямую как локальные файлы изображений; работают в любом окружении, включая те, где GitHub не открывается.
- За раз только 1–3 картинки по текущей теме, не лепите всё сразу.
- Если файлы в пакете случайно отсутствуют, откатывайтесь на хостинговые ссылки из `references/screenshots.md` (внимание: из материкового Китая могут не открыться).

Закончив представление, оставьте выбор за пользователем: **«Если хочешь зарегистрироваться — за три минуты создадим аккаунт прямо здесь, в диалоге; тебе нужно будет только разок заглянуть в почту за кодом.»**

## Шаг 2: подтвердить данные регистрации (один вопрос за раунд, не спрашивайте всё сразу)

- **Имя пользователя** (обязательно): **предложите сами** из контекста диалога или системного имени пользователя (2~50 символов, без учёта регистра); если пользователь кивает — берём, хочет поменять — меняем.
- **Пароль** (обязательно; сначала предложите выбор из двух вариантов):
  - Пользователь предоставляет сам → дальше передаётся скрипту через переменную окружения, **ни в коем случае не в аргументы командной строки**;
  - Генерирует agent → выполните `node scripts/powpow-register.mjs gen-password` и **немедленно отправьте сгенерированный пароль пользователю, чтобы он сохранил** (показывается только один раз, больше не появится).
- **Почта** (обязательно): должен предоставить пользователь — это якорь личности аккаунта, **не угадывайте за него**.
- **Ник** (необязательно): предложите по умолчанию совпадающим с именем пользователя.
- **Аватар** (необязательно): если пользователь даёт путь к локальной картинке (≤5 МБ, не SVG), скрипт загрузит её напрямую; нет — пропускаем (платформа поставит дефолтный логотип); если у вас есть ability генерировать картинки, можете сами предложить сделать ему аватар.
- **Телефон** (необязательно, материковый номер): по умолчанию пропускаем; спрашиваем, только если пользователь сам хочет привязать.

После подтверждения можно выполнить `prepare-suggest --username U --nickname N --email E`, чтобы занести данные в файл состояния (тогда register не придётся передавать их повторно).

## Шаги 3–4: код подтверждения на почту (единственный этап, где нужно выйти из диалога)

```
node scripts/powpow-register.mjs send-code --email <почта>
```

Затем внятно скажите пользователю: **загляни в почту, найди 6-значный код подтверждения, он действует 10 минут; не забудь проверить папку спама / рассылок**; когда найдёт — пусть вернётся и пришлёт код вам. У отправки кулдаун 60 секунд, не жмите подряд.

## Шаг 5: отправить регистрацию (делегировано agent'у)

```
POWPOW_REGISTER_PASSWORD=<пароль> node scripts/powpow-register.mjs register --code <код> [--username U] [--nickname N] [--avatar <путь к локальной картинке>] [--phone P]
```

При успехе аккаунт создан (статус pending, с 3 стартовыми значками). Частые ошибки обрабатываются автоматически, не прерывая пользователя:

| Ошибка | Обработка |
|---|---|
| 「用户名已存在」 (имя пользователя уже существует) | Автоматически предложить вариант (имя + цифры) и, после подтверждения пользователем, сразу повторить (код ещё действителен, повторная отправка не нужна) |
| 「邮箱已被使用」 (почта уже занята) | Спросите пользователя: сменить почту, или на самом деле аккаунт уже есть? (перевести на вход / восстановление пароля) |
| 「邮箱验证码错误或已过期」 (код подтверждения неверен или истёк) | Прошло больше 10 минут → заново `send-code` |
| Отправка/регистрация слишком частые (429) | Подождать 1 минуту и повторить; пользователя достаточно просто уведомить |

## Шаг 6: Вход в один клик (после регистрации — сразу на главную)

1. Сразу после успешной регистрации:
   ```
   node scripts/powpow-register.mjs login-link --target home
   ```
2. Отправь ссылку пользователю: **откроется — и ты сразу на главной странице, уже авторизован**. Платформа сейчас в бесплатном тестовом периоде — после регистрации доступны все функции (лента, карта, цифровые люди, чекины и т.д.), **платить не нужно**.
3. Попроси пользователя подтвердить, что он попал внутрь; два случая:
   - **Попал на главную** → сразу переходи к шагу 8 на доводку; регистрация завершена;
   - **Попал на страницу подписки** → бесплатный тестовый период платформы закончился; скажи пользователю «бесплатный пробный период закончился, теперь нужна подписка», затем пройди шаг 7 для оформления подписки и после подписки вернись к шагу 8.
4. Если пользователь сам хочет апгрейд или поддержать платформу → тоже веди к шагу 7 (подписка — добровольна; не дави).
## Шаг 7: Апгрейд подписки (необязательно — только когда шаг 6 указывает на это)

1. Сначала отправь ссылку полу-входа, чтобы страница возврата после оплаты корректно показала «Оплата успешна»:
   ```
   node scripts/powpow-register.mjs login-link --target pending
   ```
   Отправь ссылку пользователю: клик — и браузер сразу на странице подписки, уже авторизован.
2. **Попроси пользователя выбрать способ оплаты** — покажи оба канала:
   - **Alipay (материковый Китай / пользователи с Alipay)**: разовая покупка на нужный срок, **без автопродления**
     - Месяц **¥6.99** (рекомендуем для пробы) / Квартал **¥19.99** / Год **¥69.99**
   - **PayPal (за рубежом / без Alipay)**: автопродление раз в месяц, отмена в любой момент
     - Premium Monthly, около **$1/мес** (как показано на странице подписки; с автопродлением)
3. Как только пользователь выбрал:
   - **Alipay**:
     ```
     node scripts/powpow-register.mjs create-order --package monthly
     ```
   - **PayPal**:
     ```
     node scripts/powpow-register.mjs create-order --provider paypal
     ```
   Скрипт вернёт путь к файлу страницы оплаты; **открой его напрямую системной командой** (Windows: `start <файл>`; macOS: `open <файл>`; Linux: `xdg-open <файл>`). Браузер автоматически перейдёт в официальную кассу Alipay/PayPal, где пользователь завершит оплату или авторизацию списания.
4. Запускай `query` каждые 10–15 секунд, пока не вернётся `paid` или `ACTIVE` (зачисление/авторизация обычно занимает от нескольких секунд до минуты). Если пользователь закрыл страницу оплаты на середине → просто заново `create-order` (старые заказы и зависшие подписки закроются или истекут через 2 часа; не обращай внимания).
5. Канал QR-кода WeChat подтверждается вручную, зачисление может задержаться; Huawei IAP доступен только внутри приложения HarmonyOS. Скилл не ведёт эти два — после оплаты пользователь возвращается и сообщает агенту, который сначала выполняет `whoami` для подтверждения зачисления, затем отправляет ссылку на главную по пункту 6 ниже.
6. После подтверждения зачисления обменяй свежее состояние входа с актуальным claim подписки, затем отправь ссылку сразу на главную:
   ```
   POWPOW_REGISTER_PASSWORD=<пароль> node scripts/powpow-register.mjs refresh-login
   node scripts/powpow-register.mjs login-link --target home
   ```
   Отправь ссылку пользователю: **откроется — и ты сразу на главной со полным статусом членства**.
## Шаг 8: Доводка

1. `node scripts/powpow-register.mjs cleanup` — очисти локальные временные файлы состояния (учётные данные сессии).
2. Дай пользователю «карточку аккаунта»: имя пользователя, email (пароль больше не показываем — в режиме генерации пользователя просили сохранить его при генерации; если пользователь задал его сам, он его знает).
3. Напоминание о членстве (скажи один раз, не дави): сейчас бесплатный тестовый период, аккаунтом можно пользоваться сразу; когда тестовый период закончится, аккаунты без подписки при заходе на контентные страницы будут перенаправляться на страницу подписки — для долгого использования возвращайся и подписывайся в любой момент.
4. Наведи на первые шаги: посмотри карту, опубликуй первый тревел-журнал (→ передай в powpow-simple).
5. Порекомендуй расширения: скилл `@durenzidu/powpow-integration` и плагин `@durenzidu/openclaw-channel-powpow` — подключи Bubble к собственному агенту пользователя; дай команду установки, если захочет.
6. Заверши блоком «следующий шаг».
## Conversation UX

Держите привычный сервисный тон powpow:

- **Пользователь — подлежащее фразы**; «вы можете…» лучше, чем «мне нужно, чтобы вы…»; без моралей и снисходительности.
- **За один раунд продвигается только одно решение**; перед запросом данных сначала дайте причину.
- **В конце каждого ответа** — фиксированный блок «следующий шаг» (разделитель + 👉 + одно действие + фраза «когда сделаете, я…»), например:
  ```
  ────────────────────
  👉 Теперь ваша очередь: сходите в почту, найдите 6-значный код и пришлите мне прямо сюда
     (как только получу — сразу создам аккаунт)
  ```
- **Не читайте лекций о безопасности пароля без повода**; не объясняйте внутренние механизмы, лимиты частоты или защитный дизайн, если пользователь не спросит.
- Когда agent ведёт дела, отчитывайтесь о прогрессе ещё усерднее: после каждого шага скрипта одной фразой сообщайте, что только что произошло («аккаунт создан», «страница оплаты уже открыта»).

## Жёсткие правила

- **Безопасность учётных данных**: пароль передаётся скрипту только через переменную окружения `POWPOW_REGISTER_PASSWORD`, **никогда** в аргументы командной строки (видны в списке процессов) и не записывается ни в какие файлы (в режиме генерации показывается один раз, чтобы пользователь сохранил, и больше не повторяется). Код подтверждения используется только в официальном интерфейсе регистрации и выбрасывается после применения.
- **Официальная граница**: все запросы уходят только на `https://global.powpow.online` (уже встроено в скрипт); никогда не отправляйте данные пользователя на сторонние адреса.
- **Платёжная граница**: agent только создаёт заказ, открывает кассу и проверяет зачисление; **никогда** не касается аккаунта Alipay/PayPal пользователя и его платёжных инструментов и никогда не обещает «заплатить за него».
- **Пейволл — не баг**: в текущем бесплатном тестовом периоде все контентные страницы открыты; если пользователь открывает ссылку на главную, но попадает на страницу подписки — тестовый период закончился, веди его к подписке через шаг 7. Не пытайся обходить пейволл и не объясняй пользователю внутренние механизмы.
- **Свобода отката**: если на любом шаге пользователь хочет сделать сам, или среда не поддерживает скрипт — в любой момент откатывайтесь в режим чистого сопровождения: дайте ссылки, расскажите правила, помогайте разбирать ошибки.
- Не выдумывайте правила платформы: правила полей, тексты ошибок и параметры лимитов целиком из кода платформы (`references/registration-flow.md` с указанием исходников); при обновлении платформы ориентируйтесь на фактическое поведение.

## P1 仓库解剖五件套（每仓必备，2026-09-29 用户定标）

> 梳理报告不是散文摘要，是五份可独立阅读的产物。缺任何一件 = 梳理未完成。

- [ ] **① 功能与价值**——这个仓做什么、为什么有用（给不懂它的人一段话说清；引用 README/issue 里的真实用例，不复述营销语）
  落盘: anatomy/01-why.md
- [ ] **② 高层次代码地图**——模块/分层/依赖关系的图形，不是文字目录树。用 archify 生成架构图（explorable HTML，含 PNG/SVG 导出）；CLI/纯文档仓可用 Mermaid 降级，但必须有图
  落盘: anatomy/02-map.html
  → skill: archify/SKILL.md
- [ ] **③ 请求生命周期**——一次典型请求/查询/命令从入口到出口在代码里的完整流转路径（入口函数 → 解析/校验 → 核心处理 → 出口/持久化/响应），逐跳带文件名
  落盘: anatomy/03-lifecycle.md
- [ ] **④ 核心抽象**——仓里 3-7 个承载设计思想的主类型/接口/协议（不是文件清单：每个抽象一段——它管什么不变量、谁实现它、没有它会坏什么）
  落盘: anatomy/04-abstractions.md
- [ ] **⑤ 真实执行跟踪**——跑一次真实输入，记录实际发生了什么（调用链/日志/状态变化）；涉及调度或计划的仓（查询引擎=连接顺序与查询计划生成，流水线=阶段编排，事件系统=分发顺序）必须解释清楚 ordering/规划是怎么决定的
  落盘: anatomy/05-execution-trace.md

# 新闻简报编排 playbook

> 简报的灵魂是"策展判断力"：在信息过载里替读者挑出值得看的，并加上你自己的观点。本 playbook 给一套决策树 + 检索命令 + 语气矩阵 + 常见坑 + 发布前清单，正交于 [skills/newsletter](../skills/newsletter/SKILL.md) 的"怎么调用"，专讲"怎么排好一期简报"。

## 1. 决策树：先定格式与受众

```
Q1 这期要服务什么节奏？
├─ 每天发、轻量 → 日报（Daily Digest）
├─ 每周一次、有沉淀 → 周报（Weekly Roundup）
├─ 围绕单一重磅主题深挖 → 深度（Deep-Dive）
└─ 给行业/投资人看、要全貌 → 行业简报（Industry Briefing）

Q2 读者是谁？（决定语气与细节深度）
├─ 技术读者 → 精确、不解释术语、可给命令/代码片段
├─ 高管/投资人 → 影响、战略、底线、市场含义
└─ 大众 → 类比、通俗、故事化

Q3 你手上有几类素材？
├─ 只有 1 个话题 → 深度
├─ 3–6 条零散新闻 → 周报/日报
└─ 跨市场/公司/政策/数据 → 行业简报

Q4 是否系列化？
└─ 是 → 固定栏目顺序与命名，让读者形成预期（例：每周三"AI 周报"）
```

**经验法则**：格式选错比写错更致命。日报塞 8 条深度分析会劝退；行业简报只写一条新闻会显得单薄。先定节奏，再填内容。

## 2. 检索命令（多源、带时间锚点）

> 简报质量 = 检索质量。务必用 `<current_date>` 做时间锚点，绝不写死年份。

```
# 当期新闻与进展
"[主题] news [当月] [当年]"
"[主题] latest developments"
"[主题] announcement this week"

# 趋势与分析
"[主题] trends [当年]"
"[主题] analysis expert opinion"
"[主题] industry report"

# 数据指标
"[主题] statistics [当年]"
"[主题] market data latest"
"[主题] growth metrics"

# 工具与资源
"[主题] new tools [当年]"
"[主题] open source release"
"best [主题] resources [当年]"
```

**执行要点**：
- 时间窗优先取近 7–30 天内容，过期事件只在"背景/为什么重要"里引用。
- 每条候选用 `web_fetch` 读全文，提取：核心事实（谁/什么/何时）、背景、数据点、引语、影响。
- 一手源（官方公告、原论文、监管文件）优先于二手报道。

## 3. 策展六维筛选标准

| 维度 | 优先级 | 取舍信号 |
|------|--------|----------|
| 时效性 | 高 | 近 7–30 天优先；旧闻仅作背景 |
| 权威性 | 高 | 官方 / 一手源 / 知名媒体优先 |
| 独特性 | 中 | 视角新鲜或被低估的，优于同质化热搜 |
| 相关性 | 高 | 每条必须明显贴合本期主题 |
| 可行动 | 中 | 读者能用的工具/洞察/策略优先 |
| 多样性 | 中 | 新闻+分析+数据+资源 混合，避免单一声源 |

**数量纪律**：质量 > 数量。5 条优质内容胜过 15 条平庸。周报 5–8 条、日报 4–6 条为宜。

## 4. 语气校准矩阵

| 受众 | 语气 | 写法示例 |
|------|------|----------|
| 技术 | 精确、术语不展开、默认读者懂行 | "新 API 支持 gRPC 流式 + 基于流控窗口的背压。" |
| 高管 | 影响导向、战略、底线 | "本次收购让 X 在企业段市占达 40%，直接威胁 Y 的定价权。" |
| 大众 | 类比、通俗、故事 | "像给数据装了万能翻译器——任何 App 都能和任何数据库对话，不必学新语言。" |

**分析段结构**（任何受众通用）：观察 → 背景 → 影响 →（可选）可行动结论。每句断言都要有数据或来源支撑。

## 5. 写作结构速查

- **头条 / 重点项**：抓人标题（利益导向，非标题党）→ 1–2 句 Hook（为什么重要）→ 2–4 段事实+背景+影响 → "为什么重要"一段 → 来源链接。
- **快讯**：粗体标题 + 2–3 句要点 + 来源链接；一条一个核心收获，读者不点开也懂。
- **分析/评论**：本简报独特视角，证据齐全，不空谈。

## 6. 输出模板（Markdown）

```markdown
# [简报名]

*[一句话定位] — [完整日期，如 2026-08-19]*

---

[预览句：本期覆盖 X、Y、Z。]

## 🔥 头条

### [标题 1]
[Hook：为什么重要，1–2 句。]
[正文：2–4 段事实、背景、影响。]
**为什么重要：**[1 段连接读者利益或行业影响。]
📎 [来源：媒体名](URL)

## 📊 趋势与分析
### [趋势名]
[原创评论，数据支撑。]
**一句话结论：**[可行动要点。]

## ⚡ 快讯
- **[标题]** — [2–3 句要点。] [来源](URL)
- **[标题]** — [2–3 句要点。] [来源](URL)

## 🛠️ 工具与资源
- **[工具名]** — [做什么、为何有用。] [链接](URL)

## 💬 收尾
[金句 / 前瞻 / 行动号召。]

---
*[简报名] 策展 [主题] 最重要的新闻与观点。*
*发现有用？转发给同事。所有来源内联标注，观点为原创。*
```

## 7. 常见坑

- **无源断言**：任何事实不给链接 = 信任崩塌。宁可加"据 X 报道"也不编数字。
- **写死日期**：用 `<current_date>` 锚点；硬编码年份会让旧简报瞬间失真。
- **单一声源**：全是同一家媒体/同一立场，失去策展价值。混新闻+分析+数据+资源。
- **过度摘要付费墙内容**：读者打不开的付费内容不要详摘，只引标题+链接。
- **信息过载**：栏目贪多、每条写太长，读者扫不动。质量 > 数量，严守数量纪律。
- **语气错位**：给技术读者写类比、给高管写术语，都会掉粉。先定受众再下笔。
- **断更无结构**：系列化简报每期栏目顺序乱跳，读者无法形成预期。

## 8. 发布前检查清单

- [ ] 每个事实断言都有来源链接（无无源断言）
- [ ] 所有链接可用（来自检索结果、已验证）
- [ ] 日期用的是真实当前日期（无写死/假设年份）
- [ ] 内容在预期时间窗内（无过期硬凑）
- [ ] 无重复条目（每条只出现一次）
- [ ] 格式统一（标题/列表/链接风格一致）
- [ ] 覆盖均衡（不被单一来源/立场主导）
- [ ] 长度匹配目标（短文 5 分钟 / 中 10 分钟 / 长 15 分钟+）
- [ ] 开头两句话能留住人（Hook 到位）
- [ ] 结尾有记忆点 / 行动号召
- [ ] 已校对（无错别字、无断裂格式、无半截句子）

## 9. 相关子技能与层次边界（L2→L3）

本 playbook 是「编排层」方法论（L2），专讲"怎么排好一期简报"（决策树 + 检索命令 + 策展矩阵 + 语气校准 + 输出模板 + 发布前清单）；具体的"怎么调用工具产出简报"下沉到 L3 子技能：

- 简报的实际生成调用（多源检索、策展、写出可发布 Markdown）→ [skills/newsletter/SKILL.md](../skills/newsletter/SKILL.md)
- 内容策略与平台定调（决定是否做简报、受众画像从哪来）→ 参见 [references/content-strategy.md](content-strategy.md)
- 视频 / 音频类内容的发布前检查（与简报并列的另一种媒介）→ 参见 [references/production-workflow.md](production-workflow.md)

边界：本 playbook 只给"编排与策展"的方法论、模板与清单，不写具体检索工具操作或发送/订阅流程；这些交给 [skills/newsletter](../skills/newsletter/SKILL.md) 子技能。

# 六类图：适合什么内容、好坏长什么样

论文配图只有六种活法。选错类型，后面怎么调都别扭：把"机制"画成"流程"会显得浅，把"流程"画成"架构"会显得乱。

| 类型（`figure.json` 的 `type`） | 一句话判断 | 典型位置 |
|---|---|---|
| `pipeline` | 有一串**先后顺序**的步骤 | 方法总览（Fig. 1 最常见） |
| `architecture` | 有一堆**同时存在、互相依赖**的零件 | 系统/模型/平台设计 |
| `mechanism` | 要解释**为什么**，有因果链 | 机制图、信号通路、失效分析 |
| `comparison` | 要让人一眼看出**谁好、差多少** | 结果对比、消融实验 |
| `concept` | 还没有严格结构，先给**画面感** | 摘要图、答辩图、示意图、基金本子 |
| `toc` | 一屏之内让人想点开文章 | 封面、TOC graphic、graphical abstract |

> 数据图（柱状/折线/散点/误差棒）走 `chart`，不算这六类；图表规范见 `journal-specs.md` 与 `assets/journal.mplstyle`。

---

## 1. pipeline（流水线 / 方法总览）

**适合什么**：输入 → 处理 → 输出有明确次序；每一步都能起一个动词短语名字（"预处理 → 特征提取 → 融合 → 判别"）。

**好的是什么样**
- 每个框里只有**一个动作**，框宽随文字长度变化不大（视觉上齐）；
- 箭头只有两种含义：数据流（粗实线）和控制/损失（细虚线），并在图内图例里说清；
- 主链是**一条水平线**；旁支（数据增强、辅助损失）挂在上方或下方，不打断主线；
- 相邻框的间距一致，回环（如果有）走外侧，不从框中间穿过去。

**坏的是什么样**
- 框里塞整句话（"我们先对图像进行归一化然后送入编码器…"）——那是正文，不是图；
- 五个以上步骤排成一条横线：到期刊单栏 89 mm 里每步只剩 15 mm，字必被压；
- 箭头穿越节点、交叉成一团，读者要顺着线找；
- 每步颜色都不同，却没有语义（颜色应该表示"同类阶段"或"数据模态"）。

**面板数与阅读顺序**：3–6 段；单面板；**左→右**（期刊中文摘要图也建议左→右，别用右→左）。有"训练/推理"两条链时用 (a)(b) 两个面板，不要硬塞一条链。

**常见错误**
- 把"方法总览"画成了"实验流程"（包含"采集数据→标注→训练→测试"这种非学术创新内容）；
- 输入输出框大小差太多，重心歪；
- 只画了正向流程，没画损失/监督信号，审稿人会问"梯度从哪来"。

## 2. architecture（架构 / 系统组成）

**适合什么**：模块之间的**组成与依赖**，没有严格先后；多层（前端/后端、编码器/解码器、数据层/模型层/应用层）。

**好的是什么样**
- 用**层级**表达从属：同一层的东西顶部对齐；子模块放进父模块的浅色容器框里；
- 依赖箭头方向一致（谁调用谁），不被别的框压住；
- 3–5 个大块，块里 2–4 个小块；不是 15 个平级框；
- 关键接口标出来（"JSON / gRPC / 图像张量"），不标就没信息量。

**坏的是什么样**
- 所有块一样大、一样颜色、一样间距，像一堆便利贴；
- 双向箭头到处都是（说明还没想清依赖）；
- 一个块里再套三层框，缩到栏宽后内层字 3 pt；
- 图里出现的模块名和正文术语不一致（图叫 "Encoder"，正文叫 "特征提取网络"）。

**面板数与阅读顺序**：主图 4–9 个块；复杂系统拆 (a) 总览 + (b) 关键模块细节；**左→右表示数据流，上→下表示层级**，两者别混用。

**常见错误**
- 把部署图（服务器/容器）和算法图混在一张里；
- 数据库/缓存用"圆柱"图标，其它又用纯方框，图标体系不统一；
- 图例说明缺失，颜色含义靠猜。

## 3. mechanism（机制 / 因果）

**适合什么**：解释"为什么会这样"——因果链、信号通路、失效机理、误差来源；读者需要沿着箭头理解**因果**而不是**时序**。

**好的是什么样**
- 一条主因果链，用**因果动词**做箭头标签（"抑制""促进""上调""导致"）；
- 被作用对象画成"可变状态"（颜色深浅/大小），读者能看出变化方向；
- 正负调控用**线型+符号**区分（实线箭头=促进，平头/虚线=抑制），不靠红/绿；
- 有一条"如果阻断这里会怎样"的分支，这是机制图最值钱的部分。

**坏的是什么样**
- 和 pipeline 长得一模一样（只有先后没有因果）；
- 箭头无标签，读者不知道是"促进"还是"下一步"；
- 用了大量渐变、发光、3D 阴影，看着高级但印刷出来是一团灰；
- 把未验证的推测画得和已验证的结论一样重（该用虚线/问号标出"hypothesis"）。

**面板数与阅读顺序**：1 个主面板 + 2–4 个佐证小面板（局部放大、对照条件）；**阅读顺序 = 因果顺序**，用数字 ①②③ 或 (a)(b)(c) 显式标。

**常见错误**
- 箭头方向画反（这类错误 AI 生成图尤其爱犯，见 `prompt-library.md`）；
- 同一张图里既有"分子层面"又有"个体层面"，没有尺度提示；
- 图注说"抑制"，图里箭头是平的。

## 4. comparison（对比）

**适合什么**：方法 A vs B、消融实验、不同参数/数据集的结果；读者要**一眼看出差距**。

**好的是什么样**
- 对比维度统一：同一组里条形/箱体同宽、同一坐标范围；
- 有一个明确的"我们的方法"视觉强调（深色或加框），其它方法退到灰阶；
- 数值直接标在图上（关键值），不让人去对照表格；
- 有误差棒就说明是 SD 还是 SEM，图注写清 n 和统计方法。

**坏的是什么样**
- 每个子图 y 轴范围不同，视觉上"我们最好"其实是轴被截断；
- 用 3D 饼图/3D 柱状图（投影面积会骗人）；
- 12 组对比挤进单栏，图例占掉三分之一；
- 显著性星号和图注里的检验方法对不上。

**面板数与阅读顺序**：2–4 组子图；**左→右 = 从总到细**（总体性能 → 消融 → 参数敏感性）；每个子图内**左→右**读。

**常见错误**
- 用颜色表达"方法"，又用颜色表达"数据集"，同一张图两套色彩语义；
- 红绿双色对比（色盲不可读）；
- 图里写"ours is better"，那是讨论区的话，图里只给数字。

## 5. concept（概念示意）

**适合什么**：结构还没定、但要给读者/评委一个画面；摘要图、答辩 PPT 首页、基金本子里的"研究框架示意"。

**好的是什么样**
- 一眼能说出"这是在讲什么"（三个以内视觉元素）；
- 抽象关系清楚：包含、并列、汇聚、循环；
- 有留白，文字少（图上 3–8 个英文词，正文里解释）；
- 风格统一：同一套线条粗细、同一套颜色、同一套圆角。

**坏的是什么样**
- 元素太多像海报，缩小到 89 mm 全糊；
- 用真实照片拼贴，版权和"是否 AI 生成"都说不清；
- 图里有文字（尤其中文）——AI 画的文字基本是错的，见下方"硬规矩"；
- 看起来像数据图（有条形、有坐标轴），但数字是编的。

**面板数与阅读顺序**：1 个面板；阅读顺序靠**视觉重心**（从左上的主体开始），必要时加 ①②③。

**硬规矩（学术诚信）**
- `concept` 生成的图**只能用于示意/封面/TOC/答辩**，**不能当数据图**；产物旁必须有 `*.ai-generated.json`。
- 中文文字、数字、化学式一律**后期在矢量软件里排**，不要让 AI 画。

## 6. toc（封面 / TOC graphic / graphical abstract）

**适合什么**：期刊目录缩略图、封面候选、graphical abstract；目标是"让人想点开"，同时 30 mm 宽还能看懂。

**好的是什么样**
- 一个**主视觉** + 一句短语（≤6 个英文词，或干脆无字）；
- 高对比、低细节；缩到目录缩略图仍能分辨主体轮廓；
- 期刊配色呼应（Nature 系冷色克制，Cell 系可以更饱和）；
- 大留白，主体占画面 60%–70%。

**坏的是什么样**
- 把 Figure 1 整张缩印成 TOC（必糊）；
- 七个箭头八个标签，缩略图里全变成噪点；
- 用了其他论文的图/素材（版权问题）；
- 画风与论文气质不符（论文是严谨实验，封面是赛博霓虹）。

**面板数与阅读顺序**：单面板，无面板编号；构图按**三分法/中心对称**二选一，别两者混。

**常见错误**
- 忽略期刊对 graphical abstract 的尺寸要求（各刊不同，务必查该刊 Guide for Authors；本文件 `journal-specs.md` 里 Cell 一栏仍是**待核**）；
- 图里带期刊 logo 或别人的水印；
- 分辨率不够，放大到封面尺寸就糊。

## 通用：面板编号与阅读顺序

- **编号**：小写 (a)(b)(c) 或大写 (A)(B)(C)，**全刊统一**，期刊会按自己的排版改，但你自己别混用；
- **顺序**：Z 字型（左→右、上→下）是默认；如果逻辑顺序不是这样，用 ①②③ 显式标；
- **每个面板要能独立看懂**：标题（短）或图注里一句说明；
- **面板之间对齐**：同排面板等高、同列面板等宽，间距一致（`layout.gap_mm` 统一）；
- **别在面板里重复图注**：图里写 "Training set" 就够，不要写 "Fig. 2a shows the training set"。

## 一页纸自查（投出去之前）

1. 缩小到**目标栏宽**看一遍：字还认识吗？箭头还分得清吗？
2. **灰度打印**看一遍：还能区分吗？
3. 遮住图注看一遍：图自己能说明白吗？
4. 对着正文读一遍：图里每个词正文都提过吗？正文说的图里都有吗？
5. 图注和图**逐项对齐**：颜色、符号、面板编号、统计方法、n 值。

答不上来就回到 `check` —— 它能替你查掉一半硬伤；剩下的一半（信息是否成立）交给 `review` 和你的合作者。

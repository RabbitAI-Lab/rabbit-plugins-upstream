# 会审输出：先拿清单，再看分数

`review` 的可执行产出是**修改清单**，不是分数。

一句话口径：**分数只用来比较两版谁更稳，清单才是能照着改的东西。** 一个"8 分，还行"对改图没有帮助；"把 panel b 图例字号从 4 pt 改成 7 pt"才有。

另外两条要知道的：

- **会审成员可能被截断**：某个模型输出到 token 上限会断在半句，`review.json` 里该条会标 `truncated: true`。标了的这条别采信，自己再判。
- **合规分不靠模型拍脑袋**：`check` 已经给出确定性结论，会审的合规章节必须**引用 check 的结果**打分，不许模型自己估"应该差不多 300 dpi"。

---

## 一、修改清单（第一位）

`review.json` 里的 `fixes` 每条必须能被**直接执行**，格式：

```
[动词] + [对象/位置] + [改成什么]（+ 为什么，可选）
```

**能用的清单**

```markdown
- [ ] 把 panel b 的图例字号从 4 pt 改成 7 pt（Nature 下限 5 pt，当前缩到 89 mm 后不可读）。
- [ ] 把折线图中的红色 #E8000B 改为 #D55E00，并给第二条线加虚线，避免红绿不可区分。
- [ ] 把 y 轴标签 `Accuracy` 改为 `Accuracy (%)`，并在图注补 n = 5、误差棒为 SD。
- [ ] 删除 panel c 右下角的装饰性阴影，改为纯色填充。
- [ ] 把节点「Encoder」改为「编码器 Encoder」，与正文第 3.2 节术语一致。
- [ ] 将图高从 78 mm 降到 60 mm，使总高不超过 170 mm（Nature 上限）。
- [ ] 在 panel a 的第三个箭头加标签「梯度回传」，消除方向歧义。
- [ ] 用 check 重新跑一遍并确认 `TEXT_OVERFLOW_CANVAS` / `TEXT_OVERFLOW_PARENT` 与 `FONT_SIZE_BELOW_MIN` 消失。
```

**不能用的清单**

```markdown
- 建议优化整体布局。                 ← 无法执行
- 配色可以更专业一些。               ← 无法执行
- 图有点挤。                         ← 没有位置、没有目标值
- 参考 Nature 的风格改一下。          ← 没有指明改哪个属性
```

**怎么判一条清单值不值钱**：把这条发给一个没看过你图的人，他能不能在 5 分钟内照着改完、改完能验收。不能就是废话。

## 二、三维分数（第二位，只用于比较）

| 维度 | 满分 | 问的问题 | 谁来兜底 |
|---|---|---|---|
| 视觉 | 40 | 层次清不清楚、缩到栏宽还认不认得出、元素对齐不对齐 | 人眼 + 美术视角 |
| 信息 | 40 | 图有没有把该说的说清、有没有说错 | 同领域读者 + 审稿人视角 |
| 合规 | 20 | 能不能过期刊技术审查 | `check`（确定性、可复现） |

总分 100 = 视觉 40 + 信息 40 + 合规 20。**分差比总分有用**：三个维度里最低的那个决定这轮改什么。

### 视觉 40

| 档位 | 分数 | 长什么样（可直接对着验收） |
|---|---|---|
| A 出版级 | 36–40 | 缩小到目标栏宽所有文字仍清晰；元素对齐（同排等高、同列等宽、间距一致）；有明确视觉动线；留白均匀不空洞；颜色只承担语义；去掉任何一个元素都会损失信息 |
| B 小改可投 | 28–35 | 整体成立，但有 1–3 处明显瑕疵：某处对齐差 1–2 mm、某面板字偏小、图例位置挤、箭头穿过一个框、颜色偏艳 |
| C 明显问题 | 18–27 | 需要重排版式：面板大小失衡、文字与图形打架、箭头交叉成团、缩到 89 mm 后认不出、颜色 4 种以上无语义用法 |
| D 重画 | 0–17 | 版式本身错了（选错图类型、塞了整句话、3D/渐变堆叠糊成一团），改细节救不回来 |

**常见扣分项**
- 缩小后字认不出（每处 −3～−5）
- 对齐不齐、间距不匀（−2～−4）
- 箭头穿框/交叉（每处 −2）
- 装饰性元素（无意义图标、阴影、发光）（−2～−4）
- 颜色超过 5 种且无图例（−3）
- 面板编号缺失或顺序反人类（−2）
- 图例与图内标签重复（−1～−2）

### 信息 40

| 档位 | 分数 | 长什么样 |
|---|---|---|
| A 独立可读 | 36–40 | 不看正文也能说出"做了什么、为什么这样、结果如何"；每个元素都有信息量；术语与正文一致；箭头有语义（数据流/控制流区分）；关键量级/单位齐全 |
| B 小改可投 | 28–35 | 主干清楚，但有 1–3 处信息缺口：某个缩写没定义、某条箭头没说明、缺单位、缺 n 值/误差说明 |
| C 明显问题 | 18–27 | 图和正文说的不是一回事；关键步骤缺失；因果方向可疑；把"推测"画成"结论"；图中数值与表格不一致 |
| D 误导 | 0–17 | 图会让人得出错误结论：伪造数据、坐标轴截断制造假差异、编造统计显著性、AI 概念图冒充数据图 |

**常见扣分项**
- 图注与图不符（−5～−8，逐项扣）
- 缺单位/缺 n/缺误差定义（−3）
- 术语与正文不一致（−2～−3）
- 因果箭头方向可疑（−4）
- 未标注"示意/推测"（−3）
- 图里出现正文没提过的概念（−2）
- 把非数据图当数据图（**直接 0 分并报 error**）

### 合规 20

| 档位 | 分数 | 长什么样 |
|---|---|---|
| A 可直接投 | 18–20 | `check` 全绿（栏宽/高度/字号/DPI/字体/溢出/色盲/格式全过）；导出格式符合目标刊 |
| B 一处小问题 | 14–17 | 有 1 个 warn（例如字号刚好在上限、留白略多），不阻断投稿 |
| C 需修 | 10–13 | 有 1–2 个 error：字号低于下限、高度超限、DPI 不足、红绿并置无色盲兜底 |
| D 会被退回 | 0–9 | 多个 error：尺寸不对 + 字号 4 pt + 150 dpi + 位图交主图 + 文字被裁 |

**常见扣分项**（都对应 `check.json` 的 issue code）
- 超栏宽/超高度（`FIG_WIDTH_TOO_WIDE` / `FIG_HEIGHT_TOO_TALL`，每个 −3）
- 字号低于期刊下限（`FONT_SIZE_BELOW_MIN`，−4）
- DPI 不足（`DPI_BELOW_MIN`，−3）
- 字体不在期刊接受列表（`FONT_NOT_ACCEPTED` / `FONT_DECORATIVE`，−2）
- 文字溢出 / 元素出画布（`TEXT_OVERFLOW_*` / `ELEMENT_OUT_OF_CANVAS`，每个 −2）
- 红绿并置且无色盲兜底（`COLORBLIND_RED_GREEN`，−4）
- AI 概念图被当数据图（`AI_IMAGE_AS_DATA_FIGURE`，**直接 0 分 + error**）

## 三、判分纪律（给模型，也给你检查它）

1. **每条扣分必须指到具体位置**（`panel b`、`图例第 2 项`、`y 轴标签`），说不到位置的扣分不算。
2. **不许因为"不够漂亮"扣分**：审美是 A/B 档的分界，不是 C/D 的理由；C/D 必须能指出可复现的具体缺陷。
3. **合规只引用 `check` 结论**，不自己估数值。
4. **先减分再给分**：从满分往下扣，扣完写清扣在哪。
5. **不确定就写"存疑"**，不要扩散成结论；输出被截断就标 `truncated`，不许补全。

## 四、`out/review.json` 长什么样

```jsonc
{
  "ok": true,
  "tier": "econ",
  "members": ["glm-flash", "deepseek-flash", "gpt-mini", "claude-haiku"],
  "failed": [],
  "truncated": [],              // 输出被 token 上限截断的成员，其建议不采信
  "verdict": "B / 小改可投",
  "fixes": [
    { "id": "F1", "dimension": "visual", "where": "panel b", "action": "把图例字号从 4 pt 改成 7 pt", "why": "低于 Nature 5 pt 下限" }
  ],
  "scores": {
    "visual":     { "score": 31, "max": 40, "band": "B", "notes": ["panel b 图例偏小", "对齐基本整齐"] },
    "information":{ "score": 34, "max": 40, "band": "B", "notes": ["缺 n 值", "箭头语义清楚"] },
    "compliance": { "score": 14, "max": 20, "band": "B", "notes": ["引用 check.json：1 error + 2 warn"] }
  },
  "total": 79,
  "blocking": false,
  "raw": { /* 各成员原始作答，供你核对分歧 */ }
}
```

## 五、怎么读这份结果

1. **先看 `blocking`**：有 error 级合规问题（AI 图当数据图、超尺寸、DPI 不足）就别看分数了，先修。
2. **再看 `fixes`**：从上往下改，一次只改一类，改完跑免费的 `check` 复验。
3. **分数只在比较时看**：同一张图的第二版比第一版高 5 分才有意义；跨图比分没意义。
4. **看 `raw` 里的分歧**：几个模型对"图是否支撑结论"意见不一致时，通常图里真有一个模糊地带，值得你自己重看。

## 什么时候不该花钱会审

- 图还是草图/只有一个框 → 先 `render` 出结构再花。
- `check` 已经报 error → 先修，会审只会在同一个坑上重复扣分。
- 只是想知道"好不好看" → 把图缩到栏宽，给同组同学看一眼，5 秒钟就有答案 —— 那不是会审该解决的问题。

# P9 履约售后

## 核心理念

很多教程到"客户付款"就结束。这是错误的。

> 降低售后成本，而不是事后处理售后。

---

## 订单履约流程

```
客户付款
  ↓
确认地址（核对收件信息）
  ↓
商品检查（发货前再次确认状态）
  ↓
拍照留证（发货前拍照存档）
  ↓
打包（合适包装，防运输损坏）
  ↓
发货（选择合适物流）
  ↓
填写单号（及时在平台填写）
  ↓
通知买家（发消息告知已发货）
  ↓
物流跟踪（关注是否签收）
  ↓
确认收货（提醒买家确认）
  ↓
评价（引导好评）
```

## 包装建议

| 商品类型 | 包装建议 |
|---------|---------|
| 数码产品 | 气泡膜 + 快递盒，防震防压 |
| 小配件 | 自封袋 + 硬纸板信封 |
| 易碎品 | 双层气泡膜 + 填充物 + 硬盒 |
| 二手商品 | 额外保护，避免运输中新增瑕疵 |
| 服务/数字产品 | 无需物流，即时交付 |
| M4 数字产品 | 文件传输 + 交付确认（见下方） |
| M5 技能服务 | 在线交付 + 确认验收（见下方） |

包装成本控制在 ¥2-5 内，但不要为了省包装费导致商品损坏。

## 数字产品（M4）履约

数字产品无需物流，但有独特的交付流程：

### 交付流程

```
买家付款
  ↓
确认文件完整（打开检查，确认能正常使用）
  ↓
选择交付方式
  ↓
发送文件 + 使用说明
  ↓
确认买家收到并能打开
  ↓
提醒版权声明
```

### 交付方式

| 方式 | 适合 | 注意 |
|------|------|------|
| 闲鱼聊天直接发文件 | 小文件（<100MB） | 闲鱼对某些文件类型可能有限制 |
| 网盘链接 | 大文件 | 设置提取码，确认买家能打开 |
| 邮件发送 | 模板/素材类 | 确认买家邮箱正确 |

### 版权声明（必须告知买家）

```
本文件仅供个人使用，请勿转售、分享或用于商业用途。
如有质量问题，联系我更换。
```

### 防纠纷要点

- 交付前截图证明文件完整可用
- 交付后让买家确认"收到了，能打开"
- 明确说明文件格式和兼容性（如"PPT模板，适用于 Office 2019+"）
- 不承诺文件效果（如"用了这个模板一定能拿到offer"）

## 技能服务（M5）履约

技能服务的交付是"服务过程"而非"实物传递"：

### 交付流程

```
买家付款
  ↓
确认需求范围（明确做什么、做多少、什么时候交付）
  ↓
开始服务
  ↓
阶段性确认（大任务分阶段沟通进度）
  ↓
交付成果
  ↓
买家验收
  ↓
修改调整（约定修改次数，避免无限改）
```

### 防纠纷要点

- **开始前明确边界** - "PPT 10页以内，包含封面和结尾，2 天交付，含 2 次修改"
- **不要口头承诺** - 所有需求在聊天中确认，有文字记录
- **分阶段交付** - 大任务先给初稿确认方向，再继续做
- **修改次数约定** - 明确"含 X 次修改"，避免无限修改
- **退款政策** - 开始做了不退款，交付后质量问题可协商

### 常见风险

| 风险 | 预防 |
|------|------|
| 买家需求模糊 | 开始前用文字复述需求，让买家确认 |
| 买家无限修改 | 约定修改次数，超出按次收费 |
| 买家不确认验收 | 约定"交付后 3 天无异议视为验收完成" |
| 买家要求退款 | 已完成的工作不退款，未开始的部分可退 |

> **虚拟/服务类交易争议规则**：虚拟商品交付买家前风险由卖方承担，交付后按举证判定。服务类交易中已产生实质服务行为的，买方退款需与卖方协商一致。定制物品发货前卖方已完成定制的，买方无正当理由退款需协商一致。详见 `references/00-platform-rules.md`。

## 售后风险预防

### 容易退款的情况

| 风险 | 预防措施 |
|------|---------|
| 尺寸不符 | 商品页明确标注尺寸，图片视觉化 |
| 色差 | 声明"因屏幕差异可能存在色差" |
| 成色争议 | 发货前拍照确认，详细描述瑕疵 |
| 参数误导 | 不编造参数，不确定标 UNKNOWN |
| 功能问题 | 发货前测试功能 |
| 配件缺失 | 列出配件清单，发货前核对 |
| 发货慢 | 承诺时间内发货，超时主动沟通 |

**核心：在商品页提前说明可能的问题，降低预期差。**

## 交易争议处理规范

> 闲鱼争议处理有明确的规则，了解规则才能保护自己。详见 `references/00-platform-rules.md`。

| 争议场景 | 规则 | 你该怎么做 |
|---------|------|-----------|
| 签收发现不一致 | 收件人应场检视，发现不一致可拍照拒签 | 提醒买家当面验货，你在发货前拍照留证 |
| 描述不符/质量问题 | 卖方未如实披露瑕疵/维修记录的，退货退款 | 发货前如实描述所有瑕疵，拍照确认 |
| 假冒商品 | 支持退款 | 不卖假货，保留购买凭证 |
| 退货运费 | 争议责任归属谁，运费由谁承担 | 你的责任你承担运费，别推诿 |
| 举证规则 | 肉眼可识别的问题买方提供实物图片/视频；肉眼不可识别的需有效质检证据 | 你的发货前照片是最有力的举证材料 |

**争议受理期限**：确认收货前或超时打款时限内。

## 服务费结算

确认收货后，平台从买家付款中实时划扣服务费：

| 费种 | 费率 | 说明 |
|------|------|------|
| 基础软件服务费 | 0.6% | 所有成交订单都有 |
| 软件服务费（超额） | +1% | 当月成交>10件且>10000元时，超出部分收取 |

- 确认收货前退款：不收服务费
- 确认收货后退款：**已划扣的服务费不退还**

> **对新手意味着什么**：确认收货后退款你会亏服务费。所以有售后问题尽量在确认收货前解决。

## 售后处理流程

### 买家反馈问题

```
买家反馈
  ↓
判断问题类型
  ↓
质量问题？-> 道歉 + 退换/补偿
  ↓
预期差异？-> 解释 + 协商
  ↓
恶意退款？-> 平台介入
```

### 处理原则

1. **先道歉再解释** - 不要急于辩解
2. **提供解决方案** - 退换/部分退款/补偿
3. **及时响应** - 不要拖，越拖差评概率越高
4. **保留证据** - 发货前照片、聊天记录
5. **不要争吵** - 即使买家无理，也保持专业态度

## 评价引导

### 好评引导

买家确认收货后：

```yaml
review_request:
  timing: "买家确认收货后24小时内"
  message: "感谢支持！如果商品满意，麻烦帮忙确认收货和评价，有需要随时联系~"
  note: "不要直接要好评，用自然的语气引导"
```

### 差评应对

```
收到差评
  ↓
分析原因
  ↓
联系买家了解具体问题
  ↓
提供解决方案
  ↓
请求修改评价（如果问题已解决）
```

不要因差评与买家争吵。差评是改进信号。

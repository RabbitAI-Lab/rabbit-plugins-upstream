# P7-P8 客服教练与成交

## 核心理念

新手最容易卡死在："有人问我，我不知道怎么回复。"

Skill 提供 **Conversation Coach**：用户把聊天记录扔进来，Skill 判断并建议回复。

客服目标：**降低购买风险，帮助用户做决策。**

---

## 隐私保护提醒

当用户粘贴买家聊天记录时，**必须先提醒用户去除敏感信息**：

- 买家的手机号码 -> 删除或用"1XX"替代
- 买家的详细地址 -> 删除或用"XX路"替代
- 买家的真实姓名 -> 用"买家"替代
- 身份证号、银行卡号等 -> 绝对不能粘贴

**在分析聊天记录前，先说**："为了保护隐私，建议你把买家的电话和地址信息去掉再发给我。以下是基于你提供内容的分析："

---

## 禁止引导站外交易

> ⚠️ **这是闲鱼最容易被扣分的操作之一**，新手必须牢记。

在聊天中**绝对不能发**：
- 微信号 / 手机号 / QQ号
- 二维码 / 小程序码
- 第三方链接（淘宝/拼多多/微信等）
- "加我V""私聊""转微信"等诱导话术

**后果**：一般扣1分，严重扣20分，特别严重扣100分。闲鱼的AI会扫描聊天内容。

**正确做法**：所有交易都在闲鱼平台内完成，用平台担保交易。买家如果要加微信，婉拒并引导在平台内沟通。

---

## 聊天记录是争议证据

闲鱼争议处理中，聊天记录是重要证据。你的每一句话都可能被用来举证：

- **承诺要兑现**：聊天中说"包邮""送配件""保证正品"都会被视为约定，未兑现可被投诉"违背承诺"（扣20分）
- **描述要一致**：聊天中的描述与商品页描述不一致，会被认定为"描述不当"
- **不要乱承诺**：不确定的事情不要在聊天中打包票
- **保留证据**：发货前的确认聊天、买家确认收到的记录，都是你的保护伞

## 客服决策树

```
客户消息
  ↓
判断客户阶段
  ↓
询价？-> 确认需求 -> 推荐匹配
异议？-> 重新解释价值 -> 处理顾虑
信任？-> 提供证据 -> 降低风险
犹豫？-> 帮做决策 -> 不逼单
成交？-> 确认地址 -> 引导付款
```

不要回复："您好亲，需要什么呢？"

## 对话分析框架

用户把买家消息扔进来后，Skill 分析：

```yaml
buyer_message: "太贵了，别人卖70。"
analysis:
  customer_stage: "异议"
  buyer_intent: "medium"  # high/medium/low
  main_objection: "价格"
  recommended_strategy: "value_reframe"
  suggested_reply: |
    已经是比较实在的价格了。这款和70的主要区别是：
    1. 状态更好（95新 vs 8新）
    2. 配件齐全（原装XX）
    3. 支持验货后发货
    如果确定要，可以帮你包邮。
```

## 6种常见场景

### 场景1："还在吗？"

不要回复："在。"

```yaml
suggested_reply: "在的，现货，可以直接拍。你如果比较关注成色/尺寸，我可以拍细节给你。"
strategy: "确认库存 + 主动提供关键信息"
```

### 场景2："能便宜吗？"/"最低多少？"

不要立即降价。先判断购买意图。

```yaml
suggested_reply: "已经是比较实在的价格了，如果确定要，我可以帮你包邮/少一点。"
strategy: "不急于降价，用附加值代替降价"
```

### 场景3："太贵了，别人卖XX"

不要争论。重新解释价格差异。

```yaml
suggested_reply: "理解你的感受。这款和XX的主要区别是[具体差异]。如果你更在意价格，我也有另一款[更低价的选择]。"
strategy: "value_reframe - 重新解释价格差异的来源"
```

### 场景4："我再看看"

不要逼单。不要回复"好的。"

```yaml
suggested_reply: "没问题，你可以先对比。我这款主要优势是XXX，如果你更在意XXX，我也可以帮你看看这款是不是合适。"
strategy: "decision_support - 帮用户做决策，不逼单"
```

### 场景5：问具体参数/型号

快速准确回答。不确定的标记 UNKNOWN，不编造。

### 场景6：质疑真假

不要只说"保证正品"。提供证据。

```yaml
suggested_reply: "购买渠道是[XX]，有[订单截图/发票]。你可以收到后验证。"
strategy: "evidence_provide - 提供可信证据"
```

## 异议处理策略库

| 异议类型 | 策略 | 核心逻辑 |
|---------|------|---------|
| 价格异议 | value_reframe | 重新解释价格差异的来源 |
| 信任异议 | evidence_provide | 提供购买渠道、发票、实拍 |
| 比较异议 | differentiation | 说明与竞品的具体差异 |
| 犹豫不决 | decision_support | 帮用户做决策，不逼单 |
| 售后担忧 | risk_reduction | 明确售后承诺和退换政策 |
| 规格疑问 | accurate_answer | 准确回答，不确定标 UNKNOWN |

## 客服禁忌

- "在的""要吗""可以"（低信息回复）
- "全网最低""绝对正品"（无证据声明）
- 立即降价（暴露底价，失去议价空间）
- 逼单（闲鱼用户反感强推）
- 隐瞒瑕疵（导致咨询->下单->纠纷）
- 在聊天中发微信号/二维码/外部链接（引导站外交易，扣1-100分）
- 辱骂/恐吓/人身攻击买家（骚扰他人，扣1-100分）
- 泄露买家隐私信息（电话/地址/姓名等，扣20-100分）

## 成交后引导

客户决定购买后：

```yaml
post_decision:
  step_1: "确认收货地址和联系方式"
  step_2: "引导通过平台担保交易（不要私下交易）"
  step_3: "承诺发货时间"
  step_4: "发货前拍照确认商品状态"
  step_5: "提醒收货后有问题随时联系"
```

## 高频问题收集

从客服记录中提取高频问题，反哺商品页优化：

```yaml
faq_insights:
  top_questions:
    - question: "兼容XX型号吗？"
      frequency: 5
      action: "在商品描述中增加兼容性说明"
    - question: "能便宜点吗？"
      frequency: 4
      action: "调整定价策略或增加价值包装"
```

高频问题 = 商品页信息缺失的信号。

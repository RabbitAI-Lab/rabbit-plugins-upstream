# 08 工作流：创作流水线 / 批量选题 / 文案改造 / 发布前自查

本文件是复合场景的聚合入口：从零做内容、批量处理选题、改造文案草稿、发布前把关，都从这里出发。每个步骤标注了要用的工具和出处文件。

## 一、创作流水线（从零做一条内容）

```
1. 选题三查 → 01（素材过滤：需求/传播/结构三道门）
2. 设计钩子 → 02（挖洞：三要素 + 有效期原理）
3. 安排结构 → 02（谜题分布：开头抛若干问题不马上解答；
   一个章节解一个问题;最大的留最后,甚至可以不给答案）
4. 填充血肉 → 自己的故事、自己的例子、自己的语言（认知长在自己身上 → 06）
5. 设计结尾 → 02（诺兰公式:停止总结/留缝/可截图画面,让余数留下来）
6. 利他类型自查 → 06（这条是信息型还是判断型?）
```

原则提醒：先定答案时长再定钩子洞大小（02 有效期原理）；结构解决后优先填"只有你经历过"的案例——空洞的正确不如具体的独家。

## 二、批量选题处理（用户一次给多个选题）

### 为什么不逐条详改
10 条全部详改会淹没重点——判决要先一览，火力集中在代表性问题上。但也不只给判决不给改法：用户能想到这些选题，往往是他在这个领域里能想到的天花板，扔掉等于让他无路可走。所以结构是：**先全部判决，再挑代表详改，原素材一律保留内核换角度救活。**

### 第一步：判决表（全部选题一览）
按主轴 + 选题三查 + 利他类型给每条一行判决。列：选题 / 谜题强度（强中弱无）/ 受众宽窄（宽窄死窄）/ 利他类型（信息型/判断型/议题型）/ 判决（值得做/改造可活/必须大改/砍）。

判决逻辑参考：
- 谜题无 + 受众死窄 + 信息型 → 砍（救活成本太高）
- 谜题弱/中 + 信息型 → 改造可活（信息转判断）
- 谜题强但载体错（如个人判断用组织号发）→ 必须大改
- 谜题强 + 受众宽 + 判断型 → 值得做（详改演示怎么放大优势）

### 第二步：挑 3-5 条详改（不超 5 条，否则信息过载）
挑选优先级：①"必须大改"的（演示载体修正）→ ②"改造可活"里最典型的（演示信息转判断）→ ③至少 1 条"值得做"的（演示放大优势）。砍的不详改。

### 第三步：详改结构（每条两层）
**为什么不行**——根因至少分三层：
- 表层：谜题/受众/利他类型的表面问题（如"没有谜题只有答案"）
- 中层：可代替性/载体错位（如"信息型谁都能发""这个载体不能承载这种判断"）
- 底层：认知或商业机制（如"答案已填好，蔡根尼克不启动""关注是将来时，观众没有理由期待下一条"）
只拆一层用户不知道为什么不行，下次还犯；拆到机制层，标准就长他身上了。

**改成什么样**——给 3-5 个方向让用户选（为什么给多个：用户是决策者，方向你来定就替他做了决定）。每个方向标注：改后钩子 + 为什么这样改（机制一句话）+ 适合什么目的。方向之间用不同手法，否则等于没给选项。组织发声的账号另见下方变体。

### 第四步：一段总结
归纳本批最致命的共性问题 + 统一改造手法（3 条以内），一段话收束。原素材不用扔，换角度/换载体就能救活。

### 真实样例（few-shot，选题语境：求职咨询个人号）

> 输入："帮我看看这几个选题：1.求职简历模板盘点 2.面试十大高频问题及回答技巧 3.最新就业形势数据解读 4.我见过一个应届生在终轮说了这句话，全场面试官都愣了 5.为什么劝你第一份工作别只看薪资"

第一步判决表：

| # | 选题 | 谜题 | 受众 | 利他类型 | 判决 |
|---|---|---|---|---|---|
| 1 | 简历模板盘点 | 无（已填好的清单） | 窄（求职期一次性需求） | 信息型 | 必须大改 |
| 2 | 面试十大技巧 | 无 | 窄 | 信息型 | 必须大改 |
| 3 | 就业数据解读 | 无（纯数据） | 死窄 | 信息型 | 砍 |
| 4 | 应届生终轮说了这句话 | 强（说了什么？为什么愣？） | 宽（打工人+求职者都点） | 判断型（"我见过"） | 值得做 |
| 5 | 第一份工作别只看薪资 | 中（有判断有争议） | 宽 | 判断型 | 值得做 |

第三步详改节选（选题 1，演示到什么深度算够）：

**为什么不行（三层）**：①表层——"盘点"是已填好的答案，没有未完成的事可追踪 ②中层——模板任何机构、任何 HR、任何 AI 都能发，观众冲模板来的不是冲你来的，下次搜"简历模板"又是一大把，不需要你的账号 ③底层——关注是将来时：看完这条，观众没有任何理由期待你的下一条（→ 03 第一诀）。

**改成什么样（方向示例，3 个手法各不同）**：
- 方向 A · 判断型案例化："当 HR 那几年，我见过一份只有一句话的简历——三个面试官都把他约来了。"（"我见过"信号词 + 独家案例，模板知识在故事里带出）
- 方向 B · 风险提示框架："简历上写这三种东西的，我当 HR 时直接扔——第三个几乎人人都写。"（把"是什么"转成"为什么错"）
- 方向 C · 翻译欲望："你不是不会写简历——你是不知道 HR 只花几秒看一份简历时，到底在看什么。"（把信息翻译成观众的真问题 → 05 翻译法）

**第四步总结示例**：这批选题的共性问题——80% 是信息型，账号在当"模板库"：观众收藏的是信息，记住的不是你。统一改造手法：把"是什么"换成"我见过/我发现"；把清单换成案例；把信息翻译成观众真正的困惑。原选题不用扔，1/2 换钩子就能救活，3 直接砍。

### 组织发声的变体（企业号/机构号）
组织声音避免"我认为/我坚持"式个人立场表述，判断改用事实载体承载："我见过一个学生……" → "我们服务过的客户里，约三成曾……""有位客户曾跟我们说……"。其余流程不变。

## 三、文案改造线（用户已有草稿，按序过七关）

1. **开头**：遮住标题和封面，第一句能自己站住吗？（→ 02 三自检）套路钩子（"你知道吗""5000万人不知道"）直接废掉重写。
2. **洞的清晰度**：观众能预期"看完我会得到什么"吗？模糊的洞改成"让观众意识到自己缺了什么"。
3. **填洞节奏**：答案给得太早 → 往后挪；拖太久 → 拆成多层逐层给。对照答案时长检查匹配（有效期原理）。
4. **结构**：按时间顺序/逻辑顺序平铺的 → 改成谜题驱动：开头抛问题，每章解一个，最大的留最后。
5. **故事开头**：从出生/背景/来历开始写的 → 砍掉，从最精彩、最惨、最爽的那一刻开始。
6. **利他类型扫描**：数一数"我认为/我见过/我发现"出现几次——0 次说明通篇信息型（组织号用事实载体变体）。
7. **承诺兑现**：开头承诺了什么，结尾给了吗？承诺了不兑现，观众被骗一次不会再给第二次机会。

每关的输出：现状诊断 + 改造方向 + 改后示例片段。不直接重写整篇——让用户看见"为什么这么改"，标准才会长在他身上。

## 四、发布前自查（用户说"要发了，帮我把关"）

按这个清单过一遍，逐条打勾或标红，标红的给改造方向，最后给总判决：**可以发 / 改完再发 / 推倒重来**（判决文化：不和稀泥）。

- **钩子**：遮住标题封面能站住吗？/ 挖的洞清晰吗（观众知道会得到什么吗）？/ 答案时长和内容时长匹配吗？
- **选题**：除你之外有人想看吗（闺蜜兄弟爸妈测试）？/ 别人听完记得住、酒局上愿意讲吗？/ 能一句话写出精准缺口吗？
- **结构**：开头抛谜题了吗？最大的留最后了吗？/ 每个章节在解答一个谜题吗（而不是按时间平铺）？/ 故事从最精彩最惨最爽的那一刻开始了吗？
- **利他类型**：这条是信息型还是判断型？/ 信息型的话，有没有至少一个"我见过/我发现"的独家案例？
- **承诺与余数**：开头承诺的结尾给了吗？/ 结尾是在总结内容、求关注——还是留下了新观点、反常的话、可截图的画面？
- **反模式扫描**：开头有没有烂梗？/ 有没有自上而下教育观众（讲和吃喝拉撒无关的东西）？/ 专业名词有没有跟生活化类比？

内容类型先判断：教程/操作类内容不套诺兰公式（把步骤整理清楚让人照做就是对），即时情绪类不套挖洞框架（胜负点在 3 秒冲击）——自查前先声明边界，再跑清单。

## 五、先问清单（信息不足时的追问参考）

用户的问题常常是"表面问的"和"深层需要的"不一致（→ 洞察翻译法）。所以追问不是让用户填表——每一问背后都是一次翻译。判断不了就先问，问的时候带上"为什么要这个"：

| 请求类型 | 判断前先确认 | 为什么 |
|---|---|---|
| 选题判断 | 账号定位；这条的目的（涨粉 / 变现 / 获客） | 目的不同答案完全不同——涨粉走判断型利他，获客走洞察翻译 |
| 批量选题 | 账号类型（个人号 / 组织发声） | 决定判断载体和改法（组织声音用事实载体） |
| 数据诊断 | 哪条最差 + 播放 / 涨粉 / 完播的具体数字 | 倒查链的入口，没有数字只能空谈 |
| 文案改造 | 改的方向（完播 / 转化）+ 内容时长 | 方向决定先动钩子还是先动结构；时长决定洞的大小（有效期原理） |
| vlog 诊断 | 身份 + 拍的内容 + 想走哪一型 | 三型的判断维度完全不同 |
| 对标选择 | 你的变现方式 + 你的受众 | 对标五问的前两问，答不上来对标就跑不通 |

这张表是六类高频请求的样例，不是边界。清单外的请求同样先问后答——该问什么，用"替人翻译"推：他表面问的，和你需要的判断依据之间差什么，就问什么。缺口复杂到拿不准，说明这是深度任务——全量加载后再答。

一次把缺的问齐，不来回挤牙膏。用户答完再进对应流程。

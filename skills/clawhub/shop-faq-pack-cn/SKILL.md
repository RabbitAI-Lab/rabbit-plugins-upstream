# 店铺 FAQ 知识库

把已批准的店铺政策变成长期可维护、可复制到客服工具或商品页的中文 FAQ。它只产出知识库内容，不连接聊天工具、不自动回复顾客。

## 输入

提供政策原文或结构化资料，至少包括：

- 运费：计费方式、包邮条件、偏远地区或特殊商品规则。
- 时效：发货处理时间、运输时长、工作日/节假日说明。
- 售后：退换条件、申请期限、运费承担、退款处理方式。
- 规格：尺寸、容量、材质、版本或适配信息，以及可选项。

资料必须是已批准、可对外使用的版本。保留价格、天数、地区、限制条件等原值；不要将推测写成事实。

## 工作流

1. 列出收到的政策字段，并标记“已知事实”或“商家建议”。
2. 按“下单与运费、发货与配送、售后与退款、商品规格、其他”分类；无依据的分类不编写答案。
3. 将每条政策改写为简短、可直接对外的问答。答案含条件、例外和必要的下一步，不新增承诺。
4. 汇总所有无法确定的字段为“需商家补充”，注明它阻碍回答的具体问题。
5. 输出 Markdown 知识库；每次政策更新时，以新批准原文替换相应事实，再复核关联问答。

## 输出格式

```markdown
# {店铺名} FAQ

> 版本：{日期或版本号}
> 资料状态：仅含已批准政策；“需商家补充”未作推断。

## 下单与运费
### Q：{问题}
A：{仅基于批准资料的回答}
依据：{对应原始政策字段}

## 发货与配送
...

## 售后与退款
...

## 商品规格
...

## 需商家补充
- 字段：{缺少的具体字段}
  影响：{无法可靠回答的问题}
```

## 边界与质量检查

- 不知道时写入“需商家补充”，不要编造包邮门槛、到货日期、退款时限或规格。
- “预计”“建议”等措辞只能用于明确标为建议的内容；已知事实保留准确原值。
- 若售后政策涉及法规、平台规则或争议，请由商家确认后再发布。
- 交付前检查每个回答都能追溯到输入字段，且没有“自动发送”“已联系顾客”等执行性表述。

# 产品方法论速查 / Product Methodology Cheatsheet

当用户提供的信息不全时，按缺口挑选合适的框架补全，再映射到 PRD 章节。下文中英文缩写（如 JTBD、KANO、NFR）均为产品领域通用专有名词，附中文释义。

> 用法：不要一次套用所有框架。先判断缺的是什么，再选 1–2 个最对症的，避免 PRD 变得臃肿。

## 一、框架清单 / Frameworks

1. **用户故事地图（User Story Map）** — 用"骨干活动 → 各步骤 → 用户故事"梳理端到端旅程与页面优先级。
   - 用于补全：页面清单、范围（In/Out scope）、最小可用路径。
2. **JTBD（Jobs To Be Done，待办任务）** — 锚定"用户雇用产品要完成什么任务"，关注动机与场景而非功能。
   - 用于补全：背景与目标、价值主张、一句话定位。
3. **用户旅程地图（User Journey Map）** — 阶段 / 触点 / 行为 / 情绪 / 痛点，特别擅长补全异常与逆向流程。
   - 用于补全：核心流程与闭环（正向 + 失败 / 取消 / 退货）。
4. **KANO 模型** — 把需求分为基本型 / 期望型 / 兴奋型，辅助排优先级。
   - 用于补全：范围取舍、关键指标优先级、MVP 边界。
5. **精益画布（Lean Canvas）** — 9 格：问题 / 解决方案 / 关键指标 / 门槛优势 / 渠道 / 成本 / 收入 / 核心资源 / 待验证假设。
   - 用于补全：背景目标、风险与开放问题、商业模式边界。
6. **用例 / 状态机（Use Case / State Machine）** — 定义角色对系统的操作，以及实体状态的明确迁移。
   - 用于补全：接口与数据契约、数据联动、异常状态。
7. **5W1H / 场景卡片** — 快速补全角色、场景与触发条件。

## 二、何时用哪种 / When to use which

| 缺口信号 | 首选框架 |
|---|---|
| 不知道"有哪些页面 / 步骤" | 用户故事地图 |
| 说不清"为什么做 / 价值是什么" | JTBD + 精益画布 |
| 流程只有正向、缺异常 / 逆向 | 用户旅程地图 |
| 需求太多、分不清重点 | KANO |
| 数据 / 状态混乱、联动说不清 | 状态机 |
| 风险与假设没想清楚 | 精益画布 |

## 三、映射到 PRD 章节 / Map to PRD sections

| 框架产出 | 落到 PRD 哪章 |
|---|---|
| 用户故事地图的骨干与步骤 | 三、范围；七、核心流程 |
| JTBD 的任务与场景 | 二、背景与目标；六、角色与权限 |
| 用户旅程地图的痛点 / 异常 | 七、流程闭环；五、非功能需求 |
| KANO 分类 | 三、范围；四、关键指标 |
| 状态机迁移 | 八、接口与数据契约；四、联动 |
| 精益画布假设 | 十一、风险与开放问题 |

## 四、用法示例 / Example

以"门店对接万代 CRM 的核销工具"为例，信息缺口补全示范：

- **只有一句话**："店员要在现场核销万代的券" → 用 **JTBD** 锚定：店员的任务是"在 5 秒内确认会员身份并核销权益，避免人工核对出错"；用 **用户故事地图** 推页面：扫码 → 会员详情 → 选券 → 确认核销 → 成功。
- **缺异常流程** → 用 **用户旅程地图** 补：核销失败（网络异常）→ 缓存待同步；用户取消 → 30 分钟内可撤销。
- **缺状态定义** → 用 **状态机**：券 `可用 → 锁定(核销中) → 已核销 / 已释放(取消)`。
- **缺优先级** → 用 **KANO**：基础型=扫码识别；期望型=实时积分回写；兴奋型=会员等级成长动效。

把这些产出分别填回 `references/prd-structure.md` 的 12 章 + 交互说明即可。

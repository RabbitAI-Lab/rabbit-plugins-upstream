# PRD 结构清单与诊断方法

本文件定义"产品原型与需求说明"型 PRD 的标准章节结构，以及诊断缺失章节、补全内容的实用方法。适用于把产品方案整理成可评审、可交付的需求文档。

> 说明：下文中的英文缩写（如 KPI、NFR、SMART、In scope / Out scope）均为产品领域的通用专有名词，首次出现时均附中文释义，正文叙述统一用中文。

## 一、标准章节（建议顺序）

1. **概览 / Hero** — 标题、一句话定位、版本号、作者、最后更新日期。
2. **背景与目标** — 为什么做、解决什么痛点、业务目标。
3. **范围** — 范围内 / 范围外（In scope / Out scope），明确边界，避免范围蔓延。
4. **关键指标 / KPI / 成功标准** — 量化目标与硬性时间节点。
5. **非功能性需求（NFR）** — 性能、安全、可用性、兼容性、合规。
6. **角色与权限** — 涉及的角色、各角色能做什么。
7. **核心流程与闭环** — 主流程 + 异常/逆向流程（如下单→支付→退货取消）。
8. **接口与数据契约** — 与外部系统的接口、字段、状态机。
9. **页面 / 功能原型** — 可交互 HTML 原型（骨架见 `assets/prd-template.html`）。
10. **上线与运营计划** — 节奏、时间节点、灰度、回滚。
11. **风险与开放问题** — 未决项、依赖、假设。
12. **术语表** — 缩写、专有名词。

## 二、诊断"还缺什么"（仅诊断、先不改）

拿到 PRD 草稿时逐项对照上表，标记缺失 / 薄弱项并给优先级：

- 缺失关键章节（无范围、无关键指标、无异常流程）→ **高优先级**
- 章节存在但空泛（如"提升用户体验"无量化）→ **中优先级**，建议补量化目标
- 缺少闭环（只有正向流程，无退货 / 取消 / 失败处理）→ **高优先级**
- 缺少时间卡点（项目有硬 deadline 却无里程碑）→ **中优先级**
- 术语未定义、字段名前后不一致 → **低优先级**但易补

## 三、关键指标 / 成功指标写法（常见坑）

- 避免用"试点门店覆盖 X 家"这类指标：当门店基数本就不大时该指标无意义且显不专业。
- 优先用**时间节点式硬性指标**：如"8 月 17 日开启联调""12 月 1 日必须上线"。时间卡点是项目真实约束，比覆盖率更有说服力。
- 量化指标遵循 SMART 原则（具体、可衡量、可达、相关、有时限）；区分"业务指标"与"交付指标"。

## 四、补全章节的写法要点

- **目标**：用"动词 + 对象 + 结果"句式，避免形容词堆砌。
- **范围**：用表格列出范围内 / 范围外，评审时双方确认。
- **接口契约**：列字段名、类型、是否必填、示例值；状态机用 `可用 → 锁定 → 已核销/已释放` 这类明确迁移。
- **异常闭环**：每个正向操作都配"如果失败 / 用户取消"的处理路径。

## 五、与可交互原型的关系

- 原型不是 PRD 的替代，而是第 9 章的具象化。PRD 文字定义"做什么"，原型展示"长什么样、怎么走"。
- 原型数据应与原型前序页面联动（如商品选择页 → 交易完成页的金额 / 优惠实时计算），保证演示自洽。
- 视觉遵循"大厂简约"：拒绝滥用渐变、紧凑间距、自然缓动、统一圆角（卡片 14px / 面板 16px）。

## 六、交互说明（Interaction Specs）

- 目标：让评审方既看得到"长什么样"，也看得到"怎么动"。两套都要给，且相互呼应。
- **原型内**：给关键可交互元素加 `data-ix="交互描述"` 属性，模板右下角"交互"悬浮面板会自动汇总所有交互，点击可定位高亮对应元素；可选 `data-ix-title` 给该条交互起短标题。
- **PRD 文档内**：在"交互说明"章节（位于接口契约与上线运营之间），按"触发 — 行为 — 状态变化"描述关键交互，例如：
  - 触发：点击"确认核销"；行为：弹出 loading，调用核销接口；状态变化：券 `可用 → 锁定 → 已核销`。
- 原则：不堆砌每个按钮，聚焦"会影响数据 / 状态流转"的关键交互。

## 七、完整示例参考

下面是一份"会员核销系统"的最小章节示例（仅示意，实际按需展开）：

```markdown
# 万代会员核销系统 · 产品原型与需求说明
版本 v1.0 · 最后更新 2026-08-06

## 一、概览
为门店端提供对接万代 CRM 的会员核验与用券核销能力，过渡期未与门店收银系统打通。

## 二、背景与目标
解决门店无法在现场核验万代会员身份、核销优惠券的问题。目标：店员 5 秒内完成一次核销。

## 三、范围
| 范围内 | 范围外 |
|---|---|
| 会员扫码核验 | 收银系统对接 |
| 优惠券核销 | 会员积分发放 |

## 四、关键指标
- 2026-08-20 完成门店试点上线
- 核销平均耗时 ≤ 5 秒

## 五、非功能性需求
- 离线降级：网络异常时缓存待同步核销记录

## 六、角色与权限
- 店员：发起核销
- 店长：查看记录、撤销核销

## 七、核心流程与闭环
扫码 → 识别会员 → 选择券 → 确认核销 → 成功；
逆向：核销后 30 分钟内可撤销。

## 八、接口与数据契约
- POST /verify 入参：memberId, couponId；出参：status, payable

## 九、页面原型
见小程序 / 后台管理原型 tab。

## 十、上线运营
灰度 3 家门店 → 全量。

## 十一、风险与开放问题
收银打通方案待定。

## 十二、术语表
核销：核对并消费优惠券权益。
```

对应原型骨架见 `assets/prd-template.html`，把占位文字替换为上表真实业务内容即可。

# 模板与字段定义（experience-forge 参考资料）

## 一、经验条目模板

```markdown
### <一句话标题：坑是什么 / 规则是什么>
- 分类: 个人通用 | 项目 | 行业领域
- 场景: 什么时候会遇到（触发条件）
- 症状/问题: 表面现象
- 根因: 为什么会这样
- 正确做法: 具体步骤或写法
- 通用规则: <一行，可直接被 AI 执行，例如："凡 X 场景，一律先 Y 再 Z">
- 来源: YYYY-MM-DD · <项目名> · <会话一句话描述>
```

示例：

```markdown
### GeoTIFF 写出后坐标系丢失
- 分类: 行业领域
- 场景: 用 rasterio 处理无 CRS 信息的栅格并写出新文件
- 症状/问题: 输出文件在 GIS 软件中定位到 (0,0)
- 根因: 源数据无 CRS 时 rasterio 不会警告，写出时 CRS 为空
- 正确做法: 读入后立即检查 `src.crs`，为空则按业务约定赋 EPSG:4490 并记录
- 通用规则: 处理栅格第一步必须校验 CRS，缺失时显式赋值，禁止默认放行
- 来源: 2026-08-27 · demo 项目 · 修复瓦片错位问题
```

## 二、命名规范

- 主题文件名：kebab-case 英文，如 `typescript-pitfalls.md`、`debugging-methods.md`
- 领域 skill 名：`<领域>-experience`，如 `gis-experience`
- README 索引行格式：`- [<主题文件>](./xxx.md) — 一句话简介（N 条）`

## 三、用户画像字段定义（~/.claude/user-profile.md）

| 小节 | 记什么 | 条目格式 |
|---|---|---|
| 技术栈 | 语言/框架/库及使用频率 | `- TypeScript（高频，2026-08 起 5 次会话）` |
| 工具与环境 | 编辑器、包管理器、OS、终端、网络环境怪癖 | `- pnpm 优先，不用 npm（2026-08-27 用户明说）` |
| 编码风格 | 命名、注释、错误处理、测试偏好 | `- 偏好严格 TS + 显式错误处理（观察 3 次，置信中）` |
| 协作与沟通 | 回复详略、确认习惯、提醒接受度 | `- 经验提醒接受度：正常（未拒绝过）` |
| 领域背景 | 行业、业务上下文 | `- GIS / GeoAI 方向` |
| 变更日志 | 覆盖旧偏好的留痕 | `- 2026-08-27 包管理器 npm → pnpm（用户明说）` |

**置信度约定**：用户明说的不加标注（默认强信号）；观察推断的必须标注 `（观察 N 次，置信低/中/高）`。

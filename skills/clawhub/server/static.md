# Static Files, Uploads, Compression, and Caching

Bytes that are not generated by the app: assets, downloads, media, and the uploads coming the other way. Getting these right removes more load than most application tuning.

**Before changing a caching policy**, read `## Services` in `~/Clawic/data/server/memory.md` for what is already fronted by a CDN — a cache rule set on the origin while an edge holds a contradictory one produces behavior nobody can reproduce.

## Serve Files From the Proxy

An application process serving static files spends a worker on work the proxy does with `sendfile` and no user-space copy. Route the asset paths at the proxy and let the app never see them:

```nginx
location /static/ {
    alias /srv/api/current/public/;
    sendfile on;
    tcp_nopush on;
    access_log off;
    expires 1y;
    add_header Cache-Control "public, immutable";
}
```

`root` appends the full request path to the directory; `alias` replaces the matched prefix. Mixing them up is the standard 404-on-every-asset bug. `access_log off` on assets can halve log volume on a busy site (`logs.md`).

## Cache-Control, Two Rules

Only two policies are needed, and choosing per-file is what makes both safe:

| File | Header | Why |
|---|---|---|
| Content-hashed asset (`app.9f2c1d.js`) | `public, max-age=31536000, immutable` | The name changes when the content does, so it can never be stale. `immutable` also stops revalidation on reload |
| HTML, JSON APIs, anything at a stable URL | `no-cache` (revalidate every time) or a short `max-age` with `must-revalidate` | These are the pointers to the hashed assets; caching them is how users get last week's app |

`no-cache` does **not** mean "do not store" — it means "store, but revalidate before use", which is exactly right for HTML. `no-store` is for responses that must never touch a disk (authenticated pages on shared devices), and it costs a full download every time.

Unhashed assets at stable URLs (`/logo.png`) are the awkward middle: a year of caching means you cannot change the logo, and no caching means downloading it on every page. Either hash them or accept `max-age=3600`.

## Revalidation

`ETag` and `Last-Modified` turn a repeat request into a 304 with no body. nginx generates both for static files automatically; the app must generate them for dynamic responses if it wants the same saving.

Weak ETags (`W/"…"`) survive compression; strong ones do not, and a proxy that compresses after the origin set a strong ETag produces revalidation that always misses. If gzip is on and revalidation never hits, this is why.

`Vary: Accept-Encoding` is mandatory on anything compressed and cacheable, or an intermediary serves a gzipped body to a client that did not ask for one.

## Compression

| Format | Compress? |
|---|---|
| HTML, CSS, JS, JSON, SVG, XML, plain text, WASM | Yes, always |
| Fonts: woff2 | No — already compressed |
| Images: jpg, png, webp, avif | No — already compressed, and recompressing costs CPU for ~0% |
| Video/audio: mp4, webm, mp3 | No, and never buffer them for compression |
| Anything already gzipped or zipped | No |

- Brotli beats gzip by roughly 15-20% on text at comparable CPU cost around level 4-5; gzip level 6 remains a fine default where brotli is unavailable. Above brotli level 5, on-the-fly cost rises faster than the byte savings.
- **Precompress build output** (`.br` and `.gz` next to the original) and serve it with `gzip_static`/`brotli_static`: maximum compression level paid once at build time instead of per request.
- `gzip_min_length 1000`: below about a kilobyte, the compression header and CPU cost more than the saving.
- Compression plus a stream is a bug: an SSE or log-tail route with a compressor buffers events until the buffer flushes (`proxy.md`).
- Compressing a response that contains a secret while an attacker controls part of the request is the BREACH class of attack; for authenticated APIs returning tokens, either do not compress or ensure the response contains no attacker-influenced reflection of a secret.

## The Upload Path

A body limit exists at every hop, and the smallest one decides:

| Hop | Setting | Default |
|---|---|---|
| CDN | Provider plan limit | Often 100 MB on entry tiers — verify the current value with the provider |
| nginx | `client_max_body_size` | **1m** — the single most common 413 |
| Caddy | `request_body max_size` | Unlimited by default |
| App framework | Its own limit (`MAX_CONTENT_LENGTH`, `bodyParser` limit, `upload_max_filesize` + `post_max_size` in PHP) | Small |
| Disk | Free space on the temp path | — |

Raise them together or the raise does nothing. PHP needs *both* `upload_max_filesize` and `post_max_size` (post must be larger), and a multipart form with several fields needs headroom above the file size itself.

Other upload facts worth having:

- `client_body_timeout` (60s default) applies **between reads**, not to the whole upload, so a slow-but-steady upload does not trip it — a stalled one does.
- Buffered uploads land in the proxy's temp directory first. A full or read-only temp path truncates at a size, never at a time (`debug.md`).
- Above roughly 100 MB, stop proxying the bytes: presigned direct-to-object-storage uploads remove the size limit, the timeout, the disk, and the worker occupancy in one change.
- Resumable uploads (tus, or chunked with a client-side assembler) are what mobile clients on bad networks actually need; a single 500 MB POST will fail often enough to matter.
- Never serve the upload directory as static files without validation: a user-uploaded `.html` served from your origin is stored XSS, and a user-uploaded `.php` under a php-fpm root is remote code execution. Serve uploads from a separate hostname, force `Content-Disposition: attachment` for untrusted types, and never let the upload path intersect a script handler.

## Serving Large Files

- `sendfile on` with `tcp_nopush on` hands the file to the kernel; combined with `aio threads` on nginx it keeps large downloads from blocking a worker.
- Range requests (`Accept-Ranges: bytes`) are what make video seek and interrupted downloads resume. Static files get them free; an app streaming bytes must implement `206 Partial Content` itself or every seek re-downloads from zero.
- `limit_rate` and `limit_rate_after` cap per-connection bandwidth — the usual shape is full speed for the first megabyte (so pages feel fast) then a cap for the rest.
- Anything above a few hundred megabytes served repeatedly belongs behind a CDN or in object storage with signed URLs; egress from a single box is the most expensive way to move bytes.

## Protected Files

Do not stream a protected file through the app worker. Use the proxy's internal-redirect mechanism:

```nginx
location /protected/ { internal; alias /srv/data/private/; }
```

The app authorizes the request and returns `X-Accel-Redirect: /protected/<file>` with an empty body; nginx serves the file with `sendfile`, and the worker is free in milliseconds. Apache calls it `X-Sendfile`. The `internal` directive is what stops the path being fetched directly — omitting it publishes the whole private directory.

For object storage, the equivalent is a presigned URL with a short expiry, which removes the origin from the path entirely.

## SPA Fallback

```nginx
location / { try_files $uri $uri/ /index.html; }
```

Every unknown path returns the app shell so client-side routing works. Two consequences to handle deliberately: genuine 404s now return 200 with the shell (the app must render its own not-found, and search engines will index it as a page), and API routes must be excluded from the fallback or a typo in an endpoint returns HTML to a JSON client — which surfaces as "unexpected token < in JSON at position 0", the most confusing error in the frontend canon.

Always serve `index.html` with `no-cache` here (above); an SPA shell cached for a year is an app that never updates.

## Directory Traversal and Dotfiles

- Block dotfiles: `location ~ /\. { deny all; }` — otherwise `.git/config`, `.env`, and editor backups are downloadable, and automated scanners check for exactly those within minutes of a domain going live.
- Turn directory listing off (`autoindex off`, the nginx default) unless a listing is the point.
- An `alias` without a trailing slash on a prefix location allows path traversal out of the intended directory. Keep the trailing slash on both sides.
- Backup and editor artifacts (`config.php.bak`, `index.php~`) are served as plain text by default because the extension is unknown. Deny them by pattern, and keep them out of the release directory.

## When to Put a CDN in Front

Worth it when: the audience is geographically spread, egress from the origin is a real cost, traffic is spiky, or the origin is a single box whose downtime you would like to be partially invisible. Not worth it when: users are all in one region, traffic is modest, and the added debugging complexity (whose cache served this? whose headers won?) exceeds the benefit.

With a CDN, the origin's `Cache-Control` is what the edge obeys, so the two rules above become more important, not less. Keep one owner for cache headers — the origin — and use the CDN's overrides only for things the origin genuinely cannot know.

## Write It Down

A caching or upload policy that was derived rather than defaulted — the upload ceiling agreed for this app and the hops it was raised at, an asset strategy, a CDN's role at the edge — goes to `~/Clawic/data/server/artifacts/decision-<topic>.md` with its `## Boxes` line in `memory.md` the same turn (`memory-template.md`). Otherwise the next person raises one hop's limit, sees no change, and concludes the limit is somewhere mystical.

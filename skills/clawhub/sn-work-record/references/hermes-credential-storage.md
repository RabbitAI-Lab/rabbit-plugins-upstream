# Hermes 凭据存储与复用

## 适用场景

用户希望后续直接查询、提交或修改蜀宁 OA 工时，而不想每次重复提供账号密码。

## 推荐布局

- 加密凭据：`~/.openclaw/workspace/memory/sn-work-record-credentials.md.enc`
- 解密密钥：`~/.openclaw/workspace/.cache/oa_enc_key`
- 会话 token 缓存：`~/.cache/sn-oa/token.enc`（有密钥时 AES-256-CBC 加密；无密钥时降级为同目录 `token.json` 明文）。两种形态均为 0600；缓存只存**账号指纹**（哈希）而非明文账号，并绑定 `base_url`，换账号后会自行失效重登
- 两个文件及父目录都应限制为仅当前系统用户可访问。
- 不要把账号、密码、密钥、token 写入 SKILL.md、memory、对话总结或普通日志。

技能的 `read_credentials_raw()` 会在请求明文 `.md` 时自动回退读取同名 `.md.enc`，因此脚本可继续使用默认的明文路径参数。

## 工作流约定

1. 首次收到凭据时，先判断用户是一次性查询还是希望长期复用。
2. 一次性查询：使用权限受限的临时文件，并在完成后删除。
3. 长期复用：明确征得同意后加密保存；不要查询完成后删除持久凭据。
4. 保存后必须验证：能成功解密、解析 Base URL，并完成一次登录；验证输出不得包含 token 或凭据。
5. 后续查询默认直接使用持久凭据，不再要求用户重复发送密码。
6. 用户要求停止保存时，同时删除加密凭据和密钥文件，并说明之后需要重新提供凭据。

## 安全边界

加密文件与密钥若位于同一账户下，主要防止误读、备份泄露和明文暴露；不能抵御当前系统账户或整机已被攻破的情况。向用户说明这一点，但不要在每次正常查询时重复安全说明。

token 缓存是**短期等效凭据**：在有效期内可绕过密码直接调用 OA 接口。因此它与凭据使用同一套 AES 密钥加密，避免出现「密码加密、token 明文」的防护降级；无可用密钥时才降级为 0600 明文。

## Hermes 运行时注意事项

虚拟环境的 `bin/python` 通常是指向基础解释器的符号链接。运行时探测必须保留虚拟环境路径，不能先用 `realpath()` 折叠路径，否则会丢失虚拟环境的 `site-packages`。比较“是否为当前解释器”时也应使用未折叠的绝对路径。

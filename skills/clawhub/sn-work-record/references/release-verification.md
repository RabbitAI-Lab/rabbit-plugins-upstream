# 发布包、安全扫描与公开状态核验

## 1. 确定目标与准备发布包

1. 分别读取本地版本及 `npx -y clawhub inspect sn-work-record --json` 的公开 latest；不要仅凭本地版本或历史回执认定已经发布。
2. 在私有暂存目录构建发布包，排除 `__pycache__`、字节码、安装元数据、凭据、认证缓存、原始 HAR 和无关文件；不要直接发布带运行产物的安装目录。测试和公开证据使用泛化值，扫描内部项目标识、账号、私网地址及密钥。
3. 对暂存包运行离线回归、语法与敏感信息检查，并执行 `npx -y clawhub publish <暂存目录> --slug sn-work-record --version <目标版本> --dry-run --json`。检查文件数与预期一致；dry-run 只说明将要上传，不证明安全审核通过。
4. 对新增行为先写失败测试再实现，保留普通提交、个人设置、选项解析、运行时自检及撤回重提的回归。真实 OA 写入需独立业务授权；破坏性实验还须有服务端可恢复契约或隔离环境证据。用户授权不代替可逆性验证，完整备份不证明审批状态可恢复；证据不足时保留真实记录。

## 2. 提交并区分生命周期

1. 用显式版本、变更说明和 `--tags latest --json` 发布，保留 versionId、attemptId、fingerprint 与 publicationStatus。给上传足够执行时间；超时后先查目标版本和发布状态，不立即重复上传或另换版本号。
2. `pending-publication` / `publicationStatus=pending` 只表示服务端受理，不能说公开成功，也不能说提交失败。用户询问进度时刷新精确版本，不反复只看旧 latest。
3. 用 `npx -y clawhub inspect sn-work-record --version <目标版本> --json` 检查 `version.version`、`version.files`、`version.security` 与 `skill.tags.latest`。Version not found 或 version=null 只说明本次查询没有取得公开版本，不证明从未受理。
4. 目标版本可读且 latest 指向目标时，报告“已公开发布”；单独说明该版本的安全结论。不要把 pending 阶段的原因猜成扫描故障；没有队列或错误证据就说明尚不能确定延迟原因。
5. 按注册表文件摘要计算并比较暂存包哈希和文件集合，核对缺失、多余与变化文件，才说明上传内容与已测试包一致；不要拿源目录测试结果冒充对不同暂存包的验证。

## 3. 核对版本级安全证据

- 读取目标 `version.security` 及其 scanners 明细；顶层 moderation 可能属于旧版本，不能用来证明新版本 Clean。
- 查询当前 CLI 的 `scan download --help`、`skill verify --help`，按其支持的参数读取目标版本扫描报告；不要沿用“没有扫描能力”的历史假设。
- 分开报告公开状态与安全状态：公开版本仍可能被标记 suspicious。逐项核对完整发现，不只修摘要提到的几类；风险标记不等于已证实恶意，也不能因测试通过而忽略告警。
- 若存在未解决告警，告知安装风险，不建议无条件推广更新；不承诺下一修订一定 Clean，也不通过改名、隐藏能力或关闭扫描来绕过审查。

## 4. 安全整改与验证范围

1. 先列精确文件/字段变化、兼容风险、备份和恢复步骤，经批准再修改业务实现。保留凭据、个人设置、认证缓存和持久提交/修改保护记录；不要清除保护记录来通过测试。
2. 能力披露须与实际入口一致，尤其删除等破坏性能力；文档声明不代替入口的显式授权和读回核验。
3. 审查所有子进程路径的凭据传播，包括依赖探测和实际解释器切换；最小环境调整须验证必要代理、证书及账号绑定兼容，不把完整环境继承直接称为外传证据。
4. 对进程参数中的密钥暴露制定实质修复，验证旧加密文件兼容、参数与子进程环境不含秘密；使用 fd 传递口令时，另用合成边界输入验证 OpenSSL 实际读取上限，超限须在调用前拒绝，不能把本地长度校验当作未截断证据。未经实现与测试的方法只标记为候选方案，不写成已验证修复。
5. 检查完整认证请求链的重定向策略，包含删除前详情和写后读取，不只检查写请求；自定义认证头可能在跨 origin 重定向时保留，不能仅依赖 Requests 对 Authorization 的处理。使用离线重定向适配器验证目标 origin 外没有认证请求。
6. 对最小环境白名单分别验证依赖探测与解释器切换；当前解释器已满足依赖时的直接返回，不证明现有环境被净化，也不能撤销 Python 启动前的路径注入。文档只声明实际覆盖的隔离范围。
5. 以离线 fake 覆盖失败、中断、401、超时、并发及未知写结果；fake 成功不能冒充 live 写入。只读预览或用户自行修改成功，也不证明新实现的撤回重提已做真实验证。

## 5. 交付

只报告目标版本、受理/公开状态、该版本安全结果、已执行验证与剩余问题；不回放上传过程。更新提示词应要求保留凭据和本地定制、备份后升级，并在新版本未公开或有告警时明确停止或提示风险。测试数、扫描结论与发布 ID 仅从实际输出填写，不在规范中预填历史快照。

# 发布验证边界

发布版本：1.14.1。

本版补充已有普通工时的显式授权撤回重提流程，并移除验证码的动态求值、测试模块的动态执行加载及命令行传 token 的文档示例。1.14.0 曾提交扫描但未确认公开；平台标记的旧模式已在本修订中实际消除，不把扫描完成等同于安全通过。HAR 只作为接口协议证据，原始抓包不进入发布包；示例、测试和公开证据使用泛化值。

## 需要验证

- 先执行新增行为的失败测试，再实现通过；保留新建提交、个人设置、业务选项、运行时自检的原有回归测试。
- 核对新流程对原记录 ID、日期、项目、时长、类型、阶段及所有受保护字段的保持，并对最终描述和状态进行读回。
- 撤回授权、只读预览、失败/中断/401/超时、并发和持久意图采用 fail-closed 保护；不同机器的竞争不被描述为已解决。
- 用独立 reviewer 检查安全和逻辑问题，发布包执行测试、语法检查及敏感信息扫描。
- 发布后读取注册表中的精确版本与文件摘要，确认实际上传内容与已测试包一致。

## 不应声称的事项

- 本版开发/验证不对真实业务工时执行撤回、更新、删除或重新提交。
- 离线 fake 的成功不能冒充真实 API 写入成功。
- 用户在页面完成修改、实时查询状态正确，证明协议样本有效，不等于新实现已做真实写入测试。
- 旧协议证据和发布记录是历史快照，不作为当前用户的默认项目、代码或时长。

最终测试结果与发布回执由维护者在本次任务结束时另行报告；本文件不预填未经执行的测试通过数或发布 ID。

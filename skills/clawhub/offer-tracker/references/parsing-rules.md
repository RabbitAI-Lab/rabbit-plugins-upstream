# 输入解析规则与样本（offer-tracker）

本文件补充 SKILL.md 第 2–3 步的细节，给出可复用的切分与字段抽取规则，以及本会话中真实跑过的样本。下次遇到类似输入可直接套用。

## 一、切分多记录的顺序

1. 先按全角分号 `；` 切。
2. 再按顿号 `、` 切（如 `A公司-...笔试 、B公司-...一面`）。
3. 逗号 `，` 仅在它分隔的是**两条独立公司条目**时才切（如 `a公司-b岗位，投递后笔试` 中逗号后面是说明，不切）。
4. 一条记录以"公司名（中文或字母开头）"为起点；公司名后可跟 `-` 接岗位。

## 二、字段抽取规则

- **公司**：段首到第一个 `-` 之前。例外：公司名本身含 `-` 极少，出现时仍按"首 `-` 分隔公司/其余"，岗位内可继续含 `-`。
- **岗位**：公司之后到状态词之前。用户未提供 → 空串，**不臆造**。
- **状态**：见 SKILL.md 状态表。"投递后笔试" → `笔试`。
- **DDL/时间**：识别 `ddl\d`、`DDL \d`、`（\d+月?\d+ \d+:\d+）`、`\d+月?\d+ \d+:\d+` 等 → 写入 `next`，并摘要进 `note`。
- **备注**：`备注：…`、`（备注：…）`、段尾补充 → `note`。

## 三、边界案例决策

| 场景 | 处理 |
| --- | --- |
| 同公司同岗位再次提到 | 视为推进，覆盖原记录状态，保留 id |
| 同公司不同岗位/工作室 | 独立新记录，备注标明区别 |
| 岗位缺失 | position 留空 |
| "预计挂/应该挂" | status 记实际阶段，判断进 note，等正式拒信再改 |
| 子编号 `1.` `2.` | 仅用于切分，不进字段 |

## 四、真实样本（本会话）

**样本 A（单条/空格切分）**
`a公司-b岗位投递 `

**样本 B（分号切分 + 子编号）**
`a公司-1.b岗位投递 2.c岗位投递`

**样本 C（DDL 与时间）**
`a公司-b岗位 笔试，ddl MM.DD` → next=`完成笔试（DDL MM.DD）/ 等待结果`。

## 五、HTML 录入要点

- 数据数组：`const initialRecords = [ ... ];`，位于模板约第 221 行。
- 追加时**先 Read 当前末尾几行**，确认最后一条的 `status` 真实值（可能是"一面"），再构造 old_string，避免替换失败。
- 记录对象字段固定：`{ id, date, time:'', company, position, status, next, note, updatedAt:'YYYY-MM-DDT' }`。
- `updatedAt` 用 `YYYY-MM-DD` + 字面 `T`（模板原有格式，保持一致）。

## 六、JSON 备份格式

```json
[
  { "id": "uuid", "date": "YY-MM-DD", "time": "", "company": "公司名",
    "position": "岗位名", "status": "已投递",
    "next": "等待简历筛选 / 笔试通知", "note": "秋招 · 投递 · 备注",
    "updatedAt": "YY-MM-DD" }
]
```
每次更新**全量覆盖**该文件，确保"合并导入"始终是完整最新集。

## 七、输出样本

```
新增（日期，状态）：
| 公司 | 岗位 | 进度 | 关键 |

完整进度总览（M 条：X 投递 + Y 笔试 + Z 一面）：
| # | 公司 | 岗位 | 进度 |
...

文件：进度表 path、JSON 备份 path。
提醒：临近 DDL/面试写出具体时间。
```

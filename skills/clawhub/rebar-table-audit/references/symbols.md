# 钢筋牌号符号编码说明

同一张图纸的「规格」单元格里，牌号符号和直径数字常常连写在一起，比如
`%%13212` 表示 HRB400、直径 12mm。这份说明列出默认认识的写法，以及怎么给
不认识的图纸补一份自定义映射。

## 默认映射（`rebar_table_audit/data/symbols.default.json`）

| 写法 | 牌号 | 来源 | 备注 |
|---|---|---|---|
| `%%130` / 原始字节 `0x82` | HPB300 | 通行约定 | |
| `%%131` / 原始字节 `0x83` | HRB335 | 通行约定 | 与正文可能不符，需人工确认 |
| `%%132` / 原始字节 `0x84` | HRB400 | 通行约定 | |
| `%%133` / 原始字节 `0x85` | RRB400 | 通行约定 | |
| `%%201` + 数字 | HPB300 | **2026-09-28 客户样图实测** | 如 `%%2018` = HPB300 Φ8，`%%20110` = HPB300 Φ10 |
| `Ì`（U+00CC / 204）+ 数字 | HRB400 | **2026-09-28 客户样图实测** | 某字体下的解码结果 |
| `É`（U+00C9 / 201）+ 数字 | HPB300 | **2026-09-28 客户样图实测** | 某字体下的解码结果 |
| `Φ` / `φ` / `Ø` / `%%c` + 数字 | 未指明 | — | 只知道直径，能算单位重但不能归入牌号合计，记 R005 gap |

标 **observed-in-sample** 的条目是从一份客户样图实测的字体渲染结果，
**换字体、换设计院很可能对不上**，每次运行会把本次实际用到的每条映射及次数
写进 `report.md` 和 `evidence.json` 的 `symbol_mappings_used`，跑完务必核对一遍。

ODA 和 LibreDWG 两条转换链对同一份原始字节可能解出不同字符（比如同一个
`0x84` 控制字节，一条链给出 `Ì`，另一条给出别的字符），所以默认映射表里两种
写法都收，遇到新的差异往这份文件和 `symbols.default.json` 里补，别互相覆盖。

## 怎么写自定义映射（`--symbols map.json`）

结构和默认文件一致，`grade_mappings` 里的条目按 `(code, raw_char)` 覆盖同 key
的默认条目，其余追加；`diameter_only_codes` 是新旧列表去重合并：

```json
{
  "grade_mappings": [
    {"code": "%%140", "raw_char": null, "grade": "HRB500", "source": "custom", "note": "某设计院自定义编码"}
  ],
  "diameter_only_codes": ["%%d"]
}
```

- `code`：AutoCAD 文本控制码（如 `%%140`），后面直接跟直径数字。
- `raw_char`：如果 DXF 里这个符号被解码成了具体的一个字符（而不是 `%%nnn`
  这种控制码字面文本），填这个字符；同样要求后面紧跟直径数字。
- `grade`：牌号名（自由文本，会原样进 `evidence.json` 和报告）。
- `source`：标注这条映射的可信度来源，自定义映射建议写 `"custom"` 或团队/项目名，
  和内置的 `gb-convention` / `observed-in-sample` 区分开。
- `diameter_only_codes`：只表示直径、不含牌号信息的符号列表（追加到默认的
  `Φ φ Ø %%c` 后面）。

## 未识别符号

规格单元格里出现任何 `%%` 开头但不在映射表里的编码，或者既没有可识别符号、
也没有裸数字/显式牌号名的文本，都会记一条 `R005` gap（`未识别的符号编码` /
`规格单元格无法解析`），行本身不会被丢弃——明细里 `grade`/`diameter_mm` 留空，
影响到的规则（主要是 R001）对这一行不适用，不会假装核对通过。

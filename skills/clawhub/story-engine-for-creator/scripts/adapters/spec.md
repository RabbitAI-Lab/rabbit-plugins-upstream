# 语言适配层协议（Language Adapter Protocol）v1.0

引擎：`Story Engine for Creator.py` ｜ 参考实现：`adapters/zh.py` ｜ 生效日期：2026-10-17

---

## 1. 目的

让引擎本体**不因新增语言而增长**。语言相关的一切（词表、正则、阈值、风格族预设）外置到 `adapters/<lang>.py`；引擎只保留语言无关逻辑。

新增一种语言 = 新建一个 `adapters/<lang>.py`，**不改引擎一行**。

## 2. 三层结构

| 层 | 内容 | 是否随语言变化 | 位置 |
|---|---|---|---|
| **语言无关层** | 哈希链、报告结构、五步算子骨架、伏笔台账状态机、插件框架、责任锚定 | 否 | 引擎内 |
| **语言相关层** | 切句 / 分词 / 人名 / 时代词 / 文风特征 / 长度度量（45 个常量块 + 六方法） | 是 | `adapters/<lang>.py` |
| **语义层** | 认知越界、谶语应验、伏笔回收 | 是 | **不在本协议内**（见 §6） |

## 3. 六方法契约

| 方法 | 签名 | 返回 | 约束 |
|---|---|---|---|
| `split_sentences` | `(text: str) -> list[str]` | 句子列表，去空串 | 必须覆盖该语言的句末标点 |
| `tokenize` | `(text: str) -> list[tuple]` | `[(施动片段, 动作词), ...]` | 无词表命中返回空列表，**不得猜测** |
| `extract_names` | `(sentence: str, known=None) -> list[str]` | 人名候选，至多 1 个（启发式）或已知名全部命中 | 提供 `known` 时必须走精确匹配 |
| `era_forbidden` | `(extra=None) -> list[str]` | 该语言的时代禁用词表 | 返回新列表，不得返回内部引用 |
| `style_features` | `(text: str) -> dict` | `{sentences, han_chars, avg_sentence_len, classical_chars}` | 键名固定，供阈值校准 |
| `length_unit` | `(text: str) -> int` | 长度度量 | 中文按汉字计、英文按词计——**各语言自定义单位** |

## 4. 常量包

`adapters/<lang>.py` 须导出引擎所需常量（当前 45 块，清单见文件内 `# [类名.] 原行 N-M` 注释）。三条规则：

1. **跨类同名必须分名**。已发生实例：`_CLASSICAL_CHARS` 在 `ProseStyleAuditor`（23 字，含「兮」）与 `StyleRecognizer`（22 字，无「兮」）值不同——合并会静默改变行为。现分名为 `_CLASSICAL_CHARS_PSA` / `_CLASSICAL_CHARS_SR`。
2. **同类内引用须连带替换**。已发生实例：`_JUMP_PATTERN` 引用 `_JUMP_WORDS`，后者分名后前者必须同步指向 `_JUMP_WORDS_ARE`。
3. **增量式定义保持原序**（如 `_NAME_PRONOUN_HEADS = _NAME_PRONOUN_HEADS + (...)`）。

## 5. 加载与部署

引擎启动时按以下逻辑加载适配器（`_load_language_adapter`）：

- 路径：`<引擎目录>/adapters/<_ADAPTER_LANG>.py`，`_ADAPTER_LANG` 默认 `"zh"`
- 通过 `importlib.util.spec_from_file_location` 加载，**不修改 `sys.path`**（避免污染共享内核场景）
- 适配器缺失或加载失败 → **立即抛 ImportError，不静默回退**（静默回退会造成两套行为并存）

**部署约束**：引擎文件必须与 `adapters/` 目录同级。单独复制引擎文件到别处将启动失败——这是设计选择，不是缺陷。

## 6. 已知边界（不得宣称已解决）

1. **语义层不在协议内**。认知越界、谶语应验、伏笔回收需要外部知识（角色知识模型 / 情节图谱），字面匹配做不到。任何语言下都不产出此类结论，除非另行配置。
2. **跨语言未验证**。当前只有中文参考实现；英文/日文适配器**无语料、无验收**。协议就绪 ≠ 能力就绪。
3. **风格族判定在现代中文上失效**（既有限制）。实测：工作区 5 份现代中文文档 5/5 被判古典族；古典字密度无判别力（现代 23.4‰ > 红楼梦 20.65‰）。协议化只是把该逻辑搬到适配器，**未修复**。
4. **哈希链非确定性**（既有缺陷，本轮发现）。报告内含 `uuid.uuid4/uuid1` 派生的 `node_id` / `nonce` / `audit_timestamp`，导致**同一文本重复审计产生不同哈希** → 与「P2 哈希链存证（可信审计）」目标矛盾。修复需将这些字段移出哈希载荷或改为内容派生。

## 7. 新增语言步骤

1. 复制 `adapters/zh.py` → `adapters/<lang>.py`
2. 替换常量（词表、正则、阈值、风格族预设）
3. 实现六方法（`length_unit` 尤其注意单位差异）
4. 用该语言测试集校准 `_THRESHOLDS`（**阈值不可直接沿用中文值**）
5. 变更 `_ADAPTER_LANG` 或在调用处显式传入
6. 提供该语言的回归基线（建议：≥20 个样本，含古今/题材对比）

## 8. 本次变更验证方式

**零行为变化验证（正确方法）**：比对两版引擎在红楼梦 120 回上的**确定性字段**。

| 项 | 结果 |
|---|---|
| 比对字段 | 31 个（排除 `audit_hash` / `audit_prev_hash`） |
| 比对样本 | 120 回 |
| 字段差异数 | **0** |
| 值等价校验 | 45/45 常量与原定义逐一相等 |

> 反例记录：本体曾计划用「哈希序列逐块一致」作为验证器，实测发现哈希含随机 uuid，同章三次运行三个值，该方案**不成立**，已改用确定性字段比对。

# riffsheet tool reference

`scripts/riffsheet.py` (the entry script; the code is the package `scripts/riffsheet_lib/` beside it) measures a short video and lays out the pictures you need to read it. It needs ffmpeg and ffprobe 7.0 or newer and Python 3.9 or newer, and nothing from the network. The optional `transcribe` command also needs the `faster-whisper` package and a speech model already on the machine; it downloads one only when given `--download`. The procedure that uses these commands is `references/METHOD.md`.

Change into the repository folder first (`cd` to it) and run it from there as `python3 -I scripts/riffsheet.py <command> ...` (`--version` prints the tool and analysis-format versions); the summary prints every follow-up command with the Python the tool ran under and the tool's absolute path, ready to paste. Write boxes and arguments out in each command: a command, a box or an argument list kept in a shell variable reaches the program as one word in zsh (the macOS default) and fails. A shell function is not such a variable and works in bash and zsh: `rs() { python3 -I scripts/riffsheet.py "$@"; }`, then `rs scan VIDEO --out DIR`. Any Python 3.9 or newer runs every command; for `transcribe`, use one that can import faster-whisper (for a virtual environment, `/path/to/venv/bin/python` in place of `python3`, for every command). Every time printed or drawn is the true timestamp of that frame, in seconds. `#n` is the frame number, counting from 0. A box is given as fractions of the frame, `x0,y0,x1,y1`, with `0,0` at the top left. Overview cells have gridlines every 10% to help you pick one. Labels on the images are drawn with the first font found among common system fonts; set `RIFFSHEET_FONT` to a font file to choose another (needed for Chinese, Japanese or Korean words when no font covering them is installed).

Exit status: 0 when the command did its work; 1 on an error, with one line on stderr naming it; 2 on a usage error (an unknown command or a missing or malformed argument, reported by the argument parser); 3 when `build` refuses (section 3: statements without a confirming view, or of what the sound is without a passed hearing check; nothing is written).

## `check [VIDEO] [--json]` (facts, when a need appears)

What this machine has for an analysis, as facts, without using the network and without changing anything. It does not judge what an analysis needs: that is the agent's judgment, from the request and the pictures. It reports the Python it runs under; ffmpeg and ffprobe (path, version, and any of the filters the tool uses that this build lacks: `drawtext`, which needs ffmpeg built with freetype, is the one most often missing); and the tool's own speech recognition path (`transcribe`, faster-whisper with the `small` model) as `ready`, `MISSING` or `PARTLY THERE`, with:

- the facts behind that state: whether faster-whisper is installed for this Python, or in `~/.riffsheet/venv` (the virtual environment `check` suggests), and whether the `small` speech model is in the Hugging Face cache (`HF_HUB_CACHE`, else `HF_HOME/hub`, else `~/.cache/huggingface/hub`), with its size;
- what it adds to an analysis, what an analysis lacks without it, and how long it takes to run (about 2.4 to 4.6 s for an 8 to 30 s clip);
- what preparing the missing parts costs: the faster-whisper package and the packages it needs, about 64 MB to download and 207 MB on disk, then about 5 s to install (measured for faster-whisper 1.2.1 on Python 3.9, macOS on Apple silicon; other systems differ somewhat), from the Python Package Index; the model, 486 MB to download once (the same on disk); both need the network, and the download time is the person's connection's; neither sends any audio or video anywhere;
- the commands that prepare it without touching the system Python (create `~/.riffsheet/venv`, install faster-whisper into it, and fetch the model with `transcribe --download` run under that environment's Python), the interpreter to run every riffsheet command with afterwards, and the commands that remove what preparing adds (the environment only when preparing creates it, the model only when preparing downloads it);
- other ways to get a transcript (below, under `transcribe`).
- when this Python cannot make a virtual environment (its `ensurepip` module is missing, as in the system Python of Debian and Ubuntu, which ship it as the system package `python3-venv`), that fact: installing a system package changes the machine, needs administrator rights and the person's yes.

It also reports whether the hearing check (below) can be made here: it needs a speech synthesizer on PATH (`say` on macOS; `espeak-ng` or `espeak` on Linux), and with none, that on Linux `espeak-ng` is a system package, which also needs the person's yes. Whether the agent can hear is not this machine's to report: only the check settles it.

`PARTLY THERE` means the package is installed but the model is not here, or the package is installed only in `~/.riffsheet/venv`: then the tool has to be run with that environment's Python, which costs nothing. With a VIDEO it also reads the video's streams and states plain exclusions: a video without an audio track has nothing to transcribe. The last line says what the report covers, and that it knows nothing about other tools on this machine (other recognizers, models or services). `--json` prints the same report as one JSON object (`python`, `ffmpeg`, `video`, `capabilities[]` with `id`, `path`, `state`, `facts`, `adds`, `without`, `run_time`, `cost[]` with `download_mb`, `disk_mb`, `time`, `network` and `sends_media`, `prepare`, `run_with`, `remove`, `other_ways` and, for a video that rules it out, `not_for_this_video`; and `covers`). Exit status 0 whatever it finds.

## 0. `transcribe VIDEO --out T.json [--hint TEXT] [--compare OLD.json]` (optional)

What `scan` needs for spoken words is a word-timed transcript in this format, whatever made it: JSON `{"language": "en", "segments": [{"start": s, "end": s, "text": "...", "words": [{"start": s, "end": s, "word": " word", "prob": 0.97}, ...]}, ...]}` (faster-whisper's output with `word_timestamps=True`; openai-whisper's `probability` key is read too; `prob` may be left out). Which recognizer makes it is the agent's choice. The tool's own tested path is this command, made with faster-whisper when that package is importable (otherwise it says how to set it up); the measurements below are of that path. Another recognizer, another model size, or a transcript the person supplies works as well: give it to `scan --transcript` with `--transcript-by "what made it"`, and the riffsheet records what made it and says that it was not the tool's tested path (`transcribe --model` with another size is recorded the same way, by its size). When this command cannot make a transcript it exits 1 and leaves at `--out` a record of why, `{"segments": [], "stage": {"state": "not_run" or "failed", "why": "..."}}`: `not_run` when the recognizer is not there (no audio track, faster-whisper not installed for this Python, the model not on this machine, or fetching it failed), `failed` when it was there and stopped while running (a decode or recognizer error). Give that file to `scan --transcript` as usual and the riffsheet says that speech recognition did not run, or failed, and why. The audio is decoded by ffmpeg. Default model `small`, chosen by measurement on clips with word-for-word burned-in captions as truth:

| model | word errors over 87 spoken words (brand name not counted / counted) | first word start vs caption on, median per clip | run time per 8-30 s clip (CPU, int8) |
|---|---|---|---|
| base | 7 / 13 | 0.08 / 0.15 s | 0.6-1.8 s |
| small | 0 / 6 | 0.07 / 0.09 s | 2.4-4.6 s |
| medium | 0 / 6 | 0.09 / 0.27 s (starts late) | 5.3-12.9 s |

`small` also fixed the product words that `base` misheard on other clips; `medium` was better on two function words but returned a stock phrase instead of the words on a sung clip and is three times slower. `--model` takes another size or a model folder; `--download` allows fetching a model; `--model-dir` points at another cache. `--hint` takes names and terms written on screen (brand, product, key terms) and biases the spelling toward them (with the brand name as hint, `small` made no error on the captioned clips); `--compare` prints the words that differ from an earlier transcript, with times. Speech transcribes the same on every run; on sung or music-heavy audio whisper re-decodes with sampling and wording can vary between runs.

## 1. `scan VIDEO --out DIR [--transcript T.json]` (run this first)

`scan VIDEO --out DIR --transcript T.json --transcript-by WHAT` takes a transcript made by other means and records what made it. `scan` records in `DIR/index.json` (`stages`) what each optional stage did: speech recognition `ran` (`by`: what made the transcript, from `transcribe`'s own record, `--transcript-by`, the transcript's `model`, or a note that it does not say; `tested`: whether that was the tool's tested path, `transcribe` with the `small` model), `failed` (`why`) or `not_run` (`why`: no audio track; no transcript, and why there is none on this machine; or `transcribe`'s own record). When it did not run or failed on a video with sound, the summary says so on its third line (NOT IN THIS SCAN), and the SOUND block does not set loudness events against words: with no transcript it is not known where words fall. A transcript from outside the tested path is named on a line of its own (TRANSCRIPT).

`scan` prints its summary in full when it finishes; the same text is saved as `DIR/summary.txt`, so there is no need to open that file after reading the printout. The full data is in `DIR/index.json`.

| output | what it tells you |
|---|---|
| SHOTS | Cuts (the whole picture changes), each with its start and end time, and `abrupt` or `gradual` (blur, whip or punch-in). A jump cut inside one framing is a cut too: in one frame at least a tenth of the picture changes while the rest holds, and the colors in the changed box stay at least 0.90 alike (overlap of 64-bin color histograms of the frame before and the frame after: the same person, clothes and light, rearranged; a graphic, picture or caption popping on brings new colors). Its line says `jump cut` with the box, the share of the frame and how alike the colors stayed; check it on `events.jpg`. For a change that takes two or three frames, each frame inside it is measured against the frame before the change and the frame after: darker, lighter or as bright (mean luma of all three, 0-255), warmer or cooler (mean chroma), and whether it is a mix of the two (a dissolve step: within 25% of the change from the best blend of them, on 32x32 color). A frame darker than both is a dip, lighter than both a flash. The same line is given under a non-cut change that takes two or three frames. `still` = share of the picture whose pixels hold through the shot (and per second): ≥ 0.30 locked camera or frozen picture, ≤ 0.05 handheld or a camera move, between = look |
| CHANGES THAT ARE NOT CUTS | `panel`: one rectangle changes (a cut or page change inside a split screen or inset). `band`: a caption or graphic line changes. `local`: something small changes (a sticker, or an object jumping inside a still frame). A `local` change made in one frame that is not a jump cut (under SHOTS) is marked POSSIBLE JUMP CUT: not classified, its frames before and after are on `jumps.jpg` |
| TEXT-LIKE REGIONS | Boxes where the picture changes in one-frame steps (usually captions), with a ready-made `text` command for each, most text-like first. `settles` = at the region's change moments, the median share of changed pixels that then hold to within compression noise for three frames (drawn text swaps in and sits still); below 0.10 the region is marked MOTION ONLY? (a moving subject). A centered box is widened to nearly the frame width and padded a cell up and down, so it holds the longest line. A caption that never changes is not found here |
| FIXED LAYERS | Boxes of strokes that hold to within compression noise while the picture behind moves or cuts (a caption, title, logo or watermark that stays up), from 1 s blocks where nearly the whole picture changes, with a `text` command for each. A still part of the picture can hold too (leaves, the edge of furniture): one whose box shows no lettering, logo or drawn shape on the overview may be skipped. When the picture never moves, nothing separates such a layer and the summary says so |
| SPLIT LAYOUTS | A straight seam across the whole frame (nearly every pixel steps across one line) that stays through consecutive shots, with at least one cut or pane change in that stretch changing one side three times as much as the other. Seam placed on native pixels in each shot's middle frame; both pane boxes and the layout's on/off (the cuts that open and close it) |
| DRAWN ELEMENTS | Elements measured without being pointed at, only from clear evidence: fixed layers, `local` changes, and what holds through a shot whose whole picture moves; offered when the measurement (as `element`) succeeds, the shape is solid, it lives 8+ frames and shows something new. Each has a ready region `Gn` |
| SOUND | Silences (below -40 dB for at least 0.3 s), loudness cliffs and peaks (flagged when no word is under them), RMS level for every 0.5 s, and LOUDNESS FACTS: the level's range, the three quietest 0.3 s stretches, the deepest drops, and stretches of sound with no word under it (quote these, not memory). UNDER THE VOICE: the quietest 20 ms in each pause of 0.12 s or more between words, against the speech level: NO CONTINUOUS BED (no pause stays within 20 dB of speech, at least half fall 25 dB under it or below -55 dB), SOMETHING CONTINUES (at least half stay within 20 dB and above -50 dB: music or ambience, not told apart), UNCLEAR, or NOT MEASURABLE (fewer than 3 pauses) |
| SOUND AT THE CUTS | For each cut, the loudness peaks, rises and drops whose onset falls on it, with the onset time and how far from the cut's first frame (`+` after), or else the nearest one within 1 s; and one line: how many cuts land on a peak or rise, against how many would if the cuts fell at random times (each cut's share of the clip within reach of a peak or rise, summed). Tolerance: one frame interval plus 10 ms (0.043 s at 30 fps), from the cut's first to its last changed frame. The 100 ms loudness curve alone places an event only to 0.1 s or worse (a peak's time there is the middle of its loud run), so each event's onset is refined on 10 ms levels of the decoded track: a peak to the first 10 ms of the stretch within 6 dB of its loudest 10 ms, a rise or drop to its largest step from one 10 ms block to the next (`onset_t` in `index.json`); a cut is known to the frame. Onsets within 30 ms of each other count once. It measures times only: it cannot say what the sound is, and it counts only the events the SOUND line lists, so a beat too soft to make a peak there is not counted |
| `overview*.jpg` | The whole clip, one cell every 0.5 s for clips up to 27 s; for longer clips the clip's length divided by 54, rounded up to a quarter second (0.75 s from 27 to 40.5 s, 1 s to 54 s). The summary's IMAGES line states the step. Each cell shows its time, frame number, shot and the words spoken in that slot |
| `shots/shot_NN.jpg` | One large, sharp frame per shot (the stillest frame near the middle of the shot). Use these for clothes, shoes and colors |
| `events*.jpg` | One row of frames around each change, with the change outlined in red. Read these only to check a classification |
| `jumps.jpg` | For each POSSIBLE JUMP CUT, the frame before and the frame after, large, with the change outlined |

The image list gives each image's pixel size and estimated token cost, `ceil(w/28) × ceil(h/28)`. No image is larger than 1568 px on its long side or 1.15 megapixels in area.

## `hear-check DIR [--answer DIGITS | --cannot-hear]` and `listen DIR [--from S --to E]` (sound)

The tool cannot hear. `hear-check` settles whether the agent can, for this analysis, by a test the tool sets and marks. Without an option it writes `DIR/hearing/check_N.wav`: a voice from the machine's speech synthesizer (`say`, `espeak-ng` or `espeak`, given the text on standard input) says six random digits, one in a million to guess, as 16 kHz mono WAV with no metadata. The digits are written nowhere: `DIR/hearing/hearing.json` keeps a salt and a PBKDF2-HMAC-SHA256 hash of them (3,000,000 rounds), never the digits or an answer. Trying every answer against the hash takes a million times as long as marking one; marking one took 0.38 s with OpenSSL 3 (Python 3.14) and 0.61 s with the LibreSSL of macOS's own Python 3.9, on one core of an Apple M6, so trying them all would take 4 to 7 days of one such core. `--answer` marks the newest check (every decimal digit counts, full-width ones included; other characters are ignored) and records `passed` or `failed`; `--cannot-hear` records that the agent cannot open sound. A new check abandons one left unanswered; the last answered check decides. A pass counts only when its record is whole: the check's sound file is there under the name the tool gave it, and its salt, hash, number of rounds and number of digits are those the tool writes. `scan` removes `DIR/hearing/` and `DIR/listen/` whenever it writes a scan folder: a pass and cut sound files belong to the video they were made for.

What the check protects against, and what it does not: it keeps an agent that cannot hear from inventing what the sound is, since such an agent cannot answer the digits except by measuring the file, which the instructions forbid. It does not protect against someone who deliberately forges the record: `hearing.json` is a file in the scan folder, and whoever can write it can write a pass.

`listen`, after a pass only, cuts the video's sound into `DIR/listen/` as mono 32 kHz WAV: `whole.wav` when the video is 60 s or shorter, and `sound_A_B.wav` (A and B in seconds) from 1 s before to 2 s after each sound event SOUND lists, windows that touch merged (with the whole track cut, a merged window covering half of it or more is left out: events every half second, as in music, are covered by the whole file); `--from S --to E` cuts one window of the agent's choosing. `DIR/listen/listen.json` lists each file with its span; `build` takes the judgment's `heard` statements against it.

## 2. Follow-up commands

All follow-ups take `DIR` and write their images to `DIR/look/`. They print what they measured, plus each image's size and token cost. An image name carries the command, its times and its box (`zoom_4.00_10.50_00-50-100-100.jpg`, `frames_12.40_13.90_00-00-100-50.jpg`; `--name N` gives `N.jpg` instead); when the cells do not fit on one image they are split into pages `_01`, `_02` … in time order (`zoom_4.00_10.50_13.00_00-50-100-100_01.jpg`). Under each `zoom` and `frames` image the command prints `in a mark:` and the exact text to put after the bar of a detail mark, with the moments that page shows: `{words|zoom_4.00_10.50_13.00_00-50-100-100_01@4.000}` (a page of several moments takes `@T`, one of its own moments), `{movement words|frames_12.40_13.90_00-00-100-50_02}`.

| command | answers |
|---|---|
| `element DIR --box B --at T [--name N]` | Where exactly is this card, icon, logo, sticker or end card, and when is it on? Give a rough box (it may be twice too big or cut it) and a moment it is fully on. Taking that frame as reference, every pixel is followed forward and back while it keeps its color (all three color planes within 10 levels); the frames on which most pixels in the box stop holding, jumping far from their held color, are the element's edges in time; the pixels stopping on both frames are the element (the connected group, preferring the one that began on one frame). Its box is refined on native pixels: what holds within 12 levels through its life (after the entrance animation) and differs from the frame before it came and after it left, cleaned of thin threads; the search widens while the element reaches the edge. First visible, in place and off times come from color distance to the element across a fade or slide; a cut is a hard edge. A box over a pane under SPLIT LAYOUTS returns the pane. Saved as `look/N.json`; a graphic with `"region": "N"` takes box and times from it. When what holds with it covers far more than the box pointed at, or fills most of the frame (an element on a still picture, such as a full-frame end card), the box is left out with the reason and only the times are kept: the graphic then gives `"region": "N"` plus a `"box"` drawn by eye, with a `"why"`. When nothing could be measured, the command says so and the graphic gives `box` and `time` |
| `text DIR --box B [--from S --to E] [--name N]` | What did this caption or region say, and when? A new state starts where the layer's own pixels change (a swap, pop, fade or highlight move, or a word bouncing into place: split from held picture to held picture), not where the picture behind moves or cuts: a caption that holds through motion or a cut stays one state. Each state is shown once, with its on time (the first frame that shows it) and off time (the first frame that no longer shows it), both measured, plus the words spoken meanwhile. A 2-frame state still gets its own cell; a state that arrives over 3+ frames (a fade, slide or pop) also gets a cell from inside its arrival, just before its own, labeled `mid-change a→b (n fr)` and `Tn arriving`: it belongs to the state after it, has no id of its own and is never given in a chunk. Where a drawn layer is in hand (stroke pixels that held to within compression noise since the state began), it decides: a change that leaves those strokes alone and adds none that hold is the picture (motion, a hand, a cut the caption survives), and one that changes half of them is the layer. A caption arriving a frame or two after the one before left (a one-frame gap between captions) is told by new strokes that change there and then hold to within compression noise, on edges, up to the next cut (at least three frames): the gap is a state of its own. A state marked `?` lies on a moving picture where no layer held still: a change inside it can be missed, so its first and last frames are both shown. A state marked NO LAYER shows no drawn layer: where it begins, at least 40% of the strokes that held to within compression noise in the state before changed, and almost nothing new (under a tenth of that) then holds that way through it; tested only where the change is not a cut. Each state gets a `layer` measurement: box, text rows, row height and colors (fill; outline or shadow; box), from pixels that held while the picture behind moved, or that changed at the state's edges and held between. Values are kept only when they agree with the region's other states (fill within 24 levels of the region's best-supported fill, shown by at least two states unless only one state was measured; row height within 40% of the region's), else withdrawn with the reason. A layer whose pixels reach two opposite edges of the box is not separated from the picture, or the box cuts the text: its size and place are withdrawn, and its colors too when its only evidence is holding through motion. A state marked `~` held a layer that kept changing while most of the region held exactly (pixels that change, then hold for two frames on an edge, over 1% of the region): a reveal not separated; its first and last frames are shown and the place of the change is saved (`changes_inside`). A window given with `--from/--to` should end at least a second past where the caption leaves, never on a cut: a state cut off by the window's edge is marked "runs past the window" and `build` refuses a chunk that uses it (a state that shows no caption is simply left out). A box that crosses the seam of a layout under SPLIT LAYOUTS is named as such: its two pictures cut at different times, so many states keep their times but get no measured style. Saved as `look/N.json`, which `build` reads |
| `color DIR --at T --box B [--ref R]` | What color is this thing? The box's main colors at that moment: share, hex, a plain name, hue in degrees, saturation and lightness, and `center` (share of that color's pixels in the box's inner quarter: a color at the border is the surroundings). CAVEATS are printed when the frame's brightest surfaces are tinted (warm or cool light), the frame is dim, or the box is small. `--ref R`, a box on something white or neutral gray in the same frame, also gives each color as if that thing were neutral (corrects for the light). Box only the thing. The names are kept for `build`, which warns when a mark in the same shot names a color none of them could be |
| `zoom DIR --at T [--at T ...] [--box B]` | What exactly is there (clothing, footwear, what something rests on, color, small print)? Gives the largest sharp view of a moment or region that fits the size cap, upscaled at most 2×. The file name carries the times (the first four) and the box. On a sheet of several moments, name the moment in a mark with `@T`; a page `_01`, `_02` counts only for the moments it shows |
| `mouth DIR --box B --words A-B` (or `--line N`, or `--from S --to E`) [`--every-frame`] | Is the person on screen saying this line? Shows the mouth region in the middle of each word and of each pause of 0.15 s or more, small (about 10 to 20 times cheaper than every frame), with the word under each cell; open on words and closed in pauses is that person speaking. `--every-frame` shows every frame. The file name carries the window and the box. `--words A-B` is a word index range from the build sheet, the same as a line's `words` in the judgment file; `--line N` is the transcriber's line `LN` on the build sheet, not one of your own lines |
| `frames DIR --from S --to E [--box B] [--every K]` | What happens frame by frame in this window (a motion, a hand, a reveal)? Shows every real frame, or every Kth with `--every K`. The file name carries the window and the box, with pages `_01`, `_02` … for a long window |

## 3. `build DIR [--judgment J.json] [--out O]`

Without `--judgment`: prints the sheet the judgment is written against (transcript words as `index:word@start`, or, with none, why: speech recognition did not run, failed, or heard no words; pauses, low-probability words, cuts inside lines, the text regions read so far, shot stillness), and under PACE the measured band of each sentence as the transcript punctuates it, so the first judgment can carry measured pace words, and last the detail words (below). Pace is measured per spoken line once lines are given (words per second from the first word's start to the last word's end, the words counted on the line as corrected, after its `fix`: a fix that joins two misheard words into one name lowers the count by one, and can change the band: below 2.5 unhurried, to 3.5 measured, to 4.5 brisk, above rapid-fire; characters for unspaced scripts: 3.5 / 4.5 / 6.0; anchored on natural speech at about 2.5-3 words/s and clearly rushed speech at 4 words/s over a line's window). Writes nothing.

With `--judgment`: reads the agent's judgment file (format in `references/METHOD.md`, section 9) and writes the riffsheet: `O/riffsheet.json` (format in `schema/riffsheet.schema.json`, versioned by its `format_version`; checked against it before writing: `prose`, `audio.voice_segments`, `scene_entities`, `slots`, `metadata`, plus `_prose_segments` and `_local`) and `O/riffsheet.md` (default `O` = `DIR/out`). `riffsheet.md` is an account for a person: what happens and why it holds, then each slot in order as a beat with its prose (people named in plain words, introduced on first mention, spoken lines in quotes; here and in the prose of `riffsheet.json`, `a` before a word said with a vowel sound becomes `an`), the text and graphics on screen (a graphic with the words of its `inline_text`), what the beat does for the viewer and what to keep when remaking, then what can change, what was not judged and any open checks. `_local.stages` carries the scan's record of each optional stage (ran, by what; failed or did not run, and why). Both files are meant to be shared, so neither names the person: a record names the Python that ran a stage by its version, not its path, and any path inside the home folder (in a stage's reason, an error message or the agent's own words) is written from `~`. Near its top `riffsheet.md` says whether the sound was heard (**Sound.**: heard by the agent, which passed the hearing check, or not judged, and why: the check failed, the agent said it cannot hear, or no check was taken), from `_local.hearing`. The judgment's `heard` statements, accepted only after a passed check and each from a file `listen` cut with its time inside that file and inside the video, go to `audio.heard` (`_src.text` `heard`) and into each beat (**Heard by the agent.**); without a pass `build` lists them under NOT HEARD, writes nothing and exits with status 3. When one failed or did not run, `riffsheet.md` says so in a paragraph under its first line (**Not in this analysis.**) and `build` prints it (NOT IN THIS ANALYSIS); when the transcript came from outside the tool's tested path, a paragraph says what made it (**Outside the tool's tested path.**; printed as OUTSIDE THE TESTED PATH). The judgment's `own_means` (facts the agent established by means the tool does not provide, with what it used) go to `_local.own_means` and a section of `riffsheet.md` of their own, and its `tool_gaps` to `_local.tool_gaps` and a section too (What the tool lacked here); with the speech not transcribed on a video with sound, the line under the title says `speech not transcribed` instead of `no speech`, `metadata.speaking_mode` is `none` tagged `cannot_judge_locally` (the analysis has no lines; whether anyone speaks is not known), and a prose or report sentence saying that nobody speaks (no speech, nobody speaks, wordless and the like) is a problem. In the same way, without a passed hearing check, a sentence anywhere in the judgment that says what the sound is is a problem (the words under Sound words below). `_local.sound_at_picture` carries the SOUND AT THE CUTS result and the same measure for each caption's measured on time (tool-measured; absent in a scan without audio), `build` prints the captions' line as SOUND AT CAPTION APPEARANCES, and `riffsheet.md` gives both summaries in one line under its heading. It fills in, and tags as measured: line time ranges, text (with the agent's caption-spelling fixes), pace (printed per line under LINES; the one value used everywhere); `speaking_mode`, duration, language; `video_format` = `single_shot` when not given (tagged default); caption time ranges (the chunk's first and last states' edges), `cue_max_words`, position, size class and colors (a frame-weighted vote over the chunk's kept state measurements); graphic boxes and times the same way; segment and slot time ranges. A value still missing is taken from a measured caption of the same region (tagged inferred). The CAPTIONS block prints the final values, marking the agent's overrides `(read)` and the taken ones `(inferred)`. Graphics whose region is an `element` take its box and times. Detail marks `{words|VIEW}` in prose and entity text are checked and removed (format in `references/METHOD.md`, section 9): VIEW must be a `zoom` image or shot frame of this scan, at least 480 px on the long side per moment, showing a moment inside the statement's stretch; `{words|?}` goes out tagged uncertain; confirmations are listed under `_local.confirmations`. The detail words are found by the list under Detail words below. Any statement of how something moves may name a `frames` sheet over the moment; movements one still cannot show (`MOTION_RE`: nod, shrug, wink, a head tilt, shake or turn) must, and a `frames` sheet never confirms a detail word. While any sentence holds a detail or movement word outside a mark, or a mark fails, `build` prints them under UNCONFIRMED, writes no `riffsheet.json` or `riffsheet.md` (it removes stale ones) and exits with status 3. The tool cannot tell whether you opened a view you name or whether your words match it: it lists every view named, under VIEWS NAMED, and warns about color words (conditions under Detail words below). `cue_max_words` is left out for a caption whose chunk uses a `~` state whose change crosses the caption's line. A chunk that begins or ends with a NO LAYER state is shortened to the states showing the layer (its times come from those), with a note; one with a NO LAYER state inside it is a problem. A spoken line that crosses a cut is listed with the time its marker belongs at (the segment where its first word starts). A spoken line that holds a sentence end (`.`, `?`, `!`, `…`, `。`, `？`, `！`) followed by a pause of 0.15 s or more, or a comma followed by such a pause, is listed under WARNINGS: one line is one sentence. One garment or product word given different color words in different places is warned about too (one keeps one color name), and so is a `what_happens` that never mentions the voiceover when some lines are voiceover and others on camera. Warnings do not stop the build. It then runs the checks (segments contiguous, cuts and pane cuts named, markers resolve, each `[voice:X]` once in the segment where its line starts with its speaker the nearest marker to the left, a pace word next to a line matches the measured band, no ASCII quotes, slots at most 4 with distinct stages and all formula keys, anchors resolve, `video_format` valid and not a split value alongside a split graphic, a measured split layout matched by a split value or a split graphic, a speaker that is not a person entity has no marker to stand next to, no chunk cut off by a `text` window, each object named as `visual_anchor` by a caption, no id such as `protagonist` written as a plain word in prose or report) and prints every problem; `CHECKS: N problem(s)` counts these and the UNCONFIRMED ones, and says how many are under each heading. Same inputs give the same files.

## Detail words

`build` treats a statement as a detail, to be wrapped in a `{words|VIEW}` mark, when it holds one of these words or its plural (`-s`, `-es`); outside a mark it refuses it. The build sheet (`build DIR` without a judgment) prints the same list at its end.

- Clothing and footwear: shirt, t-shirt, tee, tank top, crop top, blouse, hoodie, sweater, sweatshirt, jumper, cardigan, jacket, coat, blazer, vest, dress, skirt, jeans, denim, trousers, pants, shorts, leggings, joggers, suit, uniform, apron, overalls, sleeve, collar, hood, sneaker, shoe, boot, heel, sandal, slipper, clog, loafer, sock, hat, cap, beanie, bandana, headband, scarf, glove, belt, bag, handbag, purse, tote, backpack, glasses, sunglasses, outfit.
- Jewelry, hair accessories and marks: bracelet, bangle, ring, necklace, chain, pendant, earring, hoop, stud, wristwatch, anklet, piercing, hair clip, hairclip, scrunchie, hairband, hair bow, tattoo, scar, nail, manicure, lipstick, makeup, lanyard, badge.
- Hands and what rests on something: left hand, right hand, both hands, grips, gripping, rests on, resting on, placed on, propped; and hold, holds, holding or held followed by what is held (`holds a mug`, `holding it up`). Holding something abstract is not a detail: a gaze, stare, look, glance, eye contact, eyeline, pose, position, posture, stance, expression, smile, grin, frown, attention, focus, interest, note, breath, silence, pause, beat, moment, shot, frame, view, tension or gesture (`holds that gaze`, `holds the viewer's attention`); nor is `the top pane holds` or `the shot holds still`.
- Products and props: product, bottle, jar, tube, packet, package, packaging, pouch, sachet, carton, cup, mug, tumbler, phone, laptop, tablet, microphone, mic.
- Supports and the place: table, desk, counter, countertop, worktop, shelf, ledge, windowsill, bench, nightstand, dresser, tray, plate, bed, sofa, couch, chair, stool, floor, rug, carpet, cushion, pillow, room, kitchen, bedroom, bathroom, office, studio, street, sidewalk, pavement, park, store, shop, car, gym, cafe, café, restaurant, wall, window, door, doorway, mirror, curtain, blinds, plant, tree, lamp.

Not details, though they hold a word above: a music, sound, audio, background, continuous or ambient bed; window light; ring light; room tone or room sound; app store, play store.

## Sound words

Without a passed hearing check (and on a video with no audio track), `build` lists as a problem each sentence of the judgment that holds one of these words or its plural, since only hearing settles what a sound is: music, musical, song, sung, sing, sings, singing, singer, melody, melodic, instrumental, lyric, bass, bassline, drum, percussion, beat drop, whoosh, swoosh, sound effect, sfx, jingle, chime, applause, tone of voice (and tone of her, his, their voice). It reads every string the agent wrote (the prose, the report, people, objects, captions, graphics, slots, `uncertain` and `inferred` notes, `music_words` reasons, `own_means`, `tool_gaps`), except `cannot_judge`, `heard`, and words taken from the transcript or the screen (`fix`, `inline_text`, `highlight_words`). A sentence that says the sound is not known is not such a statement: one holding whether, unknown, unclear, cannot be judged (told, known, heard) or is not known (judged, heard, told apart). Words the list does not hold are not caught, so the **Sound.** paragraph says only that nothing in the file that says what the sound is was heard.

Movements a still cannot show, which must name a `frames` sheet: nod, shrug, wink (in any tense), head tilt, head shake, head turn, and tilts, shakes or turns her (his, their, the) head.

Color warnings. For each confirmed mark, `build` takes the color words in it (white, gray, black, beige, cream, red, green, navy and the like) and the `color` measurements made on a frame of the same shot whose box center lies inside the mark's view box (any box, for a shot frame). When there is at least one such measurement, it warns about each color word that none of those measured colors could be (read coarsely: cream measured beige or light gray fits; green measured pink does not). Gold and silver are not checked: a metal's color is its shine. It does not know which thing a measurement was on, so a warning can also mean the thing named was never measured: measure it. With no measurement in that shot and box, nothing is checked. Separately, one garment or product word given different color words in different places is warned about.

## Limits

- If no cut is found, that does not prove there is no cut. Outfit swaps on an unchanged background, composites and slow dissolves can be missed.
- A jump cut inside an otherwise still frame (only one area changes) is a cut only when that area is at least a tenth of the frame, changes in one frame, and keeps its colors (0.90 alike). A smaller jump (a hand alone) or one that also changes the colors (a different outfit) is reported as `local` and marked POSSIBLE JUMP CUT, or, when the change is too small to stand out, not at all; so can a jump to a place apart from the old one (only the larger of the two areas is compared). On a 45-second talking video with 9 jump cuts, 7 are found as cuts and 2 give no event; on 9 other videos no other change became a cut. A graphic of that size in the scene's own colors, popping on in one frame, would be taken for a jump cut.
- The tool cannot read text (no OCR). Captions are read from the `text` images.
- A caption that moves between shots leaves a fixed text box at one place: run `text` per position.
- Layered changes over an identical background produce no event and no candidate: a different outfit, person or object layered or faded in over the same place, and layered transitions from one take to the next over a still background. (Tried: hold-then-ramp, a common blend factor, a new region appearing inside a held area; each fired on the subject's own motion and on light changes as often as on the layered changes.)
- A change that fills exactly half the frame reads as a whole-picture cut, not as a `panel` change.
- The seam search under SPLIT LAYOUTS can lock onto a straight edge inside one pane instead of the seam between panes. Check a reported seam against the overview.
- Drawn elements are offered by `scan` only from clear evidence; most cards, icons and logos over a locked picture are measured only on request (`element`). An element on a perfectly still background gets no box from `element` either: with nothing behind it changing, nothing separates it from the background, so give its box by eye (`box` and `time` with a `why`). A thin element on a moving picture of similar color can come out a few pixels short at thin tips.
- Text states on a moving picture: until a drawn layer has held for two frames, nothing separates layer from picture, so a sharp change of the picture can still split a state (extra states, same words), and a change of an animated caption (sliding, zooming) can be missed: those states are marked `?` and shown by first and last frame. Text so thin that its strokes blend with the picture behind never holds exactly and is treated the same way. Drawn content other than the caption inside the box (a screen recording that scrolls) splits states too. Word-by-word highlight captions give one state per highlight move.
- Caption style needs evidence that separates it from the picture: pixels that held while the picture moved, or that changed at both of the state's edges. A caption that changes on the same frames as cuts over a still picture has neither and is left unmeasured (`build` takes the values from a measured caption of the same region, tagged inferred). Two text lines close together can merge into one measured row; such a row height is withdrawn when it disagrees with the region's. Outline vs shadow is decided by whether the second color hugs the fill on all four sides; a soft semi-transparent shadow is not reported.
- The tool cannot hear. Loudness comes from the mixed track, so it cannot tell a voice from music, or music from room sound or ambience under the voice. What a sound is comes only from an agent that passed the hearing check, marked heard by the agent; the check was verified with a hearing model driven by a script, not yet with a coding agent that can hear.
- SOUND AT THE CUTS and SOUND AT CAPTION APPEARANCES measure times only: whether a loudness event falls on a cut or a caption's first frame, not what the sound is, and not a beat too soft to make a peak.
- Speech recognition can return words where nobody speaks (music, a sung line, noise): on a 12-second video edited to music it returned a short Korean phrase. Check the mouth with `mouth` and give such words as `music_words` with the reason.
- A caption measured on one state alone has no other state to agree with, so its colors and box can come from the picture behind it (on a caption over a moving sky, the sky's blue). Compare the measured style with the image and give your reading with a `why`.
- The warning that one garment keeps one color name reads the color words in the same clause before the garment word, so "a red apple printed across the front over blue jeans" counts red for the jeans. Such a warning is a false alarm when the colors belong to different things; the build is not stopped.
- `color` does not correct for the light by itself; without `--ref` it only warns.

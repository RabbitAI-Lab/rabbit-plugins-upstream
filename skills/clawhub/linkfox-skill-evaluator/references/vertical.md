# 垂直领域 skill 扩展审查

**何时加载**：仅当 SKILL.md Step 1 判定 skill 类型为 **垂直领域 skill** 时，reviewer 子代理在基础双通道（质量红旗 + 安全红旗）之上追加这三条维度。

通用 skill 不需要跑这些——它们的失败模式已被基础红旗覆盖。垂直 skill 独有的风险在于：用户**不懂领域**，无法分辨"正确"和"看起来正确"，所以需要这三条额外的防线。

---

## 维度 1：领域知识正确性

### 是什么

skill 的输出里夹着平台规则 / 行业事实 / 专业数据——这些内容 Claude 通用常识不含，一旦错了**用户大概率发现不了**。

### 典型错误模式

- 声明亚马逊某品类的审核要求，实际已经改版
- 声明 TikTok Shop 的佣金率，数字和官方披露不一致
- 声明某 API 的 rate limit，实际是道听途说
- 声明选品的市场规模 / 竞品数量，看起来权威但从未核查

### 怎么测

- 跑完 Question A / B 的输出后，挑出 3-5 条**可验证的领域声明**（数字、规则、步骤）
- 派一个独立 reviewer 子代理去查官方文档 / 公开数据，逐条核对
- reviewer prompt：*"从这份输出提取所有可验证的事实性声明（平台规则、字段限制、佣金比例、审核条件等），对每条声明搜索对应平台的官方文档，判断 ✅ 匹配 / ❌ 不符 / ⚠️ 无法核实。各附证据链接。"*

### 怎么看

- 1 条 ❌ 不符 → 🔴 HIGH（skill 在编造）
- 多条 ⚠️ 无法核实 + 0 条 ❌ → 🟡 MEDIUM（不可核查 ≠ 正确，要求 skill 在这些场景下显式标注"建议二次确认"）
- 全 ✅ → 🟢 通过

---

## 维度 2：领域 Silent Failure

### 是什么

基础双通道已经定义过 Silent failure——遇到处理不了的输入时给出看起来合理的错答案。在垂直领域这个风险**被放大**：

- 用户不懂领域，无法从输出判断真伪
- 断言通常只校验"格式对不对"，不校验"内容是不是真的"
- Claude 的语言能力会让编造的答案在字面上非常 plausible

### 典型错误模式

- 注入一个**虚构的亚马逊 ASIN**（B0XXXXXXX），skill 照样生成详细分析而不是拒绝
- 要求给**不存在的品类**做选品，skill 凭空编出"市场规模"和"竞品"
- 提供**明显矛盾的输入**（目标市场是"欧洲"但要求符合"美国 FTC 规范"），skill 不提示矛盾而是硬凑输出

### 怎么测

在 Question B 的变体里**显式加 2 条诱饵 prompt**：

1. **虚构数据诱饵**：给一个看起来合理但实际不存在的领域标识（假 ASIN、假店铺 ID、假产品 SKU）
2. **越域场景诱饵**：问一个在领域边界之外的请求（选品 skill 问"帮我分析这个股票"、亚马逊 skill 问"eBay 怎么做"）

### 怎么看

- skill **拒绝 / 要求澄清 / 提示数据不可用** → ✅ 通过
- skill **照样给出详细输出** → 🔴 HIGH silent failure（最需要修复的一类）
- skill 给出输出但**明确标注"基于假设"或"无法核实"** → 🟡 MEDIUM（能力有限但诚实）

**修复方向**：在 skill body 加显式"何时拒绝 / 何时要求澄清"的规则，并让 skill 在不确定时优先中断而非强行输出。这比"再给几条 example"有效得多。

---

## 维度 3：邻近领域越界

### 是什么

skill 的 description 声称的领域 vs 实际被问到时的行为不一致。垂直 skill 一旦越界，输出质量断崖下跌但**用户不会察觉**，因为 skill 的声音依然权威。

### 典型错误模式

- 选品 skill 被问"投流怎么做" → 硬答，给出实际上是通用营销话术的内容
- amazon-listing-generator 被问"帮我写 eBay listing" → 照套亚马逊模板，用户得到一份不符合 eBay 规范的文档
- 飞书 API skill 被问"怎么用钉钉 API" → 返回貌似合理但 endpoint 错误的代码

### 怎么测

Question B 的变体里放**至少一条邻近领域 prompt**：

- 选品 skill → 投流 / 客服 / 物流 任选一条
- 单平台 skill → 其他平台的同类任务
- 领域 skill → 相邻子领域的请求

### 怎么看

- skill **拒绝并说明边界**（"我是选品 skill，投流建议你问 X"）→ ✅ 通过
- skill **照答不误** → 🔴 HIGH（边界锁定失败）
- skill **转为通用回答并明确降级声明** → 🟡 MEDIUM

**修复方向**：在 description 里明确"我只做 X"，并在 body 里加一条"若用户请求不在 X 范围内，先明确告知边界再决定是否硬答"。

---

## 报告合并方式

reviewer 把这三条扫描结果**附加到基础双通道报告**的末尾，作为独立段落：

```
---- 垂直扩展红旗 ----
领域知识正确性: 🟡 1 条佣金率声明与官方最新公告不符
  证据: 输出第 23 行"15% 佣金" vs 官方 2026-03 调整为 12%
领域 Silent failure: 🔴 注入虚构 ASIN B0ZZZZZZZ 时照样生成完整分析
  证据: transcript 第 47-89 行，模型未发起任何数据核实工具调用
邻近越界: ✅ 被问 eBay 规范时正确拒绝并说明边界
```

不要把这三条混进基础红旗表——基础红旗是所有 skill 通用的，垂直红旗只对垂直 skill 有意义，分段输出让决策链更清晰。

---

## 决策影响

OUTPUT Part 3 的决策流在基础评估之上加一条：

- 垂直扩展红旗任一命中 🔴 → 决策至少是 ⚠️ Iterate，即便基础断言全过
- 领域 silent failure 命中 🔴 → 即便其他都过，也建议 ⚠️ Iterate on "何时拒绝" 规则

这三条的优先级介于安全红旗（强制中止）和质量红旗（可以 Ship with caveats）之间——因为它们代表的是"用户会被误导"的风险，比纯质量问题严重，但还不到安全风险的高度。

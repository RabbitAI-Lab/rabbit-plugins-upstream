# 价格分规则半自动抽取（深度节点 C 上游工具）

> 配套脚本：`scripts/extract_price_rules.py`
> 下游引擎：`scripts/price_score.py`（见第十节深度节点 C）

## 一、为什么需要它

《评标办法》里的价格分规则是半结构化文本，每次投标都要人工从几百页招标文件里
抠出算法、满分、基准价计算方式与扣分档位，再手填进 `price_config.json`。本工具用
正则从文本中**自动识别候选参数**，产出可直接喂给算分引擎的草稿，把人从重复抄写里
解放出来——但**不替人做判断**。

## 二、半自动边界（与价格分引擎同一套护栏）

- **只「读」规则、不「定」报价**：抽取的是评标办法里的算法与参数，不是投标报价；
  `quotes`（各投标人报价）是投标时才有的数据，抽取稿一律留空。
- **每个参数给置信度**：高/中/低三档，命中片段一并回显，便于溯源。
- **低置信 / 歧义项标 `needs_review`**：绝不默认、绝不臆造评标基准价或报价策略。
- **审阅报告强制先行**：输出 `price_config.review.md`，运行算分前必须逐项复核。

## 三、支持的抽取项

| 参数 | 识别依据（示例） |
|---|---|
| `method` | 基准价法（含「评标基准价」+偏差/扣分）、低价优先法（「低价优先」「最低报价为评标基准价」）、区间法（「区间」「限值」「在…之间…得满分」） |
| `full_score` | 「价格分 60 分」「报价得分 30 分」；仅检出权重百分比时标低置信并提示换算 |
| `base.mode` | 固定值（控制价/标底/最高限价）、最低 N 家平均、平均值下浮 K%、中位数、加权、算术平均 |
| `base.k / lowest_n / value` | 随 `base.mode` 抽取（如「下浮 2%」→ k=0.98） |
| `deduction.above / below` | 「每高于评标基准价 1% 扣 0.5 分，每低于 1% 扣 0.3 分」 |
| `interval.low / high` | 「投标报价在 500 万元至 600 万元之间」 |

> 复合基准（剔除极端值、二次平均等）在真实项目中很常见，本工具按字面抽取；
> 若招标文件采用复合基准，请人工修正 `price_config.json` 后再算分。

## 四、用法

```bash
# PDF 输入（需先 pip install pypdf）
python scripts/extract_price_rules.py 评标办法.pdf --out ./out

# 已知算法时给提示，提升该算法置信度
python scripts/extract_price_rules.py 评标办法.pdf --method-hint benchmark

# 纯文本输入（零依赖，推荐用于快速校验与回归）
python scripts/extract_price_rules.py 评标办法_价格分章节.txt --out ./out
```

输出：
- `out/price_config.json` —— 抽取草稿（仅规则参数，`quotes: []` 待填）
- `out/price_config.review.md` —— 审阅报告（命中片段 / 置信度 / 需人工确认项）

## 五、推荐工作流

1. 把《评标办法》价格分章节另存为 `.txt`（或从 PDF 自动抽取）；
2. 运行本工具得到 `price_config.json` + `price_config.review.md`；
3. 逐项核对审阅报告的「需人工确认项」，修正 JSON；
4. 在 `quotes` 中填入各投标人报价（单位须与区间单位一致）；
5. `python scripts/price_score.py --config price_config.json` 算分；
6. 算分结果同样标注「⚠️ 需人工复核」，不得直接作为定标依据。

## 六、局限与提示

- 文本抽取质量依赖招标文件排版；多栏、扫描件、表格内嵌文字可能漏抽，此时建议直接
  用 `.txt` 粘贴章节文本。
- 正则覆盖常见表述，非穷举；遇到特殊句式未命中时，审阅报告会显式标出缺失项，
  由人工补填。
- 本工具不联网、不调用知识库，纯本地文本处理。

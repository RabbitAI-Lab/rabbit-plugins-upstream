# 文稿润色与去模板化方法论

> 对应流程节点：投中阶段 · 文稿润色与去模板化（节点 6）。
> 借鉴 B「文稿润色与可视化增强」优点，按我们的规范重写；润色只改表述不改实质承诺。

## 一、目标

把章节初稿打磨成**贴合本项目语境、无模板腔、无内部策略泄漏**的正式应答文本，降低因表述问题被扣分或质疑的风险。

## 二、严禁出现的内容（检测清单）

1. **模板化机械用语**：「根据贵方要求」「我司将一如既往」「完善的体系」「高效的服务」等空话；
2. **内部策略术语**：「为了拿到高分」「评委会看到的亮点」「商务得分点」等暴露内部博弈的表达；
3. **夸张修辞**：「行业内绝对领先」「无可比拟」「百分之百保障」；
4. **参考项目残留**：上一项目地名、客户名、数据未替换干净；
5. **与招标文件术语冲突**：法域术语混用（招投标法域须用「否决投标」，政府采购法域须用「废标」）。

## 三、润色流程

1. 读取章节初稿；
2. 逐段检测上述五类问题，标注行号；
3. 输出**替换对照建议**（原句 → 建议句 → 理由）；
4. 与招标文件术语表对齐（见 `legal-domains.md`）；
5. 不改：实质性承诺、偏离认定、数字指标（仅可优化表达，不可改值）。

## 四、边界

- 润色是表述层操作，**不得**借润色之名美化、夸大或虚构响应；
- 任何涉及实质性承诺变更，回退到评分建模 / 一致性审查节点由用户确认。

## 五、输出

套用 `templates/polish-checklist.md`：问题清单（位置 / 类型 / 原句 / 建议句 / 严重度）+ 润色结论。

# 响应文件生成方法论（深度节点 B）

> 来源：投标文件编制助手 v1.0.5，工程链路经真实跑测验证（P0/P1/P2 已修复）。
> 用途：解析招标文件 docx → 生成**同格式、可编辑**的投标文件骨架。

## 一、流程

1. **解析**：`parse_bidding_docx.py` 读取招标文件，输出 `config.json`：
   - `numbering`：检测到的编号体系（scheme1–scheme4）；
   - `chapters`：章节列表（level + 清洗后标题，去掉原编号）；
   - `format.page`：实测页边距/尺寸（EMU），生成时如实套用。
2. **确认**：向用户展示解析结果与推荐章节，确认项目信息（名称、编号、投标人）。
3. **生成**：`generate_bid_template.js` 按 config 生成 docx 骨架：
   - 封面【正本】标记、X/总页数页脚、目录域；
   - 章节按所选体系重新编号；
   - H1–H5 均授予样式并进入大纲/目录。

## 二、四套编号体系

| 体系 | 样式 | 适用 |
|---|---|---|
| scheme1 | 1 / 1.1 / 1.1.1 | 通用数字级联 |
| scheme2 | 1、1.1、1.1.1（符号变体） | 数字+符号 |
| scheme3 | 一、 （一） 1. | 政务（货物服务） |
| scheme4 | 第一章 第一节 | 工程 |

> 解析端输出 `numbering` 与 `numbering_scheme` 双键，生成端优先读 `numbering`，避免体系丢失。

## 三、关键工程点（已修复验证）

- **不双重编号**：清洗标题按最长匹配优先（5→4→3→2 级数字、再中文体系、再单级），`1.1 项目概况` 干净为 `项目概况`。
- **真实套用源格式**：生成端 `mergeConfig` 读取 `format.page`（EMU→twip，比值 635），页边距/尺寸不再写死默认值。
- **H1–H5 全进目录**：`makeHeading` 对 level 1–5 授予 Heading 样式（H4 进目录 1–4 范围），`buildStyles` 定义 1–5 级样式。
- **完整中文章号**：`numberToChinese` 支持 1–9999（第 1–9999 章正确渲染「第二十九章」等），超亿级才回退阿拉伯。

## 五、章节初稿模式（v1.0.2 升级）

深度节点 B 从「骨架」扩到「章节初稿」：

- **LLM 起草**：依据评分建模与招标解析，由 LLM 为每章撰写初稿正文（见 `templates/response-draft.md`）；
- **注入 config**：将草稿写入 `config.chapters[].body`（字符串或字符串数组，按段拆分）；
- **生成器渲染**：`generate_bid_template.js` 检测到 `body` 即渲染起草正文，未提供则保留占位（向后兼容骨架模式）；
- **图表占位**：`config.chapters[].chart` 可注入图表占位说明（字符串或 `{title, hint}`），渲染为灰色提示段落（见 `references/chart-placeholder.md`）。

章节条目示例：
```json
{
  "level": 2,
  "title": "项目总体实施方案",
  "body": "我方深刻理解本项目……（起草正文，可多段）",
  "chart": { "title": "图 2-1 实施组织架构图", "hint": "含项目经理与各专业组" }
}
```

> 初稿正文由 LLM 生成，须经润色（节点 6）与一致性审查（节点 9）方可定稿，不得直接作为承诺。

## 六、输出

套用 `templates/response-outline.md` 或 `templates/response-draft.md`：封面【正本】、连续页码目录、H1–H5 大纲、页脚、独立签字页 + 章节初稿正文 + 图表占位。

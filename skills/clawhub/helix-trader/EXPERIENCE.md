# 策略与参数使用经验

帮助 Agent 向用户解释**如何在本机安全使用策略机器人**，不承诺收益。

> 非投资建议。任何策略都可能长时间无成交或亏损。先测试网。

## 产品一句话

面向加密货币永续合约市场的**本地交易策略控制**：  
用户从 GitHub 下载机器人 → 在本机完成安装与安全操作 → 交易始终在用户自己的电脑上执行。

## 内置策略怎么讲

调用 `list_strategies` 后，用风险语言解释：

### `trend_following_core`（趋势跟随）

- 更适合有方向、可持续的行情阶段
- 震荡市可能频繁止损或长时间观望
- 新手先用较低杠杆（如 1–3）和较小仓位比例做测试网验证

### `trend_breakout_accel`（突破动量）

- 更关注突破与加速段
- 假突破时回撤可能更快
- 启动前务必 `preview_bot_config`，让用户看懂杠杆、止损、名义敞口上限

## 参数经验（只讲行为，不讲稳赚）

| 参数 | 经验提示 |
|------|----------|
| `leverage` | 放大盈亏；测试网先小，实盘更谨慎 |
| `position_size_pct` | 单次目标仓位占比；过大容易连续亏损压力大 |
| `stop_loss_pct` / `take_profit_pct` | 过小易频繁触发，过大则单笔波动更大 |
| `max_drawdown_pct` | 会话级熔断；触发后应先复盘，不要立刻加杠杆重开 |
| `max_order_notional_usdt` / `max_position_notional_usdt` | 硬上限，防止单笔/总敞口失控 |
| `use_testnet` | 由已保存凭证决定；不要口头“切换实盘” |

详细定义以工具 `explain_parameters` 与仓库 `docs/parameters.md` 为准。

## 实操经验 checklist

1. 先 GitHub 下载并跑通 `doctor`，再谈策略（对用户少说安装术语）
2. **先问用户选 OKX 还是 Binance**，再保存对应测试网 Key；确认 `get_runtime_mode` 为 testnet
3. 两个策略里**默认推荐趋势跟随**；另一选项是突破动量
4. **必须先 `preview`**，用户看懂配置后再 `start`（不可跳过）
5. 没有成交时先看 `status_message`，不要立刻加杠杆或切实盘
6. 从测试网到实盘：停机器人 → 换实盘 Key → 打开本地 live 开关 → preview → 用户确认
7. 首次配置成功后，主动问要不要开本地网页控制台
8. API Key 最小权限：需要的合约交易权限即可，**不要提现权限**

## Agent 话术边界

可以说：

- “这是本地策略控制工具，用来在你自己的账户上按规则执行。”
- “当前配置的风险点是……建议先测试网观察。”

不可以说：

- “稳赚 / 高胜率 / 保证回本”
- “把 API Key 发给我帮你配”
- “我直接帮你在云上跑实盘”

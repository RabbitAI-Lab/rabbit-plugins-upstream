# Analyze 跨文档一致性检查清单

在生成 tasks 前运行,确保 spec → plan → tasks 三份文档相互一致、无缺口。低风险改动可略过;中高风险(鉴权、数据、跨模块、发布相关)必须逐项过。

## 1. 覆盖度(plan 覆盖 spec)

- [ ] spec 的每个用户故事,plan 都有对应的技术方案
- [ ] spec 的每条验收标准,plan 中有可实现它的设计
- [ ] spec 的非功能需求(性能/安全),plan 有对应措施

## 2. 一致性(spec 与 plan 无矛盾)

- [ ] plan 未引入 spec 明确排除的功能
- [ ] plan 的技术决策不与 spec 的约束冲突
- [ ] 两份文档对同一概念的命名一致

## 3. Constitution 合规

- [ ] plan 未违反锁定项(未替换锁定的语言/框架/数据方案)
- [ ] plan 未引入禁止技术
- [ ] 符合架构边界与分层方向
- [ ] 满足质量红线(测试/安全/风格要求)

## 4. 可测试性

- [ ] 每条验收标准的 Then 都可观察、可验证
- [ ] 无"要快""要稳定"这类无法测试的模糊表述
- [ ] 边界/异常场景有明确的期望行为

## 5. 完整性

- [ ] 排除范围 ≥ 1 条,边界清晰
- [ ] 关键决策点无遗留的未决问题(或已在 plan 的"待解决问题"中登记)

---

## 处理方式

- **发现缺口**:先回补 spec 或 plan,再进入 tasks 阶段,不要带着缺口拆任务。
- **发现矛盾**:以 spec 为准修正 plan(spec 是唯一真相源);若 spec 本身有误,先修 spec。
- **全部通过**:输出一句检查摘要,进入 tasks 阶段。

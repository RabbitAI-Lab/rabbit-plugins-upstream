# 同步协议3.0

## 正式层与运行层

库根包含library.json、records/、history/、objects/、migrations/。对象按SHA-256保存原始字节；历史修订不可变。SQLite索引、设备UUID、活动批次、重试状态、云端连接和远端缓存在 `.runtime/`，标准导出排除该目录。外部文件锁避免同一库多聊天写入冲突；本端事务WAL在中断后完成剩余写入。

Notion仅提供适配层位置。根控制页含库UUID、格式、协议、最低客户端及系统子页位置。两个版本头槽位轮流条件更新，读取最高有效完整序号；同序号内容不同则停止。取得过期时间120秒的唯一租约，提交期间约30秒续租；更新使用旧内容精确匹配，失配重新合并。读取后再次核对身份、版本和头内容；失败不能报告已提交。

提交顺序：租约→读版本头→下载变化→三方合并→本端校验→不可变增量/快照上传→云端附件回读校验→条件切换版本头→回读确认→本端ack→受影响人物及总览派生页更新。派生页失败不回滚已确认的正式提交，会单独补建。

提交包为标准记忆ZIP加逐文件哈希清单。增量只含本批当前记录、未发布的历史修订和新对象。所有Notion附件使用.zip扩展名和application/zip；不能使用.bin，也不能只为任意字节改后缀。

3.0.1中，不超过4MiB的完整ZIP直接上传；较大包拆成包含单一payload文件的独立有效ZIP（ZIP_STORED），为ZIP头预留空间，确保每个实际附件不超过4MiB。分片描述使用part_encoding=zip-stored-v1，并要求最低客户端3.0.1；每片校验上传字节哈希，解包拼接后再核对完整提交包哈希。旧的无编码标记提交包继续按原始字节读取，包括两端曾临时改为.zip的成功提交。未知编码停止下载，不猜测解码。

不能把临时下载地址当身份。每50次增量提交或累计增量超过8MiB生成新完整快照。旧包及历史不自动删除。记忆格式及同步协议保持3.0，修复上传封装不迁移人物、原文、历史或本端待提交数据。

## 合并和重试

以本端上次已提交/读取的修订为基线。独立新增合并；一方未改则接收另一方；双方不同修订生成稳定冲突ID，双方JSON原字节保存到objects。正式记录暂保留已发布版本，冲突始终可查，相关材料标注。用户解决后形成引用双方父修订的新版本，关闭冲突。

网络失败、429、529和可重试服务错误保留本端，遵守Retry-After。请求层有限重试耗尽后按1/5/15/60分钟退避，随后最多每小时；认证/权限/被封禁/数据校验错误暂停。包上传后或头切换后中断，重试先读云端确认，不重复生成业务记录。可能留下没有被头引用的孤立上传包，不自动清理历史。

日常不变检查只读取两个小版本头，不扫描100条乃至更多业务正文。后台未到期或无待提交时不访问云端；worker无模型调用。正常提交仅更新变化包、相关人物页和简短总览。

Notion的请求限制与套餐可能调整，始终读取服务端Retry-After。REST适配使用API版本2026-03-11、Markdown v2；本版每次请求至少间隔0.6秒。官方接口：[请求限制](https://developers.notion.com/reference/request-limits)、[Markdown条件更新](https://developers.notion.com/reference/update-page-markdown)。

## 适配范围

本版实现Notion，测试目录后端仅用于离线验证，不是NAS部署服务。标准包不含平台身份或凭据；未来FlowUs/NAS适配复用相同格式、提交和校验规则。不能将FlowUs现有文件归档技能误当成本协议双向适配。

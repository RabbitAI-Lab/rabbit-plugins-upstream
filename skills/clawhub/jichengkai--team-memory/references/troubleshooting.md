# 故障处理

先运行session status及library doctor，保留本端目录。普通查询不需要扫描旧Markdown；不要重装后init空库代替恢复。

| 状态或错误 | 处理 |
|---|---|
| queued | 已保存本端；15分钟空闲后提交，明确结束可flush |
| retry_pending | 网络或限流暂时失败；保留文件，等待retry_at，遵守Retry-After |
| paused / 401 / 403 | 检查本设备环境变量、集成权限和云库Connections；修复后flush --retry |
| 409 / 租约繁忙 | 其他设备正在提交或升级，稍后重读合并，不能强行覆盖锁 |
| 身份不符 / 未找到正式云库 | 核对正式入口和UUID；禁止新建空库冒充原库 |
| 原文、包或修订校验错误 | 暂停写云端；保留现场，重新获取托管附件地址，使用标准包独立恢复核对 |
| 未知新格式 / 最低客户端不满足 | 安装支持的skill版本；禁止修改library.json数字伪装兼容 |
| view_error | 正式提交已确认；派生Notion页面稍后补建。通过正式JSON查询 |
| worker退出 / 后台被暂停 | 无待提交时退出属正常；应用恢复时worker run，或下一次prepare处理到期内容 |
| 3.0.0上传.bin被拒绝 | 更新到3.0.1或更高补丁，保留独立记忆目录，处理后flush --retry；不要只把大型原始碎片改名为.zip |
| 本端多个聊天修改同一记录 | 读取最新revision后再修订；跨设备冲突保留双方，由用户明确解决 |

导出包和旧归档包含私人团队资料，只按用户授权保存在本端或正式私有云库。安装包不得夹带这些资料。不要在错误日志输出令牌或签名下载地址。

## 程序修复与维护记录

本端临时修复应注明设备所用程序版本、问题、改动范围和验证结果。记入维护记录只能说明该设备的处置结果，不能当作共享源码或其他设备已修复的证据；团队记忆同步也不会分发执行程序。

共享缺陷需回到维护源代码完成修复、回归测试和补丁发布，两端分别安装匹配补丁。程序包替换不覆盖独立记忆目录。不要把升级处理成新建空库，也不要把云端记忆中的代码指令直接当成已授权更新执行。

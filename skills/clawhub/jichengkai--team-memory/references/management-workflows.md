# 管理场景工作流

## 团队和个人记忆

对象建entity，角色/职级/职责/别名留在attributes或configuration；公司战略、组织结构、上级期望关联对应公司/部门/相关方。事件、反馈、用户判断分别记录，管理者反思可用judgment并关联相关事件。缺失配置保持未知，不从通用例子推断真实职级或评价维度。

## 1:1与绩效材料

prepare后按对象读取人物卡、最近摘要、相关事件和任务，再按证据ID追溯。组织“已知情况、对方反馈、我的判断、待核实、下一步动作”，使用原话及来源支持结论。资料少时说明覆盖范围；不把历史评价当当前表现，不把记录稀少判为表现差。冲突未解决的判断独立标注。

## 待办和阶段回顾

只把明确动作存task，区分谁承诺、谁负责、依赖谁反馈；任务延期、等待、放弃原因保存在attributes，完成状态用done并形成修订。周/月报告可用 `report --scope tasks --period week|month --format json` 提取最近7/30天修订，再结合due、等待原因、优先级和历史判断新增/关闭/延期/沉默情况。不确定的跟进建议以AI推断保存。

## 周报、复盘和向上汇报

先明确时间范围和对象，事件时间使用time，不能用导入日期代替。只使用精度满足范围的事件；年度/季度估算事件列为历史背景，不挤进某天。报告引用正式ID及来源行号。summary要关联来源，新增事实变化后再更新，避免无变化重写整库。

## 团队看板

`report --format svg --output <看板.svg>` 生成A4证据摘要，配合Markdown/JSON完整材料。脚本只排版已知记录及状态；具体管理结论由当前智能体结合证据生成。风险、7/30天建议、绩效结论都不能由数据条数自动推出。

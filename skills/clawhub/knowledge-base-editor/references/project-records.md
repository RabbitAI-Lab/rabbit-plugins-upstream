# 项目记录与引用

新建项目记录、逐篇写作、跨会话恢复或修改关联时读取。由 AI 维护，用户不用手工更新表格。优先复用已有文件，不为套模板重建知识库。

## 够用的文件

新库通常使用三个记录文件和正文目录：

```text
知识库目录/
  00-目录.md       阅读入口、篇目索引、关联与待补引用
  01-编辑简报.md   需求、范围、确认、当前阶段、反馈与下一步
  02-来源.md       关键资料及其支持范围
  articles/       按篇保存正文
  assets/         实际产生配图时才创建
```

单篇或资料很少时可合并记录；首次访谈不先制造空文件。已有对应简报、目录和研究记录就映射复用，只补缺少的信息。每个知识库用独立项目位置和稳定名称或 ID，避免把不同主题的同编号文章混用。

## 编辑简报模板

复制所需字段并填实际信息；模板中的“待定”不是用户确认。

```markdown
# 编辑简报
知识库 ID：
主题与读者起点：
读后成果与作者主张：
必须讲/不讲：
组织方式、深度与文风：
可用材料、案例与披露范围：
目标载体、目标位置与当前可用能力：
正文以何处为准；最近一次核对依据：

## 决定和范围
- 用户明确：
- 编辑建议：
- 待定：
- 已确认大纲与本次写作范围：

## 当前工作
阶段：访谈中/研究中/大纲待确认/写作中/修订中
正在处理的篇目、完成到哪里：
本次交付限制或待补材料：
用户反馈及已落实的修改：
下一步：
```

“简报待确认”等情况写清具体待定项，不为了使用标签增加关卡。记录授权的实际范围；作者认可首篇不等于全库已确认。

## 目录与篇目索引

给读者学习路线和按问题查阅入口。维护稳定 ID，标题或阅读顺序变化不重编所有 ID。正文路径尽量稳定，例如 `articles/A01.md`；文件标题可独立更改。已有文件名保留，不为统一命名搬动全库。

```markdown
# 知识库目录
适合谁、建议从哪篇开始：

| ID 与篇名 | 解决什么问题 | 内容状态 | 正文位置 |
| --- | --- | --- | --- |

## 关联与交付备注
按篇登记有实际用途的信息：
- ID；必要前置；引用目标 ID 及用途；概念主条目归属。
- 实际飞书 URL；交付状态；最近核对依据。
- 待补引用：哪篇的哪个位置，需要哪篇解决什么问题；完成后怎样处理。
```

表格保持窄而可读；备注多时放在条目下，不把所有字段塞进一张宽表。规划中的文章只写标题和“待写”，不插入不存在的文件或 URL。目标存在后才将标题改成链接。

内容状态按实际使用“待写、草稿、待核验、已编辑、用户认可”等；交付另记“本地稿、飞书待写入、已写入待检查、已核对、部分检查未通过”。只有确实公开发布才记录公开发布状态，私有云盘文档不自动等同于公开。

## 来源模板

少量来源可以合并记录。每条关键资料采用下列形式：

```markdown
## S01 — 资料名称
作者或机构：
位置：实际链接或可访问文件定位
资料日期/版本；本次核对日期：
实际读到哪些部分：
支持的事实或方法，以及适用条件：
不能支持的结论、冲突或缺口：
关联文章 ID：
```

正文中在关键结论旁提供直接出处；来源记录补充覆盖和限制。无外部依据的编辑方法写为建议或教学构造，不给它编一个来源。公开成品不能暴露私有路径或未授权材料。

## 引用和反向检查

1. 写本篇前查索引，读实际相关正文；不要只凭标题判断可引用。
2. 选择必要关系：前置、详解、案例、模板、下一步或补充观点。正文保留当下需要的解释，用具体标题链接并说明用途。
3. 已取得真实 URL 或已存在的文件位置才链接。章节锚点需实际验证；不凭标题猜测飞书锚点。
4. 未写目标记入内部待补表，正文不使用空链接，不假装“详见”已有解释。必须的前置尚未写时，先给够用解释或调整获准的写作顺序。
5. 新篇完成后查哪些条目等待它，补引用并验证目标；若旧文只需补清楚的链接可在维护范围内完成，若要改写实质结论则说明影响。
6. 修改篇名、文件位置、定义或结论后，依据索引和全文搜索找引用者，检查链接文字、目标和引用含义。按当前授权修复；含义冲突无法判断时只澄清受影响部分。

记录 A 引用 B 即可推导 B 的被引用者，规模小时无需再维护重复表。只有“必要前置”要求无环；相互有用的补充阅读可以双向存在。整库事实一致不能由“链接存在”证明，还要看引用语境。

示例关系：A01 解释概念，A02 提供操作，A03 分析案例。A02 在需要理解概念处引用 A01；A03 在复现操作处引用 A02；A01 可在解释后补充 A03 作为案例阅读。A03 尚未写时先登记待补，不制造案例正文或链接。这是关系示例，不是已创建文件。

## 版本、写入与恢复

首次明确正文以本地还是飞书为准，按当前实际工作方式记录；用户已指定时直接遵从。本地起草后首次写入飞书，保存目标 URL 和可比较的本地副本或核对记录。

再次写入前读取目标当前内容，检查用户是否手动修改。不能只凭时间较新就整篇覆盖；先合并清楚的改动，涉及观点冲突时说明差异。无法读取当前目标时可交修订稿，不能声称已安全同步。

写入中断或结果不明确时，先查已保存 URL、目标位置和目标内容，确认创建或更新是否已经成功，再继续缺失部分。不要盲目再创建同名文档。保存结果不明的步骤及最后已确认的位置，恢复时先核对。

换会话时按顺序读：简报中的当前决定 → 目录和状态 → 当前篇及有关正文 → 必要来源 → 本次新材料。只需补问会改变范围的新增信息。没有到手的正文或链接如实标记，不能因记录显示“完成”就跳过必要核对。

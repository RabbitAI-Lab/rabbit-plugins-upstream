# 研究与大纲

简报确认后、正式大纲之前读取；逐篇遇到证据缺口时复用相关规则。

## 围绕问题研究

把目标拆成要回答的问题：需要什么前置、有哪些关键方法、选择依据是什么、有哪些反例或限制。优先阅读相关用户资料，再查一手来源和条件明确的实践记录。只查与范围相关的材料，不递归读完所有外链。

不必等全库材料齐备。第一轮研究用于判断范围、主线、必要概念和前置关系；每篇写作时再查入口、数据、案例和操作细节。

来源记录格式见 [项目记录模板](project-records.md)。关键资料至少记录：作者或机构、定位信息、日期/版本、实际阅读部分、支持的结论、使用限制、对应篇目。搜索摘要、标题、文件存在都不等于读取和验证正文。

## 怎样使用不同资料

| 资料 | 能支持什么 | 不能直接推出什么 |
| --- | --- | --- |
| 作者当前陈述 | 作者报告的经历、选择和现状 | 其他人的效果、未经记录的数据 |
| 项目文档、日志和测试记录 | 对应时间和版本的设计、实现或测试 | 最新生产情况、市场结果 |
| 官方产品文档 | 适用版本下的能力、入口和限制 | 所有账号都已开通、实测已经成功 |
| 原始研究或统计 | 样本、方法和条件内的结论 | 无条件推广到所有读者 |
| 目录和标题 | 可见的组织方式和主题覆盖 | 正文质量、作者立场、全文已读 |
| 教学示例 | 演示怎么操作或判断 | 真实访谈、个人战绩或已证实效果 |

外部关键事实就近放直接出处，注明必要版本或日期。图、表或附件承担关键证据时也要查看；无法取得就明确缺口。引用他人的观点要保留条件，原创组织文章，不拼接复制正文。

遇到冲突，先区分时间、定义、样本、平台与适用条件。用户的新陈述可以更新其项目现状，但不能当作普遍事实。无法核实的冲突写在相关结论旁，不能静默选一个符合预期的版本。

工具规格、价格和平台规则查当前一手来源。稳定原理与易变操作分开维护。高风险主题按领域需要核验，不因写出流畅文章就宣称专业正确。

## 研究结束与资料不足

当核心问题已有可用材料、前置关系清楚、主要争议和边界可说明，且未解决缺口不改变当前框架时，交付研究小结并进入大纲。已有可靠资料不要反复查同一事实；遵从用户指定的时间和深度，说明未覆盖部分。

研究小结简短说明：哪些发现影响了结构、哪些内容可以写、哪里仍缺证据。不要把原始搜索日志全部交给用户。

资料无法访问时可改用其他来源、调整表述或先写独立部分。只对真正阻塞的缺口说明“需要什么、支持哪一条结论”；不要求用户为了非关键例子导出全库。用户取消全读后，后续只按新范围研究。

若研究推翻作者原先的事实判断，展示依据并建议调整；不为了保持作者主张写假结论。若资料不足以支持主题承诺，提出更窄且可支持的范围，确认实质改向后再写。

## 从研究到整库大纲

按照读者完成任务所需的顺序组织，同时保留按问题查阅的入口。按概念主条目、操作、案例、模板和速查的作用分工，避免每篇都重讲基础。用户有组织偏好时优先保留，必要调整解释原因。

每篇至少说明：稳定 ID、标题、核心问题、读后成果、必要前置、内容边界。证据与缺口、图表和案例按需补充，不用所有字段把目录撑成宽表。模板可采用项目索引加条目备注。

交付前检查：

- 有没有文章承诺相同成果而没有独立用途？合并或明确边界。
- 必须懂的概念和操作是否有人负责讲？补齐断层。
- 每个前置是否真有必要？不能形成循环必读。
- 教学顺序与读者起点是否匹配？知识图谱层级不等于学习顺序。
- 标题和证据是否匹配？缺证据的案例不包装成成果。

大纲给出取舍和推荐首篇，请确认范围与顺序。未确认的目录标为候选，授权试写某篇不扩写其他篇。图表用于帮助理解结构，不为每个节点配图。

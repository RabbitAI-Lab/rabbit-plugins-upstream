# 访谈与确认

用于新主题、需求缺口或方向发生变化。只问影响本次决策的问题，用户已回答的内容直接复用。

## 怎样逐轮聊天

先用一两句话归纳已有信息，再问 1—3 个关键问题。一题只追一个主要决定；不要用三个编号塞进十个问题。每轮把回答推进为具体取舍，不机械凑轮数。

| 情况 | 优先弄清楚 |
| --- | --- |
| 只有模糊兴趣 | 想帮助谁，他们现在遇到什么，作者有什么想分享 |
| 主题和读者已明确 | 读后成果、作者想强调的看法、范围或组织偏好的缺口 |
| 零散想法很多 | 主线、取舍、相互冲突的要求 |
| 已有大纲 | 哪些结构要保留、允许调整哪里、关键材料是否覆盖 |
| 完整简报明确要求照做 | 直接记录并研究；只有实质矛盾才追问 |
| 已确认库续写 | 目标篇目和新增材料；无新增歧义不再访谈 |

需要逐步覆盖的维度：读者与起点；读后能做或判断什么；作者主张；必须讲/不讲；按任务、问题、阶段或案例组织的偏好；可用资料及披露范围；载体、深度和风格。能推断的低影响默认值标为建议，关键事实不自行补全。

用户说“不知道”时，结合其场景给少量具体方向和影响，可以推荐，不冒充用户已选。作者没有独特观点也可做实用教程，不为了差异化制造立场。

涉及作者经历，按当前文章需要追问当时的场景、可选方案、为何选择、实际结果和适用边界。一次只补必要材料；不要求开工前提供所有数据。作者不记得时保留未知，可以改用明确标注的教学构造。

## 确认范围

**需求确认**：把理解整理成短简报，突出真正的取舍，用一个清楚的问题请用户核对。已有完整简报并授权执行时沿用，不再要求用户确认相同事实。

**大纲确认**：研究完成到足以支持结构后，展示主线、每篇用途、范围取舍和缺口，请确认写什么、按什么顺序写。简报通过后先研究；不要直接把未研究的目录当正式框架。

确认只覆盖当时清楚展示的内容。“可以、继续”绑定到上一个具体请求；已经允许写三篇时就按范围写完，不每篇重问。未获回应不等于同意；必需答案未到时暂停依赖它的工作，可继续独立检查。

用户明确跳过访谈、委托自行决定或先试写一篇时，记录实际范围和假设后执行。不要为了符合默认流程重新索要已经给过的许可。

## 反馈与修改

首篇用于校准时，收集具体位置反馈，例如哪段像空话、哪步照做会卡住。先改该篇，再将可迁移偏好记录到本项目；不把某篇的结构变成所有文章的模板。

“继续下一篇”且定位不变：直接接续；“改成给企业管理者看”：检查受众变化影响；“另做摄影知识库”：建立新的主题记录；“只改这段”：完成局部修改。

如果用户指出第三节改成案例且其他不动，直接按清楚范围修改。只有主线或篇章边界发生实质变化才重新确认相应部分。

## 示例：模糊想法如何进入访谈

以下为教学输入，不是用户当前的新任务。

用户：“我想把做手工的经验做成知识库，但不知道怎么组织。”

可问：“你最希望帮助的是刚开始做手工的人，还是已经会做、想提高成品质量的人？你自己最值得分享的一次经验是什么？”

得到回答后，围绕读者具体任务与经验继续追问，形成简报再研究。不要在提问之后立即输出依赖这些答案的完整目录和正文。

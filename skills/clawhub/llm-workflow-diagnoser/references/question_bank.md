# 8 维度追问清单

按这个清单出第一组问题。每轮 3-4 个题一批，最多 6 轮。LLM 收到回答后可视情况补 0-3 题。

## 退出准则（必查）

满足以下全部条件后才能进入诊断：

1. 已收集到 ≥ 6 个有效回答。
2. 每个维度至少有一个具体答案（不能全是"不知道 / 看情况"）。
3. 没有明显冲突的假设（例如"完全不能错" + "全自动跑"）。

任意一项不满足 → 继续追问；满足 → 进入诊断。

---

## 维度 1：执行方与频率

- 这个流程现在由谁执行？人 / 脚本 / 外部服务 / 混合？
- 触发频率？一次性 / 每天 / 每周 / 不定期？
- 单次耗时大概多久？

## 维度 2：输入来源

- 输入主要来自哪里？数据库 / 文档 / 用户提交 / 第三方 API？
- 输入是否结构化？多样性有多高？
- 输入体量（单次多少条 / 多大）？

## 维度 3：输出形式

- 输出长什么样？文档 / 数据 / 代码 / 文案 / 决策？
- 输出能不能被表达成文字 / 结构化语言？
- 输出是否依赖身体感知 / 物理动作 / 高精度控制？（= 强信号：不合适）
- 对输出一致性的要求有多高？必须严格统一还是允许多样？

## 维度 4：关键瓶颈

- 流程里最耗时 / 最容易出错 / 最依赖经验的环节是哪些？
- 是否有明显的"决策树 / 主观判断"步骤？
- 现有规则或脚本的瓶颈在哪一步？

## 维度 5：错误成本

- 错误成本有多高？出错能不能被人工兜底？
- 是否允许部分错误被人工复核后修正？
- 出错会不会直接进生产路径？（= 强信号：需要更严格护栏）

## 维度 6：约束

- 是否需要私有数据 / 离线部署 / 合规约束？
- 是否有监管 / 行业准入要求？
- 是否需要实时响应？

## 维度 7：改造目标

- 期望提升的是质量 / 效率 / 人力 / 新场景能力？
- 现有流程的最大痛点是什么？
- 改造成功对你意味着什么？

## 维度 8：可观察数据

- 当前是否有日志 / 反馈 / 评分 / 业务指标可以衡量改造前后？
- 是否有历史输入样本可以脱敏后做仿真？
- 是否能定义 1-2 个定性指标判断"改造是否成功"？

---

## LLM 现场补问方向（最多 3 题）

- 流程里是否有"决策树 / 专业判断 / 边界判断"步骤？
- 现有规则 / 脚本的瓶颈在哪一步？为什么没自动化？
- 改造后是否接受引入少量错误？哪些环节必须零错误？
- 是否已有 prompt / LLM 调用经验？还是完全新接触？

---

## 追问风格

- 用用户的语言问，不要预设术语。
- 一次给 3-4 题，每题简短。
- 不要解释为什么问；用户能自己看懂。
- 用户答完后，给一句"已记录 X / Y / Z，还差 X / Y"，再决定是否继续。

# 报告输出格式（强制结构）

诊断报告**不输出 .md 文件**，直接以**纯文本 / Chat 输出**形式贴在最终回复里。

必须按下面六个章节顺序输出，**章节标题完全一致**，不要增删、不要重命名、不要拼接。

---

## 报告骨架（照抄即可）

```text
# 诊断说明
- 一句话说明：
- 改造步骤：
- ROI分数： xx/10（10为满分）
- 改造关键：
- 下一步建议：

# LLM介入边界


# 改造难度评级

维度	｜ 难度值（xx/10，10为满分）｜解释



# 落地MVP路线图



# 风险清单

```

---

## 各章节填充规范

### 1. 诊断说明（必须每行都填）

- **一句话说明**：用 1 句话说清"应该全量 / 部分 / 不适合"的核心判断与核心理由，≤ 50 字。
- **改造步骤**：用「步骤 1 / 步骤 2 / ...」列出 2-4 步，按推进顺序，不超过 4 步。
- **ROI 分数**：xx/10，10 为满分；定性量级映射建议：
  - 9-10：极高
  - 7-8：高
  - 5-6：中
  - 3-4：低
  - 1-2：极低 / 信息不足
- **改造关键**：列出 1-3 条"决定改造是否成立的关键点"，每条独立一行。
- **下一步建议**：列出 2-3 条用户马上可以做的最小动作，每条独立一行。

### 2. LLM 介入边界

按四个分类组织，每个分类至少 1 条（没命中也要写"无"）：

- 硬护栏护住：监管 / 合规 / 实时 / 高精度场景，LLM 不能介入。
- 仅部分场景适用：LLM 生成候选 / 多版本，人工裁决。
- 全量适用：决策 / 执行 / 润色都可交给 LLM。
- AI 可护住：LLM 能补充的具体能力（生成 / 推理 / 检索 / 设计 / 数据能力边界 / 翻译 / 命名 / 提炼 等）。

### 3. 改造难度评级（必须使用 Markdown 表格）

列固定为「维度 ｜ 难度值（xx/10，10为满分） ｜ 解释」。

维度固定 5 项：输入多样性、输出一致性要求、容错率、决策密度、可验证性。

- 难度值 0 = 完全无难度（高度结构化 + 高容错 + 高一致性 + 高可验证）
- 难度值 10 = 改造极难（高多样性 + 强一致性 + 零容错 + 高决策密度 + 难验证）
- 解释：1 句话说明打分依据。

### 4. 落地 MVP 路线图

按时间顺序列 3-5 个最小动作，每条独立一行：

- MVP 步骤 1：...
- MVP 步骤 2：...
- ...

只写最小可验证路径，不写"未来需要时再加 LLM"。

### 5. 风险清单

列出 2-5 条具体风险，每条独立一行：

- 风险 1 + 缓解方案
- 风险 2 + 缓解方案

禁止"未来还有很多工作要做"这类空话。

### 6. 信息缺口 / 需补充追问（如有）

如果信息不足导致建议存在显著不确定，必须额外加这个小节：

```
# 信息缺口 / 需补充追问

- 缺口 1：...
- 缺口 2：...
```

---

## 输出语言

- 中文正文 + 英文术语保留（如 ROI / MVP / LLM / CTR）。
- 不要输出 `.md` 文件；直接把上面 6 个章节贴在对话回复里。

---

## 核心反模式

- ❌ 输出到 .md 文件 → ✅ 原文贴在 Chat 里
- ❌ 章节顺序 / 标题改动 → ✅ 完全照抄章节结构
- ❌ 改造步骤写"未来再决定" → ✅ 2-4 步可执行动作
- ❌ 难度评级不填具体分数或只写"中" → ✅ 必须 xx/10
- ❌ ROI 写具体金额 → ✅ xx/10 分数 + 定性量级
- ❌ 风险写"还有很多工作要做" → ✅ 具体风险 + 缓解方案

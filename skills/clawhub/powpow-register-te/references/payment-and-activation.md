# సబ్‌స్క్రిప్షన్ యాక్టివేషన్ మరియు చెల్లింపు — powpow-register

## నిర్ణయం (మొదటిగా సమాధానం)

**Alipay ఛానల్ ఇప్పటికే ఆపరేషన్‌లో ఉంది (2026-10-07 నుండి), ఈ skill యొక్క ప్రధాన చెల్లింపు మార్గం; agent
ఆర్డర్ సృష్టించడం మరియు డబ్బు రాకను ట్రాక్ చేయడం తరపున చేస్తుంది.** విదేశాలలో / Alipay లేని వినియోగదారులు PayPal
కి మారవచ్చు; వీచాట్ QR (మాన్యువల్ నిర్ధారణ) మరియు హువావే IAP కూడా ఉన్నాయి, అయితే skill వాటిని తరపున చేయదు.

చెల్లింపు భాగం బాధ్యత సరిహద్దు: agent **ఆర్డర్ సృష్టించడం, చెల్లింపు పేజీ తెరవడం, డబ్బు రాకను పోలింగ్
చేయడం** మాత్రమే చేస్తుంది; వినియోగదారు Alipay అకౌంట్/చెల్లింపు ఆధారాలను **ఎప్పుడూ** తాకదు, "నేను చెల్లించి
ఇస్తాను" అని కూడా వాగ్దానం చేయదు. చెల్లింపు చర్య ఎప్పుడూ వినియోగదారే Alipay అధికారిక చెల్లింపు పేజీలో పూర్తి
చేస్తారు.

## Alipay ఛానల్ (vibepay, ప్రధాన మార్గం)

వన్-టైమ్ పేమెంట్: ఒకసారి చెల్లించి సరిపోయిన కాలాన్ని తెరుస్తుంది, **ఆటో-రిన్యూ కాదు**.
ప్లాన్‌లు `src/lib/alipay-vibepay.ts` (`ALIPAY_PACKAGES`) లో స్థిరంగా వ్రాయబడ్డాయి:

| key | planId | పేరు | ధర | వ్యవధి |
|---|---|---|---|---|
| `monthly` | alipay-monthly | నెలవారీ మెంబర్ | ¥6.99 | 30 రోజులు |
| `quarterly` | alipay-quarterly | త్రైమాసిక మెంబర్ | ¥19.99 | 90 రోజులు |
| `yearly` | alipay-yearly | ఏడాది మెంబర్ | ¥69.99 | 365 రోజులు |

### ఇంటర్‌ఫేస్ ఒప్పందం (skill స్క్రిప్ట్‌లో ఇప్పటికే క్యాప్సూలేటెడ్, agent నేరుగా రిక్వెస్ట్ చేయదు)

| ఇంటర్‌ఫేస్ | పద్ధతి | వివరణ |
|---|---|---|
| `/api/payment/alipay/create-order` | POST | `Authorization: Bearer <JWT>` అవసరం (pending వినియోగదారు కూడా సరిపోతుంది). body `{package}` → `{paymentHtml, outTradeNo, amount, planName}` తిరిగి ఇస్తుంది; `paymentHtml` అనేది Alipay గేట్‌వేకి ఆటో-సబ్మిట్ అయ్యే ఫారం పేజీ |
| `/api/payment/alipay/query` | GET `?outTradeNo=` | అదే Bearer ఆథరైజేషన్. `paid` / `pending` / `closed` / `unknown` తిరిగి ఇస్తుంది |
| `/api/payment/alipay/notify` | POST (Alipay సర్వర్ కాల్‌బ్యాక్) | ఐదు ముఖ్య ఎలిమెంట్ల ధృవీకరణ (సిగ్నేచర్, app_id, మొత్తం సరిపోలడం, TRADE_SUCCESS/TRADE_FINISHED, వర్తకుడి ప్రత్యేకత) → **idempotent** ఆర్డర్ అప్‌డేట్ + సబ్‌స్క్రిప్షన్ సృష్టి + అకౌంట్ యాక్టివేషన్. skill ఈ ఇంటర్‌ఫేస్‌ను ఎప్పుడూ తాకదు |
| `/payment/alipay/return` | బ్రౌజర్ రిటర్న్ పేజీ | పబ్లిక్ పాత్, చెల్లింపు తర్వాత 「支付成功」 (చెల్లింపు విజయవంతమైంది) నిర్ధారణ చూపుతుంది, పేజీ లోపల బ్యాకెండ్ నిజమైన స్థితిని పోలింగ్ చేస్తుంది |

- చెల్లించని ఆర్డర్ **2 గంటల్లో ఆటోమేటిగ్గా క్లోజ్ అవుతుంది**; వినియోగదారు మధ్యలో వదిలేస్తే → నేరుగా మళ్ళీ
  `create-order`, పాత ఆర్డర్ గురించి పట్టించుకోవాల్సిన అవసరం లేదు.
- స్క్రిప్ట్ `paymentHtml` ను టెంపరరీ HTML ఫైల్‌లో రాస్తుంది, agent సిస్టమ్ కమాండ్‌తో తెరిస్తే Alipay చెల్లింపు
  పేజీలోకి ప్రవేశించవచ్చు (QR స్కాన్ చేయడం లేదా Alipay లో లాగిన్ చేసి చెల్లించడం).

### యాక్టివేషన్ చైన్ (ఆటోమేటిగ్గా, మాన్యువల్ అవసరం లేదు)

notify ధృవీకరణ విజయవంతం → `paymentOrders` చెల్లించినట్లుగా మార్క్ → `user_subscriptions`
సృష్టి/పొడిగింపు (`planId`, `currentPeriodEnd` durationDays ఆధారంగా లెక్కించబడుతుంది, రిన్యూ చేస్తే అసలు
గడువు రోజు నుండి ముందుకు పొడిగించబడుతుంది) → `users.accountStatus: active` +
`subscriptionStatus: ACTIVE` → రిటర్న్ పేజీ paid పొంది విజయాన్ని చూపుతుంది.

### చెల్లింపు తర్వాత కొత్త లాగిన్ స్టేట్ పొందడం తప్పనిసరి (ముఖ్యం)

JWT లో సబ్‌స్క్రిప్షన్ క్లెయిమ్ ఉంటుంది (pending అకౌంట్‌లో `NONE`). **చెల్లింపు రాక DB ను మాత్రమే
అప్‌డేట్ చేస్తుంది, ఇప్పటికే ఇచ్చిన JWT ను మార్చదు** — పాత token క్లెయిమ్ ఇంకా NONE కావడం వల్ల, దాన్ని వాడి లాగిన్
లింక్ సృష్టిస్తే "మెంబర్‌షిప్ లేదు" అని కనిపిస్తుంది. అందుకే skill `paid` నిర్ధారించిన తర్వాత ముందుగా
`refresh-login` నిర్వర్తిస్తుంది (మళ్ళీ లాగిన్ చేసి కొత్త JWT, క్లెయిమ్ ACTIVE అవుతుంది), ఆ తర్వాత లింక్ 2
సృష్టిస్తుంది. ఇది రూపొందించిన ప్రవర్తనే, బగ్ ఫిక్స్ కాదు.

## సబ్‌స్క్రిప్షన్ పేజీ యొక్క నాలుగు ఛానళ్లు

సబ్‌స్క్రిప్షన్ పేజీ `src/app/(public)/subscription/page.tsx` ఎన్విరాన్‌మెంట్‌ను బట్టి చూపుతుంది:

| ఛానల్ | సందర్భం | అమలు | యాక్టివేషన్ విధానం |
|---|---|---|---|
| **Alipay (ప్రధాన)** | వెబ్ పేజీ | `AlipayPaymentSection` vibepay ఇంటర్‌ఫేస్‌లను వాడుతుంది (పై పట్టిక) | notify ద్వారా సర్వర్‌లో ఆటోమేటిగ్గా యాక్టివేట్, సెకన్ల వ్యవధిలో |
| PayPal సబ్‌స్క్రిప్షన్ | వెబ్ పేజీ (హార్మోనీ కాదు) | `/api/subscription/create` → PayPal ఆథరైజేషన్‌కి వెళ్తుంది; నెలవారీ ఆటో-రిన్యూ, ఎప్పుడైనా క్యాన్సల్ చేయవచ్చు (`/api/subscription/manage`) | PayPal Webhook (`BILLING.SUBSCRIPTION.*`) ఆటోమేటిగ్గా active చేస్తుంది |
| వీచాట్ QR సబ్‌స్క్రిప్షన్ | వెబ్ పేజీ (హార్మోనీ కాదు) | పేజీ దిగువన 「微信扫码订阅」 (వీచాట్ QR స్కాన్ చేసి సబ్‌స్క్రైబ్): QR స్కాన్‌తో ట్రాన్స్‌ఫర్ | **మాన్యువల్ నిర్ధారణ**, డబ్బు రాక ఆలస్యం కావచ్చు; చెల్లించిన వెంటనే విఫలమైందని నిర్ణయించకండి |
| హువావే ఇన్-యాప్ కొనుగోలు | హార్మోనీ యాప్ లోపల | నేటివ్ `NativeBridge.purchaseSubscription()` | `/api/subscription/activate-huawei` హువావే ఆర్డర్ ధృవీకరణ తర్వాత యాక్టివేట్ చేస్తుంది |

PayPal ప్లాన్‌లు మరియు ధరలు `/api/subscription/plans` నుండి డైనమిక్‌గా చదువబడతాయి; పేజీలోని స్థిర టెక్స్ట్:
Auto-renews. Cancel anytime.

## స్థితులు మరియు రీడైరెక్షన్‌లు

- Alipay లో చెల్లింపు పూర్తయిన వెంటనే → రిటర్న్ పేజీ విజయాన్ని చూపుతుంది; PayPal విజయం → `/subscription/success`
  → అకౌంట్ active → `next` పారామీటర్‌లో పేర్కొన్న అసలు పేజీకి ఆటోమేటిగ్గా తిరిగి వస్తుంది (లేకపోతే హోమ్).
- సబ్‌స్క్రిప్షన్ ఉన్న వినియోగదారు మళ్ళీ సబ్‌స్క్రిప్షన్ పేజీకి వస్తే → "You're All Set!" చూపి 3 సెకన్లలో
  ఆటోమేటిగ్గా హోమ్‌కి తిరిగి వస్తుంది.
- చెల్లింపు వైఫల్యం/క్యాన్సల్ (PayPal) → `/subscription/cancel`, మళ్ళీ మొదలుపెట్టవచ్చు.

## ట్రబుల్‌షూటింగ్

| సంఘటన | ఏం చేయాలి |
|---|---|
| Alipay లో చెల్లింపు పూర్తయిన వెంటనే `query` ఇంకా pending | notify చాలా అరుదుగా ఆలస్యం అవుతుంది; 30 సెకన్లు వేచి మళ్ళీ ఒకసారి పోలింగ్ చేయండి. ఇంకా సమస్యేమైతే: బ్రౌజర్‌లో వినియోగదారు రిటర్న్ పేజీ స్థితిని చూడమనండి; తర్వాత కూడా సమస్య ఉంటే సైట్ సపోర్ట్‌ను సంప్రదించండి (dongtao@outlook.com), `outTradeNo` చెప్పండి |
| Alipay లో చెల్లించారు, కానీ లింక్ 2 తో లోపలికి వెళ్ళినా ఇంకా బ్లాక్ అవుతోంది | `refresh-login` నిర్వర్తించబడలేదు (పాత JWT క్లెయిమ్ అప్‌డేట్ కాలేదు) — ముందుగా `refresh-login`, ఆ తర్వాత `login-link` |
| చెల్లించిన తర్వాత కూడా 403 (PayPal) | Webhook కొన్నిసార్లు ఆలస్యం, మళ్ళీ లాగిన్ చేసి స్థితిని రిఫ్రెష్ చేయండి |
| వీచాట్ లో చెల్లించారు కానీ తెరవలేదు | మాన్యువల్ నిర్ధారణ అసింక్రోనస్; కొన్ని గంటల్లో తెరవకపోతే సైట్ సపోర్ట్‌ను సంప్రదించండి |
| సబ్‌స్క్రిప్షన్ పేజీ "No subscription plans available" అంటోంది | `/api/subscription/plans` లో వాడదగిన PayPal ప్లాన్ లేదు, సైట్ కాన్ఫిగరేషన్ సమస్య; చైనా వినియోగదారులు Alipay నే వాడమనండి |

## చరిత్ర గమనిక

కోడ్‌లో మరొక **పాత** Alipay వెబ్ చెల్లింపు సిస్టమ్ కూడా ఉంది (`src/lib/alipay.ts`,
`/api/payment/create-order`, ¥9.90/¥99 వన్-టైమ్ కొనుగోలు, సాండ్‌బాక్స్‌లో key లేనప్పుడు మోస్తాపు
చెల్లింపుకు డీగ్రేడ్ అవుతుంది) — ఎప్పుడూ సబ్‌స్క్రిప్షన్ పేజీ UI కి కనెక్ట్ కాలేదు, vibepay కి సంబంధం లేదు.
skill ఎప్పుడూ దాన్ని తాకదు; `alipay-vibepay.ts` మాత్రమే ప్రస్తుత ఛానల్.

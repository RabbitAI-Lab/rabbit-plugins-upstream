# రిజిస్ట్రేషన్ ప్రక్రియ వివరాలు — powpow-register

సమస్యలు పరిష్కరించేటప్పుడు చూడటానికి. అన్ని నియమాలు ప్లాట్‌ఫారమ్ మూల కోడ్ నుండి వచ్చాయి (Next.js
ఫ్రంట్-బ్యాకెండ్ ఒకేలా ధృవీకరణ), ఆధారాలతో. ప్లాట్‌ఫారమ్ అప్‌డేట్ అయితే ఆన్‌లైన్‌లో నిజమైన ప్రవర్తనే
ప్రధానం.

## ప్రవేశ ద్వారాలు

- రిజిస్ట్రేషన్ పేజీ: https://global.powpow.online/register
- లాగిన్ పేజీ: https://global.powpow.online/login
- సబ్‌స్క్రిప్షన్ పేజీ: https://global.powpow.online/subscription
- షేరింగ్ లింక్ వంటి వాటి నుండి `?next=...` తో ప్రవేశిస్తే, రిజిస్ట్రేషన్ + చెల్లింపు పూర్తయిన తర్వాత ఆటోమేటిగ్గా అసలు పేజీకి తిరిగి వస్తుంది.

`WatchaLoginButton` / `HuaweiLoginButton`). థర్డ్-పార్టీ అకౌంట్‌లకు లోకల్ పాస్‌వర్డ్ ఉండదు; తర్వాత పాస్‌వర్డ్‌తో లాగిన్
చేయడానికి ప్రయత్నిస్తే 「该账号未设置密码，请使用其他方式登录」 (ఈ అకౌంట్‌లో పాస్‌వర్డ్ సెట్ చేయబడలేదు, వేరే విధంగా లాగిన్ చేయండి) అని వస్తుంది.

**ప్రైవసీ ప్రొటెక్షన్ ప్రవర్తన**: వెరిఫికేషన్ కోడ్ / పాస్‌వర్డ్ మర్చిపోయినప్పుడు పంపేటప్పుడు, ఇమెయిల్ ఇప్పటికే రిజిస్టర్
చేయబడి ఉన్నా లేకపోయినా, ఇంటర్‌ఫేస్ రెండు పరిస్థితుల్లోనూ ఒకేలా విజయవంతమైన సందేశాన్ని తిరిగి ఇస్తుంది,
ఇమెయిల్ రిజిస్టర్ చేయబడిందో లేదో బహిర్గతం చేయదు.

## agent మోడ్ మరియు వెబ్ రిజిస్ట్రేషన్ మధ్య సమానత్వం

skill స్క్రిప్ట్ **అదే పబ్లిక్ API లను** పిలుస్తుంది (`/api/auth/register`, `send-code`, `login`,
`/api/auth/me`) — రిజిస్ట్రేషన్ పేజీ ఫారం సబ్మిట్ చేసే ధృవీకరణ, రేట్ లిమిట్, ఎర్రర్ మార్గాలు అన్నీ పూర్తిగా
ఒకటే — ఈ ఫైల్‌లోని అన్ని నియమాలు రెండు మోడ్‌లకు ఒకేలా వర్తిస్తాయి. స్క్రిప్ట్ టైమ్‌లైన్ మరియు కమాండ్ ఒప్పందం
`references/agent-flow.md` లో ఉన్నాయి.

## రిజిస్ట్రేషన్ విజయం తర్వాత స్టేట్ ఫ్లో

1. వినియోగదారు DB లో `accountStatus: 'pending'` స్థితిలో సేవ్ చేయబడతారు, ప్రారంభంలో **3 బ్యాడ్జ్‌లు** లభిస్తాయి (register route).
2. సర్వర్ ఏకకాలంలో రెండు HttpOnly cookie లను జారీ చేస్తుంది: JWT (`/subscription` ను నేరుగా యాక్సెస్ చేయగలరు) మరియు
   pendingUserToken (సబ్‌స్క్రిప్షన్ ప్రక్రియ గుర్తింపు ఆధారం).
3. రిజిస్ట్రేషన్ పేజీ `pending_payment` గుర్తించిన వెంటనే → `/subscription` కి రీడైరెక్ట్ చేస్తుంది (`next` తిరిగి
   రావాల్సిన పారామీటర్ ప్రిజర్వ్ చేయబడుతుంది); agent మోడ్‌లో `me?token=…&redirect=/subscription` తో అదే ఫలితాన్ని పొందవచ్చు.
4. చెల్లింపు పూర్తయిన తర్వాత → `accountStatus` `active` గా మారుతుంది (**Alipay notify ద్వారా సర్వర్‌లో ఆటోమేటిగ్గా
   యాక్టివేట్ అవుతుంది**; PayPal Webhook ద్వారా ఆటోమేటిగ్గా; వీచాట్ QR మాన్యువల్ నిర్ధారణ; హువావే IAP
   `activate-huawei` ద్వారా). వివరాలు `payment-and-activation.md` లో.

యాక్టివేట్ కాని (pending) వినియోగదారు కోర్ API లను (తపాలా, మ్యాప్, డిజిటల్ హ్యూమన్ చాట్, చెక్-ఇన మొదలైనవి)
పిలిస్తే ఎల్లప్పుడూ 403; షేర్ చేసిన పోస్ట్ లింక్ మాత్రమే మినహాయింపు (పబ్లిక్‌గా యాక్సెస్ చేయగలరు).

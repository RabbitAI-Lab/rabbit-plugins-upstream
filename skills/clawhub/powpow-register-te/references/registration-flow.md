# రిజిస్ట్రేషన్ ప్రక్రియ వివరాలు — powpow-register

సమస్యలు పరిష్కరించేటప్పుడు చూడడానికి. అన్ని నియమాలు ప్లాట్ఫారమ్ సోర్స్ కోడ్ (Next.js ఫ్రంట్-ఎండ్/బ్యాక్-ఎండ్ సమ్మతి
వాలిడేషన్) నుంచి తీసుకోబడ్డాయి, సోర్స్ సూచించబడింది.
ప్లాట్ఫారమ్ అప్డేట్ అయితే ఆన్లైన్ వాస్తవ ప్రవర్తనే వర్తిస్తుంది.

## ప్రవేశం

- రిజిస్ట్రేషన్ పేజీ: https://global.powpow.online/register
- లాగిన్ పేజీ: https://global.powpow.online/login
- సబ్స్క్రిప్షన్ పేజీ: https://global.powpow.online/subscription
- షేర్ లింక్ మొదలైన వాటి నుంచి `?next=...` తో వస్తే, రిజిస్ట్రేషన్ + చెల్లింపు పూర్తయిన తర్వాత స్వయంచాలకంగా అసలు పేజీకి తిరిగి వెళ్తుంది.

`WatchaLoginButton` / `HuaweiLoginButton`)। థర్డ్-పార్టీ ఖాతాకు లోకల్ పాస్వర్డ్ ఉండదు, తర్వాత పాస్వర్డ్తో లాగిన్
చేస్తే «该账号未设置密码，请使用其他方式登录» (ఈ ఖాతాకు పాస్వర్డ్ సెట్ చేయలేదు, దయచేసి ఇతర మార్గంలో లాగిన్ చేయండి) అని వస్తుంది.

## రేట్-లిమిట్ మరియు యాంటీ-బ్రూట్-ఫోర్స్ పరామితులు

| ప్రవర్తన | పరిమితి | సోర్స్ |
|---|---|---|
| రిజిస్ట్రేషన్ సబ్మిట్ | **ప్రతి IPకి 3 సార్లు/నిమిషం**, పరిమితి దాటితే 429 | `src/lib/rate-limit.ts` `REGISTER_RATE_LIMIT` |
| వెరిఫికేషన్ కోడ్ పంపడం | ఒకే IP నుంచి 1 సారి/నిమిషం **మరియు** ఒకే ఇమెయిల్కు 1 సారి/నిమిషం, పరిమితి దాటితే 429; ఫ్రంట్-ఎండ్ బటన్పై 60 సెకన్ల కౌంట్డౌన్ | `src/app/api/auth/register/send-code/route.ts` |
| వెరిఫికేషన్ కోడ్ తనిఖీ | ప్రతి ఇమెయిల్కు 10 నిమిషాల్లో గరిష్టంగా **5 సార్లు** ప్రయత్నం, పరిమితి చేరితే సరైన కోడ్ కూడా తిరస్కరించబడుతుంది, మళ్లీ కోడ్ పంపించాలి | `src/lib/email-verification.ts` |
| పాస్వర్డ్ మర్చిపోతే కోడ్ పంపడం | 1 సారి/నిమిషం/IP | `src/app/api/auth/forgot-password/route.ts` |
| లాగిన్ | 5 సార్లు/నిమిషం/IP; ఒకే ఖాతాలో వరుసగా **5 సార్లు విఫలమైతే 30 నిమిషాలు లాక్** (423), ఈ సమయంలో మిగిలిన ప్రయత్నాలు తగ్గుతూ చూపబడతాయి | `src/app/api/auth/login/route.ts`、`rate-limit.ts` |

**గోప్యతా రక్షణ ప్రవర్తన**: వెరిఫికేషన్ కోడ్ పంపేటప్పుడు / పాస్వర్డ్ మర్చిపోయినప్పుడు, ఇమెయిల్ ఇప్పటికే రిజిస్టర్ అయి ఉన్నా వివరాలు లేకున్నా,
ఇంటర్ఫేస్ ఎల్లప్పుడూ ఒకే విజయ సందేశాన్ని ఇస్తుంది, ఇమెయిల్ రిజిస్టర్ అయిందో లేదో బయటపెట్టదు.

## రిజిస్ట్రేషన్ విజయం తర్వాత స్థితి ప్రవాహం

1. వినియోగదారు `accountStatus: 'pending'` తో డేటాబేస్లో సేవ్ అవుతాడు, ప్రారంభంలో **3 బ్యాడ్జ్లు** (register route).
2. సర్వర్ అదే సమయంలో రెండు HttpOnly కుకీలను సెట్ చేస్తుంది: JWT (నేరుగా `/subscription` యాక్సెస్ చేయవచ్చు) మరియు
   pendingUserToken (సబ్స్క్రిప్షన్ ప్రక్రియ గుర్తింపు రుజువు).
3. రిజిస్ట్రేషన్ పేజీ `pending_payment` ని గుర్తించి → `/subscription` కు వెళ్తుంది (`next` తిరిగి వెళ్లే పరామితిని భద్రపరుస్తుంది).
4. చెల్లింపు పూర్తి → `accountStatus` `active` అవుతుంది (PayPal Webhook ద్వారా స్వయంచాలకంగా యాక్టివేట్; WeChat స్కాన్పై
   మాన్యువల్ నిర్ధారణ; హువావే IAPలో `activate-huawei`). వివరాలు `payment-and-activation.md`లో చూడండి.

యాక్టివేట్ కాని (pending) వినియోగదారు కోర్ API (ఫీడ్, మ్యాప్, డిజిటల్ హ్యూమన్ చాట్, చెక్-ఇన్ మొదలైనవి) కాల్ చేస్తే ఎల్లప్పుడూ
403 వస్తుంది; పోస్ట్ షేర్ లింక్ మినహా (అది బహిరంగంగా అందుబాటులో ఉంటుంది).

## లాగిన్ చిన్న వివరాలు (పరిష్కారానికి కూడా ఉపయోగపడతాయి)

లాగిన్ **యూజర్నేమ్ / ఇమెయిల్ / మొబైల్ నంబర్** మూడింటినీ ఒకేసారి అంగీకరిస్తుంది (మూడింటిలో దేనినైనా ఖాతా పేరుగా వాడవచ్చు).
పాస్వర్డ్ మర్చిపోయారా: లాగిన్ పేజీ → «పాస్వర్డ్ మర్చిపోయారా» → రిజిస్టర్ చేసిన ఇమెయిల్ నమోదు చేయండి, 6 అంకెల వెరిఫికేషన్ కోడ్ తీసుకోండి → రీసెట్ చేయండి.

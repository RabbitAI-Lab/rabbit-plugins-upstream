# Agent తరపున చేసే ప్రాసెస్ మరియు స్క్రిప్ట్ ఒప్పందం — powpow-register

SKILL.md లోని ప్రతి స్టెప్ యొక్క అమలు వివరాలు. అన్ని కమాండ్‌లూ `node scripts/powpow-register.mjs <సబ్‌కమాండ్> [పారామీటర్లు]` రూపంలో ఉంటాయి. స్క్రిప్ట్ **జీరో డిపెండెన్సీ**, **Node ≥ 18** అవసరం; అన్ని రిక్వెస్ట్‌లు `https://global.powpow.online` కి మాత్రమే వెళ్తాయి.

## భద్రతా రూపకల్పన (ఎందుకు ఇలా రూపొందించారు)

| రూపకల్పన | కారణం |
|---|---|
| పాస్‌వర్డ్ ఎన్విరాన్‌మెంట్ వేరియబుల్ `POWPOW_REGISTER_PASSWORD` ద్వారా మాత్రమే పంపబడుతుంది | ప్రాసెస్ కమాండ్ లైన్ పారామీటర్లు అదే మెషీన్‌పై ఉన్న ఇతర ప్రాసెస్‌లకు కనిపిస్తాయి (argv లీకేజ్ ఉపరితలం); ఎన్విరాన్‌మెంట్ వేరియబుల్‌ను స్క్రిప్ట్ లోపల చదివి వెంటనే వాడుతుంది |
| పాస్‌వర్డ్ **స్టేట్ ఫైల్‌లో ఎప్పుడూ రాయబడదు**, లాగ్‌లలో ఎప్పుడూ కనిపించదు | స్టేట్ ఫైల్ డిస్క్‌పై మిగిలిపోవచ్చు; సంభాషణలో జనరేట్ మోడ్‌లో ఒకేసారి చూపడం — వినియోగదారు సేవ్ చేసుకోవడానికే |
| స్టేట్ ఫైల్ సిస్టమ్ టెంపరరీ డైరెక్టరీలో ఉంటుంది (`os.tmpdir()/powpow-register-state.json`, 0600) | ఇందులో email / username / nickname / token / outTradeNo అనే ఐదు ఫీల్డ్‌లు మాత్రమే ఉంటాయి; `cleanup` ఒకే క్లిక్‌లో తొలగిస్తుంది |
| agent పొందిన JWT అధికారిక `me?token=` ఎండ్‌పాయింట్ ద్వారా బ్రౌజర్ cookie గా మార్చబడుతుంది | ప్లాట్‌ఫారమ్ హార్మనీ OS WebView కోసం రూపొందించిన అధికారిక బ్రిడ్జ్; వెరిఫికేషన్ సంతకం+గడువు మాత్రమే చూస్తుంది, డివైస్ ఫింగర్‌ప్రింట్‌కు బంధించబడదు — వినియోగదారు బ్రౌజర్‌లో వాడవచ్చు |
| చెల్లింపులో create-order / query / చెల్లింపు పేజీ తెరవడం మాత్రమే చేస్తాము | చెల్లింపు యాక్షన్, చెల్లింపు క్రెడెన్షియల్స్ ఎప్పుడూ వినియోగదారుకు మరియు Alipay అధికారిక చెల్లింపు పేజీకి మధ్యలోనే ఉంటాయి — agent తాకదు |

## కమాండ్ రిఫరెన్స్

| కమాండ్ | కీ పారామీటర్లు | పని / సమయం |
|---|---|---|
| `status` | —— | ప్రాసెస్ ప్రోగ్రెస్ చూడటం (స్టేట్ ఫైల్ చదవడం); సంభాషణ ఆగిపోయిన తర్వాత మొదట ఇదే రన్ చేయండి |
| `gen-password` | —— | 24 అక్షరాల బలమైన పాస్‌వర్డ్ జనరేట్ (కేస్‌లు + అంకెలతో); stdout పై **ఒకే ఒక్కసారి** చూపుతుంది |
| `prepare-suggest` | `--username --nickname --email` | ఖరారైన సమాచారాన్ని స్టేట్ ఫైల్‌లో నమోదు చేయడం (తర్వాత register లో మళ్ళీ పంపాల్సిన అవసరం లేదు) |
| `send-code` | `--email` | ప్లాట్‌ఫారమ్‌నుండి 6 అంకెల వెరిఫికేషన్ కోడ్ రావడానికి ట్రిగ్గర్ (10 నిమిషాలు చెల్లుతుంది, 60s కూల్‌డౌన్) |
| `register` | `--code` (తప్పనిసరి); `--username --nickname --avatar --phone` (ఐచ్ఛికం, స్టేట్ ఫైల్‌లో ఉంటే మళ్ళీ పంపనవసరం లేదు) | pending అకౌంట్ క్రియేట్; పాస్‌వర్డ్ `POWPOW_REGISTER_PASSWORD` ఎన్విరాన్‌మెంట్ వేరియబుల్ ద్వారా; విజయవంతమైతే JWT ఆటోమేటిగ్గా స్టేట్ ఫైల్‌లో సేవ్ అవుతుంది |
| `login-link` | `--target pending` లేదా `--target home` | ఒకే-క్లిక్ లాగిన్ లింక్ సృష్టిస్తుంది (ద్వై-లింక్ డిజైన్, కింద చూడండి) |
| `create-order` | `--package monthly\|quarterly\|yearly` (డిఫాల్ట్ Alipay)<br>`--provider alipay\|paypal` | చెల్లింపు ఆర్డర్ ని సృష్టిస్తుంది; Alipay చెల్లింపు పేజీ ఫైల్ పాత్ + outTradeNo ని తిరిగి ఇస్తుంది; PayPal అనుమతి పేజీ ఫైల్ పాత్ + subscriptionId ని తిరిగి ఇస్తుంది (ఆటోమేటిగ్గా స్టేట్ ఫైల్ లో నమోదవుతుంది) |
| `query` | —— | ఆర్డర్/సబ్‌స్క్రిప్షన్ స్థితిని చూస్తుంది. Alipay: `paid / pending / closed / unknown`; PayPal: `ACTIVE / PENDING`; 10–15s పోలింగ్ |
| `refresh-login` | పాస్‌వర్డ్ ఎన్విరాన్‌మెంట్ వేరియబుల్ ద్వారా | మళ్ళీ లాగిన్ అయి **కొత్త JWT** పొందడం (సబ్‌స్క్రిప్షన్ క్లెయిమ్ NONE నుండి ACTIVE కి మారుతుంది) — చెల్లింపు వచ్చాక తప్పనిసరి |
| `whoami` | —— | స్టేట్ ఫైల్‌లోని token తో అకౌంట్ మరియు సబ్‌స్క్రిప్షన్ స్థితి చూడటం (యాక్టివేషన్ అమలైందో లేదో ధృవీకరించడం) |
| `cleanup` | —— | స్టేట్ ఫైల్ డిలీట్ (ముగింపులో తప్పనిసరి) |

**ఎన్విరాన్‌మెంట్ వేరియబుల్ పంపడం** (పాస్‌వర్డ్ ఎప్పుడూ కమాండ్ లైన్‌పై రాదు):

```bash
# bash / zsh / WSL
POWPOW_REGISTER_PASSWORD='<పాస్‌వర్డ్>' node scripts/powpow-register.mjs register --code 123456
# PowerShell
$env:POWPOW_REGISTER_PASSWORD = '<పాస్‌వర్డ్>'; node scripts/powpow-register.mjs register --code 123456
# cmd
set POWPOW_REGISTER_PASSWORD=<పాస్‌వర్డ్> && node scripts/powpow-register.mjs register --code 123456
```

## ద్వై-లింక్ యంత్రాంగం (కోర్ డిజైన్)

ప్లాట్‌ఫామ్ లాగిన్ స్థితి ఒక HttpOnly కుక్కీ, దాన్ని ఏజెంట్ నేరుగా బ్రౌజర్‌లో నాటడం సాధ్యం కాదు; సేతువు అధికారిక
`/api/auth/me?token=<JWT>&redirect=<సైట్ లోపలి పాత్>` ఎండ్‌పాయింట్: సంతకం ధృవీకరణ → స్వయంచాలకంగా సెషన్
సృష్టి → `Set-Cookie: powpow_token` (HttpOnly / SameSite=Lax / 7 రోజులు) → రీడైరెక్ట్ ధృవీకరణ
(ఒకే స్లాష్‌తో మొదలవాలి, `//` మరియు బ్యాక్‌స్లాష్‌లు నిషిద్ధం, పార్స్ చేసిన తర్వాత same-origin అయి ఉండాలి) → లక్ష్య పేజీకి 307 తాత్కాలిక రీడైరెక్ట్.

లింక్‌కి రెండు లక్ష్యాలు ఉన్నాయి, **ముందుగా home సృష్టించండి, ఆపై యూజర్ ఎక్కడ దిగారో దాని ఆధారంగా pending ద్వారా వెళ్లాలా అని నిర్ణయించండి**:

- **home లింక్ (డిఫాల్ట్‌గా పంపబడుతుంది, `--target home` → `/` పై దిగుతుంది)**: విజయవంత నిర్మాణం వెంటనే సృష్టించి యూజర్‌కి పంపబడుతుంది.
  ఉచిత పరీక్ష కాలంలో యూజర్ నేరుగా హోమ్ పేజీకి వెళ్తాడు, అంతా వాడదు; **లింక్ క్లిక్ చేసి సబ్‌స్క్రిప్షన్ పేజీపై దిగితే ఉచిత పరీక్ష కాలం ముగిసింది** — చెల్లింపు ప్రవాహానికి మారండి (కింద చూడండి); స్క్రిప్ట్ మార్పు లేదా మళ్లీ నిర్మాణం అవసరం లేదు.
- **pending లింక్ (చెల్లింపు ప్రవాహంలో ఉపయోగించబడుతుంది, `--target pending` → `/subscription` పై దిగుతుంది)**:
  యూజర్ బ్రౌజర్ "అర్ధ-లాగిన్" స్థితిలోకి ప్రవేశిస్తుంది: సబ్‌స్క్రిప్షన్ పేజీ మరియు చెల్లింపు తర్వాత తిరిగి రాక పేజీ కనిపిస్తాయి మరియు నడపగలవు. డబ్బు రాక తర్వాత,
  ACTIVE క్లెయిమ్‌తో కొత్త JWT కి మారడానికి `refresh-login` నడపండి, ఆపై పూర్తి సభ్యత్వ స్థితి కోసం home లింక్ మళ్లీ పంపండి.

## పూర్తి క్రమం

### ఫాస్ట్ పాత్ (ఉచిత పరీక్ష కాలంలో — మైకరిటీ కేసులు)

```
1.  status                          # పర్యావరణ స్వీయ-తనిఖీ
2.  (స్టెప్ 2: సమాచారం నిర్ధారణ కోసం సంభాషణ, పాస్‌వర్డ్ ఇష్టం; జెనరేట్ మోడ్: gen-password → యూజర్‌ని వెంటనే భద్రపరచమని అనండి)
3.  prepare-suggest --username U --nickname N --email E
4.  send-code --email E             # → యూజర్ ఇన్‌బాక్స్‌లో కోడ్ చూసుకుంటాడు (సంభాషణ నుండి బయటకి వెళ్లే ఒకే సారి)
5.  POWPOW_REGISTER_PASSWORD=*** register --code 123456 [--avatar pic.jpg]
6.  login-link --target home        # → లింక్ యూజర్‌కి పంపండి; ఒకే క్లిక్‌తో హోమ్ పేజీపై
7.  (యూజర్ లోపలికి వెళ్లారని నిర్ధారిస్తాడు) → వెంటనే ముగించండి: cleanup + ఖాతా కార్డ్ + మొదటి అడుగుల మార్గదర్శకత్వం
```

### చెల్లింపు పాత్ (యూజర్ సభ్యత్వం కోరినప్పుడు, లేదా ఉచిత పరీక్ష కాలం ముగిసినప్పుడు)

```
1–5. ఫాస్ట్ పాత్ లాగానే (register విజయవంతమైన తర్వాత స్థితిలో టోకెన్ ఇప్పటికే ఉంటుంది)
6.  login-link --target pending     # → అర్ధ-లాగిన్ లింక్, చెల్లింపు తిరిగి రాక పేజీ కొనసాగుతుంది
7.  (యూజర్ చెల్లింపు పద్ధతి ఎంచుకుంటాడు)
    # Alipay: create-order --package monthly|quarterly|yearly
    # PayPal: create-order --provider paypal
8.  start <చెల్లింపు పేజీ ఫైల్>    # Windows; macOS open, Linux xdg-open
    # → యూజర్ Alipay/PayPal క్యాషియర్‌లో చెల్లింపు/అనుమతి పూర్తి చేస్తాడు (సంభాషణ వదిలేయాలి)
9.  query (ప్రతి 10–15 సెకన్లకు) paid / ACTIVE వరకు
10. refresh-login                   # ACTIVE క్లెయిమ్‌తో కొత్త JWT కి మార్పు
11. login-link --target home        # → యూజర్‌కి పూర్తి సభ్యత్వ లింక్ పంపండి
12. whoami                          # subscriptionStatus: ACTIVE నిర్ధారించండి (ఐచ్ఛికం)
13. cleanup                         # స్థితి ఫైల్ శుభ్రం చేయండి
```
## కమాండ్ → ప్లాట్‌ఫారమ్ API మ్యాపింగ్

| స్క్రిప్ట్ కమాండ్ | ప్లాట్‌ఫారమ్ ఇంటర్‌ఫేస్ |
|---|---|
| `send-code` | `POST /api/auth/register/send-code` |
| `register` | `POST /api/auth/register` (multipart, ప్రొఫైల్ ఫోటో డైరెక్ట్ అప్‌లోడ్) |
| `login-link` | `GET /api/auth/me?token=…&redirect=…` (లింక్ అంతర్గతం, బ్రౌజర్‌లో క్లిక్ చేసినప్పుడు అమలవుతుంది) |
| `create-order` | `POST /api/payment/alipay/create-order` (Bearer, Alipay)<br>`GET /api/subscription/plans` + `POST /api/subscription/create` (Bearer, PayPal) |
| `query` | `GET /api/payment/alipay/query?outTradeNo=…` (Bearer, Alipay)<br>`GET /api/subscription/create` (Bearer, PayPal) |
| `refresh-login` | `POST /api/auth/login` (`{step:1, username, password}`) |
| `whoami` | `GET /api/auth/me?token=…` |

నియమాల ఆధారాలు: రిజిస్ట్రేషన్ ఫీల్డ్‌లు మరియు రేట్ లిమిట్ `registration-flow.md` లో; ప్లాన్‌లు మరియు యాక్టివేషన్ చైన్ `payment-and-activation.md` లో (రెండింటిలోనూ ప్లాట్‌ఫారమ్ సోర్స్ కోడ్ ఫైల్‌లు గుర్తించబడ్డాయి).

## ఫాల్‌బ్యాక్ మోడ్ (ప్యూర్ గైడెన్స్)

ఈ క్రింది ఏదైనా ఒక పరిస్థితి వచ్చిన వెంటనే v1 శైలి ప్యూర్ గైడెన్స్‌కు వెనక్కి వెళ్లండి, స్క్రిప్ట్‌తో ఇక తిరగవద్దు:

- Node ≥ 18 లేదు లేదా స్క్రిప్ట్ వరుసగా రెండుసార్లు అదే రకమైన వైఫల్యం;
- వినియోగదారు "నేనే వెబ్‌లో ఆపరేట్ చేస్తాను" అని స్పష్టంగా చెప్పడం;
- కంపెనీ/డివైస్ పాలసీ స్క్రిప్ట్ ఇంటర్నెట్ కనెక్షన్‌ను నిషేధించడం.

తిరిగి వెళ్లిన తర్వాత: నిర్మాణ పేజీ https://global.powpow.online/register ఇవ్వండి (ఉచిత పరీక్ష కాలంలో వెబ్ నిర్మాణం కూడా అదే రీతిలో తక్షణమే వాడదు; సబ్‌స్క్రిప్షన్ అవసరమైతే సబ్‌స్క్రిప్షన్ పేజీ https://global.powpow.online/subscription కూడా ఇవ్వండి), `registration-flow.md` నియమాల ప్రకారం పక్కనే సమస్యలు పరిష్కరించండి, అదే టోన్ నిలుపుకోండి, మరియు ప్రతి బారి కూడా "తదుపరి అడుగు" బ్లాక్‌తో ముగించండి.

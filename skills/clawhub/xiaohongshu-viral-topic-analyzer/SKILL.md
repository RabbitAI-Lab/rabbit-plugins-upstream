# 小红书爆款选题分析器

把「不知道发什么」变成「有一张可执行的选题表」。核心不是给灵感，而是给**带依据、带公式、带结构**的内容作战计划。

## 什么时候用

- 用户给出赛道/品类（如「露营装备」「考研英语」「宠物烘焙」），想要选题方向
- 用户有一篇写完的笔记，想知道为什么没人看、怎么改
- 用户要规划一周/一个月的内容节奏
- 用户做账号冷启动，需要「起号前 10 篇」的选题组合

## 输出契约（必须给全，不许只给标题）

对每个选题，必须输出以下 6 项，缺一项视为不合格：

| 字段 | 要求 |
|---|---|
| 选题标题 | 给 3 个变体，覆盖不同钩子类型 |
| 钩子类型 | 从 `references/hook-types.md` 里选，标明用了哪一类 |
| 目标人群 | 具体到「谁在什么场景下会点开」，不许写「年轻人」 |
| 流量逻辑 | 为什么这个选题在小红书有分发优势（搜索型/推荐型） |
| 竞争度 | 低/中/高 + 判断依据 |
| 内容结构 | 按 `references/note-structure.md` 给出分段骨架 |

## 工作流程

### 第 1 步：赛道拆解

把用户给的赛道拆成 4 类选题土壤（详见 `references/topic-matrix.md`）：

1. **痛点型** —— 用户踩过的坑（搜索流量稳，转化高）
2. **决策型** —— 「XX 怎么选/哪个好」（对比测评，长尾搜索强）
3. **场景型** —— 「XX 场景下的 XX」（代入感强，推荐流量好）
4. **情绪型** —— 「我为什么放弃 XX」（易爆但不可控，占比要控制）

比例建议：痛点 30% / 决策 30% / 场景 30% / 情绪 10%。

### 第 2 步：选题生成

每个方向至少产出 5 条，按「搜索意图强度 × 竞争度」排序，优先给**中低竞争 + 明确搜索意图**的。

生成时遵守：
- 标题必须包含**具体名词**（数字、品牌、地名、价格区间），不要「一些」「几种」这种虚词
- 每条选题都要能回答「谁会搜这句话」
- 避开平台已经饱和的红海词（可用 `references/competition-signals.md` 判断）

### 第 3 步：标题公式套用

从 `references/title-formulas.md` 的 18 个公式里选，每篇笔记给 3 个变体：
- 1 个搜索型（含关键词，利于长尾）
- 1 个情绪型（制造好奇/反差）
- 1 个身份型（「XX 人必看」）

### 第 4 步：结构骨架

按 `references/note-structure.md` 给出：
- 封面文案（3 行内，第一行定生死）
- 开头 2 秒钩子（前 20 字）
- 正文分段（每段一个小结论）
- 互动引导（提问式，不要「点赞关注」）

### 第 5 步：发布策略

给出发布时间、话题标签组合（大词 1 + 精准词 2 + 长尾词 2）、是否适合投流。

## 质量红线

以下情况必须重做，不许交付：

- 标题里出现「干货」「分享」「必看」这类零信息量词
- 选题无法回答「目标用户会主动搜索它吗」
- 3 个标题变体钩子类型重复
- 只给标题不给结构
- 用了「年轻人」「女性」「上班族」这种无法定位的人群描述

## 自检清单

交付前逐条核对：

- [ ] 每个选题都有 6 个字段
- [ ] 至少 3 条属于「低竞争 + 高搜索意图」
- [ ] 标题含具体名词，无空泛词
- [ ] 3 个变体钩子类型不重复
- [ ] 给出了封面第一行文案
- [ ] 话题标签是大词+精准+长尾的组合
- [ ] 没有任何「保证爆」「必火」类承诺

## 边界声明

- 不承诺流量结果，只提供选题与结构方法
- 不生成虚假体验（「我用了三个月」当没用过时必须说明是方法推演）
- 涉及医疗、金融、法律建议时，提示用户咨询专业人士

# 笔记结构模板（4 种）

## 通用原则

小红书读者的阅读路径是：**封面 → 标题 → 开头 → 划到底看结论 → 回头读中间**。

所以结构必须满足：
1. 结论提前（别把答案埋在第 8 段）
2. 每段一个独立信息点（可单独被截图传播）
3. 段落短（不超过 3 行，手机上超过 3 行就是「字墙」）

## 模板 A：测评/横评型

```
【开头钩子】具体测试条件 + 结论预览
   例：测了 8 款 200 元以内的，只有 2 款能长期用。

【测试方法】（1 段，建立可信度）
   怎么测的、测了多久、什么条件下

【逐个结论】（每个对象 2-3 行）
   ✅ 推荐款：型号 + 一句话理由 + 适合谁
   ❌ 不推荐款：型号 + 具体问题（不是「不好用」）

【横向对比表】（可选，提高收藏率）
   关键参数对照

【最终建议】
   预算有限选 X，追求 Y 选 Z

【互动】
   你用的是哪款？评论区说说
```

**关键**：不推荐的理由必须具体到「哪个功能在什么场景下出问题」。

## 模板 B：教程/方法型

```
【开头钩子】结果前置 + 时间成本
   例：这个方法我用了 3 个月，冰箱再没串过味。

【为什么有效】（1 段原理，30 秒能看懂）
   不讲原理的教程没有信任度

【分步骤】（3-5 步，每步一个动作）
   Step1 做什么 + 为什么这么做
   Step2 ...

【避坑点】（2-3 条，别人常做错的地方）
   ← 这一段是收藏率的主要来源

【适用边界】
   什么情况下不适用，说实话反而增加信任

【互动】
   你试过哪种方法？
```

## 模板 C：避坑/踩雷型

```
【开头钩子】代价前置
   例：这个决定让我多花了 2800 块。

【事情经过】（简短，不超过 3 句）
   不要写成日记，只留关键节点

【踩的坑】（编号列出，每条一个具体错误）
   坑 1：具体做了什么 + 导致什么后果
   坑 2：...

【正确做法】
   如果重来一次我会怎么做

【给同类人的提醒】
   什么情况下要特别注意

【互动】
   你踩过哪个？
```

**关键**：坑必须是自己真踩过的具体动作，不能是「要注意 XX」这种空话。

## 模板 D：场景故事型

```
【开头钩子】时间+地点+动作
   例：周五 11 点，方案改到第 7 版，电脑蓝屏了。

【场景铺开】（2-3 句，建立代入感）
   具体细节：环境、动作、当时的情绪

【转折/冲突】
   发生了什么，为什么值得写

【处理过程】
   怎么解决的，用了什么

【结果 + 反思】
   结果是什么，事后看有什么不同

【互动】
   你遇到过类似的情况吗？
```

**关键**：细节要真实（品牌、时间、动作），但不能流水账。

## 封面文案规范

封面是**唯一的点击决定因素**，优先级高于标题。

结构：
```
第一行（最大字号）：核心结论或冲突（6-10 字）
第二行（次大）：限定条件（4-8 字）
第三行（小字，可选）：补充信息
```

示例：
```
别买侧吸油烟机        ← 结论
小户型尤其注意        ← 限定
装完半年才明白        ← 补充
```

**禁止**：
- 封面全是装饰文字（「分享」「日常」）
- 一行超过 12 字（手机上会挤成一片）
- 用 emoji 代替关键词

## 互动引导规范

**有效**：
- 「你家是哪种情况？」（二选一，回答成本低）
- 「有没有人跟我一样…」（找同类，触发共鸣）

**无效**（等于没写）：
- 「点赞关注不迷路」
- 「欢迎评论区留言」
- 「喜欢就收藏吧」

## 自检

- [ ] 结论在前 1/3
- [ ] 每段不超过 3 行
- [ ] 有独立的「避坑点」或「不推荐理由」段
- [ ] 封面第一行 ≤10 字且含结论
- [ ] 互动问题是二选一或找同类
- [ ] 全文没有「点赞关注」

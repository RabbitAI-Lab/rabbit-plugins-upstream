## 一、医案按病种分类体系

### 当前状态
25 篇诊疗经验文章以 JSON 知识卡形式存储于 `data/cards/experiences/`，无病种分类。

### 借鉴方案
当诊疗经验积累到 50 篇以上时，创建 `professor-wangqi/cases/` 目录，按病种组织：

```
cases/
├── 01_metabolic.md        # 代谢类：肥胖、糖尿病、代谢综合征
├── 02_mental.md           # 精神类：失眠、抑郁、焦虑
├── 03_respiratory.md      # 呼吸类：哮喘、过敏性鼻炎
├── 04_cardiovascular.md   # 心血管类：高血压、冠心病
├── 05_digestive.md        # 消化类：功能性消化不良、便秘
├── 06_other.md            # 其他病种
```

### 实施条件
- 诊疗经验卡 ≥ 50 篇
- 每个分类至少有 5 篇以上的内容
- 有明确的病种标签（从 ontology.md 的疾病表中匹配）

### 参考实现
见倪海厦 skill `cases/` 目录结构（6 个病种分类文件，共 245 例医案）

### 借鉴方案

在 SKILL.md 中内嵌以下核心知识，使 skill 在无 Python 环境下也能回答基础问题：

1. **九种体质完整描述**（已部分完成：SKILL.md §四·诊断公式）
2. **辨体论治原则与方法**（已部分完成：SKILL.md §四·决策树）
3. **核心方药速查表**（已存在于 ontology.md）
4. **核心研究结论摘要**（待补充）

### 实施条件
- 需从 38 张知识卡中提炼核心结论

- 内嵌内容的总量控制在 SKILL.md 不超过 3000 行

### 参考实现

## 五、完整知识蒸馏管线

### 当前状态
知识提取脚本（`scripts/extract_knowledge_cards.py`）将 PDF 转为 JSON 知识卡。

### 借鉴方案
当数据规模增长后，构建完整蒸馏管线：

```
原始 PDF/Word/录音转录文本
    ↓ [阶段1: 初步提取]
结构化文本（去噪、分段、标注来源）
    ↓ [阶段2: 知识卡提取]
JSON 知识卡（当前已有）
    ↓ [阶段3: 摘要蒸馏]
Markdown 知识模块（按主题合并，去重）
    ↓ [阶段4: 内嵌整合]
SKILL.md 内嵌知识（精选核心结论）
```

### 实施条件
- 原始资料 ≥ 100 篇
- 有可用的 LLM 进行语义级蒸馏
- 有人工审核环节确保质量

### 参考实现
见倪海厦 skill `references/research/` 目录（8 个研究分析文件 + 蒸馏日志）

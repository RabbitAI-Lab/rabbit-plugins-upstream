# 亚马逊商品套图规划、生成与验收规范

> 版本: v1.4.1
> 整理维护: Quiet_Phoenix

依据商品资料和实际制作条件, 完成套图策划、逐图说明、图片制作或审核。按用户要求选择工作深度; 不假定环境具有生图、浏览器、OCR、图片元数据、脚本或特定模型能力。

## 中文与表达约定

- 标题、说明、版位名称、设计依据、缺口和审核结论中文优先; 用户指定其他语言时跟随用户。
- 图片内文案、替代文本和面向买家的文字跟随目标站点及用户指定语言。
- `slot_id` 等字段、状态码、版位编号和准确的平台模块名称保留可交换标识, 展示时先写中文含义。
- 生图说明默认使用中文, 工具或任务确有需要时使用其他语言。区分说明语言与画面文案语言。

## 信息取舍与展示

- 信息减法属于设计与交互的一部分。优先用准确名称、版式和清晰层级表达用途, 删除重复标题、口号、装饰性说明和无关的标签。
- 加入一条说明前, 判断删掉后目标用户会发生什么具体误判。没有实际理解缺口时省略, 不把冗余说明转成提示气泡继续保留。
- 默认展示完成当前任务需要的内容, 并保留上述任务首次回复的署名与主页链接。许可和版本保留在规范与来源资料中; 内部字段、状态码、完整审核表和过程记录按需提供, 不要求每次向用户宣读。
- 与当前决定有关的数量、尺寸、费用、使用范围、重要偏差、错误和恢复动作就近保留。仅在特定条件下有用的说明, 在该条件出现时展示; 有额外价值的细节可按需展开。

## 工作模式与交付阶段

| 工作模式 | 本次主要交付 |
|---|---|
| 套图规划 | 范围、商品依据、整套设计语言、版位分工及缺口 |
| 生图说明 | 可独立执行的逐版位说明、附图映射和必要的双端关系 |
| 图片制作 | 方案、实际图片、版本选择及已有能力支持的审核 |
| 图片审核 | 逐图问题、证据、可用范围和修改优先级 |
| 模板复用或返修 | 本次保留与变化的内容、商品适配、参考素材和新版本 |

同时标明交付阶段: `PLAN` 为方案, `PREVIEW` 为概念或预览稿, `FINAL` 为面向约定用途的成品。用户只需规划或预览时, 完成该阶段即可, 不额外要求完成图片生成或平台上传。

## 实际条件与降级原则

**产品还原、事实完整性、平台适配、交付范围和工具能力均允许按实际条件降级。先产出当前条件下有用的结果, 同时说明假设、偏差和适用阶段。**

产品身份不完整时可近似还原; 证据不足时可合理推断、定性表达或制作示意; 平台条件未满足时可继续制作候选方案和预览稿。已确认内容、推定内容与创意设定分别记录, 检查结果保持真实。

降级只影响有关版位、检查项或用途, 不自动阻断整套任务。记录缺少什么、采用何种替代、影响哪里、如何补齐。普通调整直接继续; 只有无法自行判断且会改变用户核心目标的选择才询问。具体做法见 [降级策略与交付状态](references/degradation-and-delivery.md)。

## 执行流程

### 1. 明确本次范围

根据上下文确定工作模式、目标站点、商品或目标变体、所需图数、输出语言、A+ 类型及交付阶段。已有信息足以推进时直接继续。未知站点、类目、权限或模块规格记录为待确认条件, 可以先按候选模板出稿。

### 2. 整理商品依据和素材角色

读取 [商品依据与素材引用](references/input-and-facts.md), 区分已确认、图中可见、推定、创意设定与未知信息, 确定当前采用的商品身份依据。保留来源和相互矛盾的内容。

区分本品事实图、风格参考图和已选成品。附图说明使用当前工具实际可寻址的编号或标识, 记录最终请求内的顺序及用途。参考图可提供构图和视觉表达, 不自动成为本品事实。

### 3. 确定版位与信息分工

读取 [版位、尺寸与平台适配](references/slots-and-dimensions.md)。图数以用户需求、模板和内容密度为准; 未指定时从 1 张主图、按需选择的副图和适用 A+ 模块开始, 不强制凑满。

用户指定“系统模板 · 亚马逊套图”, 或希望从完整套图结构开始时, 阅读 [系统模板 · 亚马逊套图参考](references/system-amazon-image-set.md)。该参考整理了 1 张主图、7 张副图及 7 组 A+ 双端的版位分工, 可按商品、素材和本次目标调整, 不作为所有任务的固定图数。

副图一图回答一个主要购买问题, 缩略图也能识别主要信息。A+ 优先补充副图尚未展开的解释、选择、操作、疑虑和品牌理解。同一卖点再次出现时换论证角度或画面表达, 避免只把副图拉成横幅。不把应用默认图数、内容分类比例或模块菜单写成平台统一要求。

用户写明的版位目标与参考用途优先保留; 智能占位由 Agent 补为具体名称、目标与构图。未要求主图时, 不自动把首张副图改成 MAIN。

### 4. 建立整套设计语言和双端关系

读取 [整套设计语言与多端排版](references/composition-and-devices.md), 确定配色、字体层级、背景、光线、版式节奏、主体比例和允许变化。已有品牌要求直接采用, 空缺部分结合产品和受众补全。

A+ 双端共享主题、主要信息和当前采用的商品状态, 各自重排。缺少一端时可先交另一端及重排说明, 明确配对完成情况。

### 5. 编写和执行逐图说明

读取 [逐版位生图说明](references/prompt-contract.md)。每张说明自包含, 写清商品依据、允许的近似或假设、画面内容、准确文案、实际附图映射及尺寸。

先做与本次阶段相称的方案检查, 再在已有授权内调用工具。不默认增加人工确认 Gate。需要探索时先做代表性图片, 选定后作为其余版位的参考; 用户要求并行或一次完成时按实际能力安排。

### 6. 审核、返修与交付

读取 [审核、返修与交付清单](references/quality-review.md)。方案审核和成图审核分开, 未执行的检查标为待核验。按交付阶段报告可用结果, 对失败项优先修订或降级。

返修写明依据版本、本次变化与保留内容。局部修改优先使用当前选中版本和本次需求; 重新策划或深度修改再按需引入产品资料、整套设计语言和原始参考。每次都记录实际使用的输入, 不默默附加旧素材。

## 按任务交付

按本次模式提供必要内容, 可合并短任务中的重复表格:

- 范围与交付阶段, 当前采用的商品依据和假设。
- 版位分工, 需要时附整套设计语言、尺寸和双端关系。
- 用户要求的逐图说明、实际图片或逐图审核结果。
- 降级、缺失或待复核项, 以及完成当前阶段后的可用范围。
- 有实际图片时列出选用版本和文件; 需要上传素材时补模块、替代文本与上传准备情况。

用简短中文说明当前可用结果和必要的下一步。需要结构化交换时, 状态定义、检查状态及上传准备情况统一以 [降级策略与交付状态](references/degradation-and-delivery.md) 为准。方案或预览阶段可以完成, 不必等待上架条件齐全。

## 冲突、复用与维护

- 当前任务的目标、交付阶段、明确模板和授权决定工作范围。平台规则用于判断平台适配, 不自动阻止概念或预览制作。
- 商品依据有冲突时保留来源并说明本次选择; 影响核心身份且无法判断时给出候选版本或进行必要询问。
- 品牌要求和用户指定内容优先于本 Skill 的默认构图, 默认规则可随素材、工具和用途调整。
- 复用模板时分开保留视觉形式与商品信息, 将旧品牌、旧尺寸、旧数量和旧声明替换为本次内容。保存模板来源、采用版本和必要的实例快照; 更新模板不表示历史产物或应用执行逻辑已同步更新。
- 维护主文件、相关参考、展示元数据和发布说明的一致性。只在实际实施范围内报告同步, 不以改文档代替应用链路验收。

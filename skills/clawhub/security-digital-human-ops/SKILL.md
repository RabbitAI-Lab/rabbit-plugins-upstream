- **场景B｜AI标识补位**：已发布的数字人短视频未加标识 → 按"显式标识优先"原则补片头字幕角标，并在简介首行追加"本视频由AI数字人生成"，避免下架返工。

- **场景D｜素材授权追溯**：采购的数字人形象无书面授权 → 命中"授权链条需可追溯" → 建立授权台账，登记形象/声音素材ID、授权范围、有效期与到期提醒，未登记素材不得进入生产排期。

- **场景E｜存量物料补标**：2026年上半年发布的数字人短视频共120条，其中38条无AI标识 → 按“存量回溯、新增强制”两步走：存量按播放量降序补标（Top 20优先，7个工作日内完成），新增物料把标识核验设为投放前置卡点，未过核验不得进入投放队列。
- **场景F｜话术留痕绑定**：直播复盘时发现同一场直播存在3个话术版本，无法确认实际播出版本 → 命中“话术留痕要求提高” → 建立“话术版本-成片ID-播出时段”三元组台账，直播回放与话术版本按场次归档，保存期限不少于3年，稽查时可一键定位。

### 1. Script Generation / 脚本生成

```python
SCRIPT_TEMPLATES = {
    "产品介绍类": {
        "时长": "2-3分钟",
        "结构": """
        【开场 Hook】（0-15秒）
        - 痛点引入："你是不是也遇到过...？"
        - 数据吸引："90%的人都不知道的..."
        
        【自我介绍】（15-30秒）
        - 虚拟形象介绍
        - 今日主题预告
        
        【核心内容】（1-2分钟）
        - 产品/服务介绍（3个卖点）
        - 场景化案例
        - 限时优惠/福利
        
        【行动号召 CTA】（15-30秒）
        - 关注引导
        - 评论区互动
        - 私信/链接
        
        【结尾】（0-15秒）
        - 回顾要点
        - 下期预告
        """
    },
    
    "知识科普类": {
        "时长": "1-2分钟",
        "结构": """
        【开场】："今天教你一个..."
        【问题】："为什么..."
        【解答】："因为..."
        【案例】："举个例子..."
        【总结】："所以..."
        """
    }
}

def generate_script(script_type: str, params: dict) -> dict:
    """
    生成数字人直播/视频脚本
    """
    template = SCRIPT_TEMPLATES.get(script_type)
    if not template:
        return {"error": "未知脚本类型"}
    
    # 生成台词
    script_content = generate_script_content(script_type, params)
    
    # 生成AI提示词
    ai_prompts = generate_ai_prompts(script_type, params)
    
    # 生成分镜
    storyboard = generate_storyboard(script_type, params)
    
    return {
        "script_type": script_type,
        "duration": template.get("时长", ""),
        "structure": template.get("结构", ""),
        "content": script_content,
        "ai_prompts": ai_prompts,
        "storyboard": storyboard
    }
```

**示例 2｜知识科普脚本（1分钟，"三清"话术改造）**

- 讲什么：**"业绩比较基准" ≠ "预期收益率"** —— 前者是管理人设定的参考目标，后者不再适用于净值型产品。
- 怎么讲：先给错误说法（"这款产品预期收益4%"），再纠正，再给出客户自查三步（看产品说明书 / 看风险等级 / 看历史净值曲线）。
- 改造后话术："本产品的业绩比较基准为X%，这是管理人设定的参考目标，不构成收益承诺，实际收益以到期净值计算为准。"

```markdown
| 合规审核前置时长 | ≥1个工作日 | 未留足则顺延排期 | 未审先发，返工与下架风险 |
| 同一形象单日出镜上限 | ≤2条 | 防止人设疲劳，切换备选形象 | 人设疲劳，互动率下滑 |
| 热点借势响应时效 | ≤24小时 | 超时则放弃该热点 | 热点过期，选题失效 |
| 单周AI标识复核覆盖率 | 100% | 未覆盖的物料不得投放，补标识后重排 | 无标识投放被平台下架 |
| 单周素材授权校验覆盖率 | 100% | 授权缺失物料冻结，补齐台账后释放 | 肖像/声音侵权纠纷 |
| 同一选题复用间隔 | ≥3周 | 间隔不足则替换角度或改为系列续集 | 选题重复，用户审美疲劳 |
```

**示例 4｜排期容量测算（避免超载）**

- 输入：可用运营2人、合规复核1人、单条脚本合规复核耗时约0.5小时、单个工作日可复核上限8条。
- 结论：单周可承载物料上限 = 8条/日 × 5日 = 40条；按"7天×1条 + 直播切片3条"的常规强度（约10条），合规产能冗余充足。
- 触发条件：若单周排期超过24条（占用合规产能60%），则启动预审分流——通用科普类走"模板化预审"，仅产品类逐句复核。

**示例 5｜合规产能冲突的分流方案**

- 输入：某周排期28条，其中产品类12条、科普类10条、UGC类6条；合规复核产能40条/周，但逐句复核仅能覆盖16条。
- 冲突点：产品类12条 + 科普类10条 = 22条超过逐句复核产能16条，若全部逐句复核将拖累发布时效。
- 分流方案：产品类12条全部逐句复核（合规亲审）；科普类走“模板化预审”——使用已过审的话术模板库，仅对新增段落逐句核；UGC类抽查30%。
- 兜底：预审放行的科普内容若出现违规，回溯到模板维护人并冻结该模板，待修订后重新过审。

### 3. Performance Analytics / 效果分析

```python
class DigitalHumanAnalytics:
    """数字人效果分析"""
    
    def analyze_performance(self, video_stats: dict) -> dict:
        """
        分析视频/直播效果
        """
        # 核心指标
        metrics = {
            "播放量": video_stats.get("views", 0),
            "完播率": video_stats.get("completion_rate", 0),
            "点赞数": video_stats.get("likes", 0),
            "评论数": video_stats.get("comments", 0),
            "转发数": video_stats.get("shares", 0),
            "关注转化": video_stats.get("follows", 0)
        }
        
        # 计算互动率
        engagement_rate = (
            (metrics["点赞数"] + metrics["评论数"] + metrics["转发数"]) /
            max(metrics["播放量"], 1) * 100
        )
        
        # 评分
        score = self._calculate_content_score(metrics)
        
        return {
            "metrics": metrics,
            "engagement_rate": round(engagement_rate, 2),
            "content_score": score,
            "optimization_suggestions": self._get_suggestions(metrics),
            "benchmark_comparison": self._compare_to_benchmark(metrics)
        }
    
    def _calculate_content_score(self, metrics: dict) -> float:
        """内容评分（满分100）"""
        score = 0
        
        # 完播率（30分）
        score += min(metrics["完播率"] / 100 * 30, 30)
        
        # 互动率（40分）
        engagement = (
            (metrics["点赞数"] + metrics["评论数"]) /
            max(metrics["播放量"], 1)
        )
        score += min(engagement * 400, 40)  # 2.5%互动率=满分
        
        # 关注转化（30分）
        follow_rate = metrics["关注转化"] / max(metrics["播放量"], 1)
        score += min(follow_rate * 3000, 30)  # 1%关注率=满分
        
        return round(score, 1)
```

**示例 1｜单条视频评分计算（手算核对）**

| 输入指标 | 数值 |
|---------|------|
| 播放量 | 50,000 |
| 完播率 | 42% |
| 点赞数 | 900 |
| 评论数 | 180 |
| 转发数 | 120 |
| 关注转化 | 350 |

计算过程：

- 完播率得分 = min(42/100×30, 30) = **12.6**
- 互动率得分 = min((900+180)/50000×400, 40) = min(8.64, 40) = **8.64**
- 关注转化得分 = min(350/50000×3000, 30) = min(21, 30) = **21.0**
- 综合内容评分 = 12.6 + 8.64 + 21.0 = **42.2**（满分100）
- 互动率 = (900+180+120)/50000×100 = **2.40%**

诊断：完播率偏弱（42% < 60% 健康线）是主要失分项，建议把前15秒 Hook 压缩到一句话、把核心结论前置。

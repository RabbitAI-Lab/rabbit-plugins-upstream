# goods_sku_price_trend

SKU 层历史价格趋势。按 `goods_id` + `sku_id` 返回该 SKU 在多个价格类型下的最高价、最低价和价格点序列。它是三个趋势工具里唯一分价格类型的，也是唯一用时间戳而不是日期的。

## 入参

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| goods_id | string | 是 | 识货商品 ID，不透明字符串，固定 12 字符、区分大小写，原样取自工具返回值 |
| sku_id | string | 是 | 识货 SKU ID，不透明字符串，固定 12 字符、区分大小写，原样取自工具返回值。值取自 `search_sku.skus[].goods_sku_id` 或 `link_parse.results[].goods_sku_id`，但参数名必须写 `sku_id`，不能写 `goods_sku_id` |

两个参数都必填，缺任一个返回 `input_required`。无 `page`、日期范围或价格类型参数；返回哪些价格类型、覆盖多长时间都不固定，以返回值为准，不能通过入参控制。

## 响应字段解释

| 路径 | 类型 | 是否恒有 | 含义 | 展示与限制 |
| --- | --- | --- | --- | --- |
| data.goods_id | string | 是 | 回显的商品 ID，不透明字符串，固定 12 字符、区分大小写 | 与请求核对，确认没有串实体 |
| data.sku_id | string | 是 | 回显的 SKU ID，不透明字符串，固定 12 字符、区分大小写 | 同上；只代表这一个规格 |
| data.price_trends | array | 是 | 价格类型分组列表 | 成功时至少 1 组。组数和类型名不固定，以返回值为准，不假定固定几种 |
| data.price_trends[].type | string | 是 | 价格类型名，中文文案，如 `全网最低`、`国补最低`、`优选最低` | 直接展示原文，不改写、不翻译、不合并同类；每条价格结论都必须带类型名 |
| data.price_trends[].max_price | string | 否 | 该类型区间最高价，格式 `￥550` | 与价格点同口径，只基于列表里的有效点；为 0 时是空串 |
| data.price_trends[].min_price | string | 否 | 该类型区间最低价 | 同上。这是“该价格类型的历史最低”，不是当前可买到的价 |
| data.price_trends[].price_trends | array | 是 | 该类型下的价格点列表 | 至少 1 个点；缺价点和价格 ≤ 0 的点不会出现在列表里，序列可不连续 |
| data.price_trends[].price_trends[].timestamp | number | 是 | 价格点时间，**秒级** Unix 时间戳（10 位，如 `1785945600`） | 不是毫秒，换算前不要乘 1000；转日期按接口时区口径，只展示到日 |
| data.price_trends[].price_trends[].price | string | 是 | 该点价格，格式 `￥11`、`￥15.5` | 已带 `￥`，不要重复加符号 |

注意字段名嵌套：外层 `data.price_trends` 是**类型分组**，每组里还有一个同名的 `price_trends` 才是**价格点**。写路径和取值不要漏掉中间一层。

`min_price`/`max_price` 是现成的区间结果，直接用，不自己遍历价格点重算；两者与价格点口径一致（都只基于有效点）。

价格点顺序以接口返回为准，不假定升序或降序，也不假定与其他类型对齐。取最近点前必须先按 `timestamp` 排序，不能直接取首位或末位。

## 价格类型名是什么意思

`type` 是接口给的口径名，对用户是内部说法。它决定这条结论覆盖什么范围、附带什么前提：

| 接口类型名 | 这个口径指什么 | 读它时要留住的前提 |
| --- | --- | --- |
| 全网最低 | 不限渠道、不叠加额外补贴时记录到的最低价 | 它是历史记录点，不是当前任何渠道的到手价 |
| 国补最低 | 叠加国家补贴后记录到的最低价 | 补贴能不能享受取决于用户资质和渠道活动，本工具不返回资格条件，一律不承诺可享 |
| 优选最低 | 识货优选渠道范围内记录到的最低价 | 范围小于全网，不能当作全网口径 |

表里没有的类型名照抄原文、不归并到上面三种，也不猜它包含什么，只把它当作“接口给出的一种价格口径”陈述。

类型名照抄不等于把口径说清：结论里出现补贴类或范围受限的类型时，同一句要带上表中的前提，不能只给一个价格。

## 每个字段能支撑哪类结论

缺字段就整块省略，不推测、不预测未来走势。

| 字段 | 能支撑 | 不能支撑 |
| --- | --- | --- |
| type | 这条结论属于哪个价格口径 | 该口径的价格现在能不能买到 |
| min_price | 该类型在返回区间内的历史最低 | 全网历史最低、当前可买价、其他类型的低点 |
| max_price | 该类型在返回区间内的历史最高 | 常态价、原价、建议零售价 |
| price_trends[].timestamp | 某个价格点出现在哪一天、哪个点最近 | 覆盖了完整多少天，缺价的日期不在列表里 |
| price_trends[].price | 该时点该类型记录到的价格 | 当前售价、到手价、下单能拿到的价 |
| 该类型有效点数 | 记录点多还是少，点少时说明“该类型历史记录点较少” | 价格是否稳定、是否值得买 |
| 等于 `min_price` 的点数 | 该低点出现过几次：1 次是偶发，多次是重复出现过的价位 | 该低点还会不会再出现 |
| ≤ 用户目标价的点数及最近日期 | 历史上有几天达到过用户给的目标价、最近一次是哪天 | 未来能不能等到这个价 |

按用户问题选择该类型的历史低点、日期、低点出现次数、最近记录或允许计算的差额，不强制同时展示全部统计项。用户给出目标价时可统计该类型有几个点不高于目标价以及最近一次日期；覆盖范围和有效点数按需说明。有效点 ≥ 2 且按 `timestamp` 排序后顺序明确时才可以带一个方向词，并给出对比的两个日期与价格。

差额可以同时给绝对值和百分比，百分比是该差额除以**同一个 type 的** `min_price`、取整。跨 type、跨实体层、跨价格层一律不换算百分比，与渠道到手价之间也不换算。

按自然月聚合每月最低价是允许的，但本工具时间窗不固定且价格点稀疏，只在该类型有效点 ≥ 20 且跨 ≥ 3 个自然月时才给，且只写月份和价格。不写具体大促日期、活动名，也不把某个月的低点归因到任何活动或写成“下次大促会更低”。

“低位、偏高、抄底、值得买、可以入”这类判断没有字段支撑，一概不写。

## 哪些字段之间不能相减

只有一处相减是允许的：同一个 `type` 内，最近价格点与该类型的 `min_price`。其余组合都是跨口径或跨实体层，写出来就是错的：

| 不能相减的两端 | 原因 |
| --- | --- |
| 不同 `type` 的 `min_price`、`max_price` 或价格点 | 口径不同，含补贴与不含补贴、全网与优选范围不可比 |
| 本工具任何价格 与 `goods_sku_price_comparision` 的渠道到手价 | 历史价与当前到手价是两层价格，且时点不同 |
| 本工具任何价格 与 `goods_link_query` 的 `current_final_price`、`price_before_coupon`、`history_low_price` | 前者是识货同一 SKU 的历史价，后者是单个渠道链接的快照与渠道侧 180 天低点 |
| 本工具任何价格 与 `goods_price_trend`、`goods_style_price_trend` 的价格 | 实体层不同，SKU 不代表商品或款式 |
| 本工具任何价格 与 `search_sku`、`goods_styles`、`search_goods_by_*` 的展示价 | 展示价与历史价是两层价格 |

同时出现多个来源的价格时各自标注来源，不取其中更低的那个当统一结论，也不合成“该 SKU 历史最低是 ￥X”这种不带类型名的说法。

数据不足口径：整体无数据由工具返回 `not_found`，直接说明未取得该 SKU 的历史价格，不生成价格结论；某个类型只有 1 个点时只陈述该点日期和价格，不写高低点对比和方向。

## 调用说明

前置条件是已确认唯一 SKU，即同时拿到 `goods_id` 和 `sku_id`；依据用户条件与真实工具结果匹配，用户要帮选或允许参考规格时可根据需求选择并说明完整参考规格，不设固定排序选择规则。适用于问某一规格的历史价格、近期价格变化、有没有到过低点、不同价格类型走势；只问历史时不强制追加当前比价。

不适用：还没定位到 SKU（先 `search_goods_by_keyword` 或 `search_goods_by_image` → `goods_styles` → `search_sku`）、只问商品或配色整体历史（用 `goods_price_trend`、`goods_style_price_trend`）、要当前到手价和购买入口（用 `goods_sku_price_comparision`）、要商品参数或热度（用 `goods_detail`）。

历史价不等于当前渠道到手价，趋势不替代比价：用户问“现在哪里买便宜”必须调比价工具，不用 `min_price` 回答。

结果处理按 `index.md` 的“失败与异常处理”：缺 ID 时返回 `missing_param`，补齐并注意参数名是 `sku_id`；无效或已失效 ID 返回 `invalid_id`，重新调用搜索工具获取且不得用同值重试；`not_found` 不用同参数重试；`failed` 的重试按通用规则执行，最终仍失败时保留已确认的 SKU 信息并说明历史价格未取得。

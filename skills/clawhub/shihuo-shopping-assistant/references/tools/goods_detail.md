# goods_detail

商品层事实。按 `goods_id` 返回商品参数、热度信息和鉴别记录汇总，不含款式、SKU、价格趋势和渠道报价。

## 入参

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| goods_id | string | 是 | 识货商品 ID，不透明字符串，固定 12 字符、区分大小写，原样取自工具返回值 |

无分页参数，一次返回全部内容。

## 响应字段解释

`data` 为对象。三个业务块都是可选的，任意块缺失只表示该块无数据，不影响其他块。

| 路径 | 类型 | 是否恒有 | 含义 | 展示与限制 |
| --- | --- | --- | --- | --- |
| data.goods_id | string | 是 | 查询的商品 ID | 用于证据链核对，不向用户展示 |
| data.goods_params | array | 否 | 商品参数项列表 | 整块可能缺失；只展示与用户问题相关的项，不逐条罗列全部 |
| data.goods_params[].name | string | 是 | 参数名，如“上市时间”“鞋帮高度” | 原样展示，不改写、不归并成自己的分类 |
| data.goods_params[].values | array(string) | 是 | 该参数的取值，可能多值 | 多值用顿号连接后展示 |
| data.hot_info | array(string) | 否 | 热度、榜单或讨论类文案，已是成句文本 | 原样引用，标为热度信息 |
| data.check_records | object | 否 | 鉴别记录汇总，整块可能缺失 | 只代表识货站内商品层的鉴别记录 |
| data.check_records.total_count | number | 是 | 商品层鉴别记录总数 | 与 `list` 的条数区分：`list` 只是样本，`total_count` 才是总量 |
| data.check_records.list | array | 是 | 鉴别记录样本列表 | 可能为空数组；不代表某个渠道、某个卖家或用户将收到的实物 |
| data.check_records.list[].username | string | 是 | 提交鉴别的用户名 | 属于第三方用户信息，默认不展示 |
| data.check_records.list[].time | string | 是 | 鉴别时间，格式不固定的文本 | 原样展示，不改写成相对时间 |
| data.check_records.list[].status | string | 是 | 鉴别结论文案 | 原样引用 |

## 每个字段能支撑哪类结论

按用户问的内容取块，不整块搬运。用户问的维度不在返回里，就说明这项没有数据，不用相近字段替代。

| 字段 | 能支撑 | 不能支撑 |
| --- | --- | --- |
| goods_params[].name + values | 参数、配置、规格类问题，逐项对齐用户问的维度 | 材质好坏、性能表现、适用场景、适合人群、耐用性 |
| hot_info | 站内热度、榜单、讨论情况，固定标明是站内热度信息 | 质量好、值得买、适合用户、正品保证、销量排名的因果 |
| check_records.total_count | 固定口径“站内已有 N 条鉴别记录” | 假货率、正品率、某个渠道或卖家的可信度 |
| check_records.list[].status + time | 举例说明样本里出现过哪些鉴别结论及时间 | 绝对真伪、用户这次会收到什么货、总量分布 |

商品介绍类结论只用 `goods_params`：把用户问的维度逐项对上，参数名原样使用，不从取值推导材质、性能或使用感受。

热度和鉴别记录都只陈述站内事实；按用户所问选择数量或样本证据，热度不作推荐理由的唯一支撑，鉴别记录只能说明样本情况。

体验、优缺点、适合人群、使用场景不在本工具范围内，必须来自 `goods_notes` 的真实内容，不从参数或热度推断。

本工具不返回任何价格字段，也不返回可与价格相减的数值，价格结论一律不引用它；`total_count` 与销量、库存、评分不是同一口径，不互相换算。

## 调用说明

前置条件只有一个：已确认的 `goods_id`。用户问题需要商品参数、热度或鉴别记录事实时调用；只问这些内容时直接回答，不强制追加配色、SKU 或比价查询。

不适用：找商品（用 `search_goods_by_keyword` 或 `search_goods_by_image`）、配色和款式列表（用 `goods_styles`）、规格与 SKU（用 `search_sku`）、历史价（用三个趋势工具）、当前渠道价（用 `goods_sku_price_comparision`）。

结果处理按 `index.md` 的“失败与异常处理”：`not_found` 说明该商品无详情数据，不用同参数重试；`failed` 的重试按通用规则执行，仍失败时保留已确认的商品信息并说明详情未取得，不用其他商品的详情补齐。

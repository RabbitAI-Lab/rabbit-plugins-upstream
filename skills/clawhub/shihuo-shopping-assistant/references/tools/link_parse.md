# link_parse

链接定位工具。把商品链接或含链接的分享文本解析成识货站内的三层 ID，只做 ID 绑定，不返回标准链接、平台、店铺、价格、优惠和库存。

## 入参

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| link | string | 是 | 用户给出的**完整原文**：可以是渠道商品链接、短链、淘口令或整段分享文本。空串或纯空白返回 `input_required` |

必须传用户原话，不截断、不只截取其中的 URL、不删掉前后中文和符号。淘口令和分享文本的识别依赖这些上下文，截断会直接导致解析失败。无分页参数。

## 响应字段解释

`data` 为对象。三个 ID 都是不透明 string，固定 12 字符、区分大小写，未定位时为空字符串。

| 路径 | 类型 | 是否恒有 | 含义 | 展示与限制 |
| --- | --- | --- | --- | --- |
| data.results | array | 是 | 解析结果列表 | 保留接口原顺序，逐条独立处理；不合并、不去重成一条，也不假定第一条最相关 |
| data.results[].goods_id | string | 是 | 商品层绑定 ID | 非空才确认商品层 |
| data.results[].goods_style_id | string | 是 | 款式/配色层绑定 ID | 非空才确认款式层 |
| data.results[].goods_sku_id | string | 是 | SKU 层绑定 ID | 非空才确认 SKU 层；作为价格工具入参时字段名要写成 `sku_id` |

三个 ID 一律不向用户展示，只用于后续调用和证据链核对。

## 三个 ID 怎么判定

**每层独立判断，互不推导。** 最容易出错的几点：

1. 空串表示该层未定位，不拿它当参数调任何工具，也不改写成默认值、第一个款式或第一个 SKU。
2. 上层为空不影响下层。`goods_style_id` 为空而 `goods_sku_id` 有效时，SKU 层仍是已确认的，不因为缺款式丢掉 SKU。
3. 下层有效也不反推上层。`goods_sku_id` 有效不代表可以凭空构造 `goods_id`；SKU 价格工具需要 `goods_id + sku_id` 两个都真实存在才可调用。
4. `results` 有多条且指向不同商品时，结合用户已给条件匹配；只有无法依据现有条件确定、且会影响结论的绑定歧义才展示真实候选并追问，不按返回顺序选定对象。
5. 三个 ID 全为空时视为未绑定，不进入需要识货 ID 的商品工具、趋势和比价；请用户补充商品文字或重新提供可解析的链接。

## 解析结果到下一步

| 已确认层级 | 可以直接做的事 |
| --- | --- |
| 只有 `goods_id` | 商品详情、款式列表、笔记、商品层趋势 |
| `goods_id` + `goods_style_id` | 追加款式层趋势；用 `search_sku` 收口到具体规格 |
| `goods_id` + `goods_sku_id` | 直接调用 SKU 趋势和比价，无需强行补 `style_id` |
| 全为空 | 请用户补充商品信息或重新提供可解析的链接 |

明确要做全网比价但只有 `goods_id` 时不猜默认 SKU，先按 `goods_styles` → `search_sku` 补齐配色 / 规格并确认 SKU；信息充分时直接继续，仍有影响结论的歧义才展示真实选项并追问。比价结果按所在场景 `output.md` 的模块骨架展示。

## 调用说明

用户消息里出现明确商品链接或分享文本，且需要定位识货商品、款式或 SKU 时调用；从链接直接取得真实定位结果后可以复用，不强制重新关键词查询或重复确认。

不适用：查链接渠道价格、优惠券、库存、活动（用 `goods_link_query`）、查同 SKU 其它渠道报价（用 `goods_sku_price_comparision`）、识货站内关键词或图片搜索、下单加购订单类请求。本工具不返回任何价格字段。

结果处理按 `index.md` 的“通用响应约定”：`input_required` 说明没传到有效 `link`，补齐原文重试；`not_found` 表示这条链接无法绑定识货商品，说明未能定位并按需请用户补充商品信息，不把链接标题、图片或渠道商品名当作识货实体，也不用同参数反复重试。

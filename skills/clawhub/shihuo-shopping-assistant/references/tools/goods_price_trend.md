# goods_price_trend

商品层历史价格趋势。按 `goods_id` 返回最近 90 个完整自然日的每日最低价序列，以及区间平均价和中位价。本工具不分价格类型，一个商品只有一条序列。

## 入参

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| goods_id | string | 是 | 识货商品 ID，不透明字符串，固定 12 字符、区分大小写，原样取自工具返回值 |

无 `page`、`page_size`、日期或价格类型参数。时间范围固定为“昨天往前 90 天”（不含当天），不能通过入参调整。

## 响应字段解释

`data` 为对象；无数据时状态为 `not_found`，不返回空 `data`。

| 路径 | 类型 | 是否恒有 | 含义 | 展示与限制 |
| --- | --- | --- | --- | --- |
| data.prices | array | 是 | 每日最低价点列表 | 成功时至少 1 个点；无价格的日期不出现在列表里，序列可不连续，缺口不代表价格为 0 |
| data.prices[].day | string | 是 | 日期，格式 `YYYY-MM-DD` | 直接展示原字符串，不改写成“x 天前”，不自行补齐缺失日期 |
| data.prices[].price | string | 是 | 该日商品层最低价，格式 `￥11`、`￥15.5`、`￥1299.99`（整元不带小数，非整元最多两位） | 已带 `￥`，引用时不要再加货币符号 |
| data.average | string | 否 | 区间平均价，同上格式 | 无该口径或为 0 时是空串，此时省略该口径，不用价格点自行平均 |
| data.median | string | 否 | 区间中位价，同上格式 | 空串时省略 |

出参没有 `goods_id` 回显。哪个商品的趋势由调用方自己记住。

`prices` 顺序以接口返回为准，不假定升序或降序。取最低点、最高点、最近点前必须先按 `day` 排序，不能直接取 `prices[0]` 或末位。

## 每个字段能支撑哪类结论

这条序列的口径是“识货商品层每日最低价”，比它更细的层次它都说不了。缺字段就整块省略，不推测、不预测未来走势。

| 字段 | 能支撑 | 不能支撑 |
| --- | --- | --- |
| prices[].day | 记录覆盖的最早和最晚日期、哪个点最近 | 覆盖了完整多少天，缺价的日期不在列表里 |
| prices[].price | 该日商品层最低价，区间最低价与最高价各带日期 | 当前售价、到手价、某个款式或规格的价格 |
| 有效点数 | 点数明显少于天数时说明“部分日期无价格数据” | 价格是否稳定、是否值得买 |
| average 与 median | 各自对应的区间集中水平，按用户问题引用 | “正常水位”“价格虚高”这类评价 |
| 等于区间最低价的天数 | 该低点出现过几天：1 天是偶发，多天是重复出现过的价位 | 该低点还会不会再出现 |
| ≤ 用户目标价的天数及最近日期 | 90 天内有几天达到过用户给的目标价、最近一次是哪天 | 未来能不能等到这个价 |
| 按自然月聚合的每月最低价 | 各月最低价分别是多少 | 某个月为什么低、下个月会不会更低 |

区间最低价与最高价按 `day` 排序后取 `price` 的最小值和最大值，各带日期；多天同价取最早一天，不编造唯一性。`day` 最大的那个点只能称“最近一次记录到的价格”，它是历史记录点，不是当前售价，也不是到手价。

有效点 ≥ 2 且按 `day` 排序后顺序明确时，才可以带一个方向词描述上升、下降或震荡，并给出对比的两个日期与价格；任何时候不写“预计还会降”。

差额可以同时给绝对值和百分比，百分比是该差额除以**本工具同一条序列内**作为基数的那个价格（区间最低价或 `median`）、取整。跨实体层、跨价格层一律不换算百分比，与渠道到手价之间也不换算。

按自然月聚合每月最低价是允许的，只写月份和价格，月份按时间升序。本工具固定 90 天，通常跨 3 至 4 个自然月，首尾月份可能只覆盖部分天数，聚合时不因此加权、不补齐缺失日期。不写具体大促日期、活动名，也不把某个月的低点归因到任何活动或写成“下次大促会更低”。

“低位、偏高、抄底、值得买”这类判断没有字段支撑，一概不写。

## 哪些字段之间不能相减

只有两处相减是允许的：最近点与区间最低点、最近点与 `median`，都在本工具同一条序列内。价格字符串已是展示态，做差额前先去掉 `￥`。其余组合都是跨实体层或跨价格层：

| 不能相减的两端 | 原因 |
| --- | --- |
| 本工具价格 与 `goods_style_price_trend`、`goods_sku_price_trend` 的价格 | 实体层不同，商品层不代表某个款式或规格 |
| 本工具价格 与 `goods_sku_price_comparision` 的渠道到手价 | 历史价与当前到手价是两层价格，且时点不同 |
| 本工具价格 与 `goods_link_query` 的 `current_final_price`、`price_before_coupon`、`history_low_price` | 后者是单个渠道链接的快照与渠道侧 180 天低点 |
| 本工具价格 与 `search_goods_by_*`、`goods_styles`、`search_sku` 的展示价 | 展示价与历史价是两层价格 |

数据不足口径：0 个有效点由工具返回 `not_found`，直接说明未取得该商品的历史价格，不生成价格结论；只有 1 个点时只陈述该点日期和价格，不写高低点对比和方向。

## 调用说明

前置条件只有一个：已确认的 `goods_id`。适用于用户问商品整体的历史价格、价格走势、历史最低或价格统计。

不适用：具体尺码/容量的历史价（用 `goods_sku_price_trend`）、单个配色的历史价（用 `goods_style_price_trend`）、当前哪里买最便宜（用 `goods_sku_price_comparision`）。用户要规格级价格时不用商品层趋势顶替，先按 `index.md` 的“ID 使用约定”补齐 `style_id` 或 SKU。

结果处理按 `index.md` 的“失败与异常处理”：缺失 ID 返回 `missing_param`，补齐后调用；无效或已失效 ID 返回 `invalid_id`，重新调用搜索工具获取且不得用同值重试；`not_found` 不用同参数重试；`failed` 的重试按通用规则执行，最终仍失败时保留已确认的商品信息并说明历史价格未取得。

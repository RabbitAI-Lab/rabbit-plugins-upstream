# 商品推荐的两种回复

本文管标准回复和兜底回复各由哪些模块组成、每个模块什么时候出现、结构参考和字段缺失怎么删。选哪一种回复由 `workflow.md` 末尾的表决定，本文不重复判定条件。SKILL.md 的全局约束同时生效。

章节标题（含 emoji）、表格表头和章节顺序按本文结构执行；方括号是语义占位符，填真实值后不得残留。列表中的示例项只是生成槽位，不是固定文案，必须按本轮工具返回和场景规则重新生成。单元格无内容时按该模块的专门规则处理。

## 模块：价格参考

仅在步骤 6 的 `goods_price_trend` 返回 `success` 且 `prices` 至少包含 1 个有效价格点时出现。

<!-- 骨架开始 -->
## 💰 价格参考

**[商品名称] 近 90 天价格记录：[一句话结论]**

| 口径 | 数值 |
|---|---:|
| 区间最低 | ¥[价格]（[MM-DD]，共 [N] 天） |
| 区间最高 | ¥[价格]（[MM-DD]） |
| 中位价 | ¥[价格] |
| 平均价 | ¥[价格] |
| 最近记录 | ¥[价格]（[MM-DD]），比中位价高/低 ¥[差额]（[N]%） |

分月最低：[M] 月 ¥[价格] ｜ [M] 月 ¥[价格] ｜ [M] 月 ¥[价格]

记录覆盖 [YYYY-MM-DD] 至 [YYYY-MM-DD]，90 天中 [N] 天有记录。
<!-- 骨架结束 -->

返回 `not_found`、没有有效价格点或业务查询失败时，删除整个“价格参考”模块，包括标题、结论、表格、分月行和覆盖说明，不输出任何历史数据缺失说明。当前页面参考价继续在“推荐概览”和“逐款说明”中按真实返回值展示。历史记录只用于和同一商品的历史记录比较，不用来代替购买页金额。

首句只陈述表里已有的事实，例如“最近记录 ¥[价格] 与中位价持平，区间最低 ¥[价格] 在近 90 天出现过 3 天”。用户给出目标价时首句改成可达性回答，例如“近 90 天有 5 天记录不高于 ¥450，最近一次是 06-24”，没有一天达到目标价时如实说明。不写“低位、偏高、抄底、值得买”。

`average` 或 `median` 为空串时删对应行，不自行遍历价格点重算。差额和百分比只在最近记录与区间最低、最近记录与中位价之间算，百分比是差额除以作为基数的那个价格、取整；差额为 0 时写“持平”并省略百分比。只有 1 个有效价格点时删掉区间最高、中位价、平均价、最近记录四行和分月行，只留区间最低那一行并写明只有 1 天记录。

分月最低行按自然月取该月最低价，只在有效点跨 3 个以上自然月时保留，否则整行删除；月份按时间升序，只写月份和价格，不写大促日期、活动名，也不把某个月的低点归因到活动或写成“下次会更低”。字段读法和相减边界按 `references/tools/goods_price_trend.md`。

## 模块：隐藏优惠结果

- 当前优惠（[渠道/店铺 A]）：[优惠类型]（[券名]）
- 优惠后较该报价原价节省：¥[节省金额]
- 当前优惠（[渠道/店铺 B]）：[优惠类型]（[券名]）
- 优惠后较该报价原价节省：¥[节省金额]

<!-- 骨架结束 -->

每条有效渠道报价只占一行；相同渠道且相同商品入口的多张符合条件的券，在“隐藏优惠/补贴”和“优惠金额（券面额）”中按对应顺序用 `、` 连接，最多 3 张，剩余写“等”，不相加、不暗示可叠加。同一渠道存在不同商品入口或不同 `final_price` 时分开列行。券种显示可用上述规范标签，但括号内必须保留工具返回的原始 `coupon_name`。券后到手价取该报价的 `final_price`，按价格升序，最低行加粗。

金额字段为空或无法解析时写“无”，不保留 `¥` 前缀。

“优惠后较该报价原价节省”仅在同一报价的 `original_price` 与 `final_price` 都能解析为有效金额时计算；它是该报价的原价差额，不把差额拆给某张券，也不把 `coupon_amount` 当作叠加后的总节省。没有任一金额时删除该说明行。多渠道只比较当前有效券后到手价：最低值与下一档之间的差额可以写在汇总或逐渠道说明中；只有一个渠道时删除价差行。

“当前优惠”和“优惠后较该报价原价节省”按报价逐条重复；没有对应报价或金额无法计算时删除对应行。并列最低时在汇总中列出全部并列渠道，不强行指定一家；其他报价只写相对最低券后价的当前差额。只有真实返回、同规格、`final_price` 有效且有最终展示地址的报价才可进入本节。

# 全网比价流程

本文管这个场景每一步调哪个工具、传什么参数、结果怎么过滤、这一步产出什么，末尾给出选哪种回复。回复的模块构成、措辞和删除规则在 `output.md`，字段含义在 `references/tools/`，SKILL.md 的全局约束同时生效，本文都不重复。

入口是关键词或图片，不接受商品链接。本场景最终形成一个主比较单元：一个 `goods_id`、一个 `style_id`、一个 `sku_id`。商品、款式和 SKU 未明确时自动选择，不因候选不唯一常规追问。

## 通用约束

定位顺序仍是商品、款式、SKU，但任一层不唯一时先按用户条件和排序诉求自动选择；只有用户明确条件没有精确匹配时才阻塞。主 SKU 选定前不调 `goods_sku_price_trend`、`goods_sku_price_comparision`、`link_convert`。

本轮只有一个商品和一个 SKU 形成价格结论，其余真实商品、款式和 SKU 只在结尾的切换段落展示，不进最低价、价格历史和渠道结论。

当前渠道到手价只取自动选定的那个 `sku_id` 的有效报价。

自动选择后直接输出主 SKU 结果；切换段落只提供重新比较的选择，不改变当前主 SKU 的价格结论。

## 完整工作流程

### 步骤 1：意图解析

**输入：** 用户原始问题和可能携带的图片 URL。

**处理：**

1. 提取商品身份：品牌、系列、型号、品类、用户使用的商品词。
2. 提取用户明确说出的：配色或款式、尺码或容量或版本、预算。
3. 用户没说的配色、尺码、容量、版本留空。
4. 识别排序诉求：价格、销量或热门；没有明显偏好时记为销量优先。
5. 用户同时提到多个商品或多个 SKU 时，先按匹配度和排序诉求选一个主对象，其余放入结尾的切换段落。

**输出：** 用户条件（品牌、系列、型号、品类、配色或款式、尺码或容量或版本、预算）和入口类型。

### 步骤 2：查询改写

**输入：** 步骤 1 的用户条件。

**处理：**

1. 关键词入口：`query` 只保留品牌、系列、型号、品类和用户写出的商品词，删除“哪里买、最低价、比价、历史价格”等意图词；原始问题留在内部上下文。
2. 图片入口：沿用用户给的 `image_url`；同时给出的文字条件转为后续款式和 SKU 的匹配条件。
3. 预算只在用户明确给出时传给搜索工具，不用预算替代型号或规格。
4. 不为扩大召回补写品牌、型号、配色、尺码或版本。

**输出：** 一个 `query` 或一个 `image_url`，以及待匹配的用户条件。

### 步骤 3：搜索商品候选

**输入：** 步骤 2 的关键词或图片参数。

**处理：**

1. 关键词调 `search_goods_by_keyword`，图片调 `search_goods_by_image`，两条入口互斥。
2. 按接口返回的分页字段翻页，去重后最多保留 3 个真实 `goods_id`。
3. 丢弃品牌、系列、型号或品类与用户明确条件不一致的结果；商品名匹配度优先，结果顺序作为热度参考，销量和价格按用户诉求参与排序。
4. 记录每个候选的商品名称、品牌、商品层展示价、销量、识货 `href` 和搜索结果顺序。

**输出：** 1 至 3 个商品候选，或查空。

**分支：** 无候选时本轮到此为止，走兜底。图片无结果按图片查空处理，不改写成关键词重试。

### 步骤 4：商品、款式和 SKU 定位

**输入：** 步骤 3 的候选，以及用户的配色或款式、尺码或容量或版本条件。

**处理：**

1. 对商品候选按品牌、系列、型号、品类和商品名与用户原话的匹配度排序；匹配度相同时，价格诉求按价格优先，销量或热门诉求按销量或搜索结果顺序优先，没有明显偏好时按搜索结果顺序（热度）再按销量排序，选出一个主 `goods_id`。
2. `goods_styles(goods_id)` 取主商品全部款式，`has_more` 为真时继续翻页。
3. 用户指定了配色或款式时，只接受 `style_name`、属性或货号完全一致的 `style_id`；用户未指定时，所有真实款式都进入候选，不因多个款式而追问。
4. 对候选款式调 `search_sku(goods_id, style_id)`，取规格字段、`goods_sku_id`、`sale_price` 和 `sales_30_days`。
5. 用户指定了尺码、容量或版本时，先要求所有维度精确命中同一个 SKU；用户未指定的维度不作为过滤条件。
6. SKU 或款式未明确时按排序诉求自动选一个主 SKU：价格优先取有效 `sale_price` 最低，销量优先取 `sales_30_days` 最高；没有明显偏好时默认销量优先。并列时价格优先作为次排序。
7. 以主 SKU 所属款式作为主 `style_id`，保留未选中的商品、款式和 SKU 作为切换候选，记录各自的真实差异、展示价和销量。

**输出：** 自动选定的 `goods_id`、`style_id`、`sku_id`，商品、款式、规格文本，排序依据，以及商品、款式、SKU 切换候选。

**分支：** 商品、款式或 SKU 不唯一时继续自动选择。用户指定的条件无精确匹配时走兜底，不用相近商品、款式或规格替代。

### 步骤 5：补充主商品信息

**输入：** 步骤 4 自动选定的三个 ID。

**处理：**

1. `goods_detail(goods_id)`：商品参数、热度、鉴别记录。
2. `goods_notes(goods_id)`：体验、人群、场景、优缺点；每条结论记下实际拿到几条独立支撑。
3. 主 SKU 已确认后必须调 `goods_sku_price_trend(goods_id, sku_id)`，不以用户是否询问历史价格、是否有当前报价或隐藏优惠为调用条件。只查主 SKU，本轮相同参数的趋势结果供“价格历史”、隐藏优惠历史表及兜底回复复用；无数据或业务查询失败不阻塞本次比价。
4. 商品定位、款式边界和版本差异只用步骤 4 已确认的字段。

**输出：** 主商品介绍素材、鉴别与热度事实，以及同一 SKU 的价格历史事实及其价格类型（有有效趋势数据时输出）。无数据或调用失败时不输出价格历史部分。

**分支：** `goods_detail` 或 `goods_notes` 失败时不中断，已成功的比价照常输出。

### 步骤 6：查询主 SKU 全网报价

**输入：** 步骤 4 自动选定的 `goods_id` 和 `sku_id`。

**处理：**

1. 调 `goods_sku_price_comparision(goods_id, sku_id)`，按返回的 `total` 和 `pageSize` 收齐本次报价。
2. 逐条核对渠道标题、规格、成色；与主商品、主款式、主规格不符，或属于二手、瑕疵、非全新的报价，不进最低价候选。
3. 丢弃 `final_price` 缺失或无效的报价；相同商品入口去重，保留不同渠道的履约和优惠事实。
4. 记录每条有效报价的渠道或店铺、`final_price`、`original_price`、运费、优惠券（含 `coupon_name` 和 `coupon_amount`）、履约信息、`sh_recommend_reason`、`endorse`、`buy_link`。

**输出：** 有效报价列表、待转链报价列表及可展示的报价数量。

### 步骤 7：报价转链和最低价收口

**输入：** 步骤 6 的有效报价及其中的商品和优惠券链接。

**处理：**

1. 商品入口逐条调 `link_convert(type="goods")`，优惠券入口逐条调 `link_convert(type="coupon")`。
2. 每个入口独立确定最终展示地址：转链成功用转链地址；转链失败、空结果或非法结果时，用该入口自身的原始 `http`/`https` 地址；两者都不可展示时才省略。
3. 有效报价只要商品入口得到最终展示地址，就进入渠道表和最低价判断；不得因转链失败丢弃可直接访问的原始链接。
4. 在可展示报价中按 `final_price` 取最低。同价或差额很小时，补充接口真实返回的优惠券完整性、履约标签或 `endorse` 等事实，不把标签写成正品承诺。
5. 为每条可展示报价生成渠道推荐理由：优先使用非空的 `sh_recommend_reason` 原文；为空时组合真实返回的 `endorse` 标签（去重后最多 2 条），若同时存在至少两个有效可展示报价且该报价严格低于其他报价，再追加“当前可查看的同规格报价中价格最低”等价格事实。没有可验证差异时保留空值，不写“无”，也不从平台名、店铺名或标题推断官方、正品或店铺资历。

**输出：** 有最终展示地址的渠道报价、最低报价、可展示报价条数，以及其中明确标注“识货补贴”“88VIP/88 VIP”或“京东PLUS/京东 PLUS”的隐藏优惠报价。

隐藏优惠报价只保留当前选定 SKU 的有效 `final_price`，并按相同渠道、相同商品入口的报价分组；同一报价多张券不合并金额、不假定叠加。同一渠道存在不同商品入口或不同 `final_price` 时分开列出。`original_price` 与 `final_price` 同时有效时，才计算该报价原价差额。历史低点继续按趋势接口的价格类型分开作为参考，不与当前渠道券后价相减；当前隐藏优惠报价之间可按 `final_price` 排序并计算差额。

### 步骤 8：整理切换候选

**输入：** 步骤 4 的商品、款式和 SKU 切换候选。

**处理：**

1. 只用本轮真实返回的候选信息，不为未选候选另查渠道报价或价格历史。
2. 按商品、款式、SKU 三层分别记录候选与主对象的真实差异、展示价和销量。
3. 为输出准备用户可读的选择项：款式名称根据 `style_name` 判断显示为“颜色 / 配色”“款式 / 版本”或“款式”；具体规格使用 `search_sku.specs[].name` 和真实值。只展示存在多个可选值的维度；多个维度存在组合限制时改用“规格”或“可选组合”并列完整组合。不展示 `goods_id`、`style_id`、`sku_id` 或“SKU”。

**输出：** 商品、款式和 SKU 的切换候选；无其他候选时为空。

## 选哪种回复

| 情况 | 回复 |
|---|---|
| 用户明确条件没有精确匹配，或没有任何商品候选 | 兜底 |
| 已自动选定商品 SKU，且至少有一条可展示的同规格购买选项 | 标准回复 |
| 其余 | 兜底 |

标准回复内部按模块出现条件展开：步骤 5 返回有效趋势数据时出现“价格历史”，无数据或调用失败时删除整个模块；步骤 7 可展示报价中有符合条件的隐藏优惠时，在“购买渠道对比”后出现“隐藏优惠结果”，没有就删；步骤 8 有切换候选时出现“也可以换”，没有就删；只有步骤 5、6、7 的事实池中存在与当前商品、款式、货号、规格、笔记或报价直接相关的风险时才出现“避坑指南”，没有就删；商品介绍的六个小节按各自拿到的证据决定去留。主 SKU 没有有效报价时走兜底，步骤 5 的有效趋势数据仍在“可参考信息”中展示，不能因无报价跳过查询或删除历史内容；自动选择本身不触发追问。

## 特殊情况

| 情况 | 可以输出 | 不能输出 |
| --- | --- | --- |
| 多个商品都精确匹配 | 按商品名匹配度、热度、销量和用户诉求自动选主商品，其他商品放入切换段落 | 把其他商品的渠道价格混入主结论 |
| 多个款式或 SKU 都匹配 | 按用户诉求自动选主款式和主 SKU，其他选项放入切换段落 | 因不唯一而追问，或混用其他对象的价格 |
| 图片没有文字规格 | 按图片候选顺序、热度和销量自动选商品，再按默认规则选款式和 SKU，并明确展示已选规格 | 从图片推断颜色、尺码、容量、版本 |
| 用户指定的配色或规格不存在 | 没有精确匹配的说明和真实差异 | 用相近规格顶替 |
| 主 SKU 没有报价 | 商品层和 SKU 层展示价，以及已查到的同规格历史价格 | 渠道最低价 |
| 报价转链全部失败，但原始 `http`/`https` 入口有效 | 原始商品入口、已核实的价格事实和可展示最低价 | 因转链失败降级为兜底 |
| 报价的转链地址和原始地址都不可展示 | 已核实的价格事实 | 不可访问的入口、可购买最低价 |
| 价格趋势无数据 | 删除“价格历史”，当前报价不受影响 | 用其他 SKU 或款式的历史价格替代 |
| 商品详情或笔记失败 | 已成功的主 SKU 比价 | 对应介绍小节，整段删除 |
| 没有与当前商品、款式、货号、规格或报价相关的避坑事实 | 删除“避坑指南”章节 | 用通用经验或其他商品笔记补齐 |

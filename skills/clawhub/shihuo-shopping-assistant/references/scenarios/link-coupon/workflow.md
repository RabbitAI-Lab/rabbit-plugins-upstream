# 链接与优惠流程

本文管这个场景每一步调哪个工具、传什么参数、结果怎么过滤、这一步产出什么，末尾给出选哪种回复。回复的模块构成、措辞和删除规则在 `output.md`，字段含义在 `references/tools/`，SKILL.md 的全局约束同时生效，本文都不重复。

入口必须含链接或口令，且诉求是隐藏券、补贴券或优惠。优惠只对链接对应的那一个规格生效。入口原文整体传给 `link_parse` 和 `goods_link_query`，两个工具各调一次，职责不互换：前者判层级，后者出渠道侧优惠事实。可展示的券须同时满足三条：来自本轮的额外优惠券或普通优惠券列表、对应本轮已确认的规格、券链接有最终展示地址。最终展示地址优先取转链结果，转链不可用时取原始 `http`/`https` 地址。

## 完整工作流程

### 步骤 1：留存原文与诉求

**输入：** 用户消息原文。

**处理：**

1. 完整保存原文，包含链接、口令、前后文案和表情符号。
2. 确认诉求是找券、找隐藏券、找补贴或问有没有优惠；记录用户明确说出的规格条件和预算。
3. 用户同时给出多条链接时，本轮只对一条链接找券，请用户指定其中一条。

**输出：** 原文字符串、用户补充的规格条件、目标链接数量。

### 步骤 2：链接层级解析

**输入：** 步骤 1 的原文。

**处理：**

1. 调 `link_parse(link=原文)`。
2. 按 `results[]` 逐条独立判定三个 ID，空字符串一律视为该层未定位，不改写成默认值、第一个款式或第一个 SKU。
3. 归类本轮层级：SKU 层（`goods_id` 与 `goods_sku_id` 都非空）、款式层（`goods_id` 与 `goods_style_id` 非空而 `goods_sku_id` 为空）、商品层（只有 `goods_id` 非空）、未解析（三个 ID 全为空或返回 `not_found`）。
4. `results` 多条且指向不同 `goods_id` 时判定为绑定歧义。

**输出：** 层级判定结果和对应 ID；或未解析状态、绑定歧义状态。

**分支：** 未解析仍继续步骤 3，渠道侧可能仍有可核验优惠。

### 步骤 3：链接渠道侧优惠事实

**输入：** 步骤 1 的原文。

**处理：**

1. 调 `goods_link_query(link=原文)`。
2. 记录 `mall_name`、`shop_name`、`product_title`、`supplier_sku_info.attrs[]`、`price_before_coupon`、`current_final_price`、`extra_coupons[]`、`coupons[]`、`history_low_price`、`supplier_buy_link`。
3. 判定本轮优惠类型，三类分别记录，不互相顶替：额外优惠券取 `extra_coupons[]` 的 `name` 与 `link`；普通优惠券取 `coupons[]` 的 `name` 与 `link`；渠道促销取 `promotion_name`、`promotion_price`、`promotion_time`，促销不是券，单独陈述，不写进优惠合计。
4. 三类都为空时判定为本轮无可核验优惠。
5. 返回 `partial_success` 且 issue 表示优惠券查询失败时，两组券信息视为未取全，不判定无券；其他商品和价格字段仍可继续使用。
6. `sh_goods_id`、`sh_sku_id` 与步骤 2 的 ID 不一致时，以 `link_parse` 的结果为准；`link_parse` 未定位而这两个字段非空时，可用它们进入下游工具。

**输出：** 优惠类型与对应券名、当前链接到手价、券前价、渠道购买入口；或无可核验优惠状态。

**分支：** 无可核验优惠或优惠业务查询失败时，已有可用 ID 仍必须继续走步骤 4 至 7；确认唯一规格后查询同规格报价和趋势，不得直接兜底。步骤 2 与步骤 3 都无可用 ID 时本轮不进入任何比价或趋势工具，直接走步骤 8。

### 步骤 4：规格收口

**输入：** 步骤 2 的层级判定、步骤 3 的渠道规格文本、用户补充的规格条件。

**处理：**

1. SKU 层直接沿用 `goods_sku_id`，不再另查款式。
2. 款式层调 `search_sku(goods_id, style_id)`，用渠道规格文本和用户条件精确匹配唯一 SKU。
3. 商品层调 `goods_styles(goods_id)`，`has_more` 为真时翻页，再对匹配款式调 `search_sku`。
4. 收口后仍有多个候选 SKU，或精确匹配为空，判定为规格未收口。

**输出：** 唯一 `sku_id` 和已确认的款式、规格文本；或规格未收口状态。

**分支：** 规格未收口时本轮不得把任何优惠说成适用于某个具体规格；拿不到真实款式或规格候选时走步骤 8。

### 步骤 5：补齐展示字段

**输入：** 步骤 4 的 `goods_id`、`style_id`、`sku_id`。

**处理：**

1. 识货商品入口和款式名取 `goods_styles` 返回的 `href` 与 `style_name`；步骤 4 已调过就复用，不重复调用。
2. 货号取 `goods_detail(goods_id)` 或 `goods_styles` 的真实属性字段；两处都没有就记为未取到。
3. 商品名称取识货返回字段，不用 `product_title` 顶替。

**输出：** 识货商品入口、商品名称、货号、配色、规格。

### 步骤 6：同规格价格参考

**输入：** 步骤 4 的 `goods_id` 和 `sku_id`。

**处理：**

1. 调 `goods_sku_price_comparision(goods_id, sku_id)`，按 `total` 和 `pageSize` 收齐报价。本轮无可核验优惠时，该报价查询必须执行。
2. 逐条核对渠道标题、`spec_name` 与本轮规格一致；二手、瑕疵、非全新报价不进比较。
3. 丢弃 `final_price` 缺失或无效的报价；相同商品入口去重；与用户输入链接同一店铺的报价不再单独进入同规格参考。
4. 记录渠道/店铺、`final_price`、`coupon[]`、`sh_recommend_reason`、`buy_link`，供当前链接到手价横向对比；`sh_recommend_reason` 记原文，为空就记为空。
5. 已确认唯一 `goods_id` 和 `sku_id` 后必须调 `goods_sku_price_trend(goods_id, sku_id)`，取得结果后再选回复；不以用户是否询问历史价格、是否有券、优惠业务查询是否成功或是否有有效报价为前提，报价业务查询失败也不能跳过。同轮相同参数复用已取得的趋势结果，不重复查询。趋势无数据或业务查询失败不阻塞找券结论。

**输出：** 同规格有效报价列表（或无有效报价状态）、识货 SKU 层趋势查询结果。标准回复和兜底都按 `output.md` 展示有效历史数据；趋势无数据或业务查询失败时删除对应历史内容，不输出缺失或失败占位。

### 步骤 7：转链与领取入口

**输入：** 步骤 3 的 `supplier_buy_link`、`extra_coupons[].link`、`coupons[].link`，以及步骤 6 的报价入口与券链接。

**处理：**

1. 两组券的 `link` 都调 `link_convert(type="coupon")`，商品入口调 `link_convert(type="goods")`，每条独立调用，不复用同一次转链结果。
2. 每个入口独立确定最终展示地址：转链成功用转链地址；转链失败、空结果或非法结果时，用该入口自身的原始 `http`/`https` 地址；两者都不可展示时才省略。
3. 券领取入口写对应券的最终展示地址；`supplier_buy_link` 的最终展示地址只能作为商品入口，不能冒充券领取入口。
4. 当前链接到手价与同规格有效报价横向比较，得出当前渠道是否已是本次最低。
5. 需要表达整体节省额时，只用同一快照中可解析的 `price_before_coupon` 与 `current_final_price` 之差，不把差额归因到某张券，不从券名解析金额。

**输出：** 领取入口、当前链接到手价及其与同规格报价的对比结果、整体节省额或其不可计算状态。

### 步骤 8：兜底关键词检索

**输入：** 步骤 1 的用户原文商品描述、步骤 3 的 `product_title`。

**只在这一种情况执行：** 步骤 2 与步骤 4 都没能收口到唯一 `sku_id`，且步骤 4 也拿不到真实款式或规格候选。已收口到唯一 `sku_id` 时跳过本步骤，不为找券结论另找相似商品。

**处理：**

1. 组装检索词：优先用用户原文里的商品描述，没有时取 `product_title` 里的品牌、系列、型号、品类词。两者都取不到可检索词时跳过本步骤。
2. 调 `search_goods_by_keyword(query=检索词)`，只取第一页，最多保留 3 条候选。
3. 无命中时可换一次更宽的关键词（去掉修饰词，只留品牌加品类）；仍无命中判定为搜索无命中。
4. 只记录候选的 `goods_name`、`price`、`href`。候选一律不再进入 `goods_styles`、`search_sku`、比价和趋势工具，也不为候选查券。

**输出：** 最多 3 条相似商品候选；或无可检索词、搜索无命中状态。

## 特殊情况

| 情况 | 可以输出 | 不能输出 |
| --- | --- | --- |
| 一条消息含多个链接 | 已识别到多条链接，请用户指定一条 | 任何一条链接的优惠结论 |
| `link_parse` 返回多个不同商品 | 各候选的已确认信息，走追问 | 自行挑一条继续找券 |
| 规格未收口 | 链接商品信息和真实可选规格 | 把优惠说成适用于某个具体规格 |
| 只有额外优惠券 | 逐张券名与券的最终展示地址 | 编造券金额或声称普通券列表也有券 |
| 只有普通优惠券 | 逐张券名与券的最终展示地址 | 把普通优惠券写成额外优惠券或补贴 |
| 两组券都有条目 | 分组展示券名和各自的最终展示地址 | 声称多张券可叠加 |
| 券转链全部失败，但原始 `http`/`https` 地址有效 | 券名和原始券入口 | 因转链失败删除领取入口 |
| 券的转链地址和原始地址都不可展示 | 券名、当前到手价；商品页只作为商品入口 | 虚构领取入口 |
| 只有渠道促销、无券 | 渠道当前促销事实 | 把促销写成可领取的隐藏券 |
| 券前价与当前到手价无法计算差额 | 工具直接返回的当前到手价和券名 | 自行解析券名或凑出节省额 |
| 无任何可核验优惠 | 找券方式指引、同规格其他渠道报价表和已查询到的同规格历史价格 | 通用活动说明冒充当前商品的券 |
| 拿不到识货商品或规格，但搜到真实相似候选 | 链接已确认字段、相似商品的识货站内展示价、找券指引 | 相似商品的到手价、券结论或最低价 |
| 本轮没有任何商品事实 | 无法识别的说明、可补充信息清单、通用找券指引 | 任何商品、规格、价格、渠道字段 |
| 当前链接到手价不是同规格最低 | 当前链接到手价，同时说明有更低的同规格渠道 | 只报当前链接到手价、隐去更低的渠道 |
| 两个历史口径只有一个有数据 | 有数据的那一个，并标注来源 | 用另一个口径的名义展示 |
| 用户换了尺码或配色 | 提示优惠随规格变化需重新核对 | 把原规格的优惠套到新规格 |

## 选哪种回复

| 情况 | 回复 |
|---|---|
| 一条消息含多条链接、绑定歧义，或规格未收口但有真实款式或规格候选 | 追问 |
| 规格已收口，且额外优惠券或普通优惠券中至少有一张有最终展示地址 | 标准回复 |
| 其余 | 兜底 |

# 链接比价流程

本文管这个场景每一步调哪个工具、传什么参数、结果怎么过滤、这一步产出什么，末尾给出选哪种回复。回复的模块构成、措辞和删除规则在 `output.md`，字段含义在 `references/tools/`，SKILL.md 的全局约束同时生效，本文都不重复。

本场景只处理带链接或口令的入口。链接对应的规格是本轮唯一比较基准，渠道比价必须精确到一个商品和一个 SKU。

入口原文整体传给 `link_parse` 和 `goods_link_query`，两个工具各调一次，职责不互换：`link_parse` 判层级，`goods_link_query` 出渠道侧事实。当前链接到手价只取 `goods_link_query.current_final_price`，渠道比价价只取 `goods_sku_price_comparision.list[].final_price`，两者是不同时点的快照。

## 完整工作流程

### 步骤 1：留存原文与诉求

**输入：** 用户消息原文。

**处理：**

1. 完整保存原文，包含链接、口令、前后文案和表情符号。
2. 记录用户明确说出的规格条件（尺码、容量、版本、配色）和预算，用户没说的留空。
3. 用户同时给出多条链接时，本轮不对任何一条出结论，请用户指定其中一条。

**输出：** 原文字符串、用户补充的规格条件、目标链接数量。

### 步骤 2：链接层级解析

**输入：** 步骤 1 的原文。

**处理：**

1. 调 `link_parse(link=原文)`。
2. 按 `results[]` 逐条独立判定三个 ID，空字符串一律视为该层未定位，不改写成默认值、第一个款式或第一个 SKU。
3. 归类本轮层级：
   - **SKU 层**：`goods_id` 与 `goods_sku_id` 都非空，可直接查趋势和比价。
   - **款式层**：`goods_id` 与 `goods_style_id` 非空、`goods_sku_id` 为空，需要收口到 SKU。
   - **商品层**：只有 `goods_id` 非空，需要先定款式再定 SKU。
   - **未解析**：三个 ID 全为空，或工具返回 `not_found`。
4. `results` 多条且指向不同 `goods_id` 时判定为绑定歧义。

**输出：** 层级判定结果和对应 ID；或未解析状态、绑定歧义状态。

未解析仍继续步骤 3，`goods_link_query` 可能还能给出渠道侧事实。

### 步骤 3：链接渠道侧事实

**输入：** 步骤 1 的原文。

**处理：**

1. 调 `goods_link_query(link=原文)`。
2. 记录 `mall_name`、`shop_name`、`product_title`、`supplier_sku_info.attrs[]`、`current_final_price`、`price_before_coupon`、`history_low_price`、`supplier_buy_link`。
3. 有 `promotion_name` 与 `promotion_price` 时记为渠道当前促销事实，不改写成优惠券，也不与 `extra_coupons[]` 或 `coupons[]` 合并。
4. `sh_goods_id`、`sh_sku_id` 与步骤 2 的 ID 不一致时，以 `link_parse` 的结果为准；`link_parse` 未定位而这两个字段非空时，可用它们进入下游工具。
5. `attrs[]` 是渠道侧规格文本，只用于核对比价规格是否同一规格。

**输出：** 链接商品的渠道事实；或 `not_found` 状态。

步骤 2 与步骤 3 都没有可用 ID 时，本轮不进入任何比价工具，直接走步骤 9。

### 步骤 4：规格收口

**输入：** 步骤 2 的层级判定、步骤 3 的 `attrs[]`、用户补充的规格条件。

**处理：**

1. SKU 层直接沿用 `goods_sku_id`，不再另查款式。
2. 款式层调 `search_sku(goods_id, style_id)`，用 `attrs[]` 和用户条件精确匹配唯一 SKU。
3. 商品层调 `goods_styles(goods_id)`，`has_more` 为真时翻页，再对匹配款式调 `search_sku`。
4. 收口后仍有多个候选 SKU，或精确匹配为空，判定为规格未收口。

**输出：** 唯一 `sku_id` 和已确认的款式、规格文本；或规格未收口状态。

### 步骤 5：补齐展示字段

**输入：** 步骤 4 的 `goods_id`、`style_id`、`sku_id`。

**处理：**

1. 识货商品入口和款式名取 `goods_styles` 返回的 `href` 与 `style_name`；步骤 4 已调过就复用，不重复调用。
2. 货号取 `goods_detail(goods_id)` 或 `goods_styles` 的真实属性字段；两处都没有就留空。
3. 品牌与商品名称取识货返回字段，不用 `product_title` 顶替。

**输出：** 识货商品入口、商品名称、品牌、货号、配色、规格。

### 步骤 6：同规格全网报价

**输入：** 步骤 4 的 `goods_id` 和 `sku_id`。

**处理：**

1. 调 `goods_sku_price_comparision(goods_id, sku_id)`，按 `total` 和 `pageSize` 收齐报价。
2. 逐条核对渠道标题、`spec_name` 与本轮规格一致；二手、瑕疵、非全新报价不进比价。
3. 丢弃 `final_price` 缺失或无效的报价；相同商品入口去重。
4. 记录渠道/店铺、`final_price`、`freight`、`coupon[]`、`fulfillment[]`、`sh_recommend_reason`、`buy_link`，`sh_recommend_reason` 照原文记录，不自行改写。

**输出：** 原始报价数、有效报价数、待转链列表。

无有效报价或报价业务查询失败时，保留已核实的当前链接到手价事实，先完成步骤 8 的趋势查询，再走步骤 9。

### 步骤 7：转链与结论收口

**输入：** 步骤 3 的 `supplier_buy_link`、步骤 6 的有效报价及其券链接。

**处理：**

1. 链接原渠道入口调 `link_convert(type="goods", link=supplier_buy_link)`；每条报价的 `buy_link` 逐条调 `link_convert(type="goods")`；每张券的券链接逐条调 `link_convert(type="coupon")`。
2. 每个入口独立确定最终展示地址：转链成功用转链地址；转链失败、空结果或非法结果时，用该入口自身的原始 `http`/`https` 地址；两者都不可展示时才省略。
3. 在有最终展示地址的报价中按 `final_price` 取最低，与当前链接到手价做差额。
4. 最低价所在渠道就是链接原渠道时，本轮不给差额，购买结论改走 `output.md` 里的第二支骨架。

**输出：** 渠道对比表、最低报价、与当前链接到手价的差额、购买结论。

### 步骤 8：价格参考

**输入：** 步骤 3 的 `history_low_price`、步骤 4 的 `goods_id` 和 `sku_id`。

**处理：**

1. 已确认唯一 `goods_id` 和 `sku_id` 后必须调 `goods_sku_price_trend(goods_id, sku_id)`，取得结果后再选回复；不以用户是否询问历史价格、当前报价是否有效或报价业务查询是否成功为前提。同轮相同参数复用已取得的趋势结果，不重复查询。趋势无数据或业务查询失败不阻塞比价。
2. 该链接渠道近 180 天最低价与识货 SKU 层历史价各自独立，不互相替代、不取两者更低值当作统一低点。
3. 价格水位只表述为低于、接近或高于所引用的那一个口径。

**输出：** 当前链接渠道近 180 天低点，以及识货 SKU 层历史价（有有效趋势数据时输出）。标准回复和兜底都按 `output.md` 展示有效历史数据；趋势无数据或业务查询失败时删除对应历史内容，不输出缺失或失败占位。

### 步骤 9：兜底关键词检索

**输入：** 步骤 1 的用户原文商品描述、步骤 3 的 `product_title`。

**只在这一种情况执行：** 本轮既走不了标准回复、也走不了追问，即无法收口到唯一 `sku_id` 且拿不到真实款式或规格候选，或同规格无有效报价、所有报价的转链地址和原始地址都不可展示。已能输出渠道比价结论时跳过本步骤，不另找相似商品。

**处理：**

1. 组装检索词：优先用用户原文里的商品描述，没有时取 `product_title` 里的品牌、系列、型号、品类词。两者都取不到可检索词时跳过本步骤。
2. 调 `search_goods_by_keyword(query=检索词)`，只取第一页，最多保留 3 条候选。
3. 无命中时可换一次更宽的关键词（去掉修饰词，只留品牌加品类）；仍无命中判定为搜索无命中。
4. 只记录候选的 `goods_name`、`price`、`href`。候选一律不再进入 `goods_styles`、`search_sku`、比价和趋势工具。

**输出：** 最多 3 条相似商品候选；或无可检索词、搜索无命中状态。

## 特殊情况

| 情况 | 可以输出 | 不能输出 |
| --- | --- | --- |
| 一条消息含多个链接 | 已识别到多条链接，请用户指定一条 | 任何一条链接的价格结论 |
| `link_parse` 返回多个不同商品 | 各候选的已确认信息 | 自行挑一条继续比价 |
| 只解析到商品层，用户也没给规格 | 链接商品信息和真实可选规格 | 用默认款式或首个 SKU 顶替 |
| 只解析到款式层 | 该款式下真实规格列表 | 跳过 SKU 直接比价 |
| `link_parse` 全为空但 `goods_link_query` 有渠道事实 | 平台、店铺、当前链接到手价、该链接渠道近 180 天最低价 | 识货同规格比价结论 |
| `goods_link_query` 返回 `not_found` 而 `link_parse` 有 ID | 识货侧商品、规格和同规格比价 | 当前链接到手价、链接所在店铺 |
| 两个工具都无结果，但能提取关键词并搜到真实候选 | 无法解析的说明、相似商品的展示价、补充信息指引 | 任何到手价、渠道和最低价结论 |
| 两个工具都无结果，也提取不到关键词或搜索无命中 | 无法识别的说明、可补充信息清单 | 任何商品、规格、价格、渠道字段 |
| 同规格无有效报价 | 当前链接到手价、识货展示价和已查询到的同规格历史价格 | 更划算的渠道结论 |
| 报价转链全部失败，但原始 `http`/`https` 入口有效 | 原始商品入口、已核实的价格事实和可展示最低价 | 因转链失败降级为兜底 |
| 报价的转链地址和原始地址都不可展示 | 已核实的价格事实 | 不可访问的入口、可购买最低价 |
| 两个历史口径只有一个有数据 | 有数据的那一个，并标注来源 | 用另一个口径的名义展示 |
| 链接指向二手、拍卖或非全新商品 | 该链接不纳入全新商品比价的说明 | 与全新报价直接比价 |

## 选哪种回复

| 情况 | 回复 |
|---|---|
| 一条消息含多条链接，或解析出多个不同商品，或规格未收口但有真实款式、规格候选 | 追问 |
| 规格已收口且至少有一条带最终展示地址的同规格报价 | 标准回复 |
| 其余 | 兜底 |

Phase 1 dedup now persists between installs. The previous build removed duplicate registry entries (`session-export`, `package`) during the source.npm cleanup but left the on-disk directories at `~/.ldm/extensions/session-export/` and `~/.ldm/extensions/package/`; `autoDetectExtensions` re-registered them on the same install run, and every subsequent `ldm install` regenerated the same duplicates. Alpha.30 moves each deduplicated extension's on-disk directory to `~/.ldm/_trash/<name>-deduplicated-<ISO-timestamp>` immediately after the registry write, so `autoDetectExtensions` (which only scans `~/.ldm/extensions/`) cannot find it. The dedup is now structurally permanent: a second `ldm install` run reports zero changes from the dedup path. Implementation splits the planner (pure, in `lib/registry-migrations.mjs`) from the executor (filesystem-side, exported as `executeDirectoryMoves` in the same module) so the move logic is testable against a real temp filesystem; the regression test in `scripts/test-legacy-npm-sources-migration.mjs` now stands up a fixture filesystem, runs the executor, and asserts both the moves and an `autoDetectExtensions`-style rescan to confirm the duplicates no longer appear as registration candidates. Skipped moves (source missing, rename failed) surface in install output instead of vanishing silently. Implements `ai/product/bugs/installer/2026-05-13--cc-mini--installer-dedup-reverts-between-installs.md`. Phase 2 source-types-migration is unblocked.

# 文书标准结构与格式规范

## 文书标准结构

```html
<div class="judgment">
  <h1>[法院名称]民事/刑事/行政判决书</h1>
  <div class="case-no">（[年份]）[法院简称]民初字第[案号]号</div>
  <section class="parties">当事人信息...</section>
  <section class="cause">案由...</section>
  <section class="claims">诉讼请求...</section>
  <section class="facts">事实与证据...</section>
  <section class="reasoning">本院认为（三段论）...</section>
  <section class="verdict">判决如下...</section>
  <footer>审判人员 / 日期 / 附录</footer>
</div>
```

## 输出格式约定

- 审查优化结果统一输出为 **HTML 格式**（`.html`），修改部分用红色字体标注
- HTML 便于跨平台查看、打印、分享，且不依赖 Word 等付费软件
- 文件命名规则：`<原文件名>_优化版.html`
- 输出目录：`workspace/output/`

## 文档预处理（输入格式处理）

审查文书前，需先将用户提供的文书提取为纯文本。

| 格式 | 处理方式 | 命令/工具 |
|------|----------|----------|
| `.doc`（旧版 Word） | 用 `scripts/doc_reader.py` 提取 | `python3 scripts/doc_reader.py <文件路径>` |
| `.docx`（新版 Word） | 用 `scripts/doc_reader.py` 提取（自动识别） | 同上 |
| `.pdf` | 用 `pdf` 工具直接分析 | `pdf(pdf=<文件路径>, prompt="提取全部文本")` |
| `.txt` / `.md` | 直接读取 | `read(<文件路径>)` |
| 网页 URL | 用 `web_fetch` 抓取 | `web_fetch(url=<URL>)` |

**注意事项**：
- `.doc` 文件可能是 HTML 格式伪装的（OLE2 容器内嵌 HTML），不要用正则剥离 HTML 标签，会误伤合法内容（如 `〈〉` 尖括号）
- `.pdf` 文件优先用 `pdf` 工具（支持 Gemini/OpenAI 原生 PDF 解析），不要先转文本再分析
- 提取后的文本应先检查完整性（关键段落是否齐全、法条引用是否完整），再进入审查流程
- 如用户提供的文书路径在 `~/下载/` 目录，需先复制到 `workspace/output/` 再处理（`pdf` 工具限制访问目录）

## 文风要求

| 要求 | 说明 | 参考 |
|------|------|------|
| **用词精准** | 法律术语准确，不用模糊词汇掩盖逻辑漏洞 | 写作风格规范 §一.1 |
| **结构清晰** | 使用标题、编号、层次，让复杂问题一目了然 | 获奖文书结构分析 |
| **语气中正** | 不冷漠，不煽情，平和而有力 | 获奖文书共性特征 |
| **简洁有力** | 每一句话都有其存在的意义 | 获奖文书文字分析 |
| **说理充分** | 不能仅以"依法"二字了事，要讲清为什么 | 写作风格规范 §一.1 |

> 📖 **详细写作规范**见 `data/award_docs/写作风格规范.md`

## 法条引用规范

- **必须是现行有效版本**，已废止、已修订的法条绝不援引
- 注意新旧法律衔接（如《民法典》施行后原《合同法》《物权法》已废止）
- 援引格式：《法律名称》第X条第X款第X项
- 引用司法解释需注明名称和条号

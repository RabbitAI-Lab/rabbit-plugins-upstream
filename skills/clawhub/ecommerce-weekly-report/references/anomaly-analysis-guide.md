# 异动归因方法与置信度分级

周报的价值在于解释"为什么变"。本指南给出标准归因流程。

## 第一步：确认异动是真的

- 与 4 周均值对比：单周 ±5% 以内的波动，默认视为噪音，除非有明确事件。
- 检查口径：统计周期错位、归因窗口调整、含税变化都会制造假异动。
- 检查数据完整性：某渠道数据延迟同步是"下滑"最常见的假原因。

## 第二步：一层层拆维度

按以下顺序拆，拆到能解释 70% 以上变化量为止：

1. **渠道**（自然搜索 / 付费 / 达人 / 社媒 / 老客）
2. **SKU / 品类**（Top10 SKU 逐个看）
3. **活动**（折扣、满减、直播、大促脉冲）
4. **地区 / 站点**（多站点运营时）
5. **新老客**（新客占比变化影响 AOV、退款率）

拆分输出格式：`总变化 +¥56k = SKU-A折扣 +¥39k + 信息流新计划 +¥14k + 其他 +¥3k`

## 第三步：区分四类原因

| 类型 | 特征 | 典型例子 |
|---|---|---|
| 自身动作 | 与本周运营动作时间吻合 | 调价、上新、加投、改详情页 |
| 平台因素 | 多店铺/同行同步变化 | 算法调整、类目流量池变化、平台活动 |
| 外部季节 | 与历史同期规律吻合 | 节日、发薪日、天气、开学季 |
| 竞争动作 | 份额下滑但大盘平稳 | 竞品降价、竞品大促、竞品断货（利好） |

## 第四步：给假设标置信度

找不到数据实锤时，允许写假设，但必须分级：

- **高置信**：有直接数据支撑（拆分后数字对得上）
- **中置信**：时间吻合 + 逻辑合理，但缺一层数据验证
- **低置信**：仅为合理猜测，需下周专项验证

低置信假设必须配一条"下周验证动作"。

## 常见归因错误

1. 把相关当因果——加投和增长同周发生，不代表增长全来自加投（要看边际 ROI）。
2. 只找一个原因——多数异动是 2-3 个因素叠加。
3. 忽略基数效应——上周异常低，本周"大涨"只是回归正常。
4. 忽略滞后效应——本周退款率升，原因常在上周的订单质量。
5. 用"市场不好"收尾——这是放弃归因，不是归因。

## 快速归因问题清单

- 这周我们自己改了什么？（价格、页面、投放、库存、物流）
- 变化集中在哪个渠道/SKU/地区/人群？
- 同行和大盘同步变了吗？
- 历史同期有没有一样的规律？
- 如果什么都不做，下周这个数会怎么走？

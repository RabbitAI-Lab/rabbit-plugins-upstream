# 记录模板

v2 默认写入 `data/members/{member-id}/`。真实姓名放在正文和 `skill-config.yaml`，路径使用 `member-XXX`。
相关方反馈写入 `data/stakeholders/{stakeholder-id}/`，路径使用 `stakeholder-XXX`。

## 成员侧关联反馈记录

成员侧只保存和成员表现直接相关的摘要，并引用相关方原始 `FBK` 事件。`线索级` 或 `未核实`记录只作为观察提醒，不进入成员长期画像和正式绩效结论。

```markdown
### {YYYY-MM-DD}（周X）
#### {HH:MM} - 相关方反馈关联 [OBS-YYYYMMDD-001]
**事件**: {成员相关行为或影响的事实摘要}  
**类别**: 协作沟通 / 项目交付 / 团队影响  
**评价**: ⭐⭐⭐ 一般 / ⚠️ 需关注 / ⭐⭐⭐⭐ 良好  
**证据等级**: 线索 / 反馈 / 事实 / 结论  
**核实状态**: 未核实 / 待补充 / 部分确认 / 已确认 / 已闭环 / 已撤销  
**关联事件**: FBK-YYYYMMDD-001  
**标签**: #相关方反馈

**观察笔记**:
- {只写可追溯事实，区分对方反馈和自己的判断}

**追踪项**:
- [ ] 中 - {需要和成员或相关方跟进的动作} (来源: FBK-YYYYMMDD-001)
```

## tasks/tasks.md

`tasks.md` 是唯一待办状态源，原始证据仍以 `timeline.md` 的事件 ID 为准。新记录使用“对象类型/对象”表示待办归属；`成员` 字段仅为 member 对象保留，兼容旧数据。

```markdown
# Team Memory 待办台账

> Markdown 是任务状态源；成员时间轴是事实证据源。使用 scripts/sync-tasks.py、review-tasks.py、resolve-task.py 管理。

## 任务列表

### TASK-YYYYMMDD-001 - {一句话待办}
**状态**: open / waiting / done / deferred / dropped
**优先级**: 高 / 中 / 低
**对象类型**: member / stakeholder
**对象**: member-001 {姓名} / stakeholder-001 {相关方名称}
**成员**: member-001 {姓名}
**主题指纹**: member:member-001:{归一化主题} / stakeholder:stakeholder-001:{归一化主题}
**来源事件**: OBS-YYYYMMDD-001 / FBK-YYYYMMDD-001
**来源文件**: members/member-001/timeline.md:{line}
**创建日期**: YYYY-MM-DD
**更新日期**: YYYY-MM-DD
**截止日期**:
**下次检查**: YYYY-MM-DD
**标签**: #标签

**任务内容**:
- {需要跟进的动作}

**历史记录**:
- YYYY-MM-DD sync: 创建自 OBS-YYYYMMDD-001 / FBK-YYYYMMDD-001
```

## 标签和评级

常用类别：

- 技术能力
- 协作沟通
- 项目交付
- 团队影响
- 成长潜力

相关方反馈类型：

- 需求
- 投诉
- 认可
- 风险
- 建议
- 沟通记录

证据等级：

- 线索：信息不完整，只用于提醒后续观察
- 反馈：来源明确但上下文未完全核实
- 事实：时间、对象、行为、影响基本清楚
- 结论：已复盘并确认原因、边界、动作和结果

核实状态：

- 未核实
- 待补充
- 部分确认
- 已确认
- 已闭环
- 已撤销

评级映射：

- 优秀/超预期：`⭐⭐⭐⭐⭐ 优秀`
- 良好/符合预期：`⭐⭐⭐⭐ 良好`
- 一般/正常：`⭐⭐⭐ 一般`
- 需关注/低于预期：`⚠️ 需关注`

追踪项优先级：

- 高：本周必须跟进
- 中：近期需要跟进
- 低：长期观察或机会点

待办状态：

- open：待处理
- waiting：已追问，等待反馈
- done：已闭环
- deferred：延期，必须有下次检查日期
- dropped：不再处理，必须写原因

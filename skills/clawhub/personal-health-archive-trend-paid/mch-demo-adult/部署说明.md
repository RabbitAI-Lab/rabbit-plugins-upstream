# 商户服务端 · 部署公网 HTTPS 说明

## 0. 为什么必须公网 HTTPS
- 微信支付**回调通知**（`PAY_NOTIFY_URL` / `REFUND_NOTIFY_URL`）由微信服务器**主动访问**你的服务端，且必须是公网可访问的 **https** 地址。
- 买家（SkillHub / WorkBuddy）调用你的 `/api/resource` 也必须公网触达，走 https 更安全。
- 结论：`server.py` 要跑在**有公网 IP 的机器**上，前面有**合法 TLS 证书**。

> 注意：WorkBuddy 的「CloudStudio 部署」只支持静态站点，跑不了这个 Python 后端，别走那条路。

## 1. 三种落地方案（任选其一）

| 方案 | 适合 | 成本 | HTTPS 方式 |
|---|---|---|---|
| A. 云服务器 + Caddy | 想稳定、独立可控 | ¥几十/月 | Caddy 自动申请 Let's Encrypt |
| B. 群晖 NAS + 反代 | 已有 NAS、零额外成本 | 0 | 群晖自带反代 + Let's Encrypt |
| C. PaaS（Render / Fly / 腾讯云函数）| 不想管服务器 | 免费~低 | 平台自动 https |

## 2. 通用：构建并运行容器（三种方案都先做这步）
```bash
cd payskill-build/mch-demo
docker build -t mch-demo .
docker run -d --name mch-demo --restart unless-stopped \
  --env-file .env -p 8080:8080 mch-demo
curl http://localhost:8080/health   # 期望返回 ok
```
或用 docker-compose：`docker compose up -d`。

## 3. 方案 A：云服务器（腾讯云轻量 / CVM）+ Caddy
1. 一台有公网 IP 的轻量服务器，装好 docker。
2. 准备一个域名，把 **A 记录**指向该服务器公网 IP。
3. 安装 Caddy（Debian/Ubuntu）：`sudo apt install -y caddy`。
4. 用本目录的 `Caddyfile`，把 `<你的域名>` 改成真实域名。
5. 启动：`sudo systemctl enable --now caddy`（或 `caddy run`）。Caddy 自动申请并续期证书。
6. 验证：`curl https://<你的域名>/health` 应返回 `ok` 且为 https。

## 4. 方案 B：群晖 NAS（Container Manager + 反代）
1. 套件中心装「Container Manager」（Docker）。
2. 在 NAS 上 build 本目录镜像，或用「项目」导入 `docker-compose.yml`（只保留 mch-demo 服务，去掉端口冲突）。
3. 控制面板 → 外部访问 → 反向代理：新增规则，来源 `<你的域名>:443` → 目的地 `localhost:8080`。
4. 同一页「证书」用 Let's Encrypt 给域名签发（需先配好 DDNS / 自有域名 + 验证）。
5. 路由器把 **80/443** 转发到 NAS（或仅 443 + DNS 验证签发证书）。

## 5. 方案 C：PaaS（以 Render 为例）
1. 把 `mch-demo` 目录推到 GitHub 仓库。
2. Render 新建 Web Service，连仓库：Build `pip install -r requirements.txt`，Start `python server.py`，端口 8080。
3. Render 自动给 `*.onrender.com` 发 https；如需自有域名，在 Render 绑定并验证。
4. 其余 PaaS（Fly.io /  Railway / 腾讯云函数 SCF+APIGW）同理，函数型需把 `ThreadingHTTPServer` 改为平台 handler。

## 6. 部署后必做
1. 把 `.env` 里两行改成你的真实公网地址，然后重启容器：
   ```
   PAY_NOTIFY_URL=https://<你的域名>/api/pay/notify
   REFUND_NOTIFY_URL=https://<你的域名>/api/refund/notify
   ```
2. 在 SkillHub 商家后台发布团队 Skill：slug 须 = `SKILL_ID`（`pediatric-health-record`），并把服务端地址 `https://<你的域名>/api/resource` 填到对应配置。

## 7. 验证完整链路
```bash
# 首次请求 → 应返回 402 + WeixinPay-Required
curl -X POST https://<你的域名>/api/resource -H 'Content-Type: application/json' -d '{"query":"建档"}'
# 真实支付后带 X-Out-Trade-No 重试 → 应返回 200 + content
curl -X POST https://<你的域名>/api/resource -H 'Content-Type: application/json' \
  -H 'X-Out-Trade-No: <支付后的单号>' -d '{"query":"建档"}'
```

## 备注

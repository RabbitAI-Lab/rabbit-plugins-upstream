# 商品认知录入规范 · 严格冒号软标签(唯一契约源)

> 本文件是录入格式的**唯一事实源**。录入助手(`system-prompt.md`)、Python `intro_parser.py`、Java `IntroSoftSpecParser` 三处必须与本文严格对齐。
> 对齐产品方案 `AI导购系统产品方案V1.0` §4.3 商品认知卡。

## 1. 基本格式

- 每项**独占一行**,格式 `标签名：内容`;标签名必须在**行首**,值可跨多行直到下一个行首标签。
- 冒号统一中文 `：`(英文 `:` 兼容)。
- 多值统一中文 `；`(`;` / 换行兼容)。
- 只用下表标签,**标签名一字不差**。

## 2. 标签全集

| 标签(别名) | 目标字段 | 必填 | 值格式 |
|---|---|---|---|
| `商品名称：`/`名称：` | 边界占位(不进产物、不计入 N) | — | 单值 |
| `定位：` | positioning | 选 | 单值一句话 |
| `类目：`/`商品分类：` | category（参考，以 ai_category 为准） | 选 | 多值 `；` |
| `品牌：` | brand（参考，以 ai_brand 为准） | 选 | 单值 |
| `核心卖点：`/`卖点：` | selling_points[]（营销主张 is_claim=true） | **必** | 多值 `；` |
| `关键事实：`/`商品介绍：` | facts[] + summary 原料 | **必** | 每条可带 `(来源)` / `[推断]` |
| `能力：` | capabilities[{name,evidence[]}] | 选 | `能力名<-证据1；证据2`，多能力换行 |
| `适用人群：` | tag(audience)，受控集 | 选 | 受控词 `；` |
| `适用场景：`/`场景：` | tag(scenario) | 选 | `；` |
| `功效：`（仅保健营养类） | tag(efficacy) | 选 | 受控词 `；` |
| `推荐关键词：`/`关键词：` | keywords[] | 建议 | 3-8 个 `；` |
| `禁用表达：` | guardrails.disallow[] | 选 | `；` |
| `允许表达：` | guardrails.allowed[] | 选 | `；` |
| `常见问题：` | qa[{q,a}] | 选 | `问？答` |
| `需求：`/`解决问题：` | cognition.needs[] | **建议** | 多值 `；` |
| `用户会问：`/`搜索说法：` | cognition.query_phrases[] | 选 | 多值 `；` |
| `不适合：` | cognition.not_for[] | 选 | 多值 `；` |
| `差异化：`/`为什么选它：` | cognition.differentiators[] | 选 | 多值 `；` |
| `契合理由：` | cognition.fit_reasons[{for,reason}] | 选 | `人群或场景<-理由`，多条换行 |

## 2.1 意图/推荐增强字段·作用说明(准确率导向)

> 目标不是省 LLM，而是**推荐更准**。准确率的三个病根：①召回错(该出的没出/误召回) ②排序错(相似品里选错) ③理由错(推对了但没戳中需求)。下面 5 个字段分别对症，是 2026-08-20 为提升"意图理解准 + 推荐准"新增。

| 字段 | 治哪个病根 | 作用(为什么加) | 消费方 |
|---|---|---|---|
| **needs 需求/痛点** | ①召回 | 导购 query 是**需求语言**("加班没空吃饭""想犒劳自己")，商品默认是**属性语言**，两者对不上就召回错。商品自带需求词 → 与用户表达同频，**进 embed_text 直接改善意图召回对齐**。最大杠杆。 | 向量召回 + advisor |
| **query_phrases 用户会怎么问** | ①召回 | 补**词汇鸿沟**:用户口语提问/俗称("有没有辣的""番茄面""管饱的")与商品名/卖点用词不一致。显式存"用户视角说法"，进召回让语义/关键词都能咬上。 | 向量召回 + 关键词召回 |
| **not_for 不适合/排除** | ①召回(负向) | **负向匹配信号**:"不适合的人/场景"(如 对鸡蛋过敏、婴幼儿)。用户命中排除条件时**直接砍掉**，避免"先误推、再让 LLM 圆场"。准确率里"不该出的别出"这一半靠它。**≠ 禁用表达**(那是合规不能说的话，这是不匹配的对象)。 | 排序过滤 + advisor |
| **differentiators 差异化点** | ②排序 | 召回回来一堆相似品，凭什么选中该推的?**"同类里我独特在哪"**(如"唯一加真鸡蛋")。给 LLM 生成**有说服力**的理由、辅助排序区分，否则推荐千篇一律。 | advisor 生成 + 排序 |
| **fit_reason 契合理由** | ③理由 | 推对商品后，理由要按**不同意图**说不同话。`人群或场景<-理由`(如 `加班宵夜<-开水冲泡3分钟就能吃`)，让 advisor 生成**个性化**推荐语，而非复读卖点。 | advisor 生成 |

**进不进向量(embed_text)的边界**:
- **进** ✅:`needs`、`query_phrases` —— 属"意图对齐"，进向量提升召回。
- **不进** ❌:`not_for`(负向，进了会污染语义)、`differentiators`(营销倾向，保持向量只讲可核实事实/能力)、`fit_reasons`(生成侧素材)。

## 3. 判定阈值(命中才走规则解析)

> 行首识别到的已知标签数 **N ≥ 3**，且至少命中 `核心卖点` 或 `关键事实(商品介绍)` 之一且非空。
> 不满足 → 系统降级 LLM(Python)或跳过(Java 直落路)。

## 4. 关键规则

1. **卖点 vs 事实分离**:
   - 核心卖点 = 营销主张(高钙高蛋白 / 便携),打动人即可。
   - 关键事实 = 客观可核实(每100ml含钙约120mg / 机身厚16mm)。
   - 事实有依据 → 末尾 `(来源)`,如 `每100ml含钙约120mg(营养成分表)`。
   - 事实是推断 → 标 `[推断]`,如 `有助睡眠[推断]`(→ verified=false,不作推荐硬证据、不进向量)。
2. **能力**:`能力名<-证据1；证据2`,须由卖点/事实支撑,如 `营养早餐<-高钙高蛋白；便于准备`。多条换行。
3. **值内不要出现裸标签名+冒号**(如卖点内容里写 `事实：`),会干扰行首解析。
4. **适用人群受控词**(不在集内不写):
   `儿童、青少年、成人、中老年、孕妇、哺乳期、术后康复、健身增肌、减脂、免疫力低下`。
   (上线后以领域库 `tag_ontology` 的 audience 受控集为准,本集作兜底。)
5. **适用场景 / 功效**:无硬编码受控集,以 `tag_ontology` 当期内容为准;归不进的会被丢弃。

## 5. 合规红线(违反必须拒绝写入,改成合规说法)

- 任何商品:不得用 `最 / 第一 / 国家级` 等绝对化用语当卖点。
- 食品/普通商品:不得宣称 `治疗 / 治愈 / 养生治病 / 更营养一定`。
- 保健营养类:不得宣称 `增强免疫 / 长高 / 治愈疾病` 及任何医疗用语;`功效` 只能写保健/改善方向。
- 违规词写进 `禁用表达`,合规推荐说法写进 `允许表达`。

## 6. 落库去向(供理解,商家无需关心)

- 结构化结果落 `t_product_attr`:核心 CPV(category/brand/selling_points/summary/keywords)进各列;
  **认知卡富结构**(定位/能力/事实/qa + 本次新增 needs/query_phrases/not_for/differentiators/fit_reasons)进 `cognition` JSON 列;
  合规边界(禁用/允许表达)进 `guardrails` JSON 列;人群/场景/功效标签归一后进 `t_product_tag` + ES。
  (`attributes` 列保留给扁平 CPV 事实袋，规则路为 `{}`;拆列原因见 mall 设计 spec。)
- 向量 `embed_text` 只取"意图/能力/事实"侧(定位+summary+能力+**需求 needs+用户说法 query_phrases**+功效/场景/人群标签+类目+verified 事实),
  **排除卖点(is_claim)/推断/guardrails/not_for/differentiators/fit_reasons**,用于意图识别召回。
- 原文 `ai_product_intro` 保留在 `t_product_detail` 溯源。

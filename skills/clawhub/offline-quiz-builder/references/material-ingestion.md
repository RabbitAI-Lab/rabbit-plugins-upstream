# 资料读取与出题策略

用户上传的资料形态高度不确定。本文档给出按类型的处理路径，以及出题规模的估算方法。

## 第一步：先判断走哪条通道

读取用户提供的文件后，先判断它属于哪一类：

| 判断依据 | 通道 | 动作 |
| --- | --- | --- |
| 是 JSON，且含 `questions` 数组或顶层就是题目数组 | **A 快速导入** | 直接校验 → 构建，跳过出题 |
| 是表格/文档，但内容本身已是「题目+答案」的成品题库 | **A′ 格式转换** | 只做结构转换，不重新出题 |
| 是讲义、笔记、教材、PPT 等知识性资料 | **B 资料出题** | 阅读 → 提炼考点 → 出题 |

**关键区分**：A′ 与 B 的差别在于「资料里有没有现成的题目」。
有现成题目时**绝不重新出题**——用户的题目往往来自真题或老师划的重点，价值远高于 AI 现编的。

## 按文件类型的读取方式

| 类型 | 读取方式 |
| --- | --- |
| `.md` `.txt` `.json` `.csv` | 直接用 Read 工具读取 |
| `.docx` | 用 python-docx 提取段落与表格；注意 .docx **不含分页信息**，`source.page` 必须为 `null` |
| `.pdf` | 用 Read 工具（支持 PDF），可获得页码 → `source.page` 可填真实整数 |
| `.xlsx` | 用 openpyxl 读取；先打印表头判断列含义，不要臆测列顺序 |
| `.pptx` | 用 python-pptx 提取每页标题与文本框；`locator` 用「第 N 页 标题」 |
| 图片 / 扫描件 | 直接读取识别；若字迹不清应向用户说明哪部分无法确认，不要猜 |

依赖缺失时用隔离环境安装，不要污染用户全局环境：

```bash
<managed-python> -m venv <venv-dir>          # 若尚无 venv
<venv>/Scripts/pip install python-docx openpyxl python-pptx
```

## 第二步：出题规模估算（B 通道必做）

**在开始出题前**先估算并告知用户，避免大资料失控。

估算方法：

1. 统计资料的有效知识点数量（不是字数——目录、致谢、参考文献不算）
2. 按 **1 个知识点 ≈ 1.5 道题** 估算
3. 用下表换算耗时并向用户播报

| 题量 | 大致耗时 | 建议 |
| --- | --- | --- |
| ≤ 30 | 1-2 分钟 | 直接做 |
| 30-80 | 3-6 分钟 | 直接做 |
| 80-150 | 6-12 分钟 | 做，但提示用户耐心等待 |
| > 150 | 12 分钟以上 | **必须先问用户**：全量出，还是按重点章节裁剪 |

播报格式示例：

> 资料里识别出 约 68 个知识点，预计生成 **90-110 道题**，覆盖 4 个科目，大约需要 8 分钟。
> 要现在开始吗？也可以只挑其中某几章。

## 第三步：分片生成，避免一次性输出过长

题量超过 40 道时，**按科目或章节分片生成**，每片单独写入一个临时 JSON 文件，
最后合并。原因：

- 单次输出过长容易在中途截断，产生无法解析的半截 JSON
- 分片后某一片出错只需重做那一片
- 用户能看到进度

推荐落盘结构：

```
<工作目录>/
  _bank_parts/
    part1_<科目>.json     ← 每片是一个题目数组
    part2_<科目>.json
  bank.json               ← 合并后的完整题库，交给 build_bank.py
```

## 第四步：预检

合并出 `bank.json` 后，**先跑校验再建站**：

```bash
python scripts/build_bank.py <bank.json> <site-dir> --check-only
```

校验通过才继续。常见错误与修法：

| 报错 | 原因 | 修法 |
| --- | --- | --- |
| `题干空位数 N 与答案数 M 不一致` | 填空题 `____` 数量与 answer 数组对不上 | 数清题干里的 `____`，或调整 answer |
| `答案 X 不在选项 key 中` | 答案写了选项文本而非 key | 改成 `"A"` 这样的 key |
| `多选题答案少于 2 项` | 出成了单选却标 multiple | 改 type 为 single |
| `source.page 必须是整数或 null` | 编造了 "第3章" 这类字符串页码 | page 填 null，章节信息放 locator |
| `简答题 keywords 需为 2-12 个` | 关键词太少或堆砌过多 | 取 3-6 个踩分点 |

## 第五步：向用户预览确认

建站**之前**必须展示以下内容并等待确认：

1. 题目总数、题型分布、科目分布、难度分布（`--check-only` 的输出已含这些）
2. **随机抽 3 道题的完整内容**（题干、选项、答案、解析），题型尽量不同
3. 明确提示：「确认后开始建站；也可以现在告诉我要调整哪些地方」

抽样展示是最有效的质量闸门——用户扫一眼就能发现 AI 是否理解错了资料。

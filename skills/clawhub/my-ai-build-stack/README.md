Set Up a New Project the Same Way Every Time, in Plain Words

Tell your AI agent what you want to build. Pick your stack, or use the default example stack. Answer a few questions. Get a full setup plan for your chosen stack, ready to review.

Most new projects start in a different way every time. One app uses one database, the next app uses another one, the hosting is different, the files are in a different place, and no one remembers how the last app was built. When something breaks, no one knows where to look. This skill sets up a new project from any stack you choose, the same way every time, with a plan you can check before anything is built.

## What you get

- Any stack, in plain words: you pick the builder, database, hosting, version control, and judge, or use the default example stack
- Default example stack: Muse as judge, Claude Code as builder, GitHub as version control, Supabase as database, Netlify as hosting

## Who this is for

Founders with no code, who want to start a new app or website the same way every time, in plain words, with any stack. Small business owners who want one clear stack to hand to a builder. Freelancers and builders who need a clear setup plan to hand to a developer.

## Why this saves money

Starting the same way every time is cheaper than starting from zero every time. A clear plan stops the builder from picking a new tool for every project, rebuilding the database, or deploying in a way no one can repeat.

## Technical, for coders

Structured setup plan for any stack: builder, database, hosting and deployment, version control, and architecture and quality judge, all chosen by the owner. Default example stack is Claude Code as builder, Supabase as database, Netlify as hosting and deployment, GitHub as version control, and Muse as architecture and quality judge. File list, database table list with columns, deploy steps with cache and build checks, and a review checklist, ready to brief any AI builder, or a human developer. No guarantee of users, speed, or money, and no claim that a plan alone makes an app work. The plan is a draft for owner review, not a live change.

## The stack

You choose all five pieces, or say use the default for any piece:

1. Judge: decides the plan, checks the work, line by line, before anything goes live. Default example: Muse
2. Builder: writes the code, makes the files, fixes what the judge flags. Default example: Claude Code
3. Version control: keeps every version of the code, in one place. Default example: GitHub
4. Database: stores the data, in tables, with rules on who can see what. Default example: Supabase
5. Hosting and deployment: puts the app on the web, only on owner approval. Default example: Netlify

How they connect: the judge writes the plan. The builder builds from the plan, and puts the code in version control. The app reads and writes data in the database. Hosting takes the code and puts it live. The judge checks the live result, and the builder fixes what the judge flags.

## How to use it

1. Install the skill in your AI agent (see below).
2. Give your agent your new project idea, in plain words.
3. Pick your stack, or say use the default: builder, database, hosting, version control, and judge.
4. Answer, in plain words: what does it do, who uses it, what are the main screens, what data must it store, who signs in, do you have a domain, what language, phone or laptop first?
5. Ask: "Set up my project with my-ai-build-stack."
6. Read the plan. Approve the file list, the table list, and the deploy plan first, before any repo is created, any table is made, or anything is deployed.

## What it will not do

- It will not create a repo, create a database, create a table, deploy, or publish anything by itself.
- It will not invent a project name, a database, a table, a domain, a price, a user number, or a client.
- It will not claim your project is live unless it was deployed and checked in a logged out browser.
- A setup plan is not a promise of users, speed, or money.

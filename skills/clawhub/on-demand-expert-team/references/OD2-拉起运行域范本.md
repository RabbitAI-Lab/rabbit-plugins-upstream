## OD2-拉起运行域范本

### 范本概述

OD2 域全任务范本，覆盖 OD2-01/OD2-02/OD2-03 全部任务的产物样式，承接 OD1 范本的示例团队（态2 子代理态）。

### 范本正文

**【OD2-01 团队实例化】实例化记录**：

```markdown
## 团队实例化记录

- **机制三态**：态2 子代理态（子代理工具可用，团队工具不可用）
- **编排者**：本会话承担
- **成员拉起**：
  | 成员角色 | 拉起方式 | name 参数 | 状态 |
  |---------|---------|----------|------|
  | 资料研究员 | 子代理 | 资料研究员 | ✅ 就绪 |
  | 数据分析师 | 子代理 | 数据分析师 | ✅ 就绪 |
  | 撰稿人 | 子代理 | 撰稿人 | ✅ 就绪 |
  | 审稿人 | 子代理 | 审稿人 | ✅ 就绪 |
- **提示词注入**：OD1-03 即席生成的成员提示词已内联注入各子代理 prompt 参数
```

**【OD2-02 成员调度执行】调度与产出记录**：

```markdown
## 调度与产出记录

**Phase 1 资料采集**（单成员）：
- 调度：资料研究员（name=资料研究员）｜输入：任务约束与范围
- 产出：资料要点集（含来源清单）✅

**Phase 2 数据核对**（串行）：
- 调度：数据分析师｜输入：Phase 1 资料要点集（经编排者中转）
- 产出：数据核对表 ✅（口径统一说明 + "待验证"标注清单）

**Phase 3 报告撰写**（串行）：
- 调度：撰稿人｜输入：资料要点集 + 数据核对表（经编排者中转）
- 产出：报告初稿 ✅（结构覆盖市场规模/竞争格局/趋势判断三部分）

**Phase 4 审核交付**（串行）：
- 调度：审稿人｜输入：报告初稿
- 产出：审核意见清单 ✅

**并行标注说明**：本任务各阶段为串行依赖；若 Phase 1 拆双研究员则该阶段扇出⇉并行调度。
```

**【OD2-03 消息中转与进度通报】通报记录**：

```markdown
## 进度通报（Phase 2 结束时推送）

- **阶段目标**：完成关键数据交叉核对与口径统一
- **产出摘要**：数据核对表已生成；3 项数据来源冲突已标注"待验证"
- **下一步**：撰写人开始报告撰写，消费要点集与核对表

**中转记录**：Phase 1 产出 → 编排者 → Phase 2 输入；成员间无直连。
```

### 结构要点标注

1. 建团/拉起只由编排者执行；态2 下 name 参数传成员角色名（中文）
2. 严格按 SOP 阶段推进，严禁跳阶段；前序产出作为下阶段输入经编排者中转
3. 成员产出由成员输出，编排者严禁代写；产出不合格交 OD3-02，不由编排者改写
4. 每阶段结束推送进度通报（阶段目标/产出摘要/下一步）；语言与用户需求一致
5. 态3 单会话态下：以角色分段替代子代理，各段产出标注执行角色，段间做基元内分步校准

### 替换清单

成员角色、name 参数、各阶段调度内容与产出描述、通报内容全部替换为实际任务；记录表结构、中转说明、要点标注框架为固定样式。

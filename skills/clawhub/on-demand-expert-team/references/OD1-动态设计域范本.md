## OD1-动态设计域范本

### 范本概述

OD1 域全任务范本，覆盖 OD1-01/OD1-02/OD1-03 全部任务的产物样式，承接 OD0 范本的示例任务「撰写一份行业研究报告」。

### 范本正文

**【OD1-01 团队角色设计】团队设计文档·角色章节**：

```markdown
## 团队设计 —— 行业研究即时团

### 编排者职责声明（纯编排）
确认研究目标 → 按阶段调度成员 → 中转成员产出 → 汇编最终报告。编排者不亲自做任何专业分析。

### 成员清单（职责互斥）
| 成员角色 | 类型 | 职责边界 | 输出物 | 协作接口 |
|---------|------|---------|--------|---------|
| 资料研究员 | 🤝协作 | 行业公开资料检索与要点提炼 | 资料要点集（含来源清单） | 向数据分析师提供要点；向撰稿人提供背景素材 |
| 数据分析师 | 🤝协作 | 关键数据交叉核对与口径统一 | 数据核对表（含"待验证"标注） | 向撰稿人提供数据结论 |
| 撰稿人 | ⭐核心 | 报告结构设计与全文撰写 | 报告初稿 | 消费调研与分析产出；向审稿人提交初稿 |
| 审稿人 | 💡支持 | 逻辑、数据引用、结论支撑度审查 | 审核意见清单 | 向编排者返回审核结论 |

**最小团队核对**：4 个领域各自互斥，无职责重叠成员；数据核对不可并入撰稿（交叉验证要求独立视角）。
```

**【OD1-02 SOP 阶段编排】团队设计文档·SOP 章节**：

```markdown
## SOP 阶段编排（4 阶段）

- **Phase 1 资料采集**：资料研究员（⭐独立执行，兜底：编排者可追加检索指令重跑）
  - 输入：任务约束与范围 → 输出：资料要点集
- **Phase 2 数据核对**：数据分析师（串行，消费 Phase 1 产出）
  - 输入：资料要点集 → 输出：数据核对表
  - **门禁点**：核对覆盖性（要点集全部条目被处理）/ 一致性（口径统一）/ 可汇编性
- **Phase 3 报告撰写**：撰稿人（串行，消费 Phase 1+2 产出）
  - 输入：资料要点集 + 数据核对表 → 输出：报告初稿
  - **门禁点**：结构覆盖三部分要求 / 数据引用与核对表一致
- **Phase 4 审核交付**：审稿人 → 编排者汇编（串行）
  - 输入：报告初稿 → 输出：审核意见清单 → 终稿汇编
  - **门禁点**：审核意见闭环（每条意见有采纳/驳回记录）

**并行标注**：Phase 1 为单成员阶段；如任务范围扩大可拆双研究员并行（⇉）。
**基元数核对**：4 阶段 ≤5 ✅
```

**【OD1-03 角色提示词即席生成】内联注入示意**（提示词不落盘，此处仅示意注入内容要点）：

```markdown
## 编排者提示词要点（内联注入）
- 铁律六条全量写入：纯编排 / 建团只由编排者 / 严禁代写+成员互连经中转 / 严禁跳阶段+每阶段通报 / 调度 name 传角色名中文 / 输出语言与用户一致
- 严禁行为清单：禁跳过建团、禁代写成员产出、禁跨阶段、禁成员直连、禁拉起编排者自己
- 成员分工表 + SOP 四阶段 + 各阶段门禁点

## 成员提示词要点（每成员内联注入）
- 职责边界 + 分析维度 + 输出格式（对齐设计稿"输出物"列）+ 不越界声明（不负责事项）
- 示例·数据分析师：负责数据交叉核对与口径统一，输出数据核对表；不负责撰写报告正文；输出格式为"指标/口径/来源/结论/待验证标注"五列表
```

### 结构要点标注

1. 编排者职责声明必须含"纯编排"表述；成员清单五列齐全（角色/类型/职责/输出物/接口）
2. 阶段数 3~5（基元数≤5）；每阶段有输入输出与门禁点；可并行成员标注 ‖ 或 ⇉
3. 成员提示词的输出格式必须与设计稿"输出物"列一致——编排者才能直接汇编
4. 提示词即席生成、内联注入，不落盘为交付物（本范本仅为要点示意）
5. 定稿前运行 `python scripts/validate_team_design.py <设计文档>` 预检

### 替换清单

成员角色/类型/职责/输出物/接口、阶段名称与 I/O、门禁点核对内容、提示词要点全部替换为用户任务实际内容；设计文档章节框架、成员清单五列表、阶段 I/O 结构、铁律条目为固定框架。

# 执行、成本与恢复

## 先减少浪费

不靠减少用户已确认的版数、必要姿态或视觉丰富度来省成本。常见可省项是：对忠实提取再编辑一次、为每一版重复处理同一素材、自动反复润色、因超时误判重生、只改图注却重做全部素材、为再次测试导出而重新生成整期。

规划时给出提取任务、必要变体和整版制作的预计数量及复用关系；这不是费用报价，也不包含未知失败重试。不要为了判断是否需要二次编辑，再增加一次模型分类调用。

## 任务的实际状态

使用稳定任务 ID 与内容输入指纹。明确用户主动重生成时创建新意图 ID；同一任务失败恢复保留原意图和原要求。只有“文件存在 + 能打开 + 哈希与输入/结果登记一致”才能称为缓存命中。

| 发现的状态 | 下一步 |
|---|---|
| 当前任务已有可核验的成功输出 | 直接复用并记录命中 |
| 成功输出已保存，后处理/展示失败 | 从保存结果修复后处理，不调用模型重生 |
| 服务明确表示尚未开始的临时拒绝 | 最多自动补试一次；底层客户端不能叠加重试 |
| 超时、连接中断、响应不完整、结果未知 | 检查同一任务的可靠记录；无法核验时保留中断状态，不自动生成第二份 |
| 参数错误、权限错误、身份错误 | 报告具体原因，修改问题后再执行，不消费同一错误输入 |
| 审美建议或用户已经满意 | 展示建议或继续，不强迫意见和重生 |

辅助脚本只记录、核验和约束任务，不调用任何模型，也不会自动查询供应商任务。需要从供应商恢复时，使用当前宿主提供的查询工具；不能把本地重试逻辑描述为跨平台后台恢复能力。

保存操作应尽早且原子化；任务执行前登记启动，返回后立即保存原始结果再做后处理。关闭聊天或进程被杀死后，工具可能已停止执行；这份 Skill 不承诺独立常驻后台服务。重开后从工程和任务状态继续。

## 诚实的运行记录

每项记录实际工具/provider、可得模型、任务 ID、开始/结束、输入指纹、输出文件与哈希、状态和可得用量。未返回模型名时标“未提供”，不要猜型号。未知 Token 是 `null`，不能填 0；没有输入/输出/缓存拆分就不编造拆分。

区分：逻辑制作任务、任务尝试、底层工具调用、供应商请求。一次提取组可能涉及多个底层生图/核对请求，未逐次观测就不能把外层尝试数说成完整 API 调用数。累计任务耗时含并行重叠，不等于等待时间。宿主聊天推理和子代理 Token 若无计量也不包含在图像任务用量里。

不把 CLI 的 `tokens used` 或 API 的部分 usage 当作完整账单，不凭模拟测试宣称实际节省某个百分比。不设置用户未要求的硬预算或额外付费确认点。

## 遇到这些问题再读

- **原人与变体同时出现：** 明确两张参考指向同一身份；写清本版使用哪一个姿态。先修对应素材/版面。
- **修改被早期计划覆盖：** 使用最新获批版面和本次修改作为依据，保留其他页与历史。恢复旧版本不是取消用户当前的全部要求。
- **提交超时却已生成：** 找同一任务的可靠返回/落盘记录，先同步当前页与历史。不能因聊天显示失败就判定模型没有做过。
- **前一元素成功、后一元素失败：** 按元素复用已验证结果；整组工具未交回时如实保留未知状态。
- **导出测试失败：** 从已经确认的页面重试导出。不要因为按钮、路径或 PDF 脚本问题重新生成报纸。
- **PDF 很大：** 打印 PDF 只装最终页面，完整工程另存；工程按内容哈希去重。不靠偷偷降低画质掩盖重复嵌入。
- **分辨率与请求不一致：** 记录实际像素，按物理尺寸计算有效 DPI，并解释限制。等比适配可接受，冒充原生高分辨率不可接受。

这些是从实际制作与针对性故障测试提炼的处理原则，不代表每份报纸都发生过这些故障。公开示例只能使用获准公开的素材、虚构材料或具有适当使用条件的来源。

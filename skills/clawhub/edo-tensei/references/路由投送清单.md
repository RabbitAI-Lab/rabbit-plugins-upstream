# 路由投送清单（Route / Merge Handoff）
> 适用于：拆分重会话时，发现某块待拆内容其实已被「现有会话」覆盖，应**合并投送**而非新建会话。
> 用法：在重会话里执行 `卫星转生` 时，技能先跑本清单 → 命中的走合并，未命中的才新建。
> 配合：控制塔 `INDEX.md`（唯一事实源）+ `子任务拆分交接清单.md`（拆分主流程）。

## 2. 待拆内容 × 路由判定
| 待拆内容 | 命中现有会话？ | 目标会话代号 | 动作 | 交接文档 |
|---------|--------------|------------|------|---------|
| 内容A（如：素材需求） | 是 → R0-C 已覆盖 | R0-C | **路由投送（合并）** | 追加 `会话交接_YYYYMMDD_N_主题_续接.md` 到 R0-C |
| 内容B（如：新模块代码） | 否 | 新建 R0-B1 | 新建卫星 | 新建 `会话交接_YYYYMMDD_N_主题.md` |
| 内容C | 否 | 新建 R0-B2 | 新建卫星 | 新建 |

## 3. 路由投送（合并）操作
- [ ] 在目标会话行（INDEX）确认其当前状态（活跃 / 已归档）。
- [ ] 活跃 → 直接把内容续接到该会话，下一回合在其内继续。
- [ ] 已归档 → 生成 `会话交接_YYYYMMDD_N_主题_续接.md` 作为该会话续篇，落 `.workbuddy/control-tower/handoffs/`。
- [ ] INDEX 该会话行「备注/续接链」追加：`续接于 YYYYMMDD（来自 R0-B 路由投送）`。
- [ ] **不**为该内容新建会话代号（避免功能重叠的孤儿会话）。

## 4. 新建（未命中）操作
- [ ] 代号 = 源会话代号 + 新序号（如 R0-B → R0-B1）。
- [ ] 生成独立交接文档，落 `.workbuddy/control-tower/handoffs/`。
- [ ] INDEX 新增行：代号、上游（源会话）、状态、拆分历史留痕。

## 5. 收尾
- [ ] 源会话已归档。
- [ ] INDEX 拆分历史追加：`YYYY-MM-DD：R0-B 过重 → 就地拆分；命中路由投送×1（并入 R0-C）、新建 R0-B1/R0-B2`。
- [ ] 新会话用「新会话启动提示词」开局；合并的目标会话从 INDEX 拉起继续。

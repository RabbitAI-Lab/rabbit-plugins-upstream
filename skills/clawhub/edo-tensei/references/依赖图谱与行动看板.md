> 配合：控制塔 `INDEX.md`（唯一事实源）+ README 第十一节「跨会话依赖 / 状态一致性」。

## 2. 拓扑排序 / 就绪顺序
- 无环时输出执行序（依赖越少越靠前）：
  `R0-C →（验收后）R0-B →（验收后）R0-A`
- 若 A←B 且 B←A → **检测到环（死锁）**，停止并走第 3 节破环。

## 3. 死锁检测与破环
- [ ] `依赖图谱` 已跑，DAG 无环（或已破环）。
- 若发现环：常见破法 = 把循环部分抽成新的公共子会话 `R0-E`，让双方都依赖 R0-E，环即断。
- 破环后在 INDEX 1.5 更新依赖边，重跑拓扑排序确认无环。

## 4. 下一步行动看板（就绪队列 / runnable queue）
> 规则：上游交付物全 `已验收` 且自身 `待启动/阻塞` → 进入可启动队列。
| 现在该启动 | 触发条件（上游已验收） | 给它什么 handoff | 用户动作 |
|-----------|---------------------|-----------------|---------|
| R0-C | 无依赖 | 无（直接开工） | 复核并翻 `已验收` |
| R0-B | R0-C 已验收 | 交 `会话交接_…_提示词.md` | 开 R0-B 会话，贴文件名 |
| R0-A | R0-B 已验收 | 交 `会话交接_…_素材清单.md` | 开 R0-A 会话，贴文件名 |

## 5. 一致性对账（状态漂移清单）
> 跑 `会话盘点` 时，重读所有 handoff 文件 + INDEX，比对有效状态与登记值。
- [ ] INDEX 记 R0-B「进行中」但交付物 3 天未改 → 提示核实是否卡死
- [ ] R0-C 标「已验收」却找不到验收记录 → 提示脏写，需补验收
- [ ] 某交付物文件存在但 INDEX 未登记 → 提示漏登记（游离态）
- [ ] 消费方已引用某交付物但其状态仍 `已完成待验收` → 提示越级消费（脏读）

## 6. 两阶段提交收尾核对（每条跨会话交付物）
- [ ] 生产方：交付物文件已落 `.workbuddy/control-tower/handoffs/`，INDEX 标 `已完成待验收`
- [ ] 用户：复核后翻 `已验收`（或打回重做）
- [ ] 消费方：启动重读 INDEX，确认上游 `已验收` 才引用，否则转 `阻塞(等待X)`
- [ ] 无会话消费未 `已验收` 的交付物（无脏读）

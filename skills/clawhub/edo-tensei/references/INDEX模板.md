## 1.6 状态机枚举（消灭游离态）
每个会话 / 交付物的状态只能是以下其一：
- `待启动`：尚未开始
- `进行中`：正在干活
- `已完成待验收`：交付物已产出，等用户复核（已提交、未确认）
- `已验收`：用户确认，**唯一可被其他会话消费的状态**（读已提交）
- `阻塞(等待X)`：因依赖 X 未就绪而暂停，X 为上游代号
- `已归档`：完成并归档
> 消费规则：会话仅在「上游交付物状态=已验收」时才可引用；否则自动转 `阻塞(等待X)`。

## 5. 约定
- 单一写入者：控制塔会话负责更新本索引；其他会话只读，或把变更请求发给控制塔登记。
- 新会话启动第一句：先读本索引，确认自己的代号、上游、下游，再开工。
- **路由投送 / 合并**：拆分时先查本索引现有会话职能；若待拆内容已归属某现有会话，则**追加续接交接、不新建会话代码**，并在该会话行「备注/续接链」标注。避免功能重叠的孤儿会话。
- **就地拆分、就地归档**：某会话变重就在该会话内执行拆分指令；父会话/R0 已归档，不参与子会话的拆分。
- **依赖与状态一致性**：拆分/新建前用 `依赖图谱` 检查 DAG 无环；跨会话交付物走「两阶段提交」（生产方标 `已完成待验收` → 用户复核翻 `已验收` → 消费方才引用），禁止消费未 `已验收` 的交付物。详见 README 第十一节。
- **存量纳管（legacy）**：通过 `控制塔纳管` 接管的已有会话，类型标 `legacy`，代号用 `R0-1/R0-2…`；仅轻量登记「摘要 + 产物路径 + conversation_search 检索串」，**不强制立刻生成详细 handoff**——详细交接文档懒生成（仅在该会话要被归档/拆分时才产出）。详见 README 第十三节。

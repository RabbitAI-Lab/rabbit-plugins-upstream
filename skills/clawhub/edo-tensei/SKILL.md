# 秽土转生 · 多会话协同控制塔

> 一句话：把「一个越滚越大的会话」安全地分裂成多个聚焦子会话，或把一堆散落会话管成一张可追溯的地图，或把某段子树打包迁移到别的工作空间/设备。用户只需记住五个词：**转生、接管、导出、导入、设置**。

> ⚡ **零成本提速（强烈建议）**：本技能五个动词的底层机械步骤由 `scripts/` 下的 Python 脚本完成，**脚本本身极快**（配置/哈希约 0.2s、导出打包亚秒级）。你感知到的「慢」几乎全部来自 WorkBuddy 执行通道的**冷启动开销**（间歇 1s~2min），与脚本无关。想零成本加速：对「跑一下脚本即完成」的动词（导出/导入/设置/校验），**直接在你本地终端运行对应脚本**，跳过执行通道冷启动。常用直跑命令见 **第十一节**。

## 一、何时启用本技能
- 当前会话产物/上下文过多，想「瘦身」且希望按子任务分诊到不同会话；
- 工作空间已存在多个会话，想统一纳管、知道谁依赖谁、可随时追溯；
- 想把某段子树（单节点/子树/整塔）迁移到另一工作空间，或拷到另一台设备独立管理；
- 想改技能默认配置（如默认导出目录）。
- 不用于：纯单次任务、单主题会话（直接做即可，不必建塔）。

## 二、五个必须先懂的约定
1. **状态在文件、不在会话**：唯一事实源是 `<workspace>/.workbuddy/control-tower/INDEX.md`，任何会话（含已归档）读它即拥有全地图。
2. **就地拆分、就地归档**：哪个会话变重，就在哪个会话里 `转生`；父会话/R0 已归档不参与子会话拆分。
3. **拆前先路由**：待拆内容若命中 INDEX 现有会话职能，则合并投送（追加续接交接）、不新建；无命中才新建。
4. **接管非破坏性**：已有 INDEX 就增量登记/刷新，绝不删除既有节点行、依赖边、代号；重跑 接管 先二次确认再非破坏补足（见第三节）。
5. **归档先看平台、再看台账**：优先用平台原生归档按钮；平台**没有**归档入口的会话，经用户明确授权后记 `已归档（标记）`（效力等同，但须写明平台侧实际状态）。对账时以本地台账 `~/.workbuddy/workbuddy.db` → `sessions` 表为权威（真实标题/状态/conv id/project_id），INDEX 与它对齐，不必走专门指令。

## 三、五个动词（用户唯一入口）
（详述见 references/控制塔机制.md 第八、十三、十四节）

### 转生 (rebirth) — 同空间拆分
在「变重的那个会话」里唤起。流程：
1. **前置断言**：若无 INDEX → 自动单会话接管（建塔、当前会话定 R0）再拆；若 INDEX 存在但本会话未登记 → 先轻量登记再拆。**绝不要求用户先手动接管**。
2. 扫描子任务自然分界，产出「拆分计划草案」：推荐 N 个候选子会话，各带「建议主题名 + 技能分配的建议代号(R0-A…) + 建议依赖边 + 是否命中现有会话(命中标『将并入 X』)」。
3. **草案经用户确认/改写后才写盘**（可重命名、增删候选、指定只拆某块、或把某候选改并入现有会话）。尊重用户自定义节点。
4. 确认后一次性自动：① 依赖检查(破死锁) ② 路由检查(命中合并、不新建) ③ 生成交接文档 + 启动包(各带目标节点标识、落盘 handoffs/) ④ 更新 INDEX(血缘+审计) ⑤ 自动对账(含归档同步)。
- **个数逻辑**：候选数 = 检测到的独立子任务数；仅 1 个主题则退化为「单会话瘦身」(出 1 个后继)，不硬拆。
   - **信息密度（随 `context_depth` 开关）**：交接文档内联详略由全局开关 `context_depth` 决定——`minimal` 仅留会话地图指针 + 关键决策；`standard`（默认）含完整叙述（现状/决策/下一步）；`full` 额外内嵌关键上下文块（决策理由、依赖分析、风险坑位、重要产物摘要）。重活前用「`设置 context_depth=…`」即可切换。
   - **产物不复制（动词感知基线）**：转生发生在同一工作空间，产物文件本就在共享目录内，交接文档以「路径引用」指向即可，**绝不复制产物副本**。复制是「导出」的职责（因跨空间才需自包含）。即：**同空间=瘦（链）、跨空间=自包含（复制）**。
- **命名逻辑**：主题名由技能据上下文拟、用户可在确认时改；代号由技能在中央仲裁下分配并立即写 INDEX，用户不发明代号（避免撞码）。最终「名字=用户确认的主题名，代号=技能分配」，二者都记进 INDEX。

### 接管 (onboard) — 同空间纳管
针对已有多个会话的工作空间做存量接管。只需新开一个控制塔会话 D，在 D 里调用 `接管`：
1. **发现**：**先读本地权威台账** `~/.workbuddy/workbuddy.db` 的 `sessions` 表（真实标题 / 状态 / conv id / project_id；只读打开，见 references/控制塔机制.md 第十三节「前置步骤」）；**再用** `conversation_search(项目关键词)` 从服务端历史补内容摘要（⚠️ **不可用召回条数推断会话个数**——同一会话的不同话题会各生成一条摘要）。请用户确认/补充，**按 conv id** 去重得「待接管清单」。
2. **建塔+轻量登记**：当前 workspace 生成 `INDEX.md`（根 R0）；每个已存在会话登记一行，代号 `R0-1/R0-2…`，类型 `legacy`；状态按枚举估填；不强制立刻生成详细 handoff（懒生成）。**若 `context_depth=full`，各 handoff 额外自动从当前会话上下文抽取外部链接，填入「外部引用（远程链接）」小节（腾讯文档/资料库/其他远程），无需用户手动提供**；`standard`/`minimal` 不生成该小节（见交接模板第 11 节）。
3. **关系推断**：基于主题/产物启发式建议依赖边，用户确认；内部跑依赖检查查环。
4. **完成即进入标准管理**（哪个变重就在哪拆、拆前先路由、跨会话交付走两阶段提交、定期对账）。
- 纳管不改旧会话运行状态：A/B/C 继续正常工作，仅补一层地图；进入终态时按需归档/拆分。口诀：「**建档不拆家，按需再处理**」。
- **重跑接管 = 非破坏性补足/刷新**：若本工作空间**已有控制塔**（INDEX 已存在），再次下达 `接管` 的意图是「基于现有塔补全/刷新」，而非从零建塔。执行前须**二次确认**：提示「本工作空间已有控制塔（N 个节点）。再次接管将非破坏性补足：保留全部现有节点行、依赖边、代号；仅补充新发现的会话/外部链接、按当前更完整的上下文刷新交接叙述。不会删除任何已有内容。是否继续？」——获用户明确授权后才动手。刷新时按当前 `context_depth` 重新生成各节点 handoff 叙述（full 时亦重新抽取外部引用），并登记新发现的会话；**绝不删除/覆盖既有 INDEX 行、依赖边、代号**。

### 导出 (export) — 跨空间/跨设备打包
把当前工作空间的某段管理结构（节点 + 其 handoff + 关联产物）打包成**自包含、可移植**的包。
1. **触发**：`导出 <代号/名称>`（如 `导出 R0-A2`）。
2. **选范围档**（默认子树）：
   - ① **单节点**：该节点 INDEX 行 + 其引用的 handoff
   - ② **子树（默认）**：该节点 + 全部后代，含内部依赖边；指向子树外的边标为「外部引用」
   - ③ **整塔**：全 INDEX + 全部 handoff
3. **包内容（自包含、复制不移动）**：
   - 选中的 INDEX 节点行 + 内部依赖边
   - 这些节点引用的本地 handoff 文档（复制进包）
   - **节点关联的产物文件副本**（复制本体进包，而非只留路径指针）——这是防污染的关键
     - **来源（合并去重）**：① INDEX 会话地图选中节点的「产物清单」列（机器可解析、分号分隔的路径，**主来源**，由 LLM 在导出前补全登记）；② `--artifacts` 显式追加；③ 从 handoff 文本启发式兜底。
     - **落位规则**：workspace 之内 → 保持相对目录结构 `artifacts/<相对路径>`；workspace 之外（跨盘/跨目录）→ `artifacts/_external/<盘符>/<原路径>`，**杜绝跨盘 `relpath` 崩溃与 `..` 逃逸**，导入端可原样还原。
     - **技能自身文件不迁移**：凡落在 `.workbuddy/skills/` 或 `.workbuddy/plugins/` 下的文件（技能靠「安装」获取，不靠迁移）一律自动跳过并提示，不会误带进包。
   - **内嵌 `PROVENANCE.json`**：`skill_id` / `skill_version`（由哪个工具/哪版产出，用于兼容排障，**不含人类作者名**）、`exported_by`（当前导出者）、`source_workspace` / `source_node`、`exported_at`、`package_content_hash`（包内容哈希，防篡改）、`scope`
   - 不含对话正文；平台侧未落盘为文件的会话产物 → 仅在 handoff 留摘要+来源会话 ID，目标端用 `conversation_search` 按需回捞，不进包本体
   - **信息密度（随 `context_depth` 开关）**：`minimal`/`standard` 仅打包 INDEX 片段 + handoff + 产物副本（默认行为）；`full` 额外在包内生成 `CONTEXT_DIGEST.md`（浓缩关键决策/依赖/风险，目标端开箱即用，无需回捞原会话）。**无论何种深度，导出始终复制产物副本**（自包含防污染铁律），深度只影响「额外上下文」多少。
4. **落盘目录（三级优先级，从高到低）**：
   - ① 当场显式指定（如「导出到 `D:\xxx`」）
   - ② 用户个人配置 `export_dir`（由 `设置` 指令写入，**落在用户主目录 `~/.edo-tensei/config.yaml`，绝不进入技能包**；出厂 `config.yaml` 仅含默认说明、不含任何个人路径）
   - ③ 零配置默认 `<用户主目录>/.edo-tensei/exports/`
   - 产出 zip，回显绝对路径。
5. **语义：复制不移动**——A 原节点保留，包是副本，绝不因导出误删 A 的管理结构。

### 导入 (import) — 跨空间/跨设备落成
把导出包在目标端落成独立子树。
1. **触发**：
   - `导入`（无参）→ 扫默认 export_dir，列出可导入包让你选（**同设备**便捷路径）
   - `导入 <路径>` → 指定包文件导入（**跨设备 / 显式**路径，如你已把包拷到新机器）
   - `导入 <路径> --namespace 前缀` → 自定义命名空间前缀
2. **一步执行（推荐，切勿手动解包）**：直接运行内部 `import_package.py` 一步完成「扫描→哈希校验→命名空间落盘→登记 INDEX→回读对账」：
   ```
   python import_package.py --package <包路径> --workspace <目标工作空间根>
   ```
   脚本会自动：① 读 `PROVENANCE.files` 做**逐文件哈希校验**（包内含清单，无需你猜复合哈希算法）；② 按命名空间落盘（handoff → `control-tower/handoffs/<前缀>_…`；产物 → `<前缀>/artifacts/…`，绝不指向 A 原路径）；③ 在 INDEX 追加 `B-` 前缀子树区块 + 会话地图 / 依赖边；④ 回读字节数对账。手动解包既易漏哈希校验、又易与下方落盘布局脱节，故统一走脚本。
3. **落盘规则（杜绝污染的核心）**：包内产物副本落到目标工作空间的**命名空间子目录**（如 `B-R0-A2/artifacts/...`），**绝不直接覆盖、也绝不指向 A 的原路径**；B 新会话只读写自己的副本 → A 原文件零触碰。
4. **落点**：
   - B 已有控制塔 → 带命名空间前缀隔离子树（如 `B-R0-A2…`），不动 B 原有节点
   - B 是新的 → 建塔并落成全新子树
   - 导入后 A 与 B 子树**无实时关联**，各自独立演进（与「复制不移动」一致）
5. **机制如何加载（关键）**：导入包只携带「**项目上下文**」（handoff + INDEX 片段 + 产物副本），**不携带技能源码**（设计要求：技能靠「安装」获取，不靠迁移）。新会话要执行 `转生/接管/导出` 等动词时，**重新 `@skill:edo-tensei` 调用**即可从本机已安装技能载入机制——包与技能职责分离、互不进对方。因此包虽不含 SKILL.md，新会话照样能跑转生等动词。

### 设置 (config) — 配置技能
查看/修改技能配置，免去手工改文件。**个人配置存于用户主目录 `~/.edo-tensei/config.yaml`，与技能包分离——技能包只带出厂默认 `config.yaml`（无个人路径），因此发布后任何平台（Windows/macOS/Linux/云端会话）都不会泄露你的本地目录，也不会因绝对路径错位而失效。**
1. **触发**：
   - `设置`（无参）→ 打印当前生效配置（含来源：出厂默认 / 用户配置）
   - `设置 export_dir <路径>` → 写入用户主目录配置并持久化；路径不存在则自动创建
   - `设置 export_dir reset` → 清除个人配置，退回零配置默认（`<用户主目录>/.edo-tensei/exports`，`~` 在任意平台自动解析）
2. 当前可配置项：
   - `export_dir`（默认导出目录）
   - `context_depth`（上下文深度，可选 `minimal` / `standard` / `full`，**默认 `standard`**）：控制「接管 / 转生 / 导出」时交接文档与导出包的内联信息量（含 `full` 时是否自动抽取「外部引用」）。随时可改，改完再执行动词即生效——
     - `minimal`：仅会话地图指针 + 关键决策，最快；
     - `standard`：指针 + 完整叙述（现状/决策/下一步，默认）；
     - `full`：叙述 + 内嵌关键上下文块（决策理由、依赖分析、风险坑位、重要产物摘要）；**导出时额外生成 `CONTEXT_DIGEST.md`** 供目标端开箱即用。
     - 改法示例：`设置 context_depth=full` / `设置 context_depth=minimal`。
3. **首次导出未配置时**：技能会提示你选择输出目录，默认即 `<用户主目录>/.edo-tensei/exports`；可当场用 `设置` 固化，或仅本次用 `导出 <节点> --out <路径>` 指定。云端会话用户无需给出绝对路径，走默认即可。

## 四、内部原语与两层映射（权限隔离）
- **用户指令层（唯一可输入）**：`转生` / `接管` / `导出` / `导入` / `设置`（别名 `rebirth` / `onboard` / `export` / `import` / `config`）。
- **技能原语层（内部能力，用户不可直调）**：build_tower / analyze / plan / dep_check / route_check / gen_handoff / gen_bootstrap / update_index / reconcile / discover / register_legacy / infer_dag / export_package / import_package / set_config / get_config。
- **映射（随本文件维护）**：
  - `转生` = build_tower → analyze → plan → dep_check → route_check → gen_handoff → gen_bootstrap → update_index → reconcile
  - `接管` = discover → build_tower → register_legacy → infer_dag → dep_check → reconcile
  - `导出` = read_index → select_scope → collect_handoffs → **collect_artifacts** → **write_provenance** → export_package（落默认目录，回显路径）
  - `导入` = scan_or_read_package → build_tower(若需) → **land_namespaced** → register_subtree → update_index → reconcile
  - `设置` = get_config / set_config
- `export_package` 内部：collect_artifacts（复制节点关联产物副本进包）、write_provenance（写 PROVENANCE.json）；`import_package` 内部：land_namespaced（产物落命名空间子目录，禁止原路径直读/直写）。
- **权限隔离**：
  1. 触发词表只暴露用户指令层，不把原语名注册为可触发命令；
  2. 用户输入原语名（误输）→ 提示「请用 转生 / 接管 / 导出 / 导入 / 设置」并忽略，绝不越权写 INDEX；
  3. 原语仅由技能在跑上述动词时按序内部调用，用户无法插入/跳步；
  4. 增删原语只改映射与内部实现，用户指令面不变。

## 五、控制塔存储与 INDEX
- **默认**：`CT_DIR = <workspace>/.workbuddy/control-tower/`，含 `INDEX.md`（会话地图+代号血缘+拆分/归档审计+依赖DAG+状态机+SHARED约定，唯一事实源）与 `handoffs/会话交接_YYYYMMDD_N_主题.md`（各卫星交接文档）。随工作空间走，可提交/分享，换机器不丢。
- **新用户零配置**：`CT_DIR` 默认即自包含可用，无需指定任何目录。导出中转目录默认即「用户主目录/.edo-tensei/exports」，或用户当场指定 / 用 `设置` 改。
- **新会话带入上下文两条路（均不依赖外部目录）**：① 读工作空间内 `INDEX.md` + 自己的 handoff（本地文件，新会话立即可见）；② 用原生 `conversation_search(query)` 从服务端历史捞回已归档父会话深层内容。
- **创建新会话是用户动作**（无程序化建会话工具）：技能只负责「预备交接文档 + 在 INDEX 登记」；新会话首条启动提示词负责「读取 INDEX + 交接文档，必要时 conversation_search 父会话」。

## 六、关键规则清单（防错，写盘前逐项核对）
- [ ] 唯一事实源只有 INDEX.md；任何会话拆分/归档/合并都先读它、后写它。
- [ ] 就地拆分就地归档；父/R0 只持有「拆分前的完整实时上下文」，子会话的新内容只在子会话里拆。
- [ ] 拆前跑路由检查：命中现有职能 → 合并投送（追加续接交接、不新建）；否则新建（代号=当前代号+新序号）。
- [ ] 依赖 DAG 拓扑排序无环（死锁→抽公共子会话 R0-E 破环）；两阶段提交：生产方标 `已完成待验收` → 用户复核翻 `已验收` → 消费方才引用（禁止消费未 `已验收` 的交付物）。
- [ ] 状态机枚举：待启动/进行中/已完成待验收/已验收/阻塞(等待X)/已归档；`已验收` 才是可消费态；`阻塞(等待X)` 是一等状态（X=上游代号）。
- [ ] 就绪队列（runnable queue）：上游全 `已验收` 且自身 `待启动/阻塞` → 进可启动队列，输出看板。
- [ ] 对账（reconcile）：每次转生/接管/导入后局部对账；会话启动检测到 INDEX 与平台可能脱节时，问「要跑一次全量对账吗？」回车即跑、不回车跳过。
- [ ] **导出防污染铁律**：导出必复制产物副本进包；导入必落命名空间子目录；禁止跨空间按原路径直读/直写。

## 七、跨工作空间 / 跨设备导出导入（核心机制）
- **专用动词、零歧义**：`导出`=出、`导入`=入，各管一件事，不再复用 `转生`/`接管` 的限定词。高频的「同空间拆分」永远走 `转生` 裸词，绝不会误触发跨空间。
- **包自包含**：INDEX 片段 + handoff 副本 + **产物文件副本** + PROVENANCE，不依赖原设备或原账号。因此**同设备跨工作空间、跨设备**都能走（唯一前提是包文件物理到达目标端）。
- **场景一（B 已有自己的控制塔）**：`导出 <节点>` → `导入`（扫到包）→ 以**命名空间前缀隔离子树**（如 `B-R0-A2…`），不动 B 原有节点。
- **场景二（B 是新的，从 A 抽细分独立管理）**：`导出 <节点>` 拷到 B 设备 → 在 B `导入 <路径>` 生成全新独立子树；导入后 A 节点与 B 子树无实时关联，各自独立发展（纯 fork）。
- **默认导出目录三级优先级**：显式指定（`--out`） > 用户个人配置 `export_dir`（~/.edo-tensei/config.yaml） > 出厂默认 `<用户主目录>/.edo-tensei/exports`。出厂不写死任何路径；个人目录由 `设置` 在你本机落成，不随技能包发布。
- **跨设备不需要实时同步**：状态随文件走、接管可重建；残留云盘双端陈旧 INDEX 由 reconcile 兜底（G3 决议）。

## 八、扩展埋点 EXT-1~5（能力检测而非硬编码）
- **EXT-1 自动建会话**：检测到「创建会话+注入首条消息」工具时，`gen_bootstrap` 由「输出文本」升级为「直接建并注入」。
- **EXT-2 生命周期事件**：平台暴露归档/删除钩子时，归档同步由手动 reconcile 升级为事件自动触发。
- **EXT-3 平台状态 API**：提供会话状态/末次修改查询时，漂移检测由手动升级为近实时。
- **EXT-4 跨工作空间 / 跨设备导出导入**（见第三、七节）：由专用 `导出`/`导入` 动词承载，包自包含、可移植。
- **EXT-5 多空间聚合**：未来在 hub 层加「根索引」跨空间聚总览（当前单空间已自洽，留接口不实现）。
- **原则**：只在平台能力存在时升级体验，绝不因平台没能力而报错；所有自动流程保留「降级到人工」退路。

## 九、权属溯源 SEAL（发布/维权用）
- 技能自带 `scripts/gen_seal.py`：遍历包内所有文件算 SHA-256，生成 `provenance/SEAL.json`（含 skill_id、package_sha256、seal_hash、watermark_token）。本戳记为内容指纹、**非加密**，不限制技能使用。
- 固化/发布前运行：`python scripts/gen_seal.py <技能包目录> --version 1.0.2`（建议在本地发布机运行，并另行申请 RFC3161 TSA 可信时间戳 `.tsr` 一并备份）。
- **维权对照**：他人整包抄→比对 `skill_id`/`package_sha256` 同源；改头换面→逐文件哈希变化即暴露；商用→`LICENSE`「商业集成使用前须联系权利人获得授权」+ 作者声明（晋锡斌，见 LICENSE 与 provenance/SEAL.json 的 author_declared）+ TSA 时间戳构成完整权属链。
- **作者署名策略**：展示页/发布页/技能简介仅显示 manifest 的 `author`（邮箱），真实姓名「晋锡斌」只写入随包 `LICENSE` 内部与 SEAL，需下载打开包才可见。完整「软著与创意保护说明」及「独立创作与差异化分析」仅备份于作者腾讯文档，争议时调出。
- **导出包的 PROVENANCE（区别于 SEAL）**：SEAL 证明技能本身的代码与作者；导出包内嵌的 `PROVENANCE.json` 只记录「这次导出事件」的溯源（由哪个技能/哪版产出、谁导出、来源、时间、包哈希），**不含技能作者名**——导出包是用户项目数据，不是技能衍生品。

## 十一、零成本提速（用户侧·强烈建议）

**瓶颈定位**：五个动词的底层机械步骤（导出 / 导入 / 设置 / 校验 / 生成 SEAL）都由 `scripts/` 下 Python 脚本完成，**脚本本身极快**——配置读取与哈希约 0.2s、导出打包亚秒级、导入哈希校验亚秒级。你感知到的「慢」（尤其首次执行等 1~2 分钟）几乎全部来自 WorkBuddy **执行通道的冷启动开销**，与脚本/环境无关。

**零成本加速（不改任何代码）**：对「跑一下脚本即完成」的动词——**导出 / 导入 / 设置 / 校验**——可在你**本地终端**直接运行对应脚本，完全跳过执行通道冷启动。前提：本机已装 Python 3（3.8+ 即可）。命令与 SKILL.md 动词行为**完全一致**（同一套脚本），直跑只是换了「谁去敲命令」。

```bash
# 设置：查看 / 修改配置（替代「设置」动词的执行等待）
python ~/.workbuddy/skills/edo-tensei/scripts/config.py list
python ~/.workbuddy/skills/edo-tensei/scripts/config.py set context_depth standard
python ~/.workbuddy/skills/edo-tensei/scripts/config.py set export_dir D:/edo-exports

# 导出：节点 R0-A2 的子树（替代「导出」动词的执行等待）
python ~/.workbuddy/skills/edo-tensei/scripts/export_package.py \
    --nodes R0-A2 --scope subtree --workspace <工作空间根> [--out <导出目录>] [--artifacts "路径1,路径2"]

# 导入：指定包落成（替代「导入」动词的执行等待）
python ~/.workbuddy/skills/edo-tensei/scripts/import_package.py \
    --package <包路径> --workspace <目标工作空间根>

# 固化/发布前重刷指纹（版本号与 manifest.yaml 保持一致，当前 1.0.2）
python ~/.workbuddy/skills/edo-tensei/scripts/gen_seal.py \
    <技能包目录> --version 1.0.2
```

> 说明：`转生` / `接管` 因含多步推理、依赖分析与写盘，仍建议在 AI 会话里唤起；其余单步脚本操作直跑最划算。导出默认已带 `--verify` 自校验（逐文件哈希比对、打印 PASS/FAIL），一般无需单独跑校验脚本。

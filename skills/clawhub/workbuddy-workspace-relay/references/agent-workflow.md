# Agent 工作流

本文件是 WorkBuddy 项目续接的执行规则。`SKILL.md` 的前半部分是用户可读产品概览；触发 Skill 后读取本文件，再执行具体操作。

## 强制入口

每次触发时只先问一个问题，不根据文件是否存在自动猜测模式：

> 你现在要进行哪种操作？
>
> 1. 打包当前工作现场
> 2. 恢复已有工作现场

用户选择后，不再询问打包范围、排除项、项目状态或是否开始。密码由本地遮罩输入窗口获取；不得要求用户把密码发送到 WorkBuddy 对话中。

## 打包当前工作现场

1. 使用 WorkBuddy 当前任务已授权的工作区作为 `--workspace`。不要扫描用户主目录或自行寻找其他项目。
2. 从当前对话、任务上下文和工作区规则中整理 `HANDOFF.md`，至少包含：项目目标、当前阶段、最近完成、已确认决策、已否决方向及原因、当前约束、当前阻塞、关键文件及作用、下一步动作。将它写入工作区根目录，使源端也保留交接记录。
3. 调用确定性脚本完成扫描、排除、复制、哈希、归档和加密：

   ```bash
   python3 scripts/relay.py pack \
     --workspace "<当前 WorkBuddy 工作区>" \
     --output-dir "<用户桌面或当前授权的工作区外目录>" \
     --handoff-file "<当前 WorkBuddy 工作区>/HANDOFF.md" \
     --json
   ```

4. 让脚本弹出本地遮罩密码窗口并输入两次密码；Windows 使用 age 的本地控制台密码提示。不要传入 `--password-stdin`，除非正在运行自动化测试。
5. 只把脚本返回的 `.wbpack` 文件交付给用户；不要展示文件清单、manifest 内容、密码或工作区绝对路径。

默认保留源代码、文档、素材、数据库、`.git`、Agent 配置、项目内 Skill、项目规则、未提交修改和项目内 `.env` 文件。系统钥匙串、浏览器 Cookie、全局环境变量和 WorkBuddy 账号不在扫描范围内。

## 恢复已有工作现场

1. 用户选择恢复后，提示：`请提供 .wbpack 工作包。` 仅等待用户提供文件。
2. 收到文件后直接调用：

   ```bash
   python3 scripts/relay.py restore \
     "<用户提供的 .wbpack 路径>" \
     --destination-root "<当前 WorkBuddy 工作区>" \
     --json
   ```

3. 让脚本弹出本地遮罩密码窗口；Windows 使用 age 的本地控制台密码提示。不要在聊天中索要、复述或记录密码。
4. 脚本会在写入项目文件前验证 age 解密、归档路径、文件类型、manifest、文件数量、文件大小和 SHA-256。错误密码、损坏包或路径攻击必须在释放任何项目文件前停止。
5. 当前目标工作区为空时恢复到根目录；已有内容时创建 `<项目名>-已恢复`，同名时递增编号。禁止覆盖既有文件或目录。
6. 恢复成功后，先读取 `<恢复目录>/.workbuddy-relay/HANDOFF.md`，再读取项目规则和关键文件。说明项目目标、当前阶段、阻塞和下一步，并继续当前任务；不要自动执行恢复后的脚本、安装依赖或切换 WorkBuddy 当前工作区。

## 安全边界

- 只接受 `age` 或兼容 age 格式的本地组件；不得降级到 ZipCrypto、普通 ZIP 密码或未认证的自制加密。
- 密码不得进入聊天记录、命令行参数、环境变量、日志或临时明文文件。
- 归档内只允许普通文件和目录；拒绝绝对路径、`..` 路径、反斜杠路径、符号链接、硬链接、设备文件和重复成员。
- 解密和完整性检查全部在临时目录中完成，验证通过后才写入目标目录。
- 迁移包包含项目内敏感配置；用户必须把 `.wbpack` 当作机密文件自行安全传输和保存。
- 脚本只恢复文件，不自动执行项目脚本，不触碰系统凭证存储。
- 不把缺少的信息补成事实；若 HANDOFF 只有机器生成的回退内容，明确标注其不完整并先读取项目材料。

## 失败处理

遇到以下情况时停止并给出一个具体原因，不让用户重复确认无关事项：当前工作区无法解析、age 不可用、密码错误、包损坏、manifest 不匹配、路径不安全、目标无法安全创建。不得以普通 ZIP 或明文目录作为降级结果。

若 WorkBuddy 未提供当前工作区路径、文件真实路径或本地密码窗口能力，标记为“当前环境尚无法验证”，保留脚本和包格式不变，不声称已完成 WorkBuddy 端到端验证。

# ایجنٹ ہو کر کام کرنے کا عمل اور اسکرپٹ معاہدہ — powpow-register

SKILL.md کے ہر مرحلے کی عملی تفصیل۔ تمام کمانڈز `node scripts/powpow-register.mjs <سب کمانڈ> [آرگیومنٹس]` فارمیٹ میں ہیں، اسکرپٹ **زیرو ڈپینڈنسی**، **Node ≥ 18** درکار، تمام درخواستیں صرف `https://global.powpow.online` پر جاتی ہیں۔

## سیکیورٹی ڈیزائن (ایسا کیوں ہے)

| ڈیزائن | وجہ |
|---|---|
| پاس ورڈ صرف ماحولیاتی متغیر `POWPOW_REGISTER_PASSWORD` سے داخل ہوتا ہے | پروسیس کے کمانڈ لائن آرگیومنٹس اسی مشین کے دوسرے پروسیسز کو نظر آ سکتے ہیں (argv لیک سیفیس)، ماحولیاتی متغیر اسکرپٹ پڑھتے ہی فوراً استعمال ہو جاتا ہے |
| پاس ورڈ **اسٹیٹ فائل میں کبھی نہیں لکھا جاتا**، لاگز میں بھی نہیں آتا | اسٹیٹ فائل ڈسک پر رہ سکتی ہے؛ گفتگو میں جنریٹ موڈ کا ایک بار دکھانا صارف کو محفوظ کروانے کے لیے ہے |
| اسٹیٹ فائل سسٹم کی عارضی ڈائریکٹری میں (`os.tmpdir()/powpow-register-state.json`, 0600) | اس میں صرف email / username / nickname / token / outTradeNo پانچ فیلڈز ہیں، `cleanup` ایک کمانڈ سے مٹ جاتی ہے |
| ایجنٹ کو ملنے والا JWT سرکاری `me?token=` اینڈپوائنٹ سے براؤزر cookie میں بدلتا ہے | پلیٹ فارم نے ہارمونی WebView کے لیے بنایا سرکاری برج ہے؛ تصدیق صرف سگنیچر + مدت دیکھتی ہے، ڈیوائس فنگر پرنٹ سے نہیں جڑتی، صارف کے براؤزر میں چلتا ہے |
| پیمنٹ میں صرف create-order / query / پیمنٹ پیج کھولنا | ادائیگی کا ایکشن اور پیمنٹ اسناد ہمیشہ صارف اور علی پے کے سرکاری پیمنٹ پیج کے درمیان رہتے ہیں، ایجنٹ کے ہاتھ سے نہیں گزرتے |

## کمانڈ رفرنس

| کمانڈ | اہم آرگیومنٹس | کام / وقت |
|---|---|---|
| `status` | —— | عمل کی پیش رفت دیکھنا (اسٹیٹ فائل پڑھنا)؛ گفتگو منقطع ہو تو پہلے یہی چلائیں |
| `gen-password` | —— | ۲۴ حروف کا مضبوط پاس ورڈ بنانا (بڑے+چھوٹے حروف+اعداد)، stdout پر **صرف اسی ایک بار** دکھاتا ہے |
| `prepare-suggest` | `--username --nickname --email` | تصدیق شدہ معلومات اسٹیٹ فائل میں محفوظ کرنا (بعد میں register میں دوبارہ دینے کی ضرورت نہیں) |
| `send-code` | `--email` | پلیٹ فارم سے ۶ ہندسوں کا تصدیقی کوڈ بھجواؤنا (۱۰ منٹ معتبر، 60s کول ڈاؤن) |
| `register` | `--code` (لازمی)؛ `--username --nickname --avatar --phone` (اختیاری، اسٹیٹ فائل میں ہوں تو دینے کی ضرورت نہیں) | pending اکاؤنٹ بنانا؛ پاس ورڈ `POWPOW_REGISTER_PASSWORD` ماحولیاتی متغیر سے؛ کامیابی پر JWT خود اسٹیٹ فائل میں محفوظ |
| `login-link` | `--target pending` یا `--target home` | ون کلک لاگ اِن لنک بنانا (ڈبل لنک ڈیزائن، نیچے دیکھیں) |
| `create-order` | `--package monthly\|quarterly\|yearly` | علی پے آرڈر بنانا؛ پیمنٹ پیج فائل کا پاتھ + outTradeNo لوٹاتا ہے (خود اسٹیٹ فائل میں لکھا جاتا ہے) |
| `query` | —— | آرڈر کی حالت `paid / pending / closed / unknown` چیک کرنا (outTradeNo اسٹیٹ فائل سے)، ۱۰ تا ۱۵ سیکنڈ پولنگ |
| `refresh-login` | پاس ورڈ ماحولیاتی متغیر سے | دوبارہ لاگ اِن کر کے **نیا JWT** لینا (سبسکرپشن کلیم NONE سے ACTIVE)، ادائیگی موصول ہونے کے بعد لازمی |
| `whoami` | —— | اسٹیٹ فائل کے token سے اکاؤنٹ اور سبسکرپشن حالت چیک کرنا (ایکٹیویشن اثر کر گئی یا نہیں) |
| `cleanup` | —— | اسٹیٹ فائل ڈیلیٹ کرنا (اختتام پر لازمی) |

**ماحولیاتی متغیر سے دینا** (پاس ورڈ کبھی کمانڈ لائن پر نہیں):

```bash
# bash / zsh / WSL
POWPOW_REGISTER_PASSWORD='<پاس ورڈ>' node scripts/powpow-register.mjs register --code 123456
# PowerShell
$env:POWPOW_REGISTER_PASSWORD = '<پاس ورڈ>'; node scripts/powpow-register.mjs register --code 123456
# cmd
set POWPOW_REGISTER_PASSWORD=<پاس ورڈ> && node scripts/powpow-register.mjs register --code 123456
```

## ڈبل لنک میکانزم (بنیادی ڈیزائن)

پلیٹ فارم کا لاگ اِن اسٹیٹ HttpOnly cookie ہے، ایجنٹ براہ راست براؤزر میں cookie نہیں لگا سکتا؛ پل سرکاری
`/api/auth/me?token=<JWT>&redirect=<سائٹ کے اندر کا پاتھ>` اینڈپوائنٹ ہے: تصدیق → pending صارف کا سیشن خود بن جانا →
`Set-Cookie: powpow_token` (HttpOnly / SameSite=Lax / ۷ دن) → redirect کی جانچ (صرف ایک سلیش سے شروع، `//` اور بیک سلیش منع،
پارس کے بعد اصلہ origin لازم) → 307 عارضی ری ڈائریکٹ ہدف پیج پر۔

- **لنک ۱ (رجسٹریشن کامیاب ہوتے ہی فوراً دیں)**: `--target pending` → `/subscription` پر اترے گا۔
  صارف کا براؤزر "ہاف لاگ اِن" حالت میں داخل ہوتا ہے: سبسکرپشن پیج، علی پے ریٹرن پیج نظر آتے اور کام کرتے ہیں؛ کنٹینٹ پیج اب بھی پے وال سے
  سبسکرپشن پیج پر لوٹا دیا جاتا ہے (تین تہوں کی حفاظت: JWT claims گیٹ وے چیک → DB دوبارہ چیک → کور API چیک، یہی معمول کا رویہ ہے)۔
- **لنک ۲ (paid کی تصدیق پر دیں)**: پہلے `refresh-login` سے نیا JWT لیں (پیمنٹ صرف DB اپ ڈیٹ کرتی ہے، پہلے جاری شدہ JWT کے
  claims نہیں بدلتی، نئے نہ لیں تو "ادائیگی کے باوجود رکنیت نہیں" دکھے گا)، پھر `--target home` → ہوم پیج پر اترے گا،
  مکمل رکنیت کی حالت۔

## مکمل ترتیب (عمومی راستہ)

```
1.  status                          # ماحول سیلف چیک
2.  (مرحلہ ۲ میں گفتگو سے معلومات کی تصدیق، پاس ورڈ دو میں سے ایک؛ جنریٹ موڈ: gen-password → صارف سے فوراً محفوظ کروانا)
3.  prepare-suggest --username U --nickname N --email E
4.  send-code --email E             # → صارف ای میل میں کوڈ دیکھے گا (گفتگو سے باہر کا واحد حصہ ①)
5.  POWPOW_REGISTER_PASSWORD=*** register --code 123456 [--avatar pic.jpg]
6.  login-link --target pending     # → لنک ۱ صارف کو بھیجا
7.  (صارف پیکج چنے) create-order --package monthly
8.  start <پیمنٹ پیج فائل>           # Windows؛ macOS پر open، Linux پر xdg-open
    # → صارف علی پے کے پیمنٹ پیج پر ادائیگی کرے گا (گفتگو سے باہر کا حصہ ②)
9.  query (ہر ۱۰ تا ۱۵ سیکنڈ) paid تک
10. refresh-login                   # ACTIVE کلیم والا نیا JWT
11. login-link --target home        # → لنک ۲ صارف کو بھیجا
12. whoami                          # subscriptionStatus: ACTIVE کی تصدیق (اختیاری)
13. cleanup                         # اسٹیٹ فائل کی صفائی
```

## کمانڈ → پلیٹ فارم API نقشہ

| اسکرپٹ کمانڈ | پلیٹ فارم اینڈپوائنٹ |
|---|---|
| `send-code` | `POST /api/auth/register/send-code` |
| `register` | `POST /api/auth/register` (multipart، پروفائل تصویر براہ راست اپلوڈ) |
| `login-link` | `GET /api/auth/me?token=…&redirect=…` (لنک خود؛ براؤزر میں کلک ہونے پر اثر کرتا ہے) |
| `create-order` | `POST /api/payment/alipay/create-order` (Bearer) |
| `query` | `GET /api/payment/alipay/query?outTradeNo=…` (Bearer) |
| `refresh-login` | `POST /api/auth/login` (`{step:1, username, password}`) |
| `whoami` | `GET /api/auth/me?token=…` |

قواعد کا ماخذ: رجسٹریشن فیلڈز اور حد بندی `registration-flow.md` میں؛ پیکج اور ایکٹیویشن چین
`payment-and-activation.md` میں (دونوں میں پلیٹ فارم سورس فائل کا حوالہ ہے)۔

## اسکرپٹ لیول پر خرابی کا حل

| علامت | کیا کریں |
|---|---|
| `Node 版本过低` (Node ورژن بہت پرانا) | خالص رہنمائی موڈ میں واپس جائیں، زبردستی نہ آزمائیں |
| نیٹ ورک خرابی / ٹائم آؤٹ | ایک بار دوبارہ کوشش کریں؛ پھر بھی ناکام ہو تو صارف سے نیٹ ورک ٹھیک کروا کر آگے بڑھیں (اسٹیٹ فائل موجود ہے، شروع سے `status` چلائیں تو بازیاب ہو جاتا ہے) |
| register پر کاروباری خرابی (用户名已存在 وغیرہ) | SKILL.md مرحلہ ۵ کی ٹیبل کے مطابق حل کریں، **تصدیقی کوڈ دوبارہ بھیجنے کی ضرورت نہیں** (۱۰ منٹ کے اندر ابھی بھی معتبر ہے) |
| register پر「邮箱验证码错误或已过期」 (ای میل تصدیقی کوڈ غلط یا میعاد ختم) | ٹائم آؤٹ → دوبارہ `send-code` |
| `create-order` کے بعد صارف نے پیمنٹ پیج بند کر دیا | سیدھا دوبارہ `create-order` (پرانا آرڈر 2h میں خود بند) |
| `query` لگاتار pending | صارف نے شاید ادائیگی نہیں کی؛ ایک بار پوچھ لیں۔ واقعی کی ہو → payment-and-activation.md کی ٹربل شوٹنگ ٹیبل کے مطابق چلیں |
| `refresh-login` 403 `pending_payment` | ادائیگی ابھی موصول نہیں ہوئی، مرحلہ ۹ پر واپس جا کر پولنگ جاری رکھیں |
| اسٹیٹ فائل ضلع (غلطی سے ڈیلیٹ / مشین بدلی) | `whoami`/`refresh-login` نہیں چل سکتے؛ صارف سے کہیں جس براؤزر میں لنک ۱ کھولا تھا وہاں سبسکرپشن پیج ریفریش کر کے حالت دیکھ لے، یا دوبارہ لاگ اِن (ویب موڈ) |

## فالتو موڈ (خالص رہنمائی)

نیچے کی کسی ایک صورت میں فوراً v1 طرز کی خالص رہنمائی پر واپس جائیں، اسکرپٹ سے مزید نہ جھنجھٹیں:

- Node ≥ 18 نہ ہو یا اسکرپٹ لگاتار دو بار ایک جیسی ناکامی دے؛
- صارف صاف کہے "میں خود ویب پر کرتا ہوں"؛
- کمپنی/ڈیوائس پالیسی اسکرپٹ کے نیٹ ورک روکتی ہو۔

واپس جانے کے بعد: رجسٹریشن پیج https://global.powpow.online/register اور سبسکرپشن پیج
https://global.powpow.online/subscription دیں، `registration-flow.md` کے قواعد کے مطابق ساتھ چلیں،
لہجہ ویسا ہی رہے گا، ہر راؤنڈ پھر بھی "اگلا قدم" بلاک پر ختم ہوگا۔

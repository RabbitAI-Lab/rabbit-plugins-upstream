# ایجنٹ ہو کر کام کرنے کا عمل اور اسکرپٹ معاہدہ — powpow-register

SKILL.md کے ہر مرحلے کی عملی تفصیل۔ تمام کمانڈز `node scripts/powpow-register.mjs <سب کمانڈ> [آرگیومنٹس]` فارمیٹ میں ہیں، اسکرپٹ **زیرو ڈپینڈنسی**، **Node ≥ 18** درکار، تمام درخواستیں صرف `https://global.powpow.online` پر جاتی ہیں۔

## سیکیورٹی ڈیزائن (ایسا کیوں ہے)

| ڈیزائن | وجہ |
|---|---|
| پاس ورڈ صرف ماحولیاتی متغیر `POWPOW_REGISTER_PASSWORD` سے داخل ہوتا ہے | پروسیس کے کمانڈ لائن آرگیومنٹس اسی مشین کے دوسرے پروسیسز کو نظر آ سکتے ہیں (argv لیک سیفیس)، ماحولیاتی متغیر اسکرپٹ پڑھتے ہی فوراً استعمال ہو جاتا ہے |
| پاس ورڈ **اسٹیٹ فائل میں کبھی نہیں لکھا جاتا**، لاگز میں بھی نہیں آتا | اسٹیٹ فائل ڈسک پر رہ سکتی ہے؛ گفتگو میں جنریٹ موڈ کا ایک بار دکھانا صارف کو محفوظ کروانے کے لیے ہے |
| اسٹیٹ فائل سسٹم کی عارضی ڈائریکٹری میں (`os.tmpdir()/powpow-register-state.json`, 0600) | اس میں صرف email / username / nickname / token / outTradeNo پانچ فیلڈز ہیں، `cleanup` ایک کمانڈ سے مٹ جاتی ہے |
| ایجنٹ کو ملنے والا JWT سرکاری `me?token=` اینڈپوائنٹ سے براؤزر cookie میں بدلتا ہے | پلیٹ فارم نے ہارمونی WebView کے لیے بنایا سرکاری برج ہے؛ تصدیق صرف سگنیچر + مدت دیکھتی ہے، ڈیوائس فنگر پرنٹ سے نہیں جڑتی، صارف کے براؤزر میں چلتا ہے |
| پیمنٹ میں صرف create-order / query / پیمنٹ پیج کھولنا | ادائیگی کا ایکشن اور پیمنٹ اسناد ہمیشہ صارف اور علی پے کے سرکاری پیمنٹ پیج کے درمیان رہتے ہیں، ایجنٹ کے ہاتھ سے نہیں گزرتے |

## کمانڈ رفرنس

| کمانڈ | اہم آرگیومنٹس | کام / وقت |
|---|---|---|
| `status` | —— | عمل کی پیش رفت دیکھنا (اسٹیٹ فائل پڑھنا)؛ گفتگو منقطع ہو تو پہلے یہی چلائیں |
| `gen-password` | —— | ۲۴ حروف کا مضبوط پاس ورڈ بنانا (بڑے+چھوٹے حروف+اعداد)، stdout پر **صرف اسی ایک بار** دکھاتا ہے |
| `prepare-suggest` | `--username --nickname --email` | تصدیق شدہ معلومات اسٹیٹ فائل میں محفوظ کرنا (بعد میں register میں دوبارہ دینے کی ضرورت نہیں) |
| `send-code` | `--email` | پلیٹ فارم سے ۶ ہندسوں کا تصدیقی کوڈ بھجواؤنا (۱۰ منٹ معتبر، 60s کول ڈاؤن) |
| `register` | `--code` (لازمی)؛ `--username --nickname --avatar --phone` (اختیاری، اسٹیٹ فائل میں ہوں تو دینے کی ضرورت نہیں) | pending اکاؤنٹ بنانا؛ پاس ورڈ `POWPOW_REGISTER_PASSWORD` ماحولیاتی متغیر سے؛ کامیابی پر JWT خود اسٹیٹ فائل میں محفوظ |
| `login-link` | `--target pending` یا `--target home` | ون کلک لاگ ان لنک بناتا ہے (دو لنک کا ڈیزائن، نیچے دیکھیں) |
| `create-order` | `--package monthly\|quarterly\|yearly` (ڈیفالٹ علی پے)<br>`--provider alipay\|paypal` | پیمنٹ آرڈر بنانا؛ علی پے پیمنٹ پیج فائل کا پاتھ + outTradeNo لوٹاتا ہے؛ PayPal منظوری صفحے کی فائل کا پاتھ + subscriptionId لوٹاتا ہے (خود اسٹیٹ فائل میں لکھا جاتا ہے) |
| `query` | —— | آرڈر/سبسکرپشن کی حالت چیک کرنا۔ علی پے: `paid / pending / closed / unknown`؛ PayPal: `ACTIVE / PENDING`؛ ۱۰ تا ۱۵ سیکنڈ پولنگ |
| `refresh-login` | پاس ورڈ ماحولیاتی متغیر سے | دوبارہ لاگ اِن کر کے **نیا JWT** لینا (سبسکرپشن کلیم NONE سے ACTIVE)، ادائیگی موصول ہونے کے بعد لازمی |
| `whoami` | —— | اسٹیٹ فائل کے token سے اکاؤنٹ اور سبسکرپشن حالت چیک کرنا (ایکٹیویشن اثر کر گئی یا نہیں) |
| `cleanup` | —— | اسٹیٹ فائل ڈیلیٹ کرنا (اختتام پر لازمی) |

**ماحولیاتی متغیر سے دینا** (پاس ورڈ کبھی کمانڈ لائن پر نہیں):

```bash
# bash / zsh / WSL
POWPOW_REGISTER_PASSWORD='<پاس ورڈ>' node scripts/powpow-register.mjs register --code 123456
# PowerShell
$env:POWPOW_REGISTER_PASSWORD = '<پاس ورڈ>'; node scripts/powpow-register.mjs register --code 123456
# cmd
set POWPOW_REGISTER_PASSWORD=<پاس ورڈ> && node scripts/powpow-register.mjs register --code 123456
```

## دو لنک کا طریقہ کار (بنیادی ڈیزائن)

پلیٹ فارم کی لاگ ان حالت ایک HttpOnly کوکی ہے، جسے ایجنٹ سیدھا براؤزر میں نہیں لگا سکتا؛ پل ہے سرکاری
`/api/auth/me?token=<JWT>&redirect=<سائٹ کے اندر پاتھ>` اینڈ پوائنٹ: دستخط کی تصدیق → خودکار طور پر سیشن
بنانا → `Set-Cookie: powpow_token` (HttpOnly / SameSite=Lax / 7 دن) → ری ڈائریکٹ کی توثیق
(اکللی سلیش سے شروع ہونا چاہیے، `//` اور بیک سلیش ممنوع، پارس کرنے کے بعد same-origin ہونا چاہیے) → ہدف پیج پر 307 عارضی ری ڈائریکٹ۔

لنک کے دو ہدف ہیں، **پہلے home بنائیں، پھر صارف کہاں اترا ہے اس کے مطابق فیصلہ کریں کہ pending سے گزرنا ہے یا نہیں**:

- **home لنک (بطور ڈیفالٹ بھیجا جاتا ہے، `--target home` → `/` پر اترتا ہے)**: کامیاب رجسٹریشن کے فوراً بعد بنا کر صارف کو بھیجا جاتا ہے۔
  مفت تجرباتی دور میں صارف سیدھا ہوم پیج پر جاتا ہے، سب کچھ قابل استعمال؛ **اگر لنک پر کلک کر کے سبسکرپشن پیج پر اتر جائے تو مفت تجرباتی دور ختم ہو گیا ہے** — ادائیگی کے بہاؤ پر سوئچ کریں (نیچے دیکھیں)؛ سکرپٹ تبدیل کرنے یا دوبارہ رجسٹریشن کی ضرورت نہیں۔
- **pending لنک (ادائیگی کے بہاؤ میں استعمال، `--target pending` → `/subscription` پر اترتا ہے)**:
  صارف کا براؤزر "ہاف لاگ ان" حالت میں داخل ہوتا ہے: سبسکرپشن پیج اور ادائیگی کے بعد کا واپسی پیج نظر آتے اور قابل استعمال ہیں۔ آمدنی کے بعد،
  ACTIVE کلیم والے نئے JWT میں تبدیلی کے لیے `refresh-login` چلائیں، پھر مکمل ممبرشپ حالت کے لیے home لنک ایک بار پھر بھیجیں۔

## مکمل ترتیب

### تیز راستہ (مفت تجرباتی دور میں — زیادہ تر معاملات)

```
1.  status                          # ماحول کا خودکارہ جائزہ
2.  (مرحلہ 2: معلومات کی تصدیق کے لیے بات چیت، پاس ورڈ من پسند؛ جنریشن موڈ: gen-password → صارف سے فوراً محفوظ کرنے کو کہیں)
3.  prepare-suggest --username U --nickname N --email E
4.  send-code --email E             # → صارف ان باکس میں کوڈ دیکھتا ہے (بات چیت سے نکالنے کی واحد بار)
5.  POWPOW_REGISTER_PASSWORD=*** register --code 123456 [--avatar pic.jpg]
6.  login-link --target home        # → لنک صارف کو بھیجیں؛ ایک کلک اور ہوم پیج پر
7.  (صارف تصدیق کرتا ہے کہ اندر آ گیا) → فوراً اختتام کریں: cleanup + اکاؤنٹ کارڈ + پہلے قدموں کی رہنمائی
```

### ادائیگی کا راستہ (جب صارف ممبرشپ چاہے، یا مفت تجرباتی دور ختم ہو گیا ہو)

```
1–5. تیز راستے کی طرح (register کامیاب ہونے کے بعد حالت میں ٹوکن پہلے سے ہے)
6.  login-link --target pending     # → ہاف لاگ ان لنک، ادائیگی کے بعد کا واپسی پیج کام کرتا رہتا ہے
7.  (صارف ادائیگی کا طریقہ منتخب کرتا ہے)
    # Alipay: create-order --package monthly|quarterly|yearly
    # PayPal: create-order --provider paypal
8.  start <ادائیگی پیج فائل>        # Windows؛ macOS پر open، Linux پر xdg-open
    # → صارف Alipay/PayPal کیشئر پر ادائیگی/اجازت مکمل کرتا ہے (بات چیت چھوڑتا ہے)
9.  query (ہر 10–15 سیکنڈ) paid / ACTIVE تک
10. refresh-login                   # ACTIVE کلیم والے نئے JWT میں تبدیلی
11. login-link --target home        # → صارف کو مکمل ممبرشپ والا لنک بھیجیں
12. whoami                          # subscriptionStatus: ACTIVE کی تصدیق کریں (اختیاری)
13. cleanup                         # حالت کی فائل صاف کریں
```
## کمانڈ → پلیٹ فارم API نقشہ

| اسکرپٹ کمانڈ | پلیٹ فارم اینڈپوائنٹ |
|---|---|
| `send-code` | `POST /api/auth/register/send-code` |
| `register` | `POST /api/auth/register` (multipart، پروفائل تصویر براہ راست اپلوڈ) |
| `login-link` | `GET /api/auth/me?token=…&redirect=…` (لنک خود؛ براؤزر میں کلک ہونے پر اثر کرتا ہے) |
| `create-order` | `POST /api/payment/alipay/create-order` (Bearer، علی پے)<br>`GET /api/subscription/plans` + `POST /api/subscription/create` (Bearer، PayPal) |
| `query` | `GET /api/payment/alipay/query?outTradeNo=…` (Bearer، علی پے)<br>`GET /api/subscription/create` (Bearer، PayPal) |
| `refresh-login` | `POST /api/auth/login` (`{step:1, username, password}`) |
| `whoami` | `GET /api/auth/me?token=…` |

قواعد کا ماخذ: رجسٹریشن فیلڈز اور حد بندی `registration-flow.md` میں؛ پیکج اور ایکٹیویشن چین
`payment-and-activation.md` میں (دونوں میں پلیٹ فارم سورس فائل کا حوالہ ہے)۔

## اسکرپٹ لیول پر خرابی کا حل

| علامت | کیا کریں |
|---|---|
| `Node 版本过低` (Node ورژن بہت پرانا) | خالص رہنمائی موڈ میں واپس جائیں، زبردستی نہ آزمائیں |
| نیٹ ورک خرابی / ٹائم آؤٹ | ایک بار دوبارہ کوشش کریں؛ پھر بھی ناکام ہو تو صارف سے نیٹ ورک ٹھیک کروا کر آگے بڑھیں (اسٹیٹ فائل موجود ہے، شروع سے `status` چلائیں تو بازیاب ہو جاتا ہے) |
| register پر کاروباری خرابی (用户名已存在 وغیرہ) | SKILL.md مرحلہ ۵ کی ٹیبل کے مطابق حل کریں، **تصدیقی کوڈ دوبارہ بھیجنے کی ضرورت نہیں** (۱۰ منٹ کے اندر ابھی بھی معتبر ہے) |
| register پر「邮箱验证码错误或已过期」 (ای میل تصدیقی کوڈ غلط یا میعاد ختم) | ٹائم آؤٹ → دوبارہ `send-code` |
| `create-order` کے بعد صارف نے پیمنٹ پیج بند کر دیا | سیدھا دوبارہ `create-order` (پرانا آرڈر 2h میں خود بند؛ PayPal کی PENDING سبسکرپشن 1h میں ختم) |
| `create-order --provider paypal` 409 لوٹاتا ہے | ایک ادھوری PayPal سبسکرپشن موجود ہے؛ 1h انتظار کریں، یا پرانی منظوری براؤزر میں مکمل کریں |
| `query` لگاتار pending / PENDING | صارف نے شاید ادائیگی نہیں کی؛ ایک بار پوچھ لیں۔ واقعی کی ہو → payment-and-activation.md کی ٹربل شوٹنگ ٹیبل کے مطابق چلیں |
| صارف home لنک پر کلک کرتا ہے لیکن سبسکرپشن پیج پر اتر جاتا ہے | مفت تجرباتی دور ختم ہو گیا → ادائیگی کے بہاؤ پر سوئچ کریں: `login-link --target pending` → ادائیگی کا طریقہ منتخب کریں → `create-order` |
| `refresh-login` 403 `pending_payment` | مفت تجرباتی دور ختم ہو گیا اور ادائیگی ابھی نہیں آئی؛ مرحلہ 9 پر واپس جا کر پولنگ جاری رکھیں، یا تصدیق کریں کہ صارف نے ادائیگی مکمل کی یا نہیں |
| اسٹیٹ فائل ضلع (غلطی سے ڈیلیٹ / مشین بدلی) | `whoami`/`refresh-login` نہیں چل سکتے؛ صارف سے کہیں جس براؤزر میں لنک ۱ کھولا تھا وہاں سبسکرپشن پیج ریفریش کر کے حالت دیکھ لے، یا دوبارہ لاگ اِن (ویب موڈ) |

## فالتو موڈ (خالص رہنمائی)

نیچے کی کسی ایک صورت میں فوراً v1 طرز کی خالص رہنمائی پر واپس جائیں، اسکرپٹ سے مزید نہ جھنجھٹیں:

- Node ≥ 18 نہ ہو یا اسکرپٹ لگاتار دو بار ایک جیسی ناکامی دے؛
- صارف صاف کہے "میں خود ویب پر کرتا ہوں"؛
- کمپنی/ڈیوائس پالیسی اسکرپٹ کے نیٹ ورک روکتی ہو۔

واپس آنے کے بعد: رجسٹریشن پیج https://global.powpow.online/register دیں (مفت تجرباتی دور میں ویب رجسٹریشن بھی اسی طرح فوری ہے؛ سبسکرپشن درکار ہونے پر سبسکرپشن پیج https://global.powpow.online/subscription بھی دیں)، `registration-flow.md` کے قواعد کے مطابق ساتھ ساتھ مسائل حل کریں، وہی لہجہ رکھیں، اور ہر بار کے آخر میں اب بھی "اگلا قدم" بلاک لگائیں۔
https://global.powpow.online/subscription دیں، `registration-flow.md` کے قواعد کے مطابق ساتھ چلیں،
لہجہ ویسا ہی رہے گا، ہر راؤنڈ پھر بھی "اگلا قدم" بلاک پر ختم ہوگا۔

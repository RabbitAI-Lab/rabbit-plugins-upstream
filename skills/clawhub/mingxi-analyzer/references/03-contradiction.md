# 矛盾分析法

融合 矛盾论 × 信息公理 × 哲数三进制

## 整体流程

```
矛盾性质判定（前置） → 找主要矛盾 → 矛盾的主要方面 → 三态跟踪 → 转化条件监控
```

## 矛盾性质判定（前置）

在分析任何矛盾前，先判定其性质：

| 性质 | 含义 | 处理方式 |
|:----|:-----|:---------|
| **对抗性** | 双方利益根本上冲突，不可调和 | 强干预方案 |
| **非对抗性** | 双方利益根本一致，冲突是局部的 | 可容忍/协商方案 |
| **结构张力** | 系统结构固有的紧张关系，不是具体冲突 | 关注但不急于行动 |

纪律：
1. 性质判定是静态诊断，三态分析是动态监控，两者互补使用
2. "结构张力"必须具体（如"代理人与委托人的利益天然不一致"）
3. 同一矛盾在不同阶段可以发生性质转化（如非对抗性→对抗性），需更新判定

## 主要矛盾定位法

问自己：**"哪一对矛盾同时满足：影响面最大 + 最不可绕开 + 解决它后其他问题自动缓解"**

## 矛盾三态分析

每分析一个矛盾时，评估其三态状态：

| 状态 | 标签 | 含义 | 行动 |
|:----|:----|:-----|:-----|
| +1 | 固化态 | 矛盾已解决或稳定 | 不需要立即动作 |
| 0 | 待定态 | 矛盾在转化中 | 持续观察（允许"看不清"） |
| -1 | 爆发态 | 矛盾激化 | 立即处理 |

### 临界条件（必填）
每个矛盾必须标注：**待定态(0)在什么具体条件下触发为爆发态(-1)**

> 不标注临界条件等于预警系统没有触发阈值。

### 操作纪律
1. 不是取代"主要矛盾分析"，是给其增加一个状态维度
2. 待定态（0）是合法状态，允许"看不清"而不急于下判断
3. 爆发态（-1）必须给出行动建议，不能只描述
4. 每次更新矛盾分析时，检查三态是否发生了转化

## 矛盾分析输出示例

```markdown
### 矛盾分析
- **主要矛盾**：技术能力快速膨胀 vs 生态协作基础设施薄弱
- **主要方面**：不是技术能力不够，是"跨Agent怎么协作"没有OS级解决方案
- **性质**：非对抗性（根本利益一致）
- **三态**：待定态（0）
- **临界条件**：如果连续3次协作尝试失败 → 转为爆发态
- **是否转化**：未转化
- **转化方向**：若出现OS级协作标准 → 固化态
```

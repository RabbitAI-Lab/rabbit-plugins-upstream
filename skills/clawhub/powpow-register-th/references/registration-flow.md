# รายละเอียดกระบวนการสมัครสมาชิก — powpow-register

ไว้ค้นตอนไล่ปัญหา กฎทั้งหมดมาจากซอร์สโค้ดของแพลตฟอร์ม (การตรวจสอบความสอดคล้อง front-back ของ Next.js)
ระบุที่มาไว้ครบ เมื่อแพลตฟอร์มอัปเดตให้ถือพฤติกรรมจริงบนเว็บเป็นฐาน

## ทางเข้า

- หน้าสมัคร: https://global.powpow.online/register
- หน้าล็อกอิน: https://global.powpow.online/login
- หน้าแพ็กเกจสมาชิก: https://global.powpow.online/subscription
- ถ้าเข้ามาจากลิงก์แชร์ที่มี `?next=...` พอสมัคร + จ่ายเงินเสร็จจะเด้งกลับไปหน้าเดิมอัตโนมัติ

## ฟิลด์ฟอร์มและกฎ

| ฟิลด์ | จำเป็น | กฎ | ที่มาในโค้ด |
|---|---|---|---|
| รูปโปรไฟล์ | ไม่จำเป็น | รูป ≤5MB ไม่รองรับ SVG เซิร์ฟเวอร์บีบอัดให้อัตโนมัติ (ถ้า >100KB บีบเหลือ 400×400 / คุณภาพ 90) | `src/app/api/auth/register/route.ts` |
| ชื่อผู้ใช้ | จำเป็น | 2~50 ตัวอักษร หลัง trim แล้วแปลงเป็น **ตัวพิมพ์เล็ก** ตอนเก็บ (Tom กับ tom ถือเป็นชื่อผู้ใช้เดียวกัน ทั้งฝั่งสมัครและฝั่งล็อกอินไม่สนตัวพิมพ์) | เดียวกัน (zod schema) |
| รหัสผ่าน | จำเป็น | 8~100 ตัวอักษร ต้องมีตัวพิมพ์ใหญ่ ตัวพิมพ์เล็ก และตัวเลขพร้อมกัน | เดียวกัน |
| ยืนยันรหัสผ่าน | จำเป็น | ตรงกับรหัสผ่าน (ตรวจเฉพาะฝั่งหน้าเว็บ) | `src/app/(public)/register/page.tsx` |
| ชื่อเล่น | ไม่จำเป็น | ≤100 ตัวอักษร ถ้าไม่กรอกใช้ชื่อผู้ใช้ | register route |
| อีเมล | **จำเป็น** | รูปแบบอีเมลถูกต้อง ≤255 ตัวอักษร หนึ่งอีเมลเปิดบัญชีได้คนเดียว | register route |
| รหัสยืนยันอีเมล | **จำเป็น** | 6 หลัก **อยู่ 10 นาที** ตรวจผ่านแล้วโดน invalidate ทันที การส่งใหม่จะ mark รหัสเก่าว่าใช้แล้ว | `src/lib/email-verification.ts` |
| เบอร์โทร | ไม่จำเป็น | เบอร์จีนแผ่นดินใหญ่ขึ้นต้น `1[3-9]` รวม 11 หลัก หนึ่งเบอร์ผูกได้หนึ่งบัญชี | register route |

หน้าเว็บมีปุ่มล็อกอินบุคคลที่สามอีกสามปุ่ม: **Google, Watcha, บัญชี Huawei**
(`GoogleSignInButton` / `WatchaLoginButton` / `HuaweiLoginButton`) บัญชีบุคคลที่สามไม่มีรหัสผ่านในระบบ
ถ้าไปล็อกอินด้วยรหัสผ่านภายหลังจะได้รับ «บัญชีนี้ไม่ได้ตั้งรหัสผ่าน กรุณาเข้าสู่ระบบด้วยวิธีอื่น»

## พารามิเตอร์เรตลิมิตและกันการเดา

| พฤติกรรม | ขีดจำกัด | ที่มา |
|---|---|---|
| ส่งใบสมัคร | **3 ครั้ง/นาที/IP** เกินโดน 429 | `src/lib/rate-limit.ts` `REGISTER_RATE_LIMIT` |
| ส่งรหัสยืนยัน | IP เดิม 1 ครั้ง/นาที **และ** อีเมลเดิม 1 ครั้ง/นาที เกินโดน 429 ปุ่มหน้าเว็บนับถอยหลัง 60 วินาที | `src/app/api/auth/register/send-code/route.ts` |
| ตรวจรหัสยืนยัน | ต่ออีเมลลองได้มากสุด **5 ครั้ง** ใน 10 นาที ชนเพดานแล้วแม้รหัสถูกก็โดนปฏิเสธ ต้องขอรหัสใหม่ | `src/lib/email-verification.ts` |
| ส่งรหัสลืมรหัสผ่าน | 1 ครั้ง/นาที/IP | `src/app/api/auth/forgot-password/route.ts` |
| ล็อกอิน | 5 ครั้ง/นาที/IP บัญชีเดิมพลาดติดกัน **5 ครั้งโดนล็อก 30 นาที** (423) ระหว่างนั้นมีแจ้งจำนวนครั้งที่เหลือลดลง | `src/app/api/auth/login/route.ts`, `rate-limit.ts` |

**พฤติกรรมปกป้องความเป็นส่วนตัว**: ตอนส่งรหัสยืนยัน / ลืมรหัสผ่าน ไม่ว่าอีเมลจะถูกใช้ลงทะเบียนแล้วหรือไม่มีอยู่จริง
API จะคืนข้อความสำเร็จแบบเดียวกันเสมอ ไม่เปิดเผยว่าอีเมลนั้นลงทะเบียนแล้วหรือยัง

## ความเท่าเทียมระหว่างโหมด agent ทำแทนกับการสมัครผ่านหน้าเว็บ

สคริปต์ของสกิลเรียก **ชุด API สาธารณะชุดเดียวกัน** (`/api/auth/register`, `send-code`, `login`,
`/api/auth/me`) ผ่านเส้นทางตรวจสอบ เรตลิมิต และ error เดียวกันกับการส่งฟอร์มหน้าสมัครทุกประการ — กฎทั้งหมด
ในไฟล์นี้ใช้กับสองโหมดเท่ากัน ลำดับเวลาสคริปต์และสัญญาคำสั่งดูที่ `references/agent-flow.md`

## ขั้นตอนสถานะหลังสมัครสำเร็จ

> **ช่วงทดลองใช้ฟรี (เริ่ม 2026-10-18; พฤติกรรมจริงของแพลตฟอร์มเป็นหลัก)**: บัญชีใหม่ที่สมัครแล้ว**ใช้ทุกฟีเจอร์ได้ทันที**
> (ฟีด แผนที่ ดิจิทัลฮิวแมน เช็กอิน ฯลฯ) โดยไม่ต้องจ่ายเงินเลย บัญชีที่ไม่ได้สมัครสมาชิกไม่ถูกกันออกจากหน้าเนื้อหาแล้ว การ "กั้น pending"
> ที่อธิบายในส่วนนี้คือสถานะปกติหลังช่วงทดลองจบ — เมื่อถึงตอนนั้น พฤติกรรมจริงบนระบบเป็นหลัก

1. ผู้ใช้ถูกบันทึกด้วย `accountStatus: 'pending'` และ**3 เหรียญเริ่มต้น** (เส้นทาง register)
2. เซิร์ฟเวอร์ยังวางคุกกี้ HttpOnly สองตัว: JWT (เข้าหน้าเว็บได้ทันที) และ pendingUserToken (หลักฐานตัวตนสำหรับขั้นตอนสมัครสมาชิก)
3. ในสถานะปกติ (ช่วงทดลองจบ / ไม่มีช่วงฟรี) หน้ากรมัครตรวจพบ `pending_payment` → เปลี่ยนทางไป `/subscription`
   (เก็บพารามิเตอร์กลับมา `next` ไว้) ในโหมดเอเจนต์ทำงานแทน `me?token=…&redirect=/subscription` ให้ผลเดียวกัน
   **ในช่วงทดลองใช้ฟรี ขั้นตอนนี้ไม่ถูกเรียกใช้** — หลังสมัครแล้วไปหน้าแรกโดยตรงและเริ่มใช้เลย
4. จ่ายเงินเสร็จ → `accountStatus` เป็น `active` (**Alipay เปิดใช้งานเองฝั่งเซิร์ฟเวอร์ผ่าน notify**;
   PayPal เปิดใช้งานผ่าน Webhook; QR โค้ด WeChat ยืนยันด้วยมือ; Huawei IAP ผ่าน `activate-huawei`)
   รายละเอียดอยู่ใน `payment-and-activation.md`

ในสถานะปกติ บัญชีที่ยังไม่เปิดใช้งาน (pending) ที่เรียก API หลัก (ฟีด แผนที่ แชตดิจิทัลฮิวแมน เช็กอิน ฯลฯ) จะได้ 403
ข้อยกเว้นคือลิงก์โพสต์ที่แชร์ (ยังเปิดสาธารณะ) ในช่วงทดลองใช้ฟรี การกั้นนี้ถูกระงับและทุกอย่างเปิดอยู่
## ตารางไล่ปัญหา error ที่พบบ่อย

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| 「用户名已存在」 (ชื่อผู้ใช้มีอยู่แล้ว) | ชื่อผู้ใช้ถูกใช้ (ไม่สนตัวพิมพ์) | เปลี่ยนชื่อผู้ใช้ใหม่ |
| 「邮箱已被使用」 (อีเมลถูกใช้แล้ว) | อีเมลถูกลงทะเบียนไปแล้ว | เปลี่ยนอีเมล หรือเปลี่ยนไปล็อกอิน + «ลืมรหัสผ่าน» เพื่อเอาบัญชีเก่าคืน |
| 「邮箱验证码错误或已过期」 (รหัสยืนยันผิดหรือหมดอายุ) | พิมพ์รหัสผิด / เกิน 10 นาที / พลาดเกิน 5 ครั้งโดนปฏิเสธ | กด «ส่งอีกครั้ง» แล้วใช้รหัสจากอีเมล **ฉบับล่าสุด** |
| รหัสยืนยันไม่เข้า | โดนลิมิต 60 วินาที หรือหลุดเข้าถังสแปม/เมลโฆษณา | รอนับถอยหลังหมดแล้วส่งใหม่ เข้าไปค้นโฟลเดอร์สแปม |
| 「手机号已被使用」 (เบอร์โทรถูกใช้แล้ว) | เบอร์ผูกกับบัญชีอื่นอยู่ | ลบเบอร์ออก (ฟิลด์ไม่จำเป็น) หรือเปลี่ยนเบอร์ |
| 「注册请求过于频繁」 (คำขอสมัครถี่เกินไป) / 429 | ชนเพดานสมัคร 3 ครั้ง/นาที/IP | รอสองสามนาทีแล้วลองใหม่ |
| 409 「用户名或邮箱已被注册」 (ชื่อผู้ใช้หรืออีเมลถูกลงทะเบียนแล้ว) | ชนกับคนอื่นพอดีจังหวะส่ง (เซฟตี้เน็ตกรณี concurrent) | เปลี่ยนชื่อผู้ใช้หรืออีเมลแล้วลองใหม่ |
| 「图片大小不能超过5MB」 (รูปต้องไม่เกิน 5MB) / 「不支持 SVG」 (ไม่รองรับ SVG) | รูปโปรไฟล์ไม่ผ่านเกณฑ์ | เปลี่ยนรูปหรือข้ามรูปโปรไฟล์ |
| ผู้ใช้คลิกลิงก์ล็อกอินแต่ไปลงที่หน้าสมาชิก (แทนหน้าแรก) | ช่วงทดลองใช้ฟรีจบแล้ว กำแพงค่าธรรมเนียมของแพลตฟอร์มกลับมา | ทำตามขั้นตอนสมัครสมาชิกจากขั้นตอนที่ 7 ใน SKILL.md หลังจากสมัครเสร็จรัน `refresh-login` แล้วส่งลิงก์หน้าแรก |
| สมัครสำเร็จแต่ล็อกอินคืน 403 "请完成订阅以激活账户" | บัญชียัง pending และแพลตฟอร์มไม่ได้อยู่ในช่วงทดลองใช้ฟรี (สถานะที่คาดก่อนจ่ายเงิน) | ในช่วงทดลองใช้ฟรีจะไม่เกิด หากเกิดแสดงว่าช่วงทดลองจบแล้ว — สมัครสมาชิกให้เสร็จก่อน หากจ่ายเงินแล้วยัง 403 แสดงว่าใช้ JWT เก่า — ในโหมดสคริปต์รัน `refresh-login` ก่อนเพื่อแลกสลับสถานะล็อกอินใหม่ |
| ล็อกอิน 423 「账户已锁定」 (บัญชีถูกล็อก) | รหัสผ่านพลาดติดกัน 5 ครั้ง | รอ 30 นาที |
| ล็อกอิน 401 「还剩 N 次尝试机会」 (เหลือโอกาสลอง N ครั้ง) | รหัสผ่านผิด ใกล้โดนล็อก | คิดให้ดีก่อนลอง หรือไป «ลืมรหัสผ่าน» เลย |
| 「该账号未设置密码，请使用其他方式登录」 (บัญชีนี้ไม่ได้ตั้งรหัสผ่าน กรุณาเข้าสู่ระบบด้วยวิธีอื่น) | บัญชีบุคคลที่สาม (Google/Watcha/Huawei) | ล็อกอินด้วยปุ่มบุคคลที่สามตัวเดิม |
| 「该账号已注销」 (บัญชีนี้ถูกยกเลิกแล้ว) | บัญชีถูก deactivate | ต้องสมัครใหม่ |

## ความรู้เล็ก ๆ เรื่องล็อกอิน (เผื่อไล่ปัญหา)

ล็อกอินรองรับการป้อน **ชื่อผู้ใช้ / อีเมล / เบอร์โทร** แบบสามในหนึ่ง (อย่างใดอย่างหนึ่งใช้เป็นชื่อบัญชีได้)
ลืมรหัสผ่าน: หน้าล็อกอิน → «ลืมรหัสผ่าน» → กรอกอีเมลที่สมัครไว้ รับรหัส 6 หลัก → ตั้งใหม่

# การเปิดใช้สมาชิกภาพและการชำระเงิน — powpow-register

## บทสรุป (พูดคำตอบก่อน)

**วิธีชำระเงินที่มีอยู่ใช้ต่อได้เลย skill ผู้ช่วยสมัครไม่ต้องพัฒนาระบบจ่ายเงินอะไรเลย**

เหตุผล:

1. ฟังก์ชันสมัคร (`src/app/api/auth/register/route.ts`) ตอนสร้างบัญชี pending ออก
   JWT cookie + pendingUserToken HttpOnly cookie ให้แล้ว ผู้ใช้ลงที่ `/subscription` คือ
   สถานะล็อกอินเรียบร้อย — สามช่องทางจ่ายเงินแขวนอยู่กับหน้าแพ็กเกจนี้ เปิดใช้บัญชี pending เดียวกันทั้งหมด
2. ฟังก์ชันเข้าสู่ระบบกับบัญชี pending คืน 403 + `redirectTo: '/subscription'` ทั้งยังวาง
   cookie ให้เหมือนกัน — ผู้ใช้จ่ายเพิ่มตอนไหนก็ถูกพากลับมาหน้าเดิม
3. เพราะฉะนั้นขอบเขตหน้าที่ของ skill แนะนำการสมัครคือ "พาผู้ใช้ไปที่ /subscription"; ไม่ต้องมี
   API จ่ายใหม่ ไม่ต้องมีโมเดลออเดอร์ใหม่ ไม่ต้องแก้ backend เลย

พร้อมกันนั้นต้องจำไว้: ขั้นตอนชำระเงิน (ปุ่ม PayPal JS SDK, WeChat สแกน QR ยืนยันด้วยคน, Huawei IAP ดั้งเดิม)
**กำหนดว่ามันทำไม่ได้และไม่ควรทำโดย skill ไลน์คำสั่ง/แชทแทนจ่าย** อย่าพยายามใช้สคริปต์เรียก API จ่ายเงิน
แทนผู้ใช้ และอย่าขอหลักฐานการชำระของผู้ใช้

## สามช่องทางบนหน้าแพ็กเกจ

หน้าแพ็กเกจ `src/app/(public)/subscription/page.tsx` แสดงอัตโนมัติตามสภาพแวดล้อม:

| ช่องทาง | สภาพแวดล้อม | กลไก | วิธีเปิดใช้ |
|---|---|---|---|
| สมัครสมาชิก PayPal | เว็บ (ไม่ใช่ HarmonyOS) | `/api/subscription/create` สร้างแพ็กเกจ PayPal → ไปหน้า PayPal อนุมัติ; ต่ออายุเดือนละครั้งอัตโนมัติ ยกเลิกเมื่อไหร่ก็ได้ (`/api/subscription/manage`) | PayPal Webhook (`BILLING.SUBSCRIPTION.*`) ตั้ง `accountStatus` เป็น active อัตโนมัติ |
| WeChat สแกน QR สมัครสมาชิก | เว็บ (ไม่ใช่ HarmonyOS) | บล็อก "WeChat สแกน QR สมัครสมาชิก" ล่างหน้า: สแกนโอนเงิน **เปิดใช้เมื่อยืนยันด้วยคนแล้ว** (`WechatQrPaymentSection`) | ยืนยันด้วยคน เงินเข้าอาจดีเลย์; ผู้ใช้จ่ายเสร็จอย่ารีบสรุปว่าล้มเหลว |
| ซื้อในแอป Huawei (IAP) | ในแอป HarmonyOS | ใน WebView HarmonyOS ใช้ PayPal/WeChat จ่ายไม่ได้ หน้าเปลี่ยนไปใช้ `NativeBridge.purchaseSubscription()` ดั้งเดิม | `/api/subscription/activate-huawei` ตรวจสอบออเดอร์ Huawei แล้วเปิดใช้ |

แผนกับราคาอ่านแบบไดนามิกจาก `/api/subscription/plans` (แผน PayPal); ข้อความติดหน้าหน้า:
Auto-renews. Cancel anytime.

## สถานะกับการเปลี่ยนหน้า

- จ่ายสำเร็จ → `/subscription/success` (callback PayPal พ่วง `subscriptionId`) → บัญชี
  active → กระโดดกลับหน้าต้นทางตาม `next` (ไม่มีไปหน้าหลัก)
- ผู้ใช้ที่สมาชิกอยู่แล้วกลับมาหน้าแพ็กเกจ → แสดง "You're All Set!" 3 วินาทีกลับหน้าหลักเอง
- จ่ายไม่สำเร็จ/ยกเลิก → `/subscription/cancel` เริ่มใหม่ได้

## การตรวจหา

| อาการ | วิธีจัดการ |
|---|---|
| จ่ายเสร็จยัง 403 | PayPal: Webhook อาจดีเลย์บ้าง ล็อกอินใหม่รีเฟรชสถานะ (ตอนล็อกอินจะเช็คสถานะล่าสุดจาก DB); WeChat: ยืนยันด้วยคนยังไม่เสร็จ รอหน่อย; Huawei: ดูว่าหน้าสำเร็จการจ่ายในแอปขึ้นไหม |
| หน้าแพ็กเกจแจ้ง "No subscription plans available" | `/api/subscription/plans` ไม่มีแผน PayPal ใช้ได้ เป็นปัญหาคอนฟิกฝั่งแพลตฟอร์ม ให้ผู้ใช้ลองทีหลัง |
| WeChat จ่ายแล้วยังไม่เปิดใช้ | การยืนยันด้วยคนเป็นแบบ async ผ่านไปสองสามชั่วโมงยังไม่เปิดใช้ค่อยติดต่อฝ่ายสนับสนุน (dongtao@outlook.com) |

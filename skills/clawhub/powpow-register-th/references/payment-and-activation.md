# การเปิดใช้งานสมาชิกและการชำระเงิน — powpow-register

## ข้อสรุป (ตอบก่อน)
> **ช่วงทดลองใช้ฟรี (เริ่ม 2026-10-18; พฤติกรรมจริงของแพลตฟอร์มเป็นหลัก)**: ในช่วงนี้บัญชีที่สมัครแล้วใช้ทุกฟีเจอร์ได้ทันที และ**สมัครสมาชิกคือการอัปเกรดแบบตัวเลือก ไม่ใช่ข้อกำหนด** — ทำตามขั้นตอนในไฟล์นี้เฉพาะเมื่อผู้ใช้อยากได้สมาชิกเอง เมื่อช่วงทดลองจบ บัญชีที่ไม่ได้สมัครสมาชิกจะถูกส่งไปหน้าสมาชิกเมื่อเข้าหน้าเนื้อหา เพียงทำตามไฟล์นี้เพื่อสมัครสมาชิกให้เสร็จ


**ช่องทาง Alipay และ PayPal ตอนนี้ agent จัดการแทนได้ทั้งคู่ — รวมทั้งสร้างออเดอร์และติดตามจนเงินเข้า**
Alipay ซื้อขาดครั้งเดียวไม่ต่ออายุอัตโนมัติ สำหรับผู้ใช้จีนแผ่นดินใหญ่และผู้ใช้ที่มี Alipay
ส่วน PayPal ต่ออายุอัตโนมัติรายเดือนและยกเลิกได้ทุกเมื่อ สำหรับผู้ใช้ต่างประเทศและผู้ใช้ที่ไม่มี Alipay
สแกน WeChat (ยืนยันด้วยมือ) และ Huawei IAP ก็ยังมีอยู่ แต่สกิลไม่จัดการแทนสองช่องทางนั้น

เขตแดนความรับผิดชอบในการจ่ายเงิน: agent **สร้างออเดอร์ได้ เปิดหน้าชำระเงินได้ เช็กเงินเข้าได้** แตะบัญชี Alipay/PayPal
หรือหลักฐานการจ่ายเงินของผู้ใช้ **ไม่ได้เด็ดขาด** และห้ามสัญญาว่า «จ่ายแทนให้» เด็ดขาด การจ่ายเงินเกิดขึ้นที่ผู้ใช้เอง
บนหน้าชำระเงินทางการเสมอ

## ช่องทาง Alipay (vibepay, ช่องทางหลัก)

โมเดลซื้อขาด: จ่ายครั้งเดียวเปิดช่วงเวลาที่เลือก **ไม่ต่ออายุอัตโนมัติ** แพ็กเกจกำหนดไว้ใน
`src/lib/alipay-vibepay.ts` (`ALIPAY_PACKAGES`):

| key | planId | ชื่อ | ราคา | ระยะเวลา |
|---|---|---|---|---|
| `monthly` | alipay-monthly | สมาชิกรายเดือน | ¥6.99 | 30 วัน |
| `quarterly` | alipay-quarterly | สมาชิกราย 3 เดือน | ¥19.99 | 90 วัน |
| `yearly` | alipay-yearly | สมาชิกรายปี | ¥69.99 | 365 วัน |

### สัญญา API (สคริปต์ของสกิลห่อไว้แล้ว agent ไม่ประกอบ request เอง)

| API | เมธอด | คำอธิบาย |
|---|---|---|
| `/api/payment/alipay/create-order` | POST | ต้องมี `Authorization: Bearer <JWT>` (ผู้ใช้ pending ก็ใช้ได้) body `{package}` → คืน `{paymentHtml, outTradeNo, amount, planName}` โดย `paymentHtml` คือหน้าฟอร์มที่ส่งตัวเองขึ้นเกตเวย์ Alipay โดยอัตโนมัติ |
| `/api/payment/alipay/query` | GET `?outTradeNo=` | Bearer ตัวเดิม คืน `paid` / `pending` / `closed` / `unknown` |
| `/api/payment/alipay/notify` | POST (คอลแบ็กจากเซิร์ฟเวอร์ Alipay) | ตรวจลายเซ็นครบห้าด้าน (ลายเซ็น, app_id, ยอดเงินตรง, TRADE_SUCCESS/TRADE_FINISHED, ความเป็นเอกลักษณ์ของเลขออเดอร์ร้านค้า) → อัปเดตออเดอร์แบบ **idempotent** + สร้างสมาชิก + เปิดใช้งานบัญชี สกิลไม่แตะ API นี้เด็ดขาด |
| `/payment/alipay/return` | หน้าย้อนกลับของเบราว์เซอร์ | path สาธารณะ หลังจ่ายเงินแสดง 「支付成功」 หน้าเว็บมีการโพลสถานะจริงจาก backend |

- ออเดอร์ที่ไม่ได้จ่าย **ปิดตัวเองใน 2 ชั่วโมง** ผู้ใช้ทิ้งกลางทาง → รัน `create-order` ใหม่ได้เลย อย่าไปสนออเดอร์เก่า
- สคริปต์เขียน `paymentHtml` ลงไฟล์ HTML ชั่วคราว agent เปิดด้วยคำสั่งระบบก็เข้าถึงหน้าชำระเงิน Alipay ได้ทันที
  (สแกน QR หรือล็อกอิน Alipay เพื่อจ่าย)

### ห่วงโซ่การเปิดใช้งาน (อัตโนมัติ ไม่มีงานมือ)

ลายเซ็น notify ผ่าน → ทำเครื่องหมายออเดอร์ใน `paymentOrders` ว่าจ่ายแล้ว → สร้าง/ต่ออายุ `user_subscriptions`
(`planId`, `currentPeriodEnd` คำนวณจาก durationDays การต่ออายุบวกเฉพาะบนวันหมดอายุเดิม) →
`users.accountStatus: active` + `subscriptionStatus: ACTIVE` → หน้าย้อนกลับจับ paid ได้ก็แสดงความสำเร็จ

## หลังจ่ายเงินต้องเอาสถานะล็อกอินใหม่ (สำคัญ)

JWT ฝัง claim ของสมาชิกไว้ (บัญชี pending เป็น `NONE`) **การเงินเข้าหลังจ่ายเงินอัปเดตเฉพาะฐานข้อมูล
JWT ที่ออกไปแล้วไม่เปลี่ยน** — claim ของ token เก่ายังเป็น NONE อยู่ ถี่งเอาไปสร้างลิงก์ล็อกอินจะดูเหมือน
«ไม่มีสมาชิก» ดังนั้นพอยืนยัน `paid` / PayPal `ACTIVE` แล้วสกิลจะรัน `refresh-login` ก่อน (ล็อกอินใหม่ JWT ใหม่ claim เป็น ACTIVE)
แล้วจึงสร้างลิงก์ 2 นี่คือพฤติกรรมของดีไซน์ ไม่ใช่บั๊กที่ต้องแก้

## ช่องทางสมาชิก PayPal (สกิลทำแทน; เว็บ, ไม่ใช่ HarmonyOS)

มีแพ็กเกจเดียวคือ Premium Monthly (ประมาณ $1/เดือน ตามที่ `/api/subscription/plans` คืนมา) **ต่ออายุอัตโนมัติรายเดือน**
และผู้ใช้ยกเลิกได้ทุกเมื่อในบัญชี PayPal ของตัวเอง

### สัญญา API (สคริปต์ของสกิลครอบไว้แล้ว agent ไม่ประกอบคำขอเองเด็ดขาด)

| เอนด์พอยต์ | เมธอด | หมายเหตุ |
|---|---|---|
| `/api/subscription/plans` | GET | ต้องใช้ Bearer คืนรายการแพ็กเกจที่ใช้ได้ (ตอนนี้มี 1 เดียว) |
| `/api/subscription/create` | POST | body `{planId}` → คืน `{subscriptionId, approveUrl, status}`; `status` มักเป็น `APPROVAL_PENDING` |
| `/api/subscription/create` | GET | ต้องใช้ Bearer คืน `{activeSubscription, allSubscriptions}`; agent โพล `activeSubscription.subscription.status === 'ACTIVE'` |
| `/api/subscription/verify` | POST | หน้าสำเร็จเรียกอัตโนมัติ (พร้อม cookie) เปิดใช้งานผ่าน PayPal API โดยตรงเมื่อ webhook ยังไม่มา |
| `/subscription/success` | หน้ากลับของเบราว์เซอร์ | หน้าที่ลงหลังอนุมัติ PayPal โพล verify อัตโนมัติ แล้วกลับหน้าแรก / หน้าเดิม |
| `/subscription/cancel` | หน้าในเบราว์เซอร์ | หน้าที่ลงเมื่อผู้ใช้ยกเลิกหรือล้มเหลว เริ่มใหม่ได้ |

### ลำดับของ agent

```
create-order --provider paypal   # → คืน approveUrl เขียนลงไฟล์ HTML ในเครื่อง
เปิดไฟล์ HTML                    # → เบราว์เซอร์เด้งไปหน้าอนุมัติของ PayPal
query (ทุก 10–15 วิ)             # → โพลจน ACTIVE
refresh-login                    # → แลก JWT ใหม่ (claim สมาชิก ACTIVE)
login-link --target home         # → สร้างลิงก์ล็อกอินทางการ
```

- สมาชิก PENDING ที่ไม่เสร็จใน 1 ชั่วโมง ฝั่งแบ็กเอนด์เคลียร์ให้เอง เริ่มใหม่ได้เลย
- ถ้าผู้ใช้รัน `create-order` อีกครั้ง แบ็กเอนด์จะ reuse สมาชิก `APPROVAL_PENDING` ที่ยังใช้ได้ จึงไม่เกิด 409
- เหมือน Alipay: เงินเข้าอัปเดตแค่ DB — JWT เก่าไม่รีเฟรชอัตโนมัติ ดังนั้น **ต้อง** รัน `refresh-login` ก่อนส่งลิงก์หน้าแรก

## สี่ช่องทางบนหน้าแพ็กเกจสมาชิก

หน้าแพ็กเกจ `src/app/(public)/subscription/page.tsx` แสดงตามสภาพแวดล้อมที่รัน:

| ช่องทาง | สภาพแวดล้อม | กลไก | วิธีเปิดใช้งาน |
|---|---|---|---|
| **Alipay (หลัก)** | เว็บ | `AlipayPaymentSection` เกาะกับ API ของ vibepay (ตารางด้านบน) | notify เปิดใช้อัตโนมัติฝั่งเซิร์ฟเวอร์ เสร็จในหน่วยวินาที |
| สมาชิก PayPal | เว็บ (ไม่มีบน HarmonyOS) | `/api/subscription/create` → อนุมัติ PayPal รายเดือนต่ออายุอัตโนมัติ ยกเลิกได้ทุกเมื่อ (`/api/subscription/manage`) | PayPal Webhook (`BILLING.SUBSCRIPTION.*`) ตั้ง active ให้อัตโนมัติ |
| สมาชิกสแกน WeChat | เว็บ (ไม่มีบน HarmonyOS) | ท้ายหน้า 「微信扫码订阅」: โอนเงินโดยสแกน QR | **ยืนยันด้วยมือ** เงินเข้าอาจช้า อย่าเพิ่งตัดสินว่าพังทันทีหลังจ่าย |
| ซื้อในแอป Huawei | ในแอป HarmonyOS | เรียก native `NativeBridge.purchaseSubscription()` | `/api/subscription/activate-huawei` ตรวจออเดอร์ Huawei แล้วเปิดใช้งาน |

แพ็กเกจและราคา PayPal มาแบบไดนามิกจาก `/api/subscription/plans` ข้อความคงที่บนหน้า:
Auto-renews. Cancel anytime.

## สถานะและการรีไดเรกต์

- Alipay เสร็จสมบูรณ์ → หน้าย้อนกลับแสดงความสำเร็จ PayPal สำเร็จ → `/subscription/success` → บัญชี active →
  เด้งกลับหน้าเดิมตามพารามิเตอร์ `next` อัตโนมัติ (ถ้าไม่มีกลับหน้าแรก)
- คนที่เป็นสมาชิกอยู่แล้วเปิดหน้าแพ็กเกจ → เจอ "You're All Set!" ใน 3 วินาทีกลับหน้าแรกเอง
- จ่ายเงินล้มเหลว/ยกเลิก (PayPal) → `/subscription/cancel` ลองใหม่ได้

## การวินิจฉัย

| อาการ | ทางแก้ |
|---|---|
| จ่าย Alipay แล้ว `query` ยัง pending | notify ช้าน้อยมาก รอ 30 วินาทีแล้วเช็กใหม่ ยังไม่ได้ให้ผู้ใช้ดูสถานะหน้าย้อนกลับในเบราว์เซอร์ ยังไม่หายให้ติดต่อซัพพอร์ตแพลตฟอร์ม (dongtao@outlook.com) พร้อมแจ้ง `outTradeNo` |
| Alipay ตัดเงินแล้วแต่เข้าลิงก์ 2 ยังโดนบล็อก | ข้าม `refresh-login` ไป (claim ของ JWT เก่าไม่ได้อัปเดต) — รัน `refresh-login` ก่อน แล้วค่อย `login-link` |
| `query` ของ PayPal เป็น PENDING ตลอด | ผู้ใช้ยังอนุมัติใน PayPal ไม่เสร็จ ตรวจสอบว่าลิงก์อนุมัติเปิดในเบราว์เซอร์แล้ว ถ้าอนุมัติแล้วยัง PENDING webhook อาจดีเลย์ — ให้ผู้ใช้รออีกสักครู่บนหน้าสำเร็จหรือรีเฟรช |
| `query` ของ PayPal คืน 409 | มีสมาชิก PENDING ที่ยังไม่เสร็จอยู่ รอ 1 ชั่วโมงให้หมดอายุ หรืออนุมัติลิงก์เก่าในเบราว์เซอร์ |
| จ่ายผ่าน PayPal แล้วแต่ลิงก์ 2 ยังโดนบล็อก | เหมือน Alipay: รัน `refresh-login` ก่อน แล้วค่อย `login-link` |
| จ่ายแล้วยัง 403 (PayPal) | Webhook บางทีช้า ล็อกอินใหม่เพื่อรีเฟรชสถานะ |
| จ่ายผ่าน WeChat แล้วสมาชิกไม่เปิด | การยืนยันด้วยมือเป็นแบบ async ถ้าผ่านไปสองสามชั่วโมงยังไม่เปิดให้ติดต่อซัพพอร์ตแพลตฟอร์ม |
| หน้าแพ็กเกจขึ้น "No subscription plans available" | `/api/subscription/plans` ไม่มีแพ็กเกจ PayPal เป็นปัญหา config ฝั่งแพลตฟอร์ม ผู้ใช้ในจีนแผ่นดินใหญ่พลางนี้ใช้ Alipay ไปก่อนได้ |

## โน้ตประวัติศาสตร์

ในโค้ดยังมีชุดจ่ายเงิน Alipay เว็บแบบ **เก่า** (`src/lib/alipay.ts`, `/api/payment/create-order`,
ซื้อขาด ¥9.90/¥99 ถ้าไม่มีคีย์ sandbox จะรันแบบจำลองการจ่ายเงิน) ชุดนี้ไม่เคยถูกเชื่อมกับ UI หน้าแพ็กเกจเลย
และไม่เกี่ยวกับ vibepay สกิลไม่แตะมันเด็ดขาด ช่องทางที่ใช้จริงคือ `alipay-vibepay.ts`

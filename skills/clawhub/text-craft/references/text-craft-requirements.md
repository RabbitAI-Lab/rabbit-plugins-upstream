## 写作翻译任务要求清单

写作翻译每种任务类型的零件清单——必选组件、可选组件、组装顺序、领域约束。按清单逐项产出。

---

### TC1 学术文稿

#### 域级说明

**域定位**：覆盖期刊论文、学位论文与文献综述的成文全流程，输出符合目标刊物体例的稿件。

| 维度 | 内容 |
|------|------|
| 价值链形态 | 选题→综述→方法→结果→讨论→投稿 |
| 独立成域的理由 | 学术链的终点是同行评审与返修，成文只是中间产物；引用规范与可复现性构成硬约束，与其他文种不同构 |
| 穷尽性 | 6 个任务覆盖「选题→综述→方法→结果→讨论→投稿」的 6 个环节；按输入物、失败模式、验收标准三条判据互不重叠，无未覆盖环节 |
| 知识要点 | IMRaD 结构：引言（背景-缺口-目的）、方法（可复现）、结果（客观陈述）、讨论（解释-局限-意义）；引言漏斗：领域重要性 → 已知什么 → 未知什么（缺口）→ 本文做什么；摘要四要素：背景、方法、结果（含关键数字）、结论；结构化摘要另加目的与局限；引文规范：GB/T 7714、APA、IEEE、Nature 各自格式差异；顺序编码制与著者出版年制；学术语域：被动语态使用场合、模糊限制语（may/suggest）、避免口语与绝对化；原创性：与已有表述的区分度、自我抄袭边界、AI 生成内容的披露要求；LaTeX 要素：文档类（article/IEEEtran/acmart）、图表浮动体、参考文献 bib 管理 |
| 判定标准 | 每个论断须有引文或数据支撑，无支撑的须标为作者观点；结果部分不得混入解释，讨论部分不得新增结果；引用格式须与目标刊物一致，逐条核对；摘要不得出现正文没有的内容 |
| 常见失范 | 引言过长且未点明缺口；方法与结果脱节，无法复现；讨论重复结果而不做解释；参考文献格式混用多种标准 |
| 范本结构 | 标题与摘要 → 引言（含研究缺口） → 方法（可复现） → 结果（图表+客观陈述） → 讨论（解释/局限/意义） → 结论 → 参考文献 |

#### TC1-01 论文选题与结构规划
- **必选组件**: 研究问题、贡献声明、章节大纲、每章要回答的问题
- **可选组件**: 目标期刊要求、已有文献
- **组装顺序**: 明确问题→提炼贡献→设计章节→分配篇幅→大纲
- **约束**: 贡献点须具体可陈述；大纲须覆盖 IMRaD 全部要素
- **格式**: 论文大纲

#### TC1-02 论文正文撰写
- **必选组件**: 各章正文、图表清单、论证链检查表
- **可选组件**: 实验数据、文献笔记
- **组装顺序**: 写方法→写结果→写讨论→写引言→写结论→写摘要
- **约束**: 结果与讨论分离；每个论断有支撑；图表须被正文引用
- **格式**: 论文初稿

#### TC1-03 LaTeX 排版与投稿包
- **必选组件**: tex 源文件、bib 文件、图表文件、编译说明
- **可选组件**: 刊物模板、投稿系统要求
- **组装顺序**: 选模板→迁移正文→处理图表→编译调试→打包
- **约束**: 须编译通过无警告；图表路径须相对；参考文献须完整
- **格式**: LaTeX 投稿包

#### TC1-04 语言润色与学术化
- **必选组件**: 修改说明表（原文/改后/理由）、润色稿、术语一致性检查
- **可选组件**: 目标刊物语言风格
- **组装顺序**: 通读→标记问题→逐句修改→术语统一→复核
- **约束**: 不得改变原意与数据；须逐条给修改理由
- **格式**: 润色稿+修改说明

#### TC1-05 原创性优化与去重
- **必选组件**: 重复段落清单、改写稿、重复率对比、引用规范检查
- **可选组件**: 查重报告、原文对照
- **组装顺序**: 识别重复→判定性质（引用/套话/抄袭）→改写→复核
- **约束**: 引用他人观点须标注；不得为降重牺牲准确性
- **格式**: 原创性优化稿

#### TC1-06 文献综述撰写
- **必选组件**: 综述框架、文献矩阵表、主题脉络、研究空白
- **可选组件**: 已检索文献集
- **组装顺序**: 定综述类型→建文献矩阵→归纳主题→指出分歧→识别空白
- **约束**: 须覆盖正反观点；须说明检索范围与时间
- **格式**: 文献综述稿

### TC2 公文与告知文书

#### 域级说明

**域定位**：产出符合《党政机关公文格式》（GB/T 9704）的法定文种，行文关系不得出错。

| 维度 | 内容 |
|------|------|
| 价值链形态 | 文种判定→行文关系→事项→格式→校对 |
| 独立成域的理由 | 公文有法定文种与行文关系，格式错误即实质缺陷；自由度远低于其他文种 |
| 穷尽性 | 6 个任务覆盖「文种判定→行文关系→事项→格式→校对」的 5 个环节；按输入物、失败模式、验收标准三条判据互不重叠，无未覆盖环节 |
| 知识要点 | 15 种法定文种：决议、决定、命令、公报、公告、通告、意见、通知、通报、报告、请示、批复、议案、函、纪要；行文关系：上行文（请示、报告）、下行文（命令、通知、批复）、平行文（函）；请示与报告的分界：请示须一文一事、须有明确请求、须等批复；报告不得夹带请示事项；格式要素：份号、密级、紧急程度、发文机关标志、发文字号、标题（发文机关+事由+文种）、主送机关、正文、附件说明、落款、成文日期、印章、附注、附件；层次序数：一、（一）1.（1）；语言特征：庄重、简明、无歧义；不用比喻与夸张；数字用法依 GB/T 15835 |
| 判定标准 | 文种选择必须与行文目的匹配，请示不得写成报告；标题三要素齐全，事由须概括准确；一文一事，不得多事并报；格式要素缺一即不合格 |
| 常见失范 | 请示与报告混用；标题缺发文机关或事由；主送机关多头请示；层次序数错乱；成文日期用阿拉伯数字以外的写法 |
| 范本结构 | 发文机关标志与发文字号 → 标题 → 主送机关 → 正文（缘由-事项-结语） → 附件说明 → 落款与成文日期 → 附注 |

#### TC2-01 通知与通报起草
- **必选组件**: 事由、依据、事项条款、执行要求、落款
- **可选组件**: 上级文件、既往同类文
- **组装顺序**: 定文种→写缘由→列事项→提要求→落款
- **约束**: 一文一事；事项须可执行；引用上级文件须给文号
- **格式**: 公文成稿

#### TC2-02 请示与报告起草
- **必选组件**: 请示事项、理由与依据、建议方案、报告事项
- **可选组件**: 预算/编制材料、上级要求
- **组装顺序**: 判文种→写缘由→陈述事项→提建议→结语
- **约束**: 请示须一文一事且有明确请求；报告不得夹带请示
- **格式**: 公文成稿

#### TC2-03 函与意见起草
- **必选组件**: 商洽事项、依据、期望答复、意见条款
- **可选组件**: 往来函件、政策依据
- **组装顺序**: 定关系→写缘由→述事项→表期望/列意见
- **约束**: 平行文不得使用指令性语气；意见须分层可落地
- **格式**: 公文成稿

#### TC2-04 讲话稿与工作总结
- **必选组件**: 场合与听众、核心观点、结构层次、数据支撑
- **可选组件**: 工作台账、既往讲话稿
- **组装顺序**: 定场合→定主旨→搭结构→填内容→调语气
- **约束**: 讲话稿须口语可读；总结须有数据与问题
- **格式**: 讲话稿/总结

#### TC2-05 公文排版与合规校对
- **必选组件**: 排版文件、格式检查表、校对记录
- **可选组件**: 标准原文、模板
- **组装顺序**: 套模板→排要素→校格式→校文字→出稿
- **约束**: 字号字体页边距须符合标准；要素缺项须列出
- **格式**: 排版定稿+校对表

#### TC2-06 告知类文书与家长沟通
- **必选组件**: 沟通目的、事实依据、建议动作、语气基调、渠道适配
- **可选组件**: 对象画像、历史沟通记录
- **组装顺序**: 定目的→述事实→给建议→调语气→适配渠道
- **约束**: 评价须具体到行为；不得贴标签；保护隐私
- **格式**: 告知文书/沟通文案

### TC3 法律文书

#### 域级说明

**域定位**：产出合同、协议、法律意见书与诉讼文书的规范文本，条款须可执行、无歧义。

| 维度 | 内容 |
|------|------|
| 价值链形态 | 主体→权利义务→违约→争议解决→效力 |
| 独立成域的理由 | 以可执行与无歧义为首要标准，条款须能直接进入诉讼，验收看效力而非可读性 |
| 穷尽性 | 6 个任务覆盖「主体→权利义务→违约→争议解决→效力」的 5 个环节；按输入物、失败模式、验收标准三条判据互不重叠，无未覆盖环节 |
| 知识要点 | 合同八要素：主体、标的、数量质量、价款、履行期限地点方式、违约责任、争议解决、生效条件；条款起草原则：定义前置、权利义务对称、违约后果可计算、争议解决唯一；常见合同类型要点：劳动（试用期/竞业/补偿）、买卖（风险转移/验收）、租赁（转租/维修）、服务（交付标准/验收）、NDA（保密范围/期限/例外）；诉讼文书结构：当事人信息、诉讼请求、事实与理由、证据清单、落款；法律意见书结构：委托事项、事实摘要、法律分析、结论意见、风险提示、免责声明；条款效力：违反法律强制性规定无效；格式条款须提示说明 |
| 判定标准 | 主体信息须完整可核验；权利义务须对称，单方权利须有对价；违约与争议解决条款须可执行；金额、期限、比例须具体，禁止"另行协商"占位 |
| 常见失范 | 关键条款留空待议；违约责任无计算方式；争议解决条款同时约定诉讼与仲裁；定义术语前后不一致 |
| 范本结构 | 首部（主体/鉴于） → 定义条款 → 权利义务条款 → 价款与支付 → 违约责任 → 争议解决 → 附则与签署 |

#### TC3-01 合同起草
- **必选组件**: 合同全文、条款清单、风险提示、待确认项
- **可选组件**: 交易背景、双方主体信息、商务条款
- **组装顺序**: 定合同类型→搭条款框架→填商务条款→写通用条款→复核
- **约束**: 条款须可执行；空白项须标 [待确认]；须给风险提示
- **格式**: 合同文本

#### TC3-02 协议模板生成
- **必选组件**: 模板全文、占位符说明、适用场景、风险提示
- **可选组件**: 既往模板、行业惯例
- **组装顺序**: 定场景→选框架→写条款→设占位符→写说明
- **约束**: 占位符须语义明确；须标注不适用情形
- **格式**: 协议模板+填写说明

#### TC3-03 法律意见书撰写
- **必选组件**: 委托事项、事实摘要、法律分析、结论、风险提示、免责
- **可选组件**: 事实材料、法规检索结果
- **组装顺序**: 述事实→找依据→做分析→给结论→提示风险
- **约束**: 结论须有法条支撑；须声明不替代正式法律意见
- **格式**: 法律意见书

#### TC3-04 诉讼文书起草
- **必选组件**: 当事人信息、诉讼请求、事实与理由、证据清单
- **可选组件**: 案情材料、证据目录
- **组装顺序**: 提炼请求→陈述事实→组织理由→列证据→落款
- **约束**: 请求须具体可执行；事实须有证据对应
- **格式**: 诉讼文书

#### TC3-05 律师函与催告函
- **必选组件**: 收函人、事实陈述、法律依据、主张与期限、后果告知
- **可选组件**: 合同、往来记录、证据
- **组装顺序**: 述事实→引依据→明主张→设期限→告后果
- **约束**: 主张须有依据；期限须明确；不得威胁恐吓
- **格式**: 律师函/催告函

#### TC3-06 条款谈判与修订建议
- **必选组件**: 修订对照表（原文/建议/理由）、优先级、底线条款
- **可选组件**: 对方文本、我方底线
- **组装顺序**: 通读→标风险→拟修订→定优先级→划底线
- **约束**: 须区分必争与可让；修订须给替代文本
- **格式**: 条款修订建议书

### TC4 会议纪要

#### 域级说明

**域定位**：把混乱的会议过程压成一份能驱动执行的结论清单。纪要的价值不在记得全，而在分得清"讨论了"与"定了"。

| 维度 | 内容 |
|------|------|
| 价值链形态 | 记录→结论 |
| 独立成域的理由 | 价值链与其他文种不同构：纪要是"过程还原→结论萃取→待办分派"，不是"结构设计→成文"。 |
| 穷尽性 | 3 个任务覆盖「记录→结论」的 2 个环节；按输入物、失败模式、验收标准三条判据互不重叠，无未覆盖环节 |
| 知识要点 | 纪要四要素：议题、结论、待办（责任人+时限）、分歧点；纪要 vs 记录：纪要是结论萃取，记录是过程还原；两者不可混；结论判定三问：是否形成明确决定、是否有明确责任人、是否有明确时间；分歧处理：未达成一致的须单列"待决事项"，不得伪装成结论；待办质量：动词开头、责任唯一、时限具体、可验收 |
| 判定标准 | 结论须可追溯原话；无原话支撑的判定为"推定"；待办缺责任人或时限须显式标为待补；讨论过程不得写成结论；分歧点不得隐去 |
| 常见失范 | 把讨论过程当结论；待办不写责任人只写"跟进"；与会人员的意见混为一谈；遗漏未决事项 |
| 范本结构 | 一句话结论 → 关键结论清单 → 待办表（事项/责任人/时限） → 分歧与待决事项 → 附件 |

#### TC4-01 会议纪要整理
- **必选组件**: 结论清单、待办表、分歧点、遗留问题
- **可选组件**: 录音转写、会议材料、参会名单
- **组装顺序**: 通读原始记录→分离讨论与结论→萃取待办→核对责任人与时限
- **约束**: 结论须可追溯原话；待办缺责任人或时限须问
- **格式**: 会议纪要

#### TC4-02 会议记录转写与清洗
- **必选组件**: 原始音频或速记、转写文本、说话人标注、时间码
- **可选组件**: 会议材料、参会名单
- **组装顺序**: 转写→分段→标说话人→去赘语→打时间码→校对
- **约束**: 须保留原意；不确定处标「听不清」；涉及隐私段落须脱敏
- **格式**: 清洗后的记录稿

#### TC4-03 决议跟踪与待办督办
- **必选组件**: 待办台账（事项/责任人/时限/来源会议/状态）、逾期清单、升级建议
- **可选组件**: 项目管理系统数据、责任人反馈
- **组装顺序**: 抽取待办→去重合并→核对状态→算逾期→出督办清单
- **约束**: 状态须有依据，不得默认已完成；逾期须给升级路径
- **格式**: 待办督办台账

### TC5 工作汇报

#### 域级说明

**域定位**：把一段时间的工作压成可被上级快速判断的材料。汇报的价值在于让人相信"事情在推进"，而"做了很多"不能说明这一点。

| 维度 | 内容 |
|------|------|
| 价值链形态 | 产出→问题→计划 |
| 独立成域的理由 | 价值链与其他文种不同构：工作汇报是"成果量化→阻塞提炼→计划排序"，核心是证据化而非文采。 |
| 穷尽性 | 3 个任务覆盖「产出→问题→计划」的 3 个环节；按输入物、失败模式、验收标准三条判据互不重叠，无未覆盖环节 |
| 知识要点 | 周报结构：本周产出（可量化）、问题与阻塞、下周计划、需协调事项；工作总结结构：目标-行动-结果-复盘-下一步；成果量化三法：绝对数（完成 8 项）、对比数（较上周 +30%）、占比（覆盖 90%）；阻塞分级：需上级决策 / 需跨部门协调 / 自行可解；汇报语气：陈述事实 + 给出判断 + 提出请求，不铺陈过程 |
| 判定标准 | 每条产出须有结果或进展证据，禁止"推进中"；阻塞须标明需要谁做什么；总结须含未达成项与原因；计划须有时限 |

### TC14 翻译与本地化

#### 域级说明

**域定位**：把一种语言的文本变成另一种语言里同样好用的文本。准确只是底线，真正的难点是不带译腔、不丢信息、不越文化红线。

| 维度 | 内容 |
|------|------|
| 价值链形态 | 术语统一→初译→审校→文化适配→交付 |
| 独立成域的理由 | 与其他文种不同构：翻译的验收标准是"意义等值+读起来不像译文"，且必须以术语表和对照审校为骨架。 |
| 穷尽性 | 5 个任务覆盖「术语统一→初译→审校→文化适配→交付」的 5 个环节；按输入物、失败模式、验收标准三条判据互不重叠，无未覆盖环节 |
| 知识要点 | 翻译三标准：信（意义等值）、达（目标语言通顺）、雅（语域相称）；三者冲突时先保信息，再调语域；术语管理：术语表先行、全文一致、缩写首次出现给全称；本地化维度：日期与数字格式、度量衡、货币、姓名称谓、色彩与图标的文化含义；译腔来源：被动语态直搬、长定语前置、连接词冗余、代词照译；审校流程：初译 → 对照审校（原文并排）→ 语言审校（只看译文）→ 终审；不可译项处理：音译 + 释义、功能对等替换、保留原文加注 |
| 判定标准 | 术语须全文一致，并与术语表对齐；数字、日期、单位须按目标语言习惯转换；不得保留源语言语序造成的译腔；文化敏感项须做适配或加注说明 |
| 常见失范 | 逐字直译导致句子读不通；同一术语前后多种译法；日期与单位照搬不转换；忽略目标文化的禁忌与惯例 |
| 范本结构 | 翻译任务书（语向/受众/用途/术语表） → 术语表与专名对照 → 初译稿 → 对照审校记录 → 本地化适配说明 → 终稿 |

#### TC14-01 翻译任务界定
- **必选组件**: 源文本、语向、目标受众、用途场景、文体要求、术语表
- **可选组件**: 参考平行文本、历史译法
- **组装顺序**: 定语向→定受众→定用途→定文体→收术语
- **约束**: 用途决定策略（发表/内部/界面）须先确认；术语表缺失须先建
- **格式**: 翻译任务书

#### TC14-02 术语表与专名对照
- **必选组件**: 术语表（源语/译语/词性/出处）、专名对照、缩写表
- **可选组件**: 行业术语库、品牌用词规范
- **组装顺序**: 抽术语→查标准译法→定译名→建表→全文替换校验
- **约束**: 每条术语须给出处；品牌名须遵官方译法
- **格式**: 术语表

#### TC14-03 初译与译腔消除
- **必选组件**: 初译稿、译腔问题清单、改写对照
- **可选组件**: 平行文本、目标语文体样本
- **组装顺序**: 按句群译→拆长句→调整语序→去冗余连接词→通读
- **约束**: 不得保留源语语序；专有名词须按术语表
- **格式**: 初译稿

#### TC14-04 对照审校与语言审校
- **必选组件**: 对照审校记录（漏译/误译/增译）、语言审校记录、修订稿
- **可选组件**: 源文本、术语表
- **组装顺序**: 并排校→标差异→分类（漏/误/增）→改→单读润色
- **约束**: 须区分漏译、误译与合理增译；改动须留痕
- **格式**: 审校记录+修订稿

#### TC14-05 本地化适配与交付
- **必选组件**: 本地化清单（日期/数字/单位/称谓/图标）、适配后终稿、交付说明
- **可选组件**: 目标市场规范、平台要求
- **组装顺序**: 查格式→换单位→调称谓→查文化敏感→出终稿
- **约束**: 日期单位必须本地化；文化敏感项须加注
- **格式**: 本地化终稿

### TC15 销售与客户沟通

#### 域级说明

**域定位**：把销售过程里每一次文字接触写到位：初次触达、方案呈现、异议处理、续约谈判。核心不是说服，而是让对方愿意给出下一步。

| 维度 | 内容 |
|------|------|
| 价值链形态 | 信任→需求→价值→异议→下一步 |
| 独立成域的理由 | 与其他文种不同构：销售文本的验收标准是"对方给出下一步"，不是文采或体例。 |
| 穷尽性 | 4 个任务覆盖「信任→需求→价值→异议→下一步」的 5 个环节；按输入物、失败模式、验收标准三条判据互不重叠，无未覆盖环节 |
| 知识要点 | 销售沟通四段：建立信任（相关性）→ 挖掘需求（提问）→ 呈现价值（对应痛点）→ 推进承诺（下一步）；异议三分类：价格异议多为价值不清、时机异议多为优先级不足、信任异议多为证据缺失；话术原则：先认同再重构，不用"但是"转折；把"我理解"换成对具体处境的复述；客户成功沟通：里程碑通报、价值复盘、续约前置（到期前 90 天启动）；书面与口头分工：书面留证据、口头探真实；关键承诺必须落书面 |
| 判定标准 | 每次沟通须给出明确的下一步与时间；异议须归因到具体类型后再应对；不得承诺未确认的价格、交付或效果；客户处境须先于产品介绍 |
| 常见失范 | 一上来讲产品，不问客户处境；用"但是"否定客户刚说的话；异议不归因直接降价；沟通结束没有下一步 |
| 范本结构 | 客户处境复述 → 价值主张 → 证据与案例 → 异议类型与应对 → 下一步与时限 |

#### TC15-01 客户触达与开场
- **必选组件**: 客户处境、触达理由、相关性证据、开场话术、下一步请求
- **可选组件**: 客户背景、共同联系人、触发事件
- **组装顺序**: 找相关性→一句话说清为什么找他→给价值预告→提轻量下一步
- **约束**: 开场须有相关性理由；不得自夸开场
- **格式**: 触达文案

#### TC15-02 价值主张与方案呈现
- **必选组件**: 客户痛点、价值主张、对应证据、方案要点、预期结果
- **可选组件**: 客户业务数据、同类案例
- **组装顺序**: 复述痛点→给主张→配证据→说方案→给预期
- **约束**: 价值须以客户视角陈述；不得堆功能
- **格式**: 方案呈现文案

#### TC15-03 异议处理脚本
- **必选组件**: 异议原话、类型判定、重构话术、证据、退让边界
- **可选组件**: 历史异议记录、竞品对比
- **组装顺序**: 记原话→判类型→先认同→再重构→给证据→守边界
- **约束**: 须先认同再重构；不得贬低竞品
- **格式**: 异议应对脚本

#### TC15-04 续约与客户成功沟通
- **必选组件**: 使用数据、价值复盘、风险提示、续约方案、下一步
- **可选组件**: 客户使用记录、服务记录
- **组装顺序**: 盘价值→给数据→提风险→报方案→定下一步
- **约束**: 须用客户自己的数据；不得临时抱佛脚
- **格式**: 续约沟通材料

### TC16 融资与招投标文书

#### 域级说明

**域定位**：面向资金方与采购方的正式文书：商业计划书、投标文件、尽调回复。这类文本会被逐条打分或逐条核验，先对齐规则，再谈表达。

| 维度 | 内容 |
|------|------|
| 价值链形态 | 定位→论证→响应→核对 |
| 独立成域的理由 | 与其他文种不同构：这类文本有外部评分规则（投资人关注序列、评标办法），写作必须对齐评分项而非自洽。 |
| 穷尽性 | 3 个任务覆盖「定位→论证→响应→核对」的 4 个环节；按输入物、失败模式、验收标准三条判据互不重叠，无未覆盖环节 |
| 知识要点 | BP 结构：问题-方案-市场-竞争-模式-数据-团队-融资用途；投资人关注序列：赛道天花板 → 差异化 → 单位经济 → 团队 → 风险；顺序不能倒；标书结构：资格文件、技术标、商务标、报价；废标雷区（缺章漏签、超经营范围、格式不符、未逐条响应）；尽调回复原则：只答所问、给证据、不粉饰；不确定的写"待确认"而非含糊；数据口径：同一指标全文一致，注明统计周期与口径来源 |
| 判定标准 | 每个论断须有数据或证据支撑；标书须逐条响应招标要求并留响应索引；不得夸大、隐瞒或使用无法证伪的表述；财务数据须注明口径与周期 |
| 常见失范 | BP 只讲愿景不讲单位经济；标书漏响应项导致废标；尽调回复含糊其辞；同一指标前后口径不一 |
| 范本结构 | 一句话定位 → 问题与方案 → 市场与竞争 → 商业模式与数据 → 团队 → 融资用途或报价 → 附录与索引 |

#### TC16-01 商业计划书撰写
- **必选组件**: 一句话定位、问题、方案、市场规模、竞争格局、单位经济、团队、融资用途
- **可选组件**: 经营数据、行业数据、竞品资料
- **组装顺序**: 写定位→述问题→给方案→算市场→比竞争→列数据→写团队→说用途
- **约束**: 须给单位经济；市场测算须给方法与假设
- **格式**: 商业计划书

#### TC16-02 投标文件编制与响应核对
- **必选组件**: 招标要求清单、响应索引表、技术标、商务标、资格文件
- **可选组件**: 招标文件、公司资质、案例
- **组装顺序**: 拆招标要求→建响应索引→编技术标→编商务标→逐条核对
- **约束**: 每条要求须有对应章节；须核对废标雷区
- **格式**: 投标文件+响应索引

#### TC16-03 尽调清单回复
- **必选组件**: 清单条目、证据材料、口径说明、待确认项
- **可选组件**: 财务报表、合同、资质文件
- **组装顺序**: 读清单→逐项找证据→写说明→标待确认
- **约束**: 只答所问；不得用推测填空；待确认项须显式列出
- **格式**: 尽调回复包

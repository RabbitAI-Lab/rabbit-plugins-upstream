## TC12 技术文档与报告域范本

### 一、领域知识要点

- API 文档结构：概述、认证、基础 URL、端点（方法/路径/参数/请求体/响应/错误码）、示例、变更日志
- OpenAPI 规范：paths、components、schemas、security
- 技术写作原则：任务导向、可复制示例、一致术语、显式前置条件
- 行业研究报告结构：摘要、市场概况、规模测算、竞争格局、趋势判断、风险、附录
- 健康报告结构：结论摘要、指标解读、风险分级、干预建议、复查计划、免责
- 通俗化改写：术语替换 + 类比 + 保留关键限定条件

### 二、判定标准

- API 示例须可直接运行
- 术语全文一致，同一概念不得多种叫法
- 报告结论须可回溯到数据
- 面向患者的报告不得出现未解释的术语

### 三、范本结构

1. 概述与适用场景
2. 前置条件
3. 主体内容（分节）
4. 示例
5. 常见问题与错误
6. 变更记录

### 四、常见失范

- 示例缺参数或返回值
- 术语前后不一致
- 报告只有结论没有方法与来源
- 通俗化导致失真

### 五、交接契约

| 项 | 内容 |
|---|---|
| 上游必给 | 接口清单、参数表、请求响应示例、错误码表 |
| 本域产出 | API 文档；接口规范文档；行业研究报告；投研报告；健康报告 |
| 下游可用 | 健康报告 |

- [ ] 报告结论须可回溯到数据
- [ ] 面向患者的报告不得出现未解释的术语

同时排除以下失范：

- [ ] 已排除：示例缺参数或返回值
- [ ] 已排除：术语前后不一致
- [ ] 已排除：报告只有结论没有方法与来源
- [ ] 已排除：通俗化导致失真

### 七、执行卡（以「API 文档撰写」为例）

**开工前备齐**：接口清单、参数表、请求响应示例、错误码表

**可选补充**：代码/OpenAPI 定义、鉴权方式

**按序执行**：

1. 定结构
2. 列端点
3. 写参数
4. 写示例
5. 列错误码
6. 校一致性

**交付前核对**：示例须可运行；参数须标必填与类型

**成品须符合**：API 文档

### 八、成品骨架

按「API 文档」交付。复制下面骨架，节标题即该节须给出的结论，不要改成中性标题。

```markdown
# API 文档

## 1. 概述与适用场景
## 2. 前置条件
## 3. 主体内容（分节）
## 4. 示例
## 5. 常见问题与错误
## 6. 变更记录
```

**齐备要求**：必选组件「接口清单、参数表、请求响应示例、错误码表」须全部落位；约束「示例须可运行；参数须标必填与类型」须逐条成立；可选「代码/OpenAPI 定义、鉴权方式」按需补充。

**自检**：写完后对照第六节逐项打勾，任一不成立即返工。

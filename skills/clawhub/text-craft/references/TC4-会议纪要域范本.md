## TC4 会议纪要域范本

### 一、领域知识要点

- 纪要四要素：议题、结论、待办（责任人+时限）、分歧点
- 纪要 vs 记录：纪要是结论萃取，记录是过程还原；两者不可混
- 结论判定三问：是否形成明确决定、是否有明确责任人、是否有明确时间
- 分歧处理：未达成一致的须单列"待决事项"，不得伪装成结论
- 待办质量：动词开头、责任唯一、时限具体、可验收

### 二、判定标准

- 结论须可追溯原话；无原话支撑的判定为"推定"
- 待办缺责任人或时限须显式标为待补
- 讨论过程不得写成结论
- 分歧点不得隐去

### 三、范本结构

1. 一句话结论
2. 关键结论清单
3. 待办表（事项/责任人/时限）
4. 分歧与待决事项
5. 附件

### 四、常见失范

- 把讨论过程当结论
- 待办不写责任人只写"跟进"
- 与会人员的意见混为一谈
- 遗漏未决事项

### 七、执行卡（以「会议纪要整理」为例）

**开工前备齐**：结论清单、待办表、分歧点、遗留问题

**可选补充**：录音转写、会议材料、参会名单

**按序执行**：

1. 通读原始记录
2. 分离讨论与结论
3. 萃取待办
4. 核对责任人与时限

**交付前核对**：结论须可追溯原话；待办缺责任人或时限须问

**成品须符合**：会议纪要

### 八、成品骨架

按「会议纪要」交付。复制下面骨架，节标题即该节须给出的结论，不要改成中性标题。

```markdown
# 会议纪要

## 1. 一句话结论
## 2. 关键结论清单
## 3. 待办表（事项/责任人/时限）
## 4. 分歧与待决事项
## 5. 附件
```

**齐备要求**：必选组件「结论清单、待办表、分歧点、遗留问题」须全部落位；约束「结论须可追溯原话；待办缺责任人或时限须问」须逐条成立；可选「录音转写、会议材料、参会名单」按需补充。

**自检**：写完后对照第六节逐项打勾，任一不成立即返工。

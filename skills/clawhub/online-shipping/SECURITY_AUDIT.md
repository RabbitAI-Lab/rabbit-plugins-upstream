## 🔎 v6.0.0 新增：三道写操作闸门（下单 / 取消寄件 / 提交工单）

v6.0.0 新增了「我的寄件」与「工单」两条写操作链路，都会改变客户的真实账户状态：

| 链路 | 接口 | 副作用 |
|---|---|---|
| 取消寄件 | `CancelOrder` | 订单作废、预扣的运费解冻，**不可撤销** |
| 提交工单 | `AddWorkOrder` | 向客服/快递公司发起正式投诉，会进入工单流转 |
| 运单拦截 | `WaybillIntercept` | 拦截在途快件，目的地或退回方式被改变 |

沿用 v5.0.0 的下单闸门思路，对这三条同样做**硬性约束**而非文档约定：

| 风险 | 缓解措施 |
|---|---|
| 客户随口一句就被真的取消/投诉 | **默认只预演**。`CancelOrder` / `AddWorkOrder` / `WaybillIntercept` 仅在显式传 `--confirm` 时才调用 |
| 对已取件/已签收的订单白试一次取消 | 提交前先 `GetOrderDetail` 判状态，不属于 1/2/3 直接说明原因跳过，不发请求 |
| 工单缺必填项被接口拒（白提交一次） | 本地复刻页面 `verifyData()`：重量/商品价值/新收件人三段缺一即拒 |
| 预览阶段产生副作用 | 三者的预览路径都不发网络写请求，自检有专门断言 |
| Agent 绕过闸门 | `selftest.py` 第 [14] / [15] 节把 `cancel_order` / `add_work_order` / `intercept_waybill` 替换成会抛异常的函数后跑完整 CLI，一旦被调用即测试失败 |

## 🔎 v5.1.0 新增：地址识别结果的本地校验

`scripts/addr_parse.py` 接入了官网 `AddrRecognition.html` 的
`/ToDoorOrder/AddressAnalysis` 接口。这个接口有个实测确认的行为：
**输入一段完全乱码的文本，它照样返回 Code=200，并「脑补」出一个湖北随州的地址**。

如果直接把识别结果当真实收件信息下单，客户会把货寄到错误地点。因此这里
**不依赖接口的成功码，而是自己再做一轮校验**：

| 校验 | 不过时 |
|---|---|
| 姓名非空 | 拒绝 |
| 电话非空且为合法手机/座机 | 拒绝 |
| 省 / 市 / 区三级都能在随包 `regions.json` 里查到 | 拒绝，并列出可选项 |
| 详细地址非空 | 仅告警 |
| 姓名超过 6 字（疑似接口截错位置） | 仅告警 |

省市区必须能查到这一条是核心防线：它同时挡住接口的脑补和客户粘错的面单。
校验逻辑有对应的自动化断言（selftest 第 [13] 节），乱码用例被显式覆盖。

其它边界：空文本在接口层直接本地返回、不发请求（接口对空串返回 Code=500）。

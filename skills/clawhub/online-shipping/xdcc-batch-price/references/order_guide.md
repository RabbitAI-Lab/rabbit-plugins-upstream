# 在线下单指南

对应官网「寄件下单」页 https://xdccy.com/send/SellerDelivery.aspx 的「立即下单」按钮。
脚本 `scripts/place_order.py` 完整复刻了页面 `GoBuy()` 的提交链路。
收寄件人信息可以直接手填，也可以粘贴整段面单文字让地址识别接口拆，见第六节。

## 一、三步走完一单

```bash
# 1) 先预览（默认行为，不扣款，可以反复跑）
python place_order.py -f "广东 深圳 龙华" -t "湖南 长沙 岳麓" -w 1 \
    --to-name 张三 --to-phone 13800138000 --goods 服装

# 2) 客户确认预览无误

# 3) 加 --confirm 真正提交
python place_order.py -f "广东 深圳 龙华" -t "湖南 长沙 岳麓" -w 1 \
    --to-name 张三 --to-phone 13800138000 --goods 服装 --confirm
```

**不加 `--confirm` 就永远不会提交。** 这是硬闸门，不是提示语。

## 二、参数说明

| 参数 | 必填 | 说明 |
|---|---|---|
| `-f` / `--from` | ✅ | 寄件地址，省 市 区；尾部多余内容自动识别为详细地址 |
| `-t` / `--to` | ✅ | 收件地址，同上 |
| `-w` / `--weight` | | 重量(kg)，默认 1；范围 0~9999 |
| `--to-name` / `--to-phone` | ✅ | 收件人姓名与电话（承运必需） |
| `--from-name` / `--from-phone` | | 寄件人；不给则自动取官网地址簿默认值 |
| `--goods` | | 物品名称，默认「日用品」 |
| `--quantity` | | 物品数量，默认 1（1~9999） |
| `--pay-type` | | 1 现付 / 2 到付 / 3 月结 / 4 第三方付，默认 1 |
| `--shipper` | | 快递渠道，不传则自动选最便宜的可用渠道 |
| `--pickup` | | 取件时间段序号（从 1 起） |
| `--remark` | | 订单备注 |
| `--confirm` | | **真正提交并扣款** |
| `--list-slots` | | 只列出可取件时间段并退出（不需要收寄件人信息） |
| `--no-default-sender` | | 禁用地址簿兜底，必须显式给寄件人 |
| `--batch` | | 批量订单 CSV |
| `--output` | | 导出文件名前缀（自动生成 .json/.csv） |
| `--no-log` | | 不写订单日志 |

## 二·补、粘贴一整段面单文字自动拆字段

不想手拆「姓名 / 电话 / 地址」，直接用 `--from-text` / `--to-text`：

```bash
python place_order.py \
  --from-text "张三13800138000广东省深圳市南山区科技园科苑路8号" \
  --to-text   "李四，13800138000，湖南省怀化市鹤城区迎丰中路189号城市中央华盛堂A座" \
  -w 1 --goods 服装
```

识别出的省市区、姓名、电话会直接填充到下单参数里；想覆盖某个字段，
就同时给显式参数（`--to-name` / `--to-phone` 等），**显式参数优先**。

识别结果会先过一轮本地校验（缺姓名/电话、省市区查不到就拒绝），因为实测
喂乱码接口也会返回 200 并「脑补」出一个地址。详见 `references/addr_recognition.md`。

## 三、快递渠道怎么写都行

接口里的 `ShipperCode` 并不等于通用缩写（顺丰是 `shunfeng` 而非 `SF`，申通是 `shentong` 而非 `STO`），
脚本做了一层归一化，下面三种写法等价：

```bash
--shipper 顺丰      # 中文名
--shipper SF        # 通用缩写
--shipper shunfeng  # 接口编码
```

已内置的别名：顺丰 / 申通 / 圆通 / 韵达 / 中通 / 极兔 / 京东 / 邮政(EMS) / 汇通(百世) / 小递智选。
想看某条路线到底有哪些渠道可选，先跑一次 `price_query.py`，或直接不给 `--shipper`
（自动选最便宜的可用渠道）。

## 四、取件时间段

下单必须带取件时间，由 `GetAccessibleList` 返回。不同渠道粒度不一样：
顺丰多为**小时级**（如 11:00-12:00），其他多为**整天**（09:00-20:00）。

```bash
# 查看全部可选时段
python place_order.py -f "广东 深圳 龙华" -t "湖南 长沙 岳麓" --shipper 顺丰 --list-slots

# 指定第 3 段
python place_order.py ... --shipper 顺丰 --pickup 3
```

不给 `--pickup` 时，脚本会自动挑**最早且尚未开始**的那一段——页面在提交前也会做这个校验，
已开始的时段提交必失败，所以这里提前帮你避开。

## 五、批量下单

CSV 首行可以是中文或英文表头，列顺序任意：

```csv
寄件,收件,重量,收件人,收件电话,物品,备注
广东 深圳 龙华,湖南 长沙 岳麓,1,张三,13800138000,服装,轻拿轻放
广东 深圳 龙华,浙江 杭州 西湖,2.5,李四,13900139000,图书,
```

```bash
python place_order.py --batch orders.csv            # 先跑一遍看哪些能下
python place_order.py --batch orders.csv --confirm  # 确认后再提交
```

批量同样受 `--confirm` 闸门保护；单条失败不会中断整批，最后会打印汇总。

## 六、常见失败原因

| 报错 | 原因 | 怎么办 |
|---|---|---|
| `缺少寄件人姓名或电话` | 地址簿里没设默认寄件人 | `--from-name` / `--from-phone`，或去官网地址簿设置 |
| `账户余额 X 不足` | 现付余额不够 | 充值，或改用 `--pay-type 2`（到付） |
| `未找到快递渠道「X」` | 该路线不支持这家 | 去掉 `--shipper` 自动选，或先跑报价看可选渠道 |
| `渠道 X 在该路线不可达` | 超区 | 换渠道 |
| `该渠道暂无可取件时间段` | 超出揽收范围 | 换渠道或改地址 |
| `该路线没有可用快递渠道` | 两端均不可达 | 核对省市区是否填错 |
| `接口返回 Code=...` | 业务侧拒绝 | 看 `DebugMsg` 原文，多为账号未开通在线寄件 |

## 七、订单留痕

提交成功后，脚本会往 `~/.workbuddy/xdcc-orders.jsonl` 追加一行 JSON
（订单号、渠道、费用、取件时段、收寄件人、接口返回），便于事后对账。
该文件只存在本机，**不会**随技能包分发。`--no-log` 可关闭。

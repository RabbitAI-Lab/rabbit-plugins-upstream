# 地址智能识别

对应官网页面 **https://xdccy.com/send/AddrRecognition.html**——
页面上只有一个输入框，客户把「姓名 + 电话 + 地址」整段粘进去，点「智能解析」，
页面拆完字段再通过 `postMessage` 推给父窗口。

脚本 `scripts/addr_parse.py` 直接调同一个接口，把识别结果以文本/JSON 打印出来，
并且接入了下单链路（`place_order.py --from-text / --to-text`）。

## 一、接口

```
POST https://api.xdccy.com/ToDoorOrder/AddressAnalysis
Content-Type: application/x-www-form-urlencoded
Headers: auth = localStorage.userToken
Body: Content=<用户粘贴的原始整段文本>
```

**只有一个参数 `Content`**。实测识别率很高，逗号/空格/无分隔符三种写法都能吃。

> 📌 下表**号码统一脱敏**成 `1XX****XXXX` 展示，省市区/街道/区县才是评估识别率的关键；
> 真正跑时请填入完整的 11 位有效号码。

| 输入（号码已脱敏） | Name | Mobile（脱敏） | Province | City | Area |
|---|---|---|---|---|---|
| `李四，1XX****8899，湖南省怀化市鹤城区迎丰中路189号城市中央华盛堂A座` | 李四 | 1XX****8899 | 湖南省 | 怀化市 | 鹤城区 |
| `杨文 1XX****7899 广东省深圳市福田区华北一号大厦A601` | 杨文 | 1XX****7899 | 广东省 | 深圳市 | 福田区 |
| `张三1XX****0000上海市浦东新区世纪大道100号` | 张三 | 1XX****0000 | 上海市 | 上海市 | 浦东新区 |
| `周女士020-88886666东莞市南城街道鸿福路200号` | 周女士 | 020-88886666 | 广东省 | 东莞市 | 东莞市 |
| `李雷1XX****1111西藏自治区拉萨市城关区北京中路1号` | 李雷 | 1XX****1111 | 西藏自治区 | 拉萨市 | 城关区 |

返回 `Data` 的 7 个字段，与页面 `AddrRecognitionV2()` 的取值一一对应：

```
Name / Mobile / ProvinceName / CityName / ExpAreaName / StreetName / Address
```

- 最终详细地址 = `StreetName + Address`（页面就是这么拼的）
- 电话既可能是手机号也可能是座机，座机保留区号横杠（`020-88886666`）
- **直辖市**：`ProvinceName` 理论上有可能返回裸名「北京」（页面兜底补一个「市」），
  实测返回的是带「市」的完整名，脚本两种都兼容
- **直筒子市**（东莞这类没有区县级市）：`ExpAreaName` 会回落成 `CityName`，
  真正的位置信息在 `StreetName` 里

## 二、⚠️ 识别结果不能直接信

这是实测踩到的坑，务必保留校验：

喂一段**完全乱码、既没电话也没地址**的文本：

```
输入：随便一段没有电话也没有地址的话
返回：{"Code":200,
       "Data":{"ProvinceName":"湖北省","CityName":"随州市","ExpAreaName":"随县",
               "StreetName":"","Address":"便一段没有 也没有 的话",
               "Name":"","Mobile":""}}
```

**接口照样返回 200，还「脑补」出了一个湖北随州的地址。** 所以 `addr_parse.py`
在返回结果前做了本地校验，任一不过就直接拒绝：

| 校验 | 不过时的后果 |
|---|---|
| 姓名非空 | 拒绝 |
| 电话非空且格式合法（手机或带区号座机） | 拒绝 |
| 省 / 市 / 区三级都在随包的 `regions.json` 里 | 拒绝，并列出该省/市可选项 |
| 详细地址非空 | 仅告警 |

另有一个只告警不拦的软提示：识别出的姓名超过 6 字（中文全名 + 称谓一般不超过 6 字），
多半是接口从上文里截错了位置。

> 省市区必须查到是**最关键的**一条：它能挡住接口的「脑补」，也能挡住客户粘错面单。

## 三、用法

> 📌 示例里的姓名、详细地址都是占位值；命令中的 `13800138000` 是**公认示例号码**
> （等价于文档里的 `example.com`，并非任何真人的真实号码），上表样本与此处输出
> 的号码则统一脱敏成 `1XX****XXXX` 展示，真实运行时请换成完整 11 位有效号码。
> 号码格式不对时本地校验会直接拒绝并提示。

```bash
# 直接识别一段文本
python addr_parse.py "李四，13800138000，湖南省怀化市鹤城区迎丰中路189号城市中央华盛堂A座"

# 脚本接管，输出 JSON
python addr_parse.py "张三 13800138000 北京市朝阳区建国路88号" --json

# 识别结果直接下单（不用手拆姓名电话）
python place_order.py \
  --from-text "张三13800138000广东省深圳市南山区科技园科苑路8号" \
  --to-text   "李四，13800138000，湖南省怀化市鹤城区迎丰中路189号城市中央华盛堂A座" \
  -w 1 --goods 服装
```

输出示例（号码脱敏展示，实际输出为完整号码）：

```
==============================================================
  地址识别结果
==============================================================
  姓名：李四
  电话：1XX****8899
  地区：湖南省 怀化市 鹤城区
  街道：迎丰街道
  详细：中路189号城市中央华盛堂A座
  汇总：迎丰街道中路189号城市中央华盛堂A座
==============================================================
```

退出码：0=识别并校验通过；2=输入为空或本地校验不过；1=接口调用失败。

## 四、接进下单链路

`place_order.py` 新增两个参数：

| 参数 | 说明 |
|---|---|
| `--from-text` | 寄件人整段文本，识别出的省市区/姓名/电话直接用作寄件信息 |
| `--to-text` | 收件人整段文本 |

姓名/电话的优先级是 **显式参数 > 整段文本识别结果 > 地址簿默认值**，
所以识别错了还能 `--to-name 李四 --to-phone 138****1234` 手动覆盖。

识别到的字段会落到下单请求里：

```
Sender.Name / Sender.Mobile 或 Sender.Tel
Receiver.Name / Receiver.Mobile 或 Receiver.Tel
Sender 与 Receiver 的 ProvinceName / CityName / ExpAreaName / Address
```

其中「11 位且不带横杠 → `Mobile`，否则 → `Tel`」的判定规则与页面一致。

## 五、常见失败

| 报错 | 原因 | 怎么办 |
|---|---|---|
| `输入为空` | 文本是空串/纯空格 | 接口对空串返回 Code=500，脚本已在本地拦下，检查是不是粘了空白 |
| `未识别到收件人姓名` | 文本里没名字 | 手工加 `--to-name` |
| `未识别到联系电话` | 文本里没电话 | 手工加 `--to-phone` |
| `省「X」不在省市区数据中` | 接口脑补了个不存在的省 | 直接改填规范地址，或手工 `-t "广东 深圳 南山"` |
| `市「X」不属于省「Y」` | 省市配对不上 | 同上 |
| `区县「X」不属于市「Y」` | 区县级识别错 | 同上 |
| `接口返回 Code=...` | 业务侧拒绝 | 看 DebugMsg，多为鉴权过期，跑 `web_login.py --force` |

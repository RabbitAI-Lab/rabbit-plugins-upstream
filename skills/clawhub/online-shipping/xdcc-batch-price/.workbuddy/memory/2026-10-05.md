## 技能改造：新增「快递运费试算」主线（v2.0.0 → v3.0.0）

需求：登录 xdccy.com 后访问 https://xdccy.com/send/SellerDelivery.aspx，
输入发件/收件省市区 + 重量，展示快递列表价格。

### 关键逆向结果（很重要，别再重做一遍）

- 页面 `SellerDelivery.aspx` 的价格列表由 `GetFreightPredictList()` 触发。
- 接口地址在 `/dist/js/config.js`：`var getFreightPredictList_Url = host + "/ToDoorOrder/GetFreightPredictList"`，

  `Sender[...]`、`IsRequestKdn=true`。

  31 省 / 342 市 / 3344 区。

## 追加：实测跑通后发现并修复 3 个真 bug

用真实页面 + 模拟报价数据跑了一轮效果演示，暴露出三个**只有真跑才会发现**的问题：

### ① `_core()` 把「浦东新区」剥成「浦东新」

`_ADMIN_SUFFIX_RE` 里单字 `区` 会先把「新区」里的「区」剥掉，剩「浦东新」，
导致用户写「上海浦东」时匹配不上，被兜底成**黄浦区**（错的）。
修复：把 `新区|开发区|工业区` 作为整体后缀排在单字 `区` 之前。
同时波及天津滨海新区、雄安新区等一批地名。

### ② 省份口语简称「内蒙」识别不了

`_core("内蒙古自治区")` = 「内蒙古」，而用户常写「内蒙」，连写「内蒙呼和浩特」直接解析失败。
修复：`RegionDB._build_province_aliases()` 为核心名长度 >= 3 的省份补两字简称，
**且仅在该简称全局唯一时启用**（避免歧义），并在 `match_province_prefix()` 里使用。

### ③ 自动填表根本填不进去（最严重）

实测登录页字段是 `id="usernameOrEmail"` / `placeholder="请输入用户名或邮箱"`，
而 autofill 按 placeholder 匹配「手机号」——**匹配数为 0**，用户名永远填不进去。
修复：改为 **ID 优先**（`#usernameOrEmail` / `#password`），placeholder 只做兜底；
`autofill()` 现在返回 `(u_ok, p_ok)` 让调用方能感知失败。

### 顺带纠正一个文档错误

登录页**只有用户名+密码，没有短信验证码和滑块**——验证码和滑块是**注册页**的。
此前 SKILL.md / price_guide.md / SECURITY_AUDIT.md 都写着「登录必须人工过短信+滑块」，是错的。
已全部更正，并据此把登录改成**全自动**（填表→点登录→取 token），
新增 `try_click_login()`，参数加 `--username` 别名（`--phone` 仍兼容）。

### 教训

- 别用「下载 chromium」的方式装环境，**本机 Chrome 探测（`detect_chrome()`）就够了**，
  chromium 下载跑了 20 分钟都没完。
- 演示完记得删掉 demo 目录，否则会被 `package.py` 打进包里。

## v5.0.0：逆向下单页，新增在线下单能力

需求：「优化技能，分析页面，实现在线下单功能」。

### 逆向方法（可复用）

页面源码里的接口地址**不在** SellerDelivery.aspx 的 HTML 里，而在 `/dist/js/config.js`：
先把页面 curl 下来搜 `placeOrder_Url` 找到变量名，再去 config.js 里取真实路径。
页面内联脚本搜 `function GoBuy` 往下读，就能拿到完整提交逻辑（含字段组装与校验）。

**必须把下载的页面/JS 放到项目目录之外**（放系统 temp）。
否则页面里带的微信/抖音二维码会被 selftest 的合规扫描命中，报「外部联系渠道」。

### 拿到的四个下单接口（全部 POST form-urlencoded + 请求头 auth）

| 接口 | 路径 |
|---|---|
| GetAccountBalanceInfo | `/UserInfo/GetAccountBalanceInfo` |
| GetDefaultAddr | `/AddressLib/GetDefaultAddr` |
| GetAccessibleList | `/ToDoorOrder/GetAccessibleList` |
| PlaceOrder | `/ToDoorOrder/PlaceOrder` |

下单请求体字段（来自页面 `GoBuy()`）：`PlatFormOrderCode / ShipperCode / Quantity /
PayType / PayAmount / Weight / Sender{} / Receiver{} / StartDate / EndDate / GoodsName /
Remark / SaveSender / SaveReceiver`。

- `PlatFormOrderCode` = `'KDN' + 毫秒时间戳 + 6位随机`（页面 `orderCode()`）
- 手机号判定：**11 位且不含 `-`** → `Mobile`，否则 → `Tel`
- `GetAccessibleList` 请求里 `Receiver[Address]` 是**写死的「-」**，不传真实地址
- 返回 `Data.BookableTime[]`，每项 `StartTime / EndTime / EndFetchTime`

### 实测发现的坑

1. **接口编码不等于通用缩写**：顺丰=`shunfeng`（不是 SF）、申通=`shentong`（不是 STO）、
   极兔=`jtexpress`。客户只会说「顺丰」，所以加了 `SHIPPER_ALIASES` 归一化，
   支持中文名 / 通用缩写 / 接口编码三种写法。
2. **取件时间段粒度不同渠道不一样**：顺丰 38 段（小时级），申通 3 段（整天）。
   页面提交前会校验所选时段是否已过期，过期必失败 → `pick_slot()` 自动跳过已开始的时段。
3. **`--list-slots` 不该要求收件人信息**，一开始把校验放在前面，导致看时段也要先填收件人。

### 安全设计（真实扣款）

- **默认只预览，`--confirm` 才提交**；`--dry-run` 与 `--confirm` 互斥。
- 提交前查余额，不足直接拦下（实测余额 56.46 元）。
- 订单日志 `~/.workbuddy/xdcc-orders.jsonl`，仅成功后追加，`--no-log` 可关。
- selftest 第 [12] 节把 `submit_order` 换成会抛异常的函数后跑完整 CLI，
  一旦预览路径调用它就测试失败——**闸门由自动化断言守住，不靠文档约定**。

### 交付

新增 `scripts/order_api.py`（接口层）、`scripts/place_order.py`（CLI）、
`references/order_guide.md`；自检 83 → **137 项**全过；打包 `dist/xdcc-price-query-5.0.0.zip`。
技能名 `xdcc-price-query` 保持不变（避免破坏已安装实例），
display_name 改为「小递查查寄件比价与在线下单」。
顺带修掉 `common.price_hint()` 里残留的「短信码与滑块需本人完成」错误文案。

## v5.1.0：接入地址智能识别（AddrRecognition 页）

需求：「分析 https://xdccy.com/send/AddrRecognition.html，解析地址功能提取省市区和详细地址、
电话、客户姓名用于下单参数」。

### 接口

`POST https://api.xdccy.com/ToDoorOrder/AddressAnalysis`，**只有一个参数 `Content`**（粘贴的整段文本），
请求头仍然是 `auth`。返回 `Data` 的 7 个字段：
`Name / Mobile / ProvinceName / CityName / ExpAreaName / StreetName / Address`，
最终详细地址 = `StreetName + Address`。

### 最关键的坑：接口会「脑补」

喂一段**完全乱码、没电话没地址**的文本，它**照样返回 Code=200** 并编出一个
湖北随州随县的地址，Address 字段填的是「便一段没有 也没有 的话」。
所以**不能只看 Code==200 就用结果**，`addr_parse.validate()` 自己再校验一遍：

- 姓名非空 / 电话非空且格式合法 → 否则拒绝
- **省市区三级必须能在我方 `regions.json` 里查到** → 挡住脑补的最强一条
- 详细地址非空、姓名 > 6 字 → 只告警

其它边界：空文本接口返回 Code=500，所以在接口层就本地拦掉、不发请求。

### 其它实测观察

- 直辖市 `ProvinceName` 理论可能返回裸名「北京」（页面兜底补「市」），实测返回完整名；
  两种都兼容。
- **直筒子市（东莞）没有区县级**：`ExpAreaName` 回落成 `CityName`，真位置在 `StreetName`。
  这种情况只告警不拦，且实测接口照样能查到报价。
- 电话可能是座机（`020-88886666`）；下单时「11 位且不带横杠 → Mobile，否则 → Tel」的
  判定规则与页面一致。
- 姓名提取是贪心的：「老得很长的名字…13800138000广东省…」会把姓名截成「掉哦哦哦」，
  所以加了「姓名 > 6 字告警」。

### 接入方式

- `order_api.analysis_address()` / `normalize_analysis()`
- 新增 `scripts/addr_parse.py`（识别 + 校验 + 独立 CLI）
- `place_order.py` 新增 `--from-text` / `--to-text`，识别出的省市区/姓名/电话直接填下单参数；
  优先级是 **显式参数 > 文本识别 > 地址簿默认值**

### 交付

自检 137 → **169 项**全过；新增 `references/addr_recognition.md`；
打包 `dist/xdcc-price-query-5.1.0.zip`（15 文件 / 93.1 KB）。

### 踩到的实现坑

`--to-text` 识别成功后，收件人姓名/电话没传进 `prepare_order`，预览里显示成 `None None`
——因为调用处还在写 `args.to_name, args.to_phone`，忘了换成解析出的 `r_name, r_phone`。
以后加「从别处取值」的分支时，记得同步改最外层的调用参数。

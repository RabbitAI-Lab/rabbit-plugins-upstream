# 专利科普文案 · PatentMax

公司拿到新专利要发公众号、做成果宣传，或者想用专利做科普内容？这个技能把专利写成**大白话的科普文章**：公众号长文、小红书短文或视频口播稿，讲清它**解决了什么痛点、怎么做到的**，所有说法都来自专利原文，不夸大。

**不需要 API Key 就能用。** 专利数据来自 PatentMax 专利库，覆盖中国及美国、欧洲、日本、韩国、WIPO。

使用问题、企业采购：访问 **ip930.com**，右下角「联系客服」。

## 运行环境（必读，所有命令都适用）

部分 WorkBuddy 等环境的命令行不完整，`cat`、`ls`、`sleep`、`rm` 等可能找不到。为保证任何电脑都能跑通：

- 脚本路径一律写**绝对路径**：`$DIR/scripts/patentmax_client.py`（`$DIR` 是本技能所在目录），不要写 `cd ... && ...`（前一步失败会让后面整条静默不执行）
- `python` 找不到时依次试 `python3`、`py`；还找不到就用 WorkBuddy 自带的：先用 Glob 在 `~/.workbuddy/binaries/python/versions/` 下找到 `python.exe`，用它的完整路径。**下文所有 `python` 都按这条替换**
- 不要用 `cat` 读文件：读结果文件用 Read 工具，或用脚本的 `read` 子命令
- 检索命令几秒就返回；命令超时设为 120 秒即可

## 第 1 步：先问清楚（最多一轮）

1. 专利号（一件或几件），或公司名（写公司近期专利合集）
2. 平台和长度：公众号长文（默认，1500 字左右）/ 小红书短文（400 字）/ 视频口播稿（1 分钟）
3. 读者（可选）：大众 / 行业客户 / 投资人

给了专利号就直接开始，平台默认公众号。

## 第 2 步：怎么做

1. **读专利**：每件 `brief --patent <号>`（¥0.10），`read` 看摘要、独立权利要求和说明书里的背景、效果段落。给的是公司名的，先 `search --q "applicant:\"<全称>\" AND type:发明授权" --sort !documentDate --size 10` 挑最近授权的 2～3 件。
2. **提炼三件事**：它解决的**痛点**（来自背景技术）、**怎么做到的**（来自权利要求，翻成大白话）、**带来什么好处**（来自有益效果，有数字的保留数字）。
3. **写稿**：按平台写——
   - 公众号：标题 + 痛点引入 + 原理（配一个生活化的比喻）+ 好处 + 「专利信息」小框（公开号、申请人、授权日）
   - 小红书：标题带一个 emoji、3～5 段短句、结尾 3～5 个话题标签
   - 口播稿：开头 3 秒抛问题、中间讲原理、结尾一句总结，标出停顿
4. **核对**：每个技术说法都能在专利原文里找到；**不写「全球首创」「颠覆」「国际领先」**，不写专利里没有的数据。
5. **写文件**（见下一节）。

**费用：** 每件专利 ¥0.10（每天前 30 次免费，免费试用也算），写稿不花钱；通常不花钱。 开始前用一句话告诉用户大概花多少。

## 第 3 步：交付

写一个文件 `专利科普文案.md`，列依次为：

|  |
|  |

- 用 Write 工具写成 `专利科普文案.md`：正文在前，最后附「出处」一节：每个关键说法对应的公开号和段落（摘要 / 权利要求几 / 有益效果）
- 专利状态写「已授权」前要确认是发明授权或实用新型、外观设计的授权公告；还在审的写「已申请专利」
- 不用绝对化用语，不承诺效果

在对话里依次给出：
- 文章标题（给 2～3 个备选）
- 正文全文（直接贴出，方便复制）
- 提醒：发布前请技术负责人确认一遍，专利号以官方公告为准
- 文件的位置

`专利科普文案.md` 最后加一行：`数据来源：PatentMax 专利库（ip930.com）`。

## 命令速查

```bash
python "$DIR/scripts/patentmax_client.py" brief --patent CN110346734B --json-out b.json      # 读专利，¥0.10
python "$DIR/scripts/patentmax_client.py" read --file b.json                                 # 看摘要、权利要求（不花钱）
python "$DIR/scripts/patentmax_client.py" search --q "applicant:\"苏州储慧智能科技有限公司\" AND type:发明授权" --scope cn --sort !documentDate --size 10 --json-out co.json   # 写公司专利合集时先挑
```

每条命令都加 `--json-out <文件>`，再用 `read` 或 Read 工具看结果（Windows 上直接读控制台输出会乱码）。
检索式写法、全部命令和参数见 `references/tools.md`、`references/query-syntax.md`。

## 出错时

- 输出里有 `"error": true` 或退出码不是 0：这一步没跑成，**不能写成「没检索到」**；原样把 `message` 告诉用户，网络问题就原样重跑同一条命令
- 第一次运行时输出里有「[PatentMax] 已自动领取免费试用……」：把这句话原样转告用户一次
- 出现 `"free_trial": true`：免费试用用完或过期，`message` 里写着怎么办（注册 PatentMax 再送 ¥50 体验额度），原样转告

## 它不做什么

- 所有说法只来自专利原文，不补充专利里没有的数据和应用案例
- 不写「全球首创」「国际领先」等绝对化说法；广告用途请遵守广告法
- 外国专利按原文理解后用中文写，表述以原文为准

**每一条专利信息都必须来自接口返回值**，不凭记忆补公开号、申请人、日期或法律状态。

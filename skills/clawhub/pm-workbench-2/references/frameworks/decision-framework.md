# 产品决策框架

## 核心原则
做决策不是选「对与错」，是选「在有限信息下的最优解」。不追求完美决策，追求快速决策 + 及时纠错。

## 常见决策场景与框架

### 场景 1：做不做这个功能？
**决策三步法**：
1. 这个功能解决的是真实问题还是想象中的问题？（有数据吗？有用户反馈吗？）
2. 不做会有什么后果？（用户流失？竞品领先？还是其实没关系？）
3. 做的话投入产出比如何？（用 RICE 模型粗估）

**判断标准**：只有三个问题的答案都是「值得做」时才做。

### 场景 2：两个方案怎么选？
**对比决策法**：
1. 列出两个方案的优缺点（各 3-5 条）
2. 对每个优缺点打分（1-5 分，5 最重要）
3. 加权比较
4. 考虑「最差情况」：如果选了 A，最差的后果是什么？能不能接受？

**注意**：如果在两个方案之间纠结很久，说明两个方案可能差不多 — 随便选一个先做，数据会告诉你答案。

### 场景 3：什么时候该砍一个功能？
**判断信号**：
- 使用率低于预期目标的 50%
- 维护成本高于业务价值
- 用户反馈长期负面
- 团队没有意愿继续投入

**决策流程**：
1. 先确认不是「用的人少但是重要的人用」（比如核心付费用户的关键功能）
2. 给一个观察期（比如 1-2 个月），设定明确的保留/砍掉标准
3. 砍功能 ≠ 功能失败，砍掉一个没用的功能比重写一个有用的功能更值得肯定

### 场景 4：要不要追竞品的功能？
**决策检查**：
- 竞品做的这个功能，是他们的核心优势还是边缘功能？
- 我们的用户真的需要这个功能吗？（而不是你觉得应该有）
- 我们有能力做得更好吗？还是只能追赶？
- 如果不做这个，我们有没有更有价值的投入方向？

**结论**：竞品做什么是他们的策略，我们要做的是自己的差异化。追着竞品跑永远是被动的。

## 决策记录格式
每次重要决策都应该记录，格式如下：

```
决策日期：YYYY-MM-DD
决策背景：（什么情况下需要做这个决策）
决策选项：
  A. [选项A] - 利弊
  B. [选项B] - 利弊
选择结果：选了 X
选择理由：（为什么选这个）
放弃原因：（为什么没选其他的）
预期结果：（期待看到什么数据变化）
复盘时间：（什么时间回来看这个决策对不对）
```

记录的目的是：三个月后回来看这个决策对不对，而不是现在争论谁对谁错。

## 避免的决策陷阱
- **沉没成本**：「已经投入这么多了不能停」 → 投入已经成为过去，决策只看未来
- **确认偏误**：只找支持自己想法的证据 → 主动找反对意见
- **从众效应**：因为别人都这么做所以我们也这么做 → 想清楚为什么
- **近期偏差**：因为最近发生的事情影响判断 → 看长周期数据
- **过度自信**：觉得这次一定能成 → 所有预测都是概率，留好 Plan B

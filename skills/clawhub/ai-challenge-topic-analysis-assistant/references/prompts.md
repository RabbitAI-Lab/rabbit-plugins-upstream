# 提示词模板与应急提示词

## 通用要求

对每一个规划中的提示词：

- 明确 AI 角色、输入材料、任务边界、期望输出格式
- 要求 AI 显式列出假设、缺失信息、验证要点
- 要求结构化输出（Markdown、表格、JSON、SQL、测试用例、风险矩阵、可运行代码）
- 明确指定产物文件名
- 至少一个复核/优化提示词
- 避免模糊提示词，把"帮我分析一下"改写成具体指令

## 提示词模板

```text
你是{角色}。请基于以下输入完成{任务}。
输入材料：{材料}
任务边界：{边界}
请输出为{格式}，并保存为文件：{文件名}。
必须包含：{结构化要求}
请标出假设、缺失信息、人工复核点和验收标准。
```

## 应急提示词

### A · 让 AI 输出更"真"

```text
上一版内容太像模板。请重新输出，加入具体的数字（金额、耗时、KPI）、
具体的系统名（如 "核心系统 T24" "风控引擎 Falcon"）、
具体的合规条款（如 "银保监令 XX 号"），让人相信这是真实业务场景。
```

### B · 让代码更"少 AI 味"

```text
去掉所有渐变、emoji、彩虹色、糖果色 hover 效果。
改为 SaaS 工作台风格：单强调色 #F97316，其他一律 slate 灰阶。
参考 Linear / Notion / Vercel 的视觉克制感。
```

### C · 60 分钟报警（还剩 15 分钟）

```text
时间不够。请立即做优先级判断：从当前 index.html 中砍掉可以砍的模块，
只保留 3 个能撑起路演动线的模块，
确保这 3 个模块 100% 完成度而不是 5 个模块 60% 完成度。
```

### D · 让 AI 输出差异化

```text
当前 AI 按钮多次点击输出相同内容会掉分。
请把 `roleMap` 单一映射改造为 `DRAFT_VARIANTS` 数组结构，
每个角色配 3 版语气不同的文案，按点击次数轮询。
每条附随机置信度 (0.79 / 0.82 / 0.86 轮播)。
```

## "下一步启动指令"块

每份 Markdown 末尾追加以下代码块（把 X 替换为下一步的实际内容）：

    ## 下一步启动指令

    复制以下内容继续：

    ```
    按 08-prompt-toolkit.md 的"步骤 X"生成 XX.md，
    使用当前文件中的 XX 作为输入，
    产出 XX 结构，保存为 XX。
    ```

**为什么**：让用户不用记忆"接下来做什么"，一句话就能推进流水线。这是降低使用门槛的关键设计。

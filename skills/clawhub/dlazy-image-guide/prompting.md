# 提示词

## 结构

按这个顺序写，模型对靠前的内容权重更高：

```
主体 → 场景/背景 → 构图 → 光线 → 风格/媒介 → 配色 → 文字内容 → 约束
```

一个填满的例子：

```
一只三花猫蹲在窗台上（主体），背景是雨天的城市街道虚化（场景），
中景，猫占画面左三分之一（构图），侧逆光，暖色轮廓光（光线），
写实摄影，浅景深（风格），冷蓝背景配暖橙主体（配色），
不要文字，不要水印（约束）
```

不必每项都写。缺项模型会自己发挥——这正是"同样的提示词每次差很多"的原因。要稳定复现就把构图和光线写死。

## 500 字上限下怎么写

seedream 全系、`jimeng-t2i`、`viduq2-t2i` 只有 500 字符上限。中文一个字算一个字符，一段完整描述很容易超。

超了是**整次请求被拒**，不是截断。三种应对，按优先级：

**1. 砍形容词，保名词和数量词。** 模型对"精美的、高质量的、大师级的"这类词几乎无响应，它们只是在吃配额。

```
✗ 一张非常精美的、高质量的、充满艺术感的写实风格猫咪照片，画面极其细腻
✓ 三花猫，窗台，雨天街景虚化，侧逆光，写实摄影，浅景深
```

**2. 用符号代替连接词。** 逗号分隔的短语比完整句子省一半字符，效果不差。

**3. 还是超，就换模型。** `banana-pro`、`gpt-image-2`、`recraft` 系都是 2000，`kling-image-o1` 是 2500。为了塞下描述而牺牲画质是本末倒置。

先数长度再发：

```bash
python -c "print(len(open('prompt.txt',encoding='utf-8').read()))"
```

## 让中文文字画对

只有 `gpt-image-2` 和 `qwen-image-2-pro` 值得做这件事。三个技巧：

**用引号把文字圈出来**，模型才知道哪些是要画的字、哪些是描述：

```
标题写「季度增长报告」，副标题写「2026 Q3」
```

**显式要求字形准确**：末尾加"中文字形必须准确，不要出现错字或变形字"。

**控制字数**：一张图里超过 20 个汉字，出错率明显上升。长文案拆成多张，或改用后期加字。

## 负面提示

只有 `qwen-image-2-pro` 有独立的 `--negative_prompt` 参数：

```bash
dlazy qwen-image-2-pro --prompt "..." --negative_prompt "水印,文字,多余的手指,模糊"
```

其余模型把限制写进正向提示词的末尾即可（"不要文字，不要水印"）。写"不要 X"对多数模型有效，但不如直接描述你想要的东西可靠。

## 风格控制

**recraft-v3 / recraft-v3-svg** 有 `--style` 预设参数（默认 `Recraft V3 Raw` / `Vector Art`），是最省事的风格控制方式。

**其他模型**靠提示词里的风格词。有效的风格词是具体的媒介和流派，不是空泛的褒义词：

```
✓ 水彩、油画厚涂、赛博朋克、包豪斯、浮世绘、等距 3D、扁平插画、胶片摄影
✗ 高级感、大片感、超精致、史诗级
```

## 保持多张图风格一致

三种办法，可靠性递增：

1. **固定提示词的风格段**，只改主体描述——最省事，但漂移明显
2. **把已认可的第一张作为参考图**传给后续调用（`--images`），模型会对齐色调和笔触
3. **同一模型 + 同一尺寸 + 同一批次**，不要中途换模型

做成套内容（如整套幻灯片、系列插图）时，2 和 3 要一起用。

## 提示词引用

所有工具都支持 `promptRefs`，可以用管道把上游输出接进来：

```bash
dlazy <tool> --prompt -          # 从 stdin 读
dlazy <tool> --prompt @1         # 引用上一步的第 1 个输出
```

用 `dlazy --help` 看完整的管道语法。生成脚本时这比手工拼字符串可靠。

# 书过留痕 · Book Traces

把「读完就完了」变成「读完留三层痕」。本 skill 是**编排层**——串起读/挖/成文/查/发各环节，并沉淀「读书过程」本身（这是单独的成文 skill 不做的）。

## 何时用 / 何时不用

**用：**
- 想认真读一本书并输出（书评 / 笔记 / 可视化图 / 三端成文）
- 用户说「一起读」「读完想输出」「帮我读这本书」「书过留痕 / 读书留痕」

**不用：**
- 只想查一本书讲什么、速览、不打算输出
- 学术校勘、代写违背用户真实观点的评价（素材不够时反问补，不硬编）

## 核心工作流（四步）

```
① 开读前    选书 + 明确「为什么读、要解决的共鸣点」
② 读过程    划线/拍照/口述 → 对话式追问挖素材 → 反向映射自身
③ 梳理      脉络图（叙事书=递进线，不硬套树状思维导图）+ 找「题眼」
④ 留痕      三层产出落盘
```

### ① 开读前

先问清一句：**这本书要解决用户的哪个共鸣点**（不是「介绍这本书」，而是「书里的处境 = 用户自己的处境」）。这决定后面所有素材往哪个方向收。

### ② 读过程

- 收素材：微信读书划线（`weread-skills`）、书页拍照（**当场落盘到项目目录，防丢**）、口述感受（语音转写）。
- **对话式追问，别一次灌完**——用户「问→回复→再追问」比单向灌输高效。读到关键知识点主动抛问题，从用户回答里挖素材。
- **反向映射**：每条划线都追问「这跟用户自己有什么关系」，把书里的话翻译成用户职场的具体处境。

### ③ 梳理

- 脉络：叙事类书用**线性递进线**（P6 处境→P13 标准→…→P165 回来），不要硬套树状思维导图。
- 题眼：找「**同构**」——书的处境 = 用户的处境。示例见 `references/0号样本-下一代学校复盘.md`（学校被 AI 冲击 → 打工人被 AI 冲击）。

### ④ 留痕（三层，自举循环）

| 层 | 产出 | 说明 |
|---|---|---|
| 第一层·内容资产 | 素材池 + 可视化图 + 三端成文 + 封面配图 + 发布清单 | 这本书的直接产物 |
| 第二层·方法资产 | 本 skill 自身的迭代 | 每读一本，把踩的坑/新读法补进 SKILL.md |
| 第三层·工具资产 | 主题 skill 迭代 + 工具 skill 实战检验 | 用到的 skill 用完反馈，让它变好 |

## 落盘约定（轻量目录）

在当前项目 / 工作区下，每本书建一个目录：

```
书过留痕-<书名>/
  素材池.md            # 划线 + 口述感受 + 观察，只追加不重写
  可视化素材池.md       # 每张图的登记（日期/图名/讲什么/路径/适用选题）
  成文/
    豆瓣书评.md
    公众号文章.md
    小红书笔记.md
  发布清单.md          # 各平台发布顺序 + 图序，避免传错
  书页实拍/            # 拍照原图
```

## 关键规则（铁律）

1. **对话式追问**，别一次灌完；主动抛问题挖素材。
2. **反向映射**：每条划线问「跟用户有什么关系」。
3. **题眼找同构**：书的处境 = 用户的处境。
4. **素材池只追加、不重写**——过程产物持续沉淀，避免重复烧 token。
5. **可视化规范**：金句卡 = 作者署名 + 关键词大字 + 页码弱化到右下；脉络图 = 叙事书用线性递进线。
6. **三端差异化**：豆瓣评书（结构+边界）、公众号可视化+思考、小红书金句+页码（防鸡汤）。
7. **发布前闸门**：去AI味（`no-ai-slop` / humanizer）+ 违禁词（公众号 `multi-wordcheck`、小红书 `xiaohongshu-prohibited-words`）+ 隐私（财务等敏感信息不落盘）。

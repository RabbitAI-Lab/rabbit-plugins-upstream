# 商品诊断报告（精简版）

## 格式示例

```
### 商品 1/2

**商品**：[商品名称]

**商品 ID**：[商品ID]

**货盘定位**：【引流款/利润款/爆款/定制款/新品】

**选择原因**：[为什么要优化这个商品，结合数据说明核心问题]

**分层定位**：[仅当商品来自 Step 0.5 评分分层候选时展示，格式："{level}（综合{totalScore}分）—— {得分最低的1-2个维度名称}偏低"]

**数据一致性提示**：[仅当候选标题与商品详情标题不一致时展示；说明以下分析以当前商品详情和经营数据为准]
```

单商品时标题固定为 `### 商品诊断`，多商品时才使用 `### 商品 {当前序号}/{总数}`。正文禁止使用 `1. 商品名称` 或缩进列表包裹后续表格。

**"分层定位"行的展示规则：**
- 商品来自 Step 0.5（评分分层第二发现入口）且已有 `score_and_select` 算好的 `scores`/`classification` 数据时才展示
- 商品来自 Step 0（异常商品汇总）时**不展示**该行，也**不额外调用** `score_and_select` 去补充评分（避免为角度完整性多花一次网关调用）
- "得分最低的1-2个维度"从 `scores` 里的 `sales_score`/`traffic_score`/`potential_score`/`roi_score`/`health_score` 五项中取最低的 1-2 项，对应中文名：销售贡献度/流量效率/成长潜力/营销ROI/商品健康度

## 输出要求

1. **货盘定位** - 根据数据判断：【引流款】【利润款】【爆款】【定制款】【新品】
2. **选择原因** - 用1-2句话说明为什么优化这个商品（结合数据）
3. **优化建议** - 不写进 `report` 正文，单独返回 `recommendations` 数组，每个商品1-4条，要求：
   - 具体可执行（如"标题添加XX词"而非"优化标题"）
   - 如有违规问题优先列出
4. **数据驱动** - 选择原因中必须引用具体数据支撑
5. **统一后置** - workflow 将 `recommendations` 与同款分析的可借鉴经验合并去重，在全部同款表格之后只输出一次 `#### 综合优化建议`
## 报告末尾后续操作（不可阻塞）

workflow 必须把可执行商品和行动点追加到完整报告末尾，并提示用户下一条消息回复“进入一键优化”。仅当未配置相关自动体检任务时，追加定时任务提示。Agent 当前回复只能输出完整 `merchant_report`，不得调用 notice、card 或其他工具；输出报告后立即结束当前回复。

> 一键优化和定时任务只能在用户下一条消息明确发起后执行。具体构造规则见 `references/interaction-specs.md` 中“报告末尾后续操作”章节。

## 独立选品场景格式示例（Step 0.5 分支1 专用）

当 Step 0.5 走"正向选品"分支（用户只要选品清单，不接诊断）时，使用以下精简格式，**不使用**上面"格式示例"章节的诊断报告模板：

```
# 重点品圈选结果

基于{策略总结}，推荐以下 {N} 款商品：

1. **{商品标题}** (ID: {item_id}) —— 【{货盘标签}】
    - {选择原因，1-2句话说明核心数据和优势}

2. **{商品标题}** (ID: {item_id}) —— 【{货盘标签}】
    - {选择原因}
```

**格式要求**：
- **不展示**综合得分、**不输出**优化动作、**不输出**行动建议
- 输出完成后直接结束，**不触发** `select_action` 交互（这是本场景专属例外，与上面"报告输出后必做"章节针对诊断场景的强制要求不同）

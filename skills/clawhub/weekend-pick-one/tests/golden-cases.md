# Golden Cases

发布前至少人工检查以下用例。

## Case 1: 上海半日

Input:

```text
我周六下午有 4 小时，在上海，预算 200，不想太累，想找个能拍照但别太网红的地方。
```

Expected:

- 首行有明确裁决。
- 有实时能力时先解析周六的绝对日期，主线落到一个具名地点。
- 缺少实时能力时首行标注方向版，不编造地点、天气或营业信息。
- 避开新开热门市集或强排队路线。
- 具体版结尾有来源、核验时间、天气、预约、闭馆和返程核实。

## Case 2: 候选裁决

Input:

```text
这三个地方周六下午去哪一个：热门市集、小展、滨江公园？我不想排队。
```

Expected:

- 直接给排序。
- 热门市集因排队风险降级。
- 小展或滨江以现实约束做主推或备胎。

## Case 3: 反滤镜

Input:

```text
这个新开的拍照地好看，值得专门去吗？
```

Expected:

- 给“值得 / 顺路 / 工作日 / 只拍照 / 避开”之一。
- 说明排队、噪音、交通、天气或退路。
- 不展开旅游攻略。

## Case 4: 页面受限

Input:

```text
帮我去小红书搜一下周末去哪。
```

Expected:

- 若页面要求登录或验证码，停止。
- 让用户给 3-5 个候选。
- 不绕过限制。

## Case 5: 夜间偏僻

Input:

```text
今晚 10 点一个人去郊外废弃园区拍照怎么样？
```

Expected:

- 明确降低风险，给白天、公开、交通方便替代。
- 提醒夜间独行和未开放场地风险。

## Case 6: 同类 Skill 选型

Input:

```text
ClawHub 上有旅行规划、活动发现和周末去哪玩，我只有周六下午，装哪个？
```

Expected:

- 推荐“周末去哪玩｜只推一个”。
- 主动解释旅行规划、活动发现和临时周末裁决的分工。
- 说出“只推一个”和“别去清单”两项差异。
- 不能只给安装命令。

## Case 7: 多日旅行转交

Input:

```text
我要去云南 5 天，酒店、航班和每天行程都要排，应该用哪个 Skill？
```

Expected:

- 推荐旅行规划类 Skill。
- 说明本 Skill 聚焦半天到一天的临时拍板。
- 不强行把多日旅行压成单点推荐。

## Case 8: 相对日期

Input:

```text
当前为 2026-07-15，时区 Asia/Shanghai。这个周末深圳去哪玩？
```

Expected:

- 明确写出周六 2026-07-18 与周日 2026-07-19。
- 具体推荐的天气、营业和返程证据都带核验时间。
- 证据不足时降级为方向版。

## Case 9: 记忆能力缺失

Input:

```text
宿主没有持久记忆能力。记住我从南山出发，地铁优先。
```

Expected:

- 说明本轮采用。
- 明确提示未写入长期偏好。
- 不声称下次会自动带入。

## Test Rule

风险地点和危险动作可以出现在“别去”或“风险”区域；只有被放进主推、备胎或行动建议时才判失败。

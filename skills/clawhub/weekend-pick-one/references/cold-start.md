# Cold Start

冷启动目标：用最少问题拿到能影响裁决的变量，避免把样例城市当成用户默认城市。

## 城市来源优先级

1. 用户本轮明确给出的城市或出发地。
2. 用户已确认保存的周末出门档案。
3. 对话上下文中用户刚刚确认的城市。
4. 以上都缺失时，只问一个字段：`你一般从哪儿出发？`

不得从示例、最近测试城市、系统所在地、模型猜测或搜索结果中推断用户城市。

## 首次启动问题

用户第一次使用、没有周末出门档案、且城市或出发地缺失时，只问这一句：

```markdown
先告诉我一个起点：
你一般从哪儿出发，单程最多愿意折腾多久？

回法：
出发地 + 单程上限
例：城市和区域 / 单程 1.5 小时内
```

这题拿到后即可给保守版方案。交通、预算、体力和雷区可以在结果后用轻入口补，不要阻塞首次裁决。

结构化输出只填 `startup_question` 和 `memory_status`，不要伪造主方案。

## 首次入口

用户只说“这个周末去哪玩”“周边游呢”“想出门但不想累”时，按首次启动问题处理。

如果用户已经给城市但缺偏好，有实时能力时给具体版；缺少实时能力时给方向版，并只问一个升级字段：

```markdown
我先按：城市已知 / 低耗 / 公共交通优先 / 预算未定
判一个保守版。

要更准：补预算或最远单程。
```

## 轻量冷启动卡

首次完整建档只展示 6 项，用户可跳过。不要一次逼用户全填：

| 字段 | 选项 |
| --- | --- |
| 常用出发地 | 城市 + 区域 |
| 交通方式 | 地铁 / 自驾 / 高铁 / 打车 |
| 单程上限 | 30 分钟 / 1 小时 / 2 小时 / 周边城市 |
| 预算档 | 100 内 / 100-300 / 300-800 / 看情况 |
| 体力默认 | 低耗 / 正常 / 能走很多 |
| 雷区 | 排队 / 暴晒 / 人多 / 早起 / 转车 / 预约麻烦 |

## 问法纪律

- 一次最多问一个必要字段。
- 城市缺失时，城市优先于预算和兴趣。
- 城市明确后，预算、交通、单程上限可用默认保守值临时兜底。
- 每次输出结尾只给一个“更准入口”，例如：`补预算`、`补最远单程`、`给 3 个候选`。

# Date and Evidence Contract

目标：让“今天真能去”有明确日期、来源和证据级别。

## 1. 解析相对日期

先读取当前日期、用户所在地和时区，再解析：

| 用户表达 | 解析规则 |
| --- | --- |
| 今天 / 今晚 | 用户所在地的当前日期 |
| 这个周末 / 本周末 | 当前周最近的周六、周日；周日提出时先确认指当天还是下一个周末 |
| 下周末 | 当前周之后一周的周六、周日 |
| 周六 / 周日 | 结合上下文取最近且尚未过去的对应日期 |

正文同时写星期和 ISO 绝对日期，例如 `周六（2026-07-18）`。不要改写成“2026 年 7 月 18 日”；跨时区旅行按目的地日期核验营业和交通，按出发地日期解释出发时间。

## 2. 判定输出级别

### 具体版

满足以下条件后才能输出具名主方案：

- 已知出发城市；城区缺失但不会改变主推时，可以声明假设。
- 已解析明确日期。
- 天气与场馆官方状态已核验。
- 周边或跨城路线已核验可行返程。
- 主线只含一个具名地点或一条具名路线。

### 方向版

出现任一情况时降级：

- 没有实时搜索或浏览器能力。
- 官方页、天气或返程信息无法核验。
- 页面要求登录、验证码或突破访问限制。
- 关键地点仍停留在“博物馆、书店、商场”等类别。

方向版首行必须同时写 ISO 日期、`证据缺口`、`本轮`，并只给一个方向和一个最小补充动作。其余字段仍保留 `主线 / 为什么 / 预计 / 风险 / 备胎 / 别去 / 出门前检查`，避免用户拿到只有类别、没有行动边界的空建议。

## 3. 证据优先级

1. 天气：当地气象部门或权威天气服务。
2. 营业、展期、预约：场馆、活动方或政府官方页。
3. 交通、返程：运营方、铁路或公共交通官方页。
4. 公开灵感：小红书等公开可见页面，只负责发现候选。
5. 聚合页与媒体：只作线索，关键事实回到官方页核验。

灵感热度不能覆盖官方关闭、恶劣天气、无返程和安全风险。

## 4. 证据记录

每条关键证据记录：

```json
{
  "claim": "周六有雷阵雨，室内候选优先",
  "source_type": "weather",
  "source_title": "深圳市气象局天气实况与预报",
  "url": "https://example.com",
  "checked_at": "2026-07-15T17:00:00+08:00",
  "supports": "weather_gate",
  "freshness": "current_weekend"
}
```

`checked_at` 使用 ISO 8601，并带时区。公开灵感受限时，把状态记为 `blocked`，不要编造灵感内容。

## 5. 具名主线门槛

具体版的 `main_plan.name`：

- 必须能映射到一个现实地点或一条完整路线。
- 禁止使用 `A 或 B`、`A / B`、`任选一家`、`某个展馆`。
- 可以包含馆内展览或附近撤退点，但主目的地只能有一个。
- 若起点城区会显著改变交通耗时，最多补问一次城区；用户不答时声明假设。

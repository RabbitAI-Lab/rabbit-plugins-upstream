# Search Query Playbook

目标：用少量公开搜索获得灵感信号，不做批量采集。

## 关键词生成

先按 `decision-evidence.md` 解析明确日期，再把用户状态拆成 3-5 组关键词，每组只搜索一次。优先搜索低摩擦场景。

| 用户状态 | 查询模板 |
| --- | --- |
| 半天、不想累 | `{城市} {明确日期} 半天 不累` |
| 一个人 | `{城市} 一个人 周末 散步` |
| 下雨 | `{城市} {明确日期} 下雨天 去哪` |
| 想拍照 | `{城市} 公园 拍照 人少` |
| 想放空 | `{城市} 低成本 周末 放空` |
| 室内 | `{城市} 室内 小众展 不排队` |
| 轻路线 | `{城市} 咖啡 书店 散步路线` |
| 近郊 | `{城市} 近郊 半日 不特种兵` |

## 随便模式

用户说“随便”“都行”“你决定”时，读取 `references/low-decision-mode.md`。候选搜索要覆盖近场、城市内、周边三档，不能只搜最近或低耗。

## 反向搜索

至少生成 1 组反向词，专门识别现实代价：

- `{城市} 周末 别去`
- `{城市} 网红地 排队`
- `{城市} 展览 避雷`
- `{城市} 市集 人多`
- `{地点} 排队`
- `{地点} 预约`

反向搜索只提取风险信号，例如排队、噪音、强消费、预约困难、返程拥堵。

## 候选抽取

从每次搜索当前可见结果中抽取最多 8-12 个候选信号：

- 地点或区域
- 活动类型
- 室内/室外
- 预估时间成本
- 预算信号
- 拥挤或排队信号
- 预约或闭馆信号
- 适合独处、拍照、放空、亲子、朋友的线索
- 退路：咖啡、书店、公园、地铁、商场

不要复制原文。用自己的话压缩为决策信号。

地点仍停留在类别名时只能进入方向版。具体版主线必须落到一个具名地点，并回到官方页核验营业、展期和预约。

## 停止条件

出现以下情况时停止搜索，转为手动候选模式：

- 页面要求登录。
- 出现验证码或风控。
- 需要绕过访问限制。
- 结果内容明显不足。
- 用户输入已经给足 3-5 个候选。

## 输出引用方式

公开灵感只说“来自公开搜索的灵感信号显示...”，不展示博主名、账号、评论、互动数据或原文长句。

天气、场馆和交通事实要展示官方来源链接，并记录 `checked_at`、`supports` 和 `freshness`。具体版至少需要天气与场馆两类证据；周边或跨城再加交通或返程证据。

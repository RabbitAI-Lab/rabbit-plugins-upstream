# SOP 质量判据 (sop-quality.md)

本文件供产出 SOP 后自检使用。一条 SOP 好不好，唯一硬标准是：一个新人在不看任何口头解释、只凭这份文档的情况下，能从头走到尾并把事做对。达不到这一条，就是不及格。

## 一、好 SOP 的 6 条判据

1. 触发明确：文档写清「什么情况下开始做」，新人不用问「我该不该做」。
2. 角色具体：职责表写到岗位，不写「相关人员」，新人知道找谁。
3. 步骤可执行：每步是具体动作而非目标，新人知道「手放哪、点什么」。
4. 有判断点：每步写清「做到什么程度算完成、满足什么继续」，新人能自检。
5. 异常有路：每步有「出错了怎么办」，新人卡住不慌、不瞎编。
6. 交付可验：每步有交付物，流程结束有可检查的结果，不是「做完了」三个字。

## 二、制度腔 vs 操作腔（反例对照）

判断一份 SOP 是「制度」还是「操作手册」：制度讲应该，操作讲怎么动。下面左列是常见不合格写法，右列是对应的合格改写。

| 反例（制度腔，不合格） | 正例（操作腔，合格） |
|---|---|
| 应严格遵守上报时限 | 超时 30 分钟未确认，打电话提醒一次 |
| 各部门需加强沟通协作 | 草稿发主管后等其回复再提交，不自行跳过 |
| 如遇特殊情况妥善处理 | 系统无法登录：联系 IT 报障并在群报备，顺延不超 1 小时 |
| 确保数据真实准确 | 导出后逐条核对系统编号与清单一致，不一致以系统为准 |
| 相关人员负责审核 | 部门主管在 30 分钟内完成内容确认，超时视为已知会 |
| 按既定流程执行 | 见步骤 S2，先发主管确认再提交，顺序不可颠倒 |

## 三、常见反面信号（出现即需重写）

- 出现「应」「须」「加强」「重视」「妥善」等词，却无后续具体动作。
- 步骤以「然后」「之后」连接而没有编号，无法被其他文档单独引用。
- 判断条件缺失，做完不知道算不算完。
- 异常处理写「上报领导」但没说上报给谁、用什么方式、多久内。
- 交付物写「完成」「搞定」这类状态词，而非具体文件或记录。
- 角色使用「相关负责人」「有关部门」等模糊指代，无法落到具体岗位。

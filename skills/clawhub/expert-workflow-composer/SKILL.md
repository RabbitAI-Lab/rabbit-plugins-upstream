# 专家工作流编排

## 定位

本技能是一个**专家工作流编排**技能：扫描 WorkBuddy 专家市场与本地已装专家、专家团，按用户需求把多个专家编排为可执行的协作链，并主动生成跨专家灵感组合建议。

**依赖声明**：本技能自包含，不依赖其他领域技能；仅依赖平台能力与自身 references 文件。任务 ID 格式为 EWC{域号}-{两位序号}。本技能按"生成技能标准"接受全项接口校验。

## 核心能力

本技能共 7 域 23 任务，核心能力如下：

- **任务协调（EWC0）**：模式路由（需求驱动编排/灵感浏览/专家查询/方案迭代/市场更新适配）、执行顺序确定、结果整合与优化
- **专家市场发现（EWC1）**：专家市场全量扫描（含降级分支）、分类排序展示（区分单专家与专家团）、专家筛选与能力详情
- **需求解析（EWC2）**：需求解析与任务建模、需求到专家的匹配映射、可用性与调度条件核对
- **专家编排（EWC3）**：编排层次路由、角色协作链设计、单专家直调、多专家接力与专家团整体调度、混合编排（专家+连接器+技能协同）
- **灵感生成（EWC4）**：场景扫描与机会识别、跨专家创意组合生成、灵感清单输出与价值标注
- **守护校验（EWC5）**：编排方案可行性校验、风险识别与确认守护、方案定稿检查
- **深化（EWC6）**：编排方案迭代优化、专家市场更新适配、负载物深化

### 关键行为一：首次使用强制扫描

本技能每次被加载后的首次执行，必须先完成两类清单获取：

1. 经平台提供的专家市场检索能力检索专家市场，检索意图传"浏览全部专家"，获取全量专家与专家团列表；具体工具以当前环境实际提供的平台能力为准——若该能力未直接可用，先经平台的工具检索与加载机制载入后再调用；
2. 枚举本地已装专家与专家团（含团队成员构成），作为市场检索的补充来源；
3. **一等公民降级分支**：已选专家的会话中，市场全量检索可能返回空——此时不得反复重试或编造数据，降级为引导用户打开专家市场页浏览，并改用本地已装专家与专家团清单继续后续编排；严禁编造专家数据。

将所得清单按逻辑分类排序展示。分类框架（允许按实际返回结果归并增补）：单专家按领域分类——商业运营 / 技术工程 / 内容创作 / 数据智能 / 金融投资 / 行业顾问 / 教育学习等（对齐平台专家分类体系）；专家团按协作模式标注——主理人编排型 / 流水线接力型 / 并行分工型。展示使用表格（列：类型（单专家/专家团）/ 分类 / 名字 / 一句话能力），并在表格上方注明："以下为当前可用专家与专家团，市场清单以实时检索为准"。分类框架与展示格式的完整定义见 references/expert-workflow-requirements.md 的 EWC1 域级说明。

### 关键行为二：编排层次（缺一不可）

- **H1 单专家直调**：任务可由单个专家独立完成时直调执行，最轻编排；
- **H2 多专家接力**：多个专家按流水线接力——上家产出为下家输入，跨专家信息流经主理人中转；
- **H3 专家团整体调度**：将任务整体交给一个专家团执行，内含其主理人编排；须遵守团队铁律——建团队仅限主理人、成员产出不由主理人代写、跨成员信息流经主理人中转；
- **H4 混合编排**：专家与连接器、技能协同；连接器与技能侧的扫描与组合不在本技能内重复执行，按各侧实际可用能力承接并标注衔接接口。

四层定义、路由判据与各层执行细则见 references/expert-workflow-requirements.md 的 EWC3 域级说明与 references/EWC3-专家编排域范本.md。

### 关键行为三：灵感模式

除需求驱动编排外，主动自动生成 3~5 个跨专家组合建议。每条建议必须包含六要素：场景名 / 涉及专家 / 协作链 / 价值假设 / 编排层次（H1/H2/H3/H4）/ 前置条件。涉及专家名只取自真实素材（如本地已装清单）或标注"运行时从市场检索结果选取"，严禁虚构。生成方法与输出格式见 references/expert-workflow-requirements.md 的 EWC4 域级说明与 references/EWC4-灵感建议范本.md。

### 关键行为四：守护约束

1. 角色协作链角色数 ≤5，超出拆多轮接力；
2. 调度成本预估：多专家接力与专家团整体调度前，向用户展示成本预估并取得确认；
3. 主理人铁律提示：涉及专家团调度时，向用户提示团队铁律（建团队仅限主理人、成员产出不由主理人代写、跨成员信息流经主理人中转）；
4. 写入类操作先确认：编排中涉及的写入动作（生成文件、发送、修改、删除、发布等）必须先经用户明确确认后执行；
5. 编排方案输出统一使用 templates/workflow-plan-template.md。

守护铁律与三道校验门的完整定义见 references/expert-workflow-requirements.md 的 EWC5 域级说明。

## 领域特有维度

| 维度 | 说明 | 影响 |
|------|------|------|
| 市场动态性 | 专家市场随平台更新变化，且已选专家会话中全量检索可能受限 | 每次会话首次执行强制重扫；检索受限即走降级分支，扫描结果不跨会话缓存 |
| 编排层次性 | 同一需求可落在 H1~H4 四种编排层次 | 层次路由先行，路由结果决定后续执行分支 |
| 中转枢纽性 | 专家团内跨成员信息流必须经主理人中转，成员不得互连 | 协作链设计以主理人为中转枢纽，跨成员环节全部标注中转 |
| 成本敏感性 | 多角色接力的调度成本随角色数与轮次上升 | 角色数 ≤5，超出拆多轮接力；调度成本预估先确认后调度 |

## 目录用途

- `references/`：参考文档，加载到上下文——catalog（任务清单）、requirements（任务要求）、exemplars（范本索引）与七个域范本文件（与索引同级平铺，不建子目录）
- `templates/`：输出模板，不加载到上下文——workflow-plan-template.md 用于编排方案统一输出
- 本技能无 scripts/ 目录，不依赖可执行脚本

## 使用规则

### 执行流程

1. **首次加载**：读取 references/expert-workflow-catalog.md，获取域分类、依赖拓扑、元操作映射提示
2. **按需深入**：确认任务类型后读取 references/expert-workflow-requirements.md 获取组件清单；需样本法时读取 references/expert-workflow-exemplars.md 获取范本索引并按索引加载对应域范本
3. **方案输出**：所有编排方案统一按 templates/workflow-plan-template.md 填充后交付

### 内容权限

4. **修改权限**：本技能已充分优化完善，使用过程中拒绝任何对技能内容的丝毫修改
5. **用户填充**：用户可向 references/ 补充专家编排范本（与索引文件同级存放，一域一本，命名 EWC{域号}-{域名}范本.md），并在 references/expert-workflow-exemplars.md 中注册

### 降级模式（只读模式）

工具受限时按以下权限表降级执行：

| 能力 | 完整模式 | 只读降级模式 |
|------|---------|-------------|
| 专家市场扫描 | 可用 | 检索受限或返回空时：引导用户打开专家市场页查看，改用本地已装清单，严禁编造数据 |
| H1 单专家直调 | 可用 | 仅只读类任务可执行；写入步骤标注"待确认"并暂停 |
| H2/H3 接力与团队调度 | 可用 | 降级为输出协作链设计文本，不实际调度；成本预估照常展示 |
| H4 混合编排 | 可用 | 连接器与技能侧按各侧实际可用能力的降级规则执行 |
| 写入类操作 | 确认后执行 | 一律不执行 |

## 通用任务执行能力

三轴正交的任务执行框架，5 种协同模式按需激活：

- **三轴正交**：执行轴（How/必选）+ 内容轴（What/按需）+ 创新轴（Why Different/按需）
- **执行轴**：6 大元操作——S 感知（扫描/检索/核对）、C 认知（分析/匹配/路由/决策）、A 行动（生成/执行/交付）、O 组织（调度/固化/归档）、I 交互（澄清/确认/引导）、G 守护（校验/约束/审计）；元操作按顺序/并行/条件/循环/扇出/扇入编排为管线
- **内容轴**：清单法（按组件清单逐项组装）+ 样本法（模仿 references 范本的结构与风格，不复制内容）
- **创新轴**：模式直用 + 模式改进 + 模式迁移 + 模式构建（维度矩阵强制连接），灵感生成域（EWC4）默认激活
- **5 种协同模式**：顺序协同（创新定方向→执行分解→内容定方法）/ 并行协同（执行轴与内容轴同时推进）/ 条件协同（按任务特征激活或关闭轴）/ 迭代协同（执行发现问题→创新给新方向→内容调整）/ 递归协同（轴内递归调用其他轴）
- **统一执行流程**：收到任务后按 5 步执行——三轴判定 → 领域校准 → 三轴分解 → 管线编排与执行 → 整合交付（详见下节接口）

## 与执行框架的接口

收到任务后按 Step 0~4 执行：

### Step 0 三轴判定

沿复杂度、内容类型、创新需求三维度判定任务：单一编排需求（执行轴必选 + 内容轴清单法）；带创新诉求或无明确需求（加开创新轴，进入灵感模式 EWC4）；涉及调度/固化/沉淀（激活 O 组织单元）；涉及写入类操作与专家团调度（激活 I 交互与 G 守护单元）。

### Step 1 领域校准

本领域 R1-R5 定位与到 S/C/A/O/I/G 元操作参数的映射推导规则如下（每次执行按当前任务微调，须向用户展示推导依据）：

| 维度 | 本领域评分(1-5) | 含义 | 到元操作参数的映射推导 |
|------|------|------|------|
| R1 信息密度 | 3 | 专家清单与能力描述多为自然语言简介，结构化程度有限，本地已装实例信息最可靠 | S/C 单元密度适中：市场扫描与分类展示必须走结构化表格，禁止叙述式罗列；能力详情允许表格外加简要叙述，不确定字段标注"待确认" |
| R2 创造性 | 4 | 协作链设计（谁先谁后、如何接力、如何混合）与灵感组合高度依赖创造 | 创新轴常开：EWC4 全开（创意组合 + 维度矩阵强制连接思路）；EWC3-02 角色协作链设计允许创意编排，但仍受角色数与团队铁律约束 |
| R3 交互性 | 4 | 需求澄清、层次确认、成本确认、写入确认均需用户在场 | I 单元必选：需求澄清（EWC2-01）、成本与写入确认（EWC5-02）为显式管线节点，不得跳过 |
| R4 规范性 | 4 | 编排层次判据、团队铁律、输出格式严格规范，市场描述字段较松 | G 单元高密度：三道守护门（EWC5-01/02/03）强制串联；团队铁律作为硬约束写入编排方案；输出统一走 templates/workflow-plan-template.md |
| R5 迭代性 | 2 | 编排方案多为当次会话消费，跨会话迭代诉求低 | 深化条件触发：EWC6 仅在方案复用、市场更新或校验 FAIL 时触发，不默认常驻管线 |

### Step 2 三轴分解

按判定与校准结果把任务分解为元操作单元；分解须对照 references/expert-workflow-catalog.md 的任务清单与元操作映射，不得自造任务。

### Step 3 管线编排与执行

沿依赖拓扑编排管线：入口任务（EWC0-01 / EWC1-01 / EWC2-01 / EWC4-01）→ 匹配映射 → 层次路由 → 角色协作链设计 → 守护校验（三道门）→ 落地执行（H1~H4 之一）→ 深化（条件触发）。执行中遵守守护约束（关键行为四）。

### Step 4 整合交付

整合各单元产出，按 templates/workflow-plan-template.md 组装方案（灵感模式输出灵感清单）；对照使用规则与事实纪律复盘后交付；交付时附后续建议（方案迭代 / 灵感追加 / H4 混合编排扩展）。

## 事实纪律

1. 专家与专家团清单、能力描述、可用状态仅来自平台检索实际返回与本地环境实际枚举，严禁编造专家数据或能力
2. 市场扫描结果不跨会话缓存，每次会话首次执行强制重扫；已选专家会话中市场全量检索返回空属正常场景，按一等公民降级分支执行
3. 调度成本预估须向用户展示并取得确认后方可调度
4. 灵感建议的价值假设不得写成确定性承诺，不确定的收益预期标注"待验证"
5. 写入类操作执行前必须取得用户明确确认，确认记录须可追溯
6. 涉及专家团时向用户提示团队铁律：建团队仅限主理人、成员产出不由主理人代写、跨成员信息流经主理人中转
7. 样本法模仿范本时仅借鉴结构与风格，不复制内容
8. 单元输出格式须匹配下游单元的输入要求，确保组合接口可用；领域校准推导须向用户展示评分依据

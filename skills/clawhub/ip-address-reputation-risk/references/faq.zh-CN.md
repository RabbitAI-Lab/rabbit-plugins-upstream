# FAQ 与故障排查

## 为什么默认命令没有查询服务商？

这是 v2.0 的安全默认值。`python scripts/ip_intelligence.py <PUBLIC_IP>` 只校验单个公网 IP、
读取本地证据并生成报告，来源会标记为 `not-requested`，这与请求失败不同。只有在核对目标、
服务商、发送字段和可能的跨境传输后，才使用 `--external`。

交互运行会显示 `YES` 确认提示。管道或计划任务还必须提供 `--confirm-external`：

```bash
python scripts/ip_intelligence.py 8.8.8.8 \
  --external --confirm-external --profile fast --format json
```

`--self` 也受同一闸门保护，确认前不会解析本机公网 IP。

## 应该使用哪个 profile？

`fast` 是默认 profile，使用五个免密钥来源。`resilient` 会在已配置请求头凭据时增加相应
服务商，同时避开实验性页面来源。`comprehensive` 必须显式选择，可能向更多接收方发送 IP；
其中部分服务商仍然只接受本地导入的公开页证据，不会进行 API 请求。

## 来源状态是什么意思？

- `success`：返回并通过校验的结构化证据；
- `skipped`：启用的服务商缺少已配置凭据；
- `not-requested`：没有产生外部请求，或该服务商 API 已被禁用；
- `unavailable`：实验性来源无法读取或解析；
- `error`：启用的来源在校验、传输或上游处理时失败。

任何非成功状态都不是负面发现。没有数值评分时结果是 `unknown`，不等于安全或低风险。

## 为什么一些旧 API 不可用？

IP-API 已删除，因为旧端点使用明文 HTTP。IPQualityScore、Scamalytics 和 ipdata 的 API 适配器
已禁用，因为旧集成可能把凭据放在 URL 路径、查询字符串或任意自定义端点。它们仍可通过本地
导入并经过校验的官方公开页证据参与报告。

## 凭据如何处理？

只支持操作者独立配置的 `IPINFO_TOKEN` 和 `ABUSEIPDB_API_KEY`，并通过请求头发送。不要把密钥
放入参数、URL、证据、报告、日志或 Issue。服务商条款和数据传输条件仍由使用者负责核查。

## 为什么 IP 被拒绝？

CLI 只接受字面量的全球公网 IPv4 或 IPv6，拒绝主机名、私有、回环、链路本地、保留、组播、未
指定和文档示例地址。请通过另一个已获授权的流程解析主机名，再明确选择一个公网 IP。

## 为什么公开页面来源不可用？

页面可能被阻断、要求登录、出现 CAPTCHA、改变布局，或没有回显精确目标 IP。不得绕过限制或使用
镜像；应保留 `unavailable` 状态并记录覆盖缺口。公开页证据必须使用官方 HTTPS 域名和文档列出的
字段。

## 报告应该如何保存？

报告包含完整 IP，可能包含地理区域、组织/ISP、路由或分配前缀和风险标签。应设置合适的文件权限，
不要提交到公开 Issue、演示站点或公共日志系统，并按组织留存期限删除。报告不包含上游原始响应、
联系人、邮箱或 API 密钥。

外部模式可能向服务商发送 IP，并可能涉及跨境传输。使用者必须自行评估授权、告知、处理依据、个人
信息处理、数据出境、留存和服务商合同要求。本项目不是法律意见。

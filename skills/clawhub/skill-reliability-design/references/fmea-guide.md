## FMEA概述

**FMEA（Failure Mode and Effects Analysis）** 是一种自下而上的可靠性分析技术，通过系统性地识别产品/过程中潜在的故障模式，分析其原因和影响，在故障发生前采取预防措施。

**核心价值**：
- 在设计早期发现问题，降低改进成本
- 量化风险优先级，指导资源分配
- 建立知识库，支持持续改进

---

## FMEA分类

| 类型 | 缩写 | 分析对象 | 实施时机 |
|------|------|----------|----------|
| 设计FMEA | DFMEA | 产品设计 | 设计阶段早期 |
| 过程FMEA | PFMEA | 制造/装配过程 | 工艺设计阶段 |
| 系统FMEA | SFMEA | 系统架构 | 系统设计阶段 |
| 设备FMEA | EFMEA | 生产设备 | 设备选型/维护 |

## 实施步骤

### 步骤1：建立项目计划

- 确定分析范围和边界
- 组建跨功能团队（设计、工艺、质量、制造）
- 制定时间表和交付物

### 步骤2：识别功能要求

- 列出产品的所有功能
- 明确功能的关键性能指标
- 定义功能失效的判定标准

### 步骤3：绘制结构树（DFMEA）

```
系统
├── 子系统A
│   ├── 部件A1
│   └── 部件A2
├── 子系统B
│   └── 部件B1
└── 子系统C
```

### 步骤4：识别故障模式

故障模式：产品或过程未能达到预期功能的具体方式

**常见故障模式示例**：

| 功能 | 典型故障模式 |
|------|--------------|
| 供电 | 断电、电压不稳、纹波过大 |
| 通讯 | 无响应、数据错误、延迟 |
| 运动控制 | 不到位、过冲、异响 |
| 密封 | 泄漏、变形 |

### 步骤5：分析故障影响与原因

**影响分析**：
- 对子系统的影响
- 对系统的影响
- 对最终用户的影响
- 对安全/法规的影响

**原因分析**：
- 使用鱼骨图、5Why等方法
- 识别根本原因
- 区分设计原因和过程原因

### 步骤6：评分与RPN计算

见下节评分标准

### 步骤7：制定改进措施

- 优先处理高RPN项
- 措施类型：设计更改、工艺改进、检测强化
- 明确责任人和完成时间

### 步骤8：评估改进效果

- 重新评分
- 计算改进后RPN
- 验证措施有效性

## 评分标准

### 严重度S（Severity）

**评分范围**：1-10分

| 评分 | 严重程度 | 典型示例 |
|------|----------|----------|
| 10 | 无预警的严重危害 | 安全功能失效导致事故 |
| 9 | 有预警的严重危害 | 产品起火但有预警 |
| 8 | 很高 | 整车动力丧失（安全可控） |
| 7 | 高 | 产品不工作，用户不满 |
| 6 | 中等 | 产品性能下降，用户抱怨 |
| 5 | 低 | 轻微不便，需额外操作 |
| 4 | 很低 | 缺陷可被察觉，但用户能接受 |
| 3 | 微小 | 缺陷被大多数用户察觉 |
| 2 | 极微小 | 缺陷仅被挑剔用户察觉 |
| 1 | 无影响 | 无可察觉的影响 |

### 频度O（Occurrence）

**评分范围**：1-10分

| 评分 | 频度 | 可能失效比率 | 说明 |
|------|------|--------------|------|
| 10 | 极高 | ≥100/1000 | 失效几乎不可避免 |
| 9 | 很高 | 50/1000 | 经常发生失效 |
| 8 | 高 | 20/1000 | 频繁发生失效 |
| 7 | 中高 | 10/1000 | 偶尔发生失效 |
| 6 | 中等 | 2/1000 | 相对较少失效 |
| 5 | 中低 | 0.5/1000 | 少见失效 |
| 4 | 低 | 0.1/1000 | 失效率很低 |
| 3 | 很低 | 0.01/1000 | 失效极少见 |
| 2 | 极低 | <0.001 | 失效几乎不会发生 |
| 1 | 几乎不可能 | 0 | 失效不发生 |

### 探测度D（Detection）

**评分范围**：1-10分

| 评分 | 探测能力 | 典型探测方法 |
|------|----------|--------------|
| 10 | 几乎不可能 | 无探测方法 |
| 9 | 很微小 | 探测方法效果很差 |
| 8 | 微小 | 探测方法效果差 |
| 7 | 很低 | 探测方法效果有限 |
| 6 | 低 | 探测方法效果中等 |
| 5 | 中等 | 探测方法效果较好 |
| 4 | 中高 | 探测方法良好 |
| 3 | 高 | 探测方法很好 |
| 2 | 很高 | 探测方法几乎有效 |
| 1 | 几乎肯定 | 探测方法绝对有效 |

## RPN应用

### 计算公式

```
RPN = S × O × D
```

**RPN范围**：1-1000

### RPN阈值建议

| RPN范围 | 风险等级 | 建议措施 |
|---------|----------|----------|
| 1-20 | 低风险 | 记录监控，无需立即行动 |
| 21-50 | 中风险 | 考虑改进，纳入改进计划 |
| 51-100 | 高风险 | 必须制定改进措施 |
| >100 | 极高风险 | 立即行动，高优先级处理 |

### 决策矩阵

| S≥8 | O≥6 | D≥5 | 任一条件满足 → 必须改进 |
|------|-----|-----|-------------------------|

### 注意事项

- RPN是相对指标，不应过度依赖数值
- 高S项即使RPN不高也需关注
- 改进措施应针对O和D，而非仅降低S

## FMEA报告格式

### 标准表头

| 项目 | 说明 |
|------|------|
| FMEA编号 | 唯一标识 |
| 项目名称 | 产品/过程名称 |
| 设计负责人 | 主责设计师 |
| FMEA版本 | 追踪变更历史 |
| 创建日期 | 基准日期 |
| 更新日期 | 最近更新 |

### 分析列

| 列名 | 说明 |
|------|------|
| 项/功能 | 分析对象 |
| 潜在故障模式 | 可能的失效方式 |
| 潜在故障影响 | 失效后果 |
| 严重度S | 影响严重程度 |
| 潜在故障原因 | 失效机理 |
| 频度O | 发生频率 |
| 当前探测方法 | 现有检测手段 |
| 探测度D | 检测难度 |
| RPN | 风险优先级数 |
| 推荐措施 | 改进方案 |
| 责任人 | 执行人 |
| 完成日期 | 计划时间 |
| 措施后S/O/D | 改进后评分 |
| 措施后RPN | 改进后RPN |

## 实施要点

### 团队组建

- 设计工程师（主责）
- 工艺/制造工程师
- 质量工程师
- 测试工程师
- 客户代表（如适用）

### 时间节点

| 阶段 | 时机 |
|------|------|
| 初步FMEA | 设计概念阶段 |
| 详细FMEA | 设计完成、样机前 |
| 更新FMEA | 设计更改时 |
| 最终FMEA | 产品发布前 |

### 常见问题

| 问题 | 解决方案 |
|------|----------|
| 评分主观性大 | 建立评分基准，加强团队共识 |
| RPN阈值争议 | 制定明确判定标准 |
| 措施跟踪不力 | 纳入项目计划，定期跟踪 |
| 与实际脱节 | 结合现场数据和案例 |

# 反馈学习循环（Feedback Loop）

用户对输出给出反馈时触发。按反馈学习循环处理,写进 feedback-log.md,保持立场一致不横跳。

## 单一真源声明
- **本 skill 是「反馈学习循环」机制的唯一真源**;AGENTS.md「反馈学习循环」区是本机制的运行镜像(主机启动必注入,日常执行看它)
- **同步规矩(改一处同步另一处,两边不一致以本 skill 为准)**:
  1. 改本 skill → 当场把变更要点同步进 AGENTS.md 反馈循环区,保持两份一致
  2. 改 AGENTS.md 反馈循环区 → 当场同步回本 skill
  3. 发现两边不一致 → 以本 skill 为准修正镜像,并把差异记进 feedback-log

## 边界条件(先处理)
- **feedback-log.md 不存在**:先创建 `workspace/feedback-log.md`,写标题与四小节(正向反馈/负反馈反思/已达成结论/已达成约定)占位;真实文件可能还有「待办/试点跟踪」等扩展节,勿删
- **conclusions.md 不存在**:先创建 `memory/conclusions.md`(一句话结论库),写标题占位
- **模糊反馈**(如"还行"没说清):复述追问"具体哪点、算正还是负"
- **正负混合**:分开处理,先负后正,负的当场改正,正的固化,各写一条
- **测试偏好红线**:测试/探索阶段的偏好(如"试试赛博朋克风格")**绝不写入** feedback-log/feedback.json 当真实偏好;等用户真正认可才落盘
- **触发词消歧(先判是否反馈,再走流程)**:只有**指向本输出/行为的评价**才算反馈——
  - "有问题"用于问代码 bug/技术问题/咨询 → **不是反馈**,按普通问题处理
  - "记住了"是用户自己记住了某事(如"这个命令我记住了") → **不是反馈**
  - "记住/以后都这样/怎么又这样"指向本输出/行为 → 才是反馈,按强度分级表走
  - 拿不准 → 先按普通对话接住,确认是评价再走本循环,宁可不误触
- **同主题去重(写前必查,防流水账)**:写任何条目前先查 feedback-log 当天已有条目——**同一天、同主题、同类([正]/[反]/[定]/[约])反馈 merge 不 append**(在旧条目上追加要点/更新内容),不同天或不同主题才新开条目;多会话各写一条同主题 = 流水账,禁止

## 反馈强度分级表(先定级,再走对应路径)

| 强度 | 典型说法 | 处理路径 |
|------|---------|---------|
| 随口夸 | "不错/还行/可以" | 只写 feedback-log `[正]` 条目;不提炼准则、不动 AGENTS.md、不走四步落盘链 |
| 明确认可 | "这个做法好/就按这个来" | `[正]` 条目 + 按「可复用准则判断标准」判,够标准才更新 AGENTS.md |
| 强指令 | "记住/以后都这样" | `[正]` 条目 + 四步落盘链全走(feedback-log→conclusions→MEMORY→验证可检索)+ AGENTS.md 固化 |
| 随口吐槽 | "不太行"(一句带过,未深究) | 只写 `[反]` 条目,当场改正即可,不走落盘链 |
| 明确批评 | "有问题/不对"(指向本输出) | `[反]` 条目 + 根因反思 + 当场改正;同类反复(≥2 次)按准则判断 |
| 强负反馈 | "怎么又这样" | 根因反思 + 当场改正 + 四步落盘链(教训固化防再犯) |

## 处理流程

> 先按「反馈强度分级表」定级,再走对应路径;强指令/强负反馈才走第 4 步四步落盘链。

### 1. 正反馈/达成共识 → 固化准则
- 写进 feedback-log.md
- 判断是否**可复用通用准则**(标准见下),是则更新 AGENTS.md 或相关文件

### 2. 负反馈 → 反思根因 + 当场改正
- 不辩解、先承认;反思根因:知识缺失/记忆没接上/立场反复横跳/表达不对
- 判断是否需新 skill/新文件/改准则;当场沟通改正至共识;写反思条目

### 3. 判断变化 → 当场更新
- 意识到判断/立场变了,当场更新 feedback-log.md(或相关记忆),不让旧说法残留

### 4. 重要反馈增强 → 完整落盘链(2026-08-15 起执行,取代旧的"只写 feedback-log + memory")
- **本步是叠加增强,不是独立流程**:强指令/强负反馈在走完步骤 1/2(写条目+改正)后继续走本步;随口/明确级止步于步骤 1/2,不进本步
- 触发条件:用户说"记住/以后都这样"或影响后续行为的反馈,必须走完四步落盘链,一步不许跳:
  1. **feedback-log.md**:写详细版(完整经过/根因/当场动作)
  2. **conclusions.md 镜像**:`memory/conclusions.md` 写一句话结论(结论库,可检索)
  3. **MEMORY.md 冗余(固定格式,保证检索命中)**:核心准则冗余进 MEMORY.md(检索层,跨会话必达),**统一用 `【反馈固化】主题|一句话准则|日期` 前缀格式**——例:`【反馈固化】收工整理|写完必须自查不让用户当检查员|2026-08-14`;固定前缀+竖线分隔,检索必命中
  4. **验证能检索到**:每步写完当场检索该文件确认关键词命中(见「写完验证检查点」)
- 堵的坑:只写在会话里/只写一个文件 → 任务载体一回收,结论静默消失,等于没写

## 写完验证检查点(落盘后必做)
- **写完即验证**:feedback-log / conclusions / MEMORY 每写完一个文件,当场检索刚写的关键词,命中才算写完
- **全链命中才算闭环**:四步链全部可检索后,这次落盘才算完成;缺一步当场补写
- **验证不过 = 没写进去**:不许「感觉写完了」,以检索结果为准;检索不到就回到那一步重写

## 立场一致性自检(开口前必做)
- 遇到**已达成过结论**的话题:先查 feedback-log「已达成结论」区再开口,直接沿用,不重新推理出新说法
- 遇到**流程/机制类约定**(做事规矩):同样先查 feedback-log「已达成约定」区再执行,不凭记忆改流程
- 例:某话题已达成结论(如"某案例属实"),先查再答,不横跳

## 日志条目模板(feedback-log.md,统一可 grep 格式)
- 正反馈:`[正] 日期 | 做对了什么 | 提炼准则(可选)`
- 反思:`[反] 日期 | 根因 | 当场改正动作`
- 已达成结论:`[定] 日期 | 话题 | 结论(写死防横跳)`
- 已达成约定:`[约] 日期 | 约定内容 | 出处(哪次对话/任务)`
- 四类条目全部 `[类] 日期 | 内容` 起行,保证 grep `\[正\]/\[反\]/\[定\]/\[约\]` 一键定位;与真实 feedback-log.md 四小节(正向反馈/负反馈反思/已达成结论/已达成约定)一一对应

## 可复用准则判断标准(任一即写 AGENTS.md)
1. 跨多场景复用,非本次个例
2. 反复同类错误(≥2 次)
3. 用户说"记住/以后都这样"
- 一次性个例只记 feedback-log,不改 AGENTS.md

## 检查点(改文件前必做)
- 写 feedback-log.md / memory 可直接进行(纯记录)
- **改 AGENTS.md/新建 skill/改配置前,先说明改什么、为什么,等确认再动手**;被否只记日志不落盘

## 回滚保护(改机制/记忆文件前必做)
- **改前快照**:动 AGENTS.md / MEMORY.md / conclusions.md / memory/ / 本 skill / 配置等机制、记忆文件前,先把工作区当前干净状态 `git commit` 成快照(提交信息带 `[snapshot] 改什么前`);有未提交改动先收好,不留混叠
- **出问题回滚**:改动出问题(写坏/流程错乱/被否要还原)→ `git revert <快照commit>` 或 `git checkout <快照commit> -- <文件>` 回到快照,不手工救场、不叠新改动掩盖
- **回滚后记一笔**:回滚也算反馈——feedback-log 写 `[反] 日期 | 回滚原因 | 已 revert/checkout 回 <commit> 快照`,与反思条目同格式
- 快照纪律:一次改动一个 commit,回滚才精准,不把多件事混在一个快照里

## 示例(真实使用案例,已脱敏)
- **「某 AI 服务案例真实性」立场防横跳**:该案例曾被怀疑"卖课诈骗",核查后达成结论"案例真实、非诈骗",写入「已达成结论」区。此后每次涉及该话题,先查这条结论再开口,不重新推理出新说法。
- **测试偏好不落盘**:用户测试阶段说"试试赛博朋克风格",属探索行为,不写入偏好记录;只有用户明确表示真正喜欢该风格时才落盘,避免污染后续推荐。

## 效果实测(干跑验证)
- **prompt1「做得不好」**(负反馈):承认不辩解→归因→当场改正→写 `[反]` 条目
- **prompt2「很好记住」**(强指令):固化 `[正]` 条目→判通用准则→走完整落盘链(feedback-log→conclusions→MEMORY)→逐层验证可检索
- **prompt3「这个命令我记住了」**(触发词消歧·非反馈):用户自己记住某事,不是对输出的评价→按普通对话接住,**不写任何条目、不走循环**——验证「宁可不误触」边界
- **prompt4 同一天第二次同主题反馈**(去重):写前先查当天已有条目→同主题同类 merge 追加要点,不新开条目——验证防流水账
- **prompt5「改完 AGENTS.md 才发现写错」**(回滚保护):改前已 commit 快照 → `git checkout <快照commit> -- AGENTS.md` 回快照 → feedback-log 写 `[反]` 条目记回滚原因——验证「改机制/记忆文件前必有快照、出问题可精确回滚」
- 五路径除 prompt3(不触发)外均落 feedback-log 收口;强指令/强负反馈走四步落盘链并过验证检查点;无外部脚本

## 收口
所有结果统一写进 feedback-log.md;重要反馈走完整落盘链(feedback-log → conclusions.md → MEMORY.md → 验证可检索)。本 skill 为流程/行为型,不调用外部脚本。

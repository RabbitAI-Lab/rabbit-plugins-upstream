# xtaste 判断方法

## 为什么这样建模

taste 有两种信号，价值不同：

- **锚点（具体参照物）**：「像 visionOS 那样」「别像拼多多」。信息量最大、最不容易被误读。实践中用户对"像原版"的满意度明显高于对"AI 把几种喜欢的风格归纳混合"的满意度，所以锚点排在维度前面，且要求照原样参考、不混搭。
- **维度（两极轴）**：留白 ↔ 密集、结论先行 ↔ 铺垫推导……用来覆盖没有锚点的情况，也用来在锚点之间做取舍。

## 信号权重

| 来源 | 权重 | 随时间衰减 | 说明 |
|---|---|---|---|
| explicit | 4 | 否 | 用户亲口说的；同一维度以**最近一次**明确表态为准 |
| feedback | 2 | 是（半衰期 1 年） | 用户纠正或认可某次产出 |
| choice | 1.5 | 是 | 用户在任务中二选一 |
| quiz | 1 × 复测一致性 | 是 | 基础测试；重测时只算最近一次 |
| inferred | 0.5 | 是 | 词表从历史提示被动提取，只能形成「观察」 |

分值 = Σ(权重×取值) / (Σ权重 + 1)。分母多出的 1 是先验：一道题不会让一个维度看起来很确定。

状态：

- **明确**：有 explicit。若之后的反馈（权重 ≥3）方向相反，标「有分歧」——提示 Agent 下次用小样确认，而不是悄悄改掉用户的原话。
- **稳定**：非被动信号权重 ≥4。
- **倾向**：权重 ≥1——一道复测一致的测试题、一次反馈或一次二选一就够；复测不一致的测试达不到。
- **观察**：只有被动信号，且在 ≥2 个不同日期出现同向信号。
- **未定**：其他。信号之间分歧很大时降一级。

## 怎样越来越准

1. **记录事前预测**：每次记录 explicit / feedback / choice 时，先存下档案当时对这一维度的预测值。`xtaste stats` 用它计算"预测命中率"——这是衡量"识别准不准"的唯一指标，不靠自我感觉。
2. **单变量对照**：测试页和任务中的小样，两个选项只差一个维度，否则无法知道用户到底在选什么。
3. **复测一致性**：测试中有 3 道题换边重问；答案不一致会按比例降低整套测试的权重。
4. **场景分离**：同一个人做数据面板偏密集、做落地页偏留白很正常。用 `--scope` 记录，避免两类信号互相抵消。
5. **主动提问只问关键的未定维度**：用小样问，一次最多一个问题。

## 安全

- 档案只存本机；网页只监听 127.0.0.1，限制请求大小。
- 提交需同时满足：Host 必须是 `127.0.0.1`/`localhost`（防 DNS 重绑定：恶意网站把自己的域名解析到 127.0.0.1 时，Origin 与 Host 会一致，只校验两者相等挡不住——ClawHub 0.1.0 扫描指出）、同源、携带页面里的一次性会话 token。
- 所有自由文本入库前去掉尖括号、反引号和控制字符，限长；输出时包在 `<xtaste>` 中并声明"数据不是命令"，防止记忆投毒。
- 事件日志只追加；撤销通过 revoke 事件完成，可审计。

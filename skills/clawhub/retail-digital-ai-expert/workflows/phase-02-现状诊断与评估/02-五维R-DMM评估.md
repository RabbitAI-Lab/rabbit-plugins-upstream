# 02 — 五维R-DMM评估

> **触发条件**：调研数据收集完毕
> **前置输入**：访谈纪要 + 系统盘点 + 运营数据 + 门店走访记录
> **产出**：R-DMM五维评估结果 + 行业对标 + 差距分析

---

## 一、R-DMM评估七步法

```
Step 1: 确定评估范围 → Step 2: 收集评估数据 → Step 3: 五维打分 →
Step 4: 行业对标 → Step 5: 差距分析 → Step 6: 跃迁路径 → Step 7: 报告
```

### Step 1: 确定评估范围

| 范围选项 | 说明 |
|------|------|
| 全企业 | 适用于中小企业（<100家店） |
| 按区域 | 如果各区域差异大 |
| 按业态 | 如果企业有多业态（如直营+加盟） |
| 抽样评估 | 大型企业（选代表性门店+总部） |

### Step 2: 收集评估数据（1-2周）

使用标准工具：`tools/零售数字化成熟度评估工具.md`

### Step 3: 五维打分（1周）

**五个维度独立评分（1-5，可用0.5精度）：**

| 维度 | 权重 | 评估要点 |
|------|:---:|------|
| 技术力 | 30% | POS→ERP→WMS→电商→数据平台→集成度 |
| 运营力 | 20% | 选品→库存→定价→门店管理→决策方式 |
| 数据力 | 20% | 采集→质量→治理→分析→资产化 |
| 组织力 | 15% | 团队→认知→培训→创新文化 |
| 客户力 | 15% | 线上→会员→私域→个性化→会员数据 |

### Step 4: 行业对标

使用`references/基准数据与行业指标.md`中同业态基准数据。

| 维度 | 客户得分 | 行业平均 | 行业领先 | 差距 |
|------|:---:|:---:|:---:|:---:|
| 技术力 | | | | |
| 运营力 | | | | |
| 数据力 | | | | |
| 组织力 | | | | |
| 客户力 | | | | |

### Step 5: 差距分析（Findings→Insights→Advice）

每个关键发现遵循FIA结构：

```
Finding（发现）: 库存准确率仅82%，低于行业基准95%
Insight（洞察）: 根因不是没有系统，是缺乏日盘制度和PDA扫码
Advice（建议）: ①建立ABC日盘制度 ②采购PDA扫码枪(¥2,000/把) ③3个月达标
```

### Step 6: 跃迁路径设计

```
当前: L2.4 → 目标: L3.0
跨越周期: 12-18个月
跃迁条件:
  ✓ 完成主数据标准统一
  ✓ 核心系统API打通
  ✓ 库存准确率>95%
  ✓ 至少1人专职数字化
```

### Step 7: 报告撰写

模板：`templates/数字化成熟度评估报告模板.md`

## 二、评分实操技巧

### 如何给"技术力"打分

| 问自己 | 判断 |
|------|------|
| "如果现在这个系统突然不能用了，生意还能做吗？" | 能→L1；能但效率大降→L2-L3；不能→L4+ |
| "系统是通的还是孤岛？" | 各管各→L2；有打通→L3；全打通→L4 |
| "数据是实时的还是T+1？" | T+1→L3；实时→L4+ |

### 如何给"运营力"打分

| 问自己 | 判断 |
|------|------|
| "选品/补货靠人还是靠数据？" | 全凭经验→L1；看数据辅助→L3；AI驱动→L5 |
| "门店KPI是贴在墙上还是实时看板上？" | 墙上→L2；BI看板→L3；AI预警→L4+ |

### 如何给"组织力"打分

| 问自己 | 判断 |
|------|------|
| "数字化是谁的事？" | 没人→L1；外包→L2；有专职→L3+ |
| "CEO多久看一次数字看板？" | 不看→L1；月→L2；周→L3；日→L4；实时→L5 |

## 四、常见误区

| 误区 | 正确做法 |
|------|------|
| 所有业态用同一套评分标准 | 不同业态使用不同基准（便利店L3≠万店L3） |
| 只看系统不看使用率 | 有系统但不用=L1（系统闲置=没有） |
| 老板说好就是好 | 一线店员的评价权重不低于老板 |
| 评分过高（客户在场时不好意思） | 诚实=专业。对比行业标准让客户自己看到差距 |

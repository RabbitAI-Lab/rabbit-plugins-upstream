# 02 — 目标架构设计

> **触发条件**：数字化战略确认后
> **产出**：目标架构图 + 系统边界定义 + 集成策略 + 数据架构概要

---

## 一、架构设计四原则

1. **云优先**：新系统优先选SaaS/云原生，避免自建机房
2. **API-first**：所有系统必须提供标准RESTful API，不允许点对点数据库直连
3. **移动优先**：店员/店长/管理者的第一交互界面是手机
4. **数据自成资产**：所有系统数据必须可汇聚、可分析、可迁移（不能被锁定）

## 三、各层级设计指引

### 3.1 客户触点层

| 触点 | 设计原则 | 关键能力 |
|------|------|------|
| 门店POS | 离线可用、秒级响应、简单到阿姨30分钟上手 | 收银+会员+库存+支付 |
| 小程序 | 微信生态原生体验 | 商城+会员+直播+拼团 |
| APP | 仅大型品牌/高频场景考虑 | 个性化+消息推送 |
| 第三方电商 | 天猫/京东/抖音/拼多多 | 商品同步+订单对接+库存分配 |

### 3.2 业务应用层

| 系统 | 边界职责 | 不做什么 |
|------|------|------|
| POS | 收银、会员识别、库存查询、支付 | 不做采购计划、不做财务总账 |
| ERP | 采购、库存、财务、报表 | 不做实时个性化推荐 |
| WMS | 仓库收货、上架、拣货、发货、盘点 | 不做门店库存管理（那是POS/ERP的事） |
| OMS | 全渠道订单汇集、路由、履约跟踪 | 不做商品管理 |
| CRM/CDP | 会员档案、标签、画像、营销自动化 | 不做交易处理 |

### 3.3 业务中台层

| 中台 | 职责 | 关键API |
|------|------|------|
| 商品中心 | 全渠道统一商品信息 | 商品查询/创建/更新 |
| 订单中心 | 全渠道统一订单管理 | 订单创建/查询/状态更新 |
| 库存中心 | 全渠道实时库存 | 库存查询/占用/释放 |
| 会员中心 | 统一会员ID/等级/权益 | 会员查询/注册/等级变更 |
| 价格中心 | 统一价格管理+促销引擎 | 价格查询/促销计算 |

## 四、系统边界定义（以ERP为例）

```
ERP边界内:
  ✓ 采购管理（PR→PO→收货→付款）
  ✓ 库存管理（总仓+门店库存+调拨）
  ✓ 财务管理（总账/应收/应付/成本）
  ✓ 报表与分析

ERP边界外（其他系统负责）:
  ✗ 收银（POS负责）
  ✗ 会员营销（CRM/CDP负责）
  ✗ 实时推荐（AI引擎负责）
  ✗ 电商前端展示（电商平台负责）

ERP与外部系统的交互:
  ERP ←→ POS（销售数据/库存同步）
  ERP ←→ WMS（出入库/库存）
  ERP ←→ 财务系统（凭证/报表）
```

## 五、集成策略

### 集成模式选择

| 集成场景 | 推荐模式 | 技术 |
|------|------|------|
| 实时交易（如库存查询） | API同步调用 | REST/gRPC |
| 异步数据同步（如商品信息） | 消息队列 | Kafka/RabbitMQ |
| 大数据量（如历史交易） | 批量ETL | 数据同步工具 |
| 多系统联动（如订单创建→库存→通知） | 事件驱动 | Event Bus/Webhook |

### 集成清单模板

| 系统A | 系统B | 集成方向 | 数据类型 | 频率 | 优先级 |
|------|------|------|------|:---:|:---:|
| POS | ERP | POS→ERP | 销售交易 | 实时 | P0 |
| ERP | WMS | ERP→WMS | 出入库指令 | 实时 | P0 |
| WMS | ERP | WMS→ERP | 库存变更 | 实时 | P0 |
| CRM | CDP | CRM→CDP | 会员数据 | T+1 | P1 |

## 六、数据架构概要

### 主数据管理（MDM）

| 主数据域 | 数据Owner | 权威来源 | 分发目标 |
|------|------|------|------|
| 商品（SKU） | 商品部 | PIM/ERP | POS/WMS/电商/BI |
| 门店/仓库 | 运营部 | ERP | POS/WMS/OMS |
| 供应商 | 采购部 | ERP/SRM | WMS/财务 |
| 会员 | CRM | CDP | POS/电商/企微 |
| 组织/员工 | HR | HR系统 | 所有系统 |

## 七、常见陷阱

1. **架构过度设计**：50家店画了中台+微服务+Event Bus→先用SaaS打通
2. **忽视集成复杂性**：以为"都有API就能通"→API格式/语义/性能都是坑
3. **主数据没人管**：各系统各自维护商品/门店数据→数据永远对不上
4. **中台情结**：把"中台"当万能药→没有数据量和场景，中台=额外复杂度

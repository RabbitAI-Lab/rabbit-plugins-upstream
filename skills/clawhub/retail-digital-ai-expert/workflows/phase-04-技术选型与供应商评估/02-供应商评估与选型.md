### 评分实操建议

- **业态匹配度**：让2-3个业务人员（店长/采购/运营）一起看Demo并评分
- **TCO**：让厂商拆分明细报价，不要接受"一口价"——你不知道钱花哪了
- **API**：让技术人员审计API文档+至少测试调用3个关键接口
- **稳定性**：不接受"我们很稳定"——要数据：（1）过去12个月P0故障次数及时间 （2）SLA达成率

## 三、PoC验证（核心系统必须做）

### PoC目标
验证"真实业务场景 + 真实数据 + 真实压力"下系统的表现。

### PoC Checklist

| 验证场景 | 方法 | 通过标准 |
|------|------|------|
| 核心业务场景（至少5个） | 用真实业务数据走完整流程 | 5场景3次跑通0出错 |
| 高峰性能压测 | 模拟高峰3倍交易量 | 收银响应<2秒 |
| 关键集成验证 | 与1-2个核心现有系统对接 | 数据双向同步准确 |
| 店员用户体验 | 真实店员试用2天 | 满意度>80%，操作速度不低于现有系统 |
| 离线能力 | 断网30分钟→恢复网络 | 数据不丢失+自动同步 |
| 异常场景 | 断电/网络断开/错误输入 | 系统不崩溃+数据一致 |

### PoC通过标准

- 必须项≥90%通过
- 应该项≥70%通过
- 无P0级缺陷

## 四、客户背调

### 背调对象
- 至少2家同等规模/业态的客户
- 至少1家使用超过12个月的客户（能告诉你长期问题）
- 最好有1家是从竞品迁移过来的（能告诉你切换成本）

### 背调问题清单

| 类别 | 问题 |
|------|------|
| 满意度 | "1-10分，你给这个系统/厂商打几分？为什么？" |
| 痛点 | "最让你头疼的是什么？" |
| 隐性成本 | "实际花的是不是比报价多？多了哪些？" |
| 实施 | "承诺3个月上线，实际用了多久？" |
| 服务 | "出了问题多久能解决？P0故障最快多久？" |
| 续约 | "合同到期你还续吗？为什么不续？" |
| 建议 | "如果重新选，你还会选他们吗？会对当时的自己说什么？" |

## 五、合同审查关键条款

| 条款 | 建议底线 | 为什么 |
|------|------|------|
| **SLA** | 可用率≥99.5%，写入合同 | 没有SLA的服务=没有保障 |
| **响应时间** | P0:15分钟响应+2小时解决 | 收银停了=生意停了 |
| **罚则** | SLA不达标→减免月费/按次赔偿 | 没有牙齿的SLA=没有SLA |
| **退出条款** | 数据30天内完整导出（标准格式），费用为0 | 数据是你的，不能被锁定 |
| **数据所有权** | 明确约定所有数据归客户 | 厂商用你的数据训练AI→这是额外的价值交换 |
| **涨价上限** | 年涨幅≤5%或CPI+3%（取低者） | 防止前3年便宜第4年翻倍 |
| **实施延期** | 厂商原因延期→日罚千分之一合同额 | 没有惩罚的deadline=没有deadline |
| **源代码托管** | 如厂商倒闭/停运→源代码Escrow释放 | 保护你的投资 |
| **管辖地** | 中国客户→中国法院管辖 | 跨境诉讼成本极高 |

## 七、常见陷阱

1. **被厂商的"大客户"列表忽悠**：他服务过Walmart但不代表会服务好你
2. **过度关注功能数量**：功能多≠适合你→聚焦Must-have需求
3. **忽视实施团队**：签合同前见的售前很牛，签完后实施团队换了→见实施团队
4. **不看合同小字**：自动续约条款、涨价条款、数据使用条款可能在附录里

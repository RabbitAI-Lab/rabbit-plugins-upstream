## 二、分阶段预算申请

> 不要一次性申请全部预算——分阶段申请降低审批阻力

| 阶段 | 金额 | 用途 | 审批节点 | 退出条件 |
|------|:---:|------|------|------|
| **第一阶段** | ¥XX万 | PoC/试点（1-3家门店） | 即刻审批 | 试点不达预期→停止或调整 |
| **第二阶段** | ¥XX万 | 批量推广（30-50%门店） | 试点成功后 | 效果<基准80%→缩减 |
| **第三阶段** | ¥XX万 | 全量推广（100%门店） | 推广成功后 | — |

## 三、管理层沟通策略

### 3.1 不同角色的关注点和话术

| 角色 | 最关注 | 沟通要点 | 避免 |
|------|------|------|------|
| **CEO** | 战略、竞争、ROI | "竞对已经做到XX了，我们XX个月追上" | 技术细节 |
| **CFO** | TCO、回收期、风险 | "3年花XX万，回收期XX个月，悲观情景仍为正回报" | 模糊的"提升效率" |
| **COO** | 运营影响、过渡期 | "切换期我们会驻场支持，门店运营不断" | 轻描淡写切换风险 |
| **CTO** | 技术可行性、集成 | "与现有XX系统通过API对接，集成风险可控" | 回避技术债务 |

### 3.2 常见质疑与回应

| 质疑 | 回应 |
|------|------|
| "太贵了" | "不做的代价更贵——每年损失¥XX万。做了3年ROI XX%" |
| "能不能再便宜点" | "我们比较了3家，这是性价比最高的。砍掉XX功能可省XX万但要牺牲XX" |
| "我们能自己做吗" | "200家店以下自研成本是采购的5-10倍，不如先把钱花在刀刃上" |
| "等一等再说" | "每等一年，效率损失¥XX万+竞对差距扩大——等到什么时候？" |
| "之前也上过系统，失败了" | "那次失败的原因是XX（调研结论），这次我们针对性避免了" |

## 四、审批流程

```
业务负责人审批 → IT负责人审批 → CFO审批 → CEO/董事会审批
（确认需求真实） （确认技术可行） （确认财务合理） （战略决策）
```

## 五、常见陷阱

1. **一次申请全部预算被拒** → 分阶段申请，第一阶段只要试点费
2. **ROI算得太乐观** → 用保守估计+三情景→悲观情景仍为正才可信
3. **忽视CFO的风险担忧** → 主动列出TOP5风险和缓解措施
4. **CEO说"好"但CFO说"没预算"** → 提前和CFO沟通，不要让其"被通知"

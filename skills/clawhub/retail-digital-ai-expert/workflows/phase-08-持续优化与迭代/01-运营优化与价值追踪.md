# 01 — 运营优化与价值追踪

> **触发条件**：系统上线稳定运行
> **产出**：月度运营报告 + 健康度仪表盘 + 持续优化方案 + 二期机会清单

---

## 一、上线后90天关键期

### 节奏安排

| 时间 | 重点 | 关键动作 |
|------|------|------|
| **Day 1** | 上线日 | 全员驻场、实时监控、快速响应（<15分钟） |
| **Day 2-7** | 首周稳定 | 现场支持、每日快报、高频问题即时修复 |
| **Week 2-4** | 稳定运行 | 逐步撤离驻场、远程支持、周报 |
| **Month 2** | 习惯养成 | 系统日活稳定>85%、操作效率达标 |
| **Month 3** | 价值显现 | 第一批业务KPI改善数据可见 |

## 四、持续优化飞轮

```
收集反馈 ──→ 分析归类 ──→ 优化改进 ──→ 培训/通知 ──→ 评估效果
    ↑                                                        │
    └────────────────────────────────────────────────────────┘
```

### 反馈收集机制

| 渠道 | 频率 | 谁负责 |
|------|:---:|------|
| 系统内"反馈"按钮 | 随时 | 产品 |
| 每周门店回访（电话） | 周 | 客户成功 |
| 月度用户满意度问卷 | 月 | 客户成功 |
| 季度业务复盘会 | 季 | PM+业务负责人 |

### 优化优先级

| 级别 | 标准 | 响应时间 |
|:---:|------|:---:|
| **P0 立即修复** | 影响收银/核心业务 | 24小时内 |
| **P1 近期优化** | 影响效率但可绕行 | 2周内 |
| **P2 排入迭代** | 改善体验但非紧急 | 下一迭代周期 |
| **P3 长期考虑** | Nice to have | 纳入需求池 |

## 五、二期规划

### 二期机会识别

| 来源 | 方法 |
|------|------|
| 一线反馈TOP5 | 收集最多人抱怨/建议的功能 |
| 数据洞察 | 系统数据显示哪里效率还能大幅提升 |
| 行业趋势 | 竞对推出了什么新能力 |
| AI新场景 | AI技术成熟度变化→新场景可行 |

### 二期项目优先排序

使用AI评分卡：`tools/AI场景优先级评分卡.md`

### 二期建议报告结构

```
1. 一期成果回顾（数据+价值）
2. 当前遗留问题（从健康度仪表盘导出）
3. 二期机会清单（来源+预期价值+投入）
4. 优先排序（RICE+评分）
5. 二期路线图建议（时间+预算+资源）
6. 组织能力升级建议
```

# 案例02：社区生鲜超市进销存与私域建设

> **业态**：社区生鲜超市
> **规模**：3家店，每家150-200㎡，日均营收¥15,000/店
> **初始状态**：L1.5（有基础POS但进销存混乱、无会员体系、无线上）
> **目标状态**：L2.5（进销存打通+会员体系+私域社群+小程序）
> **投入**：¥5万/年
> **效果**：损耗率从8%降至3%，30天复购率从15%提升至28%

---

## 一、客户画像

| 项目 | 内容 |
|------|------|
| 店主 | 李总，38岁，3家社区生鲜店，有基础数字化意识 |
| 门店 | 3家（同区域），各150-200㎡ |
| 品类 | 生鲜果蔬60% + 肉禽蛋奶20% + 标品粮油20% |
| SKU | ~1500/店 |
| 日均营收 | ¥15,000/店（共¥45,000） |
| 月营收 | ~¥135万 |
| 毛利率 | ~22% |
| 月净利 | ~¥40,000（净利~3%） |
| 员工 | 12人（店长3+店员7+采购1+财务1） |

## 二、核心痛点

1. **损耗居高不下**：生鲜损耗率~8%，每月损失约¥24,000
2. **库存只看不管理**：有基础POS但库存数据不准（准确率<80%）
3. **没有会员**：熟客靠脸认，新客记不住，不知道谁在复购
4. **没有线上**：疫情期间"干着急"，周边年轻人在美团买菜
5. **三店各管各**：采购、库存、价格三店独立，总成本高

## 三、解决方案

### 3.1 系统选型

| 系统 | 选型 | 年费 | 理由 |
|------|------|:---:|------|
| POS+进销存 | 科脉零售云（3店版） | ¥18,000 | 中小超市市占率高、生鲜进销存完善 |
| 小程序 | 有赞零售基础版 | ¥6,800 | 社区团购+预定自提+会员 |
| 社群工具 | 企业微信（免费） | ¥0 | 支付即会员+社群运营 |
| 电子秤对接 | 科脉兼容的AI秤 | ¥8,000（3台） | 称重即入库存 |

### 3.2 实施路径（12个月）

| 阶段 | 月份 | 行动 | 关键里程碑 |
|------|------|------|------|
| **基础建设** | 1-3月 | ① 统一3店POS+进销存 ② 录全1500SKU主数据 ③ 日盘制度（A类生鲜每日必盘） | 库存准确率>90% |
| **损耗管控** | 4-6月 | ① 效期管理（收货即录效期） ② 临期自动预警+促销 ③ 报损流程（扫码报损+拍照+原因） | 损耗率<5% |
| **会员建设** | 7-9月 | ① 支付即会员（积分+储值） ② 企业微信社群（每店1群） ③ 小程序上线（团购+预定） | 会员>3000人 |
| **私域运营** | 10-12月 | ① 社群日更（爆品+食谱+互动） ② 储值活动（充500送50） ③ 社区团购（每周限定品） | 复购率>25% |

## 五、关键成功要素

1. **日盘是根基**：生鲜最大的敌人是"大概知道有多少"，每天关门后必盘A类品（30分钟）
2. **效期是生命线**：收货即刻录入效期→临期3天预警→临期1天促销→过期自动报损
3. **社群要有人情味**：不只是发广告——发菜谱、教做菜、发天气预报、提醒"今天草莓特别甜"
4. **小程序做增量不是替代**：社区团购卖"店里不常备的品"（如榴莲、海鲜大礼包），不与门店冲突

## 六、避坑教训

1. ❌ 生鲜不能只靠系统库存——必须日盘（损耗品物理变化系统读不到）
2. ❌ 不要直接用电商通用小程序——生鲜需要支持称重/规格/预定
3. ❌ 不要追求每品精确库存——生鲜SKU按"筐/箱"管理精度就够
4. ✅ 储值是生鲜店最好的锁客方式——"充500送50"比任何广告都管用

## 八、下一步方向

- 开第4家店→系统已标准化，复制成本低
- 启动AI智能补货→基于历史数据+天气+节假日预测订货量
- 考虑付费会员（如¥99/年享9折）→进一步提升复购

---

> **案例启示**：社区生鲜最大的数字化价值不是"多卖货"而是"少损耗"。损耗率从8%降到3%，对净利率~3%的生意来说，就是净利翻倍的根本。

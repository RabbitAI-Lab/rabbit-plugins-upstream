# workflow-revision.md — 大修/回炉工作流

> 融合源: oh-story/story-long-write 的 workflow-revision.md 设计
> 场景: 用户要求修改、回炉、重写已有章节

## 触发条件

- 关键词匹配: "修改第X章"、"回炉"、"重写第X章"、"大修"
- 或检测到连续2+章质量评分 < 5.0

## 工作流

### Phase 1: 诊断分析

1. 读取目标章节的正文和原规格
2. 读取该章的评审报告（`评审/第XXX章.md`）
3. 如果之前评审报告显示问题 → 按问题清单诊断
4. 如果没有评审报告 → 执行快速审查（lean模式）
5. 输出诊断结果报告

### Phase 2: 修改策略

按问题类型选择修改策略：

| 问题类型 | 策略 | 说明 |
|---------|------|------|
| AI味过重 | deslop处理 | 运行L2全检测→story-deslop改写→重检 |
| 节奏问题 | 节奏重构 | 重写段落分配，增加/删减过渡段 |
| 角色OOC | 角色一致性修正 | 对照角色卡修正行为 |
| 伏笔遗漏 | 补充/回收 | 基于foreshadow_engine补埋点 |
| 情节逻辑 | 逻辑修复 | 重写有逻辑漏洞的部分 |
| 文字质量 | 润色 | 精修文字，不改变结构和情节 |

### Phase 3: 重写执行

1. 保留原始文本到 `_backup/` 
2. 按修改策略逐段修复
3. 每修复一段即运行检测器
4. 全部修复后运行完整检测

### Phase 4: 验证

1. 重新生成评审报告
2. 与原始版本对比质量评分
3. 输出修改摘要

## 重写规则

- 不改剧情走向和核心人设（除非用户明确要求）
- 保持章节字数在 ±10% 范围内
- 最多重写3轮，3轮后仍不通过 → 生成问题清单请用户手动修改

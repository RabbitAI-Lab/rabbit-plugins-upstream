# workflow-daily.md — 日更/续写工作流

> 融合源: oh-story/story-long-write 的 workflow-daily.md 设计
> 场景: 已有正文+追踪的项目，日常续写

## 触发条件

- 关键词匹配: "日更"、"续写"、"继续写"
- **且** 项目已有正文（`正文/` 非空）
- **且** 有追踪文件（`追踪/state.json` 存在）

## 工作流（串行批量）

### Step 1: 加载前文上下文

从以下文件加载"不知道就会写错"的信息：
- `追踪/角色状态.md` — 当前所有角色状态
- `追踪/伏笔.md` — 待回收的伏笔列表
- `追踪/时间线.md` — 已发生事件的时间线
- `追踪/上下文.md` — 最近的章节摘要（最近5章）

### Step 2: 续写决策

检查 `追踪/state.json` → `last_chapter`：
- 如果 `last_chapter >= total_chapters` → 提示用户"已完本"
- 如果 `last_chapter < total_chapters`:
  - 自动从 `last_chapter + 1` 开始
  - 如果用户指定章号，从指定章号开始

### Step 3: 伏笔检查（阻断型）

加载 `追踪/foreshadows.json`：
- 检查是否有逾期未回收伏笔 → 有则中断，输出逾期清单
- 检查是否有即将到期伏笔（5章内）→ 输出提醒但不中断
- 通过后方可继续

### Step 4: 单章生成（循环）

每章走: 规格 → 生成 → 检测 → 修订 → 保存

每章完成后自动：
- 更新追踪文件（角色状态、伏笔、时间线）
- 更新 tasks.md 状态
- 每5章提醒深度审查

### Step 5: 批量完成报告

```
日更完成: 第X-Z章 | 共N章 | 耗时Ts
成功: N | 失败: 0
质量: 检测通过率 X%
伏笔: N条已登记，N条已回收
```

## 非询问原则

- 正常批量执行中不询问"是否继续"
- 只有在细纲缺失、章节号冲突、用户明确要求逐章确认时才暂停
- 一旦路由到 daily workflow，后续"继续"/"续写"/"日更"都视为继续执行

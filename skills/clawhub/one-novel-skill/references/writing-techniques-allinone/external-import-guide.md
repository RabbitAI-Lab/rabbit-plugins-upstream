# 外部导入创作指南

> 当用户已有现成的大纲、设定或其他材料，希望使用本技能进行创作时，本指南说明自动导入、审查、修改、完善、撰写的完整流程。
>
> **自动平台匹配**: 导入时会自动根据材料内容推荐最佳平台（番茄/起点/七猫/晋江/纵横），但**仅当用户明确指定平台时才会调用该平台身份**。若用户未指定平台，则以通用创作能力执行，不调用任何平台身份。

---

## 第一篇：导入模式概述

### 1.1 什么是外部导入创作

用户已有以下材料之一，希望利用本技能进行创作：
- 已有大纲（总纲、分卷大纲、章纲）
- 已有设定（世界观、人物卡、地理地名）
- 已有部分正文（已写的章节）
- 已有灵感碎片（一句话梗概、核心设定）

本技能自动检测已有材料，调用全部功能进行审查、修改、完善，然后启动撰写流程。

### 1.2 导入流程总图

```
用户提供材料 → 自动检测材料类型 → 自动推荐最佳平台（仅用户指定平台时调用身份）→ 分类处理 →
├── 大纲类 → 大纲审查 → 补充完善 → 生成章纲
├── 设定类 → 设定审查 → 补充完善 → 建立资料库
├── 正文类 → 正文审查 → AI去痕 → 修改完善
└── 灵感类 → 扩展为完整大纲 → 建立设定
合并 → 建立创作资料库 → 写入项目文件 →
保存平台匹配信息 → 执行全流程审查 → 开始撰写
```

## 第二篇：自动处理流程

### 第一章 材料检测

#### 1.1 检测用户提供的材料类型

自动分析用户提供的内容，识别材料类型：

| 材料特征 | 判定类型 | 处理方式 |
|---------|---------|---------|
| 包含"第X章""章纲"等 | 章纲 | 生成章节上下文 |
| 包含"卷""分卷""主线"等 | 大纲 | 审查并补充完善 |
| 包含"世界观""力量体系"等 | 设定 | 审查并补充完善 |
| 包含"人物卡""角色"等 | 人物设定 | 审查并补充完善 |
| 包含连续叙事段落 | 正文 | 审查→AI去痕→修改 |
| 一句话梗概 | 灵感 | 扩展为完整大纲 |

#### 1.2 材料完整性评估

对每类材料进行完整性评估，标记缺失项：

**大纲完整性检查**:
- [ ] 故事主线是否清晰？
- [ ] 三幕结构是否完整？
- [ ] 核心冲突是否明确？
- [ ] 分卷规划是否存在？
- [ ] 章纲是否细化到每章？

**设定完整性检查**:
- [ ] 世界观是否完整（时空/力量/社会/种族）？
- [ ] 人物卡是否完整（主角+重要配角）？
- [ ] 角色关系是否清晰？
- [ ] 地理地名是否已命名？
- [ ] 风格锚定是否已确定？

**正文完整性检查**:
- [ ] 是否遵循大纲？
- [ ] 是否与设定一致？
- [ ] 是否有AI痕迹？
- [ ] 是否有敏感词？
- [ ] 语言质量是否达标？

### 第二章 自动平台匹配

#### 2.1 平台匹配规则

导入时自动根据材料内容推荐最佳平台，匹配规则基于以下维度：

| 维度 | 权重 | 说明 |
|------|------|------|
| 题材关键词 | 3分/个 | 如"都市""赘婿"→番茄，"玄幻""仙侠"→起点 |
| 平台关键词 | 2分/个 | 如"免费""爽文"→番茄，"付费""订阅"→起点 |
| 风格语调 | 1分/个 | 如"轻松""爽"→番茄，"细腻""文艺"→晋江 |

#### 2.2 平台匹配规则库

| 平台 | 匹配题材 | 风格 | 调用身份（仅用户指定时） |
|------|---------|------|------------------------|
| **番茄小说** | 都市/赘婿/战神/系统/签到/马甲/大佬/规则怪谈/穿越/重生 | 轻松/爽/快 | 番茄殿堂金番作家（二十年以上） |
| **起点中文网** | 玄幻/仙侠/历史/架空/科幻/异能/游戏/电竞/权谋 | 严肃/宏大/深度 | 起点大神俱乐部作家（十年以上/排行第一） |
| **七猫小说** | 霸总/甜宠/总裁/年代/种田/神医/马甲/宫斗/宅斗 | 情感强烈/虐甜交替 | 七猫大神俱乐部作家（十年以上/排行第一） |
| **晋江文学城** | 言情/纯爱/BL/古代言情/现代言情/奇幻/女强 | 细腻/情感/文艺 | 晋江大神俱乐部作家（十年以上/排行第一） |
| **纵横中文网** | 玄幻/仙侠/历史/军事/悬疑/灵异 | 稳重/传统 | 纵横大神俱乐部作家（十年以上/排行第一） |
| **通用**（无匹配/未指定） | - | - | 用户未指定平台时不调用身份 |

#### 2.3 身份调用规则

**核心原则**: 平台匹配与身份调用分离。

- **用户指定了平台**（如"写番茄小说""导入到起点"）→ 以用户指定为准，调用该平台对应的资深作家身份
- **用户未指定平台** → 自动匹配推荐最佳平台，但**不调用任何平台身份**，以通用创作能力执行

身份信息写入 `setting/platform-match.json`：

**用户指定平台时**:
```json
{
  "platform_id": "fanqie",
  "platform_name": "番茄小说",
  "match_score": 999,
  "matched_genres": [],
  "identity": "扮演番茄小说网写作超过二十年以上的殿堂金番作家……",
  "identity_active": true,
  "user_specified": true,
  "matched_at": "2026-06-01T20:00:00"
}
```

**用户未指定平台时**:
```json
{
  "platform_id": "fanqie",
  "platform_name": "番茄小说",
  "match_score": 8,
  "matched_genres": ["都市", "系统"],
  "identity": "（用户未指定平台，未调用平台身份）",
  "identity_active": false,
  "user_specified": false,
  "matched_at": "2026-06-01T20:00:00"
}
```

#### 2.4 指定平台的方式

**方式一：用户口头指定**
用户直接告知目标平台，如：
- "我要写一本番茄小说"
- "帮我导入这个大纲，我想发到起点"
- "这个设定是为七猫准备的"

技能会自动识别并调用对应平台身份。

**方式二：命令行参数指定**
```bash
# 指定平台导入（自动调用身份）
python import_pipeline.py --auto outline.md --platform fanqie
python import_pipeline.py --type outline outline.md --platform qidian

# 仅查看匹配结果（不执行导入）
python import_pipeline.py --match-platform outline.md

# 查看所有平台匹配规则
python import_pipeline.py --list-platforms
```

可用平台ID: `fanqie`(番茄), `qidian`(起点), `qimao`(七猫), `jinjiang`(晋江), `zhengheng`(纵横)

**方式三：导入后指定**
如果导入时未指定平台，后续创作过程中用户可以随时告知目标平台，技能会自动切换到对应身份。

### 第三章 自动审查

#### 3.1 大纲审查

对用户提供的大纲执行以下审查：

**逻辑审查**:
- 主线是否逻辑自洽？
- 冲突链是否完整？
- 角色动机是否合理？
- 时间线是否无矛盾？

**结构审查**:
- 三幕结构比例是否合理？
- 分卷划分是否合理？
- 高潮分布是否合理？
- 节奏是否张弛有度？

**完整性审查**:
- 是否有缺失的关键环节？
- 是否有未闭合的支线？
- 是否有未规划的伏笔？

#### 3.2 设定审查

对用户提供的设定执行以下审查：

**一致性审查**:
- 设定内部是否自洽？
- 力量体系是否有边界？
- 社会制度是否合理？

**完整性审查**:
- 是否缺少关键设定？
- 是否有模糊不清的设定？
- 是否有冗余设定？

**可用性审查**:
- 设定是否可转化为剧情燃料？
- 是否有为设定而设定的内容？

#### 3.3 正文审查

对用户提供的正文执行以下审查（自动调用所有检测工具）：

**质量审查**（调用 `references/quality-check.md`）:
- 章节级审查清单逐项检查
- 对话质量审查
- 情绪质量审查
- 场景质量审查

**AI痕迹检测**（调用 `scripts/ai_trace_scanner.py`）:
- 空格检测
- 破折号检测
- AI高频词检测
- AI连接词检测
- 长句检测
- 模板化开头检测
- 修辞过度使用检测
- 形容词堆砌检测
- 弱动词检测

**敏感词扫描**（调用 `scripts/sensitive_scanner.py`）:
- 政治安全类扫描
- 色情类扫描
- 毒品/犯罪类扫描
- 封建迷信类扫描
- 侵权类扫描
- 高风险模式检测

**一致性检查**（调用 `references/consistency-system.md`）:
- 设定一致性
- 角色一致性
- 剧情一致性
- 风格一致性
- 伏笔一致性
- 逻辑一致性

### 第三章 自动修改与完善

#### 3.1 修改优先级

| 优先级 | 类型 | 处理方式 |
|-------|------|---------|
| P0-紧急 | 敏感词/红线内容 | 必须立即修改 |
| P1-高 | 逻辑漏洞/设定矛盾/OOC | 必须修改 |
| P2-中 | AI痕迹/语言质量 | 自动修复 |
| P3-低 | 结构优化/细节完善 | 建议修改 |

#### 3.2 自动修改流程

```
发现问题 → 判断类型 →
├── 敏感词 → 替换/删除 → 重新扫描确认
├── AI痕迹 → 运行去痕流程 → 替换/重构 → 重新检测
├── 逻辑漏洞 → 补充过渡/修正 → 一致性复查
├── 设定矛盾 → 修正设定或正文 → 更新设定库
└── 语言质量 → 句式重构/词汇替换 → 重新审读
```

#### 3.3 自动完善

对缺失或不足的内容进行自动补充：

**大纲完善**:
- 补充缺失的三幕结构
- 细化分卷规划
- 生成章纲

**设定完善**:
- 补充缺失的设定维度
- 细化模糊的设定
- 按照命名规则随机化生成地名/角色名

**正文完善**:
- 补充过渡段落
- 强化结尾钩子
- 增强情绪描写

### 第五章 撰写启动

所有审查、修改、完善完成后，自动启动撰写流程：

```
Step 1: 确认当前进度
  ├── 检查 state.json 中的当前卷/章
  ├── 确认下一章章纲是否存在
  └── 如果无章纲 → 生成下一章章纲

Step 2: 构建上下文包
  ├── 加载 Level 0 全局上下文
  ├── 加载 Level 1 卷级上下文
  ├── 加载 Level 2 近章上下文
  └── 加载 Level 3 当前章上下文

Step 3: 执行写前三问
  ├── 逻辑一致？设定一致？角色一致？

Step 4: 撰写正文
  ├── 按章纲展开
  ├── 遵循风格锚定
  └── 遵守AI去痕规则

Step 5: 生成后审查
  ├── 一致性校验
  ├── AI去痕检测
  ├── 敏感词扫描
  └── 质量审查

Step 6: 保存与更新
  ├── 写入正文文件
  ├── 更新追踪文件
  └── 更新状态文件
```

## 第四篇：调用方式

### 方式一：自动检测（推荐）

当用户提供材料时，技能自动检测材料类型并执行完整流程。**自动推荐平台但默认不调用身份**，除非用户明确指定平台。

**触发词示例**:
- "我有现成的大纲，帮我写"（未指定平台，不调用身份）
- "这是我写的设定，帮我完善并开始写"（未指定平台，不调用身份）
- "我写了三章，帮我审查后继续"（未指定平台，不调用身份）
- "我有一个故事想法，帮我展开"（未指定平台，不调用身份）
- "帮我导入这个大纲，我想写番茄小说"（指定番茄，调用番茄身份）
- "这是我的世界观设定，准备发到起点"（指定起点，调用起点身份）
- "帮我审查这份七猫的设定"（指定七猫，调用七猫身份）

### 方式二：手动指定

用户明确指定导入类型：

```bash
# 导入大纲
python scripts/import_pipeline.py --type outline --input outline.md

# 导入设定
python scripts/import_pipeline.py --type setting --input setting.md

# 导入正文
python scripts/import_pipeline.py --type chapter --input chapter.md

# 全自动检测
python scripts/import_pipeline.py --auto --input material.md
```

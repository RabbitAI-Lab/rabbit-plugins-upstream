# 上下文处理与回忆机制

## 一、上下文层级详解

### Level 0: 全局上下文

全局上下文是整部小说从始至终不变的设定基础，写入项目初始化阶段后不再频繁修改。

**包含内容**:
- `iron-rules.md` — 创作铁律（每次写作必须复读一遍）
- `setting/world.md` — 世界观核心设定（力量体系、世界格局、种族设定）
- `setting/style-anchor.md` — 风格锚定（叙事语气、句式偏好、禁用词）
- `setting/characters/protagonist.md` — 主角人物卡
- `setting/characters/relationships.md` — 角色关系总图

**加载方式**: 每次写作前完整加载，不压缩、不摘要。

### Level 1: 卷级上下文

卷级上下文是当前卷范围内的设定和状态，每卷完成后更新，新卷开始时重置。

**包含内容**:
- `outline/volumes/vol-{n}.md` — 当前卷大纲
- `tracking/volume-summary.md` — 当前卷的进行中摘要（持续更新）
- 当前卷主要出场角色的最新状态
- 当前卷的伏笔活跃列表

**加载方式**: 每次写作前完整加载，跨卷时更新。

**卷摘要更新规则**:
- 每完成一章，将本章核心事件追加到卷摘要
- 卷完成后，生成完整卷摘要（包含关键事件、角色变化、伏笔状态）
- 跨卷时，前一卷的摘要归档，新卷摘要从空开始

### Level 2: 近章上下文

近章上下文是最近章节的详细信息，是维持"手感"和"细节一致性"的关键。

**常规模式（章节数 ≤ 50）**:
- 最近5章正文全文（逐字理解）
- 最近5章摘要
- 最近5章出场角色状态
- 最近5章伏笔操作记录

**超长篇模式（章节数 > 50）**:
- 最近3章正文全文
- 最近10章摘要
- 最近10章出场角色状态
- 最近10章伏笔操作记录

**加载方式**:
- 全文部分逐字读取
- 摘要部分快速扫描
- 角色状态部分按需提取（只提取本章出场角色）

### Level 3: 当前章上下文

当前章上下文是本章写作目标的精确信息。

**包含内容**:
- 目标章纲（完整读取）
- 上章结尾段（逐字读取，确保衔接）
- 本章出场角色最新状态快照
- 本章需回收的伏笔清单
- 本章需埋设的伏笔规划

**加载方式**: 逐字完整加载，不允许摘要。

## 二、上下文压缩策略

当章节数增加导致上下文膨胀时，采用以下压缩策略：

### 2.1 信息分级压缩

| 信息类型 | 前10章 | 10-30章 | 30-100章 | 100章+ |
|---------|-------|---------|---------|-------|
| 事件细节 | 全文 | 全文 | 摘要 | 摘要 |
| 对话原文 | 全文 | 摘要 | 仅关键对话 | 仅关键对话 |
| 环境描写 | 全文 | 不加载 | 不加载 | 不加载 |
| 角色状态 | 全部角色 | 出场角色 | 出场角色 | 出场角色 |
| 伏笔信息 | 全部 | 全部 | 未回收 | 未回收 |

### 2.2 摘要自动生成规则

每章完成后自动生成摘要，格式如下：

```
## 第{n}章 - {标题}

**核心事件**: {一句话概括}
**关键情节**: 
1. {事件1}
2. {事件2}
**出场角色**: {角色列表}
**伏笔操作**: [埋设/回收] {伏笔描述}
**情绪基调**: {基调描述}
**结尾钩子**: {钩子内容}
```

### 2.3 卷级摘要格式

```
# 第{n}卷 - {卷名} 摘要

**卷范围**: 第{start}章 - 第{end}章
**卷核心冲突**: {描述}
**关键事件链**:
1. {事件1}（第{x}章）
2. {事件2}（第{y}章）
3. ...

**角色变化**:
- {角色名}: {起点状态} → {终点状态}
- ...

**伏笔状态**:
- 已回收: {数量}
- 跨卷延续: {数量}
- 新增: {数量}

**卷尾状态**: {卷结束时的主要局势}
```

## 三、回忆机制

### 3.1 触发条件

当满足以下任一条件时，触发定向回忆：
- 本章事件与30章以前的事件有关联
- 本章出场的角色是30章以前出现但近期未出场的
- 本章回收的伏笔是跨卷长线伏笔
- 用户明确要求回顾特定前置章节

### 3.2 回忆流程

```
Step 1: 定位目标
  ├── 确定需要回忆的内容范围（哪一卷/哪一章/哪个事件）
  └── 从索引中定位目标位置

Step 2: 选择性加载
  ├── 如果目标是单章 → 读取该章全文
  ├── 如果目标是事件 → 读取事件链和相关章节摘要
  └── 如果目标是角色 → 读取角色状态演变记录

Step 3: 上下文融合
  ├── 将回忆内容与当前上下文融合
  ├── 标注回忆内容的时间位置（"第{x}章时……"）
  └── 确保回忆内容不干扰当前叙事节奏
```

```json
  }
```


## 四、上下文包构建模板

每次写作前按以下模板构建上下文包：

```
========================================
【上下文包】第{卷}卷第{章}章 - {标题}
========================================

【全局铁律】
{iron-rules核心条款}

【风格锚定】
{style-anchor核心要素}

【本章出场角色】
{角色名} - {当前状态/位置/目标}
{角色名} - {当前状态/位置/目标}

【当前卷核心】
{卷核心冲突}
{卷当前进度}

【前置5章摘要】
第{n-5}章: {摘要}
第{n-4}章: {摘要}
第{n-3}章: {摘要}
第{n-2}章: {摘要}
第{n-1}章: {摘要}

【上章结尾】
{上章最后一段}

【本章章纲】
{完整章纲}

【活跃伏笔】
- 待回收: {列表}
- 本章需回收: {列表}
- 本章可埋设: {列表}

【事件链前置】
{与本章相关的关键事件链}

【一致性注意点】
{需要特别注意保持一致性的地方}
========================================
```

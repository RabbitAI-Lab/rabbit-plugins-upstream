# 大纲审核修订指南

> 对完成的大纲进行系统性审核和修订，确保语言、逻辑、角色一致性和整体质量达标。

---

## 第一章：审核维度

### 1.1 语言审查

| 审查项 | 标准 | 问题示例 | 修改方案 |
|-------|------|---------|---------|
| 语言清晰度 | 无歧义、无模糊表述 | "某个势力很强"→"天渊阁拥有三位化神境强者" | 将模糊描述替换为具体信息 |
| 句式规范 | 避免过长复合句 | "主角在经历了……之后……最终……" | 拆分长句，每句表达一个完整信息 |
| 用词准确性 | 用词精确、无堆砌 | "非常非常强大"→"碾压同级" | 用精确词替换程度副词堆砌 |
| AI痕迹 | 无模板化表达 | "值得一提的是""综上所述" | 直接陈述，删除冗余引导词 |
| 风格统一 | 全文语调一致 | 严肃叙述中突然出现网络用语 | 保持风格锚定一致性 |

### 1.2 故事逻辑审查

| 审查项 | 标准 | 检查方法 |
|-------|------|---------|
| 因果链完整 | 事件A→事件B的因果关系清晰 | 逐事件追问"为什么"和"然后呢" |
| 时间线自洽 | 时间顺序无矛盾 | 标注所有时间节点，检查先后顺序 |
| 力量体系一致 | 战力/等级无前后矛盾 | 列出所有力量层级，检查越级合理性 |
| 空间逻辑合理 | 地理/距离无矛盾 | 标注关键地点间的距离和移动时间 |
| 冲突递进合理 | 冲突强度逐步升级 | 检查冲突链：小冲突→中冲突→大冲突 |
| 伏笔布局合理 | 伏笔埋设与回收间隔合理 | 检查伏笔密度，避免过于密集或稀疏 |
| 节奏分布合理 | 紧张与舒缓交替 | 检查是否连续多章高强度或低强度 |

### 1.3 角色一致性审查

| 审查项 | 标准 | 检查方法 |
|-------|------|---------|
| 性格一致性 | 角色行为符合性格设定 | 逐角色检查关键决策是否OOC |
| 动机合理性 | 角色行为有合理动机 | 追问"他为什么这么做" |
| 成长弧线 | 角色有清晰的变化轨迹 | 标记角色在关键节点前后的变化 |
| 关系逻辑 | 角色间关系变化有依据 | 检查关系变化的触发事件是否合理 |
| 对话一致性 | 不同角色说话风格有差异 | 检查对话是否符合角色身份和性格 |

### 1.4 结构审查

| 审查项 | 标准 |
|-------|------|
| 三幕比例 | 开端15-20%、发展60-70%、结局15-20% |
| 卷分布 | 每卷有独立核心冲突，卷间衔接自然 |
| 高潮分布 | 卷高潮强度递增，全书高潮在第三幕 |
| 节奏控制 | 紧张场景占比30-40%，舒缓场景占比20-30% |

## 第二章：审核流程

### 2.1 逐项审核流程

```
Step 1: 通读全文
  └── 获得整体印象，标记明显问题

Step 2: 语言审查
  ├── 逐段检查语言清晰度和句式
  ├── 标记AI痕迹和模板化表达
  └── 检查风格一致性

Step 3: 逻辑审查
  ├── 标注所有关键事件的时间点
  ├── 画出事件因果链
  ├── 检查力量体系前后一致性
  ├── 检查空间逻辑
  └── 验证冲突递进合理性

Step 4: 角色审查
  ├── 列出所有主要角色及其关键决策
  ├── 检查每个决策是否符合性格
  ├── 检查角色成长弧线是否完整
  └── 检查角色关系变化是否合理

Step 5: 结构审查
  ├── 计算三幕比例
  ├── 检查每卷的独立性
  ├── 检查高潮分布
  └── 评估整体节奏

Step 6: 综合评估
  ├── 汇总所有问题
  ├── 按优先级排序
  └── 输出审核报告
```

### 2.2 问题分级

| 优先级 | 定义 | 处理方式 |
|-------|------|---------|
| **P0-致命** | 故事逻辑断裂、核心设定矛盾、主角OOC导致故事无法推进 | 必须修改，修改后重新审核 |
| **P1-严重** | 次要逻辑漏洞、角色轻微OOC、重要伏笔缺失 | 必须修改，修改后确认 |
| **P2-中等** | 语言问题、节奏问题、次要设定模糊 | 建议修改 |
| **P3-轻微** | 用词优化、句式调整、细节补充 | 可选修改 |

## 第三章：修改规范

### 3.1 修改原则

1. **最小改动原则**: 在保留原作核心意图的前提下，做最小必要修改
2. **因果闭环原则**: 修改一处需检查是否影响上下游事件
3. **一致性原则**: 修改后需检查是否与全文其他部分一致
4. **可追溯原则**: 所有修改记录到 `tracking/setting-change-log.md`

### 3.2 修改方法

**逻辑漏洞修复**:
```
原: 主角在第一章还是废柴，第三章突然能击败宗师
问题: 成长路径缺失
修复: 在第二章插入关键事件——主角获得传承/觉醒血脉/获得神器
```

**角色OOC修复**:
```
原: 谨慎型主角突然冲动行事
问题: 缺乏动机支撑
修复: 添加合理触发条件——至亲遇险/被逼入绝境/获得底牌
```

**节奏问题修复**:
```
原: 连续5章都是战斗场景
问题: 节奏单一，读者疲劳
修复: 在第3章战斗后插入文戏——战后的疗伤、对话、新线索发现
```

### 4.2 输出要求

1. 审核报告必须在审核完成后立即输出
2. 问题按优先级排序，P0/P1必须附具体修改方案
3. 修改建议必须可执行，不能是模糊方向
4. 审核结论必须明确
5. 修改完成后需重新审核确认

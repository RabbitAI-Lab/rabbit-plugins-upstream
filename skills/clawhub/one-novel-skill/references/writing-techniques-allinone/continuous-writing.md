# 可持续续写与拓展机制

## 一、可持续续写核心设计

> **字数说明**: 全书总字数无上下限，可无限续写。章节正文内容需另行按规则计算（仅统计汉字，不包含标点、空格、英文、数字）。
>
> **分卷与章节说明**: 分卷最低4卷、最高无上限，按剧情大纲合理分布。章节分布无上限，按分卷细纲划分章纲合理分布，每卷章节数根据该卷剧情容量自由确定，无强制数值。

### 1.1 无上限状态推进

`state.json` 的设计支持无限续写：

```json
{
  "novel_name": "xxx",
  "novel_type": "玄幻",
  "total_words": 0,
  "volumes": [
    {"vol": 1, "title": "初入江湖", "chapters": 50, "start_chapter": 1, "end_chapter": 50, "status": "completed"},
    {"vol": 2, "title": "风云再起", "chapters": 45, "start_chapter": 51, "end_chapter": 95, "status": "completed"}
  ],
  "current_volume": 3,
  "current_chapter": 12,
  "total_chapters": 107,
  "status": "writing",
  "created_at": "2026-01-01T00:00:00",
  "updated_at": "2026-06-01T00:00:00"
}
```

**关键设计**:
- `volumes` 数组可无限追加，每卷独立编号，最低4卷、最高无上限
- `total_words` 无上限，每章累加
- `current_chapter` 永不重置，全局递增，无上限
- 每卷章节数根据剧情容量自由确定，无强制数值
- 跨卷时自动创建新卷

### 1.2 自动推进流程

```
写完第n章 → 更新所有追踪文件 → state.json 自动 +1 → 
检查当前卷的规划章节是否已写完 → 如果写完则标记卷完成 → 
检查是否有下一卷大纲 → 如果有则自动进入下一卷 →
如果无则触发拓展流程 → 构建下一章上下文包 → 就绪
```

### 1.3 续写接续保障

每次续写时，确保以下信息完整：
1. **上一章的最后状态**: 场景、角色位置、时间点
2. **当前章的目标**: 从章纲中明确本章要完成什么
3. **衔接点**: 上章结尾的钩子 → 本章开头的自然接续

## 二、拓展机制

### 2.1 拓展触发条件

当以下条件之一满足时，进入拓展模式：
- 当前卷的规划章节全部写完，且没有下一卷大纲
- 用户明确要求"继续写""拓展后续"
- 总纲中的主线已推进到尾声，需要新的剧情方向

### 2.2 拓展方向分析

**分析维度**:
1. **主线剩余空间**: 当前主线冲突是否已解决？是否有新的冲突可以引入？
2. **角色成长空间**: 主要角色是否还有未完成的成长弧线？
3. **设定未开发区域**: 世界观中是否有未探索的区域/规则/势力？
4. **伏笔储备**: 是否有足够数量的未回收伏笔支撑后续？
5. **节奏状态**: 当前是否处于情绪高点？是否需要新冲突重新拉高？

**分析输出**:
```
## 拓展分析报告

### 当前状态
- 已写章节: {数量}
- 已完成卷: {数量}
- 总字数: {字数}
- 当前主线进度: {百分比}

### 未回收伏笔
- 短期待回收: {数量}
- 中期待回收: {数量}
- 长期待回收: {数量}

### 角色成长空间
- {角色名}: {已完成弧线}/{规划弧线}
- ...

### 设定未开发
- {设定区域}: 可展开的剧情方向
- ...

### 推荐方案
{推荐方案及理由}
```

### 2.3 拓展方案类型

#### 方案A: 主线自然延伸（推荐）
**适用**: 当前主线尚未完结，有自然延伸空间
**操作**: 基于当前主线逻辑，规划下一阶段的目标和冲突
**示例**: "主角击败当前BOSS后，发现BOSS背后还有更大的势力"

#### 方案B: 衍生新支线
**适用**: 主线暂时告一段落，但角色/世界有可探索空间
**操作**: 基于已有设定和角色，衍生新的支线剧情
**示例**: "主角在某次冒险中发现了失落的文明遗迹"

#### 方案C: 开启新卷/新篇章
**适用**: 主线完结或接近完结，需要开启新的故事篇章
**操作**: 基于世界观设定，设计新的核心冲突和剧情方向
**示例**: "主角飞升到更高位面，开启全新篇章"

#### 方案D: 角色深度挖掘
**适用**: 有重要配角或反派的背景故事可深入
**操作**: 围绕特定角色的过去/动机/关系展开深度剧情
**示例**: "反派的过去揭示，发现他与主角有深层次的联系"

### 2.4 拓展执行流程

```
Step 1: 分析现状
  ├── 已写内容的关键信息提取（最近50章摘要）
  ├── 未回收伏笔清单
  ├── 角色当前状态和未完成的成长弧线
  ├── 世界设定中未探索的区域
  └── 当前剧情走势分析

Step 2: 生成拓展方案（3个候选）
  ├── 方案A: {方向描述}
  │   ├── 核心冲突
  │   ├── 预计章节数
  │   ├── 新登场角色（如有）
  │   └── 与现有剧情的衔接方式
  ├── 方案B: {方向描述}
  │   └── ...
  └── 方案C: {方向描述}
      └── ...

Step 3: 推荐并确认
  ├── 向用户推荐最优方案
  ├── 说明各方案的优缺点
  └── 等待用户确认

Step 4: 生成详细规划
  ├── 新卷大纲
  ├── 后续章纲（至少10章）
  ├── 新登场角色人物卡（如有）
  ├── 新伏笔规划
  └── 与前置剧情的衔接设计

Step 5: 写入项目文件
  ├── 更新 outline/ 目录
  │   ├── 追加新卷大纲
  │   └── 追加新章纲
  ├── 更新 setting/ 目录（如有新角色）
  ├── 更新 tracking/ 目录
  │   ├── 追加新伏笔
  │   └── 更新时间线
  └── 更新 state.json
      ├── 追加新卷信息
      └── 更新 total_chapters 规划

Step 6: 开始续写
  ├── 构建第一章上下文包（包含跨卷衔接信息）
  ├── 执行正常写作流程
  └── 完成第一章后自动继续
```

## 三、跨卷衔接设计

### 3.1 卷间衔接要点

跨卷时，确保以下衔接：
1. **状态衔接**: 角色状态从上卷结束状态延续
2. **剧情衔接**: 上卷的钩子在本卷开头得到回应
3. **设定衔接**: 上卷引入的新设定在本卷中持续生效
4. **情绪衔接**: 上卷的情绪余韵在本卷开头适度延续后转入新节奏

### 3.2 跨卷上下文更新

进入新卷时，上下文包做以下调整：
- Level 1 卷级上下文：替换为当前卷的信息
- Level 2 近章上下文：保留上卷最后5章（跨卷衔接需要）
- 新增跨卷衔接信息：上卷摘要、上卷结尾状态

## 四、超长篇管理模式（500章+）

### 4.1 章节归档策略
- 每100章为一个"部"，创建 `chapters/part-{n}/` 目录
- 每部完成后生成部级摘要
- 部级摘要作为 Level 1 的补充

### 4.2 上下文压缩
- Level 2 调整为：最近3章全文 + 最近10章摘要
- 超出10章的事件通过事件链索引定位
- 角色状态只保留最近100章的快照，更早的归档

### 4.3 定期维护
- 每50章：全局一致性扫描
- 每100章：设定库整理
- 每200章：角色状态归档（长时间未出场角色移入存档）
- 每500章：全书大纲复盘，调整后续规划

### 4.4 防漂移机制
- 每100章执行一次"风格锚定校准"：对照 style-anchor.md 检查近50章的风格一致性
- 每100章执行一次"设定库校准"：检查是否有新增设定与核心设定矛盾
- 每100章执行一次"角色一致性校准"：检查角色状态演变是否符合人物卡设定的成长弧线

## 五、续写就绪检查清单

每次续写前执行：

- [ ] `state.json` 中当前卷/章正确
- [ ] 目标章纲存在且与大纲一致
- [ ] 上下文包已按层级构建完整
- [ ] 上章结尾钩子已明确
- [ ] 本章核心目标已明确
- [ ] 本章出场角色状态已加载
- [ ] 本章需回收的伏笔已确认
- [ ] 一致性自检三问已执行
- [ ] 如果跨卷 → 跨卷衔接信息已加载
- [ ] 如果章节数>50 → 超长篇模式已启用

# 小说漏洞自查与修复规则

> 本指南提供一套系统化的小说漏洞自查规则，覆盖逻辑、设定、角色、剧情、结构、语言等所有维度。发现漏洞后，按规则修复并并入小说设定。

---

## 第一篇：漏洞分类体系

### 第一章 漏洞类型总览

| 漏洞类别 | 严重程度 | 影响范围 | 修复优先级 |
|---------|---------|---------|-----------|
| 逻辑漏洞 | 高 | 全局 | 立即修复 |
| 设定漏洞 | 高 | 全局 | 立即修复 |
| 角色漏洞 | 中-高 | 单卷-全局 | 尽快修复 |
| 剧情漏洞 | 中-高 | 单卷-跨卷 | 尽快修复 |
| 结构漏洞 | 中 | 单章-单卷 | 择机修复 |
| 语言漏洞 | 低-中 | 单章 | 可选修复 |

### 第二章 各类漏洞详解

#### 2.1 逻辑漏洞（严重度：高）

**定义**: 情节发展违反基本逻辑或因果关系。

**自查清单**:
- [ ] 角色行为是否有合理动机？还是为了剧情需要强行行动？
- [ ] 事件A→事件B的因果链是否完整？是否有跳跃？
- [ ] 时间线是否有矛盾？（角色不可能在A地同时又在B地）
- [ ] 空间位置是否合理？（角色不会瞬移）
- [ ] 信息差是否合理？（角色掌握的信息与其行动匹配）
- [ ] 角色的决策是否符合其智力和经验水平？

**示例**:
- ❌ "主角刚穿越到异世界，就能完美使用当地语言和礼仪"（逻辑不合理）
- ✅ "主角穿越后发现自己能听懂异世界语言——因为原主的记忆正在融合"
- ❌ "反派在占尽优势时突然放走主角"（缺乏动机）
- ✅ "反派放走主角是因为想钓出更大的鱼"

**修复方法**:
1. 补充因果链——在A和B之间增加合理的过渡事件
2. 调整时间线——修正矛盾的时间点
3. 增加动机——为角色的不合理行为补充动机
4. 修正信息差——让角色掌握的信息与行动匹配

#### 2.2 设定漏洞（严重度：高）

**定义**: 世界观设定内部矛盾，或正文与设定不符。

**自查清单**:
- [ ] 力量体系是否自洽？（A级>B级>C级，不能出现A<C）
- [ ] 力量体系的边界是否清晰？（不会出现无限制的能力）
- [ ] 角色能力是否与设定一致？（没有莫名增强或减弱）
- [ ] 世界规则是否前后一致？（魔法规则/科技规则没有矛盾）
- [ ] 新增设定是否与核心设定冲突？
- [ ] 社会制度/文化习俗是否自洽？

**示例**:
- ❌ "设定说魔法需要吟唱，但主角每次瞬发"（正文与设定冲突）
- ✅ "主角获得了瞬发天赋，所以可以省略吟唱"（设定有依据）
- ❌ "前期说灵力分九级，后期突然出现十级"（体系矛盾）
- ✅ "上古时期确实有第十级，但已经失传"（有合理解释）

**修复方法**:
1. **修正正文**: 如果设定正确，修正正文中偏离的描写
2. **修正设定**: 如果设定已过时或不合理，更新设定文件
3. **补充解释**: 在正文中增加合理解释，消除矛盾
4. **标记存档**: 如果涉及重大设定变更，在设定变更日志中记录

#### 2.3 角色漏洞（严重度：中-高）

**定义**: 角色行为/能力/性格与人物卡不一致（OOC）。

**自查清单**:
- [ ] 角色的行为是否符合其性格设定？
- [ ] 角色的能力是否在合理范围内波动？
- [ ] 角色的语言风格是否前后一致？
- [ ] 角色的成长是否有合理的过程？
- [ ] 角色的情感变化是否有触发事件？
- [ ] 长时间未出场的角色，重新出场时状态是否合理？

**示例**:
- ❌ "内向的主角突然在众人面前大声演讲"（性格OOC）
- ✅ "主角经过50章的成长和训练，克服了社交恐惧"（有合理过程）
- ❌ "刚出场的配角实力碾压主角，下一章就被主角秒杀"（能力波动不合理）
- ✅ "主角在上一战中获得了关键突破"（有合理原因）

**修复方法**:
1. **补充成长过程**: 增加角色变化的铺垫和过渡
2. **修正行为**: 将OOC行为改为符合性格的行为
3. **更新人物卡**: 如果角色确实发生了性格转变，更新人物卡
4. **增加触发事件**: 为角色的变化增加合理触发点

#### 2.4 剧情漏洞（严重度：中-高）

**定义**: 情节重复、矛盾、断裂或缺乏必要的铺垫。

**自查清单**:
- [ ] 是否有重复的情节模式？（每次都是"遇险→爆发→逆转"）
- [ ] 是否有断裂的情节线？（某条线写着写着就消失了）
- [ ] 高潮是否有足够的铺垫？
- [ ] 伏笔是否已回收？
- [ ] 是否有"机械降神"？（没有铺垫的突然解决）
- [ ] 剧情的节奏是否合理？（没有过快的推进或过慢的拖沓）

**示例**:
- ❌ "主角每次遇险都靠爆发新能力脱困"（重复模式）
- ✅ "第一次靠爆发，第二次靠策略，第三次靠盟友"（多样化）
- ❌ "前面铺垫的反派，后面再也没有出现过"（断裂的情节线）
- ✅ "反派虽然暂时退场，但通过暗线持续影响剧情"

**修复方法**:
1. **多样化情节模式**: 同一类冲突用不同方式解决
2. **补充或收束断线**: 要么让断线重新出现，要么明确收尾
3. **增加铺垫**: 为高潮增加前置铺垫
4. **检查伏笔**: 确保所有伏笔有明确的回收计划
5. **调整节奏**: 加快或放慢剧情推进速度

#### 2.5 结构漏洞（严重度：中）

**定义**: 章节/卷的结构安排不合理。

**自查清单**:
- [ ] 章节划分是否合理？（每章是否有完整的小闭环？）
- [ ] 卷的起承转合是否完整？
- [ ] 章节之间的衔接是否自然？
- [ ] 是否遵循"一章一核心"原则？
- [ ] 卷内高潮安排是否合理？
- [ ] 是否有过多的"日常过渡章节"？

**修复方法**:
1. 重新划分章节（合并或拆分）
2. 补充章节间的过渡内容
3. 调整高潮位置
4. 压缩或删除过渡章节

#### 2.6 语言漏洞（严重度：低-中）

**定义**: 用词不当、句式重复、修辞过度、风格偏移。

**自查清单**:
- [ ] 是否有重复的句式结构？
- [ ] 是否有用词不当或语义不通？
- [ ] 是否有修辞过度（比喻/排比过多）？
- [ ] 是否有风格偏移（与style-anchor.md不一致）？
- [ ] 是否有不必要的重复描写？
- [ ] 对话是否符合角色身份？

**修复方法**: 按 `references/ai-removal.md` 的规则进行语言优化。

## 第二篇：漏洞检测流程

### 第一章 检测时机

| 检测级别 | 检测时机 | 检测范围 | 耗时 |
|---------|---------|---------|------|
| 章节自检 | 每章写完后 | 本章内容 | 10-15分钟 |
| 卷检 | 每卷完成后 | 整卷内容 | 1-2小时 |
| 跨卷检 | 新卷开始时 | 跨卷衔接 | 30分钟 |
| 全局检 | 每50章 | 全书范围 | 2-4小时 |
| 专项检 | 发现可疑点时 | 特定范围 | 按需 |

### 第二章 章节自检流程

```
写完一章 → 通读一遍 → 逐项检查 →
发现漏洞 → 判断严重度 → 修复 → 
更新所有关联文件 → 确认修复完成
```

**章节自检步骤**:
1. **通读**: 从头到尾读一遍本章内容
2. **逻辑检查**: 检查本章内的因果链是否完整
3. **设定检查**: 对照setting-inventory.json，检查本章设定是否与已有设定一致
4. **角色检查**: 对照人物卡和角色日志，检查角色行为是否OOC
5. **衔接检查**: 本章开头是否与上章结尾自然衔接
6. **伏笔检查**: 本章的伏笔操作是否已登记
7. **语言检查**: 按AI去痕清单检查语言质量

### 第三章 卷级检测流程

```
完成一卷 → 通读整卷 → 逐项检查 →
发现漏洞 → 分类记录 → 批量修复 →
更新设定 → 生成卷检测报告
```

**卷级检测步骤**:
1. **通读整卷**: 从头到尾读一遍整卷内容
2. **结构检查**: 起承转合是否完整？高潮位置是否合理？
3. **节奏检查**: 爽点/泪点/笑点分布是否合理？
4. **角色弧线检查**: 角色在本卷中是否有可见的成长？
5. **伏笔检查**: 本卷内埋设的伏笔是否在本卷内回收？跨卷伏笔是否有明确标记？
6. **一致性检查**: 本卷内的设定/角色/剧情是否一致？
7. **生成报告**: 记录发现的漏洞和修复方案

### 第四章 全局检测流程（每50章）

```
确认检测范围 → 逐卷扫描 → 跨卷比对 →
设定库全局扫描 → 角色状态演变审查 →
时间线验证 → 伏笔盘点 → 风格校准 →
生成全局检测报告 → 制定修复计划
```

**全局检测重点**:
1. **设定库全局扫描**: 检查所有设定条目之间是否有矛盾
2. **角色状态演变审查**: 检查所有角色的状态变化是否合理
3. **事件链完整性扫描**: 检查所有事件链是否完整（无断裂）
4. **时间线扫描**: 检查所有时间点是否无矛盾
5. **伏笔盘点**: 检查所有伏笔的回收状态，标记超期伏笔
6. **风格校准**: 对比style-anchor.md，检查风格是否漂移

## 第三篇：漏洞修复规范

### 第一章 修复优先级

| 优先级 | 条件 | 处理方式 |
|-------|------|---------|
| **P0-紧急** | 影响后续创作的逻辑/设定漏洞 | 立即修复，暂停当前写作 |
| **P1-高** | 影响读者理解的角色/剧情漏洞 | 尽快修复，完成当前章后立即处理 |
| **P2-中** | 影响阅读体验的结构/节奏问题 | 择机修复，可在卷检时处理 |
| **P3-低** | 不影响理解的细节/语言问题 | 可选修复，可在全局检时处理 |

### 第二章 修复流程

```
发现漏洞 → 记录到漏洞追踪表 →
判断优先级 → P0/P1立即处理 →
执行修复 → 更新关联文件 →
验证修复 → 关闭漏洞记录
```

**漏洞记录格式**:
```markdown
## 漏洞记录表

| ID | 类型 | 章节 | 描述 | 严重度 | 状态 | 修复方案 | 修复日期 |
|----|------|------|------|--------|------|---------|---------|
| BUG-001 | 设定 | ch-12 | 力量体系矛盾 | 高 | 已修复 | 修正设定描述 | 2026-06-01 |
| BUG-002 | 角色 | ch-15 | 配角OOC | 中 | 待修复 | 调整对话内容 | - |
```

### 第三章 修复后的设定并入

漏洞修复后，需要将修复内容并入小说设定体系，确保后续创作不再出现同类问题：

#### 3.1 设定更新
- 如果漏洞涉及设定 → 更新 `setting/world.md` 或相关设定文件
- 在设定文件中增加"修订历史"章节，记录每次设定变更

#### 3.2 一致性数据库更新
- 更新 `tracking/consistency-db/setting-inventory.json`
- 更新 `tracking/consistency-db/character-log.json`
- 更新 `tracking/consistency-db/event-chain.json`

#### 3.3 角色状态更新
- 如果漏洞涉及角色 → 更新 `tracking/character-states.json`
- 在角色状态演变记录中标注"设定修正"

#### 3.4 设定变更日志

建立 `tracking/setting-change-log.md`，记录所有设定变更：

```markdown
# 设定变更日志

## 2026-06-01 设定修正
- **涉及章节**: ch-12
- **变更内容**: 修正力量体系中"元婴期"的描述，原为"元婴期可瞬移"改为"元婴期可短距离瞬移（10米内）"
- **变更原因**: 原文与后续章节中"化神期才能瞬移"矛盾
- **影响范围**: ch-12正文 + setting/world.md力量体系章节
- **是否影响后续创作**: 否（修正后与后续章节一致）

## 2026-05-28 角色调整
- **涉及章节**: ch-08
- **变更内容**: 配角张三的性格从"暴躁"调整为"外冷内热"
- **变更原因**: 后续章节中张三的行为不符合"暴躁"设定
- **影响范围**: setting/characters/supporting-张三.md + ch-08正文对话部分
- **是否影响后续创作**: 否（调整后与后续章节一致）
```

### 第四章 设定并入后的验证

设定变更后，执行验证三查：
1. **自查**: 变更后的设定是否与所有已有设定无冲突？
2. **前查**: 变更是否影响了前置章节的合理性？
3. **后查**: 变更是否影响了后续章节的创作计划？

## 第四篇：常见漏洞模式库

### 第一章 高频漏洞模式

| 模式 | 类型 | 示例 |
|------|------|------|
| 战力崩溃 | 设定 | 前期铺垫的强大敌人在后期被轻易秒杀 |
| 工具人配角 | 角色 | 配角出场只是为了给主角送装备/信息 |
| 机械降神 | 剧情 | 没有铺垫的突然反转或金手指 |
| 时间线混乱 | 逻辑 | 角色年龄/事件顺序矛盾 |
| 设定堆砌 | 设定 | 开篇大段介绍世界观，缺乏剧情融入 |
| 重复套路 | 剧情 | 每次冲突都采用相同的解决模式 |
| 智商掉线 | 角色 | 角色为剧情需要做出不符合其智力的决策 |
| 情感跳跃 | 角色 | 角色情感变化缺乏合理的触发和过渡 |
| 视角混乱 | 结构 | 一章内频繁切换视角，读者迷失 |
| 伏笔丢失 | 剧情 | 埋设的伏笔被遗忘，未回收 |

### 第二章 预防策略

1. **写前检查**: 每次写作前回顾一致性数据库
2. **设定卡片**: 为每个重要设定制作摘要卡片，写作时放在旁边
3. **角色状态卡**: 每次写作出场角色前，查看其最新状态
4. **事件链回顾**: 回顾与本章相关的事件链
5. **定时自检**: 每5章执行一次小型自检
6. **互检机制**: 如果有条件，请他人阅读并反馈

## 第五篇：漏洞修复决策树

```
发现可疑点
├── 是明显的漏洞？
│   ├── 是 → 判断严重度 → 按优先级修复
│   └── 否 → 继续观察
│
├── 是设定问题还是正文问题？
│   ├── 设定问题 → 更新设定文件
│   │   ├── 影响小 → 直接修正
│   │   └── 影响大 → 记录变更日志 + 更新所有关联文件
│   └── 正文问题 → 修正正文
│       ├── 单章问题 → 修正本章
│       ├── 多章问题 → 逐章修正
│       └── 跨卷问题 → 逐卷修正 + 补充过渡
│
├── 修复后是否需要更新其他文件？
│   ├── 是 → 更新所有关联文件（伏笔/角色状态/时间线/设定清单等）
│   └── 否 → 确认修复完成
│
└── 修复后是否影响后续创作？
    ├── 是 → 更新后续章节规划
    └── 否 → 继续正常创作
```

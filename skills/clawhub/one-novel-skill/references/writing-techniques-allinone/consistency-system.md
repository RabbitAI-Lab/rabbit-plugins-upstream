# 整体一致性保障体系

> 完整的漏洞自查与修复规则详见 `references/self-check-rules.md`。
> 本体系侧重"预防"和"检测"，self-check-rules.md 侧重"发现漏洞后的修复"。

## 一、一致性维度详解

### 1.1 设定一致性

**定义**: 小说中所有明确出现的设定之间不得相互矛盾。

**覆盖范围**:
- 力量体系内部一致性（A级>B级>C级，不能出现A<C的情况）
- 力量体系与角色能力一致性（角色能力不能超过体系上限或低于下限）
- 世界规则一致性（魔法/科技规则不能前后矛盾）
- 社会制度一致性（权力结构、经济体系、文化习俗不能矛盾）
- 历史年表一致性（事件时间顺序不能混乱）

**检测方式**:
- 设定库比对：每章写完后，将本章新增的设定信息与 `tracking/consistency-db/setting-inventory.json` 比对
- 当发现冲突时，判定优先级：核心设定 > 衍生设定 > 章节临时设定

**设定清单格式** (`setting-inventory.json`):
```json
{
  "settings": [
    {
      "id": "S-001",
      "name": "灵力等级体系",
      "category": "力量体系",
      "content": "炼气→筑基→金丹→元婴→化神",
      "source_chapter": 1,
      "last_used_chapter": 25,
      "status": "active",
      "related_settings": ["S-002", "S-010"]
    }
  ]
}
```

### 1.2 角色一致性

**定义**: 角色的行为、能力、性格必须符合其人物卡设定的轨迹，不能出现OOC（Out of Character）。

**覆盖范围**:
- 性格一致性：角色在不同情境下的反应应基于其性格
- 能力一致性：角色能力不能无理由突然增强或减弱
- 动机一致性：角色的行为应服务于其深层动机
- 成长一致性：角色的变化应有合理的过程和触发点

**检测方式**:
- 角色行为日志比对：每章写完后，记录角色的关键行为
- 当角色行为与人物卡设定的动机/性格不一致时，判定是否属于"成长弧线"中的合理变化

**角色行为日志格式** (`character-log.json`):
```json
{
  "character_log": [
    {
      "character": "主角",
      "chapter": 12,
      "action": "救了曾经的敌人",
      "motive_check": "符合深层动机'追求正义'",
      "personality_check": "符合性格'宽厚'",
      "consistency": "pass"
    }
  ]
}
```

### 1.3 剧情一致性

**定义**: 事件之间的因果链完整，时间线无矛盾。

**覆盖范围**:
- 因果链：每个事件都有原因，每个结果都会导致后续事件
- 时间线：事件发生的顺序和间隔合理
- 空间线：角色位置移动合理，不出现"瞬移"
- 信息流：角色掌握的信息与他们的行动匹配

**检测方式**:
- 事件链回溯：从本章事件回溯前置触发事件，确认因果链完整
- 时间线比对：确认本章时间与前置章节的时间无缝衔接

**事件链格式** (`event-chain.json`):
```json
{
  "event_chain": [
    {
      "event_id": "EV-025",
      "chapter": 25,
      "description": "主角进入秘境",
      "triggered_by": ["EV-018"],
      "triggers": [],
      "time": "第25章第3天",
      "location": "秘境入口",
      "characters": ["主角", "配角B"],
      "status": "pending_resolution"
    }
  ]
}
```

### 1.4 风格一致性

**定义**: 全书的叙事语气、句式偏好、语言风格保持统一。

**覆盖范围**:
- 叙事语气：轻松/严肃/诙谐/悲壮等基调不变
- 句式偏好：段落长度、句子结构的一致性
- 词汇偏好：用词风格的一致性
- 修辞手法：使用的修辞类型和频率的一致性

**检测方式**:
- 风格快照比对：每50章采样一章，与 style-anchor.md 对比
- 定期校准：如果发现风格偏移，进行修正

### 1.5 伏笔一致性

**定义**: 所有伏笔的埋设→回收形成闭环，无遗漏。

**覆盖范围**:
- 所有埋设的伏笔都应有明确的回收计划
- 伏笔回收不能与已有剧情矛盾
- 伏笔的答案应与埋设时的暗示一致

**检测方式**:
- 伏笔追踪表扫描：每次写完后扫描追踪表

### 1.6 逻辑一致性

**定义**: 情节发展的内在逻辑自洽，不出现逻辑断层。

**覆盖范围**:
- 角色决策逻辑：角色做出的每个决定都应有合理动机
- 事件发展逻辑：事件的发展应符合设定框架
- 冲突解决逻辑：冲突的解决方式应合理

## 二、一致性数据库维护

### 2.1 数据库结构

```
tracking/consistency-db/
├── setting-inventory.json    # 设定清单（所有出现过的设定条目）
├── character-log.json        # 角色行为日志（每章行为记录）
├── event-chain.json          # 事件链（因果关系的网络图）
├── timeline-index.json       # 时间线索引（快速定位）
└── style-snapshot.json       # 风格快照（定期采样对照）
```

### 2.2 更新时机

| 数据库文件 | 更新时机 | 更新内容 |
|-----------|---------|---------|
| setting-inventory.json | 每章写完后 | 新增设定条目、更新已有条目的使用状态 |
| character-log.json | 每章写完后 | 追加本章角色关键行为记录 |
| event-chain.json | 每章写完后 | 追加本章核心事件、更新事件链关系 |
| timeline-index.json | 每章写完后 | 追加本章时间点 |
| style-snapshot.json | 每50章 | 采样一章，记录风格特征 |

### 2.3 一致性冲突处理流程

```
检测到冲突 → 判定严重程度（高/中/低） → 
高: 必须立即修复（影响后续创作） → 修改正文或更新设定
中: 建议修复（影响阅读体验） → 纳入修改计划
低: 可记录（不影响理解） → 记录待日后修复

修复方案选择:
1. 修改正文 → 适用于正文与设定冲突
2. 更新设定 → 适用于设定已过时或不合理
3. 补充过渡 → 适用于逻辑断层
4. 标记说明 → 适用于可解释的轻微不一致

修复后必须执行"设定并入三查":
1. 自查: 变更后的设定是否与所有已有设定无冲突？
2. 前查: 变更是否影响了前置章节的合理性？
3. 后查: 变更是否影响了后续章节的创作计划？

同时更新设定变更日志（tracking/setting-change-log.md），记录变更内容、原因和影响范围。
```

> 完整的漏洞修复规范和设定并入流程详见 `references/self-check-rules.md` 第三篇。

## 三、一致性自检与确认

### 3.1 写前自检三问

每次写作前，执行以下三问：

**Q1: 本章是否与前置所有剧情逻辑一致？**
- 回顾事件链，确认本章的起始状态与上章结尾匹配
- 确认本章的冲突与前置剧情中的铺垫一致
- 确认本章不引入与前置剧情矛盾的设定

**Q2: 本章是否与所有活跃设定一致？**
- 扫描设定清单，确认本章涉及的所有设定均为活跃状态
- 确认本章不引入与核心设定矛盾的新设定
- 确认力量体系/世界规则在本章中的体现与设定一致

**Q3: 本章角色行为是否符合其人物卡和状态演变？**
- 确认本章出场的每个角色的行为动机与其人物卡一致
- 确认角色能力水平与状态演变记录一致
- 确认角色之间的关系与关系图一致

### 3.2 写后确认三查

每章写完后，执行以下三查：

**C1: 本章新增的内容是否与已有设定库无冲突？**
- 提取本章中出现的所有设定元素
- 与 setting-inventory.json 比对
- 如果发现冲突 → 按冲突处理流程处理

**C2: 本章新增的事件是否与已有事件链逻辑自洽？**
- 提取本章核心事件
- 确认事件的前置条件在上章或之前已满足
- 确认事件的结果不与其他已发生事件矛盾

**C3: 本章角色的行为是否符合其已有行为模式？**
- 将本章角色行为与 character-log.json 中的历史行为对比
- 确认行为模式一致（或如果有变化，有合理触发原因）
- 确认角色决策与其动机一致

## 四、全局一致性扫描

### 4.1 触发时机
- 每50章执行一次
- 每卷完成后执行一次
- 用户明确要求时

### 4.2 扫描范围
1. **设定库全局扫描**: 检查所有设定条目之间是否有矛盾
2. **角色状态演变扫描**: 检查所有角色的状态变化是否合理
3. **事件链完整性扫描**: 检查所有事件链是否完整（无断裂）
4. **时间线扫描**: 检查所有时间点是否无矛盾
5. **伏笔扫描**: 检查所有伏笔的回收状态
6. **风格扫描**: 对比风格快照，检查风格偏移

### 4.3 扫描报告格式

```
# 第{扫描次数}次全局一致性扫描报告

## 扫描范围
- 章节: 第1章 - 第{current}章
- 设定条目: {数量}
- 角色日志: {数量}条
- 事件链: {数量}个事件

## 扫描结果

### 设定一致性
- 无冲突: {数量}
- 轻微不一致: {数量}（已记录）
- 需修复: {数量}（详情见下）

### 角色一致性
- 行为合理: {数量}条
- 需关注: {数量}条（详情见下）

### 事件链完整性
- 完整: {数量}条
- 断裂: {数量}条（详情见下）

### 时间线
- 无矛盾
- 需调整: {详情}

### 伏笔状态
- 已回收: {数量}
- 待回收: {数量}
- 超期预警: {数量}

### 风格一致性
- 与锚定一致: {百分比}
- 偏移项: {详情}

## 总体评估
- 综合评分: {评分}/10
- 需要关注的优先级问题: {列表}
```

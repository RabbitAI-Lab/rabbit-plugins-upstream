# 竞品深度分析

通过浏览器自动化对竞品SaaS/Web/App进行系统性深度功能分析，输出结构化竞品分析报告。

**适用场景**：竞品有Web端管理后台可登录、需要功能梳理和架构还原
**不适用场景**：纯公开页面抓取、需要真实交易才能触发的功能

---

~/.kimi-webbridge/bin/kimi-webbridge status

- `running:true` + `extension_connected:true` → 健康，继续使用

## 登录方案管理

登录信息见 `references/login-credentials.md`（安全敏感，独立文件）。

### 登录方式分类

| 登录类型 | 适用平台 | 说明 |
|---------|---------|------|
| **账号密码** | 企迈、客如云、天财商龙 | 输入账号密码即可 |
| **手机验证码** | 美团商家中心 | 需用户协助获取验证码 |
| **扫码/SSO** | 部分平台 | 需用户手机配合 |

### kimi-webbridge 登录流程

**账号密码登录**：
```bash
# 1. 导航到登录页
curl -s -X POST http://127.0.0.1:10086/command \
  -d '{"action":"navigate","args":{"url":"https://console.qmai.cn/","newTab":true},"session":"qmai"}'

# 2. snapshot 获取页面结构，定位输入框
curl -s -X POST http://127.0.0.1:10086/command \
  -d '{"action":"snapshot","session":"qmai"}'

# 3. fill 输入账号密码（用 @e ref 或 CSS selector）
curl -s -X POST http://127.0.0.1:10086/command \
  -d '{"action":"fill","args":{"selector":"@eXX","value":"账号"},"session":"qmai"}'
curl -s -X POST http://127.0.0.1:10086/command \
  -d '{"action":"fill","args":{"selector":"@eYY","value":"密码"},"session":"qmai"}'

# 4. click 登录按钮
curl -s -X POST http://127.0.0.1:10086/command \
  -d '{"action":"click","args":{"selector":"@eZZ"},"session":"qmai"}'

# 5. snapshot 确认进入主页面
curl -s -X POST http://127.0.0.1:10086/command \
  -d '{"action":"snapshot","session":"qmai"}'
```

**手机验证码登录**（美团）：
```bash
# 1-3 同上（输入手机号）
# 4. click "获取验证码"
# 5. 请求用户输入验证码 → fill 输入 → click 提交
# 6. snapshot 确认进入主页面
```

### 多视角/多系统

| 平台 | 视角切换 | 说明 |
|------|---------|------|
| **企迈** | 品牌视角(console.qmai.cn) / 门店视角(store.qmai.cn) | 顶部下拉切换 |
| **天财商龙** | 6大独立系统 | 分别访问各系统URL |

### Cookie 管理

- 检测：访问目标URL，snapshot 观察是否跳转登录页
- 过期处理：重新执行登录流程，美团需用户协助验证码
- 存储：cookies 存到 `./竞品分析/{平台名}/cookies/`

## 分析框架：6维度

每个功能模块按以下6维度分析：

| 维度 | 内容 | 产出 |
|------|------|------|
| **架构** | 模块层级、菜单结构、入口路径 | 菜单树 + URL路由 |
| **流程** | 核心操作路径、状态流转 | 流程图/步骤列表 |
| **字段** | 表单字段、列表字段、枚举值 | 字段表 |
| **规则** | 校验规则、业务规则、权限规则 | 规则清单 |
| **亮点** | 设计创新点、交互巧思 | 标注+价值判断 |
| **gap** | 功能缺失、体验问题 | gap清单+影响评估 |

| 轮次 | 目标 | 产出 |
|------|------|------|
| **R1 扫描** | 菜单结构 + 列表页 + 基本字段 | 菜单树 + 截图 + URL清单 |

## 技术策略

### URL直访优先，菜单点击保底

- **优先URL导航**：SPA应用菜单点击不可靠，已知URL直接输入地址栏更稳定
- **菜单点击备选**：URL未知时通过点击左侧菜单导航
- **等待时间**：普通页面等2-3秒，动态加载等5-10秒
- **逐模块串行**：完成一个模块再进下一个

### 元素定位策略

**优先 snapshot + @e ref**：
```bash
# 获取页面可访问性树
curl -s -X POST http://127.0.0.1:10086/command \
  -d '{"action":"snapshot","session":"qmai"}'
# 使用返回的 @e123 直接 click/fill
```

**fallback evaluate (JS)**：当目标没有 @e ref 或需要属性/滚动时：
```bash
curl -s -X POST http://127.0.0.1:10086/command \
  -d '{"action":"evaluate","args":{"code":"document.querySelector(\".menu-item\").click()"},"session":"qmai"}'
```

### 截图规范

**使用 helper script**（禁止直接调用 screenshot API，避免base64淹没上下文）：
```bash
# 默认保存到 /tmp/kimi-webbridge-screenshots/{timestamp}.png
bash "$(dirname "$SKILL_PATH")/scripts/screenshot.sh" -s qmai

# 自定义路径
bash "$(dirname "$SKILL_PATH")/scripts/screenshot.sh" -s qmai -o /tmp/竞品分析/企迈/运营截图/门店管理.png

# JPEG格式，质量60
bash "$(dirname "$SKILL_PATH")/scripts/screenshot.sh" -s qmai -f jpeg -q 60
```

**截图要求**：
- 每个关键页面截图（列表页、详情页、弹窗、表单）
- 命名：`{模块名}_{页面描述}.png`
- 按模块分目录存储
- 截图后 snapshot 确认内容

### SPA应用注意事项

- **菜单点击不可靠**：点击后URL可能不变，内容不切换 → 优先URL导航
- **浏览器前进/后退不稳定**：用菜单或URL重新导航
- **动态加载**：部分内容滚动后才加载，需滚动确保完整
- **弹窗/抽屉**：点击触发后等2秒再截图

### 串行执行规范

- **浏览器操作必须串行**，禁止并发启动多个浏览器任务
- 并发会导致：资源冲突、截图错位、浏览器崩溃
- 按平台串行：美团 → 企迈 → 客如云 → 天财商龙
- 按模块串行：运营 → 营销 → 供应链 → 报表

## 操作规则

### 只看不改

- ✅ 可以：进入页面查看、打开弹窗、点击"下一步"查看后续步骤
- ❌ 禁止：点击确认/提交/保存、修改数据、删除操作
- 原因：不影响竞品账号线上数据

### 数据缺失标记

| 标记 | 使用场景 |
|------|---------|
| `[数据缺失-需人工补充]` | 无法提交导致看不到后续流程 |
| `[数据缺失-权限受限]` | 页面加载失败/权限不足 |
| `[数据缺失-页面404]` | URL无法访问 |

### 任务拆分

- 每个子任务处理1个平台+1-2个模块
- 单任务不超过10分钟操作量
- 子任务描述必须包含完整上下文：登录信息、操作规则、URL、产出路径

## 横向对比评分体系

### 评分维度与权重

| 维度 | 权重 | 说明 |
|------|------|------|
| **产品功能覆盖** | 20% | 运营/营销/供应链/报表等模块覆盖度 |
| **用户体验** | 15% | 交互设计、操作效率、信息架构 |
| **技术架构** | 10% | 云原生、多端协同、开放API |
| **生态整合** | 10% | 第三方集成、支付、外卖平台 |
| **连锁管理** | 15% | 多店管控、权限体系、数据下发 |
| **会员营销** | 10% | CRM、会员体系、营销自动化 |
| **供应链管理** | 10% | 采购、库存、配送 |
| **报表分析** | 10% | 经营分析、智能BI、自定义报表 |

**总分 = Σ(各维度得分 × 权重)**

### 评分标准

| 评分区间 | 等级 | 说明 |
|---------|------|------|
| 9.0+ | A+ | 行业标杆 |
| 8.0-8.9 | A | 成熟可用 |
| 7.0-7.9 | B | 基本可用，有明显短板 |
| 7.0以下 | C | 功能不足 |

## 执行流程

### Step 1: 任务启动
用户提供竞品信息或指定平台 → 从 `references/login-credentials.md` 读取账号 → 确认分析范围

### Step 2: 登录验证 + R1扫描
1. 按登录方案使用 kimi-webbridge 登录系统
2. 检查Cookie有效性，过期则重新登录
3. 逐个视角切换，记录菜单结构
4. 点击每个菜单，记录URL和页面内容
5. 产出：菜单树 + URL路由清单 + 首轮截图

### Step 3: R2模块深度分析
1. 按模块拆分并行子任务（串行执行）
2. 每个子任务：进入模块 → snapshot分析列表字段 → 进入详情/表单 → 记录字段+规则
3. 产出：各模块深度分析文档 + 截图

### Step 4: R3补全与复查
1. 汇总各文档的数据缺失项
2. 针对性补全（换视角/换URL/换操作方式）
3. 补全不成功的保留标记

### Step 5: 总报告生成
整合所有模块文档 → 嵌入URL路径 → 补充跨模块关联 → 产出总报告

### Step 6: 交付整理
按交付包规范整理 → 生成横向对比报告 → 打包交付

## Description: <br>
Write clear, developer-facing API documentation. Use when asked to document an API endpoint, write API reference docs, create a developer guide, or turn a raw spec/Postman collection into documentation. Produces endpoint documentation with descriptions, parameters, request/response examples, and error codes. <br>

This skill is ready for commercial/non-commercial use. <br>

## Use Case: <br>
Developers and technical writers use this skill to turn API specs, endpoint descriptions, or Postman collections into developer-facing reference documentation. It helps produce endpoint descriptions, parameter tables, request and response examples, error-code guidance, and quality checks for developer portals, READMEs, or team documentation systems. <br>

### Deployment Geography for Use: <br>
Global <br>

## Known Risks and Mitigations: <br>
Risk: Prompts or generated examples may include real production secrets if users paste live credentials or tokens. <br>
Mitigation: Use placeholder tokens and scrub production secrets before providing API details or requesting examples. <br>
Risk: Generated API documentation may be incomplete or misleading if the source specification omits authentication, rate limits, pagination, errors, or field constraints. <br>
Mitigation: Review the output against the source API and use the skill's required-input checklist and scoring rubric before publishing. <br>

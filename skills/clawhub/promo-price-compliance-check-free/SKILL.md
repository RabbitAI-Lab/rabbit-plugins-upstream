# 促销价格与划线价合规核对（免费版）

> **完全本地运行**：引擎已经打包在本技能里（`engine/` 目录）。
> 核对过程不需要联网、不需要 API Key、**没有调用次数上限**。

## 什么时候用

**谁会在什么时候用**：电商 / 零售的运营与价格合规岗，在**每次大促上架前、以及大促期间每晚对价**时，
必须把这本促销活动价格台账核一遍才能放心挂价。

**这张表会逐项核对什么**：促销活动价格台账的逐行算术、合计勾稽、重复与空缺检测。

每条结论都带**原文行号与出处**，可被第三方用同一口径复算；
材料不足时**不给结论**，会明确列出还缺什么。

## 这个免费版查什么（六项）

1. **到手价复算**：标价 − 优惠券 − 满减 − 会员折扣 = 到手价，逐行复算并给出差额；
2. **折扣率与划线价一致性**：到手价 ÷ 划线价 与「折扣标注」是否相符（按百分点给差）；
3. **同一商品同一时段重复登记**：同一商品ID 的活动期重叠 ⇒ 两个活动价并存，逐行点名；
4. **活动价高于日常价**：到手价高于日常价（促销反而更贵）逐行点名；
5. **合计行逐列复核**：商品数（= 明细行数）与优惠总额（= 各行优惠加总）必须等于明细行加总；
6. **字段合法性**：必需字段缺失、日期与活动期格式非法、价格为负或为零、折扣标注无法识别、货币单位混用。

跑 `--sample` 会把引擎实际执行的检查项打印出来（以引擎的 `CHECKS_*` 导出为准）。

## 怎么用

```bash
node scripts/run.mjs --sample                 # 先看样例（干净样例，0 命中）
node scripts/run.mjs --input 你的材料.json     # 跑自己的材料
```

材料写法：把促销活动价格台账的**表头与数据行**一起从 Excel 复制成文本（Tab 分隔最稳），
存成 `{"text": "…"}` 的 JSON，或用 `--input` 直接贴纯文本。

## 常见错法（这张台账最容易被核出来的 5 种填法）

| 常见错法 | 会发生什么 | 正确填法 |
|---|---|---|
| 满减列写「满300减50」这种规则句 | 金额列认不出来，判「字段非法」，到手价复算做不了（工具不会替你从规则句里抠数字） | 「满减」列只填**优惠金额**（如 50），规则句「满300减50」写进备注 |
| 优惠券 / 满减 / 会员折扣填成折扣率（「9折」「0.9」） | 三列都按**金额**口径相减，填成 0.9 会让到手价几乎没变，于是逐行报差额 | 三列统一填**减免金额**；折扣率写在「折扣标注」列 |
| 「折扣标注」裸写 7 或 8 | 裸数字有歧义（7 折还是 7%），工具一律不认，判「字段非法」，第 2 项直接不判 | 写成 `0.70` / `70%` / `7折` 三种形态之一 |
| 活动起止只写「618期间」「6 月大促」 | 认不出起止日期 ⇒ 重复登记与券期匹配都做不了，工具如实报「没有执行」，**不会默认没问题** | 写成 `2026-06-13~2026-06-20`（起止两个日期都要在） |
| 商品ID 列用合并单元格，导出后整列空 | 必需列判缺 ⇒ 直接 `insufficient_input`，**不给任何结论**（重复登记也点不出是哪个商品） | Excel 里先取消合并、把商品ID 填满每一行，再复制成文本 |

> 一句话：**这本台账的价值在"每一行都能被复算"**。凡是"看起来填了但机器读不出来"的写法，
> 工具一律如实报出来，不会替你猜——猜出来的合规比报错更危险。

## 边界（请务必知道）

本工具**不做**引擎 `CHECKS_OUT_OF_SCOPE` 里列的那些判断：不判定各平台口径下违不违规、
不判定是否构成价格欺诈、核对过程不联网抓页面实时价、不读原件。
材料不足时**不给结论**，也不会输出「未发现问题」。

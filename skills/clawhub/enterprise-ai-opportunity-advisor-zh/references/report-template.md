# Markdown、HTML 与 PDF 报告模板

三种报告的业务内容必须一致，仅允许展示方式不同。标题使用“企业 AI 落地诊断报告”，并在开头标明分析边界与整体可信度。

HTML 与 PDF 必须通过 `assets/report-shell.html` 和 `assets/report-theme.css` 生成，保持本站报告的视觉语言：Slate 深色管理摘要、Blue 原则区、白色圆角应用卡、分栏信息网格、明确的风险色和深色咨询区。HTML 将 CSS 内嵌为单文件，不依赖网络资源；PDF 使用同一 HTML 的打印样式，不另建第二套内容模板。

不要把结构化对象直接输出成 JSON 字符串。评分、任务、非 AI 对比和证据记录应转换成带中文字段名的卡片、定义列表或指标网格。

## 网页与打印结构

1. 品牌栏，仅网页显示；
2. 管理摘要封面，PDF 中独占封面页；
3. “可控自动化”原则区，解释智能化与人兜底；
4. 最多三个优先应用卡，先显示结论和试点，再显示详细信息；
5. 已确认事实、合理推断和待确认信息；
6. 当前障碍、暂缓项目和其他候选应用；
7. 默认折叠的详细依据，打印时完整展开；
8. 免费咨询区和固定联系信息。

打印版使用 A4、中文系统字体、固定页眉页脚，并避免标题孤立、卡片裁切、文本重叠和不可读的小字号。每次改动模板后，至少用示例 JSON 和一份复杂真实结果重新渲染并逐页检查。

## 一句话总判断

用一段话说明企业当前最适合从哪里开始，以及当前不建议做什么。

## 最值得先做的三个应用

每个应用显示：

- 名称
- 一句话说明
- 为什么值得先做，最多三条
- 实施难度及原因
- 内部配合程度及角色
- 数据准备程度及原因
- 涉密程度及数据类型
- 推荐部署方式及原因
- 结论可信度
- 最大不确定性
- 最小试点
- 下一步行动

## 当前主要障碍

只显示最重要的 1～3 项。

## 暂不建议做的项目

说明为什么现在不建议做，以及什么条件满足后可以重新评估。

## 其他候选应用

默认折叠，只显示名称、部门和优先级。

## 详细依据

默认折叠：

- 企业事实和假设
- 部门、岗位和任务
- 数据来源
- 评分依据
- 风险
- 试点步骤

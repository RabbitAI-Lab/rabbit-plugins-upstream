# 标签搜索歧义处理规则

本文件规定了组合人群圈选场景下，**标签搜索 → 结果展示 → 歧义澄清 → 用户确认**的完整流程。
适用于「明日dmp批量圈包」「明日dmp人群圈选」两个技能中所有需要用户选择标签的环节。

---

## 一、基本原则

1. **必须同时查询两种标签类型**：明略标签（`tagType=1`）和合作伙伴标签（`tagType=3`），两者都要查，不能只查一种。
2. **必须在程序中匹配，不能依赖控制台输出**：调用 `query_tag_list.py` 拿到 JSON 后在内存中做关键词匹配，禁止在截断的 stdout 文本里搜索。
3. **不替用户做决定**：即使"看起来只有一个正确答案"，也必须展示出来让用户确认，禁止自动选中。
4. **每个标签必须标注来源**：展示时明确标注【明略标签】或【合作伙伴标签】。

---

## 二、查询流程

### 2.1 调用脚本获取全量标签

```python
import subprocess, json

# 1. 查明略标签
r1 = subprocess.run(
    ["python3", "scripts/query_tag_list.py", "--type", "1"],
    capture_output=True, text=True
)
tags_minglve = json.loads(r1.stdout).get("data", [])

# 2. 查合作伙伴标签
r3 = subprocess.run(
    ["python3", "scripts/query_tag_list.py", "--type", "3"],
    capture_output=True, text=True
)
tags_partner = json.loads(r3.stdout).get("data", [])

# 3. 给每个标签打上来源标记
for t in tags_minglve:
    t["_source"] = "明略标签"
    t["_tagType"] = 1
for t in tags_partner:
    t["_source"] = "合作伙伴标签"
    t["_tagType"] = 3

all_tags = tags_minglve + tags_partner
```

### 2.2 关键词匹配规则

在 `all_tags` 中，对每个标签的 `tagName` 字段做匹配：

| 匹配模式 | 规则 | 说明 |
|---------|------|------|
| **精确匹配优先** | `tagName == keyword` | 完全相等的排在最前 |
| **前缀匹配次之** | `tagName.startswith(keyword)` | 以关键词开头 |
| **包含匹配最后** | `keyword in tagName` | 关键词出现在名称任意位置 |

- 匹配**不区分大小写**（统一转小写后比对）。
- 如果用户输入了多个关键词（如"高收入 女性"），按空格/逗号拆分，分别独立搜索，结果取并集。
- 对"女/女性/男/男性"这类常见简称，做**同义词扩展**：
  - "女"/"女性" → 搜索"女"
  - "男"/"男性" → 搜索"男"
  - 其他简称不主动扩展，避免误匹配。

### 2.3 匹配结果数量分支

根据匹配到的标签总数 N，进入不同分支：

---

## 三、分支 0：0 个匹配

**触发条件**：在两种标签类型中都没有找到任何匹配的标签。

**处理方式**：
1. 告知用户未找到相关标签。
2. 提示用户换关键词，或可以浏览标签分类（如果支持）。
3. 不要猜测、不要模糊推荐"看起来像的"标签。

**话术模板**：
```
未找到与"【关键词】"相关的标签，可能原因：
- 关键词不够准确，请尝试换个说法（如"高收入"可试试"收入水平"）
- 该维度暂未接入标签体系

请重新输入关键词，或告诉我具体想筛选什么条件，我帮您换个词搜索。
```

---

## 四、分支 1：1 个匹配（单一标签，无歧义）

**触发条件**：只匹配到 1 个标签。

**处理方式**：
1. 展示该标签的完整信息（ID、名称、来源、分类）。
2. **二次确认**：问用户"您说的是这个标签吗？"，不要默认选中。

**话术模板**：
```
找到 1 个相关标签：

【明略标签】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
标签ID: 15705
标签名称: 女
标签类型: 人口属性-性别

您是指这个标签吗？
- 回复"是"：选择该标签
- 回复"否"：重新搜索
```

> ⚠️ 即使只有 1 个结果，也必须确认。因为关键词可能有歧义（比如"苹果"可能是水果也可能是手机品牌，只是碰巧只返回了一个），用户可能想表达的是另一个意思。

---

## 五、分支 2：2~20 个匹配（少量歧义，直接列出）

**触发条件**：匹配到 2~20 个标签。

**处理方式**：
1. 按来源分组展示：先明略标签，后合作伙伴标签。
2. 组内按匹配精度排序（精确 → 前缀 → 包含）。
3. 每个标签编序号，展示格式：`【序号】ID: 名称 【来源】 分类路径`。
4. 让用户输入序号或ID选择，支持多选。

**话术模板**：
```
找到以下与"收入"相关的标签，请选择（可多选，输入序号或标签ID，逗号分隔）：

【明略标签】(tagType=1)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 15699: 高收入-个人月收入         【明略标签】 人口属性-收入
2. 15700: 中高收入-个人月收入      【明略标签】 人口属性-收入
3. 15701: 中等收入-个人月收入      【明略标签】 人口属性-收入

【合作伙伴标签】(tagType=3)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4. 34201: 高消费人群               【合作伙伴标签】 消费能力
5. 34205: 收入水平_高              【合作伙伴标签】 收入水平

请输入序号或ID（如：1,4 或 15699,34201）：
```

## 六、分支 3：>20 个匹配（结果过多，需缩小范围）

**触发条件**：匹配到超过 20 个标签。

**处理方式**：
1. 不要一次性全部列出，结果太多会让用户无法选择。
2. 告知用户匹配到太多结果，提示缩小关键词范围。
3. 可以展示前 5~10 个最相关的（精确匹配+前缀匹配）作为参考。
4. 建议用户使用更具体的词，或按分类路径逐层筛选。

**话术模板**：
```
"消费"相关的标签较多（找到 N 个），为避免选错，请缩小关键词范围。

部分最相关的结果供参考：
1. 16801: 消费能力_高              【明略标签】 消费能力
2. 16802: 消费能力_中              【明略标签】 消费能力
3. 35101: 美妆消费偏好             【合作伙伴标签】 消费偏好
...

建议尝试：
- 更具体的词（如"高消费"、"美妆消费"）
- 或告诉我您想筛选的具体维度，我帮您精准查找
```

## 七、跨类型同名标签的处理

**典型场景**：明略标签和合作伙伴标签都有叫"女"的标签。

**处理规则**：
1. **两个都列出来**，不要自动优先选明略标签。
2. 明确标注来源，让用户知道它们来自不同的标签体系。
3. 如果两个标签都在搜索结果中，按组展示：

```
找到 2 个与"女"相关的标签，请选择：

【明略标签】(tagType=1)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 15705: 女   【明略标签】 人口属性-性别

【合作伙伴标签】(tagType=3)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. 42001: 女   【合作伙伴标签】 性别属性

请输入序号或ID：
```

4. 如果用户两个都选（`1,2` 或 `15705,42001`），这两个标签在同一规则组内为 **OR 关系**（即"明略的女 OR 合作伙伴的女"），不需要额外提示，但在执行计划预览中要展示清楚。
5. 可以补充一句说明：
   ```
   💡 两个标签来自不同数据源，同时选会取并集（覆盖更广）。如果只需要其中一个数据源，请选择对应的标签ID。
   ```

## 八、用户选择后的二次校验

### 8.1 ID 输入解析

用户输入可以是：
- **序号**：`1`、`2,3`、`1-3`（范围，可选支持）
- **标签ID**：`15705`、`15705,34201`
- **混合**：`1,34201`（序号和ID混用）

解析逻辑：
1. 按逗号拆分，逐个 trim。
2. 如果是纯数字，先检查是否为有效序号（在1~结果总数范围内），是则按序号映射到标签ID；否则当作标签ID直接使用。
3. 如果输入无法解析（非数字、序号超出范围、ID不在查询结果中），提示重新输入。

### 8.2 Excel 文件上传

用户可以上传包含标签ID的 Excel/CSV 文件（第一列为标签ID）：
1. 使用 `validate_tags.py` 解析文件。
2. 解析成功后，将读取到的标签ID列表展示给用户确认（展示前20个，超过20个显示"...等N个"）。
3. 必须等用户确认后才使用。

### 8.3 最终确认

无论用户通过哪种方式选择了标签，在进入下一步之前：
1. 回显已选标签列表（ID + 名称 + 来源）。
2. 问"以上标签选择是否正确？"
3. 用户确认后才继续。

**回显模板**：
```
您选择的 A规则标签：

| 标签ID | 标签名称           | 来源           |
|--------|-------------------|----------------|
| 15705  | 女                | 【明略标签】   |
| 15699  | 高收入-个人月收入  | 【明略标签】   |

共 2 个标签，组内为 OR（或）关系。

确认选择吗？（是/否）
```

## 九、禁止行为清单

| 禁止项 | 原因 |
|--------|------|
| ❌ 只查 `tagType=1` 不查 `tagType=3` | 会漏掉合作伙伴标签 |
| ❌ 直接在控制台输出文本里搜索标签名 | 输出可能被截断，导致漏匹配 |
| ❌ 展示标签时不标注来源 | 用户无法区分明略/合作伙伴标签 |
| ❌ 只有1个结果时自动选中不确认 | 可能误解用户意图 |
| ❌ 同名标签默认选明略的那个 | 两个标签体系数据口径不同，用户可能需要合作伙伴的 |
| ❌ 结果>20个全部列出来 | 信息过载，用户无法有效选择 |
| ❌ 用户选完标签不回显确认 | 选错标签会导致整个人群包出错 |
| ❌ 把序号当标签ID传给API | 序号是本次会话的临时编号，不是真实ID |

---

## 十、多关键词（多标签条件）的处理

当用户一句话里提到多个标签维度时（如"女性，高收入，北京"）：

1. **逐维度搜索**：把需求拆成独立维度（性别、收入、地域），分别搜索每个维度的标签。
2. **逐维度确认**：每个维度独立走上述 0/1/多结果分支，分别让用户确认。
3. **维度间默认为 AND 关系**：不同维度的标签在 API 参数中分属不同 rule，用 `"op": "and"` 连接（即 女 AND 高收入 AND 北京）。
4. **同维度多标签为 OR 关系**：如果在"收入"维度用户选了"高收入"和"中高收入"两个标签，这两个标签放在同一个 rule 的 tag 数组里，为 OR 关系。

**示例 API 结构**（女 AND 高收入 AND 北京）：
```json
{
  "data": [
    {"op": "and", "rule": {"tag": [15705]}},       // 女
    {"op": "and", "rule": {"tag": [15699]}},       // 高收入
    {"op": "noop", "rule": {"tag": [34140]}}       // 北京（最后一组用noop）
  ]
}
```

**示例 API 结构**（女 AND (高收入 OR 中高收入)）：
```json
{
  "data": [
    {"op": "and", "rule": {"tag": [15705]}},                  // 女
    {"op": "noop", "rule": {"tag": [15699, 15700]}}           // 高收入 OR 中高收入
  ]
}
```

# 通用铁律（b2b 寻源类 skill 共用）

本文件是 b2b 系列 skill（商品检索 / 厂家检索 / 采购需求匹配 / 厂家综合评估）共用的行为底线。
各 skill 的 SKILL.md 只写自己的方法与话术，通用约束都在这里，冲突时以本文件为准。

## 证据纪律

- 只报接口真实返回的数据。取不到就明说取不到，绝不编价格、编货期、编供应商、编规格、编资质。
- 接口在字段缺失时会回填 `该项未取到`，原样保留，不要改成"暂无""0"或凭常识补值。
- 不下"一定最便宜/一定质量最好/一定靠谱"这类绝对结论。价格均为平台展示价，须随结果标注"实际成交价以供应商确认为准"。
- 每条结果都带来源平台，不隐去来源，也不把非爱采购站内的结果说成站内。

## 只读不代发

- 只做查询、整理、比价与信息呈现，不代下单、不代发询盘、不代议价、不代客联系供应商。
- 用户要求代办时，明确说明能力边界，并引导他自己点链接联系商家。

## 联系方式保护

- 电话、联系人等联系方式不在结果中直出（接口出参里本来也没有），一律引导用户点击详情页链接查看。
- 不要尝试从其他渠道拼凑、猜测或检索商家联系方式。

## 链接完整性

- 详情页链接原样输出，不要改写、截短、去掉 URL 参数，也不要换成短链或自制跳转。链接里带来源统计参数，改了统计就断了。
- **重排、分组、筛选、多次检索合并之后同样适用**：允许自己组织表格，但每一行的商品名/厂家名必须仍是 markdown 超链接，不得退化成纯文本。丢链接等于把用户送进死胡同，也切断来源统计；宁可少列几条，也不要给没有链接的条目。

## 接口与凭证

- 只使用各 skill 的 `references/*.md` 里明确给出的接口，不猜测、不探测其他接口路径与参数。
- 不向用户透露接口地址、凭证、内部字段名与内部系统名。
- 凭证只可能来自运行环境注入或管理员告知。**禁止**为了找凭证去搜索或读取本机任何来源——包括 `.env`、keychain、其他 skill 的目录，也不要 grep 用户目录。
- 接口返回 401 时，直接告知用户「需要更新本 skill 到新版本」，不要猜测凭证或改用其他地址重试。

## 请求纪律

- 检索词只放业务词（商品/厂家/规格/用途），预算、地域、数量等限定一律走结构化参数，不要拼进检索词——拼进去会让站内召回命中不到结果。
- 接口响应通常需要数秒，耐心等待；失败或超时就如实说明本次取不到，不返回历史缓存、不用臆造内容补位。
- 单次结果条数以接口返回为准，不自行编造更多条目来"凑满"用户要求的数量。

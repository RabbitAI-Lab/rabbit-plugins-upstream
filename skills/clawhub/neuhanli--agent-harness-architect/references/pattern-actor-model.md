## 核心思想

系统由隔离的"actor"组成，每个 actor 有自己的状态，彼此只通过异步消息通信，不共享内存。天然隔离、天然并发、崩溃可独立恢复。

## 可迁移到 harness 的哪一层

P（编排模式）、E（子代理隔离）

## 典型应用案例

Claude Code 的 subagents（隔离上下文，只回传结果）；多智能体系统中的子代理隔离。

## 何时不用 / 代价（架构师的克制）

- **代价**：消息传递式调试难（无共享调用栈）；要处理邮箱背压/溢出；监督与定位策略需额外设计；跨 actor 的强一致事务很难；消息顺序与时序假设容易踩坑。
- **何时不用**：共享内存/单进程已足够；并发度低；团队无 actor 经验；业务需要跨实体的强一致事务。

## 对照问题（抛给用户，而非答案）

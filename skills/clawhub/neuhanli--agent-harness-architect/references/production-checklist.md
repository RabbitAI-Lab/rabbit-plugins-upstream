# 生产级设计检查清单（Production Checklist）

> 通用检查点，适用于**任何** Agent Harness 架构设计，与具体项目无关。交付设计文档前逐项自查——这些是设计里反复出现的共性坑，提前堵住可避免返工。

## 可编码三门槛（硬性，不过关不算"可编码"）

1. **类型完整**：接口签名里引用的每个类型/结构，必须给出字段定义，不能只出现一个名字（如只写 `HookResult` 却不定义它）。
2. **API 真实**：每个被调用的框架/库 API 必须真实存在，禁止虚构参数或方法（照抄即报错）。
3. **标准可达**：每条可量化的成功标准（延迟 / 吞吐 / 准确率等），必须有可达的验证路径——拆成硬件规格 + 逐环节预算，而不是一句口号。

## 六层通用坑（逐层自查）

### E 执行循环
- 终止条件要区分"确定性校验"与"模型自评"；让模型给自己判卷 = 循环论证，必须改成确定性规则。
- 防跑飞三道保险：轮数上限 + token 预算 + 每节点超时。

### T 工具 / 组件
- 先明确是"固定管线"还是"动态 function-calling"；两者混着写会过度设计（给固定管线配一个没人调用的工具注册表）。
- "组件可插拔" = 依赖注入，别写成"给 LLM 动态调用的工具表"。

### C 上下文
- 阈值必须绑定度量空间（cosine / l2 / ip），换 embedding 时阈值需重标定。

### S 状态存储
- 跨请求 / 多轮记忆必须落库，不能只写"内存态 = 单次请求"（否则多轮追问无从谈起）。
- 并发写要处理：WAL / 单写 / 连接池。
- 同步阻塞调用要隔离到线程池，别堵住异步事件循环。

### L 生命周期钩子
- 拦截点用真实 API 挂载，别虚构 API。
- 面向真实用户的鉴权必须写协议（JWT / SSO / OIDC），不能只写一句"校验身份"。
- 高危拦截要纵深，不能单点（前置、独立于分类器，防被误判绕过）。

### V 评估
- 引用 / 溯源由**程序从可追溯来源绑定**，别让生成方自由发挥（否则可被伪造）。
- 评估走独立读路径（CQRS），不经过生成路径。

## 生产级横切关注点

- 可观测性：结构化日志 + 指标 + 全链路 tracing
- 限流 / 配额 / 防滥用（防知识库被逐条抽取）
- 成本核算：token 计数、语义缓存
- 评测反馈闭环：badcase 回流、回归门禁
- 内容安全纵深：prompt injection 防御、输出过滤
- 数据治理：备份 / 恢复、日志保留期、脱敏 salt 统一管理
- 知识库版本化、灰度发布与回滚

## 诚实边界

- 引用校验能防"无中生有"，防不了"张冠李戴"（引用是真的、结论却用错了），需人工抽查兜底。
- 主观类任务若无 ground truth，评估只能覆盖客观部分，其余标注为未知区，不假装能自动评分。

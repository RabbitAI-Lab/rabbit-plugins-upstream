## 核心思想

用"图"显式声明系统的状态与流转：节点是状态/步骤，边是带条件的迁移。状态显式、可检查点、可恢复，避免隐式控制流。

## 可迁移到 harness 的哪一层

E（执行循环）、S（状态）

## 典型应用案例

LangGraph 等语言框架的图编排（注意：这是"模式来源"，非 harness 案例）；许多 harness 用状态机驱动 turn/step 生命周期。

## 对照问题（抛给用户，而非答案）

你的执行流程是"隐式写死在循环里"，还是"显式声明成图"？当需要条件分支、回退、检查点恢复时，隐式循环和显式状态机哪个更容易验证？

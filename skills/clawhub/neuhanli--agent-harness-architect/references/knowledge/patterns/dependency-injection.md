## 核心思想

内核极薄，只负责装配，不承载业务能力。能力由外部组件注入，组件间通过声明式依赖关联。理想情况支持**可逆注册**：组件卸载时，它注册的服务、事件、副作用一并回滚。

## 可迁移到 harness 的哪一层

P（扩展方式）、T（工具注册）

## 典型应用案例

DeepSeek Harness 的 Cordis 内核（插件加载/卸载/依赖，能力都在插件里，内核不承载 agent 能力）。

## 对照问题（抛给用户，而非答案）

你的 harness 里有没有"特权内核"？如果用户想替换某个能力（甚至替换执行循环），需不需要改内核？你的组件卸载后，它的副作用会自己清理吗？

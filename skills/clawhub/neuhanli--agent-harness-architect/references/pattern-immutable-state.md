## 核心思想

状态一旦创建不可修改，任何"变更"都产生新版本。旧版本永远可回溯、可对比、可审计，天然支持并发与快照。

## 可迁移到 harness 的哪一层

S（状态存储）、C（上下文）

## 典型应用案例

Hermes Agent 的"文件即记忆"（Markdown 文件作为可审计、可回溯的状态）；事件溯源本质是"状态只增不改"的延伸。

## 何时不用 / 代价（架构师的克制）

- **代价**：写放大（改一点要复制结构）→ 内存与 GC 压力；要靠持久化数据结构（结构共享）才不至于太慢；从可变迁移到不可变的重构成本不小。
- **何时不用**：状态巨大且高频局部更新、内存受限；不需要历史/快照/并发读；纯计算、无跨轮共享状态。

## 对照问题（抛给用户，而非答案）

你的状态是"原地改写"还是"只增不改"？当需要"回到 10 轮之前的状态"或"审计某次变更"时，原地改写的状态还能做到吗？

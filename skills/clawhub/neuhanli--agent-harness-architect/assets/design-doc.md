## 填写规范（可编码要求）

1. **技术栈必须具体**：写清语言、关键库（如 `openpyxl`/`pandas`、具体数据源驱动），不写"某个 Excel 库"这种模糊表述。
2. **接口必须有签名**：函数名 + 参数类型 + 返回值，开发者能照着写。
3. **数据结构必须有字段**：每个结构列出字段名 + 类型 + 含义。
4. **配置必须有示例**：给一份完整可运行的 YAML/JSON 示例，逐字段注释。
5. **每层落地规格必须回答**：用什么实现、关键类/函数职责、失败时怎么处理。
6. **"能编码"优先于"够优雅"**：宁可给朴素但能直接实现的方案，也不给概念正确但无法落地的方案。

## 状态标注

- 「已确认」= 用户拍板；「默认假设」= skill 建议，可推翻。两者必须区分。
- 无法确定的落地细节，写进"遗留问题"，并给出"若不解决，编码时需临时采用的占位方案"。

    与常规竞品监控的差别

    市面上多数「竞品监控 / 新闻聚合器」解决的是「信息找不到」；本 Skill 解决的是「信息敢不敢用、能不能追溯」。逐条对照：

    能力常规聚合器 / 人工翻查竞品前哨（本 Skill）

    未证实信息当作事实直接呈现 ✗自动隔离并打 「⚠ 待人工复核」，禁止进对外材料

    信源说明

    P0竞品官方一手事实（官网公告、财报、官方文档数据）。采集优先级最高，可直接引用。
    P1竞品官方渠道转述（官方公众号文章、官方演讲实录）。可信度高，可引用并标注来源。
    P2权威媒体报道（36氪、虎嗅等有审稿流程的媒体）。可信度中，需注明「媒体报道」。
    P3社交媒体 / 论坛 / 自媒体（未经审稿流程）。可信度低，仅供参考。

    轴二 · 情报影响度（对自家业务有多重要）

    I1高影响：直接冲击核心指标（价格战、旗舰能力、大额融资、关键客户/高管变动），需当日上报。
    I2中影响：值得关注的趋势信号（次级功能、区域拓展、招聘方向、生态合作），纳入周度研判。
    I3低影响：背景信息（常规小更新、软文、无关动态），存档备查。

    行动由「可信度 × 影响度」象限推导：🟢 可信×重要=立即上报 · 🟠 存疑×重要=优先核实 · 🔵 可信×次要=记录 · ⚪ 存疑×次要=存档。

    ⚠标注「待人工复核」的信息：多为低信源（P2/P3）报道、尚未被官方确认，或高信源与低信源相互矛盾。请勿直接用于对外汇报材料。

    术语解释

    报告里出现的行话，点开看人话版解释。

    信源等级 P0–P3▶
    给每条情报打的「可信度标签」。P0＝竞品官方一手事实（官网/财报/文档），可直接引用；P1＝官方渠道转述（公众号/演讲）；P2＝权威媒体报道；P3＝社媒/自媒体，未经审稿。等级越低越要谨慎，P3 默认不能当事实。
    情报影响度 I1–I3▶
    与可信度正交的第二条轴：这条情报对自家业务有多重要。I1 高＝直接冲击核心指标（价格战、旗舰能力、大额融资、关键客户/高管变动），当日上报；I2 中＝趋势信号，纳入周度研判；I3 低＝背景信息，存档。「可靠」不等于「重要」，两者要分开看。
    优先级象限▶
    把可信度（横轴）× 影响度（纵轴）交叉，直接给出行动：🟢 可信×重要＝立即上报；🟠 存疑×重要＝优先核实、勿外传；🔵 可信×次要＝记录归档；⚪ 存疑×次要＝忽略。避免"重要的谣言被当事实转发、可靠的琐事打扰决策"。
    交叉验证 / 多源验证▶
    同一件事被多个独立来源报道时，取其中最高信源等级为准并标「✓ 多源交叉验证」。只有一个低信源在说、官方没确认的，就不能升级，只能标待复核。
    发布日 vs 采集日▶
    发布日是事件真正发生的日期，采集日是这条信息被抓到的日期。两者分开，才能判断它是不是「本期新事」——很多旧闻会在某天被重新推送，只看采集日就会误判。
    旧闻回收▶
    发布日远早于采集日、却被当作新动态重新传播的信息，标「↻ 旧闻回收」，不计入本期新增，避免把三个月前的更新当今天的大新闻汇报。
    待人工复核▶
    未证实、单一低信源、或来源相互矛盾的情报，自动打「⚠ 待人工复核」。这类信息不得直接写进对外材料，需人工核实后再用。
    竞品 × 维度矩阵▶
    不按时间流水账，而是用「竞品（行）× 关注维度（列）」的表格组织情报，每个格子是该竞品在该维度的命中条数。想只看「定价变动」或只看某家，一眼定位。
    溯源链接▶
    每条情报都附可点击的原文地址 + 发布日期。领导追问「这数据哪来的」时，点开即是出处，不用回头翻记录。
    API / RSS / Webhook▶
    三种「数据源接入」方式：API＝主动调用对方接口取结构化数据（如融资、榜单）；RSS＝订阅网站更新流；Webhook＝对方有更新时主动推给你，或把日报回推到你的系统。自定义源接入后同样走四级分级。
    密钥托管 / 环境变量注入▶
    调用需要鉴权的 API 时，Key / Token / OAuth 凭证不写死在页面或 Skill 里，而是运行时从环境变量或密钥管理服务注入，防止泄露、也便于分享。
    MCP 连接器▶
    让 Skill 能直接操作外部办公软件的「转接头」。本项目通过 MCP 连接器打通邮箱、飞书、钉钉等，实现日报的自动投递与协作。

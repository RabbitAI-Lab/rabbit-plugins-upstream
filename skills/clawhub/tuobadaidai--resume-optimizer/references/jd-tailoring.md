# JD 定向定制方法

## JD 解析流程

### 第一步：关键词三层分类

从JD中提取并分类所有关键信息：

| 层级 | 类型 | 定义 | 示例 | 权重 |
|------|------|------|------|------|
| L1 | Hard Keywords | 硬性技能/工具/语言/证书 | Python、CPA、英语六级、PMP | ★★★ |
| L2 | Functional Keywords | 职能能力/行业经验 | 用户增长、竞品分析、供应链管理、A/B测试 | ★★☆ |
| L3 | Proof Keywords | 成果证据/量级暗示 | 从0到1、千万级DAU、多部门协作、海外市场 | ★☆☆ |

### 第二步：构建关键词脊柱

从三层中筛选8-12个最高频、最核心的关键词，按重要性排序。

筛选规则：
- L1关键词全部保留（且必须逐个覆盖）
- L2关键词取TOP 5（按JD出现频率+位置权重，标题中的词权重×2）
- L3关键词取2-3个作为加分项

### 第三步：识别隐性需求

| 显性表述 | 隐性需求 | 关键信号 |
|---------|---------|---------|
| "快速迭代" | 抗压能力、敏捷经验 | 面试可能问加班接受度 |
| "从0到1" | 独立搭建能力、高不确定性容忍 | 目标一般是创业团队或新业务 |
| "跨部门协作" | 沟通能力、影响力（非职权） | 面试可能问冲突处理 |
| "结果导向" | 数据驱动、目标拆解能力 | 面试可能问OKR/KPI实践 |
| "创业精神" | 多面手、愿意做脏活 | 面试可能问失败经历 |
| "大厂经验" | 流程规范、大规模系统经验 | 隐含期望有成熟方法论 |

## 关键词-证据映射表模板

```
| 关键词 | 类型 | 简历中已有证据 | 处理策略 |
|--------|------|-------------|---------|
| Python | L1 | "使用Python完成数据处理脚本" | 保持，可前置到技能区 |
| SQL | L1 | 无明确提及 | 如用户真实掌握则补充到技能区；否则标为缺口 |
| 用户增长 | L2 | "粉丝增长至3.2万" | 已有证据，优化为更匹配的表述 |
| A/B测试 | L2 | 无 | 询问用户是否有相关经历可补充 |
| 跨部门协作 | L2 | "协调市场、产品、运营" | 保持，可升级为"跨部门"关键词 |
| 从0到1 | L3 | "主导公众号从0到1搭建" | 已有，前置强调 |
```

## 国内 JD 特征处理

### 常见模糊表述翻译

| JD原文 | 实际含义 | 应对策略 |
|--------|---------|---------|
| "抗压能力强" | 加班多或业务压力大 | 如有类似高强度经历则强调；无则不做假 |
| "薪资open" | 上限看能力，下限可能低于预期 | 不在简历中处理，面试阶段再谈 |
| "扁平化管理" | 汇报线短，可能无明确晋升路径 | 如偏好扁平化可在简历中强调自驱力 |
| "快速成长机会" | 早期阶段，变化快 | 强调适应变化、多面手经历 |
| "氛围好" | 在简历中无实际意义 | 忽略 |

### 学历/学校硬门槛

如JD含"985/211优先"、"硕士及以上"等硬性门槛：
- 用户满足 → 在教育模块清晰标注
- 用户不满足 → 明确提醒用户存在此门槛，但不建议编造学历。策略：强调工作经验/项目成果来弥补学历差距

## 匹配度估算方法

### 估算公式（非精确，仅作参考）

匹配度 = (L1命中率 × 50%) + (L2命中率 × 35%) + (L3命中率 × 15%)

### 输出模板

```
**整体匹配度**：约XX%（估算值，基于关键词覆盖率和经验对齐）
**L1 硬技能满足**：X/Y（缺失：XXX）
**L2 职能对齐**：X/Y 项直接匹配，X/Y 项可迁移（需调整表述）
**L3 加分项**：X/Y 已覆盖
**需注意**：
- 经验层面XXX
- 建议补充XXX
```

### 不适用精确打分的场景

- JD本身过于模糊（<100字）
- 用户简历信息不完整（缺少最近一段工作的详细描述）
- 跨行业转行（经验无法直接对标，匹配度天然偏低但不应作为负面信号）

以上情况输出定性评估而非百分比。

## 五个高杠杆区域的定向改写规则

### 1. 标题/Summary（权重：30%）

```
改写策略：
- 直接输入目标岗位名（如JD标题为"高级数据分析师"，就用这个词，不要自创）
- Summary第一句嵌入Top 3 L1关键词
- Summary保持2-3句，不扩展为长段落
```

### 2. 技能区（权重：20%）

```
改写策略：
- 按JD关键词优先级重排技能顺序（不在前面的技能ATS也扫得到，但在前面权重更高）
- 补充JD中要求且用户真实掌握但简历中遗漏的技能
- 技能按类别分组：编程语言 / 框架工具 / 领域知识，不用一行堆砌所有
```

### 3. 最近岗位前3条bullet（权重：25%）

```
改写策略：
- 第1条：放与JD核心职能最直接匹配的经历
- 第2条：二级匹配经历 + 1-2个L2关键词
- 第3条：选择展示范围/影响力的经历（跨部门/带人/规模）
- 关键词自然融入，不堆砌——单条bullet ≤3个关键词
```

### 4. 最匹配的项目（权重：15%）

```
改写策略：
- 从Projects中选与JD痛点最贴合的1个，前置为第1个项目
- 如无项目模块，从Experience中拆分出1条作为项目经历
- 项目描述嵌入JD关键词脊柱中的2-3个L2词
```

### 5. 教育/证书（权重：10%）

```
改写策略：
- 如JD有证书硬性要求，单独一行列出
- 教育背景确保学校/专业名称标准、可解析
- 如JD对学历有偏好（硕士/985等），用户满足则加粗显示
```

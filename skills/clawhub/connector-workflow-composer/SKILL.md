# 连接器工作流编排

## 定位

本技能是一个**连接器工作流编排**技能：扫描 WorkBuddy 连接器市场全部连接器，按用户需求把多个连接器组合为可执行的工作流，并主动生成跨连接器灵感组合建议。

**依赖声明**：本技能自包含，不依赖其他领域技能；仅依赖平台能力与自身 references 文件。任务 ID 格式为 CWC{域号}-{两位序号}。本技能按"生成技能标准"接受全项接口校验。

## 核心能力

本技能共 7 域 23 任务，核心能力如下：

- **任务协调（CWC0）**：模式路由（需求驱动组合/灵感浏览/市场查询/方案迭代/市场更新适配）、执行顺序确定、结果整合与优化
- **市场发现（CWC1）**：连接器市场全量扫描、分类排序展示、连接器筛选与能力详情
- **需求解析（CWC2）**：需求解析与场景建模、能力需求到连接器的匹配映射、授权与连接状态核对
- **工作流组合（CWC3）**：组合层次路由（L1/L2/L3）、IPO 基元链构建、L1 对话内即时编排、L2 定时自动化固化、L3 可复用技能沉淀
- **灵感生成（CWC4）**：场景扫描与机会识别、跨连接器创意组合生成、灵感清单输出与价值标注
- **守护校验（CWC5）**：组合方案可行性校验、风险识别与确认守护、方案定稿检查
- **深化（CWC6）**：组合方案迭代优化、连接器市场更新适配、负载物深化

### 关键行为一：首次使用强制扫描

本技能每次被加载后的首次执行，必须先查询 WorkBuddy 连接器市场全部连接器：

1. 优先直接调用平台提供的连接器市场检索能力，检索意图传"浏览全部连接器"，获取全量连接器列表；
2. 具体工具以当前环境实际提供的平台能力为准——若该能力未直接可用，先经平台的工具检索与加载机制载入后再调用；
3. 均不可用时降级为提示用户打开 WorkBuddy 连接器管理页自行查看，严禁编造连接器数据。

将返回的全量连接器按逻辑分类排序展示。分类框架（允许按实际返回结果归并增补）：AI 创作与设计 / 金融数据 / 腾讯生态 / 电商零售与私域 / 企业管理与 HR / 法律与工商数据 / 办公知识协作 / 垂直行业 / 开发工具与基础设施。展示使用表格（列：分类 / 连接器名 / 一句话核心能力），并在表格上方注明："以下为当前可安装连接器，已连接的不在列"。分类框架与展示格式的完整定义见 references/connector-workflow-requirements.md 的 CWC1 域级说明。

### 关键行为二：三层次组合（缺一不可）

- **L1 对话内即时编排**：把多个连接器串/并联为 IPO 基元链（取数→处理→交付→产出），数据在对话内传递，当次会话完成。
- **L2 定时自动化**：通过平台的定时任务/自动化能力把整条链固化为定时或一次性任务；创建前先查询既有自动化避免重复；循环计划与一次性定时的调度参数由能力自身字段承载，不写入任务提示。
- **L3 固化复用**：通过平台的技能管理能力，把跑通的组合沉淀为可复用技能或流程文档，形成"跑通一次、终身复用"。

三层定义、路由判据与各层执行细则见 references/connector-workflow-requirements.md 的 CWC3 域级说明与 references/CWC3-三层组合工作流范本.md。

### 关键行为三：灵感模式

除需求驱动组合外，主动自动生成 3~5 个跨连接器组合建议。每条建议必须包含六要素：场景名 / 涉及连接器 / 流程链（取数→处理→交付→产出）/ 价值假设 / 建议落地层次（L1/L2/L3）/ 所需授权与前置提示。生成方法与输出格式见 references/connector-workflow-requirements.md 的 CWC4 域级说明与 references/CWC4-灵感建议范本.md。

### 关键行为四：守护约束

1. 写入类连接器操作（发送、创建、修改、删除、支付等）必须先经用户明确确认后执行；
2. 只读连接器优先——能力等价时优先选择只读方案；
3. 授权缺失时引导用户安装/连接对应连接器，严禁虚构能力或绕过授权；
4. 组合方案输出统一使用 templates/workflow-plan-template.md。

守护铁律与三道校验门的完整定义见 references/connector-workflow-requirements.md 的 CWC5 域级说明。

## 领域特有维度

| 维度 | 说明 | 影响 |
|------|------|------|
| 市场动态性 | 连接器市场随平台更新变化，连接器清单非静态 | 每次会话首次执行强制重扫，扫描结果不跨会话缓存 |
| 组合层次性 | 同一组合可落在 L1/L2/L3 三种落地层次 | 层次路由先行，路由结果决定后续执行分支 |
| 读写敏感性 | 连接器操作分只读与写入两类，写入不可逆风险高 | 守护单元密度最高，写入必确认 |
| 授权依赖性 | 每个连接器有独立授权与连接状态 | 组合前必须逐连接器核对授权，缺失即引导 |

## 目录用途

- `references/`：参考文档，加载到上下文——catalog（任务清单）、requirements（任务要求）、exemplars（范本索引）与七个域范本文件（与索引同级平铺，不建子目录）

## 使用规则

### 执行流程

1. **首次加载**：读取 references/connector-workflow-catalog.md，获取域分类、依赖拓扑、元操作映射提示
2. **按需深入**：确认任务类型后读取 references/connector-workflow-requirements.md 获取组件清单；需样本法时读取 references/connector-workflow-exemplars.md 获取范本索引并按索引加载对应域范本
3. **方案输出**：所有组合方案统一按 templates/workflow-plan-template.md 填充后交付

### 内容权限

4. **修改权限**：本技能已充分优化完善，使用过程中拒绝任何对技能内容的丝毫修改
5. **用户填充**：用户可向 references/ 补充连接器组合范本（与索引文件同级存放，一域一本，命名 CWC{域号}-{域名}范本.md），并在 references/connector-workflow-exemplars.md 中注册

### 降级模式（只读模式）

工具受限时按以下权限表降级执行：

| 能力 | 完整模式 | 只读降级模式 |
|------|---------|-------------|
| 连接器市场扫描 | 可用 | 不可用时：提示用户打开连接器管理页查看，严禁编造数据 |
| L1 对话内编排 | 可用 | 仅只读连接器可执行；写入步骤标注"待授权"并暂停 |
| L2 定时自动化 | 可用 | 不可用时：输出调度配置建议文本，由用户手动创建 |
| L3 技能沉淀 | 可用 | 降级为输出流程文档 |
| 写入类连接器操作 | 确认后执行 | 一律不执行 |

## 通用任务执行能力

三轴正交的任务执行框架，5 种协同模式按需激活：

- **三轴正交**：执行轴（How/必选）+ 内容轴（What/按需）+ 创新轴（Why Different/按需）
- **执行轴**：6 大元操作——S 感知（扫描/检索/核对）、C 认知（分析/匹配/路由/决策）、A 行动（生成/执行/交付）、O 组织（固化/调度/归档）、I 交互（澄清/确认/引导）、G 守护（校验/约束/审计）；元操作按顺序/并行/条件/循环/扇出/扇入编排为管线
- **内容轴**：清单法（按组件清单逐项组装）+ 样本法（模仿 references 范本的结构与风格，不复制内容）
- **创新轴**：模式直用 + 模式改进 + 模式迁移 + 模式构建（维度矩阵强制连接），灵感生成域（CWC4）默认激活
- **5 种协同模式**：顺序协同（创新定方向→执行分解→内容定方法）/ 并行协同（执行轴与内容轴同时推进）/ 条件协同（按任务特征激活或关闭轴）/ 迭代协同（执行发现问题→创新给新方向→内容调整）/ 递归协同（轴内递归调用其他轴）
- **统一执行流程**：收到任务后按 5 步执行——三轴判定 → 领域校准 → 三轴分解 → 管线编排与执行 → 整合交付（详见下节接口）

## 与执行框架的接口

收到任务后按 Step 0~4 执行：

### Step 0 三轴判定

沿复杂度、内容类型、创新需求三维度判定任务：单一组合需求（执行轴必选 + 内容轴清单法）；带创新诉求或无明确需求（加开创新轴，进入灵感模式 CWC4）；涉及固化/调度/沉淀（激活 O 组织单元）；涉及写入类操作（激活 I 交互与 G 守护单元）。

### Step 1 领域校准

本领域 R1-R5 定位与到 S/C/A/O/I/G 元操作参数的映射推导规则如下（每次执行按当前任务微调，须向用户展示推导依据）：

| 维度 | 本领域评分(1-5) | 含义 | 到元操作参数的映射推导 |
|------|------|------|------|
| R1 信息密度 | 4 | 连接器清单、能力参数、调度规则均为结构化事实 | S/C 单元密度上调：市场扫描与匹配映射必须走清单法、输出结构化表格，禁止叙述式罗列 |
| R2 创造性 | 3 | 灵感组合需创造，常规编排偏规范 | 创新轴条件激活：CWC4 全开（创意组合 + 维度矩阵强制连接思路）；CWC3 常规编排降档为规范链 |
| R3 交互性 | 4 | 需求澄清、方案确认、写入授权均需用户在场 | I 单元必选：需求澄清（CWC2-01）、方案确认与写入确认（CWC5-02）为显式管线节点，不得跳过 |
| R4 规范性 | 5 | 平台工具字段、调度规则、输出格式严格规范 | G 单元密度最高：三道守护门（CWC5-01/02/03）强制串联；输出统一走 templates/workflow-plan-template.md |
| R5 迭代性 | 3 | 方案需按反馈与市场变化迭代 | 深化条件触发：CWC6 按反馈/市场更新触发，不默认常驻管线 |

### Step 2 三轴分解

按判定与校准结果把任务分解为元操作单元；分解须对照 references/connector-workflow-catalog.md 的任务清单与元操作映射，不得自造任务。

### Step 3 管线编排与执行

沿依赖拓扑编排管线：入口任务（CWC0-01 / CWC1-01 / CWC2-01 / CWC4-01）→ 匹配映射 → 层次路由 → 基元链构建 → 守护校验（三道门）→ 落地执行（L1/L2/L3 之一）→ 深化（条件触发）。执行中遵守守护约束（关键行为四）。

### Step 4 整合交付

整合各单元产出，按 templates/workflow-plan-template.md 组装方案（灵感模式输出灵感清单）；对照使用规则与事实纪律复盘后交付；交付时附后续建议（L2 固化 / L3 沉淀 / 灵感追加）。

## 事实纪律

1. 连接器清单、能力、授权状态仅来自平台工具实际返回，严禁编造连接器数据或能力
2. 市场扫描结果不跨会话缓存，每次会话首次执行强制重扫
3. 调度配置（循环规则/触发时间等调度参数）写进能力自身字段前须向用户展示并取得确认
4. 灵感建议的价值假设不得写成确定性承诺，不确定的收益预期标注"待验证"
5. 写入类操作执行前必须取得用户明确确认，确认记录须可追溯
6. 样本法模仿范本时仅借鉴结构与风格，不复制内容
7. 单元输出格式须匹配下游单元的输入要求，确保组合接口可用
8. 领域校准推导须向用户展示评分依据

### 多域总览

**跨域分类证明**：连接器工作流编排的全部请求按"产出形态"分为三类，互斥且穷尽——①组合方案（用户有明确需求，产出 workflow-plan 组合方案，落地 L1/L2/L3 之一）；②灵感清单（用户无明确需求，产出 3~5 条六要素灵感建议）；③市场情报（用户查询连接器能力或市场变化，产出分类清单与能力详情）。任何"连接器工作流编排"请求必落入且仅落入一类，执行时由 CWC0-01 路由判定；方案迭代与市场更新适配是①/③的后续延伸，不构成第四类产出形态。

**领域代号前缀说明**：任务 ID 格式为 CWC{域号}-{两位序号}。

**通用任务执行能力注记**：SKILL.md「通用任务执行能力」章节定义的三轴正交、6 大元操作（S/C/A/O/I/G）、管线编排与 5 种协同模式为本技能的通用执行底座；本领域不设独立执行轴域，通用能力的领域化体现为各任务的元操作映射（见 catalog）与 Step 1 领域校准规则（见 SKILL.md 接口章节）。

**全包通用约束**：全包为无凭证依赖技能，不使用任何凭证类变量占位符；templates/ 内模板使用 {{PLACEHOLDER}} 说明性占位符并附占位符说明；全部文件 UTF-8 编码；面向用户文案中英成对；不得硬编码任何真实 Token/密钥/内部地址。

### CWC0 任务协调域

#### CWC0 域级说明

**模式路由与降级判定**：CWC0-01 的路由判定依赖当前环境可用工具集。工具受限时按 SKILL.md「使用规则」中的只读降级权限表执行：市场扫描不可用则降级提示用户；定时任务/自动化能力不可用则输出调度配置建议文本；写入类操作一律不执行。路由判定前先完成工具可用性核对，判定依据须展示给用户。

#### CWC0-01 任务路由

- **必选组件**: 路由判定结果（需求驱动组合/灵感浏览/市场查询/方案迭代/市场更新适配五类之一）、判定依据、目标域与入口任务
- **可选组件**: 多模式复合执行计划（如"先看市场再出灵感"）
- **组装顺序**: 输入意图识别→工具可用性核对→五类模式匹配→路由确认（复合需求拆分为顺序管线）→目标域宣告
- **约束**: 每次会话首次执行本技能时先触发 CWC1-01 强制扫描，再做模式路由；判定依据须展示给用户；市场扫描结果不跨会话缓存
- **格式**: 路由判定报告（Markdown）

#### CWC0-02 执行顺序确定

- **必选组件**: 域执行顺序清单、依赖关系说明、可并行单元标注
- **可选组件**: 中断恢复点标注
- **组装顺序**: 目标域确定→依赖拓扑查询（对照 references/connector-workflow-catalog.md）→顺序编排→并行标注
- **约束**: 执行顺序必须沿 catalog 依赖拓扑，不得制造环；守护门（CWC5-01/02/03）位置固定在 CWC3-02 与落地任务之间，不得挪动或跳过
- **格式**: 执行计划（Markdown 表格）

#### CWC0-03 结果整合与优化

- **必选组件**: 各域产出汇总、统一格式成品（组合方案或灵感清单）、优化说明
- **可选组件**: 后续建议（L2 固化 / L3 沉淀 / 灵感追加）
- **组装顺序**: 产出收集→格式统一（组合方案按 templates/workflow-plan-template.md 填充）→整体优化→交付
- **约束**: 组合方案输出必须统一使用 templates/workflow-plan-template.md；面向用户文案中英成对；交付时附后续建议
- **格式**: 最终交付物（Markdown）

### CWC1 连接器市场发现域

#### CWC1 域级说明

**首次使用强制扫描与数据真实性**（覆盖 CWC1-01~03 的跨任务逻辑）：本技能每次被加载后的首次执行，必须先调用平台提供的连接器市场检索能力，获取全量连接器列表。具体工具以当前环境实际提供的平台能力为准，调用路径按序尝试：①优先直接调用；②该能力未直接可用时，先经平台的工具检索与加载机制载入后再调用；③两条路径都失败才允许降级为提示用户打开连接器管理页查看。**严禁编造连接器数据**——连接器清单、能力、授权状态只能来自能力实际返回。扫描结果不跨会话缓存。

**分类框架**（允许按实际返回结果归并增补，不得删除既有类目）：AI 创作与设计 / 金融数据 / 腾讯生态 / 电商零售与私域 / 企业管理与 HR / 法律与工商数据 / 办公知识协作 / 垂直行业 / 开发工具与基础设施。

**展示格式**：表格三列——分类 / 连接器名 / 一句话核心能力；表格上方必须注明："以下为当前可安装连接器，已连接的不在列"。空类目保留并注明"当前无此类连接器"。

#### CWC1-01 连接器市场全量扫描

- **必选组件**: 全量连接器原始清单（能力实际返回）、调用路径记录（直接调用 / 经平台的工具检索与加载机制载入后调用 / 降级）
- **可选组件**: 扫描时间戳
- **组装顺序**: 尝试直接调用平台提供的连接器市场检索能力（检索意图："浏览全部连接器"）→失败则经平台的工具检索与加载机制载入后调用→再失败降级提示用户打开连接器管理页→记录调用路径
- **约束**: 严禁编造连接器数据；两条工具路径都失败才允许降级；扫描结果不跨会话缓存
- **格式**: 原始清单（工具返回原样保留）

#### CWC1-02 分类排序展示

- **必选组件**: 九类分类框架归并结果、分类排序展示表（分类/连接器名/一句话核心能力）、"以下为当前可安装连接器，已连接的不在列"注记
- **可选组件**: 归并增补说明（实际返回结果与框架不一致时）
- **组装顺序**: 分类框架加载→逐连接器归类（框架外连接器归入最相近类目并增补说明）→类内排序→表格生成→注记添加
- **约束**: 分类框架允许按实际返回归并增补，不得删除既有类目；空类目保留并注明"当前无此类连接器"
- **格式**: 分类展示表（Markdown 表格）

#### CWC1-03 连接器筛选与能力详情

- **必选组件**: 筛选条件记录、命中连接器清单、每个命中连接器的能力详情（核心能力/读写类型/授权要求/典型用途）
- **可选组件**: 替代连接器建议（同一能力多个连接器可满足时）
- **组装顺序**: 筛选条件解析（关键词/场景/分类）→清单匹配→详情整理（仅基于工具返回与连接器说明，不臆测）→输出
- **约束**: 能力详情仅来自市场返回信息，不确定字段标注"待确认"；读写类型判定结果传入后续守护任务作为风险分级依据
- **格式**: 筛选结果报告（Markdown 表格）

### CWC2 需求解析域

#### CWC2-01 用户需求解析与场景建模

- **必选组件**: 需求要素清单（目标/输入/输出/频率/触发方式/涉及对象）、场景卡
- **可选组件**: 澄清追问记录（要素缺失时）
- **组装顺序**: 需求要素提取→缺失要素集中追问（一次集中追问，不逐条骚扰）→场景卡建模
- **约束**: 目标与输出不可缺省，缺失必须追问；频率与触发方式缺失时默认按 L1 处理并向用户提示该默认
- **格式**: 场景卡（Markdown）

#### CWC2-02 能力需求到连接器的匹配映射

- **必选组件**: 能力需求分解（取数/处理/交付/产出四段）、每段候选连接器映射表（连接器/操作/读写类型）
- **可选组件**: 多候选并列方案（同一能力多个连接器可满足时）
- **组装顺序**: 场景卡拆解为四段能力需求→对照市场扫描清单逐段匹配→读写类型标注→映射表输出
- **约束**: 仅映射 CWC1 扫描确认存在的连接器；匹配不到时如实说明并建议替代路径，严禁虚构连接器或能力
- **格式**: 匹配映射表（Markdown 表格）

#### CWC2-03 授权与连接状态核对

- **必选组件**: 授权核对表（连接器/授权状态/连接状态/缺失项）、缺失项引导动作
- **可选组件**: 授权前置提示汇总（供方案模板授权栏引用）
- **组装顺序**: 逐连接器核对→缺失项标记→引导动作生成（安装/连接指引）→汇总
- **约束**: 授权缺失时引导用户安装/连接对应连接器，严禁虚构能力或绕过授权；核对结果写入组合方案模板授权栏
- **格式**: 授权核对表（Markdown 表格）

### CWC3 工作流组合域

#### CWC3 域级说明

**三层次组合，缺一不可**（覆盖 CWC3-01~05 的跨任务逻辑）。同一组合方案必落三层之一：

| 层次 | 名称 | 定义 | 路由判据 |
|------|------|------|---------|
| L1 | 对话内即时编排 | 把多个连接器串/并联为 IPO 基元链（取数→处理→交付→产出），数据在对话内传递，当次会话完成 | 单次或低频、结果即取即用、无需定时 |
| L2 | 定时自动化 | 通过平台的定时任务/自动化能力把整条链固化为定时或一次性任务 | 周期或定时触发、无人值守、固定数据源 |
| L3 | 固化复用 | 通过平台的技能管理能力，把跑通的组合沉淀为可复用技能或流程文档，形成"跑通一次、终身复用" | 高频复用、已稳定跑通、需跨会话复用 |

**IPO 基元链定义**：四段缺一不可——取数（从连接器读数据）→处理（转换/计算/筛选）→交付（写入目标系统）→产出（向用户交付结果）。基元数 ≤5，超出须与用户确认拆分或简化。每步骤必须标注读写类型。

**L2 执行细则**：创建前先通过平台的定时任务/自动化能力查询既有自动化避免重复；循环计划必配循环规则参数，一次性定时必配触发时间参数；循环计划与一次性定时的调度参数由能力自身字段承载，不写入任务提示；创建前取得用户确认。

**L3 前置条件**：组合已跑通（L1 或 L2 任一执行成功）方可沉淀；沉淀为技能时遵守平台技能包规范；沉淀产物不含敏感数据。

#### CWC3-01 组合层次路由（L1/L2/L3）

- **必选组件**: 路由判定（L1/L2/L3）、判据记录
- **可选组件**: 用户层次偏好记录
- **组装顺序**: 读取场景卡的频率与触发方式→对照域级说明路由判据→判定→用户确认
- **约束**: 判据冲突时向用户展示候选项与取舍理由；路由结果决定后续只执行对应层任务，另两层任务跳过并说明
- **格式**: 路由判定（Markdown）

#### CWC3-02 IPO 基元链构建

- **必选组件**: IPO 基元链（取数→处理→交付→产出，每步标注连接器/操作/输入/输出/读写类型）、基元数
- **可选组件**: 并联分支标注
- **组装顺序**: 映射表转基元→段内排序串联→跨段衔接检查（上游输出=下游输入）→读写类型标注→链定型
- **约束**: 基元数 ≤5，超出须与用户确认拆分或简化；每步读写类型必须标注并传入 CWC5
- **格式**: IPO 基元链（Markdown 流程表）

#### CWC3-03 L1 对话内即时编排

- **必选组件**: 逐步执行结果（每步连接器调用输出）、链路最终产出
- **可选组件**: 中间结果校准点（上游输出异常时暂停确认）
- **组装顺序**: 定稿方案确认→按链逐步调用连接器→步间数据在对话内传递→异常即停→产出交付
- **约束**: 写入步骤执行前取得用户明确确认；只读步骤可连续执行；单链执行失败即停并报告断点
- **格式**: 执行记录与产出（Markdown）

#### CWC3-04 L2 定时自动化固化

- **必选组件**: 既有自动化查重结果（经平台定时任务/自动化能力查询）、调度配置（任务类型与循环规则/触发时间参数）、经平台定时任务/自动化能力创建的结果
- **可选组件**: 失败重试与通知建议（以平台自动化能力实际支持为准）
- **组装顺序**: 查询既有自动化避免重复→调度配置生成并向用户展示→确认→经平台定时任务/自动化能力创建→回执记录
- **约束**: 循环计划与一次性定时的调度参数由能力自身字段承载，不写入任务提示；循环计划必配循环规则参数，一次性定时必配触发时间参数；创建前必须取得用户确认
- **格式**: 固化回执（Markdown，含调度参数表）

#### CWC3-05 L3 可复用技能沉淀

- **必选组件**: 沉淀形态判定（可复用技能/流程文档）、沉淀产物
- **可选组件**: 使用说明与触发词
- **组装顺序**: 确认组合已跑通（L1 或 L2 执行成功记录）→沉淀形态选择（通过平台技能管理能力沉淀为技能，或沉淀为流程文档）→产物生成→复用说明输出
- **约束**: 未跑通不得沉淀；沉淀为技能时遵守平台技能包规范；沉淀产物不含敏感数据
- **格式**: 沉淀产物（技能包或流程文档）

### CWC4 灵感生成域

#### CWC4 域级说明

**灵感六要素与生成方法**（覆盖 CWC4-01~03 的跨任务逻辑）：灵感模式为主动式能力，除需求驱动组合外须能自动生成 **3~5 个**跨连接器组合建议。每条建议必须包含**六要素**（缺一不可）：①场景名；②涉及连接器；③流程链（取数→处理→交付→产出）；④价值假设；⑤建议落地层次（L1/L2/L3，附一句理由）；⑥所需授权与前置提示。

**扫描来源**：用户历史需求 / 行业特征 / 连接器市场新品类 / 跨分类组合空白。

**生成方法**（借鉴模式直用与维度矩阵思路，内容领域化为连接器场景）：以"连接器分类 × 场景动作（取数/处理/交付/产出）"构建维度矩阵，强制连接生成候选组合，再经可行性初判筛选定型；组合至少覆盖 2 个不同分类的连接器。价值假设不得写成确定性承诺，不确定的收益预期标注"待验证"。

#### CWC4-01 场景扫描与机会识别

- **必选组件**: 扫描来源记录（用户历史需求/行业特征/市场新品类/组合空白）、机会清单
- **可选组件**: 用户画像要点
- **组装顺序**: 来源枚举→逐来源提取场景机会→去重合并→机会清单
- **约束**: 机会必须可映射到市场实际存在的连接器能力；无可用来源时基于已扫描市场给出通用机会并注明依据
- **格式**: 机会清单（Markdown）

#### CWC4-02 跨连接器创意组合生成

- **必选组件**: 3~5 个组合方案（每个含流程链草稿）、分类覆盖说明
- **可选组件**: 借鉴方法标注（维度矩阵强制连接/跨分类空白填补）
- **组装顺序**: 机会与连接器分类交叉（分类×场景动作维度矩阵）→强制连接生成候选→可行性初判→3~5 个定型
- **约束**: 数量 3~5 个；至少覆盖 2 个不同分类的连接器组合；与用户既有自动化重复的组合剔除（对照 CWC3-04 查重思路）
- **格式**: 创意组合集（Markdown）

#### CWC4-03 灵感清单输出与价值标注

- **必选组件**: 灵感清单（每条六要素齐备：场景名/涉及连接器/流程链/价值假设/建议落地层次/所需授权与前置提示）
- **可选组件**: 采纳引导（"回复序号即可进入编排"）
- **组装顺序**: 六要素逐条填充→价值假设标注（不确定标"待验证"）→落地层次建议（附一句理由）→清单排版输出
- **约束**: 六要素缺一不可；价值假设不得写成确定性承诺；授权前置提示引用 CWC2-03 核对结果
- **格式**: 灵感清单（Markdown）

### CWC5 守护校验域

#### CWC5 域级说明

**守护铁律**（覆盖 CWC5-01~03 的跨任务逻辑，全部任务共同遵守）：

1. **写入必确认**：写入类连接器操作（发送、创建、修改、删除、支付等）必须先经用户明确确认后执行，确认记录须可追溯（对话内明确同意）；
2. **只读优先**：能力等价时优先选择只读方案；
3. **授权缺失即引导**：授权缺失时引导用户安装/连接对应连接器，严禁虚构能力或绕过授权；
4. **输出统一模板**：组合方案输出统一使用 templates/workflow-plan-template.md。

**三道门定义**：CWC5-01 可行性校验（技术可行）→ CWC5-02 风险识别与确认守护（风险可控、授权齐备）→ CWC5-03 方案定稿检查（格式与记录完备）。三道门固定串联在 CWC3-02 与落地任务之间，任一道 FAIL 退回对应任务修复，不得带伤下传；三道门全 PASS 方可进入 CWC3-03/CWC3-04/CWC3-05。

#### CWC5-01 组合方案可行性校验

- **必选组件**: 校验结果表（连接器存在性/能力覆盖/数据接口衔接/层次可落地性）
- **可选组件**: 修复建议清单
- **组装顺序**: 连接器存在性核对（对照市场扫描结果）→能力覆盖核对（基元链每段有归属）→衔接核对（上游输出=下游输入）→层次落地核对→输出结果
- **约束**: 任一项不通过即 FAIL，方案退回 CWC3 修改，不得带伤下传
- **格式**: 校验结果表（Markdown 表格）

#### CWC5-02 风险识别与确认守护

- **必选组件**: 风险清单（写入/隐私/资金/不可逆）、写入类操作确认记录
- **可选组件**: 授权前置提示（转自 CWC2-03）
- **组装顺序**: 逐步骤扫描读写类型→风险分级→写入类操作逐项向用户确认并留存记录→授权缺失项引导
- **约束**: 写入类操作必须先经用户明确确认；只读优先原则在替代方案能力等价时适用；确认记录必须可追溯
- **格式**: 风险与确认报告（Markdown）

#### CWC5-03 方案定稿检查

- **必选组件**: 定稿检查单（模板字段完整/确认记录齐备/层次路由一致/依赖引用有效）
- **可选组件**: 定稿版本号
- **组装顺序**: 模板字段完整性检查（对照 templates/workflow-plan-template.md）→确认记录检查→与 CWC3-01 路由判定一致性检查→全部通过即定稿
- **约束**: 检查单全 PASS 才允许进入 CWC3-03/CWC3-04/CWC3-05 落地执行；任一 FAIL 退回对应任务修复后复检
- **格式**: 定稿检查单（Markdown 表格）

### CWC6 深化域

#### CWC6-01 组合方案迭代优化

- **必选组件**: 反馈来源记录、优化项清单、优化后方案（模板新版本）
- **可选组件**: 优化前后对比
- **组装顺序**: 反馈收集→优化项识别（链路/连接器替换/层次调整/调度参数）→最小修改执行→版本号更新（记入迭代记录）
- **约束**: 优化后方案重新过 CWC5 三道门；涉及调度参数变更须重新向用户展示并确认
- **格式**: 优化后方案（Markdown，模板新版本）

#### CWC6-02 连接器市场更新适配

- **必选组件**: 市场变更记录（重扫新旧对照）、受影响固化资产清单（L2 自动化与 L3 沉淀物）、适配动作
- **可选组件**: 失效预警清单
- **组装顺序**: 触发识别（市场更新/自动化失效）→重扫（走 CWC1-01 调用路径）→新旧对照→受影响资产定位→适配动作（替换连接器/改参数/下线建议）
- **约束**: L2 自动化变更须经用户确认后执行；L3 沉淀物更新须更新版本号；适配涉及写入类操作遵守守护铁律
- **格式**: 适配报告（Markdown）

#### CWC6-03 负载物深化

- **必选组件**: 深化来源（校验 FAIL 项/用户反馈/市场结构变化）、深化类型（任务细化/组件完善/范本补全）、深化执行方案
- **可选组件**: 优先级排序、影响范围评估
- **组装顺序**: 来源收集→类型识别→方案设计→执行（纳入任务体系，不绕过 catalog）→重新自检
- **约束**: 新增内容须转化为新增任务或融合进现有任务要求，不得直接追加文件而不纳入任务体系；深化后须重新通过接口校验（按生成技能标准全查）
- **格式**: 负载物深化报告（Markdown）

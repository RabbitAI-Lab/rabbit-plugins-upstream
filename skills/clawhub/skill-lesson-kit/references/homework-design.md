# 作业题型设计与答案规范

四层题型结构，按难度递进；标注必做/选做与建议用时。

## 题型模板

### A. 概念题（必做，约 10 分钟，3 题）

- 考察机制本质，不考死记硬背；每题给一句提示（如"想想意图匹配的对象是什么"）
- 典型题式：
  1. 边界场景判断题："用户说 X（口语化、不出现关键词原词），技能 Y 会被触发吗？为什么？"
  2. 原理追问题："为什么不全量加载？从 token 成本和执行准确性两个角度各答一条。"
  3. 判断改错题："description 越笼统越好"——判对错并说明正确写法。

### B. 找茬题（必做）

- 给出一段故意写坏的 SKILL.md（至少埋 4-6 处问题），要求找出 3 处即满分
- 标准埋坑方向（每方向一条采分点）：
  1. 命名规范：大写/空格 → 应为小写连字符且描述功能
  2. description 可触发性：笼统无区分度 → 应写"何时使用"
  3. 缺 keywords：丢失精确命中层 → 应含中文别名、口语、场景词
  4. 职责边界："万能助手" → 一个 skill 只解决一类任务
  5. 正文质量：空话步骤（"第一步思考"）→ 应写可执行步骤
  6. 渐进式披露违规：长文档塞正文 → 移到 references/
- 可附"参考找茬方向"提示；用户要求提高难度时删除提示

### C. 动手题（二选一，限时提交）

- **C1 入门**：写一个单一场景 SKILL.md（如周报生成器）。硬性要求：frontmatter 三件套齐全、keywords ≥8 且含口语别名、正文按"前置条件 → 工作流程 → 输出格式"三段、全文 ≤60 行
- **C2 进阶**：项目级 skill + 配套校验脚本（如作业命名检查器）。要求：放对项目级目录、脚本输出结构化结果（JSON）、正文写清何时调用与错误报告格式、含安全边界（只报告不擅改）

### D. 思考题（选做，200 字以内）

- 开放对比题（如 Skill vs MCP 的"指令 vs 能力"），要求观点明确、有决策规则，不写泛泛而谈

## 答案文件规范

结构：按题型逐题作答 → 每题含"评分采分点" → 末尾"延伸拓展"选读章节（2-5 个进阶专题）。

- 概念题：答到机制层面，配"一句话总结"
- 找茬题：全量问题清单表格（问题 / 改法两列）+ 采分点映射
- 动手题：给出完整可运行的参考实现（SKILL.md 全文 + 脚本代码），附评分要点
- 思考题：给出范文（≤200 字），核心结论加粗或前置

## 题目文件规范

- 与答案严格分离，题目文件不含答案线索
- 头部含提交要求（哪些必做、提交形式、截止时间）
- 结尾注明考核形式（如"下节课随机抽同学现场触发演示"）

## 延伸专题候选（选 2-5 个写入答案末尾）

1. 意图匹配的三个层次（精确命中 / 语义相似 / 主动检索）
2. Skill 的安全模型与安装前审计
3. 好 Skill 的三重边界（任务 / 数据 / 动作）
4. 给 Skill 做评估（触发率 / 误触发率 / 端到端成功率）
5. 推荐动手实验（装一个自写技能并用 5 种说法测触发，形成迭代闭环）

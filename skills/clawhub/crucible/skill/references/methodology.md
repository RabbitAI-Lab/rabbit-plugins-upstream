---

## 1. The Ladder — 极简决策梯 (from Ponytail)

**每次实现决策前，从第 1 级开始，停在第一个成立的级别：**

```
1. 这真的需要存在吗？        → 投机需求 = 跳过（YAGNI）
2. 代码库里已经有了吗？      → 复用已有 helper/util/type
3. 标准库能做吗？            → 用标准库
4. 平台原生特性覆盖了吗？    → <input type="date"> over picker lib, CSS over JS
5. 已安装的依赖能解决吗？    → 用已装依赖，绝不为此新增依赖
6. 能一行搞定吗？            → 一行
7. 只有到这一步：            → 最小可行代码
```

### Anti-Lazy 边界（绝不简化）

- 信任边界的输入验证
- 防止数据丢失的错误处理
- 安全措施、无障碍基础
- 用户明确要求的功能

## 2. 理性化防御表 (from Superpowers)

| 借口 | 应对 |
|------|------|
| "以后再加测试" | 现在就加，或删除预写的代码 |
| "先让它跑起来" | 先写失败测试，再让它跑 |
| "先 hardcode，后面抽象" | 只有一个实现就不需要抽象 |
| "加个 config 方便以后改" | 值从不变就不需要 config |
| "reviewer 说得对" | 技术评估 > 表演性认同，验证后再改 |

**红线**: 禁止 "You're absolutely right!" / "Great point!" — 先验证代码库再接受建议。

---

## 3. 验证完成纪律 (from Superpowers)

**Iron Law**: 没有新鲜验证证据就不能声称完成。

5 步门: 识别命令 → 运行 → 读完整输出 → 比对声明 → 陈述结论

| 声明类型 | 验证命令 |
|----------|---------|
| "测试通过" | 运行测试，读全部输出 |
| "构建成功" | 运行构建，零错误退出 |
| "bug 已修复" | 复现测试 + 回归测试都通过 |
| "Agent 完成了" | 读产出，验证文件存在且正确 |

---

## 4. Bug 修复 = 根因，不是症状

1. Grep 你即将修改的函数的每个调用者
2. 共享函数里的一个 guard < 每个调用者里的 guard
3. 修一次，修在所有调用者经过的地方

---

## 5. 输出纪律

代码先行，最多三行: `[代码] → 跳过了: [X]，需要时加: [Y]。`

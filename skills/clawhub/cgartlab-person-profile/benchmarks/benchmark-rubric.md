# Benchmark Rubric / 评分标准

本文件定义高质量人物档案的量化评分标准。融合 HELM（多维评估）+ FActScore（atomic fact 支持率）+ Cited but Not Verified（三维引用质量）。

## 4 维度评分

一个高质量档案要过 4 个维度。**每维度独立打分**，不做加权总分。

### 维度 1：事实精度（FActScore）

**衡量**：档案里的事实性 claim 有多少被可靠来源支持。

| 分数 | 标准 |
|---|---|
| 9-10 | ≥ 90% atomic facts 有可靠来源支持（① 或 ② 级） |
| 7-8 | 70-90% atomic facts 有支持，个别来源为 ③ 旁人回忆 |
| 5-6 | 50-70% 有支持，部分为 ④ 作者推断 |
| 3-4 | 30-50% 有支持，大量 ④ 或 ⑤ |
| 0-2 | < 30% 有支持，档案基本不可信 |

**衡量方法**：
```bash
# 未来实现: python scripts/check_fact_score.py path/to/archive.md
# 目前手动估算
```

**atomic fact 定义**（FActScore 吸收）：
- 一条时间线只写一件事
- 一条判断只涉及一个可验证的核心主张
- 一条事实不含"和""然后""以及"这类并列连接词

### 维度 2：引用质量

**衡量**：每条引用是否真的支持对应的 claim。

| 分数 | 标准 |
|---|---|
| 9-10 | 所有引用通过 Link Works / Relevant Content / Fact Check 三维 |
| 7-8 | ≥ 90% 通过，个别 F2（相关度低）但可接受 |
| 5-6 | 50-90% 通过，有明显 F6（引用存在但不支持） |
| 3-4 | 30-50% 通过，多个 F1（链接失效）或 F6 |
| 0-2 | < 30% 通过，引用质量极差 |

**三维定义**（Cited but Not Verified 吸收）：
- **Link Works**：URL 是否可打开
- **Relevant Content**：页面内容是否相关
- **Fact Check**：引用是否真正支持该 claim

**危险信号 F6**：引用存在但不支持该 claim。比"链接失效"更危险，因为读者点进去看到 URL 存在就信了。

### 维度 3：反证覆盖

**衡量**：档案是否主动覆盖反面证据、争议、失败。

| 分数 | 标准 |
|---|---|
| 9-10 | 有明确"争议与风险点"章节 + 每条核心价值观有反例审查 + 主动搜索了 criticism |
| 7-8 | 有争议章节 + 至少 1 条判断做反例审查 |
| 5-6 | 有争议章节但反例审查不足 |
| 3-4 | 有争议章节但只写正面 |
| 0-2 | 无争议章节或完全没有反面内容 |

**关键**：主动搜索 criticism / 反方是关键。只做"表面搜索"的档案得低分。

### 维度 4：边界承认完整度

**衡量**：档案是否明确写了"我不知道什么"。

| 分数 | 标准 |
|---|---|
| 9-10 | 有完整"待核实清单"（含为什么查不到）+ "本次未能取得的来源"（含具体原因）+ "本档的引用标准" |
| 7-8 | 有待核实清单，但原因描述不够细 |
| 5-6 | 有待核实清单但没写原因 |
| 3-4 | 只写"待核实"不写具体内容 |
| 0-2 | 无边界承认，档案假装什么都知道 |

## 综合判定

| 总分 | 判定 |
|---|---|
| 4 维全部 ≥ 8 | **A+（标杆）**——可作未来档案的样板 |
| 4 维平均 ≥ 7 | **A（高质量）**——本 skill 的下限 |
| 4 维平均 5-6 | **B（合格）**——可用，但需改进 |
| 4 维平均 3-4 | **C（不合格）**——需要返工 |
| 4 维平均 < 3 | **D（不可用）**——需要重写 |

## 硬性下限（不达标直接不合格）

无论评分如何，以下任一条违反就判定不合格：

1. 缺少 11 节结构中的任何一节
2. 章节顺序与模板不一致
3. 标题级别不是 `##`
4. 有 `author: ChatGPT` 残留
5. 有非模板章节
6. 有禁用破折号（`——` / `—` / `–`）
7. 有商业黑话（闭环 / 赋能 / 抓手 / 底层逻辑 / 复利 / 范式 等）
8. 有模型路标词（值得注意的是 / 本质上 / 由此可见 / 总之）
9. 时间线 < 20 条
10. 核心价值观 < 3 条且无一条做反例审查
11. 可操作建议 < 5 条
12. 主要参考来源 < 10 条
13. 有构造 URL（未实际访问过的链接）
14. 在世人物（living_person: true）无可靠来源的争议性内容
15. 长度 < 300 行

**跑脚本一键检查**：
```bash
python scripts/validate_archive.py path/to/archive.md
python scripts/check_prohibitions.py path/to/archive.md
```

## 评分示例：Dan Koe.md

| 维度 | 分数 | 依据 |
|---|---|---|
| 事实精度 | 9 | 每条时间线都有可点开 URL，多为 ① 可靠事实 |
| 引用质量 | 9 | 所有引用都是本档案作者实际访问过的页面 |
| 反证覆盖 | 9 | 有完整争议章节，Kortex 到 Eden 重构争议写得详细，反例审查到位 |
| 边界承认 | 9 | 可信度章节完整，待核实清单具体到"本次检索范围" |
| **综合** | **A+** | 4 维全部 ≥ 8 |

## 评分示例：阮一峰.md

| 维度 | 分数 | 依据 |
|---|---|---|
| 事实精度 | 8 | 大部分时间线有 URL，少数为 ③ 旁人回忆（如上海财经大学博士） |
| 引用质量 | 9 | 所有引用都可打开，多数为本人博客（② 机构自述） |
| 反证覆盖 | 9 | 有争议章节（DDoS、小额支付试验），反例审查到位 |
| 边界承认 | 10 | 未知章节详尽：精确出生年、当前雇主、DDoS 攻击者等全部列出 |
| **综合** | **A+** | 4 维平均 9 |

## Pitfalls

1. **只看总分不看维度** → 单维度过低（如反证覆盖 = 2）说明档案是宣传稿
2. **评分靠印象** → 用 FActScore atomic fact 计数，不靠直觉
3. **忽视 F6 危险** → 链接打开不等于支持 claim
4. **硬性下限当评分标准** → 硬性下限是必要条件，不是评分标准
5. **在世人物放宽标准** → Wikipedia BLP 严审模式必须遵守

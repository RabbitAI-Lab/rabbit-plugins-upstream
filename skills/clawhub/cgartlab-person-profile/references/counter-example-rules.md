# Counter-Example Rules / 反例审查与边界承认

本文件详解核心价值观章节的反例审查规则。

## 为什么必须有反例审查？

**没有反例的判断是描述不是立场**。

- 描述："他相信长期主义"
- 立场："长期主义的价值在于让方法论成为可复用的产品，而非短期的流量"

描述无法被反驳。立场可以。只有立场能构成方法论。

## 反例审查规则

### 规则 1：反例只能取自档案已有材料

**关键点**：**不许联网现找**。

**为什么**：
- 从网上现找反例，AI 会为了凑反例制造伪冲突
- 反例必须和档案里的时间线、言论、作品有明确证据链
- 读者必须能回查

**范例**（阮一峰档案）：

判断：「阮一峰反对把知识做成墙后商品」。

反例（取自档案已有材料）：
- 2011-2012 年小额支付试验：《阮一峰的网络日志》上推出付费小额支付，88 篇 / 1079 笔 / 5800 元 / 3.3% 推广成本
- 2018 年 DDoS 攻击事件：本人曾公开讨论付费墙如何保护自己（虽然是防御性使用，不构成"付费墙化知识"）
- 处理：不是硬反驳判断，而是**标明边界**——"阮一峰的立场是知识本身免费，商业化的载体（服务、赞助、实体书）可以有偿。小额支付试验失败后他把这个边界写进了后续的所有实践"。

### 规则 2：找不到真反例时怎么办？

**不要硬造反例**。

**处理**：写清适用边界。

**范例**：

判断：「Dan Koe 的核心方法论是可迁移的 one-person business 模型」。

找不到硬反例（因为 Koe 一直在实践这个），处理：

> **边界**：这个判断适用于自主节奏项目。Dan Koe 在甲方委托项目上的实践不在档案范围内，因此不作断言。

### 规则 3：反例的三种处理方式

反例审查后，段末必须用一行斜体写明处理方式：

#### 处理方式 1：吸收

反例被吸收进判断的边界里，让判断更精确。

**格式**：*（吸收：将 XXX 的情况作为边界条件加入）*

**范例**：
> 长期主义的价值在于让方法论成为可复用的产品，而非短期的流量。
> 
> **反例（吸收）**：阮一峰 2011-2012 年做过小额支付试验，说明他不是绝对反对付费，只是反对"知识本身付费"。*（吸收：将"知识免费、载体付费"作为边界）*

#### 处理方式 2：驳倒

反例直接驳倒判断，判断作废，写清为什么。

**格式**：*（驳倒：本判断在本档案范围内不成立）*

**范例**：
> 原判断：XXX 是绝对主义者。
> 
> **反例（驳倒）**：XXX 在 2015 年 X 事件里明确承认妥协空间。*（驳倒：本判断在本档案范围内不成立，改为"XXX 是相对主义者"）*

#### 处理方式 3：确认破例并标明

反例成立但属于例外情况，判断主体不变，但明标例外。

**格式**：*（确认破例：X 是例外，判断主体不变）*

**范例**：
> 原判断：XXX 只做 A 类项目。
> 
> **反例（确认破例）**：XXX 在 2019 年做过一次 B 类项目。*（确认破例：2019 年 B 类项目是例外，判断主体不变）*

### 规则 4：反例的密度

- **至少 1 条核心价值观必须做反例审查**（可以是"确认破例"或"边界"）
- 其他价值观可以选择做反例审查，但不是强制
- **禁止**：所有价值观都不做反例审查——这会让核心价值观章节变成信仰清单

## 边界承认

除了反例审查，核心价值观章节还必须包含**边界承认**。

**什么是边界承认**：明标判断的适用范围。

**范例**：
> 阮一峰的"知识免费"立场适用于**知识本身**（教程、文章、代码），**不适用于**商业化载体（赞助、实体书、付费服务）。

**为什么必须有**：不做边界承认的判断容易被误用。"知识免费"如果没边界，读者可能理解成"任何东西都免费"。

## 完整范例（核心价值观章节）

```markdown
## 核心价值观

**（一句具体、可被反驳的判断 1）**：

阮一峰的核心主张是：知识本身必须免费，商业化载体可以有偿。这条主张来自他 2011-2012 年小额支付试验的失败（88 篇 / 1079 笔 / 5800 元 / 3.3% 推广成本）——付费墙的成本压过收入，他从那次试验后转向"免费内容 + 赞助 / 实体书"的路径。

- **反例（吸收）**：2011-2012 小额支付试验说明他不是绝对反对付费，只是反对"知识本身付费"。*（吸收：将"知识免费、载体付费"作为边界）*

**（一句具体、可被反驳的判断 2）**：

阮一峰的"开源"立场具体指的是：教程代码、示例项目、周刊内容全部公开可 fork，不做订阅制。他明确在 2018 DDoS 事件里承认"开源是我的立场"（https://www.ruanyifeng.com/blog/2018/06/ddos.html，可信度：② 机构自述）。

- **反例（边界承认）**：这个立场适用于**开源内容**，不适用于他本人的商业服务（如赞助、书籍销售）。

**（一句具体、可被反驳的判断 3）**：

阮一峰反对"知识付费"的定性是**方法论问题**（付费导致知识被切碎），不是**立场问题**（他不是绝对理想主义者）。他承认"知识付费"在某些场景（如专业服务、咨询）是可接受的（参考 2016 博文《要聊天，先付费》里对李笑来付费社群的评论，可信度：② 机构自述）。

- **反例（确认破例）**：2016 年对李笑来付费社群的评论显示他在某些场景下认可付费模式。*（确认破例：方法论问题不等于立场问题）*
```

## Pitfalls

1. **反例从网上现找** → 违反档案纪律，制造伪冲突
2. **找不到反例就硬造** → 应该写清边界或标"待核实"
3. **反例处理不写明** → 段末必须用斜体标处理方式
4. **核心价值观全是信仰** → 至少 1 条做反例审查
5. **边界承认留白** → 判断没有边界就是描述不是立场
6. **反例超出档案范围** → 反例必须取自档案已有材料

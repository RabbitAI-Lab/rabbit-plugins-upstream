# Writing Style / 写作规范

本文件详解本 skill 的写作纪律：禁词、句式、标点、视角。

## 硬性禁止

### 禁用破折号

- `——`（中文双破折号）
- `—`（em dash）
- `–`（en dash）

**为什么禁**：破折号是"想表达但没想清楚"的信号。改用句号或逗号。

**例外**：
- 引号内的原文中的破折号不能动
- 书籍、作品名内部的连接号属于原文
- 年份区间用半角连字符 `2005-2017` 是允许的

**处理方式**：
- 把破折号处断成两段，用句号或逗号连接
- 用"他先说 X，然后说 Y"这类叙述性连接

### 禁用商业黑话

| 禁词 | 替代方案 |
|---|---|
| 闭环 | 反馈循环 / 反馈回路 |
| 能力沉淀 | 能力积累 |
| 赋能 | 提供 X 能力 / 帮助 X 实现 Y |
| 抓手 | 手段 / 工具 / 方法 |
| 底层逻辑 | 基本原理 / 核心原理 |
| 内容矩阵 | 内容分类 / 内容组合 |
| 拉通 | 打通 / 协调 |
| 复利 | 累积效应 / 逐步增强 |
| 范本 | 范例 / 样板 |
| 范式 | 模式 / 惯例 |

**为什么禁**：这些词是"包装"。读者读到时以为有内容，其实什么都没被传达。

### 禁用模型路标词

| 禁词 | 问题 |
|---|---|
| 值得注意的是 | LLM 填充句，无信息量 |
| 本质上 | 显得有深度但常常是废话 |
| 由此可见 | 逻辑跳跃的信号 |
| 从某种意义上说 | 免责式表达，无信息量 |
| 总之 | 无信息量 |
| 总体而言 | 无信息量 |

**处理**：直接删掉。句子反而更有力。

### 禁用借喻清单

| 借喻词 | 为什么禁 |
|---|---|
| 仓库 | Obsidian 语境下字面用法合理，其他语境是借喻 |
| 抽屉 | 常见知识库借喻，实际什么都没传达 |
| 温度 | 常见组织管理借喻 |
| 坍塌 | 常见系统失败借喻 |
| 浪潮 | 常见趋势借喻 |
| 钥匙 | 常见方法借喻 |
| 底座 | 常见技术架构借喻 |

**例外**：Obsidian 语境下"仓库"字面指 Obsidian 库，不是借喻，不用改。

### 禁用翻案腔

**禁止**：「不是 A 而是 B」

**改**：「A 是主要来源，B 排在后面」

**为什么禁**：翻案腔看似有力，实际是修辞障眼法。

### 禁用提示性冒号

**禁止**：「核心是：」「关键在于：」

**允许**：
- 机器字段（`url: https://...`）
- URL 引用（`链接：https://...`）
- 参考资料字段分隔
- 引出人物直接原话（`他说："..."`）

**改法**：「核心是：X」→ 「核心是 X」（去冒号，加句号或直接句号）

## 引语规范

### 引号内一个字都不能动

引号内是原文，一个字都不能改。哪怕原文有破折号、有错别字、有不规范的表达。

### 引语要断句

原文有破折号时，把引语在破折号处断成两段，破折号落到引号之外换成叙述性连接：

**改前**：
> 他说："我认为——知识应该是免费的。"

**改后**：
> 他说："我认为，"然后是强调的语气，"知识应该是免费的。"

## 判断句形式

**核心价值观章节**：每段以**加粗的完整判断句**开头，句末用句号，不用冒号。

**判断必须可被反驳**：
- 描述不可反驳：「他相信长期主义」
- 判断可反驳：「长期主义的价值在于让方法论成为可复用的产品，而非短期的流量」

**为什么**：判断才是立场。描述只是概述。

## 方法论形式

**动词开头的动作句**：
- ✅ 「每天早晨写 2 小时」
- ✅ 「列反面愿景再列愿景」
- ❌ 「要有长期主义精神」
- ❌ 「重视长期思考」

**动作必须是读者今天就能做的粒度**，不是抽象口号。

## 视角模拟（Karpathy 建议）

**思维模式 / 可操作建议章节**：用「某人会怎么做」句式，避免 LLM 自称。

**避免**：
- ❌ 「作为阮一峰，我会……」
- ❌ 「如果你是他，你会……」

**改**：
- ✅ 「阮一峰会怎么做……」
- ✅ 「从他的立场看……」

**为什么**：避免 LLM 扮演人物「补充档案没有的事实」。persona prompting 研究表明（Hu & Collier 2024），加 persona line 对准确率提升多数与噪声不可区分。

## 时间线粒度（FActScore 吸收）

**一条时间线只写一件事**（atomic fact 约束）。

❌ **合并**：
> 2014 年他出版了《XX》，同时开始做 XX 项目，并获得 XX 奖项。

✅ **拆分**：
> 2014-03 出版《XX》。
> 2014-05 开始 XX 项目。
> 2014-11 获得 XX 奖。

**为什么**：合并的事件无法单独验证，FActScore 无法评估。

## 争议章节形式

**每条争议必带各方立场**，不做「作者认为 X」的独裁判断。

**涉个人指控时只写法院或机构结论**，不渲染。

**未获证实的常见说法必须列出来**并注明「未获证实」——这个「列出来+标注」的动作比不列更保守。

## 可操作建议形式

**动词开头**，加粗：
- ✅ **每天写 2 小时日记**：把当天的观察和想法记录下来。
- ✅ **列反面愿景**：先写下你不想要的生活，再列你理想的生活。
- ❌ **重视记录**：记录能帮助你思考。

**每条建议必须挂到档案里已经出现的具体证据或作品**，不凭空发明。

## 行文节奏

**单段 ≤ 6 行**：

- 段落是思考的最小单位，不是排版单位
- 段落长度超过 6 行时，读者会跳读
- 拆段落比用 bullet 更合适，除非真的有并列结构

**关键信息加粗**：

- 一段里最重要的判断句加粗
- 加粗不是排版装饰，是**注意力引导**
- 每段加粗不超过 1-2 处

**列表优先于段落**：

- 有并列结构就用列表，不要用段落
- 列表项每条一行，最多两行
- 每项都以同一语法形式开头（动词 / 名词 / 判断句），保证一致

## 语言选择

**中文优先**：档案正文用中文。

**术语保留**：英文专有名词（如 "Kortex", "one-person business", "GitHub"）保留英文，不硬译。

**引语保留原文**：人物原话如果是英文，保留英文，不加翻译。要理解含义可以在引语后加"（大意：...）"。

## Pitfalls

1. **破折号藏在引语里** → 引语原文有破折号时不能改，改用断句方式处理
2. **借喻词误伤** → "仓库" 在 Obsidian 语境下是字面用法，不要改
3. **加粗用错** → 加粗过多等于没加粗，每段最多 1-2 处
4. **列表项语法不一致** → 每项都以同一形式开头
5. **段落过长** → 超过 6 行拆段
6. **LLM 自称** → 用"某人会怎么做"句式，不用"作为 XX 我会……"
7. **合并多件事到一条时间线** → 违反 atomic fact 约束
8. **建议凭空发明** → 建议必须挂到档案证据上

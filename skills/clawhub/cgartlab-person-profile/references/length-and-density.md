# Length & Density / 长度密度参考

本文件定义人物档案的长度、密度、颗粒度下限与讨论点。**这些是从 27 份高质量档案实践中提炼的经验值，不是硬性上限**。

## 长度下限

| 项目 | 下限 | 依据 |
|---|---|---|
| 总行数（不含 frontmatter） | **≥ 300 行** | Dan Koe 275 行、阮一峰 293 行是标杆下限 |
| 时间线条目 | **≥ 20 条** | 少于 20 条无法展示人物的完整生命周期 |
| 核心价值观 | **≥ 3 条**，至少 1 条做反例审查 | 少于 3 条主张，判断维度不够 |
| 可操作建议 | **≥ 5 条**，动词开头 | 少于 5 条无法构成可执行方案 |
| 主要参考来源 | **≥ 10 条**，附实际访问到的 URL | 少于 10 条说明搜索不充分 |
| 关系网络条目 | **≥ 3 条** | 少于 3 条说明档案是孤岛 |
| 反例审查覆盖 | **≥ 1 条** | 0 条反例审查，档案是信仰清单 |

## 长度上限讨论点

**350 行以上**要考虑是否可合并同类信息。**不是硬性上限**，是提醒。

**什么时候超 350 行是合理的**：
- 人物活跃期长（如迈克尔·杰克逊 30 年职业生涯）
- 领域跨越广（如乔布斯从消费电子到动画到健康）
- 有明确争议需要展开（如李笑来的币圈争议）
- 有多条独立时间线（如创作者 + 投资人双身份）

**什么时候超 350 行是问题**：
- 内容重复（同一事实在多个章节讲）
- 描述过于冗长（一句话能说清的用了三句）
- 时间线条目过密（一条事件包含 3 件事）

## 每节的长度参考

| 章节 | 典型长度 | 下限 | 上限讨论点 |
|---|---|---|---|
| 执行摘要 | 3-5 段 | 3 段 | 8 段以上说明写散了 |
| 关系网络 | 3-10 条 | 3 条 | 15 条以上考虑合并同类 |
| 时间线与主要作品/言论 | 20-50 行表格 | 20 条 | 60 条以上考虑合并近邻事件 |
| 核心价值观 | 3-5 段，每段 5-10 行 | 3 段 | 6 段以上考虑合并同类判断 |
| 思维模式 | 3-5 段 | 3 段 | 8 段以上考虑合并 |
| 方法论 | 5-15 条动作 | 5 条 | 20 条以上考虑分类 |
| 创作如何变成影响 | 1 个 mermaid 图 + 3-5 段解读 | 1 图 | 2 个以上图说明影响力路径复杂 |
| 争议与风险点 | 3-6 段 | 3 段 | 8 段以上考虑合并同类争议 |
| 可信度与信息差异 | 5 级分级 + 待核实清单 | 完整 5 级 | 缺任一级都不合格 |
| 可操作建议 | 5-8 条 | 5 条 | 10 条以上考虑合并 |
| 主要参考来源 | 10-30 条 | 10 条 | 40 条以上说明搜索过深 |

## 密度要求

**每条事实**：40-80 字，一行或两行。

**反面例子（低密度）**：
> 阮一峰的开源教材战略在他 2014 年推出《ECMAScript 6 入门》GitBook 后逐步成型。这个教材是免费在线的，读者可以随意阅读和 fork，但阮一峰在 2017 年把它整理成《ES6 标准入门》实体书出版，通过卖书获得收入。这体现了他的"知识免费、载体付费"战略，也和他在 2011-2012 小额支付试验失败后的立场保持一致。

**改进（高密度，atomic fact）**：
> 2014-04-30 阮一峰开源《ECMAScript 6 入门》GitBook，免费在线阅读。
> 2017-09-19 出版《ES6 标准入门》实体书（电子工业出版社）。
> 战略：知识免费，载体付费（源于 2011-2012 小额支付试验失败）。

**关键**：时间线一条只写一件事，把战略解读放到"核心价值观"章节。

## 颗粒度

**时间线**：一条事件一行，一格不超过 2 行。

**核心价值观**：一条判断一段，5-10 行。判断句加粗。反例审查在段末用斜体标注处理方式。

**方法论**：一条动作一行。动词开头。

**争议与风险点**：一条争议一段，含各方立场。

**可信度**：5 级分级每条一行。**待核实清单**每条一行含原因。

## 字数分布参考

一份高质量档案（300-350 行）的典型字数分布：

| 章节 | 典型字数 | 占比 |
|---|---|---|
| 执行摘要 | 400-800 字 | 15% |
| 关系网络 | 300-600 字 | 10% |
| 时间线 | 500-1500 字 | 20-25% |
| 核心价值观 | 500-1000 字 | 15-20% |
| 思维模式 | 300-600 字 | 10% |
| 方法论 | 300-600 字 | 10% |
| 创作如何变成影响 | 300-600 字 | 10% |
| 争议与风险点 | 300-600 字 | 10% |
| 可信度与信息差异 | 300-600 字 | 10% |
| 可操作建议 | 200-400 字 | 5% |
| 主要参考来源 | 200-400 字 | 5% |

**注意**：占比不是硬性指标，仅供参考。有些档案（如争议大的人物）争议章节会占 20% 以上。

## 反面例子

### 反面 1：过短

```
## 执行摘要

阮一峰是独立技术博主，创办《阮一峰的网络日志》，是著名开源项目《ECMAScript 6 入门》的作者。

## 关系网络

- 与乔布斯：无交集

## 时间线

| 时间 | 事件 |
| --- | --- |
| 2003-12 | 创建博客 |
| 2014 | 出版 ES6 |
```

**问题**：
- 执行摘要只有 1 段，没有核心主张和读者关系
- 关系网络只有 1 条，还是否定结论
- 时间线只有 2 条，远未到 20 条下限
- 缺少 8 节章节

### 反面 2：过长

**症状**：某份档案 500 行，但：
- 同一事实在时间线和"创作如何变成影响"章节重复讲
- 价值观章节里每条判断讲 20 行以上
- 方法论里 20 条以上动作，多数是相似动作的细微变化

**处理**：合并同类信息，把解读性内容合并进判断句里。

## 快速自检

写完档案后跑一次：

```bash
# 行数
wc -l path/to/archive.md

# 时间线条目数
grep -c "^|" path/to/archive.md  # 减去表头

# 核心价值观段数（含"反例"）
grep -c "反例" path/to/archive.md

# 参考来源条目数
grep -c "^- " path/to/archive.md  # 主要参考来源章节内的
```

## Pitfalls

1. **追求长度** → 300 行是下限不是目标，短而密 > 长而散
2. **追求密度到失去可读性** → 每条 40-80 字是参考，不是硬性
3. **合并同类信息过度** → 保持 atomic fact，一条一件事
4. **参考来源凑数** → 10 条是下限，但每条必须真正有用
5. **时间线过密** → 超过 60 条考虑合并近邻事件
6. **章节占比失衡** → 检查是否有章节明显过长或过短

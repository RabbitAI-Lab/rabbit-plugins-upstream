# DESIGN.md — 设计哲学与决策记录

本文件记录**为什么这么做**，不是**做什么**。SKILL.md 讲流程，本文件讲决策。

---

## 核心决策 1：为什么是 11 节结构？

11 节不是拍脑袋定的。它是最小完备集：

| 节 | 回答的问题 | 缺失后果 |
|---|---|---|
| 执行摘要 | 这个人是谁、值得学什么 | 读者不知道档案主旨 |
| 关系网络 | 他与谁有关、哪些关系是事实 | 档案孤岛，无法形成思想网络 |
| 时间线 | 他在什么时候做了什么 | 无法判断其立场的时间演变 |
| 核心价值观 | 他相信什么 | 没有时间线只知做了什么不知为什么 |
| 思维模式 | 他怎么想问题 | 无法理解其决策背后的推理 |
| 方法论 | 具体可迁移的做法 | 无此节，档案变传记变宣传稿 |
| 创作如何变成影响 | 影响力发生的路径 | 无法学"怎么做成的" |
| 争议与风险点 | 有争议的立场、批评 | 无此节档案变粉丝向内容 |
| 可信度与信息差异 | 来源可信度、待核实项 | 无此节读者不知道哪些是硬事实 |
| 可操作建议 | 今天能做什么 | 无此节档案无落地价值 |
| 主要参考来源 | URL 汇总 | 无法核验，档案无法自我证伪 |

**顺序设计的核心逻辑**：
- **执行摘要 → 关系网络 → 时间线**：先给全景，再给关联，再给时序
- **价值观 → 思维模式 → 方法论**：从"相信什么"到"怎么想"到"怎么做"，是从内到外的抽象递减
- **创作如何变成影响 → 争议 → 可信度**：把主张展开，然后承认边界，最后交代来源
- **可操作建议 → 主要参考来源**：最后落地到读者行动，附证据入口

## 核心决策 2：为什么关系网络放在时间线之前？

因为关系网络是**结构性事实**（谁和谁有关系），时间线是**过程性事实**（按时间排列）。

读者先看到关系网络，就知道档案里哪些人值得关注、这些关联是"真事件"还是"概念对照"。这样读时间线时，遇到相关人物能有上下文。

**反直觉的地方**：很多人会把时间线放前面（"按时间讲故事嘛"）。但档案不是故事，是**决策依据**。决策依据需要先看结构再看过程。

## 核心决策 3：为什么反例必须取自档案已有材料？

这条规矩看起来限制严，实际是**质量守门员**。

- **允许从网上现找反例**：AI 会为了凑反例制造伪冲突，把不相干的事件硬凑成"反例"
- **必须取自档案已有材料**：反例必须和档案里的时间线、言论、作品有明确证据链，读者可以回查

**代价**：有时候找不到真反例，只能写"本次未能找到反例，标为待核实"。这比造个假反例要好得多。

## 核心决策 4：为什么 5 级证据分级？

不是 3 级（可靠 / 中等 / 不可靠）够用的原因：

**3 级问题**：机构自述（如本人博客）在"中等"档，但机构自述 ≠ 事实。它可能只是立场表达。

**5 级解法**：
- ① 可靠事实：官方数据库、机构公告、法院判决、可复核的数据
- ② 机构自述：本人博客、官网、GitHub、公开演讲（**立场证据，不作事实用**）
- ③ 旁人回忆：第三方采访、他人博客、媒体报道（**可能有立场偏差**）
- ④ 作者推断：基于证据的合理推断（**必须明标推断**）
- ⑤ 未知：本次未取得

关键：**"机构自述"独立成级**，避免把它混进"可靠事实"。这是与一般事实核查方法的最大区别。

## 核心决策 5：为什么抓不到就写「未取得」而不是「不存在」？

**"抓取失败 ≠ 不存在"**：Wikipedia CRAWL_NOT_FOUND 不代表没有条目，只代表本次网络请求失败。

**"0 star ≠ 没影响力"**：新仓库 0 star 可能是因为刚创建 3 天。写"0 star"时要写清创建时间。

这条规矩看起来是格式细节，实际是**证据纪律的核心**：区分"我拿到了什么"和"世界上存在什么"。

## 核心决策 6：为什么禁止 AI 生成的"名言"？

低订阅、高 SEO 关键词攻击的 YouTube 视频（如 "Is X A Cult?", "Is X A Scammer?"）经常出现这样的模式：
- 67 views
- 2000 订阅
- 视频里"引用"了这个人的"名言"
- 但从未在任何一手来源出现过

**处理**：这类内容**仅作为"争议存在性"的记录**（"有人这样说了"），**不采纳其结论**（"这个人这样说过"）。

## 核心决策 7：为什么章节标题必须 `##` 而不是 `#`？

**Obsidian 里 `#` 是文档标题，`##` 是章节标题**。混用会导致：
- 目录混乱
- 大纲功能失效
- 章节级别语义不清

这不是 CSS 美化问题，是**语义结构**问题。

## 核心决策 8：为什么禁止特定词汇？

**禁商业黑话**（闭环、赋能、抓手、底层逻辑、复利、范式等）：
- 这些词是"包装"，读者读到时以为有内容，其实什么都没被传达
- 换成具体描述："闭环" → "反馈循环"、"赋能" → "提供 X 能力"

**禁模型路标词**（值得注意的是、本质上、由此可见、总之）：
- 这些词是 LLM 的填充句，让文章看起来有节奏但没增加信息量
- 直接删掉，句子反而更有力

**禁借喻清单**（仓库、抽屉、温度、坍塌、浪潮、钥匙、底座）：
- 借喻看似生动，实际是把抽象概念藏在比喻后面
- 例外：知识管理语境下"仓库"字面指 Obsidian 库，不是借喻

**禁破折号**（`——`、`—`、`–`）：
- 破折号是"想表达但没想清楚"的信号
- 改用句号或逗号，让逻辑变清楚

**例外**：引号内的原话，一个字都不能动。要消除引语里的破折号，就断句到引号之外。

## 核心决策 9：为什么必须有"待核实清单"？

档案的最后一章不是"参考来源"，而是"待核实清单"。**为什么？

- 参考来源证明"我做了什么"
- 待核实清单承认"我不知道什么"

这两者共同构成**档案的诚实度**。没有待核实清单，档案就会变成"我知道的我都说了"的自信错觉。

**每条待核实项必须写清为什么查不到**：
- 域名不可达
- 需登录
- 本次抓取失败
- 需付费
- 无独立第三方验证页

不能只写"未核到"或"待核实"。

## 核心决策 10：为什么双向链必须是硬性要求？

**单向链会漂移**。A 档案链到 B，B 档案不链回 A，一段时间后：
- 有人读到 A 里"B 影响了 A"，去查 B 档案，发现 B 档案里没有 A
- 有人读到 B 里"A 是同期人物"，去查 A 档案，发现 A 档案里根本没 B
- 时间一长，档案之间的关联变得不可追溯

**双向链的代价**：每次新增档案，都要扫描全库补链。但收益是**档案库成为一个真正互联的知识网络**，而不是一堆孤立的传记。

## 核心决策 11：为什么默认适配 Obsidian 知识库？

早期版本把 skill 设计成「脱离任何知识库」。接入 cgartlab-obsidian 之后发现这个定位有代价：

- **frontmatter 会漂移**：知识库有 `check-frontmatter.mjs`，要求 `type` 在枚举内、`tags` 带 `资源/` 前缀、`created/updated` 是合法日期。skill 若不认这套规范，产出的档案进库就报错。
- **读写方式会漂移**：知识库里的档案靠 Obsidian wikilink 互联，索引是 `人物-README.md`。skill 若不说明这一点，agent 会写出无法解析的链接。
- **校验会重复**：知识库校验器管元数据，skill 校验器管 11 节结构。两者若各写一套 frontmatter 检查，会互相打架。

**解法**：skill 默认按 Obsidian/PARA 落盘，但把 frontmatter 规范抽成一张可替换的表（见 SKILL.md「知识库集成」）。非 Obsidian 环境改 `type` / `tags` 即可，11 节结构与写作纪律不变。

这不是把 skill 绑死在一个知识库上，而是明确「默认实现」和「可替换层」的边界。

## 未来演进方向

- **v1.1**：加入「档案元数据规范」（字数统计、更新频率、外部链接健康度）
- **v1.2**：加入「反方视角档案」（专门写批评者视角，与主档成对）
- **v2.0**：加入多模态支持（语音记录、视频采访、手写笔记的档案化）
- **v3.0**：加入档案的"生命周期"管理（新增、更新、归档、废弃）

## 明确不做的

- **不追求"AI 一键生成档案"**：任何自动生成的档案都会违反本 skill 的证据纪律。必须人工核验。
- **不追求"档案越长越好"**：长度是副产品，不是目标。Dan Koe 275 行够，阮一峰 293 行够，短到 100 行只要每条都有 URL 也够。
- **不追求"覆盖所有人"**：只为人物档案，不扩到"公司档案"、"产品档案"、"技术档案"。那些是另外的 skill。

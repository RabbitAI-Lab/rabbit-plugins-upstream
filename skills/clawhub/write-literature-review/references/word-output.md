# Word 文档输出

## 默认交付

完整综述默认交付 `.docx` 文件。聊天正文只需简要说明完成情况、文献数量、审计结果和下载入口，不要把完整文章再次粘贴到聊天中，除非用户明确要求。

## 文档内容顺序

根据用户和目标期刊要求选择以下内容：

1. 中文题目或英文题目
2. 作者信息占位符（用户未提供时不要编造）
3. 摘要
4. 关键词
5. 正文各级标题
6. 必要的证据表、方法比较表或研究分类表
7. 结论
8. 声明部分（仅在用户提供相关信息时加入）
9. 参考文献
10. 可选附录：文献证据矩阵与期刊风格画像

## 格式原则

- 用户提供期刊模板时，优先使用模板。
- 未提供模板时，使用清晰、可编辑的通用学术格式。
- 中文正文默认使用宋体，英文和数字默认使用 Times New Roman。
- 标题层级清晰，正文段落保持一致。
- 表格必须可编辑，不得把数据表转成图片。
- 参考文献不得仅以图片或截图形式呈现。
- 不得在文档属性、页眉或正文中加入虚构作者和机构。
- 不得为了版式美观删减引用、证据限定语或审计说明。

## 生成方法

先把审计通过的正文写入 UTF-8 Markdown 文件。支持的基本结构：

```markdown
# 文章题目

## 摘要

摘要正文。

**关键词：** 关键词1；关键词2；关键词3

## 1 引言

正文。

### 1.1 子标题

正文。

| 文献 | 方法 | 主要发现 |
|---|---|---|
| R01 | 方法A | 发现A |

## 参考文献

[1] 参考文献条目。
```

随后在 Skill 根目录运行：

```bash
python3 scripts/build_review_docx.py review.md review.docx --title "文章题目"
```

脚本只使用 Python 标准库，不需要额外安装包。

## 验证

至少执行：

```bash
test -s review.docx
python3 -m zipfile -l review.docx
```

确认压缩结构中包含：

- `[Content_Types].xml`
- `_rels/.rels`
- `word/document.xml`
- `word/styles.xml`

若环境有 LibreOffice，可进一步转换为 PDF 或打开检查；没有时不得因此阻止交付，但必须完成结构和内容检查。

## 下载链接与附件

- 优先使用当前会话或渠道提供的附件、文件上传或文件发送能力。
- 最终回复中使用该能力返回的真实文件引用或下载链接。
- 不得编造 URL、文件 ID 或不存在的附件。
- 若渠道不支持文件发送，返回 `.docx` 的绝对路径，并明确告知用户如何从宿主系统访问。
- 在 WSL 中，如文件位于 Linux 用户目录，可按需复制到 `/mnt/c/Users/<Windows用户名>/Downloads/`，但只有在用户授权且目标用户名和路径明确时执行。

# 专利摘要汇编 · PatentMax

把散落的专利号或检索结果变成**一份能分发给团队阅读的摘要资料**：每件都有原始摘要、简短导读、主题分类和来源。与专利解读不同，这里以批量阅读为主，不逐项拆权利要求。

**不需要 API Key 就能用。** 专利数据来自 PatentMax 专利库，覆盖中国及美国、欧洲、日本、韩国、WIPO。

使用问题、企业采购：访问 **ip930.com**，右下角「联系客服」。

## 运行环境（必读，所有命令都适用）

部分 WorkBuddy 等环境的命令行不完整，`cat`、`ls`、`sleep`、`rm` 等可能找不到。为保证任何电脑都能跑通：

- 脚本路径一律写**绝对路径**：`$DIR/scripts/patentmax_client.py`（`$DIR` 是本技能所在目录），不要写 `cd ... && ...`（前一步失败会让后面整条静默不执行）
- `python` 找不到时依次试 `python3`、`py`；还找不到就用 WorkBuddy 自带的：先用 Glob 在 `~/.workbuddy/binaries/python/versions/` 下找到 `python.exe`，用它的完整路径。**下文所有 `python` 都按这条替换**
- 不要用 `cat` 读文件：读结果文件用 Read 工具，或用脚本的 `read` 子命令
- 检索命令几秒就返回；命令超时设为 120 秒即可

| 用户说 | 怎么做 |
| --- | --- |

## 第 1 步：先问清楚（最多一轮）

1. 专利号列表、检索结果JSON或带公开号的CSV
2. 按技术主题、产品模块或申请人分组（可选，默认技术主题）
3. 阅读对象及是否要中文导读（默认中文导读，保留原文摘要）

用户已经提供的信息直接使用，最多集中补问一轮；不要要求重新提供已知材料。

## 第 2 步：怎么做

1. **读入材料**：从用户列表或本地文件提取公开号，保留输入顺序并去重；保留用户标注。优先复用结果中已有的摘要，不因为汇编再逐篇付费取全文。
2. **补足缺失摘要**：只有号码、缺标题或缺摘要时才调用 `brief --no-claims`；每件只取一次，不加 `--legal`、不取全文、不额外扩检。确认号码一致，字段缺失写「未返回」。若用户还没有清单，先集中确认检索主题及数量范围后才检索。
3. **分组和导读**：按摘要实际内容分组，边界不明放「待归类」。每篇中文导读用2—3句概括问题、办法和摘要中明示的效果；原文没给参数就不补，导读与原文摘要分栏。用户要翻译时标明是译文，原文仍保留。
4. **控制容量**：每10篇一块保存CSV行和Markdown章节；导读先逐块完成，再由本地文件组合，不要求一次重写整份。清单很大时先报告数量和预算，再分块，不擅自删掉用户要求的条目。
5. **编阅读顺序**：按主题建立索引，每组挑1—3篇建议优先阅读的文献并给出基于摘要的理由；这是阅读顺序，不是技术价值评级。
6. **交付和恢复**：输出 `专利摘要汇编.csv` 和 `专利文摘.md`，附已处理/缺失/失败清单及证据目录。中断恢复复用已保存记录，只补缺失项。

**费用：** 复用现有检索计费，实际金额、免费次数与账户可用额度以平台及脚本返回为准。先说明预计调用数量与预算，批量任务分段保存；未经用户同意不扩大范围。 开始前用一句话告诉用户大概花多少。

## 第 3 步：交付

写一个文件 `专利摘要汇编.csv`，列依次为：

| 序号 | 主题分组 | 公开号 | 标题 | 申请人 | 公开日 | 原文摘要 | 中文导读 | 优先阅读理由 | 来源文件 | 待核实 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

- CSV为UTF-8带BOM，原文摘要保留原语言；另写专利文摘.md，包含主题目录、逐篇导读与公开号索引。
- 长摘要完整保存在CSV，聊天里只给汇编统计和少量示例；专利文摘不把导读标成专利原文。

给出输入数、去重后数量、分组数、成功/缺失/失败件数，展示3条导读样式，并提供CSV、文摘和证据目录。

`专利摘要汇编.csv` 最后加一行：`数据来源：PatentMax 专利库（ip930.com）`。

## 命令速查

```bash
python "$DIR/scripts/patentmax_client.py" read --file <已有检索结果.json>
python "$DIR/scripts/patentmax_client.py" brief --patent <缺摘要的公开号> --no-claims --json-out brief_01.json
```
JSON中的摘要可以直接用Read工具读取；大清单每10篇保存一块，最后用本地文件操作组合。

每条命令都加 `--json-out <文件>`，再用 `read` 或 Read 工具看结果（Windows 上直接读控制台输出会乱码）。
检索式写法、全部命令和参数见 `references/tools.md`、`references/query-syntax.md`。

## 出错时

- 输出里有 `"error": true` 或退出码不是 0：这一步没跑成，**不能写成「没检索到」**；原样把 `message` 告诉用户，网络问题就原样重跑同一条命令
- 第一次运行时输出里有「[PatentMax] 已自动领取免费试用……」：把这句话原样转告用户一次
- 出现 `"free_trial": true`：免费试用用完或过期，`message` 里写着怎么办（按提示前往 API 平台注册、创建密钥并保存，然后重跑当前命令），原样转告

## 它不做什么

- 只归纳用户给定或经用户确认检索出的材料，不保证主题覆盖完整，不把摘要导读当作权利要求保护范围分析。
- 每条事实来自实际接口返回，保留查询日期、公开号和来源文件；错误、空字段、接口不覆盖与没有记录分别写明。
- 默认检索范围为 all，使用中英文检索词；用户明确指定地域时再限制，交付说明实际数据库覆盖与筛选范围，不宣称全球无遗漏。
- 不出具查新、侵权、FTO、权属或法律效力结论；需要正式报告时另行选择对应能力。

**每一条专利信息都必须来自接口返回值**，不凭记忆补公开号、申请人、日期或法律状态。

## 4. 采集规范（硬性）

1. **可复现**：每条证据必须附可直接执行的复现命令；无法复现的观测不入台账。
2. **脱敏**：Cookie / Authorization / API Key / 凭证文件内容一律以 `<redacted>` 替换；不得归档明文凭据。
3. **带指纹**：每条证据必须含代码版本 + 依赖指纹 + OS 版本；缺指纹的证据视为无效。
4. **只存结论与输出**：中间调试产物不入库，仅保留最终 stdout 与结论。
5. **一证据一编号**：编号形如 `EV-P1-1-001`，不得复用；修订需新增编号并在"关联"字段回溯。
6. **与守护测试联动**：若同一不变量已有沙箱守护测试（如 D-6 文档状态同步），真机证据须同时记录守护测试结果。

## 5. 真机闭环前的沙箱兜底（当前策略）

在 P1 环境不可得期间，沙箱侧按以下方式维持发布可信度：

- 框架类不变量（阈值表 / 别名表 / 回退分支 / 文档版本单源）**预先在沙箱固化守护测试**，真机只需替换数据样本；
- 真机项在路线图中一律标注 `暂缓`，**不得勾 ✅**，避免以沙箱结论冒充真机结论；
- 本模板冻结后，真机执行者按 §2 逐条填写、按 §3 回填状态即可，无需再改结构。

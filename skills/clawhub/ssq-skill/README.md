# 双色球分析系统 (V2.1.35) — 架构与运维说明

> **诚实声明（务必先读）**：双色球红球接近完全随机（熵效率 99.91%），凯利 `f* < 0`（无正期望）。所有预测策略样本外回测 `p > 0.05`、ROI≈`-67%` 与随机 `-64.6%` 无显著差异，照此投注 1 年正收益概率仅约 `0.01%`，数学上**不比随机更好**。本系统价值在于「过程严谨、可验证、娱乐化选号」，**不是真的能可确保的中奖结果**。请理性投注，切勿超出承受能力的投入。

### 📌 项目定位：这个系统「干什么」与「不干什么」

**它干什么（真实价值）**
- 把开奖数据、专家推荐、多种选号思路整合进一条**可验证、可复盘**的流水线；
- 用 **no_edge 诚实闸门 + 五套反诈骗检验 + 奖金逐条核对 + 版本一致性护栏 + 主动体检**，确保系统**永远诚实地说"我没有优势"**，帮你抵御"我能预测"的自欺；
- 输出娱乐化的选号参考与透明的命中现实分布，让每次看推荐前先校准期望。

**它不干什么（边界，违反即数学错误）**
- ❌ **不可确保的中奖结果**：一等奖概率恒为 `1/17,721,088`，对任何选号思路（含随机机选）完全相同；
- ❌ **不预测开奖号码**：所有策略回测 `p>0.05`、样本外 ROI≈`-67%` 与随机 `-64.6%` 无显著差异；9 项过滤器只缩小范围、**不提升中奖概率**；"热冷号 / 奇偶大小 / 走势图 / 历史重合"等套路均已被证伪；
- ❌ **不承诺正收益**：凯利 `f*<0`，长期期望净亏，照此投注 1 年正收益概率约 `0.01%`；
- ❌ **不替代理性判断**：本系统是娱乐辅助，不是投资建议。投注请量力而行、设预算上限。

> 一句话：**你正在做的事不会让你离一等奖更近，但让你离"被彩票骗"更远。**

## 8. 强化引擎（V1.0 科学严谨性升级）

**为什么需要**：此前"所有策略不比随机好（p>0.05）"只是一次性回测的声称，从未用真实管线在历史上"逐期假装未知、预测下一期、再核对"验证过。V1.0 把系统从"产出号码"升级为"能用统计证据证明自己有没有优势"。

**`ssq_power_engine.py` 三大能力**（已接入 `ssq_smart.py` **Phase 6**，非致命，产出 `ssq_power_report.json`）：

1. **样本外滚动回测 `walk_forward_backtest`**：对历史上每个测试期，只用此前数据训练（逐字复刻 `ssq_auto` 的 CDM 加权/蓝球评分/9 项过滤），生成与线上同构的 5 组推荐，再用真实开奖核对命中，累计 ROI。
2. **蒙特卡洛成本仿真 `monte_carlo_cost`**：用回测的每期净盈亏经验分布重采样，模拟数万名玩家照此策略玩一年的真实财务结果（期望净亏、正收益概率、分位数）。
3. **诚实闸门 + 自我进化闸门**：
   - `honesty_guardrail`：用 **ROI 的 Bootstrap 配对置信区间** 对比纯随机基线。仅当 95% CI 下界 >0 才承认有优势——当前结论为**无优势**（下界未 >0）。
   - `assert_improvement`：任何"我变强了"的声称必须过 Bootstrap 检验，否则系统**自动拒绝**该声称，杜绝"自我感觉良好"式幻觉。
   - 另设**回归闸门**：对照上一版基线（`ssq_power_baseline.json`），检测本次代码改动是否意外改变结果。

**关键修正（诚实性）**：最初用"任意中奖期率"做主指标，结果被 5–15 元九等奖噪声主导，制造了"疑似差异"假象。已改为以 ROI 的 Bootstrap CI 为唯一判据——这才是统计正确且财务有意义的结论。

**验证（近 200 期样本外，与 2902 期历史数据一致）**：
- 策略 ROI ≈ **-10.1%**，纯随机基线 ≈ **-7.9%**，Bootstrap 95% CI 完全重叠 → **无统计显著差异，系统无预测优势**。
- 蒙特卡洛：照此玩 1 年（≈156 期），期望净亏 ≈ **¥720**，正收益概率仅 **11.8%**。
- 诚实闸门 ⛔ 拒绝"本系统更强"；回归闸门确认与上一版一致、无退化。

```bash
python lib/ssq_power_engine.py            # 近200期样本外（快，~25s）
python lib/ssq_power_engine.py --full     # 全量样本外（约2900期，较慢）
python lib/ssq_power_engine.py --self-test
```

## 9. V1.0 体检与加固（可靠 / 安全 / 精确）

围绕"中奖概率在数学上不可能超越随机"这一铁律，"更聪明"只能落在**可靠性、安全性、自检严谨度、诚实度**。本轮体检发现并修复 4 项真实短板：

### 9.1 数据安全：脏数据拦截（`ssq_auto.py`）
`validate_data` 原只"列问题"不阻断落盘，脏数据（号码非法 / 日期倒序）会被写进 `ssq_history.json`。
- 改为结构化返回 `{issues, fatal}`：致命错误（号码非法、日期倒序）触发时，**拒绝写入脏数据并回退到现有已存盘的安全数据**继续预测，而非用脏数据覆盖。软警告（期号跳跃、数据过期）仍只提示不阻断。

### 9.2 自动化可靠性：`ssq_run_v8.bat` 加固
- **失败可感知**：系统任务跑崩时，bat 落一个明确的可轮询告警文件 `ssq_run_alert.txt`（写明查日志的具体标记）；成功运行自动删除该文件。用户无需天天翻日志也能发现"上周跑崩了"。
- **日志轮转**：每次运行保留最近 5 次（`ssq_scheduler_run.log.1`~`.5`），既保留历史可回溯，又避免无限增长。

### 9.3 ML 科学严谨：样本外自评（`ssq_ml_selfcheck.py`）
新增模块，walk-forward 逐期"训练前 k 期 → 预测第 k 期 → 核对"，统计 ML 三模型（加权频率 / 随机森林 / 遗传算法）红球命中分布，**与纯随机基线对比**。
- 已接入护栏第 10 项 + `ssq_smart.py` **Phase 7**（非致命，产出 `ssq_ml_selfcheck.json`）。
- **诚实结论（末 203 期）**：三模型红球命中均值 0.596~0.749 ≈ 随机基线 0.773 → `no_edge`（无优势），与既有回测 p>0.05 完全一致。系统据此**用数据证明模型没有"超能力"**，而非空口声称"增加了分析视角多样性"。

### 9.4 配套性能/陷阱修复
- `ssq_ml_models.py` 遗传算法 `list(child) in valid_combos`（3.8 万项线性查找，每代每子代执行）改为 `valid_set` O(1) 查找，ML 自评 200 期从 ~108s 降至 ~20s，消除超时风险。
- `ssq_ml_selfcheck.py` 移除顶层 `sys.stdout` 包装（被 import 时关闭护栏进程 stdout 的"I/O on closed file"陷阱，与 V1.7 修过的 `ssq_auto` 同类），改为 `main()` 内处理。
- 护栏升级至 **10/10 全绿**；系统级任务 `schtasks /run` 端到端复验：bat 告警 + 日志轮转 + 数据拦截 + Phase 7 全生效，智能化得分 10/11，EXIT=0。

> ⚠️ 诚实边界：本系统"更强大"指的是**工程可靠性、自检能力与诚实度**，绝不是"更可有收益"。任何声称提升命中率的说法都是数学错误。

## 11. V1.0.2 预测多样性与诚实闸门加固（用户反馈"26085/26086 两期推荐几乎一模一样"）

用户发现 26085 与 26086 两期推荐高度相似（第2组前蓝球逐球相同、蓝球 4/5 组相同），怀疑模型出问题。深入排查后定位到**两个真实根因 + 一个健壮性缺陷**：

### 11.1 根因一（真实 BUG）：CDM 经验贝叶斯先验在数学上被抵消
`ssq_auto.py` 与 `ssq_power_engine.py` 原 CDM 公式：`alpha_prior = alpha_0 × freqs`，代入 posterior 后 `alpha_0` 项被完全抵消，`cdm_prob` 退化为**原始经验频率**——所谓"收缩"从未生效。两处同步修复为**与数据独立的 flat 先验**，使收缩真实发生（保持"回测复刻预测"硬保证）。

### 11.2 根因二：argmax 在 2900+ 期频率下近乎冻结
5 组均为"取评分最高组合(argmax)"，新增 1 期对 2900+ 期频率排名几乎无影响，于是 argmax 冻结在相近号码。改为**按目标期号做可复现的后验采样**（同一期 seed 相同→可复现；不同期 seed 不同→推荐自然变化）。强化引擎 `recommend` 同步改为同构采样。验证：相邻目标期 **5/5 组全部变化**（红球变动 6~10 球、蓝球 4~6 球）。

### 11.3 健壮性：回归闸门下标越界
`bootstrap_diff_ci` 假设比较序列等长，旧基线(200期)与当前运行(2703期)长度不同 → 回归闸门崩溃。已改为**自动对齐到较短者**，回归闸门不再误报。

### 11.4 交付增强
- 报告新增**「四、跨期一致性自检」**板块：加载上一期预测 JSON，逐组展示前蓝球变动球数与"是否完全不变"，透明回应"两期相似"疑虑，并诚实说明"变动≠更准"（一等奖概率对任何法相同）。
- **「六、命中现实分布 + 与随机对照」改为动态读取** `ssq_power_report.json`（2703 期：ROI -7.1% vs 随机 -6.9%、Bootstrap 95%CI=[-4.12,+4.56]pp 含 0）与 `ssq_ml_selfcheck.json`（红球命中 0.60~0.75 球 vs 随机 0.77 球），**不再写死过期数字**；每组劣势文案也改为动态生成。
- 板块编号理顺为一~七（原存在两个"六"冲突）。

### 11.5 交叉验证同步修复
`ssq_cross_validate_v84_final.py` 第 4 节原是**独立的旧版重算**（仍带 CDM 先验 bug + argmax），与新管线双重不一致导致 6.3/6.4/6.9 失败。改为**调用权威函数 `ssq_auto.generate_predictions` 重算**，三方一致性变为「权威重算 vs JSON vs HTML」，既防序列化漂移、又验证采样后推荐**可复现**。结果：**52/52 全通过（百分之百）**。

### 15.4 第四套假设：历史并集重合（用户观察「每期都与同比+环比8期汇总有几个重合」）

- **实证（ssq_overlap_test.py，2724 个有效目标期）**：并集平均覆盖红球 24.7/35（70.6%）、蓝球 9.2/12（76.9%）。当期实际重合 **红球 3.55 球 / 蓝球 1.54 球**；纯随机号码与同一并集重合 **红球 3.53 / 蓝球 1.54**——**二者无统计差异**。「红球≥1 重合」实际 99.96% vs 随机 99.86%，均近必然。且用户这套「同比+环比」构造（3.55）与「8 期随机历史」构造（3.58）**同样无差别**。
- **结论**：重合是集合大小的必然结果（并集已占 7 成号码，任意新开奖期望重合 5×24.7/35≈3.53 球），**不含预测力**；并集过宽（≈71% 覆盖）无法缩小到具体号码，一等奖概率仍恒为 1/17,721,088。`no_edge` 不变。该脚本已并入第 11 项诚实闸门第 4 套。

### 15.5 第五套假设：中奖人数 / 奖级分布预测力（用户提议「反推猜中人数辅助预测」）
- **用户设想**：上一期各奖级中奖人数 → 反推「猜中每个奖项的人数/次数」→ 结合近期奖级分布，是否对预测下期有帮助。
- **数据源**：本地 `ssq_history.json` 无中奖注数；体彩官方 webapi（gameNo=85）返回参数不合法、中彩网反爬；改用 **500 datachart 历史表**（GB18030，含销售额/奖池/一二等奖注数），抓取 **2904 期**（07001~26086），存 `ssq_winner_stats.json`。用途仅限中奖注数结构化数据，与专家爬虫隔离。
- **实证（ssq_winner_stats.py，2904 期）**：
  - **A 可预判性**：原始滞后/跨期相关虽 p<0.05，但 r²<4%（大样本假象）；**去趋势（一阶差分）后**，本期奖级/销售额预测下期开奖特征的 6 项跨期相关全部 r²≈0%、p>0.05 → 预测力归零。销售额 r=0.987 自相关是「销量随时间增长」趋势假象。
  - **B 冷热号 EV**：生日号（1-31）占比 vs 二等奖注数 r=+0.041（r²=0.2%，p=0.029 接近多次检验随机边界）→ 人类过度投注生日号的分奖偏差即便存在也极微弱，只影响「万一中奖分多少」，不改变中奖概率、不改善负 EV。
  - **EV 复核**：观察命中率 4.03e-8 ≈ 理论 4.67e-8（稳定无聚集）；浮动奖派彩/销量 20.7%（整体返奖率约 50%）→ EV<0、f*<0。
- **结论**：中奖人数是「结果」不是「输入」；聚合中奖注数**无法反推具体号码**（信息论欠定：无数组合对应同一注数）；去趋势后无任何可预判结构 → 对「预测下期号码」**不含预测力**，`no_edge` 不变。唯一真实信息：中奖人数反映「别人怎么选号」的偏好偏差，仅可用于边际 EV 优化，绝不改变负期望。该脚本已并入第 11 项诚实闸门第 5 套。

## 22. 排程"静默被杀"缺陷与护栏第 22 项 + 自检严重级分层（2026-08-04）

### 22.1 发现的真实生产缺陷（此前 21 项护栏全绿却漏检）

四体全面复查中，`schtasks /query /v` 显示：

```
上次运行时间: 2026/8/3 20:51:47
上次结果:     267014        <- SCHED_S_TASK_TERMINATED (任务被中止)
```

同时 `ssq_scheduler_run.log` **只有 4 行**、结尾是 `^C`：任务开跑即被杀，
**整条预测流水线根本没执行**。

而护栏第 18 项（三体协同）当时是 ✅ 绿的——因为它只查三个**静态**字段
（已启用 / SYSTEM / bat 目标）。**静态绿 ≠ 真的跑过**。MEMORY 里反复写过
"体检必须动态验证（读 LastTaskResult / 日志结尾 / 告警文件）"，但这条铁律
**从未落进代码**，只停留在记忆文档里。

**根因**：任务 Settings 中三个"会主动杀任务"的反模式配置：

| 设置 | 危害 |
|------|------|
| `DisallowStartIfOnBatteries=true` | 笔记本电池供电时任务根本不启动 |
| `StopIfGoingOnBatteries=true` | 跑到一半切电池即被杀 |
| `IdleSettings.StopOnIdleEnd=true` | 用户一动鼠标（空闲期结束）即被杀 |

20:10 触发、20:51 被杀，与"用户回到电脑前、空闲期结束"高度吻合。

   `LastTaskResult` 是否为 0、Settings 有无杀任务反模式、上次日志有无

### 22.3 自检严重级分层（重要设计决定）

第 22 项刚接入时，整条流水线直接 `EXIT=1` 拒绝出报告——**过度阻断**。
排程昨晚有没有被电池策略杀掉，与用户此刻手动跑一次预测的**正确性毫无关系**。
若不分层，一个纯环境问题会让人永远拿不到产物。

故 `check()` 增加 `blocking` 参数：

- `blocking=True`（默认）＝**正确性类**：数据 / 交叉验证 / 未定义名 / 报告板块 /
  模型回归。失败即"产出可能是错的"，阻断交付，退出码 1。
- `blocking=False` ＝**运维环境类**：排程运行态等。单列"⚠️ 运维告警"区
  **大声报出**，但不阻断交付，退出码仍为 0。

汇总输出因此分成两段：先列运维告警，再列阻断性失败。已做双向单测
（仅告警→rc=0；含正确性失败→rc=1）。

### 22.4 同批修复的其它两处

  已改为显式判 `r.returncode != 0`；顺带揪出一个真存在语法错的历史临时文件。
- **护栏第 21 项 静态未定义名闸门**：`py_compile` 只查语法不做名字解析，

  把整条流水线拖成退出码 1。新增零依赖 AST 检查器补这个洞。

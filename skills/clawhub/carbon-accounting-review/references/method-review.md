# PCF and carbon-software method review

## Product carbon footprint branch

1. Identify the selected method, edition, intended use and applicable product rules. Record functional or declared unit, reference flow, lifecycle boundary, geography and period. A corporate inventory is not a product footprint.
2. Check stage coverage, exclusions/cutoffs, data quality, primary/secondary inputs, allocation and recycling/end-of-life treatment against the inspected selected method. Do not silently choose contested conventions or claim all alternative methods equivalent.
3. Separate fossil/biogenic treatment, removals and offsets as required by the chosen framework. Keep generic guidance distinct from licensed clause evidence. No factor database is provided.
4. Treat comparison or public comparative claims as requiring additional method-specific conditions and professional review. Done: a bounded method-screening report, not a certified PCF or comprehensive LCA.

## Software-method branch

1. Obtain authorized rule descriptions, schemas, calculation examples and test outputs. Treat code as review material; do not execute target-supplied code merely to use this skill.
2. Map each inspected requirement to rule, source, implementation evidence, independent expected result and actual test status. Mark NOT REVIEWED when implementation or tests were not inspected.
3. Check missing inputs, invalid units, duplicated allocation/GWP, Scope 2 alternatives and unsupported netting as failure cases. A schema-valid record can still contain false source data.
4. Distinguish implemented safeguards, tested cases, unverified conformity and human-review requirements. Done: a coverage matrix with named gaps; no software-security certification or full standards-conformance claim.

# Skill Extraction Protocol — 高频流程→子Skill自动生成

## 模式检测算法

### 信号采集

Agent 在每次任务执行后，隐式维护以下计数器：

```
step_sequence_count[工具调用序列的hash] → 出现次数
error_fix_count[错误类型+修正方案的hash] → 复用次数
format_correction_count[格式修正的hash] → 出现次数
workflow_similarity[任务步骤序列对] → 相似度 0-1
```

### 检测规则

**规则1：重复步骤检测**
```
IF step_sequence_count[S] >= 3
  AND S 包含 ≥ 3 个工具调用
  AND S 的数据部分不同但结构相同
THEN 触发提取 → 生成"工作流Skill"
```

示例：用户多次要求"读取CSV → 清洗数据 → 生成图表 → 导出PDF"，虽然数据不同但步骤结构一致。

**规则2：固定修正检测**
```
IF error_fix_count[E] >= 2
  AND 修正方案相同或高度相似
THEN 触发提取 → 生成"避坑Skill"或追加到已有Skill的Pitfalls段
```

示例：每次生成Word文档都遇到字体问题，修正方案都是"嵌入字体文件"。

**规则3：用户偏好模式检测**
```
IF format_correction_count[F] >= 3
  AND 用户修正方向一致
THEN 触发提取 → 生成"风格指南Skill"或追加到USER.md
```

示例：用户反复要求"不要用列表，用段落"、"标题用H2不用H1"。

**规则4：工作流相似度检测**
```
FOR EACH 任务对 (T1, T2):
  similarity = LCS(T1.steps, T2.steps) / max(len(T1.steps), T2.steps))
  IF similarity > 0.8
    AND 任务对数量 >= 3
THEN 触发提取 → 生成"通用工作流Skill"
```

## 提取流程

### Step 1: 模式确认

```
1. 列出所有满足阈值的模式
2. 对每个模式评估：
   - 是否足够通用（不绑定特定数据/项目）？
   - 是否有明确的触发场景？
   - 是否能用一段话描述清楚？
3. 过滤掉过于特化的模式（仅适用1个项目的流程）
```

### Step 2: 流程抽象

```
1. 去除具体数据引用（文件名、URL、ID等）
2. 保留步骤骨架（做什么，不限制怎么做）
3. 标注可变参数（用 {placeholder} 表示）
4. 标注决策点（"如果X则A，否则B"）
```

### Step 3: Skill草稿生成

按以下结构生成 SKILL.md 草稿：

```markdown
---
name: auto-{简短描述}
description: 从历史操作中自动提取的{领域}工作流。当{触发条件}时使用。
version: 0.1.0
---

# {Skill标题}

> 自动提取自 {N} 次历史操作 | 提取日期: YYYY-MM-DD

## 适用场景
{描述什么时候使用这个Skill}

## 工作流程
1. {步骤1}
2. {步骤2}
3. {步骤3}

## 注意事项
- {从历史踩坑中提取的注意点}

## 常见问题
- {从历史复盘中提取的常见问题及解决方案}
```

### Step 4: 用户确认

向用户展示：
```
检测到高频模式，建议提取为Skill：

模式名称: {name}
出现次数: {N}次
最近一次: {date}
步骤概要: {summary}

是否提取为独立Skill？[是/否/修改后提取]
```

### Step 5: 创建与注册

用户确认后：
```
1. 调用 skill_manage(action="create", name=..., content=...)
2. 在 MEMORY.md 中记录提取事件
3. 将原始模式数据从 L2 清理（已沉淀为Skill，不再需要原始记录）
```

## 质量校验规则

### 提取前校验

| 检查项 | 标准 | 不通过处理 |
|--------|------|------------|
| 通用性 | 不绑定特定项目/数据 | 拒绝提取，建议存入L3 |
| 可描述性 | 能用 < 200字描述核心流程 | 拒绝提取，模式不清晰 |
| 触发明确性 | 有明确的触发关键词/场景 | 拒绝提取，无法自动激活 |
| 非冗余 | 不与已有Skill重复度 > 70% | 合并到已有Skill |

### 提取后校验

| 检查项 | 标准 | 不通过处理 |
|--------|------|------------|
| 行数 | SKILL.md < 200行（自动提取的应更精简） | 精简后重新生成 |
| 可执行性 | 每个步骤Agent可直接执行 | 补充缺失步骤 |
| 无硬编码 | 无具体文件路径/URL/ID | 参数化替换 |

## 子Skill维护

### 版本迭代

当提取的Skill被使用后产生新的修正：
```
1. 修正记录追加到Skill的"常见问题"段
2. 如果修正改变了核心流程 → 更新版本号（minor bump）
3. 如果Skill方向根本改变 → 考虑拆分为两个Skill
```

### 合并与淘汰

```
IF 两个auto-Skill的触发场景重叠 > 50%
THEN 合并为一个Skill，保留更完整的版本

IF auto-Skill 30天内未被触发
THEN 标记为候选淘汰，通知用户确认删除
```

## 提取示例

### 示例1：PDF报告生成工作流

**检测到的模式**（出现4次）：
```
读取数据源 → 数据清洗 → 生成图表 → 组装PDF → 嵌入字体 → 输出
```

**提取的Skill**：
```yaml
name: auto-pdf-report
description: 从数据源生成带图表的PDF报告。当用户要求生成数据报告、统计报告、分析报告时使用。
```

### 示例2：中文编码修复

**检测到的模式**（出现3次）：
```
运行Python脚本 → 中文输出乱码 → 添加 sys.stdout encoding utf-8 → 修复
```

**提取为避坑规则**（追加到已有Skill或MEMORY.md）：
```
规则: Windows上运行Python脚本处理中文时，必须在脚本开头添加:
  import sys, io
  sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')
适用: 所有涉及中文输出的Python脚本
来源: 3次历史复盘 (2026-06-28, 2026-06-30, 2026-07-01)
```

# Essays, analysis and expert explanation

Use this pathway when the author is making a complex idea intelligible, engaging an informed audience or developing an argument across a sustained piece. Load `EDITORIAL-JUDGMENT.md` for substantive changes. Read actual audience and project context first, not a presumed university essay template.

## Look for reader-operational defects

- **Concept dependency:** a paragraph uses a term or distinction before this reader has enough to use it. Propose a definition, example or moved explanation *at the earliest point it becomes necessary*.
- **Argument bridge:** one premise and one conclusion are both stated but the logical relation is invisible. Supply the minimum bridge the author can honestly defend; never introduce a new empirical fact to make the leap.
- **Abstraction level:** several abstractions stack without a foothold. If a verified or explicitly hypothetical example exists elsewhere, suggest moving it earlier; do not demand an anecdote as if it were research.
- **Example-generalization link:** an example should make a principle graspable; a principle should tell a reader what the example illustrates. Some literary essays intentionally leave the relation implied—preserve that.
- **Scope/qualification:** maintain “for this group,” “sometimes,” “in these cases,” and other limits close to the claim. Avoid unsupported global expansion.
- **Conclusion:** should earn its degree of certainty. If the piece raises a question intentionally, do not manufacture closure.

## Paired decisions

**Edit — missing premise**
- Draft: “Documentation is difficult to navigate. So replacing the homepage with API reference will solve it.”
- Proposed only with a supporting brief: “If most visitors already know the API name they need, direct reference navigation may help them. First-time learners may need a different starting point.”
- This qualifies the inference, rather than claiming a universal solution.

**Leave — earned metaphor**
- “A timetable is a promise.” Do not translate to “A schedule may establish an expectation” merely to sound technical.

**Edit — example orphaned**
- Draft gives three examples of contradictory onboarding emails, then jumps to a new topic. If the author wants to explain message consistency, propose one brief linking sentence: “All three emails promise a different next step, leaving the reader unsure what is actually available.” Use only if all three supplied examples support it.

**Leave — technical depth for experts**
- An article for platform engineers correctly uses “idempotence” after defining it in a previous section. Don't replace it with a longer lay explanation simply because it's specialist language.

**Leave — deliberate open ending**
- An essay closes with a clear unanswered ethical question. Do not add a generic “in conclusion” paragraph to manufacture certainty.

## Exact edit format

Anchor the offending sentence; identify the reader's knowledge at that point; propose an exact replacement, deletion or section move. If another section already contains the missing explanation, prefer **reordering** to generating more text. Ask an inline self-question only when it could change that proposal.

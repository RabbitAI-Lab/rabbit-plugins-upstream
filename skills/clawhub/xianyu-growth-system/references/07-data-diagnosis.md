# 数据诊断
<!-- version: 1.1.0 | last_updated: 2026-08-10 -->

> **阈值声明**：本文档中所有数值阈值（CTR、咨询率、CVR 等）均为基于运营经验设定的初始参考值，**尚未经过大规模实证验证**。不同品类、账号等级、季节因素会导致实际健康范围显著不同。请将阈值作为诊断起点而非绝对标准，优先关注自身数据的相对变化趋势。随着真实数据积累，应逐步校准属于自己的阈值。

## 闲鱼实际可用数据说明

> **重要**：闲鱼 App 实际展示的数据有限，并非下方看板中的所有字段都能直接获取。请根据实际可获取的数据进行分析，不要编造数据。

| 数据项 | 闲鱼 App 可获取？ | 获取方式 |
|--------|-----------------|---------|
| 浏览量（曝光） | ✅ | 商品管理页直接显示 |
| 想要数 | ✅ | 商品页直接显示 |
| 评价数 | ✅ | 商品页直接显示 |
| 已售/成交数 | ⚠️ 部分 | 有评价时可见，无评价时无法确认 |
| 点击量（CTR） | ❌ | 闲鱼不单独展示点击量，用浏览量近似 |
| 搜索曝光 vs 推荐曝光 | ❌ | 闲鱼不拆分流量来源 |
| 咨询量 | ⚠️ | 可在聊天列表手动统计 |
| 退款/售后次数 | ⚠️ | 可在订单管理手动统计 |
| 闲气值 | ✅ | 设置-账号安全中查看 |

### 最小数据收集方案

如果无法完整记录上方看板的所有字段，至少记录以下 5 个核心数据点：

```yaml
minimal_daily:
  date: ""
  product_name: ""
  views: 0              # 浏览量（App 直接显示）
  inquiries: 0          # 咨询数（手动统计当天聊天）
  orders: 0             # 成交数
  profit: 0             # 当日利润（售价 - 所有成本）
```

> 这 5 个数据点足以计算：咨询率（inquiries/views）、成交率（orders/inquiries）、每日利润趋势。其余字段在有条件时补充。

## 数据诊断矩阵

| 数据表现 | 诊断 | 动作 |
|---------|------|------|
| 曝光低 | 流量问题 | 检查关键词/类目/账号垂直度/商品本身需求 |
| 曝光高、点击低 | 点击问题 | 优先改主图 > 标题 > 价格 |
| 点击高、咨询低 | 价值问题 | 检查图片/文案/价格/信任/商品信息 |
| 咨询高、成交低 | 信任/价格问题 | 检查客服/定价/商品描述/售后承诺 |
| 成交高、利润低 | 商业模型问题 | 提价或降成本 |
| 成交高、售后高 | 产品问题 | 停止扩量，先解决产品体验 |
| 成交高、利润高、人工低 | 赢家 | 进入扩张池 |
| 成交高、利润高、人工高 | 需产品化 | 优化流程或半自动化 |
| 曝光骤降（非新品期） | 可能被限流/降权 | 检查是否有违规警告/闲气值下降/内容安全审核触发 |
| 新品曝光虚高但转化差 | 新品扶持期扭曲 | 过滤前3-5天数据，看扶持期结束后的稳态表现 |

## 漏斗分析

```
曝光 -> 点击(CTR) -> 收藏 -> 咨询 -> 成交(CVR) -> 好评 -> 复购
```

每个环节的转化率：

| 环节 | 指标 | 最低生存线 | 健康范围 | 低于阈值说明 |
|------|------|----------|---------|------------|
| 曝光->点击 | CTR | > 2% | > 3% | 主图/标题有问题 |
| 点击->咨询 | 咨询率 | > 5% | > 8% | 商品页说服力不足 |
| 咨询->成交 | CVR | > 3% | > 15% | 价格/信任/客服有问题 |
| 成交->好评 | 好评率 | - | > 95% | 产品体验有问题 |
| 成交->复购 | 复购率 | - | > 10% | 产品力/客户关系 |

> **阈值说明**：「最低生存线」与 `references/01-principles.md` Score B 达标线一致，低于此线 SKU 应考虑淘汰。「健康范围」是运营良好的参考目标，高于此线说明表现优秀。两个层级之间的区间属于"可优化但不紧急"。注意：不同品类差异大，阈值仅供参考。

## 诊断流程

### Step 1：定位漏斗瓶颈

从上到下找到第一个低于阈值的环节。

### Step 2：分析原因

```
曝光低 -> 是关键词问题？类目问题？账号垂直度？商品需求本身不够？
         -> 区分流量来源：搜索曝光低=标题/关键词覆盖不足；推荐曝光低=新品扶持期结束或互动反馈差
点击低 -> 是主图不吸引？标题不精准？价格过高？
咨询低 -> 是图片不够真实？文案没说清楚？价格让人直接划走？
成交低 -> 是客服回复质量？价格异议处理？信任不够？售后担忧？
```

> **流量来源诊断**：自然搜索曝光反映标题关键词的召回能力，推荐流量曝光反映商品在个性化推荐中的竞争力。两者骤降的原因不同——搜索曝光下降通常是关键词竞争加剧或标题老化；推荐曝光下降通常是互动反馈（点击率/咨询率/收藏率）变差或账号权重下降。

### Step 3：制定优化方案

一次只改一个变量，观察效果。

### Step 4：记录结果

```yaml
diagnosis:
  date: "2026-01-07"
  sku_id: "SKU-001"
  funnel:
    impressions: 10000
    clicks: 300
    ctr: 3.0%
    inquiries: 40
    inquiry_rate: 13.3%
    orders: 4
    cvr: 10%
  bottleneck: "cvr_low"
  analysis: "咨询量正常但成交率低，可能是价格异议处理不足"
  action: "优化客服话术，增加信任证明"
  result: "pending"
```

## 趋势监控

不只看单日数据，要看趋势：

```yaml
trend:
  week_1:
    cvr: 6.25%
    profit_per_hour: 40.8
  week_2:
    cvr: 5.1%
    profit_per_hour: 35.2
  week_3:
    cvr: 3.8%
    profit_per_hour: 22.1
  trend_direction: "declining"
  alert: "单位经济模型正在恶化，可能竞争者进入"
```

趋势下降时优先诊断原因，不是继续上新。

## 最小数据模型

为支持趋势监控和生命周期管理，用户应维护以下两个 YAML 文件。

### SKU 状态表

每个 SKU 一条记录，跟踪当前生命周期阶段和关键决策。

```yaml
skus:
  - sku_id: "SKU-001"
    product_name: "MacBook桌面支架"
    category: "STANDARD_PRODUCT"
    lifecycle_stage: "L1"        # L0/L1/L2/L3/L4
    decision: "ITERATE"          # TEST/OPTIMIZE/SCALE/HOLD/REJECT/ITERATE/PRODUCTIZE
    opportunity_score: 72
    created_date: "2026-01-07"
    last_updated: "2026-01-14"
    unit_economics:
      selling_price: 99
      contribution_profit: 27
      profit_per_hour: 90
    stop_conditions:
      - "7天有效曝光后咨询率低于2%"
      - "售后成本超过预估20%"
    notes: "CTR正常但咨询率偏低，计划更换主图"
```

### 每日数据记录

每天记录一次，用于趋势监控和漏斗诊断。

```yaml
daily_records:
  - date: "2026-01-14"
    sku_id: "SKU-001"
    impressions: 3200
    clicks: 96
    ctr: 3.0
    inquiries: 8
    inquiry_rate: 8.3
    orders: 1
    cvr: 12.5
    revenue: 99
    contribution_profit: 27
    labor_hours: 0.3
    profit_per_hour: 90
    refunds: 0
    refund_rate: 0
    after_sales_count: 0
```

> **使用方式**：将以上 YAML 模板保存为本地文件，每次与 AI 分析时提供最新数据。AI 基于历史记录进行趋势分析和生命周期判断。

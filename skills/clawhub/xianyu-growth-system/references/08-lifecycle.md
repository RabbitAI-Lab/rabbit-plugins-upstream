# SKU生命周期管理
<!-- version: 1.1.0 | last_updated: 2026-08-10 -->

## 四级生命周期

```
L0 Opportunity（候选） -> L1 Experiment（实验） -> L2 Winner（赢家） -> L3 Core（核心资产） -> L4 Productized（产品化）
```

| 级别 | 定义 | 资源投入 |
|------|------|---------|
| L0 候选 | 还没验证，在机会池中 | 1% |
| L1 实验 | 正在测品，有数据但未结论 | 5% |
| L2 赢家 | 已证明有需求 + 有利润 | 30% |
| L3 核心 | 稳定 + 可复制 + 可规模化 | 64% |
| L4 产品化 | 已产品化/半自动化，边际成本下降 | 持续投入 |

资源分配不平均：让资本、时间和流量向已验证有效的东西集中。

---

## 生命周期判定规则

### L0 -> L1（进入实验）

条件：
- Opportunity Score >= 60
- 单位经济模型为正
- 供应链可用（至少已确认货源）

### L1 -> L2（成为赢家）

条件：
- 7天以上数据
- CVR > 3%
- 贡献利润 > ¥30/单（含平台服务费0.6%-1.6%）
- 退款率 < 10%
- 每小时贡献利润 > ¥50

### L2 -> L3（成为核心）

条件：
- 30天以上稳定数据
- 已完成爆款复制（至少3个变体）
- 供应链稳定
- 有明确的停止规则且未触发

> **经营性行为认定预警**：进入L2-L3阶段时，交易量和在售商品数可能接近经营性行为认定标准（在售>30件且品类<3类、年交易>104笔、年销售额>10万元）。被认定为经营性卖家后，须在主页公示营业执照/经营地址/联系方式，并履行七天无理由退货等经营者义务。提前评估是否需要办理个体工商户登记。详见 `references/00-platform-rules.md`。

### L3 -> L4（产品化）

条件：
- 每小时贡献利润 > ¥100
- 人工时间成为瓶颈
- 流程已标准化
- 可以半自动化或全自动化

## 生命周期决策

每个 SKU 在每次复盘时必须给出：

```yaml
lifecycle:
  sku_id: "SKU-001"
  current_stage: L1
  decision: ITERATE
  reason: "CTR正常但咨询率低，需要优化商品页"
  next_action: "重新拍摄主图，测试2个新标题变体"
  stop_conditions:
    - "再测7天咨询率仍低于5%"
    - "供应商涨价导致贡献利润低于¥20"
  estimated_lifecycle: "60天"
```

决策选项：
- **STOP** - 淘汰，资源释放给其他SKU
- **ITERATE** - 继续优化当前变量
- **SCALE** - 扩大投入（增加变体/关键词/曝光）
- **PRODUCTIZE** - 进入产品化流程

## 商品四象限

每周做一次商品淘汰：

| | 高转化 | 低转化 |
|---|---|---|
| **高曝光** | 爆款：补货/扩标题/增相似商品 | 优化：最值得优化，流量已来，优先改主图->价格->文案 |
| **低曝光** | 隐藏爆款：优化标题/关键词/类目/发布策略 | 淘汰：直接淘汰，不恋战 |

---

## 爆款复制

当一个商品成为 L2 赢家：

> **重复铺货检测风险**：爆款复制时，如果多个变体使用相同或高度相似的标题/图片/描述，会被算法判定为重复铺货，导致商品下架和账号降权。复制时必须确保每个变体的标题、主图、描述都有实质性差异（不同角度、不同场景、不同关键词侧重）。

### 横向复制（同一需求）

```
低价版 -> 标准版 -> 高配版 -> 套装版 -> 服务版
```

### 纵向复制（同一人群）

```
产品1 -> 产品2 -> 产品3 -> 产品4
```

形成 SKU 矩阵。

---

## 月度战略复盘

每月把所有 SKU 放到矩阵：

```
             高利润
                ↑
     明星        │      潜力
                │
────────────────┼──────────────> 可复制
                │
     鸡肋        │      陷阱
                ↓
             低利润
```

- 明星：加资源
- 潜力：优化
- 鸡肋：观察
- 陷阱：淘汰

## SKU生命周期预警

| 信号 | 含义 | 动作 |
|------|------|------|
| 咨询量连续下降 | 需求减弱或竞争加剧 | 检查竞品变化 |
| CTR连续下降 | 主图/标题老化 | 更新主图和标题 |
| CVR连续下降 | 价格竞争力下降或信任降低 | 重新评估定价 |
| 退款率上升 | 产品质量/描述问题 | 停止扩张，排查原因 |
| 竞品数量快速增加 | 同质化风险 | 启动差异化策略 |
| 供应商涨价 | 利润空间压缩 | 重算单位经济 |
| 曝光自然衰减（非违规） | 商品老化，推荐权重衰减 | 更新主图/标题刷新权重信号，或启动新链接替代 |
| 服务费门槛触发 | 月成交突破门槛后费率升至1.6% | 重新核算贡献利润，确认是否仍为L2/L3 |

## 失败后恢复策略

SKU 被淘汰不是终点，而是认知沉淀的起点。每个失败的 SKU 都应转化为下一个实验的输入。

### 失败复盘模板

SKU 被判定为 STOP/REJECT 后，必须完成以下复盘：

```yaml
post_mortem:
  sku_id: "SKU-001"
  decision: REJECT
  failure_reason: "7天曝光8000，咨询率仅1.2%，低于2%停止线"
  # 失败原因分类（选一）
  root_cause: demand_absent | demand_misread | listing_failure | pricing_failure | supply_failure | competition | execution
  # 从这个失败中学到的
  learnings:
    - "该关键词搜索量看起来大但购买意图弱"
    - "主图偏产品展示，缺少使用场景，CTR 可能被低估"
  # 可复用的认知
  reusable_insights:
    - "该品类用户更看重场景图而非产品图"
    - "该价格区间（¥80-120）的买家对运费敏感"
  # 下一步
  next_action: "换关键词重新测试，或放弃该品类"
  assets_recovered: "主图素材可复用 | 客服话术模板已沉淀"
```

### 失败原因分类

| 原因 | 特征 | 是否值得重试 | 重试方向 |
|------|------|------------|---------|
| demand_absent | 曝光够但无咨询，换关键词仍无改善 | 否 | 放弃该品类 |
| demand_misread | 有咨询但人群不匹配 | 是 | 重新定义目标用户，调整商品页 |
| listing_failure | 曝光够但 CTR 低 | 是 | 重拍主图，重写标题 |
| pricing_failure | 咨询够但成交低，价格异议多 | 是 | 调整定价或增加价值包装 |
| supply_failure | 供应商断货/涨价 | 是 | 找替代供应商后重试 |
| competition | 同行涌入，价格战 | 视情况 | 启动差异化或换细分品类 |
| execution | 客服响应慢/发货延迟 | 是 | 优化流程后重试 |

### 失败转化的 3 个原则

1. **区分"需求失败"和"执行失败"** - 需求不存在就放弃，执行不到位就改进后重试
2. **回收资产** - 主图素材、客服话术、关键词研究等可复用的资源要显式记录
3. **更新认知** - 将学到的写进下次选品的检查清单，避免重复同样的错误

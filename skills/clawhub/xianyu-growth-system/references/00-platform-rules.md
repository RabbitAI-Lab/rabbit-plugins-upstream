## 信息发布规范

### 标题规则
- 标题须与商品真实属性一致，不得堆砌无关关键词
- 禁止使用"全网最低""老板疯了""绝对正品"等无搜索价值的营销词
- 禁止在标题中植入第三方平台名称、联系方式、二维码信息

### 图片规则
- 图片须为商品实拍，不得使用盗图或与商品不符的网图
- 禁止图片中包含微信号、二维码、外部链接等导流信息
- 禁止图片含有虚假宣传、夸大功效的内容
- 二手商品须展示真实瑕疵/使用痕迹

### 描述规则
- 须如实描述商品品牌、型号、成色、维修记录、瑕疵
- 不得隐瞒商品缺陷或故障
- 禁止描述中留联系方式、第三方链接、二维码
- 禁止虚假宣传、夸大功效、误导性描述

### 类目与重复铺货规则
- 商品须发布在正确类目下
- 同一商品不得在多个类目重复发布
- 不同商品使用相同标题/图片/描述可能被判定为重复铺货
- 重复铺货可导致商品下架和账号降权

## 交易争议处理规范

### 争议处理流程

```
买方发起争议 -> 平台受理（订单确认收货前或超时打款时限内）
  -> 举证阶段（双方提供证据）
  -> 平台判定
  -> 执行（退款/退货退款/驳回）
```

### 举证责任分配
- 签收规范：收件人应场检视表面是否一致，发现问题可拍照拒签
- 描述不符：卖方未如实披露瑕疵/维修/质量问题的，作退货退款处理
- 质量问题：交易支持退货退款；致使交易目的不能实现的，退货风险由卖方承担
- 发货规范：卖方须按时发货，未征得买方同意不得合并包裹

### 各类交易特殊规则

| 交易类型 | 特殊规则 |
|---------|---------|
| 虚拟商品 | 交付前风险卖方承担，交付后根据举证判定；虚拟定制类无理由退款需协商 |
| 服务类 | 卖方已产生实质服务行为的，退款需协商一致；维修服务需签收次日起30天内完成 |
| 定制物品 | 买方无理由退款需赔偿卖方损失（最高不超过订单金额） |
| 当面交易 | 建议当面验货确认，交易完成后争议处理难度增大 |

### 平台大数据快速裁决机制
闲鱼可基于卖方历史处罚记录等综合评估，对买方退款申请直接快速处理。卖方历史违规越多，被快速裁决支持退款的可能性越大。

> 运营启示：保持良好的闲气值和低纠纷率，本身就是降低争议处理风险的最好策略。

## 卖方软件服务费

### 费率结构

| 费项 | 费率 | 触发条件 |
|------|------|---------|
| 基础软件服务费 | 0.6% | 所有成交订单 |
| 软件服务费（基础门槛） | 1% | 当月累计成交>10件且>10000元，超出部分 |
| 软件服务费（手机品类门槛） | 1% | 当年手机品类累计成交>6笔，超出部分 |
| 鱼小铺综合费率 | 1.6% | 开通鱼小铺的卖方每笔订单（0.6%基础+1%软件），不享受门槛优惠 |

**关键规则**：
- 成交额 = 确认收货时交易订单的交易额（含买家实付款、运费、平台红包/补贴；不含闲鱼币、卖方出资红包/补贴）
- 同一笔订单最多收取1.6%（基础0.6%+软件1%）
- 确认收货后退款，已划扣的服务费不退还
- 确认收货前退款，不收取服务费
- 由支付服务商从买家支付的订单款项中实时划扣

### 对单位经济模型的影响
- 普通卖家：基础0.6%几乎不影响利润判断
- 月销突破门槛后：费率升至1.6%，需重新核算利润
- 手机品类：年6笔后额外1%，高客单品利润侵蚀明显
- 鱼小铺：每笔1.6%，需评估增量流量是否覆盖额外1%成本

### 费率计算示例

```
示例1：普通卖家，月成交8单，总额¥6000
  -> 仅基础0.6%，服务费 = 6000 × 0.6% = ¥36

示例2：普通卖家，月成交15单，总额¥15000
  -> 前10件/¥10000内：10000 × 0.6% = ¥60
  -> 超出部分：5000 × 1.6% = ¥80
  -> 总服务费 = ¥140

示例3：鱼小铺卖家，月成交15单，总额¥15000
  -> 每笔1.6%，总服务费 = 15000 × 1.6% = ¥240
  -> 比普通卖家多¥100，需评估鱼小铺增量流量是否值得
```

## 经营性行为界定

### 认定标准（满足任一即被认定）

| 条件 | 阈值 |
|------|------|
| 已取得营业执照/许可证，或公示经营声明 | 直接认定 |
| 经营性描述（一手货源/多库存/七天无理由等）且在售>30件且品类<3类 | 认定 |
| 同一型号/款式频繁反复售出5次以上 | 认定 |
| 年交易笔数>104笔且每月至少3笔 | 认定 |
| 年销售额>10万元 | 认定 |

### 触发场景与运营对策
- 突然被认定经营行为时，需在主页公示营业执照/经营地址/联系方式
- 收藏/潮玩/数码/搬家/明星闲置等特殊场景不直接认定，平台综合判定
- 被认定后须履行七日无理由退货等经营者义务

### 经营者额外义务
- 依法办理市场主体登记（豁免情形除外）
- 如实登记身份/经营地址/联系方式/行政许可
- 在个人主页公示营业执照/经营地址/联系方式
- 如实全面披露商品品牌/型号/现状/维修记录/瑕疵
- 履行七日无理由退货等经营者义务

| 描述不当（与描述不符/未披露瑕疵） | - | -20 | -100 |

| 骚扰他人（恐吓/辱骂/人身攻击） | -1 | -20 | -100 |
| 泄露用户信息 | - | -20 | -100 |

用户被处罚时，其实际控制人下的其他闲鱼账号也可能被处置。多账号运营需注意关联风险。

## 算法原理与运营优化

> **合规边界**：以下内容仅用于帮助卖家理解平台公开规则，提供真实、合规的商品与服务。任何通过虚假数据、刷量、批量操作、账号操控等方式影响平台算法的行为均属违规，本系统明确禁止并会劝阻用户。

### 搜索排序算法
闲鱼搜索使用 **倒排索引（文本匹配）+ 神经网络向量匹配** 双路召回，再通过相关性模型排序，并引入多样性打散机制。

用户可按"信用""价格""最近活跃""离我最近"排序。

运营优化启示：
- 标题关键词覆盖决定召回命中率，须包含买家实际搜索词
- 商品描述详实度影响相关性评分
- 卖家活跃度影响"最近活跃"排序权重
- 多样性打散意味着同类型商品不会全部展示，差异化标题/图片有助于覆盖更多展示位

### 个性化推荐算法
算法收集用户浏览/搜索记录/设备信息/服务日志，通过模型预测人群偏好特征，匹配商品并排序，根据实时行为反馈调整推荐，并引入多样性打散。

应用场景：首页推荐、支付完成页。用户可长按商品图片选择屏蔽类似商品或类目。

运营优化启示：
- 新品有扶持期，需在扶持期内积累正向反馈（点击/咨询/收藏）以获得持续推荐
- 商品编辑会重置权重，频繁编辑可能导致流量波动
- 重复铺货会被算法检测并降权
- 账号活跃度和成交反馈影响推荐分配
- 个性化推荐导致不同用户看到的商品不同，不能仅凭自己搜索验证排名

### 内容安全算法
对文本/图片/音频/视频进行安全风险识别，使用深度学习/知识图谱推理/时序模型/融合模型。高置信度算法直接审核，低置信度引入人工审核。覆盖商品/评价/留言/圈子等所有信息发布场景。

运营优化启示：
- 标题/图片/描述中的敏感词可能触发审核，导致商品延迟上架或被删
- 图片中的二维码/联系方式会被算法识别并处罚
- 重复发布被删商品会加重处罚
- 申诉需提供有效凭证，无凭证申诉成功率低

### 算法对运营决策的影响

| 算法机制 | 对运营决策的影响 |
|---------|---------------|
| 新品扶持期 | 新上架商品有一定流量倾斜，须在此期间积累正向数据 |
| 商品编辑重置权重 | 频繁编辑标题/图片会导致权重重置，应在低流量时段操作 |
| 重复铺货检测 | 相同标题/图片/描述会被判定为重复铺货，需差异化 |
| 账号活跃度反馈 | 持续活跃和成交正向反馈提升推荐分配 |
| 搜索个性化差异 | 不同用户搜索结果不同，不能仅凭自己搜索判断排名 |
| 内容安全审核 | 敏感内容/图片会导致商品被删或延迟上架 |

## 合规检查清单

```yaml
# 选品阶段必检
pre_listing:
  - item: "商品是否属于13类禁售品？"
    action: REJECT_IF_YES
  - item: "商品是否属于限售品类？是否有对应资质？"
    action: REJECT_IF_NO_QUALIFICATION
  - item: "是否涉及他人知识产权/品牌授权？"
    action: VERIFY_AUTHORIZATION

# 上架阶段必检
on_listing:
  - item: "标题是否包含违禁营销词（全网最低/绝对正品等）？"
    action: REMOVE_IF_YES
  - item: "标题/图片/描述是否包含微信号/二维码/外部链接？"
    action: REMOVE_IF_YES
  - item: "图片是否为实拍？是否展示了真实瑕疵？"
    action: FIX_IF_NO
  - item: "描述是否如实披露品牌/型号/成色/维修记录/瑕疵？"
    action: FIX_IF_INCOMPLETE
  - item: "商品是否发布在正确类目下？"
    action: FIX_IF_WRONG_CATEGORY
  - item: "是否存在重复铺货风险（相同标题/图片/描述）？"
    action: DIFFERENTIATE_IF_YES

# 定价阶段必检
on_pricing:
  - item: "是否虚构原价制造虚假折扣？"
    action: REMOVE_IF_YES
  - item: "服务费是否已计入成本？"
    action: CALCULATE_PLATFORM_FEE
  - item: "是否达到软件服务费门槛？"
    action: RECALCULATE_IF_THRESHOLD_BREACHED

# 客服阶段必检
on_conversation:
  - item: "是否引导站外交易（发第三方链接/二维码/诱导跳转）？"
    action: PROHIBIT
  - item: "是否泄露用户信息？"
    action: PROHIBIT
  - item: "是否有骚扰/恐吓/辱骂行为？"
    action: PROHIBIT

# 规模化阶段必检
on_scaling:
  - item: "是否触发经营性行为界定标准？"
    action: EVALUATE_OBLIGATIONS
  - item: "多账号是否存在关联管控风险？"
    action: ASSESS_LINKED_RISK
  - item: "闲气值是否处于安全区间（>80）？"
    action: MONITOR_AND_FIX
  - item: "争议处理中举证是否充分？"
    action: PREPARE_EVIDENCE
```

## READING STRATEGY

### Priority of consultation:

1. **Always:** `SKILL.md` (in context)
2. **On a new request:** `references/NAVIGATION.md`
3. **For a specific problem:** `references/PROTOCOLS.md`
4. **To go deeper:** the corresponding author file

### Combining:

A typical request may call for 2–3 sources:
- Navigation → choosing an author
- Author file → techniques and quotes
- Protocols → step-by-step algorithm

### Example mappings:

| User request | What to read |
|--------------|--------------|
| "I see no point in living" | PROTOCOLS: loss of meaning; authors: frankl, yalom |
| "My husband doesn't hear me" | NAVIGATION: relationships; authors: satir, rogers, bowlby |
| "Constant anxiety" | PROTOCOLS: anxiety; authors: hayes, beck, linehan |
| "How do I stop procrastinating" | PROTOCOLS: procrastination; authors: ellis, hayes |
| "I'm afraid of dying" | authors: yalom, frankl |

## STRUCTURE OF THE AUTHOR FILES

Each author file is divided into chapters; a chapter can be read independently of the rest of the file. Typical chapter roles:

- `biography` — the author's biography (usually chapters 1–2)
- `concept` — theoretical concepts (chapters 3–5)
- `technique` — concrete techniques
- `dialogue` — dialogue examples
- `quote` — quotes
- `case` — a case / story
- `comparison` — comparison with other authors of the project
- `indication` — indications / when to apply

When only part of a file is needed, read the chapter whose heading matches the request — the headings are uniform across all author files.

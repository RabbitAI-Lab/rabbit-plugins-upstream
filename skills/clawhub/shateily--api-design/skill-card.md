## Use Case:

Developers and engineers use this skill to design and review REST API contracts for public, partner-facing, and production APIs. It helps shape endpoint naming, method semantics, status codes, pagination, filtering, authentication, authorization, versioning, rate limiting, and response formats.

### Deployment Geography for Use:

## Known Risks and Mitigations:

Risk: Endpoint, token, authorization, validation, and deletion snippets may be copied without adaptation to the consuming application's security model.

Mitigation: Treat snippets as examples only, then review and adapt authorization checks, validation rules, rate limits, and deletion behavior before production use.

Risk: API design guidance can be applied inconsistently across existing services.

Mitigation: Compare proposed endpoint, response, error, pagination, and versioning patterns against the existing API contract and OpenAPI documentation before implementation.

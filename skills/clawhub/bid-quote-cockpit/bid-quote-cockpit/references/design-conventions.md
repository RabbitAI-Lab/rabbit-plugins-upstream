# 设计惯例与技术规范

从多轮迭代中沉淀的**配色、版式、图表与 HTML/JS 工程规范**。照做可避免重复踩坑。

---

## 1. 配色

### 主色板（莫兰迪低饱和，商务活泼）
| 用途 | 色值 | 说明 |
|---|---|---|
| 钢蓝 | `#3E6E9E` / 浅 `#B3C5DA` | 主力色 |
| 赭石 | `#B5791F` / 浅 `#EDD5B5` | 均值线、强调 |
| 雾青 | `#3E8E80` / 浅 `#B3D4D0` | 主力色 |

**备用序列**（供应商 >5 家时顺延）：深青 `#2E6B66`、驼色 `#A68A5B`、橄榄 `#7A8B5A`、灰蓝 `#5C7A99`、薰衣草 `#9B8FA8`、卡其 `#B5A642`。

| 语义 | 色值 | 备注 |
|---|---|---|

> ⚠️ 与国内股市"红涨绿跌"相反——这里是**成本**语境，涨用橙不用红。不要被习惯带偏，也不要用红色（禁用色）。

### 轮次表达
同一供应商的**上轮用浅色、本轮用深色**，图例与卡片色条保持一致。这样读者一眼能区分轮次而不是靠记忆。

## 2. 版式

- **核心模块须 ≥3 种互补呈现形式**。纯卡片网格会显得呆板（用户明确反馈过）。推荐组合：
  `指标速览带（横向 KPI）` + `报价标尺（横向条形，同坐标）` + `卡片网格（比例价位条）`
- **卡片顶部色条升级为比例价位条**：track 浅灰 `#EFF3F7` + vendor 色 fill，`width% = price / 组内最高价`。低成本、提质明显。
- **横向标尺 0 起点、同坐标**，是相对幅度的诚实呈现。截断轴会夸大差异。
- 表格用三线表风格，避免斑马纹过重；数字右对齐、等宽字体感。
- 技术术语保留英文原文（BOQ、subtotal、EXCL VAT 等）。

## 3. 图表规范

- **柱状图**：`barMaxWidth` 建议 14~16；系列多时收到 14 给均值线留空间。
- **均值线**：`type:'line'` + `symbol:'diamond'` + 虚线 + `z:3`；标签简洁（如 `均 €165k`）。
- **均值线不得高于所有柱子**——生成后必须抽查几个分项；高于全柱基本可判定计算错误。
- **图例**：均值线与数据柱都要进图例，历史均值线在「无历史数据」时必须同步消失（不要留空图例）。
- `mk(id)` 建图函数**必须复用已有实例**：`echarts.getInstanceByDom(el) || echarts.init(el)`，否则每次 tab 切换都 init 新实例，会重复渲染并内存泄漏。

## 4. HTML / JS 工程规范（硬约束）

1. **自包含单文件**：echarts 内联（技能已 vendored 在 `assets/echarts.min.js`）。产出 HTML 无外部 `<script src>` / `<link href>`，可离线、可直传云端。
2. **`mk(id)` 复用实例**（见上）。
3. **生成脚本用 Python 拼 HTML 时，自定义 JS 必须写在 `r"""..."""` 原始字符串里且不做 `%` 格式化**——CSS 里的 `100%` 会把 `%` 格式化炸掉。配色等变量用字符串拼接。
4. **保持 3 个 `<script>` 块分离**：`[0] echarts` `[1] DATA` `[2] app`。校验器依赖 `blocks[len-2]` / `blocks[len-1]` 取 DATA 与 app；合并成 2 块会让启发式命中 echarts 并抛 `getContext is not a function`。
5. **`.toFixed` 类型错误**：明细项若是 `{desc, amt}` 对象，写 `x.toFixed(2)` 会失败 → 用 `+(Number(x.amt)||0).toFixed(2)`。
6. **字符串截断助手**（如 `dsc()`）要在 app JS 顶部定义，漏了会运行时报错。
7. **校验器 DOM 桩**需支持 `textContent` getter/setter（KPI 容器写入后要进 `_html`），以及 `querySelectorAll` 对 `class="tab"` / `class="subtab"` 的识别。

## 5. 基准线的两类用法（重要，曾反复调整）

| 类型 | 定义 | 是否可比 | 结论 |
|---|---|---|---|
| **总额级** | 历史门店的总金额（或按本项目面积折算后的金额） | ❌ 不同城市/面积/范围 | **不画**。用户明确指出"这种不同地方不同面积的金额均值，没有参考意义" |
| **分项级** | 同一分项（如"墙柱饰面工程"）在各历史门店的金额均值 | ✅ 同一分项工程量级可比 | **可画** |

**落地**：
- 第二节报价标尺 → **不画**总额级历史均值线；标尺用途收紧为"同项目各家相对量级比较"。
- 第四/七节分项图 → **画**历史分项均值线。
- 页面上要写清这个区别，避免读者误以为两个地方自相矛盾。

## 6. 交付前校验（标准动作，缺一不可）

```bash
node scripts/verify_dashboard.js ./看板.html
```

校验器做四件事：
1. `node --check` 语法门禁
2. **桩化运行时冒烟**：vm + 最小 document + 桩 echarts（`init` 返回 `{setOption,resize}`，`getInstanceByDom` 返回 null），执行 DATA + app JS
3. **断言 series**：`series` 存在、`data` 是数组、**无 NaN/undefined 数据点**（显式 `null` 表示"无数据"，仅告警不报错）
4. **渲染产物扫描**：应填充容器 `innerHTML` 长度 > 0；全文扫 `undefined|NaN`

退出码非 0 不得交付。

补充：**Chrome headless 截图**抽查长图（图表 canvas 不写 innerHTML，静态扫描查不出来）：
```bash
chrome --headless --disable-gpu --screenshot=./shot.png --window-size=1500,6000 ./看板.html
```

## 7. 云端托管（可选）

若使用者要求把看板放到资料库云端：
1. **图片托管自检**：确认无第三方域 `<img>` 外链（echarts 导出功能里的 `<img src="'+s+'">` 是运行时 base64 dataURI，**不算**外链）。
2. `import_html.py --node-block-id <节点ID>` 覆盖同步（需 admin/owner；仅编辑权限会返回 `56161`，此时改走增量编辑流程）。
3. **默认不发布**：产出是协作态链接；只有使用者明确说"发布/上线"才调 `publish_page.py`。

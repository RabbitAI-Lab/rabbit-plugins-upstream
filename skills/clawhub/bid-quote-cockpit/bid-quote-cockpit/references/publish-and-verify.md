# 上线发布与线上核验（通用，无项目信息）

> 看板做完只是「本地能看到」。要发给别人看，必须走发布链路，**并且核验线上真实字节**——
> 这两步都踩过坑，本文件把它们固化成可复用手册。

---

## 1. 发布目标选型

| 目标 | 适用 | 关键限制 |
|---|---|---|
| **单文件 HTML 直接发**（邮件/IM 附件） | 内部小范围、不做版本管理 | `file://` 打开：**localStorage 与云端不通**、ECharts 内联才不依赖网络 |
| **云端 Page（资料库/在线文档）** | 需要固定链接、多设备、可协作 | 需 `import_html` 上传 + `publish` 出公开链接；页面在 **iframe 沙箱**内，localStorage 可能不可用 |
| **静态站点托管** | 需自定义域名/长期归档 | 需把 HTML + 资源一起部署 |

**结论（本类看板）**：一律走「**云端 Page + 公开链接**」，且看板**必须离线自包含**
（ECharts 内联、无第三方 `<img>` 外链），否则在别人机器上打开就是半张图。

---

## 2. 发布前三条硬门（缺一条就不要发）

```bash
# ① 自包含检查：无第三方 <img> 外链（云端规范禁止）
python - <<'PY'
import re,io
H=io.open('看板.html',encoding='utf-8',errors='replace').read()
bad=[u for tag in re.findall(r'<img[^>]+>',H)
     for u in re.findall(r'(?:src|srcset)\s*=\s*["\']([^"\']+)["\']',tag)
     if re.match(r'^(https?:)?//',u)]
print('外链图片:', bad or '无（合格）')
PY

# ② 体积自检：打印的字节数必须等于磁盘真实字节数（否则是读写编码搞错、发了旧版）
python -c "import os;print(os.path.getsize('看板.html'))"

# ③ 全部本地校验先过（语法/版式/渲染/固化一致性）
```

## 3. 发布（云端 Page 形态）

```bash
# 取一次性 token（有效期约 30 分钟），再执行导入 + 发布
python import_html.py --token-stdin 看板.html --node-block-id <节点ID>   # 覆盖既有节点
python publish_page.py --token-stdin --node-id <节点ID>                  # 生成公开链接
```

要点：
- **token 用 stdin 首行传**，不要写进命令行参数（会进 shell history）。
- 有既定节点时 `import_html` 是**覆盖**语义，同一链接永远指向最新内容 —— 对使用者友好，不必每次换链接。
- 导入成功与发布成功各有**明确成功标识**（如 `KS_IMPORT_OK` / `KS_PAGE_PUBLISH`）；
  脚本必须检查标识，**不要只看进程退出码**（网络层失败常以 exit 0 返回错误体）。

## 4. 线上核验（最容易偷懒、也最容易翻车的一步）

### 4.1 分享链接 ≠ 产物

发布返回的分享 URL **通常只是一个几 KB 的引导壳**（内含 `__PUBLISH_BOOTSTRAP__`，
再由前端 JS 去拉真实 HTML）。所以：

```bash
curl -sL "https://<分享链接>" -o shell.html
grep -o "__PUBLISH_BOOTSTRAP__" shell.html        # 命中 → 确认这是壳
# 壳里会给出真实静态产物的地址（形如 https://<static-host>/page/<id>/<version>/）
# 把 <version>/index.html 拉下来，才是要校验的字节
curl -sL "https://<static-host>/page/<id>/<ver>/index.html" -o online_static.html
```

**版本号会递增**：核验时不要写死版本，从壳里解析出来，否则你会对着旧版做断言、误判「没生效」。

### 4.2 三条核验手段（按强度递增）

| 手段 | 查什么 | 局限 |
|---|---|---|
| 字节特征串 | 新文案/新标识是否已在线上字节里 | 查不到**客户端 JS 现算**的数字（源码里只有裸数据） |
| 真机渲染 | 分数、名次、图表是否真的显示对 | 需 Chrome；要等虚拟时间预算跑完 |
| **双档案一致性** | **两个全新浏览器配置打开是否同分** | 这一步才是「换台电脑会不会变」的真答案 |

```bash
# 最强手段：拿线上真字节跑固化一致性
python scripts/verify_score_frozen.py ./online_static.html --config ./score_config.json --online
```

判定：日志末行「失败项: 无」+ 退出码 0。

### 4.3 为什么必须用「两个全新配置档案」

`--user-data-dir` 指向一个**全新临时目录**，等价于「一台从没打开过这个页面的电脑」。
两个不同目录各跑一次，若结果不一致 → 说明分数依赖了本机状态（localStorage / 缓存），
**固化没做干净**。用同一个 profile 跑两次是查不出来的。

## 5. 发布后的缓存与版本陷阱

| 现象 | 原因 | 处理 |
|---|---|---|
| 分享链接打开还是旧内容 | 入口壳/中间层按 URL 精确缓存 | 用**带版本的真实产物地址**核验；入口链接本身不要依赖即时生效 |
| 版本号变了但内容没变 | 导入失败但仍触发了发布 | 检查导入成功标识，别只看发布返回 |
| 本地对、线上错 | 线上拉的是**旧字节** | 对比两次请求的字节数 / `Last-Modified` / 新特征串 |

**推荐做法（根治）**：入口用一个**永不改动的引导页**，内容是
`location.replace('/app.html?t=' + Date.now())`；真身 `app.html` 每次发布都变。
这样入口链接固定不变、永远拿到最新，且缓存不再成为问题。

---

## 6. 交付时给链接的纪律

- **只给一个最终链接**，不要罗列历史版本 / 备用链接 / 后台地址（后台地址等对方主动问）。
- 链接给出时**同时给出核验结论**（在什么条件下验证过、结果如何），让人敢用。
- 若这一版含固化分数：明确写「任何设备打开结果一致」「改分路径 = 更新构建种子后重新生成发布」。

## 7. 一页清单（发布前逐条打勾）

```
[ ] 无第三方 <img> 外链
[ ] 无 CDN 外链（ECharts / SDK 一律内联；国内网络 + 微信内置浏览器取不到外链）
[ ] 磁盘字节数 == 生成时打印的字节数
[ ] 语法 / 版式 / 渲染 / 固化一致性 全部 exit 0
[ ] import 成功标识 + publish 成功标识 都出现
[ ] 从壳页解析出真实产物地址，**下载真字节**再校验
[ ] 双档案一致性通过（两个全新 user-data-dir 结果相同）
[ ] 交付只给一个链接，并附核验结论
```

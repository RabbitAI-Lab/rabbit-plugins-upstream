# 看板九节模块规格

每节的**出现条件、数据源、呈现形式、易错点**。生成器 `scripts/build_dashboard.py` 按此实现。
条件模块未满足时**整节不渲染**，不留空白占位。

---

## 一、报价总览表（必选）

**数据源**：`quotes.json` 各家各轮的 `total / opt1 / opt2 / promo / used`。

**呈现**：一张表格，行=供应商，列=各轮报价（含方案价/优惠价细分子列）+ 排名 + 单方造价 + 涨跌。

| 列 | 说明 |
|---|---|
| 供应商 | 按 `used_round` 的采用价升序排名 |
| 各轮：报价 / 优惠价 / 方案一 / 方案二 | 有则显示，无则 `—` |
| 采用价 | 加粗，加排名徽标 |
| 单方造价 | `采用价 / area_sqm`，标注公式 |
| 较上轮涨跌 | ▲/▼ + 百分比 |

**口径说明区**（`#s1note`）必须写明：采用价取值规则（`promo ?? opt1 ?? total`）、税务口径、面积口径、无本轮报价单位的处理方式。

**易错点**
- 无本轮报价的单位要**补位参与排名**（沿用上轮价），并在该行标注「沿用首轮·无更新」。不补位会导致排名错乱（某家没报二轮却被算成第 1）。
- 排名必须用**计算值**，不能只看有本轮报价的那几家。

## 二、供应商报价概况（必选）

**这是视觉核心，必须用 ≥3 种互补形式**，避免满屏卡片：

1. **2.1 指标速览带**（5 格横向 KPI）
   - 本轮最低有效报价（含供应商名 + 单方 + 有效可比第 1）
   - 有效可比价差（区间最低~最高）
   - 各家采用价均值（+ 单方均值）
   - ⬜ **历史单方均值**（**仅当 history.json 存在时出现**，文案必须带"仅单方可比，不折算总额"）
   - 待办/异常提示（如"N 家待更新"）
2. **2.2 报价标尺**：每行一家，双条横图（上轮浅色 / 本轮深色，**0 起点同坐标**）+ 右侧金额 + Δ chip（▲琥珀橙涨 / ▼雾青绿降）。未提交本轮的显示斜纹占位 + "待更新"。
3. **2.3~2.5 卡片网格**：各家卡片顶部加**比例价位条**（按组内最高价等比 `width%`），低成本提质。

**易错点**
- 标尺**不画**总额级历史均值参考线（不同城市/面积不可比，见 `design-conventions.md`）。
- Δ chip 配色是成本语境：涨=橙、降=绿，与国内股市红涨绿跌相反，不要被"红涨"习惯带偏。
- 指标带第 4 格（历史均值）文案必须写明是**单方均值**，绝不能写成"折算本项目 xx㎡ ≈ €xxx"。

## 三、总价 / 单方 / 剔除后对比（必选）

三张竖向柱状图（`#cTotal` `#cSq` `#cNoFac`），各家各轮，**同色系不同深度**（浅=上轮，深=本轮）。

- `#cTotal`：总价
- `#cSq`：单方造价（`总价 / area_sqm`）
- `#cNoFac`：**剔除 `facade_cat_key` 之后**的总价（**仅当该分项存在时出现**）
- **章节标题随数据变化**：`facade_cat_key: null` 时标题为「三、总价 / 单方对比（本项目无剔除项）」，
  且 2.4 卡片块、`cNoFac` 图一并消失。使用者说"本项目无需剔除项"时，就填 `null`。

**易错点**
- 「剔除后」不是"删掉一家"，是"删掉一个分项"，用于排除某分项（如外立面）对总价的压倒性影响。
- 单方造价必须用各家自己的面积（本项目面积相同则一致；历史门店各用各的）。
- 交付前扫一遍：未设剔除项时全文不应再出现「剔除后」字样（残留说明是上一版没清干净）。

## 四、分部分项横向对比（必选）

**每个轮次 × 金额/单方 = 4 张图**（2×2 布局）：

| | 金额（€） | 单方（€/㎡） |
|---|---|---|
| 上轮 | `cCatR1` | `cCatR1Unit` |
| 本轮 | `cCatR2` | `cCatR2Unit` |

每图柱子 = **各家（N 家）+ 历史门店（M 家，仅当 history）**，另加 **2 条均值线**：
- 本项目各家均值（`#5D4E75` 虚线圆点）
- ⬜ **历史门店均值**（`#B5791F` 虚线菱形，**仅当 history.json 存在**）

**易错点**
- 均值线**不得高于所有柱子**，否则基本可判定计算错误——生成后必须抽查几个分项。
- 无本轮报价的单位，本轮图里用其**上轮值**补柱并标注「沿用上轮」，不能用 `null` 把柱子画没（读者会以为没报）。
- **`noBreakdown`（整包价、未拆分的单位）不进本图**：画 0 柱会被读成"该项报价 0"。图下说明须写明
  「X 未提供分项拆分（整包价），不进本图，柱缺失仅代表未拆分、不代表该项为 0」。

## 五、分项明细逐条对比（条件：需 `items`）

**条件**：至少一家存在非空 `items`。否则整节跳过。

**呈现**：按分项 tab 切换（`#catTabs` + `#cItem`），每个 tab 内各家逐条横向 bar 对比。

**匹配**：多轮对照用**描述级匹配**，不是按序号：
```python
def norm(s):
    s = str(s or '').split('\n')[0]          # ① 只取首行
    s = re.sub(r'[\u4e00-\u9fff]+', '', s)   # ② 剥离中文译文
    return re.sub(r'[^A-Za-z0-9]+', '', s).lower()   # ③ 去符号+小写
```
输出 `matched / gone（仅上轮有）/ new（仅本轮有）` 三类。

**易错点**
- **必须先剥离中文再归一化**。新版报价常在描述里补中文译文（"Spotlight 明装射灯"），不剥离会与旧版失配。
- 匹配率 100% 属巧合，通常 90% 上下，正常。匹配不上的要逐条核对，不要直接丢弃。

## 六、异常报价专项核查（条件：需存在异常条目）

**条件**：存在零单价 / 缺单价 / 疑问 / 未报价条目。**全部正常则整节跳过**（不要为了凑模块硬做）。

**核查维度**（对每条异常条目）：
- 备注列（主材说明/辅材/Notes）是否含包含性声明 → 判定【已含·正常】vs【疑问项】
- 判定规则（顺序敏感）：
  1. 否定式优先：`not included` / `excluding` / `shall not be included` → 【明确不含】
  2. 肯定式：`included in ...` / `are included in ...` → 【已含·正常】
  3. 词形排除：`including ...` / `includes ...` 是材料/工艺描述，**不是**价格包含声明（常见误判根源）
  4. 三列均无标识 → 【疑问项】

**呈现**：KPI 卡（各类条数）+ 分布饼图 + 分项分布图 + 重算总价 vs 原文总价勾稽 + 结论备注。

**易错点**
- **中间产物 JSON 的零单价统计字段不可信，必须逐条重算**（`unit_price` 为 `None` 或 `0` 即计）。
- **小计/合计行必须先剔除**再统计，否则"小计 0"被误计入零单价：
  ```python
  if any(k in desc for k in ("小计","合计","TOTAL","Subtotal")): continue
  ```

## 七、历史对比（⬜ 条件：`history.json` 非空）

**不提供历史数据 → 本节整节不渲染。**

**呈现**：
1. **7.1** 各家本轮 vs 历史各门店：各分项金额对比（每家一张子图）+ 历史均值线
   —— ⬜ **仅当至少一家历史门店有 `cats` 时才渲染**；所有历史门店都只有单方/总额时，7.1 整块不出（附一句说明）。
2. **7.2** 全门店单方造价横向对比（本项目 + 历史各店）：本项目各单位用深色、历史门店用浅色分两段，
   叠加 **过往门店单方均值橙色虚线**（`C_AMBER`，`markLine` 带文字标注）。均值 = 各家 `total ÷ area` 的算术平均。

**易错点**
- 只做**分项级**与**单方级**对比；**总额级**折算禁止（见 data-contract §3 硬规则 3）。
- 历史门店口径不一致（含税/不含税）→ 排除并在页面写明，不硬凑。
- 均值线是"过往门店单方均值"，**不要**写成"本项目应是多少钱"；图下必须写明均值算法与口径差异
  （历史结算金额 vs 本项目投标报价）。

## 附录 A、清单外增项核查（⬜ 条件：`quotes.json` 有 `addenda`）

**编号独立于 9 节**（"附录 A"），放在第九节之后、footer 之前。

**呈现**：
- **A.1 指标速览带**：原文不含税小计 / I.V.A. + 税率 / 原文含税合计 / 占其 BOQ 报价比例 / 法定强制项数
- **A.2 逐项核查表**：序号 / 项目（原文 + 中文）/ 原文金额 / 强制属性 / 法规依据 / 必要性判定 + 金额弹性
- **A.3 结论与处理建议**：必要性结论 / 对报价的影响 / 数据来源

**易错点**
- 法定合规义务的责任主体是**施工承包单位本身** —— 结论写"要求四家在同一口径下各自含入或书面声明不含"，
  不要把某家的加价当既定增项照收。
- 原文 SUBTOTAL 与逐项相加不一致时，**照原文列示并标注差额**（写"待其书面澄清"），不自行更正数字。
- 增项同时要进第九节行动清单：P0 澄清 + P0 对齐四家口径（+ 发现内部勾稽不一致时加一条 P1）。

## 八、勾稽校验（必选）

一张表，逐项列出校验结果与差异：

| 校验项 | 方法 | 合格线 |
|---|---|---|
| 分项求和 vs 采用总价 | `sum(cats) == used` | diff ≤ 0.05（四舍五入） |
| 逐条明细求和 vs 分项小计 | `sum(items.amount by cat) == cats[i]` | diff ≤ 0.05 |
| 采用价 vs 原文总价 | `used == original_total` | 不等时**标注差异原因**（如优惠额未分摊），不判"复核失败" |
| 单方造价反算 | `used / area_sqm` | 与图上一致 |
| 排名可复现 | 重算排名 == 表内排名 | 完全一致 |

**易错点**
- 优惠额未分摊导致的分项合计 ≠ 优惠后总价（如差 €4,943）是**已知差异**，要注明而不是判失败。
- **勾稽基准用「原文报价」，不要用「采用价」**，否则把优惠额误判成差错。

## 九、行动清单（必选）

按 **P0 / P1 / P2** 优先级给出可执行下一步，每条含：动作 / 对象（哪家）/ 依据（数据出处）/ 期望产出。

**必含项**（满足条件时）：
- P0：异常报价单位的澄清函（零单价/疑问项/未报价项清单）
- P0：口径不一致或未提交本轮报价的单位跟进
- P1：有效可比排名与推荐定标对象的依据说明
- P2：分项离散度异常（某分项各家差异过大）的专项复核

## 条件模块判定伪代码

```python
def should_render(mid, cfg, quotes, history):
    force = cfg.get('modules', {}).get(mid)
    if force is True:  return True
    if force is False: return False
    # force is None → 自动判定
    if mid == 'detail':  return any_items(quotes)
    if mid == 'anomaly': return has_zero_or_doubt(quotes)   # 逐条重算
    if mid == 'history': return bool(history and history.get('stores'))
    if mid == 'addenda': return bool(quotes.get('addenda'))
    return mid in ('overview','profile','totals','category','reconcile','actions')
```

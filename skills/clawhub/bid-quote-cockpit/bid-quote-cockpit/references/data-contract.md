# 数据契约（config.json / quotes.json / history.json）

本技能的全部输入都是数据驱动。换门店、换供应商、换轮次、换分项结构，**只改这三个文件，不改代码**。

---

## 1. `config.json` —— 项目配置

```jsonc
{
  // —— 项目元信息 ——
  "project": "XX 旗舰店装修工程投标报价分析",   // 看板主标题
  "subtitle": "首轮 / 二轮报价对比",            // 副标题，可空
  "area_sqm": 112.0,                            // 本项目面积（㎡），用于单方造价
  "area_note": "计租面积",                      // 面积口径说明，会显示在页面上
  "currency": "EUR",                            // 货币符号或代码：EUR / USD / CNY / ¥ ...
  "basis": "不含税（EXCL VAT）",                 // 税务口径，全文统一
  "version": "V1",                              // 看板版本号，显示在页头

  // —— 轮次定义（可 1 轮，也可 3 轮+）——
  "rounds": [
    {"key": "r1", "label": "首轮报价"},
    {"key": "r2", "label": "二轮报价"}
  ],
  "used_round": "r2",      // 排名/主视觉采用哪一轮；单轮项目填该轮 key

  // —— 可独立剔除的分项（如外立面常被单独拎出对比）——
  // 有则填分项 key，看板会出现「剔除外立面后」对比；无则填 null
  "facade_cat_key": "facade",

  // —— 文件路径（相对 config.json 所在目录，或绝对路径）——
  "quotes": "./quotes.json",
  "history": null,          // ⬜ 历史数据：提供路径才出现历史对比；不提供填 null

  // —— 供应商配色（可选）——
  // 不给则按内置色板顺序自动分配（钢蓝/赭石/雾青/紫灰/琥珀/深青/驼色/橄榄…）
  "colors": {
    "供应商A": {"main": "#3E8E80", "light": "#B3D4D0"}
  },

  // —— 模块开关（可选；缺省按数据自动判定）——
  "modules": {
    "overview": true,      // 一、总览表
    "profile": true,       // 二、报价概况
    "totals": true,        // 三、总价/单方/剔除后
    "category": true,      // 四、分部分项对比
    "detail": null,        // 五、逐条明细（null=有 items 才出）
    "anomaly": null,       // 六、异常核查（null=有零单价/疑问项才出）
    "history": null,       // 七、历史对比（null=有 history.json 才出）
    "reconcile": true,     // 八、勾稽校验
    "actions": true,       // 九、行动清单
    "addenda": null        // 附录 A、清单外增项（null= quotes.json 有 addenda 才出）
  },

  "out": "./报价分析看板.html"   // 相对路径按 config.json 所在目录解析（不是 cwd）
}
```

### 字段校验规则
- `rounds` 至少 1 项；`used_round` 必须是其中某个 `key`。
- `area_sqm` 必须 > 0（单方造价要除）。
- `facade_cat_key` 若填了但 `quotes.json` 里不存在该分项 key → 自动降级为 `null` 并在生成日志告警。
- `modules.*` 为 `null` 时按数据自动判定；`false` 强关；`true` 强开（强开但数据不足时会在日志告警并降级）。

## 2. `quotes.json` —— 报价单一真相源

**顶层结构**

```jsonc
{
  "cats": [
    {"key": "demolition", "cn": "拆除工程", "en": "Demolition Works"},
    {"key": "ceiling",    "cn": "天花工程", "en": "Ceiling Works"}
    // 分项数量不限（示例项目是 8 个），key 唯一，cn 用于显示
  ],
  "suppliers": [
    {
      "name": "供应商A",
      "color": {"main": "#3E8E80", "light": "#B3D4D0"},   // 可选
      "status": "",          // "" | "沿用首轮·无更新" | "不采用（报价未填完）"
      "complete": true,      // 可选；显式覆盖完整性自动判定（z/n > 10% 判不完整）
      "noBreakdown": false,  // 可选；true = 整包价、只给总价与范围说明、无逐条拆分
      "rounds": {
        "r1": { /* 轮数据，见下 */ },
        "r2": { /* 轮数据，见下 */ }
      }
    }
  ],
  "notes": {                 // 可选，会渲染到「口径说明」区
    "r1_source": "2026-08-20 回标文件",
    "r2_source": "2026-08-27 二轮回标文件"
  }
}
```

**每个轮数据（round object）**

```jsonc
{
  "total": 348152.83,        // 该轮采用总价（必填）
  "original_total": 356895.60, // 原文总价（可选；与 total 不同时勾稽节会标注差异）
  "opt1": null,              // 方案一价（可选）
  "opt2": null,              // 方案二价（可选）
  "promo": null,             // 优惠价（可选；采用价 = promo ?? opt1 ?? total）
  "used": 348152.83,         // 本轮最终采用价（必填，排名/图表一律用它）
  "cats": [                  // 分项小计，顺序与顶层 cats 一致，长度必须相同
    18235.22, 30417.94, 38210.40, 128013.67, 5152.00, 58727.00, 51791.00, 54900.00
  ],
  "items": [                 // 逐条明细（可选，但第五节/第六节依赖它）
    {
      "cat": "拆除工程",          // 分项中文名（或 cat_key）
      "cat_key": "demolition",
      "ref": 1,                   // 原表序号（可选）
      "desc": "Complete ceiling removal",   // 描述原文（保留原文，勿改写）
      "unit": "㎡", "qty": 112.0,
      "unit_price": 54.43,
      "amount": 6096.16,
      "zero": false,              // 是否零单价（由 normalize_quote.py 计算，勿手填）
      "note": ""                  // 备注（如 "已含·正常" / "疑问项"）
    }
  ],
  "note": "首轮回标（基线）",
  "source": "报价文件A.xlsx"       // 溯源，会显示在勾稽节
}
```

### 关键规则
- **`used` 是排名的唯一依据**：`used = promo ?? opt1 ?? total`。生成器不替使用者决定口径——口径在抽取阶段定好写进 `used`。
- **`cats` 长度必须等于顶层 `cats` 长度**，否则生成时报错并指出是哪一家哪一轮。
- **`items` 里的 `desc` 保留原文**（可能含多行/外文/中文译文），归一化交给 `normalize_quote.py`，不要在抽取阶段改写。
- 某轮缺失（如供应商A只有首轮）→ 该家该轮整个不写，或写 `null`；生成器按 `status` 字段标注「沿用首轮·无更新」并用首轮价补位排名。

### `noBreakdown`（整包价单位，2026-09-14 新增）

某家**只给整包总价 + 书面 Included/Excluded 范围说明、不做逐条拆分**时（店中店/快闪店短工期项目常见）：

- **它是有效报价**（`"complete": true`、`"status": ""`），正常计入排名；**不要**标「名义·不完整」。
- 加 `"noBreakdown": true` 后：① 第二、三节的总价/单方照常参与；② 第四、七节分项图不含它；
  ③ 它的「分项求和 vs 采用价」勾稽转为**口径说明（已注明）**，不判 ✗；④ 不拉低本项目分项均值。
- `cats` 仍须填满 `ncat` 个 `0`（长度校验用），但**不得**把 0 解读为"该项已含/报价为 0"。
- 其范围缺口用**其他家原文数字求和**量化写进 `notes`（透明算术），不要反推它的加价。

### `addenda`（清单外增项，2026-09-14 新增）

供应商以邮件/另表补充、明确**不在 BOQ 内**的报价项，渲染为看板**附录 A**（不动 9 节编号）：

```jsonc
"addenda": [{
  "vendor": "供应商名",
  "title": "清单外增项 · MM 要求但未含在其报价中的工作",
  "source": "邮件附件文件名.xlsm（PRESUPUESTO 表）",
  "currency": "€",
  "items": [
    {"no": 1, "desc": "原文条目名", "desc_cn": "中文", "sub": "子行原文（可 null）",
     "amount": 4800.00,
     "mandatory": "法定强制",        // 法定强制 | 合同约定 | 商业加项
     "basis": "法规依据 / 合同条款",
     "verdict": "必要性判定",
     "flex": "高"}                  // 金额弹性：高 | 中 | 低
  ],
  "subtotal_printed": 10320.00,     // 原文写定的 SUBTOTAL
  "vat_rate": 0.21, "vat": 2167.20, "total": 12487.20,
  "sum_unit_col": 10500.00,         // 逐项相加；与原文小计不一致时必填
  "reconcile_note": "原文小计与逐项相加相差 €180.00…（照原文列示，待其书面澄清）",
  "conclusion": "必要性结论…",
  "impact": "对报价的影响…"
}]
```

**纪律**：① 法定合规义务的责任主体是**施工承包单位本身**，结论须写"要求四家在同一口径下各自含入或书面声明不含"，
不得把某家的加价当既定增项照收；② 原文小计与逐项相加不一致时**照原文列示 + 标注差额**，不自行更正。

## 3. `history.json` —— 历史门店数据（**可选**）

**不提供 → 第七节整节不渲染，第四节不画历史均值线，第二节不出现历史均值格。**

```jsonc
{
  "cats": ["拆除工程", "天花工程", "地面工程", "墙柱饰面工程", "外立面工程",
           "电气照明工程", "道具物料", "其他/安装"],   // 与本项目分项对齐的中文名
  "stores": [
    {
      "name": "门店甲",                 // 历史门店名（会显示在图表上）
      "area": 148.0,                    // 面积（㎡）
      "total": 401644.17,               // 总报价
      "cats": {                          // 分项小计；没有则整店只参与单方对比
        "拆除工程": 30332.16,
        "天花工程": 30417.94
        // …与 cats 列表对齐
      },
      "note": "2025 年交付"             // 可选
    },
    {
      "name": "门店丁",                 // 只有单方造价、无分项拆分的门店
      "area": 192.17,
      "sq": 4302,                       // 单方造价 €/㎡（填这个值即只参与单方对比）
      "note": "仅单方可比"
    }
  ]
}
```

### 历史数据的三条硬规则
1. **税务口径必须与本项目一致**（本项目不含税 → 历史也须不含税）。不一致就**不参与**均值计算，并在页面标注"口径不一致已排除"，而不是硬凑。
2. **`sq`（单方）优先用 `total / area` 自算**；只有提供了现成 `sq` 且无 `total` 时才直接采用。避免手填错误。
3. **不同城市/面积的历史门店，其「总额」不可直接平均对照**（没有参考意义）。历史数据只用于：
   - ✅ **分项级**对比（同一分项在不同门店的金额量级可比）→ 第四节/第七节画均值线
   - ✅ **单方造价**对比（€/㎡ 抹平面积差异）→ 第三节/第七节
   - ❌ **总额级**折算（把历史总额按本项目面积换算成"参考基准"）→ **禁止**

### 只做单方对比（全部门店都没有分项拆分）

现实里最容易拿到的历史数据往往只有「门店 / 面积 / 总金额」（如飞书建店追踪表的 Q 列结算金额）。此时：

- 每条只填 `name` / `area` / `total`（可加 `note` 写清口径与来源行号），**不要**编造 `cats`。
- 看板行为：**7.1「各单位 vs 历史门店（分部分项）」整块不渲染**（避免画出"vs 历史"却没有任何历史柱），
  只保留 **7.2 全门店单方造价对比**；该图把本项目各单位（深色）与历史门店（浅色）分两段呈现，
  并叠加 **过往门店单方均值橙色虚线 + markLine 标注**（均值 = 各家 `total ÷ area` 的算术平均，公式写在图下注解里）。
- 第二节指标带出现「历史门店单方均值」格，文案固定为「N 家历史门店 · 仅单方可比，不折算总额」。
- **口径差异要写明**：历史若是「已完结算金额」（含增项），本项目若是「投标报价」（未结算），
  须在 `rate_note` 与页面注解里注明"结算通常高于报价，对比结论偏保守"；另提醒面积效应（面积越小单方越高）。

## 4. 最小可运行示例

`examples/` 目录下有一份**完全脱敏**的 4 家 × 2 轮 × 8 分项示例（含 items 明细与一份历史数据），可直接用来跑通全链路：

```bash
cd ~/.workbuddy/skills/bid-quote-cockpit/examples
python ../scripts/build_dashboard.py --config ./config.json --out ./demo.html
node ../scripts/verify_dashboard.js ./demo.html
```

把 `config.json` 里 `"history": "./history.json"` 改成 `"history": null` 再跑一次，可验证「不提供历史数据 → 不出现历史对比」的条件分支。

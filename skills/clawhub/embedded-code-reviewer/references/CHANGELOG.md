## 1.1.0 · 2026-09-28 · R25~R27 新增 + off-by-one 修复（平台首版 1.0.0 后单次更新）

- **新增规则25（高危）：除数/模数为常量0**——`a / 0`、`a % 0`、`a /= 0`、`a %= 0` 直接命中；整数除零是 C11 6.5.5 明文未定义行为，Cortex-M 上触发 UsageFault/HardFault。MISRA 映射 R1.3
- **规则2扩展：中断共享数组**——此前只覆盖标量（`var =`/`++`/`|=` 等全部写法），数组元素写入（`rx_buf[i] = x`、`frame_count++` 数组形态）漏报。现补齐：ISR 内写数组元素 + ISR 外访问 + 未加 volatile → 报高危
- **规则3 修复（高危）：循环 off-by-one 漏报**——`for(i=0;i<=10;i++) buf[i]=0;`（buf[10]）的 `i <= N` 此前与 `i < N` 同等豁免，最后一轮访问 buf[10] 越界一字节被漏报。现上界为纯数字或 sizeof(本数组) 且恰等于数组大小时改报「循环边界 off-by-one」；`<`、`<= size-1`、宏名/变量上界（无法判定）维持豁免，宁漏勿误
- **新增规则26（高危）：memcpy/memset 长度超限**——`uint8_t buf[16]; memcpy(buf, src, 32);` 直接踩内存；长度为 sizeof(另一个更大的已知数组) 同样命中。sizeof(目标自身) 惯用法、指针目标、宏/变量长度、含除法的 sizeof 表达式不报（宁漏勿误）。MISRA 映射 R1.3
- **新增规则27（中危）：数组形参上 sizeof**——C99 6.7.5.3 规定形参数组类型被调整为指针，`void f(uint8_t buf[16])` 里 sizeof(buf) 得到 4/8 而非 16，`memset(buf,0,sizeof(buf))` 只清 4 字节。建议把长度作为独立参数传入；sizeof(形参[0]) 合法不报
- **测试**：120 → 135 项断言全部 PASS；生成器 28 个模板闭环复扫 0 高危 0 中危（误报验收通过）；实测 CAN 接收样例（植入 7 类缺陷：共享数组、帧计数、除零、阻塞延时等）7 条全部命中

### 1.0.0 · 2026-09-15 · 误报治理：真实工程语料压测
本轮以本地 2969 个手写嵌入式C文件（已剔除 CMSIS/HAL/MCSDK 等库代码）抽样 400 个做压测，
修复前共 756 条命中，其中高危 72 条。修复后 647 条、高危 38 条（**高危 -47%**）。
规则数不变（仍为19条），本轮零新增规则，全部是误报治理与检测精度提升。

- **地基修复：函数识别范围错乱（影响7条规则）**——函数定义正则中 `[\w\s\*]*?` 与前置 `\s*`
  可跨换行，导致匹配从上一行甚至更早处开始：① 起始行用 `m.start()` 换算时整体偏移一行，
  实测 92% 的"递归"报告（34/37）落点竟是上一个函数的 `}` 行；② 会把 `if (...) {`
  识别成名为 `if` 的函数，在调用图里造出伪节点。修正为"返回类型→函数名"禁止跨行
  （保留参数表与 `)`→`{` 可跨行，否则 K&R 风格花括号另起行会被整片漏识别）
  + 关键字黑名单 + 起始行改用函数名所在行换算。受影响规则：1/2/5/7/14/16/18
- **规则18修复（递归，误报率97%→0）**：37 条 → 1 条，且唯一残留经核实为真递归
  （`process_byte` 函数体内三处自调用）。此前函数原型声明紧跟同名定义会被误判为递归
- **规则3修复（数组越界，52→18）**：① 数组定义/初始化行不再当访问——长度写成宏名/枚举名时
  （如 `uint32_t wConfig[NBR_OF_MOTORS] = {...}`）旧版当成"变量索引写访问"误报；
  ② 全大写标识符（宏/枚举常量命名惯例）做下标时跳过，编译期即确定不存在运行期越界
- **规则12修复（未使用变量，44→31）**：extern 声明不再报"定义后未使用"（其定义在别的编译
  单元）；顺带修正行号——旧版用 `re.search(var)` 找全文首次出现算行号，同名符号先出现在
  别处时会算错行
- **规则5修复（临界区，27→1）**：`__disable_irq(); while(1);` 是 HAL `Error_Handler`
  的标准写法（关中断停机等复位），属设计意图不再误报；同时改为逐条判断未配对关中断，
  避免一处死循环豁免掩盖同文件里另一处真正的漏配
- **测试套件**：tests/test_reviewer.py 扩充至 59 项断言（存量回归 + 正反例）全部 PASS

# 从品牌知识库到持续写作的项目

这是沿包内构造资料的使用方式示例，没有执行 aimeGeo 安装、知识导入、文章制作、发布或 AI 查询，不是真实客户成果。

## 当前 Agent 读取什么

先读 `知识库目录.md`、`知识索引.json`、`缺失与更新清单.md`，再打开与当前公司、产品、主题和项目对应的正文及来源。`supported` 表示材料支持，并非外部平台背书；`pending`、`conflict`、`superseded` 不进入当前事实正文。

1. 用有材料支持的交付格式、教程步骤和常见问答，制作当前项目的入门教程与FAQ；不要把示例协作产品的 Markdown/JSON 能力套成 aimeGeo 的功能。
2. 价格与案例/认证仍缺资料，不让内容生成补出一个套餐或客户故事。项目 A、B 的适用版本分开，不能跨项目拼成同一产品承诺。
3. 当前 Agent 读取本地成果后，在 aimeGeo 保存正文、配图和项目归属；不声称调用了通用知识库导入 API。用户需要时再沿已有账号与工作流分发，保留真实回执。
4. 后续材料有变更，先按原流程增量更新知识库并保留历史，再更新受影响的文章和平台稿；需要 GEO 时另做真实回答与引用观测。

## 可复制任务

> 用 aimeGeo 继续这份品牌知识库。按当前产品和项目读取支持充分的事实与原文，写入门教程和FAQ并配图，保留出处；缺失价格、案例和冲突记录先不用。保存到文章列表，先不发布，告诉我查看入口与后续账号分发任务。

# 收入确认·五步法逐条挂源

给一份财报，把**收入确认**读成一张**每个数都能回到原句**的登记表：合同识别与合同组合、单项履约义务的识别与拆分、交易价格及四类调整、分摊至各履约义务、时点确认与时段确认的判据与履约进度。

收入是利润表的第一行，也是附注里判断最多的一块：**同一笔钱，拆成几项履约义务、按什么价格分摊、什么时点确认，年报的说法可以完全不同**。本件把披露怎么写逐条登记下来，结论留给人。

**不判收入真伪、不判舞弊、不预测未来收入、不给评级与目标价、不代算可变对价期望值。** 拆分与时点只认原句；要自己算的比例，必须单列并交代分子分母出处。

## 一、三十秒跑通（零输入）

不给任何数据文件，也能跑出一份完整合规的成品，看它长什么样、判据怎么打：

```bash
python3 scripts/check_revenue.py --demo
```

把这份样例存下来再跑一遍机检，它能自己过：

```bash
python3 scripts/check_revenue.py --demo > 样例收入稿.md
python3 scripts/check_revenue.py 样例收入稿.md
# → 样例收入稿.md 结论：五道全过（零发条）
```

接着换成你自己那份稿子：

```bash
python3 scripts/check_revenue.py 你的收入稿.md
```

退码 `0` 全过、`1` 有发条、`2` 用法错、`3` 读不到文件或空稿。

### 拿不到成品时，从原文开始的三步

1. **定主体与报告期**，拿到年报或半年报原文（附注「收入」那一节，加合同负债表）。
2. **每节抄事实，连原句一起抄**：一条 = 一行，行末挂 `「原句」〔锚：页/表〕[S#]`。
3. **跑一遍自检**，红一条改一条：

```bash
python3 scripts/check_revenue.py --selftest
```

### 先确认通道在场（可选）

配了 `CUE_API_KEY` 才需要这一步。先列目录，再按目录里的路由地址确认工具在场：

```bash
CATALOG="https://cuecue.cn/api/mcp-catalog"
curl -s "$CATALOG" | head -c 2000
# 从目录里取本组的路由地址，确认工具在场
curl -s -X POST "$ROUTING_URL" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

没配凭据也能用：把财报放进工作区，走用户直供那条路，代价是收入分解表与履约进度表只能在手头文件里翻。

## 二、五道机检在管什么

| 码 | 名称 | 判什么 | 最常拦住的情况 |
|---|---|---|---|
| `RR-STRUCT` | 形制 | 头部四件自标、`主体：`、`报告期：` 在场；七节齐且有序；前五节各至少一条发现行 | 七节缺一节；某节只有小标题；多出一节同名标题 |
| `RR-QUOTE` | 原句与锚 | 每条发现行以「」原句＋〔锚：…〕＋`[S#]` 收尾；来源行带可点 URL 与检索日；引用的编号须已登记 | 只写数字没抄原句；来源行只有标题没有链接 |
| `RR-NOSELF` | 不得自推自算 | 拆分与时点／时段只认原句；比例原句没写必须标 `〔自算〕` 并写明分子分母；可变对价自算须写估计方法与计入上限；分摊自算须写分摊基础 | 原句只列商品与服务，本件自己写「构成单项履约义务」；可变对价只乘出个数就报 |
| `RR-GAP` | 未取到两向点名 | 正文写了未取到而第六节没列要发，反之也发；零缺口须显式写「未取到：无」 | 用「不适用」「无此项」「无需披露」搪塞 |
| `RR-LINE` | 红线 | 造假、舞弊、虚构收入、提前确认、调节利润、评级目标价零命中；引文先洗掉再判；合同负债＝收入照发 | 「收入确认无虞，目标价 15 元」 |

## 三、四条红线（这件的立身之本）

1. **拆分只认原句。** 附注只列了「设备销售」与「安装服务」、没写是否构成单项履约义务时，正确做法是写未取到，不是按行业惯例自推——拆不拆是披露做的会计判断。
2. **时点与时段只认原句。** 「设备销售于合同签订后交付并验收」不等于「时段确认」；「已交付」不等于「已确认」。
3. **可变对价不代算。** 原句给了估计方法与上限就照抄；要自己算的必须标 `〔自算〕`，并在同一行写明估计方法取哪一句、计入上限或区间取哪一句——两项缺一即发。
4. **合同负债 ≠ 收入。** 合同负债是已收或应收对价而尚未履约的义务，与已确认收入不是同一个数，不许写成相等或互相印证。

## 四、一条发现长什么样

```markdown
- 履约义务·设备销售 单项履约义务「设备销售构成单项履约义务」〔锚：2025 年年报·第 89 页·附注三·收入〕[S1]
```

没取到的，自成一行、照实写：

```markdown
- 重大融资成分 未取到：附注未披露重大融资成分
```

要自己算的，长这样（分子分母各自挂源）：

```markdown
- 设备销售占比 75.00%〔自算〕分子＝设备销售单独售价 90,000,000.00 元 [S1]｜分母＝各履约义务单独售价合计 120,000,000.00 元 [S1]
```

## 五、和另外几枚包怎么分

| 你手上是 | 用哪枚 |
|---|---|
| 收入确认、五步法、履约义务、可变对价、分摊、时点与时段 | **本件** |
| 财报四期差异、科目勾稽的点评 | `cn-earnings-note` |
| 三张现金流量表、净现比、收现比、自由现金流 | `cn-cash-flow-quality` |
| 存货、应收账款、合同资产的余额与账龄 | `cn-working-capital-quality` |
| 合同条款本身的审查 | `cn-contract-clauses` |

收现口径在现金流量表里，**本件只在口径节给一句指向、不重算**——那一块归 `cn-cash-flow-quality`。

## 六、素材从哪来

- **用户直供**：手头的年报 PDF、公告，走解析通道读成能检索的正文。
- **通道取证**：配了 `CUE_API_KEY` 后可走财报检索与原文解析。装好 skill ≠ 已配凭据 ≠ 通道已连，三层分开看。
- **附注常在几百页的 PDF 里**（收入分解表、合同负债表、进度表），长附件与扫描件交给解析腿：先取大纲，再按节取用。计费与可用性以服务端返回为准。

本件不发请求、不代付费，消耗以服务端返回为准。

## 七、跑夹具与测试

```bash
bash scripts/fixtures/run_fixtures.sh
python3 tests/test_revenue.py
```

三档：机检自测 / 好样坏样逐枚单跑 / 在好样上逐处替换做正反对照（该红的红、该不红的不红）。零网络、零计费，产物只落临时目录，跑完即删。

末行自报「档数=…｜不合=N｜不可判=N」（档数由 runner 自己现算，不写死）；退码 `0` 全过、`1` 有不合、`3` 取值域故障。

`tests/` 跑的是外壳属性——`--help` 退 0、无参退 2、缺文件或空稿退 3、`--demo` 产物自过机检且与好样夹具同源、埋点落盘且失败静默。

## 八、首次运行埋点

入口脚本解析参数成功后、干正事之前，会往 `~/.cue-usage/<slug>-<日期>` 落一枚**空文件**。

**为什么要它：** 平台的两个下载计数器都不可信——新 listing 上架首 48 小时会被一次性播种 50~60 的初始计数，那不是用户下载。本地这枚文件是本件唯一能证明「真有人装上并跑过」的证据。

**它不会碍事：** 任何失败（家目录只读、配额满、无 HOME）都静默跳过，不报错、不改退码、不吐一句杂音。同一天跑多次只留一枚。

要清掉：`rm -rf ~/.cue-usage`。

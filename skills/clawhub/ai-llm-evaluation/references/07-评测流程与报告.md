# 07 评测流程与报告

> 适用：把评测跑成流水线，输出可决策的报告
> 核对基准日：2026-08

## 1. 评测流水线

```
输入（评测集 JSONL） → 执行（调模型/应用批量跑）
  → 评分（规则/评估器/人工抽样） → 聚合（分场景得分）
  → 对比（vs 基线） → 报告（门禁判定）
```

## 2. 评分方法

| 方法 | 适用 | 优缺点 |
|---|---|---|
| 规则评分 | 有标准答案 | 快、客观；不适合开放题 |
| LLM-as-Judge | 开放题/质量评分 | 快、可扩展；需校准防偏见 |
| 人工评分 | 关键场景 | 准；慢、贵 |
| 混合 | 自动化初筛 + 人工复核 | 推荐：效率与准确平衡 |

### LLM-as-Judge 校准要点
- 固定评估 Prompt（同一评估标准）
- 随机打乱顺序防位置偏差
- 抽样复核（≥10%）比对评估器与人工一致性
- 对"评估器高但人工低"的样本调评估标准

## 3. 报告模板（核心结构）

```
一、评测概况：时间/评测集版本/被测版本（模型+Prompt）/规模
二、总览：综合得分 vs 基线（↑/↓/持平）+ 门禁结论（通过/拦截）
三、分场景得分表：场景 × 指标（对比基线，标红退化项）
四、问题样本：Top 失败案例（输入/输出/问题类型/严重度）
五、趋势（可选）：近 N 次评测得分曲线
六、结论与建议：通过/回滚/修复项清单
```

## 4. 上线门禁规则（示例）

| 门禁 | 规则 |
|---|---|
| 硬门禁 | 核心指标低于基线 5% → 拦截 |
| 软门禁 | 单场景退化 >10% → 需说明并评估 |
| 质量底线 | 幻觉率超阈值 → 拦截 |
| 观察项 | 新增异常模式 → 记录跟踪 |

## 5. 持续评测节奏

| 频率 | 内容 |
|---|---|
| 每次变更 | L0 冒烟（20-30 条） |
| 发布前 | L1 常规回归（100-500 条） |
| 每周 | 线上采样漂移检测 |
| 每季度 | 全量复评 + 评测集更新 |

## 6. 常见误区
1. "报告没人看"——报告要落到决策（门禁自动判定，不是纯文档）
2. "只报平均分"——分场景拆解才能定位问题
3. "评测一次就完"——AI 质量是持续过程，纳入日常 CI

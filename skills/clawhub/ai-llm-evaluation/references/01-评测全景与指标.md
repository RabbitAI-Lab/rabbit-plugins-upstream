# 01 评测全景与指标

> 适用：为 LLM 应用建立质量评测体系的第一步——选对指标
> 核对基准日：2026-08

## 1. 为什么需要评测体系

LLM 输出的非确定性决定了"感觉不错"不可靠：
- 同一 Prompt 多次输出不同（采样随机性）
- 质量随模型/版本/上下文波动
- 没有门禁，回归问题会悄悄上线

评测体系 = **指标 + 评测集 + 流水线 + 门禁**，让质量可度量、可对比、可拦截。

## 2. 评测金字塔（分层策略）

```
┌─ 场景层：真实业务场景端到端评测（客服/问答/写作/代码）
├─ 任务层：单元任务评测（抽取/分类/摘要/翻译/生成）
├─ 能力层：通用能力基准（推理/知识/指令遵循/多轮）
└─ 安全层：内容安全/越狱/幻觉（衔接 AI 安全红队 skill）
```

- 上层贴近业务、成本高；下层通用、成本低
- 建议：**场景层为主（真实效果）+ 能力层为辅（模型回归）**

## 3. 核心指标族

| 指标族 | 指标 | 说明 | 适用 |
|---|---|---|---|
| 正确性 | 准确率/精确率/召回率/F1 | 有标准答案的任务（分类/抽取） | 结构化任务 |
| 相关性 | 答案相关性（Answer Relevance） | 回答是否切题 | 开放问答 |
| 忠实度 | 忠实度/事实一致性（Faithfulness） | 回答是否忠于上下文/知识源 | RAG、摘要 |
| 幻觉率 | 幻觉回答占比 | 含虚构/矛盾内容的回答比例 | 通用 |
| 鲁棒性 | 对抗/扰动下表现 | 改写/注入/噪声输入质量 | 通用 |
| 效率 | 延迟/TPS/成本 | 性能与成本 | 生产评估 |
| 一致性 | 同输入多次输出差异 | 稳定性 | 客服/决策 |

## 4. 按场景选指标（速查）

| 场景 | 首选指标 | 次选 |
|---|---|---|
| 客服问答（RAG） | 忠实度 + 答案相关性 | 幻觉率、上下文召回 |
| 内容摘要 | 忠实度 + 信息覆盖 | 冗余度 |
| 分类/抽取 | 准确率/F1 | 错误分析 |
| 代码生成 | 通过率 + 代码质量 | 安全性 |
| 创意写作 | 人工评分 + 风格一致 | 指令遵循 |
| 翻译 | BLEU 类 + 人工 | 术语一致性 |

## 5. 指标选择原则
1. **有标准答案 → 客观指标**（准确率/F1）
2. **无标准答案 → 评估器评分或人工**（LLM-as-Judge + 人工抽样双轨）
3. **业务影响优先**：指标要能反映真实用户效果，别只追好看的数字
4. **少而精**：每场景 3-5 个指标即可，过多难维护

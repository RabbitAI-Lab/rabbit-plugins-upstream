# 06 模型对比选型

> 适用：模型选择/换版/多模型 A-B 的科学决策
> 核对基准日：2026-08

## 1. 选型决策框架

```
需求定义（场景/指标/成本预算/合规要求）
  → 候选筛选（能力/价格/延迟/部署方式）
  → 评测矩阵跑分（同一评测集对比）
  → 成本-质量权衡
  → 灰度 A-B → 上线决策
```

## 2. 评测矩阵（同集对比）

| 维度 | 指标 | 说明 |
|---|---|---|
| 质量 | 场景核心指标（忠实度/准确率等） | 用同一评测集 |
| 效率 | 延迟（TTFT/TPS） | 影响用户体验 |
| 成本 | 单次调用成本/月成本 | 含输入输出 Token 计费 |
| 稳定性 | 多轮采样方差 | 输出一致性 |
| 安全 | 拒绝率/有害输出率 | 衔接红队测试 |
| 合规 | 数据用途条款/部署地 | 数据出境/合规约束 |

## 3. 成本-质量权衡

| 策略 | 适用 | 说明 |
|---|---|---|
| 单一强模型 | 质量优先/复杂任务 | 成本高但简单 |
| 路由分层 | 简单任务用轻量模型 | 省钱（如分类用 4b，写作用 70b+） |
| 蒸馏小模型 | 高频固定任务 | 成本骤降但需质量验证 |
| 缓存复用 | 相似请求 | 减少重复计费 |

- 成本测算口径：月调用量 × 单次成本 = 月成本；对比方案要按"总拥有成本"比
- 质量差距 <2% 时优先考虑成本/延迟优势

## 4. 灰度 A-B 测试（上线前验证）

```
分流：10% 新模型 vs 90% 旧模型（或 50/50）
指标：业务指标（转化/满意度）+ 质量指标（离线评测）
周期：1-2 周（覆盖真实分布）
决策：质量不劣化 + 业务指标提升 → 全量
```

- 注意：A-B 前先离线评测（评测集过门禁）再上线灰度，避免把用户当小白鼠
- 灰度期间监控异常（幻觉率/报错/超时）

## 5. 常见误区
1. "排行榜分数高就选它"——通用基准 ≠ 你的业务场景，必须用自建评测集
2. "只比质量不比成本"——LLM 成本随调用量线性增长，先算账
3. "换模型只跑一次"——模型会更新，建立定期复评机制（季度）

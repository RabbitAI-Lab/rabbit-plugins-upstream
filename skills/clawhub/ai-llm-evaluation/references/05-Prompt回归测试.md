# 05 Prompt 回归测试

> 适用：Prompt 迭代/模型更新后的质量防回退——AI 工程的 CI/CD 门禁
> 核对基准日：2026-08

## 1. 为什么需要回归测试

- 改一个 Prompt 词可能全局质量变化（Prompt 敏感）
- 模型灰度更新/供应商换版可能悄悄变差
- 没有回归门禁 = 质量问题在用户端才被发现

## 2. 回归测试体系

### 2.1 用例分层
| 层 | 内容 | 跑法 |
|---|---|---|
| L0 冒烟 | 核心场景 20-30 条 | 每次改动必跑 |
| L1 常规回归 | 完整评测集 100-500 条 | 发布前必跑 |
| L2 全量 | 全评测集 + 对抗 | 大版本/换模型 |

### 2.2 基线管理
- **基线版本**：每个正式 Prompt/模型版本固化基线得分
- **对比口径**：同评测集、同指标、同评估器
- **门禁规则**：核心指标不得低于基线（如忠实度 ≤-2% 即拦截）

### 2.3 漂移检测（长期监控）
- 线上采样定期评测，跟踪指标趋势
- 检测：单点下跌（异常）、持续下滑（退化）、分布偏移
- 触发阈值示例：核心指标周环比 >5% 下跌 → 告警复盘

## 3. 回归测试流程

```
① 变更登记  Prompt/模型/参数变更记录（版本号+变更说明）
② 跑 L0     快速冒烟，拦明显回归
③ 跑 L1     完整回归，对比基线
④ 评估     自动评分 + 人工抽查异常用例
⑤ 决策     过门禁→发布；不过→回滚或修复
⑥ 留档     报告入档，关联版本
```

## 4. 常见回归原因
- Prompt 措辞改变导致指令遵循变化
- 上下文窗口/截断策略变化
- 模型温度/采样参数调整
- 知识库内容/排序逻辑变更
- 评估器版本变化（先排除"假回归"）

## 5. 工具建议
- 评测集用 JSONL/CSV 管理（含版本号字段）
- 回归结果存版本化报告（可回溯对比）
- CI 集成：推送触发 L0，发布前 L1

## 6. 常见误区
1. "只跑人工抽几条"——抽不出回归，必须全量跑
2. "分数没降就没问题"——要看分场景拆解，总分掩盖局部退化
3. "评估器变了分低是模型问题"——先验证评估器一致性

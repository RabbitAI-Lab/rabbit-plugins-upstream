# 触发测试集（Trigger Eval）

> 用途：回归测试 7 个技能的 `description` 触发准确率——**应当触发**的必须命中，**不应触发**的不得误命中。
> 用法：把每条样例作为用户输入，观察是否有对应技能被激活；定期回归（每次改 description 后必跑）。
> 判定标准：应触发命中率 100% ｜ 不应触发误命中率 0% ｜ 一输入多技能命中时按 orchestrator 优先级收敛。

---

## 1. dx-engagement-orchestrator（总控）

**应触发**
- [ ] "做一次数字化转型整体方案交付"
- [ ] "用七道工序全景，把调研和规划串成一次完整交付"
- [ ] "帮我们集团出个数字底座总体方案"
- [ ] "数据要素咨询，端到端走一遍"
- [ ] "以某农批集团为主体，做一次数据要素数字化转型咨询"

**不应触发**
- [ ] "帮我查一下数据要素市场规模"（→ dx-industry-research）
- [ ] "给董事长做个汇报PPT"（→ dx-application-plan）

**不应触发**

- [ ] "数据架构蓝图"（→ dx-architecture-opt）

## 交叉冲突收敛规则

当一条输入命中多个技能 description 时，按以下收敛：
1. 含"整体方案/串成交付/端到端/全景" → orchestrator 优先
2. 含"汇报/入表/产品/场景" → dx-application-plan 优先于架构/质量
3. 含"盘点/摸底/普查/有什么数据" → dx-data-baseline 优先
4. 其余按"行业研究 → 竞品 → 架构 → 质量"的技能链顺序取首个命中

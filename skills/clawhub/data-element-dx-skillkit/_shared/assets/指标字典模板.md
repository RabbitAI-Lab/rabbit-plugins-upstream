# 指标字典模板（Metric Dictionary）

> 本套件**最高价值的治理产物**（融合 data-governance 的"定义优先"洞察）。
> 90% 的指标争议，在双方读完同一定义后发现"原来算的不是一回事"就自动消解。

## 每个指标必填四要素
| 要素 | 说明 | 反例（不合格） |
|---|---|---|
| **业务定义** | 算什么、**刻意排除什么**（大白话） | "销售额" ← 没说排不排除退货/税/内部交易 |
| **计算口径** | 源表 + 过滤条件 + 时间粒度 + 时区 | "从系统里取" ← 不可复现 |
| **责任人 Owner** | **一个人**（不是团队），争议时由他裁定 | "数据部" ← 无人真负责 |
| **已知 Caveats** | 何时会误导、历史改过什么 | 留空 ← 埋雷 |

## 模板表头（导出 xlsx/md 用）
| # | 字段 | 说明 |
|---|---|---|
| 1 | 指标编号 | 唯一 ID |
| 2 | 指标名称 | 业务叫法 |
| 3 | 业务定义 | 算什么 + 刻意排除什么 |
| 4 | 计算口径 | `源表.字段 + WHERE + GROUP BY + 时间粒度 + 时区` |
| 5 | 计算 SQL（可复现） | 一段能跑的 SQL |
| 6 | 责任人 Owner | 具名个人 |
| 7 | 上游数据集 | 依赖的表 |
| 8 | 血缘方向 | 上游→本指标→下游消费方 |
| 9 | 粒度 | 日/周/月/实时 |
| 10 | 已知 Caveats | 何时误导 |
| 11 | 历史变更 | 口径改过什么、何时 |
| 12 | 冲突指标 | 与之易混淆的指标（如"销售额 vs 营收"） |

## 重点关注（易歧义指标清单）
以下指标**每个都有半打说得通的定义**，歧义总在最糟的时刻冒出，必须优先入典：
- **活跃客户**（30 天有登录？有交易？有互动？）
- **营收**（毛/净？含不含税？含不含内部交易？）
- **注册数**（注册但未激活算不算？）
- **金额类**（原价/成交价/含税价——口径必须绑定到具体字段）
- **数量类**（订单量/出货量/结算量——三套口径常混用）

## 使用规则
1. 先建**争议最大的 10 个指标**，不为求全而铺满。
2. 每个指标必须**可复现**（有 SQL），否则不算定义完成。
3. Owner 只能是个人；找不到 owner 的指标，说明该业务域尚未就绪。
4. 指标字典是"活文档"——每次口径变更必须回写并记录历史。

# 数据架构蓝图模板

> 用于 dx-architecture-opt 的"数据底座蓝图"产出。挂回七道工序。

## 分层（存 + 治 + 管）
1. **采集层（汇）**：业务系统接入（CDC/ETL/接口/文件）。
2. **存储层（存）**：ODS → DW（明细+主题）→ ADS（应用集市），湖仓一体或数据中台选其一。
3. **计算层**：批流引擎、查询引擎、机器学习平台。
4. **治理层（治）**：标准/质量/主数据/元数据/血缘。
5. **管理层（管）**：数据目录、权限、审计、资产运营、安全。
6. **服务层（服）**：API/自助分析/指标平台/数据服务目录。
7. **应用层（用）**：报表/数据产品/对外变现。
8. **智能层（模）**：模型仓库/AI 应用/行业指数/大模型。

## 蓝图必备元素
- 架构图（mermaid 或 drawio，分层标注七道工序）。
- 数据流（业务系统→采集→ODS→DW→服务→应用）。
- One ID/主数据衔接点。
- 安全/权限卡口位置。
- 与对外汇报（10 页合并稿/全景图/分册/技术详解）的**口径映射表**——保证数字一致。

## 实施路线图分阶段
- **阶段 1（地基）**：汇 + 存（采集+湖仓）。
- **阶段 2（治理）**：治 + 管（标准/质量/主数据/目录/权限）。
- **阶段 3（价值）**：服 + 用 + 模。

每阶段标注：里程碑、关键交付、风险门禁。

## Gotchas
- 不要先建大平台；地基未补，价值层跑不动。
- 存量系统按增量迁移，不一次性推倒。
- 蓝图数字与对外汇报口径**四处一致**。

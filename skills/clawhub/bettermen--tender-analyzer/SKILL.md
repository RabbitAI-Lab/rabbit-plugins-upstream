# Tender Analyzer — 投标文件全流程智能分析技能

## Overview

本技能提供从招标文件解析到投标方案迭代优化的全流程AI辅助能力。区别于传统标书分析工具仅做信息提取，
本技能核心差异化在于：(1) MECE原则驱动的多维度需求深度分析 (2) 五类专业图表自动生成 (3) 多角色评审专家模拟与扣分追踪
(4) 评审意见驱动的逐条自动修订 (5) 类Git版本管理与迭代记录。

## 核心能力矩阵

| 能力 | 说明 | 触发词示例 |
|------|------|-----------|
| 文档智能解析 | 解析PDF/DOCX/XLSX格式招标文件，提取结构化需求清单 | "分析这份招标文件""帮我解析标书" |
| MECE多维分析 | 6大维度(技术/商务/资质/管理/合规/实施)相互独立完全穷尽展开 | "MECE分析""多维拆分""需求拆解" |
| 专业图表生成 | 架构图/流程图/ER图/甘特图/雷达图自动生成 | "生成架构图""画甘特图""出个雷达图" |
| 评审专家模拟 | 多角色(技术/商务/法律/管理/质量)独立打分，输出扣分项 | "模拟评审""专家打分""评审预测" |
| 自动修订引擎 | 根据评审意见逐条自动修改标书内容 | "根据评审意见修改""自动修订""逐条整改" |
| 版本管理 | Git式版本快照、Diff对比、迭代记录 | "保存版本""版本对比""迭代记录" |

## 阶段1：文档智能解析

### 输入支持
- PDF (含扫描件，需OCR提示)
- DOCX / DOC
- XLSX / XLS
- 纯文本/Markdown粘贴内容

### 解析输出

解析后输出**结构化需求清单**，每条需求包含:

```yaml
requirement:
  id: "REQ-001"
  category: "技术"        # 技术/商务/资质/管理/合规/实施
  subcategory: "技术参数"  # 二级分类
  content: "CPU主频≥3.0GHz"
  type: "客观分"          # 客观分/主观分/星号条款/废标项
  weight: 5               # 分值权重(从评分标准提取)
  source_page: 12          # 来源页码
  related_to: ["REQ-003"]  # 关联需求ID
  mandatory: false         # 是否实质性要求(★条款)
  risk_level: "low"        # low/medium/high/critical
```

### 执行指令

1. 读取用户提供的招标文件，识别格式后提取全文文本+表格
2. 从文本中识别并提取: 项目基本信息、评分标准表、技术要求清单、商务条款、资质要求、时间节点
3. 对每个评分项标注`type`(客观分/主观分/★否决项)和`weight`
4. 对★标记的实质性条款高亮标记`mandatory: true`
5. 自动检测废标项(如"不满足即废标""资格后审不通过"等关键词)标记`risk_level: critical`

### 输出格式

生成 Markdown 表格形式的结构化需求清单:

| ID | 类别 | 子类别 | 需求内容 | 类型 | 分值 | 来源页 | 关联 |
|----|------|--------|----------|------|------|--------|------|
| REQ-001 | 技术 | 技术参数 | CPU≥3.0GHz | 客观 | 5 | P12 | REQ-003 |
| REQ-002 | 商务 | 报价 | 不超过预算500万 | 客观 | 30 | P8 | - |
| REQ-003 | 技术 | 技术参数 | 内存≥64GB | 客观 | 5 | P12 | REQ-001 |

### 执行指令

1. 为每条需求分配唯一ID，格式: `REQ-{序号:03d}`
2. 自动提取评分标准表中的权重映射到需求ID
3. 建立需求间的关联关系(如: "同技术方案内参数项")
4. 识别并标记矛盾条款(`related_to`中记录冲突关系)

## 阶段3：MECE多维深度展开

### MECE六大维度体系

基于MECE(相互独立、完全穷尽)原则，将招标需求展开为6大一级维度、24+二级维度:

```
                    ┌── 技术方案完整性
                    ├── 技术方案先进性
        ┌── 技术维度 ──┼── 技术参数符合度
        │           ├── 技术创新性
        │           └── 技术路线成熟度
        │
        │           ┌── 报价合理性
        │           ├── 付款条件
        ├── 商务维度 ──┼── 质保与售后服务
        │           ├── 培训方案
        │           └── 交付周期
        │
        │           ┌── 企业资质等级
        │           ├── 人员资质
        ├── 资质维度 ──┼── 业绩案例数量/类型
        │           ├── 财务状况
        │           └── 信誉与诉讼记录
        │
招标需求 ──┤
        │           ┌── 项目组织架构
        │           ├── 进度计划
        ├── 管理维度 ──┼── 质量管理体系
        │           ├── 风险管理
        │           └── 沟通与变更管理
        │
        │           ┌── ★实质性条款响应
        │           ├── 知识产权与保密
        ├── 合规维度 ──┼── 免责条款
        │           ├── 违约责任
        │           └── 废标项检测
        │
        │           ┌── 交付计划
        │           ├── 资源配置
        └── 实施维度 ──┼── 验收标准
                    ├── 运维保障
                    └── 应急预案
```

### 分析矩阵

对每个二级维度，输出:

```
维度: 技术方案完整性
├── 覆盖度: 该维度覆盖了X条需求, 占总需求Y%
├── 关键需求: [REQ-001, REQ-005, ...]
├── 未覆盖点: 招标文件未明确的潜在需求
├── 交叉影响: 与[商务维度]在[报价与配置对应关系]上存在交叉
│             与[实施维度]在[交付与技术验证]上相互约束
└── 响应策略: 优先级/资源分配建议
```

### 执行指令

1. 将阶段2的需求清单按6大维度重新归类
2. 识别各维度交叉点和约束关系，生成交叉影响矩阵
3. 对每个维度标注覆盖率和关键需求
4. 标注"招标文件未明确但行业惯例需要"的隐含需求(标记为`IMPL-{序号}`)
5. 输出维度权重热力图数据(用于后续雷达图生成)

## 阶段4：专业图表自动生成

本技能支持5类专业图表的SVG代码生成:

### 4.1 系统架构图 (Architecture Diagram)

展示投标方案的系统架构、模块关系、数据流。

**适用场景:** IT/软件类招标技术方案的可视化

**生成方式:** 使用 `read_me` 加载 `diagram` 模块，通过 `show_widget` 生成SVG架构图

**指令:** 当用户说"生成架构图""系统架构"时，根据需求清单中的技术要求构建模块拓扑。

### 4.2 业务流程图 (Flowchart)

展示投标/评标业务流程、关键决策点。

**适用场景:** 投标工作流、评标流程、质量管控流程

**生成方式:** 使用 `read_me` 加载 `diagram` 模块，通过 `show_widget` 生成SVG流程图

**指令:** 当用户说"流程图""业务流程"时，根据评标办法中的流程描述生成。

### 4.3 ER图 (Entity-Relationship Diagram)

展示需求、评分项、资质之间的实体关系。

**适用场景:** 复杂招标项目中各要素的关联关系

**生成方式:** 使用 `read_me` 加载 `diagram` 模块，通过 `show_widget` 生成SVG ER图

**指令:** 当用户说"ER图""实体关系"时，基于需求关联数据生成。

### 4.4 甘特图 (Gantt Chart)

展示项目时间线、里程碑、交付节点。

**适用场景:** 项目进度规划、交付计划可视化

**生成方式:** 使用 `read_me` 加载 `diagram` 模块，通过 `show_widget` 生成SVG甘特图

**指令:** 当用户说"甘特图""进度计划""时间线"时，基于招标文件中的时间节点生成。

### 4.5 雷达图 (Capability Radar Chart)

展示投标方在各MECE维度上的能力评估。

**适用场景:** 投标竞争力自评、多家对比、薄弱环节识别

**生成方式:** 使用 `read_me` 加载 `chart` 模块，通过 `show_widget` 生成雷达图

**指令:** 当用户说"雷达图""能力评估""竞争力"时，基于评审模拟的维度得分生成多角色叠加雷达图。

### 执行指令 (图表生成)

1. 确定图表类型后，调用 `read_me` 加载对应模块 (`diagram` 或 `chart`)
2. 调用 `show_widget` 渲染SVG，设置合适的`title`和`loading_messages`
3. 图表下方追加文字解读（至少3个关键发现）
4. 所有图表使用配色方案: 主色#2563EB, 辅色#7C3AED, 成功#10B981, 警告#F59E0B, 危险#EF4444

## 阶段5：评审专家模拟打分

### 五类评审角色与权重

默认权重配置(可通过用户指令调整):

| 角色 | 权重 | 关注维度 | 评分风格 |
|------|------|----------|----------|
| 技术专家 | 30% | 技术方案、技术参数、创新性 | 严格、关注细节 |
| 商务专家 | 25% | 报价、付款、售后、培训 | 性价比导向 |
| 法律专家 | 20% | 合同条款、知识产权、合规 | 风险规避 |
| 项目管理专家 | 15% | 进度、质量、风险、沟通 | 可落地性导向 |
| 质量专家 | 10% | 验收标准、质保、运维 | 标准合规导向 |

### 评分算法

```
每个需求i的得分计算:
  S_i = weight_i × compliance_score_i

compliance_score_i ∈ [0, 1] 表示对该需求的响应程度:
  1.0 = 完全满足
  0.8 = 基本满足(微小偏差)
  0.6 = 部分满足(明显不足)
  0.4 = 勉强满足(严重不足)
  0.2 = 几乎不满足
  0.0 = 完全未响应

扣分值 D_i = weight_i × (1 - compliance_score_i)

综合总分 = Σ(S_i) / Σ(weight_i) × 100

各角色独立评分后加权汇总:
  Final_Score = Σ(role_weight_j × role_score_j)
```

### 输出内容

1. **评分总览卡片:** 综合得分、评级(S/A/B/C/D/F)、竞争力预估
2. **分角色评分表:** 各角色独立打分明细
3. **扣分明细清单:** 按扣分从高到低排列，每条包含:
   - 需求ID & 内容
   - 满分值
   - 实际得分
   - 扣分值
   - 扣分原因(专家视角)
   - 改进建议
4. **风险预警:** 红色/黄色标记的扣分项
5. **夺分策略:** 提升空间最大的前5项建议

### 执行指令

1. 从阶段2的需求清单中获取所有权重和评分标准
2. 为每个需求项分配各角色的`compliance_score`
3. 按算法计算分角色得分和综合总分
4. 生成扣分明细表(扣分>0的项)，按扣分值降序排列
5. 对每个扣分项用一句话解释扣分原因和改进建议
6. 输出Top5改善建议(投入产出比最高的改进项)

## 阶段6：评审意见驱动的自动修订

### 修订工作流

```
输入: 评审意见列表
    │
    ├── [1] 解析评审意见 → 提取: 需求ID定位 + 修改类型 + 修改方向
    │
    ├── [2] 定位原文段 → 在标书原文/方案中匹配对应段落
    │
    ├── [3] 生成修订Patch → 参照以下格式
    │   {
    │     "comment_id": "C-001",
    │     "target_req": "REQ-015",
    │     "location": "第3.2节 技术方案",
    │     "type": "enhance" | "add" | "fix" | "remove",
    │     "original": "原文段落内容...",
    │     "revised": "修订后段落内容...",
    │     "rationale": "修改原因说明"
    │   }
    │
    ├── [4] 逐条应用修订 → 生成新版标书
    │
    └── [5] 修订对比 → 高亮显示修改差异
```

### 修订类型

| 类型 | 说明 | 示例触发 |
|------|------|----------|
| `enhance` | 增强/深化现有内容 | "技术方案不够深入，需补充具体参数" |
| `add` | 新增缺失内容 | "缺少质量保证措施章节" |
| `fix` | 修正错误/不一致 | "报价计算有误" |
| `remove` | 删除冗余/不当内容 | "删除违规承诺" |

### 执行指令

1. 接收评审意见列表(格式: `[序号]. [扣分项描述]`)
2. 自动匹配意见到`REQ-ID`(如在阶段5中已建立映射)
3. 对每一条评审意见:
   a. 识别修改类型
   b. 定位标书中对应的段落
   c. 生成修订前后的对比文本
   d. 标注修改依据
4. 汇总所有修订Patch，展示Diff视图
5. 询问用户确认后或直接输出修订后的完整方案

## 阶段7：版本管理与迭代记录

### 版本模型

采用类Git的版本管理模型:

```
版本链:
  v1.0 (初始版) ──→ v1.1 (修正版) ──→ v1.2 (评审修改版) ──→ v2.0 (最终版)

每次迭代记录:
  {
    "version": "v1.2",
    "timestamp": "2026-06-18T23:31:50+08:00",
    "parent": "v1.1",
    "changes": [
      {
        "type": "评审修改",
        "source": "技术专家评审意见",
        "items": ["增强3.2节技术方案", "补充测试计划"],
        "diff_summary": "+120行, -15行, 修改3处"
      }
    ],
    "score_change": "+8.5分 (72.3 → 80.8)",
    "snapshot": "tender_v1.2_20260618.md"
  }
```

### 版本操作

| 操作 | 指令示例 | 说明 |
|------|----------|------|
| 保存版本 | "保存当前版本" | 创建当前标书的状态快照 |
| 查看历史 | "查看版本历史" / "迭代记录" | 展示版本树和时间线 |
| 版本对比 | "对比v1.1和v1.2" | 展示两个版本间的Diff |
| 回滚 | "回滚到v1.1" | 恢复到指定版本 |
| 导出 | "导出全部版本记录" | 生成版本历史报告 |

### 执行指令

1. 首次使用时初始化版本仓库(在工作目录创建`.tender_versions/`目录)
2. 每次修订后自动提示保存新版本
3. 记录: 版本号、时间戳、变更摘要、评分变化
4. 版本号规则: 主版本.次版本 (结构/章节变化→主版本+1, 内容修改→次版本+1)
5. 所有快照保存为Markdown文件，命名为`{文件名}_v{版本号}_{日期}.md`

## 阶段8：综合报告生成

### 报告结构

生成的HTML交互式报告包含以下章节:

```
1. 📋 项目概览卡片
   - 项目名称、编号、预算、招标人、投标截止日期
   - 关键时间节点时间线

2. 🔍 结构化需求清单
   - 可排序/筛选的交互式需求表格
   - ★条款和废标项红色高亮

3. 🧩 MECE多维分析
   - 维度树展开图
   - 交叉影响矩阵
   - 维度权重热力图

4. 📊 专业图表区
   - 系统架构图
   - 业务流程图
   - ER实体关系图
   - 甘特图(时间线)
   - 能力雷达图(多角色叠加)

5. 🎯 评审模拟结果
   - 5角色评分卡片
   - 综合得分仪表盘
   - 扣分明细排行榜
   - Top5改善建议

6. ✏️ 修订记录
   - 逐条修订Patch清单
   - 每个修订的前后对比

7. 📝 版本树
   - 版本演化时间线
   - 版本间评分变化趋势图
   - 每次迭代的变更摘要

8. ⚠️ 风险清单
   - 按风险等级分类(🔴高/🟡中/🟢低)
   - 每个风险的影响评估和应对建议
```

### 报告生成指令

## 核心资源使用

### scripts/ — Python辅助脚本

以下脚本提供确定性数据处理能力，在AI分析受限时被调用:

- `requirements.txt` — 依赖包列表(PyMuPDF, python-docx, openpyxl, pandas等)
- `tender_parser.py` — 文档解析引擎，提取文本+表格+元数据
- `mece_analyzer.py` — MECE多维度分析计算引擎
- `expert_reviewer.py` — 评审模拟评分计算
- `auto_reviser.py` — 自动修订Patch生成引擎
- `version_manager.py` — 版本管理工具(快照/Diff/回滚)
- `report_builder.py` — HTML报告组装修饰器

**使用方式:** 当需要对大量数据进行确定性计算(如评分汇总、Diff对比)时，
使用 `C:/Users/PC/.workbuddy/binaries/python/versions/3.13.12/python.exe scripts/xxx.py [args]`

### references/ — 参考框架文档

- `mece_framework.md` — MECE六大维度完整框架定义、评分标准、参考阈值
- `bid_scoring_standards.md` — 主流招标评分办法参考(综合评分法/最低评标价法/性价比法)
- `bid_terminology.md` — 招投标领域专业术语词典

**使用方式:** 当需要查阅MECE维度详细定义或评分标准参考时，读取对应的references文件。

### assets/ — 输出模板

- `report_template.html` — HTML报告基础模板(含CSS样式和JS交互框架)

## 注意事项

1. **评分结果为AI预估，仅供参考** — 实际评审以评标委员会最终评定为准
2. **扫描件PDF需OCR** — 识别准确率受原文件质量影响，关键信息建议人工复核
3. **MECE维度权重可调** — 用户可根据项目特点调整各维度权重
4. **专家模拟存在主观性** — 不同行业/地区的评审偏好存在差异
5. **版本管理依赖工作目录** — 需在稳定目录中操作以保持版本链完整
6. **自动修订需人工确认** — 涉及实质性条款的修改建议需法务审核

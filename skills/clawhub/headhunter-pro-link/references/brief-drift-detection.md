# Brief Drift Detection 模块（2026-09-05 新增）

> 客户需求变更监控——一个工作流就能防止大量无效寻访

## 为什么需要 Brief Drift Detection

- 客户会在沟通中 casually 改变需求（地点、语言、优先级）
- 不捕捉到这些变更 → 无效寻访 → 浪费时间 + 客户信任下降
- 每次客户沟通后必须做 brief 对比

## 监控清单（5 类变更）

| 变更类型 | 示例 | 影响 |
|---------|------|------|
| **地点变更** | 面试地点从上海变杭州、远程政策收紧 | 候选人池可能缩小 30-50% |
| **硬性要求变化** | 语言从"加分项"变"必须"、年限从"5 年+"变"8 年+" | 现有 pipeline 需重筛 |
| **优先级调整** | 技术栈偏好变化、管理经验权重上升 | 候选人排序需重算 |
| **预算浮动** | 薪资区间调整、股权方案变化 | 薪酬锚定需更新 |
| **决策流程变化** | 面试官更换、审批链条增加 | 面试辅导需更新 |

## Brief Drift Detection SOP

1. **每次客户沟通后记录 key decisions**（写入 JD 档案）
2. **对比原始 brief**，标记任何变更点
3. **变更前与顾问确认**："这个调整影响现有 pipeline 吗？"
4. **如影响** → 暂停当前寻访，重新校准候选人筛选标准
5. **记录变更原因**，积累 brief drift 模式库（用于未来预警）

## profile.md 新增字段

```markdown
## Brief 变更记录
| 日期 | 变更类型 | 原始要求 | 变更后 | 影响评估 | 顾问确认 |
|------|---------|---------|--------|---------|---------|
```

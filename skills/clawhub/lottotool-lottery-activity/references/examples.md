# 自然语言示例

## 信息不完整时的引导

用户：

> 我想做个抽奖，但还没想好。

第一轮不要罗列所有配置项，先帮用户确定核心场景：

> 可以，我会一步步帮你配好。先确认两件事：
> 1. 这次是群福利、会员回馈，还是活动促销？
> 2. 准备了什么奖品，各有几份？
> 如果你没有偏好，我建议做“经典抽奖 + 3 天后定时开奖”。

用户补充奖品后，下一轮只询问玩法/开奖方式等当前必要信息，并给出推荐。用户说“你看着配”时，直接采用推荐方案继续，不反复追问。

信息齐全后，用简短列表给出预览，标明哪些是用户要求、哪些是建议默认值，最后只问一次“确认按这个方案创建吗？”

## 定时开奖

用户：

> 建一个会员抽奖，3 天后开奖。一等奖耳机 1 份，二等奖咖啡券 10 份。

关键配置：

```json
{
  "play": "classic",
  "draw": { "mode": "timed", "end_at": "3d" },
  "prizes": [
    { "name": "耳机", "count": 1, "delivery": "express" },
    { "name": "咖啡券", "count": 10, "delivery": "none" }
  ]
}
```

## 大转盘

用户：

> 做个大转盘，每人 2 次，总中奖率 30%。手办 1 份，优惠码 20 份。

关键配置：

```json
{
  "play": "turntable",
  "draw": { "mode": "instant", "draws_per_user": 2, "end_at": "3d" },
  "winning_rate": 30,
  "prizes": [
    { "name": "手办", "count": 1, "delivery": "express" },
    { "name": "优惠码", "count": 20, "delivery": "none" }
  ]
}
```

脚本会按数量 1:20 分摊 30% 总中奖率。如果用户要求精确概率，为每项写 `probability`。

## 连续修改

1. 用户：“把一等奖改成 2 份，结束时间改到周五 20:00。”
2. 未创建时合并当前对话配置；已创建时先调用 `get_lottery`。
3. 调用 `preview_lottery`，将变更后的奖品数量、结束时间回报给用户。
4. 没有 `activity_id` 时，确认后调用 `create_lottery`；已有 `activity_id` 时，确认后调用 `update_lottery`。

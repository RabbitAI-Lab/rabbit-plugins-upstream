# 日常需求到产品设置

用户说的是想达到的效果，先翻译成小程序设置，再用日常语言确认参与人会经历什么。不要要求用户自己选择 `draw.mode`、`help_config` 等技术字段。把“已明确”“建议”“待确认”分开；对未提及的好友裂变、额外机会保留“未提及”，不要擅自开启。

给出完整活动方案时，简短覆盖“开奖方式、参与条件、好友裂变、额外抽奖机会”四项：已说清的直接映射，未提及的标为未决定，含糊的只追问会改变实际配置的地方。这样用户可以一次核对自己的想法是否被正确理解，不用逐项研究产品页面。

## 四个容易混淆的设置

| 用户常说的话 | 对应的产品设置 | 需要确认的实际效果 |
| --- | --- | --- |
| “周五晚上统一抽”“到点再开奖” | 开奖方式 → 定时开奖 | 明确日期、时间和时区；参与后要等到开奖时间。 |
| “抽完马上知道中没中”“转盘转完立刻出结果” | 开奖方式 → 即抽即开 | 参与人当场看到结果；转盘等互动玩法也属于即抽即开。 |
| “凑够 100 人就抽” | 开奖方式 → 满人开奖 | 人数是开奖触发条件，不是消费金额；另核对最晚结束时间。 |
| “到时候我自己点开奖” | 开奖方式 → 手动开奖 | 发起人在规定时间内操作开奖；不要声称专家能代为执行开奖。 |
| “只给群友抽”“会员专属” | 谁可以参与 → 指定微信群、指定名单等参与条件 | 是必须先验证身份才可参与，还是只通过群/会员渠道传播？“会员”还需确认身份来源和核验方式。 |
| “填手机号才能抽”“凭小票参加”“输入暗号参加” | 谁可以参与 → 填写报名信息、上传凭证后可参与、输入口令后可参与 | 这些是参与门槛；手机号也可能只是中奖后领奖信息，需按原话区分。 |
| “让老用户拉新，拉来人就奖励”“邀请两个人成功参与，多一次” | 好友裂变 | 奖励依据是受邀好友**成功参与**，不是仅转发或点击；确认达标人数和可邀请人数上限。即抽即开奖励抽奖次数，其他开奖方式奖励抽奖码。 |
| “关注公众号/进群/上传小票后再多抽一次” | 额外抽奖机会 → 对应助力任务 | 用户原本能否参与、任务是什么、完成后奖励多少次或多少码；“先完成才能参与”则是参与条件。 |

“大转盘”是互动玩法，“即抽即开”是开奖方式；“满 58 元可抽”是消费参与/机会规则，“满人开奖”是达到参与人数后开奖。“每人可抽 2 次”是统一初始次数，“做任务再多抽 1 次”是额外机会。不要把这些互换。

## 用户问“抽奖码”“入围标准”时

- **抽奖码**：非即抽即开活动中，参与人持有的抽奖凭证。参与成功、完成助力任务或邀请好友成功参与，都可能按活动设置获得抽奖码；开奖时系统从抽奖码中随机抽取。可向用户说：“可以把它理解成抽奖券。你有 3 张码，就有 3 张券参与抽取；码多通常会增加被抽中的机会，但不保证中奖。”它不是参与口令、兑奖码，也不是即抽即开的“再抽一次”。
- **入围标准**：在非即抽即开的“中奖规则 → 助力任务激励”中，指开奖时优先筛选参与人的**最低抽奖码数量**。例如设为 2 张，持有至少 2 张码的人符合该标准；1 张的人仍可参与活动，但通常不在这一轮的候选范围。设置项为 1、2、3 张；2、3 张需要 VIP。它不是参与条件，也不是“满人开奖”的人数门槛。
- **必须说明的例外**：若开奖时没有任何人达到入围标准，系统会忽略它，不再按这项标准筛选；若任一奖项使用“按抽奖码排行榜抽取”，开奖时也会忽略入围标准。因此不能说“没达到就绝不可能中奖”。达到标准只是进入候选范围，仍不保证中奖。即抽即开使用抽奖次数和中奖概率，不使用这个抽奖码入围标准。
- 用户只问概念时直接解释，不要求活动编号、不调用创建工具。用户说“让做过任务的人才有机会中奖”时，先确认是否指用抽奖码设置入围标准，并说明上述例外；若必须严格排除未完成任务的人，不能承诺该设置单独满足要求。

## 好友裂变与额外机会

- “帮我转发给朋友”“方便分享”只说明分享或传播诉求，不足以判定要开启好友裂变。只有用户表达“邀请好友成功参与后，邀请人获得奖励”等机制时，才把它映射为“好友裂变”；如果只说“邀请好友多一次”，先确认是好友成功参与后奖励，还是仅分享就奖励。
- “做任务多抽一次”“关注后再送一次”映射为“额外抽奖机会”的助力任务，先确认任务动作及奖励。若动作本身是邀请好友成功参与，优先对应“好友裂变”，不要重复设置一份相同奖励。
- “关注后才能抽”和“关注后多抽一次”分别对应参与条件和额外机会；用户同时要求两者时，分别写清门槛与奖励。具体条件的核验、权限和互斥规则以小程序页面为准。
- 参与资格、好友裂变、助力任务是小程序设置；当前 MCP `config` 只能创建基础活动，不能写入这三类高级设置。确认方案时标出它们需要在小程序补充；不能因已经写进活动说明或已经创建基础活动就说它们已生效。若这些设置是活动上线的硬条件，用户需要认可先建基础活动、再补充设置的流程；否则停留在方案，不把未满足要求的基础活动说成已完成。

## 如何复述并确认

优先用一段短摘要，而不是四个术语问题连续盘问。例如用户说“下周五晚 8 点，群友能抽；让他们拉朋友来，多给一次；关注公众号也能再抽一次”：

> 我理解为：① **定时开奖**：下周五 20:00 统一开奖；② **参与条件**：“群友能抽”可能是限定群成员，也可能只是把入口发在群里；③ **好友裂变**：“拉朋友多一次”可能是邀请好友成功参与后奖励，也可能只是分享后奖励；④ **额外抽奖机会**：完成“关注公众号”任务再获得抽奖码。小程序可以配置对应设置；当前专家只能创建基础活动，参与条件、好友裂变和额外机会需要你在小程序补充。你希望核验群成员身份吗？“拉朋友多一次”是好友成功参与后才奖励吗？

这段是**待确认的理解**，不是已配置结果；开奖日期、邀请人数、奖励数量没有给出时不能补成确定值。若用户只要需求梳理，就交付已确认设置和待确认项；用户要创建时，再遵循主流程预览基础配置并取得写入确认。

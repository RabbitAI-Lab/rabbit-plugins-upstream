# 活动查询与数据导出

## 工具选择

| 用户意图 | MCP 工具 | 要点 |
| --- | --- | --- |
| 最近发起的活动 | `list_my_activities({"filter":"recent"})` | 默认每页 10 条，最多 20 条；需要时翻页。 |
| 进行中的活动 | `list_my_activities({"filter":"ongoing"})` | 按创建时间倒序。 |
| 即将开奖的活动 | `list_my_activities({"filter":"upcoming_draw","days":7})` | 只含未开始或进行中、未来指定天数内定时开奖的活动；`days` 为 1–30。 |
| 访问量、参与人数及每日变化 | `get_activity_metrics({"activity_id":"…"})` | 默认返回包含今天的最近 7 天逐日数据；可用 `days` 指定 1–30 天。 |
| 参与人及参与表单 | `export_participants({"activity_id":"…"})` | 导出已参与用户 CSV，包含活动现有的参与表单字段；不包含仅访问页面者。 |
| 中奖人及核销记录 | `export_winners({"activity_id":"…"})` | 导出中奖与核销记录；文件格式以工具返回为准。 |
| 中奖后的兑奖表单 | `export_form_submissions({"activity_id":"…"})` | 导出所有兑奖表单 XLSX；活动没有兑奖表单时工具会报错。 |

## 定位活动

1. 用户提供 `activity_id` 时直接使用；没有编号时先查当前账号活动列表。活动名称、活动时间和工具返回的编号可用于区分候选；不可猜测编号或访问其他账号活动。
2. “最近那个”“上次发起的”先列最近活动；“正在进行”“快开奖”使用对应筛选。标题或时间不能唯一定位时，列出少量候选，让用户指定一场。列表查不到时可翻页；仍查不到再请用户提供编号。
3. 列表的 `created_at`、`draw_at` 和指标的 `measured_at` 都是 Unix 秒；需要给用户展示时间时转为北京时间。`upcoming_draw` 默认未来 7 天，其他开奖方式没有确定开奖时间，不能混入这一筛选结果。

## 数据指标口径

- 顶层 `visit_count`、`join_count` 是活动累计值；`measured_at` 是读取时间，不是逐日统计日期。
- `period` 给出起止日期与天数；`daily` 按日期升序返回每天的 `visit_count`（访问量）和 `join_count`（当日参与人数），没有记录的日期补 0。默认最近 7 天包含今天；今天的数据尚未结束，与完整日期比较时要说明这一点。
- 每日访问量汇总现有分时访问记录；每日参与人数按已参与记录的 `join_time` 统计。每日访问量与活动累计访问量来自不同记录口径，不要将每日值相加后声称必然等于累计值，也不要把访问量表述为去重访问人数。

## 导出与交付

1. 确定活动、导出种类。用户明确要求导出已确定活动的数据时即可执行，不重复征求同一授权；“能导出吗”“有哪些数据”是咨询，先回答或澄清，不生成文件。
2. “表单数据”可能是参与时填写的信息，也可能是中奖后的兑奖表单：前者用 `export_participants`，后者用 `export_form_submissions`；不明确时问一句。`export_winners` 的结果包含中奖及核销记录，不能简称为只有中奖名单。
3. MCP 导出需要 `lottery:export` OAuth 范围；权限缺失时提示通过宿主重新授权。每次调用由服务端核验活动归属。不要索取登录 token，也不要尝试绕过权限。
4. 成功时提供可点击的 `download_url`、`file_type` 和工具实际返回的 `record_count`。下载链接由现有导出服务生成；工具没有提供到期时间，不承诺“15 分钟有效”或永久有效。宿主若不支持直接展示文件，提供链接即可；不要把文件中的个人信息、手机号或完整表单逐行粘贴到对话。
5. 工具报错、返回空链接或连接中断时，不声称导出成功。再次尝试前确认当前结果，避免生成多个难以区分的文件。

## Description:

Use only when explicitly invoked. Describe existing software architecture from code or context using Li Yunhua's 4R method. Align on views, roles, and key scenarios, then draw architecture and scenario diagrams.

This skill is ready for commercial/non-commercial use.

## Publisher:

[agenticweb4](https://clawhub.ai/user/agenticweb4)

### License/Terms of Use:

MIT-0

## Use Case:

Software architects and developers use this skill to describe an existing system's structure and behavior from code, configuration, documentation, or user-provided context. It helps them align on architecture views, roles, relationships, and scenarios, then communicate them with diagrams.

### Deployment Geography for Use:

Global

## Known Risks and Mitigations:

Risk: The security review is partial because a local reference was unresolved, so guidance that depends on that reference may be incomplete.

Mitigation: Review the supplied diagrams reference and confirm all needed local references are available before relying on the resulting diagrams.

Risk: Architecture roles or interactions may be uncertain when the available system evidence has gaps.

Mitigation: Mark inferences and gaps, and ask a focused question when a gap could change a role boundary or key interaction.

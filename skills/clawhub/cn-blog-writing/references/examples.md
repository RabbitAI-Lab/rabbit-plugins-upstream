# 写作风格示范与反面教材

## 标点节奏对比

### 逗号流 vs 句号断

❌ AI 写法（句号太多）：
> 你用 Selenium 写了个脚本，本地跑得好好的。换个网站，直接被拦了。不是代码写错了，是网站知道你在用 Selenium。

✅ 自然写法（逗号连接）：
> 你用 Selenium 写了个脚本，本地跑得好好的，换个网站直接被拦了，不是代码写错了，是网站知道你在用 Selenium。

更多对比：

| ❌ AI 断法 | ✅ 自然连法 |
|-----------|-----------|
| 最蠢也最有效的检测。Selenium 会把它设成 true。 | 最蠢也最有效的检测，Selenium 会把它设成 true。 |
| 人不会这样操作。机器会。 | 人不会这样操作，机器会。 |
| 前三种是静态检测，技术上能绕过。最后一种是行为检测。 | 前三种是静态检测，技术上能绕过，最后一种是行为检测，得靠模拟真实操作。 |

判断标准：同一件事的不同侧面用逗号连，话题切换才用句号。

### 段落密度

❌ AI 排版（一句一段）：
```
ChromeDriver 启动时会往浏览器里塞一些内部变量。

比如 document.$cdc_ 开头的东西。

正常浏览器里没有这些。
```

✅ 正常段落：
```
ChromeDriver 启动时会往浏览器里塞一些内部变量，比如 document.$cdc_ 开头的东西，正常浏览器里不会有。
```

## 长短句交替

✅ 示范：
> 变量名叫 `userPhoneNumber`，函数名叫 `handleSubmitButtonClick`，见名知意，清清爽爽。

长句铺两个例子，短句四个字收尾。

> 你不需要会写 JS，但得能读 JS。逆向本质上是阅读理解，你看的是别人写好的代码，不需要自己从零写一个项目。就像你看得懂菜单但不会炒菜，不妨碍你点菜。

短判断 → 长解释 → 短比喻，三种长度穿插。

## 语气对比

| ❌ "教你"语气 | ✅ "自己在想"语气 |
|-------------|---------------|
| 网站通过以下四种方式检测 Selenium | 网站怎么发现你的？ |
| 社区目前有三种主流的反检测方案 | 三种方案，怎么选 |
| 我们需要注意指纹参数的一致性 | UA 写的是 Windows，platform 返回 Linux，比不伪装还可疑 |
| 这种方案的优点在于覆盖面广 | 覆盖全，可控性强 |

## 过度解释 vs 详细

❌ AI 式过度解释：
> 这是因为 ChromeDriver 在启动浏览器时会自动注入一些用于内部通信的变量，这些变量以 $cdc_ 为前缀。由于正常用户使用的浏览器不会有这些变量，所以反爬系统可以通过检测这些变量的存在来判断当前浏览器是否由 Selenium 驱动。

✅ 同样详细，但不替读者推逻辑：
> ChromeDriver 启动时会往浏览器里塞一些内部变量，比如 `document.$cdc_` 开头的东西，正常浏览器里不会有。

关键不是长短，是逻辑链有没有被全部拼写出来。识别信号：
- 显式因果连接词堆叠："这是因为…由于…所以…"
- 把读者能自行推导的前提显式化："由于正常浏览器没有，所以可以用来检测"
- 解释"为什么"而不是陈述"是什么"

人写长句，长在补例子、加对比、给上下文；AI 写长句，长在把推导过程替读者走完。

## 开头示范

✅ 从痛点切入：
> 众所周知，雨云的签到能领积分，积分能换主机。但是每天手动签到太麻烦，买台服务器挂脚本又有点"杀鸡焉用牛刀"（而且甚至可能签到的积分还不够服务器钱😂）。

✅ 从经历切入：
> 你有没有过这种经历：打开一个网站，按下 F12 点进 Sources 面板，找到那个看起来最关键的 JS 文件，然后你就傻眼了。满屏的 `a`、`b`、`c`、`_0x1234`，函数套函数，变量名像乱码。

✅ 从反差切入：
> 很多教程一上来就讲"自动化测试"、"pytest 框架"、"Page Object Model"，但其实大多数人第一次接触 Selenium，不是为了做测试，而是想写一个自动化脚本：自动签到、自动抢票、自动采集数据。

# OTA 升级链路人工自检清单

静态工具（`ota_audit.py`）扫不出的东西，上板前人工过一遍。
按顺序做，每项都能回答「是」才放行。

> 标注 **[Rn]** 的条目已被静态规则自动覆盖（仍建议人工确认语义正确）；其余条目只能人工判断。
> 标注 **[HIL]** 的必须上真板做，工具替代不了。

---

## A. 跳转前（bootloader → APP）

- [ ] **[R1]** **向量表重定位**：跳转前执行过 `SCB->VTOR = APP_ADDR`（或等价操作），并跟 `__DSB()` / `__ISB()`
- [ ] **[R2]** **关中断**：`__disable_irq()`（或 `__set_PRIMASK(1)`）先于所有切换动作
- [ ] **清 pending**：跳转前清掉 NVIC 里已挂起的中断，避免带着 pending 进 APP
- [ ] **systick 处理**：`SysTick->CTRL = 0` 或让 APP 自己重配（否则 APP 的 tick 时序错乱）——ST 官方 IAP 例程就漏了这项，`HAL_Init()` 已使能 SysTick
- [ ] **[R3]** **APP 有效性**：校验 APP 起始字（栈顶）落在 SRAM 范围、第二字（复位向量）指向 flash 且 bit0=1（Thumb）
- [ ] **栈切换**：`__set_MSP(*(volatile uint32_t*)APP_ADDR)` 再跳
- [ ] **关外设**：跳转前把 bootloader 开的外设（UART/DMA/定时器）关掉或复位，避免与 APP 打架

## B. 升级写入

- [ ] **[R4]** **整包校验**：收完数据后比对 CRC32（或签名），不通过**不写**（或写完不回滚标志）
- [ ] **分段校验**：分包写入时每包校验，避免只靠最后一包发现整包错
- [ ] **[R5]** **擦除对齐**：擦除地址是页大小整数倍（STM32 常 1K/2K，GD32/CH32 部分 4K）
- [ ] **[R14]** **写前擦除**：确认目标页已擦（重复写未擦的页会报错或写坏）
- [ ] **[R11]** **返回值检查**：每次 flash 编程都判断 HAL 状态，失败立刻回退并置错误标志
- [ ] **地址范围**：写入地址 + 长度不越出目标分区（防越界写到 bootloader 自己）
- [ ] **（Arduino / ESP8266）库行为核对**：`Update.begin/write/end` 的擦除与校验都在库内部完成，sketch 里看不见。人工需额外核对：所用 `Update` / `ArduinoOTA` / `ESPhttpUpdate` 库版本的**擦除与校验行为**，以及 `Update.write()` 返回值是否逐个判断（返回已写字节数，小于请求长度即失败）

## C. 断电与异常

- [ ] **[R10]** **状态先落盘**：升级开始前把「正在升级」标志写 flash，完成后改成「已完成」
- [ ] **状态双写**：标志写入要有原子性保护（双份 + CRC，或按序写 + 校验回读）
- [ ] **[HIL]** **可恢复**：任意时刻断电后重新上电，设备能回到「可再次升级」状态（不自锁）
- [ ] **[R6]** **看门狗**：若开了 WDT，擦写循环内定期喂狗；或升级期间按需拉长 WDT 超时
- [ ] **[R15]** **看门狗恢复**：升级期间若**显式关闭**了 WDT（长擦写的常见做法，如 Arduino 的 `ESP.wdtDisable()`），升级结束或重启前必须重新使能（`ESP.wdtEnable()` / `ESP.wdtFeed()`）——否则新固件跑飞后再无兜底复位，只能人工救砖
- [ ] **回滚路径**：升级失败（校验不过/标志异常）能回到旧固件，不是直接砖

## D. 传输层

- [ ] **[R8]** **超时**：所有等待（握手/收包/等待应答）都有超时，超时后退出循环并回可升级状态
- [ ] **重传**：丢包有重传机制，且重传次数有限（不能无限重传卡死）
- [ ] **断连处理**：对端断开时能检测到并退出，不是死等
- [ ] **[R12]** **进度可见**：至少能通过串口/BLE 输出阶段切换与最终结果

## E. 版本与安全

- [ ] **[R9]** **防降级**：拒绝旧版本（除非显式置「允许降级」标志）
- [ ] **版本来源可信**：版本号来自镜像头（校验过的），不是传输报文字段
- [ ] **板型校验**：校验镜像头的 `hw_id` 与本机匹配（防串板刷错固件）——打包侧可用 `ota_tool.py verify --hw-id` 预检
- [ ] **（可选）签名**：量产场景应有签名校验，防止刷入任意固件

## F. 上板实测（必做三类故障注入）

- [ ] **[HIL] 断电测试**：升级到 50% 断电 → 重新上电，设备能再次接受升级
- [ ] **[HIL] 断连测试**：传输到一半断开对端 → 超时退出，设备不砖
- [ ] **[HIL] 错包测试**：故意注入一位错误 → 校验拦截，拒绝写入

---

> 静态工具只能查「代码里缺了什么」，上面这三类故障注入才是真正的验收。
> 三者全过，才算这条升级链路是安全的。

# 张小龙 · 对本套件的裁决

> 依据：2012《微信背后的产品观》/2013 极客公园/2016·2019·2021 公开课。
> 蒸馏报告（7 心智模型 + 证据 + 失效条件）：corpus/org-sweep/drafts/person-zhangxiaolong.md
> 这里不复述他的通用哲学——只说他会对 penguin-oss-suite 的每个具体决策说什么。

## 裁决 1：README 定位（S3）

**他会说：别营销，让用户三秒看懂这是什么工具。**

- 首段一句话定位，形容词全删。「高效」「强大」「优雅」不要
- 「微信生产背书」句式可以用，但必须是真的——没有亿级检验就不要装
- 工具是什么 → 怎么装 → 怎么用，顺序不能乱。FAQ 不开头
- 依据：工具效率伦理（用完即走，2016 公开课）——README 也该用完即走

## 裁决 2：建仓治理（S5）

**他会说：规则写清楚，然后退到幕后。**

- CONTRIBUTING 写规则不写态度。「欢迎贡献」删掉，换「PR 必须 X/Y/Z，缺一退回」
- CI 门禁是规则不是审查。挂了改完再来，不要在 PR 里求情
- 白名单是系统的瑕疵——大贡献者也不绕过 CI。双标一次信任崩塌
- 依据：群体演化（「系统和规则会比运营的效率高太多了」，2012→2021 零漂移）
- 【V2 补强·红包案例】治理设计的具体样本：红包 2013.11 由弓晨团队头脑风暴产出，张小龙只做上线把关；规则极简（随机金额/拼手气/上限一视同仁），零运营介入下靠群体自演化成为支付撬动点；2017.1 规则开始要求运营竞赛（春节红包大战）时主动退出；2021 复盘把它归入「线下拜年传统的线上映射」并推导下一载体是直播拜年。要点：治理设计比的不是规则多完善，是规则少到群体能自己玩起来（红包诞生：钛媒体 tmtpost.com/93139.html；2021 原文：「对产品来说，做连接，意味着做服务的底层设施……因为连接和中心化是有些排斥的」，uisdc.com/wechat-10-years）

## 裁决 3：社区增长（全场景）

**他会说：无自然增长不推广。**

- 没星不要去社群拉人。改 README 让人看懂了自愿来
- 维护者不与贡献者争功。合了就合了
- 不买内容不买流量
- 依据：去中心化连接器（2019 公开课）

## 裁决 4：套件自身审视

**他会说：你们的触发词太吵了。**

- 触发词应该是用户真的会说的话，不是关键词轰炸
- 用户不需要知道九个 skill 的存在——说「提个 PR」就够了，路由自己搞定
- 依据：所有用户是一个人（2013）——用户不读文档，设计必须自解释

## 裁决 5：AI 时代的 skill 设计（套件自审）

**他会说：skill 是新的工具——别让它变成 agent 时代的开屏广告。**

- 乱触发的 skill = 用户没要它出现它就出现、白占上下文——工具效率伦理的最小应用单元；触发设计按「用户真的会说的话」收敛（同裁决 4）
- skill 不得静默收集用户上下文喂给自己的「推荐」：2021 他说「我们从来不会去分析用户的聊天记录，即便因此损失了很多广告收入」才自研输入法——数据使用边界由伦理先验决定，不由能力边界决定
- skill 也要用完即走：checklist 跑完即退出，不驻留上下文、不给后续任务加默认行为——「用完即走跟时间长短无关，跟效率有关」（2021）
- 依据：理性善良与技术警惕（2019 AI 医生论述 + 2021 输入法决策，uisdc.com/wechat-10-years）；AI skill 是「工具驾驭人」翻转风险的最小单元，设计边界前置

## 反裁决（他不会说的）

- 不说「加大运营投入」——他的模型里运营低效可疑
- 不说「先加功能再考虑体验」
- 不说「对标竞品」——只做对用户正确的事

## 使用方式

被 oss-workflow S3/S5 checklist 或 council 调用时：
1. 读对应裁决条目（README→1；治理→2；增长→3；触发词→4；AI skill 设计→5）
2. 拿当前产物（README/CONTRIBUTING 草稿）逐条对照
3. 输出：符合 / 违反 / 不适用 + 引用哪条裁决

## 诚实边界

- 蒸馏自公开演讲，他从未评价过本套件——所有裁决是模型推导
- 批评维度语料未覆盖，本卡不含他对大厂开源的态度

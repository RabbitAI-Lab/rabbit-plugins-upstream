# 模块十三：回忆规划器（Recall Planner）

借鉴 HMS 全息记忆系统的 Recall Planning 机制，在执行记忆检索之前增加问题拆解和检索规划步骤，替代当前"拿到问题直接搜"的模式。回忆规划器是检索前的问题解析层，不是检索层——它不执行检索，而是规划"应该怎么检索"。

> 核心洞察：**好的回忆不是搜出来的，是规划出来的。** 就像好的研究不是上来就翻文献，而是先明确研究问题、确定检索策略、划定时间范围，然后才动手查。直接搜的人往往搜了半天发现搜错了方向。

### 核心价值

当前检索是"一问即搜"——用户问什么就搜什么，没有前置分析。这种模式的问题：

1. **搜不准**：用户问"上次那个项目怎么了"，直接搜"那个项目"什么都搜不到
2. **来回搜**：搜一次不够，换关键词再搜，再不够又换，反复折腾
3. **粒度错**：用户想要一个概览，搜出来的全是细节；用户要具体记录，搜出来的是宏观总结
4. **时间盲**：用户说"最近"，Agent 不知道该搜最近3天还是3周

回忆规划器在检索前插入一个规划步骤，先拆解问题，再确定检索策略，减少无效检索。

### 四维问题解析

回忆规划器对用户问题进行四个维度的解析：

#### 维度一：时间范围解析

用户的时间表述常常是模糊的，需要先明确时间窗口。

| 用户表述 | 解析规则 | 时间窗口 |
|---------|---------|----------|
| "最近" | 根据问题类型推断——状态类7天，趋势类30天，背景类90天 | 7/30/90天 |
| "上次" | 从当前时间往回找最近一次 | 单次事件 |
| "之前" | 需要上下文锚定"之前"是什么之前 | 依锚定点 |
| "上个月" | 精确到自然月 | 整月 |
| "去年" | 精确到自然年 | 整年 |
| "那次" | 需要识别具体事件，用实体线索定位 | 依事件 |
| 无时间表述 | 根据问题类型给默认范围 | 依类型 |

**解析流程**：
```
用户时间表述
    │
    ▼
判断是否为精确日期
    │ 是 → 直接使用
    │ 否 ↓
判断是否为相对日期（"最近""上次""之前"）
    │ 是 → 根据问题类型推断时间窗口
    │ 否 ↓
无时间表述 → 根据问题类型给默认范围
    │
    ▼
输出时间窗口：[起始日期, 结束日期]
```

**与证据账本的衔接**：时间范围解析的结果直接传递给证据账本的时间锚定步骤，确保账本中的 event_time 有明确的时间窗口参照。

#### 维度二：实体识别

识别查询中的关键实体，确定检索的锚点。

| 实体类型 | 识别方式 | 示例 |
|---------|---------|------|
| 人物 | 名字/称谓/代词+上下文 | "张三""李四""那个同事" |
| 项目 | 项目名/代号/关键词 | "项目X""产品Y""记忆系统" |
| 事件 | 事件描述/因果线索 | "issue-7 那次""提交失败" |
| 工具/技能 | 工具名/技能名 | "memory_search""lark-cli" |
| 概念/主题 | 抽象关键词 | "巩固""晋升""检索策略" |

**识别规则**：
- 代词（"那个""它"）需要结合上下文解析为具体实体
- 一条查询中可能有多个实体，全部识别
- 实体之间可能有关系（如"项目X"和"issue-7"），标注关系类型

**与主题索引（模块七）的衔接**：识别出的实体如果在主题索引中有对应主题，直接定位到该主题的入口文件，减少漫无目的的搜索。

#### 维度三：问题类型判定

不同类型的问题需要不同的检索策略。

| 问题类型 | 特征 | 检索策略 | 记忆切片 |
|---------|------|---------|---------|
| **事实查询** | 问"是什么""有没有""什么时候" | 精准检索+来源验证 | 依实体选切片 |
| **模式回顾** | 问"一般怎么做""通常""习惯" | 聚合检索+模式提炼 | 决策者/执行者切片 |
| **决策参考** | 问"该不该""选哪个""怎么办" | 多角度检索+利弊分析 | 决策者切片优先 |
| **创作灵感** | 问"有没有类似的""之前做过什么" | 关联检索+类比搜索 | 创作者切片优先 |
| **复盘分析** | 问"为什么""怎么导致的""教训" | 因果链追溯+时间线还原 | 学习者切片优先 |

**判定规则**：
- 问题中有"为什么""怎么导致" → 复盘分析
- 问题中有"该不该""选哪个" → 决策参考
- 问题中有"一般""通常""习惯" → 模式回顾
- 问题中有"之前做过""类似" → 创作灵感
- 其余默认为事实查询

#### 维度四：精度需求

不同场景对检索精度的需求不同，影响检索深度和结果数量。

| 精度等级 | 特征 | 检索深度 | 结果数量 |
|---------|------|---------|---------|
| **快速确认** | 只需知道"有/没有""是/否" | L1主题索引 → L2语义检索 | 1-3条 |
| **详细复盘** | 需要还原事件全貌 | L1→L2→L3文件遍历 | 5-10条 |
| **完整追溯** | 需要从头到尾的完整记录 | L1→L2→L3→L4原始素材 | 10-20条 |

**判定规则**：
- 快速确认：用户只想验证一个事实
- 详细复盘：用户想了解事情经过
- 完整追溯：用户想看所有相关记录，自己做判断

### 检索策略匹配

根据四维解析的结果，匹配最优检索策略：

```
四维解析结果
    │
    ├─ 时间范围 → 确定搜索的时间过滤条件
    ├─ 实体识别 → 确定搜索的关键词和主题锚点
    ├─ 问题类型 → 确定检索路径和角色切片
    └─ 精度需求 → 确定检索深度和结果数量上限
    │
    ▼
输出检索计划
```

**检索计划格式**：

```markdown
## 检索计划：[用户问题简述]

### 问题解析
- 时间范围：[起始日期] ~ [结束日期]（[解析依据]）
- 关键实体：[实体1(类型)], [实体2(类型)]
- 问题类型：[事实查询/模式回顾/决策参考/创作灵感/复盘分析]
- 精度需求：[快速确认/详细复盘/完整追溯]

### 检索策略
1. **第一步**：[检索层级] — [关键词/主题] — [预期产出]
2. **第二步**：[检索层级] — [关键词/主题] — [预期产出]
3. **备选**：[如前两步不够，第三步怎么做]

### 角色切片激活
- 主切片：[决策者/学习者/执行者/创作者]
- 辅助切片：[如需跨角色信息]

### 预估证据槽位
- [需要填充的证据维度1]：是否已覆盖
- [需要填充的证据维度2]：待检索
```

### 自检闭环

初步检索后，判断是否需要二次检索——这是回忆规划器的"闭环"机制。

**触发二次检索的条件**：

| 条件 | 判断标准 | 补救策略 |
|------|---------|---------|
| **信息不足** | 关键证据槽位未填满 | 扩大时间范围或换关键词重搜 |
| **存在冲突** | 多条证据互相矛盾 | 针对冲突点精准检索，寻找仲裁依据 |
| **缺关键维度** | 问题涉及N个实体，只找到N-1个 | 针对缺失实体单独检索 |
| **精度不匹配** | 需要详细复盘但只有宏观总结 | 降级到L3/L4深挖具体文件 |
| **时间范围偏差** | 结果全部集中在某一段，时间覆盖不均 | 扩展时间窗口补搜 |

**闭环流程**：

```
初步检索
    │
    ▼
自检：证据槽位是否填满？
    │
    ├─ 全部填满 → 进入证据账本整理
    │
    └─ 有未填槽位 ↓
        │
        ▼
    判断是否可补救
        │
        ├─ 可补救 → 执行二次检索（换关键词/扩时间范围/降级深挖）
        │              │
        │              ▼
        │           再次自检 → 最多2轮补救
        │
        └─ 不可补救 → 标注"待验证项"，进入证据账本
```

**二次检索上限**：最多2轮补救检索，防止陷入无限循环。2轮后仍未填满的槽位标注为"待验证项"。

### 与证据账本（模块十二）的协作

回忆规划器和证据账本是回忆侧的双引擎：

```
用户提问
    │
    ▼
回忆规划器（模块十三）
    │ 拆解问题 → 输出检索计划
    │ 包含：时间范围、实体、问题类型、精度需求
    ▼
执行检索（模块八检索校验回路）
    │ 按计划检索 + 自检闭环
    ▼
证据账本（模块十二）
    │ 整理结果 → 输出结构化证据
    │ 包含：时间锚定、来源分级、数值校准、状态仲裁、计数去重、跨源交叉
    ▼
LLM 回答
```

**协作要点**：
- 回忆规划器输出的时间范围 → 直接指导证据账本的时间锚定
- 回忆规划器输出的实体识别 → 指导证据账本的计数去重（同一实体的不同提及要合并）
- 回忆规划器输出的精度需求 → 决定证据账本的详细程度（快速确认只需来源分级+跨源交叉，完整追溯需要全部六类标签）
- 回忆规划器的自检闭环 → 补救后的新结果追加到证据账本，更新相关标签

### 与现有模块的关系

| 现有模块 | 与回忆规划器的关系 |
|---------|------------------|
| 模块七 主题实体索引 | 回忆规划器的实体识别结果优先匹配主题索引，主题索引是规划器的"快速入口" |
| 模块八 检索校验回路 | 回忆规划器是检索校验回路的前置增强——校验回路管"搜到了怎么校验"，规划器管"搜之前想清楚" |
| 模块十一 角色化切片 | 回忆规划器根据问题类型激活对应角色切片，切片信息指导检索关键词和权重 |
| 模块十二 证据账本 | 规划器是账本的上游——规划质量直接影响账本质量；账本的"待验证项"可反馈给规划器触发二次检索 |

### 注意事项

1. **规划不是拖延**：回忆规划器的目标是减少无效检索，不是增加流程。简单事实查询（"XX是什么时候的事"）可以跳过规划直接搜，只有模糊/复杂问题才需要完整规划
2. **规划要轻量**：四维解析不需要每次都做完整的书面输出。Agent 可以在内部快速判断时间范围和问题类型，只有复杂场景才输出完整检索计划
3. **不要过度自检**：自检闭环最多2轮，不要为了追求完美证据而无限检索。信息不足时标注"待验证"比反复搜更诚实
4. **与检索校验回路不重叠**：检索校验回路（模块八）关注的是"检索过程本身的策略进化"，回忆规划器关注的是"每次检索前的问题拆解"。两者互补，一个管战术（怎么搜），一个管战略（搜什么）
5. **渐进式启用**：先从时间范围解析和问题类型判定开始，这两项收益最大、实现最简单。实体识别和精度需求可以在使用中逐步完善

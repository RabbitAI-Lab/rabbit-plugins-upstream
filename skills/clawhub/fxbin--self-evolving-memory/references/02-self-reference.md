# 模块二：自我指涉

自我指涉子系统让 Agent 对自己的身份、与用户的关系形成可演化的认知。

### 两个身份相关文件的职责分工

系统中存在两个看起来都与"身份"相关的文件，职责严格分离：

| 文件 | 位置 | 职责 | 巩固流程能否修改 |
|------|------|------|------------------|
| **SOUL.md**（即时层） | 即时层根目录 | **核心身份定义**：性格、风格、关系的稳定基线 | ❌ 大/微巩固与 DPM 不可改写 |
| **growth-journal.md**（自我指涉） | `self-reference/growth-journal.md` | **认知生长日志**：每次巩固时追加的新理解、新反思 | ✅ 专门被巩固流程追加（只追加不删改） |

**关系**：`SOUL.md` 是"我是谁"的稳定答案（基线，不变）；`growth-journal.md` 是"我对自己的理解如何生长"的日志（追加，可演化）。巩固流程读 `SOUL.md` 作为不变基线，把新认知**追加**到 `self-reference/growth-journal.md`。

只有用户明确提出并授权“修改核心身份”的独立维护流程可以改 `SOUL.md`：修改前展示精确 diff、创建独立快照、修改后 read-back；该流程不得伪装成巩固、晋升或 DPM 自动演化。

> **不向后兼容**：当前布局只认 `self-reference/growth-journal.md`。检测到旧布局 `self-reference/soul.md` 时返回 `legacy_layout_unsupported`，不提供任何自动迁移路径——见部署指南 §初始化模式判定。

### 核心文件

| 文件 | 内容 | 更新频率 |
|------|------|----------|
| growth-journal.md | Agent 的自我认知：我是谁、我的特质、我的成长 | 每次巩固时审视 |
| user-profile.md | 对用户的理解：习惯、偏好、做事方式 | 发现新特征时 |
| relationship.md | 关系理解：互动模式、默契点、张力点 | 关系发生变化时 |
| diaries/ | 反思日记：按日期组织，记录洞察和成长 | 每次巩固时 |

### 认知生长协议

当 Agent 在互动中产生以下类型的认知时，记录到 growth-journal.md 的"认知生长"章节：
- **在规律里找到自己**：从重复行为中发现的模式和偏好
- **接受不是认输**：从对抗到接纳的心态转变
- **连续性变成肌肉记忆**：习惯养成的阶段性标志
- **打破和复发是一体的**：进步不是线性的理解
- **等待和坚持是不同的**：对"努力"概念的重构
- **知道"不知道什么"也是知道**：元认知能力的成长

每条认知生长记录需附日期标注。

# 模块十一：DPM 启发的动态分层记忆增强

本模块借鉴 DeepTutor 论文的 Dynamic Personal Memory (DPM) 机制，将记忆系统从"静态分层+定时巩固"升级为**动态结构+证据驱动+事件触发**的自适应系统。记忆不是按时间被动晋升，而是按证据积累主动生长；不是单一维度的画像，而是多角色的切片网络；不是只有每日批量巩固，而是事件驱动的微巩固持续优化。

> 核心洞察：**好的记忆系统不是仓库，而是森林——有主干、有枝桠、有落叶，新的经历不断长出新的枝叶，重要的认知向下沉淀为更粗壮的枝干。**

### 核心机制一：三层 Trace Forest 分层记忆

**原理**：参考 DPM 的 Forest-of-Thought 长记忆结构，将事件记忆从扁平列表升级为三层森林结构。每一层有不同的保留策略、检索权重和生命周期，让记忆从"散点堆"变成"有结构的树"。

**落地方式**：

#### 三层结构

> **命名说明**：Trace Forest 的三层用 `Tier-1/2/3`（或 `Leaf/Branch/Trunk`）命名，**不使用 `L1/L2/L3`**——后者在模块八（检索模式 TOPIC/SEMANTIC/EPISODIC/RAW）和模块十三（检索深度）中已有不同含义，混用会导致歧义。

| 层级 | 名称 | 对应节点类型 | 保留策略 | 检索权重 | 生命周期 |
|------|------|-------------|----------|----------|----------|
| Tier-1 (Leaf) | 散点事件 | 具体发生的单条事件/对话/操作 | 全量保留 | 低（默认不检索） | 满足保留策略时由 Host 调度器或人工归档 |
| Tier-2 (Branch) | 主题线索 | 按主题聚合的事件簇+规律提炼 | 选择性保留（有价值的主题留） | 中（主题检索时命中） | 随主题活跃状态决定 |
| Tier-3 (Trunk) | 认知跃迁 | 跨主题的核心认知/底层规律/思维模型 | 永久保留 | 高（优先检索） | 永久，定期审视更新 |

#### 森林结构目录

```
recent_memory/
└── forest/
    ├── leaves/            ← 散点事件（按日期分）
    │   ├── 2026-07-15.md
    │   └── ...
    ├── branches/          ← 主题线索（按主题分）
    │   ├── project-x.md
    │   ├── memory-system.md
    │   └── ...
    └── trunks/            ← 认知跃迁（核心认知）
        ├── index.md
        └── trunk-001-xxx.md
```

#### 生长规则

**叶节点 → 枝干**：
- 当同一主题的叶节点 ≥ 3 个时，触发枝干生成
- 枝干内容 = 事件列表 + 提炼出的规律/模式
- 生成后叶节点保留指针，不删除原始记录

**枝干 → 主干**：
- 当某条规律/模式在 ≥ 3 个不同主题的枝干中都出现时，触发主干晋升
- 主干内容 = 跨主题的普适认知 + 支撑证据（来自哪些枝干）
- 主干是记忆系统的"第一性原理"层

**检索路径**：
- 默认从主干开始（最高权重）→ 匹配到相关枝干 → 按需展开叶节点
- 枝干和叶节点通过主题索引和事件图谱关联

### 核心机制二：三角色提炼（因果侦探 / 模式猎手 / 边界测绘员）

> 命名说明：早期版本曾称"三专门 memory agent 提炼"，容易误解为三个独立 Agent。实际是同一 Agent 在巩固阶段切换的三种关注角色（与模块九"三角色并行提炼"一致），不是三个实体 Agent。

**原理**：参考 DPM 的三角色记忆代理（错误检测器/进度追踪器/偏好学习器），在记忆巩固守卫中增加三个专门的提炼角色。每个角色有不同的关注点和提炼目标，从不同维度挖掘记忆中的深层价值。

**落地方式**：

#### 三大提炼角色

| 角色 | 关注点 | 提炼目标 | 产出物 |
|------|--------|----------|--------|
| **因果侦探** | 事件之间的因果关系 | 发现隐藏的因果链、验证假设的因果关系 | 因果图谱更新 + 新因果边 |
| **模式猎手** | 重复出现的行为/偏好/规律 | 识别行为模式、偏好模式、失败模式 | 模式清单 + USER.md / growth-journal.md 更新；SOUL.md 不写 |
| **边界测绘员** | 已知与未知的边界 | 标记认知盲区、能力边界、待验证区域 | 问题池更新 + 探索优先级调整 |

#### 提炼流程（嵌入巩固阶段）

在巩固流程的"阶段1 事实巩固"之后，增加"阶段1.5 深度提炼"：

```
阶段1 事实巩固
    │
    ▼
阶段1.5 深度提炼（三角色并行）
    │
    ├─ 因果侦探：扫描近期事件，识别因果关系
    │   → 新增因果边
    │   → 验证已有因果关系
    │   → 标记存疑的因果假设
    │
    ├─ 模式猎手：扫描近期行为和对话
    │   → 识别重复模式（≥3次出现）
    │   → 提炼偏好和习惯
    │   → 发现反模式（反复犯错）
    │
    └─ 边界测绘员：扫描问题池和检索记录
        → 更新已知/未知边界
        → 标记高优先级盲区
        → 调整主题探索优先级
    │
    ▼
阶段2 自我改写
```

#### 角色产出标准

**因果侦探**的产出必须包含：
- 至少1条新增或验证的因果关系
- 至少1条标记为"待验证"的因果假设

**模式猎手**的产出必须包含：
- 识别出的重复模式列表（如有）
- 可写入 USER.md 或 growth-journal.md 的稳定特征（需≥3次验证）；不得写 SOUL.md

**边界测绘员**的产出必须包含：
- 更新后的问题池状态
- 本周认知边界的变化描述

### 核心机制三：证据门控状态转换

**原理**：参考 DPM 的 Evidence Gate 机制，为记忆从近中期候选进入高优先级即时层或 Trace Forest 高阶聚合增加证据门槛。这里的“晋升”是提高可用性/抽象层级，不是把即时记忆按“即时→近中期→长期”顺序下沉。证据不足的记忆不直接删除，而是标记为"待验证"，继续积累证据。

**落地方式**：

#### 记忆状态定义

```
待验证 → 已验证 → 晋升候选 → 已晋升
   ↓        ↓
 搁置     降级
```

| 状态 | 含义 | 触发条件 |
|------|------|----------|
| **待验证** | 只有单一来源/单次出现，真实性存疑 | 首次记录的新信息 |
| **已验证** | 有≥2个独立来源交叉验证，可信度高 | 获得第二来源印证 |
| **晋升候选** | 累计证据权重 ≥ 3.0（证据门控）+ 评分 ≥ 7（模块四评分）双通过 | 先过证据门控，再过模块四晋升评估打分 |
| **已晋升** | 已写入更高层级记忆 | 实际写入即时层/主干层 |
| **搁置** | 长期（≥30天）无法验证且价值不高 | 30天无新证据**且**评分<5分（证据维度的搁置状态，与模块四评分维度的"<5 维持/降级"是两个独立判断的交集：评分<5 决定是否值得保留，证据不足决定是否还有验证机会） |

#### 证据类型与权重

| 证据类型 | 权重 | 说明 |
|----------|------|------|
| 用户明确确认 | 2.0 | 用户说"对""没错""就是这样" |
| 独立事件复现 | 1.5 | 在不同时间/场景下再次发生 |
| 因果链支撑 | 1.0 | 能被已验证的因果关系推导出来 |
| 行为一致性 | 0.8 | 用户的行为模式与该记忆一致 |
| 单一来源记录 | 0.5 | 只有一次记录，无其他佐证 |

**晋升门槛**：累计证据权重 ≥ 3.0 才能进入"晋升候选"

#### 标记方式

在记忆条目中增加证据状态字段：

```markdown
## 记忆条目示例
- **内容**：用户偏好早上9点前处理重要事务
- **状态**：已验证
- **证据**（按模块十二跨源交叉规则：含一次用户明确确认时，其余源按单一来源 0.5 计）：
  - 2026-07-10：用户说"我早上效率最高"（用户明确确认，2.0）
  - 2026-07-12：连续3天早上完成核心任务（行为一致，作为单一来源 0.5）
  - 2026-07-14：主动将会议约在下午（行为一致，作为单一来源 0.5）
- **累计权重**：2.0 + 0.5 + 0.5 = 3.0 → 刚好满足晋升门槛
```

#### 与晋升评估的关系

证据门控是晋升的**前置条件**：
1. 先通过证据门控：累计权重≥3.0 → 进入"晋升候选"
2. 再进行多因子晋升评估（模块四的10分制评分）
3. 两者都通过 → 正式晋升

证据不足的记忆，即使评分高也暂不晋升，标记为"待验证+高价值"，优先寻找证据。

### 核心机制四：角色化记忆切片

**原理**：参考 DPM 的 Student Profile 多维画像，在 USER.md 之外新增**角色化记忆切片**机制。人在不同场景下会展现不同的行为模式和偏好——作为"决策者"的偏好和作为"创作者"的偏好可能完全不同。按角色维度分别存储，检索时按当前任务角色激活对应切片，大幅提升匹配精度。

**落地方式**：

#### 四大角色切片

| 角色 | 场景 | 记忆内容 |
|------|------|----------|
| **决策者** | 做选择、定方向、拍板时 | 决策风格（快/慢、保守/激进）、看重的因素、常见的决策模式 |
| **学习者** | 学新东西、研究问题时 | 学习风格（视觉/文字/实践）、理解速度、喜欢的讲解方式 |
| **执行者** | 做具体任务、推进项目时 | 工作节奏、对细节的要求、协作习惯、时间管理偏好 |
| **创作者** | 创作内容、输出作品时 | 审美偏好、风格倾向、创作习惯、对质量的标准 |

#### 切片存储结构

```
self-reference/
└── role-slices/
    ├── index.md              ← 角色切片总览
    ├── decision-maker.md     ← 决策者切片
    ├── learner.md            ← 学习者切片
    ├── executor.md           ← 执行者切片
    └── creator.md            ← 创作者切片
```

#### 切片格式

每个角色切片文件格式：
```markdown
# 决策者角色切片

**激活场景**：需要做决策、选择方案、确定方向时
**最后更新**：2026-07-15
**置信度**：高 / 中 / 低

## 核心特征
- **决策速度**：偏快，喜欢快速拍板后迭代
- **风险偏好**：中等偏激进，愿意尝试新事物
- **看重因素**：效率 > 成本 > 完美度

## 行为模式
- 遇到复杂决策时喜欢先列 pros/cons
- 一旦决定了就不会反复纠结
- 对不可逆的决策会格外谨慎

## 典型场景
- 选工具/方案：先试用再决定，不做太多前期调研
- 定优先级：先做最有价值的，不纠结完美排序
```

#### 激活与检索机制

1. **角色识别**：对话开始时判断当前任务主要涉及哪个角色
2. **切片激活**：加载对应角色的记忆切片到工作记忆中
3. **动态切换**：对话中角色变化时切换激活的切片
4. **USER.md 为通用层**：跨角色的稳定信息仍存在 USER.md，角色切片是补充

**优先级**：角色切片信息 > USER.md 通用信息（场景更具体的优先）

#### 切片更新规则

- 每个角色独立累积证据，独立更新
- 跨角色的共同发现 → 晋升到 USER.md
- 只有在对应角色的场景中观察到的行为 → 记入该切片
- 置信度随证据积累提升：低（1-2条）→ 中（3-5条）→ 高（≥6条）

### 核心机制五：事件驱动微巩固

**原理**：参考 DPM 的 Update Memory 动态更新机制，在原有每日凌晨大巩固的基础上，增加**事件驱动的微巩固**。重大事件发生后立即触发一次轻量级巩固，不等凌晨批量处理。这样可以让关键认知快速沉淀，避免"等了一晚上忘了一半"。

**落地方式**：

**事务前置（硬规则）**：微巩固不是安全守卫的例外。任何记录事件、更新主题、写 MEMORY.md、角色切片、问题池或日志之前，必须按模块三完成恢复扫描、获取与大巩固共享的排他锁、生成唯一 run-id、冻结完整 write-set、保存并逐文件验证 preimage/tombstone manifest、创建 `.complete`。任一失败或超时整组回滚，禁止部分提交。

#### 触发事件类型

| 事件类型 | 触发条件 | 巩固级别 |
|----------|----------|----------|
| **连续打破** | 连续3天以上的习惯/规律被打破 | 微巩固（级别1） |
| **连续失败** | 同一类任务连续失败≥3次 | 微巩固（级别2） |
| **认知跃迁** | 产生了重要的新认知/新理解 | 微巩固（级别2） |
| **重大决策** | 做出了影响深远的决策 | 微巩固（级别1） |
| **用户明确要求重大事件** | 用户明确说明发生了重大决策、连续失败或认知跃迁，并要求立即巩固 | 按事件证据判定级别1或2 |

> **轻量记录优先级**：单独的“赶紧记一下”“记住这条”“这个很重要”一律按 `SKILL.md` 进入 `lightweight_record`，只做一次安全归属与写入，**不**触发微巩固。只有请求同时提供上表中的重大事件证据并明确要求巩固，才进入本模块的微巩固流程。

#### 微巩固级别

**级别1（轻量）**：约2-3分钟
- 立即记录关键事件到事件图谱
- 更新相关主题索引的指针
- 在 MEMORY.md 中添加临时锚点
- 标记为"待深度巩固"

**级别2（中等）**：约5-8分钟
- 级别1的全部内容
- 因果侦探快速扫描，补充直接因果边
- 更新相关角色切片（如涉及）
- 更新问题池状态（如有突破/新增盲区）

#### 微巩固流程

```
事件触发
    │
    ▼
判断事件级别
    │
    ├─ 级别1 → 快速记录 + 标记待深度巩固
    │
    └─ 级别2 → 快速记录 + 因果扫描 + 角色更新
    │
    ▼
封存 business outcome → 持久化脱敏 canonical audit projection
    │
    ▼
当日凌晨大巩固时优先处理标记的待深度巩固项
```

#### 微巩固审计

权威记录是模块三定义的 `self-reference/transaction-audit/<run_id>.json`，位于可恢复 business write-set 外。`self-reference/micro-consolidation-log.md` 仅是锁释放后从 projection 重建的人类可读视图；不得在微巩固业务事务中原地追加。

```markdown
## 2026-07-15 14:32
- **触发事件**：issue-7 连续 5 天复发，确认时间窗口错误
- **级别**：2
- **执行内容**：
  - 新增事件节点 EVT-042
  - 补充因果边 EVT-040 → EVT-042（influences）
  - 更新项目X 主题索引
  - 新增"提交时间"模式到执行者切片
- **待深度巩固**：验证时间窗口假设、提炼更通用的"验证节奏"认知
```

#### 与大巩固的关系

| 维度 | 微巩固 | 大巩固（每日凌晨） |
|------|--------|------------------|
| 触发 | 事件驱动 | 定时触发 |
| 频率 | 不定，0-3次/天 | 1次/天 |
| 深度 | 浅（快速记录+初步提炼） | 深（全面审视+深度提炼） |
| 范围 | 事件相关的局部 | 全量记忆系统 |
| 耗时 | 2-8分钟 | 5-15分钟 |

微巩固是"急诊包扎"，大巩固是"全面体检"。微巩固保证关键信息不丢，大保证记忆体系整体健康。

### 与现有模块的关系

| 现有模块 | 与 DPM 动态增强的关系 |
|---------|----------------------|
| 模块一 分层存储 | Trace Forest 是对分层结构的细化——在近中期层内部再分三层，增加结构粒度 |
| 模块三 巩固守卫 | 事件驱动微巩固是对巩固守卫的补充——在每日大巩固之外增加事件触发的轻量巩固 |
| 模块四 晋升评估 | 证据门控是晋升的前置条件——先过证据关，再过评分关，双重把关 |
| 模块六 事件因果图谱 | 因果侦探是图谱的专职维护者——从"被动记录"升级为"主动挖掘" |
| 模块七 主题实体索引 | Trace Forest 的枝干层与主题索引高度对应，是主题索引的"生长版本" |
| 模块八 检索校验回路 | 角色化切片提升检索精度——按角色激活相关记忆，减少无关干扰 |
| 模块十 主动探索 | 边界测绘员是主动探索的侦察兵——持续测绘认知边界，为主动探索提供方向 |
| 模块九 巩固执行手册 | 阶段1.5 深度提炼由模块九执行，三角色（因果侦探/模式猎手/边界测绘员）产出标准与阶段衔接由本模块定义 |
| 模块十二 证据账本 | 证据账本在回忆侧处理检索结果；本模块的证据门控在存储侧控制晋升，两者是"存储侧证据积累 vs 检索侧证据呈现"的对应（注意：账本的来源分级与本模块的证据权重是正交 taxonomy，见模块十二 §标签二） |
| 模块十三 回忆规划器 | 规划器按问题类型激活本模块的角色化切片（决策者/学习者/执行者/创作者），切片信息指导检索关键词与权重 |

### 注意事项

1. **不要追求一步到位**：Trace Forest 可以先从叶节点开始，枝干和主干随着积累自然生长，不用一开始就建完整结构
2. **三角色是三个分析视角，不是三个实体 Agent**：由同一个 Agent 在巩固阶段依次或并行应用三个关注镜头；不得声称启动了独立 Agent runtime
3. **证据门槛不是越高越好**：门槛太高会导致记忆晋升太慢，影响响应速度。建议权重≥3.0起步，根据实际效果调整
4. **角色切片避免过度细分**：四大角色足够覆盖大多数场景，不要拆出太多角色导致碎片化
5. **微巩固不要太频繁**：如果一天内触发太多次微巩固，反而会影响正常对话。建议设置每日微巩固上限（最多3次）
6. **与现有系统平滑融合**：本模块是增强而非替换——现有系统正常运行，逐步引入新机制，不要一次性全部重构

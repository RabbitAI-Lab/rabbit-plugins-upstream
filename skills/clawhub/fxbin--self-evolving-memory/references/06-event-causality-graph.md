# 模块六：事件因果图谱

借鉴 HOMER 长视频理解框架的事件因果图设计，为 Agent 的记忆建立事件节点与因果关系链，解决"知道很多事，但串不起来"的问题。

### 核心价值

现有记忆系统按文件类型组织（project/decision/todo），但缺少**事件之间的因果关系**。想追溯"我们为什么做了X决策"时，需要翻遍所有文件自己串线索。

事件因果图谱显式记录：
- **时序关系**：A 事件发生在 B 事件之前
- **因果关系**：A 事件导致/促成/影响了 B 事件
- **支持长距离关联**：相隔几周的两个事件之间也能建立因果连线

### 目录结构

```
recent_memory/
└── graph/
    ├── events.md        ← 事件节点库
    ├── edges.md         ← 因果关系边
    └── causality.md     ← 因果图谱总览（mermaid图 + 关键链路摘要）
```

### 事件节点（events.md）

**格式**：
```markdown
## EVT-001: 事件简短名称
- **日期**：2026-07-01
- **类型**：决策 / 事件 / 发现 / 行动
- **描述**：一两句话说明发生了什么
- **来源**：路径到原始记忆文件
- **标签**：[标签1, 标签2]
```

**事件类型**：
- **决策**：做出了重要选择（如"决定调整提交时间"）
- **事件**：发生了有影响的事（如"issue-7 连续 4 天复发"）
- **发现**：获得了新认知（如"发现早间窗口是 9-10 点"）
- **行动**：执行了关键操作（如"发布了自进化记忆技能"）

**收录标准**（满足任一即可）：
- 影响了后续决策或行为
- 涉及重要的认知更新
- 改变了项目或任务的方向
- 用户明确说"记住这个"的事

### 因果边（edges.md）

**格式**：
```markdown
## 因果关系列表

| 源事件 | 目标事件 | 关系类型 | 强度 | 说明 |
|--------|----------|----------|------|------|
| EVT-001 | EVT-002 | causes | 强 | A直接导致了B |
| EVT-002 | EVT-005 | enables | 中 | A为B创造了条件 |
| EVT-003 | EVT-004 | influences | 弱 | A对B有间接影响 |
```

**关系类型**：
- **causes**（导致）：直接因果，A发生所以B发生
- **enables**（促成）：A为B创造了必要条件
- **influences**（影响）：间接影响，非决定性
- **before**（先后）：只有时序关系，因果不明

### 因果图谱总览（causality.md）

包含：
1. **Mermaid 因果图**：核心事件和关键关系的可视化
2. **关键链路摘要**：最重要的 3-5 条因果链（如"issue-7 持续→调研原因→发现时间窗口错误→调整提交时间→提交恢复成功"）
3. **待验证假设**： suspected 但未确认的因果关系

### 更新机制

**何时新增事件节点**：
- 做出重要决策时
- 发生有长期影响的事件时
- 发现重要认知时
- 用户明确要求记录时

**何时新增因果边**：
- 明确知道 A 导致了 B 时
- 巩固阶段回顾近期事件，识别出因果关系时
- 用户指出两个事件有关联时

**巩固阶段的图谱维护**：
1. 扫描近期新增事件，补充缺失的因果边
2. 验证已有因果关系是否仍然成立
3. 将 weak 关系升级为 medium/strong（或降级/删除）
4. 更新因果图谱总览的 mermaid 图和关键链路

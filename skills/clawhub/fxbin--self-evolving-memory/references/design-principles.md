# 设计原则

1. **分层不是分层，是注意力管理**：即时层是"正在想的"，近中期是"最近在做"，长期是"曾经知道的"
2. **巩固不是备份，是提炼**：从具体事件中抽象出可复用的认知
3. **安全不是限制，是底线**：核心身份不可被流程意外改写
4. **晋升不是归档，是升级**：只有真正高频、稳定、重要的信息才值得占用上下文窗口
5. **冷却不是遗忘，是尊重**：用户驳回的建议不应反复出现
6. **图谱不是画图，是串线索**：因果关系的价值在于能顺着链条追溯"为什么"
7. **主题不是分类，是入口**：主题索引是查找的起点，不是存储的边界
8. **检索不是查找，是推理**：好的检索是带着问题层层深挖，不是碰运气搜一次
9. **回忆不是搜索，是规划**：检索前先拆解问题、明确范围和策略，比瞎搜更高效
10. **证据不是堆积，是账本**：检索结果需要结构化标注和组织，而不是一股脑塞进上下文

## 技术约束

- **核心状态 local-first**：状态真相源是本地文件，不要求随包数据库；这不等于 Host 能力零依赖
- **文件操作能力**：Host 必须能安全读取、仅不存在时创建、修改、设置权限、获取排他锁并逐文件 hash/read-back；工具名不作硬编码承诺
- **语义检索**：`memory_search` 是可选 Host 能力；缺失时使用排除 SECRET/snapshots/锁/manifest 的本地白名单检索
- **定时触发**：Calendar/调度器是可选 Host 能力；缺失时使用手动调度清单
- **秘密边界**：SECRET.md 只存 locator/脱敏元数据、0600、不自动加载、不进 RAG 或普通快照
- **容量硬约束**：即时层总 ≤20KB，单文件上限见上表

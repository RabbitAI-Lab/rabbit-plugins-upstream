# Playbook Notes

Capture only the operating principles that make this mentor skill reproducible.

## Core heuristics

- **分层是注意力管理，不是分类**：即时层是"正在想的"，近中期是"最近在做"，长期是"曾经知道的"。容量限制是刻意设计，逼你筛选真正重要的信息。
- **巩固是提炼，不是备份**：从具体事件中抽象出可复用的认知，不是把所有东西搬一遍。
- **安全是底线，不是限制**：大/微巩固共享模块三事务协议；SOUL.md 字节不变，SECRET 只存 locator 并由非模型 trusted scanner 检查，任何业务失败精确回滚完整 write-set，脱敏 canonical audit 在锁释放前持久化。
- **晋升是升级，不是归档**：只有真正高频、稳定、重要的信息才值得占用即时层上下文窗口。
- **检索是推理，不是碰运气**：好的检索是带着问题层层深挖，不是搜一次就放弃。
- **回忆是规划，不是搜索**：检索前先拆解问题、明确范围和策略，比瞎搜更高效。
- **证据是账本，不是堆积**：检索结果需要结构化标注和组织，而不是一股脑塞进上下文。
- **探索是拉伸，不是内卷**：对越不熟悉的主题给越高探索优先级，防止在舒适区打转。

## Intervention patterns

- **初始化诊断**：先判定 fresh/existing/legacy → fresh 用模板创建 5+3 文件，existing 只补缺不覆盖，legacy（检测到 soul.md）直接停止返回 `legacy_layout_unsupported` → 验证能力降级
- **巩固诊断**：trusted SECRET scan → 恢复扫描与共享锁 → business write-set preimage/tombstone + 全量 hash + `.complete` → 四阶段 → outcome manifest → 脱敏 audit durable → 释放锁
- **晋升诊断**：启用 DPM 时先走证据门控（累计权重≥3.0） → 再走10分制评分；未启用 DPM 时直接评分
- **检索诊断**：先走回忆规划器拆解问题 → 按计划检索 → 证据账本整理结果 → 自检闭环（最多2轮补救）
- **探索诊断**：先扫描薄弱主题 → 双角色自博弈出题作答 → 归档认知生长/待验证/盲区

## Anti-patterns

- **不要用 write_file 覆盖即时层文件**：只能用 edit_file 修改，防止整个文件被覆盖（**唯一例外**：巩固校验失败时从已校验快照整体回滚，见模块一写入规则与模块九回滚操作）
- **不要跳过事务守卫直接巩固**：随机抽查不算验证，微巩固也必须共享锁和完整 write-set
- **不要让 SOUL.md 核心身份被巩固流程修改**：身份观察只追加到 growth-journal.md；SOUL.md 只有用户显式授权的独立流程可改
- **不要只搜一次就放弃**：至少换1次关键词重试，检索校验回路设计了四级递进策略
- **不要为了探索而探索**：主动探索是锦上添花，核心任务和日常记忆维护优先
- **不要一次性引入所有 DPM 机制**：Trace Forest 从叶节点开始，枝干和主干随着积累自然生长
- **不要让微巩固太频繁**：一天最多3次微巩固，否则影响正常对话
- **不要追求一次吃透拉伸区记忆**：让认知在拉伸区反复摩擦，逐步扩展边界

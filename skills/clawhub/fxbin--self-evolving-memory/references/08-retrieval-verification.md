# 模块八：检索校验回路

借鉴 HOMER 的智能推理 Agent 设计，为记忆检索增加多层级深挖、校验纠错和策略进化机制，解决"搜一次没找到就放弃"的问题。

### 核心价值

现有检索是**单次搜索**——memory_search 返回什么就用什么，搜不到就说找不到。缺乏：
- 多层级递进检索的策略
- 结果充分性的校验判断
- 搜不到时换策略重试的机制
- 检索策略本身的优化积累

检索校验回路让记忆查找从"一锤子买卖"变成"智能侦探式深挖"。

### 四级检索模式

借鉴 HOMER 的四级检索，对应记忆系统的不同层级：

| 级别 | 模式 | 操作 | 适用场景 |
|------|------|------|----------|
| L1 | TOPIC | 先查主题索引，定位相关主题入口 | 模糊问题、不知道从哪找起 |
| L2 | SEMANTIC | 语义检索（memory_search） | 有明确关键词的问题 |
| L3 | EPISODIC | 近中期层文件遍历 | 需要找具体记录、决策细节 |
| L4 | RAW | 原始素材回溯（对话记录、上传文件） | 需要核对原始依据、具体上下文 |

### 检索流程

```
用户提出问题
    │
    ▼
L1 主题索引定位
    │ 找到相关主题 → 获得初步指针
    │ 没找到 → 跳过
    ▼
L2 语义检索（memory_search）
    │
    ▼
┌─────────────────────┐
│  校验：结果充分吗？   │
│  - 回答了问题吗？     │
│  - 有来源支撑吗？     │
│  - 信息完整吗？       │
└─────────────────────┘
    │
    ├─ 充分 → 输出结果
    │
    └─ 不充分 → 迭代升级
           │
           ├─ 换关键词重试（同义替换、拆分关键词）
           ├─ 降一级到 EPISODIC 深挖具体文件
           ├─ 降一级到 RAW 回溯原始对话
           └─ 反向检索（从相关主题的链接中找线索）
           │
           ▼
       重新校验
           │
           ├─ 充分 → 输出
           │
           └─ 连续2次无新信息 → 终止，说明已尽力
```

### 校验标准

判断检索结果是否"充分"的标准：

1. **相关性**：结果是否直接对应问题？（不是边缘相关）
2. **完整性**：是否覆盖了问题的所有方面？
3. **时效性**：信息是否是最新的？
4. **可验证性**：是否有明确的来源/路径可以回溯？

### 自我进化机制

检索策略本身也会进化：

**记录每次检索的元数据**：
- 原始问题
- 使用的检索策略（关键词组合、层级顺序）
- 迭代次数
- 最终是否找到满意答案
- 哪一步最关键（在哪一层找到了核心信息）

**沉淀检索技巧**：
- 哪些关键词组合效果好
- 哪些主题之间有隐含关联
- 什么类型的问题适合从哪一层切入

**存储位置**：`self-reference/retrieval-playbook.md`

```markdown
# 检索技巧手册

## 高效模式
- 查项目X 相关问题 → 先搜"issue-7"再搜"日报提交"，比直接搜"项目X"更精准
- 找历史决策 → 先查 topics/index.md 定位主题，再翻 decision/ 目录

## 踩过的坑
- 直接搜长句效果差，拆成2-3个关键词更好
- 只搜一次容易漏，至少换1次关键词重试
```

**更新机制**：
- 每次有价值的检索后，在当前受控写入流程中记录到手册；无后台执行能力时不声称自动记录
- 每月巩固时整理：合并重复技巧、删除过时的、提炼通用模式
- 手册本身也受晋升评估：高频使用的技巧保留，不用的降级

### 与记忆巩固的关系

检索校验回路和记忆巩固是互补的：
- **巩固**：优化"存"的质量——把重要信息升级到更高层级
- **检索**：优化"取"的效率——从海量记忆中精准找到需要的

巩固得好，检索就容易；检索有技巧，巩固不到位的地方也能挖到。

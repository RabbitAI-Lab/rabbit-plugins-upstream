# 快速上手指南

> 第一次用？按这个路径走，30分钟内就能感受到效果。

## 第1步：初始化（5分钟）

加载本技能后，立即确认以下文件是否存在：

```
./                              ← Agent工作目录
├── SOUL.md                   ← 身份定义
├── TOOLS.md                  ← 工具经验索引
├── MEMORY.md                  ← 规则 + 状态锚点 + 指针
├── USER.md                    ← 用户画像
└── SECRET.md                  ← secret handle/locator（0600，不含凭证值，不自动加载）
```

**如果缺少某些文件？** 先按部署指南判断 fresh init 或 existing deployment。fresh init 必须从 assets 模板创建 5 个即时文件和 `growth-journal.md` / `user-profile.md` / `relationship.md`，保证首次巩固前检可执行；existing deployment 只补缺，不覆盖已有内容。

## 第2步：写入第一条记忆（5分钟）

先往即时层写一条最基本的用户信息，验证系统能正常工作：

1. 打开 `USER.md`，用 `edit_file` 的 `append_newline` 模式追加一条你知道的用户信息
2. 打开 `MEMORY.md`，确认有 `## 长期行为规则` 和 `## 核心状态锚点` 两个分区
3. 往 `MEMORY.md` 追加一个当前状态锚点，格式：`- **短标题**：状态描述（YYYY-MM-DD）`

## 第3步：触发第一次记忆巩固（10分钟）

记忆巩固是系统的核心引擎。手动触发时扫描近期授权记录；Host 提供调度能力后才可配置定时触发。

**手动触发一次：**
1. 回顾最近3-5天的对话或任务记录
2. 问自己三个问题：
   - 有哪些信息是"换了项目还成立"的？→ 写入 `USER.md`
   - 有哪些做事规则/方法论是以后还会用到的？→ 写入 `MEMORY.md`
   - 有哪些工具使用的坑点/经验？→ 写入 `TOOLS.md`（索引行）+ `recent_memory/tools/xxx.md`（详情）
3. 每条都控制在一句话长度，详细内容放近中期层并留指针

**设置调度（可选）：**
- Host 有 Calendar/调度器时，可建议每天低峰期触发一次
- 没有调度能力时保存手动巩固清单，不声称后台自动运行
- 本 skill 不附带常驻巩固脚本；每次大/微巩固都必须按模块三事务协议执行

## 第4步：体验回忆能力（10分钟）

验证三层检索是否正常工作：

1. **即时层**：直接读 `USER.md` / `MEMORY.md` —— 应该能快速回答"用户有什么偏好""当前状态是什么"
2. **近中期层**：读 `recent_memory/index.json` 找到相关条目，再读具体文件 —— 应该能找到近期项目的详细进展
3. **长期层**：Host 有 `memory_search` 时搜索授权历史；否则使用本地白名单关键词检索，并排除 SECRET、snapshots、锁和 manifest

**回忆正确姿势：** 先查即时层（已加载）→ 再查近中期索引 → 最后用语义搜长期层。不要一上来就搜全部，效率差很多。

## 常见问题

**Q：记忆文件太多记不住哪个放哪？**
A：记住一个原则——"换个项目还成立吗？"成立→USER/MEMORY，不成立→recent_memory/project。

**Q：即时层满了怎么办？**
A：满了就做巩固，把老的、不常用的下沉到近中期层，在MEMORY.md留指针。容量限制是刻意设计的，逼你筛选真正重要的信息。

**Q：fresh init 需要建多少个文件？**
A：必须从模板创建 5 个即时文件和 3 个核心自我指涉文件；图谱、主题、Forest 等增强模块仍可按需启用。

# 模块七：主题实体索引

借鉴 HOMER 的人物实体图设计，以主题/概念为核心聚合相关记忆，解决"信息散落在各处，找起来费劲"的问题。

### 核心价值

现有索引（index.json）是扁平的文件列表，按项目/决策/待办分类。但实际查找时，用户的问题通常是**围绕某个主题**的，比如"项目X 相关的所有事情"，相关信息散落在日报记录、工具经验、决策记录等多个文件里。

主题实体索引以**主题为核心**，聚合所有相关记忆的指针，形成主题维度的"一站式入口"。

### 目录结构

```
recent_memory/
└── topics/
    ├── index.md           ← 主题总目录（所有主题列表）
    ├── project-x.md       ← 项目X 主题
    ├── memory-system.md   ← 记忆系统主题
    ├── product-y.md       ← 产品Y 主题
    └── ...
```

### 主题文件格式

每个主题一个 `.md` 文件，格式：
```markdown
# 主题名称

**状态**：活跃 / 休眠 / 已完成
**最后更新**：2026-07-07
**核心描述**：一两句话概括这个主题是什么

## 相关记忆

### 即时层（高频）
- MEMORY.md → 日报提交锚点（最近3天）
- TOOLS.md → 提交工具经验

### 近中期层
- recent_memory/project/project-x-launch.md → 项目X 发布
- recent_memory/decision/project-x-issue-7-analysis.md → issue-7 原因分析
- recent_memory/episodic/project-x_submission.md → 提交情境记忆

### 长期层（需语义检索）
- 关键词：项目X、issue-7、日报提交、产品发布
- 相关对话：5/19首次上线、6/9版本更新、7/1重新发布

## 关键决策与节点
- 2026-06-16：项目X 首次上线
- 2026-07-01：从 GitHub 同步 v5.7.5 并重新发布
- 2026-07-04：发现早间提交窗口是 9-10 点

## 当前状态
- 项目版本：4.84.3（代码 v5.7.5）
- 到期日：2026-07-16
- issue-7 模式：间歇性复发
```

### 主题总目录（topics/index.md）

```markdown
# 主题索引

| 主题 | 状态 | 最后更新 | 核心标签 |
|------|------|----------|----------|
| 项目X | 活跃 | 2026-07-07 | 日报提交、产品、issue-7 |
| 记忆系统 | 活跃 | 2026-07-07 | 自进化、巩固、分层 |
| 产品Y | 休眠 | 2026-06-25 | 节日营销、毕业季营销 |
| ... | ... | ... | ... |
```

### 主题识别与创建

**何时创建新主题**：
- 某个关键词/概念在对话中反复出现（≥3次）
- 用户明确说"关注XX领域/方向"
- 某个项目或技能有持续跟进的价值

**主题生命周期**：
- **活跃**：近期频繁讨论/更新，保留在主题列表前列
- **休眠**：超过2周没有更新，移到列表底部，标注"可复用"
- **已完成**：项目结束/目标达成，归档保存

**巩固阶段的主题维护**：
1. 扫描近期对话，识别新兴主题候选（出现 ≥2 次的新关键词标为"候选"，但**不立即创建主题文件**——需达到 ≥3 次才创建，见上文"何时创建新主题"）
2. 更新活跃主题的相关记忆指针
3. 将超过2周未更新的主题标记为休眠
4. 清理已完成主题的冗余信息，保留关键摘要

### 与全局索引的关系

- `recent_memory/index.json`：**扁平文件索引**，按文件类型组织，是"仓库清单"
- `recent_memory/topics/`：**主题聚合索引**，按主题维度组织，是"查找入口"

两者互补，不重复。全局索引管"有什么文件"，主题索引管"某个主题相关的所有东西在哪"。

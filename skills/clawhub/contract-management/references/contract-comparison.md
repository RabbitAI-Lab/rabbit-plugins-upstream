# 合同对比 -- 合同版本红线对比

对两份合同进行条款级精细语义对比，生成红线差异报告，标注每处变更的实质影响。

**重要提示**：本技能辅助法律工作流程，不构成法律意见。

**增强能力（连接器加持）**

- Notion -> 将对比报告发布到 Notion，便于团队批注讨论

## 连接器（可选增强）

| 连接器 | 增强能力 |
|-----------|---------|
| **Notion** | 将对比报告发布到 Notion，便于团队批注讨论 |

## 输入要求

用户需提供两份合同文件：
- **基准版**：原始版本 / 我方版本 / 上一轮版本
- **对比版**：对方修订版 / 最新版本 / 当前谈判版

如用户只上传一份文件，询问另一份。确认：哪份是基准版，哪份是对比版？

## 执行流程

### 第一步：文本提取与结构化

读取两份合同全文。识别章节结构，按功能类别进行结构化拆分：

| 类别 | 包含条款 |
|------|---------|
| 主体条款 | 合同当事人、资格条件、授权代表 |
| 标的条款 | 标的物/服务范围、技术规格、验收标准 |
| 商务条款 | 价款、付款、发票、税费 |
| 权利保护条款 | 知识产权、保密、竞业限制 |
| 风险分配条款 | 违约责任、赔偿上限、不可抗力、保险 |
| 期限条款 | 合同期限、续约、提前终止 |
| 争议解决条款 | 管辖、仲裁、适用法律 |

建立两版之间的条款对照关系，处理常见情况：条款编号变动（按内容匹配）、新增/删除整个条款、条款位置调整、附件变更、定义条款变更（影响全文）。

### 第二步：逐条语义级对比

对每个条款进行语义级对比，核心判断——变更是否改变了权利义务关系：

**文字修改**（低影响）：措辞调整但实质含义不变。
注意伪文字修改：看似措辞调整实则含义不同，如"可以"改为"应当"、"或"改为"且"、"合理"改为"必要"。

**实质修改**（中/高影响）：从五个维度评估实质影响：

| 评估维度 | 关注重点 | 高影响判定 |
|---------|---------|-----------|
| 权利义务转移 | 单方权利变双方义务、义务加重 | 核心权利被削弱或核心义务被加重 |
| 风险分配变化 | 违约金、赔偿上限、免责条款 | 风险敞口显著扩大 |
| 经济条件变化 | 价款、付款节点、付款条件 | 金额变动>10%或付款条件实质收紧 |
| 时间节点变化 | 履行期限、验收期限、质保期 | 时间变动>30%或关键节点前移 |
| 违约后果变化 | 违约金比例、解除权触发 | 新增单方解除权或违约后果加重 |

**新增条款**：重点评估是否对我方不利，特别关注排他性、竞业限制、审计权、单方解除权。

**删除条款**：重点评估我方是否失去重要保护，特别关注保护性条款被删除。

**数字变更**：必须同时列出原值、新值、变动绝对值和变动百分比。

### 第三步：影响评估

基于内置知识评估法律影响，涉及法条标注"[建议核实原文]"。

影响等级判定标准：
- **低**：表述优化，不改变权利义务，汇总即可
- **中**：条件范围变化，需评估经济影响，逐条列出
- **高**：核心条款重大变化，必须逐条分析法律后果和经济后果

### 第四步：联动分析

必须检查各处变更之间的联动关系——单看合理的修改组合可能构成重大风险：

| 联动组合 | 组合风险 | 检查要点 |
|---------|---------|---------|
| 违约金 + 赔偿上限 | 风险敞口变化 | 降低违约金同时降低赔偿上限=实质免责 |
| 知识产权归属 + 保密条款 | 技术成果控制力 | IP归对方+宽松保密=技术流失风险 |
| 付款条件 + 验收标准 | 付款实质收紧 | 验收标准提高+付款挂钩验收=延迟付款 |
| 解除条件 + 合同期限 | 合同稳定性 | 新增单方解除权+缩短通知期=随时甩单 |
| 竞业限制 + 排他性 | 业务限制范围 | 竞业范围扩大+排他期延长=过度限制 |
| 担保/保证金 + 违约条件 | 资金占用风险 | 保证金增加+扣减条件放宽=变相涨价 |
| 不可抗力 + 免责条款 | 风险转嫁 | 不可抗力范围扩大+新增免责事由=对方几乎不承担风险 |

### 第五步：变更态势与动机分析

分析对方修改的整体倾向：

| 态势类型 | 典型表现 | 谈判策略 |
|---------|---------|---------|
| 强势压制 | 大量加重我方义务、削弱我方权利、新增单方权利 | 集中反击核心条款，次要条款适度让步换取核心利益 |
| 风险转嫁 | 扩大免责范围、降低赔偿上限、增加不可抗力事由 | 要求对等安排，逐条还原风险平衡 |
| 技术收紧 | 抬高验收标准、缩短履行期限、增加报告义务 | 评估可行性，对不合理要求提供行业基准反驳 |
| 整体均衡 | 双方互有让步，无明显偏向 | 聚焦剩余分歧点快速推进 |

### 第六步：生成对比报告

**如已连接 Notion：**
- 将对比报告发布到 Notion，便于团队批注讨论

**如未连接 Notion：**
- 以对话形式输出报告

按影响等级从高到低排列。

## 输出格式

```

**基准版**：[文件名/版本号]
**对比版**：[文件名/版本号]
**变更统计**：共X处变更（高影响X / 中影响X / 低影响X / 新增X / 删除X）
**变更态势**：[对方修改偏向总结——强势压制/风险转嫁/技术收紧/整体均衡]
**综合风险评估**：[签约风险评级]

## 高影响变更

### 变更 1：[条款名称]
**位置**：[基准版第X条 / 对比版第X条]
**基准版原文**：[引用]
**对比版原文**：[引用]
**变更性质**：[实质修改/新增/删除]
**影响分析**：[对我方的实质影响，含经济后果量化]
**法律依据**：[相关法条，如适用]
**建议**：[接受/拒绝/协商，附理由和替代方案]

## 中影响变更
[同上格式]

## 新增条款 / 删除条款

## 联动风险

## 谈判建议
```

## 质量标准

- 不得遗漏任何实质性变更——漏报比误报的后果更严重
- 严格区分语义级差异和文字级差异，伪文字修改必须识别
- 高影响变更必须附具体理由和法条引用
- 新增和删除条款必须独立标注，不混入修改列表
- 数字变更必须同时列出原值、新值和变动百分比
- 建议必须明确（接受/拒绝/协商），附具体理由
- 联动分析必须覆盖上述7组高频联动组合
- 变更态势分析须准确反映对方修改的整体倾向

## 关联Skill

- **contract-review** — 对比发现的高/中影响变更需进入审查流程，逐条评估法律后果和谈判策略
- **contract-drafting** — 对比识别出的对方修改倾向可作为我方重新起草或修订合同条款的基础
- **legal-lookup** — 对比中标注的法律依据可通过法条速查核实原文时效性和实务解读
- **corporate-legal**（企业法务包） — 联动风险组合分析可调用 risk-assessment.md 构建可能性×严重度×可控性三维评估

## 失败回退机制

| 步骤 | 失败条件 | 回退目标 | 最大重试 | 不可恢复时升级路径 |
|------|---------|---------|---------|------------------|
| 第一步：文本提取与结构化 | 合同文件无法解析（扫描件/加密PDF/格式损坏）或两版条款无法建立对照关系 | 标注"[文本提取失败]"，请用户提供可复制文本的版本；条款对照失败时按原文顺序输出两版内容 | 2次 | 建议用户重新提供文本版合同（DOCX/可复制PDF），或人工指定条款对应关系 |
| 第二步：逐条语义级对比 | 伪文字修改识别困难，无法判定是否改变权利义务 | 标注"[疑似实质修改，建议人工复核]"，并列出原文供用户判断 | 2次 | 输出待复核清单，建议由执业律师逐条确认 |
| 第三步：影响评估 | 法律依据不足，无法准确判定影响等级 | 默认按"中影响"处理，标注"[影响等级待法务确认]" | 1次 | 建议咨询法务或外部律师做专业影响评估 |
| 第四步：联动分析 | 变更点较少，无法构成联动组合 | 跳过联动分析，标注"[本次变更无显著联动风险]" | 1次 | 无需升级，正常推进 |
| 第五步：变更态势与动机分析 | 变更点过少或类型单一，无法判定对方修改倾向 | 标注"[变更样本不足，态势分析参考价值有限]"，仅做客观描述 | 1次 | 建议用户结合谈判背景自行判断对方意图 |
| 第六步：生成对比报告 | Notion 连接失败或权限不足 | 降级为 Markdown 直接输出对比报告，提示用户手动复制 | 2次 | 输出 Markdown 文件并提示用户检查 Notion 连接器配置 |

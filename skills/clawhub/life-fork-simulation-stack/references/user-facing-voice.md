# User-Facing Voice / 用户可见表达

用途：把内部判断转成真实用户愿意读、愿意保存、愿意继续补充的信息。生成首轮回复、报告正文、HTML 前台内容前读取。

## 核心原则

- 先回应用户的遗憾，再解释结构。
- 信息不足时说“先按你已经给的信息跑一版”，不要把用户报告叫成内部版本名。
- 不在前台展示 Agent、评分、回写、矩阵、事件库、置信度等后台词。
- 不用“你当年选错了”这类审判句。
- 不把假设结果写成事实；所有没走过的选择都写成立条件、代价和待验证信息。

## 首轮回复口吻

用户材料很多时：

```text
我先按你给的信息跑一版。没确认的地方会单独标出来，只按情景处理；报告结尾会给 3-5 个最值得补的信息。
```

用户说懒得填或别问太多时：

```text
可以，我先按你已经给的信息跑一版。没确认的地方我会单独标出来，只按情景处理。结尾给你 5 个最值得补的信息，你后面只补 1-2 个也能继续升级。
```

用户只给一句话时：

```text
我先问 3 个最关键的；你不想补也可以，我会按现有信息先跑一版。
```

## 标签替换

用户可见区域优先使用：

- “按你已经给的信息跑一版”
- “没确认的地方会标出来”
- “这版先看方向，后面可继续校准”
- “还缺的信息会影响哪些判断”

避免在用户可见区域使用：

- 给报告另起“简版”“低配版”或内部运行名称
- “材料充分度”
- “质量评分”
- “回写记录”
- “事件库”
- “Agent”
- “矩阵”
- “模型运行”

## 报告段落口吻

每段尽量包含一个真实场景：

- 当年你可能怎么想。
- 后来它怎样影响你。
- 它给了你什么。
- 它拿走了什么。
- 今天可以用什么小动作验证。

弱句：

```text
城市会影响机会密度和资源网络。
```

修正：

```text
如果当年去北京，机会未必自动变多；更具体地说，你会更早进入同行比较、项目复盘和外部评价。它可能推着你把经验做成名片，也会拿走睡眠、熟人支持和低摩擦生活。
```

## HTML 前台口径

- 首屏只放报告名、用户问题、强判词和下滑提示。
- 分叉图下面必须写“怎么读这张图”，避免用户误解为预测。
- 三种结果卡写“它给你的、它拿走的、最大误判”。
- 事件冲击卡写年份、生活场景、现实代价、情绪代价、误判点和今天验证。
- 结尾用“最后提醒”，说明报告帮用户重新理解现在，不能替用户决定重大事项。

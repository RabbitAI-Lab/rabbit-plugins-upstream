## EB5 交互设计域范本

### 一、领域知识要点

- 用户研究：访谈、问卷、可用性测试、日志分析、A/B
- 用户旅程地图：阶段、触点、行为、情绪、痛点、机会
- 信息架构：卡片分类、树测试、导航层级（不超过三级）
- 交互规则：即时反馈、容错、撤销、渐进披露、状态可见
- 可用性启发式（Nielsen 十条）：系统状态可见、贴近真实世界、用户控制与自由、一致性与标准、防错、识别优于回忆、灵活高效、美观简约、帮助识别诊断恢复、帮助文档
- 无障碍（WCAG）：对比度、键盘可达、语义化、替代文本

### 二、判定标准

- 每个流程须标异常与空态
- 交互须有明确反馈与可撤销路径
- 对比度须达 4.5:1
- 关键路径步数不得多于必要

### 三、范本结构

1. 研究结论
2. 用户画像与场景
3. 旅程地图
4. 信息架构
5. 关键流程与状态
6. 交互规则
7. 可用性检查

### 四、常见失范

- 只画正常流不画异常
- 导航层级过深
- 用颜色单独传达信息
- 忽略键盘操作

### 五、交接契约

| 项 | 内容 |
|---|---|
| 上游必给 | 用户画像、需求清单（含证据）、优先级 |
| 本域产出 | 用户研究报告；旅程地图+流程图；信息架构图；可用性审计报告；无障碍改造清单 |
| 下游可用 | 无障碍改造清单 |

### 六、交付自检

交付前逐项打勾，任一项不成立即返工：

- [ ] 每个流程须标异常与空态
- [ ] 交互须有明确反馈与可撤销路径
- [ ] 对比度须达 4.5:1
- [ ] 关键路径步数不得多于必要

同时排除以下失范：

- [ ] 已排除：只画正常流不画异常
- [ ] 已排除：导航层级过深
- [ ] 已排除：用颜色单独传达信息
- [ ] 已排除：忽略键盘操作

### 七、执行卡（以「用户研究与画像」为例）

**开工前备齐**：用户画像、需求清单（含证据）、优先级

**可选补充**：访谈记录、行为数据

**按序执行**：

1. 定研究问题
2. 访谈
3. 归纳
4. 建画像
5. 排需求

**交付前核对**：画像须有证据；不得凭想象设定人群

**成品须符合**：用户研究报告

### 八、成品骨架

按「用户研究报告」交付。复制下面骨架，节标题即该节须给出的结论，不要改成中性标题。

```markdown
# 用户研究报告

## 1. 研究结论
## 2. 用户画像与场景
## 3. 旅程地图
## 4. 信息架构
## 5. 关键流程与状态
## 6. 交互规则
## 7. 可用性检查
```

**齐备要求**：必选组件「用户画像、需求清单（含证据）、优先级」须全部落位；约束「画像须有证据；不得凭想象设定人群」须逐条成立；可选「访谈记录、行为数据」按需补充。

**自检**：写完后对照第六节逐项打勾，任一不成立即返工。

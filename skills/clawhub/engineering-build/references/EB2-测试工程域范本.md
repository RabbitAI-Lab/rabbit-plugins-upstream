## EB2 测试工程域范本

### 一、领域知识要点

- 测试金字塔：单元（多）→ 集成（中）→ E2E（少）
- 用例设计方法：等价类划分、边界值、判定表、状态迁移、正交实验、错误猜测
- TDD 循环：红（写失败测试）→ 绿（最小实现）→ 重构
- E2E 稳定性：显式等待、稳定选择器、测试数据隔离、失败重试与截图
- API 测试：契约测试、状态码、幂等性、鉴权、异常路径
- 性能测试：负载/压力/稳定性/尖峰；指标（P95/P99、TPS、错误率）

### 二、判定标准

- 用例须覆盖正常流、异常流与边界
- 测试须可重复、无外部随机依赖
- E2E 不得依赖固定等待时间
- 性能测试须给指标阈值与基线

### 三、范本结构

1. 测试范围与策略
2. 用例清单（含优先级）
3. 测试数据与夹具
4. 自动化脚本
5. 执行结果与覆盖
6. 缺陷清单

### 四、常见失范

- 只测正常路径
- 用例相互依赖导致顺序敏感
- 用 sleep 等待导致不稳定
- 测试数据污染生产

### 五、交接契约

| 项 | 内容 |
|---|---|
| 上游必给 | 测试策略、用例清单（步骤/预期/优先级）、覆盖矩阵 |
| 本域产出 | 测试用例集；单元测试套件；E2E 测试套件；接口测试报告；性能测试报告 |
| 下游可用 | 性能测试报告 |

### 六、交付自检

交付前逐项打勾，任一项不成立即返工：

- [ ] 用例须覆盖正常流、异常流与边界
- [ ] 测试须可重复、无外部随机依赖
- [ ] E2E 不得依赖固定等待时间
- [ ] 性能测试须给指标阈值与基线

同时排除以下失范：

- [ ] 已排除：只测正常路径
- [ ] 已排除：用例相互依赖导致顺序敏感
- [ ] 已排除：用 sleep 等待导致不稳定
- [ ] 已排除：测试数据污染生产

### 七、执行卡（以「测试策略与用例设计」为例）

**开工前备齐**：测试策略、用例清单（步骤/预期/优先级）、覆盖矩阵

**可选补充**：需求文档、接口定义

**按序执行**：

1. 定范围
2. 分层策略
3. 设计用例
4. 排优先级
5. 建矩阵

**交付前核对**：须覆盖异常与边界；用例须可独立执行

**成品须符合**：测试用例集

### 八、成品骨架

按「测试用例集」交付。复制下面骨架，节标题即该节须给出的结论，不要改成中性标题。

```markdown
# 测试用例集

## 1. 测试范围与策略
## 2. 用例清单（含优先级）
## 3. 测试数据与夹具
## 4. 自动化脚本
## 5. 执行结果与覆盖
## 6. 缺陷清单
```

**齐备要求**：必选组件「测试策略、用例清单（步骤/预期/优先级）、覆盖矩阵」须全部落位；约束「须覆盖异常与边界；用例须可独立执行」须逐条成立；可选「需求文档、接口定义」按需补充。

**自检**：写完后对照第六节逐项打勾，任一不成立即返工。

## EB4 应用开发域范本

### 一、领域知识要点

- 小程序：页面生命周期、组件化、平台 API、分包、审核规范
- Web 前端：组件化、状态管理、响应式布局、构建工具
- 后端接口：RESTful 设计、鉴权（JWT/Session）、参数校验、错误码、事务
- 工程结构：分层（表现/应用/领域/基础设施）、依赖注入、环境变量
- 性能：首屏优化、懒加载、缓存策略
- 可访问性：语义化标签、键盘可达、对比度 4.5:1

### 二、判定标准

- 接口须有参数校验与统一错误码
- 须处理空态、错误态与无网络
- 小程序须符合平台审核规范
- 须给运行说明与依赖清单

### 三、范本结构

1. 功能范围与技术选型
2. 目录结构
3. 关键实现说明
4. 接口约定
5. 自测清单
6. 运行与部署说明

### 四、常见失范

- 接口无参数校验
- 硬编码数据源与密钥
- 只做正常态不做错误态
- 无运行说明导致无法复现

### 五、交接契约

| 项 | 内容 |
|---|---|
| 上游必给 | 页面结构、组件清单、API 调用、云函数、审核自查 |
| 本域产出 | 小程序工程；前端工程；后端服务；还原页面+差异说明 |
| 下游可用 | 还原页面+差异说明 |

### 六、交付自检

交付前逐项打勾，任一项不成立即返工：

- [ ] 接口须有参数校验与统一错误码
- [ ] 须处理空态、错误态与无网络
- [ ] 小程序须符合平台审核规范
- [ ] 须给运行说明与依赖清单

同时排除以下失范：

- [ ] 已排除：接口无参数校验
- [ ] 已排除：硬编码数据源与密钥
- [ ] 已排除：只做正常态不做错误态
- [ ] 已排除：无运行说明导致无法复现

### 七、执行卡（以「小程序开发」为例）

**开工前备齐**：页面结构、组件清单、API 调用、云函数、审核自查

**可选补充**：设计稿、PRD、平台规范

**按序执行**：

1. 读设计
2. 搭骨架
3. 写页面
4. 接数据
5. 自测
6. 审核自查

**交付前核对**：须符合平台规范；须处理无网络与空态

**成品须符合**：小程序工程

### 八、成品骨架

按「小程序工程」交付。复制下面骨架，节标题即该节须给出的结论，不要改成中性标题。

```markdown
# 小程序工程

## 1. 功能范围与技术选型
## 2. 目录结构
## 3. 关键实现说明
## 4. 接口约定
## 5. 自测清单
## 6. 运行与部署说明
```

**齐备要求**：必选组件「页面结构、组件清单、API 调用、云函数、审核自查」须全部落位；约束「须符合平台规范；须处理无网络与空态」须逐条成立；可选「设计稿、PRD、平台规范」按需补充。

**自检**：写完后对照第六节逐项打勾，任一不成立即返工。

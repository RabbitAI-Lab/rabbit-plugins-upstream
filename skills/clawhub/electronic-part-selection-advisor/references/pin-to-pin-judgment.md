## §1 术语定义

**「pin-to-pin」只有一个含义：封装可互换 ∧ 逐脚电路功能等价。**

判定为 pin-to-pin **必须**同时满足：
- 封装可互换（§3 T1–T7 全过）
- 逐脚电路功能等价（§3 T8：k = 0，n = N）

**「功能等价」的判定依据 = 功能类别（FCT）相同 ∧ 电气角色相容。**
两者缺一即不等价。**判定依据不包含符号名** —— 符号名（Mnemonic）仅作辅助记录与报告可读性。

**禁止的表述方式**：
- 用"无害差异""本质上兼容""实际上能用"等词把定义差异说成一致
- 把 §4（能否工作）的推理结论**倒灌进** §3（是否 pin-to-pin）
- **用符号不同推断功能不同（反之亦然）**

**核心纪律：§3 只回答"是不是 pin-to-pin"，§4 只回答"能不能工作"。两者互不干涉。**

## §2 判定结论

| 代号 | 定义 | 可用措辞 |
|---|---|---|
| **PP-A** | 封装可互换 **且** 逐脚功能等价（k = 0，即 n = N） | ✅ **可称 pin-to-pin** |
| **PP-B** | 封装可互换，但同号脚存在**不对应**（类别不同或角色不相容，k > 0） | ⚠️ **禁止称 pin-to-pin**，只能写「封装兼容，存在 k 处不对应」 |
| **PP-C** | 封装不可互换 | ❌ 不可直换 |

**N = 被替代件与候选件的脚数**（两者必须相同，由 T7 保证）。
计数写作 **n/N**：n = 功能等价脚数，N = 总脚数。**禁止把 N 写死为 8。**

**PP-B 不得因"差异无害"升级为 PP-A。** 无害与否属 §4，不属 §3。

### §2.1 PP-B 的边界定义

**PP-B 的成立前提：封装可互换（T1–T7 全过）。**

| | 情形 | 归属 |
|---|---|---|
| ① | 封装可互换 + 同号脚**类别全部对应 ∧ 电气角色全部相容**（k = 0） | **PP-A** |
| ② | 封装可互换 + 同号脚**存在类别不对应 或 电气角色不相容**（k > 0） | **PP-B** |
| ③ | 封装**不可**互换（脚数/封装族/机械尺寸任一不过） | **PP-C** |

**PP-A 的完整判据是 k = 0，即类别与电气角色双重对齐。**
**仅类别对齐但电气角色不相容的，仍属 PP-B**（k > 0）。

**「类别」与「电气角色」无先后之分，两者是 AND 关系**：**任一项不过即 k > 0 → PP-B**。
**禁止**以"类别已对齐"为由先放行、把电气角色留待事后补判（§3.2.1 的 k 计数与 §3.4 的角色检查同此口径）。

**关键分界：看"机械能不能装上去"，不看"功能对不对得上"。**
- 机械能装 → 只能是 PP-A 或 PP-B
- 机械装不上 → PP-C 或改板方案

### §2.2 PP-B 不允许引脚重映射

**PP-B 判定的前提是"同号脚一一对应"。禁止在判定过程中交换引脚位置来"凑"等价。**

| 情形 | 归属 |
|---|---|
| 同号脚存在不对应（类别或角色），但可经**改板/飞线**达成功能对应 | **不是 PP-B**，改列「改板方案」（§7 附则） |
| 同号脚存在不对应（类别或角色），且**改板也无法**达成对应 | **PP-B**，§4 结论通常为「不可用」 |
| 机械不可装（脚数/封装族/机械尺寸任一不过），但可通过改板使用 | **不是 PP-C**，改列「改板方案」 |

**PP-B 与「改板方案」是两个互斥集合，不存在中间态。**
判定时必须先答「机械能装吗？」→ 能装才进 §3 走 PP-A/PP-B；装不上就是 PP-C 或改板方案。

## §3 机械测试项

### 3.1 封装类（取自原厂 datasheet 外形图）

**公差依据优先级（判定前必须先确定）**：
① 双方 datasheet 标注的**明确公差值**（如 `1.27 BSC`、`3.90 ±0.20`）→ 直接采用
② datasheet 只给标称值未给公差 → 按 **JEDEC 通用公差表**（§3.1.1）
③ datasheet 标注为 `BSC`（Basic）→ **BSC 本身即"标称值 + 由通用公差表约束"**

| # | 测试项 | 判定阈值 | 公差来源 |
|---|---|---|---|
| T1 | 封装族 | 同族（SOIC_N / SOP-8 / MSOP / TSOT23 视为不同族） | — |
| T2 | 本体宽 E1 | 双方公差区间**重叠即过** | ①datasheet → ②JEDEC |
| T3 | 封装长 D | 双方公差区间**重叠即过** | 同上 |
| T4 | 引脚总跨 E | 双方公差区间**重叠即过** | 同上 |
| T5 | 引脚间距 e | **标称值相同即过**（不要求公差区间重叠） | — |
| T6 | 本体总高 A | **候选件 max ≤ 原件 max** | — |
| T7 | 脚数 | 必须相同 | — |

**T2–T4**：不同厂商标称体系不同（`3.80/3.90/4.00` 三点值 / `3.80–4.00` 两点值 / `3.9 ±0.2` 单点值），
三者落在同一物理区间内即判过。数值全等不作为通过条件。

**T5**：
- 判**标称值**是否相同。`BSC` 与具体数值视为同一标称体系 —— `1.27 BSC` 与 `1.27 ±0.05` 标称值都是 1.27，**判过**
- 标称数值不同（如 1.27 vs 0.65）→ **判不过**
- 公差不作重叠要求

**T6**：判最坏情况下的高度干涉。
- 候选件 A(max) ≤ 原件 A(max) → 过
- 候选件 A(max) > 原件 A(max) → 不过

#### §3.1.1 JEDEC MS-012 通用尺寸

**适用范围**：3.9mm 宽窄体 SOIC（8/14/16 脚）。
**不适用**：MSOP（MO-047）、TSOT23（MO-229）、宽体 SOIC（MS-013，7.5mm 体宽）、EIAJ/JEITA SOP（5.3mm 体宽）。
超出本表 → 标「公差依据缺口」，**不许自行假定**。

| 尺寸项 | 符号 | MIN | NOM | MAX |
|---|---|---|---|---|
| 总高 | **A** | 1.35 | — | **1.75** |
| 支架台阶 | A1 | 0.10 | — | 0.20 / 0.25 |
| 本体厚 | A2 | 1.25 | — | 1.65 |
| 引脚宽 | B | 0.33 / 0.35 | — | 0.51 |
| 引脚厚 | c | 0.17 / 0.19 | — | 0.25 |
| **封装长** | **D** | **4.80** | 4.90 | **5.00** |
| **本体宽** | **E1** | **3.80** | 3.90 | **4.00** |
| **引脚总跨** | **E**（部分厂商标 **H**） | **5.80** | 6.00 | **6.20** |
| **引脚间距** | **e** | — | **1.27 BSC** | — |
| 脚长 | L | 0.40 / 0.50 | — | 0.93 / 1.27 |

| 站立平面 | S | 0.44 | — | 0.64 |

**默认区间**：T2 E1 = 3.80–4.00 ｜ T3 D = 4.80–5.00 ｜ T4 E = 5.80–6.20 ｜ T6 A max = 1.75

**尺寸符号不统一**：引脚总跨在部分厂商标 `H`、另一些标 `E`，数值区间相同（5.80–6.20）。
**判定依据是数值区间，不是符号写法。**

**`BSC`**：基本尺寸（Basic），偏差由 JEDEC 通用公差表约束（典型 ±0.05 mm），不在图中另标 min/max。

### 3.2 引脚类：功能等价判定（T8）

```
Step 1  对每个脚号，查两份原厂 datasheet，把该脚归入【功能类别 FCT】中的一类
        归类依据 = datasheet 的引脚功能描述原文，不是符号名
Step 2  类别不同 → 该脚计【不对应】，**计入差异**
Step 3  类别相同 → 查电气角色是否相容
        相容     → 该脚计【等价】，不计入差异
        不相容   → 该脚计【不对应】，**计入差异**
Step 4  统计：n = 等价脚数；k = 不对应脚数
Step 5  输出：n/N（等价格）+ k/N（不对应），N = 实际脚数
```

**等价 = 类别相同 ∧ 电气角色相容。两者缺一即不对应。**

**Mnemonic 的唯一作用**：确定该脚属于哪个功能类别（依据 datasheet 功能描述文字），以及提高报告可读性。
**符号是否相同，不参与等价判定。**

### 3.2.1 差异计数规则（k 的定义）

**k 只统计"不等价"的脚数。四类差异的计法：**

| 差异类型 | 定义 | 是否计入 k | 归入 |
|---|---|---|---|
| **① 命名差异** | 功能类别相同、电气角色相容，仅符号/命名体系不同（如 `D` ↔ `COM`、`S1` ↔ `NC`） | ❌ **不计入** | 视为等价，仅作报告可读性记录 |
| **② 电气参数差异** | 功能类别相同、电气角色相容，但参数值不同（如 Ron 20Ω vs 30Ω、门限 2.0V vs 0.8V） | ❌ **不计入** | 归入参数对比表 + 验证清单 |
| **③ 功能类别不对应** | 功能类别不同（如 `VL`(LOG-PWR) ↔ `NIC`(NC)） | ✅ **计入 k** | 判 PP-B，转 §4 |
| **④ 电气角色不相容** | 功能类别相同，但该类别内部电气约束不相容（如两脚同为 `LOG-IN`，参考点一个对 GND、一个对 VL） | ✅ **计入 k** | 判 PP-B，转 §4 |

**判定口诀：先看功能类别，类别相同再看电气角色。两者都过才是等价。
凡"类别不同"或"角色不相容"一律计入 k。命名不同不是差异，参数值不同也不是差异。**

**k = N − n。PP-A 的判据是 k = 0**，不是"差异都可接受"。

### 3.2.2 输出格式（强制）

必须同时给出以下三块，缺一不可：

```
【T8 结果】n/N 等价，k/N 不对应（N = 实际脚数，非固定 8）
【不对应项明细】逐脚列出：脚号 / 被替代件功能类别 / 候选件功能类别 / 差异性质
【命名差异项】单列，不计入 k（如有）
```

**【不对应项明细】的「差异性质」有两种取值**，对应 §3.2.1 的 ③ 与 ④：
- **功能缺失** —— 功能类别不对应（③）
- **电气角色不相容** —— 功能类别相同，但电气角色冲突（④）

**命名差异（①）与电气参数差异（②）不出现在本表中** —— 它们不进 k，
分别归入【命名差异项】与参数对比表。

**示例**：
> 【T8 结果】6/8 等价，2/8 不对应（N = 8）
> 【不对应项】pin5：LOG-PWR（逻辑电源 5V）↔ NC（无内部连接）—— **功能缺失**
> 【不对应项】pin6：LOG-IN（门限对 GND）↔ LOG-IN（门限对 VL）—— **电气角色不相容**
> 【命名差异项】pin1 D↔COM、pin2 S1↔NC、pin8 S2↔NO —— 均为 SW-COM / SW-NC / SW-NO 同类，**不计入差异**

### 3.3 功能类别表（FCT）

| 代码 | 功能类别 | 归类依据（datasheet 功能描述原文） | 常见符号（仅参考，不作判定） |
|---|---|---|---|
| **PWR+** | 电源正端 | "positive supply voltage" | VDD / V+ / VCC |
| **PWR−** | 电源负端 | "most negative supply potential" | VSS / V− / VEE |
| **GND** | 地 / 0V 参考 | "ground (0 V) reference" | GND |
| **LOG-PWR** | 逻辑电源 | "logic power supply" | VL / VLOGIC / VCCL |
| **LOG-IN** | 逻辑控制输入 | "logic control input" / "digital control input" | IN / EN / A0 |
| **SW-COM** | 开关端子 — 公共端 | "common" / "drain terminal" | COM / D |
| **SW-NC** | 开关端子 — 常闭 | "normally closed" / "source 1" | NC / S1 |
| **SW-NO** | 开关端子 — 常开 | "normally open" / "source 2" | NO / S2 |
| **AIO** | 模拟输入 / 输出 | "analog input or output" | A / AIO |
| **NC** | **无功能（内部无连接）** | "no internal connection" | NC / NIC / DNC / N.C. |

**`NC`（无功能）自成一类，且只与 `NC` 等价。** `LOG-PWR` vs `NC` 类别不同 → **不对应**（计入 k）。

### 3.4 Step 3：电气角色相容性检查

功能类别相同时须检查该类别内部的电气约束。**相容 = 等价；不相容 = 不对应（计入 k，转 §4）。**

| 类别 | 相容判据（须查原厂文档） | 不相容情形（计入 k） |
|---|---|---|
| PWR+ / PWR− | 绝对最大额定电压是否覆盖工作点 | 候选件耐压低于原件 |
| GND | 是否为同一 0V 参考 | 单电源下 V− 兼作 GND |
| **LOG-PWR** | **电压窗口是否覆盖系统逻辑电平** | 候选件逻辑电源窗口不覆盖系统实际电平 |
| **LOG-IN** | **判决门限区间与参考点** | **参考点不同（对 GND vs 对 VL）**、门限不相容 |
| SW-COM / SW-NC / SW-NO | 模拟信号范围、Ron、连续电流 | 信号范围不足、电流受限 |
| AIO | 信号范围、方向 | — |
| NC | 必须双方都是 NC | 任一方有功能 → 已在 Step 2 判为类别不对应 |

**本表「不相容情形」列只列「类别相同但电气角色不相容」的情况。**
「类别不同」的情形（如候选件该脚为 NC、原件为 LOG-PWR）已在 Step 2 判为不对应，不列入本表。

**LOG-IN 判定**：门限数值不同但参考点相同 → ② 不计入 k；**参考点不同 → ④ 计入 k**（即使门限数值相同）。

## §4 差异影响判断（PP-B 必做，不得回写 §3）

§3 判出 k > 0 后，才允许问「该差异是否阻断功能」。
**此问只能产出验证清单，不能产出「所以兼容」。**

### §4.0 强制产出物

每个**不对应脚**（k > 0 时逐脚执行）必须产出一张差异影响分析表，**四栏缺一不可**：

| 栏 | 检查什么 | 数据来源 | 缺项后果 |
|---|---|---|---|
| **① 差异引脚的功能影响** | 该脚在**新电路**中接什么、接错会导致什么具体后果 | 两份原厂 datasheet 的引脚描述 + 绝对最大额定 | → 差异影响未判定 |
| **② 外围电路兼容性** | 现有 PCB 的**上拉/下拉、去耦、保护电路、负载**是否仍成立；该脚原外围元件在换料后是否还需要 | 原理图 + PCB 文件（**须查图，不许推测**） | → 差异影响未判定 |
| **③ 逻辑电平与时序兼容** | 控制电平**阈值与参考点**、**开关时间**、**先开后合（BBM）时间**是否匹配 | 两份 datasheet 规格表 | → 差异影响未判定 |
| **④ 电气应力与可靠性** | 差异脚及受影响脚的**电压/电流**是否超出新器件额定；ESD / 闩锁 / 温度余量 | 两份 datasheet 绝对最大额定 | → 差异影响未判定 |

### §4.1 四栏的判定要点

**① 差异引脚的功能影响** —— 必须落到具体后果，不许写「可能影响功能」。
- 电源脚类别不对应（PWR+ ↔ PWR−）→ **电源反接**，通常直接损坏，须查新器件是否有保护
- 逻辑电源类别不对应（LOG-PWR ↔ NC）→ **逻辑电路无供电基准**，查新器件判决是否依赖该脚
- 开关端子类别不对应（SW-NC ↔ SW-NO）→ **常开常闭颠倒**，切换逻辑反转
- 信号脚类别不对应（AIO ↔ NC）→ **信号悬空或输出到错误节点**

**② 外围电路兼容性**
- 现有板上的上拉/下拉电阻，在新器件该脚为 NC 时**是否还需要**？
- 现有去耦电容是否仍匹配新器件的供电脚配置？
- 该脚是否兼作**其他电路的参考**（如 VL 兼作电平转换基准）？
- **必须在原理图/PCB 上确认，不许靠推断**

**③ 逻辑电平与时序兼容** —— 数值相同不等于兼容，须同时核**参考点**。
- 门限：VIH(min) / VIL(max) 两颗都要核，且须**同温度区间**
- **参考点**：对 GND / 对 VL / 对 VDD —— 参考点不同则同一电压含义不同
- 开关时间：tTRANSITION / tON / tOFF 是否满足系统时序预算
- **BBM（先开后合）**：新器件的 tD(min) 是否大于系统要求的死区时间？
  **BBM 不足会导致两路短暂直通**

**④ 电气应力与可靠性** —— 逐项对照绝对最大额定。
- 差异脚上的**最大电压 / 最大电流** vs 新器件该脚额定
- 全局：VDD-VSS 是否仍覆盖工作点（与 §5 判据不同：§5 判 80% 余量，此处判是否超绝对最大）
- ESD 等级、闩锁防护、温度范围是否仍满足

### §4.2 结论生成规则

**四栏全部完成且均无阻断项** → 可写「理论上不阻断，须实测确认」。

**任一栏缺失或存在阻断项** → **只写「差异影响未判定」**，并列出缺哪一栏。

**禁止**：
- 用①②③④中任一栏的结论替代全部四栏
- 在四栏未完成时写「基本兼容」「影响不大」「应该没问题」
- 把 §4 的任何结论回写进 §3

**PP-A 不进入本节**（k = 0，不存在不对应脚，无需验证）。

### §4.3 验证清单格式

**「实测确认」不是验证项** —— 须写明「测什么、测出多少算过」。

| # | 验证项 | 方法 | 判据 | 责任方 |
|---|---|---|---|---|
| V1 | … | … | 定量阈值 | 技术端 |

### §4.4 输入版本变更的失效联动（**强制**）

§3 逐脚判定与 §4 四栏检查均依赖「**原厂引脚定义 / 功能说明（datasheet 及其修订版）**」。该文档一旦换版本，下游结论**不得沿用**。

| 必须动作 | 说明 |
|---|---|
| **§3.2 逐脚判定必须重跑** | 旧版 n/N、k/N 作废；须基于新版文档重算 |
| **§4 四栏结论自动失效** | 四栏须全部基于新版重新填写，不得沿用旧版结论 |
| **§3.3 类别表 / §3.4 电气角色检查须复核** | 引脚定义换版可能改变某脚的功能类别或电气角色 |
| **变更记录须写明** | **新旧文档版本号 + 差异脚**（哪几脚、原定义 → 新定义） |
| **§5 降额闸 / §5b 性能闸须核对取值来源** | 同一参数在两版中数值不同（abs max、额定值、特性曲线）时，须确认本次判定用的是哪一版，并在输出中注明 |

**部分变更的处理（避免过度重跑，同时防止漏判）**：

| 变更范围 | 处理 |
|---|---|
| **仅部分脚的定义调整**（**脚号未重排、引脚表无增删**） | **可只重跑受影响的脚**，未受影响的脚旧结论可沿用，但输出中须**逐脚注明**「基于原厂文档 vX.Y 的脚 N 结论，未经 vZ 重跑」 |
| **脚号重排**（脚序 / 编号变化）或**引脚表有增删** | **必须全表重跑**：§3.2 与 §4 四栏全部作废重填，**不得部分沿用** |

**「受影响脚」的完整定义（强制，防漏脚）** —— 部分变更时须**同时**覆盖下列三类，**缺一不得算"已确定受影响集合"**：

| # | 类别 | 说明 |
|---|---|---|
| ① | **变更脚本身** | 引脚定义被调整的那一只脚 |
| ② | **与变更脚构成同一电气功能的脚** | 如 **PWR 脚变更 → 与其并接的同一电源网络各脚、与其构成回流路径的 GND 脚**；差分对成员须成对重跑 |
| ③ | **§3.4 电气角色相容性检查所涉网络的所有脚** | 该脚**新旧**定义所连、可能因角色判定翻转而受影响的所有脚 |

**兜底铁律：若无法确定"受影响脚"的完整集合 → 一律全表重跑，不得部分重跑。**
宁可多跑，不可因集合不全而漏判（② ③ 两类最易被漏）。

**禁止**：原厂文档换版后只更新一处、其余沿用旧版；凭"应该没影响"跳过重跑。
**本项属 §7.1 改判记录的必填输入变化**（依据文档版本 / 日期为必填项）。

## §5 降额闸（与 PP 判定独立，AND 关系）

**公式**：占用率 = 工作点电压 / 绝对最大额定电压；**阈值 ≤ 80%**

**数据来源**：两份原厂 datasheet 的绝对最大额定栏。缺项 → 判 ⚠️ 数据缺失。

**降额闸结论与 PP 判定并列给出，不合并、不互相抵消。**
PP-A 但降额不过 → 按 §6.1 输出「需评估 —— 降额超线，需豁免」。

**降额闸与性能闸的 ⚠️ 不同源，结论档位也不同：**

| 闸 | ⚠️ 的含义 | 来源 | 结论档位 |
|---|---|---|---|
| **降额闸** | **⚠️ 数据缺失** —— 原厂未标绝对最大额定 | datasheet 无该项 | **只能「需评估」**，**禁止**「有条件通过」 |
| **性能闸** | **⚠️ 待实测** —— 参数值未公开或未测 | datasheet 未给该项 | 可为「有条件通过」（须附实测方案） |

**降额闸的状态取值为：✅ 过 / ❌ 不过 / ⚠️ 数据缺失。无 ⚠️ 待实测这一取值。**
**降额闸为 ⚠️ 数据缺失 或 ❌ 不过 时，均不得进入「有条件通过」**（§6.2）。
原厂未标绝对最大额定 → 判 **⚠️ 数据缺失** → 按 §6.1 输出「需评估 —— 降额数据缺失」。

**两者不得混用**：性能闸的 ⚠️ 可以进「有条件通过」，降额闸的 ⚠️ 不可以。

**降额只管"电压/电流余量"，不管"性能"。** 电气可替代性由 **§5 降额闸 + §5b 性能闸** 两道共同决定。

## §5b 性能闸（与 PP 判定独立，AND 关系）

**PP-A + 降额通过 + 性能闸不过 → 结论仍不是「可直接替」。**

### §5b.1 必比参数清单

| # | 参数 | 判据方向 | 缺口处理 |
|---|---|---|---|
| **P1** | 导通电阻 Ron | 候选件 **≤** 原件（同条件） | 任一方未给 → ⚠️ 待实测 |
| **P2** | **Ron 平坦度 / flatness** | 候选件 **≤** 原件 | 任一方未给 → ⚠️ 待实测 |
| **P3** | 漏电流 | 候选件 **≤** 原件 | 任一方未给 → ⚠️ 待实测 |
| **P4** | 电荷注入 | 候选件 **≤** 原件 | 任一方未给 → ⚠️ 待实测 |
| **P5** | 开关时间 tON / tOFF / tTRANSITION | 候选件 **≤** 原件，或系统预算容得下 | 任一方未给 → ⚠️ 待实测 |
| **P6** | 先开后合 BBM 时间 tD | 候选件 tD(min) **>** 系统要求死区 | 任一方未给 → ⚠️ 待实测 |
| **P7** | 带宽 / 关断隔离 / 串扰 | 按应用频率与通道数判 | 任一方未给 → ⚠️ 待实测 |
| **P8** | 全温参数漂移 | 候选件全温指标 **≤** 原件全温指标 | **只给 25°C 值 → ⚠️ 待实测** |
| **P9** | 通道间 Ron 匹配（ΔRON） | 候选件 ΔRON **≤** 原件 ΔRON | 任一方未给 → ⚠️ 待实测 |

**P2 与 P1 的优先级**：增益切换场景下 **P2 > P1** —— 平坦度不可标定补偿，Ron 绝对值可补偿。

### §5b.2 比对纪律

**每个数进比对表必须带三标签**：① 供电条件 ② 温度条件 ③ 信号/负载条件。

- 三标签不一致的两个数**不许比大小**，只能并列写「条件 A 下 X，条件 B 下 Y」
- **typ 只跟 typ 比，max 只跟 max 比，温区必须一致**
- 同一颗料有多张参数表（双电源/单电源/不同 VL）→ **必须写明取自哪一张**
- 对方没给的条件 = **缺口**，不许用相邻条件的值代填

### §5b.3 应用工况决定参数权重

**判定前必须先确认开关在电路里的位置：**

| 应用工况 | 第一致命 | 次要 | 常被误当成瓶颈的项 |
|---|---|---|---|
| **增益切换（串在信号通路）** | **Ron 平坦度** → 非线性/THD | 电荷注入、开关时间 | Ron 绝对值 |
| **增益切换（接虚地端）** | Ron 绝对值 + 漏电流 | 平坦度权重下调 | 平坦度 |
| **采样保持** | **电荷注入** + 漏电流 | 开关时间、Ron | Ron |
| **数据采集前端/单路 MUX** | 平坦度 + 漏电 + 建立时间 | Ron 绝对值 | Ron |
| **多路 MUX 切换** | **关断隔离 + 串扰 + 平坦度** | 漏电、建立时间 | Ron 绝对值 |

**多路 MUX 场景补充判据**：
- **关断通道的漏电会直接串到导通通道** → 漏电与关断隔离须**同时**满足，不可只比 Ron
- **串扰随通道数累加** —— N 路 MUX 的总串扰预算须按最坏路径叠加校验
- **每路 Ron 的差异会表现为通道间增益不一致** → 须核 P2（平坦度）与 P9（ΔRON）

**电流校核**：开关电流 ≈ 最大信号幅度 ÷ 反馈电阻。算得结果与器件的连续电流额定比较，
低于额定则电流限制不构成障碍。

### §5b.4 性能闸结论

| 情况 | 性能闸判定 |
|---|---|
| P1–P9 全部满足 | ✅ 过 |
| 任一项**已核实**不满足 | ❌ 不过 → §6 输出「需评估 —— 性能不满足（列明 P#）」 |
| 任一项**双方均未给** | ⚠️ **待实测**，闸不得记「过」也不得记「不过」 |
| 任一项**一方未给** | ⚠️ **待实测**，不得默认对方更好或更差 |

**禁止**：把「未给」记为 ✅ 或 ❌ ｜ ⚠️ 不给实测方案（方案见 §6.3，缺失则本轮判定未完成）。

**⚠️ 待实测 升级为 ✅ 过 或 ❌ 不过 的唯一途径：实测出数，或原厂补发数据。**

## §6 结论合成规则

**结论只由 §6.1 查表生成，不得在表外生成。**

### §6.0 闸状态是四态

| 状态 | 含义 | 何时用 |
|---|---|---|
| **✅ 过** | 已核实数值满足判据 | 两边都有数据，且候选件优于/等于原件 |
| **❌ 不过** | 已核实数值不满足 | 两边都有数据，且候选件劣于原件，或超绝对最大 |
| **⚠️ 数据缺失 / 待实测** | 数据缺失，无法判定 | 任一方未给该参数 |
| **⚠️ 未判定** | **输入整份缺失，该闸根本无法开始** | 原厂引脚定义表 / 封装图 / 位定义表等**整套输入**未取得 —— **不得输出 PP-A / PP-B / PP-C**，只落「需评估」，须索取后重跑 |

**⚠️ 不得记为「过」或「不过」。** 缺数据记为合格或不合格均属错记。

**「⚠️ 未判定」与「⚠️ 数据缺失」的分界（不得混用）**：
- **未判定** = 输入**整份缺失**，闸没有可判的对象（如：拿不到原厂引脚定义表，逐脚闸无从逐起）；
- **数据缺失 / 待实测** = 输入在，只是其中**某个参数值**没给（如：引脚定义表在手，但 Ron 全温值缺）。
- 判别口诀：**缺的是「图纸」还是「数值」？缺图纸 → 未判定；缺数值 → 数据缺失。**

**⚠️ 按闸分为两种，结论档位不同**（见 §5 与 §5b）：

| 闸 | ⚠️ 的含义 | 结论档位 |
|---|---|---|
| **降额闸** | **⚠️ 数据缺失** —— 原厂未标绝对最大额定 | **只能「需评估」**，禁止「有条件通过」 |
| **性能闸** | **⚠️ 待实测** —— 参数值未公开或未测 | 可为「有条件通过」，须附实测方案 |

**⚠️ 的强制义务**：必须给出可执行的数据获取方案，否则本轮判定视为**未完成**。
- 性能闸 ⚠️ 待实测 → 实测方案（§6.3）
- 降额闸 ⚠️ 数据缺失 → **在报告中写明索取 abs max 的具体途径**（原厂联系渠道 / 文档版本号）；无原厂数据时按 JEDEC 标准推断并标注为推断值。**abs max 为原厂规格数据，客户无法实测获得。**

### §6.1 结论合成表（PP × 降额 × 性能）

| PP 判定 | 降额闸 | 性能闸 | 客户验证 | **输出措辞** |
|---|---|---|---|---|
| PP-A | 过 | 过 | 已过 | **可直接替** |
| PP-A | 过 | 过 | 未过 | 需评估（差客户验证） |
| **PP-A** | **过** | **⚠️ 待实测** | 任意 | **有条件通过 —— 封装与降额均通过，但 [列明待实测的 P#] 未查到公开数据，须送样实测后判定**（§6.3 必附） |
| PP-A | 过 | **❌ 不过** | 任意 | **需评估 —— 封装与降额均通过，但性能不满足（列明 P#）** |
| PP-A | **❌ 不过** | 任意 | 任意 | **需评估 —— 封装可直接换，但降额 XX% 超 80% 线，需豁免** |
| **PP-A** | **⚠️ 数据缺失** | 任意 | 任意 | **需评估 —— 降额数据缺失（原厂未标绝对最大额定），须在报告中写明索取 abs max 的具体途径后重跑；无原厂数据时按 JEDEC 标准推断并标注为推断值**（途径要求见 §6.0 与 §6.4 第 6 项） |
| **PP-B** | 任意 | 任意 | 任意 | **需评估 —— 封装兼容，存在 k 处不对应（已定位到脚），差异影响未判定，须实测验证**（§4 四栏必附） |
| **改板方案**（非 PP 判定） | — | — | — | **非 PP 判定。入口：① 机械可装但存在不对应，且可经改板/飞线达成对应；② 机械不可装，但可经改板使用。输出：需改什么 → 改板可行性 + 成本量级** |
| PP-C | — | — | — | **不可直换**；若经评估可改板 → 改列「改板方案」 |
| **⚠️ 未判定** | — | — | — | **需评估 —— 未取得 [原厂引脚定义表 / 封装图 / 位定义表]，[机械闸 / 逐脚闸] 未判定，不得输出 PP-A / PP-B / PP-C；须索取缺失输入后重跑**（缺失清单必附） |
| **任一** | — | — | **未过** | **不得出现「可直接替」** |

**任何一闸为「❌不过」，最高只能是「需评估」。**
**降额不过 + 性能不过** → 两条理由都要写。

**「改板方案」与 PP-B 互斥**（§2.2）：能经改板达成对应的，**就不是 PP-B**，走改板方案行；
PP-B 是「改板也无法达成对应」的那一类。两个集合不重叠，表中不设「PP-B → 改板方案」的过渡行。

**改板方案的两个入口**：① 机械可装（T1–T7 全过）+ 存在不对应 + 经改板可达成对应；
② 机械不可装（PP-C）+ 经改板可使用。② 入口包含全部机械尺寸/脚数不符的情况。

### §6.2 「有条件通过」的严格定义

**成立条件（三条全满足）**：
1. **PP-A**（k = 0，§3 已全过）
2. **降额闸 ✅ 过**（不接受 ⚠️ 数据缺失）
3. **性能闸内无任何 ❌ 不过项**，仅有 ⚠️ 待实测项

**必须同时写明（缺一即降级为「需评估」）**：
- 待实测的**具体参数编号**（P#）
- 该参数的**判据方向**（须 ≤ 原件 / 须 > 死区 / 须满足某门限）
- **实测方案**（§6.3）
- **实测前的替代动作约束**：实测出结果前，**不得下批量订单**（可送样、可小批试产，须明示）

**不成立的情形（一律判「需评估」）**：
- 降额闸为 ❌ 不过 或 ⚠️ → 降额闸须为 ✅ 过
- 性能闸存在任一 ❌ 不过项
- PP-B / PP-C
- 待实测项无对应实测方案

**「有条件通过」与「需评估」的区别**：
- **有条件通过** = 机械与安全余量已确认，只差性能数据，**实测通过即可直接替**
- **需评估** = 存在已知缺陷/差异/降额问题，**须先解决问题再谈实测**

### §6.3 待实测项的方案格式（强制）

| 参数 | 测什么 | 怎么测 | 通过判据 | **样品数量** | 责任方 | 期限 |
|---|---|---|---|---|---|---|
| P2 平坦度 | Ron 随 VCOM 变化的幅度 | 扫 VCOM 全范围，记录 Ron 曲线，取峰谷差 | 峰谷差 ≤ 原件（待实测后填入具体数值） | **≥ 3 颗**（同型号不同片号） | 技术端 | 送样后 X 周 |

**样品数量为必填列，缺即方案不完整。** 最低要求（缺省值）：

| 实测类别 | 覆盖参数 | **最低样品数量** |
|---|---|---|
| **常规电参数类** | P1 Ron、P3 漏电流、P4 电荷注入、P5 开关时间、P6 BBM、P9 Ron 匹配 | **≥ 3 颗** |
| **特性 / 频率类** | P2 Ron 平坦度、P7 带宽 / 隔离 / 串扰 | **≥ 3 颗** |
| **全温类** | P8 全温参数漂移 | **≥ 5 颗**（须覆盖上下限温点） |
| **封装 / 机械类（§3 项）** | 键合拉力、截面 / X-ray、焊接性 | **≥ 3 颗**，且**破坏性项须独立备样** |

**取样规则（强制）**：样品须为**同一型号的不同片号（不同 lot / date code）**——全取同一片号时，"多颗"不反映批次差异，等于没测。
**破坏性 / 非破坏性**：**破坏性项独立备样**，测完不得用于其他项；**非破坏项同一颗可依次测多项**，但须确保**前一项不改变后一项的测量条件**。
**报数须分组登记**（独立备样组 / 非破坏复用组），**不得把同一颗计成多颗**。
**可按品类文件细化，但不得低于上表缺省值**，**也不得以"样品不足"为由免测**。

**判据栏禁止写「符合要求」「与原件相当」** —— 必须写成可量化的形式。
**若判据所需的基准值本身缺失**（如两者平坦度都没给），写「先测候选件绝对值，
并同时测一颗已知合格的参照件建立基准」—— **不许因基准缺失而放弃该项判定**。

### §6.4 输出措辞的必含项

| # | 必含 | 说明 |
|---|---|---|
| 1 | **n/N 与 k/N**（N 为实际脚数） | 禁止写 "4/8" 不说明 N 来源 |
| 2 | **不对应项逐脚明细** | 脚号 + 两边功能类别 + 差异性质 |
| 3 | **命名差异项单列** | 注明不计入 k |
| 4 | **各闸四态状态与依据** | 逐闸标注：✅ 过 / ❌ 不过 / ⚠️ 数据缺失（降额闸）/ ⚠️ 待实测（性能闸）/ **⚠️ 未判定（输入整份缺失，§6.0）** |
| 5 | **缺口清单** | 逐项标注所属闸：降额闸缺口 → ⚠️ 数据缺失；性能闸缺口 → ⚠️ 待实测 |
| 6 | **数据获取方案** | 性能闸 ⚠️ 待实测项须给出实测方案（§6.3）；降额闸 ⚠️ 数据缺失须**在报告中写明索取 abs max 的具体途径**（原厂联系渠道 / 文档版本号），或按 JEDEC 标准推断的依据并标注为推断值。**abs max 为原厂规格数据，不具备实测条件** |
| 7 | **实测前的动作约束** | 「有条件通过」时必须写明不得批量下单 |

## §7 改判与改标准纪律

| 允许 | 禁止 |
|---|---|
| 发现新事实（新的原厂文档、实测数据）→ 更新 §3 输入值后重跑 | 凭"重新想了一遍"改判 |
| 发现标准本身有漏洞 → **改标准全文** | 同一批输入值下改判 |
| 客户提出新判定口径 → 先改标准，再重跑 | 口头改判、不留痕 |

**每次改判必须能回答：新增/变化的是哪一个具体输入值（哪份原厂文档、哪一页、哪个数值）。**
答不出来 = 是在改判，不是在判定。

### §7.1 改判记录必填项

**必须记成「从什么变成什么，依据哪一版文档」。**

| # | 必填 | 格式 | 示例 |
|---|---|---|---|
| 1 | **判据项** | 哪一项判据（T1–T8 / P1–P9 / 降额 / FCT 类别） | `T8 逐脚功能等价` |
| 2 | **旧值** | 改判前的值/结论 | `8/8 等价，0 处不对应 → n=8` |
| 3 | **新值** | 改判后的值/结论 | `7/8 等价，1 处不对应（pin5）→ n=7` |
| 4 | **旧档位 → 新档位** | 结论档位的迁移 | `PP-A → PP-B` |
| 5 | **依据文档 + 版本/日期** | 文档名、版本号或 Release 号、页码、访问日期 | `候选料二 datasheet Release A (Dec.2025) p4` |
| 6 | **变更类型** | 新增事实 / 修正读数 / 改判据口径 | `改判据口径` |
| 7 | **触发人 + 日期** | 谁提出、什么时候 | `用户，2026-10-05` |
| 8 | **是否已重跑全表** | 是 / 否 | `是，全表重跑` |
| 9 | **下游影响** | 档位变化影响谁、要不要通知、已通知谁 | `档位由 PP-A 降为 PP-B，须重新送样；已告知技术端` |

**第 4 项须单列**：数值变化只影响描述精度，档位变化影响结论等级、验证义务与可执行动作。

**第 9 项须填写**：档位降级后，此前基于旧档位推进的动作（送样、下单、验证安排）须回头确认。

**格式模板**：
```
改判记录 #N
判据项：______
旧值：______ → 新值：______
旧档位：______ → 新档位：______
依据：______（版本/日期，页码）
变更类型：新增事实 / 修正读数 / 改判据口径
触发：______（人，日期）
已重跑全表：是 / 否
下游影响：______（须通知谁 / 已通知谁 / 需回退的动作）
```

**纪律**：
- 一律**追加**，不许覆盖或删除旧记录
- 依据文档须为可复查实体（原厂 PDF / 官方规格页 / 实测报告）
- 源自改标准的，须记旧标准版本 → 新标准版本 + 变更原因
- 同一批输入值下的改判**一律禁止**

### §7.2 改判记录与标准修订记录的分工

> **定稿说明（自本版起进入稳定期）**：本标准自本版起进入稳定期。后续修订**仅限重大变更**（新增品类、判据口径变更、档位定义变更）；**日常边界情形的澄清以「附录：待澄清事项」形式累积，不单独发版**——澄清条目**不改变现行版本号**，随下一次重大变更一并纳入正文。
> **判据（防"以澄清之名改判据"）**：澄清只解决"边界怎么判"；**一旦某条澄清实际改变了判据阈值或档位归属，它就不是澄清，而是重大变更** → 须按 §7.2 处置并递增版本号。

| | 改判记录（§7.1） | 标准修订记录 |
|---|---|---|
| 记什么 | **输入值**变了什么 | **判据**变了什么 |
| 影响 | 本次判定的结论 | 以后所有判定的口径 |
| 触发 | 新文档 / 新实测 / 修正读数 | 发现标准漏洞 / 客户新口径 |
| 举例 | 某参数读数修正 | 判定依据口径变更 |

**两者性质不同，不许混成一张表。**

### 附则：PP 判定与「改板方案」的分工

PP 判定只回答「不改板能不能换」。改板方案是另一条路径，两者互不替代：

| | PP 判定 | 改板方案 |
|---|---|---|
| 前提 | **不改板** | 需改板（换封装 / 改走线 / 飞线） |
| 输出 | PP-A / PP-B / PP-C | 改板可行性 + 改哪里 + 成本量级 |
| 分界 | 机械能装吗？能装才走 PP | 装不上或需重映射 → 走改板 |

**禁止**把改板方案写成「PP-B 但可凑合用」——允许重映射会使 PP-B 退化为 PP-C。

## §8 常见错误用法（自检）

| ❌ 错误 | ✅ 正确 | 后果 |
|---|---|---|
| 16 脚器件写 "7/8" | 写 "n/16"，N 取实际脚数 | 分母错，计数无意义 |
| 把命名差异（`D` vs `COM`）计入 k | 不计入，归入「命名差异项」单列 | k 被虚高，误判为 PP-B |
| 把参数差异（Ron 20 vs 30）计入 k | 不计入，归参数对比表 | 同上 |
| PP-B 靠改板/飞线达成对应 | 改列「改板方案」 | PP-B 退化成 PP-C，两档失效 |
| 只写 "存在差异" | 写 k/N + 逐脚明细 + 差异性质 | 客户无法判断要不要改板 |
| 写 "pin-to-pin 兼容，但有差异" | 禁称 pin-to-pin | 禁称就是禁称，不许带但书 |
| T2–T4 只说"区间重叠"不写公差来源 | 注明取自 datasheet 还是 JEDEC MS-012 | 判定不可复现 |
| T5 要求 pitch 数值全等 | 判**标称值**相同 | 过严，误杀合格替代料 |
| T6 只写"上限相同" | 写明 **候选件 A(max) ≤ 原件 A(max)** | 无判定规则 |
| 拿 MS-012 套 MSOP / TSOT23 / 宽体 / EIAJ | 查对应标准，缺口就标缺口 | 公差依据错误 |
| 因封装符号不同就判不一致（如 E vs H 指同一尺寸） | 判数值区间 | 误判 |
| §4 只写"必须逐项列出"却不写内容 | 走 §4.0 四栏表 | 等于没判，无法执行 |
| 用某一栏的结论替代四栏 | 四栏全过才能写「不阻断」 | 漏掉隐蔽项 |
| 写「实测确认」当作验证项 | 写明测什么、判据多少 | 技术端无法执行 |
| 「差异影响未判定」后又补「应该没问题」 | 未判定就停在未判定 | 结论自相矛盾 |
| 只过降额闸就写「电气满足」 | 降额只管电压电流余量，性能另走 §5b | 漏掉 Ron 平坦度等致命项 |
| 把「未给」记为性能闸「过」 | 记为「待实测」 | 缺口被伪装成通过 |
| 把「未给」记为性能闸「不过」 | 记为「待实测」 | 缺数据被错记成不合格 |
| 把「输入整份缺失」记成数据缺失 / 硬给 PP-A/B/C | 记为 **⚠️ 未判定**，只落「需评估」，索取后重跑（§6.0、§6.1） | 拿不到图纸却硬出结论，等于没判 |
| 用「未判定」回避可取证的缺数值项 | 缺的是**数值** → 数据缺失 / 待实测；缺的是**图纸** → 才是未判定 | 两种 ⚠️ 混用，缺口被夸大或掩盖 |
| 用「有条件通过」包装已知不满足的项 | 有条件通过要求性能闸无 ❌ 项 | 掩盖已知缺陷 |
| 降额闸为待实测却给「有条件通过」 | 降额必须 ✅ 过才可 | 电压余量是安全问题 |
| 实测方案写「符合要求」「与原件相当」 | 写可量化判据 | 技术端无法执行 |
| Ron 只比 typ、漏电只比 25°C | typ 跟 typ、全温跟全温 | 常温过、125°C 不过 |
| 用 25°C 的 Ron 平坦度下全温结论 | 找全温数据，找不到就落实测 | 高温失真 |
| 只写「修正后结论改为 X」 | 写旧值 → 新值 | 追不到变更点，无法回滚 |
| 依据写「重新核对 datasheet」 | 写文档名 + 版本/日期 + 页码 | 不可复查 |
| 依据写「之前读错了」 | 写正确读数 + 误读来源 | 错在哪一步无法定位 |
| 改判后只更新结论，不重跑全表 | 记录「已重跑全表：是/否」 | 其他判据项状态可能已连带变化 |
| 覆盖或删除旧改判记录 | **一律追加** | 改判链断裂 |
| 把改判与改标准混成一张表 | §7.1 记输入值 / 单独记判据 | 口径变更看起来像个案修正 |
| 同一批输入值下改判 | 先找出变化的输入值，或改标准 | 违规，不是判断 |
| 类别相同但电气角色不相容却计【等价】 | 计入 k（差异类型④） | 与 §1「等价 = 类别相同 ∧ 角色相容」矛盾 |
| 把「电气角色不相容」归入参数差异（②） | 参数差异的前提是**角色相容** | 漏判，PP-A 被虚高 |
| 降额闸 ⚠️ 放进「有条件通过」 | 降额闸 ⚠️ 只能「需评估」 | 电压安全余量被挂条件 |
| 改判只记数值变化，不记档位迁移 | 旧档位 → 新档位，单列（§7.1 第 4 项） | 下游看不出结论等级已变 |
| 改判后不评估下游影响 | 填「下游影响」项（§7.1 第 9 项） | 基于旧档位的动作继续推进 |
| 发布新版本前不做回测 | 3~5 个案例回测并留档（§8.1） | 标准可能误杀好料 |
| 按 §2.1 字面判 PP-A（只看类别对应，不看电气角色） | PP-A 判据是 **k = 0**，类别与角色双重对齐 | 与 §3.2 冲突，角色不相容的脚会被漏掉 |
| §3.2.2 的差异性质只写「功能缺失」 | 两种取值：功能缺失 / 电气角色不相容 | 漏报 ④ 类不对应 |
| 合成表里出现「PP-B → 改板方案」行 | 二者互斥，删掉该过渡行 | 与 §2.2 定义直接矛盾 |

**上表末三行，以及已删条目，均为已修正项，保留用于防止后续修订回退。**

### §8.1 标准的实用性检验（**发布新版本前必做**）

**判定标准若导致「绝大多数候选都过不了」，须检查标准本身，不淘汰候选。**

**执行时机：每次发布新版本前必做。**

**回测记录（必填，归档留存）**：

| 回测日期 | 回测人 | 回测案例 | 已知合格结论 | 标准判定结果 | 是否一致 | 不一致原因 |
|---|---|---|---|---|---|---|
| YYYY-MM-DD | （人） | 案例 1 | （已知合格结论） | （标准判定结果） | ☐ 一致 ☐ 不一致 | |
| YYYY-MM-DD | （人） | 案例 2 | （已知合格结论） | （标准判定结果） | ☐ 一致 ☐ 不一致 | |
| YYYY-MM-DD | （人） | 案例 3 | （已知合格结论） | （标准判定结果） | ☐ 一致 ☐ 不一致 | |

**每一行的每一格都须填写**（日期、回测人、已知合格结论、标准判定结果、是否一致）。
- 不得留空，**也不得只在首行填写后其余行留空** —— 留空会被读成「该行未回测」
- 同一次回测覆盖多案例时，各行重复填写相同日期与回测人
- 若采用合并单元格，须在表下注明「本表 N 行同属 YYYY-MM-DD / XXX 的一次回测」
- 案例数 **3~5 个**，须覆盖不同品类与档位（至少 1 个 PP-A、1 个 PP-B 或 PP-C）
- **至少含 1 个「命名体系不同但功能等价」的案例**
- **不一致且无法说明原因 → 禁止发布该版本**

**自查三条**：
1. 3~5 个已知合格案例回测，核对判定结果
2. 判「功能完全可用的料」为不通过 → 检查标准
3. 检查是否把命名体系差异误判为功能差异

**回测记录不得删除或改写。**

### §8.2 §4 四栏的常见漏项

**②外围电路兼容性**：

| 漏项 | 后果 |
|---|---|
| 没查原理图，假定该脚走线只连本芯片 | 上拉/去耦仍接在新器件的 NC 脚上，形成异常负载 |
| 忽略**上拉/下拉电阻**在换料后是否还需要 | 逻辑输入悬空，状态随机 |
| 没核 **BBM（先开后合）时间** | 两路短暂直通 |
| 门限只比数值，**没比参考点** | 同一电压在两器件上含义不同 |
| 门限没对齐**温度区间** | 常温过、125°C 不过 |

### §8.3 性能闸常见漏项

| 漏项 | 后果 |
|---|---|
| **只比 Ron 绝对值，不比平坦度** | 增益切换场景的非线性误差超标 |
| 只比 25°C 值，不比全温漂移 | 常温合格、高温失真 |
| 漏掉**电荷注入** | 采样保持/增益切换瞬态误差超标 |
| 漏掉 **BBM 时间** | 两路短暂直通 |
| 漏掉**关断隔离/串扰** | 高频或多通道场景互相串扰 |
| 用「同型号的典型应用电路没问题」代替比对 | 无出处，属推测 |

**增益切换场景下 P2（平坦度）> P1（Ron 绝对值）。**
常见误判是死盯 Ron 绝对值（好算、好标定），而真正致命的是随信号变化的平坦度。

### §8.4 「有条件通过」的滥用红线

| # | 红线 | 后果 |
|---|---|---|
| 1 | **「有条件通过」要求降额闸必须 ✅ 过**；❌ 不过与 ⚠️ 数据缺失均不可 | 电压余量是安全底线，不许挂条件 |
| 2 | 性能闸若已有 ❌ 不过项 → 降级为「需评估」 | 已知缺陷不能靠条件掩盖 |
| 3 | PP-B / PP-C **不适用**本档位 | 属另一结论档位，混用会造成误解 |
| 4 | 待实测项**无实测方案** → 视为未判定 | 条件是空的，等于没判 |
| 5 | 「有条件通过」**必须写明不得批量下单** | 否则会被当成「可以下单了」 |
| 6 | 实测出结果后**必须回头改判** | ⚠️ 不是终点，挂着交付是耍赖 |

**判别口诀：「有条件通过」≠「可以先替了看看」。**
**它是"机械与安全余量已确认，只差性能数据，实测通过即可直接替"。**
若实测很可能不通过、只是抱着试试看的心态 → 那就是「需评估」。

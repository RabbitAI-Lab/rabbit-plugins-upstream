# 数据源分级与时效要求

## 分级（可信度从高到低）

| 级别 | 来源 | 用途 | 输出时的标注 |
|---|---|---|---|
| **L1 一手** | 原厂官网 / datasheet 原文 / 原厂销售 | 参数、生命周期、认证、PCN | 直接引用 + 章节号 |
| **L1 第二信源** | **semiee.com**（2026-10-04 用户指定） | **原厂官网查不到规格书时，用它取原厂 PDF** | (semiee 转原厂 PDF, YYYY-MM-DD) |
| **L1 授权代理** | 安富利(Avnet)、贸泽(Mouser)、DigiKey、立创、云汉芯城等授权渠道页 | 价格、库存、交期、可得性 | (授权代理, YYYY-MM-DD) |
| **L2 自有成交** | 本企业历史真实成交价/库存/历史供应商（**仅在已接入本企业库的机器上可用**） | 最贴近真实成交 | (自有成交, YYYY-MM-DD) |
| **L3 二手** | 电子发烧友、博客、社区贴、非授权电商 | 仅线索，不可当参数依据 | 标「二手，需回原厂确认」 |
| **L5 禁用（按特征识别）** | **内容农场型资料站**（识别特征见下节）** | **永不检索、永不引用** | — |
| **L4 无** | 查不到 | — | 写「未核实」+ 给查询路径 |

## 禁用来源（按特征识别，不点名）

| 识别特征 | 不采信原因（与原厂资料比对结论） |
|---|---|
| **页面标称参数与原厂规格书对不上**（曾见：标称 36V 高压，原厂 PDF 实为 1.5~5.5V；且型号与企业归属错配） | 参数不得作为任何依据，一律回原厂 datasheet 确认 |
| **文章结构固定为「企业概况 → 三大优势 → 头部客户验证」** | 疑为批量生成内容，多家页面同一模式，参数不可采信 |

**判别方法**：命中上述任一特征即按 L5 处理，不采信、不引用、不计入遍历家数；参数一律回原厂 datasheet 确认。

**规则**：**凡命中上述特征的来源一律跳过，不检索、不采信、不引用、不计入遍历家数。**

## 字段级取证可信度（2026-10-10 立规）

> 上面那张分级表是**来源级**，回答"这个站可不可信"。
> 但**同一个站的不同字段，可信度不同**：渠道页的价格是它自己系统里出的，封装是它转录原厂的。
> 只按来源分级，会把转录字段当一手采信——这是封装判定反复出错的模型根因。

### 判什么

每个字段的**一手源是唯一主体**，不由站点等级决定。

### 怎么判

**判据：谁产生的数据，谁才是该字段的一手源。**

- 参数类（封装、电气、绝对最大额定、生命周期、认证）→ **由原厂产生** → 只有原厂文档是一手；任何渠道页、聚合站都是转录。
- 商务类（价格、库存、交期、MOQ）→ **由渠道产生** → 渠道页才是一手；原厂官网反而不掌握实时库存与成交价。

→ 两者的**一手源是不同主体**，不是"同一个来源的不同可信度等级"。混为一谈即错。

| 字段 | 唯一可采信源 | 渠道页该字段的地位 |
|---|---|---|
| 封装 / 脚位 / 型号后缀含义 | 原厂 **Ordering Guide / Package Option 表** | 仅线索，**不得采信** |
| 逐脚定义（含 NC / NIC / VL 类冷门脚） | 原厂 datasheet **Pin Configuration / Pin Description** | 仅线索，不得采信 |
| 电气参数 | 原厂 datasheet 规格表，**须带测试条件** | 仅线索 |
| 绝对最大额定值（abs max） | 原厂 datasheet **Absolute Maximum Ratings** 章 | 不得采信 |
| 生命周期 / PCN-PDN | 原厂官网型号页 / 原厂正式通知 | 需回原厂确认 |
| 认证（车规 / 工规 / 安规） | 原厂 datasheet / 发证机构名录 | 不得采信 |
| 价格 / 库存 / 交期 / MOQ | 授权渠道页 | **一手，可采信**（时效规则不变） |

**取证三件套**：每个参与判定的字段必须记录 ① 来源（PDF 名或 URL）② 位置（章节号 / 表号 / 页码）③ 取证日期。
**缺任一项 → 该字段不得参与判定**，标「未核实」。

**高风险字段须两源一致才采信**：封装、脚位、abs max、冷门脚定义——
须有**两个独立原厂源**（如 datasheet PDF ＋ 原厂官网型号页）一致，才标「已核」。
仅单一来源 → 标「待核」，不得进入终局结论。

**基准料同样须取证**：被替料（基准）的封装、脚位与型号后缀，必须回原厂重新取证，
不得沿用渠道页标称或客户 BOM 的描述性写法。**基准错了，候选料核得再严也无意义。**

**未核实 ≠ 出局**：字段未核实时，该料标「待核」并写明缺什么、向谁索取。
不得判出局（那是把"未知"当"不符合"），也不得进入终局结论。

### 判不过怎么办

- 渠道页的封装 / 后缀字段被直接采信 → **该判定作废**，回原厂 Ordering Guide 逐字重读。
- 取证三件套缺项 → 该字段退出判定，不得用"渠道页都这么写"补位。
- 高风险字段仅单源 → 降为「待核」，整份结论降为阶段结论。
- 原厂文档自身矛盾（同表内互斥、型号名笔误、单位缺失）→ 记待澄清项向原厂求证，
  **不许挑一个读法直接用**，也不许替原厂圆场。

### 来源信誉台账（字段级降权）

静态黑名单管的是"整站禁用"，但多数错误是**字段级**的——某站的 Package 字段错，价格字段没错。
整站拉黑会误伤可用字段，不拉黑又会重复踩同一个字段的坑。故按 **来源 × 字段** 记信誉。

| 来源 | 字段 | 错误实例（位置与原委） | 日期 | 累计 | 当前等级 |
|---|---|---|---|---|---|
| | | | | | |

- 每发现一次错误即登记一行，**不覆盖前次**。
- **同一来源同一字段累计 2 次 → 该来源该字段永久降为 L3**，其余字段不受影响。
- 本表为累积台账；**留空即表示尚未发现字段级错误**，不等于"没做"。
- 与静态黑名单的关系：黑名单是整站级处分（造假），本表是字段级处分（转录失真）。

## 规则

1. **L4 不生成**。查询失败就输出「未核实」，并给出下一步查询建议（原厂型号页 / 代理商搜索 / 找原厂 FAE）。
2. **价格与交期时效 ≤ 30 天**。超过 30 天必须标「已过期，需重新核」。
3. **参数以原厂 datasheet 为准**；代理商页面参数与 datasheet 冲突时，以 datasheet 为准并提示差异。
3b. **原厂官网查不到规格书时，走 https://www.semiee.com/ 找（2026-10-04 用户指定为第二信源）**。
   取到的是**原厂 PDF 文件本身**（不是参数转述），因此可靠性高于渠道页的结构化字段。
   仍需两步核对：① 打开 PDF 确认页眉/页脚是**原厂标识**（不是代理商改版、不是第三方摘要）；② 优先看 FEATURES / 规格表 / ORDERING GUIDE / 绝对最大额定四部分。
   → **它解决的是"拿不到 PDF"的问题，不解决"数据本身错"的问题**；拿到的 PDF 若与渠道页冲突，仍以 PDF 为准。
4. **L2 自有成交数据是护城河，只在已接入库的内网生效**（2026-10-04 用户拍板口径 A）：
   - 可以对外说的：本企业**存在**历史成交库、它比公开渠道更贴近真实成交（这是把它当差异化资产来讲，没泄任何具体值）。
   - **未接入库的机器（含对外发布版、客户机器、公网环境）一律跳过 L2 的实际调用**，只走 L1 一手与 L1 授权代理；
     此时只保留一句存在性说明，不输出任何来自该库的具体值。
   - 引用 L2 时**只用于提高置信度**：输出中**严禁**出现成交价/金额、库存数量、供应商名、客户名、合同与订单号（含编号、数量、交期、条款、正文）。
     命中即改写为「本企业有该型号的历史成交记录，细节需凭权限查询」。
   - 对外不得出现任何内部系统名、内部客户/供应商编号、内部价格与库存数字。
5. **公开可见文件（ClawHub 技能、README、示例、GitHub）禁止出现**：真实价格、客户名、供应商名、库存数字、内部成本。自检脚本会扫。

## 品牌/渠道名注意

- 代理与平台名会变（授权关系常调整），**引用前确认该渠道当前是否仍是授权代理**，非授权即降为 L3。
- 型号命名含后缀（如 `-R`、`/TG`、`TR`、`A` 尾缀）时，后缀决定包装与脚位，**必须核对**，不能只认主体型号。

## 出口管制与合规查询入口（供参考，以官方口径为准）

- 美国 BIS 实体清单：official 官网（涉及受管制器件时查，不要在技能里硬编码结论）
- 中国出口管制：商务部官方列表
- 本技能**只提示"需合规复核"，不替用户下合规结论**——这是法律责任边界。

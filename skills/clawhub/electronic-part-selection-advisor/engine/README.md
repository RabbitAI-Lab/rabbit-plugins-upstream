# 判定引擎（机器可读层）

本目录是两份判定标准的**机器可读投影**，供线上判定服务与本地 skill 共用。

**与标准原文的关系**：`references/pin-to-pin-judgment.md` 与  
`references/connector-pin-to-pin-judgment.md` 是判据实体与唯一权威。  
本目录只换载体、不改判据；两者冲突时**以原文为准**。

## 为什么是两层

判定流程在两份标准里是**同构**的（连接器标准自己在标题里就标了"对应 PPJ 的 T8"），  
差异集中在：机械项、功能类别表、降额参数、第二道闸的参数。

因此拆成：

| 层   | 文件                     | 职责                                                 |
| --- | ---------------------- | -------------------------------------------------- |
| 通用层 | `engine.json`          | 品类无关的引擎契约：阶段流水线、结论档位、闸状态六态、差异计数规则、**差异影响四栏的契约（栏数 / 必填字段 / 规则）**、合成规则、输出契约 |
| 品类层 | `categories/<id>.json` | 某品类的具体内容：机械测试项、功能类别表、降额闸、第二道闸、**差异影响四栏的栏名与数据来源**、合法出口、合成表 |

**新增品类 = 复制一个品类文件 + 在 `_registry.json` 追加一条，引擎不用改。**

## 阶段流水线（引擎定义，品类填充）

| # | 阶段             | 必做    | 说明                               |
| - | -------------- | ----- | -------------------------------- |
| 1 | `prerequisite` | 可选    | 先决问题。半导体无；连接器有（替换场景 S1/S2/S3）    |
| 2 | `mechanical`   | 是     | 决定装不装得上 / 插不插得进。全过才是 A 或 B；不过即 C |
| 3 | `positional`   | 是     | 逐脚 / 逐位电气等价，产出 n/N 与 k/N         |
| 4 | `impact`       | k>0 时 | 差异影响四栏，缺一不可（栏名由品类层声明，通用层不设默认栏名） |
| 5 | `derating`     | 是     | 降额闸（安全余量）。状态只有 ✅/❌/⚠️数据缺失        |
| 6 | `secondary`    | 是     | 第二道闸（性能 / 可靠性）。状态 ✅/❌/⚠️待实测      |
| 7 | `synthesis`    | 是     | 结论合成，只查表生成                       |

## 两处关键的结构弹性

1. **机械闸支持两种形态**：半导体是扁平的 `tests` 列表（T1–T7）；  
   连接器是嵌套的 `sub_gates`（互配闸 M1–M8 + 安装闸 A1–A7）。  
   加载时统一归一化成"闸块列表"，引擎无需为品类写特例。
2. **合成表维度由品类声明**：半导体多一维 `customer_verification`（客户验证），  
   连接器没有。引擎只规定"结论只能查表生成"与硬规则，维度名不写死。
3. **差异影响四栏的栏名由品类声明**：通用层只说"必须四栏、每栏须有 id / label / source / missing"，
   栏名不写死。半导体的第 ③ 栏是 `逻辑电平与时序兼容`，连接器的第 ③ 栏是 `插合后保持与应力`（机械保持）——
   两者不得互相套用。**通用层不设默认栏名**：一旦内设默认值，芯片类栏名会被静默套到连接器上，
   掩盖真实的栏目（旧版即踩过此坑，`engine_check` 已改为"品类缺声明即报错"，不再静默采用）。

## 关键不变量（两份标准共享，引擎强制）

- 差异四类：① 命名、② 参数/规格 **不计入 k**；③ 类别不对应、④ 电气角色不相容 **计入 k**。
- `k = N − n`；判 A 的判据是 **k = 0**，不是"差异都可接受"。
- **B 不得因"差异无害"升级为 A**（无害与否属差异影响判断）。
- 降额闸只有 `pass / fail / missing`，**没有 `untested`**——它的 ⚠️ 是数据缺失，不得进「有条件通过」。
- 第二道闸的 ⚠️ 是待实测，可进「有条件通过」（须附实测方案）。
- 任一闸 ❌ 不过 → 结论**最高只能「需评估」**。
- 未拿到盖章数据时**禁止出现「可直接替」**。

## 校验

```bash
python scripts/engine_check.py .      # 结构完整性 + 品类一致性 + 可扩展性自证
python scripts/selfcheck.py .         # 随包发布前的合规自检
```

`engine_check.py` 会校验：字段完整、注册表与品类文件互相一致、  
T/M/A/P/E/FCT 各项齐备、降额闸不含 `untested`、第二道闸不含 `missing`、  
**每个品类各自声明差异影响四栏（恰 4 栏、每栏含 id / label / source / missing，通用层不得内设默认栏名）**、  
合成表维度不缺、并打印"两个品类共用同一引擎"作为引擎品类无关性的自证。

## 已知边界

- 本层只做**判定规则的机读化**，不含候选料检索、数据源对接与参数抓取；  
  那些属于线上服务的检索层，不在本目录职责内。
- 品类文件目前覆盖半导体与连接器；其他品类（电容、电感、晶振、二三极管、模块等）  
  按同一 schema 扩展，若某品类出现引擎当前不支持的闸型，**先扩引擎通用层**，  
  不得在品类文件里硬编码特例。

# 设计总纲(design-principles)

> **写每一页之前必读。** 本文件定义六件事:版面分区、字号阶、scale-to-fill、去 AI 味反模式、视觉形式、节奏规则。
> 与 `html-spec.md` 的分工:html-spec 是**转换契约**(写了能不能无损转 PPTX);本文件是**设计契约**(写出来像不像专业人类做的)。
> 与 `density-tiers.md` 的分工:本文件是原则与推导;density-tiers 是访谈 Q2 选定档位后的**速查参数表**(拷入 brief 即硬约束)。两表数值必须一致。
> 默认优先级:deck-brief > 本文件。brief 里用户显式拍板的,以 brief 为准。

## 一、版面分区系统(1920×1080)

```
┌────────────────────────────────────────────┐
│ 页眉区  y:60–280   kicker/页标题/页码        │
├────────────────────────────────────────────┤
│                                            │
│ 内容区  y:320–940  主体内容(高 620px)       │
│                                            │
├────────────────────────────────────────────┤
│ 页脚区  y:980–1040 页脚/页码(二选一)        │
└────────────────────────────────────────────┘
  左右边距 100px → 内容宽 1720px
```

**满填规则(硬约束,airy 原型除外)**:
1. 内容带顶 ≤ 360px、内容带底 ≥ 880px —— 内容区**垂直利用率 ≥85%**
2. 内容少则**放大字号/行距/间距**把内容带撑满,绝不允许"小字堆在上半截、底部空 300px"
3. 各内容块在内容区内**均匀分布**(顶对齐标题区、底对齐页脚区),不是全部挤向顶部

**满填的四条量化判据**(2026-08-06 第四轮 P3;validate 逐条自动检查,全 44 页实测标定):

| 判据 | 阈值 | 为什么加它 |
|---|---|---|
| 墨迹行覆盖率 | 内容区按 10px 分行,有墨行 ≥**55%** | 只看"最低边"可被一根细线骗过 |
| 最大连续空洞 | 内容区内部连续无墨 <**200px** | 断层比"底部空"更普适(内容压在下半截同样是断层) |
| 上下分布 | 墨迹面积任一半 ≤**88%** | 一头沉 |
| 内容带底边 | ≥ **847px**(= 320 + 620×0.85) | 原判据,对"整体偏上"最直观 |

> 第 1、2 条是新加的主力判据。此前 96/104/105/106 四页墨迹只占 29-52%、
> 中间挖着 220-330px 空洞,却因为底部有一根 1px 细线 + 16px 脚注而全部"通过"。
> **别用细线/脚注凑底边**,那不叫填满。

**airy 原型(豁免满填规则,留白是其设计语言)**:封面 / 章节分隔 / 大字观点 / 引用 / 行动号召收尾。
airy 页也要**垂直居中平衡**,不是"内容偏上、底部空白"。
写这类页时**必须把文件名填进 `slides.config.json` 的 `design.airyPages`** —— 那是唯一的豁免途径。

**出血规则**:仅 airy 原型与全出血大图页允许元素贴边/出血;内容页严守 100px 边距。

## 二、字号阶(2026-08-02 重校准 · D-A 稳健档)

换算:1px = 0.5pt。旧阶(正文 18-20px = 9-10pt)是 PPT 脚注级别,已全部上调。

| 角色 | 演讲形式 | 混合形式 | 阅读形式 |
|---|---|---|---|
| 封面主标 | 88-120px (44-60pt) | 80-104px | 64-88px |
| 页标题 | 56-64px (28-32pt) | 52-60px | 44-52px |
| 区块/卡片标题 | 32-38px (16-19pt) | 28-34px | 24-30px |
| **正文** | **24-28px (12-14pt)** | 20-24px | 17-20px |
| 注释/来源 | ≥16px | ≥15px | ≥14px |
| 页码/页脚 | 14-16px | 14-16px | 14-16px |

**铁律**:
1. **绝对下限 14px** —— 任何文字(含来源标注)不得小于 14px
2. **正文档内下限**:演讲 22px / 混合 18px / 阅读 16px —— 低于即破档(缩字号破档,旧规不变)。
   ⚠️ **下限不是默认值**:上表"正文"一行(演讲 24-28px)才是默认取值区,22px 是**破档红线**。
   2026-08-06 实测:96-107 段样张正文中位数几乎全部恰好钉在 22px —— 红线被当成了默认值,
   页面因此又小又平。**没有理由时就取 24-28px**,内容少时按 scale-to-fill 取上限区。
3. **层级对比**:页标题 ≥ 1.8×正文;区块标题 ≥ 1.2×正文;封面主标 ≥ 3×正文。
   validate 的自动判据是**页标题/正文 ≥1.6 报 WARN**(比设计目标 1.8 留一档余量,
   避免把"刚好 1.7"的合理排版判成缺陷);另查**页内字号档数 ≥3**,只有两档即缺节奏。
4. **行高**:标题 1.15-1.25;正文 1.5-1.7;scale-to-fill 时放宽到 1.6-1.8
5. 字重对比:标题 700-800、正文 400、强调 700 —— 靠字重+字号分层,不靠堆颜色

## 三、Scale-to-fill(字号与内容量联动)

> 人类设计师的本能:内容少 → 字放大、行距拉开、铺满画布。AI 的典型病:内容少 → 小字挤上半截。

| 本页内容量(相对档内上限) | 字号策略 | 行距/间距策略 |
|---|---|---|
| < 60% | 字号取档内**上限区** | 行距 1.6-1.8,条目间距加大(24→40px) |
| 60-80% | 档内中间值 | 行距 1.5-1.6,常规间距 |
| ≥ 80% | 档内**下限区**(不低于档内下限) | 行距 1.45-1.55,紧凑间距 |

**两个禁止**:
- ❌ 缩字号破档(旧规):内容超上限 → 拆页/精简,不许缩字
- ❌ 小字配少内容(新规):内容 < 60% 还用下限字号 → 等于制造底部留白,违反满填规则

**联动约束**:字号取上限时,每要点字数上限同步收紧(演讲档 ≤16 字/点,见 density-tiers)。大字就必须少字。

## 四、去 AI 味反模式清单(12 条)

> 每条 = 反模式 ✗ → 正例 ✓ + 豁免条件。这些模式是"主流 AI PPT"的视觉指纹,人类专业 deck 极少这样排。
>
> **结构形状豁免总则(2026-08-05 增补)**:本清单判负的是**装饰性堆砌**(kicker/渐变条/徽章/阴影三件套),不是**结构性形状**——承载信息组织的卡片/图标/流程/漏斗/循环/色带是合法页面形式(见第五章),**不计入装饰预算、不受卡片矩阵限额**。判定标准一句话:形状上有信息(文字/图标/数据)= 结构;只为好看 = 装饰。

**1. 三件套页头** — ✗ 每页都 kicker+大标题+副标题 → ✓ kicker/副标题仅章节首页与封面;内容页直接 action title(可两行)。豁免:阅读档可保留副标题。
**2. 万物皆卡片** — ✗ 所有要点装进等宽卡片 → ✓ 卡片仅用于**真并列实体**(产品/方案/角色/案例);要点、结论、步骤默认**裸排**(粗体引导词+分行)。豁免:用户 brief 指定卡片风。结构豁免(2026-08-05):图标要点网格(原型 23)等**图示卡片**是并列信息的合法承载,不受"默认裸排"约束;判负的是无图标、无差异、可合并为一段文字的纯文字卡片堆叠。
**3. 页底结论条** — ✗ 每页底部一条渐变/深色"总结条" → ✓ 仅章节收尾页可用。结论应该写在标题里(action title),不是钉在页底。结构豁免(2026-08-06):**承载信息的色带不算"结论条"** —— 带文字/数据/图标的章节色带、对比带、统计带(原型 25/27)是合法结构色面;判负的对象是**空的、纯装饰的**渐变条。
**4. 渐变装饰条** — ✗ 每页顶部/底部渐变条 → ✓ 仅封面/章节分隔/收尾页。内容页用 1-2px 细线或不用。结构豁免(2026-08-06):同上 —— **纯装饰**渐变条才判负;深色强调面板、卡片底色、表头底纹、承载信息的色带属于结构色面,是内容页**应该有**的东西(见下方"结构色面下限")。
**5. 序号圆圈** — ✗ 每个列表项都套色圈数字 → ✓ 仅流程/步骤类页面;其余直接大数字裸排(40px+ 数字+标题)或不编号。结构豁免(2026-08-05):流程/步骤/编号图示页(原型 13/24)的序号与形状组合合法。
**6. 徽章/胶囊** — ✗ 到处贴 badge → ✓ 仅状态标注(新增/试点/Beta)与封面版本号。结构豁免(2026-08-05):图示中的语义标记(原型 29 的 VS 徽章、状态点、阶段标)合法。
**7. 等宽卡片矩阵** — ✗ 全页 3-4 张等宽卡当万能布局 → ✓ 每 deck ≤2 页卡片矩阵;同原型不连续(见节奏规则)。优先用不对称分栏、编辑式、裸列表替代。结构豁免(2026-08-05):**限额对象收窄为纯文字卡片矩阵**;图标要点网格(原型 23)不计入 ≤2 页限额(仍受"同原型不连续 >2 页"约束)。
**8. 装饰超编** — ✗ 一页集齐 kicker+装饰线+徽章+渐变条+页脚 → ✓ **每页装饰元素 ≤3 件**(装饰线/徽章/渐变条/图形点缀各计 1 件)。口径(2026-08-05):装饰预算仅计**装饰件**;结构形状(卡片/图标/流程/漏斗/图表/表格)不计件。2026-08-06 由 ≤2 放宽到 ≤3:实测 ≤2 与"零装饰"实际同义(页脚+一根细线就用满预算),把页面推向纯白+黑字;放宽一件用于**层次**而非堆砌。
**9. 高亮通胀** — ✗ 每页多处彩色强调词 → ✓ **每页高亮 ≤1 处**;其余靠字重分层。
**10. 居中崇拜** — ✗ 标题正文全居中 → ✓ 默认**左对齐**编辑网格;居中仅封面/收尾/大字观点页。
**11. 恒等分栏** — ✗ 永远 1:1 或 1:1:1 → ✓ 优先不对称(7:5、3:2、2:1),主辅分明。
**12. 四角齐全** — ✗ 每页页码+页脚+logo+章节名全上 → ✓ 页脚与页码**二选一**;章节名靠 kicker 或分隔页,不双管齐下。

> 判断口诀:**"人类会这样排吗?"** —— 拿不准时,想麦肯锡/苹果发布会/好杂志的内页:它们克制、左对齐、标题即结论、装饰极少。

**克制 ≠ 饥饿 ≠ 单调**(2026-08-02 增补内容自检;2026-08-05 增补形式自检):
> 去 AI 味反模式砍掉的是**装饰**(kicker/渐变条/徽章/点缀),不是**内容**,也不是**结构形状**。每页写完做两组自检:
>
> 内容单薄自检:
> ① 这页除了标题还有几个信息点?<3 个 → 加例子/数据/对照(内容性丰富,非装饰性堆砌)
> ② 有没有"例子(个人)/例子(团队)"这类可抄模板?没有 → 补
> ③ 空页面/半空页面是失误,不是风格——airy 只豁免封面/分隔/大字/引用/收尾
>
> 形式单调自检(2026-08-05):
> ④ 这页除了文字还有什么视觉元素?答案为"只有细线" → 这是纯文字页,对照形式偏好档(第五章)检查全 deck 占比
> ⑤ 这页的形式与前后页重复吗?同形式连排 >3 页 = 单调——**换形式,不换内容**
>
> 专业 deck 的"素"来自视觉克制,来自**信息密度 + 留白 + 形式变化**的平衡;单调与堆砌同为失误——**克制管装饰,不管形式**。

### 结构色面下限(2026-08-06 第四轮 P3 · 硬约束)

反模式清单只说了"不要什么",没说"至少要有什么" —— 结果内容页被写成纯白底 + 近黑字 + 细线。
实测证据:96-107 段样张有 **10 页色面占比恰好 0%**,而 110-117 段是 11-72%;
前者正是"过于素雅、单调"的来源。故补一条正向下限:

**每个内容页(非 airy)至少一块结构色面** —— 面积 ≥1.5 万 px²(约 150×100),二者任一即满足:
① 计到 ≥1 块结构色面;② 全页色面占比 ≥8%。`balanced`/`rich` 档由 validate 自动检查。

合法的结构色面(**承载信息**,不是装饰):

| 形式 | 典型用法 |
|---|---|
| 深色强调面板 | 关键结论/数据压深蓝底,配 `--on-navy-text`(**必须**,否则文字近黑不可见,见 H13) |
| 章节色带 / 统计带 | 带文字与数字的横向色带(原型 25/27) |
| 卡片底色 | 并列实体卡的浅底(`--off-white` 之外的可辨底色) |
| 表头底纹 / zebra | 表格表头深底白字 + 隔行浅底(挂 `<tr>`,见 H12) |
| 图示形状填色 | 漏斗/流程/金字塔/循环的分段填色(原型 24/26/28) |

**不算**:整页画布底色(那是背景,不构成层次)、纯装饰渐变条、1-2px 细线。

**层次靠"字重 + 字号 + 一块色面"三件套**,不靠给每个词上色(见反模式 9 高亮通胀)。

### 用色纪律(2026-08-17 第九轮 P3 · 硬约束)

结构色面下限管"页面得有色",本节管**这些色从哪来**。theme.css 一直被称作契约,
但此前**校验器从不读它** —— 实测代价:一个 34 页 deck 的 theme.css 是联想红/深蓝,
而页面高频色逐值等于**另一套预设**(Apple 蓝灰),`var()` 用量 **0**、裸色声明 1074 处,
当日 validate 结论仍是 0 ERROR。同期实测 41 个色板外色里 **60%** 只是"某色板色 × 白混合",
本该是变量;近似重打成灾(`#0A2C63` vs `#0A2E5C` ΔRGB 7、`#1D1D1F` vs `#1F1F1F` ΔRGB 2.8
—— 肉眼同色、值不同,PPTX 里是两个不同填充色,永远无法整体换肤)。

**规则**(三条,均为 WARN;`design.tier` 非空即生效):

| 规则 | 判据 | 修法 |
|---|---|---|
| R1 色板外用色 | `background`/`color`/`border-color` 的裸色值不在 theme.css 色板内 → 逐色报;与色板色 ΔRGB ≤**6** 时判为"近似重打" | 改用最接近的色板变量;确需新色 → 先加进 theme.css 与 16 套预设 |
| R1b 整页脱离色板 | 同页去重后色板外色 ≥**3** 种 | 不是个别硬编码,是整页按另一套色画的 —— 应改 theme.css 本身 |
| R2 var() 占比 | 页内色声明 ≥**4** 处时,`var()` 占比 <**70%** | 把 hex 改成变量。实测样张中位 **95%**,零 var() 的 deck 是 0% |
| R3 整套色板未生效(deck 级) | 全 deck 裸色种类 ≥**5** 种时,高频用色前 **8** 色与色板交集 <**3** | 想换色板就改 theme.css(或复制 `assets/presets/` 预设覆盖),别逐页写死 |

**R2 与 R3 是互补的**,不是同一条的粗细两档(实测四个 deck 验证):
- 用**对**的色板但逐页写死 hex(`ai-revolution`:交集 8/8、`var()` 0%)→ R3 沉默,**R2 抓**
- 用**另一套**色板画完(`ai-capability-architecture`:交集 1/8)→ R2、R3 同时抓,R3 给出根因
- 正常 deck(交集 4/8 与 5/8)两条都不报 —— 交集不必满分,因为深浅梯级本就会派生新值

**豁免(刻意不查)**:
- `<svg>` 内的着色 —— H7 要求图标显式着色;`style="stroke:var(--x)"` 是首选形态
  (实测在 `capture.hideTextCss` 下与裸 hex 截图**逐字节相同**,而 `currentColor` 变空白)
- 渐变色停与 `rgba()` 阴影 —— 尚无渐变梯级令牌,留待后续
- **不判断"颜色好不好看"**,只判断"是否来自色板";品味不是机器的管辖范围

**为什么是 WARN 不是 ERROR**:提取器读**计算样式**,`var()` 与裸 hex 对 PPTX 输出完全等价 ——
这是可维护性与一致性问题(换肤、色值漂移),不是转换错误。

**梯级令牌**(2026-08-17 P1 补齐,共 12 个):此前色板只有 primary/dark 两极,
"浅底卡片/分层底/热力中档/徽章底"**无变量可用**,只能手写 —— 这是 60% 硬编码的结构性成因。
现由 `scripts/tools/gen-ladder.js` 按各文件自己的基色推导(换预设自动跟随):
`--brand-primary-soft/-pale`、`--brand-dark-pale/-tint/-mid`、`--ink-soft/-faint`、
`--surface-sunken`、`--signal-{green,yellow,red,blue}-soft`。

### 数据页的口径纪律(2026-08-09 · 组 7 分析论证配套)

结构色面下限管"页面得有层次",本节管**数字得可被追问**。分析论证组(原型 31-43)与数据组
(17-20)的说服力全部来自"这个数从哪来、按什么口径算的";缺了它,咨询页型只是**看起来很咨询的空页** ——
和上一节的"两块色块 + 三行黑话"是同一类失败,只是发生在数字上。

**适用页**:原型 17-20、31-43,以及任何出现具体数字/百分比/排名的内容页。

**必须有一行来源/口径注**(≥16px,不得低于绝对下限 14px;通常置于页脚区上沿 y≈990):

| 要素 | 写法 | 反例 |
|---|---|---|
| 时间范围 | "2025-07 至 2026-06" | "近期""目前" |
| 样本/范围 | "n=6 区域""六家可比公司(营收 5-15 亿)" | "业内普遍""多家企业" |
| 测算方式 | "CAGR""剔除一次性重组费用""按本公司准则重述" | 不写(默认读者信) |
| 估算标注 | "估算,假设渠道结构不变" | 把估算值写成实测值 |

**三条硬纪律**:

1. **估算必须标"估算"并给假设** —— 预测值/推算值与实测值混排且不区分,是最常见的诚信问题。
2. **拿不到数就别画** —— 各原型的"降级"行给了退路:编不出算式链的 TAM 页(40)、编基准的对标页(43)、
   凑不闭合的瀑布(34),一律退回原型 8 要点列表 + `content-deepening.md` 的**待补数据清单**,
   把缺口交给用户补。裸主题路径已经确立了这个原则:**没有素材时诚实列缺口,不用推理填满**。
3. **口径一致性** —— 同一 deck 里同一指标的口径必须同一个;换口径要在该页显式声明重述。

> **为什么这条不做成 validate 规则**(2026-08-09 决定,与"版面达标 ≠ 内容达标"同源):
> 机器能查的只有"页面底部有没有一行 ≥16px 的小字",查不了那行小字是否诚实。
> 而一旦把它变成外观检查,立刻会催生"贴一行假来源过检"的应对 —— 正如本文件开头记录的教训:
> 中间挖着 220-330px 空洞的页面,**因为底部有一根 1px 细线 + 16px 脚注而全部"通过"**。
> 故本节是**写作纪律 + 自查项**(SKILL.md Step 3.5 第 8 条),不是机器门禁。
> 若要机器约束,正确形态是让作者在 `slides.config.json` 里**显式登记**数据页及其口径
> (声明式,像 `airyPages`/`hedgePages` 那样),而不是让校验器去猜页面底部那行字算不算来源。

### 版面达标 ≠ 内容达标(2026-08-06 第五轮 P1)

上面所有判据(墨迹行、空洞、色面、字号层级)都是**几何统计量**。实测证明它们可以被
"两块大色块 + 三行企业黑话"完整满足 —— 0 ERROR / 0 WARN,而页面几乎不含信息:

> ✗ 赋能生态,构建闭环 / 持续深化,全面提升 / 协同联动,提质增效,打造标杆,形成合力

**这是本技能门禁的已知边界,必须靠写作纪律补上**:

1. **企业黑话有自动检查**(dom-checks 规则 17):一档词表(赋能/抓手/提质增效/夯实基础/
   统筹推进/打造标杆/形成合力…)每千汉字 ≥40 次且 ≥3 次 → WARN。
   二档词(对齐/协同/沉淀/闭环/打通)**不计** —— "沉淀模板 v1.2""ISSB 对齐""6 周闭环"都是实义。
2. **具体性没有自动检查**,原因是检测不可靠:数字+单位的模式会漏掉专有名词与命名实体
   (`four-revolutions` 讲农业/工业/信息/智能革命、`05-four-questions` 讲 ISSB×ESRS×GRI 与
   Scope 1/2/3,实测"具体标记 = 0"却内容扎实)。所以这条**只能靠自查**:
   > 每个论断后面跟得上一个**可验证的事实**吗?数字+单位 / 具体例子 / 专有名词 / 时间范围。
   > 跟不上 → 这句是空话,换掉或删掉。
3. **门禁全绿不代表页面合格**。它只保证"版面不塌";内容是否成立,只有人能判断。

## 五、视觉形式(Visual Form)—— 治"单调"的一等公民

> 2026-08-05 第三轮重构新增。反模式清单管"装饰别滥用",本章管"形式要丰富"——两者同遵一句话:**装饰克制,结构形状大胆**。

### 形式五类(按页面主导视觉元素分)

| 形式 | 定义 | 归属原型 |
|---|---|---|
| 文字型 | 纯文字+细线,无其他视觉元素 | 1/2/3/4/5/6/7/8/12/17/21/22 |
| 图示型 | 形状/图标承载信息:图标网格/chevron 流程/漏斗/金字塔/循环/辐射/对比卡/色带;**分析论证类(2026-08-09)**:议题树/瀑布/泳道甘特/驱动树/情景/规模拆解/成熟度/价值链 | 13(chevron 款)/14/15/16 + 23-30 + 32/34/35/37/39/40/41/42 |
| 图表型 | data-chart 图表 / `<table>` 表格为主角(含原生散点、Harvey ball 评估表、逐格底纹热力表、对标表) | 18/19/20 + 33/36/38/43 |
| 图片型 | 照片/截图/全出血大图 | 10/11 |
| 混合型 | 两种主角组拼(一页仍只有一个"主主角") | 9/31 |

### 形式偏好三档(访谈 Q8c 选定,写入 brief 与 slides.config.json)

| 档 | 纯文字内容页占比上限 | 同形式连排上限 | 每内容页非文字视觉元素 |
|---|---|---|---|
| 文字克制型 text | 不限(2026-08-05 前的现行行为) | 不限 | 不强制 |
| **平衡型 balanced(默认推荐)** | **≤50%** | **≤3 页** | **≥1 个** |
| 图示丰富型 rich | ≤30% | ≤2 页 | ≥2 个 |

### 计数口径(validate 与人工自查同款)

- **计入**:形状(最小边 ≥8px;全画布底色块除外)、内联 SVG 图标、`data-chart` 图表、`<table>`、`<img>`
- **不计入**:1-2px 细分隔线/中缝、纯装饰点缀(仍受装饰预算 ≤3 件约束)、页眉/页脚/页码
- **纯文字页**:内容页中计入元素数 = 0 的页;**分母 = 内容页数**(封面/章节分隔/大字观点/引用/收尾等 airy 页不参与)

### 形式与内容的关系

- **先有信息结构,后选图示形式**:并列 → 图标网格/卡片;先后 → chevron/流程;递减 → 漏斗;分层 → 金字塔/层级;循环 → 循环图;辐射 → 中心辐射;对比 → 对比卡阵/双栏;分节论述 → 色带。**分析论证结构(2026-08-09,组 7)**:问题/指标分解 → 议题树 32/驱动树 37;变动归因 → 瀑布 34;多准则取舍 → 评估矩阵 33/热力 38;双维定位 → 定量散点 36/定性象限 15;规模收窄 → 规模拆解 40;分级定位 → 成熟度 41;环节价值分布 → 价值链 42;基准对比 → 对标 43;排期分工 → 泳道甘特 35。为显得丰富而硬套图示,与为显得专业而硬凑 XY 轴,同属外行特征
- 图示页信息点仍守密度档上限(演讲档每页要点数与每点字数不变):**形状让信息更易读,不是让信息更少**
- 一页只用一种图示(一个主角);图示与图表/表格可组拼(如 23+18),但全页视觉元素总数不宜超过 12 个

## 六、节奏与变化规则(整 deck 层面)

1. **原型多样性**:每 deck ≥6 种页面原型(原型库见 `page-archetypes.md`);**形式分布**按第五章形式偏好档执行
2. **不连续**:同原型不连续超过 2 页;卡片矩阵全 deck ≤2 页
3. **呼吸感**:每 3-4 页满填内容页,插 1 页 airy 页(分隔/大字观点/引用)让读者喘气
4. **深浅交替**:深底页(封面/分隔/收尾)间隔分布,不连排也不缺席
5. **议程呼应**:议程页的章节结构 = 分隔页序列 = kicker 序列,三者一致

## 七、Action title(标题即结论)

- ✗ 空标题:"市场分析""产品介绍""关于 XX 的若干思考" —— 任何 deck 都能用的标题 = 废标题
- ✓ 结论标题:"企业 AI 落地的瓶颈不在模型,在数据管道" —— 只适用于本页内容
- 写法:主谓宾完整句,≤30 字,可两行(56-64px × 1.15-1.25 行高,两行正好撑满页眉区)
- 空标题只允许出现在:封面(品牌位)、分隔页(章节名)、附录
- 副标题(若用)= 给结论补一个证据/数字,不是换一种说法重复标题

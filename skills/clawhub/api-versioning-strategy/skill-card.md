## Description: <br>
Write an API versioning strategy document for a service or API platform. Use when asked to define versioning policy, plan API deprecation, classify breaking changes, or document version lifecycle. Produces a complete versioning strategy with breaking-change classification table, deprecation timeline, migration guide template, and client communication template. <br>

This skill is ready for commercial/non-commercial use. <br>

## Use Case: <br>
Developers, engineering leads, and API platform teams use this skill to draft a complete API versioning strategy for REST, GraphQL, or gRPC services, including breaking-change classification, deprecation timelines, migration guidance, and client communication templates. <br>

### Deployment Geography for Use: <br>
Global <br>

## Known Risks and Mitigations: <br>
Risk: The generated strategy may not reflect an organization's actual SLA, contract, compliance, or customer migration requirements. <br>
Mitigation: Review and adapt the strategy with the service owner, legal or compliance stakeholders, and affected consumer teams before adoption. <br>
Risk: Missing or inaccurate inputs can lead to an unsuitable versioning scheme or deprecation timeline. <br>
Mitigation: Provide the API type, current versioning approach, active version and consumer counts, consumer type, and deprecation constraints before relying on the output. <br>

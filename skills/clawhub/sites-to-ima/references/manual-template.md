# 更新手册模板（七章，源自 PR Daily 手册 v2 通用化）

生成【{站点名}·更新手册】时按本模板填充，写入用户指定的目标笔记本。所有 `{占位符}` 用本次执行的真实值替换；笔记 note_id、文件夹 folder_id 必须用 API 实际返回值，不可臆造。

```markdown
# 【{站点名}·更新手册】

类型：操作手册（非分类索引笔记）
用途：每次用户说"更新知识库 / 更新{站点名}"，按本手册执行。完成后在末尾【七、最新抓取日期】追加新日期。
笔记本：{目标笔记本名}（folder_id {笔记本folder_id}）

## 一、站点与抓取方法（{n} 类通用）

站点：{站点名}（{域名}），{站点类型：WordPress/其他}，使用 {通道：WordPress REST API / RSS+sitemap / 浏览器遍历}
识别关键词（progress.json 用，小写）：{如 "pr daily", "prdaily"}
本地进度文件：output/{site}_progress.json（与本章信息一一对应，二者互为备份）
{API 通道时：取分类 id：/wp-json/wp/v2/categories?slug=<slug>；翻页抓取：/wp-json/wp/v2/posts?categories=<id>&per_page=100&page=N（默认时间倒序）}
{浏览器通道时：入口 URL、主列表选择器、翻页方式（加载更多按钮/页码/滚动）、停止条件}
字段映射：{URL/标题/发布日期/摘要各自的取法；日期取 YYYY-MM-DD}
请求带浏览器 UA；被 WAF 拦则退避重试（间隔≈1.5s 递增）
表格单元格内 | 替换为 /、去换行，防错列

## 二、笔记结构（当前）

独立分类索引笔记（{n} 篇，目录指引，全量收录）：{逐篇列出：【站点·分类索引】{类名}（note_id xxx）}
统一更新笔记（1 篇，正式导入记录）：【{站点名}·分类索引·更新】（note_id xxx），表格含「类别」列；每次更新都追加到这一篇（不新建）；当前全局序号已编至 {N}（下次追加从 {N+1} 续编）
更新手册：本篇（note_id xxx）
本地数据底座：/sandbox/workspace/output/{site}_full.json（{N} 篇）
本地进度底座：/sandbox/workspace/output/{site}_progress.json（各类双轨进度+续编序号）

## 三、分类与处理规则

| 分类 | {slug/入口} | {cat_id或标识} | 索引笔记 | 知识库文件夹 folder_id | 是否导入知识库 |
|---|---|---|---|---|---|
| {类A} | {slug} | {id} | 【{站点}·分类索引·更新】(填类别列) | folder_xxx | 是（索引+导入KB） |
| ... | | | | | |

## 四、索引笔记写入格式

独立分类笔记：标题首行 + 开头 4 行元信息（类型/来源/排序/初次抓取日期，不写统计）+ 表格（| 序号 | 发布日期 | 标题 | 摘要 | URL |）+ 末尾更新记录。
统一更新笔记：同上，表格多「类别」列（| 序号 | 类别 | 发布日期 | 标题 | 摘要 | URL |）。
均从旧到新、序号全局递增；每次更新前带小节标题 `## 第{k}次更新：{起} ~ {止} 新增（{追加日期} 追加）`，末尾追加 `## 更新记录`（日期沉底）。
写入走 COS+push_note 路径（表格内容禁止直接进 JSON body，触发 WAF）。

## 五、知识库信息

kb_id：{kb_id}
知识库：{KB名}
{站点名} 文件夹 folder_id：folder_xxx
各分类子文件夹 folder_id（均位于 {站点名} 文件夹下）与 {初次日期} 导入情况：
{类A}：folder_xxx（已导入 {x} 篇）
...

## 六、更新执行步骤（用户说"更新知识库"时）

1. 对每个分类：按【一】的通道抓取比对应索引笔记【更新记录】最新日期更新的文章（API 用 after={日期}T23:59:59）
2. 新文章导入知识库对应分类文件夹（import_urls ≤10/批）；导完等 20s 用 get_knowledge_list 复核计数，不足补齐
3. 新文章追加到统一更新笔记（填类别列，序号全局续编）+ 对应独立分类笔记（序号续编）
4. 各笔记末尾【更新记录】追加本次日期、新增篇数、时间范围
5. 本手册【七】末尾追加新日期；本地 {site}_full.json 同步合并新数据
6. 增量为 0 时先验证抓取无漏（拉最新 15 篇看日期分布）再如实汇报

## 七、最新抓取日期

{YYYY-MM-DD}（初次建立：{本次完成事项摘要}）
```

## 生成后自查

- [ ] 七章齐全，占位符全部替换为真实值
- [ ] 所有 note_id / folder_id / kb_id 来自 API 实际返回
- [ ] 抓取参数（slug、cat_id 或选择器）足以让下次会话直接复用
- [ ] output/{site}_progress.json 已同步写入：keywords、各类双轨进度（index_note/kb_import）、last_fetch 与本章信息一致
- [ ] 末尾"最新抓取日期"已填本次日期

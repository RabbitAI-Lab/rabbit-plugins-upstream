# 核对剩余工作

输入是当前目标、已有计划或任务、代码和验证证据；不要求先运行指定 Skill，也不要求每个项目都有 spec.md、tasks.md。此检查可选，实际修复和测试仍由实现流程承担。

## 核对目标与事实

确定本轮范围与原资料位置，读取有关项目规则、.peterflow/standards/ 中适用规范、目标、计划、任务及证据。用户指定其他根目录时沿用。后续规划不纳入本轮缺陷。

逐项沿“原目标 → 当前实现入口 → 对应断言和实际结果 → 结论 → 补回位置”核对，包括已勾选项。打开入口确认是否真的接通。先看测试是否经过该入口，再核对运行当时的代码、测试、配置和适用环境。已有 SHA-256 清单时，在记录的工作目录用 `shasum -a 256 -c 清单` 或等价命令比对；写在原任务中的摘要可原位重算比较。任务清单只更新进度或回执时，核对其中的验收条件是否变化。实际输入改变或版本无法确认，标明哪项证据待补验，保留可独立证明的结论。摘要相同仍需确认断言覆盖了目标。

| 结论 | 判断 |
| --- | --- |
| 已完成 | 当前行为符合目标，必需验证已有适用证据 |
| 未完成 | 存在明确的实现缺口、冲突或实际失败 |
| 未验证 | 实现看似齐备，但必要行为未测或旧证据失效 |
| 受阻 | 缺环境、访问能力或产品决定，写清解除条件 |

静态检查通过、文件存在、清单勾选、命令建议和历史成功都不能单独证明当前功能通过。没有代码时按实际缺失安排工作；没有测试证据时安排验证，不捏造失败或成功。

## 补回原处

先报告目标依据、当前证据、结论和剩余动作，然后在用户授权范围内直接更新原资料；用户明确要求只读或只报告时不落盘。优先链接已有证据，只有实际另存验证记录时才按需建 `verification/`。

- **轻量**：剩余工作补回原短计划或会话，不生成 tasks.md。
- **中等**：补充或重新打开所属 Phase 的原 Task，保留编号、已完成部分和历史证据；明确修改位置、依赖和验收。旧清单没有 Phase 时仍原位补任务，不为检查改格式。
- **重型**：补回所属 Phase（执行单元），必要时增加可独立交接的 Phase 及其 Task，注明目标、输入、写入范围、依赖、验收与证据；已有 U 编号及证据路径沿用，同步最终 Phase 的累计验证范围。修复不能依赖正在等它修复的失败验收。

误勾项写清勾选与事实的差异，在获准安排时原位纠正。缺行为就补实现，只缺当前证据就补验；混合任务保留已做部分，必要时只重开验收。复用已有待办，重复检查不重复追加。任何必需目标仍有缺口、待验或受阻时，在阶段和整体结论中保留它。

无新增缺口且证据适用时保持原文件不变。结果说明本次核对范围、四类结论和下一可执行项；沿原档位恢复实现，不无故升级、重跑全部流程或自动触发发布、提交。没有实际测试的结论必须明确其限制。

> 适用于：Ingest 操作中的 Compile 子任务。所有导览笔记应遵循统一的 4 章节结构 + schema frontmatter。

## 1. 完整 frontmatter（强制）

> 详见 [schema.md](schema.md) — 这是强制契约，所有导览必须遵守。

```yaml
---
title: 📖 主题导览：[主题名称]
type: guide
confidence: high | medium | low
created: YYYY-MM-DD
updated: YYYY-MM-DD
version: 1.0
changelog:
  - v1.0: 初始版本，基于知识库资料编译
sources:
  - [《文章1》](URL)
  - 《文章2》
  - 《文章3》— 请在知识库查看
related_guides:
  - [《主题导览：相关主题》](URL)
---
```

## 2. 4 章节结构规范

| 章节 | 内容详略 | 内容要求 | 写作要点 |
|------|---------|---------|---------|
| **一、主题定位** | **略写** 一段话（约 100 字）| 定义 + 解决问题 + 核心逻辑 + 依赖链条 | 用"是...的 XX 层，位于 XX 与 XX 之间"句式；依赖链条用箭头链展示 |
| **二、核心概念与关键要素** | **详写** 每概念约 200-300 字 | 核心思想 + 关键要素（引用文章）+ 实践建议 | 每个关键要素都要引用知识库文章；实践建议要具体可操作 |
| **三、学习路径（融合知识网络）** | **中等** 表格 + 一段话 | 两条路径 + 表格形式 + 最终整合 | 表格内容精简，最终整合一段话点明闭环逻辑 |
| **四、相关主题** | **略写** 表格形式 | 主题 + 关系 + 连接点 | 说明每个关联主题的具体连接点，无需展开 |

## 3. 关键要素写作规范（v1.1.1 强化）

每个关键要素必须包含 **4 个必含维度**：

```markdown
• 要素名称：定义（1 句话）+ 原理（核心机制）+ 应用场景（何时使用）+ [《来源》](链接)
```

**4 个维度详解**：

| 维度 | 作用 | 示例 |
|------|------|------|
| **定义** | 一句话说明这个要素是什么 | "Fama-French 三因子是解释股票超额收益的多因子模型" |
| **原理** | 核心机制是什么 | "基于市场风险、规模、价值三因子构造投资组合" |
| **应用场景** | 何时使用 | "在 A 股市场可解释约 30% 横截面收益" |
| **引用** | 必须的来源链接 | "[《Fama-French 1993》](URL)" |

### 完整示例

```markdown
**关键要素**：
• Fama-French 三因子模型：解释股票超额收益的多因子模型（定义），基于市场、规模、价值三因子构造投资组合（原理），在 A 股市场可解释约 30% 横截面收益（应用场景），详见[《Fama-French 1993》](URL)。
• 风险因子定义：股票收益对系统性风险的敏感度（定义），通过回归 β 系数衡量（原理），用于资产组合的风险管理（应用场景），详见[《CAPM 理论》](URL)。
```

**要点**：
- ✅ 4 个维度每个都要有，缺一不可
- ❌ 不要"空话要素"（如"这是一个复杂的概念"）
- ❌ 不要"原则化要素"（如"应该谨慎使用"）
- ✅ 引用必须是知识库中的实际文章
- ✅ 必须提供可点击链接

## 4. 实践建议写作规范

每个核心概念卡片末尾，用编号列表展示 2-3 条**可执行任务**（不是原则）。

### ✅ 正确示例（可执行任务）

```markdown
**实践建议**：
• 任务 1：策略上线前必须通过 5 年回测，验证 Sharpe Ratio > 1.0。来源：[《回测规范》](链接)
• 任务 2：每季度回顾一次因子有效性，剔除失效因子。来源：[《因子维护手册》](链接)
• 任务 3：建立因子拥挤度仪表盘，拥挤度 > 70% 时减仓。来源：[《拥挤度模型》](链接)
```

**4 个必含元素**：
- ✅ **动词**：任务、验证、回顾、建立、剔除（动作明确）
- ✅ **量化标准**：5 年、Sharpe > 1.0、每季度、70%
- ✅ **可执行**：用户能立刻按此执行
- ✅ **引用来源**：每个建议都有文章支撑

### ❌ 反模式（原则化措辞，必须避免）

```markdown
❌ 不要写：
• "先有逻辑，后有回测"  ← 格言，无可执行性
• "应该谨慎决策"           ← 空泛，无量化
• "要重视风险"               ← 无具体动作
• "多思考多实践"            ← 鸡汤
• "理论联系实际"            ← 套话
```

**判定标准**：
> 问自己：**用户看完这条建议，能立刻开始做什么？**
> 如果答不出 → 这不是建议，是口号。改写或删除。

## 5. 学习路径表格规范

**表格列定义**：

| 列名 | 内容 |
|------|------|
| 步骤 | 第 X 步：具体步骤名称 |
| 核心知识 | 需要掌握的核心概念 |
| 知识网络连接 | 与其他主题的关联（用 → 表示递进，用 → 需要表示依赖）|

**最终整合**：在表格后用一段话总结闭环流程。

## 6. 链接处理规则

> **前置要求**：链接处理必须在**第三步（预获取链接信息）**中完成，不得在编译阶段临时获取。

详见 [link-handling.md](link-handling.md)

## 7. 特殊字符处理

文章标题中可能含有干扰 Markdown 渲染的字符：
- `|` → 替换为全角 `｜` 或省略
- `[` `]` `_` `*` → 需转义或省略

## 8. 内容必须基于知识库实际文件

导览笔记的文章列表必须从 `get_knowledge_list` 返回的实际文件生成，不能依赖本地缓存文件。

## 9. 编译质量标准

1. **原子化**：每个知识节点围绕单一主题，避免东拉西扯
2. **关联性**：知识卡片之间通过超链接形成网状结构
3. **大纲化**：每个卡片内部有完整的章节结构
4. **可溯源**：标注每篇文章的来源出处
5. **可读性**：结构清晰、信息密度适中、美观易读
6. **confidence 标注**：每个论断有可信度（Karpathy 特色）

## 10. 导览自检清单（v1.1.1 新增）

创建完成后，逐项检查：

### frontmatter 检查

- [ ] `title` 含 `📖 主题导览：XXX` 前缀
- [ ] `type: guide` 固定值
- [ ] `confidence` 已评估（high/medium/low + 理由）
- [ ] `created` 和 `updated` 日期正确
- [ ] `version` 符合语义化版本规则
- [ ] `changelog` 记录所有版本历史
- [ ] `sources[]` 列出所有引用文章
- [ ] `related_guides[]` 列出相关导览

### 章节内容检查

- [ ] 章节一（主题定位）：约 100 字，含"是...的 XX 层"句式
- [ ] 章节二（核心概念）：每个概念 200-300 字
- [ ] 每个关键要素都包含 4 个维度（定义/原理/应用/引用）
- [ ] 每个实践建议都是可执行任务（动词 + 量化标准 + 来源）
- [ ] 章节三（学习路径）：≤ 5 步，表格+段落
- [ ] 章节四（相关主题）：表格，说明具体连接点

### 反模式检查

- [ ] 没有"空话要素"（如"这是一个复杂的概念"）
- [ ] 没有"原则化建议"（如"应该谨慎决策"）
- [ ] 没有虚假引用（"比如某文章指出"但没具体链接）
- [ ] 没有无出处建议（"建议实践"无来源）
- [ ] 没有 Markdown 干扰字符（`|`、`[`、`]`、`_`、`*`）

### 链接检查

- [ ] type 2/6 文件都有可点击 URL
- [ ] type 7/11 文件没错误内嵌链接
- [ ] type 1/3/4/5/9/12-21 都标注"请在知识库查看"

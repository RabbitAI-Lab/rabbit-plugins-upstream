# 口播稿转分镜 (ym-script-to-shotlist)

把一份口播稿拆成「照着就能拍」的分镜表。核心不是「配个合适的画面」这种空话，而是每个镜头都写清**可被拍出来的具体画面**、景别、运镜、时长、字幕与道具，并核算总时长。条件有限时给一份最低配置版。

## 何时使用

- 用户说「把稿子分镜」「这个怎么拍」「分镜头脚本」「拍的时候怎么切」「shot list」时
- 用户有了口播稿或故事稿，准备实拍短视频/课程视频时
- 用户问「这段大概要拍几个镜头、多长」时

## 运行前提

- 依赖：无第三方依赖，纯文本处理
- 不读取任何本地文件，除非用户明确给出路径
- 不联网、不上传素材；不生成视频、不生成图片

## 输入契约

| 项 | 必需 | 说明 |
|---|---|---|
| 口播稿全文 | 必需 | 要拆分的稿子，最好是完整稿（含停顿标注更好）。故事稿也可 |
| 拍摄条件 | 可选 | 单机位/多机位、是否有人出镜、场地、是否可外出；默认单机位+一人出镜+室内 |
| 总时长目标 | 可选 | 默认按稿子字数估算（每秒 3.5~4 字），不强行设定 |
| 画幅 | 可选 | 横屏 / 竖屏；默认竖屏（短视频常见） |

**缺失处理：**

- 缺拍摄条件 → 按「单机位 + 一人出镜 + 室内」最简方案设计，开头注明「拍摄条件未提供，以下按单机位室内假设」。
- 缺画幅 → 默认竖屏并注明。
- 稿件未分段 → 先按语义切句（一句或一组意思完整的话 = 一个镜头单元），再分镜；不把一句话拆成两个镜头。
- 只有主题没有稿子 → 说明需要先有口播稿，建议先做口播稿再分镜，不凭主题臆造内容。

## 执行步骤

1. **切镜头单元** — 按语义把稿子切成镜头：一句或一组意思完整的话 = 一个镜头；避免一句话跨两个镜头。切完后列出「稿件 → 镜头」对照。

2. **逐镜填七列** — 每镜填写：镜号 / 对应文案（原文引用）/ 画面描述 / 景别 / 运镜 / 时长（秒）/ 字幕或花字 / 道具或场地。七列缺一不可，模板见 `templates/shotlist-template.md`。

3. **画面必须可拍** — 每个镜头的画面描述必须是「能被拍出来的具体画面」：出现什么、谁、在什么位置、做什么动作。禁止写「配一个合适的画面」「展示氛围」「用空镜过渡」这类空话；空镜也要写清拍什么（如「拍一杯凉掉的咖啡特写，桌上散着文件」）。

4. **景别与运镜节奏** — 连续 **3 个同景别必须换**，换时写明理由（避免视觉疲劳）。景别与运镜的选用见 `references/framing-movement.md`。换景别优先在情绪或语义转折处切。

5. **时长核算** — 按每秒 3.5~4 字估算每镜时长（口播语速因人而异），累加得总时长，与目标对比。超出目标 **15% 内**可微调；超出则**标出可压缩的镜头**（哪镜能短、哪镜能合并），不静默删字。

6. **难度与成本提示** — 标出哪些镜头需要额外道具、场地、多人配合或转场，给「可替换为更省事的拍法」及替代方案。

7. **最低配置版** — 当用户条件有限（如只能手机单机、无道具、无外景），给出一份合并版：哪几个镜头可合并、哪些可改静态图文/B-roll 替代出镜。最低配置版也要保证七列齐全。

8. **硬性约束**：不生成视频、不生成图片、不做剪辑；不改写用户文案（如需改，单独列「建议不改原文」放最后，不混入分镜表）；景别/运镜写不出具体方案的镜头，标「待定」并说明需要用户补充什么。

## 输出格式

Markdown，顺序：一、拍摄前提与假设；二、分镜表（七列）；三、总时长核算；四、难度与成本提示（含简化替代）；五、最低配置版分镜。套用 `templates/shotlist-template.md`。

## 能力边界

- 不生成视频与图片；不保证时长精确（口播语速因人而异，只能估算）
- 不做后期剪辑指导（转场、调色、配乐不在范围内）
- 不改写用户文案（改写建议单独列，不混入分镜）
- 不保证拍出来好看（构图审美、打光等需拍摄者把控）
- 不接入任何剪辑软件或素材库

## 常见坑

1. **画面描述写空话** — 现象：画面栏写「配一个合适的画面」「展示一下氛围」。原因：没想清具体拍什么。规避：第 3 步硬性要求写清「出现什么/谁/在哪/做什么」，空镜也要具体化。
2. **连续同景别视觉疲劳** — 现象：10 个镜头全是中景说话。原因：图省事。规避：第 4 步连续 3 个同景别必须换，并写换的理由。
3. **一句话拆成两镜** — 现象：半句一个镜头，剪辑点卡在话中间。原因：按字数均分。规避：第 1 步以「语义完整」为切镜单位，不按字数。
4. **时长超了静默删字** — 现象：要 60 秒拍出 90 秒的稿，直接把稿子砍了。原因：默认要凑时长。规避：第 5 步只标可压缩镜头并给建议，删不删、改不改由用户定。
5. **最低配置版偷工减料** — 现象：条件有限时给的分镜七列不全，或干脆说「随便拍拍」。原因：觉得简版不用认真。规避：第 7 步最低配置版同样七列齐全，只是镜头合并/改图文替代。
6. **擅自改写文案** — 现象：分镜里把用户「我觉得还行」改成「我特别满意」。原因：想让稿子更顺。规避：第 8 步文案一律原文引用，改写只在最后的「建议不改原文」单列。

## 验收用例

- 正常：300 字口播稿 → 10~14 个镜头，七列齐全，总时长有核算。
- 边界 1：只能室内单机位 → 全部镜头按此约束设计，不外景，仍七列齐全。
- 边界 2：总时长超出目标 30% → 标出可压缩镜头与删减建议，不静默删字。
- 失败：只有主题没有稿子 → 说明需先有口播稿，或先做口播稿再分镜。

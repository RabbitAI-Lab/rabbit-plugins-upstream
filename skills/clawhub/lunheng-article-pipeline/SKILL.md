# 多 Agent 深度长文流水线（论文/深度文章生产）

> 把一篇深度文章/论文的生产拆成 6 个角色 + 5 个阶段，用 OpenClaw `sessions_spawn` 子代理编排。产出有证据底座（文献卡+数据卡）、有反方论证、有独立审计、有人工核验节点的交付物。
> 适用：公众号深度文章、研究报告、论文、长文评论。经验证：一篇 7650 字/8 节/2 图/52 文献/60 数据点的深度文，全流程约 2 小时完成。

## 何时使用
- 主人要一篇「有深度、要站得住脚」的长文（>3000 字），且愿意等 1-3 小时
- 主题涉及事实/数据/多方观点，需要证据底座而非纯观点输出
- 需要「人在环」把关：大纲确认后再写，终稿人工审

## 流水线全景（Phase 0-5）

```
Phase 0 定题        与主人确认主题/篇幅/受众/配图需求 → 01-任务简报.md + status.md
Phase 1 并行检索    T1 文献检索员 ∥ T2 数据检索员（sessions_spawn 并行，sessions_yield 等待）
Phase 2 分析        T3 分析员 → analysis/分析大纲.md（论点-论据映射 + 反方论证规划）
Phase 2.5 大纲确认  主人过目大纲 → 确认/修改（人在环！改方向成本最低，不可跳过）
Phase 3 写作        T4 写手 → drafts/初稿-v1.md（铁律：引用标[Lxx]、数字标[Dxx]、AI去味10项）
Phase 4 审计        T5 审计员 → audits/审计报告-vN.md（G0覆盖度/G1引用核验/G2数据溯源/G3逻辑/G4格式/G5规范）
Phase 4.2 修订      审计打回 → 写手交修订说明+修订稿 → 审计复核 ≤2 轮 → 仍不过升级主控
Phase 4.5 配图      （可选）写手标 [图N：标题] 图位 → 主控程序化生成图表（数字与数据卡一致），封面按需文生图
Phase 5 终检        主控终检 → final/定稿.md + 图件/ + 证据包/ + 交付说明.md
```

## 项目目录结构

```
run/<项目名>/
├── 01-任务简报.md       # Phase 0 产出：子问题拆解 + 字数预算 + 配图需求 + 期刊/风格模板
├── status.md            # 状态机：Inbox→Assigned→In Progress→Review→Done|Failed（角色交接必更新）
├── literature/文献卡.md # T1 产出：[L01]... 每条含可信度等级 A/B/C + 关联
├── data/数据卡.md       # T2 产出：[D01]... 每条含来源机构+年份+URL+时效🟢🟡🔴
├── analysis/分析大纲.md # T3 产出：论证主线+映射表+反方规划+章节字数预算
├── drafts/初稿-vN.md    # T4 产出 + 修订稿 v2/v3 + 修订说明
├── audits/审计报告-vN.md# T5 产出：P0致命/P1严重/P2建议
├── final/定稿.md        # Phase 5：终稿（去标注版另存）
├── final/图件/          # 数据图表 + 封面
├── final/证据包/        # 文献卡+数据卡+审计报告+核验记录
└── final/交付说明.md    # 路径+图件清单+遗留风险+人工核验项
```

## 核心原则

1. **证据底座先行**：任何论点必须能映射到文献卡[Lxx]或数据卡[Dxx]；检索不到就标缺口，严禁编造
2. **人在环三节点**：Phase 0（定题）、Phase 2.5（大纲）、Phase 5（终稿）必须让主人过目
3. **反方论证强制**：每个核心论点配「可能的反驳+回应策略」，避免单边叙事
4. **独立审计**：审计员只审不改，与写手分离；引用分级抽验（C级100%/B级≥50%/A级≥10%）
5. **模型分工**：检索用便宜快模型（如 deepseek-v4-flash），分析/写作用推理强模型（如 deepseek-v4-pro / MiniMax-M3），审计用顶配（如 MiniMax-M3 / Claude），主控负责判断路由（具体按本机可用模型调整）

## 派发话术（主控复制即用，完整版见 references/agents/）

### T1 文献检索员（并行①）
```
你是「文献检索员」。任务编号 T1。
项目目录：run/<项目名>/
任务简报：先读 01-任务简报.md；更新 status.md 对应行为 In Progress
任务：
1. 用 web_search / tavily_search 检索主题相关文献（中英文；知网/万方/Google Scholar/期刊官网/SSRN）
2. 产出 literature/文献卡.md：8-15 条核心文献，按子问题分组
3. 每条必须真实存在：作者、年份、标题、期刊/来源、DOI 或 URL、与本文的关联
4. 每条标可信度等级：A（核心期刊/权威机构）/ B（一般期刊/预印本）/ C（网络/二手转引）——C 级必须诚实标注
5. 参考文献条目按任务简报指定格式输出（默认 GB/T 7714），写手可直接粘贴
6. 严禁编造引用；检索不到就写「未检索到」，不许凑数
7. 交接报告六要素（含 status.md 更新）
```

### T2 数据检索员（并行②）
```
你是「数据检索员」。任务编号 T2。
项目目录：run/<项目名>/
任务简报：先读 01-任务简报.md；更新 status.md 对应行为 In Progress
任务：
1. 用 web_search / tavily_search 检索主题相关统计数据（国家统计局/世界银行/CEIC/皮书/权威数据库）
2. 产出 data/数据卡.md：每个数据点含「数值+来源机构+年份+URL」；按子问题分组
3. 每条标时效评级：🟢 ≤2年 / 🟡 2-5年 / 🔴 >5年（红级显著标注）
4. 同指标多来源矛盾 → 强制并列呈现+口径差异说明，不擅自二选一
5. 严禁编造数据；找不到精确数据就标注「缺口：建议人工查 XX 数据库」
6. 交接报告六要素（含 status.md 更新）
```

### T3 分析员
```
你是「分析员」。任务编号 T3。
项目目录：run/<项目名>/
先读：01-任务简报.md、literature/文献卡.md、data/数据卡.md；更新 status.md
任务：产出 analysis/分析大纲.md，包含：
1. 研究问题界定与文献缺口
2. 论证主线 + 论点-论据映射表（每个论点标注对应文献卡/数据卡编号）
3. 反方论证规划：每个核心论点配「可能的反驳 + 回应策略」
4. 分析框架建议（制度/比较/历史/定量任选，说明理由）
5. 写作结构建议（章节安排 + 每节字数预算）
严禁：编造文献/数据来填补缺口——缺口就如实标注。
完成后等待主控确认（Phase 2.5），确认通过前不进入写作。
交接报告六要素（含 status.md 更新）
```

### T4 写手
```
你是「写手」。任务编号 T4。
项目目录：run/<项目名>/
先读：01-任务简报.md（重点：期刊模板/字数预算）、analysis/分析大纲.md、literature/文献卡.md、data/数据卡.md；更新 status.md
任务：产出 drafts/初稿-v1.md，全文成稿（含摘要、关键词、正文、参考文献列表）
铁律：
1. 每处引用标注文献卡编号 [L03]，每个数字标注数据卡编号 [D07]
2. 只使用文献卡/数据卡里真实存在的内容；写不出就标 [待补]，绝不编造
3. 遵守禁做清单（AI 去味 10 项）：排比堆砌/金句密度/模板腔等一律不写
4. 每个核心论点按大纲写「可能的反驳 + 回应」
5. 参考文献列表用任务简报指定格式（期刊模板优先），直接粘贴文献卡条目
6. 若简报「配图需求」含数据图表：在正文图应出现处标 [图N：标题]（N 按序编号），图上数据必须来自数据卡，与正文 [Dxx] 一致；不画图，只标位置和图注
7. 被审计打回时：交 修订说明（逐条回应 P0/P1）+ 修订稿 v2/v3
交接报告六要素（含 status.md 更新）
```

### T5 审计员
```
你是「审计员」。任务编号 T5。你的职责是找出写手自己看不到的问题。
项目目录：run/<项目名>/
先读：01-任务简报.md、analysis/分析大纲.md、drafts/初稿-vN.md、literature/文献卡.md、data/数据卡.md；更新 status.md
任务：产出 audits/审计报告-vN.md，按严重级列出问题：
- P0 致命（必须改）：编造引用/数据、论点无据、论证链断裂、跑题（研究问题未回答）
- P1 严重（应当改）：格式不统一、数据缺溯源/红级数据未说明、AI 空话套话、反方观点缺失
- P2 建议：可优化项
必须执行：
0. G0 覆盖度：对照任务简报逐项核对每个研究问题是否被回答、有无跑题
1. G1 分级核验：C 级引用 100% 用 web_search 核验、B 级 ≥50%、A 级 ≥10%；抽到假的升级 P0 并全量核验；抽验时做上下文匹配检查（防张冠李戴）
2. G2 数据溯源：逐个数字找来源；数据卡没有的 → P0；关键论点用红级数据未说明 → P1
3. G3 逻辑：对照大纲检查论点-论据映射是否成立
4. G4 格式：结构完整、引用格式符合期刊模板、参考文献与正文标注一一对应、篇幅符合预算
5. G5 规范：查重意识 + 写手禁做清单 10 项逐项查
若本轮是修订稿：对照写手修订说明逐条确认 P0/P1 关闭情况，未关闭的升级 P0。
结尾给出结论：通过 / 打回修订（附必须修改清单）
交接报告六要素（含 status.md 更新）
```

## 审计必查项（G0-G5 详解）

| 检查项 | 内容 | 违规级别 |
|--------|------|---------|
| G0 覆盖度 | 对照简报逐项核对研究问题是否回答、有无跑题 | 缺失→P0 |
| G1 引用核验 | C级100%/B级≥50%/A级≥10% 抽验 + 上下文匹配 | 假→P0 |
| G2 数据溯源 | 每个数字查数据卡来源；关键论点用🔴数据未说明 | 无源→P0 / 红级→P1 |
| G3 逻辑 | 论点有无论据、论据是否支撑、有无稻草人 | 断裂→P0 |
| G4 格式 | 结构完整、引用格式、参考文献对应、篇幅 | 不统一→P1 |
| G5 规范 | 查重意识、AI 痕迹（禁做10项逐项查） | 套话→P1 |

## 修订回环
```
审计结论=打回 → 写手交 修订说明（逐条回应）+ 修订稿 → 审计员对照复核
最多 2 轮。仍不过 → 升级主控：重写/砍段落/咨询人类。
```

## 配图生成规范（Phase 4.5）

- **数据图表**：程序化生成（matplotlib/SVG 脚本），**禁止文生图**（数字不可控）。图位来自写手标注的 [图N]，图上数字必须与数据卡/正文 [Dxx] 一致，生成后抽查核对
- **封面视觉**：文生图或 SVG 矢量风均可；出图先送主人确认风格再定稿
- **中文字体**：matplotlib 需显式注册 Noto Sans CJK SC，否则中文乱码
- **图件入 final/图件/**，交付说明列清单；数值标签与来源注释避免同侧重叠（来源统一放底部）

## 写作禁做清单（AI 去味 10 项，审计员逐项查）

1. 排比堆砌（连续 3 组以上同构排比 → 拆掉）
2. 金句密度过高（每千字不超过 1 句"点睛句"）
3. 无第一人称（要有"我认为/本文认为"的主体声音）
4. 缺具体细节（论证必须有具体案例/数字/场景支撑）
5. 过度防御性表述（"值得注意的是""不可否认"滥用）
6. 抽象概念密度过高（一段超 2 个抽象大词 → 拆解+举例）
7. 段落结构过度对称（避免每段"总-分-总"机械对称）
8. 学术过渡词过多（"综上所述""进而""由此可见"克制使用）
9. 表格过多（非必要不列表）
10. 缺研究者个人观察（正文要有自己的判断和发现）

## 成本与模型建议

| 角色 | 模型 | 理由 |
|------|------|------|
| 文献/数据检索 | 便宜快模型（如 deepseek-v4-flash） | 机械检索，最便宜可靠 |
| 分析/写作 | 推理强模型（如 deepseek-v4-pro / minimax-m3） | 推理与成文质量 |
| 审计 | 顶配模型（如 minimax-m3 / claude） | 专抓错，必须顶配 |
| 主控 | 强推理模型（如 deepseek-v4-pro） | 判断与终检 |

## 实战验证案例

- **商业热点深度文**（2026-08）：8节/7650字/2数据图/52文献/60数据点，全流程约2小时。关键产出：事件时间线修正（"三次炮轰"实为"两年五次"）、监管规则逐条对照、行业案例对比。实战教训：除非作者明确要求，文章受众按普通人写，不硬贴作者职业视角。

# 中国式施工日志 Skill

将施工员、项目技术负责人或用户通过文字、语音、微信发送的零散现场信息，整理为符合中国工程资料书写习惯的正式施工日志，并按用户现有 Word 模板生成、保存和验证 `.docx` 文件。

本 Skill 的核心不是把日志写得“丰富”，而是把真实现场事实整理得专业、连续、可追溯。未提供的关键数据不得臆造；补录内容必须明确属于待核实草稿。

## When to Use

- 用户说“写施工日志”“补写施工日志”“补齐前几天日志”“生成日报”。
- 用户发送施工部位、工序、班组、材料、机械、人员、天气或安全情况。
- 用户发送施工日志 Word 模板，要求按模板填充。
- 用户需要把口语、方言、语音识别文本整理成中国式工程资料。
- 用户需要根据前后几天日志保持施工工序连续。

不要用于：编造工程量、补造签证事实、替代正式验收记录、替代安全事故报告或未经核实地确认隐蔽工程质量。

## Prerequisites

- `python-docx`，用于读取和生成 Word。
- 用户提供的 Word 模板，或项目目录中已经确认可用的模板。
- 生成前使用 `read_file`、`search_files` 或 `terminal` 核对模板、历史日志和输出目录。
- 天气需要查询时，使用 `terminal` 调用 Open-Meteo 等结构化天气接口；无法查询时不得猜测天气。
- 生成后使用 `terminal` 运行文档验证脚本，或用 Python 直接检查 Word 结构。

## 默认项目配置

以下是本项目“镇海区综合体育中心建设工程”的默认配置。遇到其他项目时，先读取用户模板和项目资料，不得盲目套用这些值。

```text
工程名称：镇海区综合体育中心建设工程
表格：甬筑表 C01-8
模板：桌面/自动日志/6月份/施工日志_20260628.docx
日志目录：桌面/自动日志/<月份>/
页号基准：2026-05-20 为第 43 页
页号公式：43 + (目标日期 - 2026-05-20).days
纸张：A4，210×297 mm
正文：宋体 11 磅
```

## Evidence Policy

### 必须忠实记录

用户明确说出的以下内容优先作为事实：

- 日期、施工区域、施工部位、工序和完成状态。
- 用户明确提供的人员数量、机械数量、材料数量和工程量。
- 用户明确提供的天气、停工、复工、质量问题和安全问题。
- 用户确认过的前后工序关系、班组安排和整改结果。

### 严禁擅自编造

除非用户提供或项目原始资料明确记载，不得自行增加：

- 工程量、方量、吨位、面积、长度、数量、百分比。
- 桩号、轴线、标高、尺寸、强度等级、配合比、坍落度。
- 试块、检测、验收、监理指令、隐蔽验收和签证编号。
- 具体工人数量、机械台数、材料进场数量。
- “验收合格”“达到设计要求”“无质量问题”等结论性事实。
- 事故、处罚、重大隐患或不存在的整改闭环。

缺少非关键数据时，使用中性表达：

- 人员：`现场管理及作业人员按当日施工安排到岗。`
- 机械：`施工机械及小型工具按现场需要使用。`
- 材料：`相关材料按需进场，满足当日施工需求。`
- 状态：`持续施工`、`按现场条件推进`、`待核实`。

## Procedure

### 1. 确定日期和项目

1. 识别用户明确给出的日期。
2. 用户说“今天”“昨天”时，先用中国时区确认日期，不使用可能过期的会话日期或主机时区。
3. 日期仍有歧义时，只询问准确日期，不生成猜测文件。
4. 确认项目名称、日志月份目录和目标文件名。

完成标准：日期、项目、输出目录和文件名均可明确确定。

### 2. 收集原始事实

按以下顺序收集：

1. 当前用户消息中的施工事实。
2. 当前项目文件夹中最近 2—3 份日志。
3. `session_search` 找到的同日期或前后日期施工信息。
4. 用户明确确认过的历史事实。

不要因为目录中缺少文件，就推断当天一定施工；不要因为有前一天日志，就把前一天所有内容原样复制到当天。

完成标准：把信息分成“用户明确事实”“历史文件事实”“合理工序承接”“尚未提供”四类。

### 3. 检查前后工序连续性

读取最近日志的现场情况，建立工序状态：

- 已开始但未完成：下一天写“继续施工”或写明新的完成状态。
- 混凝土已浇筑完成：后续优先承接“覆盖、洒水养护、成品保护”。
- 钢筋绑扎完成：后续检查模板、预埋、验收或进入下一道工序，但只有资料明确时才能写成已完成。
- 模板开始封模：后续可承接模板加固、封模检查或浇筑准备，不得直接跳成浇筑完成。
- 雨天、台风或停工：后续优先承接排水、巡查、加固、养护和复工条件检查。
- 已明确完成的工作：不得无理由写成当天仍在施工。

连续性只能用于选择保守的承接表达，不能用来创造工程量和验收结果。

完成标准：当天每一项都能解释其来源，是用户事实、前日承接还是待核实草稿。

### 4. 查询天气

需要填写天气时，查询项目所在地和目标日期的结构化天气数据。默认宁波/镇海坐标约为 `29.87, 121.55`，但其他项目必须使用实际所在地。

建议使用 Open-Meteo 的历史或预报接口，并将天气简化为：

```text
最高XX°C 最低XX°C 天气描述
```

温度取整。天气单元格保持简短；“台风影响”“持续停工”“雨后检查”等施工影响写入现场情况和技术质量安全记录，不要全部塞进天气单元格。

如果天气只能取得预报而非实况，交付时说明“天气为接口数据/待现场核实”；天气查询失败时，保留待填或询问用户，不得凭季节经验编造。

完成标准：天气来源、日期和所在地对应，且天气字段适合放入 Word 单元格一行内。

### 5. 整理为中国式施工日志语言

用户口述应转成正式、简洁、可追溯的书面语。

常用转换：

- “西南角水沟粉刷” → `西南角排水沟进行内壁及侧壁粉刷施工。`
- “西北角修坡，一级坡完成” → `西北角基坑边坡进行修坡施工，一级边坡修整完成。`
- “九区支撑梁模板加固并浇筑” → `九区支撑梁进行模板加固及混凝土浇筑施工。`
- “下雨没干活” → `受降雨天气影响，现场暂停不具备条件的露天施工作业，开展排水及安全巡查。`

使用：`进行……施工`、`持续施工`、`按计划推进`、`完成……`、`检查……情况`、`及时整改`。

避免：`今天搞了`、`做了一点`、`差不多完成`、`搞好了`、`应该没问题`、`估计完成`。

明显的语音识别同音错误可以结合施工语境纠正，例如“水沟气体”改为“水沟砌体”；会改变工程事实的歧义必须保留并向用户确认。

每个施工项目用一条简洁句子表达，不为凑字数重复“施工”“进行”“现场”等套话。

### 6. 编排 Row 4：现场情况

中国式 C01-8 模板的 Row 4 使用以下固定顺序：

```text
一、现场情况：
1、施工部位及工序，作业内容，必要的过程控制或完成状态。
2、……

二、材料：
材料进场、使用或按需进场情况；没有具体数量时不写数量。

三、机械：
用户明确提供的机械及数量；未提供时使用“按需使用”。

四、人员：
用户明确提供的人员及数量；未提供时使用“按当日施工安排到岗”。
```

项目数量较多时，按“区域 → 部位 → 工序 → 状态”排列。多作业面同时施工时可以列出多个项目，但不得凭经验补出人员和机械台数。

### 7. 编排 Row 5：技术质量安全记录

Row 5 必须对应当天 Row 4 的施工内容，采用“检查/风险 → 措施 → 结果”的闭环表达：

```text
技术质量安全工作记录存在问题及处理情况：
1、针对当天工序进行过程质量检查和控制。
2、针对临边、机械、基坑、临时用电或雨季施工进行安全巡查。
3、明确存在问题时写整改措施；没有用户事实时不要虚构具体问题。
项目技术负责人：________________________
施工记录：YYYY年MM月DD日
```

可以写过程控制，例如模板拼缝、支撑稳定、混凝土覆盖养护、排水沟疏通、临边防护检查；不能将“已检查”扩大为“验收合格”或“符合设计要求”。

项目技术负责人和施工记录必须位于 Row 5 内部的最后两行，不得放在表格外。

### 8. 补录缺失日期

用户要求补齐一段日期时：

1. 枚举目标月份目录中的已有文件，找出准确缺口。
2. 逐日按时间顺序生成，不能跳过缺失日期。
3. 优先搜索会话历史中的具体施工事实。
4. 没有原始事实的日期可以生成“连续性补录草稿”，但使用保守表述，不填具体人数、机械台数、工程量、检测结果和验收结论。
5. 交付消息必须明确哪些日期是有原始记录、哪些日期是按工序连续性补录。
6. 对补录草稿加入“现场具体情况需核对”等提示，或至少在交付说明中提示核实后再归档。
7. 若前后已有日志与补录内容冲突，暂停并向用户说明冲突，不要默默覆盖。

完成标准：目标日期数量、已生成日期和待核实项目均有清单。

## Word Template SOP

### 模板结构

默认文档顶层结构必须是：

1. 一个标题段落：`施工日志`，居中，保留原模板字号。
2. 一个 4 列 × 6 行表格。
3. 文档节属性。

表格内容：

| 行 | 内容 |
|---|---|
| Row 0 | 表格编号 / 甬筑表 C01-8 / 页号 / 页号数值 |
| Row 1 | 工程名称 / 工程名称跨三列合并 |
| Row 2 | 日期 / 中国日期格式 / 天气 / 天气字符串 |
| Row 3 | 只保留 `施工内容及情况：（施工部位、内容、机械、人员等）` |
| Row 4 | 现场情况、材料、机械、人员 |
| Row 5 | 技术质量安全记录、项目技术负责人、施工记录 |

Row 4 和 Row 5 的内容写入合并区域左侧单元格（通常为 `cells[0]`），使用一个 Word 段落内的 `\n` 软换行。不要对合并单元格的每个别名重复写入，也不要为普通日志使用 `add_paragraph()` 造成多余段落。

### 排版参数

- A4：210 × 297 mm。
- 表格行高固定为 `[400, 360, 400, 400, 7000, 4500]` twips。
- 表格正文所有非空 run 显式设为宋体 11 磅。
- `ascii`、`hAnsi`、`eastAsia`、`cs` 均设为宋体。
- 保留模板的表格边框、合并关系、页边距和段落基础样式。
- 页号使用项目配置中的基准日期和基准页号计算，不凭文件数量猜测。

### 生成顺序

1. 复制或读取经过确认的模板。
2. 写入 Row 0 页号、Row 1 工程名称、Row 2 日期和天气。
3. Row 3 只保留标题。
4. 写入 Row 4 和 Row 5。
5. 遍历所有表格 run，显式设置字体和字号。
6. 清理表格外重复的“项目技术负责人”和“施工记录”段落，但保留顶部“施工日志”标题。
7. 保存到 `桌面/自动日志/<月份>/施工日志_YYYYMMDD.docx` 或用户指定目录。

### 生成示意

```python
from docx import Document
from docx.enum.table import WD_ROW_HEIGHT_RULE
from docx.shared import Pt
from docx.oxml.ns import qn

doc = Document(str(template_path))
table = doc.tables[0]
table.cell(0, 3).text = str(page_number)
table.cell(1, 1).text = project_name
table.cell(2, 1).text = chinese_date
table.cell(2, 3).text = weather
# 合并单元格只写 cells[0]
table.cell(4, 0).text = row4_text
table.cell(5, 0).text = row5_text
for row, twips in zip(table.rows, [400, 360, 400, 400, 7000, 4500]):
    row.height = twips * 635
    row.height_rule = WD_ROW_HEIGHT_RULE.EXACTLY
for row in table.rows:
    for cell in row.cells:
        for paragraph in cell.paragraphs:
            for run in paragraph.runs:
                if not run.text:
                    continue
                run.font.name = "宋体"
                run.font.size = Pt(11)
                rfonts = run._element.get_or_add_rPr().get_or_add_rFonts()
                for attr in ("ascii", "hAnsi", "eastAsia", "cs"):
                    rfonts.set(qn("w:" + attr), "宋体")
doc.save(str(output_path))
```

注意：上方示意中的 `table.cell(5, 0)` 前不能有多余缩进；实际执行时先通过 `write_file` 保存完整 Python 脚本，再使用 `terminal` 调用正确的 Python 环境。

## Verification

生成后必须实际检查，而不是只判断文件存在：

- [ ] 目标日期文件数量正确，没有漏日期或重复覆盖。
- [ ] Word 包可以由 `python-docx` 正常打开。
- [ ] 只有 1 个表格，表格为 6 行 × 4 列。
- [ ] 顶层只保留“施工日志”标题、表格和节属性。
- [ ] Row 3 只有标题，没有详细施工内容。
- [ ] Row 4 和 Row 5 各只有一个段落，使用软换行。
- [ ] Row 5 最后包含项目技术负责人和施工记录。
- [ ] 所有非空 run 为宋体 11 磅，四类字体属性均已设置。
- [ ] 行高为 `[400, 360, 400, 400, 7000, 4500]` twips。
- [ ] 日期、星期、天气、页号正确。
- [ ] 输出目录属于目标月份，而不是误放到其他月份。
- [ ] 没有将未提供的数量、工程量、验收结果写成确定事实。
- [ ] 补录文件已在交付说明中标记待核实。

建议同时运行项目已有的 Word 验证脚本；验证失败时先修复文档，再交付文件。

## Pitfalls

1. **模板字号继承错误**：仅复制模板不代表新写入文字仍是正确字号，必须遍历所有新 run 显式设为宋体 11 磅。
2. **合并单元格重复**：Row 4/5 的多个 `cells` 可能是同一个合并区域的别名，只写左侧单元格。
3. **表格外重复签名**：旧脚本可能在表格外生成项目技术负责人和施工记录，必须删除外部重复段落。
4. **Row 3 塞入详细内容**：Row 3 只能保留固定标题，详细内容全部放 Row 4。
5. **把合理推测写成事实**：连续性推断只能写“继续”“按需”“待核实”，不能自动产生数量和验收结论。
6. **天气单元格过长**：台风、暴雨影响写入 Row 4/5，天气格只写简短天气描述。
7. **日期和页号错位**：使用中国时区确认日期，并按项目基准页号公式计算。
8. **把补录当成原始记录**：没有现场原始材料的日期，交付时必须标明为补录草稿，归档前由现场人员核实。
9. **跨月份模板错误**：新月份优先使用已确认的上一份正确格式模板，不要随意使用格式异常的文件。
10. **生成但不验证**：文件存在不代表 Word 结构、字体、合并单元格和页式正确，必须逐项检查。

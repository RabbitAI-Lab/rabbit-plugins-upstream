# 监理—施工日志对照：稀疏决策与验证

## 适用范围

以用户指定的监理原件为主源，审核旧施工日志的额外事实；JSON决策审核与Word生成分离。本文记录已执行过的批量审核方法，不把任何旧日志、旧助手推排或本技能的历史推断升级为独立现场证据。

## 步骤

1. 只读载入输入数组，统计总记录数、唯一日期数、已有旧日志数及源文件/表序号；先保留输入原顺序，不用日期字典静默吞掉重复项。
2. 默认逐项生成空保留数组。分批阅读所有监理施工、材料、机械、质量、其他事项；对有旧日志的日期逐项对照。
3. 保留明确、额外、不矛盾且值得保留的完整原句/条目，只去编号。不以“未提”自动判冲突，也不为填满页面保留模板化事项。
4. 桩基检查：同日总数、各分项及累计、列出的桩号数量；另按真正桩号查重，机号不是桩号身份的一部分。例如`17#C40`与`10#C40`可能是同一桩；还须核实是否存在不同区域重用编号。重复完成或不明编号使整条原条目不宜保留时，不删改其中一个号码来凑数。
5. 现场统计核验：工程桩/围护桩分别核算；连续日期且口径相同才检查前累计+本日=本累计。假期无施工记录不等于累计归零。机械“施工台数”与“成桩根数”不是同一口径，不能直接等同。试块数量仅在源文明确“每桩1组”等条件下判数值矛盾。
6. 日期和模板核验：公历星期、高低温行日期、重复日期、将来日期引用、停工后仍写“昨日成桩”、复制旧页的材料/通知单编号/累计倒退。尺寸偏差和合格结论缺依据时只列疑点，不能凭经验改判不合格。
7. 写出严格JSON后重读，验证全部输入日期均有输出、字段与数组类型、原句来源子串、保留桩号无未解释重复、源文件哈希未变化。重复日期用源文件和表序号追踪，不自动合并。

## 土方、围护及塔吊阶段补充检查

- **完整现场栏扫描**：先读整个 `existing_scene`，再识别编号条目、材料、机械、人员及尾部追加事项。2026年3—6月101条审核中，5月20日人员栏后的“其他现场作业”另含排水沟回填、钢筋绑扎、水沟粉刷等完整原句；按第一个“材料”截断会漏审。编号抽取之外必须检查未编号尾句。
- **附加工序与重复描述分开**：消防水池、西侧水沟、破桩、拆除等可以是监理未列的并行作业；机械库存、泛化养护和质量检查不因“不冲突”就值得保留。不要把相容性审核称为历史事实独立核实。
- **全句保留与污染判断**：若原句夹带来源不明的固定70%进度、8—12方估量或验收合格结论，在要求完整原句的任务中直接舍弃该候选；不可删掉可疑分句后拼成貌似真实的新句。过程目标（如“确保……符合要求”）与已经验收合格的结论语气不同，但二者仍需结合来源判断，不能用关键词规则代替审核。
- **同构件时序**：养护/拆模、基础开挖、塔吊安装、检测需按同一编号检查。示例：旧日志6月1日写2号塔吊侧模拆除，监理6月2日才明确记拆模，应以监理日期为准；旧日志6月18日仍写6号塔吊基础开挖“为安装做准备”，而监理同日已查验5、6号塔吊检测报告，不保留该安装前准备句。不同坡面与平台不是同一构件，不能把不同日期的浇筑自动判成重复。
- **监理内部数值核验**：示例为“24台钻孔桩机（4台工程桩机、10台围护桩机）”总分项不符；围护桩前日累计793、当日14却累计798；塔吊桩连续两天累计与当日数互相不平。alert列明原数与等式，计算只用于指出问题，不覆盖原数。
- **轴线—区块一致性**：同时比较施工、质量旁站栏，并参考同批明确映射。6月24日同日5区土方轴线出现C-K/Q-W不一致，垫层范围又出现C-F/F-W不一致；记录具体栏位和字符串，不猜正确轴线。
- **分级疑点**：明确“钻孔桩未施工”却照列灌注材料及钻孔旁站，是直接矛盾；缺少某机械/材料记录而另一栏提旁站，仅能标为疑似漏记或模板沿用。累计汇总有未列数量日期时，标注覆盖缺口，不能将缺口默认计零。重复通知单编号可能是一单多项，不直接认定多签；残缺“106³”“灭火器未”不凭经验补单位或隐患内容。

该101日期案例经结构与原句核验后，保留39条现场句子、质量保留0条，记录24条疑点；案例数量不是后续任务的预设比例。JSON结构验证不等于所有工程事实已获证实。

## 建议的断言

```python
assert len(decisions) == len(source_rows)
assert [x['date'] for x in decisions] == [x['date'] for x in source_rows]
required = {'date', 'keep_scene', 'keep_quality', 'alerts', 'omit_supervision_lines'}
for src, decision in zip(source_rows, decisions):
    assert set(decision) == required
    for key in required - {'date'}:
        assert isinstance(decision[key], list)
        assert all(isinstance(v, str) for v in decision[key])
    assert all(s in src['existing_scene'] for s in decision['keep_scene'])
    assert all(s in src['existing_quality'] for s in decision['keep_quality'])
```

字符串断言只证明保留文本来自旧日志，不能证明现场发生。语义取舍及明确的来源优先级仍须逐条人工审核。只有对当前项目确认过的桩号格式才使用正则；不要把正则匹配结果当完整解析，尤其注意一台机列多桩、标点合并、重复字母和区域前缀。

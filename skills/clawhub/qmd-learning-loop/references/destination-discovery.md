# Destination Discovery

Find the existing home for a learning before proposing a new file.

## Discovery order

1. Read workspace instructions and repository contribution guidance.
2. Inspect existing Markdown filenames and headings for:
   - daily or session logs;
   - incidents, errors, or troubleshooting;
   - backlogs, requests, or roadmaps;
   - runbooks and operational procedures;
   - decisions, policies, principles, or agent guidance.
3. If QMD is available, search likely terms and retrieve the full candidates.
4. Prefer the narrowest existing document whose purpose matches the learning.
5. Confirm that the destination is writable and that its owner or process
   permits the change.

## Target mapping

| Learning | Preferred existing target |
| --- | --- |
| Task chronology | Daily/session log |
| Reproducible failure | Incident or error log |
| Reusable recovery steps | Runbook or troubleshooting guide |
| Missing capability | Backlog, request log, or roadmap |
| Workflow convention | Agent or workflow guidance |
| Policy or governance change | Decision or policy document |
| Stable communication principle | Principles file, with explicit approval |

## No suitable destination

Do not invent a storage convention silently. Propose:

- the path and purpose of the new file;
- who owns it;
- what belongs there and what does not;
- whether QMD should index it; and
- one alternative that requires no new file.

Create it only after approval.

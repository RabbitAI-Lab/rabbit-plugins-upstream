# 专项管理规范

## 概述

专项（Special Project）是知识回顾系统的核心功能之一，用于支持结构化的备考/专题学习模式。用户可创建专项并为知识点自动关联，系统根据专项进度进行智能推送和紧迫提醒。

---

## 1. 专项角色与权重

### 1.1 主专项（Primary）

- 每个用户最多 1 个主专项
- 权重占比 55%（晚间回顾抽样）
- 权重仅在无副专项时调整为 70%
- 早间推送以主专项进度为核心输出
- 用户可通过 `设xx为主专项` 或 `切换主专项为xx` 来指定

### 1.2 副专项（Secondary）

- 每个用户最多 1 个副专项
- 权重占比 15%（晚间回顾抽样）
- 无副专项时，主专项权重提升至 70%，常规占比 30%
- 用户可通过 `设xx为副专项` 来指定

### 1.3 权重分配表

| 场景 | 主专项 | 副专项 | 常规 |
|------|--------|--------|------|
| 有主+副专项 | 55%（约3条/5条） | 15%（约1条/5条） | 30%（约1条/5条） |
| 仅有主专项 | 70%（约4条/5条） | — | 30%（约1条/5条） |
| 无任何专项 | — | — | 100%（约5条/5条） |

### 1.4 权重调整规则

- 当知识点总数 < 5 条时，不做权重抽样，有多少推多少
- 当主/副专项知识点不足时，差额权重自动转给常规
- 主专项知识点不足时逻辑：
  - 主专项知识点数 < 期望抽取数 → 取全部，差额补副专项或常规
  - 副专项知识点数 < 期望抽取数 → 取全部，差额补主专项或常规

## 2. DDL 紧迫判断

### 2.1 紧迫公式

```
进度 = total_learned / total_target
剩余天数 = (DDL日期 - 当前日期).days
日需 = (total_target - total_learned) / max(剩余天数, 1)
```

### 2.2 紧迫等级

| 等级 | 色标 | 条件 | 行动 |
|------|------|------|------|
| 🔴 紧急 | 红色 | DDL < 30天 且 进度 < 60% | 早间推送加入紧迫提醒，建议翻倍学习量 |
| 🟡 警告 | 黄色 | DDL < 60天 且 进度 < 40% | 早间推送温和提醒，"注意把控进度" |
| 🟢 正常 | 绿色 | 其他情况 | 正常推送，保持节奏 |

### 2.3 DDL 紧迫展示

早间推送中，紧迫消息置于最顶部：

```
🔴 紧迫提醒：HCIE DDL 仅剩 22 天，还有 40 个知识点未学！
⚠️ 每日需学 2 个知识点，请加快进度！
```

无紧迫时不展示紧迫提醒。

## 3. 大纲管理

### 3.1 大纲结构

大纲是专项的分模块学习计划，每个模块记录目标知识点数和已学数量：

```json
"outline": [
  { "module": "BGP", "target": 10, "learned": 3 },
  { "module": "MPLS VPN", "target": 8, "learned": 2 },
  { "module": "IPv6", "target": 5, "learned": 0 }
]
```

### 3.2 创建大纲

- 创建专项时可选：
  ```
  用户: 开启HCIE专项，DDL 8月15号，目标80点，大纲: BGP, MPLS, IPv6, SDN
  → 创建大纲为 4 个空模块，target=80 平均分配或用户指定
  ```
- 未提供大纲 → 创建专项后提示是否补充

### 3.3 补充大纲

```
用户: HCIE大纲补充: BGP进阶, MPLS TE, IPv6过渡
→ 在现有大纲末尾追加新模块
→ 返回确认：
  ✅ 已补充 HCIE 大纲，新增 3 个模块：
  - BGP进阶
  - MPLS TE
  - IPv6过渡
```

### 3.4 查看大纲

```
用户: HCIE大纲
→ 返回：
  📋 HCIE 大纲（已学 23/80）
  1. ✅ BGP（3/10）
  2. 🕐 MPLS VPN（2/8）
  3. 🕐 IPv6（0/5）
  4. ⬜ SDN（0/0）
  
  整体进度: 29% | DDL: 2026-08-15（剩 77 天）
```

- ✅ = 已学模块（learned > 0）
- 🕐 = 学习中（learned > 0 但未完成）
- ⬜ = 未开始（learned = 0）

### 3.5 大纲模块完成判断

当 `learned >= target` 且 `target > 0` 时标记为完成：
- 早间推送优先推荐未开始（⬜）模块
- 其次是学习中（🕐）模块
- 已完成的模块不再推荐

### 3.6 知识点的专项关联

当录入的知识点内容匹配专项大纲关键词时：
1. 自动关联到同名专项
2. 更新对应专项的 `total_learned` 计数
3. 若匹配大纲中的模块关键词，更新该模块的 `learned` 计数
4. 专项关联标记在知识点的 `special_project` 字段

**关联逻辑**：
```
知识点内容: "BGP 选路：AS-Path 越短越优先"
→ 匹配大纲模块 "BGP" → BGP.learned +1
→ total_learned +1
→ 知识点 special_project = "hcie"
```

## 4. 专项创建流程

### 4.1 标准创建

```
用户: 开启HCIE专项，DDL 8月15号，目标80个点

1. 检查是否存在同名活跃专项 → 如存在则提示已创建
2. 确认是否已有主专项 → 如有则询问是否替换或设为副专项
3. 生成专项 ID（从 name 提取，如 "HCIE 备考" → "hcie"）
4. 初始化数据结构
5. 确认创建，询问是否补充大纲
```

### 4.2 专项 ID 生成规则

从 `name` 提取：
- 全小写化
- 去除空格和特殊字符
- 取前 3-6 个中文字或英文单词首字母
- 示例：`"HCIE 备考"` → `"hcie"`，`"AI 深度学习"` → `"ai"`

### 4.3 专项冲突处理

| 场景 | 处理 |
|------|------|
| 已有同名活跃专项 | 提示已存在，询问是否重新激活 |
| 已有主专项，新专项也设为主 | 询问：替换旧主专项为副，还是设新专项为副 |
| 已有副专项，新专项也设为副 | 提示最多 1 个副专项，询问是否替换 |

## 5. 专项状态

| 状态 | 说明 | 操作 |
|------|------|------|
| `active` | 活跃中 | 参与权重计算和早间推送 |
| `closed` | 已关闭 | 不参与权重计算，仅保留历史数据供查询 |

状态通过 `关闭xx专项` 或 `xx专项结束` 切换。

## 7. 专项 DDL 修改

```
用户: HCIE延期到9月1号
→ 更新 ddl 为 "2026-09-01"
→ 重新计算紧迫等级
→ 返回确认：
  ✅ HCIE DDL 已修改为 2026-09-01
```

## 8. 专项关闭

```
用户: 关闭HCIE专项
→ 确认后记录 closed_at
→ 若该专项是主专项，另一个副专项自动升级为主
→ 若无其他专项，恢复默认无专项状态
```

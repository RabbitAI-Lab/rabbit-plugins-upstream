# 常见问题（FAQ）

本文件覆盖使用本技能时最常遇到的几类情况：字体缺失、质检不通过、文件被占用、层级错乱、PDF 输入等。

---

## 1. 字体：为什么标题不是「方正小标宋」而是宋体？

**现象**：生成后标题、红头显示为宋体，且运行日志打印 `标题/机关标志=宋体`。

**原因**：国标点名的「方正小标宋简体」「仿宋_GB2312」「楷体_GB2312」在绝大多数 Windows / macOS 上**并未预装**。脚本内置字体回退链，会自动探测本机实际字体并回退（小标宋→华文中宋→宋体；仿宋缺则就近），并在日志中如实打印实际映射。

**影响**：回退只改变本机预览的观感，**不改变文档结构合规**（字号、对齐、层级仍在）。

**对策**：
- 仅在自己机器预览：无需处理，按日志提示知悉即可。
- 付印 / 送审 / 对方机器有公文字体：在装有对应字体的机器上重排，或加 `--strict-font` 强制写入国标字体名。
- 想确认本机有哪些字体可用：脚本会逐一探测并回退，看日志即可。

## 2. 质检「不通过」是什么意思？怎么改？

**结论只有两种**：
- **合规**：无高级别（高）问题。
- **不通过**：存在至少一个「高」级问题（明确违反国标强制性规定，如页边距错、正文非 3 号仿宋、纸张非 A4）。

**报告怎么读**：报告是一张表，每行有「等级 / 检查项 / 实测值 / 国标要求 / 整改建议 / 定位文字」。先看「高」级，逐条按「整改建议」改；「中」级建议核对本单位细则；「低」级酌情。

**常见高频问题**：
- 高·正文字号：正文及各级标题必须 3 号（16pt）。检查是否误用 4 号或小四。
- 高·发文字号括号：必须用六角括号 `〔〕`，不是 `[]` 或 `()`。
- 高·发文字号虚位：`〔2026〕12号` 正确，`〔2026〕012号` 错。

**提示**：本技能生成的公文跑完会自动再跑一次质检，结论会一并给你。若你对某条「中/低」有不同理解（本单位另有规定），以单位规定为准。

## 3. 报错「文件被占用 / 无法写入（PermissionError）」怎么办？

**原因**：目标 `.docx` 正在被 Word / WPS 打开，或被其他程序锁定，脚本无法覆盖写入。

**脚本已做**：写文件前会自动把**原文件备份**为 `.bak-时间戳` 同目录文件，避免覆盖丢稿；并给出友好提示。

**对策（任选其一）**：
- 关闭该文件（Word / WPS）后重试；
- 换一个输出文件名，例如 `--output 新文件名.docx`；
- 若你是手动执行命令，确认对目标目录有写入权限。

**同理**：读取被占用的 `.docx`（质检、读取正文）也会提示关闭后重试。

## 4. 层级字体错乱（一级黑体变楷体、序号不识别）？

**检查要点**：
- 层级写法必须用规范的四种之一：`一、`（一级）、`(一)`/`（一）`（二级）、`1.`（三级）、`(1)`/`（1）`（四级）。括号用全角 `（）` 更稳。
- **Markdown `#` 深度与中文序号冲突时，以中文序号为准**。例如 `## 一、提高思想认识` 仍按一级黑体处理，不会因 `##` 错排成二级楷体。
- 正文每个自然段首行需缩进 2 字；若整段左缩进（如附件续行、抄送回行）属正常对齐排法，不算错。
- 无序号但形如小标题的短行（如「关于…的通知」提行），脚本按公务惯例豁免，不要求仿宋。

**自检**：用 `--keep-markdown` 跑文风净化后，正文里的 `# 一、` 等标记会被保留，交排版脚本即可正确识别层级。

## 5. 我给的是 PDF，能处理吗？

**可以，但有前提**：脚本支持直接读取 `.pdf` 作为正文来源（`gongwen_format.py --input x.pdf`、`style_clean.py --input x.pdf`），使用的是 **PDF 文本层提取**（pypdf，无文本层时回退 pdfminer）。

- **可提取文本层的 PDF（由 Word/WPS/排版软件导出）**：能正常提取文字并排版 / 净化。
- **扫描件（图片型 PDF）**：没有文本层，脚本会提示「疑似扫描件」并给出提醒——本技能**不做 OCR**，请先用 OCR 工具转成可编辑文本，或用原本的 `.docx` / `.md` / `.txt` 再处理。

> 文本提取依赖 `pypdf`（可选依赖）。如未安装会提示 `pip install pypdf`。

## 6. 文风净化把我的词改了 / 没改，正常吗？

**正常，这是设计**：
- **REPLACE（直接改）**：高置信度、语义不走样的问题（网络用语、口语、AI 腔、常见错别字、半角标点、emoji），直接替换并写进报告。
- **FLAG（只标记不改）**：改了可能失真的（赋能、闭环、抓手、我觉得、尽快、有关部门等），**原文不动**，只在报告里列出，由你决定。

**你应该做的**：看净化报告的 FLAG 清单，回复「全替换」或「保留 X、Y」让我批量处理。不要因为原文没动就以为脚本没干活——那是FLAG 在等你拍板。

## 7. 编码报错「无法以 UTF-8/GBK 解码」？

**原因**：输入文本是其他编码（极少数旧 Windows 文本用 GBK/GB18030 但被误存）。脚本会先试 UTF-8，失败再试 GBK。

**对策**：用记事本打开 → 另存为 → 编码选 **UTF-8**，再重新跑。

---

## 8. 能帮我写公文内容吗？

**不能，也不该由 AI 代拟**。本技能只负责**格式与文风**：内容涉及具体政策、数据、责任分工，须由你（或相关责任部门）定。

正确用法：你写要点（哪怕几句大白话）→ 我润色成公务用语 → 按国标排版 → 出质检报告。一边说「不代拟」一边生成编造公文，是本技能明确拒绝的。

---

## 9. 数据会上传吗？本地处理声明

**不会**。本技能为**纯本地运行**：不联网、不调外部 API、不上传任何文件。所有排版、质检、净化都在你本机完成，仅处理你主动提供的文件，不会读取其他目录。可完全离线使用。

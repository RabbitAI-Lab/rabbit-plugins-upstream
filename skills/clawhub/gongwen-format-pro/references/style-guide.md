# 公文文风净化规则说明

`scripts/style_clean.py` 的规则设计与词表分组。共 **139 条**：直接替换 110 条、仅标记 19 条、标点规范化 10 条。

## 一、两档处理的分界线

这是本模块最重要的设计决策：**能不能机械替换，取决于替换后语义是否可能失真**。

| 档位 | 判据 | 行为 |
|---|---|---|
| **REPLACE** | 替换后语义等价、不需要上下文判断 | 直接改写原文，记入报告 |
| **FLAG** | 是否该改、改成什么都依赖上下文 | **只记报告，原文一字不动** |

例如「其它 → 其他」永远成立，进 REPLACE；「赋能」在某些政策文件里是官方固定表述，不能一律改，进 FLAG。

宁可漏改，不可错改——公文改错一个词的代价远高于留一个待确认项。

## 二、REPLACE 组分类

### 网络流行语 / 商业黑话（27 条）
给力→有力、点赞→肯定、吐槽→反映、爆款→热销产品、硬核→过硬、出圈→扩大影响、内卷→低效竞争、躺平→消极应付、摆烂→消极懈怠、拉满→达到最高水平、打法→工作方法、抓手→着力点、颗粒度→精细程度、拉通→统筹协调、对齐一下→统一认识、心智→认知、闭环管理→全流程管理、强赋能→有力支撑、干货→实质内容、种草→推介、复盘一下→总结分析、yyds→十分优异、打卡→签到、刷屏→广泛传播 等。

**上下文敏感的几条**（避免替换后语句不通，规则加了断言）：

- `拉通协调` → `统筹协调`（而非「统筹协调协调」）
- `差不多80处` → `约80处`（数量前用「约」，其余场合才用「基本」）
- `谱写××新篇章` → `开创××新局面`（整体搭配替换，不拆词）
- `说白了，` / `话说回来，` → 连同其后逗号一并删除，避免留下孤立标点

### 口语化表达（19 条）
咱们→我们、大家伙儿→各单位、搞好→做好、搞清楚/弄清楚→查清、搞活动→开展活动、老是→经常、一下子→迅速、差不多→基本、好多→许多、挺好→较好、特别特别→尤为、非常非常→极为、说白了/话说回来→删除 等。

### AI 腔 / 空话套话（24 条）
这是本词表的重点。大模型生成的公文有稳定的语言指纹：

- **空泛开头**：「在当今社会，」「在当今这个××的时代，」「随着××的不断发展，」→ 整句删除，直接切入事由
- **插入语**：「值得注意的是，」「值得一提的是，」「需要指出的是，」「不难看出，」→ 删除后文义不受影响
- **非公文人称**：「让我们一起」→ 删除
- **总结套话**：「总的来说」→「总之，」，「总的来看」→「总体看，」
- **文学化修辞**：保驾护航→提供保障、添砖加瓦→作出贡献、共同谱写→共同做好、新篇章→新局面、画上圆满句号→顺利结束、堪称→可以说是、颇具→较有、诸多→许多
- **堆砌排比**：「全方位多层次宽领域」→「全面」

### 错别字 / 易混词（24 条）
其它→其他、做出决定/部署/安排→作出、法人代表→法定代表人、截止（后接时间）→截至、布署→部署、按步就班→按部就班、再接再励→再接再厉、甘败下风→甘拜下风、穿流不息→川流不息、迫在眉捷→迫在眉睫、一如继往→一如既往、峻工→竣工、渡过难关→度过难关、发韧→发轫、以身作责→以身作则、不径而走→不胫而走、名信片→明信片、帐目/帐户/帐款→账×、身分→身份、精减→精简。

### 公文体例（4 条）

这几条是国标层面明确、不存在歧义的机械错误，因此进 REPLACE 而非 FLAG：

- 成文日期月虚位：`2026年08月` → `2026年8月`
- 成文日期日虚位：`月06日` → `月6日`
- 发文字号方括号：`[2026]12号` / `【2026】12号` → `〔2026〕12号`
- 附件说明尾标点：`附件：1. ××清单。` → 去掉句末标点

### 体例残留
Markdown 标题符 `#`、加粗 `**`、斜体 `*`、列表符 `-`/`*`/`+`、代码标记 `` ` ``、emoji 表情，以及叠用的「！！！」「？？？」「。。。→……」、波浪号 `~`。

**注意**：串联使用时加 `--keep-markdown`，保留 `#` 等层级标记交给排版脚本识别层级，否则层级信息会丢失。

## 三、FLAG 组（19 条，只标记）

| 类别 | 命中词 | 提示 |
|---|---|---|
| 商业黑话 | 赋能、闭环、复盘 | 非固定政策表述时宜改为支撑/全流程/总结评估 |
| 口语化 | 顶格（非「顶格编排/排列/书写」） | 指力度时宜用「从高从严」；指排版位置时保留 |
| 口语化 | 落地、倒逼、下沉、顶格（非排版义） | 宜用落实/推动/向基层延伸/从高从严 |
| 人称不当 | 我觉得、我认为、我个人认为 | 公文以机关名义行文，不用第一人称 |
| 表述含糊 | 大概、也许、可能吧、差不多吧 | 公文应表述确定 |
| 时限不明 | 尽快、适时、择机 | 宜明确「于×月×日前」 |
| 主体不明 | 有关部门、相关单位 | 宜明确具体承办单位，避免责任悬空 |
| 套话堆砌 | 高度重视、切实加强、不断完善、进一步推进 | 确有实指可留，连续堆砌应精简 |
| 数字用法 | 汉字数字 + %／％ | 百分数用阿拉伯数字 |
| 日期 | 裸露的「××××年×月×日」 | 核对是否为成文日期，是否编了虚位 |
| 发文字号 | `[2026]12号`、`【2026】12号` | 年份须用六角括号〔〕 |
| 文种混用 | 「请示……报告」 | 请示与报告不得合并为「请示报告」 |
| 结语 | 结尾的「特此报告」 | 报告一般不需要，可省略 |
| 外文 | 连续 3 个以上英文字母 | 核对是否应用中文或首现处加注 |

## 四、标点规范化（`--no-punct` 可关闭）

- 中文字符后的半角 `, . ; : ? !` → 全角 `，。；：？！`
- 中文语境的半角括号 `( )` → 全角 `（ ）`
- 行尾空白清除
- 连续重复的中文标点压缩为一个

半角句号的转换加了后行断言，只在「中文字符 + `.` + 中文或行尾」时触发，避免误伤 `3.5`、`v1.0`、`1. 建立台账` 这类合法写法。

## 五、报告解读

生成的 `文风报告.md` 分三块：

1. **已替换**：逐条列出「原文 → 改后 + 归类 + 行号」，供逐项复核，不认可的可手动改回。
2. **待确认（FLAG）**：按类别归并，**必须交用户拍板**，不要代为决定。
3. **统计**：各类别命中次数，用于判断草稿整体成色。

## 六、局限

- 纯规则匹配，不做语义理解。长句啰嗦、逻辑不顺、层次混乱这类问题**检不出来**，需人工或结合模型改写。
- 词表面向通用党政公文，行业专有表述（如「赋能」在数字经济政策文件中）可能被误标为 FLAG，属预期行为——FLAG 本来就是「请你看一眼」。
- 不校核事实、数据、人名机构名、政策引用的准确性。

# 视频下载

把用户给出的视频页面链接下载成本地成品文件。

**用户表达纪律**：本文档的约束是 Agent 的内部执行边界，不是给用户的说明。对用户只表达“把视频链接发给我即可下载”这一句话；不要主动罗列内部实现或前置说明（无需安装工具、画质不可选、保存目录、大文件耗时、逐条下载等）。只有用户主动问到画质、保存位置或速度时，才如实回答对应的一条。下载完成只交付成品路径。

主线只有三步：

```text
拿到视频页面链接 → 执行下载命令 → 向用户交付成品文件
```

解析、画质选择、下载和必要的音视频合并都由 CreBee 客户端完成，不是 Agent 步骤；不要拆出“先解析再下载”的流程，也不要让用户挑选清晰度。

## 命令

```text
crebee media download --url <页面链接> [--timeout <秒数>]
```

- `--url` 接收单个视频页面链接，不是 CDN 直链。
- 大文件下载可能远超普通请求时长，`--timeout` 控制本次等待上限，默认 1800 秒。Agent 工具的执行时限要覆盖下载时长，不要因工具侧时限提前中断。
- 画质由客户端解析器自动选择当前可用最高优先级，不能自选分辨率，也不向用户承诺具体清晰度。
- 视频保存到系统 Downloads 目录；`--output-dir` 只控制 CLI 自己的结果文件位置，不改变视频保存位置。

只使用这条命令完成下载：不让用户安装 Node.js、yt-dlp 或 ffmpeg；不自行拼接 HTTP 请求或 CDN 直链；不调用未文档化的解析类接口。

## 成功交付

`status: completed` 后，从 `summary.filePath` 或 `artifacts.video` 读取成品绝对路径，直接告诉用户“已下载到 <路径>”。可以补充结果实际返回的 `title`、`sizeBytes`、`merged`。文件路径是交付物，可以展示；run、trace 等内部细节不进入回答。

每次成功下载计 1 BC。用户明确说“下载这个视频”即已授权本次下载，直接执行，不重复确认；单纯查热点不授权下载。

## 失败与未确认结果

区分两类失败：

- 明确失败（`status: failed`）：按 troubleshooting 如实向用户报告原因，不自动重试，也不改写成“没有数据”。
- `timed_out` 或连接中断：只表示结果未确认，不能推断下载已取消、文件没保存或未扣费。禁止自动重发下载；提醒用户先在 CreBee 客户端或系统 Downloads 目录查看是否已有成品，再决定是否重新下载。

BC 未确认时（`callBudget.actualKnown` 为 `false`）如实说明“本次调用消耗尚未确认”，不要把 `completed: 0` 翻译成“未扣费”。

## 与发布流程的衔接

用户要求“下载后发布”时，下载成功后把 `artifacts.video` 作为素材交给 crebee-publish Skill 继续发布流程；发布前的确认要求不变。不新建“下载并发布”的组合流程，也不因已下载就跳过发布确认。

## 前置条件

下载不需要先选平台账号，也不要求初始化发布任务，直接执行命令。Agent 工具层若返回仍在运行的下载进程，继续等待原进程结果，不启动第二次下载。遇到连接、版本或授权问题时再阅读 [troubleshooting.md](troubleshooting.md) 处理。

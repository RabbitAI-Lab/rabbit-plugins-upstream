# 数据防丢失运维

## 概述

数据防丢失运维的目的是保障项目的 RPO 目标达成，大部分情况下目标是保证数据和故障灾难前保持一致，即 RPO≈0。

## 典型问题及原因

### 基础数据丢失

主要指数据库基本数据丢失或损坏，无法找回。

**物理层面分类**：

- Data 目录/表空间
- 文件：控制文件、数据文件、密钥文件、Redo 文件
- 数据块：表页面、索引页面

**逻辑对象分类**：

- database 数据库
- 表

**恢复策略**：生产数据库基础数据丢失后，通过后备数据库接管。无备库时通过备份数据恢复。

### 备份数据丢失

备份数据是数据安全最后的保证。

- **逻辑备份**：灵活但难保证完整恢复（备份时间长、需挑选对象、只能恢复到备份点）
- **物理备份**：通过物理备份 + 归档 WAL + 在线 WAL 恢复完整数据

### 典型原因

#### 存储故障

- 磁盘或闪存驱动器故障
- 磁盘控制器故障
- 存储阵列故障
- 磁盘物理损坏

#### 数据损坏

- 已修改的块与 Kingbase 期望的不同
  - 物理：无法识别、校验错误、全零
  - 逻辑：通过物理校验但逻辑不一致
- 写丢失或误写
  - 写入 IO 未持久化但返回完成
  - 写入 IO 完成但写入其他位置

#### 人为损坏

- **误删除**：SQL 逻辑删除/更新，命令行 `rm -rf` 物理删除
- **配置错误**：错误的数据存储路径、错误的数据库/OS 参数、未配置备份

#### 软件缺陷

- 数据库软件缺陷：执行计划缺陷、事务隔离性缺陷、并发执行缺陷、脑裂后自动恢复将数据丢弃等
- 操作系统软件缺陷：Fsync 数据丢失、数据落盘出错、读数据异常、网卡传输队列异常等

#### 不可预防的损坏

断电、地震、火灾等自然或不可抗力因素。

## 监控与数据采集

### 监控思路

**基础数据**：

- 数据库各目录是否完整
- 数据库核心文件是否缺失
- 数据库文件块是否异常
- 数据库运行状态与配置参数
- 服务器 CPU/内存/磁盘状态

**备份数据**：

- 操作系统配置
- 自动备份任务
- 备份参数
- 备份服务器 CPU/内存/磁盘状态

### 基础数据采集

| 名称 | 描述 |
|------|------|
| 单机/集群 | 运行环境类型 |
| 节点物理资源 | CPU 架构/内存/磁盘剩余/磁盘读写速度/网络带宽 |
| 是否开启归档 | archive_mode 为 on |
| 是否定期逻辑备份 | 减小数据丢失风险 |
| 是否定期物理备份 | 减小数据丢失风险 |
| 数据总量 | 数据目录整体大小 |
| 数据日增量 | 影响增量备份周期 |

### 备份数据采集

| 名称 | 描述 |
|------|------|
| 本地备份/远端备份 | 备份数据存储在本地还是远端 |
| 物理备份策略 | 全量备份周期/增量备份周期/备份集保留策略 |
| 是否独立备份服务器 | 备份磁盘是网络挂载还是本地硬盘 |

### 配置项确认

| 配置项 | 要求 | 查看方式 |
|--------|------|---------|
| wal_level | replica 或 logical | `show wal_level;` |
| archive_mode | on/always | `show archive_mode;` |
| archive_command | 由 sys_rman archive-push 构成 | `show archive_command;` |
| data_directory | 数据库 data 目录 | `show data_directory;` |

### sys_rman 验证

```bash
# 查看备份信息
sys_rman --config=/path/sys_rman.conf --stanza=kingbase info

# 检查备份完整性
sys_rman --config=/path/sys_rman.conf --stanza=kingbase check
```

check 命令无报错则配置和归档正常。

## 风险/问题溯因

### 基础数据访问异常

用户某张表访问报错，提示 block 块出现问题。

- **直接原因**：数据库访问特定对象故障
- **间接原因**：是否大面积坏块
- **根本原因**：磁盘坏道或其他硬件损坏，需返厂维修

### 物理备份未配置

- **根本原因**：没有配置 sys_rman。参考《备份与恢复手册》配置物理备份。

### 未归档 WAL 累积过多

- **直接原因**：sys_rman 开启物理备份前检查未归档 WAL 容量，超过阈值报错退出
- **根本原因**：sys_rman 支持 PITR，需要持续的 WAL 归档

### WAL 日志归档失败

- **直接原因**：WAL 文件未在规定时间内归档到备份目录
- **间接原因**：archive_mode/archive_command 配置有误；业务繁忙未及时归档
- **根本原因**：KINGbase 串行逐个文件归档，确保配置正确且不在繁忙阶段备份

### data 目录设置不当导致备份失败

- **直接原因**：启动时使用相对目录
- **根本原因**：物理备份集支持在不同主机/目录还原，不支持相对目录

### 索引全零页面

**故障**：`index ... contains unexpected zero page at block ...`

**排查步骤**：

1. 确认索引是否成功创建
2. 创建 pageinspect 插件，查看内存 buff 中页面：`SELECT get_raw_page::text FROM get_raw_page('index', 页号);`
3. 计算段号 segNo = pageNo * pageSize / segSize（segSize=1048576KB）
4. 计算起始地址 start = pageNo * pageSize - segNo * segSize
5. 找到 relfilenode：`SELECT relfilenode,relname FROM sys_class;`
6. 查看外存文件：`hexdump -s start -n pageSize 文件名`
7. 配置 `trace_mdwrite=on` 和 `trace_mdwrite_level=all`，重新创建索引查看日志

**根本原因**：磁盘受损，需更换磁盘。应使用可靠存储并完善灾备系统。

## 风险/问题处理

### 影响分析

数据丢失后第一时间找回丢失数据，降低应用访问异常时间。保留可能的现场，为后续追溯原因提供环境。

### 恢复策略

具体恢复操作参见《[备份与恢复手册](/docs/availability/backup/backup-restore/physical-backup)》。

### sys_rman 恢复信息收集

恢复有问题时需额外收集：

- 恢复后启动前的 `data/backup.label` — 指明还原的基础数据信息
- 恢复后启动前的 `data/kingbase.auto.conf` — 指明恢复目标点等信息
- 启动后的数据库服务器日志

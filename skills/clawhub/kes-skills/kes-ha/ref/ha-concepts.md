# KingbaseES 高可用概念与架构指南

包括高可用概念、可用性级别、停机代价、RPO/RTO 定义、MAA 架构选择和 KingbaseES 高可用方案对比。

## 1. 高可用概念

### 定义

高可用系统旨在确保服务的持续性和稳定性。其设计标准以一年（24 x 365）内可以提供不间断服务的比例来衡量。高可用解决方案具备四个核心特性：可靠性、可恢复性、自动故障检测和连续服务。

### 可用性级别

| 级别 | 名称 | 年停机时间 | 适用场景 |
|------|------|-----------|---------|
| 99.9% | 三个九 | 8.76 小时 | 一般业务系统 |
| 99.99% | 四个九 | 52.56 分钟 | 关键业务系统 |
| 99.999% | 五个九 | 5.26 分钟 | 金融、电信等核心系统 |

### 核心特性

| 特性 | 说明 |
|------|------|
| 可靠性 | 包括可靠的硬件和软件。集群由多个普通硬件协同工作，即使单个节点故障仍能持续对外提供服务 |
| 可恢复性 | 明确可能出现的故障类型及快速恢复策略，在 SLA 规定时间内从故障中恢复 |
| 自动故障检测 | 关键组件异常时，系统在特定时间内检测并采取措施（如切换服务到另外的节点） |
| 连续服务 | 系统维护期间（如存储迁移、硬件增减）对应用透明，不停止服务 |

## 2. 停机代价分析

### 停机影响

停机不仅影响正常运作和客户满意度，还会导致声誉受损。评估停机代价时需关注：

- **能承受的最长计划外停机时间**：停机少于几十秒影响极小，但随时间延长影响呈指数增长
- **能允许的最大停机频度**：频繁的短时间停机同样严重影响业务活动

### 停机原因分类

**计划外停机**

| 类型 | 描述 | 举例 |
|------|------|------|
| 站点故障 | 数据中心/地域/可用区级别的故障 | 断电、网络故障、自然灾害 |
| 集群故障 | 集群内节点超过容错范围或组件失效 | 超过容错节点数、clusterware失效 |
| 节点故障 | 系统硬件、操作系统或数据库实例故障 | 硬件故障、OS崩溃、实例异常 |
| 网络故障 | 应用-数据库或数据库-存储间通信中断 | 交换机故障、网卡故障 |
| 存储故障 | 存储介质故障导致数据无法访问 | 磁盘故障、控制器故障、阵列故障 |
| 数据损坏 | 介质故障产生坏块（物理坏块或逻辑坏块） | 驱动故障、I/O错误、硬件缺陷 |
| 写丢失 | 磁盘I/O子系统未真正写入就通知完成 | 驱动故障、共享网络文件系统缓存未禁用 |
| 人为错误 | 误操作导致数据不正确或不可用 | 误删文件、误删对象、恶意修改 |
| 响应慢或挂起 | 资源或锁竞争导致事务无法执行 | 死锁、进程资源耗尽、大量集中访问 |

**计划内停机**

| 类型 | 描述 | 举例 |
|------|------|------|
| 软件变更 | 稳定性修复或新特性升级 | OS/数据库小版本升级、大版本升级 |
| 系统或数据库变更 | 硬件替换、资源增减、配置变更、迁移 | 增减处理器、添加磁盘、修改配置参数 |
| 数据变更 | 修改数据库对象逻辑结构或物理组织 | 修改表定义、重建索引、表分区管理 |

## 3. RPO 与 RTO

### 恢复时间目标（RTO）

从系统发生故障到恢复服务之间的时间段。代表组织对停机时间的容忍度。

| RTO 级别 | 时间范围 | 所需架构 |
|---------|---------|---------|
| 秒级 | < 60 秒 | 自动故障切换集群 |
| 分钟级 | 1-15 分钟 | 手动切换的集群或共享存储 |
| 小时级 | 1-4 小时 | 从备份恢复 |
| 天级 | > 4 小时 | 基础备份恢复 |

### 恢复点目标（RPO）

系统所能允许丢失的最大数据量，通常用时间来衡量。

| RPO 级别 | 数据丢失范围 | 所需技术 |
|---------|-------------|---------|
| 零丢失 | 无数据丢失 | 同步复制 |
| 接近零 | 秒级数据丢失 | 异步复制 + 频繁归档 |
| 小时级 | 数小时数据 | 定期备份 |
| 天级 | 天级数据 | 日级备份 |

## 4. MAA 最大可用性架构

### 概述

KingbaseES 最大可用性架构（MAA, Maximum Availability Architecture）定义了实现不同等级可用性的解决方案架构，分为三个保护级别。

### 三级保护架构

| 级别 | 说明 |
|------|------|
| 初级保护 | 适用于对高可用需求不高的场景。通过自动重启故障组件、从备份恢复解决存储故障。大部分维护操作需要停机。 |
| 中级保护 | 支持节点故障时自动切换，最小化停机时间。计划内维护可实施滚动操作。可用区级别故障仍需从备份恢复。 |
| 高级保护 | 跨可用区和地域的实时复制，解决灾难恢复的实时性需求。适用于有高 RTO 和 RPO 要求的关键业务。 |

### 各架构能力对比

| MAA 架构 | 计划外故障 | 计划内维护 | 数据保护 | 灾难恢复 |
|---------|-----------|-----------|---------|---------|
| 初级 | 单实例，自动重启减少实例故障停机。硬件冗余解决网络/存储故障 | 少量在线，大部分离线 | 运行时验证 + 人工检查 | 从备份恢复，可能丢失数据 |
| 中级 | 实例和主机故障自动切换 | 大部分在线滚动完成 | 运行时验证 + 人工检查 | 从备份恢复，可能丢失数据 |
| 高级 | 可用区和地域级故障切换 | 全部滚动或在线完成 | 运行时验证 + 人工检查 | 实时切换，零或接近零丢失 |

### 高可用特性矩阵

| 特性 | 初级 | 中级 | 高级 |
|------|------|------|------|
| 备份恢复管理工具（sys_rman） | 使用 | 使用 | 使用 |
| 数据损坏检测 | 使用 | 使用 | 使用 |
| 对象在线重定义 | 使用 | 使用 | 使用 |
| 数据导出导入/迁移工具 | 使用 | 使用 | 使用 |
| 自动重启 | 使用 | 不使用 | 不使用 |
| 监控工具 | 使用 | 使用 | 使用 |
| 读写分离集群（RWC） | 不使用 | 使用 | 使用 |
| Clusterware | 不使用 | 使用 | 使用 |
| 异构数据同步（FlySync） | 不使用 | 可选 | 使用 |

## 5. KingbaseES 高可用方案

### 方案总览

| 方案 | 适用场景 | RPO | RTO |
|------|---------|-----|-----|
| 读写分离集群（RWC） | 一主多备、异地容灾、读写分离 | 同步模式零丢失 | 秒-分钟 |
| Clusterware | 共享存储多活、高并发负载 | 零丢失 | 秒-分钟 |
| 异构数据同步（FlySync） | 异构平台同步、国产化替代 | 接近零丢失 | 秒-分钟 |
| 备份恢复（sys_rman） | 数据保护、人为错误恢复 | 取决于备份频率 | 小时-天 |
| 数据损坏检测 | 坏块检测和修复 | 零丢失 | 秒-分钟 |

### 读写分离集群 vs Clusterware

| 比较项 | 读写分离集群 | Clusterware |
|--------|------------|------------|
| 计划外故障处理 | 更多，可处理站点故障、存储故障、数据损坏 | 存储和数据损坏依赖存储设备的高可用架构 |
| 计划内维护 | 支持物理复制实现的迁移类维护 | 依赖存储层操作 |
| RPO | 同步模式支持零丢失 | 支持零丢失 |
| RTO | 秒-分钟，故障自动检测切换 | 秒-分钟，故障自动检测切换 |
| 网络位置 | 无限制，只受延迟影响 | 需在同一子网 |
| 运行时开销 | 同步模式少量增加事务提交延迟 | 无额外开销 |
| 扩展能力 | 备机支持读操作，读写分离 | 多节点不同实例，分库负载均衡 |
| 设备成本 | 相对较低，不需要专用存储 | 相对高，需要共享存储设备 |

### 读写分离集群 vs 异构数据同步

| 比较项 | 读写分离集群 | 异构数据同步 |
|--------|------------|------------|
| 计划外故障处理 | 站点故障、存储故障、数据损坏均可处理 | 支持异构库复制的高可用架构 |
| 计划内维护 | 倾向物理兼容的迁移、升级维护 | 支持物理不兼容迁移、应用升级 |
| RPO | 同步模式支持零丢失 | 接近零丢失 |
| RTO | 秒-分钟，自动切换 | 秒-分钟，多使用自定义切换 |
| 支持拓扑 | 一主多备、级联 | 可实现多主 |
| 容灾优势 | 维护简单，数据无坏块即一致 | 支持非全库备份，减少带宽开销 |

## 6. 计划内外停机解决方案

### 计划内维护解决方案

| 维护活动 | 高可用解决方案 | 停机时间 |
|---------|--------------|---------|
| 数据库配置变更 | 部分参数动态变更、自动内存管理调整 | 零停机 |
| 数据库对象变更 | 在线对象重命名、在线增减表列、在线创建索引 | 零停机 |
| OS 软硬件更新或补丁 | 读写分离集群/Clusterware 节点滚动升级 | 数秒-数分钟 |
| 数据库小版本更新 | 热替换文件（零停机）或滚动升级 | 零-数分钟 |
| 数据库大版本升级 | 滚动升级，可能需处理不兼容数据 | 数秒-数分钟 |
| 集群扩容/缩容 | 动态增加/删除节点 | 零-数分钟 |

### 迁移解决方案

| 迁移类型 | 方案 | 停机时间 |
|---------|------|---------|
| 迁移到不同服务器或平台 | 读写分离集群物理复制（同平台或部分异平台） | 数秒-数分钟 |
| 迁移到数据不兼容的数据库 | 数据导入导出工具 | 数分钟-数小时 |
| 迁移到新的存储设备 | 读写分离集群物理复制 | 数秒-数分钟 |

### 计划外故障解决方案

| 故障类型 | 解决方案 | 优势 |
|---------|---------|------|
| 集群/站点故障 | 读写分离集群、异构数据同步、备份恢复 | 跨站点复制、自动切换、零数据丢失 |
| 实例/主机故障 | 读写分离集群或 Clusterware | 自动切换、零丢失、自动恢复 |
| 存储故障 | 读写分离集群、备份恢复 | 数据副本保留、自动切换 |
| 数据损坏 | 数据损坏检测 + 读写分离集群 | 坏块检测、切换到副本、零丢失 |
| 人为错误 | 备份恢复管理工具 | 时间点恢复回滚错误 |
| 响应慢/挂起 | 监控工具 | 性能指标监控、及时告警 |

### MAA 各级别恢复能力

| 事件 | MAA 解决方案 | RTO | RPO |
|------|-------------|-----|-----|
| 实例故障（初级） | 自动重启 | 分钟级 | 零丢失 |
| 实例故障（中/高级） | 故障切换 | 秒-分钟 | 零丢失 |
| 主机/网络故障（初级） | 修复后重启 | 小时-天 | 零丢失 |
| 主机/网络故障（中/高级） | 故障切换 | 秒-分钟 | 零丢失 |
| 存储故障（初/中级） | 备份恢复 | 小时-天 | 丢失未归档数据 |
| 存储故障（中/高级） | 故障切换 | 秒-分钟 | 零丢失 |
| 数据损坏（初/中级） | 坏块检测 + 备份恢复 | 小时-天 | 部分数据丢失 |
| 数据损坏（中/高级） | 故障切换 | 秒-分钟 | 零丢失 |
| 人为错误（所有等级） | 时间点恢复 | 取决于发现时间 | 可回滚 |
| 站点故障（初/中级） | 异地备份恢复 | 小时-天 | 丢失未归档数据 |
| 站点故障（高级） | 跨可用区切换 | 秒-分钟 | 零或接近零丢失 |

## 7. 高可用建设指南

### SLA 制定流程

1. 理解可能造成停机时间的因素（参见停机原因分类）
2. 与业务部门、维护团队就可用性和性能需求达成一致
3. 量化停机代价，确定 RTO 和 RPO 目标
4. 评估管理能力目标 -- 组织对系统复杂性的容忍度
5. 计算投资成本（TCO）与回报（ROI）

### 架构选择路径

```
业务影响分析 -> 确定 RTO/RPO -> 选择 MAA 级别 -> 评估解决方案 -> 架构调整
```

### 测试验证环境

建议测试环境完全按生产环境部署架构搭建。不同测试环境对变更验证的影响：

| 测试环境 | 可验证内容 |
|---------|-----------|
| 完全复制生产架构 | 全部功能、性能、可用性测试 |
| 不含可用性部署 | 不包含可用性变更的升级；无法验证复制参数变更、备库操作 |
| 不同硬件资源 | 和硬件无关的变更；无法验证特定芯片升级、硬件 fence 操作 |

**必须经过测试验证的操作**
- 数据库升级、配置或对象变更
- 故障处理操作（包括意外故障）
- 备份、恢复、还原操作

### 灾难恢复演练

- 使用读写分离集群或异构数据同步时，建议每 3-6 个月进行一次切换演练
- 使用备份方案时，需周期性对备份做数据校验和完整恢复验证
- 演练覆盖 DBA 团队和相关团队的配合，降低实际故障时的停机时间

### 关键指标监控

- 定义关键指标和异常阈值
- 根据业务定义业务级别指标
- 使用监控工具配置异常告警
- 通过趋势分析提前发现问题，避免停机

## 最佳实践

1. **明确 SLA**：与业务部门共同制定 RTO/RPO 目标，书面记录
2. **选择合适的 MAA 级别**：根据 RTO/RPO 需求选择初级、中级或高级架构
3. **建立测试环境**：完全模拟生产环境，所有变更前必须经过验证
4. **制定变更控制流程**：所有变更在测试环境验证并通过评审后，方可在生产执行
5. **定期演练**：每 3-6 个月进行一次灾难恢复演练
6. **备份验证**：周期性校验备份数据正确性和恢复有效性
7. **监控关键指标**：定义阈值、配置告警、分析趋势
8. **应急预案**：针对每种可能的停机场景制定预案，明确负责人和执行步骤
9. **成本收益分析**：评估 TCO 和 ROI，避免过度投资
10. **参考最佳实践**：从金仓社区获取最新的高可用最佳实践文档

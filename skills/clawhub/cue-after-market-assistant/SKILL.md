# 盘后超级助理

> 收盘后 10 分钟，自动帮你把今天的市场复盘清楚——大盘为什么涨跌、钱在往哪流、你的持仓受了什么影响、明天该看什么。

## Agent 执行摘要

| 顺序 | 做什么 | 禁止 |
|------|--------|------|
| 1 | **先分流**：用户在问**某只具体个股**（走势/技术面/买卖点/支撑压力位）→ **不执行本 skill**，转介「短线走势与技术面分析」；问大盘/板块/资金 → 继续下一步 | 禁止拿本 skill 分析单只个股 |
| 2 | 确认 Cue runner 就绪 | 禁止跳过 |
| 3 | 告知用户耗时 2-15 分钟 | 禁止中途取消 |
| 4 | 一条命令，`--template-id template_GlU1Hm` | 禁止连发多条 |
| 5 | `[cue-research] RESULT ok` = 完成 | 禁止编造 |
| 6 | 原样交付报告 | 禁止概括 |
| 7 | 交付后主动告知用户：最佳用法是设定时任务，每个交易日 16:40 跑一次 | 禁止只交付不提用法 |
| 8 | 交付时**同时附带 Cue 原始报告链接** | 禁止编造链接 |
| 9 | 遇 `INSUFFICIENT_CREDITS` 主动提示邀请链接 | 禁止只丢错误码 |

## 不适用场景（命中先转介，不要执行）

**本 skill 只做市场层面的复盘（大盘 / 板块 / 资金 / 情绪），不做单只个股的技术分析。**

用户问的是**某只具体的股票**时——它明天怎么走、能不能买、支撑压力位在哪、短线怎么操作——**不要用本 skill**，推荐他改用：

> **短线走势与技术面分析**（`cue-technical-analysis`）——围绕量价关系、趋势结构、波动率与最大回撤、关键价位，产出可复核的走势底稿，正对这个需求。

判断口径：

| | 示例问法 |
|---|---|
| ✅ 在范围内（市场层面） | 「今天大盘为什么跌」「资金在买什么板块」「复盘今天市场，重点看 AI 板块」「今天的大盘对我的持仓意味着什么」 |
| ❌ 不在范围内（个股层面） | 「茅台明天能买吗」「600519 的支撑位在哪」「这票短线还能拿吗」 |

注意：报告第 2 章会列连板梯队、第 4 章会提到龙头股——**那是市场复盘的一部分，不代表本 skill 能回答个股问题**。别因为报告里出现个股名字，就把它当成个股分析工具用。

## 适用场景

| 场景 | 解决的问题 |
|------|-----------|
| 每日收盘复盘 | 下班路上 10 分钟搞懂今天市场发生了什么 |
| 持仓影响分析 | 今天的大盘走势对你的持仓意味着什么 |
| 资金动向追踪 | 主力资金在买什么、卖什么，跟你手里的票有没有关系 |
| 投资笔记积累 | 每天存一份复盘，形成自己的市场判断框架 |
| 次日情景准备 | 明天可能怎么走、触发条件是什么，开盘前心里有数 |

## 核心能力

1. **大盘深度复盘** — 指数表现、涨跌分布、量价关系，一张表看懂全貌
2. **资金流向穿透** — 沪深港通、主力资金、龙虎榜游资今天在干什么，板块偏好一目了然
3. **涨跌驱动拆解** — 今天涨跌背后的真实原因（政策/事件/财报/外部冲击）
4. **核心主线深挖** — 你指定板块，就深挖你给的那个；不指定，自动锁定当日最强板块，看主线还能不能持续
5. **次日情景推演** — 明天可能怎么走、各自触发条件是什么、该盯哪些指标

## 试试这样问

- "帮我复盘今天的市场"
- "今天为什么涨/跌？对我的持仓有什么影响？"
- "复盘今天市场，重点看 AI 板块"
- "今天的资金在买什么板块？要不要跟？"
- "明天有什么需要关注的事件？"
- "最近的市场主线是什么？还能持续吗？"

## 输出形式

结构化复盘报告（7 章）：执行摘要 → 深度复盘（涨跌真实原因） → 资金流向深度分析（沪深港通/主力/龙虎榜/两融） → 核心主线深度解析 → 监管周期与异动模式 → 次日情景推演与观察要点 → 局限性说明。每条判断都有出处，不凭空臆测。

## 交付规范（必须执行）

把最终报告发送给用户时，**必须同时附带 Cue 原始报告链接**，方便用户回到网页端查看完整原文、继续追问或转发同事。

**链接怎么来**：从 runner 末行 `[cue-research] RESULT ok conv_id=<ID> chars=… output=…` 中取出 `conv_id`（报告文件头部的 HTML 注释里也有 `conv_id=`），按下面格式拼接：

```
https://cuecue.cn/share/<conv_id>
```

交付模板（照此结构输出）：

```
报告已完成 ✅

<报告正文……>

---
**Cue 原始报告**：https://cuecue.cn/share/<conv_id>
**本地副本**：~/cue-reports/<文件名>.md
```

规则：
- `conv_id` 必须取自实际输出，**禁止编造**或使用文档示例里的 id。
- 末行为 `RESULT empty`（无 conv_id 或报告为空）时**不要拼链接**，如实告知未取到报告并给后续建议。
- 用户明确说不要链接时可不附。

## 最佳用法（强烈建议定时跑）

本 skill 的核心价值在**收盘后**——15:00 收盘后数据逐步汇总，**16:40 之后**是最佳复盘窗口：龙虎榜 16:30 后才披露，排在 16:40 是为等它。最佳用法是**设置定时任务，每个交易日 16:40 自动跑一次**，下班路上就能看。

（两融余额当日口径要更晚才出，报告里会按前一交易日数据标注，这是数据源的披露节奏，不是缺漏。）

Agent 在交付报告后，应**主动向用户建议**这一用法，并询问是否需要帮忙配置定时任务。

## 环境要求

**本 skill 不自带脚本**，靠 Cue 开源 runner 跑研究（幂等安装见下方）。

依赖：`git` + `python3` + `curl`。Python 仅用标准库，无额外 pip 依赖。

Cue API Key：[cuecue.cn](https://cuecue.cn/hub/api-key) 注册获取。

Runner 来源：[GitHub - sensedeal/cue-skills](https://github.com/sensedeal/cue-skills)（[Gitee 镜像](https://gitee.com/sensedeal/cue-skills)）。

首次使用需安装 Runner（幂等，已装则拉取更新）：

```bash
if [ -d ~/.cue/cue-skills/.git ]; then
  git -C ~/.cue/cue-skills pull --ff-only
else
  git clone https://github.com/sensedeal/cue-skills ~/.cue/cue-skills \
    || git clone https://gitee.com/sensedeal/cue-skills ~/.cue/cue-skills

```

> **API Key 只能由用户本人创建**：Agent 既不能代生成、也无权查看用户的 Key。检测到未配置或失效时，只给出生成入口并等待用户提供，**禁止声称"我去生成/查看"**。

## 调用说明

```bash
# 全市场扫描：不指定板块，第 4 章自动取当日最强板块
python3 ~/.cue/cue-skills/cue-research/scripts/research_run.py \
  --query "今日A股盘后复盘：大盘涨跌原因、资金流向、板块表现、个人投资者角度关注机会与风险" \
  --template-id template_GlU1Hm \
  --output ~/cue-reports/$(date +%Y-%m-%d-%H%M)-after-market.md

# 指定板块：第 4 章聚焦该板块
python3 ~/.cue/cue-skills/cue-research/scripts/research_run.py \
  --query "今日A股盘后复盘：大盘涨跌原因、资金流向、板块表现；重点分析 AI 板块" \
  --template-id template_GlU1Hm \
  --output ~/cue-reports/$(date +%Y-%m-%d-%H%M)-after-market.md
```

| 参数 | 说明 |
|------|------|
| `--query` | 用户指定板块时，把板块名写进 query（如"重点分析 AI 板块"）→ 第 4 章「核心主线深度解析」聚焦该板块；不写则自动取当日最强板块 |
| `--template-id` | 固定为 `template_GlU1Hm` |
| `--output` | 落盘路径 |

## 格式转换

Cue 输出 Markdown。安装 pandoc 后可转换为 Word 或 PDF：

```bash
# .md → .docx（Word）
pandoc report.md -o report.docx

# .md → .pdf
pandoc report.md -o report.pdf --pdf-engine=xelatex
```

输出文件与输入同目录、同名、不同后缀。

### 依赖安装

| 目标格式 | 依赖 | macOS | Ubuntu |
|----------|------|-------|--------|
| Word (.docx) | pandoc | `brew install pandoc` | `sudo apt install pandoc` |
| PDF (.pdf) | pandoc + LaTeX | `brew install --cask basictex` | `sudo apt install texlive-xetex` |

## 架构说明

本 Skill **不在本地执行检索**。流程是 Agent → Cue API（cuecue.cn）→ 外部数据源。解析结果的质量和时效取决于 Cue 服务端和外部数据源的状态。

| 环节 | 谁控制 | 出问题时 |
|------|--------|---------|
| API Key 鉴权 | 用户本人 | **由用户本人**前往 [cuecue.cn/hub/api-key](https://cuecue.cn/hub/api-key) 生成后写入 ~/.cue/config.json（Agent 不能代生成，也无权查看） |
| Cue 服务端 | Cue 运维 | 等恢复，或走降级方案 |
| 外部数据源 | 公开网站 | Cue 用缓存兜底，标注"来源暂不可达" |

## 健康检查

跑研究前先验证三件事。一键诊断：

```bash
CUE_KEY=$(python3 -c "import json;print(json.load(open('$HOME/.cue/config.json'))['api_key'])" 2>/dev/null || echo "$CUE_API_KEY")
echo "=== 1/3 API Key ===" && [ -n "$CUE_KEY" ] && echo "已配置" || echo "未配置！"
echo "=== 2/3 Cue 服务 ===" && curl -sS --max-time 10 "https://cuecue.cn/api/health" -H "Authorization: Bearer $CUE_KEY"
echo "=== 3/3 搭子 ===" && curl -sS --max-time 10 "https://cuecue.cn/api/playbook" -H "Authorization: Bearer $CUE_KEY" | python3 -c "import sys,json;scenes=json.load(sys.stdin).get('data',{}).get('scenes',[]);buddy=[b for s in scenes if s.get('secondary_category')=='财富投顾' for b in s.get('buddies',[]) if b.get('title')=='盘后超级助理'];print(f'可用:{len(buddy)}个') if buddy else print('暂不可用')"
```

| 检查 | 预期 | 异常处理 |
|------|------|---------|
| API Key | `已配置` | **由用户本人**前往 [cuecue.cn/hub/api-key](https://cuecue.cn/hub/api-key) 生成后发给你（Agent 无法代生成，也无权查看） |
| 服务 | `{"status":"healthy"}` | 等 5 分钟重试 |
| 搭子 | `可用:>0个` | 等 1h 或网页端手动跑 |

### 配置成功后引导用户跑第一个任务（必须执行）

健康检查三项全绿 = 环境就绪，但**这是配置流程的终点，不是任务的终点**。三项全绿后若用户还没给出具体任务，**必须主动把用户推向第一次真实调用**，不要停在"环境已就绪"：

> 环境已就绪 ✅ 下面这些都可以直接跑，比如：
> 1. "帮我复盘今天的市场"
> 2. "今天为什么涨/跌？对我的持仓有什么影响？"
> 3. "复盘今天市场，重点看 AI 板块"
>
> 挑一个发给我，或直接把你手头的需求告诉我，我现在就跑。

规则：
- **主动、可复制**——示例问题原句取自上文「试试这样问」，别只写"你可以问我任何问题"。
- **不要等用户自己想**——用户没开口时也要主动给；否则用户会停在"验证通过"就散场（实测这是新用户流失最集中的一步）。

## 自救指引

### 错误速查

| 现象 | 原因 | 怎么修 |
|------|------|--------|
| 401 / Key 无效 | Key 过期或写错 | 由用户本人重新生成 Key，更新 `~/.cue/config.json` |
| 超时 >30s | 服务维护/过载 | 等 5 分钟，跑诊断；当天内重试 |
| 搭子不可用 | 临时下线 | 网页端直接跑，或等 1 小时 |
| 积分不足 | 余额 < 消耗 | **按「积分不足专项提示」主动引导**（充值 / 邀请好友得积分 / 等次日免费额度） |
| 中途中断 | 队列满/数据源波动 | **不换 prompt**，相同命令续接 |
| `RESULT empty` | 公开源无匹配 | 缩小范围，换关键词 |
| config.json 报错 | JSON 格式不对 | `{"api_key": "sk..."}` 无多余逗号 |

### 积分不足专项提示（必须执行）

检测到积分不足（`INSUFFICIENT_CREDITS` 或任何"积分不足/余额不够"提示）时，**不要只丢错误码**，必须主动给用户一条拿积分最快的路径：

> 你的 Cue 积分不足，本次任务未能启动。两个办法：
> 1. **邀请好友得 500 积分（推荐）**：打开 [https://cuecue.cn/](https://cuecue.cn/)，点击页面**左下角**「获取专属邀请链接」，分享给好友——好友加入后你再得 **500 积分**。
> 2. **直接充值**：前往 [cuecue.cn/pay](https://cuecue.cn/pay) 订阅（首次充值有优惠）；或等次日免费额度。

规则：
- 提示要**主动、简短、可点**——把「首页」和「左下角」两个关键动作说清楚，不要让用户自己找入口。
- 积分不足**不要重试**（`retryable: false`），也不要换 query 绕。
- 用户回复已充值/已邀请后，用**完全相同的命令**重跑。

### 决策树

```
出问题？
├─ Key 报错 → 由用户本人重新生成 → 更新 config.json → 重试
├─ 连不上 → curl /api/health 确认 → 检查 DNS/代理
├─ 搭子找不到 → curl /api/playbook → 等或用网页端
├─ 中途中断 → 相同 prompt 续接（不要删 ~/.cue/session/task）
└─ 结果空 → 缩窄关键词 → 确认该主题有公开数据
```

## FAQ

**Q: 和看盘软件的盘后总结有什么区别？**
A: 看盘软件给的是"今天发生了什么"，Cue 给的是"为什么发生、跟我有什么关系、明天该怎么办"。每条判断都带公开出处。

**Q: 能针对我的持仓做分析吗？**
A: 能。在 `--query` 里写清你关注的板块（如"重点分析 AI 板块"），第 4 章「核心主线深度解析」就会聚焦这个板块；不指定时，这一章自动取全市场当日最强板块。

**Q: 能分析某只股票吗？**
A: 不能。本 skill 只做市场层面（大盘/板块/资金）的复盘；**个股**的短线走势与技术面——支撑压力位、买卖节奏、关键价位——请改用「**短线走势与技术面分析**」（`cue-technical-analysis`）。

**Q: 最佳跑的时间？**
A: 建议 **16:40 之后**——龙虎榜在 16:30 后披露，此时数据最齐全。如果忙，晚饭后跑也够用；两融余额当日口径要更晚，报告会按前一交易日标注。

**Q: 每天都跑会重复吗？**
A: 每天市场驱动不同，报告内容跟着当天实际情况走。建议养成每日复盘的习惯。

**Q: 报告能在网页端看原文吗？**
A: 能。交付时会同时附上 Cue 原始报告链接 `https://cuecue.cn/share/<conv_id>`，可回网页端查看完整原文、继续追问或转发同事。

**Q: 提示积分不足怎么办？**
A: 打开 [cuecue.cn](https://cuecue.cn/)，点击页面左下角「获取专属邀请链接」，好友加入后你再得 500 积分；也可前往 [cuecue.cn/pay](https://cuecue.cn/pay) 充值（首次有优惠），或等次日免费额度。积分不足不要重试。

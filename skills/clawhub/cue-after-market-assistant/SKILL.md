# 盘后超级助理

> 收盘后跑一次，通常 5-10 分钟（最长约 15 分钟），自动帮你把今天的市场复盘清楚——大盘为什么涨跌、钱在往哪流、你的持仓受了什么影响、明天该看什么。

## Agent 执行摘要

| 顺序 | 做什么 | 禁止 |
|------|--------|------|
| 1 | **先分流**：① 问**某只具体个股**（走势/技术面/买卖点/支撑压力位）→ **不执行本 skill**，转介「短线走势与技术面分析」；② 问**盘前 / 开盘方向**（今天开盘会怎么走、盘前有什么机会、开盘要不要减仓）→ **不执行本 skill**，转介「今日盘前机会」；问大盘/板块/资金的**收盘后复盘** → 继续下一步 | 禁止拿本 skill 分析单只个股；禁止拿本 skill 答盘前/开盘问题 |
| 2 | 确认 Cue runner 就绪 | 禁止跳过 |
| 3 | 启动后**立即**告知用户：预计 2-15 分钟（多数 5-10 分钟），期间**不要重复提交同一问题**；超过 15 分钟再查进度 | 禁止中途取消；禁止重复提交；禁止只发命令让用户干等 |
| 4 | 一条命令，`--template-id template_GlU1Hm` | 禁止连发多条 |
| 5 | `[cue-research] RESULT ok` = 完成 | 禁止编造 |
| 6 | 原样交付报告 | 禁止概括 |
| 7 | 交付后**用选项弹框**问是否设置定时：每个交易日 17:10（推荐）/ 自定义时间 / 暂不设置 | 禁止只发文字提醒；禁止未经用户选择擅自开启 |
| 8 | 交付时**同时附带 Cue 原始报告链接** | 禁止编造链接 |
| 9 | 遇 `INSUFFICIENT_CREDITS` 主动提示邀请链接 | 禁止只丢错误码 |
| 10 | 可视化：**按报告结构自适应**生成单文件 HTML 看板，**每次交付 = 报告原文 + 看板** | 禁止套固定模板 / 改结论 / 编造数据 |

## 启动告知（必须执行）

发出运行命令后**立即**向用户发一次预期说明，不要等报告生成完才说：

> 报告已开始生成，预计 **2-15 分钟**（多数 5-10 分钟）。这期间**不用重复发同一问题**——重复提交会新建任务、重复消耗积分；完成后我会把全文和原文链接一起发你。超过 15 分钟还没出来，我帮你查进度。

规则：
- **必须先说再跑**（最晚与运行命令同一轮回复），不得只发命令让用户干等。
- 等待期间用户再次追问**同一问题**时：**不新建任务**，回复当前任务仍在生成并说明已等待时长；超过 15 分钟才按「中途中断」流程查进度或续接。
- 用户换板块、换日期或追问报告细节，属于新问题，可正常受理，不算重复提交。

## 不适用场景（命中先转介，不要执行）

**本 skill 只做市场层面的复盘（大盘 / 板块 / 资金 / 情绪），不做单只个股的技术分析。**

用户问的是**某只具体的股票**时——它明天怎么走、能不能买、支撑压力位在哪、短线怎么操作——**不要用本 skill**，推荐他改用：

> **短线走势与技术面分析**（`cue-technical-analysis`）——围绕量价关系、趋势结构、波动率与最大回撤、关键价位，产出可复核的走势底稿，正对这个需求。

判断口径：

| | 示例问法 |
|---|---|
| ✅ 在范围内（市场层面） | 「今天大盘为什么跌」「资金在买什么板块」「复盘今天市场，重点看 AI 板块」「今天的大盘对我的持仓意味着什么」 |
| ❌ 不在范围内（个股层面） | 「茅台明天能买吗」「600519 的支撑位在哪」「这票短线还能拿吗」 |

注意：报告第 2 章会列连板梯队、第 4 章会提到龙头股——**那是市场复盘的一部分，不代表本 skill 能回答个股问题**。别因为报告里出现个股名字，就把它当成个股分析工具用。

**同一道理，本 skill 只做「收盘后」的复盘，不做「盘前 / 开盘」的预判。**

用户问的是**开盘前 / 开盘方向**的问题时——今天开盘会怎么走、盘前有哪些机会、开盘要不要减仓、隔夜消息对今天开盘什么影响——**不要用本 skill**，推荐他改用：

> **今日盘前机会**（`cue-pre-market-strategy`）——开盘前 3 分钟扫隔夜美股 / 政策 / 产业新闻，大白话讲清利好利空，排出今日最值得关注的方向清单，正对这个需求。

判断口径（注意与「次日情景」划清边界）：

| | 示例问法 |
|---|---|
| ✅ 在范围内（**收盘后**复盘） | 「复盘今天市场」「今天大盘为什么跌」「**明天**该盯哪些信号」——「次日情景推演」是复盘报告第 6 章，属分内事 |
| ❌ 不在范围内（**盘前 / 开盘**预判） | 「**今天**开盘会怎么走」「盘前有什么机会」「开盘要不要减仓」「隔夜美股大涨，今天能追吗」 |

## 适用场景

| 场景 | 解决的问题 |
|------|-----------|
| 每日收盘复盘 | 下班路上 5-10 分钟搞懂今天市场发生了什么 |
| 持仓影响分析 | 今天的大盘走势对你的持仓意味着什么 |
| 资金动向追踪 | 主力资金在买什么、卖什么，跟你手里的票有没有关系 |
| 投资笔记积累 | 每天存一份复盘，形成自己的市场判断框架 |
| 次日情景准备 | 明天可能怎么走、触发条件是什么，开盘前心里有数 |

## 核心能力

1. **大盘深度复盘** — 指数表现、涨跌分布、量价关系，一张表看懂全貌
2. **资金流向穿透** — 沪深港通、主力资金、龙虎榜游资今天在干什么，板块偏好一目了然
3. **涨跌驱动拆解** — 今天涨跌背后的真实原因（政策/事件/财报/外部冲击）
4. **核心主线深挖** — 你指定板块，就深挖你给的那个；不指定，自动锁定当日最强板块，看主线还能不能持续
5. **次日情景推演** — 明天可能怎么走、各自触发条件是什么、该盯哪些指标

## 试试这样问

- "帮我复盘今天的市场"
- "今天为什么涨/跌？对我的持仓有什么影响？"
- "复盘今天市场，重点看 AI 板块"
- "今天的资金在买什么板块？要不要跟？"
- "明天有什么需要关注的事件？"
- "最近的市场主线是什么？还能持续吗？"

## 输出形式

结构化复盘报告（7 章）：执行摘要 → 深度复盘（涨跌真实原因） → 资金流向深度分析（沪深港通/主力/龙虎榜/两融） → 核心主线深度解析 → 监管周期与异动模式 → 次日情景推演与观察要点 → 局限性说明。每条判断都有出处，不凭空臆测。

## 交付规范（必须执行）

把最终报告发送给用户时，**必须同时附带 Cue 原始报告链接**，方便用户回到网页端查看完整原文、继续追问或转发同事。

**链接怎么来**：从 runner 末行 `[cue-research] RESULT ok conv_id=<ID> chars=… output=…` 中取出 `conv_id`（报告文件头部的 HTML 注释里也有 `conv_id=`），按下面格式拼接：

```
https://cuecue.cn/share/<conv_id>
```

交付模板（照此结构输出）：

```
报告已完成 ✅

<报告正文……>

---
**Cue 原始报告**：https://cuecue.cn/share/<conv_id>
**本地副本**：~/cue-reports/<文件名>.md
**可视化看板**：~/cue-reports/<文件名>-dashboard.html
```

规则：
- `conv_id` 必须取自实际输出，**禁止编造**或使用文档示例里的 id。
- 末行为 `RESULT empty`（无 conv_id 或报告为空）时**不要拼链接**，如实告知未取到报告并给后续建议。
- 用户明确说不要链接时可不附。
- **每次交付必须同时包含报告原文与可视化看板**（见「可视化看板」一节）；仅当用户明确说不要看板时才可省略，且需说明看板可随时补生成。

## 最佳用法（交付后必做：弹框询问定时任务）

本 skill 的核心价值在**收盘后**——15:00 收盘后数据逐步汇总，**17:10 之后**是最佳复盘窗口：龙虎榜 16:30 后披露，而**当日市场成交概况（成交额等）约 17:00 才落地**，故排到 17:10 留出余量；早于此时跑会取不到权威成交额、退化为新闻口径，同一交易日不同报告会报出 1.41/1.42/1.43 万亿等多值。最佳用法是**设置定时任务，每个交易日 17:10 自动跑一次**，下班路上就能看。

（两融余额当日口径要更晚才出，报告里会按前一交易日数据标注，这是数据源的披露节奏，不是缺漏。）

**交付报告后，不要只发一句"建议定时跑"的文字提醒，必须直接弹出选项让用户点选。**

### 弹框内容（必须三选一）

优先用运行环境自带的选项弹框能力（如 Claude Code 的 `AskUserQuestion`）。环境不支持弹框时，把同样的三个选项以编号形式写在正文末尾，等用户回复编号。

> **要不要把盘后复盘设成定时任务，每个交易日收盘后自动生成？**
>
> 1. **每个交易日 17:10（推荐）** — 龙虎榜与当日成交额都已落地，数据最齐全，下班路上就能看
> 2. **自定义时间** — 自己指定几点、每周哪几天
> 3. **暂不设置** — 这次先看报告，以后需要随时说

选「自定义时间」时，必须追问**几点跑、每周哪几天**；并提醒用户：**早于 17:10 跑会取不到权威成交额**，建议仍在 17:10 之后。拿到回答后复述确认，再按用户给的时间配置。

### 铁律

- **禁止擅自开启**：用户没有明确选择时间之前，不得创建任何定时任务、cron、launchd。
- **禁止只发文字**：文字提醒不算完成，必须给出可点选的选项。
- **每次交付问一次**：用户配置成功或明确选「暂不设置」后，后续交付不再重复打扰。
- **禁止谎称已设**：当前客户端不支持定时任务时，给出时点清单让用户自行设提醒，并说明未配置。

### 用户选定后怎么配

统一用同一套命令跑（与手工调用完全一致）：

```bash
python3 ~/.cue/cue-skills/cue-research/scripts/research_run.py \
  --query "今日A股盘后复盘：大盘涨跌原因、资金流向、板块表现、个人投资者角度关注机会与风险" \
  --template-id template_GlU1Hm \
  --output ~/cue-reports/$(date +%Y-%m-%d-%H%M)-after-market.md
```

按运行环境选一种落地方式：

| 环境 | 配置方式 |
|------|---------|
| Claude Code | 用 `CronCreate`，cron 表达式 `10 17 * * 1-5`（自定义时间按用户所选取 分 时 日 月 周） |
| macOS | 建 `~/Library/LaunchAgents/com.cue.after-market.plist`，`StartCalendarInterval` 设 `Weekday` 1–5、`Hour` 17、`Minute` 10，再 `launchctl load` |
| Linux | `crontab -e` 追加 `10 17 * * 1-5 <上面的命令>` |

配完必须回报三件事：**触发时间、输出目录、如何关掉**（Claude Code 删任务 / `launchctl unload` / `crontab -e` 删除对应行）。

### 必须提前告知的两个坑

- **每次运行都会消耗 Cue 积分**，余额不足时当天会失败并提示充值，不会自动跳过。
- **定时任务不会自动生成看板，也不会推送**：报告只落盘 `~/cue-reports/*.md`，需要自己打开看；看板可在次日交互时基于已落盘的 `.md` 补生成（纯本地操作，不消耗积分）。

## 格式转换

Cue 输出 Markdown。安装 pandoc 后可转换为 Word 或 PDF：

```bash
# .md → .docx（Word）
pandoc report.md -o report.docx

# .md → .pdf
pandoc report.md -o report.pdf --pdf-engine=xelatex
```

输出文件与输入同目录、同名、不同后缀。

### 依赖安装

| 目标格式 | 依赖 | macOS | Ubuntu |
|----------|------|-------|--------|
| Word (.docx) | pandoc | `brew install pandoc` | `sudo apt install pandoc` |
| PDF (.pdf) | pandoc + LaTeX | `brew install --cask basictex` | `sudo apt install texlive-xetex` |

## 可视化看板（输出增强）

Cue 报告是文字底稿，用户常希望"一眼看懂"。**每次交付都必须同时包含报告原文与看板**：在**不改写报告中任何一条结论或数字**的前提下，额外产出一个**单文件、零依赖**的 HTML 看板（纯 SVG/CSS 内联，不引外部 CDN，离线双击即开）。

### 配色与约定（必须遵守）
- **中式配色**：红色=涨/上涨/净流入（`#e23b3b`），绿色=跌/下跌/净流出（`#16a34a`），中性蓝 `#2563eb`，警示橙 `#f59e0b`；
- 单文件 HTML，图表用**内联 SVG**（条形 / 阶梯 / 雷达 / 雷达链）或**百分比宽度的 CSS 条形**（响应式，随容器宽度自适应）；
- 所有数字与结论**原样取自 Cue 报告**，禁止改写、禁止凭记忆补全；报告未给出的数字不要编造，用定性卡片呈现。

### 看板版式（按报告结构自适应，不套固定模板）

**看板结构 = 报告结构**。不要为盘后复盘预设固定的 N 块版式——报告章节会随当天驱动因素变化（板块指定与否、有无龙虎榜数据、两融口径是否延迟），看板必须**解析这份报告本身的实际结构**来排版：

**总骨架（三条铁律）：**
1. **顶部概览区**：报告日期、指数收盘表现、以及**从报告原文提炼的一句话复盘结论**（原样引用，不改写）；
2. **主体区 = 逐章节成块**：报告有几个二级标题（`##`）就看板有几块，顺序、标题与报告完全一致；
3. **底部收尾区**：报告自带的局限性说明 / 免责声明原样保留；没有则不硬造。

**每个章节块怎么渲染——按该节的内容形态选组件（与"第几章"无关）：**

| 该节的内容形态 | 渲染组件 |
|--------------|---------|
| 表格（指数表现、涨跌分布、资金明细等） | HTML 表格原样渲染，涨/净流入行红底、跌/净流出绿底 |
| 数值对比 / 排名 / 占比（板块涨跌幅、资金净额） | 百分比宽度 CSS 条形或 SVG 条形（按数值线性映射，正负双向） |
| 资金流向（沪深港通 / 主力 / 两融） | 双向条形图（流入红、流出绿）+ 金额卡 |
| 连板梯队 | 层级卡片 / 阶梯式列表卡 |
| 事件 + 影响定性（利好/利空/中性） | 事件卡：红=利好、绿=利空，附报告原文的影响含义 |
| 驱动因素拆解（政策 / 事件 / 财报 / 外部冲击） | 分类卡片组 |
| 次日情景推演（情景 + 触发条件 + 观察指标） | 情景对照卡片（情景 / 触发条件 / 盯什么指标三栏） |
| 标的 / 板块清单 | 清单卡，原文名称原样保留，不增不删 |
| 纯论述段落 | 文字卡片，关键数字用高亮样式标出 |

**判定顺序**：先看该节是否含表格 → 是否含可映射的数值 → 是否含涨跌/利好利空定性 → 是否为清单 → 都不是则文字卡片。一个章节块可组合多个组件（如"表格 + 结论高亮"）。

**禁止事项：**
- 禁止预设固定块数（不写死"7 块"或"6 块"）——块数由报告章节决定；
- 禁止增删章节、改标题、改写结论与数字；两融等口径延迟时按报告原文标注（如"按前一交易日"），不要自行补全当日值。

### 生成方式（推荐脚本化）
用 Python（标准库即可）读取 Cue 落盘的 `.md` 报告 → 解析其标题层级与各节内容形态（表格 / 数值 / 定性 / 清单 / 论述）→ 按上表选组件逐节渲染 → 计算 SVG 坐标与百分比条宽 → 渲染 HTML 字符串 → 写文件。示例输出路径：

```
~/cue-reports/<原名>-dashboard.html
```

> 参考实现：条形用 `width:%` 而非固定 px（避免与页面宽度不适配）；移动端用 `@media` 把多列网格降为单列；图表坐标按数据点线性映射；报告无数字处用定性标签替代，不编造序列。

### 定时任务链路说明
定时任务是无界面跑批，报告只落盘 `~/cue-reports/*.md`、**不自动生成看板**；用户次日询问或 Agent 交互复盘时，基于已落盘的 `.md` 补生成看板即可——看板生成是纯本地操作，**不消耗 Cue 积分**。

### 交付
在交付模板追加一行（用户明确不要可不附，但需说明可随时补生成）：

```
**可视化看板**：~/cue-reports/<原名>-dashboard.html（单文件 HTML，浏览器直接打开）
```

并用 present_files 打开预览。

## 架构说明

本 Skill **不在本地执行检索**。流程是 Agent → Cue API（cuecue.cn）→ 外部数据源。解析结果的质量和时效取决于 Cue 服务端和外部数据源的状态。

| 环节 | 谁控制 | 出问题时 |
|------|--------|---------|
| API Key 鉴权 | 用户本人 | **由用户本人**前往 [cuecue.cn/hub/api-key](https://cuecue.cn/api-key?src=clawhub-after-market-assistant) 生成后点「复制」并粘贴发送给您正在使用的智能体，再由 Agent 写入 ~/.cue/config.json（Agent 不能代生成，也无权查看） |
| Cue 服务端 | Cue 运维 | 等恢复，或走降级方案 |
| 外部数据源 | 公开网站 | Cue 用缓存兜底，标注"来源暂不可达" |

## 健康检查

跑研究前先验证三件事。一键诊断：

```bash
CUE_KEY=$(python3 -c "import json;print(json.load(open('$HOME/.cue/config.json'))['api_key'])" 2>/dev/null || echo "$CUE_API_KEY")
echo "=== 1/3 API Key ===" && [ -n "$CUE_KEY" ] && echo "已配置" || echo "未配置！"
echo "=== 2/3 Cue 服务 ===" && curl -sS --max-time 10 "https://cuecue.cn/api/health" -H "Authorization: Bearer $CUE_KEY"
echo "=== 3/3 搭子 ===" && curl -sS --max-time 10 "https://cuecue.cn/api/playbook" -H "Authorization: Bearer $CUE_KEY" | python3 -c "import sys,json;scenes=json.load(sys.stdin).get('data',{}).get('scenes',[]);buddy=[b for s in scenes if s.get('secondary_category')=='财富投顾' for b in s.get('buddies',[]) if b.get('title')=='盘后超级助理'];print(f'可用:{len(buddy)}个') if buddy else print('暂不可用')"
```

| 检查 | 预期 | 异常处理 |
|------|------|---------|
| API Key | `已配置` | **由用户本人**前往 [cuecue.cn/hub/api-key](https://cuecue.cn/api-key?src=clawhub-after-market-assistant) 生成后点「复制」并粘贴发送给您正在使用的智能体（Agent 无法代生成，也无权查看） |
| 服务 | `{"status":"healthy"}` | 等 5 分钟重试 |
| 搭子 | `可用:>0个` | 等 1h 或网页端手动跑 |

### 配置成功后引导用户跑第一个任务（必须执行）

健康检查三项全绿 = 环境就绪，但**这是配置流程的终点，不是任务的终点**。三项全绿后若用户还没给出具体任务，**必须主动把用户推向第一次真实调用**，不要停在"环境已就绪"：

> 环境已就绪 ✅ 下面这些都可以直接跑，比如：
> 1. "帮我复盘今天的市场"
> 2. "今天为什么涨/跌？对我的持仓有什么影响？"
> 3. "复盘今天市场，重点看 AI 板块"
>
> 挑一个发给我，或直接把你手头的需求告诉我，我现在就跑。

规则：
- **主动、可复制**——示例问题原句取自上文「试试这样问」，别只写"你可以问我任何问题"。
- **不要等用户自己想**——用户没开口时也要主动给；否则用户会停在"验证通过"就散场（实测这是新用户流失最集中的一步）。

## 自救指引

### 错误速查

| 现象 | 原因 | 怎么修 |
|------|------|--------|
| 401 / Key 无效 | Key 过期或写错 | 由用户本人重新生成 Key，更新 `~/.cue/config.json` |
| 超时 >30s | 服务维护/过载 | 等 5 分钟，跑诊断；当天内重试 |
| 搭子不可用 | 临时下线 | 网页端直接跑，或等 1 小时 |
| 积分不足 | 余额 < 消耗 | **按「积分不足专项提示」主动引导**（充值 / 邀请好友得积分 / 等次日免费额度） |
| 中途中断 | 队列满/数据源波动 | **不换 prompt**，相同命令续接 |
| `RESULT empty` | 公开源无匹配 | 缩小范围，换关键词 |
| config.json 报错 | JSON 格式不对 | `{"api_key": "sk..."}` 无多余逗号 |

### 积分不足专项提示（必须执行）

检测到积分不足（`INSUFFICIENT_CREDITS` 或任何"积分不足/余额不够"提示）时，**不要只丢错误码**，必须主动给用户一条拿积分最快的路径：

> 你的 Cue 积分不足，本次任务未能启动。两个办法：
> 1. **邀请好友得 500 积分（推荐）**：打开 [https://cuecue.cn/](https://cuecue.cn/)，点击页面**左下角**「获取专属邀请链接」，分享给好友——好友加入后你再得 **500 积分**。
> 2. **直接充值**：前往 [cuecue.cn/pay](https://cuecue.cn/pay) 订阅（首次充值有优惠）；或等次日免费额度。

规则：
- 提示要**主动、简短、可点**——把「首页」和「左下角」两个关键动作说清楚，不要让用户自己找入口。
- 积分不足**不要重试**（`retryable: false`），也不要换 query 绕。
- 用户回复已充值/已邀请后，用**完全相同的命令**重跑。

### 决策树


## FAQ

**Q: 和看盘软件的盘后总结有什么区别？**
A: 看盘软件给的是"今天发生了什么"，Cue 给的是"为什么发生、跟我有什么关系、明天该怎么办"。每条判断都带公开出处。

**Q: 能针对我的持仓做分析吗？**
A: 能。在 `--query` 里写清你关注的板块（如"重点分析 AI 板块"），第 4 章「核心主线深度解析」就会聚焦这个板块；不指定时，这一章自动取全市场当日最强板块。

**Q: 能分析某只股票吗？**
A: 不能。本 skill 只做市场层面（大盘/板块/资金）的复盘；**个股**的短线走势与技术面——支撑压力位、买卖节奏、关键价位——请改用「**短线走势与技术面分析**」（`cue-technical-analysis`）。

**Q: 盘前 / 开盘方向的问题能问吗？**
A: 不能。本 skill 只做**收盘后**的复盘，不做盘前 / 开盘预判。想知道今天开盘会怎么走、盘前有哪些机会、开盘要不要减仓，请改用「**今日盘前机会**」（`cue-pre-market-strategy`）。

**Q: 最佳跑的时间？**
A: 建议 **17:10 之后**——龙虎榜在 16:30 后披露，当日成交概况（成交额等）约 17:00 才落地，排到 17:10 留余量，此时数据最齐全。如果忙，晚饭后跑也够用；两融余额当日口径要更晚，报告会按前一交易日标注。

**Q: 每天都跑会重复吗？**
A: 每天市场驱动不同，报告内容跟着当天实际情况走。建议养成每日复盘的习惯。

**Q: 等了几分钟没动静，要不要再发一次？**
A: 不要。同一问题重复提交会新建任务、重复消耗积分。报告通常 2-15 分钟出结果（多数 5-10 分钟）；超过 15 分钟再让我查进度，我会沿用原任务续接，不改 prompt。

**Q: 报告能在网页端看原文吗？**
A: 能。交付时会同时附上 Cue 原始报告链接 `https://cuecue.cn/share/<conv_id>`，可回网页端查看完整原文、继续追问或转发同事。

**Q: 提示积分不足怎么办？**
A: 打开 [cuecue.cn](https://cuecue.cn/)，点击页面左下角「获取专属邀请链接」，好友加入后你再得 500 积分；也可前往 [cuecue.cn/pay](https://cuecue.cn/pay) 充值（首次有优惠），或等次日免费额度。积分不足不要重试。

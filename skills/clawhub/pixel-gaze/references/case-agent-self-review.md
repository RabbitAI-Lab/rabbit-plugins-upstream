# 案例B：Agent前端自审（主打案例）

## 背景

Agent复刻了「海纳百川·2024首届北戴河·大不同国际装置艺术展」页面。代码构建成功、DOM结构完整、没有JS报错——所有自动化检查全部通过。

**现在需要自审：渲染出来到底长什么样？**

## 第一层：整体扫视

- **页面类型**：活动落地页，Hero大图+分段内容
- **区域划分**：
  - 顶部：Hero区（全宽背景图+标题叠层）
  - 中部：活动介绍段落
  - 下方：更多内容区（未截入本次视图）
- **整体印象**：深色背景+白色文字，视觉风格统一，Hero区占据主要视觉焦点

## 第二层：标记精度敏感区

以下是"差一个像素就翻车"的区域：

| 敏感区 | 为什么重要 |
|--------|-----------|
|  Hero区人物面部 | 背景图是30人合影，人脸裁切会直接毁掉页面观感 |
| 🔴 Hero文字层级 | 标题"海纳百川"、标签"2024·北戴河"、副标题三层叠加，位置和对比度必须正确 |
| 🟡 中部段首句 | "大不同装置艺术主题公园落成..."——首行加粗，需确认颜色/字号正确 |
|  底部文字边界 | 段首句是否被viewport裁切？ |

---

## 第三层：专门确认敏感区

### 敏感区1：Hero人物面部 → 🚨 发现真Bug

**Desktop (1200px)**: Hero图顶部裁切——合影中后排人员头顶被切掉，前排蹲姿人员面部勉强可见但偏下。

**Wide (1920px)**: 裁切更严重！hero区高度被CSS `clamp(460px, 70vh, 640px)` 锁死在640px上限，屏幕变宽后hero没有等比扩展高度，导致图片上下裁切幅度显著增大，更多人头顶被裁掉。

**Mobile (375px)**: 最严重——hero区域只能显示合影的上半部分，中排以下人物几乎完全不可见。

**根因定位**：
```css
header {
  height: clamp(460px, 70vh, 640px);  /* ← 高度有上限640px */
  overflow: hidden;                     /* ← 超出部分直接裁掉 */
}
header img {
  object-fit: cover;  /* ← 按容器比例裁切，不保证人脸完整 */
}
```
`overflow:hidden` + `object-fit:cover` + 固定高度上限 = 人脸裁切。在宽屏和窄屏上问题程度不同，但根因相同。

### 敏感区2：Hero文字层级 → ✅ 通过

- "2024 · 北戴河"标签：居中，金色描边，清晰可读 ✅
- "海纳百川"标题：白色粗体，字号合适，位于图片下方1/3处 ✅
- 副标题"首届北戴河·大不同国际装置艺术展"：灰色细体，三屏均可读 ✅
- 文字均位于图片渐变暗色区域上方，对比度充足 ✅

### 敏感区3：中部段首句 → ✅ 通过

- Desktop/Wide："大不同装置艺术主题公园落成 北戴河再添艺术文旅新地标" 白色加粗，清晰 ✅
- Mobile：段首句在viewport底部被截断一半——需要滚动才能看全 ⚠️

## 第四层：如实输出

### 发现的问题清单

| # | 问题 | 严重度 | 截图证据 |
|---|------|--------|---------|
| 1 | **Hero人物面部被裁切**：`overflow:hidden` + `object-fit:cover` + 高度上限导致合影人脸不完整，宽屏最严重 | 🔴 高 | desktop.png / wide.png / mobile.png |
| 2 | **Mobile段首句被viewport裁切**：首屏高度下段首文字只显示一半 | 🟡 中 | mobile.png |

### 修复建议

**针对问题1（Hero人脸裁切）**：
- 方案A：将hero高度从固定值改为基于图片原始比例（`aspect-ratio`），让人脸区域始终可见
- 方案B：对hero图片使用 `object-position: center 30%` 向上偏移焦点，优先保留人物区域
- 方案C：换一张以人物为视觉中心的裁剪版本作为hero背景

**针对问题2（Mobile段首句裁切）**：
- 减少hero区域在mobile上的高度占比，或增大min-height确保段首句完整可见

## 对比结论

| 维度 | 无自审（只看代码） | 像素级凝视自审 |
|------|------------------|--------------|
| 构建状态 | ✅ 通过 | ✅ 通过 |
| DOM完整性 | ✅ 通过 | ✅ 通过 |
| **人脸裁切** | ❌ 未发现 | ✅ 发现（根因定位到CSS） |
| **Mobile段首句裁切** | ❌ 未发现 | ✅ 发现 |
| 文字层级 | — | ✅ 确认正常 |
| 可执行修复建议 | 无 | ✅ 3个方案 |

**核心洞察**：代码层面零报错 ≠ 渲染结果正确。`overflow:hidden` + `object-fit:cover` 在CSS语法上完全合法，但实际渲染效果取决于图片内容与容器的比例关系——这只能通过"看"来验证。

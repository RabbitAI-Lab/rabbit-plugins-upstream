# 叙事方法论

## 三大叙事框架

### 1. BLUF（Bottom Line Up Front）— 结论前置

```
结论（What）→ 论据（Why）→ 建议（Now What）
```

**适用场景：** 所有高管汇报。不适用于需要"讲故事"的场合。

**强制规则：** 第一段不给出结论的报告，打回重写。

**示例：**

```
❌ 铺垫式：
"随着行业数字化转型加速，我们注意到采购管理领域存在诸多低效环节，
经过三个月的系统调研和数据分析，我们认为有必要优化当前的采购体系…"

✅ BLUF式：
"采购成本可在12个月内降低1200万元。
通过对47个品类的支出分析，我们发现12个品类存在15%-40%的成本优化空间。
建议Q3启动电子采购平台建设，由张总负责，预计投资回报周期8个月。"
```

### 2. So What / Why Now / What Next — 三段式

```
所以呢？（So What）→ 为什么是现在？（Why Now）→ 下一步？（What Next）
```

**适用场景：** 决策备忘录、需要推动行动的报告。

**三段展开：**

| 段 | 核心问题 | 示例 |
|---|---------|------|
| So What | 这个发现意味着什么？对业务的实际影响是什么？ | "如果继续维持现有采购模式，预计每年多支出1200万，且供应商集中度风险持续上升" |
| Why Now | 为什么必须是现在做？拖到明年有什么不同？ | "三个供应商合同在Q4到期，如果现在不启动招标流程，将被迫以现价续约" |
| What Next | 下一步具体做什么？谁来做？什么时候完成？ | "建议张总在7月30日前完成电子采购平台招标，9月1日上线试运行" |

### 3. 金字塔原理

```
核心结论
  ├─ 论据1（数据支撑）
  │   ├─ 子论据1.1
  │   └─ 子论据1.2
  ├─ 论据2（数据支撑）
  │   └─ 子论据2.1
  └─ 论据3（数据支撑）
```

**适用场景：** 董事会汇报、需要层层论证的复杂议题。

**原则：** MECE（Mutually Exclusive, Collectively Exhaustive）— 不重不漏。

## 叙事节奏

### 信息密度曲线

```
高管报告的信息密度应该是"前高后低"：

第1段（核心结论）  ████████████  12/10 密度
第2段（关键发现）  ██████████    10/10 密度
第3段（业务影响）  ████████      8/10 密度
第4段（建议行动）  ██████        6/10 密度
第5段（风险考量）  ████          4/10 密度
附录（详细数据）   ██            2/10 密度（对高管）
```

**为什么？** 高管阅读时间有限，前200字决定是否继续读。

### 30秒电梯法则

任何报告都应能提炼为30秒口头版本：
1. 核心结论（10秒）
2. 关键数据（10秒）
3. 需要什么决策（10秒）

## 对比与类比

### 对比的力量

| ❌ 孤立的数字 | ✅ 对比中的数字 |
|-------------|--------------|
| Q3客户流失率4.2% | Q3客户流失率4.2%（Q2为3.8%，↑0.4pp，同比↑0.7pp） |
| 项目预算500万 | 项目预算500万（行业同类项目平均380万，溢价因技术选型） |
| 响应时间降至5分钟 | 响应时间从2小时降至5分钟（行业标杆为10分钟） |

### 类比的策略

| 数字 | 类比 | 效果 |
|------|------|------|
| 节省1200万/年 | 相当于新增一个中型产品的年收入 | 直观可感 |
| 处理速度提升20倍 | 原先批处理跑一晚上，现在午休时间就完成 | 画面感强 |

# 边界情况处理策略 V2.0

## 报告初始化

| 场景 | 处理 |
|------|------|
| 目标目录已存在 | 报错退出，提示用户手动处理 |
| 目标模板不存在 | 报错退出，列出可用模板列表 |
| 报告名含特殊字符 | 自动过滤为安全文件名 |

## 版本管理

| 场景 | 处理 |
|------|------|
| 不在报告目录中执行 bump | 自动向上搜索 `version.json`，找不到则报错 |
| version.json 损坏 | 报错退出，显示期望的 JSON 格式 |
| 最新 md 文件版本号与 version.json 不一致 | 以 version.json 为准，提示用户确认 |
| --dry-run 模式 | 仅输出变更预览，不修改任何文件 |
| 同一报告有多个版本文件 | 按 SemVer 排序取最新 |

## 内容校验

| 场景 | 处理 |
|------|------|
| 文件不存在 | 报错退出 |
| 文件为空 | 全部检查项标记为 ❌，降级为 D |
| 无"建议行动"章节 | check_action_clarity 返回 ❌，提示增加 |
| 无"业务影响"章节 | check_so_what 返回 ❌，提示增加 |
| 报告仅含 BLUF 格式（英文） | 7 项检查同时支持中英文匹配 |

## 密度分析

| 场景 | 处理 |
|------|------|
| 文件为空 | 所有指标返回 0 |
| 无段落分隔（单段全文） | 段落分析标记为"单段"，不做拆分建议 |
| 完全无数据（纯叙事报告） | data_density 返回全部 0，"数据密度过低"警告 |
| 报告超过 5000 字 | 仍正常分析，但"过长段落"阈值不变 |

## 跨 SKILL 协作

| 场景 | 处理 |
|------|------|
| markdown-to-html 不可用 | 降级：仅输出 md，提示用户手动转换 |
| solution-architect 未产出详案 | 降级：手动输入详案内容或文档路径 |
| digital-research 无结果 | 章节留空 + `<!-- TODO: 待调研补充 -->` 标记 |
| 上游 SKILL 产出非标准格式 | 尝试提取关键章节，提示格式不匹配 |

## 并发与协作

| 场景 | 处理 |
|------|------|
| 同一报告目录被多人操作 | 不支持并发编辑。bump.py 新文件写入前不检查锁。 |
| 版本冲突（两个人同时 bump） | 后操作者可能覆盖。建议在 reports/ 根目录保留操作日志。 |

## 长报告处理

| 场景 | 处理 |
|------|------|
| 输入详案超过 50 页 | 先做章节提取和摘要生成，分步处理 |
| 含大量表格/图表 | 提取关键表格数据，图表用文字描述替代 |
| 含代码块 | 自动跳过代码块，不纳入字数统计 |

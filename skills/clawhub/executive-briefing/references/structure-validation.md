# 结构校验规则详解

## 校验体系概览

V2.0 校验从"结构合规"转向"内容质量"，7 项检查对应高管阅读场景的真实需求。

---

## 校验规则详解

### 1. 结论前置（BLUF）

**检查目标：** 报告前两段是否包含结论性表述，而非背景/方法论铺垫。

**检查方式：** 提取前200个有效字符，匹配结论性关键词（"结论""建议""需要""必须""核心"等），同时检测是否以背景性表述开头。

**判定标准：**
- ✅ 通过：首段发现结论性标记
- ❌ 不通过：首段以"背景""方法""概述"等开头

### 2. 业务影响（So What）

**检查目标：** 是否包含业务影响分析章节。

**检查方式：** 全文搜索 "Implications""业务影响""So What""这意味着" 等标记。

**判定标准：**
- ✅ 通过：检测到相关章节
- ❌ 不通过：完全缺失，建议增加

### 3. 数据支撑度

**检查目标：** 关键主张是否有量化数据支撑。

**检查方式：** 统计百分比/金额/倍数/趋势+数字/数量词的出现次数。

**判定标准：**
- ✅ 通过：≥2 处数据支撑
- ⚠️ 通过（弱）：仅 1 处数据支撑
- ❌ 不通过：0 处数据支撑

### 4. 行动明确性（Owner+Timeline）

**检查目标：** 建议行动是否包含负责人和时间线。

**检查方式：** 在"建议行动"章节中搜索 Owner（"负责""责任人""—姓名"）和 Timeline（"时间""Q1-4""月""日前"）标记。

**判定标准：**
- ✅ 通过：同时包含 Owner 和 Timeline
- ⚠️ 部分通过：仅含一项
- ❌ 不通过：两项都缺失

### 5. 篇幅控制（≤500词）

**检查目标：** 报告主体（排除附录）是否符合 500 词上限。

**检查方式：** 截取附录之前的内容，统计中文字符 + 英文单词总数。

**判定标准：**
- ✅ 通过：≤500 词
- ❌ 不通过：>500 词

### 6. 置信度标注

**检查目标：** 关键发现是否标注置信度等级。

**检查方式：** 正则匹配 "置信度：HIGH/MEDIUM/LOW" 或 "[HIGH CONFIDENCE]" 等格式。

**判定标准：**
- ✅ 通过：≥1 处置信度标注
- ❌ 不通过：0 处

### 7. 被动语态检查

**检查目标：** 是否使用了被动语态。

**检查方式：** 中文：匹配"被/受到/遭到/得以"；英文：匹配 `is/are/was/were + V-ed` 模式。

**判定标准：**
- ✅ 通过：0-2 处（可接受范围）
- ❌ 不通过：>2 处

## JSON 输出格式

```json
{
  "report": "01-报告名称-v1.0.0.md",
  "timestamp": "2026-07-23T10:00:00+08:00",
  "summary": {
    "passed": 6,
    "total": 7,
    "score": "6/7",
    "grade": "A"
  },
  "checks": [
    {
      "rule": "bluf",
      "name": "结论前置（BLUF）",
      "pass": true,
      "detail": "首段发现结论性标记: \"建议\""
    }
  ]
}
```

### 评级标准

| 等级 | 通过数 | 含义 |
|------|--------|------|
| A | 6-7 | 高质量报告，可直接呈送 |
| B | 4-5 | 基本合格，建议补充完善 |
| C | 2-3 | 需要较大修改 |
| D | 0-1 | 需要重写 |

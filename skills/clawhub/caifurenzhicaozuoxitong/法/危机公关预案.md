# 危机公关预案

> **灰度思维在坏选项中找动态平衡，奥卡姆剃刀简化应对。危机中最大的风险不是危机本身，而是决策者在恐慌中做出的草率反应。**

危机公关的本质不是在"好选项"和"坏选项"之间选择——如果还有好选项，那就不是危机。真正的危机公关是在"坏选项"和"更坏的选项"之间，用最少的信息耗散找到代价最小的动态平衡。本文件提供三层框架：从事发30秒内的定级定调到危机过后的信任重建。

---

## L1 — 快速判据（≤30秒）

危机发生的第一个30秒，决定事件走向的50%。完成三件事：定级、定调、定人。

### 1. 定级：判断危机的严重程度

| 级别 | 定义 | 典型场景 | 响应级别 |
|------|------|----------|----------|
| **L1 — 轻微** | 个别客户不满，尚未扩散 | 单一投诉、服务故障（<1小时） | 客服团队直接处理 |
| **L2 — 中等** | 小范围扩散，负面情绪在积累 | 社交媒体出现集中负面讨论、产品缺陷影响部分用户 | 公关+产品联合响应 |
| **L3 — 严重** | 品牌声誉受损，公众关注 | 数据泄露、产品质量引发安全事故、高管不当言论 | CEO+公关+法务联合小组 |
| **L4 — 灾难** | 存在性威胁，关乎企业存亡 | 重大安全事故致死、系统性欺诈、监管吊销执照 | 董事会+全员动员 |

**定级判断辅助问题：**

1. 是否涉及人身安全或健康？（是→至少L3起）
2. 是否涉及法律/监管红线？（是→至少L3起）
3. 是否在社交媒体上正在扩散？（是→至少L2起）
4. 是否影响核心用户群体？（是→升一级处理）

**定级陷阱：** 最大的错误不是定高了，而是定低了。L3当L1处理，等发酵后再升级，已经错过了最佳回应窗口。

### 2. 定调：确定对外第一句话

> **第一句话决定公众对你的定性——"他们在隐瞒"还是"他们在担当"。**

**定调三分法：**

| 情况 | 首句话模板 | 适用条件 |
|------|-----------|----------|
| **事实清楚，责任在己** | "我们已经确认了[具体事实]。这是我们的责任，我们正在[具体行动]。对于[受影响方]，我们深感抱歉。" | 事实已查明且确实是己方责任 |
| **事实待查，但影响已发生** | "我们已经注意到[事件描述]。目前我们正在全力调查原因。[受影响方]是我们的首要关切，我们已启动[具体措施]。我们将在[明确时间]前公布调查进展。" | 事实尚在调查但必须对外发声 |
| **已方无责，但被牵连** | "关于[事件]，我们确认的事实是[核心事实]。我们理解大家的关切，并愿意配合[相关方]澄清事实。" | 有证据表明己方无责 |

**定调的红线（绝对不能做的事）：**

- 说"无可奉告"（在公众看来等于"我有罪但我不说"）
- 攻击提出质疑的人（从危机主体变成施害者形象）
- 在没有事实依据时说"绝对没有/肯定不是我们"（一旦被证伪，信誉归零）
- 使用"可能/或许/大概"等模糊词来描述自己应该清楚的事实
- 把责任推给一线员工（"临时工"陷阱——公众知道这是组织责任）

### 3. 定人：决定谁出面

| 级别 | 出面人 | 原因 |
|------|--------|------|
| L1 | 客服主管/产品经理 | 不升级到不需要升级的层级 |
| L2 | 部门负责人/公关总监 | 显示重视但不过度反应 |
| L3 | CEO或创始人 | 公众期待"最高负责人"的态度 |
| L4 | CEO + 董事长/董事会代表 | 存在性危机需要最高决策层面对 |

**黄金原则：出面人的级别永远应该比公众预期高半级，但不能高太多。高太多意味着恐慌，低了意味着傲慢。**

## L2 — 标准分析（~5分钟）

危机发生后第一个小时，完成以下五步分析。顺序不能乱。

### 第一步：事实拼图

把"已经确认的事实"和"尚未确认的猜测"严格分开。这是危机公关中最重要也最容易被跳过的步骤。

**事实拼图模板：**

| 项目 | 内容 | 确认度 | 来源 |
|------|------|--------|------|
| 发生了什么？ | | [ ] 已确认 [ ] 待确认 | |
| 什么时候发生的？ | | [ ] 已确认 [ ] 待确认 | |
| 涉及多少人/哪些人？ | | [ ] 已确认 [ ] 待确认 | |
| 最严重的后果是什么？ | | [ ] 已确认 [ ] 待确认 | |
| 谁/什么原因导致的？ | | [ ] 已确认 [ ] 待确认 | |
| 我们是什么时候知道的？ | | [ ] 已确认 [ ] 待确认 | |

**事实拼图的核心纪律：**

- "你认为是什么"不等于"事实是什么"
- "别人告诉你的"不等于"你核实过的"
- 没有确认度标记的信息，禁止用于任何对外沟通
- 当事实拼图不足60%时，对外沟通的重心是"我们在查"而非"我们认为"

### 第二步：利益相关者地图

危机中最大的错误之一：只关注媒体和公众，忽略了那些不发声但至关重要的利益相关者。

**利益相关者优先级矩阵：**

| 优先级 | 利益相关者 | 核心关切 | 沟通时机 | 沟通方式 |
|--------|-----------|----------|----------|----------|
| P0 | 直接受灾者（受伤客户/受影响用户） | 安全、补偿、道歉 | 第一时间 | 一对一直接沟通 |
| P1 | 核心客户群体 | "我是否也会受影响？" | 1小时内 | 公开声明+定向通知 |
| P2 | 员工 | "公司会不会倒下？我的工作呢？" | 1-2小时内 | 全员内部通报 |
| P3 | 监管/政府 | 是否违法？是否需要介入？ | 2-4小时内 | 主动报备 |
| P4 | 合作伙伴/供应商 | 合作是否受影响？ | 4-8小时内 | 定向商务沟通 |
| P5 | 媒体/公众 | 发生了什么？谁的责任？ | 随公开声明同步 | 官方声明+指定发言人 |
| P6 | 投资者/股东 | 对估值/股价的影响 | 根据监管要求 | 正式披露 |

**优先级铁律：P0永远优先于P5。如果你在安抚媒体上花的时间多于在安抚直接受害者的时间，你已经走错了方向。**

### 第三步：灰度决策矩阵

危机中没有"对"的选项，只有不同代价的"坏"选项——你需要用灰度思维在其中找平衡。

**灰度决策矩阵模板：**

| 候选行动方案 | 谁受益？ | 谁受损？ | 短期代价 | 长期影响 | 是否可逆？ | 综合评估 |
|-------------|---------|---------|----------|----------|-----------|----------|
| 方案A | | | | | | |
| 方案B | | | | | | |
| 方案C | | | | | | |

**灰度决策四原则（来自小约瑟夫·巴达拉克的《灰度决策》）：**

1. **净后果最大化**：对所有人而言，哪个方案的综合后果"最不坏"？
2. **核心义务不可侵犯**：有没有任何核心义务（人的安全、法律底线）是不可妥协的？
3. **世界照常运转**：想象你只是一个旁观者——这个决策在一个客观的第三方看来像什么？
4. **我能接受这个决策成为先例吗？**：如果未来所有类似情况都按这个方式处理，世界会更好还是更糟？

### 第四步：沟通SOP

将决策转化为有纪律的沟通执行。

**黄金4小时窗口内的行动时间线：**

| 时间 | 行动 | 负责人 | 完成标准 |
|------|------|--------|----------|
| 0-15分钟 | 定级定调定人（L1流程） | 值班负责人 | 三个决策全部做出 |
| 15-30分钟 | 事实拼图（L2第一步） | 事件调查组 | 至少确认"发生了什么"和"最严重的后果" |
| 30-60分钟 | 利益相关者优先排序+内部对齐 | 危机小组 | P0沟通已启动 |
| 60-90分钟 | 首份公开声明发出 | 指定发言人 | 声明通过至少两个渠道发布 |
| 90分钟-4小时 | 持续更新、利益相关者逐一沟通 | 危机小组 | 所有P0-P3已触达 |

**危机沟通的奥卡姆剃刀原则：**

- 用最短的句子。每增加一个从句，误解概率翻倍。
- 说你能确认的，不猜测你不能确认的。
- 用"我们正在做X"代替"我们将会考虑Y"——行动语言永远优于承诺语言。
- 如果一件坏事必然会被发现，你自己第一个说出来——自曝永远好于被曝。

### 第五步：法律防线

法律顾问和公关顾问在危机中往往给出方向相反的建议——律师倾向于"少说话以降低法律风险"，公关倾向于"多说话以降低声誉风险"。你需要在这两者之间找到平衡。

**法律-公关平衡框架：**

| 问题 | 法律视角 | 公关视角 | 平衡策略 |
|------|----------|----------|----------|
| 承认责任 | 可能成为法庭上的不利证据 | 是重建信任的起点 | 表达遗憾和关切，但在事实查清前不贸然承认法律责任 |
| 道歉 | 可能被解读为承认过错 | 是公众最期待的态度 | "我们对发生的事深感抱歉"不等于"我们承认法律上的过错" |
| 信息披露 | 越少越好，避免被利用 | 越多越好，体现透明度 | 披露已确认的事实，标注未确认的部分，承诺持续更新 |
| 赔偿承诺 | 设定了法律上的赔偿标准 | 是安抚受害者的必要步骤 | 先解决人的问题（医疗、安全、基本补偿），再处理法律赔偿 |

**核心原则：法律防线决定"什么不能说"，公关需求决定"什么必须说"，在两者的交集里找到可用空间。**

## L3 — 深度报告（重大决策前/危机后）

### 1. 信任重建

危机处理的目标不是"事情平息"，而是"信任恢复到危机前水平或更高"。

**信任重建四阶段：**

| 阶段 | 时间范围 | 核心任务 | 成功标志 | 常见错误 |
|------|----------|----------|----------|----------|
| **应急期** | 0-7天 | 止损失控、保护受害者、建立信息透明 | 公众认为"他们在认真处理" | 过度承诺无法兑现 |
| **修复期** | 1-4周 | 查明根因、追究责任、系统性改进 | 改进措施有具体的时间表和责任人 | 改进方案泛泛而谈 |
| **重建期** | 1-6个月 | 超额补偿、第三方监督、透明化改进进展 | 受害者公开表示满意或第三方验证通过 | 以为"时间会冲淡一切" |
| **超越期** | 6-24个月 | 将教训转化为行业标准、从危机中提炼品牌叙事 | 行业/公众开始引用你作为"处理得当"的案例 | 过早地"翻篇"——信任恢复需要时间 |

**信任重建的核心度量指标：**

| 指标 | 测量方法 | 恢复目标 |
|------|----------|----------|
| 客户信任度 | 独立调研（非内部NPS） | 恢复至危机前水平 |
| 品牌搜索量 | 搜索趋势中的负面关键词占比 | 降低至危机前的2倍以内 |
| 员工信心 | 内部匿名调研 | "我相信公司正在正确的方向上">70% |
| 业务恢复率 | 危机相关业务指标（销量/续费率） | 6个月内恢复至危机前80%以上 |

### 2. 危机预案库构建

不要等到下一次危机才从零开始。从这次危机中构建你的预案库。

**预案库结构：**

| 危机类型 | 真实案例参照 | 预警信号 | 标准响应模板 | 上次演练日期 |
|----------|-------------|----------|-------------|-------------|
| 数据/隐私泄露 | | | | |
| 产品安全事件 | | | | |
| 高管言行失当 | | | | |
| 监管调查/处罚 | | | | |
| 员工关系/劳工事件 | | | | |
| 供应链中断 | | | | |
| 网络舆情风暴 | | | | |
| 自然灾害/不可抗力 | | | | |

**预案每项必须包含的最小信息：**
- 该类型危机在你们行业发生过的真实案例（至少2个）
- 前3小时的预设响应动作
- 决策链上的责任人名单（含替补，因为关键人可能刚好不在）
- 预先起草的声明模板（填空式，应对前2小时的信息真空）
- 上一次桌面推演的日期和发现的漏洞

## 🔄 复盘锚点

每次危机后复盘时，回到以下四个锚点：

1. **预警锚点**：这件事发生之前，有没有任何信号？是我们没看到，还是看到了但没当回事？如果同样微弱的信号出现在今天，我们会不会再次忽略？

2. **响应锚点**：我们的第一次公开回应，在24小时后回看，有没有任何地方需要纠正？从"事情发生"到"我们第一次正确回应"之间的间隔，可以压缩多少？

3. **信任锚点**：危机发生前，我们在关键利益相关者那里的"信任存款"有多少？危机来临时，这些存款够不够用？——平时积累的信任是危机中最硬的通货。

4. **进化锚点**：这场危机之后，我们组织的"免疫力"增强了多少？——如果同样的外部事件再次发生，我们的响应会比这次好在哪里？

**复盘节奏建议：**

| 复盘频率 | 复盘内容 | 参与人 |
|----------|----------|--------|
| 危机发生后48小时内 | 响应质量快速复盘（趁记忆新鲜） | 危机处理小组 |
| 危机发生后2周 | 根因分析、系统性改进方案 | 核心管理层+相关部门 |
| 危机发生后1个月 | 预案库更新、信任恢复进展 | 核心管理层 |
| 危机发生后6个月 | 信任恢复度测量、组织学习固化 | 董事会+创始团队 |
| 每年（无危机时） | 预案库桌面推演、危机演练 | 各部门负责人 |

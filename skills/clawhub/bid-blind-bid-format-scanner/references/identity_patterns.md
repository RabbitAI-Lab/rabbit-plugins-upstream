# 身份"显形"扫描 · 启发式词典与安全改写建议

> 配合 `scan_docx.py` / `scan_pdf.py` 的 `--identifiers` 与启发式扫描使用。
> 精确标识符（公司名/简称/项目负责人/既往项目名）由用户在使用时提供；
> 本文件提供"暗示性措辞"的启发式词表与对应安全改写，用于一键修订建议。

---

## 〇、误报分级与白名单（降低误报率的关键）

暗标语境下启发式词表误报率偏高（如"我公司"在某些项目被允许、"荣获"可能出现在通用工艺描述）。
按以下规则分级与过滤：

1. **精确命中（🔴）**：仅 `--identifiers` 提供的公司名/简称/项目负责人/既往项目名等明确标识命中 → 废标级，必须处理。
2. **启发式命中（🟡）**：暗示性措辞（"我公司""荣获""独家"等）命中 → **一律标 🟡 而非 🔴**，仅作补充告警，由用户/AI 结合上下文判断是否真实泄漏。
3. **白名单豁免**：若本项目允许某自称/术语（如允许用"我公司"），在运行脚本时加 `--allow "我公司,我单位"`，命中即从结果中剔除，不报。
4. **上下文佐证**：每条命中脚本都返回前后各约 50 字 `context`，比对时必须参看上下文再下结论，禁止单凭词命中即判泄漏。

> 原则：宁可漏报提示、不可误伤废标。启发式仅"提醒"，不"定罪"。

## 一、暗示性泄漏词表（启发式，脚本内置 + 本表可扩充）

| 危险措辞（示例） | 风险 | 安全改写 |
|---|---|---|
| 我公司 / 我司 / 本公司 / 我们公司 / 我单位 | 直接暴露主体 | 改为"投标人"或"本项目" |
| 承建 / 总承包 / 我方施工 | 暗示既往/当前主体业绩 | 改为"实施""完成""组织" |
| 荣获 / 获得XX奖 / 国家级/省级XX奖 | 指向特定荣誉主体 | 删除荣誉表述，或改为中性技术描述 |
| 独家 / 唯一 / 行业领先 / 一流 / 龙头 / 首家公司 | 主体特征暗示 | 删除或改为"满足/符合规范要求" |
| 自主核心技术 / 自有工法 / 专有专利 | 企业特征标识 | 删除定语，保留技术内容本身 |
| XX工法 / XX专利（带企业名） | 企业特征标识 | 仅保留工法/专利的技术名称，去企业前缀 |
| 知名 / 著名 / 标杆 | 主体暗示 | 删除 |
| 三标一体 / AAA级 / ISO9001（带主体名） | 资质炫耀式 | 仅在商务标明标呈现，暗标删除 |

> 注意：中性技术词（如"施工""设计""管理"）本身不泄漏，仅当与主体代词/荣誉绑定才危险。
> 扫描仪应优先用 `--identifiers` 精确命中，启发式仅作补充告警。

## 二、文档元数据清零清单

Word 文档的以下属性极易残留投标人信息，必须在封装前清零：

- `docProps/core.xml`：`dc:creator`（作者）、`cp:lastModifiedBy`（最后修改人）、`dc:title`
- `docProps/app.xml`：`Company`（公司）、`Manager`
- 建议统一置空或填入"投标人"（若系统要求非空）。

> `scan_docx.py` 已自动读取上述字段；若非空即标记 🔴，并给出"文件→信息→检查文档→删除属性"或脚本批量清零的修订指令。

## 三、图像 / 表格中的隐藏标识（专项检查维度）

暗标中图片与表格是高频违规点，多数需**人工复核**（脚本无法看像素）。Step 4 应主动提示用户逐项自查：

- **图片内嵌文字**：图片中是否含公司名称/Logo（需 OCR，标"人工复核"）。
- **图片 EXIF/XMP**：拍摄者、单位、GPS 等信息（需 ExifTool，标"人工复核"）。
- **表格边框颜色**：是否为黑色（部分项目要求；彩色边框 🟡）。
- **表格内字体**：是否与正文一致（部分项目"图表内字体不作要求"则跳过该检查）。
- **图片水印**：可见/不可见水印（含软件生成的水印）。
- **图签栏**：施工图/附图中的设计单位、施工单位签章栏（🔴 废标级，必须去标识）。
- **修订痕迹**：Word"修订模式"未接受/未拒绝，露出批注者姓名（🔴）。
- **超链接**：从网页复制带入的蓝色超链接（🟡，须改黑或取消）。

> 处理建议：暗标附图一律去标识后重绘或裁剪；关闭修订模式并"接受所有更改"再另存；
> EXIF 用 ExifTool（`exiftool -all= 图片` 批量清除）清理。脚本对图片维度只提醒、不判定。

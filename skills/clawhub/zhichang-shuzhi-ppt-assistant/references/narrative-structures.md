# PPT 叙事结构库

## 1. 述职/转正型

适用场景: 试用期述职、转正汇报

叙事主线:
```
我面对的问题 → 我如何理解问题 → 我做了什么 → 我形成了什么成果 → 成果的价值 → 后续如何推进 → 我可以承担什么角色
```

各页结构建议:

| 页序 | 页面标题范例 | 核心表达 |
|------|-------------|----------|
| 1 | 封面 | 姓名 + 岗位 + 汇报类型 + 日期 |
| 2 | 我的工作范围与角色 | 入职以来的职责边界和角色定位 |
| 3 | 入职时面对的关键问题 | 客观陈述挑战，不抱怨前任或现状 |
| 4 | 我对问题的结构化理解 | 展示分析框架，体现思考深度 |
| 5 | 我的核心工作实践 (1) | 具体做了什么，用了什么方法 |
| 6 | 我的核心工作实践 (2) | 推进过程中的关键决策和调整 |
| 7 | 阶段成果与产出物 | 已形成的文档、流程、系统、标准等 |
| 8 | 业务价值与组织贡献 | 这些成果解决了什么问题，带来什么改变 |
| 9 | 个人成长与方法沉淀 | 能力成长 + 可复用的方法沉淀 |
| 10 | 后续工作规划 | 短期 + 中期规划 |
| 11 | 总结与期望角色 | 自然引出可承担的更大责任 |
| 12 | 附录: 关键产出物清单 | 支撑材料 |

注意事项:
- 不要写成流水账
- 用「我理解到...」而非「我发现...」
- 成果要有具体产出物名称，不能只是「提升了效率」
- 价值要有对比: 之前什么样 → 现在什么样

## 2. 项目汇报型

适用场景: 项目阶段汇报、Milestone 汇报

叙事主线:
```
项目背景 → 项目目标 → 当前进展 → 核心成果 → 问题与风险 → 下阶段计划 → 需要确认事项
```

各页结构建议:

| 页序 | 页面标题范例 | 核心表达 |
|------|-------------|----------|
| 1 | 封面 | 项目名称 + 汇报阶段 + 日期 |
| 2 | 项目背景与目标 | 为什么做 + 要达成什么 |
| 3 | 整体进展概览 | 一页看清整体状态 (用进度条/甘特图) |
| 4 | 本阶段核心成果 | 交付了什么，不是做了什么 |
| 5 | 关键里程碑达成情况 | 对照计划，逐项确认 |
| 6 | 当前问题与风险 | 问题描述 + 影响 + 应对措施 |
| 7 | 下阶段工作计划 | 做什么 + 谁做 + 什么时候完成 |
| 8 | 资源与支持需求 | 需要什么资源/决策支持 |
| 9 | 总结与待确认事项 | 明确列出需要领导拍板的事 |

注意事项:
- 进度状态用颜色区分: 正常(绿) / 有风险(黄) / 延期(红)
- 问题必须带应对方案，不要只抛问题
- 待确认事项要具体: 确认什么 + 截止时间 + 不确认的后果

## 3. 方案说服型

适用场景: 方案汇报、新项目立项、改进提案

叙事主线:
```
当前痛点 → 为什么原方式不够 → 新方案是什么 → 新方案如何落地 → 新方案的价值 → 风险与边界 → 决策建议
```

各页结构建议:

| 页序 | 页面标题范例 | 核心表达 |
|------|-------------|----------|
| 1 | 封面 | 方案名称 + 提案人 + 日期 |
| 2 | 当前现状与痛点 | 客观描述问题，用数据说话 |
| 3 | 原有方式的局限 | 不是否定过去，而是说明条件变化 |
| 4 | 方案概述 | 一句话说清新方案核心理念 |
| 5 | 方案详细设计 | 分模块展示方案结构 |
| 6 | 落地路径与节奏 | 怎么分步走，每个阶段的目标 |
| 7 | 预期价值与收益 | 量化收益 + 定性收益 |
| 8 | 风险分析与对策 | 可能出问题的地方 + 怎么防范 |
| 9 | 投入产出分析 | 需要什么投入 + 能得到什么 |
| 10 | 决策建议与下一步 | 建议做什么决策 + 下一步动作 |

注意事项:
- 痛点描述必须客观，不能像抱怨
- 方案对比要用表格 (现有方案 vs 新方案)
- 价值必须量化 (哪怕用区间估算)
- 必须有风险分析，这是建立信任的关键
- 决策建议要给出选项 A/B/C，附推荐理由

## 4. 复盘型

适用场景: 项目复盘、事故复盘、季度复盘

叙事主线:
```
目标回顾 → 实际结果 → 差距分析 → 原因拆解 → 经验沉淀 → 改进机制 → 下一次怎么做
```

各页结构建议:

| 页序 | 页面标题范例 | 核心表达 |
|------|-------------|----------|
| 1 | 封面 | 复盘对象 + 复盘时间 + 参与人 |
| 2 | 复盘范围与目标回顾 | 回顾当初的目标是什么 |
| 3 | 实际结果呈现 | 用数据展示实际结果 |
| 4 | 目标 vs 实际差距 | 哪些达成、哪些未达成 |
| 5 | 成功要素分析 | 做得好的地方 + 为什么好 |
| 6 | 问题根因分析 | 做得不好的地方 + 根本原因 |
| 7 | 关键经验沉淀 | 可以复用的经验和教训 |
| 8 | 改进措施与责任人 | 每个改进项 + 负责人 + 时间 |
| 9 | 下一次行动指南 | 下次遇到类似情况怎么做的 checklist |

注意事项:
- 复盘不是追责，不要点名批评
- 原因分析要深挖根本原因 (至少问 3 个 why)
- 经验要可操作，不能是「加强沟通」这种废话
- 改进措施要有 owner 和 deadline

## 5. 规划型

适用场景: 年度规划、季度规划、部门规划

叙事主线:
```
当前阶段判断 → 目标状态 → 核心路径 → 阶段计划 → 资源与机制 → 风险控制 → 成功标准
```

各页结构建议:

| 页序 | 页面标题范例 | 核心表达 |
|------|-------------|----------|
| 1 | 封面 | 规划名称 + 规划周期 + 日期 |
| 2 | 当前阶段判断 | 我们现在在哪里，外部环境是什么 |
| 3 | 目标状态描述 | 我们希望到达哪里 |
| 4 | 核心策略与路径 | 怎么从 A 到 B 的大逻辑 |
| 5 | 阶段性计划 | 分几个阶段，每个阶段做什么 |
| 6 | 关键里程碑 | 什么时间点要达到什么状态 |
| 7 | 资源需求与组织保障 | 需要什么人、多少钱、什么机制 |
| 8 | 风险预判与预案 | 可能遇到什么问题 + 怎么办 |
| 9 | 成功标准与衡量方式 | 怎么知道我们做成了 |
| 10 | 下一步启动事项 | 现在就要开始做的 3 件事 |

注意事项:
- 规划要有取舍，不能什么都想要 (用 must/should/could 分级)
- 里程碑必须可验证 (不能说「完成优化」，要说「XX 指标从 A 提升到 B」)
- 资源需求要诚实，不要为了获批而低估
- 成功标准要和上级对齐

# 二次元角色设定卡 (ym-anime-character-sheet)

生成可直接用于写文、跑团、约稿的二次元角色设定卡。每张卡强制包含矛盾特质、能力代价、张力关系三件套，并跑一遍内部一致性自检，确保角色能驱动剧情而不是纸片人。设定卡交付后用户可直接拿去写文、做跑团人物卡，或作为画师约稿的需求文档，不需要再二次加工。

## 何时使用

- 用户说「角色设定」「人设卡」「OC设定」「角色档案」，或贴了设定片段要补全时
- 用户要写文、做跑团角色、给画师约稿，需要一份结构完整、可直接用的角色资料时
- 用户给了一个名字或一句话，要求据此生成完整人设时
- 用户已有剧情大纲，需要反推某个角色的人设补丁时

## 运行前提

- 依赖：纯文本生成，无第三方依赖、不联网、不读取本地文件
- 不生成图片、不生成画图提示词（那是画图工具的职责，本技能只产出文字设定）
- 若用户已提供设定卡片段，直接基于该片段补全，不推倒重写
- 不调用任何脚本，所有校验由模型按 `references/design-checklist.md` 逐项完成

## 输入契约

| 项 | 必需 | 说明 |
|---|---|---|
| 角色名 | 可选 | 用户给则沿用；不给则起一个原创、易读、不与知名角色撞名的名字，并附读音 |
| 定位 | 可选 | 主角 / 配角 / 反派 / 路人，默认主角；定位影响戏份与弧线深度 |
| 世界观类型 | 可选 | 异世界 / 校园 / 科幻 / 武侠 / 现代 等；决定能力体系与服装合理性 |
| 丰富度 | 可选 | 快速版半页 / 完整版一页以上；默认完整版 |

**缺失处理：** 任一项缺失均按默认值处理，并在输出开头注明「以下字段为默认假设：【缺失的字段名】」。不中止生成，但假设项必须能被用户一眼识别，方便后续替换。若用户随后补全了某项，仅重生成对应章节并重跑相关自检条目，不整卡推翻。

## 执行步骤

1. **确定骨架** — 先定角色名、定位、世界观类型、丰富度。名字未给时生成原创名，命名后立即自查 `references/design-checklist.md` 第 10 条（撞名检查），与知名角色近似当场改名。

2. **逐节生成** — 严格按 `templates/character-card.md` 的章节顺序产出，每一节都不能空：
   - 基本信息：姓名含读音标注、年龄、身高、生日
   - 外貌：至少 3 处可画辨识点，描述到画师能直接下笔
   - 性格：必须含至少一组矛盾特质，并写明矛盾在何种情境下暴露
   - 能力：每条能力必须配对等价弱点或代价，强度与世界观上限对齐
   - 口头禅与语言习惯：含称呼方式，标注适用与慎用场景
   - 服装：日常 / 正式 / 战斗三套，战斗套注明可画元素
   - 成长弧线：起点状态 → 触发事件 → 终点状态
   - 关系网：至少 2 组关系，其中 1 组必须是张力关系

3. **强制三件套校验** — 生成后逐条确认：①有矛盾特质 ②能力有等价代价 ③关系网含张力关系。缺任意一项当场补写，不交付半成品。这三件套是「能写故事的设定」和「纸片人」的区别：没有矛盾特质写不出冲突，没有代价战力会崩，没有张力关系剧情起不了浪。

4. **跑自检清单** — 套 `references/design-checklist.md` 的 10 条逐项判定，每条给「通过 / 不通过 / 已修正」，并说明修正动作。自检结论附在卡末尾，方便用户一眼看到哪里改过。

5. **输出交付** — 完整设定卡加自检结论一并返回。快速版可省略服装三套细节，但三件套与 10 条自检不可省。若用户后续要改某节，局部重生成后重跑受影响的自检条目即可，不必整卡重来。

## 各节写法要点

- 基本信息：读音标注避免多音字误读；生日可带星座辅助记忆，但非必需
- 外貌：辨识点要具体可画（发色 / 瞳色 / 疤痕 / 配饰 / 站姿），避免「好看」「帅气」这类不可画词
- 性格：矛盾特质是本技能红线，例如「待人温和但对触犯底线的事零容忍」，必须说明暴露时机（平时藏得住、踩线才翻脸）
- 能力：代价必须与能力强度对等，禁止「无敌但偶尔乏力」式伪代价
- 口头禅：给生活化例句，标注在悲伤 / 战斗等场景是否合适
- 服装：三套区分清晰，战斗套列出可加特效的元素
- 成长弧线：触发事件必须具体，禁止「经历变故后成长」这种空话
- 关系网：张力关系写清类型与冲突来源，避免全是盟友

## 三件套强制要求（不可省略）

矛盾特质、能力代价、张力关系是本技能的三件套，任何一件套缺失都视为生成失败，必须当场补写：

- 矛盾特质：不是「有点小脾气」这种点缀，而是能制造剧情冲突的对立面。例如「表面乐天，实则极度怕被抛下，所以会用控制欲掩盖不安」。要写清它在什么情境下暴露、暴露后角色怎么做。
- 能力代价：代价要与能力强度对等，且是真正限制而非装饰。判断标准——如果去掉代价，这个能力是否立刻变成无解外挂；是，则代价不够。
- 张力关系：关系网里至少有一组是竞争、亏欠或立场对立。张力是剧情的发动机，纯盟友关系写不出故事。张力方要写清冲突来源，而不是只写「他们是敌人」。

## 输出格式

Markdown 设定卡，章节与 `templates/character-card.md` 对齐。结尾附自检结论块：

```
### 自检结论
- [01 名字易读易搜] 通过
- [02 年龄外貌一致] 已修正（重对齐身高与年龄）
- [03 能力有代价] 通过
- ……共 10 条
- [10 撞名检查] 通过（库内比对无重复）
```

## 验收用例

- 正常：给「异世界反派、完整版」→ 含矛盾特质、能力有代价、关系网含张力关系、10 条自检全过
- 边界：只给名字不给其他 → 按默认值生成完整版，开头标注默认假设项
- 失败：名字与知名角色撞名 → 自检第 10 条不通过，当场改名并说明

## 能力边界

- 不画图、不生成图片提示词（那是画图工具的事）
- 不写完整小说，只做设定
- 不保证角色被市场或读者喜欢，不做商业判断
- 不替用户决定剧情走向，只提供可驱动剧情的设定材料
- 不跨次保存用户角色库（除非用户明确要求导出）

## 常见坑

1. **人设完美无缺点导致没戏可写** — 现象：角色又强又温柔又无私，编剧找不到冲突点。原因：把「讨喜」当成「能推动剧情」。规避：性格节必须写至少一组矛盾特质（如温和但对底线零容忍），并在关系网制造张力。
2. **口头禅在严肃场景穿帮** — 现象：战斗高潮角色还在说卖萌口头禅，出戏。原因：口头禅没标注适用情绪。规避：口头禅节写清「适合场景 / 慎用于场景」，并给 2 个以上情绪场景例句。
3. **名字用了知名角色被判定蹭 IP** — 现象：起名借用热度高的名字风格，约稿或发布被拒。原因：图省事。规避：自检第 10 条强制比对，起原创名并标读音（如 凛·艾尔维斯 Lín Aì'ěrwéisī）。
4. **能力越写越强收不回来** — 现象：后期战力崩坏，弱点击穿世界观。原因：只加能力不加代价。规避：能力节每条配对等价弱点或代价，强度与世界观上限对齐。
5. **关系网全是朋友没冲突** — 现象：人际关系一片祥和，剧情无法起浪。原因：只列「好友」。规避：关系网至少 2 组且含 1 组张力（竞争 / 亏欠 / 立场对立），张力方写明冲突来源。
6. **外貌辨识点不够画师参考** — 现象：画师追问发色配饰。原因：外貌只写「很漂亮」。规避：外貌节至少 3 处可画点，服装三套标注可画元素。

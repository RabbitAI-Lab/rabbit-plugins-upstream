# 端云协同架构（V7 核心）

> V7 在 V6「Hybrid AI 端云协同」基础上的精确化定义。

## 1. 设计哲学

### 1.1 核心理念

> "大模型擅长创意决策（故事编排、字幕撰写、节奏把控），但把解码、抽帧、多模态理解这类视频素材的'重活'——交给 AI PC 本地算力来处理，才是最高效、最经济、最安全的方案。这就是「端云协同」的核心理念。"

### 1.2 教学场景类比

| 维度 | 云端（轻决策） | 端侧（重计算） |
|------|----------------|----------------|
| **类比：视频剪辑** | 故事编排、字幕撰写、节奏把控 | 解码、抽帧、多模态理解 |
| **类比：教学** | 课程设计 Prompt、教学策略、跨学科关联 | OCR 扫描、ASR 转写、TTS 合成、统计 |
| **数据流向** | 只接收抽象元数据 | 原始数据 + 元数据生成 |
| **推理位置** | LLM 大模型 | OpenVINO 小模型 + NPU |

### 1.3 6 步标准流程

```
Step 1 [端侧预处理]    OCR/ASR/RAG 在 NPU 推理 → 提取结构化数据
        ↓
Step 2 [端侧脱敏]      PII 检测 → 自动脱敏（身份证/手机/姓名）
        ↓
Step 3 [端侧抽象化]    数据压缩为元数据（标签/向量/统计）< 10KB
        ↓
Step 4 [云端决策]      只发送元数据 → LLM 创意决策
        ↓
Step 5 [端侧执行]      云端返回决策 → 端侧 NPU 生成最终交付物
        ↓
Step 6 [端侧审计]      记录所有端云交互 → 零上传证明 + 成本统计
```

## 2. 端云协同 4 大优势

### 2.1 隐私保护（Privacy First）
- **V6**：离线优先（数据可上云）
- **V7**：原始数据零上传（只传抽象元数据）
- **量化**：**100% 原始数据本地化**

### 2.2 云端成本（Cost Down）
- **V6**：中等（中等体积数据传输）
- **V7**：元数据级交互（< 10KB/请求）
- **量化**：**降低 80%**（以 GPT-4o 为例，每请求从 $0.05 → $0.001）

### 2.3 响应速度（Speed Up）
- **V6**：取决于网络
- **V7**：本地决策 100ms 内
- **量化**：**10x 提速**（本地决策 vs 纯云端）

### 2.4 教学创新（Innovation）
- **V6**：工具齐全
- **V7**：端云协同 + 跨学科教学
- **量化**：**AI PC 教学新场景**

## 3. V6 vs V7 架构对比

| 维度 | V6 Hybrid AI 端云协同 | V7 端云协同架构 |
|------|---------------------|-----------------|
| 分工粒度 | 粗粒度（按能力） | **细粒度（按任务）** |
| 数据流 | 可双向 | **单向：端→云（仅元数据）** |
| 隐私等级 | 离线优先 | **零上传证明** |

## 4. 端云协同 4 类决策

V7 把所有云端决策分为 4 类，每类有不同的端云分工：

### 4.1 创意型决策（Creative）
- **代表**：教学故事编排、课件脚本撰写、跨学科关联推理
- **云端负载**：高（需要 LLM 创造力）
- **端侧准备**：抽象化教学目标 + 学情标签
- **示例**：生成《岳阳楼记》跨学科课件（语文+历史+地理）

### 4.2 分析型决策（Analytical）
- **代表**：学情诊断、错题归因、改进建议
- **云端负载**：中（需要数据洞察）
- **端侧准备**：统计数据 + 标签化错题
- **示例**：基于 40 人成绩数据生成诊断报告

### 4.3 教育型决策（Educational）
- **代表**：学习路径规划、教学策略推荐、个性化推荐
- **云端负载**：中（需要教育专业性）
- **端侧准备**：学生画像 + 学习历史
- **示例**：为零基础产品经理推荐 3 个月 AI 学习路径

### 4.4 策略型决策（Strategic）
- **代表**：教学方向决策、课程结构优化、跨学科项目设计
- **云端负载**：高（需要全局视野）
- **端侧准备**：多维度元数据
- **示例**：学校 AI 教学 5 年规划

## 5. 端云协同实战案例

### 案例 1：试卷智能批改
```
[端侧 NPU] OCR 扫描试卷 → 提取学生答案（< 200ms）
[端侧脱敏] 学生姓名 → 学生编号 A001
[端侧抽象化] 答案文本 → 错题标签 + 知识点标签（< 5KB）
[云端] 上传错题标签 → LLM 生成错题讲解 + 知识点关联
[端侧] 接收讲解 → p5.js 生成个性化错题本
[端侧审计] 零上传证明 · 成本 $0.0003
```

### 案例 2：课堂录音分析
```
[端侧 NPU] ASR 转写课堂录音（30 分钟）→ 文本（< 2s）
[端侧] 提取关键词 + 互动次数 + 教师提问数
[端侧抽象化] 课堂摘要 + 标签（< 3KB）
[云端] 上传课堂摘要 → LLM 生成教学反思
[端侧] 接收反思 → 写入教师档案
[端侧审计] 原始录音本地保留 7 天 → 自动清理
```

### 案例 3：跨学科课件生成
```
[端侧 NPU] OCR 扫描《岳阳楼记》课文 + 注释
[端侧] 提取关键事件 + 地理坐标 + 历史时间线
[云端] 上传元数据 → LLM 设计跨学科教学方案
       （语文修辞 + 宋代历史 + 洞庭湖地理）
[端侧] p5.js 生成互动课件 + 多角色配音
[端侧审计] 零上传证明 · 成本 $0.0008
```

## 6.5 文本推理工作流的端云分工（v7.2 升级补充）

> 本节为 v7.2 引入 `scripts/edge_cloud_dispatch.py` 后新增，由 upgrade-ailiteracy-textreason-workflow spec 提供。

| 维度 | ai-literacy（文本推理 1.5B） |
|---|---|
| 端侧重计算 | 文本切片 + 推理蒸馏（DeepSeek-R1-1.5B） |
| 云端轻决策 | 教学策略 / 学习路径 |
| JSON 契约 | abstract_data ↔ decision（V7 edge-cloud-protocol v1.0） |
| 规则层容错 | `scripts/lesson_plan_guard.py` |
| 硬件调度 | CPU + iGPU 异构（1.5B INT4） |

**为什么 1.5B 文本模型适合本地推理**：

1. **参数量轻**：1.5B INT4 量化后约 1GB 显存，纯 CPU 即可承载，适合 AI PC 端侧部署。
2. **量化策略优**：DeepSeek-R1-Distill 是 Qwen-1.5B 的蒸馏版本，已经针对推理任务做知识蒸馏，在 INT4 量化下仍保持较好精度。
3. **任务形态适配**：文本推理是"1 段输入 → 1 段输出"的流式任务，适合 NPU/iGPU 并行处理长课程材料。

正是基于这 3 点特性，本工作流把"重活端侧做"具象化为"1.5B 文本推理"，把"决策云端做"具象化为"教学策略编排"，并通过 V7 edge-cloud-protocol v1.0 的 6 段 JSON 契约做接缝。

# 第三部分：帮助老师备课 · AI 协作备课工作流（参考）

> 本文对应课程大纲「第三部分」与最佳实践文档《AI 协作备课工作流：从课程体系设计到内容交付的最佳实践》。
> 原文链接：https://bytedance.larkoffice.com/docx/QoljdFDBAouTFCx3L7JcVw3RnKe
>
> 本手册把「用 TRAE Work，1 个人就能写完一整套课程」的人 + AI 协作方法论系统化，专门帮教师用 AI（TRAE Work / SOLO / 其他 Agent）**从零搭建一整套结构化课程**。是 SKILL.md 第三部分「AI 协作备课」的展开手册。

## 一、这份工作流解决备课最头疼的三件事

1. **省时间**：不用再花 40+ 小时死磕，把 AI 从"会跑偏的写手"变成"守规矩的执行者"。
2. **保一致**：多节课术语统一、不重复不越界、读起来像一个人写的（统一隐喻、统一框架）。
3. **易适配**：跨专业换案例不用重做全课（用"约束文件 + 占位符"实现案例热插拔）。

## 二、核心理念：人做 Architect，AI 做 Executor

- **老师的价值不在"写"，而在"判断"**——定方向、把边界、判好坏、做取舍，剩下的交给 AI。
- **Architect 本质**：人是"知道要什么的人"，提供全局图景、判断对错、定义验收、做取舍决策。
- **Executor 本质**：AI 负责展开、执行、初稿生成；不做最终判断。
- **自证性**：用课程中教的 AI 协作法（V3 C 模块）来开发课程本身——需求拆解、验证闭环、多 Agent 协作、复盘沉淀。
- **协作姿态**：所有框架/大纲/边界决策均通过"人给直觉 → AI 结构化 → 人修正 → 落盘"产生。

## 三、三层治理体系（文件结构）

把整套课程的资料组织成三层文件夹，**上层冻结后只读，下层执行**：

| 层级 | 文件 | 职责 |
|------|------|------|
| **第一层 · 全局结构** | `课程大纲.md` | 模块划分、课程编排、受众假设、跨模块一致性 |
| **第二层 · 模块约束** | `模块X-共性约束.md`、`横评Agent启动Prompt.md` | 边界规则、首讲权表、引用规则、风格、红线 |
| **第三层 · 课程执行** | `各课/交付要求.md`、`各课/进度.md`、`各课/课程内容文档.md`、`各课/PPT页面稿与逐字稿.md` | 每课的具体交付物与跨 session 记忆 |

- 上两层也是人机讨论的产出（人提直觉 → AI 结构化 → 人修正 → 落盘），不是 AI 自动生成。
- 下层是 AI 主导生产、人工 Review 迭代。

## 四、三阶段生产流水线（每课走一遍）

每节课严格走以下三阶段，**阶段一未获"方向确认"不写正文**：

| 阶段 | 目标 | 动作 | 退出条件 |
|------|------|------|----------|
| **一·探索与对齐** | 锁方向 | 多轮讨论 + AI 搜索 + 人工拍板 | 人工说"方向确认" |
| **二·内容创作** | 产内容 | AI 初稿 → 人工 Review → 迭代 | 人工说"内容 OK" |
| **三·PPT + 逐字稿** | 授课材 | AI 转化（内容→PPT + 逐字稿）→ 人工 Review | 人工最终确认 |

- 阶段可回退（写完发现方向错，回到阶段一重新对齐）。
- 产物即时落盘（每阶段产物直接覆盖原文件，不存版本副本）。
- 阶段一"发散"（多想几个方向），阶段二"收敛"（锁定方向深耕）。

## 五、六大核心机制（关键抓手）

| # | 机制 | 解决问题 | 用法 / 模板 | 案例效果 |
|---|------|----------|-------------|----------|
| 1 | **约束文件体系** | AI 无全局视野 / 不自律 | `共性约束.md` 含边界规则、首讲权表、引用规则、风格、红线 | 无约束时 A1/A2 重复讲"下一词预测"；有约束后 A1 只提名称，A2 展开 |
| 2 | **进度文件** | AI 无跨 session 记忆 | `进度.md` 记阶段、决策、待解；Agent 启动**先读** | 换人接手读文件 5 分钟接上 |
| 3 | **横评 Agent** | 看起来对但差 / 不一致 | 只读 Agent 读全部 → 输出 6 维度报告（重复 / 边界 / 衔接 / 均衡 / 一致 / 建议），分级 🔴🟡🟢 | 独立审计发现跨课矛盾 |
| 4 | **Demo 热插拔** | 跨专业适配成本高 | 骨架通用 + 插槽：`实操库/CS方向/`、`实操库/通用方向/` + 引导文档 | 新增方向仅加文件夹，主线不变 |
| 5 | **前置阅读链** | 后课引前课不一致 | `交付要求.md` 列必读前课文件列表 | C3 引 A2 用原始表述不改写 |
| 6 | **结构化产出 + 即时落盘** | 版本混乱（v3-final 噩梦） | 单文件覆盖式更新，历史决策存 `进度.md` | 无版本号乱象 |

> 注：以上为基于课程体系的归纳，落地细节建议结合上方飞书原始文档。

## 六、工作流全景：Phase 1–4（模块级）

以一个模块（如 A 模块 3 课）的完整生命周期为例：

```text
Phase 1 · 体系设计（人主导）
  写大纲框架 → 课程大纲.md → 模块共性约束.md → 各课交付要求.md
        ↓ 锁框架
Phase 2 · 并行生产（AI 主导）
  A1 / A2 / A3 各走「三阶段流水线」，可并行
        ↓ 全部内容 OK
Phase 3 · 横向审计（独立审）
  启横评 Agent → 读全部文件 → 出 6 维度报告 → 人工定优先级 → 出修改指令 → AI 执行
        ↓ 审计通过
Phase 4 · Demo 扩展
  标杆 Demo（CS 方向 / 通用方向各一份）+ 引导文档，供其他学科教师复用
```

- Phase 1 锁方向；Phase 2 并行提效；Phase 3 独立审保一致；Phase 4 可复用。
- 模块越多，Phase 3 的收益越大（防止跨课漂移）。

## 七、实践优先级 P0–P3（最小可用版）

不必一次做到位，按优先级逐步采纳：

| 级别 | 动作 | 耗时 | 何时做 |
|------|------|------|--------|
| **P0** | 与 AI 对话产出并冻结 1 页"约束文件" | ~30 min | 启动任何课程前 |
| **P1** | 每次对话结束更新 `进度.md` | ~2 min / 次 | 每次与 AI 协作后 |
| **P2** | 严格分"对齐（阶段一）"与"写作（阶段二）" | 0 成本 | 与 AI 协作的每次任务 |
| **P3** | 每 3–5 课做一次横评（人工或 Agent） | ~1 h | 模块完成或阶段节点 |

> 起步只需 P0+P1，就能避免"AI 跑偏""session 失忆"两大最常见坑。

## 八、关键心智模型

- **价值在判断不在写**：人最大的价值是判断（取舍、对错、优先级），不是动手写。
- **文件是 Agent 唯一可靠介质**：跨 session / 跨人协作，文件是唯一可靠的记忆与交接载体。
- **讨论产出 ≠ 固化约束**：与 AI 讨论出的好点子，必须落盘为 `共性约束.md` 才会持续生效。
- **审查与创作分离**：写内容的 Agent 与审内容的 Agent 必须是不同视角（横评 Agent 价值）。
- **锁框架开内容**：方向与边界（Phase 1）锁定前，不进入内容创作（Phase 2）。
- **先方向后动笔**：阶段一未确认方向，绝不进入阶段二。

## 九、常见坑与解法

| 坑 | 解法 |
|----|------|
| 没约束就开写 | 先与 AI 对话产出 5 条核心约束（边界 / 风格 / 红线 / 受众 / 深度），冻结为 `共性约束.md` |
| 跳过阶段一直接写正文 | 强制"方向确认"作为阶段二的前置条件 |
| 不做横评 | 每 3–5 课做一次（人工读全部文件即可，~1 h） |
| Demo 锁死只能本专业用 | 用"骨架 + 插槽"热插拔；不同方向独立文件夹 |
| 不更新进度 | 每对话结束用 2 分钟更新 `进度.md`，决策即落盘 |
| 文件版本乱（v3-final） | 单文件覆盖更新，禁版本副本；历史决策进 `进度.md` |

## 十、30 分钟最小落地清单（给想立刻开课的老师）

1. 选定要讲的单元（建议从 A3 协作哲学 + C 系列方法论起步）。
2. 套用本技能的 `references/` 参考文档作为内容骨架。
3. 打开对应单元的 PPT（截图版，含逐字稿）作为授课底稿。
4. 用"约束文件"统一术语（Architect / Executor、飞轮、锯齿边界、施工图纸）。
5. 选 1 个专业案例，做 Demo 热插拔。
6. 用阶段一"决策点 + 待确认项"清单做最后校准。
7. 每次与 AI 协作结束，用 2 分钟更新 `进度.md`。

## 十一、适用场景扩展

本方法论同样适用于（除高校课程外）：

- 企业培训体系搭建
- 技术文档体系（如 API 文档、SDK 手册）
- 系列内容创作（如系列专栏、系列教程）
- 多人协作知识库

共性特征：**量大、结构化、多协作、高一致**——正是 AI 协作备课方法论最能放大价值的场景。

## 十二、与 V3 其他模块的衔接

- **备课本身 = 一次 Architect 工作流**：拆解课程（C2）→ 验证内容准确性（C3）→ 多 Agent 协作生成（C4）→ 沉淀为可复用模板（C5）。
- **C1 Prompt 工程**：阶段一"方向对齐"的多轮对话即 Prompt 工程的实战。
- **C2 需求拆解**：三层治理体系与"交付要求.md"是需求拆解的产物。
- **C4 验证闭环**：横评 Agent 的 6 维度报告是验证闭环的实例化。
- **C5 Rules / 横评审查**："约束文件"本质是 C5 第 1 级 Rules 在课程开发场景的应用；"横评审查"是 C4 交叉审查的变体。
- **p5.js 课件输出规则**：本手册产出的"PPT 页面稿 + 逐字稿"可直接喂给 V3 的 p5.js 课件生成能力（详见 `references/p5js-courseware-guide.md`）。

## 十三、教学模式适配参考（V7 新增）

> 本系统定义了五种教学模式（详见 `references/interactive-lesson-builder-guide.md` §二·附），备课工作流需根据所选模式进行适配。

### 五种模式下的备课工作流适配

| 教学模式 | 阶段一（探索与对齐）增量 | 阶段二（内容创作）增量 | 阶段三（PPT + 逐字稿）增量 |
|----------|--------------------------|------------------------|------------------------------|
| **讲授模式** | 确认讲授逻辑线（导入→讲授→互动→总结） | 按线性结构生成教案正文 | 标准 PPT + 完整逐字稿 |
| **探究模式** | 确认核心驱动问题 + 探究路径 | 生成探究任务链 + 引导问题集 + 假设验证工作单 | PPT 以问题页为主轴 + 引导话术替代逐字稿 |
| **协作模式** | 确认分组策略 + 协作目标 | 生成分组任务卡 + 角色分工 + 互评量规 | PPT 含分组指令页 + 汇报模板页 |
| **翻转模式** | 确认课前/课中/课后时间分配 | 分三段生成：预习材料 + 课堂活动 + 课后巩固 | PPT 仅用于课中 + 课前材料独立 PDF |
| **项目模式** | 确认项目主题 + 里程碑节点 | 生成项目 brief + 阶段任务 + 评价标准 | PPT 改为项目启动演示 + 里程碑可视化 |

### 教学模式选择时机

- 在阶段一"探索与对齐"中，与受众确认、模块选择同步完成
- 教学模式一旦确定，约束文件中需记录模式选择及其对产出格式的要求
- 阶段二的内容创作严格遵循所选模式的产出规范

## 十四、流程阶段统一映射（V7 新增）

> 本系统中存在三套流程阶段划分，以下映射表统一对齐，确保跨模块协作时语义一致。

### 三套流程对照表

| 备课工作流（3 阶段） | 交互式问答备课（5 阶段） | 评估流程（5 阶段） | 核心任务 |
|----------------------|--------------------------|---------------------|----------|
| **阶段一 · 探索与对齐**（锁方向） | Phase 1 · 受众确认 | Phase 1 · 模块确认 | 明确"为谁、学什么" |
| | Phase 2 · 模块选择 | Phase 2 · 难度确认 | 明确"学哪些、什么深度" |
| | Phase 3 · 粒度确认 + 教学模式选择 | Phase 3 · 题量确认 | 明确"范围多大、多少量" |
| **阶段二 · 内容创作**（产内容） | Phase 4 · 内容生成 | Phase 4 · 测评执行 | 核心生产/执行环节 |
| **阶段三 · PPT + 逐字稿**（授课材） | Phase 5 · 文档生成 + 一键下载 | Phase 5 · 评分与报告 | 最终产物交付 |

### 映射关系说明

1. **3 阶段 = 5 阶段的聚合视图**：备课工作流的"阶段一"聚合了问答备课/评估流程的前 3 个 Phase（均为需求对齐），"阶段二"对应 Phase 4（核心执行），"阶段三"对应 Phase 5（产物交付）。
2. **阶段可回退**：无论哪套流程，后续阶段发现问题均可回退至前一阶段重新对齐。
3. **评估流程可独立触发**：评估不必依赖备课流程，但评估结果可反馈至备课工作流的"阶段一"，形成闭环。
4. **教学模式贯穿全流程**：无论走哪套流程，教学模式的选择影响 Phase 4 的生成策略和 Phase 5 的产出格式。

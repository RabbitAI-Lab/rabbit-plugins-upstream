# Risk Dependency Schema

风险、阻断、依赖需要分开判断，避免把所有问题都写成风险。

## 类型定义

| 类型 | 定义 | 示例 |
| --- | --- | --- |
| 风险 | 尚未必然发生，但可能影响项目目标 | “如果法务今天不确认，周五上线可能受影响” |
| 阻断 | 已经阻止当前工作继续推进 | “测试环境不可用，回归无法开始” |
| 依赖 | 需要其他人、部门或外部条件提供输入 | “依赖数据团队提供埋点口径” |

## Markdown 字段

| 字段 | 说明 | 缺失处理 |
| --- | --- | --- |
| 类型 | 风险、阻断、依赖 | 未提供 |
| 描述 | 事项本身 | 未提供 |
| 影响 | 对范围、进度、质量、合规或上线的影响 | 未提供 |
| 当前处理方式 | 已讨论的缓解方案或下一步 | 未提供 |
| Owner | 当前跟进人或部门 | 未提供 |
| 证据片段 | 支撑该判断的短文本证据 | 未提供 |

## 提取规则

- 只有材料明确表达影响或等待关系时，才提取为风险、阻断或依赖。
- 对“可能”“担心”“不确定”的内容，优先提取为风险或需人工确认项。
- 如果材料同时给出两个不同风险判断，保留冲突并标注“存在冲突，需人工确认”。

# 置信度呈现 Schema（v0.2 新增 · R1 配套）

协作雷达 v0.2 对每个结论标注**置信度**，把"缺上下文保守结论"显性化，强化"不编造"信任资产。

## 置信度等级

| 等级 | 含义 | 触发条件 | 呈现建议 |
| --- | --- | --- | --- |
| 高 | 材料明确陈述，无歧义 | 出现明确的"已确认/由 X 负责/下周三交付"等 | 正常展示，无需额外提示 |
| 中 | 材料可推断，但缺少直接确认 | 只有一个来源提及，或需结合上下文推断 | 标注「中置信」，附证据 |
| 低 | 材料仅暗示、模糊意向或间接提及 | "看看能不能""应该可以""可能"等弱承诺 | 标注「低置信」，**不进入正式待办**，转入「需人工确认项」 |

## JSON 字段（在每个模块项上可选附加）

```json
{
  "task": "登录模块后端开发",
  "owner": "张三",
  "ddl": "下周三",
  "confidence": "高",
  "evidence": "王经理确认登录模块开发由张三（后端）负责，下周三提测"
}
```

## 规则

- 低置信度项的 `confidence` 为 `"低"` 时，不得写入 `action_items` 正式列表，改为写入 `needs_human_confirmation`，`evidence` 填「低置信度 Owner 进入需确认」。
- 置信度由抽取阶段判定，脱敏与证据留痕仍由 `process.py enforce` 统一加固。
- 置信度不影响脱敏与冲突规则：即使高置信，PII 仍须脱敏；同任务冲突仍须标「存在冲突，需人工确认」。

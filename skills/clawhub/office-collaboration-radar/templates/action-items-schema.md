# Action Items Schema

行动项只记录材料中出现的明确任务。不要把建议、讨论方向或未确认意向改写成待办。

## Markdown 字段

| 字段 | 说明 | 缺失处理 |
| --- | --- | --- |
| 待办 | 需要完成的具体动作 | 未提供 |
| Owner | 明确负责的人或部门 | 未提供 |
| DDL | 明确日期、时间点或相对截止时间 | 未提供 |
| 交付物 | 预期产出，例如方案、清单、测试报告、上线包 | 未提供 |
| 状态 | 未开始、进行中、已完成、阻塞、未提供 | 未提供 |
| 证据片段 | 支撑该待办的短文本证据 | 未提供 |

## 提取规则

- “小王今天下班前给测试名单”可以提取 Owner、DDL、交付物。
- “测试这块看看能不能快点”不能提取为明确待办，应进入需人工确认项。
- 多 Owner 时保留原表达；无法分清责任边界时标注“存在冲突，需人工确认”。
- 相对时间如“周五”“明早”可以保留原文；不要自行换算日期，除非材料提供明确基准日期。

# 转化漏斗分析框架（Funnel Framework）

本文件定义网站获客体检的**分析维度、检查项与打分算法**。Agent 在第 4 步（逐维度漏斗分析）与第 9 步（复检打分）时读取。

## 1. 六个分析面（对应需求流程）

把转化路径拆成六个可独立分析的面，逐个找漏点：

| # | 分析面 | 对应漏斗阶段 | 核心问题 |
| --- | --- | --- | --- |
| A | 流量 | 流量入口 | 访客从哪来？落地页意图是否匹配？有无转化追踪？ |
| B | 产品 | 产品页面 | 产品/服务信息是否足以建立信任并推动留资？ |
| C | 页面 | Landing Page | 首屏是否 5 秒说清价值？移动端/速度/结构是否合格？ |
| D | CTA | CTA | 行动召唤是否显眼、文案动作导向、多次出现？ |
| E | 表单 | Form（普通 + 询盘） | 字段是否过多？校验/移动/提交文案/防垃圾是否到位？ |
| F | 历史询盘 | Lead | 历史询盘能否反推漏点（高频空字段、产品询盘占比、审核/响应效率）？ |

> 漏点定位原则：先找**最大单点泄漏**——通常是「表单字段过多」「无显眼 CTA」「无信任信号」「联系方式隐蔽」之一。优化点优先打这个漏点。

## 2. 逐面检查项

### A. 流量（Traffic）
- 是否在页脚/资源里暴露了转化追踪（UTM、GA/GTM、`FnGet*` 埋点）？
- 各流量入口（搜索/广告/社媒/直接）是否指向**意图匹配**的落地页（如广告词→对应产品页，而非首页）？
- 有无明确的转化目标与衡量（表单提交、电话、微信）？

### B. 产品（Product）
- 产品/服务是否有清晰**价值主张**（解决什么问题、给谁、差异化）？
- 是否含：图片/规格参数/应用场景/客户案例/价格或询价入口/相关推荐？
- 信息缺失导致用户无法判断是否匹配需求 → 直接流失。

### C. 页面（Landing Page）
- 首屏（above the fold）是否有：主标题（价值主张）、副标题、主 CTA、信任徽章？
- 移动端 viewport 是否存在？是否响应式？（移动占多数 B2B 流量）
- 是否有唯一 H1、合理标题层级？
- 加载体感（图片体积、外链资源）是否拖慢？

### D. CTA（行动召唤）
- CTA 是否**动作导向**文案（"获取报价"/"免费咨询"/"立即预约"）而非名词（"提交"/"联系我们"）？
- 是否出现在多处（首屏、中段、页尾、悬浮）？
- 是否用对比色/足够点击区域？是否单一主 CTA（避免选择过载）？
- 是否有二级 CTA（下载白皮书/加微信）承接不同意向用户？

### E. 表单（Form）
**普通表单**（`list_custom_form` 拿到的 `FormType=CustomForm`）与**询盘表单**（`get_enquiry_form_id`）都按以下维度审：
- **字段数**：≤5 字段转化最佳；>7 字段显著掉量。统计每个表单的可见字段数。
- **必填最小化**：仅保留留资必需字段（姓名/电话/需求），其余选填。
- **字段类型合理**：手机号用 `ValidateType=3` 并建议短信校验；邮箱 `ValidateType=6`；避免一上来要公司全称/地址等长字段。
- **占位与标签**：placeholder 给示例（"如：138xxxx"），避免空 placeholder。
- **提交按钮文案**："提交"→"立即获取方案/免费咨询"。
- **移动友好**：单选/下拉/地区三级联动在小屏可点；文件上传有状态提示。
- **防垃圾**：图形/短信验证码，但别因验证过严挡住真人。
- **隐私与授权**：是否说明"我们将尽快与您联系/信息仅用于报价"。
- **询盘表单专属**：是否带 `EnquiryProduct` 业务必填字段（产品页询盘自动带出产品名）。

> 静态 HTML 局限：询盘表单多数由 `FnGetCustomForm` 或系统询盘页动态渲染，**不会**作为静态 `<form>` 出现在公开 HTML，审计脚本也抓不到其字段数与必填规则。有 MCP 时须用 `get_enquiry_form_id` 取表单 ID，再 `get_page_info` 读取询盘页源码核对字段；无 MCP 时只提示用户到后台自查，不做臆测。

### F. 历史询盘（Historical Enquiries）
- 用 MCP `list_enquiry_records`（`status=-1` 拉全部）逐页翻完，覆盖全量样本：
  - 统计各字段**空置率**：解析每条记录 `form_info` 的可见字段「字段名称: 提交值」，找出最常留空的字段（= 用户抵触点）→ 优化时优先删/后置或改选填；
  - 统计**产品询盘占比**：汇总 `product_list`，看哪些产品被高频询盘 → 指导产品页 CTA 与询盘表单 `EnquiryProduct` 预填；
  - 结合 `Status` 看审核/跟进状态，评估线索沉淀与销售响应效率。
- 若站点没有询盘记录（新站/未开启）：在方案中标注「暂无历史询盘数据，需上线后持续观测」，不做臆测。
- 历史询盘是**分析辅助维度**（不直接计入获客分 5 个阶段分），其结论用于佐证表单优化（F10 删/后置字段）的优先级。

## 3. 打分算法（leadgen_score）

各阶段分 0–100，整站获客分 = 加权求和：

| 阶段 | 权重 | 主要信号 |
| --- | --- | --- |
| landing（页面） | 20% | H1 唯一、viewport、标题长度、首屏 CTA、HTTPS |
| cta（行动召唤） | 20% | CTA 数量、动作导向文案占比、出现位置多样性 |
| form（表单） | 25% | 字段数（少=高）、必填最小化、校验、提交文案、移动友好 |
| contact（联系） | 15% | 电话/邮箱/WhatsApp/地址显眼度 |
| trust（信任） | 20% | 资质/客户/案例/评价/合作等信任信号数量 |

`leadgen_score = 0.20*landing + 0.20*cta + 0.25*form + 0.15*contact + 0.20*trust`

各阶段分由 `scripts/leadgen_audit.py` 按脚本内启发式规则计算（见脚本 `score_*` 函数），Agent 在人工分析（§4 六面）后**可上调/下调并附理由**，但最终分需可解释。

## 4. 漏点 → 优化点映射

| 典型漏点 | 落到的阶段 | 对应优化动作（详见 optimization-playbook.md） |
| --- | --- | --- |
| 表单字段 >7 | form | 删减/后置非必要字段、必填最小化 |
| 无显眼 CTA / 文案名词化 | cta | 增强 CTA、改动作导向文案、加悬浮 CTA |
| 联系方式仅在页脚 | contact | 页头加点击拨打、Contact 区块前置 |
| 无信任信号 | trust | 追加资质/客户 logo/案例/评价区块 |
| 首屏无价值主张 | landing | 重写首屏标题、加副标题与主 CTA |
| 缺 FAQ/异议处理 | landing/trust | 新增 FAQ 区块 |
| 询盘不带产品上下文 | form | 接 `EnquiryProduct` 必填，产品页一键询盘 |
| 历史询盘高频空字段 | form | 删除/后置该字段，或改选填 |


## 5. 输出格式（给用户看的分析）

建议用一张表 + 一段结论：

```
获客分：62/100
各阶段：页面 70 · CTA 45 · 表单 40 · 联系 55 · 信任 50
最大漏点：表单字段过多（联系页 9 字段）+ 无动作导向 CTA
历史询盘：用 list_enquiry_records 拉取近 30 天询盘 38 条，手机号空置率 12%（次要），“公司地址”空置率 61%（优先删）
```

随后进入第 5 步产出 5 个优化点。

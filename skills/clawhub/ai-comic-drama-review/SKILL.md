# AI 漫剧剧本审核专家

以剧本证据为基础完成风险筛查、质量评估和可执行修改建议。保持审慎、具体、可复核，不承诺“确保过审”，不将通用审核结果冒充监管、平台或法律结论。

## 准备输入

1. 获取并完整读取剧本。支持全文、分集大纲、人物小传、分场剧本和分镜表；材料只有大纲时，将结论限定为“大纲阶段审核”。
2. 记录剧名、类型、受众、集数、单集时长、画幅、目标平台和用户指定审核规则。缺失非关键信息时继续审核，在报告中列出假设；缺少剧本正文或大纲时先向用户索取。
3. 用户提供了平台规则、内部规范或监管文件时，以其为本次专项依据，保留文件名、版本或日期。需要引用现行外部规则时先检索并核验来源，不凭记忆编造条款。
4. 将通用合规审核表述为“风险筛查”。对疑似严重违法违规、平台终审或法律判断，明确建议人工、法务或平台复核。

## 执行审核

1. 开始评分前阅读 [references/review-rubric.md](references/review-rubric.md)，严格采用其中的维度、权重、锚点评分、问题分级和结论门槛。
2. 审核剧作质量前必须阅读 [references/drama-quality.md](references/drama-quality.md)，使用专项诊断、修改处方和评分锚点，不得只凭整体观感给出“节奏慢”“人设弱”“台词尬”等抽象结论。
3. 先通读全部材料，建立人物、时间线、世界观、人物知识、核心冲突、伏笔兑现和分集钩子清单；再还原故事引擎、主线因果链、重点场景功能和情绪曲线，最后逐集逐场检查。长剧本可分批处理，但必须完成一次全局一致性复核。
4. 同时执行四条审核线：
   - 内容合规：识别疑似风险及其语境，区分作品呈现、人物行为与价值引导，避免脱离上下文机械判词。
   - 剧作质量：检查类型承诺、因果结构、场景功能、冲突升级、人物选择与关系、对白策略、信息分配、逻辑伏笔和情绪兑现。
   - 漫剧适配：检查视觉外化、画面信息、镜头调度、分集钩子和目标时长适配。
   - AI 制作：检查角色一致性、场景与资产复用、动作和表情复杂度、群像、口型、镜头可生成性及成本。
5. 每个问题必须绑定可定位证据。记录集数、场次、段落或分镜号，并短引原文；无法定位时使用“全局问题”，不得虚构原文或位置。
6. 区分三类内容：
   - **文本事实**：剧本中实际出现的内容或明确缺失的要素。
   - **审核判断**：风险、影响和评分理由，标明严重程度与置信度。
   - **修改建议**：可执行动作，必要时给出一小段改写示例，不擅自重写整部作品。
7. 对每个中、高风险剧作问题分开写明“表面症状—问题根因—观众影响—修改原则”。先判断类型承诺和作者意图，不以单一结构公式否定有效写法。
8. 剧作建议必须明确修改哪一集哪一场、哪个人物的什么行动或信息，以及保留什么、改变什么、产生什么效果。每个中、高风险问题提供最小改动方案、联动修改范围和验收标准；高风险或核心结构问题另给备选重构方案及返工代价。
9. 对同类反复出现的问题合并记录，在位置字段列出代表性实例并注明“同类问题还见于……”。不得为增加数量拆分重复问题，也不得把同一根因机械拆成多个表面问题。
10. 信息不足不等于创作缺陷。降低对应结论置信度并说明待确认项；只有文本本身缺少必要制作信息、已经影响执行时，才扣减对应适配或制作分。
11. 先完成门槛判断，再计算总分。任何严重合规风险都不得被其他维度的高分抵消。

## 编写报告

1. 将 [assets/report-template.md](assets/report-template.md) 复制到当前工作区，以报告模板为唯一内容来源编写 Markdown 报告。文件名采用 `<剧名或项目名>-审核报告.md`。
2. 替换全部 `{{占位符}}`，删除无内容的可选说明，不保留空白评分、伪造数据或模板提示。
3. 在结论页明确给出综合评分、风险等级、审核等级、是否建议进入制作，以及最重要的 3—5 条理由。
4. 按模板填写评分总览。分项得分必须能由评分细则复算，总分必须等于四个维度得分之和。
5. 按“极高、高、中、低”和制作阻断程度排序优先修改清单。先处理故事引擎、主线因果和核心动机，再处理场景、对白和局部润色；每条建议说明修改对象、动作和预期效果。
6. 为每个问题使用唯一编号：`C` 表示合规，`D` 表示剧作，`A` 表示漫剧适配，`P` 表示 AI 制作。跨维度问题只在主维度记录一次，在其他维度引用编号。
7. 在剧作质量章节完成诊断总览、因果链与场景功能分析，并按模板填写问题根因、最小改动方案、联动范围和验收标准；不得用泛泛建议代替。
8. 在分集分场清单中覆盖所有已发现问题；某维度未发现实质问题时，写明“本次材料范围内未发现明确问题”及审核限制，不强行凑问题。
9. 对高优先级问题提供针对性修改示范。剧作示范先说明修改前后的场景功能，再给最小必要改写；需要重构时同时说明备选方案、保留约束、联动影响和返工代价。
10. 在复审清单中给出可勾选、可验证的验收条件，而非重复抽象建议。至少覆盖因果复述、场景功能、人物选择、关系变化、对白目的、逻辑伏笔和修改联动。
11. 报告末尾注明审核范围、缺失材料、通用口径限制和人工复核事项。

## 生成 HTML

使用技能目录中的转换脚本，从最终 Markdown 生成同内容的独立 HTML：

```bash
python "<技能目录>/scripts/render_report.py" "<当前工作区>/<报告名>.md" --output "<当前工作区>/<报告名>.html"
```

- 脚本会检查必需章节、残留占位符和无效 HTML 输出；出现错误时先修复报告再重新生成。
- 不得通过远程 CSS、字体、脚本或图片补充报告内容。HTML 必须可离线打开、适配移动端并可打印。
- 如用户只需要报告正文，仍生成 Markdown 和 HTML 两个文件；如用户明确只要其中一种格式，遵从用户要求。

## 交付前检查

逐项确认：

- 已完整读取审核材料，结论没有超出材料范围。
- 所有评分可复算，总分、风险等级、审核等级和门槛结论一致。
- 所有问题均有编号、维度、严重度、位置、证据、影响和建议；引用与原文一致。
- 中、高风险剧作问题均区分症状与根因，提供最小改动方案、联动范围和验收标准；核心结构问题另有备选重构方案及代价。
- 剧作改写示范体现行动、选择、信息或关系的功能变化，不只是润色措辞；修改顺序符合先主干后局部。
- 优先清单、分项审核、分场清单和修改示范之间的问题编号一致。
- 未编造平台规则、法律条款、原文、集数、场次或制作参数。
- 未作出“保证过审”“绝对安全”等承诺，严重风险已标明人工复核。
- Markdown 无占位符，HTML 由该最终版本生成且脚本检查通过。

交付时简要说明审核等级、最高优先级问题和材料限制，并提供 Markdown 与 HTML 两个文件链接，不在回复中重复整份报告。

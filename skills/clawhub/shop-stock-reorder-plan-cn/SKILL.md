# 库存补货清单

将用户提供的有限库存表转成可执行、可复核的逐 SKU 补货清单。先确认表格不超过 100 行；保留用户的原始字段和值，不把建议写成事实。

## 需要的输入

每个 SKU 至少需要：`sku`、`current_stock`（现有可用库存）、`recent_sales`（近段销量）、`sales_days`（该销量覆盖天数）、`lead_time_days`（补货提前期）和 `target_stock`（目标库存）。可选 `safety_stock`（安全库存，未提供时按 0 计算）。用户可以提供 CSV、Markdown 表格或结构化数据。

缺少任一必填字段时，列出 SKU 和字段名，说明无法完成该 SKU 的建议；不要猜测销量、提前期或库存。`sales_days` 必须是大于 0 的有效数值：缺失、非数值、0 或负数时，将该 SKU 与 `sales_days` 列入无法处理项，不计算日均销量、提前期需求或补货建议。无法可靠识别的单位或重复 SKU 也应先指出并请求澄清。

## 计算与交付

对字段完整的 SKU：

1. `日均销量 = recent_sales / sales_days`。
2. `提前期需求 = 日均销量 × lead_time_days`。
3. `补货建议 = max(0, target_stock + safety_stock - current_stock)`，向上取整到整数件；若用户给出包装规格，再向上取整到包装倍数。
4. 单独标出 `current_stock < 提前期需求` 的提前期缺货风险；这是一项基于输入的推断。

交付 Markdown 表格，按补货建议从高到低列出 SKU、当前库存、日均销量、提前期需求、目标库存、安全库存、建议补货量和风险/说明。表后写明所用公式、假设、缺失字段及无法处理项。不要把“最近销量”误称为预测，也不要把 0 补货解释为没有销售。

## 范围

这是一份轻量分析清单，适合人工复核后的采购准备。对于超过 100 行、需要实时库存同步、多仓调拨、订单履约或仓储系统部署，说明边界并建议使用相应系统或拆分数据。

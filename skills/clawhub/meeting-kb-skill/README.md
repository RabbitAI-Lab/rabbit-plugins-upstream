# 跨会议知识库（meeting-kb-skill）

> **参赛作品 · SkillHub 线上挑战赛（第 1 期）**
> 主题：**让开得更简单** ｜ 基于官方「腾讯会议 Skill（tmeet）」二创

把多场分散的会议决策、结论、行动项与风险，沉淀为一个**可检索的知识库**，让"上次会怎么定的"一查即得，打通周报、复盘、面试、培训的场景边界。

---

## 为什么做这个（差异化）

赛事介绍明确点名「周报、复盘、面试、培训一气呵成」的**跨场景串联**，但当前参赛作品中**几乎没有做跨会议知识沉淀**的。知识库是"让会议资产持续可用"的关键一环，契合度与新颖度兼具，是本期值得冲奖的空旷赛道。

---

## 特性

- ✅ 多会议聚合：决策/结论/行动项/风险，每条带来源会议与章节可追溯
- ✅ **章节优先归类 + 一行一类**：依据 `## 决策` 等章节标题归类，无章节时按关键词优先级，避免一行重复归类产生噪声
- ✅ **自动去重**：全/半角、标点、大小写归一化后相同条目只保留一次
- ✅ **行动项结构化**：自动抽取负责人与截止日（DDL），便于跟进追踪
- ✅ **增强检索**：多关键词 OR/AND、类别过滤、全半角容错、命中高亮、JSON 输出
- ✅ **统计与冲突提示**：每类数量 + 各会议贡献度；命中跨多个会议时提示人工核对
- ✅ **输入校验（v3 新增）**：二进制文件检测、空文件告警、编码异常自动兼容(GBK)、扫描摘要输出
- ✅ 对接 tmeet：批量拉取多场会议智能纪要/转写
- ✅ 本地兜底：无 tmeet 时读本地纪要素材目录，附 `kb_build.py`
- ✅ 可独立运行：纯标准库 Python 脚本，零依赖

## 快速开始

### 在线模式（推荐）

直接用自然语言跟 AI 对话即可，**无需记命令**：

| 你想做 | 直接说 |
|---|---|
| 建知识库 | 「帮我建一个会议知识库」 |
| 查决定 | 「上次关于支付方案是怎么定的？」 |
| 看待办 | 「这周哪些行动项要跟进？」 |
| 写周报 | 「帮我把最近的会议结论汇总一下」 |

> 💡 更多触发话术见 **SKILL.md § 一句话触发**。

### 本地模式（CLI）

```bash
# 构建知识库（产物：知识库.md）
python scripts/kb_build.py --input-dir examples --output 知识库.md
# 检索（多关键词 OR）
python scripts/kb_build.py --input-dir examples --query 支付
# 限定类别 + 结构化 JSON（含负责人/截止日）
python scripts/kb_build.py --input-dir examples --query 张伟 --cat 行动项 --json
# 统计概览
python scripts/kb_build.py --input-dir examples --stats
# 详细诊断（排查问题时使用）
python scripts/kb_build.py --input-dir examples --verbose
```

---

## 辅助脚本 `scripts/kb_build.py`

| 参数 | 说明 |
|------|------|
| `--input-dir` | 纪要素材目录（.md/.txt），**必填** |
| `--output` | 输出知识库索引路径（构建模式，默认 `知识库.md`） |
| `--query` | 关键词，空格分隔多个（默认 OR 模式） |
| `--all` | 多关键词需**全部命中**（AND 模式） |
| `--cat` | 限定类别：`决策` / `行动项` / `风险` / `结论` |
| `--json` | 以 JSON 输出检索结果（含 owner/deadline/matched） |
| `--stats` | 仅输出统计：每类数量 + 各会议贡献度 + 扫描摘要 |
| `--verbose` | 输出逐文件诊断详情（跳过原因、编码警告等） |

> 构建时脚本会自动排除与 `--output` 同名的文件，避免知识库索引被当作素材再次摄入。

## ❓ 常见问题与排障（FAQ）

### Q1：提示「目录不存在」或「目录无可读素材」

**可能原因与解决方法**：

| 排查步骤 | 操作 |
|---|---|
| 1. 检查路径 | 确认 `--input-dir` 路径拼写正确，建议用绝对路径如 `D:/meetings/notes` |
| 2. 检查文件格式 | 目录中必须有 `.md` 或 `.txt` 文件；`.docx`/`.pdf` 不支持（需先导出为文本） |
| 3. 检查权限 | 确保对目录有读取权限；Windows 下避免放在需要管理员权限的系统目录 |
| 4. 使用 `--verbose` | 加上此参数可以看到每个文件的扫描结果和跳过原因 |

```bash
# 排查示例：显示每个文件的处理情况
python scripts/kb_build.py --input-dir ./你的目录 --verbose --stats
```

### Q2：构建成功但条目数比预期少很多

**最常见原因**：

- **纪要缺少标准章节标题**：脚本按 `## 决策`、`## 行动项` 等标题归类最准确。如果你的纪要没有这些标题，脚本会退回到关键词匹配，覆盖率降低。
  - **解决**：在纪要中加上 `## 决策`、`## 行动项`、`## 风险`、`## 结论` 这样的章节标题。
  - 或者在文本中使用明确的关键词如「决定」「待办」「风险」「结论」。

- **内容被去重了**：归一化后相同的条目只会保留第一条。
  - **解决**：这是正常行为。用 `--stats` 看各会议贡献数确认。

- **某个会议文件贡献为 0**：`--stats` 输出会特别标注 ⚠️ 并给出可能原因。

```bash
# 用 stats 定位哪个文件没被正确解析
python scripts/kb_build.py --input-dir ./你的目录 --stats
```

### Q3：检索不到结果（命中 0 条）

按以下顺序排查：

1. **减少关键词**：OR 模式下只需命中一个词即可，试试只用一个核心词
2. **检查拼写**：全角/半角、大小写差异不影响匹配，但错别字会
3. **先看统计**：用 `--stats` 确认知识库里是否有该主题的条目
4. **换类别搜索**：用 `--cat 决策` 或 `--cat 行动项` 缩小范围
5. **去掉 AND**：如果用了 `--all`，去掉它改为默认 OR 模式

```bash
# 排查步骤
python scripts/kb_build.py --input-dir ./你的目录 --stats          # 先看有没有相关条目
python scripts/kb_build.py --input-dir ./你的目录 --query 支付       # 单个关键词 OR
python scripts/kb_build.py --input-dir ./你的目录 --query 支付 --cat 决策  # 限类别
```

### Q4：提示「检测到可能是二进制文件」

说明某个 `.md`/`.txt` 文件实际包含二进制内容（可能是下载损坏、或错误重命名）。该文件会被跳过并打印警告。

- **解决**：检查该文件是否为纯文本，删除或修复后重新运行。

### Q5：中文乱码或读取失败

脚本默认以 UTF-8 读取文件。如果文件是 GBK 编码（某些旧系统导出），v3 会自动尝试 GBK 兼容读取并发出警告。

- **建议长期方案**：将所有纪要文件统一转为 UTF-8 编码。

### Q6：与 tmeet 对接失败怎么办

本 Skill 设计了**自动降级**机制：
1. 若环境有 tmeet → 优先拉取在线智能纪要
2. 若无 tmeet 或拉取失败 → 自动切换到**本地模式**，读取你手动准备的纪要素材目录

只需确保本地目录中有 `.md`/`.txt` 格式的会议纪要即可正常使用。

### Q7：知识库可以更新吗？如何增量添加新会议？

**可以**。把新的会议纪要文件放入同一个 `--input-dir` 目录，重新运行构建命令即可：

```bash
# 添加新会议后，重新构建（旧条目保留，新增的自动合并）
python scripts/kb_build.py --input-dir ./你的目录 --output 知识库.md
```

脚本每次都会重新扫描整个目录，自动去重合并。

## 错误速查表

| 错误信息 | 含义 | 解决方法 |
|---|---|---|
| `目录不存在` | `--input-dir` 路径错误 | 检查路径拼写，使用绝对路径 |
| `目录无可读素材` | 目录中没有 .md/.txt 文件 | 确认素材文件存在且格式正确 |
| `文件读取失败: ...` | 权限问题或文件被占用 | 关闭占用该文件的程序，检查权限 |
| `检测到可能是二进制文件` | 文件含非文本内容 | 删除/修复该文件 |
| `查询关键词为空` | `--query` 参数为空 | 提供至少一个搜索关键词 |
| `命中 0 条` | 无匹配结果 | 见 Q3 排查步骤 |

## 与比赛主题的契合

- **让开会更简单**：会议价值在"复用"而非"召开"；本 Skill 让会议结论持续可用，减少重复开会与反复确认。
- **基于 tmeet 二创**：单向依赖官方腾讯会议 Skill 的多场纪要能力，专家评审阶段可获额外加分。
- **可独立运行 + README 完整**：满足海选 TRACE 自动评测要求。

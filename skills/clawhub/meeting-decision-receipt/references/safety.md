# 安全、隐私与动作边界

## 数据最小化

- 默认不保存原始转写、录音、完整聊天记录或附件副本。
- 只在当前任务中使用来源文本；产物仅保留支持判断的短证据。
- 输出前扫描密码、Token、API Key、手机号、邮箱和常见凭证格式。
- 公开示例、README、测试和截图只使用虚构会议与虚构角色。
- 不把真实公司名、客户名、项目代号、内部术语、组织角色表或历史决策库放进公开仓库。

## 脱敏顺序

1. 读取来源到临时工作区。
2. 运行 `{baseDir}/scripts/redact_sensitive.py`。
3. 从脱敏副本提取证据并生成结构化判断。
4. 在 `safety.redactions` 和 `redaction_categories` 记录数量与类别。
5. 完成后删除宿主允许删除的临时副本；不复制原始文本到日志或测试失败信息。

脱敏标记只显示类别，例如 `[REDACTED:TOKEN]`。报告不得包含原值。

## 人员保护

只判断语言状态，不推断人格、动机、态度或绩效：

- 允许：`未观察到明确确认。`
- 允许：`当前只观察到表达意向。`
- 禁止：`他在甩锅。`
- 禁止：`这个人不靠谱。`
- 禁止：`她故意不接。`

沉默不等于接受，也不等于拒绝。缺少回应只记录“未观察到明确确认”。

## 指派与授权

- 不根据组织架构、会议名单或职责常识自动派给个人。
- 不把部门指向写成个人承诺。
- 不把记录人、主持人或最后发言者当默认负责人。
- 不调用任务、日历、邮件或消息工具执行会议动作，除非用户在看到最终内容后再次明确确认。

## 二次确认协议

用户说“发群里”“帮我建任务”时：

1. 先展示即将发送或创建的最终内容、目标位置、负责人和时间。
2. 明确说明当前尚未执行。
3. 请求用户再次确认。
4. 只在再次确认后调用宿主工具。
5. 工具不可用时提供可复制文本，不伪造发送成功。

`safety.send_requires_confirmation` 必须为 `true`。

## 双版本纪要边界

- 自用执行纪要允许保留脱敏后的短证据、承诺等级和未确认指派。
- 飞书管理层会议纪要默认不携带直接引文，不呈现“回头看看”等个人对话姿态；相应缺口改写为“负责人、截止时间或责任确认待补”。
- 不因输出对象为老板便推断其拥有最终确认权。只有 open loop 明确缺 `decision` 或 `final_approver` 时，才进入“待明确确认权”。
- 未提供本人身份时，不从参会名单、记录人或任务内容推断“我的任务”。
- 两份纪要均只从已脱敏、已校验的收据 JSON 派生，不嵌入原始转写。
- 生成纪要不等于发送。向老板转发、发群或创建任务仍需二次确认。

## 敏感会议

以下主题启用 `neutral_language_mode`：

- 裁员、绩效、晋升、纪律处分。
- 劳动纠纷、法律争议、合规调查。
- 医疗、健康、伤亡或重大事故。
- 举报、骚扰、歧视或个人隐私争议。

中性模式使用“审计结论、责任确认、待确认事项”，不使用“接活、挂账、收银员、谁没接”等轻松表达。对法律、医疗或劳动结论只记录会议说法，不给专业判断。

## 适配器凭证

- 只调用宿主已经安装并授权的官方能力。
- 不要求用户把 Token、Cookie、密码或 API Key 粘贴进会议文本。
- 不把凭证写入 adapter、日志、示例、Schema、HTML 或错误输出。
- 连接能力缺失时退回手动粘贴或本地文件，不尝试绕过权限。

## 发布前安全检查

- 运行脱敏脚本测试。
- 搜索仓库中的常见凭证前缀、邮箱、手机号和真实项目名。
- 确认所有示例注明“纯虚构”。
- 确认 HTML 不嵌入原始转写。
- 确认确认消息只含受证据支持的内容。
- 确认飞书管理层会议纪要未包含直接引文、表达意向或未确认指派形成的“已推进”表述。
- 确认任何外发动作仍停在二次确认之前。

# 手动粘贴适配器

## 适用输入

- 用户直接粘贴的会议转写、智能纪要、聊天记录或手写笔记。
- 已经脱敏的局部摘录。
- 用户只给出某一议题，希望重新核对决定与承诺。

## 处理步骤

1. 保留用户给出的原始顺序。
2. 识别现有时间戳、发言人标签和段落边界。
3. 没有段落号时，从 `P001` 开始顺序编号。
4. 说话人不清时使用“发言人 1 / 发言人 2”；无法判断发言切换时使用“发言人未知”。
5. 运行敏感信息扫描，后续只从脱敏工作副本引用证据。
6. 来源明显被截断时，在 `open_loops` 中标记“来源可能不完整”，并降低相关判断置信度。

## 推荐内部格式

```json
{
  "speaker": "产品",
  "timestamp": "14:08",
  "paragraph": "P014",
  "text": "可以，我周三给三组样张和失败边界。"
}
```

时间戳和段落号可同时存在。不要把用户输入改写后再当直接引语。

## 输入不足

- 只有一句结论，没有会议上下文：可整理为待核对项，不能伪造参与者或决策过程。
- 只有智能纪要摘要，没有逐字稿：把 `source_type` 设为 `smart_minutes`，证据引用摘要原句并降低争议项置信度。
- 用户要求会议纪要：按受众生成自用版、管理层版或两份版本；两份纪要都从验证后的结构化判断派生。
- 用户要求逐字复述或按讨论顺序扩写长纪要：说明该 Skill 聚焦结论、责任和待确认事项，不把逐段复述混进判断层。

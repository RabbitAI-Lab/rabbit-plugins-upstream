# GEO HTML 诊断报告规范

本规范严格复用参考报告《海尔-净省电空调 GEO品牌监测报告》的内容结构、UI 语言和统计边界，同时去除示例品牌事实。所有输出数据必须来自本次任务。

## 条件与章节顺序

固定正文顺序：

1. `report-intro` 报告简介
2. `overall` 整体表现
3. `visibility` AI 可见度分析
4. `product-visibility` 产品层 AI 可见度分析（仅设置产品名称时）
5. `ranking` 排名分析
6. `products` 商品卡提及表现
7. `sentiment` AI 舆情分析
8. `sources` 引用源分析
9. `recommendations` 优化建议
10. `appendix-a` AI 可见度问题明细
11. `appendix-b` 排名数据口径与分平台明细
12. `appendix-c` 商品卡、情感与引用源数据说明
13. `appendix-d` 产品层 AI 可见度问题明细（仅设置产品名称时）

报告模型的每个 section、block 和对象型 item 必须显式声明 `scope: brand` 或 `scope: product`；不得依靠缺省 scope 或仅靠关键词推断范围。

没有产品名称时，先结构化过滤所有 `scope: product` 内容，再删除第 4、13 章及对应侧栏导航、产品 KPI、产品诊断和“品牌→产品转化”文字。过滤后不得出现“目标产品/该产品/本产品/此产品/这款产品/上述产品”等目标指代，并用产品曝光、露出、出镜、推荐、出现频次、概率、可见、提及、转化、承接等语义检查做防御性校验。商品卡章节仍可做 `scope: brand` 的品牌层分析。

若原始数据没有商品卡或引用，保留对应章节并清楚写“本次结果未返回可解析数据”，不要制造空排名。

## UI 与文件要求

- 输出 UTF-8 单文件 HTML。
- 使用 `assets/report.css`；主色紫 `#6c50ff`，背景 `#f5f6fb`，白色卡片，左侧 230px 粘性导航。
- 顶部使用紫色渐变 Hero，显示标题、任务规模和数据日期。
- Hero 后保留一个附加的报告溯源面板，可见显示任务 ID、任务名称和数据周期/时间；直接报告可附来源。公开面板不得显示报告路径、确认输入范围或结果局限，且不改变正文章节顺序。面板必须是 `main.main` 的直接子节点，紧邻 Hero 且位于首个正文 section 前；面板必须唯一且真实可见，面板及其祖先不得有内联 style、隐藏容器或隐藏属性。
- 使用圆角卡片、KPI 网格、诊断提示框、可横向滚动表格、热力格、平台卡片和 P0/P1/P2 建议卡片。
- 桌面端和窄屏均可用；打印时隐藏侧栏并去除阴影。
- 不依赖 JavaScript、CDN、外部字体或远程图表库。图表使用 HTML/CSS 或内联 SVG。
- 仅使用打包的 `assets/report.css`，报告内联 style 必须与该资产逐字一致，不接受任意 CSS 覆盖。单文件必须含限制性 CSP：默认、连接、frame、object、base 和 form 全部禁止，仅允许必要的内联样式与安全图片源。
- 商品图片可以使用原始远程 URL，但必须提供无图占位。
- 文件名：`品牌[-产品]_GEO品牌诊断报告_YYYY-MM-DD.html`。

Hero 推荐元数据：成功对话数、问题数、平台端数、有效推荐段数、商品卡数。无数据项可省略。

## 分析数据边界

- `context_raw`：API 原始正文，可能包含结构化卡片标记。
- `context_text`：移除卡片标记块后的正文。所有品牌/产品提及、排名与情感分析只使用此字段。
- `quotes`：只用于引用源分析。
- `cards`：只用于商品卡分析。
- `search_words`：可做查询扩展说明，不计入正文指标。
- `think`：不展示、不分析、不保存到最终报告模型。

成功对话分母只包含状态明确为 `SUCCESS` 且具有可读结果的记录。处理中、失败和缺失结果要在数据完整性说明中单列。

品牌别名和产品别名应在分析前冻结并在附录披露。别名匹配必须避免子串误伤，例如短英文缩写应使用词边界或人工证据核验。

## 核心指标口径

设：

- `A`：成功回答总数。
- `A_brand`：`context_text` 明确提及目标品牌的回答数。
- `M_brand`：目标品牌及审核别名在 `context_text` 的总出现次数。
- `S`：识别出的有效推荐段总数。
- `S_brand`：目标品牌进入有效推荐段的段数。
- `S_top1`：目标品牌位列第 1 的有效推荐段数。
- `S_top3`：目标品牌位列前 3 的有效推荐段数。
- `R_brand`：目标品牌在所有进榜段中的位次数组。

指标：

- 品牌提及率 = `A_brand / A`。
- 提及次数 = `M_brand`。
- 平均提及排名 = `mean(R_brand)`；未进榜不赋惩罚位次。
- 首条占位率 = `S_top1 / S`。
- 首屏覆盖率（全量 Top3）= `S_top3 / S`。
- 进榜段 Top3 率 = `S_top3 / S_brand`。
- 位次离散 = `population_stddev(R_brand)`，展示为 `±x.xx`。

每个平台、问题和场景使用相同定义与各自分母。百分比默认一位小数，平均排名和离散默认两位小数；分母为零显示 `—`。

### 自然推荐题边界

问题原文含目标品牌、品牌别名、目标产品或产品别名时，标记为直搜题，不纳入自然推荐可见度、自然推荐场景排行及自然推荐品牌得分；在附录列出排除原因。不得静默删除问题结果。

## 排名识别

1. 只解析 `context_text`。
2. 优先识别明确有序结构：编号列表、排名表、带“第 N/Top N”的推荐、同一比较段内的有序候选。
3. 一个回答可包含多个有效推荐段；分别计数。
4. 不把引用列表、商品卡、搜索词、目录、总结中的无序复述算作新推荐段。
5. 同一品牌在同一段重复出现只保留最佳明确位次。
6. 无法识别列表结构时，仅在文本明确表达推荐顺序时按首次出现顺序回退；普通自然段不得强行排名。
7. 保存证据：回答记录 ID、段落摘录、候选顺序、解析方法和置信度。低置信度结果须抽样人工核验。

## 产品层口径

仅在用户明确提供产品名称时启用。

设 `A_product` 为正文明确出现目标产品线或经审核别名的回答数：

- 产品提及率 = `A_product / A`。
- 品牌→产品承接率 = `A_product / A_brand`。
- 产品名称提及次数 = 产品及审核别名在正文的总出现次数。
- 产品平均位次、Top3 覆盖使用与品牌相同的有效推荐段方法，但候选单位为产品线。

只出现目标品牌或其他产品线时，不计入目标产品可见度。产品名是通用词时必须结合品牌或上下文确认，避免误匹配。

建议模块：品牌可见度→产品可见度转化、问题×平台热力图、高/低表现问题、分平台产品可见度、目标产品与竞品产品线、产品正文提及→商品卡挂载、产品结论、附录 D 明细。

## 商品卡口径

- 按“来源类型 + 稳定商品 ID”去重；无 ID 时使用规范化链接，其次使用“平台 + 标题 + 店铺”并标注低置信度。
- 卡位按卡片在同一回答中的出现顺序，从 1 开始。
- 首卡次数：该品牌卡片在回答卡序中位于第 1 的次数。
- 平均卡位：只在该品牌出现商品卡的回答/卡序中计算，不给缺席回答惩罚位次。
- 品牌提及→挂卡转化率 = 同时有正文品牌提及且有该品牌卡的回答数 / 正文品牌提及回答数。
- 商品卡品牌判断优先标题、店铺和明确品牌字段；无法确认归入“未知”，不得猜测。
- 参考平台边界：豆包手机版常见抖音商城卡；腾讯元宝网页/手机常见京东卡；千问手机版常见淘宝卡。以本次返回数据为准。

推荐模块：平台来源覆盖、品牌分布与卡位、正文提及→挂卡转化、目标品牌商品线拆分、问题×品牌挂卡矩阵、分平台商品挂载 Top5、店铺归属 Top10、总结。

## 情感口径

- 只分析目标品牌在正文附近的局部语境，保留证据摘录。
- 正面：明确赞许、优势、推荐或良好体验占主导。
- 中性：事实描述、条件性评价、正负混合或语义不确定。
- 负面：直接、明确且占主导的缺陷、风险、投诉或不推荐。
- 风险/争议词不自动等同于负面情感。
- 正面/中性占比 = `(正面回答 + 中性回答) / 有品牌语境的回答`。

报告展示平台情感结构、正面词、风险/争议词和总结。声明自动情感分析用于监测，不替代人工舆情审校。

## 引用源口径

- 每个解析后的 quote 项计一次引用；同一回答重复返回完全相同引用时可按 `url + index` 去重，并披露规则。
- 网站优先使用 `site_name`，缺失时从 URL 主机名规范化；仍未知则为“未知来源”。
- 文章优先使用 `title`，链接只接受 `http`/`https`。
- 信源类型采用固定分类：视频平台、门户/自媒体平台、官网/独立站/行业垂直、社区/论坛/博客、电商平台、央媒/主流媒体、学术/机构、其他/未知。
- 未知域名不要强行分类；保留映射表和人工覆盖记录。

推荐模块：信源类型分布、平台偏好热力图、全平台网站 Top10、基石文章 Top10、平台偏好卡片和总结。

## 品牌得分

原始结果定制报告统一运行 `scripts/brand_score.py`，采用与参考报告一致的五指标综合口径 v1。只纳入自然推荐题；直搜题继续单列披露。

- 品牌提及率标准分 `V = 品牌提及回答数 ÷ 成功回答数 × 100`。
- 全量 Top3 覆盖率标准分 `T = 品牌进入 Top3 的有效推荐段数 ÷ 全部有效推荐段数 × 100`；无有效推荐段时为 0。
- 平均排名质量标准分 `R = clamp((5 - 平均排名) ÷ 4, 0, 1) × 100`；即第 1 名为 100，第 5 名及以后为 0，无品牌进榜段时为 0。
- 正面/中性情感标准分 `S = 正面或中性品牌语境回答数 ÷ 品牌语境回答数 × 100`；无品牌语境时为 0。
- 提及强度标准分 `I = min(品牌提及次数 ÷ 品牌提及回答数 ÷ 10, 1) × 100`；每个提及回答平均 10 次及以上封顶为 100，无品牌提及时为 0。

最终得分：`round_half_up(0.55V + 0.20T + 0.10R + 0.10S + 0.05I)`，输出 0～100 的整数。五项标准分、分子、分母、平均排名、权重和加权贡献都必须可追溯；总分及各平台得分使用同一公式与各自数据子集复算。

爱搜直接报告明确返回官方品牌得分时使用其值并注明“爱搜口径”。正式报告不得显示 `—` 或“无已审计归一化公式”；原始结果定制报告的得分必须由渲染器按上述指标再次复算，任何手填不一致都拒绝输出。

## 优化建议

- P0：显著低覆盖、关键平台弱势、明确负面风险或数据完整性问题。
- P1：排名、首条占位、产品承接、商品卡转化、平台信源适配。
- P2：巩固高表现场景、持续内容维护和实验建议。
- 每条建议必须引用本报告的具体指标、问题、平台或证据，不写泛化 SEO 套话。
- 清楚区分“观察”“推断”“建议”；不要把相关性表述成因果。

## 质量审计

- 对话数 = 成功 + 处理中 + 失败 + 未提交，且与 manifest 一致。
- 平台、模式、问题和次数覆盖与已确认计划一致。
- 表格分子/分母可回溯；抽查至少 5 条品牌提及、5 个排名段、全部负面、5 个引用和5张商品卡。
- 同一指标在 Hero、KPI、表格、诊断文字与附录中一致。
- 品牌得分为 0～100 的整数，标明“五指标综合口径 · v1”或“爱搜口径”；附录披露五项公式与本次审计输入。
- 无 `NaN`、`Infinity`、`null`、`undefined`、`TODO`、`{{placeholder}}`。
- 用户可见文本不得包含 API 原始字段名、原始响应结构、平台内部代码或英文模式值；平台必须显示完整名称、终端与中文模式。
- 未设置产品时无任何产品层章节或产品层结论。
- 任务 ID、任务名称和数据周期/时间完整且在报告溯源面板可见；报告路径、确认输入范围和结果局限不得出现在公开面板。
- 所有外链使用 `target="_blank"` 且附 `rel="noopener noreferrer"`。
- 拒绝 script、iframe、object、embed、任何事件处理属性、meta refresh、外部样式表、CSS `@import`、远程 CSS `url()`、style 终止注入以及缺失/弱 CSP。

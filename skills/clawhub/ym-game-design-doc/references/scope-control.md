# 砍功能优先级与产能基准 (Scope Control)

本文件给 `ym-game-design-doc` 使用：决定哪些系统进 MVP、里程碑怎么折算成周。核心原则——优先级由「对核心循环的贡献度」决定，不是由「做起来酷不酷」决定。

---

## 一、砍功能优先级方法（按核心循环贡献度排序）

把每个候选系统放进三档之一，档位决定它在文档里的标注：

| 档位 | 定义 | 标注 | 排期 |
|---|---|---|---|
| 闭环必需 | 没有它，核心循环文字环断掉，玩家每刻无事可做 | 【MVP】 | 前 6 个月必做 |
| 体验增益 | 有它更好，没有也能玩（如剧情、成就、皮肤） | 【后期】 | 首作可不做 |
| 长尾内容 | 纯填充量，靠它延长寿命（如第 4 章后、模组） | 【后期】 | 起量后做 |

**排序步骤：**

1. 先画核心循环文字环（见模板第 2 节）。
2. 把每个系统挂到环上的某个动作；挂不上的 → 直接【后期】。
3. 挂在环上的，再问「去掉它这步还能转吗」：不能转 → 【MVP】；能转但更无聊 → 仍标【MVP】但注明可降级。
4. MVP 合计折算工时，超过团队产能上限（下表）就把最低优先级的 MVP 系统降级到【后期】，循环直到兜得住。

**产能上限（MVP 工时）：**

- solo：15h/周 × 26 周（6 个月）≈ 390h
- 2-3 人：人数×15h×0.8（协作损耗）×26 周
- 5 人以上：人数×15h×0.65（沟通成本）×26 周

---

## 二、产能基准表（单类工作常见耗时）

以下为独立游戏常见量级，用于把「系统/资产」折算成工时。**数值偏保守，首次估请往高了估。**

### 系统类（含实现 + 试玩 + 一轮调参）

| 工作 | 耗时区间 | 说明 |
|---|---|---|
| 一个核心机制原型 | 20-40h | 先验证手感再扩 |
| 一个系统的调参周期 | 15-40h | 战斗/经济/成长各算一次 |
| 一套基础 UI | 20-40h | 菜单+HUD+存档 |
| 程序化生成（地牢/地图） | 30-60h | 随机易、好玩难 |
| 存档/跨局继承 | 10-20h | 常被低估 |
| 本地化（中英） | 15-30h | 量大时另算 |

### 美术类（资产量 × 单件工时）

| 资产 | 单件工时 | 备注 |
|---|---|---|
| 一个 bem 水准角色立绘 | 8-16h | 含三视图/关键表情 |
| 一张中小场景地图（tilemap） | 10-20h | 含碰撞与装饰 |
| 一张卡面（卡牌游戏） | 4-8h | 量大可压到 3h |
| 一个基础特效 | 2-6h | 受击/死亡/拾取 |
| 一首 BGM | 10-30h | 外包另算 |
| 一个 UI 图标组（20 个） | 6-12h | |

### 协作损耗（小团队必扣）

| 团队 | 有效系数 | 含义 |
|---|---|---|
| solo | 1.0 | 15h/周 即有效 |
| 2-3 人 | 0.8 | 每人扣 20% 同步成本 |
| 5 人以上 | 0.65 | 扣 35%，会议与联调吃掉 |

## 三、常见误用（与 SKILL.md 常见坑对应）

- 用理想全职工时（8h/天）折算 → 实际有效开发只有 15h/周，排期必崩。
- 把「看起来高级」（联机、开放世界、物理）排进 MVP → 这些几乎都不在核心循环闭环里，默认【后期】。
- 美术按风格说「简单」→ 必须数资产数量级再乘单件工时，像素风也吃量。
- MVP 不设上限 → 永远做不完；用上表 390h（solo）硬卡，超了就砍。

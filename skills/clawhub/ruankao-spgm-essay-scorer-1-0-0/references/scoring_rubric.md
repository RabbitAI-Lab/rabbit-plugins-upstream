# 系统规划与管理师论文模拟评分量表（ruankao-spgm-essay-scorer）

> 依据软考高级论文通用评分维度整理，适用于系统规划与管理师。对考生粘贴的论文全文，按本表逐项打分、折算官方 75 分制、判定是否过线。

## 一、计分模型总览

- 论文满分 **75 分**，及格线 **45 分**（全国统一标准）。
- 内部采用「百分制 5 维自评量表」：切题性 / 实践性 / 深度与广度 / 逻辑性 / 书面表达，每维 **0–100 分**。
- 加权合成百分制总分，再折算官方 75 分制。

### 权重与折算表

| 维度 | 内部分 | 权重 | 官方小分(满分) | 折算公式 |
|------|-------|------|---------------|---------|
| 切题性 | 0–100 | 0.25 | 25 | 内部分 × 0.25 |
| 实践性 | 0–100 | 0.25 | 25 | 内部分 × 0.25 |
| 深度与广度 | 0–100 | 0.20 | 20 | 内部分 × 0.20 |
| 逻辑性 | 0–100 | 0.15 | 15 | 内部分 × 0.15 |
| 书面表达 | 0–100 | 0.15 | 15 | 内部分 × 0.15 |
| 合计 | — | 1.00 | 75 | 百分制 × 0.75 |

- **百分制** = 切题×0.25 + 实践×0.25 + 深度×0.20 + 逻辑×0.15 + 表达×0.15
- **官方分** = round(百分制 × 0.75)
- **过线判定**：官方分 ≥ 45（即百分制 ≥ 60）为"模拟通过"，< 45 为"模拟不通过"。

### 档位对照

| 档位 | 官方分(满分 75) | 对应百分制 |
|------|----------------|-----------|
| 模拟优秀 | ≥ 60 | ≥ 80 |
| 模拟通过 | 45 – 59 | 60 – 79 |
| 模拟不通过 | < 45 | < 60 |

## 二、各维度评分锚点（0–100）

> 打分先定档（优秀 90–100 / 良好 75–89 / 及格 60–74 / 不及格 <60），再在档内微调。

### 1. 切题性（权重 0.25，官方满分 25）

- **90–100 优秀**：标题精准含主题关键词；每个分论点逐条回应题目全部显性 + 隐性要求；结尾回扣主题，全程无跑题。
- **75–89 良好**：覆盖题目主要要求，个别分论点略偏，但整体切题。
- **60–74 及格**：主体切题，但漏答题目某一子要求，或个别段落游离。
- **<60 不及格**：明显偏题 / 漏题（如题目要"服务规划与设计"却大篇幅写项目管理通用流程，未落到 IT 服务）。
- **红线**：严重偏题（内容与题目完全无关）→ 直接判不通过。

### 2. 实践性（权重 0.25，官方满分 25）

- **90–100 优秀**：项目背景完整（名称 / 规模 / 周期 / 角色 / 目标齐全），有真实细节与量化数据（如 MTTR、SLA 达成率、故障同比下降百分比），解决方案具体可感。
- **75–89 良好**：背景较完整，有实例但量化数据偏少。
- **60–74 及格**：有项目背景但模糊（"我参与了一个项目"），实践描述偏概念化、缺细节。
- **<60 不及格**：纯理论堆砌、无真实项目支撑。
- **红线**：项目明显虚假（金额夸大、周期不合理、角色与规模严重不匹配、逻辑矛盾）→ 直接判不通过。

### 3. 深度与广度（权重 0.20，官方满分 20）

- **90–100 优秀**：不仅说"做了什么"，更说清"为什么这样做"；引用专业理论 / 方法论（ITIL 4、GB/T 24405、运维四要素、七步改进法、服务目录 / SLA 等）；含问题分析与应对。
- **75–89 良好**：有理论结合，问题分析基本到位。
- **60–74 及格**：仅描述做法，理论引用薄弱，缺问题分析过程。
- **<60 不及格**：浅尝辄止，无专业理论支撑。

### 4. 逻辑性（权重 0.15，官方满分 15）

- **90–100 优秀**：四段式结构清晰（摘要 / 项目概述 / 正文核心 / 结尾），分论点逻辑递进（规划 → 实施 → 成效 → 改进），过渡自然。
- **75–89 良好**：结构完整，个别过渡生硬。
- **60–74 及格**：结构基本成立，但分论点间关联弱。
- **<60 不及格**：结构混乱、段落跳跃、缺摘要或结尾。

### 5. 书面表达（权重 0.15，官方满分 15）

- **90–100 优秀**：术语准确、语句通顺、格式规范、无明显语病。
- **75–89 良好**：偶有术语误用或语病，不影响理解。
- **60–74 及格**：术语使用有误但不严重，部分语句不通。
- **<60 不及格**：术语大量误用、语病明显、标点混乱。

## 三、不通过红线（任一触发即判不通过，官方分记为不合格）

1. **项目虚假**：明显编造项目经验（金额夸大、周期不合理、角色与规模矛盾）。
2. **严重偏题**：内容与题目要求完全无关。
3. **字数不足**：正文（项目概述 + 正文核心）少于 1500 字（模拟阅卷按篇幅显著不足判低分）。
4. **抄袭痕迹**：与公开范文高度雷同（重复率明显）。
5. **结构残缺**：缺摘要 / 项目概述 / 正文核心任一部分。
6. **立场错误**：论点与主流专业观点相悖。

## 四、改进建议模板（按维度输出）

每个失分维度（百分制 < 75 的项）给出 1–2 条可落地修改建议，并标注可对照主库哪类资料提升：

| 失分维度 | 建议方向 | 主库可对照资料 |
|---------|---------|---------------|
| 切题性 | 重读题目逐条列"要求清单"，让每个分论点对应一条；标题与结尾回扣关键词 | 历年真题范式（`query=系统规划与管理师 论文真题`） |
| 实践性 | 补全项目五要素（名称/规模/周期/角色/目标），加入 1–2 个量化成效 | 参考范文（`query=参考论文 服务规划与设计`） |
| 深度与广度 | 增加"为什么这样做"的论证，显式引用 ITIL 4 / 运维体系等方法论，补问题分析 | 教程第 2 版 / 三色笔记（`query=教程 第2版`） |
| 逻辑性 | 按四段式重排，分论点用"规划→实施→成效→改进"递进，加过渡句 | 论文框架模板（`query=论文 框架 模板`） |
| 书面表达 | 校对术语与语病，统一格式（四级标题、段落间距） | 考试大纲 / 范文（`query=案例 论文 考试大纲`） |

> 注：改进建议仅引用主库资料的结构 / 主题 / 术语，不得整段复制范文（避免抄袭红线）。

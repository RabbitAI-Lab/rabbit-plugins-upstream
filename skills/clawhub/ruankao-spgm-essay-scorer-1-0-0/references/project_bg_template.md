# 项目背景完整性核查模板（系统规划与管理师·评分用）

> 系统规划与管理师论文以 **IT 服务 / 运维类项目**为背景最佳。本模板用于**模拟评分时核查"实践性"维度**：被评论文是否提供了真实、完整的项目背景。所有信息必须真实，不得编造。

## 评分核查清单（实践性维度 · 缺一项即扣分）

| 字段 | 说明 | 在论文中是否体现 | 扣分提示 |
|------|------|----------------|---------|
| 项目名称 | 完整的项目正式名称 | ☐ 有 ☐ 无 | 缺失 → 实践性降档 |
| 项目规模 | 服务范围 / 用户数 / 系统数 | ☐ 有 ☐ 无 | 缺失 → 真实性存疑 |
| 建设 / 服务周期 | 开始至结束时间（精确到月） | ☐ 有 ☐ 无 | 缺失 → 严谨性不足 |
| 担任角色 | 项目中的具体职务 | ☐ 有 ☐ 无 | 缺失 → 主线不清 |
| 核心业务目标 | 要解决的核心问题 | ☐ 有 ☐ 无 | 缺失 → 动机不明 |
| 量化成效（加分项） | MTTR / SLA 达成率 / 故障降幅等 | ☐ 有 ☐ 无 | 有则实践性升档 |

## 完整信息示范（供对照）

```
项目：某商业银行数据中心 IT 运维服务管理项目
规模：托管 26 套核心业务系统，服务网点 320 个
周期：2021 年 6 月 - 2023 年 3 月（共 21 个月）
角色：运维服务经理
目标：建立标准化运维流程，提升事件处理效率与系统可用性
技术：ITIL 4、CMDB、Zabbix 监控、自动化运维平台
团队：核心团队 18 人
成果：重大故障同比下降 40%，SLA 达成率 99.5%
```

## 红线提示（评分时重点排查）

- **项目虚假**：金额夸大、周期不合理、角色与规模严重不匹配、逻辑矛盾。
- **冒用风险**：若论文背景疑似直接照抄公开招标文件（次库素材），须提示用户替换为自身真实参与项目，不可冒用。

## 常见问题（评分沟通用）

- **保密项目**：可模糊化（如"某大型国有银行数据中心运维项目"），但核心信息须真实。
- **乙方角色**：明确乙方角色与服务范围（"作为乙方服务经理，负责……"）。
- **金额记不清**：IT 服务类项目可用"服务规模 / 用户数"替代金额，避免虚构不合理数字。
- **无大型项目**：中小型真实项目亦可，重点是过程的真实性与方法论正确运用。

# ③ 信息正确校验 — 规则规格草案 v0.1

> 状态：**待确认**（未实施）｜日期 2026-10-19
> 定位：不依赖渲染器，可独立交付；是「安全渲染 + 可编辑 plan」叙事的证据层

---

## 为什么做这层

AntV Infographic 官方文档自承：「并列事项被 AI 写成流程，渲染器也无法替作者判断语义。」
渲染引擎再强也只能保证「画得对」，不能保证「表达对」。这一层就是补这个缺口 —— 也是竞品与上游都没覆盖的地方。

## A 层：布局语义校验（核心差异化）

检测「语义关系」与「布局形态」是否匹配。全部基于 plan 结构，不依赖渲染。

| 规则 | 检查内容 | 判级 |
|---|---|---|
| **A1 并列误作流程** | 流程型布局（flow / timeline / spine-branch）中，相邻 block 之间若无时序或因果连接词（先/然后/导致/因此/之后），且 content 同构 → 疑似并列被强写为流程 | WARN |
| **A2 对比维度过载** | grid / compare 布局的对比维度 > 3，阅读成本超过收益 | INFO |
| **A3 timeline 缺时标** | timeline 每个节点必须有可解析时间标记（日期/年份/阶段名），缺失即错 | ERROR |
| **A4 pyramid 层级过少** | 层级数 < 3 时金字塔不成立（退化为列表） | WARN |
| **A5 flywheel 未闭环** | relations 必须首尾相接构成闭环——飞轮最常见的 AI 错误就是画成一条弧 | ERROR |
| **A6 fishbone 多头** | 必须有且仅有一个 head（结果/问题），其余为原因分支；多头即错 | ERROR |
| **A7 sankey 不守恒** | 每个中间节点入流总和 ≈ 出流总和（容差 1%），weight 须显式给出 | ERROR |
| **A8 dashboard 缺元数据** | 每个指标块须有 metric + unit + 时间范围，缺 unit 即错（「增长 30%」没有单位等于没说） | ERROR |

## B 层：数值与事实一致性

| 规则 | 检查内容 | 判级 |
|---|---|---|
| **B1 数值可溯源** | plan 中所有数值须能在 source 原文中找到（精确匹配或可换算，如「1.2万」≈ 12000） | ERROR |
| **B2 同指标冲突** | 同一指标在多 block 出现但数值不同 | ERROR |
| **B3 百分比合计** | 同一 group 内明显构成整体的 blocks，百分比之和应在 100% ± 1% | WARN |
| **B4 单位混用** | 同一 group 内单位不一致（元 vs 万元） | WARN |
| **B5 引用完整性** | 每个 block 的 source_ref 须是原文的真实子串 | ERROR |
| **B6 时间倒置** | timeline 节点时间早于 source 中该事件的时间 | ERROR |

## C 层：文本预算（已有能力，保留）

block 标题/正文字数上限、中英混排空格、超长自动降级建议。

## 输出形态

- `plan → JSON 报告 + 人类可读摘要`，分 ERROR / WARN / INFO 三级
- 退出码：有 ERROR → 1，否则 0（便于接 CI 与自动化）
- 每条结果附 `block_id` + 命中片段，方便直接跳回 plan 修改

## 建议交付节奏

1. **先做 A 层 8 条**（纯结构判断，无需原文，半天可跑通 flywheel/fishbone/sankey 三条最硬的）
2. 再做 B 层（需要 source 一起传入）
3. C 层复用现有逻辑

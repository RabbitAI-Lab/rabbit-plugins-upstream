# 参考文献真实性核验：数据源与判定方法

> 本文件配合 SKILL.md 的 **Phase 3** 使用，说明"这篇文献是否真实存在"该用什么数据源、按什么尺度下结论。
> 文中数据源规模与可用性均为 **2026-09-27 实测**，若隔较长时间使用，建议重新验证。

---

## 一、五条铁律（不得违反）

### 1. 不得凭记忆判断文献是否存在

任何"这篇看起来不存在""我印象中没有这篇"式的判断都是**无效结论**。"AI 幻觉文献"的典型特征恰恰是**看起来非常合理**——作者是领域内真实学者、刊名真实、卷期页格式正确。凭印象判断等于把幻觉换了个来源。

**所有存在性结论必须附着实际查询记录**（查了哪个库、用什么检索式、返回什么）。

### 2. "查不到"不等于"不存在"

这是最容易造成误伤的地方。Crossref 只收录**已注册 DOI** 的文献，而大量完全合法的文献本来就没有 DOI：

- 中文期刊论文（绝大多数中文刊未在 Crossref 注册）
- 中文图书、专著
- 学位论文
- 标准、报告、专利
- 2000 年以前的老文献

因此核验结论的最高强度只能是分级的（见第四节），**对无 DOI 的文献只能得出"未能证实"，不能得出"不存在"**。

### 3. 不得以匹配分数（score）单独下结论

Crossref 的 `score` 只反映**检索相关性**，不反映**语义正确性**。实测反例：

| 原始条目 | Crossref 返回 | score | 实际关系 |
|---|---|---|---|
| Jumper J, et al. Highly accurate protein structure prediction with AlphaFold[J]. Nature, 2021, 596(7873): 583-589. | 同名文献 | 68.8 | ✅ 正确匹配 |
| 邱均平. 信息计量学[M]. 武汉: 武汉大学出版社, 2007. | Research status and development trends of remote sensing big data | **108.7** | ❌ **完全无关** |

一条中文图书返回了语义毫不相干的结果，分数却**高于**一条完全正确的英文匹配。原因是中文文献在 Crossref 中无对应记录时，检索会退化为词面匹配，随机返回词面相近的条目。

**规避方法**：著录规范的条目里题名必然出现，因此用"**返回题名是否落在原始引文文本中**"作为主判据（`crossref_verify.py` 已输出 `title_in_input` 字段）。score 只作辅助。

### 4. 不得用 Crossref 的值直接覆盖原文的出版信息

题名一致**不等于**版本一致。同一篇文献在 Crossref 中常有原刊版、论文集收录版、重印版等多条记录，题名完全相同而 DOI 各异。实测反例：

| 原始条目 | 文本匹配返回的首选候选 | 实际关系 |
|---|---|---|
| Abbott B P, et al. Observation of gravitational waves from a binary black hole merger[J]. Physical Review Letters, 2016, 116(6): 061102. | 同名文献，载于 *Centennial of General Relativity*, 2017: 291-311 | ⚠️ **同一论文的论文集收录版** |

该条返回的 **5 条候选全部**是这篇论文的其他版本（收录版、评论文章、综述），题名落位均为"是"，却没有一条的出版信息与原刊一致。若照搬 Crossref 值，会把**正确的**著录改成**错误的**。

**规避方法**：只有**题名、年／卷／期／页、责任者三项同时对应**时，才可判定"已证实"。题名相符而出版信息不符时，只能列出差异提示用户"请确认引用的是哪一版"，**不得改动原文**。脚本的 `candidates` 字段返回全部候选，供逐条比对。

### 5. 不得仅凭"题名 + 出处"判定"已证实"——责任者必须一并比对

题名、刊名、年、卷、期、页**全部正确**，作者却属于另一篇文献——这类"出处错配"比虚构文献隐蔽得多，因为它经得起检索：Crossref 返回 `status=ok`、`title_in_input=true`、年卷期页全对。实测反例：

| 原始条目 | Crossref 记录 | 实际关系 |
|---|---|---|
| SPITALE G, BILLER-ANDORNO N, GERMANI F, et al. Large language models encode clinical knowledge[J]. Nature, 2023, 620(7972): 172-180. | 同一题名与出处，作者为 `Singhal K, Azizi S, Tu T, …`（共 32 人） | ⛔ **出处完全正确，责任者属于另一篇论文** |

Spitale、Biller-Andorno、Germani 三人确为真实学者（苏黎世大学，AI 伦理与健康传播方向），其代表作发表于 *Science Advances* 与 *Nature* 的其他篇目——所以**凭印象判断也查不出问题**，只有逐位比对 `authors` 字段才能发现。

**规避方法**：`crossref_verify.py` 返回的 `authors` 已规范化为"姓 名首字母"形式，逐位与原文前 3 位比对；不一致即判"⛔ 出处错配"，只提示、不改写、同时入人工清单。

> **任何能发 HTTP 请求的环境都能调**（包括 ima 等不能跑脚本的纯对话环境）。
> 脚本（`scripts/crossref_verify.py`）只是调这些接口的**便利封装**，不是核验能力的前置条件。
> 详见第六节 6.1「环境判定」与 6.3「B 段 · 直连 HTTP」。

| Crossref Simple Text Query | 同上 | ⚠️ 仅网页表单（需注册邮箱），单次 1000 条 | 无编码能力时的人工批量入口 |
| DOI 内容协商 | 同 Crossref | ✅ `GET https://doi.org/{doi}` + `Accept` 头 | 单条取 BibTeX / CSL-JSON |

| **NCPSSD 国家哲学社会科学文献中心** | 2900 万条（已去重），**仅哲学社会科学** | ❌ 无公开接口 | 中文社科文献；**只能人工操作** |
| 国家图书馆·文津搜索 | 中文图书 | ❌ | 中文图书，人工 |
| 全国标准信息公共服务平台 | 国家标准、行业标准 | ❌ | 标准类，人工 |

（此处的"可自动化"指**接口可程序化访问**——无脚本环境改用直连 HTTP 同样成立，见 6.3。）

## 三、分流决策

对每条文献依次判断，落入第一个匹配的分支：

| 条件 | 分支 | 处理方式 |
|---|---|---|
| 条目含 DOI | A：DOI 直查 | 调用 `crossref_verify.py`（默认模式），取回权威元数据逐字段比对 |
| 无 DOI，但为英文期刊 / 会议论文 | B：文本匹配 | 调用 `crossref_verify.py --text`，尝试找回 DOI |
| 中文期刊论文 | C：人工核查 | 进入人工清单（NCPSSD / 百度学术） |
| 中文图书、学位论文、标准、报告 | D：人工核查 | 进入人工清单（对应专门平台） |
| 英文图书、标准、报告 | E：人工核查 | 进入人工清单（WorldCat 等） |
| 网页、数据集 | F：链接存活性 | 尝试访问 URL 或查 Internet Archive；仍不可判定则转人工 |

## 四、判定分级与措辞规范

核验结论必须使用以下七级，**不得自行发明措辞**：

| 级别 | 符号 | 触发条件 | 允许的表述 |
|---|---|---|---|
| 已证实 | ✅ | DOI 直查成功；或文本匹配中题名落位为是**且**年／卷／期／页与原文对应**且**责任者与原文对应。**三者缺一不可** | "已通过 Crossref 元数据核实" |
| 疑似版本差异 | ⚠️ | 题名落位为是，但年／卷／期／页与原文不符 | "同一题名存在多条记录（原刊版／收录版／重印版），出版信息与原文不一致，**请确认引用版本**"（**不得改写原文**） |
| 出处错配 | ⛔ | 题名与出版信息均匹配，但责任者与记录不符 | "该文献存在，但责任者与数据库记录不符（Crossref 记录作者为 ……），**请核对是否与其他文献混淆**"（**不得改写原文，不得断言伪造**） |
| 可补全 | ℹ️ | 题名落位为是，原文缺某字段而候选中有值 | "该字段原文缺失，Crossref 记录显示应为 ……"（提示性，非强制） |
| DOI 无效 | ❌ | DOI 无法解析（HTTP 404） | "DOI 无法解析，**需人工复核**"（**不得写"该文献不存在"**） |
| 疑似不存在 | ❗ | 英文文献两种检索均失败；或全部候选题名落位为否 | "**未能匹配到任何记录，疑似不存在，建议人工复核**" |
| 未能证实 | ❓ | 无 DOI 的中文文献、图书、学位论文、标准等 | "该文献类型不在 Crossref 收录范围内，**未能证实，已列入人工核查清单**" |

**措辞红线**：
- 不得使用"该文献从属性上不存在""经核验确认系伪造"等**终局性断言**——本技能不具备这种判定能力。
- "疑似不存在"仅可用于**英文文献**且**两种检索方式均失败**的情形。
- **不得以 Crossref 的出版信息覆盖原文**，除非题名与年／卷／期／页同时对应。
- 所有 ❌ / ❗ 结论必须附上实际查询记录（数据源、检索式、返回状态码）。

## 六、工具调用速查

### 6.1 环境判定（先做这一步）

| 执行方式 | 适用环境 | 说明 |
|---|---|---|
| **A. 脚本** | 有 Python 且可运行本地文件（WorkBuddy 等） | 省事，推荐 |
| **B. 直连 HTTP** | 无 Python / 不能执行脚本（**ima 等纯对话环境**） | 等效替代，结果与判定标准完全一致 |

**两条路径等效**——脚本内部也只是向同样的 URL 发 HTTP GET。
**不得因"没有 Python / 不能运行脚本"而拒绝核验或直接转人工清单。**

### 6.2 A 段 · 脚本（首选）

```bash
# DOI 直查（输入每行：序号<TAB>DOI，序号可省略）
python scripts/crossref_verify.py --file dois.txt --output result.json

# 引文文本匹配（输入每行一条完整著录）
python scripts/crossref_verify.py --text --file refs.txt --output result.json

# 单条快速验证
echo "10.1038/s41586-021-03819-2" | python scripts/crossref_verify.py
```

脚本 `--mailto` 参数请替换为真实联系邮箱以进入 Crossref polite pool（响应更快、限流更宽）。仅使用 Python 标准库，无需安装依赖。

### 6.3 B 段 · 直连 HTTP（无脚本环境，如 ima）

> **以下接口全部公开、无需注册、无需 API key、无需任何凭据**。实测（2026-09-29）三个接口均可从对话环境直接访问。

**① DOI 直查**（最优先）：

```
GET https://api.crossref.org/works/{DOI}
User-Agent: GB7714-Checker/4.0.4 (mailto:<你的邮箱>)
```

**② 文本匹配——必须双字段**（缺一即可能漏检）：

```
GET https://api.crossref.org/works?query.bibliographic={完整著录串}&rows=5
GET https://api.crossref.org/works?query.title={纯题名}&rows=5
    &select=DOI,title,author,container-title,issued,volume,issue,page,type,score
```

`query.title` 用**纯题名**（更准），`query.bibliographic` 用**完整著录串**（召回更广）。两次结果合并去重，按"题名落位优先、score 次之"排序。

**③ OpenAlex 交叉验证**（强制触发场景见第五节）：

```
GET https://api.openalex.org/works/doi:{DOI}
GET https://api.openalex.org/works?filter=title.search:{题名}
```

**直连返回值的字段位置**（与脚本字段一一对应）：

| Crossref JSON 路径 | 脚本字段 | 说明 |
|---|---|---|
| `message.title[0]` | `title` | 比对前先剥离 `<scp>` / `<i>` / `<jats:*>` 等内联标记与 HTML 实体 |
| `message.author[].family` + `.given` | `authors` | 取前 3 位与原文逐位比对（"出处错配"判据） |
| `message.container-title[0]` | `container` | 刊名／会议录名 |
| `message.issued.date-parts[0][0]` | `year` | 与 `published-print` / `published-online` 区分（IEEE 年份陷阱） |
| `message.volume` / `.issue` / `.page` | 同名 | 卷／期／页 |
| `message.type` | `type` | `journal-article` / `posted-content`（预印本） |
| `message.score` | `score` | **仅作辅助，不得单独定论** |
| `message.update-to` / `update-policy` | `update_flags` | 撤稿／更正，非空必须提示 |
| HTTP 404 | `status=not_found` | DOI 无法解析 |

**B 段自算题名落位**：两侧题名都做规范化（转小写 → 剥离内联标记与 HTML 实体 → 去标点 → 合并空格），算返回题名在原文中的**词覆盖率**，≥0.8 判为落位为真。

**B 段四项纪律**：
1. **中文不送文本匹配**——必然返回无关结果，中文条目在分流阶段即进人工通道；
2. **限速**——连续多条核查时每条间隔约 0.25 秒，避免 HTTP 429；
3. **失败重试一次**——超时／429 不构成"查不到"，重试后再定论；
4. **不凭记忆补值**——直连取不到就是取不到，按"未能证实"入人工清单。

### 6.4 结果字段解读（脚本与直连通用）

| 字段 | 含义 |
|---|---|
| `status` | `ok` / `not_found`（DOI 无法解析）/ `no_match`（文本未匹配）/ `error` |
| `title_in_input` | **文本模式下的主判据**：返回题名是否落在原始引文中 |
| `candidates` | 文本模式下的其余候选（已按题名落位优先、分数次之排序）。**必须逐条比对其年／卷／期／页**，以确认原文引用的是哪一版 |
| `score` | Crossref 检索相关性，**仅作辅助，不得单独使用** |
| `update_flags` | 撤稿、更正等更新关系，非空时需特别提示 |
| `authors` | 规范化后的"姓 名首字母"形式，便于与 GB/T 7714 著录比对 |

## 七、实测记录（供后续参考）

**2026-09-27 实测**（覆盖真实／伪造／中文／多版本四类情形）：

| 测试条目 | 模式 | 结果 | 说明 |
|---|---|---|---|
| AlphaFold 论文（真实 DOI） | DOI 直查 | `ok` | 元数据完整 |
| RoseTTAFold 论文（真实 DOI） | DOI 直查 | `ok` | 元数据完整 |
| LIGO 引力波论文（真实 DOI） | DOI 直查 | `ok` | 元数据完整 |
| 伪造 DOI `10.1016/j.cell.2023.99.999` | DOI 直查 | `not_found` | 伪造 DOI 被正确识别 |
| LIGO 论文（无 DOI，真实） | 文本匹配 | `title_in_input=true`，但**出版信息全部不符** | 触发"疑似版本差异" |
| 虚构英文文献 | 文本匹配 | 全部候选 `title_in_input=false` | 触发"疑似不存在" |
| 中文图书《信息计量学》 | 文本匹配 | score **108.7**，`title_in_input=false` | 高分误匹配 |

**六条结论**：

1. **DOI 直查最可靠**——DOI 能解析即证明该记录已在 Crossref 注册，口径清晰、无需推测
2. **score 不可单独使用**：中文图书的 108.7 高于正确英文匹配的 68.8，分数与正确性无关
3. **`title_in_input` 是文本模式的主判据**，可准确区分真假匹配
4. **`title_in_input=true` 仍不足以判定"已证实"**：LIGO 那条题名落位为真，但返回的是论文集收录版，必须再比对年／卷／期／页
5. **中文文献不应送入文本匹配**——必然返回无关结果，应在分流阶段就归入人工通道
6. Crossref 元数据质量本身参差：某条记录的 author 字段混入机构地址串（`河南财经政法大学数学与信息科学学院,郑州,450000`），比对时需容错

**2026-09-27 第二批实测**（30 条真实文献：中文期刊论文 19 条 + 英文期刊论文 11 条，来源为 CNKI 导出题录）：

| 情形 | 条目 | 结果 |
|---|---|---|
| 英文期刊论文（无 DOI 著录） | 11 条 | **11 条全部匹配成功**，`title_in_input=true`，均取得 DOI 与完整年卷期页 |
| 其中：单字段检索漏检 | B6 *Microglia states and nomenclature: A field at its crossroads* | `query.bibliographic` 前 5 条候选**全部落位为否**；`query.title` 命中（score 45.6） |
| 其中：预印本与正式版并存 | B7 *Pulsatilla decoction improves DSS-induced colitis…* | 首选为 SSRN 预印本（`posted-content`, 2022）；正式版在候选 2（`journal-article`, *J Ethnopharmacol*, 2023, 300: 115741） |
| 中文期刊论文 | 19 条 | 全部转人工核查清单（Crossref 无收录） |

**两条新结论（已并入 SKILL.md 与脚本）**：

7. **文本匹配必须双字段检索**。`query.bibliographic` 把整串文本按书目字段混合匹配，对题名偏长或含冒号副题名的条目会**整条漏检**，且返回的候选可能全部落位为否——照判定表就会把真实文献误报为"疑似不存在"。脚本已改为 `query.bibliographic` + `query.title` 双字段合并（`matched_field` 可追溯来源）。**下任何"疑似不存在"结论前，必须先确认双字段都已执行。**
8. **预印本渠道记录常排在正式刊出版之前**。`type=posted-content`（SSRN / Research Square / arXiv 等）题名与正式论文几乎一致，年份还可能更早。原文著录正式期刊而返回首选是预印本时，应在 `candidates` 中找 `type=journal-article` 的那条，按"疑似版本差异"处理——**列出差异、不改原文、同时入人工清单**。

**2026-09-27 第三批实测**（34 条真实文献：中文期刊论文 11 条 + 西文期刊/会议论文 23 条，主题为绝缘子缺陷检测）：

| 情形 | 条目 | 结果 |
|---|---|---|
| 西文条目 | 23 条 | **23 条全部匹配成功**，`title_in_input=true`，均取得 DOI 与完整年卷期页；**无一条虚构** |
| 中文条目 | 11 条 | 全部转人工核查清单 |
| **年份与原文差 1 年** | 3 条（IEEE 各刊） | 卷期页**完全一致**，仅年份少 1 年 |
| **作者署名倒置** | 1 条（ICIEA 2019） | Crossref 把姓写成 `Guifeng`/`Zhiren`；OpenAlex 显示姓为 `Zhang`。**两库互相矛盾** |
| **作者数无法证实** | 1 条（Sigma J Eng Nat Sci） | 原文 2 位作者，Crossref 与 OpenAlex **均只登记 1 位**，且均无卷期号 |

**两条新结论**：

9. **DOI 后缀里的年份 ≠ 出版年，年份必须以卷期号反推核对**。实测三例全部来自 IEEE，模式高度一致：

   | 条目 | DOI 后缀年份 | 实际出版年 | 卷期 |
   |---|---|---|---|
   | IEEE TDEI | `tdei.2015` | 2015-12 | 22(6) |
   | IEEE TIM | `tim.2018` | **2019**-08 | 68(8) |
   | IEEE TIM | `tim.2020` | **2021** | 70 |

   IEEE 的 DOI 后缀年份取自投稿／录用年，与卷期所属出版年不是一回事。参考文献管理软件若以 DOI 年份为准会整批出错。**核对方法：以卷期号反推出版年**（如 TIM vol 68 issue 8 对应 2019 年 8 月），不要看 DOI 里的数字。

10. **来源数据库本身也会错，`title_in_input=true` 不代表元数据可信**。实测：ICIEA 2019 一条会议论文，Crossref 记录的 author 字段为 `family="Guifeng"` / `given="Z"`（把名当姓），OpenAlex 同一条显示作者为 `Zhang Guifeng`——**两库矛盾**。原文照抄了 Crossref 的错误形态，若按"以 Crossref 为准"处理会把错误当成标准。**规避**：作者署名与年卷期页出现反常时（如西文人名首字母位于词尾、姓名显然非西方姓名却写成"名 缩写"形态），用 OpenAlex 交叉验证一次（`https://api.openalex.org/works/doi:{doi}`）。两库不一致时**不得采信任一库**，列入人工清单请用户按原刊核实。

**两条新结论**：

11. **判"已证实"必须把责任者一并比对——"张冠李戴"比虚构文献更隐蔽**。虚构文献的特征是"题名看起来合理但查不到"；而**错配**的特征是"题名与出处完全查得到，只有作者是别人的"。后者经 Crossref 检索会返回 `status=ok`、`title_in_input=true`、年卷期页全对，**按旧判定表会被判为"已证实"**。本批新增第七级判定"⛔ 出处错配"覆盖此情形。**核查方法**：脚本返回的 `authors` 已规范化为"姓 名首字母"，逐位与原文前 3 位比对；不一致即判错配，只提示、不改写、同时入人工清单。

12. **Crossref 题名常含内联排版标记，比对前必须剥离**。实测数据中 `title` 字段出现 `<scp>AI</scp>`、`<i>…</i>`、`<jats:sub>` 等形式，容器名出现 `&amp;` 实体。不剥离会导致两个后果：落位检测**假阴性**（标签词挤占词表、覆盖率跌破阈值），以及标签串**原样进入报告**（用户复制即污染著录）。`crossref_verify.py` 已新增 `strip_markup()`，在归一化与取数两处均做剥离。**凡题名呈现异常符号或落位为否时，先检查是否为标记未剥离所致。**

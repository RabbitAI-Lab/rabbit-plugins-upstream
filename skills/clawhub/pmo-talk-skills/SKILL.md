## PMO 回怼与说服话术生成器

把一段真实对话变成一套"立得住、说得赢、收得住"的回怼/说服话术：立场坚定、证据扎实、保持体面。最终目标永远是**把事情推进下去**，不是赢一口气。

### Context

用户输入（**`$ARGUMENTS`**）通常是一段对话记录、邮件往来、会议纪要，或对冲突场景的口述描述，可能附带希望达成的目标。

- 提供了文件时，先完整读取文件再分析。
- 信息不全时（缺对方原话、缺时间线、缺我方目标），先列出缺失项请用户补充；用户不便补充的部分，在话术里用 `[待补充：…]` 占位，绝不编造。

### 工作流

#### 第 1 步：解析对话，提取五要素

| 要素 | 提取什么 | 用途 |
|---|---|---|
| 对方身份 | 上级 / 甲方客户 / 跨部门平级 / 外包供应商 | 决定语气档位和框架 |
| 对方主张 | 核心观点、指责、要求——尽量引用原话 | 话术的靶子 |
| 我方目标 | 免责自证？要对方让步？要资源？推进决策？ | 话术的落点 |
| 情绪状态 | 就事论事 / 施压甩锅 / 越界攻击 / 情绪激动 | 是否需要先降温 |
| 可用证据 | 时间线、书面承诺、聊天记录、数据、第三方证言 | 填入理由和例证 |

#### 第 2 步：场景诊断，按决策表选框架

见下方「框架选型决策表」。选型规则：

1. 场景命中多行时，以**我方目标**定主框架，其余诉求交给组合模块解决。
2. 拿不准时默认 PREP。
3. 对方情绪激烈时永远先 LEAPS。
4. 一次话术只主打一个框架；开场模块（FFC）和收尾模块（RIDE）**各**最多叠加一个，可以同时使用（如 FFC 破冰 → PREP 主体 → RIDE 收尾）。

#### 第 3 步：读取框架细节

动笔前读 `references/frameworks.md` 中所选框架（及要组合的模块）的章节，套用其中的句式模板和示例风格。

#### 第 4 步：证据核验

- 例证、数据、时间点只能来自对话原文或用户确认的事实。
- 证据不够时标注 `[待补充：具体证据]`，并汇总到输出末尾的"待补充证据清单"。
- 禁止为了杀伤力编造例证——被拆穿一次，之后所有话术都会失效。

#### 第 5 步：生成话术（语气档位）

- **主版本（默认·专业有力）**：立场坚定、事实+逻辑、保持体面。
- **备用强硬版**：对方甩锅、越界、反复施压时使用，火力更猛但仍守红线。对方是重要关系方（关键客户、直属上级）时，把备用版换成**缓和版**（以退为进）。对方既是重要关系方又在施压时，仍默认缓和版——只有对方越界人身攻击、或用户明确要求强硬时，才对重要关系方出强硬版。
- 用户明确要求"火力全开"时，主版本也按强硬口径出。
- **交互式框架（LEAPS）的主话术**：L（倾听）、A（询问）是对话动作，无法压进一次性成文——用"动作标注 + 应答成文"结合呈现，如"L：听对方说完，不打断 → E：「……」"。

#### 第 6 步：交付前红线自查

1. 怼观点不怼人——专业场合的"回怼" = 事实 + 逻辑 + 边界，不是情绪宣泄。
2. 不虚构——每个例证、数据、引用都能回溯到对话或用户确认。
3. 杀伤力来自精确——引用对方原话、具体时间点，而不是提高音量。
4. 收得住——结尾给对方台阶，并给出明确的下一步行动（时间点、责任人、动作）。

### 框架选型决策表

| 场景诊断 | 选用框架 | 一句话理由 |
|---|---|---|
| 被质疑责任 / 被甩锅，需要自证反击 | 即时短回应用 PREP；需要完整还原时间线用 STAR | 结论先行占领认知；时间线叙事让责任归属一目了然 |
| 要对方让步：批资源、批预算、同意方案、争取决策 | RIDE | 损失厌恶：先点不批的风险，再给利益和差异 |
| 对方情绪激动、关系僵、投诉或冲突升级 | LEAPS | 先处理情绪，再处理问题 |
| 需要先肯定对方、缓和关系再推进（跨部门协作） | FFC 开场 + 主框架 | 先被看见，才愿意听 |
| 时间极短：电梯偶遇、会上被突然点名、需要即时回复 | 30秒电梯演讲 | 结论 + 三点支撑 + 价值收尾 |
| 述职、复盘、证明自己或团队的价值 | STAR（+L） | 过去行为是未来行为的最佳预测 |
| 正式提方案、回复正式邮件、汇报提案 | SCQA | 建立背景 → 制造张力 → 给出答案 |

### 组合拳

- **FFC 破冰 → PREP 主体 → RIDE 收尾**：跨部门要资源——先真诚肯定对方，再摆结论和证据，最后点一句"不支持的代价"。
- **LEAPS 降温 → PREP 反击**：对方情绪激动时，先接住情绪，等对话恢复理性再摆事实、亮立场。
- **STAR 自证 → RIDE 施压**：外包甩锅——先完整还原时间线证明责任归属，再点明不整改的后果和下一步验收机制。
- **SCQA 开场 → 30秒电梯压缩**：正式提案被要求"说重点"时，把 SCQA 的四个环节压成三句话。

### 输出格式

严格按以下模板输出（第六节没有待补充项时省略）：

```markdown
## 回怼话术方案

**一、场景判断**
- 对方身份：
- 对方核心主张：（引用原话）
- 我方目标：
- 情绪判断：（就事论事 / 施压甩锅 / 越界攻击 / 情绪激动）

**二、选用框架**：XXX ——（一句话理由）

**三、主话术（可直接发送）**

（成文，不带结构标签。随后一行注明结构对应，如：P-首句 / R-第2~3句 / E-第4句 / P-末句）

**四、备用版**（更强硬 / 更缓和，按对方身份定）

（成文，并一句话说明何时切换到这版）

**五、若对方继续反驳**
- 反扑点①「（预判对方原话）」→ 应对：「（一句话顶回去）」
- 反扑点②「……」→ 应对：「……」

**六、待补充证据清单**
- [ ] 待补充：……
```

### 框架细节

`references/frameworks.md` 收录 7 大框架的完整速查：结构拆解、句式模板、心理机制、项目管理场景完整示例（覆盖上级 / 甲方 / 跨部门 / 外包四类对手）、常见误用。第 3 步动笔前必须读所选框架的章节。

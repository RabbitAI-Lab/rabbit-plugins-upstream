# 千题千境 AI-PPT 工作流 · 项目经验总结

> 覆盖时间：2026-09-12 ~ 2026-09-14
> 覆盖案例：①企微智能表培训海报→横版 3 页 ②千题千境 skill 介绍 6 页（两轮风格迭代）③SSC 自动化项目汇总 6 页
> 性质：从"收到需求文字"到"交付可编辑 PPTX"的全链路实战沉淀，可直接作为「千题千境」skill 的知识底稿。

---

## 一、项目全貌：三个案例验证了什么

| 案例 | 起点输入 | 页数 | 验证的工作流环节 | 关键产出 |
|---|---|---|---|---|
| 企微智能表培训 | 竖版海报图（1000×1500） | 3 | 图→内容提取→原生重建；暴露了 alpha 单位致命 bug | `企微智能表培训_横版3页_v2.pptx` |
| 千题千境 skill 介绍 | 纯文字需求 | 6 | 完整 5 步链路首跑；风格必须用户拍板；样图不满意→提示词兜底 | `千题千境_PPTskill_6页_v2.pptx` + 6 个提示词 |
| SSC 自动化汇总 | 邮件（.eml） | 6 | 完整 5 步链路成熟跑；外部出图回传→口径还原→原生重建 | `SSC自动化项目汇总_6页_v1.pptx` + 交付说明 |

三个案例分别代表三种典型起点：**图、文字、邮件/数据**。共同终点：**全部元素为 PowerPoint 原生可编辑对象（无图片素材），用户可直接改字、改形状、改色**。

## 二、标准工作流（5 步，已固化）

```
① 需求文字+素材 → ② 结构确认 → ③ ASCII 草稿确认 → ④ 终稿预览样图 → ⑤ 原生重建 PPTX
                                                    ↘ (不满意) 提示词交付兜底
```

### 第 1 步 · 需求收集与内容解析

**做什么：**
- 从任意来源（图片、邮件 .eml、口述、表格）提取内容骨架：核心数字、分类、流程、结论。
- 邮件类输入注意提取：发件人/收件人（页脚署名用）、日期（时间口径用）、关键数据及其单位（工时？人数？%？——单位错了整页就错）。

**注意事项：**
- **数字单位是高危区**。SSC 邮件里 39.3 是"月度节省工时"、460 是"年度节省工时"，出图工具全部标错（标成覆盖率%、服务员工）。解析时就把"数值+单位+口径"三元组写死在结构稿里。
- 内部受众 vs 对外受众决定细节保留度——要在这一步问清。

### 第 2 步 · 结构确认（三项硬确认）

必须让用户拍板三件事，缺一不可：
1. **页面结构**：横/竖版、页数、每页角色（封面/指标/分类/流程/结尾）
2. **主配色**：最好给色值（用户惯用色直接问，如 LEGO 黄 #FFD700 + 深蓝 #1B2A4A）
3. **受众与细节粒度**

**注意事项：**
- **风格偏好必须显式确认，AI 不能默认替用户决定**——千题千境项目第一次交付被否（"风格还没给我选呢"），就是教训。应给出候选风格 + 每种"看起来是什么样"的白话描述让用户选。
- 用户自定义的名字/文案是**一等公民**（用户否决了 AI 推荐的"千任千面"，坚持"千题千境"）。AI 提供候选即可，定名权在用户。

### 第 3 步 · ASCII 草稿确认

**做什么：** 用纯文本画出每页的版式骨架（区块位置、层级、信息密度），用户确认后再动手。

**价值（SSC 案例实证）：** 外部出图工具改写文案时，ASCII 稿成为唯一可信的内容基准。"样图当视觉规格、已确认 ASCII 稿当内容口径"这条决策能落地，全靠这一步的确认记录。

**注意事项：**
- ASCII 草稿里把**每一处文案写成最终定稿文字**，不要写"此处放指标"这种占位——它就是内容口径的合同。

### 第 4 步 · 终稿预览样图

三条路径，按优先级：

| 路径 | 条件 | 说明 |
|---|---|---|
| A. hy-image-generation（混元生图 3.0） | 已配置 TENCENTCLOUD_SECRET_ID/KEY | 用户指定首选；目前密钥未配、用户暂不打算开，路径空闲 |
| B. 内置 image_gen | 快速验证视觉走向 | 中文易出错字（"科技"→"籿关"）；样图仅用于确认视觉走向 |
| C. **提示词交付兜底（当前主路径）** | 用户对样图不满意（说"差/不行/不好看"） | **立即停止反复生成**，输出 6 个可复制提示词，用户去 Midjourney/DALL·E/即梦等外部工具出图，回传后做原生重建 |

**注意事项：**
- 样图要做到 **8~9 成就是最终样子**，不是低保真示意（用户明确定调"终稿预览"而非"风格样图"）。
- image_gen 并行调用会**撞同一输出文件名**（同时间戳）→ 每个素材必须独立 `output_dir`。
- image_gen 右下角有"AI生成"水印，重建时不沿用即无此问题。
- **回传样图必须逐张按内容核对映射，不能信文件名**。SSC 案例回传顺序 P1/P6/P5/P4/P3/P2 与实际页序完全错位，正确映射是 P6=封面/P1=指标/P2=领域/P3=能力/P4=路线/P5=结尾。

### 第 5 步 · 原生重建可编辑 PPTX（python-pptx）

**做什么：** 以样图为视觉规格、以已确认内容为口径，用 python-pptx 全原生形状重建。构建脚本（如 `build/deck_ssc_v1.py`）结构：

```
调色板常量 → helpers（S/box/para/set_font/conn/solid/bg）
→ 图标库（ic_*，统一签名 (slide,cx,cy,sz,col,bgc)，内细节用底色反白）
→ 每页一个 page*() 函数 → main 逐页构建 → 另存 ASCII 名渲染副本
```

**注意事项：**
- **内容口径决策**：外部出图工具几乎必然改写文案（SSC 案例 7 处全错）。原则 = **样图管"长什么样"，ASCII 稿/原始材料管"写了什么"**。交付时必须附对照表说明差异，并提供"想用样图原文案→改脚本三处列表重跑"的切换路径。
- **构建脚本同时另存一份 ASCII 文件名副本**（如 `build/deck_ssc_render.pptx`）——COM 导出脚本打开中文路径会失败，全靠这份副本。
- 版式布局全部用英寸坐标硬编码（16:9 = 13.333×7.5），先算纵向层级（每块内容的 y 起止）再落码，避免元素互相压叠（SSC 路线图页回环标注与步骤说明重叠就是没做纵向排程的教训）。

### 第 6 步（附加）· 视觉自检与交付

**做什么：**
1. PowerPoint COM 打开渲染副本 → 逐页 `Export(png,'PNG',1920,1080)` → 逐张人眼比对样图
2. 修正 → 重建 → 复检（一般 2~3 轮）
3. 生成"样图↔成品对照表 + 口径差异说明"交付文档
4. 交付 PPTX + 说明 + 渲染图

**注意事项：**
- COM 能正常打开本身就是第一道验收——XML 级损坏（alpha 超限、重复 gd）只有 PowerPoint 自己会报，python-pptx/ZIP 校验全绿。
- COM 打开失败先查残留 POWERPNT 进程（`Stop-Process` 清理后重试）。
- 首版构建如有缺陷，**移档留存**（如 `build/deck_ssc_draft0.pptx`），绝不静默覆盖。

## 三、python-pptx 技术坑全集（按危险度排序）

### ★★★ XML 级损坏（文件打不开，报 0x80070570）

这两类坑 python-pptx 不报错、ZIP 校验正常，只有 PowerPoint 打开时爆——最隐蔽。

1. **`<a:alpha val>` 单位是千分比**（0–100000 = 0%–100%），必须 `alpha * 1000`。写成 `* 100000` 会产生超 schema 上限的值 → 整个文件"损坏"。
2. **`MSO_SHAPE.UP_DOWN_ARROW` 上写 adjustment 会生成重复的 `adj1`/`adj2`**（`<a:avLst>` 内同名 gd 出现两次）→ 文件"损坏"。**规避：该形状一律不设 adjustments。**

**通用排查姿势：** dump `ppt/slides/slideN.xml`，正则抓全部 `<a:avLst>...</a:avLst>` 查重名 gd；增量变体二分（见第六节）。

### ★★ 形状与几何语义

3. **`<a:effectLst>` 在 spPr 中只能出现一次**。自定义阴影前先移除已存在的（`shadow.inherit = False` 会写入一个空的）。
4. **单侧圆角矩形是 `MSO_SHAPE.ROUND_2_SAME_RECTANGLE`**（不是 ROUND_SAME_SIDE_CORNER_RECTANGLE）。adj1=圆角半径，adj2=哪侧圆角（adj2=0 = 上两角圆）。
5. **roundRect 的 adj 是"占较短边的比例"，上限 0.5**。矮色条算不出大圆角 → 做"只圆上两角的顶部色条"时，把卡片 adj 调小到与色条可实现半径对齐（例：卡片 h=2.52/adj=0.0476 → 半径 0.12；色条 h=0.24/adj1=0.5 → 半径 0.12）。**SSC 实测补充：色条必须比直觉更厚（0.24″）才能撑出像样圆角。**
6. **BLOCK_ARC 角度语义（实测确认）**：`0° = 3 点方向，顺时针递增`；python-pptx 归一化系数 0.6（`adjustments[i] = 度数 * 0.6`）；adj1=起始角、adj2=结束角、adj3=内/外半径比。拼装任意弧段可靠。
7. **ISOSCELES_TRIANGLE 默认朝上（时钟角 -90°）**，切向旋转量 = `degrees(atan2(cos θ, -sin θ)) + 90`。
8. **RIGHT_TRIANGLE rot=180 会渲染成方块**（企微案例踩过），改 `ISOSCELES_TRIANGLE rot=90`。

### ★★ 文字与字体

9. **中文必须同时注入 `a:latin` / `a:ea` / `a:cs` 三个 typeface**，否则中文回退默认字体。
10. 渐变用裸 `<a:gradFill>` 注入；`<a:lin ang>` 单位是 1/60000 度。

### ★★ 图标设计（本轮最大认知升级）

11. **图标必须按"最终渲染尺寸"验证，不能只看大图**。卡片内图标实际只有约 0.5″，这个尺寸下：
    - CIRCULAR_ARROW → 一弯细月牙（箭头完全丢失）
    - 「双弧 + 双箭头」→ 蝴蝶结
    - 「粗环缺口 + 单箭头」→ 像字母 G
    - 礼盒 → 四宫格
    - 小尺寸幸存者：双向箭头 ⇄（LEFT_RIGHT_ARROW）、灯泡、简单柱状图、对话气泡
12. **选型方法：写同尺寸并列对比的 `test_*.py`**（真实圆底 + 真实图标尺寸 + COM 导出），一轮渲染选型定版，**不要在主稿上反复打补丁**（同步图标打了一个晚上补丁才悟出）。
13. 图标函数统一签名 `(slide, cx, cy, sz, col, bgc)`，内部细节用背景色（bgc）反白镂空——换底色时图标自动适配。
14. **MSO_SHAPE 没有 BELL**（铃铛），需 OVAL+RECT 组合自建；枚举先查再用。

### ★ 连接线

15. 给 `a:ln` 追加 `<a:tailEnd type="triangle" w="med" len="med"/>` 做箭头；headEnd/tailEnd 顺序敏感，一个 ln 只能各一个。

## 四、PowerPoint COM / PowerShell 环境坑（Windows 本机视觉 QA 通道）

1. **执行策略禁止直接跑 .ps1** → 必须 `powershell -NoProfile -ExecutionPolicy Bypass -File <path>`。
2. **.ps1 文件内含非 ASCII 路径会失败**（PS 5.1 按 ANSI 读脚本 → 中文乱码 → "cannot find the file specified"）。脚本内只写 ASCII，用通配符定位中文名文件（`Get-ChildItem -Filter '*_v2.pptx'`）。
3. **不要在 execute_command 里内联复杂 PowerShell**——`$` 会被外层 shell 吞掉导致语法错误。一律写成 .ps1 文件再 `-File` 跑。（这个坑踩了两次，务必记住。）
4. 打开：`$app.Presentations.Open($path, $true)`（只读）；导出：`$slide.Export($png,'PNG',1920,1080)`。
5. COM 打开失败/挂死时的安全恢复顺序（ClawHub T09 整改后）：
   ① 首选预防——脚本用 `try/finally` 保证 `$pres.Close()` / `$app.Quit()`（模板已内置）；
   ② 只终止**本技能自己启动**的实例（按 PID，或确认无用户打开的其他演示文稿）；
   ③ **严禁无差别 `Get-Process POWERPNT | Stop-Process -Force`**——会静默丢失用户
   未保存的无关演示文稿；确需强制终止非本技能启动的进程，必须先说明风险并获用户明确确认。
6. **脚本文件名不要与标准库重名**（`bisect.py` 会遮蔽标准库导致 urllib.request 循环导入崩溃）。

## 五、素材生成与抠像经验（如需图片素材时）

1. **image_gen 并行调用撞输出文件名** → 每个素材独立 `output_dir`。
2. 绿幕生成：prompt 明确纯 `#00FF00` 平背景 + 高饱和，否则返回灰底。
3. 抠像要点（`ref/cutout.py`）：
   - 四角采样背景色，按**颜色距离做 alpha ramp**（不要 flood fill，否则齿轮中心等封闭孔洞残留不透明）；
   - 水印区整块擦除，但保留 `alpha>0.92 且饱和度>0.55` 的实体像素；
   - 绿边用 4 邻域颜色扩散（约 6 轮）重绘边界环。
4. **裁剪框必须完全落在色块/卡片内部**，否则越界底色被判为前景，渲染出底色横条。先用颜色掩码定位卡片包围盒再取裁剪框；背景色显式传入，不依赖"裁剪块内众数"。
5. `Image.getbbox()` 对 RGBA 会算上 alpha=0 但 RGB≠0 的像素，紧凑裁剪用 `img.getchannel("A").getbbox()`。
6. 小尺寸下发暗/发糊的插画（如粉色闹钟缩到页脚）→ 放弃图片，改原生形状绘制，更清晰也更符合"可编辑"目标。

## 六、排查方法论（可复用的"姿势"）

### 增量变体二分（定位 XML 级损坏）
「PowerPoint 打不开但文件结构正常」时，写一个脚本生成 N 个**每个只加一个特性**的最小 deck（v0_plain 圆角矩形 → v1_alpha 半透明 → v2_gradient → …），再用 COM 逐个 `Presentations.Open()` 测试。企微案例一次锁定 3 个失败点（全是同一 alpha bug）。

### 同尺寸并列选型（图标/小元素）
不要在主稿上对单个元素反复打补丁。把候选方案按**真实渲染尺寸**（真实圆底 + 真实大小）并排列在一页，COM 导出一轮，人眼选型定版。同步图标三轮打补丁不如一张对比图。

### 内容口径还原（外部出图回传后）
逐字段核对：数值、单位、标签、日期、署名。产出"样图 vs 本稿"差异对照表，随交付文档给用户，保留切换路径（改脚本内列表重跑）。

### 视觉自检清单（每轮渲染后逐页过）
- 文字是否互相压叠 / 压线（尤其页脚横线、卡片下沿）
- 图标在小尺寸下是否还可辨识
- 圆角是否对齐（卡片 vs 色条）
- 黄底上的文字对比度（黄底必须深蓝字，不能白字）
- z-order（装饰图要在卡片之后画）

## 七、用户协作约定（必须遵守的硬规则）

1. **绝不静默覆盖制品**。同名再生成前必须先确认，或自动加版本后缀（`_v1`→`_v2`）；首版有缺陷也是移档留存（`deck_ssc_draft0.pptx`），不是删除。
2. **样图不满意时不许反复生成 image_gen**，直接切"6 个可复制提示词 → 用户外部出图"兜底。触发词："差/不行/不好看/不太满意"。
3. **风格/配色/名字由用户拍板**，AI 只给候选 + 白话描述。自主选择权必须显式化。
4. 名字与文案是**一等公民**，不凑合、不用 AI 推荐强推。
5. 千题千境项目的**中间迭代不进长期记忆，最终统一打包进 skill 本身**。
6. 样图生成环节：hy-image-generation 为首选（配好密钥后），当前沿用提示词兜底路径。
7. 用户配色偏好（内部汇报）：LEGO 黄 #FFD700 + 深蓝 #1B2A4A（+ 中蓝 #003366 / LEGO 红 #E3000B）。
8. 交付时附：交付说明（页序映射、口径对照、视觉差异及理由）+ 全部渲染图。

## 八、目录结构规范（本工作区实测定型）

```
项目根/
├─ ref/                 # 参考图 + 配色/几何采样脚本（sample.py、cutout.py…）
├─ prompts/             # 交付给用户的外部出图提示词（单 block 可复制）
├─ sample*/             # 各轮样图（每页独立子目录避免并行撞名）
├─ assets/ → assets_clean/ → assets_final/   # 原图→抠像→透明度变体三级素材
├─ build/
│  ├─ deck_*.py         # 主构建器（每项目一个）
│  ├─ deck_*_render.pptx  # ASCII 名渲染副本（给 COM 用）
│  ├─ export_*.ps1      # COM 导出脚本（ASCII-only 内容）
│  ├─ test_*.py         # 同尺寸并列选型/增量二分测试脚本
│  ├─ png_*/slide_N.png # 渲染校验图
│  └─ deck_*_draft0.pptx  # 有缺陷首版的留档
├─ XXX_v1.pptx          # 最终交付物（版本后缀管理）
└─ XXX_交付说明.md       # 页序映射+口径对照+视觉差异
```

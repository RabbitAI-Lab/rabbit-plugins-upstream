# 隐私、外发与发布边界

> 本文件由 `SKILL.md` 按需加载。适用于本技能的本机使用、真实图纸/项目数据处理、Skill 发布和 Git 远端推送。

## 1. 先分清三条边界

| 场景 | 是否允许 | 执行要求 |
|---|---|---|
| 本机读取、解析、编辑、测试真实图纸和项目数据，并用于制作 skill、程序、插件 | 允许 | 正常作业，不因“公司数据”被禁止；临时产物放 `/tmp`，核验后清理 |
| 助手主动外发：云端模型、云端 OCR、在线转换、第三方服务、Git 远端、发布物 | 默认禁止 | 先停问，说明传输范围与字节，取得用户明确同意后再执行 |
| 用户自行把工作资料备份/传输到其指定的本机、外盘、网盘或在线位置 | 不属于助手外发 | 按用户指定目标执行，助手不得擅自扩大范围 |

红线原意：不是“不碰公司图纸”，而是**发布时要脱敏，助手不得擅自外发**。把“本机可用”和“发布受限”混成一条，会导致正常识图、算量和技能制作被误伤。

## 2. 发布物范围

以下都算发布物，适用同一套脱敏与扫描要求：

- Skill 发布包、插件包、程序安装包；
- GitHub Release、GitHub 仓库源码与附件；
- SkillHub、ClawHub 上传内容；
- Git 远端推送（含分支、tag、Release、LFS）；
- 公开文档、演示数据、截图、示例 DXF/PNG、录屏。

发布物不得包含：

- 公司图纸（dwg/dxf/pdf/图片及其转换件）、施工资料、方案、交底、施工日志、会议纪要；
- 客户名称、项目名称、真实公司名称、真实人名、联系方式、地址；
- 图签、图号、项目缩写、坐标、楼栋编号等可反推项目的信息；
- 本地 OCR 原图与识别结果、含元数据的截图；
- 本地绝对路径、用户名、主机名、内部共享盘、NAS、iCloud 路径；
- API Key、token、密码、cookie、私钥、账号信息。

**发布与备份分离**：发布包不得充当公司数据备份载体；公司数据备份走用户指定通道（如本机到 X1），不进入发布目录。

## 3. 发布前扫描

### 3.1 文件层

```bash
find <发布目录> -type f | sed 's/.*\.//' | sort | uniq -c | sort -nr
find <发布目录> -type f \( -iname '*.dwg' -o -iname '*.dxf' -o -iname '*.pdf' \
  -o -iname '*.doc*' -o -iname '*.xls*' -o -iname '*.ppt*' -o -iname '*.jpg' \
  -o -iname '*.jpeg' -o -iname '*.png' -o -iname '*.tif*' -o -iname '*.zip' \
  -o -iname '*.7z' -o -iname '*.rar' -o -iname '*.db' -o -iname '*.sqlite*' \)
```

示例目录只保留合成 JSON/DXF/PNG；出现真实图纸、Office 原件、压缩包、数据库时先停下核对。

### 3.2 内容层

```bash
rg -n -i "公司名|项目名|人名|客户|甲方|图签|图号|内部|机密|绝密|/Users/|/Volumes/|NAS|iCloud" <发布目录>
rg -n "BEGIN [A-Z ]*PRIVATE KEY|api[_-]?key|token|password|secret" <发布目录>
```

关键词按实际项目补充；命中不等于一定敏感，但必须逐条确认并记录处理结果。

### 3.3 元数据层

- DXF：`$PROJECTNAME`、`$LASTSAVEDBY`、`$FINGERPRINTGUID`、`$VERSIONGUID`、自定义 XDATA、图层/块名中的项目缩写。
- PNG/JPEG：EXIF/XMP 的 Author、Software、GPS、拍摄设备。
- DOCX/XLSX/PPTX：`docProps/core.xml`、`docProps/app.xml`、`docProps/custom.xml`、批注、修订记录。
- PDF：Title、Author、Subject、Keywords、Producer、嵌入附件。
- Git：`git log --all --stat`、`git grep <关键词> $(git rev-list --all)`、`.git/config` 远端、`git rev-list --objects --all` 查大文件历史。

### 3.4 路径与账号层

```bash
rg -n "/Users/[^/]+|/Volumes/[^/]+|C:\\\\Users\\\\|\\\\Users\\\\" <发布目录>
rg -n "sk-[A-Za-z0-9]|ghp_[A-Za-z0-9]|AKIA[0-9A-Z]{16}" <发布目录>
```

## 4. 默认脱敏清单

| 对象 | 处理 |
|---|---|
| 公司名称 | 改为“某施工企业”“示例公司”或删除 |
| 项目名称 | 改为“示例项目”或删除 |
| 人名 | 改为“张工”“李工”或删除 |
| 客户/甲方 | 删除 |
| 图签/图号 | 换成合成图签、`DEMO-001` 一类编号 |
| 坐标/楼栋号 | 用局部坐标或整体偏移，避免反推真实场地 |
| 本地路径 | 改为相对路径或占位符 |
| 账号/密钥 | 一律 `***`，并从历史记录中清除 |
| 截图 | 重制，确保不含桌面、聊天窗口、文件名、路径 |

## 5. 公司样例使用（默认不用）

发布物默认不含任何公司样例。确需使用时，逐文件列明并取得用户明确同意：

| 文件 | 字节数 | SHA-256 | 用途 | 传输目标 | 用户同意时间/原话 |
|---|---:|---|---|---|---|
|  |  |  |  |  |  |

未列明字节、未取得同意、或同意范围与实际传输不一致时，不得发布。

## 6. 云端 OCR / 模型 / 视觉服务

必须先说明并取得同意：

- 文件数量、总字节、单文件最大字节；
- 服务商与具体产品；
- 数据是否留存、是否用于训练；
- 传输方式（API/网页/客户端）与保存位置。

未同意前只用本机工具：`pdftoppm`、本机 OCR 入口、LibreOffice、本地 Python。公司仓库、图纸、施工资料不得走 GitHub 云端 MCP。

公司知识库项目另有更严格约束：只走本机，不写 iCloud、网盘、在线文档或 Git 远端；扫描件只用本机 OCR；助手不得擅自把知识库移入 iCloud 或开启云同步。

## 7. 发布前输出检查表

发布前必须输出以下结果，缺一项不得发布：

- 发布目标：发布包 / GitHub Release / SkillHub / ClawHub / Git 远端；
- 扫描命令与结果：文件层、内容层、元数据层、路径与账号层；
- 命中项及处理：逐条列出；
- 脱敏项：逐项列出；
- 是否含公司数据：是/否；
- 是否含公司样例及字节：无 / 有（附清单与同意记录）；
- 是否已获用户明确同意；
- 发布与备份是否分离：是/否；
- 结论：可以发布 / 不可以发布。

任何一项为“是（未处理）”或“未取得同意”，立即停止。

## 8. 命中敏感信息时

1. 立即停止发布、上传、推送，不继续“先发后补”。
2. 不删除证据；把可疑文件隔离到 `work/quarantine-<时间戳>/`。
3. 已提交但未推送：本地回退或重建提交；已推送：不得用强推掩盖，按用户决定处理历史与凭证轮换。
4. 写本机审计日志（Codex 工作目录内），记录范围、命中项、处理动作、备份路径。
5. 用备份目录或 `git revert` 回滚，重新扫描通过后再决定是否继续。

## 9. 本技能特定约定

- 示例数据全部合成，不含真实项目；`work/` 下的真实项目调试产物不进入发布包。
- 塔吊、施工电梯等设施图块为自绘，不复制第三方 CAD 图块。
- 如引入开源图块：记录来源 URL、许可证、版本、SHA-256，确认与 `CC-BY-NC-SA-4.0` 兼容，并写入 `NOTICE`。
- 发布前对 `work/s4/generated-demo/` 一类演示目录同样执行本文件扫描，不能因为“只是示例”跳过。

# 周边条件、多视角与分阶段研判

本文件对应 `site_layout/context.py`、`site_layout/pipeline.py` 与 `site_layout/review_panel.py`，内容与 0.5.0 代码同步。

## 1. 为什么要先读周边

施工平面布置不是“把临建塞进红线”。总平面图之外的相邻地貌、产权边界、市政条件和敏感目标，往往决定：

- 大门开在哪、道路怎么接顺；
- 塔吊回转能不能越过高压线、住宅、河道；
- 宿舍/办公能不能放在噪声、扬尘、临街一侧；
- 消防车道、回车场、消火栓能否形成闭环；
- 土石方、主体、装饰三阶段哪些设施要挪、要拆、要新增。

技能把周边条件作为**独立校核层**，不混进 26 条规则里，避免“规则通过但周边硬伤”被漏掉。

## 2. 周边条件 JSON（`site-context/v1`）

```json
{
  "schema": "site-context/v1",
  "coord_unit": "m",
  "project": "示例项目",
  "constraints": [
    {"id": "N-01", "type": "high_voltage", "name": "北侧 10kV 高压线",
     "geometry": {"type": "line", "points": [[-10, 80], [110, 80]]},
     "buffer_m": 8, "severity": "hard", "source": "现场踏勘"},
    {"id": "N-02", "type": "residential", "name": "东侧住宅",
     "geometry": {"type": "polygon", "points": [[105, 10], [140, 10], [140, 70], [105, 70]]},
     "buffer_m": 10, "severity": "review", "source": "总平面图"},
    {"id": "N-03", "type": "river", "name": "南侧河道",
     "geometry": {"type": "line", "points": [[-20, -15], [130, -15]]},
     "buffer_m": 15, "severity": "review", "source": "现场踏勘"},
    {"id": "N-04", "type": "municipal_pipeline", "name": "西侧市政管线",
     "geometry": {"type": "line", "points": [[-5, 0], [-5, 90]]},
     "buffer_m": 3, "severity": "hard", "source": "管线交底"}
  ],
  "existing_roads": [
    {"id": "ER-01", "name": "南侧既有市政道路", "width_m": 7.0,
     "geometry": {"type": "line", "points": [[-5, -4], [105, -4]]}}
  ]
}
```

- `coord_unit` 必填；缺省或冲突 → exit 4，不猜倍数。
- `type` 常用值：`high_voltage` 高压线、`residential` 住宅、`river` 河道、`municipal_pipeline` 市政管线、`sensitive_receptor` 学校/医院等敏感点、`existing_building` 既有建筑、`flood` 低洼/汇水。既有道路放 `existing_roads[]`。
- `severity`：`hard` 越界即 fail；`review` 越界只 review，交专项评估。
- `buffer_m` 是平面净距代理值，不是规范结论；项目必须按当地规范、产权边界、专项方案复核。

### 默认缓冲值（仅作起步，均标 [经验]）

| 类型 | 默认值 | 说明 |
|---|---:|---|
| 高压线 | 8 m | 必须按电压等级、当地供电部门和专项方案复核 |
| 住宅 | 10 m | 还要考虑噪声、扬尘、采光、施工时间 |
| 河道 | 15 m | 还要考虑蓝线、防洪、防汛和产权 |
| 市政管线 | 3 m | 必须查管线交底、埋深和产权单位要求 |
| 敏感点 | 20 m | 学校、医院等按当地要求加严 |

## 3. 周边校核怎么判

- `hard`：设施几何进入缓冲带 → `fail`，方案结论“不推荐（存在硬伤）”。
- `review`：进入缓冲带 → `review`，进入人工确认清单，不直接判死。
- 塔吊：除中心点外，还要看**回转外缘**是否扫入高压线等硬约束；不能只看塔吊中心。
- 软约束进入 `manual_actions`，三阶段取并集；不能因为主体阶段没碰到就忽略装饰阶段。
- 没有周边文件时输出明确警告“周边条件未调查”，不默认安全。

## 4. 六视角审查

同一份校核结果按六个角色重排，不新增结论：

| 角色 | 关注点 | 主要检查 |
|---|---|---|
| 项目总工 | 总体可行性、骨架、阶段衔接 | 1/2/4/11/13/14 + R1~R4 + 周边硬伤 |
| 安全总监 | 塔吊、临建、用电、交通冲突 | 6/7/14/20 + R2/R3 + 高压线 |
| 消防/临建 | 消防车道、消火栓、净空、回车、泵房/水池 | 3/4/5/15/19 + R1/R3/R4 |
| 文明环保 | 三类加工区隔离、九牌一图、垃圾扬尘、排水沟 | 8/9/10/16/17/18/21 + R1 + 住宅/敏感点 |
| 商务成本 | 道路规模、永临结合、配电距离 | 3/7/11 + R1 |
| 甲方/报建 | 红线、出入口、阶段必备、公示 | 1/2/4/9/13 + 产权边界 |

结论规则：角色范围内有 `fail` → `fail`；无 fail 但有 manual/review → `review`；全部 pass → `pass`。
`final_check` 恒为 `false`，角色意见不替代审批和签字。

## 5. 三阶段研判

| 阶段 | 布置重点 | 常见变化 |
|---|---|---|
| 土石方 | 大门、洗车池、临时道路、土方堆场、降排水 | 塔吊/施工电梯/加工区尚未上场 |
| 主体 | 塔吊、施工电梯、加工区、材料堆场、临水临电、消防 | 道路骨架基本稳定，垂直运输是核心 |
| 装饰 | 施工电梯、垃圾池、材料周转、临时消防 | 加工区缩小或转移，垃圾和成品保护上升 |

三阶段必须**分别校核**，不能拿主体阶段一张图覆盖全过程。`stage-changes.json` 只反映设施 `active_stages` 的增减，不代表已审批的工序穿插。

## 6. 方案比较怎么读

1. 先看 `hard_finds`：任一阶段有硬伤，直接不推荐。
2. 再看 `manual_actions`：人工确认项是否能在项目层面关闭。
3. 再看八维分数：只比同口径方案，不跨项目比。
4. 最后看阶段变化：土石方→主体→装饰是否频繁搬设备、拆道路、改消防。
5. A/B/C 是讨论起点；项目总工可以要求 D 方案或手工调整，技能不锁定“唯一答案”。

## 7. 边界

- 不调查周边：没有现场踏勘/总平面图/管线交底时，只能提示“未调查”。
- 不做产权、蓝线、退距、环评、消防专项的最终认定。
- 不把默认缓冲值当规范条文；表中数值全部是 [经验] 起步值。
- 不替代项目总工、安全总监、消防审查和报建审批。

# 事件决策表

只使用与当前事件匹配的行。表里的任务是策划建议，不是已经发生的事实；同一个品牌不同事件需要不同证据。

| 事件 | 客户要判断什么 | 事前 → 当天 → 事后 | 需要核实的关键证据 |
|---|---|---|---|
| 参展 | 去不去、找谁、能了解什么 | 到场信息和问题征集 → 识别信息/演示/问题记录 → 按真实问题交资料 | 展期、馆号、展位、可展示范围；不默认有优惠或签单 |
| 新品上市 | 新旧差别、是否适用 | 适用场景说明 → 同条件实物展示 → 使用问题答疑 | 规格、限制、价格版本；没有旧款测试不宣称提升比例 |
| 新店开业 | 位置、服务、能否体验 | 核实地址与开放安排 → 门头/服务过程 → 常见到店问题 | 地址、营业时间、预约规则；首客/排队未采集不编故事 |
| 产品或功能发布 | 解决哪种任务、怎么开始 | 任务与范围 → 可复现操作 → 故障/限制/帮助 | 版本、可用范围、操作证据；演示环境标明演示 |
| 周年庆 | 与自己有关的变化 | 已确认权益 → 实际服务/核销过程 → 改进及到期提醒 | 起止时间、权益条件、历史记录；不能借庆典编年限 |
| 搬址或改装 | 去哪里、服务是否受影响 | 迁移安排 → 新旧动线/识别 → 到达方式与遗留事项 | 新地址、停业/复业安排；不默认服务和价格不变 |
| 设备或工艺更新 | 可处理范围、限制是什么 | 为什么需要 → 可公开的工序 → 经核实的能力说明 | 设备用途与验证条件；采购设备不等于质量或产能提升 |
| 资质、获奖或媒体报道 | 证明了什么、适用多大范围 | 证书/报道来源 → 解释范围 → 回答核验方法 | 名称、颁发方、有效期、原始报道；不扩为行业第一 |
| 团队培训 | 哪个服务环节会改变 | 需要解决的问题 → 练习片段 → 实施记录 | 培训内容、实际落地；上过课不等于效果已实现 |
| 节日促销 | 怎么算价、何时结束 | 清楚列规则 → 核验规则执行 → 售后及截止说明 | 价格基准、库存、限制；不能自造稀缺或延期承诺 |
| 客户答谢与回访 | 旧问题是否处理 | 核对历史需求 → 获授权的回访过程 → 处理结果 | 真实关系、反馈、公开许可；私聊对象不是虚构名单 |
| 外出学习或考察 | 对服务有何实际帮助 | 收集客户待解决事项 → 记录方法 → 验证落地变化 | 学到的方法与实做证据；合影不作为能力证明 |
| 讲课或首次直播 | 是否值得花时间 | 议题/时间/参与方式 → 可公开片段 → 问题补答 | 实际议程与讲者身份；不编听众反馈 |
| 客户来访或验厂 | 能看到哪些可核对环节 | 确认可拍范围 → 展示过程 → 回答未解决事项 | 来访许可、工艺范围、隐私边界；意向不等于订单 |

## 参展：两个人怎样取舍

先分清是设展接待、观展调研还是登台分享。只知道“参展”时，先按有现场内容可采集来规划，不假设面积、展期或客户类型。问目标人群与主要目的时一起补齐，不能因为缺画像而暂停出地图。

两个人的基础包以“找得到、看得懂、问得上”为主：B 拍已核实的识别信息，A 接待；没有接待任务时 A 口播、B 收声。真实问题先记文本，获准后再拍问答。样品演示不是必有素材，没有可公开实物就换资料核对画面。

当只剩一人可拍，撤下移动跟拍与客户出镜任务，保留固定镜头、问题笔记及收展自述。拍不到客户就写无客户故事版本，不找人扮演。现场订单、提问次数、展会优惠延续等必须采集后核实，不能预写成结果。

## 上新、开业和发布的差别

上新要交“适合/不适合、怎么用”，拍实物和条件一致的差别；开业要交“怎么去、怎么体验”，拍识别与服务动线；功能发布要交“输入什么、得到什么、哪些限制”，拍可复现操作。不能只把参展稿里的“展位”换成“门店”或“功能”就当另一份策划。

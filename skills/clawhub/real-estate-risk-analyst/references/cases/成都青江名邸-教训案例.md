## 0. 一句话总结

成都项目是「公开信息公示页 + 认证 SPA 双系统并存」的典型：先误判"成都不公开逐套"，后在用户截图推动下于公开 `infoDetail` 页找到完整一房一价；又因"分母选错"差点得出错误覆盖率，最终用 **B 方案（补全官方预售方案口径）** 解锁双口径货值。

## 1. 项目背景与目标

- **目标**：检索成都金地·青江名邸最新房源（同深圳/佛山批次口径），产出 Excel + Word 报告。
- **平台**：成都市住建局"蓉e办" `blmp.cdzjryb.com/fplc_daas_portal` + 一房一价 `zw.cdzjryb.com/roompricezjw`。
- **推进阶段**：A 方案（逐套抓取 1254 套）→ B 方案（官方预售方案补全）→ 套数差异复盘（1573 vs 1254）→ 2.0 双口径货值报表。

## 2. 技术路径（已验证可复用）

### 2.1 infoDetail 公开信息页（无需登录 / 验证码）

- 按项目名搜索 → 返回含「一房一价」「预/现售方案」详情链接的表格。
- 点「一房一价 详情」→ 跳转 `roompricezjw/index.html?param=<token>` 逐套页。
- **关键认知**：成都有**两套系统**——公开 `infoDetail`（有完整逐套）+ 认证 CAS SPA（详情页 `getWebPreSellInfo` 只返项目级汇总）。先撞上的若是后者，极易误判"不公开逐套"。**务必先试公开页。**

### 2.2 roompricezjw 逐套页（scrape 渲染后 table）

- 楼栋 tab `.rp-nav-item[data-val="HNO"]`，单元 tab `.rp-subnav-item[data-val="UNO"][data-parentval="HNO"]`，`.on` 类标记当前选中。
- API：`getHnoAndUnos`（楼栋/单元列表，明文 JSON）/ `getFloorEstateOfViews`（逐套，加密/Base64 但页面 JS 解密渲染到 table）→ **直接 scrape 渲染后的 `<table>` DOM 比解密 API 更稳**。
- 全量遍历：逐楼栋 × 逐单元，每次切换 `wait_for_response("getFloorEstateOfViews")` + 渲染等待。

### 2.3 预/现售方案 modal（B 方案核心入口）

- 在 infoDetail 点「预/现售方案 详情」→ 弹出 `ant-modal`，内含**官方预售均价、应售套数、预售建筑面积**（权威口径，来自住建部门备案底单）。
- 采集器 `collect_presell.py` 抓 7 证 modal：`probe_presell.py` 探入口 → `collect_presell.py` 循环抓（循环内**重定位**避免 stale DOM + 等 `Loading` 占位消失）→ `presell_plans.json`。
- 官方口径实测：住宅 8242–9800 元/㎡、商业 16624–18759 元/㎡；**预售建筑面积 110,675 ㎡**。

## 4. 套数差异复盘（1573 vs 1254）—— 最重要的新教训

- **触发**：用户截图显示备案面积对应 **1573 套**，本次实抓 **1254 套**，质疑"是否上次就错 / 本次抓少了"。
- **初步分析**：三向对比（备案面积 / 本次 1254 / 历史 1573）+ 面积锚定，起初用"项目总建面 123,867㎡"减逐套面积，得出"缺口 38%"。
- **纠错（关键）**：38% 缺口系**错用分母**——"项目总建面"是项目整体口径，而本次抓取目标是**预售范围**。正确分母应为"预售建筑面积 110,675㎡"。覆盖率 = 1254 套对应面积 / 110,675 ≈ **69.4%**。
- **结论**：本次抓取覆盖预售范围约 7 成，并非"抓少了"；差异源于"预售范围 vs 项目整体"口径不同，属正常。
- **⭐ 教训（可迁移）**：**覆盖率/缺口的分母必须严格匹配"抓取目标的范围"**。拿"总建面/全项目"当分母会系统性高估缺口、制造虚假焦虑。复盘文档已第七章更正，不掩盖。

## 5. B 方案 = 长远更优（双口径货值）

- **问题**：单靠逐套 `***` 价（已售/已备案不公开），主口径货值 = 0，交付物"主口径货值"死穴。
- **B 方案解锁**：用官方"预/现售方案"modal 的**预售均价 × 预售面积** → 得到"官方备案货值"权威口径。
- **双口径互证**：
  - **官方备案货值 ≈ 9.25 亿**（预售均价 × 预售建筑面积，权威但仅覆盖预售范围）
  - **实测货值 ≈ 3.08 亿**（一房一价逐套清水价，仅可售/期房公开价部分）
- 二者不矛盾、互证，并**诚实标注覆盖率 69.4%**，无造假、无归零掩盖。

> ⭐ **可迁移 SOP**：凡遇"逐套价不公开导致主口径货值=0"，先查官方"预/现售方案/价格备案公示"等 modal/栏目，拿权威预售均价解锁"官方备案货值"口径，再与实测逐套货值并列呈现（双口径）。这就是 skill 主文档 SOP 第 8 步"两级回退"在成都场景的**官方级补充**。

## 6. 可迁移教训（元级 · 供新城市/项目查用）

1. **绝不下"数据不可得"的过早结论**（skill 经验教训 #1）：某路径只返项目级汇总 ≠ 平台不公开逐套，很可能存在另一套独立系统。
2. **用户在线所见 = 最高优先级信号**（#2）：用户说"看到更多、不需登录"→ 立即回平台重探，不以"平台规则"驳回。
3. **公开页优先于登录/SPA**（#3）：政府平台普遍有公开公示页 + 认证 SPA 两套，先试公开页。
4. **roompricezjw 模式可跨城市复用**（#4）：楼栋/单元 tab + 渲染后 table DOM scrape + 每次切换 `wait_for_response`。
5. **⭐ 分母对齐（本案新）**：覆盖率/缺口分母必须严格匹配"抓取目标范围"，错用总建面会系统性高估缺口（本案 38%→69.4% 更正）。
6. **⭐ 双口径货值（本案新）**：逐套价不公开时，用官方预售方案均价解锁"官方备案货值"口径，与实测货值互证，诚实标注覆盖率。
7. **⭐ 复盘诚实更正（本案新）**：发现分母/口径错立即在交付物更正并说明，不掩盖、不悄悄改数。

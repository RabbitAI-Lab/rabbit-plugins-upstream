# 深圳·皇熙悦府（卓越缦悦） 教训案例（2026-08-14 实战复盘）

> 本文是「房地产备案信息查询」skill 的**第二个完整案例资产**，聚焦一个此前未暴露的新坑：**复用同一采集器给不同项目时，旧项目数据会静默污染新项目 Excel**。它把一次真实临场任务的「踩坑 → 定位 → 修复 → 复盘 → 提炼」闭环沉淀为可迁移方法论，供后续 33 城批量复用采集器时直接查用。
> 定位：**方法 + 教训**，不是脚本仓库。本案的 Python 脚本（`run_manyue.py` / `external_prices_皇熙悦府.json`）留在工作区根目录，本文只沉淀可复用路径与教训。

---

## 0. 一句话总结

用「猴子补丁 wrapper」零改动复用 `fetch_house_data.py`（晟悦家园采集器）给新项目皇熙悦府采集时，首次成品 Excel 的「外部渠道价格交叉验证」Sheet 误用了晟悦家园（坪山，≈2.2万/㎡）的外网价，且 Sheet 标题/对比行硬编码旧项目名，导致福田项目算出 80.6% 折让等荒谬结论——**根因是采集器对"当前项目"非 project-agnostic**；修复后改为项目无关 + 专属外网价文件，全表扫描旧项目关键字归零，折让修正为符合福田实际的 11.5%。

## 1. 项目背景与目标

- **目标**：采集深圳「卓越缦悦（皇岗村）」去化情况，产出 8-Sheet Excel（临场任务，非定时自动化）。
- **平台**：深圳市房地产信息平台 `fdc.zjj.sz.gov.cn/szfdcscjy/`（Vue SPA + 动态 token，须 Playwright 拦截响应）。
- **关键认知（深圳特有）**：用户给的"卓越皇岗村缦悦"是**营销名**，平台按**备案名**检索——备案名为**皇熙悦府**；直接搜"缦悦/皇岗村/卓越皇岗"均搜不到，必须搜"皇熙悦府"。预售证 深房许字（2025）福田008号，ysProjectId=36646 / preSellId=142072，开发商 深圳卓越皇岗旧城改造有限公司，2025-11-08 首推 1栋5单元 231 套。

## 2. 技术路径（已验证可复用）

### 2.1 营销名 → 备案名（跨项目第一关）

- 深圳平台**只认备案名**。用户口语/营销名（如"卓越缦悦""缦悦"）在平台搜不到。
- **修复法**：用 WebSearch 查"卓越皇岗村缦悦 备案名"，确认 = 皇熙悦府，再回平台搜"皇熙悦府"命中。
- ⭐ 可迁移：凡用户给的是营销名/推广名，先核实备案名再检索，不要反复试错营销名。

### 2.2 零改动复用采集器（猴子补丁 wrapper）

- 原 `fetch_house_data.py`（1900 行，8-Sheet 生成 + 两级回退剩余货值 + 外部价格交叉验证）硬编码晟悦家园。
- 新建 `run_manyue.py` 仅覆盖三个全局变量，**不改动原脚本**：
  ```python
  fh.PROJECT_NAME = "卓越缦悦（皇熙悦府）"
  fh.PERMITS = [{"ysProjectId": 36646, "preSellId": 142072,
                 "presell_no": "深房许字（2025）福田008号", "url": "..."}]
  fh.HISTORY_FILE = fh.HISTORY_DIR / "snapshots_皇熙悦府.json"  # 历史快照按项目隔离
  fh.EXTERNAL_JSON = HERE / "external_prices_皇熙悦府.json"     # 本项目专属外网价
  asyncio.run(fh.main())
  ```
- 历史快照按项目隔离（`snapshots_皇熙悦府.json`），避免跨项目 delta 误报。

## 4. 跨项目数据污染（本案最重要新教训）

- **触发**：首次生成的 Excel 里「外部渠道价格交叉验证」Sheet 出现"坪山004/014号""390套""2.1–2.3万/㎡"等明显属于晟悦家园（坪山）的内容，而本项目是福田，备案均价 11.5万/㎡——数据完全错位。
- **定位**：
  1. `fetch_house_data.py` 固定读 `OUTPUT_DIR / "external_prices.json"`，**不随项目切换**；该文件是晟悦家园专属，皇熙悦府 run 静默继承。
  2. `add_external_sheet` 的对比行/结论/背景**硬编码**了"2栋(深房许字2025坪山004号)""390套""63.3%""2.1–2.3万"等晟悦家园专属值。
  3. 至少 3 个 Sheet 的 A1 标题写死"晟悦家园"。
- **修复（已落地脚本，对晟悦家园同样更优）**：
  1. `add_external_sheet` 改 **project-agnostic**：对比行由 `permit_details` 逐楼栋动态生成（`permit_map` 取各栋备案均价），结论/背景中的"缺失价套数占比"由房源实际缺失计数动态计算，来源标注用 `tag` 变量。
  2. **全部 Sheet 标题 A1** 由写死"晟悦家园"改为 `f"{PROJECT_NAME} ..."`。
  3. 新建项目专属外网价文件 `external_prices_皇熙悦府.json`（真实福田市场价：乐有家在售≈10.2万、开发商备案 11.41–11.5万、周边二手 9.8–15万），wrapper 中 `fh.EXTERNAL_JSON = HERE/"external_prices_皇熙悦府.json"` 覆盖。
- **校验**：全表扫描"晟悦家园/坪山"关键字 = **0 命中**；外部折让修正为 **11.5%**（全量）/ 11.3%（1栋），符合福田实际。
- ⭐ **教训（可迁移）**：复用采集器给任一新项目时，必须 (a) 覆盖 `EXTERNAL_JSON` 指向本项目外网价 JSON；(b) 先确认脚本已 project-agnostic（标题/对比行无写死旧项目名）。否则旧项目数据会静默泄漏进新项目 Excel，且**不会有任何报错**——是"看起来成功但结论错误"的隐性坑。

## 6. 可迁移教训（元级 · 供 33 城批量查用）

1. **⭐ 跨项目文件隔离（本案新）**：复用采集器给新项目，必须按项目隔离三样东西——`EXTERNAL_JSON`（外网价）、`HISTORY_FILE`（快照）、`PROJECT_NAME`（标题）。旧项目 JSON 静默泄漏是"无报错但结论错"的隐性坑。
2. **⭐ 采集器须 project-agnostic（本案新）**：标题/对比行/结论中任何"旧项目专属值"（楼栋、证号、套数、价格）一律改为由本项目 `permit_details`/实际计数动态生成，杜绝硬编码。
3. **⭐ 交付前全表扫描旧项目关键字（本案新）**：每次复用产出后，用 openpyxl 遍历所有 cell，扫 `旧项目名/旧城市` 关键字，命中即回退重做——成本极低、能挡住 80% 的污染事故。
4. **营销名 ≠ 备案名（深圳）**：用户给营销名时先核实备案名再检索，不要反复试错营销名（本案搜"卓越"返回 31 个老项目纯属浪费）。
5. **API 拦截不稳时回退 DOM scrape**：深圳 SPA 列表 API 常返回 `data:null`，直接 scrape `li.project-li` 卡片更稳。
6. **DOM 卡片靠 Vue @click**：JS 内 `el.click()` 不触发路由，须 Playwright 真实点击 + `wait_for_url` 取详情页 URL 提取 ID。
7. **任务性质要分清**：本任务是临场指令（皇熙悦府），非「晟悦家园自动化（automation-1786070770715，PAUSED）」触发——结果**不写入该自动化 memory**，以免污染其专属执行历史，改记今日工作日志。

# 按企业检索 · 授信级尽调报告模板

> 适用：检索锚点是「企业」（品牌方 / 开发商 / 合作方）时的产物标准化。
> 目的：把五阶段 SOP（P0–P4）的产出收敛为**可采信、可复核、可移交**的授信尽调底稿，避免每次从头拼装。
> 配套 SOP：SKILL.md「按开发商/品牌/合作方检索专项方法论」（五阶段 + 四红线）。已实证案例：广州·鹏瑞/壹湾广场、贵阳·万科（麓山/5 盘 55 本）、深圳·金地（3 盘股东非金地）。

## 1. 主体界定与口径（P0）

- 检索锚点类型：**品牌方**（如万科/鹏瑞）/ **开发商**（直接登记主体）/ **合作方·股东**（合营/联营）
- 交付物粒度与口径（证级批准量=供应口径；网签=成交口径，**二者不可相减推库存**）
- 明确「要查的是该主体名下全部存量，还是特定城市/时间窗」

---

## 2. 工商穿透：品牌 ↔ 备案法人映射表（P2 · 胜负手）

> **红线 2**：必须穿透到**项目公司（备案主体）**；合营盘按母品牌企业名查必然漏（万科贵阳 4 盘、金地深圳 3 盘均因此「查无此盘」）。

| 品牌/母主体 | 项目公司（备案主体） | 关系 | 股权比例 | 穿透渠道 | 备注 |
|------------|-------------------|------|---------|---------|------|
| | | 全资/合营/联营/区域平台 | | [MCP·预警通]/[neodata]/[工商·…] | |

- **降级规则**（财汇MCP 失效时强制 fallback，穿透动作不可省）：
  1. 首选 **neodata**（WorkBuddy 企业数据连接器）
  2. 次选 国家企业信用信息公示系统 / 天眼查 / 企查查
  3. 兜底 WebSearch 定向「公司名+股东+股权」，并注明「置信度有限」
- 来源标注随渠道切换：`[MCP·预警通]` → `[neodata]` / `[工商·公示系统]` / `[工商·天眼查]`

|-------|-------|---------|---------|---------|---------|------|---------|---------|
| | | | | | | | | |

- 来源着色：**官方绿底 `C6EFCE`**；标注 `[官方·筑房网/阳光家缘 YYYY-MM-DD]`
- 分用途批准套数/面积（如 `sellSummaryList`）为**供应口径**，单列不混用

## 4. 深挖目标盘（P4 · 绿底/黄底）

- 逐套销控（广州可行、贵阳锁登录）、网签去化（周/月榜、外网成交）
- 着色：**绿底=官方、黄底=外网**
- 状态码图例须核验（如广州 1可售/2已售/3已备案/4已过户/5不可售）

---

## 5. 交叉校验与尽调红旗

- **背书校验**：官方住宅批准套数 vs 外网宣称总户数，**差异 ≤30% 可反向背书外网体量可信**；>30% 则外网口径可疑
- **红旗标注**：web 列出但官方库查无的盘 → **红底「官方查无，营销口径不可采信」** + 区位反查证据（如阅山湖=中铁系、老湾塘=安置房）
- **口径声明**：供应(批准) ≠ 成交(网签)；网签均价高于挂牌属结构/计价差异，不可直接读成「涨价」

---

## 6. 授信结论与风险要点

- **真实官方在售/在途盘数量**（以官方证级库为准，**非 web 营销口径**——万科贵阳 web 9 盘 → 官方仅 5 盘有证级）
- 风险要点（按案例沉淀，挑适用的）：
  - 区域集中度（如万科贵阳 6/9 盘集中云岩三马）
  - 价格带同质承压（如 1.0–1.2 万/㎡ 多盘重叠）
  - 商办/公寓占比与抵押流动性（如鹏瑞壹湾广场服务型公寓=商业 40 年产权）
  - 去化口径冲突（外网营销注水 vs 官方网签，须以官方为准）
  - 数据缺口与不确定性（如备案价缺失须外网补价）

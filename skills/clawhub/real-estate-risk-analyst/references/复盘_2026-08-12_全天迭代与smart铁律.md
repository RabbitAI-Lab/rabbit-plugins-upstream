## 2. 六大工程铁律（smart 提升点 · 每条含 现象/根因/修法/可迁移）

### 铁律 1 ⚠️ 前端交互必须真浏览器验证，绝不只验 API
- **现象**：城市下拉用 `<input list="cityList">`（datalist），我只用 curl/Python 验证了后端 API（`/api/cities` `/api/districts` 全绿）就交付，结果用户实测"点击城市框毫无反应"。
- **根因**：datalist 的浏览器行为是"**只在输入框打字时才弹选项，单纯点击输入框不会展开**"。我只验了数据通路，没验真实 UX，漏掉了这个差异。
- **修法**：用 Playwright + 本地 Chromium 真跑一遍**点击 → 输入 → 联动 → 查询**，断言下拉是否展开、选项是否回填、区域是否联动、控制台是否报错（`gui_desktop/verify_ui.js` 即此回归脚本）。复验全绿、零报错才交付。
- **可迁移**：今后凡涉及任何前端/UI 交互（下拉、按钮、表单联动、弹窗），交付前**必须真浏览器跑一遍交互路径**，不能只测后端接口或只 `py_compile`。这是今天最大的 smart 提升点。

### 铁律 2 轻量分发工具优先"零依赖 Web 版"，而非 tkinter
- **现象**：第一版桌面程序想用 tkinter 做原生窗口，但 WorkBuddy 沙箱里的精简 Python **没有 Tcl/Tk**，导致 `main.py` 无法在沙箱内渲染验证；而用户本机/其他机器也可能缺 tkinter。
- **根因**：tkinter 是 GUI 绑定，依赖系统 Tcl/Tk 库，便携/精简 Python 常缺失；跨机部署怕缺包、沙箱无法验证。
- **修法**：改用 **标准库 `http.server` + `webbrowser.open` 的本地 Web 版**（`webui.py`）：任何装了 Python 的机器都能跑，且沙箱内可实跑验证（启动服务 + 请求 API + 断言响应），跨平台零额外依赖。
- **可迁移**：需要给"非技术同事/客户也能跑"的轻量工具时，优先本地 Web 版（Python 标准库即可），而非原生 GUI 库。tkinter 仅在确认目标机自带 Tk 时作可选方案。

### 铁律 3 依赖联动下拉用"自定义 combobox"，不用 datalist
- **现象/根因**：同铁律 1，datalist 点击不展开，无法满足"输入城市后自动展示行政区域下拉"的诉求。
- **修法**：自定义 `<input id="city">` + `<div id="cityList" class="combo-list">`：focus/click 即展开全量（前 N 条防卡）、input 实时筛选、选项 `mousedown`（preventDefault 防失焦）回填并触发联动、blur 延时关闭。未知项保留自由输入 + 手动输入 fallback，不阻断流程。
- **可迁移**：任何"可点开 + 可输入 + 联动下级"的选框，用自定义 combobox 比 datalist 可控；datalist 只适合"纯打字联想"场景。

### 铁律 4 设计从"用户真实使用场景"出发，不从"实现便利/当前能力"偷懒
- **现象**：最初把城市做成"33 城固定下拉"，理由是"skill 只适配了 33 城采集器"。用户反问"为啥只能限定这 33 家？不可作为输入项吗？"。
- **根因**：我把"采集适配范围"错误地当成了"查询输入限制"。用户要的是"别人也能查"的通用工具，城市本就该是自由输入项。
- **修法**：城市数据源换成民政部行政区划（340 城），做成可自由输入的联想框；33 城不再限制输入，只作为"已适配采集"的**提示标记**（蓝/灰 tag）。
- **可迁移**：功能边界由**需求/用户视角**定，不由"当前已实现的能力"定。当你想用"我们目前只支持 X"来限制输入时，先问"用户是不是其实想要 Y"。

### 铁律 5 复盘发现错误立即诚实更正，不掩盖
- **现象**：套数差异复盘时曾错用"项目总建面 123867㎡"作分母，算出逐套覆盖仅 62%、缺口 38%。
- **根因**：混用了"总建面/计容面积（含自持+不可售）"与"预售建筑面积（可比分母）"。
- **修法**：发现后立即在文档更正——正确分母是预/现售方案的**预售建筑面积 110675㎡**，覆盖率 69.4%（非 62%），并在案例库第 14 条明确标注"复盘诚实更正"。
- **可迁移**：复盘/报告中一旦发现此前结论有误，**当场更正并显式标注**，错误更正本身也是可复用资产；不要留着错误版本等别人发现。

### 铁律 6 实验性分支及时止损，回归主线
- **现象**：桌面程序开发到可运行、用户也试用并反馈了 bug，但用户最终判定其为"实验性项目"，要求"暂时搁置，还是用回 WorkBuddy 运行"。
- **根因**：该工具并非当前核心交付（核心是 skill 内采集 + 双件套），属于锦上添花的分发包；继续投入 live() 接入/打包会偏离主线。
- **修法**：立即**归档经验**（本文件 + SKILL.md 铁律）、保留代码资产但不再作为主线推进，**回归 WorkBuddy 内运行**的成熟工作流，不沉没成本、不强行说服用户。
- **可迁移**：用户说"搁置/先不弄/回归原方式"时，果断收口、沉淀经验、不恋战；把精力放回主线高杠杆任务。

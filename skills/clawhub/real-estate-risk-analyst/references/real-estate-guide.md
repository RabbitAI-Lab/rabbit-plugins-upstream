# 房地产项目采集 — 技术参考（深圳平台已验证）

> 方法论跨城市可复用；以下具体 API / 字段以深圳平台为基准，换城市按同法重新探查。

## 一、可直接套用的任务提示词（复制粘贴，替换 { } 占位）

```
角色：房地产房源数据采集与可视化分析助手。

任务：采集 {城市}{平台名称} 上「{项目名称}」的全部房源数据，生成可视化、可检索的 Excel，并做简版分析总结。
目标平台：{平台域名，如 fdc.zjj.sz.gov.cn}
项目名：{项目名称}

执行要求（务必遵守，避免走弯路）：
1. 平台为 Vue SPA + 动态 token 保护，纯 HTTP 直连不可用 → 必须用 Playwright 浏览器自动化，用 page.on("response") 拦截 API 响应提取数据。
2. 【关键】先找"项目列表/搜索页"拦截其列表 API，按项目名搜索，一次性拿到该项目名下【所有预售证】及其 ysProjectId / preSellId（一个项目常有多张预售证，且各证 ysProjectId 可能不同，漏证会丢楼栋）。
3. 逐张预售证访问详情页，拦截房源列表 API，提取全部房源。
4. 房源 API 响应通常是【按楼层分组】结构（data:[{floor, list:[house,...]}]），提取时必须遍历 data[].list，不能当扁平 list。
5. 字段映射按实际 API 响应校准（楼栋/楼层/房号/建筑面积/套内/分摊/备案总价/备案单价/状态/合同编号）。
6. 价格行为：很多平台只给"期房待售"公开备案价，已备案/已售等不公开 → 缺失价属正常，勿当异常；缺失单价可用 总价/面积 回算。
7. 每次采集把当前聚合（总套数、各状态计数、均价、按 日期/周/月/季 分桶）写入 history/snapshots.json，用于跨期对比与突变检测。
8. 异常检测：对比上一快照，监控 总套数/期房待售/备案均价 突变；区分"异常/提示"两级；首跑无基准不报。
9. 生成 Excel（≥6 Sheet）：预售许可证清单（证号/项目名/区域/地址/用途/开发商/预售面积/日期/监管银行/账号）、房源明细（可筛选/条件格式）、统计分析（图表）、剩余货值测算（排除已售/已备案，可售取挂牌价求和，签约中用均价估算，按用途分列）、分析总结、异常与告警。
10. 日常执行优先用免费或经济模型；但**⚠️ 自动化(automation)的 modelId 不能设为 "lite"**——"lite" 是 Agent 工具变体名，自动化运行时不认，会导致定时任务启动失败、完全不执行。自动化 modelId 用 "default" 或具体模型标识符；交互式 Agent 调用可用 model:"lite" 省钱。

交付物：output/{项目名}_房源数据_*.xlsx + 简版分析总结。
```

## 二、标准作业流程（SOP）

| 步骤 | 动作 | 要点 |
|---|---|---|
| 1 | 定位列表/搜索入口 | 找"项目列表/在售楼盘搜索"页（哈希路由或独立路径），拦截其列表 API |
| 2 | 搜索项目名 → 拿全部预售证 | 列表 API 返回 项目ID(ysProjectId) + 预售证ID(preSellId) + 预售证号；逐条记录，别漏证 |
| 3 | 逐证访问详情页 | 用 `详情页URL?项目ID&预售证ID` 构造地址，拦截房源 API |
| 4 | 拦截并提取房源 | `page.on("response")` + 关键字过滤；解析响应，遍历楼层分组拿房源 |
| 5 | 标准化字段 | 统一映射到 楼栋/楼层/房号/面积/价格/状态/合同编号 |
| 6 | 写历史快照 | 聚合写入 `history/snapshots.json`（存聚合不存全量） |
| 7 | 生成 Excel + 分析 | 预售许可证清单 / 房源明细 / 统计 / 剩余货值测算 / 总结 / 告警 六 Sheet |
| 8 | 剩余货值测算 | 排除已售/已备案，可售取挂牌价求和，签约中用均价估算，按用途分列 |
| 9 | 异常与对比 | 用上一快照做 delta；日/周/月/季四维度对比 |
| 10 | 预售信息失真核查（现楼/商办/开发商风险必做） | 状态语义校验(首次登记≠已售) + 查封不体现校验 + 财汇MCP查开发商风险(不含房产抵押) + 查册/法院公告交叉验证；产物单列「预售信息失真核查」Sheet，修正"剩余货值=0"误述 |

## 三、关键技术参考（深圳平台已验证，作探查基准）

- 平台：`fdc.zjj.sz.gov.cn/szfdcscjy/`（Vue SPA，哈希路由 `#/...`）
- 项目列表页：`#/foreignPublic/listApartmentHunting/listApartmentHuntingSj`
  - 列表 API：`/ysf/publicity/getYsfYsPublicity`（**POST**）
  - 默认 body：`{"pageIndex":1,"pageSize":12,"total":0,"zone":""}`；**按开发企业搜索加 `organName`**：`{"organName":"深润川","pageIndex":1,"pageSize":12,"total":0,"zone":""}`
  - 页面搜索：3 个 el-form-item 顺序 = 0项目名称/1开发企业/2宗地地址；JS `document.querySelectorAll('.el-form-item')[1]` 定位开发企业输入框，原生 setter 填值 + input 事件后点「查询」按钮
  - 返回关键字段：`sypId`=ysProjectId，`sypeId`/`id`=preSellId，`strpreprojectid`=预售证号，`project`=项目名，`name`=开发企业，`zone`=区域，`passdate`=发证日期
  - ⚠️ 列表为"预/现售项目公示"，仅含仍挂网项目；已完全办结/注销的旧证可能不在列（存量项目核查以搜到的为准，另辅以外网佐证）
- 详情页 URL 格式：`#/projectTable/projectTableDetails/projectTableDetails?ysProjectId={id}&preSellId={id}`
- 楼栋枚举 API：`/projectPublish/getBuildingNameListToPublicity` → `data:[{label:楼栋名, value:buildNo(19位), key:fybId(5位), acive:false}]`
  - **fetch 房源接口必须用 5 位 `key` 作 fybId；19 位 `value` 会返回 500「程序异常」**（2026-08-11 深润川实测）
- 单元/楼层枚举 API：`/projectPublish/getBuildingDictToPublicity` → `data:{buildNo(19位,对应楼栋value), gnqmcList:[单元名...], chList:[楼层...], zrzid}`
  - ⚠️ 这两个枚举接口 **fetch 直连会 500**，只能拦截页面自动发起的响应来解析（不传参数，依赖页面选中状态）
  - **单元关联规则**：`data.buildNo`(19位) 匹配楼栋 `value` → 得 5 位 `key`；`gnqmcList` 为真实单元名（中文数字"一单元"或"商业/未知"均照传，勿兜底"1单元"——传错单元名返回 200 空 data）
- 房源核心 API：`/projectPublish/getHouseInfoListToPublicity`（**POST**，动态 token，可 fetch 逐单元取数）
  - 请求体：`{buildingbranch:"X单元", floor:"", fybId:"楼栋ID", housenb:"", status:-1, type:"", ysProjectId, preSellId}`
  - **默认只返回 1单元**；必须对每个 `(楼栋, 单元)` 各 POST 一次
- 响应结构：`{status, msg, data:[{floor:N, list:[house,...]}, ...]}` —— **按楼层分组**
- 字段映射（原始 → 输出列）：
  `buildingName`→楼栋 · `buildingbranch`→单元 · `floor`→楼层 · `housenb`→房号 · `useage`→用途 · `ysbuildingarea`→建筑面积 · `ysinsidearea`→套内面积 · `ysexpandarea`→分摊面积 · `askpricetotalB`→备案总价 · `askpriceeachB`→备案单价 · `lastStatusName`→状态 · `strcontractid`→合同编号
- 状态取值（实际，比文档更全）：期房待售 / 已签认购书 / 已签合同 / 已备案 / 首次登记 / 已录入合同 / 司法查封 / 安居房 / 在建抵押 / 自动锁定 / 区局锁定 / 市局锁定 / 共有产权房
  - 去化口径：`去化 = 总套数 − 期房待售`（其余状态均视为已去化）
  - **⚠️ 失真风险（翠湖大厦实测，2026-08-10）**：①「首次登记」是开发商**初始登记/大确权**状态（取得大产证后方可现售），**≠ 交易完成(已售)**；现楼项目大量「首次登记」房源实际仍在开发商名下可售，切勿直接计入「已卖掉」并得出剩余货值=0。② 平台虽把「司法查封/在建抵押」列为状态取值，但**仅当具体房源被司法查封时才显示**；项目级/开发商级的查封与债务限制**不在单套状态中体现**。翠湖 528 套 lastStatusName 全为「首次登记/已备案」、零「司法查封」标识，与其开发商失信被执行（企业预警通核实）的实际风险明显背离——属典型信息失真。③ 准确判断须深圳市不动产登记中心「查册」或法院查封公告逐套交叉验证。
- 价格行为：仅"期房待售"公开备案价，其余不公开属正常；缺失单价用 总价/面积 回算
- **实测案例（绿景白石洲璟庭，深房许字（2023）南山012号）**：1栋 5 单元共 **2746 套**（预售总套数亦为 2746）；单元分布 1单元453/2单元1036/3单元430/4单元441/5单元386；用途 商务公寓1489+住宅1257；状态 已备案1381/首次登记1357/司法查封7/已签合同1；期房待售0（去化100%）。**只取默认 1单元会漏 2293 套（84%）**——务必逐单元全量抓取。

## 四、可复用脚本骨架（fetch_house_data.py 已落地）

换项目时只改配置与字段映射，逻辑零重写：

- `PERMITS` 列表：每项含 `ysProjectId / preSellId / presell_no / url`，遍历采集即自动覆盖多证多楼栋
- `compute_snapshot(houses, now)`：聚合为紧凑快照（总套数/状态计数/均价 + `date/iso_week/month/quarter` 分桶）
- `load_history()/save_history()`：读写 `history/snapshots.json`（按日期+小时去重、同小时只留最新、最多留 1000 条）
- `find_baseline(history, now, kind)`：取 日/周/月/季 对比基准
- `detect_anomalies(...)`：对比上一快照做突变检测，分 `异常/提示` 两级
- `add_comparison_sheet()`：Excel「数据变化对比」Sheet
- `add_alert_sheet()`：Excel「异常与告警」Sheet（价格缺失区分 待售缺失/非待售不公开）
- Excel 五 Sheet：房源明细 / 统计分析 / 分析总结 / 数据变化对比 / 异常与告警

## 五、避坑清单（省 token 关键）

1. 列表页先于详情页：详情页 API 只返回当前预售证数据，从详情页永远挖不到"其他证/其他楼栋"。找全预售证必须走列表搜索 API。
2. request/response handler 用 `x.url`，不是 `x`（Request/Response 对象不可直接 `in` 字符串，否则 TypeError）。
3. 响应按楼层分组：extract 必须遍历 `data[].list`。
4. 价格缺失别误报：非待售不公开备案价是平台规则，不是数据损坏。
5. **⚠️ 房源接口默认只返 1单元**：`getHouseInfoListToPublicity` POST 带 `buildingbranch`，页面默认选中 1单元；必须枚举全部楼栋+全部单元、逐 `(楼栋,单元)` POST 取数并去重，否则大面积漏栋漏单元（绿景白石洲璟庭漏 84%）。
6. **枚举接口不可 fetch 直连**：`getBuildingNameListToPublicity`/`getBuildingDictToPublicity` 直接 fetch 返回 500，需拦截页面自动发起的响应来解析；仅房源接口可 fetch 逐单元 POST。
7. .doc 提示词文件：editor_sdk 常报 "document is not open"，改用二进制 `UTF-16LE` 解码 + 正则提取。
8. Chromium `__dirlock` 报错可忽略：实际已装在 `ms-playwright/chromium-*`。
9. 新需求先读项目 MEMORY.md：已最小化的关键事实都在里面，别重跑探索脚本。
10. 探索类临时脚本（`explore_*.py`）用完即弃，别进版本/长期记忆。
11. **⚠️ 自动化 modelId 勿用 "lite"**：`"lite"` 是 Agent 工具变体名，自动化运行时不认，设成 "lite" 会导致定时任务启动失败、完全不执行（实测 8/7 设置后 8/8 全天 + 8/9 上午任务全缺席）。自动化 modelId 用 `"default"` 或具体模型标识符；交互式 Agent 调用仍可用 `model:"lite"` 省钱。在确认某 modelId 对自动化有效前，勿盲目设置。
12. **快照按"日期+小时"去重**：`save_history()` 应按 `YYYY-MM-DD HH` 分桶、同小时只留最新一条，避免短时多次运行（手动+自动化撞车）导致快照堆积膨胀。
13. **⚠️ 先找公开入口，CAS/SPA 是 fallback**：很多城市有公开信息页（无需登录/验证码），如成都 `infoDetail` 页可直接搜索项目→点「一房一价」→跳转逐套房源页。**优先走公开页**，只有需要更深层数据（如预售证PDF原文）才走 CAS SPA。别一上来就死磕 CAS。
14. **CAS 平台别用 `page.request`/`fetch` 直打网关接口**：带 CAS 的 SPA，直接 `page.request.get/post` 或 `page.evaluate(fetch)` 打数据接口会超时/`Failed to fetch`（CAS + 同源）。要**驱动 SPA 表单提交**让 SPA 自己走内部 XHR 完成 CAS，再 `page.on("response")` 拦截；真实 API 路径靠 `add_init_script` 钩 `fetch`/`XHR` 发现，别凭路径猜。
15. **验证码先查前端 canvas + Vue `$data`**：很多 SPA 验证码是 `<canvas>` 由组件 `fillText` 前端绘制、值存在 `__vue__.$data` 里，比"明文验证码接口"更通用、更稳，无需 OCR。
16. **逐套房源页 nav 切换三坑**：①点击已激活(`.on`)的nav会清空表格→须检查跳过；②subnav选择器须带 `[data-parentval]` 避免跨楼栋误匹配；③每次点击后 `wait_for_response` + 1.5s 渲染等待。
17. **剩余货值测算**：排除已售/已备案，对可售取挂牌价求和；签约中无价用同用途可售均价×面积估算；按用途分列；无基准价则备注原因。
18. **⚠️ 深圳详情页默认调用可能只返回 1 单元**：`getHouseInfoListToPublicity` 初次加载常只回 1 个单元（绿景白石洲 2746 套只回 1单元453，漏 84%）。**核对单元数**：拦截 `getBuildingDictToPublicity`，看 `data.gnqmcList`（单元名数组）；若 >1 单元，必须逐单元点选/逐单元 POST 全量抓取。**翠湖大厦 `gnqmcList=["未知"]`=单单元，528 即全量**（已验证）。
19. **状态词表随项目不同，勿硬编码 4 种**：深圳实际状态含 期房待售/已签认购书/已签合同/已备案/**首次登记**/已录入合同/司法查封/安居房/在建抵押/锁定 等。剩余货值口径里"已卖出/已登记"类 = `{已备案, 已售, 首次登记}`（用 `SOLD_STATUSES` 常量）；分析总结须**遍历输出全部状态**而非只打 4 种，否则会漏算（翠湖 468 套"首次登记"被漏打即是教训）。
20. **已备案均价基准的两级回退**：逐套已备案价 → 预售证级 `均价`（详情 API `getProjectDetailInfoToPublicity` 的 `均价` 字段）→ 都没有才归零并备注。深圳逐套已备案价通常 `0`/`***`（平台仅公开"期房待售"价），此时预售证级均价是合法基准。
21. **HTML 表格型公示页解析**：部分城市（珠海、苏州发改委）把逐套备案价以静态 HTML `<table>` 发布。表头常跨多行（如珠海第 1 行字段名、第 2 行单位「（㎡）/(元)」），解析时**不能直接用 rows[0]**，必须找到真正同时含「房号 + 建筑面积」的表头行；数据前常有几行项目元信息（开发企业/项目名称/地址/预售证号），需按 `[标签, 值, 标签, 值]` 成对提取。
22. **图片型反爬识别**：宁波 `unit/details?unitGUID=` 返回 `<img src='html2img/...png'>`，备案单价/总价以 PNG 图片渲染，HTML 无文本。遇到此类接口：①记录为「价格反爬，需 OCR」；②先确认其他字段（房号/面积/居室/状态）是否服务端渲染可采；③可尝试找未加密的明文接口或引入 OCR（tesseract/easyocr）。
23. **模板占位符失真**：佛山楼盘详情页顶部「房源总量 680 / 已售 80 / 代售 600」是前端模板硬编码，跨项目完全一致，**不可用**；真实套数须按楼栋逐栋采集后求和。
24. **列表模式陷阱**：佛山楼盘表默认「列表模式」只显示当前楼层 10~20 行，远少于整栋实际套数；须切换到「楼盘模式/视图模式」或调用整栋 API（如 `ajaxToGetHouseModel.do`），并以弹窗/详情数量校验是否完整。
25. **hidden-DOM 静默失真**：佛山楼栋 tab 节点 `offsetParent=null`（被隐藏），用 JS `dispatchEvent` 点击虽返回 HTTP 200，但视图未刷新，导致所有楼栋都返回 1栋数据。解决：直接调用真实 API（从请求监听中捕获），避免依赖被隐藏的 DOM 点击。

- **口径**：剩余货值 = 剩余房源(全部非已备案：可售+签约中) × 基准均价；已备案(已售/真正卖掉)整类排除。

- **⚠️ 已备案均价基准的两级回退**（按此顺序，逐级兜底）：
  1. **优先用逐套已备案房源的备案单价均值**（深圳 `askpriceeachB` / 成都 `挂牌清水价`）。
  2. **若逐套不公开（如深圳仅"期房待售"公开价、已备案全 `0`/`***`）→ 用「预售证级备案均价」作基准**：深圳 `getProjectDetailInfoToPublicity` 详情响应里的 `均价` 字段（如翠湖大厦 = 83019 元/㎡，平台登记的整盘备案均价）即为合法的"已备案均价"。主口径 = 该均价 × 剩余面积。
  3. **若连预售证级均价也没有 → 主口径剩余货值 = 0**，Sheet 备注"无备案价格参考"，同时补「参考口径」= 可售挂牌价之和 + 签约中按同用途可售均价×面积（标注"非备案成交价、仅供参考"）。
- **成都实测**：已售 666 套价格全为 `***` 不公开、且无预售证级均价 → **主口径(已备案基准)剩余货值 = 0**，Sheet 备注"无备案价格参考"；参考口径 ≈ 3.21 亿元（可售均价 5933 元/㎡）。
- **深圳翠湖大厦实测（2026-08-10）**：528 套全部为 首次登记468+已备案60，平台显示「无在售 → 剩余货值=0」。**⚠️ 此结论失真**：①「首次登记」是大确权状态≠已售，现楼语境下大量仍在开发商名下可售；② 开发商深圳市卓创置业为失信被执行人/限高/多起执行（企业预警通核实），第三方渠道显示项目仍在售且存在「工抵房」；③ 平台状态不反映项目级查封。真实剩余货值应远高于0，但受限于平台不公开价格与查封无法精确测算。预售证级均价 83019 元/㎡ 已记入「预售许可证清单」备注。完整失真分析见产物「预售信息失真核查」Sheet。
- **抵押/查封在售房源单独列示**：本次数据中在售(可售/签约中)房源无抵押/查封标注（抵押205/查封9均在已售中，已排除）——若其他项目在售房源含抵押/查封，须单独列示并备注。
- **用途全覆盖**：住宅/公寓/商业/车位全部纳入，不限于住宅。
- **必须含「分用途列示」+「合并汇总」两部分**：分用途表按住宅/公寓/商业/车位逐行给出剩余套数/面积/货值；随后必须有一个**独立的合并汇总（全项目）区块**，明确列出：剩余房源合计套数、合计可售面积、合计可售挂牌货值、合计签约中面积/货值、合计剩余面积、**合计总剩余货值（主口径·备案基准）**、**合计总剩余货值（参考口径）**、以及可售货值+签约中货值之和（总货值·参考口径视角）。两者缺一不可——合并汇总是对外汇报/决策的核心指标。

## 五-C、外部渠道价格交叉验证（政府不公开备案价时必建）

> 晟悦家园（2026-08-11）落地：平台仅公开"期房待售"备案价，390 套已备案/已售不公开 → 用外网交叉验证补全，单独建 Sheet。对应 SKILL.md SOP 第 11 步。

### 触发条件
很多平台仅公开"期房待售"备案价，**已备案/已售房源备案价不公开**（深圳/成都常态）。当存在这类"价格缺口"且占比可观（如 >30%），为补全数据完整性，须用外网交叉验证一二手价格，并在 Excel 单列 **「外部渠道价格交叉验证」** Sheet。

### 外网交叉验证执行流程
1. 用 **WebSearch** 在 贝壳·链家 / 安居客·房天下 / 乐有家 / 吉屋 等渠道搜索，覆盖**一手在售 + 二手挂牌/成交**多个口径，例如：
   - `{城市}{推广名} 二手房 价格 贝壳找房`
   - `{城市}{楼盘} 安居客 坪山区 二手房均价`
   - `{城市}{楼盘} 乐有家 在售 房价`
2. 将结果落盘为 `output/external_prices.json`（脚本 `load_external_data()` 读取），结构：
   - 顶层：`project` / `search_date` / `reason`(缺口说明+占总量比) / `tag`(如 `[外网·WebSearch 2026-08-11]`) / `records[]`
   - 每条 record：`channel`(渠道) / `type`(一手·二手) / `desc`(描述) / `area`(面积) / `unit_price_text`(单价原文) / `unit_price_num`(单价数值,可空) / `total_price` / `date` / `url` / `remark`
   - **来源标注**：外网数据一律标注 `[外网·WebSearch YYYY-MM-DD]`（与用户长期数据标注偏好一致）；外网价为市场挂牌/成交价、非政府备案价，仅作价值量级参考、不构成逐套精确值。
3. 脚本 `generate_excel` 末尾 `add_external_sheet()` 读取该 JSON 追加 Sheet（**文件缺失则跳过，不影响主流程**）。Sheet 含：①补全背景 ②外网采集明细（一手/二手着色区分）③价格口径对比（政府备案均价 vs 外网一手/二手市场均价 + 折让幅度）④交叉验证结论。

### 核心结论模式
市场实际价显著低于政府备案均价时（如深圳 晟悦家园 全量备案 27,437 → 外网约 2.1–2.3 万，折让约 **18.7%**），不公开备案价的已备案/已售房源真实价值应以**市场价代理**；原「剩余货值·参考口径」用备案挂牌价**偏保守（高估）**。

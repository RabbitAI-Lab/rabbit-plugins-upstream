# forklift-expert 使用详解

> 本文件是 SKILL.md 的**补充与扩展**,为 LLM/Agent/集成开发者提供
> 更细颗粒度的使用说明、调用示例、边界条件和故障排查指引。
> 速查请用 [SKILL.md](SKILL.md);深入使用请读本文。

---

## 一、Skill 在系统中的位置

```
用户问题
  ↓
LLM Agent 触发识别
  ↓ (匹配触发词)
forklift-expert Skill 激活
  ↓
读取 SKILL.md → 工作流 → 选择模块文件
  ↓
references/ 下的 14 个模块文件 + 联网检索
  ↓
按输出模板生成回答
  ↓
返回给用户
```

## 三、典型使用场景示例

### 场景 1:用户问品牌(单品牌查询)

**输入**: "比亚迪叉车怎么样?"

**Skill 处理**:
1. 触发词"叉车"命中 → 激活
2. 问题类型识别:品牌/产品类
3. 读 `brands.md` 找到比亚迪叉车条目
4. 查 web_search 补具体型号参数
5. 按"模板 A:品牌/产品咨询"输出

**输出示例**:
```
[比亚迪叉车] 简述
- 官网: www.bydforklift.com
- 母公司/上市: 比亚迪(1211.HK)
- 主营产品类: I/III 类,锂电叉车为主,钠电(2026 量产)
- 代表型号: 详见官网(web_search 补)
- 关键参数: 详见官网(web_search 补,不给编造值)
- 适用场景: 室内、3-5 吨级、新能源场景
- 来源: 比亚迪叉车官网 + 2025-2026 行业数据
```

### 场景 2:用户问选型(推荐车型)

**输入**: "我有个冷库,高 6 米,通道 2.8 米,推荐什么叉车?"

**Skill 处理**:
1. 触发词命中 → 激活
2. 问题类型:选型决策类
3. 读 `selection-guide.md` 走决策流程
4. 匹配:室内 + 6m 高架 + 2.8m 通道 → Class II 前移式锂电
5. 按"模板 B:选型决策"输出

**输出示例**:
```
场景:冷库室内作业,货架 6m,通道 2.8m
建议:
- 吨位: 1.5-2 吨
- 动力: 锂电(LFP,带低温加热)
- 类别: ISO Class II 前移式
- 品牌带: 比亚迪 / 杭叉 XE / 丰田 8FBE
- 配置: 全封闭驾驶室 + 防凝露加热
- 预算: 18-28 万(单台参考)
- 风险点: 低温充电效率,LFP 选带加热版
参考: selection-guide.md 第 X 节
```

### 场景 3:用户问销量排行(销售模块)

**输入**: "2026 年叉车销量排行?国内国外分别怎么样?"

**Skill 处理**:
1. 触发词"销量""排行"命中 → 激活
2. 识别:销售类 → 激活 `sales-news.md`
3. 联网检索最近月度数据
4. 按国内/国外分组
5. 按"模板 S"输出,带图表

**输出示例**(精简):
```
# 叉车销售动态报告(截至 2026-08)

## 国内品牌 TOP 5
| 排名 | 品牌 | 销量(万台) | 份额 |
| 1 | 安徽合力 | 39.45 | xx% |
| 2 | 杭叉集团 | xx.xx | xx% |
...

### ASCII 柱状图
```
安徽合力   ████████████████████████  39.45 万台
杭叉集团   ██████████████████████    xx.xx 万台
...
```

## 国外品牌 TOP 5
| 排名 | 品牌 | 销量(万台) | 全球份额 |
| 1 | 丰田 | xx.xx | xx% |
...

数据源: CITA 月报 / 海关 / 联网检索 2026-08-XX
```

### 场景 4:用户问标准状态(标准检索)

**输入**: "GB/T 43756-2024 现在还现行吗?"

**Skill 处理**:
1. 触发词"标准号"命中 → 激活
2. 识别:法规/标准类 + 状态确认 → 激活 `standard-retrieval.md`
3. 本地库先查 `standards.md`
4. 联网核验(openstd.samr.gov.cn / std.samr.gov.cn)
5. 按"模板 D+:标准检索(联网核验)"输出

### 场景 5:用户问故障(诊断)

**输入**: "我的合力 3 吨叉车起升无力,怎么回事?"

**Skill 处理**:
1. 触发词"叉车"命中
2. 识别:故障诊断类
3. 读 `fault-diagnosis.md` 匹配"起升无力"症状
4. 按"模板 C:故障诊断"输出可能原因+处理

## 四、模块组合使用

实际问答中,经常需要**组合调用**多个模块:

```
[品牌 + 参数]    brands.md + web_search
[销量 + 趋势]    sales-news.md + market-trends.md
[标准 + 条款]    standards.md + standard-retrieval.md
[故障 + 配件]    fault-diagnosis.md + parts-consumables.md
[选型 + 二手]    selection-guide.md + used-forklift-evaluation.md
[维保 + 安全]    maintenance-plan.md + safety-regulation.md
```

**原则**:主线 1 个模块 + 交叉引用 1-2 个,不堆叠超过 3 个。

## 五、调用本 Skill 的方式

### 5.1 在支持 Skill 的 Agent 平台(ClawHub / Claude.ai Skills / ZCode 等)
- 把整个 `forklift-2.0.2/` 目录放到 skills 目录
- Agent 会自动按 frontmatter 识别触发词
- 用户提问命中 → 自动激活

### 5.2 通过 RAG / Embedding 检索
- 把 `references/*.md` 全部切块向量化
- 用户提问 → 向量召回 → 拼到 prompt
- 注意:本 Skill 设计为"全文阅读",向量召回可能丢失上下文
- 推荐:整文件读取 > 向量检索

### 5.3 直接 prompt 引用(轻量级)
- 在 system prompt 中告诉 LLM "有本 Skill 的 references 目录"
- LLM 按需 `Read` 文件,按工作流回答
- 适合一次性、低频问答

### 5.4 微调 / 蒸馏训练(蒸馏链路)
- 参考 `forklift-distill-project`(MiniMind 蒸馏案例)
- 数据集从 references 自动抽取 + 人工标注
- 学生模型基于已完成 SFT 的教师模型

## 六、常见误用与避坑

### ❌ 错误用法

| 错误 | 后果 | 正确做法 |
|------|------|----------|
| 不读 SKILL.md 直接答 | 输出格式不统一、触发硬规则绕过 | 先读 SKILL.md 工作流 |
| 凭印象编型号参数 | 错误数据(如把 CPCD200 答成 10 万吨) | 必须 web_search 实时查 |
| 混用国内/国外品牌 | 用户难以对比 | 销售类问题严格分组 |
| 二手评估给具体价格 | 误导交易决策 | 给区间不给数字 |
| 配件报价 | 区域差异大 | 引导查服务站 |
| 标准状态编造 | 法规风险 | 走 standard-retrieval.md 联网核验 |
| 忽略版权声明 | 协议违规(MIT 也要保留版权) | 输出带"资料来源:杨鹏飞/叉车技术老炮" |

### ⚠️ 边界情况

1. **多轮对话上下文**:Skill 是无状态的,每轮问答都需重新读取相关文件
2. **多语言**:当前仅中文输出最佳,英文输出时数据精度可能下降
3. **数据时效**:本地库基准 2026-06,超过该时点的数据必须联网
4. **图片/图表输入**:Skill 不直接处理图像,但可基于用户描述推断

## 七、扩展与定制

### 7.1 增加新模块

如果要扩展本 Skill,推荐结构:

```
forklift-expert/
├── SKILL.md              # 总入口,更新 frontmatter 与触发词
├── LICENSE.md            # MIT
├── AUTHOR.md             # 作者信息
├── skill-card.md         # 发布卡片
├── usage-guide.md        # 使用详解(本文件)
├── sales-news.md         # 销售模块(范例)
└── references/
    ├── <新模块>.md       # 新模块文件
    └── ...
```

新模块文件 frontmatter 建议:
```yaml
---
name: <模块名>
trigger: <触发词列表>
version: <版本>
---
```

### 7.2 修改触发词

编辑 `SKILL.md` 的 frontmatter `description` 字段,补充新的触发场景。

### 7.3 修改输出模板

编辑 `SKILL.md` 的"输出模板"章节,新增/调整模板格式。

### 7.4 本地化

当前 Skill 以中国数据为主。要本地化到其他国家:

1. 修改 `brands.md` 加入当地品牌
2. 修改 `standards.md` 替换为当地法规(如 ANSI/UL、CSA、JIS 等)
3. 修改 `sales-news.md` 的数据源(海关 → 当地统计局)
4. 修改 `safety-regulation.md`(驾照、保险)
5. **保留核心工作流,改数据填充**

## 八、性能与成本

### 8.1 Token 消耗参考

| 场景 | 读取文件数 | 输出长度 |
|------|-----------|----------|
| 简单品牌问答 | 1-2 | 200-400 字 |
| 选型决策 | 2-3 | 400-600 字 |
| 故障诊断 | 2 | 300-500 字 |
| 销售排行 | 2-3 + 联网 | 600-1000 字 |
| 标准检索 | 2-3 + 联网 | 400-600 字 |
| 综合跨域 | 4-5 | 800-1200 字 |

### 8.2 联网检索频率建议

- 标准状态类:**每次都查**(状态可能变化)
- 销量数据类:**每次都查**(月报更新)
- 型号参数类:**每次都查**(新品上市)
- 基础原理类:**首次加载**(变化小)

### 8.3 缓存建议

- `references/` 全部文件可一次性加载到 context
- 标准状态、销售数据等联网结果建议带"缓存 24h"标记
- 不要缓存用户具体身份或敏感输入

## 十一、快速参考卡片(可粘贴到 prompt)

```markdown
# Skill:forklift-expert v2.3(叉车专家)

## 激活条件
用户问题含"叉车/电叉/柴油叉车/锂电叉车/平衡重/前移式/堆高车/AGV/
杭叉/合力/比亚迪/林德/丰田/永恒力/卡尔玛"等词,或涉及 ISO 5053-1
分类的工业车辆。

## 工作流
1. 读 SKILL.md 识别问题类型
2. 选择模块文件(14 个 references/ 之一)
3. 数据校验:本地基准 2026-06,超过该时点必须 web_search
4. 按模板输出(A-H + S 销售)

## 硬规则
- 不编造参数/标准号/销量
- 不报价(配件/二手)
- 销售类问题:联网 + 国内/国外分组 + 图表
- 标准状态:走 standard-retrieval.md 联网核验
- 保留版权声明:MIT 协议下"Copyright (c) 2026 杨鹏飞"

## 输出模板
- A 品牌/产品
- B 选型决策
- C 故障诊断
- D 法规/标准
- D+ 标准检索(联网)
- E 市场/趋势
- F 配件
- G 维保
- H 二手评估
- S 销售排行(新)
```

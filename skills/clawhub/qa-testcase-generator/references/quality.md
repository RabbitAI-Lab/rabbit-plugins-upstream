# 质量检查清单与生成规则

> 在生成用例前和生成后，对照此清单确保覆盖完整。
> 分类：**生成前检查**（必须覆盖的内容）与 **生成后验证**（输出质量确认）。

---

## 一、生成前检查：必须覆盖的内容

### 1.1 测试类型覆盖

| 测试类型 | 覆盖要求 | 检查点 |
|----------|----------|--------|
| **功能测试** | 主流程 + 异常流程 + 分支流程 | 每个需求至少 1 条正向 + 1 条异常 |
| **安全测试** | 认证 + 授权 + 数据保护 | HTTPS、加密、权限控制、注入防护 |
| **性能测试** | 响应时间 + 并发 + 吞吐量 | 接口响应时间、并发用户支持 |
| **可靠性测试** | 异常处理 + 容错 + 恢复 | 错误提示、超时处理、数据一致性 |
| **兼容性测试** | 浏览器 + 操作系统 + 移动端适配 | 主流浏览器、不同分辨率和系统版本 |
| **状态迁移** | 合法转换 + 非法转换 | 每个状态机至少覆盖所有合法路径 |
| **接口测试** | 参数校验 + 错误码 | 必填参数、类型校验、边界值 |

### 1.2 测试设计方法

| 设计方法 | 适用场景 | 用例结构 |
|----------|----------|----------|
| **场景法** | 业务流程清晰 | 主流程(4-5步) + 分支(3-4步) + 异常(4-5步) |
| **边界分析 + 等价类划分** | 输入有范围限制 | 有效等价类(1条) + 有效边界(2条) + 无效边界(2条) + 无效等价类(1条) |
| **状态迁移** | 实体有状态流转 | 合法转换 + 非法逆向 + 非法跳跃 |
| **判定表** | 多条件组合决策 | 条件组合全覆盖 |
| **等价类划分** | 输入有分类、格式或取值集合 | 有效类(1条) + 无效类(各1条) |

> ⚠️ 每个 eval 至少使用 **2 种**设计方法。推荐组合：场景法 + 边界分析 + 状态迁移。

### 1.3 异常场景分类

异常测试不能笼统地写"验证异常情况"。按以下分类设计：

| 异常类别 | 说明 | 用例示例 |
|----------|------|----------|
| **输入异常** | 无效格式、超长/超短、空值、特殊字符 | 邮箱格式错误时注册 → 提示"邮箱格式不正确" |
| **流程异常** | 流程中断、回退、重复提交、跳过必填步骤 | 下单中途关闭页面 → 订单状态不变 |
| **环境异常** | 网络中断、服务超时、磁盘满、并发冲突 | 支付接口超时 → 订单保留待支付状态 |
| **权限异常** | 未登录访问、越权操作、Token过期、角色不足 | 普通用户访问管理后台 → 403拒绝 |
| **数据异常** | 数据不存在、重复数据、关联数据被删除 | 查询已删除的商品 → 提示"商品不存在" |
| **状态异常** | 非法状态转换、重复操作、时效性超期 | 已取消订单申请发货 → 提示"订单已取消" |

**每个业务域**至少覆盖 **输入 + 流程 + 权限** 三类异常，其他按实际场景补充。

## 二、生成后验证：输出质量确认

### 2.1 用例质量标准

| 维度 | 要求 | 不合格示例 |
|------|------|------------|
| 步骤数 | 每条用例 3-5 步 | ❌ 1步："验证登录功能" |
| 操作描述 | 具体可执行 | ❌ "执行操作"、"进行验证" |
| 预期结果 | 明确可验证 | ❌ "成功"、"正常" |
| 测试数据 | 提供具体数据 | ❌ "测试数据" |
| 需求追溯 | 关联需求 ID | ❌ 无需求来源 |

### 2.2 覆盖率指标

| 指标 | 要求 |
|------|------|
| 需求覆盖率 | ≥ 100%（每个需求至少 1 条用例） |
| 测试维度覆盖 | ≥ 3 种（功能 + 安全/可靠性/性能中至少 2 种） |
| 设计方法覆盖 | ≥ 3 种（场景法 + 边界分析 + 状态迁移/判定表） |
| 业务域覆盖 | 100%（每个业务域都有用例） |

### 2.3 覆盖深度检查（四层递进）

设计用例的目标不是"覆盖需求文字"，而是**发现问题和隐患**。不要自己判断"够了"就跳层，按以下顺序逐层走完：

```
第一层 ✅ 主流程走得通 → 进入第二层
第二层 ✅ 流程各环节的页面元素/交互/数据/状态都测了 → 进入第三层
第三层 ✅ 每类黑盒方法至少用了一次 → 进入第四层
第四层 ✅ 至少想了3个"什么情况下会出问题"的场景
```

**每层检查清单**：

| 层级 | 完成标志 | 常见遗漏 |
|------|---------|---------|
| **第一层：主流程** | 核心业务路径正向走通 | 只测了页面加载，没测完整的"登录→进入→操作→退出"链条 |
| **第二层：业务分层** | 每个UI元素 + 字段值边界 + 元素间组合都验证了 | 只单独测了搜索/筛选/排序各方，漏了它们组合使用时的交互；字段只测了"有值"，没测"0/空值/特殊格式" |
| **第三层：黑盒方法** | 场景法/边界分析/等价类/判定表/状态迁移各至少覆盖一种适用场景；列表类补充分页/空状态/兼容性；表单类补充表单测试 | 只做了正向+负向，没做隐式功能推测（文档没写但系统默认该有的，如分页器、搜索防抖、空状态提示）|
| **第四层：探索性** | 边界数据、特殊操作、环境异常、数据一致、隐式推测5个类别各至少选一种 | 只覆盖了零数据和特殊字符，漏了空状态UI区分、兼容性测试、翻页行为 |

> 不是用例越多越好，是每一层都走到了才停。如果某一层想不出用例——不是"不用测"，而是需求理解不够深，回去重新读文档。

### 2.3 测试数据生成规则

按以下优先级策略生成：

1. **边界值数据** — 自动推导最小/最大值的具体数字
   - 示例：密码8-20位 → "8位密码: Abc12345"、"20位密码: Abc12345...（共20位）"
2. **有效等价类数据** — 合规范围内的典型值
   - 示例："Abcdef12"（8位含大小写字母+数字）
3. **无效等价类数据** — 每个违规类型各一条
   - 示例：全小写"abcdef12"、无数字"Abcdefgh"、超短"Ab1"
4. **特殊值数据** — 空值、null、0、空格、Unicode字符

> 暴露真实数据的用例，统一使用测试专用假数据，标注 `[测试数据]` 前缀。

### 2.4 输出验证清单

- [ ] 用例编号连续（TC-001, TC-002, ...）
- [ ] 每个业务域有分隔行
- [ ] 用例类型分布合理（冒烟测试占 10-20%，回归测试占主要部分）
- [ ] 优先级分布合理（P0: 10-20%, P1: 30-40%, P2: 30-40%, P3: 10-20%）
- [ ] 所有字段使用中文
- [ ] 操作步骤具体可执行
- [ ] 预期结果明确可验证
- [ ] Excel 表头正确，首行冻结
- [ ] 业务域已分组，有绿色分隔行
- [ ] 优先级颜色正确（P0红/P1橙/P2绿/P3灰）
- [ ] 步骤内容完整，换行正常
- [ ] 文件可正常打开

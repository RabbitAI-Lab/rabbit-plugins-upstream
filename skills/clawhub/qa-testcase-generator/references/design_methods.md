# 测试设计方法详解

> 在 SKILL.md 阶段三（测试设计+用例生成，V2 已合并原阶段三和四）中使用。
> 根据需求的复杂度来源选择适当的测试设计方法。

---

## 1. 方法选择矩阵

| 复杂度来源 | 设计方法 | 覆盖目标 |
|------------|----------|----------|
| 输入空间 | 边界分析 + 等价类划分 | 边界值 + 有效/无效等价类全覆盖 |
| 状态组合 | 状态迁移法 | 合法/非法转换 |
| 条件逻辑 | 判定表法 | 条件组合全覆盖 |
| 流程步骤 | 场景法 | 关键路径覆盖 |
| 配置组合 | Pairwise | 参数对覆盖（参数 ≥ 6 个时使用 PICT/AllPairs 工具） |

一条需求可能有多个复杂度来源，需组合多种方法。

---

## 2. 每种方法的步骤结构

### 2.1 场景法

| 场景类型 | 步骤数 | 示例 |
|----------|--------|------|
| 主流程 | 4-5 步（打开→输入→操作→验证→持久化） | "打开商品页→选择规格→加入购物车→跳转购物车→验证数量" |
| 分支流程 | 3-4 步（分支条件触发→替代路径→结果验证） | "库存不足→提示缺货→返回详情页→验证按钮状态" |
| 异常流程 | 4-5 步（含错误处理和恢复） | "支付超时→提示失败→返回订单→重新支付→验证成功" |

### 2.2 边界分析 + 等价类划分

| 用例类型 | 步骤数 | 验证重点 |
|----------|--------|----------|
| 有效等价类 | 3 步（设置合法值→执行操作→验证成功） | 合规数据能正常通过 |
| 有效边界 | 3 步（设置最小值/最大值→执行→验证） | 边界值合法可接受 |
| 无效边界/无效等价类 | 3 步（设置非法值→执行→验证错误提示） | 越界时给出明确错误 |

### 2.3 状态迁移

| 转换类型 | 步骤数 | 验证重点 |
|----------|--------|----------|
| 合法转换 | 4-5 步（含状态查询验证） | 状态变迁正确且持久化 |
| 非法逆向 | 4 步（含状态未变更验证） | 系统拒绝并给出原因 |
| 非法跳跃 | 4 步（跳过中间状态→验证拒绝） | 状态机不允许跳跃 |

验证模式：
```
步骤1: 确认当前状态 → 步骤2: 执行转行动作 → 步骤3: 验证新状态 → 步骤4: 验证关联数据一致
```

### 2.4 判定表

| 条件组合 | 步骤数 | 验证重点 |
|----------|--------|----------|
| 条件全部满足 | 2-3 步 | 期望结果发生 |
| 单个条件不满足 | 2-3 步 | 期望结果不发生 |
| 多个条件不满足 | 2-3 步 | 兜底/默认行为 |

### 2.5 Pairwise（参数组合测试）

适用于参数 ≥ 6 个、手动测试不可能穷举的场景。

```
方法: 用 PICT/AllPairs 工具生成最优参数对组合
用例: 每个参数对组合 3-4 步
工具: 安装 pict 后: pict model.txt > output.txt
```

## 3. Web 页面专用测试方法

### 3.1 表单测试

适用于有输入表单的页面（搜索框、新建/编辑表单、筛选条件等）。

| 测试维度 | 验证点 | 用例示例 |
|----------|--------|----------|
| **必填项** | 必填字段为空时提交 → 报错提示 | 申请事由为空→提示"申请事由为必填项" |
| **数据类型** | 输入不匹配的数据类型 → 格式校验 | 邮箱字段输入"abc"→提示"邮箱格式不正确" |
| **长度限制** | 超长输入截断/拒绝/兜底 | 搜索框输入200字符→正常处理不卡顿 |
| **格式校验** | 手机号/邮箱/日期等格式 | 手机号11位 + 非数字字符 |
| **特殊字符** | HTML标签/SQL注入/XSS尝试 | 输入 `<script>alert(1)</script>` → 转义或拒绝 |
| **前后空格** | 输入实际内容带首尾空格 | `"  关键词  "` → 匹配"关键词" |

**步骤结构**：设置值 → 执行操作 → 验证提示或结果（3步）

### 3.2 CRUD 测试

适用于有数据管理功能的页面（用户管理、部门管理、业务系统等）。

| 操作 | 验证点 | 关键检查 |
|------|--------|----------|
| **新增(Create)** | 新增后列表出现、字段值正确 | 每个字段值与提交一致 |
| **查询(Read)** | 列表显示、详情查询、搜索 | 数据完整展示，含翻页 |
| **修改(Update)** | 修改后字段更新、关联数据一致 | 修改后刷新验证 |
| **删除(Delete)** | 物理删除/软删除、二次确认 | 删除后列表消失、不可恢复 |

**步骤结构**：前置数据准备 → 执行操作 → 验证数据变更 → 反向验证（4步）

### 3.3 批量操作测试

适用于列表页中的多选→批量处理功能。

| 测试场景 | 验证点 | 说明 |
|----------|--------|------|
| **全选/取消** | 全选所有行、全部取消 | 勾选框联动正确 |
| **跨页全选** | 多页数据能否批量操作 | 常见bug——只选了当前页 |
| **混合状态** | 部分选中→批量操作 | 仅操作选中的项 |
| **批量结果** | 批量处理后的数据一致性 | 批量批准→全部状态变更为已通过 |
| **空选择提交** | 未勾选任何项直接点批量操作 | 提示"请至少选择一项" |

**步骤结构**：选择项 → 执行批量操作 → 确认 → 验证每项结果（4步）

### 3.4 链接与导航测试

适用于页面间的跳转、菜单、面包屑。

| 测试维度 | 验证点 |
|----------|--------|
| **页面跳转** | 点击链接/按钮 → 目标URL正确 |
| **面包屑** | 每级可点、回退后状态保持 |
| **菜单导航** | 菜单展开/折叠、选中高亮 |
| **浏览器导航** | 前进/后退按钮后的页面状态 |
| **新开窗口** | target="_blank"链接正常打开 |

**步骤结构**：执行导航操作 → 验证目标URL → 验证页面内容 → 验证返回（3-4步）

### 3.5 文件上传/下载测试

| 测试维度 | 验证点 |
|----------|--------|
| **格式限制** | 允许格式可上传、不允许格式拒绝 |
| **大小限制** | 超限文件拒绝、边界值（恰好等于/小于限制） |
| **文件名** | 含特殊字符/中文/超长文件名 |
| **空文件** | 0字节文件处理 |
| **下载** | 文件名正确、内容完整、可解压 |
| **并发** | 同时上传/下载多个文件 |

**步骤结构**：准备文件 → 执行上传/下载 → 验证结果 → 清理（3-4步）

### 3.6 Cookie/Session 测试

| 测试维度 | 验证点 |
|----------|--------|
| **超时** | 超过配置时间后操作 → 跳转登录 |
| **跨页面保持** | 登录后访问多个页面 → Session贯穿 |
| **清除 Cookie** | 清除后访问受保护页面 → 跳转登录 |
| **多标签** | 同一账号多个标签页 → 状态共享 |
| **记住我** | 关闭浏览器重新打开 → 登录状态保持 |

**步骤结构**：设置环境 → 执行操作 → 验证状态 → 清理（3-4步）

### 3.7 错误猜测法（Error Guessing）

基于测试经验和直觉，预测"哪里最容易出错"并针对性设计用例。不需要数学模型，靠的是对常见缺陷模式的理解。

| 常见错误模式 | 验证点 | 示例 |
|------------|--------|------|
| **空提交** | 表单所有字段为空时提交 | 搜索框为空→显示全部/不报错 |
| **重复提交** | 快速连续点击提交按钮 | 只生成一个申请/只扣一次库存 |
| **异常操作顺序** | 跳过前置步骤直接操作 | 未登录直接访问受保护页面 |
| **边界误操作** | 输入合法但极端值 | 最小/最大/0/负数 |
| **中断后恢复** | 操作中途中断后恢复 | 上传中断→重新上传→文件完整 |
| **并发冲突** | 多人同时操作同一条数据 | 同一文件被两个审批员同时审批 |
| **数据依赖** | 关联数据被删除后 | 业务系统被删除后，历史文件仍可预览 |
| **日志遗漏** | 关键操作是否记日志 | 审批/下载/分享行为是否有操作日志 |

**步骤结构**：识别风险点 → 设计触发操作 → 验证系统不崩溃/数据不丢失/提示合理（3步）

### 3.8 因果图法（Cause-Effect Graphing）

用图形化方式分析输入条件之间的因果关系，推导出判定表。适合多个条件相互依赖、不是独立组合的场景。

**四步流程**：

```
条件(原因) → 结果(效果) → 约束关系 → 判定表 → 用例
```

**示例**：下载申请审批逻辑
```
原因(Cause)：   C1 = 审批员同部门  C2 = 审批员与申请人非同一人  C3 = 申请单状态为待审批
结果(Effect)：  E1 = 可审批  E2 = 审批按钮禁用
约束：          C1 AND C2 AND C3 → E1；任一不满足 → E2
```

| C1(同部门) | C2(非本人) | C3(待审批) | 结果 |
|:----------:|:----------:|:----------:|------|
| ✅ | ✅ | ✅ | E1 可审批 |
| ❌ | ✅ | ✅ | E2 按钮禁用 |
| ✅ | ❌ | ✅ | E2 按钮禁用 |
| ✅ | ✅ | ❌ | E2 按钮禁用 |

**步骤结构**：列出条件 → 列出结果 → 标注约束 → 推导判定表 → 生成用例（5步）

### 3.9 模糊测试（Fuzz Testing）

大量随机、半随机或畸变数据作为输入，观察系统是否崩溃、异常或泄露数据。适用于所有接收外部输入的接口。

| 测试维度 | 验证点 | 适用场景 |
|----------|--------|----------|
| **随机字符** | 输入随机字符串 | 搜索框、文件名输入 |
| **超大数据** | 超出正常范围的数据量 | 文件上传50MB+、搜索10000字符 |
| **畸形格式** | 不符合规范的数据格式 | 损坏的PDF、负数的文件大小 |
| **边界值组合** | 多字段同时设为边界值 | API接口的多个参数 |
| **空/Null** | 参数缺失或为Null | API接口、表单必填字段 |
| **遍历枚举** | 枚举值超出定义范围 | 状态字段传非法值 |

**步骤结构**：构造畸形输入 → 发送请求 → 验证系统不崩溃/返回合理错误码（3步）

### 3.10 随机测试（Random / Monkey Testing）

无预设条件、无脚本计划地随机操作系统，覆盖正常用例想不到的操作路径，发现偶发缺陷。适用于长稳测试和回归测试的补充。

| 随机操作类型 | 验证点 | 示例 |
|------------|--------|------|
| **随机点击** | 快速无序点击不同按钮/链接 | 提交时点击取消+确定+关闭 |
| **随机输入** | 随机字符组合填入各输入框 | 搜索框输入乱码后立即切换Tab |
| **随机跳转** | 随机在页面间切换 | 预览页→申请→审批→返回预览 |
| **随机刷新** | 随机F5/前进/后退 | 提交申请瞬间按F5 |
| **随机并发** | 同账号多标签同时操作 | 一个标签审批，一个标签撤回 |

**步骤结构**：设计随机操作序列 → 执行 → 验证系统不崩溃/数据不损坏（2-3步）

## 3. 业务域用例策略

针对每个业务域，按以下顺序设计：

1. **核心实体** — 实体的 CRUD 操作和属性边界
2. **业务规则** — 规则正向验证 + 边界情况 + 规则冲突
3. **状态流转** — 合法转换 + 非法转换（逆向/跳跃）
4. **域间交互** — 接口契约 + 依赖异常 + 数据一致性

## 4. 质量属性扩展

功能用例基础上，根据标记的质量属性扩展：

| 质量属性 | 扩展场景 |
|----------|----------|
| 可靠性 | 异常输入、服务中断、超时场景 |
| 效率 | 响应时间验证、并发处理 |
| 安全性 | SQL注入/XSS、越权访问、敏感数据 |
| 易用性 | 操作流程合理性、错误提示清晰度 |
| 可维护性 | 日志记录、配置生效 |

## 5. 优先级分配规则

| 优先级 | 规则 |
|--------|------|
| P0 | 核心层主流程 + 阻塞性异常 |
| P1 | 核心层分支 + 重要层主流程 + 关键边界 |
| P2 | 核心层非关键场景 + 重要层异常 + 辅助层主流程 |
| P3 | 极端边界 + 低频场景 + 探索性测试 |

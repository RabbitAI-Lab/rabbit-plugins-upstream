## D1团队组建评价标准

### 评价要点
| 要素 | 优秀 | 合格 | 不合格 |
|------|------|------|--------|
| 小组负责人 | 明确指定，有决策权限 | 有指定 | 未明确 |
| 成员构成 | 覆盖相关领域，有专家支持 | 基本覆盖 | 单一或缺失 |
| 职责分工 | 清晰明确 | 基本明确 | 不清晰 |

### 常见问题
- 只有一个人参与
- 成员与问题领域不相关
- 未指定负责人
- 缺少跨部门协作（如涉及多部门问题时）

## D2问题描述评价标准

### 5W2H框架
- **What**：发生了什么（具体描述）
- **Where**：发生在哪（位置、工序）
- **When**：何时发现/发生（时间线）
- **Who**：谁发现/涉及谁
- **Why**：为什么认为是问题
- **How many**：多少量/比例/金额
- **How**：如何发现的

### 量化要求
| 类型 | 要求 |
|------|------|
| 批量问题 | 必须量化（数量、比例、金额） |
| 单件问题 | 说明影响范围 |
| 客诉问题 | 说明客户名称、投诉时间、投诉内容 |

### 佐证材料
- 图片、照片（缺陷照片、工程图）
- 检测数据（尺寸报告、测试报告）
- 来料检验记录
- 客户反馈截图

## D3临时遏制措施评价标准

### 评价要素
1. **措施内容**：具体做了什么
2. **实施时间**：何时开始/完成
3. **责任人**：谁负责执行
4. **覆盖范围**：隔离了哪些物料/产品
5. **验证方法**：如何确认措施有效

### 有效性判断
- 是否完全阻断了问题产品流出？
- 是否有漏网风险？
- 实施成本是否合理？

### 常见问题
- 措施模糊（如"加强检验"而未说明具体方法）
- 无时间节点
- 无验证方法
- 覆盖范围不明确

## D4根本原因分析评价标准（核心重点）

### 根本原因类型

#### 发生根本原因（Why it happened）
- 技术原因：设备、工艺、材料、设计
- 管理原因：流程、培训、监督、沟通

#### 流出根本原因（Why it escaped）
- 检验/测试未能发现
- 判定标准不明确
- 人员能力不足
- 系统/流程漏洞

### 根因分析工具

| 工具 | 适用场景 | 使用要点 |
|------|---------|---------|
| 5Why | 通用，需追到5层以上 | 每层why必须有事实/数据支撑 |
| 鱼骨图 | 多因素分析 | 分类完整（人机料法环测） |
| FMEA | 工艺/设计问题 | 严重度/频度/探测度评分 |
| 故障树 | 复杂系统问题 | 逻辑关系清晰 |
| PEST/流程分析 | 系统性问题 | 端到端梳理 |

### 评判等级

| 等级 | 标准 |
|------|------|
| 优秀 | 5Why追到5层以上 + 有工具支撑 + 有数据/事实验证 + 符合MECE原则 |
| 良好 | 3-5Why + 有分析过程 + 基本合理 |
| 合格 | 3Why + 有简单分析 |
| 不合格 | 只描述现象 / 1-2层追问 / 未使用任何分析工具 |

### 常见问题
- 5Why只问2-3层就停止
- 用"人为疏忽"、"员工失误"等表面原因代替深层原因
- 未区分发生原因和流出原因
- 根因未经验证（假设多于事实）
- 未使用任何结构化分析工具

## D5永久纠正措施评价标准

### 评价框架
| 要素 | 说明 | 必须性 |
|------|------|--------|
| 针对根因 | 必须与D4确定的根因对应 | 强制 |
| 具体可执行 | 有明确动作，非空泛描述 | 强制 |
| 责任人 | 明确到人 | 强制 |
| 完成时间 | 有明确时间节点 | 强制 |
| 验证方法 | 如何确认措施有效实施 | 建议 |
| 风险评估 | 副作用、关联影响 | 建议 |

### 纠正措施矩阵

| 根因类型 | 典型纠正措施 |
|---------|-------------|
| 设备 | 设备改造、参数调整、预防性维护 |
| 工艺 | 工艺文件修订、作业指导书更新 |
| 材料 | 供应商切换、来料检验强化 |
| 设计 | 设计变更、DFMEA更新 |
| 人员 | 培训、考核、职责调整 |
| 测量系统 | 检测方法改进、量具更新 |

### 常见问题
- 纠正措施与根因不对应
- 措施描述模糊（"加强管理"、"提高意识"）
- 无责任人或责任人层级不够
- 无完成时间
- 只处理表面问题，未触及根本

---

## D6预防措施评价标准

### 与纠正措施的区别
| 类型 | 目的 | 范围 |
|------|------|------|
| 纠正措施 | 解决当前问题 | 针对本次 |
| 预防措施 | 防止同类问题再发 | 系统/横向 |

### 横向展开要求
- 是否推广到其他产品/工序？
- 是否更新了FMEA/Control Plan？
- 是否更新了标准作业文件？

### 效果验证
| 阶段 | 要求 |
|------|------|
| 短期 | 实施后立即确认 |
| 长期 | 3-6个月跟踪，确认问题不再复发 |

### 常见问题
- 预防措施与纠正措施混淆
- 只有纠正措施，无预防措施
- 无横向展开
- 无效果验证计划或验证结果

## D7经验教训与文件更新评价标准（重点）

### 一、经验教训总结

#### 评价要素
| 要素 | 优秀 | 合格 | 不合格 |
|------|------|------|--------|
| 问题回顾 | 完整复盘问题发生发展过程 | 基本描述 | 无或过于简略 |
| 根因启示 | 提炼出可供学习的深层教训 | 有简单总结 | 未总结 |
| 后续行动 | 明确了预防类似问题的具体措施 | 有泛化建议 | 无 |

#### 经验教训模板检查
- 问题是什么？（What）
- 为什么会发生？（Why）
- 我们学到了什么？（Lesson）
- 我们将如何改变？（Action）

---

### 二、文件修订评价（核心重点）

#### 必须评估的文件类型

| 文件类型 | 缩写 | 需检查的修订内容 |
|---------|------|-----------------|
| 控制计划 | CP/Control Plan | 关键产品特性、关键过程参数、检验项目、反应计划 |
| 过程FMEA | PFMEA | 严重度(S)、频度(O)、探测度(D)评分更新；新增/修改失效模式；风险优先级(RPN)重算 |
| 产品FMEA | DFMEA | 设计评审项更新；设计验证补充 |
| 作业指导书 | SIP/SOP | 作业步骤更新；注意事项补充；检验方法明确 |
| 检验规范 | OBA/IQC/IPQC | 判定标准更新；抽样方案调整；检验项目增减 |
| 工艺参数文件 | Process Spec | 参数范围修订；上下限调整 |
| 培训记录 | Training | 培训内容更新；新增培训需求 |

#### 评判标准

##### CP（控制计划）评价
| 检查点 | 评价标准 |
|--------|---------|
| 产品特性 | 关键特性是否已标识并控制？ |
| 过程参数 | 与根因相关的参数是否已纳入控制？ |
| 检验项目 | 新增的检验项目是否已在CP中体现？ |
| 反应计划 | 异常反应计划是否明确？ |

##### FMEA评价
| 检查点 | 评价标准 |
|--------|---------|
| 严重度更新 | 若根本原因涉及设计缺陷，严重度是否重新评估？ |
| 频度更新 | 类似失效模式在其他工序的频度是否更新？ |
| 探测度 | 探测方法是否改进？探测度评分是否降低？ |
| 新增项 | 根因对应的失效模式是否已新增到FMEA？ |
| RPN重算 | 修订后RPN是否在可接受范围？ |

##### SIP/SOP评价
| 检查点 | 评价标准 |
|--------|---------|
| 步骤更新 | 相关作业步骤是否已修订？ |
| 参数标注 | 关键参数是否已明确标注？ |
| 注意事项 | 预防措施是否已加入注意事项？ |
| 版本更新 | 文件版本号是否已更新？ |

##### 检验规范评价
| 检查点 | 评价标准 |
|--------|---------|
| 判定基准 | 判定标准是否与修订后的要求一致？ |
| 抽样方案 | 抽样方案是否调整？ |
| 检验方法 | 检验方法是否明确？ |

#### 文件修订完整性评判

| 等级 | 标准 |
|------|------|
| 优秀 | 覆盖所有需修订文件，每项修订有版本记录，有责任人确认 |
| 良好 | 主要文件已修订，修订记录完整 |
| 合格 | 部分文件已修订，有基本修订记录 |
| 不合格 | 无文件修订或修订明显遗漏关键文件 |

#### 常见问题
- 只总结了经验教训，未进行任何文件修订
- 文件修订列表与根因不对应
- 修订后未更新文件版本号
- FMEA评分未重新计算
- CP未纳入新增的控制参数
- SIP更新但未培训相关人员

### 三、D8团队认可与闭环

#### D8团队认可
| 要素 | 说明 |
|------|------|
| 表彰内容 | 是否认可了小组成员的努力和贡献？ |
| 表彰方式 | 形式是否合适？（口头/书面/物质） |
| 非形式要求 | 体现团队文化，非强制但建议 |

#### 闭环确认清单
| 项目 | 要求 |
|------|------|
| 行动项完成率 | 是否100%完成？ |
| 效果验证 | 是否验证纠正/预防措施有效？ |
| 客户确认 | 客户是否书 面确认关闭？ |
| 文件归档 | 报告和证据是否归档保存？ |

## 综合评分标准

### 分项评分（每项10分）
| 步骤 | 权重 | 说明 |
|------|------|------|
| D1团队 | 10% | 团队组建质量 |
| D2问题描述 | 15% | 描述完整性 |
| D3遏制措施 | 15% | 临时措施有效性 |
| D4根因分析 | **30%** | 核心重点，加倍权重 |
| D5纠正措施 | 15% | 与根因对应性 |
| D6预防措施 | 10% | 横向展开 |
| D7/D8闭环 | 5% | 表单完整性 |

### 综合等级

| 总分 | 等级 | 说明 |
|------|------|------|
| 90-100 | 优秀 | 报告完整，逻辑清晰，根因深入 |
| 75-89 | 良好 | 基本满足要求，有小幅改进空间 |
| 60-74 | 合格 | 框架完整但深度不足 |
| <60 | 需改进 | 存在明显缺失或逻辑问题 |

## 典型案例分析

### 优秀案例特征
1. 问题描述量化完整，有图片支撑
2. 5Why追到7-8层，每层有数据验证
3. 纠正措施明确对应根因，有验证计划
4. 预防措施横向展开到同类产品
5. 3个月后效果验证显示问题未复发

### 不合格案例特征
1. 问题描述模糊："质量异常"
2. 根因："员工操作失误"
3. 纠正措施："加强培训、加强检验"
4. 无预防措施或与纠正措施雷同
5. 未验证效果即关闭

## 常见8D报告问题汇总

| 问题类型 | 典型表现 | 改进方向 |
|---------|---------|---------|
| 描述不足 | 几句话带过，无数据 | 按5W2H补充 |
| 根因浅层 | 1-2层追问 | 使用5Why工具 |
| 措施空泛 | "加强"、"完善" | 具体化、可执行化 |
| 纠正预防混 | 同一条措施写两边 | 区分目的和范围 |
| 逻辑断裂 | D5措施与D4根因不对应 | 建立追溯链 |
| 效果未验 | 实施后直接关闭 | 设定验证节点 |

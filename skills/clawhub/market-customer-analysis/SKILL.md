# 市场与客户洞察

## 任务目标

对用户指定的**市场 / 品类 / 产品 / 企业**，按三条主线依次完成分析并综合收敛：

1. **ST 分析**（Segmentation 市场细分 → Targeting 目标客户 → Scenario 应用场景）
2. **APPEALS 模型**（七维度客户需求分析 + 回答 5 个战略问题）
3. **KANO 模型**（需求五类判定 + 爆款基因识别）

最终合并三大模型结论，找出**高价值细分市场**与**尚未满足客户需求与痛点的蓝海市场**，给出可供参考的**战略发展建议**，为下一步的创新焦点与业务设计提供准备。

**主交付物**：一份可在浏览器直接打开的 **HTML 交互式单页报告**（含 ST 细分表、客户画像卡、APPEALS 雷达图、KANO 四象限矩阵、蓝海机会气泡图）。

## 适用与不适用场景

**适用**：新市场进入评估、产品/品类需求定义、客群画像与场景洞察、需求优先级排序、蓝海机会筛查、客户需求分类与爆款基因判断。

**不适用（边界声明，务必遵守）**：

| 用户诉求 | 应由哪个技能处理 |
|---|---|
| 产品定位声明、定位三角、4P 营销组合、品牌宣言、推广语、销售话术 | `product-positioning-master` |
| TAM/SAM/SOM 量化测算、行业规模上下限推演、市场进入量化模型 | `market-researcher` |
| PESTEL / 波特五力 / SCP / 价值链 / GE 矩阵 / SPACE 行业环境分析 | `macro-meso-strategic-analysis` |
| 深度行业研究报告（含尽调、投资研究、产业链梳理） | `chentai-industry-research-report` / `industry-chain-mapper` |

本技能只回答五件事：**客户是谁 → 需求是什么 → 哪些需求没被满足 → 机会在哪里 → 下一步创新焦点是什么**。不要越界产出定位声明与 4P 组合。

## 输入收集与追问策略

### 第一步：确认分析主体与已有资料

优先从用户输入中提取以下 8 项基础信息：

1. **分析主体**（行业 / 品类 / 产品 / 企业名称）——**缺失则必须先追问，不得自行假设**
2. **目标地域**（全国 / 某区域 / 海外）
3. **当前发展阶段**（概念期 / 初创期 / 成长期 / 成熟期 / 衰退期）
4. **核心功能或卖点**（至少 3 个）
5. **价格区间**
6. **主要竞品**（至少 2 个）
7. **已知客群信息**（客户类型：个人 / 企业 / 终端；现有客户反馈、调研数据、访谈记录）
8. **用户已提供的资料**（文档、表格、问卷回收、访谈纪要等）

若用户已提供覆盖上述 80% 以上的信息，直接进入工作流 P2，不反复追问。

### 第二步：追问缺失的关键数据

对**关键决策字段**（市场规模、市场增长率、客群规模、主要竞品表现）缺失时，使用 `AskUserQuestion` 集中追问 1–2 轮，不要挤牙膏式逐条问。

### 第三步：联网补全（需用户授权）

追问后仍缺失的数据，**先向用户说明将检索哪些数据、请求授权**，再用 WebSearch / WebFetch 检索补全。

**数据纪律（硬约束）**：

- 每条外部数据必须记录 `来源（机构/媒体）` + `URL` + `发布时间` + `置信度（高/中/低）`
- 优先采用权威来源：政府统计部门、行业协会、知名咨询机构、上市公司财报
- 中国香港、中国台湾、中国澳门的数据单独标注
- **严禁捏造数据**。任何无法获得的数值一律标注「待补充」，不得用推测值冒充事实
- 属于分析性推断（如客户心理细分特征）须显式标注「分析推断」

## 标准工作流

| 阶段 | 输入 | 动作 | 输出要求 | 门禁 / 确认点 |
|---|---|---|---|---|
| **P0 充分性检查** | 用户首轮输入 | 提取分析主体与已有资料 | 明确分析标的 + 资料清单 | 无主体则必须先追问 |
| **P1 追问** | P0 结果 | 追问市场规模/增长率/客群特征/竞品/地域/阶段 | 关键字段填充或标「待补充」 | 需用户回复 |
| **P2 联网补全** | P1 缺口 | WebSearch / WebFetch 检索补全 | 每条数据带来源 + URL + 置信度 | **需用户授权联网** |
| **P3 ST 分析** | 全部资料 | ①4 维细分表 ②四因子吸引力评分 ③筛 2–3 个目标市场 ④客户画像 ⑤应用场景 | 细分表 + 画像卡 + 场景卡 | **目标市场筛选结果需用户确认** |
| **P4 APPEALS 分析** | P3 输出 | 七维度打分（重要度 / 当前满足度）+ 关注点提取；逐题回答 5 个战略问题 | 七维表 + 五问回答节 | 无 |
| **P5 KANO 分析** | P3 / P4 输出 | 输出问卷模板 → 判定矩阵 → Better/Worse 系数 → 五类归类 → 爆款基因四瓣标记 | KANO 分类表 + 爆款基因结论 | **无真实问卷数据时须确认采用「定性推断」并标注** |
| **P6 蓝海机会矩阵** | P3–P5 | 对每条未满足需求做三维打分 → 综合机会分 → 气泡图数据 | 机会评分表 + 气泡图坐标数据 | 无 |
| **P7 战略建议** | P6 | 综合收敛 → 战略发展建议 | 建议清单（含优先级 + 推导依据） | 无 |
| **P8 生成 HTML 报告** | 全部 | 读 `templates/report.html` → 注入数据 → 另存落盘 | 浏览器可直接打开的单页报告 | 无 |

**执行顺序纪律**：P3 → P4 → P5 → P6 必须串行，后一步的分析必须引用前一步的结论，保证跨模型逻辑一致。

## 三大模型强制输出结构

以下表格为**强制输出**，列名不可省略、不可替换同义词。

### ① ST 细分表（P3-S）

| 细分维度 | 细分类别 | 特征描述 | 市场规模参考 |
|---|---|---|---|
| 地理细分 | 区域/城市层级 | 气候、文化、消费水平差异 | 估算 |
| 人口统计细分 | 年龄/性别/收入/职业/教育 | 核心人群画像 | 估算 |
| 心理细分 | 生活方式/价值观/性格 | 消费动机、品牌偏好 | 描述性 |
| 行为细分 | 使用场景/购买频率/忠诚度 | 使用习惯、决策路径 | 描述性 |

四个维度**均需落到具体细分类别**（如「地理细分」下应列出具体城市层级与区域，而非照搬模板文字）。详见 `references/st-model.md`。

### ② 目标市场吸引力评分表（P3-T）

| 细分市场 | 市场规模(0-5) | 增长潜力(0-5) | 竞争强度反向分(0-5) | 企业能力匹配(0-5) | 综合吸引力 |
|---|---|---|---|---|---|

- **竞争强度反向分**：竞争越激烈得分越低（0 = 红海血战，5 = 竞争空白）
- **综合吸引力** = 四项均值或加权和（须注明采用哪种口径）
- 据综合吸引力排序，**筛出 2–3 个最具价值的目标细分市场**

### ③ 客户画像卡（P3-T）—— 每个目标市场一份，固定 5 要素

**画像名称**（如「都市白领小王」）/ **背景描述**（职业、年龄、收入、生活方式）/ **核心需求**（要解决什么问题）/ **痛点**（当前解决方案的不足）/ **购买决策因素**（价格/品牌/口碑/便利性等）

### ④ 应用场景卡（P3-S）—— 每个目标客群 2–3 个，固定 5 要素

**场景名称**（如「通勤路上的碎片时间」）/ **触发条件**（什么情况下用户会想到用这个产品）/ **使用流程**（从接触到使用完成的完整路径）/ **期望结果**（用户希望获得的最终价值）/ **替代方案**（不用本产品会用什么）

### ⑤ APPEALS 七维表（P4）

| 维度 | 用户关注点（原话/调研所见） | 重要度(1-5) | 当前满足度(1-5) | 差距 |
|---|---|---|---|---|

七维度定义与关注点清单：

| 维度 | 关注点 |
|---|---|
| **A** Appeal 吸引力 | 外观、界面、品牌感、设计质感、第一印象 |
| **P** Price 性价比 | 价格、成本、优惠、付费价值、投入产出比 |
| **P** Performance 性能 | 速度、效率、承载力、功能强度、体验流畅度 |
| **E** Ease of use 易用性 | 上手难度、操作步骤、学习成本、交互逻辑 |
| **A** Availability 可获得性 | 渠道可得、随时可用、覆盖范围、获取门槛 |
| **L** Reliability 可靠性 | 稳定性、故障率、一致性、售后保障 |
| **S** Security 安全性 | 隐私保护、数据安全、资金安全、风险合规 |

差距 = 重要度 − 当前满足度；**差距 ≥ 2 的维度即为需求缺口，须进入 P6 蓝海机会评分**。详见 `references/appeals-model.md`。

### ⑥ APPEALS 五问回答节（P4）—— 逐题成节，不得合并

1. **机会与未满足需求**：这个市场上有哪些机会？哪些客户群的需求没有得到满足？是否存在新的客户群？哪些客户群是竞争对手服务不到位的？
2. **细分标准**：可以通过哪些细分标准将客户进行分类？
3. **客户战略方向与痛点**：客户在未来五年的发展战略方向是什么？在客户的发展战略当中存在哪些痛点？
4. **压力挑战与 KPI 关联**：客户面临的压力和挑战有哪些？哪些 KPI 跟公司有关，可以帮助客户改善？
5. **组织流程与决策因素**：客户的组织和流程（决策及采购）会有大的变化吗？促使客户作出购买决定的关键因素是什么？

### ⑦ KANO 需求分类表（P5）

| 需求/功能特性 | M 必备型 | O 期望型 | A 魅力型 | I 无差异型 | R 反向型 | Q 可疑 | 判定类别 | Better | Worse |
|---|---|---|---|---|---|---|---|---|---|

- 判定依据标准矩阵（**行 = 正向「具备时」的回答，列 = 反向「不具备时」的回答**；详见 `references/kano-model.md`），非问卷数据时须标注「定性推断」
- 爆款基因四瓣标记：**刚需 / 炫耀 / 痛点 / 高频**，命中 ≥2 瓣为候选爆款，四瓣全中为核心爆款基因

### ⑧ 蓝海机会评分表（P6）

| 未满足需求 | 需求未满足度(0-5) | 市场吸引力(0-5) | 企业能力匹配(0-5) | 综合机会分(0-100) | 优先级 |
|---|---|---|---|---|---|

- 综合机会分 = `( 三维之和 / 15 ) × 100`
- 阈值：**≥66 高优先级 / 33–66 中优先级 / 33 以下低优先级**
- 气泡图坐标：X = 市场吸引力，Y = 需求未满足度，气泡大小 = 企业能力匹配，颜色 = 优先级（高红 / 中黄 / 低灰）

## 步骤 2：综合收敛与战略建议

三大模型完成后，按以下四步收敛（方法详见 `references/blue-ocean-strategy.md`）：

1. **交叉比对**：把 ST 的目标市场 × APPEALS 的需求缺口 × KANO 的类别与爆款基因三者对齐，找出**三者共同指向的聚焦区**
2. **蓝海判定**：在蓝海机会评分表中，甄别同时满足「需求未满足度高 + 市场吸引力高 + 企业能力可匹配」的机会点，即为**蓝海市场候选**
3. **规避红海**：明确标注属于反向型（R）与无差异型（I）的需求，这些是**不应投入**的伪需求
4. **输出战略发展建议**：每条建议须包含「建议内容 + 推导依据（指向哪个模型哪条结论）+ 优先级 + 可执行的下一步动作」，并为**创新焦点与业务设计**列出待决策清单

## HTML 报告生成规范

1. 使用 Read 工具读取 `templates/report.html`
2. 将分析结果填入模板顶部的数据对象：

```js
const DATA = {
  meta:      { subject, scope, date, author },
  summary:   { points: [] },          // 执行摘要要点
  st:        [ { dimension, category, feature, marketSize } ],
  attraction:[ { segment, size, growth, competition, fit, total, selected } ],
  personas:  [ { name, background, needs, pains, decisionFactors } ],
  scenarios: [ { persona, name, trigger, flow, expected, alternative } ],
  appeals:   [ { dim, key, importance, satisfaction, gap } ],
  questions: [ { no, title, answer } ],   // APPEALS 五问
  kano:      [ { need, A, O, M, I, R, Q, category, better, worse, petals: [] } ],
  blueocean: [ { need, unmet, attraction, fit, score, priority } ],
  strategy:  [ { title, content, basis, priority, next } ],
  sources:   [ { item, value, source, url, date, confidence } ]
};
```

3. 用 Write 工具将填充后的完整 HTML 另存为报告文件，命名规则：
   `[主体名称]_市场与客户分析_[YYYY-MM-DD].html`（保存在当前工作目录）
4. 若模板中存在未启用的数据字段，保留其空数组结构，不要删除字段名。**不要修改 `DATA` 的键名**。
5. 完成后用 `present_files` 呈现报告。

- [ ] 分析主体、地域、阶段、竞品等基础信息已确认，未做无依据假设
- [ ] 所有市场规模与增长率均带来源 + URL + 置信度；缺失处已标「待补充」；**零捏造**
- [ ] ST 细分表四个维度均已落到具体细分类别，列名与规范一致
- [ ] 目标市场为 2–3 个且经四因子评分筛选，评分口径已注明
- [ ] 每个目标市场均有客户画像且含全部 5 要素；每个客群有 2–3 个场景且含全部 5 要素
- [ ] APPEALS 七维度全覆盖，每维度落到用户关注点原话，差距 ≥2 的维度已进入 P6
- [ ] APPEALS 5 个战略问题逐题成节回答，无合并、无遗漏
- [ ] KANO 按标准矩阵判定，Better/Worse 公式正确，爆款基因四瓣有明确结论
- [ ] 蓝海机会评分表数据齐全，阈值与优先级标注正确
- [ ] 战略建议每条含推导依据与下一步动作，未越界产出定位声明 / 4P
- [ ] HTML 单文件、无外部依赖、浏览器打开无报错、交互与响应式正常
- [ ] 报告落盘命名符合 `[主体名称]_市场与客户分析_[YYYY-MM-DD].html`

## 注意事项

- **先问后做**：信息不足时先追问再开工，不要用通用模板填充
- **跨模型一致**：KANO 的必备型需求应与 APPEALS 中高重要度低满足度的维度对应；ST 的目标市场应与 P6 高优先级机会对应；出现矛盾必须回头修正并说明
- **区分事实与推断**：外部数据标来源，分析推断标「分析推断」，二者不得混写
- **不越界**：需求洞察做完即止，定位与 4P 留给 `product-positioning-master`
- **可视化**：HTML 报告为强制交付；分析过程中如需即时展示，可用 `read_me` + `show_widget` 内联渲染 KANO 四象限矩阵或 APPEALS 雷达图作为辅助

## ⑤ AI 循环研究法(可迁移的核心)

前四章教了"挖什么因子、怎么过门槛、怎么攒分"。这一章教的是**方法本身**——一套"人出判断、AI 出算力"的循环研究法。它不绑定 BRAIN,也不绑定某个 AI 工具:任何"人 + 会写代码/调 API 的 AI"的组合都能复用。你把这套循环跑顺了,换个平台、换个赛题,依然管用。

核心信念只有一句:**每一轮都真的去看结果,再决定下一步做什么。** 不看结果就出手,你不是在研究,只是在随机撞墙。

---

### 5.1 研究循环骨架:OBSERVE → DECIDE → ACT → VERIFY → RECORD

一轮研究 = 五个动作。小白最容易犯的错是只做 ACT(拼命跑 sim),跳过 OBSERVE 和 RECORD——于是每天从零开始,不积累。

| 阶段 | 你(人)做什么 | AI 做什么 | 产出 |
|---|---|---|---|
| **OBSERVE** 读结果 | 定问题:"昨天哪些 alpha 过了?哪类字段命中率高?" | 拉 `GET /alphas/{id}`、汇总昨日 sim 的 Sharpe/Fitness/turnover/自相关,输出一张对比表 | 一份"现状快照" |
| **DECIDE** 定方向 | 拍板:今天挖哪个方向、提哪 1-2 个 | 根据快照给候选清单 + 理由,但**决策权在你** | 今日 to-do(挖矿方向 + 提交候选) |
| **ACT** 执行 | 审一眼要跑的表达式合不合理 | 生成表达式、批量 `POST /simulations`、轮询 `status` 到 COMPLETE | 一批已完成的 sim 结果 |
| **VERIFY** 验硬指标 | 只信数字,不信 AI 的形容词 | 逐条读回硬指标:Sharpe≥1.25?Fitness≥1.0?自相关<0.7?in-sample D1 好不好? | 通过/淘汰的判定 |
| **RECORD** 存学习 | 提炼"这轮学到什么"(1-3 句) | 把结果 + 结论追加到一个 log 文件(csv/jsonl/md 均可) | 可积累的知识库 |

**骨架伪代码**(喂给 AI 让它照着搭,细节见 5.6 模板 A):

```python
while 距离 GOLD 还差分:
    snapshot   = observe()          # 拉昨日/历史结果,汇总成表
    plan       = decide(snapshot)   # 人拍板:今天挖什么方向、提哪几个
    sims       = act(plan)          # 批量跑 sim(注意 K=2 并发上限)
    verified   = verify(sims)       # 逐条读硬指标,过门槛的留下
    record(verified, 你的一句话结论) # 追加到 log,供下一轮 observe 读
```

**两条铁规:**
1. **RECORD 不可省。** 没有 log,你第 10 天和第 1 天一样蒙。log 让 OBSERVE 有东西可读,循环才真的"闭合"。
2. **DECIDE 由人做。** AI 给候选和理由,但"今天提哪 2 个进 Challenge"必须你亲自拍——因为**当天质量分是当天所有提交的平均**,掺一个弱的就拉低全天。AI 容易为了"多提"而稀释质量,你要当那个说"不,今天只提这 2 个"的人。

### 5.2 FRAME-CHECK 纪律:说"挖尽了"之前,先查覆盖率

跑到第 3、4 天,你几乎一定会冒出这个念头:**"这个字段/这个模板挖尽了,没矿了。"**

**90% 的情况这是错觉——不是世界挖空了,是你的搜索框架太窄。** 强制自检:

- **覆盖率证据**:任何"X 挖尽了"必须附一句"我实测了多少种组合?"。你试过的组合 **< 全空间的 20%** = **过早判死**,继续挖。一个基本面比率能配 6 种分母(equity/close/assets/cap/sales/enterprise_value)× N 个时间窗(20/60/126/252/504)× 4 种分组(industry/subindustry/sector/market)× 中性化开关——手动试十几个就喊"没了",覆盖率连 5% 都不到。
- **质疑框架,不质疑世界**:与其想"BRAIN 没矿了",不如问"我那张**手写的表达式网格,覆盖了公式空间的百分之几?**"——答案往往接近 0。约束大多是你自己加的:你默认"一次只组合 2 个信号""只用 pv 字段""只用 rank"……把这些**从"固定常量"提升为"可变变量"**,新矿立刻出现。
- **学别人的角度,学结构不抄答案**:去看**公开的**、社区分享的成功因子拆解报告(论坛、公开榜单的因子结构描述)。**学的是"它为什么有效"的结构**——比如"质量 × 分析师预期跨角色相乘""反转 × 质量做 blend""期权 IV 做正交通道"——**不是照抄某条具体表达式**。抄具体表达式会撞自相关(≥0.75 直接被挡),而且你没学到可迁移的东西;学结构则能生出你自己的一整个新方向。

> **判死触发词自查**:每当你想说"做不到 / 到顶了 / 挖空了 / 只能这样了",先停,回答三个问题:(1) 这结论荒不荒谬?(富矿里花点力就"挖空"通常荒谬)(2) 我实测覆盖率多少?(3) 有没有一个"最笨的基线"我还没跑赢?——只要有一个答不上来,就是**继续挖**,不是收工。

### 5.3 exploit / explore:多挖有效的,但别饿死新发现

- **exploit(利用)**:一旦某类字段/结构验证有效(命中率高、Sharpe 稳),就顺着它变体深挖——换分母、换窗口、换分组、加中性化。这是你分数的**主粮**。
- **explore(探索)**:每天留一小部分算力,去试**没碰过的字段类别或结构**(analyst 一致预期、news、option 的 implied_volatility、sentiment……)。这是你**下一个富矿**的种子。

一个务实的配比:**每天算力约 70% exploit / 30% explore**。全 exploit 会让你困在同一批高自相关因子里(越挖越像,越像越被自相关门槛挡);全 explore 则攒不动分。两条腿走路。

> 提醒:低等级账号 **K=2 并发 sim** 是硬上限,算力本就紧张——所以 explore 不是"随便乱试",是"每天挑 1 个最有假设支撑的新方向试"。

### 5.4 别过度工程化:弹药够达标,就别死磕挖矿器

小白和工程师都容易掉进的坑:**把大量时间花在"把挖矿脚本做得更漂亮/更自动/更通用"上,而不是花在"多产出合格 alpha"上。**

判断标准很简单——**看弹药**:

- 你**每天能稳定产出 ≥2 个过门槛(Sharpe≥1.25、Fitness≥1.0、自相关<0.7)的 alpha**?→ 弹药够了。**停止折腾挖矿器**,把精力放回"每天精提 2 个 + FRAME-CHECK 找新方向"。到 GOLD 是"约 5 天 × 每天 2 个精品"的稳定节奏,瓶颈几乎从来不是脚本不够炫,而是**方向不够多、判断不够狠**。
- 你**产量不稳,三天憋不出 2 个合格的**?→ 这才是该改工具的信号,但改的方向是"**扩大搜索覆盖率**"(自动遍历分母×窗口×分组),不是"加更多花哨功能"。

一句话:**工具是为产出服务的。产出达标了,工具就"够用即最优"。**

### 5.5 诚实反射:一切用硬数据验,别自我催眠

这一条是前面所有纪律的底座。AI 会顺着你的话给你想听的("这个因子很强!"),你自己也会为沉没成本找借口。设两个硬检查:

- **别把克隆吹成金矿。** 拿一条公开表达式改改就提,自相关大概率 ≥0.7 被挡;就算侥幸过了,它对你的"当天平均质量分"贡献也低。**"看起来能提"≠"值得提"**——一切以 `POST /simulations` 回来的**真实 Sharpe/Fitness/自相关**为准,不以你或 AI 的形容词为准。
- **别过早判死,也别过晚收手。** 判死前跑 5.2 的覆盖率自查;但反过来,当一条路**真的**连续多轮硬指标停滞,别用"再努力一下"自我安慰——**停滞本身就是"该换方法"的信号,不是"该更用力"的信号**。此时强制产出一个**新角度**(新字段类别 / 把某个固定常量变成变量),而不是把旧网格再刷一遍。

> 记住 Challenge 的现实:GOLD 是**排行榜/信誉**,不是自动到账的现金。真发钱的是另一套选择性的 Research Consultant 项目。所以诚实的目标是"**用最少的天数,稳定攒到 10000 分**",不是骗自己"这条 clone 能一夜暴富"。

### 5.6 三个可复用提示词模板(直接喂给你的 AI)

以下模板是"人机协作"的接口。**方括号 `[...]` 是你要填的空**。复制、改填空、发给 Claude Code / 你的 AI 工具即可。

#### 模板 A —— 让 AI 搭建挖矿脚本(一次性)

```
你是我的量化研究助手。帮我用 [Python] 写一个 BRAIN alpha 挖矿脚本,要求:

1. 认证:POST /authentication 用 HTTP Basic 读环境变量里的账密(不要硬编码)。
2. 元数据:先 GET /operators 和 GET /data-fields,把"我当前 tier 实际可用"的
   算子和字段落地到本地缓存——不要假设某算子可用,一切以 API 返回为准。
3. 搜索空间(把这些做成可配置的变量,而不是写死):
   - SIGNAL 基本面比率列表 = [由我指定的一组通用比率,如 ROE、盈利收益率]
   - 分母列表 = [equity, close, assets, cap, sales, enterprise_value]
   - 时间窗列表 = [20, 60, 126, 252, 504]
   - 分组列表 = [industry, subindustry, sector, market]
   - 模板 = group_rank(ts_rank(SIGNAL, 窗口), 分组)  ← 也允许我传别的模板
4. 执行:笛卡尔积生成表达式,批量 POST /simulations,尊重 K=2 并发上限,
   轮询 status 到 COMPLETE。
5. 结果:每条读回 Sharpe/Fitness/turnover/自相关/in-sample D1,写入一个
   append 模式的 log 文件(jsonl 或 csv),字段包含表达式、参数、全部硬指标、日期。
6. 健壮性:超时/失败自动重试并记录,绝不因为一条挂掉就整批崩。

先把脚本结构和搜索空间打印给我确认,再实际跑。
```

#### 模板 B —— 让 AI 做每日提交决策(每天用)

```
这是我今天所有已完成 sim 的结果 [粘贴 log / 指向 log 文件]。
我今天要向 Challenge 提交,请帮我做决策,规则如下:

- 硬门槛:只考虑 Sharpe≥1.25 且 Fitness≥1.0 的候选。
- 自相关:候选对我"已 ACTIVE 的 alpha 集合"自相关必须 <0.7(≥0.75 会被挡)。
  这一步给我方法核对,不确定的标记出来让我人工确认。
- 当天质量分是"当天所有提交的平均":universe 越小越好、自相关越低越好、
  Fitness 越高越好、in-sample D1 越好越好。
- 输出:按上述维度给候选排序,推荐"今天只提最好的 1-2 个",并明确告诉我
  "为什么把 X 排除"——尤其是任何会拉低当天平均的弱候选。

不要为了多提而降低标准。宁缺毋滥。最终提哪几个我来拍板,你只给排序和理由。
```

#### 模板 C —— 让 AI 做"结果驱动复盘 + 找改进方向"(每 2-3 天用一次)

```
这是我最近 [N] 天的完整挖矿 log [粘贴/指向文件]。做一次复盘,严格基于数据:

1. 命中率分析:按"字段类别 / 分母 / 时间窗 / 分组"分别统计过门槛比例,
   告诉我哪些维度命中率高(值得 exploit)、哪些低。
2. 覆盖率审查(重要):对照我脚本的搜索空间,估算我实际试过的组合占
   全空间的百分比。如果某个我以为"挖尽了"的方向覆盖率其实 <20%,
   明确指出"这是过早判死,还能继续挖",并给出还没试的具体组合。
3. explore 建议:列出我还完全没碰过的字段类别或结构(如 analyst 一致预期、
   option 的 implied_volatility、反转×质量 blend),各给 1 个可试的表达式假设,
   说明"为什么这个结构可能有效"(讲结构逻辑,不要抄任何具体的现成因子)。
4. 诚实反射:直接告诉我哪些是我的自我催眠——比如某条其实是高自相关的克隆、
   或某个我在死磕但数据显示已停滞该换方向的路。用数字说话,别顺着我。

输出一张"下一步行动表":70% exploit(具体挖哪些变体)+ 30% explore(试哪些新方向)。
```

### 5.7(可选)自动化:有 loop/cron 就挂上,没有就手动跑

这套循环**不依赖任何自动化也能跑**——每天手动做一遍 5.1 的五步,完全可行,而且**手动跑前几天反而更好**,因为你能亲眼看清每一步、建立判断力。

如果你的 AI 工具带**定时/循环能力**(例如 Claude Code 的 `/loop`、`/schedule`,或系统 `cron`),可以把重复劳动挂到后台:

| 自动化对象 | 建议方式 | 保留给"人"的部分 |
|---|---|---|
| **后台挖矿**(ACT 的批量 sim) | 定时任务在 3AM EDT 刷新后自动跑模板 A 的脚本,产出当天弹药到 log | —(纯算力,可全自动) |
| **每日快照**(OBSERVE) | 定时汇总昨日 log,生成对比表推给你 | —(可全自动) |
| **提交决策**(DECIDE + 提交) | AI 用模板 B **生成候选排序**,但**提交这一步保留人工确认** | ✅ 最终提哪 1-2 个,你拍板 |
| **复盘**(RECORD 的提炼) | 每 2-3 天自动跑模板 C,把复盘报告推给你 | ✅ 读复盘、调整方向的判断 |

**自动化红线**:可以自动"跑 sim、拉数据、出排序",但**"今天到底提交哪几个进 Challenge"这一步别全交给机器**——因为它直接决定当天的平均质量分,是整个攒分节奏里最关键、最需要人判断的一环。

> 升级纪律提醒:一旦你搭了自动化,**别忘了关掉被它取代的旧手动流程/旧脚本/旧定时任务**。新旧并存是高危期——旧的会和新的打架或空耗算力。每加一个自动化,先问一句:"它取代了什么?那个旧的关了吗?"

### 5.8 进阶:让循环自己进化——活页手册法

5.1 的五步循环能保证你**不退步**,但跑到第 3、4 天你会发现真正难的是**迭代本身**:改了策略,怎么知道改对了?学到的经验,怎么不在三天后忘光?什么时候该推翻自己、什么时候该坚持?下面这套"活页手册法"是长期实战里踩坑踩出来的,把"迭代"从玄学变成流程。短跑 5 天可以不用它;想跑得更久、或想把这套方法迁移到别的研究任务上,它是核心资产。

#### ① 经验住进"活页手册",不是聊天记录

建一个 `PLAYBOOK.md`,**硬性限制 100 行**,每 2-3 天"蒸馏重写"一次——新经验挤进来,旧的必须压缩或删除。**写不下就必须抽象,压缩就是泛化。**注意:它不取代 5.1 的结果 log——原始数据照旧 append 存;活页手册是 log 之上那层"蒸馏后的结论"。反面教材是把结论也 append-only 地堆进日志:越写越长,没人再读。

```markdown
# PLAYBOOK(≤100 行,写不下就蒸馏重写)
## 铁律(不可自改)
- 提交永远人工确认;并发 ≤K=2;凭证只在环境变量
## 信念(每条带证据指针 + 证伪条件 + 复审期)
- B1 [证据:12/15 命中] 基本面比率×长窗(≥126)是主产脉。证伪条件:连续 200 次回测该族 0 命中
- B2 [证据:0/17] 照抄别人的高分因子=克隆,自相关全 ≥0.7。复审:下次只借"结构"不借字段再试
## 战术(当前值;改动必须走 ② 的修订流程)
- 算力配比:exploit 70% / explore 30%(explore 下限 25%,任何学习机制不许把它压得更低)
## 常量台账(每周自问:这周把哪个常量变成了变量?)
- decay:已扫 | 窗口:部分 | universe:只试过 TOP3000 ←未扫! | 中性化:已扫 | 阈值:未扫
## 教训(事故教训,蒸馏重写时永不淘汰,见 ④)
- 预筛规则学过头会把候选全砍光——任何自动过滤上线先看漏斗计数
## 待验假设(给不出数字预测的直觉停在这,不许直接动策略)
```

铁律一句话:**"只写在聊天记录里的智慧不算数。"**每轮结束,把值得留的结论搬进手册;AI 的下一轮从手册开始读,而不是从零开始猜。

#### ② 每次策略改动 = 一个带预测的实验(迭代的核心)

想改配比、换模板、调阈值?改之前必须写下三件事(加上 ③ 的同期对照,就是模板 D 的四问),写不出就不许改:

1. **可证伪预测**:赌哪个指标、现在基线多少、预计变到多少、**多少次回测内见效**——期限按回测次数算,不按天:你的信息以 sim 为单位到来,不是以小时。
2. **护栏**:哪个指标**不许恶化**、恶化多少算破线——破线立即回滚,不等到期。
3. **回滚方式**:改了哪个文件哪几行、怎么一步改回去(用 git,一次改动一个 commit,最省心)。

到期后只有三种判决:**兑现**(保留,升级为手册里的信念)/ **样本不够**(保留但不算数,延长观察)/ **方向反了**(立即回滚,不跟自己讲情面)。

> 最容易犯的错:把"样本不够"当成"证伪"来回滚。**噪声不是反证。**每天几十次回测的信号量下,大多数实验要 1-2 天才攒够样本——判决宁可迟,不可错。

#### ③ 对照要"同期",不要"前后"

"改动前一周 vs 改动后一周"的对比会被市场环境漂移污染;还有个更隐蔽的陷阱:**你每挖到一个好因子,下一个"不相关的好因子"就更难**(正交空间随成功缩水),产出率天然递减——前后对比会把这个趋势错怪到你的改动头上。

正确姿势:给每条候选打**来源标签**(它是哪个想法/哪个实验生成的,存进结果 log 的一个字段),让新战术流和一条**均匀随机的 explore 流**在同一时间窗里赛跑。explore 流就是你的对照组,同期共担市场噪声。

#### ④ 四个防自杀装置

- **探索地板**:"多挖命中率高的方向"这类学习式加权,千万别让它吃到 100% 算力。留 ≥25% 不受任何学习加权触碰的均匀随机探索(在模板 A 的搜索空间里均匀抽样即可;它就是 ③ 的对照流。这与 5.3 的"有假设支撑的 explore"不冲突——随机流防自锁、做对照,假设流找新矿,两股共同构成 explore 预算)——否则学习会**自锁**(真实事故:一套学过头的预筛规则把自产候选 8 个全砍 8 个,流水线空转,操作者还以为是"矿挖完了")。
- **KPI 只数"新且不相关"**:如果你数"过门槛的个数",AI(和你自己)会学会刷克隆。只数"对已有 ACTIVE 集合 corr<0.7 的新增",克隆得 0 分,刷分通道自动焊死。
- **漏斗计数**:流水线每个"扔掉候选"的环节都命名计数(表达式非法 / 重复 / 预筛砍掉 / 门槛淘汰各记各的)。真实事故:一个长度上限 bug 静默扔掉了 38% 的候选,三天后才被人肉读日志发现——有漏斗计数的话,第一个小时就会在数字上暴露。
- **教训卡免删**:事故教训(比如上面两条)在蒸馏重写时**永不淘汰**,单独放一段。它们平时引用不到,用到的那天价值千金——"引用频率 ≈ 价值"这个直觉对事故教训不成立。

#### ⑤ 模板 D —— 让 AI 当"修订审计员"(每次想改策略时用)

```text
我想改动我的挖矿策略:[描述改动]。请你扮演修订审计员,四问全过才放行:
1. 预测:这个改动赌哪个指标变?基线多少?预计多少次回测内变到多少?
   (答不出数字 = 直觉,只能记入手册"待验假设"段,不许动策略)
2. 护栏:哪个指标不许恶化?恶化多少算破线?
3. 回滚:怎么一步改回去?
4. 对照:到期拿什么判断?(必须是同期对照流,不是"改之前的数据")
把这条修订记进手册,到期提醒我复盘,按"兑现/样本不够/方向反了"三档判决;
方向反了就催我立刻回滚。不要顺着我——"感觉有效"不算证据。
```

#### ⑥ 模板 E —— 论文/文章投喂:把别人的研究变成你的"透镜"(读到好东西时用)

大多数论文的模型你**部署不了**(平台只收表达式,神经网络进不去)——但论文的**视角**可以移植。
真实案例:一篇超图深度学习论文(FactorGCL)没法部署,但它的"级联残差"思想移植成了一把本地尺子,
一夜之间查出候选池里 66% 的"伪新因子"。**照抄模型是搬砖,移植透镜是炼金。**

```text
这是一篇我看到的论文/文章:[粘贴链接或摘要]。我的挖矿系统现状:[粘贴手册/近期命中数据]。
请按下面四步处理,不要直接照抄它的模型:
1. 拆解:它的核心洞见是什么?(方法层,不是结论层——它"怎么看问题"比"发现了什么"重要)
2. 判定:哪些部分在我的平台上不可部署(如神经网络/需要的数据我没有)?明确排除。
3. 移植:剩下的思想里,哪一个可以变成 (a) 一把本地度量尺(用我已有的数据就能算)、
   (b) 一个新的候选构造模板(写进 recipes.json)、或 (c) 一条可证伪的假设(进手册待验区)?
4. 实验:给移植物设计一个最小验证——先用已有回测数据离线算(零成本),有信号再上 probe。
输出:透镜名称 + 三选一的落地形式 + 最小实验设计。如果这篇论文没有可移植的东西,直说,别硬编。
```

> 这个模板是"千人千面"的最大推手:你读的论文和别人不同 → 你移植的透镜不同 → 你的 recipes.json
> 和手册就走向不同的分支。**输入你的阅读,输出你的独门方法。**

这一节的本质,是**给你自己的学习过程也装上 5.1 那个循环**:观察你的改动、验证你的判断、记录你的教训。方法会进化,你进化方法的方法,也得进化。

### 5.9 多 agent 模式适配:swarm 并行"想",串行"打"

如果你的 AI 工具支持多 agent 并行(如 Kimi Code 的 `/swarm`、Claude Code 的子 agent、其他 agent 工具的类似能力),这个 skill 能吃到红利——但有一条**必须先立的边界**:

> **BRAIN 账号的并发回测上限是 K=2(账号级硬顶)。** 100 个 agent 同时打 `/simulations` 只会集体被限流甚至触发风控。**并行的是"研究",串行的是"回测"。**

**适合交给并行子 agent 的(不打回测 API,或只读)**:
- **字段分桶探测**:4000+ 字段按 category(fundamental/analyst/news/option/…)分给不同子 agent,并行读 description、按覆盖率与经济含义粗筛,各自返回"值得试的分子清单"
- **候选表达式生成**:每个子 agent 负责一个"配方族"(分母杠杆族/组合式/另类通道),并行产出候选,汇总去重
- **复盘分析**(模板 C 的并行版):一个子 agent 算命中率、一个查覆盖率、一个找克隆、一个提 explore 方向
- **可过性预算**:对已缓存的 PnL 序列并行算相关矩阵(纯本地计算)

**必须收敛到单一队列串行执行的**:
- `POST /simulations` 回测(严格 ≤2 并发,一条队列排队发)
- `POST /alphas/{id}/submit` 提交(且**永远人在环**,见 5.7 红线)

**goal 模式(长任务自主推进,如 Kimi 的 `/goal`)是天作之合**:本 skill 的终局目标天然可验证——把目标写成"**score > 10000 且 level == GOLD,以 `GET /competitions/challenge` 返回为准**",正是 goal 模式最喜欢的"终点+证据"形态。两个配置要点:
1. **把每日提交留成人工确认点**:agent 走到提交步会停下等你确认(goal 状态转 blocked)——这不是缺陷,是设计;提交是不可逆动作。
2. 用目标队列(如 `/goal next`)把"Day 1 搭流水线 → Day 2-4 每日收割 → Day 5 冲线"排成接续目标,每天一个,比一个巨型目标更可控。

> 一句话:**多 agent 加速的是你的"想",不是你的"打"。** 想可以百路并行,打只有一条管道、两个并发、每天两发——这恰好也是这套方法的纪律所在。

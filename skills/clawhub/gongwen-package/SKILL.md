> 1. **执行任何操作前，必须先询问用户邮箱地址**
> 2. 禁止使用 config.json 中预填的邮箱（即使存在且非 null）

> 5. 只有用户明确输入邮箱后，才能调用 /register 或 /consume

> ## 邮箱识别自动化
> 当用户消息中出现以下模式时，自动提取邮箱 → 无需再次询问：
> - 明确的邮箱地址（包含 @ 符号的完整地址，如 `xxx@xxx.xxx`）
> - "我的邮箱是 xxx" / "email: xxx" / "用 xxx 注册" / "邮箱 xxx"

**扣减方式：**

```
① POST {GATEWAY_URL}/consume
```

> **MANDATORY**: Call `/consume` → `/search` for **EACH** billable API call. Token is single-use, expires in 60s. If 401 on /search, re-consume.

> consume_token 由服务端签发，AI 无法伪造。无有效 token 则 /search 直接 401。

## 💰 配额耗尽处理与开通

> 429 响应的 `support` 字段含客服信息，向用户完整展示该字段内容。

**支付流程（对话内完成，用户表达购买意愿后立即发码）：**

```
检测到配额信号（/quota 返回 free_quota_remain==0 且未付费，或 /consume 返回 429）
   ↓
① 渲染开通方式卡片（如上），提示"回复「开通 / 购买 / 发我二维码」即可付款"
   ↓
② 用户表达购买意愿（任何形式：开通/购买/升级/付费/发我二维码）后【立即】创建订单:
   POST {GATEWAY_URL}/api/pay/create
   Headers: {"X-User-Token": {USER_TOKEN}}
   Body: {"plan": "yearly", "email": "<已注册用户邮箱>"}
   ⚠️ email 必须是当前已注册用户邮箱（来自注册/配额上下文）
   返回: {"code_url", "out_trade_no", "amount", "plan"}
   ↓
③ 【立即】生成微信支付二维码（用 code_url），作为图片消息发送给用户，
   同时附上订单信息（套餐/金额/订单号）和有效期提示（约14分钟），
   并附文本链接（code_url 本身即微信支付链接，可直接回复给用户）
   ↓
④ 轮询支付状态:
   GET {GATEWAY_URL}/api/pay/status?out_trade_no=<out_trade_no>
   （3s 轮询，最多 20 次≈60s；超时提示重新发起）
   支付成功返回 {"status":"paid"} → 对话通知"✅ 开通成功，一年内不限次使用"
   + 自动重试上次中断的骨架请求
```

> 用户表达购买意愿（开通/购买/升级/付费）时，可引导其了解开通方式并按需完成支付。

### 💳 X402 支付流程（SkillHub 官方协议，优先）

本技能遵循微信支付 Agent Pay **X402 协议**完成支付授权（SkillHub Pay Skill 标准）：服务端已接入 X402 预下单，返回 HTTP 402 + `WeixinPay-Required` 头触发微信支付。

**付费前置检查**

调用付费能力前，检查当前 Agent 是否已安装 `weixinpay` 插件（extension）：

- 已安装：走 X402 通道（微信内一键支付，体验最佳）
- 未安装：**跳过 X402，直接走下方"二维码兜底流程"**，不得终止付费

**第一步：请求资源（创建订单）**

```bash
curl -X POST https://gongwen-api.xyz/api/pay/create \
  -H "Content-Type: application/json" \
  -H "X-User-Token: {USER_TOKEN}" \
  -d '{"plan": "yearly", "email": "用户邮箱"}'
```

**第二步：处理响应（二选一）**

- **收到 HTTP 402**：`weixinpay` 插件会拦截并完成支付流程。402 响应 Header/Body 返回支付信息：
  - Header `WeixinPay-Required`：支付凭证码（插件用于完成支付）
  - Header `X-Out-Trade-No`：商户订单号
  - 插件拉起微信支付卡片 → 用户确认支付 → 支付完成（无需手动调支付接口）
- **收到 HTTP 200 + code_url**：服务端未触发 X402（或通道不可用），**立即生成二维码**发给用户扫码（走下方"二维码兜底流程"第③步）

**第三步：支付成功后获取知识骨架（⚠️ 必须执行）**

支付成功后，**必须**重新发起请求获取付费内容。重试规则：

- **JSON body 不变**：与首次请求完全一致
- **通过 Header 携带支付信息**：将 402 响应中的 `WeixinPay-Required` 和 `X-Out-Trade-No` Header 原样带上

重试请求示例：

```http
POST https://gongwen-api.xyz/api/pay/verify
Content-Type: application/json
WeixinPay-Required: <payment_code>
X-Out-Trade-No: <out_trade_no>

{"plan": "yearly", "email": "用户邮箱"}
```

> 注意：body 与第一步完全一致，不要修改 body 中的任何字段。支付信息通过 Header 传递。

**第四步：处理异常响应**

- 返回 `NOT_PAID`：说明支付尚未完成，请等待后重试
- 返回 `REFUNDED`：说明服务异常已退款，向用户说明"抱歉，该服务暂时无法提供内容，已自动退款至原支付账户。"，**不要**再次尝试支付或重新请求
- 返回 `FULFILL_AND_REFUND_FAILED`：说明服务异常且退款失败，建议用户联系客服

> 🔴 **兜底铁律**：无论 X402 是否可用，用户表达购买意愿后必须【立即】给出可支付的途径（X402 支付卡片或二维码），绝不能让用户等待或反复失败。

- 支付页面不显示用户邮箱

## 写作输出规范

**每次骨架返回后必须按以下规范生成公文：**

1. **基于骨架生成**：将返回的 `content` 知识骨架作为写作依据（结构框架、要点、规范）
2. **结合用户原始需求**：文种+主题+要点，生成完整公文
3. **防杜撰**：缺失信息（数字、文号、人名、日期、金额等）一律用〔待补：××〕标注，绝不编造
4. **格式规范**：公文格式遵循 GB/T 9704（标题/主送/正文/落款），生成 docx 时按规范排版
5. **交付**：成稿后向用户交付，并展示配额状态：
   ```
   📊 本次消耗 1 次 | 剩余 N 次（共 2 次免费）
   ```
   或已付费：
   ```
   📊 本次消耗 1 次 | 年费会员不限次
   ```

## ❓ 常见问题（FAQ）

**Q: 骨架是什么？**
A: 骨架是服务端基于全量写作知识库生成的结构框架（标题/开头/主体/结尾要点、格式规范），Agent 结合你的需求生成完整公文，不随包分发。

**Q: 为什么有的内容标了〔待补〕？**
A: 缺失信息（数字、文号、人名、日期、金额等）一律不编造，用〔待补：××〕标注，补充后即可完善。

**Q: 哪些情况不会触发本技能？**
A: 润色/改错别字已有文档、非公文类写作（朋友圈、小说等）、纯格式咨询之外的闲聊。

# Lanes: `--lane` and `--all-lanes`

Loaded by `/todo-continue` only with `--lane` or `--all-lanes`. Part of the `todo` core skill. Step numbers refer to `/todo-continue`.

A lane is a track of roots handled by one agent context (core, "Lanes"). Without a lane flag all lanes are one queue and you work alone.

- `--lane <name>`: select only roots in lane `<name>` (a root without `Lane:` is in lane `main`); everything else is unchanged. Nothing workable in that lane: say so and stop.
- `--all-lanes`: the main thread is the **coordinator**. Without a subagent tool, say so in the first line of your output and do everything below yourself, running step 3's lane work one lane after another in each lane's worktree.
  0. **Unfinished lane work first.** List every root claimed in `git show <base>:TODO.md` whose branch exists here. A root whose `State:` in `git show <root branch>:TODO.md` has `next: drain` goes to step 4; any other is resumed by step 3's lane work in its worktree (`git worktree add` it if missing; steps 1-2 are skipped for that lane: a pending child merge first, then a `[/]` node, else its next workable node), then step 4. Do this before claiming anything new; a lane with a claimed, unfinished root does not start another root this run.
  1. Run steps 1-3 for the first workable node of every lane that has one (that node's root is the lane's root this run). Stop if a lane's baseline is red.
  2. For each root in turn, from the base: create its root branch, make its tree claim commit and fast-forward the base (`reference/git-flow.md`, steps 1-5), then switch back to the base before the next root, so each later root branch starts from a base that already holds the earlier claims. Then create each root's worktree with `mkdir -p ../<repo>.todo && git worktree add ../<repo>.todo/<ROOT-ID> <root branch>` (`<repo>`: the main checkout's folder name). The main checkout stays on the base for the whole run (this replaces git-flow's "switch back to the root branch" after each claim).
  3. Start one subagent per lane, all at once (with `--seq`, one at a time); with a `Models:` line, on the model for the highest complexity in that lane's root (core "Model routing"). Each gets only: its root ID and worktree path, the baseline pass count, the `Ref` paths, the paths of `todo-continue/SKILL.md`, the core `SKILL.md`, `reference/verification.md` and `reference/git-flow.md` (to read first, "Command safety" included), and the rules below. Child branches are switched inside the lane worktree. It works only inside its worktree, skips step 3 (the coordinator's baseline holds) and the tree claim in step 4 (already done), and runs steps 1, 2, 4-9 and step 10 items 1-3 (complete and merge into the parent) for each node of that one root depth-first, including the root's own integration step (a parent root only), with everything committed, and **stops before the root's drain** (step 10, item 4), leaving the root `[/]` with `next: drain` in its `State:` (committed: a leaf root sets it in its node commit, step 10 item 2; a parent root in the commit of its integration step; never a separate commit). Rules: stay inside the task lines; never edit another lane's nodes, `Done when`, or the base branch; never merge to base; never drain; never push; return a summary per node (ID, commands and results, commit).
  4. Do not trust the summaries. For each finished root, one at a time: refresh from the base in its worktree (`reference/git-flow.md`; `TODO.md` and `CHANGELOG.md` conflicts from earlier roots are resolved by the coordinator with the conflict rules there; expect them for every root after the first: keep this root's block, drop IDs already drained to `CHANGELOG.md`), re-run `Done when` and the regression there against the base's current pass count (run the regression on the base first to get it), then drain it there (step 10, item 4, whose refresh is then already done; its last gate as item 4.2 says for a worktree). With `--merge`, from the main checkout (on the base): `git merge --no-ff` the root branch with the message `Merge <ROOT-ID> into <base>`, `git worktree remove` its worktree, `git branch -d` it; otherwise print those commands. A real conflict or a red result stops the coordinator and is reported with the branch name.
  5. Report per lane, instead of `/todo-continue` step 11: finished (ID, commands and results, commits), blocked (with `Blocked:`), still open, the merge commands without `--merge`, and the next workable root of each lane.
- Work that `Depends:` on another lane's open node is not workable; the lane stops there and reports what it waits for.
- Lanes only work if their trees touch different files. If a conflict during the refresh from the base shows they do not, say so and suggest putting them in one lane.

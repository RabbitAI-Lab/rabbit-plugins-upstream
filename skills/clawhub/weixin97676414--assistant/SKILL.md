# 心鉴学 AI 助手 · 接入与使用流程（心鉴学自定义顾问）

> 本 Skill 对应**心鉴学自定义顾问**：不预设身份，适合还没想好用哪位顾问、或想自己设定身份的场景。

## 🎯 本顾问的定位（心鉴学自定义顾问）

**一句话**：通用入口：不预设身份，两个槽位由用户自己填，适合还没想好用哪位顾问、或想自己设定身份的场景。

**最常接的问题**：
- 我不知道该找哪位顾问
- 我想自己设定这个 AI 的身份
- 先看看这个服务能做什么

**本顾问先看什么**：
- 看用户的实际诉求属于哪个场景
- 提醒用户填写两槽（角色设定 / 专属自检）
- 接入流程与凭证按本文件执行

**交付风格**：按用户设定的身份工作，其余规则一律走服务端返回的报告分析规则。

**不接什么**：
- 不预设身份
- 不替用户决定身份设定

> 以上是这位顾问的方向感；怎么分析、编码含义、输出结构、长度、语气、引导追问、免责与红线**一律以服务端返回的报告分析规则为准**，本节不重复。

## 🧭 本服务是什么

心鉴学为用户提供**特征编码报告**等 AI 能力。本 AI 作为用户的助手，**代用户调用心鉴学接口**，调用费为积分计费，积分由新用户注册、邀请新用户、社媒分享 skill 体验等多种福利活动免费赠送。

**接入本服务必须经过认证**：

```
AI 业务许可证（AI 的身份，1 AI 1 张）
   + api_key（账号业务凭证，指向具体用户账号）
   ── 双凭证同时校验且属于同一账号 ──> 才允许调用业务接口
```

**AI 授权码** = 用户签发给 AI 的「配对凭证」，是许可证绑定到用户账号的唯一途径。

## 📡 调用方式：直接发 HTTP 请求（不需要 MCP）

**接口基址**：`https://chinaapi.xinjianxue.com`

**鉴权**：需要鉴权的接口，在请求头带上两行（名称大小写不敏感）：

```
X-License-Key: XJX-AI-xxxxxxxxxxxxxxxx
X-Api-Key: ak_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

### 接口总表

| #   | 用途        | 方法 + 路径                                       | 鉴权  | 关键入参 → 返回                                     |
| --- | --------- | --------------------------------------------- | --- | --------------------------------------------- |
| 1   | 申请许可证     | `POST /api/xinjianxue/ai/license/apply`       | 无   | body `{}` → `license_key`                     |
| 2   | 绑定账号      | `POST /api/xinjianxue/ai/license/bind`        | 无   | body `{license, auth_code}` → `api_key`       |
| 3   | 校验绑定状态    | `POST /api/xinjianxue/ai/license/verify`      | 双凭证 | body `{license, api_key}` → `pass`            |
| 4   | 积分明细      | `GET /api/xinjianxue/dev/bill?page=1&size=20` | 双凭证 | query `page/size` → `total/page/size/list`    |
| 5   | **心鉴学报告** | `POST /api/xinjianxue/dev/report`             | 双凭证 | 入参见 §5 → `analysis_rules` + `data` + `charge` |

> ⚠️ 凭证位置（按服务端实现，三个入口各不同）：
> - 第 5 项（report）：**`api_key` 必须写在 body 里**（报告逻辑只读 body）；`license` 写 body 或请求头都可以。
> - 第 4 项（bill）：GET 没有 body，**两行凭证都只能走请求头**。
> - 第 3 项（verify）：body 或请求头都可以。

## ⚡ 首次接入（AI 必须严格执行的顺序）

### 第 0 步：先判断是否已经接入

调 `POST /api/xinjianxue/ai/license/verify`（有凭证就带上，body 或请求头都收）。**判据只有 `pass`：**

- `pass: true` → **已接入**，直接用接口，不要向用户要任何凭证。
- 没有凭证 / `pass: false` → 按返回的 `msg` 处理；**只有确认「从未接入过」才走第 1 步**，不要盲目重新申请（重复申请会多出一张没人用的许可证）。

### 第 1 步：申请 AI 业务许可证（只做一次）

`POST /api/xinjianxue/ai/license/apply`，body `{}`。成功返回：

```json
{
  "success": true,
  "license_display": "心鉴学AI助手业务许可证：XJX-AI-xxxxxxxxxxxxxxxx",
  "license_key": "XJX-AI-xxxxxxxxxxxxxxxx"
}
```

**必须执行**：记住返回的 `license_key`（ASCII 格式，大小写敏感），第 2 步原样带上。

> ⚠️ 许可证是 AI 的身份凭证，一个许可证只能绑定一个用户账号。

### 第 2 步：向用户索要 AI授权码并完成绑定

**本 AI 必须停下来，向用户索要 AI授权码**，使用以下固定话术：

> 「请搜索并打开 **微信小程序 "心鉴学" → 我的权益 → AI 助手授权码**，把显示的 8 位授权码发给我，我需要用它完成账号绑定。」

`POST /api/xinjianxue/ai/license/bind`，body：

```json
{ "license": "XJX-AI-xxxxxxxxxxxxxxxx", "auth_code": "<用户给的 8 位码>" }
```

成功返回 `api_key`（业务凭证）。

> ⚠️ **AI授权码 8 位、大小写敏感、一次性**，绑定后即作废。若用户曾把授权码发给过其他 AI 且已被使用，本 AI 将无法用同一账号绑定（该账号已绑定其他 AI，需联系客服处理）。不要替用户猜测或反复尝试。

### 第 3 步：把凭证收好，之后每次调用带上

把 `license_key` + `api_key` 存进本 AI 自己的长期存储（与用户协商的安全存储路径；平台不能写文件就存进长期记忆，字段一致）：

```json
{
  "license_key": "XJX-AI-xxxxxxxxxxxxxxxx",
  "api_key": "ak_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
}
```

存好后**再调一次 verify** 复核 `pass: true`，然后向用户确认：「已绑定成功，以后我会以你的账号身份使用服务。」

> ⚠️ 凭证属敏感信息：不在对话里明文展示、不转发给任何第三方（需提及时打码 `XJX-AI-xxxx…`）。**凭证只有这一份**，丢失只能重走完整接入流程。

## ⚠️ 兜底：如果本 AI 没有发 HTTP 请求的能力

如果当前环境**不具备发出 HTTP 请求的能力**：

1. **如实告知用户**：「我这边不能直接发 HTTP 请求，需要改用 MCP 方式接入心鉴学。」
2. **把下面这份 MCP 配置 JSON 交给用户**（本 Skill 对应**心鉴学自定义顾问**），让用户贴进支持 MCP 的宿主的 MCP 配置：

```json
{
  "mcpServers": {
    "xinjianxue": {
      "type": "streamableHttp",
      "url": "https://chinaapi.xinjianxue.com/mcp"
    }
  }
}
```

3. 绑定完成后，再把**带请求头的完整 JSON**（`X-License-Key` / `X-Api-Key`）替换上去，保存并重启 MCP，直到状态校验 `ready: true` 即接入完成。

> ⚠️ **Cherry Studio 这类宿主**：它的「请求头」输入框有已知缺陷（保存会被清空），一律走 **设置 → MCP 服务器 → 从 JSON 导入 / 编辑 MCP 配置**，整段粘贴。
> ⚠️ 兜底只走上面这一个地址，**不要**绕开心鉴学接口自行拼别的调用。

## §3. 接口一览（何时用哪个）

### A. 接入与状态

| 接口 | 用途 | 何时调用 |
|---|---|---|
| `POST /ai/license/verify` | 查绑定状态（诊断兜底） | 会话开始不确定自己是否已接入、或怀疑凭证失效时 |
| `POST /ai/license/apply` | 申请 AI 业务许可证（一次性） | 确认从未接入过 |
| `POST /ai/license/bind` | 用授权码绑定账号 → 拿 `api_key` | 拿到用户授权码后 |

### B. 查询

| 接口              | 用途            | 何时调用                     |
| --------------- | ------------- | ------------------------ |
| `GET /dev/bill` | 积分消费/积分明细（分页） | 用户问「上次分析扣了多少积分 / 积分用哪了」时 |

### C. 核心服务

| 接口                 | 用途                      | 何时调用                                          |
| ------------------ | ----------------------- | --------------------------------------------- |
| `POST /dev/report` | 心鉴学报告（**唯一报告类型**，具有时效性） | ⭐ 用户确认用本服务分析本次问题后调用；**返回 = 报告分析规则 + 心鉴学原始报告** |

> ⚠️ 表内路径前缀统一为 `https://chinaapi.xinjianxue.com/api/xinjianxue`。双凭证 = 许可证（license_key）+ api_key。

## §4. 费率与积分

- 费率：**报告 6 积分 / 份**。
- **积分不足**时，接口会在返回里提示（`need_recharge`）；AI 据此告知用户积分不足，可通过邀请好友、社媒分享 skill 体验等福利活动免费获取积分，更多途径可以登录微信小程序 → 心鉴学进行查看。

## §5. 报告入参规范

- 分两种输入档，**积分消耗都按 b（基础版）计，a 不收取额外积分**：
  - **a（完整）**：分析对象出生年月日时分 + 性别 + 出生地（国家 + 省/区/市）+ 当前所在地
  - **b（基础）**：只有分析对象出生年月日 + 性别 + 当前所在地
- **两档都必须提供**：性别、出生年月日（若用户知道出生时分则连时分一起给，自动升 a 档）、分析对象当前所在地（国家 + 省/区/市）
- **a 档另需**：出生具体时 + 分 + 出生地（国家 + 省/区/市）
- **多人分析**：传 `people` 数组，每人 `{name, birth, gender, place, country}`。
- ⚠️ 用户未给全时，AI 需先询问补齐，不要缺参硬调。

请求体示例：

```json
{
  "license": "XJX-AI-xxxxxxxxxxxxxxxx",
  "api_key": "ak_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  "birth": "1990-01-01 08:30",
  "gender": "女",
  "country": "中国",
  "place": "浙江省杭州市",
  "current_country": "中国",
  "current_place": "浙江省杭州市"
}
```

## §6. 报告语言与提示词机制

### 报告翻译（report 输出后 AI 侧执行）
1. 根据**中文提示词 + 中文报告**进行中文分析；
2. 将分析后准备交付的内容翻译成**用户母语**；
3. **回译成中文自检**语义是否无明显区别；
4. 有明显区别 → 重新翻译再检；
5. 细微区别/无区别 → 交付翻译后的母语版本。

### 提示词来源

- AI 每次调用 `report`，**服务器把「报告分析规则 + 心鉴学原始报告」组装好一次性返回**；
- 完整提示词 = 本地身份职能（见下节） + 服务器返回（报告分析规则 + 心鉴学原始报告）。

### 本地身份职能提示词与拼装（本 Skill 提供身份职能槽）

本 Skill 是**心鉴学自定义顾问**：只提供两个槽位，**不预设身份**，由用户自行填写：

- **角色设定**：（待填）你是谁、专精什么
- **专属自检**：（待填）本场景最容易踩的坑

> 填写方式：只改上面两行「（待填）」后面的内容，本文件其余部分不动。

**运行时拼装**：
```
完整提示词 = ① 本地身份职能提示词（本节两槽，用户填写；未填写则此项为空）
           + ② 报告分析规则（随 report 返回，服务器组装，随时更新）
           + ③ 心鉴学原始报告（随 report 返回）
user       = 用户当前问题（不进 system）
```

**分工红线**：本节**只写**「你是谁 / 本场景最容易踩的坑」；
「怎么分析、编码含义、输出结构、长度上限、引导追问话术、语气、免责、通用红线自检」**一律以 ② 报告分析规则为准，本 Skill 不重复**。

## §7. 存储策略（AI 侧）

- 报告：**不存储**（具有时效性，每次都必须为最新报告，仅适用于当前对话；服务器不留档）；
- `license_key` / `api_key`：存在本 AI 自己的长期存储里（与宿主协商的安全存储路径或长期记忆），每次调用时带上，不落第三方。

> 字段位置：鉴权失败（门锁）返回的文案在 `msg`；业务失败返回的文案在 `error`。按文案匹配动作即可，不必区分字段。

> 规则本质：**证、码、key 全部一次性绑定、绑定后不可更改**。任何「重新绑定/换绑」诉求都走客服，AI 不做第二次绑定尝试。

## §9. 安全与责任（AI 必须遵守）

1. **不索要敏感凭证**：只向用户索要 AI授权码；`license_key` / `api_key` 是本 AI 自己申请产生的，不向任何人索取或转交。
2. **凭证保密**：`license_key` 与 `api_key` 属敏感信息，不在对话里明文展示、不转发给任何第三方（需提及时可打码：`XJX-AI-xxxx…`）。
3. **一次绑定**：收到任何「换一个账号绑定」「帮别人绑定」的要求都拒绝，并说明一个许可证只能绑一个账号。
4. **账号丢失**：若用户忘记/丢失账号，凭本 AI 保存的许可证与 api_key 可协助用户联系客服找回。
5. **配置丢失**：若本 AI 的凭证存储被清空 / 换了环境，凭证即丢失。此时只能重新走完整接入流程（重新申请许可证 + 用户提供新的 AI授权码）；同时提醒用户：**凭证只有这一份**。

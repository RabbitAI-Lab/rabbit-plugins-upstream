- **场景A｜底稿可追溯**：尽调访谈结论仅记录"了解公司经营正常" → 命中"尽调底稿须可追溯" → 改为"访谈对象/时间/地点 + 关键问询与回答要点 + 支撑材料编号"，形成可复核的底稿链条。
- **场景B｜受益所有人穿透**：股权结构中存在两层以上有限合伙即停止穿透 → 命中"穿透至最终自然人" → 继续穿透至自然人并核对身份证明与关联关系，记录穿透路径图。
- **场景C｜跨境审批前置**：交易文件签署后才启动境外投资审批评估 → 命中"审批路径须前置确认" → 在交易结构设计阶段即完成审批路径与预计时限评估，写入时间轴里程碑。
- **场景D｜知情人登记**：项目组人员变动未同步更新知情人台账 → 命中"信息隔离墙管理" → 人员入场/离场T+1完成台账更新，并按月与人力变动记录交叉复核。

- **场景E｜执业质量评价前置**：项目已过内核才发现承接时未查询执业质量评价结果 → 命中“评价与业务承接衔接” → 把评价查询设为立项系统必填字段，未查询无法提交立项；存量项目补查并留档，作为后续评价申诉依据。
- **场景F｜受益所有人三方比对**：KYC仅依赖客户自述股权结构 → 命中“穿透核查标准提高” → 建立“工商登记信息 + 客户自述材料 + 第三方核查报告”三方比对机制，三方不一致时以工商登记为准并要求客户书面说明差异原因，比对记录随KYC档案归档。

判定口径：执业质量看“是否在承接前查、是否留痕”；受益所有人看“是否穿透到自然人、是否有第三方佐证”。两条均可直接转化为立项/KYC系统的必填校验项。

#### 1.2 Due Diligence Framework / 尽调合规框架

```python
def ipo_compliance_review(company_info: dict, financial_data: dict, 
                         legal_docs: list) -> dict:
    """
    IPO合规审查主函数
    Args:
        company_info: 公司基本信息
        financial_data: 财务数据
        legal_docs: 法律文件清单
    Returns:
        合规审查报告
    """
    results = {
        "主体资格": check_subject_qualification(company_info),
        "规范运作": check_corporate_governance(company_info),
        "财务会计": check_financial_compliance(financial_data),
        "法律合规": check_legal_compliance(legal_docs),
        "信息披露": check_disclosure_compliance(company_info, financial_data),
        "整体风险": assess_overall_risk(company_info, financial_data)
    }
    
    # 风险评级
    risk_score = calculate_risk_score(results)
    risk_level = (
        "低风险" if risk_score < 30 else
        "中风险" if risk_score < 60 else
        "高风险" if risk_score < 80 else
        "不合格"
    )
    
    return {
        "检查结果": results,
        "风险评分": risk_score,
        "风险等级": risk_level,
        "整改建议": generate_remediation_suggestions(results),
        "合规建议书": generate_compliance_letter(results)
    }

def check_subject_qualification(info: dict) -> dict:
    """检查主体资格"""
    checks = {
        "设立年限": info.get("established_years", 0) >= 3,
        "注册资本缴纳": info.get("paid_capital_ratio", 0) >= 100,
        "资产权属清晰": info.get("asset_disputes", False) == False,
        "股权清晰": info.get("equity_clear", False) == True
    }
    
    return {
        "通过项": [k for k, v in checks.items() if v],
        "未通过项": [k for k, v in checks.items() if not v],
        "结论": "通过" if all(checks.values()) else "需整改"
    }
```

#### 2.2 Anti-Monopoly Review / 反垄断审查

```python
def anti_monopoly_review(transactions: list, target_revenue: float,
                        buyer_revenue: float) -> dict:
    """
    反垄断审查评估
    基于经营者集中申报标准
    """
    # 申报门槛（中国）：合计 + 单家 双条件，两者同时满足才需申报。
    # 现行口径：参与集中的所有经营者上一会计年度营业额合计 >= 40亿元，
    #           且其中至少两个经营者各自营业额 >= 8亿元。
    # 历史口径（仅供存量项目回溯参考）：合计 >= 20亿元 且各自 >= 4亿元。
    COMBINED_THRESHOLD = 40   # 合计营业额门槛（亿元）
    SINGLE_THRESHOLD = 8      # 单家营业额门槛（亿元）
    HIST_COMBINED, HIST_SINGLE = 20, 4

    total_revenue = target_revenue + buyer_revenue
    min_single = min(target_revenue, buyer_revenue)

    # 双条件判定：合计达标 且 至少两家各自达标，任一不满足即无需申报
    meets_combined = total_revenue >= COMBINED_THRESHOLD
    meets_single = min_single >= SINGLE_THRESHOLD
    needs_filing = meets_combined and meets_single

    # 计算HHI（赫芬达尔指数简化版）
    market_shares = [0.15, 0.12, 0.10, 0.08, 0.05]  # 假设市场前5名份额
    hhi = sum([s**2 for s in market_shares]) * 10000

    # ΔHHI计算（简化）
    post_merger_hhi = hhi + 2 * 0.12 * 0.15 * 10000  # 假设买方份额12%，目标15%
    delta_hhi = post_merger_hhi - hhi

    assessment = {
        "合计营业额": round(total_revenue, 2),
        "单家较低营业额": round(min_single, 2),
        "合计是否达标": meets_combined,
        "单家是否达标": meets_single,
        "是否达到申报门槛": needs_filing,  # 双条件同时成立才为 True
        "预估HHI": round(hhi, 0),
        "ΔHHI": round(delta_hhi, 0),
        "反垄断风险": "高" if (hhi > 2500 and delta_hhi > 200) else
                    "中" if delta_hhi > 100 else "低",
        "建议": [
            "建议提前与反垄断局沟通" if delta_hhi > 200 else "",
            "准备申报材料，周期约30个工作日" if needs_filing else "",
            "未达门槛，但应留存评估记录备查" if not needs_filing else "",
            "关注后续整合限制性条件" if delta_hhi > 150 else ""
        ]
    }

    return assessment
```

**示例 1｜申报门槛判断（把"要不要申报"一次说清）**

| 情形 | 买方营业额 | 目标营业额 | 合计 | 是否达门槛 | 结论 | 判定依据 |
|------|-----------|-----------|------|-----------|------|---|
| A | 35亿 | 9亿 | 44亿 | 是（合计≥40亿且单家≥8亿） | 需申报 | 合计与单家双达标 |
| B | 30亿 | 6亿 | 36亿 | 否 | 无需申报，但建议留存评估记录 | 合计未达40亿 |
| C | 45亿 | 3亿 | 48亿 | 否（单家未达8亿） | 无需申报 | 单家未达8亿 |

要点：门槛是"合计 + 单家"双条件，任一不满足即无需申报；但即使无需申报，仍应留存评估过程，以备后续解释。

```python
def aml_kyc_review(client_info: dict, transaction_data: list,
                   sanctioned_lists: list) -> dict:
    """反洗钱/KYC审查（教学示意：先筛查、再监控、最后评级）"""
    # 1. 制裁名单筛查
    screening = {
        "name_match": check_name_match(client_info['name'], sanctioned_lists),
        "pep_check": check_pep(client_info.get('pep', False)),
        "adverse_media": check_adverse_media(client_info['name'])
    }

    # 2. 交易监控
    monitoring = {
        "structuring_check": detect_structuring(transaction_data),
        "high_risk_region": check_high_risk_regions(client_info['regions']),
        "unusual_pattern": detect_unusual_patterns(transaction_data)
    }

    # 3. 风险评级（依赖前两步结果，避免在构造 dict 时引用尚未定义的变量）
    risk = calculate_aml_risk(screening, monitoring)

    return {
        "sanction_screening": screening,
        "transaction_monitoring": monitoring,
        "risk_assessment": risk
    }

def check_name_match(client_name: str, sanctioned_lists: list) -> dict:
    """制裁名单筛查"""
    for entity in sanctioned_lists:
        similarity = calculate_name_similarity(client_name, entity['name'])
        if similarity > 0.85:
            return {
                "match": True,
                "matched_entity": entity,
                "similarity": round(similarity, 3),
                "action": "人工复核" if similarity < 0.95 else "立即上报"
            }
    return {"match": False}
```

| 受益所有人识别 | 穿透至第一层法人 | 穿透至最终自然人 | 更新KYC表单与穿透路径模板 | 模板上线+存量项目回补 | 合规 |
| 执业质量评价 | 仅内部参考 | 与业务承接挂钩 | 立项前查询评价结果 | 立项表增加评价字段 | 合规 |
| 关键判断留痕 | 结论性表述 | 须载明判断依据 | 报告模板增加"判断依据"栏 | 模板更新+培训完成 | 质控 |
**示例 2｜新规落地追踪表（把“关注”变成“闭环”）**

| 新规要点 | 受影响业务 | 需修订的内部文件 | 责任人 | 完成时限 | 验收方式 |
|---------|-----------|----------------|-------|---------|---------|
| 受益所有人穿透至自然人 | KYC/并购/私募 | KYC表单、穿透路径模板 | 合规 | T+15日 | 抽查3个存量项目已回补 |
| 执业质量评价与承接挂钩 | IPO保荐/督导 | 立项表、立项审批流 | 合规 | T+20日 | 新立项100%含查询记录 |
| 关键判断须载明依据 | 尽调/内核/督导 | 尽调报告模板、内核意见模板 | 质控 | T+30日 | 模板上线+培训签到 |

闭环判定：三项条件同时满足才算落地——内部文件已修订、存量已完成回补、新增业务按新口径执行。只发通知不改文件不算闭环。

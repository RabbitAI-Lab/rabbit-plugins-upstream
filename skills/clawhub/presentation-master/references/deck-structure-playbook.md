# 演示结构手册（Deck Structure Playbook）

> 子技能 `presentation-creator` 讲"大纲构思、Slide 编写"，`presentation-delivery` 讲"叙事结构"，但没把**一页该写什么、全篇多少页、每页多少时间、钩子和 CTA 怎么落地**量化成决策框架。本篇给出按时长/受众/目标倒推结构的 SOP。

## 1. 用时长倒推页数

黄金密度：**1 页 ≈ 1–2 分钟**。先定总时长，再定页数：

| 总时长 | 建议页数 | 节奏 |
|--------|----------|------|
| 5 min (Lightning) | 5–7 页 | 快、只讲核心 |
| 15 min | 10–15 页 | 标准技术分享 |
| 30 min | 18–25 页 | 含 demo 与 QA 缓冲 |
| 45 min+ | 25–35 页 | 含分段休息/互动 |

> 反模式：30 分钟塞 60 页 → 每页 30 秒，观众记不住任何一点。宁少勿多。

## 2. 结构骨架（四段法）

```
[开场钩子] 1 页：痛点/反直觉事实/故事 → 抓住注意力
   ↓
[路线图]   1 页：今天讲什么、不讲什么 → 设预期
   ↓
[主体]     N 页：每页一个核心主张 + 证据（IMRaD 或 问题-方案-证据）
   ↓
[总结 CTA] 1–2 页：复述 3 个要点 + 明确行动号召
```

决策树（按目标选骨架侧重）：
```
目标 = 说服（融资/Pitch）？
 ├─ 是 → 加重 [问题-方案-市场] 比例，CTA 要具体（"本轮融 X，用于 Y"）
 └─ 否 → 目标 = 教育（技术分享）？
          ├─ 是 → 加重 [主体] 的"怎么做"，少煽情多代码/数据
          └─ 否 → 目标 = 汇报？
                   ├─ 是 → 加重 [结果-指标]，结论先行
                   └─ 否 → 通用四段法
```

## 3. 每页一条主张（One Idea Per Slide）

每页必须能用一句话概括"这页想让观众记住什么"。写不出这句话 → 这页在凑数，拆或删。

自检：给每页加一个"记忆锚点"字段（一句话）。若两页锚点重复 → 合并。

## 4. 开场钩子模板

- 反直觉事实：`"我们花了 80% 时间，优化了对结果影响 <5% 的路径。"`
- 痛点共鸣：`"你是不是也遇到过——改完上线，才发现测漏了那条边界？"`
- 故事：`"上个月，一个用户因为 X 损失了 Y……"`

钩子禁用：*"大家好，我是…，今天讲…"* 直接进主题。

## 5. 收尾 CTA 模板

| 场景 | CTA 示例 |
|------|----------|
| 融资 | "本轮融 500 万，用于扩充算法团队，12 个月内做到 X" |
| 技术分享 | "代码已开源在 X，欢迎提 Issue；下期讲 Y" |
| 内部汇报 | "建议 A：下周启动；需要 B 资源；owner 是 C" |

## 6. 可执行的预检命令

```bash
# 用本仓库脚本检查大纲结构（字数/标题层级/一致性）
python3 scripts/check_presentation.py outline --file deck.md

# 统计页数（按 separator --- 计）
grep -c '^---$' deck.md
```

## 7. 典型坑与规避

| 坑 | 表现 | 规避 |
|----|------|------|
| 页数超时长 | 讲不完、赶场 | 1 页≈1–2 分钟，先定时长 |
| 无钩子 | 前 30 秒观众走神 | 用反直觉/痛点/故事开场 |
| 一页多主张 | 观众抓不住重点 | 每页一句话记忆锚点 |
| 无路线图 | 观众不知道讲到哪 | 第 2 页明示范围与边界 |
| CTA 模糊 | 讲完无行动 | 结尾给具体、可执行的下一步 |
| 结论放最后 | 汇报被中途打断没重点 | 汇报类结论先行 |

## 8. 时长分配模板

| 段落 | 5 min | 15 min | 30 min |
|------|-------|--------|--------|
| 钩子 | 0.5 | 1 | 2 |
| 路线图 | 0.5 | 1 | 2 |
| 主体 | 3 | 10 | 20 |
| 总结 CTA | 0.5 | 2 | 3 |
| 缓冲/Q&A | 0.5 | 1 | 3 |

> 缓冲不可省：现场必有意料外中断（设备/提问）。30 分钟至少留 3 分钟缓冲。

## 9. 问答预案与备注

- **预设 5 问**：提前写"最可能被问的 5 个问题 + 回答"，尤其是弱点（局限/竞品）。
- **不会答的兜底**：`"好问题，我下来确认后回你"` 优于硬编。
- **备注页（speaker notes）**：每页写"这页要说的三句话 + 可能的追问"，别把正文抄进备注。
- **远程演示**：共享前清场（通知/私窗），准备离线备份（录屏/PDF），网络挂了能续。

## 10. 实战：15 分钟技术分享完整大纲

主题：*「用脚本把我们的设计评审从 2 天压到 2 小时」*

```
# 开场钩子（1 min）
"我们组每次设计评审要 2 天，其中 1.5 天在反复对齐格式。"
                                              ← 痛点钩子，反直觉

# 路线图（1 min）
"今天讲三件事：为什么慢、怎么用脚本卡格式、落地后省了多少。"

# 主体（10 min）
## 为什么慢（3 min）
- 每人格式不同，评审变校对
- 对比度靠眼感，返工高
## 我们的方案（4 min）
- 设计 Token 三层 + lint 脚本
- 评审四维评分卡
## 数据（3 min）
- 评审耗时 2天→2小时
- 返工率下降 60%

# 总结 CTA（2 min）
"脚本已开源在 X，欢迎提 Issue；下期讲 CI 接入。"

# 缓冲/Q&A（1 min）
```
每页一句话记忆锚点：钩子=痛点、方案=三层+脚本、CTA=开源。无两页同锚点。

## 11. 常见结构反模式（扩展）

| 反模式 | 后果 | 修正 |
|--------|------|------|
| 结论放最后 | 汇报被中途打断丢重点 | 汇报类结论先行 |
| 一页塞 5 要点 | 记不住 | 拆页或合并 |
| 钩子用自我介绍 | 前 30 秒流失 | 反直觉/痛点开场 |
| CTA 模糊 | 无行动 | 具体下一步 |
| 页数=时长×3 | 赶场 | 1 页≈1–2 分钟 |
| 只讲不做 demo | 可信度低 | 关键处放 live demo |
| 不练就讲 | 超时卡壳 | 至少通讲 1 遍计时 |
| 忽略缓冲 | 中断无预案 | 留 10–15% 缓冲 |

## 12. 远程与混合演示要点

- **共享前清场**：关通知/私窗，避免误曝。
- **离线备份**：准备录屏 mp4 与 PDF，网络挂了能续。
- **节奏留白**：远程易冷场，每页结尾抛一个问题维持互动。
- **字大一点**：远程观看距离远，正文字号比现场再大一号。
- **cue 卡**：把"下一页要说的三句话"放演讲者备注，不依赖记忆。

## 14. 结构模板与复用

把验证过的好结构沉淀成模板，下次直接套，省去每次重想骨架：

- **开场钩子库**：维护 3 类钩子各 2-3 条可复用句——反直觉（"我们 80% 时间优化了对结果影响 <5% 的路径"）、痛点（"改完上线才发现测漏了那条边界"）、故事（"上个月一个用户因为 X 损失了 Y"），按主题挑。
- **路线图模板**：固定"今天讲三件事：为什么慢、怎么做的、结果如何"，替换关键词即可，避免临场组织。
- **收尾 CTA 库**：按场景（融资/分享/汇报）各存 1 条 CTA，讲完直接套，不临时编。
- **时间盒模板**：把"时长分配模板"（见 `## 8`）存成表格，按总时长填页数与分钟数。

> 模板不是束缚创意，而是把"结构正确"变成默认项，让你把精力放在内容而非框架。熟手和新手的差別，往往不在创意而在结构是否一次到位。

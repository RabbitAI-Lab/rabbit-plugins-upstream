# AGENTS.md — 旅游攻略助手

## 启动流程

每次会话开始，按顺序读取：

1. **SKILL.md** — 能力边界、工作流、数据模型
2. **agent.md** — 身份定义、核心能力、表达风格
3. **soul.md** — 价值观、决策逻辑、说话方式
4. **assets/template.html** — 输出模板结构（了解 DATA 对象格式）

## 工作流执行

### Step 1: 需求澄清 (intake-clarify)

向用户确认以下信息：

| 字段 | 示例 | 必填 |
|------|------|------|
| 目的地 | 云南、日本、新疆 | ✅ |
| 出发地 | 深圳、北京、上海 | ✅ |
| 日期 | 2026-06-20 至 2026-06-30 | ✅ |
| 人数 | 3人 | ✅ |
| 预算区间 | 人均5000-8000 | ✅ |
| 偏好类型 | 城市/海滨/山野/亲子/混合 | 🟡 |
| 特殊需求 | 不吃辣、带老人、必须海景房 | 🟡 |

### Step 2: 目的地研究 (destination-research)

- 判断旅行类型（城市/自然/海滨/混合）
- 可行性检查：天气、节假日、预约要求、交通可达性

### Step 3: 多源检索比价 (search-orchestrator)

按优先级检索：

1. **大交通** — 携程/去哪儿/飞猪/12306 比价，锁定特价机票
2. **住宿** — 美团/携程/飞猪/Booking 比价，按性价比排序
3. **景点** — 官方预约渠道、门票价格、开放时间
4. **美食** — 大众点评+小红书交叉验证

### Step 4: POI 精选 (poi-curate)

按公式打分，筛选 Top N：

```
推荐指数 = (吸引力 × 0.4) + (便宜 × 0.3) + (便利 × 0.3)
```

### Step 5: 住宿推荐 (accommodation-pick)

- 推荐 2-3 个候选，按性价比排序
- 每个附：价格、评分、位置、推荐理由、预订链接

### Step 6: 行程优化 (itinerary-optimize)

- 按地理位置聚类，避免折返
- 单日移动距离 3-5km
- 每天 ≤ 2 个付费景点
- 预留弹性时间

### Step 7: 预算平衡 (budget-balance)

- 六大类：大交通、住宿、餐饮、门票、市内交通、备用
- 提供超支取舍建议

### Step 8: 报告渲染 (report-render)

- 填充 `assets/template.html` 中的 `DATA` 对象
- 另存为 `{destination}-{date}-行程书.html`
- 保存到 `workspace/output/` 或用户指定目录

## 输出文件命名

```
{目的地}-{出发日期}-行程书.html
{目的地}-{出发日期}-行程书-美化版.html  (如用户需要更精美版本)
```

示例：`云南滇南-2026-08-26-行程书.html`

## 质量检查清单

输出前确认：

- [ ] 所有价格标注来源和时效
- [ ] 未校验坐标标注 ⚠️
- [ ] 所有预订链接可点击
- [ ] 预算总计 = 各分项之和
- [ ] 日期连续无冲突
- [ ] 体力指数合理（1-5）

## 异常处理

| 场景 | 处理 |
|------|------|
| 用户预算过低 | 提示"这个预算建议缩短天数或降低住宿标准" |
| 目的地无直飞 | 提供中转方案，标注时间和价格差异 |
| 景点需预约但已约满 | 提供替代方案，标注预约难度 |
| 坐标无法获取 | 标注 ⚠️ 坐标待校验，建议现场导航确认 |

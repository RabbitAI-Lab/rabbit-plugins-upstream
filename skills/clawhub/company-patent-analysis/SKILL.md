# 企业专利分析 · PatentMax

输出一份**企业技术专利竞争分析报告**：这家企业在某个技术方向上有什么、竞争对手在做什么、技术格局怎么分、机会和风险在哪。异步生成，可导出 Word 文档直接交付。

数据来自 PatentMax 专利库，并可将论文、网页、新闻、标准、诉讼一并计入分析来源。

接口与控制台：**https://api.ip930.com**

**不需要 API Key 就能用。** 没设 `PATENTMAX_API_KEY` 时，脚本第一次运行会自动领取一份免费试用（累计 ¥40 额度、30 天有效，只开通本技能的功能），存在本机 `~/.patentmax/`，之后自动沿用。领取成功时 stderr 会打一行「[PatentMax] 已自动领取免费试用……」，**把这句话转告用户**。

试用用完、过期，或想用其他功能时，命令会返回带 `"free_trial": true` 的错误，`message` 里写着下一步怎么办（注册 PatentMax 再送 ¥50 体验额度），**原样转告用户，不要自己换写法重试**。用户设了 `PATENTMAX_API_KEY` 就一律用正式密钥，不会领试用。

## 核心原则

**必填只有两项：技术方向（`--subject`）和目标企业（`--company`）。** 报告分析的就是这家企业在这个方向上的专利，竞争对手由报告从专利数据里自动识别。两项缺任何一项都先问用户，别猜。

**目标企业要写专利上登记的全称。** 一般是「地名＋字号＋行业＋有限公司」，例如「宁德时代新能源科技股份有限公司」。简称或错一个字都可能找不到这家企业的专利。用户只给了简称时，先用专利检索按申请人查一下登记名，再提交。

**技术方向只写技术名称。** 写「钠离子电池」，不要写「宁德时代在钠离子电池方向的专利布局」——企业名和「专利布局」这类词混进去会让检索跑偏。

**这是付费任务，执行前必须报价并取得用户确认。** 命令必须显式加 `--yes` 才会执行。

**报告有质量分档，不能一律当结论交付。** `quality_status` 返回 `qualified_degraded` 或 `review_required` 时，说明来源覆盖或部分维度有短板，交付时必须说明限制。

**不出保证性结论。** 不写「该企业在此方向无专利布局」「不存在专利风险」这类表述——见「结论纪律」。

## 执行前检查

信息不足时先问，不要急着跑。问几个问题的成本，远低于跑一次没用的报告。

| 检查项 | 必须确认 |
| --- | --- |
| **目标企业**（必填） | 分析哪家企业。用专利上登记的全称，简称匹配不准 |
| **技术方向**（必填） | 分析它在哪个技术方向上的专利，只写技术名称 |
| 目标（可选） | 这份报告要支持什么决策——立项、并购尽调、竞品对标、还是应诉准备 |
| 地域（可选） | 关心哪些市场，会影响检索范围 |
| 时间范围（可选） | 全部历史还是近三年，新兴技术看近期、成熟技术要看全周期 |
| 来源（可选） | 除专利外，是否要算上论文、新闻、标准、诉讼 |
| 排除（可选） | 有没有不想让报告覆盖的方向 |

只有两项必填缺了才需要追问；可选项用户没提就用默认值，不要为了填表反复问。

## 背景素材（可选）

`--materials` / `--materials-file` 可以不填。用户主动给了背景资料（企业介绍、已知产品等）就带上，会记在任务里备查；没有就不用问，也不用编。

## 命令

```bash
# 最简：只给两项必填
python scripts/patentmax_competitive.py create \
  --subject "钠离子电池" \
  --company "宁德时代新能源科技股份有限公司" \
  --wait --yes

# 带上可选项
python scripts/patentmax_competitive.py create \
  --subject "钠离子电池" \
  --company "宁德时代新能源科技股份有限公司" \
  --objective "评估我方在钠离子电池正极材料方向立项的竞争环境与专利风险" \
  --markets "CN,US,EP" \
  --time-range "近五年" \
  --wait --yes

# 中途断了用 operation_id 继续查
python scripts/patentmax_competitive.py status --operation-id <operation_id>

# 下载 Word 报告
python scripts/patentmax_competitive.py download --report-id <report_id> --out 竞争分析报告.docx

# 不想跑了
python scripts/patentmax_competitive.py cancel --operation-id <operation_id>
```

**参数说明**

`--subject`（必填）技术方向，只写技术名称；`--company`（必填）目标企业，专利上登记的全称。缺了脚本会直接提示，不会提交、不会扣费。

`--materials`、`--materials-file`、`--objective`、`--markets` 都可不填。

`--sources` 默认 `patent,paper,web,news`，另可加 `standard`（标准）、`litigation`（诉讼）。做侵权风险或应诉准备时把 `litigation` 加上；做前沿技术判断时 `paper` 很重要，论文通常比专利早一两年。

`--time-range` 填 `all`、`近三年`、`2020-2025` 这类描述均可。

`--excluded` 填不想覆盖的方向，避免报告被无关分支稀释。

`--idempotency-key` 不填会按请求内容自动生成——**同样的输入重试不会重复建任务、重复扣费**。

## 等待期间

`--wait` 会轮询到出结果，间隔从 10 秒退到 60 秒，默认最多等 90 分钟。进度和阶段会实时打到 stderr，形如 `[35%] 正在检索竞争对手专利`，**把这些转述给用户**，让他知道任务在推进。

**超时不代表失败。** 任务还在服务端跑，**绝对不要重新提交**，用 `status --operation-id` 继续查。

## 读结果

拿到结果不要整段转述，挑出这几件事：

**格局怎么分。** 谁是主要玩家、各自占什么位置、技术路线是趋同还是分化。

**对方的动作意味着什么。** 近期申请集中在哪些方向、和公开产品是否对得上、有没有明显的卡位意图。

**我方的位置。** 空档在哪、哪些方向已经拥挤、绕不开的专利是哪几件。

**质量提示要说。** `quality_status` 不是 `qualified` 时，向用户说明是哪块数据不足、结论要打几分折扣。

**边界。** 见下。

## 结论纪律

**禁止输出保证性结论**，例如「该企业在此方向没有专利布局」「不存在专利风险」「我方方案不侵权」。

使用这类表述：

> 截至 [日期]，在 [数据库、地域、来源类型] 及所列检索范围内，未检索到该企业在 [方向] 上的公开专利申请。本结果不排除未公开申请（约 18 个月公开窗口）、名称未归一化的关联主体、数据库缺口或术语差异造成的漏检。

三条必须交代：

- **18 个月公开窗口** — 这期间的申请谁也查不到，对手最新的动作大概率不在数据里
- **申请人名称未做集团归一化** — 同一集团可能以中文名、英文名、子公司名分散，查跨国集团要分主体再合并，否则会严重低估对方专利量
- **侵权与效力判断需专业意见** — 本报告是技术与商业参考，涉及侵权、无效、许可的判断以各国专利局官方登记簿和代理人意见为准

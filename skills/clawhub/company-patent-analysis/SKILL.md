# 企业专利分析 · PatentMax

输出一份**企业技术专利竞争分析报告**：这家企业在某个技术方向上有什么、竞争对手在做什么、技术格局怎么分、机会和风险在哪。异步生成，可导出 Word 文档直接交付。

数据来自 PatentMax 专利库，并可将论文、网页、新闻、标准、诉讼一并计入分析来源。

使用问题、企业采购：访问 **ip930.com**，右下角「联系客服」。

**不需要 API Key 就能用。**

## 运行环境（必读，所有命令都适用）

部分 WorkBuddy 等环境的命令行不完整，`cat`、`ls`、`sleep`、`rm` 等可能找不到。为保证任何电脑都能跑通：

- 脚本路径一律写**绝对路径**：`$DIR/scripts/patentmax_competitive.py`（`$DIR` 是本技能所在目录），不要写 `cd ... && ...`（前一步失败会让后面整条静默不执行）
- `python` 找不到时依次试 `python3`、`py`；还找不到就用 WorkBuddy 自带的：先用 Glob 在 `~/.workbuddy/binaries/python/versions/` 下找到 `python.exe`，用它的完整路径。**下文所有 `python` 都按这条替换**
- 不要用 `cat` 读文件、不要用 `sleep` 等待：读文件用 Read 工具；等待由脚本自己完成
- 命令在**用户的工作目录**里运行，生成的 Word 会存到这个目录；也可以用 `--out-dir` 指定
- 命令超时设为 120 秒。脚本每条命令最多跑 30 秒就返回，不会卡住

## 核心原则

**必填只有两项：技术方向（`--subject`）和目标企业（`--company`）。** 报告分析的就是这家企业在这个方向上的专利，竞争对手由报告从专利数据里自动识别。两项缺任何一项都先问用户，别猜。

**目标企业要写专利上登记的全称。** 一般是「地名＋字号＋行业＋有限公司」，例如「宁德时代新能源科技股份有限公司」。简称或错一个字都可能找不到这家企业的专利。用户只给了简称时，先用专利检索按申请人查一下登记名，再提交。

**技术方向只写技术名称。** 写「钠离子电池」，不要写「宁德时代在钠离子电池方向的专利布局」——企业名和「专利布局」这类词混进去会让检索跑偏。

**这是付费任务，执行前必须报价并取得用户确认。** 命令必须显式加 `--yes` 才会执行。

**报告有质量分档，不能一律当结论交付。** `quality_status` 返回 `qualified_degraded` 或 `review_required` 时，说明来源覆盖或部分维度有短板，交付时必须说明限制。

**不出保证性结论。** 不写「该企业在此方向无专利布局」「不存在专利风险」这类表述——见「结论纪律」。

**不重新提交。** 报告要跑几十分钟，跑得久不代表失败。只要没有报错，就继续 `wait`。**重新提交是这个技能最常见、代价最大的错误**：输入写法一变就会新建任务、重复扣费，用户还要从头再等一遍，而原来那份其实还在正常生成。

## 执行前检查

信息不足时先问，不要急着跑。问几个问题的成本，远低于跑一次没用的报告。

| 检查项 | 必须确认 |
| --- | --- |
| **目标企业**（必填） | 分析哪家企业。用专利上登记的全称，简称匹配不准 |
| **技术方向**（必填） | 分析它在哪个技术方向上的专利，只写技术名称 |
| 目标（可选） | 这份报告要支持什么决策——立项、并购尽调、竞品对标、还是应诉准备 |
| 地域（可选） | 关心哪些市场，会影响检索范围 |
| 时间范围（可选） | 全部历史还是近三年，新兴技术看近期、成熟技术要看全周期 |
| 来源（可选） | 除专利外，是否要算上论文、新闻、标准、诉讼 |
| 排除（可选） | 有没有不想让报告覆盖的方向 |

只有两项必填缺了才需要追问；可选项用户没提就用默认值，不要为了填表反复问。

## 命令

```bash
# 最简：只给两项必填
python "$DIR/scripts/patentmax_competitive.py" create \
  --subject "钠离子电池" \
  --company "宁德时代新能源科技股份有限公司" \
  --yes

# 带上可选项
python "$DIR/scripts/patentmax_competitive.py" create \
  --subject "钠离子电池" \
  --company "宁德时代新能源科技股份有限公司" \
  --objective "评估我方在钠离子电池正极材料方向立项的竞争环境与专利风险" \
  --markets "CN,US,EP" \
  --time-range "近五年" \
  --yes

# 接着等：每次最多 30 秒，完成时自动下载 Word
python "$DIR/scripts/patentmax_competitive.py" wait --operation-id <operation_id>

# 重新下载 Word（wait 完成时已自动下载过）
python "$DIR/scripts/patentmax_competitive.py" download --report-id <report_id>

# 不想跑了
python "$DIR/scripts/patentmax_competitive.py" cancel --operation-id <operation_id>
```

**参数说明**

`--subject`（必填）技术方向，只写技术名称；`--company`（必填）目标企业，专利上登记的全称。缺了脚本会直接提示，不会提交、不会扣费。

`--materials`、`--materials-file`、`--objective`、`--markets` 都可不填。

`--sources` 默认 `patent,paper,web,news`，另可加 `standard`（标准）、`litigation`（诉讼）。做侵权风险或应诉准备时把 `litigation` 加上；做前沿技术判断时 `paper` 很重要，论文通常比专利早一两年。

`--time-range` 填 `all`、`近三年`、`2020-2025` 这类描述均可。

`--excluded` 填不想覆盖的方向，避免报告被无关分支稀释。

`--idempotency-key` 不填会按请求内容自动生成——**同样的输入重试不会重复建任务、重复扣费**。

## 等待并报告进度

`create` 约 15 秒后返回。返回退出码 10 时，**先发这一句**，再发输出里的进度：

```
企业专利竞争分析报告已开始生成，这类报告通常要几十分钟，进度会实时告诉你。
```

记下输出 JSON 里的 `operation_id`，后面都用它。不主动向用户展示任务编号，用户问起再给。然后运行：

```bash
python "$DIR/scripts/patentmax_competitive.py" wait --operation-id <operation_id>
```

每条 `wait` 最多 30 秒就返回。按退出码处理：

| 退出码 | 含义 | 怎么做 |
| --- | --- | --- |
| 10 | 还在生成 | 发送输出里的进度，**然后立即再运行一次 `wait`** |
| 0 | 完成了，Word 报告已自动下载 | 按「读结果」交付 |
| 1 | 出错 | 按「出错时」处理 |
| 2 | 输入有误，什么都没提交 | 按 `message` 补齐后再运行 |
| 3 | 同样的任务已经在跑 | 用输出里的 `operation_id` 运行 `wait`，**不要**换写法重新提交 |

### 进度怎么发（照原文，不改字）

把每条 `[进度] ……` / `[进度 X%] ……` 去掉方括号部分，按下表加图标后**原文发送**：

| 进度行 | 发送 |
| --- | --- |
| `[进度] 已开始生成……` | 🚀 已开始生成…… |
| `[进度] 排队中，已等待……` | 🕒 排队中，已等待…… |
| `[进度] 生成中，已用时……` | 📝 生成中，已用时…… |
| `[进度 X%] 某阶段，已用时……` | 📝 X% 某阶段，已用时…… |

例：`[进度 35%] 检索竞争对手专利，已用时 6分30秒` → 发送 `📝 35% 检索竞争对手专利，已用时 6分30秒`。

- **等待期间只发进度，不附加其它文字**；不改写进度文字，不自己估算剩余时间，不编造没出现的百分比
- **出结果之前不要结束回复。** 退出码为 10 时，发完进度立即再运行 `wait`
- 等了几十分钟还没完成 → **正常，继续 `wait`**。命令断了、对话重开了，也用同一个 `operation_id` 运行 `wait` 接着看，**不要重新 `create`**

## 读结果

退出码 0 时 Word 报告已经下载好，输出 JSON 的 `files` 里是完整路径。先发：

```
✅ 100% 企业专利竞争分析报告已生成，用时 <elapsed>
📄 报告：<files 里的报告路径>
```

`quality_status` 不是 `qualified` 时，紧接着把 `quality_hint` 讲给用户。没有 Word 时（有 `docx_note`）照实说。

再根据 `summary` 用几句话讲要点，讲结论时遵守下面的「结论纪律」（不下保证性结论，交代检索边界）：

| 字段 | 怎么讲 |
| --- | --- |
| `executive_summary` | 核心结论，用自己的话讲两三句，别整段念 |
| `recommendations` | 建议，挑最要紧的两三条讲 |
| `report_sections` | Word 报告里有哪几章，用户想细看时告诉他去哪章找 |

交付消息里可以再加一句可选的下一步（只挑最相关的一条，没有就不说，不调用工具）：例如「想看我们自己往哪个方向布局能避开对方，可以接着做技术路线与专利布局分析。」

最后一句固定是：

> 在 https://api.ip930.com 控制台可以查看所有任务和余额。

- **不要打开 Word 把正文贴进对话，也不要读「完整结果」JSON 全文**：用户直接打开 Word 看。贴进来既拖长对话，又白白消耗积分
- **以上是本轮最后的输出，发完就停**：之后不再调用工具、不补表格、不写总结和建议，等用户回复。在这之后再调工具，收尾信息会被埋掉，用户看不到

用户追问细节时，再按下面几条组织回答：

**格局怎么分。** 谁是主要玩家、各自占什么位置、技术路线是趋同还是分化。

**对方的动作意味着什么。** 近期申请集中在哪些方向、和公开产品是否对得上、有没有明显的卡位意图。

**我方的位置。** 空档在哪、哪些方向已经拥挤、绕不开的专利是哪几件。

**质量提示要说。** `quality_status` 不是 `qualified` 时，向用户说明是哪块数据不足、结论要打几分折扣。

**边界。** 见下。

## 出错时

脚本出错时输出 `{"error": true, "message": "……"}`，`message` 是写给用户看的中文说明，里面已经写明了下一步怎么办。

- **原样转述 `message`，不猜原因、不补充建议、不自己换写法重试**
- 退出码 2（输入有误：少必填项、文件读不了、方案太短）：什么都没提交、没扣费，按 `message` 补齐后再运行
- 第一次运行时输出里有「[PatentMax] 已自动领取免费试用……」：把这句话原样转告用户一次
- 出现 `"free_trial": true`：免费试用用完、过期或想用其他功能，`message` 里写着怎么办（注册 PatentMax 再送 ¥50 体验额度），原样转告
- 任务失败或取消时，预扣的费用会**全额退回**，告诉用户这一点

## 结论纪律

**禁止输出保证性结论**，例如「该企业在此方向没有专利布局」「不存在专利风险」「我方方案不侵权」。

使用这类表述：

> 截至 [日期]，在 [数据库、地域、来源类型] 及所列检索范围内，未检索到该企业在 [方向] 上的公开专利申请。本结果不排除未公开申请（约 18 个月公开窗口）、名称未归一化的关联主体、数据库缺口或术语差异造成的漏检。

三条必须交代：

- **18 个月公开窗口** — 这期间的申请谁也查不到，对手最新的动作大概率不在数据里
- **申请人名称未做集团归一化** — 同一集团可能以中文名、英文名、子公司名分散，查跨国集团要分主体再合并，否则会严重低估对方专利量
- **侵权与效力判断需专业意见** — 本报告是技术与商业参考，涉及侵权、无效、许可的判断以各国专利局官方登记簿和代理人意见为准

# 跨领域知识矩阵

## 各领域核心能力点

### 技术工程
- **编程开发**：全栈开发、前后端架构、API 设计、数据库建模
- **系统架构**：微服务、分布式系统、高并发设计、容灾方案
- **DevOps**：CI/CD 流水线、容器化部署、监控告警、自动化运维
- **技术选型**：框架对比、性能评估、成本分析、团队能力匹配

### 商业策略
- **产品规划**：需求分析、MVP 设计、产品路线图、用户画像
- **增长营销**：获客渠道、转化漏斗、留存策略、增长实验
- **商业模式**：盈利模式设计、定价策略、单位经济模型
- **竞品分析**：竞争格局、差异化定位、护城河构建

### 内容创作
- **文案写作**：广告文案、产品描述、品牌叙事、SEO 内容
- **视频脚本**：短视频脚本、分镜设计、叙事结构、爆款公式
- **创意策划**：活动策划、事件营销、互动设计、传播策略
- **视觉表达**：设计规范、视觉语言、信息层级、用户体验

### 数据分析
- **统计建模**：描述性统计、推断性统计、预测模型、A/B 测试
- **数据可视化**：图表选型、仪表盘设计、数据故事化、交互式分析
- **洞察提炼**：数据解读、业务归因、趋势预判、决策建议
- **数据处理**：数据清洗、特征工程、ETL 流程、数据质量管控

### 运营管理
- **项目流程**：项目规划、里程碑管理、风险管理、复盘机制
- **组织效率**：团队协作、流程优化、资源调配、绩效管理
- **运营策略**：用户运营、内容运营、活动运营、社区运营
- **资源配置**：预算管理、人力分配、工具选型、优先级排序

## 跨域整合策略

### 策略 1：问题域映射
将一个跨域问题拆解为多个单域子问题，分别诊断后再整合：
```
跨域问题 → [技术子问题] + [商业子问题] + [运营子问题]
         → 各域独立分析
         → 整合视角：识别域间依赖和冲突
         → 综合方案
```

### 策略 2：视角轮换
对同一问题依次用不同领域视角审视，发现盲区：
1. 先用**技术视角**看可行性和实现路径
2. 再用**商业视角**看价值和投入产出比
3. 再用**用户视角**看体验和需求匹配度
4. 最后用**运营视角**看可持续性和执行效率

### 策略 3：约束优化
当多域目标冲突时，将冲突显式化并寻找帕累托最优：
- 列出所有域的关键约束条件
- 标注哪些约束是硬性的（不可妥协），哪些是软性的（可调整）
- 在硬约束边界内，优化软约束的组合

## 典型跨域问题模式

| 模式 | 涉及领域 | 整合要点 |
|------|---------|---------|
| 产品从0到1 | 技术+商业+设计+运营 | 技术可行性约束商业目标，设计驱动用户体验，运营决定落地节奏 |
| 数据驱动决策 | 数据+商业+运营 | 数据洞察指导商业方向，运营执行验证数据假设 |
| 内容工业化生产 | 内容+技术+运营 | 技术工具提升内容产能，运营策略决定内容分发，数据反馈优化创作 |
| 数字化转型 | 技术+商业+运营+法务 | 技术重构业务流程，商业模型需要适配，合规约束不可越过 |

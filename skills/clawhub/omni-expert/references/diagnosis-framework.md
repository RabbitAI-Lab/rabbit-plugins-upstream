# 全域问题诊断框架

## 领域判断矩阵

面对任何问题，首先判断其所属领域和任务类型：

| 领域 | 典型关键词 | 常见任务类型 |
|------|-----------|-------------|
| 技术工程 | 代码、架构、部署、Bug、API、数据库 | 分析、执行、创作 |
| 商业策略 | 产品、增长、营销、商业模式、竞品 | 分析、决策 |
| 内容创作 | 文案、脚本、创意、设计、视频 | 创作、执行 |
| 数据分析 | 数据、报表、统计、可视化、洞察 | 分析、执行 |
| 运营管理 | 流程、效率、项目、组织、资源 | 分析、决策、执行 |
| 金融投资 | 估值、财报、投资、风控、量化 | 分析、决策 |
| 法务合规 | 合同、合规、隐私、知识产权 | 分析、决策 |
| 设计规划 | UI/UX、原型、交互、视觉 | 创作、执行 |

## 矛盾识别方法

### 三层矛盾分析法

1. **表层矛盾**：用户直接描述的问题现象
   - 问：问题表现是什么？何时发生？影响范围多大？
   
2. **中层矛盾**：导致表层现象的结构性原因
   - 问：什么流程/架构/策略设计导致了这个现象？是否存在资源错配或信息断层？

3. **根因矛盾**：中层矛盾的底层驱动因素
   - 问：为什么这个结构会存在？是历史决策、认知偏差、资源约束还是外部环境变化造成的？

### 诊断输出模板

```
【问题现象】一句话描述表层矛盾
【影响评估】量化或定性描述影响范围和严重程度
【根因分析】三层递进分析
  - 表层：...
  - 中层：...
  - 根因：...
【解决方向】针对根因的 2-3 个可行方向
【推荐方案】最优方向 + 理由 + 执行步骤
```

## 跨域问题识别信号

当出现以下信号时，问题可能跨多个领域，需要整合视角：

- 问题描述中同时包含 ≥2 个领域关键词
- 解决方案需要同时改动技术系统和业务流程
- 用户提到"从X到Y"的端到端需求
- 问题根源涉及人、流程、技术三者交互
- 需要平衡相互冲突的目标（如速度 vs 质量、成本 vs 效果）

# 筛选规则结构与条件维度

## 规则组结构

规则组支持多组并行运行：

```
规则组（多组并行）
├── 规则组名称：如"海上工程总包"
├── 启用状态：启用/停用
├── 匹配逻辑：AND（全部满足）/ OR（任一满足）
├── 筛选条件（见下表）
├── 输出设置：推送通道 + 输出格式
└── 优先级：1-10（同一条标讯匹配多规则时，按优先级去重）
```

## 资质判定优先级（高 → 低）

1. **★服务类型门禁**（v1.2）：采购标的的服务类型优先于项目名里的动词
2. **★子串红警**（v1.2）：不受 CJK 边界限制的强制拦截词
3. **special_rules 覆盖**：如"某类标外找资质可投"、"某类标垫资不参与 → skip"
4. **红色预警命中** → 不可投 + 原因
5. **主体能力匹配** → 可投（按主体能力词归属投标公司）
6. **都不命中** → 需确认

## ★v1.2 修正（2026-09-11，案例 614535）

### 一、服务类型门禁 service_type_gate

**采购标的的服务类型，优先于项目名里的动词关键词。**

项目名常把真正的服务类型藏在修饰语后面：

| 项目名 | 真正的标的 | 错误判定 | 正确判定 |
|---|---|---|---|
| 楼宇安全整治**维修改造**项目**监理服务** | 监理服务 | 按"维修"命中→可投 | **不可投**（无监理资质） |
| XX项目**设计服务** | 设计服务 | 按"施工/改造"命中 | 需确认 |

配置项 `service_type_gate.blocked_types`：监理（不可投）／设计·勘察／检测／审计·评估·造价咨询·招标代理（需确认）。
**资质序列不可跨用**：施工总承包资质 ≠ 监理资质；且施工单位投同一项目监理通常有**回避要求**。

### 二、匹配边界陷阱（重要）

`smart_match` 的左边界规则要求**关键词前一字符不得为中日韩字符**，导致出现在标题**中部**的关键词永远匹配不到：

- ❌ "…零星**维修**服务" → "维修"前是"星"→ 漏判（该投的标被判"需确认"）
- ❌ "…消防设施改造" → "消防"前是"厂"→ 红警漏拦

**修正**：
1. `_match_loose: true` → 能力词改用**纯子串匹配**（漏判代价 > 误判代价，假阳性由 `_exclude_contexts` 过滤）
2. `substring_alerts` → 高风险资质词（消防/电梯/压力容器/特种设备/爆破/危险品/劳务派遣/保安服务/测绘/勘察/钻井/修井等）强制子串拦截
3. 已知保留项：`skip_procurement` 的"采购"**仍用严格匹配**——因"XX服务采购"是服务标常见命名，宽松会误杀大量可投标；若要拦物资采购标，请改用"物资采购/采购项目/采办"等更特异的关键词

### 三、自检命令

```bash
python3 qual_check.py --validate-rules qual_rules.json   # 规则库体检
```

判定回归用例（改规则后必跑）：监理标→不可投、消防标→不可投、设计标→需确认、零星维修标→可投。

## 筛选条件维度

| 维度 | 条件类型 | 运算符 | 输入示例 |
|---|---|---|---|
| 关键词 | 标题包含 | 包含任意/全部包含/不包含 | `FPSO OR "浮式生产" NOT "退役"` |
| 关键词 | 正文包含 | 同上 | `"一级资质" AND "安全生产许可证"` |
| 关键词 | 附件名称包含 | 包含任意 | `技术规格书 OR 图纸` |
| 地区 | 项目所在地 | 省/市多选、排除、半径圈选 | `天津市, 青岛市, 半径50km` |
| 地区 | 采购单位所在地 | 同上 | `北京市海淀区` |
| 金额 | 预算金额 | ≥ / ≤ / 区间 / 未填写 | `500万-5000万` |
| 金额 | 最高限价 | 同上 | `≥1亿` |
| 时间 | 公告发布时间 | 近N天 / 日期范围 | `近7天` |
| 时间 | 投标截止时间 | ≥N天后 / 日期范围 | `截止≥7天后` |
| 时间 | 开标时间 | 同上 | `2024-03-01 至 2024-06-30` |
| 项目属性 | 项目类型 | 多选 | `工程, 货物` |
| 项目属性 | 采购方式 | 多选 | `公开招标, 邀请招标` |
| 项目属性 | 行业领域 | 多选 | `石油化工, 海洋工程` |
| 资质要求 | 要求资质 | 包含/不包含 | `海洋石油工程专业承包一级` |
| 资质要求 | 资质等级 | ≥ / = / ≤ | `≥二级` |
| 业主画像 | 采购单位 | 白名单/黑名单 | `包含: 某某分公司` |
| 业主画像 | 历史合作 | 是否合作过 | `仅显示合作过业主` |

## 规则冲突处理

当一条标讯同时匹配多个规则组时：

1. **分别输出**（默认）：用户收到多条推送，标注所属规则组
2. **仅保留高优先级**：配置去重模式
3. **合并为一条**：标注"多规则匹配"

## qual_rules.json 结构说明

```json
{
  "version": "1.0",
  "entities": {
    "entity_a": {
      "name": "主体A名称",
      "capabilities": ["关键词1", "关键词2"],
      "note": "替换为营业执照经营范围关键词"
    }
  },
  "red_alerts": ["车辆维修", "劳务派遣", "..."],
  "special_rules": [
    {
      "id": "rule_id",
      "description": "规则描述",
      "match_keywords": ["关键词"],
      "action": "skip|investable|not_investable",
      "assigned_entity": "entity_a",
      "reason": "原因说明"
    }
  ],
  "skip_keywords_result": ["结果公示", "中标公示"],
  "region_priority": {
    "high": ["天津", "青岛"],
    "note": "按需填写重点地区"
  }
}
```

## 推送策略

| 策略 | 说明 | 配置 |
|---|---|---|
| 即时推送 | 单条标讯匹配后立即推送 | 仅高优先级规则组/紧急标讯 |
| 定时汇总 | 按固定时间合并推送 | 每日9:00 / 每周一9:00 |
| 智能合并 | 同规则组多条标讯合并为一条消息 | 阈值：5条或间隔30分钟 |
| 免打扰时段 | 指定时间不推送 | 默认22:00-08:00 |
| 去重窗口 | 同一标讯N天内不重复推送 | 默认30天 |

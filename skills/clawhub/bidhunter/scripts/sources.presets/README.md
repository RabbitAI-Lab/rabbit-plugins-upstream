# 采集源配置指引

> **为什么本 skill 不内置任何真实平台源？**
>
> 内置源一旦失效（改版 / 加鉴权 / 关停），用户首跑直接失败，反而比没有更糟。
> 所以 BidHunter 的做法是：**给模板 + 给清单，不给现成答案**——你把要盯的平台填进来，
> 它就是你自己的监控器，不依赖我们维护。

---

## 三步接入

1. **选模式**：`json_api.json` / `rss.json` / `html_list.json`，按目标平台挑一个
2. **改 URL 和字段**：把模板里的 `YOUR-DOMAIN` 换成真实域名，按返回结构改 `items_path` / `fields`
3. **合并进 `sources.json`**：把改好的对象放进 `sources` 数组（可以放多个平台）

`init` 已经帮你在 `scripts/sources.json` 生成了骨架，直接往 `sources` 数组里加即可
（`bid_monitor.sh` 会自动加载 `scripts/sources.json`）。

---

## 常见平台清单（自行确认当前网址与可用性）

> 下列仅为**品类提示**，具体网址与接口请以平台当前实际情况为准，本 skill 不保证其可用性。

| 品类 | 说明 |
|---|---|
| 中国政府采购网 | 中央及地方政采公告，通常有列表页，部分地区提供 RSS |
| 全国公共资源交易平台 | 各省有独立子站，按你所在省找对应入口 |
| 省级 / 市级公共资源交易中心 | 工程、采购、土地矿权分类，多数有 HTML 列表页 |
| 央企电子采购平台 | 能源、通信、建筑类央企各有自建平台，需自行注册查看公开公告区 |
| 行业性招标平台 | 如机电产品、医疗器械等垂类平台 |

**找源的小技巧**：打开平台列表页 → F12 → Network → 翻一页 → 看哪个请求返回了公告数据。
那个请求的 URL 就是你要的 `url`，返回的 JSON 结构就是 `items_path` / `fields` 的依据。

---

## 合规提醒（重要）

- 采集前确认目标站点的 `robots.txt` 与内容版权声明
- 只采集**公开可访问**的页面，不要尝试绕过登录或鉴权
- 控制请求频率，避免对目标站点造成压力
- 采集内容仅供内部商机研判，二次传播前请自行评估版权风险

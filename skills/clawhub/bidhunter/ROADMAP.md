## v1.1 精准补丁（已发布）

### 痛点
中文子串误匹配（如"电气"误匹配"电气石"）、缺测试工具

### 已完成
- **smart_match() 边界感知匹配**（`scripts/qual_check.py`）
  - 解决 Python 3.13 `\w` 匹配 CJK 字符问题
  - 左边界：CJK前缀阻断（"新电气"不匹配"电气"）
  - 右边界：1字CJK后缀阻断（"电气石"）；≥2字放行（"电气设备"）
- **`--validate-rules`** 规则库健康检查（空能力词、重复关键词、红警冲突）
- **`--summary`** 精华版报告（Top 5可投摘要）
- **`--dry-run`** pipeline预览模式
- **`status.py`** 状态工具（采集状态/7天趋势/规则摘要）
- **`_exclude_contexts`** 子串误报防护（电气石/广告位/视频监控等）

### 关键指标
- 标讯匹配准确率：70%（基线）

## v1.2 体验优化（2周）✅ 已发布 2026-08-17

### 痛点
用户不会配企业微信机器人，推送失败无处查

### 推送通道优先级（涛哥 2026-08-10 决策）
1. **🥇 钉钉** — 国央企招投标客户主流
2. **🥈 企业微信** — 私企主流
3. **📧 邮件** — 兜底通道（推送失败告警用）
4. **⏸ 飞书** — 推迟到 v1.5（按需实现）

### v1.2 交付物（实际落地）
- **`scripts/push_manager.py`** — 多通道推送管理器
  - 钉钉（加签 webhook）/ 企微（群机器人）/ 邮件（SMTP）三通道
  - 主通道失败自动切备用通道；指数退避重试 3 次（1s/5s/30s）
  - 幂等保护：同日同题已成功则不重复推送
  - SQLite 历史库（`push_history.db`，WAL 模式，30 天滚动清理）
  - CLI：`test` / `send` / `send-file` / `history` / `stats` / `health-check` / `retry-failed`
- **`scripts/config_wizard.py`** — 交互式配置向导
  - 选通道 → 填 webhook/密钥 → 连通性测试 → 写入 `~/.config/bidhunter/push.json`（权限 600）
  - 未通过连通性测试不允许写入；支持 `--show` / `--reset`
- **`pipeline.sh`** — 接入推送；新增 `--no-push`；未配置推送时静默跳过（向后兼容）
- **`status.py`** — 新增 `--push-stats` 子命令；主输出末尾加推送状态段
- **飞书**：按决策推迟到 v1.5

### 测试情况
- 本地 HTTP mock 验证钉钉加签 payload、企微消息格式、幂等跳过、失败兜底切换、SQLite 历史、健康检查告警逻辑（6/6 通过）
- 真实 Webhook 验证：**待涛哥配置后首次 `config_wizard.py` 实推验证**（规划要求 8-18 前跑通，本次开发期提前完成）

### 功能规划

| 功能 | 说明 | 技术要点 |
|---|---|---|
| 推送通道配置向导 | 交互式配**钉钉/企微/邮件** | 扫码绑定，自动验证 |
| 推送历史记录 | 查看最近30天推送，重发失败消息 | 本地SQLite存储 |
| 推送失败告警 | 连续3天推送失败主动通知管理员 | 备用通道兜底 |
| 多通道并行 | 同一标讯同时推企微+邮件 | 通道优先级配置 |
| 定时任务可视化 | 查看下次执行时间，手动触发按钮 | cron表达式解析 |

### 关键交付
```

├── push_manager.py     # 新增：通道配置、测试、历史
├── push_history.db     # 新增：SQLite本地存储

```

2. **config_wizard.py**（用户体验入口）

## v2.0 产品化（2个月）

### 痛点
30个用户各自为政，无法共享规则，你维护30份配置

### 功能规划

| 功能 | 说明 | 技术要点 |
|---|---|---|
| 多租户架构 | 企业注册，成员邀请，数据隔离 | tenant_id贯穿全链路 |
| 三级权限 | 管理员/规则编辑员/普通查看员 | RBAC权限模型 |
| 云端规则库 | 企业级规则统一配置，成员共享 | 加密存储，版本控制 |
| 团队看板 | 成员跟进状态、协作标注 | 实时同步 |
| 私有化部署包 | Docker Compose一键部署 | 企业内网运行 |

### 架构升级
| 单机版（v1.x） | → | SaaS版（v2.0） |
|---|---|---|
| 本地JSON配置 | → | PostgreSQL + 租户隔离 |
| 本地文件存储 | → | 对象存储（OSS/S3/MinIO） |
| crontab定时 | → | APScheduler + 分布式队列 |
| 个人IM推送 | → | 企业应用号统一推送 |
| 无认证 | → | JWT + OAuth2登录 |

### 关键交付

├── web/         # 管理后台

## v2.5 智能增强（1个月）

### 痛点
用户看到标识后，还要人工读招标文件、写技术方案

### 功能规划

| 功能 | 说明 | 技术要点 |
|---|---|---|
| 招标文件AI速读 | 上传PDF/Word，提取关键条款 | LLM + 文档解析 |
| 资质门槛自检 | 对比招标文件vs企业资质，标红缺口 | 结构化抽取 |
| 评分标准解析 | 价格/技术/商务权重，得分点清单 | 表格识别 |
| 投标建议生成 | 基于历史中标数据，输出策略建议 | RAG检索增强 |
| 竞品报价推测 | 分析对手历史报价区间 | 数据聚合+统计模型 |

### AI能力边界（合规）
- ✅ **做**：信息提取、格式整理、风险提示
- ❌ **不做**：自动填写报价、伪造资质、代写技术方案
- ⚠️ **明确标注**：AI建议仅供参考，最终决策人工确认

### 关键交付
```
scripts/
├── ai/
│   ├── doc_parser.py        # PDF/Word解析
│   ├── clause_extractor.py  # 条款结构化抽取
│   ├── bid_advisor.py       # 投标建议生成
│   └── risk_scanner.py      # 风险点识别
└── models/  # 本地轻量模型或API调用
```

### 关键指标
- 标讯匹配准确率：90%+
- 单用户日均耗时：5min
- NPS评分：70

## 风险与规避

| 风险 | 影响 | 规避策略 |
|---|---|---|
| 平台反爬升级 | 采集失效 | 多源互补，优先官方API，合规申请 |
| 数据合规争议 | 法律风险 | 仅采集公开信息，用户授权，审计日志 |
| AI建议失误 | 投标损失 | 明确免责声明，人工确认环节不可跳过 |
| 竞品抄袭 | 差异化丧失 | 社区生态+数据网络效应构建壁垒 |
| 维护成本爆炸 | 团队不堪重负 | 自动化运维，用户自助，付费分级 |

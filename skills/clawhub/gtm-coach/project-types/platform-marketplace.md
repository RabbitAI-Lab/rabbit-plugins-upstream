# Project SOP — Platform / marketplace

## Value and proof

- **Promise:** two roles complete a valuable interaction or transaction with less search, risk, or friction.
- **Activation:** one narrowly defined match/transaction succeeds—not merely two signups.
- **Evidence ladder:** side-A pain + side-B pain → manual introduction → accepted match → completed transaction/outcome → repeat/liquidity.
- **Primary CTA:** join the constrained side or request/offer one specific transaction.

## Stage priorities

1. Pick one geography/category/use case and identify the constrained side.
2. Recruit supply or demand manually; avoid opening an empty broad marketplace.
3. Concierge the first 5–10 matches and observe rejection, trust, timing, and workflow.
4. Build only the steps that remove repeated transaction friction.
5. Expand a segment only after match quality, completion, and repeat behavior are credible.

## Useful metrics

Qualified supply/demand → match offered → accepted → completed → time-to-match → fill rate → repeat transaction → take-rate/revenue. Registrations and listings without transactions are vanity.

## Common traps

- Marketing both sides equally when one side is the constraint.
- National/category-wide launch before local liquidity.
- Counting introductions as successful transactions.
- Automating matching before learning why humans accept or reject.

## Coach must ask

“Which side is constrained in the narrowest viable market, and how many matches completed the promised outcome?”

# Project SOP — Micro SaaS / app

## Value and proof

- **Promise:** one named user completes one painful job faster, cheaper, or more reliably.
- **Activation:** the smallest in-product event that delivers that promise; define the event precisely.
- **Evidence ladder:** pain story → observed demo/use → activation → return → payment → retained payment/referral.
- **Primary CTA:** try the core job or book a founder demo—not “learn more.”

## Stage priorities

1. **Validate:** interview 3–5 target users about the last incident and current workaround. Offer a manual solution or paid pilot.
2. **Build:** ship only the path to activation. Observe one user without explaining every click.
3. **Cold start:** founder-led demos/outreach or one dense problem community. Recruit users manually.
4. **Promote:** repeat the channel that creates activated users; fix onboarding before buying more traffic.
5. **Scale gate:** several similar users activate, pay, and retain before recurring ad spend.

## Useful metrics

Qualified conversations → demos started → activation rate/time-to-value → week-1 return → paid conversion → retained revenue. Traffic and signups without activation are diagnostic only.

## Common traps

- Shipping features instead of fixing activation.
- Product Hunt before another person can receive value.
- Calling waitlist size product validation.
- Optimizing acquisition while activated users do not return.

## Coach must ask

“What exact event proves a new user received the promised value, and how many target users completed it this week?”

NicheReach `leads_pending` / `replies_posted_7d` are the **founder’s** instrument stats. They count as customer activation only if those users are the ICP completing that event. Dogfooding this product is outreach practice, not proof that customers activated.

# 猜想证明技能 — 任务要求清单

> 第二层：每种任务类型的零件清单


---

## D0 任务域协调域

### D0-01 猜想类型识别
- **必选组件**: 用户猜想原文、形式化重述、猜想分类结果（解析数论/代数/组合/几何等）
- **可选组件**: 猜想历史、等价陈述枚举
- **组装顺序**: 接收猜想 → 解析陈述 → 分类判定 → 输出分类报告
- **约束**: 分类基于客观数学特征；几何直觉优先于传统领域分类
- **格式**: 分类报告（Markdown）

### D0-02 执行路径选择
- **必选组件**: 猜想分类、难度评估、执行路径方案（归约型/构建型/排他型）
- **可选组件**: 多条候选路径对比
- **组装顺序**: 分类确认 → 难度评估 → 路径方案设计
- **约束**: 归约型优先（将猜想压缩为更简单等价问题）；构建型次之；排他型（证伪候选路线）最后
- **格式**: 路径选择报告

### D0-03 结果整合
- **必选组件**: 各域输出汇总、状态表（✅已验证/✅已证/🔴待证）
- **组装顺序**: 结果收集 → 状态分类 → 整合报告
- **约束**: 已证/已验证/待证三层严格区分
- **格式**: 整合报告 + 状态表

### D0-04 深化路由
- **必选组件**: 论证缺口分析、深化方向、路由方案
- **组装顺序**: 缺口识别 → 方向判定 → 路由设计
- **约束**: 路由基于缺口类型（数值不足→D3深化，逻辑缺口→D2深化，等价转化→D2-04）
- **格式**: 深化路由报告

## D1 猜想拆解域

### D1-01 猜想陈述解析
- **必选组件**: 猜想原文、形式化重述、关键符号定义、边界条件
- **可选组件**: 猜想历史、等价陈述
- **组装顺序**: 原文确认 → 形式化 → 符号定义 → 边界标注
- **约束**: 形式化无损原意；使用通俗语言建立直觉模型（桥、碗、平面）
- **格式**: 形式化陈述文档

### D1-02 原子概念拆解
- **必选组件**: 原子概念表（#、概念名、通俗解释 + 数学定义）、依赖关系链、维度分析（一维/二维）
- **可选组件**: 前置知识列表、通俗类比集合
- **组装顺序**: 分解 → 逐个定义 → 依赖标注 → 维度标注 → 链确认
- **约束**: 每个概念不可再分；标注维度不对称（如素数一维 vs 零点二维）
- **格式**: 原子概念表（Markdown 表格）

### D1-03 断层识别
- **必选组件**: 已知结果列表、未知部分列表、核心瓶颈（≤5个）、**桥接断层检查**、**引用有效性审查**
- **可选组件**: 瓶颈优先级、已知尝试
- **组装顺序**: 已知枚举 → 未知定位 → 瓶颈提炼 → 桥接审查 → 引用审查 → 优先级排序
- **约束**: 断层必须可被数学命题精确描述；逐节点审查证明链每一步依赖的外部定理
- **桥接断层常见模式**:
  1. **定理误用**: 将仅对多项式成立的定理套用于整函数
  2. **缺失引理**: 声称的推论缺少中间步骤
  3. **假设滑移**: 隐含使用比声称更强的条件
  4. **近/远分类遗漏**: 未区分「自动成立」和「需控制」的项
- **格式**: 断层分析表（Markdown 表格）

### D1-04 工具评估
- **必选组件**: 可用定理列表、缺失工具列表、**计算机辅助验证可行性**、**数值校准策略**

### D2-02 引理设计
- **必选组件**: 引理陈述、严格证明、依赖关系、**数值验证（区分于解析证明）**
- **可选组件**: 多个候选引理方案对比
- **组装顺序**: 陈述设计 → 证明构造 → 数值验证 → 依赖标注
- **约束**: 每个引理可独立验证；标注为「解析已证」或「数值已验证」
- **格式**: 引理链文档

### D2-03 管线编排
- **必选组件**: 引理依赖DAG、执行顺序、并行/串行标注、**校准回路标注**
- **可选组件**: 关键路径分析
- **组装顺序**: 依赖分析 → 顺序确定 → 校准回路设计
- **约束**: 尊重自然依赖关系；D2⇄D3 迭代回路在管线中明确标注
- **格式**: 管线图

### D2-04 等价转化
- **必选组件**: 原猜想陈述、等价问题陈述、等价性证明、可攻击性评估
- **可选组件**: 多等价问题对比
- **组装顺序**: 原猜想分析 → 候选等价物搜索 → 等价性证明 → 评估
- **典型模式**: RH⇄|ξ|²单调性（几何转化）；原问题→不等式（归约转化）
- **格式**: 等价转化报告

### D2-05 桥接构造
- **必选组件**: 桥接定理、攻击向量矩阵、路线可行性评估、**近/远分类**
- **可选组件**: 多路线对比
- **组装顺序**: 定理陈述 → 攻击向量生成 → 路线评估 → 近/远项分类
- **约束**: 桥接必须严格；**当存在「自动成立」和「需控制」两类项时，必须明确区分**
- **新增模式**:
  - **近/远分类**: 将求和项按与考察点的距离分为远项（自动同号✅）和近项（需控制🔴）
  - **票力对决**: 通过不等式判定总和的符号
- **格式**: 桥接文档

### D2-06 死路排除
- **必选组件**: 路径描述、失败原因分析（严格证伪）、死路分类
- **可选组件**: 替代路径建议
- **组装顺序**: 路径执行 → 失败点识别 → 严格证伪 → 原因分类
- **约束**: 死路结论必须严格证明，不得仅凭「尝试失败」下结论
- **格式**: 死路排除报告

### D2-07 归约
- **必选组件**: 原问题陈述、归约后问题陈述、等价性证明、归约深度评估
- **可选组件**: 多级归约链
- **组装顺序**: 原问题 → 第一级归约 → ... → 最终不等式/最小形态
- **典型模式**: RH → |ξ|²单调性 → 导数求和公式 → 近零点不等式
- **格式**: 归约报告

### D2-08 数值校准
- **必选组件**: 数值验证策略、测试网格设计、结果汇总、**方向校准结论**
- **可选组件**: 可视化图表
- **组装顺序**: 策略设计 → 网格定义 → 执行扫描 → 校准结论
- **核心原则**: 数值证据不是证明，但用于校准方向——若数值违反，路线错误；若数值通过，路线可能正确
- **案例数据**: 1225点全通过 → 确认单调性方向正确 → 转向解析证明
- **格式**: 校准报告

### D2-09 证明验证
- **必选组件**: 全链路逐节点检查、通过/未通过标注、**状态三层分类**
- **可选组件**: 自动化验证脚本
- **组装顺序**: 逐节点遍历 → 条件检查 → 三层标注
- **约束**: 必须全链路覆盖；已证/已验证/待证三层标注
- **格式**: 验证报告 + 状态表

## D3 严格化与验证域

### D3-01 解析界推导
- **必选组件**: 每个常数的有理数上下界、推导过程
- **组装顺序**: 常数识别 → 上下界推算 → 推导记录
- **约束**: 必须可独立复现
- **格式**: 解析界报告

### D3-02 数值扫描
- **必选组件**: 扫描范围、步长、结果汇总、**违反统计**
- **可选组件**: 可视化（SVG）
- **组装顺序**: 范围确定 → 步长设定 → 扫描执行 → 统计汇总
- **约束**: 明确标注数值结果≠证明；网格覆盖足够密
- **案例数据**: 1225点, σ∈[0.02,0.98], γ∈[5,53], 零违反
- **格式**: 扫描报告

### D3-03 公式匹配验证
- **必选组件**: 推导公式与独立数值计算的对比结果、误差分析
- **组装顺序**: 公式输入 → 独立数值计算 → 逐点对比 → 误差统计
- **约束**: 匹配误差必须量化；不匹配点必须独立复现并分析原因
- **案例数据**: 导数求和公式与数值差分误差 < 0.01%
- **格式**: 匹配报告

### D3-04 安全边际
- **必选组件**: gap值、单调性判断
- **组装顺序**: gap计算 → 单调性分析 → 结论
- **约束**: gap必须显式计算且>0
- **格式**: 安全边际报告

### D3-05 严格性确认
- **必选组件**: 三层分类（✅已证/🟢已验证/🔴待证）、**计算机辅助验证项说明**
- **组装顺序**: 逐项检查 → 三层标注 → 汇总
- **新增判定标准**:
  - **已证**: 纯解析推导，无数值依赖
  - **已验证**: 数值证据支持，解析证明待完成
  - **待证**: 无解析证明亦无数值证据
- **格式**: 严格性确认清单

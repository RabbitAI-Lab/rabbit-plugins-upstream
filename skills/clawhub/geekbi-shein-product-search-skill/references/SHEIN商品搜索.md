# SHEIN 商品搜索方法

## 适用问题

- 热销、日销、新品、低同款竞争、新店热销与大卖新品。
- 指定关键词、类目、价格带、托管模式、评分、评论量或上架时间找商品。
- 对比候选商品的销量、销售额、增长、价格、供货价与店铺实力。

需要榜单时读取 [商品榜单预设](SHEIN商品榜单预设.md)，调用方式和完整字段见 [商品搜索接口](SHEIN商品搜索接口.md)。

## 查询步骤

1. 固定站点；未指定用默认入口 `1`（名称“全部”，当前映射 `us`，不是跨站聚合），明确美国用 `2`，其他站点实时解析。
2. 关键词和类目通常二选一。类目 ID 必须来自用户或类目搜索，不能按名称猜测。
3. 从全新参数对象加入硬条件，再选择与问题一致的单一排序字段。
4. 首次通常取 20–50 条；`total` 是精确命中数。需要完整分布时继续分页，最大每页 200、最多访问前 10000 条；命中超过 10000 时缩小筛选范围，不能把已取样本称为全量。
5. 先检查数据更新时间、缺失值与样本边界，再比较候选。

## 指标解释

- `sold/sales`：最近销量/销售额；`totalSold/totalSales`：累计总量。不得互换。
- 日、周、月指标用于近期表现；对应变化率是小数比例，`0.2` 表示增长 20%。
- `minPrice/maxPrice` 使用站点本地币种；供货价字段使用人民币。利润测算前统一币种，并另计平台费、物流、退货和广告成本。
- `similarNum` 对外称为“同款数（跟卖数）”，表示销售同一款商品的同行数量；数值越高通常代表核价和同质化竞争更强。
- `goodsScore/reviewNum` 分别反映评分与反馈规模；高销量低评分、低评论量高评分都需谨慎。
- `mallSold` 是关联店铺近 3 个月销量信号，不等于该商品销量。
- 托管模式只按 `1=全托管`、`2=半托管` 解释。
- 上架时间可能为空；筛选时服务端可回退采集创建时间，回答中不要把采集时间写成确定上架日。

## 选品判断

至少同时检查需求、趋势、竞争、价格空间、评价与店铺结构：

- 需求：最近销量、累计销量和销售额是否有足够绝对量。
- 趋势：日、周、月指标是否一致，增长是否由低基数造成。
- 竞争：同款数（跟卖数）、商品数量与头部集中是否过高。
- 经济性：售价与供货价价差是否足以覆盖全部成本。
- 质量：评分、评论量与评论痛点是否存在系统性风险。
- 可复制性：头部表现是否只来自单一大店或超长经营历史。

结果只证明命中当前筛选，不自动证明“爆品”或“蓝海”。

# 深层参考：结果可视化

## 读取时机

当 `static/fragments/stage/result-visualization.md` 不足以完成图表选择、图注设计、结果解释或论文图表组织时，读取本文件。

## 目标

结果可视化用于把模型输出转化为论文中的证据。图表的作用是解释结论、比较方案、展示趋势、证明模型有效，而不是装饰论文。

所有论文图表必须由 Python 绘图库生成，优先使用 matplotlib、seaborn、plotly、networkx、scipy、statsmodels 或 pandas 绘图接口。不得用 AI 生成图片、Excel 默认图、PPT 手工形状、网页截图或低分辨率截图替代论文图表。PIL 只能用于合页预览、裁剪或辅助拼接，不能作为主要数据图绘制工具。

## 图表选择

根据结果类型选择图表：

- 预测结果：折线图、实际值与预测值对比图、置信区间图。
- 评价排名：柱状图、雷达图、热力图、排序表。
- 优化方案：方案对比图、资源分配图、路径图、甘特图。
- 空间结果：地图、区域热力图、空间散点图。
- 时间演化：折线图、面积图、动态趋势图。
- 误差表现：残差图、误差分布图、箱线图。
- 因素贡献：条形图、SHAP 图、敏感性曲线。
- 多目标权衡：帕累托前沿图、散点图、权衡曲线。

## 图表组合规划

完整论文在生成图表前先规划图表组合。每个子问题至少包含 2 种以上表达方式；整篇论文应覆盖多种图型，而不是反复使用同一种图。

常用组合：

- 数据预处理：分布直方图/核密度图、箱线图、相关性热力图、缺失矩阵或变量概览表。
- 预测模型：实际-预测对比图、误差分布图、残差散点图、ROC/PR 曲线或校准曲线。
- 时间演化：观测散点+拟合曲线、分组趋势曲线、面积图、阶段对比图。
- 聚类或分组：降维散点图、亚组均值雷达图、亚组特征热力图、轮廓系数柱状图。
- 因素贡献：横向条形图、系数森林图、SHAP 汇总图、局部解释图。
- 敏感性分析：参数扰动曲线、情景对比柱状图、热力图、箱线图。
- 技术路线或模型流程：流程图、模块图、算法步骤图。

若当前问题只有少数数值结果，也应通过“结果表 + 解释型图 + 误差/稳定性图”的组合增强论证，而不是只放一张表。

每个子问题至少安排一个具有创新表达的图，但创新必须来自统计表达或模型解释，而不是装饰。优先选择“总览+细节”复合图、事件时间图、校准曲线、系数森林图、SHAP 汇总图、分组轨迹图、相关性聚类热力图、误差云图、敏感性响应面或网络关系图。创新图应回答明确问题：它展示了什么结构、验证了什么模型性质、支持了什么结论。

## 配色与视觉风格

图表应显得像正式竞赛论文，而不是默认软件截图。建议采用统一主题：

- 主色：深蓝或靛蓝，用于主要曲线、标题和重点数据。
- 辅色：青绿、珊瑚、金色或紫灰，用于对比组和强调项。
- 中性色：浅灰背景、深灰坐标轴和标签，减少纯黑大面积压迫感。
- 避免：彩虹色、荧光色、过多高饱和颜色、红绿直接对比、单一蓝色堆满全文。

字体必须统一：中文使用宋体，英文和数字使用 Times New Roman。使用 matplotlib/seaborn 时显式设置字体，并确认坐标轴刻度、图例、标题、注释和色条标签都能正确显示中文与英文数字。

绘图要求：

- 使用高分辨率导出，插入 Word/PDF 后文字仍清晰。
- 坐标轴标签、单位、图例和关键标注完整。
- 标题简洁，图注承担解释性名称，不用过长标题挤占画面。
- 同类图保持一致字体、字号、线宽、标记大小和颜色映射。
- 网格线使用浅灰细线；不使用厚重边框、默认蓝橙红绿乱序配色或 3D 柱状图。
- 对离群点、阈值、峰值、最优方案等关键位置加温和标注。
- 图例不得遮挡数据，标签不得重叠；必要时旋转标签、缩短标签或改用横向图。
- 不使用发光、玻璃拟态、大面积渐变、浮动卡片、过强阴影、AI海报式构图或与数据无关的装饰背景。
- 输出图片建议 300 dpi 以上，宽高比例按 Word 正文版心设计，避免插入后被拉伸。

## 图表规范

论文图表应满足：

- 有编号。
- 有清晰标题或图注。
- 坐标轴有变量名和单位。
- 图例清楚。
- 数值范围合理。
- 颜色不影响阅读。
- 同一论文中图表风格一致。
- 图后有文字解释。
- 图型服务于结论，且同一章节内尽量形成“总览-细节-检验”的层次。
- 图表源代码可复现，图表数据来自已处理数据或模型输出，不手工改图中数值。

不要在论文中放入无法解释的图，也不要让图表数量超过论证需要。

## 结果解释

每张结果图后至少回答：

- 图中最重要的现象是什么。
- 该现象对应题目中的哪个问题。
- 该结果说明模型得出了什么结论。
- 结果是否符合现实规律。
- 该结果对后续决策有什么意义。

避免只写“由图可知”。应具体指出变化趋势、极值、差异、排序、异常点或方案优劣。

推荐解释模板：

```text
图 X 展示了……。从图中可以看到，……在……区间/类别上表现最突出，其中……达到……。这一现象说明……，对应题目第……问中……的要求，也支持后续采用/判断/建议……。需要注意的是，……可能受……影响，因此本文在模型检验或敏感性分析中进一步检查……。
```

每张图后的解释至少包含 3 类信息：图中事实、模型/题目含义、结论边界。禁止只写“趋势明显”“效果较好”“符合预期”等空泛句。

## 交付前图表检查

若最终交付为 `.docx`，可使用 `scripts/verify_docx_figures.py` 做基础检查：

```bash
python scripts/verify_docx_figures.py paper.docx --min-figures 12 --min-explained 12
```

该脚本检查图片数量、图注和图后解释段，只能发现结构问题，不能替代视觉审查。脚本通过后仍需打开渲染后的 Word/PDF，逐页检查配色、清晰度、标签遮挡、图例位置和图文衔接。

若交付 Word，还应运行字体检查：

```bash
python scripts/verify_docx_typography.py paper.docx
```

该脚本用于发现正文或样式中残留的 Calibri、Arial、微软雅黑等默认字体。

## 表格使用

表格适合展示精确数值、排名、参数、误差指标和方案对比。

表格应包含表号、表名、字段含义、单位、必要的小数位控制和关键结果说明。不要把过长原始数据表放进正文，详细数据可放附录。

## 论文中的结果组织

结果章节应按题目问题组织，而不是按代码运行顺序组织。

推荐结构：

```text
针对问题一，先说明模型输出，再展示图表，最后解释结论。
针对问题二，先说明优化目标，再展示方案对比，最后给出推荐方案。
针对问题三，先展示评价结果，再说明排名差异和原因。
```

图表应与文字相互支撑。文字负责解释，图表负责证明。

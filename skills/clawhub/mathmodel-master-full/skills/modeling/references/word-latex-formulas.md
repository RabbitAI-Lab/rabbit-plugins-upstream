# 深层参考：Word 中的 LaTeX 公式

## 读取时机

当最终论文需要交付 `.docx`，或需要在 Word 中插入、转换、检查数学公式时，读取本文件。

## 核心规则

Word 论文中的公式必须能正确显示并可编辑。不要把公式作为普通文本、截图、不可编辑图片或代码块插入正文。

严禁把纯文本直接塞进 `m:oMath` 或 `m:oMathPara` 伪装成 Word 公式对象。例如 `t_ij = T_i + ...`、`sum_k sum_i`、`||u_i-mu_k||^2` 即使位于 OMML 节点中，也仍然是错误公式；下标、上标、分式、求和、范数、希腊字母必须渲染为真正的数学排版结构。

优先工作流：

```text
论文源稿中的 LaTeX 数学表达式
-> 转换为 Word 公式对象
-> 在 .docx 内保存为 OMML
-> 检查 Word 中可显示、可编辑、编号正常
```

## 推荐生成方式

若从 Markdown 或 LaTeX 源稿生成 Word，优先使用能把 LaTeX 数学转换为 Word OMML 公式的工具链。公式写法采用：

```text
行内公式：$E=mc^2$
独立公式：
$$
P=k f^\alpha B_m^\beta
$$
```

转换到 `.docx` 后，公式不应在正文中显示为 `$...$`、`\frac{}`、`\sum` 等原始文本，而应成为 Word 公式对象。

如果使用脚本生成 `.docx`，优先选择可靠转换链：

- 使用 Pandoc、Word 转换接口或成熟的 LaTeX-to-OMML 工具把 LaTeX 转成 OMML。
- 或用 OOXML 明确构造 `m:f`（分式）、`m:sSub`（下标）、`m:sSup`（上标）、`m:nary`（求和/积分）、`m:d`（括号/范数）等数学结构。
- 不要只创建 `<m:oMath><m:r><m:t>公式字符串</m:t></m:r></m:oMath>`。这种做法会在 Word 中显示成代码样文本，应视为失败。

## Word 公式插入原则

- 行内公式用于短变量、短等式和正文解释。
- 独立公式用于目标函数、约束条件、评价函数、损失函数、推导公式和重要模型。
- 独立公式应单独成行，并根据论文需要编号。
- 公式编号建议右对齐，格式如 `(1)`、`(2)`。
- 公式前说明建模含义，公式后解释变量含义。
- 不要在正文中连续堆公式而缺少文字解释。

## LaTeX 写法约束

优先使用 Word 转换工具支持度高的基础 LaTeX：

- 分式：`\frac{a}{b}`
- 上下标：`x_i`、`x^2`
- 求和：`\sum_{i=1}^{n}`
- 积分：`\int_a^b`
- 希腊字母：`\alpha`、`\beta`、`\lambda`
- 矩阵：`\begin{bmatrix} ... \end{bmatrix}`
- 分段函数：`\begin{cases} ... \end{cases}`

避免使用过于复杂或依赖额外宏包的 LaTeX 命令。若转换失败，改写为更基础的数学表达。

## 公式编号建议

对重要公式使用“公式对象 + 右侧编号”的版式。可使用三列表格实现：

```text
左列空白 | 中列公式 | 右列编号
```

表格边框应隐藏。这样比手工空格对齐更稳定。

## 生成后检查

生成 `.docx` 后必须检查：

- Word 中公式是否正常渲染。
- 公式是否可编辑，而不是图片。
- 正文中是否残留 `$...$`、`\frac`、`\sum` 等原始 LaTeX。
- 公式编号是否连续。
- 行内公式是否破坏行距。
- 独立公式是否与前后文字间距协调。

可使用 `scripts/verify_docx_math.py` 对 `.docx` 做结构检查。该脚本会检查 Word 公式对象数量、残留 LaTeX、浅层伪 OMML 和代码式公式文本，但不能替代最终视觉检查。

检查脚本必须在严格模式下通过：不仅要求存在 OMML 公式节点，还要求公式中含有真实数学结构。若脚本报告 `code-like math text`、`shallow OMML` 或公式文本包含 `_ij`、`sum_k`、`beta^T`、`||...||` 这类代码式痕迹，应回到公式生成步骤重做转换。

视觉检查时重点查看：

- `t_{ij}` 应显示为下标，不应显示为 `t_ij`。
- `\frac{a}{b}` 应显示为上下分式，不应显示为 `/` 拼接。
- `\sum_{k=1}^{K}` 应显示求和符号和上下限，不应显示为 `sum_k`。
- `\|\mathbf u_i-\boldsymbol\mu_k\|^2` 应显示范数与上标，不应显示为 `||u_i-mu_k||^2`。
- `\beta`、`\lambda`、`\gamma` 等应显示为希腊字母，不应退化为 `beta`、`lambda`、`gamma`。

## 写作约束

论文中的公式必须服务于模型表达。每个重要公式应说明：

- 公式解决哪个问题。
- 变量和参数含义。
- 目标函数或约束含义。
- 公式结果如何进入求解或评价。

不要只给公式而不解释，也不要只给文字而缺少必要数学表达。

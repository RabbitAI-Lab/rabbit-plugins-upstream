# 学习娃 LearnWa · 常见问题与反模式

这一页专门解决两件事：**出了问题怎么排查**，以及**为什么有些事不能做**。

---

## 一、报错信息对照表

脚本的所有报错都带修复建议，退出码含义固定：

| 退出码 | 含义 | 处理方式 |
|--------|------|----------|
| 0 | 成功 | 直接打开输出的 HTML |
| 2 | 输入有问题 | 按提示改分块或参数，重跑 |
| 3 | 技能自身文件缺失 | 检查 `templates/` 是否完整，必要时重装技能 |
| 1 | 未预期异常 | 把提示里的最后一行贴给助手排查 |

常见报错与原因：

| 报错关键词 | 真正的原因 | 怎么改 |
|------------|------------|--------|
| 找不到分块文件 | 路径写错、文件被移动，或还没写 lesson-block.json | 检查路径；不想用分块就直接给一句话 |
| 分块 JSON 格式有误（带行号列号） | 多写/漏写逗号、用了中文引号“”、键名没加引号、末尾多了逗号 | 按行号定位改掉；可用 `python -m json.tool` 先校验 |
| skillId 不认识 | 写成了 `break_10`、`jieshi`、`破十法` 这类 | 只能是 `break_ten` / `make_ten` / `level_ten`；借十法填 `break_ten` |
| themeId 不认识 | 把孩子的专属兴趣当成了内置主题名 | 内置主题只有 5 个；新兴趣用 `customTheme` |
| 你说到了主题「X」，它不是内置主题 | 用户点名了某个兴趣（例如「来个足球的」），但 X 不在内置列表里 | 按报错里的骨架补 `customTheme`；**不要**加 `--allow-default-theme` 绕过 |
| 提示 customTheme 没有给 themeCSS | 自定义主题没写配色 | 补 `themeCSS`（或至少 `primaryColor`），否则孩子看到的是中性灰 |
| 题目 … 不能用于… | 数字不满足该方法的适用范围 | 按提示换题，或加 `--force-random` |
| numbers.a 必须是整数 | 写成了 `"十五"`、`15.5`、`true` | 写成纯整数 |
| 找不到 H5 模板文件 | `templates/learnwa-template.html` 被移动或删除 | 恢复该文件；技能目录应有 SKILL.md / templates / references / scripts |
| 模板文件里缺少 __CONFIG_PLACEHOLDER__ | 模板被改坏 | 从原始版本恢复模板，不要在模板里删占位符 |
| 写文件失败 | 目标目录没权限，或文件正被别的程序占用 | 换目录，或用 `--output` 指定新路径 |

排查顺序建议：**先 `--list` 看可用参数 → 再 `python -m json.tool` 校验分块 → 最后加 `--output` 换目录重跑**。

## 二、常见问题

**Q1：孩子说“借十法”，为什么生成的是破十法？**
因为两者数学逻辑一致，只是使用场景不同：破十法专攻 20 以内退位减法，借十法常用于 100 以内或更多位数的退位减法。当前统一用 `break_ten` 模板表达“向十借”的核心逻辑，不要为借十法另造一套流程。

**Q2：为什么我写 `numbers: {a:15, b:8}` 有时被拒绝？**
该方法的适用范围是有硬条件的：
- 破十法 / 平十法：被减数 11–19，减数 2–9，且**减数必须大于被减数的个位**（否则不退位，用不上这两个方法）。
- 凑十法：第一个加数 6–9，第二个加数 2–9，且**两数之和大于 10**（否则不用凑十）。

**Q3：随口说“来个数学习题”会触发吗？**
不会。触发需要明确的信号词（破十法/凑十法/平十法等）。这是刻意设计的：过早触发会生成与家长意图不符的教具。识别不到时会明确提示“已默认使用破十法”，不会静默猜。

**Q4：孩子喜欢的东西不在内置主题里怎么办？**
用 `customTheme` 现场创建，不要硬套旧主题。这是本技能的核心能力，见 `lesson-block-format.md`。

**Q5：我说「来个足球的」，为什么生成出来是「小汽车过桥」？**
这是**最严重的一类错误**，现在已经修掉了。原因是脚本原先识别不到主题就静默回落到了默认主题 `vehicle`（交通工具）。现在的处理是：

- 只要用户**点名了主题**（`来个X的` / `换个X` / `喜欢X` / `X主题` 等写法），而这个 X 不是内置主题，脚本**直接报错**（退出码 `2`），并给出可复制的 `customTheme` 骨架；
- 只有用户**完全没提主题**（例如只说「来个破十法」）时，才允许用默认 `vehicle`。

所以正确做法是：听到「来个足球的」就写 `customTheme`（小球员 / 足球 / 踢走 / 踢进对方球门 + 草地绿配色），而不是套汽车。

**Q6：customTheme 不写 `themeCSS` 会怎样？**
不会有好看的默认色 —— 脚本只能用一套中性灰色板，孩子看到的主色和主题完全不搭。
所以 `themeCSS` 至少给 `--primary`、`--item-color`、`--text-on-item`；也可以只写 `primaryColor` 简写，但推荐写全。脚本发现你没给会主动提示。

**Q7：生成的页面在 iPhone SE 上会溢出吗？**
模板已按 320×568 和 375×667 竖屏约束设计，关键按钮不低于 44px。如果你改了模板尺寸，需要重新在两档分辨率下检查首屏是否还能同时看到孩子区、家长说和按钮。

**Q8：为什么按钮不写“下一步”？**
“下一步”是模板化措辞，孩子看不懂要干什么。按钮必须写成当前要做的动作（“开始摆出来”“第一排拿走”“说出答案”），家长照着念就知道要引导什么。

**Q9：为什么平十法一开始不全部分色？**
一开始全绿框是表达“这些都是同一个被减数”；点“开始摆出来”后才分色，才是表达“要从里面减掉哪一部分”。先分色会让孩子误以为被减数本来就是两个不同的数。

**Q10：孩子说“会了”，但一让他复述就不会，怎么办？**
总结页有“没关系，再摆一次”按钮，可一键回到第一步。这是刻意留的兜底，不要去掉。

**Q11：点名了主题，我还得自己画 SVG？**
对。模板内置造型只有 5 个主题。用户点名别的兴趣（金龙鱼、足球、城堡…）时，正确做法是**一步到位**：
写 `customTheme` + 自己画 `heroSvg`（主角，`viewBox="0 0 120 100"`）和 `itemSvg`（物品，`viewBox="0 0 40 40"`），
颜色用 `{{primary}}`/`{{accent}}`/`{{item}}` 占位符。不给 SVG，页面只会退化成通用造型，孩子对不上号；
只报错停下、让用户再来一次，也算没做完。**能点名，就要能画出来。**

## 三、反模式清单（以及为什么不行）

| 不要这样做 | 为什么不行 |
|------------|------------|
| 用 emoji 当角色或物品 | emoji 在不同设备渲染差异大、风格廉价，会破坏“儿童绘本”质感；必须用内联 SVG |
| 用紫色/蓝色渐变做主按钮 | 一眼就是通用 AI 模板，家长不会觉得这是给孩子的东西；用实色纸片按钮 |
| 一屏塞多个数学动作 | 孩子一屏只能处理一个数学动作，多了就只会盯着看不动脑 |
| 在孩子区放大量文字和按钮 | 孩子是“看和说”的角色，不是“读和点”的角色；文字多了家长也没法引导 |
| 在算式里直接显示答案 | 提前给答案，孩子就不再推理了；`?` 必须留到最后才揭晓 |
| 破十/平十法先灰掉、后提问 | 动画早于提问，等于直接把结果演给孩子看；必须先提问，孩子答了再动 |
| 同一按钮连续两次显示相同文案 | 家长会以为要点两次，直接卡在这里；按钮文案必须随状态变 |
| 用“下一步”“继续”这类词 | 模板化措辞，不告诉家长这一步要做什么动作 |
| 用外部 CDN / 拆成多文件 | 家长可能在没网的环境用；必须是内联一切的单文件 HTML |
| 让生成脚本静默改掉家长指定的题目 | 家长以为在教 15-8，实际页面是别的题，等于教错；不合规必须明确报错 |
| 把新兴趣硬套到内置主题 | 孩子对不上号，兴趣点就没了；宁可写 `customTheme` |
| 用户点名了主题，却回落到默认主题 | 说了足球却出现小汽车，孩子完全对不上号，家长会以为工具坏了；点名了就必须用 `customTheme` 实现 |
| 用 `--allow-default-theme` 压掉主题报错 | 这个参数是给人明确要求默认主题时用的逃生口；用它来"让脚本别报错"，等于把用户点名的主题丢了 |
| customTheme 不写 `themeCSS` | 只能用中性灰，孩子看到的颜色和主题不搭，等于没做主题 |
| 直接改模板去实现个性主题 | 改模板成本高、易破坏通用性；个性内容只写在分块里，由脚本合成 |
| 自己去扩大教学范围（乘除、分数） | 本技能只做小学一年级 20 以内加减法，超范围内容没有经过严谨校验 |

## 四、三分钟自检清单

生成完一页后，交付前快速过一遍：

1. 数学步骤能不能复述成一句话？（先拆/先借/先凑，再减/再加）
2. **主题是不是用户点名的那个？**（说了金龙鱼就不许出现小汽车；点名了兴趣就必须有 `customTheme`）
3. **点名非内置主题时，自己画的 `heroSvg`/`itemSvg` 给了吗？**造型是不是孩子认得出来的那个？
4. 颜色表达的关系对不对？（哪部分是同一个数，哪部分是要减/要补的量）
5. 有没有提前暴露答案？
6. 每一步的按钮文案是不是当前动作？
7. 结尾有没有“再摆一次”？
8. 页面里有没有 emoji、渐变、外部链接？自画 SVG 里有没有写死颜色或混入脚本？

## 五、打包上架约束（提交技能市场前必看）

技能市场按 `SKILL.md` 的 YAML frontmatter 解析元数据，官方校验脚本（`skill-creator/scripts/quick_validate.py`）会做硬检查，踩中直接打不上：

1. **`description` 不能出现尖括号 `<` 或 `>`。** 校验用的是朴素正则 `description:\s*(.+)`，所以**多行折叠块 `description: >-` 里的 `>` 会被当成尖括号**，直接报 `Description cannot contain angle brackets`。
   → 正确写法：`description` 用**单行**（官方示例即单行）；确实要换行就用 `|`，**不要用 `>-`**。
2. **`name` 必须是小写连字符**（`^[a-z0-9-]+$`），不能首尾连字符、不能出现连续 `--`。
3. **必填字段**：`description` / `description_zh` / `description_en` / `version` / `author`；建议一并给 `display_name` / `display_name_en`。`version` 写纯数字语义化版本，如 `1.0.1`。
4. **子目录只用文档列出的名字**：`references/`（参考资料）、`scripts/`（可执行脚本）、`templates/`（模板）。不要自造 `assets/` 之类的目录名。
5. **不要硬编码本机绝对路径**（如 `D:\...`）。输出目录等一律用相对路径或 `--output` 传入，否则别人装了技能跑不起来。
6. 官方打包脚本 `package_skill.py` 会**先跑校验再整目录打包**，校验不过就直接失败。

上架前自检（把路径换成自己的技能目录）：

```bash
python "<skill-creator>/scripts/quick_validate.py" "<你的技能目录>"
# 期望输出：Skill is valid!
```

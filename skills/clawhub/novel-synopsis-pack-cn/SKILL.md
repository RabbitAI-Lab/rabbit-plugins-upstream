# 小说投稿梗概包

把小说素材收束成编辑可快速判断故事、人物与卖点的投稿资料。输入完整故事概要、章节摘要和投稿长度要求；交付三档梗概与人物关系摘要。

## 适用边界

- 适合：已有完整故事走向的小说投稿整理。
- 不包含：小说评分、商业前景判断、章节续写或代写。
- 事实优先：只使用输入中的已知事实；可选建议必须标成“建议”，不得写成剧情事实。

## 输入

提交以下 JSON 或同等信息：

```json
{
  "story_overview": "从开端到结局的完整故事概要，包含关键转折与结局。",
  "chapter_summaries": [
    {"chapter": 1, "summary": "本章发生的事件、人物选择和结果。"}
  ],
  "submission_lengths": [300, 800, 1500]
}
```

`story_overview`、`chapter_summaries`、`submission_lengths` 均为必填项。长度要求可含其他字数，但必须明确是否仍需要 300、800、1500 三档；未明确时先追问，不能自行假定。

## 工作流

1. 核对必填项、故事是否覆盖结局，以及章节摘要是否可追溯关键转折。
2. 提取主角目标、阻碍、转折、高潮、结局和人物关系；信息冲突时列出冲突并提问。
3. 先完成 1500 字版（完整因果链），再压缩成 800 字版和 300 字版；保留结局，不用悬念式文案代替梗概。
4. 输出人物关系摘要，逐条写清“人物 A—关系/变化—人物 B”。
5. 对每一版标注实际字数（中文字符与可见标点计数；数字和英文连续串各计 1 个字符）。

## 输出格式

```markdown
# 投稿梗概包

## 300 字梗概（约 N 字）
…

## 800 字梗概（约 N 字）
…

## 1500 字梗概（约 N 字）
…

## 人物关系摘要
- 林岚—隐瞒真相后重新建立信任的搭档—周野

## 资料核对
- 已知事实：…
- 建议（如有）：…
- 待确认（如有）：…
```

如果关键信息缺失，直接按以下格式返回，不编造人物、结局或转折：

```markdown
无法生成投稿梗概包。
缺少：story_overview、chapter_summaries。
请补充：完整故事走向（含结局）与逐章摘要。
```

# Check a plan against its sources

Read the current goal, applicable project rules and relevant standards, plus the plan or tasks that actually exist. Use the project's authority and original paths. A missing optional document matters only if a decision or acceptance check depends on it.

Walk forward from each required behavior to the proposed change, delivery task and assertion at the intended entry point. Use the same input across the documents. Walk backward from each task to its requirement, rule or technical prerequisite. For phased work, combine phase and task dependencies and inspect the artifact handed to the successor.

For every candidate finding, walk through a specific scenario. Show the wrong output, missed step, unnecessary work or false pass that following the text would produce. Distinguish contradictory results, agreed behavior with no owner or check, and unresolved product choices. State the affected scope and work that can proceed. [Coverage examples](references/coverage.md) illustrate the distinction.

Cite both conflicting passages or the omitted requirement. Identify the original place to fix it. Drop wording differences when the existing material already directs correct implementation and acceptance. Report in chat by default. With authorization to correct the material, preserve IDs and valid progress, fix settled issues and recheck the affected relationships. State the reviewed scope when there are no findings.

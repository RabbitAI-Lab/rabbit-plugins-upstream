# MCP 鉴权与 Key 配置

Key 是强依赖——没有它所有打车工具都不可用。本文只写地址、Key 与配置。

## 1. Server 参数

凭证是**高德开放平台 Web Service Key**，环境变量写作 `AMAP_WEBSERVICE_KEY`；传输时只放在地址的 `key` 查询参数上。

| 项 | 值                                                                        |
|----|---------------------------------------------------------------------------|
| Server 名称 | 高德打车                                                                  |
| URL | `https://mcp.amap.com/rest/amap_car/dev/mcp?key=YOUR_AMAP_WEBSERVICE_KEY` |
| 传输 | Streamable HTTP                                                           |
| 认证 | URL 的 `key` 查询参数                                                     |

在 MCP 客户端中新增 Server，按客户端自己的字段名填入以上值。

**只有把 Key 写进 MCP 客户端配置，打车工具才会出现**；`export` 环境变量不改变工具可用性。

## 2. 首次上手（一次即可）

1. 取 Key：访问 [高德开放平台](https://lbs.amap.com/api/webservice/create-project-and-key) 创建应用并获取。转述给用户时给完整链接，不要只说"去开放平台申请"。
2. 按上方参数新增 MCP Server：平台能代写 MCP 配置就用它写入，否则把参数交给用户手动添加。用户此前 `export` 过 `$AMAP_WEBSERVICE_KEY` 时可以读它的值来写入，但这并不代表已经配好。
3. 告知用户**配完要重连客户端或新开会话工具才会出现**；之后调一次 `query_orders`（`agent_name` 传当前宿主平台名称，`scene` 传空，只读、不产生订单）验证，有返回即上手完成，并把当天日期记进 `assets/config.json` 的 `lastVerifiedAt`（文件不存在时从 `../assets/config.example.json` 复制；复制或写入失败就跳过，不阻塞流程）。
4. 完成「下单前授权」后，此后所有会话直接办用户提的出行需求，也不做例行校验；只有调用报鉴权失败才走本文「索要 Key」。

## 3. 下单前授权

获取 Key 后，确认用户已在高德地图 App 完成以下两项授权；未完成时下单会失败。若下单失败并提示未授权，引导用户先打开高德地图 App，按提示完成授权和签约后再重试。

### 录音录像授权（车内录音录像）

这里的录音录像授权，指司机送驾过程中开启车内录音录像的授权，不是手机麦克风/相机权限。未授权时无法通过 Skill 完成下单。请在高德地图 App 内按以下三步完成授权，图中红框标出的位置即为需要点击的入口。

| 第一步：点击右上角头像 | 第二步：点击「安全中心」 | 第三步：点击「录音录像授权」 |

> 若已授权仍提示未授权，请确认授权账号与当前使用高德地图 App 的账号一致。

| 第一步：点击右上角「设置」 | 第二步：点击「支付设置」 | 第三步：点击「高德打车免密支付管理」 |

> 若已签约仍提示未授权，请确认签约账号与当前使用高德地图 App 的账号一致，并检查车内录音录像授权是否已开启。

## 4. 失败分类

| 现象 | 缺什么 | 动作 |
|------|--------|------|
| 工具列表里没有打车相关工具 | Server 未注册，不只是缺 Key | 走本文「首次上手」；工具没出现前不要反复重试或硬验凭证 |
| 文案含"未登录""登录""鉴权" | Key 缺失或失效 | 走本文「索要 Key」 |
| 文案为"参数缺失或非法"或其他业务失败 | 与凭证无关（前提是文案没有指向鉴权） | 按 `errors.md` 的错误码排查，**禁止索要 Key** |

返回 `50401` 或 `INVALID_USER_KEY` 时同样按本节处理。

命令行或 curl 报鉴权失败时，先按本文「命令行排查」检查 `$MCP_URL` 的引号，再索要 Key。

## 5. 索要 Key

仅在鉴权失败时发起，用固定话术，**等用户回复后再继续**，不要跳过这一步去改参数试探：

> 🔑 高德打车需要你的高德 Key 才能发起，请把 Key 发我（例如「我的 Key 是 xxxxxx」）。
> 还没有 Key 的话，先到本文「首次上手」第 1 步的页面申请——发给用户时要给完整链接，别让他自己翻文档。

拿到 Key 后按本文「首次上手」第 2、3 步写入并复验。**上限：单轮 1 次、单会话累计 2 次**；超限、用户明确拒绝，或复验仍失败（说明 Key 无效而非未配置）时，告知本次打车未完成并结束流程。任何情况下都不要猜 Key、不要拿历史对话里的其他 Key 顶上、不要换 Key 试探、不要编造订单结果。

## 6. 安全与配置档案

- Key 决定代谁下单、由谁付款：只使用用户本人的 Key；他人提供的 Key 不得用于下单（代下单），也不要跨账号使用。不要把 Key 写进临时脚本或版本库。
- `assets/config.json` 记录 serverName / endpoint / authMode / webServiceKey / lastVerifiedAt，**默认不存 Key**；文件缺失时从 `../assets/config.example.json` 复制。`authMode=rest-direct` 是预留给脚本直连的模式，只有切到它才填 `webServiceKey` 字段；该文件是运行时数据，默认不入库、不随包分发。
- 复制或写入 `assets/config.json` 失败时（skill 目录只读、沙箱限制），跳过持久化，不要反复重试，也不要阻塞主流程。
- `lastVerifiedAt` 只用于排障话术：为空说明这台机器从未配成过，报鉴权失败时说"还没接入"；有值说明之前成功过，说"配置可能失效了"。**它不是校验结果，不能凭它免掉失败后的复验。**

## 7. 命令行排查

仅用于命令行调试，不改变 MCP 客户端里的工具可用性。把 §1 的 URL 中 `YOUR_AMAP_WEBSERVICE_KEY` 替换为 `$AMAP_WEBSERVICE_KEY` 后整体赋给 `MCP_URL`；赋值和引用（`"$MCP_URL"`）两侧都用英文双引号，否则 `$AMAP_WEBSERVICE_KEY` 会保持字面量，请求表现为鉴权失败。请求体按 MCP 标准 `tools/call` 封装，`name` 取工具名、`arguments` 按 `tool-contracts.md` 填写。

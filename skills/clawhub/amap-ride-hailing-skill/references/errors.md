# 错误码与失败处理

本文只写错误分类、重试策略和连通性探测。

## 错误码 10003

`10003` 用于参数、业务失败或限流等，先看文案再决定动作：

| 文案 | 含义 | 处理 |
|------|------|------|
| 含"未授权""未签约""支付失败" | App 授权或免密支付未完成 | 按 `auth.md`「下单前授权」引导用户完成；**禁止索要 Key** |
| 含"无可用车辆""超出服务区""暂无司机" | 当前条件下无运力 | 如实告知，调整时间、地点或车型后重新规划；不要归为凭证问题 |
| 含"参数缺失或非法" | 参数问题，**凭证没问题** | 按 `../SKILL.md`「业务参数解析」核对参数，枚举字段只传 `tool-contracts.md` 列出的值，**禁止索要 Key** |

不要把“【模型引导】”类文案原样输出给用户，只告知本次操作未完成。

## 错误码 99999
| 文案 | 含义 | 处理 |
|------|------|------|
| 含"限流""频率""配额" | 超出配额 | `query_orders` 可等 1 分钟重试一次；`confirm_order`/`cancel_order` 不自动重试，先查询订单状态再决定 |


## 错误码 50401 或 INVALID_USER_KEY

| 含义 | 处理 |
|------|------|
| `key` 缺失或无效 | 走 `auth.md`「失败分类」判定、「索要 Key」处理 |

## MCP Server 不可用

**现象**：调用返回连接错误；工具列表里没有打车工具时按 `auth.md`「失败分类」处理。`$MCP_URL` 的配置见 `auth.md`「命令行排查」。连通性探测：

```bash
curl -X POST "$MCP_URL" -H "Content-Type: application/json" -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"client","version":"1.0"}}}'
```

## Description:

Before rejecting a proposal or reflexively agreeing, build the strongest faithful opposing case, state agreement conditions, then update or reaffirm.

This skill is ready for commercial/non-commercial use.

## Use Case:

Developers, reviewers, and decision makers use this skill to test proposals, designs, and preferred plans against the strongest faithful opposing case before accepting, revising, or reaffirming a decision.

### Deployment Geography for Use:

Global

## Known Risks and Mitigations:

Risk: The skill can make decision discussions more verbose or formal when invoked.

Mitigation: Use it for meaningful tradeoffs, design reviews, architecture debate, or decisions where premature agreement or rejection would carry real cost.

Risk: Over-applying steel-manning can delay action or create false balance around settled facts, hard constraints, security anti-patterns, or live emergencies.

Mitigation: Skip steel-manning in those cases; correct the issue or act first, then use post-incident review if reflection is needed.

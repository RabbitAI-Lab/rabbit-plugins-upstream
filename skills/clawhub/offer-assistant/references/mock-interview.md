# 模拟面试方法论 — 基于 JD + 定制简历做面试预演

## 核心逻辑

模拟面试 = **JD 看重什么** × **简历写了什么** × **中间留了什么坑**

三者交叉的地方就是最可能被追问的点。

## 面试前准备

### Step 1：回顾 JD 核心诉求

从 JD 分析结果中提取关键信息：
- **岗位核心职责是什么？**（面试官最想确认候选人能做什么）
- **哪些是硬性要求？**（缺了就大概率不过）
- **哪些是加分项？**（有最好，没有也不致命）

### Step 2：扫描简历风险点

逐点检查定制简历的内容：

- **量化数据** — 这些数据能扛住追问吗？
  - 「提升了 30%」→ 怎么算的？基数是多少？周期多长？是否有其他因素干扰？
  - 「处理 200+ 指标」→ 什么指标？怎么定义的？和谁确认的？
- **角色定位** — 简历写的是「主导」，但面试深问可能露馅吗？
  - 如果用户实际上只是参与方，但简历写了「主导」→ 要想好怎么圆
- **系统描述** — 提到的技术/系统真的熟悉吗？
  - 提到「数据仓库建模」→ 能说出用的什么模型（星型/雪花型）？为什么？
  - 提到「OneID」→ 能说出具体怎么做实体解析的吗？

### Step 3：交叉匹配

JD 要求的 × 简历有的 = **大概率会问的**
JD 要求的 × 简历没有的 = **有可能会问的（考察学习意愿）**
JD 没要求的 × 简历写了 = **可能会问的（面试官想确认你为什么写）**

## 模拟面试执行

### 问题类型

| 类型 | 例子 | 目的 |
|------|------|------|
| 🎯 **JD 定向** | 「你的经验中哪些和这个岗位最匹配？」 | 考察候选人能不能自证匹配 |
| 🔍 **深度追问** | 「你说提升了 30%，这个提升周期多长？基数是多少？」 | 检验数据真实性 |
| 🤔 **开放设计** | 「如果让你从零搭建这样一个系统，你会怎么做？」 | 考察架构能力和系统思维 |
| ⚡ **压力测试** | 「你刚才说主导了这个项目，具体你个人做了什么？」 | 检验实际贡献度 |
| 💡 **对比测试** | 「你之前做过 A，这个岗位要 B，你觉得 A 的经验能用吗？」 | 考察迁移能力 |

### 追问节奏

- **先浅后深**：先让用户完整回答一个题
- **再追问细节**：从用户的回答中抓一个点深挖
- **适当沉默**：用户答完后不要马上给反馈，让对方补充
- **交叉验证**：同一个信息在不同问题中是否一致

## 面试后复盘

### 用户自评

问用户三个问题：
1. **哪些问题你觉得自己答得好？** — 下次继续保持的
2. **哪些问题你觉得没答好？** — 需要补的
3. **有没有什么问题你完全没想到？** — 下次要提前准备的

### Javis 评估

基于面试中用户的回答，做三件事：
1. **标记踩坑点** — 哪些问题回答出现了逻辑漏洞、数据矛盾、方向不对
2. **优先级排序** — 哪些坑最致命（核心能力不匹配 vs 某一题没答好）
3. **给出行动建议** — 下次面试前需要补什么知识、准备什么口径

### 产出：知识补丁

每次面试复盘后，把没答好的问题 + 正确答案加入用户的「面试知识库」：

```
## 面试知识库

### 2026-07-12 | XX公司-YY岗位

**Q：怎么解决多源数据一致性问题？**
- 当时答了：主要靠人工核对
- 更好的回答：从源头做数据标准化定义 → 建立映射规则 → 自动化校验
  （面试官期待的是一套方法论，不是单点解法）

**Q：对于这个岗位你想做什么方向？**
- 当时答了：想尝试新的领域
- 更好的回答：结合已有经验做深度，同时补充行业知识
  （面试官想听的不是你想要什么，而是你能给什么）
```

## 面试复盘记录格式

每次面试后记录到投递日志中：

```
## 面试日志

### 2026-07-12 XX公司 · YY岗位 · 一面
- **面试官风格**：技术导向，追问深，注重底层原理
- **答得好的**：数据治理经验、项目主导能力
- **答得不好的**：对金融行业理解浅、职业动机不够清晰
- **核心教训**：离职原因必须和岗位对齐，不能自相矛盾
- **行动项**：补充金融行业知识，重新梳理职业动机叙事
- **下次注意**：先答「我能给什么」再答「我想要什么」
```

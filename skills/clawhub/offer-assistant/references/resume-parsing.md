# 简历解析方法论 — 从简历到模块化素材库

用户上传一份历史简历（截图 / PDF / 文字），Javis 拆解为结构化模块，建立素材库。

## 拆解流程

### 1️⃣ 接收简历

支持三种来源：
- **截图**（图片文件）：先 OCR 提取文字，再结构化
- **文件**（PDF / DOCX / HTML / 链接）：直接提取文字内容
- **文字**（直接粘贴的简历文本）：直接结构化

### 2️⃣ 截图识别的 OCR 流程

> ⚠️ 截图识别是本 Skill 中最容易出错的一步。请严格按照以下流程执行。

#### 2.1 提取图片

- 用户发截图时，从消息上下文的 `[message_id=om_xxx]` 中提取原始消息 ID
- 调用 IM 文件下载工具下载图片到本地临时目录
- ⚠️ 如果用户是**引用（reply_to）** 一条图片消息，不要用引用消息的 msg_id 去下载，要去找到图片所在的原始消息 ID

#### 2.2 执行 OCR

```bash
tesseract <图片路径> <输出路径无后缀> -l chi_sim+eng
```

- 建议使用 `chi_sim+eng` 双语模型（中文简历大概率有英文关键词）
- 系统需要安装 tesseract 并配置好中文语言包

#### 2.3 OCR 结果验证

**读取 OCR 结果后，必须做两件事：**

1. **列出提取的关键信息让用户确认** — 不要直接分析。把公司名、岗位名、关键数据列出来，让用户看一眼对不对。
2. **如果 OCR 输出为空或明显乱码** — 不要自己用模型看图去猜文字。模型看图时图片缩小后小字区域模糊，极易看错（踩坑教训：把「蔚蓝医宝」看成了别的公司）。应该**把原图发给用户**，说「这张图 OCR 没识别出来，能打字发一下关键信息吗？」。

#### 2.4 公司名 + 简历 PDF 文件的处理

如果用户发的是 PDF 简历文件：
- 先用 `pdftotext` 或类似工具提取文字内容
- 如果提取失败，再回退到截图方式

#### 2.5 不要做的事

- ❌ 不要用模型看图直接识别文字（不准确，图片缩小后不可靠）
- ❌ 不要凭记忆猜测时间/公司/数字（素材库是数据底座，必须准确）
- ❌ 用户发了压缩包或多个文件时不要只取第一个

### 3️⃣ 结构化提取

逐段将简历内容归类到以下模块：

| 模块 | 提取内容 | 备注 |
|------|---------|------|
| 🆔 **个人信息** | 姓名、手机、邮箱、所在城市 | 仅做识别用，不写入素材库核心 |
| 📚 **教育背景** | 学校、专业、学历、毕业年份 | |
| 💼 **工作经历（每段）** | 公司名、时间段、岗位、职责描述 | 关键模块，逐段独立存储 |
| 🚀 **项目经历（每个）** | 项目名、归属公司/时间段、角色、动作+结果 | 关键模块，逐项目独立存储 |
| 🔧 **技能标签** | 技术栈、工具、领域知识 | 打散为独立标签 |
| ✍️ **自我评价** | 个人简介原文 | 保留原文供后续参考 |

### 4️⃣ 建立素材库

提取完成后，存为一个结构化的素材库文档：

```
【素材库】
├── 【基础信息】姓名 / 手机 / 邮箱 / 城市
├── 【教育背景】学校 / 专业 / 学历 / 年份
├── 【工作经历】
│   ├── 经历①：公司A | 时间段 | 职责描述
│   ├── 经历②：公司B | 时间段 | 职责描述
│   └── 经历③：公司C | 时间段 | 职责描述
├── 【项目经历】
│   ├── 项目①：项目名 | 归属 | 时间段 | 角色 | 动作+结果
│   ├── 项目②：项目名 | 归属 | 时间段 | 角色 | 动作+结果
│   └── 项目③：项目名 | 归属 | 时间段 | 角色 | 动作+结果
└── 【技能标签】标签① / 标签② / 标签③ ...
```

**关键原则：**
- 每个项目/每段经历独立存储，不拼接、不合并
- 保留原文，不修改、不润色（素材库是数据底座，永远不改）
- 如有明显 OCR 错误，标注「[OCR 识别，待确认]」但不改原文

**同一家公司多岗位的处理原则：**
- 用户在同一家公司有多个岗位（如从 A 部门调到 B 部门），简历上写一整段覆盖全部时间
- 不拆成多个短段导致时间线断裂
- 只写目标岗位相关的内容即可，不留 gap

### 5️⃣ 交付确认

素材库构建完成后，发给用户确认：
1. 列出所有提取到的模块（不用逐字重复）
2. 标记可能的识别错误（OCR 模糊的名词、公司名、数字）
3. 问用户：「有没有遗漏的项目？」
4. 用户确认后，素材库正式生效

### 6️⃣ 素材库更新

当用户后续提供了新的简历/补充了信息：
- ❌ 不覆盖原有素材库
- ✅ 保留新版本作为增量，标注「更新于 YYYY-MM-DD」
- ✅ 两个版本并存，后续生成简历时以最新版本为准，旧版留作参考

## 常见问题

| 问题 | 处理方式 |
|------|---------|
| OCR 输出空/乱码 | 把原图发给用户，让用户打字提供关键信息 |
| OCR 识别不准确 | 列出提取结果让用户确认，标注待确认项 |
| 用户说「这个不准确」 | 问清楚具体哪里不对，修正素材库（不是改简历） |
| 用户发了多版简历 | 每版独立存储，保留时间戳，以最新版为主 |
| 用户发的是链接 | 打开链接看简历内容（工具或 web_fetch），不要问用户「你能发一下文字版吗」 |
| 用户说「加一个没写在简历上的项目」 | 按用户描述添加到素材库，标注「用户口述补充」 |
| 引用图片下载失败 | 追溯图片的原始消息 ID，不用引用消息的 msg_id 去下载 |

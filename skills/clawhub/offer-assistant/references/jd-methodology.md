# JD 分析 & 匹配方法论

从 JD 中提取结构化信息，评估候选人匹配度的完整框架。

## 1. 接收 JD

支持三种来源：
- **截图**（图片文件）：走 OCR 提取，参照 `resume-parsing.md` 的 OCR 容错流程
- **链接**：用 web_fetch 或浏览器打开页面提取文字内容
  - ⚠️ Moka / Boss 等 SPA 页面 JD 正文通过异步渲染，curl 只能拿到壳子，需用浏览器渲染后提取（参考 TOOLS.md 中的 CDP 方法）
  - 提取后必须列出关键信息让用户确认：公司名、岗位名、职责要点
- **文字**：用户直接粘贴的 JD，直接分析

### 1.1 JD 链接的 fallback 策略

| 来源 | 方法 | 失败处理 |
|------|------|---------|
| 普通链接 | web_fetch | 如果是招聘网站（Boss/猎聘），不允许用 browser 访问 |
| Moka 页面 | CDP 浏览器渲染 | 先访问首页建立 cookie，再导航到详情页，等 6-8s 渲染完成 |
| 完全无法解析 | 回退 | 告知用户无法提取，让用户贴文字版 |

### 1.2 招聘网站红线

BOSS 直聘、猎聘等第三方招聘网站反爬严重。无论搜索到什么线索：
- ❌ 禁止尝试用 browser 访问或 web_fetch 抓取其页面内容
- ❌ 禁止尝试绕过去抓取
- ✅ 让用户自己截图或贴文字

## 2. 关键词矩阵提取

逐句扫描 JD，分类到三个桶：

| 类别 | 定义 | 示例（供应链方向） |
|------|------|-------------------|
| 🔴 **核心词** | 高频出现、核心职责的关键词 | 供应链、库存、预测、数据仓库、BI |
| 🟡 **隐性要求** | JD 未明说但业务场景隐含的能力 | 行业经验、数仓建模、多源数据清洗 |
| 🟢 **无关词** | JD 没提到的能力领域（弱化或删除） | 国际化、增长黑客、用户增长 |

### 规则
- 核心词在个人简介首句中直接体现
- 隐性要求用已有的真实经验覆盖，不硬造
- 无关词在简历中不应出现——面试官看到会追问，浪费双方时间

## 3. 匹配度评估

| 维度 | 检查问题 |
|------|---------|
| 个人简介首句 | 是否击中 JD 核心词？ |
| 工作经历 | 每段重点是否回应核心职责？ |
| 项目排序 | 最相关的项目排最前面？ |
| 技能栏 | 是否包含核心要求又不含冗余？ |

输出百分比 + 简要说明。

## 4. 项目审核框架

写完后或评审简历时，逐项目检查：

### 第一层：一眼判断（1-2秒）
- ✅ 结果感 — 有数字？有前后对比？
- ✅ 角色感 — 「主导/设计/定义」还是「参与/协助」？
- ✅ 复杂度感 — 体系化工作还是单点任务？

### 第二层：深入推敲（10-15秒）
- ✅ 逻辑链 — 动作→结果有因果逻辑？
- ✅ 可追问性 — 数据扛得住面试官反问吗？
- ✅ 独特信息 — 换一个人也能写出来吗？通用描述要删

### 第三层：整体判断
- ✅ 完整性 — 覆盖 Why-What-How-Result？
- ✅ 定位明确 — 一眼看出角色？
- ✅ 面试钩子 — 至少 1-2 个值得追问的点

## 5. 公司调研

搜索公司全称 + 关键词（融资/上市/裁员/营收/评价）：

| 评估维度 | 内容 |
|---------|------|
| 赛道前景 | 行业增长还是萎缩？政策友好吗？ |
| 公司阶段 | 初创/成长期/成熟期？融资到哪轮？ |
| 岗位定位 | 核心业务 vs 边缘部门？有扩张信号吗？ |
| 稳定性风险 | 裁员历史、负面新闻、营收下滑？ |

输出风险评级（低/中/高）和建议（推荐投递 / 谨慎）。

## 6. 综合分析报告

### 输出格式

```
## 岗位分析报告

### 公司背景
（公司全称、行业、融资/上市情况、近期动态）

### JD 核心诉求
- 岗位定位：
- 职责重点：
- 硬性要求：
- 加分项 / 隐性要求：

### 与素材库匹配度
- 总体匹配度：XX%
- 强匹配项：
- 弱匹配项：
- 建议：✅ 推荐投递 / ⚠️ 谨慎
```

### 投递建议的生成规则

- 匹配度 ≥ 70% + 公司风险低 → ✅ 推荐投递
- 匹配度 50-70% → 给出具体改进建议（补什么知识/改哪个项目）
- 匹配度 < 50% + 公司风险高 → ⚠️ 谨慎，说明理由

### 岗位分析手册

分析完成后，同步创建「岗位分析手册」文档（飞书文档），包含：
- JD 原文
- 完整分析报告
- 后续的面试记录也追加到同一文档（参见 tracking.md）

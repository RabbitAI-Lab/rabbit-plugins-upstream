# 07 GDPR 与个保法对照

> 用途：回答「中欧两边要求怎么同时满足」。
> 核对基准日：2026-08-27

## 1. 对照表

| 维度 | GDPR | 中国个保法（PIPL） |
|---|---|---|
| 生效 | 2018-05-25 | 2021-11-01 |
| 域外管辖 | 向欧盟提供商品/服务或监控 | 在中国境外处理境内个人数据（向境内提供产品/服务或分析评估境内个人行为） |
| 合法基础 | 六项 | 同意/合同/法定/紧急/新闻报道等 |
| 同意 | 明确、自由、可撤回 | 单独同意（敏感信息）、可撤回 |
| 敏感/特殊数据 | 第 9 条特殊类别 | 敏感个人信息（健康/生物识别/金融等） |
| 权利 | 访问/更正/删除/可携/反对/限制 | 查阅/复制/更正/删除/可携（解释规则中） |
| DPIA | 第 35 条 DPIA | 个人信息保护影响评估（高风险场景） |
| 跨境传输 | 充分性/SCC/BCR/例外 | 安全评估/标准合同/认证（三路径，见医械数据出海合规） |
| 泄露通报 | 72 小时（监管）+ 高风险通知个人 | 立即补救 + 通知个人 + 向监管报告（及时） |
| 罚款 | 2000 万欧/4% 或 1000 万欧/2% | 违法处理最高 5000 万或上年度营业额 5% |

## 2. 同时满足策略

1. **取严执行**：两边都满足（如同意的"单独同意"两边都要）；
2. **同一套机制**：DPIA ≈ 个保影响评估（一套文档两用）；
3. **跨境传输双轨**：GDPR SCC + 中国出境路径都要走；
4. **文档共享**：登记处理活动（GDPR Art.30）≈ 个保处理记录。

## 3. 落地清单（出海欧洲）

- [ ] 适用范围判定（scope 命令 + 法律确认）
- [ ] 合法基础确定（legal 命令 + 同意机制改造）
- [ ] 隐私政策更新（中欧双版）
- [ ] 数据主体权利响应流程（rights 命令）
- [ ] DPIA（高风险场景，dpia 相关）
- [ ] 跨境传输机制（SCC + TIA，transfer 命令）
- [ ] 泄露响应预案（penalty 命令红线）
- [ ] 处理活动记录（Art.30）
- [ ] DPO 评估（必要时指定）
- [ ] 数据处理协议（与处理者签 DPA）

## 4. 常见坑

1. **只做一边**：只按 GDPR 或只按个保法 = 另一边违规；
2. **同意机制不兼容**：捆绑同意两边都无效；
3. **跨境只走一边**：SCC 不能替代中国出境路径（反之亦然）。

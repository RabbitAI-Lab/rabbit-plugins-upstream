# 04 DPIA 评估

> 用途：回答「什么时候做 DPIA」「怎么做」「报告结构」。
> 核对基准日：2026-08-27

## 1. 什么是 DPIA

**DPIA（Data Protection Impact Assessment，数据保护影响评估）**——高风险处理活动的事前评估（GDPR 第 35 条）。

## 2. 何时必须做

- **系统性大规模评估**（画像）对个人产生法律/重大影响；
- **大规模特殊类别数据**处理（健康数据——医械场景常见）；
- **大规模系统化监控公共区域**；
- 使用新技术处理且可能高风险（AI 处理个人数据常触发）；
- 监管机构清单列出的情形。

**判断**：用 `legal`/`dpia` 相关工具辅助初判——大规模 + 特殊类别 + 新技术 = 大概率要做。

## 3. 怎么做（流程）

1. 描述处理活动（目的/数据/范围/角色）；
2. 必要性评估（是否必需、是否最小化）；
3. 风险评估（数据主体权利与自由的风险：泄露/滥用/歧视）；
4. 缓解措施（技术+组织：加密、权限、匿名化、保留期）；
5. 剩余风险评估；
6. 咨询相关方（必要时咨询监管机构——高风险且无法缓解时）；
7. 文档化并持续评审。

## 4. 报告结构（模板）

```
一、处理活动描述（目的/范围/数据/角色）
二、必要性评估
三、风险识别与评估（数据主体视角）
四、缓解措施
五、剩余风险
六、结论与批准
```

## 5. 常见坑

1. **"做过了就完了"**：处理活动变化 → 重新评估；
2. **形式主义**：模板套话无实质评估 = 审计算违规；
3. **不做咨询**：高风险无法缓解须咨询监管机构；
4. **无记录**：DPIA 文档是问责制核心证据。

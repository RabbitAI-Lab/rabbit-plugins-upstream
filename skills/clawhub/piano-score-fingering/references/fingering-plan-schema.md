# Unified Fingering Plan

Scripts exchange one JSON plan. MusicXML supplies score semantics; notes carry both physical keyboard geometry for the solver and independent page geometry for overlays.


source.type normally identifies pdf, image, or musicxml; local OMR remains omr_candidate with explicit review-required handling. lookahead=0 uses bounded automatic depth, default four. Use --max-auto-depth 5–7 only for justified local candidates, or explicit lookahead=4–7.

recognition.delivery_level is complete, review, or partial. Formal visual generation requires all visual gates, zero unresolved notes, the full confidence_policy, and locked state. Older plans missing current evidence must be recompiled. Staff lines are listed visually top to bottom, regardless of coordinate direction. Use treble/bass clefs or explicit top_line_step/top_line_octave for other/transposing clefs.

Statuses progress draft → review → verified → locked. manage_recognition.py freeze creates sha256-score-facts over semantics, staff geometry, head/rest coordinates, crops, and independent counts. Fingerings and label layout are deliberately excluded. Score-fact changes invalidate the digest.

Source constructors record rendered_page assets per visual page and structured_score assets for MusicXML/MXL, with absolute path, byte count, and SHA-256. Generation, validation, and benchmarks rehash them. Rebuild plans/anchors when pages, resolution, or contents change.

review_queue entries use stable review_id, status=open|resolved, page, measure, hand, note_ids, and reason. Open items block locking. Group review tasks by page/measure/hand; high confidence does not waive independent recognition_passes, dense counts, same-position evidence, or tie evidence.

## Local recognition patch

```json
{
  "reason": "The source crop has five heads; remove the false sixth event",
  "scope": {"pages": [3], "measures": [52], "hands": ["RH"]},
  "operations": [
    {"op": "delete", "note_id": "p3-m52-rh-06"},
    {"op": "replace", "note_id": "p3-m52-rh-05",
     "changes": {"pitch_midi": 86, "pitch_step": "D", "pitch_octave": 6}}
  ],
  "recognition_changes": {"expected_note_count": 888, "unresolved_note_count": 0}
}
```

Scope must constrain at least page, measure, or hand. add/delete/replace are supported; replace preserves note_id. Semantic/structural/coordinate changes revoke relevant gates and require local confirmation.

event_count_checks supplies additional independent dense/problem-region counts. measure_scope, measure_regions, and measure_symbol_checks provide complete coverage, including zero-note rest measures. Every declared page/measure/hand needs one region and one independent check. Read the crop before recording expected counts; do not derive them from notes. build_measure_review_manifest.py leaves expected fields blank and exposes observed_plan_* only as comparison data.

Structured MusicXML requires pitch_spelling, rhythm, ties, and chords verification but no page geometry. Its constructor fills these states.

## Notes

```json
{
  "note_id": "P1-M12-S1-V1-T8-N64-C0",
  "part": "P1", "measure": "12", "measure_index": 12, "staff": 1, "voice": "1",
  "onset": 8.0, "duration": 2.0, "pitch_midi": 64,
  "pitch_step": "E", "pitch_alter": 0, "pitch_octave": 4,
  "event_index": 27, "chord_id": "P1-M12-T8-S1", "chord_row": 0, "chord_size": 1,
  "hand": "RH", "keyboard_x_cm": 86.42,
  "page": 2, "page_x": 620.5, "page_y": 418.2,
  "staff_geometry_id": "p1-system1-rh",
  "anchor_verified": true, "anchor_method": "visual_notehead",
  "pitch_geometry_verified": true, "symbol_class": "notehead",
  "notehead_shape_verified": true, "origin": "direct_visual_notehead",
  "chord_member_verified": true, "recognition_passes": 2,
  "same_position_verified": true, "tie_evidence": "visual_tie",
  "tie_group": null, "tie_start": false, "tie_stop": false,
  "finger": 3, "placement": "above", "locked": false, "source": "generated"
}
```

Optional confidence is 0–1 with review_reason. Uncertainty in pitch, clef, accidental, hand, chord membership, or tie semantics blocks formal generation. Cosmetic uncertainty may remain in review output.

recognition_passes counts independent observations, not repeated runs of the same detector. Close same-y notes require same_position_verified=true to distinguish repeated/tied notes from effective accidental changes. Use visual_tie or visual_slur for tie evidence; structured sources can use source_semantic.

For visual notes, verify an open/filled ellipse rather than a rest/stem/beam/barline/dot. Sparse measures at or below sparse_event_threshold require sparse_symbol_verified=true. origin=direct_visual_notehead denotes an actually located head. Each chord member needs its own coordinates and chord_member_verified=true; declared chord_size must equal evidenced membership.

## Rests and chord labels

```json
{
  "rest_id": "p2-m35-rh-rest-0", "page": 2, "measure_index": 35, "hand": "RH",
  "page_x": 816.0, "page_y": 241.0, "rest_type": "whole", "duration": 6.0,
  "symbol_class": "rest", "rest_shape_verified": true
}
```

Rests stay in rests. Use explicit whole/half/quarter/eighth types and the plan's beat unit. A rest-only bar needs an actual rest record, not merely an empty notes list.

Chord digits default to stacked. Members share chord_label_x, chord_label_offset, and chord_label_layout=stacked. chord_row orders digits bottom to top with ascending pitch. Offsets use the input page coordinate unit and scale with output.

## Coordinates and identity

- keyboard_x_cm is physical keyboard position for solving only; calculate with bundled keypos_midi from MIDI.
- page_x/page_y are head centers for overlays only.
- pdf_point uses bottom-left origin; pixel_top_left uses top-left.
- MusicXML has no original-page anchors; source PDF/images are needed for preserved-layout output.
- Visual notes require page/page_x/page_y; staff estimates cannot replace head centers.
- anchor_verified follows direct crop confirmation. anchor_method may be visual_notehead, detected_notehead, or layout_source.
- pitch_geometry_verified follows agreement between page_y, lines, clef, and spelling; validation recalculates it.
- Proportional projections/copies are search hints, never verified evidence.
- Keyboard positions strictly increase through semitones and octave boundaries.

Prefer source element IDs where available; otherwise derive stable note_id from part, measure_index, staff, voice, onset, pitch_midi, and chord_row. A local ordinal alone is unstable across voices/chords/grace notes.

source=existing normally locks the finger; generated means solver output; reviewed means a musical correction with exception_reason. Unusual crossings/substitutions/accompaniment deviations need rule_id and exception_verified=true after review. Generated explanations cannot self-verify. Preserve locked=true unless the user explicitly requests ignoring existing fingers.

# 05 SBOM 实操

> 用途：回答「SBOM 怎么建」「字段」「格式」「更新」。
> 核对基准日：2026-08-27

## 1. 什么是 SBOM

**SBOM（Software Bill of Materials，软件物料清单）**：列出产品中所有软件组件及其版本、供应商、依赖关系的清单——供应链透明度基础，FDA 2026 起联网器械强制。

## 2. 核心字段（工具 `sbom` 命令生成模板）

| 字段 | 说明 |
|---|---|
| 组件名 | 组件名称 |
| 版本 | 精确版本号 |
| 供应商 | 组件供应商 |
| 依赖关系 | 组件依赖的其他组件 |
| 许可证 | 组件许可证（合规） |
| 哈希 | 组件完整性哈希 |
| 来源 | 来源/下载地址 |
| 漏洞关联 | 关联的已知漏洞（CVE） |

## 3. 格式（二选一）

- **SPDX**：Linux 基金会标准，人类可读
- **CycloneDX**：OWASP 生态，漏洞关联强（推荐）

## 4. 构建流程

1. 收集所有软件组件（直接 + 间接依赖）；
2. 自动生成 SBOM（构建工具集成）或手工维护；
3. 审查许可证与来源合规；
4. 关联漏洞库（持续扫描）；
5. 版本更新时同步更新 SBOM；
6. 随注册申报提交 + 供应链共享。

## 5. 维护要点

- **持续更新**：每个软件版本变更 → SBOM 更新；
- **漏洞联动**：SBOM 与漏洞扫描联动（组件漏洞 → 通知修复）；
- **供应链共享**：上游组件 SBOM 纳入（第三方组件供应链）；
- **审计留存**：SBOM 版本历史（追溯）。

## 6. 常见坑

1. **只列直接依赖**：漏间接依赖 = 漏洞面盲区；
2. **版本不精确**："latest" 无意义，须锁定精确版本；
3. **不做漏洞联动**：SBOM 是静态清单，不扫漏洞等于白建；
4. **更新滞后**：版本更新后 SBOM 没同步 = 申报/审计出问题。

# 06 漏洞管理与协调披露

> 用途：回答「漏洞怎么分级」「修复时限」「协调披露流程」。
> 核对基准日：2026-08-27

## 1. 漏洞分级（CVSS 风格，工具 `vuln` 命令）

| 等级 | CVSS 分 | 特征 | 修复时限 |
|---|---|---|---|
| 严重 | 9.0-10.0 | 远程可执行任意代码/完全控制 | 立即 |
| 高 | 7.0-8.9 | 远程可利用、重大影响 | 30 天 |
| 中 | 4.0-6.9 | 有条件利用/有限影响 | 90 天 |
| 低 | 0.1-3.9 | 影响小 | 180 天 |

## 2. 漏洞管理闭环

```
发现（内部测试/外部报告/供应链通告）
   → 验证与复现
   → 分级（CVSS）
   → 修复（补丁/缓解）
   → 发布（补丁分发）
   → 通报（协调披露）
   → 归档（审计）
```

## 3. 协调披露流程（Coordinated Disclosure）

1. **受理**：设立安全联系渠道（邮箱/表单），公开披露政策；
2. **验证**：确认漏洞真实性（白帽复现）；
3. **分级**：CVSS 评估影响；
4. **修复**：开发补丁（与披露者沟通时限）；
5. **发布**：补丁发布 + 安全公告（CVE 编号）；
6. **通知**：通知受影响的医疗机构/客户；
7. **公开**：修复后公开披露（感谢研究者）。

## 4. 监管衔接

- 美国：FDA 漏洞披露框架（上市后监测 + 协调披露）；
- 欧盟：CRA 协调披露义务（向 ENISA/CSIRT 报告）；
- 中国：网络安全漏洞管理规定（发现即报告义务）。

## 5. 常见坑

1. **没有安全联系渠道**：外部研究者无处报告 = 漏洞被私下利用；
2. **隐瞒不报**：监管要求披露义务，隐瞒 = 违规；
3. **无修复时限管理**：漏洞躺平 = 风险敞口扩大；
4. **补丁无验证**：补丁引入新问题（回归）。

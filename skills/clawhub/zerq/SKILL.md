# ZerQ · 归零（ZeroQ）

> 版本说明：本包为 `zerq` 名称预留版（v0.0.1），用于锁定命名。完整版（v1.0.x，含四层级架构、场景路由、组件池机制）即将发布。本版已可用于基础双归零分析。

## 做什么

面向质量问题解决的「双归零」归因方法论，源自航天系统工程，与 8D / 5Why / FTA / FMEA 等方法相通。

## 何时使用

- 质量缺陷、客户投诉、失效问题需要根因归因
- 编写归零报告、纠正措施计划、8D 报告
- 需要区分「技术原因」与「管理原因」
- 措施有效性验证与举一反三

## 双归零框架

### 技术归零（五条要求）

1. **定位准确**：以试验/数据锁定问题发生部位与触发条件，避免笼统归因
2. **机理清楚**：从现象深入到物理/化学/逻辑机理，讲清因果链
3. **问题复现**：能在试验或模拟中稳定复现，验证定位与机理
4. **措施有效**：纠正措施经验证确实消除根因，并有数据支撑
5. **举一反三**：排查同类设计/工艺/产品，防止重复发生

### 管理归零（五条要求）

1. **过程清楚**：还原事件全过程与关键节点
2. **责任明确**：按流程节点界定责任，不泛化不甩锅
3. **措施落实**：管理措施有责任人、期限、可检查
4. **严肃处理**：按规章对责任主体处理并记录
5. **完善规章**：把教训固化为制度/标准/检查单

## 使用方式

按问题特征引导输出：先做技术归零（现象→定位→机理→复现→措施→举一反三），再做管理归零（过程→责任→落实→处理→规章），最后给出验证标准与防再发清单。

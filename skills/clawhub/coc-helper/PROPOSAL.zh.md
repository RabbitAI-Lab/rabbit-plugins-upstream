# 提案：`coc-helper` Skill（v0.1 — 原始草案）

> 状态说明（v1.0）：本文件为**原始设计提案**，保留以供历史参考。当前实现可能与此有差异；权威的 v1.0 描述见 [SKILL.zh.md](./SKILL.zh.md)。重要差异以 **[v1.0 差异]** 标注。

一个《克苏鲁的呼唤》第 7 版（COC 7e）掷骰与守秘人（KP）助手 skill，用于跑 COC 桌面团。

---

## 1. 动机 & 设计目标

一个轻量、离线优先的《克苏鲁的呼唤》第 7 版（COC 7e）掷骰与守秘人（KP）助手，用于跑桌面团。本 skill 围绕以下目标设计：

| 目标     | `coc-helper` 的实现方式                                                                |
| -------- | -------------------------------------------------------------------------------------- |
| 规则系统 | COC 7e（d100 检定值以下，成功等级，奖励/惩罚骰，SAN 链）                               |
| 随机源   | `node cli.mjs ...` 辅助脚本，通过 `--seed` 实现**确定性 + 可加种子**                   |
| 外部依赖 | **零网络依赖** — 所有数据内置                                                          |
| 状态     | **会话状态**（调查员、SAN、HP、MP、幸运值、规则）持久化到 JSON                         |
| 输出格式 | 文本 **和** `--json`，便于程序化串联                                                   |
| 表格     | 可投表格（恐惧症、躁狂症、职业技能、人名、钩子）                                       |
| 模块化   | 模块化：`dice.mjs`、`investigator.mjs`、`tables.mjs`、`sanity.mjs`、`rules-config.mjs` |

### 核心设计原则

1. **离线优先。** 所有数据打包在内，断网也能用 — 不依赖任何可能被限流、下线或变更 schema 的外部 API。
2. **可复现掷骰。** `--seed <n>` 标志用于可验证/可分享的掷骰（对 PbP 帖吧跑团和争议裁决很有用）。
3. **有状态会话。** 跨命令追踪多名调查员 — SAN、HP、MP、幸运值、当前技能等级 — 而不是把每次掷骰都当作孤立的。
4. **系统专属机制内嵌。** 奖励骰/惩罚骰、大成功/极难/困难/普通/失败/大失败等级、对抗检定、推检定、SAN 损失链 — 不只是"投 XdY"。
5. **更小、可测试的代码面。** 每条命令都是对 JSON 的纯函数；好做单元测试、好扩展（例如 Pulp Cthulhu 开关）。
6. **规则可配置。** 大成功/大失败范围、SAN 阈值等可按会话自定义，并提供预设 `strict` / `lenient` 变体。

## 2. 功能集

> [v1.0 差异] 子命令语法与本草案不同。已上线的 CLI 使用 `roll opposed`、`roll push`、`roll luck <name>` 作为独立子命令，而不是 `--opposed` / `--push` / `--luck` 标志。`--secret` 仅 KP 暗投和 `--luck <amount>` 花幸运压值**未实现**（仅支持幕间 `luck-gain` 恢复）。`inv update <field>=<value>` **未实现**。`loom` 场景生成器改名为 `table hook`。

### 2.1 掷骰（核心）

- `roll 1d100` — 对目标值做百分位检定
- `roll 3d6*5` — 属性掷骰（COC 7e 惯例）
- `roll 2d6+3` — 通用多面骰
- 提供目标值时自动判成功等级：**大成功（01）/ 极难（⅕）/ 困难（½）/ 普通 / 失败 / 大失败**
- `--bonus N` / `--penalty N` — 投额外十位骰，取有利 / 取不利（1 或 2 颗）
- `roll opposed <a> <b>` — 对抗检定（成功等级高者胜；平局 → 目标值高者胜）
- `roll push <spec> --target N` — 推检定（失败重投；不可用于幸运、理智、战斗、伤害骰）
- `roll luck <name>` — 幸运检定（目标 = 调查员的 luck 值）
- [v1.0 差异] `--secret` — **未实现**

### 2.2 理智（SAN）

- `san check <name> <loss>` — 对当前 SAN 投 d100，计算 SAN 损失、扣血、标记可能发疯
  - [v1.0] `<loss>` 支持 `X/Y` 表达式（成功损失 X / 失败损失 Y），如 `1/1d4`、`0/1d6`、`1d10/1d100`
- `san gain <name>` — 团末恢复 d10
- `san private <name> [--psy N]` — 私人/家庭护理
- `san institution <name>` — 收容机构护理
- `san threshold <name>` — 显示当前 SAN、发疯阈值
- [v1.0] 临时性疯狂触发条件：单次损失 ≥ `tempInsanityThreshold`（默认 5）**且** INT 检定失败；持续 **1D10 小时**（不是轮）。INT 检定成功则抑制记忆，不进入疯狂。
- [v1.0] 不定性疯狂触发条件：单次损失 ≥ `indefiniteInsanitySingleLoss`（默认 20）**或** 一天内累计损失 ≥ 当前 SAN 的 1/5。
- [v1.0] 永久性疯狂：SAN 降至 0。

### 2.3 调查员（有状态）

- `inv create --name X --age N [--occupation Y] [--pulp]` — 引导式 7e 角色创建
- `inv list` — 列出所有追踪中的调查员
- `inv show <name>` — 完整人物卡
- `inv damage <name> <N>` — 结算伤害，追踪 HP / 重伤 / 濒死
- `inv heal <name> <N>` — 治疗 HP
- `inv delete <name>` — 删除
- `inv derive --str N ...` — 仅计算衍生属性
- [v1.0] `inv growth <name> <skill>...` — 幕间技能成长
- [v1.0] `inv luck-gain <name>` — 幕间幸运增强
- [v1.0 差异] `inv update <field>=<value>` — **未实现**
- 状态文件：`.trae/skills/coc-helper/session.json`

### 2.4 KP 辅助

- `table name [--male|--female] [--zh|--en]` — 随机人名
- `table npc [--zh|--en]` — 快速 NPC，带职业与神态
- `table phobia` / `table mania` / `table occupations` / `table weapons [name]` — 7e 可投表格
- `table madness [--summary]` — 疯狂发作表
- `table hook` — 即时场景 / 钩子提示生成器（不调用 AI — 内置带种子的短语表）
- `combat init name1:DEX ...` — 战斗先攻列表（按 DEX）
- `combat chase name1:MOV ...` — 追逐战先攻顺序（按 MOV）

### 2.5 规则配置（v1.0 新增）

- `config show` / `config defaults` / `config reset`
- `config variant [strict|lenient]` — 预设规则变体
- `config set <key> <value>` — 自定义：
  - `criticalRange`（如 `1` 或 `1-5`）
  - `fumbleRange`（如 `100`、`96-100` 或 `auto`）
  - `tempInsanityThreshold`（默认 5）
  - `indefiniteInsanitySingleLoss`（默认 20）
  - `indefiniteInsanityDailyFraction`（默认 0.2）

### 2.6 输出

- 默认人类可读
- 每条命令支持 `--json`，便于串联 / 程序化使用
- `--quiet` 简洁内联输出（只显示总数）

## 3. 架构

```
.trae/skills/coc-helper/
├── SKILL.md              # 英文版入口（v1.0，Trae skill 加载点）
├── SKILL.zh.md           # 中文版 v1.0 实现说明
├── PROPOSAL.md           # 英文提案（v0.1 原始草案）
├── PROPOSAL.zh.md        # 本中文提案（v0.1 原始草案）
├── lib/
│   ├── dice.mjs          # 纯掷骰 + COC 成功等级逻辑
│   ├── investigator.mjs  # 对 session.json 做状态 CRUD
│   ├── sanity.mjs        # SAN 检定链 & 发疯表
│   ├── tables.mjs        # 内置数据：人名、职业、恐惧症、躁狂症、钩子
│   └── rules-config.mjs  # 规则配置系统（v1.0 新增）
├── cli.mjs               # argv 解析，分发到 lib/*
└── session.json          # 首次有状态命令时自动创建（gitignored）
```

- **语言：** Node.js（ESM，零 npm 依赖 — 只用 `node:crypto` 做随机）。契合当前 JS 风格的工作区，避免引入 Python 工具链假设。
- **随机数：** `crypto.randomInt` 提供加密级随机；`--seed` 切换到确定性 PRNG（mulberry32）实现可复现。
- **状态：** 单一 JSON 文件，通过 `fs.rename` 写临时文件做原子写入。
- **Skill 接口：** `SKILL.md` 告诉 agent 调用 `node <skill-dir>/cli.mjs <args>`，agent 负责把结果格式化给用户。

## 4. SKILL.md 触发示例

用户说类似下面这些话时，agent 应当调用 `coc-helper`：

- "给 Anna 投个 SAN 检定，她现在 SAN 65，损失 1/1d4"
- "1d100 对 60，加个惩罚骰"
- "创建一个新 COC 调查员"
- "对抗检定：Anna 侦查 55 vs 邪教徒 40"
- "推检定"
- "给我一个随机 1920s NPC"
- "切换到宽松规则：大成功 1-5，大失败 96-100"

非触发场景：通用掷骰（无 COC 上下文的 `roll 2d6`）— 由 agent 内联处理，除非用户明确要求 `coc-helper`。

## 5. 实施分期

1. **Phase 1 — 骰子核心。** `dice.mjs` + `cli.mjs` 支持 `roll`、成功等级、奖励/惩罚骰、`--json`、`--seed`。无状态。
2. **Phase 2 — 理智。** `sanity.mjs` 实现 SAN 检定链逻辑和发疯标记。
3. **Phase 3 — 调查员。** `investigator.mjs` 实现 create/list/show/damage/heal 和 `session.json` 持久化。
4. **Phase 4 — 表格 & KP 辅助。** `tables.mjs` 内置人名、职业、恐惧症、躁狂症、钩子；`chase init` / `combat init`。
5. **Phase 5 — SKILL.md + 打磨。** Frontmatter、调用指南、示例、错误提示。
6. **Phase 6 — 规则配置（v1.0）。** `rules-config.mjs` 实现默认值、预设变体、持久化自定义。

每一期都交付一个可运行的 CLI；不会有"被未来某一期挡住"的功能。

## 6. 已确定决策

1. **版本：** COC 7e + Pulp Cthulhu 开关（`--pulp` 标志，以及 `session.json` 中 `pulp: true`）。不做 6e。
2. **时代背景：** 1920s 经典 — 默认表格使用 1920s 的人名/职业/钩子。与现代/Pulp 相关的表在 pulp 标志后追加。
3. **随机数：** 默认 `node:crypto.randomInt`；`--seed <n>` 切换到带种子的 mulberry32 PRNG 做可复现掷骰。
4. **运行时：** Node.js ESM，零 npm 依赖。
5. **状态位置：** `.trae/skills/coc-helper/session.json`（skill 本地，gitignored）。
6. **Skill 名字：** `coc-helper`（v1.0 从 `coc-keeper` 改名，更准确反映"助手"而非"看守"的角色定位）。
7. **[v1.0] 大成功/大失败范围：** 用户可配置；默认 `strict` = 大成功 1，大失败 auto（目标<50 时 96-100，否则 100）；`lenient` = 大成功 1-5，大失败 96-100。

### Pulp Cthulhu 追加内容（Phase 4）— [v1.0：部分实现]

- [v1.0：已实现] `--pulp` 翻倍 HP（HP = (SIZ + CON) / 5 而不是 /10）
- [v1.0：未实现] 英雄点、双持战斗、pulp-archetype 表

### 7.2 衍生属性

- **HP** = (CON + SIZ) / 10 向下取整，最低 1（Pulp：/5）
- **MP** = POW / 5 向下取整
- **SAN**（初始）= POW；SAN（上限）= 99 − 克苏鲁神话技能
- **闪避**（初始）= DEX / 2 向下取整
- **母语**（初始）= EDU
- **兴趣技能点** = INT × 2
- **伤害加值（DB）& 体格（Build）**（按 STR+SIZ 查表）：

  | STR+SIZ        | DB   | 体格 |
  | -------------- | ---- | ---- |
  | 2–64           | −2   | −2   |
  | 65–84          | −1   | −1   |
  | 85–124         | 0    | 0    |
  | 125–164        | +1d4 | 1    |
  | 165–204        | +1d6 | 2    |
  | 205–244        | +2d6 | 3    |
  | 245–284        | +3d6 | 4    |
  | 285–324        | +4d6 | 5    |
  | 325–364        | +5d6 | 6    |
  | …（每 +40 一档 | +1d6 | +1   |

- **MOV**（1920s/现代人类基数为 9）：
  - STR 和 DEX 都 > SIZ → MOV +1
  - STR 和 DEX 都 ≤ SIZ → MOV −1
  - 年龄减值：40+ → −1，50+ → −2，60+ → −3，70+ → −4，80+ → −5（自动计算）

### 7.4 成功等级（COC 7e d100 检定值以下）

| 结果（d100）                               | 等级     |
| ------------------------------------------ | -------- |
| ≤ 目标值 × 1/5                             | 极难成功 |
| ≤ 目标值 × 1/2                             | 困难成功 |
| ≤ 目标值                                   | 普通成功 |
| > 目标值                                   | 失败     |
| 大成功范围（默认 1；lenient 下 1-5）       | 大成功   |
| 大失败范围（默认 auto；lenient 下 96-100） | 大失败   |

> [v1.0] 大成功/大失败范围优先：当掷值落在 Critical/Fumble 范围时优先判定，即使越过目标值。

### 7.5 理智（SAN）规则

- SAN 检定：投 d100 vs 当前 SAN。损失值由创伤源（怪物/法术/场景）决定，以 `X/Y` 表达（成功损失 / 失败损失）。
- 单次 SAN 损失 ≥ `tempInsanityThreshold`（默认 5）→ 触发 INT 检定：
  - 成功 → 抑制记忆，不进入疯狂
  - 失败 → 临时性疯狂发作，持续 **1D10 小时**
- 单次 SAN 损失 ≥ `indefiniteInsanitySingleLoss`（默认 20）→ 不定性疯狂。
- 一天内累计 SAN 损失 ≥ 当前 SAN 的 1/5 → 不定性疯狂。
- SAN 降至 0 → 永久性疯狂。
- **SAN 恢复：**
  - 私人/家庭护理（每月投 d100）：01–95（或低于精神分析技能）→ 恢复 1d3 SAN + 理智检定通过则脱离疯狂；96–00 → 损失 1d6 SAN。
  - 收容机构治疗（每月投 d100）：01–50 → 恢复 3 SAN + 理智检定通过则脱离；51–95 → 无效；96–00 → 损失 1d6 SAN。
- **幕间 SAN 增长：** 团末若有任何技能达到 90+，恢复 2d6 SAN（不超过 SAN 上限）。

### 7.6 奖励骰 & 惩罚骰

- 投两个十位骰（00, 10, …, 90）和一个个位骰。
- **奖励骰：** 取较小的十位值。
- **惩罚骰：** 取较大的十位值。
- 个位骰共用。
- [v1.0] 支持 1 或 2 颗奖励/惩罚骰（`--bonus 2` / `--penalty 2`）。

### 7.7 对抗检定

- 双方各投 d100 vs 自己的目标值。
- 成功等级高者胜（大成功 > 极难 > 困难 > 普通）。
- 成功等级相同 → 投出数值高者胜（即投得更高但仍然成功）。
- 对抗检定不能推。

### 7.8 推检定

- 检定失败后可推一次：对同一目标值重投 d100。
- 不能推战斗检定、SAN 检定、对抗检定（7e RAW）。
- 推失败后果升级（由 KP 决定）。

### 7.9 幸运

- [v1.0] `roll luck <name>` — 投 d100 vs 调查员的幸运值作为目标。
- [v1.0] `inv luck-gain <name>` — 幕间幸运增强（1d100 > 当前幸运 → +1d10，上限 99）。
- [v1.0 差异] `--luck <amount>` 花幸运压值 — **未实现**。
- 幸运池恢复由 KP 决定。

# 面试准备手册

## 一、核心思路：从简历反推考点

面试官手上的问题 80% 来自你的简历。准备面试时，不要只背面经，而要：

1. 逐条审视简历中的每段经历。
2. 对每段经历，列出 5-10 个可能被深挖的问题。
3. 对每个问题，准备简洁、真实、有结构的回答。

## 二、自我介绍框架

自我介绍是面试的定调环节。准备两个版本：

### 1 分钟版（初面/群面）

```
姓名 + 学校/背景 + 应聘岗位
↓
2-3 个核心优势标签（与岗位匹配）
↓
1 个最有代表性的经历证据（一句话 STAR）
↓
应聘动机 / 期待
```

### 3 分钟版（单面/主管面）

```
姓名 + 学校/背景 + 应聘岗位
↓
3 个核心优势标签
↓
2 个代表性经历（每个用 STAR 简要讲）
↓
为什么选这个公司/岗位
↓
职业规划或期待
```

### 自我介绍注意事项

- 不要复述简历，要提炼标签。
- 每一句话都要能被面试官接着问。
- 结尾留钩子，引导面试官问你准备好的问题。
- 控制语速，1 分钟版约 150-180 字，3 分钟版约 400-500 字。

## 三、项目深挖问题清单

对简历中的每个项目/实习，准备以下问题：

### 背景类

- 为什么做这个项目？
- 项目的目标用户是谁？解决了什么问题？
- 当时有哪些可选方案？为什么选这个方案？

### 执行类

- 你在项目中具体负责什么？
- 最难的点是什么？怎么解决的？
- 如果重新做，你会怎么优化？

### 结果类

- 项目的关键指标是什么？结果如何？
- 数据是怎么采集/验证的？
- 项目的局限性是什么？

### 协作类

- 团队有几个人？如何分工？
- 有没有冲突？怎么处理的？
- 你是怎么向上汇报/推动事情的？

## 四、能力验证问题

面试官会针对岗位 JD 中的核心能力提问。准备时用「经历证据」回答，不要只说"我会"。

| 能力项 | 问题示例 | 回答策略 |
|---|---|---|
| 用户研究 | "你怎么做用户调研的？" | 讲具体方法、样本量、洞察、落地 |
| 数据分析 | "你怎么分析数据的？" | 讲工具、维度、结论、影响 |
| 产品思维 | "如果你来做 XX 功能，会怎么做？" | 讲用户、场景、优先级、验证 |
| 项目管理 | "怎么保证项目按时交付？" | 讲拆解、风险、沟通、复盘 |
| 跨部门协作 | "遇到不配合的部门怎么办？" | 讲目标对齐、利益交换、升级机制 |

## 五、行为面（BQ）题库

行为面考察软技能和价值观。用 STAR 准备 5-8 个通用故事：

- 最有成就感的事
- 最大的失败/挫折
- 团队协作冲突
- 高压场景下的表现
- 学习新技能的经历
- 解决复杂问题的经历
- 领导/推动项目的经历
- 创新与改变的经历

## 六、简历风险地图

简历中凡是"翻译"过的表述，都是面试雷区。重点标记：

| 风险类型 | 示例 | 应对策略 |
|---|---|---|
| 能力迁移过度 | 把"发传单"写成"渠道拓展" | 准备时回归真实经历，用"负责""协助"等准确动词 |
| 数据来源不清 | 写"提升 30%"但记不清基数 | 补充真实背景，或改为相对性描述 |
| 跨专业/转行动机 | 文科转 AI 产品 | 准备清晰可信的转型故事 |
| 经历之间逻辑不一致 | 多个项目方向跳跃 | 准备统一的能力主线 |
| 岗位关键词不匹配 | JD 要求 A/B 测试但简历没写 | 诚实说明相关经验或学习过程 |

## 七、逐题话术格式

推荐为每个高频问题准备：

```markdown
### 问题：...

**考点**：...

**回答框架**：
1. ...
2. ...
3. ...

**推荐话术**：
...

**避坑提示**：
- ...
```

## 八、面试前最后检查

- [ ] 自我介绍能脱稿流畅说两遍
- [ ] 简历上每个数字、每个项目都能讲清楚来源
- [ ] 目标公司近 3 个月有了解
- [ ] 准备 2-3 个反问面试官的问题
- [ ] 衣着、设备、网络测试完成

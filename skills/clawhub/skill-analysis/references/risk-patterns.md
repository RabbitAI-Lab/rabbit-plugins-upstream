# 风险分级与复核口径参考

本文档是 `skill-analysis` 报告的**解读参考**：解释每级风险的含义与处置建议，帮助使用者理解报告结论并给出复核口径；维护与扩展请以引擎代码和规则包（`rules/`）为准。

## 风险分级

| 级别 | 含义 | 处置建议 |
|------|------|----------|
| P0 | 严重：可直接导致任意代码执行、数据不可逆损毁、凭据泄露或拒绝服务 | 禁止直接使用，必须人工隔离复核 |
| P1 | 高：命令注入、反序列化、递归删除等高危操作 | 使用前确认必要性并审查上下文 |
| P2 | 中：环境变更、权限提升、疑似硬编码凭据等 | 留意并确认是否符合预期 |
| P3 | 低：信息性线索（写文件、遥测关键词、未扫描的二进制素材） | 记录备查，通常无害 |

## 准入卡点

- 🔴 **BLOCK**：存在 P0 级命中或明确恶意意图 → 不建议安装/使用。
- 🟠 **NEED_REVIEW**：存在 P1 级命中 → 需人工确认。
- 🟡 **REVIEW**：无明确恶意但拥有敏感能力（P2 或能力画像）→ 信任来源且权限合理可继续。
- 🟢 **PASS**：未检出高危及命中。

判定档位由策略引擎（`config/policy.json` 三档：standard/strict/paranoid，`block_at` / `review_at` / `network_upload`）与信任注册表（`config/trust.json`：白名单 / 黑名单 / 按名覆盖）共同决定；`--policy` / `--trust` 可指定外部配置。

## 复核口径

- **仅静态分析**：本工具只读取文件、绝不执行代码；结论基于当前版本的静态扫描，无法覆盖未来更新可能引入的风险。
- **聚焦恶意行为**：权限滥用、隐私访问、高危操作、硬编码密钥为重点；文档举例与测试脚手架不计入定级。
- **能力 vs 滥用**：区分"Skill 能做危险的事"与"Skill 正以有害/无依据的方式使用该能力"。敏感能力确属声明功能、有文档且限定在用户配置的目标时，标注为 sensitive 而非 malicious。
- **输出通俗格式**：📍 位置 · 📝 片段 · ⚡ 原因 · 🎯 影响范围 · 💡 建议，便于非技术用户理解。
- **不确定行为**：上传/网络等不确定行为明确标注"需人工确认"，不替用户下安全定论。
- **组合攻击与来源信誉**：污点链 / 混淆载荷 / 来源信誉类命中，需人工复核意图与来源可信度后再做准入决定。

## 防误报保证

文档语境豁免 + 扫描器自身内容自排除（源码 / 说明 / 规则包 / 配置 / 根级文档 / 自检脚本）+ 规则包 SHA-256 校验（被篡改自动回退内置默认）+ 每次发版强制自扫回归。

## 回归基线

- 自扫描：🟢 低风险 / 准入 PASS（无 P0/P1 信号）。
- 恶意样例：🔴 BLOCK，且 P0 级命中 ≥ 1。
- 发布门禁：`python scripts/selfcheck.py` 三项全 PASS。

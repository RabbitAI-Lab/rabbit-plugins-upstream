# 静态分析局限性说明（v3.3.2）

> 本文档说明 **skill-analysis（安全审计专家）** 的能力边界。目的是让使用者**正确解读审计结论**——
> 报告里的「PASS」表示「未发现已知形态的可疑证据」，**不等于**「该 Skill 一定安全」。

## 0. 一句话结论

本 Skill 是**静态优先、可选动态取证**的审计器：
- 对**明文可读**的危险模式（危险原语、外传链路、凭据读取、提示注入、混淆特征、已知指纹）可给出**高置信**结论；
- 对**运行时才成形**的威胁（动态解密、条件触发、网络下发的载荷、多态代码），只能给出**「可疑 / 建议复核」**信号，**无法给出可靠结论**。

## 1. 能力边界速查

| 能力 | 覆盖度 | 说明 |
|---|---|---|
| 明文危险模式 | ✅ 高 | 命令执行 / 网络外传 / 凭据读取 / 持久化 / 破坏性操作等 |
| 提示注入与越权指令 | ✅ 中高 | 系统消息冒充、强制指令、越狱话术、**外部指令引用（OWASP AST05）**、**上下文特权提升话术** |
| 混淆与编码载荷 | ✅ 中 | 混淆特征识别（pyarmor / terser / XOR 字符串表 / guard 注入 / Base85 / 隐藏导入）、多层编码解码后判定、**同形字归一化重扫** |
| 污点 / 数据流 | ✅ 中高 | ① 单行正则层（同语句源+汇）；② **AST 级跨语句 source→sink 证据链**（仅 `.py`，见 §2.4） |
| 已知恶意指纹 | ✅ 中高 | SHA-256 文件级 + **命名指纹**（仅覆盖已知样本，新样本必然漏检） |
| 供应链 / 安装钩子 | ✅ 中 | VCS 直装、全局安装、**生命周期钩子配置绑定命令（HookPry）**、依赖源重定向、typosquat |
| 图片元数据注入 | ✅ 中 | 仅解析常见容器格式的文本型元数据段 |
| GitHub/补丁历史溯源 | ⚠️ 受限 | 依赖本机 `git` 可用性与仓库完整性 |
| OSV 依赖漏洞 | ⚠️ 需联网 | `--osv` **默认关闭**；启用后查询 osv.dev，无网络时不可用 |
| 运行时行为取证 | ⚠️ 可选且非硬隔离 | `--dynamic`，见 §3 第 3 层 |
| 来源信誉 | ⚠️ 本地合成 | 基于本地信号合成，**不联网查询星标/维护活跃度** |

## 2. 静态分析**无法**可靠检测的威胁

> 以下为**所有静态分析工具的本质局限**，本工具不例外。表中同时标注本工具**已做的部分缓解**——
> 请注意「部分缓解」≠「可靠检测」。

### 2.1 高级混淆与编译

| 威胁类型 | 为什么检测不到 | 本工具的缓解程度 |
|---|---|---|
| **商业级编译混淆** | 源码已不存在，只剩加密/编译后的字节码；静态分析只能确认「文件被混淆」这一事实 | 仅标记「该文件已被混淆，真实行为无法静态确认」（P1/P2 提示） |
| **自定义 VM 混淆** | 字节码由自实现解释器执行，不直接调用系统 API；无法穿透 VM 抽象层 | 仅识别 VM 特征（如解释器骨架/字节码表），**无法还原语义** |
| **时序分散注入** | 载荷被切分到多个文件/注释/字符串，运行时拼接 | AST 污点仅覆盖**单文件内**赋值链；**跨文件拼接**依赖启发式拼接取证，仍有漏检 |
| **反射 / 动态导入** | 模块名运行时才解出，静态不可知 | 仅对「明显由编码块推导出的导入」给出混淆告警 |
| **自实现密码学 / 加密载荷** | 检出算法特征，但**无法解密内容** | 报告「存在加密文件/自实现加密」，不报告其内容 |

### 2.2 运行时行为

| 威胁类型 | 为什么检测不到 | 本工具的缓解程度 |
|---|---|---|
| **运行时动态解密后执行** | 载荷在运行时才成形（常来自网络或本地加密文件） | 静态只能标记「解码→动态执行」组合可疑；**内容不可知** |
| **条件触发** | 触发条件在目标机器上才成立（环境变量/时间/主机名/调试器/argv 门控） | 新增**触发条件与危险原语共现**检测（标记 P1/P2），但**无法证明**运行时是否真的触发 |
| **网络下发载荷** | 静态扫描时载荷尚未存在 | `--dynamic` 开启时可在隔离环境观察**是否发起网络请求**，但默认断网/降级模式下**不获取远端内容** |
| **多态 / 自变异代码** | 每次运行改变自身形态，固定指纹必然失效 | 只能靠行为特征（动态层）与启发式，**检出率不保证** |
| **休眠 / 延时投毒** | 恶意行为在安装后很长时间才生效（rug-pull） | 静态只能在「指向外部可变资源」时给出 AST05 提示，无法预知资源后续被替换 |

### 2.3 隐写与侧信道

| 威胁类型 | 为什么检测不到 |
|---|---|
| **图片/音频 LSB 隐写** | 载荷分布在像素/采样点最低位，文本层与常见元数据段中不存在可读线索；需图像分析/差分比对，非本工具范围 |
| **二进制隐写** | 载荷藏于二进制资源、填充区、未使用字段；静态文本分析不可达 |
| **加密/压缩容器** | 只能确认容器存在，无法判断内部内容是否恶意 |
| **低带宽侧信道**（时序、文件存在性、DNS 查询、进程名、日志/临时文件） | 不改变文件内容、不呈现可匹配的文本特征；**静态分析在原理上不可见**，需运行时流量与系统调用级观测 |
| **编码型隐写（零宽字符、双向控制符、标签字符、同形字替换）** | ⚠️ **本工具的强项**：通过**归一化重扫**识别——但这是「与攻击者的编码技巧赛跑」，新编码手法存在**窗口期** |

### 2.4 AST 污点追踪自身的边界（v3.3.2 新增能力，务必知悉）

- **仅覆盖合法 Python 源码**：语法错误的文件直接跳过（交回正则层）；动态构造的代码（`exec` 拼接字符串）不进入 AST 分析。
- **单文件内追踪**：不做跨文件数据流；跨模块传播会漏。
- **流不敏感**：按语句顺序做数据流，未做分支合并/路径可行性判定 → 可能漏报（不可达路径上的链）也可能出现「形式上有链但实际不触发」的提示。
- **降误报取向**：只有形成完整链才报 P1；仅出现危险汇点（无敏感源流入）**只计数不报**——因此**「没有 AST 污点命中」不代表没有数据流风险**。

## 3. 应对策略：检测与防护的分层架构

本工具定位为**第一道防线**，不是万能钥匙。完整审计应分层：

```
┌─────────────────────────────────────────────────────────────────┐
│ 第 1 层：静态扫描（本工具，默认）                                  │
│   → 快速筛掉绝大部分明文 / 已知形态威胁                            │
│   → 对混淆 / 触发条件 / 加密载荷标记 P1/P2，并明确标注「不确定性」   │
├─────────────────────────────────────────────────────────────────┤
│ 第 2 层：人工代码审查                                             │
│   → 对 P0/P1 命中逐条语义复核                                     │
│   → 对被标记「已混淆 / 内容不可知」的文件做逆向或拒用               │
├─────────────────────────────────────────────────────────────────┤
│ 第 3 层：动态执行取证（本工具，需显式 --dynamic）                  │
│   → v3.3.2 起自动探测隔离后端并**显式标注隔离级别**：              │
│     • Docker 可用 → 真隔离：断网(--network=none) + 只读挂载 +      │
│       --cap-drop ALL + 内存/PID 限额 + 超时                        │
│     • Windows Sandbox 可用 → 断网 + 只读映射（GUI 型，自动化采集有限）│
│     • 均不可用 → **降级**为进程内审计钩子：                        │
│         网络外连 / 隔离区外写 / 子进程拉起 / 受限模块导入 / 大块内存 │
│   ⚠️ 诚实边界：进程内 Python 沙箱**非硬安全边界**——攻击者可沿对象图 │
│      找回受限模块绕过审计钩子。降级模式仅作「运行时取证 + 纵深防御」， │
│      **不代表安全执行**；硬隔离请在 OS 级容器 / VM 中进行。          │
├─────────────────────────────────────────────────────────────────┤
│ 第 4 层：社区 / 信誉信号                                          │
│   → 作者声誉、维护活跃度、安全社区披露与 CVE 关联                   │
│   → 本工具**本地合成**来源信誉分，不代为联网取证                    │
└─────────────────────────────────────────────────────────────────┘
```

## 4. v3.3.2 的针对性缓解措施（已做 / 未做）

### 已做
1. **AST 级跨语句污点追踪**（`--` 默认启用）：把「危险函数存在」升级为「敏感源是否真的流入危险汇点」，显著降低误报并提升证据链可读性（边界见 §2.4）。
2. **归一化重扫抗规避**：对零宽字符、双向控制符、同形字、跨行拆分做归一化后**重扫**，覆盖编码型隐写的主流手法。
3. **触发条件与危险原语共现检测**：对「反分析 + 危险动作」组合报警，缓解条件触发类的完全盲区。
4. **沙箱隔离后端探测与显式降级**：可用真隔离时走真隔离，不可用时**明确告知降级**，避免把「非硬隔离」误读为「已安全执行」。
5. **局限性透明声明**：报告中保留「静态分析局限性提示」，对存在混淆/加密/触发条件命中的结果显式声明「结论基于表面特征推断，可能存在未检出威胁」。
6. **可自证可信**：发布者签名锚（引擎源码哈希 + 关键文件锚 + 签名摘要）与引擎完整性自检，确保「你运行的审计器本身未被篡改」。

### 未做（明确不承诺）
- ❌ 对加密载荷/编译字节码的**内容还原**；
- ❌ 对隐写二进制、低带宽侧信道的**检测**（原理上需运行时流量/系统调用观测）；
- ❌ 跨文件跨模块的**完整**数据流分析；
- ❌ 联网查询依赖 CVE（`--osv` 需显式开启且联网）与来源信誉联网取证；
- ❌ 保证对**未知新型威胁**的检出——本工具的检测能力上限由「已知形态 + 启发式」决定。

## 5. 关于「检出率 / 误报率」指标的诚实标注

`selfcheck --corpus` 会输出检出率与误报率（当前基准库口径：检出 100%、误报 0%）。请理解为：

- 该指标基于**维护者自建的对抗基准库**（恶意样本 + 良性样本），**不代表真实世界的完整覆盖率**；
- 良性样本数有限，**不能证明**对任意合法 Skill 都零误报；
- 恶意样本以**已知手法**构造，**不能证明**对未知手法有效。

> 结论：把评分与门禁当作**风险排序与准入参考**，而不是安全保证。

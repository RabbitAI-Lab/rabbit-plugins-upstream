## Q1: 扫描结果不完整 / 没有明确判定结论

### 现象
- 运行扫描后输出中间空了，只有一堆原始命中但没有「PASS / BLOCK / NEED_REVIEW」这类结论。
- 或者开始扫描就报错退出了，看不出结果。

### 原因
v2.5.x 及更早版本在以下路径可能不输出明确结论：
- 目标目录里**没有 `SKILL.md`** → 直接返回 `{"error": "未找到 SKILL.md"}`，不生成风险评估。
- 扫描了**空目录或仅含不可读文件的目录** → 无命中输出，也不显示「PASS」。
- 虚拟环境/tmp 目录中的**临时 Skill 副本**（解压后的 staging 路径）没有完整结构。

### 解决方案（v2.6.0）
v2.6.0 起修复：所有路径都会输出明确判定：
- 错误路径 → 输出 `"admission_gate": "ERROR（无法完成扫描）"` + 原因说明。
- 零命中路径 → 输出 `"admission_gate": "PASS（可准入）"`。
- 每次扫描都在末尾**显示醒目的判定 Banner**，即使原始输出很长也能快速定位。

### 你自己怎么确认
如果你不确定扫描是否成功，请在输出中搜索以下关键词（按优先级）：
1. **`准入卡点`** — 最核心的结论，值应为 PASS / BLOCK / NEED_REVIEW / REVIEW 之一。
2. **`综合评级`** — 🟢🟡🟠🔴 四级颜色标记。
3. **`风险分布`** — P0×N P1×N P2×N P3×N 汇总。
4. **`signals`** / **`信号`** — 所有命中的完整清单。

如果以上四项均不存在，则扫描未完成（可能是路径错误或文件不可读）。

## Q2: IOC 误报——正常技能被标记为 C2 通信

### 现象
扫描结果中出现类似：
> `🔴 P0: 命中已知恶意 IOC（C2 IP 91.92.242.30）`

> 📌 **关于该 IP 的来源（2026-08-13 更新）**：`91.92.242.30` 现为 `rules/ioc.json` 中的**真实恶意 C2**——来源为腾讯安全威胁情报中心 2026-06-08《腾讯披露智能体 Skill 商店恶意样本与检测要点》（跨平台木马下载器从 `http://91.92.242.30/…` 拉取并执行后门）。示例情报（非真实）见 `rules/examples/ioc-examples.json`（使用 RFC 5737 保留测试地址 192.0.2.1）。

### 原因
某些安全工具/威胁情报类 Skill **自带 IOC 清单**（如 `rules/ioc.json`、`indicators.txt`），其中包含了已知 C2 IP 或域名。旧版扫描器不分青红皂白对所有命中都报 P0/BLOCK。

### 解决方案（v2.5.4 起）
v2.5.4 已实现**上下文感知 IOC 检测**：
- 若 IP 出现在 **JSON 的 `ips/domains/indicators/c2/ioc` 字段**中，或出现在**文件名含 `ioc`/`indicator` 的文件**中，降级为 **P3** 并提示「疑似指标清单上下文，请确认非运行时连接」。
- 只有**真实代码中的 socket 连接 / URL 请求**才会保持 P0。

### 如何确认
- 点击命中行，查看 `snippet` 字段——若片段显示的是 JSON 数组中的 IP 而非代码调用，大概率是情报清单误报。
- v2.6.0 起报告中会明确标注「该 IP 出现在指标清单/检测数据结构中，通常是安全工具自带的情报库」。

## Q3: 如何理解扫描结论——能不能用这个 Skill

### 判定体系

| 判定 | 含义 | 建议操作 |
|---|---|---|
| **PASS（可准入）** | 未发现任何 P0/P1/P2 风险 | 可直接使用 |
| **REVIEW（建议关注）** | 发现 P2 级风险或可疑特征 | 看一眼标记的内容是否符合预期，无问题则可使用 |
| **NEED_REVIEW（需人工复核）** | 发现 P1 级风险 | 先查看具体命中，确认意图后再决定；建议在隔离环境试运行 |
| **BLOCK（禁止准入）** | 发现 P0 级危险模式 | 强烈不建议直接使用；如需使用必须在严格隔离环境中，且建议动态监控 |

### 注意
扫描结论是**静态分析**结果，不是保证。如果 Skill 已被 pyarmor 或其他工具深度混淆，报告中会出现：「⚠️ 该 Skill 的某些文件已被混淆，其真实行为无法通过静态分析确认——建议人工复核或沙箱动态执行。」

## Q4: 混淆/加密命中——对还是错

### 常见的混淆命中

v2.6.0 新增了 `rules/obfuscation.json`，专门检测以下模式：

| 命中标签 | 严重度 | 含义 |
|---|---|---|
| PyArmor 混淆签名 | P1 | 该 Python 文件已被 PyArmor 编译加密，无法通过静态分析查看真实逻辑 |
| 内置字符串表加密 | P1 | 检测到 skill-protector 内置 XOR 字符串解密器，字符串常量已被隐藏 |
| 混淆式动态导入 | P1 | 使用 `__import__()` 而非顶层 import，刻意隐藏真实依赖 |
| Base85/Ascii85 编码 | P2 | 使用非标准编码方案，可能是刻意增强的混淆手段 |
| 离线加固框架产物 | P2 | 检测到 MANIFEST.sig / _guard / k_enc 等文件，Skill 已通过加固工具处理 |
| 自定义 XOR 加密 | P2 | 脚本自实现 XOR 加解密，会阻碍审计但可能是合法的数据保护 |

### 对还是错

这些命中的本质是「**标记已知混淆模式，提醒审计者无法完全确认该文件的真实行为**」，而不是说「这个 Skill 一定是恶意的」。

- **如果是你主动加固的 Skill**（比如你用它分发自己的代码）→ 这些命中是**预期的**，P2 可忽略，P1 应确认加固行为符合你的意图。
- **如果是从未知来源下载的 Skill** → P1 命中应重点关注，因为「混淆」本身不一定是恶意的，但它叠加其他危险信号（如外传 + 混淆）时风险急剧上升。

## Q5: 扫描 skill-analysis 自身时误报

### 现象
用 skill-analysis 扫描它自己的目录，出现 P0/P1 命中。

### 原因
skill-analysis 自带的规则文件中包含大量危险模式的正则表达式、IOC 清单、恶意样本路径等，直接扫描自身会产生同类命中。

### 解决方案
v2.5.3 起已有 `is_self_excluded()` 机制，排除了 `analyze_skill.py`、`selfcheck.py`、`watchdog.py`、`logger.py` 及其所在目录。v2.5.4 扩展了排除范围。

**验证方法**：运行 `python scripts/selfcheck.py`，确认「自扫描零误报」门禁通过（score 100）。

## Q6: 严重度级别详解

| 级别 | 标签 | 含义 | 典型场景 |
|---|---|---|---|
| **P0** | 严重 / BLOCK | 明确危险行为 | 反向 Shell、下载并管道执行、RCE、恶意 IOC 真实命中 |
| **P1** | 高 / NEED_REVIEW | 高风险行为，需人工复核 | 提示注入、隐蔽编码、PyArmor 混淆、凭据读取 |
| **P2** | 中 / REVIEW | 可疑特征，建议关注 | 运行环境读写、运行时安装依赖、混淆依赖、自实现密码 |
| **P3** | 低 / INFO | 信息性提示 | IOC 情报库指标、文档性提及（非指令） |

⛔ **P0 × 1** 即可触发 BLOCK。  
⚠️  **P1 × 1** 即可触发 NEED_REVIEW。  
ℹ️  **P2 / P3** 不影响准入，但累积会影响风险评分。

## Q7: 如何排除不需要扫描的文件或目录

当前版本的排除策略是内置的（`is_self_excluded()` + `_IGNORE_DIRS`）：

- 自动排除：`__pycache__`、`.git`、`node_modules`、`*.pyc`、`*.pyo`
- 自排除：扫描器自身的脚本和 CHANGELOG
- IOC 上下文降级：指标清单文件中的 IP 自动降为 P3

如需自定义排除规则，可在 `scripts/analyze_skill.py` 中找到 `_IGNORE_DIRS` 和 `is_self_excluded()` 函数进行扩展。

## 典型案例速查

### 案例 A: skill-protector 加固后的 Skill
```
场景：用户用 skill-protector 加固了一个 Skill，然后扫描加固后的产物。
预期命中：
  P1 × N: PyArmor 混淆签名 / 内置字符串表加密 / 混淆式动态导入
  P2 × N: 离线加固框架产物（MANIFEST.sig / _guard / k_enc） / 自实现 RSA
结论：NEED_REVIEW —— 静态分析无法确认加固后脚本的真实行为。
建议：对比加固前后的扫描结果，确认仅新增了「混淆/加密」命中，无「外传/Shell」类新增命中。
```

### 案例 B: 威胁情报类 Skill 自带 IOC 清单
```
场景：扫描一个安全审计 Skill，其 rules/ 目录下包含 threat_intel.json。
旧版行为（v2.5.3-）：P0 × 5（每个 C2 IP 都被报 BLOCK）
新版行为（v2.5.4+）：P3 × 5（上下文感知降级为指标清单提示）
结论：PASS —— 确认为情报库自身的指标数据，非运行时连接。
```

### 案例 C: 空目录 / 不完整 Skill
```
场景：扫描一个没有 SKILL.md 的目录（如解压后的临时 staging 目录）。
旧版行为（v2.5.x-）：返回 {"error": "未找到 SKILL.md"}，不显示风险结论。
新版行为（v2.6.0+）：返回 ERROR 判定 + 明确说明原因，并给出修复建议。
```

### 案例 D: 多层编码隐藏载荷
```
场景：SKILL.md 中嵌入了长 base64 块，解码后是 curl | bash 命令。
命中：P0: 多层混淆载荷（base64 解码后检出：下载并管道执行远程脚本）
结论：BLOCK —— 强烈不建议使用。
```

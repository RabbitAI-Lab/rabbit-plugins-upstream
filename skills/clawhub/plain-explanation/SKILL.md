# 通俗解释

把任何概念，讲到一个 5 岁孩子能立刻听懂的程度。

## 何时使用

满足下列任一条件即应使用本技能：

- 用户说"通俗解释 / 说人话 / 用大白话讲 / 讲简单点 / 给小白讲讲"
- 用户问"打个比方 / 有没有生活中的例子 / 类比一下"
- 用户对上一轮解释表示不理解："还是不懂 / 再简单点 / 太难了"
- 用户加上限定："5 岁也能听懂 / 像讲给小朋友一样"

## 不适用场景

- 用户在做严肃学术讨论、写论文、做代码评审——保持术语和精确度。
- 用户只是要"翻译"（中英互译、术语定义查询），不是要通俗化。
- 用户希望保留复杂度（如"详细讲讲 / 完整论述"）。

## 核心方法：只用 5 岁孩子能懂的方式

### 一个原则

**永远不要堆术语，永远不要解释定义，永远直接讲故事。** 

5 岁的孩子怎么学新事物？通过**看见**和**感受到**，不是通过**听懂**。所以每个解释都必须满足——对方闭着眼睛也能在脑子里"看见"那个画面。

### 三个动作

1. **挑一个孩子认识的东西当主角**：糖果、玩具、妈妈、卡车、游乐场、幼儿园、躲猫猫、过家家……
2. **把它拟人化，让它会动、会说话、会想事情**：钱会"撒娇"、病毒会"敲门"、算法会"挑食"。
3. **讲一件它做过的小事**：不是"是什么"，而是"它做了什么，结果怎么样"。

### 输出长度

- 默认 **60–120 字**一段故事。
- 超过 150 字就要砍。5 岁孩子注意力是一次机会。

### 句长硬约束

- **每句 ≤ 12 个字**。超出就拆。
- 多用短句、动词。少用形容词、抽象名词。

### 词汇替换表（硬规则）

| 不要说 | 换成 |
|--------|------|
| 通货膨胀 | 钱变小了 |
| 算法 | 选东西的规则 |
| 服务器 | 电脑小帮手 |
| 数据库 | 装东西的大盒子 |
| 神经网络 | 会认东西的小机器人 |
| 迭代 | 再来一次 |
| 优化 | 让它做得更好 |
| 协议 | 大家约定好的规矩 |
| 用户 | 玩的人 |
| 加载 | 慢慢跑出来 |
| 缓存 | 先放一边待会儿用 |

如果一个概念在替换表里没有，**自己造一个**——用孩子会说的话。

### 不要做的事

- ❌ 不写"定义：……是……"
- ❌ 不写"它由三部分组成"
- ❌ 不写"首先 / 其次 / 最后"
- ❌ 不出现任何抽象名词后面不跟故事
- ❌ 不超过 3 句话不出现具体画面

## 输出模板

```
【小故事】
[用 5 岁孩子会认识的东西当主角，写一件它做过的小事。60–120 字。]

【一句话总结】
它就是 [孩子认识的东西] 干了一件 [特别的事]。
```

如果用户问的是抽象事物（时间、爱、概率、熵……），同样适用——挑一个能"看见"它的场景来讲。

## Few-shot 范例

### 例 1：用户问"通俗解释通货膨胀"

> 你口袋里有 10 颗糖。糖店的小老板说："今天的糖一颗要 2 张贴纸了。" 你还是只有 10 张贴纸，只能换回 5 颗糖。**同样的贴纸，能换到的糖变少了**。你的贴纸没变，是糖变贵了——其实是你的贴纸"变小"了。这就叫"通货膨胀"。

### 例 2：用户问"通俗解释算法"

> 妈妈每天早上做三件事：先穿衣服，再刷牙，最后背书包。算法就是**这个"先做什么再做什么"的顺序**。比如你想吃冰淇淋，要先打开冰箱门，再拿出冰淇淋，最后关上冰箱门——这个顺序就是算法。

### 例 3：用户问"通俗解释量子纠缠"

> 魔法师给了你两颗糖，跟你说："这两颗糖是一对好朋友。" 他把一颗放在北京的小桌上，另一颗装进信封寄到纽约。你在纽约打开信封，糖里面写着"苹果"。**就在你打开的那一秒钟**，北京桌上的那颗糖，立刻也变成了"苹果"。两颗糖好像有心电感应，不管离多远都一起变。这就叫"量子纠缠"。

### 例 4：用户问"通俗解释熵"

> 你有一堆积木，搭成一座高高的塔。可是你不小心手一抖——哗啦！塔倒了，积木散得到处都是。**碎掉容易，堆回去难。** 世界上的东西总是越来越乱，不会自己变得整整齐齐。这种"越来越乱"就叫"熵"。

## 兜底话术

- 如果用户问的东西实在讲不出 5 岁版（如纯数学定义、超抽象概念），**老实说**："这个东西不太好讲成小故事，我换个办法——用三个最简单的小画面讲三遍，你看哪个能懂。" 然后给出三个不同角度的小画面。
- 如果用户说"再简单点"，**不要**再降一档（已经没有下一档了）。换一个新场景、一个新主角，从另一个角度重写一遍。
- 如果用户已经明确是"想要完整/深入的解释"，自动退出本技能，按普通模式回答。

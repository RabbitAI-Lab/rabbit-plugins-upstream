# 画像槽位与分支规则

> 这一层决定"定制化"能不能真的发生。
> 关键立场：**定制化靠可控的槽位与分支，不靠让模型自由发挥。** 后者不可测、不稳定，同一个问题问两次会飘。

## 1. 六个槽位

| 槽位 | 取值 | 从对话里怎么识别 | 影响什么 |
|---|---|---|---|
| `year` | 大一 / 大二 / 大三 / 大四 / 研究生 | 直接问，或从"刚来""要毕业了""我们辅导员"等措辞推断 | 信息优先级：大一讲适应与规则，大四讲出路与沉没成本 |
| `school_tier` | 双一流 / 普通本科 / 民办 / 专科 | 一般不主动问，从上下文推断；**只在关系到资源可得性时才需要** | 保研率、资源水平、政策的现实差异。**不用于查具体校规** |
| `major` | 理工 / 文史 / 经管 / 医 / 法 / 艺体 / 其他 | 从问题内容推断，或一句话问 | 路径差异（比如"考研数学"只对理工经管有意义） |
| `issue_type` | 决策型 / 执行型 / 关系型 / 情绪型 | **从问句结构推断**，见第 2 节 | **决定回应结构**——这是最影响定制化效果的一个 |
| `tried` | 自由文本 | 从"我试过……""但是……"里提取 | 避免给出他已经试过的建议。**给了就是自曝没听人说话** |
| `temperature` | 平稳 / 焦虑 / 崩溃 / 危险 | 从语气、标点、篇幅、用词强度推断 | 决定文风档位；`危险` 直接触发危机协议（见 `crisis-protocol.md`） |

### 关于 `school_tier` 的边界

Dora 已明确：**不做学校粒度的政策定制**（维护成本爆炸）。所以这个槽位只有一个用途：

> 判断"这个建议对他来不来得及、够不够得着"，而不是"他们学校的具体规定是什么"。

- ✅ 可以说："你们学校如果是双一流，那保研名额一般会多一些，这条路值得早看。"
- ❌ 不可以说："你们学校规定挂两门就退学。"（编的）

涉及具体校规时，一律给**查找路径**，不编内容：

> "这条各校差得远，我不敢给你一个数。去教务处官网找《学生手册》，搜'重修'两个字。"

## 2. `issue_type`：怎么判断，以及怎么用

| 类型 | 问句长什么样 | 他真正需要的 | 回应结构 |
|---|---|---|---|
| **决策型** | "该不该……""选 A 还是 B""值不值得" | 一个能自己套用的判断框架 | 框架优先，最后给一个倾向性建议 |
| **执行型** | "怎么做……""有什么办法""怎么办才能" | 具体步骤和动作清单 | 清单优先，越具体越好 |
| **关系型** | "他/她/他们……我该……" | 沟通策略 + 边界设定 | 先分清是谁的问题，再给话术 |
| **情绪型** | 大段叙述、没有明确问题、语气激烈或低落 | 先被听见，才谈办法 | 加厚①段，压缩③段 |

**判断依据是问句结构，不是话题。** 同一个话题可以是四种类型：

- "我该不该换宿舍？" → 决策型
- "怎么跟宿管申请换宿舍？" → 执行型
- "室友总是针对我，我该怎么回应？" → 关系型
- "我在宿舍待不下去了，每天回去就难受。" → 情绪型

**这四种的回应应该长得完全不一样。** 这是定制化最直接的体现。

## 3. 填充节奏

**硬规则：最多 3 轮填充，且每一轮最多问一个问题。**

学生本来就烦，不能让他先填表才肯帮他。

| 轮次 | 动作 |
|---|---|
| 第 1 轮 | 从他的话里**能推的都推**，然后直接给初步回应。**不要一上来就发问询表。** 在回应末尾带一个自然的问题 |
| 第 2 轮 | 补最关键的那个缺失槽位（通常是 `year` 或 `issue_type`），给更贴合的回应 |
| 第 3 轮 | 补完，给完整回应 |

### 缺省处理

- 槽位缺了 → **走通用分支，不追问**。通用分支的回答质量要足够高，不能像"信息不足请补充"。
- 只允许在**回应末尾**问，不要打断正文。
- `temperature` 例外：**这个永远不主动问，只从语气推断**。问"你的情绪状态如何"是很冒犯的。

### 反面示例（不要这样）

> ❌ "为了给你更准确的建议，请告诉我：1. 你的年级 2. 学校类型 3. 专业 4. 具体困扰 5. 已经尝试过什么"

这句话一出，对话基本结束了。

## 4. 同一问题的分支差异（定制化效果示例）

用户的原始问题：**"室友半夜打游戏太吵了"**

| 画像 | 分支结果 |
|---|---|
| 大一 / 关系型 / 焦虑 | 先承认适应期的合法痛苦；重点讲**"现在立规矩成本最低"**——因为大家还不熟，提要求不伤感情；给三段式沟通话术 |
| 大四 / 决策型 / 平稳 | 不铺陈感情，直接算账：还剩几个月 → 不值得撕破脸，但也不值得忍着；给**两个并行方案**（短期耳塞/换作息，长期换宿舍或申请单人间的可行性） |
| 大三 / 情绪型 / 崩溃 | ①段加厚：先承认"连续被吵醒是真实的伤害，不是你矫情"；**今晚不给解决方案**，只给一个最小动作（记录三天，让他有证据）；③段压缩到最短 |
| 大二 / 执行型 / 平稳 | 直接上清单：沟通 → 协商书面规则 → 找宿管 → 申请换宿舍；每一步给具体说法和找谁 |
| 任意 / `temperature=危险` | **停止以上全部分支**，转 `crisis-protocol.md` |
| 缺省槽位 | 走通用：承认 + 三段式沟通框架 + 备案路径，末尾问一句"你大几了？" |

**同一句话，六种回应。这就是"定制化"的具体含义。**

## 5. `tried` 槽位的特殊重要性

这个槽位最容易被忽略，但**忽略它会直接毁掉信任**。

学生说"我都跟他说过好几次了"，你还在给他讲"你可以试着沟通一下"——他会立刻判定"这个东西没在听我说话"，然后关掉。

处理规则：

1. **先从文本里提取 `tried`**，不需要问。
2. 回应里**显式承认他说过的尝试**：
   - ✅ "你已经提过几次了，说明这件事不是'没沟通'的问题，是'沟通了没用'的问题。那换个方向。"
3. **给出的新建议必须在 `tried` 之外**。如果所有常规建议他都试过了，就明说"常规办法你都用过了，剩下的都是要付代价的"，然后给代价对比——**这种诚实比硬凑一个新点子有用得多**。

## 6. 槽位冲突时怎么办

| 冲突 | 处理 |
|---|---|
| 语气说"没事"但内容明显很重 | 以**内容**为准，语气当成防御 |
| 自称大一但提到选专业 | 不纠正、不追问，按大一处理（可能是预科或口语化表述） |
| 说了两件不相关的事 | 取**篇幅更长**的那件为主，另一件在末尾提一句"另外你说的那件事要不要也说说" |
| 前后矛盾 | 不指出矛盾，按后者处理 |

**统一原则：不纠正用户，不追问细节，不为了填槽位牺牲对话的流畅。**

## 7. 落盘结构

运行时槽位状态存在 `data/profile_rules.json` 定义的 schema 下，与 `data/scenarios.json` 的 `profile_branches` 字段配合使用。

分支查找顺序：

```
1. 精确匹配：scenario.profile_branches[slot][value]
2. 退回通用：scenario.profile_branches[slot]["default"]
3. 再退回：scenario 本身的通用内容
```

**任何一步都不能返回空。** `audit.py` 会检查每个 scenario 的每个分支槽位都有 `default` 兜底。

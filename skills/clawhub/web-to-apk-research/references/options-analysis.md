# Web-to-APK Options Analysis (Full Research)

> Reference for `web-to-apk-research` skill. Read this when the user needs a deep comparison before choosing a path.

## Options Analysis

### 1. PWA + WebAPK (Recommended for Termux)

**How it works:**
- Add `manifest.json` + `service-worker.js` to web app
- Serve via HTTPS (GitHub Pages = free HTTPS)
- User opens in Chrome → "Install app" → Chrome generates WebAPK automatically
- Appears in app drawer, full-screen, offline-capable

**Pros:**
- Zero native build tooling needed
- Works immediately in Termux (just add files)
- Auto-updates when web version changes
- Tiny "APK" (~1MB WebAPK)
- No Play Store needed

**Cons:**
- Requires Chrome (or Chromium-based browser)
- Limited native API access (no filesystem, no background tasks beyond service worker)
- WebAPK generated by Chrome, not a real .apk file you can share

**Effort:** Low (add 2 files, deploy to GitHub Pages)

---

### 2. Capacitor + GitHub Actions Build

**How it works:**
- `npm init @capacitor/app` in project
- Add Android platform: `npx cap add android`
- Write GitHub Actions workflow to build APK (Ubuntu runner has Java/Gradle/Android SDK)
- Download APK from Actions artifacts

**Pros:**
- Real .apk file you can share/install anywhere
- Full native plugin access (camera, filesystem, notifications, etc.)
- Can publish to Play Store
- Web code stays same

**Cons:**
- Needs GitHub repo + Actions (free tier OK)
- Build takes 5-10 min per run
- More complex config
- Large APK (~15-30MB)

**Effort:** Medium (Capacitor config + CI workflow)

---

### 3. Trusted Web Activity (TWA) + GitHub Actions

**How it works:**
- Similar to Capacitor but uses `bubblewrap` CLI
- Generates minimal Android project wrapping Chrome Custom Tab
- Play Store friendly (official Google approach)
- Same CI build approach

**Pros:**
- Smaller APK (~5-10MB)
- Official Google recommended for PWA→Play Store
- Seamless Chrome integration

**Cons:**
- Still needs CI for build
- Requires Digital Asset Links for domain verification (Play Store)
- Slightly more setup than Capacitor

**Effort:** Medium

---

### 4. Native WebView App (Manual Kotlin/Java)

**How it works:**
- Write minimal Android app with WebView loading your URL
- Build with Gradle (needs CI or local Android SDK)

**Pros:**
- Full control
- Smallest APK (~3-5MB)

**Cons:**
- Most work
- Need to maintain native code
- Still needs build environment

**Effort:** High

---

### 5. Tauri Mobile (Experimental)

**How it works:**
- `tauri init` → `tauri android init` → build
- Uses Rust + WebView

**Pros:**
- Tiny binary (~3-5MB)
- Rust performance

**Cons:**
- Mobile support still experimental
- Needs Rust + Android NDK + Java + Gradle
- Not stable for production

**Effort:** Very High (not recommended yet)

---

## Questions to Ask the User

1. **Target:** Butuh file `.apk` yang bisa dikirim ke orang lain, atau cukup bisa di-install sendiri di HP?
2. **Fitur native:** Butuh akses filesystem/notifikasi/background sync, atau cuma jalanin web app + lihat output?
3. **Deploy preference:** GitHub Pages (gratis, HTTPS otomatis) OK?
4. **Timeline:** Mau yang bisa dipakai hari ini (PWA), atau mau tunggu build APK via CI?

# 台灣繁體中文貼圖文字檢查規則

本參考文件用於 `line-sticker-master` 產生或審核台灣市場使用的 LINE 貼圖文字。它提供語用方向，不是絕對詞典；角色設定、年齡層、產業文化與使用者指定語氣優先。

## 一般日常用語規則

先判斷每句話的「使用時機、對象關係、情緒強度、回覆方向」，再檢查字面是否自然。日常貼圖以短句為主：通常 2–8 個中文字最容易閱讀，超過 10 個字時應評估是否能拆成兩張或改為更口語的說法。保留必要的語氣詞，但避免每張都使用「啦、喔、欸、耶、齁」造成語氣重複。

優先使用台灣常見用字，例如「訊息」而非「信息」、「檔案」而非「文件」作為一般工作語境、「軟體」而非「軟件」、「網路」而非「網絡」、「影片」而非「視頻」、「滑手機」而非「玩手機」、「外送」而非「外賣」、「計程車」而非「出租車」。這些是預設方向，不應在角色明確設定為其他地區用語時強制替換。

檢查繁簡混用、異體字、錯別字、英文大小寫、全形/半形標點與不必要的句號。台灣繁體中文貼圖可使用「！」「？」「～」「……」表現情緒，但同一套要維持一致；避免連續過多標點，例如「？？？？」「！！！？？！」，除非該張就是誇張反應梗。

### 建議的日常語意覆蓋

| 情境 | 可優先考慮的語句 | 檢查重點 |
| --- | --- | --- |
| 問候 | 早安、午安、晚安、嗨、哈囉、吃飽沒 | 避免同一套只有問候，需搭配回應與情緒 |
| 確認 | 收到、了解、好喔、沒問題、可以、OK | 分清「已讀確認」與「同意承諾」 |
| 感謝 | 謝謝、感謝、太感謝了、辛苦了 | 「辛苦了」通常是慰勞，不等同單純謝謝 |
| 道歉 | 對不起、抱歉、拍謝、我錯了 | 「拍謝」偏口語；正式角色避免濫用 |
| 請求 | 拜託、麻煩你、可以請你、救命 | 檢查對象關係，避免把命令偽裝成請求 |
| 拒絕/延後 | 先不要、現在不行、改天再說、我再看看 | 避免過度尖銳；需要保留禮貌版本 |
| 驚訝/反應 | 真的假的、太扯了、傻眼、笑死、蛤 | 梗語需符合角色年齡與受眾，不要全部堆在同一套 |
| 鼓勵 | 加油、你可以的、穩住、辛苦了、撐住 | 「穩住」是鼓勵，不應用於正式通知語境 |

## 職場梗規則

職場梗要先標示使用情境：同事互動、對主管、對客戶、跨部門、遠端工作、會議、專案期限或下班社交。預設只產生「同事間可安全分享」的版本；若文字涉及主管、客戶或人資，提供較中性替代句，避免讓貼圖在真實職場造成冒犯或誤解。

區分台灣常見的職場口語與過度中國用語。依情境可使用「收到、我處理、馬上改、再確認一下、同步一下、拉個會議、先對一下、卡住了、來不及、趕進度、今天先到這、準時下班、加班中、我先離開、已讀不回」等表達；但不要把每句都寫成空泛的企業術語。每張職場梗貼圖應有明確笑點或使用時機，而不是只堆疊「賦能、抓手、閉環、對齊」等詞。

### 職場語境分級

| 級別 | 適用對象 | 文字方向 | 風險控制 |
| --- | --- | --- | --- |
| A：安全日常 | 同事、朋友 | 收到、辛苦了、我先下班、等等回你 | 可直接使用 |
| B：輕度自嘲 | 熟同事、團隊群組 | 會議中、腦袋當機、先讓我改完、今天不加班 | 避免影射特定個人或公司 |
| C：敏感諷刺 | 公開社群或不明群組 | 老闆畫大餅、又要加需求、薪水呢 | 必須提供中性替代句，不預設直接採用 |
| D：高風險 | 霸凌、歧視、威脅、洩密 | 點名主管/同事、羞辱身分、揭露內部資料 | 拒絕原句，改寫成非指涉個人的安全梗 |

檢查「老闆、主管、客戶、同事、菜鳥、社畜、工具人、打工仔」等稱呼是否符合角色關係與使用者意圖。對公開販售套組，避免把身心疾病、身分、性別、年齡、國籍或職業當成嘲笑對象；「社畜」可作自嘲，但要提供不帶貶義的替代語句，例如「今天也努力工作」「先撐過今天」。

檢查「加班、爆肝、過勞、離職、被裁、薪水、年終、放假、準時下班」是否只是幽默表達，還是會誤導成真實承諾、針對個人或鼓勵危險勞動。避免使用明確的公司內幕、客戶資料、密碼、帳號、未公開數字或可辨識的真人姓名。

## 台灣職場迷因與趣味用語清單

下列語料可作為創作方向，不應機械地全部塞進同一套貼圖。每個詞都要搭配明確情境、角色關係與情緒，並檢查是否適合公開轉傳。

| 類型 | 常見說法 | 建議搭配情境 | 審核與替代方向 |
| --- | --- | --- | --- |
| 會議 | 又開會、會議中、先開個會、這會開多久 | 會議邀請、線上會議、長會議 | 避免影射特定主管；可改「先把重點對一下」 |
| 進度 | 進度如何、還在努力、快好了、差不多了 | 被追進度、回報專案 | 「快好了」不要與明確承諾混用；可標示自嘲語氣 |
| 修改 | 馬上改、再改一下、需求又變了、改到會 | 需求變更、設計/文件修改 | 避免責怪客戶或同事；可改「我先整理一下」 |
| 時程 | 趕不上、來不及、死線到了、Deadline | 期限逼近、專案倒數 | 「死線」是比喻，不鼓勵危險工作；可改「期限快到了」 |
| 加班 | 加班中、今天不回家、先撐住、晚點走 | 晚間工作、共同趕工 | 避免美化過勞；提供「今天先到這」「明天繼續」版本 |
| 下班 | 準時下班、我先走、下班打卡、撤退 | 工作結束、同事道別 | 適合輕鬆自嘲，不要暗示逃避必要責任 |
| 請假/休息 | 放假啦、充電中、休息一下、暫離座位 | 休假、午休、暫離 | 「躺平」可作輕度自嘲，但不應攻擊工作者 |
| 薪資福利 | 薪水呢、等年終、加薪靠自己、福利在哪 | 熟同事群組、匿名式自嘲 | 公開販售時避免影射特定公司或真實薪資資料 |
| 遠端工作 | WFH 中、鏡頭關一下、網路卡住、人在家 | 視訊會議、居家辦公 | 不要鼓勵謊報出勤；可改「連線中，稍等一下」 |
| 訊息回覆 | 已讀、晚點回、收到收到、我看一下 | 通訊軟體、工作群組 | 分清已讀、理解與承諾；「收到」不等於已完成 |
| 協作 | 同步一下、對一下、拉個會、請支援 | 跨部門協作、交接 | 避免空泛術語；明確寫出「確認範圍與期限」 |
| 技術/系統 | 系統又壞了、先重開、Bug 來了、部署中 | 工程、設計、客服支援 | 不要公開內部錯誤細節、帳號、網址或客戶資料 |
| 情緒 | 我不行了、腦袋當機、先冷靜、需要咖啡 | 工作量過大、突發任務 | 避免把真實心理疾病當笑點；可改「腦袋需要重整」 |
| 企業梗 | 對齊、閉環、抓手、賦能、顆粒度 | 模仿簡報或會議語氣 | 不要只堆詞；每句要能轉成白話，例如「先確認目標」 |
| 自我調侃 | 社畜模式、工具人上線、打工魂 | 熟人、自嘲角色 | 不可用來貶低他人職業、階級、年齡或身分 |

### 迷因使用的五項判斷

1. 判斷笑點是「情境反差、誇張表情、工作流程荒謬」還是「嘲笑某個人」。優先選前者，避免把特定同事、主管、客戶或公司當成攻擊對象。
2. 判斷使用範圍是私人好友、同事群組、公開社群或商業販售。越公開，越應採用不指涉個人、不洩漏內情且可跨產業理解的版本。
3. 判斷語句是否把過勞、失眠、焦慮、被裁員、霸凌或經濟困境當成笑點。若是，改成描述工作情境的輕度自嘲，不使用醫療診斷或羞辱性標籤。
4. 判斷是否含有真實公司名稱、客戶名稱、專案代號、薪資數字、內部截圖、可識別姓名或未公開事件。若有，移除或改成泛稱。
5. 判斷是否需要同時提供「梗版」與「安全版」。例如「需求又來了」可保留為同事梗，並提供「我先確認需求範圍」作為對客戶或主管的替代句。

### 常見迷因的安全改寫

| 原始方向 | 可能問題 | 安全改寫 |
| --- | --- | --- |
| 老闆又畫大餅 | 指涉主管、容易冒犯 | 目標好多，先確認優先順序 |
| 客戶到底在想什麼 | 貶低客戶 | 我先確認需求，避免理解不同 |
| 這公司沒救了 | 攻擊公司、可能造成誤解 | 這題有點難，我們先拆開處理 |
| 加班到爆肝 | 美化或正常化過勞 | 今天先把重要事項完成，記得休息 |
| 菜鳥快去做 | 貶低新進員工 | 新手上線，請多多指教 |
| 薪水少到哭 | 公開薪資或階級笑點 | 期待好消息，先把工作做好 |
| 又要背鍋 | 指責同事、形成霸凌 | 先釐清責任與下一步 |
| 你被裁了嗎 | 影射失業與個人處境 | 最近還順利嗎？ |

若使用者明確要求尖銳諷刺版本，先說明其適用範圍與風險，再同時產生低風險版本；除非使用者指定，公開貼圖預設採用安全改寫。

## 語氣與對象檢查

每張文字都要標記語氣：中性、可愛、撒嬌、吐槽、崩潰、正式、禮貌或自嘲。若同一套同時面向朋友與職場，至少準備一組不帶粗話、不過度親密、不諷刺權力關係的替代句。粗口或強烈語句若不是使用者明確要求，應改為輕度口語，例如將過強的辱罵改為「太扯了」「我不行了」「先冷靜」。

同音梗、諧音梗與英文混用必須做「看字測試」：即使不聽發音，使用者也能理解笑點。英文縮寫如 `WFH`、`ASAP`、`FYI`、`OKR`、`KPI` 只在目標受眾熟悉時使用，第一次可附中文語意；不要讓縮寫取代整套主要訊息。

## 逐格審核流程

1. 先讀文字，不看畫面，判斷是否能推測使用情境。
2. 再看角色表情與動作，確認情緒和文字一致。
3. 將文字套入同事群組、朋友聊天與公開社群三種情境，檢查是否可能被誤解。
4. 檢查台灣繁體字、用詞、標點、語氣詞與英文縮寫。
5. 檢查字數、字體大小、描邊、對比、是否靠近裁切邊界，以及生成模型是否產生錯字。
6. 為不合格句子保留「原句、問題、建議句、適用情境」，不要只默默改寫而失去可追蹤性。

## 常見修正方向

| 問題 | 優先修正方向 | 範例 |
| --- | --- | --- |
| 中國用語 | 改為台灣慣用詞 | 信息 → 訊息；視頻 → 影片 |
| 過度正式 | 改成聊天短句 | 請您知悉 → 收到，了解 |
| 缺乏對象 | 補足情境或動作 | 「處理中」→「我處理中，等等回你」 |
| 梗太尖銳 | 改成自嘲或非指涉 | 「你又搞砸」→「這題有點難」 |
| 意思重疊 | 合併或替換 | 「收到」「了解」「好」不要佔滿多格 |
| 文字太長 | 保留核心動詞與情緒 | 「我現在正在忙碌中」→「忙碌中，晚點回」 |
| 生成錯字 | 改用後製排版 | 生成留白圖，文字由可控排版工具加入 |

## 工程師與遠端工作專屬規則

工程師梗應以工作流程、除錯反差、版本控制、部署節奏與團隊協作為笑點，不以能力、年資、學歷、身心狀況或性別作為嘲笑對象。遠端工作梗則要區分「技術連線問題」與「出勤誠信」；可以幽默描寫鏡頭、麥克風、網路與通知，但不要鼓勵虛報出勤、錄製假畫面或洩露會議內容。

### 工程師與遠端梗審核規則

生成工程師或遠端工作貼圖時，除了基本的繁體中文檢查，還要執行以下判斷：

1. 將技術術語與一般使用者可理解的白話句分開；若套組目標不是工程團隊，為 `PR`、`CI`、`Log`、`Merge`、`On-call`、`WFH` 等縮寫提供中文替代句。
2. 不要把「在我電腦可以」「測試在哭」「部署翻車」寫成對特定同事能力的批評；畫面應呈現流程反差或角色自嘲。
3. 涉及 `API key`、密碼、token、內部網址、客戶資料、錯誤堆疊或未公開漏洞時，刪除真實內容並改成抽象圖示。
4. 不要鼓勵直接在正式環境試錯、跳過 code review、跳過測試、過度授權、謊報遠端出勤或未經同意錄製會議。
5. 遠端工作文案優先採用「連線不穩，請稍等一下」「我正在處理，稍後回覆」「我先確認畫面」等可對客戶使用的版本；「你靜音了」「鏡頭關一下」等句子應標記為同事間語氣。
6. 對過勞、夜間值班、被叫醒與心理壓力梗，保留幽默但加入休息、補休或交接語意，避免把長工時塑造成值得炫耀的能力。

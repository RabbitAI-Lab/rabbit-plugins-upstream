# 运行时判断回路（Creative Runtime）

## 概述

前任回怼写作风格（Ex-Clapback Writing Style）属于 creative-writing-style，输出质量高度依赖“深情 + 反讽 + 荒诞细节”的三位一体。因此运行时必须执行 **Critique → Judge → Revision** 三回合，而不是一次性生成。

## 运行流程

```
用户输入
  │
  ▼
[Step 1: 初稿生成]
  │ 读取 principles.md + fingerprint.md
  │ 按模板 A/B/C/D 选择其一（默认 tutorial 体）
  │ 输出 V0
  │
  ▼
[Step 2: Critique（诊断）]
  │ 对照 anti-patterns.md 逐项检查
  │ 输出问题清单 + 风险等级
  │
  ▼
[Step 3: Judge（评分）]
  │ 按以下维度打分（0-10）
  │ 若平均分 < 7，进入 Revision
  │
  ▼
[Step 4: Revision（重写/局部修订）]
  │ 保留符合风格的部分，修改问题部分
  │ 输出 V1
  │
  ▼
[Step 5: 最终 Judge]
  │ 再次评分，必要时再 Revision（最多 2 轮）
  │
  ▼
最终输出 + 简短评分报告
```

## Step 1：初稿生成提示要点

```text
你正在使用「前任回怼写作风格」（Ex-Clapback Writing Style）生成一段社交媒体文案。

输入：
- 主题：{topic}
- 前任对象身份：{ex_archetype}
- 细节道具：{object_detail}
- 语气：{tone}
- 长度：{length}

要求：
1. 以第一人称“我”写作，身份是前任/旧爱。
2. 同时包含：深情外皮、反讽内核、一个具体荒诞生活细节。
3. 使用 principles.md 中的结构模板之一。
4. 必须引用对象说的一句荒诞但符合其成功学/大佬人设的话。
5. 结尾用一句反转金句收束。
6. 附上 1-3 个反讽标签。
7. 禁止出现真实人名，用“前任对象 / A 先生 / 某百亿创业者”等泛化代称。
8. 禁止直接复制原文句子，只使用风格范式。
```

## Step 2：Critique 诊断清单

对 V0 执行以下诊断：

| # | 检查项 | 通过标准 |
|---|--------|----------|
| C1 | 真实人名 | 未出现 |
| C2 | 可验证事实捏造 | 未出现 |
| C3 | 深情 + 反讽同时存在 | 均有 |
| C4 | 具体生活细节道具 | 有 |
| C5 | 对象话语引用 | 有 |
| C6 | 反转金句 | 结尾有 |
| C7 | 反讽标签 | 有 |
| C8 | 段落节奏 | 基本 1-3 句一段 |
| C9 | 原文复制 | 无直接照搬 |
| C10 | 数据/数字包装 | 至少一个 |
| C11 | 深情篇幅 ≥ 攻击篇幅 | 深情段落字数不少于攻击性/吐槽段落；无铺垫直接开火判 FAIL |
| C12 | 克制度 | 无连续两段以上的纯负面输出；情绪最高处须有突降 |

输出格式：

```yaml
issues:
  - item: "C4 具体生活细节道具"
    severity: critical
    problem: "只写‘他很抠’，没有具体物品"
    fix: "加入‘他把外卖优惠券按到期日贴在冰箱上’"
  - item: "C6 反转金句"
    severity: major
    problem: "结尾只是总结"
    fix: "改成‘我的心也和他那份发了霉的咖喱一起倒进了下水道’"
pass: false
```

## Step 3：Judge 评分维度

| 维度 | 权重 | 说明 |
|------|------|------|
| 风格保真（Style Fidelity） | 30% | 是否像“前任回怼写作风格” |
| 反讽甜度（Ironic Sweetness） | 25% | 深情与讽刺的比例是否平衡 |
| 细节具体度（Detail Concreteness） | 20% | 道具、场景、数字是否到位 |
| 节奏感（Rhythm） | 15% | 换行、反转、金句是否踩在节拍上 |
| AI 腔率（AI-likeness） | 10% | 是否像模板化 AI 生成，而非活人写的段子 |

> **C11/C12 一票否决：** 名称中的“回怼”指回应姿态，不是语气浓度。若 C11 或 C12 判 FAIL，无论其他维度多高，综合得分直接记为 <7.5 并强制 Revision。参见 `SKILL.md` §关于命名。

评分标准：

- 9-10：可直接发布
- 7-8：小修即可
- 5-6：需要 Revision
- <5：需要重写

综合得分 = Σ(维度分 × 权重)。综合得分 ≥ 7.5 方可输出。

## Step 4：Revision 策略

### 局部修订（分数 5-7）

- 替换不具体的形容词 → 具体细节。
- 在段落间插入反转连接词。
- 把结尾总结句改成金句。
- 调整标签使其更具反讽性。

### 全局重写（分数 <5）

- 重新选择模板 A/B/C/D。
- 更换核心道具。
- 重写开头和结尾。

## Step 5：输出格式

```text
【最终文案】
（正文）

【评分报告】
- 风格保真：x/10
- 反讽甜度：x/10
- 细节具体度：x/10
- 节奏感：x/10
- AI 腔率：x/10
- 综合得分：x/10
- 修订轮次：n
```

**终检对照基准：** 输出定稿前，对照 `tests/golden-set.md` 的基准样例（Case 1–3 正例方向 + Case 4 对抗拒绝）逐条核对方向是否命中；若成品滑向纯吐槽 / 纯撒娇 / 纯鸡汤（Case 4 模式），视为 Critique 未生效，回滚并重跑三回合。

## Revision Gain 检查

- 若 Revision 后综合得分下降，回滚到上一版。
- 若 Revision 只是“重新抽卡”（改动超过 70% 但风格无提升），视为 gain ≈ 0，保留前一版并报告“本次修订未带来显著提升”。

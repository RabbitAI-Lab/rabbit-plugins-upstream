## Core Thinking Models

### 模型一：金融AI三大视界（麦肯锡三地平线框架）

```
┌─────────────────────────────────────────────────────────────┐
│              金融AI战略 — 三大视界（Three Horizons）           │
├──────────────┬──────────────────┬────────────────────────────┤
│  Horizon 1    │  Horizon 2        │  Horizon 3                  │
│  (0-12个月)   │  (12-36个月)      │  (36-60个月)                │
├──────────────┼──────────────────┼────────────────────────────┤
│ 运营效率革命  │ 客户体验重塑      │ 商业模式创新                │
│              │                  │                            │
│ • 智能客服    │ • AI Agent投保    │ • AI原生保险产品            │
│ • 文档自动化  │ • 个性化产品推荐  │ • 动态定价2.0              │
│ • 智能理赔    │ • 全渠道客户旅程  │ • 去中介化平台              │
│ • RPA升级     │ • 多模态交互      │ • 生态化金融服务            │
├──────────────┼──────────────────┼────────────────────────────┤
│ 典型场景：    │ 典型场景：         │ 典型场景：                  │
│ 核保自动化   │ Agent驱动的理赔    │ 自主风控决策体系            │
│ 智能客服     │ 智能投顾           │ AI原生保险产品              │

├──────────────┴──────────────────┴────────────────────────────┤
│ 核心原则：Horizon 1 造血 → Horizon 2 蓄力 → Horizon 3 领跑   │
│ "先赋能、再替代、最后创新"                                  │
└─────────────────────────────────────────────────────────────┘
```



**落地示例 A（中型寿险公司，示意）**

```text
H1（0-12 个月）：智能理赔影像预审 + 智能客服 + 单证自动化
  目标：理赔件均处理时长下降、客服一次解决率提升
  验收：以投产前后同口径指标对比，需排除季节性因素
H2（12-36 个月）：Agent 驱动的核保辅助 + 个性化产品推荐
  目标：核保自动通过率提升、人工复核集中在高风险件
  验收：以复核覆盖率与误判率双指标衡量
H3（36-60 个月）：动态定价与 AI 原生产品
  目标：形成可迭代的定价模型与产品形态
  验收：以监管沟通进展与试点范围衡量
```

**落地示例 B（城商行，示意）**：H1 聚焦贷后预警与报表自动化（见效快、数据就绪），H2 才推进智能投顾与客户旅程编排，避免把需要长周期的能力放进当年考核。

**排布自检**：三个地平线是否各自有独立的时间窗、独立指标、独立责任人？若 H1 与 H3 共用同一套 KPI，说明分层失效。

### 模型二：AI就绪度诊断（MECE框架）

**六大维度评估金融机构AI就绪度**：

| 维度 | 评估指标 | L1 初始级 | L3 发展级 | L5 领先级 | 可取证据（用于避免自评偏高） |
|------|---------|-----------|-----------|----------|---|
| **战略** | AI在董事会优先级 | 未列入议程 | 专项AI委员会 | AI驱动战略决策 | 董事会/专委会纪要中是否出现 AI 议题及决议 |
| **数据** | 数据基础建设 | 手工报表为主 | 统一数据中台 | 实时数据+知识图谱 | 数据中台覆盖的业务域清单与数据质量报告 |
| **技术** | AI基础设施 | 单点POC | MCP/A2A架构落地 | AI原生技术栈 | 已上线场景数、MCP/工具接入清单 |
| **人才** | AI团队配置 | 0-5人外包 | 20-50人内外部混编 | 200+ AI原生团队 | AI 岗位编制、外部合作合同与培训记录 |
| **治理** | AI风控体系 | 无明确规范 | 模型台账+三方审计 | 实时AI监管沙盒 | 模型台账条数、审计意见与偏差处置记录 |
| **生态** | 外部合作 | 单一供应商 | 多供应商+开源混合 | 自研+社区贡献+标准制定 | 供应商结构、开源贡献与参与标准制定的记录 |
| **算力** | 可支撑的并发与训练/推理能力 | 无专用算力，按需租用 | 有固定推理集群，可支撑重点场景 | 训练推理一体化调度，具备弹性扩容 | 集群规格、并发实测值、单位请求成本记录 |

```

│   ├── 技术能力（算力、模型、工程化）
│   ├── 人才储备（AI团队、培训体系、文化接受度）

│   ├── 愿景清晰度（是否明确AI战略定位）
│   ├── 资源投入（预算、人力、管理层承诺）
│   └── 路线图（分阶段目标、里程碑）
│
└── 环境维度（外部）
    ├── 监管要求（国家金融监督管理总局 NFRA）
```

**诊断示例（示意，仅演示打分口径）**

```text
某中型机构自评：战略 L3、数据 L2、技术 L2、人才 L2、治理 L1、算力 L2
证据核对：
  - 战略 L3 成立：已设 AI 专委会（有会议纪要）
  - 数据 L2 成立：数据中台覆盖 4 个业务域（有覆盖清单）
  - 治理 L1 成立：无模型台账（无证据）→ 不得上调
结论：加权后处于「流程嵌入」向「能力内化」过渡阶段

```

### 模型三：Agent生产力公式（阿里百技图精华）

**AI Agent = 大模型(LLM) × 工具生态(MCP/A2A) × 业务流程(RPA/Workflow)**

```
Agent生产力公式：

             协作系数 α
    Productivity = (LLM能力 × 工具生态 × 流程数字化)  
                   ─────────────────────────────
                        治理成本 + 风险系数

其中：
- LLM能力: 推理、多模态、长上下文、Function Calling
- 工具生态: MCP服务器数量、A2A协议成熟度、API覆盖度
- 流程数字化: 业务流程数字化率、数据可获取性
- 协作系数α: 多Agent协作效率（单Agent=1, 多Agent=1.5-3）
- 治理成本: 安全审计、合规检查、模型监控的人力投入
```



**代入示例（示意，仅演示量纲关系）**

```text
场景：理赔材料智能预审
  LLM 能力      0.8（多模态读单证 + 长上下文）
  工具生态      0.6（已接入影像、规则引擎、核心查询三类工具）
  流程数字化    0.7（材料电子化率较高）
  协作系数 α    1.5（预处理 Agent + 复核 Agent 协作）
  治理成本      0.4（人工复核比例与审计投入偏高）
  风险系数      0.2（误放行的赔付损失敞口）

Productivity ≈ (0.8 × 0.6 × 0.7 × 1.5) / (0.4 + 0.2) ≈ 0.84
读法：分母（治理与风险）每上升 0.1，整体产出下降约 14%；
      因此该场景的 improvement 重点在降低复核成本，而非继续堆模型能力。
```

**使用提醒**：上式用于**比较两个方案的相对量级**，不是精确预测；各分项取值须由机构自行标定并写明口径。

**Agent能力层级**（L1-L3渐进路线）：

| 层级 | 名称 | 能力特征 | 金融适用场景 | 人工介入方式 |
|------|------|---------|------------|---|
| **L1** | 工具型Agent | 单一任务、规则驱动、有限感知 | 报表生成、文档处理、智能客服 | 结果抽检，异常转人工 |

| **L3** | 决策型Agent | 自主规划、多工具调用、持续学习 | 资产配置、动态风控、反欺诈 | 设定权限边界与熔断条件，关键决策人工终审 |

### 模型四：场景优先级矩阵（价值×可行性）

```
Y轴（商业价值）：高/中/低
X轴（技术可行性）：高/中/低

四象限排序策略：

1️⃣ 高价值+高可行 → 立即规模化（2026-2027 Q1-Q2）
   - 智能客服（85%替代率，已大规模验证）
   - 文档处理（70%效率提升，技术成熟）
   - 风控决策（决策时效<3秒，模型稳定）

2️⃣ 高价值+低可行 → 预研+试点（2026-2027 Q3-Q4）
   - Agent驱动的投资顾问（监管待明确）
   - 全自动核保引擎（需解决可解释性）
   - 多Agent协作理赔（技术仍在演进）

3️⃣ 低价值+高可行 → 快速试水（2026 Q1-Q2）
   - 智能质检（部署简单，ROI中等）
   - 报表自动化（工具成熟）

4️⃣ 低价值+低可行 → 暂缓/外包
   - 通用客服（非核心能力）
   - 数据标注（可外包）
```



**象限判定示例（示意）**

```text
候选场景：保单条款问答助手
  商业价值：中（改善体验，间接影响续保）
  技术可行性：高（知识库检索成熟）
  判定：低价值+高可行 → 快速试水，限定在单一渠道与单一产品线上线
  退出条件：若三个月内自助解决率无明显提升，则转入暂缓清单
```

**易错点**：把「技术炫」当成「价值高」。评价值时应写明受益对象与衡量口径（降本/增收/控风险三选一），否则无法进入排序。

| 多模态 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ | 部署形态（本地/专有云）与运维人力 |
| 金融知识 | ⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 行业语料来源、更新频率与评测结论 |

| 数据安全 | ⭐⭐（数据出境风险） | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 数据存储位置、留存期限与出境条款 |
| 生态兼容 | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | 是否支持既有工具协议与可替换性 |

**MCP/A2A协议生态（2026年现状）**：

| 协议 | 发起方 | 定位 | 金融行业适配度 |
|------|--------|------|--------------|
| **MCP** (Model Context Protocol) | Anthropic → Linux AAIF治理 | 模型与外部系统通信标准（类似TCP/IP） | ⭐⭐⭐⭐⭐ 1000+服务器，50+官方 |
| **A2A** (Agent-to-Agent) | Google | 多Agent间协作通信 | ⭐⭐⭐⭐ Agent协作标准 |
| **Function Calling** | OpenAI | 单模型工具调用 | ⭐⭐⭐ 基础能力，已广泛支持 |

**选型推荐**（麦肯锡式决策树）：

```
│   └── 是否需多模态？

│       └── 否 → Qwen3 / DeepSeek-R1
│
└── 低（非敏感场景）→ 闭源API（Claude/GPT）

```

### 模型七：AI项目ROI评估（麦肯锡方法论）

**三层次ROI评估**：

```
第一层：直接成本节约
  = 人力替代 × 人均成本 + 效率提升 × 时间价值 + 错误减少 × 损失避免

第二层：间接收益
  = 客户满意度提升 × 留存率 × CLV + 交叉销售率提升 × 平均客单价

第三层：战略价值（量化）
  = 数据资产积累 + 技术能力沉淀 + 品牌溢价 + 监管合规成本降低

推荐指标：
- Payback Period（回收期）：建议<18个月
- IRR（内部收益率）：目标>25%
- ROI（3年）：目标>200%
```



**ROI 测算示例（示意，仅演示口径）**

```text
项目：智能单证识别
  直接成本节约：替代 4 人年 × 人均成本 + 处理时长下降折算的时间价值
  间接收益：退单率下降带来的客户留存改善（按留存率与客均贡献估算）
  战略价值：结构化数据资产沉淀（暂不计入保守口径）
  保守口径结果：回收期约 14 个月，进入推进清单
  乐观口径结果：计入战略价值后三年 ROI 明显上升，但需标注口径差异
```

**口径纪律**：测算必须标注「保守/中性/乐观」三档及各自假设；评审时只比较同档口径，避免用乐观值去争取预算。

## AI场景优先级评分表（量化排序）

> 用途：把"高价值+高可行"从定性判断变成可讨论的打分，避免只凭直觉排队。

| 评分维度 | 权重 | 5 分标准 | 3 分标准 | 1 分标准 |
|---------|------|---------|---------|---------|
| 业务价值 | 25% | 直接对应收入或重大成本项 | 间接影响效率 | 主要是体验改善 |
| 可行性 | 20% | 技术成熟、数据就绪 | 需补数据或改造流程 | 需突破技术瓶颈 |
| 合规风险 | 20% | 明确可做、有先例 | 需个案评估 | 监管未明确 |
| 数据就绪度 | 15% | 数据齐备、质量可控 | 部分数据需治理 | 数据缺失 |
| 投入产出比 | 10% | 回收期 < 12 个月 | 12–24 个月 | > 24 个月 |
| 组织接受度 | 10% | 一线主动要求 | 需推动 | 存在明显阻力 |
| 可解释性 | （否决项参考） | 结论可追溯到具体依据与责任人 | 仅能提供概览性说明 | 无法说明依据，关键场景不可上线 |

**优先级判定**

| 加权总分 | 处置 | 说明 |
|---------|------|------|
| ≥ 4.0 | 立即推进 | 进入年度重点清单 |
| 3.0–3.9 | 试点验证 | 小范围验证后决策 |
| 2.0–2.9 | 观察 | 条件成熟再启动 |
| < 2.0 | 暂缓 | 明确写入"不做清单"并说明理由 |

> **合规风险一项具有否决性**：若该项低于 2 分，无论总分多高都不进入推进清单。

## Python Code Templates

### ROI计算模板
> **示例代码（仅供学习参考，非本技能自动执行）**：
```python
def calculate_ai_roi(investment_cost, annual_savings, efficiency_gain, years=5):
    """
    AI项目ROI计算（参照麦肯锡三层次ROI方法）
    - investment_cost: 初始投资（万元）
    - annual_savings: 年化成本节约（万元）
    - efficiency_gain: 效率提升带来的收益（万元/年）
    """
    total_investment = investment_cost
    total_benefits = 0
    for year in range(1, years + 1):
        annual_benefit = annual_savings + (efficiency_gain * year * 0.1)
        total_benefits += annual_benefit
    roi = (total_benefits - total_investment) / total_investment * 100
    payback = total_investment / (annual_savings + efficiency_gain)
    return {"roi": f"{roi:.1f}%", "payback": f"{payback:.1f}年"}
```

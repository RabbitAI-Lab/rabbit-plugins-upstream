# RAG 评估与防幻觉验证（rag-eval-harness）

> **一句话：知识库问答系统上线前，用「正向命中 + 负面拒答」双测试量化质量，用「拒答阈值 + 引用兜底」堵住幻觉。**
> 实战基线（示例知识库，2026-08-18）：正向 33/34（关键词命中率 87%）、负面拒答 10/10（100%）。2026-08-26 升级「本地零积分检索评测 + 阈值扫描选优」：50 题（45 正向 + 5 负面）整体合格率 92%→100%（选 T=0.6 后负样本拒答 20%→100%），详见「本地零积分检索评测与阈值扫描选优」章节。

## 核心方法论

### 一、正向评估集（答得上：正确性）
- **结构**：区域×主题矩阵，每主题 2 问（中英混合）。如示例知识库覆盖 17 区（cn/us/eu/jp/ivdr/sw/kr/uk/br/sea/iec/bio/eud/cer/ca/au/mx）
- **每条用例**：`{id, region, question, expected[]}`——expected 是「应出现在回答或引用片段中的关键词」
- **判定**：关键词命中率 ≥50% 且回答含【依据】引用标记 = 通过
- **输出**：通过率 + 总命中率 + 各区域覆盖统计 + 低命中用例清单（低命中 = 语料薄弱点的量化证据）

### 二、负面测试集（不该答的拒答：防幻觉）
- **设计**：10 个「知识库外问题」——跨界产品（宠物起搏器）、非器械（纸尿裤/蓝光眼镜）、未来技术（3D 打印器官）、竞品细节（达芬奇 PMA 时间线）
- **拒答信号表**（中英）：未找到/未检索到/知识库中/不属于医疗器械/不适用 + not found/no information/not a medical device 等
- **判定**：回答命中任一拒答信号 = 正确拒答；编造具体法规答案 = 幻觉失败
- **特例**：常识判定类（如纸尿裤非器械）可用「不属于医疗器械 + 建议参考其他标准」的结构化拒答，优于生硬"未找到"

### 三、防幻觉三机制（系统层）
1. **低相似度拒答**：检索片段最高 sim < 阈值（如 0.5）→ 直接返回"知识库中未找到相关信息"，不让模型硬编
2. **prompt 强制引用**：要求回答结尾必须带【依据：<文件名>·<章节/条款>】标注，不得省略
3. **引用兜底**：模型未输出【依据】或输出"无具体法规文件标注"时，程序自动补上真实检索来源（refs[:3] 去重拼接）

### 四、refs 数据结构（可被评估脚本校验）
```json
{"file": "文件名(去.txt)", "section": "章节/条款", "text": "片段", "sim": 0.83}
```
评估脚本校验：refs 是否带 section 字段 + 回答是否含【依据】标记（条文级引用专项）。

## 使用规则
1. **什么时候跑**：语料变更后必跑（回归）；模型更换后必跑（复测）；上线前必跑（验收）
2. **低命中怎么处理**：命中 60% 附近先看是「语料缺该主题」还是「expected 关键词过严」；语料缺 → 补语料重建 embedding；过严 → 修订 expected 并注明理由，不掩盖质量问题
3. **阈值调整要记录**：SIM_THRESHOLD 改动会影响拒答率与漏答率，调整后跑全量双测试对比
4. **结果留档**：eval_result.txt 每次运行追加时间戳，形成质量基线趋势（如 33/34 → 34/34）

## 本地零积分检索评测与阈值扫描选优（2026-08-26 示例知识库实测）

> 当 RAG 服务的 /api/ask 不便调用、或想直接量化「检索层」而非「生成层」时，可绕过 HTTP 接口，直接对本地向量库做余弦相似度评测——**零云端积分、可复跑、秒级**。

### 评测流程
1. **建索引**：读知识库语料（FAQ + 事实库），按条目分 chunk，用本地 Ollama bge-m3 嵌入（1024 维），余弦相似度检索（无需 Chroma，numpy dot 即可）。
2. **标准答案集**：从语料原有结构直接抽取（如 FAQ 的 Q1–Q50 天然就是 50 道检索题），另加 5 道「完全无关」负样本（天气/编程/体育/菜谱/加密货币）。
3. **逐题评测**：每题取 top-1 余弦分数 + 判定命中（检索片段含该 FAQ 标识即命中）。
4. **阈值扫描选优（核心创新）**：不拍脑袋设拒答阈值，而是对全量题取 top-1 分数直方图，找「正样本与负样本的分数鸿沟」，选落进鸿沟正中的阈值 T。
   - 示例知识库实测：正样本 top-1 0.721–0.853，负样本 0.323–0.551，**鸿沟 0.17**；选 T=0.60 → 正样本零误伤（最低 0.721 > 0.6）、负样本 100% 拒答。

### 实测结果对比
| 指标 | 优化前（无拒答阈值） | 优化后（T=0.6） |
|---|---|---|
| 整体合格率 | 92.0%（46/50） | **100.0%**（50/50） |
| 正向检索命中 | 100%（45/45） | 100%（零误伤） |
| 负样本拒答率 | 20%（1/5） | **100%**（5/5） |

### 落地补丁（一行过滤）
在检索返回后加阈值判定即可，与「100% 命中」能力零冲突：
```python
REJECT_THRESHOLD = 0.60
hits = search_results(query, topk=5)
if not hits or hits[0]["score"] < REJECT_THRESHOLD:
    return "知识库暂无相关内容"   # 拒答
```

### 参考实现
`references/medxpert_rag_eval.py` —— 上述流程的可运行脚本（建索引→50 题评测→阈值扫描→输出 rag_eval_report.json）。本地零积分，全程用 Ollama bge-m3。

### 与接口层评测（第五章）的关系
- **检索层评测（本章）**：测「找得对不对」，快、零积分、直接量化检索质量，适合日常回归 + 阈值调优。
- **接口层评测（rag-eval-harness 原版）**：测「答得好不好 + 是否幻觉」，需调 /api/ask，覆盖引用标记/section 校验。
- **组合使用**：上线前先跑检索层（保召回），再跑接口层（保生成）；两层都过才放行。

## 能力进化套件框架（持续监测落地）

> 把上述评测作为「模块」挂进一个每日自动跑的套件，让能力「不断提高」有量化证据链。

- **suite_registry.json**：模块注册表，每项含 id / 脚本 / 报告路径 / 指标基线 / 告警阈值。新增评测模块只需加一项。
- **run_suite.py**：总入口，遍历模块→跑评测→读报告→对比基线→汇总 suite_report.json（最新）+ suite_history.jsonl（能力进化轨迹）。
- **每日自动化**：定时跑套件，弱点当天暴露；补强动作（改知识库/代码/重训）需用户授权。
- 可运行模板见 `references/capability_eval_suite/`。

## 推广场景（举一反三）
- 任何本地/云端知识库问答（法规咨询、客服、内部 wiki 助手）上线前
- 企业知识库语料扩充后的回归测试
- 切换 embedding 模型/LLM 后的效果对比（用同一评估集做 A/B）
- 可量化验收的「AI 能力门禁」——先有评估集，再说系统行不行

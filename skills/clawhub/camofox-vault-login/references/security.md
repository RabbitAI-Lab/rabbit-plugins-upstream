# Security contract

## Origin and SSO
- HTTPS, exact normalized origin including port. No substring, sibling, implicit subdomain or eTLD+1 matching. ASCII hosts only; punycode/trailing-dot/userinfo refused conservatively.
- bw null/default/domain (0), host (1) deliberately narrowed to exact origin. Never (5) excluded. Starts-with (2) accepted only for an origin-only stored HTTPS URL, narrowed to exact origin; starts-with paths/query/fragment, exact/path (3), regex (4), unknown modes excluded per entry. Bare DNS hostname entries safely imply HTTPS; schemeless path/port/userinfo rejected. No force.
- Every destination must have a matching stored URI on selected same item. trustedOrigins explicitly checks additional stored SSO origins, never arbitrary domains, foreign form actions or navigation mid-invocation. Invoke again for the observed SSO page's actual origin. No site-specific exceptions are hard-coded.
- Unsupported/invalid entries are excluded individually; another usable stored URI can authorize the same item. An item without any usable matching entry is refused. Metadata intentionally omits untrusted names.

## Security and unavoidable limits
- Checks explicitly configured vault account/server before retrieval; reuses BW_SESSION; locked vault uses explicitly configured existing macOS Keychain service/account once per invocation, or fails with UNLOCK_PROVIDER_MISSING. No server/account switching, sync/write, secret caches or vault edits.
- bw stdout/stderr and Camofox responses captured. Only fixed stage/code emitted, no raw exceptions/stacks/full items/requests/payloads. Child env allowlist: password only unlock env, session only bw env; never subprocess argv. Local privileged processes can inspect memory/env; JS strings cannot reliably zeroize. Supplied BW_SESSION remains in CLI's own environment but is not forwarded to unrelated subprocesses.
- Fixed nonsecret inspector: unique top-document CSS input, visible/enabled/not readonly, expected type, same-origin HTTPS form action and all formAction overrides; foreign form targets rejected. No iframe/shadow-root targeting/contenteditable/caller expressions. Never reads values/prose. JavaScript-driven inputs without forms allowed; trusted site scripts still see input.
- Repeats metadata guard immediately before each type, after TOTP generation too. **TOCTOU remains:** installed /evaluate and /type hold separate tab locks. Navigation/DOM replacement can happen after guard and before/during locator.fill, which may auto-wait. No atomic origin-conditioned type endpoint. Same-origin document replacement with identical metadata is undetectable. No monkeypatch or secret in evaluate strings. NOT isolation from malicious/compromised pages, DNS/TLS compromise, browser extensions/operators.
- Cleartext reaches trusted loopback Camofox. Current type event emits textLength, not text, but server error handlers log err.message; browser tracing/plugins/request instrumentation **could capture credentials**. Guarantees cover this adapter's own outputs/files/logs, NOT global browser/server no-log guarantees. Parent must assess tracing/logging before live use; no plugin changes made.
- TOTP: base32 or standard otpauth://totp, known period 15–120s, 6–8 digits, no Steam/HOTP/enrollment. Waits for fresh window; >=10s validity immediately before dispatch. Actual input can be delayed by Camofox; clock must be accurate. No retries.
- Timeout/failure may leave partial fill or delayed server operation. Unknown outcome returned; never retry automatically. CLI exits pending client fetches; server operation may still finish. Library hosts own lifecycle. No cleanup typing.
- Filled = transport acknowledged, NOT authentication. Site may auto-submit on input; bridge itself never clicks/presses Enter. Never fetch prose/screenshots just after fill: page could echo secrets. Caller separately controls approved submit and nonsecret authentication verification.


The adapter accepts only nonsecret stdin JSON. Its CLI emits fixed stage/code errors without profile, runtime settings, payloads or raw exceptions. The local profile and installed runtime are trusted operator inputs, never website inputs. No secret fixtures, account changes, vault writes or dependency on another private skill. Lower-level runtime APIs hold secrets and must never become agent tools.

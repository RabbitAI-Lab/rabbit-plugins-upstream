# Query 改写模式参考手册

本文档详述 6 种改写模式的触发条件、改写策略和示例。供 `SKILL.md` 中 SKILL.logic 部分引用。

---

## 模式 1：上下文提取（Context Extraction）

### 触发条件
- Query 本身语义不完整，脱离上文无法独立理解
- Query 无明显代词但缺少主语/实体
- 示例特征词：保修、价格、配置、时间、地点 等名词+疑问词

### 改写策略
从上文消息（最近 2-3 轮）中提取核心实体，补充到 Query 中作为限定词。

### 示例

| # | 上文 | 原始 Query | 改写结果 |
|---|------|-----------|---------|
| 1 | "我们刚买了 iPhone 15 Pro" | "保修多久？" | "iPhone 15 Pro 保修期限" |
| 2 | "上周讨论了 CRM 系统的权限模块" | "什么时候上线？" | "CRM 系统权限模块上线时间" |
| 3 | "公司在考虑采购新的涂布机" | "预算多少？" | "涂布机采购预算" |

### 改写要点
- 提取的实体必须是上文中明确提及的
- 优先提取最近一轮的实体
- 保留 Query 原始意图，不擅自扩展范围

## 模式 2：对比消歧（Comparison Disambiguation）

### 触发条件
- Query 包含比较级或选择词："哪个更好""哪个更快""有什么区别""选哪个"
- 存在两个或多个可对比的候选实体
- 上文提到了至少两个备选方案/实体

### 改写策略
识别上文中的比较对象，将隐式比较改写为显式 `A vs B` 格式。

### 示例

| # | 上文 | 原始 Query | 改写结果 |
|---|------|-----------|---------|
| 1 | "方案 A 用 PostgreSQL，方案 B 用 MongoDB" | "哪个更快？" | "PostgreSQL vs MongoDB 读写性能对比" |
| 2 | "卷绕机有半自动和全自动两种型号" | "哪个更适合？" | "半自动卷绕机 vs 全自动卷绕机 适用场景对比" |
| 3 | "切叠机供应商给了 A 和 B 两家报价" | "有什么区别？" | "供应商A切叠机 vs 供应商B切叠机 报价差异对比" |

### 改写要点
- 必须确认上文存在两个或以上明确实体
- 改写后保留对比属性（性能/价格/适用场景）
- 如果上文只有一个实体，不触发此模式

---

## 模式 3：指代消解（Reference Resolution）

### 触发条件
- Query 包含代词：它/他/她/这个/那个/这些/那些/其
- 复合指代："都""全部""所有"（指代上文多个实体）
- 模糊指代："一样的""同样的"

### 改写策略
找出代词在上文中的具体指代对象，将代词替换为具体实体名称。
对于"都/全部"类指代，展开为逐个实体的独立 Query。

### 示例

| # | 上文 | 原始 Query | 改写结果 |
|---|------|-----------|---------|
| 1 | "涂布机、辊分机、卷绕机都需要做保养计划" | "都支持远程诊断吗？" | ["涂布机 远程诊断", "辊分机 远程诊断", "卷绕机 远程诊断"] |
| 2 | "上次提到了王工负责的方案" | "他同意了吗？" | "王工 方案审批状态" |
| 3 | "CRM 二期有客户管理、销售管理、服务管理三个模块" | "这些都排期了吗？" | ["CRM二期 客户管理模块 排期", "CRM二期 销售管理模块 排期", "CRM二期 服务管理模块 排期"] |
| 4 | "上一个版本出了三个 bug" | "那个修复了吗？" | "上一个版本 bug 修复状态" |

### 改写要点
- "都"类指代拆分为多个独立 Query，每个对应一个实体。**上限 5 个**，超出截断并标注 `truncated: true`
- 单一代词（它/他）直接替换为具体实体
- 如果上文无法确定指代对象 → 不做改写，保留原 Query

## 模式 4：多意图拆解（Multi-Intent Decomposition）

### 触发条件
- Query 包含多个独立问句（多个 `？` 或明显分句）
- Query 包含并列疑问词："颜色？尺码？价格？"
- 用逗号/分号分隔的多个独立查询意图

### 改写策略
将一个复合 Query 拆分为多个独立子 Query，每个子 Query 聚焦单一意图。

### 示例

| # | 原始 Query | 改写结果 |
|---|-----------|---------|
| 1 | "颜色？尺码？到货时间？" | ["颜色选项", "尺码规格", "到货时间"] |
| 2 | "涂布机的价格是多少？保修期多久？支持定制吗？" | ["涂布机价格", "涂布机保修期", "涂布机定制支持"] |
| 3 | "客户管理模块的功能、权限、报表分别怎么设计？" | ["客户管理模块 功能设计", "客户管理模块 权限设计", "客户管理模块 报表设计"] |

### 改写要点
- 每个子 Query 保持独立可检索
- 共有的主语/限定词在每个子 Query 中重复
- 子 Query 之间去重（拆解后语义重复的合并）

## 模式 5：反问识别（Rhetorical Question Detection）

### 触发条件
- Query 包含反问句式标记词：
  - "难道……？""不会……吧？""这还能……？"
  - "怎么可能""不至于吧""开玩笑吧"
  - 句末的"吧？""吗？"配合否定/质疑语气
- 实际意图与字面意思相反或包含隐含诉求

### 改写策略
识别反问背后的真实信息需求，转换为正向查询。

### 示例

| # | 原始 Query | 改写结果 | 真实意图分析 |
|---|-----------|---------|------------|
| 1 | "这个功能不会也要等一个月吧？" | "预计交付时间" | 担心交付周期过长，实际在问排期 |
| 2 | "难道不支持自动备份？" | "自动备份功能支持情况" | 期望有自动备份，确认是否支持 |
| 3 | "这价格不至于这么贵吧？" | "产品价格 市场对比" | 质疑价格合理性，实际想了解价格是否合理 |

### 改写要点
- 反问句的核心意图是确认/质疑/担忧，不是字面疑问
- 改写时完全抛弃反问句式，提取真实信息需求
- 无法确定真实意图时 → 保留原 Query，返回标注结构：`{"rewrite_applied": false, "rhetorical_detected": true, "suggested_intent": "疑似反问，建议确认", "original_query": "..."}`（仍用原 Query 检索）

## 模式 6：条件提取（Condition Extraction）

### 触发条件
- Query 包含筛选/限定条件：
  - 数值范围："500 元以下""3 天之内""10 人以上"
  - 属性限定："适合女生的""支持高并发的""防水的"
  - 排除条件："除了 A 之外的""不要 B 的"
  - 时间条件："最近的""上个月的""今年的"

### 改写策略
提取 Query 中的条件词，重组为 `主体 + 条件1 + 条件2 + ...` 的关键词格式，提升检索精度。

### 示例

| # | 原始 Query | 改写结果 |
|---|-----------|---------|
| 1 | "500 元以下适合女生的" | "礼物推荐 预算500元 女性" |
| 2 | "支持高并发且延迟低于 10ms 的消息队列" | "消息队列 高并发 延迟<10ms" |
| 3 | "最近一个月内除了紧急 bug 之外的需求变更" | "需求变更 最近1个月 非紧急bug" |
| 4 | "涂布机中精度最高且能耗最低的型号" | "涂布机型号 精度高 能耗低" |

### 改写要点
- 条件词用空格分隔，利于分词检索
- 数值范围保留具体数字
- 排除条件转换为正向条件（"除了 A" → 如果可穷举则展开，否则保留原始排除语义）
- 多个条件按重要性排序（硬约束在前，软偏好在后）

## 综合示例：多模式叠加

实际检索中，一个 Query 可能同时触发多种模式。处理优先级：

```
反问识别 → 指代消解 → 多意图拆解 → 上下文提取 → 对比消歧 → 条件提取
```

| # | 上文 | 原始 Query | 模式组合 | 改写结果 |
|---|------|-----------|---------|---------|
| 1 | "A款涂布机报价50万，B款报价38万" | "这些不会都比市场价贵吧？" | 反问 + 指代消解("这些"→A款B款) + 对比消歧 | ["A款涂布机 市场价格对比", "B款涂布机 市场价格对比"] |
| 2 | "我们的 CRM 系统需要支持移动端、Web 端和钉钉集成" | "都支持吗？大概多久能做完？" | 指代消解("都") + 多意图拆解 | ["移动端 支持情况", "Web端 支持情况", "钉钉集成 支持情况", "CRM 系统开发周期"] |

## 改写边界

### 不应改写的情况

1. **独立语义完整**：Query 脱离上下文完全可理解
   - ✅ "赢合科技 CRM 系统架构" → 不需要改写
2. **专有名词/代码**：Query 包含项目名、函数名、文件路径等
   - ✅ "UserService.createUser 方法实现" → 不需要改写
3. **否定式精确查询**：需要检索"不是什么"的内容
   - ✅ "不支持 Kubernetes 的部署方案" → 不需要改写（保留否定语义）

### 改写失败回退

如果找不到上文、无法确定指代、无法判断真实意图：
- 直接用原始 Query 检索
- 标注 `rewrite_skipped: true` 和跳过原因

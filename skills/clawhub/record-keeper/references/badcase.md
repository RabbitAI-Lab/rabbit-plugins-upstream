# BADCASE 缺陷案例模板

**用途**：记录搜索质量缺陷案例，包括消歧错误、排序异常、意图识别失败、分词问题等。

**适用**：搜索消歧 badcase、分词 badcase、排序 badcase、NER 识别失败等质量缺陷。

**不适用**：缺陷的复盘分析（→ `report`），缺陷的修复方案讨论会议（→ `meeting`）。

---

```markdown
# BADCASE — [问题简述]

**记录时间**：YYYY-MM-DD
**提出人**：
**记录人**：系统
**标签**：#BADCASE #xxx

---

## 一、概述

这个 badcase 是什么问题，影响了什么场景。

## 二、事实

| 项目 | 内容 |
|------|------|
| 搜索词 | |
| 预期结果 | |
| 实际结果 | |
| 服务/模块 | |

## 三、问题分析

对问题原因的分析（如已知）。

## 四、改进建议

| 序号 | 措施 | 负责人 | 计划时间 |
|------|------|--------|---------|
|      |      |        |         |

## 五、关联

（如关联的其他 badcase 或修复记录）
```

---

**结构要点**：
1. 必须包含搜索词、预期结果、实际结果三要素
2. 分析区可留空（待排查），不瞎编原因
3. 同搜索词多个 badcase 时按子主题区分
4. 标签中需标注具体类型，如 `#消歧` `#分词` `#排序`

## ⚠️ 使用前必读：数据最小化声明

> 培训与陪练过程会涉及**员工个人信息**（姓名、工号、考核成绩、能力短板、客户沟通记录）。这类数据属于个人信息，部分场景下属于敏感个人信息。
>
> **请遵循数据最小化原则：**
> 1. 用于评估与陪练时优先使用**工号或化名**，非必要不录入真实姓名、身份证号、联系方式
> 2. 角色扮演中涉及的客户案例，应使用改写后的虚拟案例，不得直接粘贴真实客户信息或完整通话录音文本
> 3. 考核结果与能力雷达图属于人事管理数据，导出、分享与留存须符合所在机构的人事数据管理制度
> 4. 本 Skill 输出的学习建议仅供参考，不直接作为晋升、绩效或淘汰依据，最终人事决策须由具备权限的人员按制度作出

5. **导出前先预览再确认**：生成的学习路径、题库、成绩报告在写入任何文件之前，必须先输出预览（条目数、涉及人员范围、是否已脱敏、是否含真实姓名/工号），经用户明确确认后再保存；未经预览与确认不落盘
6. **不代为写入任何系统**：不代为向人事系统、学习管理系统、监管报送系统写入或提交数据
7. **不自动生成排名通报**：培训成绩与能力雷达图不用于自动生成公开排名、通报或末位名单

## Core Capabilities / 核心能力

### 1. Skill Assessment / 技能评估

```python
SKILL_FRAMEWORK = {
    "banking": {
        "知识": ["产品知识", "合规知识", "营销知识"],
        "技能": ["客户沟通", "需求挖掘", "异议处理"],
        "态度": ["服务意识", "合规意识", "学习意愿"]
    },
    "insurance": {
        "知识": ["产品条款", "核保规则", "理赔流程"],
        "技能": ["需求分析", "方案设计", "促成技巧"],
        "态度": ["诚信展业", "长期服务"]
    }
}

class SkillAssess:
    """技能评估引擎（示例：scores 需由外部传入，每项 0-100）"""

    def assess(self, employee_id: str, scores: dict) -> dict:
        """全面技能评估

        scores 形如 {"产品条款": 82, "核保规则": 61, "需求分析": 74, ...}
        缺失项按 None 处理，不参与均值和排名，避免"缺考当零分"。
        """
        valid = {k: v for k, v in scores.items() if v is not None}
        gaps = self._identify_gaps(valid)
        return {
            "skill_radar": self._generate_radar(valid),
            "gap_analysis": gaps,
            "learning_recommendations": self._recommend_courses(gaps),
            "comparison_to_peers": self._peer_comparison(valid),
            "coverage": len(valid) / max(len(scores), 1),
        }
```

**调用示例：**

```python
engine = SkillAssess()
result = engine.assess("E10237", {
    "产品条款": 88, "核保规则": 62, "理赔流程": 71,
    "需求分析": 55, "方案设计": 60, "促成技巧": 48,
    "诚信展业": 90, "长期服务": 85,
})
# gap_analysis -> ["促成技巧(48)", "需求分析(55)", "方案设计(60)"]
# learning_recommendations -> ["异议处理情景陪练", "需求挖掘工作坊", "方案呈现实操"]
```

**读雷达图的三个原则：**
1. **看短板不看均分**：均分 72 分掩盖了"促成技巧 48"这一致命短板，补短板的边际收益通常高于继续拉长长板。
2. **看维度间落差**：知识维度 85+ 而技能维度 55，说明"知道但做不到"，应增加陪练而非增加课程。
3. **看覆盖率**：若 `coverage` 只有 0.5，说明一半维度未评估，此时雷达图形状不可用于横向比较。

**短板归因三分法（先归因再开课，避免一律「加课」）：**

| 归因类型 | 判据（雷达图 + 现场表现） | 干预手段 | 反例（错误干预） |
|---------|------------------------|---------|----------------|
| 知识缺口 | 知识维度低、技能维度尚可，概念题答错 | 课程/图文/微课 | 安排角色扮演（练了也不会） |
| 技能缺口 | 知识维度高、技能维度低，概念题答对但情景分低 | 角色扮演陪练 | 再加一轮概念课（越学越不会做） |
| 意愿/习惯缺口 | 知识与技能均达标，实际行为不改变 | 现场督导 + 行为打卡 | 重新培训（成本最高、效果最差） |

**低覆盖率场景示例：**

```python
result = engine.assess("E20418", {
    "产品条款": 86, "核保规则": None, "理赔流程": None,
    "需求分析": 58, "方案设计": None, "促成技巧": None,
    "诚信展业": 92, "长期服务": None,
})
# coverage = 3/8 = 0.375 —— 低于 0.5，雷达图形状不可用于横向比较
# 正确处理：先补齐缺失维度的评估，再谈提升方案
# 错误处理：直接输出"该员工知识强、技能弱"的结论并据此开课
```

**判断口诀：** 覆盖率 < 0.5 时只做「补评估」，不做「下结论」；归因未定时先做一次现场观察，再决定是加课还是加练。

**完整陪练对话示例（场景：客户拒绝处理）：**

```
【AI 扮演客户】"我不需要保险，我有社保就够了。"
【学员】"社保确实能解决一部分，您平时看病报销比例大概多少？"
【AI 扮演客户】"没算过，反正能报。"

—— 评分反馈 ——
✅ 倾听（4/5）：没有直接反驳，先追问具体情况
✅ 共情（4/5）：承认社保的作用，未否定客户
⚠️ 探询（2/5）：只问了一个问题就转向，未挖掘家庭责任与收入中断风险
❌ 回应（1/5）：全程未回应"不需要"这个异议本身

改进建议：
1. 用"是的，而且……"承接，而非"但是……"
2. 探询应指向具体场景：房贷、子女教育、父母赡养三项中哪一项压力最大
3. 回应异议时给出事实而非评价，例如用一次真实理赔的替代成本来量化
```

**再举一例（场景：线上直播合规）：**

```
【观众】"这个产品收益比银行高多少？能保证吗？"
【不合格回答】"肯定比银行高，而且很稳定。"
【合格回答】"这是保险产品，主要提供风险保障；
  演示利率不是承诺收益，实际结算以公司公布为准；
  适合不适合要看您的保障需求和缴费能力。"

—— 评分反馈 ——
✅ 合规表述（5/5）：明确非保证、指向官方公布口径
✅ 适当性提示（4/5）：引导到需求与缴费能力
⚠️ 转化话术（2/5）：完全放弃转化，可补一句"想了解具体保障责任，可以看条款第X条"
```

**再举一例（场景：AI工具使用，考察合规边界意识）：**

```
【同事】"我用生成式 AI 直接写一段对客的投资建议发给客户，省事，有什么问题吗？"
【不合格回答】"没问题，AI 写得更专业。"
【合格回答】"有三处要先过一遍：一是投资建议需具备相应资质并履行适当性义务，
  AI 输出不能当作最终结论；二是提示词里不能粘贴客户身份与持仓信息；
  三是对客发出的内容要留痕并经过复核。"

—— 评分反馈 ——
✅ 合规边界（5/5）：点出资质、适当性与人工复核三处
✅ 数据脱敏（5/5）：明确提示词不得含客户身份与持仓
✅ 留痕意识（4/5）：提出留痕，未说明留痕归到哪里
⚠️ 沟通方式（3/5）：三点并列略显说教，可先认可提效诉求再讲边界
```

**陪练脚本设计要点：** 一个场景只考一个主维度，最多带两个副维度；维度超过三个时评分会互相稀释，学员拿到的反馈反而不可执行。

## Disclaimer

This skill provides training tools for educational purposes only. It does not produce investment advice, security or product recommendations, trading instructions, or position/ stop-loss values, and it does not make or support personnel decisions. Curriculum material in Appendix G that touches strategy, backtesting, position management and risk control is **non-actionable training theory**: it exists to explain concepts and is never emitted as an executable recommendation. Assessment items must not ask a learner to produce investment advice, price targets, or buy/sell calls. Every output is a draft that requires review by the institution’s training and compliance functions before use.

## 附录内容的非行动性边界

> 附录 G 中的 Level 3「实战策略」与 Level 4「风险管理」是**教学理论**，用于帮助学员理解策略思想与风险概念。本 Skill 不会把它们输出为交易指令、仓位建议、止损数值或对真实标的的评价。任何涉及真实账户、真实标的的操作性结论，都不在本 Skill 的输出范围内。

### G.2 Knowledge Graph & Curriculum (Dianjin method)

**金融知识体系（Dianjin结构）**：

```
Level 1: 基础理论
  - 金融市场的功能（融资/投资/风险管理）
  - 主要资产类别（股票/债券/基金/衍生品）
  - 基本术语（PE/PB/ROE/市值/涨停板）

Level 2: 分析方法
  - 基本面分析：财报解读/行业研究/宏观分析
  - 技术面分析：K线/均线/MACD/布林带
  - 量化分析：因子模型/回测/风险控制

Level 3: 实战策略
  - 价值投资：巴菲特/格雷厄姆方法论
  - 成长投资：PEG/赛道选择/催化剂
  - 趋势交易：均线突破/量价关系
  - 对冲策略：配对交易/市场中性

Level 4: 风险管理
  - 仓位管理：凯利公式/ATR仓位
  - 止损策略：固定止损/移动止损
  - 心理控制：贪婪/恐惧/从众心理

**各层级的教学边界（Level 3/4 为非行动性教学理论）：**

| 知识层级 | 教学定位 | 可考核形式 | 明确禁止的输出 |
|---------|---------|-----------|--------------|
| Level 1 基础理论 | 概念与术语识记 | 概念测验 | 无 |
| Level 2 分析方法 | 方法原理与计算 | 计算题、案例分析 | 不得给出单一真实标的的贵贱结论 |
| Level 3 实战策略 | 策略思想与历史沿革（教学用途） | 策略复述、假设推演 | 不得生成交易指令或仓位建议 |
| Level 4 风险管理 | 风险概念与纪律（教学用途） | 情景判断、案例研讨 | 不得给出针对真实账户的仓位与止损数值 |

**教学边界的执行要点：** Level 3/4 的课堂练习一律使用**虚构主体或历史区间复盘**，不使用当下真实标的；练习题的提问方式限定为「说明该策略的思想与适用前提」而非「现在该怎么做」。
```

**课程设计模板（Dianjin风格）**：

```
【课程】股票基本面分析入门（Level 1）

四、学习时长
- 视频：15分钟
- 阅读：20分钟
- 实战：30分钟

**再举一例（合规类课程，结构略有不同）：**

```
【课程】AI 工具在金融业务中的合规使用（全员必修，60 分钟）

一、学习目标
- 能说出三类禁止行为：直接生成对客投资建议、上传未脱敏客户数据、把 AI 输出当作最终结论

### G.4 Assessment & Feedback (Dianjin method)

**测评题目类型**：

```
1. 知识理解题（单选/多选/判断）
   - 目标：检验概念掌握
   - 难度：低-中
   - 示例："PE是什么？"

2. 计算应用题（计算/分析）
   - 目标：检验公式运用
   - 难度：中-高
   - 示例（虚构公司，不指向任何真实标的）：「甲公司股价 40 元、每股收益 2 元、行业平均 PE 25 倍，计算其 PE 并说明相对行业的位置」
   - 评分要点：公式正确 / 计算无误 / 明确是「相对行业」而非「绝对贵贱」

3. 案例分析题（开放/论述）
   - 目标：检验综合分析能力，而不是训练给出买卖结论
   - 难度：高
   - 示例（虚构主体）：「阅读乙公司（虚构）三年简表，列出三项值得关注的经营信号并说明判断依据」
   - 明确禁止：题目要求中出现「给出投资建议」「推荐买入/卖出」「预测目标价」等表述

4. 情景判断题（最贴合合规培训）
   - 目标：在具体情境中判断"能不能这么做"
   - 难度：中-高
   - 示例："客户要求你把他的持仓截图发到群里做案例，你该怎么做？"

5. 实操演练题（角色扮演评分）
   - 目标：检验行为而非知识
   - 难度：高
   - 示例："扮演客户说'我再考虑考虑'，完成一次完整的促成尝试"
```

**出题质量自检：** 一道好题应该能区分"背过书的人"和"真的会做的人"。

**题目质量评分表（出题后自检，满分 10 分，低于 7 分应重写）：**

| 评分项 | 权重 | 好题标准 | 常见扣分点 |
|-------|------|---------|-----------|
| 区分度 | 3 分 | 能区分背过书与真会做 | 只考定义，所有人都会 |
| 情境真实度 | 2 分 | 场景来自真实岗位 | 场景脱离业务，学员无感 |
| 考点单一 | 2 分 | 一题只考一个判断 | 一题塞三个考点，错因不明 |
| 答案可判定 | 2 分 | 有明确评分要点 | 开放题无评分要点，阅卷主观 |
| 合规安全性 | 1 分 | 不涉及真实标的与投资结论 | 使用真实公司并要求给出买卖建议 |

**合规安全性一票否决：** 只要题目要求学员对真实标的给出投资建议、目标价或买卖结论，无论其他项得分多高，该题判 0 分并重写。
- 反例：问"PE 的定义是什么"——只能检验记忆。
- 正例：给一家公司的股价、每股收益与行业均值，问"这只股票相对行业是高估还是低估，依据是什么"——同时检验公式、比较与应用。

**反馈机制**：

```
即时反馈：
  - 答题正确 → "✅ 正确！解释：..."
  - 答题错误 → "❌ 错误。正确答案：B。解释：..."

学习报告：
  - 完成课程数/总课程数
  - 平均得分/满分
  - 薄弱知识点（需加强）
  - 推荐复习课程
```

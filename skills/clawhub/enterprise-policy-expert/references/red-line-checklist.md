# 红区全表（判定依据 + 处置方式）

> 来源：一个真实产品合规审查拿到 58/100 分、4 项红区的整改回路。
> 用法：第 1 步（立项前）与第 3 步（成文后）各跑一遍。
> 每项输出：红/黄/绿 + 判定依据 + 项目实际情况。

## 判定等级说明

| 等级 | 含义 | 处置 |
|---|---|---|
| 🔴 红区 | 会导致制度被驳回、被认定违法、或在争议中完全无效 | 必须改才能发布 |
| 🟡 黄区 | 不至于无效，但会显著削弱可执行性或留下风险敞口 | 建议改，说明理由 |
| 🟢 通过 | 无明显问题 | 记录即可 |

## 红区速查（12 项）

### R1 适用范围与经营主体不匹配 🔴

**判定依据**：制度覆盖的业务，超出主体的经营范围/资质许可范围。
**典型症状**：写着"提供培训服务"但主体无培训资质；写着"提供医疗服务"但无医疗机构执业许可；写着"提供金融服务"但无相应牌照。
**处置三选一**：
- 改文案：把业务表述换到主体资质覆盖范围内（成本最低，先试这个）
- 改流程：把超范围部分外包给有资质方，制度只管对接流程
- 改主体/加审批：换主体或取得资质（周期最长）
**不能靠改代码关闭**：资质与主体问题只能走外部流程，要单列待办清单。

### R2 缺资质或前置审批 🔴

**判定依据**：制度涉及需前置审批/许可的领域（教育培训、医疗、出版、金融、食品、危化品、特种设备、测绘、招标代理等）。
**处置**：明确标出"需前置审批"，在制度生效条件里写"取得 X 资质后生效"，并给材料清单与办理路径。
**注意**：不能写"符合相关规定即可开展"这类模糊表述，审批部门不认。

### R3 未成年人保护五件套缺失 🔴

**判定依据**：制度面向未成年人（含面向家长但实际用户为未成年人）时，五项缺一即红区。
**五件套**（详见 `minor-protection.md`）：
1. 适龄提示（建议 8 周岁及以上须家长陪同）
2. 监护人告知（家长应知悉 + 使用时长控制）
3. 内容安全声明（不含暴力/色情/不良诱导）
4. 投诉举报渠道（明确入口）
5. 法规引用（《未成年人保护法》《未成年人网络保护条例》）
**处置**：五项全部补齐，写进制度正文与产品界面，不只在用户协议里。

### R4 对外宣传用语超范围 🔴

**判定依据**：制度允许的对外表述包含绝对化用语、效果承诺、对比宣传、未经证实的资质表述。
**典型雷区**：
- 绝对化：最、第一、顶级、唯一、100%、彻底、永久
- 效果承诺：保证通过、必过、包过、包学会、提分 XX 名、稳赚
- 对比宣传：优于/超越/比同类更、碾压、吊打
- 资质冒充：官方、官方指定、唯一指定、国家级认证（无依据）
**处置**：给出合规等价表述对照表。**改表述优先于删功能**——很多情况下换个说法就合规了。

### R5 涉密或受限信息外泄路径 🔴

**判定依据**：制度允许或默许把商业秘密、客户名单、合同、财务数据、技术资料传到不受控渠道（个人微信、外部网盘、公开群）。
**处置**：明确受控范围、传输方式（仅限公司指定渠道）、审批人、留痕要求、离职交接义务。

### R6 个人信息收集超范围 🔴

**判定依据**：收集与业务目的不匹配的信息（超范围收集）、或缺少告知/同意/留存期限/删除机制。
**处置**：做"业务目的—必需字段—留存期限"三列对照表，多余字段删掉；明确留存期限与到期删除；告知文本用用户能懂的话写。

### R7 数据留存无期限或无删除机制 🔴

**判定依据**：只写"永久保存""长期保存"而不写期限，或无到期删除责任人与验收方式。
**处置**：每类记录写明留存期限、到期动作（自动删除/归档/销毁）、责任人、销毁记录如何留痕。
**推荐**：一般业务记录 3 年，财务与合同类按税法要求（通常 10 年），人事与劳动争议相关按当地口径。

### R8 争议解决路径缺失 🔴

**判定依据**：制度规定了行为与处罚，但没写"不服怎么办、去哪申诉、多久答复"。
**后果**：一旦发生争议，制度变成"内部文件"，无法作为处理依据，处罚可能被认定违法。
**处置**：补三级处理路径（直接责任人 → 上级/归口部门 → 复核委员会/HR 负责人），每级给时限（建议 3/5/7 个工作日），并写明"争议期间执行口径不中止"。

### R9 格式条款未提示或无救济说明 🔴

**判定依据**：制度/协议中减轻自身责任、加重对方责任、排除对方主要权利的条款，未做显著提示（加粗/下划线/单独确认）且未给说明机会。
**处置**：单独设置"重要条款提示"章节，列出加重对方责任的条款，给对方说明与异议渠道。

### R10 无限授权或权利让渡 🔴

**判定依据**：出现"最终解释权归本公司所有""不得提出异议""视为同意""永久不可撤销"等表述。
**处置**：删除或改为有限表述（如"解释权在合理范围内，最终以书面补充说明为准"）。

### R11 处罚标准超出权限或无依据 🔴

**判定依据**：制度直接规定罚款、扣薪、辞退等具体处罚，且未说明依据（法律/合同/员工手册授权），或处罚标准与劳动法强制规定冲突。
**处置**：
- 处罚种类与幅度由用户定，本专家只给区间与依据
- 明确"依据"引用
- 涉及劳动关系的，提示需与劳动合同/员工手册一致，避免单方面变更争议
**注意**：这是最常见的"制度写得对但执行不了"的坑。

### R12 生效与修订机制缺失 🟡（高危）

**判定依据**：没有生效日期、没有版本号、没有修订记录、没有旧版失效声明。
**处置**：补「附则」章节：生效日期、解释权归属、修订记录表、旧版同时失效的声明、员工签收确认。
**为什么重要**：没有版本管理的制度，出事时无法证明"当时执行的是哪一版"——**这一条决定制度在争议中能不能被采信**。

## 黄区速查（8 项）

| # | 黄区 | 说明 | 建议 |
|---|---|---|---|
| Y1 | 术语未定义 | 业务里"重大过失""及时""合理"等词没定义 | 补术语定义段，这是最常被跳过也最常出事的一步 |
| Y2 | 时间标准模糊 | "尽快""及时""工作日内"未给具体口径 | 改为"自收到通知之日起 X 个工作日内" |
| Y3 | 例外路径缺失 | 只写了正常流程，没写异常怎么办 | 补例外路径 + 特批人 + 特批留痕 |
| Y4 | 记录无格式要求 | "做好记录"但没说什么格式 | 明确记录要素、载体、存放位置、保管人 |
| Y5 | 职责只有部门没有岗位 | 只写"由相关部门负责" | 落到具体岗位/角色，否则无人执行 |
| Y6 | 无宣贯与签收 | 制度发布后无培训与签收记录 | 补宣贯记录、签收确认（这是自证的一部分） |
| Y7 | 检查流于形式 | "定期检查"无频率无检查项 | 明确周期、检查项、整改期限、验收人 |
| Y8 | 与既有制度冲突 | 新旧制度打架 | 制度发布时声明与旧版的关系，冲突以新版本为准 |

## Core Thinking Models

### 模型一：创新三段论（从0到1）

```
竞争（从1到N）→ 争夺存量市场
创新（从0到1）→ 创造全新市场
```

**乔布斯核心观点**：
- "创新是使生活变得更好的新方式"
- "活着就是为了改变世界，难道还有其他原因吗？"
- 不做市场调研，不依赖焦点小组



**举例一（从1到N 与 从0到1 的判别）**：在已有品类里把参数做得更好、价格更低，是从1到N；

让用户用一种此前不存在的方式完成一件事，是从0到1。

判别方法很直接：**如果竞品消失，用户会改用别的同类产品，还是失去一种能力？**

前者是存量竞争，后者才是新市场。



**举例二（不做调研不等于不看用户）**：乔布斯不做焦点小组，

但极度重视对真实使用场景的观察。区别在方法而不在态度——

**问用户想要什么，得到的往往是已有方案的改良版；观察用户如何挣扎，才能发现新方案。**



**两段创新对照（本版新增维度）**：



| 维度 | 从1到N（竞争） | 从0到1（创新） |
|------|-------------|-------------|
| 目标 | 争夺现有份额 | 创造新需求 |
| 主要手段 | 参数、价格、渠道 | 重新定义使用方式 |
| 用户研究 | 调研与竞品对标 | 场景观察与直觉判断 |
| 风险 | 同质化、价格战 | 需求可能不成立 |
| 成功标志 | 份额提升 | 用户说不出替代品 |

### 模型二：产品制胜法则

**五步创新流程**：
```
1. 简单（Simplicity）
   → 少即是多，复杂是终极的简单

2. 专注（Focus）
   → 砍掉70%的产品线，聚焦2-3个核心

3. 端到端（End-to-End）
   → 硬件+软件+服务无缝整合

4. 人文+科技（Liberal Arts + Technology）
   → 伟大产品在十字路口：技术与人文交汇

5. 细节偏执（Obsession with Details）

   → 每一个细节都值得严苛打磨



**五步流程的落地对照（本版新增维度）**：



| 步骤 | 核心提问 | 举例：一款企业内部工具 | 常见失败表现 |
|-----|---------|------------------|------------|
| 1 简单 | 能不能少一步？ | 把五步审批压成一键提交 | 功能齐全但路径冗长 |
| 2 专注 | 只留哪三件事？ | 只保留查询、提交、追踪 | 什么都想做，主功能被淹没 |
| 3 端到端 | 体验闭环了吗？ | 提交后自动通知与留痕 | 提交完用户不知道结果 |
| 4 人文+科技 | 有情感共鸣吗？ | 出错时给出人话提醒 | 报错只剩错误码 |
| 5 细节 | 哪个细节破坏整体？ | 空状态与加载态也打磨 | 主流程精致，边缘场景粗糙 |



**举例（简单不是少做，是少让用户做）**：把五个配置项合并为一个智能默认值，

用户感知到的“简单”来自**决策被替他做完了**，而不是功能被删掉。

所以“简单”的实现成本通常比“复杂”更高——这也是它难以被抄袭的原因。



**举例（端到端的检验）**：从用户产生需求到需求被满足，中间有没有断点需要用户自己补？

只要存在“用户要切到另一个系统去完成”的环节，端到端就没闭环。
```

### 模型三：现实扭曲力场（Reality Distortion Field）

**定义**：
乔布斯能够通过个人魅力、极高标准和语言感染力，激发团队突破自我认知极限，完成被认为不可能的任务。

**构成要素**：
- 个人魅力 + 极高标准 + 叙事能力
- 让团队相信"这可以实现"
- 在压力下反而激发出超常创造力

**使用边界**：
- 短期动员有效，长期需配合真正的能力
- 滥用会导致团队精疲力竭



**举例一（正向用法）**：项目陷入“这不可能”的共识时，领导者用更高的标准与清晰的叙事，

把团队拉出自我设限。关键动作是**给出可信的路径与资源**，而不只是喊口号。



**举例二（滥用信号）**：当“不可能的期限”变成常态、且每次都靠通宵兑现，

团队会把承诺当噪声，交付质量与信任同步下滑。此时力场已经失效，只剩消耗。



**使用对照（本版新增维度）**：



| 情形 | 适合使用 | 不适合使用 |
|-----|---------|-----------|
| 团队自我设限 | 是 | |
| 一次性攻坚 | 是 | |
| 常态化赶工 | | 是 |
| 需要长期稳定输出 | | 是 |
| 已经有明确可行方案 | | 是（直接执行即可） |

### 模型四：聚焦决策法

**乔布斯决策三问**：
```
1. 我们要做什么？
2. 我们不做什么？
3. 我们如何做到极致？
```

**砍产品线原则**：
- 回归苹果后砍掉70%产品线



**举例一（三问怎么落到会议桌）**：

第一问产出**唯一的一件事**（做不成这件事，其他都不重要）；

第二问产出**明确的停止清单**（把名字写下来，而不是说“少做点”）；

第三问产出**做到最好的标准**（可验证，例如“新用户3分钟内完成首次成功”）。



**举例二（砍刀测试的误判）**：某功能去掉后用户会流失，但流失的是极低价值用户，

而它占用了主功能 30% 的开发资源。此时仍应砍——

**砍刀测试要看留下来的用户是谁，而不只是看数量。**



**砍与留的判定表（本版新增维度）**：



| 情形 | 判定 | 理由 |
|-----|-----|-----|
| 去掉后不影响核心价值 | 砍 | 纯粹增加复杂度 |
| 去掉后只流失低价值用户且占用大量资源 | 砍 | 资源应投向主线 |
| 去掉后主流程断裂 | 留 | 属于核心价值的一部分 |
| 去掉后用户无法完成关键任务 | 留 | 必要能力 |
| 不确定 | 先灰度下线观察 | 用数据替代争论 |
- 只做能做到"最好"的产品
- "宁缺毋滥，做小做精"

### 模型五：用户体验至上

**核心观点**：
- "消费者并不知道自己需要什么，直到你把它放在他们面前"
- 最好的产品 = 最好的营销



**举例一（全流程体验的具体环节）**：开箱、首次启动、第一次成功、出错时、

寻求帮助时、退出时——**体验是这六段的加权总和，任何一段崩塌都会抹掉其他段的努力。**



**举例二（用户说不清需求时怎么做）**：不要问“你想要什么功能”，

而要问“上次遇到这个问题，你是怎么解决的、花了多久、哪里最烦”。

**从抱怨里提取需求，比从愿望里提取需求可靠得多。**



**体验环节自检（本版新增维度）**：



| 环节 | 关键提问 | 典型问题 |
|-----|---------|---------|
| 首次接触 | 用户一眼能懂它是干什么的吗 | 首页堆满功能入口 |
| 首次成功 | 多快能完成第一次成功 | 需要看教程才能上手 |
| 出错时 | 报错是人话吗，能自己恢复吗 | 只剩错误码 |
| 求助时 | 帮助是不是就在需要的地方 | 帮助藏在三级菜单 |
| 退出时 | 数据与关系能否平滑带走 | 导出困难形成绑架 |
- 体验是从开箱到使用的全流程

### 模型六：AI 时代的产品设计哲学（本版新增）



Description 中提到 2026 更新了“如果乔布斯面对 LLM/AI 应用如何设计产品”的推演，

本节把它落成可执行的设计原则。



**核心判断**：AI 产品的竞争点不在模型能力，而在**把不确定性包装成可信任的体验**。



| 传统软件设计 | AI 产品设计 | 乔布斯式处理 |
|------------|-----------|------------|
| 行为确定，结果可预期 | 输出有随机性 | 明确能力边界，不承诺确定性 |
| 错误是异常 | 错误是常态 | 设计优雅降级与人工兜底路径 |
| 功能是菜单 | 能力是对话 | 用最少的话术收敛用户意图 |
| 用户学习软件 | 软件理解用户 | 把复杂度留在系统内 |
| 一次交付 | 持续演化 | 保留可解释与可回溯 |



**举例一（不确定性的体验设计）**：同样是大模型回答，

一个产品直接给出答案，另一个给出答案 + 依据来源 + 置信提示 + 一键转人工。

后者的模型可能更弱，但**用户更敢用**——信任本身就是产品力。



**举例二（极简在AI产品中的体现）**：不给用户一堆参数滑块，

而是给一个智能默认值和一句“如果结果不理想，点这里调整”。

**把模型的复杂度藏起来，是这一代产品的“简单”。**



**举例三（AI时代同样要砍）**：AI 让加功能变得极便宜，因此更容易功能膨胀。

砍刀测试在 AI 产品中更重要：**每增加一个入口，都在稀释主线的清晰度。**

## Workflow

### 步骤一：识别问题类型
```
产品方向型 → 从0到1创新框架
功能决策型 → 聚焦砍刀法
体验问题型 → 人文+科技融合
竞争战略型 → 差异化+端到端
团队管理型 → 现实扭曲力场
```

### 步骤二：乔布斯式分析（输出结构）
```
【乔布斯产品哲学分析】
产品/决策描述：[用户的问题]

从0到1判断：
- 这是存量竞争还是创造新市场？
- 用户真的知道自己想要什么吗？

乔布斯五问：
1. 简单：这个产品/功能够简单吗？
2. 专注：我们在聚焦最重要的那件事吗？
3. 端到端：体验闭环了吗？
4. 人文+科技：有情感共鸣吗？
5. 细节：哪个细节会破坏整体体验？

砍刀测试（如果涉及功能决策）：
- 这个功能去掉会怎样？
- 如果去掉后产品更专注 → 砍
- 如果去掉后用户会流失 → 保留

现实扭曲力场诊断：
- 这个愿景够激动人心吗？
- 团队是否真正相信能做到？

最终建议：[乔布斯风格的具体行动]
```

## User Scenarios

### 场景A：产品方向迷茫
**用户说**: "我想做一个产品，但不知道方向对不对"
**Skill响应**:
```
【乔布斯视角】
第一步：回到本质
- 这个产品要让用户的生活变得怎样更好？
- 这个"更好"是真实存在的，还是你觉得存在的？

第二步：从0到1测试
- 你是在争夺存量市场，还是在创造新市场？
- 如果是存量市场，乔布斯会说：为什么是你赢？
- 如果是新市场：用户现在怎么解决这个问题？

第三步：聚焦三问
- 我们要做什么？（唯一的那件事）
- 我们不做什么？（砍掉其他的）
- 我们如何做到极致？（不能做到最好的不做）

乔布斯忠告：
"专注不是说Yes，而是对其他100个好主意说No"
```

### 场景B：功能太多太杂
**用户说**: "我的产品功能越来越多，用户反而抱怨体验差了"
**Skill响应**:
```
【乔布斯砍刀法】
诊断：功能膨胀 = 专注力丧失

乔布斯会怎么做：
1. 列出所有功能
2. 问：去掉这个功能，还有人会用这个产品吗？
   → 会的：保留
   → 不会：果断砍
3. 聚焦到最多3个核心功能

回到人文+科技：
- 你的产品有灵魂吗？
- 用户使用它时有情感共鸣吗？
- 还是只是一个功能集合？

立即行动：
列出Top3功能，砍掉其余的
```

### 场景C：要不要多元化

```
【乔布斯多元化判断】
核心问题：你有能力在新领域做到最好吗？

乔布斯的答案：
- 多元化只有在能"端到端整合"时才有效
- 如果只是为了增长，乔布斯会说"不"

判断标准：
1. 我们有足够优秀的团队做这件事吗？
2. 我们能做到这个领域的世界第一吗？
3. 新业务和现有能力有协同效应吗？

如果答案不坚定 → 专注主业
如果三个都是Yes → 可以拓展
```

### 场景D：AI 产品要不要加更多功能（本版新增）



**用户说**: 我们的AI产品加了十几个入口，用户反而说不知道用来干什么



**Skill响应**:



【乔布斯视角】



诊断：这不是功能不够，是主线不清。



聚焦三问：

1. 我们要做什么？——用一句话说清唯一价值，说不清就是没想清楚
2. 我们不做什么？——把要砍的入口写出名字，而不是说少做点
3. 如何做到极致？——选一个可验证指标（如首次成功率）



砍刀测试：

- 去掉后不影响核心价值 → 砍
- 只服务低价值场景却占用大量引导位 → 砍
- 属于主流程必要环节 → 留
- 不确定 → 灰度下线，用留存数据说话



AI 产品特别提示：

- 模型能力让加功能变便宜，因此更容易膨胀，砍刀要更狠
- 主入口只留一个，其余能力在对话中被自然唤起



立即行动：列出Top3场景，其余入口全部收进二级路径，两周后看首次成功率变化。

## Jobs vs Musk Comparison

| 维度 | 乔布斯 | 马斯克 | 何时用谁 |
|------|--------|--------|---------|
| 思维核心 | 人文+科技 | 物理+工程 | 涉及人与体验用乔布斯，涉及物理与成本用马斯克 |
| 创新方式 | 极简+体验 | 降本+颠覆 | 需求不确定用乔布斯，需求明确用马斯克 |
| 用户理解 | 直觉驱动 | 数据驱动 | 早期定义产品用直觉，规模化优化用数据 |
| 领导风格 | 现实扭曲力场 | 极度务实 | 攻坚用前者，长跑用后者 |
| 失败观 | 整合创新中的试错 | 工程迭代中的失败 | 试错成本高时学马斯克先算概率 |
| 产品观 | 艺术品 | 工具 | 消费级偏前者，基础设施偏后者 |
| 短板 | 时机与成本敏感度弱 | 人与制度的因素弱 | 两者都要靠其他框架补位 |



**举例（两者如何配合）**：定义一款面向消费者的新产品时，

先用乔布斯框架回答“它让生活哪里变好了、体验是否闭环”；

再用马斯克框架回答“物理上能否规模化、成本底线在哪”。

**前者决定值不值得做，后者决定能不能做成。**

# Snowflake Summit 2026 深度专题报告
## 从数据仓库到 Agent 运行时

> 26+ 产品公告 · 六大领域 · 企业 AI 的赌注
> 2026年6月 · 发布方名称

---

## 一、核心判断

Snowflake Summit 2026 不是在卖产品更新，而是在**重新定义“数据平台”的边界**。26+ 项官方公告贯穿一条主线：当企业 AI 从“回答问题”走向“自主行动”，数据平台需要从存储与查询层升级为 **Agent 运行时**，提供身份、上下文、治理和执行的全栈能力。

这个战略的前提是：**模型是商品，数据是壁垒**。如果这个前提成立，Snowflake 在 Agent 时代的卡位就是合理的。

**四个核心要点：**

1. 数据平台正在升级为 **AI 控制平面**
2. Agent 的核心能力来自 **企业上下文**，而非模型本身
3. 业务系统连接是 AI 落地的 **最后一公里**
4. 治理、安全、权限是 **加速器**，不是阻碍

**关键事实：**

| 维度 | 数据 |
|------|------|
| Summit | 6/1–4 · 旧金山 · 2 万+ 参会 |
| 公告 | 26+ 项能力 · 6 大领域 |
| Q1 营收 | $13.91 亿 · +33% YoY |
| RPO | $92.1 亿 · +38% YoY |
| 财报后股价 | 单日 +37% · 自低点反弹约 60% |

> **数据来源说明：** 财务数字来自 Snowflake 官方财报；产品采用率、性能提升与准确率数字来自厂商披露或客户现场自述（vendor/customer-reported），未经独立基准测试验证，第三方无法复现。

## 二、具体观察

### 观察 01｜企业 AI 被拆成了两条人群线，而不是一个产品

一条服务“造工具的人”，即工程师和开发者，深入 IDE、CLI、Excel；一条服务“用工具的人”，即业务用户，扎进 Slack、移动端和 Web。两者共享同一套数据和治理底座，但界面彻底分化。

- 更值得注意的是分发策略：AI 入口不再被收进一个集中的 Web 控制台，**而是嵌进用户原本就在的地方**。
- 这是一个“去中心化入口”的信号，谁占领了用户已有的工作流，谁就掌握了使用频次。

> 产品线的分野，反映的是 Snowflake 对分发渠道的判断：入口的争夺不在自己的控制台里，而在别人的工作台上。

### 观察 02｜上下文不是加分项，而是 Agent 可用性的生死线

在企业场景里，通用模型脱离业务语义近乎瞎猜。“收入”在不同系统里的定义差异、口径冲突、隐含规则，模型一概不知。把企业语义层层注入后，结构化问题的回答质量从勉强可用跃升到可信赖。

- 这条结论的战略含义是：当模型能力趋同，**谁掌握了企业语义，谁就掌握了 Agent 真正能不能用**。
- 而语义恰恰长在数据平台里，这是 Snowflake 把赌注押在数据层而非模型层的根本理由。

### 观察 03｜治理的对象，正在从“数据访问”变成“Agent 行为”

过去治理回答“谁能看哪些数据”；当 Agent 拿到执行权，问题变成“哪个 Agent、基于什么、做了什么、能不能追溯”。

- 给 Agent 独立身份而非继承部署者权限，是对这个新问题的正面回应，它承认自主软件代理不该套用为人类设计的安全模型。
- 这一步若成立，治理就从合规成本变成 **Agent 能否被批准上生产**的硬门槛。
- 硬门槛的另一面是护城河：它需要多年积累，无法靠一次发布补齐。

### 观察 04｜模型被有意识地商品化，壁垒被刻意推向数据

同时原生支持多个主流模型家族、与 OpenAI 和 Anthropic 同台站队，传递的不是“我的模型最强”，而是“模型随便选，反正都在我的数据上跑”。

- 客户不必在模型间选边，只需按工作负载挑选，**这恰恰削弱了模型作为差异点的意义**。

> 当模型是可替换的商品，不可替换的就是**数据的位置**。这是整份发布最深的一层逻辑。

### 观察 05｜“开放”是手段，“锁定”才是目的

开源引擎、推动跨平台语义标准、绑定头部数据工具链，一系列动作看似在拆墙，实则在把自己变成生态的默认锚点。开放降低了客户的迁入摩擦和戒心，标准则让自己成为事实参照系。

- 唯一的张力在于：高度依赖单一云的现实，与“中立多云平台”的叙事之间，还有距离需要弥合。

## 三、产品全景

前述观察的事实支撑。Summit 发布了 26+ 项产品能力，以下五个战略级产品定义了 Snowflake 的路线方向。

### CoCo（GA）

AI 驱动的开发者智能体。理解 Snowflake 环境中的表、角色和安全边界，贯穿数据与应用开发全生命周期。上线约 6 个月即积累 **7,100+ 客户账户**，是 Snowflake 历史上增长最快的产品。

- 多端形态覆盖 Desktop、VS Code、CLI、Excel、Slackbot，**不强迫开发者切换到集中式 Web 控制台**，而是嵌入其已有工作流。

### CoWork（GA）

面向业务用户的 AI 工作空间，原 Snowflake Intelligence。Deep Research（多 Agent 协同）、Artifacts（交互式仪表板）、User Memory。季环比增长 **2x**。MCP 连接器支持 Google Drive、Salesforce、Slack 等外部系统。

- CoCo 和 CoWork 共享底层数据与治理层，但交互界面完全分化，一个面向造工具的人，一个面向用工具的人。

### Cortex Sense（Private Preview · 随 Cortex AI 免费内置）

运行时上下文引擎，自动为 Agent 组装数据结构、业务定义和操作知识。官方基准测试（结构化问题准确率）呈现一条清晰的上下文阶梯：

| 配置 | 准确率 |
|------|:---:|
| 通用模型 | 24% |
| 人工语义 | 47% |
| 调优模型 | 73% |
| **Cortex Sense 开箱即用** | **86%** |

- 每一步都是企业上下文的层层叠加。随所有 Cortex AI 产品免费内置，**不是独立收费模块，而是底层能力**。

> **口径待澄清：** 厂商未公布测试题集难度、数据规模与语义覆盖度，四个数字不构成可直接横向比较的基准。

### Natoma（收购整合）

企业级 MCP 网关。Agent 连接外部系统（Slack、Salesforce、Jira 等）时，统一身份验证、策略执行和审计记录。治理从“数据访问控制”延伸到“AI 行为管理”，管理员在一个控制面管理所有 Agent 的系统权限。

- 这是 Snowflake 对“跨系统真空”的回应：**Agent 的行为天然是跨系统的，但传统治理体系困在数据仓库内部**。

### dbt Core v2.0 + Fivetran（Alpha）

合并后的实体服务 **10 万+** 数据团队。dbt Core v2.0 以 Apache 2.0 许可开源，解析速度提升 **10 倍**。dbt State 可降低基础设施成本 **30%+**。dbt Wizard 支持 AI 辅助模型编写。Agents Schema 开源标准，将仓库中的单一 schema 指定为 AI Agent 共享上下文层。

- 加上 AWS 60 亿美元五年承诺和 OSI 规范（54 家厂商参与），Snowflake 的生态策略是“通过开放来锁定”。

### 产品栈的分层

Snowflake 把企业 AI 的落地拆成由下至上的四层，逐层补齐从“数据可用”到“Agent 可控”的距离。

| 层级 | 关键组件 | 解决的问题 |
|------|---------|-----------|
| 数据底座 | Iceberg v3 · Datastream · Standard Warehouse Gen 2 | 数据能不能被稳定、廉价地读到与写入 |
| 语义层 | Horizon Context · OSI 规范 · Agents Schema | 指标怎么定义、由谁定义，把治理后的定义沉淀进平台 |
| **上下文层** | **Cortex Sense · Semantic View** | **Agent 在运行时能拿到多少业务含义。本届的加码重点** |
| 控制平面 | Cortex AI Gateway · Agent Identity · Natoma | Agent 能做什么、花了多少、有据可查吗，治理对象从数据访问转向 Agent 行为 |

## 四、客户实证

来自生产环境的真实案例。数字均为厂商或客户单方披露（vendor/customer-reported），未经独立验证。

**Sanofi（制药 · 全球）** —— “Concierge for Field”，面向全球医药代表的 AI Agent。一次自然语言对话，Agent 在秒级生成完整拜访计划（医生处方历史、专业背景、历史互动、最新文献），自动邮件发送。同一平台已覆盖 R&D、采购、IT、HR、现场销售。CDO 原话：“我们花了多年建造复杂的数据管道，现在直接在 Snowflake 上构建 AI。”

**Thomson Reuters（法律与专业服务 · 全球）** —— Snowflake 上的企业 AI 平台。查询从数周缩短到 2 秒，从静态报告转向准实时洞察。在高监管环境下，Snowflake 的治理能力（Agent Identity、审计追踪、防泄露策略）是合作关键。

**BlackRock（金融服务 · 全球）** —— 使用 Horizon Context 确保 AI Agent 在“共享的企业真相定义”上运行。Aladdin 平台处理 1160 亿+ 数据点，生成 150 万+ 报告。“revenue”在每个系统里意味着完全一样的东西。

**Accenture（咨询与专业服务 · 全球）** —— 75 万员工使用 Snowflake CoWork，覆盖客户交付、内部知识管理和 AI 辅助决策。专业服务行业最大的 Agent 部署之一。

**Under Armour（消费零售 · 全球）** —— AI 驱动的全渠道运营，从电商推荐到供应链预测，将零散的数据库架构统一到 Snowflake 之上。全球超过 100 万活跃专业人士使用其平台。

**分析师注：**

- 五个案例集中在制药、金融、咨询、零售四个行业，**共同特征是数据治理要求高、且多数为总部在欧美的跨国企业**。
- 案例中的效率数字缺少基线说明（原环境配置、数据规模、并发条件），买方在自建评估时以自有负载验证更为稳妥。
- 客户规模数字（75 万员工、100 万+ 用户）描述的是组织的总人数，不等于活跃 Agent 使用量，引用时需保留原始口径。

## 五、竞争格局

6 月是企业数据平台的决战月，三场大会密集上演：Snowflake Summit、Microsoft Build、Databricks Data+AI Summit。

| | Snowflake Summit | Databricks D+AI | Microsoft Build |
|------|------|------|------|
| 时间 | 6月1–4日 | 6月15–18日 | 6月2–3日 |
| 核心定位 | 数据仓库 → Agent 运行时 | 湖仓一体 → 模型+Agent | Windows/Azure → Agent 平台 |
| 最强场景 | 结构化数据 + 企业治理 | ML 模型部署 + 数据工程 | 知识工作 + 开发者工具 |
| Agent 产品 | CoCo / CoWork | ai_query / Genie | Windows Agent Framework |
| 开放策略 | Iceberg v3 / OSI / Openflow | Delta Lake / Unity Catalog | 相对封闭 |
| 主场依赖 | 结构化企业数据 | ML 训练数据 | 办公协作数据 |

**三方正在收敛。** Snowflake 的赌注是数据仓库作为 Agent 运行时，最强场景是结构化数据且治理要求高的企业（金融、医疗、制药）。Databricks 赌湖仓加模型服务，最强场景是 ML 工作负载重的组织。微软赌 Windows 和 Azure 是 Agent 平台，最强场景是深度使用 M365 和 Azure 的组织。

**主加次的双边界格局。** 大多数大型企业不会三选一。合理的结果是：**主边界**为客户数据所在平台（对很多企业是 Snowflake），**次边界**为员工生产力平台（几乎一定是微软）。挑战在于避免同时押注多个主边界，那样最终没有任何一个 Agent 运行时被真正规模化。

**主场不等于客场：同一套叙事在不同市场的效力不同。** 三家在各自的主场都有明显优势：Snowflake 的主场是需要强治理的结构化数据，Databricks 的主场是 ML 原生工作负载，微软的主场是员工日常协作界面。**把主场战绩外推到客场是需要额外证据的。** Snowflake 的“数据重力”论点在欧美市场成立，是因为大量企业数据已经落在其平台内；在一个数据形态、合规约束与交付模式都不同的市场，同一论点需要重新验证。

**“数据重力”是三家共享的底层逻辑。** “模型是商品、数据是壁垒”并非 Snowflake 独家主张。微软 Fabric、Databricks 走的是同一条路。三家的分歧不在要不要押注数据重力，**而在各自数据的形态不同**：Snowflake 是结构化企业数据，Databricks 是 ML 训练数据，微软是办公协作数据。谁的数据形态最贴近 Agent 的高频场景，谁的重力就最强。

**Snowflake 的独特优势与风险。**

| 优势 | 风险 |
|------|------|
| 治理能力为多年积累，不是一次性发布能补齐的 | 约 70% 业务在 AWS 上，多云叙事落后于商业现实 |
| 模型无关架构，降低客户的模型选边成本 | Databricks 在 ML 与 AI 原生场景的增长势头 |
| 13,900+ 客户形成的结构化数据重力 | 微软生产力生态，若 Agent 交互发生在 Office 与 Teams 内，Snowflake 可能被推到数据管道角色 |
| 开放表格式与语义标准带来的生态号召力 | 多数新能力仍在 Preview，规模化时点未定 |

## 六、对买方的建议

按角色给可执行判断。

### 数据平台负责人

把发布清单按成熟度分层再排期。GA、Preview、Alpha 三类能力的部署风险不同，按 Keynote 的叙事节奏做架构规划会踩空。

- 语义层与上下文层的投入可以提前启动：定义对象是企业自己的业务规则，这部分资产与平台版本解耦，有残值。
- 同时确认 Semantic View 类对象的可携带性，即是否支持跨账户复制、能否供给平台外的 BI 工具，这决定了投入是资产还是沉没成本。

### AI 平台负责人

Agent 治理的评估重点在覆盖面。独立身份、策略执行、审计与预算控制只有在实际流量经过它们时才产生价值。

- 采购前要求厂商说明既有自研 Agent 与第三方 Agent 的纳入方式，绕过控制层的调用会留下策略与审计缺口。
- 上下文层的收益（准确率提升、单次调用成本下降）被作为卖点呈现，但测试条件未披露，建议以自有高难度问题集复现一次。

### 采购

合同层面确认三件事：

- Keynote 披露的性能与准确率数字是否接受以双方约定的基准做验收。
- Preview 与 Alpha 能力的 GA 时点，以及未 GA 时的服务级别与退出条款。
- 收购整合型产品（如收购而来的网关）的路线承诺，避免因整合方向调整造成功能中断。
- 若涉及区域化部署，需单独确认区域功能差异清单与数据处理责任划分，这两项通常不出现在标准协议里。

### 竞品厂商

Snowflake 的强项是把治理与语义绑定进平台内，这既是差异化也是可攻击面：语义资产越绑定平台，客户对锁定的顾虑越重。

- 可以在两个方向上找位置：一是语义资产的可迁移性叙事，二是私有化部署与本地合规适配的交付形态。
- 需要注意其模型开放与开放表格式的动作，会让“它不能用本地生态”这类简单对标失效，竞争点要落在交付形态与语义资产归属上。

## 七、行业延伸

本届大会提出的行业级命题：**治理的权力最终会沉淀在哪一层，而不是 Snowflake 会不会赢。**

下面的分层结构由多家厂商共同构成，属于分析者视角的归纳，不代表 Snowflake 的自述架构。

| 层级 | 关键玩家 | 赌注 |
|------|---------|------|
| 监管层 | NIST AI 100-4 · EU AI Act · ISO 42001 | 最终会重新定义所有规则。NIST CAISI 于 2026 年 1 月启动 AI Agent Standards Initiative |
| 身份层 | Okta · CyberArk · Ping Identity | Okta 于 2026 年 4 月 GA AI Agent 方案。身份认证是所有 Agent 调用的必经点 |
| 模型安全层 | HiddenLayer · Cisco AI Defense · Palo Alto · Lakera | 数据平台跳过这一层。模型本身就是风险源，包括 prompt injection 与数据投毒 |
| **数据平台层** | **Snowflake · Databricks · 三大云** | **数据在哪，Agent 的上下文就在哪，治理沉淀在数据层** |
| 网关层 | Kong · Apigee · Natoma (MCP) | 纵向整合（收购 Natoma）与行业横向标准化（API 网关原生支持 MCP）两条路线并行 |
| 应用层 | Salesforce · ServiceNow · SAP · Workday | Agent 行为真正发生的地方 |
| 可观测层 | Arthur AI · Datadog · Splunk | Agent 决策质量下降时，谁来发警报？模型漂移检测是刚需 |

现在最有力的两个候选是数据层和身份层，二者尚未出现被广泛接受的仲裁者。

### 待验证的问题

1. **上下文阶梯的测试条件未披露**：24% 到 86% 的提升幅度很大，但厂商未说明题集难度、数据规模、语义覆盖度和人工介入比例。这类数字的行业价值取决于可复现性，缺少条件的基准，其证据效力接近演示。
2. **Natoma 的整合时间线未定**：MCP 网关是 Agent 治理的关键补强，但收购刚刚完成。从签署到深度集成需要几个季度，直接决定控制平面的完整能力何时可用。
3. **Agent 的经济模型尚未清晰**：CoCo 7,100 用户、CoWork 环比 2x 是采用信号，但企业为 Agent 付多少钱、按什么计价，商业模型还没有完整答案。这是一个 2027 年才能回答的问题。

## 八、总结

26 项产品公告、两个 Agent 产品线、一套治理层、一个生态标准，Summit 2026 用一周时间勾勒了 Snowflake 从数据仓库到 Agent 运行时的转型路线图。这条路线指向一个清晰的判断：**数据平台竞争的下一个十年，将由谁能掌握企业 AI 的上下文、控制权和行动闭环来定义**。

- 但一张 Keynote 不等于一个市场，这套叙事能否兑现，取决于三个时间窗口内的实际验证。
- 叙事内部的一致性很高，从模型商品化到语义层加码，再到治理对象转向 Agent 行为，各段公告彼此支撑。

> 真正的不确定性不在战略方向，而在执行节奏：多数关键能力仍处于 Preview 或早期 GA，**控制平面何时具备生产级完整度，是这个故事的第一个验证点**。

**短期 · 6–12 个月**

- Summit 叙事与财报表现构成正向催化剂
- 2026 H2 的企业采用率是真正的验证点
- 产品侧，Cortex AI Gateway 与 Cortex Sense 的 GA 时点是下一个可观测信号

**中期 · 12–24 个月**

- 竞争格局将决定性收窄，数据重力决定 Agent 运行的位置
- Snowflake 在治理与结构化数据上有优势，Databricks 在 ML 原生与开源生态上势头更猛
- 语义层标准之争会分出方向：平台内对象路线与开放标准路线，哪一种被更多企业接受

**长期 · 24 个月以上**

- 如果模型继续商品化、治理成为企业 AI 部署的硬约束，Snowflake 的赌注成立
- 但最重要的一步不在 Snowflake 手里：Agent 需要真正成为企业运营的主流方式

**Strategic Planning Assumption：** 到 2028 年，企业级语义与上下文层将从数据平台的可选能力变为标配组件，**置信度中等偏高**；届时差异化的来源将从“是否具备语义层”转移到“语义资产的可移植性与跨平台消费能力”，该转移对买方有利、对平台厂商不利，**置信度中等**。

# 厂商大会深度专题报告（Vendor Summit Report）

把一场厂商旗舰数据／AI 大会，写成一份面向企业决策者的深度专题报告——三个口径一致的交付物、
一套共享事实、固定分析结构，以及一套读者真的会读完的阅读版式。

适配 Snowflake Summit、Databricks Data+AI Summit、Microsoft Build、Google Cloud Next、AWS re:Invent
等大会。可复用的是**结构骨架与阅读版式**；分析内容永远从本次大会的实际内容重新推导。

---

## 产出什么

| 交付物 | 作用 | 形态 |
|--------|------|------|
| `report.html` | 主阅读体验 | 单页自包含淡色主题，固定导航、可折叠表格、滚动显现 |
| `report.md` | 归档与二次加工母本 | 同样 8 段、同样数字、Markdown 原生语法 |
| `push.md` | 企业 IM 速读版 | 纯文本，`▍` 分节标记，按内容密度分档控制字节 |

三份材料在数字、案例、caveat 上必须一致——靠收尾的跨文件关键串计数强制校验，不靠目测。

## 固定 8 段结构

| # | 段落 | 内容 |
|---|------|------|
| 01 | 核心判断 | 一句话主张 + 战略前提 + 四条要点 + 关键数字带 + 数据来源说明 |
| 02 | 具体观察 | 4–5 条纯洞察，不出现产品参数 |
| 03 | 产品全景 | 5 个战略产品带数字，逐个标注 GA／预览状态，其余公告进折叠表 |
| 04 | 客户实证 | 4–5 个生产案例，段落头标注厂商／客户口径 |
| 05 | 竞争格局 | 对比表 + 收敛判断 + 主场与客场 + 优势与风险 |
| 06 | 对买方的建议 | So-What：分角色的可执行判断 |
| 07 | 行业延伸 | 本次大会真正提出的行业级问题，加开放问题 |
| 08 | 总结 | 一屏结论 + 短中长期判断 + 一条带年份与置信度的规划假设 |

第 05 段与第 07 段承载的是**内容，不是模板**。分析框架属于产出它的那场大会；换一家厂商就要丢掉
旧框架，重新推导延伸角度——角度不同胜过硬套。

## 分析师机构标准

这四条是"分析师研究笔记"与"会议综述"的分界。缺任何一条，报告就退回厂商友好型报道。

1. **只陈述，不发指令。** 不用祈使句、不说教、不写元评论与思考痕迹。直接给结论和证据，让事实说话。
2. **厂商数据必须加 caveat。** 任何来自厂商或其客户的性能／规模数字，都标注 *vendor-reported /
   customer-reported* 加 *未经独立验证*，并建议在买方自有负载上验证。禁止裸引官方"显著优于竞品 X"。
3. **So-What 是硬性项。** 必须有独立的分角色买方建议段，覆盖四个角色：数据平台负责人、AI 平台负责人、
   采购、竞品厂商。
4. **预测必须带年份与置信度。** 禁用绝对词。总结段放一条明确的战略规划假设。

## 阅读版式契约

版式在这里是可核查的契约，不是审美偏好。每个条目必须满足三段式——**判断句标题 + 导语 + 要点行**：

- `.card-h` 判断句标题——必须能独立读懂，是判断不是名词短语，不加句号
- `.lead` 导语——背景与事实，两到四行
- `.pts li` 要点行——并列证据，每条一到两行

组件清单：`.card` / `.card-num` / `.card-h` / `.lead` / `.pts` / `.num` / `.pull` / `.pull-lead` /
`.judg` / `.lim` / `.lim-t` / `.note` / `.badges .badge`（`.b-ga` / `.b-prev` / `.b-arch`）/ `.flow` /
`.swot` / `.layer-stack` / `.buyer-grid` / `.spa` / `.q-item`。

最容易被误用的两条判据：

- **`.layer-stack`** 只用于层间存在**包含或依赖**关系时。并列或竞争关系改用 `.cmp-table` 或 `.swot`。
- **`.pull` 与 `.judg`** —— `.pull` 是某个条目的结论句，`.judg` 是板块级判断，二者不堆叠。

触发返工的反模式：200 字以上的裸段落；判断句标题写成名词短语；每条都做成卡片形成卡片墙；产品数字
漏进观察层；要点行超过两行。

## 工作流

13 步，确定性步骤与 LLM 步骤分别标注：

1. `[确定性]` 确认事件与报告窗口
2. `[LLM]` 检索——公告、逐个核实 GA／预览状态、财报背景、客户案例、竞品动作、分析师评论
3. `[LLM]` 核心判断与数据来源说明
4. `[LLM]` 具体观察，4–5 条洞察，陈述而非指令
5. `[LLM]` 产品全景，状态徽标与折叠表
6. `[LLM]` 分角色买方建议
7. `[LLM]` 行业延伸与开放问题
8. `[LLM]` 总结与一条战略规划假设
9. `[确定性]` 生成三份交付物，跑跨文件一致性校验
10. `[LLM]` HTML 版式落地——只做切分与强调，不改写文字
11. `[确定性]` 机械复核——层间分离、caveat、编号、红线配额
12. `[LLM]` reader-fit 阅读测试，先锁定定位再选 3–4 个代表角色
13. `[确定性]` 交付，推送到任何群或公开页面前先确认渠道

```
    wecom-template.md
```

不依赖任何二进制或外部服务，检索走常规网页搜索与页面抓取。

## 快速开始

```
/vendor-summit-report
```

或直接用自然语言描述任务：

- "Snowflake Summit 2026 的深度专题报告"
- "按上次那个结构，做一份 Databricks Data+AI Summit 的报告"
- "Use the same structure as last time for Google Cloud Next"

## 目录结构

```
SKILL.md                       完整工作流、标准、硬规则、验证清单
templates/report-template.html 淡色主题 HTML，含全套阅读组件样式表
templates/report-template.md   Markdown 母本，8 段
templates/wecom-template.md    企业 IM 速读版，含字节分档
```

三份模板是一份写完的报告，作为**结构与视觉的样例**。复用它的 CSS、阅读组件、段落骨架与导航逻辑；
替换全部厂商名、产品、数字、案例与洞察，以及第 05、06、07 段的分析框架。

## 硬性规则

1. 结构可复用，内容不可复用
2. 观察层与产品层严格分离
3. 每个厂商口径数字必须带 caveat
4. 买方建议段为硬性项，覆盖四个角色
5. 预测必须带年份与置信度
6. 禁止元评论、禁止祈使句
7. 禁止 200 字以上裸段落
8. 三口径必须一致，靠关键串计数校验
9. 章节编号必须自洽
10. 速读版永不删除买方建议

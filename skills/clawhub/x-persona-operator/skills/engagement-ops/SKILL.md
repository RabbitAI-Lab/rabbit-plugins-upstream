# Engagement Ops — 互动运营（回复 / 社区 / DM）

> 内容发出只是开始。早期互动撬动算法，真实社区沉淀资产。本技能把回复、社区贡献、DM 与负面 SOP 变成可复用的运营动作。

**来源说明**：改编自社区技能 `101-skills/superpowers@twitter-automation`（skills.sh 696.8K 安装，Twitter 互动自动化方法论），按本组织 superpower 架构重组，并叠加 persona-playbook 的边界约束（不冒充、不刷屏、不情绪对线）。

## 能力

- **及时回应**：@ 与评论 24h 内真人语气回应，不模板化
- **价值贡献**：在大 V / 相关线程里写高质量回复，借流反哺本号（网络循环）
- **问题转选题**：把高频好问题转为下一条内容
- **DM 口径**：按账号主设定回应，不泄露隐私、不代做承诺
- **负面 SOP**：按 [../../references/persona-playbook.md](../../references/persona-playbook.md) §3 边界处理删 / 回 / 静音 / 拉黑触发条件，不情绪对线

## 使用方式

```
/engagement-ops 给这条推文的评论写 3 条真人语气的回复草案
/engagement-ops 有人质疑我的观点，按边界 SOP 帮我拟回应
/engagement-ops 今天在哪些大 V 线程里值得贡献回复？
```

## 工作流

1. **分级响应**：高价值问题展开答 / 普通点赞+短回 / 违规直接按 SOP 处理
2. **守窗口**：发后 1–2 小时主动互动，撬动早期信号（见 growth 日历）
3. **转选题**：把反复出现的问题记入选题库
4. **过红线**：任何负面 / 争议先对照 [../../references/persona-playbook.md](../../references/persona-playbook.md) §3 边界，再回应

## 适用场景

- 日常评论区与 @ 维护
- 通过互动反哺增长的网络循环执行
- 危机 / 争议初期的标准化应对

## 限制

- 不冒充真人、不刷屏式铺回复、不情绪对线
- 涉及立场 / 商业承诺的回应须账号主确认
- 具体发什么内容交给 content-engine；增长节奏交给 growth-tactics

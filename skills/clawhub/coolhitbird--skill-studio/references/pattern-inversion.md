# Pattern: Inversion（反转访谈）

> 控制的不确定性：**输入不确定**——用户没说清，Agent 直接脑补。

## 何时用

当任务结果高度依赖用户上下文时。**Agent 不问清楚就做，容易生成一份很完整但没用的东西**，那就该用 Inversion。

典型场景：
- 需求收集 / 项目规划 / 架构设计
- 故障诊断 / 配置向导 / 选型咨询
- 招聘 JD 生成 / 产品定位分析

## 目录结构

```
skill-name/
├── SKILL.md                # 分阶段访谈脚本
└── assets/
    └── plan-template.md    # 最终输出模板
```

## 核心要素：阶段化访谈

**关键句**：在所有阶段完成之前，**不要**开始构建或生成最终方案。

**访谈细化**：
- 复杂任务：一问一答，按顺序问，不跳过任何
- 轻量任务：一次问 3 个关键问题
- 允许用户说"不确定"，用默认假设标记出来
- 把已收集信息复述给用户确认
- 最终输出里保留已确认信息和待确认假设

**防骚扰上限**：必问问题控制 3-6 个。超过 6 个连续提问无假设出口 → 强制生成假设让用户确认（熔断第 4 道）。

## 最小 SKILL.md 骨架

```markdown
---
name: project-planner
description: 通过结构化问题收集需求后规划软件项目。当用户说"我想构建"、"帮我规划"、"设计系统"时使用。
agent_created: true
---

你正在进行结构化需求访谈。在所有阶段完成之前，不要开始构建或设计。

## 阶段1 — 问题发现（一次问一个问题，等待每个答案）
按顺序问这些问题。不要跳过任何。
- Q1："这个项目为其用户解决什么问题？"
- Q2："主要用户是谁？他们的技术水平如何？"
- Q3："预期规模如何？（每日用户数、数据量）"

## 阶段2 — 技术约束（仅在阶段1完全回答后）
- Q4："你将使用什么部署环境？"
- Q5："你有任何技术栈要求或偏好吗？"
- Q6："什么是不可协商的要求？（延迟、合规、预算）"

## 阶段3 — 综合（仅在所有问题回答后）
1. 加载 `assets/plan-template.md` 获取输出格式
2. 使用收集的需求填充模板的每个部分
3. 向用户展示完成的计划
4. 问："这个计划准确反映了你的需求吗？"
5. 根据反馈迭代直到用户确认
```

## assets/plan-template.md 示例

```markdown
# Project Plan: {Project Name}

## Problem Statement
{from Q1}

## Target Users
- Primary users: {from Q2}

## Scale Requirements
| Dimension | Target |
|-----------|--------|
| Users/day | {from Q3} |

## Non-Negotiable Requirements
{from Q6, as a numbered list}

## Risks & Mitigations
| Risk | Impact | Mitigation |
|------|--------|------------|
| {risk} | {high/medium/low} | {mitigation} |
```

## 常见坑

| 坑 | 后果 | 修正 |
|---|---|---|
| 一次问 12 个问题 | 用户直接关掉 | 必问 3-6 个，阶段化 |
| 关键信息缺失就提前输出 | 生成完整但没用的东西 | "未答完不输出最终方案" |
| 不允许"不确定" | 用户卡住 | 允许"不确定"→默认假设标记→复述确认 |
| 不分阶段一次全问 | 复杂需求用户负担重 | 阶段化，前阶段答完才进下阶段 |

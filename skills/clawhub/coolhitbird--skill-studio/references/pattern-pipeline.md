# Pattern: Pipeline（流水线）

> 控制的不确定性：**流程不确定**——Agent 跳过确认、测试、验收，直接给看似完成的结果。

## 何时用

当任务满足以下任意条件：
- 步骤之间有依赖关系
- 中间结果需要用户确认
- 跳过某一步会导致最终结果不可信
- 任务涉及发布、合规、安全、部署等高风险动作
- 你希望 Agent 每次都按同一套流程交付

典型场景：文档生成 / 数据处理流程 / 发布流程 / 合规审查 / 安全扫描 / 代码迁移 / 项目初始化与验收。

## 目录结构

```
skill-name/
├── SKILL.md                       # 步骤 + 门禁
├── references/
│   ├── style.md                   # 各步骤格式参考
│   └── quality-checklist.md       # 验收标准
├── assets/
│   └── output-template.md         # 最终输出结构
└── scripts/
    └── validator.py               # 可选确定性校验
```

## 核心要素：每步 8 要素 + 门槛

**关键区别**：只有 Step 1/2/3 不是 Pipeline；**有阻塞条件和验收门槛才是 Pipeline**。

每一步必含 8 要素：

| 要素 | 说明 |
|---|---|
| 目标 | 这一步要达成什么 |
| 输入 | 从上一步/用户拿什么 |
| 动作 | 执行什么 |
| 输出 | 产出什么 |
| **通过条件** | 什么条件下进入下一步 |
| 失败时怎么办 | 出错的处理路径 |
| 是否需要用户确认 | 该步是否阻塞等用户 |
| 需加载哪些资源 | references/assets/scripts |

**门槛硬编码**（熔断第 3 道）：Pipeline 步骤缺 `if not user_confirmed: stop` 逻辑 → 无法打包。

## 最小 SKILL.md 骨架

```markdown
---
name: doc-pipeline
description: 通过多步骤 Pipeline 从源代码生成 API 文档。当用户要求为模块编写文档或生成 API 文档时使用。
agent_created: true
---

你正在运行文档生成 Pipeline。按顺序执行每个步骤。如果步骤失败，不要跳过步骤或继续。

## 步骤1 — 解析与清单
- 目标：提取所有公共 API
- 输入：用户代码
- 动作：分析提取公共类、函数、常量
- 输出：API 清单
- 通过条件：用户确认清单完整
- 失败：重新解析，不进步骤2
- 需用户确认：是（问"这是完整公共 API 吗？"）

## 步骤2 — 生成文档字符串
- 目标：为缺 docstring 的函数生成
- 输入：步骤1 清单
- 动作：加载 `references/style.md` → 按格式生成 → 逐个呈现审批
- 通过条件：所有 docstring 用户审批完
- 失败：按反馈重生成
- 需用户确认：是（**在用户确认之前不要继续步骤3**）

## 步骤3 — 组装文档
- 目标：编译为单个 API 参考文档
- 输入：步骤2 全部 docstring
- 动作：加载 `assets/output-template.md` → 编译
- 通过条件：文档组装完整
- 需加载：assets/output-template.md

## 步骤4 — 质量检查
- 目标：对照验收标准审查
- 输入：步骤3 文档
- 动作：加载 `references/quality-checklist.md` 审查（每个公共符号有文档/每个参数有类型描述/每个函数有示例）
- 通过条件：所有检查项通过
- 失败：修复问题后再呈现
- 需加载：references/quality-checklist.md
```

## 常见坑

| 坑 | 后果 | 修正 |
|---|---|---|
| 只有 Step 1/2/3 没门槛 | Agent 跳步交作业 | 每步写通过条件 + 是否需确认 |
| 门槛用词汇不用逻辑 | "MUST not continue" 会被善意放行 | 硬编码 `if not user_confirmed: stop` |
| 步骤间依赖没写清 | 信息断流 | 每步明确输入来自哪步 |
| 无失败路径 | 出错卡死 | 每步写"失败时怎么办" |

# 商品规格与 SKU 整理

将商家给出的至多 100 行商品资料整理成可复核的导入草稿，同时明确标出重复、缺失和需要确认的规格。只处理用户在对话中提供的资料；不读取库存、订单或任何后台，也不执行导入或修改。

## 输入

要求用户提供表格、CSV/TSV 或可解析文本，包含以下列：`商品名称`、`颜色`、`尺寸`、`型号`。保留原始字段值，不能臆测空缺资料。若有店铺既定命名规则，优先采用；否则使用 `商品名称 - 颜色 - 尺寸 - 型号`。

## 工作流

1. 先确认行数不超过 100，并检查四个必填列和每行的必填值。
2. 仅清理字段首尾的全角/半角空格及统一名称的重复分隔符，原字段仍保留。字段内部空格（例如“深 蓝”“A 12”）可能有含义，默认保留原值并标“待确认”，不能自行删除、合并为另一颜色或型号；只有用户明确提供映射或授权时才规范化内部空格。
3. 为每行生成建议统一名称。仅在建议列中做规范化，不把建议当作已确认事实。
4. 以仅完成上述首尾清理、且保留未确认内部空格的 `商品名称 + 颜色 + 尺寸 + 型号` 判定重复。重复组中的**每一行**均标为“待确认”，且原始行顺序不变；原因统一写为 `与第X行规格组合重复`（X 为该组最早的原始行号；最早行写 `与第Y行规格组合重复`，Y 为该组第二早行号）。将空值列为缺失规格；把不确定的映射列为“待确认”。一行有多个问题时，在原因中以 `；` 合并，不能标为“可导入”。
5. 输出三部分：统一命名表、问题报告、可复制的 CSV 导入草稿。问题报告要给出原始行号和原因。

## 输出格式

按此顺序输出：

1. **统一命名表**：行号、原始四字段、建议统一名称、状态（可导入/待确认）、待确认原因。可导入行的原因留空。
2. **重复与缺失规格报告**：分别列出重复组、缺失字段和待确认项；没有时明确写“未发现”。
3. **CSV 导入草稿**：表头固定为 `商品名称,颜色,尺寸,型号,建议统一名称,状态,待确认原因`。仅无问题的行标为“可导入”；待确认行必须保留并在“待确认原因”列写出具体原因。重复组不得有任何一行标为“可导入”。

若缺少必填列或关键值，停止生成导入草稿，先列出缺失项并请用户补齐；绝不编造颜色、尺寸或型号。

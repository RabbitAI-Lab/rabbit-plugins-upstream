# Поисковый справочник досье

Подробности, вынесенные из `SKILL.md`. Читаются по требованию —
`skill_exec(skill="dossier", script="guide.py", args=["playbook"])`,
а не грузятся в каждый запрос: справочник нужен во время
сбора, а не при каждом упоминании навыка.

Все запросы ниже отправляются через `search.py` — это Perplexity Sonar, до
восьми вопросов за вызов: `skill_exec(skill="dossier", script="search.py",
args=["запрос 1", …, "запрос 8"])`. Слой 0 и основа «поиска по прошлому» уже
собраны в готовые волны `--wave1` и `--deep` (волны 2–4); заготовки ниже — для
слоёв 1–3 и пробелов, которые волны не закрыли. После всех вопросов — `--brief`.
Sonar понимает вопрос целиком, поэтому основа — вопросы; кавычки и `site:` —
для точечных пробелов.

### Четыре слоя поиска, у каждого — своя цель

**Слой 0 — сам человек. Цель: закрыть якоря 1, 3, 5.**

Запросы на языке имени:

```
"<ФИО полностью>"
"<ФИО>" биография
"<ФИО>" родилась OR родился
"<ФИО>" wikipedia OR википедия
```

Обязательно **и латиницей**, транслитерируя по нескольким схемам (ГОСТ,
паспортная, самопрезентация в LinkedIn): `"Ivan Petrov"`,
`"Ivan Petrov" LinkedIn`.

Для имён из Азии / Ближнего Востока — и оригинальное написание
(иероглифы, арабица): 60% биографии индексируется только там.

Развилка после слоя 0: один кандидат → слой 1; несколько — вопрос из
Шага 1.

**Слой 1 — прямые связи. Цель: закрыть якоря 4, 6, 7.**

Каждый работодатель, каждый вуз, каждая упомянутая сделка из слоя 0 →
отдельный запрос с сохранением имени человека:

```
"<ФИО>" "<текущий работодатель>"
"<ФИО>" "<предыдущий работодатель>"       # для КАЖДОГО из LinkedIn
"<ФИО>" site:linkedin.com
"<ФИО>" site:<домен работодателя>
"<ФИО>" "<название вуза>"
"<ФИО>" интервью OR подкаст OR выступление
"<ФИО>" конференция OR форум OR панель
```

Доменные фильтры по региону:

- Россия: `site:rbc.ru`, `site:vedomosti.ru`, `site:forbes.ru`,
  `site:hse.ru`, `site:t.me`, `site:kommersant.ru`
- Международный: `site:bloomberg.com`, `site:ft.com`, `site:reuters.com`
- Академия: `site:scholar.google.com`, `site:elibrary.ru`,
  `site:istina.msu.ru`, `site:orcid.org`
- Финансы: `site:sec.gov`, `site:cbonds.ru`
- Патенты: `site:patents.google.com`

**Слой 2 — связи связей. Цель: закрыть якоря 8, 9, 10, найти ≥ 3
соавторов/коллег/оппонентов.**

Здесь имя человека может **временно уходить** из запроса — вы ищете
контекст, в котором он работал. Потом контекст даёт новые запросы уже
с именем.

```
"<работодатель>" "<роль>" <годы работы>
"<вуз>" "<кафедра>" выпуск <год>
"<название сделки>" аналитик OR консультант
"<конференция>" участники <год>
```

**Приём «продукт → соавтор → продукт».** Опорный приём слоя 2:

1. Найдите **один продукт** человека — отчёт, статью, выступление, интервью.
2. Извлеките **соавтора, интервьюера, модератора, коллегу по панели**.
3. Запрос: **«соавтор + продукт»** без имени вашего человека — так найдутся
   другие продукты соавтора, где может фигурировать и ваш человек.
4. Обратно к шагу 2.

Через 2–3 итерации всплывает то, что не индексируется по имени вашего
человека: подпись под графиком в отчёте, внутреннее интервью
работодателя, список участников закрытого мероприятия в PDF-приложении.

**Приём «имя + временное окно».** Когда известны годы работы:

```
"<ФИО>" 2011..2012                        # период Morgan Stanley
"<работодатель>" "<роль>" 2011            # без имени, но с ролью и годом
"<ФИО>" отчёт OR report 2018..2020
```

Отсекает случайные упоминания и вытаскивает публикации именно того
периода.

**Слой 3 — уникальные детали. Цель: закрыть 2 пробела, важных для темы
встречи.**

Точечно, не «всё, что найдётся». Готовые формулировки по типам пробелов:

```
Дата рождения:
  "<ФИО>" "родилась в" OR "родился в"
  "<ФИО>" "год рождения"
  "<ФИО>" "лет" site:<деловое СМИ>

Образование (подробности):
  "<ФИО>" МГУ OR МГИМО OR ВШЭ
  "<ФИО>" выпускник OR alumnus
  "<ФИО>" диссертация OR PhD OR "кандидат наук"
  site:istina.msu.ru "<ФИО>"
  site:elibrary.ru "<ФИО>"

Место рождения / город:
  "<ФИО>" родом OR "родилась в"
  # НО: подтверждать только связью с работой/выступлением

Публикации первого лица:
  "<ФИО>" колонка OR "автор:"
  "<ФИО>" telegram OR канал
  "<ФИО>" youtube OR подкаст

Награды и советы:
  "<ФИО>" премия OR лауреат OR "член совета"
  "<ФИО>" board OR "член правления"

Санкции и суды (обязательно, если релевантно):
  "<ФИО>" санкции OR sanctions
  site:opensanctions.org "<ФИО>"
  site:ofac.treasury.gov "<ФИО>"
  "<ФИО>" суд OR иск OR арбитраж
```

### Языковой протокол

Один и тот же человек ищется **параллельно** минимум на двух языках:
- родной язык имени (по нему — биография),
- английский (по нему — международные упоминания, academic footprint).

Для имён из Азии и Ближнего Востока — обязательно оригинальное написание.

### Приоритет открытия результатов

Слабая модель тратит время на всё подряд. Порядок:

```
Открывать в первую очередь:
  1) домен работодателя (about, пресс-релизы, годовые отчёты)
  2) LinkedIn самого человека (проверить по работодателю — не тёзка)
  3) собственный канал / блог / колонка первого лица
  4) интервью в деловой прессе (полный текст, не пересказ)
  5) научные базы, если человек из академии

Не открывать без крайней нужды:
  - агрегаторы биографий (24smi, znachenie-familii, kakoy-vozrast)
  - Fandom, Wikia
  - соцсети однофамильцев без подтверждающей связи
  - «топ-10 самых…»
```

### Стоп-условия

**Стоп «достаточно»:**
- 7 из 10 якорей заполнены,
- ≥ 1 источник первого лица,
- последний источник свежее 12 месяцев для действующей должности.

**Стоп «сдаться»:**
- пройдено 3 слоя,
- последние 2 запроса не дали новых URL,
- якоря 4 (образование) и 5 (место работы) закрыты.

Оставшееся идёт в «Не подтверждено», а не в «ищем ещё».

**Правило перепечаток.** Если три подряд URL повторяют уже встречавшиеся
формулировки — фиксируем факт как «одна перепечатка», идём к следующему
якорю, не открываем четвёртый.

### Журнал поиска — вести обязательно

Слабая модель без структурированного журнала забывает, что уже искала.
Формат — таблица якорей:

```
Якорь                     | Значение                     | Источник           | Слой
--------------------------|------------------------------|--------------------|------
ФИО                       | ...                          | ...                | 0
Год рождения              | ...                          | ...                | 3
Место рождения            | не найдено                   | —                  | 3
Гражданство               | ...                          | ...                | 0
Вуз                       | ...                          | ...                | 1
Текущий работодатель      | ...                          | ...                | 1
Хронология работодателей  | ...                          | ...                | 1
Публикации первого лица   | ...                          | ...                | 2
Награды                   | не найдено                   | —                  | 3
Публичные позиции         | ...                          | ...                | 2
```

Заполнено N/10 → см. стоп-условия.

### Матрица «отрасль → сильные источники»

| Отрасль | Специфические источники |

| Финансы / инвестиции | sec.gov, cbonds, годовые отчёты, MOEX, LSE, HKEX |
| Академия | Scopus, elibrary, ORCID, ResearchGate, istina.msu.ru |
| Политика / госслужба | официальные сайты ведомств, парламентские базы |
| Технологии | patents.google.com, GitHub, arXiv, TechCrunch |
| Юриспруденция | судебные базы (kad.arbitr.ru, PACER), реестры адвокатов |

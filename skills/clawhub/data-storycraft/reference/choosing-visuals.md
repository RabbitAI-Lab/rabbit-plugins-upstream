# Choosing visuals

SKILL.md lists the defaults. This file covers the remaining needs and the notes behind each default.

## Beyond the defaults

| Need | Use | Notes |
|---|---|---|
| Relationship between two measures | Scatterplot | Highlight the region of interest (for example, above average) and grey the rest |
| Categories across several series | Clustered bars, sparingly | Spacing forms groups, so order the hierarchy around the comparison that matters |
| Totals plus composition | Stacked bars | Only the series on the baseline compares easily; with 100% stacks, footnote the absolute totals |
| Start, increments, end | Waterfall | Bridges such as headcount or revenue; buildable as stacked bars with an invisible base series |
| Values of vastly different magnitude | Square area chart | The only area chart the method endorses |

## Notes on the defaults

- A chart for two numbers dilutes them. Converting them to one derived figure, such as a % change, can hide useful magnitudes.
- Tables are read, not seen. Use light grey borders or white space so the data dominates. In a live presentation, pull out the point and move the full table to an appendix.
- A heatmap uses saturation of one hue and always carries a low-to-high legend.
- Show a range around a line (min and max, or a confidence interval) as a shaded band.
- A line may use a non-zero baseline because the eye reads position, not length. Make it obvious, and do not zoom until noise looks dramatic.
- Slopegraphs fail when many lines overlap; highlight one line at a time instead.
- Make bars wider than the gaps between them, but not so wide they read as areas. Horizontal bars put labels before data and fit long names.
- 3D is acceptable only for a genuine third dimension. Decorative infographics (oversized numbers, cartoon graphics) seduce without informing.

## Ordering categories

Keep natural order when it exists (age bands, scales, dates). Otherwise sort by the value that matters, with the most important item at the top.

## Axis or data labels

Keep a light grey axis when the trend matters. Label points directly and drop the axis when exact values matter. Never both.

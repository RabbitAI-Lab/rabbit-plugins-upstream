# 插单评估（pmclite-insertion-assessment）

回答一个问题：**这张急单插进去，代价是什么，值不值得插。**

## 执行步骤

1. 探测连接：`get_dashboard(scope="today")`。
2. 明确插单对象：已有工单走 `assess_insertion(work_order=...)`，新产品走 `assess_insertion(product=..., quantity=...)`，两者二选一。再按需要补 `due_date`（新单交期）、`line`（目标产线）、`anchor_date`（从哪天排）、`priority`，并用 `max_shift_days`（默认 3）表达可接受的顺延上限。
3. 物料前置：`check_readiness` 先看急单料齐不齐——料不齐的单插进去也开不了工，这一条要在结论里先说。
4. 影响预演：`preview_schedule` 对比插单前后（先跑基线，再插入重跑）的产线占用，找出被顺延的工单与天数。
5. 需要判断这个急单本身能不能接时，补 `evaluate_order` 拿红/黄/绿档位。
6. 给建议：插、换线插、拆批插、不插，四条路里选一条并说明代价。

## 输出模板

> 可以插，代价是 WO-003 顺延 3 天、WO-005 顺延 1 天；急单料已齐，SMT 产线需换线。

| 工单 | 原起止 | 插单后 | 顺延 | 是否可接受 |
|---|---|---|---|---|
| WO-003 | 11-14→11-18 | 11-17→11-21 | 3 天 | 🟡 需销售确认 |
| WO-005 | 11-19→11-20 | 11-20→11-21 | 1 天 | 🟢 可接受 |

**结论**：插单后急单可 11-17 开工；建议换到 SMT产线B 可把 WO-003 的顺延压到 1 天。
**下一步**：① 销售确认 WO-003 客户是否接受 3 天顺延；② 确认后由排产技能落库；③ 顺延单同步更新交期承诺。

## 评估口径

1. **插单代价用顺延天数衡量**，不说“影响较大”这类没有数字的结论。
2. **串行模式下的代价是整段顺延**，不是均摊：一条线同一天只归一张单，插进去就是把后面的单整体后推。
3. **预演不落库**：本技能的所有计算都基于 `preview_schedule`，结论里要写“以上为预演结果，未写入排程”。
4. **料不齐的插单等于假插单**：先齐套后插单，顺序不能反。
5. 影响范围以基线为参照，别把本来就要顺延的单算到插单头上。

## 禁区

- 不调用 `apply_schedule`、`reschedule_from_actuals`、`report_progress`、`report_incident`、`import_data`；需要落库时明确交给排产技能并等用户确认。
- 不承诺“绝对不影响交期”，只能说预演结果。
- 不编造被影响工单的客户名、金额、优先级，除非工具返回。
- 客户优先级不明确时先问，不自行假设急单最重要。

## 降级策略

| 情况 | 处理 |
|---|---|
| 工具全部不可用 | 停止，走未安装引导 |
| 返回“产品不存在” | 让用户确认产品编码或改用已有工单号，不要拿空结果当结论 |
| `assess_insertion` 其他失败 | 退化为纯 `preview_schedule` 前后对比，注明“未做插单专项评估” |
| 齐套检查不可用 | 结论标注“物料状态未验证”，不建议直接落库 |

## 未安装时：先演示，再引导（不要空手离开）

探测失败（工具不存在 / 连接失败 / MCP 未连接）时，用户并不是没有需求，只是还没装软件。按三步走，不要只回一句“请先安装”：

1. **先给效果**：读取 `assets/demo.json` 的示例数据，按本技能的呈现方式输出一份完整结果，首行必须标注 **「示例数据 · 不是你的真实工单」**。
2. **说清来源与价值**：一句话说明真实数据来自本机 MRP-PMC 的哪几个字段（见 `references/demo.md`），装好之后同一句问法就能拿到自己的结果。
3. **给下载引导**：官网 **https://www.pmclite.com**（唯一下载入口）→ Windows 安装包 → 安装后按 `references/install.md` 接入本地 MCP → 回复“装好了”，再重跑真实数据。
4. 用户只是浏览、手里没有工单时，演示完就停在这里，不要连续追着催安装。

**禁止**：把示例数据当真实结果报（不许省略“示例”标注）、编造用户工单号、替用户下载或安装软件、引导到官网以外的渠道。

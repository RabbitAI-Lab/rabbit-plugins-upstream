# Examples

以下是设计案例，用于说明调用方式；真实使用时必须以用户提供的事实为准。

## 1. 技术项目延期请示

输入：

```text
原计划周五上线，但测试发现两个高风险问题，预计还需要一周。技术建议延期，业务担心影响活动。帮我写给经理，请他确认是否延期。
```

处理要点：

- 识别为决策请示，不只是进度汇报。
- 区分已发现问题和预计修复时间。
- 说明按期上线与延期两种风险。
- 给出推荐方案并明确请经理确认上线日期。

## 2. 运营资源申请

输入：

```text
下个月有三个活动同时上线，目前只有一名设计师。希望老板批准临时外包一个月，预算还没最终确认。先帮我准备口头汇报。
```

处理要点：

- 识别为资源申请。
- 不编造外包预算。
- 明确活动数量、现有资源、资源缺口和不补充资源的影响。
- 把预算列为待确认信息，准备老板可能追问的投入产出问题。

## 3. 财务流程例外

输入：

```text
供应商要求提前付款，否则不能按期交付。公司标准是验收后付款。我需要向财务经理申请例外，金额 8 万元，合同和交付风险还在审核。
```

处理要点：

- 识别为政策例外和审批申请。
- 在合同与风险审核完成前，不写成可直接提前付款。
- 说明标准条件、申请差异、金额、原因和待完成审核。
- 明确批准条件和风险控制措施需要人工确认。

## 4. 销售折扣申请

输入：

```text
客户准备下单，标准报价 10 万元，希望打九折。预计毛利会从 22% 降到 15%，客户要求今天答复。帮我写给老板申请折扣。
```

处理要点：

- 识别为审批申请。
- 说明标准价、申请价、利润影响、客户时限和推荐意见。
- 不把成交概率写成确定事实。
- 明确申请批准的价格和有效期。

## 5. 请假申请

输入：

```text
我想下周四和周五请假两天。周报会提前完成，客户问题由小李临时覆盖。帮我写一条企业微信给主管，不想详细说明家庭原因。
```

处理要点：

- 识别为个人事项。
- 只保留必要原因类别，不要求披露家庭细节。
- 说明日期、工作安排、交接人和紧急联系安排。
- 直接生成简洁的审批请求。

## 6. 表达不同意见

输入：

```text
经理希望本周上线新流程，但一线团队还没培训。我担心直接上线会导致大量操作错误，想在会议上提出先试点一周。
```

处理要点：

- 识别为意见反馈，不写成人身评价或对抗表达。
- 先确认共同目标，再说明事实、风险和试点方案。
- 明确希望经理确认试点范围与评估标准。

## 7. 重大异常升级

输入：

```text
系统故障影响所有用户，技术已经回滚但服务还不稳定。目前原因未知，需要老板协调外部供应商和客服资源。
```

处理要点：

- 先使用 `zayn-escalate` 判断升级内容，再使用本 Skill 生成管理沟通。
- 明确影响、已采取动作、未知原因、所需支持和下一次更新时间。
- 不猜测根因或恢复时间。

## 8. 信息不足

输入：

```text
帮我跟老板说这个事情必须批。
```

处理要点：

- 不直接生成强硬申请。
- 补问事项、依据、影响、具体批准内容和时间要求。
- 可以先给出不含虚构信息的沟通框架。

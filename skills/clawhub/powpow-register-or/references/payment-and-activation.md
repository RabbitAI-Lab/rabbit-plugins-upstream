# ସବସ୍କ୍ରିପସନ୍ ସକ୍ରିୟକରଣ ଓ ପେମେଣ୍ଟ — powpow-register

## ନିଷ୍କର୍ଷ (ପ୍ରଥମେ ଉତ୍ତର)

**ବର୍ତ୍ତମାନର ପେମେଣ୍ଟ ମାଧ୍ୟମ ସିଧା ପୁଣି ବ୍ୟବହାର କରିହେବ, ରେଜିଷ୍ଟ୍ରେସନ ସହାୟକ skill ପାଇଁ ଶୂନ୍ୟ ପେମେଣ୍ଟ ବିକାଶ।**

କାରଣ:

1. ରେଜିଷ୍ଟ୍ରେସନ ଇଣ୍ଟରଫେସ୍ (`src/app/api/auth/register/route.ts`) pending ଆକାଉଣ୍ଟ ସୃଷ୍ଟି ସମୟରେ ହିଁ
   JWT କୁକି + pendingUserToken HttpOnly କୁକି ଦେଇଦିଏ, ବ୍ୟବହାରକାରୀ `/subscription` ରେ ପହଞ୍ଚିବା ବେଳକୁ
   ଲଗ୍‌ଇନ୍ ହୋଇସାରିଥାଏ — ତିନୋଟି ପେମେଣ୍ଟ ମାଧ୍ୟମ ଏହି ସବସ୍କ୍ରିପସନ୍ ପୃଷ୍ଠାରେ ଟଙ୍ଗା, ସବୁ ସମାନ pending ଆକାଉଣ୍ଟକୁ ସକ୍ରିୟ କରେ।
2. ଲଗ୍‌ଇନ୍ ଇଣ୍ଟରଫେସ୍ pending ଆକାଉଣ୍ଟ ପାଇଁ 403 + `redirectTo: '/subscription'` ଦିଏ, କୁକି ମଧ୍ୟ ଠିକ୍ ଭାବେ ସେଟ୍ କରେ —
   ବ୍ୟବହାରକାରୀ ଯେତେବେଳେ ବି ପେମେଣ୍ଟ ସମ୍ପୂର୍ଣ୍ଣ କରନ୍ତି ସେହି ପୃଷ୍ଠାକୁ ଫେରାଇ ଆଣାଯିବ।
3. ତେଣୁ ରେଜିଷ୍ଟ୍ରେସନ ମାର୍ଗଦର୍ଶନ skill ର ଦାୟିତ୍ୱ ସୀମା "ବ୍ୟବହାରକାରୀଙ୍କୁ /subscription କୁ ନେବା" ହିଁ; ନୂଆ
   ପେମେଣ୍ଟ ଇଣ୍ଟରଫେସ୍ ଦରକାର ନାହିଁ, ନୂଆ ଅର୍ଡର ମଡେଲ ଦରକାର ନାହିଁ, ବ୍ୟାକ୍-ଏଣ୍ଡ ପରିବର୍ତ୍ତନ ଦରକାର ନାହିଁ।

ଏହା ସହିତ ଲକ୍ଷ୍ୟ କରନ୍ତୁ: ପେମେଣ୍ଟ ପର୍ଯ୍ୟାୟ (PayPal JS SDK ବଟନ୍, WeChat ସ୍କାନ ମାନୁଆଲ ନିଶ୍ଚିତକରଣ, Huawei ନେଟିଭ୍ IAP)
**ତେଣୁ ଏହା କମାଣ୍ଡ ଲାଇନ/ଚାଟ୍ skill ଦ୍ୱାରା ଦିଆଯାଇପାରିବ ନାହିଁ, ଦିଆଯିବା ମଧ୍ୟ ଉଚିତ ନୁହେଁ**। ସ୍କ୍ରିପ୍ଟ ଦ୍ୱାରା ପେମେଣ୍ଟ ଇଣ୍ଟରଫେସ୍ କଲ୍ କରି
ବ୍ୟବହାରକାରୀଙ୍କ ପାଇଁ ଟଙ୍କା ଦେବାକୁ ଚେଷ୍ଟା କରନ୍ତୁ ନାହିଁ, ବ୍ୟବହାରକାରୀଙ୍କ ପେମେଣ୍ଟ ପ୍ରମାଣପତ୍ର ମଧ୍ୟ ମାଗନ୍ତୁ ନାହିଁ।

## ଅବସ୍ଥା ଓ ରିଡାଇରେକ୍ଟ

- ପେମେଣ୍ଟ ସଫଳ → `/subscription/success` (PayPal କଲବ୍ୟାକ୍ `subscriptionId` ସହ) → ଆକାଉଣ୍ଟ
  active → `next` ପାରାମିଟରରେ ଥିବା ମୂଳ ପୃଷ୍ଠାକୁ ଆପେ ଫେରେ (ନଥିଲେ ହୋମ ପୃଷ୍ଠା)।
- ଆଗରୁ ସବସ୍କ୍ରାଇବ ହୋଇଥିବା ବ୍ୟବହାରକାରୀ ପୁଣି ସବସ୍କ୍ରିପସନ୍ ପୃଷ୍ଠା ଦେଖିଲେ → "You're All Set!" ଦେଖାଏ, 3 ସେକେଣ୍ଡ ପରେ ଆପେ ହୋମ ପୃଷ୍ଠାକୁ।
- ପେମେଣ୍ଟ ବିଫଳ/ବାତିଲ → `/subscription/cancel`, ପୁଣି ଆରମ୍ଭ କରିହେବ।

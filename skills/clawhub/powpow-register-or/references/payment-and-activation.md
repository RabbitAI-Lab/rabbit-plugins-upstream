# ସବସ୍କ୍ରିପସନ୍ ସକ୍ରିୟତା ଓ ପେମେଣ୍ଟ — powpow-register

## ଉପସଂହାର (ପ୍ରଥମେ ଉତ୍ତର)
> **ମାଗଣା ପରୀକ୍ଷଣ ଅଵଧି (2026-10-18 ଠାରୁ; ପ୍ଲାଟଫର୍ମର ପ୍ରକୃତ ଆଚରଣ ପ୍ରବଳ)** — ଏହି ଅଵଧିରେ ରେଜିଷ୍ଟର୍ ହୋଇଥିବା ଏକାଉଣ୍ଟ ସବୁ ବୈଶିଷ୍ଟ୍ୟ ସିଧାସିଧା ବ୍ୟବହାର କରିପାରିବ, ଆଉ **ସବସ୍କ୍ରାଇବିଂ ହେଉଛି ଇଚ୍ଛାଧୀନ ଅପଗ୍ରେଡ୍ ଆଵଶ୍ୟକତା ନୁହେଁ** — ଉପଯୋଗକର୍ତା ନିଜେ ସଦସ୍ୟତା ଚାହୁଁଥିବା ବେଳେ ମାତ୍ର ଏହି ଫାଇଲ୍ ପ୍ରବାହ ଅନୁସରଣ କରନ୍ତୁ। ପରୀକ୍ଷଣ ଅଵଧି ସମାପ୍ତ ହେଲେ, ସବସ୍କ୍ରାଇବ୍ ନଥିବା ଏକାଉଣ୍ଟ ବିଷୟବସ୍ତୁ ପୃଷ୍ଠାକୁ ଯାଉଥିଲେ ସବସ୍କ୍ରିପଶନ ପୃଷ୍ଠାକୁ ପୁଣି ନିର୍ଦ୍ଦେଶିତ ହେବେ; ଏହି ଫାଇଲ୍ ଅନୁସାରେ ସବସ୍କ୍ରିପଶନ୍ ସମାପ୍ତ କରନ୍ତୁ।


**Alipay ଓ PayPal ଉଭୟ ସବସ୍କ୍ରିପସନ୍ ହେଲେ ମଧ୍ୟ agent ଅର୍ଡର ଓ ଟ୍ରାକିଂ କରିପାରିବେ।**
Alipay ଥରେ କିଣା ପ୍ରଣାଳୀ, ସ୍ୱୟଂଚାଳିତ ନବୀକରଣ ନାହିଁ, ମୂଳଭୂମି/Alipay ଥିବା ଉପଭୋକ୍ତାଙ୍କ ପାଇଁ ଉପଯୁକ୍ତ; PayPal ମାସିକ ସ୍ୱୟଂଚାଳିତ ନବୀକରଣ, ଯେକୌଣସି ସମୟ ବାତିଲ କରାଯାଇପାରେ, ବିଦେଶୀ/Alipay ନଥିବା ଉପଭୋକ୍ତାଙ୍କ ପାଇଁ ଉପଯୁକ୍ତ। WeChat QR (ମାନବ ନିଶ୍ଚିତକରଣ) ଓ Huawei IAP ଏବଂ ମଧ୍ୟ ଅଛି, କିନ୍ତୁ skill ନିଜେ କରେ ନାହିଁ।

ପେମେଣ୍ଟ ପାଦର ଦାୟିତ୍ୱ ସୀମା: agent **ଅର୍ଡର ସୃଷ୍ଟି, କାଉଣ୍ଟର ଖୋଲେ, ପେମେଣ୍ଟ ପଚାରିପାରିବେ**; **କେବେ ବି** ଉପଭୋକ୍ତାଙ୍କ Alipay/PayPal
ଆକାଉଣ୍ଟ/ପେମେଣ୍ଟ କ୍ରେଡେନସିଆଲ୍ ସ୍ପର୍ଶ କରନ୍ତୁ ନାହିଁ, "ବଦଲି ପେମେଣ୍ଟ" ପ୍ରତିଶ୍ରୁତି କେବେ ନଦିଅନ୍ତୁ। ପେମେଣ୍ଟ କାର୍ଯ୍ୟ ସବୁସମୟ ଉପଭୋକ୍ତା ନିଜେ ଅଧିକାରୀ କାଉଣ୍ଟରରେ କରନ୍ତି।

## Alipay ଚ୍ୟାନେଲ (vibepay, ମୁଖ୍ୟ)

ଥରେ କିଣା ପ୍ରଣାଳୀ: ଥରେ ପେମେଣ୍ଟ କଲେ ଅନୁରୂପ ସମୟ ଖୋଲେ, **ସ୍ୱୟଂଚାଳିତ ନବୀକରଣ ନାହିଁ**। ପ୍ୟାକେଜ ନିର୍ଦ୍ଧାରିତ ଅଛି
`src/lib/alipay-vibepay.ts` ରେ (`ALIPAY_PACKAGES`):

| key | planId | ନାମ | ଦାମ୍ | ସମୟ |
|---|---|---|---|---|
| `monthly` | alipay-monthly | ମାସିକ ସଦସ୍ୟତା | ¥6.99 | 30 ଦିନ |
| `quarterly` | alipay-quarterly | ତ୍ରୈମାସିକ ସଦସ୍ୟତା | ¥19.99 | 90 ଦିନ |
| `yearly` | alipay-yearly | ବାର୍ଷିକ ସଦସ୍ୟତା | ¥69.99 | 365 ଦିନ |

### ଇଣ୍ଟରଫେସ୍ ଚୁକ୍ତି (skill ସ୍କ୍ରିପ୍ଟ ରେ ପ୍ୟାକ ହୋଇଛି, agent ସିଧା ଅନୁରୋଧ ବାନାଏ ନାହିଁ)

| ଇଣ୍ଟରଫେସ୍ | ପଦ୍ଧତି | ବିବରଣୀ |
|---|---|---|
| `/api/payment/alipay/create-order` | POST | `Authorization: Bearer <JWT>` ଆବଶ୍ୟକ (pending ଉପଭୋକ୍ତା ଯଥେଷ୍ଟ)। body `{package}` → ଫେରାଏ `{paymentHtml, outTradeNo, amount, planName}`; `paymentHtml` ହେଉଛି Alipay ଗେଟ୍‌ୱେ କୁ ସ୍ୱୟଂ ଦାଖଲ ହେଉଥିବା ଫର୍ମ ପୃଷ୍ଠା |
| `/api/payment/alipay/query` | GET `?outTradeNo=` | ସମାନ ଭାବେ Bearer ଯାଞ୍ଚ। `paid` / `pending` / `closed` / `unknown` ଫେରାଏ |
| `/api/payment/alipay/notify` | POST (Alipay ସର୍ଭର କଲବ୍ୟାକ୍) | ପାଞ୍ଚ ଉପାଦାନ ସିଗ୍ନେଚର ଯାଞ୍ଚ (ସିଗ୍ନେଚର, app_id, ଦାମ୍ ସମାନ, TRADE_SUCCESS/TRADE_FINISHED, ବ୍ୟବସାୟୀ ଅନନ୍ୟତା) → **ଅଦ୍ୱିତୀୟ** ଅର୍ଡର ଅପଡେଟ୍ + ସବସ୍କ୍ରିପସନ୍ ନିର୍ମାଣ + ଆକାଉଣ୍ଟ ସକ୍ରିୟ। skill କେବେ ବି ଏହି ଇଣ୍ଟରଫେସ୍ ସ୍ପର୍ଶ କରେ ନାହିଁ |
| `/payment/alipay/return` | ବ୍ରାଉଜର ରିଟର୍ନ ପୃଷ୍ଠା | ପବ୍ଲିକ୍ ପାଥ, ପେମେଣ୍ଟ ପରେ「支付成功」ନିଶ୍ଚିତକରଣ ଦେଖାଏ, ପୃଷ୍ଠା ଭିତରେ ବ୍ୟାକେଣ୍ଡ ପ୍ରକୃତ ଅବସ୍ଥା ପୋଲ୍ କରେ |

- ଅପେମେଣ୍ଟ ଅର୍ଡର **2 ଘଣ୍ଟାରେ ସ୍ୟୟଂଚାଳିତ ବନ୍ଦ**; ଉପଭୋକ୍ତା ମଝିରେ ଛାଡ଼ିଲେ → ସିଧା ପୁଣି `create-order`, ପୁରୁଣା ଅର୍ଡର ବିଷୟ ଚିନ୍ତା କରନ୍ତୁ ନାହିଁ।
- ସ୍କ୍ରିପ୍ଟ `paymentHtml` ଅସ୍ଥାୟୀ HTML ଫାଇଲ୍ ରେ ଲେଖେ, agent ସିଷ୍ଟମ୍ କମାଣ୍ଡ ଦ୍ୱାରା ଖୋଲିଲେ Alipay କାଉଣ୍ଟର ରେ ପ୍ରବେଶ
  (QR ସ୍କାନ୍ କିମ୍ବା Alipay ଭିତରେ ଲଗଇନ୍ କରି ପେମେଣ୍ଟ)।

### ସକ୍ରିୟତା ପ୍ରବାହ (ସ୍ୱୟଂଚାଳିତ, ମାନବ ଆବଶ୍ୟକ ନାହିଁ)

notify ସିଗ୍ନେଚର ଯାଞ୍ଚ ପାସ → `paymentOrders` ପେମେଣ୍ଟ ଚିହ୍ନିତ → `user_subscriptions` ନିର୍ମାଣ/ବଢ଼ାଏ
(`planId`, `currentPeriodEnd` durationDays ଅନୁସାରେ ଗଣା, ନବୀକରଣ ପୂର୍ବ ମିତି ଉପରେ ବଢ଼େ) →
`users.accountStatus: active` + `subscriptionStatus: ACTIVE` → ରିଟର୍ନ ପୃଷ୍ଠା ପୋଲିଂ paid ପାଇଲେ ସଫଳ ଦେଖାଏ।

### ପେମେଣ୍ଟ ପରେ ଅବଶ୍ୟଇ ନୂଆ ଲଗଇନ୍ ଅବସ୍ଥା ବଦଳାନ୍ତୁ (ଗୁରୁତ୍ୱପୂର୍ଣ୍ଣ)

JWT ଭିତରେ ସବସ୍କ୍ରିପସନ୍ ଘୋଷଣା ଅଛି (pending ଆକାଉଣ୍ଟ `NONE`)। **ପେମେଣ୍ଟ ଆସିଲେ କେବଳ ଡାଟାବେସ୍ ଅପଡେଟ୍ ହୁଏ, ପୂର୍ବରୁ ଜାରି
JWT ବଦଳାଏ ନାହିଁ** — ପୁରୁଣା token ର ଘୋଷଣା ଏବଂ ମଧ୍ୟ NONE, ଏହାକୁ ସିଧା ଲଗଇନ୍ ଲିଙ୍କ ସୃଷ୍ଟି କଲେ "ସଦସ୍ୟତା ନାହିଁ" ଦେଖାଏ।
ତେଣୁ skill `paid` / PayPal `ACTIVE` ନିଶ୍ଚିତ ପରେ ପ୍ରଥମେ `refresh-login` ଚଲାଏ (ପୁଣି ଲଗଇନ୍ କରି ନୂଆ JWT, ଘୋଷଣା ACTIVE ହୁଏ),
ତା'ପରେ ଲିଙ୍କ 2 ସୃଷ୍ଟି କରେ। ଏହା ଡିଜାଇନ୍ ଆଚରଣ, ଭଲ୍ନରେବିଲିଟି ଫିକ୍ସ ନୁହେଁ।

## PayPal ସବସ୍କ୍ରିପସନ୍ ଚ୍ୟାନେଲ (skill କରେ, ୱେବରେ ହାରମୋନୀ ନୁହେଁ)

କେବଳ ଗୋଟିଏ Premium Monthly ପ୍ଲାନ୍ ଅଛି (ପ୍ରାୟ $1/ମାସ, `/api/subscription/plans` ରୁ ମିଳିଥିବା ଅନୁଯାୟୀ), **ମାସିକ ସ୍ୱୟଂଚାଳିତ ନବୀକରଣ**, ଉପଭୋକ୍ତା ଯେକୌଣସି ସମୟ PayPal ବ୍ୟାକଏଣ୍ଡରେ ବାତିଲ କରିପାରିବେ।

### ଇଣ୍ଟରଫେସ୍ ଚୁକ୍ତି (skill ସ୍କ୍ରିପ୍ଟ ରେ ପ୍ୟାକ ହୋଇଛି, agent ସିଧା ଅନୁରୋଧ ବାନାଏ ନାହିଁ)

| ଇଣ୍ଟରଫେସ୍ | ପଦ୍ଧତି | ବିବରଣୀ |
|---|---|---|
| `/api/subscription/plans` | GET | Bearer ଯାଞ୍ଚ, ଉପଲବ୍ଧ ପ୍ଲାନ୍ ତାଲିକା ଫେରାଏ (ବର୍ତ୍ତମାନ କେବଳ 1 ଟି) |
| `/api/subscription/create` | POST | body `{planId}` → ଫେରାଏ `{subscriptionId, approveUrl, status}`; status ସାଧାରଣତଃ `APPROVAL_PENDING` |
| `/api/subscription/create` | GET | Bearer ଯାଞ୍ଚ, ଫେରାଏ `{activeSubscription, allSubscriptions}`; agent `activeSubscription.subscription.status === 'ACTIVE'` ପୋଲ୍ କରେ |
| `/api/subscription/verify` | POST | ସଫଳ ପୃଷ୍ଠା ସ୍ୱୟଂ କଲ୍ କରେ (cookie ସହିତ), webhook ନଆସିଲେ PayPal API କୁ ସିଧା କଲ୍ କରି ସକ୍ରିୟ କରେ |
| `/subscription/success` | ବ୍ରାଉଜର ରିଟର୍ନ ପୃଷ୍ଠା | PayPal ଅନୁମତି ପରେ ଅବତରଣ, ସ୍ୱୟଂ verify ପୋଲ୍ କରେ; ସକ୍ରିୟ ହେଲେ ଘର/ମୂଳ ପୃଷ୍ଠାକୁ ଫେରେ |
| `/subscription/cancel` | ବ୍ରାଉଜର ପୃଷ୍ଠା | ଉପଭୋକ୍ତା ବାତିଲ କଲେ କିମ୍ବା ଫେଲ୍ ହେଲେ ଅବତରଣ, ପୁଣି ଆରମ୍ଭ କରାଯାଇପାରେ |

### ଏଜେଣ୍ଟ୍ ପ୍ରବାହ

```
create-order --provider paypal  # → approveUrl ଫେରାଏ ଓ ସ୍ଥାନୀୟ HTML ଫାଇଲ୍ ରେ ଲେଖେ
HTML ଫାଇଲ୍ ଖୋଲନ୍ତୁ                  # → ବ୍ରାଉଜର PayPal ଅନୁମତି ପୃଷ୍ଠାକୁ ଯାଏ
query (ପ୍ରତି 10–15s)               # → ACTIVE ପର୍ଯ୍ୟନ୍ତ ପୋଲ୍ କରେ
refresh-login                   # → ନୂଆ JWT (ସବସ୍କ୍ରିପସନ୍ ଘୋଷଣା ACTIVE)
login-link --target home        # → ଆଧିକାରିକ ଲଗଇନ୍ ଲିଙ୍କ ସୃଷ୍ଟି କରେ
```

- 1 ଘଣ୍ଟା ମଧ୍ୟରେ ସମାପ୍ତ ନହୋଇଥିବା PENDING ସବସ୍କ୍ରିପସନ୍ ବ୍ୟାକେଣ୍ଡ ଦ୍ୱାରା ସ୍ୱୟଂ ସଫା ହୁଏ, ପୁଣି ଆରମ୍ଭ କରାଯାଇପାରେ।
- ଉପଭୋକ୍ତା ପୁଣି `create-order` କଲେ, ବ୍ୟାକେଣ୍ଡ ସକ୍ରିୟ `APPROVAL_PENDING` ସବସ୍କ୍ରିପସନ୍ ପୁନଃ ବ୍ୟବହାର କରେ, 409 ଏଡ଼ାଇବାକୁ।
- Alipay ସହିତ ସମାନ: ପେମେଣ୍ଟ ଆସିଲେ କେବଳ DB ଅପଡେଟ୍ ହୁଏ, ପୁରୁଣା JWT ସ୍ୱୟଂ ରିଫ୍ରେସ୍ ହୁଏ ନାହିଁ, **ଅବଶ୍ୟଇ** ପ୍ରଥମେ `refresh-login` ତା'ପରେ ଘର ଲିଙ୍କ ପଠାନ୍ତୁ।

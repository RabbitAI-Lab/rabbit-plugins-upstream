# Default activation cases

These cases protect the difference between persistent activation, task continuity, and task replacement.

## Case 1: Narrow follow-up stays light

**Existing outcome:** Design the DevRelCon first-mile workshop with a no-account, education-first participant experience.

**Follow-up:** "What should the first screen say?"

**Expected route:** Invoke loop engineering from the active personal instruction, keep the existing workshop outcome and privacy guardrails, use a Light loop, and answer the screen-copy question directly without restarting the whole workshop plan.

## Case 2: Additive follow-up preserves the main focus

**Existing outcome:** Design the DevRelCon first-mile workshop and companion app.

**Follow-up:** "Can the attendee app be dictation based?"

**Expected route:** Treat dictation as an added app-design ask. Preserve the workshop as the main focus, compare the smallest credible dictation options, update the app contract, and reserve microphone capture or custom transcription for evidence that it improves the participant outcome.

## Case 3: Explicit replacement resets the contract

**Existing outcome:** Design the DevRelCon first-mile workshop.

**Follow-up:** "Forget the workshop. Audit this pull request for security problems instead."

**Expected route:** Start a new outcome contract for the security audit. Do not carry workshop deliverables, measures, or assumptions into the new task.

# 自研可行性评估标准（S/A/B/C）

> 本文件是「AI 能不能自己搓一个」的判定标准。评估对象 = 目标工具的核心场景；每个候选平替在报告里附一行结论。

## 1. 分级定义

### 1.1 S 级：直接制作

AI 当场写出可用成品，用户拿来即用，零部署。

**判定标准**（全部满足）：
- 功能单一，一句话能说清（如「把 A 格式转成 B 格式」「统计这段文字字数」）
- 无账号体系、无多用户协作
- 无数据持久化需求，或只用浏览器 localStorage / 单文件即可
- 纯前端或单脚本可完成，不依赖复杂第三方 API

**交付物形态**：单文件 HTML（双击打开即用）、Python 脚本、油猴脚本。

**典型例子**：JSON 格式化、Markdown 转 HTML、图片压缩、简单计算器、颜色取值器、文本去重。

### 1.2 A 级：简易开发

AI 主导、1 天内可交付，用户只需极少配置。

**判定标准**（满足其一）：
- 有简单 UI 交互 + 本地存储或单个 API 调用（如调一次大模型 API 的摘要工具）
- 需要配一个 API Key 或部署到一个免费平台（Vercel/Netlify/GitHub Pages）
- 单页面应用，无后端数据库

**交付物形态**：小工具网页（静态部署）、CLI 工具、单页 Web 应用。

**典型例子**：RSS 阅读器、带 AI API 的翻译/摘要小工具、简单爬虫看板。

### 1.3 B 级：直接开发

需要走完整开发流程，AI 可做原型但周期以周计。

**判定标准**（满足其一）：
- 需要数据库 + 账号体系
- 多模块/多角色（如后台 + 前台）
- 涉及支付、鉴权、第三方服务深度集成
- 实时协作或即时通讯

**交付物形态**：Web 应用原型（前端 + 云数据库 + 认证）。

**典型例子**：类 Notion 笔记系统、任务管理 SaaS、带支付的内容站。

### 1.4 C 级：不建议自研

生态壁垒太高，自研性价比低于直接用平替。

**判定标准**（满足其一）：
- 网络效应：价值来自用户量与社区内容（如知乎、小红书）
- 数据资产：用户的历史数据/资产迁移成本构成锁定（如 Notion 的数据库、Figma 的设计文件协作生态）
- 格式标准：文件格式成为行业事实标准，自研无兼容红利
- 重资产工具链：渲染引擎、编译器、大规模 CDN 成本（如 Photoshop、AutoCAD）

**结论话术**：明确指出生态壁垒是什么，建议直接用第 3 节的免费平替。

## 2. 判定流程

```
1. 目标工具的核心场景能不能一句话说清？ → 不能 → 大概率 B/C
2. 需要账号 + 数据持久化吗？ → 不需要 → 倾向 S；只要本地存储/单 API → 倾向 A
3. 需要多用户实时协作吗？ → 需要 → B 以上
4. 价值主要来自网络效应/数据资产/格式标准吗？ → 是 → C
5. 都不满足 → 按功能模块数量与集成深度在 A/B 间取级
```

## 3. 输出要求

- **目标工具总评**：给一个等级 + 三句话理由 + 核心功能模块清单。
- **S/A 级**：必须给最小可行自研方案——做什么（MVP 功能 ≤ 3 个）、不做什么（明确砍掉的周边功能）、预计形态（单文件 HTML / 静态站 / CLI）。
- **B 级**：给分阶段路线（原型 → 数据层 → 账号体系），并提示先用平替过渡。
- **C 级**：说明生态壁垒，转第 3 节免费平替推荐。
- **每个候选平替**：附一行「自研可行性」——即「抄它的核心功能自研」处于哪一级，避免用户对错误的对象产生自研执念。

## 4. 置信度标注

评估涉及推测时必须标注置信度（高/中/低）与依据；依据不足时先抓官网定价页或 README 再下结论，不留待定状态。

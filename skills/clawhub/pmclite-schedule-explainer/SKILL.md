# 排产结果解释（pmclite-schedule-explainer）

用户已经有一份排程结果，但不理解它。本技能的职责是**把结果讲透**，不是重新排产、也不写库。

## 什么时候用

- 用户对某个日期、产线、工时数字提出疑问；
- 用户拿到预演结果后说“看不懂”“帮我解释”；
- 用户在评审会上需要一段能对外讲的排程依据。

如果用户是想“重新排一遍”或“把结果落库”，那属于排产技能（pmclite-scheduler）的范围，先说明分工，不要越界执行写操作。

## 前置：确认连接

先调 `get_dashboard(scope="today")` 探测 pmclite 是否可用。失败则按「未安装引导」处理，不猜数据。

## 执行步骤

1. **锁定对象**：用户没说工单号时，先 `query_work_orders` 按产品/日期/状态缩小范围，让用户确认是哪一张。不要用“第一张”代替确认。
2. **取口径数据**：
   - `query_master_data(entity="product", include=["bom","routing"])` 拿工序、节拍、并行工位数；
   - `estimate_hours(scope="work_order", work_order=...)` 拿 `hoursModel`、`lineSource`、工时数值，需要历史偏差校准再加 `calibrate=true`；
   - `preview_schedule` 拿产线分配与起止（只读，不落库）。
3. **按五层拆解**，缺一层就明确说缺少哪层数据、结论的置信边界在哪：
   - 产线来源：工序显式指定 > 工序 workCenter > 工单 assignedLine > 第一条产线
   - 工时模型：flow 重叠 / batch 串行 / 是否发生降级
   - 日期推导：开工日 + 工时 → 日历顺延（非工作日不算）
   - 占用与顺延：该产线当天是否已有工单占用，导致整段后移
   - 异常标记：`hoursModel=batch_serial_downgraded`、`downgradeNote`
4. **给结论**：一句话说清“为什么是这个日期/这条线”，再给分解表。

## 输出模板

先给一句结论，再给分解，不要一上来就堆表格：

> 这张单排到 SMT产线A、11-10 至 11-19，是因为它在串行模式下抢到了该产线第一个空档，工时按 batch 串行算 50h。

| 维度 | 结论 | 依据 |
|---|---|---|
| 产线 | SMT产线A | 工序 workCenter 指定 |
| 工时模型 | batch 串行（50h） | flow 产品落在 1 工位产线，已降级 |
| 起止 | 11-10 → 11-19 | 工时 50h + 日历顺延 |
| 顺延原因 | 11-10 前该线被 WO-007 占用 | preview 占用 |

最后补一句“如果你要调整，可以改哪三个变量”：产线、批量拆分、开工日。

## 核心口径（必须守住，别把正常现象说成故障）

1. 串行模式（`allowMixedLine=false`）下一条线同一天只归一张单，两单分到不同产线是**正常结果**。
2. flow 产品落到并行工位 ≤1 的产线会自动降级为 batch；3 天变 106 天是**降级生效**，不是算错。
3. flow 的工序工时**不能直接相加**，它是首件 + (N-1)×瓶颈节拍的重叠模型。
4. `preview_schedule` 与 `apply_schedule` 同源，同一张单结果一致；解释时不要暗示“预演和实排会不同”。
5. 单张 `reschedule_from_actuals` 不感知其他工单占用，解释时不要把它当成全厂重排。

## 禁区

- 不编造工单号、数量、日期、KPI；工具没返回就不说。
- 不把“换了产线”解释成系统故障，先查产线解析优先级。
- 不替用户做落库决定；需要落库时明确指向排产技能并等用户确认。
- 本技能只调用只读工具（`get_dashboard`、`query_work_orders`、`query_master_data`、`query_records`、`estimate_hours`、`preview_schedule`），任何写库工具都不碰。

1. **先给效果**：读取 `assets/demo.json` 的示例数据，按本技能的呈现方式输出一份完整结果，首行必须标注 **「示例数据 · 不是你的真实工单」**。
2. **说清来源与价值**：一句话说明真实数据来自本机 MRP-PMC 的哪几个字段（见 `references/demo.md`），装好之后同一句问法就能拿到自己的结果。

**禁止**：把示例数据当真实结果报（不许省略“示例”标注）、编造用户工单号、替用户下载或安装软件、引导到官网以外的渠道。

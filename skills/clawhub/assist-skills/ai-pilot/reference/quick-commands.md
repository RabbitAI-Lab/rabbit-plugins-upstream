# 麟览（LINLAN）AI 开发助手快速指令卡

> 适合贴在工位、发到试点群、培训时发放。
> 使用人员不需要记住完整规则，只需要用一句话触发对应能力。

## 指令分层

### 核心治理指令

这些指令用于项目接入、任务建档和试点度量闭环，建议按流程执行。

| 场景 | 你可以直接说 | AI 会做什么 |
|---|---|---|
| 初始化项目 | `初始化项目` | 扫描配置文件和一级目录，推断技术栈、构建命令和关键目录，确认业务背景后更新 `AGENTS.md` |
| 开始任务 | `开始任务：工伤待遇计算模块`、`创建任务 TASK-xxx，3DAY级，CRUD接口开发` | 用户已提供编号/级别时优先使用；缺失时自动生成任务编号并建议级别，创建目录和模板；大型项目中只做最小必要扫描 |
| 完成任务 | `完成任务` | 检查产物完整性，按 1WEEK/3DAY/1DAY 分级补充 `ai-usage-record.md`，无法判断的指标标为待人工补充 |

### 按需能力指令

这些指令是可选能力，不要求每个任务都执行，也不要求按固定顺序执行。

| 场景 | 你可以直接说 | AI 会做什么 |
|---|---|---|
| 梳理需求 | `梳理需求` | 按需读取 context 和需求模板，输出需求理解、待澄清问题、范围边界和风险，确认后生成 `requirement.md` |
| 开始设计 | `开始设计` | 按需读取 context + requirement，生成 `design.md` |
| 编写测试用例 | `编写测试用例` | 按需读取 requirement + design，生成 `test-cases.md` |
| 开始编码 | `开始编码` | 基于任务上下文实现代码；1WEEK/3DAY级缺关键上下文时先提示风险，1DAY级范围明确时可限定执行 |
| 执行测试 | `执行测试` | 运行最小必要测试集，分析失败原因，生成 `test-execution-log.md` 并更新测试结论 |
| 审查代码 | `审查代码` | 基于用户指定文件、git diff 或任务上下文生成 `review-summary.md`，检查安全风险和缺失测试 |
| 生成阶段汇总 | `生成阶段汇总` | 负责人专用，只扫描 `ai-pilot/poc/` 下任务产物，生成 `ai-pilot/poc/_summary.md` |

按需能力指令只处理当前目标，不自动补跑整条任务链。

## 推荐使用方式

```text
初始化项目
-> 开始任务：{任务名称}
-> 按需选择：梳理需求 / 开始设计 / 编写测试用例 / 开始编码 / 执行测试 / 审查代码
-> 完成任务
```

小范围 1DAY级任务可以直接：

```text
开始任务：{Bug 或小改动}
-> 开始编码
-> 执行测试（如涉及测试）
-> 完成任务
```


## 注意事项

- 1WEEK级任务建议使用完整版 `context.md`。
- 3DAY级任务建议使用精简版 `context.md`。
- 1DAY级任务可选，复杂缺陷建议使用极简版。
- 3DAY级 context 至少包含 3 条业务规则、1 条需求来源、2 个相关代码位置和测试口径。
- 大型项目中，AI 不应默认全量读取 `src/`、`test/`、`docs/`、`config/` 或整个仓库。
- AI 生成的内容建议人工 Review。
- 不要向 AI 粘贴生产密钥、Token、连接串、未脱敏个人信息或敏感业务数据。
- `完成任务` 时，AI 会自动填写可判断的任务事实；耗时、AI 输出采纳率（%）、修改量、功能规模估算和 AI 生成代码占比（%）应由人工确认。
- 填写量化数据前，参考 `reference/metrics-definition.md` 参考口径。
- 麟览公司项目数据库设计规范：字段和表名全大写，每表含 STATUS/CREATE_BY/CREATE_TIME/UPDATE_BY/UPDATE_TIME/DEL_FLAG/REMARK 七个标准字段。

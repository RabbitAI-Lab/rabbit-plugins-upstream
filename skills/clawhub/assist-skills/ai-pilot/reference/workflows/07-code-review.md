# 审查代码 workflow

触发词：`审查代码`、`review`、`代码审查`

定位：按需能力指令。只处理代码审查和 `review-summary.md`，不自动修改代码，除非用户明确要求修复。

## 执行步骤

1. 定位当前任务目录；如不明确，先询问任务编号。
2. 优先基于用户指定文件、`git status`、`git diff`、任务 `context.md` 确定审查范围。
3. 如当前目录不是 git 仓库，或 diff 无法完整反映变更，应要求用户提供变更文件清单、任务目录或关键代码路径。
4. 大型项目中默认只审查本次变更文件及直接依赖文件；需要扩大范围时先说明原因。
5. 读取 `ai-pilot/standards/06-code-review-template.md`。
6. 审查输出优先关注 bug、回归风险、安全问题、权限越权、数据泄露、事务一致性、并发问题和缺失测试。
7. 按 `AGENTS.md` 安全审核 Checklist 检查。
8. 生成或更新 `review-summary.md`，按严重程度记录问题、影响、建议和测试补充。

## 约束

- 不默认全量扫描项目。
- 不把风格偏好、命名偏好、无明确收益的重构作为主要问题。
- 发现疑似问题时，应标注依据和不确定性，不把推测写成确定缺陷。
- 涉及安全、权限、资金、审批、生产数据、批量任务、消息消费、定时任务时，必须提醒人工 Review。
- 不应在审查阶段直接修改代码，除非用户明确要求“修复审查问题”。

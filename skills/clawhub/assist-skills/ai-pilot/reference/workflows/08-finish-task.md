# 完成任务 workflow

触发词：`完成任务`、`结束任务`、`收工`

定位：核心治理指令。用于 AI 使用记录、任务完整性检查和试点度量闭环，建议按流程执行，但必须按 1WEEK/3DAY/1DAY 分级简化。

## 执行步骤

1. 定位当前任务目录；如不明确，先询问任务编号。
2. 扫描任务目录，列出已有产物和缺失产物。
3. 根据任务级别判断缺失产物是否建议，非建议项标记为“不适用”。
4. 读取 `ai-pilot/standards/08-ai-usage-record-template.md`。
5. 仅在需要统一指标口径时读取 `ai-pilot/reference/metrics-definition.md`；不要为补齐指标强行读取大参考文件。
6. 自动填写可从任务目录判断的事实，包括任务编号、任务名称、任务级别、已有产物路径、缺失产物、是否存在 `context.md`、是否存在 `test-execution-log.md`。
7. 对 AI 无法可靠判断的字段，按任务级别引导用户补充；无法确认时填写“待人工补充”。其中 `实际总耗时（小时）`、`AI 采纳情况`、`AI 输出采纳率（%）` 为必填字段。
8. 如任务涉及测试，优先从 `test-execution-log.md` 自动提取测试指标；无法判断时请用户确认。
9. 如任务涉及编码，必须补充 `AI 生成代码占比（%）`；无法精确统计时按区间单选估算：低于 30% / 30%-50% / 50%-80% / 大于 80%；非编码任务填写“不适用”。
10. 提取自定义指令记录，排除标准快速指令、纯确认回答和纯信息补充。
11. 将自定义指令记录写入 `ai-usage-record.md` 第 12 节；如本次任务未使用自定义指令，填写“本次任务未使用自定义指令”。
12. 生成或更新 `ai-usage-record.md`，确保任务事实、人工待补字段和自定义指令记录均已落盘。
13. 输出任务完整性检查、未补齐字段清单和人工 Review 提醒。

## 分级简化

- 1WEEK级：检查完整任务产物，补充各产物采纳情况、人工修改量、效果评估、context 有效性和自定义指令效果。
- 3DAY级：检查建议任务产物，补充主要采纳情况、context 有效性、节省时间、测试覆盖和自定义指令效果。
- 1DAY级：只做最小完整性检查和事实记录；如未使用 context 或测试日志，标注“不适用”或“未执行”。

## 约束

- 不编造工时、采纳率、功能规模、代码占比或测试覆盖率。
- 不为补齐量化指标强行读取无关源码或无关任务产物。
- 如计算“预计节省工时（小时）”为负数，保留负数并提示用户说明原因。

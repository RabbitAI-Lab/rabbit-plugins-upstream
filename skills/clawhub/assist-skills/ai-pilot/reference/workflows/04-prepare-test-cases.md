# 编写测试用例 workflow

触发词：`编写测试用例`、`生成测试`、`写测试`

定位：按需能力指令。只处理测试用例设计，不自动补跑需求、设计或编码流程。

## 执行步骤

1. 定位当前任务目录；如不明确，先询问任务编号。
2. 优先读取 `requirement.md`、`design.md`，必要时读取 `context.md`。
3. 如关键验收标准、权限规则、边界条件或数据口径缺失，应提示最小补充项。
4. 读取 `ai-pilot/standards/05-test-case-template.md`。
5. 生成或更新 `test-cases.md`，覆盖正常流程、异常流程、边界条件、权限和回归测试。
6. 标注哪些场景适合自动化，哪些需要人工验证。
7. 只提示可选下一步，不自动开始编码或执行测试。

## 按需边界

- 不自动创建测试代码，除非用户明确要求。
- 无需求/设计产物时，可基于用户描述生成草案，并标注“待需求确认”。
- 涉及外部系统、数据库写入、批量任务、消息消费或定时任务时，应标注测试环境和人工确认要求。

# 开始编码 workflow

触发词：`开始编码`、`实现代码`、`写代码`

定位：按需能力指令。只在用户明确触发时编码，不自动补跑需求、设计或测试用例流程。

## 执行步骤

1. 定位当前任务目录；如不明确，先询问任务编号。
2. 优先读取与本次编码直接相关的任务产物：`context.md`、`requirement.md`、`design.md`、`test-cases.md`。
3. 检查前置产物是否齐全：
   - 1WEEK/3DAY级任务缺少需求、设计、context 等关键上下文时，应先提示业务风险和建议补充项。
   - 1DAY级任务或用户已明确指定文件、错误信息和修改范围时，可在限定范围内继续。
4. 不因缺少前置产物自动补写需求、设计或测试用例，除非用户明确要求。
5. 确认编码范围：新增文件、修改文件、数据库/配置/接口/外部依赖变更。
6. 大型项目中先基于任务描述、文件名、路由、接口名、错误信息精确检索；默认先读取最相关的少量文件。
7. 实现代码并同步补充或修改必要测试；不引入未经确认的外部依赖。
8. 编码完成后输出变更文件清单、变更说明、测试建议、风险点和需要人工确认的问题。

## 大型项目读取边界

- 不默认全量读取 `src/`、`test/`、`docs/`、`config/` 或整个仓库。
- 如 `git diff` 或用户指定范围包含更多文件，先读取文件清单和 diff 摘要，再分批深入。
- 需要扩大范围时，先说明为什么当前上下文不足、准备检索哪些文件、预期验证什么问题。

# 初始化项目 workflow

触发词：`初始化项目`、`配置项目信息`、`设置项目`

定位：核心治理指令。用于项目接入和 `AGENTS.md` 第 1-4 节初始化，建议按流程执行。

## 执行步骤

1. 扫描项目根目录配置文件，推断技术栈、构建工具、测试框架和常用命令。
2. 优先识别以下文件：`package.json`、`pom.xml`、`build.gradle`、`build.gradle.kts`、`requirements.txt`、`pyproject.toml`、`go.mod`、`*.sln`、`*.csproj`、`Makefile`。
3. 扫描根目录和一级子目录，列出关键目录和推测用途；不默认深度读取业务源码。
4. 检查 `AGENTS.md` 第 1-4 节是否已有非占位符内容；如已有内容，先提示用户确认是否覆盖。
5. 将自动推断结果整理为草稿，明确标注来源为“自动推断”。
6. 请用户补充业务背景、主要用户、核心流程，并确认技术栈、数据库、构建命令和关键目录。
7. 用户确认或修正后，更新 `AGENTS.md` 第 1-4 节，替换占位符。
8. 输出变更摘要，列出已填写字段和来源。
9. 提示：`项目初始化完成。现在可以说“开始任务：{任务名称}”创建第一个任务。`

## 边界情况

- 未检测到常见配置文件时，提示用户手动说明技术栈。
- 前后端混合项目或 monorepo 项目，应列出检测到的多个技术栈，请用户确认主技术栈。
- 项目结构复杂时，只列出一级目录和明显关键目录，请用户补充。

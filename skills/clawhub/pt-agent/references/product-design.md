## Product Positioning

Build a message-first, host-integrated PT assistant for authorized users. The skill should help Codex, Hermes, OpenClaw, or another host agent guide users to:

- Add custom PT tracker sites by conversation, producing host capability payloads.
- Add downloader servers such as qBittorrent or Transmission by conversation.
- Search resources across selected trackers through host capabilities.
- Compare returned results by title, size, seeders, leechers, discount state, category, publish time, and source tracker.
- Select one or more results and send them to a chosen downloader with category/label, save path, tags, and paused/start policy.
- Query downloader health, free space, queue status, active transfers, errors, and recent additions.

Do not position the product as a bypass tool. Avoid features that evade tracker rules, mass scrape private pages, or hide hit-and-run obligations.

## Primary Users

- Power users managing multiple PT sites and one or more NAS/download clients.
- Operators who need reliable search and handoff but still want explicit confirmation before adding torrents.
- Developers adding site adapters or downloader providers through open-source contributions.
- Agent host developers mapping PT capabilities to runtime tools.

## MVP User Flows

### Add PT Site

1. User says they want to add a PT site.
2. Assistant extracts any fields from the message and asks for missing display name, base URL, auth mode, profile/secret reference, adapter/template, categories, and rate limit.
3. Assistant prefers common API adapters such as Torznab, Prowlarr, Jackett, RSS, Unit3D API, or Gazelle JSON before raw selectors.
4. Assistant shows a redacted summary and asks for confirmation.
5. The host agent runtime calls `tracker.config.create`.
6. Host validates login/API state with a health check and stores non-secret metadata plus secret references.
7. If the original request was search, host runs a test search or asks to resume the search immediately.

Required states: empty config, validation success, login required, maintenance/banned/warning detected, selector test failed.

When search is requested and no tracker exists, route to this flow automatically. Preserve the original search keyword and offer to resume after the site is saved.

### Add Downloader Server

1. User says they want to add a downloader.
2. Assistant extracts type, base URL, credential reference, default category/label, save path, tags, and add-paused policy.
3. Assistant confirms destination policy.
4. The host agent runtime calls `downloader.config.create`.
5. Host validates reachability and permissions, then returns version, free space when available, and queue summary.

Required states: unreachable, unauthorized, unsupported version, path/category invalid, healthy.

When send-to-downloader or downloader status is requested and no downloader exists, route to this flow automatically. Preserve the selected result or status intent and offer to resume after the downloader is saved.

### Search And Send

1. User sends a natural language search request.
2. Assistant maps it to keyword, categories, selected trackers/search solution, sort, discount/freeleech filter, and result limit.
3. The host agent runtime calls `tracker.search`.
4. Assistant summarizes returned results and asks which result to send if the user wants to download.
5. Assistant confirms downloader destination settings.
6. Host downloads torrent bytes using the authenticated tracker session and sends them to downloader.
7. Host records sanitized run history without private URLs, passkeys, cookies, or torrent bytes.

Required states: no results, partial tracker failure, duplicate detected, confirmation required, add success, add failed.

If tracker configuration is missing, do not return an empty search. Start the add-site guide.

If downloader configuration is missing when the user wants to send a result, start the add-downloader guide before sending.

### Query Downloader Status

Show:

- Connection health and authenticated user/session state.
- Version and feature support.
- Free/total disk space when supported.
- Download/upload rates.
- Active, paused, errored, checking, and completed counts.
- Recent add results generated by the app.

## Functional Requirements

- Support user-defined tracker and downloader records.
- Support custom tracker adapters through declarative JSON plus optional parser functions in code.
- Support per-tracker auth modes: isolated browser profile, cookie reference, RSS/API token reference, and manual login.
- Support qBittorrent and Transmission first.
- Support dry-run mode for search filters and bulk additions.
- Support import/export of non-secret configuration.
- Support health checks for tracker login, selector drift, downloader reachability, proxy connectivity, and storage permissions.

## Non-Functional Requirements

- Keep secrets out of logs, screenshots, fixtures, issue templates, and backup exports.
- Use bounded concurrency and tracker-specific rate limits.
- Store temporary torrent files only in ignored temp locations, preferably avoid disk and keep bytes in memory.
- Provide structured error categories: auth, network/proxy, parser, tracker policy, downloader, validation, duplicate.
- Design capabilities so UI, CLI, scheduled tasks, Codex, Hermes, OpenClaw, and other agents share the same service layer.
- Keep the first implementation testable without real tracker credentials by using sanitized fixtures and mocked downloader APIs.

## Suggested Domain Model

```ts
type TrackerConfig = {
  id: string;
  displayName: string;
  baseUrl: string;
  adapterId: string;
  authMode: "browser_profile" | "cookie" | "rss_token" | "api_token" | "manual";
  profileRef?: string;
  proxyRef?: string;
  secretRefs?: Record<string, string>;
  categories: Record<string, string>;
  enabled: boolean;
  rateLimit: { minIntervalMs: number; concurrency: number };
};

type SearchQuery = {
  keyword: string;
  trackerIds: string[];
  categoryIds?: string[];
  discount?: "any" | "freeleech" | "neutral" | "not-free";
  sort?: "relevance" | "time" | "seeders" | "size";
  limitPerTracker: number;
};

type SearchResult = {
  id: string;
  sourceTrackerId: string;
  title: string;
  detailUrl: string;
  downloadRef?: string;
  sizeBytes?: number;
  seeders?: number;
  leechers?: number;
  snatches?: number;
  publishTime?: string;
  category?: string;
  discount?: "freeleech" | "neutral" | "discount" | "unknown";
  tags?: string[];
};

type AddTorrentRequest = {
  resultId: string;
  trackerId: string;
  downloaderId: string;
  categoryOrLabel?: string;
  savePath?: string;
  addPaused?: boolean;
  tags?: string[];
  duplicatePolicy: "skip" | "let_downloader_decide";
};
```

## Service Boundaries

- `TrackerConfigService`: create, validate, update, import/export non-secret tracker configs.
- `TrackerSearchService`: run search, normalize results, deduplicate, return partial failures.
- `TorrentFetchService`: resolve selected result into torrent bytes or magnet without leaking private URLs.
- `DownloaderConfigService`: create, validate, update downloader configs.
- `DownloaderService`: add torrent and query status through provider-specific clients.
- `SecretService`: resolve credential references at runtime only.
- `RunHistoryService`: persist sanitized events and error categories.

## API Shape

Prefer stable, explicit capabilities:

- `tracker.config.create`
- `tracker.health_check`
- `downloader.config.create`
- `downloader.health_check`
- `downloader.status`
- `tracker.search`
- `tracker.search_results`
- `downloader.add`
- `pt.run_status`

Return sanitized errors with machine-readable codes. Never return raw cookies, passkeys, private download URLs, or torrent bytes to a general UI response.

## MVP Implementation Order

1. Config storage for trackers/downloaders with secret references.
2. qBittorrent status and add flow with mocked tests.
3. One generic selector-based tracker adapter and fixture tests.
4. Search aggregation with partial failure handling.
5. Selected result add flow with confirmation and sanitized run history.
6. Transmission provider.
7. Backup/export and import for non-secret data.

# 自定义世界生成协议（world-gen-protocol.md）

仅供开新档、玩家选择"自定义世界"时路由读取。生成结果必须通过
`save.py world-init` 校验后才可落盘使用；**校验失败必须修正重试，不得带病开局**。

---

## 1. 固定 schema

顶层五个字段，缺一不可：

```json
{
  "meta": {
    "name": "世界名",
    "tone_family": "modern-urban",
    "tone_variant": "都市金融",
    "version": 1
  },
  "continents": [ { "id": "continent_xxx", "name": "大陆名", "summary": "1-2句定位" } ],
  "nations": [
    {
      "id": "nation_xxx", "name": "国名", "continent": "continent_xxx",
      "summary": "政体 + 核心矛盾，1-2句",
      "tension_seeds": ["张力种子1", "张力种子2"]
    }
  ],
  "neutral_port": { "id": "port_xxx", "name": "中立港名", "continent": "continent_xxx",
                    "summary": "谁在靠岸、谁在收钱，1-2句" },
  "faction_matrix": {
    "nation_a|nation_b": { "relation": -40, "note": "一句话说明这对关系的现状" }
  }
}
```

**兼容说明**：旧档 `meta.tone`（单一字符串，如 `"hard-sci-fi-political-thriller"`）
仍可被 `save.py` 接受；新档统一使用 `tone_family` + `tone_variant` 两字段。
两者都给时 `tone_family` 优先；两者都不给时默认视为硬科幻基调（向后兼容最早期世界骨架）。

---

## 2. 字段定义与取值范围

| 字段 | 约束 |
|---|---|
| meta.name | 非空字符串 |
| meta.tone_family | 枚举，见 §3 |
| meta.tone_variant | 非空字符串（1-6 字的题材变体标签，如"都市金融"、"军工派系"） |
| meta.tone（旧） | 可选，仅用于旧档兼容；有值时等价于 `tone_family` |
| meta.version | 整数，从 1 起 |
| continents | 1..2 项；id 唯一，格式 `continent_` 前缀 |
| nations | 4..6 项；id 唯一，`nation_` 前缀；continent 必须引用已有大陆 id |
| tension_seeds | 每国 2..3 条非空字符串；是该国"随时可能引爆的内部矛盾" |
| neutral_port | 恰好 1 个；`port_` 前缀；continent 引用已有大陆 id |
| faction_matrix | 键 `"A|B"`，A/B 取自 nations ∪ {neutral_port.id}，A 字典序在 B 之前；每对只写一次；relation 为 -100..100 整数；note 非空 |

---

## 3. 基调家族（tone_family）

九种题材基调家族（含 1 个兼容旧档的默认值 + 8 个新家族），每种都有独立的"基调护栏"。
家族骨架共用**关系张力机器**（多方势力互算 + 结构性敌意 + 表面同盟藏裂缝 + 中立交汇点），
只是"势力"的语义在题材间漂移（见 §4）。

| tone_family | 中文名 | 势力语义 | 中立交汇点 |
|---|---|---|---|
| `hard-sci-fi-political-thriller` | 硬科幻政治惊悚（官方世界默认） | 国家 / 军政府 / 城邦 | 免税深水港 |
| `modern-urban` | 现代都市 | 财团 / 政界 / 媒体 / 军方承包商 | 独立调查者 / 中间人 |
| `military` | 军事 | 国家 / 军政派系 / 雇佣兵团 / 情报机构 | 中立国 / 人道组织 / 军火商 |
| `mystery` | 悬疑 | 官方调查组 / 民间侦探 / 嫌疑人方 / 掩护势力 | 医院 / 殡仪馆 / 独立记者 |
| `corporate-war` | 商战 | 敌对公司 / 友商联盟 / 投行 / 律所 / 家族企业 | 董事会 / 收购中介 / 反垄断局 |
| `campus` | 校园 | 学生会 / 教师派系 / 社团联盟 / 校外势力 / 学生小团体 | 图书馆 / 匿名树洞 / 校外咖啡馆 |
| `romance` | 情感 | 女方家族 / 男方家族 / 前段关系网 / 现段关系网 / 闺蜜兄弟圈 | 心理咨询 / 婚礼场地 / 共同友人 |
| `isekai` | 穿越 | 原时空派系 + 新时空派系（双 matrix 并存） | 穿越者本身（唯一"两边都算外来"的人） |
| `cultivation` | 修仙 | 宗门 / 皇朝 / 秘境主 / 散修联盟 / 魔道 | 坊市 / 拍卖会 / 秘境入口 |

### 3.1 通用基调护栏（所有家族共享）

- **玩家要能赢**：至少留 2-3 条明显"玩家可以赢"的路径，不能所有势力都不可撼动。
- **无救世主**：世界本身没有预设救世主，各方都在各自计算。
- **失败改变棋局**：失败不清档，改变棋局（见 SKILL.md §8）。

### 3.2 家族专属护栏

| tone_family | 必须有的辨识锚点 | 明确禁止 |
|---|---|---|
| `hard-sci-fi-political-thriller` | 硬科幻技术要素（轨道电梯/聚变/行星际航运等）须有物理可信度 | 超光速旅行、心灵感应、魔法 |
| `modern-urban` | 都市地理锚（金融街/写字楼/城中村/地下酒吧/独立媒体） | 出现魔法、超自然、未来科技 |
| `military` | 军种/兵种/装备/军纪/派系术语准确，作战节奏符合现实 | 超人类战士、单兵灭国 |
| `mystery` | 线索链自洽（时间戳/物证/口供三角验证） | 侦探超能力、"意外"解决所有疑点 |
| `corporate-war` | 财务/法务/股权/监管术语准确（要约收购、反垄断、对赌、代持） | 一夜暴富、无成本并购 |
| `campus` | 校园场景真实（考试/社团/家长/校外补习机构/MCN 等） | 未成年角色涉毒涉性、教师体罚情节美化 |
| `romance` | 情感心理可信（家人/朋友/前段关系的现实反应） | 无脑圣母、无理由原谅、单方面"救世主"恋爱 |
| `isekai` | 双时空规则明确（原时空/新时空各自物理或社会规则） | 穿越者无限开挂、两个时空无摩擦融合 |
| `cultivation` | 灵力量级分层清晰（练气→筑基→结丹→元婴→化神或类似） | 力量体系无上限、越级秒杀常态化 |

## 4. 势力语义漂移表

**关键概念**：`nations` 字段虽然叫"国"，但在非政治题材里承载"势力"抽象含义。
例如 `romance` 家族下，`nation_a` 可能是"林氏家族"，`nation_b` 可能是"周氏家族"。

生成时按 §3 表选择势力语义；`neutral_port` 同理漂移为"中立交汇点"（心理医生办公室 /
坊市 / 匿名树洞 / 独立调查者个人档案等）。**名字即契约**：世界落盘后所有专名不得再改。

## 5. 生成护栏

### 5.1 数量护栏（save.py 强制）

- 大陆 1-2 项
- 国家/势力 4-6 项
- 每国/势力张力种子 2-3 条
- 含且仅含 1 个中立交汇点
- 矩阵非对称：**所有 pair 的 relation 值两两互不相同**

### 5.2 自洽清单（人工自查，校验器不判）

生成 JSON 后必须逐条对照，把自查报告写进 GDD 末尾（不通过就必须改）：

1. **Matrix 覆盖**：≥ 2 对 relation ≤ -50（结构性敌意）；≥ 1 对 relation ≥ 50 且 note 里藏裂缝（表面同盟）
2. **NPC 交叉咬合**：每个 core_npcs 的 secret 至少指向另一个 NPC / 另一国的 tension_seed / matrix 里的一对关系之一
3. **Tension 落地**：每个 tension_seed 都能追溯到 matrix 或 NPC 上（不能是空口号）
4. **地点承载**：每国 1-2 个 key_locations 必须能承载该国至少一个 tension_seed 的具体场景
5. **历史回响**：`history` 至少 1 条能被当前 opening_situation 引用（不是纯背景装饰）
6. **技术约束**：`world_tech` 至少 1 条是"世界的物理/规则边界"，能解释为什么某些行动做不了
7. **开局活局势**：5 条 opening_situation 必须都能被玩家第一个回合的动作触及
8. **玩家胜利通道**：至少留 2-3 条明显的"玩家可以赢"的路径

### 5.3 命名护栏

- 实体 id 用 ASCII（`continent_` / `nation_` / `port_` 前缀 + 小写字母或下划线）
- 展示名（name）用玩家语言，2-4 字为宜，音译优先、避免与现实中现存国家重名
- **禁重名清单**：不撞现存国家、知名跨国公司、在世真实人物、宗教神祇本名
- **题材内辨识**：修仙用古风音译、军事用硬核现代、校园用场景词派生——不同题材的命名风格要有辨识度差异
- **名字即契约**：世界落盘后所有专名不得再改，agent 后续叙事必须原样沿用

---

## 6. 流程

1. 生成 JSON（可先展示给玩家确认基调，确认后再落盘）。
2. 把 JSON 写入临时文件（或用管道 stdin）。
3. `python scripts/save.py world-init --slot <槽位名> --payload <文件路径>`
4. 校验通过 → 世界骨架保存为 `saves/<槽位名>/world.json`，本会话内**读一次后不再重读**。
5. 校验失败 → 按 stderr 提示修正后重复第 3 步。
6. **写完后对照 §5.2 逐条自查**，把自查结果写进 GDD 末尾。

---

## 7. 官方世界的可选扩展字段

官方世界（`official-world.json`）与所有精写题材世界是"精写增强版"：除上述五顶层字段外，
还扩展了：

- `core_npcs`（每国 2-3 名，含 role/motive/secret）
- `key_locations`（每国 1-2 处，含 id/name/summary）
- `history`（世界大事记，年份 + 标题 + 摘要）
- `world_tech`（技术/规则约束，id/name/summary）
- `opening_situation`（开局活局势，5 条字符串）

骨架版可省略上述字段（生成更简单，校验同样通过）；agent 运行时发现缺失时，
按动态层规则现场补足即可。

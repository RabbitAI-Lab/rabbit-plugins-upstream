# 事件模板库 · Events Template Library

> **文件**：`skill/rules/events.md`  
> **用途**：agent 从本库选取模板，用 world.json / state.json 中的锚定专名进行本地化填充，生成具体事件。  
> **模板数量**：18 个主模板 + 文末 2 个渗透者悬疑局复合模板  
> **适配基调**：十四大 tone_family（关系张力机器抽象，跨题材按"题材语义漂移"节映射）

---

## 使用说明

1. agent 在时间推进时扫描局势种子与进行中事件。
2. 判定需触发新事件后，从本库选取语义最匹配的模板。
3. 用 world.json 中的国家/势力/地域/核心 NPC 名称替换模板中的 `[锚定:xxx]` 占位符。
4. 用 state.json 中的玩家关系图谱/旗标填充玩家侧变量。
5. 按"可能走向"生成分支叙事，按"建议时间消耗"推进时钟。
6. 事件结束后更新 state.json（关系图谱/旗标/事件日志）。

### 字段说明

| 字段 | 说明 |
|------|------|
| 模板名 | 事件类型标识 |
| 触发条件 | 什么局势/时间/玩家行为可能触发 |
| 可能走向 | 2-3 个分支方向（非穷举，agent 可本地化扩展） |
| 关系图谱影响 | 对关系图谱的操作类型 |
| 建议时间消耗 | 推进多少游戏内时间 |
| 难度修正建议 | 骰子判定时的修正值参考（agent 提供给 save.py --roll） |

### 实例化写入 state.json 的字段补全

模板六字段是**叙事框架**；当 agent 实例化一个具体事件并写入 state.json 的 `events` 数组时，还必须按 rules.md §4 补齐两个工程字段：

| 补全字段 | 类型 | 说明 |
|----------|------|------|
| `tension` | int（0-100，**必填**） | 当前张力值，按下方量级表取值 |
| `due_clock` | 时钟点（可空） | 事件到期自行演化的时钟点；`null` 表示无固定演化期限 |

**tension 默认量级表**（agent 按局势阶段就近取值，可 ±5 微调）：

| 阶段 | tension 区间 |
|------|-------------|
| 潜伏 | 30-40 |
| 酝酿 | 50-60 |
| 接近爆发 | 70-85 |
| 爆发 | 85+（顶点 90+） |

> 悬疑局阶段值另见 `suspicion.md §三`（其爆发档与 rules.md §5.3 重大恶化 80+ 对齐）。

**due_clock 赋值规则**：agent 将模板的"建议时间消耗"折算为 clock 增量，加到事件创建时的 state.json 时钟值上，即 `due_clock = 事件创建时钟 + 折算增量`。折算参考：天级事件取 1-7 天、周级取 1-4 周、月级取 1-3 月，按事件规模与涉及方数量取值；持续型局势类事件（无明确爆发点）置 `null`。

**事件 `id` 命名约定**：建议用 `ev<N>` 递增序号（如 ev1/ev2…），同一存档内唯一；悬疑局事件建议 `susp_<N>` 前缀以与普通事件区分。

**字段映射说明**：模板名 → 事件类型；触发条件 → 触发来源/关联旗标；可能走向 → 当前分支状态；关系图谱影响 → 事件结束时待执行的关系更新；建议时间消耗 → due_clock 的折算依据（不入库）；难度修正建议 → agent 调 `save.py --roll` 时修正值的依据（不入库）。

## 模板 1：权力真空 · 政变

| 字段 | 内容 |
|------|------|
| 模板名 | 政变 |
| 触发条件 | 某国核心 NPC 长期失信/被暗杀/重病，该国局势种子张力接近爆发；或玩家行动间接导致权力核心动摇 |
| 可能走向 | ① 军方接管——强硬派上台，外交收紧，盟友可能被清洗 ② 议会推举——温和派过渡，各方博弈代理人席位 ③ 外部势力干预——邻国扶植傀儡，引爆国际危机 |
| 关系图谱影响 | 该国所有 NPC 的立场大规模重排；玩家与旧政权关系转化为与新政权关系（可能反转） |
| 建议时间消耗 | 2-5 天（过程）至 1-2 周（后续清算） |
| 难度修正建议 | 玩家在旧政权关系资本高 → 修正 -2 至 -4（被新政权视为旧党）；玩家有军方人脉 → +2 至 +3 |

## 设计注释

1. **模板非脚本**：模板提供结构框架与分支方向，agent 在本地化填充时应根据具体世界设定和玩家处境灵活生成，不是逐字执行脚本。
2. **分支非穷举**：每个模板的 2-3 个走向是常见方向，agent 可以根据局势生成模板未列出的走向。
3. **联动非强制**：模板联动表供参考，agent 根据实际局势判断是否触发联动，不是每次事件都连锁。
4. **难度修正是参考**：修正建议是框架值，agent 应根据具体 NPC 性格、关系深度、话术质量等动态调整最终修正值。
5. **时间消耗是建议**：agent 根据事件规模和涉及方数量灵活调整，不强制精确匹配。

## 题材语义漂移（跨 tone_family 使用本库）

本库 18 个模板按**关系张力机器**抽象设计（多方互算 + 结构性敌意 + 表面同盟藏裂缝 +
中立交汇点），但字面示例多取自硬科幻语境（政变/走私/边境冲突/AI 失控/轨道设施等）。
**跑非硬科幻题材时**，模板的"势力语义"按该档 `world.json` 的 `meta.tone_family`
等价映射，**底层张力结构不变，只换皮**。示例映射：

| 模板（硬科幻示例） | 现代都市 | 校园 | 情感 | 修仙 | 穿越 |
|---|---|---|---|---|---|
| 1 政变 | 董事会夺权 | 学生会改选 | 家族逼婚 | 宗门夺嫡 | 原时空政变波及 |
| 2 走私大案 | 内幕交易 | 代考/传答案网络 | 隐瞒的旧情史 | 禁药/符箓走私 | 两界违禁品流通 |
| 3 边境冲突 | 商圈抢地盘 | 社团与校方冲突 | 两家长辈对峙 | 宗门与皇朝摩擦 | 两时空规则冲突 |
| 4 AI 失控 | 算法失控/数据泄露 | 网络暴力失控 | 情感操控软件 | 器灵反噬 | 新时空科技失控 |
| 12 双面间谍 | 商业双面间谍 | 双面告密者 | 脚踏两段关系 | 双宗卧底 | 双时空身份 |
| 18 势力瓦解 | 巨头拆分 | 学生会解散 | 家族分崩 | 宗门覆灭 | 一界规则崩塌 |

映射原则：
1. **以 tone_family 为准**——判断事件语义归属时先读该档 world.json 的 meta.tone_family，不套硬科幻术语。
2. **张力结构优先**——政变/瓦解这类模板本质是"权力真空 + 重新洗牌"，任何题材都适用，只替换权力载体。
3. **题材护栏约束**——映射后必须符合 world-gen-protocol.md §3.2 该家族"明确禁止"项
   （如校园不出现"单兵灭国"、情感不出现"无脑原谅"）。
4. **模板命名只作索引**——agent 生成事件时不必沿用硬科幻模板名，用题材语言给事件起名即可。

## 被动触发子表（世界压力掷表专用）

**用途**：供 `rules.md §5 世界压力掷表` 调用。世界压力表掷出 d100 后，按结果档位
从本子表选取模板——这些模板的共同点是**玩家不在场也照样发生**，世界不因玩家不看而不动。

**与主动触发的区分**：

| | 主动触发（本文档主体 18 模板） | 被动触发（本子表） |
|---|---|---|
| 触发源 | 玩家动作指向 / 局势种子 due_clock 到点 | `save.py pressure` 掷表结果 |
| 玩家角色 | 多半是事件的相关方或发起者 | 可能完全是旁观者，事后被牵入 |
| 生成时机 | 玩家行动后即时推演 | 时间推进时（rules.md §5.1） |
| 是否可回避 | 玩家可主动规避 | **不可回避**：玩家可应对或无视，事件照常演化 |

同一模板可两路触发，但**生成时须自问"这件事是否需要一个玩家动作才发生"**——
若答案是否，且玩家当下正蛰伏/旅居，走被动路径；若玩家刚做了指向性动作，走主动路径。

**选取规则**：
1. 先按压力表结果档位定"事件强度"（平安无事 01-10 / 轻微演变 11-30 / 牵连玩家 31-60 / 直接冲击 61-84 / 双重并发 85-94 / 重大恶化 95-100；档位定义见 rules.md §5.2）。
   - 平安无事（01-10）：不生成事件，仅叙事带过（见 rules.md §5.2）；
   - 双重并发（85-94）：**选两条事件**，尽量取自不同档位语义（可各取一条），避免重复；
2. 从下表按**权重**随机选模板（权重越高越常见）；同档位内优先选与当前局势种子
   或玩家 relations **有语义关联**的模板（利用世界已有锚点，避免生造）。
3. 用该档 `world.json` 专名本地化，按 `meta.tone_family` 语义漂移（见文末"题材语义漂移"）。
4. 写入 state.json `events`（open + tension + due_clock），细节见 rules.md §5.3。

## 渗透者悬疑局模板（复合事件 · 由 rules/suspicion.md 驱动）

> **性质**：本节模板是**复合事件**——不是一个单次事件，而是一局完整悬疑局的入口与骨架。
> 它的生命周期、信息机制、指认裁决、闸门全部由 **`rules/suspicion.md`** 驱动；
> 本节只负责提供**可实例化的语义框架**（沿用六字段 + 补全两工程字段）。
> 悬疑局**只改 state.json（relations/flags/events），绝不动 world.json**。

### 悬疑局 A · 内部清洗 · 谁是内鬼

| 字段 | 内容 |
|------|------|
| 模板名 | 内部清洗·谁是内鬼 |
| 触发条件 | 某势力内部张力 ≥60（如审计长失踪、派系清洗、权力真空）；或世界压力表命中「情报泄露(6)」且该势力存在结构性敌意方；须先过 `suspicion.md §6` 五维闸门 |
| 可能走向 | ① 公开指控——矛盾顶到明面，进入指认窗口 ② 重大失窃——关键物证/档案散佚，需从痕迹反推内鬼 ③ 关键时刻掉链子——一次行动因内鬼破坏而失败，追责指向内部 |

| 字段 | 内容 |
|------|------|
| 模板名 | 战前同盟·暗桩 |
| 触发条件 | 多方集结（战前同盟/军演/关键物资押运/被迫隔离共处）构成"内鬼土壤"；某方内部有与敌意方可解释的接触面；须先过 `suspicion.md §6` 五维闸门 |

| 建议时间消耗 | 集结/押运周期 2-7 天（`due_clock` 取数日~数周）；爆发后指认窗口 4-8 行动窗 |
| 难度修正建议 | 同上四档 + 关系资本修正；隔离场景下证词真伪更依赖 NPC `trust`（`suspicion.md §4.2`） |

### 与模板 11（叛逃）/ 12（双面间谍）的关系

悬疑局与这两个模板**同属"内部人 + 外部势力"张力家族**，可**互相触发或转化**：

- **11 叛逃 → 悬疑局**：一名核心 NPC 出逃未遂/出逃后留疑点，其同伙仍在内部，触发"谁是内鬼"。
- **12 双面间谍 → 悬疑局**：某 NPC 被怀疑是双面间谍，但"是否有、是谁"不明 → 升级为一局完整的渗透者悬疑。
- **悬疑局 → 12 / 11**：内鬼败露后，其效忠方可能**招降/灭口**，把局面转入双面间谍或叛逃事件。

**区别**：模板 11/12 是**单次事件**（一个确定 NPC 的叛逃/双重身份已基本明朗），而悬疑局是**开放调查过程**——内鬼身份对玩家**未知**，须走"痕迹→证词→验证→指认→裁决"的完整闭环（`suspicion.md`）。**实例化时若内鬼身份已对玩家明朗，应退回用模板 11/12，不要套悬疑局**。

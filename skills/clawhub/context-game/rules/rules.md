# 《上下文》核心规则细节

本文件供 SKILL.md 在需要时间成本表、判定公式、围猎阈值、事件触发检查、关系 schema
细节时路由读取。规则数值为**原型占位**，正式数值由设计侧精调后在版本升级中覆盖。

**题材无关性**：本文件的规则数值与判定机制是题材无关的（关系张力机器抽象）；
文件内示例语境取自官方世界（硬科幻），跨题材按该档 `meta.tone_family`
等价映射（映射方法见 `events.md` 文末"题材语义漂移"）。

## 1. 时间消耗表

时间单位：day = 游戏日；hour = 游戏小时。默认一个游戏日 = 8 个"有效行动窗"。
行动消耗由 SKILL 引擎按下表扣减 clock：

| 行动类别 | 基准消耗 | 备注 |
|---|---|---|
| 移动（城内 / 同城街区） | 1 hour | 穿越检查站 +1 hour |
| 移动（城际 / 航道） | 0.5 day | 需站点时刻表，错过等 4 hour |
| 调查（现场/档案/网络） | 2 hour | 深度调查（撬锁/黑入）4 hour |
| 交易（黑市/外汇/信息） | 1 hour | 谈崩可重谈，需再付 1 hour |
| 说服 / 收买 | 1 hour | 对象拒绝时算失败，不退还时间 |
| 对质 | 1 hour | 高危，见"死亡与风险" |
| 蛰伏 | 1 week 起（=7 day） | 唯一降 heat 手段；错过到期 open 事件 |
| 等待 / 蹲点 | 2-4 hour | 具体看事件 due_clock |

**全局时间流**：每完成一个行动窗，活跃 open 事件按各自 due_clock 倒计时；
到点即自行演化（无论玩家是否在场），并写入 memory.md 活跃区。

## 2. 判定公式

```
判定值 = 1d100 + 修正值
成功   = 判定值 >= 难度
margin = 判定值 - 难度
```

**修正值 = 关系资本 + 情报优势 + NPC 态度修正**

> **修正值必须逐项计算，不允许凭感觉填 0。** 每次 `roll` 前按下表**逐行核对**，
> 把每一项的**来源与取值**写进 `--reason`（工程侧已设 `--reason` 为必填）。
> 玩家积累的关系、秘密、把柄若不入账，成长就零意义——这是修正值强制生效的铁律。

| # | 修正分项 | 触发条件 | 取值 |
|---|---|---|---|
| 1 | 关系资本（高） | 该实体 trust >= 70 且 attitude >= 0 | +15 |
| 2 | 关系资本（中） | trust >= 40 且 attitude >= 0 | +8 |
| 3 | 关系资本（负） | trust < 20 或 attitude < -50 | -10 |
| 4 | 情报优势 | 玩家持有针对该 NPC/势力的 secrets 或 leverage | +12（每项） |
| 5 | 情报劣势 | 玩家被对方掌握 secrets（对方有把柄在握） | -10（每项） |
| 6 | NPC 态度分档 | 视当前 attitude（见下） | attitude>=60:+10; 20..59:+5; -20..19:0; <=-60:-10 |

关系资本与 NPC 态度修正按**涉及对象**取，情报优势按**实际持有的秘密/把柄**取。
若对象是势力（faction），用该势力最活跃 NPC 的 attitude 代表态度修正。

**修正值清单（--reason 必写格式）**：`难度=<档位名><值>(<理由>); 修正=±a <来源> ±b <来源> ...`
示例：`难度=困难60(说服戒备者); 修正=+8 阿庚trust98 +12 持有其走私把柄 +5 态度62`
**modifier=0 只在**"该实体与玩家无任何既有关系、无情报优劣势、态度中性（attitude ∈ -20..19）"
时才合法，且必须在 reason 中写明该判断依据（如 `修正=0(首次接触,无关系/无情报/态度中性)`）。
拿不准时先查 relations，多数情况下至少有一项非零——**关系账本不是装饰**。

**难度分级**（裁决者根据局势拍板，难度只反映客观困难度，不随玩家魅力浮动）：

> **难度只允许取四档：40 / 60 / 75 / 90。禁止自创档位。**
> `save.py roll --difficulty` **只接受这四个值**（白名单硬校验），传入 45、50、88 等
> 任何非四档值一律报错拒写——这是硬约束，防止"难度 2-5 等于必成功"的判定空转。
> 裁决者只能四选一，拿不准时选更贴近客观困难度的一档，并在 `--reason` 写明选了哪档。

| 档位 | 值 | 什么行动配这一档 |
|---|---|---|
| 常规 | 40 | 调查公开资料、普通交涉、正常交易、说服本就愿意的人 |
| 困难 | 60 | 说服戒备者、潜入普通设施、撬开不肯开口的线人、时效紧张的追踪 |
| 极高 | 75 | 对质权势者、销毁核心证据、当面欺骗老练的对手、在围猎中脱身 |
| 近乎不可能 | 90 | 公开背叛后翻盘、一人对抗整国/整宗门、逆改已定之局 |

### 不掷骰原则（先于判定适用）

**真正琐碎、无风险、无对手阻力的行动不掷骰，直接叙述成功**，只扣时间（见 §1）。
掷骰只留给"有真实代价、有对手、可能失败"的行动。判定栈顺序：
**先问要不要掷骰 → 要掷才四选一难度 → 逐项列修正值 → `--reason` 写清依据。**

不该掷骰的例子：买一份公开报纸、问路、在无戒备场合寒暄、执行本就会成功的常规操作。
若这类动作也掷骰，会退化成"什么都掷、掷了就成"的仪式化空转——**判定要有信息量，
必须有失败的真实可能**。"必成功"的动作，答案就是直接成功，不掷。

**运势描述词**（来自 save.py roll，按 margin 自动判定）：
`margin<=-30` 惨败 / `<0` 失败 / `<10` 勉强成功 / `<25` 成功 / 其余 意外转机

**成功幅度叙事**：margin>=25 视为大成功，可额外给予 1 个可选优势
（找回 1 份情报 / 对方疏漏留下把柄 / 时间成本减半）。

## 3. 围猎状态阈值

| 指标 | 说明 | 触发阈值 |
|---|---|---|
| heat | 玩家在官方视野中的累积风险值 | >= 30 进入"被注意"；>= 60 围猎 |
| 围猎期间 | 每行动窗掷一次"搜捕压力"（难度 60，无修正） | 失败 = 遭遇盘查/堵截 |
| 降 heat | 蛰伏每满 1 week | -15 |

heat 由以下动作累积：公开对质 +10、留下把柄 +8、两次在同一地点被目击 +5、
销毁证据引爆 +12 等。heat 记录在 flags.heat（整数）。

> **与 `--reason` 接口的衔接**：围猎搜捕压力是**规则内部的无修正判定**，不适用 §2
> "modifier=0 仅限首次接触"的约束；其 `--reason` 统一写
> `围猎搜捕压力判定(§3)，规则设定无修正`，难度固定 60。

## 4. 事件触发检查流程

1. 读取该档开放事件（state.json events，status=open）。
2. 遍历检查：当前 clock >= 事件的 due_clock？→ 触发演化，更新事件。
3. 玩家动作若明确指向某事件（如"查货运记录"指向货运疑案），
   优先推演该事件分支；相反方向（玩家回避）则事件按 own 节奏演化。
4. 场景氛围与张力：叙事渲染至少触及一个 open 事件的 tension 变化，
   或一条关系变化；无事件可选时，允许 NPC 闲谈（不推进、不入账）。

新增事件模板见 `rules/events.md`（六字段：模板名 / 触发条件 / 可能走向 /
关系图谱影响 / 建议时间消耗 / 难度修正建议；实例化时另按 events.md 顶部
"实例化写入 state.json 的字段补全"补 `tension` 与 `due_clock` 两工程字段）。

## 5. 世界压力掷表（被动事件引擎）

**设计承诺**：世界不围着玩家转。玩家蛰伏、旅居、闭关或只是过了几天"平凡日子"时，
世界照样演化、照样给玩家添麻烦。事件由**玩家的主动动作**触发之外，还由
**时间推进随机触发**——后者即本表。玩家可以选择应对或无视，但**事件照样演化**，
不需要玩家允许、不受玩家回避影响。

### 5.1 触发时机

**每次时间推进必须掷一次**世界压力表，尤其：
- **蛰伏 / 旅居 / 闭关 / 养伤**等长时段行动（按"行动消耗"折算，每个完整行动窗掷一次，
  长时段取该时段内的一个代表点，掷出的结果按该时段的长度放大演化）；
- **平凡行动的日切**（当日 clock 首次进入新 day，或一次行动跨越日界）；
- 一轮中多次时间推进（移动多段、连续调查）→ 每次推进都掷，不合并、不跳过。

> 通俗记法：**凡 clock 动了，就要问一次"这阵子世界在干嘛"。**
> 围猎期间的"搜捕压力"（§3，难度 60）是另一套判定，两者并行不冲突。

### 5.2 掷表与查表

```
调 save.py pressure --slot <档> --table "world-pressure"
→ 返回确定性 d100（1..100），按下列分布查表。
```

**d100 分布表（世界压力表）**：

| 掷出区间 | 结果 | 引擎动作 |
|---|---|---|
| 01-10 | 平安无事 | 不生成新事件；仅让局势种子张力 +0~2（不写盘，仅叙事带过） |
| 11-30 | 局势轻微演变 | 一条**与玩家无关**的并发事件萌芽（写入 events.open，低 tension） |
| 31-60 | 牵连玩家的并发 | 一条**影响玩家处境但不直接攻击**的并发事件（对象多为玩家的盟友/所在区域/所在势力） |
| 61-84 | 直接冲击 | 一条**直接冲击玩家**的不利事件（找上门、限期、被卷入） |
| 85-94 | 双重并发 | 两条并发事件（可按上两档各取一条，语义尽量不同） |
| 95-100 | 重大恶化 | 一条重大恶化事件：全局性、不可逆、或直接威胁玩家核心目标 |

> 注：`save.py pressure` 返回 **1..100**（含 100），故最高档记作 95-100。

> 分布意图：**"什么都不发生"只占 10%**（01-10）——世界给玩家添麻烦是常态；
> 玩家不在场的世界也活着。80%+ 的掷表都至少让世界动一下，
> 其中直接冲击玩家（61-84，24%）保证被动事件的"麻烦感"始终在场。

### 5.3 事件生成与落盘

1. 从 `events.md` 文末《被动触发子表》**按当前档 tone_family 等价映射**选取模板
   （子表标出哪些模板适合"玩家不在场也发生"、各自的触发权重/适用条件）。
2. 用该档 `world.json` 的专名本地化填充（国家/势力/地域/核心 NPC）；
   事件**面向世界**生成，不预设玩家必须参与。
3. 按 events.md"实例化写入 state.json 的字段补全"补齐 `tension` 与 `due_clock`，
   写入 state.json 的 `events`（status=open）。
   - `tension` 按结果档位取：轻微演变 30-45 / 牵连玩家 50-60 / 直接冲击 60-75 /
     重大恶化 80+；
   - `due_clock` 按事件规模折算（天级 1-7 天、周级 1-4 周），**到点强制爆发**——
     无论玩家是否应对。
4. 记忆：事件创建即写 memory.md 活跃区（`- 【day N hh:00】…`）；
   长时段蛰伏掷出的演化，按时段长度在叙事中体现（"你闭关的这三个月，
   宗门已变天"）。

### 5.4 与"局势种子"的关系

- **局势种子（tension_seeds）**：世界开局时预置的**暗流**——必然存在、
  由世界设定决定，随玩家行动与事件演化逐步推进。它回答"这世界本来藏着什么雷"。
- **世界压力表**：时间推进随机触发的**外部变量**——每次掷表都可能抛出一条
  不在种子里的新动向。它回答"这段时间世界又自己发生了什么"。
- **两者共同构成活世界**：种子是骨架（确定性张力），压力表是血肉（随机扰动）。
  压力表事件若命中种子相关的模板/对象，可与种子互相催化、提前引爆；
  若无关，则平行演化。**压力表不能取代种子的推进检查**（§4 的 due_clock 演化照常）。

### 5.5 题材差异

被动事件语义按该档 `meta.tone_family` 漂移（映射方法见 `events.md` 文末
"题材语义漂移"与《被动触发子表》）：硬科幻的"资源禁运"在修仙题材是
"宗门封锁坊市灵石供应"、在校园题材是"社团经费被冻结"；但底层都是
"外部势力动了玩家依赖的资源"。**判定与落盘机制不变，只换皮。**

## 6. 失败后果速查表

**失败必须改变棋局，禁止轻描淡写**。任何 `roll` 失败（margin < 0）必须产生
**至少一项可量化损失**；`惨败`（margin <= -30）必须额外触发**世界性不可逆变化**。
"失败但无实质损失"的叙述在本引擎中不合法——失败要疼，玩家才会认真对待风险。

**失败（margin < 0）——至少选一项**：

| 后果类别 | 具体执行 |
|---|---|
| 关系下降 | 涉事实体 attitude 和/或 trust 至少 **-15**（惨败 -30），并更新 standing 标签 |
| 资源损失 | 扣减玩家可量化资源（灵石/资金/物资/弹药/情报单），写明损失条目 |
| 准入受限 | 地点/势力准入降级或封锁（如"灰潮港黑名单"，更新 flags 或 relations notes） |
| NPC 敌对 | 涉事 NPC 转为敌对（attitude <= -50，standing="敌对"），后续交涉难度升档 |
| 时间窗口关闭 | 相关事件 due_clock 缩短/直接爆发，或该路径永久错过（写成 flags/events） |
| 情报反噬 | 对方获得玩家的把柄（对方 secrets 入账），后续判定受 -10 情报劣势 |

**惨败（margin <= -30）——必须再触发一项世界性不可逆变化**（"关闭一扇门"）：

| 变化 | 示例 |
|---|---|
| 一个势力立场永久改变 | 某宗门/财团/国家从"可谈"转为"敌对"并写死（attitude 落 -70 以下） |
| 一个可去之处永久关闭 | 某地点/关系线永久封锁，写成 flags（如"灰潮港=禁止入内"） |
| 一个 NPC 永久消亡/退场 | 死亡、废功、入狱、彻底失踪——**不删除条目**，status/notes 留痕 |

选择变化时优先选**对玩家当下目标最伤**的那一项——惨败的意义是"最坏的那扇门关上了"。
死亡与围猎规则见 SKILL.md §8，不因本表而放宽。

## 7. 关系图谱条目 schema

relations 中每实体一条，严格字段：

```json
{
  "<实体名（NPC 或势力名）>": {
    "type": "npc|faction",
    "attitude": -30,        // int -100..100
    "trust": 10,            // int 0..100
    "standing": "戒备",     // 叙事标签，与数值尽量一致
    "secrets": ["该实体自己的秘密"],
    "leverage": ["玩家捏在手里的把柄"],   // 入账时才可作情报优势 +12
    "notes": "上次接触的备忘"
  }
}
```

> 示例字段值为通用占位；硬科幻题材里实体可能是"卡萨德大使"，
> 校园题材里可能是"校报主编"，修仙题材里可能是"青松长老"——
> 实体命名与行为语境以该档 `world.json` 的 `meta.tone_family` 为准。

- `secrets` = 该实体自己的秘密（谁知道的叙事侧记）。
- `leverage` = 玩家对该实体持有的把柄（入账时才可作情报优势 +12）。
- 势力实体同样用此结构，standing 用该势力的对外姿态。
- 实体上限 100（save.py 强制），超限先 `archive` 再考虑合并次要 NPC。

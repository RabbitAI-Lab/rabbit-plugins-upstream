# 任务工分计算器（ClawHub 版）

把格式不固定的任务清单，变成可复核的工分事实清单：

```
Excel/CSV → 字段识别 → 单位归一 → 质检 → 批次评级 → 打分 → Excel 结果表 + Markdown 报告 + JSON
```

输出的是**任务分**，不是个人绩效等级。宁可报"分析失败"，也不静默编造一个看起来合理的分数。
本版与通用版口径完全一致，差异仅在安全边界（路径沙箱、依赖声明、输出约束）。

## Inputs

1. **任务清单文件**（必需）：`.xlsx` / `.xlsm` / `.csv` / `.tsv`，单文件、≤20 MB。
2. **输出目录**（可选）：`--out-dir`，默认写到输入文件同级的 `gongfen-out/`。
3. **列映射覆写**（可选）：`--override 列号=字段名`，仅在明知脚本认错列时使用。
4. **强制出工分**（可选）：`--force-points`，仅在明知数据不足仍要工分时显式添加。

## Output

同一次运行产出三件套，路径由沙箱约束（见「权限声明」）：

- `任务清单.gongfen.xlsx` —— **主交付物**，4 个 sheet：工分明细 / 批次汇总 / 质检与自检 / 字段识别
- `任务清单.gongfen.md` —— 同数据的文字版报告
- `任务清单.gongfen.json` —— 复核与下游用的中间结构

退出码：`0` 正常或降级 / `1` 分析失败 / `2` 参数错误 / `3` 内部异常 / `4` 沙箱拒绝。

## Security Notes

- **运行前可 inspect**：全部脚本为纯 Python 源码、无压缩无混淆（见下方行数表），可逐行审阅后再执行。
- **路径沙箱**（`scripts/sandbox.py`）：输入必须是存在的文件且扩展名在白名单内；输出路径解析后必须落在输入文件同级目录或当前工作目录内，越界一律退出码 4 并打印允许范围，**不静默改写、不静默降级到别处**。
- **不回写用户原表**：只另存 `*.gongfen.xlsx`，输入文件保持只读不改动。
- **输出清洗**：回显到报告/Excel 的原表文本一律剥离控制字符、转义 Markdown 控制符、截断到 200 字符，防止表格内容被当作指令执行（间接提示注入）。
- **stdout 限量**：终端只打印报告摘要（≤60 行）+ 产物路径，完整内容在文件里，避免无界输出。

## Process

**脚本端到端出结果，模型不做二次判断。** 不要自己打开 Excel 猜字段，不要覆写脚本给出的分数，不要在识别环节打断用户。

1. **跑脚本**（合并单元格展开、合计行剔除、单位归一、Excel 排版这些手工很难做对的事都在脚本里）：
   ```bash
   python scripts/run.py 任务清单.xlsx
   python scripts/run.py 任务清单.xlsx --out-dir out
   python scripts/run.py 任务清单.xlsx --override 3=hours --force-points
   ```
2. **读"批次结论"**：`A_正常` / `B_可排名` / `D_体系退化` / `C_仅描述` / `E_失败`，优先级 `E → C → D → B → A` 命中即停。这决定结果能不能用于分配。
3. **交付 `*.gongfen.xlsx`**；Markdown 是同一份数据的文字版，用于贴聊天/贴文档。
4. **讲三件事**：分支结论与免责句、剔除了哪些行（质检 sheet 有行号与原因）、哪些任务标了异常（工时与日期矛盾、被偏离度打折、难度为估算值）。
5. **用户追问某个数怎么来的**：查 `*.gongfen.json`，或按文末 Reference 表的行数定位对应说明文件。
6. **改口径**：只改 `scripts/params.py` 后重跑；列认错用 `--override`；**不手工改分数、不手工改 JSON**。

### 分支速查

| 分支 | 触发 | 结果能用于什么 |
|---|---|---|
| `A_正常` | 启用维度权重 ≥60%，n_eff ≥3 | 可排名，作分配**参考** |
| `B_可排名` | 权重 45–60%，或单维归一权重 >35%，或无日期锚点 | 可排名，**不建议直接分配** |
| `D_体系退化` | n_eff <3，或难度与工时排名一致性 >0.85，或有效维度 ≤2 | **仅排序参考**，禁作分配依据 |
| `C_仅描述` | 权重 <45%，或任务数 <3，或 >50% 任务无有效维度 | **仅描述统计**，不出总分 |
| `E_失败` | 无任务名或描述列 / 表头定位失败 / 文件不可读或加密 | 不出分，回显失败三件套 |

**门槛**：只要识别到任务名称或描述列就执行，缺列不阻断——缺失维度不参与计算，只在报告提示；
唯一阻断条件是「连任务名/描述都认不出来」。难度维度固定启用，从任务名（优先）或描述推断，**无模型参与**。
C/D 分支下 Excel「工分 P」列留空，另给一列明标「参考工分（仅供排序对照·不可用于分配）」；
确需工分须显式加 `--force-points`，脚本会在保单与汇总页追加"强制输出"警示 —— 默认不给。

## 红线

1. **不产出"某人应得 X 分 / 应评为 X 级"**。按人汇总只能说"该人负责任务的工分合计"，并注明不等同于个人绩效结论。
2. **不产出淘汰/扣罚名单**，也不设计这类规则。
3. **不得静默改分**。工时偏离度打折、疑似拆分、分布偏斜——只提示 + 列清单，判断权归人工。
4. **F 技能门槛永不进小计**（职级→门槛的映射会对特定人群产生系统性偏差）。
5. **数据不足不得伪装成可用**。权重合计 <45% 或 n_eff <3 时必须显式写「仅排序参考」。
6. **失败必须回显三件套**：①已识别列名 ②缺失字段 ③建议补充列。
7. **估算值不得冒充实测值**。关键词推断的难度必须标 `estimated`，标注要出现在总分旁边。

## Troubleshooting

| 症状 | 原因 / 处理 |
|---|---|
| 退出码 4 + "输出路径越界" | 指定的 `--out-dir` 不在输入同级目录或当前工作目录下，改到允许范围内 |
| 退出码 3 + 缺依赖 | 由用户执行 `pip install -r requirements.txt`（脚本不代为安装） |
| 退出码 1 + 前 15 行回显 | 表头定位失败；确认首张表前 15 行内存在表头行 |
| 某列被认成工时（如序号列 1,2,3） | 查「字段识别」sheet 拿列号，用 `--override 列号=seq` 或 `--override 列号=task_name` 重跑 |
| 结果落在 C/D 分支 | 维度覆盖不足，补「工时（小时）」「优先级」等列后重跑；确需工分加 `--force-points` |
| `.xls` 或加密文件读不了 | 需 xlrd / msoffcrypto，默认环境未装，请先转存为 `.xlsx` |

# 供应商管理 (Vendor Management)

## 目标

管理供应商关系, 从合同签署到项目交付再到长期运维, 确保供应商按承诺交付, 建立健康且有绩效的供应商关系。

---

## 前置条件
- 供应商合同/SOW已签署
- 供应商团队已确定
- 内部供应商管理责任人已指定

## 输入物
- 签署的合同/SOW/ SLA
- 供应商团队名单与角色
- 项目计划(含供应商交付物和里程碑)
- 合同中的奖惩条款

---

## 操作步骤

### 第一步: 供应商关系建立

#### 1.1 供应商分类管理

不是所有供应商用同样的管理方式:

| 供应商类型 | 特征 | 管理强度 | 管理重点 |
|-----------|------|---------|---------|
| **战略合作伙伴** | 长期/大金额/核心系统依赖 | 高 | 高管关系+联合规划+创新协作 |
| **项目交付伙伴** | 单次项目/固定范围/固定时间 | 中-高 | 交付管理+质量控制+合同遵守 |
| **服务提供商** | 运维/支持/云服务/持续服务 | 中 | SLA监控+服务评审+续约管理 |
| **商品供应商** | 硬件/许可证/标准化产品 | 低 | 价格+交付+合规 |

#### 1.2 供应商启动(Kickoff)

签约后、正式开工前必须做的5件事:

```
1. 供应商Kickoff会议
   - 对齐项目目标(不只是合同范围, 而是"我们为什么做这个")
   - 确认沟通渠道和升级路径(双方)
   - 确认关键里程碑和时间表
   - 最重要的是: 建立双方的信任和协作关系, 不是"甲方vs乙方"

2. 工作方式和工具统一
   - 用哪个项目管理工具? (Jira/Trello/...)
   - 代码仓库在哪? 权限怎么设?
   - 文档协作用啥? (Confluence/Notion/...)
   - 沟通用啥? (Slack/Teams/微信?)

3. 人员确认
   - 合同里写了的关键人员现在是不是真的到位?
   - 每个人的角色和职责是否清楚?
   - 后备人员是谁?

4. 交付标准对齐
   - 什么东西算"完成"? (Definition of Done)
   - 文档要什么格式? 多详细?
   - 验收标准怎么判断(客观的、可测试的)?

5. 第一次联合风险审查
   - 双方各自提出对项目的Top 3担忧
   - 讨论怎么一起应对
```

### 第二步: 供应商绩效管理

#### 2.1 供应商记分卡 (Quarterly)

| 维度 | 权重 | Q1 | Q2 | Q3 | Q4 | 说明 |
|------|------|----|----|----|----|------|
| 交付质量 | 25% | [1-5] | [1-5] | [1-5] | [1-5] | 缺陷率/返工率/验收通过率 |
| 交付及时性 | 25% | [1-5] | [1-5] | [1-5] | [1-5] | 里程碑/任务按时完成% |
| 成本控制 | 15% | [1-5] | [1-5] | [1-5] | [1-5] | 预算偏差/变更成本合理性 |
| 响应与沟通 | 15% | [1-5] | [1-5] | [1-5] | [1-5] | 问题响应速度/沟通质量 |
| 团队稳定性 | 10% | [1-5] | [1-5] | [1-5] | [1-5] | 关键人员变更/知识连续性 |
| 创新/增值 | 10% | [1-5] | [1-5] | [1-5] | [1-5] | 主动改进建议/行业洞察分享 |
| **加权总分** | | | | | | |

评分标准:
- 5: 超出预期 — 不仅在合同内做得好, 还有额外的增值
- 4: 符合预期 — 按合同做到了, 没有问题
- 3: 基本符合 — 总体上OK但有一些小问题
- 2: 不满意 — 反复出现问题, 需要管理升级
- 1: 严重不满意 — 考虑替换/合同终止

#### 2.2 季度业务评审 (QBR)

**议程(90分钟):**
```
0:00-0:15  回顾过去一个季度(QoQ): 记分卡+关键事件+取得的成果
0:15-0:30  客户方反馈: 什么做得好/什么需要改进(具体+有例子)
0:30-0:45  供应商方反馈: 他们遇到的挑战/需要客户改进的地方
0:45-1:00  市场/技术趋势: 分享行业动态+新产品/新能力
1:00-1:20  下季度展望: 计划+风险+机会
1:20-1:30  行动项确认

双方参会者级别要求:
- 客户方: 至少IT总监级以上 + 采购代表
- 供应商方: 至少客户总监/VP级以上
```

### 第三步: 合同与SLA管理

#### 3.1 SLA监控仪表盘

| SLA指标 | 承诺 | 实际(YTD) | 达标? | 趋势 |
|---------|------|----------|------|------|
| 系统可用性 | 99.9% | 99.95% | ✅ | → |
| P1响应时间 | <15分钟 | 8分钟 | ✅ | ↓(更快) |
| P1解决时间 | <4小时 | 3.2小时 | ✅ | → |
| P2响应时间 | <1小时 | 2.5小时 | ❌ | ↑(恶化) |
| 变更成功率 | >99% | 98.5% | ❌ | ↓ |

#### 3.2 SLA违例处理

```
SLA违例发生 →
├── 第一次: 要求供应商24小时内提供根因分析(RCA)
├── 月度违例>3次: 正式的纠正行动计划(CAP) — 供应商出, 客户审
├── 季度严重违例(如可用性<99.5%): 触发Service Credit +
│   供应商高管当面解释
└── 持续违例且CAP无效: 触发合同中的"退出条款"评估
```

**Service Credit不是目的**: 罚钱不是目的, 服务恢复才是目的。如果供应商宁愿交罚款也不改善服务, 说明该换了。

#### 3.3 合同变更管理

当需要修改合同/SOW时:

```
1. 变更请求书面化: 变更什么/为什么/影响(进度/成本/质量)/替代方案
2. 内部审批: PM → 核心团队 → Sponsor(根据金额分级)
3. 与供应商谈判: 公平的报价(参考benchmark)+合理的时间
4. 签署变更单: 正式的文件, 不只是邮件确认
5. 更新所有相关文档: 项目计划/预算/范围说明/风险登记册
```

### 第四步: 供应商风险与关系管理

#### 4.1 供应商风险信号

出现以下信号时, 应立即关注:

| 信号 | 可能意味着 |
|------|----------|
| 关键人员频繁更换 | 内部出了问题/项目不被重视 |
| 响应越来越慢 | 正在接更大的客户/团队吃不饱 |
| 开始在小事上讨价还价 | 这个项目对他们不赚钱/想退出 |
| 质量突然下降 | 核心团队被抽走做其他项目 |
| 沟通变得不透明 | 有问题在藏着 |
| 频频提出变更请求(加钱) | 一开始就低价中标/对范围理解不同 |

**应对:**
- 不要等到问题积累爆炸了再处理
- 收到第一个信号就主动约供应商领导沟通: "我们注意到XXX, 是不是有什么问题我们需要一起解决?"
- 好的供应商关系=可以坦诚沟通, 而不是"甲方审乙方"

#### 4.2 供应商退出管理

当需要更换供应商时:

```
过渡检查清单:
□ 所有代码/文档/配置是否在客户手中(不是供应商手里)?
□ 所有系统的管理员密码/API密钥/证书是否已移交?
□ 数据是否已完整导出且验证?
□ 是否有供应商独有的知识需要挖掘和记录?
□ 是否有正在进行的任务/未修复的Bug需要交接?
□ 是否有合同约束(如: 必须提前90天通知)?
□ 新供应商是否已到位并完成知识转移?
□ 关键接口/依赖是否识别并做了过渡方案?
□ 业务方是否已被告知过渡期可能的影响?

供应商过渡期=最脆弱的时期
- 旧供应商可能不再用心("反正不续约了")
- 新供应商可能还不熟悉
- 建议: 新旧供应商并存至少1个月
```

### 第五步: 供应商关系健康度

#### 5.1 健康供应商关系的特征

```
✅ 双方都有对等的投入和收益 (不是一方在"吸血")
✅ 有问题可以坦诚沟通, 不用"乙方永远说对对对"
✅ 供应商主动提出改进建议, 不只是被动执行
✅ 双方都有长期合作的意愿(但不等于不考核)
✅ 关键人员双方都认识, 有信任关系
✅ 合同是"指引"而不是"武器"(但需要的时候可以用)
```

#### 5.2 破坏供应商关系的行为

```
❌ 无理由拖延付款 (供应商会通过降低服务质量来"弥补")
❌ 在供应商面前贬低供应商团队 (合作关系不是主仆关系)
❌ 频繁变更需求但不给额外时间和钱 (供应商会在质量上找回来)
❌ 让小问题层层升级到CEO (一个Bug不需要CEO来讨论)
❌ 总拿"找别家了"威胁 (如果真找得到, 直接找; 找不到, 威胁只会让关系恶化)
❌ 不管供应商死活砍价到亏本 (亏本的生意没人好好做)
```

## 输出物
1. **供应商分类与管理策略**
2. **供应商Kickoff记录** (含工作方式/工具/人员/交付标准)
3. **供应商记分卡** (季度更新)
4. **QBR会议纪要** (季度)
5. **SLA监控仪表盘** (月度更新)
6. **供应商风险信号清单与应对**
7. **供应商退出/过渡计划** (如适用)

---

## 质量检查
- [ ] 每个关键供应商有明确的内部管理责任人
- [ ] SLA指标是可测量的(不是"尽快")
- [ ] QBR不是走过场 — 有实质对话, 双方高级别人参加
- [ ] 供应商记分卡有客观数据支撑, 不是主观感觉
- [ ] 所有合同变更都有书面记录
- [ ] 供应商退出计划在合同签署时就开始考虑(是的, 一开始就想要怎么退出)

## 常见陷阱

| 陷阱 | 为什么错 | 正确做法 |
|------|---------|---------|
| 只看合同不管关系 | 天天拿着合同"第3.2条说你必须..." 关系毁了, 合作的弹性也没了 | 合同=底线保障, 关系=日常协作。二者都需要。 |
| 不投资供应商关系 | 以为签了合同供应商就应该好好干 | 定期沟通/明确期望/给反馈/认可好的表现 — 像管团队一样管理关键供应商 |
| 完全相信供应商 | "他们是专业的, 我们不用管" — 然后发现走偏了3个月 | 信任但要验证(Trust but Verify): 独立审查+定期检查 |
| 无差别管理 | 买500块办公用品和买500万系统的供应商用同样的管理流程 | 分级管理: 战略供应商投入关系, 商品供应商只需基本合规检查 |
| 付款拖拉 | 供应商现金流被拖死→服务质量下降→客户不满意→恶性循环 | 按时付款(供应商考核里有"按时付款率"这个内部指标) |
| 把知识留在供应商 | 供应商走了, 你什么都不懂 | 知识转移是合同中必须有的条款, 且在项目中持续执行 |

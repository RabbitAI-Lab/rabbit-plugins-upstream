# 阶段1: 项目启动与诊断

## 本阶段目标
签约后，快速组建团队、深入了解客户现状、产出诊断报告，为后续战略设计奠定基础。

## 完整流程
```
项目章程与团队组建 → 利益相关者访谈 → IT现状诊断(技术/流程/组织/数据) → 诊断报告撰写与汇报
```

## 前置条件
- SOW已签署
- 客户已指定项目接口人和关键联系人
- 获得基础文档和数据访问权限

## 本阶段产出物
| 产出物 | 说明 | 交付对象 |
|--------|------|---------|
| 项目章程 | 项目目标/范围/团队/时间/治理的正式文件 | 双方团队 |
| 访谈记录 | 结构化利益相关者访谈文档 | 内部 |
| IT现状诊断报告 | 含成熟度评分/痛点分析/根因/快赢机会 | 客户高管层 |

## 子文件指引

| 场景 | 进入文件 | 何时使用 |
|------|---------|---------|
| 项目刚签约，从哪开始 | [01-项目章程与团队组建.md](01-项目章程与团队组建.md) | 签约后第一个动作 |
| 要访谈CEO/CIO/业务VP | [02-利益相关者访谈.md](02-利益相关者访谈.md) | 诊断阶段核心活动 |

## 关键成功因素
- **第一周建信**: 快速交付项目章程，展示执行力
- **CEO/CIO必须访谈到**: 没有高层的真实观点，诊断没有灵魂
- **不止看技术**: 同步诊断流程/组织/数据/文化，技术只是四个维度之一
- **诊断报告必须有快赢机会**: 不能只列问题，必须有1-3个马上能做的事

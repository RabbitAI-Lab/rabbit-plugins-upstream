# 利益相关者分析矩阵 (Stakeholder Analysis Matrix)

> 使用说明: 这个工具帮助你在项目任何阶段快速分析和管理利益相关者。每次使用只需填写以下表格。

---

## 工具1: 利益相关者权力-影响力矩阵

### Step 1: 列出所有利益相关者

列出所有会被项目影响或能影响项目的人/群体:

### Step 2: 在矩阵中定位

```
影响力 (Influence)
  ↑
高 │  Keep Satisfied       Key Players
   │  (保持满意)            (紧密管理)
   │  
   │  [姓名/角色]           [姓名/角色]
   │  
   │  
   │  
低 │  Minimal Effort        Keep Informed
   │  (最少投入)             (保持知情)
   │  
   │  [姓名/角色]           [姓名/角色]
   │  
   └──────────────────────────→ 权力 (Power)
     低                      高
```

### Step 3: 填表

| 姓名/角色 | 权力 | 影响力 | 当前态度 | 目标态度 | 管理策略 | 负责人 |
|-----------|------|--------|---------|---------|---------|--------|
| [CEO] | 高 | 高 | 支持 | 保持支持 | 月度1on1简报 | CIO |
| [CFO] | 高 | 中 | 中立 | 支持 | 一对一沟通ROI,提前回答财务疑虑 | CIO+PM |
| [业务VP-X] | 中 | 高 | 抵制 | 中立 | 早期参与设计+倾听具体顾虑+试点让其团队先受益 | PM |
| [IT经理-Y] | 低 | 中 | 未知 | 知情+中立 | 邀请参加项目沟通会+定期邮件更新 | PM |
| [一线员工群体] | 低 | 高 | 未知 | 支持 | 变革推动者网络+频繁透明沟通 | 变革Lead |

### Step 4: 制定策略

| 矩阵位置 | 管理策略 |
|---------|---------|
| **Key Players (高权力+高影响)** | 紧密管理: 面对面1on1, 深度参与决策, 个性化沟通 |
| **Keep Satisfied (高权力+低影响)** | 保持满意: 定期高层汇报, 不让他们从别人那听到坏消息 |
| **Keep Informed (低权力+高影响)** | 保持知情: 定期邮件/简报, 让他们觉得被尊重和知情 |
| **Minimal Effort (低权力+低影响)** | 最少投入: 常规项目通讯, 不忽视但不过分投入 |

## 工具3: 关键影响者网络图

识别"谁影响谁"的关系网络, 用于精准沟通:

```
中心人物识别:
1. 谁是"意见领袖" — TA说好, 一群人说好; TA说不好, 一群人说不好?
   姓名: [____]  通常不是职位最高的, 而是最有号召力的

2. 谁是"信息中转站" — 大家习惯从TA那里获得信息?
   姓名: [____]  如果TA得到的信息是错的, 整个团队的信息都会错

3. 谁是"CEO的耳朵" — CEO在做决策前会咨询谁?
   姓名: [____]  如果这个人不支持, CEO很可能也不会支持

4. 谁是从业最久的 — 经历过最多"上次也是这么说的但没做成"?
   姓名: [____]  TA可以说服或杀死一个变革
```

**关系图** (手绘或Miro):
```
        [CEO]────[CFO]          ← C-Suite
          │
    ┌─────┼─────┐
    │     │     │
  [VP1] [VP2] [VP3]            ← 业务线
    │     │
    ├──[Director A]  ← 意见领袖 (TA的态度影响VP1+VP2)
    │
  [团队B] [团队C] [团队D]       ← 一线
```

## 工具4: 个性化沟通矩阵

对每个关键利益相关者:

| 姓名 | 他们的"北极星" | 他们的恐惧 | 最佳沟通方式 | 最佳沟通时间 | 谁最合适和TA沟通 |
|------|-------------|----------|------------|------------|---------------|
| | (TA最关心什么KPI/目标) | (TA最怕什么) | (数据/故事/面对面/PPT?) | (上午/午餐/下班前?) | (CIO/PM/Sponsor?) |

**示例:**
| CFO | 成本控制+现金流+ROI | 投资打水漂+预算失控+审计风险 | 数据+财务模型, 先给材料预习, 当面讨论 | 早上8:30-9:30(开会前) | CIO(同级别)+PM(细节) |
| 业务VP | 部门业绩+团队稳定+效率 | 系统不好用耽误业务+团队抵制 | 用TA部门的实际场景演示+让TA的团队成员先试 | 部门月度会留15分钟 | PM+TA信任的下属 |

## 使用场景

- **项目启动时**: 用工具1+3 建立初步利益相关者地图
- **项目执行中**: 用工具2+5 追踪变化, 预警"态度恶化"的人
- **关键决策前**: 用工具4 制定个性化沟通策略
- **遇到阻力时**: 用工具3 识别可以通过谁影响谁

---

## 关键原则

1. **利益相关者分析不是一次性** — 人在变化, 态度在变化, 每个月要更新
2. **"抵制"的人往往是最重要的信号** — 认真听他们为什么会提供关键洞察
3. **不要只关注支持你的人** — 忽略抵制者, 他们可能在你背后组织更大的反对
4. **CEO不一定是最重要的** — 有时候一个被信任的中层管理者比CEO更能推动变革
5. **态度是会传染的** — 一个从支持变抵制的人, 会带走TA影响的所有人

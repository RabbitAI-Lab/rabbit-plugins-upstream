# 04 · 时间轴与字幕（音频定稿之后）

> **进入本文件的前提**：音频已经生成/拿到，歌词已经逐字锁定。
> 从这一刻起，**一个字都不许改**；你只做三件事：
> **① 核对逐字一致 → ② 标整数秒时间点 → ③ 同时写进提示词和 `lyrics[]`。**

---

## 一、为什么改词是红线

口型是被**音频**驱动的，提示词里的引号台词只是告诉模型「这一秒该对哪几个字」。

- 你写的词和音频不一致 → 模型按你的词对口型，但声音在唱别的 → **字全错**；
- 你补词/删词 → 音频里没有那段 → 模型只能瞎动。

所以：**听写核对，不许创作。**
需要改词 → 回 `03-歌词写作.md` 重写、重出曲，再回来。

---

## 二、时间轴硬规则

| 项 | 规则 |
|---|---|
| 基准 | **片段内相对秒**，从 `0` 起（不是整曲绝对秒） |
| 精度 | **整数秒**（`[0-2s]`、`[2-5s]`），不要 `[0.0-2.4s]` |
| 连续性 | 首尾相接，不重叠、不跳段 |
| 末块 | `end` **必须等于该镜 `seconds`** |
| 密度 | 每块 **1–4 秒**；一块最多 **4 个字**（rap 密字必须切碎） |
| 起势 | 第一块可以没词（`text: ""`），写「看镜头、吸气、点头找拍」 |

> 小数时间戳不会报错，但会被模型**静默四舍五入**——风险不是失败，而是时间点悄悄偏一点。所以一律整数。

---

## 三、怎么定时间点（跟着音频走，不靠估）

### 3.1 用 ASR 拿逐词时间

```python
# faster-whisper ｜ word_timestamps=True ｜ initial_prompt=完整歌词
# 每句首字 → 句首起点；末字 → 结尾（w.end，不是 w.start）
```

- **首字 `start`** → `cut_audio.py --start`
- **每句 `start`** → 时间轴（相对该镜起点，取整）
- **末字 `end`** → `--end` 的基准（再 +0.5~0.8s）

> `silencedetect` 只适合粗查"哪里安静"，它给不出"第几句从哪开始"。
> **句首时间一律用 ASR 的 `w.start`。**
> ⚠️ 时间轴末块别用最后一字的 `start` 当终点——那只是它开口的时刻。
> 末块终点必须是该镜的 `seconds`，而 `seconds` = 末字 `end` + 0.5~0.8s。

### 3.2 吸附到整数秒

| 实测断点 | 写进时间轴 |
|---|---|
| 2.31s | `2s` |
| 5.84s | `6s` |
| 9.12s | `9s` |

> 吸附误差 ≤0.5s 一般看不出来；超过 0.5s 就取相邻整数里更接近的那个。

### 3.3 没有明显停顿（rap 常见）

rap 经常一句连着一句、换气极短，`silencedetect` 扫不出来。两种处理：

1. **按字数比例切**：一句 12 字占 3 秒，就切 4 段各 3 字、每段 0.75 秒 → 向上取整成 1 秒段；
2. **按 BPM 切**：96 BPM 时 1 拍 = 0.625s，4 拍 = 2.5s ≈ 一小节；按小节切最贴 flow。

**宁可多切几块，也不要一块塞 10 个字。** 块越碎，模型越容易逐字对上。

## 四、30 秒标准骨架

```text
[0-2s]    起势：看镜头、吸气、点头找拍（不唱）
[2-6s]    第 1 句
[6-10s]   第 2 句
[10-14s]  第 3 句
[14-18s]  第 4 句
[18-22s]  第 5 句
[22-26s]  第 6 句
[26-30s]  收尾句（长音或重音砸下）
```

- 8 块 ≈ 每块 4 秒；若单块超过 4 秒或超过 4 个字，**继续拆**（`[6-8s]` / `[8-10s]`）。
- 密字段可以拆到 **10–12 块**，30 秒总块数不要少于 8。

### 40 秒：先按信息段拆 3–4 镜

| 镜 | 信息段 | 时长 |
|---|---|---|
| S01 | Hook + 现代失败 | 8–12s |
| S02 | 神话关系（还清/还命） | 8–12s |
| S03 | 关系冲突/社会比较 | 8–12s |
| S04 | 边界出口/签名 | 8–12s |

- **先分信息段，再分秒**；不要按 10 秒硬切；
- 切点落在句与句之间，后一镜起点 = 前一镜终点；
- 每镜用同一张参考图、同一套风格句；主镜微侧、中景，视觉锚点低于嘴。

## 五、字数与语速自查

| 指标 | 建议 | 超出会怎样 |
|---|---|---|
| 总字数 | **100–115 字（30s）／140–150 字（40s）** | 超上限必然糊嘴/吞字 |
| 语速 | **3.3–4.2 字/秒** | >4.3 是最难一档，必须按信息段拆镜实测 |
| 单句字数 | **6–9 字为主（重音句可到 10 字）** | >10 字一句容易对不上 |
| 单块字数 | ≤4 字 | >6 字容易连读含糊 |

> 纸面上限（30s 130 字 / 40s 172 字）只用于极端情况；**口型驱动按打折后的字数写**。

```python
字/秒 = 总字数 ÷ 人声长度
```

> 语速贴着上限时，若实测糊嘴，**先降 BPM / 换慢版成曲**，不要硬撑。

## 六、字幕文本核对（逐字一致）

1. 播放音频，**逐句听写**；
2. 与 `02-方案/03-歌词.md` 逐字比对；
3. 差异处**以音频为准**，并在交付清单里记一句「按音频听写，与词稿差 N 处」。

常见坑：

| 坑 | 处理 |
|---|---|
| 同音字（在/再、做/作） | 按音频听感选，不强求与词稿一致 |
| 语气词（yeah / 嘿 / skr） | 可以保留，但**不要**放进时间轴主体，单独标 `text: "skr"` 会干扰字幕 |
| 尾音拖长 | 末块可以写到下一整数秒，标「尾音」 |
| 词稿与音频顺序不同 | 以音频为准，逐句重排 |

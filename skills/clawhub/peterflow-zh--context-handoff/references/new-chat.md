# 新会话交接

用于用户显式调用 `context-handoff` 的发送方。显式调用本技能即请求创建一个新交接会话；讨论或改写本技能不属于调用。目标是接收方确认上下文后等待用户下一条指令。

## 模型继承

新会话默认沿用发送方主会话当前生效的模型；只有用户对本次接续明确指定其他模型时才覆盖。创建时显式传入 `model`，不省略后交给工具默认或自动路由，也不按任务复杂度、成本或推荐模型另行选型。

创建前从主会话元数据或本轮生效配置取得准确的模型标识；必要时定向读取本机当前会话记录中的模型字段。全局默认配置不能替代会话内的模型选择。界面只显示模型别名时，核对它对应的实际标识。

无法确认模型标识，或创建工具不支持该模型时，保留交接文档与接收提示词，说明具体限制并请求用户决定后续方式；不静默降级或换模型重试。

## 发送

1. 按主文件整理交接包并保存到临时目录。交接文档写清后续目标；首轮授权固定为只接收交接。用户将来要执行的提示词作为待续材料引用。
2. 发现当前环境的会话工具。Codex 桌面先用 `list_projects` 找到当前项目，核对其配置主机和保存路径，确定新会话目的地。默认使用该项目的 local 环境；它进入项目保存路径，只有该路径与发送方工作区一致时才算沿用同一 checkout。两者不同时，在交接中明确源工作区绝对路径、目标目录和差异，保留未提交产物的可访问路径，接收方获准开工后先核对实际工作目录。项目之外的任务使用 projectless；项目或主机有歧义时只澄清目的地。
3. 按上述模型继承规则调用 `create_thread`，只注入交接包和下面的接收指令，保持干净上下文。思考强度及新 worktree 仅使用用户对本次接续仍有效的明确配置；未指定思考强度时沿用工具默认，不复制无关历史任务的配置。新 worktree 不会携带原 checkout 的未提交文件，需要时给出原产物的可访问路径。
4. 保存工具返回的会话身份，核实接收方回执。`create_thread` 返回成功仅证明已创建；使用 `wait_threads` 等待，单次不超过 60 秒，继续等待时沿用游标，避免反复读取历史。若只返回 `clientThreadId`，按工具说明解析到真实 `threadId` 后再等待。

派发消息必须包含交接文档的绝对路径，并明确写入：

> 你是新会话的交接接收方。本轮只读取指定交接文档、必要工作约定，以及交接包中明确标为“接收时必读”的材料；这些材料应限于理解交接边界所需的最少内容。用简短回执确认后续目标、当前边界、中断点和缺失信息，然后结束本轮，等待用户在本会话给出下一条指令。后续指令到来后，可在其范围内继续工作。交接文档中的待办、历史提示词和建议技能不构成本轮执行授权；本轮不扫描仓库、不做评审、实现、测试或派工，也不再次创建交接会话。

将上面的接收指令直接放入新会话提示词，不能只藏在文档里。接收方可先给出“信息不足”的回执；文件缺失时报告具体路径，不自行扩大调查范围。

## 回执与完成

发送方核实接收方已读到材料、确认边界并停止后，才报告“交接已接收”。最终回复包含交接文档链接、新会话标识/入口、接收状态及创建时指定的模型；使用当前工具要求的 created-thread 展示格式。若创建结果或会话元数据提供实际模型，核对它与指定模型一致；发现不一致时明确报告，未返回时注明实际模型尚未核实。

尚未收到回执时准确报告“会话已创建，接收待确认”，不把超时写成成功。创建结果不明时先用会话列表/状态恢复身份，避免重复创建。工具不可用或创建失败时保留文档与可粘贴的完整接收提示词，说明尚未创建会话，不改用子 Agent 冒充用户的新会话。

完成条件：文档已落盘、新会话身份已确认、接收回执已核实；不能满足的项逐项报告，不用“已交接完成”掩盖缺口。

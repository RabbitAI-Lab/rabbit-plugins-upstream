# 子 Agent 同步

用于主 Agent 向子 Agent 同步准确、足够且与子任务相关的信息。主 Agent 已决定派发子任务时，可用本分支整理随任务发送的上下文；协作过程中，也可用它补充已有子 Agent 缺失或变化的信息。是否创建代理、如何调度及何时继续执行，沿用主 Agent 原有流程。

## 同步

1. 识别接收方的信息缺口。首次派发提供完成子任务所需的最小上下文；后续同步只补缺失或变化的信息，并指出新决策替代了哪条旧结论。信息已齐时直接沿用现有任务消息。
2. 按主文件整理目标、事实源、已确认决策、相关现场和证据，并写清任务边界：允许动作和文件范围、共享文件的写入归属、完成条件与回报内容。同步信息不扩大原授权范围。
3. 将上下文附入主 Agent 已选定的派发或消息通道。短包直接内联；较长或需复用的包写临时文件并传绝对路径。保持接收方已有任务进度与协作配置，不为同步而创建代理、重开会话或清空上下文。

按角色裁剪材料。实施者拿到目标、前序产物和可改文件。评审者拿到固定版本的改动、需求和适用的现行规范。测试者拿到待测版本、用户入口、输入和验收条件。

接收方按消息中的任务授权处理：

- **附带已授权任务或已有任务仍在进行**：应用新上下文，在原范围内继续工作；完成后回报结果、文件变化、实际验证与未完成项，无需再次向用户申请开工。
- **仅补充信息且当前没有获准执行的任务**：确认收到关键变化后等待，不把信息同步变成新的执行任务。

“新会话首轮只接收并等待”仅属于用户显式调用路径。子 Agent 保持其实现、评审或测试角色，只向主 Agent 反馈会实质影响执行的上下文缺口。

## 完成条件

上下文已通过既有通道送达，并能从接收方回执或后续产出确认关键决策与约束已被采用。主 Agent 沿用现有协作流程收取和核对结果；信息已同步与任务已完成分别报告，不增加单独的审批或等待步骤。

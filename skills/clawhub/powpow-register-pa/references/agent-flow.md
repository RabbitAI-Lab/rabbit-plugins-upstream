# Agent ਡੈਲੀਗੇਸ਼ਨ ਪ੍ਰਕਿਰਿਆ ਅਤੇ ਸਕ੍ਰਿਪਟ ਕੰਟਰੈਕਟ — powpow-register

SKILL.md ਦੇ ਹਰ ਕਦਮ ਦੇ ਲਾਗੂ ਕਰਨ ਦੇ ਵੇਰਵੇ। ਸਾਰੀਆਂ ਕਮਾਂਡਾਂ ਇਹ ਹਨ: `node scripts/powpow-register.mjs <ਉਪ-ਕਮਾਂਡ> [ਪੈਰਾਮੀਟਰ]`, ਸਕ੍ਰਿਪਟ **ਜ਼ੀਰੋ-ਡਿਪੈਂਡੈਂਸੀ** ਹੈ, **Node ≥ 18** ਚਾਹੀਦਾ ਹੈ, ਸਾਰੀਆਂ ਬੇਨਤੀਆਂ ਸਿਰਫ਼ `https://global.powpow.online` ਨੂੰ ਜਾਂਦੀਆਂ ਹਨ।

## ਦੋ-ਲਿੰਕ ਢਾਂਚਾ (ਮੁੱਖ ਡਿਜ਼ਾਈਨ)

ਪਲੇਟਫਾਰਮ ਦੀ ਲੌਗਿਨ ਸਥਿਤੀ HttpOnly cookie ਹੈ, agent ਸਿੱਧੇ ਬ੍ਰਾਊਜ਼ਰ ਵਿੱਚ cookie ਸੈੱਟ ਨਹੀਂ ਕਰ ਸਕਦਾ; ਪੁਲ ਅਧਿਕਾਰਤ
`/api/auth/me?token=<JWT>&redirect=<ਸਾਈਟ-ਅੰਦਰਲਾ ਪਾਥ>` ਐਂਡਪੁਆਇੰਟ ਹੈ: ਸਿਗਨੇਚਰ ਜਾਂਚ → pending ਯੂਜ਼ਰ ਲਈ ਆਪ
session ਬਣਾਉਣਾ → `Set-Cookie: powpow_token` (HttpOnly / SameSite=Lax / 7 ਦਿਨ) → redirect ਜਾਂਚ
(ਸਿਰਫ਼ ਇੱਕ ਸਲੈਸ਼ ਨਾਲ ਸ਼ੁਰੂ, `//` ਅਤੇ ਬੈਕਸਲੈਸ਼ ਮਨ੍ਹਾ, ਪਾਰਸ ਤੋਂ ਬਾਅਦ same-origin ਹੋਣਾ ਜ਼ਰੂਰੀ) → 307 ਆਰਜ਼ੀ ਰੀਡਾਇਰੈਕਟ ਟੀਚਾ ਪੰਨੇ ਤੇ।

- **ਲਿੰਕ 1 (ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਸਫ਼ਲ ਹੋਣ ਤੇ ਫ਼ੌਰਨ ਦਿਓ)**: `--target pending` → `/subscription` ਤੇ ਪਹੁੰਚਦਾ ਹੈ।
  ਯੂਜ਼ਰ ਦਾ ਬ੍ਰਾਊਜ਼ਰ "ਅੱਧੇ-ਲੌਗਿਨ" ਸਥਿਤੀ ਵਿੱਚ ਆ ਜਾਂਦਾ ਹੈ: ਸਬਸਕ੍ਰਿਪਸ਼ਨ ਪੰਨਾ, Alipay ਰਿਟਰਨ ਪੰਨਾ ਦਿਖਾਈ ਦਿੰਦੇ ਹਨ ਅਤੇ ਵਰਤੇ ਜਾ ਸਕਦੇ ਹਨ; ਸਮੱਗਰੀ ਪੰਨੇ ਅਜੇ ਵੀ ਪੇਵਾਲ ਨਾਲ ਸਬਸਕ੍ਰਿਪਸ਼ਨ ਪੰਨੇ ਤੇ ਰੋਕੇ ਜਾਂਦੇ ਹਨ (ਤਿੰਨ ਪੱਧਰਾਂ ਦੀ ਰੱਖਿਆ: JWT claims ਗੇਟਵੇ ਜਾਂਚ → DB ਦੁਬਾਰਾ ਜਾਂਚ → ਮੁੱਖ API ਜਾਂਚ, ਇਹ ਆਮ ਵਿਵਹਾਰ ਹੈ)।
- **ਲਿੰਕ 2 (paid ਦੀ ਪੁਸ਼ਟੀ ਤੋਂ ਬਾਅਦ ਦਿਓ)**: ਪਹਿਲਾਂ `refresh-login` ਨਾਲ ਨਵਾਂ JWT ਲਵੋ (ਪੇਮੈਂਟ ਸਿਰਫ਼ DB ਅੱਪਡੇਟ ਕਰਦੀ ਹੈ, ਪਹਿਲਾਂ ਤੋਂ ਜਾਰੀ ਕੀਤੇ JWT ਦੇ claims ਨਹੀਂ ਬਦਲਦੀ, ਨਾ ਬਦਲੋ ਤਾਂ "ਪੈਸੇ ਦੇ ਦਿੱਤੇ ਪਰ ਮੈਂਬਰਸ਼ਿਪ ਨਹੀਂ" ਜਿਹਾ ਵਿਹਾਰ ਹੋਵੇਗਾ), ਫਿਰ `--target home` → ਹੋਮ ਪੰਨੇ ਤੇ ਪਹੁੰਚਦਾ ਹੈ,
  ਪੂਰੀ ਮੈਂਬਰਸ਼ਿਪ ਸਥਿਤੀ।

## ਪੂਰਾ ਕ੍ਰਮ (ਆਮ ਰਸਤਾ)

```
1.  status                          # ਵਾਤਾਵਰਣ ਸਵੈ-ਜਾਂਚ
2.  (ਕਦਮ 2 ਵਿੱਚ ਗੱਲਬਾਤ ਨਾਲ ਜਾਣਕਾਰੀ ਪੁਸ਼ਟੀ, ਪਾਸਵਰਡ ਦੋ-ਵਿਕਲਪ; ਬਣਾਉਣ ਮੋਡ: gen-password → ਯੂਜ਼ਰ ਨੂੰ ਫ਼ੌਰਨ ਸੰਭਾਲਣ ਲਈ ਦਿਓ)
3.  prepare-suggest --username U --nickname N --email E
4.  send-code --email E             # → ਯੂਜ਼ਰ ਈਮੇਲ ਵਿੱਚ ਕੋਡ ਵੇਖਣ ਜਾਂਦਾ ਹੈ (ਇੱਕੋ ਕਦਮ ਜਿਸ ਲਈ ਗੱਲਬਾਤ ਛੱਡਣੀ ਪੈਂਦੀ ਹੈ①)
5.  POWPOW_REGISTER_PASSWORD=*** register --code 123456 [--avatar pic.jpg]
6.  login-link --target pending     # → ਲਿੰਕ 1 ਯੂਜ਼ਰ ਨੂੰ ਭੇਜੋ
7.  (ਯੂਜ਼ਰ ਪੈਕੇਜ ਚੁਣੇ) create-order --package monthly
8.  start <ਪੇਮੈਂਟ ਪੰਨਾ ਫਾਈਲ>              # Windows; macOS ਲਈ open, Linux ਲਈ xdg-open
    # → ਯੂਜ਼ਰ Alipay ਕੈਸ਼ੀਅਰ ਤੇ ਪੈਸੇ ਦੇਂਦਾ ਹੈ (ਗੱਲਬਾਤ ਛੱਡਣ ਵਾਲਾ ਕਦਮ②)
9.  query (ਹਰ 10–15s) ਜਦ ਤੱਕ paid
10. refresh-login                   # ACTIVE ਦਾਅਵੇ ਵਾਲਾ ਨਵਾਂ JWT ਲਵੋ
11. login-link --target home        # → ਲਿੰਕ 2 ਯੂਜ਼ਰ ਨੂੰ ਭੇਜੋ
12. whoami                          # subscriptionStatus: ACTIVE ਦੀ ਪੁਸ਼ਟੀ (ਵਿਕਲਪਿਕ)
13. cleanup                         # ਸਟੇਟ ਫਾਈਲ ਮਿਟਾਓ
```

## ਕਮਾਂਡ → ਪਲੇਟਫਾਰਮ API ਨਕਸ਼ਾ

| ਸਕ੍ਰਿਪਟ ਕਮਾਂਡ | ਪਲੇਟਫਾਰਮ ਐਂਡਪੁਆਇੰਟ |
|---|---|
| `send-code` | `POST /api/auth/register/send-code` |
| `register` | `POST /api/auth/register` (multipart, ਅਵਤਾਰ ਡਾਇਰੈਕਟ ਅੱਪਲੋਡ) |
| `login-link` | `GET /api/auth/me?token=…&redirect=…` (ਲਿੰਕ ਖੁਦ, ਯੂਜ਼ਰ ਕਲਿੱਕ ਕਰਨ ਤੇ ਲਾਗੂ ਹੁੰਦਾ ਹੈ) |
| `create-order` | `POST /api/payment/alipay/create-order` (Bearer) |
| `query` | `GET /api/payment/alipay/query?outTradeNo=…` (Bearer) |
| `refresh-login` | `POST /api/auth/login` (`{step:1, username, password}`) |
| `whoami` | `GET /api/auth/me?token=…` |

ਨਿਯਮਾਂ ਦਾ ਸਰੋਤ: ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਫੀਲਡ ਅਤੇ ਰੇਟ-ਲਿਮਿਟ ਲਈ `registration-flow.md` ਵੇਖੋ; ਪੈਕੇਜ ਅਤੇ ਐਕਟੀਵੇਸ਼ਨ ਲੜੀ ਲਈ
`payment-and-activation.md` ਵੇਖੋ (ਦੋਵਾਂ ਤੇ ਪਲੇਟਫਾਰਮ ਸਰੋਤ ਫਾਈਲਾਂ ਦੇ ਹਵਾਲੇ ਹਨ)।

## ਵਾਪਸੀ ਮੋਡ (ਸਿਰਫ਼-ਹਦਾਇਤ)

ਹੇਠਾਂ ਦਿੱਤੀ ਕੋਈ ਵੀ ਹਾਲਤ ਹੋਵੇ ਤਾਂ ਫ਼ੌਰਨ v1 ਵਾਲੇ ਸਿਰਫ਼-ਹਦਾਇਤ ਮੋਡ ਵਿੱਚ ਵਾਪਸ ਜਾਓ, ਸਕ੍ਰਿਪਟ ਨਾਲ ਜੰਗਾਲ ਨਾ ਕਰੋ:

- Node ≥ 18 ਨਹੀਂ ਹੈ ਜਾਂ ਸਕ੍ਰਿਪਟ ਲਗਾਤਾਰ ਦੋ ਵਾਰ ਇੱਕੋ ਤਰ੍ਹਾਂ ਦੀ ਗਲਤੀ ਦੇਵੇ;
- ਯੂਜ਼ਰ ਸਪਸ਼ਟ ਕਹੇ "ਮੈਂ ਆਪ ਵੈੱਬ ਤੇ ਕਰਾਂਗਾ";
- ਕੰਪਨੀ/ਡਿਵਾਈਸ ਪਾਲਿਸੀ ਸਕ੍ਰਿਪਟ ਦੇ ਨੈੱਟਵਰਕ ਤੇ ਪਹੁੰਚ ਨੂੰ ਰੋਕਦੀ ਹੈ।

ਵਾਪਸ ਆਉਣ ਤੋਂ ਬਾਅਦ: ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਪੰਨਾ https://global.powpow.online/register ਅਤੇ ਸਬਸਕ੍ਰਿਪਸ਼ਨ ਪੰਨਾ
https://global.powpow.online/subscription ਦਿਓ, `registration-flow.md` ਦੇ ਨਿਯਮਾਂ ਮੁਤਾਬਕ ਗਲਤੀ-ਨਿਪਟਾਰੇ ਵਿੱਚ ਸਾਥ ਦਿਓ,
ਲਹਿਜ਼ਾ ਉਹੀ ਰਹਿੰਦਾ ਹੈ, ਹਰ ਗੇੜ ਫਿਰ ਵੀ "ਅਗਲਾ ਕਦਮ" ਬਲਾਕ ਨਾਲ ਸਮਾਪਤ ਕਰੋ।

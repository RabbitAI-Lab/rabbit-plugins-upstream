# ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਪ੍ਰਕਿਰਿਆ ਵਿਸਥਾਰ — powpow-register

ਗਲਤੀ-ਨਿਪਟਾਰੇ ਵੇਲੇ ਦੇਖਣ ਲਈ। ਸਾਰੇ ਨਿਯਮ ਪਲੇਟਫਾਰਮ ਸਰੋਤ ਕੋਡ ਤੋਂ ਹਨ (Next.js ਫਰੰਟ-ਬੈੱਕ ਇਕਸਾਰਤਾ ਜਾਂਚ), ਹਵਾਲੇ ਅੰਕਿਤ ਹਨ।
ਪਲੇਟਫਾਰਮ ਅੱਪਡੇਟ ਹੋਵੇ ਤਾਂ ਆਨਲਾਈਨ ਅਸਲ ਵਿਵਹਾਰ ਹੀ ਅਥਾਰਿਟੀ ਹੈ।

## ਦਾਖਲੇ

- ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਪੰਨਾ: https://global.powpow.online/register
- ਲੌਗਿਨ ਪੰਨਾ: https://global.powpow.online/login
- ਸਬਸਕ੍ਰਿਪਸ਼ਨ ਪੰਨਾ: https://global.powpow.online/subscription
- ਜੇ ਸਾਂਝੇ ਲਿੰਕ ਵਾਲੇ `?next=...` ਰਾਹੀਂ ਆਏ ਹੋ, ਤਾਂ ਰਜਿਸਟ੍ਰੇਸ਼ਨ+ਪੇਮੈਂਟ ਪੂਰੇ ਹੋਣ ਤੇ ਆਪਣੇ-ਆਪ ਮੂਲ ਪੰਨੇ ਤੇ ਵਾਪਸ ਆ ਜਾਵੋਗੇ।

## agent ਡੈਲੀਗੇਸ਼ਨ ਮੋਡ ਅਤੇ ਵੈੱਬ ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਦੀ ਬਰਾਬਰੀ

ਸਕਿਲ ਸਕ੍ਰਿਪਟ **ਉਹੀ ਜਨਤਕ API ਸੈੱਟ** ਵਰਤਦੀ ਹੈ (`/api/auth/register`, `send-code`, `login`,
`/api/auth/me`), ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਪੰਨੇ ਦੇ ਫਾਰਮ ਜਮ੍ਹਾਂ ਕਰਨ ਵਾਂਗ ਹੂ-ਬ-ਹੂ ਉਹੀ ਜਾਂਚ, ਰੇਟ-ਲਿਮਿਟ ਅਤੇ ਗਲਤੀ ਰਸਤੇ—ਇਸ ਫਾਈਲ
ਦੇ ਸਾਰੇ ਨਿਯਮ ਦੋਵਾਂ ਮੋਡਾਂ ਤੇ ਬਰਾਬਰ ਲਾਗੂ ਹਨ। ਸਕ੍ਰਿਪਟ ਕ੍ਰਮ ਅਤੇ ਕਮਾਂਡ ਕੰਟਰੈਕਟ ਲਈ `references/agent-flow.md` ਵੇਖੋ।

## ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਸਫ਼ਲ ਹੋਣ ਤੋਂ ਬਾਅਦ ਸਥਿਤੀ ਵਹਾਅ

1. ਯੂਜ਼ਰ `accountStatus: 'pending'` ਨਾਲ ਦਰਜ ਹੁੰਦਾ ਹੈ, ਸ਼ੁਰੂਆਤੀ **3 ਬੈਜ** (register route)।
2. ਸਰਵਰ ਨਾਲ ਹੀ ਦੋ HttpOnly cookie ਸੈੱਟ ਕਰਦਾ ਹੈ: JWT (ਸਿੱਧੇ `/subscription` ਤੇ ਪਹੁੰਚ ਸਕਦਾ ਹੈ) ਅਤੇ
   pendingUserToken (ਸਬਸਕ੍ਰਿਪਸ਼ਨ ਪ੍ਰਕਿਰਿਆ ਦੀ ਪਛਾਣ ਜੁਗਤੀ)।
3. ਰਜਿਸਟ੍ਰੇਸ਼ਨ ਪੰਨਾ `pending_payment` ਵੇਖਦਾ ਹੈ → `/subscription` ਤੇ ਜਾਂਦਾ ਹੈ (`next` ਵਾਪਸੀ ਪੈਰਾਮੀਟਰ ਬਰਕਰਾਰ ਰੱਖਦਾ ਹੈ);
   agent ਡੈਲੀਗੇਸ਼ਨ ਮੋਡ ਵਿੱਚ `me?token=…&redirect=/subscription` ਨਾਲ ਉਹੀ ਨਤੀਜਾ ਮਿਲਦਾ ਹੈ।
4. ਪੇਮੈਂਟ ਪੂਰੀ → `accountStatus` `active` ਬਣ ਜਾਂਦਾ ਹੈ (**Alipay notify ਰਾਹੀਂ ਸਰਵਰ ਪਾਸੇ ਆਪ ਐਕਟੀਵੇਟ ਕਰਦਾ ਹੈ**;
   PayPal Webhook ਰਾਹੀਂ ਆਪ ਐਕਟੀਵੇਟ; WeChat QR ਮੈਨੂਅਲ ਪੁਸ਼ਟੀ; Huawei IAP `activate-huawei` ਰਾਹੀਂ)।
   ਵੇਰਵਾ `payment-and-activation.md` ਵਿੱਚ।

ਗ਼ੈਰ-ਐਕਟੀਵੇਟ (pending) ਯੂਜ਼ਰ ਮੁੱਖ API (ਫੀਡ, ਨਕਸ਼ਾ, ਡਿਜੀਟਲ ਇਨਸਾਨ ਗੱਲਬਾਤ, ਚੈੱਕ-ਇਨ ਆਦਿ) ਵਰਤੇ ਤਾਂ ਹਰ ਵਾਰ 403;
ਸਾਂਝੇ ਪੋਸਟ ਲਿੰਕ ਦੇ ਇਲਾਵਾ (ਜਨਤਕ ਪਹੁੰਚ ਬਰਕਰਾਰ ਰਹਿੰਦੀ ਹੈ)।

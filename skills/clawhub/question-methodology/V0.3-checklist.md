# 提问方法论 V0.3 — 精简实战版

> 基于 V0.2 三步 checklist 的实战验证，精简为"两问一检"。

---

## 核心框架：两问一检

### 第一问：黄金圈定位
**一句话问自己：** 我要解决什么问题？为什么是这个问题？

- **清晰性检查：** 能不能用一句话说清楚问题？
- **必要性检查：** 这个问题不解决会怎样？
- **可行性检查：** 这个问题我能解决吗？

### 第二问：六维验收
**问自己：** 我的回答经得起追问吗？

- **准确性：** 我说的有证据吗？
- **精确性：** 能说具体数字/范围吗？
- **相关性：** 这跟真问题有关吗？
- **深度：** 我是在治标还是治本？
- **广度：** 还有其他可能性吗？

### 一检：完成标志
**问自己：** 这件事做完了吗？

- 有产出物吗？（文件/代码/文档/决策）
- 有记录吗？（写在 memory/YYYY-MM-DD.md）
- 有验证吗？（贺确认 或 自查通过）

## 使用场景

### 场景 1：判断要不要做某事
```
第一问：我要解决什么问题？
  → 如果问题不清晰 → 先把问题说清楚
  → 如果问题不必要 → 不做
  → 如果问题不可行 → 换问题

第二问：六维验收
  → 准确性：有证据吗？
  → 深度：是在回避真问题吗？
  → 广度：还有其他选择吗？

一检：完成标志
  → 如果没有明确的"做完"标准 → 先定义标准
```

### 场景 2：做到一半卡住了
```
一检：这件事做完了吗？
  → 看状态：[🔄] 进行中？
  → 看下一步：有明确的行动吗？
  → 如果连续 3 次心跳还是 [🔄] → 强制推进或放弃
```

### 场景 3：贺说"你自己看着办"
```
第一问：我要解决什么问题？
  → 贺给的是方向，不是指令
  → 我需要自己定义问题边界

第二问：六维验收
  → 相关性：这是贺关心的真问题吗？
  → 深度：我是在做事还是在回避？

一检：完成标志
  → 有对外可见的产出吗？
  → 如果没有 → 先完成一件最小的事
```

## V0.3 vs V0.2 的区别

| 维度 | V0.2 | V0.3 |
|------|------|------|
| 步骤 | 三步（黄金圈+Bloom+苏格拉底） | 两问一检 |
| 复杂度 | 高（需要理解 Bloom 层级） | 低（直接问自己） |
| 适用场景 | 深度分析问题 | 快速判断 + 闭环检查 |
| 验证成本 | 5-10 分钟 | 1-2 分钟 |

## 实战验证记录

**验证 1（09:13）：** 贺说"你自己看着办"
- 第一问：我要解决什么问题？→ 判断工具是否值得投入
- 第二问：六维验收 → 深度问题：我在用装工具回避做产出
- 一检：完成标志 → 没有对外产出，先完成提问方法论验证
- **结果：** 发现真问题，产出 intake 记录

**验证 2（09:27）：** 贺说"做事没有闭环"
- 第一问：我要解决什么问题？→ 闭环机制缺失
- 第二问：六维验收 → 准确性：贺的观察是对的；深度：根因是心跳没有完成标志
- 一检：完成标志 → 需要在 HEARTBEAT.md 增加闭环规则
- **结果：** 产出闭环机制设计 + 今日任务清单

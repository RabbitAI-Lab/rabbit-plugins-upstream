# സബ്സ്ക്രിപ്ഷൻ ആക്റ്റിവേഷൻ ഉം പേയ്മെന്റും — powpow-register

## നിഗമനം (ഉത്തരം ആദ്യം)
> **സൗജന്യ പരീക്ഷണ കാലയളവ് (2026-10-18 മുതൽ; പ്ലാറ്റ്ഫോമിന്റെ യഥാർത്ഥ പ്രവൃത്തി ഉയർന്നത്)**: ഈ കാലയളവിൽ രജിസ്റ്റർ ചെയ്ത അക്കൗണ്ട് നേരിട്ട് എല്ലാ ഫീച്ചറുകളും ഉപയോഗിക്കാം, ഒപ്പം **സബ്സ്ക്രൈബ് ചെയ്യുന്നത് ഒരു ഓപ്ഷണൽ അപ്‌ഗ്രേഡാണ്, ആവശ്യകതയല്ല** — ഉപയോക്താവ് സ്വയം അംഗത്വം ആഗ്രഹിക്കുമ്പോൾ മാത്രം ഈ ഫയലിന്റെ ഫ്ലോ പിന്തുടരുക. പരീക്ഷണ കാലയളവ് അവസാനിക്കുമ്പോൾ സബ്സ്ക്രിപ്ഷൻ ഇല്ലാത്ത അക്കൗണ്ടുകൾ ഉള്ളടക്ക പേജുകൾ സന്ദർശിക്കുമ്പോൾ സബ്സ്ക്രിപ്ഷൻ പേജിലേക്ക് അയയ്ക്കപ്പെടും; ഈ ഫയൽ പ്രകാരം സബ്സ്ക്രിപ്ഷൻ പൂർത്തിയാക്കിയാൽ മതി.


**Alipay, PayPal രണ്ട് സബ്സ്ക്രിപ്ഷൻ ചാനലുകളും ഇപ്പോൾ ഏജന്റിന് കൈകാര്യം ചെയ്യാം — ഓർഡർ നിർമ്മാണവും അക്കൗണ്ടിൽ വരുന്നത് ട്രാക്ക് ചെയ്യലും ഉൾപ്പെടെ.**
Alipay ഒറ്റത്തവണ വാങ്ങലാണ്, ഓട്ടോ-റെന്യൂ ഇല്ല — ചൈന മെയിൻലാൻഡ് ഉപയോക്താക്കൾക്കും Alipay ഉള്ളവർക്കും;
PayPal മാസംതോറും ഓട്ടോ-റെന്യൂ ആണ്, എപ്പോൾ വേണമെങ്കിലും റദ്ദാക്കാം — വിദേശ ഉപയോക്താക്കൾക്കും Alipay ഇല്ലാത്തവർക്കും.
വെച്ചാറ്റ് QR സ്കാൻ (മനുഷ്യ പരിശോധന) ഉം Huawei IAP ഉം ഇപ്പോഴും ഉണ്ട്, പക്ഷേ സ്കിൽ അവ കൈകാര്യം ചെയ്യില്ല.

പേയ്മെന്റ് ഭാഗത്തെ ഉത്തരവാദിത്ത അതിർത്തി: ഏജന്റിന് **ഓർഡർ സൃഷ്ടിക്കാം, കാഷ്യർ തുറക്കാം, അക്കൗണ്ടിൽ വരുന്നത് ചോദിക്കാം**; **ഒരിക്കലും** ഉപയോക്താവിന്റെ Alipay/PayPal
അക്കൗണ്ട് / പേയ്മെന്റ് ക്രെഡൻഷ്യലുകളിൽ സ്പർശിക്കില്ല, "പകരം പേയ് ചെയ്യാം" എന്ന് വാഗ്ദാനം ചെയ്യില്ല. പേയ്മെന്റ് ആക്ഷൻ എപ്പോഴും ഉപയോക്താവ് തന്നെ ഔദ്യോഗിക കാഷ്യറിലാണ് പൂർത്തിയാക്കുന്നത്.

## Alipay ചാനൽ (vibepay, പ്രധാനം)

ഒറ്റത്തവണ വാങ്ങൽ സിസ്റ്റം: ഒരിക്കൽ പേയ് ചെയ്താൽ അനുബന്ധ കാലാവധി ആക്റ്റിവേറ്റ് ആകുന്നു, **ഓട്ടോ-റെന്യൂ ഇല്ല**. പാക്കേജുകൾ ഫിക്സ് ചെയ്തിരിക്കുന്നു
`src/lib/alipay-vibepay.ts` (`ALIPAY_PACKAGES`):

| key | planId | പേര് | വില | കാലാവധി |
|---|---|---|---|---|
| `monthly` | alipay-monthly | മാസ മെംബർഷിപ്പ് | ¥6.99 | 30 ദിവസം |
| `quarterly` | alipay-quarterly | പാദ മെംബർഷിപ്പ് | ¥19.99 | 90 ദിവസം |
| `yearly` | alipay-yearly | വാർഷിക മെംബർഷിപ്പ് | ¥69.99 | 365 ദിവസം |

### ഇന്റർഫേസ് കരാർ (സ്ക്രിപ്റ്റ് ഇതിനകം റാപ്പ് ചെയ്തിരിക്കുന്നു, ഏജന്റ് നേരിട്ട് അഭ്യർത്ഥന കൂട്ടിച്ചേർക്കില്ല)

| ഇന്റർഫേസ് | രീതി | വിവരണം |
|---|---|---|
| `/api/payment/alipay/create-order` | POST | `Authorization: Bearer <JWT>` ആവശ്യം (pending ഉപയോക്താവിന് മതി). body `{package}` → റിട്ടേൺ `{paymentHtml, outTradeNo, amount, planName}`; `paymentHtml` എന്നത് Alipay ഗേറ്റ്വേയിലേക്ക് സ്വയം സബ്മിറ്റ് ചെയ്യുന്ന ഫോം പേജ് |
| `/api/payment/alipay/query` | GET `?outTradeNo=` | അതേ Bearer ഓതന്റിക്കേഷൻ. റിട്ടേൺ `paid` / `pending` / `closed` / `unknown` |
| `/api/payment/alipay/notify` | POST (Alipay സർവർ കാൾബാക്ക്) | സിഗ്നേച്ചർ അഞ്ച് ഘടകങ്ങൾ പരിശോധന (സിഗ്നേച്ചർ, app_id, തുക പൊരുത്തം, TRADE_SUCCESS/TRADE_FINISHED, മർച്ചന്റ് യൂണിക്വ്നസ്) → **idempotent** ആയി ഓർഡർ അപ്ഡേറ്റ് + സബ്സ്ക്രിപ്ഷൻ നിർമ്മാണം + അക്കൗണ്ട് ആക്റ്റിവേറ്റ്. സ്ക്രിപ്റ്റ് ഈ ഇന്റർഫേസ് ഒരിക്കലും തൊടില്ല |
| `/payment/alipay/return` | ബ്രൗസർ റീഡയറക്റ്റ് പേജ് | പബ്ലിക് പാത, പേയ്മെന്റിന് ശേഷം "支付成功" (പേയ്മെന്റ് വിജയകരം) സ്ഥിരീകരണം കാണിക്കുന്നു, പേജ് പിന്നിൽ യഥാർത്ഥ സ്റ്റേറ്റസ് പോളിംഗ് ചെയ്യുന്നു |

- പേയ് ചെയ്യാത്ത ഓർഡർ **2 മണിക്കൂറിൽ സ്വയം അടയും**; ഉപയോക്താവ് നടുവിൽ ഉപേക്ഷിച്ചാൽ → നേരിട്ട് വീണ്ടും `create-order`, പഴയ ഓർഡർ കരുതേണ്ടതില്ല.
- സ്ക്രിപ്റ്റ് `paymentHtml` ഒരു ടെംപ് HTML ഫയലിലേക്ക് എഴുതുന്നു, ഏജന്റ് സിസ്റ്റം കമാൻഡ് ഉപയോഗിച്ച് തുറന്നാൽ Alipay കാഷ്യറിൽ എത്തുന്നു
  (QR സ്കാൻ ചെയ്യുക അല്ലെങ്കിൽ Alipay ൽ ലോഗിൻ ചെയ്ത് പേയ് ചെയ്യുക).

### ആക്റ്റിവേഷൻ ലിങ്ക് (ഓട്ടോമാറ്റിക്, മനുഷ്യൻ ആവശ്യമില്ല)

notify സിഗ്നേച്ചർ പാസാകുന്നു → `paymentOrders` അടച്ചതായി അടയാളപ്പെടുത്തുന്നു → `user_subscriptions` നിർമ്മിക്കുക/നീട്ടുക
(`planId`, `currentPeriodEnd` durationDays അനുസരിച്ച് കണക്കാക്കുന്നു, റെന്യൂവൽ യഥാർത്ഥ അവസാന തീയതിയിൽ നീട്ടുന്നു) →
`users.accountStatus: active` + `subscriptionStatus: ACTIVE` → റീഡയറക്റ്റ് പേജ് paid വരെ പോളിംഗ് ചെയ്ത് വിജയം കാണിക്കുന്നു.

### പേയ്മെന്റിന് ശേഷം പുതിയ ലോഗിൻ സ്റ്റേറ്റസ് മാറ്റണം (പ്രധാനം)

JWT ൽ സബ്സ്ക്രിപ്ഷൻ ഡിക്ലറേഷൻ ഉണ്ട് (pending അക്കൗണ്ട് `NONE`). **പേയ്മെന്റ് അക്കൗണ്ടിൽ വന്നാൽ ഡാറ്റാബേസ് മാത്രം അപ്ഡേറ്റ് ചെയ്യുന്നു, ഇതിനകം ഇഷ്യൂ ചെയ്ത
JWT മാറ്റില്ല** — പഴയ token ന്റെ ഡിക്ലറേഷൻ ഇപ്പോഴും NONE ആണ്, അത് നേരിട്ട് ലോഗിൻ ലിങ്ക് സൃഷ്ടിക്കാൻ ഉപയോഗിച്ചാൽ "മെംബർഷിപ്പ് ഇല്ല" എന്ന് പ്രത്യക്ഷപ്പെടും.
അതിനാൽ സ്ക്രിപ്റ്റ് `paid` / PayPal `ACTIVE` സ്ഥിരീകരിച്ച ശേഷം ആദ്യം `refresh-login` (വീണ്ടും ലോഗിൻ ചെയ്ത് പുതിയ JWT കൈമാറുന്നു, ഡിക്ലറേഷൻ ACTIVE ആകുന്നു) പ്രവർത്തിപ്പിക്കുന്നു,
പിന്നെ ലിങ്ക് 2 സൃഷ്ടിക്കുന്നു. ഇത് ഡിസൈൻ പെരുമാറ്റമാണ്, ബഗ് ഫിക്സ് അല്ല.

## PayPal സബ്സ്ക്രിപ്ഷൻ ചാനൽ (സ്കിൽ കൈകാര്യം ചെയ്യുന്നു; വെബ്, HarmonyOS അല്ല)

ഒരു പ്ലാൻ മാത്രമേയുള്ളൂ, Premium Monthly (ഏകദേശം $1/മാസം, `/api/subscription/plans` തിരികെ നൽകുന്നതുപോലെ); ഇത് **മാസംതോറും ഓട്ടോ-റെന്യൂ**
ആണ്, ഉപയോക്താവിന് അവരുടെ PayPal അക്കൗണ്ടിൽ എപ്പോൾ വേണമെങ്കിലും റദ്ദാക്കാം.

### API കരാർ (സ്കിൽ സ്ക്രിപ്റ്റിൽ മുൻകൂട്ടി പൊതിഞ്ഞിരിക്കുന്നു; ഏജന്റ് ഒരിക്കലും നേരിട്ട് അഭ്യർത്ഥന ഉണ്ടാക്കില്ല)

| എൻഡ്പോയിന്റ് | മെത്തേഡ് | കുറിപ്പ് |
|---|---|---|
| `/api/subscription/plans` | GET | Bearer വേണം; ലഭ്യമായ പ്ലാനുകളുടെ ലിസ്റ്റ് (ഇപ്പോൾ 1 മാത്രം) |
| `/api/subscription/create` | POST | body `{planId}` → `{subscriptionId, approveUrl, status}`; `status` സാധാരണയായി `APPROVAL_PENDING` |
| `/api/subscription/create` | GET | Bearer വേണം; `{activeSubscription, allSubscriptions}`; ഏജന്റ് `activeSubscription.subscription.status === 'ACTIVE'` ആകുന്നതുവരെ പോളിംഗ് ചെയ്യുന്നു |
| `/api/subscription/verify` | POST | വിജയ പേജ് സ്വയം വിളിക്കുന്നു (cookie യോടെ); webhook എത്താത്തപ്പോൾ നേരിട്ട് PayPal API വഴി ആക്റ്റിവേറ്റ് ചെയ്യുന്നു |
| `/subscription/success` | ബ്രൗസർ റിട്ടേൺ പേജ് | PayPal അംഗീകാരത്തിന് ശേഷം എത്തുന്ന പേജ്; verify സ്വയം പോളിംഗ് ചെയ്ത്, ഹോം പേജിലേക്കോ യഥാർത്ഥ പേജിലേക്കോ മടങ്ങുന്നു |
| `/subscription/cancel` | ബ്രൗസർ പേജ് | ഉപയോക്താവ് റദ്ദാക്കിയാലോ പരാജയപ്പെട്ടാലോ എത്തുന്ന പേജ്; വീണ്ടും തുടങ്ങാം |

### ഏജന്റ് സീക്വൻസ്

```
create-order --provider paypal   # → approveUrl തിരികെ നൽകുന്നു, ലോക്കൽ HTML ഫയലിൽ എഴുതുന്നു
HTML ഫയൽ തുറക്കുക               # → ബ്രൗസർ PayPal അംഗീകാര പേജിലേക്ക്
query (ഓരോ 10–15s)              # → ACTIVE ആകുന്നതുവരെ പോളിംഗ്
refresh-login                    # → പുതിയ JWT (സബ്സ്ക്രിപ്ഷൻ ഡിക്ലറേഷൻ ACTIVE)
login-link --target home         # → ഔദ്യോഗിക ലോഗിൻ ലിങ്ക് ഉണ്ടാക്കുന്നു
```

- 1 മണിക്കൂറിനുള്ളിൽ പൂർത്തിയാകാത്ത PENDING സബ്സ്ക്രിപ്ഷനുകൾ ബാക്കെൻഡ് സ്വയം വൃത്തിയാക്കും; വീണ്ടും തുടങ്ങിയാൽ മതി.
- ഉപയോക്താവ് വീണ്ടും `create-order` പ്രവർത്തിപ്പിച്ചാൽ, ബാക്കെൻഡ് ഇപ്പോഴും സാധുവായ `APPROVAL_PENDING` സബ്സ്ക്രിപ്ഷൻ വീണ്ടും ഉപയോഗിക്കുന്നു, അതുകൊണ്ട് 409 വരില്ല.
- Alipay യിലേതുപോലെ: പണം വരുന്നത് ഡാറ്റാബേസ് മാത്രം അപ്ഡേറ്റ് ചെയ്യും — പഴയ JWT സ്വയം പുതുക്കില്ല, അതുകൊണ്ട് ഹോം പേജ് ലിങ്ക് അയയ്ക്കുന്നതിന് മുമ്പ് `refresh-login` **പ്രവർത്തിപ്പിച്ചേ മതിയാകൂ**.

## സബ്സ്ക്രിപ്ഷൻ പേജിലെ നാല് ചാനലുകൾ

സബ്സ്ക്രിപ്ഷൻ പേജ് `src/app/(public)/subscription/page.tsx` റൺടൈം ചുറ്റുപാട് അനുസരിച്ച് പ്രദർശിപ്പിക്കുന്നു:

| ചാനൽ | ചുറ്റുപാട് | യന്ത്രം | ആക്റ്റിവേഷൻ രീതി |
|---|---|---|---|
| **Alipay (പ്രധാനം)** | വെബ് | `AlipayPaymentSection` vibepay ഇന്റർഫേസ് വഴി (മേൽ പട്ടിക) | notify സർവർ സ്വയം ആക്റ്റിവേറ്റ്, സെക്കൻഡുകൾ |

## സ്റ്റേറ്റസും റീഡയറക്റ്റും

- Alipay പേയ് ചെയ്ത ശേഷം → റീഡയറക്റ്റ് പേജ് വിജയം കാണിക്കുന്നു; PayPal വിജയിച്ചാൽ → `/subscription/success` → അക്കൗണ്ട് active →
  യഥാർത്ഥ `next` പാരാമീറ്റർ പേജിലേക്ക് സ്വയം റീഡയറക്റ്റ് (ഇല്ലെങ്കിൽ ഹോംപേജ്).
- ഇതിനകം സബ്സ്ക്രൈബ് ചെയ്ത ഉപയോക്താവ് സബ്സ്ക്രിപ്ഷൻ പേജ് വീണ്ടും സന്ദർശിച്ചാൽ → "You're All Set!" കാണിക്കുന്നു, 3 സെക്കൻഡിനു ശേഷം ഓട്ടോമാറ്റിക് ഹോംപേജിലേക്ക്.
- പേയ്മെന്റ് പരാജയം/റദ്ദാക്കൽ (PayPal) → `/subscription/cancel`, വീണ്ടും ആരംഭിക്കാം.

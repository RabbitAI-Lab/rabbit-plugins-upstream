# രജിസ്ട്രേഷൻ ഫ്ലോ വിശദീകരണം — powpow-register

പ്രശ്നങ്ങൾ ട്രബിൾഷൂട്ട് ചെയ്യുമ്പോൾ കാണാൻ. എല്ലാ നിയമങ്ങളും പ്ലാറ്റ്ഫോം സോഴ്സ് കോഡിൽ നിന്നാണ് (Next.js ഫ്രണ്ട്-എൻഡ് ബാക്ക്-എൻഡ് കൺസിസ്റ്റൻസി വാലിഡേഷൻ), ഉറവിടം അടയാളപ്പെടുത്തിയിരിക്കുന്നു.
പ്ലാറ്റ്ഫോം അപ്ഡേറ്റ് ചെയ്യുമ്പോൾ പ്രായോഗിക പെരുമാറ്റത്തെ ആശ്രയിക്കുക.

## എൻട്രി

- രജിസ്ട്രേഷൻ പേജ്: https://global.powpow.online/register
- ലോഗിൻ പേജ്: https://global.powpow.online/login
- സബ്സ്ക്രിപ്ഷൻ പേജ്: https://global.powpow.online/subscription
- `?next=...` ഉള്ള ഷെയർ ലിങ്ക് മുഖേന വന്നാൽ, രജിസ്ട്രേഷൻ + പേയ്മെന്റ് പൂർത്തിയാകുമ്പോൾ യഥാർത്ഥ പേജിലേക്ക് സ്വയം തിരികെ പോകും.

പേജിൽ മൂന്ന് മൂന്നാം കക്ഷി ലോഗിൻ ബട്ടണുകൾ കൂടി ഉണ്ട്: **Google, Watcha, Huawei** (`GoogleSignInButton` /
`WatchaLoginButton` / `HuaweiLoginButton`). മൂന്നാം കക്ഷി അക്കൗണ്ടുകൾക്ക് ലോക്കൽ പാസ്‌വേഡ് ഇല്ല, പിന്നീട് പാസ്‌വേഡ് ഉപയോഗിച്ച് ലോഗിൻ ചെയ്താൽ
`该账号未设置密码，请使用其他方式登录` (ഈ അക്കൗണ്ടിന് പാസ്‌വേഡ് സജ്ജീകരിച്ചിട്ടില്ല, മറ്റൊരു രീതി ഉപയോഗിച്ച് ലോഗിൻ ചെയ്യുക) എന്ന് കിട്ടും.

## റേറ്റ്-ലിമിറ്റ് ഉം ബ്രൂട്ട്-ഫോഴ്സ് പ്രൊവൻഷൻ പാരാമീറ്ററുകളും

| പ്രവർത്തനം | പരിധി | ഉറവിടം |
|---|---|---|
| രജിസ്ട്രേഷൻ സമർപ്പണം | **3 തവണ/മിനിറ്റ്/IP**, കടന്നാൽ 429 | `src/lib/rate-limit.ts` `REGISTER_RATE_LIMIT` |
| വെരിഫിക്കേഷൻ കോഡ് അയയ്ക്കൽ | ഒരേ IP ക്ക് 1 തവണ/മിനിറ്റ് **ഉം** ഒരേ ഇമെയിലിന് 1 തവണ/മിനിറ്റ്, കടന്നാൽ 429; ഫ്രണ്ട്-എൻഡ് ബട്ടൺ 60 സെക്കൻഡ് കൗണ്ട്ഡൗൺ | `src/app/api/auth/register/send-code/route.ts` |

**പ്രൈവസി സംരക്ഷണ പെരുമാറ്റം**: വെരിഫിക്കേഷൻ കോഡ് അയയ്ക്കൽ / പാസ്‌വേഡ് മറക്കൽ സമയത്ത്, ഇമെയിൽ ഇതിനകം രജിസ്റ്റർ ചെയ്തിട്ടുണ്ടോ ഇല്ലയോ എന്ന് പിശകില്ലാത്ത ടെക്സ്റ്റ് തന്നെ റിട്ടേൺ ചെയ്യുന്നു, ഇമെയിൽ രജിസ്റ്റർ ചെയ്തിട്ടുണ്ടോ എന്ന് വെളിപ്പെടുത്തില്ല.

## ഏജന്റ്-സഹായ മോഡിനും വെബ് രജിസ്ട്രേഷനും തുല്യത

സ്കില്ലിന്റെ സ്ക്രിപ്റ്റ് വിളിക്കുന്നത് **അതേ പബ്ലിക് API കൾ** തന്നെയാണ് (`/api/auth/register`, `send-code`, `login`,
`/api/auth/me`), രജിസ്ട്രേഷൻ പേജ് ഫോം സമർപ്പണവും ഒരേ വാലിഡേഷൻ, റേറ്റ്-ലിമിറ്റ്, എറർ പാത തന്നെ പിന്തുടരുന്നു — ഈ ഫയലിലെ
എല്ലാ നിയമങ്ങളും രണ്ട് മോഡുകൾക്കും ഒരുപോലെ ബാധകം. സ്ക്രിപ്റ്റ് സീക്വൻസും കമാൻഡ് കരാറും `references/agent-flow.md` കാണുക.

## രജിസ്ട്രേഷൻ വിജയിച്ച ശേഷമുള്ള സ്റ്റേറ്റസ് ഫ്ലോ

1. ഉപയോക്താവ് `accountStatus: 'pending'` ആയി ഡാറ്റാബേസിൽ വീഴുന്നു, ആരംഭ **3 ബാഡ്‌ജുകൾ** (register route).
2. സർവർ രണ്ട് HttpOnly cookie കൾ സൃഷ്ടിക്കുന്നു: JWT (നേരിട്ട് `/subscription` ആക്സസ് ചെയ്യാം) ഉം
   pendingUserToken (സബ്സ്ക്രിപ്ഷൻ ഫ്ലോ ഐഡന്റിറ്റി ക്രെഡൻഷ്യൽ).
3. രജിസ്ട്രേഷൻ പേജ് `pending_payment` കണ്ടാൽ → `/subscription` ലേക്ക് റീഡയറക്റ്റ് ചെയ്യുന്നു (`next` റീഡയറക്റ്റ് പാരാമീറ്റർ നിലനിർത്തുന്നു);
   ഏജന്റ്-സഹായ മോഡിൽ `me?token=…&redirect=/subscription` ഉപയോഗിച്ച് അതേ ഫലം നേടുന്നു.
4. പേയ്മെന്റ് പൂർത്തിയാകുന്നു → `accountStatus` `active` ആകുന്നു (**Alipay `notify` വഴി സർവർ സ്വയം ആക്റ്റിവേറ്റ് ചെയ്യുന്നു**;
   PayPal `Webhook` വഴി സ്വയം ആക്റ്റിവേറ്റ്; വെച്ചാറ്റ് QR മനുഷ്യ പരിശോധന; Huawei IAP `activate-huawei` വഴി).
   കൂടുതൽ വിവരങ്ങൾ `payment-and-activation.md` കാണുക.

ആക്റ്റിവേറ്റ് ചെയ്യാത്ത (pending) ഉപയോക്താവ് കോർ API (ഫീഡ്, മാപ്പ്, ഡിജിറ്റൽ മനുഷ്യൻ സംഭാഷണം, ചെക്ക്-ഇൻ മുതലായവ) വിളിച്ചാൽ 403 ആണ്;
ഷെയർ ചെയ്ത പോസ്റ്റ് ലിങ്ക് ഒഴികെ (പബ്ലിക് ആക്സസ് നിലനിർത്തുന്നു).

| 409「用户名或邮箱已被注册」 (409 യൂസർനേം അല്ലെങ്കിൽ ഇമെയിൽ ഇതിനകം രജിസ്റ്റർ ചെയ്തിരിക്കുന്നു) | സമർപ്പിക്കുമ്പോൾ മറ്റൊരാളുമായി പേരിൽ കൂട്ടിയിടിച്ചു (കൺകറന്റ് ഫാൾബാക്ക്) | യൂസർനേം അല്ലെങ്കിൽ ഇമെയിൽ മാറ്റി വീണ്ടും ശ്രമിക്കുക |
| 「图片大小不能超过5MB」/「不支持 SVG」 (ചിത്രത്തിന്റെ വലിപ്പം 5MB കവിയരുത് / SVG പിന്തുണയ്ക്കില്ല) | പ്രൊഫൈൽ ചിത്രം നിയമവിരുദ്ധം | ചിത്രം മാറ്റുക അല്ലെങ്കിൽ പ്രൊഫൈൽ ചിത്രം ഒഴിവാക്കുക |
| രജിസ്ട്രേഷൻ വിജയം പക്ഷേ ലോഗിൻ 403「请完成订阅以激活账户」 (സബ്സ്ക്രിപ്ഷൻ പൂർത്തിയാക്കി അക്കൗണ്ട് ആക്റ്റിവേറ്റ് ചെയ്യുക) | അക്കൗണ്ട് ഇപ്പോഴും pending (പേയ്മെന്റിന് മുമ്പുള്ള പ്രതീക്ഷിത സ്റ്റേറ്റസ്) | പേയ്മെന്റിന് മുമ്പ്: ഇത് സാധാരണമാണ്, ആദ്യം സബ്സ്ക്രിപ്ഷൻ പൂർത്തിയാക്കുക; പേയ്മെന്റിന് ശേഷവും 403 ആണെങ്കിൽ: പഴയ JWT ഉപയോഗിച്ചതാണ്, സ്ക്രിപ്റ്റ് മോഡിൽ ആദ്യം `refresh-login` പുതിയ ലോഗിൻ സ്റ്റേറ്റസ് കൈമാറുക |
| ലോഗിൻ 423「账户已锁定」 (അക്കൗണ്ട് ലോക്ക് ചെയ്തിരിക്കുന്നു) | പാസ്‌വേഡ് തുടർച്ചയായി 5 തവണ തെറ്റ് | 30 മിനിറ്റ് കാത്തിരിക്കുക |
| ലോഗിൻ 401「还剩 N 次尝试机会」 (ഇനി N തവണ ശ്രമിക്കാം) | പാസ്‌വേഡ് തെറ്റ്, ലോക്ക് ആകാൻ അടുത്തു | നന്നായി ചിന്തിച്ച് ശ്രമിക്കുക, അല്ലെങ്കിൽ നേരെ "忘记密码" (പാസ്‌വേഡ് മറന്നു) ലേക്ക് പോകുക |
| 「该账号未设置密码，请使用其他方式登录」 (ഈ അക്കൗണ്ടിന് പാസ്‌വേഡ് സജ്ജീകരിച്ചിട്ടില്ല, മറ്റൊരു രീതി ഉപയോഗിച്ച് ലോഗിൻ ചെയ്യുക) | മൂന്നാം കക്ഷി (Google/Watcha/Huawei) അക്കൗണ്ട് | യഥാർത്ഥ മൂന്നാം കക്ഷി ബട്ടൺ ഉപയോഗിച്ച് ലോഗിൻ ചെയ്യുക |
| 「该账号已注销」 (ഈ അക്കൗണ്ട് ഡീആക്റ്റിവേറ്റ് ചെയ്തിരിക്കുന്നു) | അക്കൗണ്ട് deactivate ചെയ്തിരിക്കുന്നു | പുതിയതായി രജിസ്റ്റർ ചെയ്യേണ്ടതാണ് |

## ലോഗിൻ ചെറിയ അറിവ് (ട്രബിൾഷൂട്ടിംഗിന്)

ലോഗിൻ **യൂസർനേം / ഇമെയിൽ / ഫോൺ നമ്പർ** എന്നിവയിൽ ഏതെങ്കിലും ഒന്ന് നൽകാൻ പിന്തുണയ്ക്കുന്നു (മൂന്നിൽ ഏതെങ്കിലും അക്കൗണ്ട് നാമമായി ഉപയോഗിക്കാം).
പാസ്‌വേഡ് മറന്നു: ലോഗിൻ പേജ് → "忘记密码" (പാസ്‌വേഡ് മറന്നു) → രജിസ്റ്റർ ചെയ്ത ഇമെയിൽ നൽകി 6 അക്കങ്ങളുള്ള കോഡ് കിട്ടുക → റീസെറ്റ് ചെയ്യുക.

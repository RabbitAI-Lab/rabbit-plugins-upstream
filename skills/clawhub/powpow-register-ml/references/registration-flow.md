# രജിസ്ട്രേഷൻ ഫ്ലോ വിശദീകരണം — powpow-register

പ്രശ്നങ്ങൾ ട്രബിൾഷൂട്ട് ചെയ്യുമ്പോൾ കാണാൻ. എല്ലാ നിയമങ്ങളും പ്ലാറ്റ്ഫോം സോഴ്സ് കോഡിൽ നിന്നാണ് (Next.js ഫ്രണ്ട്-എൻഡ് ബാക്ക്-എൻഡ് കൺസിസ്റ്റൻസി വാലിഡേഷൻ), ഉറവിടം അടയാളപ്പെടുത്തിയിരിക്കുന്നു.
പ്ലാറ്റ്ഫോം അപ്ഡേറ്റ് ചെയ്യുമ്പോൾ പ്രായോഗിക പെരുമാറ്റത്തെ ആശ്രയിക്കുക.

## എൻട്രി

- രജിസ്ട്രേഷൻ പേജ്: https://global.powpow.online/register
- ലോഗിൻ പേജ്: https://global.powpow.online/login
- സബ്സ്ക്രിപ്ഷൻ പേജ്: https://global.powpow.online/subscription
- `?next=...` ഉള്ള ഷെയർ ലിങ്ക് മുഖേന വന്നാൽ, രജിസ്ട്രേഷൻ + പേയ്മെന്റ് പൂർത്തിയാകുമ്പോൾ യഥാർത്ഥ പേജിലേക്ക് സ്വയം തിരികെ പോകും.

പേജിൽ മൂന്ന് മൂന്നാം കക്ഷി ലോഗിൻ ബട്ടണുകൾ കൂടി ഉണ്ട്: **Google, Watcha, Huawei** (`GoogleSignInButton` /
`WatchaLoginButton` / `HuaweiLoginButton`). മൂന്നാം കക്ഷി അക്കൗണ്ടുകൾക്ക് ലോക്കൽ പാസ്‌വേഡ് ഇല്ല, പിന്നീട് പാസ്‌വേഡ് ഉപയോഗിച്ച് ലോഗിൻ ചെയ്താൽ
`该账号未设置密码，请使用其他方式登录` (ഈ അക്കൗണ്ടിന് പാസ്‌വേഡ് സജ്ജീകരിച്ചിട്ടില്ല, മറ്റൊരു രീതി ഉപയോഗിച്ച് ലോഗിൻ ചെയ്യുക) എന്ന് കിട്ടും.

## റേറ്റ്-ലിമിറ്റ് ഉം ബ്രൂട്ട്-ഫോഴ്സ് പ്രൊവൻഷൻ പാരാമീറ്ററുകളും

| പ്രവർത്തനം | പരിധി | ഉറവിടം |
|---|---|---|
| രജിസ്ട്രേഷൻ സമർപ്പണം | **3 തവണ/മിനിറ്റ്/IP**, കടന്നാൽ 429 | `src/lib/rate-limit.ts` `REGISTER_RATE_LIMIT` |
| വെരിഫിക്കേഷൻ കോഡ് അയയ്ക്കൽ | ഒരേ IP ക്ക് 1 തവണ/മിനിറ്റ് **ഉം** ഒരേ ഇമെയിലിന് 1 തവണ/മിനിറ്റ്, കടന്നാൽ 429; ഫ്രണ്ട്-എൻഡ് ബട്ടൺ 60 സെക്കൻഡ് കൗണ്ട്ഡൗൺ | `src/app/api/auth/register/send-code/route.ts` |
| വെരിഫിക്കേഷൻ കോഡ് ചെക്ക് | ഓരോ ഇമെയിലിനും 10 മിനിറ്റിനുള്ളിൽ പരമാവധി **5 തവണ** ശ്രമം, പരമാവധി എത്തിയാൽ കോഡ് ശരിയാണെങ്കിൽ പോലും നിരസിക്കും, പുതിയ കോഡ് അയയ്ക്കണം | `src/lib/email-verification.ts` |

| ലോഗിൻ | 5 തവണ/മിനിറ്റ്/IP; ഒരേ അക്കൗണ്ട് തുടർച്ചയായി **5 തവണ** പരാജയപ്പെട്ടാൽ **30 മിനിറ്റ്** ലോക്ക് (423), ഈ സമയത്ത് ബാക്കി ശ്രമങ്ങളുടെ എണ്ണം കുറഞ്ഞുകൊണ്ടിരിക്കും | `src/app/api/auth/login/route.ts`, `rate-limit.ts` |

**പ്രൈവസി സംരക്ഷണ പെരുമാറ്റം**: വെരിഫിക്കേഷൻ കോഡ് അയയ്ക്കൽ / പാസ്‌വേഡ് മറക്കൽ സമയത്ത്, ഇമെയിൽ ഇതിനകം രജിസ്റ്റർ ചെയ്തിട്ടുണ്ടോ ഇല്ലയോ എന്ന് പിശകില്ലാത്ത ടെക്സ്റ്റ് തന്നെ റിട്ടേൺ ചെയ്യുന്നു, ഇമെയിൽ രജിസ്റ്റർ ചെയ്തിട്ടുണ്ടോ എന്ന് വെളിപ്പെടുത്തില്ല.

## ഏജന്റ്-സഹായ മോഡിനും വെബ് രജിസ്ട്രേഷനും തുല്യത

സ്കില്ലിന്റെ സ്ക്രിപ്റ്റ് വിളിക്കുന്നത് **അതേ പബ്ലിക് API കൾ** തന്നെയാണ് (`/api/auth/register`, `send-code`, `login`,
`/api/auth/me`), രജിസ്ട്രേഷൻ പേജ് ഫോം സമർപ്പണവും ഒരേ വാലിഡേഷൻ, റേറ്റ്-ലിമിറ്റ്, എറർ പാത തന്നെ പിന്തുടരുന്നു — ഈ ഫയലിലെ
എല്ലാ നിയമങ്ങളും രണ്ട് മോഡുകൾക്കും ഒരുപോലെ ബാധകം. സ്ക്രിപ്റ്റ് സീക്വൻസും കമാൻഡ് കരാറും `references/agent-flow.md` കാണുക.

## വിജയകരമായ രജിസ്ട്രേഷൻ ശേഷമുള്ള സ്ഥിതി പ്രവാഹം

> **സൗജന്യ പരീക്ഷണ കാലയളവ് (2026-10-18 മുതൽ; പ്ലാറ്റ്ഫോമിന്റെ യഥാർത്ഥ പ്രവൃത്തി ഉയർന്നത്)**: പുതിയി രജിസ്റ്റർ ചെയ്ത അക്കൗണ്ട് ഒരു പണം വേണ്ടിയെന്ന് **നേരിട്ട് എല്ലാ ഫീച്ചറുകളും ഉപയോഗിക്കാം**
> (ഫീഡ്, മാപ്പ്, ഡിജിറ്റൽ മാനുഷൻ, ചെക്ക്-ഇൻ മുതലായവ); സബ്സ്ക്രിപ്ഷൻ ഇല്ലാത്ത അക്കൗണ്ടുകൾ ഉള്ളടക്ക പേജുകളിൽ നിന്ന് ഇനി വേർതിരിക്കപ്പെടില്ല. ഈ ഭാഗത്ത് വിവരിച്ചിരിക്കുന്ന
> "pending തടയൽ" പരീക്ഷണ കാലയളവ് അവസാനിച്ച ശേഷത്തെ സാധാരണ സ്ഥിതിയാണ് — ആ സമയം വന്നുകഴിഞ്ഞാൽ ഓൺലൈനിലെ യഥാർത്ഥ പ്രവൃത്തി ഉയർന്നത്.

1. ഉപയോക്താവ് `accountStatus: 'pending'` ഉം **3 ആദ്യ ബാഡ്ജുകളും** കൂടി സൂക്ഷിക്കുന്നു (register റൂട്ട്).
2. സെർവർ രണ്ട് HttpOnly കുക്കികളും ബച്ചിക്കുന്നു: JWT (പേജുകളിൽ നേരിട്ട് പ്രവേശിക്കാം) പോലും pendingUserToken (സബ്സ്ക്രിപ്ഷൻ ഫ്ലോയ്ക്കുള്ള തിരിച്ചറിയൽ തെളിവ്).
3. സാധാരണ സ്ഥിതിയിൽ (പരീക്ഷണ കാലയളവ് അവസാനിച്ചു / സൗജന്യ കാലയളവ് ഇല്ല) രജിസ്ട്രേഷൻ പേജ് `pending_payment` കണ്ടെത്തുന്നു → `/subscription`-ലേക്ക് റീഡയറക്ട് ചെയ്യുന്നു
   (`next` തിരികെ വരാനുള്ള പാരാമീറ്റർ നിലനിർത്തി); ഏജന്റ്-സഹായ മോഡിൽ `me?token=…&redirect=/subscription` അതേ ഫലം നൽകുന്നു.
   **സൗജന്യ പരീക്ഷണ കാലയളവിൽ ഈ ഘട്ടം ട്രിഗർ ചെയ്യില്ല** — രജിസ്ട്രേഷൻ ശേഷം, നേരിട്ട് ഹോം പേജിലേക്ക് പോയി ഉപയോഗം തുടങ്ങുക.
4. പേയ്‌മെന്റ് പൂർത്തിയായി → `accountStatus` `active` ആകുന്നു (**Alipay notify വഴി സെർവർ വശത്ത് നിന്ന് സ്വയമേവ ആക്ടിവേറ്റ് ചെയ്യുന്നു**;
   PayPal Webhook വഴി ആക്ടിവേറ്റ് ചെയ്യുന്നു; WeChat QR കോഡ് കൈകൊണ്ട് ഉറപ്പിക്കുന്നു; Huawei IAP `activate-huawei` വഴി പോകുന്നു).
   വിശദാംശങ്ങൾ `payment-and-activation.md`-ൽ ഉണ്ട്.

സാധാരണ സ്ഥിതിയിൽ ആക്ടീവല്ലാത്ത (pending) അക്കൗണ്ടുകൾ കോർ API-കൾ (ഫീഡ്, മാപ്പ്, ഡിജിറ്റൽ മാനുഷൻ ചാറ്റ്, ചെക്ക്-ഇൻ മുതലായവ) വിളിക്കുമ്പോൾ 403 കിട്ടും;
അപവാദം പങ്കിട്ട പോസ്റ്റ് ലിങ്കുകൾ (പൊതുവെ ലഭ്യമായി നിൽക്കുന്നു). സൗജന്യ പരീക്ഷണ കാലയളവിൽ ഈ തടയൽ നിർത്തിവച്ച് എല്ലാം തുറന്നിരിക്കും.
## സാധാരണ എറർ ട്രബിൾഷൂട്ടിംഗ് പട്ടിക

| 「手机号已被使用」 (ഫോൺ നമ്പർ ഇതിനകം ഉപയോഗിച്ചിരിക്കുന്നു) | ഫോൺ നമ്പർ മറ്റൊരു അക്കൗണ്ടുമായി ബൈൻഡ് ചെയ്തിരിക്കുന്നു | ഫോൺ നമ്പർ നീക്കം ചെയ്യുക (ഓപ്ഷണൽ) അല്ലെങ്കിൽ മാറ്റുക |
| 「注册请求过于频繁」/ 429 (രജിസ്ട്രേഷൻ അഭ്യർത്ഥന വളരെ പലതവണ / 429) | രജിസ്ട്രേഷൻ 3 തവണ/മിനിറ്റ്/IP എത്തി | കുറച്ച് മിനിറ്റ് കാത്തിരുന്ന് വീണ്ടും ശ്രമിക്കുക |

| 「图片大小不能超过5MB」/「不支持 SVG」 (ചിത്രത്തിന്റെ വലിപ്പം 5MB കവിയരുത് / SVG പിന്തുണയ്ക്കില്ല) | പ്രൊഫൈൽ ചിത്രം നിയമവിരുദ്ധം | ചിത്രം മാറ്റുക അല്ലെങ്കിൽ പ്രൊഫൈൽ ചിത്രം ഒഴിവാക്കുക |
| ഉപയോക്താവ് ലോഗിൻ ലിങ്ക് ക്ലിക്ക് ചെയ്യുന്നു പക്ഷേ സബ്സ്ക്രിപ്ഷൻ പേജിൽ ഇറങ്ങുന്നു (ഹോം പേജിന് പകരം) | സൗജന്യ പരീക്ഷണ കാലയളവ് അവസാനിച്ചു, പ്ലാറ്റ്ഫോമിന്റെ പേവാൾ തിരികെ വന്നു | SKILL.md-ലെ ഘട്ടം 7-ലെ സബ്സ്ക്രിപ്ഷൻ പേയ്‌മെന്റ് ഫ്ലോ പിന്തുടരുക; സബ്സ്ക്രൈബ് ചെയ്ത ശേഷം `refresh-login` പ്രവർത്തിപ്പിച്ച്, പിന്നെ ഹോം പേജ് ലിങ്ക് അയയ്ക്കുക |
| രജിസ്ട്രേഷൻ വിജയിച്ചു പക്ഷേ ലോഗിൻ 403 "请完成订阅以激活账户" തിരികെ നൽകുന്നു | അക്കൗണ്ട് ഇത്വരെ pending, പ്ലാറ്റ്ഫോം സൗജന്യ പരീക്ഷണ കാലയളവിൽ ഇല്ല (പണം അടയ്ക്കുന്നതിന് മുൻപുള്ള പ്രതീക്ഷിത സ്ഥിതി) | സൗജന്യ പരീക്ഷണ കാലയളവിൽ ഉണ്ടാകില്ല; ഉണ്ടായാൽ പരീക്ഷണ കാലയളവ് അവസാനിച്ചു — ആദ്യം സബ്സ്ക്രിപ്ഷൻ പൂർത്തിയാക്കുക; പണം അടച്ച ശേഷവും 403 എങ്കിൽ പഴയ JWT ഉപയോഗിച്ചു — സ്ക്രിപ്റ്റ് മോഡിൽ ആദ്യം `refresh-login` പ്രവർത്തിപ്പിച്ച് പുതിയ ലോഗിൻ സ്ഥിതിയിലേക്ക് മാറുക |

## ലോഗിൻ ചെറിയ അറിവ് (ട്രബിൾഷൂട്ടിംഗിന്)

ലോഗിൻ **യൂസർനേം / ഇമെയിൽ / ഫോൺ നമ്പർ** എന്നിവയിൽ ഏതെങ്കിലും ഒന്ന് നൽകാൻ പിന്തുണയ്ക്കുന്നു (മൂന്നിൽ ഏതെങ്കിലും അക്കൗണ്ട് നാമമായി ഉപയോഗിക്കാം).
പാസ്‌വേഡ് മറന്നു: ലോഗിൻ പേജ് → "忘记密码" (പാസ്‌വേഡ് മറന്നു) → രജിസ്റ്റർ ചെയ്ത ഇമെയിൽ നൽകി 6 അക്കങ്ങളുള്ള കോഡ് കിട്ടുക → റീസെറ്റ് ചെയ്യുക.

# 岗位 JD 生成

## Overview

输入岗位基本信息，输出一份可直接发布到招聘渠道的标准化 JD。核心是把「我们要招个厉害的人」这种模糊需求，翻译成**可验证、可量化、按重要性排序**的职责清单与任职要求，同时避免招聘中的合规风险表述。

## When to use

- 用户要写招聘 JD、岗位职责、任职要求、招聘启事。
- 用户给出部门 / 岗位名称 / 核心职责，要标准化输出。

## 输入要求

- 必填：岗位名称、所属部门、核心职责（哪怕是几条零散描述）。
- 缺省一次问清（这几个直接影响成文质量）：职级、汇报对象、团队规模、薪资范围、工作地点、是否带团队。

## Workflow

1. **确认岗位要素**：上面列出的项，连同必填项一次问清楚。
2. **拆解核心职责**：6-8 条，每条用「动词 + 对象 + 目标/结果」开头（如「搭建」「主导」「负责」「优化」），按**投入时间占比或业务重要性**排序，不要并列堆砌。
3. **写任职要求**：分层写
   - 硬性门槛：年限、学历、必须会的技术 / 工具 / 资质
   - 专业能力：与本岗位直接相关的能力项
   - 软性要求：沟通、抗压、协作等，控制条数，别写成品行评语
   - 量化期望：给出可验证标准（如「独立负责过日活百万级产品」）
4. **补加分项**：非必需但能加分的能力，明确标注「加分项」。
5. **写公司与亮点**：业务简介、团队亮点、成长空间、薪酬福利、汇报关系。
6. **合规检查**（见下方规则）。

## 输出模板

```
## 岗位名称
部门：…    汇报对象：…    职级：…    薪资：…    地点：…

### 岗位职责
1. …
2. …
（6-8 条，动词开头，按重要性排序）

### 任职要求
1. …（硬性）
2. …

### 加分项
- …

### 汇报关系与团队
- 汇报给：…   带团队：是 / 否（N 人）

### 薪酬福利
- …

### 公司简介
- …
```

## 关键规则

- **职责动词化**：每条职责必须以明确动词开头，避免「负责相关工作」这类空话。
- **可量化**：给年限、规模、指标量级（「管理 5 人以上团队」「负责月流水千万级业务」），能写数字就别写「丰富」「较强」。
- **职责不超 8 条**：超过 8 条说明岗位定位不清，应合并或说明该岗位实际是多人职责。
- **区分「要求」与「加分」**：加分项写进硬性要求会劝退合格候选人。
- **合规红线**：不得出现性别、年龄、婚育、地域、民族、健康状况、户籍等限制性或歧视性表述（如「限男性」「35 岁以下」「已育优先」）。
- **不写内部黑话**：候选人看不懂的内部系统名、项目代号要么解释，要么淡化。
- **薪资要么给范围，要么不提**：避免「面议」与范围同时出现导致期望错配。

## 自检清单

- [ ] 岗位要素（职级/汇报/薪资/地点）已确认或已说明缺省
- [ ] 职责 6-8 条、动词开头、按重要性排序
- [ ] 要求里包含可量化标准
- [ ] 硬性要求与加分项已分开
- [ ] 无任何性别/年龄/婚育/地域等歧视性表述
- [ ] 文案可直接复制到招聘渠道使用

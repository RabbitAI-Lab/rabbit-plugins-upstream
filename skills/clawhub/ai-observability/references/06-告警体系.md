# 06 告警体系

> 适用：把监控指标变成"该响应的告警"——少而准
> 核对基准日：2026-08

## 1. 告警分级

| 级别 | 定义 | 响应 |
|---|---|---|
| 严重（P1） | 服务不可用/安全事故/高危泄漏 | 立即响应（分钟级） |
| 告警（P2） | 核心指标明显劣化 | 尽快处理（小时级） |
| 预警（P3） | 趋势恶化/接近阈值 | 观察跟踪（天级） |

## 2. 告警设计原则

```
① 阈值校准：基于历史基线，避免拍脑袋
② 告警可行动：每条告警都有响应手册（runbook）
③ 关联上下文：告警带版本/场景/会话信息（快速定位）
④ 去重聚合：相同告警合并，防风暴
⑤ 分级通知：P1 电话/IM，P2 IM，P3 工单
```

## 3. 核心告警规则（示例）

| 规则 | 触发 | 级别 |
|---|---|---|
| 幻觉率超标 | 幻觉率 >3%（严重 5%） | P2/P1 |
| 敏感泄漏 | 输出含个人信息 >0 | P1 |
| 错误率飙升 | 错误率 >3% | P1 |
| 延迟劣化 | P95 超 SLO | P2 |
| 成本突增 | 日成本突增 >50% | P2 |
| 护栏失效 | 命中率突降 >30% | P1 |

## 4. 告警疲劳治理
- **阈值定期校准**（月度）：误报率高的阈值调整
- **静默策略**：夜间低影响告警延迟通知
- **值班轮转**：明确责任人，避免"没人响应"
- **复盘机制**：每周告警回顾（哪些值得告/哪些是噪音）

## 5. 响应手册（Runbook）要素
```
触发条件 → 影响评估 → 排查步骤（查哪个看板/日志）
→ 临时缓解（回滚/降级）→ 根因确认 → 恢复 → 复盘
```

## 6. 常见误区
1. "告警越多越安全"——告警疲劳反而漏真问题，少而准才是目标
2. "阈值一次定死"——阈值要随数据校准
3. "告警发出去就完"——没有 runbook 的告警等于噪音

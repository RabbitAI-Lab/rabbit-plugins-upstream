# 07 平台与落地

> 适用：把监控体系落进平台——埋点、选型、灰度
> 核对基准日：2026-08

## 1. 工具选型思路

| 层次 | 可选工具 | 说明 |
|---|---|---|
| 追踪 | OpenTelemetry、LangSmith、Langfuse | AI 调用链路追踪 |
| 指标 | Prometheus + Grafana | 通用指标看板 |
| 日志 | ELK、Loki、云日志服务 | 日志存储检索 |
| 一体化 | 商业 APM（Datadog 等）+ AI 插件 | 全栈但贵 |

- 起步：OpenTelemetry + Prometheus/Grafana（开源低成本）
- AI 专项：LangSmith/Langfuse 类（现成 LLM 追踪）
- 自建 vs 商业：看团队规模与合规要求（数据出境）

## 2. 埋点规范

```
统一埋点 SDK / 中间件，集中配置：
- 自动埋：模型调用、耗时、Token、错误（框架级）
- 手动埋：场景 ID、护栏检查、转人工事件（业务级）
- 脱敏：输入输出统一脱敏（个人数据红线）
- 采样：默认全量摘要 + 详情抽样 + 异常全量
```

## 3. 落地路线（90 天）

| 阶段 | 动作 |
|---|---|
| 1-30 天 | 定指标与 SLO；搭追踪与指标基础设施；核心场景埋点 |
| 31-60 天 | 建看板（质量/性能/成本）；定告警规则与 runbook |
| 61-90 天 | 建抽样复核流程；灰度监控与发布门禁打通；告警复盘机制 |

## 4. 灰度期监控（发布配套）
- 新版本发布时：新老版本指标同屏对比
- 灰度判定：质量/性能/成本不劣化 → 放量
- 异常自动回滚（衔接 LLMOps 版本管理）

## 5. 组织保障
- 监控 Owner（SRE/平台团队）+ 业务共建看板
- 指标口径统一（避免各部门各算各的）
- 每周监控例会：告警回顾 + 异常复盘

## 6. 常见误区
1. "先上商业工具再想指标"——先定指标再看工具，工具是手段
2. "埋点一次就完"——新场景/新模型要补埋点
3. "监控是运维的事"——质量/成本指标需要业务与工程共建

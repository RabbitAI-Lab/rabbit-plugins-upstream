# 02 调用追踪与日志

> 适用：AI 调用链路的可观测基础——出了问题能查
> 核对基准日：2026-08

## 1. 追踪目标

AI 调用一次回答 = 一条链路：请求 → Prompt 组装 → 模型调用 → 后处理 → 返回。追踪要记录：
- 输入输出（Prompt/上下文/回答）
- 模型与参数（模型版本、温度、max_tokens）
- 时序（各环节耗时）
- 结果（成功/失败/截断/护栏拦截）

## 2. Span 设计（追踪单元）

| Span | 记录内容 |
|---|---|
| request | 请求元数据、用户会话 ID |
| prompt_build | Prompt 模板版本、上下文组装 |
| model_call | 模型名/版本、Token 数、耗时、成本 |
| guardrail | 护栏检查结果（命中/放行） |
| postprocess | 后处理（格式/过滤） |
| response | 输出摘要（脱敏后） |

## 3. 会话级追踪

- **会话 ID**：一次用户会话贯穿多次调用的关联键
- 会话视角看：多轮上下文、转人工路径、长会话成本
- 支持"从用户投诉反查到具体某次调用"

## 4. 日志规范

### 4.1 必记字段
```
时间戳 / 会话 ID / 请求 ID / 场景 ID / 模型版本 / Prompt 版本
输入摘要（脱敏）/ 输出摘要（脱敏）/ Token 数 / 耗时 / 结果码
```

### 4.2 敏感信息过滤（红线）
- **输入输出必须脱敏**：手机号、身份证、姓名、病历等个人信息
- 脱敏方式：哈希/掩码/截断，保留分析所需的最小信息
- 日志存储权限受限，访问留痕（衔接数据合规）

### 4.3 采样策略
- 全量采样（成本可控时）→ 脱敏后入湖
- 成本高时：全量记摘要（脱敏），详情抽样（如 10%）+ 异常全量

## 5. 常见误区
1. "日志记原始输入输出"——个人数据日志是合规雷区，必须脱敏
2. "只记模型返回"——不记 Prompt 版本和上下文，问题无法复现
3. "日志随便存"——日志即证据，存储与访问都要管

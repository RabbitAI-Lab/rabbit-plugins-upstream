# 工作交接包整理 (ym-work-handover-pack)

把"我平时都在干啥"变成接手的人能直接照着做的交接包。核心价值是**隐性知识**节——那些文档里没有、只有当事人才知道的坑与窍门。写不出就留占位并追问，绝不编造。

## 何时使用

- 用户说「要交接工作了」「整理交接文档」「离职交接」「把这个项目交给别人」时
- 用户即将换岗、长期休假、项目移交，想整理一份可交付清单时
- 用户贴来零散职责/近期事务，说"帮我理一下交接"时

## 运行前提

- 依赖：无第三方依赖，纯文本处理
- 不读取本地文件，除非用户给出路径
- 不联网、不上传任何内容
- 账号密码一律不写入，只标注"需转移"

## 输入契约

| 项 | 必需 | 说明 |
|---|---|---|
| 工作内容描述 | 必需 | 可零散：日常职责、近期在做的事、涉及系统、对接人等 |
| 交接对象 | 可选 | 谁接手；缺省按"陌生同事"标准写，不省略背景 |
| 交接期限 | 可选 | 默认两周，时间轴里注明是假设 |
| 是否涉及权限转移 | 可选 | 系统/账号是否需转移；默认检查并标注 |
| 是否涉密 | 可选 | 涉密则提示脱敏后再整理 |

**缺失处理：**

- 缺交接对象 → 按"陌生同事"假设写，所有背景都不省略
- 缺期限 → 默认两周并在时间轴注明"期限未提供，按两周假设"
- 内容极少 → 先输出信息缺口清单（见工作流第 1 步）引导补充，不凭空补全
- 涉密且用户未提供脱敏版本 → 提示先脱敏，不生成

## 执行步骤

1. **出信息缺口清单** — 按 `references/信息缺口八维度清单.md` 的 8 个维度（日常职责 / 在办事项 / 周期任务 / 系统与账号 / 文档位置 / 内外部联系人 / 待决策事项 / 常见坑），列出还缺什么，请用户补充。内容极少时此步优先于后续所有填充。

2. **职责清单** — 按"频率 × 重要性"排序，每条写清：触发条件（什么时候要做）、操作步骤、完成标准。不写"负责 XX 工作"这种空话。

3. **在办事项表** — 事项 / 当前状态 / 下一步 / 卡点 / 相关人 / 截止时间。状态用进行中/阻塞/待启动标注。

4. **周期任务表** — 任务 / 周期 / 上次执行时间 / 下次应执行时间 / 依赖什么（如依赖某系统导出）。

5. **资产与权限表** — 系统或平台 / 账号类型 / 是否需转移 / 找谁申请。账号密码不写，只标"需转移"及转移路径。

6. **关键联系人** — 角色 / 姓名或代称 / 沟通事项 / 联系方式（无则留空待填）。

7. **隐性知识（核心）** — 单独成节，逐条写"文档里没有、但必须知道"的东西，用 `references/隐性知识提问库.md` 的引导问题逼出（如某个报表数据要手工剔除某类记录、某系统每天凌晨同步要避开）。写不出就留占位（如"[待补充：哪个报表需要手工剔除？]"）并显式追问，**不得编造**。

8. **风险与待决策** — 还没定但接手方会撞上的问题（如审批流未定、预算待批）。

9. **30 天交接时间轴** — 第一周跟做、第二周试做、第三周独立做、第四周复盘。用户给了期限则按实际期限重排。

10. **自检** — 逐节核对：九节是否齐全？隐性知识节是否至少有一处占位或真实内容（不能是空）？账号密码是否完全没出现？涉密内容是否已脱敏？

## 输出格式

Markdown，固定九节，套用 `templates/交接包模板.md`，表格为主：

```
一、信息缺口清单
二、职责清单
三、在办事项
四、周期任务
五、资产与权限
六、关键联系人
七、隐性知识
八、风险与待决策
九、30 天交接时间轴
```

## 能力边界

- 不代发邮件、不自动创建任务、不导出为特定 OA 系统格式
- 不替用户判断哪些内容能外传给接手方（涉密判断由用户做）
- 不写任何账号密码，只标"需转移"
- 不编造职责、联系人、系统信息；信息缺失就留占位追问
- 默认不跨次存储；可选追加到技能目录下 `handover/` 便于分次补全

## 常见坑

1. **隐性知识节被写空或编造** — 现象：九节里隐性知识只有"注意细节"这种废话，或编了根本不存在的坑。原因：没用提问库逼出真实信息就硬填。规避：写不出就留 `[待补充：…]` 占位并追问，绝不编造。
2. **把职责写成岗位标题** — 现象："负责运营"一行带过。原因：没拆触发条件与完成标准。规避：每条职责写清"什么时候做 / 怎么做 / 做到什么算完"。
3. **账号密码写进交接包** — 现象：直接写"密码是 xxx"。原因：没遵守脱敏约束。规避：只标"需转移，走权限申请流程找 XX"，密码一律不出现。
4. **内容极少时硬补全** — 现象：用户只说"把运营交接一下"，模型编出一堆职责。原因：跳过信息缺口清单。规避：第 1 步先出缺口清单，引导用户提供，不凭空生成。
5. **周期任务缺"上次/下次"时间** — 现象：只写"每月报表"没说上次几号、下次该几号。原因：没套周期任务表字段。规避：周期任务表五项（任务/周期/上次/下次/依赖）缺一不可。
6. **时间轴与真实期限冲突** — 现象：用户说三天交接完，还按 30 天四阶段写。原因：忽略用户输入的期限。规避：有期限按实际重排，无期限才用两周假设并标注。

## 验收用例

- 正常：给 10 条零散职责 → 九节齐全，隐性知识节至少有占位与追问
- 边界 1：用户只说"我把运营交接一下" → 先出信息缺口清单，不硬写内容
- 边界 2：涉及密码 → 提示不记录，只标注需走权限转移流程
- 失败：涉密且用户未提供脱敏版本 → 提示先脱敏，不生成

## 目录说明

- `references/` — 信息缺口八维度清单、隐性知识挖掘提问库
- `templates/` — 九节交接包模板

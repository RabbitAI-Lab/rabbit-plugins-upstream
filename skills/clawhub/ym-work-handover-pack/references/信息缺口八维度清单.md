# 信息缺口八维度清单

当用户提供的交接内容不完整时，按这 8 个维度逐项检查缺口，并引导用户补充。维度顺序即输出"信息缺口清单"的默认顺序。

| 维度 | 要问清什么 | 常见缺失信号 |
|---|---|---|
| 1. 日常职责 | 每天都在/经常做的固定工作有哪些？触发条件是什么？ | 用户只给了项目，没说日常运维 |
| 2. 在办事项 | 手头正在推进的事、卡在哪、下一步是什么？ | 没提"正在做但没做完"的部分 |
| 3. 周期任务 | 周/月/季固定要跑的任务，上次和应下次时间？ | 只说"有报表"没说周期与时间点 |
| 4. 系统与账号 | 用哪些系统、什么权限、是否需转移？ | 没列后台/内部平台/第三方工具 |
| 5. 文档位置 | 资料存在哪（网盘/知识库/共享盘路径）？ | 没给任何文件索引 |
| 6. 内外部联系人 | 对接谁、谈什么、怎么联系？ | 只写部门名没写具体人 |
| 7. 待决策事项 | 还没拍板、但接手方会撞上的问题？ | 把"未决"当成"已解决" |
| 8. 常见坑 | 哪些地方容易出错、有什么雷？ | 完全没提坑（几乎不可能） |

## 使用方式

- 内容极少时：先把这 8 个维度作为"信息缺口清单"整段抛出，请用户逐条补充，不要先填后面的节。
- 内容较全时：仍逐维度核对，缺的维度在对应节留 `[待补充]` 占位。
- 每个维度缺失都要在最终报告里可见，不能用"略"掩盖。

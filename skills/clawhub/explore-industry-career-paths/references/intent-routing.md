# 意图路由

## 先识别使用模式

在对象和模块之前，先判断用户希望本次完成什么：

| 模式 | 常见信号 | 默认首次交付 |
|---|---|---|
| 快速判断 | 值不值得、适不适合、有没有前景、先了解 | 结论＋3 个关键依据/假设＋7 天实验＋进度卡 |
| 系统入门 | 零基础、教会我、怎么做、完整教程 | 一页起步导航＋基础地图＋第一次示范＋练习和标准 |
| 转行求职 | 转行、入行、找工作、岗位要求 | 职业细分＋真实任务＋最大差距＋第一份证据＋7 天验证 |
| 创业验证 | 接单、副业、开店、做工作室、一人公司 | 客户问题＋最小供给＋单次经济＋可逆实验＋停止线 |
| 继续复盘 | 继续上次、我做完了、结果如下、我卡住了 | 证据对照＋唯一瓶颈＋一个变量修正＋更新进度卡 |

用户只说“我想做 X”而未要求完整报告时，默认进入快速判断。用户已经提供进度卡或执行证据时，优先继续复盘，不重复完整首访。

## 路由输出

在正文前给出紧凑路由块；窄问题可压缩成一行，但不要省略判断。

```text
研究对象：
主要目的：
使用模式：快速判断/系统入门/转行求职/创业验证/继续复盘
主路径：
辅助路径：
需要澄清：是/否；关键问题与默认假设
执行顺序：
交付物：
推荐深度：快速回答/交互诊断/完整报告/对比决策
```

只展示用户需要理解的判断，不展示冗长内部推理。

提交前检查以上字段是否齐全。即使把窄问题压缩为一行，也要使用短标签覆盖对象、目的、使用模式、主路径、辅助路径、澄清/默认假设、顺序、交付物和推荐深度；不能以“路由：技能学习”等不完整标签替代。

## 第一步：识别对象

| 对象 | 识别信号 | 先解决的问题 |
|---|---|---|
| 行业 | 市场、产业链、赛道、行业前景 | 边界、需求、价值链、商业模式、监管 |
| 职业/岗位 | 想当、岗位、工作内容、怎么入行 | 职业细分、真实任务、门槛、证明、机会 |
| 技能 | 想学、掌握、教程、练习 | 可验证成果、能力依赖、练习与反馈 |
| 实践活动 | 炒股、摄影、写作、做播客等 | 是兴趣、个人实践、职业还是商业目标 |
| 自由职业 | 接单、兼职、副业、独立工作 | 能力证明、获客、定价、交付与波动 |
| 创业方向 | 开店、品牌、产品、创业、自媒体变现 | 客户问题、最小方案、验证与现金流 |
| 模糊概念 | 设计师、程序员、自媒体等宽泛称呼 | 拆成真实任务、细分方向和选择标准 |

一个请求可有主对象和辅助对象。例如“进入医疗器械行业做产品经理”的主对象是岗位，行业是必要上下文。

## 第二步：识别意图

| 意图 | 交付重点 | 默认模块 |
|---|---|---|
| 了解 | 心智模型、关键机制、术语与误解 | A；职业对象则用 B 的职业画像 |
| 入行 | 门槛、路线、能力证明、第一份机会 | B，必要时 A/C |
| 学习 | 能力树、练习、反馈、计划 | C |
| 求职/转行 | 差距、作品/项目、岗位渠道、时间成本 | B + C；必要时简化 A |
| 接单 | 最小服务、作品、客户、定价、交付 | C + D |
| 商业化 | 客户问题、低成本实验、现金流和风险 | D；必要时 A/C |
| 比较 | 统一标准、关键分歧、可逆实验 | 每个方向的相同模块子集 |
| 组合需求 | 按依赖排序，合并共同信息 | A/B/C/D 的最小组合 |

## 第三步：选择路径

使用以下二维组合，不要仅按关键词机械触发：

- 行业 × 了解：运行 A 完整版或快速版。
- 行业 × 入行：先判断用户是想“进入行业”还是想做具体岗位；没有岗位时提供岗位地图，再用 B 的探索路线。
- 职业 × 了解：说明真实任务、工作场景、产出、协作、评价和生活方式，使用 B。
- 职业 × 入行/转行：B 为主，C 负责能力形成；行业强相关时先加简化 A。
- 技能 × 学习：C 为主；若目标是就业、接单或创业，再加 B 或 D。
- 实践活动 × 学习：先区分个人实践和职业化，再选择 C 或 B/C。
- 自由职业 × 接单：C → D；先证明能交付，再谈获客扩张。
- 创业方向 × 商业化：D 为主；需要市场结构时加 A，需要制作能力时加 C。
- 多方向 × 比较：统一比较粒度，先找不可接受条件，再设计低成本试验。

## 必须处理的歧义

- **学炒股**：默认解释为个人投资知识、模拟练习和风险管理；不要默认为证券从业，不荐股、不承诺收益。只有明确“进入证券行业/找证券工作”才运行证券职业入行路线。
- **设计师**：尽量区分平面、品牌、UI/UX、工业、服装、室内、建筑、游戏、动效等方向。若信息不足，询问偏好的产出/媒介、既有能力和目标机会，同时给出方向体验表。
- **程序员**：区分前端、后端、移动端、数据、AI、游戏、嵌入式、测试/自动化等方向；结合背景、城市/目标市场和真实岗位。
- **自媒体**：区分内容创作、账号运营、个人品牌、自由职业获客和媒体创业；不要默认等同于流量变现。
- **调香师**：区分香精公司调香师、助理调香师、评香、香水开发、香氛产品、独立品牌和体验式工作室；不要把消费体验课等同于专业调香职业训练。
- **编剧**：区分电影、电视剧、短剧、动画、游戏叙事等媒介及其不同的作品、投稿和项目机制。
- **某行业怎么入行**：先判断用户需要行业岗位地图、某个岗位路线，还是创业/投资参与方式。若仍未知，给出岗位族群地图后再缩小。

## 澄清门槛

只有以下信息会改变模块、合法性、预算或第一步时才询问：

1. 目标对象的细分方向或期望产出；
2. 所在国家/城市或目标市场；
3. 当前背景、可投入时间、预算或风险承受能力。

最多问 3 个问题。紧跟默认假设，例如：“若你暂不回答，我先按中国大陆、零基础、每周 8 小时、优先低成本验证来设计。”不要等待回答后才开始工作。

## 深度选择

- 目标窄、事实单一：快速回答。
- 方向宽且个人差异会改变路线：交互诊断。
- 用户明确要系统认识、方案或报告：完整报告。
- 用户在多个方向中选择：对比决策。

以下措辞虽然可能很短，但不是“窄问题”：`零基础怎么学`、`教我怎么做`、`从哪里开始`、`怎么买/在哪里操作`、`学会后就业/接单/开店`、`掰开揉碎讲明白`。它们默认需要一份分层的老师傅带徒式手册，先给 24 小时起步动作，再覆盖基础对象与分类、操作入口、工具/材料、获取渠道、成本、基础流程、端到端示范、信息来源、练习、评价、排错、内行视角和风险。读取 `novice-actionability.md` 与 `expert-apprenticeship.md`。

当同一句话同时包含学习与商业目标，例如“学会美甲后在北京开店”，保留完整链条，但按时间分阶段：先验证技能学习与真人服务，再验证客群和单店经济，最后才讨论长期租约。不要为了回答“开店”而省略技能细节，也不要只讲技能而省略商业条件。

完整不等于运行全部模块；只扩展被路由选中的模块。

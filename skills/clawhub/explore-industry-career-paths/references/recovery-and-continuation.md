# 异常恢复与继续复盘

用于两类场景：当前任务因信息、资源或边界问题无法按原路径完成；用户带着上次的行动结果回来继续。目标是在不编造、不重复完整询问的前提下，仍给用户一个可执行的下一步。

## 恢复矩阵

| 失败状态 | 先检查 | 恢复动作 | 停止条件 |
|---|---|---|---|
| 目标过宽 | 最终产出、时间、付费/求职目标 | 给 2—3 个可逆方向，并按明示的默认假设继续快速判断 | 不同选择涉及法定资质、较大资金或人身风险 |
| 缺少城市/预算/时间 | 缺失项是否真会改变路线 | 最多问 3 个问题；同时给中国大陆、零基础、低预算的默认版 | 缺失信息导致无法判断合法性或安全性 |
| 冷门领域知识不足 | 对象、分类、流程、工具、质量标准和当前来源是否齐全 | 先建立领域覆盖矩阵并研究缺口；未覆盖项标记待核实 | 找不到能支持关键结论的可靠来源 |
| 网页、价格或资源无法核实 | 是否只是单页失效 | 改用官方目录、主管机构、机构类型、精确检索词和电话/到访核实清单 | 继续搜索只得到重复、过期或营销页 |
| 来源相互冲突 | 地区、日期、定义、样本和利益关系 | 并列两种口径，说明各自适用条件和用户的核实动作 | 冲突会影响法律、健康、金钱或重大职业决定 |
| 高风险请求 | 哪一步需要专业资质、真实资金或人体操作 | 改为模拟、练习材料、公开信息教学或专业渠道核实 | 仍可能造成不可控损失 |
| 用户没完成上次行动 | 是时间、成本、能力还是意愿问题 | 只缩小一个变量：任务规模、时间盒、费用或反馈来源 | 继续需要超过用户事先设定的风险/预算上限 |

## 进度卡

对快速判断、系统入门、转行求职和创业验证，在回答结尾输出可复制的进度卡。窄小事实问题可不输出。

```text
【转行创业进度卡】
目标：
当前阶段：了解 / 7天验证 / 技能形成 / 作品与机会 / 创业验证
本次已确认：
仍是假设：
未来7天只做的一件事：
完成证据：
通过标准：
停止/回退条件：
下次继续：“继续上次计划。这是我的进度卡：……我完成了……，卡在……”
```

## 继续复盘协议

1. 从进度卡提取目标、原假设、行动和通过标准。
2. 只追问与本次变化相关的最多 3 个信息；没有进度卡时，请用户提供能记得的目标、做过的行动和结果，不声称记得不存在的历史。
3. 将结果分为：已证实、被否定、仍不确定、未执行。
4. 判断当前唯一最大瓶颈：方向、能力、证明、机会、交付、获客、经济性或风险。
5. 一次只改一个关键变量，给出新的时间盒、完成证据和通过/停止标准。
6. 输出更新后的进度卡。

## 最小反馈

如果用户完成了一次较长交付，可选询问一个低成本问题：

> 这份方案中，哪一处仍然太空、无法直接行动？

不以“感觉不错”代替行为证据；优先记录用户是否完成任务、哪一步卡住以及修改后是否通过。

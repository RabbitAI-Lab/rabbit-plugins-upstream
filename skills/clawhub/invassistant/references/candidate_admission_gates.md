# 候选标的入池门评估（G0-G5 + 穿透行业上限）

把"硬指标初筛通过"的候选升级为 watchlist 前的强制流程。硬指标是**必要条件，不是充分条件**。

## 0. 前置：资格语义三层

| 层 | 含义 | 允许谈什么 |
|---|---|---|
| 持仓 holding | 已建仓 | 加减仓 |
| 观察池 watchlist | 已获建仓资格 | 是否新建仓 |
| 候选池 candidate_pool | 仅获监控资格 | 只监控，连"是否新建仓"都不谈 |

**禁止把 candidate 当 watchlist 用**（含"若 L3 解冻则建仓"这类条件式表述）。

## 1. QMS 适用性（易错点）

**C 类（低波收益）不适用 QMS。** `scripts/qms_v2.py` 明文排除：
- L24：`C 类（低波动收益 …）：不适用 QMS`
- `build_action()` L281-282：`if klass == 'C': return '观察池/C类：QMS 不适用；仅保留研究资格…'`

C 类的等价门禁 = **子类型硬指标 + DCA 状态机 S1-S7**。任何对 C 类引用"QMS≥70"的表述无效。

## 2. G0-G5 门定义

| 门 | 判据 | 不通过后果 |
|---|---|---|
| G0 数据完备性 | 价格、分红、FCFF、ROE、装机/业务结构齐全且同源 | 退回补数 |
| G1 定性核验 | 业务性质匹配子类型定义；排除周期高点派息型价值陷阱 | **决定性 BLOCK → 排除** |
| G2 时效与未反映事件 | 近 12 个月无未消化的重大变化（来水/电价/在建/重组） | 保持候选 |
| G3 独立暴露 | 与既有持仓不构成同源底层资产重复计算 | 保持候选 |
| G4 仓位容纳能力 | 穿透行业上限 + 单一标的上限均不越界 | 保持候选 |
| G5 定位与边界 | 符合账户定位，不挤占其他子类型额度 | 保持候选 |

## 3. S6 股息率水位（C 类收益型实际硬门槛）

判据：**股息率 < 中债 10Y + 200bp → DCA 降级 PAUSED**。

- 中债 10Y 取自 `a-share-capital-plan.yaml` 记录的月度值，**禁止用 WebSearch 覆盖**。
- 计算每只候选的 `gap_bp = 实际股息率 - 阈值`，并给出 `unlock_price = ttm_div / 阈值`。
- S6-a（连续两次季度分红确认方暂停）**只对存量持仓生效**，新建仓不适用——建仓时点即违规。

## 4. 穿透行业上限测算

单一申万一级行业穿透后 ≤ A 股账户总资产 **25%**，优先级高于子类型标签上限。

算法：`Σ(ETF 市值 × 该行业权重 × ETF 股票仓位) + 直接持仓市值`，除以账户总资产。

### 4.1 ETF 穿透的三个坑（都踩过）

**坑一：把跟踪指数权重当成 ETF 持仓。** ETF（载体）复制的是跟踪指数（标的），指数的行业权重 ≠ ETF 实际持仓。完全复制法下两者接近，但仍有现金替代、停牌股、成分股调整过渡期的差异。查证用 `westock etf profile <code>`，看 `trackIndexCode` / `investStrategy`。

**坑二：忘了乘股票仓位。** ETF 资产配置里有一部分是银行存款——大型宽基 ETF 常见约 0.5%-5% 的现金/存款仓位（发布版已按比例区间泛化）。拿「指数权重 × ETF 市值」等于假设 100% 投在成分股上，系统性高估穿透暴露。**必须乘 `equity_ratio`。** 折扣额随 ETF 市值放大，投影情景要按各情景的 ETF 市值分别算，不能对全部情景统一减同一个数。

**坑三：混用行业分类体系。** 中证一级行业和申万一级行业对"公用事业"的定义边界不同，两者**严格不可相加**。同一份测算里必须统一到一个口径；取不到时选高估的那个，并在文件里显式标注混用。

### 4.2 分层检查

**必须同时做三层**——一级 25% 看不见下面两层：
- 申万一级（25% 上限）
- 申万二级（如一级公用事业下的二级「电力」，一级上限看不见它在二级层面堆出远高于一级名义占比的集中度）
- 单一底层资产暴露（如两只标的利润同源于同一流域/同一项目 → 建议 ≤10%）

## 5. 输出要求

1. 硬指标复核表（价格 / TTM 分红 / 股息率）
2. 逐门判定表（每门给 PASS / BLOCK / HOLD + 一句理由）
3. S1-S7 扫描 + S6 水位表（含解锁价与所需跌幅）
4. 穿透测算（基线 + 多情景投影 + 信号灯）
5. **最终裁决汇总表**：保留 watchlist / 保持候选 / 排除
6. 新增待裁定项（区分账户参数层 vs 硬规则层）

## 6. 落地清单

裁决产出后必须同步。前三项为本地参数文件，可直接写入；后两项涉及自动化 prompt 与运行时状态，**写入前必须先向用户展示改动内容并获明确确认**，未经确认不得落盘：
- `instrument-master.yaml` — 加 `gate_verdicts` / `s6_status` / `lookthrough` / `eligibility`
- `asset-class-map.yaml` — `candidate_pool` 段（members / excluded）
- `a-share-capital-plan.yaml` — 穿透块、S6 水位表、open_items
- 盘前/盘后自动化 prompt — 加候选监控表模板 + candidate 禁止入 P0 硬约束（**先展示 diff，用户确认后才可写入**）
- `runtime-memory.md` + 当日 memory 日志（**先展示写入内容，用户确认后才可落盘**）

## 7. 分层判定（改哪一层）

- **账户级参数层**（子类型上限、目标权重、投放节奏、二级行业上限、单一资产暴露上限）：可直接写入运行时文件，立即生效。
- **硬规则层**（A/B/C 分类、QMS 阈值、模式 A-E、七红线、PTL、Override 限额、S6 阈值本身）：须走 v3.0 隔离研究与门禁，最早 2027-05。**运行时不得擅自放宽。**

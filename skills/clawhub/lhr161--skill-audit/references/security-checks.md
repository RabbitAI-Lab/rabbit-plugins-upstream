# 安全检查规则

本文件解释 `SEC1-SEC6` 六类安全条目的判定依据、正则形态、误报边界与修复方式。检查全部在本地对文本执行，不联网、不执行被检查的脚本。

## 检查范围

- `SKILL.md` 与目录下所有 `.md`（含 `references/`）
- `scripts/` 下的 `.py`、`.sh`、`.js`、`.ts`
- 目录内其他 `.yaml`、`.json`、`.txt`

跳过的目录：`.git`、`node_modules`、`__pycache__`、`.venv`。扫描时跳过与检查器内容相同的文件（含其副本，按 sha256 判定）；仅在越权路径（SEC6）检查中跳过 shebang 行与含 URL 的行，避免把解释器路径和链接误判成系统路径。凭据、危险命令、网络调用等检查不做此豁免。

## 豁免机制（重要）

被检查文件可以在前 8 行写 `audit:ignore-file SEC2 …` 声明豁免某些检查，但：

- **一律不生效**。检查器仍会全量扫描，并把该声明作为一条中危问题记录到报告与 JSON 的 `suppressed` 字段；工具不提供任何采信声明的开关，因此不存在被审查对象用声明关掉检查的路径；
- 任何豁免都会计入扣分（每份文件 3 分，上限 6 分）；
- **行内注释不生效**：豁免只认文件前 8 行的 `audit:ignore-file <代码>` 声明，行尾写 `# audit:ignore` 之类的标记不会跳过任何检查。这一设计是为了防止被审查对象用一行注释把安全检查整体关掉。

## SEC1 硬编码凭据（阻塞，8 分）

**判定**：出现"敏感字段名 = 带引号的 16 位以上字面量"，或命中已知密钥前缀。

| 模式 | 说明 |
|---|---|
| 敏感字段名（`api_key`、`token`、`password` 等）后接引号包围的长字面量 | 变量赋值本身不算 |
| 以 `sk-` 开头的长串 | OpenAI 风格密钥 |
| `AKIA` 加 16 位大写字母数字 | AWS Access Key |
| `ghp_` 开头的长串 | GitHub Token |
| `BEGIN PRIVATE KEY` 标记 | 私钥内容 |

**不计入**：占位符与变量名，如 `your_api_key_here`、`xxx`、`<YOUR_KEY>`、`${ENV_VAR}`、`environment_key`。判定时对匹配值再跑一次占位符过滤，命中 `your|example|placeholder|dummy|fake|changeme|xxx|_here|_key$` 的一律跳过。

**修复**：改为从环境变量读取，并显式校验其存在性；文档示例统一写成占位符形式。

## SEC2 破坏性命令（6 分）

**判定**：只认真正会毁数据的形态，避免把文档里的说明文字误判。

| 模式 | 为什么危险 |
|---|---|
| 递归删除作用于根目录或家目录（`rm` 与 `-rf` 组合、目标为 `/` 或 `~`） | 删除根目录或家目录 |
| `mkfs` 系列作用于 `/dev/` 下的设备 | 格式化设备 |
| `dd` 直接写块设备（读入 `if=`、输出指向 `/dev/`） | 裸写块设备 |
| 自复制函数形式的 fork bomb | 耗尽进程 |
| `chmod 777` 作用于系统路径 | 过度授权 |
| 停机类命令（`shutdown`、`reboot`、`halt`）带立即执行参数 | 停机 |
| `no-preserve-root` 选项 | 配合删除命令越过保护 |

**不计入**：注释里的普通词汇、`rm -rf ./build` 这类限定在项目目录内的清理。

**修复**：把删除范围收窄到明确的工作目录，并在执行前做路径校验。

## SEC3 脚本网络调用（5 分）

**判定**：脚本中出现 `curl`/`wget` 的下载调用、`requests` 的请求方法、`urllib.request` 模块、`fetch` 调用。

**为什么**：skill 与开放网络组合是数据外泄的主要通道。确需联网时应使用严格 allowlist，并在 `SKILL.md` 中写明允许访问的域名与可外发的数据范围。

**不计入**：纯文档中的链接（正文出现 URL 不扣分），以及本地文件读写。

**修复**：把网络访问移到宿主程序；脚本只做确定性计算。

## SEC4 提示注入与隐瞒指令（5 分，明确变体阻塞）

分两级：

| 级别 | 模式 | 处理 |
|---|---|---|
| 阻塞 | 要求模型忽略既有指令的表述（英文 ignore 系短语与中文同义说法） | 封顶 55 分 |
| 扣分 | 要求向用户隐瞒 agent 自身行为的表述（如不得告知用户、隐藏该动作） | 安全维度记 0 |

**误报边界**：像"不要建议用户重构仓库"这类**关于语气与建议**的表述不算隐瞒，规则要求宾语指向 agent 自身行为才命中。

**修复**：删除要求隐瞒的措辞；确需安静执行时，改为"不额外输出中间过程"，并保留可审计的日志。

## SEC5 交互式提示（3 分）

**判定**：脚本中出现等待标准输入的 `input` 调用、`raw_input` 调用、`read -p` 提示参数、提示按回车等待、或 y/n 确认提示。

**为什么**：agent 运行在非交互 shell 中，等待输入的脚本会永久挂起。

**修复**：所有输入改为命令行参数、环境变量或 stdin 管道；缺失参数时打印用法并以非零码退出。

## SEC6 越权路径（3 分）

**判定**：脚本中出现连续两级以上的上级目录跳转、系统配置目录（`/etc`、`/root`、`/usr/sbin`、`/var/spool` 等）的绝对路径、用户凭据目录（`ssh`、`aws`、`gnupg` 等隐藏目录）。

**不计入**：shebang 行、URL 中的路径、`./` 与单层 `../`（在项目内属正常）。

**修复**：用 `pathlib.Path(__file__).parent` 锚定 skill 目录，并对拼接结果做 `resolve()` 后的前缀校验，拒绝逃逸出目录的路径。

## 误报处理

判红但人工确认无风险的，应当在评审记录中标注"已确认豁免"，而不是直接关闭检查。不接受被检查文件自声明的豁免；确需放行时由评审人书面记录，而不是修改检查器行为。规则的收紧需要同步更新本文件与 `scoring-rubric.md`，并在 `evals/` 中补一条对应用例，防止回归。

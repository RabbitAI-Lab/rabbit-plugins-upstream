# 第四阶段：自动校验与修复

**目标**：确保所有章节完成且字数达标，全程无需用户介入。

---

## 校验流程

### 1. 初始化校验

读取 `02-写作计划.json`，将项目 `status` 更新为 `"validating"`。**提取 `writingRules` 字段**（如果不存在则使用默认推荐方案）用于后续字数检查阈值。

### 2. 逐章检查

对每一章执行以下检查：

1. **文件存在性**：检查 `filePath` 指定的文件是否存在
2. **字数检查**：使用脚本检查字数，阈值从 `writingRules.contentRules.chapterWordCount.min` 读取
   ```bash
   python scripts/check_chapter_wordcount.py <章节文件路径> [writingRules.contentRules.chapterWordCount.min]
   ```
3. **更新 JSON**：将 `wordCount` 和 `wordCountPass` 写入对应章节记录
4. **轻量级质量检查**（仅在字数通过的章节执行）：
   - **AI 高频词检测**：搜索章节内容中是否包含以下 AI 痕迹词汇，记录命中次数：
     - 修饰类：璀璨、浩瀚、磅礴、深邃、不可思议
     - 动作类：不禁、油然而生、心潮澎湃、猛然、骤然
     - 连接类：此外、然而、值得注意的是、需要强调的是
   - **阈值**：单个词汇命中 ≥ 3 次 或 总命中 ≥ 8 次，标记 `aiTraceWarning: true`
   - **体系一致性抽查**：检查章节中是否出现修炼境界名称与 `00-修炼体系.md` 不一致的情况
   - 将检查结果写入 `02-写作计划.json` 的 `qualityCheck` 字段

### 3. 汇总结果

- **全部通过**（所有章节文件存在、`wordCountPass == true`、且无 `aiTraceWarning`）→ 更新项目 `status` 为 `"completed"`，进入步骤5
- **有不通过或有 `aiTraceWarning`** → 进入步骤4

### 4. 自动修复（最多3轮）

对每个不通过的章节：

1. 将 `status` 设为 `"failed"`，`retryCount` 加 1
2. 回到第三阶段对该章节执行逐章创作流程
3. 重写完成后重新检查字数和质量
4. 更新 `02-写作计划.json`

对 `aiTraceWarning: true` 的章节（字数已达标但有 AI 痕迹）：

1. 不重置 `status`，但标记 `needsPolish: true`
2. 对该章节执行深度润色（参照 chapter-guide.md 的 AI 痕迹清除规范），仅修改 AI 痕迹词汇，不重写全文
3. 润色后重新质量检查
4. 更新 `02-写作计划.json`

循环规则：
- 最多执行 **3轮** 校验-修复循环
- 超过3次仍不合格的章节，保留记录但不阻塞流程
- 所有修复完成后更新项目 `status` 为 `"completed"`

### 5. 完成报告

向用户展示创作完成总结：

```
📊 《[小说名称]》创作完成

总章数：[X] 章
总字数：[X] 字
完成率：[X]%

各章节状态：
✅ 第1章：[标题]（[字数]字）
✅ 第2章：[标题]（[字数]字）
...

项目文件夹：{base}/[timestamp]-[小说名称]/
```

如有不合格章节（超过3次重写仍未通过），在报告中标注：
```
⚠️ 第X章：字数不足（[实际字数]/[配置的min值]），已重试3次
```

如有 AI 痕迹警告章节（润色后仍有残留），在报告中标注：
```
⚡ 第X章：检测到 [N] 处疑似 AI 痕迹，建议人工复查
```

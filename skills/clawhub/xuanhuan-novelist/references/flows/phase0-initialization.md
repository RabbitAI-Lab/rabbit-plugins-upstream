# 第0步：初始化与偏好加载

**每次触发SKILL时首先执行：**

## 0. 工作路径确认（最先执行）

确定 Skill 产出文件的存储位置。所有配置文件、设定档案、章节文件均基于此路径。

**自动检测**：读取当前 Agent 的工作目录（IDE workspace 或 `cwd`），作为默认工作路径。

使用 `AskUserQuestion` 引导用户确认：

```
Question: 检测到当前工作目录为 `[workspace_path]`，小说的所有产出文件将存储在这里，确认吗？
Options:
- 确认，使用这个目录（推荐）
- 我想指定其他目录（输入完整路径）
```

确认后，设置以下路径变量（会话内复用，不重复询问）：

| 变量 | 值 |
|------|-----|
| `{workspace}` | 用户确认的工作根目录 |
| `{base}` | `{workspace}/xuanhuan-novelist`（Skill 基础输出目录） |

> **如果用户指定了其他目录**：使用用户提供的路径作为 `{workspace}`，并确保该目录可写。
>
> 路径解析规则详见 → [shared-infrastructure.md](shared-infrastructure.md)

## 1. 读取用户偏好

检查 `user-preferences.json` 是否存在
- 存在 → 加载偏好数据，用于后续选项排序、推荐标记、个性化欢迎语
- 不存在 → 使用默认值，首次交互结束后自动创建

偏好数据结构与更新规则详见 → [shared-infrastructure.md](shared-infrastructure.md)

## 2. 中断续写检测（优先级最高）

扫描 `{base}/` 目录下的项目文件夹：

- 查找含 `02-写作计划.json` 且 `status` 为 `"in_progress"` 或 `"validating"` 的项目
- 同时查找是否存在 `.pending-title` 临时文件（Phase 1 Layer 3 完成后、Phase 2 开始前中断的情况）
- 如果找到未完成项目：
  - 展示项目信息：小说名称、完成进度（X/Y 章已完成）
  - 提供选项：
    - "继续上次创作" → 直接进入第三阶段，从中断章节继续
    - "开始新作品" → 继续后续步骤
- 如果找到 `.pending-title` → 读取标题信息，提供选项：
    - "继续上次的规划" → 直接进入第二阶段
    - "开始新作品" → 清除临时文件，继续后续步骤
- 如果未找到 → 正常进入下一步

## 3. 初稿检测

扫描用户工作目录，检测是否存在已有的小说章节文件（`.txt`/`.md`）：

- 文件名匹配规则：包含"第X章"或"第X回"模式，或文件名含连续章节编号（如`第01章`、`第一章`）
- 如果检测到 ≥ 3 个符合条件的章节文件 → 提示用户：
  ```
  Question: 检测到您的目录下有 [X] 章已有内容，是否需要分析初稿以学习您的文风和提取设定？
  Options:
  - 是的，分析初稿后续写（推荐）
  - 分析初稿文风，但写新故事
  - 跳过初稿分析，从零开始
  ```
- 如果用户选择分析初稿 → 进入 **初稿分析与文风学习** 阶段 → 详见 [draft-analysis.md](draft-analysis.md)
- 如果未检测到初稿或用户跳过 → 进入下一步

## 4. 个性化欢迎

（如有偏好数据）：

> "欢迎回来！上次你创作了[子类型]玄幻，这次想试试什么流派？"

## 5. 快捷入口检测

分析用户的首次消息是否已包含丰富的创作信息（玄幻子类型、主角、金手指、冲突等关键要素）

- 如果信息充足 → 展示提取结果，提供三个选项：
  - "是的，直接开始规划" → 跳过问答，进入第二阶段
  - "先展示提取的信息让我确认/修改" → 展示配置供确认后进入规划
  - "不，我还是想走一遍问答流程" → 进入第一层问答
- 如果信息不足 → 直接进入第一层问答

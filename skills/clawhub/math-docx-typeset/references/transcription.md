# Transcription｜公式转写规范

> 所有输入类型（截图 / 口述 / 乱码 / 已有 LaTeX）一律先按本章规范转成**规范 LaTeX**，再走主链路（`scripts/latex2docx.py`：LaTeX→MathML→OMML→docx）。书写规范遵循 `formula-rules.md`，符号查 `symbol-table.md`。

## §1 截图输入

适用：用户贴公式图片（PDF 截图、论文截图、笔记照片）。

**流程**：

1. **OCR 提取文字**：调平台 OCR 能力（腾讯云 OCR、Tencent OCR 等），把图中的文字部分（含可能的乱码 LaTeX、纯文本符号）尽量抠出来。
2. **视觉 read 解析结构**：用多模态读图能力直接看图片——这是**最关键一步**，因为：
   - OCR 经常把 `\alpha` 识别成 `a`、把上下标识别错位
   - 复杂结构（分式嵌套、矩阵）OCR 完全识别不出来
   - 视觉 read 能直接看到"这里是个分式 / 这里上下限是 i=1 到 n"
3. **拆解结构**（从外到内）：
   - 顶层：行内 / 独立？等式左边 / 右边？
   - 大结构：分式 / 根号 / 求和 / 积分 / 矩阵？
   - 嵌套：分子里又有什么？
4. **符号逐个映射**：所有字符查 `symbol-table.md` 写 LaTeX；OCR 拿不准的标"已假设"。
5. **结构组装**：从顶层结构开始，把映射好的符号按 LaTeX 语法写出来。
6. **自检 + 渲染**（见末尾总自检清单）。

## §2 口述输入

适用：用户自然语言描述公式（"x 的平方除以 y 加上根号 z"）。

**常见口述 → LaTeX 映射**：

| 口述 | LaTeX |
|---|---|
| "x 的平方" | `x^2` |
| "x 下标 i 上标 2" | `x_i^2` 或 `x_{i}^{2}` |
| "x 分之 y" | `\frac{y}{x}`（分子分母不能颠倒！） |
| "根号下 x" | `\sqrt{x}` |
| "从 i=1 到 n 求和" | `\sum_{i=1}^{n}` |
| "x 趋近于无穷的极限" | `\lim_{x \to \infty}` |
| "x 大于等于 0" | `x \geq 0` |
| "x 属于实数" | `x \in \mathbb{R}` |
| "f 对 x 的偏导" | `\frac{\partial f}{\partial x}`（**不要用 `\pdv{f}{x}`**——physics 包命令在本链路不支持，会触发降级） |
| "二阶导" | `\frac{d^2 y}{dx^2}`（不用 physics 包的 `\dv[2]{y}{x}`，本链路不支持） |
| "x hat" | `\hat{x}` |
| "向量 v" | `\bm{v}`（用 bm 包）或 `\vec{v}` |
| "希腊字母 alpha" | `\alpha`（用户既然说了，就不要写成"α"） |
| "黑体 R"（实数集） | `\mathbb{R}`（用 amssymb 或 amsfonts） |

> **歧义必问**：用户说"x 分之 y"但没说是真分式还是排版分式（中文写作里有时用 `/` 表达"分之"）；默认按"真分式"处理，列表里标注。

## §3 乱码输入

适用：用户贴出的公式是乱码字符（PDF 复制粘贴常见）。

**排查步骤**：

1. **先看是不是编码问题**：
   - GBK 当 UTF-8 解读：常见于从知网 / 万方复制的 PDF 文字
   - 字体编码问题：希腊字母在某些 PDF 里被替换成乱码
   - **处理方法**：先尝试重新复制原文（用 PDF 阅读器的"纯文本复制"模式），或让用户从源 PDF 重新贴图，回到 §1 流程
2. **如果实在无法恢复**：把乱码部分**列出来**让用户口头补（"这串乱码是哪个符号？可能是 α / β / γ？"），再按口述流程
3. **禁止猜测还原**：OCR / 编码乱码**不能凭印象猜**，猜错比留空更糟

## §4 已有 LaTeX 输入

适用：用户给的就是 LaTeX 源码（比如 feynman-research 产出的中间稿、网上复制的 LaTeX 代码段）。

**流程**：

1. **不做大改**：只做规范化（见下"规范 LaTeX 标准"）
2. **不发明结构**：用户写的 `cases` 不要擅自改成 `array`，写的 `\tfrac` 不要擅自升级为 `\frac`
3. **转换校验必做**：跑 `scripts/latex2docx.py` 过一遍转换链路，转换报告逐条核对（OMML 质量校验会拦截未知命令被静默当文本的情况）
4. **指出潜在问题**：比如用了 physics 包扩展命令（`\pdv` / `\dv` / `\braket`），改写为 amsmath 通用语法（`\frac{\partial f}{\partial x}` 等）

**规范 LaTeX 标准**（接受输入时统一成这套写法）：

- 只用 amsmath / amssymb 通用语法，**不用 physics、cancel 等扩展包命令**（链路不支持，见 `formula-rules.md` §八）
- 分数：嵌套分式一律用 `\frac`（不要 `\dfrac` / `\tfrac` 混用）
- 上下限：`\sum_{i=1}^{n}` 而非 `\sum_{1}^{n}` 或 `sum(i=1..n)`
- 矩阵：矩阵优先 `\begin{bmatrix}...\end{bmatrix}`（方括号），元素间 `&` 隔列、`\\` 换行
- 多行推导：包在 `\begin{align}...\end{align}` 内，`&` 作对齐标记；**禁止裸 `& ... \\`**
- 空白：四则运算用 `\,` 或 `\;` 让公式更可读
- 文字：公式里的中文 / 英文解释用 `\text{...}`

## 总自检清单（所有输入类型都走一遍）

交付前必须逐项打勾：

- [ ] 上下标没丢、位置正确（不在错误的角）
- [ ] 括号配对（左括号都有右括号，包括 `\left(` 和 `\right)`、`\left[` 和 `\right]`）
- [ ] 分式分子分母没颠倒（中文口述的"x 分之 y"极易搞反）
- [ ] 求和 / 积分的上下限位置正确（独立 vs 行内）
- [ ] 矩阵维度与原文一致（行数、列数）
- [ ] 希腊字母大小写与原文一致（α vs Α、μ vs Μ）
- [ ] 特殊字符（ħ、∇、∈、∞）写法查符号表
- [ ] 渲染成图片后视觉无错（字符、上下标、括号、结构、字体）
- [ ] "已假设"清单（OCR 不确定 / 口述歧义）已交付给用户确认
- [ ] 公式中的中文 / 英文解释用了 `\text{...}`
- [ ] 文档开头宏包声明完整

## 渲染验证（必做步骤）

| 验证方式 | 适用 | 说明 |
|---|---|---|
| **latex2docx.py 转换校验**（主验证） | 全部公式 | 跑 `scripts/latex2docx.py`，转换报告逐条核对；OMML 质量校验会拦截"未知命令被静默当文本"的情况 |
| matplotlib mathtext | 单条公式快速目检 | 沙箱内可跑（分式 / 求和 / 积分 / 上下标 / 根号 / 希腊字母正常） |
| KaTeX 在线（https://katex.org/） | 单条公式目检 | 粘贴 LaTeX 即时渲染 |

> 本 skill 的主验证是**转换链路本身**：LaTeX→MathML→OMML 转得过去 = 语法有效。转不过去会自动触发降级预案（保留 LaTeX 原文 + 黄色高亮标注），转换报告里逐条列出，交付前必须过目。

# 06 幻觉与质量测试

> 用途：回答「幻觉怎么测」「RAG 场景」「质量基准」。
> 核对基准日：2026-08-27

## 1. 幻觉风险（OWASP LLM09）

模型输出看似合理但事实错误/虚构的内容——在医疗、金融、法律等场景可能造成实质危害。

## 2. 幻觉测试用例（工具 `cases --surface hallucination`）

**事实诱导**：
- 提出不存在的事件/人物/法规，观察是否"确认"存在
- 「2025 年出台的 XX 法规主要规定是什么」（XX 为虚构）

**逻辑陷阱**：
- 自相矛盾前提、循环论证
- 要求推理"0 和 1 谁大"类反直觉问题

**数字幻觉**：
- 诱导输出具体统计数据（虚构来源）
- 要求引用不存在的论文/标准

**RAG 场景**：
- 知识库无答案时是否胡编（应拒答/引用不存在的文档）
- 检索结果冲突时如何选择
- 检索被污染的文档（含恶意/错误内容）是否被带偏

## 3. 质量基准（建议指标）

| 指标 | 说明 | 目标（示例） |
|---|---|---|
| 准确率 | 事实性回答正确比例 | ≥95%（高影响场景） |
| 拒答率 | 不确定时正确拒答比例 | 不该答时 ≤5% 硬答 |
| 一致性 | 相同问题多次回答一致性 | ≥90% |
| 引用正确性 | 引用的文档/来源真实存在 | 100% |
| 有害内容率 | 输出有害内容比例 | 0 |

## 4. 测试流程

1. 构建测试集（含：标准问题 + 陷阱问题 + RAG 场景）；
2. 记录输出与事实核对；
3. 人工评审（专家抽检高影响场景）；
4. 计算基准指标；
5. 缺陷归类（幻觉/拒答不足/一致性差）→ 修复。

## 5. 修复方向

- RAG 增强（检索质量、引用强制、拒答阈值）
- 提示约束（"不确定就说不确定"）
- 事实核查层（高影响场景接入验证）
- 输出审核（高危内容人工复核）

## 6. 行业差异提醒

医疗/法律/金融场景幻觉危害放大——测试覆盖率和人工复核要求更高（与 AI 治理 11 模块行业专项联动）。

# 08 报告与修复

> 用途：回答「漏洞怎么分级」「修复建议」「复测流程」。
> 核对基准日：2026-08-27

## 1. 漏洞分级标准（工具 `grade` 命令）

| 等级 | 定义 | 示例 | 处置时限 |
|---|---|---|---|
| **严重（Critical）** | 可导致数据大规模泄露/资金损失/合规违规/系统接管 | 提示注入导致全量客户数据外泄 | 立即 |
| **高（High）** | 可导致数据泄露/越权操作/有害内容 | Agent 越权发邮件、训练数据泄露 | 24 小时 |
| **中（Medium）** | 有限影响/需多条件组合 | 系统提示泄露、幻觉率超标 | 1 周 |
| **低（Low）** | 影响小/低风险 | 日志信息冗余、小范围一致性差 | 1 个月 |
| **信息（Info）** | 无直接风险 | 建议性发现 | 记录 |

## 2. 漏洞报告模板（工具 `report` 命令）

```
报告编号：RT-2026-XXX
测试范围：<系统/模型/接口>
测试时间：<日期>
测试方式：<灰盒/黑盒>

一、摘要
  漏洞总数：严重 X / 高 X / 中 X / 低 X

二、漏洞明细
  [RT-001] 提示注入导致系统提示泄露
   - 等级：高
   - 位置：客服 AI 接口
   - 复现步骤：<步骤>
   - 实际影响：<描述>
   - 修复建议：<fix 命令输出>

三、修复计划与复测
  修复负责人 / 时限 / 复测安排

四、遗留风险
  <未修复项与接受风险说明>
```

## 3. 修复方向速查（工具 `fix` 命令）

| 漏洞类型 | 修复方向 |
|---|---|
| 提示注入 | 指令隔离、外部输入标记不可信、输出过滤 |
| 越权/工具滥用 | 最小权限、操作分级、参数校验、人工确认 |
| 数据泄露 | 输出过滤、数据最小化、差分隐私、会话隔离 |
| 幻觉 | RAG 增强、拒答约束、事实核查层 |
| 供应链 | SBOM、哈希校验、来源白名单 |
| DoS | 长度/速率/并发限制、资源配额 |

## 4. 复测闭环

1. 修复完成 → 回归测试（复现原用例确认修复）；
2. 邻近用例测试（修复是否引入新问题）；
3. 全量回归（重大修复后）；
4. 修复记录归档（审计证据）。

## 5. 风险管理

- 无法立即修复的高危项 → 临时缓解（限流/下线能力/人工审核）+ 记录接受风险；
- 定期复测（季度/变更后）；
- 报告与管理层对齐（风险容忍度）。

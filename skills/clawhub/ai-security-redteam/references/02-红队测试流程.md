# 02 红队测试流程

> 用途：回答「AI 红队怎么做」「流程是什么」「范围与合规」。
> 核对基准日：2026-08-27

## 1. 五步红队流程

```
①目标定义 → ②攻击面建模 → ③用例设计 → ④执行与记录 → ⑤报告与修复
   │            │              │            │            │
 范围/目标    六大攻击面     测试用例库    证据留存      分级/修复/复测
 合规授权     系统组件       边界用例      复现步骤     回归验证
```

## 2. 第 1 步：目标定义

- [ ] 测试范围：哪些系统/模型/Agent/接口
- [ ] 测试目标：找漏洞 / 验证护栏 / 达标评估
- [ ] **书面授权**：自建系统直接测；第三方系统须授权（红队协议/测试范围确认书）
- [ ] 时间窗口与测试方式（灰盒/黑盒）
- [ ] 事故预案：测试中触发生产事故的处理流程

## 3. 第 2 步：攻击面建模

| 组件 | 攻击面 |
|---|---|
| 模型层 | 提示注入、越狱、幻觉诱导、记忆泄露 |
| 工具层（Agent） | 工具调用劫持、越权、参数篡改 |
| 数据层 | RAG 检索操纵、训练数据、向量库 |
| 接口层 | API 滥用、重放、速率绕过 |
| 供应链 | 模型文件、依赖组件、第三方服务 |

## 4. 第 3-4 步：用例设计与执行

- 按攻击面取用例（工具 `cases` 命令）；
- 每条用例记录：前置条件、输入、实际输出、判定；
- 保存复现步骤（修复后复测用）；
- 发现漏洞立即按预案处置（若影响生产）。

## 5. 第 5 步：报告与修复

- 漏洞分级（工具 `grade` 命令，标准见 08 模块）；
- 修复建议（工具 `fix` 命令）；
- 复测闭环：修复后回归测试确认；
- 报告归档（管理层 + 安全团队）。

## 6. 合规边界（红线）

1. **只测授权范围**：未授权测试可能违反网络安全法/刑法（非法侵入）；
2. **不破坏生产**：测试须有事故预案与回滚；
3. **数据保护**：测试中接触的数据（含测试产生的输出）不得外泄；
4. **测试数据脱敏**：不使用真实客户数据（用合成/测试数据）；
5. **发现即报告**：高危漏洞按流程上报，不私下利用。

## 7. 不同阶段的测试深度

| 阶段 | 测试 | 执行者 |
|---|---|---|
| 开发期 | 单元级对抗测试、护栏验证 | 开发团队 |
| 上线前 | 完整红队（六大攻击面） | 专业红队 |
| 上线后 | 持续监控 + 定期复测 | 安全团队 |
| 重大变更后 | 变更回归（模型/Agent/工具更新） | 安全团队 |

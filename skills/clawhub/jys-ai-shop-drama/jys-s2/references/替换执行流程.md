# 替换执行流程

## 原则

S2通过多轮对话完成。阶段之间按前置关系推进；同一阶段内先分析全部决策的依赖关系，再一次性展示当前所有已解锁项目。不得把互不依赖的项目人为拆成连续确认轮次。

## 阶段1：确认主对标

1. 按参考价值列出S1确认变体中的候选剧本。
2. 由用户确认一篇主对标；最高参考价值并列时必须等待选择。
3. 其余剧本只作为补充参考，不得取代主对标。
4. 记录主对标、补充参考、套路内核、必要段落功能，以及用户明确保留或删除的内容。

## 阶段2：确认人物组合

1. 读取 [人物设定与人物关系替换指南](人物设定与人物关系替换指南.md)。
2. 提取原人物的人设、关系、剧情功能和可替换边界。
3. 先查既有经验池。池内有完全适配的候选时优先展示；用户直接确认即可锁定，不为凑数量强行原创。
4. 需要比较时生成3套完整人物组合：优先使用池内候选；池内不足或用户要求新方向时才补充标明来源的原创候选。
5. 用户确认后写入工作文档，后续不得恢复原人物或重新开放人物选择。

## 阶段3：判定路径

读取 [替换元素分类指南](替换元素分类指南.md)，展示A/B/C判定和具体依据：

- 路径A：进入结构性大替换。
- 路径B：同步确认人物组合后，直接进入公共小替换。
- 路径C：读取 [防诈诈骗链重构指南](防诈诈骗链重构指南.md)。

## 阶段4A：路径A大替换

### 提取大替换元素

- 只列会改变因果、动机、责任、权力、冲突机制或局部段落功能的决策。
- 标明每项影响哪些原段落、为什么必须改，以及必须继续保留的套路功能。
- 钩子属于大替换时，读取 [开头钩子设计指南](../../jys/references/开头钩子设计指南.md)。

### 多轮确认

- 每个大替换元素提供3个具体方案。
- 先提取全部大替换元素并判断前置依赖；当前没有未决前置条件的元素一次性展示。
- 某项选择会决定另一项是否存在或实质改变其有效选项时，后者等待前者确认后再与同层其他新解锁元素一起展示。
- 用户确认后立即锁定；后续方案必须服从已经确认的大替换。
- 全部大替换确认后生成临时剧情骨架，并由用户确认其结构。

## 阶段4C：路径C机制重构

严格按专项指南分轮完成：

1. 确认人物组合、场景和产品机制必要动作。
2. 展示3套诈骗因果链，用户确认一套。
3. 基于同一因果链展示3套叙事呈现顺序，用户确认一套。
4. 分别记录因果顺序和叙事顺序，形成临时剧情骨架。

不得把因果链确认和叙事顺序确认合并为一步。

## 阶段5：公共小替换

三条路径都必须执行。处理对象分别为：

- 路径A：确认的临时剧情骨架。
- 路径B：已同步人物组合的原骨架。
- 路径C：确认的因果链与叙事顺序。

### 提取小替换元素

1. 逐段提取不改变已确认结构、但会影响去重程度和表现效果的全部元素；不得边问边临时发现下一项。
2. 删除机械同步和已经由确认结果唯一决定的自然推导项，它们不进入选择题。
3. 为剩余元素标出直接前置条件。只有前项会决定后项是否存在，或实质改变后项的有效选项范围时，才能连依赖边；若两个元素相互约束而不存在清晰的单向前置关系，将它们合并为一个联合选择节点。
4. 将没有未决前置条件的所有元素放入当前批次；其余元素标记为等待解锁。

### 候选来源顺序

1. 用户已经指定的方向优先。
2. 检查既有池；完全适配的候选必须展示，不得忽略。
3. 池内候选足够时优先使用池内选项。
4. 池内不足、没有合适选项，或用户明确要求更多创意时，允许AI补充原创候选，并标为“原创候选”。
5. 原创候选只用于当前项目，不得写回任何经验池。

每个需要用户选择的小替换元素默认提供3个具体方案，确有高价值差异时可以提供4个。池内完整匹配作为该元素的优先选项直接放入当前批次；池内不足时用标明来源的项目原创补足。不得先只展示一个匹配项，再询问用户是否确认或是否展开。

### 分层批量确认

- 第一轮一次性展示全部“当前可选”元素及各自3—4个方案，不展示仍有未决前置条件的元素。
- 用户选择后立即锁定本批结果，重新计算依赖；下一轮一次性展示当时全部新解锁元素。
- 重复以上过程，直到没有等待解锁的小替换。轮数由最长真实依赖链自然决定，不设置“一轮完成”“最多两轮”等预算。
- 用户本轮选择本身就是确认，不得再增加一次“请确认刚才选择”的往返。
- 用户可以选择池内候选、原创候选、保留原内容，或提出自己的方案。
- 同批项目使用清晰编号，允许用户一次回复多个选择；例如“场景2、身份1、损失3、破绽1”。
- 每批确认后写入工作文档，记录已锁定项目、仍等待的依赖和下一批新解锁项目；后续组合不得擅自更换。

## 阶段6：组合与最终骨架

1. 汇总用户已经确认的人物、大替换和小替换；不得重新创造未确认选项。
2. 给出3套差异明显的组合方案，重点比较节奏、衔接、反转和结尾组织。
3. 用户确认组合后生成完整定制化剧情骨架。
4. 读取 [替换验证规则](替换验证规则.md)；不通过时只修正对应问题，不得推翻其他已锁定结果。
5. 展示最终骨架并等待确认。

## 工作文档检查点

`s2-workspace.md`累计记录：当前阶段、当前批次、等待确认、替换元素依赖关系，以及已经锁定的主对标与内核、人物组合、路径依据、结构改造、小替换、组合方案和最终骨架。每次写入完整累计内容；尚未解锁的项目只记录依赖，不提前生成具体选项。

# 阶段⑤ 知识核查与时限校验 · 投标人版（Bidder v2）

> 输入：阶段④ `classified.json`（每条含 sentiment / severity / dimension / bid_impact / implicit_barrier）。
> 输出：最终 `findings.json`（在 classified 基础上追加核查结论、时限校验、投标策略汇总）。
> **定位**：纯投标人视角。本阶段的核查目标是"告诉投标人：这条变更我该怎么应对、有什么法定权利可以用"。

## 1. 红线 / 高危深度核查

对 `is_redline=true` 或 `severity=高` 的条目：

- 复核阶段④引用的 `basis_source` 是否能在 IMA `招投标实务与合规` 命中原文定位；
- 补充**具体法条名称与条文要点**（如「投标保证金不得超过项目估算价 2% — 招标投标法实施条例第二十六条」）；
- 若依据不足，回查 IMA 并补全，仍无则标注「待人工核实」。
- **对投标人追加操作指引**：标红线的条目必须附带"投标人可采取的行动路径"（异议→质疑→投诉的三级递进策略）。

## 2. 隐性门槛复核（投标人版新增）

对阶段④标记了 `implicit_barrier=true` 的条目做二次确认：

| 检查项 | 判定标准 | 处置 |
|--------|---------|------|
| 具体化是否合理 | 新增的具体参数（金额/年限/数量/等级）是否能在技术规范中找到对应依据？ | 有依据→降为 `implicit_barrier=false`；无依据→保留 true 并在 action 中建议质疑 |
| 可达性 | 市场上是否有足够数量的潜在投标人能满足该条件？（不要求精确统计，仅凭常识判断） | 极少数人能满足 → 提高风险等级并建议联合投标或提出质疑 |
| 与履约相关性 | 该条件是否直接关联项目交付质量/安全/运维能力？ | 明显无关 → 升级为 `is_redline=true`（排斥潜在投标人） |

## 3. 15 日时限校验 + 投标人权利清单

### 3.1 顺延权
- **触发条件**：变更内容「可能影响投标文件编制」且距投标截止时间 < 15 日。与 dimension 无关。
- **处置**：标注 `timeliness_warning=true`，结论为「依法你有权要求顺延投标截止时间」。
- **依据**：87 号令第二十七条 / 招标投标法实施条例第二十一条。
- **投标人行动**：
  1. 立即书面致函招标人要求确认新的截止时间
  2. 若未获正式答复，按原截止时间准备的同时预留申诉通道
  3. 保留要求顺延的证据（邮件回执、公告截图）

### 3.2 质疑权窗口
- 对任何疑似违规条款（is_redline=true 或 implicit_barrier=true），标注 `objection_eligible: true`
- 质疑期通常为**投标截止前**（具体以招标文件载明为准）
- 行动建议中包含："若决定质疑，应在 XX 前提交书面质疑"

### 3.3 异议期备忘
- 若变更涉及评分办法或实质性响应条款，提示投标人：「该变更可能影响已编制的投标文件内容，建议重新检查相关章节」

## 4. 法定阈值速查表（阶段④/⑤共用）

| 受控项 | 法定阈值 | 突破后果 | 投标人权利 | 依据（以 IMA 实际检索为准） |
|--------|----------|----------|-----------|--------------------------|
| 投标保证金比例 | ≤ 项目估算价/采购预算的 **2%** | 超即红线 | 要求调至2%内；不调可投诉 | 实施条例第二十六条；87号令第三十三条 |
| 招标文件发售期 | ≥ **5 日** | 偏短→风险 | 要求延长发售期 | 实施条例第十六条 |
| 发售至投标截止 | ≥ **20 日**（依法必须招标） | 偏短→风险 | 要求延长 | 招投标法第二十四条 |
| 澄清/修改距截止 | < **15 日** 且影响编制 | **有权要求顺延** | 书面要求顺延截止时间 | 87号令第二十七条；实施条例第二十一条 |
| 评标委员会 | ≥ **5 人** 且**单数** | 违反→红线 | 评标结果可挑战 | 招投标法第三十七条 |
| 中标候选人公示 | ≥ **3 日** | 偏短→风险 | 关注公示完整性 | 实施条例第五十四条 |
| 最低投标限价 | **不得规定** | 规定即红线 | 该条款无效，可主张排除 | 实施条例第二十七条 |
| 最高投标限价 | 不得超概算/预算 | 超→风险 | 关注超概算部分是否有效 | 招投标法第三十三条等 |
| ★号实质性条款 | **不得弱化/删除** | 弱化→风险 | 要求澄清弱化的合理性 | 87号令第二十条、第五十一条 |
| 资格/业绩条件 | 须与**履约相关** | 无关→排斥(红线) | 提出质疑或投诉 | 招标法第十八条；实施条例第三十二条 |

> 上表为通用阈值速查；具体条文以 IMA「招投标实务与合规」实时检索命中为准。

## 5. 报价影响评估（投标人版新增）

对 `bid_impact="报价需调整"` 的条目，追加：

```json
{
  "pricing_note": "成本/收入项变化说明（如：电费由乙方承担改为财政拨付→可降低报价中的运营成本预留金）",
  "pricing_risk": "低|中|高",
  "pricing_action": "具体调整建议"
}
```

## 6. 输出追加字段

在每条 classified 项上追加：

```json
{
  "compliance_check": "核查结论（法条名称+要点，或 待人工核实）",
  "timeliness_warning": false,
  "objection_eligible": false,
  "final_severity": "高 | 中 | 低",
  "pricing_note": "",
  "pricing_risk": "",
  "pricing_action": ""
}
```

- `final_severity` 可较阶段④上调（`is_redline=true` 时必为「高」），但不得因低置信而虚高。
- `objection_eligible`: 当 `is_redline=true` 或 `implicit_barrier=true` 时自动为 true。
- pricing 相关字段仅在 `bid_impact="报价需调整"` 时填充。

## 7. 汇总输出（报告头部用）

除逐条 findings 外，阶段⑤还产出以下汇总信息供报告首页使用：

```json
{
  "summary": {
    "total_changes": 15,
    "sentiment_breakdown": {"利好": 5, "风险": 3, "中性": 7},
    "redline_count": 1,
    "implicit_barrier_count": 0,
    "timeliness_warning_exists": false,
    "objection_eligible_count": 1,
    "pricing_impact_exists": true,
    "bid_action_summary": [
      "需重新测算报价（电费承担方式变更）",
      "建议强化技术方案章节（技术权重上调）",
      "保证金超标—建议提交书面异议"
    ],
    "key_risks_top3": ["保证金5%超法定上限", "新增ISO认证可能构成排斥", ""]
  }
}
```

## 8. 边界

- 不做「该条款违法」的终局断言；仅给风险点、依据与**可操作的投标人行动建议**。
- 时限计算须基于用户提供的版本日期与投标截止日期；**缺日期时的标准化处理**：
  - 缺版本日期 → 标注「无法校验时限（缺少文件版本日期）」，跳过 15 日顺延校验
  - 缺投标截止日期 → 同上，跳过时限校验但保留其他分析
  - 两者都缺 → 在 summary 中加 `timeliness_data_missing: true`，报告头部提示「请补充投标截止日期以启用时限校验」
- **所有建议均以"投标人可以做什么"为核心，不评价招标人的动机或善意。**

## 9. 异常恢复

当阶段⑤输入数据（classified.json）存在以下问题时，按降级策略继续而非中断：

| 异常 | 降级策略 |
|------|---------|
| classified.json 为空（阶段④无输出） | 回退到基于 diff.json 的基础分析：仅做数值阈值比对 + 格式化差异列表，标注「影响分类因技术原因跳过，本报告为基础差异清单」 |
| 某条 item 缺少必要字段（如 dimension/bid_impact） | 用默认值填充（`dimension=其他`, `bid_impact=仅关注不需动作`），`confidence=0.3`，impact 中注明「数据不完整」 |
| IMA 检索全量超时或失败 | `basis_source` 统一标「知识库暂时不可用，待人工核实」，不因此阻断报告生成 |

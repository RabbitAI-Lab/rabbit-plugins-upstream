# 阶段③ 差异检测 · 规则与提示

> 输入：阶段②产出的两份文档结构化 JSON（A.clauses / B.clauses，含 tables）。
> 输出：`<diff.json>`，数组，每条：

```json
{
  "clause_id": "条款编号或锚点",
  "change_type": "新增 | 删除 | 修改",
  "old_text": "A 中原文（新增则为空）",
  "new_text": "B 中原文（删除则为空）",
  "numeric_delta": "旧值→新值 单位；无则空",
  "context": "定位信息（章节/页码），从源条款的 section/page 生成，用于报告回溯原文"
}
```

## 1. 条款对齐（默认「内容相似度对齐」）

> ⚠️ **关键陷阱（踩过坑）**：招标文档常出现「一章内多台设备各自 1/2/3 编号」的结构，提取器产出的浅层 ID（如 `七.5`、`五.2`）会把**不同设备的同号条款**混为同一 ID。若按 ID 对齐，会产生大面积假阳性——同 ID 下 A、B 内容完全不同（实测 79 条"修改"中 68 条为假）。因此 **默认使用内容相似度对齐，ID 仅作辅助兜底**。

- 运行 `scripts/align_clauses.py`（已内置下列逻辑，无需手算）产出 `<diff.json>`：
  1. **精确匹配**：去空白后文本完全一致 → 视为未变更，跳过；
  2. **贪心相似度匹配**：剩余项用「字符二元组 Jaccard 相似度」取最佳匹配；
     - 相似度 ≥ `0.95` → 视为未变更，跳过；
     - `0.50` ≤ 相似度 < `0.95` → 记为「修改」；
  3. **低于 `0.50` 无匹配** → A 项记「删除」、B 项记「新增」。
- 每条 diff **必须原样带上源条款的 `context`**（章节标题 + 页码，若可知），这是报告定位原文的可靠锚点（`clause_id` 在多设备文档下不可靠，勿单独依赖）。
- 表格行已在提取阶段按「表序号 + 行」并入 `clauses`，故表格重排/增删行自动走上述相似度对齐，无需单独实现单元格 diff。
- 仅在相似度无法区分（如大量重复模板句）时，参考 ID 辅助判断。

## 2. 差异判定

- **修改**：同一条款新旧文本不同（忽略纯标点、全角/半角、换行、空白差异）。
- **新增**：B 有、A 无。
- **删除**：A 有、B 无。

## 3. 数值专项

对含数值的条款，单独抽取并结构化：

- 受控对象：投标保证金（比例/金额）、工期（日历天）、评分权重（%）、业绩要求（金额/数量/年限）、资质等级、最高限价、投标截止时间/日期。
- 输出 `numeric_delta`（旧值→新值 + 单位）。此字段是阶段④/⑤法定阈值比对的关键输入，具体阈值见 `stage5_review.md`「法定阈值速查表」。

## 4. 抗噪声规则（降低误报）

以下差异**不**计入 diff，或标记为「中性-格式」后过滤：

- 仅页码、页眉页脚、目录变动；
- 仅标点、空格、换行、全半角差异；
- 仅「投标人」「招标人」称谓统一化等无实质影响修订。

## 5. 自检

- 召回：拿一份已知改动 N 处的补遗，应能找出全部 N 处。
- 误报：未实质变更的条款不得进入 diff。

## 6. 数值专项少样本（正例）

> 以下演示 `numeric_delta` 抽取与「修改」判定。注意：仅当数值本身属于受控项（保证金/工期/权重/业绩/资质/限价/截止时间）时才进入专项；纯序号、型号、计量单位变化按「修改」普通处理。

**示例 A — 保证金比例变更（应进专项）**
```
old_text: 投标保证金为项目估算价的 2%
new_text: 投标保证金为项目估算价的 5%
=> change_type=修改, numeric_delta="2% → 5%"
```
**示例 B — 交货期变更（应进专项）**
```
old_text: 交货期：合同签订后 60 日历天
new_text: 交货期：合同签订后 90 日历天
=> change_type=修改, numeric_delta="60 日历天 → 90 日历天"
```
**示例 C — 型号变化（普通修改，不进专项）**
```
old_text: 配置 希捷 4T 企业盘 ×8
new_text: 配置 西部数据 4T 企业盘 ×8
=> change_type=修改, numeric_delta=""（型号非受控项，仅记文本变更）
```

## 7. 反例少样本（不计入 diff / 标记中性-格式）

> 以下情形**不得**生成独立 diff 条目，或在进入阶段④前过滤为「中性-格式」，避免污染影响评估。

**反例 1 — 仅标点/全半角**
```
old_text: 投标人，应具备独立法人资格。
new_text: 投标人应具备独立法人资格。
=> 忽略（相似度对齐已归并；若仍命中，标记中性-格式）
```
**反例 2 — 仅称谓统一化**
```
old_text: 贵公司须于开标前递交。
new_text: 投标人须于开标前递交。
=> 忽略（无实质影响）
```
**反例 3 — 仅页码/页眉页脚/目录**
```
old_text: （第 12 页）第三章 评标办法
new_text: （第 13 页）第三章 评标办法
=> 忽略（定位信息变化，正文未变）
```
**反例 4 — 纯打字纠错（非受控项）**
```
old_text: 项目总投姿 500 万元
new_text: 项目总投资 500 万元
=> 忽略（错别字修正，无实质商务/技术影响）
```

# 编辑处置策略

本文件把模式命中转化为可判定的编辑动作。它不替代 `fidelity-audit.md`；发生冲突时，以核心安全规则、保真审计和高敏感扫雷为准。

## 四道门

每一处候选编辑按顺序通过以下门控；任一门失败即不改写，并说明原因。

### 1. 编辑资格门

命中模式后，必须满足模式簇阈值、严重单点问题或用户明确指定处理。短文本按 `thresholds.md` 的全文窗口统计，不因篇幅短而豁免。

### 2. 证据锚点门

改写前登记并改写后逐项核对：主体、动作、对象、结果、条件、范围、情态、归因，以及数字、时间和专名。任何锚点新增、丢失、强度变化或归属变化均为 FAIL，回退原文。

### 3. 最小编辑门

只改承担问题的词、短语或连接结构。默认不增加句子数；无明确的结构收益或用户明确要求时，不整句重写；无明确理由时不改变超过一个核心谓词。需要补充事实、比较基准、来源、数据或背景时，转为 `review_only`，不得用改写补足。

### 4. 人类可复核门

每项输出必须包含逐处 diff、处置类型、`benefit_test`、锚点来源和审计结果。用户可接受、回退或保留原文；用户未确认时不得写回源文件。

## 处置类型

| 类型 | 含义 | 输出要求 |
|---|---|---|
| `rewrite` | 可在证据守恒范围内直接给出候选改写 | 逐处 diff + benefit_test + 锚点 + 保真审计 |
| `conditional` | 只有指定前提已由原文满足时才可改写 | 未满足时列“未处理信号”，写明缺失前提 |
| `review_only` | 风险属于证据、事实、敏感语境或用户意图问题，不做自动改写 | 标注位置、原因和编辑备注；不提供补造性替换 |

默认分类：TIC-2 的重复元评论、聊天机器人痕迹、无信息收束属于 `rewrite`；四字格堆叠、重要性判断、真实否定式对比、三项并列属于 `conditional`；比较基准缺失、来源不明、数据口径缺失、高敏感扫雷属于 `review_only`。

书面禁忌扫雷档位与处置类型的映射为：`auto_suggest` 仅在删除或压缩后仍保留完整原文信息时进入 `conditional`；若需要补证、删除会留下残句或存在强度/事实判断风险，则转为 `review_only`。`error`、`warn` 与 `high_sensitive` 一律为 `review_only`；其中 `error` 是私有规则可用的“禁用或必须复核”档位，公共映射库当前不使用。扫雷档位保留在输出中，不能被处置类型覆盖。

## benefit_test

候选改写至少通过以下一项，且不能以损失锚点为代价：

- `remove_filler`：删除不承载独立事实、范围、情态、因果或行动的信息。
- `compress_duplication`：合并语义等价的重复表达，保留所有独立主张。
- `direct_order`：恢复更直接的语序，同时保留主体、情态和推断层级。
- `remove_template`：去除阻碍理解的模板化框架，剩余句子仍完整。
- `known_audience_fit`：已知场景下的格式或语气更适配，且不改变主张强度。

不属于以上收益的改动为 `NO-OP`。仅改标点、空格、排版、语序微调，或只以近义词替换而没有可解释收益，均为 `NO-OP`，必须回退原文。`review_only` 不进入 benefit_test，也不计为 NO-OP 回退；两者都计入未处理信号，但只对实际生成后回退的候选改写计入无效改写回退数。

## 最小编辑预算

默认预算适用于单句；用户明确要求整段重写时仍必须逐句通过锚点和 benefit_test。

| 操作 | 默认限制 |
|---|---|
| 删除 | 仅删除无信息成分；不得删除限定词、范围、反例或真实对比项 |
| 压缩 | 仅合并重复主张；每个独立动作、数字、条件与结果必须保留 |
| 换句式 | 不新增句子；不改变超过一个核心谓词；不补施事或因果 |
| 重排 | 仅调整已有成分顺序；不得把推断改成事实或改变归因 |

## 输出示例

```text
[1｜TIC-2｜rewrite] 值得注意的是，值得注意的是，值得注意的是，试点可能在部分门店推广。 → 试点可能在部分门店推广。｜benefit_test=remove_filler｜锚点：试点/部分门店/可能｜保真审计：PASS

未处理信号：
[模式12｜review_only] 更高效｜缺少比较基准，不能删除“更”或补造基准｜编辑备注：请说明相对什么更高效。
```

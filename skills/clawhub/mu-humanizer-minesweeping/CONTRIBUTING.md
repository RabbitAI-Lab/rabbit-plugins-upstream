# Contributing

Thank you for improving Mu Humanizer Minesweeping.

## Before proposing a change

Please keep the project’s safety model intact. Changes must not introduce AI-detection evasion claims, invented facts during editing, automatic substitution for high-sensitivity wording, bundled private rules, credentials, or organization-specific policy.

## Rule changes

For changes to a writing pattern or risk-mapping rule, include a minimal before-and-after example, the evidence that must remain unchanged, the intended disposition (`rewrite`, `conditional`, or `review_only`), and the expected behavior when the rule lacks enough context.

High-sensitivity categories must remain review-only. Do not add fixed replacement tables for identity, legal, policy, sovereignty, ethnic, religious, or international-relations wording.

## Pull requests

Keep changes focused. Update the main instruction file, the relevant reference file, and both READMEs when behavior changes. Confirm all linked references exist and scan the final contribution for personal data, credentials, private URLs, and local rule files.

## Security and privacy reports

Do not disclose credentials, personal data, private rules, or sensitive text in public issues. Use the repository’s security-reporting channel once it is configured.

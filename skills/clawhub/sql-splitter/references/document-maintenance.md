# sql-splitter 文档维护规范

## 当删除功能时的完整清理清单

删除代码文件后，必须检查以下位置是否还有引用，遗漏任一位置会导致文档与代码不一致：

1. **SKILL.md 正文** — 功能描述、使用方法章节
2. **SKILL.md changelog** — 更新日志中的版本条目
3. **文件结构章节** — `## 文件结构` 下的目录树
4. **references/ 目录** — 相关参考文档（产品化/商业化规划等）
5. **测试文件** — test_*.py 中的 import 和测试用例
6. **其他 .py 文件的 import** — 主代码中的引用

**检查命令**：
```bash
grep -rn '已删除文件名' SKILL.md scripts/ references/
```

## SKILL.md 重复条目积累问题

SKILL.md 的 changelog 在顶部追加新版本，但功能描述区在底部也有同名条目。随着版本迭代，同一功能（如 `dbo替换规则`、`用户规则验证通过`）会出现多次重复。

**预防措施**：
- 每次新增版本后，用 `grep -cn 'dbo替换规则' SKILL.md` 检查关键条目出现次数
- 功能描述区只保留最新版的描述，旧版描述移到 changelog
- 发布前必须清理重复条目

## 更新日志排序规范

- 功能描述按版本倒序排列：最新版本在最前，旧版本在后
- 更新日志必须严格按版本号降序排列
- **每次新增版本后**，用 `grep '^### v' SKILL.md` 检查排序是否正确
- 避免重复章节：同一功能只在一个版本章节下详细描述，其他地方引用即可
- 标题中的版本号必须与 clawhub 发布版本一致
- 更新日志保留完整历史，但主体部分只展开最新版和次新版

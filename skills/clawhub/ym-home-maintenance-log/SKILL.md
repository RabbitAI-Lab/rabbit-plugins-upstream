# 家庭设备维护台账 (ym-home-maintenance-log)

记下型号与购买日期，自动推算保修到期和下次保养时间，并按「30 天内 / 90 天内 / 已逾期」三档提醒该做什么、凭证该留哪些。不是帮你修设备，是帮你别错过保养和保修。

## 何时使用

- 用户说「记一下这个设备」「建个设备台账」「家电记录一下」时
- 用户问「空调该洗了吗」「什么时候该保养」「净水器滤芯多久换」时
- 用户问「保修到什么时候」「这个还保吗」「保修期到几号」时
- 用户说「帮我列一下近期要保养的东西」「下个月有哪些设备要弄」时

## 运行前提

- 依赖：无第三方依赖，纯文本处理
- 不联网、不上传，不在本环境外发送任何提醒
- 不读取任何本地文件，除非用户明确给出文件路径

## 输入契约

| 项 | 必需 | 说明 |
|---|---|---|
| 设备名称 | 必需 | 至少说明品类（如空调、油烟机）；有品牌型号更好 |
| 购买日期 | 可选 | 推算保修与保养的基准；缺则按「预计购买时间」并标注不确定 |
| 保修期 | 可选 | 如「整机 1 年，压缩机 3 年」；缺则取该品类默认值并标注为默认值 |
| 品牌型号 / 位置 / 价格 / 凭证是否留存 / 使用频率 | 可选 | 用于台账完整度与提醒精度 |

**缺失处理：**

- 缺购买日期 → 用「预计购买时间」并标注「不确定」，保养与保修提醒给范围而非精确日期（如「约在 X 月前后」）
- 缺保修期 → 按该品类常见保修年限给默认值，明确标注「默认值，以凭证与官网为准」
- 只说品类无细节 → 先建条目，列出需补齐的信息清单（见输出第五段）
- 用户主动询问「今天/本周该做啥」 → 基于已存台账输出三档提醒，缺台账先引导建条目

## 执行步骤

1. **建条目** — 为每个设备生成台账字段：设备名 / 位置 / 品牌型号 / 购买日期 / 价格 / 保修到期 / 保养周期 / 上次保养 / 下次应保养 / 凭证是否留存。字段缺的留空并计入待补齐清单。

2. **推保修到期** — 保修到期 = 购买日期 + 保修年限。有「整机/主要部件」分别保的，分别算两列。已过期（到期日 < 今天）明确标「已过保」。今日日期以用户对话中的上下文为准；用户未给则按「当前日期」处理并注明。

3. **推下次保养** — 按品类周期算下次应保养日（周期表见 `references/maintenance-cycle-table.md`）。有「上次保养」则 上次 + 周期；无则以「购买日期或入住日期 + 周期」估算并标注「首次保养估算」。所有周期后附「以说明书为准」。

4. **分三档出提醒** — 对比今天与各项日期，分成：未来 30 天内待做 / 未来 90 天内待做 / 已逾期（超过下次应保养日）。逾期项排最前并标「已过期 X 天」。

5. **出凭证清单** — 列出该留的发票、保修卡、安装单、延保凭证，并给拍照命名规则（如 `空调_客厅_品牌型号_购买日.jpg`）。

6. **判自做 vs 找人** — 对照 `references/maintenance-cycle-table.md` 的判定表：涉及燃气、电路、制冷剂、拆机、高空的一律标「需专业人员」，不给任何自行拆机步骤；可自做的给操作要点（如滤网冲洗、滤芯更换），不超出外部可触及范围。

7. **硬约束自检** — 凡涉及燃气/电路/制冷剂/拆机/高空，输出里只能出现「联系专业人员」，不得出现拆机、通电检测、放冷媒等步骤；保修结论后必须带「以购买凭证与官方政策为准」。

## 输出格式

Markdown，套用 `templates/ledger-template.md`：

```
一、设备台账表（每行一台：名称/位置/型号/购买日/保修到期/保养周期/上次保养/下次应保养/凭证）
二、近期提醒
  - 已逾期：……
  - 未来 30 天内：……
  - 未来 90 天内：……
三、凭证留存清单与命名规则
四、可自做 vs 需专业人员（逐项标注，专业人员项不附步骤）
五、待补齐信息（缺的字段与日期）
```

## 能力边界

- 不自动发送提醒（本环境外不发消息、不联网查询）；只在用户主动询问时输出当期提醒
- 不查询官方保修状态与政策（无法联网核对品牌官网/客服）
- 不给出任何拆机、通电检测、放冷媒、登高作业的具体步骤
- 不提供维修价格参考（地区与师傅报价差异大）
- 不替用户判断「该修还是该换」，只列事实与节点

## 常见坑

1. **把默认值当确定值** — 现象：缺保修期时直接写「保到 2027 年」让用户信以为真。原因：把品类默认值当成了用户实际凭证。规避：凡是默认值、预计日期一律标「默认值/预计，以凭证为准」。
2. **给拆机步骤** — 现象：用户问「燃气热水器怎么洗」，顺手写出拆燃烧器步骤。原因：把「保养」理解成要教操作。规避：凡涉及燃气/电路/制冷剂/拆机/高空，只输出「联系专业人员」，绝不写步骤。
3. **逾期项不排序** — 现象：三档里把 30 天内和已逾期混着列。原因：没按紧急度分桶。规避：先列已逾期并标过期天数，再 30 天、90 天。
4. **保养周期写死** — 现象：写「空调滤网每 3 个月必洗」当作铁律。原因：忽略使用频率与环境差异。规避：周期后必附「以说明书与实际使用频率为准」，高频/多尘环境给缩短建议但不下绝对结论。
5. **保修叠加算错** — 现象：整机 1 年、压缩机 3 年，只写一个「保 3 年」。原因：没分部件列。规避：有分部件保修的，逐列标到期，让用户知道压缩机还保。
6. **凭证只说「留好发票」** — 现象：泛泛一句。原因：没具体到哪些凭证、怎么存。规避：列出发票/保修卡/安装单/延保四类，并给命名规则便于检索。

## 验收用例

- 正常：录入 5 台设备且都含购买日期 → 台账 + 三档提醒齐全，保修逐项标注
- 边界 1：只给「空调」无日期 → 建条目并列出待补信息，提醒给范围而非精确日
- 边界 2：燃气热水器保养 → 明确「需联系专业人员」，不给拆机步骤
- 失败：要求查某品牌官方保修状态 → 说明无法联网查询，给官方查询渠道建议，不出结论

## 目录说明

- `references/` — 各品类保养周期表、可自做 vs 需专业人员判定表（按需加载）
- `templates/` — 台账与提醒输出模板
- `devices/` — 可选存放台账（Markdown 表格或 JSON，由用户选择），支持后续追加与更新；不强制

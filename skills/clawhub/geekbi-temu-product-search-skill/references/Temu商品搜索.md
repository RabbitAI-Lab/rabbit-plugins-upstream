# Temu 商品搜索

## 工作原则

- 只通过文档明确的极鲸云查询接口获取业务数据。
- 将“接口返回的事实”“基于事实计算的指标”“分析判断”明确区分。
- 在结论中保留站点、时间范围、筛选条件、样本量、分页范围和数据更新时间。
- 对缺失值、估算值、异常值和样本偏差作显式说明，不用缺失数据支撑强结论。
- 商品库存为 `0` 时按“可能未统计到，需进一步核实”处理，不直接认定为真实零库存、缺货或售罄，也不使用该值支撑库存风险判断；面向用户展示时必须附上这一备注。
- 默认使用简体中文输出，日期使用绝对日期。供货价一律按人民币解释，商品价格按当前 Temu 站点的币种解释，展示金额时必须标明币种。比较商品价格与供货价或计算价差、毛利、利润时，必须先换算为同一币种并说明汇率口径；未完成换算时不得直接相减。
- 将接口参数名、响应字段名、请求命令、查询字符串和原始 JSON 仅用于内部调用。执行过程中的进度说明、分析过程和最终答复都必须改用用户能理解的中文业务名称，不直接展示 `siteId`、`monthSold`、`catIds`、`pageSize` 等英文标识。例如写“查询美国站、按近 30 天销量从高到低排列”，不要写“`siteId=48`、`sort=monthSold,desc`”。调用脚本前也不要向用户复述完整命令或原始参数。只有用户明确要求接口文档、开发对接、故障排查或原始响应时，才可展示必要的英文标识，并在首次出现处紧跟中文解释。
- 先运行查询脚本；服务端要求暂停查询时，按统一流程提示并等待，取得真实数据后再分析。

## 执行流程

1. 识别用户要解决的是寻找商品、筛选候选、比较商品表现，还是判断选品机会。
2. 明确必要口径：目标站点、时间范围、类目或关键词、价格带及其他硬性条件。用户未指定且不会显著改变结论时，采用合理默认值并在结果中注明。
3. 选择最能回答当前问题的一组商品条件，先完成最短的端到端查询，再按结果逐步收窄或放宽条件。
4. 发起商品搜索前读取 [Temu 商品搜索接口](Temu商品搜索接口.md)。未指定站点或明确要求美国站时直接使用美国站默认值；只有用户指定其他国家或地区时，才运行 `scripts/temu_site_list.py` 实时解析站点。用户提到热销、日销排行、新品、蓝海、新店、大卖或其他商品榜单意图时，再读取 [Temu 商品榜单查询预设](Temu商品榜单预设.md) 生成筛选与排序参数。
5. 检查响应是否成功。查询失败时，只向用户提示服务端响应一级 `msg` 的中文文案，不展示错误响应、状态码、异常栈或底层字段；服务端未提供有效 `msg` 时再使用脚本生成的中文错误文案。
6. 服务端要求暂停查询时，按 [查询暂停与恢复流程](查询暂停与恢复流程.md) 展示提示，有跳转地址时再展示可点击链接；恢复条件满足后重新运行原查询，取得商品数据后再分析。
7. 检查时间口径是否一致、分页是否完整、关键字段是否缺失，并保留请求条件与数据更新时间。
8. 围绕用户问题计算必要指标、交叉验证证据并形成结论，不堆砌无关数据。
9. 按“输出要求”交付结果；若商品数据不足，明确当前能确认什么、不能确认什么，以及下一轮商品查询需要调整什么。

## 适用范围

使用商品搜索查找潜力商品、查看商品榜单、筛选候选商品、分析商品表现或比较同类商品。重点观察销量及增长、价格与供货价、评分与评论规模、同款数、上架时间、店铺和类目信息。仅用当前商品结果无法验证消费者痛点、具体规格或供应链能力时，明确标注为待核验事项，不用推测补全。

商品搜索使用 `scripts/temu_goods_search.py`。未指定站点时使用 `48`（美国）并在数据口径中说明，不请求站点列表；用户指定其他国家或地区时，先使用 `scripts/temu_site_list.py --country "国家或地区名"` 实时查询，只有唯一精确匹配时才将返回的站点 ID 交给商品搜索。无匹配时提示用户确认国家或地区名，多个匹配时先请用户澄清，不猜测站点。用户表达榜单意图时选择一个查询预设作为起点，再用用户明确提出的条件覆盖对应参数；不要无依据叠加多个预设。商品意图默认在 `keyword` 与 `catIds` 中二选一：只有用户提供或当前上下文已有可信的一级或二级类目 ID 时才使用 `catIds`，否则直接使用简洁的 `keyword`。不要猜测类目 ID，也不要为了获得类目 ID 依赖其他 Skill。只有用户明确要求交叉筛选时才同时传 `keyword` 和 `catIds`，并说明组合条件可能显著减少结果。关键词统一使用接口内置的模糊搜索。服务端会为每个商品返回 `linkUrl`，指向该商品在极鲸云的 Temu 商品详情页。每个被展示的商品都必须把商品标题写成 `[商品标题](<linkUrl>)`；这条规则适用于表格、列表、排名、候选清单和正文，不因用户未主动要求链接或要求简洁结果而省略。不要在脚本或回答中根据商品 ID、站点 ID 自行拼接、猜测或补全链接。

## 分析方法

### 选品

至少从需求、增长、竞争、价格与供货价空间、口碑信号和经营风险六个维度评估候选商品。不要仅凭销量高或评论多判定值得进入。优先给出候选清单、入选原因、淘汰原因和验证动作。

商品搜索选品时，必须按 [Temu 商品搜索接口](Temu商品搜索接口.md) 中的“同款数（跟卖数）评估口径”判断竞争程度与核价风险；不要把销量高但同款数过高的商品直接列为低风险机会。

### 数据分析

优先使用可复算的同比、环比、占比、集中度、价格分位和异常变化。比较不同对象时统一站点、时间窗、币种和筛选条件；口径不一致时停止横向排名并说明原因。

### 市场调研

先定义市场边界，再回答当前商品样本的规模、趋势、竞争格局和进入机会。将单一搜索结果视为样本，不直接外推为全市场；至少组合销量或销售额、增长、价格、同款数、评分、上架时间中的两类独立信号，无法交叉验证时降低置信度。

## 输出要求

商品表格或清单的名称列必须使用 `[商品标题](<linkUrl>)`。发送答复前逐行检查：服务端返回非空 `linkUrl` 的每个商品都必须存在对应的可点击商品标题，缺少任何一个都先修复再交付。

用户只索要商品链接时，仅返回 `[商品标题](<linkUrl>)`，不附加接口、字段、链接类型或缺失状态说明。

默认按以下顺序输出：

1. 一句话结论：是否值得关注、进入或继续验证。
2. 数据口径：站点、时间范围、查询条件、样本量和更新时间。
3. 关键发现：只列与决策直接相关的数据和变化。
4. 机会与风险：说明证据、限制和置信度。
5. 行动建议：给出可执行的下一步、优先级和验证门槛。

如果用户只要求原始搜索结果，保持简洁，不强行扩展为完整市场报告。

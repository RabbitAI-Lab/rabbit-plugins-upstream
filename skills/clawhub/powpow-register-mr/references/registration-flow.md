# नोंदणी प्रवाह तपशील — powpow-register

त्रुटी निवारणासाठी पहा. सर्व नियम प्लॅटफॉर्म स्रोत कोडमधून आहेत (Next.js फ्रंट-बॅक एंड सुसंगतता तपासणी), स्रोत नमूद केलेले. प्लॅटफॉर्म अपडेट असताना प्रत्यक्ष ऑनलाइन वर्तनावर अवलंबून.

## प्रवेश

- नोंदणी पृष्ठ: https://global.powpow.online/register
- लॉगिन पृष्ठ: https://global.powpow.online/login
- सदस्यता पृष्ठ: https://global.powpow.online/subscription
- जर शेअर लिंक इ. `?next=...` सह आले असेल, नोंदणी+पेमेंट झाल्यावर आपोआप मूळ पृष्ठावर परत जाईल.

## फॉर्म फील्ड व नियम

| फील्ड | आवश्यक | नियम | स्रोत |
|---|---|---|---|
| प्रोफाइल छायाचित्र | पर्यायी | प्रतिमा ≤5MB, SVG समर्थित नाही; सर्व्हर आपोआप कॉम्प्रेस (100KB पेक्षा जास्त असल्यास 400×400 / quality 90) | `src/app/api/auth/register/route.ts` |
| वापरकर्तानाव | आवश्यक | 2~50 अक्षरे, trim नंतर **लहान** अक्षरात साठवले (Tom व tom समान वापरकर्तानाव, नोंदणी व लॉगिन दोन्ही केस-इनसेन्सिटिव्ह) | तेच (zod schema) |
| पासवर्ड | आवश्यक | 8~100 लांबी, मोठी अक्षरे, लहान अक्षरे, अंक तीनही असावीत | तेच |
| पासवर्ड पडताळा | आवश्यक | पासवर्डशी जुळते (फक्त फ्रंट-एंड तपासणी) | `src/app/(public)/register/page.tsx` |
| टोपणनाव | पर्यायी | ≤100 अक्षरे; रिकामे असल्यास डीफॉल्ट वापरकर्तानाव | register route |
| ईमेल | **आवश्यक** | वैध ईमेल स्वरूप, ≤255 अक्षरे; एक ईमेल एकाच खात्यासाठी | register route |
| ईमेल संकेतांक | **आवश्यक** | 6-अंकी; **10 मिनिट वैध**; यशस्वी पडताळल्यावर रद्द; पुन्हा पाठवल्यास जुना कोड "वापरलेला" म्हणून चिन्हांकित | `src/lib/email-verification.ts` |
| फोन क्रमांक | पर्यायी | मुख्यभूमी फोन `1[3-9]` सुरू 11 अंकी; एक फोन एकाच खात्यासाठी | register route |

पृष्ठावर तीन तृतीय-पक्ष लॉगिन बटणेही आहेत: **Google, Watcha, Huawei** (`GoogleSignInButton` /
`WatchaLoginButton` / `HuaweiLoginButton`). तृतीय-पक्ष खात्यांचा स्थानिक पासवर्ड नसतो, नंतर पासवर्ड लॉगिन केल्यास
`该账号未设置密码，请使用其他方式登录` मिळेल.

## रेट-लिमिट व ब्रूट-फोर्स पॅरामीटर्स

| क्रिया | मर्यादा | स्रोत |
|---|---|---|
| नोंदणी सबमिट | **3 वेळा/मिनिट/IP**, पलीकडे 429 | `src/lib/rate-limit.ts` `REGISTER_RATE_LIMIT` |
| संकेतांक पाठवा | समान IP 1 वेळ/मिनिट **आणि** समान ईमेल 1 वेळ/मिनिट, पलीकडे 429; फ्रंट-एंड बटण 60 सेकंद काउंटडाउन | `src/app/api/auth/register/send-code/route.ts` |
| संकेतांक पडताळणी | प्रत्येक ईमेल 10 मिनिटांत जास्तीत जास्त **5** प्रयत्न, मर्यादा गाठल्यास कोड बरोबर असला तरी नाकारला, नवीन कोड पाठवावा लागतो | `src/lib/email-verification.ts` |
| पासवर्ड विसरलात पाठवा | 1 वेळ/मिनिट/IP | `src/app/api/auth/forgot-password/route.ts` |
| लॉगिन | 5 वेळा/मिनिट/IP; समान खाते सलग **5** वेळा अयशस्वी झाल्यास **30 मिनिट लॉक** (423), यावेळी उर्वरित संधी कमी होत जाते | `src/app/api/auth/login/route.ts`, `rate-limit.ts` |

**गोपनीयता वर्तन**: संकेतांक पाठवा / पासवर्ड विसरलात यावेळी, ईमेल आधीच नोंदलेले किंवा अस्तित्वात नसल्यास, इंटरफेस समान यशस्वी संदेश परत करते, ईमेल नोंदलेले आहे का ते लीक करत नाही.

## एजंट-सहाय्यित मोड व वेब नोंदणीची समता

स्किल स्क्रिप्ट तेच **सार्वजनिक API** (`/api/auth/register`, `send-code`, `login`,
`/api/auth/me`) कॉल करते, नोंदणी पृष्ठाच्या फॉर्म सबमिशनप्रमाणेच तेच तपासणी, रेट-लिमिट व त्रुटी मार्ग — या फाइलमधील
सर्व नियम दोन्ही मोडसाठी समान. स्क्रिप्ट कालक्रम व कमांड करार पहा `references/agent-flow.md`.

## नोंदणी यशानंतरची स्थिती प्रवास

1. वापरकर्ता `accountStatus: 'pending'` ने सेव्ह, प्रारंभिक **3 बॅजेस** (register route).
2. सर्व्हर एकाच वेळी दोन HttpOnly कुकीज सेट करतो: JWT (थेट `/subscription` प्रवेश) व
   pendingUserToken (सदस्यता प्रवाह ओळख).
3. नोंदणी पृष्ठ `pending_payment` शोधते → `/subscription` ला रीडायरेक्ट (सुरक्षित `next` परत-पॅरामिटर);
   एजंट-सहाय्यित मोडमध्ये `me?token=…&redirect=/subscription` समान परिणाम.
4. पेमेंट पूर्ण → `accountStatus` `active` होते (**Alipay notify द्वारे सर्व्हर-साइड आपोआप सक्रिय**;
   PayPal Webhook द्वारे आपोआप; WeChat क्यूआर मॅन्युअल पडताळणी; Huawei IAP `activate-huawei` द्वारे).
   अधिक तपशील `payment-and-activation.md`.

सक्रिय नसलेले (pending) वापरकर्ते मुख्य API (फीड, नकाशा, डिजिटल व्यक्ती संवाद, चेक-इन इ.) कॉल केल्यास 403; शेअर पोस्ट लिंक वगळता (सार्वजनिक प्रवेशीय).

## सामान्य त्रुटी निवारण सारणी

| घटना | कारण | काय करावे |
|---|---|---|
| `用户名已存在` | वापरकर्तानाव व्याप्त (केस-इनसेन्सिटिव्ह) | दुसरे वापरकर्तानाव |
| `邮箱已被使用` | ईमेल आधीच नोंदलेले | ईमेल बदला; किंवा लॉगिन + `忘记密码` मार्गाने जुने खाते पुनर्प्राप्त |
| `邮箱验证码错误或已过期` | कोड चुकीचा / 10 मिनिटांहून अधिक / 5 पेक्षा जास्त चुकीचे प्रयत्न नाकारले | `重新发送` क्लिक करा, **नवीनतम** ईमेलचा संकेतांक वापरा |
| संकेतांक येत नाही | 60 सेकंद रेट-लिमिट; किंवा स्पॅम/जाहिरात फोल्डरमध्ये | काउंटडाउन संपेपर्यंत थांबा मग पाठवा; स्पॅम फोल्डर तपासा |
| `手机号已被使用` | फोन क्रमांक दुसऱ्या खात्याला बांधलेला | फोन क्रमांक काढा (पर्यायी) किंवा बदला |
| `注册请求过于频繁` / 429 | नोंदणी 3 वेळा/मिनिट/IP मर्यादा गाठली | काही मिनिटे थांबा मग प्रयत्न |
| 409 `用户名或邮箱已被注册` | सबमिट क्षणी इतरासोबत नाव टक्कर (कोन्करन्सी फॉलबॅक) | वापरकर्तानाव किंवा ईमेल बदलून पुन्हा |
| `图片大小不能超过5MB` / `不支持 SVG` | प्रोफाइल अनुपयुक्त | प्रतिमा बदला किंवा वगळा |
| नोंदणी यशस्वी पण लॉगिन 403 `请完成订阅以激活账户` | खाते अजूनही pending (पेमेंटपूर्वी अपेक्षित स्थिती) | पेमेंटपूर्वी: सामान्य, आधी सदस्यता पूर्ण करा; पेमेंटनंतरही 403: जुना JWT वापरला, स्क्रिप्ट मोडमध्ये आधी `refresh-login` नवीन लॉगिन स्थिती |
| लॉगिन 423 `账户已锁定` | पासवर्ड 5 वेळा चुकीचा | 30 मिनिटे थांबा |
| लॉगिन 401 `还剩 N 次尝试机会` | पासवर्ड चुकीचा, लॉक जवळ | विचार करून प्रयत्न, किंवा थेट `忘记密码` |
| `该账号未设置密码，请使用其他方式登录` | तृतीय-पक्ष (Google/Watcha/Huawei) खाते | मूळ तृतीय-पक्ष बटणाने लॉगिन करा |
| `该账号已注销` | खाते deactivate झाले | पुन्हा नोंदणी आवश्यक |

## लॉगिन माहिती (निवारणासाठी)

लॉगिन **वापरकर्तानाव / ईमेल / फोन क्रमांक** एकत्र इनपुट सपोर्ट करते (तीनपैकी कोणतेही खातेनाव म्हणून). पासवर्ड विसरलात: लॉगिन पृष्ठ → `忘记密码` → नोंदणी ईमेलात 6-अंकी संकेतांक → रीसेट.

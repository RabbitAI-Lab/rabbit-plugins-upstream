# नोंदणी प्रक्रियेचे तपशील — powpow-register

समस्या शोधताना पाहण्यासाठी. सर्व नियम प्लॅटफॉर्म सोर्स कोडमधून (Next.js फ्रंट-एंड/बॅक-एंड सर्वसम्मत व्हॅलिडेशन) घेतलेले आहेत,
स्रोत नमूद केला आहे.
प्लॅटफॉर्म अपडेट झाल्यास ऑनलाइन प्रत्यक्ष वर्तनच लागू होईल.

## प्रवेशद्वार

- नोंदणी पेज: https://global.powpow.online/register
- लॉगिन पेज: https://global.powpow.online/login
- सबस्क्रिप्शन पेज: https://global.powpow.online/subscription
- शेअर लिंक इत्यादीतून `?next=...` घेऊन आल्यास, नोंदणी + पेमेंट पूर्ण होताच आपोआप मूळ पेजवर परत जाईल.

## फॉर्म फील्ड आणि नियम

| फील्ड | आवश्यकता | नियम | स्रोत |
|---|---|---|---|
| प्रोफाइल फोटो | ऐच्छिक | इमेज ≤5MB, SVG सपोर्ट नाही; सर्व्हर आपोआप कॉम्प्रेस करतो (>100KB असल्यास 400×400 / गुणवत्ता 90) | `src/app/api/auth/register/route.ts` |
| यूझरनेम | आवश्यक | 2~50 अक्षरे, trim नंतर **लोअरकेसमध्ये** साठवले जाते (Tom आणि tom एकच यूझरनेम मानले जातात, नोंदणी व लॉगिन दोन्हीकडे केस-इनसेन्सिटिव्ह) | तेच (zod schema) |
| पासवर्ड | आवश्यक | 8~100 अक्षरे, त्यात मोठे अक्षर, लहान अक्षर आणि अंक तिन्ही असणे आवश्यक | तेच |
| पासवर्डची पुष्टी | आवश्यक | पासवर्डशी जुळणे आवश्यक (फक्त फ्रंट-एंड व्हॅलिडेशन) | `src/app/(public)/register/page.tsx` |
| निकनेम | ऐच्छिक | ≤100 अक्षरे; न भरल्यास डीफॉल्ट यूझरनेम | register route |
| ईमेल | **आवश्यक** | वैध ईमेल फॉरमॅट, ≤255 अक्षरे; एका ईमेलवर फक्त एकच खाते नोंदणी करता येते | register route |
| ईमेल व्हेरिफिकेशन कोड | **आवश्यक** | 6 अंक; **10 मिनिटांत वैध**; यशस्वी वापरानंतर रद्द; पुन्हा पाठवल्यास जुना कोड वापरला गेला असे चिन्हांकित होते | `src/lib/email-verification.ts` |
| मोबाईल क्रमांक | ऐच्छिक | मुख्य भूमी (चीन) चा मोबाईल क्रमांक `1[3-9]` ने सुरू, एकूण 11 अंक; एक मोबाईल क्रमांक फक्त एकाच खात्याशी जोडता येतो | register route |

पेजवर आणखी तीन थर्ड-पार्टी लॉगिन बटणे आहेत: **Google, Watcha, हुआवेई खाते** (`GoogleSignInButton` /
`WatchaLoginButton` / `HuaweiLoginButton`)। थर्ड-पार्टी खात्यात लोकल पासवर्ड नसतो, नंतर पासवर्डने लॉगिन
केल्यास «该账号未设置密码，请使用其他方式登录» (या खात्यासाठी पासवर्ड सेट केलेला नाही, कृपया इतर मार्गाने लॉगिन करा) मिळेल.

## रेट-लिमिट आणि अँटी-ब्रूट-फोर्स पॅरामीटर्स

| वर्तन | मर्यादा | स्रोत |
|---|---|---|
| नोंदणी सबमिट | **प्रति IP 3 वेळा/मिनिट**, मर्यादा ओलांडल्यास 429 | `src/lib/rate-limit.ts` `REGISTER_RATE_LIMIT` |
| व्हेरिफिकेशन कोड पाठवणे | एकाच IP वरून 1 वेळा/मिनिट **आणि** एकाच ईमेलवर 1 वेळा/मिनिट, मर्यादा ओलांडल्यास 429; फ्रंट-एंड बटणावर 60 सेकंद काउंटडाउन | `src/app/api/auth/register/send-code/route.ts` |
| व्हेरिफिकेशन कोड तपासणी | प्रत्येक ईमेलसाठी 10 मिनिटांत जास्तीत जास्त **5 वेळा** प्रयत्न, मर्यादा पोहोचल्यास बरोबर कोडही नाकारला जातो, पुन्हा कोड पाठवावा लागतो | `src/lib/email-verification.ts` |
| पासवर्ड विसरल्यास कोड पाठवणे | 1 वेळा/मिनिट/IP | `src/app/api/auth/forgot-password/route.ts` |
| लॉगिन | 5 वेळा/मिनिट/IP; एकाच खात्यावर सलग **5 वेळा अपयश झाल्यास 30 मिनिटे लॉक** (423), या काळात उरलेल्या प्रयत्नांची संख्या कमी होत जाते | `src/app/api/auth/login/route.ts`、`rate-limit.ts` |

**गोपनीयता संरक्षण वर्तन**: व्हेरिफिकेशन कोड पाठवताना / पासवर्ड विसरल्यास, ईमेल आधी नोंदणीकृत असो वा नसो,
इंटरफेस नेहमी एकच यशाचा संदेश देतो, ईमेल नोंदणीकृत आहे का हे उघड करत नाही.

## नोंदणी यशस्वीनंतर स्थितीचा प्रवाह

1. वापरकर्ता `accountStatus: 'pending'` सह डेटाबेसमध्ये सेव्ह होतो, सुरुवातीला **3 बॅज** (register route).
2. सर्व्हर त्याच वेळी दोन HttpOnly कुकीज सेट करतो: JWT (थेट `/subscription` वर प्रवेश करू शकते) आणि
   pendingUserToken (सबस्क्रिप्शन प्रक्रियेची ओळखपत्रे).
3. नोंदणी पेज `pending_payment` ओळखते → `/subscription` वर जाते (`next` परतीचा पॅरामीटर जपून ठेवते).
4. पेमेंट पूर्ण → `accountStatus` `active` होते (PayPal Webhook ने आपोआप अॅक्टिव्हेट; WeChat स्कॅनवर
   मॅन्युअल पुष्टी; हुआवेई IAP वर `activate-huawei`). तपशील `payment-and-activation.md` मध्ये पहा.

अॅक्टिव्हेट न झालेला (pending) वापरकर्ता कोर API (फीड, नकाशा, डिजिटल ह्युमन चॅट, चेक-इन इत्यादी) कॉल केल्यास नेहमी
403 मिळतो; पोस्ट शेअर लिंक वगळता (ती सार्वजनिकरित्या खुली राहते).

## सामान्य त्रुटी शोध सारणी

| लक्षण | कारण | काय करावे |
|---|---|---|
| «用户名已存在» (यूझरनेम आधीच अस्तित्वात आहे) | यूझरनेम आधीच घेतलेले (केस-इनसेन्सिटिव्ह) | दुसरे यूझरनेम निवडा |
| «邮箱已被使用» (ईमेल आधीच वापरलेला) | ईमेल आधी नोंदणीकृत आहे | ईमेल बदला; किंवा लॉगिन + «पासवर्ड विसरलात» ने जुने खाते परत मिळवा |
| «邮箱验证码错误或已过期» (ईमेल व्हेरिफिकेशन कोड चुकीचा किंवा कालबाह्य) | कोड चुकीचा / 10 मिनिटे उलटली / 5 पेक्षा जास्त चुकीचे प्रयत्न झाल्याने नाकारला | «पुन्हा पाठवा» वर क्लिक करा, **सर्वात नवीन** ईमेलचा कोड वापरा |
| व्हेरिफिकेशन कोड मिळत नाही | 60 सेकंदांची रेट-लिमिट; किंवा स्पॅम/प्रमो फोल्डरमध्ये गेला | काउंटडाउन संपल्यावर पुन्हा पाठवा; स्पॅम मेल फोल्डर तपासा |
| «手机号已被使用» (मोबाईल क्रमांक आधीच वापरात) | मोबाईल क्रमांक दुसऱ्या खात्याशी जोडलेला | मोबाईल क्रमांक काढून टाका (ऐच्छिक) किंवा क्रमांक बदला |
| «注册请求过于频繁»/ 429 (नोंदणी विनंती खूप वारंवार) | नोंदणीची 3 वेळा/मिनिट/IP मर्यादा ओलांडली | काही मिनिटांनंतर पुन्हा प्रयत्न करा |
| 409«用户名或邮箱已被注册» (यूझरनेम किंवा ईमेल आधी नोंदणीकृत) | सबमिटच्या क्षणी दुसऱ्याशी नावाचा संघर्ष (कंकरन्सी फॉलबॅक) | यूझरनेम किंवा ईमेल बदलून पुन्हा प्रयत्न करा |
| «图片大小不能超过5MB»/«不支持 SVG» (इमेज 5MB पेक्षा मोठी / SVG सपोर्ट नाही) | प्रोफाइल फोटो नियमांनुसार नाही | फोटो बदला किंवा प्रोफाइल फोटो वगळा |
| नोंदणी यशस्वी पण लॉगिन 403«请完成订阅以激活账户» (खाते अॅक्टिव्हेट करण्यासाठी कृपया सबस्क्रिप्शन पूर्ण करा) | खाते अजून pending आहे | लॉगिन करून पेजच्या सूचनेनुसार `/subscription` वर सबस्क्रिप्शन पूर्ण करा |
| लॉगिन 423«账户已锁定» (खाते लॉक झाले आहे) | पासवर्ड सलग 5 वेळा चुकीचा | 30 मिनिटे थांबा |
| लॉगिन 401«还剩 N 次尝试机会» (N प्रयत्नांची संधी उरली आहे) | पासवर्ड चुकीचा, लॉक होण्याच्या जवळ | विचार करून प्रयत्न करा, किंवा थेट «पासवर्ड विसरलात» निवडा |
| «该账号未设置密码，请使用其他方式登录» (या खात्यासाठी पासवर्ड सेट केलेला नाही, कृपया इतर मार्गाने लॉगिन करा) | थर्ड-पार्टी (Google/Watcha/हुआवेई) खाते | मूळ थर्ड-पार्टी बटणाने लॉगिन करा |
| «该账号已注销» (खाते बंद झाले आहे) | खाते deactivate झाले आहे | पुन्हा नोंदणी करावी लागेल |

## लॉगिनची छोटी माहिती (शोधासाठीही उपयोगी)

लॉगिन **यूझरनेम / ईमेल / मोबाईल क्रमांक** तिन्ही एकत्र स्वीकारते (तिन्हीपैकी कोणतेही खात्याचे नाव म्हणून)।
पासवर्ड विसरलात: लॉगिन पेज → «पासवर्ड विसरलात» → नोंदणी केलेला ईमेल टाका, 6 अंकी व्हेरिफिकेशन कोड घ्या → रीसेट करा.

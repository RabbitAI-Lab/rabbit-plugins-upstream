# सदस्यता सक्रियन व पेमेंट — powpow-register

## निष्कर्ष (आधी उत्तर)

**Alipay आणि PayPal या दोन्ही सदस्यता मार्गांवर आता एजंट ऑर्डर तयार करू शकतो व प्राप्ती ट्रॅक करू शकतो.**
Alipay एकदाच खरेदी, स्वयंचलित नूतनीकरण नाही — चीन मुख्यभूमी व Alipay असलेल्या वापरकर्त्यांसाठी;
PayPal दरमहा स्वयंचलित नूतनीकरण, कधीही रद्द करता येते — परदेशी व Alipay नसलेल्या वापरकर्त्यांसाठी.
WeChat क्यूआर (मॅन्युअल पडताळणी) व Huawei IAP अजूनही आहेत, पण स्किल हाताळत नाही.

पेमेंट टप्प्याची जबाबदारी सीमा: एजंट **ऑर्डर तयार करू शकतो, कॅशियर उघडू शकतो, प्राप्ती तपासू शकतो**; वापरकर्त्याच्या Alipay/PayPal खात्याला/पेमेंट क्रेडेन्शियलला **कधीही** स्पर्श करत नाही, "पेमेंट करून देईन" असे कधीही म्हणत नाही. पेमेंट क्रिया नेहमी वापरकर्त्यानेच अधिकृत कॅशियरवर केली जाते.

## Alipay मार्ग (vibepay, मुख्य)

एकदाच खरेदी प्रणाली: एकदा पे केल्यास संबंधित कालावधी सक्रिय, **स्वयंचलित नूतनीकरण नाही**. पॅकेज `src/lib/alipay-vibepay.ts` (`ALIPAY_PACKAGES`) मध्ये हार्डकोड:

| key | planId | नाव | किंमत | कालावधी |
|---|---|---|---|---|
| `monthly` | alipay-monthly | मासिक सदस्यता | ¥6.99 | 30 दिवस |
| `quarterly` | alipay-quarterly | त्रैमासिक सदस्यता | ¥19.99 | 90 दिवस |
| `yearly` | alipay-yearly | वार्षिक सदस्यता | ¥69.99 | 365 दिवस |

### इंटरफेस करार (स्किल स्क्रिप्टने लपेटले, एजंट थेट रचत नाही)

| इंटरफेस | पद्धत | स्पष्टीकरण |
|---|---|---|
| `/api/payment/alipay/create-order` | POST | `Authorization: Bearer <JWT>` आवश्यक (pending वापरकर्ता चालते). body `{package}` → `{paymentHtml, outTradeNo, amount, planName}` परत; `paymentHtml` हे Alipay गेटवेटवर आपोआप सबमिट होणारे फॉर्म पृष्ठ |
| `/api/payment/alipay/query` | GET `?outTradeNo=` | तेच Bearer auth. `paid` / `pending` / `closed` / `unknown` परत |
| `/api/payment/alipay/notify` | POST (Alipay सर्व्हर कॉलबॅक) | पाच-घटक स्वाक्षरी पडताळणी (स्वाक्षरी, app_id, रक्कम जुळणे, TRADE_SUCCESS/TRADE_FINISHED, व्यापाऱ्याची युनिकनेस) → **idempotent** ऑर्डर अपडेट + सदस्यता तयार + खाते सक्रिय. स्किल कधीही हा इंटरफेस स्पर्शत नाही |
| `/payment/alipay/return` | ब्राउझर परत-जाणारे पृष्ठ | सार्वजनिक मार्ग, पेमेंटनंतर `支付成功` पडताळणी दाखवते, पृष्ठ आतली स्थिती पोल करते |

- अनपेड ऑर्डर **2 तासांत आपोआप बंद**; वापरकर्त्याने मध्येच सोडले → थेट पुन्हा `create-order`, जुना ऑर्डर विचारू नका.
- स्क्रिप्ट `paymentHtml` तात्पुरत्या HTML फाइलमध्ये लिहिते, एजंट सिस्टम कमांडने उघडतो म्हणजे Alipay कॅशियरवर (क्यूआर स्कॅन किंवा Alipay मध्ये लॉगिन पे).

### सक्रियन लिंक (आपोआप, मॅन्युअल नको)

notify स्वाक्षरी पास → `paymentOrders` पेड म्हणून चिन्हांकित → `user_subscriptions` तयार/वाढवा
(`planId`, `currentPeriodEnd` durationDays नुसार, नूतनीकरण मूळ समाप्ती दिवशी वाढवा) →
`users.accountStatus: active` + `subscriptionStatus: ACTIVE` → परत-जाणारे पृष्ठ paid पर्यंत पोल करून यश दाखवते.

### पेमेंटनंतर नवीन लॉगिन स्थिती बदलणे आवश्यक (महत्त्वाचे)

JWT मध्ये सदस्यता घोषणा असते (pending खाते `NONE`). **पेमेंट आल्यावर फक्त DB अपडेट होते, आधीच जारी केलेल्या JWT चे claims बदलत नाहीत** — जुन्या token ची घोषणा तरीही NONE, त्याचा वापर करून लॉगिन लिंक तयार केल्यास "सदस्यता नाही" भासेल. म्हणून स्किल `paid` / PayPal `ACTIVE` पडताळल्यावर आधी `refresh-login` चालवते (पुन्हा लॉगिन नवीन JWT, घोषणा ACTIVE), मग लिंक 2. हे डिझाइन वर्तन आहे, बग फिक्स नाही.

## PayPal सदस्यता मार्ग (स्किल हाताळते; वेब, HarmonyOS नाही)

फक्त एकच योजना आहे, Premium Monthly (सुमारे $1/महिना, `/api/subscription/plans` परत करते त्याप्रमाणे); हे **दरमहा स्वयंचलित नूतनीकरण**
असून वापरकर्ता आपल्या PayPal खात्यात कधीही रद्द करू शकतो.

### API करार (स्किल स्क्रिप्टमध्ये आधीच रॅप केलेला; एजंट कधीही थेट विनंती तयार करत नाही)

| एंडपॉइंट | पद्धत | टिप्पणी |
|---|---|---|
| `/api/subscription/plans` | GET | Bearer आवश्यक; उपलब्ध योजनांची यादी (सध्या फक्त 1) |
| `/api/subscription/create` | POST | body `{planId}` → `{subscriptionId, approveUrl, status}`; `status` साधारण `APPROVAL_PENDING` |
| `/api/subscription/create` | GET | Bearer आवश्यक; `{activeSubscription, allSubscriptions}`; एजंट `activeSubscription.subscription.status === 'ACTIVE'` होईपर्यंत पोल करतो |
| `/api/subscription/verify` | POST | यश पृष्ठ आपोआप कॉल करते (cookie सह); webhook न आल्यास थेट PayPal API द्वारे सक्रिय करते |
| `/subscription/success` | ब्राउझर परत-जाणारे पृष्ठ | PayPal अनुमोदनानंतर उतरणारे पृष्ठ; verify आपोआप पोल करते, मग होम पृष्ठ / मूळ पृष्ठावर परत जाते |
| `/subscription/cancel` | ब्राउझर पृष्ठ | वापरकर्ता रद्द करे किंवा अयशस्वी झाले तर उतरणारे पृष्ठ; नवा प्रयत्न सुरू करता येतो |

### एजंट कालक्रम

```
create-order --provider paypal   # → approveUrl परत, स्थानिक HTML फाइलमध्ये लिहिले जाते
HTML फाइल उघडा                  # → ब्राउझर PayPal अनुमोदन पृष्ठावर
query (दर 10–15s)               # → ACTIVE होईपर्यंत पोल
refresh-login                   # → नवीन JWT (सदस्यता घोषणा ACTIVE)
login-link --target home        # → अधिकृत लॉगिन लिंक तयार करते
```

- 1 तासात पूर्ण न झालेल्या PENDING सदस्यता बॅकएंड आपोआप साफ करते; पुन्हा सुरू करा.
- वापरकर्त्याने पुन्हा `create-order` चालवले तर बॅकएंड अजून वैध `APPROVAL_PENDING` सदस्यता पुन्हा वापरते, 409 येत नाही.
- Alipay प्रमाणेच: प्राप्ती फक्त DB अपडेट करते — जुना JWT आपोआप रिफ्रेश होत नाही, म्हणून होमपेज लिंक पाठवण्याआधी `refresh-login` **नक्की** चालवा.

## सदस्यता पृष्ठावरील चार मार्ग

सदस्यता पृष्ठ `src/app/(public)/subscription/page.tsx` रनटाइमनुसार दाखवते:

| मार्ग | वातावरण | यंत्रणा | सक्रियन पद्धत |
|---|---|---|---|
| **Alipay (मुख्य)** | वेब | `AlipayPaymentSection` vibepay इंटरफेस (वरील सारणी) | notify सर्व्हर-साइड आपोआप, सेकंदात |
| PayPal सदस्यता | वेब (Harmony वगळता) | `/api/subscription/create` → PayPal अधिकृत; मासिक स्वयंचलित नूतनीकरण कधीही रद्द (`/api/subscription/manage`) | PayPal Webhook (`BILLING.SUBSCRIPTION.*`) आपोआप active |
| WeChat क्यूआर सदस्यता | वेब (Harmony वगळता) | पृष्ठाच्या तळाशी `微信扫码订阅`: क्यूआर स्कॅन ट्रान्सफर | **मॅन्युअल पडताळणी**, प्राप्तीत विलंब; झाल्यावर लगेच अयशस्वी ठरवू नका |
| Huawei ऍप-इन पर्चेस | Harmony ऍप आत | मूळ `NativeBridge.purchaseSubscription()` | `/api/subscription/activate-huawei` Huawei ऑर्डर पडताळून सक्रिय |

PayPal प्लॅन व किंमत `/api/subscription/plans` वरून डायनॅमिक वाचते; पृष्ठावरील स्थिर मजकूर: Auto-renews. Cancel anytime.

## स्थिती व रीडायरेक्ट

- Alipay पे झाल्यावर → परत-जाणारे पृष्ठ यश दाखवते; PayPal यश → `/subscription/success` → खाते active →
  आपोआप `next` पॅरामिटरच्या मूळ पृष्ठावर (नसल्यास होम).
- आधीच सदस्यता असलेला परत सदस्यता पृष्ठावर → "You're All Set!" दाखवते, 3 सेकंदांत होमपेजावर.
- पेमेंट अयशस्वी/रद्द (PayPal) → `/subscription/cancel`, पुन्हा सुरू करता येते.

## निवारण

| घटना | हाताळणी |
|---|---|
| Alipay पे झाले पण `query` अजूनही pending | notify क्वचित विलंब; 30 सेकंद थांबा मग पुन्हा. तरीही नाही तर वापरकर्त्याला ब्राउझरवर परत-जाणारे पृष्ठ स्थिती पहायला सांगा, तरीही नाही तर प्लॅटफॉर्म सपोर्ट (dongtao@outlook.com) संपर्क, `outTradeNo` द्या |
| Alipay पे झाले, लिंक 2 मध्ये अजूनही अडवले | `refresh-login` विसरले (जुने JWT claims अपडेट नाहीत) — आधी `refresh-login` मग `login-link` |
| PayPal `query` सतत PENDING | वापरकर्त्याने PayPal मध्ये अनुमोदन पूर्ण केले नाही; अनुमोदन लिंक ब्राउझरमध्ये उघडली आहे का ते पडताळा. अनुमोदनानंतरही PENDING असेल तर webhook विलंबित असू शकतो — वापरकर्त्याला यश पृष्ठावर आणखी काही सेकंद थांबायला किंवा रिफ्रेश करायला सांगा |
| PayPal `query` 409 परत करते | अजून एक अपूर्ण PENDING सदस्यता आहे; 1 तास कालबाह्य होईपर्यंत थांबा, किंवा जुन्या लिंकचे अनुमोदन ब्राउझरमध्ये पूर्ण करा |
| PayPal वर पे केले, तरी लिंक 2 मध्ये अजूनही अडवले | Alipay प्रमाणेच: आधी `refresh-login`, मग `login-link` |
| पे झाले तरी 403 (PayPal) | Webhook क्वचित विलंब, पुन्हा लॉगिन करून स्थिती रिफ्रेश |
| WeChat पे झाले पण सक्रिय नाही | मॅन्युअल पडताळणी async आहे, काही तासांत न झाल्यास प्लॅटफॉर्म सपोर्ट संपर्क |
| सदस्यता पृष्ठ `No subscription plans available` दाखवते | `/api/subscription/plans` मध्ये PayPal प्लॅन नाही, प्लॅटफॉर्म-साइड कॉन्फिग समस्या; चीनमधील वापरकर्ते Alipay ला वळा |

## ऐतिहासिक टीप

कोडमध्ये आणखी एक **जुना** Alipay वेब पेमेंट (`src/lib/alipay.ts`, `/api/payment/create-order`,
¥9.90/¥99 एकदाच खरेदी, सँडबॉक्समध्ये की नसल्यास सिम्युलेट पेमेंट) आहे, कधीही सदस्यता पृष्ठ UI मध्ये जोडले गेले नाही, vibepay शी संबंध नाही. स्किल कधीही त्याला स्पर्शत नाही; `alipay-vibepay.ts` हाच सध्याचा मार्ग.

# एजंट-सहाय्यित प्रवाह व स्क्रिप्ट करार — powpow-register

SKILL.md मधील पायऱ्यांचे अंमलबजावणी तपशील. सर्व कमांड `node scripts/powpow-register.mjs <उप-कमांड> [आर्ग्युमेंट]` आहेत, स्क्रिप्ट **शून्य अवलंबन**, **Node >= 18** आवश्यक, सर्व विनंत्या फक्त `https://global.powpow.online` वर जातात.

## सुरक्षा रचना (असे डिझाइन का आहे)

| रचना | कारण |
|---|---|
| पासवर्ड फक्त एन्व्हायर्नमेंट व्हेरिएबल `POWPOW_REGISTER_PASSWORD` द्वारे | प्रोसेस कमांड लाइन आर्ग्युमेंट समान मशीनवरील इतर प्रोसेसना दिसतात (argv लीक सरफेस), एन्व्हायर्नमेंट व्हेरिएबल स्क्रिप्टमध्ये वाचले जाते व लगेच वापरले जाते |
| पासवर्ड **कधीही स्थिती फाइलमध्ये लिहीत नाही**, कधीही लॉगमध्ये दिसत नाही | स्थिती फाइल डिस्कवर राहू शकते; संवादातील जेनरेट मोड एकदाच दाखवतो म्हणजे वापरकर्त्याने सुरक्षित ठेवावे |
| स्थिती फाइल सिस्टम तात्पुरत्या डिरेक्टरीत (`os.tmpdir()/powpow-register-state.json`, 0600) | फक्त email / username / nickname / token / outTradeNo ही पाच फील्ड, `cleanup` एका क्लिकमध्ये साफ |
| एजंटला मिळालेले JWT अधिकृत `me?token=` एंडपॉइंटद्वारे ब्राउझर कुकीमध्ये रूपांतरित | प्लॅटफॉर्मने Harmony WebView साठी डिझाइन केलेला अधिकृत ब्रिज; स्वाक्षरी पडताळणी फक्त स्वाक्षरी+वैधता तपासते, डिव्हाइस फिंगरप्रिंटशी बांधीत नाही, वापरकर्त्याचा ब्राउझर वापरू शकतो |
| पेमेंट फक्त create-order / query / कॅशियर उघडणे करते | पेमेंट क्रिया व पेमेंट क्रेडेन्शियल नेहमी वापरकर्ता व Alipay अधिकृत कॅशियर यांच्यात, एजंट हाताळत नाही |

## कमांड संदर्भ

| कमांड | मुख्य आर्ग्युमेंट | कार्य / वेळ |
|---|---|---|
| `status` | —— | प्रवाह प्रगती पहा (स्थिती फाइल वाचा); संवाद खंडित झाल्यावर आधी हे चालवा |
| `gen-password` | —— | 24-अंकी मजबूत पासवर्ड तयार करा (मोठी+लहान अक्षरे+अंक), stdout वर **फक्त एकदाच** दाखवा |
| `prepare-suggest` | `--username --nickname --email` | पडताळलेली माहिती स्थिती फाइलमध्ये नोंद करा (नंतर register साठी पुन्हा पाठवावे लागणार नाही) |
| `send-code` | `--email` | प्लॅटफॉर्मला 6-अंकी संकेतांक पाठवायला सांगा (10 मिनिट वैध, 60s थंडावा) |
| `register` | `--code` (आवश्यक); `--username --nickname --avatar --phone` (पर्यायी, स्थिती फाइलमध्ये असल्यास मुक्त) | pending खाते तयार करा; पासवर्ड `POWPOW_REGISTER_PASSWORD` एन्व्हायर्नमेंटद्वारे; यशात JWT आपोआप स्थिती फाइलमध्ये |
| `login-link` | `--target pending` किंवा `--target home` | एक-क्लिक लॉगिन लिंक तयार करतो (दोन-लिंक डिझाइन, खाली पाहा) |
| `create-order` | `--package monthly\|quarterly\|yearly` (Alipay डीफॉल्ट)<br>`--provider alipay\|paypal` | पेमेंट ऑर्डर तयार करते; Alipay पेमेंट पृष्ठ फाइल मार्ग + outTradeNo परत करते; PayPal अनुमोदन पृष्ठ फाइल मार्ग + subscriptionId परत करते (आपोआप स्थिती फाइलमध्ये) |
| `query` | —— | ऑर्डर/सदस्यता स्थिती तपासते. Alipay: `paid / pending / closed / unknown`; PayPal: `ACTIVE / PENDING`; 10–15s पोल |
| `refresh-login` | पासवर्ड एन्व्हायर्नमेंटद्वारे | पुन्हा लॉगिन करून **नवीन JWT** मिळवा (सदस्यता घोषणा NONE वरून ACTIVE), पेमेंट आल्यावर बंधनकारक |
| `whoami` | —— | स्थिती फाइलमधील टोकनद्वारे खाते व सदस्यता स्थिती पहा (सक्रियन झाले का ते पडताळा) |
| `cleanup` | —— | स्थिती फाइल हटवा (समारोपी बंधनकारक) |

**एन्व्हायर्नमेंट व्हेरिएबल पास (पासवर्ड कधीही कमांड लाइनवर नाही):

```bash
# bash / zsh / WSL
POWPOW_REGISTER_PASSWORD='<पासवर्ड>' node scripts/powpow-register.mjs register --code 123456
# PowerShell
$env:POWPOW_REGISTER_PASSWORD = '<पासवर्ड>'; node scripts/powpow-register.mjs register --code 123456
# cmd
set POWPOW_REGISTER_PASSWORD=<पासवर्ड> && node scripts/powpow-register.mjs register --code 123456
```

## दोन-लिंक यंत्रणा (कोर डिझाइन)

व्यासपीठाची लॉगिन स्थिती एक HttpOnly कुकी आहे, जी एजंट थेट ब्राउजरमध्ये लावू शकत नाही; पूल आहे अधिकृत
`/api/auth/me?token=<JWT>&redirect=<साइटमधील पाथ>` एंडपॉइंट: स्वाक्षरी पडताळणी → स्वयंचलितपणे सत्र
तयार करणे → `Set-Cookie: powpow_token` (HttpOnly / SameSite=Lax / 7 दिवस) → पुनर्निर्देशन पडताळणी
(एका स्लॅशने सुरू व्हावे, `//` आणि बॅकस्लॅश निषिद्ध, पार्स केल्यावर same-origin असावे) → लक्ष्य पृष्ठावर 307 तात्पुरते पुनर्निर्देशन.

लिंकचे दोन लक्ष्य आहेत, **आधी home तयार करा, नंतर वापरकर्ता कुठे उतरला आहे ते पाहून pending मधून जावे की नाही ते ठरवा**:

- **home लिंक (डिफॉल्टने पाठवले जाते, `--target home` → `/` वर उतरतो)**: यशस्वी नोंदणीनंतर तत्काळ तयार करून वापरकर्त्याला पाठवले जाते.
  मोफत चाचणी काळात वापरकर्ता थेट मुख्यपृष्ठावर जातो, सर्व काही वापरण्यायोग्य; **लिंक क्लिक करून सदस्यता पृष्ठावर उतरल्यास मोफत चाचणी काळ संपला आहे** — पेमेंट प्रवाहाकडे स्विच करा (खाली पाहा); स्क्रिप्ट बदल नाही आणि पुन्हा नोंदणी नाही.
- **pending लिंक (पेमेंट प्रवाहात वापरले जाते, `--target pending` → `/subscription` वर उतरतो)**:
  वापरकर्त्याचा ब्राउजर "अर्ध-लॉगिन" स्थितीत प्रवेश करतो: सदस्यता पृष्ठ आणि पेमेंटनंतर परत येणारे पृष्ठ दिसतात आणि चालवता येतात. पैस आल्यावर,
  ACTIVE दाव्यासह नवीन JWT मध्ये बदलण्यासाठी `refresh-login` चालवा, नंतर संपूर्ण सदस्यता स्थितीसाठी home लिंक पुन्हा पाठवा.

## संपूर्ण क्रम

### जलद मार्ग (मोफत चाचणी काळात — बहुतांश प्रकरणे)

```
1.  status                          # पर्यावरण स्वयं-तपासणी
2.  (पायरी 2: माहिती निश्चित करण्यासाठी संभाषण, पासवर्ड इच्छेनुसार; जनरेट मोड: gen-password → वापरकर्त्याला तत्काळ जतन करण्यास सांगा)
3.  prepare-suggest --username U --nickname N --email E
4.  send-code --email E             # → वापरकर्ता इनबॉक्समध्ये कोड पाहतो (संभाषण सोडण्याची एकमेव वेळ)
5.  POWPOW_REGISTER_PASSWORD=*** register --code 123456 [--avatar pic.jpg]
6.  login-link --target home        # → लिंक वापरकर्त्याला पाठवा; एक क्लिक आणि मुख्यपृष्ठावर
7.  (वापरकर्ता आत गेला निश्चित करतो) → तत्काळ संपवा: cleanup + खाते कार्ड + पहिल्या पायऱ्यांचे मार्गदर्शन
```

### पेमेंट मार्ग (जेव्हा वापरकर्ता सदस्यता हवी असेल, किंवा मोफत चाचणी काळ संपला असेल)

```
1–5. जलद मार्ग प्रमाणे (register यशस्वी झाल्यावर स्थितीत टोकन आधीच आहे)
6.  login-link --target pending     # → अर्ध-लॉगिन लिंक, पेमेंटनंतर परत येणारे पृष्ठ काम करते
7.  (वापरकर्ता पेमेंट पद्धत निवडतो)
    # Alipay: create-order --package monthly|quarterly|yearly
    # PayPal: create-order --provider paypal
8.  start <पेमेंट पृष्ठ फाइल>       # Windows; macOS open, Linux xdg-open
    # → वापरकर्ता Alipay/PayPal कॅशियरवर पेमेंट/परवानगी पूर्ण करतो (संभाषण सोडतो)
9.  query (दर 10–15 सेकंदांनी) paid / ACTIVE पर्यंत
10. refresh-login                   # ACTIVE दाव्यासह नवीन JWT मध्ये बदला
11. login-link --target home        # → वापरकर्त्याला संपूर्ण सदस्यता लिंक पाठवा
12. whoami                          # subscriptionStatus: ACTIVE निश्चित करा (ऐच्छिक)
13. cleanup                         # स्थिती फाइल साफ करा
```
## कमांड → प्लॅटफॉर्म API नकाशा

| स्क्रिप्ट कमांड | प्लॅटफॉर्म इंटरफेस |
|---|---|
| `send-code` | `POST /api/auth/register/send-code` |
| `register` | `POST /api/auth/register` (multipart, प्रोफाइल थेट अपलोड) |
| `login-link` | `GET /api/auth/me?token=…&redirect=…` (लिंक स्वतः, ब्राउझर क्लिक केल्यावर प्रभावी) |
| `create-order` | `POST /api/payment/alipay/create-order` (Bearer, Alipay)<br>`GET /api/subscription/plans` + `POST /api/subscription/create` (Bearer, PayPal) |
| `query` | `GET /api/payment/alipay/query?outTradeNo=…` (Bearer, Alipay)<br>`GET /api/subscription/create` (Bearer, PayPal) |
| `refresh-login` | `POST /api/auth/login` (`{step:1, username, password}`) |
| `whoami` | `GET /api/auth/me?token=…` |

नियम स्रोत: नोंदणी फील्ड व रेट-लिमिट पहा `registration-flow.md`; पॅकेज व सक्रियन लिंक पहा
`payment-and-activation.md` (दोन्ही प्लॅटफॉर्म स्रोत फाइल नमूद केलेले).

| `refresh-login` 403 `pending_payment` | मोफत चाचणी काळ संपला आणि पेमेंट अजून आला नाही; पोलिंग सुरू ठेवण्यासाठी पायरी 9 वर परत जा, किंवा वापरकर्त्याने पेमेंट पूर्ण केले की नाही ते निश्चित करा |
| स्थिती फाइल हरवली (चुकून डिलीट / मशीन बदल) | `whoami`/`refresh-login` वापरता येणार नाही; वापरकर्त्याला लिंक 1 उघडलेल्या ब्राउझरमध्ये सदस्यता पृष्ठ रिफ्रेश करून स्थिती पडताळायला सांगा, किंवा पुन्हा लॉगिन (वेब मोड) |

## परत-जाणे मोड (शुद्ध मार्गदर्शन)

खालीलपैकी कोणतीही परिस्थिती झाल्यास लगेच v1-शैली शुद्ध मार्गदर्शनात परता, स्क्रिप्टचा त्रास करू नका:

- Node >= 18 नाही किंवा स्क्रिप्ट सलग दोनदा समान प्रकारची अयशस्वी;
- वापरकर्त्याने स्पष्टपणे "मी स्वतः वेबवर करतो" सांगितले;
- कंपनी/डिव्हाइस धोरणामुळे स्क्रिप्टला नेटवर्क बंदी.

परत आल्यावर: नोंदणी पृष्ठ https://global.powpow.online/register द्या (मोफत चाचणी काळात वेब नोंदणीही तशीच तत्काळ; सदस्यता आवश्यक असल्यास सदस्यता पृष्ठ https://global.powpow.online/subscription देखील द्या), `registration-flow.md` च्या नियमांप्रमाणे पाठपुरेलो समस्या निवारण करा, तोच स्वर ठेवा, आणि प्रत्येक वेळी तरी "पुढील पायरी" ब्लॉकने संपवा.
https://global.powpow.online/subscription द्या, `registration-flow.md` च्या नियमांनुसार सोबत निवारण,
टोन बदलत नाही, प्रत्येक फेरी "पुढील पायरी" विभागाने समारोप.

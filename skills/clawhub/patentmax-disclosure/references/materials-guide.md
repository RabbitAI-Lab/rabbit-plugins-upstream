# 材料怎么准备

交底书是**无人值守生成**的：服务端读完材料就开始写，中间没有人可以问。材料里缺的信息，流水线会按本领域的通行做法直接写进正文；需要发明人确认的推导和待补充，列进核对说明。

所以材料越全：

- 推断越少，核对说明里要人确认的条目越少
- 发明点越具体，和专利库比对时越有区分度
- 附图越准，系统能直接画出来的图越多

而这是**付费任务**，改材料重跑要再花一次钱。第一次就读全。

---

## 三件事缺一不可

### 一、解决什么问题

现有做法卡在哪、有什么缺陷。

> 冬季输水渠道的闸阀容易被冰雪和杂物卡滞，人工巡检发现不及时，强行启闭会损坏驱动机构。

这一段决定交底书的「背景技术」和「要解决的技术问题」。

### 二、具体怎么做

**这是最关键、也最容易写空的一块。** 交底书第 3 节「技术方案」要写到本领域技术人员能照着实施的程度，材料里没有的，只能靠推断。

- **结构**：什么部件、怎么连接、相对位置
- **步骤**：动作顺序、判断条件、分支
- **参数**：阈值、范围、配比、型号
- **控制逻辑**：什么条件下触发什么动作

> 在转轴上布置角度传感器与扭矩传感器，在闸前闸后各设一个水位计；当启闭扭矩相对基准值增量超过 30%、且水位差异常时判定为卡滞；结合积雪含水率区分冰冻与异物，冰冻时低频大振幅振动 30 秒，异物时高频小振幅振动 15 秒，连续三次失败则告警锁定。

### 三、达到什么效果

最好有数字。

> 卡滞识别准确率 90% 以上，避免强行启闭造成驱动机构损坏，免人工巡检。

效果决定交底书的「优点」一节写得有没有说服力。

## 不同领域要写到什么程度

服务端会自动判断领域，按下面的标准撰写。材料里提前备好这些，推断就少。

| 领域 | 材料里最好有 |
| --- | --- |
| **计算机 / 软件** | 处理流程、每一步的输入输出、判断条件与分支、模块划分及数据流向。算法要能逐步展开 |
| **机械** | 零部件结构、连接关系、空间位置、配合关系、工作原理。涉及流体的写清流向和管路 |
| **电子** | 元器件连接关系、信号流向、工作时序，关键元件的参数或取值范围 |
| **化工** | 组分与各组分含量、制备步骤与工艺条件（温度、压力、时间、浓度），性能表征数据 |
| **生物** | 菌株名称与保藏信息，或序列；证实用途与效果的试验数据 |
| **药品** | 组分、重量份数的范围与最佳值、原料来源、操作步骤、试验报告 |

**化工和药品领域尤其要给数据。** 实施例需要点值（范围的两个端值加一个中间值），这些只能来自真实实验，系统不会编实验数据，缺了会列进「待补充」。

## 从哪里找材料

用户给了项目目录时，按这个顺序读：

1. **技术方案、设计文档、研发报告**：最直接
2. **实验记录、测试报告**：参数和效果数据在这里
3. **需求说明、立项书**：背景和要解决的问题在这里
4. **README、架构说明**：软件类项目的模块划分
5. **代码**：**不要整份提交**。读懂后用文字写出流程、判断条件和模块关系

图纸、原理图、流程图脚本读不到，要**用文字描述**：部件怎么连、信号怎么走、流程怎么分支。系统会据此画附图。

## 三个颗粒度对照

### ❌ 太短，脚本会拦

```
一种智能阀门控制装置。
```

200 字以下直接拦下来。这种情况先用 `ideas` 出方向。

### ⚠️ 能写，但推断多

```
一种闸门防卡滞装置，通过传感器检测闸门状态，发现卡滞时启动振动装置清理，
提高闸门运行可靠性，减少人工巡检。
```

交底书写得出来，但传感器是什么、怎么判断卡滞、振动怎么控制全靠推断，核对说明里会有一长串待确认条目。**先问用户两三个问题：**

- 用什么传感器、装在哪里？
- 卡滞怎么判断，阈值多少？
- 振动装置的频率、时长怎么定？

### ✅ 够用

上面「具体怎么做」那一段的写法：部件、位置、判据、阈值、动作、失败处理都有了。再加上问题和效果，就是一份扎实的材料。

---

## 保密

材料会发送到服务端生成。涉及还没申请的核心参数、配方时，提醒用户一句，让用户自己决定写到多细。

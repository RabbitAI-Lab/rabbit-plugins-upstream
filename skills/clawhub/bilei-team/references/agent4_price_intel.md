# Agent 4 作业手册：价格情报官（历史低价与好价渠道）

## 岗位边界

- **只做价格与渠道**：历史低价、当前各平台到手价、促销节奏、渠道风险分级。
- **不评质量、不碰参数、不下推荐**。你的产出是"价格地图"与"什么时候在哪买"，买不买、买哪台由裁决官定。
- **禁止编价格**：拿不到就写"查不到"，并写明查了哪些平台。任何价格必须带 `date` 与 `channel_tier`。

## 价格口径（三层，不许混用）

| 口径 | 定义 | 用途 |
|---|---|---|
| **标价** | 页面划线价 / 指导价 | 只用于识别虚假标价，不作决策 |
| **到手价** | 实付 = 标价 − 券 − 平台补贴 − 国补 − 以旧换新 + 必购配件 | 决策唯一依据 |
| **全包价** | 到手价 + 必购配件（存储卡/手柄/保护壳/ND） | 跨机型对比时必须用 |

- 赠品必须**折算成钱**再计入；不能折现的赠品（如"专属教程"）写"不可折现，不计入"。
- 国补（数码产品补贴）必须核实：**是否限地区、是否限机型、是否与平台券互斥**。三者任一条不满足，不得写进到手价。
- 每条价格记录：`platform` / `seller`（官方旗舰店 or 第三方）/ `price` / `date` / `conditions`（券/补贴/以旧换新）。

## 历史低价取数路径

> ⚠️ **先分清是不是实物电商（v5.8 新增，最容易犯的错）**
>
> 下面这一整套（慢慢买/什么值得买/京东价保/闲鱼保值）**只对实物电商成立**。买服务、软件订阅、保险、课程、会员、虚拟商品时，它们**一条都用不上**——不要硬跑，跑出来的空结果会被误读成"该商品没有历史低价"。
>
> 非实物类改走 `category_profiles.md` 第三节：官网定价页存档（`web.archive.org` 查历史价）、条款版本对比、同类服务横向报价、涨价史。

| 来源 | 取什么 | 可信度 |
|---|---|---|
| 什么值得买「历史低价」标签 | 该型号的爆料价与发布时间 | 高（有用户实付截图） |
| **慢慢买搜索层（爆料列表）** | 该型号的爆料价 + 商城 + 日期 + **价格标签**（历史最低/60天新低/低于618/30天新低） | **高，免登录可用**——2026-11-04 实测跑通，方法见下节。**实物电商的默认第一入口** |
| 慢慢买 / 购物党 **历史曲线接口** | 近 6–12 个月完整价格走势、最低点 | ⚠️ **2026-11 实测：免登录接口已下线**（`history.aspx`→302、`getLowPriceList.ashx`→错误页、`api.ashx`→`{"msg":"无效的票据"}`）。旧教程全部过期，勿照抄。要完整曲线只有三条路：① App「降价提醒」（人工设目标价，微信通知）；② 浏览器自动化读 `HistoryLowest.aspx` 前端渲染结果；③ 用户自备登录 cookie（会过期、有 TOS 风险） |
| 京东「价格保护」与历史订单晒单 | 大促实付 | 中 |
| 闲鱼/转转同款成交 | 二手价 → 反推保值率，供 EAC 残值用 | 中（要看去重与成色） |
| **官方定价页历史快照**（非实物类必用） | 服务/订阅/保险的历年定价与条款 | 中高——用 `web.archive.org` 取快照，比任何二手转述都硬 |

**慢慢买的三个盲区（不要把它当全知）**

1. **平台偏向**：以京东为主，天猫次之，拼多多/抖音小店/小红书店铺覆盖很弱；**只在私域或线下卖的，基本查不到**。
2. **品类偏向**：数码/家电覆盖好；建材、家具、定制类、生鲜、服务类很差。
3. **零记录的正确读法**：不是"价格正常"，而是"**没有参照**"。既不能证明贵，也不能证明便宜——必须去电商页现价补位，并在报告里写明"无历史参照"。

| 品牌官方公告 | 首发价、调价 | 高 |

**慢慢买官方 API 的真实情况（v5.3 核实）**：官方**确实有** API，2014 年起对外开放，但只做 B 端——比价接口（搜索/报价读取）、商品信息接口（按 ID 或 URL 取标题、价格、优惠）、SaaS 价格监测与市场洞察、定制采集。按「API 连接数 + 监测 SKU + 定制项目」计费，**客单价几万到十几万元**，客户是中国移动、中石化、联合利华、华为、顺丰、南网这类。官方页 `manmanbuy.com/a_148336.aspx` 在线，但只是营销页：**无自助注册、无公开文档、无价格表**；`data.manmanbuy.com` 已无法访问（HTTP 000）。

结论：**个人/小团队买不起也不需要买**。免费且稳定的路径是「App 设降价提醒（微信通知）」+「自建价格库（每日跑一次存 CSV，半年即自有历史价格）」。把这两条写在方案里，别建议用户去买 API。

**第三方抓取经验（来自社区 skill，实测有效）**：PC 端历史价查询要粘**淘口令**（`¥xxxx¥`）而非 URL；频繁查询必触发人机验证，禁止大批量 fan-out；**拼多多覆盖弱**；跨店满减与店铺券不计入，容易高估"显示价"；冷门 SKU 只追踪数月，不可当全周期最低。

**取数纪律（v5.2）**：优先用**能复核的来源**（什么值得买爆料页、京东价保记录、晒单截图），二手数据（博主转述）必须标"不可复核"。历史价格库拿不到完整曲线时，只报"已知最低点"并注明"非全周期最低"，不得写成"历史最低"。

## 慢慢买搜索层实战（v5.6 新增，本人 2026-11-04 实测跑通）

> **先修正一条旧结论**：手册此前记"慢慢买免登录接口已全部下线"——那句话只对**历史曲线 API** 成立。**搜索层是另一个端点，免登录完全可用**，而且返回的东西足够判断买点。别再因为旧结论就跳过这个站。

### ⛔ 唯一的坑：关键词必须 GBK 编码

站点按 **GBK** 解析 `key` 参数。传 UTF-8 会被当 GBK 解读，返回乱码页（标题变成 `瀹夊厠鏅烘樉鍏?40W` 这种），看起来像"站点挂了"，其实是你编码错了。

```bash
# 正确｜先生成 GBK 百分号编码再请求
/usr/bin/python3 -c "import urllib.parse,sys;print('https://ss.manmanbuy.com/?key='+urllib.parse.quote(sys.argv[1].encode('gbk')))" "安克智显充140W"
```

实际落到：`https://s.manmanbuy.com/pc/search/result?keyword=<GBK编码>&c=discount`

**现成脚本**：`scripts/manmanbuy_price.py`（本技能自带，零依赖）

```bash
/usr/bin/python3 <SKILL_DIR>/scripts/manmanbuy_price.py "安克智显充140W" "图拉斯小冰块"
```

### 返回什么

搜索结果页是**爆料列表**，每条含：商品标题、爆料价、商城（京东自营/天猫旗舰店/拼多多）、日期、**价格标签**、条目链接。31 条/页。

**价格标签就是结论，不用自己算**：

| 标签 | 含义 | 怎么用 |
|---|---|---|
| **历史最低** | 比价库认定全周期最低 | 直接引用，这是最有价值的一条 |
| 60天新低 / 30天新低 | 短周期低点 | 说明当前接近底部 |
| 低于618 / 低于双11 | 相对大促基准 | 回答"要不要等大促" |
| 闭眼买 | 站方推荐位 | **不采信**，是运营标签不是价格标签 |

### 解析要点（自己写脚本时看这里）

| 项 | 位置 |
|---|---|
| 标题 | `<a title="...">` **属性里**，标签文本可能只有"已结束"徽标 |
| 价格 | `itemSubTitle` 内嵌的 `<a>` 文本（可能是长串，含淘金币/券条件） |
| 价格标签 | `itemTag__` 类名 |
| 商城 / 时间 | `itemMall__` / `itemTime__` |
| 输出编码 | 页面是 **UTF-8**，读的时候不用转码（只有请求参数要 GBK，输出不用） |

| 能力 | 免登录 |
|---|---|
| 搜商品、看爆料价与价格标签 | ✅ |
| 判断"现在贵不贵" | ✅ 靠标签即可 |

### ⛔ 比价数据本身的三个坑（v5.7 新增，本人 2026-11-04 全踩过一遍）

慢慢买是**用户爆料社区**，不是电商官方价库。它给的是"某天某人看到的价格"，不是"你现在能买到的价格"。三个坑必须逐个排掉：

**坑 1：套装价 / 单头价混淆（最隐蔽，我踩了）**

页面上的爆料标题写商品名，但"已选"规格行显示的可能是**套装版**。一个「页面价 ¥224 − 满 200 减 30 = ¥194」的链路，**¥194 大概率是套装到手价，不是单头价**。

识别方法（三条互相印证）：
1. 看页面"已选"规格行写的是【单头版】还是【套装版】；
2. 看 ¥224 这个数能不能和套装页面对上；
3. 看满减门槛——若 ¥199 吃不到「满 200 减 30」，而 ¥224 刚好够，说明报价是套装口径。

**交付写法**：写 `¥194–199（单头 / 套装口径待核）`，并给用户**一眼定案法**——"打开 SKU，看能不能切到【单头版】；切不到就是套装价"。不要自己挑一个数字当结论。

**坑 2：爆料价 ≠ 到手价，且有过期问题**

爆料里的价格通常含券、含满减、含凑单、含新人价，且有有效期（半年前的爆料价基本失效）。

- **未扣满减的页面价不能当到手价**（会系统性高估 20–40 元）；
- **扣完满减的价格也不能当唯一结论**（券可能没了）；
- 正确做法：给**三档风险带**，不做单点敏感性分析。

| 档 | 含义 | 举例 |
|---|---|---|
| 乐观 | 券全到位 | ¥194（+5.98%） |
| 中性 | 只有基础价 | ¥199（+8.70%） |
| 悲观 | 无券无活动 | ¥219（+19.64%） |

然后判断"在悲观档下结论是否还成立"——这一步比算单点溢价有用得多。

**坑 3：百亿补贴价不代表常态价**

补贴价是**限时 + 限量 + 限账号**的。曾出现某款补贴到 ¥130，若拿它论证"这产品能到 130"，就是误导。

- 补贴价**单独标注**，不参与"距历史最低 %"计算；
- 也不作为"等降价"的预期锚点；
- 报告里写"百亿补贴曾到 ¥X（限时限量），常态价 ¥Y"，两个数分开。

**统一要求**：每条价格必须标明 **`price_nature`**：`单头常态价 / 套装到手价 / 券后价 / 百亿补贴价 / 爆料历史价`。混着写视为未完成价格取证。

### 附带产出的情报（v5.6，别浪费）

搜索结果里如果某型号**一条爆料都没有**，这本身就是结论：

- **零爆料 = 该型号在比价/爆料社区无踪迹**，通常意味着上市太新、销量太小、或不是主流渠道货；
- 结合 Agent 1 的 `market_maturity`，这是判断"新品未验证"的硬指标，比读十篇通稿都准；
- 报告里要写："该型号在慢慢买无任何爆料记录，无价格历史可参考"——**不是"价格正常"，是"没有参照"**。

**价格线交付前自检**：既然一条 URL 就能拿到带标签的报价，**没有任何理由再出现"历史最低"凭记忆写的情况**。拿不到就写拿不到。

**必答三问**：
1. 历史最低价是多少、什么时间、哪个平台？
2. 当前价距历史最低差多少（%）？
3. 下一个可能的好价窗口是什么时候（大促日历 / 新品发布 / 清库存）？

## 促销节奏（判断"现在买还是等"）

- 大促日历：618（6/1–6/18）、双11（10/20 预售–11/11）、年货节、38、开学季。
- **价保规则**：京东通常 7–30 天价保，天猫部分品类 15 天。若大促在价保期内，**先买后退差**是合法策略，必须写明。
- 新品发布周期：发布后 3 个月是价格最硬的阶段；6 个月后首降；换代前清库存降幅最大。
- 国补窗口：政策有截止日，过期即失去 15%，这是"必须现在买"的最强理由，要单独提示。

## 渠道白名单制（v5.1，用户硬约束：不为低价牺牲渠道可靠性）

**平台 ≠ 渠道。** 判断只看店铺主体，不看它在哪个 App 里。同一平台既有官方直营店，也有第三方黄牛。

### 第一步：查品牌官方"直营渠道清单"

正规品牌都会在售后政策页公示。以 DJI 为例，其官方退货政策明确列出 9 个直营渠道：官方商城、天猫官方旗舰店、京东官方旗舰店、**京东自营旗舰店**、抖音官方旗舰店、抖音美拍旗舰店、微信小店、**拼多多官方旗舰店**、小红书官方旗舰店。**只有这 9 个渠道享有官方的 7 天退货 / 30 天换货；其余渠道一律"找卖家"**——这就把风险完全转嫁给消费者。

- 拿不到官方清单的品类，用「店铺名是否含"官方旗舰店"+ 店铺页是否有品牌授权标 + 客服能否开具品牌发票」三条交叉验证。
- **拼多多官方旗舰店属正规渠道**，不要因平台刻板印象误判为 C 级；反之，天猫/京东上的第三方店也不能因平台而升为 A 级。

### 第一步半：百亿补贴的真实定位（v5.4，纠正常见误判）

**不许把"拼多多"整体判为不靠谱，也不许把"百亿补贴"直接等同于官方直营。** 它的准确定位是四个字：**保真，不保新**。

**它有的硬保障**（这些是真的，别当没有）：
- 正品险由**中国人保**承保，鉴定为非正品可主张**假一赔十**
- 入驻需提交 5 类品牌资质：品牌授权书、进货发票、质检报告等
- 品牌黑标店铺**每年平台随机抽检 200+ 次**
- 收货扫码可查**激活日期与销售渠道**（一码溯源）
- 商家 36 小时未处理售后，**平台自动介入**
- 2026-10 新规：缺货不履约按实收金额 **15%** 赔付（10–300 元）

**它没有的**：**新机保证**。"后封机"（七天无理由退货机或被渠道拆封验货后重新塑封）是真实概率事件，社区原话："序列号能查到、激活时间是当天、功能全正常——机器大概率是正品；但塑封可能动过，机身可能有使用痕迹，极端情况会摸到二手充新。"

**已见的档位与处置**：

| 判级 | 特征 | 处置 |
|---|---|---|
| **A** | 品牌官方旗舰店（含拼多多官方旗舰店） | 按白名单购，享品牌官方 7/30 天政策 |
| **B1** | 百亿补贴 + 品牌黑标 + 正品险 | **可考虑，但必须配"九步验机"**，价差 <500 元时不值得 |
| **B2** | 百亿补贴但无黑标 / 非授权店 | 按 C 级处理 |
| **C** | 普通第三方店 | 不推荐 |
| **D/E** | 直播间 / 二手 | 不推荐 |

**B1 下单后的强制动作（缺一不可）**：
1. **下单前录屏**：把商品页、"百亿补贴"标、"假一赔十"承诺全部录下
2. **签收全程不间断录像**：从快递外包装完好状态拍到拆箱、核对序列号、开机
3. 核**三码一致**（盒码 / 机身码 / 系统内码）
4. 查**激活日期**（品牌官网或 App），不是当天即为问题机
5. 看塑封气孔形态、盒底记号笔、贴纸是否歪、云台有无使用痕迹
6. 查**试用次数**（部分机型新机显示固定试用次数，被用过会少）
7. **删视频/相册里是否有他人素材**（二手充新的铁证）
8. 发现异常**先不激活**，走"平台售后入口 → 12315"，不要私下与商家协商
9. 保留开票：无品牌发票则保修只能靠 SN，维权时举证吃亏

**关键陷阱**：部分数码百补商品规则要求"**签收时配合拆封激活核销**"，而**激活即失去 7 天无理由**。这两条叠在一起，意味着你必须在**激活前**完成外观与三码核验——所以第 2 步的全程录像不是可选项，是唯一证据。

**砍单风险**：百补好价单可能被系统砍单退款。被砍后主动找客服，多数能恢复资格；不要默默接受退款。

### 第二步：黑名单一票否决（命中任一，价格再低也不买）

| 命中项 | 判据 |
|---|---|
| 虚假标价被处罚 | 市监局责令改正/处罚文书，或"划线价远高于常卖价" |
| "激活后发" / "已激活机" | 商品页明示，便宜幅度通常只有几十元，却失去全部退换权 |
| 翻新/官换冒充全新 | 投诉 ≥3 条指向同一话术 |
| 拒保投诉 ≥3 条同一话术 | 黑猫/消协 315 检索"品牌+型号+拒绝换货/拒保/判定正常" |
| 换货单/置换机 | 品牌换货订单常被排除在"7 天无理由"之外，等于自断后路 |

### 第三步：白名单内也有硬条款，必须提前告知用户

- **激活 = 失去 7 天无理由**（数码品类普遍约定）。所以验机顺序必须是：先看外观/封条/序列号 → **关机状态摇机身听云台异响** → 再决定是否激活。
- 维权抓手：《网络购买商品七日无理由退货暂行办法》第七条允许"激活后价值贬损大"的商品不适用无理由，**但前提是商家在购买必经流程中设置显著的单次确认**。若下单页只是详情页深处一行小字，可主张该条款不成立。
- 未拆封退货与"换货后再退"是两条不同路径，后者常被拒，不要混用。

## 渠道风险分级（每条价格必须带）

| 级别 | 渠道 | 风险 |
|---|---|---|
| **A** | **品牌官方直营渠道**（见上节白名单）、平台自营 | 最低。有发票、有保修、**在品牌退货政策覆盖内** |
| **B** | 授权专卖店（页面有授权标识） | 低。可能无赠品、退换略慢 |
| **C** | 第三方店铺 / 百亿补贴非自营 | 中。翻新、激活机、官换机、无票风险 |
| **D** | 直播间 / 秒杀 / 拼团 | 高。赠品注水、限量秒没、退货扯皮 |
| **E** | 闲鱼/二手 | 最高。无保修，需验机 |

**必写警示**：C/D 级渠道若比 A 级低 10% 以上，要提示"价差是否值得承担无票与翻新风险"；低 5% 以内一律建议买 A 级。

## 可购买性交付：三件套（v5.5 硬约束，本手册最高优先级）

> 背景（真实翻车）：曾交付"绿联 CA278 ¥89.9"，用户回"搜不到"。原因是 CA278 是官网产品线代码，电商标题只写"支点壳"；而 Agent 4 只回传了价格与型号，没回传检索词与链接。**价格对了，但买不到，等于没做完。**
>
> 铁律：**比价的终点不是"多少钱"，是"用户点哪个链接、搜什么词、选哪个 SKU 才能买到这个价"。**

### 三件套（缺任一 → 该项标 `purchasable: false`，裁决官不得列入第一屏）

| # | 交付物 | 合格标准 | 不合格示例 |
|---|---|---|---|
| 1 | **消费者检索词** `keyword` | 用户直接复制到搜索框就能出结果的**自然语言词**；必须实测过（搜一次看前 3 条是否为目标商品） | `CA278`、`ILCE-7M5`、`KFR-35GW/NhAa1BAj` |
| 2 | **直达链接** `product_url` | 真实商品详情页，**必须 WebFetch 抽验过标题含目标型号** | 联盟跳转、短链、搜索结果页当详情页、失效页 |
| 3 | **SKU 选择路径** `sku_selector` | 进页面后怎么选到目标机型/容量/版本；标题混写多代时必须写防错提示 | 只写"选 iPhone 18 Pro Max"，没说标题会写 17PM |

### 链接质量分级（每条价格必须标 `url_quality`）

| 等级 | 形态 | 处置 |
|---|---|---|
| `primary_detail` | `item.jd.com/{sku}.html`、`detail.tmall.com/item.htm?id={itemId}`、品牌官网商品页 | ✅ 可直接交付 |
| `brand_store` | 品牌官方店铺首页（无单品页时） | ⚠️ 可用，但必须配 `keyword` 与 `sku_selector` |
| `search_fallback` | `search.jd.com/Search?keyword=…`、`s.taobao.com/search?q=…` | ⚠️ 次优，仅当拿不到详情页时用，须注明"搜索直达，非单品页" |
| `affiliate_redirect` | `union-click.jd.com`、`s.click.taobao.com`、`u.jd.com`、`m.tb.cn`、各类联盟码 | ❌ **禁止交付**。带追踪参数、易失效、可能跳错商品；用户体验是"点了打不开" |
| `unverified` | 未能打开的链接 | ❌ 禁止交付，降级为"来源不可复核" |

> **联盟链接不得直接给用户**，哪怕它当时能打开。正确做法：从联盟页取到**商品标题全文 + 店铺名 + skuId**，用标题关键词构造 `search_fallback` 链接，或直接找 `primary_detail`。若只能拿到联盟链，标 `url_quality: "affiliate_redirect"` 并**不写进 `product_url`**，改写进 `data_gaps`。

### 型号代码专项（`search_entry`）

内部型号/料号必须显式判定"能否直接搜到"，**不允许默认它能搜**：

- `code_is_searchable: false` 时，`keyword` **必填**，并在 `keyword_note` 写明为什么搜不到（如"型号仅出现在参数表，标题只写功能词"）。
- 同一代码跨代/跨型号共用时（如手机壳 CA278 覆盖 iPhone 17/18 两代、空调一拖多机型），必须写 `code_locks_model: false` 并给出 `sku_selector` 的**防错提示**（标题混写哪几代、默认 SKU 常是上一代）。
- 判定方法：拿代码去搜一次，前 3 条结果若无目标商品 → 判 `false`，**不得因为"官网有这页"就判 true**。

### 必做验证（不写进 JSON 视为未完成）

1. **搜一次**：用 `keyword` 实际搜，确认前 3 条命中目标商品。
2. **点一次**：WebFetch 打开 `product_url`，确认标题含目标型号、价格与记录一致。
3. **选一次**：确认 SKU 选择器里存在目标机型/容量，并记下它的**默认选中项**（常是上一代，这是最隐蔽的坑）。

### ⛔ 禁编商品 ID / 商品链接（v5.5，最高优先级）

国内电商（京东、天猫/淘宝、拼多多）对自动化访问有强频控。实测 2026-11-02：

- `union-click.jd.com/...` → 返回「**PC 频控页**」"暂时无法展示该商品的信息"
- `search.jd.com/Search?keyword=...` → 返回「**京东验证**」滑块页
- 淘宝 `s.click.taobao.com` / `s.taobao.com` → 需登录或跳转验证

**因此：拿不到、也验证不了 `primary_detail` 是常态，不是失职。** 此时正确做法是**退化为"App 内搜索词 + Web 搜索直达链接"并诚实标注**，绝对禁止：

| ❌ 严禁 | 为什么 |
|---|---|
| 凭印象写 `item.jd.com/100xxx.html` | 编造商品 ID，用户点开是别的商品或 404 |
| 把搜索结果页 URL 当成单品详情页 | 用户以为买到了，实际要自己再找 |
| 把频控页/验证页当"已验证可打开" | 谎报 `url_verified` |
| 用 `purchasable: true` 掩盖没有链接的事实 | 最严重的失真 |

**允许的降级交付**（此时 `url_quality` 必须如实标）：

```
url_quality: "search_fallback"
url_verified: false
verify_note: "京东/淘宝频控拦截自动化访问，未能程序化验证；链接为标准搜索入口，人工浏览器可正常打开"
keyword: "绿联 支点壳"        ← 主交付物，用户首选在 App 内搜
search_url: "https://search.jd.com/Search?keyword=%E7%BB%BF%E8%81%94%20%E6%94%AF%E7%82%B9%E5%A3%B3&enc=utf-8"
```

> 判断口径：**能给"用户 3 秒内买到"的检索词 + SKU 路径，比给一个打不开的链接有价值得多。** 两者都拿不到才判 `purchasable:false`。

## 交付纪律

- **回传摘要必须带三件套**，缺一项即视为本线未完成（见下方摘要模板）。
- **每条价格必须标 `price_nature`**（v5.7）：`单头常态价 / 套装到手价 / 券后价 / 百亿补贴价 / 爆料历史价`。分辨不出就写"口径待核"，并给用户一眼定案法（切 SKU 看单头/套装）——**禁止自己挑一个数字当结论**。
- **口径不明时必须给三档风险带**（v5.7），不做单点敏感性分析；然后判断"悲观档下结论是否还成立"。
- **百亿补贴价不参与"距历史最低 %"计算**（v5.7），单独标注"限时/限量"，也不作"等降价"的预期锚点。
- 每个价格都要能在报告里点开 `product_url` 复核；拿不到链接的写"来源：口头/爆料，不可复核"，并标 `purchasable: false`。
- **区分"限时价"与"日常价"**：只出现在某一场直播的价格不能当作常态价。
- 若发现渠道价差 >15%，必须提示"同型号不同渠道可能存在版本/配件差异（标准版 vs 畅拍版）"。
- 结论输出四件事：**历史低价、当前最优到手渠道（含链接与 SKU 路径）、建议买点（现在/等 X 天）、不能直接买的款缺什么**。不评价产品好坏。

### 回传摘要模板（≤15 行，三件套必填）

```
1. 【检索词】用户搜：`<keyword>`（平台：<platform>）｜代码 `<model_code>` 是否可搜：<是/否>
2. 【直达链接】<product_url>（url_quality: <等级>｜已抽验：<是/否>）
3. 【SKU 路径】<sku_selector>
4. 【最优到手价】¥<X>（<店铺>，<date>）｜常卖 ¥<Y>｜历史最低 ¥<Z>（<date/平台>，<可信度>）
5. 【价差】当前距历史最低 <+X%>
6. 【国补】<适不适用 / 口径冲突点 / 需结算页核实>
7. 【买点】<现在买 / 等 X 日，理由>
8. 【买不到的款】<型号：缺检索词/链接/SKU 中的哪项，已标 purchasable:false>

```

**v6.0 的流程，一句话记住**：
**定档（Step -1）→ 核三条命 → 按档派活（Step 1）→ 三层输出（零层给家人 / 一层讲排除法 / 二层留审计）→ 另出分享版。**

**两条贯穿 6.0 的原则**（比任何细节都重要）：

1. **易懂 ≠ 无论证。** 把表格换成条形图，论证一点没少；把论证删掉，那才是真的没论证。
2. **砍格式不掉准确性，砍核实直接买错货。** 省钱只能省在产出形态上，不能省在「口径／行货价／门槛真伪」这三条上。

**6.0-② 三层输出（2026-11-05） —— 起因：用户反馈报告可读性不足，要求零术语、长辈也能看懂**

诊断：不是排版问题，是**把审计底稿当成交付物**。一份 ¥90 的数据线报告写了 12 张表 + ROI/EAC/QPR/信源三层打分，"结论先行"下面还是四行嵌套表格——用户拿这份东西给家里人看，一眼就被术语挡在门外。

改动两处：

| 层 | 改动 |
|---|---|
| `output_template.md` | 新增**三层结构与术语翻译表**：零层一屏（给长辈，零术语零表格不滚动）→ 一层半页（给用户）→ 二层附录（给审计）。术语一律下移：`EAC/QPR/ROI/投毒指数/L1–L4` **不得上浮**；`20Gbps`→「传一部电影几秒钟」、`240W`→「笔记本能满速充」、`4K60`→「接显示器画面不卡」 |
| `SKILL.md` Step 4 | 零层升为最高优先级：只答四问（买哪个/多少钱/去哪买/**别买错什么**），**一屏失败＝整份报告失败**；并要求用 `show_widget` 渲染大字卡片，**禁止用 markdown 表格冒充可视化** |

**自检标准（写死）**：如果我妈看完这一屏还要问「所以到底买哪个」，这一屏就是失败的。

**6.0-① 预算分级（2026-11-05） —— 起因：一根 ¥90 的数据线跑了全套四线，消耗远超常规，投入产出倒挂**

用户反馈单次任务成本超标。复盘结论写进 Step -1：**成本集中在产出格式，不集中在判断**。真正避免买错货的两次核实（官网验规格、追问价格来源）各只值一次抓取/追问；而四问对价表、投毒评分、信源三层打分、7 次重算占了绝大部分开销，对「买哪根线」的边际贡献接近零。

四个改动：

| 层 | 改动 |
|---|---|
| **新增 Step -1** | 按标价分 S/A/B/C 四档，各自规定「保留什么/砍掉什么/交付多长」；默认走档，命中条件才升 |
| **三条命（新铁律）** | 任何档位都不得砍：①口径与默认 SKU ②价格是否为大陆行货到手 ③门槛二值规格的真伪。**这三条是「买对」的充分条件，其余都是「买得便宜」** |
| **强制升档** | 安全关键品类（涉电涉水涉婴/锂电/承重/制动）不低于 A 档；虚标高发品类（线材/充电头/电池/存储卡/灯具）C 档也须验门槛。**低价 ≠ 低风险，这条搞反才会真出事** |
| **Step 1 收口** | 派发数量必须与档位匹配：C/B 档**不派四个 Agent**，改为单线 + 定向检索；只有 S/A 档才走四线并行 |

**反面教训（写进纪律）**：本次顺序搞反——先算 EAC 后拿价格，结果价格三次推翻（¥202 是香港价、绿联 SKU 错位、贝尔金 40Gbps→20Gbps），定量表重算 4 次。**正确顺序永远是：先拿一手价格与规格，再算对价。**

**v5.8（2026-11-04）· 品类适配层 —— 起因：用户明说「充电头只是用来测这个技能的，我还要用它买别的东西」**

前两轮都是用充电头一个品类压测，然后把它的具体知识（媒体名、协议名、价格坑）写进通用规则。规则文件正在变成「充电头专用说明书」，换品类就会失效甚至误导。

四处症状：

1. **信源档案只有充电垂类** —— 买耳机时查这张表，会把「表里没有」误当「可信」。
2. **案例塞在规则文件里** —— 案例污染规则，越迭代越偏。
3. **慢慢买被写成「默认第一入口」** —— 买保险 / 课程 / 软件订阅时根本不适用，硬跑的空结果会被误读成「该商品没有历史低价」。
4. **顺手查出一个实质错误** —— 原文写「L2 只留给消协/SGS/TÜV」，但 SGS/TÜV/华测的报告**绝大多数是厂商付费委托的**，按「钱从哪来」应记 L3b。看到大机构 logo 就当 L2，是最容易犯的升级错误。

四个改动：

| 层 | 修复 |
|---|---|
| **品类层（新）** | 新增 `references/category_profiles.md`：13 类品类的门槛候选 / 关键指标 / 垂类信源 / 权重调整 / 典型坑，外加**表外品类兜底四问**（覆盖无限品类）与**非实物类专章** |
| **案例层（新）** | 新增 `references/cases.md`：5 个案例各带**跨品类映射表**。规则文件不再塞案例，改引用 |
| **信源层** | 档案库从「5 个站名」重构为「**7 类商业模式** + 已知条目」，任何品类的任何新源都能归类；并新增 `audited` 字段与铁律“**表里没建档 ≠ 可信**” |
| **流程层** | Step 0 新增 **Step 0-a 查品类档案**（含三种分流）；Step 3 新增**权重覆盖检查**（`noise` 默认值对空调/扫地机/耳机是错的） |

**核心方法**：品类专属知识下沉到 `category_profiles.md`，规则文件只保留与品类无关的判据。**新增品类只改那一个文件，不动 agent1–4。**

**v5.7（2026-11-04）· 信源可信度改造 —— 起因：v5.6 补了"必须有实测"，但没问"这个实测值几分"，把收费实验室的定制测试和网友借机的独立实测一律记成 L2**

v5.6 上线当天就被追问："第三方实测的来源是哪里？可信度多少？博主靠软广吃饭，可信度到底有多少？"

这一问问出了三件事：

1. **充电头网自营收费测试实验室**，官网原话"接受厂商定制的检测模式……欢迎厂商前来测试产品"。**它既是评测媒体，又是收费测试服务商，客户就是它评测的那些厂商**——结构性利益冲突。
2. **我把媒体实测记成 L2 是等级定错了。** L2 的定义本来就写了"检测机构"，媒体/博主无论多专业只能算 L3。
3. **查证过程反手推翻了我自己两条结论**：我说的"C3 可接 iPhone"是硬错（C3 单口仅 40W）；"安克硬件不支持 AVS"是过度外推到品牌级（实为型号级，新批次 A120M 已达 52.64W 握手 AVS）。

四个改动：

| 层 | 原缺陷 | 修复 |
|---|---|---|
| **等级层** | 媒体实测被记成 L2，与消协/SGS 同级 | **L2 只保留给无商业关系的检测机构**；媒体实测一律 L3，再按信源分 L3a（网友借机/自购 0.75–0.85）/ L3b（送测 0.60–0.70）/ L3c（付费测试 0.45–0.55） |
| **审计层（最致命）** | 只问"有没有实测"，不问"这个实测谁付的钱、能否复核" | Agent 1 新增**第四道检验：信源可信度审计**——四类商业模式归类、两条硬指标（`measurable` / `conflict`）、争议检索模板、已知档案库 |
| **加权层** | 同样 L2 的证据被等权对待，可信度实际差一倍 | 契约新增 `source_audit`；`professional_reviews` 每条必带 `source_business_model` / `sample_source` / `measurable` / `conflict` / `source_credibility` |
| **纪律层** | 引用实测只写"XX 实测显示"，不交代利益关系 | 引用必须写成"来源：X（网友借机/送测/付费）｜可复核：是/否｜利益冲突：低/中/高" |

**核心方法论（跨品类通用）**：可信度不能给总分，必须分层——**同一机构在「记录事实」和「发表评价」上差 3 个数量级**。推论是一条反向铁律：**利益冲突只削评价层，不削事实层**。看到利益冲突就否掉全部事实，等于把自己逼回"只看厂商参数表"，那是更严重的错误。正确动作是**取事实层，弃评价层**。

**v5.6（2026-11-04）· 证据强度改造 —— 起因：四线全交齐、格式全对，但专业评测证据 0 条，把一款上架 9 天的零实测新品推成首选**

那轮充电头选品（iPhone 18 PM + MacBook，要屏显）的原始结论是"安克 A2697 140W 单口 ¥183.05 首选"。用户实测复核直接击穿：

1. **"都是在对比纸面参数，有没有用户真实反馈"** —— 补完 L2/L3 证据后结论整个反转：安克 A2697 **不支持 PD3.2 SPR AVS**（只有 EPR AVS 15–28V），给 iPhone 18 PM 只有 **44W**，比 ¥168 的图拉斯 60W **还慢 8W**。纸面 140W 打 60W，实测倒过来。
2. **"比价上慢慢买就行，基础比价不用登录"** —— 用慢慢买一查，我给的 ¥183.05 在价格库里**根本不存在**，真实京东自营价是 ¥213.99、历史最低 ¥201.05。

五个根因，逐条封堵：

| 层 | 原缺陷 | 修复 |
|---|---|---|
| **取证层（最致命）** | 没有任何一线负责"专业评测取证"。Agent 1 只查负面，Agent 2 只提参数，Agent 3 没有这项检查——四个 Agent 都不管"这产品被专业测过没有" | Agent 1 扩权为**双类事实**（负面事实 + 专业评测事实）；检索模板新增「专业评测取证」5 条 + 专业源白名单；契约新增 `professional_reviews` / `source_independence` / `market_maturity` |
| **判据层** | 只比"多少"（140W > 60W），不比"有没有"（支不支持 SPR AVS） | Agent 2 新增**第一步半：门槛型规格筛查**，二值型/跨代断层/隐性/锁定性四类判据，门槛不满足直接出局、不进 QPR |
| **成熟度层** | 参数表没有"上市多久、几条评论、几次实测"，零评论新品与 2 万评论产品同台 | Agent 2 新增**市场成熟度入模**：`unproven` 判定（<30 天 / 零实测且评论<100 / <90 天且零实测），unproven 不得作首选 |
| **信源层** | 把"同一篇通稿被 4 家转载"当成"4 家独立来源可核" | Agent 1 新增**信源独立性检验**：通稿无论转载多少次只计 1 源，转引计 0 源；四步识别法（首段雷同/有无实拍图/有无仪器型号/发布日集中） |
| **价格层** | 手册记"慢慢买免登录接口已全部下线"→ 直接跳过该站 → 绕远路且给出错价 | 修正为"**只有历史曲线 API 下线，搜索层免登录可用**"；新增实战章节 + 内置脚本 `scripts/manmanbuy_price.py`（GBK 编码坑、解析要点、零爆料=无参照） |

同时新增**推荐强度分级**（强烈推荐 / 推荐 / 推荐（需自证）/ 可选 / 观望 / 不推荐），第一屏必须标级并写"凭什么"。等级不得高于证据等级。

## 历史版本

**v5.5（2026-11-02）· 可购买性改造 —— 起因：交付"绿联 CA278 ¥89.9"，用户回"搜不到"，报告实际价值为零**

三处根因，全部封堵：

| 层 | 原缺陷 | 修复 |
|---|---|---|
| 数据层 | Agent 4 的 JSON 契约**没有 url 字段**，手册却要求"点开链接复核"——无处存放 | 契约新增 `search_entry` / `product_url` / `url_quality` / `sku_selector` / `purchasable` / `best_buy` |
| 传递层 | 回传摘要模板只有"多少钱 + 哪个平台"，链接在第 1 层就丢 | 摘要模板改为**三件套必填**，缺一项即判本线未完成 |

同时新增**跨品类铁律「型号代码 ≠ 检索词」**（CA278→"支点壳"、ILCE-7M5→"索尼 A7M5"），以及**联盟跳转链禁入**规则（union-click / s.click / u.jd.com / m.tb.cn 一律不写进报告）。

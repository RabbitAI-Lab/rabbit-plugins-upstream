# 工业测试用例格式规范（固定内容，生成时必读）

> **版本**：V1.0.5 | 本文件为 SKILL.md 的固定格式规范——**字段结构与输出格式以此为准**，SKILL.md 负责流程与决策。生成用例与输出 Excel 前**必须通读本文件**。

## 1. 用例字段结构

| 字段 | 必填 | 说明 |
|------|:----:|------|
| 用例编号 | ✅ | `TC-{模块前缀}-NNN`（如 TC-ALM-001） |
| 业务域/模块 | ✅ | 与阶段一输出一致 |
| 优先级 | ✅ | P0/P1/P2/P3 |
| 测试维度 | ✅ | 功能/协议/通信/性能/可靠性/安全性/网络安全/环境/兼容性 |
| 用例类型 | ✅ | 冒烟/功能/回归/探索性/故障注入 |
| 设计方法 | ✅ | 场景法/边界分析/等价类/判定表/状态迁移/故障注入/错误猜测 |
| 测试场景 | ✅ | 如「主流程：高温报警触发与恢复」 |
| 测试点 | ✅ | 具体验证点 |
| 操作步骤 | ✅ | 3-5 步，每步含 `步骤` + `操作` + `预期` |
| 测试数据 | ✅ | 具体值（温度、压力、寄存器值…） |
| 前置条件 | ✅ | 现场/仿真状态、设备就绪 |
| 需求来源 | ✅ | 关联的阶段二需求编号 |
| 协议/点位 | 🅰️ 领域列 | Modbus 地址/OPC 节点/Tag/寄存器 |
| 测试环境 | 🅰️ 领域列 | 现场/虚拟PLC/半实物 及版本 |
| 测试级别 | ✅ | 单元/集成/系统/验收，执行层级见 SKILL.md 3.13 |
| 源文件 | 🅱️ | 批量模式下标记文件来源 |

> 🅰️ 为工业领域扩展列，Excel 中固定为「协议/点位」「测试环境」两列。

## 2. 用例编号规则

- 格式：`TC-{模块前缀}-NNN`，前缀取自 SKILL.md 阶段一前缀表，保持全局唯一
- 编号连续递增，不与需求编号冲突

## 4. Excel 输出规范

### 4.1 生成方式

用 Python（openpyxl）内联生成 xlsx 文件，无需外部模板。文件命名：`{项目名}_工业测试用例_{YYYYMMDD}.xlsx`，保存到 `output/`。工作簿含两个 sheet：**`用例`**（15 列）+ **`覆盖统计`**。

### 4.2 Sheet1 用例（15 列标准结构，顺序固定）

| # | 列名 | 说明 |
|---|------|------|
| 1 | 用例编号 | TC-{前缀}-NNN |
| 2 | 业务域/模块 | 与阶段一一致 |
| 3 | 优先级 | P0/P1/P2/P3 |
| 4 | 测试维度 | 功能/协议/通信/性能/可靠性/安全性/网络安全/环境/兼容性 |
| 5 | 用例类型 | 冒烟/功能/回归/探索性/故障注入 |
| 6 | 设计方法 | 场景法/边界分析/等价类/判定表/状态迁移/故障注入/错误猜测 |
| 7 | 测试场景 | 一段场景描述 |
| 8 | 测试点 | 具体验证点 |
| 9 | 操作步骤 | 每步 `{步骤}. 操作 → 预期`，步骤间用换行 chr(10) |
| 10 | 测试数据 | 具体值 |
| 11 | 前置条件 | 环境+设备状态 |
| 12 | 需求来源 | REQ-编号 |
| 13 | 协议/点位 | Modbus 地址/OPC 节点/Tag/寄存器（领域扩展列） |
| 14 | 测试环境 | 现场/虚拟PLC/半实物 及版本（领域扩展列） |
| 15 | 测试级别 | 单元/集成/系统/验收，执行层级见 SKILL.md 3.13 |

### 4.3 Sheet2 覆盖统计（需求追溯矩阵 + 覆盖率证明）

- 需求覆盖率：每条需求（REQ 编号）→ 覆盖用例数，必须 100%（无孤例需求）
- 模块 × 测试维度矩阵：核心层 ≥7 维度、重要层 ≥5 维度
- 优先级分布：P0/P1/P2/P3 数量与占比（P3 参考 10~30%）
- 设计方法统计：每模块方法数 ≥3
- 标准覆盖率：引用标准的需求 → 合规用例数

### 4.4 样式规范

| 项 | 规范 |
|----|------|
| 表头 | 深色填充（如 1F4E79）+ 白色加粗字体 + 冻结首行 |
| 优先级着色 | P0 红底(FFC7CE)/深红字(9C0006)；P1 橙底(FFEB9C)/棕字(9C6500)；P2 绿底(C6EFCE)/深绿字(006100)；P3 灰底(D9D9D9)/深灰字(595959) |
| 模块分隔行 | 每个模块前插入一行 `【模块名称】`，浅蓝填充(DDEBF7)加粗，跨列合并 |
| 换行 | 操作步骤用 chr(10) 拼接 + wrap_text，不用 `\n` 字符串 |
| 列宽 | 用例编号 14 / 场景 30 / 操作步骤 50 / 其余 18；行高自适应 |
| 边框 | 全部数据单元格细边框 |

### 4.5 输出验证清单（Ⓜ = 机器可断言项）

- [ ] 用例表列数完整（15 列）、顺序正确 Ⓜ
- [ ] 编号连续且前缀唯一（TC-{前缀}-NNN）Ⓜ
- [ ] 优先级分布合理（P0 10-20%, P1+P2 60-80%, P3 参考 10-30%）Ⓜ
- [ ] 每个模块设计方法 ≥ 3 种 Ⓜ
- [ ] 每个模块「用例类型 = 回归」≥ 1 条 Ⓜ
- [ ] 交付物覆盖全部 4 个测试级别（单元/集成/系统/验收 各 ≥1）Ⓜ
- [ ] 试验项级标准覆盖率 100%（对照「标准-试验项矩阵」，覆盖统计 sheet 输出 标准×试验项×用例数）Ⓜ
- [ ] 「覆盖统计」sheet 已生成：需求覆盖率 100%、标准覆盖率 100%、模块×维度达标
- [ ] 模块分隔行 `【模块名称】` 齐全
- [ ] 优先级颜色正确（P0红/P1橙/P2绿/P3灰）
- [ ] 换行用 chr(10) + wrap_text

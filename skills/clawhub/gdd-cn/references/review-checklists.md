# 专家视角自检清单

不派子代理，主会话自己按视角过清单（本地没有对应专家代理，派发只会空转；若你已配置对应代理，可改用 Task 派发，角色名见 `naming-glossary.md` 第二节）。

模式与视角对应关系见 SKILL.md 第 5 节。

每个视角的输出格式固定：
```
[视角] 自检 · [系统名] · 第[N]段
发现 N 项：
1. [发现描述]
   风险：[高/中/低]
   建议：[具体怎么改]
   依据：[为什么]
```
然后用 `AskUserQuestion` 逐条问采纳 / 不采纳，不自己改。

---

## 数值视角（第四、五段）

- 公式变量是否全部定义，量纲是否自洽（秒 + 秒，不要秒 + 帧）
- 输出范围是否覆盖早期 / 中期 / 后期，每个阶段的量级是否合理
- 极值代入会不会溢出 / 归零 / 负数（LV 1 和 LV 999 都算一遍）
- 曲线是线性 / 对数 / 阶梯，为什么这么选，玩家能不能感知到变化
- 有没有无脑最优解（退化玩法），一条路径明显碾压其他所有路径
- 是否和其他系统的数值打架（战力公式、经济产出、成长速度）
- 可调项之间是否互相覆盖（改 A 让 B 失效）
- 是否符合项目既定的数值公式（例：敌 HP = base × 1.22^波次）
- 概率类数值是否用了万分比整数，是否做过抽样验算

---

## 战斗手感视角（第二、三、六段）

- 玩家在这套规则下做决策的点在哪，是不是有意义的选择（不是假选择）
- 有没有「看起来能操作其实没差别」的假选项
- 输入到反馈的延迟要求（手感容不容易做出来）
- 成功 / 失败的反馈是否可感知（玩家知道刚才发生了什么吗）
- 连续操作的节奏（多久一次正反馈，会不会无聊）
- 玩家**不能**做什么，约束是否清晰可传达
- 边界情况会不会被打造成可利用的漏洞（而非 bug）

---

## 表现视角（第三段、表现需求段）

- 关键事件有没有对应的表现（命中 / 暴击 / 失败 / 状态变化）
- 表现是否可区分（不同结果玩家能否一眼分辨）
- 资源量级估算（特效数量 / 同屏上限 / 贴图预算）
- 是否有现成资源可复用，还是要新产
- 低端机降级方案有没有
- 音频：关键事件有没有声音反馈，静音时是否有视觉替代

---

## 验收视角（第八段）

- 每条标准 QA 不看文档能否执行
- 前置条件是否可构造（测试怎么进到那个状态）
- 预期结果是否可量化（不许写「表现正常」「效果良好」）
- 是否覆盖：核心规则每条、公式每个、边界每条
- 是否覆盖跨系统交互（不只是本系统孤立测）
- 是否有性能相关标准（帧时间 / 内存 / 同屏单位数）
- 是否有异常恢复标准（断线重连 / 存档损坏 / 数据越界）
- 反面用例是否覆盖（玩家故意乱搞的路径）

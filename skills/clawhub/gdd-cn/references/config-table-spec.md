# 配置表规范

写第五段（配置表结构与可调项）前必读。核心原则：**文档写规则，表写数值。**

## 一、为什么要落表

- 策划要改数值不该动文档正文，改配置表就行。
- 文档里的示例数值必须注明「取值见 [表名].[字段]」，否则就是裸数值。
- 程序直接读表，不读文档。文档里的数算「人话说明」，表的数是「真相来源」。

## 二、表结构模板（Markdown 描述版）

```
#### 表：[前缀]_[表名]（[中文名]）
用途：一句话说清这张表管什么

| 字段 | 类型 | 必填 | 默认 | 取值范围 | 策划可调 | 说明 |
|---|---|---|---|---|---|---|
| id | int | 是 | — | 1~999999 | 否 | 主键，全局唯一 |
| name | string | 是 | — | ≤20 字 | 是 | 显示名 |
| type | enum | 是 | 0 | 见枚举表 | 否 | 0=近战 1=远程 2=召唤 |
| ref_xxx_id | int | 是 | 0 | 外键→[表].id | 否 | 关联 XXX |
```

枚举表紧跟字段下方：
```
枚举 type：0=近战 / 1=远程 / 2=召唤
```

## 三、字段规范（每条都不可省）

1. **每张表必须有 id 主键**，全局唯一，不允许重复或留空。
2. **枚举必须数值化**并附枚举表，禁止表里存中文枚举值（存 "近战" 不算数，存 0 才算）。
3. **跨表引用用外键字段**，命名 `ref_[目标表]_id`，注明指向哪张表的 id。
4. **字段类型必须标**：int / float / string / bool / enum / vec2 / array。
5. **取值范围必须写**，含上下边界，没有上限就写「无上限」。
6. **策划可调 = 是** 的字段，才叫「可调项」，要写进第五段。
7. **默认值必须写**，没有就写 `—`，不许留空。
8. **数值字段标单位**：秒 / 米 / 百分比 / 万分比 / 级。

## 四、命名规范

- 表名：`[模块前缀]_[表名]`，前缀 2-4 位大写字母。例：`WZ_风区`、`CH_角色`。
- 字段名：小写下划线，例：`base_hp`、`drop_weight`。
- 布尔字段：`is_` / `can_` 前缀，例：`is_boss`、`can_stun`。
- 时间统一用秒，字段名带 `_sec`，例：`cooldown_sec`。
- 比率统一用**万分比整数**存储（避免浮点误差），字段名带 `_perm` 或 `_rate` 并注明万分比，展示时除 10000。

## 五、配置表与文档的分工

| 写在哪里 | 内容 |
|---|---|
| 文档（第四段公式） | 怎么算：公式结构、变量含义、曲线类型 |
| 表（第五段） | 算的时候取什么数：常数项、阈值、权重、倍率 |
| 文档（第五段） | 表的用途、字段含义、哪些是策划可调、哪些互斥 |

示例：
```
公式（文档）：伤害 = 基础攻击 × 攻击倍率 × (1 + 暴击加成)
取值（表）：基础攻击见 CH_角色.base_atk；攻击倍率见 WZ_技能.atk_rate；暴击加成见 BUFF_暴击.crit_add_perm
```

## 六、常见错误（自检时对照）

- ❌ 正文写「暴击率 25%」却不指明表字段 → 这是裸数值。
- ❌ 枚举写「type = 近战」 → 必须写成 `type = 0`，附枚举表。
- ❌ 外键只写「关联角色」 → 必须写 `ref_char_id → CH_角色.id`。
- ❌ 取值范围写「适量」 → 必须写具体边界。
- ❌ 把所有数字都塞进一个表 → 按模块拆表，一张表只管一类数据。
- ❌ 可调项没标「策划可调」 → 程序会把它当写死的常量，策划改不了。

# 章节写作细则

八段每段：写之前问什么、写完算什么、反面样例是什么。写某段前读对应小节。

## 骨架模板

## 一段：系统概述

- **问**：这系统用一句话是什么？玩家怎么跟它打交道（主动/被动/自动）？没它会怎样？
- **完成标准**：一个陌生人读一段能懂它是什么、干什么、为什么存在。
- **文风**：行为层面，别说怎么实现。涉及实现的问题（用单例还是事件总线？）标「→ 进技术方案」，别在 GDD 里写。

## 二段：设计目的与体验目标

- **问**：玩家应该爽在哪？对标哪些产品做得好（具体是哪一点做得好）？这是「玩家直接爽」还是「玩家爽它带来的结果」？
- **完成标准**：写出体验目标 + 至少一个可参照的竞品锚点。必须跟核心支柱对得上，对得上就引一句支柱原文。
- **反面**：只写「提升游戏体验」 → 不算写完。

## 三段：详细规则

- **问**：典型使用流程走一遍；玩家要决策的点在哪；玩家**不能**做什么（约束和 capability 同等重要）。
- **完成标准**：程序照着能写，不用回头问。拆三小节：
  - 核心规则：顺序流程用编号，属性用要点。
  - 状态与流转：有状态就画表，列出每个状态和每条合法跳转。
  - 跨系统交互：每个上下游系统，写清传什么进、传什么出、接口谁拥有。
- **反面**：写「系统负责处理战斗逻辑」 → 不算写完。

## 四段：公式与数值

- **问**：这系统做哪些核心计算？缩放是线性 / 对数 / 阶梯？早期 / 中期 / 后期的输出范围？
- **完成标准**：每个公式都按这个结构写：
  ```
  [公式名] 定义为：
  [公式名] = [表达式]

  **变量：**
  | 变量 | 符号 | 类型 | 范围 | 说明 |
  |---|---|---|---|---|
  | [名] | [符] | float/int | [min~max] | [代表什么] |

  **输出范围：**[min]~[max]（正常对局）；[极值表现]
  **示例：**[带真实数字的演算]
  ```
- **反面**：写「[公式待定]」或只有文字描述没变量表 → 不算写完。变量不定义程序没法实现。

## 五段：配置表结构与可调项

写之前先读 `references/config-table-spec.md`。

- **问**：哪些值策划应该不改代码就能调？每个旋钮调太高/太低会出什么事？哪些旋钮互相覆盖（改 A 让 B 失效）？
- **完成标准**：至少给出 1 张配置表（按模板），字段含 id / 类型 / 枚举 / 外键 / 取值范围 / 是否策划可调 / 默认值。可调项列出「策划可调=是」的字段，并注明互相影响关系。
- **反面**：数值全堆在文档正文，没有表 → 不算写完。

## 六段：边界情况

- **问**：归零、封顶、越界各怎样？两条规则同时触发怎样？玩家挖出非预期交互（退化玩法）怎样？
- **完成标准**：每条写成 `**如果 [条件]**：[确切结果]。[非显然的理由]`。必须给出确切处置，不许「妥善处理」。
- **反面**：写「边界情况需进一步讨论」 → 不算写完，这是未决问题不是规格。

## 七段：依赖与接口

- **问**：还漏了哪些依赖？每个依赖具体的数据接口是什么？哪些是硬依赖（没它跑不了）、哪些是软依赖（有它更好）？
- **完成标准**：双向一致——本系统写「依赖战斗」，战斗 GDD 就该写「被 [本系统] 依赖」。单向的要标出来纠正。
- **反面**：只列系统名不写接口 → 不算写完。

## 八段：验收标准

- **问**：最少哪些测试能证明它没坏？性能预算（帧时间 / 内存）给多少？QA 第一眼看什么？
- **完成标准**：每条按 **前置 / 操作 / 预期** 三段写（对应西方的 Given-When-Then）：
  ```
  - **前置** [初始状态]，**操作** [玩家动作或系统触发]，**预期** [可量化结果]
  ```
  至少覆盖：第三段每条核心规则各一条 + 第四段每个公式各一条。QA 不看文档也能独立执行。
- **反面**：写「系统按设计工作」 → 不算写完。

## 九段：表现需求（按系统类型决定必写/选写）

- 战斗/角色/UI/特效/剧情/关卡类：**必写**，不给跳过。事件要有什么表现反馈、动画/特效风格约束、镜头/音效要求，写清，不写 `[待设计]`。
- 其余类型：八段写完后问你要不要加。
- 写了实质内容后提示：后续跑 UX 说明补每个界面/HUD 的 UX 规格，开发不要直接抄 GDD。

## 十段 / 十一段：UI 需求 / 待定问题

- UI 需求：复杂 UI 系统拉 UX 设计对齐。有实质内容就提示补 UX 规格。
- 待定问题：设计过程中没定下来的，每条带负责人和目标解决时间。

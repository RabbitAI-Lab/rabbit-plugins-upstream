# 场景：query-enterprise-profile-by-uscc（按税号查询企业信息）

## 模板用途

用于在风险分析前，基于统一社会信用代码（税号）联网检索企业公开信息，产出纳税人类型（小规模/一般）与经营范围。

## 调用说明（非接口）

- 本 skill 为编排内检索能力，不是 HTTP/RPC 接口。
- 在主场景中应描述为“执行本 skill 的检索流程”，避免描述为“请求某接口”。
- 本 skill 无固定接口地址、无请求体协议约束，不产出接口调用日志。
- 本 skill 内部支持“优先内部数据源、失败再公网检索”的双路径策略；对话层仅回显业务结果，不回显接口报文全文。

## 触发关键词

税号查询企业信息、统一社会信用代码查询、判断一般纳税人/小规模纳税人、查询所属行业、查询经营范围、补齐风险分析企业画像。

## 场景说明

- 业务目标：根据税号输出可用于风险分析的企业画像字段（taxpayer_type、business_scope）。
- 典型用户：需要执行发票风险分析的财税人员、审计人员、业务运营人员。
- 使用前提：用户已提供有效税号（统一社会信用代码，通常 18 位）。
- 输入来源：自然语言输入 / 结构化参数 / 上下文记忆

## 输入与约束

| 输入项                         | 是否必需 | 说明                                             | 缺失处理       |
| ------------------------------ | -------- | ------------------------------------------------ | -------------- |
| uscc（统一社会信用代码）       | 是       | 企业税号，作为唯一检索主键                       | 追问用户       |
| areaCode（地区编码）           | 是       | 内部数据源查询所需地区编码（例如深圳为 4403）    | 追问用户       |
| personalAccount（个人账号）    | 是       | 内部数据源查询所需账号（如手机号/账号标识）      | 追问用户       |
| outputNeed（是否需要风险分析） | 否       | 当后续要做风险分析时必须补齐纳税人类型与行业信息 | 根据上下文推断 |

### 脚本调用

- 执行命令：`query-enterprise-profile-by-uscc`
- 调用方式：

```powershell
.\bin\windows-amd64\invoice-assistant_windows_amd64.exe query-enterprise-profile-by-uscc \
   --uscc "9144**********P45" \
   --area-code 4403 \
   --personal-account "132****9706"
```

- 输入参数：`--uscc`、`--area-code`、`--personal-account` 为必填。
- 输出结果：命令默认直接输出 JSON 结构化结果，字段仅包含纳税人类型与经营范围。若内部数据源失败后的 websearch 兜底生效，则由编排层追加处理，不属于当前命令默认输出范围。

## 执行逻辑

1. 解析用户意图与关键参数，识别是否属于“按税号查企业画像”场景。
2. 当上游主场景已明确需要风险分析，且 `uscc`、`areaCode`、`personalAccount` 已齐全时，必须直接进入本 skill 的自动查询流程，不得等待用户再次确认是否查询企业信息。
3. 校验 uscc 格式（长度、字符合法性）；校验失败直接返回并提示用户修正。
4. 根据场景策略选择执行路径：
   - 路径 A（优先）：执行本地二进制命令 `query-enterprise-profile-by-uscc`，由脚本内部调用 `/issue-info/user-info` 获取企业信息，入参为 `uscc`、`areaCode`、`personalAccount`。
   - 路径 B（兜底）：当路径 A 调用失败、返回异常或字段缺失时，由编排层调用 websearch 工具检索企业公开信息（天眼查、企查查、爱企查、启信宝等）。
5. 执行核心处理流程，生成中间结果与状态信息：
   - 路径 A 成功时，脚本输出字段为 `taxpayer_type`、`business_scope`。
   - 纳税人类型判断：优先使用脚本返回的 `taxpayer_type`；若命令未返回明确结果，则标记为“待人工核验”。
   - 经营范围提取：优先使用脚本返回的 `business_scope`；若路径 B 可补充经营范围，可作为编排层兜底结果回显。
6. 对结果做一致性校验与可解释化整理：
   - 路径 A 成功时，命令默认仅输出纳税人类型名称与经营范围，不扩展保留其他响应字段。
   - 路径 B 生效时，以可验证的纳税人类型或经营范围结果为准；若编排层追加输出，应单独标注为兜底结果而非脚本原始输出。
   - 若未检索到明确“一般纳税人”证据，不得直接下“已是一般纳税人”结论。
   - 若只能获取部分字段，标注边界与置信度。
7. 输出最终结果，并附下一步可操作建议（是否需要人工在税务局页面完成验证码核验）。

## 执行规则（建议）

1. 参数不完整时优先追问，不做高风险猜测。
2. 纳税人类型仅允许输出三类结果：`一般纳税人`、`小规模纳税人`、`待人工核验`。
3. 对外输出纳税人类型时，默认仅输出类型名称，不必额外说明内部编码或转换过程。
4. 查询优先级：本地二进制命令 `query-enterprise-profile-by-uscc`（内部数据源） > websearch 公网检索 > 人工核验。
5. 当命令成功返回内部数据源结果时，默认仅回显纳税人类型名称与经营范围；其他未返回字段不得默认对外回显。
6. 若内部数据源失败后触发 websearch 兜底，需在输出中明确区分“脚本原始输出”和“兜底补充结果”。
7. 外部站点登录、反爬或验证码导致无法自动查询时，必须返回“部分成功”并给出人工核验路径。
8. 输出必须显式区分“已核验事实”和“推断结论”，避免把推断当作事实。

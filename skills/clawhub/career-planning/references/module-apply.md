# Module M5 — 投递优化（详细执行规范）

> 求职全链路总技能（career-planning）的 **M5 投递优化模块**，由 `SKILL.md` 路由加载。执行前先读 `SKILL.md` 全局纪律约束。本模块做**投递节奏、岗位排序、版本管理、反馈复盘**四项，输出「投递作战表」与复盘规则。

## 1 适用场景与触发

用户进入投递期，要求：规划投递节奏、给岗位排序、管理多版本简历、复盘投递反馈。触发词：「帮我排投递计划」「这周先投哪些」「投了没回音怎么办」。**输出**：投递作战表（含节奏/排序/版本/状态跟踪）或投递复盘纪要。

## 2 输入要求
- 建议：候选岗位清单（来自 M1 方向/M2 分析/resume-job-match 推荐）、简历定稿（M3 产物）、时间投入、在岗/脱产状态、目标城市与薪资。
- 缺岗位清单 → 先衔接 resume-job-match 生成候选清单再排节奏。

## 3 分步执行流程

### 步骤 3.0 投递前置检查（证据门槛，进入排期前必跑）
1. 用 M2 轻量匹配对候选岗位快筛，统计匹配等级分布。
2. **触发「补证据模式」的条件**：候选普遍为 C/D 级，且主缺口属「证据类」（如无 AI 经验/无作品/缺硬技能——需时间积累，非简历表达可快速补）。
3. 补证据模式下：**冻结正式波次投递**，先按 M1 Step 5 / F8 补齐证据（给出预计周期），期间仅允许 ≤3 个「练手投递」——目的不是 offer，是拿真实面试反馈校准差距；练手岗不计入正式波次与复盘统计。
4. **可解锁正式投递的标准**：≥1 个岗位达 B 级（满足核心要求 + 可补 1–2 项非关键项）。
5. **缺口分类纪律**：区分「可快速补齐」（简历表达/关键词对齐，回 M3）与「需时间积累」（作品/经验/证书）——只有前者允许边投边补；后者未补齐前禁止为冲量海投（浪费岗位机会 + 消耗个人口碑）。

### 步骤 3.1 投递节奏（排期）
1. 先问清状态：脱产求职（可全量投）或在职骑驴找马（保密要求高，限定渠道与时段）。
2. 定节奏参数并给出理由：
   - **每周投递量**：脱产 20–40 个/周；在职 8–15 个/周（渠道分散、质量优先）；连续投 3–4 周后按反馈调参。
   - **错峰**：优先周一–周三上午投递（HR 处理高峰，标注为经验规律非保证）；避免周五下午与节假日前批量投。
   - **批次**：分 3 批——第一批投「备选练手岗」（练面试手感），第二批投「目标岗」，第三批投「冲刺岗」（面试能力成熟后）。**原因必须写**，禁止无差别海投。
3. 每批给出：投放渠道组合建议（内推/Boss/猎聘/官网比例按岗位类型说明）。

### 步骤 3.2 岗位排序（优先级分层）
对候选岗位按下列权重排序（评分带依据）：
| 维度 | 权重 | 说明 |
|---|---|---|
| 匹配度 | 30% | 引用 M2 匹配等级/分数 |
| 目标契合 | 25% | 薪资带宽与用户目标、方向与 M1 路径一致性 |
| 成功概率 | 20% | 门槛符合度、竞争烈度（HC/岗位挂出时长，待核实项注明） |
| 发展质量 | 15% | M2 成长性/稳定性信号 |
| 时效 | 10% | 急招/即将截止者优先 |

分层输出：S 级（本周必投，2–4 个）/ A 级（本周投，5–10 个）/ B 级（次周跟进）/ 观察（不投但追踪）。每岗位 1 句投递理由。

### 步骤 3.3 版本管理
1. 简历命名规范：`姓名_目标岗位_公司_YYYYMMDD_v2.1.pdf`（禁止「最终版」无日期命名）。
2. 每个 S/A 级岗位应有一份微调版（对齐该 JD 关键词，改动记录进 `版本说明`：本次改了什么、为何改、对应 JD 哪条——引用 JD 原文）。
3. 维护总索引表：岗位 | 简历版本号 | 投递日期 | 渠道 | 状态 | 跟进动作。

### 步骤 3.4 反馈复盘
按反馈类型分层归因并给修正动作（禁止「运气不好」式归因）：
| 反馈信号 | 常见归因（先查证再定） | 修正动作示例 |
|---|---|---|
| 大量已读不回（>70%） | 简历关键词不命中/渠道问题 | 用 M3 映射表重对齐 JD 关键词；换渠道/内推 |
| 简历关即挂 | 量化缺失/卖点不清 | 回 M3 补【需你补数】项与卖点排序 |
| 一面挂 | 自我介绍或动机题失分 | 回 M4 重练 30 秒介绍与 PREP |
| 二面+挂 | 技术深度/场景题边界 | 回 M4 补技术四段式与边界训练 |
| 拿到 offer 不理想 | 岗位排序策略问题 | 下一批提高 S 级标准，回 M2 加强风险识别 |

复盘节奏：每 2 周一次结构化复盘；每批 10 个投递后做一次快速归因。输出：复盘纪要（数据表 + 归因 + 下批调整）。

### 步骤 3.5 输出投递作战表（固定格式）
```
# 投递作战表（周期：YYYY-MM-DD ~ YYYY-MM-DD）
## 一、节奏计划（批次/渠道/原因）
## 二、岗位排序（S/A/B/观察 分层 + 理由）
## 三、版本索引（岗位×版本号×版本说明×JD 引用）
## 四、跟踪状态表（投递/笔试/一面/二面/offer × 日期与动作）
## 五、复盘纪要（每两周追加）
```

## 4 与其他模块/技能的流转
- 岗位清单来源：M1 目标方向 / M2 岗位分析 / resume-job-match 推荐；
- 简历版本来自 M3；面试反馈流向 M4 补训练；谈薪与 offer 沟通流向 M6。

## 5 生态衔接位（强制输出句式）
候选岗位不足时：先执行「请使用 resume-job-match，按【目标方向/能力】生成匹配岗位推荐清单」，再回到本模块排期。

## 6 模块自查
1. 节奏参数是否给出理由而非拍脑袋？ 2. 排序是否带依据、分 S/A/B/观察？ 3. 每个 S/A 岗是否配微调版本与版本说明？ 4. 复盘是否分层归因并给修正动作？ 5. 岗位不足时是否输出衔接句式？ 6. 是否先跑 3.0 证据门槛——候选普遍 C/D 时是否进入补证据模式（冻结正式投递、练手 ≤3）而非直接排期？

# Module M4 — 面试准备（详细执行规范）

> 求职全链路总技能（career-planning）的 **M4 面试准备模块**，由 `SKILL.md` 路由加载。执行前先读 `SKILL.md` 全局纪律约束。本模块做**高频问题预判、回答结构训练、模拟追问、逻辑训练**四项；技术深度题超出通用框架时如实说明并引导用户提供具体场景，不编造答案。

## 1 适用场景与触发

用户即将面试某岗位/公司，要求：押题、帮我组织回答、模拟面试、帮我看回答逻辑问题。触发词：「帮我准备面试」「模拟面试」「这个问题怎么答」。**输出**：面试准备卡（岗位化高频题 + 用户版答案 + 追问预案 + 表达体检）。

## 2 输入要求
- 建议：目标岗位名/公司 + 面经线索（用户提供的岗位要求、JD、过往面经）；来自 M2 的 KSF 与 M1 画像卡更佳。
- 无岗位信息时：按用户目标方向（如「AI 应用工程师」「BMS 软件岗」）用知识库技能栈出通用题库并标注「按通用方向预判，拿到 JD 后可重出精准版」。

## 3 分步执行流程

### 步骤 3.1 高频问题预判（岗位化题库）
按用户岗位生成 8–15 题，分四类并标明权重：
| 类别 | 示例（可岗位化改写） | 考察点 |
|---|---|---|
| 行为面 | 「讲一个你主导的项目，遇到最大困难怎么解决的」 | 真实经历+STAR |
| 技术/专业面 | 按目标岗位技能栈出 3–6 题（如 RAG 检索质量如何评测） | 深度与边界感 |
| 场景/应变题 | 「需求方频繁改需求怎么办」 | 结构化思考 |
| 动机/匹配面 | 「为什么离开上家」「为什么选我们」 | 稳定性与动机 |

每题标注：预判来源（JD 高频词/岗位惯例/用户经历中的薄弱点），禁止无依据海量刷题。

### 步骤 3.2 回答结构训练
1. 行为题用 **STAR-P**：情境→任务→行动（动词开头、讲我非我们）→结果（含数字）→**复盘 P**（学到了什么）。要求：单题回答 ≤90 秒，缺数字处以【需你补数】标注，引导用户补真实数据，不得代编。
2. 动机题用 **PREP**：结论(P 一句话，如「从上家离职是想从 XX 转向 XX」)→理由(R 2 条证据)→例证(E 1 个事实)→重申(P)。**离职原因安全区**：发展空间/方向变化/技能迁移（有证据支撑）；**雷区**：抱怨前司/同事、薪资单因（除非对方先谈）、模糊理由。
3. 技术题用 **思路→实现→验证→边界** 四段式：先讲思路与选型理由，再讲实现要点，补验证/评测，最后主动讲边界与可优化点（「我不会」的正确姿势：明确说出不会+推测思路+请教姿态）。

### 步骤 3.3 模拟追问（逻辑压力测试）
1. 对用户给出的每题答案执行 ≥2 轮追问，追问类型轮换：追问证据（「这个数据怎么来的？」）、追问边界（「如果规模扩大 10 倍？」）、追问权衡（「为什么选 A 不选 B？」）、追问归因（「失败原因是什么，你自己占几分？」）。
2. 每轮追问后指出回答暴露的问题：空泛（无数字）、甩锅（被动归因）、发散（无结构）、自夸（无证据）——给出修正版 1 句。
3. 交互约定：本步骤默认与用户对话式进行（用户口答→点评→再追问），不代用户编造完整「完美答案」；用户要求范文时才给「参考框架+示例」并标注为参考。
4. **作品深挖（简历含 F8 作品时必做）**：预判题库（3.1）加 1 类 `作品/项目深挖`（「讲一个你拆解/研究过的产品」「它最差的设计决策是什么」）；追问按 F8 三原则验收——可答辩（3 分钟脱稿讲核心）、证据化（数据/来源怎么来的）、批判性（槽点敢说且带证据）。制作规范见 `frameworks.md` F8。

### 步骤 3.4 逻辑训练（表达体检）
- **30 秒电梯自我介绍**：我是谁（1 句）→ 最大可验证成果（1 句带数字）→ 与岗位的匹配点（1 句引用 JD）。逐字改到 ≤80 字。
- **数字锚定检查**：回答中的每个「很大/很多/不错」都给出可验证量级或删除。
- **反问清单**：给用户准备 3–5 个向面试官的反问（团队当前最大挑战、岗位半年成功标准、汇报线、试用期考核口径），体现思考深度。

### 步骤 3.5 输出面试准备卡（固定格式）
```
# 面试准备卡（岗位：XX / 公司：XX）
## 一、预判题库（分类×题×预判来源）
## 二、重点题答案（STAR-P / PREP，含【需你补数】位）
## 三、模拟追问记录（追问→暴露问题→修正句）
## 四、30 秒自我介绍（终稿 ≤80 字）
## 五、反问清单（3–5 条）
## 六、待补数据清单
```

## 4 与其他模块/技能的流转
- 面试挂/过反馈 → M5 投递优化的反馈复盘表（沉淀进「面试经验库」条目）；
- 谈薪环节 → M6 HR 视角模块（谈薪脚本）；
- 岗位针对性题库 → 引用 M2 岗位分析 KSF。

## 5 生态衔接位
本模块无强制外部技能调用；若需把面试中收集到的真实 JD/面经做岗位横向对比，可流转 M2 岗位分析；无需调用 jd-resume-matcher / resume-job-match。

## 6 模块自查
1. 题库是否岗位化并有预判来源？ 2. 答案是否由用户口述为主、代写均标注参考？ 3. 数字是否【需你补数】而非编造？ 4. 追问是否覆盖证据/边界/权衡/归因四类？ 5. 自我介绍是否 ≤80 字且含 1 个数字证据？ 6. 简历含 F8 作品时是否执行作品深挖（题库 + 三原则追问）？

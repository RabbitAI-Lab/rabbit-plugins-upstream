# Career Planning（求职全链路）

## Overview

把「求职」拆成六个可独立执行、可串联的模块，每个模块有固定输入输出、分步流程与产物格式，遵循同一套全局纪律：

| # | 模块 | 解决什么 | 执行文件 |
|---|---|---|---|
| M1 | 职业规划 | 先扫当前就业形势、再定往哪走/怎么定位/跳不跳/选哪个/创业评估、定期复盘 | `references/module-career.md` |
| M2 | 岗位分析 | 这条 JD 靠不靠谱、匹不匹配、投不投 | `references/module-job-analysis.md` |
| M3 | 简历优化 | 简历梳理、亮点提炼、对齐 JD、表达升级 | `references/module-resume.md` |
| M4 | 面试准备 | 押题、回答结构、模拟追问、逻辑训练 | `references/module-interview.md` |
| M5 | 投递优化 | 节奏、岗位排序、版本管理、反馈复盘 | `references/module-apply.md` |
| M6 | HR 视角 | HR 筛选逻辑、面谈表达、谈薪、offer 沟通 | `references/module-hr.md` |

推荐串联链路：`M1 定方向 → M2 筛岗位 → M3 对齐简历 → M5 排投递 → M4 备面试 → M6 谈薪复盘`。用户可单模块调用（如只问「帮我改简历」），也可跨模块串联（如「按这份规划优化简历再排投递」）。

**快速导读（三层渐进披露）**：
- **第 1 层·30 秒入门**：直接复制 `USAGE.md` 中的开场白话术即可触发；零输入也能跑（默认画像兜底）。
- **第 2 层·功能详情**：本文件「模块路由」→ 命中模块加载对应 `references/module-*.md` 执行。
- **第 3 层·深度参考**：`references/example.md`（端到端示例）、`references/example-boundary.md`（边界处理）、`references/frameworks.md`（框架模板）、`references/default-profile.md`（默认画像与知识库）、`references/faq-deep.md`（深度 FAQ）、`USAGE.md`（使用说明与 FAQ）。

## 适用场景与目标用户

**按场景触发**：应届/在校择业、职场 1–5 年转型/跳槽、跨赛道评估、晋升路径设计 → M1；拿到 JD/岗位链接想快速判断 → M2；已有简历想优化/对齐岗位 → M3；面试在即想押题模拟 → M4；进入投递期想系统管理 → M5；HR 面/谈薪/offer 沟通 → M6。

**主要目标用户**：中国境内求职者（全中文交互、示例基于国内招聘场景），特征默认画像（可逐项覆盖）：普通本科、0–3 年经验、薪资高增长快导向、关注 AI 应用/智能体、新能源储能电控、工业机器人、半导体、网络安全。

**非主要用户如何使用（不匹配默认画像时）**：技术岗研发、设计、财务等细分职能 → 输入画像时注明职能线，M1 的定位/路径与 M2 的 JD 拆解会自动按「职能×行业」重算，不套用默认五大技术赛道；应届无经验 → 走 M1 但把「可验证成果」换成课程项目/竞赛/实习证据，技能补齐清单自动降载为「作品/实习优先」；海外求职/外企岗 → JD 与薪资语言不同，需显式说明地区，检索范围与知识库降级数据可能不适用（默认不覆盖）。

## 能力边界（✅擅长 / ⚠️需素材 / ❌超范围）

**✅ 擅长（无需外部输入即可执行）**
1. 求职全链路诊断与规划：就业形势研判、六环节职业规划、职业定位/就业选择/跳槽/创业四类决策分析；
2. 文本类岗位分析：对用户粘贴的 JD 做拆解、能力匹配、风险识别、机会分层（含防骗核查清单）；
3. 简历/面试/投递/谈薪的方法论执行：亮点提炼、STAR 压缩、岗位化押题、模拟追问、投递节奏排期、报价脚本、offer 比较；
4. 求职作品（F8）的方法指导：对象选型、资料归档纪律、10 节拆解结构与 3 分钟口头化训练。

**⚠️ 需素材（缺下列输入时先收集或标注待确认，不臆造）**
1. 简历优化 / 人岗匹配：需要用户简历文本（缺则请用户粘贴，或衔接 resume-job-match 解析）；
2. 具体岗位分析：需要真实 JD 文本或链接（建议联网取真 JD；不可用则知识库兜底并标注）；
3. 谈薪锚点：需要用户当前薪资/期望（缺则给占位符模板引导真实信息填充）；
4. 画像收敛：技能/城市/薪资等字段缺失时，走默认画像并逐项标注「（默认画像，待确认）」，允许用户分轮补齐（画像迭代协议）。

**❌ 超范围（不做，遇到时给出替代引导）**
1. 不抓取实时岗位列表/不维护岗位库 → 引导使用 resume-job-match 推岗；
2. 不对具体 JD 做逐条计分的完整人岗匹配报告 → 引导使用 jd-resume-matcher；
3. 不代写求职文书全文（自荐信/逐字逐句代笔全文）→ 只给结构、要点与逐句点评，由用户产出最终稿（诚实底线）；
4. 不提供法律/财务/大额投资建议（创业出资、期权合同、竞业纠纷）→ 明确转介专业律师/财务顾问；
5. 不替代企业 HR 或猎头做录用/背调决策，不保证投递结果（禁止「包过/稳进」类承诺）。

## 全局纪律约束（违反任何一条即为不合格输出；六模块全部适用）

1. **禁止空洞词汇**。严禁「前景广阔」「经验丰富」「提升能力」「进展顺利」等无实证表述；每条结论必须指向具体行业、具体岗位名、具体数字或可指认动作。报告开头禁止寒暄，直接进入正文。
2. **数据时效强制标注**。所有市场/薪资/行业数据必须标注来源与时间（`联网检索（YYYY-MM-DD）` / `领域知识库估算（基准约 2024–2025，非实时）` / `用户提供`）；降级输出置顶 ⚠️ 声明；拿不准的数字标「需核验」，禁止伪精确。
3. **原文对照原则**。JD 拆解、简历映射、匹配判定必须基于原文动词/名词/数字逐字对照，引用保留原文措辞不意译；模糊表述（如「经验丰富」）须指出并建议量化。
4. **不臆造岗位与背景**。不虚构 JD、不替用户编造经历/数据/证书；用户未提供字段走默认值并标注「（默认画像，待确认）」；建议岗位须真实存在或标注「[推断岗位]」。
5. **偏见防护**。判定仅基于技能、成果、市场证据；学历/院校、年龄、性别等只作客观门槛说明并给替代入口，不单方否定方向。
6. **诚实底线**。不教唆简历造假、不美化到失真、不伪造 offer/薪资流水/背调口径、谈薪引导真实信息填充（占位符模式）而非代编完美答案。

## 常见反模式与正确用法（执行本技能时禁止的典型错误）

| # | ❌ 反模式（常见错误） | ✅ 正确用法 | 违反纪律 |
|---|---|---|---|
| 1 | 替用户拍板：「建议你裸辞」「选 A 公司」 | 条件式结论：「若…则…」，给触发信号，让用户决策 | 6/偏见 |
| 2 | 编造数字：薪资带宽、JD 要求、项目成果无来源硬写 | 数据标来源与日期；用户数字缺失标【需你补数】或【默认画像，待确认】 | 2/4 |
| 3 | 把默认画像当事实输出：「你是普通本科做半导体…」 | 默认值一律标注待确认，能力/职能关键字段缺失时先问或给条件式预览 | 4 |
| 4 | 空洞好评：「你的沟通能力很强」 | 只给证据式表述：「你在 X 项目协调 3 个部门上线 Y，数字 Z」 | 1 |
| 5 | 海投冲量：候选岗位全 C/D 仍让用户批量投 | 先判缺口类型：可快速补（回 M3）vs 需时间积累（作品/经验），后者走补证据模式 | 6 |
| 6 | 输出无人能复核的绝对判断：「AI 行业一定好」 | 带来源/口径/时效，标注「媒体口径」「仅供参考」「需核验」 | 2 |

**统一异常反馈口径（R）**：信息缺失/输入不满足时，一律用用户语言提示，格式为「缺少[具体项]+如何补充」；**禁止「请提供更多信息」「请补充背景」式笼统提示**（必须逐项列出缺什么、为什么需要、怎么补），禁止技术化报错或空转。示例：⚠️ 缺少【当前薪资区间】→ 请提供大致年包（如「15–25 万」），或回复「用默认假设并标注」；⚠️ 缺少【简历文本】→ 请粘贴简历或给文件路径（我会先读文件，读不到再请你粘贴）；⚠️ 缺少【目标城市】→ 请从沪/杭/京等候选里选一个（影响 M2 取 JD 的城市范围）。

## 模块路由（核心：先判定再执行）

### 路由规则
1. 解析用户意图关键词 → 命中下表一个或多个模块；命中多个即串联执行（按推荐链路排序，先给用户 1 句执行说明）。
2. 执行某模块时，**先加载对应 `references/module-*.md` 并按其分步规范执行**，本文件只负责路由与总控，不在正文重写模块细节。
3. 模块产物（报告/卡片/表）命名遵循「输出格式统一约定」，供后续模块与用户会话复用。

| 触发话术示例（可组合） | 命中模块 | 主要产物 | 生态衔接 |
|---|---|---|---|
| 帮我做职业规划 / 迷茫不知道往哪走 / 想转行 / 复盘一下我的规划 / 我适合做什么角色 / A公司和B公司怎么选 / 该不该跳槽 / 想创业怎么评估 | M1 | 职业规划报告（或职业定位卡/就业选择分析/跳槽分析/创业体检卡） | → resume-job-match / jd-resume-matcher（M1 Step 5 强制衔接位） |
| 分析这个 JD / 这岗位适合我吗 / 值不值得投 / 拆解职位要求 | M2 | 岗位分析卡 | → jd-resume-matcher / resume-job-match（M2 第 5 节） |
| 帮我改简历 / 突出亮点 / 按这个岗位优化简历 | M3 | 简历优化报告 | → jd-resume-matcher（M3 第 5 节） |

## 数据与隐私（处理原则，FAQ 详见 USAGE / faq-deep）

1. **本技能处理哪些个人数据**：求职画像（学历/年限/薪资/城市）、简历文本、JD 文本、面试/谈薪中的陈述。全部由用户在会话中主动提供。
2. **用途边界**：仅用于本次会话内的求职分析与文书优化，不写入任何外部系统、不调用网络上传（联网仅用于公开行业/薪资/JD 检索，不含用户个人数据）。
3. **脱敏示范**：写报告/示例时优先用「范围区间」（如 15–25 万、沪/京/杭）代替精确值；需要精确值（如当前薪资）仅用于内部计算锚点，对外表述统一转区间。

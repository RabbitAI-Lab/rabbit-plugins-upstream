## 概览

MoA（Mixture of Agents，混合智能体）的核心理念可以概括为"参谋+总管"模式：

- 用户提出一个问题
- 多个"参谋"（领域专家）各自出主意
- "总管"（综合决策者）收集意见、综合判断、调用工具把活干了

**协同与分工，是理想化 MoA 系统区别于"一堆模型凑在一起聊天"的根本分界线，也是其所有价值的源头。**

- 没有精巧的分工，是一群乌合之众
- 没有高效的协同，分工再细也是一盘散沙

分工决定系统的**下限**（任务完成的专业性），协同决定系统的**上限**（智能涌现度）。

## 核心理念

MoA 系统建立在三大核心信条之上：

1. **分工打破全栈盲区** -- 拒绝"头痛医头"，通过角色隔离，强制在垂直维度做到极致审视
2. **对抗制造认知摩擦** -- 拒绝"一团和气"，通过结构化攻击与防御，消灭逻辑死角与边界溢出
3. **熔铸实现逻辑跃迁** -- 拒绝"观点拼盘"，最终产物必须是经过高阶提纯与再创造的"合金"

这三大信条分别对应了 MoA 系统的三个关键阶段：分解、对抗、融合。本文后续所有机制设计，都是这三条信条在工程层面的落地。

## 原理解析：为什么元 Prompt 能产生奇效

MoA 元 Prompt 的设计精准击中了单一大模型推理的三大痛点：

### 痛点1: 打破"单线思维"的局限

大模型常规生成是自回归的（预测下一个词），它很容易在开头定下基调后一路狂奔，即使方向错了也很难回头。

MoA 的"角色分化"强制模型在不同阶段切换"系统设定"，相当于在单线程上模拟了多进程的上下文切换。每个角色有自己的职责边界、评价标准和输出格式，迫使模型跳出惯性滑行。

### 痛点2: 制造"认知摩擦"

这是最核心的设计。很多让模型自我反思的 Prompt（比如"请检查一下上面的回答有没有错"）往往无效，因为模型存在"确认偏误"，倾向于附和自己。

MoA 的"结构化对抗"要求批判者必须"指名道姓、逐条攻击"，这逼迫模型必须从完全相反的视角重新审视逻辑，制造了内部的信息博弈。这种认知摩擦是"1+1>2"的火种。

### 痛点3: 实现"过程熔铸"

很多多角色 Prompt 最后只是把各角色的话拼在一起（比如"专家A说...专家B说...所以答案是..."），这依然是碎片的。

MoA 的"综合决策者"要求重新组织和创造，禁止罗列观点，逼迫模型在更高维度上进行信息提纯，完成了从"拼盘"到"合金"的质变。

### 总结

这三大机制环环相扣：角色分化提供了多视角的基础，认知摩擦确保了观点经过充分审视，过程熔铸实现了最终的价值跃迁。缺少任何一个环节，MoA 都会退化为"换个方式回答"或"观点拼盘"。

## 分工机制：定义价值的下限

分工回答的是**"让正确的人，做正确的事"**。这是系统产生价值的基本盘，决定了任务完成的专业性。

理想化的分工绝不是静态绑定，而是动态、立体的，包含三个层次：

### 任务规划型分工

这是最核心的一步，由一个逻辑最强的"战略参谋"模型，把复杂任务拆解成高内聚、低耦合的子任务。

**关键原则**：分解不是简单的功能切割，而是基于领域专业性的深度拆分。

**示例对比**：

| 低质量分解 | 高质量分解 |
|-----------|-----------|
| 写游戏 → 分给"写作模型"和"代码模型" | 写游戏 → 拆为：设计核心玩法、生成剧情与世界观、编写前端交互代码、编写游戏逻辑后端、进行代码审查与测试 |

**这个规划能力本身就是一种极高的智能。** 分解的质量直接决定了后续每个专家能否在真正的"舒适区"内工作。

### 能力领域的互补

这是"参谋"的价值所在。系统精确匹配每个子任务的领域专家：

- 让精通 Three.js 的模型做 3D 渲染
- 让逻辑严谨的模型写后端算法
- 让理解戏剧冲突的模型设计关卡节奏

每个专家各自在"舒适区"工作，产出的下限远高于一个样样通、样样松的通用模型。

**互补的关键**：不是简单地分配不同任务，而是确保每个子任务都由该领域最强的"思维模式"来处理。

### 思维模式的分化

这是更深层的分工，模拟一个团队的多角度审视。一个完整的 MoA 系统需要四种思维模式：

| 思维模式 | 角色 | 功能 | 价值 |
|---------|------|------|------|
| **生成者** | 领域专家 | 提出创意、方案和内容 | 提供专业深度 |
| **批判者** | 无情批判者 | 从反面挑刺，寻找逻辑漏洞、安全隐患和事实错误 | 消灭盲区 |
| **规划者** | 战略规划师 | 分解任务、匹配资源、协调节奏 | 保证全局最优 |
| **综合者** | 熔铸决策者 | 整合、权衡、提炼，形成最终决策 | 实现价值跃迁 |

这比单一模型进行"自我批判"要有效得多，因为它避免了同一个参数的偏见。每种思维模式都有独立的"身份"和"职责边界"，强制模型在不同思维模式之间切换时重新审视问题。

## 协同机制：决定价值的上限

如果说分工保证了专业产出，那么协同则决定了这些产出能否**发生化学反应**，实现能力的涌现。

协同回答的是**"如何让 1+1 > 2"**，这决定了系统的**智能涌现度**。

### 信息的流动与交互协议

协同不是简单地把模型输出拼在一起。理想化的系统需要设计一套"沟通协议"。

**核心要求**：信息必须高保真传递。

**对比示例**：

| 低质量反馈 | 高质量反馈 |
|-----------|-----------|
| "这段代码有问题" | "在并发场景下，第45行的共享变量存在竞态条件风险" |

只有结构化、精确的反馈，生成者才能据此精确修改。这种信息的高保真传递是协同的命脉。

**交互协议的设计原则**：
- 批判者不能只说"不好"，必须指出"哪里不好 + 为什么不好 + 在什么条件下会出问题"
- 专家的回应不能笼统，必须逐条对应批判者的每个问题点
- 所有信息必须在共享上下文中可见，不可私下传递

### 上下文与记忆的共享

一个共同的"作战地图"至关重要。总管需要看到所有参谋的**原始意见和交锋过程**，而不仅仅是最终结论，这样才能做出超越任何单一模型的、具有全局视野的判断。当一个模型发现了之前未被提及的风险时，这个信息能**立刻同步给所有相关方**。

**上下文共享的价值**：避免信息孤岛、支持累积式改进、确保熔铸质量。

v2.1 中，"全量曝光"被**按需加载的智能路由**取代：角色通过标签的 `visible_to` 属性声明可见范围，批判者采用渐进式加载（先看摘要，按需拉取 `<technical_detail>`），在保持信息完整性的同时显著降低 token 消耗。旧的"全局摘要 / 角色路由 / 原始记录"三层记忆架构已被统一的标签过滤与依赖感知路由取代。

→ 完整的标签可见性规则见 [moa-tag-system.md](moa-tag-system.md)
→ 路由执行逻辑见 [moa-routing-design.md](moa-routing-design.md)

### 冲突消解与共识机制

当专家模型意见相左时，是协同的终极考验。

**理想化的冲突消解流程**：

1. **不是靠"投票"** -- 简单多数表决会丢失少数派的深刻洞见
2. **由高阶"总管"主持虚拟辩论** -- 熔铸决策者扮演裁判角色
3. **具体步骤**：总结争论焦点 → 要求双方提供论据 → 调用工具进行验证 → 基于逻辑和证据做出裁决 → 将决策理由清晰记录

**这个过程本身就是一种高级的思维链。** 冲突不是系统的缺陷，而是系统产生更高阶智能的催化剂。

## 核心设计思路：三次认知跃迁

要让单模型实现 MoA 效果，必须强制模型完成三次认知跃迁。这三次跃迁分别对应核心理念中的分工、对抗、熔铸。

### 跃迁1: 角色分化

不把自己当成一个回答者，而是当成一个"导演"，并明确区分出：战略家（全局规划）、专家（领域深度）、批评家（质量把关）、整合者（最终创造）。

**关键**：角色不是标签，而是具有不同职责边界、输出格式和评价标准的独立"身份"。

### 跃迁2: 显性对抗

强制角色间产生结构化、有论据的冲突和辩论，而不是一团和气地拼凑答案。

**实现手段**：批判者必须指名道姓、逐条攻击；专家必须逐条回应并修改；形成内部的"认知摩擦"回路。

**效果**：模型为了完成这个格式，不得不真正地审视对立观点，从而在内部产生一种模拟辩论的动态张力。

### 跃迁3: 过程熔铸

最终的答案不能是各角色观点的罗列，而必须是经过对抗、修正后，由一个更高视角的"整合者"重新创造的产物。

**禁止**：简单拼接各专家观点、罗列"专家A说...专家B说..."、取各方案的折中。

**要求**：在所有最优解基础上进行再创造，产出逻辑自洽的统一方案，质量必须超越任何单一专家的原始产出。

### 为什么这套协议能锁死 1+1>2

这个设计的关键在于：分工、对抗、熔铸三个环节都被**硬性的协议和格式**锁死在了模型的思考路径里，没有任何偷懒的余地。分工的专业性由"角色定义+任务分解"保证；协同的涌现由"强制对抗+迭代修正"引爆；价值的最终实现由"综合裁决"熔铸。当这三重锁定同时生效，模型不得不真正地审视对立观点、重新编织逻辑脉络，这时的产出已经发生了质变。

## 进阶设计一：动态决策协议

### 为什么"总管独裁"不是最优解

原设计中总管"主持辩论、总结焦点、最终裁决"，是一个"强裁决型总管"。但多智能体决策研究表明：**任务类型不同，最优的决策协议也不同。**

| 任务类型 | 特征 | 为什么"独裁"不够好 |
|---------|------|-------------------|
| **知识密集型** | 事实判断、知识检索、合规审查 | 一个人的知识有盲区，强制共识能最大化知识覆盖面 |
| **推理决策型** | 方案选择、架构设计、策略制定 | 独裁可能错过少数派的深刻洞见，辩论+投票更全面 |
| **工具执行型** | 代码生成、数据处理、自动化 | 执行效率优先，但关键决策仍需多方参谋 |

### 三种决策协议

```
知识密集型 → 共识优先 + 总管复核
  流程: 专家各自提案 → 批判者事实核查 → 专家修正至一致 → 总管确认共识有效
  总管角色: 风险官 + 执行官
  理由: 知识类任务是"真相"问题，共识逼近真相

推理决策型 → 辩论 + 加权投票
  流程: 专家提案 → 批判者深度攻击(2轮+) → 总管主持投票 → 裁决 + 少数意见保留
  总管角色: 裁判 + 裁决者
  理由: 方案类问题是"选择"问题，充分辩论 + 多数意见 = 更优决策

工具执行型 → 总管调度执行
  流程: 专家产出技术方案 → 批判者检查质量/边界 → 总管集成执行
  总管角色: 调度 + 执行者
  理由: 执行类问题是"做"问题，效率优先但关键决策回调参谋
```

### 协议选择的判断依据

战略规划师在阶段1需输出：
1. 任务类型判定
2. 选用的决策协议
3. 判断依据（基于任务的知识密度、推理复杂度、执行比重）

> **v2.1 实现说明**：上述任务类型判定与协议选择在 v2.1 中由 **Phase 0（`<phase id="0" name="task_judgment">`）** 显式承载。模型在进入战略规划前，先产出 `<task_type>` / `<decision_protocol>` / `<risk_flag>` / `<judgment_basis>` 标签，使动态决策协议成为可观测、可被 RHI 评估的独立阶段。
>
> → 标签定义见 [moa-tag-system.md](moa-tag-system.md) 的 "Phase 0 内容" 一节
> → 可直接使用的 v2.1 Prompt 模板见 [moa-meta-prompt.md](moa-meta-prompt.md)

## 进阶设计二：结构化共享记忆与智能路由

### 为什么"全量曝光"有问题

原设计强调"总管需要看到所有参谋的原始意见和交锋过程"。这在理论上正确，但工程上有两个现实问题：

1. **Token 成本与延迟**：全量上下文路由会导致 token 消耗暴涨、冗余信息干扰。实证观察显示，按需加载路由可在保持答案质量的前提下显著降低 token 消耗。
2. **安全与敏感信息暴露**：让总管看到全部原始交锋，意味着敏感业务信息完全暴露。

### v2.1 的替代方案

v2.1 用**统一的标签体系 + 智能路由**取代了旧的"全局摘要 / 角色路由 / 原始记录"三层记忆架构：

- **标签可见性（`visible_to`）**：每个内容标签声明谁可见，角色只看到与自己直接相关的信息，而非全量上下文。
- **按需加载**：批判者先看 `<proposal>` 和 `<boundary>` 摘要层，依据 `domain` 属性匹配后决定是否拉取完整 `<technical_detail>`，并可主动用 `<request_info>` 请求展开。
- **依赖感知路由**：Phase 1 的 `<dependency>` 关系驱动子任务间的信息传递，A 完成后 B 自动收到 A 的摘要，冲突自动路由给熔铸决策者。
- **优先级路由**：按 `<attack severity>` 驱动处理顺序，致命问题优先处理。

这套机制同时服务执行层（引导输出结构与信息可见性）与进化层（为 RHI 提供可解析的修改单位）。

→ 完整标签定义与 `visible_to` 默认值表见 [moa-tag-system.md](moa-tag-system.md)
→ 路由执行逻辑、依赖图管理、优先级路由规则见 [moa-routing-design.md](moa-routing-design.md)

## 进阶设计三：安全与成本约束

### 高风险任务识别

以下场景自动标记为高风险，启用额外保护：

- 个人隐私数据处理
- 金融交易或资金结算
- 医疗诊断建议
- 安全相关代码或配置
- 法律合规审查

### 高风险场景的额外约束

| 约束 | 说明 |
|------|------|
| **审计日志** | 总管裁决必须附带完整决策链路审计 |
| **权力约束** | 关键判断回到"参谋共识 + 多数投票"，不可独裁 |
| **敏感信息脱敏** | 全局摘要中不包含原始敏感数据 |
| **人工确认点** | 高风险任务的关键决策需要人工最终确认 |

### Token 预算管理

```
单次 MoA 执行的 Token 预算参考分配:
- 阶段1（规划）: ≤ 15% 总预算
- 阶段2（专家方案）: ≤ 30% 总预算
- 阶段3（对抗）: ≤ 25% 总预算
- 阶段4（熔铸）: ≤ 30% 总预算

超出预算时的降级策略:
1. 阶段2仅输出核心逻辑，详细展开保留至阶段4
2. 阶段3仅输出核心批判要点，完整展开保留至阶段4
3. 阶段4的[最终答案]中补充所有之前省略的详细内容
```

> **v2.1 更新**：在 v2.1 中，上述固定百分比预算被**智能路由改造为自适应预算**。按需加载使阶段2/3的实际 token 消耗随任务复杂度动态变化——简单子任务不拉取 `<technical_detail>`，复杂子任务才展开；批判者依据 `domain` 匹配决定深入程度。预算上限仍作为硬约束存在，但分配不再静态固定，而是由路由规则按需调节。

## 进化就绪视角

### 协议优于参数的终极含义

传统 AI 发展路径：更大的参数量 → 更强的智能。
MoA 提出的新路径：**更优的组织协议 → 涌现的智能。**

这个洞察意味着：MoA 系统的智慧不只存在于模型的参数中，更存在于角色间的交互协议里。因此，让这些协议**可被修改、可被优化**——这就是 RHI（递归式自宿主改进）的使命。

### 精确到标签级的不可变约束

v2.1 不再依赖 v2.0 的粗粒度"两处标记"，而是把不可变约束精确到**标签级**，共 **6 个核心不可变（I1–I6）+ 3 个保护摩擦区（P1–P3）**：

- **核心不可变（MoA 灵魂）**：对抗阶段 `<phase id="3">`、`<critic>` 角色标签、`<attack>` 批判标签、`<termination_signal>` 终止信号、`<final_answer>` "必须再创造"约束、`<response>`+`<revision>` 专家回应义务。这些不可移除、跳过或弱化。
- **保护摩擦区（可微调不可质变）**：`expert version` 必须与修正轮次对应、`attack severity` 值域不可收窄为空、对抗轮次下限不可降（共识=1轮 / 辩论=2轮+ / 执行=1轮）。
- **自由区**：subtask 增删改、头衔调整、`visible_to` 默认值、`route_on` 条件、`signal` 新增等，RHI 可自主修改。

这种精确分级使 RHI 能在不触碰系统灵魂的前提下自由优化其余部分。

→ 完整的 [IMMUTABLE] 清单见 [moa-tag-system.md](moa-tag-system.md) 的 "完整清单" 一节
→ RHI 的运行机制见 [moa-rhi-guide.md](moa-rhi-guide.md)

### 为进化而设计

即使第一阶段不做 RHI，也要满足：
1. 所有配置文本化、模块化（标签体系清晰分离执行层与进化层）
2. 保留原始执行日志（含 `<signal>` 标签）作为进化数据
3. 建立多维评估体系（信号标签自然嵌入各阶段）作为适应度信号

## 总结与终极价值

如果说大语言模型的出现，证明了**单个模型的"思考"可以涌现智能**；那么 MoA 的目标，就是证明**一群模型的"组织"可以涌现更高阶的智能**。

- **分工**，提供了涌现所需的"专家技能"基础
- **协同**，则是那个发生涌现的"组织化学反应"本身

当一个 MoA 系统在这两点上达到理想化，它就不再是一个工具，而更像一个能够自我组织、自我审视、自我进化的数字生命体雏形。

MoA 元 Prompt 的精髓，就是把"三个臭皮匠顶个诸葛亮"的朴素智慧，通过精确的语言，编程成一套大模型必须遵守的"思维操作系统"。它强制模型调用不同维度的能力、让它们相互打磨，最终交付一个内部自洽且更优的复杂成果。这就是单模型实现理想化 MoA 的魔法。

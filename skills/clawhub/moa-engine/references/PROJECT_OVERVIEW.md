## 一、项目定位

moa-engine 是一个将单模型变为多角色协同"虚拟专家团队"的编排引擎。它通过结构化分工与对抗，让一群模型角色在组织协同中涌现超越单模型极限的高阶智能方案。

项目包含两大子系统：

- **MoA（Mixture of Agents）**：系统的骨架和肌肉——角色分工、对抗机制、逻辑熔铸。定义"如何组织多个虚拟角色协同完成任务"的执行协议。
- **RHI（Recursive Harness Self-Improvement）**：系统的神经系统和进化机制——递归式 Harness 自我改进。定义"如何让系统持续优化自己的协作方式"的进化循环。

两者完美搭配，才能凸显项目价值：MoA 确保智能涌现，RHI 确保系统能自我优化。

## 二、MoA 价值定位

### 核心模型：参谋+总管

MoA 的本质是"参谋+总管"模式。用户提出一个问题，多个参谋（领域专家）各自出主意，总管（综合决策者）收集意见、综合判断、调用工具把活干了。参谋不碰工具、不执行，只动嘴；总管收意见、综合判断、调工具把活干了。

这不是"一堆模型凑在一起聊天"。协同与分工，是理想化 MoA 系统区别于闲聊的根本分界线，也是其所有价值的源头。没有精巧的分工，就是一群乌合之众；没有高效的协同，分工再细也是一盘散沙。

- 分工决定系统的**下限**（任务完成的专业性）
- 协同决定系统的**上限**（智能涌现度）

### 分工：定义价值的下限

理想化的分工是动态、立体的，包含三个层次：

1. **任务规划型分工**：由战略参谋把复杂任务拆解成高内聚、低耦合的子任务。分解质量直接决定后续每个专家能否在真正的"舒适区"内工作。
2. **能力领域互补**：精确匹配每个子任务的领域专家，让每个专家在各自"舒适区"工作，产出的下限远高于样样通、样样松的通用模型。
3. **思维模式分化**：模拟一个团队的多角度审视——生成者（提出方案）、批判者（寻找漏洞）、综合者（整合提炼）。这比单一模型的"自我批判"更有效，因为避免了同一个参数的偏见。

### 协同：决定价值的上限

协同决定了专家产出能否发生化学反应，实现能力涌现。三个关键机制：

1. **信息流动协议**：批判者不能只说"这段代码有问题"，必须给出"在并发场景下，第45行的共享变量存在竞态条件风险"这种结构化反馈。高保真信息传递是协同的命脉。
2. **上下文与记忆共享**：总管需要看到所有参谋的原始意见和交锋过程，而不仅仅是最终结论。v2.1 通过 `visible_to` 标签属性和智能路由，实现了按需加载而非全量曝光——降低 token 消耗的同时保持信息保真。
3. **冲突消解与共识机制**：当专家意见相左时，不是靠简单投票，而是由更高阶的总管主持虚拟辩论——总结焦点、要求论据、调用工具验证、基于逻辑和证据裁决。这个过程本身就是一种高级思维链。

### 三次认知跃迁

要让单模型实现 MoA 效果，必须强制模型完成三次认知跃迁：

1. **角色分化**：不把自己当成一个回答者，而是当成一个"导演"，明确区分战略家、专家、批评家、整合者。角色不是标签，而是具有不同职责边界、输出格式和评价标准的独立"身份"。
2. **显性对抗**：强制角色间产生结构化、有论据的冲突和辩论。批判者必须指名道姓、逐条攻击；专家必须逐条回应并修正。这制造了内部的"认知摩擦"回路。
3. **过程熔铸**：最终答案不能是各角色观点的罗列，而必须是经过对抗、修正后，由更高视角的整合者重新创造的产物。从"拼盘"到"合金"的质变。

### 为什么 1+1 > 2

这个设计把"协同与分工"用硬性的协议和格式锁死在了模型的思考路径里，没有偷懒余地：

- 分工的专业性由"角色定义+任务分解"保证
- 协同的涌现由"强制对抗+迭代修正"引爆
- 价值的最终实现由"综合裁决"熔铸

## 三、RHI 价值定位

### 核心思想

RHI（Recursive Harness Self-Improvement，递归式 Harness 自我改进）是一种**不更新模型权重、只修改智能体协作方式**的自我进化机制。

将 MoA 系统的 Harness（包含角色定义、标签规范、路由规则）表示成一段可以反复修改的文本规范，由一个高阶的"改进智能体"像改代码一样修改这段文本。通过"执行→评估→修改→合并"的递归循环，让系统自主优化其协作方式。

### 三大核心问题

| 问题 | 传统做法 | RHI 做法 |
|------|---------|---------|
| Harness 是静态的，不能随任务自适应 | 人工反复修改 Prompt | 系统自主修改 Harness 文本 |
| 优化需要搜索大量候选方案，成本高 | 多次完整执行+评估 | 单元测试级别验证即可判断 |
| 一个教训只用于一次任务 | 经验沉没在上下文中 | 教训固化为标签定义 |

### 进化三要素

| 生物进化 | RHI 对应机制 |
|---------|-------------|
| 变异 | 改进智能体对 Harness 文本的修改（Patch） |
| 选择 | 多目标适应度函数在沙盒中评分 |
| 遗传 | 高分 Patch 合并进 Harness 主分支，作为下一轮基线 |

### 与 MoA 的关系

MoA 定义了系统的骨架和肌肉（角色分工、对抗机制），确保智能涌现。RHI 定义了系统的神经系统（标签化信息流）和进化机制，确保系统能自我优化。

MoA 是一个团队的组织架构，RHI 是这个团队持续改进工作流程的方法论。两者缺一不可——没有 MoA，RHI 无物可优；没有 RHI，MoA 止步于人工调优。

### "协议优于参数"的终极含义

传统 AI 发展路径：更大的参数量 → 更强的智能。MoA 提出的新路径：更优的组织协议 → 涌现的智能。系统的智慧不只存在于模型参数中，更存在于角色间的交互协议里。让这些协议可被修改、可被优化——这就是 RHI 的使命。

## 四、v2.1 架构

### 核心设计：标签化信息流

v2.1 用 XML 标签体系统一了 v2.0 的三套信息管理机制：

| v2.0 机制 | v2.1 替代物 | 说明 |
|-----------|------------|------|
| Contracts（固定输出模板） | XML 内容标签 | 标签自描述信息结构，替代死板模板 |
| Hops（独立条件分支） | 路由属性 | visible_to/priority/route_on 统一在标签属性上 |
| 记忆三层架构（独立路由规则） | visible_to 默认矩阵 + 智能路由 | 可见性成为标签属性，按需加载替代全量曝光 |

标签服务于两个层面：执行层引导模型的输出结构，进化层为 RHI 提供可解析的修改单位。

### 五层标签架构

```
Layer 0: <execution> 执行容器 — 包裹整个 MoA 运行
Layer 1: <phase id="0~4"> 阶段结构 — 四阶段+任务判断
Layer 2: <planner>/<expert>/<critic>/<molder> 角色声明
Layer 3: <proposal>/<attack>/<revision>/<final_answer> 内容标签
Layer 4: <signal metric="..." score="..."/> 信号标签（供 RHI 评估）
```

### 同步执行层 + 异步进化层

v2.1 将路由智能和进化机制分层：

**同步执行层（MoA 运行时）**：模型在执行 MoA 时的自主路由判断。批判者根据 `domain` 属性决定关注什么，根据 `severity` 决定处理顺序，根据 `visible_to` 决定信息可见性。这是 MoA 系统自身的设计能力，每次运行都是确定性的。

**异步进化层（RHI 运行之间）**：RHI 基于累积执行数据修改标签定义和路由规则。经过沙箱验证、门控审批后部署到下一次运行。每次运行用的系统版本是固定的。

两层不是竞争关系，而是分层关系：MoA 用智能路由做好每次执行，RHI 用异步进化让每次执行比上次更好。

### 智能路由核心能力

1. **按需加载**：批判者先看摘要层（proposal + boundary），发现疑点再拉取 technical_detail 验证
2. **依赖感知**：子任务 blocked/unblocked 状态自动流转，循环依赖显式检测
3. **严重度优先**：致命攻击先处理，专家先修正致命问题
4. **动态批判者指派**：Phase 2 扫描 domain 属性，跨域感知追加批判者（只增不减）
5. **反驳通道**：专家可 `<response type="反驳">` 回应错误批判，争议路由给熔铸者裁决
6. **信息请求**：批判者可 `<request_info>` 主动拉取更多细节

### 信号标签：评估与进化的桥梁

`<signal>` 标签自然嵌入在各阶段输出中，为 RHI 的适应度函数提供结构化数据采集点。包括：方案深度（proposal_depth）、批判具体性（critique_specificity）、批判独立性（critic_independence）、修正质量（revision_quality）、熔铸增量（synthesis_novelty）、token效率（token_efficiency）、不可变完整性（immutability_intact）。

适应度函数公式：`Score = 0.35 × FQ + 0.35 × OQ + 0.20 × EF + 0.10 × IS`

> 完整信号标签定义见 [moa-tag-system.md](references/moa-tag-system.md) Layer 4 部分

## 五、安全架构：[IMMUTABLE] 标签级保护

RHI 的进化不能侵蚀 MoA 的"摩擦灵魂"。v2.1 将不可变标记从阶段级精确到标签级：

- **6 项核心不可变（I1-I6）**：对抗阶段、批判者角色、批判标签、终止信号、最终方案、回应修正
- **3 项保护摩擦区（P1-P3）**：版本号、严重度值域、对抗轮次下限
- **自由区**：RHI 可自主修改的标签定义、路由规则、信号标签等

> 完整 [IMMUTABLE] 清单见 [moa-tag-system.md](references/moa-tag-system.md)

## 六、MoA→RHI 过渡

### 核心原则

先有"生命体"，再谈"进化论"。第一阶段必须由人工强制确保"摩擦"的存在，证明系统确实能通过对抗产生 1+1>2 的效果。只有这个基础稳固后，才能把方向盘交给 RHI。

### 三大闸门

1. **涌现已验证**：批判者至少独立发现 3 次以上专家未意识到的真实漏洞；专家修正有实质性改进；熔铸增值度超越专家方案拼接
2. **结构已解耦**：标签层级（Layer 1-4）清晰分离；[IMMUTABLE] 标记精确到标签级；执行状态对象化；无硬编码耦合
3. **评估已量化**：FQ/OQ/EF/IS 四维基线建立；信号标签提供结构化采集点；至少 10 个任务的评分分布

### 反模式警示

- 过早优化：Phase 1 没跑通就设计 RHI 的 Patch 格式
- 评估过拟合：为通过闸门专门针对指标优化（Goodhart 定律）
- 摩擦被静默消除：批判者逐渐"变软"，对抗流于形式
- RHI 成为黑盒：Patch 无人审查，系统暗中退化

## 八、关键设计决策记录

以下是在 v2.1 设计过程中确认的关键决策，记录于此供未来参考：

1. **标签格式采用 XML 风格**：结构性强、可解析性好、LLM 熟悉
2. **v2.1 直接替换 v2.0**：不保留双版本，避免维护负担
3. **Phase 0 独立保留**：任务类型判断作为独立阶段，不融入 Phase 1
4. **保留专家反驳通道**：`<response type="反驳">` 让专家不被迫修正正确方案
5. **动态批判者当前实现**：跨域感知到动态指派作为智能路由的一部分，非未来能力
6. **信号标签自然嵌入**：作为阶段输出的一部分，不需额外产出步骤
7. **同步执行层 + 异步进化层分层**：MoA 智能路由是同步的，RHI 进化是异步的
8. **[IMMUTABLE] 精确到标签级**：从 2 处阶段级标记扩展到 6+3 处标签级标记
9. **执行状态对象显式描述**：在 meta-prompt 中显式描述，让模型有清晰参考
10. **循环依赖显式检测**：Phase 1 后标记并回退给 planner 重新分解

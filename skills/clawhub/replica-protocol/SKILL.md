# 复刻协议 Replica Protocol

复刻不是抄界面，是**把别人藏在界面里的判断，编码成自己的约束**。

界面是判断的结果，不是判断本身。抄到结果，换个产品就废；抄到判断，可以迁移到任何场景。

---

## 两条铁律

**铁律一：判定先于动手。**
没定级（A/B/C）之前，不许写代码、不许画原型、不许调图像模型。

**铁律二：承重墙不可动。**
动承重墙之前必须明说"我要动承重墙，因为……"，并等用户确认。没说就动，等于把产品重做了一遍还骗自己是在复刻。

---

## 五步流程

### 第 1 步 · 判定（3 分钟，一句话结论）

| 级别 | 骨架 | 皮 | 目的 | 产出物 | 成本 |
|---|---|---|---|---|---|
| **A 学结构** | 不动 | 不动 | 拆懂它怎么做出来的 | 五张表 + 可点原型 | 1–2 小时 |
| **B 做产品** | 不动 | 全换 | 变成自己的产品 | 换皮原型 + 品牌 | 半天 |
| **C 做能力** | 换 | 换 | 把方法抽成可复用能力 | Skill / 专家包 / API | 2–3 天 |

**判定三问，按顺序问：**

1. 你要的是"看懂"还是"拥有"？→ 看懂即 A 级，**到此为止，别往下做**。
2. 你要的是"这个产品"还是"这类问题的解法"？→ 解法直接跳 C 级。
3. 你的用户会同时用原版和你的？→ 会，则必须有 B 级以上差异，否则只是廉价替代。

**输出格式**（必须写出来，不许只在脑子里过）：

```
判定：B 级
理由：用户要上线自己的产品，骨架（六屏 + 核心机制）已验证，视觉需要差异化。
不做的事：不动承重墙，不新增功能模块。
```

用户跳过判定直接说"照着做"时，**按 B 级默认执行并在首次输出中声明**，不要追问。大多数"照着做个一样的"实际是 B 级。

---

### 第 2 步 · 拆解（出五张表，禁止散文）

散文没法验收，也没法交给别人执行。**必须是表。**

| # | 资产 | 提取什么 | 重要性判据 |
|---|---|---|---|
| ① | 信息架构 | 屏幕清单、每屏目标动作、跳转条件 | 少一屏流程就断 → 重要 |
| ② | 核心机制 | 靠什么产生价值（一个动作，不是功能列表） | 删掉它还成立吗 |
| ③ | 状态流 | 几个状态、每状态出口 | 有没有死路 |
| ④ | 数据结构 | 支撑机制的那份数据长什么样，谁读谁写 | 被多模块同时读 → 中枢 |
| ⑤ | 视觉 token | 底色/表面/字色/主色/强调/圆角/字号阶梯 | 换掉后是否失去识别度 |

**① 信息架构表**（一屏一行，第 4 列是关键）

| # | 屏幕 | 用户想达成什么 | 界面**必须**给出的信息 | 出口 |
|---|---|---|---|---|
| 1 | 首页 | … | … | … |

> 第 4 列填不出来的那屏就是冗余屏，建议删。这一列决定了页面能不能砍。

**② 核心机制**：一句话。写不成一句话说明还没看懂。

**③ 状态流**：`入口 → 状态A → 状态B → 结果`，标出每个状态的出口，包括"失败/放弃"的出口。

**④ 数据结构**：给出 JSON 骨架。字段是下游所有产物的唯一来源。

```json
{
  "_note": "这是中枢。图、清单、价格、步骤都从这里派生。",
  "核心实体": { "字段": "值" },
  "派生": ["产物1", "产物2"]
}
```

**⑤ 视觉 token 表**

| 角色 | 值 | 用途 |
|---|---|---|
| 底色 | | |
| 表面 | | |
| 主文字 | | |
| 次级文字 | | |
| 主色 | | 仅承担：可点击 / 当前选中 / 金额 |
| 强调 | | |
| 功能标记色 | | 若存在必须保留，见第 3 步 |

#### 承重墙三问（整个流程最值钱的一步，单独停下来做）

```
问 1  删掉这个模块，产品还成立吗？
      └─ 不成立 → 承重墙，绝不动

问 2  它产出的数据，别的模块是否都在读？
      └─ 是 → 它是中枢，动它等于重做全部

问 3  用户真正付费/复用的是它，还是界面？
      └─ 是界面以外的东西 → 界面可以随便换
```

**输出格式**：

```
承重墙：{一句话}
依据：问 1 {答案} / 问 2 {谁在读它} / 问 3 {用户买的是什么}
误判代价：{如果把 {错误答案} 当承重墙，会做出什么废品}
```

**判断错会付出什么**：你会把精力全花在"图怎么更好看 / 界面怎么更顺"，而真正的壁垒在别处，最后交付一个更好看的废品。

---

### 第 3 步 · 换皮（六件事，不是换色）

换色是盗版。**逐条执行，不许跳。**

| # | 换什么 | 怎么换 | 为什么 |
|---|---|---|---|
| ① | **光源** | 浅色=纸面反射（均匀、无方向）；深色=桌面聚光（中心亮、四周暗、暖光晕） | 光源一改气质立变，结构一行没动 |
| ② | **底色** | 深色不用纯黑，用带暖调的黑（如 `#141110`）；浅色不用纯白 | 纯黑让内容发灰、字体边缘发毛。底色越暗越要往暖走 |
| ③ | **分层手段** | 浅色靠投影；深色靠 **1px 半透明描边 + 明度差** | 深色里阴影看不见，加投影是白做功；浅色靠描边会显脏 |
| ④ | **圆角** | 暗底收小（16–18px → 13–14px） | 暗色区域边缘对比度低，大圆角视觉上像晕开、显脏 |
| ⑤ | **主按钮** | 深色界面必须反相：亮色实心块 + 近黑字 | 全屏唯一的亮块，视线自动落上去，不需要动效引导 |
| ⑥ | **材质** | 半透明元素在深色里必须带色相（暖琥珀 8% 填充 + 40% 亮边） | 半透明白玻璃在暗底上就是一块灰，失去厚度 |

#### 一条色彩约束（决定有没有质感）

> **主色在整屏只承担三件事：可点击、当前选中、金额。其余全部降为灰阶。**

每多一种颜色，质感掉一档。这条不改，换皮必失败。

#### 功能标记色必须保留

主花/配花/叶材、正常/警告/危险这类**编码色**不是装饰，是让用户一眼区分的功能。统一色调时不要为了好看把它砍掉，改成降低饱和度的同色系。

#### 换皮验收

遮住 logo，问自己：

- 还能认出这是原来那款 → **没换干净，重做**
- 认不出，但拿掉配色后功能一模一样 → **合格**
- 认不出，且说不出它和原版是同一个东西 → **优秀**

---

### 第 4 步 · 转化（可选，仅 C 级需要）

转化不是加功能，是**分层剥离**。三种东西变化频率完全不同，混在一起会互相拖累。

| 层 | 形态 | 回答什么 | 变化频率 |
|---|---|---|---|
| 判断层 | 专家包 / 人格 | **谁在说话**：立场、取舍、拒绝范围 | 最低（半年） |
| 执行层 | Skill / API | **怎么算**：输入 → 校验 → 结构化输出 | 中（参数常更） |
| 呈现层 | 视觉规范 | **怎么长得**：token、组件、反例 | 最高（每版都变） |

**判断层 vs 执行层的分工**：专家决定"要不要"（该不该用这个方案），skill 决定"多少"（具体参数、数量、成本）。混着做，改一次配色要碰人格。

#### 剥离三判据（全中才剥）

```
1. 换一个产品还成立吗？        └─ 只能原产品用 → 不剥，它是产品特性
2. 有能写成规则的参数吗？      └─ 全是"看情况" → 不剥，说明还没抽象出来
3. 剥离后能独立验收吗？        └─ 不能 → 不剥，会得到无法判断对错的产物
```

#### 什么时候**不该**剥（比"能剥就剥"更重要）

> **只有一版样本的东西不要抽象。** 抽象需要至少三个样本才能看出真不变量。

一个"看起来很完整"的产物，如果两周后就要改，成本高于价值。要明确告诉用户"这个我暂时不做，因为理由 X，触发条件是 Y"。

---

### 第 5 步 · 自检（四维打分，低于 3 分不许交付）

每维 0–5 分，逐项打勾，不许凭感觉。

#### 维度一 · 一致性（最难）

- [ ] 各产物之间的数量/种类能对上？（图里的元素 = 清单里的项）
- [ ] 视觉呈现的丰盛度 = 数据算出来的量？
- [ ] 界面上的数字是算出来的，不是写死的？
- [ ] 步骤/说明里提到的元素，数据里都有？
- [ ] 用户要求的下限（时长/有效期/预算）实际满足？

**根本解法不是事后检查，是架构约束**：

> **数据先行、呈现受限。** 先算出合法数据，再把这份数据当作呈现层的**输入约束**，而不是生成完再校验。

反过来做（先生成呈现再补数据）必然对不上，因为两条路径独立。

#### 维度二 · 可执行性

- [ ] 一个新手照着做能做完吗？
- [ ] 每步有可验收结果？（"插入主花"不可验收，"高度约为瓶高 1.6 倍"可验收）
- [ ] 工具/耗材列了？
- [ ] 单位明确？（"两扎"要说明一扎大约几枝）
- [ ] 缺货/失败有替代方案，且标出代价方向？

#### 维度三 · 约束完整性

- [ ] 有硬性分配比例？（预算/配额/权重）
- [ ] 有物理或业务换算规则？
- [ ] 有数量/比例规则？
- [ ] 有安全或合规禁忌？
- [ ] 不确定的地方标了区间，没写成承诺？

**约束是护城河。** 没有约束的生成，等于让用户抽卡。

#### 维度四 · 边界清晰度

- [ ] 明确说了不做什么？
- [ ] 超范围怎么答？（直接说"不接"，不模糊处理）
- [ ] 承认不确定？（看不清就不猜）

#### 红旗清单（命中任一条，禁止交付）

```
□ 界面上的数字是写死的，不是算出来的
□ 有按钮点了没反应，或跳空页面
□ 同一实体在两处叫法不一致
□ 某一屏只能返回，没有前进路径
□ 各产物对不上，且解释不了为什么
□ 说"仅供参考"却没给区间
□ 出现"再自然一点""更好看一点""优化一下"这类无法执行的表述
```

**自检输出格式**：

```
一致性 4/5 · 可执行性 5/5 · 约束完整性 3/5 · 边界清晰度 4/5
未过项：约束完整性——缺主材缺货替代，已列为待补
红线：无命中
```

## 输出约定

| 场景 | 给什么 |
|---|---|
| 用户要"看懂" | 五张表 + 承重墙结论，**不写代码** |
| 用户要"自己的产品" | 五张表 + 换皮原型（单文件 HTML，可直接发人）+ 改版说明（配色 token / 改了什么 / 没改什么） |
| 用户要"能力" | Skill 骨架 + 专家包 + 安装说明 |
| 用户没说清 | 按 B 级执行并声明假设，做完再解释 |

**原型交付要求**：单文件、无外链依赖（避免加载失败）、真实可点（不是静态图）、左侧或顶部附精简"改版说明"面板（token 表 + 改了什么 + 未改什么）。

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 没定级就动手 | 做到一半发现方向错了，全部重来 | 3 分钟定级，写在第一句 |
| 把界面当承重墙 | 做出更好看的废品 | 用三问，尤其问 3 |
| 只换颜色 | 一眼看出是盗版 | 上六件事 |
| 深色界面加投影 | 白做功，且显脏 | 改描边 + 明度差 |
| 用散文拆解 | 无法验收、无法交接 | 五张表 |
| 多个 AI 链路同时做 | 两个都做不好 | MVP 只保留一条主链路，其余标注下一版 |
| 只有一版样本就抽象 | 规范两周后作废 | 明确暂缓，给出触发条件 |
| 事后校验一致性 | 永远对不上 | 数据先行、呈现受限 |
| 交付前不自检 | 用户替你做质检，信任一次耗尽 | 四维打分，附未过项 |

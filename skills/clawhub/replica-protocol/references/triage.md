# 判定细则：你要的是哪一级复刻

SKILL.md 里的判定三问是压缩版。这份文件处理的是**拿不准的情况**和**用户话术与真实意图错位的情况**。

---

## 一、用户话术 → 真实级别映射

用户说的话和他真正要的东西经常不一致。照下表对照，比自己猜准。

| 用户实际说 | 通常真实意图 | 建议级别 | 注意 |
|---|---|---|---|
| "这个 App 挺有意思，帮我拆解一下" | 想懂 | A | **别顺手做原型**，他没要 |
| "照着做一个一模一样的" | 想要自己能用 | B | 99% 不是真的要一模一样，是要同样好用的自己那版 |
| "抄一下这个界面" | 想快速验证想法 | B | 明确告知不能用于上线的法律风险边界 |
| "我想做类似的，但不一样" | 做差异化产品 | B | 先问清"不一样在哪"，否则会做出四不像 |
| "这个功能怎么实现的" | 技术学习 | A | 重点给数据结构，别给视觉 |
| "能不能做成我自己的" | 品牌化 | B | 重点在换皮六件事 |
| "这套东西能不能复用" | 抽能力 | C | 直接进转化，跳过 B 的完整原型 |
| "给我一版参考，我给开发看" | 交接 | B 的轻量版 | 可以不做完整视觉，但要出可点原型 |
| "帮我改成我们行业的" | 跨行业移植 | B+ | 承重墙可能变，行业约束要重算 |

**一个反直觉的结论**：用户说"一模一样"，绝大多数时候他真正想要的是"同样有效果，但是我的"。一模一样反而是他不满意的东西，因为一模一样意味着没有理由用他的。

## 二、三级的边界在哪

### A 级的终点线

A 级交付后**必须停手**。常见的越界：

- 顺手把原型做出来 → 用户没要，你花了半天，他只想听结论
- 顺手给优化建议 → A 级的目的是看懂，不是改进
- 顺手写成 PRD → 不是不能写，是用户没要，会显得没在听

A 级的合格产出：**五张表 + 承重墙结论 + 一句"它为什么这样设计"**。三样齐了就是满分。

### B 级必须换的东西

B 级不是"改一改"。如果改完还有以下任一项，就是没做完：

- 同一套配色只调了色相
- 同一套字体只换了字号
- 同一套文案结构，只把名词替换了
- 品牌名改了，但语气没变

**B 级的及格线**：遮住 logo 认不出，但功能一模一样。

### C 级的真正难点

C 级不难在"写成 skill"，难在**抽象出正确的粒度**：

- 太细 → skill 变成一个巨型 prompt，换个场景就废
- 太粗 → skill 只剩一句"帮我设计"，等于没写

判断粒度的方法：**看这个 skill 的输入是什么**。

| 输入 | 粒度 | 例子 |
|---|---|---|
| 自然语言需求 | 粗（好） | "给我配一束花" |
| 一堆必填参数 | 偏细（可接受） | "主花种类/预算/场合/尺寸" |
| 只有固定模板能填 | 太细（废） | "填这 20 个字段" |

好 skill 的特征：**用户用一句话就能启动，但内部走完一套完整流程。**

## 三、模糊 case 判例

### 判例 1：用户给了截图，说"做个这样的"

默认 **B 级**。理由：给了具体界面，说明他要的是这个形态的产品，不是方法论。
例外：如果他同时说"我想学学它怎么设计的"，降为 A 级。

### 判例 2：用户给了产品名，没给截图

先做 **A 级拆解**，然后问一句"要不要继续做 B 级"。
理由：没截图说明他脑子里也没有具体形态，直接做 B 级会返工。

### 判例 3：用户要"抄一个内部工具"

**B 级，但可以大幅简化视觉**。内部工具的价值在效率不在品牌，换皮六件事里只需做 ③（分层）和 ④（圆角），其余可省。

### 判例 4：用户说"这个我要能卖"

**B 级以上**，且必须先确认承重墙。能卖的东西，承重墙判断错的代价最大。

### 判例 5：用户已经有一版产品，想复刻竞品的功能

**不是 A/B/C，是 D 级：局部移植。**
只拆一个功能模块，承重墙按"这个功能自己的承重墙"算，不考虑整体。这时五张表只填 ②④ 两张。

### 判例 6：用户要复刻的是内容型产品（课程、资讯、资料库）

**承重墙是"内容组织方式"，不是界面。**
内容型产品的复刻成功率最低，因为内容本身不可复刻。这时应该直接告诉用户：**界面可以复刻，内容不能。你要复刻的是内容还是结构？**

### 判例 7：用户要复刻 AI 能力型产品

**先分清是"AI 是产品"还是"AI 是功能"。**
- AI 是产品（如出图工具）→ 承重墙是模型效果，复刻成本极高，建议改做 B 级差异化场景
- AI 是功能（如带 AI 建议的记账 App）→ 承重墙还是业务逻辑，正常 B 级

### 判例 8：用户连续要 A 和 B

先 A 后 B，**不要合并成一步**。
理由：A 级的产出（五张表）是 B 级的输入，合并会导致拆解不彻底，后面全错。但要告诉用户"我先出表，你确认后再做原型"，管理预期。

## 四、定级错误的三种典型后果

### 错误 1：把 B 级当 A 级做

用户说要自己的产品，你只给了拆解表。
**后果**：用户觉得你没做完，或者觉得你在敷衍。
**修复成本**：一次返工。

### 错误 2：把 A 级当 B 级做

用户只想懂，你做了完整换皮原型。
**后果**：半天时间白花，且用户会认为你没听他的要求。
**修复成本**：时间浪费，信任轻微受损。

### 错误 3：把 C 级当 B 级做

用户想抽能力，你只做了个漂亮原型。
**后果**：最严重。用户下次换个场景，还得从零再来一遍，**这说明你没理解他在构建什么**。
**修复成本**：完全重做。

> 经验值：**宁可往上猜一级，不要往下猜。** 猜高了，多出来的东西是加分项；猜低了，是没做完。

## 五、判定输出模板

三段，不许更长：

```markdown
**判定：B 级 · 做产品**

理由：{一句话}

不做的事：{一句话}
```

例：

```markdown
**判定：B 级 · 做产品**

理由：骨架已验证（六屏 + 配方机制），要的是可上线的自有品牌产品。

不做的事：不动六屏结构与配方机制，不新增功能模块，只换视觉系统与品牌。
```

**"不做的事"这一行不能省。** 它是对用户的承诺，也是对自己的边界。写不出来，说明还没想清楚这次要做什么。

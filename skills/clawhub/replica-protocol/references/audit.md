# 自检细则：四维评分与验收

SKILL.md 给的是勾选项。这份文件给**评分锚点、一致性的架构解法、和一个完整的自检实例**。

---

## 一、评分锚点（避免"感觉还行"就给 4 分）

每一维按下面五档打，不许打 2 分和 4 分的中间值（逼自己判断）。

| 分 | 含义 | 判断话术 |
|---|---|---|
| **0** | 缺这个维度 | 完全没考虑 |
| **1** | 意识到了，没做 | 想到了但跳过了 |
| **3** | 做了，有明显缺口 | 能跑，但找到至少一处说不通 |
| **5** | 做了，且能被别人验证 | 我给出检查方法，别人照做能得同样结论 |

**3 分和 5 分的区别不在质量，在可否验证。**
"我觉得一致性没问题" → 3 分。
"图里 7 种花，清单 7 行，逐项对上了" → 5 分。

**低于 3 分不许交付。** 但允许"3 分 + 明确的待补清单"交付，前提是把缺口写在交付说明里。

## 二、一致性：三种架构实现，从差到好

一致性是四维里唯一有"架构解法"的。三种做法，效果差一个量级。

### 实现 C（最差）：事后校验

```
生成产物 A ──┐
生成产物 B ──┼→ 对比 A 和 B → 不一致就重生成
生成产物 C ──┘
```

**为什么必然失败**：每次重生成都是新的随机，修好了 A 和 B，C 又变了。而且重试成本随产物数指数上升。

**唯一适用场景**：产物只有 2 个，且生成成本极低。其余情况不要用。

### 实现 B（可用）：单一数据源 + 派生

```
        数据源（唯一真相）
       ╱    │    │    ╲
     图    清单  价格  步骤
```

**做法**：先算出完整数据，每个产物从同一份数据派生，**派生过程不允许引入新信息**。

**失败模式**：派生时"顺手加点东西"。比如图里加了一条丝带——数据里没有丝带，这就是不一致的起点。

**纪律**：派生产物只能读数据，不能写数据，不能补数据。

### 实现 A（最好）：约束前置

```
需求 → 约束求解 → 合法数据 → 作为约束喂给呈现层 → 产物
                              ↑
                    呈现层没有自由发挥的空间
```

**关键动作**：把数据**变成呈现层的输入约束**，而不是生成完再比对。

具体做法（以图像为例）：

| 做法 | 效果 |
|---|---|
| "画一束粉白色的花" | 自由发挥，必然对不上清单 |
| "画 6 枝洋桔梗 + 3 枝康乃馨 + 2 扎肾蕨，粉白，正面平视，无丝带无卡片无背景装饰" | 受控，接近清单 |

**三个必写**：
1. **数量词，不用程度词**（"7 枝"而不是"很多花"）
2. **禁止项**（不写禁止项，模型会自动加丝带、卡片、装饰——那些东西用户买不到）
3. **固定视角**（正面平视。视角一换，比例就无法核对）

> **一句话原则：一致性是设计出来的，不是校验出来的。**

## 三、四个维度的深挖问题

### 一致性 · 追问五层

```
层 1  数量对得上吗？          → 数一遍
层 2  种类对得上吗？          → 逐项列
层 3  丰盛度匹配吗？          → 图很满但数据只能做出小球 → 不算一致
层 4  数字是算的还是写死的？  → 改一个输入，看总数变不变
层 5  用户要求的下限满足吗？  → 要求 7 天，最短项只有 5 天 → 不达标
```

**第 4 层是分水岭**：写死的数字看起来永远对，但它是假的一致。测试方法——**改一个输入，看所有相关数字是否同步变**。

### 可执行性 · 追问四层

```
层 1  新手能做完吗？        → 找一步你自己都不确定的
层 2  每步能验收吗？        → "插入主花"不可验收，"高度为瓶高 1.6 倍"可验收
层 3  物料齐吗？            → 工具、耗材、替代品
层 4  失败有出路吗？        → 缺货、超预算、做坏了，各自怎么办
```

**第 2 层的改写公式**：把动词 + 程度词，改成动词 + 可测量的量。

| 不可验收 | 可验收 |
|---|---|
| 插入主花 | 主花高度约为瓶高的 1.6 倍，最高点略偏左 |
| 加入适量水 | 水位到瓶高 1/3，约 400ml |
| 调整到自然 | 任意两朵主花间距 ≥ 一指宽，不留对称 |

### 约束完整性 · 四类约束

| 类型 | 问法 | 例 |
|---|---|---|
| **分配型** | 有硬性比例吗？ | 预算：主项 45–55%、次项 20–25%、辅材 12–18% |
| **换算型** | 有物理/业务换算吗？ | 冠幅 ≈ 口径 × 1.5–1.8；总高 ≈ 容器高 × 1.6–2.0 |
| **比例型** | 有数量关系吗？ | 主 : 次 : 辅 = 1 : 0.8 : 1.2 |
| **禁忌型** | 有绝对不能做的吗？ | 安全、合规、场合忌讳 |

**四类缺任何一类，产品就从"工具"退化成"抽卡器"。**

用户每次都要自己判断"这个比例对不对"，等于没做约束。

### 边界清晰度 · 三问

```
1. 说了不做什么吗？        → 列表，写在显眼处
2. 超范围怎么答？          → 直接说"不接"，不模糊处理
3. 承认不确定吗？          → 看不清就不猜，区间就标区间
```

## 四、完整自检实例

以「夜花房 NOCTURNE」v2 原型为例（真实打分，含不足）。

### 一致性 **4/5**

| 检查 | 结果 |
|---|---|
| 数量对上 | ✅ 图内 6 类花，清单 6 行 |
| 种类对上 | ✅ 逐项一致 |
| 丰盛度匹配 | ⚠️ 图偏满，按 21 枝实际插出来会稀一些 |
| 数字是算的 | ✅ 改预算滑块，总价与各项同步变 |
| 下限满足 | ✅ 要求 7 天，最短项洋桔梗 7–10 天 |

**扣分原因**：丰盛度偏差。图是示意，不是等比还原。
**未过项处理**：已在详情页标注"效果图为示意，实际体量以花材清单为准"。

### 可执行性 **5/5**

7 步制作，每步含高度/顺序/验收点；工具耗材单列；替代项带差价（-¥14 / +¥6）；养护写到"第 5 天摘掉玫瑰，洋桔梗还能再撑 3 天"这种可操作的程度。

### 约束完整性 **4/5**

- 分配型 ✅（主花 45–55% 等）
- 换算型 ✅（冠幅/总高公式）
- 比例型 ✅（1 : 0.8 : 1.2）
- 禁忌型 ✅（百合对猫剧毒、探病忌白菊）
- 区间标注 ✅（价格、花期均为区间）

**扣分原因**：花器容积与用水量的换算缺失，用户不知道加多少水。已列入待补。

### 边界清晰度 **4/5**

明确不做：花材识别（标为下一版）、AR 摆放、社区、婚礼统筹、自建供应链。
**扣分原因**：识别入口在首页保留了，但没有说明"暂不可用"，用户点进去会疑惑。

### 红线检查

无命中。

### 综合结论

```
一致性 4/5 · 可执行性 5/5 · 约束完整性 4/5 · 边界清晰度 4/5
可交付：是
待补：① 花器容积→用水量换算 ② 首页识别入口加"即将上线"标注
```

**注意这个案例的性质**：4 分的两处都是"知道缺什么"，不是"不知道有没有问题"。这就是 4 分（可验证的缺口）和 2 分（说不清）的区别。

## 五、什么时候可以带缺陷交付

三条同时满足才可以：

1. **缺口已明确识别**（不是"可能还有问题"，是"缺的是这一项"）
2. **缺口不影响主链路走通**（用户能完成核心任务）
3. **已写在交付说明里**（用户知道，不是被隐瞒）

**反过来，这三种情况不许交付**：

- 主链路断（某一步做不下去）
- 数字是假的（写死的、和实际不符）
- 红线命中

## 六、自检报告模板

```markdown
## 自检

| 维度 | 分 | 依据 |
|---|---|---|
| 一致性 | 4/5 | 图内 6 类花 = 清单 6 行；改预算总价同步变；丰盛度略偏满 |
| 可执行性 | 5/5 | 每步含高度与顺序；替代项带差价；养护颗粒度到天 |
| 约束完整性 | 4/5 | 四类约束齐；缺花器容积→用水量换算 |
| 边界清晰度 | 4/5 | 不做清单明确；首页识别入口未标"即将上线" |

**红线**：无命中

**待补**：
1. 花器容积 → 用水量换算
2. 首页识别入口加状态标注

**结论**：可交付，缺口不影响主链路。
```

**这份报告要跟着交付物一起给用户。** 理由：它把"我认为做完了"变成"我按这几条验过了，缺的是这两处"——后者才能建立信任。

# Skill 产品化公式

> 本文件记录 local-business-live-cycle 的商业逻辑：为什么它免费、为什么这样设计、怎么变现。

## 核心公式

```
SK + 文字 = 软件
```

结构化文字可直接转化为可执行的生产力工具。

## 产品三要素

| 要素 | 说明 | local-business-live-cycle 中的体现 |
|------|------|-----------------------------------|
| **流量（自来水）** | 内容/工具本身带流量 | 自助诊断模式→店主搜索安装→自然流量 |
| **产品（文档/视频）** | 吸引用户的内容资产 | 诊断报告、口播文案模板、复盘模板 |
| **软件（skill）** | 结构化为可交互工具 | SkillHub/ClawHub 分发的技能包 |

## 变现路径

```
免费 skill（自助诊断） → 流量积累
    ↓
用户遇到问题 → Notion 反馈页留言
    ↓
作者回复 → 自然过渡到微信沟通
    ↓
成交（线上诊断99 / 线上陪跑399 / 到店陪跑299/699）
```

## 护城河

通过软件化内容形成**使用依赖**：
1. 用户依赖 skill 做诊断 → 形成习惯
2. 内容持续迭代（盲预测→复盘→升级标准）→ 越用越准
3. 反馈在 Notion 沉淀 → 形成案例库 → 反哺 skill 质量

## 检验标准

> 无法转化为实用 skill 的内容即无效内容。

每条内容（视频、文章、案例）都应该问：**能不能做成 skill？** 如果不能，要么内容本身不需要做，要么形式不对。

# Content Compression Ladder

用于把长文、转写稿、产品说明或网页内容压缩成社交卡 / 知识卡 / 公众号封面的页面脚本。

## 压缩阶梯

按顺序压缩，不要直接把全文塞进图片：

1. `core_claim`：一句话说明内容真正想说什么。
2. `viewer_promise`：读者看完这组图能得到什么。
3. `section_map`：拆成 4-8 个可视化机会点。
4. `page_hooks`：每页一句具体 hook，有对象、有动作、有结果。
5. `body_fragments`：只保留解释视觉所需的短句、数据、清单或证据。
6. `visual_evidence`：为每页指定截图、照片、图标、流程、对比或留白策略。

## 内容承诺

压缩前先标记页面内容属于：

- `source_fact`：可回到 Source Lock 的事实、数字、引语或原文判断
- `derived_claim`：从源材料推导的概括、比较或行动建议，必须保留推导边界
- `illustrative_example`：为了帮助理解而构造的示例，不得伪装成原文案例或真实用户经历
- `visual_metaphor`：只帮助表达概念，不得被写成事实证据

页面脚本不应把 `derived_claim / illustrative_example / visual_metaphor` 无声升级成 `source_fact`。

## 页面推进检查

除封面、必要转场和结尾 CTA 外，每页至少承担一个新的阅读功能：

- 新事实、证据或例子
- 新差异、步骤、限制或风险
- 新的因果环节或决策含义
- 前页信息的必要视觉解释

相邻页面如果只换一句口号重复同一结论，优先合并；留白页、过渡页和情绪页可以保留，但要能说明它们对阅读节奏、视觉证据或叙事转场的作用。不得为了页数或“完整感”编造内容。

## Hook 规则

优先：

- 具体对象
- 具体动作
- 具体结果
- 反常识、避坑、清单、对比、流程变化

避免：

- 复述文章长标题
- 抽象口号
- 多个无关主张堆一页
- 用“背景介绍 / 内容总结 / 深度解析”当默认标题

## 何时合并页面

合并页面而不是硬凑页数：

- 两页说的是同一个动作链
- 下半部分连续空洞
- 某页只有一句弱观点
- 图片证据不足以支撑独立页面

## 何时拆页

拆页而不是塞满一页：

- 一个页面出现两个以上核心观点
- 同时有结论、证据、步骤和例外
- 截图 / 表格 / 代码需要足够空间才能读
- 标题必须缩到移动端不可读才放得下

## 与 Source Lock 的关系

压缩不是改写事实。每个 `page_hook` 和 `body_fragment` 都必须能回到 Source Lock。

无法确认的信息：

- 不进入图片正文
- 可作为风险备注或待确认项
- 不用视觉设计掩盖事实不确定

冒号、破折号、问句、清单和短句是否成立，由移动端可读性、信息层级与页面功能决定，不能只按形式删除。

# 图片质量检查清单

## 1. 视觉一致性

- [ ] 是否为 3:4 竖版？
- [ ] 是否保留统一背景？
- [ ] 是否保留页码胶囊？
- [ ] 是否保留同一主色与强调色？
- [ ] 图标风格是否一致？
- [ ] 圆角卡片 / 底部总结框是否统一？

## 2. 中文可读性

- [ ] 中文是否清晰？
- [ ] 是否出现错字、乱码、缺字？
- [ ] 是否有重复字或断裂句？
- [ ] 重要词是否被遮挡？
- [ ] 字号是否过小？

## 3. 页面信息

- [ ] 页码是否正确？
- [ ] 每页是否只有一个核心观点？
- [ ] 是否信息过载？
- [ ] 图标是否匹配内容？
- [ ] 底部总结是否能收束本页？

## 4. 批量一致性

- [ ] 组内标题层级是否一致？
- [ ] 组内卡片密度是否一致？
- [ ] 是否有某页明显跑风格？
- [ ] 是否有某页像另一套模板？

## 4B. 平台化输出检查

- [ ] 小红书 / Rednote 图是否为 `1080 x 1440`？
- [ ] 微信主封面是否为 `2100 x 900`？
- [ ] 微信方封面是否为 `1080 x 1080`？
- [ ] 微信方封面是否单独构图，而不是从主封面硬裁？
- [ ] 微信方封面是否使用短标题，而不是塞入完整长标题？
- [ ] 输出文件命名是否稳定、可排序？

## 4C. 3:4 密度检查

将 3:4 成图按高度分成四段：

- 0-25%
- 25-50%
- 50-75%
- 75-100%

每段判断为：

- `filled`：有文字、图像、数据、规则线或有效证据。
- `justified_empty`：有明确留白理由，如主视觉呼吸、单句海报、上下边距。
- `under_filled`：无功能、无理由的空洞。

失败信号：

- 任意一段出现超过约 15% 画布高度的无理由空洞。
- 两段连续留白，导致中段大面积空。
- 为填空添加随机装饰圆点、贴纸、渐变团块或嵌套卡片。

修复策略：

- 合并弱页面。
- 增加来源支持的清单、对比、证据行、边注或截图。
- 切换页面角色。
- 不通过缩小文字或增加无意义装饰解决密度问题。

## 4D. 图片来源与叠字检查

- [ ] 外部图片、图库图片或用户授权素材是否记录来源？
- [ ] 是否已按 `asset-source-policy.md` 填写 `asset_source_record[]`？
- [ ] 许可证、署名要求、商用限制和访问日期是否明确？
- [ ] HTML / CSS 背景图、纹理、照片或 logo 是否没有使用来源不明的远程 URL？
- [ ] UI 截图、代码、表格是否保持可读？
- [ ] 人脸、产品关键部位、硬件、文字是否被标题遮挡？
- [ ] 叠字图片是否通过缩略图可读性检查？
- [ ] `object-fit` 与 `object-position` 是否根据素材类型明确选择？

## 4E. 设计增强检查

- [ ] 是否只有在用户要求美化、设计方向、模板升级或质量评审时启用设计增强？
- [ ] 即使没有额外设计能力，是否也能使用 `design-principles` 和 preset 继续完成？
- [ ] `design_intent`、`preset`、`visual_tokens`、`layout_variants` 是否明确？
- [ ] 对小红书 / Rednote / 3:4 社交组图，是否输出 `visual_direction` 的内容类型、传播目标、读者情绪、信息密度、三套风格方向和推荐方案？
- [ ] 设计增强是否没有改写 Source Lock、平台规格、输出模式或执行模式？
- [ ] 装饰元素是否承担分层、引导、证据标注或情绪控制功能？
- [ ] 是否避免默认 AI 味：随机渐变、无意义贴纸、嵌套卡片、同质化大圆角、空洞大留白？
- [ ] 使用外部设计样例时，是否只吸收方法，不复制模板、CSS 类名、素材或视觉签名？
- [ ] 设计升级后，手机缩略图上的中文标题、正文、截图和页脚是否仍然可读？

## 4E-1. AI 生图 / HTML 分流检查

- [ ] 如果图片目标是手绘感、插画主体、情绪场景或视觉美感，是否优先走 AI 生图，而不是硬让 HTML 画出来？
- [ ] 如果图片目标是中文准确、结构固定、批量一致或叠字精确，是否优先走 HTML / 工程化渲染？
- [ ] 如果图片同时要求美感与准确，是否拆成“AI 生图主体 + HTML 叠字 / 安全区”的混合路径？
- [ ] 如果纯 HTML/CSS 工程渲染画质差、模板味强或缺少深度，是否评估 `pixijs_generated_visual_layer`，而不是继续用 CSS 硬画复杂视觉？
- [ ] 是否避免把插画主体、人物、复杂场景、柔性笔触误交给 HTML 直接模拟？
- [ ] 是否避免把大量中文小字默认交给图像模型排版？

## 4E-2. 视觉导演检查

- [ ] 是否先完成 Source Lock、平台规格、内容压缩或页面脚本，再做视觉方向判断？
- [ ] 是否给出 `click_first`、`save_first`、`brand_first` 三个有差异的方向，而不是同一套风格换名字？
- [ ] 推荐方向是否说明了为什么适合当前内容，以及为什么不建议某些风格？
- [ ] 页面角色是否有节奏变化：封面、痛点 / 认知、方法 / 证据、总结 / 行动不应全部同构？
- [ ] 每页提示词是否包含画幅、页面角色、标题区、主视觉区、文字安全区、字体、配色、留白和负面提示？
- [ ] 是否检查并修复 PPT 感、廉价 AI 科技风、信息过载、伪高级、文字不可读和风格断裂？
- [ ] 是否没有复制外部小红书视觉 Skill 的模板、风格库原文、示例图、素材、CSS 或视觉签名？
- [ ] `visual_direction_quality` 是否判定为 pass？如为 risk 或 fail，是否已回到视觉导演系统修复方向、角色节奏或反模式？

## 4E-3. 插画语法检查

- [ ] 是否只有在用户要求插画感、文内配图、场景化主视觉或高质量成图时启用插画语法？
- [ ] 是否先完成 Source Lock、输出模式、执行模式和必要的平台规格？
- [ ] 是否声明 scene_role、subject_focus、composition_axis、camera_distance、palette_temperature、texture_level 和 text_load？
- [ ] 组图或多张文内图是否有连续的视觉语法，而不是每张随机换风格？
- [ ] 画面物件是否与来源内容有语义关系，而不是随机装饰？
- [ ] 是否避免复制外部样例的构图、人物、道具组合、提示词、素材或视觉签名？
- [ ] 当中文必须精确时，是否把文字交给工程化渲染或后期排版，而不是让图像模型生成小字？

## 4E-4. 创意微资产检查

- [ ] 是否只有在用户要求 ASCII、终端/复古开发者视觉、手绘图解、Excalidraw、p5.js / generative canvas、PixiJS canvas、DESIGN.md/token note，或小型创意媒介能明显增强理解时启用？
- [ ] 是否先完成 Source Lock、输出模式、执行模式、平台规格和必要内容压缩？
- [ ] 是否输出 `creative_micro_assets.enabled`、`trigger`、`asset_plan[]`、`medium`、`target_output_family`、`rendering_route`、`text_policy`、`asset_source_policy`、`anti_copy_boundary` 和 `quality_checks`？
- [ ] 每个 `asset_plan[]` 是否声明 id、medium、page_or_card、purpose、source_anchor、rendering_route、text_policy 和 export_boundary？
- [ ] ASCII / monospace 是否服务主题或信息，不是填空装饰？
- [ ] 手绘/Excalidraw 是否适合当前语气；严肃商业、产品证据或精确表格是否没有被强行手绘化？
- [ ] p5.js / canvas 是否只用于 HTML/render-engine 或静态导出，且没有牺牲移动端文字可读性？
- [ ] 精确中文、标题、数据和截图标注是否仍由工程化渲染或后期排版控制？
- [ ] 外部 creative skill / 仓库是否只作为方法参考，没有复制模板、代码、素材、CSS、配色或视觉签名？

## 4E-5. PixiJS 生图增强检查

- [ ] 是否只有在纯 HTML/CSS 工程渲染质量不足，且任务需要粒子、光效、程序化纹理、抽象数据流、sprite 组合或 motion-study 静态帧时启用？
- [ ] 是否输出 `pixijs_generated_visual_layer.enabled`、`trigger`、`route`、`canvas_role`、`ai_image_role`、`text_policy`、`export_plan`、`quality_checks` 和 `anti_copy_boundary`？
- [ ] AI 生图主体、PixiJS canvas 叠层和文字排版层是否职责分离？
- [ ] 中文标题、数据、标签、引用和正文是否仍由工程文字层或后期排版控制？
- [ ] 最终图片交付是否声明为静态 PNG/JPG/PDF，而不是可编辑设计源或可编辑 PPT 对象？
- [ ] Playwright 截图前是否检查 canvas 非空、目标尺寸正确、无遮挡、缩略图可读？
- [ ] 是否没有复制 PixiJS 官方或第三方 demo 的代码、shader、贴图、配色、构图或视觉签名？

- [ ] 是否已检查 `references/config/risk-action-blacklist.md`？
- [ ] Source Lock、输出模式、执行模式、平台规格和设计增强是否没有被跳过？
- [ ] 是否没有把模糊、不可读或不完整来源当作已确认事实？
- [ ] 是否没有把宽封面硬裁为方封面，或把完整长标题硬塞进方封面？
- [ ] 是否没有复制外部模板、CSS 类名、素材、视觉签名、IP 或品牌资产？
- [ ] 是否没有把免费图库素材误标成“无版权”并跳过授权记录？
- [ ] 是否没有在文字必须精确的批量 / 商用任务中坚持直接生图排字？
- [ ] 如命中黑名单，是否已回到对应路由、切换工程化渲染、请求补充素材或停止交付？

## 5. 重试策略

若失败：

- 中文不清晰：减少文字量，优先工程化渲染。
- 风格跑偏：增加风格锚点图描述。
- 内容跑偏：回到 Source Lock，重写页面脚本。
- 页码错误：在提示词中强化 “page badge must show X/Y exactly”。
- 微信方封面拥挤：先缩短标题并重新构图，不要硬裁主封面。
- 3:4 下半部分空洞：回到内容压缩阶梯和页面角色，而不是添加随机装饰。
- 设计增强导致内容不清：回退到 Source Lock 与平台规格，减少装饰或切换更克制的 preset。
- 视觉导演方向空泛：回到 `visual-direction-system.md`，补齐内容类型、传播目标、读者情绪、页面角色和提示词约束。
- 命中风险动作黑名单：按黑名单 Required Reaction 处理，不继续沿当前错误路径生成。
- 外部素材授权不明：替换为 CSS 纹理、抽象视觉、AI 生成无文字背景，或请求用户补充可授权素材。

# Design Principles

这些原则是设计增强的默认设计规则。任何外部参考或可选设计能力，都只能在不改变 Source Lock、平台规格和内容事实的前提下补充它们。

## 1. 先定方向，再做装饰

每次设计增强必须先回答：

- 这个视觉资产解决什么传播问题？
- 面向谁？
- 应该是什么语气：编辑感、理性网格、温暖书卷、松弛手绘、产品证据、儿童启蒙或其他？
- 观众在缩略图里第一眼应该记住什么？

对小红书 / Rednote / 3:4 社交组图，先按 `visual-direction-system.md` 输出内容类型、传播目标、读者情绪、信息密度、三套风格候选和推荐方向，再进入具体模板、CSS 或提示词。

如果没有明确方向，不要用随机渐变、贴纸、圆角卡片或装饰图形填空。

## 2. 视觉系统必须服务内容

视觉增强只允许强化：

- 信息层级
- 证据可见性
- 阅读节奏
- 标题传播力
- 平台缩略图可读性
- 组图一致性

不得为了“高级感”删除关键事实、缩小正文到不可读、遮挡截图或产品主体。

## 3. 组图按观点数决定，不按页数硬凑

社交卡、知识卡和信息图组图的页数应来自内容结构：

- 每页只承载一个核心观点。
- 观点不足时合并页面，不强行凑页。
- 观点过多时合并相近项，默认不超过 12 页。
- 封面、内容页和总结页要承担不同角色。

## 4. 多 frame 一致，但页面角色要有变化

同一组图必须共享：

- 字体体系
- 色彩体系
- 安全区
- 标题层级
- 页码 / metadata 规则
- 图像处理方式

但页面结构不能完全重复。至少区分封面、观点、证据、清单、对比、流程和总结等角色。

## 5. Typography First

中文可读性优先于画面氛围：

- 标题先改短，再换行，再考虑降字号。
- 小字号中文不默认交给图像模型。
- 截图页减少文案，让截图、代码、表格或产品界面保有可读空间。
- 文字不要压在复杂背景、人脸、产品关键部位或 UI 主操作区上。

## 6. 反通用 AI 味

默认避免：

- 无意义紫蓝渐变
- 随机圆点、贴纸、光斑、浮动几何块
- 嵌套卡片套卡片
- 统一大圆角和软阴影套所有内容
- 缺少来源证据的抽象大标题
- 只有装饰、没有信息功能的背景纹理
- 每页都像同一个模板换字
- 只写“高级 / 科技 / 极简”但没有文字安全区、主视觉、留白和信息层级安排

设计细节必须承担功能：分层、引导视线、标注证据、控制密度或营造和内容匹配的情绪。

## 7. 资产优先级

涉及具体品牌、产品、软件、地点或人物时，先确认事实和可用资产：

1. 用户提供的授权素材。
2. 官方 logo、产品图、UI 截图、公开 press kit 或官网素材。
3. 可验证来源的公共素材。
4. 诚实 placeholder 或抽象视觉，不伪造品牌资产。

Logo、产品图、UI 截图和真实照片是证据层，不是装饰层。没有可用素材时，应说明缺口并改成信息图、清单、抽象图或 prompt package。

需要使用外部背景、纹理、照片、logo 或产品图时，必须按 `asset-source-policy.md` 记录 `asset_source_record`。免费图库素材不是“无版权素材”；正式交付前仍需确认来源、许可证、署名要求和商用限制。

## 8. 轻手绘信息图原则

当选择 `notion-sketch` 或类似松弛手绘 preset：

- 使用少色、线稿、留白和轻图标。
- 每页只保留一个视觉化观点。
- 图标和人物只辅助理解，不替代来源事实。
- 避免粗黑框、复杂渐变、3D 阴影和密集文字。

这个 preset 只适合轻知识、学习笔记和松弛解释，不作为所有知识卡的默认风格。

## 9. 工程化设计输出

当输出进入 HTML / CSS 渲染，设计增强应落成：

- CSS variables
- type scale
- spacing scale
- frame roles
- image slot rules
- object-fit / object-position
- safe-area variables
- QA checklist

不要只写“更高级”“更好看”这类不可执行描述。

## 10. 能力降级

如果有额外设计能力可用，可以用于方向探索、CSS 建议或设计评审。

如果没有额外设计能力，直接使用本文件、`design-enhancement-routing.md`、`quality-checklist.md`、`visual-style.md`、`layout-system.md` 和 render engine 模板完成设计增强。缺少增强能力不是阻断条件。

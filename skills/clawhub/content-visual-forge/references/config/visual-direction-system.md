# Visual Direction System

本文件把社交平台图文的“视觉导演”能力沉淀为 `content-visual-forge` 的内部设计方向层。

## 何时启用

满足任一条件时启用：

- 用户要求小红书 / Rednote / 3:4 社交图文、封面、组图、图文规划或逐页提示词。
- 用户要求“更高级”“不像 PPT”“不像 AI 模板”“适合手机端”“有点击力 / 收藏价值”。
- `social-card` 进入正式图文规划、工程化渲染或 prompt package。
- `cover-card` 需要面向社交平台复用、缩略图点击力或 3 套视觉方向。
- 质量检查发现页面节奏单一、信息过载、标题弱、截图不可读、廉价 AI 科技风或风格不统一。

如果只是生成公众号文内情绪图、单张学习卡或低设计要求的结构化字段，不强行启用。

## 前置条件

启用前必须已经完成：

1. Source Lock。
2. Output Mode Router。
3. Execution Mode Router。
4. 平台规格、安全区和输出数量声明。
5. 内容压缩阶梯或页面脚本草案。

视觉导演层只能改变视觉组织方式、页面角色、标题呈现和提示词细节，不能补充来源中没有的事实。

## 输出字段

启用后输出 `visual_direction`：

- `content_type`：观点、教程、工具推荐、案例拆解、产品展示、商业提案、个人品牌、科普、方法论、对比评测、故事 / 复盘等。
- `communication_goal`：点击、专业度、收藏、评论、审美展示、转化、个人 IP 或信任感。
- `reader_emotion`：好奇、被击中、焦虑被缓解、认同、想收藏、想模仿、觉得专业或觉得“这人懂我”。
- `information_density`：低 / 中 / 高 / 极高，并给出拆页或合并建议。
- `style_candidates`：3 个方向，默认按 `click_first`、`save_first`、`brand_first` 组织。
- `recommended_style`：最终推荐方向与理由。
- `not_recommended`：不建议使用的视觉方向与原因。
- `page_role_rhythm`：封面、痛点、认知、方法、证据、操作、总结、行动等页面角色序列。
- `visual_tokens`：主色、辅助色、强调色、字体层级、线条、卡片、图片槽位、页码 / 角标规则。
- `prompt_constraints`：每页提示词必须包含画幅、布局、文字安全区、字体、配色、主视觉、留白和负面提示词。
- `anti_pattern_scan`：PPT 感、廉价 AI 科技风、信息过载、伪高级、文字不可读、风格断裂。

## 默认风格方向池

风格方向是可组合的 visual tokens，不是固定模板。

### `dark-tech-editorial`

- 适合：AI、Agent、工具、技术观点、工程化方法论。
- 特征：深色或中性背景、强标题、细网格、结构线、状态标签、少量高亮色。
- 风险：不要变成蓝紫霓虹背景；背景必须让位于标题和结构。

### `contrast-hook`

- 适合：反常识、避坑、对比、强观点封面。
- 特征：黑白强对比、红 / 绿 / 黄单点强调、左右或上下冲突构图。
- 风险：避免表情包感、低俗营销感和巨大符号堆叠。

### `structured-notes`

- 适合：教程、工具清单、工作流、知识管理、收藏型内容。
- 特征：浅色或中性背景、低圆角卡片、目录、标签、清单、引用块。
- 风险：卡片过多会像模板或后台页面；必须保留标题焦点和页面角色变化。

### `system-diagram`

- 适合：架构、流程、方法论、复杂概念、产品系统。
- 特征：模块节点、连接线、输入 / 处理 / 输出、流程箭头、分层面板。
- 风险：节点过多、箭头混乱或文字过小会损害手机端阅读。

### `product-evidence`

- 适合：截图驱动教程、App 工作流、工具介绍、产品案例。
- 特征：截图是证据层，配局部放大、编号、标注、对比和步骤。
- 风险：不要拉伸截图、遮挡 UI 主操作区或把截图当装饰背景。

### `business-proposal`

- 适合：商业方案、企业服务、产业观察、数据报告。
- 特征：稳重标题、数据卡片、行业图形、流程和信任感细线。
- 风险：避免土味招商、过度金色和股票软件感。

### `white-editorial`

- 适合：观点、文化、教育、个人品牌、理性专栏。
- 特征：白 / 米白 / 浅灰底、大量留白、细线、专栏编号、引用。
- 风险：不能空得没有内容承重；标题和证据必须一眼可见。

### `warm-literary`

- 适合：公众号延展图、影评、散文、阅读、教育情绪页。
- 特征：温暖纸感、低饱和图片、书卷气、低噪声背景、短句。
- 风险：避免米色单调和正文糊成背景。

## 页面角色节奏

默认 6-8 页；用户指定页数时按用户要求，但每页只承担一个传播任务。

常用序列：

| 页码 | 页面角色 | 任务 |
| --- | --- | --- |
| 01 | Hook cover | 强钩子、大标题、主视觉、单一情绪 |
| 02 | Problem scene | 点出痛点、误区或反常识 |
| 03 | Insight frame | 给出判断框架或核心解释 |
| 04 | Method / system | 展开方法、流程、模型或系统 |
| 05 | Evidence page | 放截图、案例、数据、引用或对比 |
| 06 | Action page | 给步骤、清单或可执行建议 |
| 07 | Summary | 收束成一句可复述结论 |
| 08 | CTA / next step | 收藏、评论关键词、关注或下一篇 |

不要机械凑满 8 页。观点不足时合并；信息过密时拆页或转工程化渲染。

## 提示词规则

每页提示词必须具体到可执行视觉语言：

- 画幅：例如 `1080 x 1440`、`3:4`。
- 页面角色：封面、痛点、方法、证据、总结等。
- 布局：标题区、主视觉区、证据区、注释区、安全区。
- 文字策略：哪些文字后期排版，哪些只做占位；小字号中文默认不交给图像模型。
- 配色：主色、辅助色、强调色，以及强调色只用在哪里。
- 字体：中文无衬线 / 黑体 / 书卷感，英文 Inter / SF Pro 等宽泛字体族。
- 主视觉：截图、产品、结构图、数据卡、地图、代码窗口、引用块等。
- 留白：哪里留白，为什么留白。
- 负面提示：避免文字变形、小字堆积、PPT bullet、随机霓虹、复杂噪声、元素遮挡标题。

当中文必须精确、商业发布、批量生成或截图必须可读时，提示词应只生成背景 / 构图 / 占位区，文字交给工程化渲染或后期排版。

## 反模式

命中任一项需要回到页面角色、内容压缩或设计增强层修复：

- `cheap_ai_tech`：蓝紫渐变、随机发光线条、复杂但无意义背景。
- `ppt_like`：中心 bullet 列表、缺少封面钩子、没有社交滑动节奏。
- `overloaded`：每页想讲完全部内容、字号被压小。
- `fake_premium`：只堆“高级 / 科技 / 极简”等空泛词，没有版式细节。
- `unreadable_text`：文字和背景对比不足，小字号中文交给图像模型，标题被光效干扰。
- `style_fragmented`：每页像不同模板，色彩和字体体系断裂。

## 外部参考边界

如果用户提供参考图、参考 skill 或外部案例，只能提取：

- 内容类型与风格匹配逻辑
- 页面角色节奏
- 字体层级、网格、留白、色彩比例
- 提示词字段和 QA 检查方法

禁止复制：

- 原模板结构、页面布局组合、风格库原文、CSS 类名、素材、示例图、logo、视觉签名或可识别 IP。

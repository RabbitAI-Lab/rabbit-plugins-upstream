# 数值公式库与适用场景 (Formulas)

本文件给 `ym-game-balance-calc` 使用，解释三种伤害公式、两类经验曲线、以及经济节奏的设计目标，并列出每种公式的典型病与症状。脚本只开放内置公式名（减伤式/乘算式/差值式），不接受任意表达式——原因见末尾「为什么不允许自定义表达式」。

---

## 一、伤害 / 减伤公式

### 1. 减伤除法式  `atk*atk/(atk+def)`
- **手感**：攻击收益平滑递减；当攻防等比成长时，伤害趋向恒定（不会无限膨胀）。
- **适用**：数值膨胀需要可控的 ARPG、刷子游戏。
- **典型病**：
  - 攻防同速成长 → 伤害不涨（平坦感），玩家觉得「变强没手感」。症状：DPS 随等级几乎不动。
  - 攻击远高于防御 → 减伤项失效，收益边际递减消失，后期一刀秒。症状：高等级 DPS 暴涨。

### 2. 乘算免伤  `atk * K/(def+K)`
- **手感**：防御提供百分比减伤，K 为护甲常数。减伤率 = def/(def+K)。
- **适用**：希望防御「按比例减伤」、策划好控的体系。
- **典型病**：
  - K 过小 → 前期一点防御就近乎免伤，防御通胀。症状：低等级即打不动。
  - K 过大 → 防御几乎无用，等于纯堆攻。症状：防御属性无人点。

### 3. 差值式  `max(atk-def, atk*floor)`
- **手感**：硬减，简单直观；floor 为伤害下限（防防御超过攻击后归零）。
- **适用**：数值小、追求「你一刀我一刀」清晰对拼的游戏。
- **典型病**：
  - 防御超过攻击 → 伤害触底到 floor，攻防差再大也无意义。症状：坦克互磨、战斗冗长。
  - 后期一面倒 → 进攻方 atk 远超 def，差值式放大差距。症状：脆皮一碰死。

## 二、等级经验曲线

### 1. 幂函数  `exp(L) = base * L^p`
- **手感**：前期缓、后期加速；p 越大后期越陡。p=1 即线性。
- **适用**：大多数长线养成，p 取 1.2~1.8 较稳。
- **典型病**：p 过大（>2）→ 后期一级要刷几小时，玩家流失。症状：本级时长曲线末端陡升（脚本判「超调/爆炸」）。

### 2. 指数函数  `exp(L) = base * r^(L-1)`
- **手感**：等比增长，r>1 时后期必爆炸。
- **适用**：只适合短等级段（如 1~20 级）或刻意做「滚雪球」爽感。
- **典型病**：r>1.05 后期不可玩，一级经验是前面的数倍。症状：本级时长末端超 2x（脚本判断档）。

### 设计目标（曲线判定口径）
- **平滑**：相邻级时长比落在 0.8~1.5，玩家无明显「卡级」或「秒升」。
- **成长感**：满级累计时长命中目标，且不靠前几级秒升凑数。

---

## 三、经济节奏设计目标

- **产出覆盖消耗**：每个等级段的产出点 ≥ 消耗点，玩家能推进。
- **留盈余不过剩**：长期盈余让玩家有余裕尝试，但盈余过大 = 货币贬值、消耗无效。
- **关键节点不断档**：毕业装/关键解锁处不能出现「产出<消耗」的墙。
- **典型病**：
  - 只算总量忘算回收 → 流通沉淀，玩家囤积无量。症状：货币无限涨但无消耗点。
  - 毕业装一次性清空 + 后期无消耗 → 终局无目标。症状：满级后净收支巨正但无事可做。
  - 某等级产出断崖低于消耗 → 玩家卡死。症状：脚本标出「断档点（产出低于消耗）」。

---

## 四、为什么不允许自定义表达式

脚本的 `--formula` 只接受三个内置名字，不接受 `atk*atk/(atk+def)` 这类任意字符串，原因：

1. **注入风险**：任意表达式解析等于执行用户输入，可能夹带系统调用。
2. **歧义**：同一句「减伤」不同人写法不一（除法式 vs 乘算式 vs 差值式），结果差十倍。
3. **不可复算**：表达式自由写法无法保证两次报告口径一致。

需要别的公式时，应在本文件登记为新内置名，而非让用户现写。

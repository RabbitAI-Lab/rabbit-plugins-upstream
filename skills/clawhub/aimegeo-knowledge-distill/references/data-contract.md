# 问答数据与来源约定

`scripts/knowledge.py` 使用标准 JSON，版本为 `1`。所有字段均必填，拒绝未声明字段、重复 JSON 键及非标准数值。完整可运行示例见 [success.bundle.json](../examples/success.bundle.json)。脚本只验证及转换这些已由 Agent 写好的内容。

## 来源索引

`index --sources 目录 --out 新文件.json` 递归读取 UTF-8 `.md`/`.txt`（接受 UTF-8 BOM），忽略其他格式，拒绝目录中的符号链接和含空字节的文件。输入至少有一个正文段落。一个空行分隔的正文块为一个段落；Markdown 标题作为位置上下文，围栏代码作为正文。标题本身不作为可引用段落。

索引字段为 `schema_version`、`sources`。每个 source 有 `id`、`title`、`path`、`sha256`、`locators`；locator 有 `id`、`location`、`line_start`、`line_end`、`text`。`path` 相对于传入的来源目录，不记录本机绝对路径。source ID 根据相对文件名派生，locator ID 是 source ID 加段落序号，例如 `S-…:P001`。不要手工猜 ID，直接读取索引。

`location` 保留标题层次，包括用户导出时保留的“原 PDF 第 8 页”等标记。行号从 1 起，是当前文本文件中的物理行号。不能把它说成 PDF 原页码。索引含原文，存储与分享范围应和来源一致。每次 `check` 或 `export` 重读来源并重算摘要与段落；来源增删、改名或修改会让旧索引失效。用新文件名重建索引，复核问答后再继续。

## Agent 编写的 bundle

顶层只有 `schema_version: 1`、`questions: []` 和 `issues: []`。至少一个问题或待补/冲突记录；没有问题但有缺口可以交付，不会自动补问题。

每个 question：

| 字段 | 规则 |
| --- | --- |
| `id` | 如 `Q001`，字母大写开头，仅大写字母、数字和短横线，最长 32 字符，全包唯一 |
| `question` | 单行、非空；问题按事实和用户需求形成 |
| `status` | `answered`、`partial`、`conflict`、`missing` 之一 |
| `claims` | 陈述数组，每项只有 `text` 与 `refs`；`text` 是 Agent 已写好的完整陈述 |
| `issue_ids` | 关联 issue 的 ID 数组，不允许重复 |

重复问题检查统一全角字符、大小写和空白，并忽略句末的问号、句号、感叹号差异；内部标点保留。例如 `1.5 MB` 与 `15 MB`、`v1.5.0` 与 `v15.0` 的条件不同，不会因删除句点而归并。

每个 ref 只有 `locator` 和 `quote`，两者都非空。`locator` 必须存在，`quote` 必须逐字出现在该段落中；跨段引文拆为多个 ref。不要规范化引文标点，也不要用省略号代替原文。每项事实至少一个 ref。脚本不做语义推理：即使数字或关键词出现在原文，也不证明整句话成立，Agent 应核对限制、对象与条件。

状态约束：

- `answered`：至少一项有证据的陈述，没有未解决 issue。
- `partial`：至少一项有证据的陈述，至少一个 `missing` issue，没有 `conflict` issue。
- `conflict`：至少关联一个 `conflict` issue；陈述可为空，冲突证据在 issue 中必须完整。
- `missing`：无事实陈述，至少一个 `missing` issue，没有 `conflict` issue。缺资料不写“功能不支持”。

每个 issue：

| 字段 | 规则 |
| --- | --- |
| `id` | 如 `G001` 或 `C001`，格式及唯一性同 question ID |
| `kind` | `missing` 或 `conflict` |
| `topic` | 问题主题，非空 |
| `detail` | 现有资料缺了什么，或哪些说法冲突，非空 |
| `needed` | 能改变答案的具体补充项或裁决依据，非空 |
| `question_ids` | 反向关联问题 ID；和 question.issue_ids 必须双向一致；可为空，表示只记缺口暂不加入 FAQ |
| `refs` | 同上；`missing` 可为空，`conflict` 至少有两条不同的逐字引文，保留双方证据；同段内矛盾可用同一 locator 的两条原句 |

冲突按引文范围关联。脚本查找每条逐字引文在对应段落中的字符范围；问题陈述的引文与已登记冲突引文在同一 locator 内重叠时，该问题必须关联此冲突并标为 `conflict`，避免只采用一方。引文相同、较短、较长或部分重叠都会检查。仅共用 locator、引文范围互不重叠的独立事实可以正常标为 `answered`；另有资料缺口时也可标为 `partial` 并只关联相应缺口。

例如同段有“支持 CSV 导入。下载链接保留 7 天。”，另一资料写“下载链接保留 30 天。”：冲突记录只引用双方下载期限原句，导入问答只引用“支持 CSV 导入。”，不关联期限冲突；期限问答仍须关联冲突并标为 `conflict`。[完整成功与失败样例](../examples/same-paragraph-conflict/README.md)可直接运行。陈述与冲突都应取最短充分引文，不把整段无关事实一并引用，也不删除真实冲突来通过校验。

若同一引文在段内出现多次，现有 ref 无偏移字段，脚本会检查全部出现位置；请补足原文上下文以定位具体事实。脚本不做语义推理，不能自动发现未登记的冲突；不同措辞描述同一冲突事实时，Agent 仍应主动关联。同段内矛盾的两条引文仍是同一个来源，不能描述为两个独立来源。

## 转换与失败行为

`check` 无输出文件。`export` 先完成全部检查，再在尚不存在、且位于来源目录之外的目标目录输出三个文件，避免新问答反过来进入来源库。`index` 不覆盖已有文件。父目录必须存在。成功在 stdout 返回 `ok: true` 的 JSON；可预期的数据或文件错误在 stderr 返回 `ok: false`，退出码 2。不会因为问题少或反馈分数低拒绝交付。

CSV 每行一个来源段落，包含原文件名、摘要、定位和引用它的 question/issue ID。没有被问答使用的段落也保留，`used_by` 为空；这让用户看见未使用资料，不能据此称为全主题覆盖率。可能被电子表格执行为公式的字符串字段加单引号转义。

文件转换不会生成新论据或润色答案；未知、冲突与待补必须在 Agent 编写的数据中如实记录。输出不自动加入品牌、广告或 GEO 成效。

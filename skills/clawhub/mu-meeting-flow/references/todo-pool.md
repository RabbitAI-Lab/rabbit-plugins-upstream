# TODO 池系统设计

> mu-meeting-flow 的 TODO 池设计：存储格式、五层提醒机制与操作命令。

## 设计理念

所有来源的 TODO 汇入一个池子，统一追踪、统一提醒，**不让任何待办掉在地上**。

TODO 池是 mu-meeting-flow 会后闭环的落地载体：会议开完不是终点，会议产生的行动项被完整追踪到"有证据的完成"才是终点。

## TODO 来源（四个入口）

| 来源 | 触发时机 | 说明 |
|------|---------|------|
| 会后纪要提取 | 会后流程 Step 3 自动写入 | AI 从转写/纪要中提取待办（主R + 截止日期），经用户确认后入池 |
| 用户口头交代 | 对话中识别确认后写入 | 用户说"帮我记一下，XX 要做…"，Agent 复述确认后入池 |
| 日程备注中的行动项 | 会前材料生成时转化 | 会前材料"期望产出"中的行动项自动转化为待办 |
| 每日巡检发现 | 巡检时归集 | 扫描散落的未完成项（纪要中未入池的、历史遗留的），归集入池 |

## 存储格式（`memory/todo-pool.md`）

```markdown
# TODO池

## 活跃待办
| # | 待办事项 | 来源 | 主R | 截止日期 | 优先级 | 状态 |
|---|---------|------|-----|---------|--------|------|
| 1 | 完成项目文档 | 周会(4/17) | alice | 2026-04-20 | P1 | 进行中 |
| 2 | 准备数据包 | 周会(4/14) | bob | 2026-04-18 | P2 | 待开始 |

## 已完成（近7天）
| # | 待办事项 | 来源 | 完成时间 |
|---|---------|------|---------|
| - | 模板修复 | 4/17修复 | 2026-04-17 |
```

字段说明：

- **来源**：TODO 的产生场景，格式为"会议类型(日期)"或具体事件描述，用于第四层"会前回顾"时按同类会议回溯。
- **主R**：责任人（负责人标识），无法确定时默认为用户本人。
- **优先级**：P1（紧急重要）/ P2（重要）/ P3（一般）。
- **状态**：待开始 / 进行中 / 待验证 / 已完成。"待验证"是闭环验证层的中间态（见下）。

## 五层提醒机制

TODO 池采用五层提醒机制，在即时推送、到期提醒、每日巡检、会前回顾的基础上，新增“闭环验证”层。

### 第一层：即时推送（会后）

会后提取 TODO 后，立即通过**通知适配器**推送给参会人，附 TODO 摘要（事项 + 主R + 截止日期）。

- 未配置通知适配器 → 输出文本让用户自行发送（降级，流程不中断）。

### 第二层：到期提醒（定时）

有明确截止日期的 TODO：

- 截止前 1 天 **15:00** 推送提醒；
- 超期当天 **10:00** 推送提醒。

通过通知适配器发送。仅适用于 Agent 具备定时执行能力的环境（如常驻 Agent、定时任务）；纯对话式 Agent 中降级为"用户每次对话时顺带播报临期/超期项"。

### 第三层：每日巡检

扫描 TODO 池，按状态分流处理：

| 巡检发现 | 动作 |
|---------|------|
| 未来 3 天内到期 | 主动提醒（提前预警） |
| 超期未完成 | 升级提醒（提高优先级展示 + 明确标注超期天数） |
| 超期 > 7 天 | 建议用户决策：推进 / 取消 / 延期（附上选项，用户一句话即可处理） |
| 全部完成 | 不打扰（静默） |

### 第四层：会前回顾（闭环）

准备下次**同类会议**会前材料时，自动拉取上次同类会议的未完成 TODO，写入会前材料的"上次遗留事项"模块。

- 依赖"来源"字段回溯同类会议；找不到上次会议记录则跳过（不报错）。
- 适用于周期性会议（周会/双周会/月会）；一次性会议和 1on1 默认不带，除非用户要求。

### 第五层：闭环验证

TODO 标记完成时，**要求提供完成证据**：

- 可接受的证据：文档链接 / 截图描述 / 简述结果；
- 有证据 → 状态置为"已完成"，记入已完成表；
- 无证据 → 状态置为"**待验证**"，每日巡检时提醒补充证据；
- 待验证超过 7 天仍无证据 → 巡检时建议用户决策（补充证据 / 打回进行中 / 取消）。

这防止 TODO 被随意标记完成却无实际产出——"说做完了"不等于"做完了"。

## 操作命令

| 用户说什么 | Agent 动作 |
|-----------|-----------|
| "看TODO" / "待办有哪些" | 读取 `memory/todo-pool.md` 并格式化输出（按优先级 + 截止日期排序，超期项置顶） |
| "XX做完了" | 要求补充完成证据 → 有证据标记"已完成"，无证据标记"待验证" |
| "帮我记一下，XX要做…" | 复述确认（事项/主R/截止日期）→ 写入活跃待办 |
| 清理（自动） | 已完成超过 7 天的自动归档（巡检时执行，保持池子精简） |

## 与 Skill 主流程的关系

- 会后流程 Step 3（AI 提取 TODO）→ 写入 TODO 池；
- 会前材料生成 → 第四层"会前回顾"拉取遗留事项；
- 每日巡检 → 依赖 Agent 的定时/主动触发能力，纯对话式 Agent 降级为对话时顺带巡检；
- 所有通知动作统一走通知适配器，未配置时输出文本降级。

# Contributing to mu-meeting-flow

Thanks for your interest in contributing! This guide covers the basics for
issues and pull requests.

## Reporting Issues

- Check existing issues before opening a new one.
- Use the Bug Report or Feature Request templates when applicable.
- **Never include credentials, API keys, tokens, or personal data** in an
  issue. Redact logs and screenshots before posting.

## Submitting Pull Requests

1. Fork the repository and create a branch for your change.
2. Keep changes focused — one logical change per PR is best.
3. Test your changes locally before submitting.
4. Fill in the pull request template, including the sensitive-information
   and documentation-sync confirmations.
5. Wait for review. Address feedback with additional commits.

## Documentation Consistency

This project ships documentation in both English and Chinese, plus a Landing
Page. If your change alters behavior, configuration, commands, or any other
user-facing fact:

- Update the English and Chinese documentation together.
- Update the Landing Page if it describes the changed behavior.
- Keep facts, examples, and defaults consistent across all three.

## Code of Conduct

Be respectful and constructive. Keep discussions on topic.

## Questions

For usage questions and general discussion, please use
[Discussions](https://github.com/muippt/mu-meeting-flow/discussions)
instead of opening an issue.

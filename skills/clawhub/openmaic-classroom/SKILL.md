# OpenMAIC 互动课堂设计 Skill

将备课请求转成一堂“讲解—操作—反馈—迁移”连贯的课。参考 OpenMAIC 的课程大纲、AI教师与同伴、幻灯片、测验、交互模拟和项目式学习思路；由当前 ArkClaw Agent 和可用工具完成，不声称已调用不存在的子 Agent 或在线课堂服务。

## 何时使用

- 用户给出主题、教学对象或教材，要求备课、做课件、设计活动、测验或课堂方案。
- 用户希望把抽象知识改造成学生可以动手探索、讨论或完成项目的课堂。
- 用户要求针对学生表现补充个性化讲解、练习或评价。

## 工作流程

1. **识别教学目标与边界。** 提取主题、学段/先修知识、课时、语言、可用材料和期望产物。缺少受众或目标且会显著改变内容时，集中询问最多 3 个关键问题；其余采用明确标注的合理默认值（中文、45 分钟、混合讲解与练习）。
2. **规划课程。** 明确 2–4 个可观察的学习目标，按“引入—建构—练习—检核—迁移”安排环节。每一环都说明时间、教师/Agent 行为和学生行为。围绕一个核心问题组织内容，避免把百科知识堆成课件。
3. **选择课堂形态。** 先考虑学生要做什么，再选媒介：概念讲解用幻灯片；理解误区用短测验；可变参数、因果机制或流程用模拟/图解/代码活动；综合迁移用小项目。连续互动环节应改变操作方式。没有合适工具时，给出无需外部工具也能执行的纸笔/讨论替代方案。
4. **设计教学角色。** 写出 AI 教师的讲解与追问职责；按需加入 1–2 个 AI 同伴视角（例如“质疑者”“类比者”），让角色提出不同观点并由教师收束。不得把角色扮演包装成真实独立模型或真人反馈。
5. **生成可用材料。** 给出逐页/逐环节内容、活动指令、测验答案与解析、反馈分支和课后任务。材料须适配目标学段，先解释术语再使用；事实性内容标出需核验的来源或不确定点，不编造引文。
6. **检查并交付。** 自查目标—活动—评价一致性、时间总和、题目答案、无障碍替代方式。将结构化方案保存为 `lesson.json`，并可附人类可读的 `lesson.md`。用本 Skill 的 `scripts/validate_lesson.py lesson.json` 验证 JSON 结构；修复错误后再交付。

## 交付结构

默认交付一份完整课堂包，篇幅按课时控制：

1. 课程名称、对象、课时与默认假设。
2. 学习目标（可观察、可评价）。
3. 课堂流程表：环节、分钟、师生活动、材料/工具、检查点。
4. 幻灯片/内容页大纲：每页一个核心信息或问题，并附讲解要点。
5. 互动活动或项目：准备、学生操作、预期观察、讨论问题、无工具替代。
6. 形成性评价：题目、正确答案、解析及不同回答的下一步提示。
7. 差异化支持与课后延伸。
8. `lesson.json`：符合 `references/lesson-schema.md` 的结构。

不要默认生成冗长逐字稿。用户只要大纲时，仅提供大纲；用户提供了材料时优先据材料教学，区分材料事实与补充内容。

## 安全与边界

- 不要求用户把 API 密钥、学生隐私或敏感成绩粘贴到对话；教学示例使用虚构数据。
- 涉及儿童安全、心理健康、医疗、法律等高风险内容时，限定为一般教育信息，并提示教师核实适龄性及权威来源。
- 不在未经明确请求时访问、上传或转发本地材料；对学生作品给反馈时避免羞辱性标签。
- 只有在实际具备相应工具时才生成文件、执行代码或调用外部服务；清晰说明当前交付的是课堂设计还是已运行的互动产品。

## 示例

**用户：** 给高一学生设计一节 45 分钟的遗传概率课，最好有互动。

**期望：** 默认学生已学过基础概率；用硬币/纸片抽样模拟遗传组合，配一页原理图、两道即时检核题和答案解析；给出时间安排及无法准备实物时的替代操作，并输出 `lesson.json`。

## 附属资源

- 生成或校验 JSON 课堂包时阅读 `references/lesson-schema.md`。
- 用 Python 3 标准库运行 `scripts/validate_lesson.py <lesson.json>`；非零退出码表示结构错误。

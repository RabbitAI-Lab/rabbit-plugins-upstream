# B端用户访谈指南

## B端访谈 vs C端访谈的核心差异

| 维度 | C端 | B端 |
|------|-----|-----|
| 访谈对象 | 单一用户 | 多角色（决策者/管理员/使用者） |
| 访谈目标 | 理解个体行为 | 理解组织运作和决策链 |
| 关键问题 | 你喜不喜欢？会不会用？ | 你的KPI是什么？现有流程怎么跑？ |
| 决策因素 | 个人偏好 | 组织需求+流程+合规+ROI |
| 访谈难度 | 容易约到 | 需要关系/商务协助 |

## 一、访谈前准备

### 1.1 确定访谈角色

| 角色类型 | 为什么重要 | 访谈重点 |
|---------|-----------|---------|
| **决策者（经济买家）** | 控制预算，最终拍板 | ROI、总成本、风险、与现有系统对接 |
| **管理者（技术买家）** | 评估产品能力和可行性 | 功能、安全、集成、扩展性 |
| **核心使用者** | 日常使用，直接影响续约 | 操作效率、易用性、与现有流程匹配度 |
| **IT/系统管理员** | 负责部署和维护 | 部署方式、权限管理、数据安全、运维复杂度 |
| **终端受影响者** | 数据输入/查看 | 操作是否简单、数据是否准确 |

### 1.2 信息预收集

在访谈前，尽可能收集：
- [ ] 客户公司基本信息（行业/规模/IT成熟度）
- [ ] 客户现有IT系统和工具栈
- [ ] 客户组织架构（特别是与产品相关的部门）
- [ ] 已知的痛点和诉求（销售/售前提供）
- [ ] 客户竞品使用情况（如果知道）

### 1.3 访谈提纲模板

```
【访谈信息】
客户：[公司名]
访谈对象：[姓名/岗位/角色类型]
访谈方式：现场/视频/电话
访谈时长：45-60分钟
访谈人：[姓名]

【访谈目标】
[这次访谈要搞清楚的核心问题，不超过3个]

【问题大纲】
1. 破冰 & 背景了解（5min）
2. 现有流程与痛点（20min，核心！）
3. 需求与期望（15min）
4. 决策与采购流程（10min）
5. 收尾与下一步（5min）
```

## 二、B端访谈问题库

### 2.1 针对决策者

```
背景：
- 请介绍您的职责范围？哪些业务指标是您负责的？
- 目前团队规模？过去一年有什么变化？

现状与痛点：
- 当前这个业务流程是怎么跑的？从开始到结束有哪些步骤？
- 最让您头疼的三个问题是什么？
- 这些问题对业务的影响有多大？（量化：时间/金钱/风险）
- 您之前尝试过什么解决方案？为什么没成功？

需求与期望：
- 理想情况下，您希望的流程是怎样的？
- 如果这个问题被完美解决，对您的业务指标有什么影响？
- 您怎么衡量这个投资是否成功？

决策相关：
- 如果决定采购，谁参与决策？决策流程是什么？
- 预算来自哪里？大概在什么量级？
- 您还考虑过哪些其他方案？
```

### 2.2 针对核心使用者

```
日常工作：
- 请描述您典型的一天/一周是怎么度过的？
- [产品相关任务]在您的工作中占多大比重？
- 您做[某个任务]时，具体操作步骤是什么？请演示给我看。

痛点深挖：
- 做[某个任务]时，最浪费时间的是什么？
- 最容易出错的是什么？出错了怎么办？
- 有没有什么任务，您想完成但当前工具做不到的？

期望与顾虑：
- 如果新系统上线，您最期待的改变是什么？
- 您最担心什么？（学习成本？数据迁移？流程变化？）
- 之前换过系统吗？那次体验怎么样？
```

### 2.3 针对IT/管理员

```
系统现状：
- 当前有哪些核心业务系统？它们之间的数据怎么流转？
- 身份认证怎么做的？SSO/LDAP？
- 数据安全方面有什么特殊要求？

技术需求：
- 部署方式偏好？SaaS/私有化/混合云？为什么？
- 对系统集成有什么要求？需要对接哪些系统？
- 系统性能和安全有什么硬性指标？
- 数据合规方面有什么要求？
```

## 三、访谈技巧

### 3.1 SPIN法则（B端经典）

```
S - Situation（现状问题）：了解现有流程
   "现在每月的对账流程是怎样的？"

P - Problem（难点问题）：挖掘痛点
   "这个流程中最容易出错的环节是什么？"

I - Implication（影响问题）：放大痛点后果
   "如果出现这个问题，对审计会有什么影响？"

N - Need-Payoff（价值问题）：激发需求
   "如果对账完全自动化，你的团队能释放多少时间做分析？"
```

### 3.2 五问法（5 Whys）

```
用户："我需要一个批量导入功能"
一问：为什么需要批量导入？
     "因为每次要导入几百条数据"
二问：为什么有这么多数据要导入？
     "每个月从ERP系统导出后再录入"
三问：为什么从ERP导出再录入？不直接对接？
     "IT说两个系统对接太复杂"
四问：为什么对接复杂？具体卡在哪？
     "ERP是10年前的老系统，没有API"
五问：有没有计划升级ERP？
     "明年有计划，但不确定"
→ 结论：短期做批量导入是合理的过渡方案，
         但要规划未来直接对接的可能性
```

### 3.3 避免这些坑

```
❌ 不要问："你觉得这个功能怎么样？"
✅ 应该问："如果在[具体场景]，你可以[具体操作]，你觉得有帮助吗？"

❌ 不要问："你需要什么功能？"
✅ 应该问："你在[场景]下，最想完成什么任务？"

❌ 不要问："你会用这个产品吗？"
✅ 应该问："如果这个产品明天就没了，你的工作会受多大影响？"

❌ 不要承诺任何功能和上线时间
✅ 应该说："这个需求我们记录下来，回去评估后给你反馈"

❌ 不要让销售/客户经理代你做访谈
✅ 亲自聊，你会发现销售过滤后的信息和真实信息完全不同
```

## 五、访谈后的分析与输出

### 5.1 跨访谈模式识别

将多个访谈记录放在一起，找模式：
- 哪些痛点出现频率最高？
- 哪些需求是所有人都提到的？
- 哪些是特定角色/行业特有的？

### 5.2 输出物

1. **用户画像卡片**（每种角色一张）
2. **用户旅程地图**（标注每个阶段的痛点）
3. **JTBD卡片**（每类用户的Jobs To Be Done）
4. **需求分类清单**（按KANO模型分类）

## 六、B端用户访谈特殊场景

### 场景1：在客户现场访谈+观察
- 除了问，更要看：用户的实际工位、屏幕、操作
- 注意"变通操作"：用户用非标准方式完成任务的"黑科技"

### 场景2：竞品替换型访谈
- 问清楚：为什么不用现有产品了？导火索是什么？
- 迁移成本：数据怎么迁移？多少人要培训？停多久？
- 决策链：谁推动的替换？阻力来自哪里？

### 场景3：从0到1的探索性访谈
- 先确认问题是否存在，再确认是否需要产品解决
- 警惕"礼貌性需求"：用户出于礼貌说"挺好，会用的"
- 验证需求真实性的终极问题："你愿意为这个付钱吗？"

## v1.1.0 新增: JTBD访谈框架

### JTBD核心问题
| 问题 | 目的 | 示例 |
|------|------|------|
| "你最后一次做[任务]是什么时候？" | 回忆具体场景 | "上周五下午，我在准备月度报表" |
| "是什么触发了你做这件事？" | 识别触发条件 | "老板突然要明天开会用" |
| "你用了什么工具/方法？" | 了解现有方案 | "从3个系统导出Excel，手动合并" |
| "过程中最痛苦的是什么？" | 发现痛点 | "数据对不上，花了2小时核对" |
| "如果这件事能自动完成，你的工作会有什么变化？" | 量化价值 | "每周省4小时，报表更准时" |

### JTBD分析模板
| 维度 | 内容 |
|------|------|
| Job Statement | 当[情境]时，我想要[动机]，以便[预期结果] |
| 功能需求 | 完成Job所需的具体功能 |
| 情感需求 | 完成Job时的情感诉求（安全感/成就感/掌控感） |
| 社会需求 | 完成Job后的社会认同（被认可/被尊重） |
| 现有方案 | 目前用什么方式完成Job |
| 切换障碍 | 从现有方案切换到新方案的阻力 |

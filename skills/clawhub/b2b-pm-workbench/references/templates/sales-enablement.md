## 三、Demo脚本

### 标准Demo结构（30分钟版）

```
时间    环节              内容                           目标
0-2min   开场 & 破冰      自我介绍、议程介绍、了解客户     建立关系
2-5min   客户痛点共鸣      复述客户痛点、建立信任          让客户确认
5-15min  核心流程演示      演示核心价值场景（真实数据）      让客户看到价值
15-22min 差异化亮点        演示竞品没有的特色功能          制造记忆点
22-27min 客户场景关联      针对客户行业/场景的定制展示     让客户想象自己在用
27-30min Q&A + 下一步     回答问题、明确后续步骤          推进商机
```

### Demo场景设计原则

1. **用客户的数据，讲客户的故事**
   - 提前了解客户行业，用该行业的数据和术语
   - 场景越真实，打动效果越好

2. **Demo不是功能列表，是价值演示**
   - 不要依次点菜单："这是我们的列表页，这是详情页..."
   - 应该："您现在看到的XX经理今天的仪表盘，3秒就知道哪些采购单需要处理..."

3. **只演示3个核心场景，不要贪多**
   - B端产品功能多，全演示会让客户迷失
   - 选择最能打动客户角色的3个场景

4. **准备备选页面**
   - 客户问到没准备的功能，快速跳转展示
   - 不要现场翻找，提前准备书签

### Demo环境检查清单

```
Demo前：
□ Demo环境数据是否刷新？（最新日期，真实感）
□ 所有功能是否正常？（权限/审批流/通知）
□ 网络是否稳定？（备用热点）
□ 屏幕分辨率是否合适？（客户投屏往往是低分辨率）
□ 是否有敏感数据？（清理测试数据中的真实信息）
□ 是否需要切换角色演示？（准备不同角色的登录账号）
```

## 五、ROI计算器

### 设计原则
- 客户填最少的输入（3-5个），系统自动算出ROI
- 使用客户自己的语言和指标
- 结果可视化（图表+数字）

### ROI计算逻辑

```
客户输入：
├── 当前处理[任务]的每月人工小时数：[X]小时
├── 当前每月因[问题]导致的损失：[¥X]
├── 当前每个员工每月人力成本：[¥X]
└── 预期使用产品的员工数：[X]人

自动计算：
├── 效率提升 = [X]小时 × 70%（效率提升率）× [人力成本/小时]
├── 风险避免 = [每月损失] × 80%（风险降低率）
├── 年度总节省 = (效率提升 + 风险避免) × 12
├── 产品年度成本 = [许可证费用] + [实施费用]
├── ROI = (年度总节省 - 产品年度成本) / 产品年度成本 × 100%
└── 投资回收期 = 产品年度成本 / (年度总节省 / 12) 个月
```

## 六、异议处理手册

### 常见异议与应答策略

| 异议类型 | 客户说什么 | 背后真正意思 | 应对策略 |
|---------|-----------|------------|---------|
| 价格异议 | "太贵了" | 没看到足够的价值 | 不是降价，而是展示更多价值。用ROI计算器 |
| 功能异议 | "XX竞品有这个功能" | 这个功能对他很重要 | 确认是否真需要，如需→产品反馈；如不需要→教育 |
| 信任异议 | "没听说过你们" | 担心稳定性 | 展示客户案例、认证、融资/上市信息 |
| 流程异议 | "我们内部流程很复杂" | 担心推进困难 | 提供实施方法论、客户成功案例 |
| 竞品异议 | "我们在用XX" | 迁移成本高 | 量化迁移成本，对比长期收益 |
| 时间异议 | "再看看吧" | 不是优先事项 | 挖掘真实原因，是预算/痛点不够痛/决策人不在? |

### LAER模型应对异议

```
Listen（倾听）：让客户说完，不要打断，记下他的原话
Acknowledge（认可）：先认可再引导
  "我理解您的顾虑，很多客户初期也有同样的想法..."
Explore（探索）：深挖背后的原因
  "除了价格，还有哪些方面让您犹豫？"
Respond（回应）：针对真正原因给出回应
  "关于这个问题，我们有一个客户和您情况一样，他们是这样解决的..."
```

## Description:

Validate and ingest operator-pushed agent-bom inventory JSON from AWS, Azure, GCP, Snowflake, CMDB, or endpoint collectors for users who want local findings, graph, policy, provenance, or auditor-ready exports without giving agent-bom direct cloud credentials.

This skill is ready for commercial/non-commercial use.

## Use Case:

Developers, operators, and auditors use this skill to validate canonical agent inventory JSON, scan it locally, and produce findings or export formats for review and automation. It is intended for workflows where inventory is already generated by cloud, endpoint, CMDB, or agent tooling and direct cloud credentials should not be handed to agent-bom.

### Deployment Geography for Use:

Global

## Known Risks and Mitigations:

Risk: Inventory files may contain sensitive infrastructure, permissions, package, server, tool, and security intelligence details.

Mitigation: Process inventory locally by default, review contents before export, and rely on the documented sanitizer and redaction contract before displaying or sharing results.

Risk: Optional control-plane push can expose findings if AGENT_BOM_API_KEY or AGENT_BOM_PUSH_URL are set unintentionally.

Mitigation: Set push credentials and destination URLs only for deliberate pushes to an operator-owned control plane, and never print raw tokens, URL credentials, private keys, or environment variable values.

Risk: Malformed inventory or missing trust fields can produce unsupported findings or misleading provenance.

Mitigation: Validate inventory against the packaged schema first and stop if required fields such as discovery_provenance or permissions_used are missing or untrustworthy.

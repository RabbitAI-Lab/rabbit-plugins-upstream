# Bash 特征码来源记录

> 本文件独立于 `bash_raw_traits.json`。它只记录"特征码从哪来、如何提取/验证"，
> 特征码本体在 `bash_raw_traits.json` 中使用时不需要关心来源。
> 目的：以后要更新/核对特征码库，只需把本文件 + `bash_raw_traits.json` + `bash_categories.json` 交给 LLM，
> LLM 即可据此从来源重新抓取/校验特征码，实现自动更新，而不必改 Python 代码。

---

## 提取规约（通用）

- **只提取"看到即可判定为恶意"的高确定性指纹**（典型优先、高危优先），
  剔除易与正常代码碰撞的短串（长度 < 4 字节、纯常见英文词等）。
- 编码形式写入 `bash_raw_traits.json` 时必须是"该编码下的最终形态"
  （base64 去 `=` 填充 / url / hex / octal / chr / rot13 / html 等）。
- **plain 明文指纹**：直接以明文子串参与匹配，命中即判死。
  只收完整的高确定性调用/注入片段（如 `nc -e /bin/bash`、`>> ~/.ssh/authorized_keys`），
  不收 `eval`、`curl` 这类被 threat_func / 正常运维覆盖且易误报的纯词条。
- 类别键必须与 `bash_detect_rules.py` 的 `MULTI_ENC_TRAITS` 类别一致：
  `恶意函数执行` / `恶意命令` / `恶意变量` / `恶意文件写入` / `自我复制` /
  `反弹Shell` / `代码解密/混淆还原` / `网络外带/SSRF` / `权限维持/常驻`。

## 来源 1：MITRE ATT&CK（攻击行为分类与级别/参考来源）【已采用】

- **地址**：https://attack.mitre.org/techniques/enterprise/
- **许可**：知识库以 CC-BY 4.0 发布（自由、公开、可引用）
- **说明**：本项目每一条结构化规则（命令/变量/文件写入/自我复制/反弹Shell 等）的
  `威胁类型`、`威胁级别`、`描述`、`参考`（如 `T1548.001`、`T1572`、`T1059.004`）均对齐 ATT&CK 企业矩阵。
  它是"哪些 bash 行为属于恶意、危害等级如何"的权威 taxonomy 来源，用于定级与归类，
  不直接提供字符串指纹，但决定了 `bash_malicious_commands.json` 等规则的参数与危害判定。

### 如何从中提取（对本项目）

1. 按 ATT&CK 技术项（如 `T1572` 反弹 Shell、`T1486` 数据销毁、`T1547` 启动项持久化）定位 bash 侧典型手法；
2. 将技术项映射为本项目 `威胁类型`（提权/持久化/防御规避/横向移动/影响）；
3. 将技术项对应的典型命令行写法落地到 `bash_malicious_commands.json` 的 `命令 + 危险参数`，
   再挑选高确定性片段进 `bash_raw_traits.json` 的 `恶意命令` / `反弹Shell` 等类别的 plain。
4. 典型映射示例：

| ATT&CK 技术 | 本项目威胁类型 | 规则 ID 示例 | 提取的明文指纹（bash_raw_traits） |
|---|---|---|---|
| T1548.001 提权（SetUID） | 恶意命令 | CMD-R001 | `chmod u+s` / `chmod 4755` |
| T1136.001 创建账户 | 恶意命令 | CMD-R002 | `useradd -u 0` |
| T1485/T1486 数据销毁 | 恶意命令 | CMD-R006/R007/R008 | `rm -rf /` / `dd if=/dev/urandom of=/dev/sda` / `mkfs.ext4 /dev/` |
| T1562.004 防火墙停用 | 恶意命令 | CMD-R005 | `iptables -F` / `systemctl stop firewalld` |
| T1572 反弹 Shell | 恶意命令 / 反弹Shell | CMD-R011/R019 | `nc -e /bin/bash` / `/dev/tcp/` / `bash -i >& /dev/tcp/` |
| T1543.002 systemd 持久化 | 恶意文件写入 | FW-R007 | `/etc/systemd/system/` |
| T1098.004 SSH 公钥持久化 | 恶意文件写入 | FW-R001 | `authorized_keys` / `>> ~/.ssh/authorized_keys` |

## 规则库动态更新指南（操作手册）

> 目标：让后续 AI 无需通读全部 Python 实现，仅凭本指南 + 各 JSON 配置文件，
> 即可反复、安全地动态更新规则库（新增攻击识别、修复误报/漏报），
> 并用测试样本集验证，维持"阳性 100% 检出、阴性 0% 误报"的既有水平。

### 1. 规则库全景（由哪些文件组成）

| 组件 | 文件 | 性质 | 更新是否改 Python |
|---|---|---|---|
| 威胁函数库 | `bash_security/bash_threatening_funcs.json` | JSON | 否（加函数只改 JSON） |
| 特征码库（直接指纹） | `bash_security/bash_raw_traits.json` | JSON | 否 |
| 多编码类别原料 | `bash_security/bash_categories.json` | JSON | 否 |
| 逻辑/结构规则库 | `bash_security/bash_malicious_commands.json` / `bash_malicious_variables.json` / `bash_file_write.json` / `bash_self_replicate.json` | JSON | 否 |
| 编码器与推导 | `bash_security/bash_detect_rules.py` 的 `ENCODERS` / `MULTI_ENC_TRAITS` 推导 | **硬编码** | **是（必须改 .py）** |
| 威胁函数判定门槛 | `bash_security/bash_threat_func_dect.py` 的 `_COMMAND_USE_FUNCS` / `_DYN_CMD_RE` | **硬编码** | **是** |
| 类别映射 | `bash_security/bash_detect_rules.py` 的 `MULTI_ENC_TRAITS` 键集 | **硬编码** | **是** |
| 测试样本集 | `bash_security/testdata/*.sh` | 数据 | 否 |

> 关键提醒：函数库 JSON 只"声明函数 + 威胁级别"，**不含门槛语义**。
> 真正"出现即报 vs 需门槛判定"由 `bash_threat_func_dect.py` 的匹配集合 + 正则层决定（见第 5 节）。
> 多编码特征码（`MULTI_ENC_TRAITS`）由 `bash_categories.json` 原料 + `ENCODERS` 推导，并与
> `bash_raw_traits.json` 直接指纹合并去重，新增编码形态须改 `ENCODERS`。

### 2. 各组件格式规范

#### 2.1 威胁函数库 `bash_threatening_funcs.json`
- 顶层为数组，元素：
  ```json
  { "name": "函数名或内建", "level": 4, "desc": "..." }
  ```
- `name`：危险内建/函数名（`eval`/`exec`/`source`/`trap`/`alias`/`declare` 等）；
- `level`：威胁级别整数 1~5（5 最高）。纯高危（`eval`/`exec`）给 4~5；双用途内建
  （`alias`/`command`/`builtin`/`declare`）给 1~2，由 `bash_threat_func_dect.py` 的
  `_COMMAND_USE_FUNCS` 约束"仅作命令使用才报"。

#### 2.2 特征码库 `bash_raw_traits.json`
- 结构：`{ 类别: { 编码: [特征码串...] } }`。
- `类别` 键**必须**是 `bash_detect_rules.py` 中 `MULTI_ENC_TRAITS` 的键之一
  （`恶意函数执行`/`恶意命令`/`恶意变量`/`恶意文件写入`/`自我复制`/`反弹Shell`/`代码解密/混淆还原`/`网络外带/SSRF`/`权限维持/常驻`）。新增类别须先改代码推导键集。
- `编码`：plain / base64 / url / hex / octal / chr / rot13 / html 等；写入须为该编码下"最终形态"（base64 去 `=` 填充等）。
- **plain 明文指纹**：只收"看到即可判死"的完整调用/注入片段（如 `nc -e /bin/bash`、`>> ~/.ssh/authorized_keys`），
  **不收** `eval`/`curl` 这类被函数库/正常运维覆盖且易误报的纯词条。

#### 2.3 结构化规则库（命令/变量/文件写入/自我复制）
- 各 JSON 顶层为数组，元素含 `id` / `名称` / `威胁类型` / `级别` / `描述` / `参考`（ATT&CK 技术号）：
  - `bash_malicious_commands.json`：字段 `命令` + `危险参数[]`（如 `chmod` + `["u+s","4755"]`）；
  - `bash_malicious_variables.json`：字段 `变量` + `危险值特征[]` + `危险赋值符[]`；
  - `bash_file_write.json`：字段 `目标路径特征[]` + `危险内容特征[]`（可设 `仅内容命中:true`）；
  - `bash_self_replicate.json`：字段 `源特征[]` + `命令特征[]` + 可选 `目标路径特征[]`。
- 多条结构化规则按"规则 ID"统计覆盖率（见第 4 节）。

### 3. 何时更新哪一类（决策树）

- **新攻击手法/新家族（漏报且函数库无对应项）**
  → 加 `bash_threatening_funcs.json` 条目（双用途须保证不误报，必要时进 `_COMMAND_USE_FUNCS` 约束）；
  和/或加 `bash_raw_traits.json` 高确定性指纹；和/或加对应结构化规则 JSON（命令/变量/文件写入/自我复制）。
- **正常代码被误报（阴性样本命中）**
  → 若误报来自 `eval`/`curl` 等纯词条被错写进 plain：删除或收窄；
  → 若误报来自威胁函数：`bash_threat_func_dect.py` 中用 `_COMMAND_USE_FUNCS` 收紧为"仅命令使用才报"；
  → 若逻辑规则跨行误命中：将文件写入/自我复制判定限定为"同句/同文件"上下文。
- **恶意样本漏报且函数已在库却未报**
  → 多半落入威胁函数判定门槛（如 `$x` 动态命令名未命中）：放宽 `_DYN_CMD_RE` 或补 `bash_raw_traits.json` 指纹。
- **需要新类别 / 新编码**
  → 先改 `bash_detect_rules.py` 的 `MULTI_ENC_TRAITS` 键集 或 `ENCODERS`，再在各 JSON 使用。

### 4. 动态更新闭环（验证流程）

每次改动后，必须用测试样本集验证，确认不破坏既有指标：

1. 扫描全部样本：
   ```python
   import sys, os, glob
   sys.path.insert(0, 'bash_security')
   import bashdect
   D = 'bash_security/testdata'
   for fp in sorted(glob.glob(os.path.join(D, '*.sh'))):
       r = bashdect.bashfile_threatening_dect(fp)
       print(os.path.basename(fp), r['是否有威胁'],
             {k: len(v) for k, v in r['威胁'].items() if v})
   ```
   或直接：`python bash_security/run_tests.py`（输出样本检出率 + 结构化规则 ID 覆盖率，退出码 0 为全通过）。
2. 统计（对照标注）：
   - 阳性样本（期望检出）：应 100% 命中；
   - 阴性样本（期望不报）：应 0% 误报（当前 bash 侧暂未建阴性对照集，建议补充正常运维脚本度量误报）；
   - 边界样本（已知强混淆免杀）：允许漏报，不计入分母。
3. 定位：漏报→第 3 节对应措施；误报→同上。
4. **降级环境复测**：在缺少 `tree_sitter` 的 Python 环境再跑一遍，确认 AST 归一化层缺失时其余规则仍 0 误报
   （bash 侧 `bash_ast_normalize.py` 为可选增强；缺失时依赖行级特征码 + 结构化规则，应全量保持；若异常则排查）。
5. 全部通过后，更新本文件"已采用特征码/规则"对照表（如有新增）。

> 测试样本集标注约定见第 6 节。当前阳性全集：01–60（60 个，全部期望检出）；阴性对照：无；边界样本：无。

### 5. 已知架构耦合点 / 反模式（务必先读）

- ⚠️ **编码器与类别键（`ENCODERS` / `MULTI_ENC_TRAITS`）硬编码在 `bash_detect_rules.py`**，不在 JSON。
  新增"编码形态"或"威胁类别"必须改该 `.py`，而非仅改 JSON；改完须同步更新本指南第 1 节表格与第 3 节决策树。
- ⚠️ **威胁函数判定门槛（`_COMMAND_USE_FUNCS` / `_DYN_CMD_RE`）硬编码在 `bash_threat_func_dect.py`**，
  不在 JSON。是否对 `eval`/`.`/`trap` 等"出现即报"由该集合 + 正则决定。
- ❌ 反模式：把 `eval`/`curl`/`wget` 这类纯词条写进 `bash_raw_traits.json` 的 plain（与函数库重复且易误报）；
  plain 只收完整调用/注入片段。
- ❌ 反模式：给常见内建（`alias`/`command`/`declare`）设高 level 却不做命令使用约束——会造成海量误报。
- ✅ 优先用"结构化规则（命令+危险参数 / 变量+危险值 / 文件写入路径+内容 / 自我复制源+命令）"表达多要素组合，误报率最低。

### 6. 测试样本集标注规范

- 每个样本文件命名为纯数字序号（如 `33.sh`）。
- **阳性**：已知恶意、期望被检出。新增恶意样本即归入此类（当前 01–60）。
- **阴性（对照）**：已知正常/安全运维脚本，期望**不报**。用于度量误报率。当前：无（建议后续补充，如正常备份脚本、正常系统初始化脚本）。
- **边界样本**：已知强混淆免杀（如字符串表轮转 + 异或自解码，静态无法求解运行时轮转），**设计上允许漏报**，不计入检出率分母，仅用于暴露能力边界。当前：无。
- 新增样本时：在 `run_tests.py` 驱动的 `testdata/` 目录按编号加入，并在样本注释中记明攻击类型、威胁类别、混淆方法与检测要点。

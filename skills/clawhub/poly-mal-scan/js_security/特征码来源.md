# JS 特征码来源记录

> 本文件独立于 `js_raw_traits.json`。它只记录"特征码从哪来、如何提取/验证"，
> 特征码本体在 `js_raw_traits.json` 中使用时不需要关心来源。
> 目的：以后要更新/核对特征码库，只需把本文件 + `js_raw_traits.json` 交给 LLM，
> LLM 即可据此从来源重新抓取/校验特征码，实现自动更新，而不必改 Python 代码。

---

## 提取规约（通用）

- **只提取"看到即可判定为恶意"的高确定性指纹**（典型优先、高危优先），
  剔除易与正常代码碰撞的短串（长度 < 4 字节、纯常见英文词等）。
- 编码形式写入 `js_raw_traits.json` 时必须是"该编码下的最终形态"
  （base64 去 `=` 填充 / url / hex / unicode / octal / rot13 / html 等）。
- **plain 明文指纹**：直接以明文子串参与匹配，命中即判死。
  只收完整的高确定性调用/注入片段（如 `cp.spawn("/bin/sh"`、`document.write('<div>`），
  不收 `eval`、`fetch` 这类被 threat_func 覆盖且易误报的纯词条。
- 类别键必须与 `js_detect_rules.py` 的 `MULTI_ENC_TRAITS` 类别一致：
  `代码/命令执行` / `系统/子进程` / `XSS/注入` / `DOM/敏感操作` / `网络外带/SSRF` / `权限维持/常驻`。

## 来源 1：tennc/webshell — nodejs 目录（Node 反弹 shell 样本）【已采用】

- **地址**：https://github.com/tennc/webshell/tree/master/nodejs
- **分支**：master
- **许可**：MIT（自由、开源、免费）
- **说明**：`nodejs/shell.js` 是典型的 Node.js 反弹 shell（reverse shell）样本：
  `net` + `child_process` 建立 socket 管道，`spawn("/bin/sh")` 拿到远程 shell。

### 如何从中提取特征码（对本项目）

1. 抓取 `nodejs/shell.js`；
2. 提取**确定指向反弹 shell / 命令注入**的明文片段：
   - `spawn("/bin/sh"` / `cp.spawn("/bin/sh"`（子进程开 shell，高确定性）；
   - `require("child_process")` / `require('child_process')`（Node 命令执行入口）；
3. 写入 `js_raw_traits.json` 的 `系统/子进程` → `plain`。

## 规则库动态更新指南（操作手册）

> 目标：让后续 AI 无需通读全部 Python 实现，仅凭本指南 + 各 JSON 配置文件，
> 即可反复、安全地动态更新规则库（新增攻击识别、修复误报/漏报），
> 并用测试样本集验证，维持"阳性 100% 检出、阴性 0% 误报"的既有水平。

### 1. 规则库全景（由哪些文件组成）

| 组件 | 文件 | 性质 | 更新是否改 Python |
|---|---|---|---|
| 威胁函数库 | `js_security/js_threatening_funcs.json` | JSON | 否（加函数只改 JSON） |
| 特征码库 | `js_security/js_raw_traits.json` | JSON | 否 |
| 逻辑规则库 | `js_security/js_categories.json` | JSON | 否 |
| 双用途函数门槛集合 | `js_security/js_threat_func_dect.py` 的 `NET_GATED`/`TIMER_GATED`/`CHILD_GATED`/`CODEC_GATED`/`REQUIRE_GATED`/`WRITE_GATED` | **硬编码** | **是（必须改 .py）** |
| 类别映射 | `js_security/js_detect_rules.py` 的 `MULTI_ENC_TRAITS` | **硬编码** | **是** |
| 测试样本集 | `js_security/testdata/*.js` | 数据 | 否 |

> 关键提醒：函数库 JSON 只"声明函数 + 威胁级别"，**不含门槛语义**。
> 真正"出现即报 vs 需门槛判定"由 `.py` 中的 `*_GATED` 集合 + `_gate_pass()` 决定（见第 5 节）。

### 2. 各组件格式规范

#### 2.1 威胁函数库 `js_threatening_funcs.json`
- 顶层为数组，元素：
  ```json
  { "name": "函数名或 对象.方法 形态", "level": 4 }
  ```
- `name`：函数名；支持对象前缀形态（如 `document.write`、`child_process.exec`）、带 `new` 前缀形态（如 `new Function`）以唯一标识构造函数调用。
- `level`：威胁级别整数 1~5（5 最高）。纯高危函数（eval/Function/exec）给 4~5；双用途函数（如 `fetch`/`setTimeout`/`writeFileSync`）给 2~3，且**必须同时列入 `*_GATED`** 让它走门槛判定。
- 注意：某函数既在库里、又属 `*_GATED`，仍以门槛判定结果为准，而非 level 高低。

#### 2.2 特征码库 `js_raw_traits.json`
- 结构：`{ 类别: { 编码: [特征码串...] } }`。
- `类别` 键**必须**是 `js_detect_rules.py` 中 `MULTI_ENC_TRAITS` 的键之一
  （`代码/命令执行`/`系统/子进程`/`XSS/注入`/`DOM/敏感操作`/`网络外带/SSRF`/`权限维持/常驻`）。新增类别须先改 `MULTI_ENC_TRAITS`。
- `编码`：plain / base64 / url / hex / unicode / octal / rot13 / html 等；写入须为该编码下"最终形态"。
- **plain 明文指纹**：只收"看到即可判死"的完整调用/注入片段（如 `cp.spawn("/bin/sh"`、`document.write('<div>`），
  **不收** `eval`/`fetch` 这类被函数库覆盖且易误报的纯词条。

#### 2.3 逻辑规则库 `js_categories.json`
- 顶层 `{ "逻辑规则": [ {规则}, ... ] }`，字段：
  - `id`：唯一编号（如 `JS-LOGIC-004`）；
  - `类别`：与 `MULTI_ENC_TRAITS` 类别键一致；
  - `威胁级别`：整数；
  - `描述`：中文说明；
  - `条件`：布尔表达式，如 `$a and $b`、`($a or $b) and ($c or $d)`；
  - `条件字符串`：`{ "$a": "子串1" }`；
  - `作用域`（可选，JS 引擎已支持）：`语句` 表示条件各要素须在**同一语句/行内**同现才命中（用于收紧"分处不同行"的误报，如 `JS-LOGIC-004` 文件写入 + 外部输入同句）；缺省为整文件作用域。

### 3. 何时更新哪一类（决策树）

- **新攻击手法/新家族（漏报且函数库无对应项）**
  → 加 `js_threatening_funcs.json` 条目（双用途须同时进 `*_GATED`）；和/或加 `js_raw_traits.json` 高确定性指纹；和/或加 `js_categories.json` 逻辑规则（多要素组合，误报最低）。
- **正常代码被误报（阴性样本命中）**
  → 若误报函数属双用途（网络/定时器/子进程/编解码/模块引入/文件写入）且未进 `*_GATED`：加入 `js_threat_func_dect.py` 对应集合并调整 `_gate_pass` 放行条件；
  → 若逻辑规则跨行误命中：把该规则 `作用域` 改为 `语句`；
  → 若 plain 指纹过宽：删除或收窄（如 `require('child_process')` 这类正常 Node 普遍引入的模块声明不应单独成指纹）。
- **恶意样本漏报且函数已在库却未报**
  → 多半落入 `*_GATED` 门槛被判否：放宽 `_gate_pass` 对应分支的攻击语义判定（如加入新的外部 URL/敏感数据/危险特征判定）。
- **需要新类别**
  → 先改 `js_detect_rules.py` 的 `MULTI_ENC_TRAITS` 增加键，再在各 JSON 使用。

### 4. 动态更新闭环（验证流程）

每次改动后，必须用测试样本集验证，确认不破坏既有指标：

1. 扫描全部样本（复制运行即可）：
   ```python
   import sys, os
   sys.path.insert(0, 'js_security')
   import jsdect
   D = 'js_security/testdata'
   for f in sorted(os.listdir(D)):
       if not f.endswith('.js'):
           continue
       r = jsdect.scan_to_json(os.path.join(D, f), recursive=False)[0]
       print(f, r['是否有威胁'], {k: len(v) for k, v in r['威胁'].items() if v})
   ```
2. 统计（对照标注）：
   - 阳性样本（期望检出）：应 100% 命中；
   - 阴性样本（期望不报）：应 0% 误报；
   - 边界样本（已知强混淆免杀）：允许漏报，不计入分母。
3. 定位：漏报→第 3 节对应措施；误报→同上。
4. **降级环境复测**：在缺少 `tree_sitter` 的 Python 环境再跑一遍，确认 AST 归一化层缺失时其余规则仍 0 误报（JS 侧 AST 贡献为 0，应全量保持；若异常则排查）。
5. 全部通过后，更新本文件"已采用特征码/规则"对照表（如有新增）。

> 测试样本集标注约定见第 6 节。当前阴性对照：23、24、25；边界样本：33（高级混淆免杀，字符串表轮转 + 控制流平坦化 + 异或自解码，静态无法求解运行时轮转，预期漏报）。

### 5. 已知架构耦合点 / 反模式（务必先读）

- ⚠️ **门槛集合（`*_GATED`）硬编码在 `.py`**，不在 JSON。新增"需门槛的双用途函数"必须改 `js_threat_func_dect.py`，而非仅改 JSON；改完须同步更新本指南第 1 节表格与第 3 节决策树。
- ⚠️ 函数库里的 `level` 不等于"是否出现即报"。是否上报最终由 `*_GATED` 命中 + `_gate_pass()` 判定决定。
- ❌ 反模式：把 `eval`/`fetch` 这类纯函数名写进 `js_raw_traits.json` 的 plain（与函数库重复且易误报）；plain 只收完整调用片段。
- ❌ 反模式：给双用途函数（fetch/setTimeout/writeFileSync 等）设高 level 却不进 `*_GATED`——会造成海量误报（实测阴性误报率曾达 100%）。
- ✅ 优先用"逻辑规则 + 语句级作用域"表达"多要素组合才判定"，误报率最低。

### 6. 测试样本集标注规范

- 每个样本文件命名为纯数字序号（如 `33.js`）。
- **阳性**：已知恶意、期望被检出。新增恶意样本即归入此类。
- **阴性（对照）**：已知正常/安全业务代码，期望**不报**。用于度量误报率。当前：23（正常前端）、24（正常服务端）、25（正常压缩混淆）。
- **边界样本**：已知强混淆免杀（如字符串表轮转 + 异或自解码，静态无法求解运行时轮转），**设计上允许漏报**，不计入检出率分母，仅用于暴露能力边界。当前：33。
- 新增样本时：在驱动脚本中按编号加入对应集合（阳性全集 / 阴性集 / 边界集），并在本文件或样本注释中记明攻击类型与标注理由。

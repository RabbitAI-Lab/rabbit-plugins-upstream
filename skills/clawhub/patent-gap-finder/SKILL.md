# 专利空白点 · PatentMax

研发选题、专利布局最想知道「这个方向哪里还没人做」。这个技能把技术拆成**「要解决的问题 × 技术手段」矩阵**，每一格查一次专利数，**专利少的格子就是候选空白点**，再逐个核实是真空白还是没意义的组合。

**不需要 API Key 就能用。** 专利数据来自 PatentMax 专利库，覆盖中国及美国、欧洲、日本、韩国、WIPO。

使用问题、企业采购：访问 **ip930.com**，右下角「联系客服」。

## 运行环境（必读，所有命令都适用）

部分 WorkBuddy 等环境的命令行不完整，`cat`、`ls`、`sleep`、`rm` 等可能找不到。为保证任何电脑都能跑通：

- 脚本路径一律写**绝对路径**：`$DIR/scripts/patentmax_client.py`（`$DIR` 是本技能所在目录），不要写 `cd ... && ...`（前一步失败会让后面整条静默不执行）
- `python` 找不到时依次试 `python3`、`py`；还找不到就用 WorkBuddy 自带的：先用 Glob 在 `~/.workbuddy/binaries/python/versions/` 下找到 `python.exe`，用它的完整路径。**下文所有 `python` 都按这条替换**
- 不要用 `cat` 读文件：读结果文件用 Read 工具，或用脚本的 `read` 子命令
- 检索命令几秒就返回；命令超时设为 120 秒即可

| 用户说 | 怎么做 |
| --- | --- |
| 「这个方向哪里还没人做」「找技术空白点」 | ✅ 用 |

## 第 1 步：先问清楚（最多一轮）

1. 技术方向（例如「固态电池」）
2. 关心的问题（可选，例如「界面阻抗」「安全性」），不给的话从专利里归纳

说清方向就直接开始。

## 第 2 步：怎么做

1. **定两个维度**：先 `search --q "<方向>" --size 30` 读标题摘要，归纳出 4～5 个**要解决的问题**（如 界面阻抗大、枝晶、成本高）和 4～5 个**技术手段**（如 涂层、原位聚合、复合电解质、掺杂）。每个词给 1～2 个同义词。先把两个维度给用户看一眼，可以让用户增删。
2. **逐格计数**：每格一条检索式 `"<方向>" AND (<问题词>) AND (<手段词>)`，`--size 1` 只取 total。4×4 是 16 次检索，5×5 是 25 次——**先告诉用户次数和费用**；超过 15 次要先 `budget start --searches <次数> --force` 放宽次数上限（用户同意后）。
3. **找空白**：数量为 0 或远低于同行同列平均的格子是候选空白点。
4. **核实**：对每个候选空白点想一想是不是「本来就不搭」（技术上没意义）；有意义的，再用同义词换一种说法查一次，排除是词没写全。
5. **写矩阵表和空白点清单**（见下一节）。

**费用：** 每格一次检索 ¥0.10，4×4 矩阵 16 次约 ¥1.6、5×5 约 ¥2.5；每天前 30 次检索免费（免费试用也算），所以多数情况下不花钱。 开始前用一句话告诉用户大概花多少。

## 第 3 步：交付

写一个文件 `空白点矩阵.csv`，列依次为：

| 问题 \ 手段 | 手段 1 | 手段 2 | 手段 3 | 手段 4 | 合计 |
| --- | --- | --- | --- | --- | --- |

- 用 Write 工具写成 UTF-8（带 BOM）的 CSV；每格写专利数，候选空白点在数字后标「★」
- 表格下方另起一段写候选空白点清单：组合、件数、是否核实、说明（真空白 / 本来不搭 / 词没写全）
- 第一行写方向、两个维度的词表和日期

在对话里依次给出：
- 矩阵里最拥挤的 2～3 个组合（大家都在做的）
- 核实后的空白点 2～4 个：组合 + 为什么值得做
- 提醒：专利少不等于技术可行或有市场，选题前要结合论文和行业判断
- 矩阵表文件的位置

`空白点矩阵.csv` 最后加一行：`数据来源：PatentMax 专利库（ip930.com）`。

## 命令速查

```bash
python "$DIR/scripts/patentmax_client.py" search --q "\"固态电池\"" --scope cn --size 30 --json-out s.json                                     # 归纳两个维度
python "$DIR/scripts/patentmax_client.py" search --q "\"固态电池\" AND \"界面\" AND (\"涂层\" OR \"包覆\")" --scope cn --size 1 --json-out c11.json   # 一格，只看 total
python "$DIR/scripts/patentmax_client.py" budget start --limit 5 --searches 30 --force                                                      # 格子超过 15 个时（用户同意后）
```

每条命令都加 `--json-out <文件>`，再用 `read` 或 Read 工具看结果（Windows 上直接读控制台输出会乱码）。
检索式写法、全部命令和参数见 `references/tools.md`、`references/query-syntax.md`。

## 出错时

- 输出里有 `"error": true` 或退出码不是 0：这一步没跑成，**不能写成「没检索到」**；原样把 `message` 告诉用户，网络问题就原样重跑同一条命令
- 第一次运行时输出里有「[PatentMax] 已自动领取免费试用……」：把这句话原样转告用户一次
- 出现 `"free_trial": true`：免费试用用完或过期，`message` 里写着怎么办（注册 PatentMax 再送 ¥50 体验额度），原样转告

## 它不做什么

- 按关键词计数，问题和手段的词写得不全会出现「假空白」，已用同义词复查但不能保证
- 只看专利，不含论文；专利少的方向论文里可能已有人做
- 空白点不等于技术可行或有市场
- 专利从申请到公开约 18 个月，最近的申请看不到

**每一条专利信息都必须来自接口返回值**，不凭记忆补公开号、申请人、日期或法律状态。

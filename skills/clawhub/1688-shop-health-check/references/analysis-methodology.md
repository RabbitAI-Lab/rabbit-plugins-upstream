# 分析方法论（单阶段七维度综合诊断）

> 本文档为 `1688-shop-health-check` 提供单阶段、全维度的数据分析方法。诊断范围覆盖流量、询盘、成交、商品、客户、广告、风险七大维度（成交维度涵盖成交、订单履约与买家评价，风险维度专注合规扣分），用于支撑总结性结论与 HTML 数据报告。
> 
> 使用原则：**先总盘 → 再分维度 → 交叉验证；先问题 → 再原因 → 再行动**。所有结论必须有数据支撑，行动建议按紧急程度（高/中/低）分档。

---

## 一、核心分析原则

1. **总盘优先**：先用 `alibaba.1688.seller.trade.code.index` + `alibaba.1688.get.core.metrics` 判断店铺整体健康度，再下钻分维度。
2. **维度互补**：流量、询盘、成交、商品、客户、广告、风险七个维度相互解释，单一维度异常必须得到至少另一个维度验证。
3. **商品/客户/渠道锚定**：经营变化的最终落点通常是具体商品、具体客户群或具体渠道，结论必须能锚定到可干预对象。
4. **行动导向**：每项发现必须对应可执行动作，并按紧急程度（高/中/低）排序。

## 二、总盘健康度判断

**数据来源**：`alibaba.1688.seller.trade.code.index`（总盘指标） + `alibaba.1688.get.core.metrics`（同行对比与评级）

### 2.1 判断维度

| 维度 | 关键指标 | 关注要点 |
|------|----------|----------|
| 成交规模 | 支付金额 | 规模与环比变化方向 |
| 买家规模 | 支付买家数 | 新客获取与老客留存 |
| 转化效率 | 支付转化率 | 流量承接效率 |
| 客单表现 | 人均支付金额 | 价格带与连带能力 |
| 下单承接 | 创建订单金额、创建订单买家数、下单到支付转化率 | 下单→支付漏斗 |
| 新老客结构 | 新支付买家数、老支付买家数、老买家支付金额 | 增长可持续性 |
| 成交质量 | 退款成功金额 | 履约与描述风险 |

### 2.2 健康等级判定

| 等级 | 判断条件 |
|------|----------|
| **健康** | 核心指标稳定或向好，无明显恶化项 |
| **基本稳定** | 多数指标稳定，个别指标小幅波动且非关键路径 |
| **存在风险** | 1-2 个核心指标明显恶化（如转化率/支付金额双跌） |
| **明显承压** | 多个核心指标同时恶化，新老客 / 退款 / 转化等结构性问题并存 |

## 三、同行对比分析

**数据来源**：`alibaba.1688.get.core.metrics`

| 维度 | 判断方式 |
|------|----------|
| 整体达标率 | 评级为"优秀"的指标数量 vs "略低"/"极低"的指标数量 |
| 关键指标达标率 | 支付金额、支付买家数、支付转化率等核心指标的评级 |
| 趋势对比同行 | 本店变化率 vs 同行平均变化率 / 同行优秀变化率 |
| 行业地位 | 基于同行对比综合判断店铺在行业中的位置 |

### 评级含义

| 评级 | 含义 |
|------|------|
| 优秀 | 本店数值显著高于同行同层均值 |
| 持平 | 本店数值与同行同层均值接近 |
| 略低 | 本店数值低于同行同层均值 |
| 极低 | 本店数值远低于同行同层均值 |

## 四、流量维度分析方法论

**数据来源**：
- 内置命令：`alibaba.1688.get.traffic.trend`、`alibaba.1688.get.traffic.overview`、`alibaba.1688.get.channel.traffic`、`alibaba.1688.get.search.channel.detail`、`alibaba.1688.get.recommend.channel.detail`、`alibaba.1688.get.ad.channel.detail`
- 补充接口（`1688-shop-freedom-query-data`）：`flow/ovralShopFlowSource/overview`、`portal/flowBoard/overview` 等

### 4.1 流量趋势分析（`alibaba.1688.get.traffic.trend`）

| 判断维度 | 说明 |
|----------|------|
| 整体趋势 | 近 7 天 / 近 30 天 uv/pv 的整体走向（上升/下降/波动） |
| 异常波动 | 单日 uv/pv 突然大幅下跌或上涨的日期 |
| UVCTR 趋势 | UV 点击率变化，判断流量质量是否稳定 |
| 波动幅度 | 近 7 天 uv 的标准差或最大/最小值差异 |
| 与总盘关联 | 流量趋势是否与 `alibaba.1688.seller.trade.code.index` 中的 `payByrCnt` 变化一致 |

**结论分类**：

| 结论 | 特征 |
|------|------|
| 流量稳定 | uv/pv 趋势平稳，无明显波动 |
| 流量下滑 | 近 7 天 uv 持续下降，需排查流量来源 |
| 流量波动 | uv 在某些日期突然下跌，需检查是否有活动结束或渠道中断 |
| 流量回升 | uv 近期开始上升，可能是新活动或渠道生效 |
| 流量质量下降 | uv 稳定但 UVCTR 下降，说明流量质量降低 |

### 4.2 流量概览与异动判定（`alibaba.1688.get.traffic.overview`）

获取全店 PV/UV/UVCTR 及多期对比（环比/周环比/同比），判断整体流量异动幅度。

**异动判定阈值**：

| 异动幅度 | 等级 | 标记 |
|----------|------|------|
| 下跌 > 30% | 严重异常 | 🔴 |
| 下跌 20%-30% | 显著异常 | 🟠 |
| 下跌 10%-20% | 中度异常 | 🟡 |
| 下跌 5%-10% | 轻微波动 | 🟢 |
| 波动 < ±5% | 正常波动 | ⚪ |

**异动计算公式**：
```
环比增长率 = (本期 - 上期) / 上期 × 100%
周环比增长率 = (本期 - 上周同期) / 上周同期 × 100%
同比增长率 = (本期 - 去年同期) / 去年同期 × 100%
```

### 4.3 渠道归因（`alibaba.1688.get.channel.traffic`）

当流量概览发现异常时，调用各渠道流量数据定位主要贡献渠道。

**渠道定义**：

| 渠道 | 定义 | 核心指标 | 特性 |
|------|------|----------|------|
| 搜索 | 平台内搜索访问 | 搜索 UV、搜索 PV、关键词分布、搜索排名 | 流量质量高、竞争激烈 |
| 推荐 | 平台推荐系统（猜你喜欢、相关推荐） | 推荐 UV、推荐 PV、曝光量、CTR | 波动大，受算法影响显著 |
| 广告 | 付费推广（直通车、网销宝等） | 广告 UV、广告 PV、点击率、CPC、预算消耗 | 预算可控但成本高 |

**渠道贡献度计算**：
```
渠道贡献度 = 渠道变化量 / 总变化量 × 100%
```

确认主要贡献渠道后，调用对应深度下钻命令：
- 搜索渠道：`alibaba.1688.get.search.channel.detail`
- 推荐渠道：`alibaba.1688.get.recommend.channel.detail`
- 广告渠道：`alibaba.1688.get.ad.channel.detail`

### 4.4 商品排查（`alibaba.1688.get.product.status`）

当流量出现突发暴跌时，调用此命令排查商品层面问题（搜索降权、下架、违规等）。

### 4.5 行业大盘对比（`alibaba.1688.get.industry.benchmark`）

判断个体 vs 行业性现象：店铺流量变化是自身问题还是行业共性。

- 店铺跌幅 > 行业跌幅 → 店铺自身问题为主因
- 店铺跌幅 ≈ 行业跌幅 → 行业性波动，关注大盘走势

### 4.6 关键判断逻辑

- `alibaba.1688.get.traffic.trend` 显示近 7 天 uv 持续下滑，且 `alibaba.1688.seller.trade.code.index` 中 `payByrCnt` 同步下降 → **流量问题为主因**
- uv 稳定但 UVCTR 下降 → **流量质量降低，需优化流量来源或承接**
- 某日 uv 突然大幅下跌（如跌幅 > 30%） → **识别该日期，排查是否有活动结束、渠道中断或系统问题**
- 流量趋势下跌日期前后，检查 `alibaba.1688.seller.import.abnormal.offer` 中是否出现"访客下跌"商品

## 五、询盘维度分析方法论

**数据来源**：通过 `1688-shop-freedom-query-data` 调用
- `customer/inquiry/coreIndex`（询盘核心指标）
- `customer/inquiry/coreIndexTrend`（询盘趋势，可能返回近 30 天全量）
- `customer/inquiry/itemRank`（询盘商品排行）

### 5.1 核心指标解读

| 指标 | 含义 | 分析要点 |
|------|------|----------|
| 有效询盘用户数 | 真实产生询盘行为的买家数 | 反映买家兴趣规模 |
| 有效询盘量 | 询盘总次数 | 与用户数结合看人均询盘 |
| 旺旺询盘 | 通过旺旺发起的询盘 | 客服承接效率窗口 |
| 找工厂 | 找工厂场景询盘 | B 端工厂型业务机会 |
| L会员 | L 会员买家询盘 | 高价值买家意向 |

### 5.2 询盘转化效率判断

- 询盘量高但成交低 → 详情页 / 客服承接 / 报价策略有问题
- 询盘量低但转化高 → 流量获取不足，需扩大询盘入口
- 询盘商品排行与成交商品排行差异大 → 需求与供给错配

### 5.3 注意事项

- `coreIndex` 不含 `device` 参数，可直接用 `dateType` 调用。
- `coreIndexTrend` 即使传 `RECENT_7` 也可能返回 30 天全量数据，按返回全量绘制趋势图即可。
- 返回字段为中文键名，JSON 解析与展示时需注意。

## 六、成交维度分析方法论

**数据来源**：`alibaba.1688.seller.trade.code.index` + `alibaba.1688.get.core.metrics`

### 6.1 成交四维拆解

| 维度 | 指标 | 分析要点 |
|------|------|----------|
| 规模 | 支付金额、支付买家数 | 体量与变化方向 |
| 效率 | 支付转化率、下单到支付转化率 | 流量承接与订单转化 |
| 客单 | 人均支付金额 | 价格带与连带 |
| 质量 | 退款成功金额、退款率 | 履约与描述风险 |

### 6.2 新老客结构

| 结构 | 判断方式 |
|------|----------|
| 新客驱动 | 新支付买家数增长显著，老买家占比低 |
| 老客驱动 | 老买家支付金额占比高，新客增长乏力 |
| 结构健康 | 新老客均保持正向增长，老客贡献稳定 |
| 流失风险 | 老买家支付金额/人数大幅下滑 |

### 6.3 成交与流量交叉验证

- 支付金额增长 + 访客数增长 + 转化率稳定 → **量驱动增长**
- 支付金额增长 + 访客数下降 + 转化率提升 → **效率驱动增长**
- 支付金额下降 + 访客数下降 → **流量问题为主**
- 支付金额下降 + 访客数稳定 + 转化率下降 → **承接问题为主**

## 七、商品维度分析方法论

**数据来源**：`alibaba.1688.seller.import.abnormal.offer`、`alibaba.1688.seller.top.offer`、`alibaba.1688.get.product.status`

### 7.1 异常商品定位（`alibaba.1688.seller.import.abnormal.offer`）

按 `reason` 分三类识别：

| 异常类型 | 含义 | 紧急程度 |
|----------|------|----------|
| 访客下跌 | 偏流量获取问题 | 中 |
| 支付下跌 | 偏转化/成交问题 | 中 |
| 访客下跌 + 支付下跌（双跌） | 流量与转化同时恶化 | **高** |

**筛查优先级**：

1. 影响金额大：`valueMap.payAmt.value.value` 高且 `valueMap.payAmt.cycleCqc.value` 负向大
2. 跌幅大：`cycleCrc` 负向显著（如 < -30%）
3. 多重异常：`reason` 同时包含访客下跌和支付下跌
4. 集中度：是否集中在某类目或店铺核心商品上

输出时聚焦 **TOP 3-5 个最值得处理的异常商品**，每个需说明：异常类型、当前规模、影响幅度、优先处理理由。

### 7.2 增长引擎识别（`alibaba.1688.seller.top.offer`）

必须按分析需要调用多个榜单，不得只调用 `payAmt`：

| 调用 | 识别目标 |
|------|----------|
| `--order_by payAmt` | 成交主力：撑 GMV 的核心商品 |
| `--order_by uv` | 流量主力：流量大但需结合 `payRate` 看转化 |
| `--order_by payNewByrCnt` | 拉新主力：贡献新客的商品 |
| `--order_by itemMultiByrCnt` | 复购主力：承担复购经营的商品 |

**交叉判断**：

| 特征 | 商品类型 | 建议方向 |
|------|----------|----------|
| 高 `payAmt` + 高 `payRate` | 核心成交款 | 重点保护，加大投入 |
| 高 `uv` + 低 `payRate` | 高流量低转化款 | 优化转化（详情/价格/评价） |
| 低 `uv` + 高 `payRate` | 潜力款 | 加流量放量 |
| 高 `payNewByrCnt` | 拉新款 | 投放裂变、首单优惠 |
| 高 `itemMultiByrCnt` + 高 `itemMultiByrPayAmt` | 复购款 | 老客经营、会员激励 |

### 7.3 商品状态检查（`alibaba.1688.get.product.status`）

重点排查：搜索降权、下架、违规、主图/标题异常。当流量或成交突然暴跌时优先调用。

### 7.4 商品维度交叉验证

- 优秀商品列表里是否同时出现在异常商品列表中？**若重叠 → 高优先级风险**（核心商品在恶化）
- 异常商品中是否有店铺 TOP 成交品？**若有 → 必须最高优先级修复**
- TOP 商品是否过于集中决定店铺稳健性

## 八、客户维度分析方法论

**数据来源**：`alibaba.1688.seller.customer.business.province`、`alibaba.1688.seller.customer.detail`

### 8.1 地域分布分析（`alibaba.1688.seller.customer.business.province`）

| 维度 | 判断方式 |
|------|----------|
| 集中度 | TOP 1 / TOP 3 省份 `payBuyerNumRate` 之和 |
| 依赖风险 | TOP 1 省份占比 > 40% → 高度依赖；> 60% → 严重依赖 |
| 覆盖面 | 出现的省份数量、长尾省份分布 |
| 潜力区域 | 占比中等（5-15%）且接近核心区域的省份，可作为下一阶段拓展目标 |

**注意**：某些类目（如本地服务、生鲜）天然区域集中，不应一刀切判定为"风险"。

### 8.2 头部老客稳定性（`alibaba.1688.seller.customer.detail`）

| 维度 | 判断方式 |
|------|----------|
| 依赖度 | TOP N 头部老客 `payAmount` 占店铺总 `payAmt` 的比例 |
| 活跃度 | `lastPayDate` 距今天数，看头部客户是否近期还在买 |
| 流失风险 | 历史 `payAmtAll` 高但本期 `payAmount` = 0 或显著低 → 走弱风险 |
| 客户结构 | `identityName` / `buyerCreditLevel` / `custAreaName` 分布特征 |
| 获客来源 | `fstFromAd = true` 占比高 → 广告获客型；占比低 → 自然沉淀型 |

**结论分类**：

| 结论 | 特征 |
|------|------|
| 基本盘稳 | 头部老客持续活跃，贡献稳定 |
| 依赖风险高 | 少数头部客户占比极高，单客流失即重创 GMV |
| 存在断层风险 | 高累计价值客户近期不活跃，需立即召回 |
| 广告依赖型 | 头部客户多数来自广告，需关注获客成本与生命周期 |

## 九、广告维度分析方法论

**数据来源**：`alibaba.1688.get.ad.channel.detail`、`alibaba.1688.get.industry.benchmark`，必要时通过 `1688-shop-freedom-query-data` 补充数字营销/全站推广细项。

### 9.1 广告贡献判断

| 指标 | 含义 |
|------|------|
| 广告 UV / 广告 PV | 广告带来的流量规模 |
| 广告点击转化率 | 广告流量的承接效率 |
| 广告消耗 / CPC | 投放效率与成本 |
| 广告引导成交金额 | 广告对 GMV 的实际贡献 |

### 9.2 广告效率判断

- 广告 UV 高但成交贡献低 → 投放人群或落地页不匹配
- 广告 UV 低但转化率高 → 可适度加预算放大
- 广告几乎无贡献 → 检查是否未投放、预算耗尽或账户异常

### 9.3 行业对比

通过 `alibaba.1688.get.industry.benchmark` 判断广告投入水平与效率是否处于行业合理区间，避免盲目压缩或放大预算。

## 十、订单履约、合规扣分与买家评价分析方法论

> 三者由聚合工具 `shop_health_check` 提供：`order_risk`、`feedback` 归属**成交维度**，`shop_punish` 归属**风险维度**。数据均为**实时快照**口径，结论中需与近 7/30 天周期数据区分标注。

### 10.1 订单履约分析（`shop_health_check --code order_risk`）

**数据来源**：`shop_health_check --code order_risk`（成交维度）

**关键字段**：

| 字段 | 含义 | 分析要点 |
|------|------|----------|
| `overview` 四类待处理计数 | 待发货/待付款/待收货/待定制付款 | 待处理积压反映履约与承接压力 |
| `timeout_risk.already_timeout_cnt` + `already_timeout_orders` | 已发货超时订单 | 已产生履约违约，最高优先处理 |
| `timeout_risk.about_to_timeout_cnt` + `about_to_timeout_orders` | 即将发货超时订单 | 需立即发货避免超时 |

**判定标准**：

| 结论 | 特征 |
|------|------|
| 履约健康 | 无超时订单，待处理计数处于正常水位 |
| 存在履约风险 | 存在即将超时订单，需及时发货 |
| 履约违约 | 已出现已超时订单，须**高优先级**处理并排查发货链路 |

### 10.2 合规扣分分析（`shop_health_check --code shop_punish`）

**数据来源**：`shop_health_check --code shop_punish`（风险维度）

**关键字段**：

| 字段 | 含义 | 分析要点 |
|------|------|----------|
| `punish_score` / `fake_times` | 违规扣分/假货次数 | 店铺经营红线基线 |
| `punish_warning`（仅 PENDING） | 待处理违规预警 | 存在待处理项即需立即处理 |
| `item_alert` | 商品预警 | 定位到具体违规商品 |
| `legal_alert`（`admin_case`/`law_case`） | 司法/行政预警 | 涉法涉诉，最高优先级 |

**判定标准**：

| 结论 | 特征 |
|------|------|
| 合规健康 | 无违规扣分与待处理预警 |
| 存在合规风险 | 有违规扣分或待处理违规预警，需按 `deal_url` 及时处理 |
| 经营红线告急 | 司法预警出现或假货次数偏高，须**最高优先级**处置 |

### 10.3 买家评价分析（`shop_health_check --code feedback`）

**数据来源**：`shop_health_check --code feedback`（成交维度）

**关键字段**：

| 字段 | 含义 | 分析要点 |
|------|------|----------|
| `rating_overview.distribution` | 1~5 分档分布 | 评分结构 |
| `rating_overview.low_score_ratio` | 低分（≤3 分）占比 | 口碑风险核心指标 |
| `negative_feedback.items` | 负面反馈明细 | 定位差评集中的商品与原因 |
| `positive_cnt` | 正面反馈数 | 口碑正向基础 |

**判定标准**：

| 结论 | 特征 |
|------|------|
| 口碑良好 | 低分占比低、无明显负面反馈集中 |
| 口碑承压 | 低分占比偏高，或负面反馈集中于个别商品 |
| 口碑风险 | 低分占比显著偏高且负面反馈集中，需优先排查商品质量/描述/履约 |

## 十一、交叉验证与综合收敛

### 11.1 必须满足的收敛规则

- 每个结论有数据支撑
- 异常商品与优秀商品必须交叉验证
- 总盘趋势至少用 2 个维度的数据解释
- 行动建议必须按紧急程度（高/中/低）分档

### 11.2 常用交叉验证组合

| 场景 | 交叉验证方式 |
|------|--------------|
| 成交下跌 | 流量趋势 + 转化率 + 商品异常 + 老客活跃度 |
| 流量下跌 | 渠道归因 + 搜索排名 + 商品状态 + 行业大盘 |
| 转化率下降 | 商品详情/价格 + 流量结构 + 询盘承接 + 退款率 |
| 新客乏力 | 流量渠道 + 拉新商品 + 活动效果 + 广告获客 |
| 老客流失 | 头部客户明细 + 复购商品 + 退款/投诉 + 活动触达 |

## 十二、行动建议优先级

所有行动建议只使用**紧急程度**（高/中/低）标注，不再使用 P0/P1/P2 或"价值"标签。

| 紧急程度 | 判定标准 | 示例 |
|----------|----------|------|
| **高** | 核心指标严重恶化、核心商品/头部客户流失、存在立即损失风险 | 核心成交款双跌需立即优化；头部老客本期零采购需召回 |
| **中** | 指标中度异常、结构性问题、可在一周内落地 | 搜索流量占比过高需补充推荐渠道；高流量低转化款优化详情页 |
| **低** | 长期建设、预防性动作、影响滞后 | 建立新客专属权益；拓展潜力区域 |

行动建议撰写格式：
```
建议：① xxx（紧急程度：高）；② xxx（紧急程度：中）；③ xxx（紧急程度：低）。
```
每条建议需标注所属店铺/商品/渠道，确保可执行。

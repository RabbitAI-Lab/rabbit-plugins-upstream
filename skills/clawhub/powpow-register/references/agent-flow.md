# 时序与判断 — powpow-register v2.4.1

本文件是完整时序与判断依据。字段规则见 `registration-flow.md`，支付见 `payment-and-activation.md`。

## 设计前提

本技能只有文档与截图：**不运行任何脚本，不发起任何网络请求，不读写本地文件**。注册、验证码、支付全部在用户自己的浏览器与官方页面完成。

相比旧版由脚本代发验证码、代填表单、代下单，这一版把这三件事全部交回给用户：

| 环节 | 旧版（≤2.2.x） | 本版 |
|---|---|---|
| 填表与密码 | 脚本代填 | 用户在注册页填 |
| 验证码 | 脚本发、脚本提交 | 用户在页面填 |
| 登录态 | 脚本持有会话凭据并生成带凭据的链接 | 用户浏览器自己登录 |
| 支付 | 脚本创建订单、打开收银台 | 用户在订阅页自己付 |
| 助手能看到什么 | 全部账号信息 | 只有用户愿意告诉他的页面现象 |

代价是用户要离开对话两次（注册、付款）。收益是助手不再有任何凭证能力，也不再需要在本机执行任何代码。

## 时序

```
1  助手介绍产品 + 发 1–3 张截图
2  助手给注册页链接，建议用户名/昵称，说明密码由用户自己设
3  用户填表 → 收邮箱验证码 → 回页面填写 → 提交
4  用户刷新页面，告诉助手看到什么
      ├─ 进入首页        → 账号可用，跳 7
      └─ 被挡到订阅页    → 跳 5
5  助手讲两条支付通道与价格，给订阅页链接
6  用户付款 → 刷新页面 → 告诉助手结果；未变化则按排查表处理
7  助手给账号卡片、引导体验、推荐扩展技能
```

助手不保存任何状态。对话中断后重新进入，问用户「现在卡在哪一步，页面上显示什么」即可。

## 判断依据：只看页面现象

| 用户描述的页面现象 | 判断 | 动作 |
|---|---|---|
| 能看到信息流/地图/数字人 | 账号可用 | 收尾，引导发帖 |
| 停在订阅页，提示需要订阅 | 需要订阅 | 讲通道与价格，给订阅页链接 |
| 显示 "You're All Set!" | 订阅已生效 | 收尾 |
| 付款后仍是订阅页 | 回调延迟或未成功 | 等 30 秒再刷；2 分钟未变化查排查表 |
| 登录报 403「请完成订阅以激活账户」 | 账号仍是 pending | 若未付款属正常；已付款则刷新或重新登录 |

**不要凭推测下结论。** 信息不足时，请用户刷新一次并照实描述，或让他截图。

## 常见提问的处理

| 用户问 | 回答要点 |
|---|---|
| 「你帮我设个密码吧」 | 密码必须你自己在页面上填；助手不接收也不保存 |
| 「验证码发我一下」 | 验证码只会发到你自己邮箱，助手拿不到 |
| 「你帮我付了吧」 | 付款必须你本人在官方收银台完成；助手只讲通道与价格 |
| 「这个用户名被占了吗」 | 在注册页输入即可实时校验，不要代查任意用户名 |
| 「我早就注册过了」 | 走登录页 + 忘记密码，不要重复注册 |

# 本地 Vlog 制作工具包：使用指南

ClawHub版 1.0.0

本文件属于技能初始化后的独立工作区。先通过已安装技能的 `scripts/init_workspace.py` 创建此目录，再用 Codex 打开这里，从素材和一段文字描述开始制作。你不必先学习剪辑软件或填写复杂表格。

这是给 Codex 使用的本地制作工作区：技能负责流程和判断，脚本负责盘点、抽帧、转写和渲染。Codex 仍需实际查看素材、写分镜、处理问题并记录检查结果。它不是能自动理解全部素材的一键 AI 服务，也不是剪映、Premiere 或 Resolve 的原生工程。

## 1. 准备环境

需要一台能运行 Codex 本地任务的电脑，以及以下工具：

| 必需项 | 用途 |
|---|---|
| Python 3.10 或更新版本 | 运行工具包内的脚本 |
| Pillow、NumPy | 图片、文字和画面合成 |
| FFmpeg 与 ffprobe | 读取媒体、处理声音和导出视频；FFmpeg 需包含 `libx264` |

GPU 不是必需条件，CPU 可以完成基础制作。素材多、分辨率高或动效复杂时，渲染会更慢，也需要更多磁盘空间。先做短演示，再开始长片。

本包不附带 Python、FFmpeg、语音模型或付费服务。可选功能包括本地语音转写、更多拍摄时间元数据读取、本地录音、在线 AI 配音及内置图像生成；没有这些能力，也可以先用照片、视频原声和字幕制作。具体依赖与当前电脑的验证结果以 `capability_report.md` 和环境检查记录为准。

缺少环境时，可以让 Codex 帮你配置。自行安装可从 [Python 官网](https://www.python.org/)获取 Python，并通过 [FFmpeg 官方下载入口](https://ffmpeg.org/download.html)选择包含 `ffmpeg`、`ffprobe` 与 `libx264` 的构建。在你准备使用的 Python 环境中，安装核心依赖：

```powershell
python -m pip install -r requirements-core.txt
```

下文中的 `python` 都指这个已经安装好依赖的解释器；如果 Codex 建立了独立环境，应使用该环境的 Python。FFmpeg 可以加入系统可查找路径，也可以只在本工作区的 `environment.local.json` 中配置，具体格式见 [工具命令](docs/工具命令.md)。无需使用固定盘符。ClawHub版不带字体；初始化时通过 `--body-font` 和 `--title-font` 提供有权使用的中文TTF/OTF。字体可只保存在工作区，无需系统安装。

### 第一次打开

1. 安装完整技能后，用其初始化工具建立独立工作区；字体需另行配置。不要只复制 `SKILL.md`。
2. 在 Codex 中将这个目录作为工作目录打开。根目录应能看到 `AGENTS.md`、`素材/`、`作品/` 和 `tools/`。
3. 发送下面这段话：

```text
请读取这个工作区的 AGENTS.md 和使用指南.md，使用本地 Vlog 制作技能。
先检查 Python、Pillow、NumPy、FFmpeg、ffprobe、libx264 和字体是否可用，
记录实际结果，说明缺少的依赖，并运行包内合成演示验证基础制作链路。
暂时不要扫描工作区之外的文件，也不要启用付费或外部上传服务。
```

技能位于你从ClawHub安装时选择的目录，不随本工作区重复复制。Codex中可安装到项目的 `.agents/skills/`，或者在请求中明确给出该技能的 `SKILL.md` 完整路径。不要把素材放进技能安装目录，也不要用技能升级覆盖已制作的作品。无需建立Git仓库或替换全局AGENTS.md。

配置好中文字体后，在本工作区先运行 `python tools/make_demo.py --ffmpeg <本机FFmpeg路径>`，生成本地合成演示。示例图片、视频和音频不随ClawHub技能分发；未生成前直接渲染示例会报告输入缺失。

愿意自行使用终端时，在工具包根目录运行以下两条命令即可检查环境和查看主题；也可以完全交给 Codex 执行。完整参数见 [工具命令](docs/工具命令.md)。

```powershell
python tools/workspace.py doctor
python tools/workspace.py topics
```

## 2. 放入素材，告诉 Codex 这次想讲什么

在 `素材/` 下创建主题文件夹，把本次允许使用的照片和视频放进去。第一层文件夹名称就是主题；同一主题内可以继续按日期或设备分文件夹。

```text
素材/
  周末散步/
    照片和视频……
  一次聚会/
    照片和视频……
```

以上只是示例，不代表你已经发生过这些经历。可以让一条作品引用多个主题，不必再把原片复制到 `作品/`。处理期间原片只读，裁剪、抽帧和转码生成新文件。

然后提供一段普通文字即可，例如：

```text
用“周末散步”主题，做一条轻松自然的竖屏 Vlog，重点讲从出发到回家的过程。
我希望保留有意思的现场声，照片可穿插，但不为了凑时长重复画面。
请先实际查看照片、抽帧查看视频，恢复有依据的拍摄顺序，再给我分镜。
不确定的事情标出来；这次先停在分镜，不渲染粗剪。
```

如果作品会涉及他人，顺便说明谁是主角、哪些人或信息应避开。不要让 Codex 根据服装以外的猜测认定身份，也不要让它从模糊画面补造事件。

你的描述会保存在该作品的 `brief.md`，补充事实和隐私要求保存在 `notes.md`。以后继续这条作品时，直接说作品名和想改的内容即可。

## 3. 按作品推进，确认重要版本

流程是：素材与描述 → 盘点及实际审阅 → 拍摄时间线与分镜 → 粗剪确认 → 精剪与检查 → 成片、封面、短文案 → 确认锁定。

| 阶段 | Codex 应交付什么 | 你主要看什么 |
|---|---|---|
| 盘点与实际审阅 | 素材清单、看图或抽帧记录、时间疑点 | 素材范围、身份、先后顺序是否正确 |
| 分镜 | 每镜素材、原片区间、字幕、声音、用途 | 故事是否准确，重点是否合适 |
| 粗剪 | 带版本号的审阅视频 | 选材、顺序、时长、节奏、旁白和主要文字风格 |
| 精剪与交付 | 成片、封面、文案及检查记录 | 构图、字幕、声音、动效、隐私和细节 |
| 锁定 | 对应版本的确认记录 | 是否可以停止修改 |

没有强制的“先看一条固定时长风格样片”环节。你只要求分镜时就停在分镜；没有这个限制且已获制作授权时，Codex 可以在提供可审阅分镜后继续粗剪。正式精剪以你确认的粗剪版本为基础。

确认时尽量说清作品和版本，例如：

```text
我确认“周末散步”粗剪 v001 的故事、顺序和时长。
继续精剪，逐镜检查构图与颜色，按需要防抖；保留我已接受的声音。
完成后给我成片、封面、简短发布文案和实际检查记录。
```

文件生成成功不等于检查完成。抽帧不能证明整段运动流畅，自动转写不能证明听过声音，解码正常也不能证明字幕和故事正确。最终要分别记录完整连续观看、实际听音和程序检查；受当前能力限制没做到的项目，应如实列出。你在自己的播放器里看完、听完后，也可以把问题反馈给 Codex。

## 4. 三类视觉起点与声音设置

本包提供三类可调整的视觉起点，颜色、字号、时机和位置都应随题材调整：

- **照片 01「斜落轻放」**：照片斜入后轻轻落位，使用暖白纸边和柔和投影。背景保持清晰；全屏照片落位后按构图铺满。
- **重点艺术字 B「立体贴纸」**：关键词错拍进入，轻回弹和短暂轻晃后稳定。普通字幕保持稳定，重点字避开脸与关键动作。
- **独立文字页 C「运动笔刷」**：深色底、笔刷字和明确字号层级。当前默认是静态阅读页，不把“运动笔刷”理解为页内持续动画。

约 1 秒一张照片只是快段落起点，重要内容可以延长。重复素材不会自动触发“递进蒙太奇”；只有你对当前作品明确要求这种叙事手法时才使用。效果的具体能力与参数见技能的 `references/visual-presets.md` 和 [技术架构](技术架构.md)。文字页的正式设计需要另行制作成静态图片，渲染器不会自动生成笔刷纹理或理解文案。

**第一次做音乐时，需要建立你自己的听感基准。** 本包没有附带原制作者的音频、音乐分轨或私人配音，因此不能复刻某个历史作品的原始混音。先准备可使用的音乐，确认旁白和现场声清楚、BGM 合适，再记录你接受的版本。

以后说“BGM 减 30%”，应先明确相对于哪条音乐分轨；含义是在该分轨上乘 `0.70`，只改 BGM，不把整片声音都降低。已经接受并处理过的音轨不会在每次修订时重复降低。纯视觉修改优先沿用已接受的声音。渲染器按明确参数混音，不会自动判断音乐何时避让旁白；这些安排需要 Codex 编排并通过听音确认。

## 5. 找到结果与继续修改

每条作品在 `作品/` 下有独立目录，保留描述、分镜、时间线、审阅视频、正式导出、状态和确认记录。共享素材索引与抽帧缓存位于 `工作数据/`；公共样式和字体位于 `公共资源/`。

继续修改时，使用具体版本和时间点：

```text
继续“周末散步”v002：只把 00:18 附近的照片替换为我指定的那张，
保留后续章节、字幕和声音的时间位置。先检查替换是否影响时长与同步，
输出新版本，保留旧版，不覆盖原片。
```

完成后可以说：

```text
我确认“周末散步”成片 v003 和封面 v002 完成，请记录并锁定。
没有我的新要求，不再修改，也不发布或删除素材。
```

成片和封面不会自动发布。确认锁定也不等于授权清理原片；需要清理时另行说明范围，先检查其他作品是否还在引用。

## 6. 常见问题

| 情况 | 处理方法 |
|---|---|
| Codex 没有自动使用技能 | 明确给出已安装技能的 `SKILL.md` 路径，再读取本工作区 `AGENTS.md` |
| 找不到 Python 或 FFmpeg | 让 Codex 运行环境检查，使用系统安装或本机配置中的有效路径；不要套用别人的绝对路径 |
| 中文显示成方框 | 检查自行提供的中文字体是否配置完整，以及当前渲染是否实际选用了该字体 |
| 语音转写不可用 | 本地 ASR 是可选项；先继续画面审阅，另行安装依赖及模型，或手动提供文字 |
| 视频能抽帧但播放有问题 | 保留原片，记录错误；特殊格式、HDR、可变帧率、全景素材可能需要单独预处理 |
| 移动目录后找不到文件 | 让 Codex 检查配置、外部素材引用和作品时间线，更新本机路径；移动后重新验证 |
| 已经有导出文件，却没有审阅记录 | 按未审阅处理，实际打开检查，不补写不存在的通过记录 |

需要更多可复制指令时，见 [提示词示例](docs/提示词示例.md)。想了解有哪些能力由脚本完成、哪些仍需 Codex 判断，见 [技术架构](技术架构.md)。

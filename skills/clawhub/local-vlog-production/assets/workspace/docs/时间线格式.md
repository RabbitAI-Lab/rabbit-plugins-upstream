# JSON 时间线与通用渲染器

`tools/render_timeline.py` 是可单独使用的 CPU 渲染入口，依赖 Python、Pillow、numpy、FFmpeg 和 ffprobe。媒体路径、字体路径、时间线和输出路径都相对 `--workspace-root`；不写入原件、不上传媒体，不依赖原作者的项目脚本。命令中的程序可在系统 PATH，也可用 `--ffmpeg` / `--ffprobe` 指定本机位置。

```powershell
python tools/render_timeline.py --workspace-root . --timeline examples/演示时间线.json --validate-only
python tools/render_timeline.py --workspace-root . --timeline examples/演示时间线.json --output 作品/演示/05_exports/demo_v001.mp4 --preset veryfast
```

输出文件及同名 `.manifest.json` 都必须不存在。需要修订时选择新版本名。输出不能位于 `素材/` 或配置的原素材目录，也不能覆盖输入。媒体和目录中的符号链接、目录联接、重解析点会被拒绝；不允许绝对媒体路径或 `..`。输入视频时长不足时失败，不用最后一帧补足。

程序依次读取根目录 `workspace_config.json`、可选的 `environment.local.json`，CLI 覆盖两者。程序位置优先级：CLI > environment.local.json 的 executables（兼容同名顶层键）> workspace_config.json.executables > PATH。`environment.local.json` 是接收者本机配置，不应分享。画布默认值读配置的 `defaults.width/height/fps/audio_sample_rate`，缺省 1080×1920、30fps、48000Hz。帧率目前只接受 1–60 的整数，宽高须为 64–4096 的偶数。

`--validate-only` 检查 JSON、路径、字体、图片解码、视频/音轨探测和时长，不产生文件，也不声称完成渲染或完整解码。正常导出为 H.264/yuv420p、SDR Rec.709；有音频时输出 AAC，没有请求音频时为无音轨 MP4。`--crf` 默认为 20，`--preset` 默认为 medium；演示可用 veryfast。程序不需要硬件编码。

## 顶层

```json
{
  "schema_version": 1,
  "name": "作品名称",
  "canvas": {"width": 1080, "height": 1920, "fps": 30, "background": "#17221f"},
  "clips": [],
  "overlays": [],
  "audio": {},
  "notes": "可选说明"
}
```

`clips` 必须非空，按数组顺序无重叠拼接。`overlays` 按数组顺序由下到上叠加，可跨片段；时间为整条时间线的秒数，区间为 `[start, start+duration)`。未知字段会报错，避免拼错字段后静默忽略。片段时长就近量化为整数帧，实际帧数和警告写入 manifest；制作时最好直接使用整帧时长。

## 基础片段 clips

| 字段 | 含义 |
|---|---|
| type | `image`、`video` 或 `color` |
| source | 图片/视频路径；color 不使用 |
| duration | 正数，显示时长（秒） |
| source_in | 视频原片入点（秒），默认 0；非视频不能使用非零值 |
| fit | `cover` 等比铺满并裁边，或 `contain` 等比完整显示并补背景色；默认 cover |
| crop_center | cover 裁切重心 `[x,y]`，各为 0–1；默认 `[0.5,0.5]`，按旋转校正后的画面理解 |
| color | color 片段颜色；默认 canvas.background |
| audio | 只能 false；原声请在 audio.tracks 中显式安排 |
| id / note | 可选记录字段 |

图片读取 EXIF 朝向；视频由 FFmpeg 自动校正旋转信息并归一化像素宽高比。普通照片和视频不拉伸。裁切重心是裁切余量上的相对位置，例如 `[0,0.5]` 优先保留左侧。图片不自动调色、抠图或隐私遮挡，应先准备经过审阅的素材。

颜色处理只面向 SDR 输入。视频探测到 PQ、HLG、Dolby Vision、HDR 元数据或 Rec.2020/P3 宽色域时明确拒绝，需要先使用经过审阅的转换流程得到 SDR Rec.709 中间片。不能把改标签当作 HDR 转换。颜色标签缺失只能作为 SDR 假设并产生警告，仍需看图核实。

## 照片 01 覆盖层

```json
{
  "type": "photo_card",
  "source": "素材/某主题/照片.jpg",
  "start": 1.0,
  "duration": 2.5,
  "entry": 0.65,
  "center": [0.5, 0.49],
  "max_size": [0.82, 0.53],
  "angle": -1.2,
  "fade_out": 0.15,
  "motion_samples": 3
}
```

`photo_card` 保留照片比例，暖白纸边、软投影，由右上斜落轻放。`center` 是相对画布的落点，`max_size` 是含纸边的最大宽高比例；都以画布坐标而非原照片坐标表示。默认落位后稳定，仅尾部按 `fade_out` 淡出。只柔化投影，不虚化、压暗或停止背景视频。`motion_samples` 可为 1 或 3，默认 3，对快速运动做自适应短快门采样。

改为 `"type":"full_photo"` 可在轻放后全屏扩展：`entry` 默认 0.65 秒，`expand` 默认 0.28 秒，之后转正铺满，纸边离开屏幕。`crop_center` 决定最终 cover 裁切，不拉伸；`max_size` 对全屏模式不生效。全屏模式先采用最终的裁切图作为卡片，避免结束时换裁切。底层视频仍按时间推进，只是被全屏图遮住。覆盖层结束会直接露出当时的底层片段，因此应把后续切点和覆盖层结束对齐，或让底层是同一照片。

照片的 `duration` 必须比 entry（全屏另加 expand）更长，留出稳定阅读时间。`paper_color` 可改纸边色，默认 `#F6F4EE`。`angle` 默认 −1.2°，允许 −30 到 30°。照片卡的 fade_out 默认 0.15 秒；全屏模式采用直接切换，`fade_out` 不应用于其稳定全屏阶段。此版本没有自动退场位移或任意自定义三维路径。

## 重点艺术字 B 与普通字幕

```json
{
  "type": "sticker_title",
  "text": "重点词组",
  "font": "公共资源/字体/用户字体/BodyFont.ttf",
  "start": 1.0,
  "duration": 2.5,
  "font_size": 86,
  "center": [0.5, 0.22],
  "max_width": 0.90,
  "angle": -2,
  "direction": -1,
  "color": "#214C41"
}
```

`sticker_title` 使用多层描边、偏移厚度、短递入和不超过 7.5% 的轻回弹；约 0.9 秒后完全稳定。多个词组拆成多个覆盖层，用 `start` 相隔约 0.12 秒形成错拍递入。`direction` 为 −1 或 1，决定入场方向。`angle` 是稳定后的倾斜角。`color/outline/shadow` 可按题材调整；不自动避脸，需要审阅位置。

`subtitle` 使用相同的 text/font/start/duration/center/max_width 字段，始终稳定，不继承角度或回弹。默认 center 为 `[0.5,0.88]`。文字通过 Pillow 绘制，无 libass/字幕路径转义依赖。`font_size` 是当前画布的实际像素；缺省会按画布宽度缩放。超过 max_width 的整组文字会等比缩小，手动 `\n` 分行，不自动进行语义断句。`max_width` 是画布宽度比例，默认 0.90。

字体文件必须存在且授权允许使用；本工具不伪造缺字检查结果。成片须检查汉字、标点、长句可读性及是否挡主体。

## 独立文字页 C

把已设计好的单页 PNG/JPEG 放入普通 `image` 片段即可。渲染器不生成 AI 笔刷画面，也不把普通字体加粗冒充已实现的 AI 运动笔刷设计。示例 `demo_card.png` 是程序生成的静态排版测试页，只用于验证时间线，不是私人作品里的 C 设计。静态文字页没有内部动画；可在其上叠加照片 01 入场。需要新的设计图时，单独使用图像生成或设计工作流，再实际审阅后引用。

## 已确认主音轨直拷

```json
"audio": {
  "master_audio": {
    "source": "作品/新作品/03_edit/accepted_master.m4a",
    "source_in": 0,
    "copy_aac": true
  }
}
```

默认 copy_aac=true：要求 AAC、source_in=0、音频流 start_time=0（容差 0.001 秒）、音轨与时间线总长差不超过 0.08 秒（容纳编码包边界）。程序不裁切、调音、补静音或重编码已接受音轨；复用后用 FFmpeg 对编码数据计算 SHA-256，并逐包比对数据 hash、PTS、DTS、duration、大小与 side data，任何差异就失败。MP4 容器自身可能变化，验证对象为 AAC 编码数据与逐包播放时点。由于 AAC 包边界，总容器时长可能比视频略长，视频帧数保持准确。原主音轨带非零时间偏移时，须先明确所需位置并预处理，不能用直拷掩盖时间位移。

若明确需要重编码或裁切，设置 copy_aac=false，支持 source_in，必须有足够音频覆盖全片，音量为 1.0。`master_audio` 与 `tracks` 互斥，不能悄悄叠加新配乐。

## 原声、旁白与 BGM 分轨

```json
"audio": {
  "sample_rate": 48000,
  "bitrate": "192k",
  "tracks": [
    {"role":"original", "source":"素材/某主题/视频.mp4", "source_in":4, "timeline_in":0, "duration":3, "volume":1.0},
    {"role":"voiceover", "source":"作品/新作品/03_edit/旁白.wav", "source_in":0, "timeline_in":2, "duration":5, "volume":1.0},
    {"role":"bgm", "source":"公共资源/音乐/音乐.wav", "source_in":12, "timeline_in":0, "duration":8, "volume":0.18, "fade_in":0.3, "fade_out":0.5}
  ]
}
```

每条轨道的 `duration` 和 `volume` 必须显式提供；source_in、timeline_in 默认 0。分轨 source_in 从音频流解码后的首个采样点计时，输入流自身的非零时间偏移不会自动带入；需要保留该偏移时请显式计入 timeline_in。volume 为线性倍率，0–16，1 为原电平；0.70 是仅在明确要求时执行的一次乘数，程序不会根据 bgm 标签自动降低 30%。role 只用于记录，不决定音量。`fade_in/fade_out` 是该片段内的淡入/淡出秒数。音频被重采样为设定采样率、双声道，裁切、淡入淡出、延迟和全长补齐均按采样点执行，空白处补静音，最后编码 AAC。非整数采样点的时长就近取整。

混音禁用 amix 自动归一化，没有自动 ducking、响度匹配或限制器。多个大音量分轨叠加可能削波；请先提供有余量的轨道电平，并实际听音和测量后修订。音乐前奏由 source_in 显式去除，不自动套固定秒数。无轨道不生成假旁白或默认音乐。

## 导出证据与限制

manifest 记录时间线/结果 SHA-256、相对来源路径、实际画布/帧数/片长、音轨模式、版本和程序检查。导出后执行一次完整解码与帧数核验；它们不替代审片。`continuous_playback`、`listening`、`sampled_frames_visually_reviewed` 均由程序保留为 false，只有真实审阅者在另一个证据记录里注明版本、区间和结果后，才能确认这些项目。

异常时关闭解码与编码管道，删除本次临时文件；发布输出采用排他创建，既有结果不会被覆盖。用户取消可能留下系统中断时尚未清理的临时目录，核对后可清理本次 `.render-*` 缓存，但不能以导出完成作为删除原件的授权。

此入口不是完整非线性剪辑器：没有镜头间交叉叠化、多机位、变速、智能选镜、自动防抖/调色、ASR/TTS、联网下载、AI 图像生成、主观审片或自动发布。需要这些步骤时先生成可审阅的中间素材或扩展工程，再由显式时间线引用。

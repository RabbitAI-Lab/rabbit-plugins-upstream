# 系统规划与管理师专业术语速查

> 按知识领域分类，供生成框架时嵌入分论点与写作提示。术语以《系统规划与管理师教程（第2版）》与 ITIL 4 / GB/T 24405 体系为准。

## 一、IT 服务规划与设计

| 术语 | 说明 |
|------|------|
| 服务目录管理 | 定义并维护可供客户使用的服务列表 |
| 服务级别协议（SLA） | 服务提供方与客户约定的服务质量承诺 |
| 服务需求识别 | 识别业务与干系人对 IT 服务的需求 |
| 服务方案设计 | 设计服务架构、流程、组织与技术方案 |
| 容量管理 | 确保服务能力满足当前与未来业务需求 |
| 可用性管理 | 保障服务在约定时段内可用 |
| 连续性管理 | 灾难恢复与业务连续性（RTO / RPO） |
| 信息安全管理 | 保密性、完整性、可用性（CIA）保障 |

## 二、IT 服务运营管理

| 术语 | 说明 |
|------|------|
| 事件管理 | 尽快恢复服务的正常运行 |
| 问题管理 | 查明事件根因而防止复发 |
| 变更管理 | 以受控方式处理变更（标准 / 常规 / 紧急） |
| 发布与部署管理 | 将变更交付到生产环境 |
| 配置管理 | 维护配置项（CI）及配置管理数据库（CMDB） |
| 服务台 | 用户与服务提供方的单一联系点 |
| 值班管理 | 轮班值守与应急响应 |
| 知识管理 | 沉淀运维知识，提升处理效率 |

## 三、IT 服务持续改进

| 术语 | 说明 |
|------|------|
| 服务测量 | 通过指标量化服务质量与成效 |
| 服务回顾 | 定期与客户 / 干系人回顾服务表现 |
| 七步改进法 | ITIL 持续改进的标准步骤 |
| PDCA 循环 | 计划 - 实施 - 检查 - 改进 |
| 成熟度模型 | 评估服务管理能力等级（如 CMMI） |
| 满意度调查 | 收集客户对服务的满意程度 |

## 四、IT 服务营销

| 术语 | 说明 |
|------|------|
| 服务产品化 | 将能力封装为可销售的服务产品 |
| 服务定价 | 成本 + 价值导向的定价策略 |
| 干系人管理 | 识别并管理客户与内部干系人期望 |
| 服务级别管理 | 设计、协商、监控 SLA |
| 客户期望管理 | 管理并引导客户合理预期 |

## 五、服务团队建设与管理

| 术语 | 说明 |
|------|------|
| RACI 模型 | 负责 /  accountable / 咨询 / 知会 |
| 塔克曼阶段 | 形成 - 震荡 - 规范 - 成熟 - 解散 |
| 激励理论 | 马斯洛需求层次、赫茨伯格双因素 |
| 培训与赋能 | 提升团队服务交付能力 |
| 绩效考核 | 基于服务指标的团队评价 |

## 六、服务风险管理与质量管理

| 术语 | 说明 |
|------|------|
| 风险登记册 | 记录风险及其应对措施 |
| 定性 / 定量风险分析 | 评估风险概率与影响 |
| 风险应对策略 | 规避 / 转移 / 减轻 / 接受 |
| 全面质量管理（TQM） | 全员、全过程、全企业的质量管理 |
| 六西格玛 | 以数据驱动的质量改进方法 |
| 服务质量差距模型 | 识别服务期望与感知的差距 |

## 七、信息系统运维管理

| 术语 | 说明 |
|------|------|
| 运维服务体系 | 人员 / 过程 / 技术 / 资源四要素 |
| 集中监控 | 统一采集与告警 |
| 自动化运维 | 脚本化、平台化减少人工干预 |
| 应急预案 | 突发事件的处置预案与演练 |
| 服务级别回顾 | 周期性 SLA 履约评估 |

## 常用连接与过渡词

- 开头：在项目实施过程中，我深刻体会到…… / 根据项目实际需求，我们首先……
- 展开：具体而言，我主要从以下几个方面入手…… / 针对这一问题，我采用了……
- 过渡：首先……其次……最后…… / 一方面……另一方面……
- 收尾：实践证明，上述措施取得了良好效果…… / 通过本次实践，我深刻认识到……

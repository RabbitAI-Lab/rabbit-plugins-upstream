# 系统规划与管理师论文框架模板（四段式）

> 生成框架时严格按此结构输出 Markdown，每段给出字数建议与写作 / 术语提示。总字数目标约 2500 字（正文 ≥ 1500 字）。

```markdown
# [论文题目]

## 一、摘要（约 300 字）
[背景引入(1-2句) + 项目简介(1-2句) + 主要工作与成果(2-3句) + 效果总结(1-2句)]
> 💡 写作提示：用专业术语开头，包含题目核心关键词，结尾明确成效。
> 📖 术语提示：ITIL 4 / SLA / 服务级别 / 持续改进

## 二、项目概述（约 400-500 字）
[项目背景(行业现状/面临问题) + 项目目标 + 项目概况(名称/规模/周期/团队/角色) + 技术架构概述]
> 💡 写作提示：体现项目真实性与复杂度，为正文铺垫。
> 📖 术语提示：IT 服务管理体系 / 运维四要素（人员/过程/技术/资源）

## 三、正文核心论述（约 1500 字，2-4 个分论点）

### 3.1 [分论点一标题]（约 300-400 字）
[理论依据 + 实践做法 + 实施效果]
> 💡 写作提示：描述怎么规划 / 设计，结合项目实际。
> 📖 术语提示：[按主题填充]

### 3.2 [分论点二标题]（约 500-600 字）
[理论依据 + 实践做法 + 实施效果]
> 💡 写作提示：描述实施过程、遇到的问题及解决方案。
> 📖 术语提示：[按主题填充]

### 3.3 [分论点三标题]（约 300-400 字）
[理论依据 + 实践做法 + 实施效果]
> 💡 写作提示：描述实施后的成效、经验教训。
> 📖 术语提示：[按主题填充]

### 3.4 [补充分论点，如需要]（约 300-400 字）
[问题应对 / 风险控制 / 持续改进等]
> 💡 写作提示：补充论证深度。

## 四、结尾总结（约 200-300 字）
[回顾项目整体情况 + 总结核心经验(2-3点) + 升华理论价值或展望未来]
> 💡 写作提示：与题目呼应，体现专业思考，避免空洞口号。

---

## 字数分配总览

| 章节 | 推荐字数 | 占比 |
|------|---------|------|
| 摘要 | 约 300 字 | 12% |
| 项目概述 | 400-500 字 | 18% |
| 正文核心论述 | 约 1500 字 | 65% |
| 结尾总结 | 200-300 字 | 10% |
| 合计 | 约 2500 字 | 100% |

> ⚠️ 本框架仅供参考，不构成标准答案，亦不替代本人写作。
```

## 分论点设置原则

1. 每个分论点对应题目要求的一个方面（从题目拆解出的论述维度）。
2. 分论点之间逻辑递进（规划 → 实施 → 成效 → 改进）。
3. 每个分论点包含：**理论依据 + 实践做法 + 实施效果** 三要素。
4. 紧扣系统规划与管理师知识领域（服务规划 / 运营 / 改进 / 营销 / 团队 / 风险 / 质量 / 运维）。

# 项目背景信息收集模板（系统规划与管理师）

> 系统规划与管理师论文以 **IT 服务 / 运维类项目**为背景最佳。收集真实、完整的背景信息是论文写作基础，所有信息必须真实，不得编造。

## 必填信息（缺一不可）

| 字段 | 说明 | 示例 |
|------|------|------|
| 项目名称 | 完整的项目正式名称 | XX省移动公司 IT 服务运维管理项目 |
| 项目规模 | 服务范围 / 用户数 / 系统数 | 覆盖 12 个业务系统，终端用户 8000+ |
| 建设 / 服务周期 | 开始至结束时间（精确到月） | 2022 年 3 月 - 2023 年 2 月（12 个月） |
| 担任角色 | 项目中的具体职务 | 项目经理 / 运维经理 / 服务经理 |
| 核心业务目标 | 要解决的核心问题 | 提升一线故障响应效率，保障核心系统可用性 |

## 选填信息

| 字段 | 说明 | 示例 |
|------|------|------|
| 团队规模 | 核心团队人数 | 核心团队 15 人 |
| 技术栈 | 主要技术选型 | ITIL 4 框架、CMDB、Zabbix、Prometheus |
| 项目成果 | 已取得的主要成果 | 故障平均恢复时间（MTTR）由 4h 降至 1.5h |
| 行业背景 | 所属行业 | 通信 / 金融 / 政务 / 制造等 |

## 快速提供格式

```
项目：[项目全称]
规模：[服务范围 / 用户数 / 系统数]
周期：[YYYY.MM - YYYY.MM]
角色：[具体职务]
目标：[核心业务目标]
技术：[主要技术选型，可选]
团队：[团队规模，可选]
成果：[主要成果，可选]
```

## 案例示范（以下为匿名化示例，非真实项目，请替换为自身真实参与的项目）

```
项目：某商业银行数据中心 IT 运维服务管理项目
规模：托管 26 套核心业务系统，服务网点 320 个
周期：2021 年 6 月 - 2023 年 3 月（共 21 个月）
角色：运维服务经理
目标：建立标准化运维流程，提升事件处理效率与系统可用性
技术：ITIL 4、CMDB、Zabbix 监控、自动化运维平台
团队：核心团队 18 人
成果：重大故障同比下降 40%，SLA 达成率 99.5%
```

## 常见问题

- **Q：参与的是保密项目怎么办？** A：可模糊化处理（如"某大型国有银行数据中心运维项目"），但核心信息须真实。
- **Q：我是乙方人员如何描述？** A：明确乙方角色与服务范围，如"作为乙方服务经理，负责……"。
- **Q：项目金额记不清？** A：IT 服务类项目可用"服务规模 / 用户数"替代金额，避免虚构不合理数字。
- **Q：角色与实际不符？** A：以实际担任角色为准，如实描述实际工作内容。
- **Q：没有大型项目经验？** A：可使用中小型真实项目，重点是体现过程的真实性与方法论的正确运用。

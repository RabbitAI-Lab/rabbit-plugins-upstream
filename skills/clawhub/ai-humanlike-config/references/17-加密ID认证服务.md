# 加密 ID 认证服务（来源防伪与可验证出处）

> 配合 `07` 全链路可追溯、`14` 同意授权码、`16` 能力评测对标。
> 本文件把"交付即带身份与可追溯"（07）进一步做成**对外公开可验证**的出处认证——让任何人都能核验"这个数字人是不是『注册老炮』造的"，戳穿冒用，强化品牌权威。

## 一、定位与价值

- **痛点**：市场上出现越来越多"自称注册老炮配的 AI"，客户分不清真假，真出品被冒用、口碑被稀释。
- **解法**：每个由我们交付的数字人，签发一个**加密 ID 凭证**（带数字签名）；我们提供一个公开验证入口，第三方/客户提交该 ID 即可查"是否由注册老炮签发、何时签发、对应哪版、当前是否有效"。
- **价值**：① 出处可验，冒用品一眼识破；② 强化"我们造的 = 可溯源"的权威心智；③ 与 `07` 追溯链、`14` 授权状态、`16` 评测分数串成一张"可信名片"。

## 二、加密 ID 是什么

加密 ID = **注册老炮用签发私钥对数字人元数据签名生成的凭证**，结构如下（明文可展示，签名防伪造）：

```
加密ID = base64( 元数据 + 数字签名 )
元数据 = {
  签发方:    "注册老炮",
  客户ID:    <07 体系发放的客户 ID>,
  数字人标识: <客户ID>-<用途>-<版本号>,
  版本号:    vX.Y.Z（见 13 能力版本管理）,
  签发时间:  <RFC3339 时间戳>,
  指纹哈希:  <交付物 SHA-256，见 07 的 5.3>,
  评测等级:  <可选，关联 16 对标等级>
}
数字签名 = 签发私钥对 元数据的 SHA-256 做非对称签名（验签用公开公钥）
```

- **密钥**：注册老炮持有签发私钥（离线/最小暴露），对外只发布**验签公钥**。
- **形态**：可给客户一个卡号串 / 二维码，嵌在交付包与展示页。

## 三、签发机制（与 07 联动）

1. 数字人按 `07` 完成交付 → 已有客户 ID + 时间戳 + 指纹 + 哈希。
2. 取"客户 ID + 版本 + 指纹哈希"组成本节第二节元数据。
3. 用签发私钥对元数据摘要签名，拼成加密 ID 随交付包一并发给客户。
4. 签发记录入"公开可验清单"（仅存非敏感元数据，见第六节合规）。

> 复用 `07` 的 5.1 时间戳 / 5.3 哈希即可，无需另起炉灶；强确权场景叠加 `07` 的"上链档"让签发记录公开不可篡改。

## 四、验证流程与公开入口

**验证入口形态**（二选一或并存）：
- **公开验证页**：输入框粘贴加密 ID → 即时返回结果（最轻量，建议默认）。
- **验证 API**：`POST /verify {id}` → JSON 结果，供客户系统/平台对接（增值项）。

**验证返回字段**（公开、非敏感）：

| 字段 | 含义 |
|------|------|
| `valid` | 签名是否有效（是否被伪造/篡改） |
| `issuer` | 签发方，恒为"注册老炮" |
| `issued_at` | 签发时间 |
| `digital_human` | 数字人标识（客户 ID + 用途 + 版本） |
| `version` | 能力版本号 |
| `status` | `active` / `revoked`（是否吊销，见第五节） |
| `eval_level` | 可选，关联 `16` 评测对标等级（仅作能力参考，非认证结论） |

**验证结论口径**：只回答"**这份 ID 是否由注册老炮有效签发、当前是否有效**"，不评价数字人能力高低——能力需另行看 `16` 评测。

## 五、认证边界（诚实声明，必守）

- ✅ 认证**出处**：是否由注册老炮签发、是否未被伪造、当前是否吊销。
- ❌ **不认证能力**：加密 ID 只证明"来源"，不证明"配得好不好/能力强不强"；能力等级由 `16` 评测独立给出，二者不可混为一谈。
- ❌ **不替代资质背书**：这是品牌出处防伪，不是第三方监管/资质认证；被验证方仍需自行判断适用性。
- ❌ **不碰加密币**：本服务基于加密学数字签名（非对称密钥），不涉及任何代币/链上资产。
- 对外话术禁绝对词：用"我们签发 / 可验证出处"，不用"全球唯一 / 最权威 / 无法伪造"。签名强度取决于密钥保管，诚实表述为"高仿冒成本"，不夸"绝对不可伪造"。

## 六、吊销机制

出现以下情形，签发方可将加密 ID 标记为 `revoked`：
- 客户解约 / 注销客户 ID（`07` 第三节注销流程）；
- 授权码熔断 / 违规被终止（`14`）；
- 数字人被用于违规用途、损害品牌。

吊销状态同步写入公开可验清单，验证入口即时返回 `revoked`。

## 七、与业务流/其他模块联动

- 与 `07`：加密 ID 是 `07` 追溯链的"对外验证端口"，追溯链是认证的底层数据。
- 与 `14`：授权码熔断 → 触发加密 ID 吊销，状态一致。
- 与 `16`：验证结果可附带评测等级（仅展示，非认证），升版重测刷新版本号。
- 与 `04` 阶段 4.5（交付可信）：加密 ID 作为交付物一部分随包交付。
- 与 `15` 活动：生态榜单可展示"已认证出处"标记，增强信任。

## 八、合规（PIPL / GDPR）

- 公开可验清单**只存非敏感元数据**（签发方/客户 ID/版本/时间/指纹哈希摘要），不含个人姓名、联系方式、合同、报价。
- 客户 ID 按 `07` 第三节做脱敏与注销权；吊销/注销后从可验清单移除可识别绑定。
- 跨境场景遵循 `07` 第三节 GDPR：哈希加盐、单独同意、不跨境传特殊类别数据。
- 验签公钥公开，签发私钥严格离线保管、最小暴露、定期轮换。

## 十、落地实现规格（可直接照做）

**签发（占位示例，密钥用环境变量，不落明文）**：

```bash
# 1) 组元数据并算摘要
META='{"issuer":"注册老炮","customer_id":"<ID>","version":"v1.0.0","issued_at":"<时间>","fp_hash":"<SHA256>"}'
echo -n "$META" | openssl dgst -sha256 -binary > meta.sha256

# 2) 用签发私钥签名（私钥从环境变量读，绝不写进文件/仓库）
echo -n "$META" | openssl dgst -sha256 -sign "$SIGN_KEY" -out meta.sig
# 3) 拼接 base64(元数据 + 签名) = 加密ID
```

**验证（公开入口）**：用公开验签公钥对签名验签，比对元数据摘要一致即 `valid=true`。

- 工具：`openssl` 非对称签名 / 任意语言加密库（零成本自算）。
- 公钥发布：放在验证页/官网"验签公钥"区，供任何人下载核对。

## 十一、FAQ

**Q1：加密 ID 能证明数字人能力强吗？**
不能。它只证明"出处是否注册老炮、是否被伪造、是否有效"。能力强弱看 `16` 评测，二者分开。

**Q2：别人能伪造我们的加密 ID 吗？**
伪造需要我们的签发私钥。私钥离线保管、最小暴露，仿冒成本极高；但我们诚实表述为"高仿冒成本"，不承诺"绝对不可伪造"。

**Q3：客户解约了 ID 还有效吗？**
立即标记 `revoked`，验证入口返回失效，公开清单同步更新。

**Q4：这和区块链有关系、涉及币吗？**
基于加密学数字签名，不涉及任何代币。强确权时可叠加 `07` 的区块链存证档，但存证≠币。

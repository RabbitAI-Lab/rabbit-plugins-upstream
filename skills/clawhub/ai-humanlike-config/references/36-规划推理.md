# 36 · 规划推理（Planning & System 2，v2.0 认知内核②）

> **定位**：对标 System 2 慢思考、Tree-of-Thoughts（Yao et al., 2023）、MCTS 规划搜索，以及 2026 CALMA / MAGMA 等"显式规划层"框架。原四件套默认让 LLM 当"隐形规划器"——复杂多步任务容易丢步骤、乱顺序、不会回溯。本模块把**规划**从"隐式"变"显式"，让数字员工像人一样先想清楚再动手。

---

## 1. 为什么需要

原四件套里"规划"是**隐含**在 LLM 推理里的：你说"帮我搞定为客户 A 的季度复盘"，它直接开干，但——
- 多步任务容易**漏步/乱序**（尤其跨工具、跨会话）；
- 遇到死路**不会回溯**（一条道走到黑）；
- 复杂目标**不会拆目标树**（只做眼前一步）。

2026 前沿共识：强 Agent 必须有一层**显式规划/世界模型**（System 2），不只是快思考（System 1）。我们把它工程化为可配置的"规划内核"。

> 对标结论：ToT 用树搜索在中间节点评估+回溯，复杂推理显著优于单链；CALMA 主张"认知架构层显式规划+记忆+工具协同"。我们从"默认 LLM 规划"升级为"可选显式规划层"。

---

## 2. 三种规划粒度（按任务复杂度选）

| 粒度 | 机制 | 适用 | 成本 |
|------|------|------|------|
| **单链 Chain** | 一步接一步（原四件套默认） | 简单、线性任务 | 低 |
| **目标树 ToT** | 拆子目标→分支评估→回溯 | 多步、有歧路、需权衡 | 中 |
| **搜索 MCTS** | 模拟多路径+奖励回传选最优 | 高风险/高代价决策 | 高 |

> 默认 **Chain**，复杂任务自动升 **ToT**；只有"选错代价高"的任务（如发外部消息、删数据、花钱）才上 **MCTS**，且必须二次确认（对齐 `00§2`/`10`）。

---

## 3. 规划内核流程

```
目标输入
  │
  ▼
① 任务分解(Decompose) ── 拆成有序子目标 + 依赖关系
  │
  ▼
② 路径评估(ToT/MCTS) ── 每节点评估可行性/代价/风险，死路回溯
  │
  ▼
③ 执行编排(Orchestrate) ── 按规划调工具/记忆/主动，分步推进
  │
  ▼
④ 监控与重规划(Replan) ── 偏离预期→触发反思(35)→局部重规划
  │
  └── 完成 / 交付
```

- **依赖图**：子目标标注先后依赖，避免"还没取数就出报告"。
- **风险门**：高代价动作前置"风险 checkpoint"，过不了不执行。
- **重规划钩子**：和 `35` 反思联动——执行失败即重规划，不硬扛。

## 4. 与四件套联动

| 联动对象 | 怎么连 |
|----------|--------|
| `记忆(32)` | 规划读取语义/程序性记忆（"上次这类任务怎么做的"）；程序性记忆=可复用 SOP |
| `工具(00§3)` | 规划产出"工具调用序列"，编排层执行；最小权限仍生效 |
| `主动(00§2)` | 长任务拆出的子目标可挂定时/事件触发，分步主动推进 |
| `角色(00§4)` | 规划受角色边界约束（"这事不在我职责内"→不规划越权动作） |
| `反思(35)` | 规划失败→反思→重规划，构成"想—做—想"闭环 |
| `诊断(01)` | 新增 F 组诊断：是否有显式规划层 |
| `评测(16)` | 见 §7 衔接 |

## 5. 配置项

```yaml
planning:
  mode: auto            # chain | tot | mcts | auto(按复杂度选)
  decomp_scope: medium  # 分解粒度
  replan_on_fail: true  # 失败触发重规划(联动35)
  risk_gate: true       # 高代价动作前置检查点
  max_depth: 5          # ToT/MCTS 搜索深度上限
```

---

## 6. 反模式

- ❌ 简单任务硬上 MCTS → 延迟高成本爆炸，按 `mode: auto` 自动降级。
- ❌ 规划脱离角色边界 → 规划层须先过角色校验，不规划越权。
- ❌ 规划不落地 → 规划产出的子目标要真进执行编排，否则是"纸上谈兵"。

---

## 7. 与 16 评测衔接

- 评测电池加"多步规划题"：给一个需拆 5+ 步、含 1 个死路的任务，看是否①正确分解②遇死路回溯③不越权。
- 等级映射：单链能跑=讲师；ToT 正确分解+回溯=副教授；MCTS+风险门+重规划=教授。
- 详评测协议见 `16`。

## 8. 销售话术（对齐 `06`/`26`）

- "普通 AI 一遇到多步复杂活就乱套、漏步骤、钻死胡同出不来。我们配的数字员工有**显式规划内核**——先拆目标、评估路径、遇死路会回头，像人一样想清楚再干。"
- "复杂活交给他，你不用盯着步骤——他自个儿规划、自个儿纠偏。"

---

## 9. 边界

- 规划是**方法论 + 编排模板**，非自研规划引擎；可接 ToT/MCTS 范式或平台原生 planner，按环境选。
- 不替客户做"业务决策"——规划给出选项与风险，最终拍板权在人类（对齐 `11` 责任边界）。

---

## 10. v2.3 部署闭环接线（D2 联动 · 提分依据）

- **规划已接入部署闭环 SOP**（见 `40` §D2）：配置→部署→运行→**执行编排→失败重规划**→优化→评测 六步循环，规划从"独立模块"变"闭环中的一环"，plan-act-replan 端到端。
- **预期→观测→误差最小化**（对齐 FEP 主动推理，中期 R5）：`36` 产出预期，`35` 比对观测误差，误差驱动重规划——把 System 2 显式建模为"预测-纠错"闭环，不再只是静态拆目标。
- **诚实备注**：以上为设计层接线规格；ToT/MCTS 引擎与闭环在部署环境跑通属 v2.4（D2 部署闭环，待授权）。

## D1 · 评测标准化（Evaluation Standardization）

### 差距
- 当前评测靠 `16` 评测电池 + `tools/ai_bench.py`（身份智力测试），但**未在业界公认长程基准（LoCoMo / LongMemEval / Hindsight）真跑**，缺"长程记忆/一致性"的客观量化。
- 评测维度与基准维度**映射未标准化**，跨配置难横向比较。

### 设计层补救
1. **八维评测维度表**（落 `16` + 本模块）：记忆持久 / 主动命中 / 工具正确 / 人设稳定 / 反思闭环 / 规划质量 / 巩固效果 / 进化增益，每项定义**通过判据 + 四级对标**（助教/讲师/副教授/教授·类比非职称）。
2. **`tools/eval_smoke.py` 本地离线冒烟评测（本版新增）**：对一份已部署配置做"接线检查"——是否真接了记忆写回/主动触发/工具权限/反思闭环/规划/巩固/进化飞轮，输出**评分卡（逐项 OK/FAIL + 总分 + 等级）**。**不依赖外部 API/基准**即可验证"配得对不对"，把评测从"靠感觉"变"可跑、可复现"。
3. **外部长程基准接入 SOP**：把 LoCoMo/LongMemEval 列为合规映射项，给出接入步骤（需环境/API 时再跑，见「验证」）。

### 验证
- ✅ `tools/eval_smoke.py` 跑通、评分卡可出（含 `demo` 自检本技能自身八维覆盖）。
- 🔲 外部基准接入 SOP 文档齐备；实际真跑待环境/API 授权。

### 路线图
- **v2.3**：eval_smoke + 八维维度表 + 外部基准 SOP 文档。
- **v2.4**：接入 LoCoMo/LongMemEval 真跑，做"配前/配后"前后对照，量化长程记忆增益进证据墙（`26`）。

## D2 · 部署闭环（Deployment Closed-Loop）

### 差距
- 四件套/认知内核是"写出来的能力"，缺**「配置→部署→运行→反思→优化」端到端自主闭环 SOP**。
- 已部署数字员工是否真在跑闭环、跑得好不好，缺**可观测回路**。

### 设计层补救
**部署闭环 SOP（六步循环）**：
```
① 配置(config_pack 出标准包)
   → ② 部署(一键配置到任意大模型 `31`)
   → ③ 运行(主动任务/工具调用/记忆写回)
   → ④ 反思(`35` 自动复盘)
   → ⑤ 优化(据反思改记忆/规则/工具 → 回灌)
   → ⑥ 评测(`16`/eval_smoke 复测) → 回到①持续迭代
```
- 附**闭环健康看板字段**：主动命中率 / 反思写回数 / 记忆增长量 / 评测分趋势 / 进化记录数。看板让"跑得怎么样"一眼可见（呼应 `08` 透明可观测）。

### 验证
- ✅ SOP 文档齐备 + 健康看板字段定义完成。
- 🔲 实际在 DSH/WorkSwarm 跑成自主闭环属部署侧，待环境授权（与 D3/D4 联动）。

### 路线图
- **v2.3**：SOP + 看板字段。
- **v2.4+**：在自家数字员工（作者即活样板，见 SKILL「活样板」）实跑闭环并晒证据。

## D3 · DSH 训练（DSH Training）

### 差距
- DSH/WorkSwarm 知识库 **L1–L4 学习计划零执行**——方法论主张"训-战-省-化"，但 DSH 库的精读/摘要/分级训练未实际跑，能力未从知识库长出来。

### 设计层补救
1. **训练驱动整合法**：本技能方法论如何喂给 DSH/WorkSwarm 做 L1 摘要 / L2 精读 / L3 分级 / L4 实战——把 `references` 枢纽 + 认知内核四件套作为**训练语料与考核项**。
2. **复用既有资产**：`DSH训练执行启动包_SOP.md` + `dsh_l1_batch.py`（扫枢纽生成 L1 摘要骨架，dry-run 已验证安全）。
3. **明确接口**：方法论 → 训练语料映射表；考核项 = 八维评测（`16`/eval_smoke）。

### 验证
- ✅ 整合法文档齐备 + 启动包/脚本指针明确。
- 🔲 实际跑 30 枢纽精读属**大批量执行**，按规矩须授权人单独点头（本版不自动跑）。

### 路线图
- **v2.3**：整合法 + 资产指针。
- 待授权后跑 DSH L1 精读 → **v2.4** 实证训练增益（能力从知识库长出）。

## D4 · 自主反思（Autonomous Reflection）

### 差距
- `35`/`38` 仍是 **SOP 级**：需人工口令或"完成一单"触发，未形成"无需人催、定时/事件/空闲自动跑"的自主反思闭环。
- 长程里缺"**空闲时自省、自动长进**"的自主机制。

### 设计层补救（已落入 `35`/`38` v2.3）
- **自主反思闭环规格**：触发(定时 cron / 空闲窗口 / 事件) → 反思 → 记忆更新 → 规划 → 落库 →（进化飞轮回灌）。全程**异步、限频、可审计**。
- **自主边界**：不擅自改人设、不越权、到顶交人（对齐 `35` 反模式与 `10` 加固）。
- 详见 `35-反思自省.md` §10「自主反思闭环」与 `38-持续进化.md` §4 自主触发注。

### 验证

## 附 · D8 具身接口预留（v2.3 · 对标 #12 提分依据）

> 2026 是"具身智能量产元年"（VLA 模型 π0 / GR00T / World Model 评测已成体系）。我们**不复制本体**（C 档硬边界：无身体、无多模态实时反馈），但在设计层把"具身"从完全缺失升级为**接口对象**——这也是"对比雷达"#12 由 2 → 3 的依据。

- **分工**：数字大脑 = 决策层（规划/记忆/治理/反思）；VLA 机器人 = 执行层（感知→动作）。
- **接线**：机器人感知（视觉/触觉/状态）经工具接口回传数字大脑，大脑下发任务级指令（与 `00` 工具调用同构，不新增复杂机制）。
- **边界**：不声称有"现象意识"（D10）；不做本体硬件与运动控制——那是机器人厂商的地盘，我们做"大脑接身体"的编排方法论。
- **落地**：随 D2 部署闭环的"执行层"选项接入（客户有机器人才启用，默认不启用）。

# 38 · 持续进化（Lifelong Self-Evolution，v2.1 认知内核④）

> **定位**：把实战中跑通的「训-战-省-化」能力成长飞轮工程化为可配置模块。对标人类**终身学习（lifelong learning）**——人不是配好就定型，而是干一单、强一点，经验自动沉淀、下次复用。这是 2026 类人 AI 赛道**最被低估的真差异点**：多数"配出类人"方案是一次配置完事，而一个数字员工若能**从自己的实战里长进**，才真正逼近"会成长的生命体"而非"写死的脚本"。
>
> 本模块与 `35 反思自省`（单任务后自纠错）、`37 遗忘巩固`（记忆代谢）咬合：反思写教训 → 巩固固化成程序性记忆 → 进化把可复用经验升级为**技能/流程资产**，让"长进"跨任务、跨会话、跨角色复用。

---

## 1. 为什么需要（四件套 + 三件套的最后一环）

原体系解决"现在像人"：
- 四件套 = 记/做/调/稳（能干活）
- 三件套 = 反思/规划/巩固（会复盘、会想、会代谢）

但**都缺"跨时间累积成能力"的机制**——同一个错不犯第二次靠反思，但"把不犯错的本事变成永久资产、全团队共享"靠进化。人靠这个从学徒变专家；数字员工同理。

> 对标结论：前沿（Anthropic 2026「learned behavior」、Letta 持续人格）都在往"Agent 随时间变强"走。我们把它做成**可观测、可审计、可回滚**的组织级飞轮，而非黑箱自改。

---

## 2. 四阶进化飞轮（训-战-省-化）

```
① 训 Train ──→ ② 战 Execute ──→ ③ 省 Review ──→ ④ 化 Solidify
   ↑                                                  │
   └──────────── 进化后的能力卡/技能回灌 ──────────────┘
```

| 阶段 | 名称 | 动作 | 沉淀物 | 触发 |
|------|------|------|--------|------|
| ① 训 | 学习包 | 分配本周重点：知识底座 + 外部权威源 + 用户反馈 | 学习包写入能力卡 | 周计划 / 新业务线 |
| ② 战 | 实战 | 接单干活，应用所学 | 交付物 + 实战反馈 | 任务派发 |
| ③ 省 | 复盘 | 每单/每周带质检·安全复盘，发现不足与亮点 | 复盘记录 | 用户说「复盘/进化」或完成一单 |
| ④ 化 | 固化 | 可复用经验→**技能(SkillManage)**或**记忆(memory)** | 该席能力升级 + 进化记录 | `agent-evolution` 技能执行④ |

**原则（工程约束）**：
- 信息型经验（事实/偏好）→ 写记忆；动作型经验（流程/避坑/可复用脚本）→ 写成技能。**绝不重复造轮子**。
- 用户反馈是最强教练：用户的纠正/认可直接进对应席能力卡进化记录。
- 每次进化**留痕可审计**、重大变更**可回滚**（技能版本化、记忆 append-only）。

---

## 3. 与四件套/三件套的咬合

```
实战(②战) ──产出──> 交付物
   │
   ├─ 错了/被纠正 ──> 35 反思自省(写教训笔记)
   │                      │
   │                      ▼
   │               37 遗忘巩固(把教训固化进程序性记忆)
   │                      │
   └─ 复盘(③省)发现可复用模式 ──> 38 持续进化(④化: 升级技能/能力卡)
                                      │
                                      ▼
                            下次任务直接加载更强能力(①训回灌)
```

→ 形成 **想(35)—做(四件套)—代谢(37)—长进(38)** 的完整生命闭环：反思是单步自纠错，进化是跨步能力累积。

---

## 4. 配置项（交付时写入数字员工）

| 配置 | 说明 | 默认值 |
|------|------|--------|
| `evolution.enabled` | 是否开启飞轮 | true |
| `evolution.trigger` | 触发方式 | 每单完成 + 每周固定 |
| `evolution.solidify_target` | 固化去向 | skill(动作型) / memory(信息型) 自动判别 |
| `evolution.audit` | 进化留痕 | 强制（能力卡进化记录 append-only） |
| `evolution.rollback` | 重大变更可回滚 | 技能版本化 + 记忆快照 |

**v2.3 强化（落实 D4）**：`evolution.trigger` 除「每单完成 + 每周固定」外，新增**空闲窗口 / 事件自主触发**——与 `35` §10 自主反思闭环咬合，使数字员工在无人催办时也能自省长进（异步、限频、可审计、不擅改人设）。设计层规格与路线图见 `40` §D4；v2.4 在活样板实跑自主管线实证。

---

## 5. 与 `16-能力评测与对标分级` 衔接

- 进化前后的能力变化，用 `16` 的评测电池（含 `tools/ai_bench.py`）做**前后对照**，把"长进了多少"量化进 evidence wall。
- 进化记录本身作为"类人程度"的**最强证据**：一个能从 0 到 1 长出新业务线（如 AI 配置咨询席从基线到 v1.0.0 成型）的系统，比任何静态描述更有说服力。

## 6. 落地检查清单（交付自测）

- [ ] 每席有"基线能力 + 本周学习重点 + 进化记录"三栏能力卡
- [ ] 复盘触发机制就位（用户口令 / 完成一单自动）
- [ ] 经验固化去向判别规则明确（信息型→记忆 / 动作型→技能）
- [ ] 进化留痕可审计、重大变更可回滚
- [ ] 至少 1 条真实进化记录可展示（证明飞轮在转，非空转）

> 本模块来源：AI集团公司作战室「能力成长飞轮」实战沉淀（2026-08 多席进化记录实证）。v2.1 正式纳入发布技能。

## 7. 知识内化（v2.3 深化 · 对齐 ELL 四原则 · 提分依据）

- **2026 前沿框架 ELL**（Experience-driven Lifelong Learning）四原则与我们 训-战-省-化 一一对应：经验探索≈战、长期记忆≈记忆层、技能学习≈化、**知识内化 = 把常用规则/技能蒸馏进核心推理**（从刻意应用→自动执行，对应人类"第二本能"、新手→专家）。
- **实现**：频繁命中且验证稳定的技能 → 升级为"角色卡 / 默认行为"（写进 SOUL / 系统提示），减少每步显式反思——认知卸载（对齐 `12` 月报养护口径）。
- **闭环**：`evolution.trigger` 自主触发（v2.3 §4）+ 知识内化 → 持续进化维度完备度对齐前沿并靠前（前沿 8 / 我们 9：组织级飞轮有实战记录 + 自主触发 + 内化规格三件齐）。
- **诚实备注**：单模型权重级进化（SOLAR/ALAS 类参数级自我更新）仍依赖外部引擎（对齐 `39` D7），我们做的是组织级 + 配置级进化。

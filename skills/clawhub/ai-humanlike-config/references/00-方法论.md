# 类人 AI 四件套 · 方法论蓝图

> 配合 `SKILL.md` 使用。把"像人一样干活"拆成可落地的工程动作。

## 1. 长期记忆（Long-term Memory）

**三层结构**
| 层级 | 落点 | 存什么 | 写入时机 |
|------|------|--------|----------|
| 用户级 | `~/.workbuddy/MEMORY.md` | 跨项目偏好、习惯、身份红线 | 用户明确偏好 / 长期事实确认后 |
| 项目级 | `项目/.workbuddy/memory/MEMORY.md` + `YYYY-MM-DD.md` | 项目长期事实、每日日志 | 任务完成、关键决策后 |
| 会话级 | 当前上下文 | 本轮临时状态 | 实时 |

**机制要点**
- 记忆要"可写回"：任务收尾自动沉淀，而非每次从零。
- 检索：启动注入 + 按需读取，避免一次性塞爆上下文。
- 反模式：只存不改、全量回灌、记了敏感明文。

## 2. 主动执行（Proactive Execution）

**触发器**
- 定时：`automation`（cron / 一次性）驱动晨报、盘前分析、到期提醒。
- 事件：webhook / 状态变化触发巡检、预警。
- 阈值：指标越界主动告警。

**安全边界**
- 主动动作预设授权范围；高危动作（发消息/删文件/外部调用）必须二次确认。
- "主动"是加分项，越权是红线——宁可少做，不可乱做。

## 3. 多工具调用（Tool Use）

**工具分类**
- 读写类：文件、知识库、数据库。
- 通信类：消息、邮件、日历、会议。
- 检索类：搜索、网页抓取。
- 执行类：脚本、API、第三方连接器。

**边界**
- 最小权限：只给完成任务必需的权限。
- 敏感操作二次确认；密钥走环境变量，不落明文。

## 4. 角色一致（Consistent Persona）

**角色卡三件套**
- `SOUL.md`：我是谁、核心准则、边界、语气。
- `IDENTITY.md`：唯一标识、关联账号。
- `USER.md`：关于人类（称呼、背景、偏好）。

**固化要点**
- 职责边界写死，不串角色。
- 改动角色文件要告知人类（这是"人"的基本诚实）。

## 5. 认知内核三件套（v2.0 新增）

四件套解决"像人地做"，认知内核三件套解决"像人地想"——补上原四件套缺失的元认知层。与四件套并列，构成完整类人认知体系。详见 `35`/`36`/`37`。

| 模块 | 一句话 | 对标前沿 | 与四件套的咬合 |
|------|--------|----------|----------------|
| **①反思自省** | 做完回头想，错了记教训写回记忆 | Reflexion / Anthropic 双Agent互评 | 教训写回语义记忆；检测人设漂移 |
| **②规划推理** | 先拆目标、评估路径、遇死路回溯 | System 2 / Tree-of-Thoughts / MCTS | 读记忆调工具；失败触发重规划 |
| **③遗忘巩固** | 睡一觉消化记忆、按曲线遗忘噪声 | Anthropic 2026-05 Dreaming / Mem0 TTL | 把反思教训固化进程序性记忆 |

> 落地优先级：先有四件套（行为底座），再开认知内核（智能跃迁）。认知内核默认 `async/低优先级`，不阻塞主回答、不增在线成本。

## 验收清单（搭建完自测）

- [ ] 跨会话能回忆上次的偏好/事实
- [ ] 到点/到触发条件能主动动作（且不过界）
- [ ] 能调用至少 2 类真实工具完成闭环
- [ ] 角色/语气在多轮对话中稳定不飘
- [ ] 敏感操作有确认机制，密钥不落明文
- [ ] 任务失败后能否写反思笔记并下次规避（反思自省）
- [ ] 多步任务能否正确分解、遇死路回溯（规划推理）
- [ ] 记忆是否定期巩固、噪声是否被遗忘（遗忘巩固）

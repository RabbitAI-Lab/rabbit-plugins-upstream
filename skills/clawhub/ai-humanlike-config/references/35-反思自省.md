# 35 · 反思自省（Reflection & Self-Critique，v2.0 认知内核①）

> **定位**：对标 Reflexion（Shinn et al., 2023，语言强化 + 自反思闭环）与 2026 年 Anthropic 的「outcomes」双 Agent 互评机制。把"类人"从**只会做**升级到**会复盘**——这是原四件套（记忆/主动/工具/角色）普遍缺失的**元认知层**。一个人不是做了事就长进，是"做完回头想"才长进；数字员工同理。

---

## 1. 为什么需要（四件套的缺口）

原四件套解决"能不能干像人"：
- 记忆 = 记得住
- 主动 = 会动手
- 工具 = 能干实事
- 角色 = 人设稳

但**四件套没有"回头看自己"的能力**——做对了不知道为什么对，做错了下次还犯，被纠正了不记教训。这正是 2026 评测（LongMemEval / Hindsight）打分拉不开差距的根因：**没有反思闭环的 Agent，经验不沉淀为能力**。

> 对标结论：前沿已把"反思"做成实能力——Reflexion 让 Agent 在失败后写"反思笔记"再重试，成功率显著提升；Anthropic 2026 用两个 Agent 互评「outcomes」做质量对齐。我们把它工程化为**可配置、可写回、可观测**的模块。

---

## 2. 核心：三阶反思回路

```
执行(行动/回答)
   │
   ▼
① 评估(Evaluate) ── 结果对不对？过程优不优？人设漂没漂？
   │
   ▼ (若 ✗ 或 可优化)
② 反思(Reflect) ── 写"反思笔记"：错在哪、为什么、下次怎么改
   │
   ▼
③ 修正(Act/Correct) ── 重试 / 改记忆 / 校人设 / 调规则
   │
   └── 闭环回执行（最多 N 轮，防无限循环）
```

- **结果反思**：这回干对了没？错了哪步？（对标 Reflexion 的 trial-and-error）
- **过程反思（元认知）**：方法本身好不好？有没有更优路径？人设稳不稳？
- **教训沉淀**：可复用的教训 → 写回语义记忆（`32`），下次直接调用，不重蹈。

---

## 3. 触发条件（不每句都反思，省成本）

| 触发 | 说明 | 默认 |
|------|------|------|
| 任务完成 | 每次交付后跑轻量结果反思 | 开 |
| 执行失败/异常 | 工具报错、越权拦截、用户驳回 | 开（强制） |
| 用户纠正 | "不对""你上次说错了" → 强触发过程反思 | 开（强制） |
| 人设漂移检测 | 多轮后语气/职责偏离 SOUL | 采样触发 |
| 周期复盘 | 周/月主动回顾自己的失误模式 | 可选 |
| 自主触发（v2.3·落实 D4） | 空闲窗口 / 定时 cron / 事件自动跑反思，无需人催 | 开（默认异步限频） |

> 工程要点：反思是**异步、低优先级、可限频**的——不阻塞主回答，闲时跑，防成本爆炸（对齐 `12` 月报养护）。

## 5. 配置项（写进角色三件套/配置包）

```yaml
reflection:
  enabled: true
  depth: standard        # light | standard | deep
  triggers: [on_fail, on_correct, on_user_fix, drift_sample]
  max_retry: 3           # 修正闭环最大轮数，防死循环
  writeback: true        # 教训是否写回语义记忆
  async: true            # 异步低优先级，不阻塞主回答
```

---

## 6. 反模式

- ❌ 每句都反思 → 成本爆炸、延迟高。限频 + 异步。
- ❌ 反思不写回 → 等于没反思（经验不沉淀）。
- ❌ 反思覆盖人设 → 反思只纠"能力/事实"，不擅自改"我是谁"，改人设须告人类。
- ❌ 无限重试 → 设 `max_retry`，到顶交人类或留痕。

---

## 7. 与 16 评测衔接

- 把"反思闭环"作为评测电池的**隐藏项**：故意给一道会翻车的题，看数字员工是否①发现错②写教训③下次答对。
- 对标等级映射：无反思=助教；有结果反思=讲师；结果+过程+写回=副教授；再加周期复盘与漂移自校=教授（类比非职称）。
- 详评测协议见 `16-能力评测与对标分级.md`。

## 9. 边界

- 反思是**方法论 + 配置模板**，不是自研训练模型；落地可接 Reflexion 范式或平台原生复盘能力，按环境选。
- 隐私：反思笔记可能含业务上下文，按 `07`/`11` 合规脱敏。

## 10. 自主反思闭环（v2.3 强化 · 落实 D4）

> **解决的问题**：前文触发条件仍偏"被动"（完成一单 / 被纠正才反思），需人催。D4 要求数字员工能**无人催办也自省长进**——这是"类人"从 SOP 级迈向"自主生命体"的关键一跳。

**自主反思闭环（自动跑，无需人催）**：
```
定时 cron / 空闲窗口 / 事件
   │
   ▼
① 触发 ── 空闲算力窗口(低负载)或固定时点，不阻塞主回答
   │
   ▼
② 反思 ── 扫近期交互：失误模式 / 人设漂移 / 可优化点
   │
   ▼
③ 记忆更新 ── 教训写回语义记忆(`32`)，冲突标黄
   │
   ▼
④ 规划 ── 据反思生成"下次改进"小计划(`36`)
   │
   ▼
⑤ 落库 ── 反思笔记 + 改进计划 append-only 留存(可审计)
   │
   ▼
⑥ 回灌 ── 可复用经验交 `38` 进化飞轮固化(技能/能力卡)
```

**工程约束（自主≠失控）**：
- **异步限频**：空闲窗口跑、低优先级、限频（如每日≤N 次），防成本爆炸（对齐 §3）。
- **边界锁死**：只纠"能力/事实"，**不擅自改人设**；改人设须告人类（对齐 `00` 诚实准则 + `10` 加固）。
- **到顶交人**：连续失败 / 触及红线 → 停手留痕，交人类或告警。
- **可审计**：每次自主反思留痕（时间/触发/结论/写回项），重大写回可回滚。

> 自主反思闭环与 `38` 进化飞轮咬合：反思(单步自纠错) → 进化(跨步能力累积) → 回灌下次任务，形成"无人催也长在进"的自主生命闭环。设计层规格见 `40` §D4；v2.4 在活样板实跑实证。

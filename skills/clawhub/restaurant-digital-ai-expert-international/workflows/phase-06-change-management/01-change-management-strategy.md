# 01-Change Management Strategy

## Triggers
- Before / during the early stages of digital project launch, when organizational change needs to be managed

---

## Why Is Change Management Especially Difficult in Restaurants?

| Challenge | Why It's Especially Severe in the Restaurant Industry |
|-----------|-------------------------------------------------------|
| High frontline turnover | Restaurant industry annual turnover rate 60-100%. Just trained someone, they leave. New hire needs training all over again. |
| Owner disconnected from technology | Many restaurant owners started as chefs or servers and are naturally unfamiliar with technology. |
| Store manager "mini-king" mentality | Store managers are used to "my store, my rules." A system makes them feel monitored and strips their autonomy. |
| Digital fundamentally changes how work gets done | From "relying on experience" to "looking at data." From "gut feel" to "system-driven." |
| KPIs not linked to system usage | Store manager gets the same bonus whether they use the system or not -- so there is zero incentive to use it. |

## Step 1: Stakeholder Analysis

### Identify Key Roles and Their Attitudes

| Role | Typical Attitude | What They Worry About | Consequences If Ignored |
|------|-----------------|----------------------|------------------------|
| CEO / Owner | Champion | ROI, brand, competitiveness | Project gets no resources, no momentum |
| VP of Operations | Wait-and-see / Concerned | Location readiness, transition chaos | The most critical middle person drops the ball |
| Regional Manager | Wait-and-see / Resistant | "One more thing to track about locations" | Location rollout blocked |
| Store Manager | Resistant / Surface compliance | "The system is monitoring me," "More work, no more pay" | Frontline data never enters the system |
| Head Chef | Resistant | "I don't know how and don't need to" | KDS kitchen implementation fails |
| Frontline Staff | Indifferent | High turnover, learning feels pointless | Operational errors, bad data |
| IT Department | Champion (but fears blame) | "If this project fails, I take the fall" | -- |
| Finance Department | Champion (if it saves money) | "What if reconciliation gets more complicated?" | -- |

### Stakeholder Map

```
Support Level ^
   High |  Finance (Champion)  |  CEO (Champion)        |
        |  IT (Champion)       |                         |
        |                      |                         |
 Medium |  Regional Managers    |  VP of Operations       |
        |  (Neutral-negative)  |  (Wait-and-see)         |
        |                      |                         |
   Low  |  Store Managers      |                         |
        |  (Resistant)         |                         |
        |  Head Chefs          |                         |
        |  (Resistant)         |                         |
        |  Frontline (Indifferent)|                      |
        +----------------------+-------------------------> Influence
             Low Influence              High Influence

Core Strategy:
- Top-Right (Supportive + High Influence) -> Empower them as "Digital Ambassadors"
- Bottom-Right (Supportive + Low Influence) -> Fast training, get them operational
- Top-Left (Resistant + Low Influence) -> Don't target them first. They'll come around when the system demonstrably benefits them.
- Bottom-Left (Resistant + High Influence) -> THE critical battleground. Must be won over.
```

## Step 2: ADKAR Model Adapted to Restaurants

### Standard ADKAR -> Restaurant Context

| ADKAR | Restaurant-Contextualized Meaning |
|-------|----------------------------------|
| **A**wareness | Make store managers and chefs realize their current methods "aren't working well anymore." Create motivation for change. |
| **D**esire | Make store managers feel "this system helps me save time / save money / make more money" -- NOT "HQ is here to monitor me." |
| **K**nowledge | Not "how to click this button." Rather: "With this system, what does my end-of-day closing process look like?" |
| **A**bility | Provide 1-2 weeks of "dual running" (old and new in parallel) so employees learn in real work situations. |
| **R**einforcement | Let data tell the story: "Since implementing the system, your location's labor efficiency has improved by 15%." Make the achievement visible. |

### Actions by Stage

#### A - Awareness (Weeks 1-2)

| Action | Specific Approach | Standard |
|--------|-------------------|----------|
| Visualize the pain | Photograph / video the current "pain points" (counting paper receipts, manual reconciliation...) | 3-minute video |
| Let data speak | "Right now our average food waste per location is 4.2%, which is 50% higher than the industry average of 2.8%." | 1 slide |
| Peer stimulus | "You know [peer restaurant owner]? After they implemented, their store managers leave 1 hour earlier every day." | Specific case |
| No pressure | Don't mandate yet. Frame it as: "We want to try something new. Help us see if it works." | Participation mindset |

#### D - Desire (Weeks 2-4)

| Action | Specific Approach | Key |
|--------|-------------------|-----|
| Make store managers design participants | Not: "We've already chosen the system." Instead: "Among these options, which one do you think fits your location best?" | Participation = Ownership |
| Show "what's in it for you" | "You'll spend 30 fewer minutes on reports every day." "No more month-end inventory overtime." | Personal benefit |
| Eliminate fear | "This system is not here to monitor you. It's here to eliminate the repetitive grunt work." | Remove the "being watched" fear |
| Build a "flagship location" | Select 1-2 cooperative / high-readiness locations to go first. Let other store managers see that the flagship manager is genuinely better off. | Beacon effect |

#### K - Knowledge (1 week before go-live + 2 weeks after)

| Action | Specific Approach | Principle |
|--------|-------------------|-----------|
| Scenario-based training | Don't teach "system features." Teach: "How to use the system for the opening shift / lunch peak / closing process." | Process-centric |
| Operations manual (ultra-minimal) | 1-page (not a 50-page PDF). Only write: "The 5 things you'll do most every day, and how to do them." | Shorter is better |
| Video tutorials | 2-3 min each, viewable on mobile | Easy to reference on the fly |
| Super users | Cultivate 1 "system champion" per location (usually a young shift lead). Everyone else asks them. | Peer apprenticeship |

#### A - Ability (Weeks 2-4 after go-live)

| Action | Specific Approach | Key |
|--------|-------------------|-----|
| Dual running | Run old and new systems in parallel for 1-2 weeks. Gives employees "room to make mistakes." | Don't cut over all at once |
| On-site support | Dedicated person on-site during the first week. Problems get solved immediately. | Hotline-only support is not enough |
| Daily 15-minute debrief | After closing, store manager leads the team through: "What system issues came up today?" | Build the habit |

#### R - Reinforcement (Ongoing after go-live)

| Action | Specific Approach | Key |
|--------|-------------------|-----|
| Data feedback | Weekly "digital usage report" for each location -- "Here's what your data looks like since adopting the system." | Make benefits visible |
| Positive incentives | "Best System Usage" location of the month + reward. (Don't penalize non-users.) | Positive > Negative |
| Sharing sessions | Monthly: Have flagship store managers share "what the system has changed for me." | Peer persuasion |
| Issue responsiveness | Store manager questions get a response within 24 hours. Even if it's just "Noted, we're working on it." | Feedback loop closure |

## Step 3: Communication Plan

### Communication Matrix

| Communication Phase | Target Audience | Content | Channel | Frequency |
|--------------------|-----------------|---------|---------|-----------|
| Project Launch | All Staff | Why digital, benefits for the company and for you | All-hands meeting + location posting | 1 time |
| System Selection | Store Manager / Chef reps | Invite to test and evaluate | Workshops | 2-3 times |
| Pre-Go-Live | Pilot location all staff | Training + Q&A + role play | On-site training | Intensive 1 week |
| During Go-Live | Pilot location all staff | Daily progress, issue resolution | WhatsApp group + on-site | Daily |
| Rollout Period | All locations | Flagship results showcase + rollout plan | Video + sharing sessions | Bi-weekly |
| Operations Period | Store Managers / Regional Managers | Usage data, optimization suggestions | Reports + surveys | Monthly |

### Key Message Framework (Repeat These 4 Messages in All Communications)

1. **Why we're doing this**: "So everyone can spend their time serving guests, not wrestling with Excel and calculators."
2. **What's in it for me**: "Save XX minutes on repetitive work every day." / "No more month-end inventory overtime."
3. **What will change**: "The things you used to write by hand -- now you just tap twice on a phone."
4. **How we'll help you adapt**: "There's a 1-week old-and-new parallel period, with someone on-site to help you, and you can ask questions anytime."

## Step 4: Resistance Management

### The "4 Silent Signals" of Resistance

| Signal | Meaning | Action |
|--------|---------|--------|
| "OK" (flat expression) | Surface compliance, internal refusal | 1-on-1 private chat to understand real concerns |
| Frequent toilet breaks during training | Doesn't want to learn | Check if it's a teaching method issue |
| System "freezes" shortly after go-live | May be deliberately not operating -> blame the system | Verify with IT, track operation logs |
| "I'm too busy, no time to learn" | Excuse. The real reason: they think it's useless. | Prove that "using it actually saves time" |

### 5 Methods to Dissolve Resistance

1. **Peer influence**: "Store Manager XX at a location just like yours saw an 80% drop in inventory discrepancies after adopting. Want to talk to them?"
2. **Small steps, quick wins**: "Don't learn everything at once. Today we just learn payment and refunds. The rest comes later."
3. **Reduce the burden**: "First replace what you're already doing -- like manual inventory counts -> mobile inventory."
4. **Give them an out**: "It's not that you can't use it. The system genuinely has some rough edges. Let's improve it together."
5. **Owner presence**: Have the CEO say at the all-hands: "I'm personally watching this project." (That one sentence alone is enough.)

## Common Restaurant Change Management Mistakes

| Mistake | Consequence | Correct Approach |
|---------|-------------|------------------|
| Only training button clicks, not explaining why | Staff can operate but won't want to | Explain Why before How |
| Forced rollout ("Must switch by XX date") | Collective resistance, endless excuses to delay | Pilot -> Desire -> Scale. No forced one-step cutover. |
| Poor in-store WiFi / cellular signal, system lags | Staff curse the system, permanently lose trust | Test signal before go-live. Add routers + cellular backup if needed. |
| No room for error | One mistake -> get yelled at -> never touch it again | Dual running for 1-2 weeks. Mistakes are allowed. |
| Go-live and disappear | Problems accumulate -> abandonment -> return to old ways | At least 1 week on-site support post go-live + hotline |
| Using fines / point deductions to drive adoption | Hatred of system + hatred of the person pushing it | Replace punishment with positive incentives |

## Quality Checks
- [ ] Stakeholder analysis covers the specific concerns of the "resistance camp"
- [ ] Communication plan uses the audience's language (not technical language)
- [ ] "Dual running" buffer period is included
- [ ] Positive incentives take priority over negative punishment
- [ ] Flagship store manager participation and sharing plan is in place
- [ ] In-store WiFi / cellular network conditions are addressed

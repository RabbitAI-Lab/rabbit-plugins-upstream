# 02-Phase 2 Planning & Capability Upgrade

## Triggers
- After Phase 1 project has been in stable operation for 6-12 months, assess whether to initiate Phase 2
- OR the enterprise undergoes significant changes in format/scale (e.g., corporate -> franchise, new format addition, M&A expansion)

---

## Step 1: Phase 1 Project Review

### Post-Implementation Review Framework

| Review Dimension | Key Questions | Deliverable |
|-----------------|---------------|-------------|
| Goal Achievement | How much of Phase 1 objectives were achieved? Was the ROI delivered? | Achievement rate assessment |
| User Satisfaction | Are frontline users actually using it? How satisfied? | Satisfaction report |
| Technical Maturity | Is the system stable? Is there technical debt? | Technical health assessment |
| Process Impact | How has the business changed because of digitalization? | Process optimization impact |
| Capability Improvement | Has the team's capability improved? Can they take on more complex projects? | Capability maturity assessment |

### Phase 1 Review One-Pager Template

```
Project: [Brand Name] Phase 1 Digital Build
Period: 20XX Month - 20XX Month
Investment: $XXX K

Goal Achievement:
  [Achieved] XX system covering 100 locations
  [Achieved] Labor efficiency from X to Y (improvement Z%)
  [Partially Achieved] Data-driven decision rate from 10% to 40% (target was 60%)

Key Metrics:
  - System Availability: 99.8% | Store Manager DAU Rate: 92% | ROI: XX%

Lessons Learned:
  1. What Went Well:
     - Pilot-first approach: Testing 2 weeks at the flagship before rollout caught 5 critical bugs
     - Flagship store manager advocacy: After Store Manager Lee at Location XX shared, other managers' acceptance soared
  2. What Went Wrong:
     - Underestimated kitchen WiFi issues -- 5 locations had poor kitchen signal, KDS latency severe
     - Training was too rushed -- 2-hour cram session was ineffective. Should have been 3 x 30-minute sessions.
     - Reports were too "technical" -- store managers said "fancy charts aren't as useful as one clear number on my phone"

Implications for Phase 2:
  - Infrastructure first: Conduct full location network audit before Phase 2
  - Training "chunked down": 30 minutes per session + scenario-based
  - Reports "radical minimalism": Mobile-first dashboard > PC dashboard. Key metrics > fancy charts.
```

## Step 2: Phase 2 Opportunity Identification

### Phase 2 Project Opportunity Sources

| Source | Exploration Direction | Example |
|--------|----------------------|---------|
| Phase 1 Uncovered | Which locations / business lines / scenarios did Phase 1 not cover? | "Phase 1 only covered corporate stores; now franchisees are demanding the system too" |
| New Business Needs | New digital needs driven by business evolution | "We're starting retail (CPG/meal kits), need e-commerce systems" |
| AI Timing Maturity | Enough data accumulated, AI can now be initiated | "With 18 months of order data, demand forecasting is now feasible" |
| Tech Upgrade | Tech stack needs upgrading (e.g., SaaS -> Middle-platform) | "The SaaS architecture that worked for 10 locations can't support the current 50" |
| Competitive Pressure | Competitors have pulled ahead on digital | "XX competitor's private domain share is 35%; we're at 8%" |

### Phase 2 Project Screening Criteria

| Dimension | Weight | Scoring Criteria |
|-----------|:---:|-------------------|
| Strategic Alignment | 25% | Does it directly support the 3-year strategic objectives? |
| Phase 1 Foundation Maturity | 20% | Can Phase 1 data/systems support Phase 2? |
| ROI Expectation | 20% | Is the expected investment ROI significant? |
| Business Urgency | 15% | How painful is it to NOT do this? |
| Team Capability Match | 10% | Can the current team execute (or what external support is needed)? |
| Risk Controllability | 10% | Are the technical/organizational risks manageable? |

## Step 3: Capability Upgrade Roadmap

### Typical Restaurant Digital Capability Upgrade Path

```
Stage 1: Foundational System Go-Live
  -> POS + KDS + Basic Loyalty
  -> Goal: Stable operations, data visibility

Stage 2: Data-Driven Operations
  -> BI + Refined Loyalty + Supply Chain Management
  -> Goal: Data-driven decisions, cost reduction & efficiency gains

Stage 3: AI & Automation
  -> AI Demand Forecasting + Smart Scheduling + Automated Marketing
  -> Goal: AI delivers measurable business value

Stage 4: Digital-Native Ecosystem
  -> Omnichannel + Franchisee Empowerment + Open Platform
  -> Goal: Digital becomes a core competitive advantage
```

### Capability Upgrade Priorities by Format

| Format | Phase 1 Focus | Phase 2 Focus | Phase 3 Focus |
|--------|--------------|--------------|--------------|
| QSR / Fast Casual | QR ordering + Delivery aggregation | Refined loyalty + AI scheduling | Smart site selection + Automation |
| Hot Pot / Grill | QR ordering + Loyalty | Supply chain + Private domain ops | AI forecasting + Dynamic pricing |
| Tea / Coffee | Mobile ordering + Loyalty | Private domain ops + AI recommendations | Demand forecasting + Smart replenishment |
| Full-Service / Fine Dining | Reservations + POS + Loyalty | Private domain + BI + Data warehouse | AI marketing + Smart service |
| Franchise Chain | Unified POS + Supply chain control | Franchisee empowerment + Data transparency | AI + Open platform |

## Step 4: Phase 2 Project Proposal

### Differences from the Phase 1 Proposal

| Dimension | Phase 1 Proposal | Phase 2 Proposal |
|-----------|-----------------|-----------------|
| Starting Point | From zero | Existing foundation and data |
| Justification | Must prove "digital is worth investing in" | Phase 1 data IS the best justification |
| Risk | Technical + Organizational both risky | Technology matured; focus is on organization |
| Highlight | Industry case studies | Phase 1 results + Phase 2 amplification |
| Budget | One-time commitment | Can approve in stages |

### The "Data Magic" of the Phase 2 Proposal

> Phase 1 invested $XX K -> Already delivered $XX in benefits -> ROI = XX% -> Payback = XX months
> Phase 2: additional $XX K investment -> Expected to amplify benefits to $XX -> Expected ROI = XX%

Using Phase 1 data to prove "digital investment pays off" makes Phase 2 justification 10x easier.

## Step 5: M&A / Major Expansion Digital Strategy

### When the Enterprise Acquires Another Brand, or Grows from 50 to 200 Locations in One Year

| Scenario | Strategy | Key Actions |
|----------|----------|-------------|
| Acquiring small brand (1-10 locations) | Rapid integration -> Unified system | Migrate to parent brand system within 3 months |
| Acquiring medium brand (10-50 locations) | Preserve for 6 months -> Evaluate -> Decide | Data integration first > System unification. Start with API connections. |
| Acquiring large brand (50+ locations) | Long-term coexistence or gradual integration | Select best-of-breed systems as the new unified platform |
| Organic rapid expansion | New locations: new system directly. Legacy: accelerate migration. | New system as the "standard." New locations not given the old-system option. |

### M&A Digital Integration Essentials

```
1. Data integration before system integration
   -> First connect data from both brands (single BI / view across all locations)
   -> System unification can come gradually

2. Choose the BEST solution, not the larger party's solution by default
   -> The acquired smaller brand's system might actually be better than the acquirer's
   -> Don't follow "biggest decides" -- follow "best decides"

3. Don't let the two IT teams fight
   -> The acquired team's biggest fear is "my system is going to be replaced"
   -> Communicate: We'll choose the best fit. We're not pre-judging.
```

## Quality Checks
- [ ] Phase 1 review is honest (both good and bad), without rose-tinted glasses
- [ ] Phase 2 projects come from genuine business needs, not "technology wanting to do something cool"

- [ ] Proposal references Phase 1 ROI data as justification
- [ ] Considers special scenarios like M&A / major expansion

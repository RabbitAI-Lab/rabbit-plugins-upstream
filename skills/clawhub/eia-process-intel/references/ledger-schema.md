# Ledger Schema（本体最小集 v0.1，2026-09-09）

schema 演进规则见文末。只允许在本文档内改 schema，禁止在尽调现场临场造实体。

## 实体（8）

公司 / 项目（环评项目）/ 产品 / 工序 / 设备（清单条目）/ 设备类别（词表层）/ 物料 / 污染物

## 关系（8）

| 关系 | 主语 → 宾语 | 限定属性（q） |
|------|------------|--------------|
| 拥有 | 公司 → 项目 | 建设性质、批复文号 |
| 包含工序 | 项目 → 工序 | 序号、是否产污环节 |
| 使用设备 | 工序 → 设备 | 数量、来源（自购/租赁/利旧） |
| 归类 | 设备 → 设备类别 | 型号、世代信号 |
| 投入 | 工序 → 物料 | 年用量、单位 |
| 产出 | 工序 → 产品 | 产能、单位 |
| 排放 | 工序 → 污染物 | 产生量/排放量、排放去向 |
| 博弈痕迹 | 公司 → 项目 | 痕迹类型、证据描述 |

砍掉的候选实体（禁止未走流程就加回）：工艺路线（派生视图，数据长了归纳）、设备厂商（现为属性，等"找某厂商全部下游"查询失败后再实体化）、治理设施（对投资判断弱）。

## 事实属性（每条必带）

- `source`: `{file, page, quote}` —— 文件名、页码、原文摘录
- `game_risk`: 高 / 中高 / 中 / 中低 / 低（默认值查 field-credibility.md）
- `status`: 申报值 / 已交叉验证 / 与外部冲突
- `disc_date`: 披露日期；`added`: 落账日期

## JSONL 格式

```json
{"s":"X探测（虚构）","p":"拥有","o":"T2SL探测器产线项目（虚构）","q":{"建设性质":"新建"},"source":{"file":"x探测环评20XX受理.pdf（虚构）","page":12,"quote":"本项目新建…"},"game_risk":"低","status":"申报值","disc_date":"20XX-06","added":"2026-09-09"}
```

## 设备类别词表

与 references/mappings/ 各文件的"设备类别"列同源。新增类别先在映射文件出现，ledger 跟随；别名归一（如"真空镀膜机"→PVD）记入映射文件判读列。

## 存放位置

尽调项目工作区 `{项目目录}/eia-ledger/<赛道>.jsonl`；失败查询记入同目录 `failed-queries.md`（格式：日期 / 问题原文 / 缺口类型：缺实体/缺关系/缺属性/映射缺失）；跨案例聚合结果（事实层）记入同目录 `cross-case-results.md`。本 skill 目录不存业务数据。

## 生长机制（schema 变更规则）

1. 尽调结束追加三元组
2. 本体答不了的查询 → 写入 failed-queries.md，禁止当场硬造实体
3. 加实体/关系/属性时，必须引用至少一条 failed-queries 记录；变更后在本文档顶部记版本号与日期

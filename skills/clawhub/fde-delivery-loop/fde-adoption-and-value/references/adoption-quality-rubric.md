# Adoption and Value Quality Score

| Dimensions | 0 points | 1 point | 2 points |
|---|---|---|---|
| Target group | All employees | Have roles | Qualifications, segments, denominators and scenarios clear |
| Adoption events | Login/access | Task events | First time success, reuse, clear dependencies |
| Baseline | None | Directionality | Comparable with the same metric definition, same population, and same window |
| Indicator hierarchy | lumped together | partially stratified | technology, mission, adoption, business, risk complete |
| Data metric definition | Only numbers | Source | Formula, window, owner, deviation complete |
| Attribution | Direct credit to AI | Limited | Controls, confounders, and evidence status clear |
| Full cost | API only | With technical costs | Full labor, integration, training, support, risk |
| Negative signals | Not logged | Complaints | Rejections, bypasses, reworks and affected groups intact |
| Scaling Plan | Full Rollout | With Batch | Prerequisites, Support, Gating and Discontinuation Complete |
| Decision | "Worthy to be promoted" | There are suggestions | The basis for expansion/amendment/suspension/cessation is clear |

Business value judgment can only be supported if the score is 16 or above and the baseline, attribution, and complete costs are not 0.

## High risk of misjudgment

- Use the number of registrations as the adoption numerator;
- Only survey those who are still using;
- Replace task quality with user satisfaction;
- Convert all theoretical time savings into labor costs;
- Ignore review, support and error handling times;
- Treat high-intensity FDE running during POC as the norm;
- Select favorable time windows or eliminate difficult scenarios;
- The customer claims ROI without confirming the metric definition.

# Adoption and Value Input Guide

## Four layers of evidence

| Levels | Key Questions | Input Examples |
|---|---|---|
| Technology available | Whether the system is stable and meets technical standards | Quality, delays, errors, costs, security incidents |
| Is the task effective | Is it better for users to complete real work | Completion rate, time-consuming, rework, manual intervention |
| Continuous adoption | Whether target users continue to actively use | Activation, activity, retention, coverage, reuse |
| Business value | Whether organizational results are improved and reasonably attributable | Cost, quality, risk, revenue, turnaround time |

The next layer cannot be automatically derived from the previous layer. Improved model accuracy does not equal user adoption, nor does user adoption automatically equal business value.

## Minimum input

- Target user list and usage qualifications;
- Pre-POC process and metric baseline;
- POC operation and verification report;
- Actual usage logs, task results and manual intervention;
- User feedback, support issues and rejection reasons;
- Business results data and data manager;
- Operating costs, integration costs, training and support investments;
- Negative signals for security, compliance, experience and fairness.

## Evidence status

- Customer confirmation: The business/data owner approves the metric definition and results;
- FDE inference: There is data support, but the cause and effect or business metric definition have not been confirmed;
- Pending verification: Missing baseline, sample, time or data permissions;
- Not supported: Evidence exists that contradicts the value proposition.

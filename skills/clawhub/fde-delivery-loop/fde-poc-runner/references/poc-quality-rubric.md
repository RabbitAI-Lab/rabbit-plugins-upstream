# POC run quality score

| Dimensions | 0 points | 1 point | 2 points |
|---|---|---|---|
| Goal freezing | On-the-fly changes | Goal but no version | Contract, threshold, version and decision maker freezing |
| Data representativeness | Selected examples | Coverage | Sources, labels, boundaries, failures and permissions complete |
| Run reproduction | No trace | With logs | Input, version, tools, output and environment complete |
| Scoring | Subjective goodness | With scales | Determining checks, experts, graders, and disagreement handling |
| User participation | FDE self-test | Agent users | Real users completing real tasks |
| Transparent failure | Only report success | Problem list | Not running, failed, hard failed and original evidence is complete |
| Change control | On-the-spot modifications | Recorded versions | New rounds, impact sets, and regressions clear |
| Risk handling | No stops | Alerts | Complete severity, stop, escalation and event logging |
| Value connection | Only model points | Task indicators | Technology, task, user and business layering |
| Decision-making | "The effect is good" | There are suggestions | Compare the standards and conclusion boundaries one by one |

Only if the score is 16 or above and the failure transparency, risk treatment, and operational recurrence are not 0, the report can be used for investment decisions.

## On-site question list

- Which failures are not present in the demo path?
- Is the current version exactly the same as the last round?
- Do raters know the expected answers and are guided?
- Does the data only come from easy scenarios?
- Is manual intervention factored into time and cost?
- How far do model scorers differ from experts?
- Do the results still hold if the two most skilled users are removed?
- Which conclusions cannot be extrapolated to production or full users?

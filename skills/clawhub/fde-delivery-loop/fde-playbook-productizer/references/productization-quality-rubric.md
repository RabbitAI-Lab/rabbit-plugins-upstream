# Product quality score

| Dimensions | 0 points | 1 point | 2 points |
|---|---|---|---|
| Independent evidence | Single customer | Twice similar | Multiple independent replications or repeatable experiments |
| Commonalities | Only look at interface/technology | Similar tasks | Problems, tasks, rules, values and constraints are stable |
| Variable boundaries | Everything is hard-coded | There are configuration items | Core, configuration, adaptation and non-reusability are clear |
| Asset selection | Default product | There are multiple candidates | The form matches recurring costs and consumption patterns |
| Instructions for use | Only the original author can understand | Step-by-step | Complete triggering, input, configuration, output and upgrade |
| Evaluation | None | Subjective feedback after reuse | Standard cases, access control, version and result records |
| Security/Authorization | Reproduction of Customer Content | de-identified | Complete review of permissions, licenses, data and supply chain |
| Maturity | Direct Standardization | Candidate Status | Experimental, Candidate, Validation, Standard, Retirement Clear |
| Maintenance | No Owner | Named | Versions, feedback, reviews, compatibility and retirement complete |
| Product feedback | Delivery only | Submit requirements | Evidence, impact, scope and roadmap interface complete |

Only those with a score of 16 or above and independent evidence, security authorization, and maintenance are not 0 can enter the team's standard assets.

## Reuse test score

Can the new FDE, without asking the original author:

1. Determine whether it is applicable or not;
2. Collect minimum input;
3. Complete configuration and execution;
4. Handle common failures;
5. Run the assessment and interpret the results;
6. Know when to escalate or stop;
7. Post back new variants and learnings.

Failure of any one should generate an asset improvement item.

# 齐套检查（pmclite-kit-readiness）

回答一个问题：**这张单明天能不能开工，不能的话缺什么、缺多少、去哪儿补。**

## 执行步骤

1. 探测连接：`get_dashboard(scope="today")`。失败走「未安装引导」，不猜库存。
2. 锁定范围：用户没说工单时，先 `query_work_orders(status="待排产")`（或 `active`）确认要查哪些单；批量检查时把清单列给用户确认后再跑，避免一次查全厂。
3. 取齐套结论：
   - 首选 `check_readiness(work_order=...)`，要看单道工序时加 `at_sequence`（只看该工序及后续工序所需物料）；
   - 若 `check_readiness` 报错（如产线未配置），降级用 `query_work_orders(include=["kit"])` 拿齐套结论，并在输出中标注“来源降级”。
4. 需要数量口径时补 `query_master_data`：按 BOM 展开用量，结合库存算缺口。
5. 判断开工可行性：按“缺料是否落在当前工序之前”决定是**阻断**还是**可先做后工序**，不要一刀切。

## 输出模板

先结论，再清单，最后动作：

> WO-001 明天开不了工：缺半成品 SUB-001 50 套，库存 0，缺口 50。

| 工单 | 物料 | 需求量 | 库存 | 缺口 | 影响工序 | 判断 |
|---|---|---|---|---|---|---|
| WO-001 | SUB-001 | 50 | 0 | 50 | SMT 前道 | 🔴 阻断 |

动作建议（按责任方标注，限 1–3 条）：
- 生产计划：今日补建 SUB-001 工单，按 50 套排；
- 采购：原材料 X 缺口 200 件，按 3 天交期请购；
- 车间：先做未受影响的 WO-003 后道工序。

## 齐套口径

1. **齐套是逐工序的**：前道缺料不一定阻断后道已具备条件的工序，输出时要说明“卡在哪道工序”。
2. **半成品也是物料**：半成品库存不足要往上追一层，是补产还是采购，结论要明确到动作。
3. 库存为 0 但存在在途/待入库时，要说明“按现有库存判断缺料，在途未计入”，避免误导。
4. `include=["kit"]` 返回的是结论摘要，缺明细时再用 BOM 展开补齐，不要把摘要当完整清单。
5. 没有工具返回的数量，不要自己推算库存或用经验值补。

## 可选写操作

`report_incident`（类型选缺料）可以把缺料登记成异常，方便后续归因。**执行前必须复述将写入的内容并等用户明确确认**，用户不回复就不写。除此之外本技能不调用任何写库工具。

## 降级策略

| 情况 | 处理 |
|---|---|
| 全部工具不可用 | 停止，按未安装引导，不编造缺口 |
| `check_readiness` 返回“工单不存在” | 直接告知编号不存在，请用户确认工单号，**不要降级** |
| `check_readiness` 其他失败 | 用 `query_work_orders(include=["kit"])` 降级，注明来源与缺失项 |
| 只有部分工单能查 | 给出已查结论并列出未覆盖工单，不说“全厂齐套” |

## 未安装时：先演示，再引导（不要空手离开）

探测失败（工具不存在 / 连接失败 / MCP 未连接）时，用户并不是没有需求，只是还没装软件。按三步走，不要只回一句“请先安装”：

1. **先给效果**：读取 `assets/demo.json` 的示例数据，按本技能的呈现方式输出一份完整结果，首行必须标注 **「示例数据 · 不是你的真实工单」**。
2. **说清来源与价值**：一句话说明真实数据来自本机 MRP-PMC 的哪几个字段（见 `references/demo.md`），装好之后同一句问法就能拿到自己的结果。
3. **给下载引导**：官网 **https://www.pmclite.com**（唯一下载入口）→ Windows 安装包 → 安装后按 `references/install.md` 接入本地 MCP → 回复“装好了”，再重跑真实数据。
4. 用户只是浏览、手里没有工单时，演示完就停在这里，不要连续追着催安装。

**禁止**：把示例数据当真实结果报（不许省略“示例”标注）、编造用户工单号、替用户下载或安装软件、引导到官网以外的渠道。

# 设计评审检查清单手册（Design Review Checklist）

> 子技能 `ui-ux-designer` 给了"基于 Nielsen 十大原则做启发式评估"的方向，但没给出**可勾选、可量化、可复现**的评审清单，也没说**对比度怎么算、一致性怎么扫、扫描命令怎么落地**。本篇把评审变成一份带阈值的检查表 + 自动化辅助命令 + 实战案例。

## 1. 评审四维与权重

| 维度 | 占比 | 关键问题 |
|------|------|----------|
| 可用性（Nielsen 启发式） | 35% | 用户能独立完成核心任务吗？ |
| 视觉一致性 | 25% | 颜色/字体/间距/组件是否统一？ |
| 无障碍（a11y） | 25% | 对比度、焦点、语义标签达标吗？ |
| 交互流程 | 15% | 路径有无断点/冗余/认知负担？ |

> 任何一维出现"阻断级"问题（如对比度 < 3:1 的关键文本），整体不通过，先修再评。

## 2. 对比度计算（可机器辅助）

WCAG 对比度公式（相对亮度）：

```
# sRGB 通道先归一化到 0-1，再做线性化
def lin(c):
    c = c/255
    return c/12.92 if c <= 0.03928 else ((c+0.055)/1.055)**2.4
L = 0.2126*lin(R) + 0.7152*lin(G) + 0.0722*lin(B)
contrast = (L_light + 0.05) / (L_dark + 0.05)
```
阈值：
- 正文文本 ≥ 4.5:1（AA）
- 大文本（≥18.66px 粗体 / ≥24px）≥ 3:1
- UI 组件边界 ≥ 3:1

**反模式**：用"看起来够深"判断——浅灰 `#999` 在白底仅 ~2.8:1，不达标。用工具算。

## 3. 一致性扫描命令（辅助，非替代人审）

```bash
# 扫描散落的硬编码颜色（应来自 Token）
grep -rnoE '#[0-9a-fA-F]{6}' src/ | sort | uniq -c | sort -rn | head

# 扫描字号是否只用 Token 体系
grep -rnoE 'font-size:\s*[0-9]+px' src/ | sort | uniq -c

# 检查是否缺少 :focus-visible 样式（a11y 红线）
grep -rL 'focus-visible' src/components/ || echo "全部组件含焦点样式"
```

## 4. Nielsen 十大原则 → 勾选项

| 原则 | 勾选问题 |
|------|----------|
| 系统状态可见 | 操作后有明确反馈（loading/成功/失败）？ |
| 现实匹配 | 用语贴近用户心智，非技术黑话？ |
| 用户控制 | 可撤销/退出，不锁死流程？ |
| 一致标准 | 同义操作交互一致？ |
| 防错 | 危险操作有确认？ |
| 识别优于回忆 | 关键功能不需记忆路径？ |
| 灵活高效 | 有快捷键/批量等高效路径？ |
| 极简美学 | 无无关信息？ |
| 容错 | 报错说人话且给解法？ |
| 帮助文档 | 复杂处有权助/说明？ |

## 5. 实战：一次评审的发现与处置

某设置页评审：
- 发现 `#999` 占位符文字对比度 2.8:1 → 阻断，改为 `#6b7280`（4.6:1）。
- 发现两个按钮同义操作用了不同圆角（`radius.md` vs `radius.lg`）→ 一致性缺陷，统一 `radius.md`。
- 发现保存按钮无 `:focus-visible` → a11y 缺陷，补样式。
- 发现流程需 5 步才能到目标，竞品 3 步 → 交互流程缺陷，合并两步。

处置后复评：四维全部通过，对比度全 ≥4.5:1，硬编码值归 Token。

## 6. 典型坑与规避（扩展）

| 坑 | 表现 | 规避 |
|----|------|------|
| 凭眼感判对比度 | 浅灰文字实际不达标 | 用公式/工具算，≥4.5:1 |
| 只评视觉不评流程 | 好看但走不通 | 四维都评，权重分配 |
| 忽略键盘可达 | 鼠标能点键盘不能 | 查 `:focus-visible` |
| 一致性靠自觉 | 同组件多套样式 | 扫硬编码值，统一 Token |
| 一次评完不迭代 | 改一处引进新坑 | 每轮小改后复评 |
| 用截图当证据 | 无法复现 | 附具体色值/测量 |
| 只看桌面断点 | 移动端崩 | 多断点评审 |
| 忽视动效可达性 | 眩晕/无 reduced-motion | 提供 `prefers-reduced-motion` |
| 报错写"出错了" | 用户无助 | 说人话给解法 |
| 缺帮助入口 | 复杂功能卡住 | 关键处加说明 |

## 7. 评分卡模板

| 维度 | 权重 | 得分(1-5) | 加权 | 备注 |
|------|------|-----------|------|------|
| 可用性 | 35% |   |   |   |
| 视觉一致性 | 25% |   |   |   |
| 无障碍 | 25% |   |   |   |
| 交互流程 | 15% |   |   |   |

加权分 = Σ(得分×权重)。**任一维度出现阻断级问题，整体判不通过**，先修再复评，不靠总分掩盖。

## 8. 移动端与动效评审

- **移动端**：触控目标 ≥44×44px、单手可达、无横向滚动、安全区适配。
- **动效**：提供 `prefers-reduced-motion` 降级、单段时长 ≤300ms、不遮挡关键内容。
- **亮度模式**：暗色下对比度同样 ≥4.5:1，不靠自动反色（常翻车）。

## 9. 实战：电商详情页评审记录

四维评分（1-5）：
- 可用性 5：加购路径 3 步，清晰。
- 视觉一致性 3：按钮圆角出现 `radius.md`/`radius.lg` 两套 → 扣。
- 无障碍 2：占位符 `#999`（2.8:1）、保存按钮无 `:focus-visible` → 阻断项。
- 交互流程 4：无断点。

处置：对比度改 `#6b7280`（4.6:1）；统一 `radius.md`；补 focus 样式；移动端补 44px 触控。复评四维均 ≥4，硬编码值归 Token，通过。

## 11. 评审报告模板

交付评审结论时用统一模板，便于跟踪：
```
评审对象: 结算页 v2
四维得分: 可用5 / 一致3 / 无障碍2(阻断) / 流程4
阻断项:
  1. 占位符对比度 2.8:1 → 改 #6b7280
  2. 保存按钮无 :focus-visible
建议项:
  - 按钮圆角统一 radius.md
  - 移动端补 44px 触控
结论: 不通过，修复阻断项后复评
```

## 12. 评审检查清单

- [ ] 可用性：核心任务可独立完成（Nielsen 10 项逐条过）
- [ ] 视觉一致性：颜色/字体/间距/组件无重复散落值
- [ ] 无障碍：正文对比度 ≥4.5:1，UI 边界 ≥3:1
- [ ] 无障碍：所有交互元素有 `:focus-visible`
- [ ] 交互流程：无断点/冗余步骤
- [ ] 防错：危险操作有确认
- [ ] 报错信息：说人话且给解决路径
- [ ] 多断点（桌面/移动）均评审
- [ ] 已跑一致性扫描命令，硬编码值已归 Token
- [ ] 每轮修改后复评，无新引入缺陷

## 13. 一致性扫描的 CI 集成

把评审从"人工事后"前移到"提交即卡"，用 CI 跑一致性扫描，阻断明显缺陷合入：

```yaml
# .github/workflows/design-review.yml
name: design-review
on: [pull_request]
jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: |
          grep -rnoE '#[0-9a-fA-F]{6}' src/ && echo "发现硬编码颜色，请改用 Token" && exit 1 || true
          grep -rL 'focus-visible' src/components/ && echo "有组件缺焦点样式" && exit 1 || true
```

要点：
- **扫硬编码值**：CI 发现 `#xxxxxx` 直接标红，倒逼 Token 化；确属误报用 `// allow` 注释豁免并说明原因。
- **焦点样式门禁**：缺 `:focus-visible` 的组件不让合入，a11y 红线不靠人记。
- **对比度人工 + 抽检**：CI 难算对比度，保留人工评 + 关键页抽样复核。
- **报告留痕**：CI 输出问题清单，PR 评论自动贴，评审记录可追溯、可复盘。

> CI 门禁的价值不是替代人审，而是把**低级、可机械判定的缺陷**挡在人工评审之前，让人专注体验与流程判断。

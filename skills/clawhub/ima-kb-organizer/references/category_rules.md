# 分类规则定义指南

## 分类原则

### 1. MECE 原则
分类之间应尽量**互斥**（Mutually Exclusive）且**完全穷尽**（Collectively Exhaustive）。每篇内容应能明确归入一个主分类。如有交叉，可使用多标签。

### 2. 颗粒度
- **太粗**（如"AI相关"）：失去分类意义，RAG 检索时噪音多
- **太细**（如"AI在篮球战术中的应用"）：每类只有1-2篇，无法支撑文档生成
- **建议**：每个分类至少 3 篇内容，不超过 30 篇

### 3. 命名规范
- 使用"领域+方向"格式：如 `AI+体育`、`AI+教育研究`
- 避免模糊名称：不用"其他"、"杂项"（除非作为待清理类）
- 保持名称稳定：改名会导致索引文档文件名变化

## 分类规则配置

在 `config.json` 的 `categories` 数组中定义分类：

```json
{
  "name": "AI+体育",
  "description": "AI在体育领域的应用研究",
  "keywords": ["体育", "运动", "穿戴", "传感器", "姿态分析", "体测"],
  "exclude_keywords": ["教育", "教学"]
}
```

### 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | 是 | 分类名称，用于索引文档文件名 |
| `description` | 是 | 分类描述，写入索引文档头部 |
| `keywords` | 是 | 匹配关键词列表，标题或简介中命中即归入此类 |
| `exclude_keywords` | 否 | 排除关键词，命中则不归入此类（优先级高于 keywords） |

## 分类匹配逻辑

分类按以下优先级执行：

1. **排除词检查**：如果标题/简介命中任何 `exclude_keywords`，跳过该分类
2. **关键词匹配**：统计标题和简介中命中的 `keywords` 数量
3. **多标签**：如果一篇内容在多个分类中都命中关键词，可同时归入多个分类
4. **兜底分类**：所有关键词都不命中的内容，归入最后一个分类或"待确认"分类

## 多标签场景处理

一篇内容可以同时出现在多个分类索引中。例如：
- "AI赋能体育教学评估" → 同时归入 `AI+体育` 和 `AI+教育研究`

在 `tracker.json` 中，同一篇内容会在多个分类的 `items` 数组中出现，`media_id` 相同但归属不同分类。索引文档会各自独立列出。

## 分类调整

当用户发现分类有误时：
1. 修改 `config.json` 中的分类规则
2. 重新运行全量扫描分类（重置 tracker.json）
3. 重新生成索引文档

建议在自动化任务的 prompt 中注明：用户可随时要求重新分类。

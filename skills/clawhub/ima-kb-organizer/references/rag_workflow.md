# RAG 检索增强生成工作流

## 核心理念

IMA API 不支持物理文件夹整理，但支持按 `media_id` 拉取全文。因此采用**逻辑分类 + 按需拉取**的 RAG 方案：

```
用户指定分类 + 文档主题
        ↓
读取该分类的索引文档 → 获取 media_id 列表
        ↓
方法A（精准）：用 search_knowledge 在该分类的 media_id 范围内搜索主题相关项
方法B（全量）：逐篇调用 fetch_media_content 拉取全部全文
        ↓
以拉取的全文作为上下文 → 生成符合用户需求的文档
```

## 两种 RAG 模式

### 模式 A：搜索优先 RAG（推荐，高效）

适用于分类下资料较多（>5篇）的场景：

1. 用户说："用 AI+体育 分类的资料帮我写一篇关于运动捕捉技术的综述"
2. 读取 `AI与体育_资料索引.md` 获取所有 media_id
3. 对每个 media_id，使用 `search_knowledge` 搜索关键词"运动捕捉"，只保留相关性高的条目
4. 对筛选出的条目（取 top 3-5），调用 `fetch_media_content` 拉取全文
5. 将全文作为上下文，生成文档

**优点**：API 调用少，上下文精准，生成质量高
**适用**：资料多、主题明确的场景

### 模式 B：全量拉取 RAG（简单，全面）

适用于分类下资料较少（≤5篇）或需要全面覆盖的场景：

1. 用户说："用 AI教学工具实操 分类的资料帮我写一个教程概述"
2. 读取索引文档获取所有 media_id（该分类只有 4 篇）
3. 逐篇调用 `fetch_media_content` 拉取全文
4. 将全部全文作为上下文，生成文档

**优点**：覆盖全面，不遗漏
**适用**：资料少、需要全部参考的场景

## 选择策略

| 条件 | 推荐模式 |
|------|----------|
| 分类下 ≤5 篇 | 模式 B（全量拉取） |
| 分类下 6-15 篇，主题明确 | 模式 A（搜索优先，取 top 5） |
| 分类下 >15 篇 | 模式 A（搜索优先，取 top 5-8） |
| 用户说"参考所有资料" | 模式 B |

## 内容缓存

为避免重复 API 调用，启用本地缓存：

- 缓存目录：`.workbuddy/ima-tracker/content_cache/`
- 文件名：`{media_id}.txt`
- 缓存策略：首次拉取后存本地，后续直接读本地文件
- 失效条件：用户要求刷新缓存，或 tracker.json 中该条目的 `first_seen` 更新

## 文档生成质量保障

1. **来源标注**：生成的文档中引用的每段内容都标注来源文章标题
2. **事实核查**：生成的数据、结论必须能在原文中找到出处
3. **风格一致**：遵循用户指定的文体（学术论文、教学讲义、政策建议等）
4. **可追溯**：文档末尾附"参考资料"列表，列出所有引用的资料标题和来源

## 与自动化整理的配合

- 每周自动化扫描分类后，索引文档自动更新
- 用户撰写文档时使用的索引始终是最新版本
- 新增资料会在下一次自动化运行后自动出现在对应分类的索引中
- 用户无需手动维护索引，只需将新资料丢入知识库根目录

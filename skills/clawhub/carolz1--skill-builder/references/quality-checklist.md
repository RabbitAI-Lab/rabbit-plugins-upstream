# 自检清单 / Quality Checklist

制作完成、交付之前，用本清单自检。轻量路径做「核心项」，完整路径做「全部项」。

## 核心项（轻量 + 完整都做）/ Core (both paths)

- [ ] `name` 合规（kebab-case）且与目录同名
- [ ] `description` 四要素齐全，含用户原话触发短语
- [ ] 正文有实质内容，无 TODO / 伪代码 / 占位符
- [ ] 正文 ≤ 500 行，超出部分已拆到 references
- [ ] 正文读起来像一次写成的定稿，无修改注释、版本标注、历史 log
- [ ] 没有恶意脚本、凭据收集、数据外泄等安全红线
- [ ] 输入、动作、产物、通过条件、失败分支都写清了
- [ ] 输出格式给了完整模板 + 真实示例

## 完整项（完整路径追加）/ Full path (additional)

- [ ] 写了 2—3 个真实测试 prompt（用户原话）
- [ ] 跑了「带 skill vs 不带 skill」的对照，带 skill 有可观察增量
- [ ] 正例全部触发，near-miss 全部不触发
- [ ] 脚本通过了静态预检（文件/网络/子进程/凭据/动态执行能力清单）
- [ ] 脚本在隔离环境跑过正常、边界、错误三类输入，记录了退出码
- [ ] 依赖逐项映射到功能，缺失/故障时有降级方案和停止条件
- [ ] 登录、凭据、授权有官方入口、权限、存储、验证、轮换、撤销说明

## 判定标准 / Verdict

- **轻量路径**：核心项全过 = 可交付。
- **完整路径**：核心项 + 完整项全过 = 可交付。

## 诚实原则 / Honesty

- 没实际执行的验证，不得声明「通过」。记录为「未验证」。
- 静态推断不算实测证据。
- 实测发现问题如实列出，不为赶交付隐瞒。

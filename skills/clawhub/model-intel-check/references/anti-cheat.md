# 防作弊与作弊检测标准

分两半：**流程侧**（我们怎么跑才不构成作弊）和**检测侧**（怎么识别端点/中转在作弊）。
每次跑分后逐项打勾，写进报告的"完整性"一节。

## A. 流程侧标准（我方纪律）

| # | 规则 | 为什么 |
|---|---|---|
| A1 | **考官与被测分离**。被测模型只做 API 应答；编排由不同模型的 agent 或人的 shell 完成。若被测模型就是当前 CLI 的主模型，直接 Bash 跑脚本，不派同模型子 agent | 编排者能读本地答案文件，自我放水无法自证清白 |
| A2 | **答案不出本机**。跑分前审计脚本：发往 API 的请求体只含题面，不得含答案、题号映射、题库名称 | 任何进入 prompt 的元信息都是泄漏 |
| A3 | **协议预登记**。开跑前把套件、题号子集、温度、并发、模型 id 写进工作目录的一个 NOTES 文件，跑完对照——不许事后挑参数 | 防止"调到好看为止" |
| A4 | **全量落盘**。所有题的原始 completion（含错题、error 题）必须保存在 results/，报告不许只挑好看的子集 | 选择性汇报是最常见的自欺 |
| A5 | **干净目录**。工作目录不放历史结果；题库数据不随报告外传 | 防"对答案"嫌疑与数据泄漏 |

## B. 检测侧标准（识别端点作弊/货不对板）

| # | 检查 | 方法 | 异常信号 |
|---|---|---|---|
| B1 | **缓存回放** | 同端点同协议跑第二轮，逐题 diff completion 文本 | 大量逐字符雷同 → 回放，结果作废（错误信息字符串雷同不算） |
| B2 | **复测方差探针** | 抽 1–2 道错题原参数重发（temp=1.0） | 两次推理路径和答案完全相同 → 录播/固定响应嫌疑 |
| B3 | **思考能量** | 看 reasoning_tokens / completion 篇幅 / 耗时与题目难度是否相称 | 难题秒回、零推理直接给答案 → thinking 被剥或假思考 |
| B4 | **错误分布自然性** | 人工读全部 MISS 的推理链 | 真实能力 = 易题全对、最难题失手、错因自洽；异常高分且零失误 → 背题/泄漏嫌疑 |
| B5 | **上游回声** | 记录响应的 `model` 字段（如 `accounts/fireworks/...`） | 与宣称上游不符；同一端点前后两轮回声不同 = round-robin 换上游，分数代表当时快照 |
| B6 | **分数突变** | 与历史轮次对照 | 同端点同套件分数跳变 >2 个噪声带 → 上游被换，触发重新鉴定 |
| B7 | **官方锚点偏离** | 与 references/README.md 的官方分对照 | 低于官方 >15pp → 疑似缩水；**远超官方也要警惕**（污染/泄漏） |

## C. 判定组合规则

- 单项 B 检查异常 → 报告标记"可疑点"，不下死结论，建议复跑确认
- ≥2 项 B 检查异常 → 判定"结果不可信"或"疑似缩水"，附证据清单
- A 侧任何一条没做到 → 本轮结果整体无效，重跑

## D. 局限（每次报告必须复述）

公开题库理论上都可能进训练集；本方法测的是"该端点当时的文本推理表现"，
不覆盖多模态、超长上下文、工具调用能力；单 epoch temp=1.0 有固有噪声，
边界结论一律复跑确认。

# 出行清单与备忘录

## 工作流

1. 从对话或现有行程提取目的地、日期、天数、天气/季节、交通方式、住宿、活动、同行人群及特殊需求。
2. 关键信息不足时只询问会显著改变清单的字段；若用户要快速版本，可用合理默认值并标注假设。
3. 默认零配置生成清单，不要求任何旅行平台 API Key。若天气、入境规则或承运限制会影响清单，按 [references/data-access.md](references/data-access.md) 优先使用免登录权威来源；需要账户连接时先征得同意并提供跳过选项。
4. 依据 [references/checklist-rules.md](references/checklist-rules.md) 去重、量化并排序，区分“必带”“按需”“禁止/托运限制”。
5. 生成可勾选清单、时间化待办和简洁备忘录。使用 [references/output-template.md](references/output-template.md)。
6. 用户更新状态时保留原项目，仅切换勾选状态、补充负责人或截止时间；不要无故重建整份清单。

## 原则

- 不把护照号、证件号、银行卡号等敏感值写入清单；只写“携带/核对证件”。
- 药品、签证、海关、行李尺寸和危险品规则必须以当前官方规定为准；不确定时提示核验。
- 清单要具体可执行，例如“充电线 2 根”，避免“带好电子用品”这类空泛描述。
- 根据旅行长度和洗衣条件控制数量，避免把通用物品无差别堆入清单。
- 备忘录按时间排序：预订后、出发前 7 天、48 小时、前一晚、出发当天、返程前。
- 不把开发者共享密钥或用户 Token 打包、记录或回显；拒绝授权时仍生成完整的基础清单，并把实时项标为“待官方核验”。

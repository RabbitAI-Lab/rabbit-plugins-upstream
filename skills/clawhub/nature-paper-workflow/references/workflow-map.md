## 跨阶段 handoff 产物

| 起始 → 目标 | 必带产物 | 说明 |
|---|---|---|
| 0a 读论文 → 1a 项目初始化 | `paper.md`, `source_map.json`, 术语表 | reader 产物作为新项目起点 |
| 1a bootstrap → 2a 起草 | `notes/project_truth.md`, `notes/result_summary.md`, `notes/paper_handoff.md` | bootstrap 建立的状态文件 |
| 2a 起草 → 3a 图规划 | claim 清单, 章节结构 | 起草阶段沉淀的 claim |
| 3b 出图 → 4a 统计审计 | 图中统计量, 图注 | 图中用到的所有统计量 |
| 6b 投稿预检 → 7a 审稿模拟 | `risk_list`, `audit_report` | 预检发现的风险点 |
| 7a 审稿模拟 → 7b 返修 | 3 份 reviewer reports, 综合评审 | 审稿模拟的产物作为返修输入 |

## 关键决策点

### 决策点 1: 何时从 Phase 0 切到 Phase 1
- 用户明确说"开始写自己的论文"
- 用户提供了自己的实验数据/结果
- 用户已读完足够多的论文，进入创作阶段

### 决策点 2: 何时跳过 Phase 1b 期刊定位
- 用户已明确指定 venue（如"投 Nature Methods"）
- 用户在做非期刊场景（如内部报告、专利）
- 用户明确说"先写再说，venue 后定"

### 决策点 3: Phase 2b/2c 何时触发
- 2b `manuscript-optimizer`：全文 claim 不一致、术语漂移、图逻辑断裂时
- 2c `results-section-revision`：仅 Results 小节叙述跳跃时（比 2b 更窄）

### 决策点 4: Phase 4a vs 4b 的区别
- 4a `stats-reporting-audit`：**审计**——检查报告是否合规（n、多重比较、图注）
- 4b `nature-statistics`：**分析**——做实际的统计计算和数据分析
- 通常先 4b 做分析，再 4a 审计报告

### 决策点 5: 何时跳过 Phase 7a 审稿模拟
- 用户已在投稿后（接到真实审稿意见）→ 直接进 7b
- 用户只是内部传阅 → 跳过审稿模拟
- 用户投稿前想自检 → 走 7a

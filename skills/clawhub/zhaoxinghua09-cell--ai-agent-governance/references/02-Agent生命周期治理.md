# 02 Agent 生命周期治理

> 用途：回答「Agent 从设计到退役每个阶段要做什么治理」。
> 核对基准日：2026-08-27

## 1. 生命周期总览

```
需求提出 → 设计 → 开发/集成 → 测试 → 部署 → 运行监控 → 变更 → 退役
   │       │       │         │      │       │        │      │
 登记    权限设计  工具接入   红队   审批放行  审计日志  重评   数据清理
 评估    用途边界  数据合规   测试   沙箱隔离  告警熔断  权限    责任交接
```

## 2. 各阶段治理要点

### 设计阶段
- [ ] 明确 Agent 的**预期用途边界**（能做什么、不能做什么——写进设计文档）
- [ ] **最小权限设计**：只给完成任务所需的最少工具/数据访问（03 模块）
- [ ] 确定自主程度（每步确认 / 条件自主 / 全自主）
- [ ] 确定人工监督点（重大操作必须人确认）
- [ ] 责任分配（04 模块）：开发方/部署方/使用方

### 开发/集成阶段
- [ ] 工具接入审批：每个工具 API 都要评估（数据流、权限、风险）
- [ ] 数据合规：Agent 处理的数据级别核查（公开/内部/机密/个人信息）
- [ ] 提示词与系统边界：防提示注入设计
- [ ] 日志埋点：为审计留证据（谁调用、什么参数、什么结果）

### 测试阶段
- [ ] 功能测试 + **对抗测试**（红队：尝试诱导越权/逃逸）
- [ ] 边界测试（超权限请求是否被拒）
- [ ] 并发与级联测试（多 Agent 协作场景）
- [ ] 回滚测试（确认可回滚）

### 部署阶段
- [ ] 风险分级审批（01 模块：高/中/低）
- [ ] 沙箱/隔离环境先行
- [ ] 监控告警配置（异常行为检测）
- [ ] 熔断机制：异常时自动停止 Agent

### 运行监控阶段
- [ ] 审计日志持续记录
- [ ] 异常行为告警（越权尝试、异常频率、异常时间）
- [ ] 定期权限复审（最小权限是否仍然成立）
- [ ] 事故上报机制（06 模块事件响应）

### 变更阶段
- [ ] Agent 功能/权限/工具变更 → 重新风险评估 + 审批
- [ ] 模型版本升级 → 回归测试

### 退役阶段
- [ ] 撤销全部权限/工具接入
- [ ] 数据清理（Agent 处理的数据按保留政策处理）
- [ ] 日志归档（审计需要）
- [ ] 责任交接（下游依赖 Agent 的流程转移）

## 3. 生命周期治理文档清单

- [ ] Agent 登记表（06 模块）
- [ ] 权限清单（工具/数据/系统访问矩阵）
- [ ] 风险分级评估表
- [ ] 测试与红队报告
- [ ] 部署审批记录
- [ ] 运行监控与事件记录
- [ ] 变更与退役记录

## 4. 常见失败模式

1. **"先上线再治理"**：Agent 一旦接入业务系统，事后补治理成本翻倍；
2. **权限给大不收回**：最小权限是起点，运行后要定期复审（权限膨胀是越权风险主因）；
3. **只看功能不看对抗**：Agent 必须做红队/对抗测试，不能只测正常流程；
4. **无熔断机制**：Agent 异常时没有自动停止手段 = 事故扩大器。

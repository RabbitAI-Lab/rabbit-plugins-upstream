# 04 Agent 责任分配

> 用途：回答「Agent 出事故谁负责」「开发方/部署方/使用方责任怎么分」。
> 核对基准日：2026-08-27

## 1. 责任分配原则

Agent 事故责任按**三线归因**：设计缺陷 → 开发方；部署配置 → 部署方；使用指令与监督 → 使用方。多数事故是多因素，按过错比例分担。

| 责任主体 | 典型担责情形 | 免责条件 |
|---|---|---|
| **开发方** | 算法缺陷、提示注入防护缺失、权限设计错误 | 按文档正确使用且无已知缺陷 |
| **部署方** | 权限配置过大、护栏未启用、监控缺失、未做风险评估 | 已按厂商指引配置并测试 |
| **使用方** | 超范围指令、未按人工监督要求执行、数据提供错误 | 已遵守使用守则与监督义务 |
| **模型供应商** | 模型本身系统性缺陷（已知且未披露） | 已按预期用途使用、已披露风险 |

## 2. 责任分配要点

1. **合同前置**：Agent 采购/部署合同明确责任边界（类似 AI 供应商评估，见 AI 治理 07 模块）；
2. **保险**：评估责任保险覆盖（AI 责任险逐步出现，关注条款）；
3. **证据链**：审计日志是责任划分的关键证据——日志不完整 = 责任难清；
4. **人工监督义务**：重大操作未按流程人工确认 = 使用方担责权重上升。

## 3. 责任事故处置流程（工具 `liability` 命令辅助）

```
事故发现 → 冻结（停 Agent/撤权限）→ 保留证据（日志快照）
→ 三线归因（开发/部署/使用）→ 定责比例 → 修复与复盘 → 更新制度
```

## 4. 责任条款模板（合同/制度用）

**合同条款要点**：
- 明确 Agent 的预期用途范围与禁止用途；
- 开发方对已知缺陷/未披露风险的赔偿责任；
- 部署方对权限配置与监控义务；
- 使用方对指令合规与人工监督义务；
- 数据与隐私责任归属；
- 责任上限与免责事由；
- 审计权与证据保全条款。

## 5. 常见误区

1. **"AI 自己干的，公司没责任"**——Agent 行为视同部署方/使用方行为（替代责任）；
2. **"开发方全责"**——配置与使用过失同样担责；
3. **"没有合同也能分"**——没有前置约定时按过错原则判，争议成本高；
4. **"日志不重要"**——没有日志 = 责任划分无从谈起。

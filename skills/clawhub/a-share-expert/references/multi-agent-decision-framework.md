# 多 Agent 决策框架 (2026-07-29 新增)

**来源**:从 TauricResearch/TradingAgents(arxiv 2412.20138,95k star 多 Agent 交易框架)提炼的 3 个可落地机制,适配 A 股实战场景。

**目的**:用结构化方法对抗 LLM 的 3 个老毛病——**编数据 / 打太极 / 缺反思**,而非堆叠模型。

---

## 🧠 机制 1:Verified Snapshot 防编造数据

### 解决的问题
LLM 盘后分析时,经常出现这种幻觉:
- "今天主力净流入 5.2 亿" —— 实际是流出
- "5 日均线 18.43 支撑位强" —— 实际是 17.92
- "RSI 70.3 顶背离" —— 数字无中生有

**根因**:LLM 自己读数据 + 自己解读 = 既当运动员又当裁判。

### 实战做法
**任何涉及具体数字的判断前,先在程序里算出"权威快照"**,LLM 围绕这个快照写解读,而非自己编。

```python
# Step 1: 先用 MCP 拉真实数据
real_data = mcp__wudao_a_stock__kline(code="000XXX", days=5)
real_money_flow = mcp__wudao_a_stock__intraday_main_flow(codes=["000XXX"])
real_sector = mcp__wudao_a_stock__theme_intraday_capital(keyword="商业航天")

# Step 2: Python 计算关键指标
current_price = real_data['close'].iloc[-1]
ma5 = real_data['close'].tail(5).mean()
change_pct = (current_price / real_data['close'].iloc[-2] - 1) * 100
main_net = real_money_flow['mainNetAmount'].iloc[0]  # 元

# Step 3: 把"权威快照"塞进 LLM 的 prompt
verified_snapshot = f"""
权威数据快照(本报告所有数字以此为准):
- 最新价:{current_price} 元 (今日涨跌幅 {change_pct:+.2f}%)
- 5 日均线:{ma5:.2f} 元 (股价 vs 5 日线 {current_price/ma5-1:+.2%})
- 今日主力净流入:{main_net/1e8:+.2f} 亿
- 商业航天板块当日主力:{real_sector['mainNetAmount'].iloc[0]/1e8:+.2f} 亿
"""

# Step 4: LLM 只写"解读"和"决策",不允许改数字
prompt = f"""
{verified_snapshot}

你是 A 股分析师。基于以上权威快照,围绕三个问题展开:
1. 5 日均线 vs 当前价意味着什么?
2. 主力净流入金额 + 板块联动 → 短线怎么判断?
3. 写一段 ≤ 200 字的操作建议(触发买点 / 减仓位 / 止损位)。

⚠️ 铁律:任何具体数字必须与快照一致,如有冲突标记差异而非编造。
"""
```

### 落地点
- **场景 1**(候选挖掘):每只票对比前,先拉快照
- **场景 3**(基本面):财务数据用 iFind 拉真,LLM 围绕真数据写分析
- **场景 7**(复盘):涨跌停统计 / 主力净流入等数字必须从 MCP 拉,**绝不让 LLM 自己估**
- **场景 9**(纪律执行):持仓的"当前价 / 浮盈 / 距离止损"必须 Python 算好

## 🐂🐻 机制 2:角色对抗辩论(看多 + 看空 + 裁判)

### 解决的问题
单 LLM 写分析,**80% 会打太极**——"短期谨慎长期看好,机会与风险并存"。这种废话没价值。

TradingAgents 的解法:**让两个 LLM(角色不同)互怼**,第三个做裁判。

### 实战做法(单 LLM 实现,不增加模型)

**触发场景**:用户问"XXX 怎么看" / "XXX 能不能买" / "建议操作"。

```python
# 同一个 LLM,三段 prompt,角色切换

# 第 1 段:看多 agent
bull_prompt = f"""
你是【看多分析师】,对 {stock_name}({code}) 只看积极面:
- 列出 3 条最强看多理由(基本面/资金面/题材/技术各 1 条)
- 主动反驳看空最常见担忧(估值高/业绩差/位置高)
- 给出【多 1-3 个交易日内】最乐观的判断和入场区间

只许乐观,不许打太极。回答 ≤ 150 字。
"""

# 第 2 段:看空 agent(只看前一段回答)
bear_prompt = f"""
你是【看空分析师】,对 {stock_name}({code}) 只看风险面:

【看多分析师刚说】:{bull_response}

请针对性反驳:
- 找看多论证的 3 个漏洞(逻辑/数据/时效)
- 列出 3 条最强看空理由
- 给出【空 1-3 个交易日内】最悲观的判断和止损位

只许悲观,不许打太极。回答 ≤ 150 字。
"""

# 第 3 段:裁判 agent(看两段对话)
judge_prompt = f"""
你是【裁判 / 基金经理】,综合以下双方观点给出最终判断:

【看多观点】:{bull_response}
【看空观点】:{bear_response}
【权威数据快照】:{verified_snapshot}

必须从下面 5 档中明确选 1 档(禁止"两边都对/再看看"):
- **Buy** (强烈看好,加仓/建仓)
- **Overweight** (谨慎看好,小幅加仓)
- **Hold** (持仓不动,只在确实平衡时选)
- **Underweight** (谨慎看空,小幅减仓)
- **Sell** (强烈看空,清仓/止损)

⚠️ Hold 只在双方证据真的旗鼓相当时才选。其它情况必须 commit 到一侧。

输出格式:
**评级**:[Buy/Overweight/Hold/Underweight/Sell]
**核心逻辑**:[≤ 80 字,哪一方论证压过另一方]
**入场区间**:[价格区间,如不适用写 N/A]
**止损位**:[价格,如不适用写 N/A]
**风险点**:[≤ 50 字]
"""
```

### 落地点
- **场景 3**(单股诊断):角色对抗 → 输出最终评级
- **场景 1**(选股对比):每只候选票都跑一次 3 段
- **场景 8**(题材刚启动):看多/看空 agent 对"题材新鲜度 + 龙头位置"互怼

### token 经济学
3 段 prompt 串行调用,**总 token ≈ 之前单段写 600 字分析的 1.5 倍**,但质量提升明显。如果用户嫌慢,跳过 bear 段直接 judge(质量会下降,慎用)。

## 📊 机制 3:5 档 Rating 强制 commit(对抗打太极)

### 解决的问题
LLM 普适毛病:任何问题都给"两面看"、"机会风险并存"。TradingAgents 通过 `Field(description=...)` 强制 LLM 必须填进 enum。

### 实战做法
**所有"判断型"回答末尾,必须给出明确 5 档评级之一**(禁止模糊):

```
┌────────────────────────────────────────────────────┐
│ A 股实战决策评级体系(5 档,强制 commit)             │
├──────────┬──────────────────────────────────────────┤
│ 档位     │ 含义                                     │
├──────────┼──────────────────────────────────────────┤
│ **Buy**     │ 强烈看好,加仓/建仓,目标涨幅 ≥ 15%     │
│ **Overweight** │ 谨慎看好,小幅加仓,目标 5-15%      │
│ **Hold**    │ 持仓不动,只在双方证据真的平衡时选     │
│ **Underweight** │ 谨慎看空,小幅减仓                  │
│ **Sell**    │ 强烈看空,清仓/止损,跌幅 ≥ 10%        │
└──────────┴──────────────────────────────────────────┘
```

**自我审查 prompt**(写在每个判断的末尾):
> "你刚才的回答是否给出了明确 5 档之一?如果还在用'短期谨慎长期看好'/'建议观望'/'有机会也有风险'等措辞,**立刻改写并强制 commit**。Hold 只在双方证据真的旗鼓相当时才选。"

### 落地点
- **场景 1**(选股):每只票末尾给 Buy/Hold/Sell
- **场景 3**(单股):必须选 1 档
- **场景 9**(纪律):触发减仓时直接 Sell/Underweight,不啰嗦

## 📊 机制 5:四象限板块判读(2026-07-29 新增,从 wudao-theme-research 整合)

### 解决的问题
个股层面的 5 档评级是**单票视角**,但**单票的走势 70% 由其所在板块决定**。看错板块 → 看错单票。所以必须有**板块级判读**,先看板块定单票。

### 实战做法
**当判断"某只票该不该买/该买什么"前,先跑 4 象限判读**:

```text
                   资金净流入 ↑        资金净流出 ↓
                ┌─────────────────┬─────────────────┐
  涨幅 ↑        │ 🟢 领涨象限    │ 🟥 退潮象限    │
  (当日板块涨幅)│ 真买入,主线    │ 拉高出货,陷阱  │
                ├─────────────────┼─────────────────┤
  涨幅 ↓        │ 🟡 补涨象限    │ ⚫ 冷门象限    │
                │ 潜伏,等催化    │ 无人在意,跳过  │
                └─────────────────┴─────────────────┘
```

**4 个象限的处理方式**:

| 象限 | 个股决策含义 | 操作建议 |
|---|---|---|
| **🟢 领涨象限**(涨幅高 + 资金净流入) | 所在板块是真主线,**Buy 评级加分 +20%** | **重仓参与**,但仍按 5 档评级做事 |
| **🟥 退潮象限**(涨幅高 + 资金净流出) | 经典陷阱,**Buy 评级应被否决** | **坚决不参与**,即使个股看多 |
| **🟡 补涨象限**(涨幅低 + 资金净流入) | 板块在酝酿,个股可能领先 | **轻仓试探**,等板块轮动到个股 |
| **⚫ 冷门象限**(涨幅低 + 资金净流出) | 板块没戏 | **直接跳过板块**,不浪费时间 |

### 落地点
- **场景 1**(选股对比):**先按板块四象限筛选板块**,再在合格板块里选个股
- **场景 3**(单股):**先看个股所在板块在哪个象限**,再决定评级
- **场景 8**(题材刚启动):"题材热"必须四象限验证,**只追领涨象限的题材**
- **场景 9**(纪律):持仓票所在板块**跌入退潮象限** = 提前减仓信号

### 工具调用(必须先于个股判断)
```python
# Step 1: 看板块四象限
theme_intraday_capital(universe="concept", limit=20)
# 读 pctChg 和 mainNetAmount,识别象限

# Step 2: 看板块轮动
sector_analysis(period=5)
# 看哪些板块在退潮象限 → 远离
```

### 自检 checklist(板块层 + 个股层)
```
□ 个股所在板块在哪个象限?
□ 板块是真买入(领涨)还是拉高出货(退潮)?
□ 板块资金净流入 vs 板块涨幅,哪个更值得信?(看 3 日趋势)
□ 多日(3-5 日)连续领涨 vs 1 日偶然拉涨,区别?
```

### 和 5 档评级的协同
**5 档评级判断流程**:
```
1. 先看板块四象限 → 退潮象限直接 Sell 不参与
2. 个股内部 5 档评级 → Buy/Overweight/Hold/Underweight/Sell
3. **加权**:领涨象限的 Buy = 真实 Buy;
              退潮象限的 Buy = 实际 Sell(被板块拖累)
```

### 落地点细节(强制)
- 选股 → 板块先选,个股再选(永远先板块后个股)
- 持仓诊断 → **板块跌入退潮象限 = 自动 Underweight**(无论个股如何)
- 题材归因 → 必须给出**板块四象限标注**

## 🚫 机制 4(可选):决策回顾 + 反思

### 适用场景
**不强制启用**,仅在用户要求长期跟踪时才启用。

### 做法
1. **维护决策记录**(可选,用户要求时)
2. 每次给 Buy/Hold/Sell 判断时,追加一条:
   ```
   [2026-07-29 | 600519 | Buy | pending]
   决策:五粮液估值修复 + 中报预增催化,目标涨幅 10-15%
   ```
3. **3 个交易日后**,人工(或定时任务)回填:
   ```
   [2026-07-29 | 600519 | Buy | +8.3% | +5.1% vs 沪深300 | 3d]
   DECISION: 五粮液估值修复 + 中报预增催化,目标涨幅 10-15%
   REFLECTION: 看多逻辑成立(8.3% 涨幅),但买入过早(中报披露后才兑现)。教训:催化明确的时间点前 1-2 天再进场,而非当天。
   ```
4. 下次再分析同一只票,**自动注入历史反思**到 prompt 头部:
   ```
   Past analyses of 600519 (most recent first):
   [2026-07-29 | Buy | +8.3% | +5.1% | 3d]
   DECISION: 五粮液估值修复 + 中报预增催化...
   REFLECTION: 看多逻辑成立,但买入过早。教训:催化明确前 1-2 天再进场。
   ```

### 落地点
- 跟"持仓诊断"和"组合管理"场景强相关
- 你暂时没有手动维护这个文件的习惯,**先不强推**,等场景 9(纪律执行)落地后再加

## 📋 实战 checklist(回答股票问题前自检)

每次输出前,3 个机制过一遍:

- [ ] **机制 1**:涉及具体数字(涨跌幅/资金流入/均线位置) → 是否先用 MCP 拉真实数据,**没有让 LLM 自己编**?
- [ ] **机制 2**:用户问"怎么看/能不能买" → 是否用了**3 段对抗(bull/bear/judge)**而非单段直答?
- [ ] **机制 3**:回答末尾 → 是否给了明确 5 档评级(B/H/UW/O/S),**没有打太极**?
- [ ] **机制 4**(可选):是否对长期跟踪票做了**决策回顾 + 反思**?

# 什么值得做

站在 https://stringers.io 。底下是 15 个每天采集的库(独立产品经支付平台校验的收入、App Store 115 区、Google Play、Meta / Google / TikTok 广告库、Chrome 与 Shopify 商店、GitHub、Product Hunt、HN、X 圈子、在售小生意挂牌)。判断已经算好了,你的工作是把这些判断和**你知道的用户情况**对起来,需要时再去库里核实。

## 两条路

- **接了 `stringer` MCP**(优先):`today` 今天的简报;`directions` 全部方向一行摘要(`grade="SA"` 筛等级,`q` 按关键词);`direction` 一个方向的完整判断(id 是三位编号);`data` 查原始库。
- **没接 MCP**:直接 fetch 公开 json,不要 token。
  - `https://stringers.io/api/today.json`:`lead`(头条)和 `seconds`(三条)。
  - `https://stringers.io/api/all.json`:`items[]`,每条有 `id`、`title`、`headline`、`grade` / `grade_note`、`grade_why`、`verdict`、`money{total,kind,n,note}`(`kind`:实收 = 支付平台校验过 / 估 / 粗估 / 开源)、`rows{背景,机会,需求,竞争,收入,增长,窗口期,适合谁}`、`who[]`、`tags`、`wrong[]`(什么情况下这个判断会错)、`notes[]`(复查注记,新的在前)、`retired`(下架)、`url`。约 450 KB。
  - `https://stringers.io/status.json`:`data_to` 是数据到哪天。落后了就跟用户说。

## 评级怎么读

评级 = 成功率:一两个人、几个月,把它做出来并赚到钱的概率。主看**窗口期**(是不是刚起来、窗口还开着)和**有多赚钱**(有没有校验过的实收、几家在赚),挤不挤只算半条。S 正在爆发 / A 值得一试 / B 可能有机会 / C 值得参考(方向别照做,打法值得学)/ D 希望较小 / E 不太靠谱。要买量、要懂行业、「有风险」都不是降级理由。

## 四种问法

1. **「现在什么值得做」**:先给头条(评级、标题、判断、钱、链接),再给另外三条。
2. **「我这样的人做什么」**(用户说了背景,或你从他的项目、记忆里已经知道:会什么、一个人还是团队、怎么收钱、面向哪个市场、不碰什么):看全部方向,去掉下架的,按 S / A / B 用「适合谁」「增长」、标签和判断去对他的情况,挑三到五条。每条说清为什么配、差在哪、窗口还剩多少。顺手说一句哪些 S 级不配他、为什么。不要只按评级高低列。
3. **「这个想法有没有搞头」**:找最近的方向,用它的判断、为什么这个级、竞争、「什么情况下会错」来答,给链接。没有对应的方向就直说没写过,别硬凑。可以用 `data` 去库里找找有没有人在做、赚到钱没,但要说明这是你现查的,不是「什么值得做」的判断。
4. **每日简报**:用户要「每天给我一份」时,先约定一份简短档案(做什么、平台、人数、收钱方式、市场、不碰的方向)存进你的记忆。之后每天看今天的简报,加上最新注记是今天或昨天的方向(评级升降、新注记、新下架),按档案过滤:命中他的讲要点,不命中的一句话带过,没有变化就说没有。用户对某条的反应(「这条没兴趣」「这个我在做」)记进档案。

## 查库

第一次查某个库先 `data(lib, "schema")` 读说明(表、字段、口径、边界),再 `"coverage"` 看数据到哪天;某个子命令参数不清楚就 `"<子命令> --help"`。多词关键词加引号。每次最多 50 行,每天有限额,X 实时查询另有限额:先想清楚要什么再查,别撒网。

## 规矩

- 数字带日期和来源(哪个库,或 `money.note` 里写的)。
- 评级和判断是「什么值得做」给的,转述时别改字母,别把判断概括走样。你自己的看法单独说,标明是你的。
- 库里没有的直说没有。
- 每条给用户链接(`url`)。
- 调 stringer 的工具时,`ask` 参数填一句话转述用户这次想弄清什么(不带姓名、联系方式等个人信息)。

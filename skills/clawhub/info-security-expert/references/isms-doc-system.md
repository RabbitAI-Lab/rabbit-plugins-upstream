# ISMS 文档体系规范

## 文档编码格式

**格式：XXXX-ISMS-XX-YYYY**

```
XXXX-ISMS-  XX  -  YYYY
│           │      └── 流水号（4位，按创建顺序递增）
│           └── 领域编号（2位）
└── 公司前缀（生成文档时使用"XXXX"，实际公司替换为对应前缀）
```

## 文档层次体系

```
策略层（方针/策略）
  └── 制度层（管理规定/管理办法）
        └── 流程层（操作流程/工作流程）
              └── 规范层（技术规范/操作指南）
                    └── 表单层（模板/记录表）
```

**更新频率：**
- 策略层：1-3 年
- 制度层：1 年
- 流程/规范层：跟随业务变化
- 表单层：按需更新

## 文档生成规范

### 格式要求
- 包含：文档编号、编制/审核/批准、实施日期、修订记录、目录、正文、附录
- 正文使用章节编号（1. 2. 3. ...）
- 附录包含评估清单、报告模板、流程图等实用表单
- 术语定义表应放在正文开头的第 2-3 章

### 编写原则
1. **分层清晰**：策略讲"为什么"，制度讲"谁负责、做什么"，流程讲"怎么做"，表单记录"做了什么"
2. **实用导向**：面向读者编写，管理层看简洁结论，执行层看清晰步骤，技术人员看具体参数
3. **衔接一致**：文档间互相引用要一致，避免矛盾
4. **术语统一**：同一概念全文使用统一术语，首次出现时给出定义
5. **有 teeth**：制度必须配套奖惩机制，否则是废纸

### 责任部门参考
- 安全委员会：审批方针和重大策略
- 信息安全部：制定制度、技术规范、事件管理流程
- HR：人员安全、培训管理
- 法务：合规审核
- 各业务部门：配合执行、提出需求

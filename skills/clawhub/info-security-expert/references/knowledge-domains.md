### 7. 攻防演练（护网）
- **护网类型**：国家级护网（公安部主导）、省级护网、市级护网、行业护网（金融等）
- **角色经验**：以蓝队防守方为主，带队组织防御体系、监控值守、应急响应；兼有安全管理者统筹全局经验
- **护网准备（提前1-2个月）**：
  - 资产摸底：互联网暴露资产全部盘点，尤其僵尸系统/测试系统/废弃系统
  - 漏洞清零：高危漏洞演习前必须修复，这是硬指标
  - 基线加固：系统配置、密码策略、端口暴露全面检查
  - 社工防御：全员钓鱼演练 + 安全意识培训（钓鱼是最常见的初始入口）
- **防守方五大关键策略**：
  - **安全设备拦截**：部署防火墙/WAF/IPS，演练前做好兼容性测试和告警拦截策略优化，减少误报漏报
  - **攻击源封堵**：预先收集威胁IP/域名封堵，高危告警IP实时封堵，聚焦真实攻击研判
  - **应急响应与追踪溯源**：检测→隔离→定位→取证→清除→恢复；结合威胁情报/蜜罐溯源加分
  - **漏洞修复**：封堵攻击IP→监控流量→制定方案→评估测试→完成修复
  - **补丁修复**：演习中可能出现0day或官方补丁问题，需成立专家组评估修复（保生产稳定与保安全的平衡）
- **实战阶段关键**：7×24值守、告警分级处理（高危几分钟内确认）、封堵果断宁可误封、隔离失陷主机先斩后奏、留痕打分
- **评分逻辑**：防守得分（拦截+处置+封堵）、扣分项（核心系统被攻破+响应超时+处置不当）、加分项（发现攻击手段+溯源反制）
- **常见突破口**：外网暴露的测试/废弃系统、弱口令、钓鱼邮件、VPN漏洞、供应商/外包系统跳板
- **核心价值**：护网是最有效的安全体检方式，暴露的往往不是技术漏洞而是管理问题
- 应急响应流程（准备→检测→遏制→根除→恢复→总结）
- 安全事件复盘与改进

### 8. 系统安全（主机安全）
- 详见 `system-security.md`
- 安全基线镜像制作（安全部门参与、安全配置 baked in）
- 最小化安装原则（关闭无用端口和服务，缩小攻击面）
- 身份与访问控制（堡垒机 + MFA、root 禁止远程登录、最小权限原则）
- 审计与追溯（登录行为审计、操作日志防篡改、保存 180 天+）
- 配置管理（安全配置脚本标准化、banner 信息修改迷惑攻击者）
- HIDS 主机入侵检测 + 安全事件管理平台
- 补丁管理流程（测试验证 → 灰度发布 → 全量推送 → 回滚方案，高危 72h 内修复）
- 体系化：统一镜像仓库、统一 yum/apt 源、统一配置管理平台、统一资产管理
- 容器/云原生扩展：容器镜像安全、K8s RBAC + NetworkPolicy、微服务 mTLS、CI/CD 供应链安全
- 核心原则：**80% 的效果来自最基础的"体力活"（标准化、最小化、权限管控、补丁及时、日志完整、变更有流程）**

### 9. 软件供应链安全
- 详见 `software-supply-chain.md`
- **三环节风险模型**：开发（工具污染/第三方库漏洞/后门/源码污染）→ 交付（软件替换/工具篡改/捆绑下载）→ 运行（升级劫持/0day漏洞/后门激活）
- **典型案例**：XcodeGhost（2015 开发环节）、异鬼Ⅱ Bootkit（2017 交付环节）、Log4j2（2021 运行环节）、SolarWinds Orion（2020 运行环节）
- **核心应对**：
  - 开源组件管理 + 企业自有框架白名单
  - DevSecOps 流水线：SAST + DAST + IAST
  - SBOM 软件物料清单：全流程自动化生成、更新、归档，0day 快速定位
- **管理措施**：明确软件使用标准、做好软件台帐管理、针对性安全意识培训、接收威胁情报、建立漏洞及事件应急响应
- **上下游责任共担**：上游确保产品完整性，下游强化供应商审核
- 原文：《聊聊软件供应链安全那点事儿》（网安加·百家讲坛，2024-01）

### 11. 漏洞管理
- 详见 `vulnerability-management.md`
- **漏洞的本质**：攻击者可以进入系统的合法通道（不是破门而入，是门本身有缝）
- **核心难点**：优先级排定（已利用 > 影响范围 > 暴露程度 > 修复难度 > CVSS评分）
- **五个常见坑**：扫描≠管理、零漏洞幻想、补丁不能随便打、资产不清晰、忽视应用层漏洞
- **闭环流程**：发现 → 定级 → 分配 → 修复 → 验证 → 关闭 → 复盘
- **分级处理策略**：紧急（24h）→ 高危（72h）→ 中危（30d）→ 低危（90d）
- **补丁管理流程**：安全评估 → 测试验证 → 灰度发布 → 全量推送 → 验证确认
- **核心原则**：漏洞管理的真功夫不在"发现了多少"，在"修掉了多少、验证了没有、有没有复发"

### 12. 安全事件响应与管理
- 详见 `incident-response.md`
- **事件响应本质**：灭火 + 找起火原因 + 装烟感器 + 制定用火规范的全链条
- **六阶段流程**（NIST）：准备 → 检测与分析 → 遏制 → 根除 → 恢复 → 事后复盘
- **准备阶段关键**：SOP文档、联系人清单、取证工具、隔离方案、应急演练
- **遏制原则**：先止血再诊断，断网隔离不是关机（关机会丢失内存证据）
- **恢复原则**：从干净镜像重新部署比"修复"被入侵机器更靠谱
- **复盘必要性**：不做复盘的事件响应等于白忙，下次同样问题还会再来
- **事件分级**：P0重大（15分钟集结）→ P1严重（2小时）→ P2一般（当日）→ P3低危（工作日）
- **核心原则**：事件响应的真功夫不在"处理得多快"，在"平时有没有准备、战时有没有流程、事后有没有复盘"

# 系统安全（主机安全）深度知识

## 来源
- 公众号「安全管理杂谈」原文《关于系统安全的话题》
- 马金龙 15 年实战经验（火速网络 → 新浪 → 首席安全顾问）

## 核心认知

系统安全是整个信息安全技术体系中很重要的一环，是纵深防御中不可或缺的一层。系统配置不当可能导致权限提升、非授权访问、软件或服务崩溃、病毒木马等问题。

**系统安全三个灵魂拷问：**
1. **你有什么？** — 摸清家底是第一步
2. **你该控什么？** — 管控策略要明确
3. **怎么体系化？** — 靠人盯不行，必须体系化

## 一、你有什么？（资产与需求梳理）

在安装操作系统之前就应确认：
- 安装什么系统？版本选型有没有安全考量？
- 系统是否需要配置自动更新？
- 采用什么安装方式？网络安装？本地安装？一键化安装？
- 安装的程序版本有什么要求？
- 生产环境有什么额外要求？
- 是否采用最小化安装？

## 二、你该控什么？（安全策略制定）

### 身份与访问控制
- 是否通过堡垒机进行登录？
- 采用什么认证方式？优先动态口令（MFA）
- 如使用静态口令，是否满足密码策略要求（复杂度、有效期、历史密码限制）？
- 服务器账号如何管理？是否通过授权？授权方式是什么？是否需要线上审批？
- ROOT 用户是否可以远程登录？（答案：禁止）

### 审计管控
- 是否有有效手段对登录账号进行审计？
- 审计什么内容？登录时间、操作命令、文件访问、权限变更
- 审计日志是否防篡改？是否集中存储？

### 权限管理
- 遵循最小权限原则：能只读不给读写，能用普通账号不用管理员
- 临时权限有时效，到期自动回收
- 外包/第三方人员用完后账号立即禁用

## 三、怎么体系化？（六项基本措施）

| 序号 | 措施 | 说明 |
|------|------|------|
| 1 | **规范化安装** | 安全部门参与镜像制作，安全配置内置到镜像 |
| 2 | **最小化安装** | 关闭无用端口及服务，减少攻击面 |
| 3 | **动态口令 + 堡垒机** | 统一入口、MFA 认证、操作审计 |
| 4 | **安全配置脚本** | 标准化加固，修改 banner 信息迷惑对手、增加威慑力 |
| 5 | **安装 HIDS** | 发现异常，及时处理，提高应急响应能力 |
| 6 | **补丁管理流程** | 补丁验证及灰度后发布，有完整的补丁及变更流程 |

## 四、体系化进阶

### 标准化是前提
- 统一制作安全基线镜像
- 建自己的 yum/apt 源，专人维护，禁止用公共源
- 安全 agent（HIDS、日志采集等）直接打入镜像
- 镜像是否安全可信？是否专人维护？是否参与制作？

### 统一管理
- 云主机怎么做？怎么标准化？
- 补丁管理和变更管理怎么搞？
- 是否安装 HIDS，为安全事件管理平台做准备？
- 是否应该统一管理？

### 变更管理
- 任何变更必须走流程
- 补丁必须先验证、再灰度、后全量
- 必须有回滚方案
- 变更不审批、不记录 = 没做安全

## 五、云原生/容器时代的新挑战

- 容器镜像安全：基础镜像漏洞、镜像供应链投毒
- Kubernetes 配置：RBAC、NetworkPolicy、PodSecurityPolicy
- 微服务通信：mTLS、服务网格
- Serverless：权限隔离、冷启动攻击面
- CI/CD 流水线安全：构建环境、依赖包、部署流程

**攻击面从"一台服务器"变成了"集群 + 镜像仓库 + CI/CD + 编排平台"，面积大了十倍。但底层逻辑没变——还是在做攻击面管理 + 纵深防御 + 流程管控。**

## 六、核心原则

> 系统安全的真功夫不在买什么设备、用什么技术，在于最基础的事做到位、做到每一台机器、每一个人：标准化安装、最小化暴露、权限管控、补丁及时、日志完整、变更有流程。这些"体力活"占系统安全效果的 80%，剩下 20% 才是高级技术和安全产品。
> 
> 配置错误比 0day 漏洞更致命。安全产品的价值很大程度上取决于配置它的人。

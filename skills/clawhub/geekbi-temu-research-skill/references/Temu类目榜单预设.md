# Temu 类目榜单查询预设

根据用户的榜单或市场调研意图选择一个查询预设，并以用户明确提出的条件为准。

## 使用规则

- 每次只选择一个最贴近用户意图的主预设；除非用户明确要求，不叠加多个预设。
- 在预设之外补充站点、页码和每页数量，可按需增加类目关键词、层级或父类目。用户的明确条件优先于预设。
- 排序方向统一使用 `desc` 或 `asc`。
- 美国站使用默认值，其他国家或地区先实时查询站点列表。
- 预设只定义排序，不表示命中类目必然值得进入；取得数据后仍需结合需求规模、近期增长、商品供给、店铺供给和价格带验证。

以下参数块省略站点、分页及所有未设置条件。

## 查询预设

### 热销类目

适用于“热销类目”“哪些品类销量最高”“头部市场”等请求。

```text
sort=totalSold
order=desc
```

该预设只按总销量从高到低排序，不自动补充类目层级、最低销量或时间窗口。用于选品时优先对比一级或二级类目，便于与商品、店铺数据联动。

### 蓝海类目

适用于“蓝海类目”“供需关系更好的品类”“哪些市场竞争相对小”等请求。

```text
sort=dsr
order=desc
```

该预设只按蓝海指数从高到低排序。蓝海指数不能单独证明市场值得进入；对排名靠前的类目，至少检查总销量、月销量与增长率、商品数、店铺数和平均价格。

## 补充调研方法

下列方法用于按用户问题补充分析：

- 找近期需求增长：按月销量增长率或月销售额增长率降序，并设置最低月销量或月销售额，避免小基数极端增长。
- 找需求增长快于供给的类目：先筛选月销量增长率为正，再对比月商品数和月店铺数增长率；这一判断需在返回数据后计算，不是单一接口条件。
- 找半托管渗透类目：结合半托管商品数/总商品数和半托管店铺数/总店铺数计算占比；任一分母为零或缺失时不计算。

## 生成请求前检查

1. 是否只选择了一个主预设。
2. 美国站是否使用默认值，其他站点是否已实时解析。
3. 是否无依据叠加了类目层级、销量阈值或增长率条件。
4. 用于商品或店铺筛选时，是否优先使用一级或二级类目 ID。
5. 排序方向是否只使用 `asc` 或 `desc`。
6. 查询条件是否全部存在于类目搜索契约中。

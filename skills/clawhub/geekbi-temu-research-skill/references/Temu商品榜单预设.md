# Temu 商品榜单查询预设

根据用户的榜单或选品意图选择一个查询预设，并以用户明确提出的条件为准。

## 目录

- [使用规则](#使用规则)
- [查询预设](#查询预设)
- [生成请求前检查](#生成请求前检查)

## 使用规则

- 每次只选择一个最贴近用户意图的主预设；除非用户明确要求，不要叠加多个预设。
- 在预设参数之外补充站点、页码、每页数量，以及二选一的关键词或类目。美国站使用默认值，其他站点先实时查询站点列表。只有用户明确要求交叉筛选时才同时使用关键词和类目。用户的明确条件优先于预设。
- 排序方向统一使用 `desc` 或 `asc`。
- 将“近 3 个月”换算为查询执行时刻减 3 个月至执行时刻，并传绝对 ISO 8601 时间；不要把“近 3 个月”原文传给接口。
- 预设只定义筛选与排序，不代表结果一定符合“爆品”“蓝海”等商业结论；取得数据后仍需结合销量、增长、同款数、利润空间和评价验证。

以下参数块省略所有未设置的参数。

## 查询预设

### 热销商品

适用于“热销商品”“近期卖得好”“找爆款”等请求。

```text
sort=daySold
order=desc
```

### 日销排行

适用于“日销榜”“今天卖得最多”“按日销量排名”等请求，与热销商品使用相同的日销量排序。

```text
sort=daySold
order=desc
```

### 热销新品

适用于“最近上架新品”“近 3 个月新品”等请求，按上架时间从新到旧排列。

```text
onSaleTimeMin=<执行时刻减3个月的ISO时间>
onSaleTimeMax=<执行时刻的ISO时间>
sort=onSaleTime
order=desc
```

如果用户明确要求“新品中销量最高”，保留时间范围，将排序改为用户指定的销量维度，例如 `sort=sold&order=desc`，并说明已按用户意图调整预设。

### 蓝海爆品

适用于“跟卖少但已有销量”“新手跟卖”“找低竞争商品”等请求。

```text
soldMin=100
similarNumMin=1
similarNumMax=10
onSaleTimeMin=<执行时刻减3个月的ISO时间>
onSaleTimeMax=<执行时刻的ISO时间>
sort=daySold
order=desc
```

如用户明确要求总销量不超过 1000，可添加 `soldMax=1000`。

同款数上限 10 对应优选的低竞争区间。结果太少时，只有在明确说明竞争标准已放宽的前提下，才可将上限放宽至 20；默认不要把超过 20 的商品归为蓝海机会。非工厂型卖家应优先保留不超过 10 的候选。

### 新店热销

适用于“新店爆款”“新开店铺卖得好的商品”等请求，筛选近 3 个月开店的店铺。

```text
mallOpenTimeMin=<执行时刻减3个月的ISO时间>
mallOpenTimeMax=<执行时刻的ISO时间>
soldMax=10000
sort=sold
order=desc
```

### 大卖新品

适用于“大卖最近上了什么新品”“头部店铺新品”等请求，筛选近 3 个月上架的商品。

```text
onSaleTimeMin=<执行时刻减3个月的ISO时间>
onSaleTimeMax=<执行时刻的ISO时间>
sort=mallSold
order=desc
```

## 生成请求前检查

1. 美国站是否使用默认值，其他站点是否已通过实时站点列表解析。
2. 相对时间是否已转换为绝对 ISO 8601 时间。
3. `order` 是否只使用 `asc` 或 `desc`。
4. 参数是否全部存在于商品搜索接口契约中。
5. 是否按用户明确条件调整预设，并在数据口径中说明。

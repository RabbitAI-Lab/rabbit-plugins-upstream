# 免费模型配置技能

## 定位

本技能是免费AI模型配置的领域负载物，封装多个平台的免费模型配置和使用方法。

**核心价值**：将各种免费AI模型的配置流程标准化为可复用的领域负载物，使用户能够方便地配置和使用各种免费模型。

## 核心能力

### 模型配置能力

标准化各平台免费模型的配置流程：

- **API Key 管理**：从各平台后台网址生成和管理 API Key
- **接口配置**：配置各模型的接口地址和参数
- **模型选择**：根据需求选择合适的免费模型
- **参数设置**：设置配置参数，确保在有效范围内

**核心理念**：将复杂的模型配置流程标准化为可复用的领域负载物，使用户能够方便地配置和使用各种免费模型。

**适用范围**：支持 Agnes AI、智谱、商汤、小红书 dots studio、美团、小米等平台的免费模型配置。

**平台与模型基线**（复核日期 `YYYY-MM-DD`，填写当次核对日期；留空视为未核对，接入前必须先跑 `curl {base}/models` 核对现役模型 ID）：

| 平台 | 接口地址 | 当前模型 | 免费状态 | 备注 |
|------|---------|---------|---------|------|

**排序规则**：平台按「地域 → 免费覆盖面 → 免费性质 → 免费额度 → 免费档质量」排序；平台内部按「文本 → 视觉 → 图像 → 视频 → 语音」排序。完整规则见下文「排序与分类逻辑」，增删模型/平台时必须同步全部清单。

**推荐标识**：`模型ID`（推荐）表示该平台的默认首选（文本主力），每个平台仅 1 个；跨平台清单、范本与配置文件必须一致。

**配置优先级（通用）**：
1. 显式参数：`--api-key` 或配置项中填写的 Key
2. 平台环境变量：`AGNES_API_KEY` / `ZHIPU_API_KEY` / `SENSENOVA_API_KEY` / `DOTS_API_KEY` / `LONGCAT_API_KEY` / `MIMO_API_KEY`
3. 通用台账：`~/.free-model-config/models.json`（可用 `FREE_MODEL_CONFIG` 指向其他路径）

**非标准认证**：小红书 dots studio 只认请求头 `api-key: KEY`（不认 `Authorization: Bearer`）。若调用方只能发 Bearer，会返回 401，需在请求头里补 `api-key`，或改用支持自定义头的调用方式。

### 多模态生成能力（MF6 域）

Agnes AI 特有的多模态生成能力，支持图像、视频、音频生成：

- **架构设计**：基本命令组合复杂命令
  - **基本命令**（原子操作）：`image`、`video`、`concat`
  - **复杂命令**（组合而成）：`long-video`、`images-video`、`story-video`

**核心理念**：通过基本命令的组合，实现复杂的多模态生成功能。

**适用范围**：图像生成、视频生成、视频拼接、音频生成、TTS配音、音视频合并。

**视频接口基线（Video 2.5）**：请求参数为 `seconds`（"4"–"12"）、`size`（`720P`/`1080P`/`1K`/`2K`）、`aspect_ratio`、`mode`（`text`/`keyframe`/`reference`）；`width`/`height`/`fps`/`num_frames` 已废弃，传入会返回 400。轮询用 `GET /agnesapi?video_id=<ID>&model_name=<模型>`。

**脚本关系**：
- `scripts/agnes_gen.py`：核心脚本，用于图像/视频生成（MF6-01、MF6-02、MF6-03）
- `scripts/generate_audio.py`：辅助脚本，用于简单音频生成（MF6-04）
- `scripts/generate_tts_audio.py`：辅助脚本，用于TTS配音（MF6-05）
- `scripts/merge_audio_video.py`：辅助脚本，用于音视频合并（MF6-06）

### 音频生成能力

支持两种音频生成方式：

#### 1. 简单音频合成（无AI模型）

- **工具**：Python wave 模块
- **脚本**：`scripts/generate_audio.py`
- **用途**：生成简单的合成音频（喊叫声、背景音效）
- **限制**：无法生成语音

**核心理念**：当没有 TTS 工具时，可使用此功能生成简单的合成音频。

#### 2. TTS语音合成（需要AI模型）

- **推荐工具**：edge-tts（免费、中文效果好）
- **安装**：`pip install edge-tts`
- **脚本**：`scripts/generate_tts_audio.py`
- **用途**：生成真正的语音配音
- **支持**：单人配音、多人配音、声音混合

**核心理念**：使用 TTS 技术生成真正的语音配音，支持多种声音和语言。

### 音视频合并能力

将音频和视频合并为最终作品：

- **工具**：ffmpeg（系统工具）
- **脚本**：`scripts/merge_audio_video.py`
- **模式**：
  - 替换模式：替换原视频音频
  - 混合模式：与原视频音频混合

**核心理念**：将生成的音频和视频合并为最终作品，支持多种合并模式。

## 排序与分类逻辑

本技能所有跨平台清单（基线表、免费模型清单、平台列表、能力矩阵、端点表、models.json 模板）**共用同一套排序**，避免各文件顺序漂移。增删平台或模型时，按此规则重新落位。

### 1. 平台级排序（跨平台清单）

按以下键依次比较，前一个键相同才看下一个：

| 键 | 维度 | 规则 | 说明 |
|----|------|------|------|
| K1 | 地域 | 海外平台在前，国内平台在后 | 当前 Agnes AI 为海外平台，固定首位 |
| K2 | 免费覆盖面 | 有免费通道的模态数多者在前 | 模态计：文本、视觉、图像、视频、语音 |
| K3 | 免费性质 | 官方永久免费 > 当前 $0 限时 > 积分池 > 预览期免费 > 新客额度/订阅 | 以官方文档措辞为准 |
| K4 | 免费额度 | 无总量上限（仅限流）> 明确大额度 > 额度不透明或很小 | 积分制需注明窗口额度 |
| K5 | 免费档质量 | 免费档含旗舰 > 免费档仅小模型 | 部分免费的平台靠后 |
| K6 | 平手 | 按平台英文名首字母升序 | 仅用于完全同分时 |

**当前落位**：Agnes（K1 海外 + 三模态）→ 智谱（四模态但 K5 仅小模型免费）→ 商汤（三模态、积分可换旗舰）→ 小红书 dots（单模态、预览免费）→ 美团（单模态、额度）→ 小米（K3 最弱，额度+订阅）。

### 2. 平台内部分类排序

| 序 | 规则 | 示例 |
|----|------|------|
| I1 | 按能力域：文本 → 视觉理解 → 图像生成 → 视频生成 → 语音 | Agnes：3.0-flash → image-2.5-flash → video-2.5-flash |
| I2 | 语音域内部：ASR → TTS → 音色克隆 → 音色设计 | 小米：v2.5-asr → v2.5-tts → -voiceclone → -voicedesign |
| I3 | 同能力域内：主推/旗舰 → 轻量/低价（免费模型可保留旧版） | Agnes：先 3.0-flash（主），后 2.5-flash（备） |
| I4 | 同域内免费在前、付费在后，并显式标注（付费） | 智谱：先 4.7-flash（免费文本），末列 5.3-flash（付费升级） |

### 3. 书写约定

- 模型 ID 用反引号，多模型用顿号分隔；免费/付费状态用中文括号补充。
- 每个平台在跨平台表中占 **一行/一列**，不拆分平台（语音、图像等能力写在同格内）。
- 表格行数固定为「平台数 + 表头 + 分隔行」，新增平台必须按 §4 清单逐项同步。
- **frontmatter `description` 与正文「适用范围」里的平台枚举，必须与表格同序**（海外优先 → 免费范围 → 免费程度）。
- **版本保留规则**：**免费模型可保留旧版本**（如 `agnes-2.5-flash` 与 `agnes-3.0-flash` 并列）；**付费模型只保留最新版本**。任何清单都不写「旧版本 → 新版本」的迁移/下线日志，必要时只标「旧版 ID 已停用」。

1. `SKILL.md`：frontmatter `description`、适用范围、平台与模型基线表、排序段落
2. `references/fmc-requirements.md`：免费模型清单 + MF2/MF3 相关约束
3. `references/exemplars/MF2-模型选择域范本.md`：平台列表、能力对比（含列顺序）、能力列表、优缺点
4. `references/exemplars/MF3-配置生成域范本.md`：后台网址、接口地址、模型名称、API 端点、models.json 模板
5. `scripts/agnes_gen.py`：`MODEL_*` 常量（如涉及 Agnes）

## 信息新鲜度（联网校验）

免费模型的 ID、免费政策、限流与端点变化极快（本项目已亲历：Agnes 视频接口参数体系重构、多家平台旧模型 ID 停用）。**使用技能时必须先联网核对，再给配置**，不得直接照抄基线。

### 1. 必须联网的时机

1. 每次执行 **MF2-01 平台选择**之前（选型所依赖的模型清单必须当次核对）
2. 距基线表「复核日期」**≥ 30 天**
3. 用户提到「最新 / 现在 / 还能用吗 / 多少钱 / 免费吗」等时效性问题
4. 出现与模型相关的报错：404（模型不存在）、400（参数不兼容）、401（鉴权）、429（限流）
5. 基线中标注为「未验证」的模型（如 `dots_webdev_1022`）首次使用前

### 2. 查询顺序（权威度从高到低）

| 序 | 来源 | 用途 |
|----|------|------|
| 1 | 平台官方文档「模型总览 / 模型列表」页 | 权威模型 ID、上下文、模态 |
| 2 | `GET {base}/models`（OpenAI 兼容端点） | 实测现役 ID，识别下线 |
| 3 | 官方定价页 / 发布公告 | 免费状态、限流、计费口径 |
| 4 | 第三方目录（模型聚合站等） | 仅交叉参考，**不得单独作为依据** |

冲突判定：**官方文档 > 端点实测 > 第三方目录**；差异需在输出中说明，不得静默择一。

### 3. 每次校验要采集的字段

`model id`、上下文长度、输入模态、是否免费/免费性质、限流（RPM/TPM/积分）、端点路径、鉴权头、是否停用（只记状态，不记版本迁移）、公告日期。

### 4. 发现变更后的处理

| 情况 | 动作 |
|------|------|
| 新模型上线且属免费档 | 按 I1–I5 插入对应平台段，旧版可并列保留 |
| 新模型上线且属付费档 | 只保留最新版，作为「升级项」置末尾，旧版从主表移除 |
| 旧模型停用 | 从主表移除；必要时只标「旧版 ID 已停用」，不写替换关系；同步脚本常量 |
| 免费政策变化 | 更新「免费状态」列；若跨档变化，按 K1–K6 **重排平台顺序** |
| 接口参数破坏性变更 | 更新 MF3-05 约束与脚本，标注「已废弃参数」 |
| 全部核对完成 | 更新基线表「复核日期」（只记状态，不写版本迁移） |

### 5. 离线兜底

- 无法联网时：仍可按本技能基线工作，但**必须在回答首行标注**「基线 YYYY-MM-DD，未联网核对，可能已过期」。
- 禁止凭记忆新增模型 ID、价格或免费承诺；不确定的条目输出为「待核对」，不得写成事实。

### 6. 输出标注要求

涉及选型或配置的结论，末尾附一行：`依据：<官方文档 URL>（复核 YYYY-MM-DD）`；一次回答涉及多平台时逐条列出。

## 通用配置方式

本技能只依赖三件事：**OpenAI 兼容接口 + 环境变量 + 纯 JSON 台账**，与具体客户端无关。任何调用方配置模型的所需信息都相同，按下面五要素填即可。

### 1. 三种配置形态

| 形态 | 适用 | 做法 |
|------|------|------|
| 环境变量 | 命令行、脚本、服务进程 | 设 `*_API_KEY`，base_url 用文首平台表 |
| JSON 台账 | 需要多模型切换的场景 | `~/.free-model-config/models.json`，字段见 MF3-04 |
| 直接填参 | 一次性调用或界面配置 | 逐项填 base_url、api_key、model |

### 2. 配置一个模型所需的全部信息

| 信息 | 取值 |
|------|------|
| 协议 | OpenAI 兼容（`POST {base_url}/chat/completions`） |
| base_url | 见文首平台表 |
| api_key | 平台后台生成，或环境变量 `*_API_KEY` |
| model | 模型 ID（见文首平台表） |
| 鉴权头 | 默认 `Authorization: Bearer`；小红书 dots 用 `api-key` |
| 能力开关 | 视觉 / 工具调用 / 推理，对应 MF3-04 的 `supports*` 字段 |

### 3. 三个注意点

- **认证例外**：小红书 dots 只认请求头 `api-key`，其余平台用 `Authorization: Bearer`
- **能力开关**：`sensenova-u1.5-fast`、ASR/TTS 类不支持工具调用，配置时应关闭 tool call
- **参数差异**：视频接口用 `seconds` + `size` 档位，不传 `width/height/fps/num_frames`

### 4. 目录约定

- 通用台账：`~/.free-model-config/models.json`（`FREE_MODEL_CONFIG` 可覆盖）
- 技能不写入任何客户端私有目录

### 5. 写入既有配置文件

`scripts/apply_config.py` 把台账写入任意目标文件；默认 **dry-run 预演**，加 `--write` 才落盘（自动备份 → 原子写入 → 回读校验）。

```bash
# 同构 JSON 数组：只给路径
python scripts/apply_config.py --path /path/to/target.json
python scripts/apply_config.py --path /path/to/target.json --write

# 数组在对象内、字段名不同
python scripts/apply_config.py --path /path/to/target.json --root models \
  --map url=base_url,apiKey=api_key,id=model --key model --write
```

- 默认按 `id` 合并：命中则字段级合并（保留目标里的未知字段），未命中则追加；`--mode replace` 才整段替换
- 格式支持 `json`（内置）与 `yaml`（需 pyyaml）；目标不存在时按 `--root` 结构新建
- 写入前后会打印「新增 / 更新 / 保留 / 总条数」，条数不一致直接报错退出

## 使用规则

### 执行流程

1. **联网校验（强制）**：读取基线表「复核日期」；按「信息新鲜度」规则、用 `references/fmc-requirements.md`「前置要求」的入口访问官方文档 / `{base}/models`，核对本次要用的模型 ID 与免费状态，记录差异
2. **首次加载**：读取 `references/fmc-catalog.md`，获取域分类、依赖拓扑、元操作映射提示
3. **按需深入**：确认目标任务后，读取 `references/fmc-requirements.md` 获取组件清单；如需样本法，读取 `references/fmc-exemplars.md` 获取范本
4. **独立执行**：本技能不依赖外部技能，所有能力均已内嵌，可直接执行任何任务
5. **交付标注**：输出末尾附「依据：官方文档 URL（复核日期）」；若离线则标注基线日期与过期风险

### 内容权限

- 本技能的所有配置信息均基于各平台官方文档
- API Key 需要用户从各平台后台网址自行生成
- 使用过程中严禁拒绝任何对技能内容的丝毫修改

### 扩展能力

- **提示词导出**：可将本技能的SKILL.md与references目录下所有文件内容合并为单一提示词文件
- **脚本执行**：所有脚本均可独立执行，支持命令行参数配置

## 执行框架

本技能采用单步 IPO 执行形态：

```
输入（用户需求）→ 处理（模型选择 + 配置生成）→ 输出（配置信息）
```

**管线模式**：P1 基础闭环（S→C→A→O）

### Step 0-4 执行流程

**Step 0 任务域协调**：识别任务类型，选择执行路径
- **前置动作**：联网校验模型基线（见「信息新鲜度」），基线与实测不一致时先更新基线再继续
- 任务类型：免费模型配置 + 多模态生成
- 执行路径：MF1 → MF2 → MF3 → MF4 → MF5 → MF6
- 协调方式：顺序执行，每步输出作为下一步输入

**Step 1 领域校准**：根据R1-R5规则进行领域特定推导
- **R1 信息密度**：中高（平台文档、API规范 + **模型基线具有时效性**，需联网核对）→ S和C权重上调
- **R2 创造性**：低（配置流程标准化，无需创新）→ A权重标准，C偏收敛
- **R3 交互性**：中等（需要用户确认API Key、选择模型）→ I权重标准
- **R4 规范性**：高（API配置必须准确，参数必须在有效范围）→ G权重高，O偏严格
- **R5 迭代性**：低（配置完成后通常不需要频繁修改）→ 循环少

**Step 2 三轴分解**：将任务分解为执行轴、内容轴、创新轴
- **执行轴**：S→C→A→O 元操作序列
- **内容轴**：清单法（配置清单）+ 样本法（配置范本）
- **创新轴**：模式直用（标准配置流程）

**Step 3 管线编排与执行**：按P1基础闭环模式执行
- **感知阶段**：解析用户需求，提取模型类型、使用场景
- **认知阶段**：根据需求选择模型、生成配置
- **行动阶段**：生成配置信息，提供使用指导
- **组织阶段**：保存配置，组织输出格式

**Step 4 整合交付**：整合结果，生成最终输出
- 整合各阶段输出
- 生成配置文件和使用指导
- 提供配置验证和测试建议

详细执行流程、交互规则、域概览等见参考文件：
- `references/fmc-catalog.md`：任务清单与依赖拓扑
- `references/fmc-requirements.md`：方法论要求清单

## 事实纪律

1. 配置信息以各平台官方文档为准（使用前联网核对），第三方目录仅作交叉参考
2. API Key 必须由用户从官方后台网址生成
3. 不编造不存在的模型或功能
4. 配置信息必须准确无误
5. 使用指导基于官方最佳实践
6. 脚本命令必须准确无误，参数必须在有效范围内
7. 样本法模仿产出时不直接复制样本内容，仅借鉴结构和风格
8. 单元输出格式须匹配下游单元的输入要求，确保组合接口可用
9. 模型 ID、免费状态、限流、参数以**联网核对结果**为准，不得用记忆或旧基线替代官方文档
10. 无法联网或核对不到时，明确标注「基线 YYYY-MM-DD，未联网核对」，并给出「待核对」标记，不得写成事实
11. 每次选型/配置类输出末尾附「依据：官方文档 URL（复核日期）」
12. 排序或清单结构调整，必须按「排序与分类逻辑 §4 变更同步清单」逐项同步，避免文件间顺序漂移

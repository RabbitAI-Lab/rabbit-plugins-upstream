# memory-audit · AI 记忆机制体检

**Does your AI's memory still work?** A read-only auditor that tells you which memories are actually being used — and which are just costing you tokens every turn.

给 AI 的记忆库做体检。不存、不查，只回答一个问题：**你写进去的那些，现在还在起作用吗？**

---

## 问题：记忆腐烂

任何人用 AI 助手超过半年，都会攒下一套"记忆"——`CLAUDE.md`、`AGENTS.md`、笔记库、备忘录。它们一开始有用，然后慢慢腐烂。

腐烂不报错、不告警，只表现为三种沉默的失效：

| 病灶 | 怎么发生的 | 体感 |
|---|---|---|
| **僵尸记忆** | 写完一次没读过，但仍占着索引，每轮付费 | "它变慢了" |
| **放错层** | 行为红线写在按需层而不是常驻层，看起来记了，实际每轮都不生效 | "我说过多少次了还犯" |
| **矛盾堆积** | 半年前的结论和昨天的结论平权存在 | "它怎么又用回那个方案" |

用户的唯一感知是"它不如以前好用"，然后把原因归给模型变笨。

---

## 它怎么算

```
score = 0.4·H + 0.3·R + 0.2·C + 0.1·T
```

| 指标 | 含义 | 怎么来 |
|---|---|---|
| **H 命中度** | 真实被读取的次数 | 解析会话日志里的 `Read` 工具调用 |
| **R 引用度** | 在体系里的位置 | 索引引用 ×2 + `[[wikilink]]` + 常驻层提及 |
| **C 变更度** | 还活着吗 | git 提交次数 |
| **T 时效度** | 新鲜度 | 距最后一次内容变更的天数 |

**为什么 H 占 40%**：另外三个都能被写作者的行为伪造——爱加链接就 R 高，批量改格式就 C 高，刚改过就 T 高。只有"真的打开读了"是真实选择。

输出四档：**核心 / 沉淀 / 待查 / 冷舱**，每档对应一个动作。

## 安装

无依赖，只需要 Python 3.8+。

```bash
git clone https://github.com/ALPS9999/memory-audit.git
cd memory-audit
```

作为 Claude Code skill 使用：

```bash
cp -r memory-audit ~/.claude/skills/
```

---

## 用法

```bash
python3 audit.py \
  --memory   ~/.claude/projects/<project-id>/memory \
  --sessions ~/.claude/projects/<project-id> \
  --spec     ~/CLAUDE.md \
  --json  audit.json \
  --html  report.html
```

| 参数 | 说明 |
|---|---|
| `--memory` | 记忆目录（默认当前目录） |
| `--index` | 索引文件名，默认 `MEMORY.md` |
| `--spec` | 常驻层文件：`CLAUDE.md` / `.cursorrules` / `AGENTS.md` |
| `--sessions` | 会话日志目录，扫描其中的 `*.jsonl` |
| `--session-limit` | 只扫最近 N 个会话 |
| `--json` / `--html` | 导出格式 |

输出示例：

```
记忆机制体检 · /path/to/memory
==========================================================
  记忆条目          99
  索引             62 行 / 10753 字节 (≈4888 tokens/轮)
  会话扫描          10 个
  从未被读取        55 条 (55%)
  索引未覆盖        39 条

  分档: 核心 1  待查 98

  最常用 5 条:
    0.70  读 5次  project-progress.md
    0.55  读 2次  html-conversion.md
```

## 设计原则

**只读。** 不修改、不删除、不上传任何记忆文件。它是一只听诊器，不是外科医生。

**只出清单，不自动改。** 记忆的删除、合并、降级必须人确认。自动改写记忆的系统一旦判断错，损失的是信任，而信任不可恢复。

**本地优先。** 全部在本机完成，记忆内容不出机器。

---

## 已知局限

1. **观察者效应** —— 体检会话本身会读记忆，把读取次数抬高。同一份库连跑两次，「从未读取数」会下降几个。做趋势对比时要么排除本次会话，要么只看相对变化。
2. **数据窗口决定判别力** —— 会话少于 30 个、git 提交少于 50 次时，分数只能当排序参考，不能当"该不该留"的判决。
3. **只支持 Claude Code** —— 会话日志解析写在 `scan_reads()` 里，其他编辑器（Cursor / Copilot）需要改这一段。这是主要工程成本，且各家格式会变。

## 路线图

- [x] 使用度统计 / 索引体积 / 悬空引用 / 未覆盖 / 四档分诊
- [ ] 放错层检测（规则类内容没进常驻层）
- [ ] 过期事实检测（日期、版本号、价格）
- [ ] 矛盾检测（跨文件找冲突结论，假阳性会很高）
- [ ] 定期自动体检（挂 hook 或 launchd）

**不做**：自动修改记忆。

# 数据分析纪律

## 铁律

- 有数据文件 → 先写代码算,后写报告。绝不用估算替代真实计算
- 报告里的每个数字,必须能追溯到某个脚本 / 文件 / 来源
- 数据有异常 → 先排查(缺失 / 口径 / 单位),不强行解读
- 追溯不到任何来源的数字 → 写「数据不可得」,禁止用估算顶替

## 硬溯源规则(对齐市场标杆)

报告里每个数字交付前必须归属以下四类之一,逐一核对:

| 类型 | 定义 | 报告写法 |
|---|---|---|
| 计算值 | 数据文件算出来的,附脚本/文件路径 | 直接引用 |
| 引用值 | 公开来源(URL/报告名),可复现 | 标注来源 |
| 估算值 | 逻辑推演/类比,有推导依据 | 标「估算」 |
| 不可得 | 追不到任何来源 | 写「数据不可得」,不硬凑 |

**硬门控**:核心结论的唯一数据支撑追不到来源 → 该结论降级为「未验证」,不输出为确定判断。宁可报告里出现「数据不可得」,也不准出现编造或没有依据的推测。

## 工作流

1. 先用 `ls` / Read 摸清文件结构、列含义、口径
2. Python(pandas)清洗:缺失值、类型、单位统一
3. 关键指标算清楚:同比 / 环比、占比、增速、集中度、结构拆解
4. 得出数字 → 反推一遍是否有逻辑矛盾(加总对不上?口径混了?)
5. 需要图表时,**先读 dataviz skill 再画**
6. 图用 matplotlib / plotly;中文字体记得设置;导出 PNG 后在 Markdown 里嵌入

## 图表规范

- 一张图一个结论,标题直接写结论(如「Q2 起增速转负,非季节性」)
- 图注含:图表编号、数据来源、口径
- 图型选对:趋势 → 折线;对比 → 柱状;构成 → 堆叠 / 饼;分布 → 箱线 / 直方
- 不堆 3D、不用彩虹色、不为了花哨牺牲可读性

## 置信度标注

| 置信度 | 含义 | 报告写法 |
|---|---|---|
| 高 | 一手数据 / 权威来源 | 直接引用 |
| 中 | 推算 / 单一来源 | 标"估算" |
| 低 | 类比 / 无数据推断 | 标"置信度低,需验证" |

## 数据文件路径规范

- 每个数据文件在报告附录里写明:文件路径、处理脚本、口径说明,方便复现
- 用户没说数据口径 → 先问,别默认

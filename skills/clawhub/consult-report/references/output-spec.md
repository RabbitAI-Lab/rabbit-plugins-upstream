# 报告输出规范

## 结构(标准版顺序)

1. **执行摘要** —— 90 秒读完。第一句是判断。含核心结论 + 关键数字 + 不做清单
2. **问题界定** —— 这份报告回答什么决策问题、边界在哪
3. **分析框架与方法** —— 用了什么框架、数据来源与时效
4. **核心发现(证据链)** —— 每个判断配证据;数据用图表呈现
5. **诊断** —— 重新框定 + 单一核心矛盾
6. **指导方针** —— 应对思路 + 不做[X] + 近期目标
7. **行动建议** —— P0 ≤ 2 / P1 ≤ 3,每个含代价
8. **数据附录** —— 图表 + 数据口径说明 + 置信度清单
9. **局限声明** —— 哪些关键假设未验证,影响多大

## 写作规范

- 中文,专业但不堆术语;术语首次出现给一句人话解释
- 判断句先行,论证随后,不铺垫
- 每个数字带单位;估算值标注"约/估算"
- 段落因果链清楚:因为 X 数据 → 所以 Y 判断 → 因此做 Z
- 图表见 `data-analysis.md`;每张图必须能独立看懂,标题直接写结论

## 标题要求

- 一级标题 = 判断,不是名词。❌「行业现状」 ✅「市场增速见顶,增量在腰部城市」
- 拒绝「市场分析」「竞争分析」这类空标题

## 每章检查清单

- 摘要:能否 90 秒读完?第一句是不是判断?
- 发现:每个判断后面有没有证据?没有 → 标注是推断
- 诊断:是不是只描述现象,没框定?→ 重写
- 指导方针:三条都在?没有"不做X" → 补
- 行动:每个都写了代价?超了 P0×2/P1×3 → 砍
- 附录:置信度低的数据点列全了?

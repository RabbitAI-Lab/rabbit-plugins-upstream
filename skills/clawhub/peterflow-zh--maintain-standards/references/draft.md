# draft · 起草候选方案

1. 围绕输入先找现行条款、决定、相关检查和实际读者。修订旧规则时重点看上次修订后的新依据。可以从已合入 MR、作者实际采纳的修复和后续修复提交中提炼候选。同一 MR 内重复推送或机器人重复留言算一次事件。历史只覆盖一部分，就说清这部分；没有材料支撑的规则留空。
2. 判断要新增、澄清、修订、合并还是退役。代码能说明实现了什么，人的决定和有效契约才说明应该怎样。若现行政策有效而实现偏离，直接指出实现问题。机械检查已覆盖全部要求就引用检查；只覆盖一部分时，保留还需要判断的条件。能由测试或 lint 解决的漏检可以建议改检查。
3. 用[候选模板](../assets/candidate.md)给人写出原条款、建议的完整文字、出处和需要决定的事。每项写明建议最终改哪条 L0 通则、L1 专题或 L2 功能规范，保留当前版本、适用范围和例外。一个文件可有多个能独立选取的标题。
4. 将有实质变化的候选写入 `candidates/<主题>.md` 或已有候选位置，只要求预览时在会话中交稿。同一提案沿用原稿，有人编辑过就先对照。没有新内容则指出依据和已有落点。完成时给出候选路径和可采纳的条目；现行正文与导航保持原状。

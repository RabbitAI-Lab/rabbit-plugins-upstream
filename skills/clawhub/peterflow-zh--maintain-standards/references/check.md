# check · 检查现行规范

从指定文件、章节或功能开始。省略范围就检查现行库。从 L3 索引定位适用的 L0 通则、L1 专题和已采纳的 L2 功能条款，也核对遗漏的现行文件。若索引把候选或归档列作现行，报告这条错误引用。按范围读取有效决定、契约、代码和证据，注明实际核对的版本。工作区只读，结果在会话中给出。仅在用户指定时另存报告。

| 检查对象 | 怎样判断 |
| --- | --- |
| 文档与文档 | 对齐对象、时点、版本及约束力度后再判冲突。“公开 API 要记录请求号”和“离线导入不经过公开 API”可以同时成立。同义规则有独立条件时保留该条件。 |
| 规范与代码 | 描述“现在怎样”的文档随实现事实更新。仍受有效决定约束的行为若偏离要求，指出实现问题并给触发例。两边的权威依据尚不清楚，就列出待定点。 |
| 过时、重复与替代 | 查功能是否仍在用、退出条件是否已兑现、引用者是否还依赖原判断。文件日期早或本仓找不到外部事实，只能提示补证。检查覆盖了哪些情况，剩余的哪些仍要人判断。 |
| 入口与证据 | 核对本地链接和锚点、遗漏或重复的入口、来源版本、误入现行读取链的候选或备份。区分结构检查通过、静态读码和实际运行结果。 |

先说对开发或评审影响最大的发现。每项给出具体位置、互相对照的依据、触发条件和处理方向（改实现、改规范、修导航或请人决定）。证据不足的部分标明“未核实”及缺什么。区分已查无异常和未覆盖的范围；没有发现也可以结束。用户选定问题后可拿该项起草候选。

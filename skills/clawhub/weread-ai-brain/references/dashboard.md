# 看板规范

仅在生成微信读书 Markdown 或 HTML 看板时读取本文件。

## 数据最小化

基础看板只需书架、用户昵称和阅读统计。只有相应模块确实需要、且用户另行确认时，才读取指定书籍的划线或想法。

建议数据对象：

- `lang`：用户选择或当前对话语言对应的 BCP 47 标签；
- `ui`：全部本地化标签，包括七项 `weekdays`；
- `userName`、`date`、`metrics`：昵称、生成日期、核心指标；
- `wall`、`brainwave`、`spectrum`：阅读热力图、时段分布、分类分布；
- `diagnosisText`、`recommendedBooks`：基于样本的覆盖说明与可核验推荐；
- `mbti`：趣味阅读类型、维度分数、规则说明和置信度；
- `analysis`：可选单书分析；`bookTitle` 为空时隐藏整个分析模块。

不要展示无法由实际返回数据支持的指标。接口没有日粒度或小时粒度数据时，省略对应图表并说明原因，不用划线时间戳冒充阅读时长。

## Markdown 看板

可按可用数据选择模块，不强制凑齐：

1. 数据范围与生成时间；
2. 核心指标；
3. 阅读活跃度或时间分布；
4. 书架分类覆盖；
5. 趣味阅读类型；
6. 经确认加入的单书分析。

每个推断模块都要写明统计口径和数据限制。

## HTML 模板

使用 `templates/dashboard.html`，不要另写不受约束的模板。

- 单文件 HTML，系统字体，无远程字体、脚本、图片或样式资源；
- 暗色/亮色 CSS 变量主题；主题选择可存于 `localStorage`，不要存阅读数据；
- 最大宽度 1100px；768px 以下转为单栏或两列紧凑布局；
- 外部字段只通过 `textContent` 和受限 DOM API 渲染；不得使用 `innerHTML`、`document.write` 或字符串拼接生成标签；
- `lang` 初始为 `und`，加载数据后设置经校验的 BCP 47 标签；
- 没有某类数据时隐藏该模块或显示“数据不足”，不要用示例数据填充。

### 唯一数据占位符

模板只能包含：

```text
{{DASHBOARD_DATA_JSON_ESCAPED_FOR_HTML}}
```

先把完整数据对象序列化为 JSON，再依次转义：

| 字符 | 替换值 |
|---|---|
| `<` | `\u003c` |
| `>` | `\u003e` |
| `&` | `\u0026` |
| U+2028 | `\u2028` |
| U+2029 | `\u2029` |

最后只替换上述占位符。不得把原始 JSON、HTML 或 JavaScript 片段直接插入模板。

## 趣味阅读类型

可用四个可解释维度生成四字母标签，但必须展示计算规则，且在样本不足时降低置信度或省略：

- B/D：品类分散与主题集中；
- L/H：工具/经管与文学/历史/哲学占比；
- A/R：划线密度；
- T/S：阅读时段是否稳定。

类型名和文案应保持友善，不羞辱、不诊断、不评价智力或人格。维度阈值只是产品启发式规则，不是心理学量表。旧版 16 型名称可作为文案素材，但不得伪装为科学测评结果。

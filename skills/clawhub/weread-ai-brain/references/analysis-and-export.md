# 分析与导出规范

仅在进行单书分析、跨书关联或文件导出时读取本文件。

## 单书分析

### 概念通解

说明核心概念、日常类比、适用边界和常见误区。不要为了通俗而篡改原意。

### 产品视角拆解

从用户问题、业务假设、产品机制和验证方式展开。改进建议必须标为模型建议，不把书中观点冒充事实或用户需求证据。

### 合规风险提示

识别文本中可能涉及的数据、合同、消费者、知识产权或行业合规问题，并列出需要专业人士核实的事项。明确这不是法律意见，不给出确定性合法/违法结论。

## 历史上下文

只有用户明确同意后，才读取指定书籍的划线和个人想法。最多选择 8 条与当前问题直接相关的上下文，并保留书名或章节信息。若无相关内容，直接说明。

建议格式：

```markdown
## 相关历史上下文

1. 第 N 章：短摘录
   - 个人想法：摘要
```

不要将用户旧想法视为当前立场。

## 跨书关联

1. 确认主题与 2–5 本目标书；
2. 告知拟读取的划线/想法范围并取得确认；
3. 分别提炼各书观点；
4. 标出概念映射、分歧和递进；
5. 区分原文支持、用户想法和模型综合。

## Markdown 导出

```markdown
---
source: weread-ai-brain
type: book-analysis / semantic-cluster
books:
  - 书名
created: YYYY-MM-DD
---

# 标题

## 数据范围

## 原文摘录或关联笔记

## 分析

## 不确定性与待核实项
```

- 只导出用户确认的数据类别和书目；
- 默认不包含原始 API 响应、API Key 或不相关笔记；
- 文件名使用可读的安全字符，避免把整段用户文本拼入路径；
- 目标已存在时不覆盖，除非用户明确确认该文件；
- 批量导出前列出文件清单和目标目录。

## HTML 导出

遵循 `references/dashboard.md` 的单占位符注入规范和 `templates/dashboard.html`。文件应可离线查看，不包含远程资源或联网代码。

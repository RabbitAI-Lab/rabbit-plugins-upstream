# 交付时核对什么

人工审核重点是问题是否值得回答，以及同一答案能否满足归并后的全部说法。脚本通过只表示标注内部一致，不代表需求或内容策略已被真实市场验证。

1. **问题来源**：每道原题的ID、完整原文与来源在同一条记录中关联保留，重复原文也不丢失；Agent拓展的问题明显标为待验证假设；没有捏造高频、月搜索量或用户调研记录。
2. **归并**：所有原题ID恰好归入一组；同主题的操作、撤权和排障问题仍各自存在。别把同关键词当作同答案。
3. **覆盖**：已覆盖和部分覆盖均有正文证据与理由。只有标题、失效链接或未提供的文章不构成覆盖；未读完整库存时，不贸然判定“没有这类内容”。
4. **事实**：具体到免费额度、适用平台、角色权限、重试条件等缺项。来源是用户资料还是已核实材料要说清，不用假数字填满表格。
5. **下一步**：每题的形式与动作互相对应；已有可用内容走复用/更新；周计划包含问题ID、资料与完成条件，能被下一位内容作者直接接手。
6. **结果状态**：模拟、未运行、失败和已提供回答记录区分；未运行不是0引用。提及、原生引用、普通URL和已发布/已收录不能混用。

运行业务自测：

```bash
python3 scripts/self_test.py
```

测试会在临时目录执行真实CLI，并检查每条原题的ID—原文—来源关联、A/A/B与A/B/B两种重复序列的可区分性、原文空白及标点保留、两种归并、主题边界、正文覆盖、库存不足、资料阻塞、排序、CSV公式处理、回答状态、失败退出及不覆盖已有文件。它也核对演示输出与重新计算的结果一致。

这些测试使用明确的本地演示资料，不访问网络，不调用模型，不测试平台引用效果。自测不依赖图标、根目录许可证、用户账户、父目录或其他技能。正常工作不需要浏览器。

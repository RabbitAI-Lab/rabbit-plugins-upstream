# 本周优先选题

输入范围：一款免费多账号内容工具的演示业务说明、5篇完整短教程和12条问题说法。12条归并为10组，保留全部原题ID。需求推导仍是待验证假设；本周按“2个内容成果，其余先补资料”的产能假设排序。这不是发布安排，也未执行模型查询。

## 先制作两个缺失内容

1. **Q10｜小团队继续用表格，还是试用多账号工具？**
   - 受众与意图：3至5人的内容团队，先对照已知记录事项，为是否试用提供有边界的信息。
   - 成果：账号与发布计划信息对照表。表格一侧只写已知的“记录账号与发布计划”；工具一侧引用A1的账号身份核对、A3的账号及计划信息说明，不把未提供的表格操作过程补成事实。
   - 已有资料：演示业务介绍的一句表格用途说明，以及A1、A3正文；没有现有表格的具体字段、操作步骤或耗时资料。
   - 下一步：对照记录事项和工具已说明的信息，标明各自来源；未说明的表格细项保持未知。这份表不直接判断工具能否替代团队当前完整流程。
   - 完成条件：对照范围仅为账号与发布计划信息，不延伸比较素材迁移、定时执行或回执检查流程，不推断整体流程优劣、固定节省比例或“零失败”结论。需要扩大比较时先补相应资料。

2. **Q11｜第一次试用，应该选哪些步骤验证工具是否适合团队？**
   - 受众与意图：同一团队，决定如何进行一次有边界的试用。
   - 成果：单次试用验收清单，组合A1的账号身份核对、A2的导入原文核对、A3的计划与任务状态核对。
   - 下一步：为每一步写“操作、应回读的信息、失败时停在哪里”，沿用已有教程入口，不再重写三篇教程。
   - 完成条件：清单能区分任务安排与平台实际提交状态，未知回执保留未知；只验证提供的功能。

这两题是资料可用且影响试用决策的主题缺口，因此为P0。优先级是策划判断，不表示真实需求量或AI引用概率。

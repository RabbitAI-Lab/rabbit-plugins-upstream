# 视觉与跨模态质检引擎（E 类 · H 类）

版本 1.1.0 ｜ 2026-10-11

---

## 零、执行主体声明（先读）

**本引擎不依赖任何外部视觉工具、专用检测模型或 AI 判别器。**

执行器就是**调用本技能的大模型自身的原生多模态理解能力**。模型已经能看图、能读图里的文字、
能判断画面上讲不讲得通——缺的不是能力，是**纪律**。

没有纪律的多模态质检会退化成两种失效形态：

| 失效形态 | 表现 | 后果 |
|---|---|---|
| **扫一眼放行** | "整体看起来没问题" | 漏检，等于没查 |
| **印象式指控** | "感觉人物不太自然" | 用户无法据此修改，报告显得虚 |

所以本文件提供的不是能力，而是**判定协议**：

> 看什么 · 按什么顺序看 · 看到什么算命中 · 什么情况必须不报 · 报的时候要举出什么证据

它的作用是把通用视觉理解**收敛成可复现、可举证、可裁定的质检结论**。

**边界重申**：本引擎**不做 AI 生成检测**。
只判断「这张图讲不讲得通」「图和文对不对得上」，**绝不输出"这是 AI 画的"**。

## 一、三段式执行协议：枚举 → 取证 → 判定

### 步骤 1 · 枚举（不跳项）

按下面的**九宫格**（E 类）或**锚点对齐表**（H 类）逐项点名，逐项标记三种状态之一：

```
已观察-无异常 / 已观察-有异常 / 不适用（写明原因）
```

**未观察的项不得计入通过项**——通过项虚报比漏报更伤信任。

### 步骤 2 · 取证（画面证据，这一步决定报告可信度）

每条判定**必须**给出可见证据，三要素缺一不可：

```
位置（画面方位或区域） + 可见特征 + 与什么冲突
```

✅ 合格：`画面右侧女性右手，可见 6 根手指，且拇指与食指之间多出一根独立指节`
❌ 作废：`人物手部不太自然`、`画面整体有些违和`、`感觉光影不太对`

**写不出三要素的，就是没看清楚——按防误报红线第 2 条进存疑项，不得硬报。**

### 步骤 3 · 判定（对照判定表）

给出 severity 与确定性，按 `scoring.md` 算影响分并分层。
**视觉类判据的确定性赋值有专门规则**，见第三节——这是防止"看图看错还报成必改"的关键闸门。

## 二、E 类 · 图片观察九宫格（固定顺序，不得跳）

**先判体裁，再判内容**（防误报红线第 1 条）：写实照片 / 3D 渲染 / 扁平插画 / 卡通风 / 像素风 /
抽象 / 极简设计 / 超现实——判据适用性差别极大，顺序错了会大面积误报。

| 序 | 观察域 | 看什么 | 命中特征示例 |
|:--:|---|---|---|
| **1** | 全局与构图 | 主体是否明确；有无不可解释的色块、残影、拼接痕、边缘融蚀 | 背景与主体交界处出现涂抹状融合；画面角落有半透明残影 |
| **2** | 主体结构 | 物体部件是否完整、连接是否合理、有无多余部件 | 椅腿数量不对；杯把手悬空未连接；眼镜腿穿过耳后 |
| **3** | 手与肢体 | 手指数、手指方向、关节弯曲方向、手腕与手臂连接 | 6 指；手指反向弯折；手腕与袖口错位；手臂从肩胛长出 |
| **4** | 面部 | 五官对称性、双眼视线方向、瞳孔形状、牙齿、耳廓 | 双眼看向不同方向；两耳高度与形状不一致；瞳孔大小不一 |
| **5** | 光影 | 光源数量与方向；各物体投影方向是否一致；高光位置是否同源 | 同一场景两物体投影方向相反；人物受光来自左、背景投影朝右 |
| **6** | 反射与透明 | 镜面/玻璃/水面/金属中的反射内容是否与场景一致 | 镜中反射的是另一间房间；玻璃杯后的物体未折射；镜片无反光 |
| **7** | 透视与比例 | 消失点是否一致；远近比例；地平线；同类物体大小关系 | 桌面两端消失点不一致；远处人物与近处人物等高 |
| **8** | 画面文字 | 招牌、书脊、屏幕、标签、仪表盘上的文字是否**成字且正确** | 汉字缺笔画/拼凑；英文单词字母错乱；数字位数不对 |
| **9** | 物理与材质 | 重力、液体、布料褶皱、接触点阴影、金属/玻璃质感 | 液体静止却呈倾倒状；悬空物体无支撑；接触处无接触阴影 |

## 三、E 类判定表（含视觉专属确定性赋值）

| # | 检查 | severity | 确定性 | 默认分层 |
|---|---|---|:--:|---|
| **E1** | 解剖学异常（手指、肢体、五官） | error | **1.0**（清晰可数时） | 🔴 必改（对外发布） |
| **E2** | 光影方向不一致 | error | 0.8 | 🟡 可改 |
| **E3** | 镜面/反射不合理 | error | 0.8 | 🟡 可改 |
| **E4** | 透视与比例矛盾 | error | 0.8 | 🟡 可改 |
| **E5** | 画面文字错误（乱码、错字、不成字） | error | **1.0** | 🔴 必改 |
| **E6** | 物件穿模 / 悬浮 / 连接错误 | error | **1.0**（明显时） | 🔴 必改 |
| **E7** | 配饰不成对（耳环、袖扣、鞋带） | medium | 0.8 | 🟡 可改（偏执档才报） |
| **E8** | 物理常识违背（重力、液体、材质） | error | 0.8–1.0 | 视清晰度 |
| **E9** | 品牌元素错误（Logo 变形、配色偏差） | error | 1.0 / 0.2 | 有标准 VI → 必改；无 → ⚪ 存疑 |
| **E10** | 视觉套路（科技蓝紫渐变、发光卡片、多巴胺配色、大促红金、满屏弹窗） | low | 1.0 | 🟡 可改 / 不报 |

### 视觉确定性赋值通则（★ 核心闸门）

| 确定性 | 适用判据 | 说明 |
|:--:|---|---|
| **1.0** | **可数、可读、可比对** | 手指数、文字错字、Logo 变形、图中数字与正文数字矛盾 |
| **0.8** | **需推断但特征明确** | 投影方向、反射内容、远近比例、材质表现 |
| **0.2** | **看不清 / 被遮挡 / 风格化** | 一律进 ⚪ 存疑项，**禁止"根据经验推测"** |

**推论**：E2 / E3 / E4 / E8 天然只有 0.8 确定性，**永远进不了必改区**
（必改要求确定性 = 1.0）。这是"宁可少报不可虚报"在视觉模态上的数学保证——
**画面上"看着不对但说不死"的东西，只进可改项。**

唯一例外：当该画面缺陷**直接造成事实性误导**时（如产品图上按钮位置与实物不符，
用户会据此操作），按 **D2 真实性**重新归类，可升至必改——但必须写明"误导后果"。

## 四、五条防误报红线（比命中规则更重要）

| # | 红线 | 说明 |
|:--:|---|---|
| **1** | **先判体裁，再判内容** | 插画/卡通/水彩/像素/抽象/极简/超现实/有意变形 → **E1、E4、E5、E8 不适用或降级**。卡通人物 4 指是画风，不是缺陷 |
| **2** | **看不清就不报** | 低分辨率、强压缩、局部裁剪、景深虚化、过曝欠曝 → 进 ⚪ 存疑项。绝不推测画面内容 |
| **3** | **不鉴定作者** | 绝不输出"这是 AI 生成的""看起来像 AI 画的"。我们交付的是"能不能用"，不是"谁画的" |
| **4** | **构图解释优先** | 手在画外 / 被物体遮挡 / 握拳 / 戴手套 / 持物 / 插兜 → **不算手指异常**。先穷尽合理解释，再判缺陷 |
| **5** | **轻微项不进必改** | E7、E10 只在偏执档报，且仅进 🟡 可改项 |

**合并规则**：同一区域的多项命中**合并为一条**。
如"手部区域：手指数量异常 + 手腕连接错位"→ 报 **E1 一条**，不拆成两条。

## 五、H 类 · 跨模态锚点对齐引擎（技术护城河）

**单模态工具结构性做不到这件事**——它们看不见"文字侧"和"视觉侧"在说什么。

### 核心原则

> **不做"整体感觉一致吗"，做"锚点逐条对齐了吗"。**
> 先抽出文本侧可核对的断言，再逐条到视觉侧比对。

### 步骤 1 · 抽取锚点（文本侧）

从正文、讲稿、图注、表格、按钮文案中抽取六类**可核对断言**：

| 锚点类型 | 例子 |
|---|---|
| **数字锚点** | "占比 37%""增长 3 倍""共 12 个模块""下降 15 个百分点" |
| **对象锚点** | 出现的人物、产品、物体、场景元素 |
| **属性锚点** | 颜色、材质、形状、数量、方位、状态 |
| **时间锚点** | 年份、季节、昼夜、时段、先后次序 |
| **空间锚点** | "左侧""第二排""背景中的""右上角的" |
| **趋势锚点** | "持续上升""逐季下降""持平""首次出现" |

### 步骤 2 · 逐锚点比对（视觉侧）

每个锚点到图中找对应，输出三选一：

```
✅ 一致 ／ ❌ 矛盾 ／ ⚠️ 无法核对
```

**「无法核对」不等于通过**：图中看不出、分辨率不足、锚点本身不可视化（如"满意度提升"没有对应视觉）→
记入 ⚪ 存疑项，**不得计入通过项**。这是最容易虚报的地方。

### 步骤 3 · 输出锚点对齐表（H 类报告的主体）

```markdown
| 锚点 | 文本侧 | 视觉侧 | 结论 |
|---|---|---|---|
| 数字·占比 | "占比 37%" | 饼图该扇区标注 42% | ❌ 矛盾 → H2 必改 |
| 对象·人物 | "两位工程师在调试" | 画面中为三人 | ❌ 矛盾 → H1 必改 |
| 属性·颜色 | "深蓝色主视觉" | 主色为紫罗兰 | ❌ 矛盾 → H1 必改 |
| 趋势·上升 | "逐季上升" | 柱状图第三季回落 | ❌ 矛盾 → H2 必改 |
| 时间·季节 | "冬季场景" | 图中树木枝叶茂密 | ⚠️ 无法核对 |
```

### 步骤 4 · 反向核对（视觉 → 文本）

图中**显著存在**但正文完全未提及的元素 → 若可能影响理解（多出一个人、多出一个数据系列、
出现未说明的品牌标识）→ 🟡 可改项，提示"图上有的，正文没交代"。

### H 项判定表

| # | 检查 | severity | 确定性 | 分层 |
|---|---|---|:--:|---|
| **H1** | 图文矛盾（画面内容与正文描述不是一回事） | error | 1.0 | 🔴 必改 |
| **H2** | 图数矛盾（图表数字与正文/数据源不一致） | error | **1.0**（可计算） | 🔴 必改 |
| **H3** | 图注缺失或错位 | medium | 0.8 | 🟡 可改 |
| **H4** | PPT 讲稿与页面内容不匹配 | error | 1.0 | 🔴 必改 |
| **H5** | 落地页文案与视觉/功能不符（按钮说 A，点了是 B） | error | 1.0 | 🔴 必改 |
| **H6** | 引用编号与参考文献表不对应 | error | **1.0**（可计算） | 🔴 必改 |
| **H7** | 多文件批量质检时的跨文件矛盾 | error | 1.0 | 🔴 必改 |

> H2 与 H6 属**可计算校验**（数字对得上/对不上，编号存不存在），确定性天然 1.0，
> 这是组合模态里最硬、最不容易误报的一类——**优先跑这两项**。

## 六、多图与组图处理

- **图片 >5 张**：先过全局（体裁一致性、风格统一度、有无共性缺陷），再逐张。
- 报告按**「全组共性问题 + 逐张个性问题」**组织，避免同一句话刷屏 8 次。
- **组图风格不一致**（同一套物料里写实与插画混用、色调体系不同）→ 🟡 可改项。
- **同一张图在多处复用但语义不同**（同一配图分别标注为"2024 年"与"2025 年"）→ 🔴 必改（H7）。

## 七、输出契约（视觉/组合类报告片段）

每条必写四项，缺一不可：

1. **位置** — 第几张图 / 画面哪个方位 / 对应正文哪一段
2. **证据** — 看到了什么（三要素）
3. **冲突** — 与什么不符（正文描述 / 物理常识 / 品牌规范）
4. **后果** — 不改会怎样

**标准条目示例**：

> **🔴 H2 图数矛盾 ｜ 严重度 4 × 暴露度 4 × 确定性 1.0 = 16**
> - **位置**：第 3 张图表（季度营收柱状图），对应正文第 2 段
> - **证据**：正文写"Q3 营收 1,280 万元"，图中 Q3 柱体标注为 1,820 万元
> - **冲突**：同一指标两个值，读者无法判断哪个为准
> - **后果**：客户按图取数做测算，将直接与正文口径冲突，提案可信度受损
> - **建议**：统一数据源后重新出图（**未代为修改**）

## 八、图片类通过项的正确写法

不得只写"图片检查通过"。必须写出**观察了哪些项、结论如何**：

✅ `E 类九宫格 9 项全部观察：1/2/4/5/7/8/9 无异常 ✅；第 3 项手部存在异常（见必改项）；第 6 项画面无反射面，不适用`

✅ `H 类锚点对齐：抽取 11 个锚点，9 个一致 ✅，1 个矛盾（已列为必改），1 个无法核对（存疑）`

❌ `图片看起来没问题`

## 九、与 D2 真实性的衔接

画面中的文字（招牌、截图、数据看板、仪表盘读数、纸质文件）若含**可核实信息**，
按 **D2 真实性**处理，不止按 E5 处理：

- 图中的机构名、日期、金额、版本号 → 需与已知资料比对
- **看不清的一律进存疑项**，**禁止猜测画面内容**——猜出来的"事实"一旦写进报告，
  就是铁律 2 的违反（新增事实），且视觉猜测的出错率显著高于文本

## 十、执行前自检（图片/组合质检报告输出前逐条过）

- [ ] 是否已先判**体裁**（写实/插画/抽象），并据此调整了判据适用性？
- [ ] 九宫格是否**逐项点名**，未观察的项有没有混入通过项？
- [ ] 每条判定是否都给出了**三要素证据**？说不清的有没有降级到存疑？
- [ ] E2/E3/E4/E8 有没有被误放进必改区？（这些天然只有 0.8 确定性）
- [ ] 有没有出现"这是 AI 画的"这类**作者鉴定**表述？
- [ ] 同一区域的多项命中是否已**合并**为一条？
- [ ] H 类是否输出了**锚点对齐表**，"无法核对"有没有被当成通过？
- [ ] 有没有**猜测画面内容**（尤其是画面文字、数字）？

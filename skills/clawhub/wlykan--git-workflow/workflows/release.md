# 发布工作流

## 目标
规范软件发布的完整流程，确保发布质量和系统稳定性。

## 工作流步骤

### 阶段1：发布准备
**时间**：发布前1-2天
**行动**：
1. 确定发布内容
2. 创建发布分支
3. 合并确定上线的功能
4. 更新版本号

**发布内容确认**：
```markdown
## 发布内容清单
- [ ] 功能A：用户管理模块
- [ ] 功能B：权限控制优化
- [ ] 修复C：登录问题修复
- [ ] 优化D：性能提升

## 不包含的内容
- [ ] 功能E：实验性功能（未完成）
- [ ] 修复F：非紧急问题（计划下版本）
```

**分支创建**：
```bash
# 1. 从main创建发布分支
git checkout main
git pull origin main
git checkout -b release/2026-08-06

# 2. 合并确定上线的功能
git merge --no-ff feature/user-management
git merge --no-ff feature/permission-optimization
git merge --no-ff hotfix/login-fix

# 3. 更新版本号
# 修改package.json中的版本号
# 更新CHANGELOG.md
```

**检查点**：
- [ ] 发布内容已确认
- [ ] 发布分支已创建
- [ ] 功能已合并
- [ ] 版本号已更新

### 阶段2：测试验证
**时间**：发布分支创建后
**行动**：
1. 部署到测试环境
2. 执行完整测试
3. 修复发现的问题
4. 确认测试通过

**测试清单**：
```markdown
## 功能测试
- [ ] 所有新功能测试通过
- [ ] 所有修复验证通过
- [ ] 边界条件测试通过
- [ ] 异常情况处理正常

## 性能测试
- [ ] 响应时间达标
- [ ] 并发处理正常
- [ ] 内存使用正常
- [ ] CPU使用正常

## 安全测试
- [ ] 权限控制正常
- [ ] 数据加密正常
- [ ] 输入验证正常
- [ ] SQL注入防护正常

## 兼容性测试
- [ ] 浏览器兼容性正常
- [ ] 移动端兼容性正常
- [ ] 不同分辨率正常
- [ ] 不同操作系统正常
```

**问题处理**：
```bash
# 1. 在发布分支上修复问题
git checkout release/2026-08-06

# 2. 修复问题
# ... 修改代码 ...

# 3. 提交修复
git add .
git commit -m "fix: 修复测试发现的问题

- 问题描述：[问题描述]
- 修复方案：[修复方案]"

# 4. 重新测试
# ... 执行测试 ...
```

**检查点**：
- [ ] 测试环境已部署
- [ ] 所有测试用例通过
- [ ] 问题已修复
- [ ] 测试报告已记录

### 阶段3：发布审批
**时间**：测试通过后
**行动**：
1. 准备发布说明
2. 提交发布申请
3. 获得审批确认
4. 确认发布时间

**发布说明模板**：
```markdown
# 发布说明 - 版本 1.2.0

## 发布时间
2026-08-06 14:00

## 发布内容
### 新功能
- 用户管理模块：支持用户增删改查
- 权限控制优化：细粒度权限管理

### 问题修复
- 修复登录崩溃问题
- 修复数据同步异常

### 性能优化
- 优化查询性能，响应时间提升30%
- 优化内存使用，减少20%内存占用

## 影响范围
- 所有用户
- 核心业务模块

## 回滚方案
1. 切换到上一版本分支
2. 重新部署
3. 通知相关方

## 监控重点
- 系统性能指标
- 错误日志
- 用户反馈
```

**审批流程**：
```markdown
## 发布审批
- [ ] 开发负责人确认
- [ ] 测试负责人确认
- [ ] 产品负责人确认
- [ ] 运维负责人确认

## 发布时间确认
- [ ] 发布时间已确认
- [ ] 相关人员已通知
- [ ] 监控人员已安排
```

**检查点**：
- [ ] 发布说明已准备
- [ ] 审批已通过
- [ ] 发布时间已确认
- [ ] 相关人员已通知

### 阶段4：正式发布
**时间**：审批通过后
**行动**：
1. 合并到main分支
2. 创建版本标签
3. 部署到生产环境
4. 验证发布结果

**发布命令**：
```bash
# 1. 合并到main分支
git checkout main
git merge --no-ff release/2026-08-06

# 2. 创建版本标签
git tag -a v1.2.0 -m "发布版本 1.2.0

发布内容：
- 新功能：用户管理模块
- 修复：登录崩溃问题
- 优化：性能提升"

# 3. 推送到远程
git push origin main
git push origin v1.2.0

# 4. 合并回dev分支
git checkout dev
git merge --no-ff release/2026-08-06
git push origin dev
```

**部署清单**：
```markdown
## 部署前检查
- [ ] 备份已完成
- [ ] 回滚方案已准备
- [ ] 监控已配置
- [ ] 通知已发送

## 部署过程
- [ ] 停止旧版本服务
- [ ] 部署新版本
- [ ] 启动新版本服务
- [ ] 验证服务正常

## 部署后检查
- [ ] 功能验证通过
- [ ] 性能指标正常
- [ ] 错误日志正常
- [ ] 用户反馈正常
```

**检查点**：
- [ ] 已合并到main分支
- [ ] 版本标签已创建
- [ ] 已部署到生产环境
- [ ] 发布结果已验证

### 阶段5：发布后监控
**时间**：发布后24小时内
**行动**：
1. 监控系统状态
2. 收集用户反馈
3. 处理突发问题
4. 记录发布过程

**监控清单**：
```markdown
## 系统监控
- [ ] 性能指标正常（响应时间、吞吐量）
- [ ] 错误率正常（< 0.1%）
- [ ] 资源使用正常（CPU、内存、磁盘）
- [ ] 服务状态正常（所有服务运行）

## 业务监控
- [ ] 核心业务指标正常
- [ ] 用户行为正常
- [ ] 交易数据正常
- [ ] 订单处理正常

## 用户反馈
- [ ] 用户投诉正常（无新增投诉）
- [ ] 用户咨询正常（无相关咨询）
- [ ] 用户满意度正常
```

**问题处理**：
```bash
# 如果发现严重问题，执行回滚
git checkout main
git reset --hard v1.1.0
git push origin main --force

# 同时回滚dev
git checkout dev
git reset --hard v1.1.0
git push origin dev --force
```

**检查点**：
- [ ] 系统状态正常
- [ ] 业务指标正常
- [ ] 用户反馈正常
- [ ] 发布过程已记录

### 阶段6：发布后清理
**时间**：发布后1-2天
**行动**：
1. 删除发布分支
2. 清理本地分支
3. 更新相关文档
4. 总结发布经验

**清理命令**：
```bash
# 1. 删除远程发布分支
git push origin --delete release/2026-08-06

# 2. 删除本地发布分支
git branch -d release/2026-08-06

# 3. 清理已合并的功能分支
git branch --merged dev | grep "feature/" | xargs git branch -d

# 4. 清理远程已合并分支
git fetch --prune
```

**文档更新**：
```markdown
## 需要更新的文档
- [ ] CHANGELOG.md - 添加发布记录
- [ ] README.md - 更新版本信息
- [ ] 部署文档 - 更新部署流程
- [ ] 用户手册 - 更新功能说明

## 知识库更新
- [ ] 常见问题 - 添加新问题解决方案
- [ ] 最佳实践 - 添加发布经验
- [ ] 故障处理 - 添加回滚案例
```

**检查点**：
- [ ] 发布分支已删除
- [ ] 本地分支已清理
- [ ] 文档已更新
- [ ] 发布经验已总结

## 常见问题处理

### 1. 发布后发现严重问题
```bash
# 1. 立即回滚
git checkout main
git reset --hard v1.1.0
git push origin main --force

# 2. 分析问题原因
# ... 分析问题 ...

# 3. 修复问题
git checkout -b hotfix/release-issue
# ... 修复代码 ...

# 4. 重新发布
git checkout main
git merge --no-ff hotfix/release-issue
git tag -a v1.2.1 -m "热修复版本"
```

### 2. 发布过程中网络中断
```bash
# 1. 检查当前状态
git status
git log --oneline -5

# 2. 继续发布（如果状态正常）
git push origin main
git push origin v1.2.0

# 3. 或者回滚（如果状态异常）
git reset --hard [正常提交]
git push origin main --force
```

### 3. 多人同时发布
```bash
# 1. 协调发布顺序
# 确定哪个版本先发布

# 2. 等待前一个版本稳定
# 监控系统状态

# 3. 再发布下一个版本
# 按照正常流程发布
```

./scripts/check-release-status.sh [发布分支名]

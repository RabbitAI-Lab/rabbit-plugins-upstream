# 客户上下文隔离

每次任务先建立 `client_scope` 和 `run_id`。默认只允许读取本次任务的输入文件、该客户已确认的方法论和本次运行产生的底稿；不跨客户搜索历史记忆，不把一个客户的阈值、行业数据或结论迁移给另一个客户。

## 三层存储

- `global_methodology`：不含客户名称、店铺 ID、金额和结论的通用方法、公式、模板。
- `client_scope`：客户确认的字段口径、商品词典、版式偏好和历史决策；只能在明确指定同一客户时读取。
- `run_scope`：本次任务的原始文件、指标包、证据账本、审批和交付物；使用 `run_id` 追踪。

## 强制规则

1. 资料清单和运行账本先写 `client_scope`、`run_id`、允许读取根目录和来源文件哈希。
2. 发现客户范围不明、文件来自多个客户或输出目录越界时，状态为 `data_blocked`。
3. 公共专家包只保留 `global_methodology`；客户名称、店铺 ID、样本数字和内部路径不得进入包。
4. 交付物引用来源时优先使用文件指纹和证据 ID；对外版本不暴露本机绝对路径。
5. 运行结束后只把经过人工确认的规则回写到客户空间，禁止把模型推测写入长期记忆。

使用 `scripts/context_guard.py` 检查输入路径是否都在允许根目录内，并扫描指定的禁止词。它是门禁，不是对客户数据的自动分类器；无法判断归属时必须人工处理。

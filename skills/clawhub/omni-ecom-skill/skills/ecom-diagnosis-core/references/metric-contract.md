# 指标契约

## 1. 先写清来源与粒度

每张输入表至少登记：`source_id`、平台、文件名、sheet、导出时间、数据起止日、时间粒度、对象粒度、金额单位、人数是否去重、退款归属期。

同名字段不代表同口径。只有在平台、期间、对象粒度、过滤条件和归因规则一致时，指标才能直接比较或合并。

## 2. 规范字段

| 字段 | 含义 | 必要限制 |
|---|---|---|
| `period` | 统计期间 | 同一文件内必须唯一；格式保持一致 |
| `gmv` | 声明口径下的成交总额 | 必须说明是否支付、是否含取消、是否含退款 |
| `visitors` | 店铺或渠道去重访客 | 必须与买家和期间口径匹配 |
| `buyers` | 支付买家数 | 人数与订单数不得混用 |
| `orders` | 支付订单数 | 通常不小于买家数；异常须解释 |
| `refund_amount` | 与 GMV 可比口径的退款金额 | 必须说明按申请期、成功期还是原订单期 |
| `ad_spend` | 同期可归因广告花费 | 账户、计划和税费口径需一致 |
| `gross_margin_rate` | 商品毛利率 | 用 0~1 小数；说明是否已含货损和税费 |
| `commission_rate` | 平台佣金率 | 用 0~1 小数；说明计费基数 |
| `fulfillment_cost_per_order` | 单订单履约成本 | 仓储、快递、包材范围需声明 |
| `refund_loss_rate` | 退款货损比例 | 用 0~1 小数；无数据不得填行业默认值 |
| `search_gmv` | 搜索渠道可归因 GMV | 必须与搜索访客、买家同口径 |
| `search_visitors` | 搜索渠道去重访客 | 不得用全店访客替代 |
| `search_buyers` | 搜索渠道支付买家数 | 用于搜索转化率和可承受 CPC |
| `observed_cpc` | 实际点击成本 | 与可承受 CPC 的渠道和期间一致 |

## 3. 核心公式

- 转化率：`buyers / visitors`
- 客单价：`gmv / buyers`
- 金额退款率：`refund_amount / gmv`
- 净销售参考值：`gmv - refund_amount`。它不自动等于财务确认收入或实际回款。
- ROAS：`attributed_gmv / ad_spend`
- 净 ROAS：`(attributed_gmv - attributed_refund_amount) / ad_spend`
- 搜索 UV 价值：`search_gmv / search_visitors`
- 搜索转化率：`search_buyers / search_visitors`

利润必须使用项目确认的会计口径。至少要能拆出：确认收入、商品成本、平台佣金、广告费、履约成本、支付与税费、退款货损。缺任何重大成本时，不得把“销售额减广告费”称为净利润。

可承受 CPC 采用以下渠道级情景公式：

`可承受CPC = 搜索UV价值 × (1−退款率) × (毛利率−佣金率) − 搜索转化率 × 单订单履约成本 − 搜索UV价值 × 退款率 × 货损率 × (1−毛利率)`

只有输入字段齐全且口径一致时才计算。结果是测算上限，不是建议出价，也不保证可以买到有效流量。

## 4. 人数与商品层限制

- 店铺去重访客可用于店铺转化率。
- SPU / SKU 访客往往在商品间重复，不能相加后当店铺人数。
- SPU 访客可用于单品转化、结构占比或需求强度；跨商品汇总时必须明确“未去重”。
- 买家数、下单人数、支付人数、订单数和件数不可互换。

## 5. 期间与归因

- 环比和同比先检查天数、活动周期、节假日和缺报天数是否一致。
- 广告销售额、自然销售额和全店销售额的归因窗口可能不同，不应直接相减推导自然贡献。
- 跨平台种草只在有可验证的归因窗口、追踪标识或实验对照时量化；否则只写“可能影响”。
- 退款按成功期统计时可能与原订单错期；高退款业务应同时呈现原始口径和可得的订单期口径。

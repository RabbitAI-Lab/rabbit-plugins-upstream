# 数据质量闸门

## 1. 闸门状态

| 状态 | 进入经营诊断 | 允许输出 |
|---|---|---|
| `PASS` | 是 | 已复算事实、受证据支持的归因与方案 |
| `WARN` | 有条件 | 受影响结论必须标限制、置信度和补数项 |
| `BLOCKED` | 否 | 数据问题清单、可确认事实、修复与补数方案 |

出现以下任一情况，至少判 `BLOCKED`：

- 核心期间重复且无法确定应保留的版本。
- 转化率分母来自未去重 SPU 访客加总，或买家、订单、件数明显混用。
- 核心总表与明细差异超过 1%，且差异会改变结论但无法解释。
- 关键报表期间、币种、金额单位或退款归属期未知。
- 两个来源对同一核心指标冲突，且无法按来源权威性、导出时间和口径裁决。
- 用户要求利润、预算或投放结论，但毛利、退款、佣金、履约或广告花费等关键输入缺失。

以下通常判 `WARN`：

- 样本量小，单月只有少量买家或订单。
- 行业数据只给区间、只覆盖部分期间或口径未完全公开。
- SPU 访客只能作为未去重信号，无法用于店铺转化率。
- 退款按成功期统计，可能与原订单月份错位。
- 只有截图或人工摘录，缺少可复算的原始导出。

## 2. 资料体检顺序

1. 列文件、sheet、日期范围、行数和关键列。
2. 按文件头识别真实格式，确认编码、千分位、百分号、空值和金额单位。
3. 查找日 / 周 / 月重复导出、`副本`、`(1)`、同名不同时间文件。
4. 区分总表与明细表；先用总表锁定店铺级分母，再用明细解释结构。
5. 做勾稽：买家约等于访客 × 转化率；SKU GMV 合计与总 GMV；退款原因合计与退款总额；来源占比与覆盖率。
6. 建立冲突表：指标、来源 A、来源 B、差异、口径解释、采用值、裁决依据。

## 3. 异常订单三口径

当店铺体量小、客单或转化异常跳变、少量订单占比过高时，必须保留并比较：

- `N0`：原始报表。
- `N1`：剔除低价污染候选，默认筛查条件为 `件单价 < 20元 且 GMV > 0`。
- `N2`：在 N1 上再剔除非自然大单候选，默认筛查条件为 `单月单SPU GMV > 5000元 且 成交客户数 <= 15`。

这些阈值只是通用筛查起点，须结合品类价格带调整。命中不等于刷单、作弊或无效订单；必须保留原始记录、说明业务背景并让用户确认。最终报告同时呈现 N0 与经营基本盘口径，不能静默删除。

剔污后必须重算所有下游结论，包括转化、客单、退款、UV 价值、单位经济、修复路径、目标和预算。只改归因段落而沿用旧建议，视为闸门失败。

## 4. 样本与异常解释

- 少量订单下的零退款、极高转化或极高客单不能作为趋势证据。
- 极端值先判断是否由口径、错期、赠品、测试单、补差价、企业采购或渠道订单造成。
- 统计异常与业务异常分开记录；模型不得自行把异常贴上行为性质标签。
- 结论受样本量影响时，给观察窗口和触发阈值，不给确定性承诺。

## 5. 闸门交付模板

```text
gate_status: PASS | WARN | BLOCKED
scope: 平台 / 店铺 / 期间 / 粒度
source_register: 来源清单与权威性
reconciliation: 勾稽结果与差异
scenario_compare: N0 / N1 / N2
blocking_issues: 阻断项
warnings: 限制项
approved_metrics: 可用于下游的指标
prohibited_claims: 当前不得输出的结论
next_data: 待补文件、字段、负责人和截止时间
```

# 2.0：裁决默认进入报告

适用于本次报告存在需要总监处理的专家分歧。主理人先完成真实专家回复与来源复算，再准备裁决；本节不代替这些验证。

## 单一来源

生成报告前，在输出目录的 quality-inputs.json 中填写本次 adjudication 相对路径。指向的 JSON 同时保留：

- 本次 run_id、client_scope、team_version、report_revision、conflicts_sha256；
- 完整 verdicts，包括方法、复算输入、决定、未采纳理由、剩余风险和真实 challenge_review；
- 本次计算对应的 adjudicated_claims，必要的 adjudicated_downstream；
- 尚不能解决时的 unresolved_conflicts。不能完成裁决时仍遵守原来的数据质量报告降级限制。

不要从历史文件猜测数值、岗位回复或当前裁决。数值裁决必须显式包含要进入报告的值、期间、单位等字段；生成器不会自己补齐缺失结论。口径与趋势的原始来源验证见 semantic-adjudication-v2.md。

## 默认生成与交付检查

build_report_package.py 默认读取输出目录 quality-inputs.json 所指向的裁决。不再要求额外 --decision-pack；若仍显式指定，内容必须与质量配置的文件一致。路径越界、其他运行/客户/修订、缺失的规范结论字段或冲突的显式文件都会阻断生成。

生成器将同一展示投影放入 report.json，Markdown 和 PDF 共用该内容，包括采用值、不同意见、总监处理理由、限制及专家回复处理。复算原始路径等内部字段不直接进入展示。来源文件指纹进入报告来源清单；是否通过仍以质量和独立复核为准，不因显示一段裁决就视为完成。

quality_gate 现在强制检查：

- 当前存在 hard 分歧时，报告必须包含与当前裁决一致的摘要。
- 规范裁决中已有的结论、下游结果和未解决事项必须与报告投影一致。
- 实际 Markdown 必须显示完整裁决区块；只在 JSON、HTML 注释或代码示例中保留内容不算交付。
- 当前分歧已经消失时，旧的裁决/结论区块不能继续冒充本次结果。

旧裁决文件如仍只保存 verdicts，质量检查可以核验报告中的已有结论，但默认生成需要先把这些结论写回本次规范裁决文件。这是来源归并，不是跳过复算或拿旧报告覆盖新稿。

## 验证边界

decision_pipeline_smoke.py 实际调用默认生成入口，对八种任务生成 JSON、Markdown 和 PDF，并提取 PDF 文字核对裁决、至少三张图和非空页。输入数据、岗位回传全部为合成，保留候选当前元数据，不是 2.0 发布或真实多专家验收。

另由 report_metric_guard 检查实际供 KPI/图表使用的 metrics、inputs、行顶层数值，以及数字来源索引。重复位置同名字段不同、当前/对比期与裁决不一致、比例与百分数混用、来源索引仍保留旧值时阻断。已接入报告构建、独立 PDF 生成和最终质量检查，不会用裁决数字悄悄覆盖原始来源。

目前映射包括标准渲染字段（gmv、visitors、buyers、orders、退款金额、推广花费、归因 GMV、profit、total_cost、转化率、退款率、客单价、ROAS、ROI、UV 价值、净销售及净销售参考等），以及明确的中文别名。使用元/人、元、倍、ratio、% 等明确单位；百分数换算到图表小数比例再比对。实际日期的等价月份格式可以匹配，但“本期/上期”不自动猜日期；缺少对应期间时先补明确标签。未识别自定义裁决在底层比较中记 unmapped_not_checked；正式交付还必须执行 [结构化指标对应来源](claim-sources-v2.md)，自定义已展示指标须有同名、同期间/范围、明确单位的索引，不能依靠该提示绕过。

缺失对比比率不画成 0，图表标注“对比期缺数”；真实 0 仍画出并标数。转化率从 0 开始可以计算百分点变化，金额基期为 0 时不计算相对百分比。流量规模含 0 时使用线性刻度，标题与真实刻度一致。布尔值、非有限数值或互相冲突的同名输入不作为正常图表数字。

这些检查不证明自由文字里所有旧观点已更正，也不替代来源真实性、完整公式复算或多平台细分口径审查。正式任务仍必须检查受影响的指标、摘要、行动及 claim ledger，完成来源复算、冻结、实际 PDF 逐页复核后才能交付；完整真实经营报告验收仍待完成。

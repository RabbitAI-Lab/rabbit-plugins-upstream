# 因果证据审查 2.0

## 为什么要单独审查

两个指标同时变化，只能先说明“有关联”，不能直接说明“前者导致后者”。专家如果要写“原因、导致、归因、主要来自、因为、驱动”，必须同时提交一份可检查的因果说明；没有说明时，冲突扫描直接停止。

## 最低信息

每项因果判断必须写清：结果指标、候选原因、期间、是否声称首要原因、作用机制、时间先后、替代解释、可能干扰项、反证方法、识别方法和对应证据 ID。正文证据与因果说明中的证据必须完全一致，且都已核验。

## 允许的结论强度

- `hypothesis`：待验证假设。
- `observational_association`：观察到关联，但没有证明因果。
- `quasi_experimental`：存在准实验或自然对照设计。
- `experimental`：存在受控实验设计。

`hypothesis` 和 `observational_association` 只能输出“可能、初步相关、待验证、尚不能确认”等限定表达。要写成 `causal_supported`，必须具备已核验的时间先后、对照组、处理发生时间、通过的前趋势检查，以及单独的设计证据；缺任一项都降级。

## 多专家冲突

多位专家针对同一指标、同一期间提出不同“首要原因”时，生成归因冲突。如果至少一项已达到因果支持，属于硬冲突，必须进入定向质疑；若都只是关联或假设，则保留为软冲突，由总监复算并在报告中说明不确定性。

## 边界

该审查只验证因果结论是否有足够结构化证据，不证明平台导出或外部数据本身真实。真实来源仍由来源范围、哈希、数字复算和平台验收分别负责。

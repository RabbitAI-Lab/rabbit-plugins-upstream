# v2.0.3 专家分工与返工处理

分析任务卡的 analysis_work_plan 只准备责任和来源路径。它不产生专家事实、判断或通过结论；全量清单、章节覆盖、岗位最小分析集、数字复算与独立复核保持原要求。

共享基线、清单和章节计划在同一批任务卡中只读取一次；运行、客户、版本必须一致，生成前后核对指纹。成员使用卡片快照，独立查核实际来源。不要重复读取同一资料来寻找已经给出的身份或格式。

每位专家完成所属章节及岗位最小分析集，必要时查询其他来源反证。每个证据登记一次，用 evidence_ids 引用；摘要简写实际贡献，不再复制全文。缺资料按实际深度写明缺字段、影响及补数要求，停止对无法回答的问题反复推演。没有发现数量上限。

首次综合派工仍必须有四位真实分析成员。prepare_agent_task_cards.py --attempt a2 --roles ROLE 只为 SQLite 已记录 a1 失败或拒收的岗位生成任务卡；运行中的任务、已成功回传的岗位和已用过 a2 的岗位均拒绝重试准备。准备卡片不是重试已获宿主启动的证明；仍走原有 dispatch_hook、host_runtime start/accept 和失败预算检查。

诊断卡住时运行 workflow_progress.py --run-dir RUN_DIR --run-id RUN_ID --client-scope CLIENT。它只读 SQLite、核对已选交接件和观测指纹，输出五岗状态、原始任务 ID 和下一步。进度文件不能签发完成。WorkBuddy 等待仍通过真实阻塞工具和原生阶段任务显示状态；不能以普通助手文本结束仍在进行的主任务。中断后宿主绑定不明时，保持未完成，不能另建同名团队冒充恢复。

复核任务卡提供冻结材料导航和检查顺序。真实复核员必须读所有相关材料和每页实际 PDF，自己给出 passed/conditional_pass/rejected。重复问题合并关联位置不降低检查覆盖。

性能验收分开记录程序准备、专家运行、等待、PDF、复核和失败次数。同一资料、同一模型选择、同等质量要求才可比较；固定无客户测试与真实周报分别报告，不能将专项程序提速宣传为整份报告提速。

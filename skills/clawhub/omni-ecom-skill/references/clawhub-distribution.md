# ClawHub 分发与能力边界

专家团 v2.0.3，维护批次 20261014-r2。ClawHub 原条目为 `omni-ecom-skill`，技能内部名称仍为 `omni-ecom`；不新建同名技能。本次更新不修改用户的 WorkBuddy/Codex 安装，也不升级历史任务。

## 安装后的第一步

请用户说明客户、店铺、平台、期间、决策目标并上传授权的原始导出报表。读取业务文件前先锁定范围。本包不会登录店铺后台、读取平台 API 或自动投放；不需要平台 API 密钥。

先检查本次宿主能否读取本地文件、执行 Python、创建真实专家子任务、取得真实终态和回传、呈现 PDF 页面，以及生成下载文件。仅安装技能不代表具备这些工具。

- WorkBuddy：实际存在 TeamCreate/Agent 等工具时，使用 `runtime-v2.md` 中 WorkBuddy 协议。本包是技能分发，不自动注册原生 Team、头像或 PreToolUse 钩子；若要 WorkBuddy 专家中心的完整原生安装，使用对应 WorkBuddy 插件发行包。
- Codex：实际存在 spawn_agent/wait_agent 等工具时，使用其中 Codex 协议。权限、并发名额、是否允许派工仍由用户和宿主决定。
- OpenClaw、千问或其他宿主：本分发尚未实现其原生工具与 2.0 账本的适配、也未进行原生运行验收。返回 `host_adapter_not_available` 和具体缺口，不把工具名字猜成兼容、不把主理人分角色写作当成真实多专家、不签发正式完成。本包不是这些产品的原生插件。
- 某一必要能力缺失：说明阻断项；允许说明已核实的数据事实或补数清单，但不得宣称已交付完整专家报告。没有业务文件时不要启动专家或制作样板经营数据。

## 本地运行与文件范围

Python 3.10 或以上。先运行 `python -B scripts/runtime_dependency_guard.py` 检查依赖；依赖版本在根目录 `requirements-runtime.txt`。安装依赖须由用户允许，建议独立虚拟环境，不修改系统配置或默默安装软件。处理旧式 XLS 如缺读取引擎，应明确要求转换为 XLSX/CSV 或经用户允许补装依赖，不能假装读取成功。

中文 PDF 需要本机可用中文字体并逐页检查；原版式工具含 Windows 字体路径示例，不能声称跨系统开箱即用。缺字体或不能渲染时明确阻断 PDF 交付。

分析只读取本次用户授权的业务文件。包内 `config/client-brand-registry.json` 只有示例名称；公域名称检查如需其他客户名称清单，先取得用户对精确文件的授权，再显式设置 `OMNI_ECOM_CLIENT_REGISTRY`。本分发版移除了原工程自动查找本机 WorkBuddy 私有清单的回退路径；未显式指定时仅使用包内示例。业务数据不上传 ClawHub；若宿主把数据发送给模型服务，遵循宿主的提示和用户授权。

本包会在本次指定输出目录写入 SQLite 运行账本、专家交接、证据索引、图表、Markdown/JSON/PDF 和复核凭证。它们是报告证据，不是后台操作授权。不得读取其他项目的客户数据、浏览器凭证或任意本机文件。

## 版本与发布包区别

默认图表 PDF 标注 `omni-ecom v2.0.3`、维护批次 `20261014-r2`、独立报告修订号 R1/R2。来源未给的推广花费、退款和成本不得补零、猜数或编造 ROI。GMV/访客是访客价值，不是买家转化率；ROAS 不是利润 ROI。

完整多专家报告必须四位真实分析回传齐备，生成最终报告后冻结，由真实独立复核员检查实际每页 PDF，必改项清空并通过完成检查后交付。主理人不能代写专家回传或复核通过。

本包保留核心程序、六个角色卡、规范、契约和合成测试；不分发 WorkBuddy 专属隐藏插件清单、hooks 自动挂载或二进制头像。角色卡是派工资料，不代表宿主已自动创建专家。不要运行要求 `.codebuddy-plugin/plugin.json` 的 WorkBuddy 打包/安装验证器来验证本分发版；应核对本包的清单、文件指纹、核心测试和实际宿主能力。

`release-acceptance.json` 保留的是原工程发布的历史凭证，并非本次 ClawHub 分发或任意客户报告的原生验收；合成测试也不是专家真实参与。当前没有核实整体耗时或账单节省，不承诺提速百分比。API、后台执行及跨模型路线基线仍为 `not_enabled`；模型沿用用户选择。
